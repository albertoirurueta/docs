Collections and Utility Packages

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Go 1.27 (go1.27.2), checked on 2026-10-18. Every runnable program below was vetted with go vet, compiled and run with that toolchain, and the output (including compiler errors, vet reports and panics) is the real output. Go deliberately keeps its core small: the language gives you slices and maps, and the standard library adds the rest as ordinary packages. This page is a tour of those packages that you reach for every day once a program grows past fmt and net/http: the generic helpers in slices, maps and cmp; the older sort package you will still meet in existing code; the three container/... packages; floating-point, arbitrary-precision and bit-level arithmetic; random numbers, both the fast kind and the cryptographically secure kind; the uuid package that arrived in Go 1.27; and the two low-level helpers hash/maphash and unique. The examples use the library catalogue domain (shelf) of this reference.

The page assumes the basics of Arrays and Slices and Maps, and the generics syntax from Generics. Iterator-returning functions such as slices.Values and maps.Keys are explained in Iterators and Range-over-Func. Cryptographic hashing, keys and TLS are on Crypto and Security; this page only covers the random-number side of crypto/rand. If you come from Rust, the equivalents of much of this page are on Collections and Numbers and Numeric Computing; from C, see Numbers and Math.

cmp: ordering and defaults

The cmp package is the vocabulary that slices and maps share. It defines:

  • the constraint cmp.Ordered, the set of all types that support the ordering operators <, <=, > and >=: every integer type, every floating-point type and string, together with any defined type whose underlying type is one of those (the ~ forms in the constraint);

  • cmp.Compare(x, y), a three-way comparison that returns a negative number, zero or a positive number (in practice -1, 0 or +1);

  • cmp.Less(x, y), the boolean form; and

  • cmp.Or(vals...), which returns the first argument that is not the zero value of its type (Go 1.22).

Three-way comparison is the signature of every Func function in slices: SortFunc, BinarySearchFunc, MinFunc, CompactFunc and so on take func(a, b E) int. That shape composes, which is what cmp.Or is for: a multi-key ordering is the first comparison that is not zero.

package main

import (
	"cmp"
	"fmt"
	"math"
	"slices"
)

type Config struct {
	Addr    string
	Timeout int
}

func main() {
	fmt.Println(cmp.Compare(1, 2), cmp.Compare("b", "a"), cmp.Compare(3.5, 3.5))
	fmt.Println(cmp.Less("apple", "banana"))

	// NaN sorts before every other float; NaN equals NaN for Compare.
	nan := math.NaN()
	fmt.Println(cmp.Compare(nan, 1), cmp.Compare(nan, nan), cmp.Compare(1, nan))
	fmt.Println(cmp.Less(nan, math.Inf(-1)), nan < math.Inf(-1))
	// -0.0 and +0.0 compare equal.
	fmt.Println(cmp.Compare(math.Copysign(0, -1), 0))

	floats := []float64{3, nan, 1, math.Inf(1), -2, math.Inf(-1)}
	slices.Sort(floats)
	fmt.Println(floats)

	// cmp.Or returns the first argument that is not the zero value.
	def := Config{Addr: ":8080", Timeout: 30}
	user := Config{Timeout: 5}
	merged := Config{
		Addr:    cmp.Or(user.Addr, def.Addr),
		Timeout: cmp.Or(user.Timeout, def.Timeout),
	}
	fmt.Printf("%+v\n", merged)
	fmt.Println(cmp.Or(0, 0, 0) == 0, cmp.Or[string]() == "")

	// It works for any comparable type, e.g. pointers and structs.
	fmt.Println(cmp.Or(Config{}, def) == def)
}

Points to remember:

  • Floating-point rules. cmp.Compare and slices.Sort define a total order for floats that the < operator does not: a NaN is less than any non-NaN and equal to another NaN, and -0.0 equals +0.0. That is why the Sort call above puts NaN first and does not corrupt the result. With a hand-written a < b comparison, any NaN makes the ordering inconsistent.

  • cmp.Or evaluates every argument. It is a function, not an operator, so cmp.Or(expensive(), fallback()) calls both. It also treats a legitimate zero as "unset": a Timeout of 0 meaning "no timeout" cannot be distinguished from a missing value. For such fields use a pointer or a separate bool.

  • Or needs comparable. It compares each argument with the zero value using ==, so slices, maps and functions are rejected at compile time.

  • Do not subtract. The older idiom return a.Year - b.Year works for small numbers but overflows for large or extreme ones:

package main

import (
	"cmp"
	"fmt"
	"math"
)

func main() {
	a, b := math.MaxInt-1, -5
	fmt.Println(a-b > 0)           // wraps: wrongly reports a < b
	fmt.Println(cmp.Compare(a, b)) // correct: 1
}

The next program combines them on the shelf domain: a multi-key sort with cmp.Or, a binary search by ISBN, grouping, ordered iteration over a map with slices.Sorted(maps.Keys(m)), MinFunc and Chunk for paging.

package main

import (
	"cmp"
	"fmt"
	"maps"
	"slices"
	"strings"
)

// Book is a trimmed-down catalog.Book for the example.
type Book struct {
	ISBN   string
	Title  string
	Author string
	Year   int
}

func main() {
	books := []Book{
		{"9780441013593", "Dune", "Herbert", 1965},
		{"9780141439518", "Emma", "Austen", 1815},
		{"9780141439884", "Persuasion", "Austen", 1817},
		{"9780199535569", "Ulysses", "Joyce", 1922},
		{"9780141439471", "Dubliners", "Joyce", 1914},
	}

	// Multi-key ordering: author, then year descending, then title.
	slices.SortFunc(books, func(a, b Book) int {
		return cmp.Or(
			strings.Compare(a.Author, b.Author),
			cmp.Compare(b.Year, a.Year), // reversed operands = descending
			cmp.Compare(a.Title, b.Title),
		)
	})
	for _, b := range books {
		fmt.Printf("%-8s %d %s\n", b.Author, b.Year, b.Title)
	}

	// Binary search needs the same ordering on the searched key only.
	byISBN := slices.SortedFunc(slices.Values(books), func(a, b Book) int {
		return cmp.Compare(a.ISBN, b.ISBN)
	})
	i, found := slices.BinarySearchFunc(byISBN, "9780199535569", func(b Book, isbn string) int {
		return cmp.Compare(b.ISBN, isbn)
	})
	fmt.Println(i, found, byISBN[i].Title)

	// Group titles by author, then walk the authors in order.
	titles := map[string][]string{}
	for _, b := range books {
		titles[b.Author] = append(titles[b.Author], b.Title)
	}
	for _, author := range slices.Sorted(maps.Keys(titles)) {
		fmt.Println(author, titles[author])
	}

	oldest := slices.MinFunc(books, func(a, b Book) int { return cmp.Compare(a.Year, b.Year) })
	fmt.Println("oldest:", oldest.Title)

	for page := range slices.Chunk(slices.Sorted(maps.Keys(titles)), 2) {
		fmt.Println("page:", page)
	}
}

Notes on the program:

  • In SortFunc the order of the operands picks the direction: cmp.Compare(b.Year, a.Year) sorts newest first.

  • BinarySearchFunc only requires that the slice is sorted by the searched key; the program re-sorts a copy by ISBN first. The comparison function receives an element and the target, in that order.

  • Maps iterate in a random order, so the program sorts the keys before printing or chunking them. Without the sort, the pages would differ from run to run.

  • Sort and SortFunc are not stable. Use SortStableFunc when records that compare equal must keep their input order (for example when sorting a table by one column after sorting by another).

Pitfalls

  • The result must be used. Insert, Delete, Compact, Replace, Grow, Clip and friends return the new slice, because the length (and maybe the backing array) changes. go vet reports a call whose result is dropped:

s := []int{1, 2, 3}
slices.Delete(s, 0, 1)
slices.Sort(s)
slices.Insert(s, 0, 9)
./main.go:10:2: result of slices.Delete call not used
./main.go:12:2: result of slices.Insert call not used

Source: slices.Delete and slices.Insert

(Sort returns nothing, so it is not reported.)

  • Sorted input is a precondition, not a check. BinarySearch on an unsorted slice neither panics nor errors; it returns an arbitrary answer. Compact removes only neighbours, so it needs a sorted slice to remove every duplicate.

  • Aliasing. Delete and Insert modify the backing array of the argument; the old slice header now shows a shifted array. Clone first when the original must survive, and Clip to force a copy on the next append.

  • Out-of-range arguments panic with the runtime’s messages, as the program below shows.

package main

import (
	"fmt"
	"slices"
)

func try(name string, f func()) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("%s: panic: %v\n", name, r)
		}
	}()
	f()
}

func main() {
	// Delete shifts the tail down and (since Go 1.22) zeroes the vacated slots,
	// so pointers there no longer keep objects alive.
	s := []*int{new(int), new(int), new(int), new(int)}
	t := slices.Delete(s, 1, 3)
	fmt.Println(len(t), len(s), s[2] == nil, s[3] == nil)

	// Compact only removes *consecutive* duplicates.
	fmt.Println(slices.Compact([]int{1, 1, 2, 1, 1, 3, 3}))

	// BinarySearch on an unsorted slice is not an error: it just returns nonsense.
	i, found := slices.BinarySearch([]int{9, 1, 8, 2, 7}, 2)
	fmt.Println(i, found)

	// Clip and the append aliasing trap.
	base := make([]int, 3, 10)
	grown := append(base, 99)
	clipped := append(slices.Clip(base), 100) // capacity 3: forces a new array
	fmt.Println(grown[3], clipped[3], len(base), cap(slices.Clip(base)))

	try("Insert", func() { _ = slices.Insert([]int{1, 2}, 5, 9) })
	try("Min", func() { _ = slices.Min([]int{}) })
	try("Chunk", func() {
		for range slices.Chunk([]int{1}, 0) {
		}
	})
	try("Delete", func() { _ = slices.Delete([]int{1, 2, 3}, 2, 1) })
	try("Repeat", func() { _ = slices.Repeat([]int{1}, -1) })
}

sort: the legacy package

The sort package predates generics. It has three layers:

  • the interface sort.Interface (Len, Less(i, j int) bool, Swap(i, j int)) with sort.Sort, sort.Stable, sort.IsSorted and the sort.Reverse adapter;

  • the convenience function sort.Slice (and SliceStable, SliceIsSorted), which takes any slice as any plus a less function over indices and swaps elements with reflect.Swapper; and

  • typed helpers: sort.Ints, sort.Strings, sort.Float64s, the IntSlice, StringSlice and Float64Slice types, and the searches sort.Search, sort.SearchInts, sort.SearchStrings, sort.SearchFloat64s and sort.Find (Go 1.19).

package main

import (
	"fmt"
	"slices"
	"sort"
	"strings"
)

type Book struct {
	Title string
	Year  int
}

// byYear implements sort.Interface, the pre-generics way.
type byYear []Book

func (s byYear) Len() int           { return len(s) }
func (s byYear) Less(i, j int) bool { return s[i].Year < s[j].Year }
func (s byYear) Swap(i, j int)      { s[i], s[j] = s[j], s[i] }

func main() {
	books := []Book{{"Ulysses", 1922}, {"Emma", 1815}, {"Dune", 1965}, {"Dubliners", 1914}}

	// 1. sort.Slice: reflection-based swapper, `less` gets indices.
	sort.Slice(books, func(i, j int) bool { return books[i].Year < books[j].Year })
	fmt.Println(books)

	// 2. sort.Sort with a named type implementing sort.Interface.
	sort.Sort(sort.Reverse(byYear(books)))
	fmt.Println(books)

	// 3. The modern replacement: generic, no reflection, three-way compare.
	slices.SortFunc(books, func(a, b Book) int { return a.Year - b.Year })
	fmt.Println(books)

	// Typed helpers for the basic types.
	ints := []int{5, 2, 8}
	sort.Ints(ints)
	words := strings.Fields("pear apple fig")
	sort.Strings(words)
	fmt.Println(ints, words, sort.IntsAreSorted(ints))

	// sort.Search: smallest index in [0,n) where f is true (f must be monotone).
	years := []int{1815, 1914, 1922, 1965}
	i := sort.Search(len(years), func(i int) bool { return years[i] >= 1920 })
	fmt.Println(i, years[i])
	// Not found: Search returns n, so check the bounds yourself.
	j := sort.Search(len(years), func(i int) bool { return years[i] >= 2000 })
	fmt.Println(j, j == len(years))

	// sort.SearchInts and slices.BinarySearch also report whether it was found.
	k := sort.SearchInts(years, 1914)
	fmt.Println(k, k < len(years) && years[k] == 1914)
	pos, ok := slices.BinarySearch(years, 1914)
	fmt.Println(pos, ok)

	// sort.Find (Go 1.19) is the three-way variant and reports found.
	pos, ok = sort.Find(len(years), func(i int) int { return 1922 - years[i] })
	fmt.Println(pos, ok)

container/heap

container/heap implements a binary min-heap on any type that satisfies heap.Interface:

type Interface interface {
	sort.Interface   // Len, Less, Swap
	Push(x any)      // add x as element Len()
	Pop() any        // remove and return element Len()-1
}

Source: container/heap: Interface

You implement the five methods on a slice type, and the package supplies heap.Init, heap.Push, heap.Pop, heap.Fix and heap.Remove. The Push and Pop methods you write only append to and truncate the slice; you never call them directly. The heap.Push and heap.Pop functions call them and then restore the heap order, in O(log n). The smallest element, according to Less, is at index 0.

The next program is a queue of loans ordered by due date. Each element stores its own index so a renewal can call heap.Fix and a cancellation can call heap.Remove in O(log n).

package main

import (
	"container/heap"
	"fmt"
	"time"
)

// Loan is a due-date entry; index is maintained by the heap for Fix/Remove.
type Loan struct {
	Member string
	Book   string
	Due    time.Time
	index  int
}

// dueQueue is a min-heap of loans ordered by due date.
type dueQueue []*Loan

func (q dueQueue) Len() int           { return len(q) }
func (q dueQueue) Less(i, j int) bool { return q[i].Due.Before(q[j].Due) }
func (q dueQueue) Swap(i, j int) {
	q[i], q[j] = q[j], q[i]
	q[i].index = i
	q[j].index = j
}

// Push and Pop are called by package heap; do not call them directly.
func (q *dueQueue) Push(x any) {
	l := x.(*Loan)
	l.index = len(*q)
	*q = append(*q, l)
}

func (q *dueQueue) Pop() any {
	old := *q
	n := len(old)
	l := old[n-1]
	old[n-1] = nil // let the GC reclaim the loan
	l.index = -1
	*q = old[:n-1]
	return l
}

func main() {
	day := func(d int) time.Time { return time.Date(2026, time.November, d, 0, 0, 0, 0, time.UTC) }
	q := &dueQueue{}
	heap.Init(q)

	loans := map[string]*Loan{
		"dune":      {Member: "ann", Book: "Dune", Due: day(20)},
		"emma":      {Member: "bob", Book: "Emma", Due: day(5)},
		"ulysses":   {Member: "cat", Book: "Ulysses", Due: day(12)},
		"dubliners": {Member: "dan", Book: "Dubliners", Due: day(30)},
	}
	for _, k := range []string{"dune", "emma", "ulysses", "dubliners"} {
		heap.Push(q, loans[k])
	}

	fmt.Println("next due:", (*q)[0].Book, (*q)[0].Due.Format("Jan 2"))

	// Renewal: change the key, then restore the heap invariant with Fix.
	loans["emma"].Due = day(25)
	heap.Fix(q, loans["emma"].index)

	// Remove an arbitrary element by its index.
	heap.Remove(q, loans["ulysses"].index)

	for q.Len() > 0 {
		l := heap.Pop(q).(*Loan)
		fmt.Println(l.Due.Format("Jan 2"), l.Book, l.Member)
	}
}

package main

import (
	"container/heap"
	"fmt"
)

// PQ is a small generic wrapper that hides the any-typed heap API.
type PQ[T any] struct{ h inner[T] }

type inner[T any] struct {
	items []T
	less  func(a, b T) bool
}

func (h inner[T]) Len() int           { return len(h.items) }
func (h inner[T]) Less(i, j int) bool { return h.less(h.items[i], h.items[j]) }
func (h inner[T]) Swap(i, j int)      { h.items[i], h.items[j] = h.items[j], h.items[i] }
func (h *inner[T]) Push(x any)        { h.items = append(h.items, x.(T)) }
func (h *inner[T]) Pop() any {
	n := len(h.items)
	x := h.items[n-1]
	var zero T
	h.items[n-1] = zero
	h.items = h.items[:n-1]
	return x
}

func NewPQ[T any](less func(a, b T) bool) *PQ[T] {
	return &PQ[T]{h: inner[T]{less: less}}
}

func (p *PQ[T]) Push(x T) { heap.Push(&p.h, x) }
func (p *PQ[T]) Pop() T   { return heap.Pop(&p.h).(T) }
func (p *PQ[T]) Len() int { return p.h.Len() }

func main() {

		pq.Push(s)

		fmt.Print(pq.Pop(), " ")

container/list and container/ring

container/list is a doubly linked list. Its zero value is an empty list ready to use, PushFront/PushBack/InsertBefore/InsertAfter return the new *list.Element, and Remove, MoveToFront, MoveToBack, MoveBefore and MoveAfter take an element and run in O(1). An Element exposes Value any, Next() and Prev(). Because the values are any, you assert them back on reading.

The classic use is an LRU cache: a map from key to element for lookup, and a list ordered by recency, where a hit moves the element to the front and an insertion beyond the capacity evicts the back.

container/ring is a circular list: there is no head or tail, every *ring.Ring is an element and a pointer to any of them refers to the whole ring. ring.New(n) builds a ring of n elements, Next, Prev and Move(n) walk it, Do visits every element, Len counts them (in O(n)), and Link/Unlink splice rings together or cut elements out. A ring with a fixed size is a natural bounded history, for example the last three searches:

package main

import (
	"container/list"
	"container/ring"
	"fmt"
)

// lru is a least-recently-used cache of book titles by ISBN.
type lru struct {
	cap   int
	order *list.List // front = most recently used
	items map[string]*list.Element
}

type entry struct{ isbn, title string }

func newLRU(n int) *lru {
	return &lru{cap: n, order: list.New(), items: map[string]*list.Element{}}
}

func (c *lru) Get(isbn string) (string, bool) {
	el, ok := c.items[isbn]
	if !ok {
		return "", false
	}
	c.order.MoveToFront(el)
	return el.Value.(entry).title, true
}

func (c *lru) Put(isbn, title string) {
	if el, ok := c.items[isbn]; ok {
		el.Value = entry{isbn, title}
		c.order.MoveToFront(el)
		return
	}
	c.items[isbn] = c.order.PushFront(entry{isbn, title})
	if c.order.Len() > c.cap {
		last := c.order.Back()
		delete(c.items, last.Value.(entry).isbn)
		c.order.Remove(last)
	}
}

func (c *lru) Keys() []string {
	var keys []string
	for el := c.order.Front(); el != nil; el = el.Next() {
		keys = append(keys, el.Value.(entry).isbn)
	}
	return keys
}

func main() {
	c := newLRU(2)
	c.Put("a", "Dune")
	c.Put("b", "Emma")
	c.Get("a")            // a becomes most recent
	c.Put("c", "Ulysses") // evicts b
	_, okB := c.Get("b")
	fmt.Println(c.Keys(), okB)

	// container/ring: a fixed-size circular buffer of recent searches.
	r := ring.New(3)
	for _, q := range []string{"dune", "emma", "ulysses", "dubliners"} {
		r.Value = q
		r = r.Next()
	}
	r.Do(func(v any) { fmt.Print(v, " ") }) // oldest to newest
	fmt.Println(r.Len())

	// Rotate moves the starting point; Link and Unlink splice rings.
	r = r.Move(1)
	r.Do(func(v any) { fmt.Print(v, " ") })
	fmt.Println()
}

When should you use them? Rarely. Linked lists have poor cache locality and cost one allocation per element, so a slice is faster for almost every workload; list earns its place when you need O(1) removal or reordering of an element you already hold, as in the LRU cache. ring suits a fixed-size buffer where overwriting the oldest entry is the policy, although a slice with an index modulo its length does the same with fewer allocations. Neither has a generic version in the standard library.

What the output teaches:

  • Float division by zero does not panic. 1/zero is +Inf, zero/zero is NaN. Integer division by zero does panic.

  • NaN is never equal to anything, including itself, so x == x is false for a NaN. Use math.IsNaN. Using a NaN as a map key creates entries that can never be found again; see Maps.

  • % versus math.Mod: both keep the sign of the dividend (-7 % 3 is -1), unlike Python; math.Remainder follows IEEE 754 and returns 1 for Remainder(7, 3) because 7/3 rounds to 2.

  • Equality of floats: 0.1 + 0.2 computed from variables is not 0.3. Compare with a tolerance (absolute, relative, or both) suited to the problem. The constant expression 0.1 + 0.2 is exactly 0.3 because constant arithmetic is exact; the example uses variables to show the run-time behavior.

  • Integer overflow wraps silently for fixed-size integers (int8 127 plus 1 is -128). The language has no overflow trap and no checked arithmetic; detect it before it happens, as addOverflows does, or with math/bits for unsigned values (below).

  • Signed zero: -0 exists and math.Min(-0, 0) returns -0; cmp.Compare and == treat both zeros as equal.

Observations:

  • QuoRem truncates toward zero like Go’s / and % (-7/2 is -3, remainder -1); DivMod uses Euclidean division so the remainder is never negative (-4 and 1).

  • Int.Divide is new in Go 1.27. It takes an explicit RoundingMode (Trunc, Floor, Round or Ceil) and writes the quotient and the remainder together, so you no longer assemble floor or ceiling division from QuoRem and sign fix-ups. The remainder satisfies r = x - y*q for the chosen rounding. Round is the same constant as ToNearestEven; Trunc prints as ToZero, Floor as ToNegativeInf and Ceil as ToPositiveInf, which is why the output uses those names.

  • Exp(x, y, m) with a non-nil modulus is modular exponentiation; with nil it is plain x**y. GCD, ModInverse and ProbablyPrime(n) (which has a negligible false-positive chance for n = 20) are the number-theory basics.

  • Rat keeps results in lowest terms and prints 1/2; FloatString(5) rounds to five decimals. Use it for money-like quantities where float rounding is unacceptable.

  • A big.Float created with SetPrec(200) has 200 bits of mantissa; NewFloat gives 53 bits, which is float64 precision.

  • Formatting verbs: %d, %x, %s, %v work on *big.Int, which implements fmt.Formatter; print the pointer, not the struct.

  • Operations on big numbers allocate and are orders of magnitude slower than int64; use them only when the range requires it.

Big numbers also arise for correctness: if you only need to know that a 64-bit result would overflow, math/bits does it without allocation.

The top-level functions (rand.IntN, rand.Float64, rand.Shuffle, …​) use a randomly seeded generator that the runtime provides; they are safe for concurrent use and need no setup. To get a reproducible sequence, build your own generator from a source:

  • rand.NewPCG(seed1, seed2): a small, very fast generator with 128 bits of state;

  • rand.NewChaCha8(seed): a ChaCha8-based generator with a 32-byte seed, designed to resist prediction. It is what the runtime uses for the top-level functions.

A *rand.Rand (made with rand.New(source)) is not safe for concurrent use. Give each goroutine its own, or guard it with a mutex.

import (
	"fmt"
	"time"
	"uuid"

// createdAt extracts the millisecond timestamp stored in a version 7 UUID.
func createdAt(u uuid.UUID) (time.Time, bool) {
	if u[6]>>4 != 7 {
		return time.Time{}, false
	}
	var ms int64
	for _, b := range u[:6] {
		ms = ms<<8 | int64(b)
	}
	return time.UnixMilli(ms), true

hash/maphash

hash/maphash hashes byte sequences and comparable values to a uint64 with a seeded, collision-resistant function. It is the building block for your own hash tables, Bloom filters and sharding. It is not cryptographic and not stable: a Seed exists only in one process and cannot be saved, so never store or compare hashes across runs.

  • maphash.MakeSeed() creates a random Seed. Give each data structure its own seed; a different seed is a different hash function, which defeats hash-flooding denial-of-service attacks.

  • maphash.String(seed, s) and maphash.Bytes(seed, b) hash text and bytes in one call.

  • maphash.Comparable(seed, v) (Go 1.24) hashes any comparable value so that v1 == v2 implies equal hashes.

  • maphash.Hash is the incremental form: SetSeed, Write, WriteString, WriteByte, Sum64, Reset, and WriteComparable for non-byte data. It is not safe for concurrent use (a Seed is).

  • Go 1.27: the interface maphash.Hasher[T] (methods Hash(*Hash, T) and Equal(x, y T) bool) is the contract between a hash-based container and its elements, and maphash.ComparableHasher[T] is the ready-made implementation for comparable types that uses ==. A Hasher can define an equivalence other than ==: case-insensitive strings, pointers compared by their fields, even types that are not comparable.

The contract has two rules: values that are Equal must produce the same hash, and a Hasher must be stateless. The program below builds a minimal generic hash set on top of the interface and plugs in a case-insensitive hasher:

package main

import (
	"fmt"
	"hash/maphash"
	"strings"
)

// CaseInsensitive is a maphash.Hasher[string] that ignores letter case.
type CaseInsensitive struct{}

func (CaseInsensitive) Hash(h *maphash.Hash, s string) { h.WriteString(strings.ToLower(s)) }
func (CaseInsensitive) Equal(x, y string) bool         { return strings.ToLower(x) == strings.ToLower(y) }

// HashSet is a minimal open-hashing set built on any maphash.Hasher.
type HashSet[T any] struct {
	hasher  maphash.Hasher[T]
	seed    maphash.Seed
	buckets map[uint64][]T
}

func NewHashSet[T any](h maphash.Hasher[T]) *HashSet[T] {
	return &HashSet[T]{hasher: h, seed: maphash.MakeSeed(), buckets: map[uint64][]T{}}
}

func (s *HashSet[T]) sum(v T) uint64 {
	var h maphash.Hash
	h.SetSeed(s.seed)
	s.hasher.Hash(&h, v)
	return h.Sum64()
}

func (s *HashSet[T]) Add(v T) bool {
	k := s.sum(v)
	for _, e := range s.buckets[k] {
		if s.hasher.Equal(e, v) {
			return false
		}
	}
	s.buckets[k] = append(s.buckets[k], v)
	return true
}

func (s *HashSet[T]) Has(v T) bool {
	for _, e := range s.buckets[s.sum(v)] {
		if s.hasher.Equal(e, v) {
			return true
		}
	}
	return false
}

	Prefix string
	Number int
}

func main() {
	seed := maphash.MakeSeed()
	h1 := maphash.String(seed, "Dune")
	h2 := maphash.Bytes(seed, []byte("Dune"))
	fmt.Println(h1 == h2, h1 == maphash.String(seed, "dune"))

	// Comparable hashes any comparable value consistently with ==.
	k := ISBNKey{"978", 441013593}
	fmt.Println(maphash.Comparable(seed, k) == maphash.Comparable(seed, ISBNKey{"978", 441013593}))

	// A different seed is a different hash function (hash-flooding resistance),
	// and a seed cannot be saved: the numbers differ from run to run.
	fmt.Println(maphash.String(seed, "Dune") == maphash.String(maphash.MakeSeed(), "Dune"))

	var a, b maphash.Hash
	a.SetSeed(seed)
	b.SetSeed(seed)

	b.WriteString("ne")

	set := NewHashSet[string](CaseInsensitive{})

	keys := NewHashSet[ISBNKey](maphash.ComparableHasher[ISBNKey]{})
	fmt.Println(keys.Add(k), keys.Add(k), keys.Has(ISBNKey{"978", 1}))

unique

unique.Make(v) returns a unique.Handle[T] for a comparable value v. Two handles are equal if and only if the values are equal, and comparing handles is a pointer comparison, not a comparison of the (possibly long) values. h.Value() returns a copy of the original. This is interning (canonicalizing): many equal strings or structs share one stored copy. The unique values are kept in a global table that does not keep them alive when no handle refers to them anymore.

package main

import (
	"fmt"
	"strings"
	"unique"
	"unsafe"
)

// Genre is interned: copies are one pointer-sized handle, and comparing two
// genres is a pointer comparison instead of a string comparison.
type Genre = unique.Handle[string]

type Book struct {
	Title string
	Genre Genre
}

func main() {
	genres := []string{"Science Fiction", "science fiction", "Novel"}
	var books []Book
	for i, g := range genres {
		books = append(books, Book{Title: fmt.Sprint("book", i), Genre: unique.Make(g)})
	}
	books = append(books, Book{Title: "book3", Genre: unique.Make(strings.Clone("Science Fiction"))})

	fmt.Println(books[0].Genre == books[1].Genre) // different strings, different handles
	fmt.Println(books[0].Genre == books[3].Genre) // same value, same handle
	fmt.Println(books[0].Genre.Value(), unsafe.Sizeof(books[0].Genre))
}

A handle is a single pointer (8 bytes on 64-bit platforms) regardless of the size of T, so a field like Genre costs less than a string header (16 bytes) and compares in one instruction. The trade-off is a map lookup per Make, so interning pays off for values that repeat a lot and are compared often (genres, host names, log keys, net/netip for IPv6 zone names). For values that are mostly distinct, it only adds cost. How the cleanup of unreferenced entries works, and the sibling packages weak and runtime.AddCleanup, are on Cleanups, Weak Pointers and Interning.

Where the books are outdated or wrong

  • Bodner (Learning Go, chapter 3) predates the slices, maps and cmp packages, so the hand-written loops for copying, comparing, deleting and ordered keys, and the sort.Slice idiom, have a one-line replacement today (slices.Clone, slices.Equal, slices.Sort, slices.Sorted(maps.Keys(m))). Its chapter-15 discussion of what generics would bring is answered by these packages and by iter.Seq (see Iterators and Range-over-Func).

  • Both books describe the math/rand default generator as having a fixed seed that you must replace with rand.Seed. Since Go 1.20 the default generator is seeded randomly, rand.Seed has been deprecated since then and has been a no-op since Go 1.24 (unless GODEBUG=randseednop=0), and new code uses math/rand/v2 (Go 1.22): rand.IntN, rand.N, and for reproducibility a local rand.New(rand.NewPCG(a, b)). For secrets, the books' mention of crypto/rand stands, and rand.Text (Go 1.24) now covers token generation in one call.

  • Vivien (Learning Go Programming) predates math.FMA, the generic slices, maps and cmp helpers, math/rand/v2 and, in math/big, the Int.Divide rounding-mode method (1.27). The width of int is not 32 bits on 64-bit platforms (it has been 64 bits there since Go 1.1); math.MaxInt and bits.UintSize report the real size.

  • Neither book covers unique (1.23), maphash.Comparable (1.24), the maphash.Hasher interface (1.27) or the new uuid package (1.27). Before Go 1.27 the usual answer for UUIDs was a third-party module; code that still imports one keeps working, and migrating is a type change because the two UUID types are unrelated arrays of 16 bytes.

  • Code that sorts a plain slice with a hand-written sort.Interface type, or with sort.Slice, is superseded by slices.SortFunc with cmp.Compare.
