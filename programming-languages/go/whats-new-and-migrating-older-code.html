What’s New and Migrating Older Code

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Go 1.27 (go1.27.2), checked on 2026-10-18; every go.mod shown has the line go 1.27 unless the example is about an older language version. Go 1.28 is not released: it is expected in February 2027, no release candidate exists, and the go.dev/doc/go1.28 page is an empty draft, so it appears here only as "upcoming". The page has three jobs. First, a release-by-release record of what changed in the language, the tools, the runtime and the standard library from Go 1.18 to Go 1.27. Second, a practical guide to migrating older code, blog posts and tutorials to today’s idioms, with the real output of the commands that do most of the work (go vet, go fix, the godebug directive). Third, one table that collects every statement in the books this reference consulted that is outdated or wrong, with the version in which the situation changed.

It is the last page of the section on purpose: every topic page already has a short "where the books are outdated" passage, and this page gathers them. The version policy and the go and toolchain lines are the subject of Toolchain Versions and Compatibility; the tools used for migration are described in Formatting, vet, fix and Static Analysis. The idioms that replace the old ones are on Idioms, Style and Code Review and Common Mistakes and Gotchas. For first steps with the language see Getting Started.

Older code is shown here only in passages labelled Older code you may meet. It is shown so that you can recognise it and replace it; it is not a recommendation. All other pages of the section use the current forms. Every program and command below was run with go1.27.2 on darwin/arm64; compiler, vet and go fix messages are copied from real runs. Timings and random numbers are machine-specific, as noted where they appear. Unless a different go line is shown, the module is:

How "since version" works

Three mechanisms decide whether a change applies to your code, and they are easy to confuse.

Mechanism What it controls Example

The toolchain (go version)

The compiler, linker, go command, runtime and standard library you run. New library functions and new tools appear with it.

slices.Concat exists in every toolchain from 1.22 on, whatever the module says.

The go line of go.mod (or //go:build go1.N in a file)

The language version of each package and the minimum toolchain. A new language feature is rejected below its version, and a few behavior changes depend on it.

min(3, 1, 2) fails to compile with go 1.20; per-iteration loop variables apply only with go 1.22 or later.

GODEBUG defaults, derived from the go line

Run-time behavior changes that could break programs. The go line selects the defaults that were current for that version, and a godebug directive or //go:debug comment overrides single settings.

httpmuxgo121=1 restores the old ServeMux; randseednop=0 makes rand.Seed work again.

The compiler enforces the language version. This is the real message for a builtin from 1.21 in a module that says go 1.20:

./m.go:3:16: built-in min requires go1.21 or later (-lang was set to go1.20; check go.mod)

Library symbols are not checked by the compiler, but since Go 1.27 go test runs the stdversion vet analyzer by default (go vet has run it since Go 1.23). With go 1.21 in go.mod and a call to slices.Concat, which arrived in Go 1.22, go vet reports:

main.go:9:16: slices.Concat requires go1.22 or later (module is go1.21)

The program still builds and runs on a newer toolchain; the report tells you the code would not build on the toolchain the go line promises. The analyzer only reasons about modules that declare go 1.21 or later, because earlier go lines were advisory.

Release by release

The tables list what a working programmer is most likely to meet. Each release also fixed bugs, added ports and sharpened vet and the compiler; the linked release notes are the complete record. "GA" means generally available after an experiment or preview.

Go 1.18 (2022-03-15)

Area Change

Language

Type parameters on functions and types, the predeclared any and comparable, constraint interfaces with unions and ~T; a generic function can be instantiated explicitly or inferred. Several limits shipped at first (for example no type declarations inside generic functions) and were lifted later. See Generics.

Tools

Native fuzzing (go test -fuzz); go work workspaces (go.work); go get stops building and installing packages, which go install pkg@version does; the build embeds version control information (go version -m); GOAMD64 microarchitecture levels.

Runtime

Slice capacity growth uses a threshold of 256 and a smoother formula instead of doubling to 1024; the register ABI reaches arm64 and ppc64.

Library

strings.Cut and bytes.Cut, net/netip, sync.Mutex.TryLock, reflect.Pointer, debug/buildinfo.

Go 1.19 (2022-08-02)

Area Change

Language

No language change. The Memory Model was revised (still the version of June 6, 2022 today): sequentially consistent atomics are defined, and the model aligns with C, C++ and Rust. See Memory Model and Data Races.

Tools

//go:build unix constraint; doc comments gain links, lists and headings, and gofmt reformats them. See Documentation and Doc Comments.

Runtime

The soft memory limit GOMEMLIMIT (and debug.SetMemoryLimit); initial goroutine stack size adapts to the average; jump tables for large switch statements.

Library

Typed atomics (atomic.Int64, atomic.Pointer[T] and friends), sort switches to pattern-defeating quicksort, url.JoinPath, fmt.Append family, flag.TextVar, os/exec refuses relative-path results (ErrDot).

Go 1.20 (2023-02-01)

Area Change

Language

Conversion from a slice to an array (and to an array pointer since 1.17); unsafe.SliceData, unsafe.String, unsafe.StringData; an interface type that is not strictly comparable (such as any) now satisfies comparable; struct and array comparison is specified to stop at the first difference.

Tools

Profile-guided optimization preview; coverage profiles for whole programs (go build -cover, GOCOVERDIR); the standard library is no longer shipped precompiled; go test -skip.

Runtime

math/rand seeds its global generator randomly at start-up; rand.Seed is deprecated.

Library

errors.Join and several %w verbs in one fmt.Errorf; context.WithCancelCause; http.ResponseController; time.DateTime, DateOnly, TimeOnly and Time.Compare; strings.CutPrefix and CutSuffix; exec.Cmd.Cancel and WaitDelay; crypto/ecdh; the experimental arena package.

Go 1.21 (2023-08-08)

Area Change

Language

Builtins min, max and clear; panic(nil) now produces a *runtime.PanicNilError (GODEBUG=panicnil=1 restores the old result); package initialization order is specified precisely; type inference handles generic functions passed as arguments and untyped constants better.

Tools

The go line becomes a strict minimum, the toolchain line and GOTOOLCHAIN let the go command download the toolchain a module needs; GODEBUG defaults follow the go line; PGO GA (default.pgo is picked up automatically with -pgo=auto); the wasip1 port and //go:wasmimport; Windows 10 or later required.

Library

New packages log/slog, slices, maps, cmp, testing/slogtest; sync.OnceFunc, OnceValue and OnceValues; context.WithoutCancel, AfterFunc, WithDeadlineCause and WithTimeoutCause; errors.ErrUnsupported; runtime.Pinner; reflect.Value.Clear.

Go 1.22 (2024-02-06)

Area Change

Language

Each iteration of a for loop has its own copy of the loop variables, for modules that say go 1.22 or later; for i := range 10 ranges over an integer; range-over-func is available as GOEXPERIMENT=rangefunc only.

Tools

go/version; go work vendor; vet checks for time.Since in defer, append with a single argument, and slog argument mismatches; go test -cover reports packages without tests; vet stops reporting loop-variable captures in files that require Go 1.22.

Runtime

A redesigned execution tracer (lower overhead, streaming, per-thread buffers); metadata layout changes cut CPU overhead 1 to 3 percent; PGO enables inlining and devirtualization improvements.

Library

math/rand/v2 (and a ChaCha8 and PCG generator); ServeMux accepts methods and wildcards in patterns, with Request.PathValue; http.ServeFileFS, FileServerFS; slices.Concat, Insert always panics on a bad index, Delete/Compact/Replace zero the vacated tail; cmp.Or; database/sql.Null[T]; reflect.TypeFor.

Go 1.23 (2024-08-13)

Area Change

Language

Range over function types (func(yield func(K, V) bool)), with the standard iter.Seq and iter.Seq2 and iter.Pull. See Iterators and Range-over-Func.

Tools

The godebug directive in go.mod and //go:debug comments; Go telemetry (local by default); go mod tidy -diff; go env -changed; restrictions on //go:linkname pulls into the standard library; the stdversion vet analyzer.

Runtime

Timers and tickers that are no longer referenced become collectable even if not stopped, and their channels are unbuffered (synchronous) in modules that say go 1.23 or later; GODEBUG=asynctimerchan=1 could undo it until Go 1.27 removed the setting.

Library

unique (canonicalizing handles), structs.HostLayout, iterator forms in slices and maps (All, Values, Collect, Sorted, Chunk, Keys, Insert), slices.Repeat, os.CopyFS, sync.Map.Clear, path/filepath.Localize, reflect.Value.Seq.

Go 1.24 (2025-02-11)

Area Change

Language

Generic type aliases (type Set[T comparable] = map[T]struct{}).

Tools

tool directives in go.mod, go get -tool, go tool runs them, the tool meta-pattern; go build -json and structured go test -json build output; GOAUTH for private module fetches; the main module’s version is stamped into binaries (+dirty for uncommitted changes); GOCACHEPROG; cgo annotations #cgo noescape and #cgo nocallback; vet gains tests and a non-constant format string check.

Runtime

Swiss-table maps, a new internal mutex and cheaper small-object allocation (2 to 3 percent less CPU on average); runtime.AddCleanup.

Library

os.Root; testing.B.Loop, T.Context, T.Chdir; weak pointers; crypto/mlkem, crypto/hkdf, crypto/pbkdf2, crypto/sha3; the FIPS 140-3 module; omitzero for encoding/json; strings.Lines, SplitSeq, FieldsSeq; maphash.Comparable; rand.Text; //go:wasmexport and a WASI reactor mode; the experimental testing/synctest.

Go 1.25 (2025-08-12)

Area Change

Language

No change affecting programs. The notion of core types was removed from the spec in favor of dedicated prose for each operation.

Tools

ignore directive in go.mod; go doc -http; go version -m -json; the work package pattern; vet analyzers waitgroup (misplaced Add) and hostport (Sprintf("%s:%d") addresses); go build -asan leak detection; module roots in repository subdirectories; the go command stops adding a toolchain line when it updates the go line.

Runtime

GOMAXPROCS respects cgroup CPU limits and is updated at run time; the Green Tea collector as an experiment; the trace flight recorder; a nil-check bug introduced in 1.21 is fixed (programs that used a result before checking its error can now panic correctly); DWARF 5; unhandled re-panics print [recovered, repanicked].

Library

sync.WaitGroup.Go; testing/synctest GA; encoding/json/v2 experiment; http.CrossOriginProtection; T.Attr and T.Output; hash.Cloner; reflect.TypeAssert; more os.Root methods.

Go 1.26 (2026-02-10)

Area Change

Language

new takes an expression (new(yearsSince(born)) yields a *int holding the value); a generic type may refer to itself in its own type parameter list (type Adder[A Adder[A]] interface{ Add(A) A }).

Tools

go fix rewritten: it is now the home of the modernizers, shares the analysis framework with go vet, and supports //go:fix inline; go mod init is documented to write a lower go line (see Starting a module and the version in the go line for what go1.27.2 actually wrote); cmd/doc and go tool doc removed (use go doc); the pprof web UI opens on the flame graph.

Runtime

Green Tea GC enabled by default (10 to 40 percent less GC overhead in GC-heavy programs; GOEXPERIMENT=nogreenteagc opt-out, which the 1.26 notes said was expected to go in 1.27); cgo calls about 30 percent cheaper; randomized heap base address on 64-bit platforms; the goroutine leak profile as an experiment.

Library

errors.AsType[T]; slog.NewMultiHandler; crypto/hpke; bytes.Buffer.Peek; io.ReadAll about twice as fast with half the allocation; ServeMux trailing-slash redirects use status 307; T.ArtifactDir; reflect iterators (Type.Fields, Type.Methods, Value.Fields); os/signal.NotifyContext cancels with a cause naming the signal; testing/cryptotest; the experimental simd/archsimd and runtime/secret.

Go 1.27 (2026-08-19)

Area Change

Language

Generic methods (a method declaration may declare its own type parameters; interface methods may not, and generic methods cannot implement interface methods); a struct literal key may be any valid field selector, so promoted fields can be named; function type inference applies wherever a generic function is assigned or converted to a matching function type.

Tools

go test runs the stdversion vet check; go test -json output lines get an OutputType; go doc pkg@version and go doc -ex; new modernizers atomictypes, embedlit, slicesbackward, unsafefuncs, and waitgroup renamed waitgroupgo; go mod tidy merges duplicate require blocks into at most two for go 1.27 modules; gofmt alignment fix that can change whitespace in a few files; bzr support removed; response files (@file) for the compile, link, asm, cgo, cover and pack tools; go tool trace -http=:6060 listens on localhost only; vet reports wrapping a pointer to an error type with %w.

Runtime

Size-specialized allocation (up to 30 percent cheaper for small objects, about 60 KB of binary growth, GOEXPERIMENT=nosizespecializedmalloc opt-out expected to go in 1.28); the goroutine leak profile GA (goroutineleak, /debug/pprof/goroutineleak); tracebacks include pprof goroutine labels for go 1.27 modules; the asynctimerchan setting removed, so timer channels are always synchronous; macOS 13 or later required.

Library

encoding/json/v2 and encoding/json/jsontext GA with encoding/json reimplemented on top of v2 (opt-out GOEXPERIMENT=nojsonv2); uuid; crypto/mldsa; strings.CutLast and bytes.CutLast; Rand.N as a generic method in math/rand/v2; httptest.NewTestServer for synctest; url.URL.Clone; synctest.Sleep; maphash.Hasher; database/sql.ConvertAssign; Unicode 17; the experimental simd and simd/archsimd.

Go 1.28 (upcoming)

Go 1.28 is not released. The release notes at go.dev/doc/go1.28 are an empty stub on 2026-10-18, so nothing can be documented from them. Planning discussions mention a url.MustParse, an HTTP QUERY method and iterator methods in regexp and flag, but a feature is not part of Go until the release notes say so. When 1.28 ships, the opt-outs that the 1.27 notes call temporary (such as GOEXPERIMENT=nosizespecializedmalloc) are expected to disappear, and Go 1.26 leaves support.

A tour of the new features in one program

The program below uses one feature from each release 1.18 to 1.27 and prints a line per release. It needs a toolchain of 1.27 or later (the generic method and the uuid package are 1.27 features), so its go.mod says go 1.27.

package main

import (
	"errors"
	"fmt"
	"iter"
	"maps"
	"math/rand/v2"
	"slices"
	"strings"
	"sync"
	"sync/atomic"
	"uuid"
)

// Book is the running example from the shelf module.
type Book struct {
	Title string
	Pages int
}

// Set is a generic alias (1.24) for a map used as a set.
type Set[T comparable] = map[T]struct{}

// Shelf holds books.
type Shelf struct{ books []Book }

// Project is a generic method (1.27): the method declares its own type parameter.
func (s *Shelf) Project[T any](f func(Book) T) []T {
	out := make([]T, 0, len(s.books))
	for _, b := range s.books {
		out = append(out, f(b))
	}
	return out
}

// Pages is an iterator (1.23).
func (s *Shelf) Pages() iter.Seq[int] {
	return func(yield func(int) bool) {
		for _, b := range s.books {
			if !yield(b.Pages) {
				return
			}
		}
	}
}

// Map is a generic function (1.18).
func Map[T, U any](in []T, f func(T) U) []U {
	out := make([]U, 0, len(in))
	for _, v := range in {
		out = append(out, f(v))
	}
	return out
}

type notFound struct{ title string }

func (e *notFound) Error() string { return "not found: " + e.title }

func main() {
	shelf := &Shelf{books: []Book{{"Dune", 612}, {"Emma", 474}, {"Ulysses", 730}}}

	// 1.18: generics, strings.Cut
	fmt.Println("1.18", Map(shelf.books, func(b Book) int { return len(b.Title) }))
	before, after, _ := strings.Cut("978-0141439518", "-")
	fmt.Println("1.18 cut:", before, after)

	// 1.19: typed atomics
	var loans atomic.Int64
	loans.Add(2)
	fmt.Println("1.19", loans.Load())

	// 1.20: errors.Join
	err := errors.Join(errors.New("title missing"), errors.New("isbn invalid"))
	fmt.Printf("1.20 %q\n", err.Error())

	// 1.21: min, max, clear, slices, maps
	fmt.Println("1.21", min(3, 1, 2), max(2.5, 1), slices.Max([]int{4, 9, 2}))
	m := map[string]int{"a": 1}
	clear(m)
	fmt.Println("1.21 cleared:", len(m))

	// 1.22: range over int and math/rand/v2 with an explicit seed
	r := rand.New(rand.NewPCG(1, 2))
	for i := range 3 {
		fmt.Print("1.22 ", i, " ", r.IntN(10), "; ")
	}
	fmt.Println()

	// 1.23: range over func, iterator helpers
	fmt.Println("1.23", slices.Collect(shelf.Pages()), slices.Sorted(maps.Keys(map[string]int{"b": 1, "a": 2})))

	// 1.24: generic alias, strings.SplitSeq
	s := Set[string]{"Dune": {}}
	for part := range strings.SplitSeq("a,b,c", ",") {
		fmt.Print(part, " ")
	}
	fmt.Println("1.24 set size", len(s))

	// 1.25: WaitGroup.Go
	var wg sync.WaitGroup
	var total atomic.Int64
	for _, b := range shelf.books {
		wg.Go(func() { total.Add(int64(b.Pages)) })
	}
	wg.Wait()
	fmt.Println("1.25 pages:", total.Load())

	// 1.26: new(expr) and errors.AsType
	pages := new(len(shelf.books))
	var wrapped error = fmt.Errorf("lookup: %w", &notFound{"Persuasion"})
	if nf, ok := errors.AsType[*notFound](wrapped); ok {
		fmt.Println("1.26", *pages, nf.title)
	}

	// 1.27: generic method, strings.CutLast, uuid
	fmt.Println("1.27", shelf.Project(func(b Book) string { return strings.ToUpper(b.Title) }))
	dir, file, _ := strings.CutLast("catalog/books/dune.json", "/")
	fmt.Println("1.27 cutlast:", dir, file)
	id, err := uuid.Parse("123e4567-e89b-42d3-a456-426614174000")
	fmt.Println("1.27 uuid:", id, err, len(uuid.New().String()))
}

Migrating older code: the plan

Migrating is mostly mechanical, and the toolchain does most of it. The order below keeps every step small enough to review and to revert.

Step Command or action Why this order

1

Commit a clean tree and run the tests with the toolchain you have now.

You need a green baseline to tell a migration problem from an old one.

2

Install the current toolchain (or let GOTOOLCHAIN=auto fetch it) and run the tests again without touching go.mod.

A new toolchain with an old go line keeps the old language rules and the old GODEBUG defaults, so this step isolates library and tool changes.

3

go vet ./...

Fix what vet reports first. The checks are cheap and go test runs a subset of them anyway.

4

Raise the go line (go get go@1.27 or edit go.mod) and run the tests.

This turns on the language and GODEBUG changes for your module: per-iteration loop variables, the new ServeMux, timers and the rest of the table in the GODEBUG section.

5

go fix -diff ./..., review, then go fix ./..., then gofmt -l . and the tests again.

The modernizers rewrite old idioms without changing behavior. Run it on a clean tree and commit the result on its own.

6

Replace the things no tool can rewrite: third-party routers, log calls, the b.N loops, header-cast unsafe code, golint in CI.

These need judgement; the sections below show the current form of each.

7

Remove godebug entries that were only a stopgap.

Each entry is a deferral, not a fix. go version -m shows the settings the binary was built with.

Habit by habit: older form and current form

GOPATH to modules

Older code you may meet: code that lives under $GOPATH/src/<import path> and is built by go build with no go.mod. Go 1.11 introduced modules, Go 1.13 made the proxy and checksum database the default way to fetch them, and Go 1.16 made module mode the default. Inside a directory without go.mod, the real go1.27.2 result is:

$ go build .
go: go.mod file not found in current directory or any parent directory; see 'go help modules'

The old mode still exists as an explicit opt-out, for archaeology only. With GO111MODULE=off and a GOPATH that holds the package under src/, the program builds and runs:

$ GO111MODULE=off GOPATH=$PWD/../.. go run .
built in GOPATH mode

The current form is a module anywhere on disk, created with go mod init. GOPATH is now only the default location of the module cache ($GOPATH/pkg/mod) and of the binaries go install writes ($GOPATH/bin); on this machine go env GOPATH prints /Users/albertoirurueta/go. See Modules and Dependency Management and Workspaces, Versioning and Publishing for go work, which replaced the habit of keeping several repositories side by side under one GOPATH (Go 1.18).

b.N loops to b.Loop

Older code you may meet: a benchmark body written as for i := 0; i < b.N; i++ { ... }. It is not wrong, but the compiler may optimize away the work if the result is unused, the framework runs the function several times with growing b.N (so setup runs repeatedly), and forgetting the loop silently measures nothing. Go 1.24 added b.Loop(): the function runs once per -count, setup and cleanup outside the loop execute once, and the compiler keeps the loop body alive. The two versions side by side (no modernizer rewrites this; it is a manual change):

Third-party routers to ServeMux patterns

Older code you may meet: a router package added to a project only because the standard ServeMux matched fixed paths and prefixes and ignored the request method. Since Go 1.22 patterns can name a method, a path wildcard and a rest-of-path wildcard, and Request.PathValue reads the value. A method mismatch becomes a 405 automatically:

package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /books/{isbn}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "book %s\n", r.PathValue("isbn"))
	})
	mux.HandleFunc("GET /files/{path...}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintf(w, "file %s\n", r.PathValue("path"))
	})
	mux.HandleFunc("GET /{$}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "home")
	})

	for _, c := range []struct{ method, target string }{
		{"GET", "/"},
		{"GET", "/books/9780141439518"},
		{"POST", "/books/9780141439518"},
		{"GET", "/files/a/b/c.txt"},
		{"GET", "/nothing"},
	} {
		rec := httptest.NewRecorder()
		mux.ServeHTTP(rec, httptest.NewRequest(c.method, c.target, nil))
		fmt.Printf("%-4s %-22s -> %d %q\n", c.method, c.target, rec.Code, rec.Body.String())
	}
}

The patterns {path...} (match the rest of the path) and {$} (match exactly the trailing slash) cover what routers added. Conflicting patterns panic at registration, not at request time. Go 1.26 changed the trailing-slash redirect of ServeMux to status 307, which keeps the method of a POST. A router is still a sensible choice when you need regular expressions, route groups or generated documentation; it is no longer needed for method and parameter routing. The old behavior is a GODEBUG away: with httpmuxgo121=1 the same GET /books/{isbn} pattern in the earlier example no longer matches as a wildcard, and the request returns 404 404 page not found. log to slog

Older code you may meet: the log package with Printf-style messages that bake the fields into text, so a line like lent isbn=... member=... has to be parsed back into fields by whatever collects the logs. Go 1.21 added log/slog, with leveled, structured records and pluggable handlers (text, JSON, or your own), and keeps the old API working by routing it through the same handler:

package main

import (
	"log"
	"log/slog"
	"os"
)

func main() {
	// Older style: a formatted line, with the fields baked into the message.
	old := log.New(os.Stdout, "", 0)
	old.Printf("lent isbn=%s member=%d", "9780141439518", 42)

	// Current style: a message plus typed key/value attributes.
	opts := &slog.HandlerOptions{ReplaceAttr: func(groups []string, a slog.Attr) slog.Attr {
		if a.Key == slog.TimeKey && len(groups) == 0 {
			return slog.Attr{} // drop the time so the output is stable
		}
		return a
	}}
	logger := slog.New(slog.NewTextHandler(os.Stdout, opts))
	logger.Info("lent", "isbn", "9780141439518", "member", 42)

	// Bridge: code that still calls log.Printf now flows through the slog handler.
	slog.SetDefault(logger)
	log.Printf("legacy call isbn=%s", "9780141439518")

	jsonLogger := slog.New(slog.NewJSONHandler(os.Stdout, opts))
	jsonLogger.Warn("overdue", slog.Group("loan", slog.String("isbn", "9780141439518"), slog.Int("days", 3)))
}

JSON v1 to v2

Older code you may meet: encoding/json only. In Go 1.27 the package is still there and still the default, but it is now implemented on top of encoding/json/v2, and the new package and its low-level companion encoding/json/jsontext are generally available (a Go 1.25 and 1.26 experiment before that; GOEXPERIMENT=nojsonv2 selects the original implementation and is expected to go away). The v2 defaults are stricter. This program runs the same inputs through both packages:

package main

import (
	"encoding/json"
	jsonv2 "encoding/json/v2"
	"fmt"
)

type Book struct {
	Title   string   `json:"title"`
	Authors []string `json:"authors"`
	Pages   int      `json:"pages,omitzero"`
}

func main() {
	b := Book{Title: "Dune"}

	v1, _ := json.Marshal(b)
	v2, _ := jsonv2.Marshal(b)
	fmt.Println("v1 nil slice:", string(v1))
	fmt.Println("v2 nil slice:", string(v2))

	// A key that differs only in case: v1 matches it loosely, v2 does not.
	in := []byte(`{"TITLE":"Emma","pages":474}`)
	var a, c Book
	err1 := json.Unmarshal(in, &a)
	err2 := jsonv2.Unmarshal(in, &c)
	fmt.Printf("v1: %+v err=%v\n", a, err1)
	fmt.Printf("v2: %+v err=%v\n", c, err2)

	// Duplicate member names: v1 keeps the last, v2 reports an error.
	dup := []byte(`{"title":"A","title":"B"}`)
	var d1, d2 Book
	e1 := json.Unmarshal(dup, &d1)
	e2 := jsonv2.Unmarshal(dup, &d2)
	fmt.Printf("v1: %q err=%v\n", d1.Title, e1)
	fmt.Printf("v2: %q err=%v\n", d2.Title, e2)

	// Opting back into the old nil-slice rendering while using the v2 API.
	v2old, _ := jsonv2.Marshal(b, jsonv2.FormatNilSliceAsNull(true))
	fmt.Println("v2 + option:", string(v2old))
}

v2 nil slice: {"title":"Dune","authors":[]}
v1: {Title:Emma Authors:[] Pages:474} err=<nil>
v2: {Title: Authors:[] Pages:474} err=<nil>
v1: "B" err=<nil>
v2: "A" err=jsontext: duplicate object member name "title"
v2 + option: {"title":"Dune","authors":null}

Three differences show: a nil slice marshals as [] in v2 and null in v1, member names match case-sensitively in v2 (the TITLE key was ignored), and duplicate names are an error. v2 also rejects invalid UTF-8. Because v1 is now built on v2 with options that preserve its historical behavior, nothing has to change for existing code, but error message texts may differ. Migrating gradually is supported: pass v2 options to get v1 behavior one difference at a time, then drop them. The official migration guide lists all the differences and options. See encoding/json.

GODEBUG settings that preserve old behavior

A change to run-time behavior that could break a working program ships with a GODEBUG setting, so that the new toolchain can keep behaving the old way. The rules (Go 1.21 and later) are:

  • A setting that was added in Go 1.N has, for each Go version, a default; the go line of the main module picks the defaults of that version. A go 1.20 module on a 1.27 toolchain behaves like Go 1.20 for every setting that exists.

  • A project overrides single settings in three places: a godebug directive in go.mod (Go 1.23), a //go:debug comment in a package main source file, or the GODEBUG environment variable at run time (which wins).

  • go version -m binary prints the DefaultGODEBUG the binary was built with, which is how you audit a deployed program.

  • Settings are kept for at least two years (four releases) and some for much longer; the policy permits removing them later. Since Go 1.27 the go command refuses a removed setting only if it is set to an old value, so programs that set a removed setting to its final default keep building.

A go.mod that keeps the pre-1.22 ServeMux while the rest of the module moves on:

How to keep up

  • Read the release notes of each release before you upgrade: go.dev/doc/go1.N is short and has a section per area.

  • Raise the go line one release at a time; the stdversion vet check and go test tell you if a file uses a library symbol your go line does not allow.

  • Run go fix -diff ./... on every upgrade. New modernizers arrive each release (four in 1.27).

  • Keep godebug entries in go.mod with a comment saying why and when to remove them.

  • Check the supported releases (1.27 and 1.26 on 2026-10-18) and plan to leave a release before it falls out of support. Go 1.28 is expected in February 2027, and when it ships Go 1.26 stops receiving fixes.

  • For topic-by-topic detail follow the links in the tables to the page of the section that covers it. The cheat sheet collects the current idioms on one page.
