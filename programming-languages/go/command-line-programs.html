Command-Line Programs

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Go 1.27 (go1.27.2), checked on 2026-10-18; every go.mod shown has the line go 1.27. A Go program is a single static executable that the operating system starts with a list of arguments, an environment, three open streams and a way to deliver signals, and that reports back with an exit status. That is a small contract, and the standard library covers every part of it: os.Args and flag for the arguments, os for the environment and the streams, bufio for efficient line input and output, os/signal for interruption, os/exec for starting other programs and os.Exit for the status. This page covers all of them, shows the traps that each one hides, and finishes by building the cmd/shelf program of the running shelf scenario: search, lend, return, import and export, with exit codes, a testable structure and graceful interruption.

It builds on Functions, Closures and Defer (why os.Exit skips deferred calls), Error Handling (errors.Is/errors.As, which map errors to statuses here) and Context (cancellation, signal.NotifyContext and exec.CommandContext from the context side). The related pages are Packages, Imports and Initialization (the main package and init), I/O, Files and the Filesystem (io.Reader, io.Writer, files), fmt, Strings and Text Processing (Fprintf, Sscanf, text/tabwriter), Structured Logging with slog, encoding/json, The go Command, Builds and Cross-Compilation (-ldflags -X, -trimpath, go install), Testing and net/http Clients and Servers (graceful shutdown of a server). The same ground in other languages is covered in Rust I/O, Files, Processes and Environment and C Input, Output and Files.

The standard library is deliberately enough for most tools, and this page stops there. For a command tree with generated help and shell completion (Cobra) and for terminal user interfaces (Bubble Tea) see Go & Rust CLI Frameworks, which is not repeated here; the design of a CLI that people, scripts and AI agents can all use is the subject of the CLI for Agents section, linked where it applies.

Every example was compiled, vetted with go vet and run with Go 1.27.2 on macOS (arm64); the output shown is the real output, and the compiler message is copied from a real run. The signal, pipe and process examples use Unix facilities (SIGPIPE, kill, sh, sleep) and therefore run on Linux and macOS as shown; the Windows differences are called out where they matter. Each example is a package main in its own directory of the example module, built into the module root with go build ./cmd/<name>, so that the transcripts show ./name as the program name. The go.mod of the module is:

Building the shelf CLI

One design principle makes every other piece of this page easier: keep main almost empty. main builds the real dependencies (the three streams, the environment, a signal-aware context), calls a function that returns an int, and passes that value to os.Exit. Everything else, including parsing, validation, work and the translation of errors into statuses, lives in run, which tests can call with fake streams and a fake environment. The final sections build the shelf CLI exactly this way.

Program arguments: os.Args

os.Args is a []string. os.Args[0] is the name the program was started with (a path as typed, a name looked up on PATH, or the temporary executable that go run builds), and os.Args[1:] are the arguments, exactly as the operating system delivered them. On Unix the shell has already done the quoting, variable expansion and wildcard expansion, so 'a b' arrives as one argument and *.go arrives as the list of matching files; on Windows the process receives one command-line string, which the Go runtime splits into os.Args, and no wildcard expansion happens at all. A Go program never sees the quotes.

cmd/args/main.go
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	fmt.Println("program:", filepath.Base(os.Args[0]))
	fmt.Println("count:  ", len(os.Args)-1)
	for i, a := range os.Args[1:] {
		fmt.Printf("arg %d: %q\n", i+1, a)
	}
}
$ ./args 'a b' '' 'c"d'
program: args
count:   3
arg 1: "a b"
arg 2: ""
arg 3: "c\"d"
$ go run ./cmd/args one two | head -2
program: args
count:   2

Source: os: Args

Three habits make os.Args safe:

  • Check the length before indexing. os.Args[1] panics with index out of range [1] with length 1 when the user typed nothing. Test len(os.Args) or, better, let flag do the parsing and test flag.NArg().

  • Arguments are bytes, not necessarily UTF-8. A file name on Linux can hold any bytes, and os.Args carries them unchanged; see Strings, Runes and UTF-8 before assuming range yields valid characters.

  • Use os.Executable, not os.Args[0], to find the program’s own file. os.Args[0] can be a bare name that is only meaningful to the shell that resolved it. os.Executable returns an absolute path to the executable that started the process (it may be the symbolic link that was used, depending on the operating system, so use filepath.EvalSymlinks when a stable location matters, and there is no guarantee that the file still exists). Its documented use is finding resources located next to the executable.

Reading os.Args directly is fine for a program with a fixed shape, such as tool <file>. As soon as options appear, use the flag package.

The flag package

flag implements the traditional single-dash option syntax used by the Go toolchain itself (go build -o out -v ./...). It is small, has no dependencies and is complete enough for most tools. What it deliberately lacks are the things that Cobra and similar libraries add: short and long aliases for one option (-v and --verbose), grouped short options (-abc), options after positional arguments, and a command tree. The sections below cover what it does have in full.

Flag syntax

Form Meaning

-flag

Boolean flag: sets it to true.

--flag

Identical to -flag: one or two dashes may be used.

-flag=x

Any flag, value x. The only form that can set a boolean to false (-json=false).

-flag x

Non-boolean flags only: the next argument is the value.

-

Not a flag: a lone dash is a positional argument, conventionally meaning standard input.

--

Terminator: everything after it is a positional argument, even if it starts with a dash.

Parsing stops at the first argument that is not a flag, so flags must come before positional arguments: shelf -limit 5 go works, shelf go -limit 5 treats -limit and 5 as positional. Boolean flags take their value only with =: -json false sets json to true and leaves false as a positional argument, because otherwise cmd -x * would change meaning when a file called false or 0 exists. Integer flags accept decimal, octal (0664), hexadecimal (0x1234) and negative values; boolean flags accept 1, 0, t, f, T, F, true, false, TRUE, FALSE, True and False; duration flags accept anything time.ParseDuration does (250ms, 1h30m).

Every constructor takes (name, default, usage). Constructors panic at start-up, not at parse time, when a definition is wrong, which is why a mistake surfaces on the very first run:

  • a name that begins with - or contains = panics (the check was added in Go 1.17);

  • defining the same name twice panics with flag redefined: v, or shelf search flag redefined: v for a named FlagSet;

  • since Go 1.21, defining a flag after Set was already called for that name panics too.

A first example

The search command of the shelf program needs a text to look for, a limit, a switch for JSON output and a timeout.

cmd/flagbasics/main.go
package main

import (
	"flag"
	"fmt"
	"os"
	"time"
)

func main() {
	var (
		title   = flag.String("title", "", "match books whose title contains `text`")
		limit   = flag.Int("limit", 10, "maximum number of results")
		asJSON  = flag.Bool("json", false, "print results as JSON")
		timeout = flag.Duration("timeout", 5*time.Second, "give up after this long")
	)
	var verbose bool
	flag.BoolVar(&verbose, "v", false, "verbose output")

	flag.Parse()

	fmt.Printf("title=%q limit=%d json=%t timeout=%v verbose=%t\n", *title, *limit, *asJSON, *timeout, verbose)
	fmt.Printf("NFlag=%d NArg=%d Args=%q\n", flag.NFlag(), flag.NArg(), flag.Args())
	if flag.NArg() > 0 {
		fmt.Fprintln(os.Stdout, "first positional:", flag.Arg(0))
	}
}

The back-quoted word in a usage string ( text ) names the value in the help output. Running it shows the forms from the syntax table, including the two ways that a boolean flag surprises people:

Errors, usage text and -h

When parsing fails, or when the user passes -h or -help and no such flag is defined, the FlagSet prints the problem and the usage text and then acts according to its error handling value:

Value What Parse does after printing the message

flag.ExitOnError

Calls os.Exit(2); for -h/-help it calls os.Exit(0) (changed from 2 to 0 in Go 1.15). This is the default for the command line (flag.CommandLine) and therefore for flag.Parse().

flag.ContinueOnError

Returns the error (flag.ErrHelp for -h/-help). This is the zero value, so a FlagSet created with new or as a zero struct uses it. The right choice for subcommands and for tests.

flag.PanicOnError

Panics with the error.

Both the error message and the usage go to standard error by default (FlagSet.Output is os.Stderr unless SetOutput changed it), including for -h: asking for help prints nothing on standard output, which is why ./flagbasics -h 2>/dev/null below prints nothing. Custom flag types: Value, Func, BoolFunc and TextVar

A flag’s value is anything that implements flag.Value: String() string and Set(string) error. Set is called once, in command-line order, for each occurrence, so a type can accumulate (a repeatable flag) or validate (return an error that the parser reports as invalid value "x" for flag -year: ...). If the type also has IsBoolFlag() bool returning true, -name alone means -name=true. The optional flag.Getter interface adds Get() any; every value type of the package implements it except the two behind Func and BoolFunc.

Most custom flags do not need a type any more:

  • flag.Func(name, usage, fn) (Go 1.16) calls fn with the value each time the flag appears; an error from fn is a parse error. Use it to validate, to parse into a struct or to append to a slice.

  • flag.BoolFunc(name, usage, fn) (Go 1.21) is the same for a flag that takes no value, such as -v that raises the verbosity each time it is repeated. fn receives the text "true" for -v and the explicit text for -v=false.

  • flag.TextVar(&v, name, default, usage) (Go 1.19) binds any variable whose pointer implements encoding.TextUnmarshaler, with a default that implements encoding.TextMarshaler: slog.Level, netip.Addr, time.Time, *big.Int and your own types, with no glue code.

cmd/flagtypes/main.go
package main

import (
	"errors"
	"flag"
	"fmt"
	"log/slog"
	"os"
	"strconv"
	"strings"
)

// authors is a repeatable flag: -author A -author B. It implements flag.Value.
type authors []string

func (a *authors) String() string { return strings.Join(*a, ",") }

func (a *authors) Set(s string) error {
	if strings.TrimSpace(s) == "" {
		return errors.New("author name must not be empty")
	}
	*a = append(*a, s)
	return nil
}

func main() {
	fs := flag.NewFlagSet("shelf search", flag.ContinueOnError)
	fs.SetOutput(os.Stdout) // usage and parse errors go to stdout so the demo is easy to capture

	var by authors
	fs.Var(&by, "author", "restrict to `name` (repeatable)")

	verbosity := 0
	fs.BoolFunc("v", "increase verbosity (repeatable)", func(string) error {
		verbosity++
		return nil
	})

	var year int
	fs.Func("year", "publication `year` between 1450 and 2100", func(s string) error {
		n, err := strconv.Atoi(s)
		if err != nil {
			return errors.New("not a number")
		}
		if n < 1450 || n > 2100 {
			return fmt.Errorf("%d is out of range", n)
		}
		year = n
		return nil
	})

	level := slog.LevelInfo
	fs.TextVar(&level, "log-level", slog.LevelInfo, "log `level`: debug, info, warn or error")

	if err := fs.Parse(os.Args[1:]); err != nil {
		if errors.Is(err, flag.ErrHelp) {
			return
		}
		fmt.Println("parse failed:", err)
		os.Exit(2)
	}

	fmt.Printf("authors=%q verbosity=%d year=%d level=%v\n", by, verbosity, year, level)

	fmt.Print("set explicitly:")
	fs.Visit(func(f *flag.Flag) { fmt.Print(" ", f.Name) })
	fmt.Println()

	f := fs.Lookup("log-level")
	fmt.Printf("log-level: default %q, current %q\n", f.DefValue, f.Value)
}

Custom usage text, required flags and detecting explicit flags

flag.Usage is a variable of type func(): assign a function to control the help text of the command line. A FlagSet has the same field, FlagSet.Usage. The function runs for -h and for every parse error, and it may print to flag.CommandLine.Output() so that a later SetOutput is respected.

flag has no notion of a required flag. Check after parsing and fail with the same status the package uses, 2. And since a flag that was not given has its default value, flag.Visit (which walks only the flags that were set) tells -days 14 apart from the default of 14; flag.VisitAll walks every defined flag.

cmd/usage/main.go
package main

import (
	"flag"
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	name := filepath.Base(os.Args[0])
	member := flag.String("member", "", "member `id` (required)")
	days := flag.Int("days", 14, "loan length in `days`")

	// flag.Usage is a variable: replace it to control the help text. It is
	// called for -h/-help and for every parse error.
	flag.Usage = func() {
		fmt.Fprintf(flag.CommandLine.Output(), "Usage: %s [flags] ISBN...\n\nLend books to a member.\n\nFlags:\n", name)
		flag.PrintDefaults()
		fmt.Fprintf(flag.CommandLine.Output(), "\nExample:\n  %s -member ana 978-0-13-419044-0\n", name)
	}
	flag.Parse() // the default error handling for the command line is ExitOnError

	// Flag.Parse cannot express "required": check it yourself, and exit with
	// the same status the flag package uses for a bad command line.
	if *member == "" || flag.NArg() == 0 {
		flag.Usage()
		os.Exit(2)
	}

	// Visit walks only the flags that were set on the command line, so it can
	// tell "-days 14" from the default of 14.
	explicit := map[string]bool{}
	flag.Visit(func(f *flag.Flag) { explicit[f.Name] = true })
	fmt.Printf("lending %q to %s for %d days (days set explicitly: %t)\n", flag.Args(), *member, *days, explicit["days"])
}

Pitfalls of the flag package

Pitfall What to do instead

Flags after the first positional argument are silently treated as positional

Document "flags first", reject unexpected leftovers with flag.NArg(), or write a small loop that re-parses fs.Args() when you want interleaving.

-json false leaves false as an argument and sets json to true

Always -json=false.

Forgetting that flag.Int returns a pointer

*limit, or bind a variable with flag.IntVar. The compiler catches most misuse (see below).

Defining flags inside a function that runs twice (tests, init plus main)

-1 looks like a flag. Put them after --.

Environment or config file that should override defaults

Subcommands with FlagSet

shelf search, shelf lend, shelf export and so on are subcommands: the first non-flag argument selects a command and the remaining arguments belong to it. The standard library has no command tree, but one flag.FlagSet per subcommand and a map from names to functions is all it takes. Three details make it robust:

  • Every subcommand gets its own FlagSet with ContinueOnError, named shelf <command> so that messages and usage say which command complained, and with its output set to the standard error of the surrounding program (not the global os.Stderr, so that tests can capture it).

  • Because flag stops at the first positional argument, global flags (-data, -version) go on a top-level set that is parsed first, and Args()[0] is the subcommand name. shelf -data x.json search go works and shelf search -data x.json go does not, which is the same rule git and go follow.

  • A parse error or a usage mistake is reported once and becomes exit status 2; -h is status 0; anything else a command returns is status 1.

The skeleton below contains only that structure, with two commands; the complete program is built later.

cmd/subcmds/main.go
package main

import (
	"errors"
	"flag"
	"fmt"
	"io"
	"os"
	"sort"
)

// errUsage means "the user was already told what is wrong": the flag package
// printed its message and usage, or the command did. run maps it to exit status 2.
var errUsage = errors.New("usage error")

// command is one subcommand: a summary for the help list and a function that
// owns its FlagSet.
type command struct {
	summary string
	run     func(args []string, stdout, stderr io.Writer) error
}

func main() {
	os.Exit(run(os.Args[1:], os.Stdout, os.Stderr))
}

func run(args []string, stdout, stderr io.Writer) int {
	commands := map[string]command{
		"search": {"find books", search},
		"lend":   {"lend a book to a member", lend},
	}

	if len(args) == 0 || args[0] == "-h" || args[0] == "-help" || args[0] == "help" {
		fmt.Fprintln(stderr, "usage: shelf <command> [flags]")
		names := make([]string, 0, len(commands))
		for name := range commands {
			names = append(names, name)
		}
		sort.Strings(names)
		for _, name := range names {
			fmt.Fprintf(stderr, "  %-8s %s\n", name, commands[name].summary)
		}
		if len(args) == 0 {
			return 2
		}
		return 0
	}

	cmd, ok := commands[args[0]]
	if !ok {
		fmt.Fprintf(stderr, "shelf: unknown command %q (try \"shelf help\")\n", args[0])
		return 2
	}

	err := cmd.run(args[1:], stdout, stderr)
	switch {
	case err == nil, errors.Is(err, flag.ErrHelp):
		return 0
	case errors.Is(err, errUsage):
		return 2
	default:
		fmt.Fprintf(stderr, "shelf %s: %v\n", args[0], err)
		return 1
	}
}

// parse runs fs.Parse and converts a failure into errUsage, because the
// FlagSet has already printed the problem and the usage text to its output.
func parse(fs *flag.FlagSet, args []string) error {
	if err := fs.Parse(args); err != nil {
		if errors.Is(err, flag.ErrHelp) {
			return err
		}
		return errUsage
	}
	return nil
}

func search(args []string, stdout, stderr io.Writer) error {
	fs := flag.NewFlagSet("shelf search", flag.ContinueOnError)
	fs.SetOutput(stderr)
	title := fs.String("title", "", "match books whose title contains `text`")
	limit := fs.Int("limit", 10, "maximum number of results")
	if err := parse(fs, args); err != nil {
		return err
	}
	fmt.Fprintf(stdout, "search title=%q limit=%d rest=%q\n", *title, *limit, fs.Args())
	return nil
}

func lend(args []string, stdout, stderr io.Writer) error {
	fs := flag.NewFlagSet("shelf lend", flag.ContinueOnError)
	fs.SetOutput(stderr)
	member := fs.String("member", "", "member `id` (required)")
	if err := parse(fs, args); err != nil {
		return err
	}
	if *member == "" || fs.NArg() != 1 {
		fmt.Fprintln(stderr, "usage: shelf lend -member ID ISBN")
		return errUsage
	}
	fmt.Fprintf(stdout, "lent %s to %s\n", fs.Arg(0), *member)
	return nil
}

Exit codes, os.Exit and deferred calls

A process ends with an integer status that the caller reads: shells expose it as $?, make and CI systems treat non-zero as failure, exec.Cmd returns it in an *exec.ExitError. The conventions are old and widely relied on:

Status Meaning

0

Success.

1

General failure. What log.Fatal and most hand-written os.Exit(1) calls report.

2

Misuse of the command line. The flag package exits with 2 on a parse error; an unrecovered panic and a runtime fatal error such as "all goroutines are asleep" also end with 2.

3 to 125

Free for the program’s own meanings. The shelf program below uses 3 for "the catalogue refused: unknown book, already on loan".

126, 127

Reserved by shells: found but not executable, command not found.

128 + n

Terminated by signal n, as reported by shells: 130 for SIGINT (Ctrl-C), 141 for SIGPIPE, 143 for SIGTERM. A program that handles the signal itself and then exits normally conventionally returns the same value, as the shutdown example below does.

os.Exit(code) ends the process immediately: deferred functions do not run, goroutines are not stopped, buffered writers are not flushed, and log.Fatal is just Print followed by os.Exit(1). Conversely, when main returns the program exits with status 0 even if other goroutines are still running. Two consequences follow:

  • never defer something important in a function that ends with os.Exit or log.Fatal; and

  • call os.Exit in exactly one place, main, after a function that owns all the deferred cleanup has returned.

On Unix the kernel keeps only the low eight bits of the status, so values outside 0 to 255 wrap around; the documentation advises staying in the range 0 to 125 for portability. A small program shows the wrap-around, and the flag-redefinition panic message from earlier:

The next program contrasts the four ways a Go program can end badly, selected by its first argument: os.Exit, log.Fatal, a panic and the run pattern. Its exitError type lets a command choose its status, and errors.As finds it even when the error was wrapped with %w on the way up.

cmd/exitcodes/main.go
package main

import (
	"errors"
	"fmt"
	"log"
	"os"
)

// exitError carries the exit status a failed command wants the process to use.
type exitError struct {
	code int
	err  error
}

func (e *exitError) Error() string { return e.err.Error() }
func (e *exitError) Unwrap() error { return e.err }

func main() {
	switch os.Args[1] {
	case "exit":
		defer fmt.Println("deferred: never printed")
		fmt.Println("calling os.Exit(3)")
		os.Exit(3)
	case "fatal":
		defer fmt.Println("deferred: never printed")
		log.SetFlags(0)
		log.Fatal("shelf: cannot open the catalogue")
	case "panic":
		defer fmt.Println("deferred: printed while the panic unwinds")
		var books map[string]int
		books["go"]++
	case "run":
		os.Exit(realMain())
	}
}

// realMain owns all the deferred cleanup; main only turns its result into a
// status, after realMain has returned and its defers have run.
func realMain() int {
	defer fmt.Println("deferred: flushed and closed everything")

	err := work()
	var ee *exitError
	switch {
	case err == nil:
		return 0
	case errors.As(err, &ee):
		fmt.Fprintln(os.Stderr, "shelf:", ee)
		return ee.code
	default:
		fmt.Fprintln(os.Stderr, "shelf:", err)
		return 1
	}
}

func work() error {
	return fmt.Errorf("lend: %w", &exitError{code: 4, err: errors.New("book is already on loan")})
}

Standard streams

os.Stdin, os.Stdout and os.Stderr are ordinary *os.File values for file descriptors 0, 1 and 2, so they are an io.Reader, two io.Writer`s and a `Stat-able file. The Unix convention, which Go tools follow, is:

  • standard output carries the program’s result (the data a pipe or a redirect should receive);

  • standard error carries everything else: error messages, usage text, progress, warnings and logs.

Keeping the two apart is what lets shelf search zzz > out.txt leave a clean file and show the diagnostics on the terminal, and shelf export | jq keep working when a warning is printed. fmt.Fprintln(os.Stderr, ...) is the direct way; the log package writes to standard error by default (log.SetFlags(0) removes the timestamp for CLIs), and slog handlers should be pointed at os.Stderr for the same reason. The os.Stderr variable can be replaced in tests only if the code reads it through a field, which is why the shelf program keeps its streams in an app struct.

package main

import (
	"bufio"
	"errors"
	"fmt"
	"os"
)

func main() {
	// Is standard input a terminal, a pipe or a file?
	if fi, err := os.Stdin.Stat(); err == nil {
		switch {
		case fi.Mode()&os.ModeCharDevice != 0:
			fmt.Println("stdin: a character device (a terminal, or /dev/null)")
		case fi.Mode()&os.ModeNamedPipe != 0:
			fmt.Println("stdin: a pipe")
		case fi.Mode().IsRegular():
			fmt.Println("stdin: a redirected file")
		}
	}

	sc := bufio.NewScanner(os.Stdin)
	if len(os.Args) > 1 && os.Args[1] == "big" {
		// The default limit is 64 KiB per line (bufio.MaxScanTokenSize).
		sc.Buffer(make([]byte, 0, 64*1024), 1024*1024)
	}

	n, longest := 0, 0
	for sc.Scan() {
		n++
		longest = max(longest, len(sc.Text()))
	}
	if err := sc.Err(); err != nil {
		fmt.Fprintln(os.Stderr, "read error:", err)
		fmt.Printf("too long: %t, lines read before the error: %d\n", errors.Is(err, bufio.ErrTooLong), n)
		os.Exit(1)
	}
	fmt.Printf("lines=%d longest=%d\n", n, longest)
}

func confirm(in *bufio.Reader, prompt string) (bool, error) {
	fmt.Fprintf(os.Stderr, "%s [y/N] ", prompt)

		return false, err
	}
	answer := strings.ToLower(strings.TrimSpace(line))
	return answer == "y" || answer == "yes", nil
}

		os.Exit(1)
	}
	if !ok {
		fmt.Fprintln(os.Stderr, "aborted")
		os.Exit(1)
	}
	fmt.Println("returned 3 books")
}

Writing output

os.Stdout is not buffered: every fmt.Println is a system call. A program that prints a lot should wrap it in a bufio.Writer, write through it, and check the error of Flush: it is where a full disk or a closed pipe is reported. That is also where Go’s treatment of SIGPIPE matters. When the reader of a pipe goes away (prog | head -2), the kernel sends SIGPIPE on the next write. By the os/signal documentation, a Go program that has not called Notify for SIGPIPE and writes to a broken pipe on file descriptor 1 or 2 is terminated by SIGPIPE, like a C program; a write to a broken pipe on any other descriptor just fails with EPIPE; and once the program has called Notify for SIGPIPE, every descriptor behaves the second way. So command-line programs behave like typical Unix tools by default, and servers do not crash when a client hangs up.

cmd/pipes/main.go
package main

import (
	"bufio"
	"fmt"
	"os"
	"os/signal"
	"syscall"
)

func main() {
	if len(os.Args) > 1 && os.Args[1] == "handle-sigpipe" {
		// Once SIGPIPE is registered with Notify, a write to a closed pipe on
		// stdout or stderr returns EPIPE instead of killing the process.
		signal.Notify(make(chan os.Signal, 1), syscall.SIGPIPE)
	}
	os.Exit(run())
}

func run() int {
	out := bufio.NewWriter(os.Stdout)
	for i := 1; i <= 200000; i++ {
		if _, err := fmt.Fprintf(out, "978-0-13-%06d-0 title %d\n", i, i); err != nil {
			fmt.Fprintln(os.Stderr, "shelf: write:", err)
			return 1
		}
	}
	// Flush is where buffered write errors surface: always check it.
	if err := out.Flush(); err != nil {
		fmt.Fprintln(os.Stderr, "shelf: flush:", err)
		return 1
	}
	return 0
}

Environment variables

The environment is a list of KEY=value strings that every process inherits from its parent and passes to its children. It is the usual way to configure a program without flags (SHELF_DATA, HTTP_PROXY, NO_COLOR), and the standard way for a deployment platform to hand over settings.

Function Behaviour

os.Getenv(key)

The value, or "" when unset: it cannot tell unset from set to the empty string.

os.LookupEnv(key)

(value, ok): ok is false only when the variable is unset. Use it whenever "empty" and "missing" mean different things.

os.Setenv(key, value), os.Unsetenv(key), os.Clearenv()

Change this process’s environment (and what children started later inherit). Nothing outside the process changes.

os.Environ()

A copy of the environment as KEY=value strings, in unspecified order: sort it before printing.

os.ExpandEnv(s), os.Expand(s, mapping)

Replace $var and ${var}; unset variables become the empty string. Expand takes any lookup function, so it also expands from a map.

os.UserHomeDir(), os.UserConfigDir(), os.UserCacheDir()

Per-user directories. The configuration directory is $XDG_CONFIG_HOME or $HOME/.config on Unix, $HOME/Library/Application Support on macOS and %AppData% on Windows; the cache directory is the analogous $XDG_CACHE_HOME, $HOME/Library/Caches and %LocalAppData%. Create an application subdirectory inside them.

os.TempDir()

$TMPDIR or /tmp on Unix. Use os.CreateTemp and os.MkdirTemp rather than inventing names in it.

os.Hostname(), os.Getwd(), os.Executable()

Host name, working directory, path of the running program.

On Windows, environment variable names are case-insensitive; elsewhere they are case-sensitive. The example program below resolves one setting with the usual precedence, flag, then environment, then built-in default, and exercises the functions. (It was run with HOME set explicitly, and the last two lines show the macOS answers; on Linux they are /home/ana/.config and /home/ana/.cache.)

cmd/envvars/main.go
package main

import (
	"fmt"
	"os"
	"slices"
	"strings"
	"time"
)

// setting resolves one option: an explicit flag wins, then the environment,
// then the built-in default.
func setting(flagValue, envName, def string) (value, source string) {
	if flagValue != "" {
		return flagValue, "flag"
	}
	if v, ok := os.LookupEnv(envName); ok && v != "" {
		return v, "environment"
	}
	return def, "default"
}

func main() {
	// Getenv cannot tell "unset" from "set to the empty string"; LookupEnv can.
	fmt.Printf("Getenv(SHELF_EMPTY)=%q\n", os.Getenv("SHELF_EMPTY"))
	_, set := os.LookupEnv("SHELF_EMPTY")
	_, missing := os.LookupEnv("SHELF_MISSING")
	fmt.Println("SHELF_EMPTY set:", set, "SHELF_MISSING set:", missing)

	dir, src := setting("", "SHELF_DATA", "./shelf-data")
	fmt.Printf("data dir: %s (from %s)\n", dir, src)
	dir, src = setting("/tmp/from-flag", "SHELF_DATA", "./shelf-data")
	fmt.Printf("data dir: %s (from %s)\n", dir, src)

	d, err := time.ParseDuration(os.Getenv("SHELF_TIMEOUT"))
	fmt.Println("SHELF_TIMEOUT:", d, err)

	// Setenv changes only this process (and the children it starts later).
	os.Setenv("SHELF_COLOR", "never")
	fmt.Println("after Setenv:", os.Getenv("SHELF_COLOR"))
	os.Unsetenv("SHELF_COLOR")
	_, still := os.LookupEnv("SHELF_COLOR")
	fmt.Println("after Unsetenv, set:", still)

	// Environ returns a copy of "key=value" strings.
	var mine []string
	for _, kv := range os.Environ() {
		if strings.HasPrefix(kv, "SHELF_") {
			mine = append(mine, kv)
		}
	}
	slices.Sort(mine) // the order of Environ is not specified
	fmt.Println("SHELF_* variables:", mine)

	// Expand and ExpandEnv substitute $var and ${var}; unset variables become "".
	fmt.Println(os.ExpandEnv("data in ${SHELF_DATA}/books.json, user=$SHELF_MISSING."))
	fmt.Println(os.Expand("$title by $author", func(k string) string {
		return map[string]string{"title": "TGPL", "author": "Donovan"}[k]
	}))

	home, _ := os.UserHomeDir()
	cfg, _ := os.UserConfigDir()
	cache, _ := os.UserCacheDir()

Guidance for configuration through the environment:

  • Prefix your own variables (SHELF_) so they do not collide with others, and document each one in the help text.

  • Treat the environment as input to be validated, exactly like flags: the example parses SHELF_TIMEOUT with time.ParseDuration and a missing or malformed value is an error to handle, not a zero.

  • Do not put secrets in flags (they appear in process listings) and be careful with the environment (children inherit it, and on many systems it is readable by the same user’s other processes).   • In tests, use t.Setenv, which restores the old value and forbids parallel tests, or inject a getenv function as the shelf program does, which is better still because it needs no global state.

Signals and graceful shutdown

A signal is the operating system’s way to interrupt a process: the user pressed Ctrl-C, the terminal closed, an orchestrator wants a container to stop, a pipe broke. What a Go program does by default depends on the signal; os/signal changes it.

On Windows the only signal that exists is os.Interrupt, delivered for Ctrl-C and Ctrl-Break; closing the console window, logging off or shutting down is reported to Notify as syscall.SIGTERM while the process is given a short time to clean up. os.Process.Signal(os.Interrupt) is not implemented on Windows, so code that stops a child that way needs another mechanism there.

signal.Notify

signal.Notify(c, sigs...) relays the listed signals to the channel c, replacing the default behaviour. With no signals listed it relays all of them, which is rarely what you want. The channel must be buffered: Notify never blocks when it sends, so a signal that arrives while nobody is receiving on an unbuffered channel is dropped. A buffer of one is enough for a single "please stop" notification, and go vet has an analyzer (sigchanyzer) for the mistake:

signal.Stop(c) unregisters a channel and guarantees that it receives nothing more; signal.Reset(sigs...) removes every handler for the signals and restores the default; signal.Ignore(sigs...) makes the signals do nothing; and signal.Ignored(sig) reports whether one is currently ignored.

signal.NotifyContext

For the common case (stop on the first Ctrl-C or SIGTERM), signal.NotifyContext(parent, sigs...) (Go 1.16) returns a context that is cancelled when one of the signals arrives, and a stop function. Since Go 1.26 the context is cancelled with a cause that names the signal, so context.Cause(ctx) returns the text interrupt signal received or the text terminated signal received, while ctx.Err() is still context.Canceled. Call stop as soon as signals no longer need to be diverted: it releases the resources and, like signal.Reset, may restore the default behaviour, which is what lets a second Ctrl-C kill a program that is stuck while shutting down.

The program below sends the signals to itself so that its output is deterministic. It shows Notify, NotifyContext with its cause, and what stop does: the final SIGINT terminates the process with the default action, status 130 as seen by the shell, and "not reached" is never printed.

cmd/signals/main.go
package main

import (
	"context"
	"fmt"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	self, err := os.FindProcess(os.Getpid())
	if err != nil {
		panic(err)
	}

	// 1. Notify: a buffered channel receives the signals. The buffer must hold
	// at least one value because the package never blocks when it sends.
	sigs := make(chan os.Signal, 1)
	signal.Notify(sigs, syscall.SIGINT, syscall.SIGTERM)
	self.Signal(syscall.SIGTERM)
	select {
	case s := <-sigs:
		fmt.Println("Notify received:", s)
	case <-time.After(5 * time.Second):
		fmt.Println("no signal")
	}
	signal.Stop(sigs) // unregister; SIGTERM would now terminate the process again

	// 2. NotifyContext: the context is cancelled by the first signal, and
	// context.Cause says which one.
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()
	self.Signal(os.Interrupt)
	select {
	case <-ctx.Done():
		fmt.Println("NotifyContext: Err =", ctx.Err())
		fmt.Println("NotifyContext: Cause =", context.Cause(ctx))
	case <-time.After(5 * time.Second):
		fmt.Println("no signal")
	}

	// 3. After stop, signals behave as before Notify. A second Ctrl-C now kills
	// the process with the default action instead of being swallowed.
	stop()
	fmt.Println("stopped; sending SIGINT with the default action restored")
	self.Signal(os.Interrupt)
	time.Sleep(5 * time.Second)
	fmt.Println("not reached")
}

Graceful shutdown of a CLI

Interruption should leave the program’s data consistent. The pattern used by long-running commands is:

  1. create the signal-aware context in main and pass it down;

  2. check ctx.Err() between units of work (between records, between pages), never in the middle of one;

  3. when the context is cancelled, finish or roll back the current unit, flush and close everything, and return instead of exiting from deep inside;

  4. return a distinctive status (conventionally 128 + signal, so 130 for Ctrl-C);

  5. call stop right after the first signal so a second one forces the exit.

cmd/shutdown/main.go
package main

import (
	"context"
	"errors"
	"flag"
	"fmt"
	"os"
	"os/signal"
	"syscall"
	"time"
)

func main() {
	cleanup := flag.Duration("cleanup", 0, "simulated time needed to flush before exiting")
	flag.Parse()
	os.Exit(run(*cleanup))
}

func run(cleanup time.Duration) int {
	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	// After the first signal, give the default behaviour back: a second
	// Ctrl-C then terminates the process even if cleanup hangs.
	go func() {
		<-ctx.Done()
		stop()
		fmt.Fprintln(os.Stderr, "shelf: interrupted, finishing the current record (press Ctrl-C again to force quit)")
	}()

	fmt.Println("importing")
	done, err := importRecords(ctx, 20)
	fmt.Printf("imported %d records\n", done)

	time.Sleep(cleanup) // flush files, close connections, ...

	switch {
	case err == nil:
		return 0
	case errors.Is(err, context.Canceled):
		return 130 // 128 + SIGINT, the shell convention for "stopped by Ctrl-C"
	default:
		fmt.Fprintln(os.Stderr, "shelf:", err)
		return 1
	}
}

// importRecords handles one record at a time and checks for cancellation
// between records, never in the middle of one.
func importRecords(ctx context.Context, n int) (int, error) {
	for i := 0; i < n; i++ {
		if err := ctx.Err(); err != nil {
			return i, context.Cause(ctx)
		}
		time.Sleep(100 * time.Millisecond) // the real work
	}
	return n, nil
}

Running other programs: os/exec

os/exec starts external programs. Unlike C’s system and the shell’s backticks it never invokes a shell: it does not expand $HOME, does not expand wildcards, does not interpret pipes, redirections or ;. The arguments are an exact list. That makes it safe by default (there is no string to inject into), and it means that if a shell feature is needed the caller must ask for a shell explicitly, with the user input passed as a separate argument and never spliced into the command text.

Starts the command and waits for it to finish.

Output()

Runs it and returns standard output. On failure the error is usually an *exec.ExitError whose Stderr field holds the (possibly truncated) standard error, if Cmd.Stderr was nil.

CombinedOutput()

Runs it and returns standard output and standard error interleaved in one buffer.

Start() and Wait()

Start without waiting; Wait blocks until the process exits and the copying goroutines finish, and releases the resources. After a successful Start, Wait must be called.

StdinPipe(), StdoutPipe(), StderrPipe()

A pipe to or from the child for streaming. Call them before Start, read everything, then call Wait; do not use Run with them because Wait closes the pipes.

import (
	"bufio"
	"errors"
	"fmt"
	"os"
	"os/exec"
	"strings"
)

func main() {
	// Output runs the command and returns its standard output.
	out, err := exec.Command("echo", "hello", "shelf").Output()
	fmt.Printf("Output: %q err=%v\n", out, err)

	// There is no shell: $HOME and * are passed through literally.
	out, _ = exec.Command("echo", "$HOME", "*.go").Output()
	fmt.Printf("no shell: %q\n", out)
	out, _ = exec.Command("sh", "-c", `echo "$1"`, "sh", "an argument; rm -rf / is just text").Output()
	fmt.Printf("sh -c with $1: %q\n", out)

	// A non-zero exit status becomes *exec.ExitError.
	_, err = exec.Command("sh", "-c", "echo oops >&2; exit 3").Output()
	var ee *exec.ExitError
	if errors.As(err, &ee) {
		fmt.Printf("ExitError: %v, code=%d, success=%t, stderr=%q\n", ee, ee.ExitCode(), ee.Success(), ee.Stderr)
	}

	// CombinedOutput interleaves stdout and stderr into one buffer.
	out, err = exec.Command("sh", "-c", "echo to-stdout; echo to-stderr >&2").CombinedOutput()
	fmt.Printf("CombinedOutput: %q err=%v\n", out, err)

	// Stdin: any io.Reader. Env and Dir configure the child.
	cmd := exec.Command("tr", "a-z", "A-Z")
	cmd.Stdin = strings.NewReader("the go programming language\n")
	out, _ = cmd.Output()
	fmt.Printf("stdin: %q\n", out)

	cmd.Env = append(os.Environ(), "SHELF_MODE=readonly")
	cmd.Dir = "/usr"
	out, _ = cmd.Output()
	fmt.Printf("env and dir: %q\n", out)

	// Streaming: StdoutPipe, Start, read, then Wait (never Run with a pipe).
	cmd = exec.Command("sh", "-c", "for i in 1 2 3; do echo record-$i; done")
	stdout, err := cmd.StdoutPipe()
	if err != nil {
		panic(err)
	}
	if err := cmd.Start(); err != nil {
		panic(err)
	}
	sc := bufio.NewScanner(stdout)
	for sc.Scan() {
		fmt.Println("streamed:", sc.Text())
	}
	if err := cmd.Wait(); err != nil {
		panic(err)
	}
	fmt.Println("String():", cmd.String())
	fmt.Println("state:", cmd.ProcessState)
}

LookPath, ErrNotFound and ErrDot

exec.LookPath(file) finds an executable on PATH, and exec.Command calls it for names without a path separator. Two named errors report why a lookup failed:

  • exec.ErrNotFound ("executable file not found in $PATH") when nothing matches;

  • exec.ErrDot ("cannot run executable found relative to current directory") when the match would be an executable in the current directory, because PATH contains . or an empty entry, explicitly or implicitly.

Since Go 1.19, os/exec refuses to run a program found that way. The reason is a classic attack: a program that runs ls from a directory the user does not control would otherwise execute a malicious ./ls placed there. The functions do not return ErrDot itself, so test with errors.Is(err, exec.ErrDot). A program that really wants the current directory says so with a path, "./shelf-tool"; one that insists on accepting relative PATH entries must clear the error deliberately (if errors.Is(cmd.Err, exec.ErrDot) { cmd.Err = nil }). The setting GODEBUG=execerrdot=0 restores the pre-1.19 behaviour for old programs and may be removed in a future release.

CommandContext, Cancel and WaitDelay

exec.CommandContext(ctx, name, args...) ties the process to a context: when ctx is done before the command finishes, the process is killed. Two Cmd fields, added in Go 1.20, refine this:

  • Cancel func() error is what runs when the context ends. The default (from CommandContext) calls Process.Kill. Replace it to ask politely first, for example by sending SIGTERM or closing a pipe. If the command then exits with success after Cancel was called, Wait still returns an error (the one from Cancel, or the context’s), because the work was cancelled, unless Cancel returns an error wrapping os.ErrProcessDone.

  • WaitDelay time.Duration bounds how long Wait waits after the context ends or the process exits: for a process that ignored the Cancel signal (it is killed when the delay passes) and for output pipes that a grandchild still holds open (they are closed when the delay passes, and Wait returns exec.ErrWaitDelay if everything else succeeded). Zero, the default, waits for end of file on the pipes, however long that takes.

The program demonstrates the four situations: the default kill, a graceful SIGTERM that the child handles, a background grandchild that keeps the output pipe open (with and without WaitDelay), and a child that ignores SIGTERM, which WaitDelay escalates to a kill.

cmd/execctx/main.go
package main

import (
	"bytes"
	"context"
	"errors"
	"fmt"
	"os"
	"os/exec"
	"syscall"
	"time"
)

func timed(name string, f func() error) {
	start := time.Now()
	err := f()
	fmt.Printf("%-22s err=%v (about %s)\n", name, err, time.Since(start).Round(100*time.Millisecond))
}

func main() {
	// 1. Default: the context deadline kills the process.
	timed("default (Kill)", func() error {
		ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
		defer cancel()
		return exec.CommandContext(ctx, "sleep", "30").Run()
	})

	// 2. A custom Cancel asks politely with SIGTERM. The script handles it and
	// exits 0, yet Wait still reports the context error, because the command
	// was cancelled.
	timed("Cancel with SIGTERM", func() error {
		ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
		defer cancel()
		cmd := exec.CommandContext(ctx, "sh", "-c", `trap 'echo cleaning up; exit 0' TERM; sleep 30 & wait`)
		cmd.Stdout = os.Stdout
		cmd.Cancel = func() error { return cmd.Process.Signal(syscall.SIGTERM) }
		return cmd.Run()
	})

	// 3. A child that outlives its parent keeps the output pipe open, so Wait
	// blocks until it exits. WaitDelay bounds that wait.
	slowStart := `sleep 2 & echo started`
	for _, delay := range []time.Duration{0, 300 * time.Millisecond} {
		timed(fmt.Sprintf("WaitDelay=%v", delay), func() error {
			var out bytes.Buffer
			cmd := exec.Command("sh", "-c", slowStart)
			cmd.Stdout = &out // not an *os.File, so Go copies it through a pipe
			cmd.WaitDelay = delay
			err := cmd.Run()
			if errors.Is(err, exec.ErrWaitDelay) {
				fmt.Printf("  output so far: %q\n", out.String())
			}
			return err
		})
	}

	// 4. A process that ignores SIGTERM: Cancel is tried first, and WaitDelay
	// escalates to Kill.
	timed("ignores TERM + delay", func() error {
		ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
		defer cancel()
		cmd := exec.CommandContext(ctx, "sh", "-c", `trap '' TERM; while :; do sleep 1; done`)
		cmd.Cancel = func() error { return cmd.Process.Signal(syscall.SIGTERM) }
		cmd.WaitDelay = 300 * time.Millisecond
		return cmd.Run()
	})
}

store.go

The library file is a JSON document, loaded whole and saved atomically: write a temporary file in the same directory and os.Rename it over the target, so that a crash or a full disk never leaves a half-written catalogue. A missing file is an empty library (errors.Is(err, fs.ErrNotExist)). The domain errors are sentinels that run maps to status 3; they are wrapped with %w so the message says which ISBN.

cmd/shelf/store.go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
	"slices"

	"example.com/shelf/catalog"
)

var (
	errNotFound  = errors.New("no such book")
	errOnLoan    = errors.New("book is already on loan")
	errNotOnLoan = errors.New("book is not on loan")
)

// library is the document stored on disk.
type library struct {
	Books []catalog.Book `json:"books"`
	Loans []catalog.Loan `json:"loans"`
}

// load reads the library file; a missing file is an empty library.
func load(path string) (*library, error) {
	data, err := os.ReadFile(path)
	if errors.Is(err, fs.ErrNotExist) {
		return &library{}, nil
	}
	if err != nil {
		return nil, err
	}
	var lib library
	if err := json.Unmarshal(data, &lib); err != nil {
		return nil, fmt.Errorf("%s: %w", path, err)
	}
	return &lib, nil
}

// save writes the library atomically: a temporary file in the same directory,
// then a rename, so a crash never leaves a half-written catalogue.
func (l *library) save(path string) error {
	data, err := json.MarshalIndent(l, "", "  ")
	if err != nil {
		return err
	}
	tmp, err := os.CreateTemp(filepath.Dir(path), ".shelf-*.tmp")
	if err != nil {
		return err
	}
	defer os.Remove(tmp.Name()) // harmless after a successful rename
	if _, err := tmp.Write(append(data, '\n')); err != nil {
		tmp.Close()
		return err
	}
	if err := tmp.Close(); err != nil {
		return err
	}
	return os.Rename(tmp.Name(), path)
}

func (l *library) find(isbn catalog.ISBN) (int, bool) {
	return slices.BinarySearchFunc(l.Books, isbn, func(b catalog.Book, id catalog.ISBN) int {
		switch {
		case b.ISBN < id:
			return -1
		case b.ISBN > id:
			return 1
		}
		return 0
	})
}

// put inserts or replaces a book, keeping Books sorted by ISBN.
func (l *library) put(b catalog.Book) {
	i, ok := l.find(b.ISBN)
	if ok {
		l.Books[i] = b
		return
	}
	l.Books = slices.Insert(l.Books, i, b)
}

func (l *library) loanIndex(isbn catalog.ISBN) int {
	return slices.IndexFunc(l.Loans, func(ln catalog.Loan) bool { return ln.Book == isbn })
}

func (l *library) lend(isbn catalog.ISBN, member string) error {
	if _, ok := l.find(isbn); !ok {
		return fmt.Errorf("%s: %w", isbn, errNotFound)
	}
	if l.loanIndex(isbn) >= 0 {
		return fmt.Errorf("%s: %w", isbn, errOnLoan)
	}
	l.Loans = append(l.Loans, catalog.Loan{Book: isbn, Member: member, State: catalog.OnLoan})
	return nil
}

func (l *library) giveBack(isbn catalog.ISBN) error {
	i := l.loanIndex(isbn)
	if i < 0 {
		return fmt.Errorf("%s: %w", isbn, errNotOnLoan)
	}
	l.Loans = slices.Delete(l.Loans, i, i+1)
	return nil
}

app.go

app.go holds run, the shared flag helpers and the six commands. Points to notice, each tied to a section above:

  • the global FlagSet is parsed first, so -data and -version must precede the command, and Args()[0] names it;

  • newFlags and parse give every command a ContinueOnError set whose output is the injected standard error, and turn any parse failure into errUsage so that the message is printed once;

  • the data path is resolved flag, then $SHELF_DATA through the injected getenv, then shelf.json;

  • search writes results to standard output, no matches to standard error, and an empty JSON result as [] (a nil slice would be encoded as null);

  • import accepts a file or -, checks ctx.Err() between records and returns the context error, which run turns into 130;

  • export writes to standard output or a file, and the deferred Close of a file opened for writing reports its error through the named result, because that is the last chance to learn that the data did not reach the disk.

// Exit statuses. 0 and 1 are universal; 2 is the convention for usage errors
// (it is also what the flag package and the Go runtime use).
const (
	exitOK          = 0
	exitFailure     = 1
	exitUsage       = 2
	exitRefused     = 3 // the catalogue rules said no: unknown book, already on loan
	exitInterrupted = 130
)

// app holds everything a command touches outside the process: tests replace it.
type app struct {
	stdin          io.Reader
	stdout, stderr io.Writer
	getenv         func(string) string
}

// errUsage means the problem has already been reported to the user.
var errUsage = errors.New("usage error")

type command struct {
	summary string
	run     func(ctx context.Context, a *app, lib string, args []string) error
}

var commands = map[string]command{
	"add":    {"add or replace a book", cmdAdd},
	"search": {"search by title or author", cmdSearch},
	"lend":   {"lend a book to a member", cmdLend},
	"return": {"return a book", cmdReturn},
	"import": {"import books from JSON (file or -)", cmdImport},
	"export": {"export books as JSON", cmdExport},
}

func run(ctx context.Context, args []string, a *app) int {
	global := flag.NewFlagSet("shelf", flag.ContinueOnError)
	global.SetOutput(a.stderr)
	data := global.String("data", "", "path of the library `file` (default $SHELF_DATA, then ./shelf.json)")
	showVersion := global.Bool("version", false, "print the version and exit")
	global.Usage = func() { usage(global, a.stderr) }

	if err := global.Parse(args); err != nil {
		if errors.Is(err, flag.ErrHelp) {
			return exitOK
		}
		return exitUsage
	}
	if *showVersion {
		fmt.Fprintln(a.stdout, versionString())
		return exitOK
	}

	rest := global.Args()
	if len(rest) == 0 {
		global.Usage()
		return exitUsage
	}
	cmd, ok := commands[rest[0]]
	if !ok {
		fmt.Fprintf(a.stderr, "shelf: unknown command %q\n", rest[0])
		global.Usage()
		return exitUsage
	}

	// Precedence: flag, then environment, then default.
	path := *data
	if path == "" {
		path = a.getenv("SHELF_DATA")
	}
	if path == "" {
		path = "shelf.json"
	}

	err := cmd.run(ctx, a, path, rest[1:])
	switch {
	case err == nil, errors.Is(err, flag.ErrHelp):
		return exitOK
	case errors.Is(err, errUsage):
		return exitUsage
	case errors.Is(err, context.Canceled):
		fmt.Fprintf(a.stderr, "shelf %s: interrupted\n", rest[0])
		return exitInterrupted
	case errors.Is(err, errNotFound), errors.Is(err, errOnLoan), errors.Is(err, errNotOnLoan):
		fmt.Fprintf(a.stderr, "shelf %s: %v\n", rest[0], err)
		return exitRefused
	default:
		fmt.Fprintf(a.stderr, "shelf %s: %v\n", rest[0], err)
		return exitFailure
	}
}

func cmdAdd(_ context.Context, a *app, path string, args []string) error {
	fs := newFlags(a, "add")
	isbn := fs.String("isbn", "", "ISBN-13 of the book (required)")
	title := fs.String("title", "", "title (required)")
	var by authors
	fs.Var(&by, "author", "author `name` (repeatable)")
	if err := parse(fs, args); err != nil {
		return err
	}
	id, err := catalog.ParseISBN(*isbn)
	if err != nil {
		return usageErr(a, "%v", err)
	}
	if strings.TrimSpace(*title) == "" {
		return usageErr(a, "add: -title is required")
	}
	book := catalog.Book{ISBN: id, Title: strings.TrimSpace(*title)}
	for _, n := range by {
		book.Authors = append(book.Authors, catalog.Author{Name: n})
	}

	lib, err := load(path)
	if err != nil {
		return err
	}
	lib.put(book)
	if err := lib.save(path); err != nil {
		return err
	}
	fmt.Fprintf(a.stdout, "added %s %q\n", book.ISBN, book.Title)
	return nil
}

func cmdSearch(_ context.Context, a *app, path string, args []string) error {
	fs := newFlags(a, "search")
	asJSON := fs.Bool("json", false, "print the matches as JSON")
	limit := fs.Int("limit", 20, "maximum number of results")
	if err := parse(fs, args); err != nil {
		return err
	}
	query := textutil.Normalize(strings.Join(fs.Args(), " "))

	lib, err := load(path)
	if err != nil {
		return err
	}
	found := []catalog.Book{} // not nil: a nil slice would encode as null
	for _, b := range lib.Books {
		if matches(b, query) {
			found = append(found, b)
			if len(found) == *limit {
				break
			}
		}
	}

	if *asJSON {
		enc := json.NewEncoder(a.stdout)
		enc.SetIndent("", "  ")
		return enc.Encode(found)
	}
	tw := tabwriter.NewWriter(a.stdout, 0, 8, 2, ' ', 0)
	for _, b := range found {
		status := catalog.Available
		if lib.loanIndex(b.ISBN) >= 0 {
			status = catalog.OnLoan
		}
		fmt.Fprintf(tw, "%s\t%s\t%s\n", b.ISBN, b.Title, status)
	}
	if err := tw.Flush(); err != nil {
		return err
	}
	if len(found) == 0 {
		fmt.Fprintln(a.stderr, "shelf: no matches") // diagnostics go to stderr, data to stdout
	}
	return nil
}

func matches(b catalog.Book, query string) bool {
	if strings.Contains(textutil.Normalize(b.Title), query) {
		return true
	}
	for _, au := range b.Authors {
		if strings.Contains(textutil.Normalize(au.Name), query) {
			return true
		}
	}
	return false
}

	fs := newFlags(a, "return")
	if err := parse(fs, args); err != nil {
		return err
	}
	if fs.NArg() != 1 {

// cmdImport reads a JSON array of books from a file, or from standard input
// when the argument is "-" or missing and input is piped in.
func cmdImport(ctx context.Context, a *app, path string, args []string) error {
	fs := newFlags(a, "import")
	if err := parse(fs, args); err != nil {
		return err
	}
	var in io.Reader = a.stdin
	switch {
	case fs.NArg() > 1:
		return usageErr(a, "import takes at most one file (or -)")
	case fs.NArg() == 1 && fs.Arg(0) != "-":
		f, err := os.Open(fs.Arg(0))
		if err != nil {
			return err
		}
		defer f.Close()
		in = f
	}

	var books []catalog.Book
	if err := json.NewDecoder(in).Decode(&books); err != nil {
		return fmt.Errorf("reading JSON: %w", err)
	}
	lib, err := load(path)
	if err != nil {
		return err
	}
	for i, b := range books {
		if err := ctx.Err(); err != nil { // stop between records, never in the middle of one
			return err
		}
		if _, err := catalog.ParseISBN(string(b.ISBN)); err != nil {
			return fmt.Errorf("record %d: %w", i+1, err)
		}
		lib.put(b)
	}
	if err := lib.save(path); err != nil {
		return err
	}
	fmt.Fprintf(a.stdout, "imported %d books\n", len(books))
	return nil
}

func cmdExport(_ context.Context, a *app, path string, args []string) (err error) {
	fs := newFlags(a, "export")
	out := fs.String("o", "-", "write to `file` instead of standard output")
	if err := parse(fs, args); err != nil {
		return err
	}
	lib, err := load(path)
	if err != nil {
		return err
	}

	w := a.stdout
	if *out != "-" {
		f, err := os.Create(*out)
		if err != nil {
			return err
		}
		defer func() {
			// The Close error of a file opened for writing is the last chance
			// to learn that the data did not reach the disk.
			if cerr := f.Close(); cerr != nil && err == nil {
				err = cerr
			}
		}()
		w = f
	}
	enc := json.NewEncoder(w)
	enc.SetIndent("", "  ")
	return enc.Encode(lib.Books)
}

	}
	for _, tc := range tests {
		code, _, stderr := runShelf(t, t.Context(), "", nil, tc.args...)

			t.Errorf("%s: exit code = %d, want %d (stderr %q)", tc.name, code, tc.wantCode, stderr)
		}
		if !strings.Contains(stderr, tc.wantErr) {
			t.Errorf("%s: stderr = %q, want it to contain %q", tc.name, stderr, tc.wantErr)
		}
	}

	}

Beyond the standard library

flag is a good tool until a program needs one of the following: nested command trees with per-command help, short and long aliases, grouped short options, flags interleaved with arguments, generated shell completion or generated man pages. At that point the usual answer in Go is Cobra, and for full-screen terminal interfaces Bubble Tea. Both are covered, with their APIs, with a running example and with notes for AI-agent callers, in Go & Rust CLI Frameworks; the choice between a command-line program and a terminal interface is in TUIs vs. CLIs. What stays the same whichever library parses the arguments is everything on this page after the flag sections: the run function that returns an exit status, the separation of standard output and standard error, the environment precedence, the signal-aware context and the care taken with child processes.

The standard library is enough when Reach for a framework when

A few flags and at most a handful of subcommands

The command tree is deep or grows often

The audience is the team that wrote it

End users expect polished --help, completion and man pages

Dependency count matters (one static binary, nothing to audit)

Consistent flag conventions across many commands matter more

Output is plain text or JSON

An interactive terminal interface is the product

Pitfalls

Pitfall What to do instead

os.Exit or log.Fatal in the middle of a function that has deferred calls

Return an error to main, exit there, after run has returned.

Indexing os.Args[1] without checking

Use flag.NArg() after parsing, or check len(os.Args).

Assuming flags can follow positional arguments

Parsing stops at the first non-flag; document it or re-parse the rest.

-json false to turn a boolean off

-json=false.

Printing the error again after a FlagSet with ContinueOnError already printed it

Map the failure to a status silently.

Exit statuses outside 0 to 255, or 256 meaning failure

Stay in 0 to 125; os.Exit(256) exits with 0 on Unix.

Everything on standard output, including errors and prompts

Data on standard output, everything else on standard error.

A bufio.Writer on standard output without a checked Flush

if err := w.Flush(); err != nil, and decide what a broken pipe means.

bufio.Scanner on input with long lines

sc.Buffer(...) with a larger limit, or bufio.Reader; always check sc.Err().

Detecting a terminal with ModeCharDevice and trusting it

It is true for /dev/null too; use a real IsTerminal check from golang.org/x/term when it matters.

os.Getenv where an empty value is meaningful

os.LookupEnv.

Secrets in flags or logged environments

A file, a credential helper or standard input; never log os.Environ().

An unbuffered channel passed to signal.Notify

make(chan os.Signal, 1); go vet reports it.

Forgetting to call stop from NotifyContext

defer stop(), plus an early stop() after the first signal so a second one kills.

Treating context.Canceled after Ctrl-C as an ordinary failure

Return 130 and say "interrupted", not a stack of wrapped errors.

Building a shell command line with user input and sh -c

Pass every user value as a separate argument of exec.Command; if a shell is needed, pass values as $1, $2.

Reusing a Cmd

A new Cmd for each run: exec: Stdout already set.

cmd.Run() after StdoutPipe()

Start, read, then Wait.

CommandContext on a command whose children outlive it

Set WaitDelay; use a process group when grandchildren must stop too.

A relative PATH entry and exec.ErrDot

Use an explicit ./name or an absolute path; do not blanket-ignore ErrDot.

Reading configuration in library code

Take parameters; only main reads flags, environment and files.

Where the books are outdated

  • Vivien, Learning Go Programming, chapter 6 introduces os.Args and the flag package for Go 1.6 and 1.7. The basics it teaches (the flag syntax, flag.Parse, Args, the pointer and Var constructors) are unchanged and still correct. It predates flag.Func (Go 1.16), flag.TextVar (Go 1.19) and flag.BoolFunc (Go 1.21), the change that makes -h exit with status 0 (Go 1.15), the panic on invalid flag names (Go 1.17). The chapter’s workflow is GOPATH based: building binaries and fetching remote packages are done today with modules, go build, and go install pkg@version; see Modules and Dependency Management and The go Command, Builds and Cross-Compilation.

  • Vivien, chapter 10 (standard streams, fmt and bufio scanning, files) uses ioutil.ReadAll and similar helpers; the io/ioutil package has been deprecated since Go 1.16 and its functions live in io (io.ReadAll) and os (os.ReadFile, os.WriteFile, os.CreateTemp).

  • Neither book covers signals and graceful shutdown (os/signal, and signal.NotifyContext since Go 1.16, with a cause since Go 1.26), os/exec beyond the basics (Cmd.Cancel and Cmd.WaitDelay in Go 1.20, ErrDot in Go 1.19, which changed how PATH is searched), the "tiny main, testable `run`" structure, or exit-status design. The official documentation linked below supplies them.

  • Bodner, Learning Go (1st edition) has no command-line chapter. Its context chapter (chapter 12) predates the cause that signal.NotifyContext attaches (Go 1.26) and exec.Cmd.Cancel and WaitDelay (Go 1.20), both described above.
