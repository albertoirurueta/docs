Text and HTML Templates

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Go 1.27 (go1.27.2), checked on 2026-10-18; every go.mod shown has the line go 1.27. Go ships two template packages in its standard library. text/template turns a template and some data into any text format (configuration files, source code, e-mails, command output), and html/template has the identical API but understands HTML, CSS, JavaScript and URLs and escapes every value for the place where it lands, which is what keeps a web page free of cross-site scripting (XSS) holes. This page covers the template language once, since both packages share it, then the escaping model that only html/template adds, then the practical parts: nested templates and layouts, error messages, rendering the shelf catalogue as HTML from cmd/shelfd, testing templates, and the Go templates that you meet outside Go programs, in Helm charts and in kubectl -o go-template.

It builds on Structs and Embedding and Methods and Receivers (templates read exported fields and call exported methods), Interfaces and Error Handling (execution errors wrap their cause). Related pages: fmt, Strings and Text Processing (printf in a template is fmt.Sprintf), I/O, Files and the Filesystem (io.Writer, io/fs and embed.FS, which templates are loaded from), Directives, Code Generation and Embedding (//go:embed and go generate), net/http Clients and Servers (the handler that serves the page), encoding/json (how html/template embeds data in JavaScript), Testing and Iterators and Range-over-Func (templates can range over iterators). Outside Go, the Go template language is the template language of Helm and the -o go-template output format of kubectl; both are revisited at the end. For comparison with other server-side template engines see Axum server-side templates, Flask Jinja templates, Django templates and Vapor Leaf templates.

Neither of the two reference books used for this section covers templates; the page is built from the package documentation and the release notes. Every example was compiled, vetted with go vet and run with Go 1.27.2; the output shown is the real output (compiler, parser and escaper messages are copied from real runs; trailing white space at line ends is trimmed for readability). html/template wraps text/template, so everything in the next sections about actions, pipelines, variables, functions, associated templates and options applies to both. The packages differ in one rule that matters in practice: use html/template whenever the result is HTML, even for pages that "only" show your own data. Titles, names and comments eventually contain <, & and quotes, and an unescaped one is a bug at best and a vulnerability at worst. Both import paths are called template, so a program that needs both aliases one of them, as the comparison example below does.

The life of a template

A template goes through three steps. template.New(name) creates an empty, named template. Parse(text) turns the source text into a parse tree and reports syntax errors. Execute(w, data) walks the tree with data as the starting value, writes the result to the io.Writer w and reports execution errors. Parsing is the expensive part and a parsed template is immutable in practice, so a program parses its templates once, at start-up, and executes them many times, from as many goroutines as it likes.

template.Must takes a (*Template, error) pair and panics on an error. It is meant for package-level variables and main, where a template that does not parse is a programming error that should stop the program at start-up, not a runtime condition to handle.

package main

import (
	"fmt"
	"os"
	"text/template"
)

// Member is a library member.
type Member struct {
	Name  string
	Loans []string
}

// Greeting returns a salutation; templates can call niladic methods.
func (m Member) Greeting() string { return "Welcome back, " + m.Name }

// Remaining reports how many loans are still allowed; the second result
// is an error that stops execution when non-nil.
func (m Member) Remaining(limit int) (int, error) {
	if len(m.Loans) > limit {
		return 0, fmt.Errorf("member %s is over the limit of %d", m.Name, limit)
	}
	return limit - len(m.Loans), nil
}

func main() {
	const text = "{{.Greeting}}!\n" +
		"You have {{len .Loans}} loan(s): {{range .Loans}}[{{.}}]{{end}}\n" +
		"You may borrow {{.Remaining 4}} more.\n"

	tmpl, err := template.New("welcome").Parse(text)
	if err != nil {
		fmt.Fprintln(os.Stderr, "parse:", err)
		os.Exit(1)
	}
	m := Member{Name: "Ada", Loans: []string{"Go", "Rust"}}
	if err := tmpl.Execute(os.Stdout, m); err != nil {
		fmt.Fprintln(os.Stderr, "execute:", err)
		os.Exit(1)
	}

	// A method that returns a non-nil error stops execution.
	over := Member{Name: "Bob", Loans: []string{"a", "b", "c", "d", "e"}}
	err = tmpl.Execute(os.Stdout, over)
	fmt.Println()
	fmt.Println("error:", err)
}

Points worth noticing in the output:

  • The template text is ordinary data. Everything outside {{ }} is copied unchanged; everything inside is an action.

  • {{.Greeting}} called the method Greeting of the value m. A template can call a method with no arguments by naming it, or with arguments by listing them after the name, as in {{.Remaining 4}}.

  • A method may return one value, or two values whose second is an error. When the error is non-nil, execution stops and Execute returns the error. Output produced before the failure has already been written: for Bob the writer received You may borrow ` and then nothing. The error message names the template, the line and column and the action that failed (`welcome:3:17), and wraps the cause.

  • Execute returns an error for a failing io.Writer as well, and then the error is the writer’s error itself.

Partial output matters for web handlers; see The shelf catalogue as HTML for the usual remedy of rendering into a buffer.

Data and dot

The cursor of a template is written . and called dot. It starts as the data argument of Execute and changes inside range, with and template actions. $ always refers to the data that Execute received, whatever dot is at that point.

Expression Meaning

{{.}}

The current value of dot

{{.Title}}

Field Title of a struct (the field must be exported)

{{.Authors}}

A field that is a slice, map or any other value

{{.Stock.go}}

Key go of a map. Map keys written this way must be identifiers; they need not start with an upper-case letter

{{.Author.Name}}

Chained fields and keys, to any depth; pointers are dereferenced automatically

{{.Greeting}}

A method with no arguments (called)

{{.Remaining 4}}

A method with arguments (the call can be the last element of a chain)

{{$.Title}}

Field of the root data, even inside a range

{{index .Stock "go"}}

The index function, for keys that are not identifiers or that are computed

Anything that is not exported cannot be reached. The template package uses reflection, so only exported fields and methods are visible, and a lower-case name gives a clear execution error (see Execution errors). A pointer in the path is followed automatically; a nil pointer in the middle of a chain is an error, not an empty string. A value that is a function is not called when it is a field or a map entry; it is called with the call function ({{call .Hook 1 2}}), and it can be tested with if.

Actions

An action is anything between the delimiters. Parse accepts these forms:

Action Effect

{{/* comment */}}

A comment; discarded. It must start and end at the delimiters and does not nest

{{pipeline}}

Prints the value of the pipeline, as fmt.Print would (escaped contextually in html/template)

{{if pipeline}} T1 {{end}}

Runs T1 when the value of the pipeline is not empty

{{if pipeline}} T1 {{else}} T0 {{end}}

With a fallback branch

{{if p1}} T1 {{else if p2}} T2 {{else}} T0 {{end}}

A chain of conditions, equivalent to nested if actions

{{range pipeline}} T1 {{end}}

Runs T1 once for each element, with dot set to the element

{{range pipeline}} T1 {{else}} T0 {{end}}

Runs T0 when there are no elements; dot is unchanged inside T0

{{break}} and {{continue}}

Leave the innermost range, or skip to its next iteration (Go 1.18)

{{with pipeline}} T1 {{end}}

Runs T1 with dot set to the value when it is not empty

{{with pipeline}} T1 {{else with p2}} T2 {{else}} T0 {{end}}

A chain of with actions (Go 1.23)

{{define "name"}} T {{end}}

Defines an associated template; only at the top level of a template text

{{template "name"}} and {{template "name" pipeline}}

Runs the named template with nil data, or with dot set to the pipeline

{{block "name" pipeline}} T {{end}}

Defines the template and runs it in place; used for overridable defaults

range accepts an array, slice, map, channel, integer (Go 1.24), or an iter.Seq or iter.Seq2 function (Go 1.24). A map is visited in sorted key order when its keys have a defined order (strings and numbers), which makes template output deterministic, unlike a for range loop over a map in Go code. With two variables, {{range $i, $v := .Books}} sets $i to the index (or the key) and $v to the element; with one variable, {{range $v := .Books}}, the variable is the element, the opposite of for i := range in Go code, where a single variable is the index.

package main

import (
	"fmt"
	"iter"
	"os"
	"text/template"

	"example.com/shelf/catalog"
)

type Shelf struct {
	Name    string
	Books   []catalog.Book
	Owner   *catalog.Author
	Notes   map[string]string
	Overdue []catalog.Loan
}

func (s Shelf) Titles() iter.Seq[string] {
	return func(yield func(string) bool) {
		for _, b := range s.Books {
			if !yield(b.Title) {
				return
			}
		}
	}
}

func main() {
	const text = `{{- /* A comment; the dashes trim surrounding white space. */ -}}

{{- if not .Books}}
  (empty)
{{- else if eq (len .Books) 1}}
  one book
{{- else}}

{{- end}}

{{range $i, $b := .Books -}}

{{end -}}

{{with .Owner}}Owner: {{.Name}}{{else with .Notes}}Notes: {{len .}}{{else}}No owner, no notes{{end}}

{{range $k, $v := .Notes}}{{$k}}={{$v}}; {{end}}
{{range .Overdue}}{{.Book}}{{else}}Nothing is overdue.{{end}}

{{range 3}}{{.}} {{end}}
{{range .Titles}}{{if eq . "Skip me"}}{{continue}}{{end}}{{if eq . "Stop"}}{{break}}{{end}}<{{.}}>{{end}}
`
	tmpl := template.Must(template.New("shelf").Parse(text))

	s := Shelf{
		Name: "Go",
		Books: []catalog.Book{

			{Title: "Third"},
			{Title: "Stop"},
			{Title: "Never shown"},
		},
		Notes: map[string]string{"room": "2", "floor": "1"},
	}
	if err := tmpl.Execute(os.Stdout, s); err != nil {
		fmt.Fprintln(os.Stderr, err)
	}
}

Details that the example shows:

  • The first line, {{- /* ... */ -}}, is a comment with trim markers; the comment produces no output and the markers remove the white space around it, so the output begins with Shelf.

  • {{.Name | printf "%q"}} is a pipeline (see below) that quotes the name.

  • {{- else if eq (len .Books) 1}} shows that an if chain is not "one big condition": the not .Books test is false, and eq (len .Books) 1 is false too, so the plain else ran. The branch printed 5 books.

  • {{with $b.Authors}} by {{(index . 0).Name}}{{else}} (anonymous){{end}}: inside with, dot is the author slice; an empty slice, and nil, take the else branch. Parentheses group index . 0 so that .Name applies to its result.

  • {{with .Owner}}...{{else with .Notes}}...{{else}}... is the Go 1.23 chain: the owner is a nil pointer, so the second with ran with dot set to the notes map (len . is 2). Before Go 1.23 the same logic needed a nested {{else}}{{with ...}}...{{end}}{{end}}.

  • {{range .Overdue}}...{{else}}Nothing is overdue.{{end}} uses the range else for the empty case.

  • {{range 3}} iterates over 0 1 2, and {{range .Titles}} ranges over a method that returns an iter.Seq[string], where continue skipped Skip me and break ended the loop at Stop, so Never shown is never visited. Both forms need Go 1.24 or later.

  • The notes were printed in sorted key order (floor before room), although the Go map literal lists room first.

White space and trim markers

Text between actions is copied exactly, including the newlines that make a template readable in a source file. If the left delimiter is followed by a minus and a white-space character, {{- x}}, all white space before the action is removed; if the right delimiter is preceded by a space and a minus, {{x -}}, all white space after it is removed. The white space is required: {{-3}} is the number minus three, while {{- 3}} is 3 with trimmed predecessor. White space is space, tab, carriage return and newline. Trimming applies to the adjacent text, not to the output of other actions. Most templates that generate line-oriented output (YAML, source code, e-mail) use trim markers on every control action so that if, range and end lines leave no blank lines behind.

Which values count as true

if, with, and, or and not test whether a value is "empty". The rule is that of template.IsTrue: false, zero numbers, nil pointers and interfaces, and arrays, slices, maps and strings of length zero are false; everything else is true.

package main

import (
	"fmt"
	"text/template"
	"time"
)

type Loan struct{ Member string }

func main() {
	var nilLoan *Loan
	var nilErr error
	values := []struct {
		label string
		v     any
	}{
		{"false", false},
		{"0", 0},
		{"0.0", 0.0},
		{`""`, ""},
		{"nil", nil},
		{"nil *Loan", nilLoan},
		{"nil error", nilErr},
		{"[]int{}", []int{}},
		{"map[string]int{}", map[string]int{}},
		{"&Loan{}", &Loan{}},
		{"Loan{} (empty struct)", Loan{}},

The surprises are the last rows. A struct is always true, even when it is the zero value, because there is no general notion of "an empty struct": time.Time{} is true. Test the property you mean, for example {{if not .Due.IsZero}} for "has a due date", or add a method to the type. The string "false" is true, and so is a slice that holds a single zero value.

Variables

A pipeline can be stored in a variable whose name starts with $. {{$n := len .Tags}} declares $n and prints nothing; {{$n = 10}} assigns to an existing variable. A variable’s scope extends to the end of the control action (if, with, range) in which it was declared, or to the end of the template when it was declared at the top level. range can declare one or two variables, as shown above. A {{template}} call does not inherit the caller’s variables, and referring to an undeclared one is a parse error (undefined variable "$x"), reported before anything runs. Assigning inside a nested block with = changes the outer variable, whereas := would declare a new one that disappears at end; this is the same shadowing rule as in Go code.

Pipelines, arguments and functions

An argument is a constant, nil, dot, a variable, a field, a map key, a method or a function name, or a parenthesised argument. Constants follow Go’s syntax: {{1_000}}, {{0x1F}}, {{'a'}} (the rune, printed as 97), {{1.5e3}}, {{true}}, interpreted strings with escapes and raw strings in backquotes.

A pipeline is one or more commands separated by |. The result of each command is passed as the last argument of the next, so {{"ada lovelace" | upper | printf "%s!"}} is printf("%s!", upper("ada lovelace")). A command that returns an error as a second value stops execution when it is non-nil.

package main

	"errors"
	"fmt"

			}
			return b.String()

	}

	const text = `printf:   {{printf "%-8s|%5.1f|%03d" "shelf" 3.14159 7}}

The predefined functions

Function Description

and, or, not

Boolean logic over truthiness. and returns its first empty argument, or the last; or returns its first non-empty argument, or the last. Arguments are evaluated left to right and evaluation stops as soon as the result is known (since Go 1.18)

eq, ne, lt, le, gt, ge

Comparisons. eq alone accepts more than two arguments ({{eq .Kind "a" "b"}} means Kind == "a" || Kind == "b"), but all arguments are evaluated. Operands must be of comparable basic kinds; any signed or unsigned integers compare with each other, but an integer and a string, or an int and a float32, are an error

len

Length of a string, array, slice, map or channel

index

{{index x 1 2 3}} is x[1][2][3] for maps, slices and arrays; an out-of-range index is an error

slice

{{slice x 1 2}} is x[1:2]; {{slice x}} is x[:]; three indexes give a full slice expression; for strings, slices and arrays

print, printf, println

fmt.Sprint, fmt.Sprintf, fmt.Sprintln. Note that Sprint adds spaces between operands when neither is a string, which is why {{print "a" 1 2 "b"}} printed a1 2b

call

Calls a function-valued field or map entry: {{call .Format 3}}

html, js, urlquery

Escape the text of their arguments for HTML, JavaScript and URL queries. They exist in text/template for manual escaping; in html/template they are unavailable except as the last command of a pipeline, because the package escapes automatically

Functions are looked up first in the template’s own FuncMap, then in the predefined set, so a custom function replaces a predefined one of the same name; avoid doing that, because the next reader expects len to be len.

Custom functions

Template.Funcs(template.FuncMap{...}) adds functions. A function must have one result, or two with the second being an error, and it can take arguments of any type that the pipeline can supply (a parameter of type any or reflect.Value accepts every type). The map must be installed before Parse, because the parser resolves function names while reading the template; a template that mentions an unknown function does not parse. Funcs panics when a map value is not a suitable function or the name cannot be used as a function name, so call it during start-up.

Keep template functions small and pure: formatting (dates, money, ISBN hyphenation), simple arithmetic that has no better home, safe construction of URLs, and lookups that cannot fail. Business rules belong in Go code that prepares the view model. A function that returns a value of a trusted content type, such as template.HTML, bypasses escaping; see the section on html/template below.

Nested templates

A template is a named piece of text. A Template value also carries an association: the set of other templates that it can invoke by name with {{template "name" data}}. Associations are created in three ways:

  • {{define "name"}}...{{end}} inside the text given to Parse defines an additional template associated with the one being parsed. Definitions must appear at the top level of a template text, not inside another action.

  • t.New("name") creates a new, empty template associated with t; parse text into it with Parse.

  • ParseFiles, ParseGlob and ParseFS create one template per file, named by the file’s base name, all associated with each other (see below).

{{block "name" pipeline}}default{{end}} is a define immediately followed by a template call. It is the tool for layouts: the base template defines a block with default content, and a derived template set redefines the block. A template can be associated with only one set. To use the same text in two sets, parse it twice, or Clone the set first.

package main

	"fmt"

The example uses the methods that deal with the set:

  • Execute runs the template named by the value on which it is called (page), ExecuteTemplate(w, name, data) runs any associated one. Executing a name that is not in the set is an error that names the template that was asked (no template "nope" associated with template "page").

  • Clone() copies the set. Parsing a new definition of header into the clone leaves the original untouched, which is the way to derive a variant of a layout without rebuilding it. With html/template, cloning is only possible before the first execution (see below).

  • Parse can be called repeatedly on the same template. A definition whose body is only white space and comments does not replace an existing body, so a text consisting of just define actions adds templates without overwriting the main one.

Loading templates from files and from an embedded filesystem

ParseFiles(names...), ParseGlob(pattern) and ParseFS(fsys, patterns...) create a template per file. The template for templates/layout.gohtml is named layout.gohtml, with directories dropped; two files with the same base name in different directories collide and the last one wins. The returned *Template is named after the first file, and when you call the method form, t.ParseFiles(...), t should carry one of the file names or you must call ExecuteTemplate with the name you want. ParseFS accepts any fs.FS, so embed.FS makes the templates part of the binary and removes the "where is the working directory?" problem of deployments; the pattern follows path.Match, so use forward slashes.

Typical conventions: the file extension is free (.tmpl, .gotmpl, .gohtml, .html); .gohtml tells editors and readers that the file is a Go HTML template. There is no inheritance mechanism beyond block and association, so a page-per-set structure is common, as in the cmd/shelfd example below.

Options and delimiters

Template.Option("missingkey=...") controls what happens when a map is indexed by a key it does not contain (a missing struct field is always an error):

Option Behaviour

missingkey=default (or invalid)

The default. The action prints <no value> in text/template; in html/template it prints an empty string

missingkey=zero

The zero value of the map’s element type. For a map[string]any the zero value is a nil interface, so text/template still prints <no value>

missingkey=error

Execution stops with an error

missingkey=error is the right setting for configuration and manifest generation, where a typo in a key should fail loudly rather than produce <no value> in the output; the example in the Helm section below uses it. Option panics on an unknown or malformed option string.

Template.Delims(left, right) changes the delimiters for subsequent Parse calls, for text that already contains {{, such as JSON, Go source with generics-free braces, or the output of another template engine. An empty string means the default. Nested definitions inherit the setting.

What to take from the output:

  • Syntax errors (unclosed action, unexpected EOF, an unknown function, an undefined variable, a stray end, break outside range, a define that is not at the top level) are parse errors, reported by Parse with the template name and line, before any data is involved.   • Data errors are execution errors: a missing field, an unexported field, a nil pointer in a chain, a method called with the wrong number or type of arguments, a comparison between incompatible kinds, an index out of range, len of a type that has no length, an unknown template. Contextual auto-escaping with html/template

The problem

HTML is not one language but five that nest: text, tags and attributes, URLs, CSS and JavaScript. A string that is harmless in one place is code in another: O'Reilly & <i>Sons</i> is fine as text, breaks out of a single-quoted attribute, and ends a JavaScript string in an event handler. Escaping "for HTML" once, with a function such as HTMLEscapeString, protects only the first of those places. The classic injection holes (cross-site scripting) come from printing user-controlled data into a place the escaper did not consider.

html/template solves this at the root. When a template is executed for the first time, the package runs a static analysis over the whole parse tree: it follows the text between actions through a state machine that models the HTML, CSS and JavaScript tokenisers, so it knows, for every {{ }}, whether the value is going to be inside element text, an attribute value (quoted or not), a URL (and which part of it), a CSS value, a JavaScript expression, string or regular expression. It then rewrites each action to add exactly the escaping functions that context requires. The documentation shows the effect: <a href="/search?q={{.}}">{{.}}</a> becomes <a href="/search?q={{. | urlescaper | attrescaper}}">{{. | htmlescaper}}</a>. The template author writes plain {{.Title}}, in every place, and the package picks the escaper. This property is called contextual autoescaping.

The same template text is run through both packages below, with a deliberately hostile title, a javascript: link and a font name that tries to inject CSS.

Read the second half of the output line by line:

  • In element text, <, >, & and both quotes become entities: &lt;script&gt;alert(&#34;x&#34;)&lt;/script&gt;.

  • In the query part of a URL, every byte that is not an unreserved URL character is percent-encoded, so the title can never end the query or start a new parameter.

  • In a link that begins with the value, the URL is filtered as well as encoded: javascript:alert(1) has a scheme other than http, https or mailto, so the output is #ZgotmplZ, a harmless placeholder that makes the problem visible in the page source. A relative URL passes.

  • In a quoted attribute, the value is HTML-escaped, so a quote in the data cannot end the attribute.

  • In a <script> element the Go value becomes a JavaScript value, not text: the string is a quoted JavaScript string with <, > and & written as \u003c, \u003e and \u0026, and the map is a JSON object.   • In an inline event handler (onclick), which is JavaScript inside an HTML attribute, the escaping is both: the string body is JavaScript-escaped (\u0027) and the result is attribute-safe.

  • In CSS, a value that does not look like a safe token is replaced by #ZgotmplZ, so the attacker’s ; background: url(evil) never reaches the style sheet.

Typed content: telling the package that a value is already safe

The types template.HTML, HTMLAttr, JS, JSStr, CSS, URL and Srcset are strings that carry a promise: "this is safe in the right context; do not escape it". The package then writes the value verbatim, or just checks that it is compatible with the context.

The example shows what the types do and what they cost:

  • A plain string with markup is escaped; the same text converted to template.HTML is written verbatim, including its onclick attribute. Converting a value to template.HTML is the way to introduce an XSS hole in a Go web application: the conversion cannot be checked by the compiler, so every one of them needs a reason you could defend in a code review (usually: it was produced by a sanitizer, or by another template from this package).

  • template.URL("javascript:alert(1)") suppresses the scheme filter and the browser would run it: the output keeps javascript: (with the parentheses percent-encoded, which does not make it safe). Never convert user input.

  • template.HTMLAttr("disabled") is written as an attribute; the same text as a plain string, with an injected onfocus=..., is replaced by the harmless ZgotmplZ.

  • template.JS("1 + 2") is written into the script as an expression, and template.JSStr inside quotes is written verbatim. Do not use template.JS for untrusted JSON; unmarshal it with encoding/json and pass the Go value, which the package re-encodes safely.

  • Comments in the template are stripped; a comment in template.HTML data is not.

The rule of thumb: keep data as plain Go values and let the package escape it; use a typed string only for markup that your own code, or a trusted sanitizer, created. The type belongs on a function result or a view-model field, close to where the trust decision was made, and not in a place where it is sprinkled over arbitrary strings.

Escaping errors

Because the escaper must know the context of every action statically, a template whose context depends on runtime data is rejected. The escaper runs on the first Execute, not on Parse, so these errors appear when the template is first used. This is one more reason to render every template in a test, as shown later. The errors are *template.Error values with an ErrorCode, the template name and, where known, the line; the code is available with errors.AsType.

An action in a URL whose position depends on a condition (href="{{if .C}}/a/{{else}}/s?q={{end}}{{.X}}"). Move the action into each branch

ErrBadHTML

Malformed tag syntax: an unquoted attribute with <, href = /x, a typo in a tag name. Quote all attributes

ErrBranchEnd

The branches of an if, range or with end in different contexts ({{if .C}}<a href="{{end}}). Put whole tags inside the branches

ErrEndContext

A template (or fragment) ends inside a tag, attribute, script or other non-text context. Such a template cannot be executed directly

ErrNoSuchTemplate

A template call whose target is not defined when the caller is first escaped

ErrOutputContext

A recursive template that does not finish in the context it started in

ErrPartialCharset

An action inside a JavaScript regular expression character class (/foo[{{.}}]/). Not supported

ErrPartialEscape

An action right after a backslash in a JavaScript string ("\{{.X}}"). Write "{{.X}}" and pass template.JSStr for a deliberate partial escape

ErrRangeLoopReentry

A range whose second iteration ends in another context than the first, typically a missing quote in a script

ErrSlashAmbig

A / in JavaScript that could be division or the start of a regular expression, depending on a branch. Add semicolons or parentheses

ErrPredefinedEscaper

html or urlquery used in the middle of a pipeline. Remove it; the package already escapes

ErrJSTemplate

Deprecated. Formerly returned for actions inside a JavaScript template literal, which are supported now

The "ends in a non-text context" and "branches end in different contexts" messages include the escaper’s internal state ({stateURL delimDoubleQuote ...}), as the output above shows; read them as "the template ended inside a URL in a double-quoted attribute". A frequent real cause is a missing closing quote or > far from the action named in the error.

Lifecycle: execute once, then the set is frozen

html/template rewrites the parse tree during the first Execute. Afterwards, the set cannot change. Parse after Execute, and Clone, AddParseTree of a template that has executed, return an error; clone and add templates before you execute any of them.

package main

import (
	"fmt"
	"html/template"
	"io"
	"strings"
)

func main() {
	t := template.Must(template.New("page").Parse(`<p>{{.}}</p>`))

	// Funcs must be registered before Parse; an unknown function is a parse error.
	_, err := template.New("f").Parse(`{{shout .}}`)
	fmt.Println("unknown func:", err)

	shout := template.FuncMap{"shout": strings.ToUpper}
	f := template.Must(template.New("f").Funcs(shout).Parse(`<b>{{shout .}}</b>`))
	_ = f.Execute(io.Discard, "ok")

	// The first Execute runs the escaper and freezes the template set.
	_ = t.Execute(io.Discard, "x")
	_, err = t.Parse(`{{define "late"}}x{{end}}`)
	fmt.Println("parse after execute:", err)
	_, err = t.Clone()
	fmt.Println("clone after execute:", err)

	// A template that is never executed can still be cloned and extended.
	base := template.Must(template.New("base").Parse(`{{block "b" .}}default{{end}}`))
	v := template.Must(base.Clone())
	template.Must(v.Parse(`{{define "b"}}variant{{end}}`))
	var sb strings.Builder
	_ = v.Execute(&sb, nil)
	fmt.Println("variant:", sb.String())
}

Details worth knowing

  • Comments. HTML comments in a template are removed from the output. Do not put secrets or TODOs in them anyway; use {{/* */}}, which never reaches the output of either package.

  • Quoting. The unquoted attribute <a href=/x?q={{.}}> is handled by a stricter escaper and some inputs are rejected as ErrBadHTML. Always quote attribute values.

  • JavaScript template literals. Actions inside backtick strings in <script> are escaped and supported again by default. The release notes list this change under Go 1.22 and the GODEBUG history file under Go 1.23; either way, jstmpllitinterp no longer has any effect. Between Go 1.21 and that release, an action inside a template literal was an error (ErrJSTemplate).

  • <meta> refresh URLs (Go 1.27). A URL in the content attribute of a <meta http-equiv="refresh"> is now escaped and filtered like a URL. The behaviour was added as a security fix and backported to Go 1.25.8 and 1.26.1. The setting is htmlmetacontenturlescape; GODEBUG=htmlmetacontenturlescape=0 restores the old behaviour. The documentation text for the setting spells its default htmlmetacontentescape=1, but the name in the source and in the godebugs table is htmlmetacontenturlescape. The example below was run with and without the setting.

  • JSON in script blocks. A Go struct, map or slice in a <script> becomes a JavaScript literal through encoding/json, so tags such as json:"isbn" apply there too (see encoding/json). For a JSON data island, prefer <script type="application/json" id="data">{{.Data}}</script> and parse it in JavaScript; the package encodes the value as JSON there too, and writes </script> inside a string as \u003c/script\u003e.

  • Manual escaping functions. template.HTMLEscapeString, JSEscapeString, URLQueryEscaper and friends exist for code outside templates (for example when writing an error message in a handler). Inside html/template, do not combine them with the automatic escaping: the result is escaped twice.

What html/template does not do

  • It does not sanitize HTML. It escapes strings; it cannot make a piece of untrusted markup (a forum post with allowed <b> tags) safe. That needs a sanitizer, whose output you may then mark template.HTML.

  • It does not validate where a URL points. href="{{.Next}}" with an attacker-controlled absolute https: URL is accepted; open-redirect checks belong in the handler.

  • It trusts the template author. Anyone who can edit the template text can write a script tag; templates are source code.

  • It does not set a Content Security Policy, CSRF tokens, cookies or any HTTP header. Those belong to the handler and middleware (see net/http Clients and Servers, CORS and the discussion of cross-site request forgery in Axum CSRF and security hardening, whose concepts transfer). A nonce for a CSP script-src is an ordinary string field on the view model.

  • It does not protect output that is not HTML. For JSON responses use encoding/json; for plain text responses text/template is correct, and html/template would escape characters that should stay literal.

//go:embed templates/*.gohtml
var templateFS embed.FS

// pages maps a page name to a template set: the shared layout plus one page.
type pages map[string]*template.Template

func loadPages() (pages, error) {
	p := pages{}
	for _, name := range []string{"books", "book"} {
		t, err := template.ParseFS(templateFS,
			"templates/layout.gohtml", "templates/"+name+".gohtml")
		if err != nil {
			return nil, fmt.Errorf("parse %s: %w", name, err)
		}
		p[name] = t
	}
	return p, nil
}

type server struct {
	store catalog.Store
	pages pages
}

// render executes into a buffer first, so a failing template never sends a
// half-written page with a 200 status.
func (s *server) render(w http.ResponseWriter, r *http.Request, status int, page string, data any) {
	var buf bytes.Buffer
	if err := s.pages[page].ExecuteTemplate(&buf, "layout.gohtml", data); err != nil {
		slog.Error("render", "page", page, "err", err)
		http.Error(w, "internal error", http.StatusInternalServerError)
		return
	}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	w.Header().Set("X-Content-Type-Options", "nosniff")
	w.WriteHeader(status)
	_, _ = w.Write(buf.Bytes())
}

type catalogView struct{ Books []catalog.Book }

// view returns the whole catalogue sorted by title, so pages are stable.
func (s *server) view() catalogView {
	books := s.store.All()
	slices.SortFunc(books, func(a, b catalog.Book) int {
		return strings.Compare(a.Title, b.Title)
	})
	return catalogView{books}
}

type bookView struct {
	catalogView
	Book  catalog.Book
	State catalog.LoanState
}

func (s *server) routes() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", func(w http.ResponseWriter, r *http.Request) {
		s.render(w, r, http.StatusOK, "books", s.view())
	})
	mux.HandleFunc("GET /books/{isbn}", func(w http.ResponseWriter, r *http.Request) {
		isbn, err := catalog.ParseISBN(r.PathValue("isbn"))
		if err != nil {
			http.NotFound(w, r)
			return
		}
		b, ok := s.store.Get(isbn)
		if !ok {
			http.NotFound(w, r)
			return
		}
		s.render(w, r, http.StatusOK, "book", bookView{s.view(), b, catalog.Available})
	})
	return mux
}

Design points, in the order of the code:

  • //go:embed templates/*.gohtml puts the files in the binary; ParseFS reads them from the embed.FS with a glob (see Directives, Code Generation and Embedding). In development, template.ParseFS(os.DirFS("templates"), ...) re-reads the files from disk, so a rebuild is not needed.

  • loadPages parses every template at start-up and returns an error, which main reports and exits on. A page that does not parse should never be discovered by the first visitor.

  • render executes into a bytes.Buffer first and writes to the http.ResponseWriter only when the template succeeded. Executing straight into the response would send 200 OK and half a page, followed by an error that cannot change the status any more. The cost is one buffer per response; a sync.Pool of buffers removes it if profiling ever shows it.

  • The handler sets Content-Type: text/html; charset=utf-8 and X-Content-Type-Options: nosniff itself; html/template does not touch headers.

  • The list is sorted before it reaches the template, because MemStore.All iterates a map. Sorting belongs in Go code, not in the template.

  • The route patterns are the Go 1.22 ServeMux patterns: GET /{$} matches only the root, GET /books/{isbn} captures a path value that the handler validates with catalog.ParseISBN before looking it up; an unknown or malformed ISBN gets a 404 without ever reaching a template.

  • The hostile-looking title Algebra <& Geometry> and the author name Bo "B" Li are escaped in element text and in the <title> element, which has its own (RCDATA) context, with no code in the template.

Templates and trust

text/template and html/template assume that the author of the template is trusted and that the data may not be. These are different questions:

  • The data in html/template is escaped, so a visitor who types <script> into a form cannot run it.

  • The template text is code. A template can read every exported field of its data, call every exported method (with arguments), and run every function in the FuncMap. If untrusted users can write templates (an admin-editable e-mail template, a user-defined report layout), those users can read whatever the data exposes and trigger whatever its methods do. The text/template documentation says plainly that its security model assumes trusted template authors, and that it does not auto-escape.

package main

import (
	"fmt"
	"os"
	"strings"
	"sync"
	"text/template"
)

// Session is data handed to a template. Everything exported is reachable.
type Session struct {
	User     string
	APIToken string // placeholder value; never put real secrets in template data
}

func (s *Session) Logout() string { return "logged out " + s.User }

var greeting = template.Must(template.New("greeting").Parse("hello {{.User}}\n"))

func main() {
	// 1. A parsed template is safe for concurrent Execute calls; only the
	//    shared writer needs protection.
	var (
		wg  sync.WaitGroup
		mu  sync.Mutex
		out strings.Builder
	)
	for _, name := range []string{"ada", "bo", "cy"} {
		wg.Go(func() {
			var local strings.Builder
			_ = greeting.Execute(&local, &Session{User: name})
			mu.Lock()
			out.WriteString(local.String())
			mu.Unlock()
		})
	}
	wg.Wait()
	fmt.Println(len(strings.Split(strings.TrimSpace(out.String()), "\n")), "greetings rendered")

	// 2. A template written by an untrusted user is code: it can read every
	//    exported field and call every exported method of its data.
	userTemplate := "token={{.APIToken}} {{.Logout}}\n"
	t := template.Must(template.New("user").Parse(userTemplate))
	_ = t.Execute(os.Stdout, &Session{User: "ada", APIToken: "EXAMPLE-NOT-A-REAL-TOKEN"})
}

token=EXAMPLE-NOT-A-REAL-TOKEN logged out ada

The remedies are structural: pass a small, purpose-built view model that contains only what the template should see; give it no methods with side effects (Logout above is the anti-example); never put secrets, tokens or database handles in template data; and, for user-written templates, use a deliberately limited language such as a placeholder substitution rather than text/template.

The first half of the example shows the concurrency rule. A parsed template can be executed from many goroutines at the same time, because execution does not mutate it; the only shared mutable thing is the writer, which here is guarded by a mutex (and, in a web server, is a per-request ResponseWriter). Template construction (New, Parse, Funcs, Clone) must not run concurrently with other uses of the same set. wg.Go (Go 1.25) starts a goroutine and counts it in the wait group in one call; because Go 1.22 each iteration of for range has its own name, so the closure is correct.

Generating source code and other text

text/template is also the tool behind many go generate programs, because it separates the shape of the output from the data that fills it. Go templates outside Go: Helm and kubectl

The Go template language is used well beyond Go programs, because text/template is easy to embed. The two most common places for an infrastructure engineer are Helm and kubectl; both have their own pages in this site, and this page explains the language underneath them.

  • Helm renders every file in a chart’s templates/ directory with text/template plus a function library, then applies the result. The constructs you saw in this page are the ones in a chart: {{define}} and {{template}} in _helpers.tpl, {{range}} and {{with}} for lists and optional blocks, {{if}}, pipelines, trim markers ({{- is essential in YAML, where indentation is structure), and .Values, .Release and .Chart as the data. Helm adds functions (include, toYaml, nindent, default, required, tpl, and a large set of string and list helpers) that are not part of the standard library; they are not available in plain text/template. See Helm, especially "The template language".

  • kubectl offers -o go-template='...' and -o go-template-file: the object (or list) is decoded from JSON and your template is executed with it, so field names are the lower-case JSON keys (.items, .metadata.name). See kubectl essentials, "Output formats".

The following program implements a miniature of both with only the standard library: Helm-style helpers (include, nindent, default, required) written as a FuncMap, a deployment template that uses them, missingkey=error, and a kubectl-style template run over a JSON pod list. It shows what those tools do under the hood and why their error messages look like the ones in the execution-errors section.

		// action cannot be used in a pipeline.
		"include": func(name string, data any) (string, error) {
			var buf bytes.Buffer
			err := t.ExecuteTemplate(&buf, name, data)
			return buf.String(), err
		},
		"nindent": func(n int, s string) string {
			pad := strings.Repeat(" ", n)
			return "\n" + pad + strings.ReplaceAll(s, "\n", "\n"+pad)
		},
		"default": func(def, v any) any {
			if truth, _ := template.IsTrue(v); truth {
				return v
			}
			return def
		},
		"required": func(msg string, v any) (any, error) {
			if truth, _ := template.IsTrue(v); !truth {
				return nil, errors.New(msg)
			}
			return v, nil
		},
	})

Things the example makes concrete:

  • include is a function, not an action, which is why {{include "shelf.labels" . | nindent 4}} can be piped, while {{template "shelf.labels" .}} cannot. The function is a closure over the template set that calls ExecuteTemplate and returns the text; Helm provides its include in the same spirit.

  • nindent 4 writes a newline and indents every line; YAML is whitespace-sensitive, and most Helm template bugs are an indentation or trim-marker slip.

  • required and default look at truthiness: a replicaCount of 0 is empty, so default 1 replaced it. Remember the table of true and false values when a value of zero or an empty string has meaning.

  • With missingkey=error, a key that is absent from the values map (tag) stops the render, before default can supply a fallback; with an empty-but-present key (repository: ""), required produced its own message. Helm’s required and defaults work on keys that exist in values.yaml, which is why charts declare every value there.

  • kubectl runs the template with the decoded JSON, a map[string]any tree, so .items and .status.phase are map keys. A missing key is silent by default, which is the same trade-off as missingkey=default; the flag --allow-missing-template-keys=false of kubectl get turns it into an error.

The Kubernetes operators page, Custom Resources and Operators, uses Go for controllers; the templates above are about manifests, which are data, whereas controllers build objects as typed Go structs and never need a template.

Practical guidance

  • Parse once, execute often. Parse at start-up into package-level variables or a struct, as the server above does; never call Parse per request, which repeats the escaping analysis and allocates the parse tree every time.

  • Fail early. Use template.Must or return the error from loadPages before listening on a port. Render every template in a test to trigger the first-execution escaping errors.

  • Buffer the output of a page so that a failure can still produce a 500 page; flush it on success.

  • Pass a view model, not the domain object. A struct with exactly the fields the page shows keeps methods with side effects and secrets out of reach and lets Go code (not the template) do sorting, formatting and decisions.

  • Keep logic out of templates. A range with an if and a few formatting functions is fine; if a template needs a FuncMap with a dozen functions that call the database, the view model is too thin.

  • Name templates and blocks by purpose and keep one concern per file; a partials/ convention ({{template "partials/pager" .Pager}}) works with ParseFS globs such as templates/*.gohtml and templates/partials/*.gohtml.

  • Use html/template for everything that ends in a browser, including e-mail HTML bodies; use text/template for the plain-text alternative of the same e-mail.

  • Third-party libraries. Type-checked template compilers and component libraries for Go exist outside the standard library; the standard packages remain the baseline and are what Helm and kubectl use. This page does not cover third-party modules.

Common pitfalls

Pitfall What happens and what to do

Using text/template for HTML

No escaping; the page is open to XSS. Import html/template

Converting user input to template.HTML or template.URL

Disables escaping for that value; the conversion is where the vulnerability is

Forgetting that Funcs precedes Parse

function "x" not defined at parse time

Executing straight into the ResponseWriter

A failure in the middle of the page leaves a truncated response with status 200; render into a buffer

Lower-case field names in the view model

is an unexported field of struct type; export the field

A zero struct or time.Time in if

Always true; test a method such as IsZero

A range with one variable

The variable is the element (not the index, as in Go code)

Dot changed inside range or with

.Title now means the element’s field; use $.Title for the root

eq between an int and a string, or int and float32

incompatible types for comparison; convert in Go code

Hidden typo in a map key; use Option("missingkey=error") in configuration templates

Slow and repeats the escaper work; parse once at start-up
