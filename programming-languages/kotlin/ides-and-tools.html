Kotlin IDEs & Tools

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page lists the IDEs and editors most commonly used to write Kotlin, with a link to each product’s official page. IntelliJ IDEA and Android Studio offer the most complete Kotlin support, since Kotlin is developed by JetBrains, while the editor-based options cover lighter workflows.

IDEs

  • IntelliJ IDEA — JetBrains' IDE, which bundles Kotlin support, refactoring and a Java-to-Kotlin converter.

  • Android Studio — Google’s official IDE for Android, built on the IntelliJ platform with Kotlin as the default language.

  • Eclipse Kotlin plugin — adds Kotlin editing and compilation to the Eclipse IDE.

Editors with extensions

  • VS Code Kotlin extension — Kotlin language support for Visual Studio Code, powered by a language server.

Choosing an IDE

Tool Best for Notes

IntelliJ IDEA

JVM back ends, libraries, Kotlin Multiplatform and general Kotlin work

first to receive new Kotlin tooling; Gradle and Maven projects are imported directly.

Android Studio

Android apps

IntelliJ-based, adds the Android emulator, layout and Compose tooling; use it for any module that applies the Android Gradle plugin.

Eclipse with the Kotlin plugin

teams already standardised on Eclipse

basic editing and compilation; fewer refactorings than the JetBrains IDEs.

VS Code with the Kotlin extension

quick edits and scripts

language-server features only; debugging and refactoring are limited compared with IntelliJ.

The Kotlin compiler front end is shared between the IDE and the command line (see Build and Tooling), so the errors the editor shows are the ones the build reports.

Kotlin Features Worth Knowing in the IDE

  • Convert Java File to Kotlin — paste Java code into a .kt file or use the menu action; review the result, because the converter keeps Java nullability assumptions (see Null Safety).

  • Show Kotlin Bytecode and Decompile — see exactly what a construct compiles to (see Kotlin and the JVM).

  • Inlay hints — the IDE can show inferred types, parameter names at call sites and lambda receivers, which is the usual way to read inferred code (see Basic Types and Variables).

  • Intentions and inspections — replace a manual loop with a collection operation, add a missing when branch for a sealed type, convert between a single-expression and a block body.

  • Run gutter icons next to main and test functions, and the debugger’s coroutine view for suspended coroutines.
