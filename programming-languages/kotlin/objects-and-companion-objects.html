Objects and Companion Objects

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The object keyword covers three related but distinct jobs that Java splits across the singleton pattern, static members and anonymous inner classes. This page explains each of the three forms, when each is created and initialised, how they compile to JVM bytecode (which matters as soon as Java code calls them), the pitfalls around initialisation order and hidden global state, and how they fit the running library example (Book, Member, Loan) used across this section.

The three forms, side by side:

flowchart TD O["object keyword"] --> D["object declaration: named singleton"] O --> C["companion object: singleton scoped to a class"] O --> E["object expression: anonymous, new instance each evaluation"] D --> D1["created lazily on first access of the class"] C --> C1["created when the enclosing class is loaded"] E --> E1["created every time the expression runs"]

object Declarations (Singletons)

object declares a class with exactly one instance, created lazily on first access — Kotlin’s built-in answer to the singleton pattern, with no separate getInstance() or double-checked locking boilerplate. The first access triggers the JVM class initialisation of the generated class, which the JVM specification guarantees to run once and in a thread-safe way:

object LibraryConfig {
    var maxLoansPerMember: Int = 3
    val loanDays: Int = 14

    init {
        println("LibraryConfig initialised")
    }

    fun describe() = "up to $maxLoansPerMember loans for $loanDays days"
}

fun main() {
    println("before first access")
    LibraryConfig.maxLoansPerMember = 5
    println(LibraryConfig.describe())
    println(LibraryConfig === LibraryConfig)   // always the same instance
}

Output:

before first access
LibraryConfig initialised
up to 5 loans for 14 days
true

LibraryConfig can implement interfaces and extend classes exactly like an ordinary class — it just cannot declare a constructor, because there is only ever the one, compiler-managed instance. An object is also useful as the payload-free case of a sealed hierarchy (see Sealed Classes and Enums) and, with a data object declaration, it gets a readable toString():

sealed interface LoanState {
    data object Open : LoanState
    data object Closed : LoanState
}

fun main() {
    println(LoanState.Open)    // Open
}

An object that holds mutable state is global state. It is shared by every caller, makes tests order-dependent and cannot be replaced by a fake. Prefer passing a collaborator through a constructor and reserve object for stateless helpers, constants and true singletons.

How an object compiles

For object LibraryConfig the compiler generates a final class LibraryConfig with a private constructor, a public static final LibraryConfig INSTANCE field assigned in the static initialiser, and instance methods for the members. Kotlin callers write LibraryConfig.describe(); Java callers must write LibraryConfig.INSTANCE.describe(). Annotate a member with @JvmStatic to also generate a real static method, so that Java can call LibraryConfig.describe() directly.

Companion Objects

A companion object is a singleton object scoped to a class, replacing Java’s static members — Kotlin has no static keyword at all. Its members are reached through the enclosing class name, and it has access to the private members of that class, which makes it the natural home for factory functions:

class Member private constructor(val id: Int, val name: String) {

    companion object {
        private var nextId = 1

        fun register(name: String): Member = Member(nextId++, name)   // factory function
    }

    override fun toString() = "Member($id, $name)"
}

fun main() {
    val ada = Member.register("Ada")
    val grace = Member.register("Grace")
    println(ada)
    println(grace)
    // Member(3, "x")   // does not compile: the constructor is private
}

Output:

Member(1, Ada)
Member(2, Grace)

A factory function behind a private constructor lets a class validate its input, cache instances, return a subtype or choose a descriptive name (Member.register) where a constructor could only be called Member.

A companion object is a real object: it can implement an interface (for example a shared Parser<T> contract across several classes) and can be passed around by its class name. The following example gives Book a parser:

fun interface Parser<T> {
    fun parse(text: String): T
}

data class Book(val isbn: String, val title: String) {
    companion object : Parser<Book> {
        override fun parse(text: String): Book {
            val (isbn, title) = text.split(";")
            return Book(isbn.trim(), title.trim())
        }
    }
}

fun <T> parseAll(lines: List<String>, parser: Parser<T>): List<T> = lines.map(parser::parse)

fun main() {
    val books = parseAll(listOf("1; Clean Code", "2; Refactoring"), Book)   // the class name is the companion
    println(books)
}

Output:

[Book(isbn=1, title=Clean Code), Book(isbn=2, title=Refactoring)]

Only one companion object is allowed per class, and it may optionally be named (companion object Factory { ... }), though Member.register(...) works identically either way. An unnamed companion is called Companion internally. Constants are better declared as const val (a compile-time primitive or String), which the compiler inlines like a Java static final constant:

class Loan {
    companion object {
        const val DEFAULT_DAYS = 14
    }
}

Companion objects and Java

In bytecode the companion is a nested class Loan$Companion, and the enclosing class holds a public static final Loan.Companion Companion field. Java code therefore writes Member.Companion.register("Ada"). To get a real static method on Member, annotate the function with @JvmStatic; to expose a property as a static field, use @JvmField (or const val). A companion can also be extended from outside the class: an extension function declared on Member.Companion is called as Member.guest(), which is a handy way to add factories without touching the class.

Object Expressions (Anonymous Classes)

An object : SomeType { ... } expression creates a one-off, unnamed instance of an interface or class — Kotlin’s equivalent of Java’s anonymous inner class, most often used where a lambda is not expressive enough (an interface with more than one abstract method) or where an extra property is needed:

interface LoanListener {
    fun onBorrowed(title: String)
    fun onReturned(title: String)
}

class Desk {
    private val listeners = mutableListOf<LoanListener>()
    fun register(l: LoanListener) { listeners += l }
    fun borrow(title: String) = listeners.forEach { it.onBorrowed(title) }
    fun giveBack(title: String) = listeners.forEach { it.onReturned(title) }
}

fun main() {
    var borrowedCount = 0
    val desk = Desk()
    desk.register(object : LoanListener {
        override fun onBorrowed(title: String) {
            borrowedCount++                       // captures and mutates a local variable
            println("borrowed $title")
        }
        override fun onReturned(title: String) = println("returned $title")
    })
    desk.borrow("Clean Code")
    desk.giveBack("Clean Code")
    println("count = $borrowedCount")
}

Output:

borrowed Clean Code
returned Clean Code
count = 1

An object expression, unlike an object declaration, is not a singleton — a new instance is created every time the expression is evaluated — and, like a Java anonymous class, it can capture and even mutate variables from its enclosing scope (the compiler wraps such variables in a Ref object, as for lambdas). It may implement several supertypes at once, object : A, B { ... }, which a lambda can never do.

When the expression is not given a type, as in a local val, its members stay accessible:

fun main() {
    val point = object {
        val x = 1
        val y = 2
    }
    println(point.x + point.y)    // 3: the anonymous type is visible for a local or private declaration
}

If such an object is returned from a public function or stored in a public property, its declared type is the supertype (Any when there is none) and the extra members are no longer reachable.

Choosing Between the Forms

  • Need a single shared instance? An object declaration. Keep it stateless where possible.

  • Need factories or constants tied to a class? A companion object, with const val for constants.

  • Need a one-off implementation of an interface with several methods? An object expression. For a single-method interface, a lambda (or a fun interface with a SAM-converted lambda) is shorter.

  • Need a named, reusable implementation? A regular class.
