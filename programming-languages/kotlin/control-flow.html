Control Flow

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Control flow in Kotlin is built from expressions: if, when and try all produce values, which is why the language needs no ternary operator and why so many functions are one line. Loops remain statements. This page covers if and when in all their forms (subject, no subject, ranges, type checks, guards, exhaustiveness), for and while and how for is translated to iterators, jumps with break, continue and labels, and return from nested lambdas. The examples use the lending library of this section (Book, Member, Loan).

if as an Expression

if/else can produce a value directly, replacing Java’s ternary operator (which Kotlin does not have) and, for anything more than a one-liner, replacing an assignment split across several statements:

fun main() {
    val a = 5
    val b = 2

    val max = if (a > b) a else b               // an expression: no ternary operator needed

    val description = if (max > 10) {
        "big"
    } else {
        "small"                                 // the last expression in each branch is the branch's value
    }

    val overdueDays = 3
    val fee = if (overdueDays == 0) 0.0
    else if (overdueDays <= 7) overdueDays * 0.25
    else 2.0 + (overdueDays - 7) * 0.5          // else-if chains are nested ifs, each one an expression

    println("$max $description $fee")
}

Output:

5 small 0.75

When used as an expression, if must have an else branch (the compiler needs a value on every path); used as a plain statement whose value is discarded, else remains optional exactly as in Java. The type of an if expression is the common supertype of its branches, and a branch that throws or returns has type Nothing, so it does not affect the result: val title = if (ok) "x" else error("no title") is a String.

when as an Expression

when replaces Java’s switch and is far more general: its branches can match exact values, ranges, type checks, or arbitrary boolean conditions, and — like if — it can produce a value. Branches are tried top to bottom and the first match wins:

data class Book(val title: String, val pages: Int)

fun describe(value: Any): String = when (value) {
    1, 2, 3 -> "small number"                              // comma-separated values share a branch
    is Int -> "some other number"                          // type check; value is smart-cast to Int here
    is String -> "a string of length ${value.length}"      // type check plus smart cast, see below
    is Book -> "book '${value.title}' with ${value.pages} pages"
    else -> "something else"
}

fun pagesCategory(pages: Int): String = when (pages) {
    in Int.MIN_VALUE..0 -> "invalid"                       // range membership
    in 1..99 -> "short"
    in 100..399 -> "medium"
    else -> "long"
}

fun main() {
    println(describe(2))
    println(describe(7))
    println(describe("Dune"))
    println(describe(Book("Emma", 320)))
    println(describe(2.5))
    println(pagesCategory(0))
    println(pagesCategory(50))
    println(pagesCategory(250))
    println(pagesCategory(464))

    val x = 7
    val category = when {                       // no subject: each branch is its own boolean condition
        x < 0 -> "negative"
        x == 0 -> "zero"
        x % 2 == 0 -> "positive even"
        else -> "positive odd"
    }
    println(category)
}

Output:

small number
some other number
a string of length 4
book 'Emma' with 320 pages
something else
invalid
short
medium
long
positive odd

Range branches need a subject whose type matches the range (Int above), and !in 1..99 negates a membership test.

A when with a subject can also bind it to a name for use in the branches, when (val book = catalog.find(isbn)) { ... }, which limits the variable’s scope to the when. Inside an is branch, value is automatically smart-cast to that type for the rest of the branch — no explicit cast needed (see Null Safety for the general smart-cast rule). A when used as an expression must be exhaustive, so it needs an else unless the subject is an enum, a sealed type or a Boolean.

When when has a subject over a sealed type or an enum, the compiler can enforce exhaustiveness at compile time with no else needed — covered in depth in Sealed Classes and Enums.

Guard conditions

Since Kotlin 2.2 a branch of a when with a subject can add a guard with if, which is checked after the pattern matches and lets one is branch distinguish several cases without a nested if:

fun classify(item: Any): String = when (item) {
    is Book if item.pages > 400 -> "long book"
    is Book -> "book"
    is String if item.isBlank() -> "empty text"
    is String -> "text"
    else -> "unknown"
}

fun main() {
    println(classify(Book("Clean Code", 464)))
    println(classify(Book("Emma", 320)))
    println(classify("  "))
}

Output:

long book
book
empty text

Two further conveniences: when without a subject is the idiomatic replacement for a long if-else if chain, and a branch body can be a block whose last expression is the value. The evaluation order of a when is:

flowchart TD S["when (subject)"] --> B1{"branch 1 matches?"} B1 -->|"yes"| R1["evaluate branch 1, result of the when"] B1 -->|"no"| B2{"branch 2 matches?"} B2 -->|"yes"| R2["evaluate branch 2"] B2 -->|"no"| BN{"..."} BN -->|"no more branches"| E{"else present or exhaustive?"} E -->|"yes"| RE["evaluate else"] E -->|"no"| X["compile error as an expression"]

for and while

for iterates any Iterable (a collection, a range or progression, an array, a String) — Kotlin has no C-style three-clause for. while and do-while test before and after each iteration exactly as in Java:

fun main() {
    for (i in 1..5) print(i)                 // over a range, see Operators and Ranges
    println()
    for (c in "abc") print(c)                // Strings are Iterable<Char>
    println()
    for ((index, value) in listOf("Dune", "Emma").withIndex()) {
        println("$index: $value")            // destructuring the IndexedValue, see Destructuring
    }
    val titles = listOf("Dune", "Emma", "Walden")
    for (i in titles.indices) print("${titles[i]} ")        // indices is the range 0 until size
    println()
    for (i in 10 downTo 1 step 3) print("$i ")              // 10 7 4 1
    println()

    var n = 5
    while (n > 0) {
        print(n--)                            // 54321
    }
    println()

    var attempts = 0
    do {
        attempts++                            // the body runs once before the first test; locals of the body
    } while (attempts < 3)                    // are visible in the condition
    println(attempts)
}

Output:

12345
abc
0: Dune
1: Emma
Dune Emma Walden
10 7 4 1
54321
3

A for over an Iterable is translated by the compiler to a call of iterator() followed by a while loop over hasNext() and next(), so any type with iterator(), hasNext() and next() operator members (member or extension) can be iterated. Ranges of primitives over literals compile to a counted loop with no iterator at all (see Operators and Ranges). The loop variable is a val, so it cannot be reassigned in the body, and a for loop is a statement: there is no value, and no list comprehension. Use map, filter and buildList where the loop’s purpose is to build a collection.

break, continue, and Labels

break and continue behave as in Java for the innermost loop; a label@ prefix lets either target an outer loop explicitly:

fun main() {
    outer@ for (row in 0..2) {
        for (col in 0..2) {
            if (row + col == 3) break@outer       // leaves BOTH loops
            if (col == row) continue@outer        // next row
            println("$row,$col")
        }
    }

    listOf(1, 2, 3, 4).forEach lit@{
        if (it == 3) return@lit                   // "continue" for this one lambda invocation only
        println(it)
    }
}

Output:

1,0
2,0
1
2
4

Since Kotlin 2.2, a break or continue inside an inline lambda such as the body of forEach can target an enclosing loop (non-local break and continue), while older code uses a labeled return@label from the lambda or a plain for loop. A bare break or continue that would cross a non-inline lambda boundary is still an error.

return@label inside a lambda is Kotlin’s way of returning from that lambda rather than the enclosing function — necessary because a bare return inside an inline lambda (like the one passed to forEach) returns from the enclosing function itself, which is almost never what is wanted when the intent was to skip an element:

fun firstLong(books: List<Book>): String? {
    books.forEach { book ->
        if (book.pages > 400) return book.title    // non-local return: leaves firstLong itself
    }
    return null
}

fun main() {
    println(firstLong(listOf(Book("Emma", 320), Book("Clean Code", 464))))   // Clean Code
}

See Lambdas and Higher-Order Functions for the full non-local-return rule.

Choosing the Right Construct

  • A value that depends on a condition: if expression. Several alternatives on one subject: when.

  • A fixed number of iterations over a range: for (i in a until b); over elements: for (x in xs); to build a result: a collection operation.

  • An early exit from a function: a return, or a guard clause at the top (if (x == null) return), which keeps the main path unindented.

  • repeat(n) { } for "do this n times" when the index is not needed.
