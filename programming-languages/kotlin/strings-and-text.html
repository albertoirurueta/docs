Strings and Text

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

String in Kotlin is java.lang.String — there is no separate string type — so every method already known from Java is available. Kotlin adds string templates, multi-line raw strings and a large set of extension functions on top. This page covers templates and the rules for escaping, raw strings and margin handling, the most useful String operations, Char versus String, why StringBuilder and buildString matter, Unicode and code points, regular expressions with Regex, number formatting, and the JVM representation. The examples use the lending library running through this section (Book, Member, Loan).

String Templates

A $name or ${expression} inside a string literal is replaced with the value’s string representation at run time — Kotlin’s built-in equivalent of Java’s String.format or text-block interpolation, with no separate formatting call needed for the common case:

data class Book(val title: String, val author: String, val year: Int)

fun main() {
    val name = "Ada"
    val age = 30
    val book = Book("Clean Code", "Martin", 2008)

    println("Hello, $name! You are $age years old.")        // simple name reference
    println("Next year you'll be ${age + 1}.")              // arbitrary expression needs braces
    println("Your name has ${name.length} letters.")        // property or method calls need braces too
    println("Book: $book")                                  // calls toString()
    println("Title: ${book.title}, but $book.title is wrong")  // $book.title is "$book" then ".title"

    // a literal dollar sign, when not followed by an identifier, needs no escaping;
    // to put a dollar before an identifier, use ${'$'}
    println("Price: ${'$'}9.99, ${'$'}name")
    println("Cost: $9.99")                                  // fine: 9 is not an identifier start
}

Output:

Hello, Ada! You are 30 years old.
Next year you'll be 31.
Your name has 3 letters.
Book: Book(title=Clean Code, author=Martin, year=2008)
Title: Clean Code, but Book(title=Clean Code, author=Martin, year=2008).title is wrong
Price: $9.99, $name
Cost: $9.99

A template can contain any expression, including another string literal with its own templates, and it can span if/when expressions: "${if (age >= 18) "adult" else "minor"}". Templates work in raw strings too, with the caveat that backslash escapes do not (see the next section).

Templates on the JVM

The compiler turns a template into a StringBuilder chain (append calls) or, when the target is Java 9 or later and the JVM target allows it, into an invokedynamic call to StringConcatFactory. Either way it is at least as efficient as manual concatenation and needs no String.valueOf. A null interpolates as the text null, which is a frequent source of surprising output.

Multi-dollar interpolation

Since Kotlin 2.2 a literal can be prefixed with several dollar signs so that a single $ is plain text. This is useful for JSON templates and other formats where $ is common: with a $$ prefix, only $$name and $${expression} interpolate.

fun main() {
    val field = "title"
    val schema = $$"""{"$schema": "http://json-schema.org/schema", "name": "$$field"}"""
    println(schema)
}

Output:

{"$schema": "http://json-schema.org/schema", "name": "title"}

Raw (Triple-Quoted) Strings

A triple-quoted string spans multiple lines with no escape processing at all — ideal for regular expressions, file paths and embedded snippets that would otherwise need heavy backslash-escaping:

fun main() {
    val regex = """\d{3}-\d{4}"""                // no need to escape the backslashes
    val path = """C:\Users\ada\file.txt"""       // no backslash escaping needed

    val query = """
        |SELECT id, title
        |FROM books
        |WHERE year > 2000
    """.trimMargin()                             // strips everything up to and including the leading |

    val text = """
        Dear member,
          your loan is due.
    """.trimIndent()                             // strips the common leading whitespace

    println(regex)
    println(path)
    println(query)
    println(text)
}

Output:

\d{3}-\d{4}
C:\Users\ada\file.txt
SELECT id, title
FROM books
WHERE year > 2000
Dear member,
  your loan is due.

trimMargin() (default margin prefix |, or a custom one) and trimIndent() (strips the common leading whitespace of every line, and a first and last blank line) are the standard ways to keep a raw string’s source indentation without that indentation leaking into the resulting value. Because there are no escapes, a raw string cannot contain """ itself; build such a value with a template (${'"'}) or an ordinary string.

Common String Operations

Because String is java.lang.String, methods like length, substring(), indexOf(), replace(), split(), trim() and uppercase() all work as expected; Kotlin adds a large set of extension functions on top (see Extension Functions and Scope Functions) for common tasks that need a manual loop in Java:

fun main() {
    val csv = "id,title,author"
    val fields = csv.split(",")                    // List<String>: [id, title, author]
    println(fields)

    println("7".padStart(3, '0'))                  // 007
    println("ab".repeat(3))                        // ababab
    println("  hi  ".trim())                       // hi
    println("Clean Code".substringBefore(" "))     // Clean
    println("Clean Code".substringAfterLast(" "))  // Code
    println("clean code".replaceFirstChar { it.uppercase() })   // Clean code
    println("a-b-c".replace("-", "+"))             // a+b+c
    println("Kotlin".reversed())                   // niltoK
    println("Kotlin".take(3) + "|" + "Kotlin".takeLast(2) + "|" + "Kotlin".drop(4))   // Kot|in|in
    println("hello world".split(" ").joinToString("_") { it.uppercase() })   // HELLO_WORLD
    println("Kotlin".contains("tli"))              // true
    println("Kotlin".startsWith("Ko"))             // true
    println("Kotlin".equals("KOTLIN", ignoreCase = true))   // true
    println("abc" < "abd")                         // true: lexicographic compareTo
    println("".isEmpty() && "  ".isBlank())        // true

    // building a string efficiently in a loop uses buildString { } (backed by a StringBuilder)
    val joined = buildString {
        for (i in 1..3) append(i).append(", ")
        setLength(length - 2)                      // drop the trailing separator
    }
    println(joined)                                // 1, 2, 3
}

length is a property (str.length), not a method call, unlike Java’s str.length() — one of the small, deliberate differences meant to make code read more like plain English. Indexing with str[i] returns a Char; str[i] out of range throws StringIndexOutOfBoundsException, while getOrNull(i) returns null.

Char versus String

A Char is written with single quotes ('a'+) and is a 16-bit UTF-16 code unit, not a string of length one. There is no implicit conversion between the two, and 'a' + 1 is the Char 'b'+ while 'a' + "b" is the String "ab". The usual Char helpers are isDigit(), isLetter(), uppercaseChar(), digitToInt() and code. Use toString() or a template to convert a Char to a String.

fun main() {
    val c = 'k'
    println(c + 1)               // l
    println(c.uppercaseChar())   // K
    println('7'.digitToInt())    // 7
    println(c.code)              // 107
    println("title".map { it.uppercaseChar() }.joinToString(""))   // TITLE
    println("Title".count { it.isUpperCase() })                   // 1
}

Unicode, code units and code points

Because a String is a sequence of UTF-16 code units, characters outside the Basic Multilingual Plane (emoji, many CJK extensions) occupy two Chars, a surrogate pair. length counts code units, not user-perceived characters. Use codePointCount (through java.lang.String) or iterate by code points when you need the real character count; grapheme clusters need java.text.BreakIterator.

fun main() {
    val s = "a\uD83D\uDE00b"                  // a, grinning face emoji, b
    println(s.length)                        // 4 UTF-16 code units
    println(s.codePointCount(0, s.length))   // 3 code points
}

Regular expressions

Regex wraps java.util.regex.Pattern. Raw strings keep the patterns readable, matches tests the whole string, and find and findAll return MatchResult objects whose destructured property pairs well with destructuring:

fun main() {
    val isbn = Regex("""\d{3}-\d{10}""")
    println(isbn.matches("978-1617299599"))      // true
    println("978-1617299599" matches isbn)       // true, infix form

    val line = Regex("""(\w+) borrowed (\w+)""")
    val (who, what) = line.find("Ada borrowed Dune")!!.destructured
    println("$who -> $what")                     // Ada -> Dune

    println(Regex("""\d+""").findAll("a1b22c333").map { it.value }.toList())   // [1, 22, 333]
    println("a1b22".replace(Regex("""\d+""")) { "<${it.value}>" })            // a<1>b(22)
}

Output:

true
true
Ada -> Dune
[1, 22, 333]
a<1>b(22)

Formatting numbers and text

String.format and the extension format use Java’s Formatter syntax. Pass a Locale when the output must not depend on the machine, because the default locale changes decimal separators:

import java.util.Locale

fun main() {
    println("%.2f".format(Locale.ROOT, 3.14159))        // 3.14
    println("%05d".format(42))                          // 00042
    println("%-8s|".format("Dune"))                     // Dune    |
    println(String.format(Locale.ROOT, "%,d", 1234567)) // 1,234,567
}

Comparison to Java’s String

  • == compares structural equality for String in Kotlin (it calls equals()), unlike Java where == compares references — see Equality and Operator Overloading for the full rule and its === referential-equality counterpart.

  • Kotlin’s String is immutable, exactly like Java’s — StringBuilder (also java.lang.StringBuilder directly, or wrapped by buildString { }) remains the tool for repeated concatenation in a loop. Concatenating in a loop with + creates a new string on every iteration and is quadratic in the total length.

  • Text blocks ("""...""" in Java 15+) and Kotlin’s triple-quoted strings look similar but differ: Kotlin’s strips no indentation automatically (you call trimIndent() or trimMargin() explicitly), whereas Java’s text blocks strip common leading whitespace by the language rules themselves.

  • String? is a distinct type: calling a member on a nullable string needs ?., and the stdlib offers isNullOrEmpty(), isNullOrBlank() and orEmpty() for the common checks (see Null Safety).

  • Kotlin’s equals(other, ignoreCase = true), lowercase() and uppercase() replace the deprecated toLowerCase() and toUpperCase(); the new functions use the root locale, so "I".lowercase() is the same on every machine, unlike Java’s toLowerCase() with the default locale.
