Reading and Writing Text Data

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Text is the format in which most data reaches R and in which most results leave it, and R has a small family of functions for each direction: read.table() and its relatives turn a delimited file into a data frame, scan() and readLines() read values or lines, write.table() and write.csv() write a data frame, and cat(), writeLines(), sprintf() and sink() write text for people. This page covers every argument of the readers and writers that changes what you get, the conventions of CSV files and how they differ between countries, the errors and warnings that a badly described file produces (with the exact text R prints), why a round trip through a text file loses some types and how to keep them, the datasets that ship with R and the way data() loads them, and which package to reach for when the data is in an Excel, SPSS, SAS, Stata, Octave, Parquet or JSON file instead of a text file. Every example uses base R and the foreign package, which is a recommended package shipped with R (checked at version 0.8-91, used for one short example). The add-on packages readr (checked at version 2.2.0), vroom (1.7.1), readxl (1.6.0), haven (2.5.5) and data.table (1.18.6.1) are installed in the checking environment and were called on the shelf files to check the statements made about them, but they are described in prose, and none of their code appears in the examples; arrow, writexl, openxlsx and R.matlab are not installed there and are named only as pointers.

Every example below is a complete script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts also pass the default lintr linters. Errors and warnings that a script shows on purpose are caught with tryCatch() or withCallingHandlers() and printed as their conditionMessage(), so the text is exactly what R says. The examples use the library-shelf scenario of the section: the files books.csv and loans.csv, the data frames books and loans, the constants shelf_today and loan_days and the book class come from the scenario.R file described on the section index, and the scripts start in the directory that holds those files, so read.csv("books.csv") and source("scenario.R") work as written. books has 16 rows and the columns title, author, isbn, year, genre and pages; loans has 60 rows and the columns loan_id, isbn, member, loan_date and return_date. Both are deliberately untidy, because the interesting part of reading a file is what the file does not say. Files that an example writes go to tempfile() or are removed before the script ends, and file names that appear in messages are relative names such as draft.csv. Where an example needs a text that is too awkward to read from the shelf files (a Latin-1 file, a file without a final newline, a Windows export with semicolons), the script builds it in a few lines.

Text files in R: the big picture

An Introduction to R puts the design assumption plainly: R’s input facilities are simple and fairly strict, and the designers presume that you will adjust an awkward input file with other tools (an editor, a scripting language) so that it fits what R expects (An Introduction to R: Reading data from files). R Data Import/Export, the manual for this whole topic, adds that the primary function for importing from a text file is scan() and that it underlies most of the more convenient functions, which then build on it (R Data Import/Export: Imports). Everything on this page follows from those two statements. A text file carries no description of itself, so every fact about it that R cannot guess has to be said in an argument, and the readers differ in how much they guess.

Three things in the text are worth noticing before any parsing happens. Every text field is in double quotes and every number is bare, which is what write.csv() produces. The ISBN in loans.csv is quoted although it is made of digits, which is a hint that it is an identifier, not a quantity. And the last two columns of loans.csv hold dates in the ISO 8601 form YYYY-MM-DD as plain text: CSV has no date type, so a date is always text until some function converts it. The scenario also leaves empty fields in both files (an unreturned loan has an empty return_date, and some books have no year or page count) and a handful of spelling and spacing problems that belong to the cleaning pages. The reading functions treat those empty fields differently depending on the column type, and that difference is the first thing to understand.

read.csv() and read.table()

read.table() is the main function for reading tabular data into R. The other four readers are the same function with different defaults: the help page says that read.csv() and read.csv2() are identical to read.table() except for the defaults, and likewise read.delim() and read.delim2(). Reading the signatures from R itself shows what changes.

readers <- c("read.table", "read.csv", "read.csv2", "read.delim", "read.delim2")
settings <- c("header", "sep", "quote", "dec", "fill", "comment.char")

# The defaults of each reader, as the function signatures state them
defaults <- vapply(readers, \(name) {
  formals_of <- formals(get(name))
  vapply(settings, \(arg) {
    paste(deparse(formals_of[[arg]]), collapse = "")
  }, character(1))
}, character(length(settings)))

cat(sprintf("%-13s", ""), sprintf("%-19s", readers), "\n", sep = "")

The table is worth reading column by column. read.table() expects white-space-separated fields (sep = ""), accepts both kinds of quote, treats # as a comment character, and does not insist on a header; its fill default is the opposite of blank.lines.skip, so with the default skipping of blank lines it does not pad short rows. The four convenience functions assume that the first line holds the names (header = TRUE), pad short rows (fill = TRUE), and switch comments off (comment.char = ""). read.csv() and read.delim() use the point as the decimal mark, and read.csv2() and read.delim2() use the comma, together with the semicolon as the field separator for the CSV variant. The result follows the rules that the help page gives. Unless colClasses says otherwise, every column is read as text and then converted by type.convert() to logical, integer, numeric or complex, whichever is the first that accepts every non-missing value; a column that none accepts stays character, because the default of stringsAsFactors has been FALSE since R 4.0.0 (the section on column types below has the details and the NEWS line). year and pages are integer. The two blank page counts and the blank year are NA, because the help page says that blank fields in logical, integer, numeric and complex columns are missing values. The blank isbn of "Rivers of Glass" is not NA: in a text column a blank field is the empty string, and only the text NA (the default of na.strings) is missing. The same distinction shows up in every later example.

The arguments that describe the file’s shape

The help page lists a few arguments that change what a line means. A script with a small export that has a preamble is the clearest way to see them together.

report <- c(
  "Library export, produced by the circulation desk",
  "Counts are as of the end of the month",
  "loan_id,loan date,pages (est.),member",
  "L001,2025-01-14,214,Hugo Silva",
  "L002,2025-01-16,387,Ben Okafor",
  "L003,2025-01-21,432,Dev Patel"
)
path <- tempfile(fileext = ".csv")
writeLines(report, path)

# skip= drops the preamble; check.names = TRUE (the default) repairs the names
read.csv(path, skip = 2L)
#>   loan_id  loan.date pages..est..     member
#> 1    L001 2025-01-14          214 Hugo Silva
#> 2    L002 2025-01-16          387 Ben Okafor
#> 3    L003 2025-01-21          432  Dev Patel
names(read.csv(path, skip = 2L, check.names = FALSE))
#> [1] "loan_id"      "loan date"    "pages (est.)" "member"

# nrows= reads only the first records
read.csv(path, skip = 2L, nrows = 2L)
#>   loan_id  loan.date pages..est..     member
#> 1    L001 2025-01-14          214 Hugo Silva
#> 2    L002 2025-01-16          387 Ben Okafor

# header = FALSE keeps the first line as data and numbers the columns V1, V2
read.csv(path, skip = 3L, header = FALSE)
#>     V1         V2  V3         V4
#> 1 L001 2025-01-14 214 Hugo Silva
#> 2 L002 2025-01-16 387 Ben Okafor
#> 3 L003 2025-01-21 432  Dev Patel

#> 2 L002 2025-01-16   387 Ben Okafor
#> 3 L003 2025-01-21   432  Dev Patel

read.csv(path, skip = 2L, row.names = 1L)
#>       loan.date pages..est..     member
#> L001 2025-01-14          214 Hugo Silva
#> L002 2025-01-16          387 Ben Okafor
#> L003 2025-01-21          432  Dev Patel

Six rules are visible in the output. skip counts lines of the file before the header is looked for, which is how a preamble is dropped. With check.names = TRUE, the default, the names loan date and pages (est.) become the syntactically valid loan.date and pages..est..; this is make.names() at work, and R FAQ 7.14 (What are valid names?) is the reference for why R does it (R FAQ 7.14: What are valid names?). check.names = FALSE keeps the original names, which then need backticks in a formula or $ access. nrows reads only the first records; the help page recommends a mild over-estimate of the true number when it is used for speed. header = FALSE makes the header line ordinary data and numbers the columns V1, V2 and so on. col.names overrides the names that the header supplies. row.names = 1L makes the first column the row names, which is how a file written by write.csv() with its default row names is read back.

The manual recommends stating header explicitly instead of relying on the guess. The help page says that when the argument is missing, read.table() sets it to TRUE if and only if the first row has one field fewer than the number of columns, which is the shape of a table printed by R, with row names but no name for them. The convenience functions do not guess; they fix header = TRUE.

A last argument in this family is text, which replaces file with a character string. It is the way to put a small table in a script, and many examples of this page use it for the awkward cases that the shelf files do not contain.

# text= reads a character string as if it were a file
loans_small <- read.csv(text = "
loan_id,member,days
L001,Hugo Silva,21
L002,Ben Okafor,10
")
loans_small
#>   loan_id     member days
#> 1    L001 Hugo Silva   21
#> 2    L002 Ben Okafor   10

# Leading and trailing blank lines are trimmed; the lines may be a vector
read.table(
  text = c("title pages", "Dune 412", "Emma 474"),
  header = TRUE
)
#>   title pages
#> 1  Dune   412
#> 2  Emma   474

# A raw string keeps backslashes and quotes without escaping (R 4.0.0)
read.csv(text = r"(note,path
"say ""hi""",C:\data\books.csv)")
#>       note                path
#> 1 say "hi" C:\\data\\books.csv

# The same idea for numbers and text vectors
scan(text = "3 1 4 1 5", quiet = TRUE)
#> [1] 3 1 4 1 5
readLines(textConnection("alpha\nbeta"))
#> [1] "alpha" "beta"

Source: R documentation: read.table

The first call shows that blank lines at the start and end of the string are trimmed. The vector form joins its elements as lines. The raw string (an R 4.0.0 syntax, written with r"( and )") lets the CSV quotes and a Windows path appear without a single escape; the backslashes in the printed data frame are doubled only because the console shows string values in escaped form.

Separators and quotes

CSV is a convention more than a standard (RFC 4180 describes the common form, with a comma separator, double quotes and doubled quotes inside quoted fields, and CRLF line endings: RFC 4180), and R reads the common form. The relevant arguments are sep, quote and allowEscapes. When sep is given, a quoted field may contain the separator and a doubled quote stands for one quote; when sep is the default white space, a backslash in a quoted string escapes the next character instead. The manual says the same (R Data Import/Export: Variations on read.table).

# Quoted fields can hold the separator, a doubled quote and a line break
csv <- c(
  "title,note",
  "\"Salt, Fire and Ice\",\"Said to be \"\"the\"\" best\"",
  "\"Two\nLines\",plain"
)
path <- tempfile(fileext = ".csv")
writeLines(csv, path)
result <- read.csv(path)
result
#>                title                  note
#> 1 Salt, Fire and Ice Said to be "the" best
#> 2         Two\nLines                 plain
nchar(result$title)
#> [1] 18  9
result$note[[1L]]
#> [1] "Said to be \"the\" best"

# read.csv() quotes only with the double quote, so an apostrophe is safe
read.csv(text = "name,place\nO'Brien,Cork")
#>      name place
#> 1 O'Brien  Cork

# read.table() also accepts the single quote, but only at the start of a field
read.table(text = "name place\nO'Brien Cork", header = TRUE)
#>      name place
#> 1 O'Brien  Cork

# The default separator of read.table() is any run of white space
read.table(text = "title pages\nDune 412\nEmma 474", header = TRUE)
#>   title pages
#> 1  Dune   412
#> 2  Emma   474

# sep = "\t" separates only on tabs, so blanks inside a field survive
tsv <- "title\tpages\nThe Long Table\t256\nPaper Moons\t88"
read.delim(text = tsv)
#>            title pages
#> 1 The Long Table   256
#> 2    Paper Moons    88

# A backslash escapes a quote only when no separator is given
read.table(text = "x\n\"say \\\"hi\\\"\"", header = TRUE)
#>          x
#> 1 say "hi"
unlink(path)

Source: R Data Import/Export: Variations on read.table

A quoted field can therefore hold a comma, a doubled quote and a line break; the second title in the output contains a real newline, and nchar() shows 9 characters for it. read.csv() recognizes only the double quote, so an apostrophe in O'Brien is plain text; read.table() recognizes both quotes, but only at the start of a field, so the same name passes there too. A name that starts with the apostrophe would open a string that never closes, and the section on common errors shows what R says then. quote = "" turns quoting off.

The help page adds that quoting is considered only for columns read as character. It also says that quoted fields with embedded newlines are supported, except after a comment character. Embedded NUL bytes are not supported; skipNul = TRUE may help.

The delimiter choice has its own pitfalls. A comma is a poor separator for data that contains commas, and in countries that write the decimal comma it is not the separator at all. The manual says that a semicolon or a tab is probably the safest option when writing, and a tab-separated file read with read.delim() keeps the blanks inside fields, as the output shows for "The Long Table". If a tab-delimited file has empty fields, say sep = "\t" explicitly: with the default white space a run of tabs counts as one separator and the empty field disappears.

Missing values

na.strings is a character vector of the spellings of a missing value. Two rules matter. First, blank fields in logical, integer, numeric and complex columns are always missing, whatever na.strings says; in a text column a blank field is "" unless "" is listed. Second, the comparison happens after white space is stripped (only if stripping is enabled), so a field written as a blank followed by NA is not missing unless strip.white = TRUE removes the blank first.

Column types: the guess, and how to override it

The help page describes the algorithm: read every column as text, then call type.convert() on it. The manual states the order as logical, then integer, then numeric, then complex, moving on whenever an entry that is not missing cannot be converted; if all of those fail the column is text, or a factor when factors were requested (R Data Import/Export: Variations on read.table). A column made only of TRUE, FALSE, T, F and missing values is logical, a column of whole numbers within the range of an integer is integer, and everything else numeric is double. colClasses

colClasses is the argument to know. It is a character vector of classes, one per column; if it is unnamed it is recycled to the number of columns, and if it is named, the names pick columns and the others are guessed. The allowed values are NA (guess; the default), "NULL" (skip the column), one of the atomic classes ("logical", "integer", "numeric", "complex", "character", "raw"), "factor", "Date", "POSIXct", or any class for which a methods::as() conversion from character exists. The help page notes that the argument is per column, not per variable, so it also counts a row-names column if the file has one. The R FAQ gives the performance reason as well: stating the classes avoids the guessing and is the first thing to do with a big file (R FAQ 7.28: Why is read.table() so inefficient?).

Numbers and dates that turn into text

The most common complaint about read.csv() is a numeric column that arrives as text, nearly always because one entry is not a number. Older tutorials and the R FAQ describe the same symptom as a factor, because before R 4.0.0 the default turned all text into factors (see the version notes below).

csv <- "title,pages\nA Map of Salt,352\nLoud Roofs,n/a\nTen Winters,256"

pages <- read.csv(text = csv)$pages

tryCatch(as.numeric(pages), warning = conditionMessage)
#> [1] "NAs introduced by coercion"

pages <- read.csv(text = csv, na.strings = c("NA", "n/a"))$pages

#> [1] "integer"

#> [1] 304

# as.Date() tries "%Y-%m-%d", then "%Y/%m/%d", and "14/01/2025" fits the

The remedy is in the reading, with na.strings. The factor case is the one the R FAQ warns about: as.numeric() of a factor returns the integer codes of the levels (here 2, 3, 1), never the numbers that the labels show, and the FAQ gives the two safe conversions, as.numeric(as.character(f)) and the faster as.numeric(levels(f))[f]. The last part is a trap that does not warn. colClasses = "Date" is not a date-format argument. as.Date() tries %Y-%m-%d and then %Y/%m/%d, and the text 14/01/2025 fits the second pattern as year 14, month 01, day 20, so a European date comes back as a valid Date in the year 14 and no message at all. Read such a column as text and give the format (R documentation: as.Date); the Dates and Times page has the format codes.

Comments, blank lines and short rows

The three arguments comment.char, blank.lines.skip and fill decide what a line that is not a plain record means. read.table() treats # as the start of a comment, and so the rest of the line, even inside a data field, is discarded; the help page adds that quotes are not processed in comments and that comment lines before the header must have the comment character in the first non-blank column. The four convenience functions turn comments off with comment.char = "", and the manual advises setting it to the empty string whenever the data cannot contain comments, because it is both safer and faster.

lines <- c(
  "# exported from the circulation desk",
  "title,rating",
  "Loud Roofs #2,4",
  "Ten Winters,5  # re-read"
)

# read.csv() has no comment character, so "#" is ordinary text: the comment
# line becomes the header, and since the data lines have one field more, the
# first field of each line turns into a row name

#> Loud Roofs #2                                     4

#> 1 Loud Roofs #2            4
#> 2   Ten Winters 5  # re-read

#>         title rating
#> 1 Loud Roofs      NA
#> 2 Ten Winters      5

tryCatch(

Spreadsheet programs write the CSV that their locale prefers. Encodings and the byte order mark

A CSV file has no field for its encoding. The reading functions have two arguments that look alike and do opposite jobs, and the help page spells out the difference: fileEncoding re-encodes the input to the encoding of the session through a connection, and encoding only marks the strings as Latin-1 or UTF-8 without converting them. For a Latin-1 file in a UTF-8 session, which is the commonest case, the manual’s remedy is fileEncoding = "latin1" (R Data Import/Export: Variations on read.table). The full treatment, with iconv(), Encoding() and the bytes mark, is on Encodings, Locales and Internationalization; this section keeps to what a reader needs.

# A Latin-1 file: one byte (e9) for each accented letter
text <- "name,city\nJosé,Café\n"
path <- "latin1.csv"
writeBin(iconv(text, "UTF-8", "latin1", toRaw = TRUE)[[1L]], path)
file.size(path)
#> [1] 20
nchar(text, type = "bytes")
#> [1] 22

# Without fileEncoding the bytes are taken as UTF-8, which they are not
bad <- read.csv(path)
validUTF8(bad$name)
#> [1] FALSE
tryCatch(nchar(bad$name), error = conditionMessage)
#> [1] "invalid multibyte string, element 1"

# fileEncoding converts to the session encoding while reading
good <- read.csv(path, fileEncoding = "latin1")
good
#>   name city
#> 1 José Café
validUTF8(good$name)
#> [1] TRUE
nchar(good$name)
#> [1] 4

# encoding only declares what the bytes are; the strings stay Latin-1 inside
declared <- read.csv(path, encoding = "latin1")
Encoding(declared$name)
#> [1] "latin1"
declared$name == good$name
#> [1] TRUE

# A file saved by Excel as "CSV UTF-8" starts with the three bytes of a BOM
bom <- c(as.raw(c(0xef, 0xbb, 0xbf)), charToRaw("title,year\nA,2000\n"))
writeBin(bom, path)
names(read.csv(path))
#> [1] "title" "year"
# The same bytes read as Latin-1 show the mark as letters in the first name
names(read.csv(path, fileEncoding = "latin1"))
#> [1] "ï..title" "year"
names(read.csv(path, fileEncoding = "UTF-8-BOM"))
#> [1] "title" "year"
unlink(path)

Source: R Data Import/Export: Encodings

The Latin-1 file is two bytes shorter than its UTF-8 text because each accented letter is one byte instead of two. Read with the session’s encoding, the strings are not valid UTF-8, nothing fails at the time of reading, and the failure comes later, in the first function that needs characters: nchar() stops with invalid multibyte string, element 1. With fileEncoding = "latin1" the text is converted while it is read and is valid. With encoding = "latin1" the strings are marked as Latin-1, which R converts when needed, so they compare equal to the converted ones, but the bytes are not changed in memory.

A byte order mark (BOM) is the character U+FEFF at the start of a file, and Microsoft programs write it at the start of "CSV UTF-8" files. Since R 3.0.0, readLines() and scan() (and hence read.table()) discard a UTF-8 BOM in a UTF-8 locale, so the first name is title, and the connection encoding name "UTF-8-BOM" discards it in any locale (R NEWS: Changes in R 3.0.0). The third result shows what the mark looks like when it is not recognized, which is the origin of the many questions about a first column name that starts with ï..: the three bytes read as Latin-1 become the letters ï, » and ¿, and make.names() turns the last two into dots. Names such as utf8 are not valid encoding names (UTF-8 is), and "UTF-16LE" is the one for the "Unicode" text files of Windows.

Four of these deserve a second look.

The line number. In line N did not have M elements, N counts the lines after the header, so the 41st line of the file is line 40, and M is the width found in the first five data lines. A bad line beyond the first five is named correctly, as the script in the next section shows. A bad line among the first five sets the width itself, and then the first correct line is the one reported, as in the stray-comma file below, which blames its first line. In the first script the short row really is the first data row, so line 1 is right there.

The two incomplete-line messages. They look alike and come from two functions. readLines() accepts the final line and warns incomplete final line found on 'draft.txt'; read.table() looks at the header with an internal helper and its warning says incomplete final line found by readTableHeader on 'draft.txt'. In both cases the data are read in full. The help page of readLines() explains that the behaviour depends on whether the connection is blocking: for a non-blocking text-mode connection the incomplete line is pushed back silently, for all others it is accepted with a warning.

The unclosed quote. It does not stop the read. The warning EOF within quoted string is printed, and all the text from the stray quote to the end of the file becomes the value of one field, so the data frame has fewer rows than the file has lines. The script above shows the symptom: the warning with no error, and eight rows from nine data lines. Nothing in the data frame itself says that anything was wrong; the warning is the only signal, which is why a script should not run with warnings switched off.

Latin-1 bytes. Reading never fails on an encoding problem; use is what fails. This is the same lesson as in the encodings section above, and validUTF8() on the result is the quick check.

The first output is the default, and it is almost never what the next program expects: a header cell with an empty name for the row names, and a column of row numbers "1", "2", "3". A data frame that has the default row names has nothing to write there, so row.names = FALSE is the right choice in nearly every call (and the one used for the shelf files). To read a file that has the row-name column, use read.csv(row.names = 1). file = "", the default, prints to the console. quote = FALSE removes the quotes, and then a title that contains a comma would break the file. The na argument controls how missing values are written: the default is the text NA, which read.csv() reads back as a missing value in every column; na = "" writes an empty field, which the shelf files use, and which read.csv() reads back as NA only in numeric columns; a text column then needs na.strings = "". The help page says that write.csv() writes compliant files on Windows and that other platforms need eol = "\r\n", because on Windows a text-mode connection converts "\n" itself.

The defaults of write.table() are the space separator, quoted text and a header that has no cell for the row names, which R itself reads back with the automatic header detection. col.names = NA is the CSV convention, and as the help page notes it is the form to use when the file will be opened in a spreadsheet, which expects a header cell above the row names. sep = "\t", quote = FALSE, row.names = FALSE writes tab-separated text. append = TRUE adds to an existing file; the header would be written again, so it is switched off on the second call. The last three calls show the difference between the two ways of escaping a double quote inside a field: a backslash by default, a doubled quote with qmethod = "double" and in write.csv(). The manual calls the doubled form the one that spreadsheets use. It has a consequence for reading: a backslash-escaped quote is understood only when no separator is given, and doubling is the rule when one is, so a file written with qmethod = "double" must be read with its separator named, as the example on the help page notes.

A CSV round trip keeps text, numbers and the empty/missing distinction if the arguments are chosen with care, and loses everything that is not text or a number unless it is put back.

readLines() and writeLines()

readLines() reads text lines from a file name or a connection and returns a character vector of one element per line, with no parsing at all; writeLines() is its counterpart. The arguments of readLines() are n (the maximum number of lines, a negative number meaning all), ok (whether a short read is allowed), warn (warn about a missing final newline and about embedded NUL bytes), encoding (a declared encoding, not a conversion) and skipNul. writeLines() has text, con, sep (the terminator written after each line) and useBytes.

path <- tempfile(fileext = ".txt")

# writeLines() writes one string per line and adds the newline
writeLines(c("first line", "second line", "", "fourth line"), path)
readLines(path)
#> [1] "first line"  "second line" ""            "fourth line"

# n= limits how many lines are read; the rest is not touched
readLines(path, n = 2L)
#> [1] "first line"  "second line"

# sep= changes the line terminator that writeLines() adds
writeLines(c("a", "b"), path, sep = ";")
readBin(path, "raw", n = file.size(path))
#> [1] 61 3b 62 3b
readLines(path, warn = FALSE)
#> [1] "a;b;"

# Without a file, writeLines() writes to the console
writeLines(c("alpha", "beta"))
#> alpha
#> beta

# readLines() does not parse: numbers are still text
writeLines(c("3", "4.5", "x"), path)
lines <- readLines(path)
lines
#> [1] "3"   "4.5" "x"
suppressWarnings(as.numeric(lines))
#> [1] 3.0 4.5  NA

# readLines() accepts LF, CRLF and CR as line endings
writeBin(charToRaw("one\r\ntwo\rthree\nfour"), path)
readLines(path, warn = FALSE)
#> [1] "one"   "two"   "three" "four"

# An empty file gives character(0)
writeLines(character(), path)
file.size(path)
#> [1] 0
readLines(path)
#> character(0)
unlink(path)

Source: R documentation: readLines

A few things to see in the output. readLines(path, n = 2L) reads two lines and leaves the rest. A blank line in the file is the empty string in the vector, so the file with four lines gives four elements. sep in writeLines() replaces the terminator: with sep = ";" the file has no newline at all, and readLines() then returns one element "a;b;". The line endings accepted by readLines() are LF, CRLF and a lone CR, whatever the platform, which the example with "one\r\ntwo\rthree\nfour" demonstrates; that is why a Windows file read on Linux has no stray carriage returns. writeLines() writes the default "\n" and, on a text-mode connection on Windows, the platform converts it to CRLF. Reading an empty file gives character(0).

Reading from an open connection

A character string as con opens the file for the duration of the call and closes it. A connection that is opened once reads on from where the previous call stopped, which is how a file is processed in chunks and how a function consumes the header before the data.

path <- tempfile(fileext = ".txt")
writeLines(sprintf("record %02d", 1:7), path)

# A connection opened once reads on from where it stopped
con <- file(path, "r")
readLines(con, n = 3L)
#> [1] "record 01" "record 02" "record 03"
readLines(con, n = 2L)
#> [1] "record 04" "record 05"
readLines(con)
#> [1] "record 06" "record 07"
readLines(con)
#> character(0)
close(con)

# on.exit() closes the connection even when reading fails
first_lines <- function(path, n) {
  con <- file(path, "r")
  on.exit(close(con))
  readLines(con, n = n)
}
first_lines(path, 2L)
#> [1] "record 01" "record 02"

# ok = FALSE turns a short read into an error
con <- file(path, "r")
tryCatch(readLines(con, n = 10L, ok = FALSE), error = conditionMessage)
#> [1] "too few lines read in readLines"
close(con)

# A file name is enough for a one-off read; the file is opened and closed
length(readLines(path))
#> [1] 7

# readLines() on a text connection is the in-memory version
tc <- textConnection("a\nb\nc")
readLines(tc)
#> [1] "a" "b" "c"
close(tc)
unlink(path)

Each call of readLines(con, n) continues from the previous position, and at the end the result is character(0). on.exit(close(con)) closes the connection even if the code after file() fails, which is the pattern for any function that opens a connection itself. ok = FALSE turns a short read into an error whose text is too few lines read in readLines. A textConnection() is the in-memory counterpart that lets code that reads lines be tested without a file. The rest of the connection family is on Connections and the File System.

The second part shows the other behaviour from the help page. A non-blocking connection treats the last line as not complete yet and returns only "123"; when more text arrives (here appended with cat(append = TRUE)) the next call returns the finished line "abc def". scan()

scan() is the primitive under read.table(). It reads a stream of values of the type given by what and returns either a vector or, if what is a list, a list with one vector per field. The manual’s chapter on using scan() directly gives the reason to know it: the arguments that read.table() has are mostly those of scan(), and scan() is the faster and more economical tool for a big numeric matrix, where read.table() pays the cost of one column per field (R Data Import/Export: Using scan directly).

# scan() reads a stream of values of one type; text= stands in for a file
scan(text = "2 3 5 7 11")
#> Read 5 items
#> [1]  2  3  5  7 11

# quiet = TRUE removes the "Read N items" line
scan(text = "2 3 5 7 11", quiet = TRUE)
#> [1]  2  3  5  7 11

# what= gives the type of the values; sep= the separator
scan(text = "ana,ben,carla", what = "", sep = ",", quiet = TRUE)
#> [1] "ana"   "ben"   "carla"
scan(text = "1,2,,4", sep = ",", quiet = TRUE)
#> [1]  1  2 NA  4

# A character value in a numeric stream is an error
tryCatch(scan(text = "1 2 three", quiet = TRUE), error = conditionMessage)
#> [1] "scan() expected 'a real', got 'three'"

# n= and nlines= limit what is read; skip= drops leading lines
text <- c("header line", "1 2 3", "4 5 6", "7 8 9")
scan(text = text, skip = 1L, nlines = 2L, quiet = TRUE)
#> [1] 1 2 3 4 5 6
scan(text = text, skip = 1L, n = 4L, quiet = TRUE)
#> [1] 1 2 3 4

# what= may be a list: one entry per field, so each record is a row
records <- c("L001 Hugo 21", "L002 Ben 10", "L003 Dev 1")
inp <- scan(text = records, what = list(id = "", who = "", days = 0L),
            quiet = TRUE)
str(inp)

#>  $ id  : chr [1:3] "L001" "L002" "L003"

#>     id  who days
#> 1 L001 Hugo   21
#> 2 L002  Ben   10
#> 3 L003  Dev    1

                quiet = TRUE)
str(skipped)
#> List of 3
#>  $ id  : chr [1:3] "L001" "L002" "L003"
#>  $     : NULL
#>  $ days: int [1:3] 21 10 1

The main arguments are visible here. Without quiet = TRUE, scan() prints a line saying how many items it read (Read 5 items), which goes to the message stream, not to the output; quiet = TRUE silences it, and scripts normally want that. what gives the type ("" for text, 0L for integers, 0 for doubles) and sep the separator, with the default being any white space. An empty numeric field between two separators is NA, and a non-number in a numeric stream is the error scan() expected 'a real', got 'three'. skip drops leading lines, nlines limits the lines read, n and nmax limit the number of values or records. A list for what reads one record per line: each field is converted to the type of its element, the list names become the names of the result, and as.data.frame() turns it into a data frame; a NULL element skips a field but keeps its place in the result. fill = TRUE pads short records, flush = TRUE drops the fields after the last one requested (which also allows comments after the last field), and multi.line = FALSE requires each record to sit on one line. Reading a matrix is matrix(scan(file), nrow, byrow = TRUE), as in the manual.

Two defaults differ from read.table(), and they are the usual cause of surprises when code is moved between the two. The default comment.char of scan() is the empty string, whereas read.table() uses #; and a quoted string in scan() with the default separator treats a backslash as an escape.

Fixed-width files

Some old systems, and some government data, write fields in fixed character positions with no separators. read.fwf() reads them from a vector of field widths. The manual describes how it works: the function reads the whole file into memory as lines, splits them by position, writes a temporary tab-separated file and calls read.table() on it. That is adequate for small files; the manual suggests a preprocessing tool in another language for anything more complicated, and mentions read.fortran() for Fortran-style column specifications (R Data Import/Export: Fixed-width-format files).

# A fixed-width export from an old circulation system: no separators at all
loans <- read.csv("loans.csv", colClasses = "character")[1:3, ]
records <- sprintf(
  "%-4s %-10s %-12s %s", loans$loan_id, loans$loan_date, loans$member,
  loans$isbn
)
path <- tempfile(fileext = ".txt")
writeLines(records, path)
writeLines(readLines(path))
#> L001 2025-01-14 Hugo Silva   9780141439518
#> L002 2025-01-16 Ben Okafor   9780306406157
#> L003 2025-01-21 Dev Patel    9780002000291

#>     V1         V2           V3           V4
#> 1 L001 2025-01-14 Hugo Silva   9.780141e+12
#> 2 L002 2025-01-16 Ben Okafor   9.780306e+12
#> 3 L003 2025-01-21 Dev Patel    9.780002e+12

The widths count characters. A negative width skips that many characters, and the skipped fields are not part of the result, so they are not given in col.names or colClasses. The extra arguments pass through to read.table(), so colClasses can keep an ISBN as text, and strip.white = TRUE removes the padding that the fixed width put around "Hugo Silva"; without it the member names keep their trailing blanks. A field of zero width, or one beyond the end of a short line, is NA. sep is the character that read.fwf() uses internally between fields (a tab by default); it must not occur in the file.

type.convert()

type.convert() is the function that read.table() calls on every column, and it is also the way to apply the same guessing to a data frame whose columns are all text (the result of readLines() plus strsplit(), or of colClasses = "character"). It works on a vector, matrix, array, data frame or list, and recurses into data frames and lists.

# type.convert() is the function behind the guessing of read.table()

type.convert(x, as.is = TRUE)

# complex, and then text (a factor only when as.is = FALSE)

class(type.convert(c("1", "x"), as.is = TRUE))

class(type.convert(c("1", "x"), as.is = FALSE))
#> [1] "factor"

class(type.convert(c(NA, NA), as.is = TRUE))

The first type that accepts every non-missing value wins, in the order logical, integer, numeric and complex, then text; as.is = FALSE makes the last step a factor. Text for people: cat(), format(), sprintf(), formatC() and prettyNum()

write.table() is for machines; for a report, a log line, or a message the output is built as text. The tools are cat(), which prints values with a separator and no quotes or index; format(), which turns a vector into aligned strings; sprintf(), which fills a C-style template; formatC(), which does the same with named arguments; and prettyNum(), which inserts big marks into numbers. The manual’s note on export is the reason to care: cat() underlies the exporting functions, takes a file and an append argument, and is the tool for writing text a piece at a time.

Several details are visible in the output. cat() uses up to 7 significant digits for numbers, as print() does, so pi is 3.141593 and a number like 123456789 is written in full; a precise number needs format(digits = ). fill wraps at the given width and adds a final newline. format(c(1, 10, 100)) pads to a common width so that the numbers align; nsmall is a minimum number of decimals, not a rounding; big.mark inserts thousands marks. sprintf() is vectorised over every argument, so sprintf("%-10s|%8.2f|", names, prices) formats a column in one call; %% is a literal percent, %05d pads with zeros and %e is scientific. formatC() has the same power with width, flag, digits, format and big.mark, and a negative width means left-justify. prettyNum() works on numbers and on strings that already hold digits. Which one to prefer is a matter of taste; sprintf() is the most compact for a fixed template and format() for aligning a whole column.

sink() and capture.output()

Sometimes the text you want to keep is what print() already shows: a model summary, a table, a str(). The R Data Import/Export manual’s section on exporting notes that sink() diverts R’s standard output to a file, that it is not usually the most efficient route, and that options(width) may need increasing. capture.output() is the safer front-end: it evaluates its arguments and returns what they printed as a character vector, or writes it to a file.

books <- read.csv("books.csv")
path <- tempfile(fileext = ".txt")

# capture.output() returns what the expressions would have printed
text <- capture.output(summary(books$year))
text
#> [1] "   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.     NAs "
#> [2] "   1813    2006    2016    1999    2020    2023       1 "
capture.output(cat("one\n"), print(1:3))
#> [1] "one"       "[1] 1 2 3"

# It is the right tool to write printed output to a file
writeLines(capture.output(str(books[1:3, c("title", "year")])), path)
writeLines(readLines(path))
#> 'data.frame':	3 obs. of  2 variables:
#>  $ title: chr  "The Dispossessed" "Pride and Prejudice" "  the quiet streets "
#>  $ year : int  1974 1813 2019

# sink() diverts all output to a file until sink() is called again
sink(path)
print(summary(books$pages))
cat("pages known:", sum(!is.na(books$pages)), "\n")
sink()
writeLines(readLines(path))
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max.     NAs
#>    88.0   202.0   268.0   268.2   344.5   432.0       2
#> pages known: 14

# sink(append = TRUE) adds to the file; sink.number() counts the open sinks
sink(path, append = TRUE)
cat("appended; open sinks:", sink.number(), "\n")
sink()
tail(readLines(path), 1L)
#> [1] "appended; open sinks: 1 "

# A sink that is never closed swallows the rest of the output; on.exit()
# inside a function is the safe pattern
log_to <- function(path, code) {
  sink(path)
  on.exit(sink())
  force(code)
}
log_to(path, print("inside the file"))
readLines(path)
#> [1] "[1] \"inside the file\""

# cat(file =) and write() are the simple alternatives for small outputs
cat("title\n", file = path)
cat("Dune\n", "Emma\n", file = path, sep = "", append = TRUE)
readLines(path)
#> [1] "title" "Dune"  "Emma"
write(c(1, 2, 3, 4, 5, 6), path, ncolumns = 3L)
readLines(path)
#> [1] "1 2 3" "4 5 6"
unlink(path)

Source: R documentation: sink

The first part is the whole of capture.output(): the printed lines of summary() come back as two strings, and several expressions can be captured in one call. The writeLines(capture.output(x), path) form is the usual way to write a printed object to a file. sink(path) diverts all the output that follows until sink() is called again, which is why the print() and cat() calls in the script printed nothing to the console; append = TRUE adds to the file, and sink.number() reports how many diversions are open (one, inside the sink). A sink that is never closed swallows the rest of the output, and an error between sink(path) and sink() leaves it open, so inside a function the pattern is sink(path); on.exit(sink()). The help page warns against sinking the message stream (type = "message") unless the effects are understood, because there is no stack and the target must be an already open connection. split = TRUE sends output to the file and the console both, like the Unix tee, but splits only R’s own printing and the default output of writeLines(). The last block shows the plain alternatives: cat(file = , append = TRUE) and write(), which writes a vector in rows of ncolumns values.

The two tools differ in what they capture. capture.output() works through a sink, so the code it evaluates must not close connections, and if the code fails, the output collected so far is lost unless a file is given. Neither captures messages and warnings by default.

What each part shows:

  • head(mtcars, 3L) works at once. The data sets of datasets are lazy-loaded: the object is not in memory until first used, and it lives in the package, not in your workspace. data() is not needed, and the help page says that the need it once met, to avoid having large data sets in memory, has been almost entirely superseded by lazy loading.

  • data(package = "datasets") returns an object of class "packageIQR" whose $results matrix has one row per item (108 in this version, including entries such as BJsales.lead (BJsales), which says that the object BJsales.lead is loaded by data(BJsales)).   • package = says where to look when the same name exists in several packages.

The semicolon is not a typo: a .csv file in the data directory of a package is semicolon-separated, and Writing R Extensions notes that .csv there is not the standard CSV format. data() also documents a warning that applies to all four: loading a data set can silently create objects other than the one named, and there have been published packages in which data() replaced .Random.seed.

The foreign package works without any file from another system, because it can also write Stata files and the text and program files that SAS, SPSS or Stata use to read a text file.

write.dta() writes a Stata file and read.dta() reads it back; the text columns stay text, the integers stay integers, and a factor is written as Stata value labels, which read.dta() turns back into a factor (convert.factors = FALSE keeps the integer codes 1, 2, 1). write.foreign() writes two files, a text file of the data and a program in the language of the target package; with package = "SPSS" the program is a DATA LIST and VARIABLE LABELS script (the line that names the data file is dropped from the output above because it holds a temporary path). The data file is written with write.table(), which is why it has the quoting and trailing-comma features of that function.

readr, vroom, readxl, haven, arrow and fread

Five packages are named so often in data-import advice that a reader should know what they are. readr (readr package documentation: read_delim) is the tidyverse reader for delimited files: read_csv(), read_delim() and write_csv() return tibbles, report the column types they guessed, trim white space and treat both the empty string and NA as missing by default, and read the shelf’s year and pages as doubles where base R reads integers. vroom (vroom package documentation) indexes a delimited file and reads its columns lazily through the ALTREP framework, so that you only pay for the columns you use. readxl (readxl package documentation: read_excel) reads .xls and .xlsx with no external dependencies. haven (haven package documentation: read_spss) reads and writes SAS, SPSS and Stata files by wrapping the ReadStat C library and keeps their value labels. arrow (not installed in the checking environment; arrow package documentation) reads and writes Parquet and Feather files and provides an Arrow C++ backend for dplyr; this page does not run it. Outside the tidyverse, data.table::fread() (data.table package documentation: fread) detects the separator and header by itself and returns a data.table. All of these are described in the documentation sites named above, and readr, readxl and arrow also have chapters in the community book "R for Data Science"; the pages The tidyverse and dplyr and data.table cover the ecosystems around them. Base R is enough for the files of this page, needs nothing to install, and its defaults are the ones that the rest of the R documentation assumes.

Putting it together: clean, save, reload

The pieces combine into the usual cycle for the shelf data: read the raw files with the types stated, clean the text columns, write a tidy CSV with the conventions the next reader needs, and prove that the file reads back to the same data frame. The cleaning steps (trimws(), collapsing double spaces, lower-casing the genre, turning the empty ISBN into NA) are the ones the Data Frames page explains.

source("scenario.R")

# The cleaning steps of the data-frames page, applied to the text columns

The file shows the point of each choice. row.names = FALSE keeps the first column meaningful. na = "" writes missing values as empty fields, which is how the raw shelf files look and what a spreadsheet shows as an empty cell; the matching na.strings = "" on the way back turns the empty text fields (including the ISBN) into NA again. The column classes are stated, so nothing is guessed and the isbn text, with its hyphens, cannot be mistaken for a number. With those two settings the cleaned books table is identical() to the original; the loans table, with its two date columns, round-trips the same way once colClasses names "Date", including the impossible date that is NA in the original and empty in the file.

Pitfalls

  • Trusting the guess for identifiers. ISBNs, postcodes, phone numbers and account numbers are labels, not quantities. colClasses = "character" or a named vector keeps their zeros; the guess does not (the 007 example).

  • One bad value turns a column into text. The mean of the column is NA with a warning, and arithmetic fails later, far from the read. Look at str() of every imported data frame; list the spellings of missing in na.strings.

  • Leaving the factor trap to old habits. as.numeric(f) on a factor returns the codes of the levels; the safe conversion is as.numeric(as.character(f)) (R FAQ 7.10), and since R 4.0.0 a text column is not a factor unless asked.

  • Names that need repair. check.names = TRUE renames loan date to loan.date, and a name that starts with a digit gets an X. R FAQ 7.14 explains what a valid name is; check.names = FALSE keeps the original, which then needs backticks.

  • The default write.csv() row-name column. Writing a data frame with the default row names and reading it with read.csv() gives an extra column X. Use row.names = FALSE to write, row.names = 1L to read.

  • Wrong separator, no error. A semicolon file read by read.csv() is one wide column. Look at the first lines with readLines() before choosing the reader.

  • Silent record splitting. With fill = TRUE a line with too many fields wraps into a new record; compare the number of rows with length(readLines()) minus the header, and use count.fields() when they differ.

  • An unclosed quote. The warning EOF within quoted string is the only signal. Never silence warnings in an import.

  • Dates. CSV has no date type. as.Date() understands YYYY-MM-DD and YYYY/MM/DD; a day-first date parsed with colClasses = "Date" is silently wrong. Read as text and give the format.

  • Encoding. fileEncoding converts and encoding only labels. A Latin-1 file in a UTF-8 session fails at the first function that needs characters, not at the read.

  • Windows paths. A backslash in a string is an escape character. The R FAQ 7.8 advice is to write "C:/data/books.csv" or double each backslash; the raw string r"(C:\data\books.csv)" is the third way since R 4.0.0.

# A Windows path pasted into a string: the backslash starts an escape
code <- "path <- \"C:\\data\\books.csv\""
writeLines(code)
#> path <- "C:\data\books.csv"
tryCatch(parse(text = code), error = conditionMessage)
#> [1] "'\\d' is an unrecognized escape in character string (<input>:1:13)"

# Forward slashes work on every platform, and so do doubled backslashes
nchar("C:/data/books.csv")
#> [1] 17
nchar("C:\\data\\books.csv")
#> [1] 17

# file.path() joins the parts with "/"; raw strings keep a backslash as typed
file.path("data", "shelf", "books.csv")
#> [1] "data/shelf/books.csv"
r"(C:\data\books.csv)"
#> [1] "C:\\data\\books.csv"

# A relative name is looked up in the working directory, a missing file is a
# warning and then an error
file.exists("books.csv")
#> [1] TRUE
file.exists("data/books.csv")
#> [1] FALSE
tryCatch(read.csv("data/books.csv"), error = conditionMessage,
         warning = conditionMessage)
#> [1] "cannot open file 'data/books.csv': No such file or directory"

# Tilde expansion is done by file(), so read.csv("~/books.csv") works too
nchar(path.expand("~")) > 1L
#> [1] TRUE
