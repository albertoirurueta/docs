Matrices and Arrays

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R (the functions xtabs() and ftable() live in the stats package, which is attached in every session), except the last section, which uses the Matrix package, version 1.7-5, a recommended package that is installed with R. The lintr 3.4.0 default linters were used only to check the scripts.

R has no separate matrix type. A matrix is an ordinary vector that carries a dim attribute with two entries, and an array is the same thing with any number of entries. Everything else on this page follows from that sentence: the data are stored one column after another, so the first subscript moves fastest; the operators that work element by element on vectors work element by element on matrices; subsetting with one index ignores the shape; and the functions that treat the shape seriously (%*%, solve(), apply(), t()) are separate functions with their own names. This page goes through the construction of matrices and arrays, the class vector they have had since R 4.0.0, names and the drop argument, combining and reshaping, the matrix product and its relatives, the decompositions behind linear algebra, locating elements, the summaries over rows and columns, tables as arrays of counts, the BLAS and LAPACK libraries that do the numerical work, and the Matrix package for sparse matrices.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts pass the default lintr linters; the one idiom that a default linter dislikes, the use of the special variable .Generic inside a method in Operators on matrices, carries a # nolint: comment. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says. The examples use the library scenario of the section: books, loans, shelf_today, loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"). Examples that do not need the shelf use small matrices with round numbers, so that every result can be checked by hand.

A matrix is a vector with dimensions

An Introduction to R defines an array as a multiply subscripted collection of data entries, a matrix as the special case with two subscripts, and says that a vector can be used as an array only if it has a dim attribute, a vector of non-negative integers (An Introduction to R: Arrays). The R Language Definition adds the rules of the representation: the content is stored in a vector in column-major order, R ensures that the length of the vector is the product of the extents, an extent may be zero, and a vector is not the same thing as a one-dimensional array, because the vector has no dim attribute and the array has one of length one (The R Language Definition: Dimensions). The order is the one of Fortran: for a dimension vector c(3, 4, 2) the data vector holds a[1, 1, 1], a[2, 1, 1], a[3, 1, 1], a[1, 2, 1] and so on, with the first subscript moving fastest and the last one slowest.

Creating a matrix

matrix(data, nrow, ncol, byrow, dimnames) builds a matrix from a vector (R documentation: matrix). The arguments and their rules are in the help page:

Argument Meaning

data

the values, taken in order; a list is allowed and gives a list matrix; a classed object is coerced with as.vector() and loses its attributes

nrow, ncol

the extents; when only one is given the other is worked out from the length of data; when neither is given the result has one column

byrow

FALSE (the default) fills column by column, TRUE fills row by row; either way the matrix is stored column-major, so byrow changes only the arrangement of the input

dimnames

NULL or a list of length two with the row names and the column names; a list of length one gives row names only, and the names of the list become the names of the dimensions

short data

too few values are recycled to fill the matrix; zero values give NA of the right type (0 for a raw vector, NULL for a list)

The first script shows the stored vector, the byrow fill, the inferred extent, the recycling and the warnings. matrix(1:3, nrow = 2, ncol = 3) is silent although the data do not line up with the columns: the warning is raised when the length of data does not divide the number of cells, here 2 * 3 = 6, and three does divide six. R 4.2.0 made matrix() warn in more cases where the length of data differs from nrow * ncol, and the environment variable _R_CHECK_MATRIX_DATA_, which R CMD check --as-cran sets, turns that warning into an error (R NEWS: Changes in R 4.2.0). The messages name the first extent that does not fit, or say that the data are longer than the matrix: data length [6] is not a sub-multiple or multiple of the number of rows [4], data length differs from size of matrix: [6 != 3 x 3].

# A matrix is a vector with a "dim" attribute; the fill is column-major
m <- matrix(1:6, nrow = 2, ncol = 3)
m
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6
dim(m)
#> [1] 2 3
nrow(m)
#> [1] 2
ncol(m)
#> [1] 3
length(m)
#> [1] 6
typeof(m)
#> [1] "integer"
attributes(m)
#> $dim
#> [1] 2 3
#>

# byrow = TRUE fills the rows first; the stored vector does not change order
r <- matrix(1:6, nrow = 2, byrow = TRUE)
r
#>      [,1] [,2] [,3]
#> [1,]    1    2    3
#> [2,]    4    5    6
as.vector(r)
#> [1] 1 4 2 5 3 6

# Only one dimension is needed: the other is inferred from the length
matrix(1:6, ncol = 2)
#>      [,1] [,2]
#> [1,]    1    4
#> [2,]    2    5
#> [3,]    3    6
matrix(0, nrow = 2, ncol = 2)

#> [1,]    0    0
#> [2,]    0    0

# Too few values are recycled; a non-multiple length warns
matrix(1:3, nrow = 2, ncol = 3)
#>      [,1] [,2] [,3]

warning_text(matrix(1:6, nrow = 3, ncol = 3))

Source: R documentation: matrix

typeof(m) is "integer" and attributes(m) is a list with one element, dim: nothing else marks the object as a matrix. That is also why dim<- is the cheap way to turn a vector into a matrix. The help page for matrix() recommends it for a conversion of a vector, because it avoids duplicating the data and keeps the class of the vector, which matters for objects such as dates, and the same help page shows dimnames<- as the companion for the names. An assignment whose extents do not multiply to the length of the vector is an error: dims [product 8] do not match the length of object [6]. The manual points out the contrast with array(), which recycles a short vector and silently drops extra values, where dim<- insists on an exact match (An Introduction to R: The array() function).

Arrays of any rank

array(data, dim, dimnames) is the general constructor; matrix() is the rank-two case with a friendlier interface, and identical(matrix(1:6, 2), array(1:6, c(2, 3))) is TRUE (R documentation: array). The element a[i, j, k] of an array with extents c(2, 3, 4) is element i + 2 * (j - 1) + 6 * (k - 1) of the data vector, which the script checks. Indexing an array with one subscript per dimension follows the rules of Subsetting and Indexing, with the component of dimnames taking the place of names (The R Language Definition: Indexing matrices and arrays).

# array(data, dim, dimnames): the same column-major fill, with any rank
a <- array(1:24, dim = c(2, 3, 4))
dim(a)
#> [1] 2 3 4
a[2, 3, 4]
#> [1] 24
a[, , 1]
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6
a[1, , ]
#>      [,1] [,2] [,3] [,4]
#> [1,]    1    7   13   19
#> [2,]    3    9   15   21
#> [3,]    5   11   17   23
dim(a[1, , ])
#> [1] 3 4

# The element at (i, j, k) is at position i + 2 * (j - 1) + 6 * (k - 1)
a[2, 3, 4] == a[2 + 2 * (3 - 1) + 6 * (4 - 1)]
#> [1] TRUE

Three details in the output matter later. The array printed with named dimnames shows each slice with a header such as , , format = print, and the names of the dimensions appear as row and column headings; those names are what apply() and marginSums() accept in place of numbers. A one-dimensional array has a dim of length one and its names() come from dimnames[[1]]; the manual says such arrays are usually treated like vectors, including when printing, but that the exceptions cause confusion, and is.matrix() is FALSE for them. Finally dim(x) <- NULL removes the shape and leaves the data vector, in the same order.

Extents: nrow, ncol, NROW and NCOL

nrow(x) and ncol(x) are dim(x)[1L] and dim(x)[2L], so they give NULL for a vector. NROW(x) and NCOL(x) treat a vector as a one-column matrix and give its length and 1, which is what code that accepts "a vector or a matrix" wants. R 4.4.0 changed NCOL(NULL) from 1 to 0, for consistency with cbind(), and NROW(NULL) was already 0 (R documentation: nrow). The script in Names and drop shows all four.

Matrices are arrays: the class vector

A matrix has had two classes since R 4.0.0. The NEWS entry for that release reads "matrix objects now also inherit from class "array"" and warns that this invalidates code which incorrectly assumes that the class of a matrix has length one (R NEWS: Changes in R 4.0.0). In the same release S3 methods for the class "array" began to be dispatched for matrix objects. The matrix help page repeats the fact in its See Also section: a matrix is the special case of a two-dimensional array and inherits(m, "array") is true for a matrix m.

The class is implicit: oldClass(m) is NULL because no class attribute is stored, and class(m) computes the vector from the dim attribute (R documentation: class). is.matrix(x) is true when x is a vector with a dim attribute of length two, which is why a data frame, which has a dim() method but no dim attribute, fails the test; is.array(x) is true for any dim attribute of positive length. The which = TRUE form of inherits() returns the position of each class in the class vector, 2 1 for c("array", "matrix"), because "matrix" comes first.

m <- matrix(1:6, nrow = 2)
a <- array(1:24, dim = c(2, 3, 4))
x <- 1:6

# Since R 4.0.0 a matrix has a class vector of length two
class(m)
#> [1] "matrix" "array"
class(a)
#> [1] "array"
class(x)
#> [1] "integer"
inherits(m, "array")
#> [1] TRUE
inherits(m, "matrix")
#> [1] TRUE
inherits(a, "matrix")
#> [1] FALSE
oldClass(m)       # the implicit class is not stored as an attribute
#> NULL
inherits(m, c("array", "matrix"), which = TRUE)
#> [1] 2 1

# The type tests: is.matrix() needs exactly two dimensions
is.matrix(m)
#> [1] TRUE
is.array(m)
#> [1] TRUE
is.matrix(a)
#> [1] FALSE
is.array(a)
#> [1] TRUE
is.matrix(x)
#> [1] FALSE
is.array(array(1:3))     # a 1-d array is an array but not a matrix
#> [1] TRUE
is.matrix(data.frame(a = 1:2))
#> [1] FALSE

# The code that broke in 4.0.0: a test written for a length-one class
# (an error since R 4.2.0, a warning in 4.0.0 and 4.1.x)
old_test <- \(x) {
  if (class(x) == "matrix") "a matrix" else "something else"
}
tryCatch(old_test(m), error = \(e) conditionMessage(e))
#> [1] "the condition has length > 1"
old_test(x)
#> [1] "something else"

Source: R documentation: class

The last lines are the practical consequence. Code written before R 4.0.0 often tested class(x) == "matrix"; the comparison now returns two values for a matrix, and if with a condition of length greater than one is an error since R 4.2.0 (it was a warning before): the condition has length > 1. Use is.matrix(x) for "exactly two dimensions", inherits(x, "matrix") or is.array(x) for "has a shape", and never compare class(x) with a single string. The same reasoning applies to identical(class(x), "matrix"), which is now FALSE for every matrix. The attributes behind these classes are the subject of Attributes and Names.

The dispatch rule the NEWS entry describes is easy to see with a generic of your own. S3 dispatch on an object without a class attribute uses its implicit class, in the order matrix, array, the type and then the default; NextMethod() moves down that order. An "array" method therefore serves matrices, and a "matrix" method added later takes precedence over it for matrices while arrays of other ranks keep using the array method (see S3 Classes and Generics).

# S3 dispatch on a matrix tries "matrix", then "array", then the default
describe <- function(x) UseMethod("describe")
describe.array <- function(x) "an array method"
describe.default <- function(x) "the default method"
describe(matrix(1:4, 2))
#> [1] "an array method"
describe(array(1:8, c(2, 2, 2)))
#> [1] "an array method"
describe(1:4)
#> [1] "the default method"

describe.matrix <- function(x) paste("a matrix method, then", NextMethod())
describe(matrix(1:4, 2))
#> [1] "a matrix method, then an array method"
describe(array(1:8, c(2, 2, 2)))
#> [1] "an array method"

Source: R NEWS: Changes in R 4.0.0

Names, dimnames and drop

The dimnames attribute is a list with one element per dimension, each either NULL or a character vector of the length of that extent. The list may itself be named, and the R Language Definition says those names are used as headings when an array is printed (The R Language Definition: Dimnames). rownames() and colnames() are the accessors for the first two elements (R documentation: colnames), and dimnames() with its replacement form sets all of them at once (R documentation: dimnames). A name that does not exist is an error for a matrix, unlike a missing name in a vector, which gives NA: subscript out of bounds. A replacement vector of the wrong length is an error too: length of 'dimnames' [1] not equal to array extent.

# Names for the rows and columns: dimnames is a list of two character vectors
visits <- matrix(
  c(12, 7, 9, 4, 15, 6),
  nrow = 2,
  dimnames = list(c("Ana", "Ben"), c("Jan", "Feb", "Mar"))
)
visits
#>     Jan Feb Mar
#> Ana  12   9  15
#> Ben   7   4   6
dimnames(visits)
#> [[1]]
#> [1] "Ana" "Ben"
#>
#> [[2]]
#> [1] "Jan" "Feb" "Mar"
#>
rownames(visits)
#> [1] "Ana" "Ben"
colnames(visits)
#> [1] "Jan" "Feb" "Mar"

# The list itself can be named: the names print as headers
named <- matrix(
  1:4, nrow = 2,
  dimnames = list(member = c("Ana", "Ben"), month = c("Jan", "Feb"))
)
named
#>       month
#> member Jan Feb
#>    Ana   1   3
#>    Ben   2   4
names(dimnames(named))
#> [1] "member" "month"

# Assigning names to an existing matrix
m <- matrix(1:6, nrow = 2)
rownames(m) <- c("a", "b")
colnames(m) <- c("x", "y", "z")
m
#>   x y z
#> a 1 3 5
#> b 2 4 6
dimnames(m) <- NULL
m
#>      [,1] [,2] [,3]
#> [1,]    1    3    5
#> [2,]    2    4    6

# Indexing by name, and the extents that dimnames must match
visits["Ana", "Feb"]
#> [1] 9
visits[, c("Jan", "Mar")]
#>     Jan Mar
#> Ana  12  15
#> Ben   7   6
tryCatch(
  rownames(m) <- c("a", "b", "c"),
  error = \(e) conditionMessage(e)
)
#> [1] "length of 'dimnames' [1] not equal to array extent"
tryCatch(
  visits["Eve", ],
  error = \(e) conditionMessage(e)
)
#> [1] "subscript out of bounds"

x <- c(5, 6, 7)
nrow(x)
#> NULL
NROW(x)
#> [1] 3
NCOL(x)
#> [1] 1

#> NULL

NROW(NULL)
#> [1] 0
NCOL(NULL)
#> [1] 0

drop = FALSE

Subsetting a matrix to a single row or column returns a plain vector, and an array with an extent of one loses that extent. R FAQ 7.5 says that this was determined, after much discussion, to be a feature, and gives the remedy: add drop = FALSE to the subscripting, and use it defensively in programs, because somerows <- mat[index, ] returns a vector instead of a matrix when index happens to have length one (R FAQ 7.5: Why do my matrices lose dimensions?). The function drop() is the explicit form of the same operation: it removes every extent of length one. See Subsetting and Indexing for the whole subscripting story; the script here shows the bug that drop = FALSE prevents, a helper that works for two rows and returns a vector for one.

m <- matrix(1:6, nrow = 2, dimnames = list(c("a", "b"), c("x", "y", "z")))

# A single row or column loses its dimension and becomes a plain vector
m[1, ]
#> x y z
#> 1 3 5
m[, 2]
#> a b
#> 3 4
dim(m[1, ])
#> NULL

# drop = FALSE keeps the matrix, with its names
m[1, , drop = FALSE]
#>   x y z
#> a 1 3 5
m[, 2, drop = FALSE]
#>   y
#> a 3
#> b 4
dim(m[1, , drop = FALSE])
#> [1] 1 3

# drop() removes extents of length one from an array on demand
one <- m[1, , drop = FALSE]
drop(one)
#> x y z
#> 1 3 5

Combining: cbind() and rbind()

cbind() binds vectors and matrices side by side and rbind() stacks them (R documentation: cbind). The manual notes that the result always has matrix status, so cbind(x) and rbind(x) are the simplest ways to treat a vector explicitly as a column or a row (An Introduction to R: Forming partitioned matrices, cbind() and rbind()). The rules in the help page are worth knowing exactly:

  • If all arguments are vectors, the number of rows of the cbind() result is the length of the longest one and shorter ones are recycled, with a warning only when the recycling is fractional (number of rows of result is not a multiple of vector length (arg 2)).

  • If there are matrix arguments, they must agree on the number of rows (columns for rbind()), otherwise the call is an error (number of rows of matrices must match (see arg 2)); vectors are recycled or cut to that length.

  • The type of the result is the highest in the hierarchy raw, logical, integer, double, complex, character, list, so a character argument turns everything into text.

  • Classes of the inputs are discarded: a factor is replaced by its integer codes. Zero-length arguments, including NULL, are ignored unless that would leave the result with no rows (columns).

  • The column names of cbind() come from the colnames of matrix arguments and otherwise from the names of the arguments; unnamed arguments are named by deparsing the expression, but only when deparse.level allows it: 0 never, 1 (the default) only when the expression is a symbol, 2 always. rbind() is the mirror image for row names.

  • cbind() and rbind() are S3 generic, with methods for data frames; the dispatch is done internally and not with UseMethod(), so there is no rbind.default. The data frame method of cbind() is a wrapper for data.frame(..., check.names = FALSE), and rbind() matches data frame columns by name.

Changing the shape: t(), aperm() and c()

t(x) transposes a matrix, and a plain vector is treated as a column, so t(1:3) is a one-row matrix and t(t(1:3)) is a column again (R documentation: t). For a data frame, t() first converts it with as.matrix(). aperm(a, perm) is the generalisation to any rank: the new dimension j is the old dimension perm[j], and the manual points out that aperm(A, c(2, 1)) is the transpose (An Introduction to R: Generalized transpose of an array). With no perm the dimensions are reversed, which makes aperm() equal to t() for a matrix. The dimension names, and the names of the dimensions, move with the dimensions, and perm may be given as those names. With resize = FALSE the data are rearranged but the dim attribute is kept as it was, which is rarely what you want (R documentation: aperm).

The diagonal: diag()

diag() has four distinct usages, which the help page lists, and the manual admits that making the meaning depend on the argument is confusing (R documentation: diag):

Call Result

diag(m) with a matrix m

the diagonal of m as a vector, named when the row and column names match and names = TRUE

diag(nrow = 3) or diag(1, nrow = 2, ncol = 3)

an identity matrix, not necessarily square

diag(3), a single number

the identity matrix of that size (the number is truncated with as.integer())

diag(v) with a vector v of length two or more, or with nrow or ncol

a matrix with v on the diagonal, recycled or truncated as needed, and zeros elsewhere

The trap is the third row. The help page says that diag(x) can have unexpected effects if x is a vector that could be of length one, and recommends diag(x, nrow = length(x)) for consistent behaviour: diag(2.5) is a 2 by 2 identity matrix, not a 1 by 1 matrix holding 2.5. The identity matrix of the linear algebra books is diag(n); the function identity() is something else, the function that returns its argument, and it appears in apply() examples.

Operators on matrices

Element by element

The arithmetic, comparison and logical operators work element by element on arrays, exactly as on vectors, and keep the shape. A * B is therefore the matrix of element by element products, and A %*% B is the matrix product; the manual states the contrast in that form (An Introduction to R: Matrix multiplication), and the Language Definition warns that multiplying two matrices with * does not produce the usual matrix product (The R Language Definition: Operators). The rules for mixing arrays and vectors are in the section of An Introduction to R on the recycling rule, which admits that they are quirky and hard to find elsewhere: the expression is scanned from left to right, short vectors are extended by recycling to the size of the other operands, arrays that meet must have the same dim, a vector operand longer than an array operand is an error, and the result has the common dim of its array operands (An Introduction to R: Mixed vector and array arithmetic. The recycling rule). The Language Definition gives the compact version: for matrix plus matrix the dimensions must match, and for vector plus matrix R recycles first and then checks whether the dimensions fit (The R Language Definition: Dimensional attributes).

The script runs each rule once. m * c(1, 10) recycles the vector down the columns, because the data are column-major. Two matrices of different shapes are an error (non-conformable arrays); a vector whose length does not divide the number of cells is a warning (longer object length is not a multiple of shorter object length); and a vector longer than the matrix is an error once the warning has been silenced (dims [product 4] do not match the length of object [5]). Comparison keeps the shape too: m > 2 is a logical matrix, and which(m > 2) gives positions in the column-major vector.

The matrix product

x %*% y multiplies two matrices if they are conformable, that is if the number of columns of x equals the number of rows of y, and otherwise stops with non-conformable arguments (R documentation: matmult). A vector operand is promoted to a row or a column matrix, whichever makes the shapes conformable; the manual says that this is not always unambiguously possible. Two vectors of the same length give the inner product as a 1 by 1 matrix, which drop() turns into a number; the help page also points out that the names of a vector are not promoted to row or column names. Operands must be numeric or complex, so a character matrix gives requires numeric/complex matrix/vector arguments. The product is not commutative, and the script shows it with a matrix that swaps columns when it multiplies from the right and rows when it multiplies from the left.

Cross products, outer and Kronecker products

crossprod(x, y) is t(x) %*% y, and tcrossprod(x, y) is x %*% t(y), but the transpose is not formed, so the call is faster; with one argument, crossprod(x) is t(x) %*% x, the form that appears in the normal equations of regression (R documentation: crossprod). The outer product of two arrays has the concatenated dimension vector of its operands, and its data are all possible products of an element of the first with one of the second; it is written a %o% b or outer(a, b), it is not commutative, and the multiplication can be replaced by any vectorised function of two arguments (An Introduction to R: The outer product of two arrays). The function must accept two vectors of the same length and return a vector of that length: the call outer(1:3, 1:2, \(a, b) 1) fails with dims [product 6] do not match the length of object [1] because the function returned one value, not six. kronecker(X, Y) (alias %x%) is the Kronecker product: each element of X multiplies a whole copy of Y, so the result has the product of the extents (R documentation: kronecker).

x <- matrix(c(1, 2, 3, 4, 5, 6), nrow = 3)

#> [2,]   10   10

#> [2,]   32   77

Linear equations, determinants and conditioning

solve() and det()

solve(a, b) solves the linear system a x = b; with b missing, it returns the inverse of a. The default method is an interface to the LAPACK routines DGESV and ZGESV, the matrix must be square, and b can be a vector or a matrix (R documentation: solve). The manual’s advice is to prefer solve(a, b) to solve(a) %*% b: the inverse is rarely needed, and computing it is both inefficient and potentially unstable. It writes the quadratic form x %*% A^-1 %*% x as x %*% solve(A, x) for the same reason (An Introduction to R: Linear equations and inversion). The row and column names of the result come from the column names of a and of b, as the help page says; in the script solve(a, b) is named by the columns of a and solve(a) has the columns' names as rows and the rows' names as columns.

Two failures are distinct. A matrix that is exactly singular is detected by the factorisation itself, and the message names the pivot: Lapack routine dgesv: system is exactly singular: U[2,2] = 0. A matrix that is singular only to working precision passes the factorisation, and solve() then compares the estimated reciprocal condition number, rcond(), with the argument tol, whose default is .Machine$double.eps; if it is smaller, the error is system is computationally singular: reciprocal condition number = 2.48656e-17, where the number is the estimate for the matrix at hand and can differ in the last digits with the BLAS in use. The 12 by 12 Hilbert matrix is the standard badly conditioned example. The check is skipped when tol <= 0; the result is then dominated by rounding error. Shape errors name the dimensions: 'a' (2 x 3) must be square and 'b' (3 x 1) must be compatible with 'a' (2 x 2). The argument LINPACK of solve() is defunct. From R 4.3.0 solve() for complex inputs uses tol as well and checks for computational singularity, as it has long done for real inputs.

det(x) is a wrapper around determinant(x), which uses an LU decomposition and returns the modulus (by default on the logarithmic scale) and the sign separately; the help page adds that computing the determinant is often not what you should be doing to solve a given problem, and its logarithm = TRUE default exists because the determinant itself easily overflows or underflows (R documentation: det). A non-square argument is an error: 'x' must be a square matrix.

norm(), rcond(), kappa() and the triangles

norm(x, type) computes a matrix norm: "O" (or "1") is the largest absolute column sum and the default, "I" the largest absolute row sum, "F" the Frobenius norm, "M" the largest absolute value of an element, and "2" the spectral norm, the largest singular value (R documentation: norm). R 4.4.0 made norm() work for complex matrices, and R 4.6.0 fixed the S4 method for type missing to use "O", as intended for years (R NEWS: Changes in R 4.6.0). The condition number of a matrix is the norm of the matrix times the norm of its inverse. rcond(x) estimates the reciprocal of the 1-norm condition number cheaply, which is what solve() uses, and kappa(x, exact = TRUE) computes the 2-norm condition number as the ratio of the largest to the smallest non-zero singular value; with the default exact = FALSE, kappa() is only a rough estimate (R documentation: kappa). The 4.4.0 release made kappa() and rcond() correct in more cases and made kappa(., norm = "2") warn that it then computes the 1-norm unless exact = TRUE.

lower.tri(x, diag = FALSE) and upper.tri(x, diag = FALSE) return logical matrices that mark the triangles, so they are indexes for reading or writing them (R documentation: lower.tri). A common use is to fill half of a symmetric matrix and mirror it with s + t(s); isSymmetric() checks the result (R documentation: isSymmetric).

Decompositions: qr(), chol(), eigen() and svd()

R’s matrix factorisations all return a plain list (or an object of class "qr"), and the manual introduces them in its section on matrix facilities (An Introduction to R: Matrix facilities).

The QR decomposition

qr(x) computes the QR decomposition and returns an object of class "qr" with the components qr, rank, qraux and pivot; qr.Q() and qr.R() extract the factors, and the qr.coef(), qr.fitted(), qr.resid() and qr.solve() family uses the decomposition without forming Q (R documentation: qr). The default code is the LINPACK routine with limited column pivoting and the tolerance tol = 1e-07 for detecting linear dependence of the columns; LAPACK = TRUE selects the LAPACK routine, which pivots differently and always reports full rank; qr.fitted() and qr.resid() support only the LINPACK interface. The decomposition does not assume full column rank: redundancies are found and reported in rank. qr.solve(a, b) solves a system, and for a non-square a it returns the least-squares solution, which is why the same coefficients come out of qr.solve(x, y), of the normal equations solve(crossprod(x), crossprod(x, y)) and of lm(). The QR route is the numerically safer one, because forming crossprod(x) squares the condition number; the manual says this QR-based interface is the older, low-level way to do least squares, which lm() and the facilities of Statistical Models have replaced for modelling (An Introduction to R: Least squares fitting and the QR decomposition). A rank-deficient matrix makes qr.solve() stop: singular matrix 'a' in solve. Signs in qr.R() and qr.Q() are fixed by the algorithm (the diagonal of R is negative in the script).

Cholesky, eigenvalues and singular values

chol(x) returns the upper triangular factor R with R'R = x for a symmetric positive definite x; only the upper triangle of x is used, and an x that is not positive definite, or only positive semi-definite, is an error that names the leading minor: the leading minor of order 2 is not positive (R documentation: chol). chol2inv(r) inverts x from its Cholesky factor, which is cheaper than solve() when the factor is already at hand (R documentation: chol2inv). The argument pivot = TRUE handles positive semi-definite matrices; R 4.3.1 corrected the error or warning message for a matrix that is not positive definite, and R 4.6.0 made chol(x, pivot = TRUE) zero the trailing submatrix when the algorithm stops early, because the reconstruction recipe in the help page gave wrong results when the rank was two or more less than the dimension. A non-square input fails with 'a' must be a square matrix.

eigen(x) returns a list with values, sorted in decreasing order (by modulus for a non-symmetric matrix, whose values may be complex), and vectors, the unit-length eigenvectors as columns (R documentation: eigen). With symmetric unspecified, isSymmetric(x) decides; it is surer and typically faster to set it yourself, and with symmetric = TRUE only the lower triangle is used. only.values = TRUE skips the eigenvectors, which is the slow part for large matrices. A real matrix whose eigenvalues form a complex conjugate pair, such as a rotation, gives complex values. Missing, NaN or infinite entries are an error. The signs of the eigenvectors are not fixed by the mathematics, and the Installation and Administration manual says that the signs of eigenvectors and of singular vectors may differ between BLAS and LAPACK implementations without either being wrong (R Installation and Administration: Linear algebra); that is why the script prints eigenvalues and checks reconstructions instead of printing the vectors.

svd(x) returns d, the singular values in decreasing order, and the matrices u and v with orthonormal columns such that x = u %*% diag(d) %*% t(v) (R documentation: svd). The arguments nu and nv control how many columns of each are computed. Missing or infinite values are an error: infinite or missing values in 'x'. A non-square matrix is an error for eigen() (non-square matrix in 'eigen') but not for svd().

Locating elements: which(), row(), col() and friends

Subscripting with one index ignores the shape and uses the data vector, so m[1] usually differs a lot from m[1, ] and m[, 1], as the Language Definition points out. Two index forms respect the shape without naming each dimension. A numeric matrix with one column per dimension picks single cells, one per row: negative values are not allowed, zero rows are ignored and NA rows give NA (An Introduction to R: Index matrices). A logical matrix of the same shape picks the cells that are TRUE, as a vector. which(x, arr.ind = TRUE) goes the other way and converts the TRUE cells to row and column subscripts; arrayInd(ind, .dim) is the same conversion for any vector of positions and any dim (R documentation: which). row(m) and col(m) return matrices holding each cell’s row and column number, so row(m) > col(m) is the strict lower triangle written from first principles, and slice.index(a, d) generalises them to the d-th dimension of any array (R documentation: row, R documentation: slice.index). max.col(m) returns, for each row, the column of its largest element; its default ties.method = "random" breaks ties at random, treating entries within a relative tolerance of 1e-5 as tied, so pass "first" (the same as unname(apply(m, 1, which.max))) or "last" where the result must be reproducible (R documentation: max.col).

Summaries over rows and columns: apply(), sweep() and scale()

apply()

apply(X, MARGIN, FUN, ...) calls FUN on each slice of X: MARGIN = 1 is the rows, 2 the columns, c(1, 2) every cell, and for a higher-rank array c(1, 3) keeps the first and third dimensions and applies FUN to what is left, a matrix for each pair. MARGIN can be a character vector when the dimensions are named (R documentation: apply). The shape of the result follows the help page. If every call returns a vector of length n, the result is an array with dim c(n, dim(X)[MARGIN]) when n > 1, so the answers sit in columns, one per slice, which is why a function that returns a vector per row produces the transpose of what a reader expects; when n is 1 the result is a vector for a single margin. If the calls return different lengths, the result is a list. Since R 4.1.0 simplify = FALSE always returns a list (R NEWS: Changes in R 4.1.0). Arguments after FUN are passed on to FUN, which also means that an extra argument must not partially match MARGIN or FUN. A data frame is converted with as.matrix() first, which turns it into text when one column is not numeric (see Data frames and matrices). apply() is the matrix member of the family described on The apply Family and Functionals; it is a loop in R code, not a vectorised kernel.

sweep() and scale()

sweep(x, MARGIN, STATS, FUN = "-") applies FUN between the array and a summary statistic that is recycled along the margin, which is how a column of means is subtracted from each column or a row of totals divides each row (R documentation: sweep). With the default check.margin = TRUE it warns when STATS does not recycle exactly: STATS does not recycle exactly across MARGIN. MARGIN can be a dimension name, as for apply(), since R 4.0.0, which also gave slice.index() the same ability. scale(x, center = TRUE, scale = TRUE) centres and scales the columns of a numeric matrix: with center = TRUE it subtracts the column means and with scale = TRUE divides by the column standard deviations, and when it does not centre, the divisor is the root mean square of the column, computed with n - 1 (R documentation: scale). The result is a matrix with extra attributes scaled:center and scaled:scale that record what was used, so the transformation can be undone or applied to new data with sweep(); they print after the matrix, which surprises people the first time. Both arguments can also be numeric vectors of per-column values. scale() works on columns; to standardise rows, transpose twice.

Proportions and margins

proportions(x, margin) divides by the sum over the margin (margin = 1 makes rows sum to one, 2 columns, none the whole table), and marginSums(x, margin) gives the sums themselves; both arrived in R 4.0.0 to replace the unfortunately named prop.table() and margin.table(), which stay as aliases for compatibility, and they accept the names of the margins (R documentation: proportions). Appearing in the script above, proportions(per_month, 1) and prop.table(per_month, 1) give the same numbers.

Tables as arrays

The last section of the matrix chapter of An Introduction to R is about frequency tables: table() takes equal-length factors and returns a k-way array of frequencies, ordered and labelled by the levels of the factors, and for one factor it gives the same counts as tapply(f, f, length) more conveniently (An Introduction to R: Frequency tables from factors). The manual builds its income-by-state example with cut(); the script uses the same pattern with the shelf, a genre factor and page-count bands. table() documents the arguments that matter in practice: useNA = "ifany" (or "always") adds an NA row or column, because NA is not a level and is otherwise left out; dnn names the dimensions; and a factor with an unused level still gets a row of zeros (R documentation: table).

The formula interface is xtabs(). Data frames and matrices

A data frame is not a matrix, although it has dim(), nrow() and t(). as.matrix(df) is the conversion, and its type follows the columns: all numeric columns give a numeric matrix of the highest type, all logical a logical matrix, and as soon as one column is not numeric, logical or complex the result is a character matrix, with factors converted by as.vector() and other columns by format(), so numbers become padded strings. The row names become the row names of the matrix only when they are not the automatic ones (R documentation: matrix). data.matrix(df) always returns numbers: factors become their integer codes, and since R 4.0.0 character columns are first converted to factors and then to integers (R documentation: data.matrix). That is the safe route to a numeric matrix for a mixed data frame, but the codes of a character column depend on the sorted values and mean nothing numerically. apply() calls as.matrix() on a data frame, so apply(df, 2, class) reports "character" for every column of a mixed data frame; vapply(df, class, character(1)) looks at the columns as they are. See Data Frames for the other direction.

BLAS and LAPACK

R does not implement matrix algebra itself. The Installation and Administration manual states in its appendix on linear algebra that the routines make use of BLAS (Basic Linear Algebra Subprograms) and, for most of them, of LAPACK (Linear Algebra PACKage), that the R sources contain reference Fortran implementations of both, and that they can be replaced by external libraries, usually tuned for specific CPUs (R Installation and Administration: Linear algebra). %*%, crossprod(), solve(), qr(LAPACK = TRUE), chol(), eigen() and svd() end up there. The practical consequences are in the same appendix:

  • An external BLAS gives results that are not identical to the reference implementation. Some differences are benign, such as the signs of singular vectors and eigenvectors, but the optimised routines can be less accurate and, for LAPACK, older, with fewer corrections.

  • R relies on ISO/IEC 60559 (IEEE 754) arithmetic, and a library that assumes a term with a zero factor is zero can break that, since x * 0 can be NaN.

  • Multi-threaded BLAS libraries can use more CPU time, and even more elapsed time, than a single-threaded one, and BLAS and LAPACK calls inside threaded code (OpenMP sections in packages such as mgcv) may be unsafe with some external libraries. See Parallel and Asynchronous Computing.

  • BLAS has been unchanged for decades, until LAPACK 3.12.1 (January 2025) added routines such as dgemmtr. R 4.5.0 updated its bundled sources to that release, stated that it is expected to be the last update of the bundled BLAS and LAPACK, and that building against external libraries will be required in future; BLAS libraries are therefore no longer freely interchangeable (R NEWS: Changes in R 4.5.0).

  • The choice is made when R is built (--with-blas, --with-lapack) or, on Debian-style systems with the alternatives mechanism and with FlexiBLAS, switched afterwards; see the BLAS and LAPACK subsections of the appendix (R Installation and Administration: BLAS, R Installation and Administration: LAPACK).

From inside R, La_version() reports the version of LAPACK in use at run time (R documentation: La_version), La_library() the shared object file that contains it (R documentation: La_library), and extSoftVersion() a named character vector with the versions of third-party libraries, among them the BLAS entry with the name of the library file (R documentation: extSoftVersion). The file names are machine specific, so the script prints the LAPACK version, which is the number the manual’s text is about, and shows that La_library() returns a string without printing it. The file is typically libRlapack.so (libRlapack.dylib on macOS) for the internal LAPACK and a vendor name for an external one, and the detection does not work on Windows or for the Accelerate framework on macOS. sessionInfo() includes La_version() since R 4.3.0, and since R 4.5.0 it still reports it when La_library() is empty (R documentation: sessionInfo). The version printed below, 3.12.0, is that of the container this page was checked in, and on your machine it can differ.

The option matprod selects how %*%, crossprod() and tcrossprod() are computed for double and complex vectors: "default" uses BLAS but falls back to a plain three-loop algorithm when the input may contain NaN or Inf, so that they propagate correctly; "internal" always uses the three-loop code, with a long double accumulator where available; "blas" always uses BLAS without checks, which the help page says needs extreme care; and "default.simd" is experimental (R documentation: options).

Sparse matrices: the Matrix package

A shelf of 16 books and 8 members is small, but the table of members by books of a real library is mostly zeros, and a dense matrix stores every zero. The recommended package Matrix, version 1.7-5 on this page, provides S4 classes for sparse and dense matrices with the same operators: %*%, t(), crossprod(), solve(), chol() and qr() have methods, and Matrix::sparseMatrix(i, j, x, dims, dimnames) builds a column-compressed sparse matrix from the row and column positions of the non-zero entries, adding up entries that repeat the same position (Matrix package documentation: sparseMatrix). Matrix::Matrix(data, nrow, ncol, sparse) is the friendlier constructor, which chooses a class from the content: a diagonal matrix becomes a "ddiMatrix", and sparse = TRUE asks for a sparse class (Matrix package documentation: Matrix). Class names such as "dgCMatrix" encode the content: d for double, g for general, and C for column-compressed sparse (Matrix package documentation: Matrix-class). A sparse matrix prints a dot for each structural zero. The script counts the loans by member and ISBN, takes the products tcrossprod(borrowed) that stay sparse and symmetric ("dsCMatrix"), and converts a corner to a base matrix with as.matrix(). The package is the right tool when the data are large and mostly zero; for the small dense matrices of this page, base R is enough. The package page is Matrix on CRAN.

source("scenario.R")

# Who borrowed which book? Count loans by member and ISBN as a sparse matrix

known <- loans$isbn %in% normalise_isbn(books$isbn)
d <- loans[nzchar(loans$member) & known, ]
who <- factor(d$member)
what <- factor(d$isbn)

borrowed <- Matrix::sparseMatrix(
  i = as.integer(who),
  j = as.integer(what),
  x = 1,
  dimnames = list(levels(who), levels(what))
)
class(borrowed)[[1]]
