Missing and Special Values

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R (the base, stats and utils packages that ship with R), so no add-on package version applies; the lintr 3.4.0 default linters were used only to check the scripts, and the add-on functions that people reach for next (tidyr::drop_na(), tidyr::replace_na(), dplyr::coalesce()) are named in prose only and are not run.

Statistics is the field where R was born, and a statistical language has to answer a question that most languages avoid: what do you store when a value exists in the world but you do not know it? R’s answer is a family of special values. NA is the marker for a value that is not available, NaN is the result of arithmetic that has no sensible answer, Inf and -Inf are the infinities of IEEE 754 arithmetic, and NULL is the absence of an object altogether. They look alike on the console and they are tested in different ways, and most of the errors that beginners meet (missing value where TRUE/FALSE needed, argument is of length zero, a mean that comes out as NA) are one of these four being used as if it were another. This page separates the four, shows the rule by which NA spreads through a computation, lists the tools that remove, count and fill missing values, and ends with the zero-length vectors that NULL has as relatives and the checks that keep a condition from receiving one.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts pass the default lintr linters; where an idiom being shown is exactly what a default linter dislikes (x == NA and x %in% NA) the line carries a # nolint: comment. A script is shown in several consecutive blocks, one per topic, and a later block uses the variables of the earlier ones. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says; a message that contains a line break shows it as \n. The examples use the library scenario of the section: books, loans, shelf_today, loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"). The shelf has real gaps on purpose: books$year has one NA, books$pages has two, loans$loan_date has one (the impossible date 2025-02-30), loans$return_date has seven (the loans still out), and books$isbn has one empty string "" that is not an NA.

Four things that are called "missing"

The manuals keep the four notions apart, and so must you. An Introduction to R introduces NA in the section on missing values: when a value is not available in the statistical sense, a place in the vector is reserved for it with the special value NA; any operation on an NA becomes an NA, because if the specification of an operation is incomplete the result cannot be known; and is.na(x) is the function that finds them (An Introduction to R: Missing values). The R Language Definition adds that this is the statistical sense of "missing" and must not be confused with the missing property of a function argument that was not supplied (The R Language Definition: NA handling); that other meaning is on Functions. NULL has its own subsection in the Language Definition: a special object used whenever it is necessary to indicate that an object is absent, and it should not be confused with a vector or list of zero length (The R Language Definition: NULL).

NA and its typed variants

NA is a reserved word, a logical constant of length 1 that contains a missing-value indicator, and it can be coerced to any other vector type except raw. There are also constants for the other atomic types that support missing values: NA_integer_, NA_real_, NA_complex_ and NA_character_. The help page documents that all five are reserved words in the language (R documentation: NA). The reason there are several is that an atomic vector has one type, so the missing value inside it must have that type too. The Language Definition points out the one case in which the difference matters to a user: the default NA is logical, so a bare NA used as an index triggers logical rather than numeric indexing (see Where missing values come from).

The first block shows the five constants and how a vector keeps its type when an NA joins it: c(1L, NA) is still integer, c("a", NA) is still character, because the logical NA is the lowest type in the coercion order and is promoted to the type of the other elements. The second block is the most common confusion: the character NA is not the string "NA". A vector c("NA", NA) holds a string with two letters and a missing value; is.na() finds only the second, nchar() reports 2 for the first and NA for the second, and printing without quotes shows the missing one as <NA> to tell them apart (the Introduction to R mentions this printing). Real data brings the string case from files: read.csv() treats the text NA as a missing value in every column, including text columns (its na.strings argument defaults to "NA"), which is how the country code of Namibia becomes a missing value; na.strings = character(0) keeps it as text. NaN, Inf and -Inf

NaN ("not a number") and the infinities come from the floating-point arithmetic of the computer, not from R, and R follows IEEE 754 for doubles. Dividing a nonzero double by zero gives Inf or -Inf; log(0) is -Inf; a computation that overflows, such as exp(1000), is Inf; and an operation with no defined result (0/0, Inf - Inf, Inf * 0) is NaN. The Language Definition says that NaN exists only in the double type and in the real or imaginary components of the complex type (The R Language Definition: NA handling). An integer has no way to store either: integer division by zero is NA (5L %/% 0L), while the double 5 %/% 0 is Inf and 5 %% 0 is NaN, as described on Numbers and Arithmetic.

A function called outside its domain returns NaN and says so with the warning NaNs produced, which is the same warning for sqrt(-1) and log(-1). It is a warning because the result is a legitimate NaN, so the computation continues; the script catches it to print its text.

Where missing values come from

A missing value enters a computation from a short list of places, and knowing the list helps to find the one that put it there. Data entry is the obvious source: an empty field in a CSV file becomes NA in numeric, logical and date columns (the year of "Garden of Small Fires", the page counts of the two books with a blank, the unreturned loans), and a text that cannot be parsed becomes NA with a warning. The rest are R’s own rules, and the script below shows them in turn:

  • An index that selects an element that does not exist gives NA for an atomic vector (x[5L], x["z"]) and NULL for a list (lst[["z"]]), while the double-bracket forms on an atomic vector stop with subscript out of bounds. An NA in the index itself gives an NA element (x[c(1L, NA)]), with the names of an atomic vector turning into <NA>.

  • The type of the NA used as an index matters. A bare NA is logical, so y[NA] is a logical index, which is recycled to the length of y and selects every element as unknown: the result is four NA values. y[NA_integer_] is an integer index and selects one element, the result being one NA. The Language Definition points at this case in its NA handling section (The R Language Definition: Indexing by vectors).

  • A logical index that contains NA gives an NA for each NA in the index. In a data frame this means a whole row of NA values with the row name NA: with the two unknown page counts, books[books$pages > 300L, ] has 8 rows although only 6 books have more than 300 pages, and the 4th and 5th rows of the printed excerpt show one of the phantom rows. which() drops the NA values, subset() does so too, and !is.na(big) & big says it explicitly. This is the most common way for missing values to damage a data frame silently.

  • Assignment with an NA index is restricted: z[c(1L, NA)] <- c(0L, 1L) is an error, NAs are not allowed in subscripted assignments, because R cannot know which of the two values goes where; it is allowed with a single replacement value, and the NA positions are skipped.

  • Making a vector longer with length<-, and joins that keep unmatched rows (merge(all = TRUE), merge(all.x = TRUE)), pad with NA.

  • Numbers: integer overflow gives NA with the warning NAs produced by integer overflow, a failed parse with as.integer("seven") gives NA and the warning NAs introduced by coercion, and a conversion outside the integer range gives NA and NAs introduced by coercion to integer range (see Numbers and Arithmetic).

Summaries and na.rm

A summary of a vector that contains an NA is NA, because the sum or the maximum of a set that includes an unknown is unknown. Most summary functions take the argument na.rm, which, when TRUE, removes the missing values (the NA and NaN values) before the computation. sum(books$pages) is NA and sum(books$pages, na.rm = TRUE) is 3755, the sum of the 14 known page counts; the mean is 268.2143 (rounded by the printing), the median 268, the range 88 to 432. na.rm = TRUE answers the question "of the values I know", and it changes the size of the sample behind the statistic, so for a report you also want the count of what was dropped (sum(is.na(x))).

Strings, sorting and tables

Strings have their own missing value, NA_character_, and the string functions disagree on what to do with it. Most keep it (toupper(), substr(), trimws(), nchar() return NA), but paste() and paste0() convert it to the text "NA" (paste("pages:", c(214L, NA)) is "pages: NA"), sprintf() does the same, and format() pads it to the common width. So a result that goes through paste() can no longer be tested with is.na(); test the inputs first. nchar() has a keepNA argument: the default returns NA for the character types (type = "chars" and "bytes") and 2 for type = "width", and keepNA = FALSE always returns 2, the number of characters in the printed NA. nzchar(NA) is TRUE by default, which means that nzchar() is not a missing-value test either: use !is.na(x) && nzchar(x) for "a non-empty string" (nzchar(x, keepNA = TRUE) returns NA for an NA).

Failing coercions produce NA and a warning, and the shape of the warning is the same in all of them: NAs introduced by coercion. That is a signal, not a nuisance, and the way to deal with it is to look at the strings that failed (x[is.na(as.numeric(x)) & !is.na(x)], with the warning suppressed) rather than to suppress the warning on the first line.

Sorting must put the missing values somewhere. sort() removes them by default (na.last = NA) and order() puts them last (na.last = TRUE), so the two do not agree on a vector with an NA: sort(x) has 3 elements and x[order(x)] has 4. Filling and recoding

Removing is not the only option and it is rarely a neutral one: dropping rows changes what the data represent. When a missing value has to be given a value, three tools do the job in base R, and all of them take a logical vector from is.na() to say where. ifelse(is.na(x), fill, x) is vectorised and returns a new vector; replace(x, is.na(x), fill) is the same without the wrapper (replace() is x[list] <- values written as a function); and the assignment x[is.na(x)] <- fill modifies in place. The fill can be a constant or a statistic of the known values (mean(x, na.rm = TRUE), median(x, na.rm = TRUE)). Which one is correct is a statistical question that R cannot answer: filling a page count with zero tells the next function that the book has no pages, and filling with the mean shrinks the variance. tidyr::replace_na() and dplyr::coalesce() do the same job for data frames and are named in prose only (see tidyr, purrr and stringr and The tidyverse and dplyr).

ifelse() returns NA where its test is NA, so a classification such as long or short based on a page count leaves the two unknown books unclassified, and the second form of the example says explicitly what to do with them. The type of the fill matters: replace(books$pages, is.na(books$pages), 0) turns an integer column into a double one, because 0 is a double, and filling the year with "unknown" turns the column into a character vector, and every number in it into a string, which is why the fill value for an integer column is written 0L and why a placeholder text does not belong inside a numeric column.

Base R has no function for "last observation carried forward", the fill that time-series data often needs, but the index trick of the last block does it: seq_along(x) * !is.na(x) is the position where the value is known and 0 where it is not, cummax() carries the last known position forward, and indexing with it repeats the known value. A leading NA gives the index 0, which [ drops, so a vector that starts with an unknown needs a guard. Packages offer ready-made versions of this and of interpolation.

NULL in lists

NULL is not a value that a vector can hold, but a list can hold it as a component, and that creates a trap that has its own entry in the R FAQ. The question is how to set a component of a list to NULL. The answer in R FAQ 7.1 is to use x[i] <- list(NULL), and not to set x[i] or x[[i]] to NULL, because that removes the component from the list (R FAQ 7.1: How can I set components of a list to NULL?). The same entry notes that for dropping the row names of a matrix rownames(x) <- NULL is the easier way. The script runs the experiment on a list with three named components: x[["b"]] <- NULL and x$b <- NULL remove b, so the list has two components; x["b"] <- NULL removes it as well, which is the case the FAQ warns about; and only x["b"] <- list(NULL) leaves a component named b whose value is NULL, so the list still has three components, x$b is NULL, is.null(x$b) is TRUE and "b" %in% names(x) is TRUE.

The null-coalescing operator %||%

Taking a default when something is NULL is so common (an optional argument, an absent list component, a missing option) that R 4.4.0 added an operator for it: L %||% R is the idiom for if (!is.null(L)) L else R (R NEWS: Changes in R 4.4.0; documented with the control-flow operators in R documentation: Control). The right operand is evaluated only when the left one is NULL, like ||. The operator tests for NULL and only for NULL: NA %||% "default" is NA, character(0) %||% "default" is character(0) and list() %||% "default" is list(), because none of them is NULL. For a missing value in a book field, b$genre %||% "unclassified" is NA, while b$notes %||% "no notes" is the default, and the safe test for the field is is.na(b$genre). Code that supports R older than 4.4.0 defines the helper itself (the function fallback() in the script is one possible definition) and loses nothing when it runs on a newer R, though a package that defines its own %||% masks the base one inside its namespace.

Functions on an empty input follow the mathematics of the empty set, and a few of the results are surprising until the rule is seen. sum(integer(0)) is 0 and prod(numeric(0)) is 1, the identity elements of addition and multiplication; any(logical(0)) is FALSE and all(logical(0)) is TRUE (the "vacuous truth", for which no counter-example exists); mean(numeric(0)) is NaN, because it computes 0/0; median(numeric(0)) and var(numeric(0)) are NA. The ones that return empty things return a typed one: nchar(character(0)) is integer(0), toupper(character(0)) is character(0), cumsum(numeric(0)) is numeric(0). Two functions deserve a warning label. sapply() of an empty input returns list() instead of a typed empty vector, because it has no result to simplify, while vapply() returns the empty vector of its template type, so use vapply() whenever the input can be empty (see The apply Family and Functionals); and paste0("pages: ", integer(0)) is "pages: " and not character(0), because a zero-length argument is treated as the empty string, unless recycle0 = TRUE is given, an argument added in R 4.0.1 (R NEWS: Changes in R 4.0.1).

The loop variable of a for over an empty sequence is never set and the body runs zero times, provided that the sequence is a proper empty one: seq_along(NULL) and seq_len(0L) are integer(0), whereas 1:length(x) is 1:0, which counts down to 0 and runs the body twice (see Control Flow).

max() and min() of nothing

max() and min() of an empty vector have no mathematically sensible result, and R returns the identity of the operation, -Inf and Inf, with a warning: no non-missing arguments to max; returning -Inf and no non-missing arguments to min; returning Inf. The same warning appears when every value is NA and na.rm = TRUE removes them all, which is how a filter that matches nothing and a column that is all missing end up in the same message. max(character(0)) returns NA with a different warning, no non-missing arguments, returning NA. range() of an empty vector warns once for the minimum. which.max() and which.min() ignore both cases and return integer(0).

Two defences work. The first is to give max() a floor that is a legitimate answer for the data (max(x, 0), or max(numeric(0), -Inf), which is -Inf without the warning) and the second is to test first and choose the result explicitly, as the safe_max() function of the script does: if x is empty or all missing, return a default, else take the maximum of the known values. Suppressing the warning with suppressWarnings() leaves -Inf in the result, which then propagates as a number and shows up later as an impossible axis or a division by zero.

Guarding a condition

Make the condition always have exactly one answer, and make the choice for the unknown explicit. The tools are few:

  • length(x) == 1L && !is.na(x) && x > 300L spells out the three requirements in order, and relies on && stopping at the first FALSE.

  • isTRUE(x > 300L) is TRUE only when its argument is exactly the single value TRUE; NA, FALSE, logical(0) and a vector of length 2 all give FALSE. isFALSE() is its counterpart, true only for the single FALSE. Both are in the help page of the logical operators, and they are the shortest way to fold "unknown" into one of the branches. The price is that a typo in the column name also folds into FALSE silently, so use them where unknown really means no.

  • if (length(x)) tests that a vector is not empty, using the rule that 0 is FALSE and any other number is TRUE; if (length(x) > 0L) says the same more plainly.

  • any(x, na.rm = TRUE) and all(x, na.rm = TRUE) reduce a vector to one answer, with na.rm = TRUE deciding to ignore the unknowns. For an empty vector any() is FALSE and all() is TRUE, so all(x > 0) on an empty filter is true: check length(x) first when "all of nothing" is not a sensible answer, as the vacuous line shows.

  • nzchar(x) is not a test for a missing string (it is TRUE for NA by default), so use !is.na(x) && nzchar(x).

stopifnot() is the tool for conditions that must hold. It treats NA as a failure: stopifnot(books$pages > 0L) stops with books$pages > 0L are not all TRUE because of the two unknown page counts, and stopifnot(NA) says NA is not TRUE. An empty logical vector passes (stopifnot(logical(0)) is silent), as it is "all TRUE". A named argument supplies the message, as in stopifnot("pages must be known" = !anyNA(books$pages)), which is the form to use for input checks (see Defensive Programming and Input Validation and Conditions and Error Handling).

identical(), switch() and sizes

identical() and NA

identical() compares two objects for exact equality, including their types, and returns a single TRUE or FALSE that is never NA. That makes it the safe comparison for NA and NULL, but the exactness catches people: identical(NA, NA_integer_) is FALSE because the types differ, identical(NA_real_, NaN) is FALSE, identical(NULL, character(0)) is FALSE, and identical(books$year[7L], NA) is FALSE, because the year is an integer NA and the constant is a logical one. The comparison with the right type, identical(books$year[7L], NA_integer_), is TRUE, and is.na() avoids the question of type altogether. The second pitfall is the vector: identical(x, NA) for x <- c(NA, NA) is FALSE because the lengths differ, so it is not a test for "all missing"; use all(is.na(x)). The same exactness applies to isTRUE(all.equal(...)) on NULL against character(0).

switch() and NA

switch() selects by a string or by a number, and its help page does not describe what it does with a missing value, so the next block reports what R 4.6.1 does rather than a documented guarantee. With a string, an NA_character_ is not an error: it takes the default alternative, and if an alternative is named NA (written "NA" = ...) it matches that one. With a number, an integer or logical NA, or a number outside the range, returns an invisible NULL. With a NULL, a zero-length vector or a vector of length two or more, it stops with EXPR must be a length 1 vector. So a switch() on data that may be missing needs an explicit if (is.na(x)) before it, and one that returns a value should always have a default alternative. See Control Flow for switch() in general.

NROW, NCOL and lengths

nrow() and ncol() return NULL for anything that is not a matrix or data frame, which is awkward when the object may be a plain vector or NULL. NROW() and NCOL() treat a vector as a one-column matrix: NROW(1:3) is 3 and NCOL(1:3) is 1, NROW(character(0)) is 0, and a data frame with no rows gives 0. R 4.4.0 made NCOL(NULL) return 0 instead of 1, consistently with cbind(), while NROW(NULL) was already 0 (R NEWS: Changes in R 4.4.0); code written for older versions that counted columns of a possible NULL should be checked. seq_len(NROW(x)) is a safe loop sequence for a vector, a matrix or a data frame that may be empty.

length() of a list(NULL) is 1, since the list holds one component that happens to be NULL, while length(NULL) and length(list()) are 0. lengths() gives the lengths of the components of a list at once, and is the quick way to find the empty ones. is.na() on a list is true only for the components that are single missing values (the help page: a length-one atomic vector whose element is NA or NaN), so is.na(list(1, NA, NULL, c(NA, 2), "a")) is FALSE TRUE FALSE FALSE FALSE. anyNA() gives the same for a list unless recursive = TRUE, which looks inside the components: anyNA(list(1, c(2, NA))) is FALSE and anyNA(list(1, c(2, NA)), recursive = TRUE) is TRUE. anyNA(NULL) is FALSE and is.na(NULL) is logical(0); R 3.1.0 introduced anyNA() as a fast version of any(is.na(x)), and is.na(NULL) stopped warning in 3.4.4 (R NEWS (R 3.x): Changes in R 3.1.0 and 3.4.4).
