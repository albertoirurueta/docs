Atomic Vectors and Types

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. This page is about the one data structure that everything else in R is made of: the vector. It starts with the six atomic types and the four functions that report what a value is (typeof(), mode(), storage.mode() and class()), goes through the is.*() tests and the as.*() conversions with the exact warning texts they produce, explains the coercion hierarchy that decides the type of c(), shows every way of creating a vector (c(), vector() and its typed shortcuts, the colon operator, seq(), seq_len(), seq_along() and rep()), and then covers recycling, length(x) <- n, zero-length vectors, raw, character and complex vectors, the way attributes turn a vector into a matrix, a factor, a date or a data frame, the change of is.atomic(NULL) in R 4.4.0, and long vectors. Everything on this page is base R, so no add-on package version applies; the lintr 3.4.0 default linters were used only to check the scripts.

Every example below is a complete script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The vector family at a glance

A programmer coming from C, Java or Python looks for a scalar type and does not find one. The R language definition says it plainly: single numbers such as 4.2 and strings such as "four point two" are still vectors of length one, there are no more basic types, and vectors of length zero are possible and useful (The R Language Definition: Vectors). The manual calls a vector made of one of the six basic types an atomic vector, and a second kind of vector, the list (a "generic vector"), can hold elements of any type, including other lists. A list is therefore called recursive, and the atomic types are called atomic where it is necessary to exclude lists (The R Language Definition: Lists). Everything that looks like a richer data structure (a matrix, a factor, a date, a data frame) is one of these two kinds of vector with attributes attached, which the figure summarises.

The six atomic types

The language definition names the six basic vector types as logical, integer, real, complex, character and raw. The word "real" is the old name of what typeof() now calls "double": the name of the type is double, while numeric is the name of the mode and of the implicit class. The help page of numeric calls this a historical anomaly and explains the consequence that matters in practice: is.numeric() tests the mode, so it is true for integers and doubles alike, but as.numeric() is identical to as.double() and always produces a double (R documentation: numeric).

Literals and what the parser makes of them

A number written in a script is a double unless it carries the suffix L, which asks for an integer. The suffix works on decimal, hexadecimal and exponent forms. The raw string r"(...)" was added in R 4.0.0 (R NEWS: Changes in R 4.0.0) and is a character constant like any other. The syntax of numeric and string constants in general is in Syntax and Lexical Structure.

Single values are vectors, and empty vectors have a type

Because there is no scalar, length(1.5) is 1 and a string is one element of a character vector, whatever its number of characters. nchar() counts characters; length() counts elements. A vector can have length zero and still have a type: character(0) and numeric(0) are different objects, and the type is what lets sum(numeric(0)) return 0 (the identity of addition) instead of failing. The next section looks at the types with four different functions.

typeof(), mode(), storage.mode() and class()

R has four functions that answer "what is this value?", and they answer different questions. They agree for most atomic vectors, which is why many tutorials treat them as synonyms, and they disagree in exactly the cases that matter.

Function What it reports

typeof(x)

The internal storage type of the object: what the interpreter and C code see. For atomic vectors it is one of "logical", "integer", "double", "complex", "character", "raw"; for other objects it includes "list", "NULL", "closure", "special", "builtin", "environment", "symbol", "language" and a few that are rarely seen at user level.

mode(x)

A coarser classification inherited from the S language: integers and doubles are both "numeric", the three function types are "function", the type "symbol" is called "name" and "language" is "call" (or "(").

storage.mode(x)

Like typeof() for data, except that every function type is reported as "function". It is what storage.mode(x) <- value changes.

class(x)

The class used by S3 dispatch and by print(): the class attribute when there is one, otherwise an implicit class derived from the type and the dimensions ("matrix" and "array" for objects with dim, "integer", "numeric", "function", …​).

The length of class(x) is not always one. R 4.0.0 made every matrix inherit from the class "array", so class(matrix(1:6, nrow = 2)) is c("matrix", "array"), and NEWS said at the time that this invalidates code that wrongly assumes class(matrix_obj) has length one (R NEWS: Changes in R 4.0.0). A comparison such as class(m) == "matrix" then returns a vector of length two, and as the condition of an if() it is an error since R 4.2.0. Write inherits(m, "matrix") or is.matrix(m) instead; both give a single TRUE or FALSE. How dispatch uses the class is the subject of S3 Classes and Generics.

The implicit class

An object without a class attribute still has a class, computed from the type and the dimensions, and S3 dispatch uses a longer implicit class than class() prints: for an integer it is "integer" then "numeric", for a double "double" then "numeric", and for a matrix "matrix", "array" and then the type’s classes. The internal helper .class2() shows the dispatch vector. The practical consequence is that a method written for "numeric" is found for both integers and doubles, and that inherits(1L, "numeric") is FALSE although is.numeric(1L) is TRUE: inherits() looks at class(), is.numeric() at the mode.

# class() reports one thing; dispatch uses the implicit class, which is longer.
class(1L)
#> [1] "integer"
class(1)
#> [1] "numeric"
.class2(1L)
#> [1] "integer" "numeric"

is.numeric() on integers, doubles and factors

is.numeric() is true for integers and doubles because it tests the mode and not the type, but it is false for a factor, although a factor is an integer vector underneath and its mode() is "numeric". The help page explains that is.numeric() is an internal generic function: the default method returns true when the mode is numeric and the object is not a factor, and R ships methods for "Date", "POSIXt", "difftime" and "complex" that all return false, because arithmetic on a date is not arithmetic on a number. The rule for authors of new classes is that a method should return true only if the base type is double or integer and the values can reasonably be regarded as numbers. The consequence for code is that is.numeric(x) is the right check for "can I do arithmetic on this?", and is.double(x) or typeof(x) == "double" is the right check for "is this stored as a double?". Likewise is.integer(x) tests the type, not whether the values are whole numbers: is.integer(5) is FALSE, and the help page of integer points to a tolerance-based is.wholenumber() for the other question.

Converting: the as.* family

Every type test has a converter: as.logical(), as.integer(), as.numeric() (which is as.double()), as.complex(), as.character() and as.raw(). The manual for beginners introduces them with the same idea: R changes the mode almost anywhere it could be considered sensible to do so, and a large collection of as.something() functions performs the coercion from one mode to another (An Introduction to R: Intrinsic attributes: mode and length). Two rules hold for all of them. First, a conversion that fails does not stop the program: it returns NA for the element that could not be converted, and for most failures it also signals a warning. Second, as.integer(), as.numeric() and the other converters strip all attributes, names included; to keep the attributes use storage.mode<- (see the previous section).

as.integer() truncates, it does not round

Converting a double to an integer drops the fractional part towards zero, so as.integer(3.9) is 3L and as.integer(-3.9) is -3L. The help page of integer says that non-integral values are truncated towards zero (as.integer(x) equals trunc(x) there) and that real values larger in modulus than the largest integer become NA, unlike the S language, which returned the most extreme integer of the same sign. A string is read first as a number and then truncated, so as.integer("3.9") is also 3L. Logical values map to 1 and 0, and NA stays NA. If you want rounding, call round(), ceiling() or floor() first, as the next script shows beside the truncated results.

The strings that as.numeric() accepts

A character string is converted if it consists of optional white space around either a decimal number or a hexadecimal number starting with 0x or 0X (the help page of integer adds "as well as any allowed by the platform for real numbers", which is why "inf", "Inf" and "NaN" work). An exponent is fine ("1e3"), a sign is fine ("+5" and "-.5"), and the empty string gives NA without a warning. Everything else gives NA with the warning NAs introduced by coercion: a decimal comma, a unit, a thousands separator, a word, and also the text "NA" itself, which is a four-character string and not a missing value. A genuine NA_character_ converts to NA silently. When a real data file is read with read.csv() or read.table() the readers use their na.strings argument for the literal "NA"; the converters do not.

The warning NAs introduced by coercion

The warning has exactly one text for strings that are not numbers, NAs introduced by coercion, and a second text when the number is valid but does not fit in an integer: NAs introduced by coercion to integer range. Both are warnings, not errors, so a script that ignores them carries on with NA values and a message at the end. Both are also real signals: the first means that some text was not a number, the second means that the value was a number and was too large for 32 bits. The shelf data has both cases at hand. as.logical() and the strings it knows

The coercion hierarchy

R combines values of different types by promoting them to the highest type involved. The help page of c() gives the order: NULL < raw < logical < integer < double < complex < character < list < expression (R documentation: c). The first types are the narrowest: a raw byte can become a logical, a logical a 0 or 1 integer, an integer an exact double, and a double a complex number with a zero imaginary part. Character is the catch-all for atomic data, because everything has a text form; the list is the only type that can hold anything, which is why c(1, list("a")) is a list. Nothing in the order goes down: to go from character to numeric you have to call as.numeric() yourself, and it may fail.

The next script builds the whole table by applying c() to every pair of types, then shows concrete results. Implicit and explicit coercion

Coercion is implicit when R does it for you and explicit when you call an as.*() function. Implicit coercion happens in four places that you meet all the time.

  • c(), unlist() and vector subassignment (x[i] <- value) promote to the highest type, as in the table above.

  • Arithmetic coerces logicals to integers, and integers to doubles when the other operand is a double. TRUE + TRUE is the integer 2L; 5L / 2L is a double because division always returns one; 5L %/% 2L stays an integer.

  • Comparison coerces to the highest type, and a string wins: 1 == "1" is TRUE, and "10" < 9 compares the strings "10" and "9" and is TRUE because "1" sorts before "9". This is the usual reason a column that was read as text sorts and compares in a surprising order.

  • A condition in if() or while() is coerced to a single logical; the string "TRUE" and any non-zero number are accepted, anything else is an error such as argument is not interpretable as logical (see Control Flow).

# Logical values take part in arithmetic as 0 and 1.
TRUE + TRUE
#> [1] 2
typeof(TRUE + TRUE)
#> [1] "integer"
sum(c(TRUE, FALSE, TRUE, TRUE))
#> [1] 3
mean(c(TRUE, FALSE, TRUE, TRUE))
#> [1] 0.75

# Integer arithmetic stays integer, except for division and powers.
typeof(5L + 2L)
#> [1] "integer"
typeof(5L * 2L)
#> [1] "integer"
typeof(5L / 2L)
#> [1] "double"
typeof(5L %/% 2L)
#> [1] "integer"
typeof(5L^2L)
#> [1] "double"
typeof(5L + 2)
#> [1] "double"

# Comparisons coerce to the common type, and a string wins.
1 == "1"
#> [1] TRUE
TRUE == "TRUE"
#> [1] TRUE
"10" < 9
#> [1] TRUE
"10" < "9"
#> [1] TRUE

# Arithmetic does not do that; it refuses text.

#> [1] "non-numeric argument to binary operator"

#> [1] "string TRUE is accepted"

#> [1] "argument is not interpretable as logical"
tryCatch(if (NA) 1, error = \(e) conditionMessage(e))

Arithmetic is stricter than comparison: "1" + 1 is the error non-numeric argument to binary operator, because arithmetic does not coerce text. R chooses the implicit rules to be permissive where the result is unambiguous and to fail where it would have to guess.

Implicit coercion is also the reason a subassignment can silently change the type of a whole vector. Storing a double in an integer vector turns the vector into a double, and storing a string turns it into a character vector, with every other element converted by its text form. A column that has been polluted by one bad value becomes character without any message. Creating vectors

There are six everyday ways to make a vector: c() joins values, vector() and the typed constructors make a vector of a given length, the colon operator and seq() generate arithmetic sequences, rep() repeats values, and the readers and the apply family produce vectors from data and from functions. The first five are covered here.

c(): combining values and names

c() is short for "combine". Its arguments are coerced to a common type by the hierarchy above, nested vectors are flattened, NULL arguments disappear, and c() with no arguments returns NULL. All attributes except names are removed. Names given as name = value arguments become the names attribute, and an element without a name gets the empty string; when the value of a named argument is itself a vector, the result gets a prefix (c(x = c(a = 1, b = 2)) has names x.a and x.b, and an unnamed vector of length two gives x1 and x2). Two argument names are reserved by c() itself: recursive and use.names. A call such as c(recursive = 1, value = 2) does not create an element called recursive; it sets the argument, which is easy to hit by accident when a value is called recursive or use.names in the data. The vector of values should then be built with setNames() or names<- instead.

The colon operator

from:to creates a sequence of integers when from is a whole number, in steps of one, and counts down when to is smaller than from. If from is not whole (1.5:4), the result is a double sequence 1.5, 2.5, 3.5. The colon binds tighter than the arithmetic operators and looser than ^ and unary minus, so 1:n - 1 is (1:n) - 1, -1:3 is (-1):3, and 2:3^2 is 2:(3^2). The precedence table is in Operators and Precedence.

The colon has one famous trap: 1:0 is not empty, it is the sequence 1, 0. Code that writes for (i in 1:length(x)) runs the loop body twice for an empty x, with i equal to 1 and then 0, and indexing with those values gives surprising results. The fix is seq_along(x), which is empty for an empty vector, or seq_len(n) when the count is a number. lintr flags the first form (the seq_linter), which is why the script marks the deliberate uses with # nolint: seq_linter.. The colon also needs a non-missing number: 1:NA is the error NA/NaN argument, and a vector of length greater than one on either side gives a warning that only the first element is used (numerical expression has 2 elements: only the first used).

seq(), seq_len() and seq_along()

seq() is the general sequence generator and has several forms, selected by which arguments are given. seq(from, to, by) steps by a fixed amount (a negative by with from greater than to counts down, and the wrong sign is the error wrong sign in 'by' argument), seq(from, to, length.out = n) spreads n points evenly, and seq(from, by = b, length.out = n) or seq(to = t, by = b, length.out = n) build the sequence from one end. With one argument, seq(n) is 1:n and seq(v) is seq_along(v), which is the reason seq(x) is not safe when x might be a single number: seq(c(10, 20, 30)) is 1:3 but seq(5) is 1:5. The help page recommends seq_len() and seq_along() for loops: seq_len(n) is 1:n for positive n and empty for zero, an error for a negative n, and seq_along(x) is seq_len(length(x)); both return integers (or doubles for a long vector) and are primitive and fast. seq.int() is the faster internal version for the same arguments.

The type of the result follows the arguments: seq(1, 10) is an integer sequence, like 1:10, seq(1, 10, by = 3) is a double sequence because by is a double (even though all the values are whole), seq(1L, 10L, by = 3L) is an integer sequence, and anything with a fractional step is a double. A double sequence with a decimal step accumulates floating-point error, so compare its elements with a tolerance (see Numbers and Arithmetic).

rep() and rep_len()

rep(x, times, each, length.out) repeats a vector. times repeats the whole vector (a single number) or each element a different number of times (a vector of the length of x), each repeats each element in turn, and length.out cuts or recycles the result to an exact length; when each is combined with another argument the each replication happens first, and when length.out and times are both given length.out wins. rep_len(x, n) and rep.int(x, times) are faster, less flexible versions. rep() keeps the names of its input, while rep_len() and rep.int() drop them. A negative or NA count is an error (invalid 'times' argument), and so is a vector of counts of the wrong length. The most common use is to preallocate a typed vector filled with NA (rep(NA_character_, n)), because NA alone is logical and would set the type of a column to logical.

Recycling and vectorised arithmetic

The arithmetic, comparison and logical operators and most mathematical functions work on whole vectors, element by element, without a loop; this is what "vectorised" means in R. When the operands have different lengths the shorter one is recycled: the language definition says that if the longer length is not a multiple of the shorter one a warning is given, and that any arithmetic operation involving a zero-length vector has a zero-length result (The R Language Definition: Recycling rules). The warning text is longer object length is not a multiple of shorter object length, and it belongs to the arithmetic, comparison and logical operators alike.

Recycling is what makes x * 2 and x - mean(x) work, so it is a feature; the problem is that the exact-multiple case is silent. Comparing a length-16 column with a vector of length two repeats the vector eight times without any message, which is almost never what was meant, and the script shows the intended %in% next to it. Other functions have their own messages for the same situation: assigning a replacement that does not fit gives number of items to replace is not a multiple of replacement length, matrix() complains that the data length is not a multiple of the number of rows, and data.frame() refuses columns of different lengths with an error (arguments imply differing number of rows: 3, 2) because a data frame does not recycle by default, except where the lengths are an exact multiple.

Changing the length of a vector

length(x) returns the number of elements, and the replacement form length(x) <- n changes it: shortening discards the extra elements, and lengthening pads at the end. The padding is NA for logical, integer, double, complex and character vectors, a zero byte for raw vectors, and NULL for lists and expression vectors, the same values that vector(mode, n) creates, as the help page says. The replacement removes all attributes except names, which are adjusted and extended by empty strings (""); a matrix loses its dim and becomes a plain vector. The introduction manual shows the same pair of operations, adding elements by assigning to an index beyond the end (e[3] <- 17 on an empty vector) and truncating with length(alpha) <- 3 (An Introduction to R: Changing the length of an object).

length<- rejects a negative or NA value with the error invalid value. It cannot lengthen NULL, which stays NULL with the warning length of NULL cannot be changed, so a variable that starts as NULL has to be created as vector("list", 0) or character(0) first. Reading past the end with [[ is an error (subscript out of bounds), while assigning past the end with [<- or [[<- quietly extends the vector with NA between the old end and the new element. head() and tail() from the utils package are the non-destructive way to take the first or last elements, and append() inserts values at a position without changing the original.

Zero-length vectors and preallocation

A zero-length vector is a normal value, and it is what most functions return when there is nothing to return: integer(0) from grep() or which() with no match, character(0) from grep(value = TRUE), numeric(0) from a subset that selects nothing. Its type is kept. Arithmetic with it gives a zero-length result (the language definition’s rule, shown in the recycling script), the summary functions have defined values for it (sum(numeric(0)) is 0, prod(numeric(0)) is 1, while max(numeric(0)) is -Inf with the warning no non-missing arguments to max; returning -Inf), and a loop over seq_along() of it does not run at all. The things that go wrong are 1:length(x) (see the colon operator) and conditions such as if (x == 1), where a zero-length x makes the condition logical(0) and the error is argument is of length zero, a topic of Missing and Special Values and Control Flow.

The same constructors that make empty vectors make the containers that loops fill. Growing a vector one element at a time with x[length(x) + 1] <- value or c(x, value) works, but each step may allocate a new vector, and the type of the vector can change halfway; creating integer(n), character(n) or vector("list", n) once and assigning into it by index states the type and the length up front. When each result is a single value, vapply() does both in one call: its third argument, FUN.VALUE, is a template of the type and length each call must return, and a mismatch is an error with a clear message instead of a silent change of type. sapply() guesses, so it returns a list for empty input and an inconsistent shape whenever the results differ in length, which is why the recommended form in code that other people run is vapply() (the apply family is covered in The apply Family and Functionals).

source("scenario.R")

# Preallocate a result of the right type and length, then fill it.
title_chars <- integer(nrow(books))
for (i in seq_along(books$title)) {
  title_chars[i] <- nchar(trimws(books$title[i]))
}
title_chars
#>  [1] 16 19 17 10 15 13 21 16 15 14 11 16 13 14 11 15

# vapply() states the type and length of every result and checks them.
vapply(books$title, \(t) nchar(trimws(t)), integer(1L), USE.NAMES = FALSE)
#>  [1] 16 19 17 10 15 13 21 16 15 14 11 16 13 14 11 15
vapply(books$pages, \(p) p > 300L, logical(1L))[1:6]
#> [1]  TRUE  TRUE FALSE FALSE  TRUE    NA

# A wrong promise is an error, not a silent change of type.
tryCatch(
  vapply(1:3, \(i) "a", numeric(1L)),
  error = \(e) conditionMessage(e)
)
#> [1] "values must be type 'double',\n but FUN(X[[1]]) result is type 'character'"
tryCatch(
  vapply(1:3, \(i) c(i, i), numeric(1L)),
  error = \(e) conditionMessage(e)
)
#> [1] "values must be length 1,\n but FUN(X[[1]]) result is length 2"

# On empty input vapply() still returns the promised type; sapply() cannot.
vapply(character(0), nchar, integer(1L))
#> named integer(0)
sapply(character(0), nchar)
#> named list()

#> integer(0)

Raw, character and complex vectors

Three of the types need a few more words.

Raw vectors

A raw vector holds bytes, each printed as two hexadecimal digits, and is the type that binary data, hashes and byte-level text work with. as.raw() converts numbers 0 to 255; a value outside the range becomes a zero byte with the warning out-of-range values treated as 0 in coercion to raw. There is no missing byte, so no NA exists for raw, and a raw vector lengthened with length<- is padded with zero bytes. charToRaw() shows the bytes of a string in its encoding: "A" is the single byte 41, and "é" is the two bytes c3 a9 in UTF-8, so nchar("é") is 1 and nchar("é", type = "bytes") is 2 (the Encodings, Locales and Internationalization page continues with this). rawToChar() goes back, utf8ToInt() and intToUtf8() convert between characters and Unicode code points, and rawToBits() and packBits() convert between bytes and their bits. The logical operators &, |, ! and xor() are bitwise on raw vectors, rawShift() shifts bits, and arithmetic such as + is not defined and gives non-numeric argument to binary operator.

Character vectors

A character vector is a vector of strings. A string is one element, however many characters it has, so length() counts the strings and nchar() counts the characters; the number of characters of a missing string is NA_integer_, not zero. Strings can be written with double or single quotes, with backslash escapes, and, since R 4.0.0, as raw strings r"(...)" in which backslashes mean nothing (R documentation: Quotes). A comparison that involves NA_character_ gives NA, not FALSE; NA_character_ == "one" is a comparison with a missing value and is.na() is the test. Everything about searching, splitting and replacing is in Strings and Regular Expressions.

Complex vectors

Complex numbers are the sixth type and the least used. complex(real = 3, imaginary = 4) builds 3+4i, and Re(), Im(), Mod(), Arg() and Conj() take it apart. sqrt(-1) is NaN with the warning NaNs produced, because the real square root of a negative number is not defined; sqrt(as.complex(-1)) is 0+1i. Converting a complex vector to a real type discards the imaginary part with the warning imaginary parts discarded in coercion. Complex arithmetic is part of Numbers and Arithmetic.

Lists, attributes and the rest of the family

A list is the other kind of vector. It has a length, it is created by list() or vector("list", n), and typeof() reports "list"; is.vector() is true for it, is.atomic() is false, is.recursive() is true. c() combines lists and atomic vectors into a list when any argument is a list, and unlist() flattens a list by the same coercion ranking, so a list of an integer, a double and a logical becomes a double vector, and one that contains a string becomes a character vector. lengths() returns the length of each element at once, which is the fast replacement for sapply(x, length). The container itself and its operations are in Lists.

Long vectors

Vectors in R 2.x were limited to 2^31 - 1 (about two billion) elements, because the length was stored in a C int. R 3.0.0 added support for longer vectors on 64-bit platforms, a feature described in the "Long vectors" section of the R internals manual and in the 3.0.0 NEWS (R Internals: Long vectors and R NEWS: Changes in R 3.0.0). The support covers raw, logical, integer, double, complex and character vectors and lists; the elements of character vectors (single strings) are still limited to 2^31 - 1 bytes. The length is recorded as a 64-bit value. In theory lengths could have 63 bits, but there is currently a 52-bit limit, which exceeds what current operating systems offer and ensures that a length can be stored exactly in a double.

Four practical consequences follow.

  • length() returns an integer for ordinary vectors and a double when the length exceeds .Machine$integer.max, which is 2147483647. Code that calls as.integer(length(x)) before passing it to C or Fortran has to check for the NA result.

  • A single long vector of 2^31 or more elements takes at least 8 GB when it is integer or logical and 16 GB when it is double or character, so you will meet them on large machines only. The length argument of vector() has to be a double for such sizes, and a request that is too large is an error: vector size specified is too large beyond the theoretical limit, or cannot allocate vector of size ... when the memory is simply not there.

  • Indexing is done with doubles: a double index above 2^31 - 1 reaches elements that no integer could address, and seq_len() and seq_along() return doubles when the vector is long. Most functions work with long vectors. The 3.0.0 NEWS said that some others report long vectors not supported yet, mostly because they work with integer indices, and named anyDuplicated() and match() as examples; later releases lifted several of these limits (R 3.6.0, for example, made match(x, table) work for a long character x), so check the NEWS of your version rather than older advice.

  • Arithmetic sequences created by 1:n, seq_along() and the like have used a compact representation since R 3.5.0 (the ALTREP framework), which defers the expansion: 1:3e9 is a long vector that occupies almost no memory until a function touches every element. That makes it a safe way to demonstrate the type and length rules without allocating 24 GB. In R 4.6.1 object.size() reports the size the expanded vector would need, not the memory in use, so do not read it as a measurement for such a sequence.

# The largest integer, and so the largest value length() returns as integer.

#> [1] 2147483647
2^31 - 1
#> [1] 2147483647
typeof(length(1:10))
#> [1] "integer"

# A compact sequence is a long vector that costs almost no memory.
x <- 1:3e9
length(x)
#> [1] 3e+09

#> [1] "double"
length(x) > .Machine$integer.max
#> [1] TRUE
typeof(x)
#> [1] "double"

#> [1] 3e+09

#> [1] TRUE

# Code that needs an integer length has to check for the overflow.

#> [1] "NAs introduced by coercion to integer range"

# lengths() on a list gives the integer length of every element.
lengths(list(1:3, letters, character(0)))
#> [1]  3 26  0

# Asking for more than the machine can ever hold is an error.
tryCatch(numeric(2^53), error = \(e) conditionMessage(e))
#> [1] "vector size specified is too large"

The numeric side of this limit, integer overflow to NA with the warning NAs produced by integer overflow, is in Numbers and Arithmetic, and memory and copying for large objects are in Memory and Copy Semantics.

Pitfalls

  • Treating a warning as noise. NAs introduced by coercion is the only sign that text was not a number. Convert, count the new NA values, and look at the offending strings.

  • 1:length(x) and 1:0. An empty vector turns the loop into two iterations. Use seq_along() and seq_len().

  • as.numeric() on a factor. The result is the codes (R FAQ 7.10: How do I convert factors to numeric?). Go through as.character() or the levels.

  • is.numeric() is not is.double(). It is true for integers and false for factors and dates.

  • class(x) == "matrix". Since R 4.0.0 the class of a matrix has length two. Use inherits() or is.matrix().

  • Silent recycling. A comparison with a vector whose length divides the length of the other one is recycled without a word; %in% is usually what was meant.

  • A named argument that c() keeps for itself. recursive and use.names are arguments, not names.

  • Mixed types in one column. One string turns a numeric vector into a character vector, and a double turns an integer vector into a double. Check typeof() after reading data and after assigning into a vector.

  • length(x) <- n on NULL. It does nothing and warns; create the right empty vector first.

  • as.integer(length(x)) for a long vector. The result is NA above 2147483647.

  • is.atomic(NULL) in old code. It was TRUE before R 4.4.0; code that relied on it needs is.null(x) || is.atomic(x).

  • Using T and F. They are ordinary variables that can be reassigned (R FAQ 3.3.3); write TRUE and FALSE.
