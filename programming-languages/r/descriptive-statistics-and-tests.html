Descriptive Statistics and Tests

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Almost everything on this page is base R (the base, stats, utils and datasets packages that ship with R), and every example runs. One add-on package is used, in a single example: broom 1.0.13, to turn the result of a test into a one-row data frame. The lintr 3.4.0 default linters were used only to check the scripts. Describing a sample and testing a statement about it are the first things almost every analysis does. R has a function for each step: mean(), median(), quantile() and summary() describe a vector, table() and xtabs() count, cor() measures association, aggregate() and tapply() do the same by group, and the classical tests (t.test(), wilcox.test(), chisq.test() and a dozen more) all return the same kind of object, an "htest", that prints in one familiar layout and can be taken apart like any list. This page walks through them in that order: the summaries first, then counts and correlations, then the "htest" object, then each test with its assumptions, its real output and the warnings it raises, then the correction for many tests, p.adjust(), and last the limits of what a p-value can tell you.

Every example is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines that start with #> are what it printed. The scripts also pass the default lintr linters. The names books, loans, shelf_today, loan_days and the book() constructor come from the running library-shelf scenario described on the section index: a script that needs them starts with source("scenario.R"). The scenario data are synthetic and small, 16 books and 60 loans, so the numbers below show how the functions behave and not what libraries are like. Two other kinds of data are used where the shelf has too little to say: the datasets penguins (added to the datasets package in R 4.5.0), airquality and sleep, which are always available without loading anything. Scripts that draw random numbers call set.seed() first, so that their output can be reproduced; the random-number generators themselves are the subject of Distributions and Random Numbers. Where a message contains quotation marks, they are the typographic quotes R prints in a UTF-8 locale. Test results print with a tab before the title of the test (Welch Two Sample t-test and so on); that tab is part of the real output and is kept below.

The page leans on four neighbours. The data frames the examples summarise are described in Data Frames, the factors that table() and summary() count in Factors, the missing values that decide so many results in Missing and Special Values, and the formula y ~ x that the test functions accept in Formulas. Fitting models, which is what most of statistics becomes after the first descriptive pass, is in Statistical Models, and drawing the histograms and box plots that go with these numbers is in Base Graphics and Devices.

The data used on this page

Most examples need the length of a loan and the size of the book that was borrowed, so the first script builds one data frame with a row per loan. It tidies the genre labels as the Formulas page does, counts the days of each loan (a loan that is still out counts up to shelf_today), marks a loan as overdue when it lasted more than loan_days (21) days, and joins the books to the loans by ISBN. Two loans cannot be used: one has an impossible loan date, which is NA, and one was returned before it was taken out, whose negative length is replaced by NA because a negative number of days is an error and not a short loan. One loan has an ISBN that matches no book and drops out of the join. That leaves 59 loans of 15 different books; the 16th book, "Rivers of Glass", has an empty ISBN and so can match no loan. Every later script that needs these objects repeats the same lines at its top, so that each script runs alone.

source("scenario.R")

# The 16 books: tidy the genre labels, as the formulas page does.
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)

# Days a loan lasted; a loan still out counts up to shelf_today.
back <- loans$return_date
back[is.na(back)] <- shelf_today
loans$days <- as.integer(back - loans$loan_date)
loans$days[loans$days < 0L] <- NA # a return before the loan: impossible
loans$overdue <- loans$days > loan_days

# One row per loan, with the book's pages, year and genre attached.
loan_books <- merge(loans, books, by = "isbn")

Means, medians and spread

The mean, trimming and missing values

mean() is the generic function for the arithmetic mean, and its default method has the signature mean(x, trim = 0, na.rm = FALSE, ...). With trim between 0 and 0.5 it drops that fraction of the observations from each end of the sorted data before averaging, so trim = 0.5 is the median; a value outside that range is taken as the nearest endpoint. The mean of a logical vector is the proportion of TRUE, which is the cheapest way to compute a rate, and the mean of dates is a date (see Dates and Times).

source("scenario.R")
pages <- books$pages
pages
#>  [1] 387 432 214 198 301  NA  96 280 352 256  88 410 175 322  NA 244
mean(pages)
#> [1] NA
mean(pages, na.rm = TRUE)
#> [1] 268.2143

# trim drops that fraction of the observations from each end before averaging.
p <- sort(pages, na.last = NA) # na.last = NA removes the NAs
length(p)
#> [1] 14
mean(p, trim = 0.1)
#> [1] 269.5833
mean(p[-c(1, length(p))]) # the same: one value removed from each end
#> [1] 269.5833
mean(p, trim = 0.5) == median(p)
#> [1] TRUE

# A logical vector is a 0/1 vector: its mean is a proportion.
mean(books$year > 2010, na.rm = TRUE)
#> [1] 0.6666667

# Dates and difftimes have means too (see the Dates and Times page).
mean(loans$loan_date, na.rm = TRUE)
#> [1] "2025-09-20"

Source: R documentation: mean

The first call returns NA, and that is the default on purpose. The mean of the 14 known page counts is 268.2 and their 10 percent trimmed mean is 269.6, but two books have no page count, and the two unknown values make the average of all 16 unknown too. na.rm = TRUE is a decision to answer a different question, the mean of the books for which the number is known, and it should be a visible one. The next section comes back to why the default is FALSE.

When the input is not a number

mean() of something that is not numeric or logical does not stop with an error. Its help page says that NA_real_ is returned, with a warning. The usual cause is a column that was read as text, so the first cure is to look at class() and str() of the column, and the second is to convert with as.numeric() and look at the values that did not convert. The other summaries are stricter or differ: var() coerces and warns, sd() of a factor is an error, and median() of a character vector sorts it and picks the middle string without complaint, which is rarely what was wanted.

# A tiny helper: the text of the first warning or error an expression raises.
message_of <- \(expr) {
  tryCatch(
    {
      expr
      "no condition"
    },
    warning = \(w) paste("warning:", conditionMessage(w)),
    error = \(e) paste("error:", conditionMessage(e))
  )
}

# mean() of something that is not numeric: a warning and NA, not an error.
message_of(mean("a"))
#> [1] "warning: argument is not numeric or logical: returning NA"
suppressWarnings(mean("a"))
#> [1] NA
message_of(mean(factor(c("a", "b"))))
#> [1] "warning: argument is not numeric or logical: returning NA"

# The functions that need a number are stricter or coerce.
message_of(var("a"))
#> [1] "warning: NAs introduced by coercion"
message_of(sd(factor(c("a", "b"))))
#> [1] "error: Calling var(x) on a factor x is defunct.\n  Use something like 'all(duplicated(x)[-1L])' to test for a constant vector."

# The cure is to convert on purpose, and look at what did not convert.
x <- c("12", "7", "n/a", "30")
nums <- suppressWarnings(as.numeric(x))
nums
#> [1] 12  7 NA 30
mean(nums, na.rm = TRUE)
#> [1] 16.33333
x[is.na(nums)]
#> [1] "n/a"

Source: R documentation: mean

The text of the first warning, argument is not numeric or logical: returning NA, is the one to search for when a script prints NA after reading a CSV file. The messages of the other functions on this page are collected in the section Messages and what they mean near the end.

Why missing values propagate

An Introduction to R states the rule in its section on missing values: in general, any operation on an NA becomes an NA, because if the specification of an operation is incomplete, the result cannot be known. The summary functions follow the rule by default, and each has an argument to say that the missing values should be dropped first. The argument is not the same everywhere, and neither is the default. The example uses airquality, the daily air quality in New York from May to September 1973 (datasets help page), in which the ozone column has 37 missing values among its 153 days.

# airquality (datasets): daily New York air quality, May to September 1973.
colSums(is.na(airquality))
#>   Ozone Solar.R    Wind    Temp   Month     Day
#>      37       7       0       0       0       0
nrow(airquality)
#> [1] 153

# Missing values propagate: the mean of anything that includes an unknown is
# unknown. That is a deliberate default, and na.rm = TRUE is an explicit choice.
mean(airquality$Ozone)
#> [1] NA
mean(airquality$Ozone, na.rm = TRUE)
#> [1] 42.12931
sum(!is.na(airquality$Ozone)) # how many values that mean is based on
#> [1] 116

# The defaults differ by function: know which one you are calling.
median(airquality$Ozone)
#> [1] NA
sd(airquality$Ozone, na.rm = TRUE)
#> [1] 32.98788
tryCatch(quantile(airquality$Ozone), error = \(e) conditionMessage(e))
#> [1] "missing values and NaN's not allowed if 'na.rm' is FALSE"
range(airquality$Ozone, na.rm = TRUE)
#> [1]   1 168
summary(airquality$Ozone) # counts the NAs instead of failing
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max.     NAs
#>    1.00   18.00   31.50   42.13   63.25  168.00      37
table(is.na(airquality$Ozone))
#>
#> FALSE  TRUE
#>   116    37

# na.rm in a grouped summary: the mean per month, with and without.
tapply(airquality$Ozone, airquality$Month, mean)
#>  5  6  7  8  9
#> NA NA NA NA NA
tapply(airquality$Ozone, airquality$Month, mean, na.rm = TRUE) |> round(1)
#>    5    6    7    8    9
#> 23.6 29.4 59.1 60.0 31.4
tapply(airquality$Ozone, airquality$Month, \(x) sum(!is.na(x)))
#>  5  6  7  8  9
#> 26  9 26 26 29

# Two columns, two different sets of rows: na.rm works column by column,
# complete cases work row by row.
mean(airquality$Ozone, na.rm = TRUE)
#> [1] 42.12931
mean(airquality$Ozone[complete.cases(airquality)])
#> [1] 42.0991
nrow(na.omit(airquality))
#> [1] 111

# Correlation: use = decides which rows enter.
cor(airquality$Ozone, airquality$Temp)
#> [1] NA
cor(airquality$Ozone, airquality$Temp, use = "complete.obs")
#> [1] 0.6983603

# Dropping is not neutral: the missing days are not a random sample.
tapply(is.na(airquality$Ozone), airquality$Month, sum)
#>  5  6  7  8  9
#>  5 21  5  5  1

Source: An Introduction to R: Missing values

The pattern in the output is worth reading closely. mean(), median() and range() return NA unless na.rm = TRUE; quantile() goes further and stops with an error, missing values and NaN's not allowed if 'na.rm' is FALSE; summary() counts the missing values in an extra column instead of failing; and fivenum() drops them by default (na.rm = TRUE), unlike nearly every other function. tapply() has no such argument: extra arguments such as na.rm = TRUE are passed on to the function it applies. The formula interfaces of aggregate() and xtabs() have an na.action instead (the former omits incomplete rows, the latter keeps them), and cor() and cov() have use. Dropping is also not neutral: the table of missing days per month at the end shows that June has 21 missing ozone values among its 30 days and September only one. A mean computed with na.rm = TRUE is a mean of the days someone measured, which may not be a typical sample of the days that happened.

The two ways of dropping rows give different data. na.rm works column by column, so the mean of Ozone uses 116 values, whereas na.omit() and complete.cases() work row by row: only the 111 days with all six readings present remain, and the mean of ozone over those days is a different number (42.10 against 42.13). cor(..., use = "complete.obs") makes the same choice as na.omit(), and use = "pairwise.complete.obs" makes the choice of na.rm for each pair of columns. Which is right depends on why the values are missing, a question about the data and not about R; Missing and Special Values covers NA, NaN and the other special values.

Variance, standard deviation and range

var() and sd() use the denominator n - 1, not n. The help page of cor() (which also documents var() and cov()) says that this gives an unbiased estimator of the variance for independent identically distributed observations, and that these functions return NA when there is only one observation. The script computes the sum of squares by hand with both denominators to show which one R uses; the n - 1 version is what a textbook calls the sample variance and a calculator often labels s, and the n version is the variance of the data treated as the whole population. sd() is the square root of var(). range() returns the minimum and the maximum, not the width; diff(range(x)) is the width, and range() of data with a missing value is c(NA, NA) without na.rm.

Quantiles

quantile() and its nine types

A sample quantile is not defined uniquely, and R implements nine definitions of it, selected by the type argument of quantile(). The help page describes them following Hyndman and Fan (1996): types 1 to 3 are step functions of the probability (type 1 is the inverse of the empirical distribution function, type 2 averages at the steps, type 3 takes the nearest even order statistic), and types 4 to 9 interpolate linearly between consecutive order statistics, each with a different plotting position. The default is type 7, the definition used by S and by R before 2.0.0, and it has stayed the default; type 6 is the one used by Minitab and by SPSS, and the help page says that Hyndman and Fan recommended type 8. This matters whenever a number computed in R has to match a number from another program: the 25 percent point of the 14 known page counts is 202.00 in R and 192.25 in a program that uses type 6, and neither is wrong.

Other facts from the help page that show up in the examples. probs must lie in [0, 1], but values up to 2e-14 outside are moved to the endpoint. names = FALSE drops the labels, and digits (default 7, added in R 4.1.0) is the precision used to format them: before R 4.1.0 the names depended on getOption("digits"). Types 1 and 3 can be used with dates and ordered factors. fuzz protects against floating-point error when the position is computed; since R 4.5.0 it is used by every type, with a default of zero for type 7 so that results stay the same.

fivenum(), summary() and quantile()

Three functions return "the quartiles", and they do not agree. fivenum() returns Tukey’s five numbers: the minimum, the lower hinge, the median, the upper hinge and the maximum. The hinges are the medians of the lower and upper halves of the sorted data, and the median belongs to both halves when the number of values is odd. quantile() with its default type 7 interpolates at the position 1 + (n - 1) p, and summary() of a numeric vector calls quantile() (its argument quantile.type is 7 by default) and adds the mean. With 14 values the first hinge is the 4th value (198) and the quartile of type 7 is a quarter of the way from the 4th to the 5th (202); the upper hinge is the 11th value (352) and the upper quartile is 344.5. The differences are small and systematic, and they are the reason that boxplot() and fivenum() draw the same box, whereas quantile() can give a slightly different one. The example computes the hinges by hand from the halves, and shows the positions that types 7 and 6 use.

Robust spread: IQR() and mad()

The standard deviation is pulled by long tails, and so is the mean. median(), IQR() and mad() are the robust companions. IQR(x, na.rm = FALSE, type = 7) is the distance between the quartiles; the help page notes that it uses quantile() and not Tukey’s hinges, and that dividing by 1.349 gives a normal-consistent estimate of the standard deviation. mad(x) is the median of the absolute deviations from the median, multiplied by 1.4826 (constant) so that it estimates the standard deviation for normal data; constant = 1 gives the raw median. The loan lengths of the shelf have a long right tail (a few loans of 58 to 84 days), so the mean (25.4 days) is higher than the median (23) and the standard deviation (17.1) is nearly twice the scaled MAD (8.9). The same data give the outliers boxplot.stats() would draw: values beyond 1.5 times the IQR from the quartiles, which are Tukey’s fences.

Proportions and margins: proportions(), marginSums() and addmargins()

A table of counts is rarely the final answer; the proportions are. proportions(x, margin = NULL) divides by the grand total, or, with margin = 1, by the row totals, or with margin = 2 by the column totals, so that the margin you name is the one that sums to 1. Which margin to use is a question about what is being compared: row proportions answer "of the loans of each genre, which share was overdue", column proportions answer "of the overdue loans, which share was of each genre". R 4.0.0 added proportions() and marginSums() to replace the unfortunately named prop.table() and margin.table(), in the words of the NEWS entry; they are drop-in replacements that also accept the name of a dimension as margin, and the old names stay as aliases, so old code keeps working. addmargins() appends the totals as a new row and column (or only to the margins named), and rowSums() and colSums() also work on a two-way table.

Binning numbers: cut(), tabulate() and findInterval()

To tabulate a number, turn it into a factor of intervals. cut(x, breaks) takes either a vector of break points or a number of equal-width intervals, closes them on the right by default (right = TRUE, so (150,300]), and labels them. include.lowest = TRUE closes the first interval on its left edge too, which is needed when a break point equals the minimum, as the example with 88 pages shows; dig.lab sets how many digits the labels use. labels names the bins and ordered_result = TRUE makes them an ordered factor. Correlation and covariance

cor(x, y) returns Pearson’s correlation coefficient by default, method = "spearman" gives Spearman’s rho (the correlation of the ranks) and method = "kendall" gives Kendall’s tau, which is the tau-b variant when there are ties. The two rank-based measures are more robust and suit data that are not bivariate normal. cov() has the same arguments and returns the covariance, and cov2cor() rescales a covariance matrix into a correlation matrix. Given a matrix or a data frame as x, cor() returns the correlation matrix of its columns, and every column must be numeric: a data frame with a text column is an error, so subset the numeric columns first. The inputs must be numeric as is.numeric() sees them; logical values are also allowed, for historical compatibility.

The use argument decides what happens with missing values, and it is the argument most often left at its default by mistake: "everything" (the default) propagates NA; "all.obs" stops with an error if there is any; "complete.obs" drops every row with a missing value in any column (and is an error if no complete row is left); "na.or.complete" does the same but returns NA when no row is left; and "pairwise.complete.obs" uses, for each pair of columns, all the rows that are complete for that pair. The last choice can give a matrix that is not positive semi-definite, and the correlations in it are computed from different subsets of the rows. Abbreviations of the values of use and method are accepted. The loan lengths and the page counts have a correlation near zero, as the synthetic data intend: the example shows the values, not an effect.

Grouped summaries

A grouped summary applies a function to the pieces of a data frame defined by one or more grouping variables. Base R has four tools, which differ in what they return. aggregate() returns a data frame with one row per group and is the one to reach for first: its formula method (aggregate(days ~ genre, data, FUN)) omits the rows with missing values in any variable of the formula, and its default method takes a list of grouping vectors and leaves the missing-value decision to FUN. If FUN returns several numbers the result has a matrix column, which is handy and awkward (agg$days[, "mean"]). tapply(X, INDEX, FUN) returns an array indexed by the groups, a named vector for one grouping variable and a matrix for two, and gives NA for an empty combination. ave(x, g, FUN = mean) returns a vector the length of x, with the group value repeated on every row, which is the form wanted to centre or standardise within groups, to add a group total as a new column or to filter rows. by(data, INDICES, FUN) applies a function to the rows of a data frame, group by group, and prints in its own format. The apply family in general is described in The apply Family and Functionals, and split() plus vapply() (shown in the section on "htest" objects) is the building block under all of them.

Every classical test in the stats package returns a list of class "htest" (hypothesis test), with a fixed set of components that each test fills in as far as it applies. The help page of each test lists them in its Value section, and the print() method for the class, which is documented on the page of print.htest(), lays them out in the familiar block: a title (the method component), the data (data.name), the statistic and its degrees of freedom and p-value, the alternative hypothesis, the confidence interval and the sample estimates. The components of t.test() are statistic, parameter (the degrees of freedom), p.value, conf.int (with the confidence level stored in its "conf.level" attribute), estimate, null.value, stderr, alternative, method and data.name. stderr has been returned since R 3.6.0. Other tests have fewer components (shapiro.test() has no interval and no estimate) or more (chisq.test() also returns observed, expected, residuals and stdres). The fact that the object is a plain list is the useful property: $p.value is a number, $conf.int a vector of two, and str() shows the whole structure at once.

Comparing means: t.test()

t.test() performs one-sample, two-sample and paired Student t tests. The signature of the default method is t.test(x, y = NULL, alternative = c("two.sided", "less", "greater"), mu = 0, paired = FALSE, var.equal = FALSE, conf.level = 0.95, ...). With only x, it tests whether the mean is mu. With x and y, it tests whether the means differ by mu, and by default it uses the Welch (Satterthwaite) approximation, which does not assume that the two variances are equal, so the degrees of freedom are not whole numbers. var.equal = TRUE gives the classical pooled-variance Student test, which has whole degrees of freedom and slightly more power when the variances really are equal. paired = TRUE tests the mean of the differences x - y. Missing values are removed without a message, in pairs when paired = TRUE. alternative = "greater" is the alternative that x has the larger mean (in the one-sample case: that the mean is greater than mu), and a one-sided test returns a one-sided interval, with Inf as one limit. An Introduction to R first runs var.test() and then chooses between the Welch and the pooled test; the section on interpretation explains why the Welch test is the safer default and why a test of the variances first adds little.

Paired samples

When each observation in one sample is matched with one in the other (the same patient under two drugs), the pairing carries information, and a paired test uses it. The classic example is sleep, the extra hours of sleep of ten patients under two drugs (Student, 1908; datasets help page). t.test(x, y, paired = TRUE) is the same test as the one-sample test of the differences. The formula interface for a paired test is Pair(x1, x2) ~ 1, introduced in R 4.0.0 when the formula method was extended to one-sample and paired tests. R 4.4.0 made passing paired = TRUE to the formula method an error, with the message cannot use 'paired' in formula method: an old call such as t.test(extra ~ group, data = sleep, paired = TRUE) used to be accepted and quietly paired the observations in their order of appearance, which is only right if the data are sorted consistently, so the change protects against a silent error.

# sleep: extra sleep of 10 patients under two drugs (datasets::sleep).
head(sleep, 3)
#>   extra group ID
#> 1   0.7     1  1
#> 2  -1.6     1  2
#> 3  -0.2     1  3
x <- sleep$extra[sleep$group == 1]
y <- sleep$extra[sleep$group == 2]

# paired = TRUE tests the mean of the differences.
t.test(x, y, paired = TRUE)
#>
#> 	Paired t-test
#>
#> data:  x and y
#> t = -4.0621, df = 9, p-value = 0.002833
#> alternative hypothesis: true mean difference is not equal to 0
#> 95 percent confidence interval:
#>  -2.4598858 -0.7001142
#> sample estimates:
#> mean difference
#>           -1.58

#> [1] 0.00283289

tryCatch(
  t.test(extra ~ group, data = sleep, paired = TRUE),
  error = \(e) conditionMessage(e)

t.test(x, y)$p.value
#> [1] 0.07939414

The last line shows what the pairing buys. Ignoring it, the Welch test gives p = 0.079, not significant at 5 percent, whereas the paired test gives p = 0.0028. Pairing removes the variation between patients from the comparison. The converse mistake, treating two independent samples as paired, is as wrong, and the choice is a statement about how the data were collected, not about how the numbers look.

Rank-based tests: wilcox.test()

wilcox.test() performs the Wilcoxon signed rank test (one sample or paired) and the Wilcoxon rank sum test, also known as the Mann-Whitney test (two independent samples). They test a shift in location without assuming normality: the one-sample test asks whether the distribution is symmetric about mu, the two-sample test whether the two distributions differ by a location shift of mu. The help page cautions that the estimator for the difference that conf.int = TRUE returns is not the difference of the medians (a common misconception) but the median of the differences between a value of x and a value of y, the Hodges-Lehmann estimator, and that the one-sample estimate is the pseudomedian. The default method in R 4.6.1 is wilcox.test(x, y = NULL, alternative = c("two.sided", "less", "greater"), mu = 0, paired = FALSE, exact = NULL, correct = TRUE, conf.int = FALSE, conf.level = 0.95, tol.root = 1e-4, digits.rank = Inf, ...). The formula interface, as for t.test(), takes a response and a two-level factor, or 1 on the right-hand side for the one-sample test, or Pair(x1, x2) ~ 1 for a paired one.

Exact inference with ties in R 4.6

Before R 4.6.0, wilcox.test() could compute an exact p-value only when there were no ties and fewer than 50 observations. Real data nearly always have ties, because measurements are rounded: with ties, older versions printed a warning, cannot compute exact p-value with ties, and fell back to the normal approximation. The 4.6.0 NEWS entry reads that wilcox.test() can now perform exact (conditional) inference in case of ties. The help page of R 4.6.1 describes it: by default, if exact is not specified, an exact p-value is computed when the samples contain fewer than 50 finite values, and if there are ties the exact inference uses the conditional (permutation) distribution given the observed ranks, with an implementation of the Streitberg-Roehmel shift algorithm contributed by Torsten Hothorn. The message is therefore gone from wilcox.test(). It is not gone from R: cor.test() with method = "spearman" or "kendall" and the one-sample ks.test() still warn about ties (their texts are in the examples further down). An Introduction to R shows the old behaviour in its section 8.3, with the sample of ice-melting measurements of Rice (1995): the manual’s transcript ends with Warning message: Cannot compute exact p-value with ties in: wilcox.test(A, B) and a p-value of 0.007497. The container used for this page has only R 4.6.1, so the old warning cannot be reproduced here; what can be shown is that the new default gives a different p-value, that exact = FALSE gives the manual’s number back, and that the two samples of the manual have ties.

What "conditional" means is easiest to see on a small example, where everything can be listed. Given the pooled ranks, with tied values sharing the average rank, the null hypothesis says that every choice of which observations belong to the first sample is equally likely. With 8 and 9 observations there are 24,310 such choices; counting those whose rank sum is as small as the observed one, or as large, gives the exact p-value. The script does that by brute force with combn() and gets the same number that wilcox.test() reports.

Edgeworth-corrected p-values

When the normal approximation is used (exact = FALSE, or 50 or more observations) there is a second change in R 4.6.0: the NEWS entry says that wilcox.test() can optionally compute improved asymptotic p-values by including up to 3 correction terms of the Edgeworth series. The option is the existing argument correct: a logical value keeps its old meaning (TRUE, the default, is the continuity correction, and FALSE is none), and an integer from 0 to 3 gives the number of Edgeworth terms, where 0 is the same as TRUE. Anything else is an error, 'correct' must be an integer between 0 and 3. The help page states that the improved p-values are available when the normal approximation is used and there are no ties; with ties the integer is accepted and has no effect, as the second part of the script shows. R 4.6.1 fixed the p-value computation of wilcox.test(x, exact = FALSE, correct = k), which had lost a factor of dnorm(z), so p-values computed with an integer correct in R 4.6.0 should be recomputed.

The digits.rank argument, new in R 4.0.0 (NEWS), decides which values count as tied: if finite, the ranks are computed from signif(r, digits.rank). It exists because floating-point arithmetic splits ties that the data should have, a case of R FAQ 7.31: 0.4 - 0.3 and 0.3 - 0.2 are not exactly equal.

Counts: chisq.test() and fisher.test()

chisq.test() does two jobs. Given a vector of counts, it performs a goodness-of-fit test against the probabilities p (equal by default; rescale.p = TRUE rescales p if it does not sum to 1, otherwise that is an error). Given a matrix or two factors, it performs Pearson’s test of independence on the two-way table. For a 2 by 2 table, correct = TRUE (the default) applies Yates' continuity correction. The statistic is the sum of (observed - expected)^2 / expected, referred to a chi-squared distribution with (rows - 1) (columns - 1) degrees of freedom. The result holds the observed and expected counts, the Pearson residuals and the standardised residuals stdres, whose absolute values above about 2 point to the cells that depart from independence.

The approximation behind the p-value is poor when the expected counts are small, and R warns: Chi-squared approximation may be incorrect, when any expected count is below 5. R warns as soon as any expected count is below 5, which is the simple form of a common rule of thumb (Cochran’s rule: no expected count below 1 and at most a fifth of them below 5). There are two remedies. One is to simulate: simulate.p.value = TRUE computes a Monte Carlo p-value from B random tables with the same margins (2000 by default; the smallest possible p-value is 1/(B + 1)), which depends on the random seed, so call set.seed() first. The other is Fisher’s exact test, fisher.test(), which conditions on the margins and for a 2 by 2 table also returns the conditional maximum likelihood estimate of the odds ratio and its interval; for a larger table it is exact but can be slow. The shelf’s table of overdue loans by genre has expected counts as low as 1.8, so it triggers the warning. The script captures the warning text with withCallingHandlers() and still uses the result.

Normality: shapiro.test()

shapiro.test(x) performs the Shapiro-Wilk test of the null hypothesis that the sample comes from a normal distribution. It needs between 3 and 5000 non-missing values, and it stops with sample size must be between 3 and 5000 otherwise (and with all 'x' values are identical for a constant sample). The p-value is approximate: the help page says that the calculation is exact for n = 3, and uses approximations after that, said by Royston (1995) to be adequate for p-values below 0.1. The test is easy to run and easy to misuse. With few observations it has little power, so a large p-value says very little (the shelf’s 14 page counts give p = 0.83, and so would many non-normal samples of that size); with thousands of observations it rejects tiny departures from normality that do not matter for a t test (the 4000 draws from a t distribution with 10 degrees of freedom, which looks normal to the eye, reject at p = 2e-12). The question that matters is how far from normal the data are and how sensitive the method is to it, and a normal quantile plot (qqnorm() and qqline(), in Base Graphics and Devices) answers it better than a p-value. An Introduction to R runs shapiro.test() and ks.test() on the eruption data in its section 8.2, and notes that the distribution theory of the Kolmogorov-Smirnov test is not valid when the parameters of the normal distribution are estimated from the same sample.

Proportions: prop.test() and binom.test()

prop.test(x, n, p = NULL, alternative, conf.level, correct = TRUE) tests proportions with a normal (chi-squared) approximation: given a number of successes and trials it tests one proportion against p, given vectors it tests that several proportions are equal, and given a two-column matrix of successes and failures it does the same. With one or two groups it applies Yates' continuity correction by default (correct = TRUE), and the confidence interval depends on the number of groups: for one group it is the interval for the proportion obtained by inverting the score test, for two groups it is an interval for the difference of the two proportions, both with a continuity correction where it applies, and for more groups there is none. binom.test(x, n, p = 0.5) is exact: it sums binomial probabilities, so it has no approximation to go wrong for small n, and its interval is the Clopper-Pearson one. For a large number of trials the two agree. Both need a count of successes, so a data frame with an overdue flag is summarised with sum() and sum(!is.na()) first; a missing flag is neither a success nor a failure, and counting it as a failure is a quiet error.

Association, variances and distributions

cor.test(x, y) tests the hypothesis that a correlation is zero. For method = "pearson" it uses a t statistic with n - 2 degrees of freedom and returns a confidence interval from the Fisher z transformation. For Spearman’s rho and Kendall’s tau it uses exact p-values where it can and an approximation otherwise; with ties it cannot compute an exact p-value, and warns cannot compute exact p-value with ties. The formula interface is one-sided: ~ x + y. The loans of the shelf show a Pearson correlation of 0.017 between the number of pages and the length of a loan (p = 0.91, interval from -0.27 to 0.30): a correlation of this size cannot be told from zero with 48 pairs, and neither can a correlation of 0.25 be excluded.

var.test(x, y) compares the variances of two samples with an F test, and, like the F test in general, it is sensitive to non-normality, so treat it as a rough guide. Its formula interface is the same as that of t.test().

Several groups: aov(), TukeyHSD() and pairwise tests

When there are more than two groups, comparing them two at a time with t.test() multiplies the chances of a false positive, and the first step is a single overall test. aov(y ~ g, data) fits a one-way analysis of variance, and summary() of the fit prints the analysis of variance table with the F statistic and its p-value. The object has classes "aov" and "lm", because aov() is lm() underneath, and the extractor functions of the next page apply (Statistical Models). The test says that at least one mean differs, not which. For that, TukeyHSD() computes simultaneous confidence intervals for all the pairwise differences, with the 95 percent level applying to the whole family and its adjusted p-values labelled p adj. pairwise.t.test() compares each pair with t.test()-like statistics (with a pooled standard deviation by default, pool.sd = !paired) and adjusts the p-values with p.adjust(); its default is Holm’s method (p.adjust.method = p.adjust.methods, the first of which is "holm"). pairwise.wilcox.test() is the rank-based counterpart.

Many tests: p.adjust()

If you run twenty tests of true null hypotheses at the 5 percent level, you expect one to come out significant by chance alone; if you then report only that one, the reported result is an artefact. p.adjust(p, method = p.adjust.methods, n = length(p)) corrects a vector of p-values for the number of tests. The method names are in the vector p.adjust.methods: "holm", "hochberg", "hommel", "bonferroni", "BH", "BY", "fdr" (an alias of "BH") and "none". The first four control the family-wise error rate, the probability of at least one false positive. Bonferroni multiplies each p-value by the number of tests and is dominated by Holm’s method, which the help page says has no reason not to replace it, and which is valid under any dependence. "BH" (Benjamini and Hochberg) and "BY" control the false discovery rate, the expected share of false positives among the results declared significant, which is a weaker requirement and gives more power when many tests are run and some real effects are expected. n is the number of tests, and is larger than length(p) only if some p-values were not passed in. Missing p-values stay missing and are not counted unless n says so.

The result is in the same order as the input, so adjusted p-values can be put next to the raw ones. The example runs the t test of 250 pages in each genre (six p-values), and then a simulation of 20 tests on pure noise.

What a p-value does not say

The functions above produce numbers that are easy to misread. The limits, in order of how often they matter:

  • A p-value is the probability, if the null hypothesis and all the assumptions of the test are true, of data at least as extreme as the data observed. It is not the probability that the null hypothesis is true, not the probability that the result was produced by chance, and not the probability that the result will replicate. A p-value of 0.54 does not show that the mean is 250; it shows that these data are unsurprising if it were.

  • A small p-value says nothing about the size of the effect. With 300 penguins, a difference of a fraction of a millimetre is significant; with 14 books a difference of 100 pages is not. Report the estimate with its confidence interval, which has the units of the data, and use the p-value as a footnote. t.test(), prop.test() and wilcox.test(conf.int = TRUE) return the interval.

  • The tests assume that the observations are independent. The loans in the shelf data are not: there are 59 loans of 15 books by a handful of members, and loans of one book or by one member resemble each other. Treating every loan as an independent observation inflates the sample size and the degrees of freedom, so the test claims more precision than the data have; the example below shows how the answer changes when the unit of analysis becomes the book. The degrees of freedom fall from 32 to under 5, and the p-value moves from 0.93 to 0.61: pooling dependent observations misstates the uncertainty, and the resulting p-value can be wrong in either direction.

  • A non-significant result is not evidence of no effect. With 5 books per genre the power to detect a difference of 30 pages (with a standard deviation of 108) between two genres is about 6 percent, barely above the 5 percent that a test has when there is no difference at all. power.t.test() works the problem in both directions: the sample size needed for a target power, or the power of a design.

  • The data here are synthetic. The 16 books and 60 loans are generated to have realistic problems (missing values, spelling variants, a date that does not exist) and not realistic effects, so no result on this page, significant or not, is a finding about libraries or books.

  • Many tests, many chances: report how many were run, and correct for them (the previous section), or state that the analysis is exploratory.

  • Test assumptions are checked with diagnostics and subject knowledge, not with preliminary tests. A pre-test of normality or of equal variances before a t test makes the overall procedure a different procedure, with error rates nobody has derived; the safer defaults are the Welch test (no equal variance assumption) and a look at the data. The method still applies if the data are far from normal and the sample is large, because the t test is a test of a mean, and the mean of many observations is close to normal; it is then the outliers and the independence that need attention.

Power and effect sizes

power.t.test() takes any four of n, delta, sd, sig.level and power, and solves for the fifth, in one of the three designs (type = "two.sample", "one.sample" or "paired", with alternative = "two.sided" or "one.sided"). n is the number in each group. The effect size used above, Cohen’s d, is the difference of the means in units of the pooled standard deviation; there is no function for it in base R, but the formula is short. Do the power calculation before collecting data: afterwards it only restates the p-value. The printed result is a "power.htest" object, printed by the second method on the page of print.htest(), and the NOTE: n is number in *each* group line is part of its output.

Message Meaning and cure

not enough 'x' observations

t.test() or var.test() needs at least two non-missing values in a sample (a pooled two-sample t test needs only one in each group); look for a filter that removed every row or a column that is all NA.

data are essentially constant

t.test() of a sample with no variation, compared with its mean; the statistic would be infinite.

grouping factor must have exactly 2 levels

the formula interface of t.test(), wilcox.test() or var.test() was given a factor with other than two levels; subset the rows first, or use aov() for three or more.

cannot use 'paired' in formula method

R 4.4.0 and later; use Pair(x1, x2) ~ 1.

argument is not numeric or logical: returning NA

mean() (and so t.test()) of text or a factor; convert with as.numeric().

'x' must be numeric

cor() given text or a data frame that has text columns; cor.test() says 'x' must be a numeric vector.

the standard deviation is zero

a constant vector given to cor(); the correlation is NA.

missing values and NaN's not allowed if 'na.rm' is FALSE

quantile() of data with an NA; add na.rm = TRUE.

Chi-squared approximation may be incorrect

some expected counts are below 5; use simulate.p.value = TRUE with a seed, or fisher.test().

all entries of 'x' must be nonnegative and finite

chisq.test() of negative or infinite counts, often a table of differences instead of counts.

cannot compute exact p-value with ties

cor.test() with method = "spearman" or "kendall"; the p-value is an approximation. Before R 4.6.0 also wilcox.test().

sample size must be between 3 and 5000

shapiro.test() of fewer than 3 or more than 5000 non-missing values.

ties should not be present for the one-sample Kolmogorov-Smirnov test

ks.test(x, "pnorm") and friends on data with repeated values.

'probs' outside [0,1]

quantile() given probabilities as percentages.

'correct' must be an integer between 0 and 3

wilcox.test() in R 4.6.0 or later, given correct = 4.

Pitfalls

  • Forgetting that the default for missing values differs. mean(), median() and range() give NA, quantile() stops, fivenum() silently drops, summary() counts, cor() gives NA, and t.test() and wilcox.test() drop silently. Know which function you call, and report the number of values used.

  • Treating sd() as the population standard deviation. It divides by n - 1; for a complete population multiply the variance by (n - 1) / n.

  • Comparing quartiles from different programs. The nine quantile types differ; fivenum(), quantile() and summary() are three different answers, and a spreadsheet or Minitab may use a fourth.

  • Using table() on a number with many distinct values. Every distinct value is a level. Bin first with cut().

  • Reading a row-proportion table as a column-proportion table. The margin argument of proportions() is the one that sums to 1.

  • Running chisq.test() on percentages or on the raw data. It needs counts, or two factors that it tabulates itself. A table of percentages gives a meaningless statistic.

  • The one-sided alternative chosen after seeing the data. alternative = "greater" halves the p-value when the data go that way; decide before looking.

  • Taking exact = TRUE for granted for large samples. The help page of wilcox.test() warns that with exact = TRUE it can take a very long time to run if one sample is large (several thousands or more). The default switches to the normal approximation at 50 observations for that reason.

  • Calling wilcox.test() a test of medians. It tests a location shift under the assumption that the distributions have the same shape; with different shapes it also detects differences that are not in the medians.

  • Rounding p-values to zero. p-value < 2.2e-16 is a bound, not a zero. Quote the estimate and the interval.

  • Comparing floating-point numbers that should be ties. See R FAQ 7.31, digits.rank in wilcox.test() and round() before ranking.
