Attributes and Names

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R, so no add-on package version applies; the scripts also use the book class of the running shelf scenario, which is plain base R code, and the lintr 3.4.0 default linters were used only to check the scripts.

Almost everything in R that is not the plain data of a vector is stored in one place: its attributes. A matrix is a vector with a dim attribute, a factor is an integer vector with levels and class attributes, a data frame is a list with names, class and row.names attributes, a time series is a numeric vector with tsp and class, and the names that label the elements of a vector are the names attribute. Because attributes are so central, the rules for when they are kept, copied or dropped decide whether a calculation returns a labelled result or a bare vector. This page starts with the generic tools (attributes(), attr(), structure() and mostattributes<-), goes through the attributes that R treats specially one by one (names, dim, dimnames, class, levels, tsp and comment), then collects the rules for which attributes survive which operations, each with an example you can run, and ends with the attributes of a data frame, user-defined attributes as metadata, and the places where older tutorials give outdated advice.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts pass the default lintr linters. A long script is shown in consecutive parts, each part continuing the previous one with the same variables; the part boundaries are always at a blank line. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says. The examples use the library scenario of the section: books, loans, shelf_today, loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"). The neighbouring pages go deeper on each attribute’s own topic: Atomic Vectors and Types, Factors, Matrices and Arrays, Lists, Data Frames and Dates and Times; S3 Classes and Generics and OOP Overview and Base Types cover what the class attribute does for method dispatch.

What an attribute is

The R Language Definition puts it in one paragraph. All objects except NULL can have one or more attributes attached to them. Attributes are stored as a pairlist where all elements are named, but they should be thought of as a set of name and value pairs. A listing is obtained with attributes() and set with attributes<-; individual components are accessed with attr() and attr<-. Some attributes have special accessor functions (levels<- for factors) and these should be used when they exist: besides hiding the implementation, they may perform additional operations, and R intercepts calls to attr<- and attributes<- that involve the special attributes to enforce consistency checks. Matrices and arrays are simply vectors with the attribute dim and optionally dimnames attached to the vector, and the class structure of R is implemented by the class attribute (The R Language Definition: Attributes). An Introduction to R adds that attributes() returns the non-intrinsic attributes, that attr(object, name) selects one, and that these functions are rarely needed except when some new attribute is being created for a particular purpose, for example to associate a creation date with an object, but that the concept is very important (An Introduction to R: Getting and setting attributes).

Two words in those descriptions matter. First, the attributes are a set: their order does not matter, the names must be unique, and identical() compares them as a set by default (attrib.as.set = TRUE, see Comparing objects). Second, the attributes are non-intrinsic: the mode (or type) and the length of an object are its intrinsic properties, so they never appear in attributes() (see Atomic Vectors and Types for typeof(), mode() and length()).

The next table lists the seven attributes that R treats specially. The help page of attributes() names them: class, comment, dim, dimnames, names, row.names and tsp are treated specially and have restrictions on the values that can be set; levels is not on that list, and is set for factors through its own replacement function (R documentation: attributes).

Attribute Meaning and checks Accessors

names

labels the elements of a vector or list; a character vector of at most the length of the object (padded with NA)

names(), names<-, setNames(), unname()

dim

the extents of an array; the product must equal the length; setting it drops names and dimnames

dim(), dim<-, nrow(), ncol()

dimnames

a list of character vectors (or NULL), one per dimension; each as long as its extent

dimnames(), dimnames<-, rownames(), colnames()

class

the classes an object inherits from; no check that the object has the parts the methods expect

class(), oldClass(), class<-, inherits(), unclass()

levels

the labels of a factor; any character vector, checked by the factor methods and not by attr()

levels(), levels<-, nlevels()

tsp

start, end and frequency of a time series; checked for consistency with the length

tsp(), tsp<-, start(), end(), frequency()

comment

a character vector that is never printed

comment(), comment<-

row.names

the row labels of a data frame, stored in a compact form when they are the automatic 1, 2, 3 and so on

row.names(), rownames(), .row_names_info()

Reading, setting and removing attributes

attributes(x) returns the list of all attributes, or NULL when there are none. attr(x, "name") returns one attribute, and attr(x, "name") <- value creates or replaces it; assigning NULL removes it. attributes(x) <- NULL removes them all, and structure(x, name = value, ...) is the same as setting each attribute in turn, written as an expression so that it can be used inside a call. The script uses the first four books' page counts.

source("scenario.R")

# A plain vector has no attributes: attributes() returns NULL
pages <- books$pages[1:4]
pages
#> [1] 387 432 214 198
attributes(pages)
#> NULL

# attr<- creates an attribute; attr() reads it back
attr(pages, "unit") <- "printed pages"
attributes(pages)
#> $unit
#> [1] "printed pages"
#>
attr(pages, "unit")
#> [1] "printed pages"

# print() shows non-special attributes under the values
pages
#> [1] 387 432 214 198
#> attr(,"unit")
#> [1] "printed pages"

Source: R documentation: attr

The default print() method shows the attributes that it does not treat specially below the values, in the form attr(,"name"); the section How print shows attributes says which attributes are hidden. The script continues with structure() and with removal.

# Attributes survive a copy, and you can set several at once with structure()
shelf_pages <- structure(pages, source = "books.csv", checked = TRUE)
str(attributes(shelf_pages))
#> List of 3
#>  $ unit   : chr "printed pages"
#>  $ source : chr "books.csv"
#>  $ checked: logi TRUE

# attr<- with NULL removes one attribute, attributes<- with NULL removes all
attr(shelf_pages, "checked") <- NULL
names(attributes(shelf_pages))
#> [1] "unit"   "source"
attributes(shelf_pages) <- NULL
shelf_pages
#> [1] 387 432 214 198
attributes(shelf_pages)
#> NULL

Source: R documentation: structure

structure() is the idiom of the book constructor in the shelf scenario (new_book() calls structure(list(...), class = "book")). Its help page says what to remember: the last of two equal tags wins, a tag set to NULL removes the attribute, and adding the class "factor" ensures that numeric codes are given integer storage mode. The next part shows that attributes() reports only non-intrinsic properties, so that the length and the type are asked for separately.

# attributes() returns a list of the non-intrinsic attributes: mode and length
# are not attributes
x <- c(a = 1, b = 2)
attributes(x)
#> $names
#> [1] "a" "b"
#>
length(x)
#> [1] 2
mode(x)
#> [1] "numeric"
typeof(x)
#> [1] "double"

Source: R documentation: attributes

Partial matching in attr()

The extractor attr(x, which, exact = FALSE) looks first for an exact match of which among the attributes of x and then, unless exact = TRUE, for a unique partial match; it returns NULL when there is no match or when more than one attribute matches. The replacement attr<- only uses exact matches, so assigning to a shortened name creates a new attribute instead of changing the one you meant. Setting options(warnPartialMatchAttr = TRUE) makes partial matches give warnings (R documentation: attr).

# attr() accepts a unique partial match unless exact = TRUE
x <- 1:3
attr(x, "shelf_location") <- "A3"
attr(x, "shelf_number") <- 3L

attr(x, "shelf_loc")
#> [1] "A3"
attr(x, "shelf_loc", exact = TRUE)
#> NULL
attr(x, "shelf_")
#> NULL
attr(x, "shelf_location", exact = TRUE)
#> [1] "A3"

# The replacement function matches exactly, so this creates a new attribute
attr(x, "shelf_loc") <- "B1"
names(attributes(x))
#> [1] "shelf_location" "shelf_number"   "shelf_loc"

# options(warnPartialMatchAttr = TRUE) makes partial matching warn
old <- options(warnPartialMatchAttr = TRUE)
msg <- tryCatch(attr(x, "shelf_n"), warning = \(w) conditionMessage(w))
msg
#> [1] "partial argument match of 'shelf_n' to 'shelf_number'"
options(old)

# Without the option, a shortened or mistyped name silently reads
# another attribute
attr(x, "shelf_nu")
#> [1] 3

Source: R documentation: attr

The partial match is the reason why a typo in an attribute name can read back the wrong value without any message. Code that must be exact passes exact = TRUE, and a package that checks attr(x, "unit") for a classed object should do the same, because a user attribute named unit_of_measure would otherwise answer to it.

Errors and restrictions when setting attributes

The special attributes are checked at assignment, whether through attr<-, attributes<-, structure() or their own accessors. The messages below are what R 4.6.1 prints. The same script shows the NULL rule: NULL cannot have attributes, so attr<- on NULL is an error, attributes<- on NULL silently promotes it to an empty list, and since R 4.6.0 structure(NULL, ...) is an error as well (the argument was deprecated for years, and the 4.6.0 NEWS lists it as defunct). In R 4.6.0 setting attributes on a primitive function became an error too: it was deprecated in R 4.5.0 because it modified the function without copying it.

# structure(): the last of two equal tags wins, NULL removes a tag
structure(1:3, a = 1, a = 2) |> attributes()
#> $a
#> [1] 2
#>
structure(structure(1:3, a = 1), a = NULL) |> attributes()
#> NULL

# structure() with special tags is checked by the same code as attr<-
r <- tryCatch(structure(1:6, dim = c(4, 2)), error = \(e) conditionMessage(e))
r
#> [1] "dims [product 8] do not match the length of object [6]"
r2 <- tryCatch(
  structure(1:3, names = letters),
  error = \(e) conditionMessage(e)
)
r2
#> [1] "'names' attribute [26] must be the same length as the vector [3]"
r3 <- tryCatch(
  structure(1:3, dimnames = list("a")),
  error = \(e) conditionMessage(e)
)
r3
#> [1] "'dimnames' applied to non-array"

Source: R NEWS: Changes in R 4.6.0

# NULL has no attributes: attr<- on NULL is an error, and since R 4.6.0
# so is structure(NULL, ...)
r4 <- tryCatch(
  {
    z <- NULL
    attr(z, "a") <- 1
  },
  error = \(e) conditionMessage(e)
)
r4
#> [1] "attempt to set an attribute on NULL"
r5 <- tryCatch(structure(NULL, a = 1), error = \(e) conditionMessage(e))
r5
#> [1] "attempt to set an attribute on NULL"

# attributes<- on NULL silently coerces to an empty list
z <- NULL
attributes(z) <- list(a = 1)

#> list()
#> attr(,"a")
#> [1] 1

# Attributes of primitive functions cannot be set (R >= 4.6.0)
f <- sum
r6 <- tryCatch(attr(f, "foo") <- NA, error = \(e) conditionMessage(e))
r6
#> [1] "cannot set an attribute on a 'builtin'"

Source: R NEWS: Changes in R 4.6.0 and 4.5.0

attributes<- replaces all the attributes: it first removes every existing attribute, then sets any dim, and then the remaining attributes in the order given, which guarantees that dim always precedes dimnames. mostattributes<- is the forgiving variant: it assigns dim, names and dimnames only when they are valid, where attributes<- would give an error, and sets the other attributes as they are. Its help page says that it is principally intended for arrays, should be used with care on classed objects, and does not, for example, check that row.names are assigned correctly for data frames.

# attributes<- replaces all attributes; dim is set before dimnames
x <- 1:6
attributes(x) <- list(dimnames = list(c("a", "b"), c("x", "y", "z")), dim = 2:3)
x
#>   x y z
#> a 1 3 5
#> b 2 4 6

# mostattributes<- sets only the valid ones
y <- 1:6
mostattributes(y) <- list(unit = "n", dim = 3:2, names = letters[1:6],
                          dimnames = list(c("a", "b", "c"), c("x", "y")))
attributes(y)
#> $unit
#> [1] "n"
#>
#> $dim
#> [1] 3 2
#>
#> $dimnames
#> $dimnames[[1]]
#> [1] "a" "b" "c"
#>
#> $dimnames[[2]]
#> [1] "x" "y"
#>
#>
y2 <- 1:6
mostattributes(y2) <- list(dim = c(4, 2), unit = "n")
attributes(y2)
#> $unit
#> [1] "n"
#>

# attributes<- with an invalid dim is an error
r7 <- tryCatch(
  {
    y3 <- 1:6
    attributes(y3) <- list(dim = c(4, 2))
  },
  error = \(e) conditionMessage(e)
)
r7
#> [1] "dims [product 8] do not match the length of object [6]"

Source: R documentation: attributes

In the second call the invalid dim is skipped without a message, the user attribute is kept, and in the first call the names are not assigned because the object has become a matrix (a matrix has dimnames, not names).

How print shows attributes

print.default() shows an attribute that it has no special treatment for as attr(,"name") after the values, for vectors, matrices and lists alike. It does not show names and dim as attributes because it uses them to lay out the values, it shows dimnames as the row and column headings, it hides comment, and it shows class unless a print method for that class exists. The book objects of the shelf scenario have a print.book() method that prints one line, so a user attribute on a book is never shown by print(); unclass() or attributes() is the way to see it, and str() lists each attribute with the prefix - attr(*, "name")=.

source("scenario.R")

b <- book(

  year = 2017, genre = "Science fiction", pages = 410

attr(b, "shelf") <- "B2"

#> $class
#> [1] "book"
#>
#> $shelf
#> [1] "B2"
#>
#> $acquired
#> [1] "2025-03-14"
#>

#> [1] "B2"

The value of the attribute is not hidden by the method: it is the method that chooses what to show. That is the reason why print() is not a reliable way to check whether an attribute survived an operation; names(attributes(x)) is.

Names

A names attribute labels the individual elements of a vector or list: the names are used to print the object and also for indexing, for example quantile(x)["25%"]. names(x) <- value performs the consistency checks that the attribute has the proper type and length. Pairlists and one-dimensional arrays are special: for a pairlist the names are a virtual attribute constructed from the tags of the components, and for a one-dimensional array the names attribute really accesses dimnames[[1]] (The R Language Definition: Names).

names() and names<- are generic and primitive. The help page adds the rules to remember:

  • value is a character vector of up to the same length as x, or NULL; a shorter value is extended with character NA values.

  • The name "" is special: it means that there is no name for that element. Subscripting by "" matches nothing, not even the elements that have no name.

  • A name can be a character NA, but it will never be matched and is likely to lead to confusion.

  • A part of the attribute can be updated through the general replacement rules: names(z)[3] <- "c2" is evaluated as z <- "names<-"(z, "[<-"(names(z), 3, "c2")).

  • For an environment, names(env) gives the names of the corresponding list (ls(env, all.names = TRUE, sorted = FALSE)), in arbitrary order.

source("scenario.R")

# Names label the elements of a vector or list
pages <- setNames(books$pages, trimws(books$title))[1:4]
pages
#>    The Dispossessed Pride and Prejudice   the quiet streets          Loud Roofs
#>                 387                 432                 214                 198
names(pages)
#> [1] "The Dispossessed"    "Pride and Prejudice" "the quiet streets"
#> [4] "Loud Roofs"

# names<- replaces all names; a shorter value is padded with NA
names(pages) <- c("dispossessed", "pride")
names(pages)
#> [1] "dispossessed" "pride"        NA             NA
pages
#> dispossessed        pride         <NA>         <NA>
#>          387          432          214          198

# Partial replacement: names(x)[2] <- "..." works through names<- and [<-
names(pages) <- c("dispossessed", "pride", "streets", "roofs")
names(pages)[2] <- "pride_prejudice"
names(pages)
#> [1] "dispossessed"    "pride_prejudice" "streets"         "roofs"

# NULL removes the names
names(pages) <- NULL
pages
#> [1] 387 432 214 198
names(pages)
#> NULL

Source: R documentation: names

The padding with NA in the second step is the trap: a half-finished names(x) <- c("a", "b") on a longer vector leaves NA names that print as <NA>, and a lookup by name never finds them. The part below shows the empty name, the NA name, and how lists and c() build and combine names.

# The empty name "" means "no name for this element"; it never matches
v <- c(a = 1, 2, c = 3)
names(v)
#> [1] "a" ""  "c"
v[""]
#> <NA>
#>   NA
v["b"]
#> <NA>
#>   NA

# A character NA is a valid, but never matched, name
w <- c(1, 2)
names(w) <- c("x", NA)
names(w)
#> [1] "x" NA
w[NA_character_]
#> <NA>
#>   NA

# Lists have names too, and c() keeps and combines them
info <- list(title = "The Dispossessed", year = 1974L)
names(info)
#> [1] "title" "year"
combined <- c(info, list(pages = 387L))
names(combined)
#> [1] "title" "year"  "pages"
c(a = 1, b = 2, 3)
#> a b
#> 1 2 3
c(first = c(x = 1, y = 2), second = 3)
#> first.x first.y  second
#>       1       2       3
c(first = 1:2, second = 3)
#> first1 first2 second
#>      1      2      3
unlist(list(a = 1:2, b = list(c = 3, d = 4:5)))
#>   a1   a2  b.c b.d1 b.d2
#>    1    2    3    4    5

Source: R documentation: names

The last lines are the naming rules of c() and unlist(): an argument name is prefixed to the inner names with a dot when the argument has names (first.x), and followed by a running number when it has none and more than one element (first1, first2). That is how unlist(list(a = 1:2, b = list(c = 3, d = 4:5))) gets a1 a2 b.c b.d1 b.d2. See Lists for the [[ and $ side of named components.

setNames() and unname()

setNames(object, nm) is names(object) <- nm returning the object, which makes it usable inside a pipeline and as a one-liner for a lookup table. It lives in the stats package. unname(obj, force = FALSE) removes the names and the dimnames of an object; for a data frame it removes them only with force = TRUE. A common task is to find the name of the best element: which.max() and which.min() return a named integer index, so names(which.max(x)) is the label.

make.names() and make.unique()

make.names(names, unique = FALSE, allow_ = TRUE) turns arbitrary strings into syntactically valid names: invalid characters become dots, an X is prepended when the first character is not a letter or a dot followed by a non-digit, a reserved word gets a trailing dot, and NA becomes "NA.". Dimensions: dim

The dim attribute implements arrays. The content of the array is stored in a vector in column-major order, and the dim attribute is an integer vector with the extents; R ensures that the length of the vector is the product of the extents, and the length of one or more dimensions may be zero. A vector is not the same as a one-dimensional array: the latter has a dim attribute of length one, whereas the former has no dim attribute (The R Language Definition: Dimensions).

dim(x) <- value accepts NULL or a numeric vector that is coerced to integer by truncation. The replacement checks that the new dimensions are compatible with the length, and it removes any dimnames and names attributes (R documentation: dim). dim() has a method for data frames that returns the number of rows (from the row.names attribute) and the number of columns.

Class

The class attribute is a character vector with the list of classes that an object inherits from; it is the basis of the generic functions of S3. It can be accessed and manipulated virtually without restriction by users: there is no checking that an object actually contains the components that its methods expect. The manual therefore recommends caution, and the use of the specific creation and coercion functions when they are available (The R Language Definition: Classes). All objects have a class, reported by class(): for simple vectors it is the implicit class (the mode, for example "numeric", "logical", "character" or "list", or "matrix", "array", "factor" or "data.frame"), and unclass() removes the effect of a class temporarily (An Introduction to R: The class of an object).

The functions, from the help page of class():

  • class(x) returns the class attribute when there is one, and the implicit class otherwise. oldClass(x) returns only the attribute, and so is NULL for an object without one (including a plain matrix, whose implicit class is computed from dim).

  • class<- and oldClass<- set the attribute; assigning NULL removes it. Assigning an empty character vector also removes the class, which is natural in class(x) <- setdiff(class(x), "ts"). Assigning an implicit class such as "character" coerces the object to that type (the script shows it), while assigning "numeric" to an integer vector leaves it as an integer.

  • inherits(x, what, which = FALSE) tests whether any class of x is in what, or, with which = TRUE, returns the position of each of what in the class vector (0 for no match). R 4.3.0 let what be something other than a character vector, resolved through the generic nameOfClass(), to support alternative object systems.

  • .class2(x) is the full implicit class chain that is used for S3 dispatch (new in R 4.0.0).

  • unclass(x) returns a copy of the object without the class attribute.

  • isa(x, what) is TRUE when all of the classes in what are in class(x) (inherits() needs any of them).

  • is.object(x) is TRUE if the object has a class attribute.

Levels

A factor is an integer vector with two attributes, levels (the character labels) and class equal to "factor". levels(x) returns the attribute, levels<- replaces it, and nlevels(x) is its length. The help page of attributes() stresses that levels is not one of the specially treated attributes, so attr(x, "levels") <- value is not checked: for factors the replacement function levels<- should be used. When it is given a list, levels<- merges several old levels under one new name; renaming one level is the idiom levels(x)[levels(x) == "old"] <- "new".

Which attributes survive which operations

The R Language Definition collects the rules for copying attributes in one section, and says that whether attributes should be copied when an object is altered is a complex area, with the general rules taken from The New S Language (Becker, Chambers and Wilks, 1988):

  • Scalar functions (those which operate element-by-element on a vector and whose output is similar to the input) should preserve attributes, except perhaps the class.

  • Binary operations normally copy most attributes from the longer argument and, if they are of the same length, from both, preferring the values on the first. Here "most" means all except names, dim and dimnames, which are set appropriately by the code for the operator.

  • Subsetting, other than by an empty index, generally drops all attributes except names, dim and dimnames, which are reset as appropriate. Subassignment, on the other hand, generally preserves attributes even if the length is changed. Coercion drops all attributes.

  • The default method for sorting drops all attributes except names, which are sorted along with the object.

Arithmetic and element-by-element functions

The script keeps a helper kept() that returns the names of the attributes of a result. The first group shows the rule for two operands of the same length and of different lengths: the attributes come from both operands when the lengths are equal, from the longer operand otherwise, and the first operand wins when both have the same attribute.

# Binary operations copy the attributes of the longer operand, or of both
# when the lengths are equal, with the first operand winning on a clash.
# Names, dim and dimnames are set appropriately by the operator itself.
kept <- \(v) names(attributes(v))
a <- structure(c(x = 1, y = 2, z = 3), unit = "pages")
b <- structure(c(10, 20, 30), note = "bonus")

# Same length: the attributes of both
kept(a + b)
#> [1] "note"  "unit"  "names"
kept(b + a)
#> [1] "unit"  "note"  "names"

# Different length: the attributes of the longer operand only
kept(a + 1)
#> [1] "unit"  "names"
kept(1 + a)
#> [1] "unit"  "names"
long <- structure(1:6, unit = "pages")
short <- structure(1:2, note = "short")
kept(long + short)
#> [1] "unit"
kept(short + long)
#> [1] "unit"

# On a clash for the same attribute, the first operand wins
c1 <- structure(1:2, tag = "first")
c2 <- structure(3:4, tag = "second")
attr(c1 + c2, "tag")
#> [1] "first"
attr(c2 + c1, "tag")
#> [1] "second"

The next part has the names, which follow their own rule: the names come from the first operand that has them when the lengths are equal, and from the longer operand when they are not, so c(p = 1) + c(r = 10, s = 20) has the names r and s. kept(-a)

kept(a > 1)
#> [1] "names"

Subsetting

[ keeps names, dim and dimnames and drops everything else, including the class, unless a method for the class restores it. Factors, dates and data frames have their own [ methods, which is why they keep their class. An empty index (x[]) is the exception: it returns the object with all its attributes, which is why x[] <- value keeps the shape of a matrix. [[ extracts one element and drops all the attributes of the container; head() and tail() call [.

# Subsetting drops all attributes except names, dim and dimnames

attributes(unclass(x)[1:2])
#> $names
#> [1] "a" "b"
#>
names(attributes(x[1:2]))
#> [1] "names"

Combining, coercing and collecting

c() removes all attributes except the names; c() of dates and factors is carried out by their own methods (since R 4.1.0 c() of factors returns a factor; before, it returned the integer codes). as.vector() removes all attributes including the names for atomic vectors, but not the names of a list or expression; the as.numeric(), as.integer(), as.character() and as.logical() family removes all attributes, including the names. unlist() returns a vector with only the names that it builds, and sapply() and vapply() take the names of the result from the input (a character vector is used as names unless it already has names and USE.NAMES = FALSE).

User attributes as metadata

Attributes are the natural place for metadata that belongs to a value, not to its elements: the unit of a measurement, the shelf where a book stands, the source of a column. The rules of the previous section describe how fragile that is: an operation that does not preserve an attribute loses it silently, so metadata that must survive is better handled in one of three ways. First, make the object a classed list and keep the metadata in a named component (the book class: the shelf would be a seventh field, validated by validate_book()). Second, give the class a constructor and methods that propagate the attribute (a [.shelf_pages that restores unit). Third, put the metadata in an attribute and write a small helper that restores it, as keep_shelf() does for the book below. The last two lines are the usual way to test whether an object has a given attribute: attr() returns NULL for a missing attribute, so test with is.null(); beware of partial matching (exact = TRUE).

source("scenario.R")

# The book of "How print shows attributes", with its shelf attribute
b <- book(
  "Notes on Gravity", "Elias Moreau", "978-0-01-000104-4",
  year = 2017, genre = "Science fiction", pages = 410
)
attr(b, "shelf") <- "B2"

# Copying: modifying a copy leaves the original untouched
b2 <- b
attr(b2, "shelf") <- "C1"
attr(b, "shelf")
#> [1] "B2"
attr(b2, "shelf")
#> [1] "C1"

# Attributes are lost when a book is rebuilt from its fields
b3 <- book(b$title, b$author)
names(attributes(b3))
#> [1] "names" "class"

# A helper that restores the shelf attribute on a new object
keep_shelf <- function(new, old) {
  attr(new, "shelf") <- attr(old, "shelf")
  new
}
b4 <- keep_shelf(book("Ten Winters"), b)
attr(b4, "shelf")
#> [1] "B2"

# Check an attribute exists: attr() gives NULL, so test for NULL
is.null(attr(b3, "shelf"))
#> [1] TRUE
"shelf" %in% names(attributes(b))
#> [1] TRUE

The script in How print shows attributes showed what the shelf attributes look like, and why print(b) does not reveal them (the print method of the book class chooses what to show): ask attributes(b) when in doubt. The attributes class and names of the book list are intrinsic to its S3 structure, so they are always at the front of the list; the user attributes follow. A modified copy has its own attributes (copy-on-modify, see Memory and Copy Semantics).
