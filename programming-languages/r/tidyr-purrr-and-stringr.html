tidyr, purrr and stringr

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. This page uses add-on packages, none of which is part of R: tidyr 1.3.2, purrr 1.2.2, stringr 1.6.0, forcats 1.0.1, lubridate 1.9.5 and readr 2.2.0, together with dplyr 1.2.1 and tibble 3.3.1 wherever a data frame has to be filtered, joined or counted, the tidyverse 2.0.0 meta-package for its start-up message, and lifecycle 1.0.5 (the package behind the function-stage labels, whose version is printed once). They were installed from CRAN, and the lintr 3.4.0 default linters were used only to check the scripts. Base R already has a tool for every job below, and the Data Frames, The apply Family and Functionals, Strings and Regular Expressions, Factors and Dates and Times pages teach those first. This page is about the tidyverse spelling of the same work: what each package adds, which base function it replaces, where its answers differ, and the real error and warning text of the places where it is stricter. The packages are community-maintained by Posit (the tidyverse team) and documented on their own pkgdown sites, which this page cites for package behaviour.

Every example is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines that start with #> are what it printed. The scripts also pass the default lintr linters. Each block stands alone: a block that needs the cleaned shelf data repeats the few setup lines that make it, so any block can be pasted into a fresh session and run. The names books, loans, shelf_today, loan_days and the book() constructor come from the running library-shelf scenario described on the section index: a script that needs them starts with source("scenario.R"), and the CSV files books.csv and loans.csv sit in the working directory. The books data frame has messy title, author, isbn and genre columns, and loans has one impossible date (2025-02-30) and one return date before its loan date, which is what the cleaning examples work on. Tibbles are printed with the pillar package, whose output uses the typographic characters of a UTF-8 locale. Where a message contains quotation marks or bullets, they are the ones R and the cli package print in such a locale.

This page is the second of the three data-manipulation pages. The tidyverse and dplyr covers the data-frame verbs (filter(), mutate(), summarise(), joins) that the shelf examples use without explaining them, and data.table is the other large ecosystem. Dates, strings and factors are first taught with base R on their own pages; here lubridate, stringr and forcats are shown next to the base function they correspond to, not re-taught. Parallel iteration with in_parallel() belongs to Parallel and Asynchronous Computing.

The packages and what they replace

The six packages answer six separate jobs. They share conventions (the data comes first, so they work with the native pipe |> of Pipes and the Native Pipe; names are lower-case with underscores; arguments after the required ones are named; errors are formatted by the rlang and cli packages), but each can be used alone.

Reading data with readr

readr reads delimited text into a tibble. read_csv() is read_delim() with a comma, and the same family has read_csv2() (semicolon, decimal comma), read_tsv() and read_delim() for other separators. Since readr 2.0.0 (2021-07-20) the engine is vroom, which reads files lazily and uses several threads; readr 2.1.0 turned the lazy reading back off by default because it kept files locked on Windows. The differences from read.csv() that matter on the shelf data are in the first block: text fields are trimmed (trim_ws = TRUE), so " the quiet streets " loses its blanks while read.csv() keeps them; empty fields are NA in every column, text included (na = c("", "NA")), where read.csv() leaves an empty string in a character column; and whole numbers are read as doubles (year is <dbl>), where read.csv() gives integers. The column types are guessed from the first guess_max rows, at most 1000.

library(readr)

# read_csv() guesses the column types from the first rows. Text fields are

col_types fixes the types instead of guessing them, and cols() builds the specification (spec() printed one above). Dates are col_date() with an optional format. A value that cannot be parsed becomes NA and readr records where: the call gives a warning and problems() returns a tibble with the row, the column, what was expected and the text that was found. The impossible date 2025-02-30 of the shelf data is such a value. The problems() result also has a file column with the path that was read, which is left out of the output below.

Reshaping with tidyr

tidyr starts from an idea about the shape of a table. In tidy data each variable is a column, each observation is a row and each value is a cell (tidyr package documentation: Tidy data). A report that shows genres down the side and months across the top is wide: the months are the values of one variable, month, spread over several columns. Analysis code (grouping, plotting, modelling) usually wants the long form, with one row per genre and month and the count in one column, and a report wants the wide one. Base R converts between them with reshape(), stack() and table(), which Data Frames explains with the same data; reshape() takes the names of the id, time and value columns in several arguments and builds the new column names itself, which is the part many people find hard to remember. tidyr 1.0.0 (2019-09-11) added pivot_longer() and pivot_wider() as redesigned replacements for gather() and spread(), with the argument names saying which columns the names and the values come from.

The data for the next two blocks is the number of loans per month and genre in 2026: the ISBNs of the loans are matched with the (cleaned) ISBNs of the books, the genre is trimmed and put in lower case, and count() gives one row for every month-and-genre pair that occurs.

pivot_wider(): long to wide

pivot_wider() takes a long table and makes one new column for each distinct value of names_from, filled from values_from. The columns that are neither are the identifiers (id_cols, by default all of them), and one output row is made for every distinct combination of them. A combination that does not occur in the input is NA in the output, unless values_fill gives a value. Since tidyr 1.3.0 the optional arguments must be named (... sits right after data). names_prefix goes in front of the new names, names_sep (default "_") joins the parts of a new name (the value name and the names_from value when values_from has several columns), names_glue builds the names from a template, names_sort and names_vary control the column order, names_expand and id_expand (tidyr 1.2.0) make the implicit factor combinations explicit, and unused_fn says how to summarise the columns that are not used.

library(dplyr, warn.conflicts = FALSE)

source("scenario.R")

pivot_longer(): wide to long

pivot_longer() is the reverse. cols selects the columns to gather, names_to is the name of the new column that receives their names and values_to the name of the one that receives their values. The selection uses the tidyselect language (!genre means every column but genre, starts_with(), matches() and the rest), and a selection that matches nothing is an error. Two arguments turn the information in the names into columns: names_sep splits at a separator and names_pattern takes the pieces from the groups of a regular expression; names_to then has one name for each piece, and the special name .value makes a piece the name of a value column, which is how several measures are gathered at once. names_transform and values_transform convert the new columns (a single function applies to all of them), names_ptypes and values_ptypes check their types, values_drop_na = TRUE drops the rows whose value is missing, names_prefix removes a prefix and cols_vary (tidyr 1.3.0) sets the order of the output rows.

library(dplyr, warn.conflicts = FALSE)
library(tidyr)
source("scenario.R")

# The wide report of the previous script.
books$genre <- tolower(trimws(books$genre))
books$isbn <- gsub("[^0-9X]", "", books$isbn)
wide <- loans |>
  filter(loan_date >= as.Date("2026-01-01")) |>

Splitting and combining columns

A column that holds several pieces of information in one string, such as "Le Guin, Ursula K." (a surname, a comma and a given name) or "978-0-306-40615-7" (five parts of an ISBN), is split into columns by the separate_wider_*() family, which tidyr 1.3.0 (2023-01-24) added. The functions are separate_wider_delim() (split at a delimiter), separate_wider_position() (split at fixed widths) and separate_wider_regex() (take the pieces from a vector of regular expressions); the long counterparts separate_longer_delim() and separate_longer_position() split into rows instead. They replace separate(), extract() and separate_rows(), which the tidyr reference marks as superseded: they stay in the package and receive only critical bug fixes. The tidyr NEWS describes them as thorough refreshes with better performance, a more consistent interface and a new approach to handling problems: a mismatch between the number of pieces and the number of names is an error that says how to diagnose it.

separate_wider_delim() and separate_wider_position()

separate_wider_delim(data, cols, delim, names = , names_sep = ) splits each value of the selected column at the literal delim, which is not a regular expression. names gives the new column names in order; names_sep names the pieces <column>_1, <column>_2, and so on, when the number of pieces is not known. An NA in names drops that piece. The original column is removed unless cols_remove = FALSE. separate_wider_position(data, cols, widths) takes a named integer vector: each width is the number of characters of a piece, and an unnamed width is skipped.

Too few and too many pieces

The most useful part of the new design is what happens when a value does not have the expected number of pieces. By default every function stops and says how many values were wrong and which argument to set. too_few has the options "error" (the default), "debug" and "align_start", plus "align_end" for the delimiter function; too_many (delimiter and position functions) has "error", "debug" and "drop", plus "merge" for the delimiter function. "debug" adds three columns, named after the input column: _ok is TRUE for the values that fit, _pieces is the number of pieces found (_matches for the regex function) and _remainder is the text that was left over; it also warns that it did so, because debug mode is meant for diagnosis and not for production code.

The block splits every author of the shelf data on ", ". Only one of the 16 books has an author with the surname first; the other 15 are in the form "Ursula K. Le Guin", so the default stops with the number of values that were too short, and "debug" shows which ones. "align_start" would fill the missing pieces with NA at the end, which is rarely what you want for names. The last calls give an ISBN too few names: "error" again, "merge" keeps the rest in the last column, and "drop" discards it.

Missing values and implicit gaps

Nesting and rectangling

A data frame column can be a list, and when it is a list of data frames the table is nested: one row per group, with the group’s rows inside a cell. Nesting is the tidyverse’s answer to "do something for each group and keep the results next to the group", the job that split() plus lapply() does in base R (see Data Frames). Rectangling is the opposite problem: deeply nested lists, usually from JSON, are turned into a table.

nest() and unnest()

nest(.data, .by = ) groups by the columns of .by and puts the remaining columns, as a tibble, in a list-column called data (.key renames it). The other form names the list-column and the columns to nest, nest(history = c(loan_id, loan_date)), and groups by whatever is left; since tidyr 1.3.0 .key is used whenever ... is not given. unnest() reverses it, repeating the other columns for every row. The rows of a list-column can be summarised with vapply() or with purrr::map_int() and its relatives (see purrr below); dplyr also has nest_by() for row-wise work on nested data (see The tidyverse and dplyr). chop() and unchop() do the same for vectors instead of data frames, and pack() and unpack() make and unmake data-frame columns.

Rectangling nested lists

Data that comes from a web API or a JSON file is a list of records, each a list that can contain other lists and vectors, and the records do not all have the same fields. tidyr turns it into a table in two steps: put the list in a column of a tibble, then unnest it one level at a time. unnest_wider() makes each named element a column (a record that lacks the element gets NA), unnest_longer() makes each element of a vector a row, and hoist() pulls out the pieces named by a path, the way purrr::pluck() does, and keeps the rest. Each level of nesting is a decision, wider or longer, and the result of the first call shows the structure that is still to be unpacked: <named list [2]> is a record, <chr [2]> a vector, <NULL> an empty one.

The record in the block has a nested member (a record of its own, in which one member has no card) and a renewals vector (empty for one loan). names_sep prefixes the unnested names, which avoids collisions; unnest_longer() drops the records whose vector is empty unless keep_empty = TRUE, a behaviour that tidyr 1.3.0 made consistent for NULL and for empty vectors.

hoist() is the shortcut when only a few fields are wanted from deep inside the records. Each argument is new_name = path, where the path is a character vector of names, an integer vector of positions, or a list that mixes both (list("renewals", 1L) is the first renewal). Iterating with purrr

purrr is the tidyverse’s answer to the apply family. The idea is the same as vapply(): a function is applied to every element, and the suffix of the function name says what kind of vector you get back, so a result of the wrong shape is an error that names the element and not a surprise further down the script. The apply Family and Functionals has a full comparison table of purrr and base functions and its own runs of the error messages; this section covers what that page leaves out: the shapes the results come in, combining them, and turning errors into values. The data comes first and the function second in every purrr function, which is what a pipe wants. purrr needs R 4.1 or later (purrr 1.1.0 dropped support for older versions).

map() and the type-specific variants

map(.x, .f, ..., .progress = FALSE) returns a list with the names of .x. Its siblings map_lgl(), map_int(), map_dbl() and map_chr() return an atomic vector and require every result to be a single value of that type. The conversions follow the vctrs rules: an integer can become a double, a double only an integer if no precision is lost, and a logical and the numbers 0 and 1 are interchangeable; a number is no longer converted to a string (deprecated in purrr 1.0.0, an error since purrr 1.2.0), so as.character() has to be explicit. map_vec() is the version for results that are not one of the four basic types (dates, factors, date-times): it keeps the class, where map_dbl() would have dropped it. modify() keeps the type of its input, so a data frame in is a data frame out.

.f can be written in four ways. A named function and an anonymous function (\(x) x + 1) are the ones to use. A formula (~ .x + 1) works, but the purrr documentation lists it as no longer recommended. A string, an integer or a list is a shortcut for pluck() on each element: "name" takes the element called name, 2L the second element, and list("tags", 1L) the first element of tags; a .default is returned where the element is missing or NULL. The documentation also advises against passing constant arguments through ... and in favour of a lambda that calls the function with them, which makes it clear which arguments belong to which function.

library(purrr)

# map() always returns a list, with the names of its input.

map2(), pmap(), imap() and walk()

map2() walks two vectors in step and pmap() any number: its first argument is a list of the arguments, matched by name or position, and a data frame is such a list (one element per column), so pmap() is the row-wise map of a data frame. Since purrr 1.0.0 these functions follow the tidyverse recycling rules: only a length-1 input is recycled and the others must have the same length. imap() calls the function with each element and its name, or its position when the vector has no names. walk(), walk2(), pwalk() and iwalk() are for the side effect of the function (printing, writing a file); they return their first input invisibly so that they can sit in the middle of a pipeline.

library(purrr)
source("scenario.R")

# map2() walks two vectors in step; the lengths must match (or be 1).
title <- trimws(books$title[1:3])
author <- books$author[1:3]
map2_chr(title, author, \(t, a) paste0(t, " - ", a))
#> [1] "The Dispossessed - Ursula K. Le Guin"
#> [2] "Pride and Prejudice - Jane Austen"
#> [3] "the quiet streets - Mara Quill"

# pmap() takes a list (or a data frame) of the arguments, matched by name.
books[1:3, c("title", "year", "pages")] |>
  pmap_chr(\(title, year, pages) {
    sprintf("%s (%s): %s pages", trimws(title), year, pages)
  })
#> [1] "The Dispossessed (1974): 387 pages"
#> [2] "Pride and Prejudice (1813): 432 pages"
#> [3] "the quiet streets (2019): 214 pages"

# imap() passes the name, or the position when there is no name.
imap_chr(c(a = "x", b = "y"), \(value, name) paste0(name, "=", value))
#>     a     b
#> "a=x" "b=y"
imap_chr(c("x", "y"), \(value, i) paste0(i, "=", value))
#> [1] "1=x" "2=y"

# walk() is for side effects: it returns its input invisibly, so it can sit in

loans <- loans[nzchar(loans$member), ]
loans_by_member <- split(loans$loan_id, trimws(tolower(loans$member)))

walk(c("first", "second"), \(s) cat("shelf:", s, "\n"))

Combining the results

A list of data frames is combined with list_rbind() and list_cbind(), and a list of vectors with list_c(), all added in purrr 1.0.0. They replace map_dfr() and map_dfc(), whose names suggested the strict single-value contract of map_dbl() but which accepted results of any size and relied on dplyr::bind_rows(). The purrr documentation marks map_dfr() and its relatives superseded, which means that they still work and receive only critical bug fixes: map(x, f) |> list_rbind() is the replacement. list_flatten() removes one level of nesting and replaces flatten(); its name_spec is a glue template for the names ("{outer}_{inner}" by default), and is_node (purrr 1.2.0) says which elements count as nodes. list_simplify() reduces a list of length-1 vectors to one vector (the simplify() replacement), and list_transpose() turns a list of records into a record of vectors (the transpose() replacement).

source("scenario.R")

counts <- map(by_member, \(d) {

Selecting and folding

keep() and discard() select the elements for which a predicate is TRUE and FALSE; keep_at() and discard_at() (purrr 1.0.0) select by name, and detect() and detect_index() return the first match; every(), some() and none() summarise a predicate over the whole input, and since purrr 1.2.0 the predicate must return a logical scalar. reduce(.x, .f, ..., .init, .dir) folds the list from the left with a two-argument function, and accumulate() keeps the intermediate values; with .dir = "backward" they fold from the right (the right = TRUE of Reduce(); the older reduce_right() was removed in purrr 1.2.0). reduce2() takes a second list for the third argument of the function.

library(purrr)

# keep() and discard() select by a predicate (compare Filter()).
keep(books$pages, \(p) !is.na(p) && p > 400)

#> [1] 14

#> [1] TRUE

#> [1] TRUE
none(books$pages, \(p) isTRUE(p > 1000))

Turning errors into values

safely(), possibly() and quietly() take a function and return a function that does not stop. safely(.f) returns a list with the elements result and error, exactly one of them NULL, so a map over a whole vector gives a list of such pairs, and list_transpose() turns it into one list of results and one of errors. possibly(.f, otherwise) returns otherwise instead of the error; its default NULL (purrr 1.0.0) is replaced here by NA_real_ so the result can be a numeric vector. quietly(.f) captures the printed output, the messages and the warnings of a call, and returns them with the result. insistently() retries a function with a rate (rate_delay(), rate_backoff()), which is the right tool for a flaky web request and is not run here. All of them build on tryCatch() and withCallingHandlers() of Conditions and Error Handling, and their error is the condition object, so its message and call can be read.

library(purrr)

# safely() wraps a function so it returns list(result, error) and never stops.
safe_log <- safely(log)
safe_log(100)
#> $result
#> [1] 4.60517
#>
#> $error
#> NULL
#>
str(safe_log("a"))
#> List of 2
#>  $ result: NULL
#>  $ error :List of 2
#>   ..$ message: chr "non-numeric argument to mathematical function"
#>   ..$ call   : language .f(...)
#>   ..- attr(*, "class")= chr [1:3] "simpleError" "error" "condition"

# Over a vector: transpose the list of pairs into results and errors.
res <- map(list(1, 10, "a", 100), safe_log) |>
  list_transpose()
res$result
#> [[1]]
#> [1] 0
#>
#> [[2]]
#> [1] 2.302585
#>
#> [[3]]
#> NULL
#>
#> [[4]]
#> [1] 4.60517
#>
map_lgl(res$error, is.null)
#> [1]  TRUE  TRUE FALSE  TRUE

# unless otherwise is given (purrr 1.0.0).
possible_log <- possibly(log, otherwise = NA_real_)
map_dbl(list(1, 10, "a", 100), possible_log)
#> [1] 0.000000 2.302585       NA 4.605170

What purrr stops on

The strictness is the point. The block shows the text of the failures that the map family raises, each preceded by the iteration that failed. Since purrr 1.0.0 the error raised by the function inside map() is wrapped in an error that tracks the iteration, and since purrr 1.0.1 that wrapper has the class purrr_error_indexed, records the location (the position) and the name (for a named input) and keeps the original condition as parent. A progress bar is requested with .progress = TRUE.

library(purrr)

msg <- function(expr) {
  res <- tryCatch(expr, error = identity, warning = identity)
  cat(conditionMessage(res), "\n")
}

# A result of the wrong length or the wrong type (compare vapply()).
msg(map_dbl(1:3, \(x) c(x, x)))

Pattern modifiers: regex(), fixed(), coll() and boundary()

A string used as a pattern is a regular expression. Wrapping it in a modifier changes what it means: regex() takes the flags ignore_case, multiline, comments and dotall; fixed() compares the bytes of a literal string and is what fixed = TRUE is in base R; coll() compares strings with the collation rules of a locale, which matters for case folding (the Turkish dotted and dotless i) and for characters that can be written in two ways; and boundary() matches the edges of characters, words, sentences or line breaks, so that str_split(x, boundary("word")) splits on words without a pattern. str_equal() compares two strings by Unicode equivalence, which == does not. str_escape() makes a literal string safe to paste into a regular expression, the stringr counterpart of the escaping routine of the base page.

The regular-expression dialect is the part that differs most from base R. Base R has three engines: TRE (the default, POSIX extended expressions), PCRE2 (perl = TRUE) and no regular expression at all (fixed = TRUE). stringr has one, ICU: it has lookaround, named groups, the \p{...} property classes and flags, and its \d and \w are Unicode-aware, so \d matches the Arabic-Indic digits that grepl() with the default engine did not match in the base page. It is not identical to PCRE2: the error messages are ICU’s own (they carry a constant such as U_REGEX_MISMATCHED_PAREN), and a few escapes differ, so a pattern copied from a perl = TRUE call is tested before it is trusted. The help for stringr’s modifiers and the package’s Regular expressions article describe the dialect.

What stringr stops on

Most of the strictness was added in stringr 1.5.0 (2022-12-02): an empty pattern or a boundary() pattern in str_detect(), str_starts(), str_ends() and str_subset() is an error (str_detect(x, "") used to be TRUE for every non-empty string), an NA pattern is an error since stringr 1.6.0, and arguments of the wrong type are errors where they used to be warnings. The block prints the messages. Deprecated functions and arguments give a lifecycle warning of class lifecycle_warning_deprecated, once per session. An invalid pattern raises an error from ICU, which has no preceding warning, unlike the TRE and PCRE2 errors of base R. str_view() is the debugging tool: it prints the strings with the matches highlighted (since 1.5.0 with ANSI colour in the console and no HTML widget); here the colour is replaced by angle brackets.

Parsing and reading the parts

Intervals, comparisons and rounding

An Interval is the span between two specific instants, built with interval(start, end) or with the operator %--%. It knows its start and end (int_start(), int_end()), its length in seconds (int_length()) and can be converted to a period or measured in any unit with time_length(), which is the right way to say "days between two dates" when months and years are involved. %within% asks if a date, or an interval, lies inside an interval, and int_overlaps() whether two intervals share any time (lubridate 1.9.0 fixed %within% for intervals that run backwards). The loans of the shelf data are intervals from the loan date to the return date, and the 25 overdue returned loans are the ones longer than loan_days. floor_date(), ceiling_date() and round_date() round to a unit ("day", "week", "month", "quarter", "year" and the smaller ones), with week_start for the first day of the week, which is how the loans per quarter are counted.

Periods and durations

A period is a span in calendar units, a duration a span in exact seconds, and the two differ whenever the calendar does not have a fixed length. days(1) is "one day on the clock" and ddays(1) is 86400 seconds. Across the change to daylight saving time the first keeps the clock reading (noon is still noon the next day) and the second adds 24 hours of elapsed time, so the two results are an hour apart. Months and years are written as periods (months(), years()) because a month has no fixed length; the duration dmonths() converts a month into a fixed number of seconds. Adding a period that lands on a day that does not exist gives NA; %m+% and %m-% are the operators that roll back to the last valid day, and they are what to use for "same day next month". The Europe/Madrid change of 2026-03-29 and the leap day of 2024-02-29 are the examples.

The tidyverse packages label their functions with the four lifecycle stages of the lifecycle package: experimental, stable, deprecated and superseded. A superseded function stays in the package and gets only critical bug fixes, and it gives no warning, which is why so many old tutorials still run (each superseded form named in the next section ran without a warning on the versions of this page). A deprecated function has a better alternative and is scheduled for removal, and calling it gives a warning once per session; the reduce_right() of purrr, removed in purrr 1.2.0, is an example of a function that went all the way.
