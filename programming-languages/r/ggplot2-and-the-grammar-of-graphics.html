ggplot2 and the Grammar of Graphics

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. This page uses the add-on package ggplot2 version 4.0.3 (the CRAN release of 2026-04-22), one of the core packages of the tidyverse, and a few packages that come with it: scales 1.4.0 (one label function and one out-of-bounds function are called by name), S7 0.2.2 (to ask what a plot object is), svglite 2.2.2 (the SVG writer that ggsave() uses) and dplyr 1.2.1 (a single pipeline, called as dplyr:: functions, prepares one summary table). gtable 0.3.6 supplies the class of the rendered plot and is not called by name, and rlang 1.3.0 supplies the quosures that aes() stores and the embrace operator behind {{ }}; it is called by name once, as rlang::quo_get_expr(), to show what a mapping holds. Behind the scenes ggplot2 also uses cli 3.6.6 (the formatting of its messages), lifecycle 1.0.5 (the deprecation warnings), viridisLite 0.4.3 and RColorBrewer 1.1.3 (the viridis and brewer palette scales) and, when it is installed, ragg 1.5.2 (the PNG files that ggsave() writes). Every other preparation step is base R (merge(), aggregate(), subset(), table()), and the drawing engine underneath is the grid package that ships with R. The packages patchwork, cowplot and gridExtra are named in one sentence and not installed here, so they are never run. The lintr 3.4.0 default linters were used only to check the scripts.

ggplot2 is a package for describing a graphic rather than drawing it: the data, the mapping from variables to visual properties, the shapes, the statistical summaries, the scales, the coordinate system, the panels and the theme are separate parts that are added together with the plus operator into one object, and drawing happens later, in a separate step. This page explains that model and where each part lives in the object, shows what every part does to the data by printing the data behind the plot (the plots themselves are not reproduced on this page), and rebuilds the four charts of the shelf scenario in ggplot2. It also collects the messages and warnings that ggplot2 prints, with their real text, and the places where tutorials written before 2022 no longer match ggplot2 4.0.

Every example is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines that start with #> are what it printed. The scripts also pass the default lintr linters; a # nolint: comment marks a line where the idiom on show is what a default linter dislikes. The names books, loans and loan_days come from the running library-shelf scenario described on the section index: a script that needs them starts with source("scenario.R"). The genre column of books holds nine spellings of six genres, so scripts that group by genre first run books$genre <- tolower(trimws(books$genre)); cleaning is the subject of Strings and Regular Expressions and Data Frames. No script prints a plot at the top level or opens a window. Each one either writes the picture to a file with a name from tempfile(), which is never printed because it contains a session-specific directory, or only prints what the plot contains. Where a ggplot2 message has a second line that starts with a small i in a circle or a cross, those are the bullet symbols that the cli package prints in a UTF-8 locale.

This page continues Base Graphics and Devices, which draws the same shelf charts with the graphics package, and Grid Graphics and Lattice, which explains the grid model that ggplot2 draws with. The mapping step relies on the data masks of Evaluation and Non-Standard Evaluation, and the plot object on the system described in The S7 Object System.

The grammar of graphics

A chart type such as "scatter plot" or "bar chart" is a name for one combination of choices, not a primitive. The statistician Leland Wilkinson made that observation the basis of his book The Grammar of Graphics (Springer, 1999; second edition 2005): a graphic is a sentence built from a small number of independent parts (the data, how variables are turned into visual properties, the geometric shapes, the statistical transformations, the scales, the coordinate system, the panels), and different sentences give the familiar chart types and many unfamiliar ones. Hadley Wickham adapted that idea to R in the paper "A Layered Grammar of Graphics" (Journal of Computational and Graphical Statistics, 2010), and ggplot2 is its implementation. Both are community and book material, not part of the official R documentation, and this page does not reproduce them; what it describes is ggplot2 4.0.3 as its own documentation describes it. The package’s introduction names seven composable parts, and says that a chart needs at least three of them (data, a mapping and a layer) because the scales, facets, coordinates and themes have defaults (ggplot2 package documentation: Introduction to ggplot2).

The pipeline below follows the data through those parts in the order ggplot2 applies them. First ggplot() and the plus operator only record what was asked for in an object. Drawing it takes three stages. ggplot_build() runs the data through the layers and the scales and returns a list of data frames, one per layer, ready to draw; the reference page for it calls this the step that performs everything necessary to produce an object that can be rendered. ggplot_gtable() turns that into a table of grid graphical objects (grobs), applying the theme and building the legends. And a graphics device draws the table. print() on a plot, the automatic printing of a plot at the console, and ggsave() all run the three stages. The diagram orders the facets last, as the page would explain them, but the assignment of rows to panels is decided at the very start of the build (the plot’s layout is set up before the aesthetics are evaluated), and the panels themselves are laid out and labelled in the gtable stage.

Every box in the diagram corresponds to a function family with a regular name: geom_*() and stat_*() build layers, position_*() the adjustments, scale_<aesthetic>_<type>() the scales, and coord_*(), facet_*() and theme_*() the rest. A name that follows the pattern can be guessed and found with tab completion, and the regularity is the reason the same few ideas cover a very large number of charts. The rest of this page takes the stages one by one, always by looking at the data or the object that the stage produced.

A plot is an object

ggplot() does not draw anything. It returns an object, and everything after it with a plus sign returns a new object with one more component. The reference page for ggplot() says that it initializes the object, declares the default data frame and the aesthetic mappings that all later layers share unless they override them, and is almost always followed by a plus sign (ggplot2 package documentation: ggplot). The script below creates a plot with no layers, adds one, and then takes the three stages of the pipeline apart: the object, the built data, and the gtable.

Five things to take from the output. The class vector of a plot starts with "ggplot2::ggplot": since ggplot2 4.0 the plot is an S7 object (see ggplot2 4.0 on S7). Adding a layer returns a new plot and leaves the old one with no layers: the plot is a value, and p can be kept and extended into several plots. summary() of a plot prints the data frame’s columns and size, the mapping, the facets and the layers, which is the quickest way to check what a long expression built. ggplot_build() returns an object of class "ggplot2::ggplot_built" whose data (built$data, one data frame per layer) already has the aesthetics evaluated and the scales applied: the first rows show the numbers x and y that will be drawn, the default shape, colour, size and stroke that the geom filled in, the panel the row belongs to and the group. ggplot_gtable() takes that built object and returns a gtable, a grid graphical object, and measuring the text for it needs a graphics device, which is why the script opens svg() to a temporary file around the call. The reference page for ggplot_build() documents the helpers that read the middle stage, layer_data() (the data of layer i) and layer_scales() (the scales of a panel), and in 4.0 their new names get_layer_data() and get_panel_scales(); the page says they are useful for tests, and this page uses layer_data() as a window on what a layer will draw. In ggplot2 4.0 the reference page also describes the internal function build_ggplot() as the builder and ggplot_build() as vestigial; ggplot_build() is the one that is exported by the package and the one to call.

Printing, ggsave() and the default device

A plot object is drawn when it is printed. At the console the value of an expression is printed automatically, so typing the name of a plot draws it. Inside a script that is executed with source(), inside a function or inside a loop, nothing is printed automatically and a plot that is never passed to print() is never drawn; this is a frequent surprise, and it has its own entry in the R FAQ, which names ggplot2 graphics among the objects that are created but not displayed until their print() method runs (R FAQ 7.22: Why do lattice/trellis graphics not work?). The documentation of print.ggplot() makes the same point: the default top-level print method does it for you, and an explicit print() is needed to draw a plot inside a function or a for loop (ggplot2 package documentation: print.ggplot).

The other half of the surprise happens under Rscript. No device is open when the script starts. The first operation that needs one, whether drawing a plot or just measuring text for ggplotGrob(), opens the default device, which for a non-interactive session is the pdf device, and the pdf device writes a file called Rplots.pdf in the working directory. The script below shows it, and cleans up after itself; code that is meant to run unattended should open its own device, or use ggsave(), so that no stray file appears.

library(ggplot2)
source("scenario.R")
known <- subset(books, !is.na(pages) & !is.na(year))
p <- ggplot(known, aes(pages, year)) + geom_point()

# Under Rscript no device is open until something needs one.
dev.cur()
#> null device
#>           1
g <- ggplotGrob(p) # measuring text opens the default device
dev.cur()
#> pdf
#>   2
file.exists("Rplots.pdf")
#> [1] TRUE

# Clean up: close the device and delete the file it wrote.
invisible(dev.off())
unlink("Rplots.pdf")
file.exists("Rplots.pdf")
#> [1] FALSE

The plus operator

Everything that can be added to a plot is added with the plus operator, which is a method of the plot class and returns a new plot. The script below adds a layer, a second layer, a scale, a coordinate system, a facet specification, a complete theme and a title, then shows where each landed. The plus operator is a binary operator, so it must end the line when an expression continues on the next one: a line that starts with a plus is a new statement, and ggplot2 detects that case and says so.

Data and aesthetics

The first argument of ggplot() is the data, a data frame (the reference page says that anything else is converted by fortify(); the shelf books and loans of Data Frames are data frames already). The second is the mapping, built by aes(). A mapping is a set of pairs: the name of an aesthetic on the left, an expression on the right that is evaluated in the data to give that aesthetic’s values. The common aesthetics are x and y, colour (also spelt color), fill, shape, size, alpha, linewidth, linetype, label and group; each geom has a list of those it understands, printed by GeomPoint$aesthetics() in the script below, and the article on aesthetic specifications says which values each one accepts (ggplot2 package documentation: Aesthetic specifications).

aes() quotes its arguments. Like quote() in Language Objects and Quoting, it does not evaluate genre; it records the expression together with the environment where it was written (a quosure), and ggplot2 evaluates it later, in the data. That is the data mask of Evaluation and Non-Standard Evaluation, and it is the reason a column name can be written without quotes or books$.

The distinction between mapping and setting causes more confusion than any other. An aesthetic inside aes() is a mapping: it is evaluated against the data, goes through a scale, and gets a legend. The same name outside aes(), as an argument of the geom, is a setting: a constant for the layer, stored in aes_params, with no scale and no legend. The script shows both: the mapped colour column holds the hexadecimal colours the discrete colour scale picked for each genre, and the set colour holds the constant. The classic mistake, aes(colour = "red"), maps the constant string: it is a one-value variable, so it gets the first colour of the default palette (a salmon pink, #F8766D) and a legend with one entry called "red". Write colour = "red" outside aes().

Groups

Several geoms draw one shape per group, for example one line for each group. The group aesthetic says which rows belong together, and ggplot2 builds it by default from the interaction of all the discrete variables in the mapping (the group column of the built data in the first script was -1, meaning no discrete variable). When a line plot comes out as a single zigzag through all the groups, or as a set of single points, the cause is the group aesthetic: the cure is aes(group = ...), and the message in the section on messages, "Each group consists of only one observation", is ggplot2 pointing at it.

Functions that take column names: {{ }} and .data

A function that builds a plot from a column the caller names has the problem described in the page on non-standard evaluation: aes(var) quotes the symbol var, not the argument that var stands for. Tidy evaluation, from rlang, solves it, and aes() supports it: embracing the argument with {{ var }} passes on what the caller wrote, and the .data pronoun indexes the data with a string held in a variable. The .data pronoun is re-exported by ggplot2 and the embrace operator is syntax that aes() understands, so no other package needs to be attached.

library(ggplot2)
source("scenario.R")
known <- subset(books, !is.na(pages))

shelf_plot <- function(df, var) {
  ggplot(df, aes({{ var }})) + geom_histogram(binwidth = 100)

p <- shelf_plot(known, pages)

Layers: geoms, stats and positions

The heart of a plot is its layers. The introduction article says that every layer has three important parts: the geometry that decides how the data is displayed, the statistical transformation that may compute new variables from the data and affect which of it is shown, and the position adjustment that mostly decides where each piece of data is displayed. A layer is built either with a geom_*() or with a stat_*() function, and which one is used only decides which of the three parts the function sets as its default; the other two stay arguments (ggplot2 package documentation: Introduction to ggplot2). Underneath both is layer(), which takes the geom, the stat and the position explicitly and is what an extension package calls (ggplot2 package documentation: layer). The script prints the triple for a representative set of constructors.

Bars: geom_bar() and geom_col(), histograms, boxes and smooths

geom_bar() and geom_col() are the pair that older tutorials mix up. geom_bar() takes only x (or only y) and counts the rows at each value; giving it a y as well is an error. geom_col() takes a y and draws a bar of that height; omitting it is the other error. The tutorials that write geom_bar(stat = "identity") to draw given heights were writing geom_col() by hand: the reference page says that geom_col() uses stat_identity() and leaves the data as it is. geom_histogram() bins a continuous variable by binwidth or by bins (30 by default, with a message that says so) and counts the rows in each bin; the script below uses binwidth = 7 with boundary = 0 so that the bins are weeks starting from day 0. geom_boxplot() gets its five numbers and its outliers from the stat. geom_smooth(method = "lm") fits the model and draws the line and its band; it prints a message when the formula was not given.

layer_data() is the tool for reading what a layer will draw. Stats and computed variables

A stat is a function from the layer’s data to new data. geom_bar() replaces the rows by counts; geom_smooth() replaces them by a fitted curve; stat_summary() replaces the rows of each group by a summary. The output has new columns, the computed variables, and the geom reads some of them by default: the histogram’s bars read count as their height because StatBin$default_aes maps y to after_stat(count), as the script prints. To use a different computed variable, map it with after_stat(), inside aes(): aes(y = after_stat(density)) turns a histogram of counts into a density scale, and an expression such as after_stat(count / sum(count)) can compute from the columns the stat produced. The reference page for the evaluation functions lists the three stages at which an aesthetic can be mapped: from the data, after the stat (after_stat()), and after the scale has mapped it (after_scale()); after_stat() replaces the older stat() and the dot-dot notation (ggplot2 package documentation: Control aesthetic evaluation). after_scale() works on the visual value that the scale produced, which is how the box outline in the script is made a darker version of its fill without a second scale.

Position adjustments

When shapes land on the same position, the position adjustment decides what happens. It is the third part of a layer, and it works on the data after the stat, as a function from the data to data. position_stack() (the default of bars) puts the shapes on top of each other; position_dodge() puts them side by side, each taking part of the slot; position_fill() stacks and rescales every stack to the interval from 0 to 1, so that the bars show shares; position_jitter() adds random noise. The argument can be the name (position = "dodge") or the object, which is the form to use when the adjustment has its own arguments (position_dodge(preserve = "single"), position_jitter(width = 0.2, height = 0, seed = 282)). The reference pages are ggplot2 package documentation: position_dodge, ggplot2 package documentation: position_stack and ggplot2 package documentation: position_jitter.

Scales

A scale is the dictionary between data values and visual values for one aesthetic. The introduction article describes scales as the translation from what is shown on the graph back to an understanding of the data: they update the limits, set the breaks, format the labels and may apply a transformation, and in the plot they are represented by guides, the axes and legends. The functions are named scale_<aesthetic>_<type>(), where the aesthetic is one from the mapping and the type says what kind of scale it is: scale_x_continuous(), scale_x_date(), scale_colour_manual(), scale_fill_brewer(), scale_colour_viridis_d(). The type matches the data: continuous data gets a continuous scale, a factor a discrete one, a Date a date scale (Dates and Times covers the class). If no scale is added for a mapped aesthetic, ggplot2 adds the default one for the type of the data, and it is that default scale which the scripts below read.

A scale has two jobs, in this order, on every layer’s data: it is trained, which means it learns the range of the data (the limits for a continuous scale, the levels for a discrete one) across all the layers that use the aesthetic, and then it maps each data value to a visual value (a position, a colour, a size). The script below reads the trained scales from a built plot to show both steps, and then changes the limits, the breaks and the labels of a position scale, applies a logarithmic transformation, swaps the colour scale, and sets the titles with labs().

Limits, dropped rows and zooming

The most common warning in ggplot2 is not about a mistake in the code. It is about data that cannot be drawn. A missing value in a mapped aesthetic cannot be placed, and a value outside the limits of a scale has been turned into a missing value by the scale; in both cases the row is removed before drawing and ggplot2 says how many were removed and by which layer. The same mechanism explains two spellings that look equivalent and are not: xlim(100, 300) (and lims(), and limits = in a scale) set the limits of the scale, so the data outside them is converted to NA and removed, and every stat then works on what is left; coord_cartesian(xlim = c(100, 300)) only changes the window through which the plot is seen, and the stats still use all the data. When the question is "show me this part of the plot", use the coordinate system; when the question is "ignore these values", use the scale.

The script collects the conditions raised while a plot is built and drawn, to show the text of the warning in each case, and then compares what the two approaches do to a fitted line. The warning is raised while the plot is drawn, not when it is built, which is why the helper in the script saves the plot to a temporary file.

The coordinate system is documented at ggplot2 package documentation: coord_cartesian and the out-of-bounds handlers at scales package documentation: oob.

Coordinate systems

The coordinate system turns the positions the scales produced into positions on the page. The default is coord_cartesian(), which also carries xlim and ylim (the zoom above), expand and, since 4.0, a ratio and a reverse. The others change the geometry. coord_fixed(ratio = ) makes one unit on x as long as ratio units on y, which is right for maps and for plots where both axes are in the same unit; in 4.0 it is a wrapper around coord_cartesian(ratio = ). coord_flip() swaps the axes. coord_polar() maps x to an angle and y to a radius, and its successor coord_radial() (introduced with 3.5.0) adds a better axis system. coord_transform() (named coord_trans() before 4.0.0) applies a transformation after the stats, which is different from a scale transformation that is applied before them.

coord_flip() is the one that old tutorials use for horizontal bars and horizontal box plots, and the reason is historical: before ggplot2 3.3.0 the way to put the groups on the vertical axis was to draw the vertical version and flip the whole plot. Since 3.3.0 the geoms and stats that have a direction can choose it, deduced from the mapping or given by the orientation argument. Mapping the categorical variable to y is enough: ggplot(shelf, aes(duration, genre)) + geom_boxplot() draws horizontal boxes. The ggplot2 3.5.0 NEWS marks coord_flip() as superseded and recommends swapping the aesthetics and using orientation, and the script shows that both ways draw the same boxes.

Facets

Facets split the data into panels that share the scales and the layout. facet_wrap() makes a ribbon of panels from the levels of one or more variables and wraps it to fit; facet_grid() makes a grid with one variable on the rows and another on the columns. Both take the variables as vars() (the current spelling, which quotes like aes()) or as a formula such as ~ genre or genre ~ period, which is the older spelling and still works. facet_wrap() has ncol and nrow, scales ("fixed", "free", "free_x" or "free_y" to let each panel have its own axis range), and labeller, a function that makes the text of the strip: label_both adds the variable name, label_wrap_gen() wraps long labels, and as_labeller() turns a named vector or a function into one.

The faceting is done on the data: the number of rows of a point layer in each panel is the number of loans of that genre, which agrees with table(shelf$genre). The last chunk saves two faceted plots with strip labels from label_both and from as_labeller(). The functions are documented at ggplot2 package documentation: facet_grid, ggplot2 package documentation: labellers, ggplot2 package documentation: as_labeller and ggplot2 package documentation: vars. A faceted plot of different charts (a histogram next to a scatter plot) is not what facets are for: they repeat one chart over subsets. Different charts are combined with another package, see Combining different plots.

Themes

The theme controls everything that is not data: text, lines, backgrounds, spacing and the position of the legend. There are two layers to it. A complete theme, theme_gray() (the default, also spelt theme_grey()), theme_bw(), theme_minimal(), theme_classic(), theme_light(), theme_dark(), theme_linedraw() and theme_void(), sets every element at once and takes base_size and base_family; in 4.0 it also takes ink, paper, accent and header_family. A partial theme made by theme() sets only the elements named, and is added to the plot like any other component. The elements form a tree (axis.text.x inherits from axis.text, which inherits from text), and each is built by an element function: element_text() for text, element_line() for lines, element_rect() for rectangles, and element_blank() for "draw nothing", which is how a part of the plot is removed. The ggplot2 documentation describes this hierarchy in the reference pages for ggplot2 package documentation: theme, ggplot2 package documentation: complete themes and ggplot2 package documentation: theme elements.

Guides

Guides are what scales draw to be read: axes for position scales, legends and colour bars for the others. The guides are built from the trained scales, and since ggplot2 3.5.0 they are ggproto objects styled through the theme (the 3.5.0 NEWS lists the rewrite of the whole guide system as its main breaking change). Two aesthetics mapped from the same variable merge into a single legend; a different variable makes a separate one; a continuous colour or fill gets a colour bar. The function guides() switches a guide off (guides(size = "none"); the old FALSE is deprecated since 3.3.4) or replaces it by a restyled one: guide_legend(ncol = 2) arranges the keys in two columns and guide_colourbar(reverse = TRUE) reverses the bar. The legend position is a theme setting, theme(legend.position = ) with "right", "left", "top", "bottom", "none" or "inside"; a numeric vector as the position was deprecated in 3.5.0 in favour of "inside" with legend.position.inside. The reference pages are ggplot2 package documentation: guides, ggplot2 package documentation: guide_legend and ggplot2 package documentation: guide_colourbar.

Saving plots: ggsave() and devices

ggsave() is the function to save a plot to a file. Its reference page says that it defaults to saving the last plot that was displayed, uses the size of the current device unless a size is given, and guesses the type of device from the extension of the file name. The arguments that matter are filename, plot, device, path, width, height, units ("in", "cm", "mm" or "px"), dpi (default 300; a number, or a string such as "print"), scale, bg and, since 3.5.0, create.dir. Always give a plot and a size in a script: the defaults refer to the last plot displayed and the size of whichever device happens to be current, which depends on the session, and ggplot2 says so with the message Saving 7 x 7 in image when the size had to be taken from the device. The return value is the file name, invisibly, since ggplot2 3.3.4. In 4.0.0 the plot argument can also be a list of plots, saved as the pages of a PDF.

The device is chosen by the extension, or by device, which is a name or a device function. For vector output ggplot2 maps "svg" to svglite::svglite() and checks that the svglite package is installed (it is a suggested, not a required, dependency: 3.5.1 made ggsave() offer to install it, and the NEWS entry that began using it is in 2.1.0); the package is documented at svglite package documentation: svglite. The base R device svg() is the Cairo one and is still available by passing the function (device = svg), as the script shows. For PNG, JPEG and TIFF, ggplot2 uses the ragg package if it is installed and the base devices otherwise (the NEWS entry is in 3.3.4), which is why a PNG can look different on two machines. For PDF, "pdf" is the default and cairo_pdf (a device function, with device = cairo_pdf) embeds fonts through Cairo. The base R devices are documented at R documentation: svg and cairo_pdf, R documentation: png and R documentation: pdf; the page Base Graphics and Devices explains the device model. An alternative that does not use ggsave() is to open a device yourself, print the plot and close the device, as the script does with svg(); print() returns the plot invisibly, so it can sit inside a function.

Under the plot: grid and gtable

A rendered ggplot is not a bitmap or a special ggplot2 drawing language: it is a gtable, a table of grid graphical objects, drawn by the grid package that ships with R. ggplotGrob(p) returns that table, and so does ggplot_gtable(ggplot_build(p)). The table has a row and column structure (the script prints 16 rows by 13 columns), a layout data frame that says which cell each grob occupies and under which name (panel, axis-l, axis-b, title, the legend boxes), and heights and widths in grid units. Each cell holds a grid grob; the panel is a gTree whose children are the pieces of the layers (here points, with grid lines and borders that are empty zeroGrob placeholders). Because it is a grob, it can be drawn on any device with grid.draw() after grid.newpage(), edited cell by cell with the gtable functions, or combined with other grobs. Extending ggplot2 with ggproto

Everything that draws, computes or lays out in a plot is a ggproto object: Geom, Stat, Position, Coord, Facet, Scale and Guide are the base classes, and GeomPoint, StatBin and so on are their instances, as the matrix in the layers section showed. ggproto is ggplot2’s own object system with mutable objects and inheritance that works across packages, designed for this purpose, and the article on extending ggplot2 gives its history and builds a stat, a geom, a facet and a guide with it (ggplot2 package documentation: Extending ggplot2). The reference page for ggproto() documents the constructor (ggplot2 package documentation: ggproto). The script defines the smallest useful extension: a stat that replaces each group’s rows by the group’s median point, and a constructor function that wraps layer() in the form that package code exports. The nolint block is there because ggproto objects are named in CamelCase and the layer constructors use the dotted argument names (na.rm, show.legend, inherit.aes) that every ggplot2 function uses.

library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
known <- subset(books, !is.na(pages) & !is.na(year))

# A stat is a ggproto object: compute_group() gets one group's data frame
# and returns a new data frame.
# nolint start: object_name_linter.
StatMedianPoint <- ggproto("StatMedianPoint", Stat,
  required_aes = c("x", "y"),
  compute_group = function(data, scales) {
    data.frame(x = median(data$x), y = median(data$y))
  }
)

# The user-facing function wraps layer(); it is what package code exports.
# The argument names are ggplot2's own conventions, hence the nolint block.
stat_median_point <- function(mapping = NULL, data = NULL, geom = "point",
                              position = "identity", ...,
                              na.rm = FALSE, show.legend = NA,
                              inherit.aes = TRUE) {
  layer(
    stat = StatMedianPoint, data = data, mapping = mapping, geom = geom,
    position = position, show.legend = show.legend,
    inherit.aes = inherit.aes, params = list(na.rm = na.rm, ...)
  )
}

# nolint end

p <- ggplot(known, aes(pages, year, colour = genre)) +
  geom_point(alpha = 0.3) +
  stat_median_point(size = 4)

The page on base graphics draws four charts of the shelf scenario: loans per month, the distribution of loan duration, duration by genre and pages against duration. The data preparation is the same in every one: loans has the loan and return dates; a loan returned before it was lent (a negative duration) and a loan not yet returned (a missing return date) have no usable duration; the books are joined on the ISBN after the hyphens are stripped, as in Data Frames. The plots are saved to temporary files and the scripts print the data that each layer will draw, which is what a test of a chart would check.

Combining different plots

The patchwork package arranges ggplot objects with the operators +, | and / (p1 | p2 puts two plots side by side), cowplot offers plot_grid() and publication themes, and gridExtra has grid.arrange(); all three are community packages that work on the grid layer, and none is installed in the environment used for this page, so they are not run here. The grid layer is also available directly: ggplotGrob() returns the gtable of each plot, and grid.layout() and viewports (see Grid Graphics and Lattice) place them. The base graphics equivalent, par(mfrow = ) and layout(), does not work for ggplot objects, because they are drawn with grid and not with the graphics package.

Pitfalls

  • A plot that is never printed is never drawn. In source(), in a function and in a loop the automatic printing does not happen, so call print(p) or ggsave(). This is R FAQ 7.22, and it names ggplot2 graphics (R FAQ 7.22: Why do lattice/trellis graphics not work?). Under Rscript, drawing without opening a device writes Rplots.pdf into the working directory.

  • A plus at the start of a line is a new statement. End the line with the plus, not the next one. The error is Cannot use + with a single argument.

  • Mapping is not setting. aes(colour = "red") maps a constant and adds a legend; colour = "red" outside aes() sets it.

  • xlim() and limits drop data; coord_cartesian() zooms. They give different fits and different counts of removed rows.

  • geom_bar() counts, geom_col() draws heights. Giving geom_bar() a y and geom_col() no y are the two errors in the table of messages.

  • Order of a discrete axis is the order of the factor levels (alphabetical for a character vector). Reorder with a factor, or with reorder() as the genre chart does (Factors).

  • Randomness in geom_jitter() and position_jitter() changes the plot at each draw. Give the position a seed to make a plot reproducible.

  • Columns in aes() of package code need .data. Otherwise R CMD check reports "no visible binding for global variable" (see the evaluation page). Inside aes(), df$col is discouraged and says so: Use of known$pages is discouraged. Use pages instead.

  • A global theme_set() changes every later plot in the session. Keep the previous value that it returns and restore it, or pass the theme to each plot.

  • Lifecycle warnings are normally shown once per session. A script that runs once shows each deprecation once; a long interactive session may have seen it earlier and show nothing.

Tutorials written before ggplot2 3.4.0 (2022) contain idioms that now warn or fail, and some that only look dated. The script below runs the deprecated ones under a helper that prints the warning instead of raising it, so the message each one gives today is on record; the idioms in the last block are old but still fine.

library(ggplot2)

books$genre <- tolower(trimws(books$genre))

# Old idioms still run, mostly; this script only shows what they now say. The
# calls are wrapped so that the warning text is printed instead of raised.
old <- \(label, expr) {
  seen <- character()
  withCallingHandlers(
    expr,
    warning = \(w) {
      seen <<- c(seen, conditionMessage(w))
      invokeRestart("muffleWarning")
    }
  )
  cat("--", label, "\n", paste(seen, collapse = "\n"), "\n", sep = "")
}
