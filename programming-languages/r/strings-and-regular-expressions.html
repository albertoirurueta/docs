Strings and Regular Expressions

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R except the last section before the pitfalls, which uses stringr 1.6.0 (a CRAN package that calls the stringi library, which in turn wraps ICU) only to show the equivalents of the base functions; the scripts also use the books and loans data frames and the book class of the running shelf scenario, which are plain base R code, and the lintr 3.4.0 default linters were used only to check the scripts.

R has no string type of its own. A string is one element of a character vector, and almost every string job is done by a handful of vectorised functions that take a character vector and return a character vector (paste(), sprintf(), substr(), sub()), a logical vector (grepl(), startsWith()), a list (strsplit(), gregexpr()) or an integer vector of positions (regexpr()). This page goes through those functions in the order a data-cleaning job needs them: build strings, format numbers into them, trim and slice them, split and convert them, print them, and then match patterns with regular expressions, which in R come in three flavours selected by two logical arguments. It finishes by cleaning the deliberately messy text columns of the shelf data and by mapping the base functions to stringr.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. Long scripts are shown in several consecutive pieces, one per section, and a piece that needs a helper defined earlier in the same script says so. The scripts pass the default lintr linters. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says. The examples use the library scenario of the section: books, loans and shelf_today come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"). The example session was a UTF-8 session in an en_US.UTF-8 locale (an example locale name; the results that depend on the locale are pointed out where they occur, and Encodings, Locales and Internationalization explains the mechanism).

Strings are elements of character vectors

The manual introduces character quantities in the section on character vectors: they are written between matching double or single quotes, always printed with double quotes (or without quotes at all), and use C-style escapes with the backslash as the escape character (An Introduction to R: Character vectors). Three consequences shape everything that follows.

  • There is no scalar string. "The Dispossessed" is a character vector of length 1, so every function below is vectorised over a whole column such as books$title without a loop.

  • An empty string and a missing string are different values. "" has zero characters and NA_character_ is a missing value of type character; is.na(), nzchar() and nchar() tell them apart (see Missing and Special Values).

  • The text that R prints is a representation of the string, not the string itself: it adds the quotes and escapes backslashes, quotes and control characters. Printing and quoting returns to this.

source("scenario.R")

# A string is one element of a character vector; there is no scalar string
typeof("The Dispossessed")
#> [1] "character"
length("The Dispossessed")
#> [1] 1
is.vector(books$title)
#> [1] TRUE
length(books$title)
#> [1] 16
nchar(books$title[1:3])
#> [1] 16 19 20

# NA_character_ is a missing string, "" is an empty one
missing_title <- c("Loud Roofs", NA, "")
is.na(missing_title)
#> [1] FALSE  TRUE FALSE
nzchar(missing_title)
#> [1]  TRUE  TRUE FALSE
nchar(missing_title)
#> [1] 10 NA  0

# The deliberate mess of the shelf data
books$title[c(3, 10)]
#> [1] "  the quiet streets " "THE LONG TABLE"
books$author[c(8, 10)]
#> [1] "Le Guin, Ursula K." "Iris  Fenwick"
books$genre[c(1, 4, 10)]
#> [1] "Science fiction" "fiction"         "Fiction "

#> [1] "Science fiction" "Classic"         "Fiction"         "fiction"
#> [5] "Mystery"         "Non-fiction"     "Poetry"          "Fiction "
#> [9] "science fiction"

Le Guin and as Le Guin, Ursula K., the double space in Iris Fenwick, and nine spellings of what should be six genres. Building strings

paste() and paste0()

paste() converts its arguments to character with as.character() and joins them term by term; paste0() is paste(..., sep = "") a little more efficiently (R documentation: paste). Two arguments control the shape of the result:

  • sep goes between the terms of each element of the result (default " ").

  • collapse, when it is a string, folds the whole result into a single string with that separator between the elements; when it is NULL (default) the result keeps one element per term. Confusing the two is the usual reason a result has the wrong length: paste("a", "b", collapse = ", ") is the single string "a b", because the arguments have length 1 and there is nothing to collapse; use sep to join arguments and collapse to join elements.

Arguments are recycled to the length of the longest one, so the vectors in the next script behave like the labs example of the manual: the shorter vector is repeated.

source("scenario.R")

# paste() joins with sep = " "; paste0() has no separator
paste("Ursula K.", "Le Guin")
#> [1] "Ursula K. Le Guin"
paste0("978", "0306406157")
#> [1] "9780306406157"
paste("a", "b", sep = "-")
#> [1] "a-b"

# Vectors are joined element by element and recycled
paste("L", 1:3, sep = "")
#> [1] "L1" "L2" "L3"
paste0("L", sprintf("%03d", 1:3))
#> [1] "L001" "L002" "L003"
paste(c("a", "b", "c"), 1:6)
#> [1] "a 1" "b 2" "c 3" "a 4" "b 5" "c 6"

# collapse folds a vector into one string
paste(books$title[4:6], collapse = "; ")
#> [1] "Loud Roofs; Midnight Ledger; A Map of Salt"
paste0(c("x", "y"), collapse = "")
#> [1] "xy"

# sep and collapse together
paste(c("a", "b"), c("c", "d"), sep = "+", collapse = " | ")
#> [1] "a+c | b+d"

Source: R documentation: paste

The third example of the first group, paste(c("a", "b", "c"), 1:6), recycles the shorter vector twice. When the longer length is not a multiple of the shorter one, paste() recycles silently and does not warn, a trap that the last example of the next block shows.

Missing and zero-length arguments

NA is converted like any other value, so it becomes the two characters NA: paste("pages:", NA) is "pages: NA", and the help page notes that this may be undesirable when pasting two character vectors but is convenient in a message. If you want a missing value to propagate instead, test with is.na() first (stringr’s str_c() propagates it; see stringr).

A zero-length argument is not dropped but recycled as the empty string "", so paste("a", character(0)) is "a " with a trailing separator, not character(0). This surprises people who build file names from a possibly empty vector. R 4.0.1 added the argument recycle0 for the standard vectorised behaviour, where a zero-length argument makes the whole result zero-length. The NEWS entry for R 4.0.1 says that paste() and paste0() gain recycle0 and adds that a package using it should depend on R (>= 4.0.1). Note the one exception that the help page spells out: with collapse set to a string the result is always a single string, so recycle0 = TRUE gives "" and not character(0).

# NA is pasted as the text "NA"
paste("pages:", books$pages[5:7])
#> [1] "pages: 301" "pages: NA"  "pages: 96"
paste0("year ", NA)
#> [1] "year NA"
paste(NA_character_, "x")
#> [1] "NA x"

# A zero-length argument is recycled as "", not dropped
paste("a", character(0))
#> [1] "a "
paste0("a", NULL, "b")
#> [1] "ab"
paste(character(0), collapse = "+")
#> [1] ""
paste("a", character(0), sep = "-")
#> [1] "a-"

# recycle0 = TRUE (R 4.0.1) gives character(0) unless collapse is a string
paste("a", character(0), recycle0 = TRUE)
#> character(0)
paste("a", character(0), recycle0 = TRUE, collapse = "+")
#> [1] ""
paste0("a", character(0), recycle0 = TRUE, collapse = NULL)
#> character(0)

Source: R NEWS: Changes in R 4.0.1

Other classes

paste() calls as.character() on each object argument, so a factor contributes its labels, a Date its ISO text, and a list element that is a vector contributes its deparsed form. Numbers are converted with up to 15 significant digits, which is the cause of several of the surprises in Pitfalls.

# Factors are pasted as their labels
paste(factor(c("fiction", "poetry")), 1:2)
#> [1] "fiction 1" "poetry 2"

# Dates are formatted with as.character()
paste("due", shelf_today + 21L)
#> [1] "due 2026-07-21"

# A list element that is a vector is deparsed
paste(list(1:3, "a", c(TRUE, FALSE)))
#> [1] "1:3"            "a"              "c(TRUE, FALSE)"

# A non-multiple length recycles silently, without a warning
paste(1:3, c("a", "b"))
#> [1] "1 a" "2 b" "3 a"

Source: R documentation: paste

toString(x) is paste(x, collapse = ", ") (R documentation: toString), and strrep(x, times) repeats a string (R documentation: strrep; added in R 3.3.0). rep() plus paste(collapse = "") was the idiom before it.

sprintf()

sprintf() is a wrapper for the C library function of the same name: a format string with conversion specifications that start with % is filled from the following arguments, which are recycled together with the format and processed in parallel (R documentation: sprintf). paste() builds a string from pieces; sprintf() writes the whole sentence as a template and fills in typed values, which is also what translators prefer (gettextf() is sprintf() with translation of the format string). The conversions used most often are:

Specification Meaning Example result

%s

a string; other types are converted with as.character(); NA becomes "NA"

sprintf("%s", 3.5) is "3.5"

%d, %i

an integer; a double is accepted when it holds a whole number, and a logical is accepted too

sprintf("%d", 3) is "3"

%f

fixed-point decimal; the precision is the number of decimals, default 6

sprintf("%5.2f", pi) is " 3.14"

%e, %E

exponential notation

sprintf("%e", 123456.789) is "1.234568e+05"

%g, %G

%e or %f depending on the exponent; the precision counts significant digits

sprintf("%g", 123456.789) is "123457"

%x, %X, %o

hexadecimal and octal integer

sprintf("%X", 255L) is "FF"

%a, %A

hexadecimal floating point

sprintf("%a", 1) is "0x1p+0"

%%

a literal percent sign

sprintf("100%%") is "100%"

Between the % and the letter come, in any order, a width and precision m.n, the flags - (left-justify), + (always show a sign), a space (prefix a space), 0 (pad numbers with zeros) and # (alternate form), an optional n$ to select the nth argument, and * to take the width or the precision (but not both) from an argument.

source("scenario.R")

# The conversion specifications
sprintf("%s has %d pages", "Loud Roofs", 198L)
#> [1] "Loud Roofs has 198 pages"
sprintf("%5.2f", pi)
#> [1] " 3.14"
sprintf("%-10s|", "left")
#> [1] "left      |"
sprintf("%10s|", "right")
#> [1] "     right|"
sprintf("%05d", 42L)
#> [1] "00042"
sprintf("%+d", 7L)
#> [1] "+7"
sprintf("%e", 123456.789)
#> [1] "1.234568e+05"
sprintf("%g", 123456.789)
#> [1] "123457"
sprintf("%x %X %o", 255L, 255L, 8L)
#> [1] "ff FF 10"
sprintf("%.3s", "Dispossessed")
#> [1] "Dis"
sprintf("100%%")
#> [1] "100%"
sprintf("%08.2f", pi)
#> [1] "00003.14"
sprintf("%#x", 255L)
#> [1] "0xff"
sprintf("%.0f", c(0.5, 1.5, 2.5))
#> [1] "0" "2" "2"
sprintf("%5.1f%%", 45.678)
#> [1] " 45.7%"

# %d accepts a whole-number double, %s accepts anything
sprintf("%d", 3)
#> [1] "3"
sprintf("%s", 3.5)
#> [1] "3.5"
sprintf("%s", TRUE)
#> [1] "TRUE"
sprintf("%s", 1e6)
#> [1] "1e+06"
sprintf("%s", 123456789)
#> [1] "123456789"

# Vectorised over all arguments
sprintf("%s (%d)", books$title[4:6], books$year[4:6])
#> [1] "Loud Roofs (2021)"      "Midnight Ledger (2016)" "A Map of Salt (2008)"
sprintf("%2$s was written by %1$s", "Jane Austen", "Pride and Prejudice")
#> [1] "Pride and Prejudice was written by Jane Austen"

# The width can come from an argument with *
sprintf("%*d", 6L, 42L)
#> [1] "    42"
sprintf("%-*s|", 8L, "ab")
#> [1] "ab      |"

Source: R documentation: sprintf

Three details from the help page matter in practice. %.0f does not round half up: 0.5, 1.5 and 2.5 print as 0, 2 and 2, because the C library rounds the binary double to even in the halfway case. %s applied to a number uses as.character(), so a double such as 1e6 becomes "1e+06"; use %d for an integer-valued count and %.0f or format() when you want plain digits. And an argument that the format does not use makes sprintf() warn: that warning exists since R 4.1.0, whose NEWS says that sprintf() now warns on arguments unused by the format string; %.0s skips an argument without the warning.

Missing, zero-length, bytes and vectors

NA is formatted as NA for every type and keeps the field width. A zero-length argument gives a zero-length result, unlike paste(). The width of %s is counted in bytes, as the help page says (it follows the C standard), so an accented letter that takes two bytes in UTF-8 gets one space fewer than an ASCII letter: use formatC() or format() (below), which count characters or display width, when you align non-ASCII text. The format itself is vectorised, and the last example formats a small table with cat(sep = "\n").

# NA is printed as NA, with width and for every type
sprintf("%d", NA_integer_)
#> [1] "NA"
sprintf("%5.1f", NA_real_)
#> [1] "   NA"
sprintf("%s", NA_character_)
#> [1] "NA"
sprintf("%10s|", NA)
#> [1] "        NA|"

# Widths of %s count bytes, not characters
sprintf("%5s|", "e")
#> [1] "    e|"
sprintf("%5s|", "é")
#> [1] "   é|"

# Zero-length arguments give a zero-length result
sprintf("%s", character(0))
#> character(0)

# fmt itself is vectorised
sprintf(c("%d pages", "%d years"), 387L)
#> [1] "387 pages" "387 years"

# Format a table of the shelf
cat(sprintf("%-22s %4d %5s", books$title[1:4], books$year[1:4],
            format(books$pages[1:4])), sep = "\n")
#> The Dispossessed       1974   387
#> Pride and Prejudice    1813   432
#>   the quiet streets    2019   214
#> Loud Roofs             2021   198

Source: R documentation: sprintf

The errors of sprintf()

The format is checked against the type of the argument before anything is formatted, so the common mistakes are errors, and the error text names the right conversion. The first one below is the error that people meet when they print a computed double with %d: a double with a fractional part (or outside the integer range) is not accepted by %d. The script catches every condition and prints its message.

# The errors and warnings of sprintf(), caught so that their text is shown
msg <- function(expr) {
  tryCatch(expr, error = \(e) conditionMessage(e),
           warning = \(w) paste("warning:", conditionMessage(w)))
}

msg(sprintf("%d", 3.5))
#> [1] "invalid format '%d'; use format %f, %e, %g or %a for numeric objects"
msg(sprintf("%d", "3"))
#> [1] "invalid format '%d'; use format %s for character objects"
msg(sprintf("%s and %s", "one"))
#> [1] "too few arguments"
msg(sprintf("%s", "one", "two"))
#> [1] "warning: one argument not used by format '%s'"
msg(sprintf("%y", 1L))
#> [1] "unrecognised format specification '%y'"
msg(sprintf("%5", 1L))
#> [1] "unrecognised format specification '%5'"
msg(sprintf("%s", list(1, "a")))
#> [1] "1" "a"
msg(sprintf("%s", list(1:2, "a")))
#> [1] "1:2" "a"
msg(sprintf("%f", 1L))
#> [1] "1.000000"
msg(sprintf("%d", TRUE))
#> [1] "1"
msg(sprintf("%s", sum))
#> [1] "cannot coerce type 'builtin' to vector of type 'character'"
msg(sprintf("%s %s", c("a", "b"), c("x", "y", "z")))
#> [1] "arguments cannot be recycled to the same length"
msg(sprintf("%.2f%%", 12.345))
#> [1] "12.35%"
msg(sprintf("%s", factor("fiction")))
#> [1] "fiction"
msg(sprintf("%d", factor("fiction")))
#> [1] "1"

Source: R documentation: sprintf

Read the results one by one. %d with 3.5 gives invalid format '%d'; use format %f, %e, %g or %a for numeric objects, and %d with a string says to use %s for character objects; a format that needs more arguments than given is too few arguments; an extra argument is a warning, not an error; an unknown conversion is unrecognised format specification; and arguments of different lengths that do not recycle to a common length are an error (arguments cannot be recycled to the same length). Two results are not errors although they look like traps: a list is accepted for %s and each element is converted with as.character(), so a vector element is deparsed (list(1:2, "a") gives "1:2" and "a"), and a factor passed to %d supplies its integer codes. The hazard of sprintf() is therefore silent conversion rather than an error, which Pitfalls expands.

format(), formatC() and prettyNum()

sprintf() formats each value on its own. format() is different: it formats a whole vector so that all elements have a common width and a common number of decimals, which is what a printed column needs (R documentation: format). Its main arguments are width (a minimum width), justify ("left", "right", "centre" or "none", for character input), digits (significant digits for numbers), nsmall (a minimum number of digits after the decimal point), scientific (force or forbid exponents), big.mark and na.encode. formatC() is the C-style interface to the same job for numbers and strings, with width, digits, format ("d", "f", "e", "g", "fg" or "s"), flag ("0" pads with zeros, "-" left-justifies, "+", " " and "#") and big.mark; prettyNum() inserts the marks into numbers that are already formatted (R documentation: formatC).

source("scenario.R")

# format() pads a vector to a common width
format(c("a", "bbb", "cc"))
#> [1] "a  " "bbb" "cc "
format(c("a", "bbb", "cc"), width = 6)
#> [1] "a     " "bbb   " "cc    "
format(c("a", "bbb", "cc"), justify = "right")
#> [1] "  a" "bbb" " cc"
format(c("a", "bbb", "cc"), justify = "centre", width = 7)
#> [1] "   a   " "  bbb  " "  cc   "

# For numbers it uses a common number of significant digits
format(c(1, 10, 100))
#> [1] "  1" " 10" "100"
format(pi, digits = 3)
#> [1] "3.14"
format(c(0.5, 10, 123.456))
#> [1] "  0.500" " 10.000" "123.456"
format(2, nsmall = 2)
#> [1] "2.00"
format(1234567.891, big.mark = ",")
#> [1] "1,234,568"
format(1e6, scientific = TRUE)
#> [1] "1e+06"
format(1e-5)
#> [1] "1e-05"
format(0.00001, scientific = FALSE)
#> [1] "0.00001"
format(TRUE)
#> [1] "TRUE"
format(NA)
#> [1] "NA"
format(c(1.5, NA, 3))
#> [1] "1.5" " NA" "3.0"
format(NA_character_)

Case, translation, trimming and prefixes

toupper(), tolower() and casefold() change case, and chartr(old, new, x) translates characters one for one (a range such as "a-c" is allowed, character classes are not) (R documentation: chartr). Case conversion uses the rules of the current locale, so it is not one-to-one in every language: the help page notes that more than one character can be mapped to a single upper-case character. substr(), substring() and the replacement forms

substr(x, start, stop) extracts the characters from start to stop of every element, with 1-based positions, and substring(text, first, last) is the S-compatible variant that recycles first and last along the longest argument, which makes it the tool for cutting one string at many places (R documentation: substr). Positions outside the string are forgiven: start beyond the end gives "", stop beyond the end gives the rest, and start below 1 is treated as 1. NA in an argument gives NA, the names of x are kept by substr(), and both functions count characters in a UTF-8 string.

R 4.6.0 changed what the end argument may be. The NEWS says that substring(txt, i1, i2), substr(..) and their replacement versions now accept i2 = NULL to mean "to the end_of_string". The names i1 and i2 are the NEWS shorthand, because the help page for 4.6.1 names the arguments start/stop for substr() and first/last for substring(): stop (or last) may now be NULL, meaning the end of each string. In 4.6.1 last of substring() defaults to NULL, so substring(x, 5) returns everything from position 5, while stop of substr() still has no default, so substr(x, 5) is the error argument "stop" is missing, with no default and you write substr(x, 5, NULL). Older code that wrote substr(x, 5, 1000000L) or substr(x, 5, nchar(x)) still works.

Splitting and converting

strsplit()

strsplit(x, split, fixed = FALSE, perl = FALSE) splits each element of x at the matches of split and returns a list with one character vector per element, in the same order (R documentation: strsplit). The list is what makes a typical beginner’s loop wrong: strsplit(x, ",") of one string is a list of length 1, so you take [[1]] of it or vapply() over the elements. A few behaviours follow from the algorithm that the help page prints:

  • The pattern is a regular expression. strsplit("a.b.c", ".") splits at every character, because . matches anything, and returns five empty strings; use fixed = TRUE or "[.]".

  • An empty pattern (or character(0)) splits into single characters, counted in characters, not bytes.

  • A match at the start gives a leading empty string, but a match at the end does not give a trailing one: "a,b," splits into "a" and "b".

  • A missing x gives NA, an empty string gives character(0), and a factor is an error (non-character argument).

Printing and quoting

A string and the text that R prints for it are different things, and the R FAQ spends an entry on the difference (R FAQ 7.37: Why does backslash behave strangely inside strings?). print() (and autoprinting) shows the representation: the quotes, and the escape sequences \", \\ and \n. cat() and writeLines() write the characters themselves (R documentation: cat). nchar() counts the characters of the string, so the string with a newline in it has one character for the \n, not two.

noquote(x) and print(x, quote = FALSE) drop the surrounding quotes but still escape backslashes and control characters, which surprises people who expect the output of cat(): the printed back\\slash still has two backslashes although the string has one. encodeString(x, quote = "'") returns the escaped form as a string, the same text print() would show (R documentation: encodeString); it is the right function when you build an error message from user text, and noquote the right one for a table of names without quotes (R documentation: noquote).

#> say "hi"
#> back\slash
#> new
#> line
nchar(x)
#> [1]  8 10  8
noquote(x)

Regular expressions

A regular expression is a pattern that describes a set of strings, and R has three ways to read one. The help page ?regex is the reference for the syntax and is long: this page covers what you need to choose the engine, to write patterns that survive R’s escaping rules and to read the results (R documentation: regex). Every function in the family takes the pattern as a single string and accepts the same three switches, which select the engine:

Switch Engine What the pattern means

none (the default)

POSIX 1003.2 extended regular expressions, implemented by the TRE library (with some extensions)

the dot, bracket expressions, groups, alternation a|b, quantifiers such as {n,m}, and the backreferences \1 to \9; the extensions \w, \d, \s, \b, \< and \>; POSIX classes such as [[:digit:]]; lazy quantifiers such as .*?

perl = TRUE

Perl-like regular expressions, implemented by the PCRE2 library

everything above except \< and \>, plus lookahead and lookbehind, \U and \L in replacements, the flags (?i), (?m) and (?s), \Q and \E quoting, \h, Unicode properties such as \p{Nd}, and named groups

fixed = TRUE

a literal string, no metacharacters at all

the characters of the pattern, matched exactly

fixed = TRUE takes priority: the help page says it overrides all conflicting arguments. R 4.0.0 migrated the perl = TRUE engine from PCRE to PCRE2, and the 4.0.0 NEWS lists the consequence: PCRE2 reports an error for some patterns PCRE1 accepted, for example a hyphen inside a character class now has to be escaped to be literal unless it is first or last, and \R, \B and \X are no longer allowed inside a class. Which engine is the right one? The help page’s guidance on performance is qualitative: perl = TRUE is generally faster than the default engine, and fixed = TRUE is faster still when the pattern is a literal. Choose by meaning first: fixed = TRUE for any pattern that is just text (a file name, a prefix, a user’s input), the default engine for simple patterns, and perl = TRUE when you need lookaround, case conversion in a replacement, named groups or Unicode properties. Name the logical arguments: a bare TRUE in the wrong position can land in ignore.case, perl or value, and the grep help page warns that passing unnamed arguments that land in these slots is an all too common mistake.

sub() and gsub()

sub(pattern, replacement, x) replaces the first match in each element and gsub() replaces all of them, and both return a character vector with the attributes of x (R documentation: grep). The replacement is not a plain string: in the default engine and in PCRE a backslash followed by a digit from 1 to 9 inserts the text of that parenthesised group, which is how the shelf’s Le Guin, Ursula K. becomes Ursula K. Le Guin; with perl = TRUE the replacement may also contain \U, \L and \E to convert the rest of the replacement to upper or lower case. Neither engine has a backreference to the whole match: put the whole pattern in parentheses and use \1. Remember that R reads the string first, so every backslash is written twice ("\\2 \\1"); Escaping gives the full rule.

Details you will otherwise discover the hard way:

  • \0 is not a backreference: ?grep documents only \1 to \9, and with or without perl = TRUE the replacement "<\\0>" inserts <0>. Wrap the whole pattern in a group and use \1 instead. An unmatched optional group inserts nothing.

  • \U\1 without perl = TRUE is not an error: the U is kept as a literal, and gsub("(\\w+)", "\\U\\1", "the long") returns "Uthe Ulong".

  • ignore.case = TRUE works with the default and PCRE engines and is ignored (with a warning) with fixed = TRUE.

  • An NA replacement makes every matched element NA; an NA pattern makes everything NA; non-matching elements are returned unchanged, and a factor x is returned as character.

  • Named backreferences are not supported by sub(): the help page of ?regex says so.

# Invalid patterns: a warning with the engine's reason, then an error
show <- \(expr) {
  out <- character()
  res <- withCallingHandlers(
    tryCatch(
      paste("value:", format(expr)),
      error = \(e) paste("error:", conditionMessage(e))
    ),
    warning = \(w) {
      txt <- gsub("\n\t", " ", conditionMessage(w))
      out <<- c(out, paste("warning:", txt))
      invokeRestart("muffleWarning")
    }
  )
  c(out, res)

The error invalid regular expression '(', reason 'Missing ')'' is the one everybody meets: an unbalanced parenthesis, where the reason Missing ')' is itself quoted, so the message ends with two apostrophes. The default engine gives short reasons (Missing ']', Invalid contents of {}, Trailing backslash, Invalid character range) and treats a few odd patterns as valid: a leading * or an unmatched ) compiles, which hides typos. A replacement that refers to a group that does not exist does not fail: gsub("(a)", "\\2", "banana") removes the a, since the help page says only that the result is undefined and in practice the missing group is taken as empty. a literal dot

\. (two characters)

\\, which matches one backslash

a digit

"\\d"

a word boundary

\b (a single "\b" is the backspace character, not a boundary)

group 1 in a replacement

"\\1"

\1

a newline

"\n"

Raw strings

R 4.0.0 added raw character constants, written r"(...)" with the same idea as C++. The NEWS entry says the content is any character sequence that does not contain a closing parenthesis followed by a double quote, and that this makes it easier to write strings that contain backslashes or both kinds of quotes. Inside a raw string nothing is an escape, so r"(\.)" is the two characters backslash and dot, and r"(C:\shelf\books.csv)" is the Windows path as typed. If the text contains a closing parenthesis followed by a double quote, add dashes between the r and the quote: r"-(...)-" ends only at the sequence closing parenthesis, dash, double quote. The delimiters can also be square or curly brackets instead of parentheses, and the r can be upper case. The syntax and the delimiter rules are covered on Syntax and Lexical Structure; raw strings do not exist before R 4.0.0, so code for older versions keeps the doubled backslashes.

Raw strings do not make the regex engine’s own escapes go away: r"(\d{13})" still contains the backslash and the braces that PCRE and TRE read, only R’s string parser stays out of the way. A raw string is also an ordinary character constant once parsed, so identical() shows it equal to the doubled form.

Titles and authors

A title is cleaned by trimming it, squeezing inner runs of blanks into one, and applying a case convention. Sentence case is built with substr(), toupper() and substring(); title case with a PCRE replacement that upper-cases the first letter of each word with \U. # Titles: trim, squeeze blanks, then sentence case
clean_title <- function(x) {
  x <- gsub("\\s+", " ", trimws(x))
  paste0(toupper(substr(x, 1, 1)), tolower(substring(x, 2)))
}
clean_title(books$title[c(1, 3, 10)])
#> [1] "The dispossessed"  "The quiet streets" "The long table"

# Title case with PCRE: capitalise each word
title_case <- function(x) {
  gsub("\\b([a-z])", "\\U\\1", tolower(trimws(x)), perl = TRUE)
}
title_case(books$title[c(3, 10)])
#> [1] "The Quiet Streets" "The Long Table"

Pitfalls

  • sprintf() converts silently. A list argument is converted element by element with as.character(), so a vector element is deparsed ("1:2"), and %d rejects a list altogether (unsupported type). A double with a whole value is accepted by %d, a fractional or out-of-range one (3000000000) is the invalid format error.

  • Numbers are converted with up to 15 significant digits: paste(0.1 + 0.2) is "0.3" while sprintf("%.17g", 0.1 + 0.2) shows 0.30000000000000004. as.character(1e5) is "1e+05" but as.character(100000L) is "100000", and as.character(1e15) is "1e+15". Format numbers explicitly with sprintf() or format() when the text matters, as with identifiers and file names. R FAQ 7.31: Why doesn’t R think these numbers are equal? explains why decimal fractions are not exact in binary.

  • sprintf() argument lengths must recycle to a common length (arguments cannot be recycled to the same length), but paste() recycles silently.

  • Case conversion and sorting depend on the locale. In the example en_US.UTF-8 locale sort(c("b", "A", "a", "B")) is "a" "A" "b" "B", while method = "radix" sorts by code point and gives "A" "B" "a" "b". Compare strings with == for equality; use tolower() on both sides for case-insensitive equality, and do not rely on toupper("ß") == "SS".

  • A string that looks like one character on the screen can be two: "na\u0308ive" with a combining diaeresis has six characters, five of display width. See Encodings, Locales and Internationalization.

  • toupper(NA) is NA (as a character), toupper(1:3) converts numbers to character, and toupper(factor("a")) returns the upper-cased label as a character vector.

  • charmatch() and pmatch() do partial matching and treat an ambiguous match differently (0 versus NA); exact matching is match() or %in%. Do not use partial matching for data cleaning.
