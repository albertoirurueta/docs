Lists

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R (base, utils and stats), so no add-on package version applies; the package jsonlite is named in the section on JSON-shaped data but nothing from it is run, and the lintr 3.4.0 default linters were used only to check the scripts. A list is the data structure of R with the fewest restrictions: its elements can have any type and any length, and an element can be another list. That makes it the structure behind records, nested configuration, the result of almost every function that returns more than one thing, S3 objects and, underneath, data frames. This page covers what a list is, the three ways to take things out of it ([, [[ and $) and the errors they signal, how to put things in and take them out, how lists are combined, flattened (unlist()), merged (modifyList()), walked (rapply()), compared and inspected (str()), how to build a data frame from one with list2DF(), and then the three roles that the shelf scenario uses a list for: a record, an S3 object and a table.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts pass the default lintr linters. Each script is shown in several consecutive blocks with prose between them; a block uses the objects created by the blocks above it in the same script. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says. The messages are printed in a UTF-8 locale, where R uses curly quotes in a few of them (all.equal() writes the component names between “ and ”); in a locale that is not UTF-8 they are plain quotes. str() writes a tab character after the class name in its first line for a data frame ('data.frame':<tab>16 obs. of 6 variables:), and the blocks below keep it. The examples use the library scenario of the section: books, loans, shelf_today, loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R").

What a list is

The R Language Definition describes lists in one paragraph: lists, which it also calls generic vectors, are another kind of data storage; they have elements, each of which can contain any type of R object, so the elements do not have to be of the same type; and lists are vectors, with the basic vector types being called atomic vectors where it is necessary to exclude lists (The R Language Definition: Lists). An Introduction to R says the same for beginners: an R list is an ordered collection of objects known as its components, and the components need not be of the same mode or type (An Introduction to R: Lists). Two words in that description decide how lists behave:

  • A list is a vector, so it has a length, it can have names and other attributes, and it is indexed with [, [[ and $. Functions written for vectors, such as length(), rev(), c(), head() and lapply(), work on lists.

  • A list is recursive: its elements can be lists, so a list is a tree. An atomic vector is a flat sequence of values of one type; a list is a flat sequence of references to objects of any type, and that is what lets it hold a tree.

is.list(), is.vector(), is.recursive() and is.atomic() are four different questions. is.list() asks whether the type is a list (or a pairlist), is.vector() asks whether the object is a plain vector of a given mode with no attributes other than names, is.recursive() asks whether the object can hold other objects, and is.atomic() asks whether it is one of the atomic types. Since R 4.4.0 is.atomic(NULL) is FALSE, so NULL is neither atomic nor a list; the page Missing and Special Values covers NULL.

is.vector(entry)
#> [1] TRUE
is.recursive(entry)
#> [1] TRUE
is.atomic(entry)
#> [1] FALSE
is.vector(entry, mode = "list")
#> [1] TRUE
is.vector(entry, mode = "character")
#> [1] FALSE

Printing a list

The way a list prints is the way to read its structure. An element without a name is labelled with its position, [[1]], an element with a name is labelled $name, and the labels of a nested list are chained: $a$b is the element b of the element a, and [[3]][[1]] is the first element of the third. A NULL element prints as NULL. An empty element name is not a name, so an element that has none among named ones prints with its position. Printing a long, deeply nested list is hard to read, which is why the section on str() below is the habit to build; print() is what the console does automatically, and it calls the print method of each element that has a class, as the shelf records further down show.

# A list can nest, and printing shows the path to each element.
nested <- list(a = list(b = 1:3, c = "x"), 2, list(NULL))
nested
#> $a
#> $a$b
#> [1] 1 2 3
#>
#> $a$c
#> [1] "x"
#>
#>
#> [[2]]
#> [1] 2
#>
#> [[3]]
#> [[3]][[1]]
#> NULL
#>
#>

# A list without names prints [[i]] headers; names print as $name.
list(1, "a", TRUE)
#> [[1]]
#> [1] 1
#>
#> [[2]]
#> [1] "a"
#>
#> [[3]]

vector("list", n) creates a list of n elements that are all NULL. It is the list counterpart of numeric(n) and character(n) and the way to pre-allocate a list that a loop fills in. list() itself is the constructor for a list of known elements, and it nests: whatever is passed in is stored as one element, so a vector is not spread over several elements. A list can also hold functions, environments, calls and NULL, which is why functions such as lapply() can work on lists of closures, lists of environments and lists of models.

Extraction: single bracket, double bracket and dollar

A list has three extraction operators, and the difference between them is the most important fact about lists. The help page for the operators states it in two sentences: indexing by [ selects a list of the specified elements, and both [[ and $ select a single element of the list; the main difference between the last two is that $ does not allow computed indices, whereas [[ does (R documentation: Extract). The mnemonic that is often used is the train and the passenger: [ gives you a smaller train (still a list), [[ gives you what is in the carriage.

$ takes a name that is written in the code, not a value; x$field is the element called field, even when a variable called field exists. To use a name that is held in a variable, use [[. This is the most frequent error when a loop over field names uses $: it silently returns NULL. For the same reason $ is convenient at the console and in a function that knows its field names, and [[ is the one to use in generic code.

# [[ and $ work through a character string too.
field <- "genres"
entry[[field]]
#> [1] "Science fiction" "Classic"
entry$field
#> NULL

Source: R documentation: Extract

Nested access and recursive indexing

A list of lists is read by chaining: x$a$b or x[["a"]][["b"]] evaluates the first extraction and applies the next one to the result. The help page for the operators adds that [[ can be applied recursively: if the single index i is a vector of length p, then alist[[i]] is equivalent to alist[[i1]]...[[ip]], provided that all but the final indexing result in a list. The index vector can be numbers or names, and it is also the form of a path that is held in a variable. The final extraction can be of any length-one element, including one that is itself a list.

# Nested access: step by step, or with a vector in [[ (recursive indexing).
catalogue <- list(
  fiction = list(
    classic = list(title = "Pride and Prejudice", year = 1813L),
    modern = list(title = "Loud Roofs", year = 2021L)
  ),
  poetry = list(title = "Paper Moons", year = 2005L)
)
catalogue$fiction$classic$title
#> [1] "Pride and Prejudice"
catalogue[["fiction"]][["modern"]][["year"]]
#> [1] 2021
catalogue[[c("fiction", "classic", "title")]]
#> [1] "Pride and Prejudice"
catalogue[[c(1L, 2L, 1L)]]
#> [1] "Loud Roofs"
catalogue[[c(1L, 2L)]]
#> $title
#> [1] "Loud Roofs"
#>
#> $year
#> [1] 2021
#>

Source: The R Language Definition: Indexing

A chain stops at the first NULL. x$a$b is NULL when a is missing, because NULL$b is NULL; this convenient behaviour is also the reason a misspelt field name inside a long chain is not noticed. A recursive index vector is stricter: it signals an error as soon as a step has nothing to descend into.

Partial matching with $

$ is the one extraction operator that matches names partially: x$ti finds title when it is the only name that starts with ti. The help page says that x$name is equivalent to x[["name", exact = FALSE]], that [[ does not partial-match unless exact = FALSE, that exact = NA allows partial matching with a warning, and that the default behaviour is to use partial matching only when extracting from recursive objects (except environments) by $. getElement(x, name) is x[[name, exact = TRUE]] and is the exact accessor that also works on S4 objects. The option warnPartialMatchDollar turns every partial match with $ into a warning; it is worth setting while developing code that handles lists of records, where a partial match is almost always a bug. The reverse is the usual reason to write the full name: a record that later gains a field title_sort makes x$ti ambiguous and returns NULL.

# $ partial-matches a name, [[ does not unless exact = FALSE.
partial <- list(title = "Notes on Gravity", year = 2017L)
partial$ti
#> [1] "Notes on Gravity"
partial[["ti"]]
#> NULL
partial[["ti", exact = FALSE]]
#> [1] "Notes on Gravity"
tryCatch(partial[["ti", exact = NA]], warning = \(w) conditionMessage(w))
#> [1] "partial match of 'ti' to 'title'"
getElement(partial, "ti")
#> NULL

Source: R documentation: options (warnPartialMatchDollar)

Putting things in and taking them out

The three operators have assignment forms, [<-, [[<- and $<-, and they follow the same division of labour: x[i] <- value replaces a slice and expects a list on the right when the slice should hold list elements, x[[i]] <- value and x$name <- value replace a single element. Assigning to a name that does not exist adds an element at the end; assigning to a position beyond the end extends the list and pads the gap with NULL. A name is an attribute, so an element added by position has an empty name when the other elements have names. The assignments follow copy-on-modify like every other R object (see Assignment, Names and Values): a list that is modified is copied shallowly, which means the new list refers to the same element objects as the old one for every element that was not changed, so modifying a long list does not duplicate its contents. The page Memory and Copy Semantics has the details.

# Adding, replacing and deleting elements by name and by position.
x <- list(a = 1, b = "two")
x$c <- c(3, 3, 3)
x[["d"]] <- list(4)
x[5L] <- list("five")
names(x)
#> [1] "a" "b" "c" "d" ""
x[["a"]] <- 100
x$a
#> [1] 100
str(x)
#> List of 5
#>  $ a: num 100
#>  $ b: chr "two"
#>  $ c: num [1:3] 3 3 3
#>  $ d:List of 1
#>   ..$ : num 4
#>  $  : chr "five"

Source: The R Language Definition: Subset assignment

Deleting with NULL, keeping with list(NULL)

The R FAQ has an entry for the most surprising consequence. FAQ 7.1, "How can I set components of a list to NULL?", says: use x[i] <- list(NULL) to set component i of the list x to NULL, similarly for named components, and do not set x[i] or x[[i]] to NULL, because this will remove the corresponding component from the list (R FAQ 7.1: How can I set components of a list to NULL?). The help page for the operators puts it as a rule for all three replacement forms: a value of NULL deletes the corresponding item of the list, and to set entries to NULL you need x[i] <- list(NULL).

Assigning deeper, and into NULL

An assignment through a chain, config$loans$limit <- 3L, is evaluated as a sequence of $ extractions followed by a replacement at each level, which R rewrites into nested calls of $<- (the page Assignment, Names and Values shows the rewrite). When an intermediate element does not exist it is NULL, and assigning with $<- into a NULL first turns it into a list, so the chain creates the missing levels as named lists. That is how a nested configuration is built up without writing the nesting out, and also how a misspelt level creates a new branch instead of failing.

The recursive form of [[<- takes a vector of names or positions, exactly as the extraction form does: x[[c("fiction", "classic", "year")]] <- 1813L replaces a leaf and adds a new one when its name is new. With $ the intermediate levels must be lists or NULL; if one is an atomic vector, x$a$b <- 2 gives the warning Coercing LHS to a list (the text was captured from R 4.6.1, see the section Lists and other types), whereas the recursive form x[[c("a", "b")]] <- 2 adds a named element to the vector.

The behaviour of an assignment into NULL changed in R 4.0.0. The help page for the operators says: when $<- is applied to a NULL x, it first coerces x to list(); this is also what happens with [[<-, where in R versions before 4.0.0 a length one value resulted in a length one (atomic) vector. The NEWS of R 4.0.0 gives the reason: N <- NULL; N[[1]] <- val now turns N into a list also when val has length one, which enables dimnames(r1)[[1]] <- "R1" for a one-row matrix (R NEWS: Changes in R 4.0.0). A tutorial that shows x <- NULL; x[["a"]] <- 1 giving the numeric vector 1 describes R 3.x.

Building and combining lists

There are three ways to put lists together and they behave differently, which is a frequent source of nested lists that were meant to be flat:

  • list(a, b) makes a list of two elements, each of which is a or b. Lists are nested.

  • c(a, b) joins. When any argument is a list the result is a list, and its elements are the elements of the list arguments (not the lists themselves) and one element per value of the atomic arguments, in the order of the arguments (so c(list(1), 2:3) has three elements). Names are kept. This is the operation described in An Introduction to R under "Concatenating lists" (An Introduction to R: Concatenating lists).

  • append(x, values, after) is c() with an insertion point. It works on lists the same way, so values must itself be a list when it is to be inserted as one element (list("inserted")), otherwise a character vector is spread over several elements.

The help page for c() also has an argument recursive: with recursive = TRUE, the arguments are flattened as unlist() would; the section on unlist() shows the equivalence.

Flattening with unlist()

unlist() goes the other way: it takes a list structure and produces a vector that holds all the atomic components. The help page defines it so: given a list structure x, unlist simplifies it to produce a vector which contains all the atomic components which occur in x. Three arguments control it: recursive (TRUE by default) decides whether list components of x are unlisted too, use.names (TRUE by default) decides whether names are built, and x is typically a list.

The type of the result is decided by coercion. Non-vector elements, such as functions, names, formulas and calls, are not coerced, so a list that contains one stays a list.

Names

With use.names = TRUE the names of the result are built from the names of the list and of its elements. The rule is implemented in compiled code and the help page documents it only by saying that unlist tries to retain the naming information: an element called a that holds one unnamed value gives the name a; one that holds several unnamed values gives a1, a2, and so on; and one that holds named values gives a.x, a.y, joining the names with a dot. An unnamed element inside a named list gets the name of the enclosing element. Two elements with the same name are not made unique. The consequence for a list that is going to be used by name is that unlist() is a convenient way to read a result and a poor way to build a lookup table; if names matter, build them yourself with setNames() or avoid flattening. use.names = FALSE drops all names, and for an atomic vector unlist() does nothing useful, not even drop the names.

recursive = FALSE and the cases that look like bugs

recursive = FALSE flattens one level only; elements that are lists are spliced into the result as list elements, and the names are joined in the same way. This is the idiom for turning a list of lists into one list of the inner elements. Two behaviours of unlist() surprise users of dates and factors. A list of Date objects loses the class, because unlist() does not know about the Date class and returns the underlying number of days; do.call(c, x) keeps the class because c() dispatches to c.Date. A list of factors is the opposite: unlist() is documented to combine factors, and the result is a factor whose levels are the union of the levels. c() combines factors in the same way since R 4.1.0, when its NEWS entry says that using c() to combine a factor with other factors now gives a factor (R NEWS: Changes in R 4.1.0).

Merging nested lists with modifyList()

A nested configuration is the typical list that has to be merged: the defaults of the program, a layer from a file and a layer from the command line, where a layer changes some leaves and leaves the others alone. modifyList(x, val, keep.null = FALSE) is the function in utils for it. The help page defines the result element by element: elements in val which are missing from x are added to x; for elements that are common to both but are not both lists themselves, the component in x is replaced by the one in val; and for common elements that are lists in both, x[[name]] is replaced by modifyList(x[[name]], val[[name]]). That makes it a recursive merge in which the right-hand list wins, and the shape of x is preserved except where val says otherwise.

NULL in val deletes the element in x, consistent with the rule of assignment, unless keep.null = TRUE, in which case the NULL is stored. The argument keep.null was added in R 3.0.2; its NEWS entry says it allows NULL components in the replacement to be retained, instead of causing corresponding components to be deleted (R NEWS: Changes in R 3.0.2). Both lists must be lists: x has to be a named list, val is checked with is.list(), and its elements without a name are ignored.

#>  $ loan_days: int 21

Lists with the functional tools

A list is the natural argument of the higher-order functions of base R, which is why they appear on this page only in a short tour; the page The apply Family and Functionals has the detail, and Function Factories and Higher-Order Functions the design side.

Comparing lists

== does not compare two lists: for two lists it signals comparison of these types is not implemented, and for a list and an atomic vector it compares only when every element has length one, otherwise it fails with 'list' object cannot be coerced to type 'double'. Use identical(x, y) for exact equality, which compares the types, the values, the names and every attribute, and all.equal(x, y) for equality up to numerical tolerance: it returns TRUE or a character vector that says what differs, element by element, including the names and the lengths. Wrap all.equal() in isTRUE() when it is a condition, as the page Operators and Precedence explains for floating-point numbers.

# Comparing lists.
identical(list(1, "a"), list(1, "a"))
#> [1] TRUE
identical(list(1L), list(1))
#> [1] FALSE
all.equal(list(1, "a"), list(1L, "a"))
#> [1] TRUE
all.equal(list(a = 1, b = "x"), list(a = 2, b = "y"))
#> [1] "Component “a”: Mean relative difference: 1"
#> [2] "Component “b”: 1 string mismatch"
all.equal(list(a = 1), list(b = 1))
#> [1] "Names: 1 string mismatch"
all.equal(list(1, 2), list(1))
#> [1] "Length mismatch: comparison on first 1 components"
isTRUE(all.equal(list(a = 1), list(a = 1 + 1e-10)))
#> [1] TRUE

Lists and other types

A list is not an atomic vector, and the functions for numbers do not accept one. sum(list(1, 2, 3)) is an error, l + 1 is an error, and is.numeric(l) is FALSE even if every element is a number; the fix is unlist() first, or vapply() over the elements. In the other direction, x[2L] <- list("text") on an atomic vector turns the whole vector into a list, with each value in its own element, and $<- on an atomic vector coerces it with the warning Coercing LHS to a list, while [[<- adds an element to the vector without making it a list.

NULL, empty elements and matrices of lists

NULL in a list is a value like any other, with three consequences. list(1, NULL, 3) has three elements, whereas c(1, NULL, 3) has two, because c() drops NULL; lengths() returns 0 for a NULL element and for an empty vector alike; and lapply() keeps a NULL result in its slot, so the output is as long as the input. Lists as the basis of S3 objects

An S3 object is nothing more than a base-type object with a class attribute, and the base type is usually a list. The book is one example; a fitted model from lm() is another, a list of coefficients, residuals and other components of class "lm"; so is the result of t.test(), of class "htest". The consequence is that you can open an S3 object with the list tools: names(fit), fit$coefficients, str(unclass(fit)). The R Language Definition describes the mechanism in the section on object-oriented programming: the class is the attribute, and the dispatch looks at it (The R Language Definition: Object-oriented programming). The practice that follows from the list base is simple:

  • Build the object with structure(list(...), class = "name") inside a constructor function that checks the types, and validate the values in a separate function, as the scenario does with new_book() and validate_book().

  • Access the fields with $ and [[ inside the methods, and give the users functions (accessors) so that the user code does not depend on the layout.

  • Keep in mind that unclass(x) removes the class and that inherits(x, "book") tests it; both are covered with the dispatch rules in S3 Classes and Generics.

Lists as the basis of data frames

A data frame is a list. More exactly, it is a list of equal-length columns with the attribute class set to "data.frame", the attribute names (the column names) and the attribute row.names. An Introduction to R says it at the start of its section on data frames: a data frame is a list with class "data.frame", with restrictions on the lists that may be made into data frames; vector variables must all have the same length, and matrix variables the same number of rows (An Introduction to R: Data frames). Every list operation of this page therefore works on a data frame, and the data frame class changes only the operators that need the row dimension.

JSON-shaped nested lists

A nested list is also the natural R image of a JSON document. A JSON object becomes a named list, a JSON array becomes either an atomic vector (when all its values have one scalar type) or an unnamed list, JSON null becomes NULL, and the three scalar types become length-one logical, numeric and character vectors. The package jsonlite (on CRAN; it is the usual tool and is not used here) reads and writes this mapping, with arguments such as simplifyVector and simplifyDataFrame that decide whether arrays of values become vectors and arrays of objects become data frames, or stay lists; the page Serialization: RDS, RData and JSON covers it, and the page HTTP and Web APIs shows how a response body arrives as such a list. The block below builds the list by hand so that the tools of this page can be applied to it without the package.

The shelf catalogue is a named list with a name, an array of three book objects and a flag. str(catalogue, max.level = 2L) shows the top of the tree. The three tags fields are different on purpose: a vector of two strings, an empty character vector (JSON []) and a single string; and the third book has year = NULL, which list() keeps as an element (JSON null) while an assignment b$year <- NULL would delete it.

# A nested list shaped like a JSON document: objects are named lists, arrays
# are unnamed lists or vectors, null is NULL.
catalogue <- list(
  shelf = "Main hall",
  books = list(
    list(title = "Paper Moons", year = 2005L, tags = c("poetry", "short")),
    list(title = "Ten Winters", year = 2022L, tags = character()),
    list(title = "Loud Roofs", year = NULL, tags = "novel")
  ),
  open = TRUE
)
str(catalogue, max.level = 2L)

#>  $ books:List of 3

#>   ..$ :List of 3

The block shows the three habits that a JSON-shaped list needs. First, read the fields with vapply() and a declared type, so that a missing or wrongly typed field is an error and not a silent NA. Second, give the missing value an explicit default with the operator %||%, which returns its right-hand side when the left is NULL; it is in base R since 4.4.0 (R NEWS: Changes in R 4.4.0), and the page Operators and Precedence covers it. Third, flatten to a table with list2DF() from vectors that were built field by field, as the last block does, because unlist() of a record turns every field into a string when one of them is a string.
