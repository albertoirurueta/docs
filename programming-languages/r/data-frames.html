Data Frames

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. A data frame is R’s name for a table: a list of columns of equal length, each column a vector of one type, with one row per observation. This page shows how to build one (and what the stringsAsFactors = FALSE default of R 4.0.0 changed), how to look inside it, how row names work and fail, how to select, filter, add and remove columns and rows, how to sort and join, how to summarise by group with the split-apply-combine pattern and its base shortcuts (aggregate(), tapply(), by(), ave(), rowsum()), how to reshape between long and wide, how to find duplicates, and how to print. Every example uses base R and the packages that ship with it (base, utils, stats and tools), except one short example that runs tibble, checked at version 3.3.1. The add-on package data.table, checked at version 1.18.6.1, appears in prose only; no data.table code is run. Both are described in a section near the end and have pages of their own: The tidyverse and dplyr, tidyr, purrr and stringr and data.table.

Every example below is a complete script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts also pass the default lintr linters. Errors and warnings that a script shows on purpose are caught with tryCatch() and printed as their conditionMessage(), so the text is exactly what R says. The examples use the library-shelf scenario of the section: the data frames books and loans, the constants shelf_today and loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"), which reads books.csv with read.csv("books.csv") and loans.csv with read.csv("loans.csv", colClasses = "character"). books has 16 rows and the columns title, author, isbn, year, genre and pages; loans has 60 rows and the columns loan_id, isbn, member, loan_date and return_date. Both are deliberately untidy (blanks, two spellings of one author, an empty ISBN, NA years and page counts, an impossible date, a loan returned before it was made), because most of the work with data frames is cleaning them. This page is the data-frame chapter of the vectors-and-data-structures group: Lists covers the type underneath, Subsetting and Indexing the general rules of [, [[ and $, Factors the categorical columns, Missing and Special Values the NA that runs through the examples, and Attributes and Names the attributes a data frame is built from.

What a data frame is

The two manuals say the same thing in different words. An Introduction to R says that a data frame is a list with class "data.frame"; the components must be vectors, factors, numeric matrices, lists or other data frames; vector components must all have the same length and matrix components the same number of rows (An Introduction to R: Data frames). The language definition describes a data frame as the structure that most closely mimics a SAS or SPSS data set, a table of cases by variables: a list of vectors, factors and matrices of equal length, with a names attribute that labels the variables and a row.names attribute that labels the cases (The R Language Definition: Data frame objects). The language definition adds a warning that a list column of differing element lengths, which would give a ragged array, is not generally handled correctly by the functions that work on data frames.

Three consequences shape everything else on this page.

  • A data frame is a list, so length(df) is the number of columns, df[[1]] is the first column, and lapply(), Filter() and vapply() walk the columns.

  • A data frame looks like a matrix, so dim(), nrow(), ncol() and the two-index form df[i, j] work, but each column keeps its own type. Operations that need a single type (apply(), t(), as.matrix()) convert the whole table first, which is where many surprises come from.

  • The row names are part of the structure. Every data frame has them, they are unique, and subsetting carries them along.

source("scenario.R")

Source: The R Language Definition: Data frame objects

The three attributes in the output are names, class and row.names. unclass() strips the class, and what remains is an ordinary named list with one attribute left over, the row names. dput() shows the representation that R keeps internally. The row names of small are written c(NA, 3L): when the row names are the integers 1:n with n above 2, R stores them in a compact form, a two-element integer vector that starts with NA, instead of a vector of length n. The help page for row.names says this form is visible only to C code or by deparsing, never through row.names() or attr(x, "row.names"), which expand it. A negative second element, as in the -16 of books, marks the row names as automatic (added by R because the creator gave none); the positive 3 of small is the same sequence, kept by the subset books[1:3, ], but not marked automatic. The function .row_names_info() reports the number of rows with a negative sign for automatic names (type = 1, the default) or the raw stored vector (type = 0). It is documented among the internal objects of the base package, so it is shown here to explain the structure and is not something a script should depend on.

Source: R documentation: row.names

Building a data frame

data.frame()

data.frame() is the constructor. Each argument is a column; a named argument gives the column its name; vectors of length one are recycled to the number of rows. Its signature is data.frame(..., row.names = NULL, check.rows = FALSE, check.names = TRUE, fix.empty.names = TRUE, stringsAsFactors = FALSE) (R documentation: data.frame). It converts every argument with as.data.frame(), so a matrix, a list or another data frame passed as an argument contributes one column per column, element or variable.

# data.frame() builds a data frame from vectors; scalars are recycled.
members <- data.frame(
  member = c("Ana Ruiz", "Ben Okafor", "Dev Patel"),
  joined = as.Date(c("2024-03-01", "2023-11-15", "2025-01-10")),
  active = c(TRUE, TRUE, FALSE),
  tier = "standard"
)
members
#>       member     joined active     tier
#> 1   Ana Ruiz 2024-03-01   TRUE standard
#> 2 Ben Okafor 2023-11-15   TRUE standard
#> 3  Dev Patel 2025-01-10  FALSE standard
str(members)
#> 'data.frame':	3 obs. of  4 variables:
#>  $ member: chr  "Ana Ruiz" "Ben Okafor" "Dev Patel"
#>  $ joined: Date, format: "2024-03-01" "2023-11-15" ...
#>  $ active: logi  TRUE TRUE FALSE
#>  $ tier  : chr  "standard" "standard" "standard"

# Since R 4.0.0 character vectors stay character; ask for factors explicitly.

The tier column of members shows the recycling of a length-one value. str() is the quickest way to see the column types; the Date column prints compactly, and the character columns are character vectors, not factors.

The stringsAsFactors default

Before R 4.0.0 data.frame() and read.table() (and so read.csv()) converted every character vector to a factor by default, and a large part of the older material on the web still works around it with stringsAsFactors = FALSE. The NEWS entry for R 4.0.0 says that R now uses a stringsAsFactors = FALSE default and so by default "no longer converts strings to factors in calls to data.frame() and read.table()" (R NEWS: Changes in R 4.0.0). The help page records the same change: the factory-fresh default had been TRUE and became FALSE for R 4.0.0. The argument still exists, so stringsAsFactors = TRUE asks for factors explicitly, as the last lines of the script above do, and factor() or as.factor() converts a column later. The consequence for code is that levels() of a text column is now NULL, table() of it still works, and a column that really is categorical, with a fixed set of allowed values, must be made a factor on purpose (see Factors).

Source: R NEWS: Changes in R 4.0.0

Recycling and the "differing number of rows" error

data.frame() recycles a shorter column only when the longer length is a whole multiple of it. The help page says that atomic vectors, factors and character vectors protected by I() are recycled a whole number of times if necessary, including as elements of list arguments. Anything else is an error.

# Columns are recycled only when the longer length is a multiple of the shorter.
data.frame(copy = 1:6, shelf = c("A", "B", "C"))
#>   copy shelf
#> 1    1     A
#> 2    2     B
#> 3    3     C
#> 4    4     A
#> 5    5     B
#> 6    6     C

# Otherwise data.frame() stops, with this message.
tryCatch(
  data.frame(title = c("Ten Winters", "Loud Roofs", "Paper Moons"), year = 1:2),
  error = conditionMessage
)
#> [1] "arguments imply differing number of rows: 3, 2"

# A list column holds one vector per row. Assign it with $<-, or wrap it in
# I() inside data.frame() so that the list is not split into columns.
tags <- list(c("new", "popular"), "reissue")
with_lists <- data.frame(id = 1:2, tags = I(tags))
with_lists
#>   id         tags
#> 1  1 new, popular
#> 2  2      reissue
str(with_lists)
#> 'data.frame':	2 obs. of  2 variables:
#>  $ id  : int  1 2
#>  $ tags:List of 2
#>   ..$ : chr  "new" "popular"
#>   ..$ : chr "reissue"
#>   ..- attr(*, "class")= chr "AsIs"
vapply(with_lists$tags, length, integer(1))
#> [1] 2 1

Source: R documentation: data.frame

The message is arguments imply differing number of rows: 3, 2, listing the distinct row counts it met, in the order found. A list column, a column whose cells are themselves vectors, is built with I() in data.frame() or by assigning a list with $<-. The str() output shows it as a list of two elements. List columns are legitimate but most functions in this page treat the cell as one opaque object, and the language definition warns that ragged columns are not handled correctly everywhere.

Column names: check.names and the X prefix

check.names = TRUE, the default, passes the column names through make.names() so that they are syntactically valid and unique: a space becomes a dot, a name that starts with a digit gets an X prefix, a reserved word such as if gets a trailing dot, and a duplicate gets .1, .2, and so on. The help page describes this as checking that the names are syntactically valid variable names and not duplicated, adjusting them with make.names where necessary. read.csv() has the same argument and the same rule, which is the source of the X2025.total style of name that appears when a CSV header starts with a digit or contains a space.

# data.frame() turns column names into syntactic names (check.names = TRUE).
odd <- data.frame(
  `first name` = "Ana", `2nd loan` = 2L, `if` = TRUE, dup = 1, dup = 2
)
names(odd)
#> [1] "first.name" "X2nd.loan"  "if."        "dup"        "dup.1"

# check.names = FALSE keeps the names; they then need backquotes to use.
raw <- data.frame(`first name` = "Ana", `2nd loan` = 2L, check.names = FALSE)
names(raw)
#> [1] "first name" "2nd loan"
raw$`first name`
#> [1] "Ana"

# make.names() is the function behind it; unique = TRUE adds .1, .2.
make.names(c("first name", "2nd loan", "if", "dup", "dup", ""), unique = TRUE)
#> [1] "first.name" "X2nd.loan"  "if."        "dup"        "dup.1"
#> [6] "X"

# A name already syntactic is kept; read.csv() applies the same rule, which
# is where the X prefix comes from.
csv_text <- "id,2025 total,total
1,10,20"
read.csv(text = csv_text)
#>   id X2025.total total
#> 1  1          10    20
names(read.csv(text = csv_text, check.names = FALSE))
#> [1] "id"         "2025 total" "total"

Source: R documentation: make.names

With check.names = FALSE the original names are kept, and then they need backquotes whenever they are used in code, as the last line of the script shows. The more robust habit is to rename the columns once, at the top of the script, to snake case names, and use those names everywhere.

read.csv(), as.data.frame() and list2DF()

read.csv("books.csv") is the usual way to get a data frame from a file; the details of delimiters, na.strings, colClasses, encodings and large files belong to Reading and Writing Text Data. as.data.frame() converts other objects: a matrix becomes a data frame with columns V1, V2, and so on unless it has column names, a list becomes one column per element (after the same recycling rule), and a table becomes the long form with a Freq column. list2DF(), added in R 4.0.0, is the minimal constructor: it takes a list of equal-length columns and builds the data frame directly, without name checking, recycling or conversion of the columns, so it is the fast and exact way to turn a list you already trust into a data frame. Its nrow argument gives the row count of a data frame without columns.

source("scenario.R")

Looking at a data frame

Partial matching of row names

The extraction methods [ and [[ for data frames match row names partially: the help page says that both partially match row names, that neither does by default for column names, and that match() should be used for exact matching on row names. This is easy to forget when row names are used as keys, because a prefix of a key is silently accepted, and an ambiguous prefix gives a row of NA rather than an error.

subset() and its non-standard evaluation

Adding rows

rbind() on data frames appends rows. The second argument can be another data frame, matched to the first by column name, not by position, or a list, matched by position. If the names differ or the number of columns differs, the error is names do not match previous names or numbers of columns of arguments do not match. Since R 4.2.0, binding a vector whose length is not a divisor of the number of columns also warns.

source("scenario.R")

tryCatch(

with(), within() and why not attach()

with(df, expr) evaluates expr with the columns visible as variables and returns the value of the expression; within(df, expr) does the same and returns the modified data frame, so assignments inside the braces create or change columns and rm() removes them. Both are in the help page with, and both are the safe replacements for attach(): the data frame is visible only for the duration of the expression.

source("scenario.R")

  age <- 2026L - year

within() has a quirk worth knowing: variables created inside it are added to the data frame in the reverse of the order in which they were created (long before age, although age was assigned first). transform() keeps the order of its arguments but cannot refer to a column created in the same call, as the error object 'age' not found shows. For a sequence of dependent steps, plain df$new <- ... statements are the most readable.

attach(): why older tutorials are wrong

An Introduction to R devotes a whole section to attach() and detach() (6.3.2) and a convention for working with data frames that attaches one at position 2 of the search path, works with bare names, and detaches it at the end (An Introduction to R: attach() and detach(), Working with data frames). The same manual lists the caveats: what is attached is a copy of the data frame, so changes to the data frame are not visible to the attached names until it is detached and attached again; assigning to an attached name creates a new variable in the workspace, which masks the attached one, instead of changing the data frame; lists and data frames can only be attached at position 2 or later; and detach() should name what it detaches. Section 6.3.4 of that manual extends attach() to any list, and with() likewise accepts a list or an environment (Attaching arbitrary lists). The R FAQ repeats the position restriction in R FAQ 3.3.3: Others, in the list of differences between R and S. Modern code avoids attach() for these reasons: two data frames with the same column names mask each other silently, a script that attaches inside a function leaves the search path changed on error, and a reader cannot tell where a name comes from.

The script below shows the older style, caught and shown so that the effects are visible; it is not a pattern to copy.

Sorting

R has no ORDER BY. A data frame is sorted by computing a permutation of the row numbers with order() and indexing the rows with it: df[order(df$a, df$b), ]. The R FAQ answers the question "How can I sort the rows of a data frame?" with exactly that expression (R FAQ 7.23), and adds that from R 4.4.0 sort_by() provides a less verbose alternative with a formula interface. sort() is not the tool: it sorts one vector and returns the sorted values, not the permutation.

order()

order(..., na.last = TRUE, decreasing = FALSE, method = c("auto", "shell", "radix")) takes one or more keys of the same length and returns the integer permutation. Later keys break ties in earlier ones; the sort is stable, so rows that tie on every key keep their original order; NA go last by default.

Sorting text depends on the locale

For character keys, every method except "radix" follows the collating sequence of the locale, and "radix" always compares code points as in the C locale. The two disagree on case. In an English UTF-8 locale (the example locale name is en_US.UTF-8; the container that produced the output below used it) "Ten Winters" sorts before "THE LONG TABLE", and in the radix order every upper-case letter sorts before every lower-case one, so "THE LONG TABLE" comes first. A script that must give the same order on every machine either sorts on tolower(x) or sets method = "radix" and accepts the code-point order; see Encodings, Locales and Internationalization.

source("scenario.R")

# Character keys are compared with the collation rules of the locale, unless
# method = "radix" is used, which always compares code points (C locale).
titles <- c(
  "the quiet streets", "THE LONG TABLE", "Ten Winters", "A Map of Salt"
)
titles[order(titles)]
#> [1] "A Map of Salt"     "Ten Winters"       "THE LONG TABLE"
#> [4] "the quiet streets"
titles[order(titles, method = "radix")]
#> [1] "A Map of Salt"     "THE LONG TABLE"    "Ten Winters"
#> [4] "the quiet streets"
sort(titles)
#> [1] "A Map of Salt"     "Ten Winters"       "THE LONG TABLE"
#> [4] "the quiet streets"
sort(titles, method = "radix")
#> [1] "A Map of Salt"     "THE LONG TABLE"    "Ten Winters"
#> [4] "the quiet streets"

# Lower-case the key when the order must not depend on the locale.
titles[order(tolower(titles))]
#> [1] "A Map of Salt"     "Ten Winters"       "THE LONG TABLE"
#> [4] "the quiet streets"

sort_by()

sort_by() is a generic function added in R 4.4.0. The NEWS entry describes it as primarily useful for its data frame method, which sorts the rows of a data frame by one or more columns (R NEWS: Changes in R 4.4.0). For a data frame, y is typically a formula whose terms are evaluated inside the data frame: ~ g or ~ list(g) sorts by g, and ~ g1 + g2 or ~ list(g1, g2) by several keys with the later ones breaking ties. It is a front end to order(): the keys are collected and passed to it, and the remaining arguments (decreasing, na.last, method) go to order() too. If y is not a formula, a vector or a list of vectors is used as given, with no non-standard evaluation. The default method sorts a vector by another vector, x[order(y, ...)].

source("scenario.R")
books$genre <- tolower(trimws(books$genre))
shelf <- books[c("title", "genre", "year")]

sort_by(shelf, ~ genre + year)[1:5, ]

#> 8      The Lamp at Noon classic 1999
#> 3    the quiet streets  fiction 2019
#> 4            Loud Roofs fiction 2021
#> 15          Ten Winters fiction 2022

# ~ list() takes any expression per key, including a negated one.
sort_by(shelf, ~ list(genre, -year))[1:5, ]

#> 8     The Lamp at Noon classic 1999
#> 2  Pride and Prejudice classic 1813
#> 10      THE LONG TABLE fiction 2023
#> 15         Ten Winters fiction 2022
#> 4           Loud Roofs fiction 2021

#>                  title   genre year
#> 8     The Lamp at Noon classic 1999
#> 2  Pride and Prejudice classic 1813

What can go wrong in a merge

source("scenario.R")

# Duplicate keys multiply: two copies of one book make two rows per loan.

  isbn = c("9780141439518", "9780141439518", "9780306406157"),
  copy = c("A", "B", "A")

#> [1] 13

# NA keys match each other by default; incomparables = NA stops that.
a <- data.frame(isbn = c("x", NA), left = 1:2)
b <- data.frame(isbn = c("x", NA), right = 3:4)
merge(a, b, by = "isbn")
#>   isbn left right
#> 1    x    1     3
#> 2 <NA>    2     4
merge(a, b, by = "isbn", incomparables = NA)
#>   isbn left right
#> 1    x    1     3

# A key that is not a column of both frames.
tryCatch(merge(loans, a, by = "member"), error = conditionMessage)
#> [1] "'by' must specify a uniquely valid column"

# by = NULL (or character(0)) gives every combination: a cross join.

#> [1] 6 2

Source: R documentation: merge

  • Duplicate keys multiply. The help page says that if there is more than one match, all possible matches contribute one row each. Joining loans_of_two (10 loans) to copies (two copies of one book and one of another) gives 13 rows, not 10. A join result with more rows than either input is the sign of duplicate keys; check with anyDuplicated(y$key) before a join that is meant to add a column.

  • NA keys match each other. The ISBN NA in a matched the NA in b. Databases do not match NULL records, and the help page notes that this corresponds to incomparables = NA in R. Remove the missing keys first or pass incomparables = NA.

  • A key missing from either frame. by = "member" fails with 'by' must specify a uniquely valid column when member is not a column of both data frames (or of the pair named by by.x and by.y).

  • Row order is lost. The default sort = TRUE re-sorts the result on the key. If the original order matters, use match() for a lookup, or keep a row-number column and sort again.

  • Cross joins are quadratic. by = NULL returns nrow(x) * nrow(y) rows (6 for the two-by-three example above).

Grouping and summarising

"Compute something for each group" is the most common operation on a table, and R has one underlying pattern and a family of shortcuts. The pattern is split-apply-combine: split the data frame into pieces by a key, apply a function to each piece, and combine the results. split() does the first step, lapply() or vapply() the second, and do.call(rbind, ...) (for data frames) or unlist() (for scalars) the third. The base functions aggregate(), tapply(), by(), ave() and rowsum() package the pattern for the common cases.

"one call" .-> agg["aggregate(), tapply(), by()"] agg -.-> out df -. "result as long as the input" .-> ave["ave()"] ave -.-> back["new column, same rows"]

The solid path is the explicit version: three steps that can each be inspected. The dotted paths are the shortcuts that do all the steps in one call: aggregate(), tapply() and by() collapse each group to a summary, while ave() returns a vector as long as the input, one value per original row, so it can be assigned back as a new column. The explicit form is the one to reach for when the function per group is not a simple summary (the top two books of every genre, a model per group), and the shortcut when it is.

aggregate()

aggregate() is the one-call version for summaries. It has two calling forms.

  • Formula: aggregate(pages ~ genre, data = books, FUN = mean). The left side names what to summarise (cbind(pages, year) for several columns, or . for all the others), the right side names the grouping columns (genre + decade for several), and data supplies them. A formula is the readable form, but it applies na.action = na.omit by default: any row with an NA in any variable of the formula is dropped before the function sees it.

  • Non-formula: aggregate(x, by = list(genre = books$genre), FUN = mean), where x is a vector or a data frame and by is a named list of grouping vectors (a data frame of keys works too). No rows are dropped: NA values reach FUN, and a group whose key is NA is left out of the result.

tapply() and by()

tapply(X, INDEX, FUN) applies FUN to the groups of a vector formed by one factor (the result is a named vector) or by several (the result is an array, a matrix for two factors, with NA in the cells that have no data). simplify = FALSE returns a list, and default = 0 replaces the NA of the empty cells (for functions such as length() where zero is the right value). Since R 4.3.0 tapply() accepts a data frame as X with a formula as INDEX, and by() accepts a formula as INDICES. by(data, INDICES, FUN) is the data frame counterpart: FUN receives the sub-data-frame, and the result is an object of class "by" that prints one block per group. Bind its data frame results back with do.call(rbind, ...).

ave(): group statistics as a column

Reshaping: long and wide

A table is long when each row is one observation (one member in one quarter) and wide when one of the identifying variables is spread across columns (one row per member, one column per quarter). Reports are usually wide and analysis is usually long. Base R converts between them with reshape(), and with the simpler stack() and unstack().

The wide table of loans per member per quarter has two routes. table() makes it directly from the rows, with a zero for every combination that does not occur. aggregate() makes the long form with only the combinations that do occur.

stack(), unstack() and why not t()

stack(x) takes a list or the columns of a data frame and returns a two-column data frame values and ind, with ind a factor naming the original column. unstack() reverses it, returning a data frame when the groups have equal lengths and a list when they do not. These are the right tools for plotting or modelling several columns together, and for turning a list of vectors into a table.

A data frame is not a matrix, and t() is the wrong way to turn rows into columns. t(df) first converts the data frame with as.matrix(): if any column is not numeric the whole matrix becomes character, the numbers are formatted as text, and the result has lost its column types. For numeric columns only, t() gives a numeric matrix, which is correct, but it is a matrix and no longer a data frame. data.matrix() converts a data frame to a numeric matrix by turning character columns into integer codes of a factor, which is almost never what is meant (the title column of the last example became the codes 3, 2, 1). To turn the rows of a data frame into columns, use reshape(), or as.data.frame(t(...)) after selecting only the columns that can be transposed.

Duplicates

duplicated(x) returns TRUE for every element that already occurred earlier in x; fromLast = TRUE scans from the end instead; unique(x) returns the distinct values, in order of first appearance; anyDuplicated(x) returns the index of the first duplicate, or 0 when there is none, which is the cheapest test of "is this key unique?". All three have data frame methods that compare rows, over all columns or over a subset of columns selected first (duplicated(books[c("author", "genre")])). Working row by row

Row-wise work on a data frame is the case where it behaves least like a matrix. apply(df, 1, f) converts the data frame with as.matrix() first, so with a mixed-type data frame every row is a character vector and numbers are formatted with a common width: the page count 88 arrives as " 88", with a leading blank. Work with whole columns instead (sprintf() and paste() are vectorised), use mapply() or Map() over the columns when a function takes one value from each column, loop over seq_len(nrow(df)) when a step needs the whole row, or split(df, seq_len(nrow(df))) for a list of one-row data frames.

source("scenario.R")
shelf <- books[c(11, 1, 2), c("title", "year", "pages")]

# apply() turns the data frame into a matrix first; with mixed types that is a
# character matrix, and as.matrix() pads the numbers to a common width.
apply(shelf, 1, \(row) row[["pages"]])
#>    11     1     2
#> " 88" "387" "432"
apply(shelf, 1, \(row) paste0(row[["title"]], ": ", row[["pages"]], " pages"))
#>                               11                                1
#>         "Paper Moons:  88 pages"    "The Dispossessed: 387 pages"
#>                                2
#> "Pride and Prejudice: 432 pages"

# Work on the columns instead: vectorised functions, or mapply() over them.
sprintf("%s: %d pages", shelf$title, shelf$pages)
#> [1] "Paper Moons: 88 pages"          "The Dispossessed: 387 pages"
#> [3] "Pride and Prejudice: 432 pages"
label <- \(title, year) sprintf("%s (%d)", title, year)
mapply(label, shelf$title, shelf$year, USE.NAMES = FALSE)
#> [1] "Paper Moons (2005)"         "The Dispossessed (1974)"
#> [3] "Pride and Prejudice (1813)"

# A loop over row numbers is fine when a step needs the whole row.

}
#> 1 Paper Moons 2005
#> 2 The Dispossessed 1974
#> 3 Pride and Prejudice 1813

# split() by row gives one data frame per row, with the row names as names.

#> [1] "1" "2" "3"

Factor columns

A factor column keeps its full set of levels after the rows are filtered, so table() still lists the empty levels and tapply() still reports them. droplevels() removes the unused levels from every factor column of a data frame. Assigning a value that is not a level gives NA and the warning invalid factor level, NA generated, while rbind() with a character value extends the levels. Since R 4.0.0 text columns are character by default, so these effects appear only when a column is made a factor on purpose.

source("scenario.R")
tidy <- read.csv("books.csv", stringsAsFactors = TRUE)
tidy$genre <- factor(tolower(trimws(as.character(tidy$genre))))

# Subsetting rows keeps every level of a factor column.
keep <- tidy$genre %in% c("poetry", "mystery")
poetry_mystery <- tidy[keep, c("title", "genre")]
levels(poetry_mystery$genre)
#> [1] "classic"         "fiction"         "mystery"         "non-fiction"
#> [5] "poetry"          "science fiction"
table(poetry_mystery$genre)
#>
#>         classic         fiction         mystery     non-fiction          poetry
#>               0               0               2               0               2
#> science fiction
#>               0

# droplevels() removes the unused levels from every factor column.
levels(droplevels(poetry_mystery)$genre)
#> [1] "mystery" "poetry"

# rbind() with character values adds new levels...
extra <- data.frame(title = "Cookbook", genre = "cooking")
levels(rbind(poetry_mystery, extra)$genre)
#> [1] "classic"         "fiction"         "mystery"         "non-fiction"
#> [5] "poetry"          "science fiction" "cooking"

# ...but assigning a value that is not a level gives NA and a warning.
tryCatch(
  poetry_mystery$genre[1L] <- "cooking",

#> [1] "invalid factor level, NA generated"

# Convert back to character for string work.

#> [1] "character"

Printing

print() of a data frame has arguments of its own, and several options control the rest. row.names = FALSE hides the row names, right = FALSE left-aligns text, digits sets the significant digits, quote = TRUE quotes strings, and max caps the number of entries. The global options are width (the line width in characters, which decides where wide data frames wrap their columns), digits, and max.print, which is the maximum number of entries printed by default: for a data frame it prints as many whole rows as fit in max.print divided by the number of columns, followed by the message [ reached 'max' / getOption("max.print") -- omitted 11 rows ]. The default is 99999. format() converts a data frame to a data frame of character columns, which is the starting point for custom tables.

Tibbles and data.table

Two add-on packages provide alternatives to the base data frame, and both are covered in their own pages. They are labelled packages, not part of base R, and the base functions in this page keep working on both of them.

tibble (checked at version 3.3.1) is the data frame of the tidyverse. A tibble has class c("tbl_df", "tbl", "data.frame"), so every data frame function still applies, and it differs in a few places that remove the traps above: it drops row names on conversion, [ with one column returns a tibble and not a vector, $ does not match a partial name (it warns Unknown or uninitialised column and returns NULL), and it does not recycle anything except length-one values. It prints the type of each column under its name and shows only the first rows that fit. It is created with tibble() or as_tibble().

data.table (checked at version 1.18.6.1) is a package for large tables that extends the data frame (a data.table is a data.frame too) with a terse DT[i, j, by] syntax, modification by reference (:=), keyed joins and fast grouping and reading (fread()). Because it modifies in place, it breaks the copy-on-modify rule that this page relies on: DT[, new := 1] changes DT without an assignment. Pitfalls

  • df[, "x"] is a vector, df["x"] is a data frame. Use drop = FALSE when the number of columns is not fixed (R FAQ 7.5 is the matrix version of the same rule).

  • NA in a row filter gives a row of NA. Use which(), subset(), or !is.na(x) & cond.

  • subset(), transform() and with() look inside the data first. A parameter named like a column loses; use a different name or df[which(df$year < cutoff), ] in functions.

  • Row names survive subsetting. Numbers select by position and strings by label; reset with rownames(df) <- NULL. [ matches row names partially, $ matches column names partially.

  • aggregate() with a formula drops whole rows with any NA. Use na.action = na.pass with na.rm = TRUE.

  • merge() re-sorts, multiplies rows for duplicate keys and matches NA with NA. Check anyDuplicated() on the key and normalise key text first.

  • - in a sort_by() formula is not "descending". Use ~ list(a, -b).

  • apply(), t() and as.matrix() on a mixed data frame give character. Work on columns.

  • df[-which(...)] drops every column when nothing matches. Use setdiff() or %in%.

  • rbind() in a loop is quadratic and do.call(rbind, named_list) mangles row names. Bind once; unname() or make.row.names = FALSE.

  • Converting a factor to numbers. as.numeric(f) gives the level codes; convert through as.character() first (R FAQ 7.10: How do I convert factors to numeric?).
