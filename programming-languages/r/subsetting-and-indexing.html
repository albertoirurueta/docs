Subsetting and Indexing

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

Checked against R 4.6.1 (2026-06-24) on 2026-10-20; R 4.6.2 is scheduled for 2026-10-29. Everything on this page is base R (base, utils, stats and methods), so no add-on package version applies; the scripts also use the book class of the running shelf scenario, which is plain base R code, and the lintr 3.4.0 default linters were used only to check the scripts. Selecting parts of an object and replacing them is the operation an R program performs most often, and it is where most of the surprises of the language live: the same square bracket returns a vector, a matrix, a list or a data frame depending on what it is applied to and on whether a comma is present; a missing value in a condition adds a row of NA instead of an error; a matrix that has one row left stops being a matrix; and x[[i]] <- NULL deletes while x[i] <- list(NULL) stores. This page goes through the three operators [, [[ and $, the four kinds of index that [ accepts and the special cases of zero, NA and out-of-bounds values, matrices, arrays and index matrices, lists and data frames, the functions that turn conditions into positions (which(), which.max(), head(), tail(), match() and %in%), then sub-assignment with all of its traps, how a replacement call such as names(x)[2] <- "b" is evaluated, and the difference between subset() and [. It ends with the warning that R-devel adds for x[logi] and with a table of every error and warning text that the examples produced.

Every example below is a script that was run with Rscript on R 4.6.1 with warnings printed as they happen (options(warn = 1)), and the lines starting with #> are what it printed. The scripts pass the default lintr linters; where a helper needs an assignment that a default linter dislikes (the <<- inside warns() below) the line carries a # nolint: comment. Errors and warnings that a script shows on purpose are caught, and their real text is printed: msg(expr) returns the text of the error that expr signals, and warns(expr) lets expr finish and returns the text of the warnings it gave, so the messages below are exactly what R says. The examples use the library scenario of the section: books, loans, shelf_today, loan_days and the book class come from the scenario.R file described on the section index, and the scripts that use them start with source("scenario.R"). The outputs are the real outputs of R 4.6.1; the only change is that the trailing blanks that R prints after a printed vector have been removed.

The pages Atomic Vectors and Types, Lists, Data Frames and Matrices and Arrays introduce the objects themselves; this page is about getting parts of them in and out. Names and other attributes are in Attributes and Names, missing values in Missing and Special Values, and the question of when an object is copied after a sub-assignment is in Assignment, Names and Values.

One idea, three operators

R has no separate array, record and dictionary syntax. Everything that holds several values is a vector (atomic or list) with optional attributes, and one family of operators takes parts out of any of them. The language definition lists the forms: x[i], x[i, j], x[[i]], x[[i, j]], x$a and x$"a", and then gives the rules that the rest of this page unfolds: [ can select several elements and returns an object of the same kind, [[ selects exactly one element and returns it, and $ is a shorthand for [[ with a literal name that applies to lists, to NULL and to environments (The R Language Definition: Indexing). The help page puts the first distinction in one sentence: the most important distinction between [, [[ and $ is that [ can select more than one element whereas the other two select a single element (R documentation: Extract).

A way to remember the three is a box of items. [ takes a smaller box with some of the items in it (the result has the type of the container). [[ takes one item out of the box (the result has the type of the item). $ does the same as [[ and saves typing the quotes, at the price of the rules for names that the section on partial matching explains. All three operators are ordinary generic functions, and a class can supply its own method: [.data.frame and [.factor are the two methods that ship with R (The R Language Definition: Indexing other structures). This page describes the default methods and, from the data frame section on, the data frame method. The classes of the S3 classes and generics page can define their own [ and [[; those methods do not have to follow the rules below, for example for partial matching.

An atomic vector is also what a matrix is, with a dim attribute, so every vector form of indexing works on a matrix with a single index (see Matrices and arrays). The same is true of a data frame, which is a list of columns, so df[j] and df[[j]] index it as a list (see Data frames).

The four kinds of index

An introduction to R lists four kinds of index vector for x[i] on a vector: a logical vector, a vector of positive integers, a vector of negative integers, and a vector of character strings; and says that an indexed expression can also appear on the receiving end of an assignment (An Introduction to R: Index vectors; selecting and modifying subsets of a data set). The language definition adds the special cases: a zero, real numbers, factors, the empty index, NULL and NA (The R Language Definition: Indexing by vectors). The first script works through all of them on a vector made from the shelf scenario: the number of days that each of the first eight loans lasted, with the loan ids as names. A loan lasts return_date - loan_date days, and loan_days (21) is the loan period.

The rules the output shows, one by one:

  • A vector of positive integers selects by position, in the order given and as often as given. The result has the length of the index, so loan_len[c(3, 1)] reverses two elements and loan_len[c(2, 2, 2)] repeats one. The names of the selected elements are selected with them.

  • A vector of negative integers selects everything except the positions given. The elements of the index must all have the same sign. A negative position that is outside the vector is silently ignored (loan_len[-20] returns the whole vector); the language definition says this has been so since R 2.6.0, for compatibility with S, because dropping a non-existent element is an empty operation.

  • A logical vector keeps the positions where it is TRUE. loan_len > loan_days is a logical vector with the names of loan_len, so it can be used directly as the index, and this is the form that most filters take: x[condition].

  • A character vector is matched against the names of x. The match is exact for [: there is no partial matching with a single bracket for any object. A name that is not there gives NA with the name <NA>.

  • Zero is the neutral index. x[0] is an empty vector of the same type (a named empty vector when x has names, printed named integer(0)), and a zero among positive or negative indices is as if it were not there: x[c(0, 2)] is x[2] and x[c(-1, 0)] is x[-1]. The case of x[-0] is a trap: -0 is 0, so x[-0] selects nothing, it does not drop nothing. Code that builds the index as -n with n possibly zero (x[-n]) returns an empty vector exactly when it should return all of x.

  • A positive index larger than length(x) gives NA for that position, and the result still has the length of the index: loan_len[c(1, 10)] has two elements, the second named <NA>.

  • Real numbers are truncated towards zero, so loan_len[2.9] is loan_len[2] and loan_len[-1.9] is loan_len[-1]; loan_len[0.9] is loan_len[0]. R 4.2.0 made the implementation follow what had always been documented: the index is as.integer(i) unless that would overflow, and then trunc(i) (R NEWS: Changes in R 4.2.0).

  • The empty index x[] returns x (all of it, with its names, dim and dimnames), and NULL is treated as integer(0), so x[NULL] is empty. The empty index matters most on the left of an assignment (x[] <- 0 keeps the attributes of x), see Sub-assignment of vectors.

Zero, NA and the length of the index

Three things go wrong in practice with indexes that are not plain vectors of valid positions: mixing signs, missing values in the index and the interplay of logical indexes with recycling. The second script shows them, with the real text of the one error in the group.

days <- as.integer(loans$return_date - loans$loan_date)
names(days) <- loans$loan_id
loan_len <- days[1:8]

# Mixing positive and negative subscripts is an error; zeros are the exception
tryCatch(loan_len[c(-1, 2)], error = \(e) conditionMessage(e))

loan_len[c(-1, 0)]

#>   10    1   26   26   17   24   10

# integer NA selects one element

with_gap <- c(a = 21L, b = NA, c = 26L)

Mixing positive and negative subscripts

loan_len[c(-1, 2)] is an error. The message of R 4.6.1 is only 0's may be mixed with negative subscripts: zero is the single value that may be combined with negative numbers, because it selects nothing and drops nothing. Some older posts quote the wording can't mix positive and negative subscripts; this is not the text that R 4.6.1 prints, and the NEWS files do not record the change of wording, so search for the message as printed on your version. The reason for the restriction is that "everything except 1, and also the second element" has no meaning: a negative index means "all but these", and a positive one means "only these".

NA in the index

The index can contain NA, and its type decides the result. The language definition explains it with one example: x[NA] has the length of x, whereas x[c(1, NA)] has length 2, because the literal NA is a logical value and the rules for logical indexes apply to it, while in c(1, NA) it is coerced to an integer. The output above shows both:

  • loan_len[NA] recycles the logical NA to the length of the vector and returns eight NA values, all with the name <NA>.

  • loan_len[c(1, NA)] returns the first element and one NA.

  • NA_integer_ and NA_character_ select one unknown element and return one NA.

The help page generalises this: when extracting, a numeric, logical or character NA index picks an unknown element and returns NA in the corresponding position of a logical, integer, numeric, complex or character result, and NULL for a list (and a raw zero byte for a raw vector). The practical consequence is the one that gets its own section for data frames: a comparison on data that holds a missing value produces an NA in the logical index, and the result of the filter holds an NA element for it. with_gap[with_gap > 21L] in the script returns NA and 26, while with_gap[which(with_gap > 21L)] returns only 26, because which() drops everything that is not TRUE. The fix for a filter on data that may have missing values is one of which(), !is.na(x) & x > 21L or subset(); see Rows by condition and the NA-row trap.

Logical indexes and recycling

A logical index is recycled to the length of the vector if it is shorter, as the manual says, and if it is longer then the vector is conceptually extended with NA values. The script shows the three cases: c(TRUE, FALSE) selects every other element, c(TRUE, FALSE, FALSE) selects positions 1, 4 and 7 of a vector of length eight, and a logical index of length ten applied to a vector of length eight selects two positions that do not exist, which are returned as NA. One more observation belongs to The upcoming R-devel warning for x[logi]: R 4.6.1 gives no warning when the length of the logical index does not divide the length of the vector. The call warns(loan_len[c(TRUE, FALSE, FALSE)]) returns character(0), which means that the expression produced no warning.

Character indexes

A character index is matched against names(x). If x has no names at all, every name is the empty string and nothing matches: plain["a"] is NA, and the result has no name because the vector has none to carry. Four rules are worth remembering:

  • the string "" matches no element, not even those without a name (loan_len[""] is NA);

  • NA_character_ also matches nothing;

  • when names are duplicated, a character index returns the first element with that name, and an index of two equal strings returns that element twice (dup[c("x", "x")] is 1 1); the second x of dup can only be reached by position;

  • partial matching is never used by [, so loan_len["L00"] is NA even though "L00" is a prefix of every name.

The script also shows the fifth kind of index that the manual lists, a factor. A factor index is the same as x[as.integer(f)]: the integer codes are used and the labels are never looked at. The levels of f are sorted, so f <- factor(c("L003", "L001")) has the codes 2 and 1, and loan_len[f] returns the second and the first element, not the elements called L003 and L001. The result is wrong and nothing says so. If the labels are meant, convert them: loan_len[as.character(f)]. This trap was more common when read.csv() and data.frame() made factors from strings by default; since R 4.0.0 the default of stringsAsFactors is FALSE and a character column is indexed by its values (R NEWS: Changes in R 4.0.0). The Factors page has the details on the factors themselves.

What the output shows:

  • A unique prefix is accepted. dune$tit is the title and dune$p is the number of pages, because only pages begins with p. Nothing warns by default. When several names have the prefix, as pages and pagesize have pa, the match fails and the result is NULL: an ambiguous prefix is not an error either.

  • [[ does not match partially by default. The usage of the help page is x[[i, exact = TRUE]] and the behaviour of R 4.6.1 agrees: shelf_entry[["pagesi"]] is NULL. The argument exact has three values: TRUE (no partial matching, the default), NA (partial matching with a warning) and FALSE (partial matching without warning). The warning has the text partial match of 'pagesi' to 'pagesize'. The language definition says in its section on indexing by vectors that the default of exact is NA; that sentence is out of date, the help page and the behaviour are the reference.

  • options(warnPartialMatchDollar = TRUE) makes $ warn with the same text whenever it matches a prefix. The option is FALSE unless you set it (the options page describes it as a logical switch that warns when partial matching is used for extraction by $). The warning for data frames was given by default in R versions before 3.1.1, whose NEWS says it is now only given when this option is TRUE. A package that wants to be sure that no code relies on a partial match can turn the option on in its tests (see Testing with testthat); the help page example uses it to check li$p.

  • [ never matches partially, for any object: shelf_entry["pagesi"] is a list with one NULL element named <NA>.

  • $ cannot be computed. dune$field looks for an element called "field" (and returns NULL), whereas dune[[field]] uses the value of the variable. dune$"title" works because a string is allowed as the name.

  • $ on an atomic vector is an error with the text $ operator is invalid for atomic vectors, and $ on NULL returns NULL. The error is the usual sign of a vector that should have been a list or data frame, for example a column of a data frame (a vector) on which $ was used again.

  • getElement(x, name) is x[[name, exact = TRUE]], and for S4 objects it reads the slot, so it works on both kinds of object.

  • For environments, $ and [[ take a character name and do an exact lookup with get(i, envir = x, inherits = FALSE); they return NULL when there is no match, and no partial matching is done. shelf_env$op is NULL although shelf_env$open exists. The replacement forms create or change a binding (see Scoping, Environments and Closures).

The advice that follows from the rules is to use the full names with $, to use [[ with a variable holding a name, and to remember that partial matching exists when a result that should have been a vector is NULL.

Matrices and arrays

A matrix is a vector with a dim attribute and an array is the same with more dimensions, so every kind of vector indexing works with a single index, and there are three more forms for several: one index per dimension, an index matrix, and (as a special case) the logical matrix. Why do my matrices lose dimensions: drop = FALSE

When a subscripting operation leaves a dimension of length one, R removes it by default: row <- mat[2, ] is a vector, and an array of dimensions 2 x 3 x 1 x 4 becomes 2 x 3 x 4. The R FAQ says that the behaviour was kept after much discussion as a feature, and advises using drop = FALSE defensively when programming (R FAQ 7.5: Why do my matrices lose dimensions?). The argument is an additional argument to [, it does not count as an index (the manual: m[1, , drop = FALSE] is the first row as a 1 by n matrix) and it must be named. The same applies to a one-dimensional array: any subsetting gives a vector unless drop = FALSE is used.

The trap is in code that works for the usual size of the input and fails on the edge. The next script defines a helper that selects the rows asked for, and calls it with two shelves and with one.

Index matrices, logical matrices and the triangles

A third form of indexing a matrix uses a matrix as the single index: a matrix with one column per dimension of x, where each row selects one element and the result is a vector of the length of the number of rows (An Introduction to R: Index matrices). pick <- cbind(c(1, 2, 3), c(4, 3, 1)) selects [1, 4], [2, 3] and [3, 1], the elements that are on a diagonal of the layout, in one operation.

The rules, from the help page and the manual:

  • the index matrix has one column per dimension and one row per element wanted;

  • negative values are not allowed (negative values are not allowed in a matrix subscript);

  • rows with a zero are ignored and rows with NA give NA (pages_grid[rbind(c(1, 1), c(0, 0), c(NA, 2))] has two elements: the value at [1, 1] and NA);

  • a character matrix with one column per dimension is matched against the dimnames when the array has them; each row selects one element, NA gives NA, and an unmatched value or the empty string "" is an error (subscript out of bounds). R 4.1.3 changed the case of an array without dimnames, where a character matrix of the right shape used to return meaningless results and is now an error;

  • assignment works the same way: capped[long_ones] <- 380L replaces the elements at the listed positions, which is the second use in the manual’s example.

An Introduction to R says that an index matrix must be numeric and that any other form of matrix, such as a logical or a character one, is treated as an indexing vector. For logical matrices that is still right and it is the next case; for character matrices the help page of [ documents the matching against the dimnames that the script shows, so the sentence of the introduction is older than the help page.

A logical matrix of the same shape as x is a vector of the same length when used as a single index: pages_grid[pages_grid > 300] returns the values for which the comparison is TRUE, as a vector in column order, and the cell with NA is returned as NA because the logical index is NA there. which(pages_grid > 300) drops it. The comparison keeps the dim and dimnames of the matrix, so pages_grid > 300 prints as a matrix with the shelf and slot labels.

which(x, arr.ind = TRUE) goes the other way, from a condition to an index matrix: the result is a matrix with one row per element, the row names are taken from the first dimension names, and its column names come from names(dimnames(x)) when they exist (shelf and slot above, and row and col otherwise). It can be fed back as an index, which is what pages_grid[long_ones] does. arrayInd() is the function that converts positions to an index matrix for a given dim.

upper.tri() and lower.tri() return logical matrices that mark the elements above or below the diagonal (with diag = TRUE they include it), so sq[upper.tri(sq)] extracts the upper triangle as a vector, in column order. diag(sq) is the diagonal. row(sq) and col(sq) return the row and the column number of each element as matrices of the same shape, and a condition on them, such as row(sq) == col(sq) + 1, selects the sub-diagonal or any other band (R documentation: lower.tri; R documentation: row).

Subsetting a data frame with a logical or two-column integer matrix is possible, but the help page of [.data.frame advises against it: the data frame is first coerced to a matrix, so every column takes the type of the common one. The data frame section shows the replacement form that is useful.

Arrays

An array has one index per dimension; an empty index keeps the whole extent, and the rules of drop apply to each dimension that is left with length one. Lists

A list is a vector whose elements can be anything, so subsetting it raises the question that atomic vectors do not: do you want a list back or the thing inside? Sub-assignment

An index on the left of an assignment changes part of an object. The help page names it subassignment: the part of x that is indexed is set to the value of the right-hand side, no partial matching of character indexes is done, and the left-hand side is coerced as needed to accept the values. The form is x[i] <- value, x[i, j] <- value, x[[i]] <- value and x$name <- value (R documentation: Extract; The R Language Definition: Subset assignment). The result is a new value that is bound to the name: R evaluates a call to the replacement function and rebinds the variable, and it avoids the copy when no other name refers to the vector, a mechanism described in Assignment, Names and Values.

  • Recycling. The value is recycled to the length of the selection: x[1:4] <- 0L assigns four zeros. When its length does not divide the number of replaced items, the assignment is still done and R warns with number of items to replace is not a multiple of replacement length: y[1:4] <- 1:3 gives 1, 2, 3, 1. The warns() helper shows the warning and lets the assignment run, which a plain tryCatch(warning = ...) would not do, because the handler leaves the expression before the assignment completes.

  • Extension. An index beyond the end extends the vector and pads the gap with NA: z[6] <- 99L on a vector of length three gives six elements, and a new name extends it too (z["new"] <- 5L). The padded elements have the empty name "".

  • A value of length zero. z[1:2] <- integer(0) is the error replacement has length zero. If the index also selects nothing (z[integer(0)] <- integer(0), z[0] <- 1L), nothing happens and there is no error.

  • Type change. The vector takes the higher of the types of x and value in the hierarchy raw, logical, integer, double, complex, character, list, expression. Assigning 2.5 to an integer vector makes it double, and assigning a string turns everything into character ("7", "2.5", "late"), with NA staying NA. Attributes are kept, and names, dim and dimnames are adjusted.

  • NA in the index. When replacing, an NA index selects nothing. As there is ambiguity about whether the corresponding element of the value should be used, an NA in the index is only allowed if the value has length one: w[c(1, NA)] <- 10 changes the first element, and w[c(1, NA)] <- c(8, 9) is the error NAs are not allowed in subscripted assignments. A logical NA index (w[NA] <- 0) changes nothing. The help page records the history: S documented that an NA index selects nowhere but still uses up an element of the value, and R has not done that.

  • Negative and zero indexes work as for extraction (w[-1] <- 0 assigns to all but the first).

  • Order. Subassignment is done sequentially, so if an index is repeated the last value wins: u[c(1, 1, 2)] <- c(10, 20, 30) leaves 20 and 30.

  • The empty index. v[] <- 0 replaces every value and keeps all attributes, while v <- 0 replaces the object, which now has no names. The empty index is what to use to reset the values of an object while preserving its shape.

  • In a function, a replacement such as names(x)[2] <- "b" or x[i] <- v is applied to a local copy, unless the function uses <<- (see Functions).

How a replacement call is evaluated

x[i] <- v looks like an assignment to a part of x, but R evaluates it as a call to the replacement function named [<- and assigns the result to x. The language definition spells out the steps with a temporary variable that has the internal name *tmp*; the listing below is that conceptual expansion, a fragment and not a script to run. A function whose name is another name followed by <- works the same way, and its last argument must be called value. The second part of the listing is the nested case: names(x)[3] <- "Three" is two replacements, evaluated from the inside out, where the value of the inner [<- call becomes the value of the outer names<- call.

x[3:5] <- 13:15
# is evaluated as if it were
`*tmp*` <- x
x <- "[<-"(`*tmp*`, 3:5, value = 13:15)
rm(`*tmp*`)

names(x)[3] <- "Three"
# is evaluated as if it were
`*tmp*` <- x
x <- "names<-"(`*tmp*`, value = "[<-"(names(`*tmp*`), 3, value = "Three"))
rm(`*tmp*`)

Source: The R Language Definition: Subset assignment

The index is converted to numbers first and the elements are replaced in order along them, as if by a for loop. The same mechanism works with <<-, where only the target variable is looked up in the enclosing environment and the other names of the expression are evaluated in the current one; the manual advises against a local variable with the same name as the target of a superassignment. subset() versus [

subset() is a function that selects rows and columns with a condition written in terms of the columns. It is documented as a convenience function intended for use interactively, and it has a warning that it should not be used for programming (R documentation: subset). The condition year > 2020 is not evaluated in the calling environment: subset() evaluates it in the data frame, so the columns are variables. That is non-standard evaluation, and Evaluation and Non-Standard Evaluation explains the mechanism. The help page lists the differences from [:

  • for a vector, subset(x, cond) is x[cond & !is.na(cond)]: missing values in the condition count as FALSE, so there is no NA-row trap;

  • for a data frame, the argument subset works on the rows and the argument select on the columns. select is an expression in which the column names have been replaced by the column numbers, so ranges (title:year), negative selections (-c(isbn, genre)) and c() of names all work without quotes;

  • the argument drop is passed to [, but its default is FALSE for data frames and matrices, which is different from the default of the indexing operator;

  • factors are not cleaned: unused levels remain, and droplevels() removes them (R documentation: droplevels);

  • since R 4.3.0 the data frame method warns about extra arguments, which typically catches = written where == was meant, as in subset(books, year = 2020) (R NEWS: Changes in R 4.3.0).

Why not subset() in functions

The warning of the help page is about the evaluation. subset() looks the names in its condition up in the data frame first and then in the environment where it was called, so a name that is both a column and a variable is silently the column. The next script is the classic accident: a helper whose argument has the same name as a column.

source("scenario.R")

# A helper that keeps books longer than a given number of pages. The argument
# is called pages, which is also a column of the data frame.
longer_than <- function(df, pages) {
  subset(df, pages > pages)
}
nrow(longer_than(books, 400))
#> [1] 0

# The condition pages > pages compares the column with itself: the column
# wins, because subset() looks in the data frame first. No row is TRUE, so
# nothing is kept, and no error says why.
longer_than(books, 400)[, c("title", "pages")]
#> [1] title pages
#> <0 rows> (or 0-length row.names)

# With [ the two names cannot be confused
longer_than <- function(df, min_pages) {
  df[which(df$pages > min_pages), , drop = FALSE]
}
longer_than(books, 400)[, c("title", "pages")]
#>                  title pages
#> 2  Pride and Prejudice   432
#> 12    Notes on Gravity   410

# col is a string here, so the condition compares strings with "2020"

#> [1] 1974 1813 2019

#> NULL

#> 4      Loud Roofs 2021
#> 10 THE LONG TABLE 2023
#> 15    Ten Winters 2022

# The usual advice: use subset() at the console, [ in functions and packages.
# A function that needs the NSE can pass the expression on with eval().
newer_than <- function(df, year_min) {
  keep <- eval(substitute(year > year_min), df, parent.frame())
  df[which(keep), , drop = FALSE]
}

#> 4      Loud Roofs 2021
#> 10 THE LONG TABLE 2023
#> 15    Ten Winters 2022

  • longer_than(df, pages) calls subset(df, pages > pages). Both pages are the column, because the data frame is searched before the function’s argument, so the condition compares the column with itself and no row is TRUE: an empty data frame, without an error. The [ version (df[which(df$pages > min_pages), , drop = FALSE]) cannot have the problem, because the column is always df$pages and the argument has another name.

  • A column name held in a variable does not work with $ (books$col looks for a column called col, and returns NULL) or with the unquoted names of subset(). In the script col is the string "year" and subset(books, col > 2020) compares the string "year" with "2020" as strings, which is TRUE for every row: sixteen rows come back and no message says it. Use books[[col]] or get(col), the latter inside the data frame as the script shows.

  • When a function needs the non-standard form, it can build the condition itself, as newer_than() does with eval(substitute(...), df, parent.frame()), so that the caller’s argument is evaluated with the columns of df visible. This is what dplyr and other packages automate; the details and their trade-offs are the subject of the evaluation page.

The practical rule is the one the help page gives: subset() for interactive work at the console, [ and [[ in functions, scripts that are run unattended, and packages.

The upcoming R-devel warning for x[logi]

The development version of R (4.7.0, not released) has a change in the NEWS that affects the logical indexes of this page. The R-devel NEWS says that x[logi], with logi a logical index, now warns if length(x) is not a multiple of length(logi), fixing PR#19155, after the discussions of several participants in R Dev Days and the R Sprint in 2026 (R NEWS: Changes in R-devel). The text was read from the development NEWS on 2026-10-20 and the examples of this page were not run on R-devel, so what follows is the consequence and not a captured message.

  • Today, in R 4.6.1, the call loan_len[c(TRUE, FALSE, FALSE)] with a vector of eight elements is recycled silently and selects the positions 1, 4 and 7; the script of Logical indexes and recycling shows warns() returning no warning. A logical index of length ten for a vector of length eight is also silent (and gives two NA elements).

  • According to the NEWS entry, the same expressions will warn in the development version. Code that relied on a short logical index that does not divide the length (a mask of length 3 recycled over 8 elements, usually by accident) will produce a warning there, and a test suite that turns warnings into errors will fail.

  • A logical index whose length divides length(x) (x[TRUE], or x[c(TRUE, FALSE)] on a vector of even length) and a logical index of the same length as x, which is the normal case, are multiples in the sense of the rule and are not affected.

  • The fix is the same as for any recycling accident: build the mask with the length of the vector (rep(c(TRUE, FALSE, FALSE), length.out = length(x)), made explicit), or use which().

The change is not in any release at the time of the check. Whether it appears under the number 4.7.0 and with this wording is for the NEWS of that release to say; the page What’s New and Migrating Older Code tracks the version differences.
