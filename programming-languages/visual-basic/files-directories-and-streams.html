Files, Directories and Streams

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Almost every program reads or writes a file sooner or later: a catalogue exported to CSV, a configuration file, a log, a cache. This page covers the .NET types that do it (System.IO), the Visual Basic additions on top of them (Microsoft.VisualBasic.FileIO.FileSystem, My.Computer.FileSystem and TextFieldParser), the numbered-file statements inherited from BASIC, and the habits that keep file code correct: disposing streams, choosing an encoding, replacing a file safely, and checking where a path lands. It was written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and checked on 2026-10-19. Every program was built with Option Strict On and TreatWarningsAsErrors and run in a Linux container, so path separators are /, paths are case-sensitive and the temporary directory is /tmp; the programs create a uniquely named folder under the temporary directory, print only relative names, and delete it afterwards. The project root namespace is ShelfDocs, which appears in some exception messages. System.IO is not one of the namespaces the SDK imports for Visual Basic projects, so each program that uses File, Path or Directory starts with Imports System.IO.

Serialization of objects into JSON and XML files is on Serialization: JSON and XML. The Using statement and disposal in general are on Object Lifetime and Disposal, the Microsoft.VisualBasic module functions that this page touches are listed on The Visual Basic Runtime Library, and My is on The My Namespace. Text encoding of strings is on Strings and Text, and the C# view of the same APIs is on Memory Management and Disposal in the C# reference.

The System.IO map

The types fall into four groups. The static helpers do a whole job in one call and never leave a file open; the stream types give control and are the only way to handle data that does not fit in memory; the *Info classes cache metadata about one file or folder; and the Visual Basic additions package common jobs with a different API.

The File class: whole-file operations

File.ReadAllText, ReadAllLines, WriteAllText, WriteAllLines, AppendAllText and the byte versions open the file, do the work and close it, so they cannot leak a handle. File.ReadLines is the lazy cousin of ReadAllLines: it returns an IEnumerable(Of String) that reads as it is enumerated, so a loop over a large file keeps only one line in memory, but the file stays open until the enumeration finishes or is disposed. The text methods use UTF-8 without a byte order mark unless you pass an encoding (see the encodings section below).

Option Strict On
Imports System.IO
Imports System.Text

Module Ex01
    Sub Main()
        Dim root As String = Path.Combine(Path.GetTempPath(), "shelf-" & Guid.NewGuid().ToString("N"))
        Directory.CreateDirectory(root)
        Try
            Dim shelfFile As String = Path.Combine(root, "shelf.txt")

            ' Write, append, read: the one-call File methods.
            File.WriteAllText(shelfFile, "Dune" & vbLf & "Emma" & vbLf)
            File.AppendAllText(shelfFile, "Ulysses" & Environment.NewLine)
            File.AppendAllLines(shelfFile, {"Hamlet", "Beloved"})

            Dim lines As String() = File.ReadAllLines(shelfFile)
            Console.WriteLine($"ReadAllLines: {lines.Length} lines, first={lines(0)}, last={lines(lines.Length - 1)}")
            Console.WriteLine($"ReadAllText length: {File.ReadAllText(shelfFile).Length}")

            ' ReadLines is lazy: it streams, and the file stays open until the enumeration ends.
            Dim longTitles As Integer = 0
            For Each title As String In File.ReadLines(shelfFile)
                If title.Length > 5 Then longTitles += 1
            Next
            Console.WriteLine($"Titles longer than 5 characters: {longTitles}")

            ' Existence, copy, move, delete.
            Dim backup As String = Path.Combine(root, "shelf.bak")
            File.Copy(shelfFile, backup)
            Console.WriteLine($"Exists: {File.Exists(shelfFile)} {File.Exists(backup)} {File.Exists(Path.Combine(root, "nope.txt"))}")
            Try
                File.Copy(shelfFile, backup)
            Catch ex As IOException
                Console.WriteLine($"Copy over existing file: {ex.GetType().Name}")
            End Try
            File.Copy(shelfFile, backup, overwrite:=True)
            Dim moved As String = Path.Combine(root, "archive.txt")
            File.Move(backup, moved)
            Console.WriteLine($"After move: {File.Exists(backup)} {File.Exists(moved)}")
            File.Delete(moved)
            File.Delete(moved) ' Deleting a file that does not exist is not an error.
            Console.WriteLine($"After delete: {File.Exists(moved)}")

            ' Metadata without opening the file.
            Console.WriteLine($"Length of shelf.txt in bytes: {New FileInfo(shelfFile).Length}")
            Console.WriteLine($"Attributes: {File.GetAttributes(shelfFile)}")
            File.SetLastWriteTimeUtc(shelfFile, New Date(2026, 1, 15, 8, 30, 0, DateTimeKind.Utc))
            Console.WriteLine($"Last write (UTC): {File.GetLastWriteTimeUtc(shelfFile):yyyy-MM-dd HH:mm}")

            ' Bytes.
            File.WriteAllBytes(Path.Combine(root, "raw.bin"), {&H44, &H75, &H6E, &H65})
            Console.WriteLine($"Bytes as text: {Encoding.UTF8.GetString(File.ReadAllBytes(Path.Combine(root, "raw.bin")))}")

            ' The errors you meet.
            Try
                File.ReadAllText(Path.Combine(root, "missing.txt"))
            Catch ex As FileNotFoundException
                Console.WriteLine($"FileNotFoundException, FileName ends with: {Path.GetFileName(ex.FileName)}")
            End Try
            Try
                File.ReadAllText(Path.Combine(root, "no-such-dir", "x.txt"))
            Catch ex As DirectoryNotFoundException
                Console.WriteLine("DirectoryNotFoundException for a missing folder")
            End Try
            Try
                File.ReadAllText(root)
            Catch ex As UnauthorizedAccessException
                Console.WriteLine("UnauthorizedAccessException when the path is a directory")
            End Try
        Finally
            Directory.Delete(root, recursive:=True)
        End Try
    End Sub

The exceptions are part of the contract, and which one you get tells you what to do.

Exception Typical cause and response

FileNotFoundException

The file does not exist. ex.FileName holds the path. File.Exists before opening is a race (the file can vanish in between); catch the exception where a missing file is a normal case.

DirectoryNotFoundException

A folder in the path does not exist. Directory.CreateDirectory creates all missing levels and does nothing if the folder exists.

UnauthorizedAccessException

No permission, a read-only file, or (as in the example) a path that names a directory where a file was expected.

IOException

The file is in use, the target already exists (File.Copy and FileMode.CreateNew without overwrite), the directory is not empty, the disk is full, or the device is unavailable. FileNotFoundException, DirectoryNotFoundException and PathTooLongException derive from IOException, so catch them before it.

PathTooLongException

A path longer than the platform allows. Modern Windows with long path support enabled, and Linux, accept much longer paths than the classic 260 characters.

ArgumentException, NotSupportedException

The path is empty, contains an invalid character, or has an invalid format (a colon in the wrong place on Windows).

IOException with a sharing violation

Another process holds the file open (the message says the file is being used by another process). Retrying after a short delay is the usual response.

Visual Basic version notes: File.Move(source, target, overwrite) exists since .NET Core 3.0; ReadLinesAsync and ReadExactly since .NET 7; none of these existed on .NET Framework 4.8, where File.Move always failed if the target existed.

Paths and directories

A path is only a string until it is used, and Path manipulates strings without touching the disk. That makes it safe to call with paths that do not exist, and also means it cannot tell you whether a path is valid on disk. Three rules save most path bugs: never build a path with & and a literal separator (use Path.Combine or Path.Join); never trust a relative path (it resolves against the process’s current directory, which is not the executable’s directory); and never combine a fixed root with untrusted input without checking where the result lands (see the safety section below).

            Next

            Try

Member Behaviour worth knowing

Path.Combine(a, b)

Joins with the platform separator, but if b is rooted the result is b alone, discarding a. This is the bug behind several directory traversal vulnerabilities.

Path.Join(a, b)

Joins and never discards: a rooted b is appended. (.NET Core 2.1.)

Path.GetFullPath(p)

Resolves . and .. segments and relative paths against the current directory. It does not check that the path exists.

Path.GetRelativePath(base, p)

The reverse: how to reach p starting at base. (.NET Core 2.0.)

Path.GetExtension, GetFileName, GetFileNameWithoutExtension, GetDirectoryName, ChangeExtension

String operations. The extension includes the leading dot; GetDirectoryName returns Nothing for a root.

Path.GetTempPath(), GetTempFileName(), GetRandomFileName()

The temporary folder, a created empty file with a unique name, and a random name without creating anything. GetTempFileName creates a file, so it must be deleted.

Path.GetInvalidFileNameChars()

Depends on the operating system: two characters on Linux (the slash and NUL), many more on Windows. Code that validates file names with this list on Linux accepts names that Windows rejects.

Path.DirectorySeparatorChar, AltDirectorySeparatorChar, PathSeparator

\ and / on Windows (both separators are accepted there), / on Linux and macOS, and ; or : for the separator in a list of paths such as PATH.

Directory and DirectoryInfo list and manage folders. The Get* methods return an array after reading everything; the Enumerate* methods stream results, which matters for folders with many entries. Neither guarantees an order, so sort when the output must be stable (the example sorts with StringComparer.Ordinal). A wildcard such as *.csv is applied to the file name; a three-letter extension filter on Windows also matches longer extensions that begin with the same three letters, a legacy short-name quirk that Linux does not share.

Reading and writing text: StreamReader, StreamWriter and FileStream

When the data is large or arrives gradually, open a stream. StreamWriter and StreamReader add an encoding and line handling on top of a byte stream; FileStream is the byte stream itself with position and seeking. Always wrap them in Using, so that End Using calls Dispose, which flushes buffered data and releases the file even if an exception is thrown.

Option Strict On
Imports System.IO
Imports System.Text

Module Ex03
    Sub Main()
        Dim root As String = Path.Combine(Path.GetTempPath(), "shelf-" & Guid.NewGuid().ToString("N"))
        Directory.CreateDirectory(root)
        Try
            Dim report As String = Path.Combine(root, "report.txt")

            ' StreamWriter / StreamReader: text, line by line. Using closes (and flushes) the file.
            Using writer As New StreamWriter(report, append:=False, encoding:=New UTF8Encoding(encoderShouldEmitUTF8Identifier:=False))
                writer.WriteLine("Shelf report")
                writer.WriteLine($"{"Dune",-10}{3,5}")
                writer.Write("Total: ")
                writer.WriteLine(3)
            End Using

            Using reader As New StreamReader(report)
                Dim lineNumber As Integer = 0
                Dim line As String = reader.ReadLine()
                Do While line IsNot Nothing
                    lineNumber += 1
                    Console.WriteLine($"{lineNumber}: {line}")
                    line = reader.ReadLine()
                Loop
                Console.WriteLine($"EndOfStream: {reader.EndOfStream}")
            End Using

            ' FileStream gives full control: mode, access, sharing, position.
            Dim dataFile As String = Path.Combine(root, "data.bin")
            Using stream As New FileStream(dataFile, FileMode.Create, FileAccess.ReadWrite, FileShare.None)
                stream.Write(Encoding.ASCII.GetBytes("ABCDEFGHIJ"))
                Console.WriteLine($"Position after write: {stream.Position}, Length: {stream.Length}")
                stream.Seek(2, SeekOrigin.Begin)
                Dim buffer(2) As Byte
                Dim read As Integer = stream.Read(buffer, 0, buffer.Length)
                Console.WriteLine($"Read {read} bytes: {Encoding.ASCII.GetString(buffer)}")
                stream.Seek(-1, SeekOrigin.End)
                stream.WriteByte(CByte(Asc("Z")))
                stream.SetLength(8)
            End Using
            Console.WriteLine($"File content: {File.ReadAllText(dataFile)}")

            ' FileMode behaviours.
            Try
                Using s As New FileStream(dataFile, FileMode.CreateNew)
                End Using
            Catch ex As IOException
                Console.WriteLine($"FileMode.CreateNew on existing file: {ex.GetType().Name}")
            End Try
            Try
                Using s As New FileStream(Path.Combine(root, "absent.bin"), FileMode.Open)
                End Using
            Catch ex As FileNotFoundException
                Console.WriteLine("FileMode.Open on missing file: FileNotFoundException")
            End Try
            Using s As New FileStream(dataFile, FileMode.Append, FileAccess.Write)
                s.Write(Encoding.ASCII.GetBytes("++"))
            End Using
            Console.WriteLine($"After Append: {File.ReadAllText(dataFile)}")
            Using s As New FileStream(dataFile, FileMode.Truncate, FileAccess.Write)
            End Using
            Console.WriteLine($"After Truncate: length {New FileInfo(dataFile).Length}")

            ' Sharing: a second writer is refused while the first is open.
            Using first As New FileStream(dataFile, FileMode.Open, FileAccess.ReadWrite, FileShare.None)
                Try
                    Using second As New FileStream(dataFile, FileMode.Open, FileAccess.Read, FileShare.Read)
                    End Using
                Catch ex As IOException
                    Console.WriteLine($"Second open while locked: {ex.GetType().Name}")
                End Try
            End Using
        Finally
            Directory.Delete(root, recursive:=True)
        End Try
    End Sub

The mode, access and sharing parameters of the FileStream constructor decide what the open does.

FileMode Behaviour

CreateNew

Creates a new file; throws IOException if it already exists. Use it to avoid overwriting.

Create

Creates the file, or truncates it to zero length if it exists.

Open

Opens an existing file; FileNotFoundException if it does not exist.

OpenOrCreate

Opens the file or creates an empty one.

Truncate

Opens an existing file and empties it.

Append

Opens or creates the file and positions at the end; allowed only with FileAccess.Write, and the position cannot be moved before the original end.

FileAccess (Read, Write, ReadWrite) states what this stream may do, and FileShare (None, Read, Write, ReadWrite, Delete) states what other streams may do while it is open. The shared default for File.OpenRead is FileShare.Read; for File.Create and File.OpenWrite it is FileShare.None. On Windows the operating system enforces sharing; on Linux and macOS .NET emulates it with advisory locks, which protects against other .NET processes but not against programs that ignore the locks. A StreamWriter buffers: data reaches the file only on Flush, Close or Dispose, so a program that crashes before disposing loses the last buffered text.

Reading a text file line by line is the same loop in every program: ReadLine returns Nothing at the end, so the idiomatic loop is Do While line IsNot Nothing, reading the next line at the bottom, or Do Until reader.EndOfStream. The page on Control Flow shows the sentinel-loop pattern in general.

Disposing streams: the File.Create leak

A common beginner program writes File.Create(path) and discards the result, or keeps the FileStream in a variable and forgets it. File.Create does not only create the file: it returns the open FileStream, and until that object is disposed the file is locked. The garbage collector eventually finalizes the stream, but not at a time the program controls, so the failure is intermittent and often appears only on a faster machine or in a release build.

Option Strict On
Imports System.IO

Module Ex04
    ' The classic leak: File.Create returns an open FileStream that nobody disposes.
    Sub Main()
        Dim root As String = Path.Combine(Path.GetTempPath(), "shelf-" & Guid.NewGuid().ToString("N"))
        Directory.CreateDirectory(root)
        Try
            Dim target As String = Path.Combine(root, "leak.txt")

            ' Wrong: the returned FileStream stays open until the garbage collector finalizes it.
            Dim leaked As FileStream = File.Create(target)
            Try
                File.WriteAllText(target, "second writer")
            Catch ex As IOException
                Console.WriteLine($"Leak: writing the file again fails with {ex.GetType().Name}")
            End Try
            leaked.Dispose()

Asynchronous file I/O

File reads and writes are I/O, so they benefit from Async and Await in programs that must stay responsive (a user-interface thread) or that serve many requests (a web service). The File class has async twins for the whole-file methods (ReadAllTextAsync, ReadAllLinesAsync, WriteAllTextAsync, WriteAllLinesAsync, AppendAllTextAsync), StreamReader and StreamWriter have ReadLineAsync, ReadToEndAsync and WriteLineAsync, and every stream has ReadAsync and WriteAsync. A FileStream opened with useAsync:=True (or FileOptions.Asynchronous) uses overlapped I/O on Windows; without it, async calls run the blocking call on a thread-pool thread.

Watching a folder

FileSystemWatcher raises Created, Changed, Deleted and Renamed events for a folder and, optionally, its subfolders. It sits on operating-system notification facilities (inotify on Linux, ReadDirectoryChangesW on Windows, FSEvents or kqueue on macOS) and inherits their limits. The events arrive on thread-pool threads, one save can raise several Changed events, a large burst can overflow the internal buffer (the Error event, InternalBufferOverflowException), and the event is raised as soon as the file appears, which may be before the writing program has finished, so reading it immediately can fail with a sharing violation. Production code treats events as hints: debounce them, retry the read, and rescan the folder after an Error.

Option Strict On
Imports System.IO
Imports System.Threading

Module Ex07
    Sub Main()
        Dim root As String = Path.Combine(Path.GetTempPath(), "shelf-" & Guid.NewGuid().ToString("N"))
        Directory.CreateDirectory(root)
        Try
            Dim seen As New System.Collections.Concurrent.ConcurrentQueue(Of String)()
            Dim renamed As New ManualResetEventSlim(False)

            Using watcher As New FileSystemWatcher(root, "*.csv")
                watcher.NotifyFilter = NotifyFilters.FileName Or NotifyFilters.LastWrite
                watcher.IncludeSubdirectories = False

                ' Handlers run on a thread-pool thread, not on the thread that called Main.
                AddHandler watcher.Created, Sub(sender As Object, e As FileSystemEventArgs) seen.Enqueue("Created " & e.Name)
                AddHandler watcher.Deleted, Sub(sender As Object, e As FileSystemEventArgs) seen.Enqueue("Deleted " & e.Name)
                AddHandler watcher.Renamed, Sub(sender As Object, e As RenamedEventArgs)
                                                seen.Enqueue("Renamed " & e.OldName & " -> " & e.Name)
                                                renamed.Set()
                                            End Sub
                AddHandler watcher.Error, Sub(sender As Object, e As ErrorEventArgs) seen.Enqueue("Error " & e.GetException().GetType().Name)
                watcher.EnableRaisingEvents = True

                File.WriteAllText(Path.Combine(root, "books.csv"), "x")
                File.WriteAllText(Path.Combine(root, "notes.txt"), "ignored: the filter is *.csv")
                Thread.Sleep(300)
                File.Move(Path.Combine(root, "books.csv"), Path.Combine(root, "catalog.csv"))
                renamed.Wait(TimeSpan.FromSeconds(5))
                File.Delete(Path.Combine(root, "catalog.csv"))
                Thread.Sleep(500)
            End Using

            For Each entry As String In seen
                Console.WriteLine(entry)
            Next
        Finally
            Directory.Delete(root, recursive:=True)
        End Try
    End Sub

CSV with TextFieldParser

The .NET libraries have no CSV reader. Visual Basic ships one, TextFieldParser, in the Microsoft.VisualBasic.FileIO namespace since Visual Basic 2005, and it is also usable from C# by referencing Microsoft.VisualBasic.dll, which is part of every .NET project (a C# project needs using Microsoft.VisualBasic.FileIO;). It reads delimited or fixed-width text and handles quoted fields; it does not write anything.

CSV is not one format. RFC 4180 describes the common one and the parser follows it closely:

RFC 4180 rule Meaning for a reader

One record per line, lines end with CRLF

TextFieldParser also accepts a lone LF as the line end.

The last record may or may not end with a line break

Both work; EndOfData becomes True after the last record either way.

An optional header record

The parser does not treat the first record specially: read it with ReadFields and keep or discard it.

Fields are separated by commas

Any delimiter works with SetDelimiters (semicolons are common in locales that use a comma as decimal separator; tabs for TSV).

A field that contains a comma, a double quote or a line break must be enclosed in double quotes

HasFieldsEnclosedInQuotes (default True) turns this on.

A double quote inside a quoted field is written as two double quotes

Handled; the field comes back with one quote.

Every record has the same number of fields

Not enforced: you check fields.Length.

A field with an embedded line break spans several physical lines, so parser.LineNumber counts physical lines while a record count must be kept separately. A defaults probe shows the state of a fresh parser.

Malformed lines and fixed-width text

ReadFields throws MalformedLineException when a line cannot be parsed: for delimited text that means an unterminated quote or a closing quote that is not followed by a delimiter; for fixed-width text, a line shorter than the declared widths. The exception’s LineNumber and the parser’s ErrorLine identify the problem. After the exception the parser has already advanced, so the loop continues with the next line, which makes a "log and skip" strategy possible. A quote in the middle of an unquoted field, such as Em"ma, is not an error when HasFieldsEnclosedInQuotes is True.

Writing CSV

Nothing in the libraries writes CSV, so the program does it with StreamWriter. The rule is short: quote a field if it contains the delimiter, a double quote, or a line break; double any quote inside it. Use Invariant formatting for numbers and dates so that the file does not depend on the machine that wrote it, write line endings as CRLF if a Windows spreadsheet will open it, and pick the encoding on purpose (UTF-8 with a BOM for Excel on Windows, otherwise without).

    ' RFC 4180: quote a field that contains a comma, a quote or a line break, and double the quotes inside it.
    Private Function QuoteField(value As String) As String
        If value.IndexOfAny(SpecialCharacters) < 0 Then
            Return value
        End If
        Return """" & value.Replace("""", """""") & """"
    End Function

    Private Function JoinRecord(fields As IEnumerable(Of String)) As String
        Return String.Join(",", fields.Select(AddressOf QuoteField))
    End Function

The shelf catalogue as a small, complete program: save the books atomically, load them with TextFieldParser, validate every record, and keep a list of rejected lines with the reason instead of failing the whole load.

    Public Class Book

            Me.Title = title

        Public ReadOnly Property Isbn As String
        Public ReadOnly Property Title As String
        Public ReadOnly Property Author As String
        Public ReadOnly Property Year As Integer
        Public ReadOnly Property Price As Decimal
    End Class

    Private Function Quote(value As String) As String
        Return If(value.IndexOfAny({","c, """"c, ControlChars.Cr, ControlChars.Lf}) >= 0, """" & value.Replace("""", """""") & """", value)
    End Function

    ' Write to a temporary file and move it over the target, so a crash never leaves a half-written catalog.
    Sub Save(books As IEnumerable(Of Book), target As String)
        Dim temp As String = target & ".tmp"
        Using writer As New StreamWriter(temp, False, New UTF8Encoding(False)) With {.NewLine = vbCrLf}
            writer.WriteLine("Isbn,Title,Author,Year,Price")
            For Each b As Book In books
                writer.WriteLine(String.Join(",", {Quote(b.Isbn), Quote(b.Title), Quote(b.Author),
                    b.Year.ToString(CultureInfo.InvariantCulture), b.Price.ToString(CultureInfo.InvariantCulture)}))
            Next
        End Using
        File.Move(temp, target, overwrite:=True)
    End Sub

    Function Load(source As String, ByRef rejected As List(Of String)) As List(Of Book)
        Dim result As New List(Of Book)()
        rejected = New List(Of String)()
        Using parser As New TextFieldParser(source, New UTF8Encoding(False))
            parser.SetDelimiters(",")
            parser.HasFieldsEnclosedInQuotes = True
            parser.ReadFields() ' header
            Do While Not parser.EndOfData
                Dim startLine As Long = parser.LineNumber
                Try
                    Dim f As String() = parser.ReadFields()
                    Dim year As Integer
                    Dim price As Decimal
                    If f.Length <> 5 Then
                        rejected.Add($"line {startLine}: expected 5 fields, found {f.Length}")
                    ElseIf Not Integer.TryParse(f(3), NumberStyles.None, CultureInfo.InvariantCulture, year) Then
                        rejected.Add($"line {startLine}: year '{f(3)}' is not a number")
                    ElseIf Not Decimal.TryParse(f(4), NumberStyles.Number, CultureInfo.InvariantCulture, price) Then
                        rejected.Add($"line {startLine}: price '{f(4)}' is not a number")
                    Else
                        result.Add(New Book(f(0), f(1), f(2), year, price))
                    End If
                Catch ex As MalformedLineException
                    rejected.Add($"line {ex.LineNumber}: malformed ({ex.GetType().Name})")
                End Try
            Loop
        End Using
        Return result
    End Function

Binary files

Binary formats are sequences of bytes with a layout you define. BinaryWriter and BinaryReader read and write the primitive types in little-endian order, strings with a length prefix, and Decimal as 16 bytes; they are a fine choice for private formats and a poor choice for anything another system must read, where a documented format (JSON, protobuf, a database) is better. BitConverter and System.Buffers.Binary.BinaryPrimitives convert between numbers and byte arrays, the latter with an explicit byte order.

            ' Flush(True) asks the operating system to write to the device, not just to its cache.
            Using stream As New FileStream(target, FileMode.Create, FileAccess.Write, FileShare.None, 4096, FileOptions.WriteThrough)
                stream.Write(Encoding.ASCII.GetBytes("durable"))
                stream.Flush(flushToDisk:=True)
            End Using
            Console.WriteLine(File.ReadAllText(target))

            ' Never build a path from untrusted input without checking where it lands.
            Dim requested As String = "../../etc/passwd"
            Dim resolved As String = Path.GetFullPath(Path.Combine(root, requested))
            Dim inside As Boolean = resolved.StartsWith(Path.GetFullPath(root) & Path.DirectorySeparatorChar, StringComparison.Ordinal)
            Console.WriteLine($"Request '{requested}' stays inside the root: {inside}")

            ' Symbolic links and Unix permissions are visible too.
            If Not OperatingSystem.IsWindows() Then
                File.SetUnixFileMode(target, UnixFileMode.UserRead Or UnixFileMode.UserWrite)
                Console.WriteLine($"UnixFileMode: {File.GetUnixFileMode(target)}")
            End If
        Finally
            Directory.Delete(root, recursive:=True)
        End Try
    End Sub

Four habits from the example. Replace, do not rewrite: write the new content to a temporary file in the same folder and move it over the target, so that readers see either the whole old file or the whole new one; a crash while writing leaves the temporary file, not a truncated catalogue. Flush to the device when it matters: Flush empties the .NET buffer, Flush(True) also asks the operating system to write to the disk. Check where a path lands: Path.GetFullPath(Path.Combine(root, requested)) resolves .., and testing that the result starts with the root plus a separator rejects traversal such as ../../etc/passwd; compare with StringComparison.Ordinal (or OrdinalIgnoreCase on a case-insensitive file system). Set permissions on the file, not on the folder, with File.SetUnixFileMode on Linux and macOS (.NET 7) or access control lists on Windows; a file created by File.WriteAllText gets the process’s default permissions, which are often more open than a file of secrets should have.

Legacy numbered files: FileOpen, PrintLine, Input and Put

Visual Basic 6 and earlier opened files with a number: Open "x.txt" For Output As #1, then Print #1, ..., Input #1, ..., Line Input #1, ..., Put #1, Get #1 and Close #1. The Microsoft.VisualBasic runtime keeps a compatible implementation as ordinary functions (FileOpen, PrintLine, Print, Write, WriteLine, Input, LineInput, EOF, LOF, Loc, Seek, FilePut, FileGet, FileClose, FreeFile, Reset) so that migrated code compiles. Recognise them; do not write them in new code. The program below is a tested recognition aid: it shows what the functions write and what goes wrong.

Option Strict On
Imports System.IO

Module Ex13
    ' Recognition only: the numbered-file model inherited from BASIC, still implemented by Microsoft.VisualBasic.
    Sub Main()
        Dim target As String = Path.Combine(Path.GetTempPath(), "shelf-" & Guid.NewGuid().ToString("N") & ".txt")
        Try
            Dim number As Integer = FreeFile()
            FileOpen(number, target, OpenMode.Output)
            PrintLine(number, "Dune", 1965)           ' Print # : plain text
            Write(number, "Emma", 1815, True)         ' Write # : comma-delimited, strings quoted, no line end
            Print(number, vbCrLf)
            WriteLine(number, "Ulysses", 1922, False) ' Write # plus the platform line end
            Console.WriteLine($"LOF while open: {LOF(number)} bytes, Loc={Loc(number)}")
            FileClose(number)
            Console.WriteLine(File.ReadAllText(target).Replace(vbCrLf, "<CRLF>" & vbLf))

            ' Input # reads typed fields written by Write #. It ends a record at CR or CRLF, not at a lone LF.
            Dim second As Integer = FreeFile()
            FileOpen(second, target, OpenMode.Input)
            Dim skip As String = LineInput(second)
            Dim title As String = Nothing
            Dim year As Integer
            Dim flag As Boolean
            Input(second, title)
            Input(second, year)
            Input(second, flag)
            Console.WriteLine($"Skipped [{skip.TrimEnd()}], then title={title}, year={year}, flag={flag}")
            Console.WriteLine($"EOF: {EOF(second)}")
            Try
                Input(second, title)
                Input(second, year)
                Input(second, flag)
            Catch ex As InvalidCastException
                Console.WriteLine("The record that ended with a lone LF did not terminate: InvalidCastException")
            End Try
            FileClose(second)

            ' Random access with Put and Get uses fixed-size records.
            Dim recordFile As String = target & ".dat"
            Dim third As Integer = FreeFile()
            FileOpen(third, recordFile, OpenMode.Random, OpenAccess.ReadWrite, OpenShare.Default, 4)
            FilePut(third, 100, 1)
            FilePut(third, 200, 2)
            FilePut(third, 300, 3)
            Dim value As Integer
            FileGet(third, value, 2)
            Console.WriteLine($"Record 2 = {value}, file length = {LOF(third)} bytes")
            FileClose(third)
            File.Delete(recordFile)

            Try
                Dim junk As String = LineInput(7)
            Catch ex As Exception
                Console.WriteLine($"Unopened file number: {ex.GetType().Name}")
            End Try

                File.ReadAllText(target)
            Catch ex As IOException
                Console.WriteLine($"Open numbered file blocks other readers: {ex.GetType().Name}")
            End Try
            Reset() ' closes every file opened with FileOpen
        Finally
            File.Delete(target)
        End Try

Notice the traps. PrintLine and WriteLine end lines with the platform’s line break (a lone LF on Linux), while Input ends a record at CR or CRLF and treats a lone LF as part of the field, so a file written on Linux by these functions cannot always be read back by Input; Write emits fields separated by commas with strings quoted and booleans as #TRUE# and #FALSE#, and leaves a trailing comma unless WriteLine ends the record; PrintLine lays several items out in 14-column zones and gives a number a leading sign space and a trailing space, as the first line of the output shows; a file number that was not opened raises IOException; a file opened and not closed stays locked (Reset closes all). The mapping to the modern API is direct.

Where the books are outdated

Two points in the books' file chapters need correcting for .NET 10. The serial-port class SerialPort is presented as built in; since .NET 5 it lives in the System.IO.Ports NuGet package, which the project must reference (and a serial port is a hardware feature that containers and many servers lack, so tests should not depend on one). And the beginner example that calls File.Create without disposing the returned stream is the leak demonstrated above; the correct form is the Using block shown there. The numbered-file model (FileOpen, PrintLine, Input and the others) that the books describe is kept for compatibility, with the limits shown in its section, and the file code in books written for the .NET Framework has three more current-platform differences that this page covers where they matter: Encoding.Default is UTF-8 on .NET, not the machine’s ANSI code page; My.Computer is available only in project types that define it; and the UIOption and RecycleOption overloads work only on Windows.

Pitfalls checklist

  • Dispose every stream; File.Create and File.Open return open streams. Prefer the one-call File helpers for small files.

  • Build paths with Path.Combine or Path.Join; never with & and a literal separator. A rooted second argument makes Combine discard the first.

  • Resolve and check any path that includes untrusted input before opening it.

  • Do not rely on enumeration order; sort when the output must be stable.

  • State the encoding for any file another program reads. Use UTF-8 without a BOM unless a spreadsheet on Windows will open the file.

  • A relative path depends on the current directory, not on the executable’s directory.

  • Replace files by writing a temporary file and moving it over the target.

  • FileSystemWatcher events are hints: they can repeat, overflow and arrive before the file is complete.

  • TextFieldParser reads but does not write; an unterminated quote can swallow the rest of the file, so validate field counts and types.

  • UIOption and RecycleOption overloads work only on Windows; use the plain overloads in portable code.

  • Numbered-file functions are for migrated code; Input does not treat a lone LF as a record end.

  • Await is not allowed in Catch or Finally; Async Sub Main and Await For Each do not exist in Visual Basic.

  • A CSV exported for spreadsheets needs formula-injection protection when it includes user text.

  • Tests should not touch the real file system when StringReader, StringWriter or MemoryStream will do.
