Numbers and Math

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Visual Basic arithmetic has four habits that surprise programmers coming from C-family languages: / always produces a floating-point number (except for Decimal), \ is the integer division, ^ is an exponentiation that returns a Double, and integer overflow throws an OverflowException instead of wrapping around. On top of the .NET Math class the language adds the VB6 helpers Int, Fix, Rnd, Val, IsNumeric and a module of financial functions. This page covers the numeric operations, rounding rules, Decimal versus Double, big integers, random numbers, the financial functions, overflow, floating-point special values and the parsing helpers, and ends with what VB cannot do with the generic-math interfaces of .NET 7 and later. It was written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and checked on 2026-10-19; every program was built with Option Strict On and TreatWarningsAsErrors and run in a Linux container, unless it is marked otherwise. The numeric types, their ranges and literals are on Data Types and Literals; casts and the C... conversion functions on Type Conversions; operator precedence on Operators and Expressions. Formatting numbers as text (ToString("N2"), Format) is on Dates, Times and Formatting. For the C# side see Operators and Expressions in the C# reference.

The Math class, rounding and the integer operators

System.Math is a static class (VB code calls it as Math.Sqrt(2); no Imports is needed because System is imported). Besides the usual functions it has Clamp, DivRem, FusedMultiplyAdd, BitIncrement, IEEERemainder, Truncate, Cbrt, Log2 and the trigonometric functions in radians; MathF is the Single twin. The VB6 functions Abs, Sgn, Sqr, Sin, Atan and the like do not exist in Visual Basic .NET (a program that calls them gets BC30451, "is not declared"); use Math.Abs, Math.Sign, Math.Sqrt, Math.Sin and Math.Atan. Only Int, Fix and the random-number functions Rnd and Randomize survive from that generation.

Rounding

Three different roundings are in play, which is a favourite source of off-by-a-cent bugs:

  • Math.Round(x) and CInt(x) and CLng(x) round a tie (a value exactly halfway between two integers) to the nearest even integer, "banker’s rounding": 0.5 becomes 0, 1.5 and 2.5 become 2, and 3.5 becomes 4. The result for -0.5 is the Double negative zero, printed -0. VB6’s CInt used the same rule, so this is not new, but C# programmers expect Math.Round(2.5) to give 3 because of school arithmetic.

  • Math.Round(x, MidpointRounding.AwayFromZero) is the "school" rounding. The other modes are ToEven (the default), ToZero, ToNegativeInfinity and ToPositiveInfinity; the digits overload is Math.Round(x, digits, mode), with 0 to 15 digits for Double and 0 to 28 for Decimal. There is no negative-digits overload: divide, round and multiply, as the program does for hundreds.

  • Formatting rounds too, and not always the same way (see the dates-and-formatting page): 2.5D.ToString("F0") is 3 but 2.5.ToString("F0") is 2. If a rule is part of the requirements, round explicitly with the mode you want and format the result.

Int(x) is the floor (the largest integer not greater than x: Int(-2.7) is -3) and Fix(x) truncates toward zero (Fix(-2.7) is -2). They return the type of their argument, so Int(2.7D) is a Decimal and Int(7) an Integer, not an Integer conversion. The Math counterparts are Floor/Ceiling/Truncate, which exist for Double and Decimal only (Math.Floor(2.7) returns a Double).

Division, remainder and power

  • a / b returns a Double when the operands are integers: 7 / 2 is 3.5, and Dim ratio As Integer = 7 / 2 is BC30512 under Option Strict On. If both operands are Decimal the result is Decimal. Dividing by zero gives Infinity or NaN for Double (no exception) and throws DivideByZeroException for Decimal.

  • a \ b is integer division and truncates toward zero: -7 \ 2 is -3. It works on integer operands (7.9 \ 2 is BC30512 under Option Strict On, because a Double does not convert implicitly to Long), throws DivideByZeroException for a zero divisor, and Integer.MinValue \ -1 throws OverflowException.

  • a Mod b returns the remainder with the sign of the dividend (-7 Mod 2 is -1), the same as C#'s %. It works on floating point too (7.5 Mod 2 is 1.5) and throws for an integer zero divisor. For a result that is never negative use ((a Mod n) + n) Mod n; Math.IEEERemainder is a different (round-to-nearest) definition.

  • a ^ b converts its operands to Double, calls Math.Pow and returns a Double: assigning it to an Integer needs CInt(2 ^ 10) (BC30512 otherwise). Its precedence is higher than unary minus, so -2 ^ 2 is -4. ^ is not "exclusive or" (that is Xor), and it is undefined for BigInteger.

  • The shift operators << and >> mask the shift count to the type’s width (a shift of 32 on an Integer shifts by 0), >> is arithmetic for signed types, and there is no unsigned right shift operator (>>> is a syntax error, BC30201).

Decimal and Double

Double is a 64-bit IEEE 754 binary number: fast, with 15 to 17 significant decimal digits, and unable to represent most decimal fractions exactly. Decimal is a 128-bit decimal number with 28 to 29 significant digits and a stored scale (the number of digits after the decimal point), which is exact for the amounts that people write in decimal, which makes it the type for money, rates and anything that has to match a calculator. It is slower (software arithmetic), has a smaller range (about 7.9 x 1028) and no NaN or Infinity.

Use these rules:

  • Money, quantities that are counted in fractions of a unit, and anything that is typed by a person in decimal: Decimal. Literals need the D suffix (0.1D) or the @ type character; a bare 0.1 is a Double, 1D + 0.1 is a Double and assigning it to a Decimal is BC30512 under Option Strict On (write 1D + 0.1D, or CDec(0.1)).

  • Measurements, geometry, statistics, anything with Math.Sqrt or trigonometry: Double.

  • Decimal keeps trailing zeros that you wrote or computed: 1.10D * 2 is 2.20, and Decimal.GetBits shows the scale. This is useful for money and surprising in comparisons of text; = ignores scale.

  • CDec(0.1 + 0.2) is 0.3 because the conversion from Double rounds to 15 significant digits; that hides, not repairs, the noise in the Double result.

  • The late-fee function rounds once, at the end, away from zero, as a billing rule would; do not round every intermediate step.

BigInteger and the 128-bit integers

System.Numerics.BigInteger is an arbitrary-precision signed integer: it grows as needed, supports the arithmetic operators and Mod, compares with < and =, and converts from any integer type implicitly. It has no \ or ^ in VB (both are BC30452, "Operator is not defined for types BigInteger and Integer`"): use `/, which is integer division for BigInteger, and BigInteger.Pow. Conversions to fixed-size types are explicit (CInt, CLng, CDbl) and throw OverflowException when the value does not fit. Int128 and UInt128 (.NET 7) are fixed-size 128-bit integers with the usual arithmetic and overflow checking.

Random numbers

System.Random is a pseudo-random generator for simulations, games, sampling and tests. Create one instance and reuse it rather than a new one per call, or use the thread-safe shared instance Random.Shared (.NET 6). Next(min, max) has an exclusive upper bound; NextDouble() returns a value in [0, 1); Shuffle (.NET 8) and GetItems (.NET 8) cover the common array tasks. A seeded generator is reproducible, which is why tests seed it, but the algorithm and therefore the sequence are not guaranteed to stay the same across .NET versions. Random is not suitable for secrets: tokens, passwords, keys and nonces come from System.Security.Cryptography.RandomNumberGenerator.

The legacy VB generator is Rnd() (a Single in [0, 1)) with Randomize() to seed it from the clock and Randomize(seed) to seed it deterministically. Rnd(-1) followed by Randomize(n) restarts the same sequence for a given n, Rnd(0) repeats the last number, and the classic die formula is Int((upper - lower + 1) * Rnd() + lower). Use Random in new code.

Option Strict On
Imports System.Security.Cryptography

Module Ex04
    Sub Main()

The Financial functions

Microsoft.VisualBasic.Financial is a VB-only convenience library that every VB project can call without a package: Pmt, IPmt, PPmt, PV, FV, NPer, Rate, NPV, IRR, MIRR, and the depreciation functions SLN, SYD, DDB. The sign convention is the spreadsheet one: money you pay out is negative, money you receive is positive, and the rate is per period, so a 6 percent annual loan paid monthly uses 0.06 / 12 and a number of months. IRR takes a Double() of cash flows and an optional guess, and throws ArgumentException ("Arguments are not valid") if the flows do not change sign, for example IRR({100.0, 200.0}). NPV discounts the first value by one period too (it does not treat it as "time zero", unlike spreadsheet usage where the initial outlay is added separately). Everything is Double: for money that must be exact, use the results for estimates and do the booking arithmetic in Decimal.

Integer overflow

The VB compiler emits checked arithmetic for +, -, *, unary - and the narrowing conversions of Byte, SByte, Short, UShort, Integer, UInteger, Long and ULong: a result that does not fit throws OverflowException. This is the opposite of C#'s default (unchecked), and means that a VB program notices overflow where a C# one silently wraps. Decimal always checks. A constant expression that overflows is a compile error (Integer.MaxValue + 1 is BC30439, "Constant expression not representable in type 'Integer'"). Some operations check regardless of settings: Math.Abs(Integer.MinValue), Integer.MinValue \ -1, Decimal arithmetic and CInt of a value outside the range of Integer, which in the checked mode throws.

Option Strict On
Imports System.Text
Imports System.Numerics

Module Ex11
    ' 32-bit FNV-1a: the algorithm relies on wrap-around multiplication.
    ' Visual Basic checks integer overflow, so the arithmetic is done in Long and masked to 32 bits.
    Function Fnv1a(text As String) As UInteger
        Dim hash As Long = &H811C9DC5L
        For Each b In Encoding.UTF8.GetBytes(text)
            hash = (hash Xor b) * 16777619L And &HFFFFFFFFL
        Next
        Return CUInt(hash)
    End Function

    ' Reinterpreting the bits of an Integer as a UInteger (and back) without an overflow check.
    Function ToSigned(value As UInteger) As Integer
        Return BitConverter.ToInt32(BitConverter.GetBytes(value), 0)
    End Function

    Function Rotate(value As UInteger, count As Integer) As UInteger
        Return BitOperations.RotateLeft(value, count)
    End Function

    Sub Main()
        Console.WriteLine($"FNV-1a(""a"")     = {Fnv1a("a"):X8}")
        Console.WriteLine($"FNV-1a(""shelf"") = {Fnv1a("shelf"):X8}")
        Console.WriteLine($"As signed Integer: {ToSigned(Fnv1a("a"))}")
        Console.WriteLine($"Rotate left by 8:  {Rotate(&H12345678UI, 8):X8}")

        Dim a As Integer = Integer.MaxValue
        Try
            Console.WriteLine(a * 16777619)
        Catch ex As OverflowException
            Console.WriteLine("Plain Integer multiplication overflows: " & ex.GetType().Name)
        End Try

        ' Shifts and bit operators never overflow
        Dim flags As Integer = &HF0
        Console.WriteLine($"{flags >> 4:X} {flags << 4:X} {flags And &H3C:X} {flags Or 1:X} {flags Xor &HFF:X} {Not flags} {-16 >> 2} {&H80000000UI >> 31}")
        Console.WriteLine($"PopCount {BitOperations.PopCount(&HFFUI)}, LeadingZeroCount {BitOperations.LeadingZeroCount(1UI)}, IsPow2 {BitOperations.IsPow2(64)}")
    End Sub

Floating-point special values and comparisons

Double and Single implement IEEE 754, so besides the numbers they have Infinity, -Infinity, NaN and a negative zero. Visual Basic does not turn these into exceptions: 1 / 0.0 is Infinity, 0 / 0.0 is NaN, Math.Sqrt(-1) is NaN, and Math.Log(0) is -Infinity. Test with Double.IsNaN, IsInfinity and IsFinite, not with =: NaN = NaN is False and NaN <> NaN is True, while NaN.Equals(NaN) is True (which is what sorting uses, and why a sorted array has the NaN first). Math.Max(1, NaN) is NaN. Never compare computed doubles with =; use a tolerance that is relative to the magnitude, as the NearlyEqual function does, because Double.Epsilon is the smallest positive value (about 5E-324), not a rounding tolerance.

Option Strict On

Module Ex07
    Function NearlyEqual(a As Double, b As Double, Optional relative As Double = 0.000000001) As Boolean
        If a = b Then Return True
        Return Math.Abs(a - b) <= relative * Math.Max(Math.Abs(a), Math.Abs(b))
    End Function

Parsing numbers: Val, IsNumeric and TryParse

Visual Basic keeps its VB6 parsing helpers. Val(text) reads the leading numeric part of a string and ignores the rest (and spaces), returns 0 if there is none, always treats the point as the decimal separator regardless of culture, understands the prefixes &H and &O, and returns a Double. IsNumeric is culture-sensitive and accepts what CDbl accepts, including leading and trailing white space, group separators, and the &H... and &O... forms. Both are convenient in throwaway code and misleading in anything that handles data: Val("1,5") is 1 while CDbl("1,5") is 1.5 under de-DE. The reliable tools are TryParse with an explicit NumberStyles and CultureInfo, and Parse when failure should be an exception (FormatException for bad text, OverflowException for text that does not fit). CInt, CDbl and friends throw InvalidCastException for text that does not parse.

Generic math from Visual Basic

NET 7 turned the numeric types into a hierarchy of generic interfaces (INumber(Of T), IAdditionOperators, IBinaryInteger, IFloatingPoint and others) whose members are static abstract: operators and constants such as T.Zero. Visual Basic 17.13 can consume the interfaces but cannot call their static abstract members through a type parameter, and it cannot declare such interfaces. The

practical limits, all of them verified by the build below:

  • A method may constrain a type parameter to INumber(Of T), and may call the instance members that the interfaces expose (CompareTo, Equals, ToString).

  • T.Zero is BC32098 ("Type parameters cannot be used as qualifiers"), and a + b on two T values is BC30452, so no generic sum, average or dot product can be written over an INumber.

  • The static methods of the concrete types remain callable by name: Integer.CreateSaturating(3000000000L), Byte.CreateChecked(300), Double.Clamp, Integer.IsEvenInteger, Double.Parse.

  • The usual workaround is to pass the operations in (a Func(Of T, T, T) and a zero value), to use LINQ’s Sum, Average and Aggregate, or to put the generic algorithm in a C# library and call it from VB.

    ' The constraint is accepted, and so are the instance members the interfaces expose.
    Function Largest(Of T As INumber(Of T))(first As T, second As T) As T
        Return If(first.CompareTo(second) >= 0, first, second)
    End Function

    ' Operators and static members of T are out of reach in VB, so pass in what you need.
    Function SumOf(Of T)(items As IEnumerable(Of T), zero As T, add As Func(Of T, T, T)) As T
        Dim total = zero
        For Each item In items
            total = add(total, item)
        Next
        Return total
    End Function

Where the books are outdated. Older material, including the two books that this section was planned from, says that dividing by zero throws DivideByZeroException. That is true for \, Mod and Decimal division, and false for / on integers or Double: 10 / 0 is Infinity. They show Dim q As Integer = a / b and a ^ b assigned to an Integer, which do not compile under Option Strict On (both operators return Double). They teach Rnd and Randomize for random numbers, where Random and Random.Shared are current, and Val and IsNumeric for input validation, where TryParse with a culture is current. Banker’s rounding in Math.Round and CInt is often presented as a surprise or omitted. They predate BigInteger, Int128, Decimal formatting changes and generic math.

Pitfalls checklist

  • / returns a Double; \ is integer division; ^ returns a Double and is not Xor; -2 ^ 2 is -4.

  • Math.Round, CInt and Decimal.Round round ties to even; ToString("F0") follows a different rule for Double than for Decimal. Choose the MidpointRounding explicitly.

  • Int floors, Fix truncates; Math.Floor returns Double.

  • Integer overflow throws, constants that overflow do not compile; RemoveIntegerChecks is project-wide and hides bugs.

  • Math.Abs(Integer.MinValue) and Integer.MinValue \ -1 throw.

  • 0.1 + 0.2 = 0.3 is False for Double, True for Decimal. Compare doubles with a relative tolerance; NaN never equals anything.

  • Decimal division by zero throws; Double division by zero does not.

  • Mod keeps the sign of the dividend.

  • A literal like 0.1 is Double; money literals need D. &H80000000 is negative.

  • Random.Next(1, 7) never returns 7; do not use Random for secrets; do not create a new Random in a loop.

  • Val ignores the culture, IsNumeric and CDbl do not; use TryParse with a culture.

  • NPV discounts the first cash flow; Pmt needs the signs right.

  • T.Zero and + on generic T do not compile.
