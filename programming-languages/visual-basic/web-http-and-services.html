Web, HTTP and Services

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Examples marked "built and run" are complete programs that start with Option Strict On, were built with warnings treated as errors and were run in the .NET 10 SDK container (Linux, arm64); the output shown is real output. No example needs the internet: every web server in this page listens on the loopback address (port 0, so the operating system chooses a free port) or runs in memory, and the client code talks to it inside the same process. The scratch projects had the root namespace App. Code that needs .NET Framework or Windows is labelled "built, not run" and was compiled against reference assemblies on Linux; nothing more is claimed for it.

"The web" means several different things to a Visual Basic programmer, and the answer to "can I do it in VB?" changes with each. The server side has a hard edge: ASP.NET Web Forms and ASP.NET MVC 5 are fully supported with Visual Basic, but they run only on .NET Framework and IIS, and ASP.NET Core can be written in Visual Basic by hand, but Microsoft ships no Visual Basic template for it and the Razor view engine has no Visual Basic syntax. The client side has no edge at all: HttpClient, System.Net.Http.Json, the SignalR client and ClientWebSocket are ordinary .NET libraries that Visual Basic calls like any other. This page covers both sides, using the shelf library catalogue (an ISBN lookup service and its callers) as the running example. The existing sections on ASP.NET Web Forms, ASP.NET MVC and ASP.NET Core document those frameworks in depth, in C# for ASP.NET Core and in markup plus C# or VB code-behind for the Framework stacks; this page does not repeat them, it says what is different when the language is Visual Basic.

Web Forms and MVC 5 with Visual Basic

Web Forms and MVC 5 are the stacks where Visual Basic is a first-class language on the server. A Web Forms page is markup in an .aspx file with a Visual Basic code-behind file (Default.aspx.vb); an MVC 5 application has controllers in .vb files and views in .vbhtml. Both run on .NET Framework 4.8.1 under IIS, which is why they have no net10.0 form and why the rest of this page cannot show them running on Linux. The listing below is the code-behind of a Web Forms search page and an MVC 5 controller for the shelf, compiled against the .NET Framework 4.8 reference assemblies (Microsoft.NETFramework.ReferenceAssemblies, which the SDK adds on its own for a net48 target) with the Microsoft.AspNet.Mvc 5.3.0 package. It is built, not run: compiling proves the language and API shapes, not that a page renders.

Three things are specific to Visual Basic on these stacks. First, Handles clauses wire events in code-behind (Sub Page_Load(sender As Object, e As EventArgs) Handles Me.Load), exactly as in Windows Forms; the markup can also name the handler (OnClick="SearchButton_Click") as above, in which case no Handles is written. Second, Public Partial Class is how the designer-generated half of a page (the .aspx.designer.vb file declaring the control fields) joins the half you edit; in a hand-written class the fields are plain Protected members. Third, Razor views are .vbhtml files with Visual Basic expressions (@If model IsNot Nothing Then ... End If); that dialect exists only in MVC 5 and Web Pages, and was never carried to ASP.NET Core.

The web My objects belong to the same world. MyType=Web makes the compiler generate My.User, My.Request, My.Response, My.Computer (as ServerComputer) and My.Log (as AspLog), all backed by System.Web. On .NET Framework that works; on .NET 10 it does not. The same project property that builds on net48:

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Library</OutputType>
    <TargetFramework>net48</TargetFramework>
    <MyType>Web</MyType>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="System.Web" />
  </ItemGroup>
</Project>

builds there (a class using My.User.Name compiled, not run), while <MyType>Web</MyType> in a Microsoft.NET.Sdk.Web project that targets net10.0 fails with five BC30002 errors:

vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.ApplicationServices.WebUser' is not defined.
vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.Devices.ServerComputer' is not defined.
vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.Logging.AspLog' is not defined.
vbc : error BC30002: Type 'Global.System.Web.HttpRequest' is not defined.
vbc : error BC30002: Type 'Global.System.Web.HttpResponse' is not defined.

The generated My code names System.Web.HttpRequest and friends, which do not exist on .NET 10. The other MyType values (WindowsForms, WindowsFormsWithCustomSubMain, Console, Empty) are described in The My Namespace.

Session and application state are the two ideas that Classic ASP, Web Forms and ASP.NET Core share, with different mechanics: Session("visits") and Application("hits") are dictionaries of Object in Classic ASP and Web Forms. ASP.NET Core splits them: per-visitor state is the opt-in session middleware (typed accessors such as SetInt32), application-wide state is an ordinary singleton or a field. The ASP.NET Core version, written in Visual Basic, is shown further down in the section on sessions.

ASP.NET Core written in Visual Basic

ASP.NET Core is a set of ordinary .NET libraries (the Microsoft.AspNetCore.App shared framework), so nothing stops Visual Basic from calling them. What is missing is everything around the libraries: dotnet new webapi -lang VB does not exist, and the template engine says so:

No templates found matching: 'webapi', -lang='VB'.
Allowed values for '-lang' option are: 'C#', 'F#'.

Microsoft’s ASP.NET Core documentation shows C# only, and the Razor compiler produces C# and skipped the Visual Basic project in the test below. The language strategy (see History, Versions and Language Strategy) says that new workloads are not planned for Visual Basic, so treat what follows as supported-by-the-compiler, not supported-by-the-product.

The project file is the C# one with a .vbproj extension: the Web SDK works for Visual Basic. The difference that matters is that there is no implicit using list. C# web projects get ImplicitUsings, a generated file of global usings for Microsoft.AspNetCore.Builder, Microsoft.AspNetCore.Http, Microsoft.Extensions.DependencyInjection and others; a Visual Basic project gets none of them, so every file imports what it needs, and a missing import shows up as BC30456 on an extension method:

error BC30456: 'UseUrls' is not a member of 'ConfigureWebHostBuilder'.
error BC30456: 'ClearProviders' is not a member of 'ILoggingBuilder'.

Both are extension methods whose namespaces (Microsoft.AspNetCore.Hosting and Microsoft.Extensions.Logging) were not imported. The demonstration project used in this page has one .vbproj and several modules; StartupObject selects the program, and each listing is complete except for the shared types, shown first:

Public Class BookStore
    Private ReadOnly _books As New Dictionary(Of String, BookDto) From {
        {"9780306406157", New BookDto With {.Isbn = "9780306406157", .Title = "Shelf Basics", .Year = 2020}}
    }

    Public Function Find(isbn As String) As BookDto
        Dim book As BookDto = Nothing
        Return If(_books.TryGetValue(isbn, book), book, Nothing)
    End Function

    Public Sub Add(book As BookDto)
        _books(book.Isbn) = book
    End Sub

    Public Function All() As IReadOnlyList(Of BookDto)
        Return _books.Values.ToList()
    End Function
End Class

Friend Module Hosting

    ' The loopback address Kestrel picked when asked for port 0.
    Friend Function ServerAddress(app As WebApplication) As String
        Return app.Services.GetRequiredService(Of IServer)().Features.Get(Of IServerAddressesFeature)().Addresses.First()
    End Function

End Module

BookDto is a plain class with public get/set properties and a parameterless constructor, which is what the JSON binder needs; Visual Basic has no record, and a Structure or a class with only a parameterised constructor would not bind the way a C# record does. Hosting.ServerAddress reads the address Kestrel chose for port 0 from IServerAddressesFeature.

A minimal API

A minimal API maps a URL pattern and a delegate to the request pipeline. Visual Basic lambdas are the delegates. Two things differ from the C# examples in the ASP.NET Core documentation: a multi-statement lambda is written as a Function block ending in End Function, and the As IResult is worth keeping, because when the branches return different result types (here Results.NotFound() and Results.Ok(book)) an explicit return type avoids relying on type inference.

Option Strict On

Imports System.Net.Http
Imports System.Net.Http.Json

Imports Microsoft.AspNetCore.Http

Module MinimalApiDemo

    Sub Main(args As String())
        RunAsync(args).GetAwaiter().GetResult()
    End Sub

    Async Function RunAsync(args As String()) As Task
        Dim builder = WebApplication.CreateBuilder(args)
        builder.WebHost.UseUrls("http://127.0.0.1:0")
        builder.Configuration("Logging:LogLevel:Default") = "None"
        builder.Services.AddSingleton(Of BookStore)()
        Dim app = builder.Build()

        app.MapGet("/books", Function(store As BookStore) store.All())
        app.MapGet("/books/{isbn}",
                   Function(isbn As String, store As BookStore) As IResult
                       Dim book As BookDto = store.Find(isbn)
                       Return If(book Is Nothing, Results.NotFound(), Results.Ok(book))
                   End Function)
        app.MapPost("/books",
                    Function(book As BookDto, store As BookStore) As IResult
                        store.Add(book)
                        Return Results.Created("/books/" & book.Isbn, book)
                    End Function)

        Await app.StartAsync()
        Dim address As String = Hosting.ServerAddress(app)
        Console.WriteLine("listening on loopback: " & address.StartsWith("http://127.0.0.1:").ToString())

        Using client As New HttpClient With {.BaseAddress = New Uri(address)}
            Dim all = Await client.GetFromJsonAsync(Of List(Of BookDto))("/books")
            Console.WriteLine("GET /books -> " & all.Count & " book(s), first = " & all(0).Title)

            Dim created = Await client.PostAsJsonAsync("/books", New BookDto With {.Isbn = "9780131103627", .Title = "Types and Tables", .Year = 1988})
            Console.WriteLine("POST /books -> " & CInt(created.StatusCode) & " " & created.StatusCode.ToString() & ", Location = " & created.Headers.Location.ToString())

            Dim found = Await client.GetAsync("/books/9780131103627")
            Console.WriteLine("GET known -> " & CInt(found.StatusCode) & " " & Await found.Content.ReadAsStringAsync())

            Dim missing = Await client.GetAsync("/books/0000000000000")
            Console.WriteLine("GET unknown -> " & CInt(missing.StatusCode) & " " & missing.StatusCode.ToString())
        End Using

        Await app.StopAsync()
    End Function

Notes on the listing. WebApplication.CreateBuilder(args) and builder.Build() are the same calls as in C#. app.StartAsync() (rather than app.Run()) starts Kestrel without blocking so that the program can drive it; a real service ends Main with app.Run(). The entry point is a synchronous Sub Main that waits on an Async Function, because the language has no Async Main (declaring one fails with BC30737, see the pitfalls below). Configuration("Logging:LogLevel:Default") = "None" silences the request log so that the output stays readable; ClearProviders() would need Imports Microsoft.Extensions.Logging, and that import makes the name Console bind to the namespace Microsoft.Extensions.Logging.Console (BC30456 on every Console.WriteLine), which is why the listing uses configuration instead. If you do need the logging import, put it in a file that does not print.

Controllers

Web API controllers are classes decorated with attributes, which Visual Basic writes with angle brackets and line continuation inside the brackets as usual. The action methods are Function`s; `ActionResult(Of BookDto) is ActionResult<BookDto>, and returning a BookDto where an ActionResult(Of BookDto) is expected works through the implicit conversion that the type defines (Visual Basic accepts the widening conversion without a cast). Validation attributes on the model class give the automatic 400 application/problem+json response of [ApiController].

Visual Basic specifics visible here. The attribute argument "api/[controller]" is just a string; NameOf(GetOne) works as in C#; the anonymous type New With {.isbn = book.Isbn} supplies route values to CreatedAtAction; and the controller is discovered because it is Public and declared at namespace level in the entry assembly (a Public Class nested inside a default Friend Module is not visible outside the assembly, because its container is Friend; the same rule makes XmlSerializer fail on such a class). The Location header reads /api/Books/... with a capital B: the [controller] token takes the class name without the Controller suffix as written, so the casing of the class name appears in the URL, and URLs are case-insensitive in ASP.NET Core routing.

Handlers, attributes and the places where Visual Basic differs

The delegate-based API is where the language shows. These are the four things a C# example in the documentation does that a Visual Basic program cannot, with the real compiler messages and the working replacement for each.

1. A method group does not convert to Delegate. MapGet takes a Delegate (and a RequestDelegate). C# converts a method group to a delegate type it infers; Visual Basic’s AddressOf needs a concrete delegate type to convert to:

app.MapGet("/hello/{name}", AddressOf Hello)
Program.vb(14,13): error BC30518: Overload resolution failed because no accessible 'MapGet' can be called with these arguments:

Wrap the method in the delegate type that matches it: New Func(Of String, IResult)(AddressOf Hello).

2. No attributes on lambda parameters. C# writes ([FromQuery(Name = "q")] string term) => term. Visual Basic forbids attributes on lambda parameters:

3. No Optional lambda parameters. C# lambdas can have default values ((int page = 1) => ...); Visual Basic cannot:

app.MapGet("/page", Function(Optional page As Integer = 1) page.ToString())

Use a named method with Optional, a nullable parameter (page As Integer?) or a property with a default in an <AsParameters> class.

Rules shown or implied by the listing:

  • One HttpClient for the life of the program (or one per named/typed client from the factory), not one per request: each instance holds a connection pool, and creating many exhausts sockets. Dispose it with Using only when you really own the lifetime.

  • BaseAddress needs a trailing slash when the relative paths have no leading slash ("isbn/..."): http://host/api plus "isbn/1" resolves to http://host/isbn/1, dropping api. The listing appends "/".

  • GetFromJsonAsync(Of T), PostAsJsonAsync and ReadFromJsonAsync(Of T) (namespace System.Net.Http.Json) replace the manual ReadAsStringAsync plus JsonSerializer.Deserialize pair; they use the web defaults (camelCase, case-insensitive on read). They are reflection-based, so a trimmed or AOT application needs a source-generated context (a C# helper project; see the Serialization, JSON and XML page).

  • EnsureSuccessStatusCode() throws HttpRequestException whose StatusCode property carries the code (ServiceUnavailable above). Decide per call whether a 404 is an error (here it is a normal "not found" result).

  • Cancellation and timeouts both surface as TaskCanceledException (a subclass of OperationCanceledException). The HttpClient.Timeout expiry carries a TimeoutException as its inner exception, as the last line of the output shows; that is how to tell it from a cancellation by your own token. Timeout is set once, before the first request: changing it afterwards throws InvalidOperationException.

  • Async is the rule: see Async and Await; do not call .Result or .GetAwaiter().GetResult() on a UI thread.

SOAP and WCF clients

The books show "Add Service Reference" wizards and ASMX proxies. On .NET 10 the equivalents are the WCF client libraries (System.ServiceModel.Http and System.ServiceModel.Primitives) plus dotnet-svcutil, a command-line tool that reads a WSDL and writes the client code. The tool runs for Visual Basic projects but wrote C# in the test: it produced ServiceReference1/Reference.cs next to a .vbproj and did not touch the project, because a Visual Basic project cannot compile a .cs file. Pitfalls

  • An Async Main does not exist. Async Function Main(args As String()) As Task fails with BC30737: No accessible 'Main' method with an appropriate signature was found in 'App'. Use Sub Main and wait: RunAsync(args).GetAwaiter().GetResult().

  • Changing StartupObject on the command line without --no-incremental re-runs the previous program.

  • A local named after a child namespace (schema with Imports System.Text.Json, text with Imports System) hides or is hidden by the namespace, because Visual Basic names are case-insensitive.

  • Imports Microsoft.Extensions.Logging breaks Console.WriteLine in the same file (BC30456): qualify as System.Console or keep that import in another file.

  • Public is required for controllers, hubs and DTOs; a type declared in a default Friend Module is Friend and invisible to discovery and to the JSON serialisers.

  • A lambda passed where a Delegate is expected becomes a compiler-generated VB$AnonymousDelegate type: give the handler a real delegate type when its return type matters (async handlers).

  • Do not trust a build for a view layer: .cshtml/.razor files in a VB project compile to nothing.

  • Security: the shelf examples are demonstrations. Real services need authentication, authorization and hardened headers; see Authentication and Identity and Security Hardening.
