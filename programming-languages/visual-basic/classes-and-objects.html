Classes and Objects

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is a complete console program that starts with Option Strict On, was built with warnings treated as errors (unless the text says otherwise) and was run in the .NET 10 SDK container (Linux); the output shown is real output. The examples that are meant to fail say so, and show the compiler messages that the SDK printed. The projects use the root namespace Shelf, which is why the runtime messages below mention Shelf.Magazine and not just Magazine. The project-level imports that the SDK adds (Microsoft.VisualBasic, System, System.Collections.Generic, System.Linq and others) are why Console, List(Of T) and LINQ need no Imports line.

A class is the basic unit of object-oriented code in Visual Basic: a reference type that bundles data (fields), behaviour (methods) and the rules for creating and exposing them. Almost everything you write for a real application is a class: the shelf library catalogue used throughout this reference is built from Book, Magazine, Author, Loan and Catalog. This page covers the class itself, how an object comes into existence, how its members are declared and how visible each one is, and how two references to objects compare. Properties and default properties are on Properties and Default Properties, Shared members and Module on Modules and Shared Members, value types on Structures and Value Types, inheritance on Inheritance and Polymorphism, interfaces on Interfaces, events on Events and Handlers, equality operators on Operator Overloading and Equality and disposal on Object Lifetime and Disposal. If you come from C#, the same topic is on Classes and Objects in C#; the differences are collected in a table near the end of this page.

Declaring a class

[<attributes>] [accessmodifier] [Shadows] [MustInherit | NotInheritable] [Partial] Class Name [(Of typeparameters)]
    [Inherits BaseClass]
    [Implements Interface1, Interface2]
    members
End Class

  • The members are declarations between Class and End Class: fields, Const, methods (Sub and Function), properties, events, operators, constructors, nested types, and Declare statements. Executable statements are only allowed inside procedures, never directly in the class body.

  • Class has no mandatory Public. A top-level class without an access modifier is Friend, visible inside its assembly only (the reflection example in the access modifiers section prints it). Write Public for every type that is part of a library’s API.

  • MustInherit makes the class abstract (it cannot be created with New, BC30569), NotInheritable makes it sealed. They are mutually exclusive. Both are developed on Inheritance and Polymorphism.

  • Shadows on a nested class hides a base-class member of the same name.

  • Partial splits the declaration over several files (see below), and Of adds type parameters (see Generics).

  • A file may contain any number of classes, but the usual convention is one type per file named after the type. The layout of a source file is on Program Structure and Code Conventions.

  • Names are not case sensitive. Book, BOOK and book are the same identifier, so a local variable called book of type Book is legal and common (Dim book As Book), but a class and a method of the same spelling in one scope are not.

The first complete example shows the vocabulary used in the rest of the page: private fields, a constructor, an instance method that uses the fields, a Shared field that belongs to the class and an overridden ToString.

Option Strict On

Public Class Loan
    Private ReadOnly _title As String
    Private _renewals As Integer

    Public Shared ReadOnly MaxRenewals As Integer = 2
    Public Shared Created As Integer

    Public Sub New(title As String)
        _title = title

        End If

        Return True
    End Function

    End Function

Fields

A field is a variable declared in the class body. Dim in a class means Private, so Dim Count As Integer is a private field, while Public Count As Integer is a public one. Prefer Private fields, exposed through properties when other code needs them: a public field cannot later change into a property without recompiling every caller, cannot be used in data binding, and cannot carry validation.

  • The usual naming convention is a leading underscore (_title), which also avoids the clash with a parameter of the same name described under "Case-insensitivity" below.

  • ReadOnly fields may be assigned only in their declaration or in a constructor of the same class (BC30064 otherwise). Shared ReadOnly fields may be assigned in their declaration or in Shared Sub New.

  • Const fields are compile-time constants, implicitly Shared, and only of an intrinsic type (numbers, Boolean, Char, Date, String) or an Enum. Use Shared ReadOnly for anything else, such as an object or a computed value.

  • WithEvents fields make event wiring with Handles possible; see Events and Handlers.

  • A field may be declared with an initializer, Private _count As Integer = 5, or with As New, Private ReadOnly _log As New List(Of String). The initializers of instance fields can use Me and the fields declared before them (unlike C#, where an instance initializer cannot refer to another instance member).

When the initializers run

The order in which a new object is built matters when constructors call overridable methods. The rule in Visual Basic is:

  1. memory for the object is allocated and every field has its default value (0, False, Nothing);

  2. the constructor starts. If its first statement calls MyBase.New(...), the base constructor runs first, to the end; if it calls Me.New(...), that other constructor of the same class runs first and the initializers are not repeated;

  3. immediately after the base constructor has returned, the instance field initializers of this class run in the order they are written;

  4. then the rest of the constructor body runs.

C# differs: field initializers run before the base constructor. The consequence in Visual Basic is that a base constructor that calls an Overridable method sees the derived class’s fields before their initializers ran:

Option Strict On

Public Class Base
    Public Sub New()
        Console.WriteLine("Base.New starts")
        Console.WriteLine("  Describe() says: " & Describe())
        Console.WriteLine("Base.New ends")
    End Sub

    Public Overridable Function Describe() As String
        Return "base"
    End Function
End Class

    Private _count As Integer = 5
    Private ReadOnly _upper As String = _label.ToUpperInvariant()

    Public Sub New()
        MyBase.New()
        Console.WriteLine("Derived.New body: " & Describe())
    End Sub

    Public Overrides Function Describe() As String
        Return "label=" & If(_label, "<Nothing>") & ", count=" & _count
    End Function

While Base.New ran, _label was still Nothing and _count was 0, although both have initializers. Calling an overridable member from a constructor is a known design problem in every .NET language; in Visual Basic it is slightly worse than in C# because even the initializer values are missing. Keep constructors free of virtual calls, or make the member NotOverridable/Private, or move the work into an explicit Initialize step.

Constructors

A constructor is a Sub named New. It runs once for every object created with New, after the memory has been zeroed.

[accessmodifier] Sub New([parameters])
    [MyBase.New(...) | MyClass.New(...) | Me.New(...)]
    statements
End Sub

  • A class that declares no Sub New receives a default public parameterless constructor from the compiler. As soon as you declare any constructor, the default one disappears: New Reader() then fails with BC30455 when only Sub New(name As String) exists.

  • Constructors can be overloaded like any method. They may use Optional parameters and named arguments (New Reader(limit:=9)), though many designs prefer two or three explicit overloads so the intent is clear in the call.

  • To reuse one constructor from another, call Me.New(...) as the first statement. Me.New anywhere else is BC30282. A cycle of constructor calls is BC30298.

  • The constructor of the base class is called with MyBase.New(...), also as the first statement. If you omit the call, the compiler inserts MyBase.New() and that must exist and be accessible: otherwise BC30387 (when the derived class declares no Sub New at all) or BC30148 (when it declares one without the call). A constructor cannot have both a Me.New and a MyBase.New call.

  • A constructor does not return a value; Return takes no expression there (BC30647).

  • A Private Sub New prevents creating objects from outside, which is how factory methods, singletons and classes of only Shared members are written.

  • Shared Sub New is the type initializer. It has no parameters and no access modifier, runs once, before the first instance is created or the first Shared member is read, and runs in a thread-safe way. If it throws, the type becomes unusable: every later access throws TypeInitializationException (see "Instance and Shared members").

The Watcher constructor registers Me with another object before it finishes; the notifier now holds a reference to an object that is not completely built. Private constructors and factories

A private constructor and a Shared factory method control how objects are created: they can validate, cache, or choose among subclasses. NotInheritable closes the class so that no derived class can bypass the factory. A class that only groups Shared functions can use the same two tools, although a Module is simpler (see Modules and Shared Members).

Option Strict On

' A class that is only ever created through a Shared factory method
Public NotInheritable Class Isbn
    Private Shared ReadOnly Known As New Dictionary(Of String, Isbn)

    Public ReadOnly Property Value As String

    Private Sub New(value As String)
        Me.Value = value
    End Sub

    Public Shared Function Create(value As String) As Isbn
        Dim existing As Isbn = Nothing
        If Known.TryGetValue(value, existing) Then
            Return existing
        End If
        Dim created As New Isbn(value)
        Known.Add(value, created)
        Return created
    End Function

    Public Overrides Function ToString() As String
        Return Value
    End Function
End Class

' A class that only has Shared members: NotInheritable plus a Private constructor
Public NotInheritable Class Strings
    Private Sub New()
    End Sub

    Public Shared Function Initials(name As String) As String
        Return String.Concat(name.Split(" "c).Select(Function(part) part.Substring(0, 1)))
    End Function
End Class

    Sub Main()

        Dim b = Isbn.Create("9780134757599")

Creating objects and the meaning of Nothing

New allocates an object and runs a constructor. A class-typed variable holds a reference to the object, or Nothing (null) when it refers to none; Nothing is the default of every reference-type variable and field. The semantics of Nothing, including its meaning for value types, are on Nothing and Nullable Value Types.

  • Dim x As New T(args) declares and creates in one statement. With several names, Dim x, y As New T() creates one object per name; Dim p, q As T declares two variables of type T, both Nothing, with no object .

  • Assigning a variable of class type copies the reference, not the object. Two variables then name the same object, and a change through one is visible through the other. Passing an object ByVal copies the reference too: the callee can change the object but cannot make the caller’s variable refer to another object, which ByRef can.

  • A method call on Nothing throws NullReferenceException. The compiler warns about the obvious cases: reading a local that has not been assigned on every path gives BC42104, an error here because the project treats warnings as errors.

Option Strict On

Public Class Basket
    Public Property Items As New List(Of String)
    Public Property Label As String = "basket"
End Class

Module Program
    Private Sub AddByVal(b As Basket)
        b.Items.Add("added through the reference")   ' the caller sees this
        b = New Basket()                              ' the caller does not see this
        b.Label = "new basket, local only"
    End Sub

    Private Sub ReplaceByRef(ByRef b As Basket)
        b = New Basket With {.Label = "replaced"}
    End Sub

    Sub Main()
        Dim first As New Basket()
        Dim alias1 = first
        alias1.Label = "renamed through alias"
        Console.WriteLine(first.Label & " / same object: " & (first Is alias1))

        AddByVal(first)
        Console.WriteLine(first.Label & " / items: " & first.Items.Count)

        ReplaceByRef(first)
        Console.WriteLine(first.Label & " / items: " & first.Items.Count & " / alias still: " & alias1.Label)

        ' As New with several names creates one object per name; a separate As clause does not create any.
        Dim x, y As New Basket()
        Dim p, q As Basket
        p = Nothing
        q = x
        Console.WriteLine("x Is y: " & (x Is y))
        Console.WriteLine("p Is Nothing: " & (p Is Nothing) & ", q Is x: " & (q Is x))

        Try
            Console.WriteLine(p.Label)
        Catch ex As NullReferenceException
            Console.WriteLine("NullReferenceException: " & ex.Message)
        End Try
    End Sub
End Module

Object initializers

An object initializer creates the object and assigns accessible fields and properties in the same expression: New Book With {.Title = "...", .Year = 2004}. They were added in Visual Basic 9.0 (Visual Studio 2008). The rules:

  • Each assignment starts with a dot and names a member that is accessible, settable and not ReadOnly (BC30526 for a read-only property). The assignments run in the order written.

  • The constructor runs first, with the arguments in parentheses if any (New Book("title", 2004) With {.Pages = 1}), then the assignments run top to bottom.

  • Initializers nest: a value can itself be New Author With {...}. They can appear anywhere an expression is allowed: as an argument, in a Return, in a From collection initializer.

  • A ReadOnly collection property cannot be assigned in an initializer; add to it afterwards, or provide a constructor parameter.

  • The matching With statement (below) is a different feature, and the initializer’s list uses braces, while the statement is a block.

Option Strict On

Public Class Author
    Public Property Name As String = ""
    Public Property BornOn As Date?
End Class

Public Class Book
    Public Property Title As String = ""
    Public Property Year As Integer
    Public Property Lead As Author
    Public ReadOnly Property Tags As New List(Of String)
    Public Property Pages As Integer = 100
End Class

    Sub Main()

            .Year = 2004,

        book.Tags.Add("refactoring")

Instance and Shared members

An instance member belongs to one object. A Shared member belongs to the class itself: there is one copy, it can be used without an object (Loan.Created), and it is the equivalent of static in C#. The rules:

  • A Shared member cannot use Me or an instance member without an object reference (BC30043, BC30369, BC30469). An instance member can use Shared members freely.

  • Accessing a Shared member through an object variable (c.Level) compiles, but warns: BC42025, "qualifying expression will not be evaluated". The warning exists because GetCounter().Total would not call GetCounter(). Always qualify with the class name.

  • Static local variables keep their value between calls. In an instance method there is one copy per object; in a Shared method, one for the class. They are not thread safe.

  • Shared Sub New runs once before first use; Shared field initializers run at the same time, in written order.

  • Module members are implicitly Shared; a Module is the right container for helper procedures that have no state.

Nested types

A type declared inside a class is a nested type. Use one when a type is meaningful only to its container (a private Entry record in a Catalog), or when you want the container to act as a namespace for a closely related type (Catalog.Options, Catalog.SortOrder). Rules: nested types default to Public; they are named through the container (Catalog.Options) or by Imports with an alias; the CLR name uses a plus sign (Shelf.Catalog+Options); a nested type sees the container’s Private members, but it needs an object reference to use instance members (BC30469 without one).

Partial classes

Partial (Visual Basic 2005) lets one class be declared in several files of the same project. They are merged by the compiler into one type. Typical uses are generated code (Windows Forms designer files and XAML code-behind files that contain the Partial part generated by a tool, next to the part you edit) and keeping a very large class manageable.

  • All parts must belong to the same project (assembly) and namespace, have the same class name and type parameters, and the same base class and interfaces if they name them (the union of Implements is used).

  • Access modifiers written on several parts must agree. MustInherit or NotInheritable on one part applies to the whole class.

  • Partial methods (a declaration in one part and an implementation in another) are on Extension Methods and Partial Methods.

Identity and equality

Two questions are different and both are common:

  1. Identity: do two variables refer to the same object? This is the Is operator (and IsNot). It compares references only, it cannot be overloaded, and it works on any pair of reference or nullable operands, including Nothing. For value types the compiler rejects it (BC30020).

  2. Equality: do two objects have the same value, as defined by their class? That is Equals(Object), and, if the class overloads it, the = operator. The default Object.Equals of a class is a reference comparison, so it returns False for two distinct but identical-looking objects unless the class overrides it.

= on two class-typed operands that do not define an operator is a compile error (BC30452), in contrast with C#, where == on classes silently compares references. Visual Basic forces you to say which one you want: Is for identity, Equals or the overloaded = for value equality. Overriding Equals requires overriding GetHashCode as well, because hash-based collections (HashSet, Dictionary) use both; the full set of rules, IEquatable(Of T), and user-defined operators are on Operator Overloading and Equality.

the runtime Type; GetType(Book) is the compile-time operator form. x.GetType() Is GetType(Book) is an exact type test, TypeOf x Is Book accepts derived classes.

MemberwiseClone()

Protected; a shallow copy of the object. Useful inside a Clone or copy method, see below.

Finalize()

Protected; called by the garbage collector; almost never written by hand, see Object Lifetime and Disposal.

ReferenceEquals(a, b)

Shared; the function behind Is (and safe for classes that overload =).

Copying and comparing objects

MemberwiseClone copies the fields of an object into a new object but does not copy the objects that the fields refer to, so a "clone" shares its collections with the original. A deep copy copies those too. IComparable(Of T) makes the natural order of a class available to Sort, SortedSet and Order By; a Comparison(Of T) lambda gives an alternative order for one call. Avoid ICloneable: it does not say whether the copy is shallow or deep.

Option Strict On

Public Class Author
    Public Property Name As String = ""
End Class

Public Class Book
    Implements IComparable(Of Book)

    Public Property Title As String = ""
    Public Property Year As Integer
    Public Property Authors As New List(Of Author)

    Public Function ShallowCopy() As Book
        Return DirectCast(MemberwiseClone(), Book)
    End Function

    Public Function DeepCopy() As Book
        Dim copy = ShallowCopy()
        copy.Authors = New List(Of Author)(Authors.Select(Function(a) New Author With {.Name = a.Name}))
        Return copy
    End Function

    Public Function CompareTo(other As Book) As Integer Implements IComparable(Of Book).CompareTo
        If other Is Nothing Then Return 1
        Return Year.CompareTo(other.Year)
    End Function

    Public Overrides Function ToString() As String
        Return Title & " (" & Year & ")"
    End Function
End Class

Module Program
    Sub Main()
        Dim original As New Book With {.Title = "Clean Code", .Year = 2008}
        original.Authors.Add(New Author With {.Name = "Robert C. Martin"})

        Dim shallow = original.ShallowCopy()
        Dim deep = original.DeepCopy()
        shallow.Title = "Changed"
        original.Authors(0).Name = "R. Martin"

        Console.WriteLine(original.ToString() & " | " & shallow.ToString() & " | " & deep.ToString())
        Console.WriteLine("shallow shares authors: " & (shallow.Authors Is original.Authors) & ", " & shallow.Authors(0).Name)
        Console.WriteLine("deep author: " & deep.Authors(0).Name)

        Console.WriteLine(original.GetType().FullName & " / " & GetType(Book).Name)
        Console.WriteLine(original.GetType() Is GetType(Book))

        Dim shelf As New List(Of Book) From {
            New Book With {.Title = "Refactoring", .Year = 1999},
            New Book With {.Title = "Clean Code", .Year = 2008},
            New Book With {.Title = "DDD", .Year = 2003}
        }
        shelf.Sort()
        Console.WriteLine(String.Join(" < ", shelf))
        shelf.Sort(Function(x, y) String.Compare(x.Title, y.Title, StringComparison.Ordinal))
        Console.WriteLine(String.Join(" < ", shelf))
    End Sub
End Module

Type tests and casts

An object can be treated as any of its base classes or interfaces. The conversion from derived to base is implicit; the other direction needs a check at run time.

Expression Behaviour

TypeOf x Is T

True if x is not Nothing and its type is T or derives from or implements T. Used in If, not in Select Case.

TryCast(x, T)

the object as T, or Nothing when it is not one; T must be a reference type (or nullable). Never throws.

DirectCast(x, T)

the object as T, or InvalidCastException. Fast, no user-defined conversions.

CType(x, T)

like DirectCast, but also runs defined conversions, such as numeric ones.

x.GetType()

the exact runtime type, for an equality test with GetType(T).

Case-insensitivity and name clashes

Names are not case sensitive, and a parameter hides a member of the same spelling. The most common consequence is in constructors and setters. With a field or property Name and a parameter name, the unqualified Name refers to the parameter (the innermost scope), so the statement Name = name assigns the parameter to itself. It compiles without a warning and silently loses the value. Use Me.Name = name, or give the fields an underscore prefix.

Option Strict On

Public Class ReaderBroken
    Public Property Name As String = "unset"

    Public Sub New(name As String)
        ' VB is case-insensitive: "Name" here is the parameter "name", so this assigns the parameter to itself.
        Name = name
    End Sub
End Class

Public Class ReaderFixed
    Public Property Name As String = "unset"

    Public Sub New(name As String)
        Me.Name = name
    End Sub
End Class

Module Program
    Sub Main()
        Console.WriteLine("without Me: " & New ReaderBroken("Ada").Name)
        Console.WriteLine("with Me   : " & New ReaderFixed("Ada").Name)
    End Sub
End Module
without Me: unset
with Me   : Ada

A local variable with the same name as its type is legal (Dim book As Book), and is the convention for a single object of a type. Because identifiers are not case sensitive, such a variable and the type differ only in context.

Pitfalls

  • Writing Name = name in a constructor with a parameter name: the field stays unset (use Me.Name or _name).

  • Forgetting that adding any Sub New removes the default parameterless constructor (BC30455 at the old New T() calls).

  • Calling an overridable method from a constructor: the derived class’s initializers have not run.

  • Comparing objects with = (BC30452) and then "fixing" it by comparing ToString() results; use Is for identity and override Equals and GetHashCode for value equality.

  • Using Is on strings or boxed numbers.

  • Relying on the defaults of access modifiers; Dim fields are Private, Sub is Public, nested types are Public.

  • A class with a Shared Sub New or Shared field initializer that can throw: the type is unusable after the first failure (TypeInitializationException).

  • Giving a Public member a Friend type (BC30909).

  • Using MyClass as a name; rename it or write [MyClass].

  • Accessing a Shared member through an instance (BC42025).

  • A shallow MemberwiseClone that shares collections with the original.

  • Hiding bugs by exposing public fields; use properties (see Properties and Default Properties).
