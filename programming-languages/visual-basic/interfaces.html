Interfaces

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is a complete console program that starts with Option Strict On, was built with warnings treated as errors and was run in the .NET 10 SDK container (Linux); the output shown is real output. The examples that are meant to fail say so, and show the compiler messages that the SDK printed. The examples use the root namespace ShelfDocs, which is why a few runtime messages show it. The project-level imports that the SDK adds (System, System.Collections.Generic, System.Linq and others) are why Console, List(Of T) and Enumerable methods need no Imports.

An interface is a contract: a named list of members (methods, properties, events) that a class or structure promises to provide, with no implementation and no state. Code that depends on the interface does not know, or care, which type is behind it. That makes interfaces the unit of substitution in Visual Basic: a unit test replaces a database store with an in-memory fake, the For Each statement walks any IEnumerable(Of T), List(Of T).Sort orders any type that implements IComparable(Of T), and a WPF or Windows Forms binding listens to anything that implements INotifyPropertyChanged. The running example is the shelf library catalogue, whose Catalog class talks to an ICatalogStore and never to a concrete store.

Visual Basic interfaces are the .NET interfaces, so what you know from C# carries over. The differences are in the syntax and they are worth learning precisely, because Visual Basic implements an interface explicitly by name, member by member, with the Implements clause. There is no implicit matching by name and signature as in C#, and no separate "explicit interface implementation" form: every implementation is explicit in that it names the member it implements, and a Private method can implement a member the way a C# explicit implementation does. Declaring an interface

[attributes] [accessmodifier] [Shadows] Interface Name [(Of typeparameters)]
    [Inherits InterfaceA, InterfaceB]

Source: Interface Statement

  • An interface can be declared at namespace level, or inside a class, structure, module or another interface. Without an access modifier a top-level interface is Friend (visible inside the assembly), so a contract that other assemblies must see is written Public Interface.

  • The members are Sub, Function, Property, Event and nested type declarations. A nested Enum and a nested Class compiled on 17.13 and are used as IShelf.Zone; use nested types sparingly, because they hide in the contract. Fields, constants, constructors and members with a body are not allowed in an interface. The fields and constants are rejected with BC30602, a body with BC30603 and a Sub New with BC30363 (see Errors the compiler reports).

  • Interface members are implicitly Public, and you must not write a modifier on them. Public, Shared, Overridable and MustOverride are each rejected with BC30270: the interface says what, the implementing type says how.

  • A property is declared with its shape only: Property Name As String (read/write), ReadOnly Property Name As String or WriteOnly Property Name As String. There is no Get/Set block. The implementing property may offer more than the interface asks for: a ReadOnly interface property can be implemented by a read/write property (the extra setter is just not reachable through the interface).

  • A parameter in an interface member is written exactly as in a class: ByVal/ByRef, Optional with a default, ParamArray. The implementation must have the same parameter types, modifiers (ByVal versus ByRef), return type and, for an Optional parameter, the same default value: an implementation that wrote Optional text As String = "b" for an interface member that says = "a", or that dropped Optional, is BC30401. The parameter names may differ (count in the interface, n in the class).

  • By convention the name starts with I (ICatalogStore, IComparable); the .NET design guidelines use that prefix for every interface, and Visual Basic code follows it.

A new interface with a few members, two implementations and a client:

Option Strict On

Public MustInherit Class CatalogItem
    Public Property Id As Integer
    Public Property Title As String = ""
    Public MustOverride ReadOnly Property Kind As String
End Class

Public Class Book
    Inherits CatalogItem

    Public Overrides ReadOnly Property Kind As String
        Get
            Return "Book"
        End Get
    End Property
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Overrides ReadOnly Property Kind As String
        Get
            Return "Magazine"
        End Get
    End Property
End Class

Public Interface ICatalogStore
    Function GetAll() As IReadOnlyList(Of CatalogItem)
    Sub Add(item As CatalogItem)
    Function Find(id As Integer) As CatalogItem
End Interface

Public Class InMemoryCatalogStore
    Implements ICatalogStore

    Private ReadOnly _items As New List(Of CatalogItem)

    Public Function GetAll() As IReadOnlyList(Of CatalogItem) Implements ICatalogStore.GetAll
        Return _items
    End Function

    Public Sub Add(item As CatalogItem) Implements ICatalogStore.Add
        _items.Add(item)
    End Sub

    Public Function Find(id As Integer) As CatalogItem Implements ICatalogStore.Find
        Return _items.FirstOrDefault(Function(item) item.Id = id)
    End Function
End Class

' A decorator: it is an ICatalogStore and it has one.
Public Class CountingCatalogStore
    Implements ICatalogStore

    Private ReadOnly _inner As ICatalogStore

    Public ReadOnly Property Calls As Integer

    Public Sub New(inner As ICatalogStore)
        _inner = inner
    End Sub

    Public Function GetAll() As IReadOnlyList(Of CatalogItem) Implements ICatalogStore.GetAll
        _Calls += 1
        Return _inner.GetAll()
    End Function

    Public Sub Add(item As CatalogItem) Implements ICatalogStore.Add
        _Calls += 1
        _inner.Add(item)
    End Sub

    Public Function Find(id As Integer) As CatalogItem Implements ICatalogStore.Find
        _Calls += 1
        Return _inner.Find(id)
    End Function
End Class

Public Class Catalog
    Private ReadOnly _store As ICatalogStore

    Public Sub New(store As ICatalogStore)
        _store = store
    End Sub

    Public Sub Add(item As CatalogItem)
        _store.Add(item)
    End Sub

    Public Function Count() As Integer
        Return _store.GetAll().Count
    End Function
End Class

Module Program
    Sub Main()
        Dim counting As New CountingCatalogStore(New InMemoryCatalogStore())
        Dim catalog As New Catalog(counting)

        catalog.Add(New Book With {.Id = 1, .Title = "Domain Modelling"})
        catalog.Add(New Magazine With {.Id = 2, .Title = "Shelf Monthly"})
        Console.WriteLine("items: " & catalog.Count())
        Console.WriteLine("calls on the decorator: " & counting.Calls)

        Dim store As ICatalogStore = counting
        Console.WriteLine("Find(2): " & store.Find(2).Title)
        Console.WriteLine("Find(9) is Nothing: " & (store.Find(9) Is Nothing))
        Console.WriteLine("calls now: " & counting.Calls)

        ' An interface variable lets the compiler check what may be called, nothing more.
        Console.WriteLine("variable type: " & store.GetType().Name)
        Console.WriteLine("is ICatalogStore: " & (TypeOf counting Is ICatalogStore))
        Dim asDisposable = TryCast(store, IDisposable)
        Console.WriteLine("is IDisposable: " & (asDisposable IsNot Nothing))
    End Sub
End Module

What the example shows:

  1. Catalog depends on ICatalogStore. Constructing it with a CountingCatalogStore that wraps an InMemoryCatalogStore required no change to Catalog. That is the decorator pattern, and it is possible because the decorator is also an ICatalogStore (see Design Patterns in Visual Basic).

  2. A variable declared As ICatalogStore exposes only the interface’s members plus the members of Object. The run-time type (store.GetType().Name) is still CountingCatalogStore, and TypeOf ... Is ICatalogStore and TryCast(store, IDisposable) test and convert at run time. TryCast returns Nothing when the object does not implement the interface; DirectCast throws InvalidCastException.

  3. Find(9) Is Nothing is True: the contract of Find is "returns Nothing when there is no such item". An interface cannot express that rule in the language, so write it in the XML documentation of the member (see XML Documentation, Analyzers and Code Style).

  4. _Calls += 1 increments the hidden backing field of the auto-property Calls. The field is named _Calls, with a leading underscore and the property’s spelling; it is accessible inside the class only. A ReadOnly auto-property needs no Set, and code inside the class can still assign to the backing field.

Implementing an interface

A class or structure promises a contract with the Implements statement, which is placed first in the type, after Inherits (if there is one) and before any member declaration. A type can name several interfaces, separated by commas or on several Implements lines.

Public Class Report
    Inherits ReportBase                    ' at most one base class, first
    Implements INamed, IExporter           ' any number of interfaces
    Implements IPrinter                    ' more can follow on another line
    ...
End Class

The Implements statement alone is not enough. The compiler then demands that the type contains, for every member of every interface named, a member that says it implements that interface member.

Program.vb(9,16): error BC30149: Class 'MemoryStore' must implement 'Function Count() As Integer' for interface 'ICatalogStore'.

Public Interface ICatalogStore
    Sub Add(title As String)
    Function Count() As Integer
End Interface

Public Class MemoryStore
    Implements ICatalogStore

    Public Sub Add(title As String) Implements ICatalogStore.Add
    End Sub
End Class

    Sub Main()
    End Sub
End Module

The message names the missing member with its full signature, which is exactly what you need to paste into the class. Visual Studio offers "Implement Interface" on the light bulb of the Implements line (or on the error) and writes every missing member with the clauses filled in.

The Implements clause

The member that implements an interface member says so with an Implements clause after its signature:

Public Sub Save() Implements IExporter.Export
Public Function Compare(x As Book, y As Book) As Integer Implements IComparer(Of Book).Compare
Public Property Name As String Implements INamed.Name
Public Event Changed As EventHandler Implements IShelfLabels.Changed

Source: Implements Clause

The rules, all of which the examples below demonstrate:

  • The member kind must match (Sub for a Sub, Function for a Function, Property for a Property, Event for an Event) and so must the parameters and the return type. A mismatch is BC30401.

  • The member name does not have to match. Save() above implements Export().

  • The accessibility does not matter to the compiler. A Public, Friend or Private member can implement an interface member. If it is Private, nobody can call it through the class, but a variable of the interface type reaches it. This is the Visual Basic counterpart of a C# explicit interface implementation.

  • One member can implement several interface members: Implements IPrinter.Print, IArchiver.Archive. The signatures of all of them must be compatible with the member.

  • One interface member can be implemented by only one member of a type. A second member that names the same interface member is BC30583.

  • A member that implements nothing is an ordinary member of the class.

  • For a member inherited from a base interface, the clause may name the interface that declares it (Implements IReadable.Read) or the derived interface that the type implements (Implements IStore.Read); both compile and map the same member.

  • Members that implement an interface member cannot be Shared (BC30505), and a Module cannot implement an interface at all (BC30231 and BC31083); an interface is implemented by instances.

  • A ReadOnly interface property can be implemented by a read/write property. The reverse does not compile: a read/write interface property implemented by a ReadOnly property is BC31444.

Option Strict On

Public Interface INamed
    Property Name As String
End Interface

Public Interface IExporter
    Sub Export()
    ReadOnly Property Format As String
End Interface

Public Interface IPrinter
    Sub Print()
End Interface

Public Interface IArchiver
    Sub Archive()
End Interface

Public Interface IAuditable
    Sub Audit()
End Interface

Public Class Report
    Implements INamed, IExporter, IPrinter, IArchiver, IAuditable

    ' An auto-property can implement an interface property.
    Public Property Name As String = "Quarterly loans" Implements INamed.Name

    ' A ReadOnly interface property can be implemented by a read/write property.
    Public Property Format As String = "csv" Implements IExporter.Format

    ' The method name does not have to match the interface member name.
    Public Sub Save() Implements IExporter.Export
        Console.WriteLine("exporting '" & Name & "' as " & Format)
    End Sub

    ' One method can implement members of several interfaces.
    Public Sub Output() Implements IPrinter.Print, IArchiver.Archive
        Console.WriteLine("Output called")
    End Sub

    ' A Private method can implement a member: only the interface can reach it.
    Private Sub AuditEntry() Implements IAuditable.Audit
        Console.WriteLine("audited " & Name)
    End Sub
End Class

Module Program
    Sub Main()
        Dim report As New Report()
        Dim exporter As IExporter = report
        Dim printer As IPrinter = report
        Dim archiver As IArchiver = report
        Dim named As INamed = report
        Dim auditable As IAuditable = report

        named.Name = "Overdue loans"
        exporter.Export()
        printer.Print()
        archiver.Archive()
        auditable.Audit()

        report.Save()
        report.Output()
        Console.WriteLine(named.Name & " / " & exporter.Format)
    End Sub
End Module

Output called
Output called
audited Overdue loans
exporting 'Overdue loans' as csv
Output called
Overdue loans / csv

Source: Implements Clause

Read the output in three parts. The first four lines are the calls made through the interface variables (exporter.Export() reaches Save, printer.Print() and archiver.Archive() both reach Output, auditable.Audit() reaches the Private AuditEntry; named.Name = ... wrote through INamed, which is why Save prints the new name). Lines five and six are the calls made on the class variable, report.Save() and report.Output(). The last line reads the property through the two interfaces. AuditEntry cannot be called through report: the compiler reports BC30390 (the member is Private), and report.Audit() is BC30456 because the class has no member of that name.

A mapping you can inspect

The mapping from the interface member to the implementing member is recorded in the compiled type and is available to reflection through Type.GetInterfaceMap. A program that prints the map for the Private AuditEntry above printed:

interface: Audit
target   : AuditEntry private=True virtual=True final=True

The implementing method keeps its own name (AuditEntry), unlike a C# explicit implementation, whose method name includes the interface name. It is Private, virtual and final (sealed): not reachable by name, still dispatched through the interface, and not overridable by a derived class unless that class re-implements the interface (see Dispatch and re-implementation).

Name clashes and several interfaces

Two interfaces can declare the same member name with the same signature. With C#, that is the textbook reason to use an explicit implementation. With Visual Basic the clause already names the interface, so the clash resolves itself: give each interface member its own implementing method, or let one method serve both.

Option Strict On

Public Interface ILender
    Sub [Return]()
End Interface

Public Interface IReturnable
    Sub [Return]()
End Interface

' Two interfaces declare a member with the same signature. The class
' picks, member by member, what each interface member runs.
Public Class Loan
    Implements ILender, IReturnable

    Public Sub LenderReturn() Implements ILender.Return
        Console.WriteLine("lender side: book is back on the shelf")
    End Sub

    Public Sub BorrowerReturn() Implements IReturnable.Return
        Console.WriteLine("borrower side: receipt printed")
    End Sub

    ' Not an implementation of anything: it is just a method called Return.
    Public Sub [Return]()
        Console.WriteLine("Loan.Return called through the class")
    End Sub
End Class

Public Class SimpleLoan
    Implements ILender, IReturnable

    ' One method can serve both members when the behaviour is the same.
    Public Sub [Return]() Implements ILender.Return, IReturnable.Return
        Console.WriteLine("SimpleLoan.Return")
    End Sub
End Class

Module Program
    Sub Main()
        Dim loan As New Loan()
        DirectCast(loan, ILender).Return()
        DirectCast(loan, IReturnable).Return()
        loan.Return()

        Dim simple As New SimpleLoan()
        Dim lender As ILender = simple
        Dim returnable As IReturnable = simple
        lender.Return()
        returnable.Return()
    End Sub
End Module
lender side: book is back on the shelf
borrower side: receipt printed
Loan.Return called through the class
SimpleLoan.Return
SimpleLoan.Return

Source: Implements Clause

Three things are visible here. Return is a reserved word, so a member with that name is written [Return] in the declaration (and Return after a dot, where the context makes it a name). Loan has three different methods, and which one runs depends on the type of the expression, not on the object. And SimpleLoan shows the one-method-for-two-members form, which is correct when the two interfaces mean the same thing by the member.

Interface inheritance and name clashes

An interface can inherit one or more interfaces with the Inherits statement inside the interface body. (A class has at most one base class, an interface has any number of base interfaces; that is the one place where Visual Basic has multiple inheritance.) A type that implements the derived interface implements every base interface too, and the Implements clause of a member that comes from a base interface names the interface that declares it.

Option Strict On

Public Interface IReadable
    Function Read(id As Integer) As String
End Interface

Public Interface IWritable
    Sub Write(id As Integer, text As String)
End Interface

' An interface can inherit several interfaces. Implementing it means implementing all members.
Public Interface IReadWriteStore
    Inherits IReadable, IWritable

    ReadOnly Property Count As Integer
End Interface

Public Class DictionaryStore
    Implements IReadWriteStore

    Private ReadOnly _data As New Dictionary(Of Integer, String)

    Public ReadOnly Property Count As Integer Implements IReadWriteStore.Count
        Get
            Return _data.Count
        End Get
    End Property

    ' The inherited members are named after the interface that declares them.
    Public Function Read(id As Integer) As String Implements IReadable.Read
        Dim text As String = Nothing
        Return If(_data.TryGetValue(id, text), text, "(missing)")
    End Function

    Public Sub Write(id As Integer, text As String) Implements IWritable.Write
        _data(id) = text
    End Sub
End Class

Module Program
    Sub Show(source As IReadable, id As Integer)
        Console.WriteLine(id & " -> " & source.Read(id))
    End Sub

    Sub Fill(target As IWritable)
        target.Write(1, "Domain Modelling")
        target.Write(2, "Shelf Monthly")
    End Sub

    Sub Main()
        Dim store As IReadWriteStore = New DictionaryStore()
        Fill(store)                 ' IReadWriteStore widens to IWritable
        Show(store, 1)              ' ... and to IReadable
        Show(store, 3)
        Console.WriteLine("count: " & store.Count)

        ' The inherited members are available through the derived interface.
        Console.WriteLine(store.Read(2))

        ' Narrowing needs a cast, and the cast can fail.
        Dim readOnlyView As IReadable = store
        Dim writable = TryCast(readOnlyView, IWritable)
        Console.WriteLine("back to IWritable: " & (writable IsNot Nothing))
    End Sub
End Module
1 -> Domain Modelling
3 -> (missing)
count: 2
Shelf Monthly
back to IWritable: True

Source: Inherits Statement

  • A derived interface converts implicitly to each of its base interfaces (IReadWriteStore to IReadable and IWritable). The opposite direction needs a cast: TryCast(readOnlyView, IWritable) returns Nothing when the object does not implement it.

  • Inherits must be the first statement in the body. A type that implements the derived interface does not have to repeat the base interfaces in its own Implements statement.

  • An interface cannot inherit from itself, directly or indirectly (the compiler reports a cycle).

When two base interfaces declare a member with the same name, a call through the derived interface is ambiguous. The compiler reports BC30521 on the call and the program does not build. The remedies are a cast to the interface that declares the member you mean, or Shadows on a new member in the derived interface that hides both:

Option Strict On

Public Interface IReadable
    ReadOnly Property Name As String
End Interface

Public Interface IWritable
    ReadOnly Property Name As String
End Interface

' Inheriting two interfaces with a member of the same name makes a call on the derived interface ambiguous.
Public Interface IReadWrite
    Inherits IReadable, IWritable
End Interface

' Shadows declares a new member that hides both inherited ones.
Public Interface IShadowedReadWrite
    Inherits IReadable, IWritable

    Shadows ReadOnly Property Name As String
End Interface

Public Class Store
    Implements IReadWrite, IShadowedReadWrite

    Private ReadOnly Property ReadName As String Implements IReadable.Name
        Get
            Return "read side"
        End Get
    End Property

    Private ReadOnly Property WriteName As String Implements IWritable.Name
        Get
            Return "write side"
        End Get
    End Property

    Private ReadOnly Property BothName As String Implements IShadowedReadWrite.Name
        Get
            Return "shadowing member"
        End Get
    End Property
End Class

Module Program
    Sub Main()
        Dim store As New Store()

        Dim ambiguous As IReadWrite = store
        ' ambiguous.Name is BC30521. Convert to the interface that declares the member you mean.
        Console.WriteLine(DirectCast(ambiguous, IReadable).Name)
        Console.WriteLine(DirectCast(ambiguous, IWritable).Name)

        Dim shadowed As IShadowedReadWrite = store
        Console.WriteLine(shadowed.Name)
        Console.WriteLine(DirectCast(shadowed, IReadable).Name)
    End Sub
End Module

write side

Dispatch and re-implementation

An interface call is virtual: the runtime finds the method that the object’s type mapped to the interface member. If the implementing member is Overridable, a derived class can override it and the interface call reaches the override, exactly as with an ordinary virtual method. But a derived class can also hide the implementing member with Shadows, and then two different things can happen, depending on whether the derived class re-implements the interface by repeating Implements.

Option Strict On

Public Interface IDescribable
    Function Describe() As String
End Interface

Public Class CatalogItem
    Implements IDescribable

    ' Overridable: the interface call is dispatched to the most derived override.
    Public Overridable Function Describe() As String Implements IDescribable.Describe
        Return "CatalogItem.Describe"
    End Function

Structures that implement interfaces

A structure can implement interfaces (Isbn of the shelf implements IEquatable(Of Isbn)). Converting a structure to an interface type boxes it: the common language runtime copies the value into a new object on the heap and the interface variable refers to that copy. Calls through the interface mutate the copy.

Option Strict On

Public Interface ICounter
    Sub Increment()
    ReadOnly Property Value As Integer
End Interface

Public Structure Counter
    Implements ICounter

    Private _value As Integer

    Public Sub Increment() Implements ICounter.Increment
        _value += 1
    End Sub

    Public ReadOnly Property Value As Integer Implements ICounter.Value
        Get
            Return _value
        End Get
    End Property
End Structure

Module Program
    Sub Main()
        Dim a As New Counter()
        a.Increment()
        Console.WriteLine("a.Value after a.Increment(): " & a.Value)

        ' Converting to the interface boxes a copy of the structure.
        Dim boxed As ICounter = a
        boxed.Increment()
        boxed.Increment()
        Console.WriteLine("boxed.Value after two calls: " & boxed.Value)
        Console.WriteLine("a.Value is unchanged:       " & a.Value)

        ' Two boxes are two copies; assigning a box copies the reference, not the structure.
        Dim alias1 As ICounter = boxed
        alias1.Increment()
        Console.WriteLine("boxed.Value through the alias: " & boxed.Value)

        ' A constrained generic call does not box.
        Dim b As New Counter()
        Bump(b)
        Console.WriteLine("b.Value after Bump(Of T) with ByRef: " & b.Value)
    End Sub

    Sub Bump(Of T As {Structure, ICounter})(ByRef counter As T)
        counter.Increment()
    End Sub
End Module

boxed.Value after two calls: 3
a.Value is unchanged:       1
boxed.Value through the alias: 4
b.Value after Bump(Of T) with ByRef: 1

Read the output line by line. a is incremented once, so a.Value is 1. boxed = a copies a (value 1) into a box; two increments through the box make it 3, while a stays 1. Assigning boxed to alias1 copies the reference to the same box, so the increment through alias1 shows through boxed (4). The generic method Bump constrained with As {Structure, ICounter} takes the argument ByRef and calls the interface member on the original structure without boxing it, which is the way to keep a mutable structure mutable behind an interface. Mutable structures remain a design smell; the better answer is an immutable structure with methods that return a new value (see Structures and Value Types).

Two practical consequences:

  • A generic algorithm over T As IComparable(Of T) does not box when T is a structure, because the JIT compiles a separate version for each structure type and calls the interface method directly. The same algorithm over a variable declared As IComparable(Of T) boxes every element.

  • A For Each over a List(Of T) uses the structure enumerator List(Of T).Enumerator, not IEnumerator(Of T), and does not box; through an IEnumerable(Of T) variable the same loop does.

Generic interfaces and variance

An interface can have type parameters with constraints, exactly like a class (see Generics). The constraint T As CatalogItem of IRepository is checked wherever the interface is closed: IRepository(Of String) does not compile. A type can implement the same generic interface several times with different type arguments, as long as each closed interface is distinct.

An interface type parameter may be marked Out (covariant: it appears only in return positions) or In (contravariant: it appears only in parameters). Variance is allowed for interfaces and delegates, never for classes or structures. The compiler checks the declaration and, under Option Strict On, converts between closed types that differ by variance without a cast.

Three conversions are demonstrated. A GetAll() returning IEnumerable(Of Book) is assignable to an IEnumerable(Of CatalogItem) because IEnumerable(Of Out T) is covariant. A BookProducer (an IProducer(Of Book)) is assignable to IProducer(Of CatalogItem) because Out T allows widening. An ItemPrinter, which prints any CatalogItem, is usable where an IPrinter(Of Book) is wanted because In T allows narrowing. The line that the example comments out, assigning an IRepository(Of Book) to an IRepository(Of CatalogItem), is invalid because IRepository(Of T) has T in both an input (Add) and an output (GetAll) position, so it is invariant. The compiler reports it as BC36757 and, helpfully but misleadingly, suggests Out T:

Program.vb(17,52): error BC36757: 'IRepository(Of Book)' cannot be converted to 'IRepository(Of CatalogItem)'. Consider changing the 'T' in the definition of 'Interface IRepository(Of T)' to an Out type parameter, 'Out T'.

That program declared IRepository(Of T) without constraints and with an Add(item As T) member, which is why Out T could not be applied to it: a covariant T may appear only in output positions. The suggestion is generic and does not check the interface. Arrays are covariant too (a Book() converts to a CatalogItem()), but a store into such an array can fail at run time with ArrayTypeMismatchException; the generic interfaces are checked at compile time instead.

IComparable, IEquatable and IComparer

An ordering and an equality both belong with the type, and a second ordering belongs in a separate comparer. IComparable(Of T).CompareTo returns a negative number, zero or a positive number; it must be consistent with IEquatable(Of T).Equals (two objects that compare as zero should be equal) and with GetHashCode (equal objects must produce equal hashes). Visual Basic overloads Equals: the typed Equals(other As Book) implements the interface and needs Overloads, and the Overrides of Equals(Object) delegates to it (see Operator Overloading and Equality).

Option Strict On

Public Class Book
    Implements IComparable(Of Book), IEquatable(Of Book), IComparable

    Public ReadOnly Property Title As String
    Public ReadOnly Property Year As Integer

    Public Sub New(title As String, year As Integer)
        Me.Title = title
        Me.Year = year
    End Sub

    ' Natural order: by title, ignoring case.
    Public Function CompareTo(other As Book) As Integer Implements IComparable(Of Book).CompareTo
        If other Is Nothing Then Return 1
        Return String.Compare(Title, other.Title, StringComparison.OrdinalIgnoreCase)
    End Function

    ' The non-generic interface is still used by older APIs.
    Private Function CompareToObject(obj As Object) As Integer Implements IComparable.CompareTo
        Dim other = TryCast(obj, Book)
        If obj IsNot Nothing AndAlso other Is Nothing Then
            Throw New ArgumentException("Object must be a Book.", NameOf(obj))
        End If
        Return CompareTo(other)
    End Function

    Public Overloads Function Equals(other As Book) As Boolean Implements IEquatable(Of Book).Equals
        Return other IsNot Nothing AndAlso
               String.Equals(Title, other.Title, StringComparison.OrdinalIgnoreCase) AndAlso
               Year = other.Year
    End Function

    Public Overrides Function Equals(obj As Object) As Boolean
        Return Equals(TryCast(obj, Book))
    End Function

    Public Overrides Function GetHashCode() As Integer
        Return HashCode.Combine(Title.ToLowerInvariant(), Year)
    End Function

    Public Overrides Function ToString() As String
        Return Title & " (" & Year & ")"
    End Function
End Class

Public Class ByYearThenTitle
    Implements IComparer(Of Book)

    Public Function Compare(x As Book, y As Book) As Integer Implements IComparer(Of Book).Compare
        Dim byYear = x.Year.CompareTo(y.Year)
        Return If(byYear <> 0, byYear, x.CompareTo(y))
    End Function
End Class

  • HashSet(Of Book).Contains(New Book("SHELF DESIGN", 2021)) is True because Equals(Book) ignores case and GetHashCode hashes the lower-case title: the two methods agree. A hash code that included the title with its original case would make the lookup fail even though Equals returns True.

  • The Private IComparable.CompareTo(Object) throws ArgumentException for an object of another type, which is the contract of the non-generic interface. Private is correct for it, since it is not part of the type’s usual API.

IEnumerable(Of T)

Implement IEnumerable(Of T) to make a type usable in For Each and LINQ. In Visual Basic an Iterator function (see Iterators and Yield) writes the enumerator for you. The generic interface inherits the non-generic IEnumerable, so both GetEnumerator methods are needed: the generic one is the iterator, the non-generic one is a Private method that forwards to it.

Option Strict On

Public Class Bookshelf
    Implements IEnumerable(Of String)

        Next

IDisposable

IDisposable has one method, Dispose. A Using statement calls it when the block ends, even after an exception, for any variable whose type implements it. The pattern for a type that owns only managed resources is shown below: Dispose is idempotent, and members check the disposed state.

Option Strict On

Public Class ReportWriter
    Implements IDisposable

    Private _disposed As Boolean
    Private ReadOnly _name As String

    Public Sub New(name As String)
        _name = name
        Console.WriteLine("open " & _name)
    End Sub

    Public Sub Write(line As String)
        ObjectDisposedException.ThrowIf(_disposed, Me)
        Console.WriteLine(_name & ": " & line)
    End Sub

    Public Sub Dispose() Implements IDisposable.Dispose
        If _disposed Then Return
        _disposed = True
        Console.WriteLine("close " & _name)
        GC.SuppressFinalize(Me)
    End Sub
End Class

Module Program
    Sub Main()
        Dim kept As ReportWriter
        Using writer As New ReportWriter("loans.txt")
            writer.Write("3 loans overdue")
            kept = writer
        End Using

        kept.Dispose()                    ' calling Dispose again must be harmless
        Try
            kept.Write("too late")
        Catch ex As ObjectDisposedException
            Console.WriteLine(ex.GetType().Name & ": " & ex.ObjectName)
        End Try

        ' Using accepts any expression whose type implements IDisposable, also an interface type.
        Dim disposable As IDisposable = New ReportWriter("audit.txt")
        Using disposable
            Console.WriteLine("working through IDisposable")
        End Using
    End Sub
End Module

INotifyPropertyChanged

INotifyPropertyChanged has a single event, PropertyChanged. The implementation declares the event with its delegate type and an Implements clause; the Event statement can name the delegate type (PropertyChangedEventHandler) instead of a parameter list. An observer attaches to the interface event with AddHandler, which also works when the class variable is not available. The CallerMemberName attribute (see Attributes, Caller Info and Reflection) supplies the property name, so a typo cannot slip into a string.

Interfaces from C#

C# has added two features to interfaces that Visual Basic only consumes: default interface members (an interface method with a body) and static abstract members (a contract on the type itself, the basis of generic math). Visual Basic’s strategy is to consume new .NET features, not to extend its own syntax (see History, Versions and Language Strategy). The results of the experiments are below; the library is a C# project with an interface that has a default method and a second interface with a static abstract member:

namespace CsShelf;

public interface IShelfLabel

Designing with interfaces

  • Interface or base class? An interface is the right tool for a role that unrelated types play (IDisposable, ICatalogStore) or when a type needs several roles. A base class (MustInherit) is right when the types share state and implementation and form a hierarchy (CatalogItem and Book). The two combine well: an interface for clients, a MustInherit helper class that implements it for convenience, and implementations free to ignore the helper. See Inheritance and Polymorphism.

  • Small interfaces. ICatalogStore has three members. Clients that only read should depend on a smaller IReadOnlyCatalog, so a read-only fake or a cached view can implement it. This is the interface segregation principle; when a class implements an interface of ten members to supply one, split the interface.

  • Depend on the interface at the boundary. Constructor parameters, fields and return types name the interface (ICatalogStore, IReadOnlyList(Of CatalogItem)); the one place that says New InMemoryCatalogStore() is the composition root. The dependency injection container of Microsoft.Extensions.DependencyInjection registers AddSingleton(Of ICatalogStore, InMemoryCatalogStore)() and then resolves a Catalog (see Design Patterns in Visual Basic).

  • Test with fakes. Because Catalog takes an ICatalogStore, a unit test passes a small class or a library-generated mock; see Testing.

  • Do not change a published interface. Adding a member breaks every implementer outside your control. In C# a default interface member can soften that; Visual Basic cannot write one, so version a contract by adding a new interface that inherits the old one (ICatalogStore2 Inherits ICatalogStore) and test with TypeOf store Is ICatalogStore2.

  • Naming. I prefix, PascalCase, no Hungarian prefixes; an interface that names a capability uses an adjective (IComparable, IDisposable), a role uses a noun (ICatalogStore).

  • Trimming and Native AOT. Code that discovers implementers by reflection (Type.GetInterfaces, Assembly.GetTypes) depends on metadata that trimming may remove; code that names the interface and its implementers statically does not.

  • Not interfaces. A Delegate fits a contract of one method better (see Delegates and Lambda Expressions), and an Enum or a MustInherit class fits a closed set of alternatives.

Older material you may meet

  • Visual Basic 6 and VBA have Implements as well, with a convention rather than a clause: the implementing procedure must be called InterfaceName_MemberName (IShelfLabel_Text), the interface is another class module whose methods are empty, and a class can implement an interface but cannot inherit a class. In Visual Basic .NET the method can have any name and the clause says which member it implements. Ported code usually keeps the underscored names and gains an Implements clause. See The VB Family: VB6, VBA and VBScript.

  • Older .NET Framework samples use the non-generic IComparable, IEnumerable and ICollection with ArrayList and Object elements, and ICloneable for copies. Today, implement the generic interfaces (IComparable(Of T), IEnumerable(Of T)) and give the non-generic ones a Private forwarding implementation only when an old API needs it.

  • Older INotifyPropertyChanged samples raise the event with a string literal in every setter (RaiseEvent PropertyChanged(Me, New PropertyChangedEventArgs("Title"))). CallerMemberName removes the literals, and a renamed property can no longer leave a stale name behind.

  • The "interface or abstract class" advice in older material predates default interface members. Visual Basic still cannot declare them, but it can consume them (see Interfaces from C#), so a library written in C# can add a member to an interface without breaking Visual Basic callers, while a Visual Basic class that implements it must still write the member.

  • The interface rules are the same on .NET Framework 4.x and on .NET 10 for Visual Basic. Default interface members are a runtime feature of .NET Core 3.0 and later, so a .NET Framework application cannot run a library that uses them.
