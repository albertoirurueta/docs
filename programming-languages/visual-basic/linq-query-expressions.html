LINQ and Query Expressions

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is a complete console program that starts with Option Strict On, was built with warnings treated as errors (except where the text says a warning is the subject) and was run in the .NET 10 SDK container (Linux); the output shown is real output. The examples that are meant to fail say so and show the compiler messages that the SDK printed, with the file path removed. The project-level imports that the SDK adds (System, System.Collections.Generic, System.Linq and others) are why List(Of T) and the query operators need no Imports line; System.Data and System.Linq.Expressions are imported where they are used. To keep every program self-contained, the examples declare small Book, Author and Loan classes with the members they need, instead of referencing the full shelf domain model; the names and the data follow the shelf library catalogue.

Language Integrated Query (LINQ) puts a declarative query language into the language itself: the same From ... Where ... Select text works over arrays, lists, XML trees, DataTable rows and, through other providers, databases. A query expression is not a separate engine. The compiler translates every clause into a call of a query operator method (Where, Select, OrderBy and so on) that is looked up by name on the source, and the arguments are lambda expressions built from the clause text. What that call returns, and when the work happens, is decided by the method that is found, which is the reason the same syntax can be a lazy in-memory pipeline over IEnumerable(Of T) or a SQL statement over IQueryable(Of T).

Visual Basic had LINQ from the start. It arrived with Visual Basic 9 and Visual Studio 2008, together with local type inference, anonymous types, extension methods, lambda expressions and XML literals (see XML Literals and Axis Properties). Its query syntax is richer than C#'s: Aggregate, Distinct, Skip, Take, Skip While, Take While and Group By ... Into are query clauses in Visual Basic, and they have no query-syntax counterpart in C#, where they exist only as method calls. The method-based operators of System.Linq are shared and are the same in both languages; the C# reference covers them in LINQ in C#.

Rules shared by all clauses:

  • A query has exactly one first clause, which is From or Aggregate. Every later clause works on the range variables that are still in scope.

  • Clauses may be repeated and, unlike in C#, mostly reordered: Select can come before Where, and a query can contain several Select, Where and Order By clauses. A Select is optional; without one the query returns the range variable itself.

  • The query is one logical line. Line breaks are allowed before each clause keyword, and the example listings use that to put one clause per line (see Program Structure and Code Conventions).

  • A query cannot contain statements, only expressions. Any ByRef parameter used in a query is rejected (BC36533, shown below).

The clause pipeline

The sections below follow the pipeline. The first example is a complete query next to the same query in method syntax; the two are the same program for the compiler, which SequenceEqual confirms (the Key keywords the method form needs are explained in the section on anonymous types).

Public Class Book
    Public Property Title As String
    Public Property Author As String
    Public Property Year As Integer
    Public Property Pages As Integer
    Public Property Genre As String

        Me.Author = author
        Me.Year = year
        Me.Pages = pages
        Me.Genre = genre
    End Sub
End Class

Module Program
    Function Library() As List(Of Book)
        Return New List(Of Book) From {
            New Book("Dune", "Frank Herbert", 1965, 412, "Science fiction"),
            New Book("Emma", "Jane Austen", 1815, 474, "Novel"),
            New Book("Neuromancer", "William Gibson", 1984, 271, "Science fiction"),
            New Book("Persuasion", "Jane Austen", 1817, 249, "Novel"),
            New Book("Hyperion", "Dan Simmons", 1989, 482, "Science fiction"),
            New Book("Ulysses", "James Joyce", 1922, 730, "Novel")
        }
    End Function

    Sub Main()
        Dim books = Library()

        ' Query syntax: From, Where, Order By, Select
        Dim recent = From b In books
                     Where b.Year > 1900 AndAlso b.Genre = "Science fiction"
                     Order By b.Year Descending
                     Select b.Title, b.Year

        For Each r In recent
            Console.WriteLine(r.Title & " (" & r.Year & ")")
        Next

        ' The same query in method syntax
        Dim sameQuery = books.
            Where(Function(b) b.Year > 1900 AndAlso b.Genre = "Science fiction").
            OrderByDescending(Function(b) b.Year).
            Select(Function(b) New With {Key b.Title, Key b.Year})

        Console.WriteLine(recent.SequenceEqual(sameQuery))
    End Sub

Range variables, type inference and the type of a query

From b In books is neither an assignment nor a loop. It declares b as the range variable of the query: it stands for one element at a time and is typed from the element type of books (here Book). The source can be anything that has the query operator methods in scope, which in practice means IEnumerable(Of T) (through the extension methods of System.Linq.Enumerable), IQueryable(Of T) (through System.Linq.Queryable) and any type that supplies its own methods. A type that is not queryable produces BC36593, as shown below.

The query result is an unexecuted query object. Its static type is rarely worth writing out: with Select b.Title, b.Year it is an IEnumerable of a compiler-generated anonymous type that has no name, so the declaration must rely on local type inference. That is the reason Option Infer On (the SDK default; see Option Statements) is practically a requirement for query code. With Option Infer Off and Option Strict On the same declaration is rejected:

Option Strict On
Option Infer Off

    Sub Main()
        Dim numbers As New List(Of Integer)
        Dim q = From n In numbers Select n
    End Sub
End Module

A query whose Select returns an existing type has a nameable type, IEnumerable(Of T), and may be assigned to a variable declared with it; with a Select of several members it cannot be.

Filtering, ordering, projecting and trimming

Where takes any Boolean expression, and AndAlso and OrElse short-circuit inside it as everywhere else. Order By takes a comma-separated list of keys, each optionally followed by Ascending (the default) or Descending; the sort is stable, so equal keys keep their source order. Select can be followed by the trimming clauses Distinct, Skip, Take, Skip While and Take While. The next program shows each clause on one small data set; every For Each or String.Join runs the query at that moment.

Option Strict On

Public Class Book
    Public Property Title As String
    Public Property Author As String
    Public Property Year As Integer
    Public Sub New(title As String, author As String, year As Integer)
        Me.Title = title
        Me.Author = author
        Me.Year = year
    End Sub
End Class

Module Program
    Sub Main()
        Dim books As New List(Of Book) From {
            New Book("Emma", "Jane Austen", 1815),
            New Book("Persuasion", "Jane Austen", 1817),
            New Book("Dune", "Frank Herbert", 1965),
            New Book("Ulysses", "James Joyce", 1922),
            New Book("Dubliners", "James Joyce", 1914),
            New Book("Neuromancer", "William Gibson", 1984)
        }

        Console.WriteLine("-- Order By author, then year descending")
        For Each b In From x In books Order By x.Author, x.Year Descending Select x
            Console.WriteLine(b.Author & " / " & b.Year & " / " & b.Title)
        Next

        Console.WriteLine("-- Distinct authors")
        Console.WriteLine(String.Join("; ", From b In books Select b.Author Distinct))

        Console.WriteLine("-- Skip 1, Take 3 over Order By Year")
        Console.WriteLine(String.Join("; ", From b In books Order By b.Year Select b.Title Skip 1 Take 3))

        Console.WriteLine("-- Skip While year < 1960 (in source order)")
        Console.WriteLine(String.Join("; ", From b In books Skip While b.Year < 1960 Select b.Title))

        Console.WriteLine("-- Take While year < 1960 (stops at the first failure)")
        Console.WriteLine(String.Join("; ", From b In books Take While b.Year < 1960 Select b.Title))

        Console.WriteLine("-- Where after Select, with the projected name")
        Console.WriteLine(String.Join("; ", From b In books Select b.Title, b.Year Where Year > 1950 Select Title))
    End Sub
End Module

Points worth remembering from that program:

  • Skip While and Take While test the elements in source order and stop testing at the first element that decides the matter. With Skip While b.Year < 1960 the prefix Emma and Persuasion is dropped, and everything after Dune is kept, even Ulysses (1922) and Dubliners (1914), which are older than 1960. Take While b.Year < 1960 is the mirror image: it ends the result at Dune and never examines the older books after it. Neither is a filter; use Where for that.

  • Skip and Take are clauses, not methods, and apply to the query as written so far. Written after Order By, they page the sorted sequence; written before it, they would cut the unsorted sequence.

  • Distinct compares the projected elements. With a single member it compares values; with several members it compares the anonymous-type instances, whose equality depends on the Key properties (explained below).

  • A Where may follow a Select. The projected names (Title, Year) are then the range variables for the later clauses and the original b is no longer visible.

Deferred and immediate execution

Defining a query does not run it. The query object holds the source reference and the lambdas; the work happens when something asks for the elements: a For Each, String.Join, ToList(), ToArray(), Count(), First(), Aggregate and every other operator that returns a value rather than a sequence. Two consequences follow, and the program shows both. First, a query that is enumerated twice does its work twice. Second, a query sees the source and the captured variables as they are when it runs, not as they were when it was written.

Option Strict On

Module Program
    Sub Main()
        Dim numbers As New List(Of Integer) From {1, 2, 3}

        ' Deferred: nothing runs here
        Dim evens = From n In numbers
                    Where n Mod 2 = 0
                    Select n

        ' Immediate: ToList, Count(), Sum() and friends run the query now
        Dim snapshot = evens.ToList()
        Dim total = (From n In numbers Select n).Sum()

        numbers.Add(4)
        numbers.Add(6)

        Console.WriteLine("snapshot: " & String.Join(",", snapshot))
        Console.WriteLine("evens   : " & String.Join(",", evens))
        Console.WriteLine("total   : " & total)

        ' A query sees the variables it captures when it runs, not when it is written
        Dim limit As Integer = 3
        Dim small = From n In numbers Where n <= limit Select n
        limit = 4
        Console.WriteLine("limit 4 : " & String.Join(",", small))

        ' Tracing the pipeline: each element flows through all stages before the next one starts
        Dim traced = From n In numbers.Where(Function(x)
                                                 Console.WriteLine("  where  " & x)
                                                 Return x > 2
                                             End Function)
                     Select Doubled = Doubler(n)

        Console.WriteLine("query defined, nothing traced yet")
        For Each d In traced
            Console.WriteLine("got " & d)
        Next
    End Sub

    Function Doubler(n As Integer) As Integer
        Console.WriteLine("  select " & n)
        Return n * 2
    End Function
End Module

The trace at the end of the output also shows how the pipeline works: the operators are stacked iterators, so each element travels through Where and Select before the next element is touched. Nothing is buffered between them, except by the operators that must see everything before they can emit anything: Order By, Group By, the inner side of Join and Group Join, and Reverse. That is why a pipeline of Where and Select can start returning results immediately, while the first result of an Order By is available only after the whole source has been read.

Execution style Operators and keywords

Deferred, streaming

Where, Select, Skip, Take, Skip While, Take While, Distinct, Let, the second From of a flattening query (SelectMany), Concat, Zip, Union

Deferred, buffering

Order By, Group By, Join and Group Join (their inner source), Except and Intersect (their second source), Reverse

Immediate (returns a value)

Aggregate ... Into, Count(), Sum(), Min(), Max(), Average(), Any(), All(), First(), Single(), Last(), ElementAt(), Contains()

Immediate (materialises a collection)

ToList(), ToArray(), ToDictionary(), ToHashSet(), ToLookup()

The classic pitfalls of deferral are the next program: running a query several times, modifying the source while it is being enumerated, and calling an operator that needs an element on an empty sequence. Sum of nothing is 0, but Max, Min and Average of a sequence of non-nullable values have no answer and throw InvalidOperationException; use FirstOrDefault, DefaultIfEmpty or a nullable projection when emptiness is possible.

Option Strict On

Module Program
    Sub Main()
        Dim names As New List(Of String) From {"emma", "dune"}

        ' 1. Multiple enumeration runs the query again
        Dim runs As Integer = 0
        Dim q = From n In names
                Let counted = Tick(runs)
                Select n.ToUpper()
        Console.WriteLine(q.Count() & " " & q.Count() & " runs=" & runs)

        ' 2. Changing the source while a query is being enumerated
        Try
            For Each n In From x In names Select x
                names.Add(n & "2")
            Next
        Catch ex As InvalidOperationException
            Console.WriteLine("modify while iterating: " & ex.Message)
        End Try

        ' 3. First/Single/Max on an empty sequence
        Dim empty = From n In New List(Of Integer) Select n
        Try
            Console.WriteLine(empty.First())
        Catch ex As InvalidOperationException
            Console.WriteLine("First : " & ex.Message)
        End Try
        Try
            Console.WriteLine(Aggregate n In empty Into Max())
        Catch ex As InvalidOperationException
            Console.WriteLine("Max   : " & ex.Message)
        End Try
        Console.WriteLine("Sum of nothing: " & Aggregate n In empty Into Sum())
        Try
            Console.WriteLine(Aggregate n In empty Into Average())
        Catch ex As InvalidOperationException
            Console.WriteLine("Average: " & ex.Message)
        End Try
    End Sub

    Function Tick(ByRef runs As Integer) As Integer
        runs += 1
        Return runs
    End Function
End Module

Capturing the loop variable

A query captures variables, not values. A For loop control variable is a single variable that changes during the loop, so a query created in the loop and enumerated after it sees the final value. The compiler warns about it (BC42327); under TreatWarningsAsErrors the program does not build, so the next listing is built with that one setting turned off in the project to show the warning and the effect. Copy the loop variable to a local declared inside the loop (the second list) to get one variable per iteration.

Option Strict On

Module Program
    Sub Main()
        ' Lambdas created in a loop capture the variable, not its value at that moment
        Dim queries As New List(Of IEnumerable(Of Integer))
        Dim numbers = {1, 2, 3, 4, 5, 6}

        For divisor As Integer = 2 To 3
            queries.Add(From n In numbers Where n Mod divisor = 0 Select n)
        Next
        ' The loop variable of For ... Next is shared by every iteration (BC42327 is a warning)

        For Each q In queries
            Console.WriteLine(String.Join(",", q))
        Next

        Dim fixedQueries As New List(Of IEnumerable(Of Integer))
        For d As Integer = 2 To 3
            Dim divisor As Integer = d
            fixedQueries.Add(From n In numbers Where n Mod divisor = 0 Select n)
        Next
        For Each q In fixedQueries
            Console.WriteLine(String.Join(",", q))
        Next
    End Sub
End Module

Joins

Join is an inner join. Both sides of the Equals keyword must each mention range variables from only one side of the join (the left key uses the variables defined before the Join, the right key uses only the new one), and the keyword is Equals, not =. Several key pairs are joined with And. A Group Join keeps every outer element together with its group of matches, which may be empty, and is also how a left outer join is written: flatten the group with DefaultIfEmpty() in a second From.

Option Strict On

    Public Property Id As Integer
    Public Property Name As String
    Public Sub New(id As Integer, name As String)
        Me.Id = id
        Me.Name = name
    End Sub
End Class

Public Class Book
    Public Property Title As String
    Public Property AuthorId As Integer
    Public Property Year As Integer
    Public Property Pages As Integer
    Public Sub New(title As String, authorId As Integer, year As Integer, pages As Integer)

        Me.AuthorId = authorId
        Me.Year = year
        Me.Pages = pages
    End Sub
End Class

Public Class Review
    Public Property Title As String
    Public Property Year As Integer
    Public Property Stars As Integer
    Public Sub New(title As String, year As Integer, stars As Integer)
        Me.Title = title
        Me.Year = year
        Me.Stars = stars
    End Sub
End Class

Module Program
    Sub Main()
        Dim authors As New List(Of Author) From {
            New Author(1, "Jane Austen"), New Author(2, "Frank Herbert"), New Author(3, "Anonymous")
        }
        Dim books As New List(Of Book) From {
            New Book("Emma", 1, 1815, 474), New Book("Persuasion", 1, 1817, 249),
            New Book("Dune", 2, 1965, 412), New Book("Orphan", 99, 2001, 100)
        }

        Console.WriteLine("-- Inner join: only matching pairs")
        Dim pairs = From b In books
                    Join a In authors On b.AuthorId Equals a.Id
                    Select b.Title, AuthorName = a.Name
        For Each p In pairs
            Console.WriteLine(p.Title & " <- " & p.AuthorName)
        Next

        Console.WriteLine("-- Group Join: every author, with a possibly empty group of books")
        Dim shelves = From a In authors
                      Group Join b In books On a.Id Equals b.AuthorId Into Titles = Group
                      Select a.Name, Count = Titles.Count(), Titles
        For Each s In shelves
            Console.WriteLine(s.Name & ": " & s.Count & " [" & String.Join(", ", From t In s.Titles Select t.Title) & "]")
        Next

        Console.WriteLine("-- Left outer join = Group Join + Select Many with DefaultIfEmpty")
        Dim leftJoin = From a In authors
                       Group Join b In books On a.Id Equals b.AuthorId Into g = Group
                       From x In g.DefaultIfEmpty()
                       Select a.Name, Title = If(x Is Nothing, "(none)", x.Title)
        For Each l In leftJoin
            Console.WriteLine(l.Name & " / " & l.Title)
        Next

        Console.WriteLine("-- Composite key: the pairs on each side of And are compared with Equals")
        Dim reviews As New List(Of Review) From {
            New Review("Emma", 1815, 5), New Review("Emma", 1816, 1), New Review("Dune", 1965, 4)
        }
        Dim matched = From b In books
                      Join r In reviews On b.Title Equals r.Title And b.Year Equals r.Year
                      Select b.Title, r.Stars
        For Each m In matched
            Console.WriteLine(m.Title & " " & m.Stars)
        Next

        Console.WriteLine("-- Join with a third source (chained Join)")
        Dim chain = From b In books
                    Join a In authors On b.AuthorId Equals a.Id
                    Join a2 In authors On a.Id Equals a2.Id
                    Select b.Title, a2.Name
        Console.WriteLine(chain.Count())
    End Sub
End Module

Two behaviours matter in practice. Grouping and aggregating

Group By partitions the sequence by a key. The Into list that follows is required: it names what each group contributes to the result. It may contain the aggregate functions (Count(), Sum(expr), Min, Max, Average, Any, All, and any extension method that takes the group) and the group itself under any name, by default Group. After the clause the original range variables are no longer in scope. Only the key (named, or inferred from the expression) and the Into names are, which is why Order By Genre after the grouping works and Order By b.Year does not.

Group By with an element selector (Group b.Title By ...) makes Group a sequence of titles instead of books. The key can be an expression (b.Year \ 100 + 1, the century) or a composite built with an anonymous type; for a composite key the members that must take part in the comparison are marked Key.

Aggregate is the one clause that can start a query. It runs at once and returns either the value of its single aggregate, or a record whose members are named after the functions when there are several. It also works as a clause inside a larger query, introducing a range variable that holds the aggregate for each element (with Let here).

Let and several From clauses

Let computes a value once per element and gives it a name that later clauses can use, which both avoids repeated work and keeps queries readable. A second From clause iterates a second sequence for each element of the first: if the second sequence depends on the first range variable it flattens nested collections (this is SelectMany), and if it does not it is a cross join. Range variables that are declared by a clause stay in scope until a Select, Group By or Aggregate …​ Into ends their scope, and a name cannot be declared twice (BC30978).

What the output teaches:

  • Order By a, b Descending is one OrderBy followed by ThenByDescending; the first key uses OrderBy, never ThenBy.

  • A Select that just projects the final range variable is folded into the previous operator when one can carry it (Join and SelectMany take a result selector), which is why those queries show no separate Select.

  • Let is a Select that carries the old range variables along with the new one in a hidden anonymous type; this is the reason Let appears as Select in the trace.

  • Group Join ... Into Group is GroupJoin followed by Select that exposes the group; Group By is a single GroupBy call.

  • Aggregate applies the filtering clauses once and then calls each aggregate method (Count, Sum) separately on the filtered query object. Over a lazy source every function enumerates the filter again: the last program on this page counts eight filter calls for four elements and two aggregate functions.

  • A query with only a Where has no Select at all; its type is the source’s element type.

The same pattern is why the same query text can be a pipeline of delegates over an array or an expression tree handed to a database provider: the lookup finds Enumerable.Where(Func(Of T, Boolean)) for the former and Queryable.Where(Expression(Of Func(Of T, Boolean))) for the latter.

Anonymous types in projections

Select b.Title, b.Year produces elements of an anonymous type. In a query, the members that the compiler creates from the projection are Key properties: they are read-only and they take part in equality and hash codes. The same projection written as New With {b.Title, b.Year} in a method call creates non-key properties, which is why the comparison at the start of this page needed Key in the method form to type-check (without it, BC36754 reports that the two anonymous types differ). The consequences are:

  • Two projected rows with equal values are equal, so Distinct, Group By with an anonymous key and Join on a composite key work as expected for query-syntax projections.

  • Anonymous types declared without Key use reference equality for those members, so Distinct removes nothing and a composite Group By key creates one group per element.

  • The members cannot be assigned after construction (Key members are read-only) and their types are not nameable, so a function that returns them must return IEnumerable(Of Object), a named class or a tuple.

Comparison, ordering and Option Compare

Strings in a Where clause are compared with the normal = operator, so Option Compare Text makes b.Genre = "NOVEL" match "Novel". The key comparisons that the operators perform internally are different: Group By, Join and Distinct call the default equality of the key type, which for String is ordinal and case-sensitive, and the Equals keyword of Join is therefore not affected by Option Compare either. Order By uses the default comparer of the key type (for strings, the comparison of the current culture); it needs a key that implements IComparable, and a key that does not fails when the query runs, not when it is compiled. To control string comparison in grouping, ordering or joining, call the method form with an explicit StringComparer (books.GroupBy(Function(b) b.Genre, StringComparer.OrdinalIgnoreCase)).

LINQ to DataSet

A DataTable is not generic and does not implement IEnumerable(Of DataRow); the last line of the program shows that. The adapter is AsEnumerable() (from System.Data.DataTableExtensions, in the shared framework), which exposes the rows as IEnumerable(Of DataRow). Columns are read with Field(Of T)(name), which converts to the requested type and maps DBNull to Nothing for reference types and nullable value types, while a direct cast of DBNull fails (and Field(Of Integer) on a DBNull throws). CopyToDataTable() goes the other way, from a query over rows back to a table. LINQ to DataSet is plain LINQ to Objects over rows; no SQL is generated, so it fits in-memory data, data that has already been fetched with a DataAdapter, and tests. See Data Access: ADO.NET and EF Core for the connection and adapter side.

Expression trees and IQueryable

A lambda is converted to one of two things depending on the target type. Assigned to a delegate type such as Func(Of Book, Boolean) it becomes compiled code. Assigned to Expression(Of Func(Of Book, Boolean)) it becomes a data structure that describes the code (an expression tree) which a provider can inspect and translate, for example to SQL. Queries over an IQueryable(Of T) pick the Queryable operators, whose parameters are expression trees, so the query is captured as one tree and executed by the provider when it is enumerated. Entity Framework Core works this way; see Data Access: ADO.NET and EF Core.

The restrictions of expression trees in Visual Basic are stricter than those of delegates: only single-expression lambdas (Function(b) b.Year > 1900) can be converted, statement lambdas cannot (BC36675, shown below), and the tree supports the operators that System.Linq.Expressions has nodes for. The next program shows the two conversions, the tree of a query over AsQueryable() (a real provider such as EF Core would translate it to SQL; the in-memory EnumerableQuery provider simply compiles it), and a tree built by hand.

Option Strict On

Imports System.Linq.Expressions

        Me.Year = year

End Class

Module Program
    Sub Main()
        Dim books As New List(Of Book) From {New Book("Emma", 1815), New Book("Dune", 1965)}

        ' A lambda converted to a delegate type is code; converted to Expression(Of ...) it is data
        Dim asDelegate As Func(Of Book, Boolean) = Function(b) b.Year > 1900
        Dim asTree As Expression(Of Func(Of Book, Boolean)) = Function(b) b.Year > 1900
        Console.WriteLine(asTree)
        Console.WriteLine(asTree.Body.NodeType.ToString() & " / " & asTree.Parameters(0).Name)
        Console.WriteLine(asTree.Compile()(books(1)) & " " & asDelegate(books(0)))

        Dim source As IQueryable(Of Book) = books.AsQueryable()

        Console.WriteLine(q.Expression)
        Console.WriteLine(q.Provider.GetType().Name)
        Console.WriteLine(String.Join(",", q))

        ' Building a tree by hand: b => b.Title = "Dune"
        Dim p = Expression.Parameter(GetType(Book), "b")

        Dim lambda = Expression.Lambda(Of Func(Of Book, Boolean))(body, p)
        Console.WriteLine(lambda)
        Console.WriteLine(books.AsQueryable().Count(lambda))

PLINQ

AsParallel() turns an IEnumerable(Of T) into a ParallelQuery(Of T), and the same query clauses then bind to the operators of System.Linq.ParallelEnumerable, which partition the source across threads. Query syntax works unchanged, Aggregate accepts a parallel source, and AsOrdered() restores the source order at a cost. Parallelism pays off for CPU-bound work on large sources, and not for small sources or cheap lambdas, where partitioning costs more than it saves. Delegates inside the query must be thread safe and free of side effects; to collect results use ForAll with a concurrent collection, or enumerate the result. The threading primitives are covered on Threads, Parallelism and Synchronization.

Option Strict On

Module Program
    Sub Main()
        Dim numbers = Enumerable.Range(1, 20)

        ' AsParallel: the query runs on several threads, so the result order is not defined...
        Dim unordered = From n In numbers.AsParallel()
                        Where n Mod 3 = 0
                        Select n * n
        Console.WriteLine("unordered sorted: " & String.Join(",", unordered.OrderBy(Function(x) x)))

        ' ...unless AsOrdered is used
        Dim ordered = From n In numbers.AsParallel().AsOrdered()
                      Where n Mod 3 = 0
                      Select n * n
        Console.WriteLine("AsOrdered       : " & String.Join(",", ordered))

        ' Aggregates over a parallel source
        Dim stats = Aggregate n In numbers.AsParallel() Into Sum(n), Count()
        Console.WriteLine("sum=" & stats.Sum & " count=" & stats.Count)

        ' Do not mutate shared state from a parallel query
        Dim sink As New Concurrent.ConcurrentBag(Of Integer)
        numbers.AsParallel().ForAll(Sub(n) sink.Add(n))
        Console.WriteLine("collected: " & sink.Count)
    End Sub
End Module

A shelf report

A last example puts the pieces together on the shelf scenario: overdue loans joined with their books, a Let for the days late, an Order By, a tuple projection with a named member, a grouped summary that uses the conditional form of Count, and a query whose Select creates objects of an ordinary class.

Option Strict On

Public Enum LoanState
    Active = 1
    Returned = 2
    Overdue = 3
End Enum

Public Class Book

    Public Property Title As String
    Public Sub New(isbn As String, title As String)
        Me.Isbn = isbn
        Me.Title = title
    End Sub
End Class

Public Class Loan
    Public Property Isbn As String
    Public Property Member As String
    Public Property DueOn As Date
    Public Property State As LoanState
    Public Sub New(isbn As String, member As String, dueOn As Date, state As LoanState)
        Me.Isbn = isbn
        Me.Member = member
        Me.DueOn = dueOn
        Me.State = state
    End Sub
End Class

Module Program
    Sub Main()
        Dim today As New Date(2026, 10, 19)
        Dim books As New List(Of Book) From {
            New Book("9780441172719", "Dune"), New Book("9780451524935", "1984"), New Book("9780141439518", "Emma")
        }
        Dim loans As New List(Of Loan) From {
            New Loan("9780441172719", "ana", New Date(2026, 9, 1), LoanState.Overdue),
            New Loan("9780451524935", "ben", New Date(2026, 10, 1), LoanState.Overdue),
            New Loan("9780141439518", "ana", New Date(2026, 10, 30), LoanState.Active),
            New Loan("9780441172719", "ben", New Date(2026, 5, 1), LoanState.Returned)
        }

        Dim report = From l In loans
                     Where l.State = LoanState.Overdue
                     Join b In books On l.Isbn Equals b.Isbn
                     Let daysLate = (today - l.DueOn).Days
                     Order By daysLate Descending
                     Select (Member:=l.Member, b.Title, daysLate)

        For Each row In report
            Console.WriteLine(row.Member & " has " & row.Title & " " & row.daysLate & " days late")
        Next

        Dim perMember = From l In loans
                        Group By l.Member Into Total = Count(), Open = Count(l.State <> LoanState.Returned)
                        Order By Open Descending, Member
        For Each m In perMember
            Console.WriteLine(m.Member & ": " & m.Total & " loans, " & m.Open & " open")
        Next

        ' Query results can be projected into ordinary objects too
        Dim overdueBooks As List(Of Book) = (From b In books
                                             Join l In loans On b.Isbn Equals l.Isbn
                                             Where l.State = LoanState.Overdue
                                             Select New Book(b.Isbn, b.Title.ToUpper())).ToList()
        Console.WriteLine(String.Join(", ", From b In overdueBooks Select b.Title))
    End Sub
End Module

Pitfalls

The last program of the page collects three behaviours that the discussion above relies on: how many times an Aggregate with two functions runs its filter, when a Nothing source is detected, and that Sum is overflow-checked.

Option Strict On

Module Program
    Sub Main()
        ' 1. Aggregate with several functions: the filter runs once per function
        Dim filterCalls As Integer = 0
        Dim numbers As Integer() = {1, 2, 3, 4}
        Dim stats = Aggregate n In numbers
                    Where Seen(filterCalls, n) > 1
                    Into Count(), Sum(n)
        Console.WriteLine(stats.Count & " " & stats.Sum & " filter calls: " & filterCalls)

        ' 2. A Nothing source fails when the query is built, not when it is enumerated
        Dim missing As List(Of Integer) = Nothing
        Try
            Dim q = From n In missing Select n
            Console.WriteLine("query built")
        Catch ex As ArgumentNullException
            Console.WriteLine("Nothing source: " & ex.ParamName)
        End Try
        Console.WriteLine(String.Join(",", From n In If(missing, New List(Of Integer)) Select n).Length)

        ' 3. Sum of Integer is checked, whatever the project overflow setting is
        Dim big As Integer() = {Integer.MaxValue, 1}
        Try
            Console.WriteLine(big.Sum())
        Catch ex As OverflowException
            Console.WriteLine("Sum: " & ex.GetType().Name)
        End Try
        Console.WriteLine(big.Sum(Function(x) CLng(x)))
    End Sub

  • Writing a query does not run it, and a query that is enumerated twice runs twice; call ToList() to take a snapshot, or keep the query when you want it to see later changes.

  • ToList() on a very large source copies it; the streaming operators do not.

  • Side effects in Where and Select lambdas run at unpredictable times and possibly more than once.

  • Order By is stable, and Group By returns the groups in the order their keys first appear in the source.

  • Keys: use Key on every anonymous-type member that should take part in equality; do not rely on Option Compare Text for grouping, joining or distinct.

  • Single() throws on zero and on several matches; SingleOrDefault() throws on several; First() throws on zero. FirstOrDefault() returns the type’s default value, which is 0 for Integer, so test the result type before trusting a 0.

  • A ByRef parameter or the loop control variable of a For cannot be used safely in a query (BC36533, BC42327); copy it to an ordinary local first.

  • A Nothing source throws ArgumentNullException as soon as the query is built (the last program shows it), not when it is enumerated. Guard with If(source, Enumerable.Empty(Of T)()).

  • Prefer Any() to Count() > 0: it stops at the first element, and Count() on a plain sequence has to read all of it.

  • LINQ to Objects on Dictionary enumerates KeyValuePair(Of TKey, TValue) items; use Key and Value of the pair.

Where the books are outdated

The two books consulted for this section treat LINQ as a feature of the language and as a way to query databases. Three of their points are out of date for .NET 10:

  • LINQ to SQL (System.Data.Linq, DataContext) is not part of modern .NET. It is a .NET Framework technology that is no longer developed. The current tool for object-relational queries is Entity Framework Core, whose DbSet(Of T) is an IQueryable(Of T) and whose queries use the same query syntax shown here. EF6 (System.Data.Entity, automatic migrations, Enable-Migrations) is likewise replaced by EF Core with dotnet ef migrations add; the scaffolding tools emit C#, so a Visual Basic project writes its entity classes by hand or uses a community package. The data-access page has the details.

  • Query-versus-method syntax is presented as a choice of style; the compiler translation shown above makes clear that they are the same thing and may be mixed, and that several operators exist only as methods.

  • The VB-only clauses (Aggregate, Distinct, Skip, Take, Skip While, Take While, Group By ... Into) are usually not covered; they are shown on this page with their translations.
