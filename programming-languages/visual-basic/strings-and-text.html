Strings and Text

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Text is where Visual Basic shows its two layers most clearly. The first layer is the .NET String type: an immutable sequence of UTF-16 code units, with instance methods that count from zero, exactly as in C#. The second layer is the Microsoft.VisualBasic.Strings module, inherited from Visual Basic 6 and imported into every file by default: functions such as Mid, Left, InStr and Trim that count from one, treat Nothing as the empty string and, for some of them, take their comparison mode from Option Compare. Both layers are always available, and a large part of writing good VB text code is knowing which one to use and where their rules differ. This page covers the types, the literals, the two sets of operations, comparison and culture, building strings, regular expressions, encodings and the & versus + question. It was written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and checked on 2026-10-19. Every program was built with Option Strict On and TreatWarningsAsErrors, and run in a Linux container, where the current culture is the invariant culture; a program that depends on the current culture sets the culture it needs explicitly. For C#'s view of the same material see Strings and Text in the C# reference; the formatting of numbers and dates is on Dates, Times and Formatting, and the numeric conversions on Type Conversions.

The String and Char types

String is the keyword for System.String: a reference type whose value is a sequence of UTF-16 code units (Char values), not of "characters" as a person counts them. A String is immutable, so every operation that seems to change one returns a new string, and a string literal is the only form of constant that can be a reference type. Nothing is a valid value of type String (see Nothing and Nullable Value Types), and the VB operators and Strings functions treat it like "".

Char is the keyword for System.Char, a 16-bit UTF-16 code unit. There is no implicit conversion from a one-character String to Char: the declaration Dim c As Char = "A" is BC30512 under Option Strict On ("disallows implicit conversions from String to Char`"). A `Char literal is a string literal with the suffix c: "A"c. A string is indexed from zero: s(0) and s.Chars(0) are the same read-only indexer, and the compiler rejects an assignment to it with BC30526 ("Property Chars is `ReadOnly`").

Unicode: code units, runes and text elements

Because the unit is the UTF-16 code unit, three notions of "length" coexist. Length counts code units. Rune (System.Text, .NET Core 3.0 and later) is a Unicode scalar value, and one rune takes one or two code units (a surrogate pair). A grapheme cluster, what a reader sees as one character, may consist of several runes, for example a letter followed by a combining accent, and System.Globalization.StringInfo enumerates those "text elements".

Imports System.Globalization
Imports System.Text

    End Sub

Consequences you should plan for: Length and Mid/Substring can cut a surrogate pair in half; LINQ’s Reverse() reverses code units and breaks pairs and combining sequences (StrReverse, in contrast, reverses by text element and keeps them intact); Equals and = compare code units, so a precomposed é and e + U+0301 are different strings until both are normalised with Normalize(); ToUpperInvariant() and Char.ToUpperInvariant apply simple one-to-one mappings (the ß stays ß). For text that users see, process runes or text elements, or leave the splitting to a library.

String literals and special characters

A string literal is text between double quotes. There are no backslash escape sequences (so Windows paths and regular expressions can be written as is), a double quote inside the literal is written twice (""), and nothing else is special. Visual Basic 14 (Visual Studio 2015) allows a string literal to continue over several source lines, and the literal then contains the line break that is in the source file: LF in a file saved with Unix line endings (length 12 in the program below), CRLF in a file saved with Windows line endings. A literal whose content depends on how the file is saved is a portability bug in disguise; build line breaks explicitly with vbCrLf, vbLf or Environment.NewLine unless the line ending is irrelevant.

Characters that cannot be typed are named with constants and functions: ControlChars.Tab, ControlChars.Cr, ControlChars.Lf, ControlChars.CrLf, ControlChars.NewLine (always CR LF when measured on Linux with .NET 10, unlike Environment.NewLine, which is LF there), ControlChars.Quote, ControlChars.NullChar, ControlChars.Back, ControlChars.FormFeed, ControlChars.VerticalTab, the VB6-era constants vbTab, vbCr, vbLf, vbCrLf (always CR LF, two characters), vbNewLine (the platform’s), vbNullChar, vbBack, vbFormFeed, vbVerticalTab, vbNullString (which is simply Nothing), and ChrW(code) / AscW(text) for any UTF-16 code unit. Source files may contain any Unicode text, so a literal "€" is fine. The compiler also accepts the typographic quotes U+201C and U+201D as string delimiters (a program that wrote “smart” compiled and printed smart), a behaviour that surprises people who paste code from word processors: an unnoticed pair of curly quotes is a legal string literal.

Option Strict On

Module Ex01
    Sub Main()
        ' Quotes are doubled; there are no backslash escapes.
        Dim quoted = "She said ""Hello"" and left"
        Dim windowsPath = "C:\Shelf\catalog.json"

        Console.WriteLine(windowsPath)

        Console.WriteLine("Tab:" & vbTab & "|" & ControlChars.Tab & "|")

        Console.WriteLine("Euro sign: " & ChrW(&H20AC) & ", code " & AscW("€"c))
        Console.WriteLine("vbCrLf length = " & vbCrLf.Length & ", vbLf length = " & vbLf.Length)

        ' A string literal may contain line breaks (VB 14): the text includes the file's own line endings.
        Dim poem = "first
second"
        Console.WriteLine("Literal with a line break has length " & poem.Length & " and contains LF: " & poem.Contains(vbLf))

        ' Character literals use the c suffix.
        Dim letter As Char = "A"c
        Console.WriteLine(letter & " has code " & AscW(letter) & ", next is " & ChrW(AscW(letter) + 1))

What VB does not have, unlike C#: no \n or € escape sequences, no raw string literals (C# 11), no UTF-8 string literals ("abc"u8, C# 11: BC30205 "End of statement expected"), no verbatim prefix (everything is already verbatim). Use ChrW, ControlChars and &.

Interpolated strings

Visual Basic 14 added interpolated strings: $"Hello {name}". A hole is {expression}, {expression,alignment}, {expression:format} or {expression,alignment:format}; the alignment is a signed integer (negative left-aligns) and the format is any format string that the value’s type understands (see Dates, Times and Formatting). {{ and }} produce literal braces. The expression is ordinary VB, including string literals with plain quotes and calls ({If(year > 1900, "modern", "old")}), and the compiler turns the string into a call to String.Format, so the current culture applies to every formatted value. Assign it to FormattableString to defer the formatting and pass a culture later: FormattableString.Invariant($"{price:N2}") is the idiom for stable, culture-independent output. VB 17.13 has no interpolated string handlers (a C# 10 feature): String.Create(CultureInfo.InvariantCulture, $"{x}") fails with BC30311 ("Value of type String cannot be converted to DefaultInterpolatedStringHandler`"), so use `FormattableString.Invariant. VB has no $@ prefix and no multi-quote variants, and a format specifier cannot contain }.

String methods and the Strings module

Every VB program can call both text.Substring(6, 5) and Mid(text, 7, 5). The module Microsoft.VisualBasic.Strings (documented in the Language Reference as the "string functions") is in scope without an Imports, because Visual Basic projects import Microsoft.VisualBasic implicitly. The functions are thin wrappers, but they carry the VB6 semantics, and the differences are what matter.

VB function Counterpart on String What differs

Mid(s, start, length)

s.Substring(start - 1, length)

start is 1-based. start greater than the length gives "", not an exception, and a length that is too long is shortened. start less than 1 throws ArgumentException. Mid(s, 6, 5) of "Hello World!" is " Worl", not "World": the word starts at position 7

Left(s, n), Right(s, n)

s.Substring(0, n), s.Substring(s.Length - n)

n larger than the length returns the whole string; Substring throws ArgumentOutOfRangeException. A negative n throws

Len(s)

s.Length

Len(Nothing) is 0; Nothing.Length throws NullReferenceException

InStr(s, find), InStr(start, s, find, compare)

s.IndexOf(find)

1-based and 0 for not found (IndexOf is 0-based and -1). The compare mode defaults to Option Compare; InStrRev(s, find) searches from the end and also returns 0

Trim(s), LTrim(s), RTrim(s)

s.Trim(), s.TrimStart(), s.TrimEnd()

The VB functions remove only the space character U+0020: tabs and line breaks stay. String.Trim() removes every white-space character

UCase(s), LCase(s)

s.ToUpper(), s.ToLower()

The same current-culture conversion; use ToUpperInvariant() for identifiers (see culture, below)

Replace(s, find, repl, start, count, compare)

s.Replace(find, repl)

start (default 1) is 1-based, and the result starts at start: Replace(text, "l", "L", 5) returns "o WorLd!", with the first four characters discarded. count -1 means all. The compare mode comes from Option Compare

Split(s, delimiter, limit, compare)

s.Split(delimiter)

The delimiter defaults to a single space; empty entries are kept; limit stops splitting. String.Split takes StringSplitOptions (RemoveEmptyEntries, TrimEntries)

Join(array, delimiter)

String.Join(delimiter, values)

Argument order differs. Join takes an array of String or Object; String.Join takes any IEnumerable

StrComp(a, b, compare)

String.Compare(a, b, comparison)

Returns -1, 0 or 1, and the compare mode comes from Option Compare. String.Compare uses the current culture and returns any negative or positive value

Space(n), StrDup(n, text)

New String(" "c, n), New String(c, n)

StrDup(3, "ab") repeats only the first character of the text ("aaa"); use String.Concat(Enumerable.Repeat("ab", 3)) or the String.PadLeft/PadRight methods to repeat longer pieces

StrReverse(s)

New String(s.Reverse().ToArray())

StrReverse keeps surrogate pairs and combining sequences together (it reverses text elements); the LINQ version reverses code units and breaks them

LSet(s, n), RSet(s, n)

s.PadRight(n), s.PadLeft(n)

They also truncate to n characters

Filter(array, text)

array.Where(Function(x) x.Contains(text))

Returns the elements that contain the text, as an array, with a Include flag and a compare mode

Format(value, style)

value.ToString(format)

VB6-style named and custom formats, see the dates page. Format and the FormatNumber, FormatCurrency, FormatPercent and FormatDateTime functions take their culture from the thread

StrConv(s, VbStrConv...)

TextInfo.ToTitleCase, ToUpperInvariant, …​

Windows only: the analyzer reports CA1416, "This call site is reachable on all platforms …​ only supported on: `windows`", and so the example avoids it. The narrow/wide, katakana/hiragana and Chinese conversions have no .NET equivalent outside Windows

Asc(c), Chr(code)

AscW(c), ChrW(code)

Asc and Chr convert through the system ANSI code page (code 128 to 255), which on .NET needs the code pages provider registered, otherwise NotSupportedException. AscW and ChrW are plain UTF-16

Which one should you use? There is no single rule, but these defaults are close to universal:

  • For new code prefer the String members (Substring, IndexOf, Contains, StartsWith, Trim, Replace, Split, PadLeft, String.Join): they are the same members C# developers use, they take StringComparison, and they do not depend on Option Compare.

  • The Strings functions that have no good counterpart are fine: Mid and Left/Right when you want "cut politely, never throw", StrDup, Space, InStrRev and the Like operator.

  • When you call Left, Right, Mid or Len inside a class that has a member with the same name (a WinForms Form has a Left property, and a Control has Right), the member wins: qualify the call as Strings.Left(...).

  • A Strings function accepts Nothing and returns a sensible value; the String member needs a non-Nothing receiver.

The Mid statement

Mid is also a statement: Mid(target, start, length) = replacement overwrites characters of the string variable target in place, from the 1-based position start. The string is still immutable, so the statement assigns a new string to the variable; it never makes the string longer or shorter, uses at most length characters (and at most the characters left in target), and with the replacement shorter than the field, keeps the remaining characters. The first argument must be a writable variable or property, not an expression or a literal.

Option Strict On

Module Ex04
    Sub Main()
        ' The Mid statement overwrites characters in place; it never changes the length.
        Dim label = "Title: Dune     "
        Mid(label, 8) = "Emma"
        Console.WriteLine($"[{label}]")

        Dim code = "ABCDEFGH"
        Mid(code, 3, 2) = "xyz"
        Console.WriteLine($"Mid(code, 3, 2) = ""xyz""  -> {code}")
        Mid(code, 7) = "123456"
        Console.WriteLine($"Mid(code, 7) = ""123456"" -> {code}")

        ' The LSet and RSet functions pad or truncate to a fixed width.
        Console.WriteLine("[" & LSet("left", 10) & "] [" & RSet("right", 10) & "] [" & LSet("truncated", 4) & "]")

Culture, ordinal and invariant

NET comparison and casing have three families. Ordinal compares the numeric value of the UTF-16 code units: fast, stable and independent of the machine. Culture-sensitive uses the collation rules of a culture

(CultureInfo.CurrentCulture unless one is passed): correct for text shown to people, but the result can differ between users and between operating systems, because since .NET 5 the rules come from ICU on Linux, macOS and recent Windows, and from NLS on older Windows. Invariant culture applies the same culture-sensitive rules for an English-like "no particular culture", intended for persisted data. The guidance of the .NET best-practices for strings applies unchanged to VB:

  • Use ordinal (StringComparison.Ordinal, OrdinalIgnoreCase) for identifiers, keys, file names, paths, URLs, protocol tokens and any other data that a program, not a person, reads.

  • Use culture-sensitive comparison for text that you sort or search for people, passing the culture explicitly (String.Compare(a, b, culture, CompareOptions.IgnoreCase)).

  • Convert case with ToUpperInvariant or ToLowerInvariant before comparing machine data, never with ToLower() (the Turkish I, below), and prefer OrdinalIgnoreCase to converting at all.

Building strings

Concatenating a few values with &, String.Concat or an interpolated string is fine and the compiler turns several operands into a single String.Concat call. The pattern to avoid is a loop that appends to a string with &=: each step creates a new string and copies the old one, so n appends cost O(n2) time and produce n short-lived garbage strings. Use System.Text.StringBuilder, or String.Join when you already have a sequence, or a TextWriter when the destination is a stream. StringBuilder is mutable, grows by chunks, has chainable Append, AppendLine, AppendFormat, AppendJoin, Insert, Remove and Replace, and is not thread-safe.

Pattern matching: Like and regular expressions

The Like operator compares a string with a pattern that has five metacharacters: ? (one character), * (any number of characters, also none), # (one digit), [list] (one character from the list or a range such as [A-C]), and [!list] (one character not in the list). Put a metacharacter in brackets to match it literally: a[*]b. The case sensitivity follows Option Compare. Like works on .NET: it is implemented by LikeOperator in Microsoft.VisualBasic.Core, and the following program, built and run on .NET 10, shows that it does. The Language Reference page for the operator still carries a note that it is not supported on .NET Core, which is out of date (checked 2026-10-19).

For anything beyond that, use System.Text.RegularExpressions.Regex. VB string literals need no escaping of backslashes, which makes patterns easier to read than in C# without the verbatim prefix. Points specific to VB and to current .NET:

  • Named groups are read with m.Groups("year"); test .Success on a group for an optional part.

  • Always give a match timeout on patterns that process untrusted input (New Regex(pattern, options, TimeSpan.FromSeconds(1))): nested quantifiers such as (a+)+$ have exponential backtracking and raise RegexMatchTimeoutException when the limit is reached. RegexOptions.NonBacktracking (.NET 7 and later) avoids backtracking altogether, with a smaller feature set.

  • RegexOptions.CultureInvariant together with IgnoreCase avoids the Turkish I problem; RegexOptions.Compiled trades start-up time for speed.

  • Escape user input before embedding it in a pattern with Regex.Escape.

  • The GeneratedRegex source generator of .NET 7 is not available to VB: its attribute goes on a partial method with a return value, and VB’s partial methods must be Sub (BC31437, "partial methods must be Subs"). A Shared ReadOnly field holding a New Regex(...) is the VB replacement.

  • The static methods (Regex.IsMatch(text, pattern)) cache recently used patterns, which is fine for a few patterns and a poor choice in a hot loop with many.

Rules of thumb: write UTF-8 (without a BOM unless a consumer needs it); use Encoding.Latin1 for ISO-8859-1; register CodePagesEncodingProvider.Instance once at start-up when you must read Windows-1252 or other legacy code pages; never rely on Chr and Asc for non-ASCII text, use ChrW and AscW; and for a console program that prints non-ASCII text set Console.OutputEncoding = Encoding.UTF8 yourself. The same encoding rules apply to File.ReadAllText/WriteAllText (see Files, Directories and Streams).

Concatenation: & versus

& is the concatenation operator: it always converts both operands to String and joins them, so "Copies: " & 2 is "Copies: 2" and 1 & 2 is "12". + is the addition operator that, when both operands are strings, also concatenates for compatibility with early BASIC. The two are not interchangeable:

  • With one string and one number, + tries to convert the string to a number: "1" + 2 and "x" + 2 are BC30512 under Option Strict On ("disallows implicit conversions from String to Double`"); with strict typing switched off (checked in a scratch project) the first quietly gives the `Double 3 and the second throws InvalidCastException ("Conversion from string "x" to type 'Double' is not valid") at run time.

  • The precedence is different: arithmetic binds tighter than &, so "Total: " & 1 + 2 is "Total: 3" while the addition-only reading would first apply + to a string and a number.

  • Nothing is an empty string for &, and Nothing + "a" also works but "a" + 1 does not.

  • Two strings that happen to contain digits (left + right in the program) are concatenated by +, which hides a missing conversion: someone later changes one variable to Integer and the meaning of the line changes.

Always write & for concatenation (and &= for appending), interpolation for formatting, and keep + for numbers.

Option Strict On

Module Ex11
    Sub Main()
        Dim count As Integer = 2
        Dim title As String = "Dune"

        ' & always concatenates and converts both sides to String.
        Console.WriteLine("Copies: " & count)
        Console.WriteLine(1 & 2)
        Console.WriteLine("Total: " & 1 + 2)
        Console.WriteLine("Total: " & (1 + 2))
        Console.WriteLine(title & Nothing & "!")

        ' Concatenation has lower precedence than arithmetic and higher than comparison.
        Console.WriteLine("a" & "b" = "ab")

        ' + on two strings concatenates as well, but it is a numeric operator that falls back to concatenation.
        Dim left As String = "10"
        Dim right As String = "5"
        Console.WriteLine(left + right)
        Console.WriteLine(left & right)
        Console.WriteLine(CInt(left) + CInt(right))

        ' Interpolation and String.Format never ask whether + was meant.
        Console.WriteLine($"{left}{right} / {count + 1}")
    End Sub
End Module

Where the books are outdated. The two books that this section was planned from draw on VB6 and early VB.NET habits in text handling: they use ` for concatenation, they present `Mid("Hello World!", 6, 5)` as "World" when it is `" Worl"` (`Mid` is 1-based, so the word starts at position 7), and they treat `FormatDateTime` and `Format` as the usual way to format, where interpolation and `ToString(format)` are the current choice. The corrections are all in this page: `&` and interpolation instead of `, the 1-based Mid, Left, Right and InStr against the 0-based Substring and IndexOf, and the culture rules of ToLower and String.Compare. Their 8-bit view of text (Chr, Asc, ANSI) is also outdated: .NET text is UTF-16 and files default to UTF-8.

Pitfalls checklist

  • The positions in Mid, InStr and Left, and the start argument of Replace, are 1-based; Substring and IndexOf are 0-based; Replace with a start position drops the beginning.

  • Trim (the function) removes only spaces; s.Trim() removes all white space.

  • StrDup(n, "ab") repeats the first character only.

  • Nothing = "" is True, while Nothing Is "" is False (the second is an empty string, an object); use String.IsNullOrEmpty for "missing or empty".

  • Option Compare Text affects operators, Select Case, Like, InStr and StrComp only; dictionaries, List.Contains and String.Equals ignore it.

  • ToLower()/ToUpper() use the current culture: use the Invariant variants or OrdinalIgnoreCase for machine data.

  • StartsWith(String), IndexOf(String) and Compare are culture-sensitive by default; Contains, Replace and Split are ordinal.

  • A multiline string literal contains the line endings of the source file.

  • Curly quotes pasted into code are valid string delimiters.

  • The Asian conversions of StrConv are Windows-only; Chr and Asc above 127 depend on a code page.

  • s &= x in a loop is quadratic; use StringBuilder or String.Join.

  • + between a number and a string is a conversion error under Option Strict On; & never is.

  • Length counts UTF-16 code units, not characters; Mid and Substring can cut surrogate pairs.

  • No VB local can have a span type, and GeneratedRegex cannot be used.
