Libraries, Packaging and Deployment

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Examples marked "built and run" are complete projects that were built with warnings treated as errors (except where the text says otherwise) and run in the .NET 10 SDK container (Linux, arm64); the output shown is real output. The class library is called Shelf.Lib, it is the reusable part of the shelf library-catalogue sample, and the C#-compatibility checks use a C# console program that consumes it. Sizes quoted for publish modes are du -sk kilobytes on that container, for linux-arm64, and only the ratios are meaningful. Anything that needs Windows (Windows Forms publishing, ClickOnce, MSIX, running a Windows service) is labelled "built, not run" or "not run".

A library is the unit of reuse in .NET, and for Visual Basic it is also the safest way to work: the language has no ASP.NET Core, MAUI or Blazor templates, but a Visual Basic class library can be referenced by projects in any .NET language (see Web, HTTP and Services for a C# web host over a Visual Basic library). This page covers how to write a library that is pleasant to consume from Visual Basic and C#, how to target several frameworks, how to package it for NuGet, and how to ship an application with the right publish mode, including what Native AOT and trimming do and do not mean for a language with late binding. The build system itself (properties, the dotnet command line, vbc options) is on Projects, MSBuild and the dotnet CLI.

The root namespace is the Visual Basic surprise for C# developers: with <RootNamespace>Shelf</RootNamespace>, the code Namespace Catalog ... End Namespace declares Shelf.Catalog, and a type outside any Namespace block is in Shelf. Writing the full name in the Namespace statement as well (Namespace Shelf.Catalog) declares Shelf.Shelf.Catalog. A class called Shelf inside Shelf.Catalog would read confusingly as Shelf.Catalog.Shelf (and Visual Basic names are case-insensitive), which is why the sample class is called Bookshelf.

Designing the public API for Visual Basic and C# consumers

A library written in Visual Basic is consumed by C# as ordinary IL, but several Visual Basic constructs show up differently. The sample library has three files that exercise them. The ISBN value type:

Built and run: Isbn.vb, an immutable value object with TryParse
Option Strict On

Imports System.Runtime.InteropServices

Namespace Catalog

    ''' <summary>A validated 13-digit ISBN.</summary>
    Public NotInheritable Class Isbn
        Implements IEquatable(Of Isbn)

        Private ReadOnly _digits As String

        Private Sub New(digits As String)
            _digits = digits
        End Sub

        ''' <summary>The 13 digits without separators.</summary>
        Public ReadOnly Property Digits As String
            Get
                Return _digits
            End Get
        End Property

        ''' <summary>Parses an ISBN-13, ignoring hyphens and spaces.</summary>
        ''' <param name="text">The text to parse.</param>
        ''' <param name="result">The ISBN when the text is valid; otherwise Nothing.</param>
        ''' <returns><c>True</c> when the text is a valid ISBN-13.</returns>
        Public Shared Function TryParse(text As String, <Out> ByRef result As Isbn) As Boolean
            result = Nothing
            If text Is Nothing Then Return False
            Dim digits As String = text.Replace("-", "").Replace(" ", "")
            If digits.Length <> 13 Then Return False
            Dim sum As Integer = 0
            For i As Integer = 0 To 12
                If Not Char.IsDigit(digits(i)) Then Return False
                sum += (AscW(digits(i)) - AscW("0"c)) * If(i Mod 2 = 0, 1, 3)
            Next
            If sum Mod 10 <> 0 Then Return False
            result = New Isbn(digits)
            Return True
        End Function

        Public Overloads Function Equals(other As Isbn) As Boolean Implements IEquatable(Of Isbn).Equals
            Return other IsNot Nothing AndAlso _digits = other._digits
        End Function

        Public Overrides Function Equals(obj As Object) As Boolean
            Return Equals(TryCast(obj, Isbn))
        End Function

        Public Overrides Function GetHashCode() As Integer
            Return _digits.GetHashCode()
        End Function

        Public Overrides Function ToString() As String
            Return _digits
        End Function
    End Class

End Namespace

    ''' <summary>Functions that C# callers see as <c>Helpers.Slugify(...)</c>.</summary>
    Public Module Helpers

        ''' <summary>Makes a URL-friendly slug.</summary>
        ''' <param name="title">The title.</param>
        ''' <param name="separator">The separator; a hyphen by default.</param>
        <System.Runtime.CompilerServices.Extension>
        Public Function Slugify(title As String, Optional separator As String = "-") As String
            Return String.Join(separator, title.ToLowerInvariant().Split(New Char() {" "c}, StringSplitOptions.RemoveEmptyEntries))
        End Function

        ''' <summary>Joins any number of tags.</summary>

            Return String.Join(",", tags)
        End Function

            End Get
        End Property

    End Class

How each Visual Basic construct looks from C#:

In Visual Basic C# sees Design advice

Module Helpers with `Public Function`s

A static class Helpers (and, with <Extension>, extension methods)

A Module is fine for a library, but its members are also visible without the module name inside Visual Basic callers that import the namespace. Prefer a NotInheritable Class with a Private Sub New() and Shared members when the API is mainly for C# callers; the type is then an ordinary static-like class.

Default Public ReadOnly Property Item(index As Integer)

An indexer this[int]

A default property must have a parameter and there is at most one per type; the compiler records its name in DefaultMemberAttribute, which is what C# reads.

ParamArray tags As String()

params string[] tags

Fine. Only the last parameter can be a ParamArray.

Optional separator As String = "-"

An optional parameter with a default

The default value is compiled into the caller (see below): changing it later does not change callers that were not recompiled. The same rule holds in C#.

ByRef result As Isbn with <Out>

out Isbn? result; without <Out> it would be ref

Use <Out> from System.Runtime.InteropServices for the "Try" pattern so C# callers write out.

Event TitleAdded As EventHandler(Of TitleAddedEventArgs)

An event of that type

Use EventHandler(Of TArgs) and an EventArgs subclass; a RaiseEvent is the only way to raise it.

Friend

internal

Share internals with a test project through InternalsVisibleTo (below).

NotInheritable Class Isbn

A sealed class

Seal types that are not designed for inheritance; a small immutable value is a sealed class or a Structure.

Reference types and Nothing

Reference types without nullable annotations ("oblivious")

Visual Basic does not emit C# nullable-reference-type attributes, so C# callers get no warnings and no guarantees; document nullability in the XML comments.

Optional parameter defaults are baked into callers

A consumer compiled against version 1.2.0 of the library (default separator -) was run twice: once with that library, then with a rebuilt Shelf.Lib.dll whose default had become _, copied over the first without recompiling the consumer. The call "Types and Tables".Slugify() passes the separator the compiler saw:

Build succeeded.
Build succeeded.
--- consumer built against the old library (default "-"):
slug:    types-and-tables / types_and_tables
--- same consumer binary, library replaced by one whose default is "_":
slug:    types-and-tables / types_and_tables

(Both runs printed types-and-tables for the call that omitted the argument.) The consequence for library authors: treat a changed default as a breaking change, or give the parameter no default and add an overload. Overloads are also more reliable than Optional for C# callers and for reflection.

CLS compliance

Visual Basic is a CLS consumer and producer; <Assembly: CLSCompliant(True)> makes the compiler report public API that another .NET language might not be able to use, such as unsigned types:

Option Strict On

<Assembly: CLSCompliant(True)>

Public Class Totals
    Public Function Total() As Integer
        Return 1
    End Function

    Public Function total(value As Integer) As Integer
        Return value
    End Function

    Public Function Count(value As UInteger) As UInteger
        Return value
    End Function
End Class
Code.vb(14,21): warning BC40027: Return type of function 'Count' is not CLS-compliant.
Code.vb(14,27): warning BC40028: Type of parameter 'value' is not CLS-compliant.
Build succeeded.

The two warnings (BC40027 and BC40028) name the unsigned return and parameter types. Visual Basic has UInteger, ULong and UShort, but Visual Basic programs seldom use them in public signatures; a library meant for every .NET language should not either.

Friend assemblies

Friend members are invisible to other assemblies. To let a test project see them, add InternalsVisibleTo as an MSBuild item; the SDK writes the attribute into the generated assembly info for Visual Basic too:

<ItemGroup>
  <InternalsVisibleTo Include="Tests" />
</ItemGroup>

With the item present, a console program in the Tests assembly calls New Engine().Secret() on a Friend method and prints:

42

Without the item the same call fails to compile:

Program.vb(7,27): error BC30456: 'Secret' is not a member of 'Engine'.

Multi-targeting

A library that must serve both .NET Framework and modern .NET lists several target frameworks:

<TargetFrameworks>net481;net10.0</TargetFrameworks>

dotnet build then compiles the same sources once per framework and writes one output folder per target, and dotnet pack puts each into its own lib/<tfm>/ folder. The test library above builds both on Linux, because the SDK downloads the .NET Framework reference assemblies for net481 (it can compile for Framework anywhere; it cannot run the result there):

  Shelf.Lib -> Shelf.Lib/bin/Release/net481/Shelf.Lib.dll
  Shelf.Lib -> Shelf.Lib/bin/Release/net10.0/Shelf.Lib.dll
  Successfully created package 'nupkgs/Irurueta.Shelf.Lib.1.2.0.nupkg'.
  Successfully created package 'nupkgs/Irurueta.Shelf.Lib.1.2.0.snupkg'.

Code that differs per framework uses the preprocessor constants the SDK defines for each target (NET10_0_OR_GREATER, NETFRAMEWORK, NET481, …​): the BuildInfo.Target property above is "net10.0 build" when the net10.0 assembly is loaded and ".NET Framework build" for the other. The #If ... #ElseIf ... #Else ... #End If forms are the Visual Basic conditional compilation directives (see Conditional Compilation and Directives). Package references can also be conditional on the target:

<ItemGroup Condition="'$(TargetFramework)' == 'net481'">
  <PackageReference Include="System.Text.Json" Version="10.*" />
</ItemGroup>

netstandard2.0 and the Visual Basic runtime

netstandard2.0 is the target of choice for a library consumed by old and new runtimes, and it works for Visual Basic with one important exception: the functions of the Visual Basic runtime library (Left, Mid, Format, CInt conversions that call into the library, Strings, Interaction) are not available to it. A library that calls Left fails on the netstandard2.0 target:

Option Strict On

Public Module Text
    Public Function FirstThree(value As String) As String
        Return Left(value, 3)
    End Function
End Module
Code.vb(5,16): error BC30451: 'Left' is not declared. It may be inaccessible due to its protection level.

Embedding the runtime (<VBRuntime>Embed</VBRuntime>) did not help (the same BC30451), and adding the Microsoft.VisualBasic 10.3.0 package turned it into 'Left' is not a member of 'Strings':

Code.vb(5,16): error BC30456: 'Left' is not a member of 'Strings'.

The robust choice is to avoid the old functions in a netstandard2.0 library and use the .NET equivalents (value.Substring, String.Format, Convert), or to multi-target net481;net10.0 instead as above. Both netstandard2.0 and net10.0 outputs build when the library uses only .NET Base Class Library types.

Source: .NET Standard, Cross-platform targeting

XML documentation

<GenerateDocumentationFile>true</GenerateDocumentationFile> makes the compiler write Shelf.Lib.xml next to the assembly. Visual Basic doc comments start with three apostrophes ('''); typing them above a member in Visual Studio inserts the skeleton. The XML file is packed with the assembly into lib/<tfm>/, so consumers get IntelliSense (see the listing of the package below). The compiler checks the comments it can: a param name that does not exist and a cref that does not resolve are warnings.

Option Strict On

''' <summary>Documented type.</summary>
Public Class Documented
    Public Property Undocumented As Integer

    ''' <summary>Has a bad param.</summary>
    ''' <param name="wrong">Not a parameter.</param>
    Public Sub Run(value As Integer)
    End Sub

    ''' <summary>See <see cref="Missing"/>.</summary>
    Public Sub Other()
    End Sub
End Class
Code.vb(12,27): warning BC42309: XML comment has a tag with a 'cref' attribute 'Missing' that could not be resolved.
Code.vb(8,9): warning BC42307: XML comment parameter 'wrong' does not match a parameter on the corresponding 'sub' statement.
Build succeeded.

Two things follow. BC42307 and BC42309 are warnings, and TreatWarningsAsErrors makes them errors, which is what you want on a library. And the compiler did not warn that the public property Undocumented has no comment: unlike C# (warning CS1591), the Visual Basic compiler printed no "missing XML comment" warning in this test, so missing documentation needs an analyzer or a review rule. The conventions for comments and the analyzers that enforce style are on XML Documentation, Analyzers and Code Style.

Source: Documenting your code with XML

NuGet packaging

dotnet pack builds the project and creates a .nupkg. The metadata is MSBuild properties in the project file, shown in the Shelf.Lib.vbproj above: PackageId, VersionPrefix, Authors, Description, PackageTags, PackageLicenseExpression (an SPDX identifier), PackageReadmeFile with the file added as a None item with Pack="true", RepositoryUrl, and IncludeSymbols plus SymbolPackageFormat for a .snupkg of portable PDBs. The package contents, listed with unzip -l (sizes in bytes):

Using a package: a local feed, PackageReference and ProjectReference

The consumers above used a folder as the package source. A nuget.config next to the project (the single source /m/nupkgs was the mounted package folder):

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="local" value="/m/nupkgs" />
  </packageSources>
</configuration>

and <PackageReference Include="Irurueta.Shelf.Lib" Version="1.2.*" /> in the consumer project (or dotnet add package Irurueta.Shelf.Lib --version 1.2.0). The version 1.2.* is a floating range that resolved to 1.2.0. Two cautions: <clear /> removes nuget.org, so a restore that also needs public packages must add it back; and a nuget.config in a parent folder applies to every project below it, which cost the scratch build one failure (the clear-ed source made a runtime-pack restore fail) until the file was moved into the consumer folders.

Inside a solution the library is referenced as a project, not as a package:

dotnet add Shelf.Consumer reference Shelf.Lib
dotnet add Shelf.Consumer package Microsoft.Extensions.Logging

A ProjectReference rebuilds the library with the consumer and flows its target frameworks (the consumer picks the best match from net481;net10.0); a PackageReference consumes a binary. Version numbers for many projects are best kept in one place with central package management (Directory.Packages.props with ManagePackageVersionsCentrally set to true, and PackageReference items without a Version).

Trimming and late binding

The trimmer removes code that it cannot prove is used. A call written as a string (CallByName(instance, "Describe", CallType.Method), Type.GetType("Deploy.Magazine"), Activator.CreateInstance(type)) hides the target from it, and Visual Basic’s late binding is built on the same mechanism: late-bound member access on Object (possible only when Option Strict is switched off) is compiled into calls of the NewLateBinding runtime helpers, which the stack trace below shows underneath CallByName. Publishing with -p:PublishTrimmed=true reports it as a warning:

Program.vb(26,9): Trim analysis warning IL2026: Deploy.Program.Main(): Using member 'Microsoft.VisualBasic.CompilerServices.Versioned.CallByName(Object, String, CallType, Object[])' which has 'RequiresUnreferencedCodeAttribute' can break functionality when trimming application code. The method name cannot and type cannot be statically analyzed so it may be trimmed.

With TreatWarningsAsErrors set, which the project file in this page does, the warning is an error and the publish fails:

Native AOT

Native AOT compiles the program to a native executable with no JIT and no runtime installed. The documented limitations are: no dynamic loading (Assembly.LoadFile), no runtime code generation (System.Reflection.Emit), no C/CLI, no built-in COM on Windows, and the app must be trimmed and, effectively, single-file. Compiling needs a native toolchain (a C/C linker and zlib headers), so the build used the sdk:10.0-aot container image, which has it.

What this means for Visual Basic was tested rather than assumed. A program that uses the typical static language features, the runtime library (Format, UCase, Left, Mid, CInt, CDbl, IsNumeric, Like), LINQ query syntax, string interpolation, Select Case and For Each, published with PublishAot=true and TreatWarningsAsErrors=true without a single warning and ran:

Built and run (Native AOT): ordinary Visual Basic with the runtime library
Option Strict On

Imports System.Collections.Generic
Imports System.Linq
Imports Microsoft.VisualBasic

Public Class Book
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Module Program

    Sub Main()
        ' Typical Visual Basic code: runtime-library functions, Like, LINQ, interpolation, For Each.
        Dim books As New List(Of Book) From {
            New Book With {.Title = "Types and Tables", .Year = 1988},
            New Book With {.Title = "Shelf Basics", .Year = 2020}
        }
        Dim recent = From b In books Where b.Year > 2000 Select b.Title
        Console.WriteLine("LINQ:      " & String.Join(", ", recent))
        Console.WriteLine("Format:    " & Format(1234.5, "N2") & " | " & Strings.UCase("shelf") & " | " & Left("catalogue", 3) & " | " & Mid("catalogue", 4, 3))
        Console.WriteLine("Conversion: " & CInt("42") + 1 & " | " & CDbl("3.5") & " | " & IsNumeric("12x").ToString())
        Console.WriteLine("Like:      " & ("ISBN-0306" Like "ISBN-####").ToString())
        Console.WriteLine("Select:    " & Describe("vb"))
        Console.WriteLine($"Interp:    {books.Count} books, newest {books.Max(Function(b) b.Year)}")
        Dim items As Object = books
        For Each item As Object In CType(items, IEnumerable(Of Book))
            Console.WriteLine("For Each:  " & CType(item, Book).Title)
        Next
    End Sub

    Function Describe(language As String) As String
        Select Case language
            Case "vb" : Return "Visual Basic"
            Case "cs" : Return "C#"
            Case Else : Return "unknown"
        End Select
    End Function

End Module

Public NotInheritable Class OverdueWorker

    Public Sub New(lifetime As IHostApplicationLifetime)

    End Sub

    Protected Overrides Async Function ExecuteAsync(stoppingToken As CancellationToken) As Task

            Await Task.Delay(100, stoppingToken)
        Next

    End Function

        builder.Services.AddHostedService(Of OverdueWorker)()
        Using app As IHost = builder.Build()
            app.Run()
        End Using
        Console.WriteLine("stopped")
    End Sub

Pitfalls

  • A nuget.config with <clear /> in a parent folder applies to every project beneath it, including projects that need nuget.org for runtime packs: put it next to the consumers, or add the public source back.

  • Changing Optional defaults is a breaking change for callers that were not recompiled.

  • Duplicate assembly attributes (BC30663) after migrating an old project: delete them or turn off generation.

  • netstandard2.0 plus the Visual Basic runtime functions: use net481;net10.0 or avoid Left, Mid and Format.

  • The .pdb is counted in the single-file rows above: set DebugType to none to leave symbols out of the publish folder.

  • Trimming with TreatWarningsAsErrors turns every trim warning into a failed publish: that is the desired behaviour for libraries.

  • Single-file publish is not trimming: the code inside is the same, only packed; it does not shrink the app unless compression or trimming is added (see the table).

  • Late binding survives a normal run and fails only after trimming or AOT: add a publish-and-run step to the build for apps that use CallByName, CreateObject or a project with Option Strict switched off.

  • The Lib identifier is a keyword (Declare ... Lib): a project or namespace called Lib fails with BC30183, so name it EngineLib or ShelfLib.

  • Cross-publishing for Windows from Linux compiles but does not run the result: test on Windows.
