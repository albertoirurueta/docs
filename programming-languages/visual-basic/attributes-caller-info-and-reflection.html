Attributes, Caller Information and Reflection

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-20. The examples are complete console programs that start with Option Strict On; they were built with warnings treated as errors (except where the page says the opposite) and run in the .NET 10 SDK container (Linux, arm64). The CLR and compiler messages include the project’s root namespace, which is ShelfApp for every single-file example (the assembly is named App); the plugin example is a three-project solution. Where an example is meant to fail, the messages shown are the ones the SDK printed.

Three features share this page because they share one mechanism: metadata. The compiler writes information about your code into the assembly, and a running program can read it back. An attribute is metadata that you add; caller information is metadata the compiler fills in for you at each call; reflection is the API that reads it all, and that can also act on what it finds, by creating objects and calling members whose names it learned at run time. Calling members through an Object variable under Option Strict Off is a related but different mechanism, late binding, and has its own page: Early and Late Binding. The C# counterpart is on Attributes and Reflection (C#).

Attributes

An attribute is a class that derives from System.Attribute, applied to a declaration with angle brackets. It does nothing by itself: the compiler stores it in the assembly, and some other code (the compiler, a tool, the runtime, your program) reads it and acts on it. Visual Basic puts the attribute list before the declaration, inside < and >:

<Attribute1(positionalArgument, NamedProperty:=value)>
<Attribute2>
Public Class Example

The syntax is regular:

  • The class name may omit the Attribute suffix: <Obsolete> is ObsoleteAttribute.

  • Positional arguments come first and select a constructor. Named arguments follow and set a public field or property with := (C# uses =), in any order.

  • Parentheses are optional when there are no arguments (<Serializable>).

  • Several attributes can share one list, separated by commas (<Description("a"), Category("b")>), or be written as separate lists. A list may be broken over lines after a comma; a closing > may sit on the next line after a line-continuation underscore.

  • The list is part of the declaration, not a separate statement, so there is no attribute syntax for local variables or statements.

The program below applies attributes to every kind of target Visual Basic allows and then reads each one back by reflection. It exercises the target list in the next table.

Custom attributes

A custom attribute is a class that derives from Attribute. Its constructor parameters become the positional arguments and its public read/write fields and properties become the named ones. AttributeUsage, itself an attribute, controls where it may be applied:

AttributeUsage setting Meaning

ValidOn (first, positional argument)

the AttributeTargets values the attribute may be applied to, combined with Or; the default is All

AllowMultiple:=True

the attribute may appear more than once on the same declaration; the default is False

Inherited:=True

derived classes, and overriding members of derived classes, see the attribute through the inheritance-aware reading APIs; the default is True

Source: Creating custom attributes (Visual Basic)

The program defines a CatalogRule attribute with a constructor argument, properties of five types (String, an enum, an Integer, a String() array and a Type), and AllowMultiple and Inherited set. It applies it to CatalogItem and its members, reads the rules back, and shows what inheritance does:

Public Enum Audience
    Everyone
    Staff
    Admin

                AllowMultiple:=True, Inherited:=True)>
Public NotInheritable Class CatalogRuleAttribute
    Inherits Attribute

    Public ReadOnly Property Name As String
    Public Property Audience As Audience = Audience.Everyone
    Public Property Priority As Integer
    Public Property Tags As String()
    Public Property Handler As Type

    Public Sub New(name As String)
        Me.Name = name
    End Sub

<CatalogRule("NoDuplicates", Priority:=2, Audience:=Audience.Staff)>
<CatalogRule("MaxLoans", Tags:=New String() {"loans", "limits"}, Handler:=GetType(String))>
Public Class CatalogItem
    <CatalogRule("TitleRequired")>
    Public Overridable Property Title As String = ""

    <CatalogRule("OnlyAdmins", Audience:=Audience.Admin)>
    Public Overridable Sub Remove()
    End Sub
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Overrides Sub Remove()
    End Sub

    Public Overrides Property Title As String
End Class

        Dim tags As String = If(rule.Tags Is Nothing, "-", String.Join("/", rule.Tags))
        Dim handler As String = If(rule.Handler Is Nothing, "-", rule.Handler.Name)
        Console.WriteLine($"{label,-26}{rule.Name,-14}audience={rule.Audience,-9}priority={rule.Priority} tags={tags} handler={handler}")
    End Sub

    Sub Main()
        For Each rule As CatalogRuleAttribute In GetType(CatalogItem).GetCustomAttributes(GetType(CatalogRuleAttribute), False)
            Describe("CatalogItem", rule)
        Next

        Next

What the output teaches:

  • Argument types are limited to what a constant can express: numbers, strings, Boolean, enum values, a Type (GetType(String)) and one-dimensional arrays of those (New String() {"loans", "limits"}). The program used a String, an enum, an Integer, a String() and a Type.

  • Reading a missing named argument gives the property’s default: Audience is Everyone and Priority is 0 for the second rule, which set neither.

  • GetCustomAttribute(Of T) is for a single attribute. With AllowMultiple:=True and two attributes present it throws AmbiguousMatchException; use GetCustomAttributes for lists.

  • The inherit flag is honoured for classes and methods but not for properties and events when you read through MemberInfo. The overriding Magazine.Title reported 0 rules through MemberInfo.GetCustomAttributes(type, True) and 1 through Attribute.GetCustomAttributes(member, type, True). If you must support inherited property attributes, use the Attribute class methods (or the CustomAttributeExtensions ones, which call them).

  • IsDefined does not create an attribute instance. It is the cheap way to test for presence, because reading an attribute runs its constructor.

What arguments are allowed

An attribute argument must be a constant the compiler can evaluate: a literal, a Const, a concatenation of constants, NameOf(...), an enum value, GetType(...), or an array of those. A value only known at run time, including a Shared ReadOnly field and a method call, is rejected. The program below uses one example of each:

CallerArgumentExpression

CallerArgumentExpression("name") gives a helper the source text of the argument that the caller wrote for another parameter. What the run shows:

  • The type name includes the project’s root namespace. Type.GetType("Book") is Nothing — there is no exception — and Type.GetType("ShelfApp.Book") finds the type. Type.GetType(name, throwOnError:=True) is the variant that fails loudly.

  • An exception inside the invoked method arrives wrapped in TargetInvocationException; read InnerException. A wrong argument type arrives as ArgumentException before the method runs.

  • Private members are reachable with BindingFlags.NonPublic, which is why reflection over a library you do not own is fragile and why it is a security-sensitive feature in sandboxed code.

The reflection feature that matters most in real applications is finding implementations in an assembly that was not known when the host was compiled. The design decisions in the host:

  • The shared contract lives in a third assembly that both sides reference; the host loads the plugin into a separate AssemblyLoadContext, whose fallback to the default context resolves Contracts to the host’s copy, so IExporter is the same type on both sides. Without a shared contract the plugin’s IExporter would be a different type from the host’s.

  • The test GetType(IExporter).IsAssignableFrom(type) finds the implementations; HiddenExporter implements the interface but is Friend, so a host that wanted only public plugins would also test IsPublic. The compiler’s _Closure$__ class turns up in GetTypes() and is filtered out because it does not implement the interface.

  • The attribute carries the name the plugin wants to be known by. Reading the attribute does not require creating the plugin.

  • isCollectible:=True and Unload() let the runtime free the plugin assembly, but only when nothing references it: the loading code is in a NoInlining method so that no local from the plugin survives in the caller, and the test collects with WeakReference and GC.Collect in a loop. The last line shows the context was collected. A stray reference (a static event handler, a running thread, a cached Type) can keep it alive, and the line then reads False.

  • A real host must not trust arbitrary DLLs; a plugin is code that runs with the host’s rights.

Reflection, trimming and Native AOT

Trimming (PublishTrimmed) and Native AOT (PublishAot) remove code the linker thinks is unused. Reflection reaches code by name at run time, so the linker cannot see it: a type that is only created through Type.GetType(name) may be gone from the published application. The annotations that tell the tools what reflection needs are the attributes DynamicallyAccessedMembers (on a Type parameter, naming the members that will be reflected on), RequiresUnreferencedCode and RequiresDynamicCode (on a method that cannot work when trimmed). They are ordinary attributes, so they work in Visual Basic. The program below has one method of each kind:

Pitfalls checklist

  • An <Assembly: attribute that the SDK also generates is a duplicate (BC30663); set the project property instead or switch off GenerateAssemblyInfo.

  • The reflection name of a type includes the root namespace: Type.GetType("Book") returns Nothing; use the FullName.

  • GetCustomAttribute(Of T) throws AmbiguousMatchException when the attribute allows multiples and appears more than once.

  • MemberInfo.GetCustomAttributes(inherit:=True) does not look at the base member of a property or event; use Attribute.GetCustomAttributes.

  • Reading an attribute runs its constructor; use IsDefined or CustomAttributeData when you only need to know it is there.

  • Caller-information attributes need an Optional parameter of the right type; Visual Basic does not warn when they are wasted.

  • CallerFilePath embeds the build machine’s path; use PathMap for shipped binaries.

  • MethodInfo.Invoke wraps exceptions in TargetInvocationException; unwrap InnerException.

  • Reflection finds the compiler’s own types and members (_Closure$__, _Title, $STATIC$...); filter by IsSpecialName and CompilerGeneratedAttribute.

  • A name used only through reflection can be trimmed away; annotate it with DynamicallyAccessedMembers or keep it with a root descriptor. The Visual Basic build printed no trimming diagnostics here, so run the publish with trim warnings as errors in CI.

  • A collectible AssemblyLoadContext is unloaded only when nothing references it; keep the loading code in a separate non-inlined method and test it.

  • Never load or run code from a path supplied by users.
