Data Access with ADO.NET and EF Core

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example that talks to a database and prints results is a complete program that was built with warnings treated as errors (Option Strict On, root namespace ShelfApp) and run in the .NET 10 SDK container on Linux. Databases that need a server (SQL Server, MongoDB, Redis) cannot run in that container, so the SQL Server code is labelled built, not run; the parts of the SQL Server provider that do not need a server (connection string defaults, the error for an unreachable server) were run. SQLite, which is an in-process engine, stands in for the server wherever a real round trip is needed: Microsoft.Data.Sqlite for ADO.NET and the Microsoft.EntityFrameworkCore.Sqlite provider for EF Core. Package versions used: Microsoft.Data.Sqlite 10.0.13, Microsoft.Data.SqlClient 7.1.1, Microsoft.EntityFrameworkCore.Sqlite 10.0.13, Dapper 2.1.89.

Data access is where Visual Basic differs from C# in several small ways that all come from the same source: the language has no nullable reference types and no Await Using, and the tooling around it (the EF Core command line, the designers) was built for C# first. This page shows what works as in C#, what needs a different spelling, and what does not work at all. The reference scenario is the shelf catalogue; the entities are Book, Author and the others from Shelf.Core.

SQL itself, indexes and schema design are not repeated here: see the SQL reference and the Databases section. EF Core concepts are explained for C# on Data Access with EF Core in the ASP.NET Core section, and the older EF6 on Data Access with EF6; this page covers the Visual Basic spelling and the differences.

ADO.NET provider (Microsoft.Data.SqlClient, Microsoft.Data.Sqlite, Npgsql, …​)

You write SQL, need every provider feature (bulk copy, table-valued parameters, output parameters), or you are building the layer that other tools sit on.

Everything works. Use Using for every disposable; no Await Using.

Works; anonymous types are the usual way to pass parameters. A community project, not a Microsoft one.

Legacy. Not for new development; see the last sections.

Connections, pooling and connection strings

A connection is expensive to open and cheap to keep in a pool. The rule that follows is the same in every language: open late, close early, and let the pool do the sharing. In Visual Basic that means a Using block around every SqlConnection or SqliteConnection; the Dispose at End Using returns the physical connection to the pool, it does not close the socket.

Pooling defaults, and a failed connect, without a server

Two things about SQL Server connections can be checked without a server. The first is what the connection-string builder assumes when you say nothing; the second is what a failed connection looks like. This program was run (a loopback port with nothing listening gives an immediate refusal, so no network is needed):

Option Strict On

Imports Microsoft.Data.SqlClient

Module Offline
    Sub Main()
        Dim builder As New SqlConnectionStringBuilder()
        Console.WriteLine("Defaults of SqlConnectionStringBuilder:")
        Console.WriteLine("  Encrypt             = " & builder.Encrypt.ToString())
        Console.WriteLine("  TrustServerCertificate = " & builder.TrustServerCertificate)
        Console.WriteLine("  Pooling             = " & builder.Pooling)
        Console.WriteLine("  Min / Max Pool Size = " & builder.MinPoolSize & " / " & builder.MaxPoolSize)
        Console.WriteLine("  Connect Timeout     = " & builder.ConnectTimeout)
        Console.WriteLine("  MultipleActiveResultSets = " & builder.MultipleActiveResultSets)

        builder.DataSource = "db.example.test"
        builder.InitialCatalog = "Shelf"
        builder.IntegratedSecurity = True
        builder.ApplicationName = "Shelf.Cli"
        builder.ConnectTimeout = 1
        Console.WriteLine("Built: " & builder.ConnectionString)

        ' Nothing listens on this loopback port, so the failure is immediate and needs no network.
        builder.DataSource = "127.0.0.1,1"
        Using connection As New SqlConnection(builder.ConnectionString)
            Try
                connection.Open()
            Catch ex As SqlException
                Console.WriteLine("SqlException number " & ex.Number & ", class " & ex.Class)
                Console.WriteLine("  message starts: " & ex.Message.Substring(0, ex.Message.IndexOf(" The server")))
            End Try
        End Using
    End Sub
End Module

Read the defaults: pooling is on with a maximum of 100 connections per distinct connection string, the connect timeout is 15 seconds, and, since version 4 of Microsoft.Data.SqlClient, Encrypt is True and TrustServerCertificate is False. A program that used to connect to a development server with a self-signed certificate through System.Data.SqlClient therefore fails with a certificate error after the switch. The fix for a real server is a valid certificate. For a throw-away local server, TrustServerCertificate=True makes the error go away and removes the protection, so keep it out of production configuration. A failed connect raises SqlException, whose Number is 0 for transport failures and a server error number once the server answered; the text of the transport message varies by operating system, which is why the program prints only its first sentence.

Source: SQL Server connection pooling and SqlConnectionStringBuilder

Pooling rules that matter (SQL Server):

  • A pool belongs to one connection string (character for character), one process and, with integrated security, one identity. Ten strings that differ only by Application Name make ten pools.

  • A connection that is not disposed is not returned: the classic symptom is InvalidOperationException ("Timeout expired. The timeout period elapsed prior to obtaining a connection from the pool"). Visual Basic’s Using makes the correct code the short code; the leak appears when the connection is stored in a field and nobody owns its disposal.

  • SqlConnection.ClearAllPools() and ClearPool(connection) exist for tests and for failover; do not call them in normal code.

  • Microsoft.Data.Sqlite pools too (the Pooling keyword; New SqliteConnectionStringBuilder().Pooling is True, see the check below) and its in-memory databases live only as long as one connection stays open, which is why the EF examples below keep a connection open for the duration.

Source: Connection pooling and SQLite connection strings

Connection strings come from configuration

A connection string holds a server name and often credentials. It does not belong in source code, in the repository, or in a compiled resource. Read it from configuration at start-up, and keep the secret part in a store that is not in the repository: environment variables, dotnet user-secrets for development, a cloud key vault or the platform’s secret manager in production, or integrated authentication so that there is no secret at all. Microsoft.Extensions.Configuration layers sources, and later sources override earlier ones. The program writes a small appsettings.json, then overrides the value with an environment variable (the double underscore stands for the : separator):

Option Strict On

Imports System.IO
Imports Microsoft.Data.Sqlite
Imports Microsoft.Extensions.Configuration

Module ConfigDemo
    Sub Main()
        Dim folder = Path.Combine(Path.GetTempPath(), "shelf-config-demo")
        Directory.CreateDirectory(folder)
        File.WriteAllText(Path.Combine(folder, "appsettings.json"),
            "{ ""ConnectionStrings"": { ""Shelf"": ""Data Source=shelf-dev.db;Cache=Shared"" } }")

        Dim configuration = New ConfigurationBuilder().
            SetBasePath(folder).
            AddJsonFile("appsettings.json", optional:=False).
            AddEnvironmentVariables(prefix:="SHELF_").
            Build()

        Dim fromFile = configuration.GetConnectionString("Shelf")
        Console.WriteLine("From appsettings.json: " & fromFile)

        Environment.SetEnvironmentVariable("SHELF_ConnectionStrings__Shelf", "Data Source=:memory:")
        Dim withEnvironment = New ConfigurationBuilder().
            SetBasePath(folder).
            AddJsonFile("appsettings.json", optional:=False).
            AddEnvironmentVariables(prefix:="SHELF_").
            Build()
        Dim effective = withEnvironment.GetConnectionString("Shelf")
        Console.WriteLine("With SHELF_ConnectionStrings__Shelf set: " & effective)

        Dim builder As New SqliteConnectionStringBuilder(effective)
        builder.Mode = SqliteOpenMode.ReadWriteCreate
        builder.Pooling = False
        Console.WriteLine("Normalised: " & builder.ConnectionString)

        Using connection As New SqliteConnection(builder.ConnectionString)
            connection.Open()
            Console.WriteLine("Opened, server version " & connection.ServerVersion.Split("."c)(0) & ".x")
        End Using
        File.Delete(Path.Combine(folder, "appsettings.json"))
    End Sub
End Module

Visual Basic specifics seen in this program: named arguments use := (optional:=False); the extension methods AddJsonFile and AddEnvironmentVariables need their packages and Imports Microsoft.Extensions.Configuration; and a local variable named directory would hide System.IO.Directory because names are not case-sensitive (the first version of this program failed with BC30456, 'CreateDirectory' is not a member of 'String', for exactly that reason). Commands, parameters and readers

The first program uses everything in the basic cycle: create a table, insert rows with parameters, read a scalar, and read rows with a reader. It was built and run:

Option Strict On

Imports Microsoft.Data.Sqlite

Module Basics
    Private Structure BookSeed
        Public Title As String
        Public Year As Integer
        Public Isbn As String
        Public Subtitle As String
    End Structure

    Sub Main()
        Dim seeds = {
            New BookSeed With {.Title = "Dune", .Year = 1965, .Isbn = "9780441172719"},
            New BookSeed With {.Title = "Neuromancer", .Year = 1984, .Isbn = "9780441569595", .Subtitle = "A novel"},
            New BookSeed With {.Title = "Hyperion", .Year = 1989, .Isbn = "9780553283686"}}

        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()

            Using create = connection.CreateCommand()
                create.CommandText =
                    "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT NOT NULL, Year INTEGER NOT NULL, Isbn TEXT NOT NULL UNIQUE, Subtitle TEXT NULL)"
                create.ExecuteNonQuery()
            End Using

            Using insert = connection.CreateCommand()
                insert.CommandText = "INSERT INTO Books (Title, Year, Isbn, Subtitle) VALUES ($title, $year, $isbn, $subtitle)"
                insert.Parameters.Add("$title", SqliteType.Text)
                insert.Parameters.Add("$year", SqliteType.Integer)
                insert.Parameters.Add("$isbn", SqliteType.Text)
                insert.Parameters.Add("$subtitle", SqliteType.Text)

                For Each seed In seeds
                    insert.Parameters("$title").Value = seed.Title
                    insert.Parameters("$year").Value = seed.Year
                    insert.Parameters("$isbn").Value = seed.Isbn
                    insert.Parameters("$subtitle").Value = If(seed.Subtitle Is Nothing, DBNull.Value, CObj(seed.Subtitle))
                    Console.WriteLine($"Inserted {insert.ExecuteNonQuery()} row: {seed.Title}")
                Next
            End Using

            Using count = connection.CreateCommand()
                count.CommandText = "SELECT COUNT(*) FROM Books WHERE Year > $year"
                count.Parameters.Add("$year", SqliteType.Integer).Value = 1970
                Dim total = CLng(count.ExecuteScalar())
                Console.WriteLine($"Books after 1970: {total}")
            End Using

            Using query = connection.CreateCommand()
                query.CommandText = "SELECT Id, Title, Year, Subtitle FROM Books ORDER BY Year"
                Using reader = query.ExecuteReader()
                    Dim title = reader.GetOrdinal("Title")
                    Dim subtitle = reader.GetOrdinal("Subtitle")
                    While reader.Read()
                        Dim text = If(reader.IsDBNull(subtitle), "(none)", reader.GetString(subtitle))
                        Console.WriteLine($"{reader.GetInt32(0)}: {reader.GetString(title)} [{reader.GetInt32(2)}] subtitle={text}")
                    End While
                End Using
            End Using
        End Using
    End Sub
End Module

Points to take from it:

  • Parameters, always. Every value that comes from outside the program goes in a parameter. The SQL text stays constant, the provider sends the values separately and the database never parses them as SQL. With SQL Server the idiom is command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn: the type and size are explicit, so the plan cache sees one statement. Parameters.AddWithValue("@isbn", isbn) is shorter and lets the provider infer the type from the .NET value, which produces a different parameter size for each string length and, for String against a varchar column, an implicit conversion that can stop an index from being used. Prefer Add(name, type[, size]).Value. Microsoft.Data.Sqlite accepts both and is not affected by the plan-cache issue; every example on this page still uses typed Add, so the habit carries over to SQL Server unchanged.

  • Parameters.Add(...) returns the new parameter, so .Value = x can be chained onto it, as in command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn in the SQL Server listing below. The first program declares the parameters once and sets Value through the collection by name.

  • Reuse one command in a loop. Declare the parameters once, change Value for each row, call ExecuteNonQuery. The program above inserts three rows with one prepared command shape.

  • Readers are forward-only and hold the connection. Read by ordinal (GetOrdinal once, outside the loop) with the typed getters (GetInt32, GetString), not by reader("Title") in a loop, which does a name lookup for every row and returns Object that Option Strict On makes you convert.

  • ExecuteScalar returns Object: convert it (CLng(...); SQLite’s COUNT(*) is a 64-bit integer, SQL Server’s is a 32-bit one, and CInt on a boxed Long is a conversion, not an unboxing). ExecuteNonQuery returns the number of rows affected.

Nothing is not NULL

The most Visual Basic-specific mistake in data access is to pass Nothing for a missing value. In .NET, a database NULL is the singleton DBNull.Value; Nothing is a null reference, which the provider treats as "no value was supplied". This program shows what the provider does with each, and the other classic ADO.NET failures: a closed connection, a constraint violation, SQL built by concatenation, and reading NULL with a typed getter:

Option Strict On

Imports Microsoft.Data.Sqlite

Module Pitfalls
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            ' 1. A command on a closed connection
            Using command = connection.CreateCommand()
                command.CommandText = "SELECT 1"
                Try
                    command.ExecuteScalar()
                Catch ex As InvalidOperationException
                    Console.WriteLine("Closed connection: " & ex.Message)
                End Try
            End Using

            connection.Open()
            Using create = connection.CreateCommand()
                create.CommandText = "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT NOT NULL, Isbn TEXT NOT NULL UNIQUE, Subtitle TEXT NULL)"
                create.ExecuteNonQuery()
            End Using

            ' 2. Nothing is not NULL
            Using insert = connection.CreateCommand()
                insert.CommandText = "INSERT INTO Books (Title, Isbn, Subtitle) VALUES ($title, $isbn, $subtitle)"
                insert.Parameters.Add("$title", SqliteType.Text).Value = "Dune"
                insert.Parameters.Add("$isbn", SqliteType.Text).Value = "9780441172719"
                insert.Parameters.Add("$subtitle", SqliteType.Text).Value = Nothing
                Try
                    insert.ExecuteNonQuery()
                Catch ex As InvalidOperationException
                    Console.WriteLine("Value Nothing: " & ex.Message)
                End Try
                insert.Parameters("$subtitle").Value = DBNull.Value
                Console.WriteLine("Value DBNull.Value: inserted " & insert.ExecuteNonQuery())
            End Using

            ' 3. A constraint violation
            Using duplicate = connection.CreateCommand()
                duplicate.CommandText = "INSERT INTO Books (Title, Isbn) VALUES ('Dune again', '9780441172719')"
                Try
                    duplicate.ExecuteNonQuery()
                Catch ex As SqliteException
                    Console.WriteLine($"SqliteException {ex.SqliteErrorCode}/{ex.SqliteExtendedErrorCode}: {ex.Message}")
                End Try
            End Using

            ' 4. Concatenated text versus a parameter
            Dim hostile = "x' OR '1'='1"
            Using unsafeCommand = connection.CreateCommand()
                unsafeCommand.CommandText = "SELECT COUNT(*) FROM Books WHERE Title = '" & hostile & "'"
                Console.WriteLine("Concatenated: " & unsafeCommand.CommandText)
                Console.WriteLine("  rows matched: " & CLng(unsafeCommand.ExecuteScalar()))
            End Using
            Using safeCommand = connection.CreateCommand()
                safeCommand.CommandText = "SELECT COUNT(*) FROM Books WHERE Title = $title"
                safeCommand.Parameters.Add("$title", SqliteType.Text).Value = hostile
                Console.WriteLine("Parameterised: " & safeCommand.CommandText)
                Console.WriteLine("  rows matched: " & CLng(safeCommand.ExecuteScalar()))
            End Using

            ' 5. Reading a NULL column without checking
            Using query = connection.CreateCommand()
                query.CommandText = "SELECT Subtitle FROM Books"
                Using reader = query.ExecuteReader()
                    reader.Read()
                    Try
                        Console.WriteLine(reader.GetString(0))
                    Catch ex As InvalidOperationException
                        Console.WriteLine("GetString on NULL: " & ex.Message)
                    End Try
                    Console.WriteLine("GetValue on NULL is DBNull: " & (reader.GetValue(0) Is DBNull.Value))
                End Using
            End Using
        End Using
    End Sub

Source: SQLite errors and SQL injection

The fifth block is worth understanding because it is the SQL injection demonstration in miniature. The concatenated text x' OR '1'='1 closes the string literal and adds a condition that is always true, so the query matches a row that does not have that title; the same text sent as a parameter is just an unusual title and matches nothing. With a database that supports stacked statements the same technique deletes tables. SQL injection is the only item on this page that can end a company, and the defence is mechanical: parameters for values, an allow-list for identifiers (a column name cannot be a parameter), least-privilege database accounts, and no string building of SQL. See Security and Cryptography for the rest of the security picture.

Transactions

A transaction makes a group of commands atomic. BeginTransaction returns an object that must be disposed; if neither Commit nor Rollback ran, disposing rolls back. With Microsoft.Data.Sqlite (as with SqlClient when you use explicit transactions) each command must be told which transaction it belongs to. This program moves stock between two shelves; the second transfer violates a CHECK constraint and rolls back:

Option Strict On

Imports Microsoft.Data.Sqlite

Module Transactions
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()
            Execute(connection, "CREATE TABLE Accounts (Name TEXT PRIMARY KEY, Balance INTEGER NOT NULL CHECK (Balance >= 0))")
            Execute(connection, "INSERT INTO Accounts VALUES ('Reading room', 100), ('Archive', 50)")

            Transfer(connection, "Reading room", "Archive", 30)
            Transfer(connection, "Reading room", "Archive", 500)
            PrintBalances(connection)
        End Using
    End Sub

    Private Sub Transfer(connection As SqliteConnection, source As String, target As String, amount As Integer)
        Using transaction = connection.BeginTransaction()
            Try
                Move(connection, transaction, source, -amount)
                Move(connection, transaction, target, amount)
                transaction.Commit()
                Console.WriteLine($"Committed: {amount} from {source} to {target}")
            Catch ex As SqliteException
                transaction.Rollback()
                Console.WriteLine($"Rolled back ({ex.SqliteErrorCode}): {ex.Message}")
            End Try
        End Using
    End Sub

    Private Sub Move(connection As SqliteConnection, transaction As SqliteTransaction, name As String, delta As Integer)
        Using command = connection.CreateCommand()
            command.Transaction = transaction
            command.CommandText = "UPDATE Accounts SET Balance = Balance + $delta WHERE Name = $name"
            command.Parameters.Add("$delta", SqliteType.Integer).Value = delta
            command.Parameters.Add("$name", SqliteType.Text).Value = name
            command.ExecuteNonQuery()
        End Using
    End Sub

    Private Sub Execute(connection As SqliteConnection, sql As String)
        Using command = connection.CreateCommand()
            command.CommandText = sql
            command.ExecuteNonQuery()
        End Using
    End Sub

    Private Sub PrintBalances(connection As SqliteConnection)
        Using command = connection.CreateCommand()
            command.CommandText = "SELECT Name, Balance FROM Accounts ORDER BY Name"
            Using reader = command.ExecuteReader()
                While reader.Read()
                    Console.WriteLine($"{reader.GetString(0)}: {reader.GetInt32(1)}")
                End While
            End Using
        End Using
    End Sub
End Module

Rules of thumb: keep transactions short, open them as late as possible and commit as early as possible; never wait for a user inside one; catch the specific exception you can handle (SqlException with a known Number, such as 1205 for a deadlock victim in SQL Server, after which the whole unit of work may be retried) and roll back in every other case. System.Transactions.TransactionScope is the ambient alternative and also works with the providers; it enlists connections that open inside the scope, which can silently escalate to a distributed transaction when two connection strings are used. Prefer the explicit transaction unless the code you call is outside your control.

Visual Basic notes on this listing:

  • Catch ex As SqlException When ex.Number = 1205 is Visual Basic’s exception filter (C# added the same idea as catch ... when in C# 6). The filter runs before the stack unwinds, so an exception that no Catch matches is not caught at all.

  • Return If(result Is Nothing OrElse result Is DBNull.Value, CType(Nothing, Integer?), CInt(result)) is how a function returns Integer?: the CType(Nothing, Integer?) types the first operand, and CInt converts to Integer, which widens to Integer?.

  • A stored procedure needs CommandType.StoredProcedure, the procedure name as the command text, and ParameterDirection.Output for output parameters, whose Value is available after ExecuteNonQuery (and, for a reader, only after the reader is closed).

  • SqlCommandBuilder generates the INSERT, UPDATE and DELETE for an adapter from its SELECT, which must return the primary key. It is convenient for tools and small tables; for a real data layer, write the commands or use EF Core.

  • SqlBulkCopy is the fast way to load many rows; it has no equivalent in EF Core (EF’s own bulk helpers are ExecuteUpdate and ExecuteDelete).

  • The Using blocks dispose synchronously even inside Async methods. Provider objects implement IAsyncDisposable, but without Await Using Visual Basic code cannot call DisposeAsync in a Finally; in practice the synchronous Dispose of a pooled connection is cheap.

    Public Sub Add(item As CatalogItem) Implements ICatalogStore.Add
        Using command = _connection.CreateCommand()
            command.CommandText = "INSERT INTO Items (Kind, Title, Year, Isbn, Issue, Authors) VALUES ($kind, $title, $year, $isbn, $issue, $authors); SELECT last_insert_rowid()"
            command.Parameters.Add("$kind", SqliteType.Text).Value = item.Kind
            command.Parameters.Add("$title", SqliteType.Text).Value = item.Title

The model and the context

Keep the migrations in a small C# project

The supported route, and the one this page tested. The model (DbContext and entities) stays in Visual Basic; a C# class library holds the generated migrations; the application and the tooling reference both.

A package that adds a Visual Basic code generator to dotnet ef design time. As checked on 2026-10-19, the newest release on NuGet is 8.0.0 (for EF Core 8; earlier ones 7.0.0 and 6.x previews). See the test below: it does not work with EF Core 10.

A migration is a class that derives from Migration with Up and Down methods that call MigrationBuilder; it can be written in Visual Basic, and the ModelSnapshot has to be kept in step by hand, which is the part nobody wants.

Binding query results to Windows Forms and WPF

For a grid in Windows Forms the shape is: load into a list, wrap it in a BindingList(Of T) or a BindingSource, set DataGridView.DataSource. EF Core can also provide a ready local view (context.Books.Local.ToBindingList()), which stays in step with the change tracker. The listing below was built, not run (Windows Forms needs Windows); the Async Sub override is the correct place to start asynchronous loading because it runs on the UI thread and resumes there.

Option Strict On

Imports System.ComponentModel
Imports System.Windows.Forms
Imports Microsoft.EntityFrameworkCore

Public Class BookRow
    Public Property Id As Integer
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Public Class RowsContext
    Inherits DbContext

    Public Property Books As DbSet(Of BookRow)

    Protected Overrides Sub OnConfiguring(optionsBuilder As DbContextOptionsBuilder)
        optionsBuilder.UseSqlite("Data Source=shelf.db")
    End Sub
End Class

Public Class BookGridForm
    Inherits Form

    Private ReadOnly _grid As New DataGridView() With {.Dock = DockStyle.Fill, .AutoGenerateColumns = True}
    Private ReadOnly _source As New BindingSource()
    Private ReadOnly _rows As New BindingList(Of BookRow)

    Public Sub New()
        Text = "Shelf"
        _source.DataSource = _rows
        _grid.DataSource = _source
        Controls.Add(_grid)
    End Sub

    Public Shared Function TrackedRows(context As RowsContext) As BindingList(Of BookRow)
        ' A binding list that stays in step with the change tracker.
        Return context.Books.Local.ToBindingList()
    End Function

    Protected Overrides Async Sub OnShown(e As EventArgs)
        MyBase.OnShown(e)
        Using context As New RowsContext()
            ' AsNoTracking: the grid edits copies; save them explicitly with a separate unit of work.
            Dim loaded = Await context.Books.AsNoTracking().OrderBy(Function(b) b.Title).ToListAsync()
            _rows.RaiseListChangedEvents = False
            For Each row In loaded
                _rows.Add(row)
            Next
            _rows.RaiseListChangedEvents = True
            _rows.ResetBindings()
        End Using
    End Sub
End Class

Public Module Program
    <STAThread>
    Public Sub Main()
        Application.EnableVisualStyles()
        Application.Run(New BookGridForm())
    End Sub
End Module

Source: Windows Forms for .NET

Notes: the entity here is a row class for the grid, with settable properties (a grid cannot edit read-only ones); the context loads with AsNoTracking because the grid edits copies and the program saves them explicitly; RaiseListChangedEvents = False while adding many rows avoids one grid refresh per row; do not keep the context alive for the lifetime of the form. For WPF the equivalent is an ObservableCollection(Of BookViewModel) that the view model fills after Await returns (see WPF Applications), and a DataTable.DefaultView binds to a DataGrid in both frameworks. The Windows Forms details (BindingSource, DataGridView columns) are on Windows Forms Applications.

Other stores: MongoDB and Redis

Document and key-value stores have their own drivers, which are .NET libraries and therefore work from Visual Basic. The listing was built, not run: it needs servers on localhost. It uses MongoDB.Driver 3.12.0 and StackExchange.Redis 3.4.5 with expression lambdas in the queries (the Mongo Find takes an expression tree, as LINQ does):

Option Strict On

Imports MongoDB.Bson
Imports MongoDB.Driver
Imports StackExchange.Redis

' Built, not run: both stores need a running server.
Public Class BookDocument
    Public Property Id As ObjectId
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Module Program
    Sub Main()
        RunAsync().GetAwaiter().GetResult()
    End Sub

    Private Async Function RunAsync() As Task
        Dim client As New MongoClient("mongodb://localhost:27017")
        Dim books = client.GetDatabase("shelf").GetCollection(Of BookDocument)("books")
        Await books.InsertOneAsync(New BookDocument With {.Title = "Dune", .Year = 1965})
        Dim newer = Await books.Find(Function(b) b.Year > 1960).SortBy(Function(b) b.Title).ToListAsync()
        Console.WriteLine("Mongo documents: " & newer.Count)

        Dim redis = Await ConnectionMultiplexer.ConnectAsync("localhost:6379")
        Dim db = redis.GetDatabase()
        Await db.StringSetAsync("book:1:title", "Dune", TimeSpan.FromMinutes(5))
        Dim cached As RedisValue = Await db.StringGetAsync("book:1:title")
        Console.WriteLine("Redis value: " & cached.ToString())
    End Function
End Module

The data models, indexing and operations of these stores are explained with their native tools in MongoDB drivers and tooling and Redis clients and client-side caching; Choosing the right database helps to decide which store a feature needs.

Legacy: EF6, LINQ to SQL and typed DataSets

  • EF6 (EntityFramework 6.x, the System.Data.Entity namespace) is in maintenance. The 6.5 line targets .NET and .NET Framework: a project test on .NET 10 restored EntityFramework 6.5.1, compiled a DbContext-derived class, and loaded the assembly at run time (EF6 type loaded: EntityFramework 6.0.0.0, Runtime: .NET 10.0.13). The test did not open a database; the EDMX designer and the Package Manager Console commands of EF6 (Enable-Migrations, Update-Database) were not exercised. For an application that already uses EF6, keeping it on .NET Framework is legitimate; moving to .NET 10 is a port to EF Core in practice, covered for C# on Data Access with EF6. The official guide for the move is Port from EF6 to EF Core.

  • LINQ to SQL (System.Data.Linq, .dbml designer files) is documented in the .NET Framework data documentation (the link below sits under /dotnet/framework/), not in the .NET documentation. Plan to port a program that uses it to EF Core or Dapper as part of a move to .NET 10.

  • Typed DataSets generated by older Visual Studio wizards are plain code on top of System.Data and port easily, but they are not a model to start from.

  • System.Data.OracleClient and System.Data.SqlClient are the old provider names; see the opening table.
