Visual Basic for Programmers of Other Languages

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was checked on 2026-10-19 against Visual Basic 17.13 on .NET 10 (LTS, SDK 10.0.402); .NET 11 was a release candidate that day and is treated as upcoming. It is written for someone who already programs in another language and wants to read and write Visual Basic without being surprised. Every program on it was built with Option Strict On and warnings as errors and run in the official mcr.microsoft.com/dotnet/sdk:10.0 container image, and the output shown is the real output. The page starts with the dozen rules that cause most of the surprises, each shown by a program, then gives side-by-side maps to C#, Java and VB6/VBA, a flowchart that answers "which Visual Basic feature replaces …​", and a list of the usual mistakes. The language is explained in order starting from Program Structure and Code Conventions; the platform it runs on is the same as C#'s, see Visual Basic and .NET.

Visual Basic and C# compile to the same intermediate language for the same runtime, and they share the .NET libraries, so most of what matters about the platform (collections, LINQ, async, IDisposable, generics) is identical. The differences are in the syntax, in a few semantic defaults inherited from older BASIC dialects, and in a handful of features that only Visual Basic has. The C# reference is at C# and .NET and the Java reference starts at Java Getting Started.

The surprises at a glance

Surprise Rule Page

Names ignore case

Copies, copies and COPIES are the same identifier, and so are Console.WriteLine and console.writeline. Two names that differ only in case in the same scope clash.

Program Structure and Code Conventions

Statements end at the end of the line

There are no semicolons. A statement continues on the next line after an operator, a comma or an opening bracket (implicit continuation since Visual Basic 10), or after an explicit _. A colon puts several statements on a line.

Program Structure and Code Conventions

Option Strict is off in a new project

The compiler allows implicit narrowing and late binding unless Option Strict On is set, in the file or in the project.

Option Statements

Array declarations give the upper bound

Dim shelf(3) As String creates four elements, indexed 0 to 3.

Arrays

= assigns and compares

The meaning depends on the position: a statement that starts with a target assigns; inside an expression it compares. There is no ==.

Operators and Expressions

/ and \ are different operators

/ is floating-point division, \ is integer division, Mod is the remainder.

Operators and Expressions

^ is exponentiation, and gives a Double

2 ^ 3 is the Double 8. It is not exclusive-or; that is Xor.

Operators and Expressions

& concatenates

Use & to join strings. + also works on strings, but is addition when both operands are numbers, so avoid it for text.

Strings and Text

And and Or do not short-circuit

Both operands are always evaluated. AndAlso and OrElse are the short-circuit forms, and the ones to use in conditions. And, Or, Xor and Not are also the bitwise operators on integers.

Control Flow

Nothing is a default value, not only null

For a reference type it is the null reference; for a value type it is the default (0, False, a zeroed structure).

Nothing and Nullable Value Types

True is -1 as a number

CInt(True) is -1, although Convert.ToInt32(True) is 1. Booleans print as True and False.

Type Conversions

Arithmetic overflow throws

Integer arithmetic is checked by default (the C# default is unchecked).

Numbers and Math

Module, Handles, My and XML literals

Features that only Visual Basic has: a type with only shared members and no static keyword, event handling by name with Handles, an application-wide helper namespace, and XML written directly in the code.

Names, lines and defaults

Names ignore case

The compiler treats identifiers case-insensitively, as BASIC always did. A variable declared as copies can be used as COPIES, and console.writeline is Console.WriteLine. In Visual Studio the editor rewrites each use to the case of the declaration, so in practice you rarely type the variants by accident, and the habit of naming a field Title and a parameter title that C# programmers rely on still works, because the two live in different scopes and Me.Title disambiguates them. What does not work is a same-scope pair that differs only in case.

Option Strict On

Module Program

    Sub Main()
        Dim line As String = "Reference"
        Dim Line As Integer = 3
        Console.WriteLine(line)
    End Sub

End Module
Program.vb(7,13): error BC30288: Local variable 'Line' is already declared in the current block.

Case-insensitivity has a consequence for type names too. A local variable named host is refused when the same method also uses the type Host (BC32000: Local variable 'host' cannot be referred to before it is declared), as met on Visual Basic and .NET. The usual cure is the same as in any language: a different name. Naming conventions for Visual Basic (PascalCase for types and members, camelCase for locals and parameters, no Hungarian prefixes) are on XML Documentation, Analyzers and Code Style.

Several surprises in one program

The next program shows case-insensitive names, upper-bound array declarations, = as assignment and comparison, Nothing as a default, and the meaning of one As clause for several names.

Points to take from the output:

  • Dim shelf(3) As String holds 4 elements: Length is 4 and the upper bound is 3. The number is the upper bound, the opposite of a C# or Java new string[3]. Dim grid(2, 4) is a 3 by 5 array. The initializer form New String(3) {} follows the same rule. Because the declaration is an upper bound, a loop is written For i = 0 To shelf.Length - 1 or For i = 0 To UBound(shelf), and an off-by-one is a classic mistake in code ported from other languages (see Arrays).

  • The statement COPIES += 1 is an assignment; the same = in Dim b As Boolean = a = 5 first compares a with 5 and then assigns the result to b. There is no way to assign inside an expression, so the C# idiom while line = reader.ReadLine( != null) has no direct form; Visual Basic reads the line first and tests it, or uses Do ... Loop Until.

  • Nothing assigned to an Integer, a Boolean or a structure gives the default value, not a null reference. The last line of that block is a classic trap: comparing an empty string with Nothing using = gives True, because the string comparison treats a null string and an empty string as equal, while the reference test Is Nothing says False. Use String.IsNullOrEmpty when you mean either.

  • In Dim low, high As Integer both names are Integer, unlike VB6 where only the last one was typed.

Lines, continuation and comments

A statement ends at the end of the physical line. A long expression can be broken after an operator, a comma, an opening bracket or brace, a ., and several keywords without any marker (implicit line continuation, Visual Basic 10); anywhere else a trailing underscore continues the line, and since Visual Basic 16 a comment is allowed after it. Comments start with an apostrophe and run to the end of the line (Rem is an old alternative); there is no block comment. ''' starts an XML documentation comment. A colon separates statements on one line, which the examples of this reference avoid except for a very short pair. A single-line If ... Then ... Else ... needs no End If; a block If does, and its ElseIf is one word. The line-oriented grammar also means that braces appear only in array and collection initializers ({10, 20, 30}) and in object initializers (With {.Name = "Reference"}), never around blocks.

Source: Nullable value types, Type characters

Five more points from it. A comparison with a nullable value that holds Nothing is itself Nothing (a null Boolean?), and an If treats it as false, so both copies = 1 and copies <> 1 were false above and the Else ran: this three-valued logic is different from C#, where == on a null nullable gives false and != gives true. String literals have no backslash escapes: a double quote is doubled (""), and the control characters are the constants vbTab, vbCrLf, vbNewLine or Environment.NewLine. A one-character Char literal carries the suffix c ("x"c), because "x" is a string. Indexing an array or calling a method both use parentheses, so items(1) is the second element, and the same brackets are used for generic type arguments with the keyword Of (List(Of String)). Literal suffixes are letters (L, UI, F, R, D) rather than C#'s L, u, f, d, m.

Numbers and operators

Option Strict On

Module Program

    Function Loud(label As String, value As Boolean) As Boolean
        Console.WriteLine("  evaluated " & label)

What each block teaches:

  • Division. 7 / 2 is the Double 3.5 even for two integers, so dividing integers never loses the fraction by accident; 7 \ 2 is the integer 3 and -7 \ 2 is -3 (it truncates toward zero). Dividing by a zero variable with \ or Mod throws DivideByZeroException, while 7 / zero prints Infinity and throws nothing, because it is floating-point; a literal zero (7 \ 0) is refused at compile time (BC30542, division by zero occurred while evaluating this expression). See Numbers and Math.

  • Power. 2 ^ 3 is a Double; to get an integer, convert (CInt(2 ^ 3)). ^ binds tighter than the unary minus on its left (-2 ^ 2 is -4, checked), and the operator is left-associative, so 2 ^ 3 ^ 2 is 64, not 512 (checked). The precedence ladder is on Operators and Expressions.

  • Strings. "Copies: " & 3 & 4 is Copies: 34: & always converts both sides to strings. 3 + 4 is 7. Mixing a string and a number with + is allowed only when Option Strict is off, where the compiler tries to convert the text to a number and can fail at run time; with Option Strict On "Total: " + 3 does not compile (BC30512, no implicit conversion from 'String' to 'Double').

  • Logic. The output shows And evaluating right although left was already False; AndAlso stopped after the left operand. In conditions that guard against Nothing (If x IsNot Nothing AndAlso x.Length > 0) only the short-circuit forms are correct. On integers, And, Or, Xor and Not are bitwise; the same word is the logical operator when both operands are Boolean.

  • Booleans. CInt(True) is -1 (all bits set, the VB6 convention kept for compatibility) while Convert.ToInt32(True) is 1. Do not use the numeric value of a Boolean for anything.

  • Overflow. Adding 1 to an Integer variable that holds Integer.MaxValue throws OverflowException in Visual Basic (a constant expression such as Integer.MaxValue + 1 is refused at compile time instead). C# wraps around silently unless checked is used. The project property RemoveIntegerChecks turns checking off (see Projects, MSBuild and the dotnet CLI).

Bitwise and comparison operators next to C#

Module Program

    Sub Main()
        Dim flags As Integer = 5                      ' binary 101
        Console.WriteLine(flags And 3)                ' bitwise on integers (C# &)

Visual Basic’s own constructs

Modules, shared members and the missing static

C# has static class; Java has static members; Visual Basic has the Module. Every member of a module is implicitly shared, nobody can create an instance of it, and its members can be called without the module’s name from anywhere in the same namespace, which makes a module the natural home for helper functions and for Sub Main. Shared marks a static member of an ordinary class, and Static (a different word) declares a local variable that keeps its value between calls. The program below puts the common C# and Java constructs next to their Visual Basic form; every comment names the construct it replaces.

Option Strict On

Imports System.IO

' abstract class            -> MustInherit            virtual / override -> Overridable / Overrides
Public MustInherit Class CatalogItem
    Public Property Title As String
    Public Shared Count As Integer                              ' static field -> Shared

    Protected Sub New(title As String)
        Me.Title = title                                        ' this -> Me
        Count += 1
    End Sub

    Public MustOverride ReadOnly Property Kind As String
    Public Overridable Function Describe() As String
        Return Kind & ": " & Title
    End Function
End Class

Public Class Book
    Inherits CatalogItem                                        ' class Book : CatalogItem
    Public Sub New(title As String)
        MyBase.New(title)                                       ' base(title) -> MyBase.New
    End Sub
    Public Overrides ReadOnly Property Kind As String
        Get
            Return "Book"
        End Get
    End Property
End Class

Public NotInheritable Class Magazine                            ' sealed -> NotInheritable
    Inherits CatalogItem
    Friend ReadOnly Issue As Integer                            ' internal readonly -> Friend ReadOnly
    Public Sub New(title As String, issue As Integer)
        MyBase.New(title)
        Me.Issue = issue
    End Sub
    Public Overrides ReadOnly Property Kind As String
        Get
            Return "Magazine"
        End Get
    End Property
    Public Overrides Function Describe() As String
        Return MyBase.Describe() & " #" & Issue
    End Function
End Class

' static class -> Module: every member is shared, no instance can be created
Module Toolbox

    Private ReadOnly Gate As New Object()

    Iterator Function Countdown(start As Integer) As IEnumerable(Of Integer)   ' yield return -> Yield
        For i As Integer = start To 1 Step -1
            Yield i
        Next
    End Function

    Function Grade(copies As Integer) As String                 ' switch -> Select Case
        Select Case copies
            Case 0
                Return "none"
            Case 1 To 3
                Return "few"
            Case Is > 3
                Return "many"
            Case Else
                Return "invalid"
        End Select
    End Function

    Function Visits() As Integer
        Static calls As Integer                                  ' static local -> Static
        SyncLock Gate                                            ' lock (gate) -> SyncLock
            calls += 1
        End SyncLock
        Return calls
    End Function

    Function Sum(ParamArray values As Integer()) As Integer      ' params -> ParamArray
        Return values.Sum()
    End Function

    Sub Swap(ByRef a As Integer, ByRef b As Integer)             ' ref / out -> ByRef
        Dim t As Integer = a
        a = b
        b = t
    End Sub
End Module

Things worth noticing in that program. Module Toolbox has a Private ReadOnly Gate field and no Shared keyword anywhere: inside a module everything is shared. Visits() printed 12 for two calls because the Static local calls survives between calls (the two numbers are printed one after the other without a separator because & joins them). Select Case never falls through: each Case ends the statement, so there is no break; a Case can list values (Case 1, 3, 5), a range (1 To 3) or a comparison (Is > 3). TypeOf item Is Book is the type test, TryCast is the as operator (it returns Nothing when the cast fails), and DirectCast and CType are the casts that throw. A method that returns a value uses Return; the older habit of assigning to the function’s name still compiles and is covered on Procedures: Sub and Function. The module pattern, Shared members and the Static statement are on Modules and Shared Members.

Events: Handles and WithEvents

C# attaches a handler with +=. Visual Basic offers that too (AddHandler) and a declarative form: a field declared WithEvents can have methods that say which of its events they handle, with a Handles clause. Windows Forms code generated by the designer uses the second form for every control. The program shows both.

Option Strict On

Public Class Loan
    Public Event Returned As EventHandler                      ' public event EventHandler Returned;

    Public Sub [Return]()
        RaiseEvent Returned(Me, EventArgs.Empty)                ' Returned?.Invoke(this, EventArgs.Empty)
    End Sub
End Class

Public Class Desk
    Private WithEvents _loan As New Loan()                      ' a field that raises events, handled by name

    Private Sub OnReturned(sender As Object, e As EventArgs) Handles _loan.Returned
        Console.WriteLine("Handles clause: loan returned")
    End Sub

    Public Sub Run()
        Dim extra As EventHandler = Sub(s, e) Console.WriteLine("AddHandler lambda: loan returned")
        AddHandler _loan.Returned, extra                         ' _loan.Returned += extra
        _loan.Return()
        RemoveHandler _loan.Returned, extra                      ' _loan.Returned -= extra
        _loan.Return()
    End Sub
End Class

Module Program

    Sub Main()

Four details. The event is raised with RaiseEvent, which does the null check that C# writes as ?.Invoke. A method that is named Return must be written in square brackets ([Return]), because Return is a keyword; the brackets let any keyword be used as an identifier. The statement Public Event Returned(sender As Object, e As EventArgs) is also legal, but declares a new delegate type (Loan.ReturnedEventHandler) instead of using EventHandler; assigning an EventHandler to such an event is then error BC30311 (the value cannot be converted), which is why the example declares Public Event Returned As EventHandler. Finally, the XML element is a literal: it is a XElement created by the compiler, with the embedded expression <%= title %>, the attribute accessed as book.@year and the child elements as book.<title>. XML literals and the axis properties exist only in Visual Basic and are covered on XML Literals and Axis Properties; events are covered on Events and Handlers.

My and default instances

My is a Visual Basic-only namespace of shortcuts to the application, the computer, the user, resources and settings. On .NET Framework it exists in every project; on .NET it is present only in Windows desktop projects whose MyType is set, and is empty in a console project (see The My Namespace for the details and the alternatives). A related feature of Windows Forms projects, the default instance, lets code call Form1.Show() on the class name as if it were a variable; it exists to ease VB6 migrations and is covered on Windows Forms Applications.

Where the books are outdated for this page

The two books that this section draws on compare Visual Basic with its older dialects, and some of what they say about those comparisons is out of date or incorrect. The corrected rules, in short:

  • Visual Basic .NET is not source-compatible with VB6. The books' remark that "backward compatibility" eases the transition applies to habits, not to code, and there are many semantic differences (type sizes, default parameter passing, the object model, the library).

  • Of the keywords above, the ones the books describe as VB6 features that the language lacks, or gained, should be checked against the lists on The VB Family: VB6, VBA and VBScript: VB6 had Implements but no class inheritance, VB6 did have Public, Private and Friend, and VBScript 5.0 and later has Class ... End Class.

  • The books present Option Strict Off code and the + operator for strings as normal. Neither is recommended: set Option Strict On and use &.

  • They describe Visual Basic as a language that is still gaining features and a runtime that is part of the .NET Framework; see History, Versions and Language Strategy.

Common mistakes for newcomers

Mistake What happens, and the fix

Dim shelf(3) As String expected to have three elements

It has four. Use Dim shelf(2) As String for three, or New String() {...} with an initializer.

If flags And 1 = 1 Then

Parsed as flags And (1 = 1); with Option Strict On it does not compile. Write (flags And 1) = 1.

If x IsNot Nothing And x.Length > 0 Then

Both operands are evaluated, so a null x throws NullReferenceException. Use AndAlso.

Dim name As String = Nothing then If name = "" Then expecting false

Nothing = "" is True for strings. Test with String.IsNullOrEmpty.

"Total: " + 3 + 4

Not text concatenation; with Option Strict On it does not compile, with it off it can throw a conversion exception. Use &.

2 ^ 3 assigned to an Integer

^ returns a Double. Convert, or use integer multiplication for small integer powers.

Adding 1 to a variable holding Integer.MaxValue expected to wrap

OverflowException. Overflow is checked by default.

A nullable n = 1 and n <> 1 both treated as exhaustive

With Nothing both are false. Test n.HasValue first, or compare with n.GetValueOrDefault().

A local and a type with the same name in different case (host and Host)

Names are case-insensitive. Rename the local.

Public Event Done(sender As Object, e As EventArgs) and then using an EventHandler

The event has its own delegate type. Declare Public Event Done As EventHandler.

Calling My.Computer from a console project

My is empty on .NET outside Windows desktop projects. Use the base class library.

Using a keyword as a name (Dim date As Date)

BC30183, keyword not valid as an identifier. Use another name or put the identifier in brackets.
