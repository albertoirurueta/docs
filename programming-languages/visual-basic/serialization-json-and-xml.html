Serialization: JSON and XML

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Serialization turns objects into text or bytes that can be stored or sent, and deserialization turns them back. .NET offers several serializers with different promises: System.Text.Json for JSON, XmlSerializer and DataContractSerializer for XML, and the lower-level XmlReader, XmlWriter, XmlDocument and JsonDocument for documents you navigate yourself. Another serializer, BinaryFormatter, is gone: since .NET 9 its implementation always throws, and this page explains why and what replaces it. It was written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and checked on 2026-10-19. Every program was built with Option Strict On and TreatWarningsAsErrors and run in a Linux container; the project root namespace is ShelfDocs, which appears in some exception messages because the shelf types are nested in the example modules. Serialization in Visual Basic has some limits that C# does not have, mainly the unusable Utf8JsonReader type and the C#-only source generator; both are shown with real compiler output and a workaround that keeps the code in Visual Basic.

Reading and writing the files that hold serialized data is on Files, Directories and Streams. LINQ to XML and the XML literals that build an XDocument from inline XML are on XML Literals and Axis Properties. Attributes in general are on Attributes, Caller Info and Reflection, and the C# view is on Attributes and Reflection in the C# reference. Web services that return JSON are on Web, HTTP and Services, and the security view of untrusted input is continued on Security and Cryptography.

System.Text.Json basics

JsonSerializer.Serialize(value) produces compact JSON, and JsonSerializer.Deserialize(Of T)(text) creates a T from it. The defaults are strict and predictable: properties use their declared names; only public properties with public getters and setters are written and read; public fields are ignored; enums are numbers; dates use ISO 8601; unknown JSON members are ignored; property names are case-sensitive on input; comments, trailing commas and quoted numbers are errors. JsonSerializerOptions changes each of those, and JsonSerializerDefaults.Web selects the usual web choices (camelCase names, case-insensitive reading, numbers accepted from strings). Create one options instance and reuse it: it caches type metadata, so building a new instance per call is slow.

The Visual Basic habits that matter here are small. A class made of auto-implemented properties (Public Property Title As String = "") is exactly what the serializer wants, including property initializers such as Tags As New List(Of String)(); the deserializer needs a public parameterless constructor unless it is told which constructor to use (next section). A ReadOnly property is written (Label in the output) and skipped on input. A public Field (the ShelfMark in the example) is ignored until IncludeFields or <JsonInclude> is used, a private field never appears, and the Date? property becomes null or an ISO string.

JsonSerializerOptions property Effect

WriteIndented

Pretty-printed output with two-space indentation.

PropertyNamingPolicy, DictionaryKeyPolicy

JsonNamingPolicy.CamelCase, SnakeCaseLower, KebabCaseLower and the others rename properties or dictionary keys.

PropertyNameCaseInsensitive

Match JSON names to properties regardless of case when reading.

DefaultIgnoreCondition

WhenWritingNull or WhenWritingDefault omit empty values when writing.

IncludeFields

Include public fields as well as properties.

Converters

Add JsonStringEnumConverter to write enums as names; custom converters cannot be written in Visual Basic (see below).

AllowTrailingCommas, ReadCommentHandling

Accept JSON that has trailing commas or comments, which strict JSON does not allow.

NumberHandling

AllowReadingFromString, WriteAsString, AllowNamedFloatingPointLiterals.

UnmappedMemberHandling

Skip (default) or Disallow.

MaxDepth

Maximum nesting depth when reading and writing; the default is 64.

ReferenceHandler

Preserve or IgnoreCycles for object graphs that contain cycles; without them a cycle is an exception.

TypeInfoResolver

Where type metadata comes from: reflection by default, a generated context when you supply one.

Encoder

By default non-ASCII and some HTML-sensitive characters are written as escapes; JavaScriptEncoder.UnsafeRelaxedJsonEscaping writes more characters literally and should not be used for HTML output.

Bad input throws JsonException with Path, LineNumber and BytePositionInLine, which is what to log. A document whose root is the literal null deserializes to Nothing, so always check the result before using it.

Attributes, constructors and surrogate properties

Attributes on the properties override the options for one member. The Visual Basic syntax is <JsonPropertyName("isbn")> before the property, several attributes may share a line separated by commas or sit on separate lines, and a named argument uses :=.

Attribute Effect

<JsonPropertyName("x")>

Name in JSON.

<JsonIgnore>, <JsonIgnore(Condition:=...)>

Never write/read, or skip when Null/default.

<JsonInclude>

Include a field or a property with a non-public accessor.

<JsonPropertyOrder(n)>

Position in the output (lower first, default 0).

<JsonRequired>

The member must be present in the input; absent means JsonException.

<JsonConstructor>

The constructor to use when there is no parameterless one; parameters match JSON names, case-insensitively.

<JsonExtensionData>

A Dictionary(Of String, JsonElement) (or JsonObject) that receives members with no matching property and writes them back.

<JsonConverter(GetType(...))>

Use a specific converter; see the next section for why Visual Basic cannot define one.

<JsonPolymorphic>, <JsonDerivedType>

Opt in to type discriminators for a base class (see the polymorphism section).

<JsonNumberHandling>

Per-member number handling.

Read the output: the member property came first because of <JsonPropertyOrder(-1)>; InternalNote is not written; Renewals was left out because it is zero and the condition is WhenWritingDefault; the public field DueOn is written because of <JsonInclude>; in the input, the member renewals (lowercase) does not match the property Renewals (the matching is case-sensitive), so it lands in the extension data together with the other unknown members, and a round trip writes them back. The Isbn structure has no useful public members to describe it, so the serialized form of a structure that hides its data would be {"Digits":"..."}; the class avoids that by keeping the structure out of the JSON with <JsonIgnore> and exposing a string surrogate property, IsbnText, renamed to isbn. A surrogate property is the Visual Basic substitute for a converter whenever the value has a natural text form.

Custom converters: Utf8JsonReader cannot be named in Visual Basic

A converter is the System.Text.Json extension point: a class that inherits JsonConverter(Of T) and overrides Read(ByRef reader As Utf8JsonReader, ...) and Write(writer As Utf8JsonWriter, ...). Utf8JsonReader is a ref struct, a kind of type that the Visual Basic compiler does not support: it treats such a type as obsolete with the message below, so any signature, local variable or field of that type is an error.

This means that a Visual Basic project cannot implement JsonConverter(Of T) (its Read method has such a parameter), cannot write a JsonConverterFactory, and cannot read JSON token by token. Utf8JsonWriter is a normal class and works, as does everything that goes through JsonSerializer, JsonDocument, JsonElement and JsonNode. The options are, in order of preference:

  • a surrogate property of a simple type, as in the previous section (no extra project);

  • a generic converter written once in C# in a small class library, which the Visual Basic code configures with lambdas (below);

  • reading the document with JsonDocument or JsonNode and building the objects by hand.

Json/StringConverter.cs
using System.Text.Json;
using System.Text.Json.Serialization;

namespace Shelf.Json;

// Visual Basic cannot name Utf8JsonReader, so it cannot override JsonConverter<T>.Read.
// This C# helper does the reading and writing and asks the caller for two functions.
public sealed class StringConverter<T> : JsonConverter<T>
{
    private readonly Func<T, string> _toText;
    private readonly Func<string, T> _fromText;

    public StringConverter(Func<T, string> toText, Func<string, T> fromText)
    {
        _toText = toText;
        _fromText = fromText;
    }

    public override T Read(ref Utf8JsonReader reader, Type typeToConvert, JsonSerializerOptions options)
        => _fromText(reader.GetString() ?? "");

    public override void Write(Utf8JsonWriter writer, T value, JsonSerializerOptions options)
        => writer.WriteStringValue(_toText(value));
}

When the structure is not fixed, or only a few members matter, work with the document. JsonDocument is a read-only, pooled representation that must be disposed; JsonElement values obtained from it are valid only until then. Files, streams and async

JsonSerializer.SerializeAsync and DeserializeAsync work on any Stream, so a large collection streams to and from a file without building the whole text. DeserializeAsyncEnumerable yields the elements of a top-level array one by one. Visual Basic has no Await For Each, so the enumerator is driven by hand. JSON Lines (one compact object per line) is appendable and can be read with ReadAllLinesAsync or a StreamReader, which makes it a better log-like format than one large array.

                written.Add(JsonSerializer.Serialize(b))
            Next
            Await File.WriteAllLinesAsync(lines, written)
            File.AppendAllText(lines, JsonSerializer.Serialize(New Book With {.Isbn = "x", .Title = "Appended", .Year = 2026}) & Environment.NewLine)

            End Try
        Finally

Polymorphism, unknown members, depth and numbers

By default the serializer writes only the declared type of a property. For a class hierarchy, <JsonPolymorphic> and <JsonDerivedType> opt in to a type discriminator and, importantly, close the set of types: only the registered derived types can be written or read, and an unknown discriminator is rejected. That is the safe design, unlike serializers that read an arbitrary type name from the input.

<XmlRoot("name", Namespace:=...)>

Name and namespace of the root element.

<XmlElement("name")>

Name of the element for a property; on a collection it removes the wrapper element, so each item becomes a sibling.

<XmlAttribute("name")>

Write the property as an attribute.

<XmlArray("x")>, <XmlArrayItem("y")>

Wrapper element and item name for a collection.

<XmlIgnore>

Skip the member.

<XmlText>

The property is the element’s text content.

<XmlInclude(GetType(Derived))>

Declare a derived type that may appear where the base type is declared.

<XmlEnum("name")>

Text of an enum member.

DataContractSerializer

DataContractSerializer comes from WCF. It is opt-in: only members marked <DataMember> in a class marked <DataContract> are serialized, whatever their access modifier, and no parameterless constructor is needed (the constructor does not run during deserialization). It writes XML with namespaces, and DataContractJsonSerializer writes the same contract as JSON. The element order is part of the contract: alphabetical by default, or by Order.

        Using stream As New MemoryStream()

                serializer.WriteObject(writer, value)
            End Using
            Return Encoding.UTF8.GetString(stream.ToArray())
        End Using
    End Function

        Using reader As XmlReader = XmlReader.Create(New StringReader(xml))

Versioning data contracts

Data that outlives a program version meets older and newer readers. A reader that drops what it does not understand and writes the document back deletes the newer data. IExtensibleDataObject is the round-trip fix: the old class implements it, the unknown content is stored in ExtensionData, and it is written back unchanged. XmlSerializer takes the opposite approach and reports unknown content through events, so the program decides.

        End Using

XmlReader, XmlWriter, XmlDocument and XPath

When no object mapping is wanted, work with the XML. XmlReader is a forward-only pull parser with constant memory; XmlWriter writes well-formed XML and escapes text for you; XmlDocument is the older mutable DOM; XPathNavigator and XPath queries select nodes; XDocument (LINQ to XML) is the modern API and the one that XML literals build. The namespace is a constant source of mistakes: XPath has no default namespace, so a document with xmlns="urn:shelf" needs an XmlNamespaceManager with a prefix of your choosing, and the query without the prefix finds nothing.

Public Module S07
    Const Catalog As String =
        "<?xml version=""1.0"" encoding=""utf-8""?>" & vbLf &
        "<catalog xmlns=""urn:shelf"" updated=""2026-01-15"">" & vbLf &

        "</catalog>"

    Sub Main()
        ' XmlReader: forward-only, low memory.
        Dim settings As New XmlReaderSettings With {.IgnoreWhitespace = True, .IgnoreComments = True}
        Using reader As XmlReader = XmlReader.Create(New StringReader(Catalog), settings)
            Do While reader.Read()

                    reader.ReadToDescendant("title", "urn:shelf")
                    Dim title As String = reader.ReadElementContentAsString()
                    Console.WriteLine($"{isbn} {title}")
                End If
            Loop
        End Using

        Using reader As XmlReader = XmlReader.Create(New StringReader(Catalog), settings)
            Dim years As New List(Of Integer)()
            Do While reader.ReadToFollowing("year", "urn:shelf")
                years.Add(reader.ReadElementContentAsInt())
            Loop
            Console.WriteLine($"Years: {String.Join(", ", years)}")
        End Using

        ' XmlWriter: well-formed output without building a tree.
        Dim sb As New StringBuilder()
        Using writer As XmlWriter = XmlWriter.Create(sb, New XmlWriterSettings With {.Indent = True, .OmitXmlDeclaration = True})
            writer.WriteStartElement("loans", "urn:shelf")
            writer.WriteAttributeString("count", "2")
            writer.WriteStartElement("loan")
            writer.WriteElementString("member", "Ann & Bob <team>")   ' escaped automatically
            writer.WriteEndElement()
            writer.WriteComment(" more loans follow ")
            writer.WriteEndElement()
        End Using
        Console.WriteLine(sb.ToString().Replace(vbCrLf, vbLf))

        Dim doc As New XmlDocument()

        Dim ns As New XmlNamespaceManager(doc.NameTable)
        ns.AddNamespace("s", "urn:shelf")

        Console.WriteLine($"Edited element: {firstBook.OuterXml.Substring(0, 62)}")

        Dim nav As XPathNavigator = doc.CreateNavigator()

        Console.WriteLine($"Books: {nav.Evaluate(expr)}")

XML security: DTDs, entities and resolvers

XML can define entities, and an external entity can point to a file or a URL. A parser that resolves external entities from untrusted input lets an attacker read local files or reach internal servers (XXE), and a document whose entities expand into each other can consume memory (the "billion laughs" attack). The defaults of current .NET are safe, and the rule is to keep them: XmlReader prohibits DTDs unless you allow them, XmlDocument.LoadXml uses no resolver, and XmlReaderSettings.XmlResolver is Nothing.

Imports System.Xml

    Const WithDtd As String =
        "<?xml version=""1.0""?>" & vbLf &
        "<!DOCTYPE catalog [ <!ENTITY owner ""Shelf Library""> <!ENTITY big SYSTEM ""file:///etc/hostname""> ]>" & vbLf &
        "<catalog><owner>&owner;</owner><file>&big;</file></catalog>"

    Sub Main()

        Try
            Using reader As XmlReader = XmlReader.Create(New StringReader(WithDtd))
                Do While reader.Read()
                Loop

        Catch ex As XmlException
            Console.WriteLine("Default XmlReader: " & ex.Message)
        End Try

        ' XmlDocument.LoadXml has no resolver, so internal entities work and external entities do not load.
        Dim doc As New XmlDocument()
        Try
            doc.LoadXml(WithDtd)
            Console.WriteLine($"XmlDocument.LoadXml: owner=[{doc.SelectSingleNode("//owner").InnerText}] file=[{doc.SelectSingleNode("//file").InnerText}]")
        Catch ex As XmlException
            Console.WriteLine("XmlDocument.LoadXml: " & ex.Message)

BinaryFormatter is gone

BinaryFormatter wrote a .NET object graph, including type names, into a binary stream, and read it back by creating whatever types the stream named. That power is the vulnerability: deserializing an attacker-controlled stream can run attacker-chosen code, and no SerializationBinder or settings change can make it safe. The official guidance is that BinaryFormatter is dangerous and not recommended for data processing, even for data you believe to be trusted. Microsoft removed it in steps:

Release Change (from the official migration guide and the SYSLIB0011 diagnostic page)

.NET 5

BinaryFormatter.Serialize and Deserialize marked obsolete; using them reports SYSLIB0011.

.NET 8

In most project types the methods throw NotSupportedException unless a compatibility switch is set.

.NET 9

The in-box implementation is removed: the types and methods still exist so that code compiles, but they always throw PlatformNotSupportedException, and the old compatibility switches no longer help.

An unsupported compatibility package named System.Runtime.Serialization.Formatters replaces the throwing implementation for applications that cannot migrate yet; the guide recommends migrating instead.

The security of deserialization

Deserializing is parsing, and parsing untrusted input is the classic way into an application. The weakness catalogue calls it CWE-502, and it appears on the OWASP lists. The safe serializers above are safe because they constrain what the input can say; the checklist keeps that property:

  • Deserialize into a fixed contract type (a class you wrote with simple properties), not into Object or an interface chosen by the input.

  • Allow only registered derived types (<JsonDerivedType>, <XmlInclude>, <KnownType>); never read a type name from the data and load it.

  • Limit the size of the input before parsing (the request size limit, the file size) and keep MaxDepth at its default; XML has MaxCharactersFromEntities and MaxCharactersInDocument.

  • Keep DTD processing off and resolvers null.

  • Validate the object after deserializing: ranges, required members, relationships; the serializer checks the shape, not the meaning.

  • Do not trust a file because it is local: files are written by other programs, restored from backups, and edited by hand.

  • Treat deserialization errors as expected input: catch JsonException, InvalidOperationException (XML) and SerializationException (data contract), log the position and not the payload, and return a clear failure.

  • Never put secrets in a serialized object that you log or send; mark them <JsonIgnore>, <XmlIgnore> or leave them out of the data contract.

Pitfalls checklist

  • Reuse JsonSerializerOptions and XmlSerializer instances.

  • System.Text.Json ignores public fields and private members by default and is case-sensitive on input.

  • A Date? that is Nothing is null in JSON and xsi:nil in XML; a Date that is Nothing is 0001-01-01.

  • Utf8JsonReader is unusable and JsonConverter(Of T) cannot be overridden in Visual Basic; use a surrogate property or a small C# helper.

  • The source generator does not run for Visual Basic projects.

  • Classes in a default Module are not public: XmlSerializer rejects them, and the data contract name includes the module name.

  • A data contract’s element order matters; an out-of-order optional member is dropped without an error.

  • IExtensibleDataObject keeps unknown content through a read and write; without it the newer data is lost.

  • XPath on a default-namespace document needs a namespace manager; XPathNavigator.Evaluate returns Double.

  • Do not deserialize into Object or arbitrary types from untrusted input; use fixed contracts and registered derived types.

  • BinaryFormatter is removed; migrate stored data once and never write it again.

  • Leave DTD processing prohibited.

  • Catch the serializer’s exception types, log the position and not the payload.
