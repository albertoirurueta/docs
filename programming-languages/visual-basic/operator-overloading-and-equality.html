Operator Overloading and Equality

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is a complete console program that starts with Option Strict On, was built with warnings treated as errors and was run in the .NET 10 SDK container (Linux, invariant culture); the output shown is real output. The projects use the root namespace ShelfDocs, which is why a few messages and type names below carry that prefix. The examples that are meant to fail say so and show the compiler messages that the SDK printed. Where an example compares with C# it was built as a real C# project that references the Visual Basic one.

A type decides for itself what +, =, < or a conversion means, and how it behaves in a HashSet, a Dictionary or a sort. Visual Basic gives you two separate mechanisms for that, and most of the confusion about equality comes from mixing them up:

  • Operator procedures (Operator =, Operator +, Widening Operator CType and so on) change what an expression such as a = b means in source code. They are resolved by the compiler from the declared types of the operands.

  • The equality and ordering contract (Object.Equals, GetHashCode, IEquatable(Of T), IComparable(Of T) and comparers) is what the .NET class library calls at run time: List(Of T).Contains, Dictionary(Of K, V), Distinct, Sort and SortedSet(Of T) never look at your operators.

A well-behaved type defines both, with the same meaning. The running example is the shelf library catalogue: the Isbn structure, a few catalogue entries and a Money structure for late fees. The Operator statement and operator overloading itself have existed since Visual Basic 2005 (VB 8.0, .NET Framework 2.0), together with the Widening and Narrowing conversion operators, IsTrue/IsFalse and the lifting of operators to nullable value types. What changed around it since is the class library (IEquatable(Of T), HashCode, generic math), and one of those changes Visual Basic cannot use, as shown near the end.

Operator procedures

An operator procedure is a Public Shared procedure named by an operator symbol. The general shape is:

[<attributes>] Public [Overloads] Shared [Shadows] [Widening | Narrowing]
    Operator operatorsymbol(operand1 [, operand2]) [As type]
    ...
    Return value
End Operator

The rules, from the Language Reference and checked against the compiler:

  • The declaration context is a class or a structure. An operator inside a Module is rejected (BC33018), and an interface cannot declare one (BC30603: a statement cannot appear within an interface body).

  • The modifiers are exactly Public and Shared: omit Shared and you get BC33012, use Private or Friend and you get BC33011.

  • Operands are always passed ByVal; ByRef, Optional and ParamArray are rejected (BC30651, BC33010).

  • At least one operand must be of the containing type (for a conversion, the operand or the return type). Nullable forms of the containing type count. Otherwise: BC33021.

  • A unary operator has one operand, a binary operator two (BC33014, BC33015). Unary + and - and binary + and - are separate declarations.

  • The return type is free: Money / Money can return a Decimal, and = can return something that is not a Boolean (although a Boolean is what every caller expects).

  • The operands may have different types, so Money * Decimal and Decimal * Money are two operators, and a type that should multiply commutatively declares both.

  • Overloads is optional on the type that declares the operator, but it is needed to overload (rather than shadow) the operator of a base class, as shown further down.

  • Nothing is inherited in the usual sense: the operator is a static method, and the compiler picks it from the declared types of the operands, never from the run-time types.

    End Function

        Return _cents.CompareTo(other._cents)
    End Function

    Public Overrides Function ToString() As String
        Return (CDec(_cents) / 100D).ToString("0.00", CultureInfo.InvariantCulture) & " EUR"
    End Function

Points worth noticing in this example:

  • total += fee is a compound assignment: the compiler rewrites it as total = total + fee, so it works for any type that has the binary operator. The compound forms that exist are +=, -=, *=, /=, \=, ^=, &=, <<= and >>=. There is no And=, Or=, Xor= or Mod= (the compiler rejects them with parse errors such as BC30201); write x = x Or y.

  • 3 * perDay and perDay * 12 both compile because both orders were declared; the integer literal widens to Decimal for the parameter. Without the second declaration the first form would not compile (BC30311, "Value of type 'Integer' cannot be converted to 'Money'").

  • fee / perDay returns a Decimal: the result type of an operator is whatever you declare.

  • fees.Sort() does not use <; it uses IComparable(Of Money). The relational operators and the interface were written separately here and both delegate to the same field comparison. Keep them consistent.

  • Money is stored as a whole number of cents. Arithmetic on money in a Double is a classic source of rounding bugs; see Numbers and Math for Decimal and rounding modes.

A widening conversion becomes op_Implicit and a narrowing one op_Explicit, which is what lets C# and Visual Basic use each other’s conversions. Operators are chosen at compile time

Operator procedures are static methods, so they are never virtual. A derived class that declares its own = has a second operator, not an override. Which one runs depends on the declared types of the expression, which is the opposite of what Equals does:

Option Strict On

Public Class CatalogItem
    Public ReadOnly Property Title As String

    Public Sub New(title As String)
        Me.Title = title

        Return Not (left = right)

Operators and nullable value types

Operators declared for a structure are lifted to its nullable form (Money?, written Nullable(Of Money)): the compiler emits a call that unwraps both operands and, if either is Nothing, produces Nothing instead of calling your code. IsTrue, IsFalse and the short-circuit operators

IsTrue and IsFalse are the conversion of an object to a condition, and they are the building blocks of AndAlso and OrElse. They are matched, both must return Boolean, and you cannot declare AndAlso or OrElse yourself. To use them on your own type you must declare:

  • AndAlso: Operator And(left As T, right As T) As T and Operator IsFalse(x As T) As Boolean.

  • OrElse: Operator Or(left As T, right As T) As T and Operator IsTrue(x As T) As Boolean.

a AndAlso b then means: if IsFalse(a) then a, otherwise a And b; b is evaluated only in the second case:

Option Strict On

    Public ReadOnly Passed As Boolean

        Me.Passed = passed

    End Operator

    Public Shared Operator Or(left As Check, right As Check) As Check

    End Operator

Bitwise and shift operators

Types that model sets of flags can define And, Or, Xor, Not and the shifts. Unlike an Enum with <Flags>, a structure can enforce a mask (the Not below keeps only the three defined rights) and carry methods:

Option Strict On

' A set of up to 8 permissions as a value type with logical and shift operators.
Public Structure RightSet
    Private ReadOnly _bits As Byte

    Public Sub New(bits As Byte)
        _bits = bits
    End Sub

    Public Shared ReadOnly Property Borrow As New RightSet(1)
    Public Shared ReadOnly Property Renew As New RightSet(2)
    Public Shared ReadOnly Property Reserve As New RightSet(4)

    Public Shared Operator Or(left As RightSet, right As RightSet) As RightSet
        Return New RightSet(left._bits Or right._bits)
    End Operator

    Public Shared Operator And(left As RightSet, right As RightSet) As RightSet
        Return New RightSet(left._bits And right._bits)
    End Operator

    Public Shared Operator Xor(left As RightSet, right As RightSet) As RightSet
        Return New RightSet(left._bits Xor right._bits)
    End Operator

    Public Shared Operator Not(value As RightSet) As RightSet
        Return New RightSet(CByte((Not value._bits) And &H7))     ' only the 3 defined rights
    End Operator

    Public Shared Operator <<(value As RightSet, count As Integer) As RightSet
        Return New RightSet(CByte((CInt(value._bits) << count) And &H7))
    End Operator

    Public Shared Operator >>(value As RightSet, count As Integer) As RightSet
        Return New RightSet(CByte(CInt(value._bits) >> count))
    End Operator

    ' With IsTrue/IsFalse, "If rights Then" means "at least one right".
    Public Shared Operator IsTrue(value As RightSet) As Boolean
        Return value._bits <> 0
    End Operator

    Public Shared Operator IsFalse(value As RightSet) As Boolean
        Return value._bits = 0
    End Operator

        If (_bits And 2) <> 0 Then names.Add("Renew")
        If (_bits And 4) <> 0 Then names.Add("Reserve")

    End Function

Conversion operators: Widening and Narrowing CType

A conversion operator is always called CType, has exactly one operand, and converts to or from the containing type. The Widening or Narrowing keyword is mandatory (BC33017 otherwise) and expresses what you promise:

  • Widening conversions must never fail and lose no information; the compiler applies them implicitly, even with Option Strict On.

  • Narrowing conversions may fail or lose information; with Option Strict On they require an explicit CType (or a conversion function). Choose Narrowing whenever the operator can throw.

A conversion operator cannot convert a type to itself (BC33024), to a base type (BC33026), to an interface (BC33025) or to Object (BC33028): those conversions already exist through inheritance. A widening and a narrowing operator with the same source and target types are duplicates (BC30269). The operator names seen from other languages are op_Implicit (widening) and op_Explicit (narrowing).

Option Strict On

    Implements IEquatable(Of Isbn)

    Public ReadOnly Property Value As String

    Private Sub New(value As String)
        Me.Value = value
    End Sub

    Public Shared Function TryParse(text As String, ByRef result As Isbn) As Boolean
        Dim digits = New String(If(text, "").Where(AddressOf Char.IsLetterOrDigit).ToArray())
        If digits.Length = 13 AndAlso digits.All(AddressOf Char.IsDigit) AndAlso HasValidCheckDigit(digits) Then
            result = New Isbn(digits)
            Return True
        End If
        Return False
    End Function

    Public Shared Function Parse(text As String) As Isbn
        Dim result As Isbn = Nothing
        If Not TryParse(text, result) Then
            Throw New FormatException($"{text} is not a valid ISBN-13.")
        End If
        Return result
    End Function

    Private Shared Function HasValidCheckDigit(digits As String) As Boolean
        Dim sum = 0
        For i = 0 To 12
            Dim d = AscW(digits(i)) - AscW("0"c)
            sum += If(i Mod 2 = 0, d, d * 3)
        Next
        Return sum Mod 10 = 0
    End Function

    ' Every ISBN converts to String without loss, so the conversion is Widening (implicit).
    Public Shared Widening Operator CType(value As Isbn) As String
        Return value.Value
    End Operator

    ' A String may not be a valid ISBN, so the conversion is Narrowing (explicit, may throw).
    Public Shared Narrowing Operator CType(text As String) As Isbn
        Return Parse(text)
    End Operator

    Public Overloads Function Equals(other As Isbn) As Boolean Implements IEquatable(Of Isbn).Equals
        Return Value = other.Value
    End Function

    Public Overrides Function Equals(obj As Object) As Boolean
        Return TypeOf obj Is Isbn AndAlso Equals(DirectCast(obj, Isbn))
    End Function

    Public Overrides Function GetHashCode() As Integer
        Return If(Value, "").GetHashCode()
    End Function

Implementing value equality

The contract that every collection relies on:

  1. Reflexive, symmetric, transitive: x.Equals(x), x.Equals(y) = y.Equals(x), and equality chains.

  2. Consistent: the same answer while the compared state does not change.

  3. Never throws for a Nothing argument, and x.Equals(Nothing) is False.

  4. Hash consistent: equal objects return equal GetHashCode() values; unequal objects may collide.

  5. IEquatable(Of T).Equals, Equals(Object), =/<> and CompareTo = 0 agree.

For a structure, the complete set is IEquatable(Of T), both Equals methods, GetHashCode, and the =/<> pair, as in the shelf Isbn:

Equality for a class

A class has the same members, with three additions: the Nothing checks, NotInheritable (or a carefully designed GetType() comparison) to avoid asymmetric equality with subclasses, and the decision whether equality is identity (default) or entity/value equality. A structure that does not implement IEquatable(Of T) pays for boxing on every comparison made through EqualityComparer(Of T).Default. The program counts allocations, not time, so the result is deterministic:

Public Structure PlainCopy

Ordering with IComparable and comparers

IComparable(Of T) gives a type its natural order, returning a negative number, zero or a positive number. It is what List.Sort(), SortedSet, Array.Sort and LINQ OrderBy/Max/Min with no comparer use. The conventions:

  • Any instance sorts after Nothing; CompareTo(Nothing) returns a positive number rather than throwing.

  • CompareTo(other) = 0 should agree with Equals; where it does not (case-insensitive ordering, say) document it, because SortedSet would then collapse values that HashSet keeps apart.

  • Implement the non-generic IComparable as well only when old code (ArrayList, Array.Sort(Array)) must be supported, and make it throw ArgumentException for other types.

  • The four relational operators are declared as two pairs and written with one shared Compare helper, so that Nothing handling cannot drift.

Option Strict On

Public NotInheritable Class Issue
    Implements IComparable(Of Issue), IComparable, IEquatable(Of Issue)

    Public ReadOnly Property Year As Integer
    Public ReadOnly Property Number As Integer

    Public Sub New(year As Integer, number As Integer)
        Me.Year = year
        Me.Number = number
    End Sub

    ' Convention: any instance sorts after Nothing; two Nothings are equal.
    Public Function CompareTo(other As Issue) As Integer Implements IComparable(Of Issue).CompareTo
        If other Is Nothing Then Return 1
        Dim byYear = Year.CompareTo(other.Year)
        Return If(byYear <> 0, byYear, Number.CompareTo(other.Number))
    End Function

    ' The non-generic interface is used by ArrayList, Array.Sort(Array) and old APIs.
    Private Function CompareToObject(obj As Object) As Integer Implements IComparable.CompareTo
        If obj Is Nothing Then Return 1
        Dim other = TryCast(obj, Issue)
        If other Is Nothing Then
            Throw New ArgumentException("Object must be of type Issue.", NameOf(obj))
        End If
        Return CompareTo(other)
    End Function

    Public Overloads Function Equals(other As Issue) As Boolean Implements IEquatable(Of Issue).Equals
        Return other IsNot Nothing AndAlso CompareTo(other) = 0
    End Function

    Public Overrides Function Equals(obj As Object) As Boolean
        Return Equals(TryCast(obj, Issue))
    End Function

    Public Overrides Function GetHashCode() As Integer
        Return HashCode.Combine(Year, Number)
    End Function

    Public Overrides Function ToString() As String
        Return Year & "/" & Number
    End Function

    ' The operators handle Nothing through a shared helper so that the rules cannot drift.
    Private Shared Function Compare(left As Issue, right As Issue) As Integer
        If left Is Nothing Then Return If(right Is Nothing, 0, -1)
        Return left.CompareTo(right)
    End Function

    Public Shared Operator <(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) < 0
    End Operator

    Public Shared Operator >(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) > 0
    End Operator

    Public Shared Operator <=(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) <= 0
    End Operator

    Public Shared Operator >=(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) >= 0
    End Operator

    Public Shared Operator =(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) = 0
    End Operator

    Public Shared Operator <>(left As Issue, right As Issue) As Boolean
        Return Compare(left, right) <> 0
    End Operator
End Class

Older material you may meet

Tutorials and the books this section was compared with often predate several of these points:

  • Examples that sort with the non-generic IComparable and ArrayList, or implement only Equals(Object): they still work, but use IComparable(Of T), IEquatable(Of T) and generic collections today, and make the structure’s Equals(Object) call the typed overload to avoid boxing.

  • "Operator overloading" chapters that stop at + and =. A type that defines = must also define <>, and should define Equals, GetHashCode and the IEquatable(Of T) implementation to match; the compiler will not remind you.

  • VB6 code compared objects with Is and relied on default properties and Variant comparison for =. In .NET, = on two class-typed operands with no operator is a compile error (BC30452), and Object = Object is BC32013 under Option Strict On.

  • Hash-code advice that XORs fields (a.GetHashCode() Xor b.GetHashCode()), which gives equal hashes for swapped values, predates HashCode.Combine.

  • Samples that compare Strings with = and assume the project is case-sensitive, ignoring Option Compare.
