Vocabulary Types

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

"Vocabulary types" are small, general-purpose types the whole standard library (and most C++ APIs) share a common understanding of — using them in your own interfaces means callers already know how to use them.

std::pair and std::tuple

#include <utility>
#include <tuple>
#include <iostream>

std::pair<int, std::string> makePair() { return {1, "one"}; }

std::tuple<int, std::string, double> makeTuple() { return {1, "one", 1.5}; }

int main() {
    auto [num, name] = makePair();              // structured bindings unpack a pair
    auto [n2, s2, d2] = makeTuple();              // and a tuple, of any size

    auto t = std::make_tuple(1, "one", 1.5);
    std::cout << std::get<0>(t) << ' ' << std::get<2>(t) << '\n';   // access by index
    (void)num; (void)name; (void)n2; (void)s2; (void)d2;
}

std::optional and Monadic Operations

std::optional<T> (C++17) represents "a T, or nothing" without a sentinel value or a separate boolean flag:

#include <optional>
#include <string>
#include <iostream>

std::optional<int> parseInt(const std::string& s) {
    try { return std::stoi(s); } catch (...) { return std::nullopt; }
}

int main() {
    auto result = parseInt("42");
    if (result) { std::cout << *result << '\n'; }        // check + dereference
    std::cout << result.value_or(-1) << '\n';               // default if empty

    auto chained = parseInt("42")
        .transform([](int x) { return x * 2; })              // C++23: map the contained value, if present
        .and_then([](int x) -> std::optional<int> {           // C++23: chain another optional-returning step
            return x > 0 ? std::optional(x) : std::nullopt;
        })
        .or_else([]() -> std::optional<int> { return 0; });    // C++23: fallback if empty at this point
    std::cout << chained.value_or(-1) << '\n';
}

The monadic operations (transform/and_then/or_else, C++23) chain optional-producing steps without a pyramid of nested if (opt) checks.

std::variant and std::visit

std::variant<Ts...> is a type-safe union — it holds exactly one of its alternative types at a time, and accessing the wrong one throws std::bad_variant_access rather than reading garbage:

#include <variant>
#include <string>
#include <iostream>

using Value = std::variant<int, double, std::string>;

std::string describe(const Value& v) {
    return std::visit([](const auto& held) -> std::string {
        using T = std::decay_t<decltype(held)>;
        if constexpr (std::is_same_v<T, int>) return "int: " + std::to_string(held);
        else if constexpr (std::is_same_v<T, double>) return "double: " + std::to_string(held);
        else return "string: " + held;
    }, v);
}

int main() {
    Value v = 42;
    std::cout << describe(v) << '\n';
    v = "hello";
    std::cout << describe(v) << '\n';
    std::cout << std::holds_alternative<std::string>(v) << '\n';   // 1 (true)
}

std::visit with if constexpr on the visitor is the idiomatic way to dispatch over every alternative exhaustively, with a compile error if a new alternative type is added and forgotten.

std::any

std::any holds a value of any copyable type, checked only at run time — the type-erasure counterpart to variant's closed, compile-time-known set of alternatives:

#include <any>
#include <string>
#include <iostream>

int main() {
    std::any a = 42;
    a = std::string("hello");             // can hold a completely different type later
    if (auto* s = std::any_cast<std::string>(&a)) {
        std::cout << *s << '\n';
    }
    try {
        std::any_cast<int>(a);              // throws std::bad_any_cast: a currently holds a string, not an int
    } catch (const std::bad_any_cast& e) {
        std::cout << e.what() << '\n';
    }
}

Prefer std::variant whenever the set of possible types is known ahead of time — it is faster (no allocation, compile-time dispatch) and safer (exhaustiveness-checkable via visit).

std::expected

C++23’s std::expected<T, E> represents "a T, or an E explaining why not" — an alternative to exceptions for expected, recoverable failures, more explicit in a function’s signature than a thrown exception would be:

#include <expected>
#include <string>
#include <iostream>

std::expected<int, std::string> parsePositive(const std::string& s) {
    int value;
    try { value = std::stoi(s); } catch (...) { return std::unexpected("not a number"); }
    if (value <= 0) return std::unexpected("must be positive");
    return value;
}

int main() {
    auto result = parsePositive("42");
    if (result) { std::cout << *result << '\n'; }
    else { std::cout << "error: " << result.error() << '\n'; }

    auto bad = parsePositive("-5");
    std::cout << bad.value_or(0) << '\n';
}

See Error Handling for a fuller comparison of expected against exceptions and error_code.

<expected> is provided by libstdc++ from GCC 12, libc++ from LLVM 16 (the syntax above compiles cleanly with the Apple clang 21 and libc++ toolchain used for this section, -std=c++23 -Wall -Wextra) and MSVC. One combination to avoid: older Clang releases such as Clang 18 paired with libstdc++ reject the header, because it gates on __cpp_concepts >= 202002L and those Clang releases still report 201907L for that macro.

std::reference_wrapper

Containers and std::optional/std::pair cannot directly hold a reference (references aren’t rebindable/assignable, which containers require); std::reference_wrapper<T> (usually spelled std::ref/ std::cref) wraps one in a copyable, assignable object that still behaves like a reference at the point of use:

#include <functional>
#include <vector>
#include <iostream>

int main() {
    int a = 1, b = 2, c = 3;
    std::vector<std::reference_wrapper<int>> refs = {std::ref(a), std::ref(b), std::ref(c)};
    for (int& r : refs) { r *= 10; }               // mutates a, b, c through the wrapper
    std::cout << a << ' ' << b << ' ' << c << '\n';  // 10 20 30
}

Absent Values, Alternatives and Errors as Types

The vocabulary types move information that used to hide in comments, null pointers and -1 sentinels into the type system. optional says "may be absent", variant says "exactly one of these", and expected says "a value or an error", and each forces the caller to handle the other case.

flowchart TB R["return type"] --> Q1{"can the result be absent,
with no reason to report?"} Q1 -->|"yes"| O["std::optional<T>"] Q1 -->|"no"| Q2{"can it fail with
information about why?"} Q2 -->|"yes"| E["std::expected<T, E>"] Q2 -->|"no"| Q3{"is it one of several
different types?"} Q3 -->|"yes, closed set"| V["std::variant<A, B, C>"] Q3 -->|"yes, open set"| AN["std::any (rarely)"] Q3 -->|"no"| T["plain T"]
vocab.cpp
#include <any>
#include <expected>
#include <map>
#include <optional>
#include <print>
#include <string>
#include <string_view>
#include <typeinfo>
#include <tuple>
#include <variant>

struct Book { std::string title; int copies; };
enum class LoanError { unknown_book, no_copies, limit_reached };

std::string_view to_string(LoanError e) {
    switch (e) {
        case LoanError::unknown_book: return "unknown book";
        case LoanError::no_copies: return "no copies left";
        case LoanError::limit_reached: return "loan limit reached";
    }
    return "?";
}

std::map<std::string, Book> catalog{{"isbn-1", {"Dune", 2}}, {"isbn-2", {"Emma", 0}}};

// optional: a value that may be absent, no sentinel needed.
std::optional<Book> find(const std::string& isbn) {
    if (auto it = catalog.find(isbn); it != catalog.end()) return it->second;
    return std::nullopt;
}

// expected: a value OR an error, with the error as part of the type.
std::expected<Book, LoanError> borrow(const std::string& isbn, int already_borrowed) {
    auto b = find(isbn);
    if (!b) return std::unexpected(LoanError::unknown_book);
    if (b->copies == 0) return std::unexpected(LoanError::no_copies);
    if (already_borrowed >= 3) return std::unexpected(LoanError::limit_reached);
    b->copies -= 1;
    return *b;
}

// variant: a closed set of alternatives, visited exhaustively.
using Item = std::variant<Book, int, std::string>;   // a book, a dvd length in minutes, a note

struct Describe {
    std::string operator()(const Book& b) const { return "book " + b.title; }
    std::string operator()(int minutes) const { return std::to_string(minutes) + " minutes"; }
    std::string operator()(const std::string& s) const { return "note: " + s; }
};

int main() {
    // optional with monadic operations (C++23)
    auto title_len = find("isbn-1").transform([](const Book& b) { return b.title.size(); }).value_or(0);
    auto missing = find("nope").transform([](const Book& b) { return b.title.size(); }).value_or(0);
    std::println("title length {} / missing {}", title_len, missing);

    // expected with and_then: errors short-circuit the chain.
    for (const char* isbn : {"isbn-1", "isbn-2", "isbn-9"}) {
        auto r = borrow(isbn, 0).transform([](const Book& b) { return b.title + " borrowed"; });
        if (r) std::println("{}", *r);
        else std::println("{}: {}", isbn, to_string(r.error()));
    }
    auto limited = borrow("isbn-1", 3);
    std::println("limit check: {}", limited ? "ok" : std::string(to_string(limited.error())));

    // variant
    Item items[] = {Book{"Dune", 2}, 117, std::string("fragile")};
    for (const auto& it : items) std::println("{} (index {})", std::visit(Describe{}, it), it.index());
    Item x = 5;
    std::println("holds int: {}, get_if<string>: {}", std::holds_alternative<int>(x),
                 std::get_if<std::string>(&x) == nullptr);
    try {
        (void)std::get<std::string>(x);
    } catch (const std::bad_variant_access& e) {
        std::println("bad_variant_access thrown");
    }

    // any and tuple
    std::any a = std::string("Dune");
    std::println("any holds string: {}, int cast fails: {}", a.type() == typeid(std::string),
                 std::any_cast<int>(&a) == nullptr);
    auto [t, y, n] = std::tuple{"Emma", 1815, 3};
    std::println("{} {} {}", t, y, n);
}
$ clang++ -std=c++23 -Wall -Wextra vocab.cpp -o vocab
$ ./vocab
title length 4 / missing 0
Dune borrowed
isbn-2: no copies left
isbn-9: unknown book
limit check: loan limit reached
book Dune (index 0)
117 minutes (index 1)
note: fragile (index 2)
holds int: true, get_if<string>: true
bad_variant_access thrown
any holds string: true, int cast fails: true
Emma 1815 3

  • find returns std::optional<Book> instead of a pointer or a magic Book. value_or(0) and the C++23 monadic operations (transform, and_then, or_else) handle the empty case without an if, as the "missing 0" line shows. *opt on an empty optional is undefined behaviour; opt.value() throws bad_optional_access.

  • borrow returns std::expected<Book, LoanError>: success and the reason for failure are both in the signature, no exceptions are involved, and the call site chooses to inspect r.error() or chain with transform. Use exceptions for exceptional, unrecoverable-locally failures and expected for anticipated failures a caller routinely handles, such as an unknown ISBN.

  • std::visit with a callable that overloads every alternative is checked for exhaustiveness at compile time: add a fourth alternative to Item and the program stops compiling until Describe handles it. get_if returns a pointer or null (no exception), std::get throws bad_variant_access on the wrong alternative.

  • A variant that holds a throwing-to-move alternative can end up valueless by exception (valueless_by_exception()); keep alternatives nothrow-movable.

  • std::any stores any copyable type and checks the type only at run time through any_cast. It is the least useful of the four: if the set of types is known, a variant is faster, safer and exhaustive.

  • Structured bindings (auto [t, y, n] = std::tuple{...}) unpack tuples, pairs and aggregates; a small struct with named members is almost always clearer than a returned tuple.
