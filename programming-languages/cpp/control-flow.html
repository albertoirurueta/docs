Control Flow

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

if/switch with Initializers

C++17 lets if and switch declare a variable scoped to just the statement, keeping helper variables out of the enclosing scope:

#include <map>
#include <string>

std::map<std::string, int> scores = {{"Ada", 100}};

bool lookup(const std::string& name) {
    if (auto it = scores.find(name); it != scores.end()) {
        return it->second > 50;    // "it" is scoped to this if/else, not leaked into the caller
    }
    return false;
}

int classify(int code) {
    switch (int category = code / 100; category) {
        case 2: return 0;    // 2xx
        case 4: return 1;    // 4xx
        case 5: return 2;    // 5xx
        default: return -1;
    }
}

if constexpr and if consteval

if constexpr (C++17) discards the untaken branch entirely at compile time — essential in templates, where the discarded branch need not even be valid for the types actually instantiated:

#include <type_traits>

template <typename T>
auto describe(T value) {
    if constexpr (std::is_integral_v<T>) {
        return value * 2;             // only instantiated for integral T
    } else {
        return value;                 // only instantiated for non-integral T
    }
}

if consteval (C++23) branches on whether the current evaluation is happening at compile time, letting one function have a fast compile-time path and a separate run-time path:

constexpr double approxSqrt(double x) {
    if consteval {
        // a compile-time-friendly algorithm (e.g. a fixed number of Newton iterations)
        double guess = x / 2 + 1;
        for (int i = 0; i < 20; ++i) guess = (guess + x / guess) / 2;
        return guess;
    } else {
        return __builtin_sqrt(x);     // a run-time intrinsic/library call, unusable in a constant expression
    }
}

Loops and Range-Based for

#include <vector>
#include <iostream>

int main() {
    for (int i = 0; i < 3; ++i) { /* classic C-style */ }

    int n = 3;
    while (n > 0) { --n; }

    do {
        n++;
    } while (n < 1);

    std::vector<int> values = {1, 2, 3};
    for (int v : values) {          // by value -- copies each element
        std::cout << v << ' ';
    }
    for (int& v : values) {          // by reference -- can modify in place
        v *= 2;
    }
    for (const auto& v : values) {   // the usual default: no copy, no accidental mutation
        std::cout << v << ' ';
    }
}

Range-for works on any type exposing begin()/end() (member or free-function ADL-found), so custom containers and views (see Ranges and Views) participate for free.

Structured Bindings

C++17 structured bindings unpack a pair/tuple/struct/array into named variables in one declaration:

#include <map>
#include <string>
#include <iostream>

int main() {
    std::map<std::string, int> ages = {{"Ada", 36}};
    for (const auto& [name, age] : ages) {          // unpacks each pair<const string, int>
        std::cout << name << " is " << age << '\n';
    }

    struct Point { int x, y; };
    Point p{1, 2};
    auto [x, y] = p;                                  // unpacks a struct's public members
    std::cout << x << ',' << y << '\n';
}

[[likely]]/[[unlikely]]

These C++20 attributes hint the optimizer about which branch is hot, without changing program behavior:

int classify(int status) {
    if (status == 200) [[likely]] {
        return 0;
    } else [[unlikely]] {
        return 1;
    }
}

Measure before adding these — an incorrect hint can make the optimizer’s code layout worse.

goto

goto still exists, mainly for breaking out of deeply nested loops (C++ has no labeled break) or centralized cleanup in code that predates RAII:

for (int i = 0; i < 10; ++i) {
    for (int j = 0; j < 10; ++j) {
        if (i * j > 50) goto done;
    }
}
done:
;

Prefer extracting a function (and returning) or RAII (see Memory Management and Smart Pointers) over goto in new code — it remains mostly for legacy/interop reasons.

Branches and Loops, With the Initializer Forms

Control flow in C++ is mostly the C vocabulary, with three modern additions worth using by default: an initializer inside if and switch that scopes a variable to the statement, structured bindings that unpack a value into named parts, and attributes such as [[fallthrough]] that record intent the compiler can check.

flowchart TB A["if (init; condition)"] --> B["init runs once
variable is in scope for the whole if/else chain"] B --> C{"condition"} C -->|"true"| T["then-branch"] C -->|"false"| F["else-branch (still sees the variable)"] T --> Z["end of statement
variable destroyed"] F --> Z
flow.cpp
#include <map>
#include <print>
#include <string>
#include <string_view>
#include <vector>

struct Book {
    std::string title;
    int copies;
};

enum class Status { available, on_loan, lost };

std::string_view label(Status s) {
    switch (s) {
        case Status::available: return "available";
        case Status::on_loan:   return "on loan";
        case Status::lost:      return "lost";
    }   // no default: -Wswitch warns when an enumerator is added later
    return "?";
}

int fee_days(int days_late) {
    int fee = 0;
    switch (days_late) {
        case 0: break;
        case 1:
        case 2:
            fee = 1;
            break;
        case 3:
            fee = 2;
            [[fallthrough]];   // intentional: 3 days also pays the "late" surcharge below
        default:
            fee += 5;
    }
    return fee;
}

int main() {
    std::map<std::string, Book> catalog{{"isbn-1", {"Dune", 2}}, {"isbn-2", {"Emma", 0}}};

    // if with initializer: `it` is scoped to the if/else chain only.
    if (auto it = catalog.find("isbn-2"); it != catalog.end() && it->second.copies == 0) {
        std::println("{} is out of stock", it->second.title);
    } else if (it != catalog.end()) {
        std::println("{} has copies", it->second.title);
    }

    // Structured bindings unpack pairs, tuples and aggregates.
    for (const auto& [isbn, book] : catalog) {
        std::println("{} -> {} ({})", isbn, book.title, book.copies);
    }

    // Range-for over a braced list or a temporary: the range expression is bound to a hidden
    // reference, so the temporary lives for the whole loop.
    for (int n : std::vector<int>{3, 1, 2}) std::print("{} ", n);
    std::println("");

    for (int d : {0, 1, 3, 9}) std::println("{} days late -> fee {}", d, fee_days(d));
    std::println("{}", label(Status::on_loan));

    // goto is legal but rare; leaving nested loops is its one defensible use.
    for (int i = 0; i < 3; ++i)
        for (int j = 0; j < 3; ++j)
            if (i * j == 2) {
                std::println("found i={} j={}", i, j);
                goto done;
            }
done:
    std::println("done");
}
$ clang++ -std=c++23 -Wall -Wextra flow.cpp -o flow
$ ./flow
Emma is out of stock
isbn-1 -> Dune (2)
isbn-2 -> Emma (0)
3 1 2
0 days late -> fee 0
1 days late -> fee 1
3 days late -> fee 7
9 days late -> fee 5
on loan
found i=1 j=2
done

  • if (auto it = catalog.find(key); it != catalog.end()) keeps the iterator out of the surrounding scope and makes it impossible to use after the check’s else has run. The same pattern with std::lock_guard gives a lock that lasts exactly one statement.

  • In a switch over an enum class, leave out default: with -Wswitch (part of -Wall) the compiler then reports every enumerator you forgot when the enum grows. A default hides that diagnostic.

  • Falling from one case into the next is silent by default. The fee_days function shows the two safe forms: stacked labels with no code between them (case 1: case 2:), which is not a fall-through, and [[fallthrough]]; where code runs and flows on deliberately. The third case there prints 7 for three days late on purpose: it adds 2 and then falls into the default branch’s 5.

  • A structured binding auto& [isbn, book] is a set of names for the members of the object, not a copy and not a new variable of its own type. They work for arrays, tuple-like types and aggregates whose members are all public.

  • goto jumping out of nested loops is the only use most style guides accept; it may not jump over the initialization of a variable still in scope at the label.

Range-for is a rewrite

for (auto&& x : range) body is defined as shorthand for a loop over hidden iterators begin and end, after the range expression has been bound to a hidden auto&& variable. That reference extends the lifetime of a temporary range for the duration of the loop, which is why for (int n : std::vector<int>{3, 1, 2}) is safe. Before C++23 only the outermost temporary was extended, so for (auto x : make_library().books()) iterated a dangling reference when books() returned a view or reference into the temporary Library. C++23 extends every temporary created in the range expression, which fixes that case in compilers that implement it, but the loop is still unsafe if the function returns a reference to an object that was already destroyed. When the code must also build with older toolchains, store the owner in a named variable first.
