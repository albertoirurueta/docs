Members, Constructors, and Member-Initializer Lists

#include <string>

class Person {
public:
    Person(std::string name, int age)
        : name_(std::move(name)), age_(age) {}   // member-initializer list -- initializes, doesn't assign

    const std::string& name() const { return name_; }
    int age() const { return age_; }

private:
    std::string name_;
    int age_;
};

Members are always initialized in declaration order, regardless of the order listed in the member-initializer list (a mismatch here is a common -Wreorder warning) — prefer using std::move for by-value parameters that are stored, exactly as name is above.

Special Member Functions and the Rule of Zero/Three/Five

Six functions are "special": default constructor, destructor, copy constructor, copy-assignment, move constructor, move-assignment. Declaring any of the copy/move/destructor set changes which of the others the compiler still generates:

class RuleOfFive {
public:
    RuleOfFive() = default;
    ~RuleOfFive() { delete[] data_; }                                  // 1. destructor
    RuleOfFive(const RuleOfFive& other)                                 // 2. copy constructor
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
    }
    RuleOfFive& operator=(const RuleOfFive& other) {                    // 3. copy assignment
        if (this == &other) return *this;
        delete[] data_;
        size_ = other.size_;
        data_ = new int[size_];
        std::copy(other.data_, other.data_ + size_, data_);
        return *this;
    }
    RuleOfFive(RuleOfFive&& other) noexcept                              // 4. move constructor
        : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
    }
    RuleOfFive& operator=(RuleOfFive&& other) noexcept {                  // 5. move assignment
        if (this == &other) return *this;
        delete[] data_;
        size_ = other.size_;
        data_ = other.data_;
        other.size_ = 0;
        other.data_ = nullptr;
        return *this;
    }

private:
    std::size_t size_ = 0;
    int* data_ = nullptr;
};

Declaring a destructor that manages a raw resource, as above, is exactly when the rule of five applies — if RuleOfFive didn’t declare a destructor at all, none of the other four would need declaring either. The rule of zero is the preferred outcome: own resources through std::unique_ptr/std::vector/std::string instead of raw pointers, so none of the six special members need writing — the compiler-generated ones already do the right thing by delegating to the members:

#include <vector>
#include <memory>

class RuleOfZero {
public:
    // no destructor, no copy/move ctors/assignment declared -- the compiler-generated ones
    // correctly copy/move buffer_ and owned_, because vector/unique_ptr already implement rule of five themselves
private:
    std::vector<int> buffer_;
    std::unique_ptr<int> owned_;
};

Which of the six special members the compiler implicitly declares (and whether as defaulted or deleted) follows a fixed decision procedure driven by what a class explicitly declares itself:

explicit

Covered in depth in Operator Overloading and Conversions; on a constructor it blocks that constructor from being used for an implicit conversion:

class Meters {
public:
    explicit Meters(double value) : value_(value) {}
    double value_;
};

void printDistance(Meters m);
// printDistance(5.0);       // error: no implicit double -> Meters conversion
printDistance(Meters(5.0));   // fine: explicit construction

static Members

class Counter {
public:
    Counter() { ++instanceCount_; }
    ~Counter() { --instanceCount_; }
    static int instanceCount() { return instanceCount_; }   // static member function: no "this", callable
                                                              // without an instance
private:
    static inline int instanceCount_ = 0;   // inline (C++17): definable in the class body, no separate .cpp needed
};

friend

A friend grants another function or class access to this class’s private members — an escape hatch to use sparingly, since it breaks encapsulation between the two types:

class Box {
public:
    explicit Box(int volume) : volume_(volume) {}
    friend bool sameVolume(const Box& a, const Box& b);   // can reach a.volume_/b.volume_ directly

private:
    int volume_;
};

bool sameVolume(const Box& a, const Box& b) { return a.volume_ == b.volume_; }

const/mutable Correctness and this

A member function marked const promises not to modify the object (the compiler enforces it) and can be called on const objects/references; mutable opts a specific member out of that promise, for state that is an implementation detail rather than part of the object’s logical value (a cache, a mutex):

#include <string>

class Circle {
public:
    explicit Circle(double radius) : radius_(radius) {}

    double area() const {                    // const: does not modify *this
        if (!areaCached_) {
            cachedArea_ = 3.14159265358979 * radius_ * radius_;   // allowed: cachedArea_/areaCached_ are mutable
            areaCached_ = true;
        }
        return cachedArea_;
    }

    Circle& scale(double factor) {             // non-const: modifies *this, returns *this for chaining
        radius_ *= factor;
        areaCached_ = false;
        return *this;                           // "this" is Circle* here; *this dereferences it
    }

private:
    double radius_;
    mutable double cachedArea_ = 0.0;
    mutable bool areaCached_ = false;
};

A Traced Tour of the Special Member Functions

The compiler can generate six special member functions: the default constructor, destructor, copy and move constructors, and copy and move assignment operators. If a class owns a resource that a destructor must release, it needs to define the rest too. This class is the inventory’s member card, which owns a raw array of borrowed-book ids, with every special member printing what it does so that the lifetime of each object is visible.

flowchart TB A["Card a constructed for Ada
ctor: allocate ids"] -->|"Card b = a"| B["copy ctor:
NEW array, memcpy"] B -->|"Card c = std::move(b)"| C["move ctor:
steal pointer
b.ids_ = nullptr"] C -.-> D["b is moved-from:
valid but empty,
destructor still runs, delete[] nullptr is a no-op"] A -->|"d = a"| E["assignment: copy-and-swap
d takes a copy, old buffer freed with the temporary"]
classes.cpp
#include <cstddef>
#include <cstring>
#include <print>
#include <string>
#include <utility>

// A member card that owns a raw buffer of borrowed-book ids: the textbook case for the rule of five.
class Card {
public:
    explicit Card(std::string owner, std::size_t slots = 4)
        : owner_(std::move(owner)), slots_(slots), ids_(new int[slots]{}) {
        std::println("  ctor     {} (slots={})", owner_, slots_);
    }
    ~Card() {
        std::println("  dtor     {}", owner_.empty() ? "(moved-from)" : owner_);
        delete[] ids_;
    }
    Card(const Card& o) : owner_(o.owner_ + " (copy)"), slots_(o.slots_), ids_(new int[o.slots_]) {
        std::memcpy(ids_, o.ids_, slots_ * sizeof(int));
        std::println("  copy     {}", owner_);
    }
    Card(Card&& o) noexcept : owner_(std::move(o.owner_)), slots_(std::exchange(o.slots_, 0)),
                              ids_(std::exchange(o.ids_, nullptr)) {
        std::println("  move     {}", owner_);
    }
    Card& operator=(Card o) noexcept {   // copy-and-swap: one assignment operator for both copy and move
        std::swap(owner_, o.owner_);
        std::swap(slots_, o.slots_);
        std::swap(ids_, o.ids_);
        std::println("  assign   -> {}", owner_);
        return *this;
    }
    void set(std::size_t i, int id) { ids_[i] = id; }
    int get(std::size_t i) const { return ids_[i]; }
    const std::string& owner() const { return owner_; }

private:
    std::string owner_;
    std::size_t slots_;
    int* ids_;
};

// Rule of zero: let the members manage themselves; declare no special member functions.
struct Member {
    std::string name;
    int loans = 0;
};

int main() {
    std::println("construct a, copy into b:");
    Card a("Ada");
    a.set(0, 101);
    Card b = a;
    std::println("move into c:");
    Card c = std::move(b);
    std::println("assign a to d (copy), then move-assign:");
    Card d("Dora");
    d = a;
    d = Card("Temp");
    std::println("rule of zero needs no code:");
    Member m{"Maria"};
    Member m2 = m;
    std::println("{} {} {}", m2.name, c.get(0), d.owner());
    std::println("leaving scope, destructors run in reverse order of construction:");
}

How to read the trace:

  • Card b = a; calls the copy constructor because a is an lvalue. Card c = std::move(b); calls the move constructor because std::move casts b to an rvalue; the buffer changes owner and b is left empty but destructible, which is why its destructor prints (moved-from).

  • The single by-value operator=(Card) is the copy-and-swap idiom: the parameter is copy-constructed (for an lvalue) or move-constructed (for an rvalue), then swapped with *this, so the old buffer is released when the parameter dies. It is exception safe and handles self-assignment without a test. Its cost is one extra move. d = Card("Temp") shows the temporary being built directly in the parameter, with no copy at all (guaranteed elision).

  • Objects are destroyed in reverse order of construction at the end of the scope: d, c, b, a. Members are destroyed in reverse order of their declaration as well, after the destructor body.

  • Member has no special members at all and is copied correctly, because std::string and int already know how. This is the rule of zero: prefer members that manage themselves (std::string, std::vector, std::unique_ptr) and write none of the five. If you do write one of destructor, copy or move operations, you almost always need all five, or = default/= delete for the ones you do not want.

  • Mark move operations noexcept. std::vector moves its elements on growth only if the move constructor cannot throw; otherwise it copies them to keep the strong exception guarantee.

Const, Mutable, Static and Friend in One Class

classes2.cpp
#include <print>
#include <string>
#include <utility>

class Book {
public:
    // explicit prevents surprising implicit conversions from int or string.
    explicit Book(std::string title, int year = 0) : title_(std::move(title)), year_(year) { ++count_; }
    Book(const Book& o) : title_(o.title_), year_(o.year_), reads_(o.reads_) { ++count_; }
    ~Book() { --count_; }

    const std::string& title() const { return title_; }
    int reads() const { return reads_; }
    void touch() const { ++reads_; }   // mutable member: logical constness, physical change
    static int count() { return count_; }
    friend std::string audit(const Book& b);   // non-member with access to private members

private:
    std::string title_;
    int year_;
    mutable int reads_ = 0;
    inline static int count_ = 0;   // one per class, not per object
};

std::string audit(const Book& b) { return b.title_ + "/" + std::to_string(b.year_); }

void show(const Book& b) {   // takes const&: can only call const members
    b.touch();
    std::println("{} read {} time(s)", b.title(), b.reads());
}

int main() {
    Book dune("Dune", 1965);
    show(dune);
    show(dune);
    {
        Book copy = dune;
        std::println("live books: {}", Book::count());
    }
    std::println("live books after scope: {}", Book::count());
    std::println("{}", audit(dune));
    // show("Emma");   // error: no implicit conversion from const char* to Book (constructor is explicit)
}
$ clang++ -std=c++23 -Wall -Wextra classes2.cpp -o classes2
$ ./classes2
Dune read 1 time(s)
Dune read 2 time(s)
live books: 2
live books after scope: 1
Dune/1965

  • A const member function promises not to change the observable state, and is the only kind callable through a const Book&. mutable is for state that is not part of the object’s logical value (a cache, a counter or a mutex) and can change inside a const function; it is a design statement, not a loophole.

  • inline static int count_ is one variable shared by every Book, defined right at the declaration since C++17. Before that, a static data member needed a separate definition in exactly one source file.

  • explicit on a constructor stops the compiler converting a std::string or int into a Book behind your back. The commented-out call show("Emma") would otherwise create a temporary Book.

  • A friend function is not a member; it simply may reach private data. Keep friendship to operators and tightly coupled helpers.
