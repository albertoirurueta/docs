Threads and Synchronization

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

std::thread and std::jthread

#include <thread>
#include <iostream>

void work(int id) {
    std::cout << "worker " << id << '\n';
}

int main() {
    std::thread t(work, 1);
    t.join();                         // must join() or detach() before a std::thread is destroyed --
                                        // otherwise std::terminate is called

    std::jthread jt(work, 2);          // C++20: automatically joins in its destructor -- no manual join() needed
}

Prefer std::jthread in new code — forgetting to join()/detach() a plain std::thread is a classic bug that jthread's RAII destructor eliminates entirely.

stop_token Cancellation

std::jthread also wires up cooperative cancellation automatically — the running function can accept a std::stop_token and periodically check it:

#include <thread>
#include <chrono>
#include <iostream>

void pollingWork(std::stop_token token) {
    while (!token.stop_requested()) {
        std::this_thread::sleep_for(std::chrono::milliseconds(50));
    }
    std::cout << "stopped cooperatively\n";
}

int main() {
    std::jthread jt(pollingWork);
    std::this_thread::sleep_for(std::chrono::milliseconds(120));
    jt.request_stop();                 // also happens automatically when jt is destroyed
}

Mutexes and Lock Helpers

#include <mutex>
#include <shared_mutex>

std::mutex m;
int sharedCounter = 0;

void increment() {
    std::lock_guard<std::mutex> lock(m);   // locks on construction, unlocks on destruction -- exception-safe
    ++sharedCounter;
}

std::mutex m1, m2;
void transferSafely() {
    std::scoped_lock lock(m1, m2);          // C++17: locks BOTH atomically, avoiding a classic deadlock from
}                                             // two threads locking m1/m2 in opposite order

void conditionalWork() {
    std::unique_lock<std::mutex> lock(m);    // more flexible than lock_guard: can unlock/relock, or defer
    lock.unlock();                             // locking -- required by condition_variable::wait, below
    // ... unlocked work ...
    lock.lock();
}

std::shared_mutex rw;
int cachedValue = 0;
int readValue() {
    std::shared_lock<std::shared_mutex> lock(rw);   // multiple readers may hold this simultaneously
    return cachedValue;
}
void writeValue(int v) {
    std::unique_lock<std::shared_mutex> lock(rw);    // exclusive: blocks all readers and other writers
    cachedValue = v;
}

Condition Variables

#include <condition_variable>
#include <mutex>
#include <queue>

std::mutex m;
std::condition_variable cv;
std::queue<int> queue;

void producer() {
    {
        std::lock_guard<std::mutex> lock(m);
        queue.push(42);
    }
    cv.notify_one();
}

void consumer() {
    std::unique_lock<std::mutex> lock(m);
    cv.wait(lock, [] { return !queue.empty(); });   // atomically unlocks while waiting, relocks before
    int value = queue.front();                        // returning -- the predicate guards against spurious wakes
    queue.pop();
    (void)value;
}

latch, barrier, and counting_semaphore

Three C++20 coordination primitives, each for a distinct pattern:

#include <latch>
#include <barrier>
#include <semaphore>
#include <thread>
#include <vector>

void latchDemo() {
    std::latch done(3);                     // a one-shot countdown: wait() blocks until count reaches 0
    std::vector<std::jthread> workers;
    for (int i = 0; i < 3; ++i) {
        workers.emplace_back([&done] { done.count_down(); });
    }
    done.wait();                              // main proceeds only once all 3 have counted down
}

void barrierDemo() {
    std::barrier sync(3);                    // reusable: unlike latch, resets automatically for the next round
    std::vector<std::jthread> workers;
    for (int i = 0; i < 3; ++i) {
        workers.emplace_back([&sync] { sync.arrive_and_wait(); });   // blocks until all 3 arrive, THEN releases
    }
}

std::counting_semaphore<4> pool(4);           // caps concurrent access to a limited resource (e.g. 4 connections)
void useResource() {
    pool.acquire();
    // ... use the limited resource ...
    pool.release();
}

thread_local

A thread_local variable has its own independent instance per thread — initialized lazily on first use in each thread:

#include <thread>
#include <iostream>

thread_local int counter = 0;

void increment() {
    ++counter;                     // each thread sees and modifies its OWN counter, no synchronization needed
    std::cout << counter << '\n';
}

Exceptions From Threads

An exception that escapes a std::thread's function calls std::terminate — it does not propagate to the joining thread. Catch it inside the thread function, or use std::async/std::promise (see Async, Futures, and Atomics), where an exception is captured and re-thrown from .get():

#include <thread>
#include <iostream>
#include <exception>

void safeWork() {
    try {
        throw std::runtime_error("boom");
    } catch (const std::exception& e) {
        std::cout << "handled inside the thread: " << e.what() << '\n';
    }
}

std::osyncstream

Covered in Input, Output, and Streams — essential whenever multiple threads write to std::cout concurrently, to avoid interleaved output.

Synchronization Primitives at a Glance

Threads, Locks and Waiting, With Output

A thread is an independent flow of control that shares the address space with every other thread. Sharing is the source of both the speed and the bugs: two threads that touch the same non-atomic variable, one of them writing, without synchronization commit a data race, which is undefined behaviour for the entire program.

sequenceDiagram participant P as producer (main) participant Q as Returns queue (mutex + condvar) participant C as consumer (jthread) C->>Q: pop locks and waits until non-empty Note over C: unlocked and asleep P->>Q: push Dune under the lock P->>Q: notify_one() Q-->>C: wakes, relocks, predicate true C->>C: processes the title P->>C: request_stop() Q-->>C: wait returns false and the loop ends
threads.cpp
#include <atomic>
#include <chrono>
#include <condition_variable>
#include <latch>
#include <mutex>
#include <print>
#include <queue>
#include <stop_token>
#include <string>
#include <thread>
#include <vector>

// Shared state: the number of copies. Without the mutex, concurrent increments race (undefined behaviour).
class Stock {
public:
    void add(int n) {
        std::lock_guard<std::mutex> lock(m_);
        copies_ += n;
    }
    int copies() const {
        std::lock_guard<std::mutex> lock(m_);
        return copies_;
    }

private:
    mutable std::mutex m_;
    int copies_ = 0;
};

// Producer/consumer queue guarded by a mutex and condition variable.
class Returns {
public:
    void push(std::string title) {
        { std::lock_guard<std::mutex> lock(m_); q_.push(std::move(title)); }
        cv_.notify_one();
    }
    // Waits until an item arrives or a stop is requested. The predicate guards against spurious wake-ups.
    bool pop(std::string& out, std::stop_token st) {
        std::unique_lock<std::mutex> lock(m_);
        if (!cv_.wait(lock, st, [&] { return !q_.empty(); })) return false;
        out = std::move(q_.front());
        q_.pop();
        return true;
    }

private:
    std::mutex m_;
    std::condition_variable_any cv_;
    std::queue<std::string> q_;
};

int main() {
    // Eight threads each add 1000 copies; the mutex makes the result exact.
    Stock stock;
    {
        std::vector<std::jthread> workers;   // jthread joins in its destructor: no std::terminate on early exit
        for (int i = 0; i < 8; ++i) workers.emplace_back([&] { for (int k = 0; k < 1000; ++k) stock.add(1); });
    }   // all threads are joined here
    std::println("total copies: {}", stock.copies());

    // A consumer thread processes returned books until asked to stop.
    Returns returns;
    std::atomic<int> processed{0};
    std::jthread consumer([&](std::stop_token st) {
        std::string title;
        while (returns.pop(title, st)) ++processed;
    });
    for (auto t : {"Dune", "Emma", "Alien"}) returns.push(t);
    while (processed.load() < 3) std::this_thread::yield();
    consumer.request_stop();   // wakes the waiting consumer; pop returns false
    consumer.join();
    std::println("processed {} returned books, consumer stopped cleanly", processed.load());

    // std::latch: wait for N workers to finish a phase.
    std::latch ready(3);
    std::atomic<int> loaded{0};
    std::vector<std::jthread> loaders;
    for (int i = 0; i < 3; ++i)
        loaders.emplace_back([&] { ++loaded; ready.count_down(); });
    ready.wait();
    std::println("all {} loaders finished before continuing", loaded.load());

    // thread_local: each thread has its own copy.
    thread_local int counter = 0;
    ++counter;
    int seen_in_other = -1;
    std::thread([&] { seen_in_other = counter; }).join();
    std::println("main counter {}, other thread's counter {}", counter, seen_in_other);
}
$ clang++ -std=c++23 -Wall -Wextra threads.cpp -o threads
$ ./threads
total copies: 8000
processed 3 returned books, consumer stopped cleanly
all 3 loaders finished before continuing
main counter 1, other thread's counter 0

  • Eight threads each add 1000 times, and the total is exactly 8000 because Stock::add holds the mutex across the read-modify-write. The scoped std::lock_guard releases the lock on every path out of the function, including by exception. Prefer std::scoped_lock when you need several mutexes: it locks them together with a deadlock-avoiding algorithm, so threads that need two locks cannot deadlock by taking them in opposite order.

  • std::jthread joins in its destructor, so leaving the scope waits for the workers. A plain std::thread that is still joinable when destroyed calls std::terminate, which is the most common thread bug in older code. jthread also supplies a std::stop_token: request_stop() is cooperative and wakes a condition_variable_any wait, so the consumer exits without a sentinel value.

  • Waiting on a condition variable always uses a predicate ([&]{ return !q_.empty(); }). Wake-ups can be spurious, and a notification sent before the waiter started is lost, so the state that the predicate tests must live under the same mutex.

  • std::latch is a one-shot countdown: three loaders call count_down() and the main thread’s wait() returns after the third. Use std::barrier for a repeating phase and std::counting_semaphore to bound a resource.

  • A thread_local variable has one copy per thread: the other thread saw 0 while main saw 1.

The race detector

Run the build with ThreadSanitizer (-fsanitize=thread) in CI. This two-thread counter increments a plain int without synchronization:

race.cpp
#include <print>
#include <thread>
int main() {
    int copies = 0;                     // plain int shared between two threads: a data race
    std::thread a([&] { for (int i = 0; i < 100000; ++i) ++copies; });
    std::thread b([&] { for (int i = 0; i < 100000; ++i) ++copies; });
    a.join(); b.join();
    std::println("copies = {}", copies);
}
$ clang++ -std=c++23 -fsanitize=thread race.cpp -o race && ./race 2>&1 | grep -E 'WARNING|SUMMARY' | sed 's/ (pid=[0-9]*)//'
WARNING: ThreadSanitizer: data race
SUMMARY: ThreadSanitizer: data race (race:arm64+0x1000021cc) in main::$_1::operator()() const+0x70

The final value of copies would be anywhere between 100000 and 200000, and differs from run to run; the sanitizer reports the race itself regardless of whether the wrong value happened to appear. Fix it with std::atomic<int> or a mutex, and rerun under the sanitizer.
