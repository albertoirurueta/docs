Move Semantics and Value Categories

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Value categories (lvalue/prvalue/xvalue) were introduced in Operators and Expressions; this page covers what they make possible: transferring ownership of a resource instead of copying it.

Rvalue References and std::move

An rvalue reference (T&&) binds only to rvalues (temporaries, or anything explicitly cast to one), which is exactly the signal a type needs to safely "steal" from its argument instead of copying:

#include <utility>
#include <vector>

class Buffer {
public:
    explicit Buffer(std::size_t size) : size_(size), data_(new int[size]) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)                       // copy: allocates a new buffer, copies elements
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    Buffer(Buffer&& other) noexcept                     // move: steals the pointer, leaves other empty
        : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
    }

private:
    std::size_t size_;
    int* data_;
};

int main() {
    Buffer a(1000);
    Buffer b = std::move(a);   // a's buffer is now owned by b; a is left in a valid-but-unspecified,
                                // "moved-from" state -- safe to destroy or reassign, but not to read
}

std::move does not itself move anything — it is purely a static_cast<T&&>, i.e. it casts its argument to an xvalue so overload resolution picks the move overload instead of the copy overload.

std::forward and Perfect Forwarding

In a template, a forwarding reference (T&& where T is deduced) can bind to either an lvalue or an rvalue; std::forward<T> preserves which one it originally was when passing it along, so a generic wrapper doesn’t force an unwanted copy:

#include <utility>
#include <memory>

template <typename T, typename... Args>
std::unique_ptr<T> makeUniqueLike(Args&&... args) {           // Args&& here are forwarding references
    return std::make_unique<T>(std::forward<Args>(args)...);   // forwards each argument as it originally was
}

struct Point { Point(int, int) {} };
// makeUniqueLike<Point>(1, 2) forwards two rvalues (int literals) without any unnecessary copy

Do not confuse T&& in a template with deduced T (a forwarding reference) with T&& where T is a concrete, non-deduced type (an ordinary rvalue reference, as in Buffer(Buffer&& other) above) — the syntax looks identical but the binding rules differ.

Copy Elision and Guaranteed Elision

Since C++17, returning a temporary by value from a function is guaranteed to construct directly in the caller’s storage — no copy or move constructor is even required to exist, let alone called:

Buffer makeBuffer() {
    return Buffer(1000);        // guaranteed elision (C++17): constructed directly into the caller's variable
}

int main() {
    Buffer buf = makeBuffer();   // no copy, no move -- Buffer is built in buf's storage directly
}

Named Return Value Optimization (NRVO) — eliding the copy/move of a named local returned from a function — is still only an optional (though near-universally applied) optimization, not guaranteed by the standard:

Buffer makeBufferNamed() {
    Buffer local(1000);
    return local;              // NRVO likely applies (not guaranteed) -- and even if it didn't, "local" is an
}                                 // lvalue that the compiler still implicitly treats as movable-from here

noexcept Moves

std::vector (and other containers) only move elements during reallocation if the move constructor is noexcept — otherwise it falls back to copying, to preserve the strong exception-safety guarantee (a reallocation that fails partway through must not leave the original data corrupted):

class SafeToMove {
public:
    SafeToMove(SafeToMove&&) noexcept = default;      // vector will move these on reallocation
    SafeToMove(const SafeToMove&) = default;
};

class RiskyToMove {
public:
    RiskyToMove(RiskyToMove&&) = default;               // NOT noexcept -- vector will copy these instead,
    RiskyToMove(const RiskyToMove&) = default;            // even though a move constructor exists
};

Always mark a move constructor/assignment noexcept when it genuinely cannot throw (which is nearly always, since a move typically just swaps a few pointers/scalars).

Returning by Value

Given guaranteed elision, returning a large object by value is now the idiomatic, efficient choice in most cases — there is rarely a reason to reach for an output parameter (void compute(Result& out)) purely for performance:

#include <vector>

std::vector<int> computeSquares(int n) {
    std::vector<int> result;
    result.reserve(n);
    for (int i = 0; i < n; ++i) result.push_back(i * i);
    return result;              // elided or, worst case, moved -- never deep-copied
}

Copy vs. Move of a Buffer-Owning Object

Tracing Copies, Moves and Elisions

Move semantics make "transfer ownership of the contents" something the type system can express. A move constructor takes an rvalue reference (T&&), steals the resources and leaves the source in a valid but unspecified state. The traced class below prints every construction, copy, move and destruction, so you can count them.

move.cpp
#include <print>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

struct Tracer {
    std::string name;
    explicit Tracer(std::string n) : name(std::move(n)) { std::println("  construct {}", name); }
    Tracer(const Tracer& o) : name(o.name + "'") { std::println("  COPY      {}", o.name); }
    Tracer(Tracer&& o) noexcept : name(std::move(o.name)) { std::println("  move      {}", name); }
    ~Tracer() { std::println("  destroy   {}", name.empty() ? "(empty)" : name); }
};

Tracer make_prvalue() { return Tracer("prvalue"); }          // guaranteed elision: constructed in the caller
Tracer make_named() { Tracer t("named"); return t; }          // NRVO: usually elided, not guaranteed
Tracer make_cond(bool b) { Tracer x("x"), y("y"); return b ? x : y; }   // cannot elide: forces a copy

void sink(Tracer t) { std::println("  sink got {}", t.name); }                   // by value: copy or move in
void take_lvalue(const Tracer&) { std::println("  overload: const&"); }
void take_rvalue(Tracer&&) { std::println("  overload: &&"); }

template <typename T>
void relay(T&& arg) {   // forwarding reference: T deduces to Tracer& for lvalues, Tracer for rvalues
    if constexpr (std::is_lvalue_reference_v<T>) take_lvalue(arg); else take_rvalue(std::forward<T>(arg));
}

int main() {
    std::println("prvalue:");
    Tracer a = make_prvalue();
    std::println("named return:");
    Tracer b = make_named();
    std::println("conditional return:");
    Tracer c = make_cond(true);
    std::println("pass lvalue / pass moved:");
    sink(a);
    sink(std::move(a));
    std::println("forwarding:");
    relay(b);
    relay(Tracer("temp"));
    std::println("vector growth with noexcept move:");
    std::vector<Tracer> v;
    v.reserve(1);
    v.push_back(Tracer("v1"));
    v.push_back(Tracer("v2"));
    std::println("end of main");
}

Reading the trace:

  • make_prvalue and make_named each print a single construct: no copy and no move. The first is guaranteed by the language since C++17; the second is the named return value optimization, which clang applied here but the standard only permits. A returned local that is not elided is moved, not copied, so return local; is both fast and correct. Writing return std::move(local); is a pessimization: it turns the expression into an rvalue of a different form, which disables the elision.

  • make_cond constructs two objects and then copies one of them: the conditional expression b ? x : y is not the name of a local, so neither elision nor the implicit move applies. Use an if with separate returns instead.

  • sink(a) copies (the argument is an lvalue); sink(std::move(a)) moves. std::move does not move anything: it is a cast to T&& that makes the overload resolution choose the move constructor. After the move, a holds an empty name and may only be destroyed or assigned to.

  • relay(T&& arg) is a forwarding reference: because T is deduced, T&& can bind to both lvalues and rvalues, and std::forward<T>(arg) restores the original category. The const& overload is chosen for the lvalue b, the && overload for the temporary. A parameter of type Tracer&& (no deduction) is not a forwarding reference.

  • In the vector growth lines, adding v2 to a full vector reallocates and moves v1 into the new buffer. That happens only because the move constructor of Tracer is noexcept; if it were not, std::vector would copy v1 to preserve the strong guarantee if a later move threw.

  • The destroy (empty) lines are moved-from objects: moves do not remove the need for a destructor to run.
