Lexical Structure and Style

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Tokens and Identifiers

Source text is broken into tokens: identifiers, keywords, literals, operators/punctuators, and comments (which are removed before tokenizing). An identifier is a sequence of letters, digits, and underscores not starting with a digit; C++ identifiers may also contain Unicode characters via universal character names.

Names starting with an underscore followed by an uppercase letter (_Foo), or containing a double underscore (foo__bar), and any name starting with an underscore at global scope, are reserved to the implementation — never define your own names in that space, even though the compiler will not always diagnose it.

Keywords

C++23 has around 95 reserved keywords (int, class, template, constexpr, co_await, requires, concept, …​) that cannot be used as identifiers. <version> and feature-test macros (see Namespaces, Modules, and the Preprocessor) let code detect which contextual keywords/features a given compiler supports.

Literals

int decimal = 42;
int octal = 052;              // leading 0 -- octal
int hex = 0x2A;                // 0x -- hexadecimal
int binary = 0b0010'1010;      // 0b -- binary; digit separators (') improve readability
long long big = 42LL;
unsigned u = 42U;

double d1 = 3.14;
double d2 = 6.02e23;           // scientific notation
float f = 3.14f;

char c = 'A';
char8_t u8c = u8'A';
char16_t u16c = u'A';
char32_t u32c = U'A';

const char* s = "hello";
const char8_t* u8s = u8"hello";
const wchar_t* ws = L"hello";

bool flag = true;
std::nullptr_t np = nullptr;

Raw String Literals

A raw string literal (R"(...)") suppresses escape-sequence processing — ideal for regular expressions, file paths, and embedded code:

#include <iostream>

int main() {
    const char* path = R"(C:\Users\name\file.txt)";   // no need to escape backslashes
    const char* regexPattern = R"(\d{3}-\d{4})";
    std::cout << path << '\n' << regexPattern << '\n';
}

An optional delimiter (R"delim(...)delim") lets the literal contain the sequence )" itself.

User-Defined Literals

A user-defined literal (UDL) attaches a suffix to a literal, calling a function you define:

#include <iostream>
#include <chrono>

constexpr long double operator""_km(long double value) {
    return value * 1000.0L;   // kilometers to meters
}

int main() {
    long double distance = 5.0_km;
    std::cout << distance << '\n';                 // 5000
    std::cout << std::chrono::seconds(3).count() << '\n';   // library UDLs: 3s, 3min, 3h also exist via <chrono>
}

Standard library UDLs like 3s/3min (<chrono>), "text"s (std::string), and "pattern"sv (std::string_view) live in inline namespaces such as std::literals::chrono_literals — see Strings and Text and Dates, Times, and Chrono.

Comments

// a single-line comment, to end of line

/* a block comment,
   spanning multiple lines */

/// a documentation comment (Doxygen-style, convention only -- not part of the standard)
int square(int x);

Attributes

Standard attributes, written [[name]], annotate a declaration or statement for the compiler without changing its meaning:

[[nodiscard]] int computeChecksum(const std::string& data);   // warn if the return value is discarded

[[deprecated("use computeChecksum instead")]]
int checksum(const std::string& data);

void handle(int status) {
    switch (status) {
        case 0:
            [[fallthrough]];   // silences "missing break" warnings intentionally
        case 1:
            break;
        default:
            [[unlikely]] throw std::runtime_error("bad status");
    }
}

Naming and Formatting Conventions

The C++ Core Guidelines do not mandate one house style, but the ecosystem has converged on common patterns worth following for consistency with most open-source code and with the standard library itself:

  • Types: PascalCase (project-specific) or snake_case (matching standard-library style, e.g. unique_ptr).

  • Functions and variables: camelCase or snake_case, consistently within a codebase.

  • Constants and enumerators: kConstantName or ALL_CAPS, depending on house style.

  • Macros: ALL_CAPS always — macros have no scope, so an unmistakable name reduces accidental collisions.

  • Private/implementation-only members: a trailing or leading underscore (count_ or _count) by convention, never both, and never the reserved patterns from Tokens and Identifiers above.

clang-format (see Build and Tooling) automates formatting so style debates do not repeat per pull request.

Literals, Separators and Attributes in Practice

Source text is turned into tokens in well-defined translation phases: trigraph-free character mapping, line splicing, comment removal and tokenization come first, then preprocessing, then adjacent string literals are concatenated, and only after that does the compiler see tokens. Several visible behaviours follow from that order, and the example below touches most of them using the inventory domain.

flowchart LR A["source characters"] --> B["line splicing
backslash-newline removed"] B --> C["tokens + comments
comments become one space"] C --> D["preprocessing
#include, #define, #if"] D --> E["string concatenation
'a' 'b' becomes 'ab'"] E --> F["parse and type-check"]
literals.cpp
#include <cstdint>
#include <print>
#include <string>
#include <string_view>

// A user-defined literal for the inventory: 3_copies is an int, but the suffix documents intent.
constexpr int operator""_copies(unsigned long long n) { return static_cast<int>(n); }

// A literal that builds a ready-made Book title with the year attached.
std::string operator""_t(const char* s, std::size_t n) { return std::string(s, n) + " (reissue)"; }

[[nodiscard]] int checkout(int copies) { return copies - 1; }

int main() {
    // Numeric literals: bases, digit separators, suffixes.
    int dec = 1'000'000;
    int hex = 0xFF;
    int bin = 0b1010'1010;
    unsigned long long big = 18'446'744'073'709'551'615ULL;
    double d = 1.5e3;
    std::println("{} {} {} {} {}", dec, hex, bin, big, d);

    // Character and string literals have different types.
    std::println("{} {} {}", sizeof('a'), sizeof("abc"), sizeof(u8"abc"));
    std::println("{}", sizeof(L'a') >= 2);

    // Raw strings keep backslashes and quotes untouched.
    std::string_view path = R"(C:\data\books "new")";
    std::println("{}", path);
    std::string_view multi = R"sql(SELECT title
FROM books
WHERE copies > 0)sql";
    std::println("{}", multi);

    // Adjacent literals concatenate at translation phase 6.
    std::println("{}", "Library "
                       "inventory");

    std::println("{} {}", 3_copies, "Dune"_t);

    // Ignoring a [[nodiscard]] result warns.
    int left = checkout(3_copies);
    std::println("{}", left);
    checkout(1);   // warning: ignoring return value of function declared with 'nodiscard'
}

Points worth noticing in the output and the warning:

  • sizeof('a') is 1 in C++ but 4 in C, because a character literal has type char in C++ and int in C. The array "abc" has four elements (the terminating zero), and u8"abc" has type const char8_t[4] since C++20, which is not the same type as const char[4]; the two are not implicitly interchangeable.

  • The digit separator '+ is ignored for the value and exists only for the reader: 1'000'000 and 0b1010'1010.

  • A raw string literal R"delim(...)delim" performs no escape processing, so it is the tool of choice for Windows paths, regular expressions, JSON and SQL. The delimiter (sql above) only has to differ from anything that follows a ) in the text.

  • A user-defined literal calls the function operator""_name. The suffix must start with an underscore in user code; names without one are reserved for the standard library (s, sv, ms, i).

  • [[nodiscard]] turns "ignored result" into a compiler warning. It is the cheapest way to make a function whose return value is an error indicator hard to misuse.

Names the standard reserves

An identifier that contains a double underscore, or begins with an underscore followed by an uppercase letter, is reserved for the implementation everywhere; a name that begins with an underscore is also reserved in the global namespace. Defining __book_count or _Inventory compiles on most compilers and then collides with a library macro on a different one, so style guides ban them outright. Names such as std or macros that the preprocessor substitutes before the compiler ever sees the declaration are the other source of surprises: a header defining #define min(a, b) silently rewrites std::min in code that is parsed later.
