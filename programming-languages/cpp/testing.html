Testing

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

C++ has no single built-in test framework the way JUnit/pytest anchor Java/Python — GoogleTest and Catch2 are today’s two dominant third-party choices, both integrating with CMake’s ctest runner.

GoogleTest: Assertions and Fixtures

#include <gtest/gtest.h>

int add(int a, int b) { return a + b; }

TEST(CalculatorTest, AddsTwoNumbers) {
    EXPECT_EQ(add(2, 3), 5);          // EXPECT_* reports a failure but keeps running the test
    ASSERT_EQ(add(-1, 1), 0);          // ASSERT_* aborts the current test immediately on failure
}

class DatabaseTest : public ::testing::Test {
protected:
    void SetUp() override { connection_ = openTestConnection(); }     // runs before EACH test
    void TearDown() override { connection_.close(); }                    // runs after EACH test
    Connection connection_;
};

TEST_F(DatabaseTest, InsertsARow) {         // TEST_F: uses the DatabaseTest fixture above
    EXPECT_TRUE(connection_.insert("row"));
}

GoogleTest: Parameterized Tests

Runs the same test body once per value in a supplied list, instead of hand-duplicating near-identical tests:

#include <gtest/gtest.h>

class IsPrimeTest : public ::testing::TestWithParam<int> {};

TEST_P(IsPrimeTest, RecognizesPrimes) {
    EXPECT_TRUE(isPrime(GetParam()));
}

INSTANTIATE_TEST_SUITE_P(SmallPrimes, IsPrimeTest, ::testing::Values(2, 3, 5, 7, 11, 13));

GoogleMock

Generates mock implementations of an interface, with expectations on how the mock is called:

#include <gmock/gmock.h>

class Repository {
public:
    virtual ~Repository() = default;
    virtual std::string findById(int id) = 0;
};

class MockRepository : public Repository {
public:
    MOCK_METHOD(std::string, findById, (int id), (override));
};

TEST(ServiceTest, LooksUpById) {
    MockRepository mock;
    EXPECT_CALL(mock, findById(42)).WillOnce(::testing::Return("Ada"));

    Service service(&mock);
    EXPECT_EQ(service.getName(42), "Ada");
}

Catch2: Sections, Matchers, Generators

Catch2’s SECTION shares setup code across multiple sub-tests without a fixture class, re-running the enclosing TEST_CASE once per leaf SECTION:

#include <catch2/catch_test_macros.hpp>
#include <catch2/matchers/catch_matchers_string.hpp>
#include <catch2/generators/catch_generators.hpp>

TEST_CASE("vector operations", "[vector]") {
    std::vector<int> v = {1, 2, 3};

    SECTION("push_back grows the vector") {
        v.push_back(4);
        REQUIRE(v.size() == 4);
    }
    SECTION("pop_back shrinks the vector") {   // setup above re-runs fresh for THIS section too
        v.pop_back();
        REQUIRE(v.size() == 2);
    }
}

TEST_CASE("string matchers") {
    std::string greeting = "Hello, World!";
    REQUIRE_THAT(greeting, Catch::Matchers::StartsWith("Hello"));
}

TEST_CASE("generated values") {
    int x = GENERATE(1, 2, 3);         // the whole TEST_CASE runs once per generated value
    REQUIRE(x > 0);
}

Boost.Test

Predates both GoogleTest and Catch2, still common in older/Boost-adjacent codebases:

#define BOOST_TEST_MODULE CalculatorTests
#include <boost/test/included/unit_test.hpp>

BOOST_AUTO_TEST_CASE(adds_two_numbers) {
    BOOST_CHECK_EQUAL(add(2, 3), 5);        // like EXPECT_*: reports failure, keeps running
    BOOST_REQUIRE_EQUAL(add(-1, 1), 0);      // like ASSERT_*: aborts the test on failure
}

CTest Integration

CMake’s built-in test runner discovers and runs tests registered via add_test (or GoogleTest’s own gtest_discover_tests helper, which registers each TEST/TEST_F individually):

enable_testing()
find_package(GTest REQUIRED)

add_executable(unit_tests calculator_test.cpp)
target_link_libraries(unit_tests PRIVATE GTest::gtest_main)

include(GoogleTest)
gtest_discover_tests(unit_tests)
ctest --output-on-failure
ctest -R CalculatorTest    # run only tests matching a name pattern

Testing constexpr Code with static_assert

Code that runs at compile time can be tested at compile time too — a static_assert failure fails the build itself, immediately, with no separate test binary to run:

constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}

static_assert(factorial(0) == 1);
static_assert(factorial(5) == 120);
static_assert(factorial(1) == 1);

This complements, rather than replaces, run-time tests — it verifies the constexpr path specifically, and gives immediate feedback during compilation for logic that’s meant to be evaluable at compile time in the first place.

What a Test Framework Does Underneath

GoogleTest, Catch2 and Boost.Test all provide the same three things: a way to register test functions without writing a main that lists them, assertion macros that record a failure with file and line, and a runner that catches exceptions, prints a summary and sets the process exit code for CI. The mini framework below implements all three in about forty lines so the pieces are no longer magic, and tests a small piece of the inventory’s borrowing rules with it.

flowchart TB T["TEST(name) macro"] --> S["defines a function
and a static Registrar object"] S -->|"constructor runs BEFORE main
(static initialization)"| R[("registry: vector of name + function")] M["main()"] --> L["for each registered test"] R --> L L --> TRY{"try: run body"} TRY -->|"returns"| OK["print OK"] TRY -->|"EXPECT_* throws Failure"| F["print FAIL with file:line and expression"] L --> E["exit status = number of failures != 0"]
minitest.cpp
// minitest.cpp -- a 40-line test framework, to show what GoogleTest, Catch2 and Boost.Test do underneath.
#include <functional>
#include <map>
#include <print>
#include <stdexcept>
#include <string>
#include <vector>

struct TestCase { std::string name; std::function<void()> body; };
std::vector<TestCase>& registry() { static std::vector<TestCase> r; return r; }   // function-local static: safe init order

struct Registrar {
    Registrar(std::string name, std::function<void()> body) { registry().push_back({std::move(name), std::move(body)}); }
};
struct Failure : std::runtime_error { using std::runtime_error::runtime_error; };

#define TEST(name) \
    static void name(); \
    static Registrar reg_##name(#name, name); \
    static void name()
#define EXPECT_EQ(a, b) \
    do { if (!((a) == (b))) throw Failure(std::string(__FILE__ ":") + std::to_string(__LINE__) + ": " #a " != " #b); } while (0)
#define EXPECT_THROW(stmt, ex) \
    do { bool caught = false; try { stmt; } catch (const ex&) { caught = true; } \
         if (!caught) throw Failure(#stmt " did not throw " #ex); } while (0)

// ---- code under test: the inventory's borrowing rules
class Library {
public:
    void add(const std::string& title, int copies) { stock_[title] += copies; }
    void borrow(const std::string& title) {
        auto it = stock_.find(title);
        if (it == stock_.end()) throw std::out_of_range("unknown title");
        if (it->second == 0) throw std::runtime_error("no copies");
        --it->second;
    }
    int copies(const std::string& title) const { auto it = stock_.find(title); return it == stock_.end() ? 0 : it->second; }

private:
    std::map<std::string, int> stock_;
};

// ---- tests; a fixture is just a helper that builds the object under test
Library make_library() { Library l; l.add("Dune", 2); return l; }

TEST(borrow_reduces_stock) {
    auto lib = make_library();
    lib.borrow("Dune");
    EXPECT_EQ(lib.copies("Dune"), 1);
}
TEST(borrow_unknown_title_throws) {
    auto lib = make_library();
    EXPECT_THROW(lib.borrow("Emma"), std::out_of_range);
}
TEST(borrow_last_copy_then_fails) {
    auto lib = make_library();
    lib.borrow("Dune");
    lib.borrow("Dune");
    EXPECT_THROW(lib.borrow("Dune"), std::runtime_error);
}
TEST(deliberately_failing_example) {
    auto lib = make_library();
    EXPECT_EQ(lib.copies("Dune"), 3);
}
// parameterized: loop over a table of (copies, borrows, expected remaining)
TEST(parameterized_table) {
    struct Row { int copies, borrows, expected; };
    for (auto r : {Row{3, 1, 2}, Row{5, 5, 0}, Row{1, 0, 1}}) {
        Library l; l.add("X", r.copies);
        for (int i = 0; i < r.borrows; ++i) l.borrow("X");
        EXPECT_EQ(l.copies("X"), r.expected);
    }
}

int main() {
    int failed = 0;
    for (auto& t : registry()) {
        try { t.body(); std::println("[ OK   ] {}", t.name); }
        catch (const std::exception& e) { ++failed; std::println("[ FAIL ] {} -- {}", t.name, e.what()); }
    }
    std::println("{} of {} tests failed", failed, registry().size());
    return failed ? 1 : 0;
}
$ clang++ -std=c++23 -Wall -Wextra minitest.cpp -o minitest
$ ./minitest
[ OK   ] borrow_reduces_stock
[ OK   ] borrow_unknown_title_throws
[ OK   ] borrow_last_copy_then_fails
[ FAIL ] deliberately_failing_example -- minitest.cpp:63: lib.copies("Dune") != 3
[ OK   ] parameterized_table
1 of 5 tests failed

The program exits with status 1 because one test fails on purpose, and that failing exit code is what makes CI red.

  • The registration works because a namespace-scope object is constructed before main: the Registrar pushes each test into a vector as the program starts. The registry is a function-local static so it exists no matter in which order translation units initialize, avoiding the static initialization order problem.

  • EXPECT_EQ is a macro only because it needs __FILE__, __LINE__ and the text of its arguments (#a, #b), which a function cannot capture. The failure message names the exact expression, which is why the real frameworks use macros for assertions.

  • A fixture is shared setup code: here the plain function make_library(). GoogleTest’s TEST_F creates a fresh fixture object per test for the same reason: tests must not depend on one another or on their order.

  • A parameterized test runs the same body over a table. The loop above is the simplest form; GoogleTest’s INSTANTIATE_TEST_SUITE_P and Catch2’s GENERATE report each row as a separate test, which makes a failure easy to locate, while a loop stops at the first failing row.

  • Test behaviour, not implementation: assert on what Library::copies returns after borrow, not on how the map is stored, so refactoring does not break the tests.

The equivalent first test in GoogleTest, linked against GTest::gtest_main (which supplies main), looks like this; it needs GoogleTest installed and is not run on this page:

#include <gtest/gtest.h>

TEST(LibraryTest, BorrowReducesStock) {
    Library lib;
    lib.add("Dune", 2);
    lib.borrow("Dune");
    EXPECT_EQ(lib.copies("Dune"), 1);
}

EXPECT_* records a failure and continues; ASSERT_* aborts the current test, which is what you want when the next line would dereference a null pointer or index past the end.
