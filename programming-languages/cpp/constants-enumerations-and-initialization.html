Constants, Enumerations, and Initialization

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

const, constexpr, consteval, constinit

const int limit = 100;             // run-time constant: cannot be reassigned, but value need not be known at compile time
constexpr int square(int x) {      // may run at compile time OR run time, chosen by the compiler
    return x * x;
}
constexpr int nine = square(3);     // guaranteed evaluated at compile time (used in a constant expression)

consteval int mustBeCompileTime(int x) {   // C++20: an "immediate function" -- MUST run at compile time
    return x * x;
}
// int bad = mustBeCompileTime(getRuntimeValue());   // error: argument not a constant expression

constinit int initializedOnce = square(4);  // C++20: guarantees compile-time *initialization*, but the
                                             // variable itself may still be mutated later at run time -- unlike
                                             // constexpr, constinit does not imply const

constinit solves the "static initialization order fiasco" for namespace-scope variables that must not run a dynamic initializer at process startup, without forcing them to also be immutable afterward.

Scoped and Unscoped Enumerations

#include <utility>   // std::to_underlying (C++23)
#include <iostream>

enum Color { Red, Green, Blue };            // unscoped: enumerators leak into the surrounding scope,
                                             // implicitly convert to int
enum class Suit { Clubs, Diamonds, Hearts, Spades };   // scoped: enumerators must be qualified, no implicit
                                                        // conversion to int

int main() {
    Color c = Red;                          // fine, unqualified
    Suit s = Suit::Hearts;                  // must qualify

    int underlying = std::to_underlying(s);  // C++23: replaces static_cast<int>(s), and works generically
    std::cout << underlying << '\n';         // 2

    using enum Suit;                        // C++20: brings Suit's enumerators into scope, unqualified
    Suit s2 = Hearts;                        // now legal without "Suit::"
    (void)c; (void)s2;
}

Prefer enum class in new code — unscoped enum is kept mainly for interop with older code and C headers.

Uniform/List Initialization and Its Pitfalls

Brace initialization ({}) works uniformly across variables, aggregates, and containers, and rejects narrowing conversions that ()/= silently allow:

int a{5};                 // direct-list-initialization
int b = {5};               // copy-list-initialization
// int c{5.5};             // error: narrowing conversion from double to int -- caught at compile time
int d(5.5);                 // allowed, and silently truncates to 5 -- the pitfall {} avoids

std::vector<int> v1{1, 2, 3};      // three elements: 1, 2, 3
std::vector<int> v2(3, 7);          // three elements, all 7 -- the "most vexing parse"-adjacent trap: () here
                                     // picks the (count, value) constructor, not a 3-element list

The classic pitfall: std::vector<int> v{3, 7} (braces) means two elements, 3 and 7, while std::vector<int> v(3, 7) (parens) means three elements, each 7 — braces prefer an initializer_list constructor when one exists, parens never do.

Default Member Initializers

struct Config {
    int retries = 3;              // used whenever a constructor doesn't set retries itself
    bool verbose = false;
    std::string name{"default"};
};

Config c1;                        // retries=3, verbose=false, name="default"
Config c2{.retries = 5};           // designated initializer overrides just retries; see below

Aggregate Initialization and Designated Initializers

An aggregate (no user-declared constructors, no private/protected non-static data members, no virtual functions, no base classes other than public non-virtual ones) can be initialized member-by-member with braces, optionally naming each member (C++20 designated initializers):

struct Point3D {
    double x;
    double y;
    double z = 0.0;
};

Point3D p1{1.0, 2.0, 3.0};             // positional
Point3D p2{.x = 1.0, .y = 2.0};         // designated -- z keeps its default member initializer, 0.0
// Point3D p3{.y = 2.0, .x = 1.0};      // error: designators must appear in declaration order

Compile-Time Constants and the Initialization Zoo

C++ has more ways to initialize an object than any other mainstream language, and most of them differ in just the ways that cause bugs: whether narrowing is allowed, whether an initializer_list constructor is preferred, and whether a scalar is left holding garbage. The decision below is the one the compiler makes for a declaration T x ...;.

The listing exercises each branch with the inventory types, plus the three keywords that move work to compile time: constexpr (may be evaluated at compile time), consteval (must be), and constinit (a static or thread-local variable that is guaranteed to be initialized before any dynamic initialization runs, but is not const).

init.cpp
#include <array>
#include <cstdint>
#include <print>
#include <string>
#include <vector>

// constexpr: usable at compile time; consteval: MUST run at compile time; constinit: static init guaranteed.
constexpr int loan_days(bool premium) { return premium ? 28 : 14; }
consteval int max_shelves() { return 12 * 4; }
constinit int next_member_id = 1000;   // initialized before main, but still modifiable

enum class Genre : std::uint8_t { fiction, science, history };   // scoped: no implicit conversion to int
enum Legacy { red, green };                                       // unscoped: leaks names, converts to int

struct Book {
    std::string title;
    int year = 2000;       // default member initializer
    int copies = 1;
    Genre genre = Genre::fiction;
};

int main() {
    static_assert(loan_days(true) == 28);
    std::array<int, max_shelves()> shelves{};
    std::println("shelves: {}, loan days: {}", shelves.size(), loan_days(false));
    std::println("next id: {}", next_member_id++);

    // Scoped enum: needs an explicit cast to get the number.
    Genre g = Genre::history;
    std::println("history = {}, sizeof(Genre) = {}", static_cast<int>(g), sizeof(Genre));
    int legacy = green;   // compiles silently
    std::println("legacy green = {}", legacy);

    // The famous brace pitfall: initializer_list constructors win.
    std::vector<int> a(3, 7);   // three elements of value 7
    std::vector<int> b{3, 7};   // two elements: 3 and 7
    std::println("a has {} elements, b has {} elements", a.size(), b.size());

    // Aggregate and designated initializers (members in declaration order).
    Book c{"Dune"};
    Book d{.title = "Hyperion", .copies = 4, .genre = Genre::fiction};
    std::println("{}: year {} copies {}", c.title, c.year, c.copies);
    std::println("{}: year {} copies {}", d.title, d.year, d.copies);

    // Value-initialization zeroes; default-initialization of a scalar does not.
    int zero{};
    std::println("zero = {}", zero);
}
$ clang++ -std=c++23 -Wall -Wextra init.cpp -o init
$ ./init
shelves: 48, loan days: 14
next id: 1000
history = 2, sizeof(Genre) = 1
legacy green = 1
a has 3 elements, b has 2 elements
Dune: year 2000 copies 1
Hyperion: year 2000 copies 4
zero = 0

Things to take from it:

  • constinit solves the static initialization order fiasco for one case: a global whose initializer is a constant expression is initialized during constant initialization, before any other translation unit’s dynamic initializers run, so no other global can observe it half-built. A plain global initialized by a function call has no such guarantee across translation units.

  • enum class has no implicit conversion to int, does not inject its enumerators into the enclosing scope and can name its underlying type (std::uint8_t above), which is also what lets you forward-declare it. The old unscoped enum converts silently, so int legacy = green; compiles.

  • A default member initializer (int year = 2000;) is used by every constructor that does not mention the member, including the implicit one, and keeps Book{"Dune"} an aggregate in C++14 and later.

  • Designated initializers must follow declaration order (.title before .copies), and the members you skip take their default member initializer or are value-initialized.

  • The line std::vector<int> b{3, 7}; is the classic pitfall: braces prefer an initializer_list constructor whenever one is viable, so this is two elements, not "three sevens". When you mean a count and a value, use parentheses.

  • Reading a default-initialized int is undefined behaviour in the general case. int zero{}; costs nothing and removes the risk; make {} your habit for locals and members.
