Compile-Time Programming

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

constexpr/consteval/constinit were introduced in Constants, Enumerations, and Initialization; this page covers the broader toolkit for computing and branching at compile time.

static_assert

A compile-time assertion — fails the build, with a message, instead of failing at run time:

template <typename T>
struct Vector3 {
    static_assert(std::is_arithmetic_v<T>, "Vector3 requires an arithmetic component type");
    T x, y, z;
};

static_assert(sizeof(int) == 4, "this code assumes a 32-bit int");

<type_traits>: Querying and Writing Traits

The standard library’s compile-time type-introspection toolkit — used constantly inside generic/template code to branch on a type’s properties:

#include <type_traits>
#include <vector>

struct Base {};
struct Derived : Base {};

static_assert(std::is_integral_v<int>);
static_assert(!std::is_integral_v<double>);
static_assert(std::is_same_v<int, int>);
static_assert(std::is_pointer_v<int*>);
static_assert(std::is_base_of_v<Base, Derived>);

// Writing a custom trait: detect whether T has a "size()" member
template <typename T, typename = void>
struct HasSize : std::false_type {};

template <typename T>
struct HasSize<T, std::void_t<decltype(std::declval<T>().size())>> : std::true_type {};

template <typename T>
inline constexpr bool HasSizeV = HasSize<T>::value;

static_assert(HasSizeV<std::vector<int>>);
static_assert(!HasSizeV<int>);

std::void_t plus a partial specialization is the classic "detection idiom" — since C++20, a requires expression (see Concepts and Constraints) expresses the same check far more readably: template <typename T> concept HasSize = requires(T t) { t.size(); };.

std::conditional and std::enable_if vs. Concepts

#include <type_traits>

template <typename T>
using StorageType = std::conditional_t<sizeof(T) <= 8, T, T&>;   // pick T or T& based on its size

template <typename T>
std::enable_if_t<std::is_integral_v<T>, T> onlyIntegral(T value) {   // SFINAE: this overload only
    return value;                                                     // participates for integral T
}

std::enable_if/SFINAE was the pre-C++20 way to constrain a template — it works, but produces poor error messages and clutters signatures. Concepts (requires Numeric<T> from Concepts and Constraints) express the same constraint more directly and are strongly preferred in new C++20/23 code; enable_if remains common in pre-C++20 codebases and libraries that still support C++17.

if constexpr and std::is_constant_evaluated

if constexpr was introduced in Control Flow. C++23’s if consteval (also covered there) is generally preferred over the older std::is_constant_evaluated() function, but the latter still appears in code that must also support C++20:

#include <type_traits>

constexpr double approxSqrtOld(double x) {
    if (std::is_constant_evaluated()) {          // C++20 way to ask "am I running at compile time?"
        double guess = x / 2 + 1;
        for (int i = 0; i < 20; ++i) guess = (guess + x / guess) / 2;
        return guess;
    } else {
        return __builtin_sqrt(x);
    }
}

if consteval { ... } (C++23) is preferred over if (std::is_constant_evaluated()) because it cannot be accidentally combined with other runtime conditions in a way that breaks the compile-time guarantee.

Constexpr Virtual Functions

C++20 allows virtual functions to be constexpr, so polymorphic code can run at compile time as long as the dynamic type is itself known at compile time:

struct Shape {
    constexpr virtual double area() const { return 0.0; }
    constexpr virtual ~Shape() = default;
};
struct Square : Shape {
    constexpr explicit Square(double side) : side_(side) {}
    constexpr double area() const override { return side_ * side_; }
private:
    double side_;
};

constexpr double computeArea() {
    Square s(4.0);              // the dynamic type is statically known here -- eligible for compile-time evaluation
    return s.area();
}
static_assert(computeArea() == 16.0);

Computing at Compile Time: constexpr, consteval, Traits and static_assert

C++ lets ordinary code run inside the compiler. A constexpr function is evaluated at compile time whenever all its arguments are constants and its result is needed as one; consteval forces that; static_assert turns a condition into a build failure; and if constexpr discards the untaken branch so one template can do something different for each type. Anything that can be checked at compile time stops being a run-time bug.

flowchart LR SRC["source with constexpr code"] --> FE["compiler front end"] FE --> CE{"needed in a constant expression?
array size, template argument,
static_assert, case label"} CE -->|"yes"| EV["compile-time interpreter runs it:
undefined behaviour is a compile error"] CE -->|"no"| RT["ordinary function:
may still be folded by the optimizer"] EV --> CONST["result embedded in the binary
as a constant"]
ctime.cpp
#include <array>
#include <cstdint>
#include <print>
#include <string>
#include <string_view>
#include <type_traits>

// A constexpr function runs at compile time when its inputs are constants.
constexpr std::uint32_t fnv1a(std::string_view s) {
    std::uint32_t h = 2166136261u;
    for (char c : s) { h ^= static_cast<std::uint8_t>(c); h *= 16777619u; }
    return h;
}

// A compile-time lookup table of loan fees by days late.
constexpr auto make_fees() {
    std::array<int, 8> fees{};
    for (std::size_t d = 0; d < fees.size(); ++d) fees[d] = static_cast<int>(d * d / 2);
    return fees;
}
constexpr auto fees = make_fees();

// consteval: an immediate function; a call with a non-constant argument is a compile error.
consteval int days_in_weeks(int w) { return w * 7; }

// Type traits and if constexpr: one function, different code per type, no run-time branch.
template <typename T>
std::string render(const T& v) {
    if constexpr (std::is_arithmetic_v<T>) return "number " + std::to_string(v);
    else if constexpr (std::is_convertible_v<T, std::string_view>) return "text " + std::string(v);
    else return "unprintable";
}

// A custom trait: does T have a .title() member?
template <typename T, typename = void> struct has_title : std::false_type {};
template <typename T> struct has_title<T, std::void_t<decltype(std::declval<T>().title())>> : std::true_type {};

struct Book { std::string title() const { return "Dune"; } };

static_assert(fnv1a("") == 2166136261u, "hash of the empty string is the offset basis");
static_assert(fees[4] == 8);
static_assert(has_title<Book>::value && !has_title<int>::value);
static_assert(sizeof(std::uint64_t) == 8, "this code assumes 64-bit integers");

int main() {
    constexpr auto h = fnv1a("Dune");                  // computed by the compiler
    std::println("hash(Dune) = {}", h);
    std::println("fee for 5 days late: {}", fees[5]);
    std::println("loan period: {} days", days_in_weeks(3));
    std::println("{} | {} | {}", render(42), render("Emma"), render(Book{}));
    switch (fnv1a("dvd")) {   // case labels must be constants: hashing a string at compile time
        case fnv1a("book"): std::println("book"); break;
        case fnv1a("dvd"): std::println("dvd"); break;
        default: std::println("other");
    }
    [[maybe_unused]] int runtime_weeks = 2;
    // std::println("{}", days_in_weeks(runtime_weeks));   // error: call to consteval function is not a constant expression
}
$ clang++ -std=c++23 -Wall -Wextra ctime.cpp -o ctime
$ ./ctime
hash(Dune) = 1051210499
fee for 5 days late: 12
loan period: 21 days
number 42 | text Emma | unprintable
dvd

  • fees is a table the compiler built from a loop; the binary stores the computed array, and static_assert(fees[4] == 8) verifies it during compilation. The same function would also work at run time, because constexpr does not forbid it.

  • The switch over fnv1a("book") and fnv1a("dvd") works because case labels must be constant expressions, which is the standard way to switch on strings in C++.

  • Constant evaluation is checked: signed overflow, out-of-bounds indexing or dereferencing null inside a constexpr evaluation is a compile error rather than undefined behaviour. This is why constexpr is a good place for unit tests (see Testing).

  • if constexpr branches that are not taken are not instantiated, so std::to_string(v) is never compiled for the Book case. A plain if would require both branches to compile for every T.

  • has_title is the pre-concepts detection idiom: SFINAE removes the partial specialization when declval<T>().title() is invalid. With C++20 the same check is one requires expression in a concept, which is shorter and gives better diagnostics.

  • consteval functions are immediate functions: days_in_weeks(runtime_weeks) would not compile (see the commented-out line), because the value of a runtime variable is not a constant.
