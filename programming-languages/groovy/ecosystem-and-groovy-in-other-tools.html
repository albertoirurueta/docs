Ecosystem & Groovy in Other Tools

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page lists the projects that are built on Groovy or that embed it as their scripting language. Every entry was checked on 2026-10-14 against the project’s own site, its repository or its artifacts on Maven Central. The baseline of the section is Apache Groovy 6.0 (6.0.0, 2026-09-22), and the column "Groovy line" says which line each project embeds or requires, which is often not the line you installed. Where a Groovy line could not be established from a source the project publishes, the cell says not verified instead of guessing. All projects below are third-party except the Groovy modules that ship with Groovy itself (groovy-ant, for example), and none of them is documented further here: each row only points to the project.

Why Groovy is embedded so widely

Groovy runs on the JVM and compiles to ordinary classes, so a host application can load a script with a few lines of Java and let it call the host’s own objects. Three properties explain most of the projects below:

  • Scripting inside a Java process. GroovyShell, GroovyClassLoader and JSR 223 compile and run text at run time, so a tool can offer a "scripts" extension point without inventing a language. See Integrating Groovy into Java Applications.

  • Domain specific languages. Optional parentheses, named arguments and closures with a configurable delegate let a build file, a pipeline or a test read like configuration. See Domain Specific Languages, Closure Delegation: Owner, Delegate & This and Builders.

  • Java interoperability and control of what scripts may do. A script can use every Java library, and compilation customizers and AST transformations let a host restrict or extend the language. See Compilation Customizers & Secure Scripting.

A consequence matters in practice: a script runs on the Groovy line the host embeds, not on the one installed on your machine. A Jenkinsfile, a JMeter JSR223 script or a Gradle build script can only use the language features of the embedded line, so check the column "Groovy line" before copying an example from this section into such a tool. The feature-by-release list is on What’s New & Migrating from Older Versions.

Selection criterion

The page lists, in this order of precedence:

  1. the projects shown on the official Groovy ecosystem page (groovy-lang.org/ecosystem.html): Grails, Gradle, Spock, GPars, Ratpack, Griffon, Geb, SDKMAN!, BeakerX and Micronaut;

  2. the tools shown on the Groovy learning page (groovy-lang.org/learn.html) and the editors table of groovy-lang.org/ides.html;

  3. the most common embedders of Groovy that the section’s other pages already mention: Apache Ant, Jenkins Pipeline, GMavenPlus, Apache JMeter, the Spring Framework, Nextflow, Apache Wayang and JasperReports, plus CodeNarc, the Groovy-Eclipse compiler and the Groovy Web Console.

Inclusion is not a ranking and the page gives no popularity or usage figures. A project that is quiet or unmaintained stays listed, with the dates that show it, because the official ecosystem page still points to it.

How the data was collected

  • "Groovy line" comes from the project’s own pages or build files: a published pom.xml on Maven Central, the version property of the project’s build (gradle.properties, pom.xml) on its default branch, or a compatibility table in its documentation. It says what the project is built with or declares, and not that every combination was tested.

  • "Status" gives the latest release or artifact date and the date of the last commit to the default branch, read from Maven Central, the GitHub API or the project’s site on 2026-10-14. No project below announces an end of life that was found, so "quiet" and "no release since" only restate the dates.

  • A cell reading not verified means the source named above did not state the line.

Groovy 6.0 and the projects above

Reading the "Groovy line" column as a whole gives a picture worth stating, again with the check date 2026-10-14:

  • Spock and the Groovy-Eclipse tooling publish artifacts for Groovy 6.0, and SDKMAN! and the Groovy Web Console offer it.

  • Gradle, Nextflow and JasperReports embed Groovy 4.0, Grails embeds 5.1, Micronaut Groovy declares 5.0, JMeter 5.6.3 bundles 3.0 and the Jenkins Pipeline plugin declares 2.4.

  • For the others the sources checked do not mention Groovy 6, which is why those cells say not verified or only give the line the project builds with.

A project that embeds an older line is not wrong: it chooses the line its own plugin API and compatibility promises depend on. What follows for you is that code written for this section’s Groovy 6.0 may use syntax or library methods that the embedded line lacks.

import groovy.ant.AntBuilder

new AntBuilder().echo('hello from Ant')

The GPars line, saved as gpars-hello.groovy (GPars is fetched from Maven Central by @Grab):

@Grab('org.codehaus.gpars:gpars:1.2.1')
import groovyx.gpars.GParsPool

GParsPool.withPool {
    final List result = [1, 2, 3, 4, 5].collectParallel { it * 2 }
    assert [2, 4, 6, 8, 10] == result
    println result
}
[2, 4, 6, 8, 10]

Where the book is outdated

Groovy in Action (first edition) was written for Groovy 1.0 (2007). Every project in the table has released versions that postdate it, and several (Spock, Geb, SDKMAN!, Micronaut, Nextflow) did not exist when it was written, so use the project pages above and not the book for anything about these tools.
