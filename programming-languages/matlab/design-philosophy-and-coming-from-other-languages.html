Design Philosophy and Coming from Other Languages

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Written against MATLAB R2026b. The short sessions below were run in GNU Octave 11.3.0 (MATLAB code that Octave also accepts) and their captured output is shown; MATLAB prints the same values with a different layout. Statements about MATLAB-only behaviour are checked against the R2026b documentation and labelled when they were not run.

This page is for readers who already program. It explains why MATLAB looks the way it does, then maps the idioms of Python with NumPy, R, Julia, Fortran and C onto it. If you have never programmed, start with Getting Started and come back later.

Everything is an array

MATLAB began as an interactive front end to the Fortran matrix libraries LINPACK and EISPACK, and its first version had a single data type, the matrix (Moler and Little, "A History of MATLAB"). That origin still shapes the language:

  • A scalar is a 1-by-1 array, a row vector is 1-by-n, a column vector is n-by-1, and a character string or a boolean is an array of characters or logicals.

  • There is no separate "list" or "vector" class, and a function written for a scalar almost always works for an array.

  • Binary operators work on whole arrays: A*B is the matrix product and A.*B multiplies element by element.

Newer data types (cell arrays, structures, tables, dictionary, classes) were added later and are still arrays at heart: a structure array has a size, and so does an object array.

The design decisions that matter

One-based indexing

The first element of v is v(1) and the last is v(end). Subscripts are written with parentheses, not square brackets, because indexing and calling a function look the same: f(3) is either one, and which one depends on whether f is a variable.

Column-major storage

Elements of a matrix are stored column by column, as in Fortran. Linear indexing with one subscript therefore walks down the first column, then the second, and so on. This is the single most important fact when you connect MATLAB with C (row-major) or NumPy (row-major by default).

v = [10 20 30 40];
v(1)
v(end)
M = [1 2 3; 4 5 6];
M(:)'
M(2, :)
M(5)

Octave 11.3.0 output:

ans = 10
ans = 40
ans =

   1   4   2   5   3   6

ans =

   4   5   6

ans = 3

M(:)' flattens the matrix into a column and transposes it back to a row, and the flattened order is 1 4 2 5 3 6, column by column. M(5) is therefore 3: the fifth element in storage order is the first element of the third column.

Source: MATLAB documentation: Array Indexing

Value semantics and copy-on-write

Assigning an array to another variable behaves as if it made an independent copy. Changing one never changes the other, and there are no references to numeric arrays that you can alias by accident. MATLAB makes this cheap by sharing the data until one of the two variables is modified (copy-on-write), so the copy happens only when it is needed. Handle classes, covered on Value and Handle Classes, are the deliberate exception.

a = [1 2 3];
b = a;
b(1) = 99;
a

Octave 11.3.0 output:

a =

   1   2   3

a is unchanged. The consequence for performance is that passing a large array to a function does not copy it unless the function modifies it.

Source: MATLAB documentation: Avoid Unnecessary Copies of Data

Dynamic typing

Variables have no declared type, and the same name can hold a number now and a string later. The default numeric type is double; integer, single-precision and logical types are opt-in. Function arguments are not typed either, although since R2019b an arguments block can validate and convert them (see Argument Validation).

Vectorization first

Idiomatic MATLAB expresses a computation on a whole array in one statement and lets the built-in library loop in compiled code. The heatflow Laplacian can be written with loops, with indexing or with implicit expansion; the second and third are shorter than the loop. The indexed form is also much faster than the loop, whereas the dense matrix form is slower than indexing in the Octave timings that Vectorization and Preallocation reports, so shorter is not always faster. Since the introduction of the JIT-accelerated execution engine, plain loops are no longer the disaster they were in the 1990s, but they remain the slower choice for array arithmetic.

The interpreter and its JIT execution engine

MATLAB code is compiled to an internal form when it is run and executed by an engine that includes just-in-time acceleration. You do not compile a MATLAB program ahead of time to run it, there is no separate build step for ordinary code, and a change to a function file takes effect the next time the function is called. The Code Analyzer (see Code Analyzer and Code Quality) takes the place of a compiler’s warnings.

Four differences cause most bugs:

  • Row-major against column-major. NumPy arrays are row-major by default, MATLAB arrays column-major. Flattening, reshaping and tofile give different orders.

  • Views against copies. A NumPy slice is usually a view of the original data; a MATLAB slice is a new array.

  • Inclusive ranges. 1:3 is [1 2 3], and the stop value is included.

  • Everything is at least two-dimensional. A MATLAB array always has at least two dimensions, so there is no 1-D array; a vector is a row or a column.

MATLAB calls Python directly (see Calling Python from MATLAB).

(Both results were produced in Octave 11.3.0 with int8(200) giving 127 and int32(7)/int32(2) giving 4; MATLAB documents the same saturation and rounding. See Numeric Types and Floating Point.

No +=: how MATLAB code is written instead

MATLAB has no compound assignment operators. The idioms are:

x = 5;
x = x + 1

Octave 11.3.0 output: x = 6. (Octave itself accepts +=; MATLAB does not, so code that uses it is not portable.)

Because the left side is an array, the same pattern covers accumulations: total = total + T(k). Growing an array in a loop, as in list(end+1) = value, works but reallocates each time and is flagged by the Code Analyzer; preallocate instead (see Vectorization and Preallocation).

Source: MATLAB documentation: MATLAB Operators and Special Characters

Three operators that surprise newcomers

  • end means the last index inside parentheses, and also closes blocks. A(end, 1) is the first element of the last row.

  • The quote ' is the conjugate transpose and .' the plain transpose. On complex data they differ.

  • The backslash \ solves linear systems and least-squares problems: x = A\b.

z = [1+2i 3-4i];
z'
z.'
A = magic(3);
A(2:end, 1)
col = [1; 2; 3]; row = [10 20 30 40];
col + row

Octave 11.3.0 output:

ans =

   1 - 2i
   3 + 4i

ans =

   1 + 2i
   3 - 4i

ans =

   3
   4

ans =

   11   21   31   41
   12   22   32   42
   13   23   33   43

z' conjugated and transposed, z.' only transposed. The last result is implicit expansion: adding a column to a row builds the whole table of sums, without repmat or the older bsxfun. It has worked since R2016b and is the subject of Implicit Expansion and Compatible Sizes.

Source: MATLAB documentation: Compatible Array Sizes for Basic Operations

Strengths and limits

Strengths

  • Dense numerical code is short and close to the mathematics.

  • Documentation, graphics and numerical libraries are integrated and consistent across releases, and backward compatibility is taken seriously.

  • The desktop supports exploration: a workspace to inspect, an editor with code analysis and a debugger.

Limits

  • Licensing. MATLAB is commercial software, and many capabilities that other ecosystems get from free libraries are separate paid toolboxes. This section documents base MATLAB only and lists the toolboxes on Toolboxes and Add-On Products.

  • General-purpose programming. The language is weaker than Python for text processing, web services and large software architectures, although classes, namespaces, a unit-testing framework and a package manager now exist.

  • Performance model. Fast code is vectorized code on dense arrays; algorithms that need millions of small irregular operations are better written in C++ and called through MEX.

  • Closed implementation. Behaviour is defined by the documentation and the product, not by a public specification.

GNU Octave in one line

GNU Octave is a free, open-source numerical language that is largely compatible with MATLAB, which is why the short sessions on these pages could be run in it; the differences are on GNU Octave Compatibility.

Where older books differ

Books written for the 2000s teach bsxfun and repmat for broadcasting (implicit expansion arrived in R2016b), character arrays as the only text type (string arrays arrived in R2016b), and numeric figure handles with set and get (graphics objects with dot notation appeared in R2014b, although set and get still work). The language described on this page is otherwise stable.
