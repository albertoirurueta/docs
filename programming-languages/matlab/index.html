MATLAB Reference

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

What MATLAB is

MATLAB, short for "matrix laboratory", is a matrix-oriented programming language and an interactive environment for numerical computing, visualization and programming. Cleve Moler created it in the late 1970s as an interactive front end to the Fortran libraries LINPACK and EISPACK, and Jack Little, Cleve Moler and Steve Bangert founded MathWorks in 1984 to commercialise it (Moler and Little, "A History of MATLAB", 2020). Its central object is the array: a scalar is a 1-by-1 array, and operators, functions and indexing are designed to work on whole arrays at once.

This section is a learning-oriented reference for the language and its basic usage, written against MATLAB R2026b. It covers base MATLAB only. The add-on products that MathWorks sells separately (the toolboxes, such as Statistics and Machine Learning, Deep Learning, Signal Processing or Image Processing) and Simulink are not documented here; Toolboxes and Add-On Products lists them with a short description and a link to each official page. Every example uses base MATLAB only. The maths, graphics and data pages document what a learner of the language needs to use base MATLAB; they are not a numerical-methods course.

Version baseline

MathWorks ships two releases a year: an "a" release in spring (March to May) and a "b" release in September. R2026b was announced on 2026-09-28 and is the current release; the release notes at mathworks.com/help/matlab/release-notes.html had no R2027a entry when this section was checked on 2026-10-22. If you read this after R2027a is out, the language described here is still valid, but newer additions are not marked; each page says in which release a feature appeared so that you can tell whether your release has it.

What R2026b changed in the platform, as it affects this section:

  • MATLAB no longer installs Java on Windows and Linux; you add OpenJDK yourself.

  • Live scripts save as plain-text .m files by default.

  • .mltbx files are now called package files, File Exchange is a default package repository, and projects use a matlab.toml definition file.

  • New markdowndisp function and ANSI styling in the Command Window.

How the pages were checked:

  • Every page names the release it was written against. MATLAB R2026b is not installed on the machine that produced these pages and cannot be installed or signed into by the author, so the examples were handled in two ways. Code that GNU Octave also accepts was run in Octave 11.3.0 in a throwaway container and its captured output is shown, labelled "Octave 11.3.0 output"; MATLAB’s own display differs in layout (for example size headers such as 3×1), and where the difference matters the page says so. Everything Octave cannot run (arguments blocks, classdef features, dictionary, tables and timetables, buildtool, matlab.unittest, App Designer, live scripts, MEX, the Python interfaces, projects and the package manager, and anything new in R2026b) was checked line by line against the R2026b documentation and is labelled "not run here" or has its output marked as illustrative. No output is shown as captured when it was not.

  • Each example is followed by a Source: link to the official documentation page it derives from, and every source is listed in the Bibliography.

  • The code follows the current idioms and the official MATLAB Coding Guidelines: string arrays and double-quoted literals, arguments blocks, Name=Value, implicit expansion, dictionary, readtable, exportgraphics. Where older material teaches something else (bsxfun, strmatch, datenum, nargchk, GUIDE, containers.Map as the default dictionary), the page explains the difference in prose. The books used as a checklist are described under How the books were used.

  • Source code blocks use [source,matlab]. The documentation site’s code highlighter has no MATLAB grammar yet, so MATLAB code is shown without colours.

Package and toolbox

Two words changed meaning, and old material uses both in the old way.

Word Meaning before Meaning now

package

Until R2023b: a +folder that groups functions and classes under a prefix, for example +heatflow. Renamed namespace in R2024a.

Since R2024b: a MATLAB Package Manager (MPM) package, installed with mpm install or from File Exchange. Since R2026b it also covers what used to be called a toolbox (a shareable bundle of user code).

toolbox

A shareable bundle of user code in a .mltbx file; also a MathWorks add-on product such as the Statistics and Machine Learning Toolbox.

Bundles are now packages (.mltbx files are "package files"). "Toolbox" still names the add-on products, which this section does not document.

The pages define each term where they use it. Namespaces and Class Folders covers the +folder feature, Packages and the MATLAB Package Manager covers the package manager with a timeline, and Toolboxes and Add-On Products covers the products.

Running example

The examples across the section share one small, original domain: heatflow, two-dimensional heat diffusion on a rectangular plate. It is the scenario of the Fortran Reference (#277), seen here from MATLAB, so that readers can compare the two languages on the same problem. It is a MATLAB project (heatflow/, defined by matlab.toml since R2026b) with these parts, which are introduced one at a time on the pages where their concept first appears:

  • A +heatflow namespace holding:

    • heatflow.Plate, a value class with the grid sizes, the spacing, the diffusivity, a temperature matrix T and validated properties;

    • heatflow.BoundaryKind, an enumeration with the members Dirichlet, Neumann and Periodic;

    • heatflow.Simulation, a handle class that steps the temperature field and fires a StepCompleted event;

    • functions such as heatflow.laplacian, written three ways (a loop, vectorized with indexing, and with implicit expansion);

    • heatflow.assembleSystem, which builds the sparse five-point system whose steady state is solved with the backslash operator.

  • An explicit time-stepping script, with the stability limit dt <= dx^2/(4*alpha), written as a script with %% sections and as a live script.

  • data/sensors.csv, a thermocouple log with timestamps, sensor IDs and deliberate gaps, read into a timetable with datetime, categorical sensor IDs and missing values; data/plate.json, a configuration file read with readstruct or jsondecode; and a dictionary that maps sensor IDs to plate coordinates.

  • Figures of the field (surf and contour), of the sensors (line plots) and of the readings (a histogram).

  • Tests (script, function and class-based), a buildfile.m, an MPM mpackage.json, a small App Designer viewer, a Python interop example that passes the field to NumPy, and a C++ MEX stencil kernel.

The pages build on each other, and the cheat sheet summarises the whole section. A page whose concept fits the scenario poorly uses a small standalone example instead; regular expressions on sensor labels are one case. The smallest taste of it is on Getting Started, where a three-point steady state is solved with the backslash operator.
