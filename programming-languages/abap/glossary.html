ABAP Glossary

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This glossary explains, in plain words, the ABAP and AS ABAP terms used across the ABAP section of this documentation, and links each one to the page that teaches it. ABAP is the programming language of SAP systems, and AS ABAP is the application server that runs it. Use the glossary when a page uses a word you have not met; every entry ends with the page where the idea is explained in full. Terms are listed alphabetically, and a term the pages write in several ways shows each spelling.

A

ABAP annotation

An annotation, a piece of metadata attached to a CDS entity, that the ABAP runtime itself reads, for example when the entity is activated. Other annotations are only read by tools such as UI frameworks. See CDS Annotations and Metadata Extensions.

ABAP Channels

The common name of AMC and APC. They let programs communicate through messages, between application server instances and with the Internet, instead of polling for changes. See ABAP Channels: APC and AMC.

ABAP Cloud

The cloud-ready way of writing ABAP: you use the restricted language version for cloud development and call only released APIs, so that your code survives upgrades of the SAP system. Obsolete statements are mostly forbidden in it. See Language Versions and Released APIs.

ABAP Debugger

The tool that stops a running program at a point you choose and lets you look at its variables and at the chain of calls that led there. See Debugging.

ABAP Development Tools
ABAP Development Tools (ADT)

The plug-ins from SAP for the Eclipse programming environment, with which you create and change ABAP objects on an SAP system. It is the environment in which modern ABAP is written. See ABAP Development Tools (ADT).

ABAP Dictionary

The central, transportable store of type definitions: tables, data elements, domains, structures, views and similar objects. Programs and databases both use these definitions, so a type is described once and reused. Classic systems maintain it with transaction SE11. See Database Tables and Structures.

ABAP for Cloud Development

A restricted ABAP language version. It allows only a subset of statements that suits cloud systems, and it lets code call released objects only. See Language Versions and Released APIs.

ABAP for Key Users

The smallest ABAP language version, meant for small extensions that business users (key users) make in dedicated tools instead of in a full development environment. See Language Versions and Released APIs.

ABAP Formatter

The editor function that re-indents code and changes the case of keywords according to the team’s settings, so that all code looks alike. In SAP GUI the same function is called Pretty Printer. See Coding Standards and Clean ABAP.

ABAP language version

A setting on a development object that fixes which statements the object may use and which other objects it may call. It is how the same system can hold both classic and cloud-ready code. See Language Versions and Released APIs.

ABAP memory

A memory area that all programs of one call chain in one main session can read and write, and that nobody else can reach. Programs use it to pass data to the programs they call. See Memory Organization and Sessions.

ABAP Profiler

The ADT tool that records how long each part of a running ABAP program takes, so that you can see where the run time goes before you try to speed it up. It succeeds the classic transaction SAT. See Performance, SQL Trace and Profiling.

ABAP Programming Model for SAP Fiori

The programming model of the 7.5x era for building transactional Fiori apps, which combined CDS views, BOPF and SAP Gateway. RAP is its successor. See BOPF and the ABAP Programming Model for SAP Fiori.

ABAP project

An Eclipse project in ADT that manages the connection to one ABAP back-end system. You open and edit that system’s objects through it. See ABAP Development Tools (ADT).

ABAP release

The number, such as 8.16 or 9.20, that names the version of the ABAP language and runtime delivered with a SAP product. It tells you which statements and features you can use. See What’s New in ABAP.

ABAP SQL

The SQL of the ABAP language: the statements, written inside ABAP programs and checked by the ABAP compiler, that read and change database tables. The runtime passes them on to the database. See ABAP SQL: Reading Data.

ABAP Test Cockpit
ABAP Test Cockpit (ATC)

The SAP tool that runs groups of quality and compatibility checks over development objects and lists the findings with a priority. See Clean Core and Cloud Readiness.

ABAP Test Cockpit (ATC)

SAP’s tool for static analysis of ABAP code: it examines development objects without running them and reports findings. It can also run ABAP Unit tests. See ABAP Test Cockpit (ATC).

ABAP Unit

The built-in ABAP framework that finds, runs and evaluates the automatic tests you write as test classes. See ABAP Unit and Test Doubles.

ABAP Workbench

The set of classic SAP GUI tools for creating and changing ABAP development objects, such as SE80, SE38 and SE11. See Classic Tools: SE80, SE38, SE11, SE37 and SE16.

abapGit

A Git client written in ABAP that exports development objects as plain text files and imports them again, with one file per object. It lets ABAP sources live in an ordinary Git repository. See Packages, Transports, gCTS and abapGit.

abaplint

A free checker for ABAP source code that reports style and correctness findings, each named by a rule. See Hands-on Lab.

Abstract class

A class that cannot be instantiated itself and may leave methods without an implementation, which its subclasses must supply. It serves as a common base for related classes. See Interfaces, Inheritance and Polymorphism.

Access rule

One statement inside a CDS role that names a CDS entity and says which rows a user may read, either by an access condition or by full access. See CDS Access Control (DCL).

Action

A named operation on a business object that is more than create, update or delete, such as submitting a claim. See Behavior Definitions and Implementations.

Activation

The step that turns a saved but inactive version of an object into the version that the system actually runs. See ABAP Development Tools (ADT).

ADBC (ABAP Database Connectivity)

The ABAP Objects classes and interfaces with which a program sends Native SQL, that is database-specific SQL, to the database and reads the result. See Native SQL, ADBC and AMDP.

Additional save

Extra code of your own that runs in the saver class of a managed business object while the framework still does the normal saving. A typical use is writing change documents. See Managed, Unmanaged and Unmanaged Save.

Adobe forms

The third generation of SAP form tools. The layout is designed in Adobe LiveCycle Designer, and Adobe Document Services renders the finished form as PDF. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

Aggregate expression

A function such as SUM or COUNT that turns many rows into a single value. Using it in the query lets the database do the adding up. See ABAP for SAP HANA and Code Pushdown.

Alias

A short second name for a component of an interface that a class implements, so that you can use the component without the long interface prefix. See Interfaces, Inheritance and Polymorphism.

ALV

The SAP List Viewer, a standard tool that shows an internal table as an interactive table with sorting, filtering, totals and export. See ALV (SAP List Viewer).

ALV object model

The set of SALV classes, with CL_SALV_TABLE and its sub-objects, that SAP recommends for new ALV output. See ALV (SAP List Viewer).

AMC (ABAP Messaging Channel)

A named channel, stored as a repository object, through which ABAP programs send and receive messages. See ABAP Channels: APC and AMC.

AMDP
AMDP (ABAP Managed Database Procedures)

Database code written in SQLScript but kept as a method of an ABAP class, so that ABAP manages its creation and transport. The method runs inside the database. See Native SQL, ADBC and AMDP.

Analytical query

A CDS-based query with measures (numbers to add up) and dimensions (ways to group them) that Fiori reports read through an OData service. See SAP Query and QuickViewer.

Annotation layer

The level of a metadata extension (core, localization, industry, partner or customer) that decides which extension wins when several set the same annotation. See CDS Annotations and Metadata Extensions.

Anonymous data object

A data object created while the program runs that has no name, only a reference that points to it. You create one with CREATE DATA or NEW. See RTTI, RTTC and Dynamic Programming.

APC (ABAP Push Channel)

A repository object that lets an ABAP system act as a WebSocket or TCP socket server or client, so that it can push messages to a connected partner. See ABAP Channels: APC and AMC.

APC handler class

The class that the system creates to react to the events of one push channel connection, such as an incoming message. See ABAP Channels: APC and AMC.

Append structure

An extra set of fields that adds to an existing table or structure without changing the original object. A customer can thus extend an SAP table without modifying it. See Database Tables and Structures.

Application destination

The destination that the system creates from a communication target when a communication arrangement is saved. Outbound calls use it to find the remote system. See HTTP Clients, JSON and XML Transformations.

Application event

A control event whose handler is called later, when the program calls the dispatch method of the Control Framework in a PAI module, instead of immediately. See Control Framework and GUI Controls.

Application function library (AFL)

The mechanism through which SAP HANA offers compiled functions, such as PAL, to SQLScript. See SAP HANA Search and Predictive Functions from ABAP.

Application job

The ABAP Cloud form of a scheduled job, created from a job template in the Application Jobs app or through an API. See Background Jobs and Parallel Processing.

Application Link Enabling (ALE)

The technology that distributes business data between loosely linked systems, mostly by sending IDocs. See RFC, BAPIs and IDocs.

Application log

A stored list of messages that a program writes and that can be read later, for example after a background job has finished. See Messages.

Application server

The computer that runs your ABAP program. It sits between the user’s screen and the database, which runs on a separate computer, and talks to both. See Getting Started.

asJSON

The fixed JSON layout that the identity transformation produces and expects when ABAP data is converted to JSON and back. See HTTP Clients, JSON and XML Transformations.

Assertion

A check inside a test, written as a call of the class CL_ABAP_UNIT_ASSERT, that makes the test fail when the result is not the expected one. See ABAP Unit and Test Doubles.

Asynchronous RFC (aRFC)

A remote function call in which the caller continues at once without waiting and collects the result later in a callback routine. See RFC, BAPIs and IDocs.

ATC exemption

An approved request that hides one ATC finding which cannot be fixed now, so that it no longer blocks the check. See ABAP Test Cockpit (ATC).

Attribute

A variable, constant or type that belongs to a class or to its objects. See Classes and Objects.

Authorization

An entry in a user’s permissions that gives complete or generic values for the fields of one authorization object. See Authorization Checks.

Authorization check

The comparison of the values a program needs with the values in the user’s authorizations. It is either explicit, with the statement AUTHORITY-CHECK, or implicit. See Authorization Checks.

Authorization field

The smallest unit of an authorization object. It stands either for data, such as a key field of a table, or for an activity such as display or change. See Authorization Checks.

Authorization object

A named set of up to ten authorization fields that the system compares with the values assigned to a user before it allows an action. Checks and permissions always refer to one such object. See Authorization Checks.

Automation queue

The buffer in which the Control Framework collects method calls for GUI controls and sends them to the user’s PC in one go. See Control Framework and GUI Controls.

B

Background job

A unit of work, made of one or more job steps, that the system runs without a user dialog. See Background Jobs and Parallel Processing.

Background processing framework

The ABAP Cloud framework that runs methods of your classes asynchronously and reliably. See Background Jobs and Parallel Processing.

Background RFC (bgRFC)

A remote call that is stored and sent after COMMIT WORK. It is the modern successor of tRFC and qRFC. See RFC, BAPIs and IDocs.

Background work process

A work process reserved for background jobs. Unlike a dialog work process it is not subject to the dialog time limit (the profile parameter rdisp/max_wprun_time). See Background Jobs and Parallel Processing.

BAdI

Business Add-In: an object-oriented enhancement option made of an interface, filters and settings. The standard code calls it, and your own ABAP class plugs in to add behavior. See Enhancements and BAdIs.

BAPI

A standardized, remote-enabled function module that is a method of a business object, so that other systems can call it in a defined way. See RFC, BAPIs and IDocs.

Basic list

The first list of a program, with list level 0. It is what the report writes before the user does anything. See Classic Lists and Interactive Reports.

Batch input

A technique that feeds data automatically into the screens of transactions, controlled by batch input sessions or batch input tables. See Batch Input, Direct Input and Data Migration.

Batch input session

A stored series of transaction calls with their input data, managed in transaction SM35. See Batch Input, Direct Input and Data Migration.

Batch input table

An internal table whose line type is BDCDATA and that holds the screens and field values for one transaction. See Batch Input, Direct Input and Data Migration.

BDCDATA

The dictionary structure of one line of a batch input table, with the components PROGRAM, DYNPRO, DYNBEGIN, FNAM and FVAL. See Batch Input, Direct Input and Data Migration.

Behavior definition

A repository object, written in the RAP Behavior Definition Language, that describes the operations and characteristics of a business object. See Behavior Definitions and Implementations.

Behavior pool

The global ABAP class named in the behavior definition. Its local classes hold the handler and saver code of the business object. See Managed, Unmanaged and Unmanaged Save.

BOPF

The Business Object Processing Framework: a runtime that holds a business object as a tree of nodes together with its business logic. See BOPF and the ABAP Programming Model for SAP Fiori.

BOPF-based RAP business object

The result of SAP’s migration tool: a RAP business object whose runtime is still provided by BOPF. See BOPF and the ABAP Programming Model for SAP Fiori.

Branch

One of several alternative blocks of statements of which only one runs, chosen by a condition. See Control Flow.

Breakpoint

A marker that makes the debugger stop when execution reaches a given line, statement, message or exception. See Debugging.

Built-in function

A function that is part of the language itself and is called inside an expression, for example abs( x ) for the absolute value. See Dates, Times and Built-in Functions.

Bulk access

One statement that handles many rows at once, for example from an internal table, instead of one statement per row. See ABAP SQL: Writing Data.

Bundling technique

A way to collect change requests in an SAP LUW and carry them out together later, instead of executing each one at once. See SAP LUW, Update Tasks and Commit.

Business key

The key attributes of a persistent class that come from the primary key of its table and are visible to the program. See Object Services: Persistence and Transaction Services.

Business Object Repository (BOR)

The catalog of SAP business object types and their methods, in which BAPIs are defined. See RFC, BAPIs and IDocs.

C

Calculation type

The data type in which ABAP carries out an arithmetic expression, chosen from the types of its operands. See Expressions, Operators and Assignments.

Call sequence

The chain of programs in which each one has called the next and is waiting for it, with the newest at the end. The programs of one call sequence share one ABAP memory. See Calling Programs, Transactions and Memory.

Cardinality

How many rows of the target can match one row of the source of an association, for example many to one. See CDS Associations and Compositions.

Cardinality

How many rows on one side of a foreign key can belong to one row on the other side. See Foreign Keys, Check Tables and Indexes.

Catchable exception

An exception that a program can handle with TRY and CATCH. The opposite is an uncatchable one, which ends the program. See Class-Based Exceptions.

CDS abstract entity

A CDS entity that only describes a structure and has neither data nor a database object. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS access control

The rule that restricts which rows of a CDS entity a user gets when ABAP SQL reads it. It is written in CDS roles. See CDS Access Control (DCL).

CDS annotation

A line that starts with the at sign and adds metadata to a CDS entity or to one of its elements. See CDS Annotations and Metadata Extensions.

CDS aspect

A named set of elements that several CDS view entities can reuse. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS association

A named, reusable link from one CDS entity to another, declared once with a join condition. It is evaluated only when it is used. See CDS Associations and Compositions.

CDS composition

A pair of to-child and to-parent associations that makes a child entity depend on its parent for its existence. See CDS Associations and Compositions.

CDS custom entity

A CDS entity that only describes a result. An ABAP class provides the rows when a framework asks for them. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS entity

The common name for an object defined in ABAP CDS, the data definition language of ABAP, such as a view entity, that you can read with ABAP SQL. See CDS Annotations and Metadata Extensions.

CDS external entity

A CDS entity that reads data from a table in another database. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS hierarchy

A CDS entity that turns rows with a parent column into a tree and adds columns such as the level of each node. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS role

The object created with DEFINE ROLE. It holds one or more access rules and applies to every user. See CDS Access Control (DCL).

CDS table function

A CDS entity whose rows are produced by a database function written in SQLScript inside an ABAP class (an AMDP method), so that ABAP SQL and other CDS views can read it like a view. See Table Functions, Hierarchies, Custom Entities and Aspects.

CDS view entity

A view defined in ABAP CDS that selects data from one or more data sources and can be read like a table. It is the current kind of CDS view and replaces classic views and DDIC-based CDS views. See CDS View Entities.

Change and Transport System (CTS)

All the tools of an ABAP system that manage development objects and transport them between systems. See Packages, Transports, gCTS and abapGit.

Check indicator

A setting that decides whether a check on an authorization object really takes place in the current context. See Authorization Checks.

Check table

The table that holds the allowed values of a foreign key, because its primary key is the foreign key. See Foreign Keys, Check Tables and Indexes.

Check variant

A named set of checks that an ATC run executes. See ABAP Test Cockpit (ATC).

Class

The blueprint that defines the attributes and methods of a kind of object. Objects are created from it and bundle data with the methods that work on it. See Classes and Objects.

Class agent

The generated class, also called class actor, that creates, loads and deletes the objects of one persistent class. See Object Services: Persistence and Transaction Services.

Class pool

The program that the system generates for a global class. See Program Types and Structure.

Classic API

An older SAP object, such as a function module or a class of classic ABAP, that SAP has nominated as the next-best option where no released API exists. See Clean Core and Cloud Readiness.

Classic exception

A name in the interface of a function module that the code raises with RAISE and that the caller tests through sy-subrc. It is the opposite of a class-based exception. See Function Modules and Function Groups.

Classic list

The page-oriented text output that WRITE creates and that the user sees on a special list screen after the report has run. See Classic Lists and Interactive Reports.

Clean ABAP

SAP’s public style guide that applies the ideas of the book Clean Code to the ABAP language. See Coding Standards and Clean ABAP.

Clean core

Keeping the SAP standard free of changes and extending it only through released or officially classified interfaces, so that upgrades stay simple. See Clean Core and Cloud Readiness.

Clean core level

One of the four classes A, B, C and D that SAP uses to rate how upgrade-stable a custom object is. See Clean Core and Cloud Readiness.

Client

A self-contained unit of business data inside one SAP system. ABAP SQL reads only the client you are logged on to. See ABAP SQL: Reading Data.

Client field

The first key column of a client-dependent table, which separates the data of the different clients of one system. See Database Tables and Structures.

Client handling

The automatic restriction of a client-dependent view to the rows of the client the program runs in. See CDS View Entities.

Client safety

The guarantee that a statement or an AMDP method reads the data of the current client only. See Native SQL, ADBC and AMDP.

Cloudification Repository

SAP’s published list that says, for each SAP object, whether it is released, classic, deprecated or not recommended, and which object replaces it. See Clean Core and Cloud Readiness.

Code Inspector

The older SAP check tool, started with transaction SCI, whose name still appears inside ATC settings. See ABAP Test Cockpit (ATC).

Code pushdown

Moving a calculation from the ABAP program to the database, so that only the result travels back. It is also called code-to-data. See ABAP for SAP HANA and Code Pushdown.

Collaborative draft

A draft, in the RAP draft concept, that several invited users edit together instead of one person alone. See Draft Handling.

Commercial rounding

The everyday way of rounding: when a value lies exactly halfway between two possible results, it goes to the one farther from zero, so 2.5 becomes 3 and -2.5 becomes -3. See Expressions, Operators and Assignments.

Common table expression

A named intermediate result that you define at the start of an ABAP SQL statement with WITH and then read like a table. It exists only while that one statement runs. See ABAP SQL: Joins, CTEs, Window Functions and Path Expressions.

Communication arrangement

The runtime setup, made by an administrator, that ties a communication scenario to a particular communication system, including its address and the credentials to use. See HTTP Clients, JSON and XML Transformations.

Communication scenario

A development object that lists the outbound and inbound services a piece of integration uses, so that an administrator can later connect it to a real system. See HTTP Clients, JSON and XML Transformations.

Communication target

A development object that generates a class your code uses to get the right destination for an outbound call, so that no address is written in the program. See HTTP Clients, JSON and XML Transformations.

Constructor

A special method that prepares an object, or the class itself, when it is created or first used. You use it to give the new object its starting values. See Classes and Objects.

Constructor expression

An expression that starts with an operator such as VALUE, COND or NEW, ends with a closing parenthesis and builds a value at the place where it is needed. See Constructor Expressions.

Consumer proxy

A generated class that hides the SOAP message of a web service, so that calling the service looks like calling an ordinary method. See HTTP Clients, JSON and XML Transformations.

Container control

A GUI control whose job is to hold other controls and give them an area on the screen, for example the custom container. See Control Framework and GUI Controls.

Content ID

The temporary name %cid that you give a new instance inside one EML request, so that later lines of the same request can refer to it before it has a real key. See Entity Manipulation Language (EML).

Control Framework

The set of ABAP classes and front-end services that create GUI controls on the user’s PC, call their methods and pass their events back to your program. See Control Framework and GUI Controls.

Control level

A point in a sorted loop over a table where the value of a leading column changes. The older statements AT NEW and AT END OF react to these points. See Looping, Grouping and Control Levels.

Controlled SAP LUW

A checking mechanism that detects statements and calls that break the rules of the SAP LUW, for example a database change made outside the intended update step. See SAP LUW, Update Tasks and Commit.

Conversion exit

A pair of routines attached to a data element or domain that translates a value between the form in which it is stored and the form in which it is shown, for example leading zeros that are hidden on screen. See Domains and Data Elements.

Conversion rule

The rule that decides how a value of one data type is changed into another when it is assigned, for example text into a number. See Expressions, Operators and Assignments.

Core data services (CDS)

A draft that only the user who created it may change, activate or discard. See Draft Handling.

Executable program

A program that a user or a background job can start directly, usually to read data and show a list. See Program Types and Structure.

Exposure

Listing an association in the select list of a CDS entity so that other entities and ABAP SQL can use it. See CDS Associations and Compositions.

Factory method

A static method whose job is to create and return an object, so that the caller does not need to know which class is actually built. See Design Patterns in ABAP.

Field label

The short, medium, long and heading texts of a data element that screens use as a caption or column title. See Domains and Data Elements.

File interface

The ABAP statements for files on the application server: OPEN DATASET, READ DATASET, TRANSFER, CLOSE DATASET and DELETE DATASET. See Files: Application Server and Front End.

The list of single values or intervals that a domain names as the allowed ones, each with a short text. See Domains and Data Elements.

The starting situation of a test, prepared by the special methods setup and class_setup and cleaned up by teardown and class_teardown. See ABAP Unit and Test Doubles.

Flow logic

The script of a dynpro that calls dialog modules at the events PBO and PAI. See Dynpros, Module Pools and Transactions.

One or more fields of a table whose values must match the primary key of another table. See Foreign Keys, Check Tables and Indexes.

The table that contains the foreign key fields and points at the check table. See Foreign Keys, Check Tables and Indexes.

Form

A template for a printed or PDF document that mixes fixed text with fields filled in at run time. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

A procedure stored in a function group that any program can call with CALL FUNCTION. See Function Modules and Function Groups.

A search that also returns rows whose text is close to the search term, for example because of a typing error. See SAP HANA Search and Predictive Functions from ABAP.

gCTS

The Git-enabled Change and Transport System, which keeps transported objects as files in a Git repository. See Packages, Transports, gCTS and abapGit.

A check that depends only on the user and the operation, not on a particular claim. See RAP Authorization, Locking and Concurrency.

The value, or the set of values, that makes rows belong to the same group. See Looping, Grouping and Control Levels.

GUI control

A user interface element that runs in SAP GUI on the user’s PC and is managed by the Control Framework, for example the ALV grid. See Control Framework and GUI Controls.

The menu bar, toolbars and function keys of a screen or list, which decide which function codes the user can trigger. See Dynpros, Module Pools and Transactions.

Handler class

A local class that inherits from CL_ABAP_BEHAVIOR_HANDLER and implements operations, determinations, validations and checks during the interaction phase and the save sequence. See Behavior Definitions and Implementations.

A table kind whose rows are found through a calculated address, so a lookup by its unique key takes about the same time however many rows there are. See Table Expressions and Secondary Keys.

The object that sends an HTTP request to another system and returns its response. See HTTP Clients, JSON and XML Transformations.

A habit of putting the kind of a variable into its name, such as lv_ for a local variable or it_ for an importing table. See Coding Standards and Clean ABAP.

Identity transformation

The predefined transformation ID that converts ABAP data to XML or JSON and back without any rules written by you. See HTTP Clients, JSON and XML Transformations.

An intermediate document, the common exchange format between systems, made of a control record, data records and status records. See RFC, BAPIs and IDocs.

A piece of source text that cannot run alone and is pasted into other programs. See Program Types and Structure.

A view of one or more data sources, prepared by an administrator, from which queries take their fields. See SAP Query and QuickViewer.

Deriving a subclass from a superclass so that the subclass has all the visible components of the superclass and can add or redefine its own. See Interfaces, Inheritance and Polymorphism.

The value a variable holds before your program puts anything into it. For a number it is zero, for text it is blanks, and every data type has its own initial value. See Expressions, Operators and Assignments.

Handing the code you want to test a stand-in object instead of the real component it normally uses. With the stand-in in place, the test does not touch a database or another system. See ABAP Unit and Test Doubles.

Creating a variable at the exact spot where it first receives a value, instead of in a separate declaration earlier. ABAP works out the type from the value, so you do not write it yourself. See Data Types and Data Objects.

A way to show a database table in an ALV list without first reading all rows into an internal table. Sorting, filtering and paging then happen in the database, so large tables stay fast. See ALV (SAP List Viewer).

The first part of a RAP transaction, in which requests change data in the transactional buffer in memory. Nothing is written to the database yet; that happens later in the save phase. See RAP Overview.

A named list of components, mostly methods, that a class can promise to provide. Callers rely on the list and not on one particular class, and an interface has no instances of its own. See Interfaces, Inheritance and Polymorphism.

A variable typed as a reference to an interface, written with TYPE REF TO. It can point to an object of any class that implements that interface, and through it you reach only the interface components. See Interfaces, Inheritance and Polymorphism.

The memory area created for one program call inside a window of a user session. It holds the data of the programs loaded into it and disappears when the call ends. See Memory Organization and Sessions.

Internal table

A list of rows of the same shape that lives only in the memory of the running program, while it runs. It can hold any number of rows and is the everyday way to work with sets of data in ABAP. See Internal Tables.

The FOR part of a constructor expression, which repeats once for each row of a table or each value of a counter. It builds a new table or value from the repeated results. See Constructor Expressions.

One unit of work inside a background job: a program, usually with a variant, or an external command. A job runs its steps one after the other. See Background Jobs and Parallel Processing.

Legacy System Migration Workbench (LSMW)

List cursor

The position in a list at which the next output will appear. The system fields sy-linno and sy-colno hold its line and column. See Classic Lists and Interactive Reports.

List event

An event that occurs while a classic list is built or after the user acts on a displayed list. Examples are TOP-OF-PAGE for a page header and AT LINE-SELECTION for a double click on a line. See Classic Lists and Interactive Reports.

The addition IN LOCAL MODE to an EML statement, which a business object uses on itself to skip feature control and authorization checks. It is meant for the object’s own code, not for outside callers. See Entity Manipulation Language (EML).

In a RAP business object, the entity whose instance is locked whenever any instance of a lock-dependent entity below it is locked. It is always a root, so one lock protects the whole tree of related records. See RAP Authorization, Locking and Concurrency.

Lock mode

The kind of lock that is requested, such as shared or exclusive, which decides what other lock requests are accepted while it exists. The page lists the modes S, E, X and O. See Lock Objects and the SAP Lock Concept.

Lock object

A repository object in the ABAP Dictionary that says which tables and which key fields a lock covers. Generating it creates the function modules a program calls to set and release the lock. See Lock Objects and the SAP Lock Concept.

Lock table

The table in the memory of the enqueue server that holds one entry for each lock currently set in the system. A new lock request is checked against it. See Lock Objects and the SAP Lock Concept.

Logical expression

A condition made of comparisons joined with AND, OR and NOT, which is either true or false. Statements such as IF and WHILE use it to decide what happens next. See Control Flow.

Logical file name

A name that does not depend on the operating system, which settings in the system link to a real path. The program uses the logical name and never contains the path, so it runs unchanged on different servers. See Files: Application Server and Front End.

Logon language

The language a user picks when logging on to the system. It decides which translated copy of a text, such as a text element or message, the program shows. See Text Elements and Translation.

Loop

A block of statements that is run again and again until a condition or a statement ends it. In ABAP it is written with statements such as DO, WHILE and LOOP AT. See Control Flow.

M

Macro

A named piece of source text, defined between DEFINE and END-OF-DEFINITION, that the compiler pastes in wherever the name is used. Because it is only text substitution, newer code prefers methods. See Modularization Overview.

Main session

One window of a user’s logon, also called an ABAP session in the Keyword Documentation. Each main session has its own stack of program calls and its own memory. See Memory Organization and Sessions.

Maintenance view

A classic Dictionary view that lets a user maintain the data of several linked tables as if it were one object. It is typically used for customizing tables. See Dictionary Views and Search Helps.

Managed business object

A RAP business object whose standard behavior, such as create, update and delete, is supplied by the RAP framework. The developer adds only the rules and extra actions. See RAP Overview.

Managed RAP business object

A RAP business object whose transactional buffer and standard operations (create, update, delete) are provided by the framework. You describe the behavior and RAP does the standard work, including saving to the database. See Managed, Unmanaged and Unmanaged Save.

Matchcode object

The older predecessor of the search help, which offered input help through a view of one or more tables. New developments use search helps instead. See Dictionary Views and Search Helps.

Message class

A named collection of numbered message texts kept in the system, not inside the program. Programs refer to a text by class and number, which lets one text be shared and translated. See Messages.

Message type

A one-letter code that decides how a message is shown and whether the program carries on. The page describes the types A, E, I, S, W and X. See Messages.

A separate piece of CDS source code that adds annotations to an existing CDS entity without changing the entity itself. It is commonly used to describe how the fields appear in a user interface. See CDS Annotations and Metadata Extensions.

Method

A named block of code that belongs to a class, with its own parameters and local data. You call it to make an object, or the class, do something and possibly return a result. See Classes and Objects.

Migration object

The description of how one kind of business data, such as a customer, is migrated. It names the source and target structures, the field mappings and the conversion rules. See Batch Input, Direct Input and Data Migration.

An overview of all modifications and enhancements in a system, opened with transaction SE95 or from within the adjustment transactions. It helps you find what was changed. See Modifications, Modification Assistant and SPAU/SPDD.

A short label of up to three characters that you give to screen elements so that a program can change several of them together. For example, it can hide all elements of one group at once. See Selection Screens and Variants.

Module pool

A program of the type module pool, which holds the dialog modules and the screens (dynpros) of a dialog application. It cannot run on its own and is started with a transaction code. See Dynpros, Module Pools and Transactions.

A draft that has no active instance yet, because the record is still being created. Saving it later turns it into the first active instance. See Draft Handling.

Object

One instance built from a class, with its own copy of the instance attributes. Many objects can be created from the same class, each holding different data. See Classes and Objects.

Offset and length

A way to address part of a text by its start position and the number of characters to take. It is written by adding the position and length after the variable name. See Strings, String Templates and Regular Expressions.

OK field

The field of a screen (dynpro) that receives the function code of the user’s action, such as a pressed button or menu entry. The program reads it to decide what to do. See Dynpros, Module Pools and Transactions.

A central store of reusable texts that many objects can share and translate once. It is opened with transaction SOTR_EDIT. See Text Elements and Translation.

Operand type

The data type that a constructor expression has to produce. It is written after the operator or taken from the place where the expression is used. See Constructor Expressions.

A way to handle several users changing the same data without blocking anyone. A change is accepted only if the data is still in the state the client saw, which an ETag value proves. See RAP Authorization, Locking and Concurrency.

Outer join

A join that keeps the rows of one side even when nothing on the other side matches them. The columns of the missing side are then left empty. See ABAP SQL: Joins, CTEs, Window Functions and Path Expressions.

Output management

The S/4HANA framework that decides which document is produced, through which channel (print, email) and with which form. It replaces the older output control based on the NAST table. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

P

Package

A container that groups development objects that belong together. It is also the unit that connects each object to the transport system and to the rules about who may use what. See Packages, Transports, gCTS and abapGit.

The list of objects that a package offers for use by other packages under the package concept. Objects not in the interface are meant to stay internal. See Packages, Transports, gCTS and abapGit.

The event of a screen that runs after the user acts on it, when the program reads and checks what was entered. It is the counterpart of PBO, which runs before the screen is shown. See Dynpros, Module Pools and Transactions.

The list of parameters and exceptions through which a function module talks to its caller. Each parameter has a name and a type, and says whether it goes in, comes out or both. See Function Modules and Function Groups.

The settings that say which messages a communication partner may exchange with the system, through which port, and how incoming messages are processed. IDoc exchange needs one for each partner. See RFC, BAPIs and IDocs.

The event of a screen that runs before the screen is shown, used to prepare what is displayed, such as filling fields or hiding elements. The counterpart is PAI. See Dynpros, Module Pools and Transactions.

A class created in the Class Builder whose objects are managed by the persistence service of Object Services and can be stored in the database. Its attributes are linked to table columns. See Object Services: Persistence and Transaction Services.

An Eclipse window layout that arranges the editors and views for one kind of task. ABAP Development Tools bring an ABAP perspective for development and a debug perspective for debugging. See ABAP Development Tools (ADT).

A way to handle concurrent changes by locking a record while one user changes it. Every other change request for that record is rejected until the lock is gone. See RAP Authorization, Locking and Concurrency.

PFCG condition

A condition of a CDS access rule that compares fields of the entity with the authorizations the current user received through role maintenance (transaction PFCG). Only rows matching the user’s authorization values are returned. See CDS Access Control (DCL).

Physical file name

The real path and name of a file in the notation of the operating system of the server or PC. A logical file name is resolved to it at runtime. See Files: Application Server and Front End.

Placeholder

A marker such as &1 in a message text that is replaced by a value when the message is raised. It lets one text carry variable details, such as a claim number. See Messages.

Polymorphism

The same call running different code depending on the class of the object behind the reference. A caller can work with an interface or a superclass and still get the behavior of the actual class. See Interfaces, Inheritance and Polymorphism.

Pragma

A marker written in the source that silences one particular warning of the compiler or of a check tool for that statement. It starts with two number signs and has replaced the older pseudo comments. See ABAP Test Cockpit (ATC).

Predicate expression

A test on a single operand, such as asking whether a variable is initial, that is either true or false. It is used wherever a condition is expected. See Expressions, Operators and Assignments.

Predictive Analysis Library (PAL)

A library of ready-made statistical and machine-learning algorithms that run inside SAP HANA. They are called from SQLScript, so the data does not have to leave the database. See SAP HANA Search and Predictive Functions from ABAP.

Presentation server (front end)

The user’s own PC, on which SAP GUI runs. Files there are reached from ABAP through the class CL_GUI_FRONTEND_SERVICES, as opposed to files on the application server. See Files: Application Server and Front End.

Primary key

The columns that identify a row of a table. For an internal table, ABAP uses them for fast key-based access, and the key can be unique or non-unique depending on the table kind. See Internal Tables.

Print program

The ABAP program that reads the data for a document, chooses the form and hands the data to it. The form itself only lays the data out. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

Processing block

A unit of code that the ABAP runtime starts and leaves as a whole. Examples are a method, a function module, a subroutine and an event block. See Modularization Overview.

Program group

A main program, such as a loaded class pool or function pool, together with the programs loaded for it inside one internal session. Programs in a group share their global data. See Memory Organization and Sessions.

Program type

An attribute of a program that tells the system how it can be started and what it may contain. Examples are executable programs, module pools, function pools and class pools. See Program Types and Structure.

Projection view

A view that shows only a part of what lies below it. In RAP it is a CDS view entity that selects, and may rename, elements of one entity of a business object for one service; a classic Dictionary projection view does the same for one table. See Projections, Service Definitions and OData V4 Bindings.

Pseudo comment

The older way of hiding a warning of a check tool, written as a comment that the tool reads. It is obsolete, and pragmas replace it. See Coding Standards and Clean ABAP.

Publish and subscribe

A way to communicate in which the sender publishes a message without knowing who receives it. Receivers subscribe to the messages they care about. See ABAP Channels: APC and AMC.

Push Channel Protocol (PCP)

SAP’s own message format for WebSocket messages, made of name and value fields and a body. It is used by ABAP Push Channels to structure what is sent. See ABAP Channels: APC and AMC.

Q

QuickViewer

The classic tool, started with transaction SQVI, with which one user builds a simple personal list without programming. It is meant for quick reports on a few tables. See SAP Query and QuickViewer.

R

Raiser

The object or class whose method raises an event. Handlers react to the event without the raiser needing to know them. See Events.

Ranges table

An internal table with the columns sign, option, low and high that stores a set of conditions on one value. A selection screen creates one for each select option, and it can be used in the WHERE clause of a query. See Selection Screens and Variants.

RAP

The ABAP RESTful Application Programming Model, the transactional programming model of ABAP Cloud. It combines CDS entities, behavior definitions and services to build business objects and OData apps. See RAP Overview.

RAP business event

A record that a significant change happened to an entity of a RAP business object, so that interested parties can react. It is announced to other systems, for example through an event messaging service. See RAP Business Events.

RAP business object

A tree of CDS entities together with a behavior definition that says what may be done with them. A claim with its items is an example, and it is the unit RAP manages. See RAP Overview.

Redefinition

Giving an inherited method a new implementation in a subclass, with the same name and parameters. It is the way a subclass changes behavior it received from its superclass. See Interfaces, Inheritance and Polymorphism.

Reference field

The field that an amount or quantity points to, so that the system knows its currency or unit. Without it, a number alone does not say what it counts. See Currencies, Units and Conversion Exits.

Reference variable

A variable that points to an object, declared with TYPE REF TO. You work with the object through it, and several variables can point to the same object. See Classes and Objects.

Regular expression

A pattern that describes which texts match, for example three digits followed by a letter. ABAP uses patterns like this to find, check and replace parts of strings. See Strings, String Templates and Regular Expressions.

Relational expression

A comparison of two operands, such as one value being smaller than another, that is either true or false. It is the building block of conditions. See Expressions, Operators and Assignments.

Release contract

The named promise that says for which kind of use an SAP object is released. The contracts are named C0 to C4, and each one fixes what you may do with the object and how stable it stays. See Language Versions and Released APIs.

Release news

The part of the ABAP Keyword Documentation that lists, release by release, what is new in the language. It is the place to check which release introduced a statement. See What’s New in ABAP.

Released API

An SAP object that SAP has marked as stable and allowed for use by your own code. ABAP Cloud development may use only released APIs, so upgrades do not break your code. See Language Versions and Released APIs.

Remote Function Call (RFC)

A call of a function module that runs in another system, or in another session, through the RFC interface. The caller names a destination, and the function module must be marked as remote-enabled. See RFC, BAPIs and IDocs.

Remote-enabled function module

A function module that is marked in its properties as callable by RFC. Only such function modules can be called from other systems. See RFC, BAPIs and IDocs.

Reporting event

One of the events of an executable program, from loading to the end of data processing. INITIALIZATION and START-OF-SELECTION are examples, and the runtime raises them in a fixed order. See Classic Reports and Event Blocks.

RFC destination

The stored connection data, such as target system, connection type and logon data, that a call refers to by name after DESTINATION. It keeps connection details out of the program. See RFC, BAPIs and IDocs.

RFC server group

A named set of application server instances that parallel processing may use. Naming the group in a parallel call limits where the work can run. See Background Jobs and Parallel Processing.

Root entity

The top parent of a composition tree, the entity that stands for the whole RAP business object. All child entities hang below it through compositions. See CDS Associations and Compositions.

Rounding mode

The rule that decides in which direction a value lying exactly halfway between two results is rounded, for example up, down or to the even neighbor. Rounding functions let you choose it. See Dates, Times and Built-in Functions.

RTTC

Runtime type creation: building a new data type while the program runs, for example a structure whose columns are only known then. It is done with the runtime type services classes. See RTTI, RTTC and Dynamic Programming.

RTTI

Runtime type identification: reading the properties of a type, such as its kind, components or length, while the program runs. It is the tool for code that must handle data of types it does not know in advance. See RTTI, RTTC and Dynamic Programming.

Runtime error

The termination of a program because something went wrong that nothing handled, for example an exception nobody caught. The system records it in a short dump that you can analyze afterward. See Class-Based Exceptions.

Runtime type

The actual class of an object at the moment the program runs. It can be more specific than the declared type of the variable pointing to it. See Control Flow.

S

SAP Event Mesh

The SAP messaging service that carries events between systems. A system publishes events to it and other applications subscribe to them. See RAP Business Events.

SAP Fiori elements

SAP technology that builds the screens of an app, such as a list page and a detail page, from annotations on a service instead of hand-written screen code. You describe the data and its labels, and the framework draws the user interface. See Projections, Service Definitions and OData V4 Bindings.

SAP Fiori elements

SAP user interface technology that builds list pages and detail pages from the annotations of a service, so no screen code is needed. The annotations on a CDS view tell it which columns, headers and sections to show. See CDS Annotations and Metadata Extensions.

SAP HANA database

The in-memory database that is the standard database of current ABAP systems. Because it can calculate on large amounts of data itself, ABAP programs are written to let it do the heavy work. See ABAP for SAP HANA and Code Pushdown.

SAP lock

A logical lock that tells other users "this record is being edited, wait". It is created from a lock object, kept in the lock table of the enqueue server and not on the database, so it can last across several screens of a dialog. See Lock Objects and the SAP Lock Concept.

SAP LUW

A business change made of one or more database steps that must be saved or undone together. It ends with COMMIT WORK or ROLLBACK WORK, and it can span several screens and work processes. See SAP LUW, Update Tasks and Commit.

SAP memory

The memory of one logged-on user that holds named parameters, the SPA/GPA parameters, and that every window of that logon can read. Typical uses are default values such as a company code that are filled into input fields. See Memory Organization and Sessions.

SAP Query

A classic SAP tool in which an administrator defines queries so that a group of business users can build and run list reports without programming. It is reached through transaction SQ01 and works on InfoSets. See SAP Query and QuickViewer.

SAP S/4HANA migration cockpit

The tool of current SAP S/4HANA for loading business data into a new system. It moves the data with migration objects, either from staging tables filled from template files or directly from another SAP system. See Batch Input, Direct Input and Data Migration.

SAPscript

The oldest SAP technology for print forms such as invoices and letters. Its forms are edited in transaction SE71, and newer form technologies have largely replaced it. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

Save sequence

The last part of a RAP transaction. After the changes have been collected in the transactional buffer and a save is requested, the framework checks that the buffer is consistent, writes it to the database and cleans up. See RAP Overview.

Saver class

A local class of a RAP behavior pool that takes part in saving, for example to assign final keys or to add extra writes. It inherits from a class delivered by SAP, named CL_ABAP_BEHAVIOR_SAVER. See Behavior Definitions and Implementations.

Search help

A Dictionary object that builds the list of values offered when a user presses F4 in an input field. It helps people pick a valid value instead of typing it from memory. See Dictionary Views and Search Helps.

Secondary index

An extra index on a database table for columns other than the primary key. Like the index of a book it lets the database find rows by those columns quickly, at the cost of extra work when rows are written. See Foreign Keys, Check Tables and Indexes.

Secondary key

An additional, named key of an internal table that gives it a second way to be searched. It speeds up lookups by other columns, but it costs extra memory and upkeep. See Table Expressions and Secondary Keys.

Segment

One structured piece of the data of an IDoc, a message between systems. Segments are arranged in a tree of parents and children, and each holds a set of related fields. See RFC, BAPIs and IDocs.

Select list

The part of a CDS view definition, written in braces, that names the elements (columns) the view returns. It decides what the view shows from its data source. See CDS View Entities.

Selection criterion

An input field of a selection screen declared with SELECT-OPTIONS. It lets the user enter several single values, ranges and exclusions at once instead of just one value. See Selection Screens and Variants.

Selection parameter

A single input field on a selection screen, declared with PARAMETERS and backed by one variable of the program. The value the user types is available in that variable when the program runs. See Selection Screens and Variants.

Selection screen

The input form that a classic report shows before it runs, so the user can enter values that restrict the data. It is generated from ABAP statements rather than drawn by hand. See Selection Screens and Variants.

Selection text

The caption shown next to an input field of a selection screen. It is kept as a text element of the program, so it can be translated. See Text Elements and Translation.

Selection variant

A saved set of values for the fields of one selection screen. Starting the report with a variant fills in the same answers again. See Selection Screens and Variants.

Selectivity

How well the values of a field tell the rows of a table apart. A field with many different values is selective, and an index on such a field pays off, while an index on a field with few values does not. See Foreign Keys, Check Tables and Indexes.

Sender

The implicit parameter that every handler of an instance event can read to find out which object raised the event. You do not declare it yourself; ABAP fills it in. See Events.

Serialization

Turning ABAP data, such as a structure or a table, into a text format like JSON or XML so it can be sent or stored. Reading the text back into ABAP data is called deserialization. See HTTP Clients, JSON and XML Transformations.

Service binding

The object that connects a service definition to a protocol, such as OData V4, and to a kind of service, a UI service or a Web API. Publishing the binding makes the service reachable. See Projections, Service Definitions and OData V4 Bindings.

Service definition

The list of CDS entities that a business service exposes, written without choosing a protocol. A service binding later attaches it to a protocol. See Projections, Service Definitions and OData V4 Bindings.

Shared memory

An area of one application server that many users and programs can read, used for data that is expensive to build. It is kept apart from the memory of a single logon. See Memory Organization and Sessions.

Short dump

The error report that ABAP writes when a program ends with a runtime error that nobody caught. You read it in transaction ST22 or in ABAP Development Tools to see where and why the program stopped. See Debugging.

Simple transformation

A small declarative program, written in a special XML-based language, that maps ABAP data to XML or JSON and back. It is used when the standard mapping is not the shape you need. See HTTP Clients, JSON and XML Transformations.

Singleton

A class written so that only one object of it exists in the running program. Everyone who asks for it gets the same object. See Design Patterns in ABAP.

Smart Forms

The second generation of SAP print forms. A form is designed graphically in the Form Builder (transaction SMARTFORMS) and activated into a function module that a program calls. See Forms: SAPscript, Smart Forms and SAP Forms by Adobe.

SOAP

An older web service protocol that wraps its XML messages in an envelope and is described by a WSDL file. Many SAP systems still offer and call SOAP services. See HTTP Clients, JSON and XML Transformations.

Software component

The delivery unit that a package belongs to. It also decides the ABAP language version that the objects of its packages follow. See Packages, Transports, gCTS and abapGit.

Sorted table

A kind of internal table that always keeps its rows in key order. Because of that order it finds a row by repeatedly halving the range to search, which is much faster than reading every row. See Table Expressions and Secondary Keys.

SPA/GPA parameter

A named value of up to 20 characters in the user memory of SAP memory. It prefills input fields and passes short values between programs and transactions of the same logon. See Calling Programs, Transactions and Memory.

SPAU

The transaction that, during an update, adjusts modified repository objects such as programs, function modules and screens. It lets you re-apply or discard your changes against the new delivery. See Modifications, Modification Assistant and SPAU/SPDD.

SPDD

The transaction that adjusts modified ABAP Dictionary objects during an update, before the new dictionary objects are activated. It lets you re-apply or discard your changes against the new delivery. See Modifications, Modification Assistant and SPAU/SPDD.

Spool request

The stored print output of a job step. It waits in the spool until it is printed or shown on screen. See Background Jobs and Parallel Processing.

SQL Monitor

A tool that records, in a running system over a long time, which ABAP SQL statements are executed and how often. It shows which statements matter in real use rather than in one test run. See Performance, SQL Trace and Profiling.

SQL trace

A recording of every database statement a program sends, with its duration and parameters. It lets you see what a program really asks the database and where the time goes. See Performance, SQL Trace and Profiling.

SQLScript

The programming language of the SAP HANA database, an extension of SQL with variables and control flow. It is used for procedures and functions that run inside the database. See Native SQL, ADBC and AMDP.

SSCR

The SAP Software Change Registration, a procedure that registers developers and manual changes to SAP source code and Dictionary objects. A developer needs an access key to make such a change. See Modifications, Modification Assistant and SPAU/SPDD.

Staging table

A temporary table in which data waits during a migration. It is filled from template files or by a tool, and the migration cockpit then moves it into the system. See Batch Input, Direct Input and Data Migration.

Standard ABAP

The full, classic ABAP language version, with all statements and unrestricted access to system objects. It is used on premise and in private cloud editions, while ABAP for Cloud Development restricts the language. See Language Versions and Released APIs.

Stateful and stateless APC

Whether the handler of an APC connection keeps its attributes between the messages of one connection (stateful) or starts fresh for every message (stateless). APC is the ABAP Push Channel framework for WebSocket and TCP connections. See ABAP Channels: APC and AMC.

Static check

A check that reads the source text of a program and reports problems without running it. The syntax check and the extended program check are examples. See Coding Standards and Clean ABAP.

Static code analysis

Checking source code for problems without running it. In ABAP the ABAP Test Cockpit is the main tool for this. See ABAP Test Cockpit (ATC).

Status bar

The line at the bottom of a classic screen where short messages, such as success, warning and error texts, appear. Which messages show there depends on the message type. See Messages.

Strategy

A design pattern in which several interchangeable classes implement the same interface and one of them is chosen at run time. It lets you swap a rule, such as how a fee is calculated, without changing the code that uses it. See Design Patterns in ABAP.

String

A text of any length whose size grows and shrinks as needed, declared with the type string. It is the usual type for text in modern ABAP. See Strings, String Templates and Regular Expressions.

String function

A built-in function that takes a text and returns a new text or a number, such as one that gives the length of a text. It does not change the original text. See Strings, String Templates and Regular Expressions.

String template

A text written between vertical bars that can contain expressions in curly braces. ABAP replaces each expression with its value, which makes it an easy way to build messages. See Strings, String Templates and Regular Expressions.

Structure

A data object made of several named components, much like one filled-in row of a form. One claim with an ID, a status and an amount is a typical structure. See Data Types and Data Objects.

Subroutine

An old kind of procedure written between FORM and ENDFORM and called with PERFORM. It is obsolete; new code uses methods instead. See Modularization Overview.

Subscreen

A screen that is shown inside a reserved area of another screen, for example on one tab page. It lets one big screen be assembled from smaller ones. See Dynpros, Module Pools and Transactions.

sy-index

The system field that holds the number of the current pass through a DO or WHILE loop, counting from 1. In nested loops it belongs to the loop that runs at that moment. See Control Flow.

sy-subrc

The system field that holds the return code of the statement that ran last, where 0 usually means success. After a function module call it holds the number given to the exception that was raised. See Function Modules and Function Groups.

Synchronous RFC (sRFC)

A remote function call in which the caller waits until the remote function has finished and then continues with the result. It is the plainest kind of RFC. See RFC, BAPIs and IDocs.

System event

An event of a GUI control that is passed to its handler at once, before field checks and without the usual screen processing. See Control Framework and GUI Controls.

System field

A read-only value that the ABAP runtime fills in, for example the result of the last statement or the current date. All of them are components of the structure sy. See Data Types and Data Objects.

T

Table buffering

Keeping the rows of a rarely changed database table in the memory of the application server so that a read need not go to the database. It makes repeated reads faster. It suits tables that are read often and changed rarely. See Performance, SQL Trace and Profiling.

Table control

A screen element of a classic dialog that shows and lets the user edit the lines of an internal table, like a small spreadsheet. See Dynpros, Module Pools and Transactions.

Table expression

An operand written as the name of an internal table followed by square brackets, which picks out one row of the table. It is the short modern way to read a single row. See Table Expressions and Secondary Keys.

Table index

The position number of a row in an internal table, counted from 1. Standard and sorted tables have it, and hashed tables do not. See Internal Tables.

Table key

The columns by which an internal table finds its rows quickly. It is either the primary key chosen with the table or a secondary key added to it. See Table Expressions and Secondary Keys.

Table kind

The way an internal table stores and finds its rows, one of standard, sorted or hashed. The choice decides how fast lookups are. See Internal Tables.

Task

The part of a transport request that belongs to one developer. Each developer writes changes into their own task, and the request is released when its tasks are done. See Packages, Transports, gCTS and abapGit.

Test class

A class marked FOR TESTING that holds test methods. It is checked by ABAP Unit and is never part of the production behavior. See ABAP Unit and Test Doubles.

Test double

An object or table that stands in for a real component during a test, so the test controls what the component answers. It is like a crash-test dummy for the part of the code you do not want to involve. See ABAP Unit and Test Doubles.

Test seam

A marked piece of production code that a test can replace with other statements. It lets you test code that is hard to isolate without rewriting it first. See ABAP Unit and Test Doubles.

Text analysis

A feature of the SAP HANA database that finds words, languages and named entities such as people and places in text. ABAP reaches it through database-specific means. See SAP HANA Search and Predictive Functions from ABAP.

Text element

A text kept in the text pool of a program or class instead of inside its source code. Text symbols, selection texts and list headings are text elements, and they can be translated. See Text Elements and Translation.

Text field

A text of fixed length, declared with the type c, which is padded with blanks on the right. It differs from a string, which has no fixed length. See Strings, String Templates and Regular Expressions.

Text symbol

A numbered or named text element that code reads as TEXT-001. Keeping the wording outside the code makes it translatable. See Text Elements and Translation.

Text table

A table that holds the language-dependent texts of the rows of a check table. It has the key of the check table plus a language key. See Foreign Keys, Check Tables and Indexes.

Time stamp

A single value that names one exact moment, down to a fraction of a second. It is not tied to the clock of any place. See Dates, Times and Built-in Functions.

Time zone

A region whose clocks show the same local time, written in ABAP as a short key such as EST or UTC. It is needed to show a moment as local time to a user. See Dates, Times and Built-in Functions.

Total ETag

A field of a RAP business object that changes whenever the active data changes. A draft uses it to notice that the active data has moved on since the draft was created. See Draft Handling.

Transaction code

A short name such as SE80 that you type in the command field of SAP GUI to open one screen or start one program. Each code is linked to a program or method. See Classic Tools: SE80, SE38, SE11, SE37 and SE16.

Transactional buffer

The memory area that holds the data of a RAP business object while it is being worked on. Changes wait there until they are saved or discarded. See RAP Overview.

Transactional phase

One of the two stages, modify and save, that a controlled SAP LUW distinguishes. Changes are made in the modify phase, and the save phase writes them. See SAP LUW, Update Tasks and Commit.

Transactional RFC (tRFC)

The older kind of remote function call that is stored and sent when the caller commits. It is obsolete; background RFC replaces it. See RFC, BAPIs and IDocs.

Translation

The work of adding the same text in another language so the system can show the right copy to each user. See Text Elements and Translation.

Transparent table

The usual kind of Dictionary table. It exists on the database under its own name and with the same columns as its Dictionary definition. See Database Tables and Structures.

Transpiler

A program that translates source code from one language into another. In the hands-on lab it translates ABAP into JavaScript so that the code can run without an SAP system. See Hands-on Lab.

Transport layer

The group of development projects that share the same transport routes. It decides where the changes of a package travel after they are released. See Packages, Transports, gCTS and abapGit.

Transport request

A container that records changed objects so they can be moved from the development system to the next system. Without a request, a change stays where it was made. See Packages, Transports, gCTS and abapGit.

Type description object

The one object per type that carries the properties of that type, such as its length or components. It is created by the static methods of the type description classes and answers "what type is this?" while the program runs. See RTTI, RTTC and Dynamic Programming.

Type group

A special program that only holds type definitions and constants for shared use. See Program Types and Structure.

U

Unit of measure

A code such as KG or PC that says what a quantity is counted in. A quantity field is meaningful only together with its unit. See Currencies, Units and Conversion Exits.

Unit test

A test of one small unit of code, such as a method, that runs automatically and needs no person to judge the outcome. In ABAP it is written with ABAP Unit. See ABAP Unit and Test Doubles.

Unmanaged business object

A RAP business object whose behavior, including its buffer, is coded by the developer. See RAP Overview.

Unmanaged RAP business object

A RAP business object whose transactional buffer and operations you implement yourself in the behavior pool. The framework does not provide them for you. See Managed, Unmanaged and Unmanaged Save.

Unmanaged save

Your own code that replaces the standard save of a managed RAP business object. It is used when the changes must be written by your own code, for example existing function modules, instead of by the framework. See Managed, Unmanaged and Unmanaged Save.

Update function module

A function module marked as an update module. A program registers it during its work, and it runs later, in a special work process, when the program issues COMMIT WORK. See SAP LUW, Update Tasks and Commit.

Update task

The mechanism that stores registered update function modules and runs them when the program commits. It is part of classic ABAP and is not available in ABAP Cloud. See SAP LUW, Update Tasks and Commit.

Update work process

A work process reserved for running update function modules. It performs the database changes that the dialog program registered. See SAP LUW, Update Tasks and Commit.

User group

In SAP Query, the set of users that may use a given set of InfoSets and queries. A query is available to the members of its user group. See SAP Query and QuickViewer.

User master record

The record that exists for every user of an SAP system and holds, among other things, the authorizations that user has. Authority checks read it to decide whether an action is allowed. See Authorization Checks.

User session

Everything that belongs to one logon of one user to one application server. It starts at logon and ends at logoff, and it can contain several windows. See Memory Organization and Sessions.

UTCLONG

The built-in type that holds a time stamp in Coordinated Universal Time with a resolution of 100 nanoseconds. See Dates, Times and Built-in Functions.

V

Validation

A check on the data of a RAP business object that runs when it is saved and rejects the save when the data is wrong. A validation only checks; it never changes the data. See Behavior Definitions and Implementations.

Value help

The list a user can open next to an input field to pick a valid value. The term covers Dictionary search helps as well as CDS-based lists and Fiori apps. See Projections, Service Definitions and OData V4 Bindings.

Value table

A table named by a domain that serves only as a default proposal for the check table of a foreign key. It does not trigger any input check by itself. See Foreign Keys, Check Tables and Indexes.

Variable

A named place in memory that holds one value which the program can change. The name lets the program read and replace that value later. See Programming Concepts for Newcomers.

Virtual data model (VDM)

SAP’s layered set of CDS views, in which each layer has a defined purpose and a naming prefix. It gives applications a stable, business-oriented way to read SAP data. See CDS View Entities.

Visibility section

One of the three parts of a class, PUBLIC, PROTECTED and PRIVATE. The section in which a component is declared decides who may use it. See Classes and Objects.

W

Watchpoint

A marker on a variable that makes the debugger stop as soon as the value of that variable changes. It is useful when you do not know where a wrong value is set. See Debugging.

Web API

A service meant for programs rather than for people, which carries no user interface information in its metadata. It is the alternative to a UI service. See Projections, Service Definitions and OData V4 Bindings.

WebSocket

A protocol that keeps one connection open so that both sides can send messages at any time. It suits live updates better than repeated requests. See ABAP Channels: APC and AMC.

Window expression

A function followed by OVER that computes a value for each row from a group of related rows, such as a rank or a running total, without merging the rows into one. See ABAP SQL: Joins, CTEs, Window Functions and Path Expressions.

Work area

A single structure that holds one row while you read it from or write it to an internal table. See Internal Tables.

Work package

One independent slice of the data that one parallel task processes. Cutting the data into packages lets several tasks work at the same time. See Background Jobs and Parallel Processing.

Work process

A worker inside the application server that runs your ABAP code when it is given a request. It handles one piece of ABAP at a time. See Getting Started.

Wrapper

A small class of your own that hides a call to old code behind a released interface. ABAP Cloud code then calls the wrapper instead of the classic code. See Migrating Classic Code to ABAP Cloud.

Writable database object

A database table or CDS entity that the statements INSERT, UPDATE, MODIFY and DELETE are allowed to change. See ABAP SQL: Writing Data.

X

XCO library
