Configuration

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Poetry’s own behaviour (where environments go, how the installer works, which credentials to use) is set with poetry config, in files, or with POETRY_* environment variables. Project metadata and dependencies are not configuration: they belong in pyproject.toml (see pyproject.toml & Project Metadata). This page is written against Poetry 2.5.1. The examples ran on 2026-10-22 on Linux with CPython 3.14.6, with POETRY_CONFIG_DIR, POETRY_CACHE_DIR and POETRY_DATA_DIR pointed at empty scratch directories (shortened to …).

Where settings live

Source Written by Notes

Environment variables

your shell or CI

POETRY_ followed by the setting name in upper case, with dots and dashes replaced by underscores: virtualenvs.in-project is POETRY_VIRTUALENVS_IN_PROJECT.

poetry.toml in the project

poetry config --local …

Project-local settings, next to pyproject.toml. It can hold user-specific values; think before committing it.

config.toml in the config directory

poetry config …

Global (per-user) settings.

auth.toml in the config directory, or the system keyring

poetry config http-basic.<name> …, pypi-token.<name> …

Credentials only; see Credentials and certificates.

When a setting is defined in several places, the precedence is, from highest to lowest: environment variables, the local poetry.toml, the global config.toml, the default value. Credentials from auth.toml and the keyring are also overridden by environment variables.

Source: Poetry: Configuration sources, Local configuration.

installer.parallel = true
installer.re-resolve = false

requests.max-retries = 0
solver.lazy-wheel = true
solver.min-release-age = 0
solver.min-release-age-exclude = null
solver.min-release-age-exclude-source = null
system-git-client = false
virtualenvs.create = true

virtualenvs.options.always-copy = false

That is the complete list of 24 plain settings in Poetry 2.5.1, with their defaults (the families keyed by a name, such as repositories.<name>.url, only appear once set). The comment after a path shows the value actually in effect: here cache-dir reports the platform default but the POETRY_CACHE_DIR override after the #. Give a single name to read one value:

poetry config virtualenvs.path
…/cache/virtualenvs

Source: Poetry: Listing the current configuration, Displaying a single configuration setting, Available settings.

Setting, local settings and unsetting

poetry config virtualenvs.in-project true
poetry config --local virtualenvs.create false
cat "$POETRY_CONFIG_DIR/config.toml" poetry.toml
[virtualenvs]
in-project = true
[virtualenvs]
create = false

The first block is the global config.toml, the second the project’s poetry.toml. Environment variables beat both:

POETRY_VIRTUALENVS_CREATE=true poetry config virtualenvs.create
poetry config virtualenvs.create
poetry config --local virtualenvs.create --unset
poetry config virtualenvs.create
true
false
true

--unset removes the value from the chosen file, so the next source down (here the default) applies again; the emptied poetry.toml is left in place. Boolean environment variables accept true/1 for true; 0, false, no and an empty string all read as false when tried. Mistakes fail with exit code 1:

poetry config virtualenvs.creat true
poetry config virtualenvs.create maybe
Setting virtualenvs.creat does not exist
"maybe" is an invalid value for virtualenvs.create

A value that starts with a dash would be read as an option; put -- before the setting name: poetry config -- http-basic.ci ci-user -starts-with-dash. Without the -- the same command fails with The option "s" does not exist (exit code 1).

Source: Poetry: Adding or updating a configuration setting, Local configuration, Removing a specific setting, Using environment variables.

Migrating renamed settings

poetry config --migrate (and --migrate --local for poetry.toml) rewrites settings that a newer Poetry has renamed, such as experimental.system-git-client to system-git-client in 2.0. With nothing to change it prints:

Checking for required migrations ...
Already up to date.

Source: Poetry: Migrate outdated configs, Poetry CLI: config.

Notes on the settings that cause most surprises:

  • installer.no-binary, installer.only-binary and installer.build-config-settings are user settings: they only decide which file is installed into a Poetry-managed environment, never what goes into poetry.lock. Set them with --local for one project, or as environment variables in CI. A global installer.no-binary = :all: slows every project down.

  • virtualenvs.in-project = true does not move an environment that already exists in the cache; remove it with poetry env remove first (see Managing Environments).

  • solver.min-release-age (2.4.0) is a supply-chain guard; the filter only works for sources that publish upload times. pip’s counterpart is --uploaded-prior-to (see Supply-Chain Security).

  • installer.re-resolve is why a Poetry 2.3+ install no longer resolves again from a lock file; see Lock File, Install, Update & Sync.

  • Values are read and written as text: poetry config installer.no-binary ':all:' reads back as [":all:"], and poetry config installer.build-config-settings.grpcio '{"CC": "gcc"}' reads back the JSON unchanged.

One more knob is not a setting: the HTTP timeout is 15 seconds, like pip’s, and only the experimental environment variable POETRY_REQUESTS_TIMEOUT (seconds) changes it.

Source: Poetry: Available settings, installer.max-workers, solver.lazy-wheel, Poetry FAQ: My requests are timing out!, installer.no-binary, installer.re-resolve, solver.min-release-age, virtualenvs.in-project.

Credentials and certificates

http-basic and pypi-token values are not stored in config.toml. They go to the system keyring when one is available, or else, with a warning, to the plaintext auth.toml in the config directory. With the keyring disabled:

export POETRY_KEYRING_ENABLED=false
poetry config repositories.birdwatch http://127.0.0.1:8080/
poetry config http-basic.birdwatch alice "$BIRDWATCH_PASSWORD"
ls "$POETRY_CONFIG_DIR"
Using a plaintext file to store credentials
auth.toml
config.toml

auth.toml then holds a [http-basic.birdwatch] table with username and password. Give only the username and Poetry asks for the password on the terminal (where no terminal is attached it keeps asking, so a CI job hangs: always use POETRY_HTTP_BASIC_<NAME>_PASSWORD there). Reading a credential back is refused with Expected a value for http-basic.birdwatch setting. Sources, repositories and certificates are covered in depth on Repositories & Package Sources.

Source: Poetry: Configuring credentials, http-basic, keyring.enabled.
