Control Flow

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Python has the usual conditional and looping constructs, plus, since 3.10, a structural pattern matching statement (match) that goes well beyond a simple switch. All of it is covered in the tutorial’s More Control Flow Tools chapter.

if / elif / else and Truthiness

Python has no switch before 3.10 and no ternary keyword — branching is if / elif / else, and every value has a truth value used wherever a condition is expected:

def describe(n):
    if n < 0:
        return "negative"
    elif n == 0:
        return "zero"
    else:
        return "positive"

An object is falsy if it is None, False, a numeric zero (0, 0.0, 0j), or an empty container ("", (), [], {}, set(), range(0)) — everything else is truthy:

for value in [0, 1, "", "a", [], [0], None, {}]:
    print(value, "->", "truthy" if value else "falsy")

# 0 -> falsy      1 -> truthy    '' -> falsy   'a' -> truthy
# [] -> falsy     [0] -> truthy  None -> falsy {} -> falsy

This means if items: is the idiomatic emptiness check for any container — prefer it over if len(items) > 0:. The full rule set is documented under More on Conditions and Truth Value Testing.

while and for Loops

while repeats as long as its condition stays truthy; for iterates over any iterable — there is no C-style three-part for:

n = 5
while n > 0:
    print(n)
    n -= 1

for ch in "abc":
    print(ch)   # a, b, c

range()

range() generates an integer sequence lazily. Counting loops iterate over it rather than manually incrementing an index:

for i in range(5):        # 0, 1, 2, 3, 4
    print(i)

for i in range(2, 10, 2):  # start, stop, step -> 2, 4, 6, 8
    print(i)

Full parameters and behaviour are documented at the range type reference.

break, continue, pass

break exits the innermost loop immediately; continue skips to the next iteration; pass is a no-op statement used where syntax requires one, such as an empty body while stubbing something out:

for n in range(10):
    if n == 3:
        continue    # skip 3
    if n == 7:
        break       # stop entirely at 7
    print(n)        # 0, 1, 2, 4, 5, 6

def not_implemented_yet():
    pass    # placeholder body -- syntactically required, does nothing

The Loop else Clause

A for or while loop can carry an else block, executed only if the loop finished without hitting a break — a Python-specific idiom often used for "search, then report not-found":

def find_factor(n):
    for i in range(2, n):
        if n % i == 0:
            print(f"{n} = {i} * {n // i}")
            break
    else:
        print(f"{n} is prime")   # runs only when no break occurred

find_factor(15)   # 15 = 3 * 5
find_factor(13)   # 13 is prime

The loop else clause is documented alongside the loop statements in Break and continue Statements, and else Clauses on Loops.

The match Statement (3.10+)

match compares a subject against a series of case patterns, executing the first one that matches — structural pattern matching, not a value switch. It is specified in the language reference’s match statement section.

Literal, Capture, and Wildcard Patterns

def http_status(code):
    match code:
        case 200:
            return "OK"
        case 404:
            return "Not Found"
        case 500 | 502 | 503:      # combine literals with '|'
            return "Server Error"
        case other:                 # capture pattern: binds 'other' to the value
            return f"Unhandled: {other}"

A bare underscore _ is the wildcard pattern: it matches anything without binding a name, and conventionally goes last as the catch-all:

def sign(n):
    match n:
        case 0:
            return "zero"
        case n if n > 0:
            return "positive"
        case _:
            return "negative"

Guards

A case may carry an if guard — extra runtime logic that must also hold, evaluated only after the pattern itself matches:

def classify(point):
    match point:
        case (x, y) if x == y:
            return "on the diagonal"
        case (x, y) if x == 0 or y == 0:
            return "on an axis"
        case (x, y):
            return f"elsewhere: ({x}, {y})"

Class, Sequence, and Mapping Patterns

A sequence pattern destructures lists/tuples by position (*rest collects the remainder); a mapping pattern destructures dicts by key, ignoring any keys not named (equivalent to always carrying an implicit **rest); a class pattern matches an instance’s type and unpacks its attributes:

from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

def describe(value):
    match value:
        case []:
            return "empty list"
        case [first, *rest]:
            return f"starts with {first}, then {rest}"
        case { "kind": "circle", "radius": r }:
            return f"circle of radius {r}"
        case Point(x=0, y=0):
            return "origin"
        case Point(x=x, y=y):
            return f"point at ({x}, {y})"
        case _:
            return "no match"

describe([1, 2, 3])                       # 'starts with 1, then [2, 3]'
describe({"kind": "circle", "radius": 2}) # 'circle of radius 2'
describe(Point(0, 0))                     # 'origin'

Dict/mapping patterns use { } just like dict literals — this is standard match syntax, not anything special to this page. The full pattern grammar (OR patterns, AS patterns binding a whole subpattern, nested class patterns) is in the same language-reference section.

if/elif/else vs. match: The Same Decision, Two Ways

Both constructs pick one branch out of several based on the subject’s shape or value — match simply lets the pattern itself express structure (class, sequence, mapping) that an if chain would otherwise have to spell out with isinstance() and manual indexing:

flowchart TD A[Start: classify shape] --> B{if/elif/else chain} B -->|isinstance Circle| C[compute pi * r ** 2] B -->|isinstance Square| D[compute side ** 2] B -->|else| E[raise ValueError] F[Start: classify shape] --> G{match shape} G -->|case Circle r=r| H[compute pi * r ** 2] G -->|case Square side=s| I[compute s ** 2] G -->|case _| J[raise ValueError]
# Equivalent if/elif/else
def area_if(shape):
    if isinstance(shape, Circle):
        return 3.14159 * shape.r ** 2
    elif isinstance(shape, Square):
        return shape.side ** 2
    else:
        raise ValueError("unknown shape")

# Equivalent match
def area_match(shape):
    match shape:
        case Circle(r=r):
            return 3.14159 * r ** 2
        case Square(side=s):
            return s ** 2
        case _:
            raise ValueError("unknown shape")

Reach for match when a value’s shape — its type, length, or set of keys — drives the branching; a plain if/elif/else chain remains clearer for simple value or range comparisons. See the tutorial’s control flow overview for how both fit alongside loops and function calls.

What the Control-Flow Statements Really Do

Python’s control-flow statements are thin layers over a few protocols. Knowing them explains behaviour that otherwise looks like magic: why an empty custom container is "false", why or can return a string, and what a for loop does with its iterable.

Truthiness is a protocol

if x: calls bool(x), which asks the object for __bool__; if that is missing it uses __len__ (zero is false); if neither exists the object is always true. The built-in "empty" values (0, 0.0, "", [], {}, set(), None) are false and everything else, including the string "0" and the list [0], is true. The boolean operators do not return True or False: a or b evaluates to a if a is truthy, otherwise to b, and a and b is the mirror image. Both short-circuit, so the right operand may never run, which is also why x = y or default is a compact default idiom and a bug when 0 or "" is a legitimate value.

class Shelf:
    def __init__(self, books):
        self.books = list(books)

    def __len__(self):                     # used for truthiness when __bool__ is absent
        return len(self.books)


class Ticket:
    def __bool__(self):                    # __bool__ wins over __len__
        return False

    def __len__(self):
        return 5


print(bool(Shelf([])), bool(Shelf(["Dune"])), bool(Ticket()))
print([bool(v) for v in (0, 0.0, "", [], {}, set(), None, " ", "0", [0])])

# and / or return an operand, not a bool
print("" or "untitled", "Dune" and "found", None or 0 or [] or "last")
name = None
print((name or "anonymous").title())       # beware: 0 and "" are replaced as well
count = 0
print(count or 10, count if count is not None else 10)   # use an explicit None test

# chained comparisons evaluate each operand once
def noisy(n):
    print("eval", n)
    return n
print(1 < noisy(5) < 10)

# the walrus operator (3.8+) names a value inside an expression
data = ["12", "x", "7"]
digits = [int(v) for s in data if (v := s.strip()).isdigit()]
print(digits)

Output:

False True False
[False, False, False, False, False, False, False, True, True, True]
untitled found last
Anonymous
10 0
eval 5
True
[12, 7]

Chained comparisons (1 < x < 10) evaluate the middle operand once, and the assignment expression := (3.8+) binds a name inside a larger expression, which removes duplicated calls in comprehension filters and while conditions.

A for loop desugars to the iterator protocol

flowchart TD A["for item in iterable"] --> B["it = iter(iterable)"] B --> C["item = next(it)"] C -->|"value"| D["Run loop body"] D --> E{"break or\nreturn?"} E -- No --> C E -- Yes --> G["Leave loop,\nskip else"] C -->|"StopIteration"| F["Run else block\nif present"] F --> H["Continue after loop"] G --> H

for calls iter() once, then next() until StopIteration. That is why any object with __iter__ can be looped over, why a generator is consumed by a loop (a second loop over the same generator sees nothing), and why mutating a list during iteration misbehaves (the iterator holds an index). The else clause of a loop runs when the loop ended because the iterable was exhausted, not because of break; it is the natural place for "searched and found nothing". Further helpers worth knowing are enumerate(start=...), zip (stops at the shortest input), reversed, and the two-argument form iter(callable, sentinel), which calls a function repeatedly until it returns the sentinel.

# What 'for' does, written out by hand
shelf = ["Dune", "Emma"]
iterator = iter(shelf)
while True:
    try:
        title = next(iterator)
    except StopIteration:
        break
    print("visit", title)

# for/else: the else block runs only if the loop was not ended by break
def find(titles, wanted):
    for t in titles:
        if t == wanted:
            print("found", t)
            break
    else:
        print("missing", wanted)

find(shelf, "Emma")
find(shelf, "Ulysses")

# while with a sentinel, enumerate/zip and reversed
queue = ["a", "b", "c"]
while queue:
    print("process", queue.pop(0))
for i, (a, b) in enumerate(zip("xyz", [10, 20]), start=1):   # zip stops at the shortest
    print(i, a, b)
print(list(reversed(range(0, 10, 3))), list(range(5, 0, -2)))

# iter(callable, sentinel) reads until the sentinel appears
import io
stream = io.StringIO("alpha\nbeta\n\ngamma\n")
for line in iter(stream.readline, "\n"):
    print(repr(line))

Output:

visit Dune
visit Emma
found Emma
missing Ulysses
process a
process b
process c
1 x 10
2 y 20
[9, 6, 3, 0] [5, 3, 1]
'alpha\n'
'beta\n'

The iterator protocol itself is covered in Iterators, Generators and Comprehensions.

Structural pattern matching beyond the basics

match (3.10+) tests a value against patterns in order and runs the first case that fits. Unlike a switch, a pattern can destructure: mappings match by the keys they list (extra keys are ignored), sequences match by shape, a pattern like str(title) checks the type and captures the value in one step, and an if guard refines a case. A bare name in a pattern is a capture that always succeeds, and a dotted name such as Color.RED is a value comparison; mixing them up is the most common pattern-matching bug. The sample requires Python 3.10 or newer:

# Requires Python 3.10 or newer (structural pattern matching).
def describe(event):
    match event:
        case {"type": "borrow", "title": str(title), "days": int(days)} if days > 14:
            return f"long loan of {title}"
        case {"type": "borrow", "title": title}:
            return f"loan of {title}"
        case ["return", *titles]:
            return f"returned {len(titles)} book(s)"
        case _:
            return "unknown"

print(describe({"type": "borrow", "title": "Dune", "days": 21}))
print(describe({"type": "borrow", "title": "Emma", "days": 7}))
print(describe(["return", "Dune", "Emma"]))
print(describe(42))

Output:

long loan of Dune
loan of Emma
returned 2 book(s)
unknown

Choosing the loop form

  • iterate over the items directly (for t in titles), not over range(len(titles)), unless you need the index, in which case use enumerate;

  • use while when the number of iterations depends on a condition you update inside the loop;

  • use else on a loop only for search patterns, and add a comment, because many readers do not know it;

  • prefer comprehensions for building a collection and a plain loop when the body has side effects.

Every snippet in this section was run with CPython 3.14.8 and the output shown is the real output.
