Ecosystem & Learning Resources

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is the only place in the Scala section that talks about libraries, frameworks and tools built on Scala, and it describes each of them in one line: what it is, the latest stable version, the Scala versions it is published for, and where its own site and documentation live. None of them is documented further here; the section’s other pages cover the language itself and the official Scala Toolkit. The page was written against Scala 3.10.0 (released 2026-10-12) with Scala 3.9.0 as the LTS line, and every version and link below was checked on 2026-10-16. Versions move quickly, so treat the version cells as a snapshot and read the project’s own site before you pin anything.

How the page was assembled

  • Selection criterion. A project is listed when the official Scala sites link to it (the docs.scala-lang.org pages on tools, books and courses, and the Scala 3 Book’s feature overview) or when it is one of the most commonly used Scala libraries in its area. The page does not rank projects and does not quote popularity statistics, download counts or star counts; the order inside a table groups related projects and is not a ranking.

  • Versions. The "Latest stable" cell is the newest release without a milestone (M), release-candidate (RC), snapshot or preview suffix, read from the project’s maven-metadata.xml on Maven Central, or from the project’s own site or release page for tools that are not libraries (Scala CLI, Metals, the IntelliJ plugin, Scala Native). Where a newer pre-release exists it is named, because several important projects (http4s, Doobie, Kyo, Pekko 2) are in that state.

  • Scala versions. For libraries this lists the Scala binary versions for which the latest stable release is published on Maven Central: 3 (the _3 artifact), 2.13 and 2.12. It says nothing about Scala.js or Scala Native artifacts, which many of these libraries also publish; see their sites. The Scala version in a coordinate is written with the :: shorthand of the Scala CLI and Coursier, so org.typelevel::cats-core:2.13.0 means the artifact cats-core_3 (or _2.13, depending on the project’s Scala version) at version 2.13.0.

  • Nothing here is run. The page contains no program. The one-line coordinates are the form the project’s own documentation or Maven Central page shows, and they are not tested against this section’s examples.

Kyo

An effect system built on algebraic effects for Scala 3; the newest release, 1.0.0-RC7, is a release candidate

Site, Source

These libraries make effects values: a description of work that a runtime runs later, which gives cancellation, retries and resource safety as library features. Ox takes the opposite route and keeps ordinary blocking code, relying on the JDK’s virtual threads for scalability. The built-in alternative is the Future of Futures & Promises. A reader coming from Kotlin will find the same questions answered by coroutines in Coroutines Basics.

Actors and streaming

Project What it is Latest stable and Scala versions Links

Apache Pekko

An Apache Software Foundation fork of Akka 2.6.x, taken before Akka adopted the Business Source License; actors, streams, cluster and persistence for Scala and Java

org.apache.pekko::pekko-actor:1.7.1, Scala 3, 2.13, 2.12; 2.0.0-M4 is a milestone

Site, Docs

Akka

The original actor and streams toolkit from Lightbend, now under the Business Source License 1.1 (see below)

the license page of the documentation names Akka 2.10.24; Maven Central carries releases only up to the 2.8 line

Site, Docs

License change. Akka was Apache 2.0 licensed until Lightbend announced on 7 September 2022 that it was moving to the Business Source License 1.1: source available, free for development and non-production use, with production use requiring a commercial license from Lightbend. The license file in the Akka documentation carries a change date, after which a release converts to Apache 2.0, and an additional usage grant for specific uses such as Play Framework. Apache Pekko is the Apache-licensed continuation, forked from Akka 2.6.x. Older books and tutorials that say "use Akka" are therefore usually describing a library whose open source successor is Pekko; Cats Effect, ZIO and Ox are the other common choices for concurrency. The project’s own sources are the announcement and the license page.

Apache Spark

A distributed data processing engine, written in Scala; since 4.0.0 its documentation says it runs on Scala 2.13 only

org.apache.spark:spark-core_2.13:4.2.0; no _3 artifact

Site, Docs

Apache Flink

A stream processing engine. The Scala DataStream and DataSet APIs were removed in Flink 2.0; Scala programs use the Java DataStream API instead

Flink 2.3.0 (a Java and Scala code base; the last Scala API artifact on Maven Central is flink-streaming-scala_2.12:1.20.5)

Site, Docs

Apache Kafka

A distributed event log. The broker code base is Scala and Java; the clients are Java libraries that any Scala program can call

org.apache.kafka:kafka_2.13:4.4.0 (the broker artifact), Scala 2.13 and 2.12

Site, Docs

Using Spark from Scala 3. Because Spark publishes only _2.13 artifacts, a Scala 3 project asks for that artifact explicitly. In sbt this is CrossVersion.for3Use2_13 on the dependency, which the Scala 3 migration guide describes in Mixing Scala 2.13 and Scala 3 classpaths. Scala 3 reads Scala 2.13 libraries, but the reverse is limited: a Scala 3.8 or newer library cannot be read from a Scala 2.13 build through the TASTy reader. The rules, with the exact versions, are in Versions, Compatibility & JDKs and Scala 2 & Scala 3 Compatibility.
