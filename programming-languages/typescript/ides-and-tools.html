TypeScript IDEs & Tools

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page lists the IDEs and editors most commonly used to write TypeScript, with a link to each product’s official page. Most of them work with the same language tooling, so choose by how much built-in integration you want versus how light and fast you want the editor to be.

IDEs

  • WebStorm — JetBrains' IDE for JavaScript and TypeScript, with refactoring, debugging and framework support built in.

Editors with extensions

  • Visual Studio Code — the most widely used editor for web development, extensible through a large extension marketplace.

  • Sublime Text — a fast, lightweight commercial text editor with a package ecosystem.

  • Zed — a fast, collaborative code editor with built-in language server support.

What every TypeScript editor has in common

Whatever editor you choose, the intelligence behind it is the same program: the TypeScript language service, hosted in a long-lived process called tsserver that ships inside the typescript package. The editor is only a front end. It sends requests ("what is the type at this offset?", "rename this symbol", "what are the completions here?") and renders the answers. This is why a hover in Visual Studio Code, a rename in WebStorm and a go-to-definition in Zed can all report exactly what tsc reports: they are all asking the same compiler front end.

flowchart LR ED["Editor
(buffer, UI)"] -->|"requests: quickinfo, completions,
rename, diagnostics"| TS["tsserver
(language service)"] TS -->|"answers + diagnostics"| ED TS --> P["Program
(parsed files + type checker)"] P --> C["tsconfig.json
(options, include)"] P --> F["Your .ts files
+ lib.d.ts + @types"] P --> M["node_modules/typescript
(the version in use)"]

Three consequences follow, and they explain most "the editor disagrees with the command line" reports:

  • The nearest tsconfig.json decides the project. The language service finds the config that includes the open file and uses its options (strict, target, module, paths). A file that no config includes is checked as a loose "inferred project" with default options, so errors can appear or vanish compared with a build. If a file shows no errors in the editor but npx tsc reports some, check that the file is matched by include.

  • The TypeScript version is a choice. Visual Studio Code ships its own copy of TypeScript, and can be pointed at the workspace copy so the editor and the build agree. Use the command palette entry "TypeScript: Select TypeScript Version" and choose the workspace version, or set it in .vscode/settings.json:

    {
  "typescript.tsdk": "node_modules/typescript/lib",
  "typescript.enablePromptUseWorkspaceTsdk": true
}

  • Editors are not the gate. Diagnostics in the editor are a convenience. The authoritative checks are npx tsc --noEmit in CI and, for style rules, a linter. See Project References and Build.

Checking what the editor sees

Two command-line switches reproduce the editor’s view of a project, which makes them the first tools to reach for when the two disagree. --showConfig prints the configuration after extends and defaults are applied, and --listFilesOnly lists the files the program contains without type-checking:

npx tsc --showConfig          # the effective compilerOptions, files and include
npx tsc --listFilesOnly       # every file in the program, including lib.*.d.ts and @types
npx tsc --explainFiles        # why each file is in the program (include pattern, import, lib)

If src/http-client.ts from the worked example is not in the --listFilesOnly output, no amount of editor restarting will make the editor type-check it strictly.

Language-service features worth learning

Most of the productivity gain comes from a handful of features that need nothing but the language service:

Feature What it does Why it matters in TypeScript

Quick info (hover)

Shows the type the checker computed for any expression, including after narrowing.

Inference is invisible until you look. Hover to learn what a generic call resolved to instead of guessing.

Go to definition / type definition

Jumps to the declaration, or to the declaration of the type of a value.

"Go to type definition" on a variable of type RequestState<PublicUser> lands on the union, not on the const.

Rename symbol

Renames a symbol and every reference the checker can resolve, across files.

Safe refactoring is the main benefit of types you cannot get from search and replace.

Organize imports, remove unused

Sorts, merges and prunes the import list; under verbatimModuleSyntax it keeps import type correct.

Keeps type-only imports from becoming runtime imports.

Quick fixes and refactors

Add a missing import, implement an interface, extract a function or type, convert to an async function.

The error list becomes a to-do list that fixes itself.

Inlay hints

Optionally shows inferred parameter names, return types and variable types inline.

Useful to review inference; turn them off if they clutter.

Call hierarchy and find all references

Lists callers and every use of a symbol, typed or not.

Answers "who depends on this type?" before a breaking change.

Choosing between editors

The decision is mostly about integration versus weight, not about type-checking quality:

  • WebStorm bundles its own indexing, refactorings and debugger and runs the TypeScript service for diagnostics. It is the lowest-setup option for large monorepos with a framework.

  • Visual Studio Code uses tsserver directly, so new TypeScript features arrive as soon as the extension host picks up a new typescript version. It is the reference experience for the language service.

  • Sublime Text and Zed reach the same service through the Language Server Protocol, using a server that wraps tsserver, such as typescript-language-server. They start fast and do fewer refactorings.

Whichever you choose, keep the editor’s TypeScript version equal to the one in package.json, keep one tsconfig.json per project, and let CI run the same tsc the editor models.
