Troubleshooting NuGet Errors and Warnings

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

NuGet reports problems with NUxxxx codes, grouped by hundreds: NU10xx project and CPM configuration, NU11xx resolution, NU13xx sources, NU14xx lock files and integrity, NU15xx project content, NU16xx dependency graph warnings, NU17xx compatibility, NU18xx source warnings and NU19xx auditing. This page gives a method and the real messages, almost all reproduced on the other NuGet pages with NuGet 7.9.0 (.NET SDK 10.0.402); each row links where.

A diagnosis method

  1. Read the first NU code and its page — https://learn.microsoft.com/nuget/reference/errors-and-warnings/nuNNNN (each page has Issue and Solution).

  2. Restore alone, verbosely. dotnet restore -v:detailed shows the sources queried (GET/CACHE), the nuget.config files used and why versions were chosen; -bl records it for the Structured Log Viewer.

  3. Rule out caches. --no-http-cache, an empty RestorePackagesPath, or dotnet nuget locals all --clear (Global Packages and Cache Folders).

  4. Explain the graph. dotnet nuget why <project> <package> and dotnet package list --include-transitive (Dependency Resolution).

NU1803

You are running the 'restore' operation with an 'HTTP' source, 'http://localhost:5555/v3/index.json'. Non-HTTPS access will be removed in a future version. Consider migrating to an 'HTTPS' source.

below

The documentation prints NU1701 as "restored using 'TargetFrameworkA' instead the project target framework"; the real message reads "instead of the".

NU1803 is the pre-.NET 9 warning that NU1302 replaced — and it comes back when SdkAnalysisLevel is lowered. The same HTTP source that fails with NU1302 by default produced only NU1803 with -p:SdkAnalysisLevel=8.0.400. The HTTPS requirement is therefore one of the SDK behaviours that SdkAnalysisLevel controls, which is worth knowing before using that property to quiet new warnings (Format and Code Analysis).

Documentation gaps

  • NU1606 and NU1607 appear in the errors-and-warnings index but have no page (the URLs return 404).

  • NU1020, the .NET 11 minimum-publish-age error (minPublishAgeHours), has no page yet.

  • NU1902 and NU1903/NU1904 share the NU1901-NU1904 page.

Common mistakes

  • Fixing the last NU code first — the first one usually causes the rest.

  • Clearing every cache before reading the message — slow, and it hides the evidence.

  • Suppressing NU1605, NU1608 or NU1701 globally — each describes a real run-time risk.

  • Lowering SdkAnalysisLevel to silence one warning — it also relaxes other checks, such as HTTPS enforcement.
