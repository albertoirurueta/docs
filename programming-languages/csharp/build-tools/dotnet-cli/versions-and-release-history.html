.NET SDK Versions and Release History

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A .NET runtime version (10.0.13) and a .NET SDK version (10.0.402) are released together but numbered differently, and several SDKs ship for each runtime patch. This page explains the numbering, the support dates as of 2026-10-23, and collects the SDK changes that the other pages of this group cite. The baseline is .NET SDK 10.0.402 (2026-10-13, runtime 10.0.13).

Runtime and SDK versions

An SDK version is major.minor.Fpp: F is the feature band (hundreds digit) and pp the patch within it. The runtime it carries is the matching major.minor.patch. The release metadata lists, for every runtime patch, the SDKs released with it:

curl -s https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json | python3 -c '
import json, sys
for r in json.load(sys.stdin)["releases"]:
    print(r["release-version"], r["release-date"], ", ".join(s["version"] for s in r.get("sdks", [])))'

The pattern:

  • A new feature band about every three months — 2xx in March, 3xx in May, 4xx in August — each bringing a newer MSBuild, NuGet and Roslyn and the features listed below. Each band is released with a runtime patch, so SDK 10.0.402 and 10.0.113 both carry runtime 10.0.13.

  • The 1xx band was patched in every release, alongside the newest band.

  • A superseded band gets one overlap release (10.0.303 in August, 10.0.204 in May) and then no more patches. global.json with rollForward: latestPatch on an old band therefore stops receiving security fixes; latestFeature moves with the bands (Installing and Selecting SDKs).

Source: .NET versioning: Semantic versioning, How .NET is versioned, .NET release metadata index.

  • LTS (even majors) releases are supported for three years, STS (odd majors) for two — so .NET 8 (LTS, November 2023) and .NET 9 (STS, November 2024) end on the same day, 2026-11-10, three weeks after this page’s date.

  • .NET 10 is the current LTS, supported until 2028-11-14.

  • .NET 11 is at release candidate 2, a go-live release: supported in production by Microsoft, but not final.

  • Building for an out-of-support framework warns NETSDK1138 (Target Frameworks and Runtime Identifiers).

Source: .NET and .NET Core support policy.

Some features reached earlier SDKs than these pages say. With SDK 10.0.402, #:include of .cs files and fish completion scripts already worked, and SDK 9.0.319 already had dotnet package add and dotnet reference add (Run and File-Based Apps, Solutions, References and Packages).

Common mistakes

  • Pinning an old feature band with latestPatch — the band stops receiving patches.

  • Confusing the SDK and runtime versions in bug reports — include dotnet --info.

  • Staying on .NET 8 or 9 after 2026-11-10 — no more security fixes; .NET 10 is the LTS.

  • Treating a go-live RC as final — supported, but APIs and defaults can still change before GA.
