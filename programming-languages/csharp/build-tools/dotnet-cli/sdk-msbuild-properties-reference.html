SDK MSBuild Properties Reference

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The .NET SDK reads hundreds of MSBuild properties; this page lists the ones a project or Directory.Build.props typically sets, grouped as in the official reference, each with its default and a link to its documentation. The defaults in the tables were read with dotnet msbuild -getProperty:… from a fresh dotnet new console project targeting net10.0 with .NET SDK 10.0.402 (Debug unless noted); "(empty)" means the property is not set and the SDK behaves as described. Properties of the C# compiler are documented with the compiler options, not on the SDK page; they are linked there.

dotnet msbuild -getProperty:LangVersion -getProperty:Deterministic -getProperty:NuGetAuditMode -getProperty:PublishRelease
{
  "Properties": {
    "LangVersion": "14.0",
    "Deterministic": "true",
    "NuGetAuditMode": "all",
    "PublishRelease": "true"
  }
}

Source: MSBuild reference for .NET SDK projects.

Common mistakes

  • Believing Nullable and ImplicitUsings are SDK defaults — the templates set them; an empty project has neither.

  • Setting TargetFramework and TargetFrameworks together — the singular wins for the outer build, with confusing results.

  • Changing DefaultItemExcludes without the $(DefaultItemExcludes); prefix — bin and obj get compiled.

  • Looking for compiler options on the SDK page — LangVersion, Nullable, Deterministic live in the C# compiler options reference.
