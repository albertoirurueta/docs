MSBuild Versions and Release History

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

MSBuild has its own version number, separate from Visual Studio and from the .NET SDK, and each Visual Studio release and each SDK feature band carries a specific MSBuild. Knowing which one runs explains most "works in Visual Studio, fails in CI" differences. This page shows how to find the version, maps it to Visual Studio and the SDK, and collects the release history cited throughout this section. The baseline is MSBuild 18.9.15 in .NET SDK 10.0.402.

Finding the version in use

dotnet --version
dotnet msbuild -version
dotnet msbuild cw.proj -getProperty:MSBuildVersion -getProperty:MSBuildRuntimeType -getProperty:MSBuildAssemblyVersion
10.0.402
18.9.15.50611
{
  "Properties": {
    "MSBuildVersion": "18.9.15",
    "MSBuildRuntimeType": "Core",
    "MSBuildAssemblyVersion": "18.0"
  }
}

  • dotnet --version is the SDK chosen for the current folder (after global.json); dotnet msbuild -version is the MSBuild inside that SDK. With 10.0.402 the two are 10.0.402 and 18.9.15.

  • msbuild -version in a Visual Studio Developer Command Prompt prints the msbuild.exe version (18.11 with Visual Studio 2026 18.11) — a different MSBuild from the one dotnet build runs on the same machine.

  • $(MSBuildVersion) is the version inside a project; $(MSBuildRuntimeType) is Core for dotnet and Full for msbuild.exe. The assemblies themselves keep assembly version 15.1.0.0 for every release from 15 to 18 (The MSBuild API and MSBuild Locator).

Source: MSBuild command-line reference (-version), MSBuild reserved and well-known properties.

Guarding logic by version

Shared .props/.targets files that must run on several MSBuild versions test $(MSBuildVersion) with the version functions, never with string or < comparisons (Conditions):

<Project>
  <Target Name="Show">
    <Message Importance="high" Condition="$([MSBuild]::VersionGreaterThanOrEquals('$(MSBuildVersion)', '18.6'))"
             Text="MSBuild $(MSBuildVersion): -mt is available" />
    <Message Importance="high" Condition="'$(MSBuildRuntimeType)' == 'Full'"
             Text="Running in msbuild.exe (.NET Framework)" />
  </Target>
</Project>
  MSBuild 18.9.15: -mt is available

A package that needs a minimum MSBuild can also fail early with an Error task under the opposite condition, which is clearer than the error the missing feature would cause.

Source: MSBuild version comparison functions.

Common mistakes

  • Assuming Visual Studio and dotnet build use the same MSBuild — 18.11 versus 18.9 on a machine with Visual Studio 2026 18.11 and SDK 10.0.402.

  • Comparing $(MSBuildVersion) with < — use VersionGreaterThanOrEquals.

  • Reading the assembly version (15.1.0.0) as the product version.

  • Looking for a "what’s new in MSBuild 18" page — use the GitHub releases and the SDK what’s-new pages.
