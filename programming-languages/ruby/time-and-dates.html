Time and Dates

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Ruby 4.0 (4.0.7, checked on 2026-10-18); features newer than Ruby 3.0 name the version that introduced them. Ruby has three tools for time, and most mistakes come from using the wrong one. Time is a core class that represents an instant on the time line together with the UTC offset it is displayed in. Date is a calendar day with no time of day and no zone, and lives in the date library. Process.clock_gettime reads the operating system clocks, notably the monotonic clock that is the right way to measure how long something took. This page covers each of them in full: how to create, convert, compare and round a Time, what a time zone is in Ruby (an offset, a name from the TZ environment variable, or a zone object you write), what happens across daylight saving transitions, every strftime directive and flag, the strict and the forgiving parsers, the Date API and the calendar reform it models, why DateTime should not be used, and how to keep time out of your tests by injecting a clock.

Related pages: the comparison protocol behind Time and Date ordering is in Equality, Hashing and Comparison, stepping through time ranges is in Ranges, matching on time fields is in Pattern Matching, writing times to JSON, YAML and Marshal is deepened in Serialization: JSON, YAML, CSV and Marshal, testing code that depends on the clock is in Testing with Minitest and RSpec and Test Doubles, measuring code is in Performance, Benchmarking and Profiling, and the traps around floating point and wall clocks are collected in Common Mistakes and Gotchas. For how other languages approach the same problem, see Java dates and times, Go time and timers and PHP date and time.

Every example on this page was syntax-checked with ruby -wc, run with ruby -w on Ruby 4.0.7 and linted with RuboCop 1.92 using the configuration of the running shelf gem (target Ruby 4.0, double-quoted strings). The output shown in # => comments is the real output. The examples that print local times first set ENV["TZ"] = "Europe/Madrid", so the output does not depend on the machine that ran them; the effect of that line is explained in The TZ environment variable. The examples reuse the shelf library catalogue used throughout this section (Shelf::LendingPolicy is new on this page); each file is self-contained so it can be run on its own. Lines written as p expression are only there because RuboCop rejects an operator expression whose value is ignored (Lint/Void); the comment shows what the expression returns.

Type What it is Use it for

Time

Core class. An instant (exact seconds since the Unix epoch, with sub-second precision) plus a UTC offset used to display it.

Timestamps, deadlines, log lines, durations between two wall-clock instants, anything with a time of day.

Date

date library (a default gem, 3.5.1 in Ruby 4.0). A day in the proleptic Gregorian or the Julian calendar. No time of day, no zone.

Birthdays, due dates, reporting periods, any value that is a day and not an instant.

DateTime

date library. A Date subclass with a time and an offset. Documented as deprecated: "Use Time class."

Nothing new. See Why DateTime is deprecated.

Process.clock_gettime

Core. Reads a named operating system clock and returns a Float or an Integer in the unit you ask for.

Measuring elapsed time, timeouts, rate limiting, benchmarks. Never for dates shown to people.

Integer or Float seconds

Epoch seconds, as returned by Time#to_i and Time#to_f.

Storage and interchange when both sides agree on the epoch. Prefer Integer or Rational to Float for precision.

Three libraries are involved, and which of them you need to require decides whether a method exists:

  • Time itself is core: Time.now, Time.new, Time.at, Time.utc, Time.local, strftime, arithmetic and Time#iso8601 need no require. Since Ruby 3.4 Time#xmlschema and its alias Time#iso8601 are part of the core class; before 3.4 they were added by the time library.

  • require "time" (the time default gem, 0.4.2 in Ruby 4.0) adds the class methods that parse and the formats other than ISO 8601: Time.parse, Time.strptime, Time.iso8601, Time.xmlschema, Time.rfc2822, Time.httpdate, and the instance methods Time#rfc2822 and Time#httpdate. Calling Time.iso8601 without the require raises NoMethodError, even on 4.0.

  • require "date" (the date default gem) defines Date and DateTime, and adds Time#to_date, Time#to_datetime and Date#to_time. The time library requires date itself.

Time

Creating a Time

Time.now returns the current instant in the local zone. Time.new with fields builds a Time from a calendar reading, Time.utc (alias Time.gm) reads the fields as UTC, Time.local (alias Time.mktime) reads them in the local zone, and Time.at builds a Time from epoch seconds. The fields are, in order, year, month, day, hour, minute, second; everything after the year is optional and defaults to the start of the period (January, the 1st, midnight). The month can also be a three-letter name, and the second can be fractional (a Rational is exact, a Float is not). A seventh argument or the in: keyword (Ruby 3.1) chooses the offset, and Time.now(in:) and Time.at(in:) accept it as well. Passing both the seventh argument and in: raises ArgumentError ("timezone argument given as positional and keyword arguments").

# frozen_string_literal: true

ENV["TZ"] = "Europe/Madrid"

# Local time (uses the TZ environment variable), UTC and an explicit offset.
local = Time.new(2026, 3, 5, 10, 30, 15)
local.inspect # => "2026-03-05 10:30:15 +0100"
local.utc_offset # => 3600
local.zone # => "CET"
local.utc? # => false

utc = Time.utc(2026, 3, 5, 9, 30, 15)
utc.inspect # => "2026-03-05 09:30:15 UTC"
utc.zone # => "UTC"
utc.utc? # => true
p utc == local # => true

tokyo = Time.new(2026, 3, 5, 18, 30, 15, "+09:00")
tokyo.inspect # => "2026-03-05 18:30:15 +0900"
tokyo.zone # => nil
p tokyo == utc # => true

# The in: keyword accepts the same offsets, and "Z" means UTC.
Time.new(2026, 3, 5, 9, 30, 15, in: "Z") # => 2026-03-05 09:30:15 UTC
Time.new(2026, 3, 5, in: "-05:00") # => 2026-03-05 00:00:00 -0500
Time.at(0, in: "UTC") # => 1970-01-01 00:00:00 UTC
Time.at(1_772_703_015, in: "+01:00") # => 2026-03-05 10:30:15 +0100

# Missing fields default to the start of the period.
Time.new(2026) # => 2026-01-01 00:00:00 +0100
Time.local(2026, "mar", 5) # => 2026-03-05 00:00:00 +0100
Time.utc(2026, 12, 31, 23, 59, 59, 500_000) # => 2026-12-31 23:59:59.5 UTC

# Epoch seconds and fractions.
utc.to_i # => 1772703015
utc.to_f # => 1772703015.0
Time.at(1_772_703_015, 250, :millisecond, in: "UTC") # => 2026-03-05 09:30:15.25 UTC
Time.at(1_772_703_015.5, in: "UTC").subsec # => (1/2)

Source: Ruby 4.0 documentation: Time.new

The points worth remembering from this file:

  • A Time created from fields with no offset takes the local zone, which comes from the TZ environment variable (see below). Such a Time has a zone name ("CET"), while a Time created with an explicit offset such as "+09:00" has zone equal to nil: an offset is not a zone, it carries no rules and no name.

  • Time.utc produces a Time whose utc? is true and whose zone is "UTC". The offsets "Z" and "UTC" give the same result, and "-00:00" is parsed too (it means "UTC, offset unknown" in RFC 3339 and prints as -0000 with %-z).

  • Two Time objects are == when they are the same instant, whatever their offsets: Time.utc(2026, 3, 5, 9, 30, 15) equals Time.new(2026, 3, 5, 18, 30, 15, "+09:00"). The offset only changes how the instant is read.

  • Time.at(seconds, subsecond, unit) accepts :millisecond, :usec or :microsecond and :nsec or :nanosecond as the unit of the second number. Time.at(1_772_703_015.5) stores the fraction exactly as the Float represents it (see the pitfalls below).

  • A Time holds an exact number of seconds (an Integer or a Rational), not a Float, so it has no fixed resolution. usec, nsec and subsec read the fraction; Time.now itself is as precise as the operating system clock.

Time.new with a string (Ruby 3.2 and 3.3)

Time.new with a single string argument parses the format that Time#inspect and ISO 8601 print. Ruby 3.2 added the feature (Feature #18033), and Ruby 3.3 made it strict (Bug #19293): a string with no time part is an error instead of silently being read as a year. The in: keyword supplies an offset when the string has none, and precision: (default 9) limits the stored fraction digits.

# frozen_string_literal: true

ENV["TZ"] = "Europe/Madrid"

# Time.new with a string parses what Time#inspect and ISO 8601 print.
Time.new("2026-03-05 10:30:15") # => 2026-03-05 10:30:15 +0100
Time.new("2026-03-05 10:30:15 +09:00") # => 2026-03-05 10:30:15 +0900
Time.new("2026-03-05T10:30:15Z") # => 2026-03-05 10:30:15 UTC
Time.new("2026-03-05 10:30:15.125 UTC") # => 2026-03-05 10:30:15.125 UTC
Time.new("2026-03-05 10:30:15", in: "-03:00") # => 2026-03-05 10:30:15 -0300
Time.new("2026-03-05 10:30:15.123456789", precision: 3) # => 2026-03-05 10:30:15.123 +0100

# Since Ruby 3.3 the string form is strict.
begin
  Time.new("2026-03-05")
rescue ArgumentError => e
  e.message # => "no time information"
end

begin
  Time.new("2026-13-05 10:30:15")
rescue ArgumentError => e
  e.message # => "mon out of range"
end

# A string holding only a year is still the year argument.
Time.new("2026") # => 2026-01-01 00:00:00 +0100

Source: Ruby 4.0 documentation: Time.new

Two rules explain the last line: a string that is only digits is still the year argument, as it was before 3.2, while a string that contains a date separator must also contain a time. The strict form is the only parser in core. For dates without a time, or for formats that are not ISO 8601, use Time.strptime, Time.parse or Date (below).

Fields, arithmetic, comparison and rounding

A Time answers year, month (alias mon), day (alias mday), hour, min, sec, wday (0 is Sunday), yday, zone, utc_offset (alias gmt_offset and gmtoff), dst? (alias isdst) and the day-of-week predicates sunday? to saturday?. to_a returns the ten-element array [sec, min, hour, day, month, year, wday, yday, isdst, zone].

Arithmetic is in seconds. Time#+ adds a number of seconds and returns a Time with the receiver’s offset; Time#- with a number subtracts seconds, and with another Time returns the difference as a Float of seconds. Adding two times is a TypeError. Time includes Comparable, so <, >, between? and clamp work, and <=> returns nil against a non-Time. round, floor and ceil take the number of fraction digits.

# frozen_string_literal: true

ENV["TZ"] = "Europe/Madrid"

borrowed = Time.new(2026, 3, 5, 10, 30, 15.75, "+01:00")
returned = Time.new(2026, 3, 19, 18, 0, 0, "+01:00")

# Adding a number adds seconds; subtracting two Times gives a Float.
p borrowed + 60 # => 2026-03-05 10:31:15.75 +0100
p borrowed - 3600 # => 2026-03-05 09:30:15.75 +0100
p borrowed + 0.5 # => 2026-03-05 10:30:16.25 +0100
p borrowed + Rational(1, 3) # => 2026-03-05 10:30:16 1/12 +0100
p returned - borrowed # => 1236584.25
((returned - borrowed) / 86_400).floor # => 14
p borrowed - returned # => -1236584.25

# Comparable: ordering, between? and clamp.
p borrowed < returned # => true
borrowed.between?(borrowed, returned) # => true
p borrowed <=> returned # => -1
borrowed.clamp(returned, returned) # => 2026-03-19 18:00:00 +0100
[returned, borrowed].min # => 2026-03-05 10:30:15.75 +0100

# Fields.
borrowed.year # => 2026
borrowed.month # => 3
borrowed.day # => 5
borrowed.hour # => 10
borrowed.min # => 30
borrowed.sec # => 15
borrowed.wday # => 4
borrowed.yday # => 64
borrowed.thursday? # => true
borrowed.to_a # => [15, 30, 10, 5, 3, 2026, 4, 64, false, nil]

# Sub-second precision.
borrowed.usec # => 750000
borrowed.nsec # => 750000000
borrowed.subsec # => (3/4)
borrowed.to_r # => (7090812063/4)
borrowed.inspect # => "2026-03-05 10:30:15.75 +0100"
borrowed.to_s # => "2026-03-05 10:30:15 +0100"

# Rounding.
borrowed.round # => 2026-03-05 10:30:16 +0100
borrowed.floor # => 2026-03-05 10:30:15 +0100
borrowed.ceil # => 2026-03-05 10:30:16 +0100
borrowed.round(1) # => 2026-03-05 10:30:15.8 +0100

# Equality compares the instant and the exact fraction, never the offset.
p Time.at(0, in: "UTC") == Time.at(0, in: "+01:00") # => true
Time.at(0, in: "UTC").eql?(Time.at(0, in: "+01:00")) # => true
p Time.at(0.1) == Time.at(Rational(1, 10)) # => false
Time.at(0.1).subsec # => (3602879701896397/36028797018963968)
Time.at(Rational(1, 10)).subsec # => (1/10)

Source: Ruby 4.0 documentation: Time#-

Equality needs care. == and eql? compare the instant and the exact fraction and ignore the offset, so a Time can be used as a Hash key without normalizing its zone first. A Float such as 0.1 is not the rational one tenth, so Time.at(0.1) and Time.at(Rational(1, 10)) are different instants (their subsec is shown above). Prefer Integer or Rational when a fraction matters, and compare with a tolerance when the values came from floating point.

Time zones and offsets

Ruby’s core has two kinds of zone and one extension point.

  • An offset: a fixed number of seconds from UTC, written "+HH:MM", "-HH:MM", "+HHMM", "+HH", "UTC", "Z", a military letter "A" to "I" and "K" to "Z" (J is excluded), or an Integer number of seconds. The offset never changes. Time.zone_offset (from the time library) converts abbreviations such as "EST" to seconds, but a bare "EST" is not accepted as an offset argument.

  • The local zone: the zone the process runs in, with its daylight saving rules, taken from the TZ environment variable or the operating system. Time.now, Time.new without an offset, Time.local, getlocal and localtime without arguments use it. Its zone is an abbreviation such as "CET" or "CEST".

  • A timezone object: any object that follows the protocol described below. This is how an IANA database library plugs in.

Names such as "Europe/Madrid" are not accepted as an offset: Time.new(2026, 7, 1, 12, 0, 0, "Europe/Madrid") raises ArgumentError, and so does an offset out of range or a malformed one. getlocal and localtime return the same instant read in another offset; getutc / getgm and utc / gmtime read it in UTC. The methods without a get prefix change the receiver and the ones with it return a new Time, which matters for an object you share.

# frozen_string_literal: true

ENV["TZ"] = "Europe/Madrid"

due = Time.utc(2026, 7, 1, 12, 0, 0)

# Converting never changes the instant, only how it is shown.
due.getlocal # => 2026-07-01 14:00:00 +0200
due.getlocal("-05:00") # => 2026-07-01 07:00:00 -0500
due.getlocal(3600 * 9) # => 2026-07-01 21:00:00 +0900
due.getutc # => 2026-07-01 12:00:00 UTC
due.zone # => "UTC"
due.getlocal.zone # => "CEST"
due.getlocal.dst? # => true
Time.utc(2026, 1, 1).getlocal.dst? # => false
due.getlocal.utc_offset # => 7200
Time.utc(2026, 1, 1).getlocal.utc_offset # => 3600

# Single-letter military zones are accepted too.
Time.new(2026, 7, 1, 12, 0, 0, "A") # => 2026-07-01 12:00:00 +0100
Time.new(2026, 7, 1, 12, 0, 0, "Z") # => 2026-07-01 12:00:00 UTC

# A bad offset is an ArgumentError.
begin
  Time.new(2026, 7, 1, 12, 0, 0, "+25:00")
rescue ArgumentError => e
  e.message # => "utc_offset out of range"
end

begin
  Time.new(2026, 7, 1, 12, 0, 0, "Europe/Madrid")
rescue ArgumentError => e
  e.message # => "\"+HH:MM\", \"-HH:MM\", \"UTC\" or \"A\"..\"I\",\"K\"..\"Z\" expected for utc_offset: Europe/Madrid"
end

# utc and localtime change the receiver, getutc and getlocal return a copy.
stamp = Time.new(2026, 7, 1, 12, 0, 0, "+02:00")
stamp.utc # => 2026-07-01 10:00:00 UTC
stamp.utc? # => true
stamp.localtime # => 2026-07-01 12:00:00 +0200
stamp.utc? # => false

Source: Ruby 4.0 documentation: Time, timezone specifiers

The TZ environment variable

The local zone comes from the TZ environment variable, using the names of the operating system’s time zone database (Europe/Madrid, America/New_York, Asia/Tokyo, UTC), or from the system setting when TZ is unset. Assigning ENV["TZ"] inside a program takes effect immediately for the whole process, every thread included, which is why the examples on this page can set it, and why library code must not: change the zone for one computation with an offset or a zone object instead. In a minimal container the database is often missing, and local times then fall back to UTC; install tzdata in the image or pass an explicit zone.

Daylight saving transitions

Local time is not continuous. When the clocks spring forward, the wall-clock readings in the skipped hour do not exist, and when they fall back the readings in the repeated hour exist twice. Ruby resolves both without raising: a skipped reading is moved forward by the size of the gap, and an ambiguous reading is resolved to one of the two instants (here the later one, with offset +01:00). Because Time arithmetic is in absolute seconds, adding 86_400 to noon of the day before a transition does not give noon of the next day.

# frozen_string_literal: true

ENV["TZ"] = "Europe/Madrid"

# Spring forward: 02:30 on 29 March 2026 does not exist in Madrid.
Time.new(2026, 3, 29, 1, 59, 59) # => 2026-03-29 01:59:59 +0100
Time.new(2026, 3, 29, 2, 30, 0) # => 2026-03-29 03:30:00 +0200
Time.new(2026, 3, 29, 3, 0, 0) # => 2026-03-29 03:00:00 +0200
p Time.new(2026, 3, 29, 3, 0, 0) - Time.new(2026, 3, 29, 1, 59, 59) # => 1.0

# Fall back: 02:30 on 25 October 2026 happens twice. Ruby picks one reading.
ambiguous = Time.new(2026, 10, 25, 2, 30, 0)
p ambiguous # => 2026-10-25 02:30:00 +0100
ambiguous.dst? # => false
Time.new(2026, 10, 25, 2, 30, 0, in: "+02:00") # => 2026-10-25 02:30:00 +0200
p Time.new(2026, 10, 25, 2, 30, 0, in: "+01:00").to_i - Time.new(2026, 10, 25, 2, 30, 0, in: "+02:00").to_i # => 3600

# "Same wall clock tomorrow" is not "plus 86,400 seconds".
p Time.new(2026, 3, 28, 12, 0, 0) + 86_400 # => 2026-03-29 13:00:00 +0200
Time.new(2026, 3, 29, 12, 0, 0) # => 2026-03-29 12:00:00 +0200
p (Time.new(2026, 3, 29, 12, 0, 0) - Time.new(2026, 3, 28, 12, 0, 0)) / 3600 # => 23.0

Source: Ruby 4.0 documentation: Time#dst?

To be explicit about an ambiguous reading, give the offset (in: "+02:00" or in: "+01:00"); to add "a day" in the wall-clock sense, do the arithmetic on the calendar fields (convert to a Date, add, and build a new Time) or run the whole computation in UTC and convert at the edge.

Timezone objects

The seventh argument of Time.new, the in: keyword of Time.new, Time.at and Time.now, and the argument of getlocal and localtime also accept an object that implements the timezone protocol. Ruby asks the object to convert in both directions:

Method Contract

local_to_utc(local_time)

Receives a Time whose fields are the wall-clock reading in the zone, expressed as if they were UTC, and returns the UTC Time for it. Called by Time.new(fields, zone).

utc_to_local(utc_time)

Receives a UTC Time and returns the wall-clock fields in the zone, again as a Time that is read as if it were UTC. Called by Time.at, Time.now and getlocal.

abbr(time)

Optional. Time#zone returns the object itself and abbr supplies the text for %Z.

The tzinfo gem is the usual implementation of this protocol for IANA zones (TZInfo::Timezone.get("Europe/Madrid") works as the in: argument). The next example writes the smallest useful one, a fixed-offset zone with a name.

# frozen_string_literal: true

module Shelf
  # A fixed-offset zone object following the protocol Time expects of the
  # objects given as the zone argument or the in: keyword.
  class FixedZone
    attr_reader :name

    def initialize(name, offset_seconds)
      @name = name
      @offset = offset_seconds
    end

    # Receives a Time whose wall-clock fields are in this zone and returns the
    # same fields read as UTC.
    def local_to_utc(local)
      local - @offset
    end

    # Receives a Time in UTC and returns the wall-clock fields in this zone.
    def utc_to_local(utc)
      utc + @offset
    end

Reading the clock: wall clock versus monotonic clock

Time.now reads the wall clock: the clock that the operating system keeps in step with real-world time. It can jump forwards or backwards at any moment (NTP corrections, an administrator, a virtual machine resuming), so the difference between two Time.now readings can be negative or wrong. Process.clock_gettime(Process::CLOCK_MONOTONIC) reads a clock that only moves forward and is never adjusted, but whose starting point is arbitrary: the number means nothing alone and is only useful subtracted from another reading of the same clock. Use the monotonic clock for durations, timeouts and benchmarks, and Time.now for "what time is it".

Process.clock_gettime(clock_id, unit = :float_second) takes the clock constant and a unit: :float_second (the default), :float_millisecond, :float_microsecond, :second, :millisecond, :microsecond and :nanosecond. The common clocks are:

Constant Meaning

Process::CLOCK_MONOTONIC

Time since an unspecified point, never adjusted and never going backwards. Use it for elapsed time.

Process::CLOCK_REALTIME

The wall clock, as Time.now reads it, as a number.

Process::CLOCK_PROCESS_CPUTIME_ID

CPU time consumed by this process, not elapsed time. A sleep does not advance it.

Process::CLOCK_THREAD_CPUTIME_ID

CPU time consumed by the calling thread.

Which constants exist depends on the platform; a missing one raises Errno::EINVAL or is not defined, so keep to the first three unless you target a single operating system. Process.clock_getres(clock_id) returns the resolution of a clock.

    end

Date

require "date" defines Date, a calendar day identified by its Julian Day Number. A Date has no time of day, no zone and no daylight saving, which is exactly why it is the right type for a due date: "the 19th" is the 19th in every zone. Arithmetic is in days: Date#+ and Date#- with a number move by days, and Date#- with another Date returns the difference as a Rational number of days (call to_i for a whole number). The month and year operators are >> and << (add and subtract months, clamping to the last day of a shorter month), next_day, prev_day, next_month, prev_month, next_year and prev_year, each taking an optional count. Constructors accept negative day and month numbers that count from the end, so Date.new(2026, 3, -1) is the last day of March and Date.new(2026, -1, -1) the last day of the year. The validity checks are Date.valid_date?, valid_ordinal?, valid_commercial? and valid_jd?, and the constructors Date.civil (alias of new), Date.ordinal, Date.commercial (ISO week date) and Date.jd.

Parsing dates

Date.parse guesses the format; Date.strptime and Date.iso8601 (also rfc3339, rfc2822, httpdate, xmlschema and jisx0301) are exact. A guessed parse of an ambiguous numeric date is the classic data bug: 05/03/2026 is read as day/month, 03/05/2026 as 3 May, and nothing in the result tells you that. Since the date library 3.2.1 a string longer than 128 characters is refused before it is parsed, which closes a regular-expression denial-of-service hole; pass limit: nil for trusted long input (as the last line shows) or a larger integer. The calendar reform

Date models two calendars. The proleptic Julian calendar has a leap year every four years, and the Gregorian calendar skips the years divisible by 100 unless they are divisible by 400. The Gregorian reform of 1582 dropped ten days, and every Date has a start, the Julian Day Number of the first Gregorian day. Before it dates are read in the Julian calendar, from it on in the Gregorian one. The default start is Date::ITALY (15 October 1582), and the constants are Date::ENGLAND (14 September 1752, the British Empire and its colonies), Date::JULIAN (infinity: always Julian) and Date::GREGORIAN (minus infinity: always Gregorian). Choose the start only when you handle historical dates; for everything after 1752 the default is already correct.

# frozen_string_literal: true

require "date"

# The Gregorian reform: ten days vanished in Italy in October 1582.
Date.valid_date?(1582, 10, 4) # => true
Date.valid_date?(1582, 10, 10) # => false
Date.valid_date?(1582, 10, 15) # => true
(Date.new(1582, 10, 15) - Date.new(1582, 10, 4)).to_i # => 1
Date.new(1582, 10, 4).julian? # => true
Date.new(1582, 10, 15).gregorian? # => true
Date.new(1582, 10, 4).start # => 2299161.0

# The start argument chooses the reform date (ITALY is the default).
p Date::ITALY # => 2299161
p Date::ENGLAND # => 2361222
p Date::JULIAN # => Infinity
p Date::GREGORIAN # => -Infinity
Date.new(1752, 9, 14, Date::ENGLAND).to_s # => "1752-09-14"
Date.valid_date?(1752, 9, 10, Date::ENGLAND) # => false
Date.valid_date?(1752, 9, 10) # => true

# The proleptic calendars extend one rule over all of history.
Date.new(1500, 2, 29, Date::JULIAN).to_s # => "1500-02-29"
Date.valid_date?(1500, 2, 29, Date::GREGORIAN) # => false
Date.new(1500, 3, 1, Date::JULIAN).jd # => 2268993
Date.new(1500, 3, 1, Date::GREGORIAN).jd # => 2268983
Date.new(1500, 3, 1, Date::GREGORIAN).new_start(Date::JULIAN).to_s # => "1500-02-20"

Source: Ruby 4.0 documentation: Calendars

Dates before the reform are therefore not what a library that applies the Gregorian rules to all of history (the ISO calendar of java.time, for example) gives for the same year, month and day, and Date.valid_date?(1582, 10, 10) is false although that day exists in the proleptic Gregorian calendar. Date#new_start, Date#italy, Date#england, Date#julian and Date#gregorian return the same day read under a different reform setting, and Date#julian? and Date#gregorian? report which reading applies.

Why DateTime is deprecated

DateTime is a Date subclass that adds a time of day and a fixed offset, and the official documentation states: "DateTime class is considered deprecated. Use Time class." Its zone support is a fixed offset with no daylight saving rules, its arithmetic mixes days and fractions of a day as Rational numbers, and its parsing and strftime duplicate those of Time. The date library keeps it for backward compatibility, and RuboCop has a Style/DateTime cop for it (disabled by default). New code, and examples older than Ruby 2.x that use it, should use Time instead:

Old DateTime code Replacement

DateTime.now

Time.now

DateTime.new(2026, 3, 5, 10, 30, 0, "+01:00")

Time.new(2026, 3, 5, 10, 30, 0, "+01:00")

DateTime.parse(string)

Time.iso8601(string), Time.strptime(string, format) or Time.parse(string) (require "time")

time.to_date

date.to_datetime

date.to_time (local midnight) or Time.utc(date.year, date.month, date.day)

The only legitimate use left is reading old data: Time#to_datetime and Date#to_datetime exist to hand a value to an API that still demands a DateTime.

Time values in pattern matching and ranges

Since Ruby 3.2, Time#deconstruct_keys and Date#deconstruct_keys (Feature #19071) let time values appear in case/in patterns. Time offers year, month, day, yday, wday, hour, min, sec, subsec, dst and zone; Date offers year, month, day, yday, wday (and DateTime adds the time fields). Passing a key array asks for only those keys. Neither class implements deconstruct, so there is no array pattern. Since Ruby 3.4 a range whose begin is a Time can be stepped with a number of seconds, and an endless range steps forever (take a bounded number).

# frozen_string_literal: true

require "date"

ENV["TZ"] = "Europe/Madrid"

t = Time.new(2026, 3, 19, 18, 0, 0, "+01:00")

# Time#deconstruct_keys and Date#deconstruct_keys (Ruby 3.2).
t.deconstruct_keys(nil).keys # => [:year, :month, :day, :yday, :wday, :hour, :min, :sec, :subsec, :dst, :zone]
t.deconstruct_keys(%i[year month]) # => {year: 2026, month: 3}
Date.new(2026, 3, 19).deconstruct_keys(%i[year wday yday]) # => {year: 2026, wday: 4, yday: 78}

def office_hours(time)
  case time
  in { wday: 6 | 0 } then "closed at the weekend"
  in { hour: 9...18 } then "open"
  in { hour: } then "closed at #{hour}:00"
  end
end

office_hours(Time.new(2026, 3, 21, 10)) # => "closed at the weekend"
office_hours(Time.new(2026, 3, 19, 10)) # => "open"
office_hours(t) # => "closed at 18:00"

# A Time range steps by seconds (Ruby 3.4).
(Time.utc(2026, 3, 19)..).step(86_400).take(3).map(&:day) # => [19, 20, 21]
(Time.utc(2026, 3, 19)..Time.utc(2026, 3, 19, 0, 0, 2)).step(1).map(&:sec) # => [0, 1, 2]

# A Time range can still be tested but not iterated with each.
(Time.utc(2026, 3, 19)..Time.utc(2026, 3, 20)).cover?(Time.utc(2026, 3, 19, 12)) # => true

begin
  (Time.utc(2026, 3, 19)..Time.utc(2026, 3, 20)).each { it }
rescue TypeError => e
  e.message # => "can't iterate from Time"
end

Source: Ruby 4.0 documentation: Time#deconstruct_keys

A range of Time values is a legitimate way to express "between these two instants": cover? and === (so case and when) work, and step works since 3.4. each does not, because Time has no succ, and the error reads "can’t iterate from Time". See Ranges and Pattern Matching.

Injecting a clock

Code that calls Time.now or Date.today directly cannot be tested without waiting or stubbing a global. The clean alternative is the dependency-injection idiom: take a callable (a lambda, a Proc, or any object that answers call) as a keyword argument whose default is the real clock, and let tests pass a frozen one. Shelf::LendingPolicy below uses it to compute the due date, whether a loan is overdue, and the fine, and it shows the main design rule for dates: a due date is a Date, derived from the instant of the loan with Time#to_date, and the comparison with today is made between dates, so the time of day does not matter.

# frozen_string_literal: true

require "date"

ENV["TZ"] = "Europe/Madrid"

module Shelf
  # Lending rules. The clock is injected, so tests never need to stub Time.now.
  class LendingPolicy
    LOAN_DAYS = 14
    FINE_CENTS_PER_DAY = 25

    def initialize(clock: -> { Time.now })
      @clock = clock
    end

    # A due date is a calendar date: the library is open until closing time.
    def due_on(borrowed_at) = borrowed_at.to_date + LOAN_DAYS

    def overdue?(borrowed_at) = today > due_on(borrowed_at)

    def fine_cents(borrowed_at)
      days_late = (today - due_on(borrowed_at)).to_i
      days_late.positive? ? days_late * FINE_CENTS_PER_DAY : 0
    end

    private

    def today = @clock.call.to_date
  end
end

borrowed_at = Time.new(2026, 3, 5, 10, 30, 0)
frozen_clock = ->(time) { -> { time } }

on_time = Shelf::LendingPolicy.new(clock: frozen_clock.call(Time.new(2026, 3, 19, 23, 59, 59)))
on_time.due_on(borrowed_at).to_s # => "2026-03-19"
on_time.overdue?(borrowed_at) # => false
on_time.fine_cents(borrowed_at) # => 0

late = Shelf::LendingPolicy.new(clock: frozen_clock.call(Time.new(2026, 3, 24, 8, 0, 0)))
late.overdue?(borrowed_at) # => true
late.fine_cents(borrowed_at) # => 125

# The default clock is the real one.
Shelf::LendingPolicy.new.overdue?(Time.now) # => false

Source: Ruby 4.0 documentation: Time#to_date

Stubbing Time.now with a test double is the alternative, and gems such as Timecop and ActiveSupport::Testing::TimeHelpers (travel_to) do it for you. They work by replacing the global, so they leak between threads and break tests that run in parallel, and they cannot see calls to Process.clock_gettime. Stubbing in each framework is covered in Testing with Minitest and RSpec and Test Doubles. Never make an assertion on elapsed wall-clock time in CI; a loaded machine fails it intermittently. sleep in a test is a smell for the same reason.

Serialization

JSON has no time type. With the json library a Time is written through its to_s (not ISO 8601), and a Date through to_s, which happens to be ISO 8601. Neither is read back as a Time or a Date: JSON.parse returns strings, so the schema (or your own code) has to convert them. Write iso8601 explicitly, with fraction digits if you need them, and parse with Time.iso8601. Marshal is the one format that round-trips every property of a Time (instant, offset and fraction), but it is Ruby-only and must never read untrusted input. YAML stores both classes as timestamps, but YAML.safe_load refuses them until the classes are permitted, which is the right default.

# frozen_string_literal: true

require "date"
require "json"
require "time"
require "yaml"

ENV["TZ"] = "Europe/Madrid"

stamp = Time.new(2026, 3, 5, 9, 4, 7.5r, "+01:00")

# JSON has no time type: Time and Date are written as strings.
JSON.generate({ at: stamp }) # => "{\"at\":\"2026-03-05 09:04:07 +0100\"}"
JSON.generate({ due_on: Date.new(2026, 3, 19) }) # => "{\"due_on\":\"2026-03-19\"}"
JSON.generate({ borrowed_at: stamp.iso8601(3) }) # => "{\"borrowed_at\":\"2026-03-05T09:04:07.500+01:00\"}"
Time.iso8601(JSON.parse(JSON.generate({ at: stamp.iso8601(3) }))["at"]).inspect # => "2026-03-05 09:04:07.5 +0100"

# Marshal keeps the instant, the offset and the fraction.
copy = Marshal.load(Marshal.dump(stamp))
copy.inspect # => "2026-03-05 09:04:07.5 +0100"
p copy == stamp # => true
p copy.utc_offset # => 3600

# YAML needs the classes allowed when loading safely.
yaml = YAML.dump({ "due_on" => Date.new(2026, 3, 19), "at" => stamp.getutc })
p yaml # => "---\ndue_on: 2026-03-19\nat: 2026-03-05 08:04:07.500000000 Z\n"

begin
  YAML.safe_load(yaml)
rescue Psych::DisallowedClass => e
  e.message # => "Tried to load unspecified class: Date"
end

YAML.safe_load(yaml, permitted_classes: [Date, Time]).values.map(&:to_s) # => ["2026-03-19", "2026-03-05 08:04:07 UTC"]

Source: Ruby 4.0 documentation: Time#xmlschema

More formats (CSV, MessagePack, and the security aspects of Marshal and YAML) are in Serialization: JSON, YAML, CSV and Marshal.

Recommended practice

  • Store and transmit instants in UTC (or with an explicit offset) as ISO 8601 strings or epoch integers; convert to a local zone only to display. Store the IANA zone name ("Europe/Madrid") next to the instant when the user’s wall-clock intent matters, for example for a recurring meeting at "10:00 local", because an offset alone cannot tell you what the clock will read after the next transition.

  • Use Date for values that are days, Time for values that are instants, and Process.clock_gettime(Process::CLOCK_MONOTONIC) for durations. Do not use DateTime.

  • Do not change ENV["TZ"] in library code, and do not rely on the machine’s zone for data that crosses machines; write the offset.

  • Parse with Time.iso8601, Time.strptime, Date.iso8601 or Date.strptime at boundaries, and let Time.parse and Date.parse stay in scripts.

  • Inject the clock (a callable that returns a Time) and take the zone as a parameter instead of reading globals inside business logic.

  • Keep Rational or Integer for sub-second values that must be exact, and compare floats of seconds with a tolerance.

  • Prefer a Date range or Date#step to loops with + 1 on a Time, which drift across daylight saving transitions.

  • RuboCop’s Style/TimeNow (pending, enabled with NewCops: enable) prefers Time.now to Time.new with no arguments, Lint/Void flags an operator expression whose result is ignored, and Style/DateTime can be enabled to ban DateTime.

Common mistakes

Mistake What to do instead

Timing code with Time.now - start

Use Process.clock_gettime(Process::CLOCK_MONOTONIC), or Benchmark.realtime. The wall clock can jump.

Using Time.now + 86400 for "tomorrow"

The result is 25 or 23 hours later in wall-clock terms across a daylight saving change. Add days to a Date or compute in UTC.

Calling Time.iso8601 or Time.parse without require "time"

require "time". The instance method Time#iso8601 needs no require since Ruby 3.4, but the parsers always do.

Parsing Time.parse("05/03/2026") or Date.parse("05/03/2026")

They read day/month, silently. Use strptime with an explicit format.

Relying on TZ of the host

Write the offset in the data, or pass an explicit zone. TZ differs between laptops, CI and containers.

Treating Time.new(2026, 2, 30) as an error

It rolls over to 2 March. Check with Date.valid_date? first, or use Date.new, which raises Date::Error.

Storing a Float of epoch seconds

Use Integer seconds (or Rational/nanoseconds). A Float has about 15-16 significant digits and loses nanoseconds; Time.at(1_772_703_015.123456789).nsec is 123456716.

Assuming a Time is a calendar day

Compare days with Date (or call to_date on both sides). A Time is never == to a Date.

Changing ENV["TZ"] to format one value

Use getlocal(offset) or a zone object. ENV["TZ"] is process-wide and not thread-safe in effect.

Using DateTime

Use Time. See the replacement table above.

Version notes

Ruby Change

3.1

Time.new, Time.at and Time.now accept in: for the zone. Time.new converts string components to integers more strictly. %-z renders -0000 for unknown offsets.

3.2

Time.new(string) parses Time#inspect and ISO 8601 style strings. Time#deconstruct_keys, Date#deconstruct_keys and DateTime#deconstruct_keys support pattern matching.

Time.new(string) is stricter: a string without a time part, like "2023-12-20", raises ArgumentError ("no time information").

4.0
