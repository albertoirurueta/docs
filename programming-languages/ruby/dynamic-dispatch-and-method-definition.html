Dynamic Dispatch and Method Definition

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Ruby 4.0 (4.0.7, checked on 2026-10-18); features newer than Ruby 3.0 name the version that introduced them. Ruby has no separate mechanism for "calling a function by name" or "adding a member at run time". Both are ordinary method calls: an object receives a message, the interpreter looks the name up, and the answer can be changed while the program runs. This page is the toolbox for doing that deliberately: calling a method whose name is only known at run time (send, public_send, Method objects), defining methods and constants from data (define_method, define_singleton_method, const_set, Class.new, Module.new), answering messages that have no method at all (method_missing and respond_to_missing?), and the judgement about when any of it is worth the cost.

The rules that decide which method runs are in Method Lookup and super, and the hooks that fire when a method, a class or a constant appears (inherited, method_added, const_added), together with instance_eval, class_eval and string eval, are in Hooks, eval and DSLs. The reflection API that lists what exists is in Reflection, Introspection and Tracing. The definition syntax is in Methods and Parameters, visibility in Visibility and Encapsulation, singleton classes in Singleton Classes and Class-Level Behavior, and blocks, which supply the bodies of most generated methods, in Blocks, Procs and Lambdas. Replacing behaviour on existing classes, safely or not, is Refinements and Monkey Patching. For the same ideas in other languages: Go resolves methods statically and offers only its reflection package for run-time access, and Rust macros generate code at compile time instead of run time.

Every example on this page was syntax-checked with ruby -wc, run with ruby -w on Ruby 4.0.7 (and re-run on 3.4 and 3.3 where a version note says so) and linted with RuboCop 1.92 using the configuration of the running shelf gem (target Ruby 4.0, double-quoted strings, the documentation and one-class-per-file cops switched off). The output shown in # => comments and in the output blocks is the real output. The examples reuse the shelf library catalogue used throughout this section (Shelf, Book, Isbn, Loan, Catalog, Store::Memory); each file is self-contained and assumes the gem’s lib directory is on the load path (ruby -I lib example.rb; see the shelf gem source). Where a file defines its own helper classes they live in the Shelf namespace so that the output reads like the real library.

Dispatch is a message send

catalog.add(book) does not "call a function". It sends the message add with one argument to the object catalog; the object’s class (and its ancestors) decide what to do. Everything else on this page is a consequence of that sentence: if the message name is just data, it can come from a variable; if the lookup table is just data, it can be changed; and if the lookup fails, the object gets a last chance to respond.

flowchart TD A["receiver.name(args, block)"] --> B{"Method named name in the singleton class, class or ancestors?"} B -- yes --> C{"Visibility allows this call site?"} C -- yes --> D["Run the method"] C -- "no: private or protected" --> F["method_missing(name, ...)"] B -- no --> F F --> G{"method_missing overridden?"} G -- "yes, and it handles name" --> H["Ghost method result"] G -- "yes, but it calls super" --> I["BasicObject#method_missing"] G -- no --> I I --> J["raise NoMethodError, or NameError for a bare identifier"]

The diagram has two details worth remembering. A call that violates visibility (a private method with an explicit receiver) is also routed to method_missing, so a catch-all method_missing swallows visibility errors, and the final error depends on how the call was written: NoMethodError for receiver.name, NameError for a bare name that could have been a local variable. Both are shown with their real messages below.

Calling a method by name

send, __send__ and public_send

Three methods take the name of a method (a Symbol, or a String that is converted to one) followed by the arguments, keyword arguments and block for that method:

Call Visibility Notes

object.send(name, *args, &block)

Ignores it: private and protected methods run

Defined on Object (through Kernel). A class may define its own send (a socket or a mail object does), which then hides this one.

object.__send__(name, *args, &block)

Ignores it

Defined on BasicObject, so it works on blank-slate proxies, and by convention is never overridden. Use it when the receiver might define send.

object.public_send(name, *args, &block)

Respects it: private and protected methods raise NoMethodError

The right default whenever the name comes from outside the object that is calling.

The Symbol or String is checked: nil or an Integer raises TypeError ("nil is not a symbol nor a string"), and a call with no argument at all raises ArgumentError ("no method name given"). Operators and setters are methods with ordinary names (:+, :[], :loan_days=), so they can be sent too. Symbol#to_proc (&:name) behaves like public_send: [object].map(&:private_method) raises NoMethodError for a private method.

# frozen_string_literal: true

require "shelf"

# A reservation desk with one public, one protected and one private method.
class Desk
  def open? = true

  def priority(other) = other.score <=> score

  protected

  def score = 10

  private

  def key_box = "keys"

  def respond(name) = "responding to #{name}"
end

desk = Desk.new
name = :open?

desk.send(:open?) # => true
desk.public_send(name) # => true
desk.send(:key_box) # => "keys"
desk.__send__(:key_box) # => "keys"
desk.send(:respond, :bell) # => "responding to bell"

def message_of
  yield
rescue StandardError => e
  e.message
end

# public_send honours visibility; send does not.
%i[key_box score nope].each { |hidden| puts(message_of { desk.public_send(hidden) }) }
message_of { desk.key_box } # => "private method 'key_box' called for an instance of Desk"
desk.priority(Desk.new) # => 0

# Operators and setters are methods too, so they can be sent.
operator = :+
1.send(operator, 2) # => 3
Shelf::Config.new.send(:loan_days=, 21) # => 21

# A class that defines its own `send` hides Object#send, but __send__ stays reachable.
class Postman
  def send(*) = "letter sent"
end

Postman.new.send(:anything) # => "letter sent"
Postman.new.__send__(:class) # => Postman

# Bare send with no arguments is an ArgumentError.
message_of { desk.send } # => "no method name given"

Output:

private method 'key_box' called for an instance of Desk
protected method 'score' called for an instance of Desk
undefined method 'nope' for an instance of Desk

Source: Object#send, BasicObject#__send__ and Object#public_send

send and __send__ reach the private key_box and respond; public_send reports the visibility of each method in the error message (the same text the ordinary call desk.key_box produces). The Postman class shows why __send__ exists: a class that defines its own send method breaks every caller that relied on the generic one, while __send__ and public_send are still there.

Three practical rules follow:

  • Prefer a plain call when the name is known when you write the code. desk.open? says what it does; desk.send(:open?) only adds noise, and RuboCop’s Style/SendWithLiteralMethodName flags it (for public_send; Style/Send, which asks for __send__ instead of send, is disabled by default).

  • Use public_send when the name is data, and send only when bypassing visibility is the point: tests of private methods, framework code that calls hooks such as initialize_copy, and serialisation.

  • Do not build the name from untrusted input without a filter (next section).

Names from untrusted input

public_send stops private methods, but it does not make a name safe. Every public method of the receiver is reachable, including the ones that change or expose state: freeze, instance_variable_set, instance_variable_get, extend, instance_eval, define_singleton_method and, on a Class, class_eval and const_set. (String eval is a separate danger covered in Hooks, eval and DSLs, and Security collects the injection patterns.) The remedy is an allow-list: check the name against a fixed set before sending.

# frozen_string_literal: true

require "shelf"

module Shelf
  # Runs a command typed by a user, but only if it is on the allow-list.
  class Commands
    ALLOWED = %i[count first to_a].freeze

    def initialize(catalog)
      @catalog = catalog
    end

    def run(name)
      command = name.to_sym
      raise ArgumentError, "unknown command: #{name}" unless ALLOWED.include?(command)

      @catalog.public_send(command)
    end
  end
end

isbn = Shelf::Isbn.new(digits: "978-0-306-40615-7")
book = Shelf::Book.new(isbn:, title: "Dune", author: Shelf::Author.new(name: "Frank Herbert"))
catalog = Shelf::Catalog.new(store: Shelf::Store::Memory.new).add(book)
commands = Shelf::Commands.new(catalog)

commands.run("count") # => 1
commands.run(:first).title # => "Dune"

def message_of
  yield
rescue StandardError => e
  "#{e.class}: #{e.message}"
end

message_of { commands.run("freeze") } # => "ArgumentError: unknown command: freeze"
message_of { commands.run("instance_variable_get") } # => "ArgumentError: unknown command: instance_variable_get"

# Without the allow-list, public_send still reaches every public method, not just the ones you had in mind.
untrusted = "freeze"
catalog.public_send(untrusted).frozen? # => true
message_of { catalog.instance_variable_set(:@store, nil) }[/\AFrozenError/] # => "FrozenError"
catalog.add(book).count # => 2

Source: Object#public_send and Object#freeze

The ALLOWED list is a frozen Array of Symbols, and the check happens before the dispatch. The last lines show what an unfiltered public_send would allow: the catalogue was frozen by a string that arrived from "outside", and instance_variable_set then fails with FrozenError. The freeze is shallow, so the catalogue still accepts new books because the store inside it is a separate, unfrozen object (see Object Lifecycle, Freezing and Copying). A hash of Symbols to Method objects or lambdas, shown at the end of the next section, is an even tighter allow-list because it contains the callables themselves, not names to look up.

Converting input to a Symbol with to_sym is safe on every supported Ruby: Symbols created from strings are garbage-collected, so the old advice to avoid to_sym on user input for memory reasons no longer applies. The remaining reason to filter is what the name can do.

respond_to?, Method objects and dispatch tables

object.respond_to?(name) answers whether a call from outside would be accepted. It returns true for public methods, false for private and protected ones (pass true as the second argument, include_all, to include them), and it consults respond_to_missing?, which is how ghost methods announce themselves (see Ghost methods with method_missing). The name may be a Symbol or a String; anything else raises TypeError. Prefer respond_to? over is_a? when you care about capability rather than ancestry: it is the duck-typing check.

When a method is going to be called more than once, or passed around, capture it as an object. object.method(:name) returns a Method bound to its receiver; Module#instance_method(:name) returns an UnboundMethod that is not tied to one object. Both are inspectable (owner, receiver, name, original_name, arity, parameters, source_location, super_method) and callable.

API What it does

object.method(:name)

The Method for a public, protected or private method (or a ghost method vouched for by respond_to_missing?). Raises NameError if there is none.

object.public_method(:name)

The same, but only for public methods.

object.singleton_method(:name)

Only methods defined directly on the object’s singleton class.

Method#call, method.(args), Method#[], Method#===

Invoke it. === makes a Method usable as a case branch.

Method#to_proc

A lambda that calls the method. This is what &object.method(:name) passes.

Method#unbind, Module#instance_method

An UnboundMethod. It cannot be called until bound.

UnboundMethod#bind(object), UnboundMethod#bind_call(object, *args)

Attach it to an object of the right class (bind_call binds and calls in one step). Binding to an object of another class raises TypeError.

Method#owner, Method#receiver, Method#name, Method#original_name

Where the method was found, what it is bound to, and both its name and the name it was defined with (they differ after alias).

 
# frozen_string_literal: true

require "shelf"

isbn = Shelf::Isbn.new(digits: "978-0-306-40615-7")
book = Shelf::Book.new(isbn:, title: "Dune", author: Shelf::Author.new(name: "Frank Herbert"))
catalog = Shelf::Catalog.new(store: Shelf::Store::Memory.new).add(book)

# respond_to? asks "would this call be accepted from outside?"
catalog.respond_to?(:add) # => true
catalog.respond_to?(:map) # => true
catalog.respond_to?(:remove) # => false
catalog.respond_to?(:puts) # => false
catalog.respond_to?(:puts, true) # => true

# Strings work as well as Symbols; anything else is a TypeError.
catalog.respond_to?("add") # => true

# Method objects capture a method together with its receiver.
adder = catalog.method(:add)
adder.owner # => Shelf::Catalog
adder.receiver.equal?(catalog) # => true
adder.arity # => 1
adder.parameters # => [[:req, :book]]
adder.name # => :add
adder.source_location&.last # => 13
adder.call(book).equal?(catalog) # => true

# Method#to_proc lets a method stand in for a block.
%w[978-0-306-40615-7 9780306406157].map(&Shelf::Isbn.method(:new))
# => [#<data Shelf::Isbn digits="9780306406157">, #<data Shelf::Isbn digits="9780306406157">]

# Unbound methods are detached from a receiver and can be rebound to compatible ones.
size = Array.instance_method(:size)
size.bind_call([1, 2, 3]) # => 3
size.owner # => Array

# public_method refuses non-public methods; method does not.
catalog.public_method(:add).call(book).class # => Shelf::Catalog
catalog.method(:puts).owner # => Kernel

# A dispatch table maps names to callables instead of calling send on user input.
shelf = Shelf::Catalog.new(store: Shelf::Store::Memory.new).add(book)
handlers = { count: shelf.method(:count), first: shelf.method(:first) }
handlers.fetch(:count).call # => 1
handlers.fetch(:first).call.title # => "Dune"

Source: Object#respond_to?, Object#method, Method and UnboundMethod#bind_call

catalog.respond_to?(:puts) is false because puts is a private Kernel method, and true once include_all is passed. catalog.method(:puts) succeeds regardless, because method ignores visibility; public_method would raise NameError ("method 'puts' for class 'Object' is private" for an Object). The Shelf::Isbn.method(:new) object passed with & turns a class method into a block, a compact alternative to map { |digits| Shelf::Isbn.new(digits:) } when the arguments line up. The final dispatch table maps Symbols to bound methods: the caller can only trigger what the table contains, and a missing key raises KeyError from fetch instead of calling something unintended.

Defining methods at run time

define_method

Module#define_method(name, body) defines an instance method on the receiver (a class or module) and returns the name as a Symbol. The body is either a block or a Proc, Method or UnboundMethod passed as the second argument. It is public, so Shelf::Loan.define_method(:x) { } works from outside the class; older code that wrote send(:define_method, ...) can drop the send. The name may be a Symbol or a String.

# frozen_string_literal: true

require "shelf"

module Shelf
  # A loan with one generated predicate per state and a few other generated methods.
  class TrackedLoan < Loan
    # One predicate per state: available?, lent?, overdue? and returned?.
    STATES.each do |name|
      define_method(:"#{name}?") { state == name }
    end

    # The block closes over a local variable that a plain def could never see.
    renewals = 0
    define_method(:renew) do |days = 7, reason: "none", &log|
      renewals += 1
      log&.call("renewed #{days} days (#{reason}), total #{renewals}")
      days
    end

    # Generated methods can be made private like any other.
    define_method(:audit_trail) { "#{book.title}: #{state}" }
    private :audit_trail

    # A Method or UnboundMethod can be reused under a second name.
    define_method(:status, instance_method(:describe))

    # A generated method can call super, but only with explicit arguments.
    define_method(:describe) { "[tracked] #{super()}" }
  end
end

isbn = Shelf::Isbn.new(digits: "978-0-306-40615-7")
book = Shelf::Book.new(isbn:, title: "Dune", author: Shelf::Author.new(name: "Frank Herbert"))
loan = Shelf::TrackedLoan.new(book, state: :lent)

loan.lent? # => true
loan.available? # => false
Shelf::TrackedLoan.public_instance_methods(false).sort
# => [:available?, :describe, :lent?, :overdue?, :renew, :returned?, :status]

# Parameters behave like those of a lambda: arity is checked, defaults and keywords work.
loan.renew # => 7
loan.renew(14, reason: "holiday") { |entry| puts entry } # => 14
Shelf::TrackedLoan.instance_method(:renew).parameters
# => [[:opt, :days], [:key, :reason], [:block, :log]]
Shelf::TrackedLoan.instance_method(:renew).arity # => -1

# Visibility: audit_trail is private, so only an implicit receiver reaches it.
Shelf::TrackedLoan.private_instance_methods(false) # => [:audit_trail]
loan.send(:audit_trail) # => "Dune: lent"

# status is the original describe; describe was redefined to wrap it.
loan.status # => "Dune is lent"
loan.describe # => "[tracked] Dune is lent"

# define_method returns the name as a Symbol, and accepts a String name too.
Shelf::TrackedLoan.define_method("extra") { :extra } # => :extra
loan.extra # => :extra

def message_of
  yield
rescue StandardError => e
  "#{e.class}: #{e.message}"
end

message_of { loan.audit_trail } # => "NoMethodError: private method 'audit_trail' called for an instance of Shelf::TrackedLoan"
message_of { loan.lent?(1) } # => "ArgumentError: wrong number of arguments (given 1, expected 0)"

# Bare super is not allowed inside define_method.
class LazyLoan < Shelf::Loan
  define_method(:describe) { super }
end

lazy = LazyLoan.new(book)
message_of { lazy.describe }[/implicit argument passing of super/] # => "implicit argument passing of super"

Output:

renewed 14 days (holiday), total 2

Source: Module#define_method, Module#instance_method and Module#private

What the example shows, and the rules behind it:

  • The block is a closure. renewals is a local variable of the class body, and every generated renew shares it. A def starts a new scope and could not see it. That makes define_method the tool for methods that need data captured at definition time (the name in each predicate, a counter, a lookup table).

  • self is the receiver. Inside the block self is the instance the method was called on (the documentation says the block is evaluated with instance_eval), so state, book and private helpers are reachable without a receiver.

  • Parameters are those of a lambda. Even when the body is a Proc created with proc { |a, b| }, the generated method checks arity: loan.lent?(1) raises ArgumentError. Optional, keyword and block parameters (|days = 7, reason: "none", &log|) all work, and Method#parameters and arity report them like any other method.

  • return leaves the method. In an ordinary block return would return from the method that wrote the block; in a define_method body it returns from the generated method.

  • Visibility follows the scope. Called directly in a class body after private, define_method creates a private method, and the same holds in a block run from the class body (such as STATES.each). Called with an explicit receiver (Shelf::TrackedLoan.define_method(:extra)) or from inside a method, the new method is public. It also returns its name, so private define_method(:x) { } works, although RuboCop’s Style/AccessModifierDeclarations prefers the separate private :x line used above.

  • Bare super is rejected. Inside a generated method super must be written with explicit arguments, super() or super(book). A bare super raises RuntimeError ("implicit argument passing of super from method defined by define_method() is not supported"). The same applies to methods defined with define_singleton_method.

  • Another method’s body can be reused. define_method(:status, instance_method(:describe)) copies the method under a second name, which is also how a method is wrapped: capture the old one with instance_method, then define a new one that calls old.bind_call(self, ...). Method-lookup-based wrapping with prepend is usually cleaner and is covered in Method Lookup and super. An UnboundMethod can only be reused on a class that is compatible with its owner.

  • The error location is the block. The backtrace of an ArgumentError raised for a wrong call shows block in <class:TrackedLoan>, and source_location points at the define_method call, not at the line where the name was computed. Generated code is harder to debug, a point returned to in When to metaprogram.

The main (top-level) object also responds to define_method: on Ruby 3.3, 3.4 and 4.0 a top-level define_method(:name) { } defines a public method on Object (unlike a top-level def, which defines a private one), so every object in the program, including nil, would respond to it. Define methods on a module of your own instead.

define_singleton_method, extend and the singleton class

A method defined for one object only lives in that object’s singleton class. define_singleton_method(name, body) is the shorthand for object.singleton_class.define_method(name, body) (a public method). extend(Module) is the way to add a whole module to a single object; it is the mechanism behind many small DSLs, where a plain object is extended with the methods the DSL block needs. The singleton class, class methods and class << self are explained in Singleton Classes and Class-Level Behavior.

# frozen_string_literal: true

require "shelf"

isbn = Shelf::Isbn.new(digits: "978-0-306-40615-7")
book = Shelf::Book.new(isbn:, title: "Dune", author: Shelf::Author.new(name: "Frank Herbert"))
loan = Shelf::Loan.new(book, state: :lent)
other = Shelf::Loan.new(book)

# define_singleton_method adds a method to one object only (its singleton class).
loan.define_singleton_method(:late_fee) { |days_late, rate: 10| days_late * rate } # => :late_fee
loan.late_fee(3) # => 30
loan.late_fee(3, rate: 25) # => 75
loan.singleton_methods # => [:late_fee]
other.respond_to?(:late_fee) # => false

Instance variables by name

instance_variable_get(name), instance_variable_set(name, value), instance_variable_defined?(name), instance_variables and remove_instance_variable(name) read and write state without going through accessors. The name must look like an instance variable (@state, a Symbol or a String) or NameError is raised ("'state' is not allowed as an instance variable name"). Aliasing, removing and undefining

Methods can also be renamed or taken away at run time. These are the reflective counterparts of the alias and undef keywords, and unlike the keywords they accept computed names:

Method Effect

Module#alias_method(new, old)

Makes new another name for old and returns new as a Symbol (Ruby 3.0; it returned the class before). Method#original_name still reports old. Inside a class body RuboCop’s Style/Alias prefers the alias new old keyword for literal names.

Module#remove_method(name)

Deletes this class’s own definition, so lookup falls through to the superclass or to an included module. Raises NameError if the class does not define it itself.

Module#undef_method(name)

Blocks the name entirely: even an inherited definition is hidden, and a call raises NoMethodError. Module#undefined_instance_methods (Ruby 3.2) lists what was blocked this way in a class.

Module#public_instance_method(name)

Like instance_method but only for public methods.

Module#method_defined?(name), public_method_defined?, private_method_defined?, protected_method_defined?

Whether the module has a method of that name, inherited ones included. method_defined? answers for public and protected methods and ignores private ones; the other three answer for exactly their own visibility.

Attribute macros and documenting generated methods

The standard family of method generators is attr_reader, attr_writer, attr_accessor (and attr). They are ordinary methods on Module that call the equivalent of define_method, and since Ruby 3.0 they return an Array of the Symbols they defined, so private attr_reader :book works (and private attr_accessor :a, :b privatises all of the generated methods). A class-level macro of your own follows the same shape: a method on the class’s singleton that calls define_method for each name it is given. Putting the macro in a module that classes extend keeps it reusable.

# frozen_string_literal: true

require "shelf"

module Shelf
  # A class-level macro that generates a reader and a writer, with their documentation.
  module Attributes
    # Declares a readable and writable attribute.
    #
    # @!macro [attach] attribute
    #   @!method $1
    #     Returns the +$1+ attribute, or its default.
    #     @return [Object]
    #   @!method $1=(value)
    #     Sets the +$1+ attribute.
    #     @param value [Object]
    #     @return [Object]
    # @param name [Symbol] the attribute name
    # @param default [Object] returned while nothing has been set
    # @return [Symbol] the attribute name
    def attribute(name, default: nil)
      variable = :"@#{name}"
      define_method(name) do
        instance_variable_defined?(variable) ? instance_variable_get(variable) : default
      end
      define_method(:"#{name}=") { |value| instance_variable_set(variable, value) }
      (@attributes ||= []) << name
      name
    end

    # @return [Array<Symbol>] the attribute names declared on this class
    def attributes = (@attributes || []).dup
  end

  # A library member who can borrow books.
  class Member
    extend Attributes

    attribute :name
    attribute :max_loans, default: 3

    def to_h = self.class.attributes.to_h { [it, public_send(it)] }
  end
end

  • YARD has the @!method directive, which creates a documented method that has no def, and @!macro [attach], which attaches a template to the method that follows (here attribute) and expands it for each call, with $1 standing for the first argument.   • RDoc has the :method: directive for the same purpose, written in a comment block that sits next to the macro call.

  • Always say what the generated method returns and accepts in the macro’s own comment, and keep a cheap check that the generated interface matches the documentation (below).

Constants by name

const_get, const_set, const_defined?, constants, const_missing, remove_const and const_source_location are the constant counterparts of send and define_method. Looking a class up by a name that arrives as a String (from a configuration file or a command-line option) is the most common use, and the one that most needs care.

  • Module#const_get(name, inherit = true) accepts a Symbol or a String, and a String may be a path ("Shelf::Store::Memory", with an optional leading ::); each segment is resolved in the result of the previous one. A name that is not a valid constant name raises NameError ("wrong constant name lower"), and a valid but missing one calls const_missing and, by default, raises NameError ("uninitialized constant Shelf::Nope").

  • inherit matters. By default the lookup also searches the ancestors of the receiver and, for a module, Object. So Shelf::Store.const_get(:String) returns ::String. Pass false to look only in the receiver itself, which is what a factory that maps names to its own adapters must do.

  • Module#const_defined?(name, inherit = true) has the same arguments and answers without raising. Module#constants(inherit = true) lists the Symbols.

  • Module#const_set(name, value) defines the constant (the name must start with a capital letter), warns "already initialized constant" if it exists, and, if the value is an anonymous class or module, gives it its name.

  • Module#const_missing(name) is called for every unresolved constant; overriding it on a module (def self.const_missing) turns a typo into a domain error or loads code on demand. It is now rarely written by hand; on-demand loading is normally done with autoload (see Code Loading: require and autoload).

  • Module#const_source_location(name) returns the file and line where the constant was assigned.

  • private_constant hides a constant from Box::NAME, but not from Box.const_get(:NAME): const_get ignores constant visibility, so it is a way around a private constant and should not be used on names you do not control.

  • remove_const is private on Module, so removing a constant takes send(:remove_const, :Name), and a reloader that does so should know exactly what it is doing.

# frozen_string_literal: true

Store.build is a factory that turns "memory" or :null into an adapter. Passing user-controlled strings to const_get (the idiom Rails spells constantize, which is ActiveSupport, not core Ruby) is a security smell for the reason shown above, and an allow-list or a registry Hash is the safe form.

Building classes and modules at run time

Class.new and Module.new

Class.new(superclass = Object) { |klass| ... } creates an anonymous class and Module.new { |mod| ... } an anonymous module. The block is evaluated with self set to the new class or module (as with class_eval), so def, define_method, attr_accessor, include and private work inside it as they do in a class body, and the new class is also yielded to the block. Data.define and Struct.new (which return anonymous classes), Class.new(StandardError) for a throwaway error class and the Module.new mixins built by libraries all rely on it.

Parameterized classes, abstract bases and class-level delegation

Class methods are ordinary methods on the singleton class, so a class can expose any operator-like method, including []. That gives parameterized classes: Repository[Book] returns a new subclass configured for Book. The pattern uses Class.new(self) to create the subclass and define_singleton_method to give it the parameter, and memoises the result so that Repository[Book] is always the same class. The same ingredients make abstract base classes, class-to-instance delegation (Renewals.renew(loan) calling Renewals.new.renew(loan)) and a callable alias such as call.

# frozen_string_literal: true

require "forwardable"
require "shelf"

module Shelf
  # An abstract base whose concrete classes are produced by Repository[Model].
  class Repository
    # Repository[Book] returns a subclass bound to Book. The result is memoised per model.
    def self.[](model)
      @bound ||= {}
      @bound[model] ||= Class.new(self) do
        define_singleton_method(:model) { model }
      end
    end

    # The abstract part: an unbound repository has no model.
    def self.model = raise(NotImplementedError, "bind a model first: #{name}[Model]")

    def initialize(store: Shelf.config.store)
      @store = store
    end

    def all = @store.all.grep(self.class.model)
  end

  BookRepository = Repository[Book]
  AuthorRepository = Repository[Author]

  # Class-to-instance delegation: Renewals.renew(...) is Renewals.new.renew(...).
  class Renewals
    def self.delegate_to_instance(*names)
      names.each do |name|
        define_singleton_method(name) { |*args, **kwargs, &block| new.public_send(name, *args, **kwargs, &block) }
      end
    end

    delegate_to_instance :renew

    def renew(loan, days: 14) = "#{loan.book.title} renewed for #{days} days"
    alias call renew
  end

Ghost methods with method_missing

When the lookup in the diagram at the top of the page finds nothing, Ruby calls method_missing(name, *args, &block) on the receiver, passing the Symbol and the original arguments. The default implementation, BasicObject#method_missing, raises NoMethodError (NameError for a bare identifier). Overriding it creates ghost methods: calls that have no def behind them. Proxies, builders (xml.title("Dune")), dynamic finders and test doubles all work this way. The behaviour of the default method, the error classes and the BasicObject proxy are described in Method Lookup and super; this section is about writing the override correctly.

The protocol and the full signature

A correct override has four parts:

  1. Handle only the names you own and send everything else to super, so that real errors (typos, calls to missing methods) still produce NoMethodError with the right name, receiver and message. RuboCop’s Lint/MissingSuper and Style/MissingRespondToMissing check this.

  2. Forward the complete call: positional arguments, keyword arguments and the block. The signature (name, *args, **kwargs, &block) does it explicitly. Anonymous forms do it without names: (name, *, **, &) (anonymous * and ** arguments can be passed on since Ruby 3.2; the anonymous block & since Ruby 3.1), and (name, ...) (... accepts a leading argument since Ruby 3.0).

  3. Define respond_to_missing?(name, include_private = false) with the same condition, ending in || super, so that respond_to?, method and public_method agree with the ghost methods.

  4. Prefer calling the real target with public_send when forwarding, so the ghost does not become a way to call private methods.

The easiest part to get wrong is the keyword arguments. Since Ruby 3.0 positional and keyword arguments are separate. A method_missing(name, *args, &block) collects the keywords into a Hash that is the last element of args, and forwarding it with *args hands the target an ordinary positional Hash, which is an ArgumentError for a method that expects keywords. There are three fixes: declare **kwargs (or the anonymous **), use ..., or keep the old signature and mark it with ruby2_keywords, which flags the final Hash so that splatting it passes keywords again.

require "shelf"

module Shelf
  # The object being wrapped: positional, keyword and block arguments.
  class Receipt
    def line(book, prefix: "", &decorate)
      text = "#{prefix}#{book.title}"

  # Forwards only *args: keyword arguments arrive as a positional Hash.
  class NaiveForwarder

      return super unless @target.respond_to?(name)

    end

  # The full signature: positional, keyword and block arguments all travel.
  class Forwarder
    def initialize(target) = @target = target

    def method_missing(name, *args, **kwargs, &block)
      return super unless @target.respond_to?(name)

      @target.public_send(name, *args, **kwargs, &block)
    end

    def respond_to_missing?(name, include_private = false) = @target.respond_to?(name, include_private) || super
  end

    def method_missing(name, ...)

      @target.public_send(name, ...)
    end

    def respond_to_missing?(name, include_private = false) = @target.respond_to?(name, include_private) || super
  end

  # rubocop:disable Style/ArgumentsForwarding, Naming/BlockForwarding

  # ruby2_keywords flags the trailing Hash so that splatting it passes keywords again.
  class FlaggedForwarder

    ruby2_keywords def method_missing(name, *args, &block)
      return super unless @target.respond_to?(name)

      @target.public_send(name, *args, &block)
    end

    def respond_to_missing?(name, include_private = false) = @target.respond_to?(name, include_private) || super
  end

respond_to_missing? and Method objects

respond_to? does not know about ghost methods unless respond_to_missing? says so, and the failure mode is subtle: code that checks respond_to?(:line) before calling concludes the object cannot do it, and forwarder.method(:line) raises NameError for a method that works when called. With respond_to_missing? in place, method(:line) returns a Method whose call goes through method_missing, whose arity is -1 and whose inspect shows #<Method: Shelf::Forwarder#line(*)>. The same ghost can then be passed as a block with &forwarder.method(:line) or stored in a dispatch table.

respond_to_missing? is also what libraries call on your behalf. Kernel#Array, Array#flatten, puts, multiple assignment, String#+, Array#join, File.join and the other implicit conversions (see Conversions and Coercion) probe their arguments for to_ary, to_str, to_path, to_proc, to_hash and similar names, which is where over-eager ghosts go wrong.

Pitfalls of ghost methods

# frozen_string_literal: true

require "shelf"

module Shelf
  # A bag of settings with ghost readers and writers that become real methods after first use.
  class Options
    def initialize(**values) = @values = values

    def method_missing(name, *)
      key = name.to_s.delete_suffix("=").to_sym
      return super unless @values.key?(key) || name.end_with?("=")

      define_accessors(key)
      public_send(name, *)
    end

    def respond_to_missing?(name, include_private = false)
      @values.key?(name.to_s.delete_suffix("=").to_sym) || super
    end

    private

    def define_accessors(key)
      define_singleton_method(key) { @values[key] }
      define_singleton_method(:"#{key}=") { |value| @values[key] = value }
    end
  end

  # Answers every message, which is exactly the problem.
  class Greedy
    def method_missing(name, *) = "ghost #{name}"

    def respond_to_missing?(*) = true
  end

  # Handles only the names it owns and leaves the rest to super.
  class Polite
    def method_missing(name, *)
      return super unless name.start_with?("get_")

      "ghost #{name}"
    end

    def respond_to_missing?(name, include_private = false) = name.start_with?("get_") || super
  end
end

  • A catch-all ghost breaks implicit conversions. Greedy answers every message, including to_ary, with a String. puts greedy, [greedy].flatten and Array(greedy) all ask for to_ary, get a String back and raise TypeError ("can’t convert Shelf::Greedy to Array (Shelf::Greedy#to_ary gives String)"). Where the conversion is to_str the damage is quieter: "x" + greedy returns "xghost to_str" and [greedy].join(",") returns "ghost to_str" instead of failing, and File.join("a", greedy) returns "a/ghost to_path". Polite answers only get_ names and sends the rest to super, so flatten and puts see an ordinary object. The rule: match narrowly (a prefix, a pattern, a lookup in a table) and never return a value for a name you did not check.

  • A ghost that raises for everything else must raise the right error. Return super, not nil, for unknown names. A method_missing that silently returns nil hides typos and makes respond_to_missing? untruthful.

  • Visibility errors reach method_missing too. A private or protected method called with an explicit receiver is routed to method_missing. A catch-all ghost therefore returns a value for object.private_method, where the default raises "private method called".

  • Recursion. A method_missing that calls a method the class does not define (or reads an attribute that is not set up yet) calls itself until SystemStackError ("stack level too deep"). Initialise the state the ghost reads, in initialize, before the object can receive messages, and reach it with @ivar rather than a method.

  • Bare identifiers. A name with no receiver and no arguments (ghost) reaches method_missing too, so a handled ghost works in all of ghost, ghost() and self.ghost. What differs is the error when the ghost ends in super: a bare identifier raises NameError ("undefined local variable or method"), the explicit forms raise NoMethodError.

  • Class-level ghosts need class-level respond_to_missing?. Define both on the singleton (def self.method_missing, def self.respond_to_missing?), as dynamic finders do.

  • Debugging. Backtraces for ghost methods pass through method_missing, and the method cannot be found with grep or instance_methods. A ghost whose names are fixed in advance is almost always better written with define_method.

  • Messages. On Ruby 4.0 the NoMethodError message for an ordinary object is undefined method 'fine' for an instance of Shelf::Options; once an object has singleton methods (which Options gets after its first access), it prints the object’s inspect instead, including its memory address.

The cost of ghost methods

Every ghost call first misses in the method lookup, then calls method_missing, which usually does string and Symbol work to decide whether the name is theirs. A generated method pays the lookup once, when it is defined. The benchmark compares three ways of writing loan.lent? with identical results: a def, a define_method loop and a method_missing ghost that parses the name on every call. Benchmark.bmbm runs each block twice (a rehearsal first, to warm caches) and reports the second pass.

  end

    (name.end_with?("?") && Shelf::Loan::STATES.include?(name.to_s.delete_suffix("?").to_sym)) || super

When to metaprogram

Metaprogramming moves work from the person reading the code to the interpreter at run time, and makes the code harder to search, to debug and to document. It earns that cost when it removes real duplication or when the set of names is genuinely data. A practical order of preference when a class needs behaviour that varies:

Need Prefer Reach for metaprogramming when

Two or three similar methods

Write them out with def. Plain code is greppable and shows up in Method#source_location.

There are many, or they come from a list that already exists (a loop that calls define_method once per state).

Calling a method chosen at run time

A case over a Symbol, or a Hash of Symbols to lambdas or Method objects.

The name space is large and regular ("#{field}=" setters), and an allow-list guards the input.

Methods known only at run time

method_missing with a narrow pattern and respond_to_missing?, preferably with the hybrid that defines a real method on first use.

A proxy or builder must accept names it cannot enumerate.

Changing an existing class

A subclass, a decorator, or a module added with prepend. See Method Lookup and super.

There is no other way into the object, and then through a refinement (Refinements and Monkey Patching) rather than a global patch.

Behaviour on one object

extend with a module, or a small wrapper object.

The object comes from code you do not control.

A configuration language

A DSL built from blocks, instance_eval and a handful of explicit methods (Hooks, eval and DSLs).

The configuration is read by many people and the declarative form removes boilerplate.

Questions that help decide:

  • Could a Hash or a case do the same job? If the generated methods are only a different way of spelling a lookup, they usually can.

  • Will a reader know where the method came from? Name the generator clearly (attribute, has_state), keep it in one file, and document the result (YARD or RDoc directives).

  • Is the input trusted? Names from a constant list are fine. Names from a file the user edits or from the network need an allow-list.

  • Is it on a hot path? If so, generate real methods, not ghosts.

  • Can the generated interface be tested? If you cannot assert what was defined, the macro does too much.

  • Does it honour the Ruby object model? Generated methods should respect visibility, call super where subclasses might override them, define respond_to_missing? for ghosts, and return the same types that equivalent hand-written methods would.

String-based eval (class_eval "def #{name}; end") is the oldest way to generate methods and the least safe: the string is parsed as code, so a name or a default value that came from outside becomes a code injection, and syntax errors appear at run time far from the cause. Prefer the block forms on this page. If a string eval is unavoidable, pass __FILE__ and __LINE__ so backtraces point at the definition (RuboCop’s Style/EvalWithLocation checks this), and add a documenting comment with an example of the generated code (Style/DocumentDynamicEvalDefinition). Ruby’s own Forwardable is such a case, and a good model for how it is done carefully. Details are in Hooks, eval and DSLs.

Testing generated code

Test the interface that the generator produces, not the generator’s implementation. Assert that each name exists (assert_respond_to, public_method_defined?), that it behaves for every input the generator accepts (loop over the same list), that it is absent for names it should not define (refute_respond_to), and that its signature is what the documentation promises (arity, parameters). For ghost methods, add the negative case: an unknown name must still raise NoMethodError. Property-style loops are cheap, since the generator’s input is a list.

# frozen_string_literal: true

require "minitest/autorun"
require "shelf"

module Shelf
  # The code under test: one generated predicate per state.
  class StatefulLoan < Loan
    STATES.each do |name|
      define_method(:"#{name}?") { state == name }
    end
  end
end

class StatefulLoanTest < Minitest::Test
  def setup
    isbn = Shelf::Isbn.new(digits: "978-0-306-40615-7")
    @book = Shelf::Book.new(isbn:, title: "Dune", author: Shelf::Author.new(name: "Frank Herbert"))
  end

  # Test the generated interface, not the generating code.
  def test_a_predicate_exists_for_every_state
    Shelf::Loan::STATES.each do |state|
      assert_respond_to Shelf::StatefulLoan.new(@book), :"#{state}?"
    end
  end

  def test_exactly_one_predicate_is_true_for_each_state
    Shelf::Loan::STATES.each do |state|
      loan = Shelf::StatefulLoan.new(@book, state:)
      truthy = Shelf::Loan::STATES.select { |name| loan.public_send(:"#{name}?") }

      assert_equal [state], truthy
    end
  end

  def test_predicates_take_no_arguments
    method = Shelf::StatefulLoan.instance_method(:lent?)

    assert_equal 0, method.arity
    assert_equal [], method.parameters
  end

  def test_unknown_states_are_not_generated
    loan = Shelf::StatefulLoan.new(@book)

    refute_respond_to loan, :lost?
    assert_raises(NoMethodError) { loan.lost? }
  end

  def test_generated_methods_are_public_instance_methods
    assert Shelf::StatefulLoan.public_method_defined?(:lent?)
  end

Pitfalls

  • send for private methods in production code. It couples callers to implementation details. Prefer public_send, or make the method public, or move the behaviour into a collaborator.

  • Unfiltered names. public_send(params[:action]) or const_get(params[:type]) is remote control of the program. Filter first.

  • define_method in a loop that captures the loop variable by reference. Block parameters are fresh on each iteration, so names.each { |name| define_method(name) { name } } is correct; a while loop with an outer variable shares one variable between all generated methods. Use each or map.

  • Forgetting respond_to_missing? (or the || super), and therefore breaking respond_to?, method and duck typing.

  • Ghosts that swallow errors. Return super for names you do not own.

  • Positional Hash instead of keywords in a forwarder written as (name, *args, &block). Use **kwargs, ..., or ruby2_keywords.

  • Constants defined inside Class.new { } land in the enclosing scope. Use const_set.

  • Redefinition warnings. -w reports method redefined; discarding old name when define_method or def replaces a method in the same class. Generate each name once, and use remove_method or a subclass if replacement is intended.

  • Class-level instance variables are not inherited. A macro that stores its list in @attributes on the class sees nothing from a superclass; subclasses need their own copy, usually made in the inherited hook (see Hooks, eval and DSLs).

  • const_get and private constants. private_constant is not enforced for const_get.

  • Shallow freezing. freeze does not freeze the objects an object points at, so a frozen catalogue still accepts books through its store.

  • Top-level define_method. It defines a public method on every object.

  • Thread safety. Defining methods at run time while other threads call them is allowed but racy for the code that checks respond_to? and then calls. Define generated methods at load time, before the program starts serving requests.

Where older material is outdated

Tutorials and books on metaprogramming were mostly written for Ruby 2.x and 3.0 to 3.2. Items to correct when reading them:

Older material says Current Ruby 4.0 behaviour

Error text such as undefined method 'x' for nil:NilClass, or with a backtick as the opening quote

Ruby 3.3 changed the receiver to "for an instance of ClassName" (and for nil), and Ruby 3.4 changed the quotes to plain apostrophes: undefined method 'x' for nil. Messages for objects with singleton classes still print the object’s inspect.

{:name=>"Ico"} in inspect output

Ruby 3.4 prints {name: "Ico"}; Data prints as #<data Shelf::Book ...>.

NotImplementedError as the way to mark abstract methods

It is a ScriptError, not a StandardError, so rescue => e misses it. Raise NoMethodError or a custom error; keep NotImplementedError for unsupported platform features.

safe_constantize or constantize as part of "the language"

They are ActiveSupport, not core Ruby, and safe_constantize returns nil for unknown names. In plain Ruby use const_get with inherit = false and an allow-list.

_1 as the only implicit block parameter

Ruby 3.4 adds it for a single parameter; the two cannot be mixed in one block.

send(:define_method, ...), singleton_class.send(:define_method, ...)

define_method and define_singleton_method are public and need no send.

alias_method_chain and hand-rolled alias wrapping

Wrap with prepend and super, or with instance_method plus bind_call when the wrapper must live elsewhere.

method_missing examples with (name, *args, &block) that forward keywords

From Ruby 3.0 keywords are separate from positional arguments; use **kwargs, ... or ruby2_keywords, which became mandatory for *args delegation in 3.2.

attr_accessor returning nil

It returns an Array of Symbols since Ruby 3.0, and private attr_accessor :x works; alias_method returns the new name.

OpenStruct as the easy "dynamic object"

ostruct is a bundled gem since Ruby 4.0 and builds methods on demand with the costs described above. Prefer Struct, Data, a Hash or a small class like Shelf::Options (Struct, Data and Value Objects).

Benchmark and Logger listed as part of the standard library

benchmark is a bundled gem in Ruby 4.0 and needs a Gemfile entry under Bundler; logger and pstore moved the same way.

Class#subclasses and Class#attached_object missing

Added in Ruby 3.1 and 3.2. Module#undefined_instance_methods and Module#const_added are 3.2, Module#set_temporary_name 3.3.

inherited as the only way to find subclasses

Class#subclasses lists direct subclasses without a hook. A method returning all descendants is in Ruby’s development branch and not in 4.0.

String eval for method generation, as in older Rails and metaprogramming books

Block-based define_method avoids the injection and debugging problems; Forwardable remains the example of careful string generation.

private returning nil

It returns its arguments since Ruby 3.1, which is why private def name and private define_method(...) work.

A top-level define_method described as invalid

On the Rubies checked (3.3, 3.4 and 4.0) it works and defines a public method on Object. Treat it as a pitfall, because every object then responds to the new method, not as an error.
