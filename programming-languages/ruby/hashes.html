Hashes

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Ruby 4.0 (4.0.7, checked on 2026-10-18); features newer than Ruby 3.0 name the version that introduced them. A Hash is Ruby’s dictionary: an unordered-looking but insertion-ordered collection of key-value pairs with fast lookup by key. It is the second most used core collection after Array, it is what a JSON document becomes when parsed, and it is what keyword arguments are made of. This page covers creating hashes, the order guarantee, reading with [], fetch and dig, defaults and default procs, mutating and iterating safely, transforming and grouping, what makes a good key (eql? and hash), compare_by_identity, the Ruby 3.4 inspect format, keyword-argument conversion, pattern matching, copying and freezing, JSON round trips, and when a Hash should be a Struct, a Data or a class instead. The literal syntax is also covered in Literals; the eql?/hash contract in Equality, Hashing and Comparison; the methods every collection shares in Enumerable; the sibling collections in Arrays, Sets and Struct, Data and Value Objects; how symbols behave as keys in Symbols; keyword arguments in Methods and Parameters and Calling Methods and Argument Forwarding; case/in on hashes in Pattern Matching; and JSON and YAML in Serialization: JSON, YAML, CSV and Marshal. For how other languages spell the same idea, see Go maps and Rust collections.

Every example on this page was syntax-checked with ruby -wc, run on Ruby 4.0.7 and linted with RuboCop 1.92 using the configuration of the running shelf gem (target Ruby 4.0, double-quoted strings). The values in # => comments, and the output in the output blocks, are the real results. Each file is self-contained so it can be run on its own, and the examples reuse the names of the shelf library catalogue used throughout this section (Isbn, Author, Book, Catalog). Where a bare expression statement would draw a "useless use in void context" warning, the example passes it to p, which returns its argument.

What a Hash is

A Hash maps keys to values. Four properties define everything else on this page:

  • Lookup is by key equality, not identity. Two keys are the same key when eql? is true and their hash values are equal. That is why "a" finds "a" even when they are different String objects, and why 1 and 1.0 are different keys.

  • Iteration follows insertion order. This is a documented guarantee (it was not in Ruby 1.8). Re-assigning an existing key keeps its position; deleting a key and adding it again moves it to the end.

  • A missing key yields the hash’s default. By default that is nil; a hash can carry a fixed default value or a default proc that computes one. fetch and key? ignore the default and tell the truth.

  • A Hash is Enumerable. each yields two-element [key, value] arrays, so map, select, sort_by, group_by, sum and the rest work, with the twist that some of them return a Hash and most return an Array of pairs.

Behind the scenes MRI stores small hashes in a compact array and larger ones in a hash table; neither detail is visible except through speed. Lookup, insertion and deletion are amortised constant time for keys with a good hash.

Creating hashes

Literals

A hash literal is a comma-separated list of pairs between braces. Four key forms are in daily use:

  • key: value makes a Symbol key. It is the standard form and the one the 3.4 inspect prints.

  • "text": value makes a Symbol key too (not a String), which allows names that are not valid identifiers, such as "call number": "QA76".

  • expression => value (the "hash rocket") accepts any object as the key: a String, an Integer, nil, an Array. Hashes written with rockets for every key (:title => "Ico") are the pre-1.9 style that RuboCop’s Style/HashSyntax rewrites.

  • x: with no value (Ruby 3.1) is shorthand for x: x: the value is the local variable or method of the same name.

A Hash can be built from another with the double splat: { **defaults, copies: 5 } copies the pairs and a later pair for the same key wins, which is the idiomatic way to apply overrides without mutating anything.

# frozen_string_literal: true

isbn = "9780134685991"
stock = { "9780134685991" => 3, "9781492078005" => 1 }
p stock # => {"9780134685991" => 3, "9781492078005" => 1}

copies = 2
title = "Ico"
book = { title:, isbn:, copies: }
p book # => {title: "Ico", isbn: "9780134685991", copies: 2}

p({ "call number": "QA76", :"x-ray" => true, :+ => 1, if: 1 })
# => {"call number": "QA76", "x-ray": true, "+": 1, if: 1}
p({ 1 => :one, nil => :nothing, [1, 2] => :pair, 1.5 => :float })
# => {1 => :one, nil => :nothing, [1, 2] => :pair, 1.5 => :float}

# rubocop:disable Style/HashConversion
Hash[[%i[a b], [:c, 2]]] # => {a: :b, c: 2}
Hash[:a, 1, :b, 2] # => {a: 1, b: 2}
# rubocop:enable Style/HashConversion
[[:a, 1], [:b, 2]].to_h # => {a: 1, b: 2}
%w[ico bach].to_h { |name| [name.to_sym, name.length] } # => {ico: 3, bach: 4}
%i[title isbn].zip(%w[Ico 9780134685991]).to_h # => {title: "Ico", isbn: "9780134685991"}
Hash(nil) # => {}
Hash.try_convert([[:a, 1]]) # => nil
Hash.try_convert({ a: 1 }) # => {a: 1}
p({ **book, copies: 5 }) # => {title: "Ico", isbn: "9780134685991", copies: 5}
p({ copies: 5, **book }) # => {copies: 2, title: "Ico", isbn: "9780134685991"}

key = +"mutable"
index = { key => 1 }
key << "!"
p index # => {"mutable" => 1}
index.keys.first.frozen? # => true
key.frozen? # => false

Source: Ruby 4.0 documentation: Hash Literals

Three details from that listing deserve a sentence each. The key that was a String is duplicated and frozen when the pair is stored, so later changes to the original String do not corrupt the hash (index.keys.first.frozen? is true while key itself stays unfrozen); other mutable keys are not copied (see Keys in depth). Duplicate keys in one literal are not an error, the last wins, but ruby -w warns (see Errors and warnings). And a { right after a method name without parentheses is parsed as a block, not a hash, which is why puts { a: 1 } is a syntax error while puts({ a: 1 }) works.

The Hash.new default value is evaluated once; the block form is evaluated on each miss. That difference is the single most common source of Hash bugs and is the subject of its own section below.

Insertion order

Ruby 1.9 made the iteration order of a Hash the order of insertion, and that behaviour is part of the language contract. The rules in practice:

  • A new key goes to the end.

  • Assigning to an existing key replaces the value and keeps the position.

  • delete removes the key, so adding it again places it last.

  • shift removes and returns the first pair (nil for an empty hash since Ruby 3.2; earlier versions returned the default).

  • first, first(n) and min_by all see that order. Equality ignores it: two hashes with the same pairs in different order are == and eql?.

  • Sorting never reorders a Hash in place: sort, sort_by and min_by return Arrays of pairs; use .to_h to get a Hash in the new order.

# frozen_string_literal: true

shelf = { a: 1, b: 2, c: 3 }
shelf[:a] = 10 # => 10
shelf.keys # => [:a, :b, :c]
shelf.delete(:a) # => 10
shelf[:a] = 1
shelf.keys # => [:b, :c, :a]
p(shelf == { c: 3, a: 1, b: 2 }) # => true
shelf.eql?({ c: 3, a: 1, b: 2 }) # => true
shelf.to_a # => [[:b, 2], [:c, 3], [:a, 1]]
shelf.first # => [:b, 2]
shelf.first(2) # => [[:b, 2], [:c, 3]]
shelf.min_by { |_, v| v } # => [:a, 1]
shelf.shift # => [:b, 2]
p shelf # => {c: 3, a: 1}
{}.shift # => nil
{ "a" => 1, a: 2 }.length # => 2

Source: Ruby 4.0 documentation: Hash

Reading values

Reading with brackets, fetch and friends

hash[key] returns the stored value or the default (nil unless configured otherwise). The ambiguity is the weakness: a nil result may mean "absent" or "stored nil`". `fetch removes the ambiguity: it raises KeyError for a missing key, or returns the fallback you supply, as a second argument or as a block. The block is only evaluated when needed and receives the key, so it is the right place for an expensive or side-effecting fallback; supplying both a fallback argument and a block is accepted but warns that the block supersedes it.

The KeyError carries key and receiver, and did_you_mean adds a corrections list, which makes typos in option names easy to spot in a log.

# frozen_string_literal: true

stock = { "9780134685991" => 3, "9781492078005" => 1 }
stock["9780134685991"] # => 3
stock["0000000000000"] # => nil
stock.fetch("9780134685991") # => 3
stock.fetch("0000000000000", 0) # => 0
stock.fetch("0000000000000") { |isbn| "no stock for #{isbn}" } # => "no stock for 0000000000000"
stock.fetch_values("9780134685991", "9781492078005") # => [3, 1]
stock.values_at("9780134685991", "0000000000000") # => [3, nil]
stock.fetch_values("0000000000000", &:to_i) # => [0]

begin
  stock.fetch("0000000000000")
rescue KeyError => e
  e.message # => "key not found: \"0000000000000\""
  e.key # => "0000000000000"
  e.receiver.equal?(stock) # => true
end

begin
  { title: "Ico" }.fetch(:titel)
rescue KeyError => e
  e.message # => "key not found: :titel"
  e.corrections # => [:title]
end

stock.key?("9780134685991") # => true
stock.member?("x") # => false
stock.value?(1) # => true
stock.key(1) # => "9781492078005"
stock.assoc("9781492078005") # => ["9781492078005", 1]
stock.rassoc(3) # => ["9780134685991", 3]
stock.length # => 2
stock.empty? # => false
stock.any? { |_isbn, copies| copies > 2 } # => true
stock.count { |_isbn, copies| copies.odd? } # => 2
stock.sum { |_isbn, copies| copies } # => 4
stock.find { |_isbn, copies| copies == 1 } # => ["9781492078005", 1]
stock.to_proc.call("9780134685991") # => 3
%w[9781492078005 9780134685991].map(&stock) # => [1, 3]

Source: Ruby 4.0 documentation: Hash#fetch

A Hash also converts to a callable: hash.to_proc returns a lambda that looks keys up, so ids.map(&stock) reads the stock of each id.

Nested data with dig

dig follows a chain of keys or indexes through nested hashes, arrays and structs, and returns nil as soon as a step is nil instead of raising. The rules from the documentation:

  • Each intermediate step is looked up with [] (so defaults and default procs apply) and the walk stops with nil if a value is nil.

  • The intermediate object must itself respond to dig: Hash, Array and Struct do. Anything else (a String, an Integer) raises TypeError with the message Integer does not have #dig method. Data has no dig.

  • dig with one argument is just []; RuboCop’s Style/SingleArgumentDig flags it.

Where the structure is required and its absence is a bug, prefer chained fetch calls, which fail loudly at the exact missing key; use dig where absence is normal, for example when reading optional parts of a parsed JSON document.

# frozen_string_literal: true

loan = { book: { title: "Ico", author: { name: "Ueda" } }, due: nil }
loan.dig(:book, :author, :name) # => "Ueda"
loan.dig(:book, :publisher, :name) # => nil
loan.dig(:due, :year) # => nil
loan[:book][:publisher] # => nil
loan.fetch(:book).fetch(:author).fetch(:name) # => "Ueda"

begin
  loan[:book][:publisher][:name]
rescue NoMethodError => e
  e.message # => "undefined method '[]' for nil"
end

begin
  loan.dig(:book, :title, :first)
rescue TypeError => e
  e.message # => "String does not have #dig method"
end

shelves = { rows: [{ slots: %w[Ico Bach] }, { slots: [] }] }
shelves.dig(:rows, 0, :slots, 1) # => "Bach"
shelves.dig(:rows, 1, :slots, 0) # => nil
shelves.dig(:rows, 5, :slots) # => nil
Hash.new { |hash, key| hash[key] = [key] }.dig(:x, 0) # => :x

Source: Ruby 4.0 documentation: dig methods

Defaults and default procs

A hash returns its default for a missing key. There are two kinds, set at construction or later:

  • A default value (Hash.new(0), hash.default = 0) is returned as is and is not stored. The same object is returned every time, which is a trap for mutable values (below).

  • A default proc (Hash.new { |hash, key| ... }, hash.default_proc = proc) is called with the hash and the key. It may compute and return a value, and it may also store it (hash[key] = ...), which is how self-filling hashes work.

Rules worth remembering:

  • [] consults the default, and so do dig and values_at, which call it. fetch, fetch_values, key?, slice, to_a, size and each do not. A default value never creates an entry, and a default proc creates one only if it assigns.

  • Giving both a positional default and a block raises ArgumentError. Assigning default= clears a default proc and default_proc= clears the default value. The default_proc= argument must accept two arguments (a lambda that takes one raises TypeError).

  • Copies made with dup, clone, merge, compact and to_h keep the default; select, reject, slice, except, transform_values and to_h with a block build a plain hash without it.

  • Hash.new(0) is the standard counter; Hash.new { |h, k| h[k] = [] } the standard grouper; the recursive form Hash.new { |h, k| h[k] = Hash.new(&h.default_proc) } the standard autovivifying tree.

The shared-default pitfall. Hash.new([]) creates one Array and returns that same object for every missing key. Appending to it changes the default for all keys and stores nothing, so the hash stays empty and hash[:anything] suddenly returns the collected elements. RuboCop reports it as Lint/SharedMutableDefault. The listing keeps it on purpose, with a cop directive, to show the symptom. The block form allocates a fresh Array per key and stores it.

# frozen_string_literal: true

visits = Hash.new(0)
%w[ico bach ico].each { |title| visits[title] += 1 }
p visits # => {"ico" => 2, "bach" => 1}
visits["missing"] # => 0
visits.key?("missing") # => false
visits.fetch("missing", :none) # => :none
visits.default # => 0
visits.default = 5
visits["still-missing"] # => 5
visits.size # => 2

shared = Hash.new([]) # rubocop:disable Lint/SharedMutableDefault
shared[:a] << "Ico"
shared[:b] << "Bach"
p shared # => {}
shared[:zzz] # => ["Ico", "Bach"]
shared.default # => ["Ico", "Bach"]

by_author = Hash.new { |hash, author| hash[author] = [] }
by_author["Ueda"] << "Ico"
by_author["Ueda"] << "Shadow of the Colossus"
by_author["Bach"] << "Cello Suites"
p by_author # => {"Ueda" => ["Ico", "Shadow of the Colossus"], "Bach" => ["Cello Suites"]}
by_author.default_proc.class # => Proc
by_author.default_proc.lambda? # => false

lazy = Hash.new { |_hash, key| key.to_s * 2 }
lazy[:ab] # => "abab"
lazy.size # => 0
lazy.fetch(:ab, nil) # => nil

tree = Hash.new { |hash, key| hash[key] = Hash.new(&hash.default_proc) }
tree[:a][:b][:c] = 1
p tree # => {a: {b: {c: 1}}}

lookup = { a: 1 }
lookup.default_proc = ->(_hash, key) { "no #{key}" }
lookup[:z] # => "no z"
lookup.default # => nil

Hash.new(capacity: 1000).default # => nil

begin
  Hash.new(0) { |_h, _k| 1 }
rescue ArgumentError => e
  e.message # => "wrong number of arguments (given 1, expected 0)"
end

begin
  Hash.new(&->(_a) { 1 })
rescue TypeError => e
  e.message # => "default_proc takes two arguments (2 for 1)"
end

Source: Ruby 4.0 documentation: Hash.new

Two conventions help when reading code. The bang methods reject!, select! and compact! return nil when they changed nothing, so do not chain on their result; delete_if and keep_if always return the hash. And merge with a block is the tool for combining counts or nested settings, because the block is called only for keys present on both sides.

Modifying during iteration. Deleting or reassigning existing keys while iterating is allowed. Adding a new key raises RuntimeError ("can’t add a new key into hash during iteration"), because the table might be resized under the iterator. Collect the changes first and apply them after the loop, or iterate over a copy (hash.dup.each).

Frozen hashes. freeze makes the hash itself read-only: every mutator raises FrozenError, but the values stay as mutable as they were, and merge still returns a new unfrozen hash. Ractor.make_shareable freezes a structure deeply; see Copying, freezing and sharing.

# frozen_string_literal: true

stock = { "9780134685991" => 3, "9781492078005" => 1 }
stock["9780134685991"] += 1 # => 4
stock.store("9780596516177", 2) # => 2
stock.delete("9781492078005") # => 1
stock.delete("nope") # => nil
stock.delete("nope") { |key| "#{key} was absent" } # => "nope was absent"
stock.merge("9780134685991" => 10) # => {"9780134685991" => 10, "9780596516177" => 2}
stock.merge({ "9780134685991" => 10 }) { |_k, old, new| old + new } # => {"9780134685991" => 14, "9780596516177" => 2}
stock.merge({ "a" => 1 }, { "b" => 2 }) # => {"9780134685991" => 4, "9780596516177" => 2, "a" => 1, "b" => 2}
stock.merge # => {"9780134685991" => 4, "9780596516177" => 2}
stock.update("9780596516177" => 0) # => {"9780134685991" => 4, "9780596516177" => 0}
stock.reject! { |_isbn, copies| copies.zero? } # => {"9780134685991" => 4}
stock.reject! { |_isbn, copies| copies.zero? } # => nil
stock.select! { |_isbn, copies| copies.positive? } # => nil
stock.compact! # => nil
{ a: 1, b: nil }.compact # => {a: 1}
stock.delete_if { |_isbn, copies| copies > 100 } # => {"9780134685991" => 4}
stock.keep_if { |_isbn, copies| copies > 100 } # => {}
stock.replace({ "k" => 1 }) # => {"k" => 1}
stock.clear # => {}

counts = { a: 1, b: 2 }
counts.each_key { |key| counts.delete(key) if key == :a }
p counts # => {b: 2}

begin
  counts.each_key { |key| counts[:"#{key}2"] = 0 }
rescue RuntimeError => e

Iterating

each and each_pair are the same method. They yield one argument, a two-element array [key, value], which blocks with two parameters destructure automatically. Everything Enumerable offers then applies to the pairs: map, flat_map, filter_map, sum, count, find, partition, min_by/max_by, sort_by, each_with_object, reduce (whose block destructures with |sum, (key, value)|), each_slice, zip, lazy.

Rules and traps:

  • each_key and each_value iterate one side; without a block they return Enumerators (each_value.sum).

  • The Hash-returning methods are select/filter, reject, slice, except, merge, compact, transform_values, transform_keys, invert and to_h. Nearly everything else (map, sort_by, partition, min_by, group_by values, zip, flatten, sort) returns an Array. Add .to_h to get a Hash back.

  • A numbered parameter or it receives the whole pair when used alone: hash.map { it } yields [key, value] arrays; _1 and _2 destructure it. it (Ruby 3.4) is a good fit when the pair is passed through; for two named parts prefer |key, value|. RuboCop’s Style/NumberedParametersLimit forbids using more than one numbered parameter.

  • A lambda passed with & does not destructure: since Ruby 3.0 Hash#each and map always yield a single two-element Array, so a lambda taking two parameters raises ArgumentError. A proc (or a block) destructures. Write ->(pair) { ... } or use a block.

  • The order is the insertion order, so first, each_slice and take_while are deterministic.

  • Unused block parameters are conventionally prefixed with _ (|_title, copies|), which RuboCop’s Lint/UnusedBlockArgument expects.

Transforming, filtering and grouping

The transformation methods return new hashes (and have bang forms that change the receiver). The ones to know:

  • transform_values (Ruby 2.4) maps values and keeps keys: the right tool for "apply this to every value".

  • transform_keys (2.5) maps keys. Since Ruby 3.0 it also takes a hash of old-to-new keys, optionally together with a block for keys not listed. If two keys map to the same new key the later pair overwrites the earlier.

  • to_h { |key, value| [new_key, new_value] } (2.6) rebuilds a hash from pairs, changing both sides.

  • select/filter, reject, compact filter pairs and return hashes; filter_map (2.7) maps and filters in one pass but returns an Array.

  • slice(*keys) (2.5) keeps the listed keys; except(*keys) (3.0) drops them. Both ignore keys that are absent.

  • invert swaps keys and values; duplicate values collapse (the last key wins).

  • group_by returns a Hash of Arrays, grouped by the block’s result; partition returns two Arrays; tally (2.7) counts equal elements into a Hash, and since 3.1 takes a hash to add to. each_with_object builds any shape.

  • sum, min_by, max_by and sort_by take blocks that destructure the pair, as in the iteration section.

Keys in depth

The eql? and hash contract

A Hash finds a key by calling hash on it to choose a bucket and eql? to confirm a match. Two objects are the same key when a.eql?(b) is true, which requires a.hash == b.hash. The consequences:

  • eql? is stricter than ==: 1 == 1.0 is true but 1.eql?(1.0) is false and their hashes differ, so { 1 => :int }[1.0] is nil. The same holds for 1 and Rational(1).

  • Strings, Symbols, Integers, Floats, Arrays, Hashes, Ranges, Struct and Data instances compare and hash by content, so they work as keys. A plain Object hashes by identity.

  • A class that overrides == but not eql? and hash is not found, which is the usual "my custom key is not found" bug. Override all three together, derive hash from the same fields, and see Equality, Hashing and Comparison.

  • The best custom keys are immutable value objects. Data.define (Ruby 3.2) gives eql? and hash for free, which is why the shelf Isbn works as a key whichever way the digits were typed.

  • Floating-point keys are fragile because of rounding (0.1 + 0.2 is not 0.3) and Float::NAN, which is never equal to anything, so avoid them.

Mutable keys and rehash

Only String keys are copied and frozen on insertion. Any other mutable key (an Array, a Hash, your own object) is stored as is. If its content changes after it was stored, its hash changes, the Hash looks in the wrong bucket, and the entry becomes unreachable, although iteration still shows it. rehash recomputes the buckets and repairs the table; it is the documented remedy but the better fix is to freeze keys or use immutable ones. Never call rehash while iterating.

Symbols or strings?

Symbols are the conventional keys for a fixed set of names that the program itself defines (options, record fields, anything written as a literal), because they are cheap to compare, are written name:, and are what keyword arguments use. Strings are the conventional keys for data that arrives from outside (JSON, CSV, HTTP headers, environment variables) and for any open-ended set. Do not convert untrusted strings with to_sym in a long-lived process without a bound (the symbol table no longer grows without limit since Ruby 2.2, but dynamic symbols still take memory); JSON.parse(symbolize_names: true) is the safe place to do it for a known document shape. A hash with mixed key types is a smell: h[:a] and h["a"] are different entries, and no automatic indifferent access exists in core Ruby (Rails' with_indifferent_access is not part of Ruby).

compare_by_identity

compare_by_identity switches a hash to compare keys with equal? (object identity) instead of eql?, so two equal Strings become two different keys. It rebuilds the table in place, is reported by compare_by_identity?, is kept by dup, select, reject, merge, slice and transform_values, and suits caching per-object data. String keys of an identity hash are stored as given, not as frozen copies. In inspect the output is the same, so the mode is invisible in logs. For associations that should not keep their keys alive, ObjectSpace::WeakKeyMap and ObjectSpace::WeakMap hold keys weakly.

# frozen_string_literal: true

module Shelf
  Isbn = Data.define(:digits) do
    def initialize(digits:) = super(digits: digits.delete("-"))
  end

  # Defines == only, so a Hash cannot find an equal instance.
  class Plain
    attr_reader :id

    def initialize(id) = @id = id
    def ==(other) = other.is_a?(Plain) && id == other.id
  end

  # Adds eql? and a matching hash: now equal instances are the same key.
  class Keyed < Plain
    alias eql? ==
    def hash = [self.class, id].hash
  end
end

Equality and inclusion

== is true when both hashes have the same size and each key of one maps to an == value in the other; the order of pairs is irrelevant. eql? demands eql? values (so { a: 1 }.eql?({ a: 1.0 }) is false), and hash is consistent with it, which makes hashes usable as keys in other hashes.

The comparison operators test inclusion. a <= b is true when every pair of a is in b (a subset or equal), a < b when it is a proper subset, and >= and > are the mirror images. Values are compared with ==. This reads naturally for "does this record satisfy the filter": filter <= record. The empty hash is a subset of every hash. The rules, with the order of the operands, are in the documentation page on hash inclusion.

Hashes and keyword arguments

Keyword arguments are Hashes at the boundary. Since Ruby 3.0 the two are separated, which fixed a large family of ambiguities, and the rules are small:

  • f(**options) passes the pairs of options as keywords. Keys must be Symbols unless the method itself accepts **kwargs (Ruby 2.7 allows non-Symbol keys there). Duplicates resolve to the last, as in a literal.

  • f(options), with a Hash as the last positional argument, is not converted to keywords any more. If the method accepts only keywords it raises ArgumentError; if it has an optional positional parameter (def f(opts = {})), the Hash fills it.

  • A braceless hash at the end of a call (f(days: 7)) is keywords if the method accepts keywords, otherwise it becomes a positional Hash. def rest(*args) receives [{days: 7}]; **{} contributes nothing.

  • **nil (Ruby 3.4) at a call site passes nothing; in a parameter list **nil declares that keywords are not accepted.

  • Inside a method, **config collects the keywords into a fresh Hash, which can be modified, merged and forwarded.

  • ** calls to_hash on the operand, so any object with an implicit to_hash converts.

  • ruby2_keywords marks a method that forwards *args so that a trailing keyword Hash stays flagged; it is only for old delegation code (use ... or *, ** in new code), and it is deprecated in the Ruby 4.1 preview.

Pattern matching with hashes

case/in matches a Hash against a pattern of keys. Only the listed keys are checked, extra keys are allowed unless the pattern ends with **nil, and values can be nested patterns, classes, ranges or bound to variables. hash => pattern raises NoMatchingPatternKeyError (a subclass of NoMatchingPatternError carrying key) when a key is missing, and hash in pattern returns a boolean. A custom class takes part by defining deconstruct_keys(keys), which receives the requested keys or nil. This is the idiomatic way to unpack parsed JSON payloads. The full syntax is in Pattern Matching.

# frozen_string_literal: true

event = { type: "loan", book: { isbn: "9780134685991", title: "Ico" }, days: 14 }

summary = case event
          in { type: "loan", book: { title: }, days: Integer => days }
            "#{title} lent for #{days} days"
          end
p summary # => "Ico lent for 14 days"

event => { book: { isbn: } }
p isbn # => "9780134685991"

event in { type: "return" } # => false
event in { type: String } # => true
event in { days: 1.. } # => true

extra = { type: "loan", extra: 1 }
kind = case extra
       in { type: "loan", **nil } then :exact
       in { type: "loan", **rest } then rest
       end
p kind # => {extra: 1}

begin
  event => { missing: _field }
rescue NoMatchingPatternKeyError => e
  e.message # => "{type: \"loan\", book: {isbn: \"9780134685991\", title: \"Ico\"}, days: 14}: key not found: :missing"
  e.key # => :missing
end

# A custom class takes part by defining deconstruct_keys.
class Point
  attr_reader :x_pos, :y_pos

  def initialize(x_pos, y_pos)
    @x_pos = x_pos
    @y_pos = y_pos
  end

  def deconstruct_keys(keys) = { x: x_pos, y: y_pos }.slice(*(keys || %i[x y]))
end

case Point.new(1, 2)
in { x:, y: } then [x, y] # => [1, 2]
end

Copying, freezing and sharing

  • dup and clone make shallow copies: a new table, the same key and value objects. Changing a nested Array through the copy changes it in the original. clone also keeps the frozen state and singleton methods (clone(freeze: false) overrides), while dup does not.

  • dup, clone, merge, compact and to_h keep the default value or default proc; select, reject, slice, except, transform_values and to_h with a block do not.

  • A deep copy needs a deliberate step. Marshal.load(Marshal.dump(hash)) works for plain data, but a hash with a default proc cannot be dumped (TypeError: can’t dump hash with default proc); recursive helpers that map over values are clearer. Never feed Marshal.load data you did not produce.

  • Ractor.make_shareable(hash) freezes the hash and everything reachable from it in place, which is the idiom for constant configuration (CONFIG = Ractor.make_shareable(...)) and what the freezing section of Object Lifecycle, Freezing and Copying and Ractors build on.

# frozen_string_literal: true

original = { title: "Ico", tags: ["game"], stats: Hash.new(0) }
shallow = original.dup
shallow[:title] = "Changed"
shallow[:tags] << "ps2"
original[:title] # => "Ico"
original[:tags] # => ["game", "ps2"]
shallow[:stats]["x"] # => 0
shallow.default_proc # => nil
shallow.equal?(original) # => false
shallow[:tags].equal?(original[:tags]) # => true

deep = Marshal.load(Marshal.dump({ title: "Ico", tags: ["game"] }))
deep[:tags] << "extra"
p deep # => {title: "Ico", tags: ["game", "extra"]}

counting = Hash.new(7)
counting.dup[:missing] # => 7
counting.clone.default # => 7
counting.merge({}).default # => 7
counting.select { true }.default # => nil
counting.to_h.default # => 7
counting.to_h { |k, v| [k, v] }.default # => nil

locked = { tags: ["game"] }.freeze
locked.dup.frozen? # => false
locked.clone.frozen? # => true
locked.clone(freeze: false).frozen? # => false
locked[:tags] << "still mutable"
p locked # => {tags: ["game", "still mutable"]}

nested = { a: { b: 1 } }
frozen_all = Ractor.make_shareable(nested)
frozen_all.frozen? # => true
frozen_all[:a].frozen? # => true
nested.equal?(frozen_all) # => true

JSON and other text formats

A parsed JSON object is a Hash whose keys are Strings by default. JSON.parse(text, symbolize_names: true) makes them Symbols, which is what dig(:author, :name) and pattern matching with key: need. In the other direction to_json and JSON.generate turn keys into JSON strings by calling to_s, so non-String keys collapse silently: nil becomes "" and an Array becomes its inspect text. Round-tripping therefore changes Symbols to Strings. The json library also offers JSON.pretty_generate; YAML (Psych) and CSV have their own Hash conversions, covered in Serialization: JSON, YAML, CSV and Marshal.

# frozen_string_literal: true

require "json"

payload = '{"title":"Ico","copies":3,"tags":["game"],"author":{"name":"Ueda"}}'
JSON.parse(payload) # => {"title" => "Ico", "copies" => 3, "tags" => ["game"], "author" => {"name" => "Ueda"}}
data = JSON.parse(payload, symbolize_names: true)
p data # => {title: "Ico", copies: 3, tags: ["game"], author: {name: "Ueda"}}
data.dig(:author, :name) # => "Ueda"
JSON.generate(data) # => "{\"title\":\"Ico\",\"copies\":3,\"tags\":[\"game\"],\"author\":{\"name\":\"Ueda\"}}"
p(data.to_json == JSON.generate(data)) # => true
{ 1 => :a, nil => :b, [1] => :c }.to_json # => "{\"1\":\"a\",\"\":\"b\",\"[1]\":\"c\"}"
JSON.parse(JSON.generate({ a: 1 })) # => {"a" => 1}
JSON.pretty_generate({ a: { b: [1, 2] } }).lines.size # => 8

Choosing between Hash, Struct, Data and a class

A Hash is the right tool for data whose keys are not known in advance or vary per instance: counters, indexes, caches, grouped results, parsed JSON, option bags. It is the wrong tool for a record with a fixed set of fields, where a typo in a key silently yields nil and nothing documents or validates the shape.

Two common upgrades: convert a record-like Hash at the boundary into a Data (Shelf::Book.new(**attributes)) and work with that inside the program, and replace OpenStruct (a bundled gem since Ruby 4.0 and slow) with Struct or Data. See Struct, Data and Value Objects.

Threads and performance notes

Threads. A Hash has no internal locking. On MRI the global VM lock makes single operations such as []= safe from corrupting the table, but a compound step (check, then insert; h[k] += 1; a default proc that stores) is not atomic, and other Ruby implementations do not offer even that guarantee. Share a mutable hash between threads only behind a Thread::Mutex, as the shelf Catalog does with its store, or share frozen data. A mutable hash cannot be reached from another Ractor unless it is made shareable (deeply frozen) first. See Threads and the GVL.

Performance. Lookups, inserts and deletes are constant time on average; building a hash from n pairs is linear. Practical guidance, without microbenchmarks that would age badly:

  • Pass capacity: (3.4) to Hash.new when a large hash is built incrementally and the size is known.

  • Symbol and Integer keys hash faster than long Strings, whose hash is computed from their bytes; do not convert the keys of a large external dataset to Symbols just for speed.

  • compare_by_identity avoids calling hash and eql? on the keys and suits per-object caches.

  • merge allocates a new table; in a loop that accumulates, merge!/update or each_with_object avoid the copies.

  • transform_values and to_h { } build the result in one pass; map { }.to_h allocates an intermediate Array.

  • keys.each or values.each allocate Arrays; prefer each_key and each_value.

  • value?, key and rassoc scan every pair; if reverse lookup is frequent, keep an inverted hash.

For measuring rather than guessing, see Performance, Benchmarking and Profiling.

Where older books and tutorials are outdated

Older claim or idiom Ruby 4.0 reality

Hashes print as {:name=>"Ico"}

Since 3.4 they print as {name: "Ico"}; update any test that compares inspect text.

Hashes are unordered

Insertion order is guaranteed (since 1.9), including for first, shift and each.

Hash#select and reject return Arrays (Ruby 1.8)

They return Hashes; map and most other Enumerable methods still return Arrays.

Hash#index(value) finds a key

Removed; use key(value).

except, symbolize_keys, deep_merge, with_indifferent_access come from ActiveSupport

except is core since 3.0. symbolize_keys is transform_keys(&:to_sym), deep_merge needs a recursive merge block, and indifferent access is not in core.

Options are passed as a trailing options Hash that converts to keywords

Positional and keyword arguments are separated since 3.0; use **options explicitly.

Hash#each yields two values to a lambda

It yields one two-element array (3.0); only blocks and procs destructure.

Build hashes with inject({}) or map { }.to_h

Use to_h { }, each_with_object, tally, group_by, transform_values and filter_map.

Hash#shift on an empty hash returns the default

It returns nil (3.2).

OpenStruct for dot access to a hash

Use Data or Struct; OpenStruct is a bundled gem since 4.0.
