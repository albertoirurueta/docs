IO, Files and Directories

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Ruby 4.0 (4.0.7, checked on 2026-10-18); features newer than Ruby 3.0 name the version that introduced them. Every Ruby program talks to the outside world through file descriptors: standard input and output, files, directories, pipes and sockets. Ruby wraps them in a small family of classes: IO is the base class with the reading, writing and buffering behavior, File adds the file system (names, permissions, locking), Dir lists and creates directories, Pathname is an object-oriented view of a path, FileUtils is the shell-like toolbox (mkdir -p, cp -r, rm -rf), and Tempfile and StringIO give you scratch files and in-memory streams that behave like files. This page covers all of them: opening and closing files safely, modes and flags, encodings and newline conversion, reading and writing whole files, lines, bytes and chunks, paths and metadata, links, globbing, Pathname (a core class from Ruby 4.0), FileUtils, temporary files, StringIO, IO::Buffer, pipes, non-blocking reads, locking, atomic replacement, error handling and path safety.

Neighboring topics live elsewhere: how strings carry encodings is in Encodings and Unicode, spawning programs and the removal of Kernel#open("|cmd") in 4.0 are in Processes, Signals and Shell, sockets and HTTP are in Networking and HTTP, reading and writing JSON, YAML, CSV and Marshal is in Serialization: JSON, YAML, CSV and Marshal, the Errno exception classes are placed in the hierarchy by Exceptions and Error Handling, and the safety side of file names and temporary files is revisited in Security. For the same ideas in other languages see Go, Rust and Python.

Every example on this page was syntax-checked with ruby -wc, run with ruby -w on Ruby 4.0.7 and linted with RuboCop using the configuration of the running shelf gem (target Ruby 4.0, double-quoted strings), apart from one deliberate exception that is marked where it occurs. The output shown is the real output. Examples that create files work inside a directory made by Dir.mktmpdir, which is removed when its block ends, so they leave nothing behind; temporary directory names are abbreviated in the output, and examples were run with a UTF-8 locale. Each example is self-contained; the ones that use the shelf scenario say so.

Opening and closing files

File.open with a block

A file descriptor is a limited operating-system resource, and a buffered stream can hold unwritten data, so every file that is opened must be closed. The idiom that makes this automatic is the block form: File.open(path, mode) { |file| ... } opens the file, yields it, closes it when the block ends (normally, through break or return, or through an exception) and returns the value of the block. Without a block, File.open and File.new return an open file and you must call close yourself, normally inside an ensure. Using a closed stream raises IOError with the message closed stream.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "notes.txt")

  # The block form closes the file when the block ends, even on an exception.
  result = File.open(path, "w") do |file|
    file.puts "first line"
    file.class
  end
  puts "block value: #{result}"

  leaked = nil
  begin
    File.open(path) do |file|
      leaked = file
      raise "boom"
    end
  rescue RuntimeError => e
    puts "rescued #{e.message}, closed? #{leaked.closed?}"
  end

  # Without a block you own the file and must close it.
  file = File.new(path)
  puts file.read
  file.close
  puts "closed? #{file.closed?}"

  begin
    file.read
  rescue IOError => e
    puts "#{e.class}: #{e.message}"
  end

  # IO#path (3.2) returns the path the file was opened with.
  puts File.open(path, &:path) == path
end

Output:

block value: File
rescued boom, closed? true
first line
closed? true
IOError: closed stream
true

Source: Ruby 4.0 documentation: File and IO

The one-shot class methods File.read, File.write, File.readlines, File.foreach and their binread and binwrite variants open and close the file for you, so use them whenever the whole operation is a single call. Reach for the block form of File.open when you need several operations on one handle or a specific mode. IO#path (Ruby 3.2) returns the path a file was opened with, and File.new and File.open accept the same arguments; File.open with a block is the one that closes for you.

A file that is garbage collected without being closed is closed by a finalizer, but you cannot predict when, and written data is only guaranteed to be flushed by close or flush. Do not depend on it.

Modes and flags

The second argument of File.open is a mode string, an integer made from File::Constants flags, or absent (read-only). The keyword form mode:, flags: and perm: is equivalent and often clearer.

Mode Meaning

"r"

Read only, starting at the beginning. The file must exist (Errno::ENOENT otherwise). The default.

"r+"

Read and write, starting at the beginning, without truncating. The file must exist.

"w"

Write only. Creates the file or truncates it to zero length.

"w+"

Read and write. Creates or truncates.

"a"

Write only, every write at the end of the file (append). Creates the file if needed.

"a+"

Read and append. Reads start at the beginning, writes go to the end.

"b" suffix

Binary mode ("rb", "wb"): no newline conversion, and the external encoding is ASCII-8BIT unless you name one.

"t" suffix

Text mode ("rt"): universal newline conversion on read.

"x" suffix

With "w" only ("wx"): fail with Errno::EEXIST if the file exists, which makes creation exclusive and race-free.

":enc" suffix

An external (and optionally internal) encoding, "r:iso-8859-1:utf-8".

 
# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "log.txt")

  File.write(path, "one\n")
  File.open(path, "a") { |f| f.puts "two" }
  puts File.read(path).inspect # => "one\ntwo\n"

  File.open(path, "r+") do |f|
    f.write("ONE")
    f.rewind
    puts f.read.inspect
  end

  File.open(path, "w") { |f| f.print "truncated" }
  puts File.size(path)

  # "x" adds File::EXCL: fail if the file exists.
  begin
    File.open(path, "wx") { |f| f.puts "never" }
  rescue Errno::EEXIST => e
    puts "#{e.class}: #{e.message.sub(dir, '<dir>')}"
  end
end

The integer form is the one that exposes everything the operating system offers. The flags are the constants in File::Constants (also reachable as File::RDONLY and so on): RDONLY, WRONLY, RDWR, APPEND, CREAT, EXCL, TRUNC, NONBLOCK, NOCTTY, SYNC, DSYNC, NOFOLLOW, BINARY and SHARE_DELETE. Combine them with |. The third argument is the permission mask applied when the file is created (before the process umask), in octal. A new file that holds anything sensitive should be created with a restrictive mask such as 0o600.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  # Integer flags and a permission argument.
  flags = File::WRONLY | File::CREAT | File::TRUNC
  path = File.join(dir, "private.txt")
  File.open(path, flags, 0o600) { |f| f.puts "first" }
  puts format("%o", File.stat(path).mode & 0o777)

  # Keyword form of mode:, flags: and perm:.
  File.open(path, mode: "a", perm: 0o600) { |f| f.puts "more" }
  puts File.readlines(path, chomp: true).inspect

  begin
    File.open(File.join(dir, "missing.txt"))
  rescue Errno::ENOENT => e
    puts "#{e.class}: #{e.message.sub(dir, '<dir>')}"
    puts e.errno == Errno::ENOENT::Errno
  end
end

File::NULL is the platform’s null device (/dev/null, or NUL on Windows), handy as a sink. IO#sync = true turns off Ruby’s write buffering for that stream, IO#flush pushes buffered data to the operating system, and IO#fsync and IO#fdatasync ask the operating system to push it to the disk; they are the difference between "written" and "durable".

Kernel#open and other shortcuts

Kernel#open("path") opens a file like File.open, but until Ruby 3.3 a path starting with | ran a shell command instead (deprecated in 3.3 together with the same behavior of IO.read, IO.readlines, IO.foreach, IO.write, IO.binread and URI.open). In Ruby 4.0 that behavior is removed: all of these now treat the string as a file name, and a name such as "|echo hi" raises Errno::ENOENT. Use File.open (or File.read) for files and Open3 or IO.popen with an argument array for programs; the processes page covers the command-injection reasons.

Encodings and newlines

A file holds bytes; Ruby turns them into strings with an encoding. Every IO has an external encoding (how the bytes in the file are interpreted) and an optional internal encoding (what the strings you get should be converted to). The external encoding defaults to Encoding.default_external, which comes from the locale (LANG, LC_ALL) and is UTF-8 on a typical modern system; with no internal encoding set, strings are tagged with the external encoding and no conversion happens. Setting both, as in "r:iso-8859-1:utf-8", makes Ruby transcode while reading. Writing converts from the string’s encoding to the external encoding when they differ. The command-line flags -E ext:int and -U change the defaults for the whole process.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "latin1.txt")
  File.binwrite(path, "caf\xE9\n".b)

  File.open(path) { |f| puts f.read.encoding } # default external, UTF-8
  File.open(path, "r:iso-8859-1") { |f| puts f.read.encoding }

  # external:internal transcodes while reading.
  File.open(path, "r:iso-8859-1:utf-8") do |f|
    text = f.read
    puts "#{text.inspect} #{text.encoding}"
  end

  # Keyword form.
  text = File.read(path, encoding: "iso-8859-1:utf-8")
  puts text.valid_encoding?

  # Writing transcodes from the string encoding to the external one.
  out = File.join(dir, "out.txt")
  File.write(out, "café", encoding: "iso-8859-1")
  p File.binread(out) # => "caf\xE9"

  # Byte order marks: "bom|utf-8" strips a UTF-8 BOM.
  bom = File.join(dir, "bom.txt")
  File.binwrite(bom, "\xEF\xBB\xBFhello".b)
  p File.read(bom).start_with?("\uFEFF")
  p File.read(bom, encoding: "bom|utf-8")

  # Binary mode: no newline conversion, ASCII-8BIT strings.
  File.open(path, "rb") { |f| puts f.read.encoding }
  puts Encoding.default_external
end

Things to remember:

  • A file with a byte order mark needs "bom|utf-8": without it the BOM stays in the string as "﻿" and breaks the first comparison or CSV header. IO#set_encoding_by_bom does the same on an already-open binary stream.

  • Binary mode ("rb", File.binread, IO#binmode) gives ASCII-8BIT (Encoding::BINARY) strings and disables newline and encoding conversion. Use it for images, archives, Marshal data and anything you pass to pack and unpack.

  • Reading invalid bytes does not raise: the string just reports valid_encoding? as false, and the error surfaces later, for example in a regular expression match. Transcoding with "r:ext:int" does raise Encoding::InvalidByteSequenceError or Encoding::UndefinedConversionError, unless you pass invalid: :replace and undef: :replace (with replace:).

  • Encoding.default_internal is nil unless you set it; setting it globally is discouraged because every library then gets transcoded text.

Newline conversion

On Unix a file is read as is: a CRLF line ending keeps its \r. Text mode ("rt") or the universal_newline: true option converts CRLF and CR to LF on read, and crlf_newline: true or cr_newline: true converts LF on write (newline: :universal, :crlf, :cr and :lf are the keyword spellings). chomp: true on the line-reading methods strips either ending. On Windows, text mode (the default there) converts automatically, which is why files written on one system sometimes carry stray \r on the other.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "crlf.txt")
  File.binwrite(path, "a\r\nb\r\n")

  p File.read(path)                                     # binary-safe default on Unix
  p File.read(path, mode: "rt")                         # text mode, universal newlines
  p File.open(path, universal_newline: true, &:read)
  p File.readlines(path, chomp: true)                   # chomp strips CRLF too

  out = File.join(dir, "out.txt")
  File.open(out, "w", crlf_newline: true) { |f| f.puts "x" }
  p File.binread(out)

  File.open(path) do |f|
    f.timeout = 2.5 # IO#timeout raises IO::TimeoutError on blocking reads
    puts f.timeout
    f.sync = true
    f.fsync
    f.fdatasync
  end
  puts IO::TimeoutError.ancestors.first(3).inspect
end

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|

  puts "wrote #{bytes} bytes"

  puts File.read(path, 4).inspect         # first four bytes
  puts File.read(path, 4, 5).inspect      # four bytes from offset 5
  p File.readlines(path)

  File.foreach(path, chomp: true).with_index(1) do |line, number|
    puts "#{number}: #{line}"
  end
end

File.read(path) loads the whole file into one string, which is simple and fast for files up to a few megabytes and wrong for a log file of several gigabytes. For big inputs iterate with File.foreach, IO#each_line or IO#read(size) in a loop. For copying use IO.copy_stream (below), which does not build the file in memory. File.write replaces the file in place: if your program is killed in the middle, the file is truncated or partial; the atomic replacement pattern later in this page avoids that.

The cursor: gets, readline, each_line, seek

An open file has a position. gets returns the next line (including its newline) or nil at the end of the file; readline does the same but raises EOFError at the end, which suits a protocol where the end is unexpected. read without an argument reads to the end and returns "" at the end of the file, while read(n) returns nil at the end. eof? tests the position, pos, seek, rewind and lineno move and report it, IO::SEEK_SET, IO::SEEK_CUR and IO::SEEK_END select the reference point (seek also accepts :SET, :CUR and :END symbols). each_line, each_char, each_byte, readlines and readchar and readbyte read from the cursor, and the line methods accept a separator ("\n" by default; nil means "everything"; "" means "paragraph mode", split on blank lines), a byte limit and chomp: true.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "books.txt")
  File.write(path, "Dune\nEmma\nUlysses\n")

  File.open(path) do |file|
    puts file.gets.inspect
    puts file.lineno
    puts file.readline(chomp: true)
    puts file.pos
    file.each_line { |line| puts "rest: #{line.chomp}" }
    puts file.eof?
    puts file.gets.inspect # nil at end of file
    begin
      file.readline
    rescue EOFError => e
      puts "#{e.class}: #{e.message}"
    end
    file.rewind
    file.seek(-8, IO::SEEK_END)
    puts file.read.inspect
  end
end

Reading in a loop of read(size) until eof? or read returns nil is the pattern for binary data. IO#readpartial(maxlen) returns whatever is available (at least one byte) and raises EOFError at the end: it is the right call for pipes and sockets, where read(n) would wait for all n bytes. IO#pread(length, offset) and IO#pwrite(string, offset) read and write at an offset without moving the position, which avoids races on the shared position when several threads read one file.

Writing

puts writes its arguments each followed by a newline (and flattens arrays), print writes without adding anything, write writes any number of strings and returns the byte count, << writes one object and returns the stream so calls chain, and printf formats. Output is buffered by Ruby; close flushes, and so does flush or sync = true. In "a" mode every write goes to the end even if you seek elsewhere.

# frozen_string_literal: true

require "tmpdir"

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "books.txt")
  File.write(path, "Dune\nEmma\nUlysses\n")

  File.open(path, "a") do |file|
    file << "Hamlet" << "\n"
    file.printf("%-8s|\n", "pad")
    file.write("a", "b", "\n")
  end
  puts File.read(path)

  # Reading in chunks keeps memory use flat.
  chunks = []
  File.open(path) { |f| chunks << f.read(10) until f.eof? }
  p chunks.map(&:size)

  # Splitting by a separator or limit.
  File.open(path) { |f| p f.gets("a") }
  File.open(path) { |f| p f.gets(nil, 6) }
  File.open(path) { |f| p f.each_char.first(3) }
  File.open(path) { |f| p f.each_byte.first(3) }
end

File.exists? and Dir.exists? were deprecated for years and are removed in Ruby 3.2: calling them raises NoMethodError. The fix is the singular exist?. Directories

Listing

Dir.children(dir) returns the entry names except . and .., Dir.entries(dir) includes them, and Dir.each_child(dir) and Dir.foreach(dir) iterate without building an array. The order is whatever the file system returns: it is neither alphabetical nor stable, so sort when the order matters. Names are bare names, not paths; join them with the directory. Dir.empty?(dir) tests for an empty directory, and Dir.exist? for existence. Dir.mkdir(path, mode) creates one level (the parent must exist), Dir.rmdir removes an empty directory (Errno::ENOTEMPTY otherwise), and FileUtils.mkdir_p and rm_rf handle trees.

Dir.glob

Dir.glob(pattern, flags = 0, base: nil, sort: true) (also Dir[]) expands shell-style patterns and returns an array of paths:

Pattern Matches

*

Any run of characters within one path segment; does not match a leading dot.

**/

Zero or more directories, recursively: lib/**/*.rb finds Ruby files at any depth.

?

Exactly one character.

[ab], [a-c], [^a]

One character from the set, the range, or not in the set.

{rb,txt}

Alternatives; the braces expand before matching, so *.{rb,txt} lists both.

a backslash

Tempfile.create and Dir.mktmpdir are the supported ways to get scratch space. StringIO

StringIO implements the IO interface over a string: gets, each_line, read, write, puts, printf, <<, rewind, seek, ungetc, eof? and so on. Use +"..." or String.new for a writable buffer.

Pipes, readiness and locks

Pipes and non-blocking reads

IO.pipe returns a connected reader and writer: whatever one thread or process writes, the other reads. The reader sees end of file only after every copy of the writer is closed, a common source of hangs when a forked child still holds one. A blocking read or gets waits for data. IO#wait_readable(timeout) waits until a stream is ready (and returns nil on timeout), IO#read_nonblock(n) never blocks and raises IO::WaitReadable (IO::EAGAINWaitReadable) when nothing is available, unless you pass exception: false, in which case it returns :wait_readable; at the end of file it raises EOFError or returns nil with exception: false. write_nonblock is the mirror. IO.select(readers, writers, errors, timeout) waits on several streams at once and returns the ready ones (nil on timeout; since 4.0 the timeout may be Float::INFINITY). Under a fiber scheduler these calls yield to other fibers instead of blocking the thread.

# frozen_string_literal: true

reader, writer = IO.pipe
writer.puts "from the writer"
writer.close
puts reader.read
reader.close

r, w = IO.pipe
p r.wait_readable(0.1) # nothing to read yet
w.write "x"
puts r.wait_readable(0.1) == r
puts r.read_nonblock(10)
begin
  r.read_nonblock(10)
rescue IO::WaitReadable => e
  puts e.class
end
p r.read_nonblock(10, exception: false)
w.close
p r.read_nonblock(10, exception: false) # nil at end of file
r.close

# IO.select waits on several IO objects at once.
a_r, a_w = IO.pipe
b_r, b_w = IO.pipe
b_w.write "b is ready"
ready, = IO.select([a_r, b_r], nil, nil, 0.1)
puts ready.map { |io| io == b_r }.inspect
[a_r, a_w, b_r, b_w].each(&:close)

Locking and atomic replacement

File#flock takes an advisory lock: File::LOCK_SH (shared), File::LOCK_EX (exclusive), optionally ORed with File::LOCK_NB to return false instead of waiting, and File::LOCK_UN to release. Advisory means that it only constrains programs that also call flock; a program that ignores locking can still write. The lock is released when the file is closed, which is another reason to use the block form. Never truncate a file before locking it: open without "w", lock, and then truncate.

To replace a file so that readers see either the old or the new content and never a partial file, write a temporary file in the same directory (a rename is atomic only inside one file system) and rename it over the target.

# frozen_string_literal: true

require "tmpdir"

# Replace a file atomically: write a sibling temp file, then rename over it.
def write_atomically(path, content)
  tmp = "#{path}.#{Process.pid}.tmp"
  File.write(tmp, content)
  File.rename(tmp, path)
end

Dir.mktmpdir("shelf") do |dir|
  path = File.join(dir, "catalog.txt")
  write_atomically(path, "v1\n")
  write_atomically(path, "v2\n")
  puts File.read(path)

  # Advisory locking with flock; the lock is released on close.
  File.open(path, File::RDWR | File::CREAT) do |file|
    file.flock(File::LOCK_EX)
    file.truncate(0)
    file.write("locked write\n")
    file.flush
    File.open(path) { |other| puts other.flock(File::LOCK_SH | File::LOCK_NB) }
  end
  puts File.read(path)
end

Errors

File operations raise Errno:: classes, all subclasses of SystemCallError, which carry the C error name, the message from the operating system, the function that failed (@ rb_sysopen) and the path. SystemCallError#errno returns the number. IOError signals a misuse of the stream (closed, not opened for that direction) and EOFError, a subclass of IOError, signals reading past the end. Rescue the narrowest class that you can handle and let the rest propagate.

Errno::EISDIR, Errno::ENOTDIR

A directory where a file was expected, or a file used as a directory component.

Errno::ENOTEMPTY

Errno::ENOSPC, Errno::EDQUOT

Safe handling of paths

  • Never trust a name from outside. A user-supplied name such as "../../etc/passwd" or an absolute path escapes the directory you meant. Resolve the candidate against the root with File.expand_path and check that the result still starts with the root plus the separator. File.join(root, name) alone does not stop .., and an absolute name is not safe with Pathname#join or Pathname#+ (it replaces the root). Use realpath when symbolic links are involved, because a link inside the root can point outside it.

  • A file name containing a null byte raises ArgumentError before the system call, so the classic null-byte truncation trick fails in Ruby.

  • Do not interpolate names into shell strings; pass an argument array to system, spawn or Open3, see Processes, Signals and Shell.

  • Create files with the narrowest mode they need (0o600 for secrets) and exclusively ("wx") when overwriting would be a bug.

  • Use Tempfile and Dir.mktmpdir, not predictable names, and remove_entry_secure when deleting in shared directories.

  • Load data from files with the safe loaders (JSON.parse, YAML.safe_load); Marshal.load and YAML.unsafe_load on a file someone else wrote can execute code, see Security.

# frozen_string_literal: true

require "tmpdir"

# Resolve a user-supplied name inside a root directory, or return nil.
def inside(root, name)
  base = File.realpath(root)
  full = File.expand_path(name, base)
  full if full.start_with?("#{base}#{File::SEPARATOR}")
end

Dir.mktmpdir("shelf") do |root|
  puts inside(root, "books.csv").sub(File.realpath(root), "<root>")
  p inside(root, "../etc/passwd")
  p inside(root, "/etc/passwd")

  begin
    File.read("books\0.csv")
  rescue ArgumentError => e
    puts "#{e.class}: #{e.message}"
  end
end

Common pitfalls:

  • File.open without a block and no close leaks a descriptor; a long-running process then fails with Errno::EMFILE.

  • File.readlines and File.read on a huge file exhaust memory; stream instead.

  • File.write overwrites; use mode: "a" to append.

  • gets in a script reads ARGF, not standard input, when arguments are present.

  • Dir.children and Dir.glob(sort: false) have no stable order, and Dir.children returns names rather than paths.

  • Dir.chdir is process-wide and raises in a second thread’s block; build absolute paths instead.

  • Dir.glob does not match hidden files unless File::FNM_DOTMATCH is given, and * never crosses a directory separator.

  • Output to a pipe is buffered; set $stdout.sync = true or flush when timing matters.

  • An exception during a write can leave a partial file: replace atomically for anything important.

  • Text read on Unix keeps \r; use chomp: true or "rt" for files that may come from Windows.

  • A StringIO over a frozen literal is read-only.

  • Tempfile.new files are removed when the object is collected: keep a reference for as long as another process needs the name.
