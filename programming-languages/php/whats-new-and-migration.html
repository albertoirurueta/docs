What’s New and Migration

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against PHP 8.5, checked on 2026-10-05. PHP 8.5 is the current release (latest patch 8.5.11, 2026-09-24). PHP 8.6 is upcoming: it was at RC2 on that date, with general availability scheduled for 2026-11-19, so 8.6 items below are marked as upcoming and may still change. Every other page in this section marks the version that introduced a feature; this page puts the versions side by side.

Release by release

Each release has a migration guide in the PHP Manual listing new features, backward-incompatible changes and deprecations. Read the guides of every version between the one you run and the one you move to.

Support timeline

Each release gets two years of active support (bug and security fixes), then two years of security fixes only. Since a 2024 policy change, both periods end on 31 December, which also extended 8.1 to the end of 2025. After that a branch is end of life: it receives no fixes at all, including for actively exploited vulnerabilities.

Libraries and frameworks set their own minimums. Laravel 13 requires PHP 8.3 to 8.5, and the next major version is expected to require 8.4. Composer’s "php" constraint in composer.json and config.platform.php make the requirement explicit (see Composer and Packages).

Deprecations and removals

PHP removes features in two steps. A minor release deprecates a feature: it still works, but emits an E_DEPRECATED notice (a soft deprecation is documented only, with no notice). The next major release (8.0, then 9.0) removes it. The table lists the deprecations that most often appear in real code.

    echo "line $line: $message\n";

    public function rename(string $name = null): void {}    // implicitly nullable parameter (8.4)

The fixes are mechanical: ?string $name = null, a declared property (or #[\AllowDynamicProperties] as a stopgap), {$name}, (int), str_increment($version) and IntlDateFormatter.

PHP 9

No release date is set for PHP 9.0, but several RFCs have already been accepted for it. Undefined variables will throw an Error instead of a warning. "${var}" interpolation will be removed. Autovivification on false ($x = false; $x[] = 1;, which silently turns $x into an array) will throw. In general, every feature deprecated during the 8.x series is a candidate for removal in 9.0, so code that runs on 8.5 without deprecation notices is the best preparation.

Source: RFC: Undefined variable error promotion, RFC: Deprecate ${} string interpolation and RFC: Deprecate autovivification on false

How to upgrade

  1. Read the migration guides for every version you skip, especially the backward-incompatible changes.

  2. Make deprecations visible. Run the test suite and staging with error_reporting=E_ALL and log E_DEPRECATED; PHPUnit’s failOnDeprecation="true" and displayDetailsOnTestsThatTriggerDeprecations="true" turn them into test failures (see Testing with PHPUnit and Pest).

  3. Check compatibility statically. PHPStan reports calls to deprecated functions with its deprecation-rules extension, and the PHPCompatibility sniffs for PHP_CodeSniffer report syntax and functions that do not exist or are removed in a target version.

  4. Rewrite automatically. Rector’s PHP sets apply each version’s upgrades (constructor promotion, match, readonly, explicit nullable types, …​). Review the diff like any other change; see Static Analysis and Refactoring.

  5. Upgrade dependencies with Composer, raising the "php" constraint last.

  6. Run the new version in CI alongside the old one before switching production.

<?php
// rector.php -- upgrade a code base to PHP 8.5 syntax
use Rector\Config\RectorConfig;

return RectorConfig::configure()
    ->withPaths([__DIR__ . '/src', __DIR__ . '/tests'])
    ->withPhpSets(php85: true);    // or withPhpSets() to follow composer.json's "php" constraint

Source: Rector — Documentation and PHPCompatibility

vendor/bin/rector process --dry-run      # show the changes as a diff
vendor/bin/rector process                # apply them
vendor/bin/phpcs -p src --standard=PHPCompatibility --runtime-set testVersion 8.5-
