Spring AI

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This sub-section was written against Spring AI 2.0.1, Spring Boot 4.1.x (4.1.1) and Java 21, with the full list in the version baseline below, all read from Maven Central, the Spring AI reference and its upgrade notes on 2026-09-29. Where an individual page and that baseline ever disagree after a later update, the baseline is the one to trust. Every Java snippet on the pages was compiled against the real 2.0.1 jars in a scratch Maven project, and most were run against a scripted ChatModel, a WireMock stand-in for the provider API or a local Ollama container; each page says in its lead paragraph what was run and what was compiled only.

Spring AI is the Spring project for building applications on large language models. It gives Java developers the same things Spring gives them for databases and messaging: portable interfaces for each kind of model, Spring Boot starters that wire a provider from a few properties, and the usual Spring idioms — dependency injection, Micrometer observations, Spring Security, Testcontainers — applied to prompts, tools, memory and retrieval. On top of the interfaces sits ChatClient, a fluent API with a chain of advisors that add conversational memory, retrieval, the tool-calling loop and guardrails around each call. The project also ships a Model Context Protocol (MCP) client and server, so a Spring application can use remote tools or publish its own.

This page is the map of the sub-section: the layers of the framework, the version table, the provider families, a suggested reading order, the running example and the bibliography that all the pages draw on.

The abstraction layers

Application code talks to the upper layers only. A starter brings a provider module and its auto-configuration, the auto-configuration reads spring.ai.* properties and registers beans for the portable interfaces, and the code injects those interfaces or a ChatClient.Builder. Changing provider is therefore mostly a matter of changing a dependency and a few properties. The portable interfaces in the 2.0.1 jars are:

Integrating with Spring AI: the VectorStore API

ChatModel, EmbeddingModel, ImageModel, TranscriptionModel, TextToSpeechModel and ModerationModel all extend the generic Model<TReq, TRes> interface in org.springframework.ai.model. ChatMemory sits beside them as the store of conversation history (Chat Memory). The class below uses two of the interfaces and never names a provider; the starter on the classpath decides which models answer.

A provider-neutral DocsAssistant service
package com.example.docsassistant;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.stereotype.Service;

@Service
public class PortableDocsAssistant {

    private final ChatClient chatClient;
    private final EmbeddingModel embeddingModel;

    // The builder and the embedding model come from whichever starter is on the
    // classpath (Ollama here); this class never names a provider.
    public PortableDocsAssistant(ChatClient.Builder builder, EmbeddingModel embeddingModel) {
        this.chatClient = builder
                .defaultSystem("You answer questions about the Irurueta documentation.")
                .build();
        this.embeddingModel = embeddingModel;
    }

    public String ask(String question) {
        return chatClient.prompt()
                .user(question)
                .call()
                .content();
    }

    public int embeddingDimensions() {
        return embeddingModel.dimensions();
    }
}

Version baseline

Every version below was read from Maven Central and the official documentation on 2026-09-29. Each page repeats the subset it uses in its own lead paragraph.

Area Versions

Spring AI

2.0.1, the current stable release, managed by org.springframework.ai:spring-ai-bom:2.0.1. 2.0.0 went GA on 2026-06-12 (release announcement). A 2.1 milestone exists; nothing in this sub-section depends on it.

Spring Boot and Java

Spring AI 2.0.x supports Spring Boot 4.0.x and 4.1.x; the examples use Spring Boot 4.1.1, Spring Framework 7, Jackson 3 (tools.jackson.*) and JSpecify null-safety annotations. Java 17 is the minimum; every example uses Java 21 with Maven.

MCP

The MCP Java SDK (io.modelcontextprotocol.sdk) 2.0.0 as resolved by Spring AI 2.0.1 (2.0.1 is the latest on Maven Central); the community org.springaicommunity:mcp-server-security and mcp-client-security 0.1.14 for OAuth and API keys.

Agents

The community org.springaicommunity:spring-ai-agent-utils 0.12.0 and Embabel 1.5.2 (com.embabel.agent:embabel-agent-starter).

Models and stores

Ollama with llama3.1:8b for chat and nomic-embed-text (768 dimensions) for embeddings, PostgreSQL 17 with pgvector 0.8.6, and ollama/ollama:0.34.4 for Testcontainers — the same as the rest of the AI section. The hosted models used elsewhere (claude-sonnet-5, claude-opus-5-5, claude-haiku-4-5, claude-fable-5-1, gpt-6-sol) appear only in provider matrices and option examples.

The MCP versions come with a skew that matters when you mix Spring AI with the rest of this site. The protocol constants of the MCP Java SDK 2.0.x stop at the 2025-11-25 revision of the specification, while the site’s Model Context Protocol reference is written against the 2026-07-28 revision. A Spring AI 2.0.x server or client therefore speaks 2025-11-25 (the initialize handshake, Streamable HTTP with sessions), and the features that exist only in 2026-07-28 — the stateless request core, server/discover, multi-round-trip requests — are not available yet. MCP Server and MCP Client spell out the consequences.

Material written for Spring AI 1.x, including every book in the bibliography, describes an older API. The differences that matter most, each flagged where it appears on the pages and collected on Migrating from 1.x to 2.x:

  • options classes are immutable builders changed with mutate(), and the .options segment was dropped from property paths (spring.ai.openai.chat.options.model became spring.ai.openai.chat.model);

  • ChatClient always registers the ToolCallingAdvisor, which runs the tool loop, and ChatModel.call() no longer executes tools by itself;

  • chat-memory advisors need a conversation ID, PromptChatMemoryAdvisor is gone, and tool messages are not stored;

  • the FunctionCallback API became ToolCallback, and SpringBeanToolCallbackResolver and toolNames() were removed;

  • the MCP annotations moved to org.springframework.ai.mcp.annotation, and the MCP Java SDK moved to 2.0;

  • the tool span is named execute_tool <tool-name> instead of tool_call <tool-name>.

Provider families

Spring AI groups providers by how they are reached. The table is a summary; the full starter list, and what each provider supports, is on Setup & Starters and the reference’s Chat Models Comparison.

Family Starters

Local runtimes

spring-ai-starter-model-ollama (the DocsAssistant default), local ONNX embeddings with spring-ai-starter-model-transformers, and OpenAI-compatible local servers (Docker Model Runner, vLLM, llama.cpp, LM Studio, Foundry Local) through the OpenAI starter — see Local Models

OpenAI and OpenAI-compatible APIs

spring-ai-starter-model-openai, with spring.ai.openai.base-url pointed at a compatible endpoint; chat, embeddings, images, transcription, speech and moderation

Anthropic, Google, Mistral AI, DeepSeek

spring-ai-starter-model-anthropic, spring-ai-starter-model-google-genai, spring-ai-starter-model-mistral-ai, spring-ai-starter-model-deepseek

Cloud platforms

spring-ai-starter-model-bedrock-converse and spring-ai-starter-model-bedrock for Amazon Bedrock

Specialised

spring-ai-starter-model-elevenlabs (speech), spring-ai-starter-model-stability-ai (images)

With more than one starter of the same kind on the classpath, choose the active one with spring.ai.model.chat, spring.ai.model.embedding, spring.ai.model.image, spring.ai.model.audio.speech, spring.ai.model.audio.transcription or spring.ai.model.moderation.
