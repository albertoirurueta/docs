A short worked example that combines the permission rule syntax with a skill: a committed .claude/settings.json that allows the test command, asks before pushing and denies reading .env, followed by a minimal SKILL.md.

{
  "permissions": {
    "allow": ["Bash(mvn test)", "Read(./docs/**)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)"]
  }
}
---
name: run-tests
description: Runs the project's unit tests and summarises failures. Use when asked to verify a change.
allowed-tools: Bash(mvn test)
---

Run `mvn test`, then list each failing test with its first error line.

With these files in place a call to mvn test runs without prompting, git push asks first and a read of .env is blocked, because deny rules are checked before ask and allow rules.
