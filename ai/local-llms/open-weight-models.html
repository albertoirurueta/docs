Open-Weight Models

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was written on 2026-09-28 with Ollama 0.34.4 and vLLM 0.30.0 for the examples (see the Running LLMs Locally baseline), and its table was re-checked against the Hugging Face model cards (license: metadata, model card text and config.json) on 2026-09-29. Model generations move fast: treat the table as a snapshot of that date, not a ranking. The Checked against column says where each row was verified — confirm it on the model card before you ship.

The conceptual landscape — closed vs. open models, providers, how model families relate — is on The Model Landscape; this page is about which open weights to download and run.

Licence classes

Open weights are not the same thing as open source, and the licence decides whether you may use a model at all:

  • Permissive (Apache-2.0, MIT) — use, modify, fine-tune and redistribute, commercially, with attribution. Apache-2.0 adds an explicit patent grant. Qwen3.6, Qwen3.8-27B, Gemma 4, Mistral Small 4, Ministral 3, Devstral Small 2 and gpt-oss (Apache-2.0), and DeepSeek V3.2 / V4 and Phi-4 (MIT) are in this class. This is the class to prefer for anything you ship.

  • Community licences — custom terms written by the vendor. The Llama 4 Community License, for example, is a separate agreement with its own acceptable-use policy and conditions; older DeepSeek models used a "DeepSeek License" model agreement distinct from the MIT code licence; within Qwen3.8 the 2.4T-A95B (qwen3.8-max) and Flash-Next (qwen-community-1.0) models carry custom licences even though the 27B is Apache-2.0; and Devstral 2 123B’s "Modified MIT" licence excludes companies above USD 20M monthly revenue while Devstral Small 2 is Apache-2.0 — so a family name never tells you the licence; the individual repository does. Read the actual text: these licences can restrict use cases, require attribution in product names, or add conditions for very large deployments.

  • Gated — the Hub repository requires you to accept the licence (and sometimes share contact details) before downloading. Gating is a distribution mechanism, not a licence type: a gated model can carry a permissive or a community licence. Pass HF_TOKEN to the engine after accepting.

The licence of a Hub repository is in its model card metadata (license:), with the full text usually in a LICENSE file; see Hugging Face — Licenses. Quantized re-uploads (GGUF, AWQ) inherit the original licence — check the base model’s, not the uploader’s summary. This is engineering guidance, not legal advice; involve your legal team for anything customer-facing.

Choosing by task

Choose by task first, then by what fits (see Hardware Sizing); this site quotes no benchmark numbers, so evaluate the two or three candidates on your own prompts.

  • Coding and coding agents — use the coding-tuned variants (Devstral, Qwen-Coder, and the general Qwen3.6 / Qwen3.8 models, which their vendor positions for agentic coding). Tool-calling reliability and at least 64k context matter more than raw size for the assistants on Local Models in Claude Code and Local Models in GitHub Copilot.

  • Reasoning — models with a thinking mode (gpt-oss with adjustable reasoning effort, DeepSeek, Qwen’s hybrid reasoning, Phi-4-reasoning). They trade latency and tokens for accuracy; see Reasoning Models.

  • Tool use and agents — a model whose chat template supports tools (the Ollama library tags them), served with the right parser (--jinja in llama.cpp, --tool-call-parser in vLLM). MoE models with few active parameters (gpt-oss-20b, Qwen3.6-35B-A3B, Gemma 4 26B-A4B) are fast enough for multi-step loops on one GPU.

  • Multilingual — Qwen3.5 and later state support for 201 languages and dialects; Gemma and Mistral are also strong multilingual families. Test in your languages — 4-bit quantization hurts non-English text first (see Quality vs. size).

  • Embeddings — a separate, much smaller model: DocsAssistant uses nomic-embed-text; see Generating Embeddings in Practice.

  • On-device and in-app — the smallest variants (Gemma 4 E2B / E4B, Qwen3.5 0.8B-4B, Phi-4-mini) are covered in Small LLMs & Embeddings.

The same advice as a decision flow:

flowchart TD T{Primary task?} -->|Coding and agents| C[Coding-tuned model with reliable tool calls] T -->|Reasoning| R[Model with a thinking mode] T -->|Multilingual| M[Test in your own languages] T -->|Embeddings| E[Small dedicated embedding model] C --> F{Fits the memory budget?} R --> F M --> F F -->|No| Q[Smaller variant, MoE or a lower quant] F -->|Yes| V[Evaluate two or three candidates on your prompts] Q --> V

Example: serving an Apache-2.0 model in Ollama and vLLM

gpt-oss-20b is Apache-2.0, runs within 16 GB of memory thanks to its MXFP4 experts (per OpenAI’s README), and runs in both engines. In Ollama:

ollama pull gpt-oss:20b
ollama run gpt-oss:20b "Explain the difference between Apache-2.0 and a community licence in three bullets."

See the openai/gpt-oss README (Ollama section) and Ollama. On a GPU server with vLLM:

vllm serve openai/gpt-oss-20b --enable-auto-tool-choice --tool-call-parser openai
curl http://localhost:8000/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model": "openai/gpt-oss-20b", "messages": [{"role": "user", "content": "Hello"}]}'

See the openai/gpt-oss README (vLLM section) and vLLM — Online serving. The same pattern works for Qwen3.6 (ollama pull qwen3.6, vllm serve Qwen/Qwen3.6-27B) once you have checked its licence on the model card.
