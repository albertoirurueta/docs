Running LLMs Locally

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Examples across this sub-section were written against the following versions, all read from the projects' release tags, PyPI, npm and Maven Central on 2026-09-28: Ollama 0.34.4; llama.cpp v0.5.0 (the project now tags semantic-version releases alongside its bNNNN build tags — b11239 on that date — and ships both the unified llama serve binary and llama-server); vLLM 0.30.0; SGLang 0.5.20; Text Generation Inference v3.3.7 (maintenance mode); LM Studio 0.4; Jan v0.8.4; Docker Model Runner v1.2.8; LocalAI v4.10.0; mlx-lm 0.31.3; LiteLLM 1.103.0; llm-compressor 0.14.0; llama-cpp-python 0.3.35; Continue 2.1; Cline 4.1; Aider 0.86.2; OpenCode 1.18.33; GitHub Copilot CLI 1.0.89; and Claude Code 2.1.284. Client code uses Python 3.12 with openai 3.20.0, anthropic 1.9.0, langchain-ollama 1.1.0 and langchain-openai 1.6.6, and Java 21 with Spring Boot 4.1 and Spring AI 2.0.1 — the same Spring baseline as LLM Foundations & Prompting. Every running example uses DocsAssistant's own local models — Ollama llama3.1:8b for chat and nomic-embed-text for embeddings, as in Vector Databases & RAG — plus current open-weight models such as qwen3.6 and gpt-oss:20b where a page needs tool calling. Several documentation hosts (docs.ollama.com, docs.vllm.ai, lmstudio.ai, docs.nvidia.com, huggingface.co model cards and others) could not be reached from the checking environment; those projects' docs were read from their public source repositories instead, and each page says where a fact could not be verified. If a page and this baseline disagree after a later update, trust this baseline.

Why run locally

Hosted APIs are the default for good reasons — the strongest models, no hardware, no operations. Running an open-weight model yourself is worth it when one of these matters more:

  • Privacy and data residency — prompts, code and documents never leave your machine or your network. For regulated data, source code under strict policy, or customer data with residency rules, this can be the only acceptable option.

  • Cost at volume — a hosted API charges per token forever; a GPU you already own costs the same whether it serves a thousand requests or a million. At high, steady volume the balance can tip (the method, not prices, is on Running Local LLMs in Production).

  • Offline use — on a plane, in an air-gapped site, or when the provider has an outage.

  • Latency — no network round trip, no shared queue; a small local model can answer faster than a large remote one.

  • Control — a pinned model that never changes under you, no rate limits, no deprecations, and the freedom to quantize, fine-tune or constrain it.

The trade-offs

  • Quality gap — the best open-weight models are strong, but a model that fits a laptop is not a frontier model. Evaluate on your own tasks; pick the task, then the model (see Open-Weight Models).

  • Operations burden — you install, update, secure, monitor and scale the servers. Most local engines are unauthenticated by default, which makes security your job from day one.

  • Hardware — memory decides which models run at all, bandwidth decides how fast (see Hardware Sizing); a GPU server is a capital purchase with a lead time.

A common outcome is a mix: local models for private data, bulk and offline work, hosted models for the hardest tasks — with a gateway routing between them (see LLM Gateways).

DocsAssistant, locally

DocsAssistant, the running example of this site’s AI and vector-database sections, already runs its models locally: Ollama serves llama3.1:8b for chat and nomic-embed-text for embeddings. This sub-section takes that setup further. Every engine page ends with the same three clients — curl against the OpenAI-compatible endpoint, Python (the openai SDK with a base_url, then LangChain), and Spring AI — so moving DocsAssistant from Ollama to llama.cpp, vLLM or NIM is a base-URL change. The integration pages then point GitHub Copilot, Claude Code and the open coding assistants at the same local models.
