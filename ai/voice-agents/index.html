Voice Agents

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This sub-section was written on 2026-10-01 against LangChain 1.4.3 (with langchain-core 1.6.6 and langgraph 1.2.12) and FastAPI 0.142.2 on Python 3.12, Spring AI 2.0.1 on Spring Boot 4.1.x with Java 21, Pipecat 1.12.0, LiveKit Agents 1.8.3, OpenAI GPT-Live (gpt-live-1) and the Realtime API (gpt-realtime-2.1), the Gemini Live API (gemini-3.8-live), the ElevenLabs Python SDK 2.70.0, Twilio ConversationRelay and Media Streams, and Asterisk 23.5, 22.11 and 20.21; the full list is in the version baseline below. Versions and model names were read from PyPI, npm, Maven Central, GitHub releases and the vendors' own documentation on that date, and hosted model names change quickly, so every page tells you which model page to check before you copy an identifier. The code on the pages is illustrative: it is written from the official documentation of each platform and is not compiled by this repository. Real-time audio, Twilio and Asterisk could not be tested here, and each page says in its lead paragraph which steps were documented from official documentation only.

A retrieval-augmented assistant that only answers in a text box is not yet a product for people who are driving, cooking, walking through a warehouse or phoning a help line. The RAG Systems in Production sub-section builds the assistant, and Conversational Channels puts it behind chat surfaces. This sub-section adds the spoken channel: how audio gets to the assistant, how the answer gets back as speech quickly enough to feel like a conversation, and how that works in a browser and on a telephone.

Voice is not chat with a microphone

A text conversation tolerates a two-second pause, long answers, tables and links. A spoken conversation does not. People expect a reply to start within a second or so of finishing a sentence, they interrupt when the answer is wrong or too long, they cannot skim, and they cannot see a citation. Five consequences shape every page that follows:

  • Latency is the user experience. The time from the end of the user’s speech to the first audible word is a sum of network, end-of-turn detection, the model’s first token and the speech synthesiser’s first audio byte; each stage has to stream. The Voice Architectures page builds the budget.

  • Turn-taking is a feature, not a detail. Deciding when the user has finished, and stopping instantly when they interrupt, decides whether the agent feels attentive or rude. See Turn-Taking and Interruptions.

  • Answers are written for the ear. Short sentences, no markdown, numbers and identifiers spelled so that they can be spoken, and citations read as "according to the installation guide" rather than as links.

  • The channel is lossy. Telephone audio is 8 kHz mu-law, browsers add echo cancellation, and recognition errors propagate into retrieval, so the assistant must confirm what it understood when the stakes are high.

  • Recording and consent are legal matters. Calls are regulated differently in each jurisdiction; the production page links the rules rather than summarising them.

The idea: one core, many voices

Every page uses the same running scenario, call DocsAssistant. The assistant answers questions about this site’s documentation and its core is the same channel-agnostic operation used by the other sub-sections:

ask(conversationId, userId, text) -> stream of { token | citation | done }

Source: Serving RAG as an API (the operation and its streaming contract) and Channel-Agnostic Architecture (the same core behind chat channels).

The core is implemented twice, as in the RAG Systems sub-section: in Python with LangChain create_agent, a retriever tool, a Postgres checkpointer and FastAPI, and in Java with the Spring AI ChatClient, the RAG advisor, JDBC chat memory and Spring Boot. The voice layer sits in front of it and has to turn audio into the text argument and the token stream back into audio. The scenario follows four paths:

  1. Browser. A WebRTC voice widget on a documentation page speaks to a Pipecat or LiveKit worker, or directly to a realtime API.

  2. ElevenLabs Agent. A hosted agent calls the DocsAssistant core as its custom LLM or as a tool.

  3. Phone call through Twilio. First with ConversationRelay, where Twilio does the speech work and your WebSocket exchanges text; then with Media Streams, where raw audio goes through Pipecat or a hand-written Spring pipeline.

  4. Company PBX. An Asterisk extension streams audio through External Media or chan_websocket to a Python (Pipecat) or Java (Spring) voice service.

Area Versions

LangChain (Python)

langchain 1.4.3, langchain-core 1.6.6, langgraph 1.2.12, on Python 3.12. LangChain’s own voice guidance describes the STT, agent, TTS "sandwich" and the realtime alternative.

Web layer (Python)

FastAPI 0.142.2; aiortc 1.15.0 (the WebRTC implementation under Pipecat’s SmallWebRTC transport).

Spring AI

2.0.1 through org.springframework.ai:spring-ai-bom:2.0.1 on Spring Boot 4.1.x and Java 21; a 2.1.0-M1 milestone exists and is not used. The audio interfaces are TranscriptionModel (extending StreamingTranscriptionModel) and TextToSpeechModel (extending StreamingTextToSpeechModel); the SpeechModel name used by Spring AI 1.0 and by books written against it no longer exists in 2.0.1, as the existing Audio Transcription & Speech page records. The pages in this sub-section use the 2.0 names. ElevenLabs is a Spring AI text-to-speech provider.

OpenAI

Two voice APIs. GPT-Live (model gpt-live-1, session created with POST /v1/live/sessions, full duplex, conversation handled by the live model and reasoning delegated to a backend through Responses or client delegation) and the Realtime API (speech-to-speech models including gpt-realtime, gpt-realtime-1.5, gpt-realtime-2 and gpt-realtime-2.1; ephemeral client secrets for browsers, WebRTC, WebSocket and SIP, function tools and remote MCP). openai Python package 3.22.1. The models page lists gpt-realtime-2.1 as the reasoning model with tool use and gpt-realtime as the first generally available realtime model.

Google

Gemini Live API over WebSockets with function calling, session management and ephemeral tokens; the models page lists gemini-3.8-live (stable) alongside gemini-3.1-flash-live-preview and gemini-2.5-flash-native-audio-preview-12-2025. google-genai Python package 2.26.0.

Azure

Voice Live API (speech recognition, generative model and speech synthesis behind one interface, with noise suppression, echo cancellation, semantic end-of-turn detection and avatars) and the Azure OpenAI realtime audio route; documented under Foundry Tools on Microsoft Learn.

ElevenLabs

ElevenAgents documentation under /docs/eleven-agents/ (the older /docs/agents-platform/ addresses redirect there); custom LLM through an OpenAI-compatible Chat Completions or Responses endpoint; elevenlabs Python package 2.70.0.

Pipecat

pipecat-ai 1.12.0 (BSD-2-Clause). Pipecat Flows is part of core in the pipecat.flows module; the separate pipecat-ai-flows package is at 1.4.0. Smart Turn is the pipecat-ai/smart-turn project.

LiveKit

livekit-agents 1.8.3 and livekit-plugins-turn-detector 1.8.3 (Apache-2.0), LiveKit server 1.13.7, with LiveKit SIP for telephony.

Other frameworks

TEN Framework 0.11.73 and TEN VAD 1.0; Kyutai Unmute and Moshi (the kyutai-labs/moshi repository is active); Vocode is not recommended because it is no longer actively developed.

Speech to text

faster-whisper 1.2.1 (MIT), whisper.cpp 1.9.4 (MIT), Moonshine (moonshine-voice 0.1.5, MIT), NVIDIA Parakeet parakeet-tdt-0.6b-v3 (CC-BY-4.0), Kyutai STT (CC-BY-4.0), Silero VAD 6.2.3 (MIT). Deepgram Flux (flux-general-en and flux-general-multi on the /v2/listen endpoint, with EndOfTurn and EagerEndOfTurn events) and AssemblyAI streaming (with an end_of_turn field) as hosted options.

Text to speech

Kokoro-82M (Apache-2.0); Piper through OHF-Voice/piper1-gpl 1.8.0 (GPL-3.0; the original repository is archived); XTTS-v2 through the idiap/coqui-ai-TTS fork 0.27.5 (code under MPL-2.0) whose model weights carry the Coqui Public Model Licence, which is non-commercial; Sesame CSM-1B (Apache-2.0, speech generation only); Kyutai TTS (CC-BY-4.0).

Twilio

Programmable Voice with <Connect><ConversationRelay> (text WebSocket messages setup, prompt, interrupt, dtmf, text, play, sendDigits, language and end) and <Connect><Stream> Media Streams (8 kHz mu-law base64 JSON with connected, start, media, mark, clear, dtmf and stop); twilio Python helper 9.11.2 and twilio-java 13.0.2.

Asterisk

Current releases 23.5.0, 22.11.0 and 20.21.0 (a 24.0.0 release candidate exists). The chan_websocket channel driver is available from 23.0.0, 22.6.0, 21.11.0 and 20.16.0; AudioSocket and ARI External Media are older.

Other telephony

Jambonz (its llm verb supports OpenAI Realtime and GPT-Live models), the third-party FreeSWITCH module mod_audio_stream 1.1.0 (MIT), Vonage and Telnyx WebSocket audio.

Web platform

Browser APIs as specified by the W3C WebRTC recommendation, MDN for getUserMedia, RTCPeerConnection, AudioWorklet and the Web Speech API.

Where the books are out of date

No requester-provided book covers real-time voice in depth. Only the chapters named in the bibliography are used, and only for concepts. The differences that matter:

  • Spring AI audio. Spring AI in Action (Chapter 8) targets Spring AI 1.0. In 2.0 TranscriptionModel extends StreamingTranscriptionModel, the text-to-speech interfaces are TextToSpeechModel and StreamingTextToSpeechModel (the SpeechModel of the book is gone), OpenAI speech streams real chunks, ElevenLabs is a provider, and the Azure OpenAI module was removed. The pages show the current API.

  • Hugging Face pipelines. Hugging Face in Action covers ASR pipelines and Gradio audio widgets; the speech catalogue and current idioms live on the speech models page.

  • Real-time voice. Turn-taking, barge-in, realtime APIs, WebRTC audio and telephony are not covered by any of the five books; those pages rely on official documentation alone.

  • OpenAI. Anything written about the Realtime API before 2026 describes the earlier preview models and event names; GPT-Live is a newer, separate API. The Realtime APIs page follows the current documentation.

  • Speech to Text — streaming versus batch, hosted and local recognisers, accuracy factors and the word error rate.

  • Text to Speech — streaming synthesis, voices and cloning, SSML, hosted and local voices with their licences, audio formats and resampling.

Hosted platforms

  • Realtime APIs — OpenAI GPT-Live and Realtime, Gemini Live and Azure Voice Live, ephemeral credentials, tools and remote MCP.

  • ElevenLabs Agents — agent configuration, a custom LLM pointing at the DocsAssistant core, tools, workflows, SDKs, Twilio and SIP.

  • LiveKit Agents — rooms, workers, AgentSession, the turn detector, tools and LiveKit SIP.

  • Building a Voice Pipeline by Hand — a minimal cascaded pipeline in Spring Boot and in Python asyncio, and what frameworks save you.

Web delivery

  • Voice in the Browser — getUserMedia, WebRTC to a voice server, the WebSocket PCM alternative, the Web Speech API and mobile caveats.

Telephony

  • Telephony with Asterisk and SIP — SIP trunks, ARI, External Media, AudioSocket, chan_websocket, FreeSWITCH, Jambonz and security.

Operations
