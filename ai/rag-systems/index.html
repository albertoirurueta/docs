RAG Systems in Production

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This sub-section was written on 2026-09-30 against LangChain 1.4.3 (with langchain-core 1.6.6, langgraph 1.2.12 and langchain-classic 1.0.8) and FastAPI 0.142.2 on Python 3.12, Spring AI 2.0.1 on Spring Boot 4.1.1 with Java 21, and LangChain4j 1.20.2; the full list is in the version baseline below. Every version was read from PyPI and Maven Central on that date. Every import in the Python snippets was resolved against the released packages in a scratch virtual environment, and every Java snippet was compiled against the released jars in a scratch Maven project that imports spring-ai-bom 2.0.1 and langchain4j-bom 1.20.2. No live model, database or graph was called while the pages were checked, so the outputs shown are illustrative; each page says what was checked in its lead paragraph.

A retrieval-augmented generation (RAG) prototype takes an afternoon: split some Markdown, embed it, store the vectors, retrieve the five nearest chunks and paste them into a prompt. The Vector Databases & RAG section of this site covers exactly that path, and covers it well. Everything that happens after the prototype works is the subject of this sub-section: real PDFs with tables and scanned pages, documents that change every hour, users who must not see each other’s files, conversations that span days and devices, answers that must cite their sources and admit when they do not know, an HTTP API and an MCP server in front of the same retriever, a latency budget, a cost per question, a knowledge graph for the questions vectors cannot answer, and the evaluation and tracing that tell you whether last week’s change made things better or worse. This is the day-2 problem of RAG.

The running scenario: DocsAssistant as a production service

Every page extends the same service. DocsAssistant answers questions about this site’s documentation. It reuses the corpus, the pgvector schema (documents, chunks, chunk_embeddings) and the local models of PostgreSQL & pgvector, the agent of LangChain and Spring AI, and the docs-assistant MCP server of Exposing RAG through MCP. Here it grows into a service with users:

flowchart LR subgraph Clients W[Web widget] C[Claude Code / Copilot] A[LangGraph agent] end subgraph DocsAssistant API["/v1/ask REST + SSE"] MCP["MCP server search_docs"] O[Orchestrator] R[Retriever with ACL filter] M[(Conversation store)] end subgraph Stores PG[(PostgreSQL + pgvector)] N[(Neo4j graph)] end W --> API C --> MCP A --> MCP API --> O O --> R O --> M MCP --> R R --> PG R --> N

  • Ingestion adds real PDFs with tables and images next to the AsciiDoc sources, keeps the index fresh from change events and deletes what was deleted.

  • POST /v1/ask takes a question, a conversationId and optional filters, and streams the answer as server-sent events with citations.

  • Conversation IDs persist memory per authenticated user, across devices.

  • Per-component ACLs filter retrieval: a caller’s groups come from the verified token and become a metadata filter.

  • The same retriever is exposed through an MCP server, so coding assistants and agents can search the docs.

  • A Neo4j graph of components, pages and concepts answers the questions that need relationships (GraphRAG).

Each build page shows the same capability three times: Python (LangChain 1.x with FastAPI), Java (Spring AI 2.0 on Spring Boot 4.1) and Java (LangChain4j 1.20). Model names are never hard-coded in the snippets: every example reads the chat and embedding model from configuration (CHAT_MODEL, EMBEDDING_MODEL, or the spring.ai. and langchain4j. properties), so the same code runs against a local runtime from Running LLMs Locally or a hosted provider.

Where the books are out of date

The requester-provided books below are excellent on concepts, but several of their APIs have moved on. The pages flag each difference where it matters; the most important are collected here.

  • LangChain. Older examples import langchain.text_splitter and build agents with create_react_agent. In LangChain 1.x the splitters live in langchain_text_splitters, agents are built with langchain.agents.create_agent and extended with middleware, and several retrievers used in Learning LangChain (ParentDocumentRetriever, MultiVectorRetriever, SelfQueryRetriever, the indexing API) now live in langchain-classic. LlamaIndex moved its documentation to developers.llamaindex.ai (llama-index 0.14.25 on 2026-09-30).

  • The Neo4j book’s stack. It uses LangChain4j 0.35, a pre-1.0 Spring AI, an earlier Haystack line, an OpenAI embedding model of 2022 and Neo4j 5.21. The current versions are LangChain4j 1.20 (with the community Neo4j embedding store and text-to-Cypher retriever), Spring AI 2.0.1 (with Neo4jVectorStore and Neo4jChatMemoryRepository), haystack-ai 3.2.0 with neo4j-haystack 2.2.1, and the calendar-versioned Neo4j 2026.x releases; the embedding model it uses has been superseded. It predates neo4j-graphrag’s text2cypher retrievers, `SimpleKGPipeline, the LLM Graph Builder and the Neo4j MCP servers, which these pages document from Neo4j’s own documentation.

  • Spring AI. Books written for Spring AI 1.0 or earlier describe PromptChatMemoryAdvisor (gone in 2.0), property paths with an .options segment (dropped), and ChatModel.call() running tools (it no longer does). See Migrating from 1.x to 2.x.

  • The Python cookbook’s UI layer. Its only interface is Streamlit, on the end-of-life python:3.9 image, with the 0.x OpenAI Agents SDK. REST, FastAPI and server-sent events are not covered; Serving RAG as an API fills that gap from the FastAPI documentation.

  • Not covered by any of the books: SSE and WebSocket API design, authoring a RAG-behind-MCP server, and LangChain 1.x middleware for guardrails and memory.

What’s covered

Architecture

  • Production RAG Architecture — the reference microservice architecture, a stateless orchestrator with fan-out and gather, independent scaling tiers, the latency budget, DIY versus RAG platforms, total cost of ownership and a POC-to-production plan.

Ingestion

  • Document Parsing — what is inside a PDF, the parser ladder from pypdf to a vision model, Docling and Unstructured, OCR, structure as metadata, and the Tika and PDF readers on the JVM.

  • Multimodal RAG — tables, images, audio and video, visual citations and multimodal hallucinations.

  • Ingestion Pipelines & Freshness — batch and streaming ingestion, idempotent jobs, content hashes, CDC with Debezium and Kafka, deletes, PII redaction and provenance.

Retrieval

  • Query Understanding & Routing — rewriting, condensation, self-query filters, decomposition, routing across vector, SQL, graph and tools, and safe text-to-SQL.

  • Advanced Indexing Patterns — hypothetical questions, propositions, auto-merging, sentence windows, multi-vector, RAPTOR, contextual retrieval and late chunking.

Conversation and answers

  • Conversational RAG & Memory — condensation, window, summary and long-term memory, persistence in three stacks, multi-device sessions, retention and memory poisoning.

  • Citations & Grounding — chunk IDs end to end, structured answers with citations, citation verification and the UX of sources.

  • Hallucination Detection & Correction — faithfulness, LLM-as-judge and HHEM, blocking and asynchronous checks, regenerate and abstain.

  • Guardrails & Prompt Injection — input and output guardrails, indirect injection through documents, delimiting context and tool allow-lists.

  • Access Control & Privacy — ACLs as filters derived from identity, tenancy models, redaction, encryption, audit and data residency.

Exposing RAG

  • Serving RAG as an API — the /v1/ask contract, OpenAPI, SSE and WebSocket streaming, async ingestion, idempotency keys, OAuth2, rate limits, versioning, CORS and a browser widget.

  • RAG Behind MCP — the same retriever as an MCP tool, resource and prompt, identity mapping, and consumption from Claude Code, Copilot and LangGraph.

  • Caching, Latency & Cost — cache tiers, semantic-cache thresholds, event-driven invalidation, prompt caching, model cascades and cost per request.

Knowledge graphs

  • GraphRAG & Knowledge Graph Construction — when a graph helps, Microsoft GraphRAG, LLM extraction, entity resolution and incremental updates.

  • Text2Cypher & Graph Retrievers — vector-Cypher, hybrid and text-to-Cypher retrievers with read-only execution.

  • Graph-Powered Recommendations — LLM-summarised embeddings plus GDS KNN and Louvain.

Operations

  • Evaluation at Scale — synthetic test sets, reference-free metrics, CI gates, online judging, A/B tests and the feedback flywheel.

  • Observability & Tracing — spans, OpenTelemetry GenAI conventions, RAG metrics and tracing backends.

  • Deployment Patterns — containers, managed platforms, GPU inference, secrets, blue/green rollouts, loads and disaster recovery.
