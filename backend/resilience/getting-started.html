Getting Started

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page takes a Spring Boot service from nothing to a working circuit breaker: the dependencies, one annotated method with a fallback, the YAML that configures it, and the Actuator endpoint that shows its state. It was written against Resilience4j 2.4.0 (released 14 March 2026), Spring Boot 4.1.1, Spring Framework 7.0.x and Java 21, and every snippet on it was built and run on exactly those versions on 4 October 2026. A Spring Boot 3.5.x variant (verified on 3.5.16 and Spring Framework 6.2.x) follows each Boot 4 step. If the vocabulary is new, read Resilience Fundamentals first.

Behind these sit a few supporting artifacts you rarely add yourself: resilience4j-annotations (the annotation types), -consumer (CircularEventConsumer, the event buffer), -circularbuffer, -framework-common (the property classes shared by the Spring modules) and -metrics (Dropwizard Metrics).

Two things have changed on the module map. resilience4j-spring-boot2 and resilience4j-spring-cloud2 were last published in 2.3.0. Their directories remain in the repository but are excluded from settings.gradle, so they are not built from the 2.4.0 sources, and a Boot 2 application stays on 2.3.0. And resilience4j-spring-boot4 is new: it is the starter for Spring Boot 4 and Spring Framework 7.

Dependencies for Spring Boot 4

A Spring Boot 4 service needs four things: the Resilience4j starter, spring-boot-starter-aspectj (so the annotations work), spring-boot-starter-actuator (for the endpoints and metrics), and a web starter. Three details are specific to Boot 4 and 2.4.0, and each was confirmed by running a sample project.

  • The starter is not in the BOM. resilience4j-bom 2.4.0 lists the core modules, spring6, spring-boot3, reactor, micrometer and others, but not resilience4j-spring-boot4 (nor resilience4j-hedge or resilience4j-commons-configuration). Import the BOM for the modules it covers, and give the starter an explicit version. Leaving the version out fails with 'dependencies.dependency.version' …​ is missing.

  • spring-boot-starter-aspectj is not transitive. The starter does not add AspectJ, and Spring Boot 4 retired spring-boot-starter-aop (its last release is a 4.0.0 milestone). Without spring-boot-starter-aspectj the application starts normally, the registries and Actuator endpoints exist, and @CircuitBreaker silently does nothing.

  • Actuator is not transitive either. Add spring-boot-starter-actuator yourself.

The starter checks your Boot version

Both starters ship a version verifier that fails the application at startup when the Spring Boot major version is wrong. Putting resilience4j-spring-boot3 on a Boot 4 application stops it with Module 'io.github.resilience4j:resilience4j-spring-boot3' is only compatible with Spring Boot 3.x, and the Boot 4 starter reports the mirror message on Boot 3. A mismatch therefore cannot go unnoticed, which is useful during migrations.

AspectJ is optional, and what you lose without it

The annotations (@CircuitBreaker, @Retry, @RateLimiter, @Bulkhead, @TimeLimiter) are implemented as Spring AOP aspects, and they need the AspectJ weaver on the classpath to be recognised. Without spring-boot-starter-aspectj (Boot 4) or spring-boot-starter-aop (Boot 3):

  • the auto-configuration still creates the registries (CircuitBreakerRegistry, RetryRegistry, and so on), the Actuator endpoints and the Micrometer metrics;

  • no aspect beans are created, annotated beans are not proxied, and the annotations have no effect and raise no error.

That last point is the common first-hour mistake: the fallback never runs and the breaker never opens, and nothing in the log says why. The remedy is the missing dependency. A service that wants only programmatic use can leave AspectJ out deliberately and inject the registry:

Programmatic use without annotations: the registry is an injectable bean
@Component
public class ProgrammaticPricing {
    private final RestClient http;
    private final CircuitBreaker breaker;

    public ProgrammaticPricing(RestClient.Builder builder,
                               CircuitBreakerRegistry registry,
                               @Value("${bookshelf.pricing.url:http://localhost:8089}") String baseUrl) {
        this.http = builder.baseUrl(baseUrl).build();
        this.breaker = registry.circuitBreaker("pricing");   // configured from application.yml
    }

    public Money price(String isbn) {
        return breaker.executeSupplier(
            () -> http.get().uri("/prices/{isbn}", isbn).retrieve().body(Money.class));
    }
}

Source: Resilience4j: Spring Boot 2 & 3 and the Spring Boot AOP reference. The programmatic style, with RestClient, WebClient and HttpClient examples, is covered in Programmatic Usage.

A first circuit breaker: the pricing call

The Bookshelf bookshelf-service asks the slow and flaky pricing-service for a book’s price. When that service is failing, the call should stop being attempted after a few failures and the page should show the last known price instead. One annotation and one fallback method do it.

The pricing client: @CircuitBreaker with a fallback
package com.example.bookshelf;

import io.github.resilience4j.circuitbreaker.annotation.CircuitBreaker;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.client.RestClient;

@Component
public class PricingClient {
    private final RestClient http;

    public PricingClient(RestClient.Builder builder,
                         @Value("${bookshelf.pricing.url:http://localhost:8089}") String baseUrl) {
        this.http = builder.baseUrl(baseUrl).build();
    }

    @CircuitBreaker(name = "pricing", fallbackMethod = "lastKnownPrice")
    public Money price(String isbn) {
        return http.get().uri("/prices/{isbn}", isbn).retrieve().body(Money.class);
    }

    Money lastKnownPrice(String isbn, Throwable t) {
        return new Money(isbn, 0, true);
    }
}

public record Money(String isbn, long cents, boolean stale) {}

Three things to notice:

  • name = "pricing" selects the instance. It is the same name used in the YAML below and in the Actuator output. One instance per remote backend is the rule (see Registries, Configuration & Decorators).

  • The fallback has the same parameters as the protected method plus a trailing Throwable, and the same return type. It runs when the call throws, and also when the breaker is open and rejects the call with CallNotPermittedException. The full resolution rules are in Fallbacks & Composition.

  • The fallback marks its answer as stale, so the caller can tell a degraded price from a live one.

A controller exposes it:

The controller needs no resilience code
@RestController
public class BookshelfController {
    private final PricingClient pricing;

    public BookshelfController(PricingClient pricing) {
        this.pricing = pricing;
    }

    @GetMapping("/books/{isbn}/price")
    public Money price(@PathVariable String isbn) {
        return pricing.price(isbn);
    }
}

Source: Resilience4j: Spring Boot 2 & 3 (the @CircuitBreaker annotation and fallbackMethod) and Resilience4j: CircuitBreaker.

The configuration

The instance is configured under resilience4j.circuitbreaker.instances.<name> in application.yml. Every key has a default; only the ones that matter for this example are set. The full list, with defaults, is in CircuitBreaker.

application.yml: the pricing breaker and the Actuator exposure
resilience4j:
  circuitbreaker:
    instances:
      pricing:
        slidingWindowType: COUNT_BASED
        slidingWindowSize: 10
        minimumNumberOfCalls: 5
        failureRateThreshold: 50
        waitDurationInOpenState: 10s
        permittedNumberOfCallsInHalfOpenState: 3
        registerHealthIndicator: true

management:
  endpoints:
    web:
      exposure:
        include: health,circuitbreakers
  endpoint:
    health:
      show-details: always
  health:
    circuitbreakers:
      enabled: true

Read the settings as a sentence: judge the last 10 calls; once at least 5 have been recorded and 50 per cent or more failed, open the circuit for 10 seconds; then let 3 trial calls through to decide whether to close it again. registerHealthIndicator and management.health.circuitbreakers.enabled are both off by default and both needed for the breaker to appear in /actuator/health. Exposing show-details: always and circuitbreakers is fine on a laptop; on a real service, expose Actuator on a management port and secure it, as described in Observability.

Source: Resilience4j: Spring Boot 2 & 3 (the property prefix and the instance model) and Spring Boot: Actuator endpoints (exposure).

How to change it per instance (allowHealthIndicatorToFail) and which probes to keep it out of are covered in Observability.

What the annotation does

The request does not call PricingClient directly. Spring wraps the bean in a proxy (a CGLIB subclass whose class name starts with PricingClient and contains SpringCGLIB in the debugger), and the Resilience4j aspect is part of that proxy’s interceptor chain. When /books/{isbn}/price is called, the aspect looks up the pricing breaker in the registry, asks it for permission, runs the real method, records the outcome, and calls the fallback if the call failed or was rejected.

sequenceDiagram participant C as BookshelfController participant P as PricingClient proxy participant A as CircuitBreakerAspect participant R as CircuitBreakerRegistry participant B as CircuitBreaker pricing participant T as PricingClient target participant S as pricing-service C->>P: price(isbn) P->>A: intercept @CircuitBreaker A->>R: circuitBreaker("pricing") R-->>A: instance (config from application.yml) A->>B: tryAcquirePermission() alt circuit CLOSED or HALF_OPEN B-->>A: permitted A->>T: proceed T->>S: GET /prices/isbn alt call succeeds S-->>T: 200 price T-->>A: Money A->>B: onSuccess(duration) else call fails S--xT: error or timeout T-->>A: exception A->>B: onError(duration, exception) A->>T: lastKnownPrice(isbn, exception) end else circuit OPEN B-->>A: CallNotPermittedException A->>T: lastKnownPrice(isbn, exception) end A-->>P: result P-->>C: Money
Figure 1. A request through the aspect proxy

Because the aspect works through the proxy, it only sees calls that enter the bean from outside. A method calling another method on this bypasses it, and private or final methods cannot be intercepted. These and other proxy pitfalls are collected in Annotations & Aspect Order.
