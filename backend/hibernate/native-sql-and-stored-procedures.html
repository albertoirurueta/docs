Native SQL and Stored Procedures

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

HQL/JPQL and the Criteria API cover the overwhelming majority of queries; this page covers the escape hatch for the rest — vendor-specific SQL (window functions, recursive CTEs, hints) that neither can express.

createNativeQuery

// mapped to an entity -- result columns must line up with Book's mapped columns
List<Book> books = em.createNativeQuery(
        "SELECT * FROM book WHERE published_year > ?", Book.class)
        .setParameter(1, 2020)
        .getResultList();

// scalar / unmapped result -- Object[] per row
List<Object[]> rows = em.createNativeQuery(
        "SELECT author_id, COUNT(*) FROM book GROUP BY author_id")
        .getResultList();

@SqlResultSetMapping

For a native query whose result does not map cleanly onto one entity’s columns — joining multiple entities, or projecting into a DTO:

@SqlResultSetMapping(
    name = "BookWithAuthorName",
    classes = @ConstructorResult(
        targetClass = BookSummary.class,
        columns = {
            @ColumnResult(name = "id", type = Long.class),
            @ColumnResult(name = "title", type = String.class),
            @ColumnResult(name = "author_name", type = String.class)
        }))
List<BookSummary> summaries = em.createNativeQuery("""
            SELECT b.id AS id, b.title AS title, a.name AS author_name
            FROM book b JOIN author a ON a.id = b.author_id
            """, "BookWithAuthorName")
        .getResultList();

@EntityResult (instead of @ConstructorResult) maps native-query columns back onto full managed entities when several entity types are joined in one native query.

@NamedNativeQuery

Same idea as @NamedQuery (see HQL/JPQL) but for native SQL, optionally paired with a @SqlResultSetMapping by name:

@Entity
@NamedNativeQuery(
    name = "Book.recentByRawSql",
    query = "SELECT * FROM book WHERE published_year > :year",
    resultClass = Book.class)
public class Book { /* ... */ }

@Subselect and @Formula

@Subselect maps an entity onto an arbitrary SELECT statement instead of a real table — a read-only, mapped "view" without needing an actual database view, useful for a reporting entity backed by a complex join or aggregation:

@Entity
@Subselect("""
        SELECT a.id AS id, a.name AS name, COUNT(b.id) AS book_count
        FROM author a LEFT JOIN book b ON b.author_id = a.id
        GROUP BY a.id, a.name
        """)
@Immutable // see basic-and-embeddable-types.adoc -- read-only, never flushed
public class AuthorBookCount {
    @Id
    private Long id;
    private String name;
    private Long bookCount;
}

@Formula is the column-level equivalent: one mapped attribute’s value comes from a SQL expression evaluated at read time rather than a stored column — a computed/derived value (price * (1 - discount)) kept in sync by the database read itself instead of application code.

Stored procedures

// ad hoc
StoredProcedureQuery query = em.createStoredProcedureQuery("recalculate_totals");
query.registerStoredProcedureParameter("order_id", Long.class, ParameterMode.IN);
query.registerStoredProcedureParameter("new_total", BigDecimal.class, ParameterMode.OUT);
query.setParameter("order_id", orderId);
query.execute();
BigDecimal newTotal = (BigDecimal) query.getOutputParameterValue("new_total");
// named, declared once on an entity
@NamedStoredProcedureQuery(
    name = "recalculateTotals",
    procedureName = "recalculate_totals",
    parameters = {
        @StoredProcedureParameter(mode = ParameterMode.IN, name = "order_id", type = Long.class),
        @StoredProcedureParameter(mode = ParameterMode.OUT, name = "new_total", type = BigDecimal.class)
    })
@Entity
public class Order { /* ... */ }

// ...
StoredProcedureQuery query = em.createNamedStoredProcedureQuery("recalculateTotals");

When to drop to raw SQL

Reach for native SQL/stored procedures when the feature has no JPQL/Criteria equivalent at all (window functions, recursive CTEs, database-specific hints or full-text operators), when an existing stored procedure already encapsulates business logic that must stay in the database, or when a single well-tuned raw query measurably outperforms the Hibernate-generated equivalent for a hot path. Each of these ties that specific query to one database’s SQL dialect — confine native SQL to a dedicated repository method with a comment explaining why, rather than mixing it freely with portable JPQL in the same class.

Worked example: native results on the running model

The statements below ran against 12 authors with three books each (Hibernate ORM 7.4.15, H2 for the queries and PostgreSQL 16 with driver 42.7.7 for the stored-procedure part). Result classes are the section’s Book entity and a BookSummary(Long id, String title, String authorName) record.

Result shapes

  • Entity — createNativeQuery(sql, Book.class) needs every mapped column in the select list; select * from book where published_year > ?1 returned the four matching books as managed entities.

  • Scalars — createNativeQuery(sql, Object[].class) returned rows such as [1, 3] for select author_id, count(*) from book group by author_id.

  • Record by alias — Hibernate 6 and later can instantiate a record or class directly from column aliases: select b.id as id, b.title as title, a.name as authorName ... with BookSummary.class as the result type returned BookSummary[id=4, title=Book 2.1, authorName=Author 2] without any @SqlResultSetMapping. The aliases have to match the constructor parameter names; the mapping annotation is still the better choice when they cannot (a author_name column against an authorName component).

  • Mapped DTO — the BookWithAuthorName mapping above works as shown; the @ColumnResult names are the aliases of the select list, and passing the target class as a third argument, createNativeQuery(sql, "BookWithAuthorName", BookSummary.class), returns a typed list.

@NamedNativeQuery with resultClass = Book.class and a named :year parameter behaved like the ad hoc query (session.createNamedQuery("Book.recentByRawSql", Book.class).setParameter("year", 2018) returned one book).

Native queries and auto flush

A native query is opaque to Hibernate: it cannot tell which tables the SQL touches, so it cannot know whether pending changes in the persistence context should be flushed first. The behavior depends on how the factory was bootstrapped. With the native Session API, an unflushed persist is not visible to the query unless the affected table is declared:

session.persist(new Author("Pending Author"));

// native Hibernate bootstrap: prints 0 -- the INSERT has not been flushed
session.createNativeQuery("select count(*) from author where name = 'Pending Author'", Object.class)
       .getSingleResult();

// declaring the table space makes Hibernate flush Author changes first: prints 1
session.createNativeQuery("select count(*) from author where name = 'Pending Author'", Object.class)
       .addSynchronizedEntityClass(Author.class)
       .getSingleResult();

The same code through an EntityManagerFactory bootstrapped with the JPA API (PersistenceConfiguration or persistence.xml) printed 1 without any declaration, because JPA bootstrapping flushes everything before a native query. addSynchronizedEntityClass, addSynchronizedQuerySpace("author") or the querySpaces attribute of Hibernate’s own @NamedNativeQuery annotation tell Hibernate which entities to flush and, for native DML, which second-level cache regions to invalidate (see Second-Level Cache).

@Subselect and @Formula in a run

The AuthorBookCount entity from the example above is queried like any other entity; HQL wraps its @Subselect in a derived table:

select abc1_0.id,abc1_0.book_count,abc1_0.name
from ( select a.id as id, a.name as name, count(b.id) as book_count
       from author a left join book b on b.author_id = a.id
       group by a.id, a.name ) abc1_0
where abc1_0.book_count>2 order by abc1_0.id fetch first ? rows only

Add @Synchronize({"author", "book"}) so that pending changes to those tables are flushed before the entity is queried; without it Hibernate cannot know the subselect depends on them. A @Formula such as price * (1 - discount) is inlined in every select (i1_0.price * (1 - i1_0.discount)); it is evaluated when the row is read, so an item persisted with price 100.00 and discount 0.15 reported its netPrice only after refresh, as 85.0000, and a changed price is not reflected until the entity is read again.

Stored procedures against PostgreSQL

A PostgreSQL 16 procedure with an OUT parameter and two functions were created through native DDL, then called:

create procedure restock(in p_book bigint, in p_qty int, out p_new_stock int) language plpgsql as
$$ begin update book set stock = stock + p_qty where id = p_book returning stock into p_new_stock; end $$;

create function books_of(p_author bigint) returns bigint language sql as
$$ select count(*) from book where author_id = p_author $$;
ProcedureCall call = session.createStoredProcedureCall("restock");
call.registerStoredProcedureParameter("p_book", Long.class, ParameterMode.IN);
call.registerStoredProcedureParameter("p_qty", Integer.class, ParameterMode.IN);
call.registerStoredProcedureParameter("p_new_stock", Integer.class, ParameterMode.OUT);
call.setParameter("p_book", 1L).setParameter("p_qty", 10);
call.execute();
Object stock = call.getOutputParameterValue("p_new_stock");   // 15 for a book that started at 5

// a scalar function is not a procedure: call it from HQL or a native select
session.createQuery("select function('books_of', a.id) from Author a where a.id = 1", Object.class)
       .getSingleResult();                                        // 3
session.createNativeQuery("select * from books_by_author(?1)", Object[].class)
       .setParameter(1, 1L).getResultList();                      // [1, Book 1.1] [2, Book 1.2] [3, Book 1.3]

Registering the scalar function books_of as a stored procedure failed with SQLGrammarException ... procedure books_of(bigint, unknown) does not exist: PostgreSQL distinguishes CREATE PROCEDURE from CREATE FUNCTION, and createStoredProcedureCall issues a procedure CALL. Functions go through function(...) in HQL or a native select.
