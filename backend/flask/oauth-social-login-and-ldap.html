OAuth Social Login & LDAP

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against Flask 3.1.3 (released 2026-02-18), Werkzeug 3.1.9, Authlib 1.8.0 (2026-08-30), Flask-Dance 7.1.0 (2024-03-05), ldap3 2.9.1 (2021-07-18), python-ldap 3.4.8 (2026-09-16) and Python 3.13, checked on 2026-10-07. Every example was executed with those versions against local fakes: a stand-in OpenID Connect provider, canned GitHub responses and the MOCK_SYNC strategy of ldap3, so no account, network or directory server is needed. Flask 3.2 is not released yet and its unreleased changelog contains nothing that changes the features used here.

Most applications stop wanting to store passwords sooner or later. Either visitors prefer "Sign in with Google" or "Sign in with GitHub", or the company already runs a directory (an LDAP server such as OpenLDAP or Active Directory) that holds every employee’s credentials. In both cases the application delegates the question "who is this?" to a system that already knows, and receives an answer it must verify before it creates its own session. The page builds that for the running Bookshelf application: social login with Authlib (the maintained, protocol-complete choice), the older Flask-Dance extension that the Flask cookbooks teach, and LDAP with a search-then-bind flow. The protocol theory is not repeated here; it lives in the OAuth section of the site, starting with Social Login and Federation, Authorization Code and PKCE and OpenID Connect.

Delegated Sign-In at a Glance

Whatever the mechanism, the shape is the same: Flask redirects the visitor (or the visitor’s credentials) to an authority, gets back proof of identity, maps it to a local user and then does what every other login does, which is to start a fresh session (see Authentication & Flask-Login). The mechanisms differ in who sees the password and in what proof comes back.

Mechanism Who sees the user’s password What Flask receives Typical use

OpenID Connect login (Google, Microsoft, Keycloak, Auth0 and others)

Only the provider

A signed ID token with iss, sub, aud, exp, nonce and profile claims, plus an access token

Public sign-up, single sign-on across your own applications

OAuth 2.0 only login (GitHub is the common case)

Only the provider

An access token; the identity is read from an API call

Developer-facing products

Flask-Dance blueprint

Only the provider

An access token held in the session or a database; no ID token validation

Quick "Sign in with X" for providers that Flask-Dance ships, and any plain OAuth 2.0 server

LDAP simple bind

Your application (it forwards the password to the directory)

A yes or no, plus attributes you search for

Intranet tools where users type their company password into your form

The last row is the important difference. With OAuth and OpenID Connect the user’s password never reaches Flask. With LDAP it does, so the page spends as much time on TLS, escaping and not logging the password as on the protocol. The figure shows the browser-based flow that Authlib automates; each step with a name in it is something the library does for you and that a hand-written implementation tends to forget.

Choosing a Library

Three libraries are involved, and they differ in how much of the protocol they own.

Library What it does What it leaves to you

Authlib (authlib.integrations.flask_client)

Provider registry configured from app.config; discovery documents; state, nonce and PKCE; ID token validation through JOSE (Authlib 1.8 uses the joserfc package); token refresh hooks; RP-initiated logout; also OAuth 1.0

Mapping claims to users, account linking, session handling, error pages

Flask-Dance (built on requests-oauthlib and oauthlib)

One blueprint per provider with login and callback routes already wired; ready-made blueprints for more than twenty providers (GitHub, Google, Facebook, Slack, Azure and others); token storage in the session or in SQLAlchemy; signals

Everything about OpenID Connect: it never reads or validates an ID token and sends no nonce; use_pkce exists only on the generic blueprint class

ldap3 and python-ldap

ldap3 is pure Python with a built-in fake server for tests; python-ldap wraps the OpenLDAP C library

Escaping, TLS settings, timeouts, search-then-bind, group mapping, provisioning

Two maintenance facts shape the choice. Flask-Dance’s latest release is 7.1.0 from March 2024, and ldap3’s latest release is 2.9.1 from July 2021; both still work with Python 3.13 and the examples below ran, but neither ships fixes quickly, so read their issue trackers before you depend on them. Authlib and python-ldap are released regularly. This page therefore teaches Authlib first, shows Flask-Dance because the books and many existing code bases use it, and uses ldap3 for the runnable LDAP examples while showing the python-ldap equivalents of the safety-critical calls.

For production OpenID Connect, prefer a library that validates the ID token over a library that only moves OAuth tokens around. Flask-Dance’s Google blueprint, for example, defaults to the userinfo.profile scope, which has no openid in it, so there is no ID token at all: the application calls an API with the access token. That is OAuth, not OpenID Connect, and it gives no proof that the response belongs to this login attempt in the way a validated, nonce-bound ID token does.

Setup and the Bookshelf Identity Model

Install the libraries into the project’s environment. responses is only used by the tests on this page, to keep the provider fakes inside the process.

pip install "Flask>=3.1" "Authlib>=1.8" Flask-Dance ldap3 python-ldap responses

Source: Authlib on PyPI

The first decision is not about OAuth at all: how does a provider’s answer become a local user? The robust rule is to key the link on the pair (iss, sub), the issuer and the subject, because the subject is a stable identifier the provider promises never to reuse for someone else, while an e-mail address can change hands. The e-mail is profile data, and it may be used for linking only when the provider says it is verified. The Bookshelf therefore has a users table and an identities table, and a small Profile value that every provider adapter produces.

@dataclass(frozen=True)
class Profile:
    issuer: str            # who vouches for the identity
    subject: str           # the provider's stable id for the person; never reused
    email: str | None
    email_verified: bool
    name: str | None


SCHEMA = """
CREATE TABLE users (id INTEGER PRIMARY KEY, email TEXT UNIQUE, display_name TEXT);
CREATE TABLE identities (
    issuer TEXT NOT NULL,
    subject TEXT NOT NULL,
    user_id INTEGER NOT NULL REFERENCES users (id),
    PRIMARY KEY (issuer, subject)
);

class AccountLinkRequired(Exception):
    """The e-mail belongs to an existing account that has not linked this identity."""


def find_or_create_user(db, profile):
    row = db.execute(
        "SELECT user_id FROM identities WHERE issuer = ? AND subject = ?",
        (profile.issuer, profile.subject),
    ).fetchone()
    if row:
        return row[0]
    if db.execute("SELECT 1 FROM users WHERE email = ?", (profile.email,)).fetchone():
        raise AccountLinkRequired          # never merge accounts on an e-mail match alone
    user_id = db.execute(
        "INSERT INTO users (email, display_name) VALUES (?, ?)", (profile.email, profile.name)
    ).lastrowid
    db.execute("INSERT INTO identities VALUES (?, ?, ?)", (profile.issuer, profile.subject, user_id))
    db.commit()
    return user_id


def safe_next(target):
    """Return target only if it is a same-site path such as /books/7."""
    if not target or not target.startswith("/") or target.startswith("//") or "\\" in target:
        return None
    parts = urlsplit(target)
    return target if not parts.scheme and not parts.netloc else None

Two details of that block carry security weight. find_or_create_user refuses to attach a new identity to an existing account just because the e-mail matches: an attacker who controls a provider account with the victim’s address would otherwise take over the victim’s Bookshelf account. The correct flow is "sign in with the old method first, then link", as discussed in Social Login and Federation. And safe_next is there because a login route that stores a next address and redirects to it afterwards is the classic open redirect; only a path on the same site is accepted.

Sign In with Authlib

Authlib’s Flask client is a registry. You create an OAuth object, register each provider under a short name, and the registry builds one client per name. The configuration can live in app.config: for a client registered as idp, the keys IDP_CLIENT_ID, IDP_CLIENT_SECRET and IDP_SERVER_METADATA_URL are read automatically (the name in upper case, an underscore and the parameter in upper case), so credentials never appear in the code. app.config.from_prefixed_env() maps environment variables such as FLASK_IDP_CLIENT_ID into those keys, which is how a container or a secret store feeds them in; see Configuration.

register() parameter or config key Meaning

client_id, client_secret (<NAME>_CLIENT_ID, <NAME>_CLIENT_SECRET)

The credentials issued by the provider when you registered the application. Keep them in the environment or a secret store, never in the repository.

server_metadata_url

URL of the provider’s OpenID Connect discovery document (/.well-known/openid-configuration). From it Authlib reads the authorization, token and JWKS endpoints, the issuer and the supported signing algorithms. For Google it is https://accounts.google.com/.well-known/openid-configuration.

authorize_url, access_token_url, api_base_url

The manual alternative for providers without discovery, such as GitHub. api_base_url lets client.get("user") build the full address.

client_kwargs

Extra settings for the underlying OAuth 2 session: scope, code_challenge_method (set S256 to turn PKCE on), token_endpoint_auth_method (client_secret_basic, client_secret_post or none).

authorize_params, access_token_params

Extra query or body parameters for those endpoints, for example prompt or access_type.

OAuth(app, cache=...)

Where the per-login state is kept. By default it is the Flask session cookie; a cache object with get, set and delete (any cachelib cache) moves it to the server.

When the registered scope contains openid, Authlib also creates a nonce, includes it in the authorization request and, on the way back, validates the ID token (signature against the provider’s JWKS, iss, aud, exp, iat and the nonce) and places the claims in token["userinfo"]. The state, the nonce and the PKCE verifier are saved in the Flask session under a key derived from the state value and removed on the first callback, which is also why a replayed callback fails. Three things in the Bookshelf factory below are deliberate: the session.clear() once the user is known (a fresh session contents after authentication, the defence against session fixation covered in Sessions, Cookies & Flashing), SESSION_COOKIE_SAMESITE="Lax" (explained below), and one generic error response for every failure, so that provider details do not leak and the page cannot be used as an oracle.

def profile_from_oidc(client, token):
    claims = token["userinfo"]                       # the validated ID token claims
    return Profile(claims["iss"], claims["sub"], claims.get("email"),
                   claims.get("email_verified") is True, claims.get("name"))


def profile_from_github(client, token):
    user = client.get("user")                        # Authlib sends the access token
    user.raise_for_status()
    emails = client.get("user/emails")
    emails.raise_for_status()
    primary = next((e for e in emails.json() if e["primary"] and e["verified"]), None)
    return Profile("https://github.com", str(user.json()["id"]),
                   primary["email"] if primary else None, primary is not None,
                   user.json().get("name") or user.json()["login"])

def create_app(test_config=None, cache=None):
    app = Flask(__name__)
    app.config.from_mapping(
        SECRET_KEY=os.environ.get("SECRET_KEY") or secrets.token_hex(32),   # a dev fallback only
        SESSION_COOKIE_SECURE=True,
        SESSION_COOKIE_HTTPONLY=True,
        SESSION_COOKIE_SAMESITE="Lax",
    )
    app.config.from_prefixed_env()    # FLASK_IDP_CLIENT_ID, FLASK_GITHUB_CLIENT_SECRET, ...
    if test_config:
        app.config.update(test_config)
    app.extensions["db"] = db = sqlite3.connect(":memory:", check_same_thread=False)
    db.executescript(SCHEMA)

    oauth = OAuth(app, cache=cache)     # reads <NAME>_CLIENT_ID, <NAME>_CLIENT_SECRET, ... from app.config
    oauth.register(
        "idp",              # any OpenID Connect provider with a discovery document
        client_kwargs={"scope": "openid email profile", "code_challenge_method": "S256"},
    )
    oauth.register(         # GitHub speaks OAuth 2.0 only: no ID token, no discovery
        "github",
        authorize_url="https://github.com/login/oauth/authorize",
        access_token_url="https://github.com/login/oauth/access_token",
        api_base_url="https://api.github.com/",
        client_kwargs={
            "scope": "read:user user:email",
            "code_challenge_method": "S256",
            "token_endpoint_auth_method": "client_secret_post",
        },
    )

    @app.get("/login/<provider>")
    def login(provider):
        client = oauth.create_client(provider) if provider in LOADERS else None
        if client is None:
            abort(404)
        session["next"] = safe_next(request.args.get("next"))
        return client.authorize_redirect(url_for("auth_callback", provider=provider, _external=True))

    @app.get("/auth/<provider>/callback")
    def auth_callback(provider):
        client = oauth.create_client(provider) if provider in LOADERS else None
        if client is None:
            abort(404)
        try:
            token = client.authorize_access_token()       # checks state, uses the PKCE verifier
            profile = LOADERS[provider](client, token)    # for OIDC the ID token is validated above
        except (OAuthError, JoseError) as exc:
            current_app.logger.warning("%s login failed: %s", provider, getattr(exc, "error", type(exc).__name__))
            return jsonify(error="login_failed"), 400
        if not profile.email_verified:
            return jsonify(error="email_not_verified"), 403
        try:
            user_id = find_or_create_user(db, profile)
        except AccountLinkRequired:
            return jsonify(error="sign_in_to_link"), 409
        target = session.pop("next", None)
        id_token = token.get("id_token")
        session.clear()                                   # fresh session after authentication
        session["user_id"] = user_id
        if id_token:
            session["id_token"] = id_token                # only needed for RP-initiated logout
        return redirect(target or url_for("me"))

    @app.get("/me")
    def me():
        if "user_id" not in session:
            abort(401)
        row = db.execute("SELECT id, email, display_name FROM users WHERE id = ?",
                         (session["user_id"],)).fetchone()
        return jsonify(id=row[0], email=row[1], name=row[2])

    @app.post("/logout")
    def logout():
        session.clear()
        return "", 204

    @app.post("/logout/idp")
    def logout_idp():
        hint = session.pop("id_token", None)
        session.clear()
        return oauth.idp.logout_redirect(url_for("signed_out", _external=True), id_token_hint=hint)

    @app.get("/signed-out")
    def signed_out():
        oauth.idp.validate_logout_response()               # checks the state of the logout round trip
        return jsonify(status="signed out")

    return app

Why SESSION_COOKIE_SAMESITE="Lax" and not "Strict"? The callback is a cross-site top-level navigation: the provider redirects the browser back to /auth/idp/callback. A Lax cookie is sent on such a navigation; a Strict cookie is not, so the callback would arrive without the session that holds the state, and the login would fail with a state mismatch that looks like a bug in the library. Keep Lax for the session cookie of an application that offers social login (see Security Considerations for the other cookie options). The ID token kept for logout makes the signed cookie larger (the demo cookie is about 800 bytes and real tokens with more claims are bigger), which is acceptable only while it stays far below the 4 KB limit; with a server-side session store (Flask-Session) the size does not matter, and an application that never uses RP-initiated logout can simply not store it.

A Local Stand-In for the Provider

Testing a login flow against the real Google or GitHub is slow, needs credentials and breaks in CI. The usual answer is a fake provider that speaks the same HTTP: the application stays unchanged, and only the network is replaced. Authlib’s sessions are built on requests, so the responses library can route every call to the provider’s host into a small Flask application that implements the four endpoints a code flow needs (discovery, JWKS, token and userinfo) and signs ID tokens with a freshly generated RSA key. The same class is reused for the Flask-Dance section. It also enforces PKCE, so a client that forgets the verifier fails here exactly as it would in production. Nothing in it is a real secret: the client id, the client secret and the signing key are generated when the object is created.

import base64
import hashlib
import re
import time

from urllib.parse import parse_qs

class FakeIdP:
    """A local stand-in for an OpenID Connect provider (never talks to the network)."""

    issuer = "https://idp.example.test"

    def __init__(self):
        self.client_id = "bookshelf-" + secrets.token_hex(4)
        self.client_secret = secrets.token_hex(16)
        self.key = RSAKey.generate_key(2048, parameters={"kid": "k1", "use": "sig"})
        self.codes = {}
        self.tokens = {}
        self.claims = {"sub": "1001", "email": "ada@example.test", "email_verified": True, "name": "Ada"}
        self.app = self._build_app()

    def config(self):
        return {
            "IDP_CLIENT_ID": self.client_id,
            "IDP_CLIENT_SECRET": self.client_secret,
            "IDP_SERVER_METADATA_URL": f"{self.issuer}/.well-known/openid-configuration",
        }

    def _build_app(self):
        app = Flask("fake-idp")

        @app.get("/.well-known/openid-configuration")
        def metadata():
            return jsonify(
                issuer=self.issuer,
                authorization_endpoint=f"{self.issuer}/authorize",
                token_endpoint=f"{self.issuer}/token",
                jwks_uri=f"{self.issuer}/jwks",
                userinfo_endpoint=f"{self.issuer}/userinfo",
                end_session_endpoint=f"{self.issuer}/logout",
                response_types_supported=["code"],
                subject_types_supported=["public"],
                id_token_signing_alg_values_supported=["RS256"],
                code_challenge_methods_supported=["S256"],
                token_endpoint_auth_methods_supported=["client_secret_basic", "client_secret_post"],
            )

        @app.get("/jwks")
        def jwks():
            return jsonify(keys=[self.key.as_dict(private=False)])

        @app.post("/token")
        def token():
            auth = request.authorization
            cid = auth.username if auth else request.form.get("client_id")
            secret = auth.password if auth else request.form.get("client_secret")
            if cid != self.client_id or not secrets.compare_digest(secret or "", self.client_secret):
                return jsonify(error="invalid_client"), 401
            record = self.codes.pop(request.form.get("code"), None)      # a code works once
            if record is None or record["redirect_uri"] != request.form.get("redirect_uri"):
                return jsonify(error="invalid_grant"), 400
            digest = hashlib.sha256(request.form.get("code_verifier", "").encode()).digest()
            if base64.urlsafe_b64encode(digest).rstrip(b"=").decode() != record["challenge"]:
                return jsonify(error="invalid_grant", error_description="PKCE verification failed"), 400
            now = int(time.time())
            claims = {"iss": self.issuer, "aud": self.client_id, "iat": now, "exp": now + 300,
                      "nonce": record["nonce"], **self.claims, **record["overrides"]}
            id_token = jwt.encode({"alg": "RS256", "kid": "k1"}, claims, self.key)
            access_token = secrets.token_hex(16)
            self.tokens[access_token] = {"iss": self.issuer, **self.claims}
            return jsonify(access_token=access_token, token_type="Bearer", expires_in=300, id_token=id_token)

        @app.get("/userinfo")
        def userinfo():
            claims = self.tokens.get(request.headers.get("Authorization", "").removeprefix("Bearer "))
            return (jsonify(claims), 200) if claims else (jsonify(error="invalid_token"), 401)

        @app.get("/logout")
        def end_session():
            return redirect(request.args["post_logout_redirect_uri"] + "?state=" + request.args["state"])

        return app

    def approve(self, authorization_url, **overrides):
        """What the browser does after the user clicks Allow: return the callback URL."""
        query = {k: v[0] for k, v in parse_qs(urlsplit(authorization_url).query).items()}
        assert query["client_id"] == self.client_id and query["response_type"] == "code"
        code = secrets.token_hex(8)
        self.codes[code] = {"nonce": query.get("nonce"), "challenge": query["code_challenge"],
                            "redirect_uri": query["redirect_uri"], "overrides": overrides}
        return f"{query['redirect_uri']}?code={code}&state={query['state']}"

    def install(self, rsps):
        """Route every requests call to the provider host into this fake."""
        pattern = re.compile(re.escape(self.issuer) + "/.*")
        for method in (responses.GET, responses.POST):
            rsps.add_callback(method, pattern, callback=self._forward)

    def _forward(self, req):
        path = req.url[len(self.issuer):]
        resp = self.app.test_client().open(path, method=req.method, data=req.body, headers=dict(req.headers))
        return resp.status_code, dict(resp.headers), resp.get_data()


@contextmanager
def provider_online(idp):
    with responses.RequestsMock(assert_all_requests_are_fired=False) as rsps:
        idp.install(rsps)
        yield rsps

The two cases that need a human decision are the ones that the library cannot make for you. An unverified e-mail must not be used to create or link an account. A known e-mail with a new subject means that a person with a second provider account (or an attacker) wants into an existing user; the answer is to ask them to sign in the old way first and to link the identity from inside the authenticated session, never to merge silently. Everything else, a forged state, a lost session cookie, a wrong nonce, a denied consent or a replay, is already refused by Authlib’s checks, and the application only has to turn the exception into a calm error page. Note that invalid ID token claims raise a joserfc JoseError, not an Authlib OAuthError, which is why the callback catches both.

Keeping the state out of the cookie

By default the per-login state (state, nonce, PKCE verifier and redirect URI) is stored inside the session cookie. For an application with many concurrent logins or large cookies, OAuth(app, cache=...) stores it in a cache and leaves only an expiry marker in the cookie. Any object with get, set and delete works; cachelib’s SimpleCache is enough for a single process and its Redis or file-system siblings for several.

OAuth 2.0 Without OpenID Connect: GitHub

GitHub’s "Sign in with GitHub" is plain OAuth 2.0: there is no ID token and no discovery document, so the identity has to be read from the API with the access token. That is what profile_from_github does. Three points matter. The user id (id, a number) is the stable key; the login handle can be renamed and reused. The profile’s email field can be empty or can be a public address the user typed, so the verified, primary address comes from /user/emails, which needs the user:email scope and returns primary and verified flags for each address. And PKCE is available: GitHub’s documentation lists code_challenge and code_challenge_method (only S256) for the authorization request and code_verifier for the token request as strongly recommended, so the registration above enables it. The token endpoint is asked for client authentication in the request body (client_secret_post), the form the GitHub documentation shows. Authlib is told only the URLs; the tests replace GitHub’s four endpoints by canned responses.

When the provider does publish a discovery document, use server_metadata_url and the OpenID Connect path instead: it validates a signed token rather than trusting a JSON answer to a follow-up API call. Flask-Dance

Flask-Dance packages the same flow as a blueprint. make_github_blueprint() returns a blueprint with two routes, the login redirect (/github) and the authorization callback (/github/authorized); you register it with a url_prefix, and Flask-Dance handles state, the token request and token storage. The client id and secret are read from GITHUB_OAUTH_CLIENT_ID and GITHUB_OAUTH_CLIENT_SECRET in app.config (note the _OAUTH_ in the name, unlike Authlib). The result is an access token that you use through the blueprint’s session or the github proxy. A login application connects a receiver to the oauth_authorized signal, builds the profile there and, because it does not need the token afterwards, returns False so that Flask-Dance does not store it.

from flask import make_response
from flask_dance.consumer import oauth_authorized, oauth_error
from flask_dance.contrib.github import make_github_blueprint
from oauthlib.oauth2 import OAuth2Error


def create_dance_app(test_config=None):
    app = create_app(test_config)             # the same factory, so /me and the database are shared
    db = app.extensions["db"]

    github_bp = make_github_blueprint(scope="read:user,user:email", redirect_to="me")
    app.register_blueprint(github_bp, url_prefix="/dance")          # /dance/github, /dance/github/authorized

    @oauth_authorized.connect_via(github_bp)
    def github_authorized(blueprint, token):

Four details of Flask-Dance explain most of the support questions about it.

  • Scopes are a comma-separated string for GitHub. The documented signature takes a comma-separated list, and GitHub answers with a comma-separated scope value. oauthlib compares the granted scope with the requested one and raises a Warning ("Scope has changed") when they differ, so a Python list of two scopes fails against GitHub while the string "read:user,user:email" works. oauthlib skips that comparison when the environment variable OAUTHLIB_RELAX_TOKEN_SCOPE is set, which is the usual workaround for providers that spell the granted scope differently; prefer sending the scope in the form the provider returns it. Unhandled, the warning reaches the user as a 500 page.

  • Errors are not handled for you. A forged state raises oauthlib’s MismatchingStateError, a subclass of OAuth2Error, from the callback view; without the error handler above it is a 500. Provider-side errors such as access_denied are sent through the oauth_error signal, and the user is redirected to redirect_url anyway unless a receiver returns a Response.

  • Plain HTTP is refused. oauthlib raises InsecureTransportError for non-HTTPS URLs. Development servers that use HTTP set OAUTHLIB_INSECURE_TRANSPORT=1 in the local environment only, and never in production, where the real fix is HTTPS (see the proxy section below).

  • Token storage is a choice. The default SessionStorage keeps the token in the signed session cookie: readable by the user, about 4 KB, and gone when the cookie is. SQLAlchemyStorage (see Flask-Dance’s token storages page) keeps one token per user in your database, which is what a multi-user application that calls the provider’s API on behalf of its users needs; then the receiver also links the OAuth record to the user record. A login-only application should store nothing, as above.

Redirect URIs Behind a Proxy

The redirect URI that the application sends must match, character for character, one registered with the provider, and it is built with url_for(..., _external=True) from the request the application sees. Behind a TLS-terminating proxy that request is plain HTTP on an internal host name, so the generated address is http://10.0.0.5:8000/..., the provider rejects it with a redirect mismatch, and (worse) a developer then "fixes" it by enabling plain HTTP. The correct fix is to make Flask aware of the proxy with Werkzeug’s ProxyFix and the exact number of proxy hops you control, so that X-Forwarded-Proto and X-Forwarded-Host are trusted from your proxy and from nobody else. Since Flask 3.1 the TRUSTED_HOSTS setting also rejects requests whose Host is not on a list, which keeps a spoofed host from ending up in a redirect URI. Details of deployment belong to the page about WSGI servers and proxies.

LDAP Authentication

LDAP is a protocol for reading and searching a directory: a tree of entries, each with a distinguished name (DN) such as uid=ada,ou=people,dc=bookshelf,dc=example, and attributes such as mail and memberOf. Directories are also authentication servers, because a client can bind (authenticate) as an entry with its password. Active Directory speaks LDAP too, with sAMAccountName or userPrincipalName where OpenLDAP uses uid. The cookbook recipe builds the DN by formatting the typed user name into a template and binds with it; that is the mistake this section avoids. A user name that contains DN or filter metacharacters can change what is being asked of the directory (LDAP injection), and a DN template also forces every user into one subtree.

The robust pattern is search then bind:

  1. Bind as a dedicated, read-only service account (credentials from the environment).

  2. Search for the single entry whose login attribute equals the typed name, with the name escaped for a filter.

  3. Take the DN from the result and bind as that DN with the typed password; the directory’s answer is the verdict.

  4. Read the attributes and group memberships you need, and unbind both connections.

The authenticator below implements it with ldap3. Four rules are encoded in it: an empty password is rejected before any network call, because a simple bind with a DN and an empty password is an unauthenticated bind that many servers answer with success (ldap3 raises LDAPPasswordIsMandatoryError instead of sending it; other clients send what they are given); the user name is escaped with escape_filter_chars (RFC 4515) and limited in length; the search is limited to two results so an ambiguous match is a failure rather than a coin toss; and an unreachable directory is a different error from wrong credentials, so that an outage does not look like every user forgetting their password. Credentials for the service account are passed in, not written in the code, and no password is ever logged. The connection factory shows the production transport: LDAPS on port 636 with certificate validation required and a connect timeout.

import ssl
from ldap3 import MOCK_SYNC, SIMPLE, SUBTREE, SYNC, Connection, Server, Tls
from ldap3.core.exceptions import LDAPException
from ldap3.utils.conv import escape_filter_chars


class DirectoryUnavailable(Exception):
    """The directory could not be reached (not the same thing as wrong credentials)."""


@dataclass(frozen=True)
class DirectoryUser:
    dn: str
    uid: str
    email: str | None
    name: str | None
    groups: tuple[str, ...]


class LdapAuthenticator:
    """Search-then-bind: find the user's DN with a service account, then bind as the user."""

    def __init__(self, server, base_dn, service_dn, service_password, strategy=SYNC):
        self.server = server
        self.base_dn = base_dn
        self.service_dn = service_dn
        self.service_password = service_password
        self.strategy = strategy

    def _connection(self, user, password):
        return Connection(self.server, user=user, password=password, authentication=SIMPLE,
                          client_strategy=self.strategy, receive_timeout=10)

    def authenticate(self, username, password):
        # An empty password turns a simple bind into an "unauthenticated bind", which many
        # servers accept: refuse it before talking to the directory at all.
        if not username or not password or len(username) > 64:
            return None
        search_filter = f"(&(objectClass=inetOrgPerson)(uid={escape_filter_chars(username)}))"
        try:
            service = self._connection(self.service_dn, self.service_password)
            if not service.bind():
                raise DirectoryUnavailable("service account bind failed")
            try:
                service.search(self.base_dn, search_filter, search_scope=SUBTREE,
                               attributes=["uid", "mail", "cn", "memberOf"], size_limit=2)
                if len(service.entries) != 1:       # unknown user, or an ambiguous match
                    return None
                entry = service.entries[0]
            finally:
                service.unbind()
            user_conn = self._connection(entry.entry_dn, password)
            try:
                if not user_conn.bind():            # wrong password
                    return None
            finally:
                user_conn.unbind()
        except LDAPException as exc:
            raise DirectoryUnavailable(type(exc).__name__) from exc
        return DirectoryUser(entry.entry_dn, entry.uid.value, entry.mail.value, entry.cn.value,
                             tuple(entry.memberOf.values))

import ldap
import ldap.filter


def ldap_authenticate(username, password):
    if not username or not password:
        return None
    conn = ldap.initialize(os.environ["LDAP_URI"])               # e.g. ldaps://ldap.example.test
    conn.set_option(ldap.OPT_REFERRALS, 0)
    conn.set_option(ldap.OPT_NETWORK_TIMEOUT, 5)
    conn.set_option(ldap.OPT_X_TLS_REQUIRE_CERT, ldap.OPT_X_TLS_DEMAND)
    conn.set_option(ldap.OPT_X_TLS_NEWCTX, 0)                    # apply the TLS options above
    try:
        conn.simple_bind_s(os.environ["LDAP_SERVICE_DN"], os.environ["LDAP_SERVICE_PASSWORD"])
        flt = f"(&(objectClass=inetOrgPerson)(uid={ldap.filter.escape_filter_chars(username)}))"
        found = conn.search_s(os.environ["LDAP_BASE_DN"], ldap.SCOPE_SUBTREE, flt, ["uid", "mail", "cn"])
        found = [(dn, attrs) for dn, attrs in found if dn]       # drop referrals
        if len(found) != 1:
            return None
        user_dn, attrs = found[0]
        conn.simple_bind_s(user_dn, password)                    # raises INVALID_CREDENTIALS
        return user_dn, attrs
    except ldap.INVALID_CREDENTIALS:
        return None
    except ldap.SERVER_DOWN as exc:
        raise DirectoryUnavailable("directory down") from exc
    finally:
        conn.unbind_s()

Transport, timeouts and the service account

Concern What to do

Encryption

Bind only over TLS: LDAPS (Server(host, use_ssl=True), port 636) or StartTLS on port 389 (AUTO_BIND_TLS_BEFORE_BIND as the auto_bind argument in ldap3, start_tls_s() in python-ldap). A simple bind sends the password in clear text otherwise.

Certificate checking

ldap3’s default Tls object performs no validation of the server certificate when use_ssl=True; pass a Tls(validate=ssl.CERT_REQUIRED, ca_certs_file=...) as in server_from_env(). In python-ldap use OPT_X_TLS_REQUIRE_CERT with OPT_X_TLS_DEMAND and a CA file.

Timeouts

connect_timeout on the ldap3 Server, receive_timeout on the Connection, OPT_NETWORK_TIMEOUT in python-ldap. Without them a dead directory hangs every worker thread that attempts a login.

Service account

Read-only, allowed to search the user subtree and read only the attributes you list. Its password comes from the environment or a secret manager, and it is never the account of a person.

Stable key

Provision the local user by an immutable attribute such as OpenLDAP’s entryUUID or Active Directory’s objectGUID, not by DN or by uid: DNs change when people move between departments, and names are sometimes reused.

Local password

Never copy the LDAP password into your own database "for later". The cookbook recipe creates a local user with the typed password; the directory is the only place that password may exist.

Throttling

A login form that forwards passwords to a directory is a password-guessing oracle. Rate limit by user and by address (Flask-Limiter is the usual extension) and let the directory’s own lockout policy apply.

From LDAP groups to Flask roles and a login view

The memberOf attribute (an overlay in OpenLDAP, native in Active Directory) lists the groups of a user. Login CSRF and authorization-code injection

A random state bound to the session, removed on first use (Authlib and Flask-Dance do it; test it as above).

Authorization-code interception

PKCE with S256 (code_challenge_method in Authlib, use_pkce=True in Flask-Dance’s generic blueprint); a confidential client also authenticates at the token endpoint.

Summary

  • Delegate sign-in to a provider with Authlib’s OAuth registry: configure <NAME>_CLIENT_ID, <NAME>_CLIENT_SECRET and <NAME>_SERVER_METADATA_URL from the environment, call authorize_redirect() and authorize_access_token(), and read validated claims from token["userinfo"].

  • Authlib creates and checks state, nonce and PKCE (code_challenge_method="S256"); catch OAuthError and JoseError, and show one generic failure page.

  • Link identities by (iss, sub), use e-mail only when verified, and never merge accounts silently.

  • OAuth-only providers such as GitHub need an API call to learn who the user is; ask for PKCE and read the verified primary e-mail from /user/emails.

  • Flask-Dance is a quick blueprint with token storage and signals but no ID token validation, a comma-separated scope quirk for GitHub, no handling of MismatchingStateError and no Twitter module; its last release is from March 2024.

  • Behind a proxy use ProxyFix so redirect URIs are HTTPS and exact; keep the session cookie Lax.

  • For LDAP use search-then-bind with escape_filter_chars, reject empty passwords, require TLS with certificate validation, separate "directory down" from "wrong password", and map memberOf groups to roles.

  • Test with fakes: responses plus a small provider application, and ldap3’s MOCK_SYNC; confirm against the real services before release.
