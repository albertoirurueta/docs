Forms with Flask-WTF

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against Flask 3.1.3 (released 2026-02-18), Flask-WTF 1.3.0 (released 2026-04-23), WTForms 3.2.2, wtforms-sqlalchemy 0.4.2 and Werkzeug 3.1.9, and was checked on 2026-10-07. Flask 3.2 was not released on that date, so anything described as "3.2" is upcoming. The code uses Python 3.10+ syntax and every example was executed on Python 3.13 with app.test_client(). A web form is the one place where a stranger types into your application on purpose, so a form library has three jobs: turn strings into Python values, decide whether the values are acceptable, and prove that the request was meant to be sent by the user who sent it. WTForms does the first two, Flask-WTF connects WTForms to Flask’s request, session and configuration and adds the third (CSRF protection). The scenario is the Bookshelf catalogue that the other pages of this section build on: a form to add a book, a form to review it and a form to upload its cover.

Why Use a Form Library

The Flask request object already gives you everything that was submitted (see Request Data), so a form library is not strictly necessary. The following view handles a book form by hand:

from flask import Flask, request

raw_app = Flask("raw")


@raw_app.post("/books")
def create_book_raw():
    title = request.form.get("title", "").strip()
    pages = request.form.get("pages", "")
    errors = {}
    if not title:
        errors["title"] = "Title is required."
    elif len(title) > 120:
        errors["title"] = "Title is too long."
    if not pages.isdecimal() or not 1 <= int(pages) <= 5000:
        errors["pages"] = "Pages must be a number between 1 and 5000."
    if errors:
        return {"errors": errors}, 422
    return {"title": title, "pages": int(pages)}, 201


with raw_app.test_client() as client:
    print(client.post("/books", data={"title": "", "pages": "abc"}).get_json())
    print(client.post("/books", data={"title": "Dune", "pages": "412"}).get_json())

Source: Flask: Form Validation with WTForms

This works for two fields and then stops scaling. Every field needs its own conversion, its own error messages, its own re-display of what the user typed, its own HTML and, on every state-changing request, a CSRF check that is easy to forget. WTForms puts those concerns in one declarative class:

  • Declaration. A form is a class whose attributes are fields; each field carries its type, label, validators and filters.

  • Processing. The form reads the submitted data, converts it (IntegerField yields an int, DateField a date) and keeps the raw input so the page can be re-rendered with what the user typed.

  • Validation. Validators run per field and collect error messages in form.errors.

  • Rendering. Each field renders itself as HTML through a widget and can be given extra attributes, so the template never repeats names, ids or values.

  • Security. Flask-WTF adds a CSRF token field to every FlaskForm and validates it as part of validate().

Which library does what is worth knowing, because the documentation is split:

Package Responsibility

WTForms

Form, fields, validators, widgets, filters, the Meta class (CSRF and translation hooks) and the processing and validation algorithm. Knows nothing about Flask.

Flask-WTF

FlaskForm (reads request, supplies the CSRF secret from Flask’s config), CSRFProtect, the csrf_token() and csrf_meta_tag() template helpers, file fields and validators (FileField, FileRequired, FileAllowed, FileSize) and the reCAPTCHA field.

ItsDangerous

Signs and time-stamps the CSRF token (the same library that signs the session cookie).

Werkzeug

Supplies request.form, request.files and FileStorage, which WTForms reads through wrap_formdata.

wtforms-sqlalchemy

QuerySelectField and friends and the model_form helper. A separate package, because the extensions that used to live inside WTForms were removed in WTForms 3.

Form handling in other frameworks is described in Django Forms and in the FastAPI section, where Pydantic models play the role of the form class. A Flask application that exposes only a JSON API does not need WTForms; it needs a schema library instead (see the REST API pages of this section).

FlaskForm, Fields and Validators

A form is a subclass of flask_wtf.FlaskForm. Fields come from wtforms and validators from wtforms.validators:

import os
import secrets

from flask import Flask, flash, redirect, render_template_string, request, url_for
from flask_wtf import FlaskForm
from wtforms import BooleanField, IntegerField, StringField, SubmitField, TextAreaField
from wtforms.validators import InputRequired, Length, NumberRange, Optional, Regexp

app = Flask(__name__)
# Read the key from the environment; fall back to a random per-process key for local runs only.
app.config["SECRET_KEY"] = os.environ.get("BOOKSHELF_SECRET_KEY") or secrets.token_hex(32)


class BookForm(FlaskForm):
    title = StringField("Title", validators=[InputRequired(), Length(max=120)])
    isbn = StringField(
        "ISBN-13",
        validators=[InputRequired(), Regexp(r"^97[89]\d{10}$", message="Enter 13 digits, no hyphens.")],
    )
    pages = IntegerField("Pages", validators=[InputRequired(), NumberRange(min=1, max=5000)])
    summary = TextAreaField("Summary", validators=[Optional(), Length(max=2000)])
    in_stock = BooleanField("In stock", default=True)
    submit = SubmitField("Save")

SECRET_KEY is mandatory: the CSRF token is signed with it (or with WTF_CSRF_SECRET_KEY), and a form without a key raises RuntimeError("A secret key is required to use CSRF.") the first time it is rendered. Never write the key in the source; generate it with python -c "import secrets; print(secrets.token_hex())" and inject it through the environment or the instance configuration. The random fallback above is acceptable for a single development process only, because every Gunicorn worker would invent a different key and reject the others' tokens.

FlaskForm() called without arguments does the Flask-specific work. If the current request uses POST, PUT, PATCH or DELETE, it takes the submitted data from request.files and request.form (combined when files are present), or from the JSON body when the request is JSON and there are no form fields. On a GET it builds an empty form. Pass formdata=None to ignore the request entirely, or any other mapping to feed the form from somewhere else.

validate_on_submit() is is_submitted() and validate(). A form that is not submitted (a GET) is never validated, so a first visit does not display "this field is required" everywhere. Three habits make this pattern correct:

  • Redirect after a successful POST (Post/Redirect/Get), so a browser refresh does not resubmit the form and flash() shows its message on the next page.

  • Return an error status when validation fails. Returning 422 Unprocessable Content (or 400) tells HTMX, Turbo and scripts that the submission was rejected; returning 200 works for plain browsers but hides the failure from tooling.

  • Read values from form.<field>.data, never from request.form, so the values you use are the converted and validated ones.

The facts the example demonstrates:

  • A field is callable. field(placeholder="...", rows=4) renders the widget with those attributes added; a trailing underscore (class_=) or render_kw on the field covers reserved words, and data_foo= becomes data-foo.

  • field.errors is a list of messages; form.errors is a dict of field name to messages. The rejected submission is rendered with what the user typed (value="Dune"), because the field keeps raw_data.

  • form.hidden_tag() renders every hidden field, including the CSRF token. Forgetting it is the most common reason for a form that "never validates".

  • novalidate on the <form> turns off the browser’s own validation so that the server’s messages are the ones shown; browser validation is a convenience and never a defence, because anyone can send a request without a browser.

  • Jinja autoescapes the field output: widgets return Markup, while messages and values are escaped. Do not wrap user input in |safe.

Validators

A validator is a callable validator(form, field) that returns nothing when the value is fine and raises wtforms.validators.ValidationError (message collected, validation continues with the next validator) or StopValidation (message collected, the chain stops) otherwise. The built-in ones that matter:

Validator Behaviour and pitfalls

InputRequired()

Passes if the browser sent a non-empty raw value. Use it for text and numbers. It sets the required flag on the field.

DataRequired()

Passes if the converted value is truthy. A BooleanField unchecked or an IntegerField containing 0 fails it, which is rarely what you want; use it for fields where an empty value is meaningless.

Optional()

If the input is empty it stops the chain, so later validators such as Length(min=3) do not run on an empty optional field. It also clears earlier errors from the conversion step.

Length(min, max)

Length of the string or list; either bound may be omitted.

NumberRange(min, max)

Compares numbers and dates; either bound may be omitted.

Regexp(regex, flags, message)

re.match semantics: anchored at the start only, so add $ yourself.

Email(), URL(), IPAddress(), MacAddress(), UUID()

Syntax checks. Email needs email_validator; URL accepts any scheme-like host by default (require_tld is on), so it does not by itself prevent javascript: style input when you later render the value in an href.

EqualTo(fieldname)

For "repeat the password" fields.

AnyOf(values), NoneOf(values)

Allow or forbid listed values; since WTForms 3.2 they also work on multi-valued fields such as SelectMultipleField.

ReadOnly(), Disabled()

Reject a value different from the object’s (or any submitted value for Disabled), for fields rendered read-only.

Pitfalls:

  • A nested form is a subform of the outer one: only the outer form carries the CSRF field, so give the inner class csrf = False in its Meta (or use plain wtforms.Form, which has no CSRF at all).

Custom Validators

A validator with options is a class with __init__ and __call__; one without is a function. The Bookshelf needs an ISBN-13 check-digit validator and a "title is unique on this shelf" rule that needs state:

def isbn13(form, field):
    digits = field.data or ""
    if len(digits) != 13 or not digits.isdecimal():
        raise ValidationError("An ISBN-13 has exactly 13 digits.")
    total = sum(int(d) * (1 if i % 2 == 0 else 3) for i, d in enumerate(digits[:12]))
    if (10 - total % 10) % 10 != int(digits[12]):
        raise ValidationError("The ISBN check digit is wrong.")


class UniqueIn:
    """Reject a value that is already present in the collection returned by ``source()``."""

    def __init__(self, source, message=None):
        self.source = source
        self.message = message

    def __call__(self, form, field):
        if field.data in {item["title"] for item in self.source()}:
            raise ValidationError(self.message or "This title is already on the shelf.")

Two details decide whether a validator is correct. Custom Fields

A field converts between form input and Python. Override process_formdata(valuelist) to turn the list of submitted strings into data, and _value() to produce the string shown in the widget:

from wtforms import Field
from wtforms.widgets import TextInput


class TagListField(Field):
    """Comma separated text in the browser, list[str] in Python."""

    widget = TextInput()

    def _value(self):
        return ", ".join(self.data) if self.data else ""

    def process_formdata(self, valuelist):
        if valuelist:
            tags = [t.strip().lower() for t in valuelist[0].split(",")]
            self.data = sorted({t for t in tags if t})
        else:
            self.data = []

Custom Widgets

A widget is a callable widget(field, **kwargs) that returns HTML (a Markup string, so Jinja does not escape it again). html_params builds the attribute string and escapes the values:

from markupsafe import Markup
from wtforms.widgets import html_params


class RatingWidget:
    """Render 1..max as radio buttons inside a fieldset."""

    def __init__(self, max_stars: int = 5):
        self.max_stars = max_stars

    def __call__(self, field, **kwargs):
        kwargs.setdefault("id", field.id)
        parts = [f"<fieldset {html_params(id=kwargs['id'], class_='rating')}>"]
        for value in range(1, self.max_stars + 1):
            attrs = html_params(type="radio", name=field.name, value=value, id=f"{field.id}-{value}")
            checked = " checked" if field.data == value else ""
            parts.append(f'<label><input {attrs}{checked}> {value}</label>')
        parts.append("</fieldset>")
        return Markup("".join(parts))

CSRF Protection

Cross-site request forgery makes the victim’s browser send a state-changing request that the browser authenticates with its own cookies. The defence Flask-WTF implements is the synchroniser token pattern: the server stores a random value in the session and puts a signed, time-stamped version of it in every form; a forged request cannot know the token.

Forms: Automatic

Every FlaskForm has a csrf_token hidden field and validates it in validate(). Nothing else is needed beyond form.hidden_tag() (or {{ form.csrf_token }}) in the template. The token is bound to the session cookie, signed with WTF_CSRF_SECRET_KEY (default SECRET_KEY), and valid for WTF_CSRF_TIME_LIMIT seconds (default 3600). Because the token depends on the session, a form left open longer than the hour, or after the session was cleared, fails with "The CSRF token has expired." Users who keep forms open overnight need a longer limit (or None, meaning the token lives as long as the session).

CSRFProtect: Non-WTForms Views, AJAX and APIs

CSRFProtect extends the same check to every unsafe-method request of the application, whether or not a FlaskForm is involved, by registering a before_request hook. It reads the token from the form field or from the X-CSRFToken or X-CSRF-Token header, so JavaScript clients can send it without a form. csrf_token() is a Jinja global, and csrf_meta_tag() (Flask-WTF 1.3) renders a <meta name="csrf-token"> tag that scripts can read:

    return jsonify(error="csrf", reason=error.description), 400

    html = client.get("/").get_data(as_text=True)
    meta_token = re.search(r'<meta name="csrf-token" content="([^"]+)"', html).group(1)

    print(client.post("/api/like", json={"book": 1}).get_json())
    print(client.post("/api/like", json={"book": 1}, headers={"X-CSRFToken": meta_token}).get_json())
    print(client.post("/webhooks/printer", json={}).get_json())
    print(client.post("/api/like", json={"book": 1}, headers={"X-CSRFToken": "forged"}).get_json())

Source: Flask-WTF: CSRF Protection

How the pieces fit:

  • Order matters. Create CSRFProtect before the first request is handled (inside the application factory with csrf.init_app(app)); Flask refuses to register hooks after that.

  • Both mechanisms can coexist. When CSRFProtect has already validated a request it marks it in g, and the form’s own CSRF check is skipped, so the token is not verified twice.

  • Exemptions. @csrf.exempt takes a view function (decorator order matters: it goes below @route) or a blueprint. Exempt only endpoints that do not rely on cookies for authentication, such as machine-to-machine webhooks.

  • Error handling. A failed check raises CSRFError, a 400 Bad Request; the default page shows the reason. Register an error handler (see Error Handling) to render something friendlier or JSON.

  • Reading the token yourself. generate_csrf() returns the signed token for the current session (the same value for the whole request) and validate_csrf(data) raises wtforms.ValidationError on failure, for protocols where the token travels in an unusual place.

  • HTTPS and the referrer. With WTF_CSRF_SSL_STRICT on, an HTTPS request without a matching Referer is refused even with a valid token, which breaks clients that strip the header; the failure message is "The referrer header is missing."

  • JSON APIs that use tokens in the Authorization header are not CSRF-prone, because the browser does not attach that header on its own, so they typically exempt the API blueprint. APIs authenticated with the session cookie are prone and need the header.

  • Cookies still matter. The session cookie should be SameSite=Lax (Flask’s SESSION_COOKIE_SAMESITE, covered on the sessions page of this section) and Secure in production; SameSite reduces the attack surface but does not replace the token.

  • Do not turn it off to "make it work". In tests set WTF_CSRF_ENABLED = False in a testing configuration, or fetch a real token as the examples above do; never disable it in the production config.

File Fields

flask_wtf.file.FileField reads FileStorage objects from request.files (WTForms' own FileField does not, which is why the book’s import from wtforms needs to change). Validators check presence, extension and size, and the form must be sent as multipart/form-data:

import tempfile
from io import BytesIO
from pathlib import Path

from flask_wtf.file import FileAllowed, FileField, FileRequired, FileSize, MultipleFileField
from werkzeug.utils import secure_filename


class CoverForm(FlaskForm):
    cover = FileField(
        "Cover image",
        validators=[
            FileRequired(),
            FileAllowed(["jpg", "jpeg", "png", "webp"], "Images only."),
            FileSize(max_size=2 * 1024 * 1024, message="At most 2 MiB."),
        ],
    )
    extras = MultipleFileField("Extra pages", validators=[Optional(), FileAllowed(["pdf"])])


UPLOAD_DIR = Path(tempfile.mkdtemp())  # in a real app: a directory outside the web root

files_app = Flask("files")
files_app.config["SECRET_KEY"] = os.environ.get("BOOKSHELF_SECRET_KEY") or secrets.token_hex(32)
files_app.config["MAX_CONTENT_LENGTH"] = 4 * 1024 * 1024


@files_app.route("/books/<int:book_id>/cover", methods=["GET", "POST"])
def upload_cover(book_id):
    form = CoverForm()
    if request.method == "GET":
        return form.hidden_tag()
    if form.validate_on_submit():
        name = f"{book_id}-{secrets.token_hex(8)}-{secure_filename(form.cover.data.filename)}"
        form.cover.data.save(UPLOAD_DIR / name)
        return {"stored": name}, 201
    return {"errors": form.errors}, 422


with files_app.test_client() as client:
    token = csrf_token_from(client.get("/books/7/cover").get_data(as_text=True))
    png = (BytesIO(b"\x89PNG\r\n\x1a\n" + b"0" * 64), "../../evil name.png")
    ok = client.post("/books/7/cover", data={"csrf_token": token, "cover": png}, content_type="multipart/form-data")
    print(ok.status_code, ok.get_json()["stored"].endswith("-evil_name.png"), len(list(UPLOAD_DIR.iterdir())))
    exe = (BytesIO(b"MZ"), "setup.exe")
    bad = client.post("/books/7/cover", data={"csrf_token": token, "cover": exe}, content_type="multipart/form-data")
    print(bad.status_code, bad.get_json())
    none = client.post("/books/7/cover", data={"csrf_token": token}, content_type="multipart/form-data")
    print(none.status_code, none.get_json())

  • FileRequired fails when the browser sent an empty file input, which DataRequired or InputRequired cannot detect.

  • FileAllowed compares the lower-cased filename suffix against a list of extensions (or a Flask-Uploads UploadSet). The filename is chosen by the client, so this is not a content check; verify the content (for images, open the file with an imaging library) before trusting it.

  • FileSize(max_size, min_size=0) is in bytes and validates one or several files (since Flask-WTF 1.2.0 the three file validators also accept MultipleFileField). Combine it with MAX_CONTENT_LENGTH, the request-level limit that rejects oversized bodies with 413 before the form is built (see Request Data).

  • Always pass the client’s name through secure_filename() and add a random component, as above, or store under an identifier of your own; never use the raw name as a path. secure_filename lives in werkzeug.utils; the old from werkzeug import secure_filename in the books no longer works.

  • Storing the file, serving it with send_from_directory, size limits and image processing are the subject of the File Uploads page of this section.

The reCAPTCHA Field

Flask-WTF ships RecaptchaField, which renders Google reCAPTCHA v2 (or a compatible service) and verifies the response with the provider’s server-side API. It is mentioned here for completeness rather than recommended: bots increasingly solve challenges, and a rate limiter, honeypot field or a provider with a privacy-respecting challenge is often a better answer. The keys come from configuration, never from source:

from flask_wtf import RecaptchaField

app.config["RECAPTCHA_PUBLIC_KEY"] = os.environ.get("RECAPTCHA_PUBLIC_KEY", "")
app.config["RECAPTCHA_PRIVATE_KEY"] = os.environ.get("RECAPTCHA_PRIVATE_KEY", "")


class ContactForm(FlaskForm):
    name = StringField("Name", validators=[InputRequired()])
    captcha = RecaptchaField()


# The validator is skipped when app.testing is true or RECAPTCHA_ENABLED is false.
app.config["TESTING"] = True
with app.test_request_context("/", method="POST"):
    form = ContactForm(formdata=MultiDict({"name": "Ana"}), meta={"csrf": False})
    print(form.validate())
app.config["TESTING"] = False

Source: Flask-WTF: reCAPTCHA

RECAPTCHA_PUBLIC_KEY and RECAPTCHA_PRIVATE_KEY are required (the widget and the verification raise RuntimeError when they are missing); RECAPTCHA_PARAMETERS, RECAPTCHA_DATA_ATTRS, RECAPTCHA_SCRIPT, RECAPTCHA_DIV_CLASS, RECAPTCHA_HTML and RECAPTCHA_VERIFY_SERVER customise the script, the markup and the verification endpoint (which is how hCaptcha or Turnstile are plugged in, since Flask-WTF 1.0). Version 1.3 added a nonce argument for pages with a nonce-based Content Security Policy. The page loads a third-party script and sends the visitor’s data to the provider, so account for it in your privacy notice and your CSP.

Translating Validation Messages

WTForms ships translated validator messages. With Flask-Babel installed and WTF_I18N_ENABLED true (the default), Flask-WTF uses the locale that Flask-Babel selected for the request. Without Flask-Babel, or with the switch off, the Meta.locales list picks the language, which is also the easiest way to test it:

app.config["WTF_I18N_ENABLED"] = False


class SpanishBookForm(BookForm):
    class Meta(BookForm.Meta):
        locales = ["es"]


with app.test_request_context("/", method="POST"):
    form = SpanishBookForm(formdata=MultiDict({"title": "", "isbn": "x", "pages": "1"}), meta={"csrf": False})
    form.validate()
    print(form.errors["title"])

app.config["WTF_I18N_ENABLED"] = True

Source: WTForms: Internationalization

Labels and your own messages are not translated automatically; wrap them in lazy_gettext (see the internationalisation page of this section). Message strings in message= arguments are shown verbatim.

Testing Forms

Two approaches work, and both avoid weakening production configuration:

  • Unit-test the form in a test_request_context with meta={"csrf": False}, as the examples above do. It tests validators and conversions without HTTP.

  • Test the view with the test client. Either configure WTF_CSRF_ENABLED = False in the testing config, which skips every token check, or do the real round trip (GET the page, extract the token with a regular expression or an HTML parser, POST it back) to prove that the template really contains hidden_tag(). Keep at least one test of the second kind per form, since the first can hide a missing token.

Test the failure paths too: a missing token, a tampered token and an expired token (set WTF_CSRF_TIME_LIMIT to -1 inside the test to expire immediately).

Pitfalls and Security Summary

  • Missing hidden_tag() (or form.csrf_token) makes every POST fail with "The CSRF token is missing."

  • validate() returns False for unsubmitted forms. Use validate_on_submit() in views; a GET form never validates.

  • Choices must be set before validation, and coerce must match the type of the choice values.

  • DataRequired rejects 0 and False. Prefer InputRequired for numbers and use Optional deliberately.

  • Never trust HiddenField, readonly or disabled. They are rendering hints; validate on the server.

  • Allow-list, do not deny-list, for uploads, redirect targets (next parameters) and sort columns that come from forms.

  • Mass assignment. Do not copy form.data straight onto a model (Book(**form.data)); it includes the CSRF token and the submit button, and lets a future field reach an attribute you did not intend. Assign fields explicitly or with form.populate_obj(book) on a form that holds only the editable fields.

  • Re-displaying input is safe only because of autoescaping. Do not build field HTML with string formatting and |safe.

  • A SECRET_KEY that changes between restarts invalidates every open form and session; keep it stable and rotate it deliberately.

  • Cookies and CORS. CSRF protection assumes the browser sends cookies only from your own site; a permissive CORS policy with credentials defeats it (see CORS).

The cookbook chapter on forms is useful for its structure (a form per concern, shared field sets, a custom field, a custom widget, a file upload and CSRF with AJAX) and every one of those ideas is covered above, but its code predates the changes in the table:

  • from flask_wtf import Form and Form as the base class: flask_wtf.Form is now only a re-export of WTForms' plain Form, which has no request integration and no CSRF field. Use FlaskForm.

  • from wtforms import TextField raises ImportError; use StringField. validators.Required is likewise gone.

  • from wtforms.ext.sqlalchemy.fields import QuerySelectField fails because wtforms.ext no longer exists; import from wtforms_sqlalchemy.fields.

  • FileField must come from flask_wtf.file, and secure_filename from werkzeug.utils.

  • Form(csrf_enabled=False) was replaced by meta={"csrf": False}; the old keyword is now silently ignored.

  • Queries written as Model.query.all() in the query_factory are the legacy SQLAlchemy API; use session.scalars(select(Model)) or db.session.scalars(db.select(Model)).

  • Examples with a literal SECRET_KEY or a key committed to the repository must be replaced by a generated key held in the environment.

Summary

  • A FlaskForm declares fields and validators, reads request.form and request.files itself, and signs a CSRF token.

  • In a view: build the form, validate_on_submit(), act and redirect; otherwise render with the errors and a 422.

  • Put the token in the page with form.hidden_tag(); for AJAX and non-WTForms views use CSRFProtect and the X-CSRFToken header (or csrf_meta_tag()).

  • Custom validators are callables, custom fields override process_formdata and _value, custom widgets return Markup.

  • Set choices on the instance before validating; use wtforms-sqlalchemy for query-backed selects.

  • File fields come from flask_wtf.file, and the extension check is not a content check.
