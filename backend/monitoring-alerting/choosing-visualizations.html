Choosing a Visualization

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked on 2026-11-09 against Grafana 13.3.x and Kibana 9.5.x.

A chart is an answer to a question. When the chart type is chosen first (because it looks good, or because it is the default) the dashboard shows data but not information. This page works the other way round: it starts from the question and arrives at a panel in Grafana and a chart in Kibana. How to lay the charts out on a dashboard is covered by Dashboard Design Principles; which metrics to chart is covered by RED, USE and the Golden Signals. The detailed pages per tool are Grafana: Graphs and Charts, Grafana: Stats, Tables and Widgets, Grafana: Logs, Traces and Special Panels and Kibana: Lens.

The catalogues

Grafana’s catalogue lists 25 visualizations in four groups: graphs and charts (Time series, State timeline, Status history, Bar chart, Histogram, Heatmap, Pie chart, Candlestick, Gauge, Trend, XY chart), stats and numbers (Stat, Bar gauge), widgets (Dashboard list, Alert list, Annotations list, Text, News) and a miscellaneous group (Table, Logs, Node graph, Traces, Flame graph, Canvas, Geomap). More types can be added with panel plugins.

Source: Grafana: Visualizations.

Kibana’s default editor is Lens, which offers XY charts (bar, line, area), partition charts (pie, donut, treemap, waffle, mosaic), single value charts (metric, gauge) and further charts (table, heat map, tag cloud, region map). Next to it there are ES|QL charts, Discover sessions as panels, Maps, alert panels, Vega, custom panels, Markdown, image and link panels, machine learning and SLO panels. The aggregation-based and TSVB editors are legacy (Stack only, unavailable on Serverless) and only show up in the Add menu if a dashboard already contains such panels. Custom panels are Planned on Stack and Preview on Serverless.

Source: Kibana: Visualize and Kibana: Lens.

Equivalences are by purpose, not by identical features. Kibana’s catalogue does not list a state timeline, and its Canvas survives only for existing content, so new Kibana work uses the other rows. Check each Kibana feature’s availability on its page in the Kibana subsection (for example Maps, Vega and Other Panels and Legacy Editors, Canvas and Graph).

Kibana’s own advice is to start from the question: trends over time with line or area, comparisons across categories with bar, share of a total with pie, treemap, waffle or mosaic, a single number or progress toward a goal with metric or gauge, exact values with a table, and geographic patterns with a region map. New Lens visualizations default to bar or line, so change the type if neither fits. Lens also has a Suggestions panel that proposes charts from the fields you drag in.

Source: Kibana: Lens ("Choosing a visualization").

The questions in more detail

Trend over time

A time series chart is the workhorse of monitoring. Use lines for continuous measurements such as latency, bars for discrete counts per interval such as events per minute, and areas where volume matters. Always show the unit and, when the chart has a threshold, show it as a line or region. In Grafana, $__interval and the query options set the resolution (see Metric Types and Aggregation); in Lens the date histogram interval does. For sparse data Lens has a "missing values" option for line and area charts, and the Grafana state timeline has "connect null values" options, so that gaps are handled deliberately rather than by accident.

Current value

A Stat panel (Grafana) or Metric (Lens) gives one large number, and is the right tool for a status row at the top of a dashboard. Add a sparkline for context and thresholds for colour. Prefer Stat to a Gauge when the position in a range adds nothing: gauges take space and give one number. A Gauge or Bar gauge is useful when the range is meaningful, such as pool utilisation from 0 to 100 percent. Bar gauges compare several values in the same range compactly.

Distribution

Averages hide the shape of the data. A histogram shows the distribution of values; a heatmap shows how the distribution changes over time, which is the best way to see a bimodal latency (a fast cache path and a slow database path) develop. Prometheus classic histograms provide the buckets, which the heatmap draws directly.

sum by (le) (rate(http_server_requests_seconds_bucket{application="bookshelf"}[$__rate_interval]))

Source: Grafana: Heatmap. The metric and label names are the Micrometer ones from the Bookshelf service; the $__rate_interval variable is described in Grafana: Prometheus template variables.

For percentile lines, compute the quantile from summed buckets, never from per-instance percentiles (see the anti-patterns).

Proportion

Pie charts answer "what share is each part of a whole" and only that. Grafana’s page describes them as suited to data that adds up to a total, and notes that a pie chart shows a single pie regardless of how many series the query returns and that by default it uses only the last row of data (the Show option is set to Calculate), so switch to All values to show multiple rows. For more than a handful of parts, or for comparing parts, a sorted bar chart is easier to read. In Lens, a percent of total is a formula with a percent value format:

sum(products.base_price) / overall_sum(sum(products.base_price))

Source: Kibana: Lens ("Recommendations", "Percent of total"). The field is the one used on that page; use your own numeric field.

State over time

A state timeline shows coloured regions for how long an entity stayed in each state: a service up or down, a deployment in progress, a circuit breaker open. It needs table-shaped data with a timestamp, an entity and a state value, though time series data works too when thresholds create the regions. Status history is the related panel for recurring states over periods. Kibana has no direct counterpart, which is one of the places where a dashboard must be designed differently in each tool.

Source: Grafana: State timeline.

Top N and exact values

If the reader needs a ranking or exact values, use a table: Grafana’s table has cell types, sparklines and a footer, and Lens tables take a terms breakdown with a limit and a sort. If only the ranking matters, a bar chart is faster to read. Put the unit in the column, not in the heading.

Geography, relationships, logs and traces

Use geographic charts only when location is part of the question. Logs and traces have dedicated panels in Grafana, and in Kibana the logs are viewed in Discover (Logs Explorer was removed in 9.0), which can be embedded in a dashboard as a Discover session panel (GA on Stack since 9.4). Link from a metric panel to the logs of the same time window instead of putting logs next to it, which is covered by Grafana: Annotations and Links and Kibana: Controls and Drilldowns.

Anti-patterns

  • Pie charts with many slices. Slices are hard to compare by angle, labels overlap and small parts disappear. Use at most a few parts, group the rest into "other", or use a bar chart. Grafana’s page documents a Limit option under value options that caps the number of values (it applies when Show is set to All values), and notes that labels may be clipped.

  • Dual axes. Two y-axes with different scales invite false correlation: the reader sees lines crossing where nothing related happens. Both tools support it (Grafana axis placement, and Lens Left or Right per y-axis), and the Grafana guide recommends it for series with different units or ranges. If you use it, label both axes, colour the axis to match its series, and prefer two stacked panels sharing one time axis.

  • Averages of percentiles. A percentile cannot be averaged. Prometheus documentation states that averaging per-instance quantiles gives statistically nonsensical values, and that summary quantiles cannot be aggregated. Sum the histogram buckets across instances first, then compute the quantile:

    histogram_quantile(0.95, sum by (le) (rate(http_server_requests_seconds_bucket{application="bookshelf"}[5m])))

    Source: Prometheus: Histograms and summaries. For the Kibana side see Metric Types and Aggregation.

  • Stacked graphs of things that are not parts of a whole. Stacking sums the series, so a stacked latency chart shows a meaningless total. The Grafana guide says stacked graphs can mislead and hide data and are usually turned off.

  • Averages instead of distributions for latency (see above), and rates shown as counters, which only ever climb.

  • Rainbow colours. Use colour for state, with a consistent scheme, as in the dashboard principles page.

  • A gauge for everything. Stats and tables carry more information in less space.

  • A y-axis that does not start at zero for bars. Lens requires zero to be within the bounds of bar and area charts for exactly this reason.

Sources: Grafana: Pie chart; Grafana: Dashboard best practices; Kibana: Lens.

What can go wrong

  • The chart shows only the last value. The pie chart’s Show option defaults to Calculate (last row); a state timeline or table can look empty when the data is not table-shaped. Check the panel inspector, or apply a transformation (see Grafana: Transformations and Expressions).

  • Series explosion. A bar chart with one bar per user id or URL path has high cardinality. Limit the breakdown (Top N), and fix the labels at the source.

  • The same colour for different things. Use Lens colour mapping and Grafana overrides to pin colours to values.

  • Thresholds that disagree with alerts. The chart turns red at one value and the alert fires at another. Keep a single source, or reference variables in thresholds (Grafana 13.3 supports variable interpolation in panel thresholds).

Verify it in the lab

In the lab (Hands-on Lab), with the load generator running:

  1. Build the request-rate trend as a Time series (Grafana) or Lens line (Kibana) and confirm the units.

  2. Add the 5xx ratio as a Stat or Metric with thresholds, then run curl -X POST localhost:8090/mode/failing and confirm the colour changes.

  3. Draw the duration heatmap and confirm that curl -X POST localhost:8090/mode/slow moves the band upwards.

  4. Switch a pie of status classes to a sorted bar chart and compare which one makes the small slices readable.

  5. Compute p95 from summed buckets, then compute the average of per-instance p95 values, and confirm that they differ when one instance is slow.

In the books

The Hernandez book still names the Singlestat and Worldmap panels, which Grafana removed in 12.0 with the other Angular panels; their replacements are Stat and Geomap. The Shah, Chhajed and Melachi books build the same charts with the aggregation-based editors, TSVB or Kibana 4 visualizations, which in current Kibana are legacy and replaced by Lens (the aggregations are the same, the editor is not). The chart choice advice in the books remains valid. Chhajed’s tile map and Paro’s coordinate and region maps correspond today to Maps and the Lens region map.
