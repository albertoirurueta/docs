Kibana: Legacy Editors, Canvas & Graph

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked on 2026-11-09 against Kibana 9.5.x.

Old Kibana tutorials, blog posts and dashboards you inherit are full of tools that are no longer the way to build something new: the "Visualize" editors, the Time Series Visual Builder (TSVB), Timelion, Canvas workpads and the Graph app. They still run in the Elastic Stack, they are not available on Serverless, and you will meet them in dashboards that were built years ago and must keep working. This page explains what each of them did, how they differ from Lens, how to convert what can be converted, and when to leave something alone. It also helps to read the books that teach Kibana (see the table at the end) without copying outdated steps. The Grafana parallel is the removal of the Angular panels (Graph, Singlestat, Worldmap) described in Grafana Logs, Traces and Special Panels, and the chart choice for new work is in Choosing Visualizations.

Source: Kibana: Legacy editors. The page calls them "still available but replaced by better alternatives", lists aggregation-based, TSVB and Timelion, marks them generally available on the Stack and unavailable on Serverless, and does not give a removal date.

Finding the legacy editors

Source: Kibana: Legacy editors (create a legacy visualization).

On 9.4 and later go to Dashboards, Visualizations, Create visualization, the Legacy tab, and choose TSVB or Aggregation-based. On 9.0 to 9.3 the entry point is the Visualize library (search for it in the menu bar). Legacy panel types appear in the dashboard Add menu only if the dashboards already contain them: if you have never used them, use Lens, as the landing page of Panels and visualizations advises.

Aggregation-based editors

Source: Kibana: Aggregation-based visualizations.

What it is. The original Kibana panels: area, data table, gauge, goal, heat map, horizontal bar, vertical bar, line, metric, pie and tag cloud. Each is a form that stacks bucket and metric aggregations (the vocabulary of Metric Types and Aggregation): choose a metric, then a bucket for the X axis and up to three levels of split series or split charts. That is more nesting than Lens or TSVB allow, and the editor accepts non-time series data and a saved Discover session as its input; its limits are few styling options, no maths between aggregations, no multiple indices, and a Date Histogram on the automatic interval requires the data view’s primary time field. A worked example on the page is a vertical bar of Date Histogram split by a terms bucket on a source field, which shows the top traffic sources over time.

Moving to Lens. The area, data table, gauge, goal, heat map, horizontal bar, line, metric, pie and vertical bar types can be opened in Lens with Edit visualization in Lens in the toolbar. To convert a panel already on a dashboard, enter edit mode, open the panel menu and choose Convert to Lens (it appears only when Kibana can convert the configuration, and needs at least read access to the Visualize library feature), then Save and return to replace the panel. Compare the result with the original before saving: a conversion that cannot represent a setting does not offer itself.

TSVB

Source: Kibana: TSVB.

What it is. The Time Series Visual Builder combines many aggregations in a time series chart, annotates the series with events from an Elasticsearch index, shows several data views in one visualization and applies functions and maths. Its panel types are Time Series, Metric, Top N, Gauge, Table and Markdown (Handlebars syntax with custom CSS). Each series behaves like a separate aggregation, with functions such as Filter Ratio (the error rate as one document set divided by another), Counter Rate, Positive Only, Series Agg and Math, and group-by options Filters and Terms. It is exactly the tool that people used to chart Bookshelf’s error ratio before Lens had formulas.

Limits that explain why it was replaced. No maths across series (the page recommends Timelion or Vega for differences between series), month-over-month changes only partly supported, no event durations computed from start and end times, derivatives that return nothing when the interval is too small, the last bucket dropped by default, and a y-axis that includes zero unless the fill is changed. Using an Elasticsearch index string instead of a data view is deprecated and will be removed; an administrator can still enable it with the metrics:allowStringIndices advanced setting.

Moving to Lens. Time Series, Metric, Top N, Gauge and Table panels open in Lens through Edit visualization in Lens and convert with Convert to Lens; Markdown is not listed as convertible and becomes a Markdown text panel (see Maps, Vega & Other Panels). By purpose the old features map as follows:

TSVB feature Replacement

Filter Ratio

A Lens formula such as count(kql='...') / count()

Counter Rate, derivative

The counter-rate and difference functions in the Lens formula reference, or RATE in an ES|QL TS query

Annotations from an index

An annotation layer with a custom query

Top N

A horizontal bar with a rank limit

Markdown panel

A Markdown text panel

Math across series

A Lens formula, an ES|QL EVAL, or Vega

The TS command and RATE are covered in Querying with KQL, ES|QL & PromQL; check the Lens formula reference icon for the exact function names of your version.

Timelion

Source: Kibana: Timelion.

Timelion is an expression language for time series: functions start with a dot and chain, for example .es(index=logs-*, timefield='@timestamp', metric='max:bytes').derivative().divide(1024).label('KB per second'), with .es fetching data (counting documents by default), series separated by commas, and functions for offsets, styling, multiple y-axes, conditions (.if()) and moving averages. It is marked deprecated since 7.10 and unavailable on Serverless. A Timelion panel is created from Create visualization, Legacy, Aggregation-based, Timelion (9.4 and later) and has to be saved to the library before it can be added to a dashboard from the library. Existing expressions are the hard case to migrate, because there is no converter: rewrite each one as a Lens formula when it is a ratio or a shift, as an ES|QL query when it is a calculation over several fields, or as Vega when it needs several series with maths between them.

Canvas

Source: Kibana: Canvas.

What it is. Canvas presents live Elasticsearch data in a multi-page workpad: backgrounds, borders, fonts, images and elements (charts, progress monitors, text, images) that you can also save as reusable elements. An element takes its data from Elasticsearch SQL, from Elasticsearch documents (raw values, suited to small data sets) or from Timelion, and a workpad can embed panels from the Visualize library. A workpad is created blank, from a template, from an imported JSON file or from a sample data set; it can be shared through the Share button (see the reporting documentation) and exported. The page states one important limit: Canvas is only available for upgraded installations with existing workpads, and it is unavailable on Serverless.

What to do. Leave a working workpad alone, export its JSON as a backup, and rebuild it as a dashboard when it is touched: Markdown, Image and Links panels cover text, logos and navigation, Lens covers the charts, and the Reporting features in Sharing, Reporting & Saved Objects replace workpad PDFs. For a status-board look on a new installation, the custom panel (Serverless preview, Planned on the Stack) is the intended direction. Grafana’s Canvas panel is a different thing: it is a panel on a dashboard, not a separate workpad app.

Graph

Source: Kibana: Graph.

Graph explores how terms in an index relate to each other. Vertices are indexed terms; a connection summarizes the documents that contain both terms, computed on the fly with aggregations and ranked by relevance so that meaningful relations stand out from noise. No extra data is stored. The documented uses are fraud and attack pattern discovery, recommendations and finding people with overlapping expertise; it is generally available on the Stack and unavailable on Serverless. The workflow is to choose a data source, adjust the fields (by default each search or expand adds the five most relevant terms per field, set with Terms per hop), enter a query and expand or link vertices, with blocking of noise terms and drilldown URLs as options. The same engine is exposed as the graph exploration API.

For monitoring it is a niche tool. Relations between services are answered better by the service map of APM (see APM & Synthetics), and relations between log fields by Discover and the log pattern analysis in Data Views & Discover. Graph can help to see which exception classes, routes and hosts co-occur in the Bookshelf error logs, but it needs a data source with terms worth relating. A graph query can be expensive on large indices; the page notes sampling controls and timeouts that limit the load on the cluster.

Verifying in the lab

  1. In a space of the lab Kibana, create an aggregation-based vertical bar (Date Histogram on @timestamp, split by a terms bucket) on the Bookshelf logs, add it to a dashboard, then use Convert to Lens in edit mode and compare the two.

  2. Open TSVB, build a Filter Ratio series for the 5xx share and reproduce it as the Lens formula of Lens; note what the editor needed that the formula did not.

  3. Check which legacy panel types the dashboard Add menu offers (none, on a fresh install) and which dashboards of an imported set contain them.

In the books

Four of the provided books teach these editors. Their steps follow old interfaces, so use them to understand the ideas and the current page for the clicks.

Book and chapter What it uses What to know today

Shah, Kibana 8.x Quick Start Guide, chapters 4 and 5

Lens, Canvas workpads, Maps, Markdown, and TSVB (Time Series, Metric, Top N, Gauge, Markdown and Table types, Filter Ratio, Counter Rate, annotations)

Lens and the other panels are current; TSVB is legacy and Canvas survives only for existing workpads

Paro, Elasticsearch 7.0 Cookbook, chapter 11

The Visualize page and its built-in widgets: area, controls, coordinate map, data table, gauge, goal, heat map, bars, line, Markdown, metric, pie, region map, tag cloud, Timelion, Vega and Visual Builder

Most widgets became Lens charts; Timelion is deprecated; coordinate and region maps are replaced by Maps and the Lens region map

Chhajed, Learning ELK Stack, chapters 7 and 8

The Visualize page with metric and bucket aggregations, and the area, data table, line, Markdown, metric, pie, tile map and vertical bar visualizations
