Kibana: Sharing, Reporting & Saved Objects

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked on 2026-11-09 against Kibana 9.5.x.

To do this by hand, follow Share, Export and Move Dashboards.

A dashboard that only its author can open does little for an on-call rota. Kibana offers four ways to get a dashboard to other people: a link for colleagues who have a login, an embed for a wall display or an intranet page, a report (a PDF, PNG or CSV file, once or on a schedule) for people who never open Kibana, and an export of the definition as JSON or NDJSON for another space, cluster or Git repository. Which one to use depends on who the audience is and whether they need live data; the Grafana equivalents are on Grafana: Sharing and Reporting. Two of the options are subscription features or unavailable on Serverless, and the text marks each.

flowchart TD Q{Who needs the dashboard?} --> A[A colleague with a Kibana login] Q --> B[A wall display or intranet page] Q --> C[A person without Kibana access] Q --> D[Another space, cluster or Git] A --> A1[Share link, absolute time optional] B --> B1[Embed iframe, Stack only] C --> C1[PDF or PNG report, or CSV, once or scheduled] D --> D1[Export JSON, Dashboards API, or saved objects NDJSON]

Share a link

Source: Kibana: Export and share dashboards, share with a link.

Choose Share > Link and Copy link. The link keeps the current filters and query. The Absolute time range switch (generally available on the Stack since 9.1 and on Serverless) is off by default, so recipients see current data for a relative range; turn it on to freeze the period, which is what you want in an incident ticket ("the five minutes around the alert"). Recipients need a Kibana login with view permission; anonymous access works only when anonymous authentication is configured and its service account has the privileges, and it is unavailable on Serverless. A link to an unsaved dashboard is temporary and may break, so save the dashboard first. A link generated while a panel is maximized opens that panel full screen.

Behind a proxy or a load balancer, set server.publicBaseUrl in kibana.yml to the address that end users use (protocol, host and port if not default, no trailing slash), so that Kibana knows its public address.

Reference: Kibana: general settings (server.publicBaseUrl).

Embed in a web page

Source: Kibana: Export and share dashboards, embed in a webpage.

Embedding is generally available on the Stack only; it is unavailable on Serverless. Save the dashboard, choose Share > Embed, select what the frame includes (top menu, query, time filter, filter bar) and copy the iframe code. The viewer still has to authenticate: access to the embedded dashboard is governed by the authentication configuration, so a wall display that nobody logs in to needs anonymous authentication to be configured. Two settings decide whether the browser is allowed to show Kibana in a frame:

Setting (kibana.yml) Effect Default

server.securityResponseHeaders.disableEmbedding

When true, the CSP header gets frame-ancestors: 'self' and X-Frame-Options is set to SAMEORIGIN, which blocks other sites from framing Kibana. It takes precedence over csp.frame_ancestors.

false

csp.frame_ancestors

Array of sources added to the CSP frame-ancestors directive; use it to allow the intranet host that embeds the dashboard.

Not listed

Reference: Kibana: general settings. An embedded dashboard that stays blank usually means that one of these headers blocks the frame: check the browser console for the blocked-frame message before touching Kibana.

Export a file: PDF, PNG, CSV and JSON

Source: Kibana: Reporting and sharing and Export and share dashboards.

Open the dashboard and use the Export icon in the toolbar (in 9.0 it was Share > Export), choose a file type and generate; the job enters the export queue and the file appears on Stack Management > Alerts and Insights > Reporting (you can only see your own reports).

Output What and where Availability

PDF, PNG

Static point-in-time capture of a dashboard or visualization (PDF also for Canvas workpads). A data table or Discover session includes only the rows that are visible. PDF has a print-friendly layout (A4 portrait, two visualizations per page). Needs the Generate PDF or PNG reports privilege.

Stack only, not Serverless; a subscription feature.

CSV report

A saved Discover session. For bulk extraction use the Elasticsearch APIs.

Stack and Serverless (scheduled CSV of Discover sessions on Serverless).

CSV download

Panel menu > Download CSV on a chart or table, typically Lens; not for Markdown, Image, Links or Maps panels.

Stack and Serverless.

JSON (dashboard)

Export > Export JSON to copy, download or open a pre-filled Dashboards API request in Dev Tools; re-import with the Dashboards app. Unsupported panel types or properties are removed and listed.

Serverless: generally available. Stack: preview in 9.4 and 9.5, generally available in 9.6+. In 9.0 to 9.3 export NDJSON from Saved Objects.

JSON (single panel)

Lens and ES|QL visualizations, Links and Markdown panels, unpinned controls; excludes dashboard-level filters, query and time range.

Serverless: generally available. Stack: Planned.

Resizing. PDF and PNG take the size of the browser window when you generate them, so resize the window first for a larger capture. Limits. CSV is meant for moderate volumes: timeouts or incomplete files become likelier above 250 MB, with slow storage, unavailable shards, cross-cluster search or ES|QL row limits. Keep PNG and PDF exports moderate and split a huge dashboard into several jobs. Docker or Elastic Cloud is the recommended way to run the PDF/PNG capture, and Elastic Cloud Hosted Kibana needs at least 2 GB of RAM for it (4 GB for large dashboards). Reports of self-managed and Elastic Cloud Hosted deployments are stored in Elasticsearch under the kibana-reporting ILM policy, which keeps them forever by default: change that policy if you generate reports often.

Reference: CSV limitations and PNG and PDF limitations.

Edit permissions for the dashboard itself are set from Share: the owner or a Kibana administrator sets Can edit or Can view (generally available on the Stack since 9.3 and on Serverless); viewers can duplicate but not edit or delete, and administrators always have write access.

Scheduled reports and the POST URL

Source: Kibana: Automatically generate reports.

Scheduled reports. From the Export icon choose Schedule export, set the start date, time zone and repeat interval, and optionally send the report by e-mail (to, cc, bcc, subject and message, with Mustache variables). Manage them on Reporting > Schedules: disable, enable, edit and delete (9.3 and later; in 9.1 and 9.2 disabling is permanent). They are generally available on the Stack since 9.3 (preview in 9.1 and 9.2) for CSV, PDF and PNG, and generally available on Serverless for Discover CSV only. The prerequisites are reporting access, the optional Manage Scheduled Reports privilege and, on self-managed deployments, a default e-mail connector (Elastic Cloud has a built-in one; see Connectors). Limitations: a 10 MB e-mail attachment limit, serial execution of the tasks, and no Canvas or Lens CSV scheduling. The documentation pages for reporting differ on the first stable version of scheduling (the dedicated page says 9.3, the overview says 9.1); this page follows the dedicated page.

POST URL (Stack only, not Serverless). The Export flyout shows the POST URL of the report (PDF/PNG of dashboards, visualizations and Canvas; CSV of Discover sessions), which a script, Watcher or any scheduler can call. The request needs the kbn-xsrf header and a credential; the response carries the path to poll:

curl -X POST \
  -H "Authorization: ApiKey ${API_KEY}" \
  -H 'kbn-xsrf: true' \
  "${KIBANA_URL}/api/reporting/generate/printablePdfV2?jobParams=..."   # copy the exact URL from the Export flyout

Reference: Kibana: Create a POST URL (the page’s own curl example uses CSV and -u elastic; jobParams is generated by Kibana, so copy the URL from the flyout instead of building it). Then GET the path from the response to download: 200 means queued or downloaded (a later job failure still returns 200, because generation is asynchronous), 503 means not finished (wait the number of seconds in Retry-After and retry), 500 means generation failed (see Management > Kibana > Reporting), and 400 means the request was not a POST or lacked kbn-xsrf. Report requests run with API keys rather than session cookies (from 9.1, not on Serverless). Watcher integrates with reporting through the reporting attachment of an email action; date math in the URL can cause a parse_exception, in which case remove the curly braces and URL-encode the characters. The &sync parameter and the old /api/reporting/generate/dashboard/<id> style URLs are deprecated.

Reporting configuration

Source: Kibana: Configure reporting and Reporting settings.

Roles and privileges. The role needs read and view_index_metadata on the indices of the data (also on the underlying indices when a CSV report is generated from an alias) and, in the Kibana feature privileges (Analytics), All or Read plus sub-features (a Basic licence has no sub-feature privileges, so use All). In the role API the feature keys are dashboard_v2 (generate_report, download_csv_report), discover_v2, canvas and visualize_v2 (generate_report each). The old xpack.reporting.roles.enabled setting was removed in 9.0.

Self-managed. PDF and PNG use a headless Chromium bundled with the Linux and Windows packages (downloaded at first start on macOS); it needs distribution-specific OS libraries and fonts (the page lists the RHEL and Ubuntu/Debian packages), does not support end-of-life Linux versions, SELinux or fapolicyd, and the Reporting diagnostics check finds missing dependencies. In production set server.host: 0.0.0.0 in kibana.yml so the headless browser can reach Kibana, keep stack.templates.enabled at its default true in Elasticsearch (reporting needs the data stream template), and for Watcher trust the Kibana CA in elasticsearch.yml (xpack.http.ssl.certificate_authorities or the truststore settings).

In the lab the kibana profile has no mail server and the PDF/PNG capture is the heavy part; use CSV and the JSON export for the lab, and treat PDF/PNG and scheduled e-mail as exercises for a deployment that has a subscription, enough memory and an SMTP relay or the Cloud e-mail connector.

Saved objects: export, import and copy to a space

Source: Kibana: Manage saved objects and Import a dashboard.

A saved object is anything Kibana stores for reuse: dashboards, visualizations, maps, data views, Canvas workpads, saved Discover sessions. The Saved Objects page (permission: Saved Objects Management, which covers all objects, including those of apps the user cannot otherwise open) lists them. Relationships shows what depends on an object before you delete it.

  • Export. Select objects or a type; the result is an NDJSON file that includes child objects by default (an exported dashboard carries its data views). savedObjects.maxImportExportSize limits the number of objects (default 10000).

  • Import. Upload the NDJSON; by default existing objects are overwritten, and Check for existing objects can create a copy with a new random ID when the same ID exists in another space. savedObjects.maxImportPayloadBytes caps the file size (default 26214400 bytes).

  • Copy to spaces. Within one deployment use Copy to spaces from the actions menu rather than export and import: related objects are copied, and you choose to overwrite or to resolve conflicts one by one.

  • Version rules. An export imports into the same version, a newer minor of the same major, or the next major; never into an older version (8.7.0 to 8.8.1 works; 8.11.1 to 8.6.0 and 7.8.1 to 9.0.0 do not). Treat the file as opaque: editing it risks errors.

  • IDs. Since 8.0 IDs are globally unique; upgrading changes the IDs of objects in custom spaces to UUIDs (the default space keeps them), and a changed ID breaks "weak" links such as Markdown links between dashboards.

The same operations are available as REST calls, which is how a pipeline moves dashboards between clusters (the saved objects import and export APIs are available on the Stack and Serverless; some saved objects APIs have been deprecated since 8.7):

# export one dashboard with everything it references
curl -X POST "${KIBANA_URL}/api/saved_objects/_export" \
  -H "Authorization: ApiKey ${API_KEY}" -H "kbn-xsrf: true" -H "Content-Type: application/json" \
  -d '{"objects":[{"type":"dashboard","id":"bookshelf-service-health"}],"includeReferencesDeep":true,"excludeExportDetails":true}' \
  -o bookshelf-service-health.ndjson

# import it into another Kibana, overwriting a previous version
curl -X POST "${TARGET_KIBANA_URL}/api/saved_objects/_import?overwrite=true" \
  -H "Authorization: ApiKey ${TARGET_API_KEY}" -H "kbn-xsrf: true" \
  --form file=@bookshelf-service-health.ndjson

Reference: Kibana API: Saved objects (POST /api/saved_objects/_export and _import, with the parameters includeReferencesDeep, excludeExportDetails, overwrite, createNewCopies). To copy between spaces, use POST /api/spaces/_copy_saved_objects (parameters objects, spaces, includeReferences, overwrite, createNewCopies); the export and import calls of another space use the prefix /s/<space_id>.

Importing a dashboard. Three paths exist, with different semantics:

Method Behaviour Availability

Dashboards app, JSON (Import dashboard)

File up to 1 MB; never updates an existing dashboard (importing again creates another); unsupported properties are dropped with a message; referenced data views, tags and library items are not imported, so they must exist in the target.

Serverless: generally available. Stack: Planned.

Dashboards API, JSON

Creates a dashboard in the space of the request path; a request with an existing ID updates that dashboard in place (see Dashboards as Code).

Serverless: generally available. Stack: preview in 9.4, generally available since 9.5.

Saved Objects page, NDJSON

Check for existing objects skips IDs that already exist; Request action on conflict picks the version to keep; Create new objects with random IDs imports everything under new IDs. Needs All on Dashboard and Saved Objects Management.

Stack Management.

Verifying in the lab

  1. Copy a link to "Bookshelf service health" twice, once with Absolute time range on, and open both an hour later: the first shows the frozen period, the second the last range.

  2. Download the CSV of the "slowest routes" table from the panel menu and check that the rows match the panel; export the dashboard as JSON (Serverless) or as NDJSON from Saved Objects (Stack) and open the file.

  3. Import the NDJSON into a second space with Copy to spaces and into a clean Kibana with the curl commands above, then check that the data views and the dashboard exist and the panels draw.

  4. If you have a subscription and enough RAM, generate a PDF, then schedule it every day with an e-mail to the lab’s mail catcher, if you add one.

Things that go wrong

  • The link opens a login page or a dashboard without data: the recipient lacks a role for the space or the index; a relative-time link on an old ticket shows today’s data.

  • The report is blank or the job fails: Chromium dependencies missing, server.host not reachable from the headless browser, or timeouts too short for a large dashboard; run the reporting diagnostics and read the Reporting page.

  • Reports fail after a restart: no fixed xpack.reporting.encryptionKey.

  • The import lost panels: unsupported properties were removed (read the message), or the referenced data views or library visualizations were not in the target.

  • The imported dashboard is a duplicate: the Dashboards app never updates an existing dashboard; use the API with the ID or the saved objects import with overwrite.

  • Everything breaks after moving between versions: saved objects cannot go to an older version.

In the books

Shah (Kibana 8.x Quick Start Guide, chapter 8) describes the Share menu of Kibana 8.x: PDF and PNG reports, a permalink and an embed code, each as a snapshot of the current state or as the saved object (the iframe example in the book uses a short URL). Chhajed (Learning ELK Stack) mentions the share button with an embed code and a direct link for Kibana 4. What has changed: reports and exports now sit under the Export toolbar icon, links can use an absolute time range, reports can be scheduled and e-mailed, report requests use API keys, dashboards can be exported as JSON for the Dashboards API (not only as NDJSON), and the dashboard has its own Can edit and Can view permissions.
