OpenAPI & Swagger

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against NestJS 12.1 (npm @nestjs/core 12.1.2, published 2026-09-30) and @nestjs/swagger 12.0.2 (published 2026-09-23, bundling Swagger UI 5.33.0), Node.js 22 and 24 LTS (the package requires Node.js 20.19+ or 22.12+), TypeScript 6 (6.0.x), Express 5.2 and Fastify 5.12, all checked on 2026-10-02. The examples are exercised with Vitest and supertest on Nest 12, the document and the Swagger UI routes behave the same on the Express and the Fastify adapter, and the CLI plugin examples build with nest build and run on Node.js 24.16. An API without a machine-readable description is an API that every consumer has to reverse-engineer. The package @nestjs/swagger reads the metadata that Nest already holds about controllers and DTOs, lets you complete it with decorators (or a compiler plugin), and produces an OpenAPI document that Swagger UI renders as an interactive page and that code generators turn into typed clients. The examples continue the Bookshelf scenario used throughout this section.

OpenAPI, Swagger UI and what the package does

Three names are easy to confuse:

  • OpenAPI is a language-agnostic specification for describing HTTP APIs: paths, operations, parameters, request and response bodies, schemas and security. A document is plain JSON or YAML. @nestjs/swagger generates OpenAPI 3.0 documents by default; DocumentBuilder.setOpenAPIVersion() selects 3.1 or 3.2 (the examples below show what each changes).

  • Swagger UI is the browser front end that renders an OpenAPI document and lets you call the API. The package bundles it (swagger-ui-dist) and serves it from your own application.

  • @nestjs/swagger is the Nest module that connects the two. It is a library, not part of Nest core: it adds SwaggerModule and DocumentBuilder, a family of @Api…​ decorators, optional mapped-type helpers and an optional compiler plugin. It requires NestJS 12 (@nestjs/common and @nestjs/core ^12.0.0).

Installation and bootstrap

Install the package. On Fastify, also install @fastify/static, which the package uses to serve the Swagger UI assets:

npm install @nestjs/swagger
npm install @fastify/static   # Fastify only

Source: NestJS: OpenAPI introduction, "Installation"

The minimal bootstrap builds a base document with DocumentBuilder, wraps createDocument() in a factory, and mounts the UI. This page keeps the configuration in a function so that the same code serves the application, the tests and the build step that writes the spec to disk:

src/openapi/openapi.setup.ts
import type { INestApplication } from '@nestjs/common';
import { DocumentBuilder, SwaggerModule, type SwaggerCustomOptions, type SwaggerDocumentOptions } from '@nestjs/swagger';

export function setupOpenApi(app: INestApplication, setupOptions: SwaggerCustomOptions = {}) {
  const config = new DocumentBuilder()
    .setTitle('Bookshelf API')
    .setDescription('Books, authors and reviews')
    .setVersion('1.0')
    .setContact('Bookshelf team', 'https://example.com/support', 'api@example.com')
    .setLicense('MIT', 'https://opensource.org/license/mit')
    .addServer('http://localhost:3000', 'Local development')
    .addTag('books', 'Catalogue of books')
    .addBearerAuth()
    .addApiKey({ type: 'apiKey', in: 'header', name: 'X-Api-Key' }, 'api-key')
    .addBasicAuth()
    .addOAuth2({
      type: 'oauth2',
      flows: { implicit: { authorizationUrl: 'https://auth.example.com/authorize', scopes: { 'books:write': 'Modify books' } } },
    })
    .addCookieAuth('sid')
    .addGlobalResponse({ status: 500, description: 'Internal server error' })
    .addGlobalParameters({ name: 'tenantId', in: 'header', required: false, schema: { type: 'string' } })
    .build();

  const options: SwaggerDocumentOptions = {
    operationIdFactory: (_controllerKey: string, methodKey: string) => methodKey,
  };
  const documentFactory = () => SwaggerModule.createDocument(app, config, options);
  SwaggerModule.setup('docs', app, documentFactory, { jsonDocumentUrl: 'docs/json', ...setupOptions });
  return documentFactory;
}

import { NestFactory } from '@nestjs/core';
import { FastifyAdapter, type NestFastifyApplication } from '@nestjs/platform-fastify';
import { writeFileSync } from 'node:fs';
import { OpenApiAppModule, OpenApiFastifyAppModule } from './app.module.js';
import { setupOpenApi } from './openapi.setup.js';

async function bootstrap() {
  const fastify = process.env.HTTP_PLATFORM === 'fastify';
  const app = fastify
    ? await NestFactory.create<NestFastifyApplication>(OpenApiFastifyAppModule, new FastifyAdapter())
    : await NestFactory.create(OpenApiAppModule);

  const documentFactory = setupOpenApi(app);
  if (process.env.WRITE_SPEC) {
    writeFileSync(process.env.WRITE_SPEC, JSON.stringify(documentFactory(), null, 2));
  }
  await app.listen(Number(process.env.PORT ?? 3000), '127.0.0.1');
}

Where the document is built and served: lifecycle position

@nestjs/swagger sits beside the request lifecycle (see Request Lifecycle), not inside it:

  • Build time of the document. createDocument() needs an application object because it inspects the module graph (controllers, their route metadata and DTO classes). It does not need the application to be listening. When you pass a factory to setup(), the document is generated on the first request for the UI or a definition and then reused; in a test, a factory that counted its calls was invoked zero times after init() and once after three requests. Passing the result of createDocument() directly generates it eagerly, which is also what you want when you write the file at start-up.

  • Serving. setup() registers plain routes directly on the underlying HTTP adapter (Express or Fastify), outside Nest’s router. Guards, interceptors, pipes and exception filters therefore do not run for the UI, the JSON or the YAML routes. Middleware registered with app.use() before setup() does run. Both facts hold on Express and Fastify:

GET /secret                          -> 401   (the global guard runs)
GET /open-docs, /open-docs-json      -> 200   (no guard on the documentation routes)
GET /protected-docs-json             -> 401   (app.use() middleware ran first)
GET /protected-docs-json + header    -> 200

Two consequences follow. A global APP_GUARD does not protect your documentation: if the spec reveals internal routes, protect it with middleware, a reverse proxy, or by not mounting it (ui: false and raw: false, see SwaggerModule.setup and its options) outside development. And because the routes are outside Nest, they do not get the global prefix unless you ask for it (Global prefix).

Order also matters for versioning. If you call createDocument() eagerly, call app.enableVersioning() first; otherwise the generated paths lack the version prefix. A factory is immune because the document is built later:

@Controller({ path: 'v', version: '1' }) class V1 { @Get() one() { return 1; } }
@Controller({ path: 'v', version: '2' }) class V2 { @Get() two() { return 2; } }

const eager = SwaggerModule.createDocument(app, config); // before enableVersioning()
app.enableVersioning({ type: VersioningType.URI });
const late = SwaggerModule.createDocument(app, config);
// Object.keys(eager.paths) -> ["/v"]
// Object.keys(late.paths)  -> ["/v1/v", "/v2/v"]

Source: NestJS: OpenAPI introduction, warning about eager document creation

DocumentBuilder

DocumentBuilder assembles the base document: everything except the paths, which createDocument() adds. Every method returns the builder, and build() returns the object.

Method What it sets

setTitle(), setDescription(), setVersion()

The info object. The version is the version of your API, not of OpenAPI.

setTermsOfService(), setContact(name, url, email), setLicense(name, url)

The remaining info fields.

setOpenAPIVersion('3.1.0')

The openapi field and the spelling rules that depend on it (nullability, tag fields, webhooks). The default is 3.0.0.

addServer(url, description?, variables?)

An entry in servers; call it once per environment.

setExternalDoc(description, url)

The document-level externalDocs.

addTag(name, description?, externalDocs?, options?)

A tag defined up front. The optional fourth argument carries summary, parent and kind (OpenAPI 3.2 tag fields).

addExtension(key, value, location?)

A document-level x- extension.

addSecurity(name, scheme)

A named security scheme in components.securitySchemes.

addBearerAuth(), addOAuth2(), addApiKey(), addBasicAuth(), addCookieAuth(cookieName)

Ready-made schemes registered under the names bearer, oauth2, api-key, basic and cookie unless you pass another name.

addSecurityRequirements(name)

A document-wide security requirement (applies to every operation).

addGlobalResponse(…​responses)

A response added to every operation, typically 500.

addGlobalParameters(…​parameters)

A parameter added to every operation, for example a tenant header.

SwaggerModule.createDocument and its options

SwaggerModule.createDocument(app, config, options?) takes the application, the base document and an optional SwaggerDocumentOptions object, and returns the OpenAPIObject. All options, with their effect on the document:

Option Default Effect

include

every module

Restricts the document to the controllers of the listed modules. include: [ReviewsModule] reduced a 17-path document to one path (/reviews).

extraModels

none

Classes to inspect and add to components.schemas even when no route refers to them (the programmatic form of @ApiExtraModels()).

ignoreGlobalPrefix

false

Leaves the global prefix out of the generated paths (see Global prefix).

deepScanRoutes

false

With include, also scans modules imported by the included ones. In a test, include: [ParentModule] found no routes when PlainModule was only imported by it, and found /plain and /plain/b with deepScanRoutes: true.

operationIdFactory

controllerKey_methodKey (ReviewsController_create)

(controllerKey, methodKey, version?) ⇒ string. Returning methodKey yields operation names such as createUser; the third argument carries the route version (one_v1, two_v2 in the versioning test).

linkNameFactory

controllerKey_methodKey_from_fieldKey

Names the entries of the links object of responses (see @ApiLink() below).

autoTagControllers

true

Tags operations with the controller name without the Controller suffix (PlainController became Plain). With false, only @ApiTags() tags remain.

onlyIncludeDecoratedEndpoints

false

Documents only handlers decorated with @ApiIncludeEndpoint(); an undecorated sibling route disappears.

excludeDynamicDefaults

false

Omits default values that are not plain at runtime (new Date(), class instances), so the document does not change on every restart.

exampleMaxDepth

undefined

Truncates example and examples on component schemas beyond that nesting depth. A per-property @ApiProperty({ exampleMaxDepth }) overrides it.

standardSchemaConverter

native conversion

Converts Standard Schema instances into OpenAPI schemas (see Standard Schema DTOs (Zod, Valibot)).

Source: NestJS: OpenAPI introduction, "Document options"

ui and raw are independent. Disabling the UI does not disable the definitions, and vice versa:

SwaggerModule.setup('api', app, () => SwaggerModule.createDocument(app, config), {
  ui: false, // Swagger UI is disabled
  raw: ['json'], // only the JSON definition is served
});

Source: NestJS: OpenAPI introduction, hint on ui and raw

GET /api       -> 404
GET /api-json  -> 200
GET /api-yaml  -> 404

With raw: false and the UI enabled, /api answered 200 (the page loads its definition inline) and /api-json answered 404. The same four requests behaved identically on Express and Fastify.

patchDocumentOnRequest, customSiteTitle and swaggerOptions can be combined:

SwaggerModule.setup('api', app, () => SwaggerModule.createDocument(app, config), {
  customSiteTitle: 'Bookshelf docs',
  explorer: true,
  swaggerOptions: { persistAuthorization: true, docExpansion: 'none' },
  patchDocumentOnRequest: (req: any, _res, doc) => ({
    ...doc,
    info: { ...doc.info, description: `served for ${req.headers.host ? 'a host' : 'nobody'}` },
  }),
});

Source: NestJS: OpenAPI introduction, "Setup options"

The served JSON contained the patched info.description, and the UI page title was Bookshelf docs.

Swagger UI is served from your own origin with a script swagger-ui-init.js that embeds the document. It works with the default Content Security Policy of Nest’s built-in security headers; custom scripts, plain-HTTP deployments outside local development and Fastify’s own @fastify/helmet need the adjustments described in Security Headers, CORS & CSRF.

Describing models: types and parameters

SwaggerModule finds every @Body(), @Query(), @Param() and @Headers() parameter of every route and builds a model from its class using reflection. TypeScript’s reflection is shallow, though: it records that a property is a string or an Array, but not which properties a class has unless they are decorated, whether a property is optional, what an array contains, or which enum a value belongs to. Everything the reflection cannot see is supplied with @ApiProperty(), or automatically by the CLI plugin (The CLI plugin).

A DTO without any decorator and without the plugin produces an empty schema, which is the most common first surprise:

class Bare {
  title!: string;
}
// components.schemas -> { "Bare": { "type": "object", "properties": {} } }

Source: NestJS: OpenAPI, "Types and parameters"

@ApiProperty and @ApiPropertyOptional

@ApiProperty() registers a property and lets you set any Schema Object keyword. @ApiPropertyOptional() is the shorthand for @ApiProperty({ required: false }). The following DTO combines the options that matter most. It is a single class, and the output shown after it is the generated schema:

src/openapi/create-book.dto.ts
import { ApiProperty, ApiPropertyOptional, ApiHideProperty, ApiSchema } from '@nestjs/swagger';
import { Genre } from './genre.js';

@ApiSchema({ name: 'CreateBookRequest', description: 'Payload to add a book to the catalogue' })
export class CreateBookDto {
  @ApiProperty({ description: 'Title as printed on the cover', minLength: 1, maxLength: 200, example: 'The Pragmatic Programmer' })
  title: string;

  @ApiProperty({ description: 'Pages', minimum: 1, default: 100, type: Number })
  pages: number;

  @ApiProperty({ type: [String], description: 'Author names' })
  authors: string[];

  @ApiProperty({ enum: Genre, enumName: 'Genre' })
  genre: Genre;

  @ApiProperty({ enum: Genre, enumName: 'Genre', isArray: true, description: 'Secondary genres' })
  tags: Genre[];

  @ApiPropertyOptional({ examples: { short: { value: '978-0135957059' }, long: { value: '9780135957059' } } })
  isbn?: string;

  @ApiProperty({
    type: 'array',
    items: { type: 'array', items: { type: 'number' } },
    description: 'Pairs of [page, line] bookmarks',
  })
  bookmarks: number[][];

  @ApiProperty({
    type: 'object',
    properties: { name: { type: 'string', example: 'Error' }, status: { type: 'number', example: 400 } },
    required: ['name', 'status'],
  })
  rawDefinition: Record<string, any>;

  @ApiHideProperty()
  internalNote?: string;
}

Generics, extra models and getSchemaPath

TypeScript erases generics, so PaginatedDto<TData> cannot be described by reflection. The recipe is: decorate the fixed properties, leave the generic one undecorated, and describe the concrete combination with a raw schema in the response. The DTO has to be registered with @ApiExtraModels() because no controller references it directly, and getSchemaPath() returns the $ref of a registered model:

src/openapi/paginated.dto.ts
import { applyDecorators, Type } from '@nestjs/common';
import { ApiExtraModels, ApiOkResponse, ApiProperty, getSchemaPath } from '@nestjs/swagger';

export class PaginatedDto<TData> {
  @ApiProperty() total: number;
  @ApiProperty() limit: number;
  @ApiProperty() offset: number;

  // not decorated: the item type is supplied by ApiPaginatedResponse()
  results: TData[];
}

export const ApiPaginatedResponse = <TModel extends Type<unknown>>(model: TModel) =>
  applyDecorators(
    ApiExtraModels(PaginatedDto, model),
    ApiOkResponse({
      schema: {
        title: `PaginatedResponseOf${model.name}`,
        allOf: [
          { $ref: getSchemaPath(PaginatedDto) },
          { properties: { results: { type: 'array', items: { $ref: getSchemaPath(model) } } } },
        ],
      },
    }),
  );

Source: NestJS: OpenAPI, "Advanced: Generic ApiResponse"

The decorator is built with applyDecorators() from @nestjs/common (see Custom Decorators), so it bundles the extra-model registration with the response and can be reused on any endpoint:

@ApiQuery({ name: 'genre', enum: Genre, enumName: 'Genre', required: false })

  void genre;
  return { total: 0, limit: 10, offset: 0, results: [] };
}

The title is the detail that matters for generated clients. Without it, a generator sees an anonymous allOf and emits an inline object type; with it, the client method returns PaginatedResponseOfBookSummaryDto.

@ApiExtraModels() is only needed once per model, and it can sit on a controller, a method or a model class. The same registration is available as the extraModels document option. Forgetting it is silent: a model that is referenced only through getSchemaPath() and never registered leaves a dangling $ref: the document contains only the owning schema (["Owner"]) while the property points at schemas that do not exist.

The fix is the standardSchemaConverter document option. Branching on the vendor (~standard.vendor) lets one converter serve several libraries; always narrow by vendor before calling a library-specific function, because passing a Valibot schema to the Zod converter (or the reverse) throws at document generation time. This example uses zod-openapi (which can hoist reusable definitions, so it returns components) and @valibot/to-json-schema (a single self-contained schema), both installed as development dependencies:

src/openapi/standard-schema.converter.ts
import type { SwaggerDocumentOptions } from '@nestjs/swagger';
import { toJsonSchema } from '@valibot/to-json-schema';
import { createSchema } from 'zod-openapi';

function hasVendor(schema: unknown, vendor: string) {
  return (
    !!schema &&
    typeof schema === 'object' &&
    (schema as { '~standard'?: { vendor?: string } })['~standard']?.vendor === vendor
  );
}

export const documentOptions: SwaggerDocumentOptions = {
  standardSchemaConverter: (schema, { schemaType }) => {
    if (hasVendor(schema, 'zod')) {
      const converted = createSchema(schema as never, { io: schemaType, openapiVersion: '3.0.0' });
      return { schema: converted.schema, components: converted.components };
    }

    if (hasVendor(schema, 'valibot')) {
      return { schema: toJsonSchema(schema as never, { target: 'openapi-3.0', typeMode: schemaType }) };
    }

    // Not handled here: let Nest fall back to its native conversion
    return undefined;
  },
};

Three less common decorators describe relationships between operations. Applied to a LoansController with OpenAPI 3.1 selected, they produce the document output below:

src/openapi/secure.controller.ts
import { CanActivate, Controller, ExecutionContext, Get, Injectable, UnauthorizedException, UseGuards } from '@nestjs/common';
import {
  ApiBasicAuth,
  ApiBearerAuth,
  ApiCookieAuth,
  ApiOAuth2,
  ApiOkResponse,
  ApiSecurity,
  ApiTags,
  ApiUnauthorizedResponse,
} from '@nestjs/swagger';

@Injectable()
export class BearerGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const header = context.switchToHttp().getRequest<{ headers: Record<string, string | undefined> }>().headers.authorization;
    if (!header?.startsWith('Bearer ')) throw new UnauthorizedException();
    return true;
  }
}

@ApiTags('account')
@Controller('account')
export class SecureController {
  @Get('me')
  @UseGuards(BearerGuard)
  @ApiBearerAuth() // refers to the "bearer" scheme added with addBearerAuth()
  @ApiUnauthorizedResponse({ description: 'Missing or invalid token.' })
  @ApiOkResponse({ description: 'The current user.' })
  me() {
    return { name: 'reader' };
  }

  @Get('keys')
  @ApiSecurity('api-key')
  keys() {
    return [];
  }

  @Get('legacy')
  @ApiBasicAuth()
  legacy() {
    return {};
  }

  @Get('sso')
  @ApiOAuth2(['books:write'], 'oauth2')
  sso() {
    return {};
  }

  @Get('session')
  @ApiCookieAuth()
  session() {
    return {};
  }
}

The CLI plugin

Reflection cannot see which properties a class has or whether they are optional, which is why every DTO property needs an @ApiProperty(). The CLI plugin removes that boilerplate by reading the TypeScript source at compile time (it works on the Abstract Syntax Tree) and adding the missing decorators. It is opt-in, and it never replaces runtime validation: class-validator decorators are still what validates the request, while the plugin only turns them into documentation.

What the plugin generates

  • annotates every DTO property with @ApiProperty() (unless @ApiHideProperty() is used);

  • sets required from the question mark (name?: string is optional);

  • sets type or enum from the TypeScript type (arrays included);

  • sets default from an initialiser;

  • copies validation rules from class-validator decorators (classValidatorShim, on by default in the option table);

  • adds a response decorator with a proper status and type to every endpoint;

  • generates descriptions and examples from comments (introspectComments).

For the plugin to analyse a DTO, the file name must end with .dto.ts or .entity.ts (change it with dtoFileNameSuffix). Controllers are recognised by .controller.ts.

Enable it in nest-cli.json:

nest-cli.json
{
  "$schema": "https://json.schemastore.org/nest-cli",
  "collection": "@nestjs/schematics",
  "sourceRoot": "src",
  "compilerOptions": {
    "deleteOutDir": true,
    "plugins": [
      {
        "name": "@nestjs/swagger",
        "options": { "introspectComments": true, "classValidatorShim": true }
      }

}

@Module({ controllers: [MembersController], providers: [NeedsDatabase] })

  NestFactory.create(OfflineModule, { logger: false, abortOnError: false, preview });

} catch (error) {

Pitfalls

  • Empty schemas. A DTO with neither @ApiProperty() nor the plugin (or a Standard Schema) is documented with properties: {}. A runner that does not run the plugin (Vitest, ts-jest without a transformer) reproduces this.

  • Arrays default to string items. Declare the item type (type: [Number]) or use @ApiBody({ type: [Dto] }) for array bodies; the plugin detects arrays itself.

  • @ApiOkResponse on a POST. Nest answers 201. Use @ApiCreatedResponse, and add a test that compares documented and real statuses.

  • Unregistered models. A model that appears only in getSchemaPath() needs @ApiExtraModels() (or extraModels); otherwise the $ref dangles and no error is raised.

  • Enums without enumName. Each property inlines its copy of the enum and generators emit duplicates.

  • Circular imports in ESM. type: () ⇒ X solves Swagger’s problem but not the design:type metadata problem; use a wrapper type such as Relation<T> (see Circular references).

  • Mapped types from the wrong package. Import PartialType, PickType, OmitType and IntersectionType from @nestjs/swagger (or @nestjs/graphql), not from @nestjs/mapped-types.

  • Missing converter for a Standard Schema library. Without Standard JSON Schema support or a standardSchemaConverter, the body is documented as a reference to a non-existent Object schema. Branch by vendor and return undefined for libraries you do not handle.

  • Eager createDocument() before enableVersioning(). Paths lose their version prefix; use a factory.

  • Documentation routes bypass guards. A global guard does not protect /docs; use middleware, network controls, or disable the routes in production with ui and raw.

  • swaggerUiEnabled is deprecated. Use ui; raw is independent of it.

  • Unstable generated files. Dynamic defaults (new Date()) change on every start; set excludeDynamicDefaults. Large examples are trimmed with exampleMaxDepth.

  • A global parameter without a schema. The generated parameter has an empty schema.

  • Declaring security without enforcing it. @ApiBearerAuth() documents; only a guard enforces.

  • Credentials in examples. Never put real tokens or keys in example values or in addSecurity() definitions; the document is public by design.

Where the book is outdated

The book introduces Swagger in its REST chapter with @ApiProperty, @ApiTags, @ApiOperation, DocumentBuilder and SwaggerModule.setup, which is the right starting point. Compared with the current package:

  • It uses @ApiOkResponse to describe the creation endpoint of a POST; the correct shorthand is @ApiCreatedResponse, because Nest answers 201.

  • It predates the document factory (SwaggerModule.setup('api', app, () ⇒ SwaggerModule.createDocument(…​))) that defers generation, the ui/raw options (replacing swaggerUiEnabled), patchDocumentOnRequest, autoTagControllers, onlyIncludeDecoratedEndpoints and the other document options listed above.

  • It does not cover Standard Schema DTOs, which became the alternative to class-based DTOs in Nest 12.

  • It does not cover the CLI plugin options (introspectComments, classValidatorShim, autoFillEnumName), the SWC PluginMetadataGenerator, or the nullability change in @nestjs/swagger 12.

  • Its imports and examples are written for CommonJS and an earlier major of the package; today @nestjs/swagger is an ES module (still loadable from CommonJS), and examples use .js import extensions in the ESM template.

What changed recently

  • @nestjs/swagger 12.0.0 (2026-08-27). A native ES module requiring Nest 12 and Node.js 20.19+ or 22.12+; CommonJS applications keep working through require(esm). It also introduced the standardSchemaConverter option and reflection of Standard Schema parameters, replaced lodash with es-toolkit internally, and made the CLI plugin detect esmCompatible per file and turn @param tags into parameter descriptions.

  • Nullability is spelled per document version (12.0.0, breaking). Documents that declare 3.1 or later use a type union (type: ['string', 'null']) instead of the removed nullable keyword; 3.0 documents keep nullable: true. A run confirmed both spellings ({"type":"string","nullable":true} on 3.0 and {"type":["string","null"]} on 3.1). Snapshot tests that assert nullable: true in 3.1 documents need updating.

  • 12.0.1 and 12.0.2 (2026-08-28 and 2026-09-23). Fixes for ESM static import hoisting, swagger-ui-init.js handling of $ characters, Standard Schema query parameters merged with @ApiQuery() and schema descriptions promoted to parameters, single literal types treated as enums by the plugin, @fastify/static resolution, typescript declared as an optional peer dependency, and support for the HTTP QUERY method.

  • Documented since the docs restructure. OpenAPI 3.2 tag hierarchy (parent, kind, summary through DocumentBuilder.addTag() after setOpenAPIVersion('3.2.0')), excludeDynamicDefaults, exampleMaxDepth, the ui and raw options, and Swagger UI working with the default Content Security Policy of Nest 12.1’s built-in security headers.

  • Related changes elsewhere in the section. Nest 12 route decorators accept Standard Schema (see Pipes & Validation); the full list of version changes is in What’s Changed & Migration.
