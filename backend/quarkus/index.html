Quarkus Reference

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the Quarkus reference. Quarkus is a Kubernetes-native Java framework built for GraalVM and the JVM alike: it moves as much work as possible — classpath scanning, bean discovery, proxy generation, configuration metadata — from application startup into an augmentation build step, so the resulting application starts in milliseconds, uses a fraction of the memory of a traditionally-bootstrapped Java application, and compiles cleanly to a native executable. That trade — accepting a closed-world assumption about what the application will do at runtime, in exchange for build-time speed and density — is the thread that runs through every page in this section.

If you are new to Quarkus, read Getting Started with Quarkus first, then Build-Time Augmentation and the Closed World to understand why it behaves the way it does, then CDI and the Programming Model (ArC) and Configuration for the two mechanisms every other page assumes. From there, read the rest of this section as needed for the technology you are integrating.

Quarkus sits alongside, not in place of, several existing references in this repository. For the Java framework most directly comparable to it, see the sibling SpringBoot Reference — Quarkus vs. Spring Boot maps the two concept-for-concept and Spring API Compatibility Extensions covers migrating existing Spring code, while Java or Kotlin for Quarkus? mirrors the SpringBoot section’s own language comparison. Quarkus does not re-document the technologies it integrates: for JPA/Hibernate fundamentals see the Hibernate Reference (Quarkus’s own pages cover only what Hibernate ORM in Quarkus and Panache add on top); for GraphQL schema design, pagination, security and federation see the GraphQL Reference (Quarkus adds only the SmallRye server and client bindings on GraphQL with SmallRye); and for the OAuth/OIDC protocols themselves — flows, tokens, JWTs, the Security BCP — see the OAuth Reference (Quarkus adds only the quarkus-oidc/quarkus-smallrye-jwt bindings on JWT, OIDC and Keycloak).

Version baseline

This section documents Quarkus 3.39.x (current) with 3.33.x LTS as the production recommendation, on the Java 17+ baseline, as published at the official Quarkus guides — which are the reference these pages are written and verified against. Quarkus 4 raises the baseline to Java 21 (first release candidate planned for end of September 2026, see the Quarkus blog); readers upgrading past 3.39.x/3.33.x LTS should expect that change.

What’s covered

Foundations

  • Build-Time Augmentation and the Closed World — the three-phase model, the closed-world assumption, class loading in dev vs. production, and the honest costs.

  • Extensions and the Platform — what an extension is, the platform BOM vs. the universe BOM vs. Quarkiverse, and the extension registry.

  • CDI and the Programming Model (ArC) — ArC’s build-time CDI, bean discovery and scopes, injection styles, producers/qualifiers/interceptors, and CDI events.

  • Configuration — config sources and precedence, @ConfigMapping, profiles, and build-time-fixed vs. runtime-overridable properties.

  • Developer Experience: Dev Mode, Dev UI, Dev Services — live reload semantics, the Dev UI, automatic Dev Services containers, and continuous testing.

REST, web and APIs

  • Quarkus REST — resources and parameter annotations, the @Blocking/non-blocking dispatch decision, exception mapping, CORS/HTTP configuration, and migrating from RESTEasy Classic.

  • The MicroProfile REST Client — typed client interfaces, headers and propagation, exception mapping, TLS, and composing with fault tolerance and Stork.

  • OpenAPI and Swagger UI — SmallRye OpenAPI generation, /q/openapi and /q/swagger-ui, and code-first vs. contract-first development.

  • GraphQL with SmallRye — the SmallRye GraphQL server (@GraphQLApi, @Query, @Mutation, @Subscription) and clients, linking the GraphQL reference for everything else.

  • gRPC — protobuf-first code generation, blocking/Mutiny/virtual-thread service implementations, streaming, and interceptors.

  • WebSockets Next — connection and broadcast APIs, security integration, back-pressure, and the legacy Undertow-based extension.

  • Qute Templating — syntax, type-safe templates with @CheckedTemplate, i18n, and the adjacent Quinoa/Renarde extensions.

  • Reactive Routes and the Vert.x HTTP Layer — reactive routes, direct Vert.x API access and the event bus, and the HTTP/management interface split.

Data

  • Datasources and Transactions — JDBC and reactive datasources, Agroal connection-pool tuning, Narayana JTA transactions, and XA/LRA.

  • Hibernate ORM in Quarkus — the no-persistence.xml configuration model, entity discovery, second-level caching, and build-time metamodel generation.

  • Panache: The Quarkus Data API — active record vs. repository, simplified queries, pagination and sorting, and REST Data with Panache.

  • Reactive Data Access — reactive SQL clients, Hibernate Reactive (including with Panache), and the rule against mixing blocking calls into a reactive path.

  • NoSQL and Other Stores — MongoDB, Redis, Elasticsearch/ OpenSearch, Infinispan, Cassandra, and a survey of Quarkiverse-hosted stores.

  • Database Migrations — Flyway and Liquibase, and migration strategy in a rolling Kubernetes deploy.

  • The Quarkus Cache Extension — the @CacheResult annotation family, the Caffeine/Redis/Infinispan backends, and cache-stampede/invalidation caveats.

  • Validation with Hibernate Validator — constraints on REST payloads and CDI beans, custom constraints, and native-image considerations.

Reactive, concurrency and messaging

  • Reactive Programming and Mutiny — the Vert.x event-loop/worker-thread model, Mutiny’s Uni/Multi operators, and context propagation.

  • Virtual Threads in Quarkus — @RunOnVirtualThread, pinning and thread-local cost, monitoring, and honest benchmarking guidance.

  • Messaging with SmallRye Reactive Messaging — channels and connectors, Kafka in depth (serde, consumer groups, DLQs, transactions), and RabbitMQ/AMQP/Pulsar/JMS.

Security

  • Authentication Mechanisms and Identity Stores — basic/form/JDBC/JPA authentication, LDAP, WebAuthn/passkeys, and mutual TLS.

  • JWT, OIDC and Keycloak — MicroProfile JWT, quarkus-oidc web-app and service modes, token propagation, and Dev Services for Keycloak.

  • Secrets, TLS and Hardening — keeping secrets out of configuration, the TLS registry, and a production hardening checklist.

Observability and resilience

  • Fault Tolerance and Resilience — SmallRye Fault Tolerance annotations (retry, timeout, bulkhead, circuit breaker, fallback), and Stork load balancing.

Testing

  • Scheduling and Mail — @Scheduled cron/interval syntax, Quartz for clustered schedules, and the Mailer extension.
