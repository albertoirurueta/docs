This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against Pyramid 2.1 (the 2.1-branch documentation and the 2.1 release installed from PyPI) on Python 3.13, checked on 2026-10-07, with WebTest 3.0.7, pytest 9.1 and pytest-cov 7.1. Every example was executed: the project files and the tests of the Bookshelf Shelves scenario run together under pytest (20 tests, all passing, 98 percent coverage with branch measurement), and the stand-alone snippets run as plain Python. Pyramid ships no test runner. It ships a small module of test doubles, pyramid.testing, a rule for pushing and popping its thread locals around a test, and an official recommendation to drive functional tests with WebTest. Fixtures, parametrization, mocks and coverage come from pytest, which is also what the cookiecutter starter project uses.

The other frameworks of this site cover the same ground with their own tools: Flask has a test client (Flask: Testing), Tornado ships AsyncHTTPTestCase (Tornado: Testing) and FastAPI uses TestClient (FastAPI: Testing). Pyramid’s test doubles exist because a Pyramid view is a plain function of a request, and because so much of the framework (route generation, permissions, renderers, events) is looked up in a registry that a unit test must populate by hand.

The Three Kinds of Test

The official chapter distinguishes three levels. The difference is how much of the real application a test runs:

Level What is real What is faked

Unit

The function under test: a view, a subscriber, a helper.

Everything it touches. The request is a DummyRequest, resources are DummyResource, and the security policy and the renderers are test doubles registered in an empty registry with the testing_* helpers of the configurator.

Integration

The code under test and its integration with the framework: a real registry populated by config.include(...) of your own includeme functions, real route generation, real request extensions.

External services and, usually, the HTTP layer (the view is still called directly).

Functional

The whole WSGI application built by main(...), driven over a fake HTTP connection by WebTest: routing, tweens, views, renderers, sessions and cookies.

Only what is outside the process: databases, remote APIs, mail, the clock.

The official guidance is to write all three. Unit tests reach every code path cheaply, functional tests prove that the parts fit together as they will in production. The usual shape is many unit tests, fewer integration tests and a thin layer of functional tests.

class ShelfStore:
    """An in-memory stand-in for the real data layer."""

    def __init__(self):
        self._shelves = {}

    def all(self):
        return [self._shelves[slug] for slug in sorted(self._shelves)]

# norun  (project file bookshelf_shelves/security.py)
from pyramid.authentication import SessionAuthenticationHelper
from pyramid.authorization import ACLHelper, Allow, Authenticated, Everyone


class SessionSecurityPolicy:
    def __init__(self):
        self.helper = SessionAuthenticationHelper()

    def identity(self, request):
        return self.helper.authenticated_userid(request)

    def authenticated_userid(self, request):
        return self.identity(request)

    def permits(self, request, context, permission):
        principals = [Everyone]
        userid = self.identity(request)
        if userid is not None:
            principals += [Authenticated, f"user:{userid}"]
        return ACLHelper().permits(context, principals, permission)

    def remember(self, request, userid, **kw):
        return self.helper.remember(request, userid, **kw)

    def forget(self, request, **kw):
        return self.helper.forget(request, **kw)


class Root:
    __acl__ = [(Allow, Authenticated, "create")]

    def __init__(self, request):
        self.request = request


def includeme(config):
    config.set_security_policy(SessionSecurityPolicy())
    config.set_root_factory(Root)

        self.base_url = base_url.rstrip("/")
        self.timeout = timeout

    def title(self, isbn):
        url = f"{self.base_url}/{urllib.parse.quote(isbn, safe='')}"
        try:
            with urllib.request.urlopen(url, timeout=self.timeout) as response:
                return json.load(response)["title"]
        except urllib.error.HTTPError as exc:
            if exc.code == 404:
                return None
            raise

def create_shelf(request):
    data = request.json_body
    slug, title = data.get("slug", ""), data.get("title", "")
    if not slug.isidentifier() or not title:
        raise HTTPBadRequest(json_body={"error": "slug and title are required"})
    if request.shelves.get(slug) is not None:
        raise HTTPConflict(json_body={"error": "slug already used"})
    shelf = request.shelves.add(slug, title, owner=request.authenticated_userid)
    request.response.status = 201
    request.response.headers["Location"] = request.route_url("shelf", slug=slug)
    return shelf

def show_shelf(request):
    shelf = request.shelves.get(request.matchdict["slug"])
    if shelf is None:
        raise HTTPNotFound()

Three design choices matter for testing, and they are the ones to copy:

  • Collaborators are looked up through the request or the registry. The views never import a global store or build an HTTP client. They read request.shelves and request.isbn_client, which includeme registers with add_request_method from objects kept in the registry.   • Secrets come from settings. Unit Tests with pyramid.testing

Thread Locals: setUp, tearDown and testConfig

Pyramid keeps two thread-local values, the current request and the current registry, and a surprising number of APIs read them: render_to_response, route_url without an explicit request, get_current_request and every method of the configurator you use in a test. The rule of the official chapter is simple. If the code under test, or the test itself, uses the Configurator or any get_current_* function, push a fresh registry in the test setup and pop it in the teardown. pyramid.testing.setUp() does the first and pyramid.testing.tearDown() the second. setUp returns an autocommitting Configurator, so every config.add_route(...) takes effect immediately and no commit() is needed.

import unittest
from pyramid import testing
from pyramid.threadlocal import get_current_registry, get_current_request


class ThreadLocalTest(unittest.TestCase):
    def setUp(self):
        self.request = testing.DummyRequest()
        self.config = testing.setUp(request=self.request)

    def tearDown(self):
        testing.tearDown()

    def test_thread_locals_are_pushed(self):
        self.assertIs(get_current_request(), self.request)
        self.assertIs(get_current_registry(), self.config.registry)


suite = unittest.defaultTestLoader.loadTestsFromTestCase(ThreadLocalTest)
result = unittest.TextTestRunner(verbosity=0).run(suite)
assert result.wasSuccessful()
print(get_current_request())    # None again: tearDown popped the stack

DummyRequest and How Faithful It Is

DummyRequest imitates a request with the minimum of attributes: params, GET, POST, headers, cookies, environ, path, matchdict, context, session (a DummySession), registry and response, plus the URL methods (route_url, route_path, static_url), the security methods (has_permission, authenticated_userid, identity), localizer and add_response_callback. Any extra keyword argument becomes an attribute, which is how DummyRequest(shelves=store, json_body={...}) supplied the collaborators in the views above. Passing post= fills POST and sets the method to POST.

It is not a real request, and the official API page says so: use pyramid.request.Request when the code under test needs the whole object. The following snippet shows three of the differences that matter most, and the instance-level override of a request property that is useful for mocking:

Difference Consequence

GET and POST are plain dictionaries, not WebOb multi-dicts.

request.params.getall("tag") and request.POST.getone("title") fail. Replace the attribute with a MultiDict, or use a real Request.blank(...).

Dummy Resources, Sessions, Renderers, Events and Security

The Configurator returned by setUp has four testing_* methods. Each registers a stand-in for a real component and returns an object to assert against. Next to them are the dummy classes:

Method or class Use

testing_securitypolicy(userid=None, identity=None, permissive=True, remember_result=None, forget_result=None)

Registers a fake security policy. permissive=False makes every has_permission call and every permission= check fail. userid is what request.authenticated_userid returns. remember_result and forget_result are the header lists that remember and forget return.

testing_add_renderer(path, renderer=None)

Registers a fake renderer for a template or renderer path and returns a DummyTemplateRenderer. Its assert_(**kw) checks that the view passed those keys and values to the renderer.

testing_add_subscriber(event_iface=None)

Registers a subscriber that appends matching events to the returned list. With no argument it collects every event.

testing_resources(resources)

Takes a dictionary from path to resource, so that find_resource finds them without a real tree.

DummyResource(__name__=None, __parent__=None, __provides__=None, **kw)

A resource with the mapping protocol: root["dune"] = child sets the child’s name and parent. Keywords become attributes, __provides__ attaches an interface for context= view lookups, and clone() copies the resource.

DummySession

A dictionary with the session API: flash, pop_flash, peek_flash, changed, invalidate, get_csrf_token and new_csrf_token.

The TestApp

webtest.TestApp(app) wraps any WSGI application, including the one returned by main(...), and exposes it as an HTTP client that never opens a socket. The members used most are:

Call What it does

testapp.get(url, params=..., headers=..., status=...)

Performs a request. status= asserts the status (an integer, a list of integers, or a pattern such as "3*" or "*") and raises AppError on a mismatch. Without it WebTest accepts only 2xx and 3xx and raises for 4xx and 5xx unless expect_errors=True.

post, put, patch, delete, options, head

The other methods. post(url, {"title": "x"}) sends a form body.

post_json, put_json, patch_json, delete_json

Follow the Location of a redirect. maybe_follow follows as many redirects as there are.

The HTML forms of the page. form["name"] = value sets a field and form.submit() posts it with the hidden fields and the cookies.

Forms, Redirects and CSRF Tokens

Applications that render HTML forms are tested through the form, not around it. The hidden CSRF field is posted automatically when the test submits the form it fetched, and a request that skips the form is rejected. The snippet is a self-contained miniature of the Bookshelf Shelves "add a shelf" page with require_csrf=True, a flash message and a redirect:

import html
import secrets

import webtest
from pyramid.config import Configurator
from pyramid.csrf import get_csrf_token
from pyramid.httpexceptions import HTTPSeeOther
from pyramid.response import Response
from pyramid.session import SignedCookieSessionFactory

SHELVES = []


def page(request):
    flashes = "".join(f"<p class='flash'>{html.escape(m)}</p>" for m in request.session.pop_flash())
    items = "".join(f"<li>{html.escape(title)}</li>" for title in SHELVES)
    form = (
        '<form method="post" action="/shelves/new">'
        f'<input type="hidden" name="csrf_token" value="{get_csrf_token(request)}">'
        '<input type="text" name="title"><button type="submit">Add shelf</button></form>'
    )
    return Response(f"<html><body>{flashes}<ul>{items}</ul>{form}</body></html>")


def add(request):
    title = request.POST.get("title", "").strip()
    if title:
        SHELVES.append(title)
        request.session.flash(f"Shelf {title} added")
    return HTTPSeeOther(request.route_path("shelves"))


with Configurator() as config:
    config.set_session_factory(SignedCookieSessionFactory(secrets.token_hex(32)))
    config.set_default_csrf_options(require_csrf=True)
    config.add_route("shelves", "/shelves")
    config.add_route("add", "/shelves/new")
    config.add_view(page, route_name="shelves")
    config.add_view(add, route_name="add", request_method="POST")
    app = config.make_wsgi_app()

testapp = webtest.TestApp(app)
res = testapp.get("/shelves")
form = res.forms[0]                       # or res.form when the page has a single form
form["title"] = "Classics & more"
res = form.submit().follow()              # 303 -> GET /shelves
assert res.status_int == 200
assert "Shelf Classics &amp; more added" in res.text and "<li>Classics &amp; more</li>" in res.text
assert "session" in testapp.cookies

# a POST without the token never reaches the view
testapp.post("/shelves/new", {"title": "Forged"}, status=400)
assert SHELVES == ["Classics & more"]
print("ok", res.html.find("p", class_="flash").text)

The same test could not be written with a DummyRequest: nothing there runs the CSRF view deriver. Checking that a protected view is really protected is a functional test. The mechanism and its options are in CSRF Protection, and the session and flash APIs used here are in Sessions and Flash Messages.

Secure Cookies Need HTTPS in the Test

A session factory built with secure=True sets the Secure flag, and the TestApp’s cookie jar honours it: over plain http the cookie is never sent back. The next snippet shows the symptom and the cure, which is to set the URL scheme in the WSGI environ:

import secrets, webtest
from pyramid.config import Configurator
from pyramid.session import SignedCookieSessionFactory

def hit(request):
    request.session["n"] = request.session.get("n", 0) + 1
    return {"n": request.session["n"]}

with Configurator() as config:
    config.set_session_factory(SignedCookieSessionFactory(secrets.token_hex(32), secure=True))
    config.add_route("hit", "/hit")
    config.add_view(hit, route_name="hit", renderer="json")
    app = config.make_wsgi_app()

http = webtest.TestApp(app)
print([http.get("/hit").json["n"] for _ in range(2)])
https = webtest.TestApp(app, extra_environ={"wsgi.url_scheme": "https"})
print([https.get("/hit").json["n"] for _ in range(2)])

Isolating Tests

Tests that share state fail in an order-dependent way. The sources of shared state in a Pyramid application, and the remedy for each, are:

Shared state Remedy

The application registry and anything kept in it: the shelf store of this scenario, a cache, a connection pool.

Build app per test (function scope), as the conftest.py above does. It is cheap when startup does not connect to anything. With a session-scoped app (the cookiecutter default) reset the stores explicitly in a fixture.

The thread locals.

setUp and tearDown, or testConfig, so that a test cannot leak a registry into the next one.

Cookies in a TestApp.

Create the TestApp per test, as the testapp fixture does, or call testapp.reset().

A relational database.

Run each test inside a transaction that is rolled back. The cookiecutter’s sqlalchemy backend does it with a doomed transaction.TransactionManager, a session joined to it and a TestApp whose environ says tm.active. It is described in the section Testing with Transaction Rollback of SQLAlchemy, Transactions and Migrations.

A ZODB database.

Point the application at an in-memory storage with a memory:// URI in testing.ini, as in ZODB and Other Data Stores.

Module-level globals and the environment.

monkeypatch.setenv, monkeypatch.setattr and monkeypatch.setitem, which undo themselves at the end of the test.

Faking External Services

An application that calls a remote API needs tests that never leave the machine. Pyramid does not prescribe a mechanism. Three work well, from the cheapest to the most realistic:

  • Replace the collaborator in the registry. monkeypatch.setitem(app.registry, "isbn_client", fake) swaps the object that request.isbn_client reads. The fake needs only the methods the view calls, and it can raise the exceptions the real client raises. This is what test_catalogue_replaced_in_the_registry and test_catalogue_outage_is_a_502 do, and it is why the client is read from the registry and not imported.

  • Override the request property. On a request built with prepare or Request.blank, assigning request.isbn_client = fake replaces the value for that instance (see the 2.0 note above). It suits integration tests.

  • Run a real HTTP server on a loopback port. The fake_catalogue fixture starts http.server.HTTPServer on port 0 (the operating system picks a free one) in a thread, and the test points isbn.base_url at it. It exercises the real client code, its URL quoting and its handling of status codes, and it is the only way to catch a bug inside the client itself.

The mixture is deliberate: most tests use the cheap fake and one or two use the loopback server. Never let a test call a real third-party service. It is slow and flaky, and it may spend money or leak data. Pyramid itself is synchronous, so the tests of its views remain synchronous even when a view starts threads.

Pitfalls

  • Forgetting tearDown. A registry that is not popped leaks into the next test, which then passes or fails depending on the order. Use testConfig or a fixture, so that the teardown is not optional.

  • Testing a view only with DummyRequest. It has no CSRF check, no tweens, no permission check, no request extensions, a session that always exists and dict parameters. Each of those can hide a bug from a green unit suite. Keep at least one functional test per view.

  • testing_securitypolicy hides the real policy. A permissive dummy proves that the view works for someone who is allowed. It says nothing about who is allowed. Test the ACL itself separately.

  • Autocommit hides conflicts. The setUp configurator commits at once, so a test that includes two modules which register the same route passes, while the application fails at startup. The integration test that builds the app with main(...) is what catches it.

  • A session-scoped application with mutable state. The cookiecutter’s app fixture is session-scoped, so a store kept in the registry is shared by every test. Reset it, or use function scope.

  • Hardcoded secrets in testing.ini or in fixtures. They are copied into other projects, committed for good and flagged by scanners. Generate them with secrets.token_hex() per run, or read them from the environment.

  • Real network access. A test that calls a real service fails on a train and passes on the build server, or the other way round. Replace the client, and use http://127.0.0.1:9 as the default base URL of the test settings.

  • Debug helpers in the test settings. pyramid_debugtoolbar and the pyramid.debug_* settings change responses (extra HTML, extra logging). Keep them out of testing.ini so that the tests see what production serves.

  • Time and randomness. Tests that compare timestamps or random identifiers are flaky. Inject the clock and the generator through the registry, like the store, and replace them in tests.

  • Asserting on the wrong layer. status= in the call, res.json for APIs and res.text for HTML are cheap and precise. Avoid asserting on whole HTML pages: assert on a stable fragment, or on an element found through res.html.

  • Slow suites. Building the application per test is fine until startup does real work. Then build once per session and isolate the state instead.

What Changed and Where Older Material Is Outdated

  • The Pyramid change history records the move from nose and coverage to pytest and pytest-cov, and the project and its documentation use pytest today. Instructions that say python setup.py test or nosetests no longer apply.

  • The 2.1 starter project uses pyproject.toml for packaging and for the pytest and coverage configuration, and the 2.1 release notes say so. The official testing chapter still shows a setup.py with tests_require and an extras_require entry. The idea (a testing extra) is unchanged and the file is not, so do not look for a setup.py in a new project.

  • The register* helpers of pyramid.testing (registerDummySecurityPolicy and the others) were removed in favour of Configurator.testing_securitypolicy, testing_add_renderer, testing_add_subscriber and testing_resources.

  • The 2.1 signature of testing_securitypolicy is userid, identity, permissive, remember_result and forget_result, in line with the single security policy of Pyramid 2.0. Tutorials for the 1.x authentication policies pass other arguments, such as group identifiers, and register a dummy authentication policy instead.

  • Pyramid 2.0 made request properties added with add_request_method(..., property=True) or request.set_property overridable per instance, which simplifies mocking them.

  • DummyRequest has gained attributes over the years (domain, script_name, charset, a session, response, request callbacks and the URL, security and localization methods). A workaround in an old test for the absence of one of them can go.

  • The official chapter says that unittest is the suggested mechanism, and the 2.1 starter project is pytest-first with fixtures. Both work, and this page uses pytest.

  • Material that builds the TestApp once per module, or with a config: URI such as testing.ini#main, still works. The per-test fixtures shown here are easier to isolate.
