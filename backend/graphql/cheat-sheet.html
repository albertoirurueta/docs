Worked example

The schema below declares a Non-Null title and author, and a nullable book root field. It is executed with the Python graphql-core library (version 3.2) using a variable, once for an id that exists and once for an id that does not.

type Query {
  book(id: ID!): Book
}

type Book {
  id: ID!
  title: String!
  author: Author!
}

type Author {
  name: String!
}

The query takes the id as a variable, and a small script runs it against an in-memory data set:

query GetBook($id: ID!) {
  book(id: $id) {
    title
    author { name }
  }
}
import json
from graphql import build_schema, graphql_sync

schema = build_schema(SDL)  # the schema shown above

BOOKS = {"1": {"id": "1", "title": "Dune", "author": {"name": "Frank Herbert"}}}

class Root:
    def book(self, info, id):
        return BOOKS.get(id)

for book_id in ("1", "99"):
    result = graphql_sync(schema, QUERY, root_value=Root(), variable_values={"id": book_id})
    print(json.dumps(result.formatted, indent=2))

Running it prints one response per id. The unknown id produces null for the nullable book field rather than an error, because nothing below it was asked to resolve:

{
  "data": {
    "book": {
      "title": "Dune",
      "author": {
        "name": "Frank Herbert"
      }
    }
  }
}
{
  "data": {
    "book": null
  }
}
