Building an Authorization Server from Scratch

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This guide builds an OAuth 2.1 and OpenID Connect authorization server with Spring, one feature at a time, by reading the code of a working example: irurueta-auth-server. Every page explains one slice of the system, shows the real code through tagged regions of the example (nothing is pasted that does not run), and ends with the tests that prove it and the limits of what the example does.

The example is a learning project: it is built and tested in CI, but it is never deployed, so every address, port and credential in these pages is a local development value.

What you build

Four applications share one PostgreSQL server. The authorization server signs people in, with any of eight methods, and issues tokens. The BFF is the only client of a browser application and keeps the tokens out of the browser. The resource server validates bearer tokens, and the service client calls it with no user at all. The Architecture page walks through the figure.

Prerequisites

  • Java: a JDK between 21 and 25 and, for the integration tests and the local services, Docker. Maven itself is optional because the repository ships the Maven wrapper.

  • Spring: Spring Boot 4.1, with Spring Security 7.1 and Spring Authorization Server. If you have never used them, start with Spring Security and Authorization Server & Social Login.

  • OAuth: you should know what an authorization code, a token and a scope are. The OAuth Reference: Getting Started page covers that in a few minutes.

Reading order

The pages build on each other, so read them in this order the first time. After that, each one stands alone.

  1. Foundations: Architecture, Project Setup and Data Model.

  2. Credentials and tokens: Passwords, Signing Keys, Tokens and Registered Clients.

  3. The applications around it: Resource Server, Login Pages and BFF.

  4. More than a password: MFA and Step-Up, then TOTP, passkeys, e-mail and SMS codes, social login and the other passwordless methods, in any order.

  5. Other grants: Implicit Flow and Client Credentials.

  6. Using it for real: API Reference, Hardening & Production and Testing.

Clone and run the example

git clone https://github.com/albertoirurueta/irurueta-auth-server.git
cd irurueta-auth-server
./mvnw -pl auth-server/boot -am spring-boot:run -Dspring-boot.run.profiles=dev

Start the resource-server and the bff the same way, then open http://localhost:8080. The Project Setup page gives the full run order, the profiles, the seeded demo user and clients, and how to run the tests. The example’s own documentation, with its installation guide, is in the irurueta-auth-server documentation.

Relationship to the other guides

  • The OAuth Reference explains the protocols and the theory, and has no framework code. This guide is its Spring Boot counterpart, and each page links back to the sections that hold the background.

  • The Authorization Server & Social Login page is a short, self-contained introduction with small snippets. Read it for a first look; read this guide to see a complete server, with its database, its keys and its tests.
