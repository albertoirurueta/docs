os, path & URL

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against Node.js 26 (26.10.0, released 2026-09-21, the Current line that becomes LTS on 2026-10-28), with the differences of Node.js 24 "Krypton" (24.21.0, Active LTS) and Node.js 22 "Jod" (22.23.3, Maintenance) called out; versions and stability levels were checked against the official documentation on 2026-10-03, and every example below was run on all three lines unless the text says otherwise. Three small built-in modules answer the questions every application asks about its surroundings: how many CPUs and what kind of machine am I on (node:os), where is this file and how do I build a path to another one (node:path), and what does this address mean (the WHATWG URL, URLSearchParams and URLPattern classes, plus node:url helpers such as fileURLToPath()). None of them touches the network or the disk: they compute on strings and read a few environment variables, so they are cheap, synchronous and safe to call anywhere. Their mistakes are not cheap, though. Path handling is where directory traversal bugs are born, and URL handling is where host-spoofing and open-redirect bugs are born, so this page spends as much time on the safe patterns as on the API tour. The running scenario is the Bookshelf application that grows across this section, described in Introduction & Architecture. Reading and writing the files that these paths point to is the subject of File System, and the HTTP server that consumes the URLs is built in HTTP Server Fundamentals.

node:os: the machine you run on

node:os exposes facts about the operating system and the hardware. Most functions are thin wrappers around libuv or around the C library, so the values are the ones the kernel reports, not something Node.js computes. Two of them deserve a decision rule; the rest are lookups.

Table 2. The os functions and properties used most often
API What it returns Use it for

os.availableParallelism()

An estimate of the default amount of parallelism a program should use; always greater than zero. A wrapper around libuv’s uv_available_parallelism().

Sizing worker pools and cluster forks.

os.cpus()

One object per logical CPU with model, speed (MHz) and cumulative times in milliseconds (user, nice, sys, idle, irq). The array is empty when the information is unavailable, for example when /proc is missing.

Reporting hardware and computing CPU load from two samples. Not for sizing pools.

os.homedir()

The home directory. On POSIX it uses $HOME if defined, otherwise it looks up the effective user; on Windows it uses USERPROFILE if defined.

Per-user config and caches. Not a trust boundary: the environment variable wins.

os.userInfo()

username, uid, gid, shell, homedir from the operating system itself (uid and gid are -1 on Windows). Its homedir ignores $HOME.

When you need the account’s real home regardless of the environment.

os.tmpdir()

The default directory for temporary files, with no trailing slash. On POSIX it checks TMPDIR, TMP and TEMP in that order and falls back to /tmp; on Windows TEMP wins over TMP.

Scratch files; combine with fs.mkdtemp() for a private directory.

os.EOL

"\n" on POSIX, "\r\n" on Windows.

Writing text files meant for people on the current platform.

os.devNull

/dev/null on POSIX, \\.\nul on Windows.

Discarding output of a child process portably.

os.constants

Objects signals, errno, priority and dlopen, plus the libuv flag UV_UDP_REUSEADDR. Not every constant exists on every platform.

Mapping between numbers and names (SIGTERM is 15, ENOENT is 2 on Linux and macOS).

os.platform(), os.arch(), os.type(), os.release(), os.version(), os.machine()

Strings identifying the OS and CPU architecture the binary was built for.

Choosing a native binary or reporting diagnostics.

os.totalmem(), os.freemem(), os.uptime(), os.loadavg(), os.hostname(), os.networkInterfaces()

Host-level numbers; loadavg() is always [0, 0, 0] on Windows.

Health endpoints and diagnostics.

os.getPriority(), os.setPriority()

Scheduling priority of a process, expressed with the os.constants.priority values (a nice value on POSIX, a priority class on Windows).

Lowering the priority of a background batch job.

import os from 'node:os';

console.log('platform        :', os.platform(), os.arch());
console.log('parallelism     :', os.availableParallelism());

console.log('homedir is str  :', typeof os.homedir() === 'string');
console.log('tmpdir          :', os.tmpdir());

node:path: building and taking apart file paths

A path is just a string until the file system gets it, and node:path is the module that manipulates those strings the way the current platform expects. It never checks that a file exists, never follows symbolic links, and never touches the disk; that is why its functions are synchronous and why the Learn article on file paths points out that neither resolve() nor normalize() verify that the result exists. The default flavour follows the operating system the code runs on, so the same call can give different answers on Linux and Windows. Two properties expose both flavours at once: path.posix and path.win32 always behave like the platform they are named after, and path.posix.posix and path.win32.win32 point back to themselves.

Joining untrusted input: the traversal check

path.join(root, name) does exactly what its name says, so when name comes from a request, '../secret.txt' or '/etc/passwd' walks right out of root. The last line of the example below shows the escape. The safe pattern has three steps: resolve the candidate against the base, compute the relative path from the base back to the candidate, and reject anything that starts by climbing out (.. as the whole result or followed by a separator) or that is absolute. Testing rel.startsWith('..') alone also rejects a legitimate file named ..notes, which is why the example checks for .. followed by the separator.

A traversal-safe join for the Bookshelf uploads directory
import path from 'node:path';

const root = path.resolve('/srv/bookshelf/uploads');

function safeJoin(base, untrusted) {
  const target = path.resolve(base, untrusted);
  const rel = path.relative(base, target);
  if (rel === '' || rel === '..' || rel.startsWith(`..${path.sep}`) || path.isAbsolute(rel)) {
    throw new RangeError(`path escapes ${base}: ${untrusted}`);
  }
  return target;
}

for (const name of ['cover.png', 'a/b.txt', '../secret.txt', '/etc/passwd', 'x/../../uploads-evil/a']) {
  try { console.log('ok  ', safeJoin(root, name)); }
  catch (e) { console.log('deny', e.message); }
}
console.log(path.join(root, '../secret.txt'));

URLPattern: routing without a framework

URLPattern matches URLs, or parts of URLs, against a pattern, using the syntax of the URL Pattern Standard (named groups such as :id, an optional regular expression in parentheses, wildcards, optional groups in braces).   ['GET', new URLPattern({ pathname: '/books' }), (m, url) => ({ page: Number(url.searchParams.get('page') ?? 1) })],
];

    if (match) {
      res.setHeader('content-type', 'application/json');
      return res.end(JSON.stringify(handler(match, url)));
    }
  }
  res.statusCode = 404;
  res.end('not found');
});

File URLs and file paths

A module’s identity in ESM is a URL, not a path: import.meta.url is a file: URL such as file:///srv/bookshelf/src/server.js. Converting between the two worlds is the job of two functions in node:url, and doing it by hand (new URL(…​).pathname, string slicing) is wrong in ways that only show up on some platforms: the pathname of a file URL is still percent-encoded (/hello%20world), and on Windows it carries a leading slash before the drive letter (/C:/path/). fileURLToPath(url) decodes it and returns a valid absolute path for the platform, pathToFileURL(path) resolves the path to absolute and encodes characters that are special in URLs (#, %, ?, spaces). Both accept a windows option (v22.1.0 and v20.13.0) to force the Windows or POSIX interpretation, which is how the example below can show Windows results on any platform. fileURLToPath() throws for non-file: URLs (ERR_INVALID_URL_SCHEME), for URLs with a host on POSIX (ERR_INVALID_FILE_URL_HOST) and for encoded slashes (ERR_INVALID_FILE_URL_PATH). url.fileURLToPathBuffer() (v24.3.0 and v22.18.0) returns a Buffer for names that are not valid UTF-8.

In ESM you rarely need the conversion for the current module: import.meta.filename and import.meta.dirname already give the path of the current file and its directory (see ECMAScript Modules); CommonJS has filename and dirname (see CommonJS Modules). Use new URL('./data/catalog.json', import.meta.url) to build a URL relative to the module, which fs functions also accept.

Converting between file paths and file URLs
import { fileURLToPath, pathToFileURL } from 'node:url';
import path from 'node:path';

console.log(import.meta.url.startsWith('file:///'));
console.log(fileURLToPath(import.meta.url) === import.meta.filename);
console.log(path.dirname(fileURLToPath(import.meta.url)) === import.meta.dirname);

console.log(pathToFileURL('/srv/bookshelf/my books/#1.txt').href);
console.log(pathToFileURL('/some/path%.c').href);
console.log(fileURLToPath('file:///srv/bookshelf/my%20books/%231.txt'));
console.log(new URL('file:///hello world').pathname, fileURLToPath('file:///hello world'));
console.log(new URL('./data/catalog.json', import.meta.url).pathname.endsWith('/data/catalog.json'));

console.log(fileURLToPath('file:///C:/data/a.txt', { windows: true }));
console.log(fileURLToPath('file://nas/share/a.txt', { windows: true }));
console.log(pathToFileURL('C:\\data\\a b.txt', { windows: true }).href);

for (const bad of ['http://example.test/a', 'file://host/a/b', 'file:///a%2Fb']) {
  try { console.log(fileURLToPath(bad)); } catch (e) { console.log(e.code); }
}

const evil = new URL('file:///srv/bookshelf/public/%2e%2e/secret.txt');

The last two lines are a security lesson the official documentation spells out. fileURLToPath() decodes encoded dot segments (%2e%2e) and then normalizes, so a URL that looks as if it stays inside /srv/bookshelf/public converts to a path outside it, and the check printed false. The documentation states that applications must not rely on fileURLToPath() alone to prevent directory traversal: run the traversal check from above on the converted path.

Why url.parse() and querystring are legacy

Before the WHATWG classes existed, Node.js had its own URL API, now called the legacy API: url.parse(), url.format(urlObject), url.resolve() and the plain urlObject they use, together with the node:querystring module. The two have different statuses, and the difference is worth knowing.

import url from 'node:url';

// 1. The legacy result shape
const input = 'https://user:pw@example.com:8080/p/a/t/h?query=string#hash';
const legacy = url.parse(input, true);
console.log(legacy.host, legacy.pathname, legacy.query, legacy.auth);

// 2. Leniency: inputs the WHATWG parser rejects, url.parse() accepts
for (const s of ['https://exa mple.test/x', 'https://shelf.test:99999/x', 'https://shelf.test%2f.evil.test/x']) {
  const l = url.parse(s);
  let w;
  try { w = new URL(s).href; } catch (e) { w = e.code; }
  console.log(JSON.stringify(s), '\n  legacy  :', l.hostname, l.port, l.pathname, '\n  WHATWG  :', w);
}

// 3. Relative and format helpers
console.log(url.resolve('https://a.test/one/two', '../three'), new URL('../three', 'https://a.test/one/two').href);
console.log(url.format({ protocol: 'https', hostname: 'a.test', pathname: '/x', query: { a: 1 } }));
console.log(url.format(new URL('https://u:p@a.test/x?y=1#z'), { auth: false, fragment: false }));

The three leniency cases are the heart of the security argument. A validator built on new URL() and a downstream consumer built on url.parse() can disagree about what an input means, and an attacker lives in that disagreement (an allow-list of hosts that checks one parser and fetches through the other). Parsing every URL once, with one parser, and passing the resulting URL object around removes that class of bug. DEP0170 shows how far this went: url.parse() used to accept ports that are not numbers, and since v25.0.0 it throws ERR_INVALID_ARG_VALUE for them (observed on Node.js 26; Node.js 24 and 22 still return the host with a null port). Note that the application deprecation only warns for code outside node_modules, so a dependency of yours may keep using it silently.

The querystring module is a different story: nothing is wrong with it, it is simply a second, older way to do what URLSearchParams does. The examples show where they differ. querystring.parse() returns an object with a null prototype and collects repeated keys into an array, while Object.fromEntries(new URLSearchParams(…​)) keeps only the last value (use getAll() for the others). querystring.stringify() expands arrays into repeated keys and turns nested objects, undefined and null into empty values, while URLSearchParams joins arrays with commas and writes the text [object Object], undefined and null. querystring.parse() replaces invalid UTF-8 with the replacement character, as URLSearchParams does, and encodes a space as %20 where URLSearchParams writes +. If you keep using querystring, keep it for the server-side cases it was written for and put an allow-list of known keys on its output; for everything that shares code with a browser, use URLSearchParams.

Migration is mostly mechanical, and the official Node.js userland migrations project ships a codemod for it, which the url.parse() documentation points to:

Pitfalls

Table 7. Mistakes that recur with these modules
Mistake What to do instead

Using os.cpus().length to size a pool

Use os.availableParallelism(); it respects the CPUs the process may use, which matters in containers.

Assuming os.tmpdir() or os.homedir() are fixed

They follow environment variables. Create private subdirectories with fs.mkdtemp() and do not trust them as a security boundary.

Joining untrusted names onto a base with path.join()

Resolve, compute the relative path and reject .. and absolute results; use generated names where you can; add realpath() if symbolic links are possible.

Hardcoding / or \ in a path

Build paths with path.join() or path.resolve(); use path.posix for keys and URL paths.

Parsing a Windows path on Linux (or the reverse) with the default path

Use path.win32 or path.posix explicitly.

Reading new URL('file:///…​').pathname as a path

Use fileURLToPath(). The pathname is still percent-encoded and, on Windows, begins with a slash before the drive letter.

Trusting fileURLToPath() to stay inside a directory

Check the converted path with the same traversal test you use for any path.

Concatenating strings into URLs and query strings

Use new URL(relative, base) and searchParams.set() or append().

Logging url.href of a URL that may contain credentials

Log url.origin + url.pathname, or clear username and password first.

Building the base URL of a request from the Host header

Use a configured constant, or a trusted proxy’s header only when you control the proxy.

Using URLPattern on Node.js 22 without a check

Test typeof URLPattern first, or require Node.js 24 or later. Remember it is still Experimental.

Using url.parse() or url.resolve() in new code

Use URL and URL.parse(). DEP0169 warns on 24 and later.

Where the books are outdated or incomplete

Efficient Node.js (Samer Buna, O’Reilly 2025) lists node:os, node:path and node:url in a one-line-each table of built-in modules and then uses them only in passing. Its cluster example sizes the number of workers with os.availableParallelism(), which is the current API, but it describes the result as a number up to what os.cpus().length reports; as the container example above shows, the two can differ, and the point of the newer function is exactly that it does not report the host. Several of its HTTP examples route by comparing req.url with literal strings in a switch; that value includes the query string, so /compute?n=5 would not match /compute, and the page-level fix is to parse req.url with new URL() against a constant base and compare pathname, or to use URLPattern on Node.js 24 and later. The book treats __dirname and import.meta.dirname as alternatives, which is right, but it does not cover fileURLToPath() and pathToFileURL(), which are what ESM needs for everything that is not the current file, and it says nothing about path.matchesGlob(), URLPattern or the legacy status of url.parse() (an application deprecation since Node.js 24.0.0).

Node.js Projects (Jonathan Wexler, O’Reilly 2025) builds its projects on frameworks and does not teach these modules. Where it needs a path it resolves a relative file name with path.resolve(), which is correct, and where it composes HTTP addresses for the peers of its blockchain project and for API calls it concatenates strings with template literals. That works while every piece is trusted; once a piece comes from a user, use new URL() and searchParams so that the encoding is done for you.

Table 9. Quick corrections for older tutorials and books
Statement you may meet Current situation

"Use os.cpus().length to decide how many workers to start"

Use os.availableParallelism(); the documentation warns against cpus().length for this purpose.

"`path.join()` makes a path safe"

It only normalizes. Untrusted names need a resolve, relative and prefix check, and symbolic links need realpath().

“__dirname` does not exist in ESM, so use `path.dirname(new URL(import.meta.url).pathname)”

Use import.meta.dirname and import.meta.filename, or fileURLToPath(import.meta.url). The .pathname shortcut breaks on spaces and on Windows.

"`url.parse()` is the standard way to read a query string"

It is deprecated; new URL() and URLSearchParams are the standard replacement.

"`querystring` is deprecated"

It is not; it is Stable but non-standard. Prefer URLSearchParams for new code.

"You need a router package to match URL patterns"

URLPattern is built in from Node.js 24 (Experimental); on 22 use a package or your own matcher.

"`fs.glob` is the only built-in glob"

path.matchesGlob() tests a path against a glob without reading the disk and is stable from v24.8.0 and v22.20.0.
