Authorization

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against axum 0.8.9 and axum-login 0.18.0 on Rust 1.99 (edition 2024), checked on 2026-10-06. Authentication establishes who the caller is (sessions, JWTs, OAuth2 — the previous pages); authorization decides what they may do. Bookshelf has two roles — member and librarian — and per-resource rules such as "a member may delete only their own reviews". Token scopes and claims as an authorization mechanism are discussed on this site’s Scopes, Claims and Permissions page.

Role extractors

The cleanest axum pattern turns each role or permission into an extractor type: a handler that takes a Librarian argument cannot run for anyone else, and the requirement is visible in its signature. The role extractors build on the CurrentUser extractor (see Custom Extractors):

use std::collections::HashMap;
use std::sync::{Arc, RwLock};

use axum::{
    RequestPartsExt, Router,
    extract::{FromRef, FromRequestParts, Path, State},
    http::{StatusCode, request::Parts},
    middleware::from_extractor_with_state,
    routing::{delete, get, post},
};

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum Role {
    Member,
    Librarian,
}

#[derive(Clone, Debug)]
struct CurrentUser {
    id: u64,
    role: Role,
}

#[derive(Clone, Default, FromRef)]
struct AppState {
    tokens: Arc<HashMap<String, CurrentUser>>,       // stands in for sessions or JWT validation
    reviews: Arc<RwLock<HashMap<u64, (u64, String)>>>, // review id -> (author id, text)
}

impl<S> FromRequestParts<S> for CurrentUser
where
    S: Send + Sync,
    Arc<HashMap<String, CurrentUser>>: FromRef<S>,
{
    type Rejection = StatusCode;

    async fn from_request_parts(parts: &mut Parts, state: &S) -> Result<Self, StatusCode> {
        let token = parts
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .and_then(|v| v.strip_prefix("Bearer "))
            .ok_or(StatusCode::UNAUTHORIZED)?;
        let tokens: Arc<HashMap<String, CurrentUser>> = FromRef::from_ref(state);
        tokens.get(token).cloned().ok_or(StatusCode::UNAUTHORIZED) // 401: we do not know who you are
    }
}

/// Only librarians. Rejects with 401 (not signed in) or 403 (signed in, wrong role).
struct Librarian(CurrentUser);

impl<S> FromRequestParts<S> for Librarian
where
    S: Send + Sync,
    Arc<HashMap<String, CurrentUser>>: FromRef<S>,
{
    type Rejection = StatusCode;

    async fn from_request_parts(parts: &mut Parts, state: &S) -> Result<Self, StatusCode> {
        let user = parts.extract_with_state::<CurrentUser, S>(state).await?;
        if user.role == Role::Librarian { Ok(Librarian(user)) } else { Err(StatusCode::FORBIDDEN) }
    }
}

async fn add_book(Librarian(user): Librarian) -> String {
    format!("book added by librarian {}\n", user.id)
}

/// Resource ownership: members may delete their own reviews, librarians any review.
async fn delete_review(
    user: CurrentUser,
    State(state): State<AppState>,
    Path(review_id): Path<u64>,
) -> Result<StatusCode, StatusCode> {
    let mut reviews = state.reviews.write().expect("lock poisoned");
    let (author, _) = reviews.get(&review_id).ok_or(StatusCode::NOT_FOUND)?;
    if *author != user.id && user.role != Role::Librarian {
        // reviews are public, so 403 leaks nothing; for private resources answer 404 instead
        return Err(StatusCode::FORBIDDEN);
    }
    reviews.remove(&review_id);
    Ok(StatusCode::NO_CONTENT)
}

async fn reports() -> &'static str {
    "loan statistics\n"
}

#[tokio::main]
async fn main() {
    let state = AppState::default();
    let mut tokens = HashMap::new();
    tokens.insert("member-demo-token".to_owned(), CurrentUser { id: 7, role: Role::Member });
    tokens.insert("librarian-demo-token".to_owned(), CurrentUser { id: 1, role: Role::Librarian });
    let state = AppState { tokens: Arc::new(tokens), ..state };
    state.reviews.write().unwrap().insert(100, (7, "A classic.".into()));
    state.reviews.write().unwrap().insert(101, (8, "Too long.".into()));

    // a whole router guarded by one extractor: every route needs a librarian
    let admin = Router::new()
        .route("/reports", get(reports))
        .route_layer(from_extractor_with_state::<Librarian, _>(state.clone()));

    let app = Router::new()
        .route("/api/v1/books", post(add_book))
        .route("/api/v1/reviews/{id}", delete(delete_review))
        .nest("/admin", admin)
        .with_state(state);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}

Source: RFC 9110: 403 Forbidden and axum: from_extractor_with_state

  • Per handler: put the role extractor in the signature (add_book). The compiler guarantees the check; reviewers see it.

  • Per router: route_layer(from_extractor_with_state::<Librarian, _>(state)) runs the extractor before every route of the admin router and discards the value. route_layer (not layer) keeps unknown paths at 404.

  • Per resource: checks that depend on the data — who wrote this review, which library branch a loan belongs to — cannot be expressed as extractors and belong in the handler or, better, the service (delete_review).

Object-level authorization (IDOR / BOLA)

Broken Object Level Authorization (BOLA, also called IDOR — insecure direct object reference) is the first item of the OWASP API Security Top 10: an endpoint checks that the caller is signed in, but not that the object id in the URL belongs to them, so GET /api/v1/loans/1002 shows someone else’s loan. Gangappa & Rangaraj (Mastering Distributed Observability in Rust, chapter 13) show how such probing appears in traces as one user requesting many sequential ids with a high 403/404 rate.

Defences, strongest first:

  1. Scope the query by the owner: SELECT ... FROM loans WHERE id = $1 AND member_id = $2. A foreign id simply finds nothing — there is no check to forget.

  2. Check ownership in one service function that every handler goes through, never in templates or clients.

  3. Use non-guessable ids (UUIDv7) for resources that are not public; this is defence in depth, not a substitute.

  4. Test it: for every endpoint with an id, a test that another user gets 404/403 (see Testing).

401, 403 or 404?

Status Use when

401 Unauthorized

no valid credentials: missing, expired or invalid token or session. Include a WWW-Authenticate challenge for token-based APIs. (The name is historical; it means "unauthenticated".)

403 Forbidden

the caller is known but not allowed: wrong role, or not the owner of a resource whose existence is not secret

404 Not Found

the caller may not even know the resource exists (another member’s loan, a private shelf). Answering 403 would confirm the id is valid.

Permissions with axum-login

axum-login adds authorization to its authentication backend: implement AuthzBackend::get_user_permissions (and optionally group permissions), then guard routes with permission_required!:

use std::collections::HashSet;

use axum::{Router, routing::get};
use axum_login::{AuthUser, AuthnBackend, AuthzBackend, UserId, permission_required};

#[derive(Clone, Debug)]
struct User {
    id: i64,
    permissions: HashSet<String>,
}

impl AuthUser for User {
    type Id = i64;
    fn id(&self) -> i64 {
        self.id
    }
    fn session_auth_hash(&self) -> &[u8] {
        b"password-hash-goes-here"
    }
}

#[derive(Clone)]
struct Backend;

impl AuthnBackend for Backend {
    type User = User;
    type Credentials = ();
    type Error = std::convert::Infallible;

    async fn authenticate(&self, _: ()) -> Result<Option<User>, Self::Error> {
        Ok(None)
    }
    async fn get_user(&self, id: &UserId<Self>) -> Result<Option<User>, Self::Error> {
        Ok(Some(User { id: *id, permissions: HashSet::from(["books.write".to_owned()]) }))
    }
}

impl AuthzBackend for Backend {
    type Permission = String;

    async fn get_user_permissions(&self, user: &User) -> Result<HashSet<String>, Self::Error> {
        Ok(user.permissions.clone())
    }
}

fn librarian_routes() -> Router {
    Router::new()
        .route("/catalogue/edit", get(|| async { "edit form" }))
        .route_layer(permission_required!(Backend, login_url = "/login", "books.write"))
}

fn main() {
    let _router = librarian_routes(); // add AuthManagerLayer as on the Password Authentication page
}

Source: axum-login: AuthzBackend and permission_required!

permission_required! redirects anonymous users to the login URL and answers 403 to signed-in users without the permission. Permission strings (books.write) scale better than roles when rules multiply: roles become named sets of permissions stored in the database, and handlers check permissions, not role names.

Where the books are outdated

Yoon (Beginning Axum, chapter 4) protects routes with a JWT middleware but performs no per-resource checks, so any authenticated user can modify any other user’s data — the BOLA pattern above. Add ownership conditions to every query that takes an id from the request.
