Request Body & Models

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against FastAPI 0.142.2 (released 2026-09-30), Pydantic 2.13 and Starlette 1.7, checked on 2026-10-02. All code uses Python 3.10+ syntax, Annotated and Pydantic v2, and was executed with TestClient on Python 3.13. A request body is the data a client sends to the API (almost always JSON in a POST, PUT or PATCH); you declare its shape with a Pydantic model and FastAPI reads, converts, validates, documents and hands it to your function as a typed object. The Bookshelf API (books, authors, reviews) is the running scenario. How the same models are written as Pydantic (validators, model_config, serialization) is the subject of Pydantic v2 Essentials; how the response side works is covered in Response Models & Return Types.

A Pydantic Model as the Body

Declare a class that inherits from pydantic.BaseModel, with one annotated attribute per JSON key, and use it as the type of a handler parameter. Attributes without a default are required; attributes with a default (including None) are optional.

from fastapi import FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()


class BookIn(BaseModel):
    title: str
    isbn: str
    pages: int | None = None
    price: float = 9.99


@app.post("/books")
def create_book(book: BookIn) -> dict:
    # book is a validated BookIn instance, not a dict
    return {"title": book.title, "price_with_tax": round(book.price * 1.21, 2), "type": type(book).__name__}

r = c.post("/books", json={"title": "Dune", "isbn": "9780441013593"})
print(r.status_code, r.json())
r = c.post("/books", json={"title": "Dune"})
print(r.status_code, r.json())
r = c.post("/books", json={"title": "Dune", "isbn": "x", "pages": "many"})
print(r.status_code, r.json())

print(r.status_code, r.json())
r = c.post("/books", json=["a"])

With a valid payload, create_book receives a real BookIn instance (the handler reports its class name), so attribute access, completion and static checking work:

Body, Path and Query Together

FastAPI decides where each parameter comes from by looking at the declaration:

  • a name that appears in the path template ({book_id}) is a path parameter;

  • a parameter of a singular type (int, str, bool, date, …​) that is not in the path is a query parameter;

  • a parameter whose type is a Pydantic model (or another structure Pydantic treats as an object) is the body.

from typing import Annotated
from fastapi import FastAPI, Path, Query
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()


class BookUpdate(BaseModel):
    title: str
    price: float


@app.put("/books/{book_id}")
def replace_book(
    book_id: Annotated[int, Path(ge=1)],          # in the path template -> path
    book: BookUpdate,                              # Pydantic model -> body
    notify: bool = False,                          # simple type -> query
    reason: Annotated[str | None, Query(max_length=50)] = None,
) -> dict:
    return {"book_id": book_id, **book.model_dump(), "notify": notify, "reason": reason}


c = TestClient(app)
print(c.put("/books/7?notify=true&reason=typo", json={"title": "Dune", "price": 12}).json())
op = c.get("/openapi.json").json()["paths"]["/books/{book_id}"]["put"]
print([(p["name"], p["in"], p["required"]) for p in op["parameters"]], list(op["requestBody"]["content"]))

The generated operation lists book_id as a required path parameter and notify and reason as optional query parameters, with a single application/json request body. Constraints on the path and query parameters (Path(ge=1), Query(max_length=50)) are covered in Path Parameters and Query Parameters. Headers, cookies and form fields are further sources selected with Header(), Cookie() and Form().

Multiple Body Parameters, Body() and embed

When the handler declares two or more body parameters, FastAPI expects a JSON object whose keys are the parameter names:

from typing import Annotated
from fastapi import Body, FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()


class Book(BaseModel):
    title: str


class Author(BaseModel):
    name: str


@app.post("/catalog")
def add_pair(book: Book, author: Author) -> dict:
    return {"book": book, "author": author}


@app.post("/catalog/ranked")
def add_ranked(book: Book, author: Author, rank: Annotated[int, Body(ge=1)]) -> dict:
    return {"book": book, "author": author, "rank": rank}


@app.post("/books/embedded")
def embedded(book: Annotated[Book, Body(embed=True)]) -> dict:
    return {"book": book}


@app.post("/books/plain")
def plain(book: Book) -> dict:
    return {"book": book}


c = TestClient(app)
r = c.post("/catalog", json={"book": {"title": "Dune"}, "author": {"name": "Frank Herbert"}})
print(r.status_code, r.json())
r = c.post("/catalog", json={"title": "Dune"})
print(r.status_code, r.json()["detail"])
r = c.post("/catalog/ranked", json={"book": {"title": "Dune"}, "author": {"name": "F"}, "rank": 1})
print(r.status_code, r.json())
print(c.post("/books/embedded", json={"book": {"title": "Dune"}}).json())
print(c.post("/books/embedded", json={"title": "Dune"}).status_code)
print(c.post("/books/plain", json={"title": "Dune"}).json())
print(c.post("/books/plain", json={"book": {"title": "Dune"}}).status_code)

Source: FastAPI: Body - Multiple Parameters

A request for /catalog must look like this; each model is validated under its own key:

{"book": {"title": "Dune"}, "author": {"name": "Frank Herbert"}}

Sending the flat {"title": "Dune"} instead fails with two missing errors, located at ["body", "book"] and ["body", "author"].

Body() has two jobs:

  • Singular values in the body. A plain int would be read as a query parameter. Annotating it with Body() (here Annotated[int, Body(ge=1)]) makes it a key of the body object next to the models, as rank is in /catalog/ranked. Body() accepts the same validation keywords as Query() and Path() (gt, ge, lt, le, min_length, max_length, pattern) plus title, description, examples, openapi_examples, media_type and deprecated.

  • embed=True. With a single body parameter FastAPI expects the model’s fields at the top level (/books/plain accepts {"title": "Dune"}). Body(embed=True) makes it expect the model nested under the parameter name (/books/embedded accepts {"book": {"title": "Dune"}} and rejects the flat form with a 422). Use it when the API shape is {"book": {…​}}, or when you expect to add further body parameters later without breaking the shape of existing requests.

Validation and Metadata with Field

Constraints that belong to the data model go in pydantic.Field, either as the default (x: int = Field(ge=1)) or, as recommended throughout this section, inside Annotated. Inside Annotated, a default is then written with = as for any other parameter, so a field without = …​ is required.

from typing import Annotated
from fastapi import FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

app = FastAPI()


class Review(BaseModel):
    reviewer: Annotated[str, Field(min_length=2, max_length=40, description="Display name", examples=["Ada"])]
    rating: Annotated[int, Field(ge=1, le=5, description="Stars from 1 to 5")]
    text: str | None = Field(default=None, max_length=500, title="Review text")
    helpful_votes: int = Field(default=0, ge=0, json_schema_extra={"readOnly": True})
    code: str = Field(default="AB-1", pattern=r"^[A-Z]{2}-\d$")
    tags: list[str] = Field(default_factory=list, max_length=3)
    score: float = Field(default=1.0, gt=0, lt=10, multiple_of=0.5)


@app.post("/reviews")
def add_review(review: Review) -> Review:
    return review


c = TestClient(app)
print(c.post("/reviews", json={"reviewer": "Ada", "rating": 5}).json())

Nested Models, Lists, Sets and Dicts

Models can use other models as field types, and any of Pydantic’s collections, to any depth. Validation recurses, and errors report the full path, including list indexes.

from fastapi import FastAPI
from fastapi.testclient import TestClient
from pydantic import BaseModel, HttpUrl

app = FastAPI()

Updating Data: PUT Replaces, PATCH Merges

The two HTTP verbs have different contracts, and a body model has to be treated accordingly.

  • PUT sends the complete representation; whatever is not sent returns to its default. Use the same model as for creation.

  • PATCH sends only the changes. Use a model where every field is optional, and apply only the fields the client actually sent.

The tool for "what did the client send?" is Pydantic’s model_fields_set, used by model_dump(exclude_unset=True): it separates a field the client omitted from one it sent explicitly as null.

from typing import Annotated
from fastapi import Body, FastAPI, HTTPException
from fastapi.encoders import jsonable_encoder
from fastapi.testclient import TestClient
from pydantic import BaseModel

app = FastAPI()


class Book(BaseModel):
    title: str
    price: float
    pages: int | None = None
    in_stock: bool = True


class BookPatch(BaseModel):
    title: str | None = None
    price: float | None = None
    pages: int | None = None
    in_stock: bool | None = None


DB: dict[int, Book] = {1: Book(title="Dune", price=9.99, pages=412)}


@app.put("/books/{book_id}")
def replace(book_id: int, book: Book) -> Book:
    if book_id not in DB:
        raise HTTPException(404, "Book not found")
    DB[book_id] = book            # full replacement: omitted optional fields fall back to defaults
    return book


@app.patch("/books/{book_id}")
def patch(book_id: int, changes: BookPatch) -> Book:
    stored = DB.get(book_id)
    if stored is None:
        raise HTTPException(404, "Book not found")
    data = changes.model_dump(exclude_unset=True)       # only what the client actually sent
    DB[book_id] = stored.model_copy(update=data)
    return DB[book_id]


@app.get("/encoded/{book_id}")
def encoded(book_id: int) -> dict:
    return jsonable_encoder(DB[book_id])

Pitfalls

from fastapi.testclient import TestClient

class Book(BaseModel):

    series_no: int | None = Field(default=None, alias="seriesNo")


@app.post("/books")
def create(book: Book) -> dict:
    return book.model_dump(by_alias=True)


@app.post("/free")
def free(payload: Annotated[dict[str, Any], Body()]) -> dict:
    return {"keys": sorted(payload)}


@app.post("/numbers")
def numbers(values: Annotated[list[int], Body(min_length=1, max_length=3)]) -> dict:

# Content-Type: missing header on a JSON body (strict_content_type is on by default since 0.132.0)

print(r.status_code, r.json())
r = c.post("/books", content=json.dumps({"title": "Dune"}), headers={"Content-Type": "application/json; charset=utf-8"})

r = c.post("/books", content=json.dumps({"title": "Dune"}), headers={"Content-Type": "application/vnd.api+json"})
print(r.status_code)
print(c.post("/free", json={"a": 1, "b": [1]}).json())
print(c.post("/numbers", json=[1, 2, 3]).json(), c.post("/numbers", json=[]).json()["detail"][0]["type"])
print(c.request("GET", "/books", json={"title": "x"}).status_code)
print(c.get("/openapi.json").json()["paths"]["/books"].keys())

Source: FastAPI: Request Body

  • Body sent without a JSON Content-Type. Since FastAPI 0.132.0 (2026-02-23) the content type is checked strictly. A request whose body is valid JSON but arrives with no Content-Type header (the call made with content= and no headers in the example) is treated as plain text and gets 422 with model_attributes_type and the raw text as input; application/json; charset=utf-8 and application/vnd.api+json both worked. Tell clients to set the header (curl with -d and no -H sends application/x-www-form-urlencoded, which is a different body type). Passing strict_content_type=False to FastAPI(…​) restores the old lenient behaviour.

  • Typos silently ignored. The default is extra="ignore", so "titel" is dropped and the required title is reported missing, or an optional misspelled field is silently lost. For write endpoints consider model_config = ConfigDict(extra="forbid"): the first call returned extra_forbidden with loc ["body", "color"].

  • Aliases. With Field(alias="seriesNo") the client must send seriesNo; series_no returned 422. Use model_dump(by_alias=True) to produce the same names again. Details in the Pydantic page.

  • A body on GET. The specification does not define semantics for a GET body; many proxies and clients drop it and OpenAPI tooling may ignore it. Send search criteria as query parameters, or as a query parameter model (see Query Parameters), or use POST for a search that needs a body.

  • Bodies are read fully before the handler runs. A huge JSON document is parsed in memory. Limit the size at the server or proxy (see Middleware, CORS & Proxies) and prefer streaming or file uploads for large data.

  • Mutable defaults are safe in Pydantic (tags: list[str] = [] is copied per instance, as the run showed with a fresh []), unlike in ordinary classes and function signatures, but default_factory states the intent more clearly.

  • Optional[X] without a default is required. Write x: X | None = None for "may be omitted".

  • model_copy(update=…​) skips validation (see Updating Data: PUT Replaces, PATCH Merges), and model_dump() returns Python objects (such as datetime), not JSON-safe values: use model_dump(mode="json") or jsonable_encoder before storing.

  • A bare dict or Any body (Annotated[dict[str, Any], Body()]) accepts anything and documents nothing; use it only for genuinely free-form data. The run accepted {"a": 1, "b": [1]} and reported only the keys.

  • List bodies need a Body() or a top-level type. Annotated[list[int], Body(min_length=1, max_length=3)] accepts a JSON array; an empty array failed with too_short.

Where Older Guides Are Outdated, and What Changed Recently

  • Pydantic v1 code. v1 support was removed in FastAPI 0.126.0 (2025-12-20) and pydantic.v1 in 0.128.0 (2025-12-27). Replace .dict() with model_dump(), .copy(update=…​) with model_copy(update=…​), .json() with model_dump_json(), class Config: with model_config, schema_extra with json_schema_extra, min_items / max_items with min_length / max_length, regex= with pattern=, and Field(…​) for "required" with simply no default. The complete mapping is in Pydantic v2 Essentials.

  • Error format. v2 error payloads use short type values (missing, int_parsing, string_too_short) and input; v1 used value_error.missing and similar.

  • Optional[X] and default markers. Use X | None and Annotated[X, Body(…​)] (0.95.0 and later) instead of item: Item = Body(…​, embed=True).

  • Examples. Body(example=…​) is deprecated; use examples=[…​], and openapi_examples (0.103.0, 2023-08-26) for named, documented examples. Older tutorials use a plain dict for examples=.

  • Models for Query, Header, Cookie and Form. Since 0.115.0 (2024-09-17) and 0.113.0 (2024-09-05) the same BaseModel technique used for bodies also works for other parameter sources; see Query Parameters, Headers & Cookies and Forms & File Uploads.

  • Strict content type. 0.132.0 (2026-02-23) made the JSON Content-Type requirement strict (see Pitfalls).

  • Base64 bytes. Documented in the advanced guide as val_json_bytes / ser_json_bytes.

  • Rust-side JSON serialization. Since 0.130.0 (2026-02-22) responses with a return type or response_model are serialized directly by Pydantic, which is faster; see Response Models & Return Types.
