Python FastAPI

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This section is written against FastAPI 0.142.2 (released 2026-09-30), Pydantic 2.13 and Starlette 1.7, checked on 2026-10-02. FastAPI supports Python 3.10 through 3.14. FastAPI is still a 0.x project, so every page notes the version in which a feature appeared and the guide recommends pinning the version you deploy.

What FastAPI is

FastAPI is a Python web framework for building HTTP APIs. It is deliberately thin: Starlette provides the ASGI toolkit (routing, middleware, requests and responses, WebSockets, background tasks, the test client), Pydantic provides validation, serialization and JSON Schema, and FastAPI adds what ties them together: parameters declared with ordinary Python type hints, a dependency injection system, and automatic generation of an OpenAPI 3.1 description with interactive documentation (Swagger UI and ReDoc).

The practical result is that one declaration does several jobs at once. A function signature such as def read_book(book_id: int) converts the path value to an integer, rejects bad input with a structured 422 error, documents the parameter in /docs, and gives your editor full autocompletion.

This section is for developers who:

  • know Python (or are coming from Flask, Django, Spring Boot, ASP.NET Core or Express) and want to build and run production-grade JSON APIs

  • want one coherent path from a first endpoint to testing, security, data access, deployment and observability

  • need the current idioms (Annotated, Pydantic v2, lifespan, the fastapi CLI, PyJWT and pwdlib) rather than the patterns found in older tutorials

Reading path

The pages are ordered so that each one builds on the previous ones. Read them in this order the first time, then use them as a reference:

  1. Foundations: what FastAPI is made of, a first running app, the Python typing and async concepts it relies on.

  2. Request data: path and query parameters, bodies and Pydantic models, headers, cookies, forms and uploads.

  3. Responses and errors: response models, status codes, error handling, custom and streamed responses.

  4. Dependencies: dependency injection and dependencies with yield.

  5. Security: authentication fundamentals, OAuth2 with JWT, scopes, CORS and proxy headers.

  6. Data and application structure: SQL with SQLModel, other data stores, layered project layout, settings and lifespan.

  7. OpenAPI: the generated contract and how to shape it.

  8. Real-time and web: WebSockets, static files, templates, front ends, sub-applications.

  9. Testing: TestClient, dependency overrides, property-based and load testing.

  10. Production: servers and workers, containers, performance and observability.

  11. Beyond the basics: serving data-science and AI workloads, and what changed between versions.

The Bookshelf API scenario

Every example builds one small original service, the Bookshelf API, so the pages fit together instead of being isolated snippets:

  • books, authors and reviews resources with full CRUD

  • users with OAuth2 password login, JWT access tokens and scopes

  • cover-image uploads

  • a live "new review" feed over Server-Sent Events

  • a WebSocket chat per book

  • a Jinja and single-page-application front end

  • PostgreSQL through SQLModel in production and SQLite in tests
