Period-End Closing

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

When a month ends, the books are not finished. Some costs have arrived in the business but not yet as an invoice, some amounts are still valued at an old exchange rate, some goods are in the warehouse without a matching invoice, and some costs sit on the wrong department. Period-end closing is the set of steps a finance team runs, in a fixed order, to put those things right so that the figures for the period can be reported and then frozen. A newcomer meets it in the first week of a project, because the first question after "can we post?" is "can we close?". After reading this page you can name the main closing steps, say which SAP tool performs each one, work out a foreign currency valuation difference by hand, and explain the difference between the Financial Closing cockpit and Advanced Financial Closing. The page is written for SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608. The classic closing programs and the Accruals Management pages are cited from the on-premise documentation; the Accounting Accruals Agent is a Public Edition feature.

Before you read

  • Fiscal Year Variants and Posting Periods: what a posting period is and how a period is opened and closed, the last step of this page.

  • Accounting Basics: debit and credit, and why an accrual exists.

  • Ledgers and Currencies: the company code currency and the parallel currencies that a valuation can use.

  • Allocations: Assessment, Distribution and Activity Allocation: the Controlling step in the close.

Key terms

  • Period-end closing: the ordered set of periodic activities that correct and complete the books of a period before they are frozen.

  • Accrual: recording a cost or revenue in the period it belongs to, even if the invoice or the cash comes later.

  • Key date: the date on which a closing run evaluates the data, usually the last day of the period.

  • Foreign currency valuation: revaluing foreign currency balances and open items at the exchange rate of the key date.

  • GR/IR clearing account: the account that holds goods received that are not yet invoiced, and the reverse.

  • Financial Closing cockpit: the task-list tool delivered with SAP S/4HANA that plans, runs and monitors closing tasks.

  • Advanced Financial Closing: SAP’s separately licensed closing solution that runs closing task lists across systems.

What period-end closing is

SAP Help groups the closing work of General Ledger Accounting under the heading "Closing Operations" and lists these functions: check and count (reconciling the receivables and payables between companies of a group), valuate, regroup, allocation, carry forward and value adjustment. The page speaks of processes performed at the end of the fiscal year, but most of them also run every month, so a team normally rehearses them each period and adds the year-end steps in the last one. Controlling has its own period-end closing, which SAP Help describes as the period-related business transactions executed after the period end.

Source: SAP Help: Closing Operations (on premise 2025 FPS02) and SAP Help: Overview: Period-End Closing (Cost Center Accounting)

Accruals

An accrual books a cost in the right period when the invoice has not arrived. Example Trading Co. (company code EX01, leading ledger 0L) receives electricity throughout December 2026 and expects an invoice of EUR 1,200.00 in January. An accrual of EUR 1,200.00 puts the cost into December: the expense account is debited and an accrued liabilities account is credited. SAP’s Accruals Management does the calculating and posting for you instead of a hand-made journal entry.

SAP Help describes it in these terms. Accruals Management offers functions for calculating, checking and posting accruals, and it builds on the accrual engine. It has components for manual accruals (you enter or load the data of the transaction), purchase order accruals (the data comes from Materials Management and is converted into accrual objects) and service entry sheet accruals (based on the amounts of unapproved service entry sheets). The system calculates the amounts at the end of the period, and it can adjust them when related postings arrive: actual costs, such as an invoice, reduce, or utilize, the accrual, and amounts that are no longer needed can be released. A check and approval procedure can be added so that proposed amounts are reviewed before posting.

Posting happens in a periodic posting run. SAP Help says that you always start the run manually for a specific key date, that the update run creates the line items in the posting document and that the accrual is saved at least in the transaction currency. A posting can be reversed in the accrual object, but SAP Help warns that this is an inverse posting and not a true reversal, so choosing the action several times creates several inverse postings.

When the January invoice for EUR 1,150.00 arrives, it uses up EUR 1,150.00 of the accrual, and the remaining EUR 50.00 can be released. The calculation is simple, 1,200.00 - 1,150.00 = 50.00; what the system posts for utilization and release depends on the posting schema and account determination of the accrual item type, which are Customizing settings.

The Accounting Accruals Agent

The Public Edition documentation describes the Accounting Accruals Agent as a feature that uses agentic AI to automate the preparation of manual accruals during month-end closing. It reads the accounting policies to find the calculation method, retrieves historical data, calculates the amounts and prepares the accrual journal entries, which you then manage as accrual proposals. The page adds that using the feature may need additional entitlements and that it is available only if SAP S/4HANA Cloud Public Edition is integrated with Joule. The documentation page used for this summary was read in a machine-translated Spanish version, so check the English wording before relying on a detail. See Joule and Business AI for the assistant itself.

Source: SAP Help: Accruals Management (on premise 2025 FPS02), SAP Help: Periodic Posting Run and SAP Help: Accounting Accruals Agent Overview (Public Edition 2608)

Foreign currency valuation

Example Trading Co. keeps its books in euros. It invoices a customer in pounds sterling and owes a supplier in pounds. Both items stay open over the year end. While they are open, the exchange rate moves, so the euro value of the items is no longer what it was when they were posted. Foreign currency valuation re-expresses them at the rate of the key date and books the difference, so that the balance sheet shows the right euro amounts.

SAP Help says the valuation covers foreign currency balance sheet accounts (the balances of accounts not managed on an open item basis) and open items posted in a foreign currency that are still open on the key date. You can value in the local currency or in a parallel currency, such as a group currency, and you can use different valuation methods, for example the lowest value principle. When additional currencies are translated from the local currency, valuation performs the currency translation in line with FASB 52 (US GAAP). One rule matters in practice: you can run a valuation only once for a valuation area and a specific key date.

The valuation difference in numbers

Write for the amount in the foreign currency, for the rate at which the item was booked and for the rate on the key date. The rates here are quoted as pounds per euro, so a euro amount is the pound amount divided by the rate. The valuation difference is the euro value at the key date minus the euro value at booking:

For an asset such as a receivable, a positive is a gain; for a liability such as a payable, a positive is a loss, because the euro amount owed has grown. GR/IR regrouping

When goods arrive before the invoice, the goods receipt credits the GR/IR clearing account; the invoice later clears it. The worked example is on the page about account determination. At the key date some items are still uncleared: goods received and not invoiced leave a credit balance, an invoice entered before the goods leaves a debit balance. Both are open obligations that a balance sheet should not hide inside one net figure.

SAP Help states that before you create the balance sheet you can analyze the GR/IR clearing account and perform any necessary correction postings. The documented path is Periodic Processing, Closing, Regroup, GR/IR Clearing in General Ledger Accounting. On the selection screen you fill the parameters; when you post acquisition tax you must give an interim account and an input tax code, and you can set the document type and the output specifications. You then choose the execution method under Program. The page does not describe the adjustment postings in detail, so how an item is shown on the balance sheet follows your accounting policy and the program documentation in the system.

The documentation for newer releases also lists apps and functions for reconciling GR/IR accounts, among them Reconcile GR/IR Accounts and an intelligent GR/IR reconciliation. They are named in the table of contents only and were not read for this page.

Source: SAP Help: Regrouping the GR/IR Clearing Account (on premise 2025 FPS02)

Regrouping receivables and payables

Before the financial statements, receivables and payables are ordered by remaining term so that they appear correctly. SAP Help lists the cases that need adjustment postings: a customer account in credit, which cannot be shown as a receivable and must appear as a payable; a vendor account in debit, which must appear as a receivable; a changed reconciliation account, where items posted to the old account move to the new one; and, in some countries such as France, investments that must be shown separately. The report is SAPF100. It analyzes all accounts managed on an open item basis (foreign currency items always, local currency items only if they carry a due date) and posts the transfer and adjustment postings for each G/L account, business area and currency. The menu path is Accounting, Financial Accounting, Accounts Receivable or Accounts Payable, Periodic Processing, Closing, Regroup, Receivables/Payables.

A small example: the customer account of an Example Trading Co. customer shows a credit balance of EUR 300.00 because of an advance payment. The customer is a net creditor for that amount, so the report moves EUR 300.00 out of the receivables total and into payables; the total of receivables falls by 300.00 and the total of payables rises by 300.00. The balance of the customer account itself is unchanged. This describes the purpose stated in SAP Help; it was not run here.

Source: SAP Help: Transferring and Sorting Receivables and Payables (on premise 2025 FPS02)

Allocations and settlement

Controlling closes its own books on top of Financial Accounting. SAP Help lists these Cost Center Accounting steps: periodic reposting, accrual cost calculation, transfer of statistical key figures, overhead calculation, periodic allocations (distribution, assessment, indirect activity allocation, target equals actual activity allocation and template allocation), variance calculation, predistribution of fixed costs and actual price calculation. The Schedule Manager helps to carry out and check the closing. For internal orders, SAP Help lists revaluation at actual prices, calculating overheads, periodic reposting, template allocation, internal order settlement, and the assessment and distribution methods.

Allocation is covered on its own page, Allocations, with a rent example for three cost centers. Settlement passes the costs collected on an order to the receivers of that order at period end; the page Cost Centers and Internal Orders explains the objects. The Public Edition uses projects instead of internal orders for this kind of collecting object.

The order matters in the close. Allocations should run after all costs have been posted and accrued, because they spread what is on the sender at the moment the cycle runs; settlement and variance calculation follow, and finance reviews the result before the period is closed.

Source: SAP Help: Overview: Period-End Closing (Cost Center Accounting) and SAP Help: Period-End Closing (Internal Orders)

Closing the periods

The last step of a close is to stop postings. A period stays open or closed according to the posting period variant of the company code, so the closing lead closes period 012 after the final review and opens period 001 of the next year. A special period (013 to 016) can stay open for year-end adjustments after the regular periods are closed. All of this is explained, with the Manage Posting Periods app, on Fiscal Year Variants and Posting Periods.

At the year end, balance carryforward carries the account balances into the new fiscal year. SAP Help describes it as a function of closing operations; its documentation lists a Generate Balance Carryforward Distribution topic and a retained earnings transfer at year end, which this page does not cover.

Source: SAP Help: Closing Operations (on premise 2025 FPS02)

Financial Closing cockpit and Advanced Financial Closing

A real close has dozens of tasks and many people. A spreadsheet of tasks soon fails: nobody knows what is done, and dependencies are in people’s heads. SAP offers two tools.

The SAP S/4HANA Financial Closing cockpit is part of the software component S4CORE and is delivered with SAP S/4HANA. SAP Help lists these cases for it: activities recur periodically, several people are involved, the activities follow a fixed or dependency-driven sequence, a shared interface helps and the status of every periodic activity has to be visible. It organizes closing activities by event, gives an overview with monitoring and offers analysis tools. Its building blocks are hierarchies of the organizational objects, templates that reflect the organization, task lists derived from templates, a monitor with critical paths and a Gantt diagram, dependencies between tasks and connections to external schedulers through the Business Automation Enabler (BAE). Tasks can also run in remote systems as remote transactions, programs or jobs. You can use it in SAP GUI or in the SAP Fiori Launchpad.

SAP Advanced Financial Closing (AFC) is the other tool. The SAP Help page on integration with Advanced Financial Closing states that the use of SAP Advanced Financial Closing requires an additional license. The page shows that a job such as the intercompany matching run is available as a closing task in AFC, which you add to a task template with the Manage Closing Task Lists app and then schedule or run in Process Closing Tasks. The cockpit is therefore the closing tool that comes with S/4HANA, while AFC is a separately licensed product. Which one a company uses depends on its landscape and its license; this page does not compare their features beyond what the cited pages state.

Source: SAP Help: SAP S/4HANA Financial Closing (on premise 2025 FPS02) and SAP Help: Integration with Advanced Financial Closing

What older books show, and what has changed

The book Configuring SAP S/4HANA Finance, 3rd edition (2025), covers foreign currency valuation, regrouping and the Financial Closing cockpit in its chapter on closing operations, including the automatic posting accounts that the valuation needs. Its menu paths match the ones in this page. The book SAP S/4HANA Financial Accounting Configuration, 2nd edition (2023), spends separate chapters on foreign currency valuation settings and on GR/IR clearing, and still words some passages for SAP R/3. Two things in the current documentation go beyond what these books explain: the Accounting Accruals Agent of the Public Edition, which is new, and the extra apps for GR/IR reconciliation. A reader of either book should treat the programs and menu paths as correct for the on-premise product and check the current Public Edition documentation for the app-based equivalents.

Common errors and pitfalls

Pitfall What to do

A valuation run is started twice for the same key date.

SAP Help allows one run per valuation area and key date. Check the result list before starting another run.

An accrual is reversed more than once.

The Reverse action posts an inverse amount each time. Use it once and check the postings.

Valuation runs before the last invoices are posted.

Post and clear first, then value, so that the key date balances are complete.

Accounts for exchange rate differences are missing.

Define the expense, revenue and adjustment accounts in the Customizing for the automatic postings before the run.

Allocations run before accruals.

Post the accruals first, so that the sender holds all its costs when the cycle runs.

The period is closed while the cockpit shows open tasks.

Close the period only after the closing lead has checked the task list status.

Summary

  • Period-end closing is an ordered set of steps: accruals, foreign currency valuation, regrouping, allocations and settlement, review, closing the period and, at the year end, balance carryforward.

  • Accruals Management calculates and posts accruals in a periodic run for a key date; in the Public Edition the Accounting Accruals Agent helps to prepare manual accruals.

  • A foreign currency valuation difference is for rates quoted as foreign currency per euro; the sign and the item type tell gain or loss. In the example, EUR 625.00 gain and EUR 312.50 loss.

  • GR/IR and receivables and payables regrouping make the balance sheet show the right terms and sides; Controlling allocates and settles on top.

  • The Financial Closing cockpit comes with S/4HANA; Advanced Financial Closing requires an additional license.
