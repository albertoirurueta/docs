Ledgers, Currencies and Exchange Rates

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A company that trades across borders has two bookkeeping problems that a single set of books cannot solve. First, different audiences want different answers from the same business: the tax office wants the local rules, the parent company wants group rules, and the two can value the same stock or the same receivable differently. Second, the same invoice is written in one currency but must be reported in others. SAP S/4HANA solves the first problem with ledgers, each a complete set of books for one accounting principle, and the second with currency types and exchange rates, so that every posting is stored in several currencies at the moment it is made. This page explains both, how they combine in parallel accounting, and the arithmetic of translating an amount, including the difference between a direct and an indirect rate. It is written against SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608. The concepts are shared; the settings differ in where they are made and in some limits, which the page names.

Before you read

  • Organizational Structures: what a company code is, because ledgers and currencies are set for each company code.

  • Customizing and the Implementation Guide: where the configuration paths on this page (the SPRO menu) are found.

  • The sibling page on the fiscal year variants and posting periods (Fiscal Year Variants and Posting Periods) matters because each ledger can have its own.

Key terms

  • Ledger: a complete set of books in General Ledger Accounting, kept for one accounting principle.

  • Leading ledger: the one ledger that is updated in every company code and that feeds Controlling; 0L in the standard system.

  • Non-leading ledger: a parallel ledger activated for the company codes that need another accounting principle.

  • Extension ledger: a ledger that reads through to an underlying ledger and stores only its own manual adjustments.

  • Ledger group: a named combination of ledgers that a posting or a closing step can address together.

  • Accounting principle: a set of valuation rules such as IFRS, US GAAP or a local standard.

  • Parallel accounting: keeping the books under more than one accounting principle at the same time.

  • Currency type: the purpose of a currency in a ledger, such as company code currency or group currency, with its translation settings.

  • Exchange rate type: a key that separates rates of the same currency pair by purpose; type M is the average rate used for posting and clearing.

  • Direct quotation: a rate written as units of the To currency for one unit of the From currency.

  • Indirect quotation: the same rate written the other way round, as units of the From currency for one unit of the To currency.

The running example: Example Trading Co.

This site uses one fictitious business, Example Trading Co., with company code EX01. For this page, EX01 keeps its books in euro (EUR), reports to a parent that consolidates in British pounds (GBP), and buys from a supplier that invoices in US dollars (USD). It has a leading ledger 0L, which holds the group accounting principle, and one non-leading ledger 2L for the local principle. The keys, currencies and rates are illustrative values chosen for this site, not SAP defaults or market rates. The same company code serves the rest of the Finance pages.

Ledgers

What a ledger is

A ledger is the central repository for accounting data in General Ledger Accounting. Each ledger is a complete set of books: SAP states that the leading ledger and the non-leading ledgers each contain the complete set of document items in the Universal Journal table ACDOCA (see the sibling page on the Universal Journal). A posting that has no valuation difference is therefore written to every ledger of the company code, and only the valuation postings differ between them. When you create a ledger, the system also creates a ledger group with the same name.

You define ledgers in Customizing under Financial Accounting, Financial Accounting Global Settings, Ledgers, Ledger, in the activity Define Settings for Ledgers and Currency Types (transaction FINSC_LEDGER).

Sources: Ledger (SAP Help Portal, on premise), Configuring Ledgers (SAP Help Portal, on premise)

The kinds of ledger

Kind What it is Rules stated by SAP

Leading ledger

The one ledger you must designate as leading; 0L in the standard system.

Assigned to every company code. Its document numbers apply to all dependent ledgers. It is integrated with Controlling, so the CO actual data is essentially the leading ledger. In each company code it takes the currencies, fiscal year variant and posting period variant of that company code.

Non-leading ledger

A parallel ledger, for example for a local accounting principle.

Activated company code by company code. It can have a different fiscal year variant and posting period variant from the leading ledger.

Extension ledger

A ledger built on an underlying ledger, either a standard ledger or another extension ledger.

Postings to the underlying ledger also apply to it without storing them twice, so only manual postings made directly in the extension ledger are physically stored; automatic postings are not possible. The currency settings and the fiscal year variant cannot differ from the underlying ledger. It is useful for a management view without touching the underlying data.

Day ledger

A ledger for reports of average daily balances.

Cannot be the leading ledger or the representative ledger of a ledger group.

Two rules matter to a newcomer. Postings to subledger accounts or to G/L accounts managed on an open item basis always affect all ledgers, so you cannot make ledger-specific postings to them. And if you use only the account approach to parallel accounting (next section), one ledger is enough, and it is automatically the leading ledger.

SAP gives this example: consolidated statements follow IFRS, while individual company codes apply US GAAP or German HGB. The system then has leading ledger 0L with the group principle, a non-leading ledger L1 activated for the company codes that apply US GAAP, and a non-leading ledger L2 activated for those that apply HGB.

Source: Ledger (SAP Help Portal, on premise)

Ledger groups

A ledger group combines any number of standard ledgers so that a function can address them together, for example one posting entered once and written to several ledgers. Each ledger is also created automatically as a ledger group of the same name, so an individual ledger can be processed on its own. If you enter no ledger group, processing runs for all ledgers, so you do not need a ledger group for "all". Extension ledgers cannot be members of a ledger group: each has only the automatic group of its own name, and the system posts to it whenever its underlying ledger is posted.

Every ledger group has a representative ledger. The system normally uses it to find the posting period and to check that the period is open, then posts to the other ledgers of the group with each ledger’s own fiscal year variant. If the group contains the leading ledger, the leading ledger must be the representative ledger. When the representative ledger’s period is open, the posting reaches the other ledgers even if their own periods are closed, unless you choose the alternative of using the periods of the non-representative ledgers.

The figure shows the two routes of a posting in the running example. A normal posting reaches both 0L and 2L. A manual valuation posting entered for the ledger group 2L reaches only that ledger. Whatever lands in 2L also shows in an extension ledger built on it, because the extension ledger reads through to its underlying ledger.

For manual postings that belong to one ledger only, SAP recommends a separate document type, and the entry screen is on the SAP Easy Access menu under Accounting, Financial Accounting, General Ledger, Posting, Enter General Posting for Ledger Group. Automatic valuations, such as the foreign currency valuation, carry the accounting principle, and the system finds the ledger group through the accounting principle assigned in Customizing.

Sources: Ledger Group (SAP Help Portal, on premise), Portrayal Using Parallel Ledgers (SAP Help Portal, on premise)

Parallel accounting: the ledger approach and the account approach

Parallel accounting means keeping the books under more than one accounting principle. SAP describes two ways to do it in General Ledger Accounting.

  • The ledger approach gives each accounting principle its own ledger. SAP recommends it. Its advantages are that each company code manages a separate ledger per principle, standard reporting works for all ledgers, different fiscal year variants are possible and the number of G/L accounts stays manageable. Its disadvantage is a larger data volume.

  • The account approach keeps several principles in one ledger and separates their values by using additional accounts. SAP recommends the ledger approach unless the number of G/L accounts would become unmanageable with the account approach. To use several principles in one ledger you select the Parallel Accounting Using G/L Accounts checkbox in the company code settings of the ledger.

The ledger approach rests on the assignment of accounting principles to ledgers and company codes. One accounting principle can be assigned to a ledger and company code, and you should not assign the same principle to different ledgers across several company codes. The same ledger can serve different principles at company code level, which lets one ledger bundle the local principles of several countries.

Postings can come from several components: Financial Accounting, Asset Accounting, Treasury and Risk Management, Controlling and Materials Management. Reporting works through drilldown reports, Report Writer and Report Painter reports, and the report Financial Statements (RFBILA00) for all ledgers. The setup of the parallel ledgers in Asset Accounting (depreciation areas) is a separate topic outside this page.

SAP describes a further, related capability, Universal Parallel Accounting, that extends ledger-specific valuation to Asset Accounting, Controlling and the Material Ledger; it has its own page in this section.

Sources: Portrayal Using Parallel Ledgers (SAP Help Portal, on premise), Configuring Ledgers (SAP Help Portal, on premise)

Currencies in the books

Currency types

An invoice carries amounts in its own currency, but the books must also hold the amounts that other audiences need. SAP separates the two ideas. The externally given currencies are the document, transaction and item currencies, for example the currency printed on the invoice. The other currencies are managed in parallel in the Universal Journal: they are configured as currency types and are translated while the posting is made, not later in a report. Translating at posting time keeps every document at a zero balance in every currency, in clearing and in reversal as well.

A currency type gets an actual currency code (USD, EUR) and a translation method. For a currency type you define the exchange rate type, the date for the translation and the source currency to translate from. The standard currency types are:

Key Currency type Where its currency is defined, and what to know

00

Document currency

The currency in which a document is posted. Cannot be changed.

10

Company code currency

Defined in the company code; every company code needs one. It must be the national currency of the company code, so that indirect tax and withholding tax reporting work. Cannot be changed.

20

Controlling area currency

Defined in the controlling area, used in cost accounting. SAP recommends setting the group currency (30) in the controlling area instead, so that consolidated reporting has one currency that all FI processes support.

30

Group currency

Defined for the client; used for consolidated statements.

40

Hard currency

A country-specific second currency for high-inflation countries, defined for the country of the company code.

50

Index-based currency

A fictitious reference currency for high-inflation countries, defined for the country of the company code.

60

Global company currency

Used for an internal trading partner; defined for the company assigned to the company code.

70

CO object currency

The currency in the master record of a CO object such as a cost center. Like the document currency, it is not a translated currency and need not balance to zero. Cannot be changed.

Y*, Z*

Freely definable currency types

Your own, for a specific purpose, created in the Define Settings for Ledgers and Currency Types activity.

For a freely definable type you enter the currency to translate into, the source currency, the exchange rate type and the date of the translation (document date, posting date or translation date). You can also choose real-time translation; without it, the translation can be done at period-end closing with the foreign currency translation run. For each additional type you decide whether its settings are valid for all company codes or per company code.

Typical uses are individual statements in the company code currency, consolidated statements, statements in a hard or index-based currency for high-inflation countries, statements in a functional currency, statements at constant exchange rates and views for transfer prices. The functional currency is the currency of the primary economic environment of the company; it must be a currency delivered by SAP (types 10, 30, 40, 50 or 60) and must be set for the leading ledger at company code level before the company code is used productively.

How many currencies, and where the limits differ

On premise, the help page on currency types states that besides the company code currency and the global company currency you can manage up to eight other currency types per ledger and company code, so up to ten currencies in all. The Universal Journal FAQ counts the ten differently: it says the Universal Journal handles up to 10 currency fields, of which two are preconfigured (the company code currency and the controlling area currency, which cannot be changed) and eight are freely definable. Both statements give ten; they name the fixed pair differently, so read the table above as the list of currency types and the settings screens of your release as the authority. The ledger topic of the same help set describes the second and third currency of the leading ledger. In SAP S/4HANA Cloud Public Edition the limit is lower: you can represent valuations in your local currency and two additional parallel currencies, and the currencies of the leading ledger determine the currencies of all parallel ledgers. SAP’s Public Edition example is a German subsidiary of an American group with EUR as company code currency (type 10), USD as group currency (type 30) and GBP as a freely defined currency (type Z0), the same in both ledgers.

On premise, two restrictions apply: you cannot change the currency and fiscal year variant settings of a ledger and company code that already have postings, and a new currency type must not be added to a ledger and company code combination in productive use.

Sources: Currencies Managed in Parallel in the Universal Journal (SAP Help Portal, on premise), Parallel Accounting and Currencies (SAP Help Portal, Public Edition)

Exchange rates and exchange rate types

An exchange rate is the relationship between two currencies and is used to translate an amount into another currency. SAP lists these purposes: posting and clearing, determining gains and losses from exchange rate differences, and valuing open items in foreign currency and foreign currency balance sheet accounts at closing. Rates are defined at client level, so they apply to all company codes.

Because the same currency pair needs different rates for different purposes, each rate carries an exchange rate type. SAP names the purposes valuation, conversion, translation and planning, and the types buying rate, bank selling rate, average rate, historical exchange rate and key date exchange rate. Type M, the average rate, has a special role: for posting and clearing the system uses type M, so it must exist and rates must be entered for it. Each rate also has a validity date, the date from which it applies, and a ratio, for example ITL/EUR was entered as 1000:1. Not every rate must be typed in: you choose per type a tool such as inversion, reference currency or exchange rate spread to derive others. Inversion is not permitted for type M, because the inverted rate would not be precise enough.

Setting On premise 2025 FPS02 (SPRO) Public Edition 2608

Check exchange rate types

General Settings, Currencies, Check Exchange Rate Types

The configuration activity Check Exchange Rate Types in the Configure Your Solution app of Manage Your Solution.

Enter and maintain rates

General Settings, Currencies, Enter Exchange Rates

The Currency Exchange Rates app (app ID F3616).

Direct or indirect as standard

General Settings, Currencies, Define Standard Quotation for Exchange Rates

The configuration activity Define Standard Quotation for Exchange Rates under Finance, General Settings, Currencies.

Requires an SAP system; not run here.

Sources: Exchange Rates (SAP Help Portal, on premise), Exchange Rate Type (SAP Help Portal, on premise), Currency Exchange Rates app (SAP Help Portal, Public Edition)

Direct and indirect quotation, and the translation formula

A rate between two currencies can be written in two ways, and the market convention for a pair is not an international standard. In the Currency Exchange Rates app, SAP defines them this way. The direct rate is the cost of one unit of the From currency given in units of the To currency; the indirect rate is the cost of one unit of the To currency given in units of the From currency. SAP’s own example is USD to EUR: the direct rate 0.80 means USD 1 equals EUR 0.80, and the indirect rate 1.25 means EUR 1 equals USD 1.25. The two are reciprocals.

In words: with a direct rate you multiply, with an indirect rate you divide. Reading the pair the wrong way is the classic mistake, because the result is then wrong by a large factor, not by a rounding difference. A quick check helps: with USD 1 equal to EUR 0.80, the euro amount must be the smaller number. Where a ratio such as 1000:1 is entered, it scales the rate, and the system applies it for you.

Which form a given pair uses is a setting: the activity Define Standard Quotation for Exchange Rates chooses indirect or direct quotation as the standard for each currency pair. Currency pairs are displayed in the usual market form of base currency over quote currency.

Source: Direct and Indirect Exchange Rates (SAP Help Portal, on premise)

Setting up ledgers

The ledger configuration is a sequence that SAP lists for the on-premise system and, in a different form, for the Public Edition.

Step On premise 2025 FPS02 (SPRO) Public Edition 2608

Create ledgers

Financial Accounting Global Settings, Ledgers, Ledger, Define Settings for Ledgers and Currency Types (FINSC_LEDGER); a leading ledger is required, others are standard or extension ledgers.

Ledgers are chosen when scoping the system, in SAP Central Business Configuration: 0L alone, 0L with 2L (IFRS by default) or 3L (US GAAP by default), three parallel ledgers in exceptional cases, and an optional group valuation ledger 4G. Ledgers cannot be added or removed after scoping.

Assign company codes, currencies and periods

The Company Code Settings for Ledgers view of the same activity: currency types, fiscal year variant and open period variant.

Assign Fiscal Year Variant to Ledgers and Company Codes. An alternative fiscal year variant cannot be assigned to the leading ledger.

Assign accounting principles

The Accounting Principle for Ledger and Company Code view, or the Parallel Accounting Using G/L Accounts indicator for the account approach.

Assign Accounting Principles to Ledgers and Company Codes, before the first posting.

Extension ledgers

Created in the ledger activity on top of a standard or extension ledger.

Define Extension Ledger; the accounting principle, fiscal year variant and currency types are inherited.

Ledger groups

Financial Accounting Global Settings, Ledgers, Ledger, Define Ledger Group.

The Public Edition help describes the ledger groups through the CDS view I_LedgerGroup, not as a configuration step.

On premise, SAP recommends one ledger per accounting principle, with the accounting principle for a ledger and company code view used only for the account approach. In the Public Edition, a closing activity such as settlement, depreciation or allocation has to be run for every activated ledger, because there is no automatic update to parallel ledgers.

Requires an SAP system; not run here.

Sources: Making Settings for Ledgers (SAP Help Portal, on premise), Configuring Ledgers (SAP Help Portal, on premise), Ledger Scenarios: Choosing the Right Combination for Your Business Needs (SAP Help Portal, Public Edition), Ledger Group (CDS view, SAP Help Portal, Public Edition)

What older books show, and what has changed

Stoil Jotev’s Configuring SAP S/4HANA Finance (3rd edition, 2025) covers the same ground in its chapter on the financial accounting global settings: ledger setup with a leading ledger 0L and non-leading ledgers, ledger groups, currency types, exchange rate types and the direct and indirect methods, and it states up to ten parallel currencies per ledger. It shows the on-premise Customizing screens of S/4HANA 2023, so it does not show the Public Edition scoping of ledgers in Central Business Configuration, the two-extra-currency limit of the Public Edition, or the Currency Exchange Rates app. Andrew Okungbowa’s SAP S/4HANA Financial Accounting Configuration (2nd edition, 2023) is a step-by-step Customizing book of the same period and is outdated in the same way. Where the books and the SAP Help Portal pages above differ, the help pages win.

Summary

  • A ledger is a complete set of books. The leading ledger 0L is in every company code and feeds Controlling; non-leading ledgers carry other accounting principles; an extension ledger reads through to an underlying ledger and stores only its own manual postings.

  • A ledger group lets one posting or closing step address several ledgers; without a group, processing runs for all ledgers, and the representative ledger decides the posting period.

  • Parallel accounting is done with one ledger per principle (the ledger approach, recommended) or with several principles in one ledger using additional accounts (the account approach).

  • A currency type fixes the purpose of a currency in a ledger (company code, group, hard, index-based, freely defined); amounts are translated at posting time, so each document balances in every currency.

  • Exchange rates carry a rate type; type M is used for posting and clearing. With a direct rate you multiply, with the indirect rate you divide, and the two are reciprocals.

  • The Public Edition and the on-premise system differ in how ledgers are scoped, how many parallel currencies are allowed and where rates are maintained.
