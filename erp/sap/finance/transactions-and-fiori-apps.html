Finance Transactions and Fiori Apps

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

If you learned SAP Finance from older material, you know it by transaction codes: short names such as FB50 or F110 that you type into a box to open a screen. In current SAP S/4HANA the same jobs are often done in a web app on the SAP Fiori launchpad, and some of the old codes still work, some are redirected and some have been removed. This page is a lookup table that pairs the classic transaction codes of Financial Accounting and Controlling with their status and with the Fiori app (app ID and name) that covers the same task. It is written for SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608. Every row says where it was checked, and a row that could not be confirmed in an official source is marked as not confirmed instead of being guessed.

Before you read

  • Finance Overview: what Financial Accounting and Controlling are and how they connect.

  • Journal Entries, Document Types and Posting Keys: the first four transactions of the table (FB50, F-02, FB01, FBV1) are explained there in detail.

  • Accounts Payable and Accounts Receivable, Dunning and Credit: the invoice and payment rows.

Key terms

  • Transaction code: a short name, such as FB50, that opens one screen of the SAP GUI.

  • SAP GUI: the older desktop-style user interface of SAP systems, in which transaction codes are typed.

  • SAP Fiori app: a task-focused web application, started from a tile on the launchpad.

  • App ID: the identifier of an app in the SAP Fiori apps reference library, for example F0718.

  • SAP Fiori apps reference library: SAP’s public catalog of apps, with name, ID, release availability and technical data.

  • Feature comparison: a table in the SAP help that lists transactions and apps side by side with what each can do.

  • Simplification List: SAP’s list of what changed between SAP ERP and SAP S/4HANA, including transactions that are redirected or obsolete.

Two kinds of "app" and what a status means

A launchpad tile can start two quite different things, and the SAP Fiori apps reference library lists both.

  • A Fiori app is a web app built for the browser, with its own ID such as F0718 (Post General Journal Entries). It is the modern replacement for a group of old screens.

  • An SAP GUI app is an old transaction shown as a tile. Its library entry has the transaction code itself as the app ID and the type SAP GUI. For example, the library lists FB60 Create Incoming Invoices and FB70 Create Outgoing Invoices as SAP GUI apps, and the Public Edition help page for Create Outgoing Invoices says "App ID: FB70". So the phrase "the app FB70" and "the transaction FB70" name the same thing, and there is no separate Fiori successor in those two cases.

The status columns in the tables use these labels. They are deliberately about what an official page says, not about what a system does.

Label Meaning

Named in help

The on-premise 2025 FPS02 help names the transaction as a current way to do the task, or lists it next to the app in a feature comparison.

Library: SAP GUI app

The Fiori apps reference library has an SAP GUI entry with this ID for SAP S/4HANA 2025 FPS02 (on premise) or for SAP S/4HANA Cloud 2608 (Public Edition), so the transaction can be put on the launchpad. A missing entry is not proof that a transaction is gone: for KB21N the help names the transaction although the library has no entry for it.

Redirected or obsolete

Taken from an item of the Simplification List. These rows rest on the item as cited on the page Business Partners, Customers and Suppliers; the list itself was not reopened for this page.

Not confirmed

No official page read for this page states it. The row says what was and was not found.

What older books show, and what has changed

Two books on the reading list contain transaction tables. They are used here only as a checklist of codes to look up, and every code was then checked against the sources above.

The book Configuring SAP S/4HANA Finance, 3rd edition (2025), has an appendix of obsolete and new transaction codes. It lists, among others, the replacements FS01, FS02, FS03 by FS00; FK01, FK02, FK03 and FD01, FD02, FD03 by BP; CK11, CK13, CK41 to CK68 by CK11N, CK13N and CK40N; KB11, KB21, KB31, KB51 by their N versions; KE21 by KE21N; KKE1 to KKED by CKUC; F.05 by FAGL_FCV; and the interest codes F.24, F.2A, F.4A and relatives by FINT and FINTAP. The book Financial Accounting Configuration, 2nd edition (2023), has an appendix of "useful" codes, mostly Customizing transactions such as OB52, OBYC, FBZP, FBN1, OBA7 and the master record codes FD01 and FK01. Its list is a set of entry points, not a status table, and it still shows FD01 and FK01 as master record transactions.

How to check a code in your own system

Everything above reflects documentation. Your own system is the final judge, because the business functions and add-ons you have switched on change what is available.

  1. In the SAP GUI, type the transaction code into the command field. A redirected code opens the target screen, an obsolete one reports that the transaction does not exist. This step requires an SAP system; not run here.

  2. In the launchpad, search for the app name from the table and open its tile. The tile exists only if your user has the business role that contains it.

  3. In the SAP Fiori apps reference library, open the app’s entry, choose your release on the Implementation Information tab and read the Configuration section for the catalog and role that grant access. The classic library announces its successor at fal.cloud.sap; that address was not opened for this page.

  4. For a transaction that is not in the table, search the Simplification List for its code. Treat a blog or forum answer as a hint to verify, never as the statement.

Common mistakes

  • Treating "no library entry" as "obsolete". The library lists the SAP GUI transactions that were published as apps. KB21N and KS01 are named in the help yet have no entry.

  • Copying an app ID from memory. Many IDs differ by one letter between releases: the library has F0717A and F0717, F3425 and F3425A, F1443A and F1443B. The letter A or B often marks the Public Edition or a newer version.

  • Expecting one app per transaction. One app often covers several transactions (F1612 covers F-53 and F-48 on the Central Payment page), and one transaction can be split over several apps.

  • Assuming the app has every feature of the transaction. F2223 cannot work with extended open item management, FBRA can; F0718 cannot post payables, FB01 can.

  • Reading a Public Edition document with transaction codes in mind. The Public Edition help describes apps and configuration activities; most of the classic codes in this table have no SAP GUI entry for 2608.

Summary

  • A classic transaction code and a Fiori app are two doors to the same function; some "apps" are just old transactions with the code as their ID, such as FB60, FB70 and FBCJ.

  • For journal entries, invoices, payments, line items, clearing and master data, the table gives the app ID and name confirmed in the SAP Fiori apps reference library and the page that pairs it with the code.

  • A status is only as good as its source: rows are marked as named in help, library entry, redirected or obsolete, or not confirmed.

  • The Public Edition mostly offers the Fiori app and no SAP GUI entry, while on premise both usually exist.

  • The old book appendices are useful checklists, but several of their statements, such as the redirected master data codes, have changed.
