Number Ranges, Field Status Variants and Tolerance Groups

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Every posting in SAP S/4HANA has to be identifiable, shaped and kept within sensible limits, and three small settings do that work. A number range gives each accounting document a unique number, the way a check book numbers its checks. A field status decides which boxes a posting screen shows and which of them the user must fill, the way a paper form can gray out a box or mark it as mandatory. A tolerance group sets how much a user may post at once and how large a difference the system may write off on its own, the way a till supervisor sets a float limit. This page explains each, shows the arithmetic of the tolerance check with real numbers first, and lists where the settings are made. It is written against SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608. The ideas are shared; the Public Edition makes some of the settings in other places, which the page names.

Before you read

  • Organizational Structures: what a company code is, because number ranges, field status variants and tolerance groups are all set for each company code.

  • Customizing and the Implementation Guide: where the paths on this page (the SPRO menu) are found.

  • Fiscal Year Variants and Posting Periods: number ranges can depend on the fiscal year.

Key terms

  • Document number: the number that identifies one accounting document within a company code and a fiscal year (field BELNR).

  • Number range: the named series of numbers, with its limits, that documents of one or more document types draw from.

  • Number range interval: the from and to numbers, and the fiscal year they apply to, that make up a number range for one company code.

  • Internal number assignment: the system picks the next free number automatically.

  • External number assignment: the user, or a feeder system, supplies the number, which must be unique.

  • Document type: the key that classifies a document and ties it to a number range.

  • Posting key: the two-digit key on a line item that sets its account type and whether it is a debit or a credit.

  • Field status variant: a container for field status groups, assigned to one or more company codes.

  • Field status group: a named set of field settings (suppressed, required, optional) that a G/L account applies to the screens used to post to it.

  • Tolerance group: a named set of limits, kept for a company code, for amounts a user may post or differences the system may accept.

The running example: Example Trading Co.

This site uses one fictitious business, Example Trading Co., with company code EX01. For this page EX01 keeps its books in euro (EUR) and reports to a parent that consolidates in British pounds (GBP), and its leading ledger is 0L. Every amount on this page is therefore a euro amount in the company code currency. The keys, numbers and limits below are illustrative values chosen for this site, not SAP defaults, and the page says so wherever it matters.

Document number ranges

What a document number is

Each document in the system is given a number that identifies it within a fiscal year in a company code. The full identity of an accounting document is therefore three values together: the company code, the document number and the fiscal year. In the running example, document 0100000000 of EX01 in fiscal year 2026 is a different document from 0100000000 of EX01 in 2027, if the number range restarts each year.

SAP describes two ways of assigning the number.

  • Internal number assignment: the system allocates the next consecutive number. The accounting clerk writes that SAP document number on the printed original document and files the paper under it.

  • External number assignment: the user enters the number of the original document, or a prebilling system transfers it. The numbers must be unique: the system checks whether the number already exists and refuses a duplicate. Numbers of archived documents can be reused.

Source: Document Number Assignment (SAP Help Portal, on premise)

From document type to number

The document type controls how the number is assigned. You assign a number range to each document type, and you assign to that number range a document number interval from which the number is taken. For the number range you also say whether assignment is internal or external. One number range may serve several document types: the same range can be used for more than one document type, depending on the business requirement, so documents can be told apart by type and still be filed in one series.

The figure follows one posting. The document type points to a number range, the range has an interval for the company code and the fiscal year, and the interval is either drawn from automatically or filled from outside.

The number range is linked to a company code and a document type. SAP’s support content names the transaction that assigns a number range to a document type as OBA7 and says that the number is stored in field BELNR of the Financial Accounting tables.

Sources: Document Number Assignment (SAP Help Portal, on premise), Number Range In Financial Accounting (SAP Help Portal, support content)

Intervals and the fiscal year

An interval is a row with a number range key, a fiscal year, a from number, a to number and an external indicator. Two rules from SAP govern the rows: only one document number interval can be defined for each document type in a company code, and the intervals in a company code must not overlap.

The fiscal year column decides whether the series restarts. SAP’s support content says the intervals are year dependent or not, so the document numbers either begin again each year or run on, and that a non-year-dependent interval uses the year 9999. SAP’s own sample for the activity enters every interval with 9999 as the fiscal year.

The running example uses three intervals. Range 01 is year independent, range 02 restarts every year, and range 91 is for numbers supplied from outside.

The capacity of one interval is the to number minus the from number plus one: 199,999,999 - 100,000,000 + 1 = 100,000,000 documents for range 01. The same count holds for ranges 02 and 91, so each interval holds one hundred million documents.

SAP’s support content adds how the numbers are handed out. The interval is stored in table NRIV for the number range object RF_BELEG, which accounting documents use. The table is locked until the posting is committed, so numbers rise in time order and a rolled-back number is given out again, which keeps the series in time order without gaps. The lock can slow down many parallel postings, and SAP names two solutions: no parallel processing, or buffering of the object.

Sources: Define Document Number Ranges for Entry View (SAP Best Practices), Number Range In Financial Accounting (SAP Help Portal, support content)

Reversals and the general ledger view

Two rules matter when ledgers are involved. When you reverse a document the system assigns a number to the reversal document, and for that it needs a document type with internal number assignment. Every document type with external assignment therefore needs a reverse document type with internal assignment; without a particular reversal type, the system uses the document type of the original document if that has internal assignment.

For non-leading ledgers the documents of the entry view and of the general ledger view can differ, and the general ledger view documents get their own numbers. SAP’s caution is to always choose internal number assignment for documents in the general ledger view. To keep the numbers of the leading and the non-leading ledgers free of gaps, SAP advises a document type with its own number range for valuation postings to the leading ledger, used for the non-leading ledgers as well but with a distinct number range for their valuation postings. The ledgers themselves are explained in Ledgers, Currencies and Exchange Rates.

Source: Document Number Assignment (SAP Help Portal, on premise)

Number ranges in the Public Edition and in transports

In the Public Edition the number ranges are maintained in the configuration activity Define Document Number Ranges, available through SAP Central Business Configuration. It replaced the Fiori app Manage Journal Entry Number Ranges, whose app ID is FBN1 and which SAP now marks as deprecated. New number ranges can be created only in the development system; in other systems you can display and change existing ones.

SAP’s help on defining ranges across a development, quality and production landscape describes how a transport behaves:

  • A number range created in quality and not yet present in production is transferred, but its current number (the number range status) starts again at the first free number in production.

  • A range that already exists in production is not overwritten when a change is transported. The status is not set back to a lower value, and you check the production values by hand.

  • Changes to the interval limits, the status or the external indicator are made by hand in each system.

  • Alphanumeric number ranges are possible, but their numbers can only be assigned externally.

Sources: Manage Journal Entry Number Ranges, deprecated (SAP Help Portal, Public Edition), Number Range Definition: Possible Scenarios (SAP Help Portal, Public Edition)

Field status variants and field status groups

The problem they solve

A posting screen has dozens of possible fields. A bank account needs few of them, an expense account may need a cost assignment, and a clerk who sees all of them makes mistakes. SAP lets you define the status of each field once, for a group of accounts, instead of per account.

SAP names three statuses for a field: suppress (the field is hidden), required entry (the field is shown and the system refuses the posting without a value) and optional entry (the field is shown and may stay empty). A field hidden by status shows up as a classic error: the message that a field of table BSEG does not exist in the screen is related to field status, and SAP’s support content says it typically appears when the field is set to suppress and a program still tries to fill it.

Sources: Defining the Field Status (SAP Help Portal, SAP ERP 6.0 EHP8, older page), Field Status Configuration (SAP Help Portal, support content)

Variant, group, account and posting key

The pieces fit together as follows.

  • A field status group holds the status of every field group. You write the key of the group into the master record of the G/L account.

  • Groups do not depend on the company code. They belong to a field status variant. In the standard system each company code has a variant named like the company code, and each company code is assigned to the variant of the same name. You can use identical groups in several company codes by assigning them to the same variant.

  • A posting key also carries a field status. The standard keys for G/L postings are 40 (debit) and 50 (credit), and their fields are optional in the standard system. SAP advises not to change that, and to build screen layouts from the field status groups of the accounts, because only two posting keys exist for G/L accounts.

  • Customer and vendor accounts have no field status group in their own master records. You set the status through their reconciliation accounts, which therefore also need a field status group.

SAP’s example of a group is a bank account group in which the assignment number, text and value date fields are optional and every other field is suppressed. One more warning from SAP: do not forget to maintain the field status when you create a group, because otherwise all fields are suppressed.

Field status in the Public Edition

In the Public Edition, G/L account groups define the allowed account number range and the screen layout for creating accounts, and the layout carries the field status. SAP warns that you must define the field status when you define an account group, because otherwise all fields are displayed, or, if you copy an existing group, the copy takes the field status of the group it was copied from. Groups are predefined for the standard chart of accounts YCOA and cannot be changed, but you can create your own groups, and only in the Product-Specific Configuration phase in the development system.

Source: Defining an Account Group (SAP Help Portal, Public Edition)

Tolerance groups

Three kinds, one idea

A tolerance is an acceptable gap or limit. SAP Learning describes three kinds of tolerance group.

  • Employee tolerance groups set upper limits for what a user may post and the payment differences the user may accept, and cap the cash discount percentage the user may grant on a line item.

  • G/L account tolerance groups set the permitted payment differences for automatic clearing.

  • Customer and vendor tolerance groups govern clearing, the treatment of permitted differences, the posting of residual items and the tolerances for payment advice notes.

The page covers the first two in detail. Customer and vendor groups belong with the Accounts Receivable and Accounts Payable pages.

Source: Managing Payment Differences (SAP Learning)

Employee tolerance groups: what a user may post

The upper limits for posting, as SAP Learning states them, are four values.

Limit What it controls

Maximum document amount

The most a user can post in one document, measured as the total of the debit or of the credit line items.

Maximum open item amount

The largest amount a user can enter as a line item in a customer or vendor account.

Maximum cash discount

The highest cash discount percentage a user can grant on a line item.

Maximum payment difference

The largest acceptable over or underpayment. For revenue the tolerance applies to overpayments, for expenses to underpayments.

You can create as many groups as you need. Each user can be assigned to one tolerance group. A user without an assignment uses the values of the blank group, which usually holds the values for most employees, and the blank group should always be set up. Each company code needs at least one entry, and tolerance amounts are always in the local currency, which for EX01 is the euro. The group currency (GBP) plays no part. Users are assigned in the activity Assign Users to Tolerance Groups.

In the running example EX01 has two employee groups. The values are illustrative.

Take a vendor invoice for 62,000.00 EUR with one vendor line of 62,000.00 EUR and a cash discount of 2.5 %. A user in the blank group is refused for three reasons: the document total 62,000.00 is above 50,000.00, the open item 62,000.00 is above 25,000.00, and 2.5 % is above 2.0 %. Sources: Managing Posting Authorizations (SAP Learning), Define Tolerance Groups for Employees (SAP Library 4.6C, older page)

G/L account tolerance groups: what the system may write off

When you clear a G/L account, the open items rarely match to the cent. A G/L account tolerance group sets the limit within which the system accepts the remaining difference and posts it by itself, instead of leaving the items open or asking a clerk. SAP’s older library page for the clearing differences activity states the purpose in one sentence: for G/L account clearing, tolerance groups define the limits within which differences are accepted, and the activity defines the accounts to which these differences are posted. The group is defined per company code; each group has debit and credit limits in local currency, and a limit can be given as an absolute amount and as a percentage.

SAP does not leave the choice to chance when both are given. SAP Learning states that "the lower of the two tolerances always applies", and that a difference must be within the group of the G/L account and the group of the customer or vendor to be handled automatically. SAP’s own numbers are: unauthorized deduction limits of 200.00 and 100.00 currency units and 2.5 % and 2.0 % of the open amount give a limit of 20 for an open amount of 1,000 and a limit of 100 for 100,000. The group an account uses is chosen in its master data.

Sources: Managing Payment Differences (SAP Learning), Create Accounts for Clearing Differences (SAP Library 4.6C, older page)

The tolerance check with numbers

Start with EX01 and two groups that both apply to one clearing: a G/L account group with an absolute limit of 10.00 EUR and a percentage limit of 1.5 %, and a customer group with 8.00 EUR and 2.0 %. The clerk clears an open amount and a payment that differ by a small amount, and the system decides whether to post it automatically.

For an open amount of 400.00 EUR:

  • G/L group: 1.5 % of 400.00 is 6.00, the absolute limit is 10.00, the lower is 6.00.

  • Customer group: 2.0 % of 400.00 is 8.00, the absolute limit is 8.00, the lower is 8.00.

  • The difference must be below both, so it must be below 6.00. A difference of 5.00 EUR is posted automatically. A difference of 7.50 EUR is not, and a clerk handles it by hand.

For an open amount of 2,000.00 EUR:

  • G/L group: 1.5 % of 2,000.00 is 30.00, the absolute limit is 10.00, the lower is 10.00.

  • Customer group: 2.0 % of 2,000.00 is 40.00, the absolute limit is 8.00, the lower is 8.00.

  • The difference must be below 8.00. The same 7.50 EUR is now posted automatically, and 9.00 EUR is not.

The percentage limit tightens the check on small amounts and the absolute limit caps it on large amounts. For the G/L group the two limits are equal at an open amount of 10.00 / 0.015 = 666.67 EUR, and above that amount the absolute limit is the lower one.

Where tolerance groups are used

The G/L and employee tolerance groups also influence a program. When you clear GR/IR accounts with extended open item management, the Include Tolerances indicator makes the program consider the tolerance groups for G/L accounts (activity Define Tolerance Groups for G/L Accounts, transaction OBA0) and for employees (Define Tolerance Groups for Employees, transaction OBA4). For that option to take effect an account must be maintained in the automatic account determination for transaction key DSA (transaction OBXZ). SAP also cautions that open item managed accounts cannot be used in the tolerance settings.

Source: GR/IR Automatic Clearing With Extended Open Item Management (SAP Help Portal, on premise)

Common errors and pitfalls

Symptom Likely cause What to check

A posting finds no number interval

No interval for the document type’s number range, company code and fiscal year.

Maintain the interval for the year, or use the year 9999 for a year-independent range.

The system refuses an external number

The number already exists in the company code and fiscal year.

External numbers must be unique; check for a duplicate original document number.

Reversal fails for a document type with external numbering

No reverse document type with internal assignment.

Assign a reversal document type with internal number assignment.

Gaps appear in a document number series

Several causes are possible, including the buffering of the number range object RF_BELEG.

SAP’s support page lists a note on the reasons for document number gaps and how to analyze them (note 1522367).

The message that a field of table BSEG does not exist in the screen appears

The field is suppressed in the field status group or the posting key.

Set the field to optional or required in the group of the account.

Every field of a new account is missing

The status of the new group was not maintained.

Maintain the field status of the group, because unmaintained fields are suppressed.

A difference that looks small is still not cleared automatically

The difference is above the lower limit of one of the groups that apply, or the account is open item managed.

Compute the limit of every group as in the worked example, and check the account.

What older books show, and what has changed

Andrew Okungbowa’s SAP S/4HANA Financial Accounting Configuration (2nd edition, 2023) devotes its chapter on document control to document types, posting keys, number range intervals (including how to copy intervals to a fiscal year) and field status variants, and its next chapter to tolerance groups for G/L accounts and employees, including the blank default group and the assignment of users to groups. It teaches the on-premise Implementation Guide screens step by step. It is outdated for the Public Edition, where number ranges are maintained in the Define Document Number Ranges configuration activity and no longer in the app of the same function, where account groups carry the field status, and where configuration happens in SAP Central Business Configuration instead of the Implementation Guide. Stoil Jotev’s Configuring SAP S/4HANA Finance (3rd edition, 2025) covers the same global settings from the S/4HANA 2023 perspective and does not show the Public Edition activities either. Where the books and the SAP Help Portal pages above differ, the help pages win.

Summary

  • Each accounting document is identified by company code, document number and fiscal year. The document type points to a number range, and the range has an interval of from and to numbers per company code and fiscal year.

  • Assignment is internal (the system picks the next number) or external (the user supplies a unique number). Reversals need a document type with internal assignment, and the general ledger view always uses internal assignment.

  • A year-independent interval uses the fiscal year 9999; a year-dependent one restarts each year. Intervals of one company code must not overlap and each document type has one interval.

  • A field status group sets each field to suppressed, required or optional. It belongs to a field status variant, is named in the G/L account master record, and works together with the posting key; reconciliation accounts carry the status for customer and vendor lines.

  • Employee tolerance groups limit the document amount, the open item amount, the cash discount percentage and the payment difference a user may post; a user without a group uses the blank group.

  • G/L account tolerance groups set the difference the system accepts when clearing. With an absolute and a percentage limit the lower one applies, and the difference must be within every group that applies.

  • All tolerance amounts are in the company code currency (EUR for EX01), never the group currency.

  • The Public Edition keeps number ranges in a configuration activity and field status in the account group, while the on-premise system uses FBN1, OBY6, OB14, OB41, OBA0 and OBA4.
