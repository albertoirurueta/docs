SAP Fiori Launchpad

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

When you sign in to a modern SAP system in a web browser, the first thing you see is usually not a menu of transaction codes but a screen of square tiles. That screen is the SAP Fiori launchpad. It is the single door to every app a person is allowed to use, on a desktop or on a phone, and it also provides navigation, personalization, embedded support and the configuration of applications. A newcomer meets it on the first day, because even the older SAP GUI transactions are started from it in current systems. This page explains how the launchpad is built (spaces, pages, sections and tiles), what a business role has to do with what you see, how searching, My Home, My Inbox and personalization work, how an administrator sets the content up, and where to look up which app does what. It is written against SAP S/4HANA 2025 FPS02 on premise and Private Edition, where the launchpad belongs to the ABAP platform 2025 with SAP_UI 816, and against SAP S/4HANA Cloud Public Edition 2608. Where a statement applies to only one of them, the text says so. The launchpad on SAP BTP is a separate product family, mentioned briefly at the end.

Before you read

  • Getting Started: what an ABAP system is, because the launchpad of an S/4HANA system runs on the ABAP application server.

  • Classic Tools: SE80, SE38, SE11, SE37 and SE16: what a transaction code is, because transactions can appear as tiles.

  • Authority Checks: what a role and an authorization are, because what you see in the launchpad follows your roles.

Key terms

  • SAP Fiori launchpad: the web entry point from which a user starts the apps the user is allowed to use.

  • Space: a top-level area of the launchpad, shown as a tab or ribbon, that frames one or more pages and is assigned to business roles.

  • Page: a screen inside a space that arranges apps in sections of tiles.

  • Tile: the clickable square or link that starts an app.

  • Catalog: a collection of tiles with the technical information needed to start each app.

  • Business role: the set of authorizations and launchpad content that a user is assigned, which decides what the user sees.

  • My Home: the landing page of the launchpad with the sections To-Dos, Pages, Apps and Insights.

  • My Inbox: the app that collects the tasks a person has to decide on.

  • SAP Fiori apps reference library: the online catalog that describes every SAP Fiori app, with its roles, catalogs and technical details.

What the launchpad is

SAP describes the launchpad as the entry point for SAP Fiori apps on mobile and desktop devices, providing services such as navigation, personalization, embedded support and application configuration. In the SAP Learning material on administering SAP Fiori it is described as combining apps on one surface, based on the role of the user. The idea behind it is a change of style. Older SAP systems offered large, monolithic transactions that did many things. A Fiori app covers one step for one role, and several apps together cover a whole process, possibly across systems. The launchpad is where those small apps are put in reach of the person who needs them.

An app does not have to be written in the newest technology to appear in the launchpad. The SAP Learning pages list three types of Fiori app: transactional apps, which use ABAP and are available for SAP S/4HANA and SAP Business Suite on any database, analytical apps, which use the analytical capabilities of SAP HANA, and fact sheet apps, which use SAP HANA Enterprise Search and show the key facts about a central business object. All of them use SAPUI5 and SAP Gateway. Classic applications, namely ABAP transactions, Web Dynpro ABAP and applications of the WebClient UI Framework, are counted among the transactional apps and are added to the launchpad through configuration. That is the reason a SAP GUI transaction can sit next to a modern app on the same page. In the SAP Learning course for SAP S/4HANA Cloud Private Edition, the transaction apps are shown in the launchpad as SAP GUI for HTML versions.

The newer apps are often built as SAP Fiori elements apps, whose screen is generated at runtime from metadata annotations and, for ABAP systems, from CDS views. SAP Learning names the page types List Report, Object Page, Overview Page, Analytical List Page and Worklist. The ABAP side of this is taught in RAP Services and OData V4 and CDS Annotations and Metadata Extensions. For readers who work with the account-free lab of this site, the lab based on the SAP Cloud Application Programming Model has a Fiori elements preview: running the development server and opening its preview address shows a list report with a filter bar, a table and the create and delete buttons, built from annotations. It loads SAPUI5 1.145.0 from the public SAPUI5 content delivery network, not the newest release. That preview is a development aid, not a launchpad.

Spaces, pages, sections and tiles

The current layout of the launchpad has four nested levels. The SAP Learning page on personalizing the launchpad describes them as follows: spaces structure the launchpad, a space appears as a ribbon or tab and frames one or more pages, a page contains sections, and sections show tiles. Tiles are kept in catalogs, which hold the technical information needed to start an app. Tiles are embedded in pages, and pages are assigned to spaces. Spaces and pages are defined centrally, and only spaces can be assigned to roles.

The following picture of the structure is a reading aid built from those statements, not a screenshot.

flowchart TD R[Business role] --> S[Space] S --> P1[Page] S --> P2[Page] P1 --> SEC1[Section] P1 --> SEC2[Section] SEC1 --> T1[Tile] SEC1 --> T2[Tile] C[Catalog] -. holds the technical start information of .-> T1 C -. holds the technical start information of .-> T2

The same Learning material gives a concrete example. For an administrator, the Administration space has eleven pages; one of them, Identity and Access Management, has a section Users and Roles that contains the apps Maintain Business Roles and Maintain Business Users. A business role usually has one space whose name is similar to the role, although it may have more than one. SAP provides space templates for the standard business roles. A custom role needs a custom space and pages. The decisive rule for beginners is this: a business role without an assigned space shows no apps on the launchpad, although the search still finds the apps the user is allowed to use.

Tile types

A tile is not always a square. According to the SAP Learning page on personalizing the launchpad there are five types, from largest to smallest: the (basic) tile, the wide tile, the flat tile, the flat wide tile and the link. The basic and wide tiles share a height and sit in the same rows, while flat tiles and links sit in their own rows. A smaller type shows less information. Analytical and news tiles are special wide tiles that show more information, such as a key figure. A tile can be converted to another type, for example into a link with the entry Convert to Link. The same page dates the wide tile to SAP S/4HANA 2021 FPS01 and the flat tiles to SAP S/4HANA 2021, so very old systems do not offer all of them.

The older home page and the transition

Before spaces and pages, the launchpad offered a home page made of groups of tiles. SAP’s documentation for the ABAP platform 2025 states that this group-based home page is replaced by the launchpad with spaces and pages, that the classic home page feature and its groups are deprecated and will be removed in a future version, and that creating new home pages based on groups is no longer recommended. Administrators are told to use the apps Manage Launchpad Spaces and Manage Launchpad Pages to define the layout. The page also lists three ways to move: create new pages from scratch, start with SAP-delivered spaces and pages (used directly or copied so they can be adapted), or create pages from existing groups. The content of the home page is not changed by any of these options, and for the moment a user can still switch between the home page and the spaces mode. The SAP Learning page on personalizing the launchpad dates the deprecation to SAP S/4HANA 2021 FPS01 and notes that spaces have structured the launchpad since SAP S/4HANA 2020. If you meet a system or an old book that talks only about groups and a home page, that is the older design.

Source: Transition from the Home Page to Pages

My Home, search and My Inbox

When spaces are active, the first page a user sees is My Home. SAP Learning describes it as having four sections.

  • To-Dos combines tasks from the My Inbox app with situations from the situation handling framework, so that the things that need your attention are in one place.

  • Pages shows the pages assigned to the user. The first eight pages appear by default, chosen from the user’s business roles and assigned spaces and pages. A News tile exists, but it is off by default and an administrator must configure it.

  • Apps shows the favorite apps the user selected, plus recent activities and frequently used apps that the system generates.

  • Insights has tiles, filled automatically from the monitoring apps the role can open, and cards, which users add themselves. The card types named are analytical, list and table cards.

Job-specific spaces appear to the right of the My Home title. The space titles sit near the top of the screen, and a drop-down under the title switches between the pages of that space.

My Inbox is an app, not a part of the launchpad frame. It lists work items, such as an approval request, that are waiting for the user, and the SAP Learning page states that its tasks feed the To-Dos section of My Home. A person therefore does not have to open My Inbox to learn that something is waiting. Tasks that originate in business processes, such as the approval of a purchase requisition, are explained further in the pages on end-to-end processes.

Search works across what the user is permitted to open. SAP Learning states that a user can search for permitted apps even if no space displays them. The user actions menu also offers a personalized search among its settings.

Source: Navigating the SAP Fiori Launchpad

Personalizing the launchpad

A user changes the look and content through the user actions menu. According to SAP Learning, the options depend on how the launchpad is configured, and they include the design theme, switching between spaces and the home page, activating user profiling, language and region, default values, the appearance and behavior of notifications, and personalized search. Two of these deserve a word.

  • Default values pre-fill selection fields when an app starts. Classic ABAP transactions are the exception: they still read the user’s parameters, which are set in transactions SU3 or SU01. On the first start of the launchpad, the back-end parameters are copied to the default values once, and only single values, not multiple values or ranges, are synchronized back. SAP recommends using default values only in SAP Fiori and refers to an SAP Note that needs an SAP login to read.

  • The design theme. The current theme is called Horizon, introduced with SAP S/4HANA Cloud 2208 according to the SAP Learning course on administering SAP Fiori. The same page says that SAP no longer uses version numbers for SAP Fiori. The Horizon themes can also change the look of SAP GUI screens.

To change what a page shows, the user chooses Edit Current Page in the user actions menu. That switches the page to an action mode in which the user can add, hide and delete sections, remove tiles, and create and rearrange tiles. The App Finder, or the Add Tile action, shows the tiles from all catalogs assigned to the user’s role, so a user can only add what the role already allows. In My Home, the Apps section is changed directly: the user adds favorites with Add Apps, or from a tile’s context menu with Add to My Home, and can gather favorites into app groups with a name and a color. My Home Settings control the layout of the four sections, which pages, insight tiles and insight cards appear, and let a user export and import personalized content, which is useful when a user wants to keep the content of a former personalized home page. A SAP Easy Access menu transaction can be added as a tile, once an administrator has mapped the ABAP system.

A report named /UIF/MIGRATE_FES_PERSO collects the personalization data of the launchpad and of applications into transport requests, according to the same page; the transport concept itself is explained in Packages, Transports, gCTS and abapGit.

Source: Personalizing SAP Fiori Launchpad

How the content reaches a user

A user sees a tile only through a chain of assignments, and knowing the chain is the fastest way to solve the question "why do I not see this app?".

  1. The administrator defines a business role that holds the authorizations for the apps.

  2. The role is assigned a space. Without a space, no apps are displayed.

  3. The space contains pages, the pages contain sections, and the sections contain tiles.

  4. Each tile comes from a catalog, which carries the technical information needed to start the app.

  5. Authorisations decide whether the app, once started, may read and change the data.

Administrators work with the apps Manage Launchpad Spaces and Manage Launchpad Pages, as the SAP documentation for the ABAP platform 2025 states. The same documentation names a bottom-up process, in which pages are created first, then spaces that include them, which are then assigned to users through business roles, and the alternative of starting from SAP-delivered spaces and pages. SAP publishes a separate documentation set for the launchpad of SAP S/4HANA Cloud, so Public Edition 2608 administrators read that set rather than the ABAP platform one. For both editions, the list of which standard role, catalog, space and page contains a given app is kept in the apps reference library, described next.

Finding apps: the apps reference library and its successor

A common beginner question is which app does a task, and what it needs. SAP’s answer is the SAP Fiori apps reference library. SAP Learning describes it as the place that lists, for each app, the standard business role, the business catalog, the space and the page, plus technical details and links to documentation, and that lets you search app features and filter by application type. A SAP Learning video explains that it can also show which apps are deprecated, successor or new between a source release and a target release, which is useful when planning an upgrade.

The classic library, at the address fioriappslibrary.hana.ondemand.com, is being retired. When this page was written on 2026-11-13, opening an app from the classic address showed a notice that the classic SAP Fiori apps reference library "will be retired soon", asked users to update their bookmarks and to use the new library at fal.cloud.sap, and said that the classic address stays active and redirects to the new library after the retirement date. The notice gives no date, so plan on the new address. The new site calls itself the SAP Fiori Apps Reference Library, offers to explore, plan and implement apps, and shows a sign-in option and a link to register an account, so this page does not rely on anything behind the sign-in. Other pages in the SAP documentation still say "SAP Fiori Apps Reference Library" and link to the classic address, which is a reason to check where such a link leads before bookmarking it.

Source: SAP Fiori Apps Reference Library has moved (the notice of the classic library)

Where the launchpad runs

The documentation for the launchpad is organized by product. The SAP Help Portal lists the launchpad for on-premise products by ABAP platform release (the 2025 release with SAP_UI 816 is the one that matches the baseline of this site), the launchpad for SAP S/4HANA Cloud, the launchpad for SAP Integrated Business Planning, and the launchpad on SAP BTP, which covers SAP Build Work Zone, standard edition, and a user guide and administration guide for the SAP BTP ABAP environment. The SAP Learning administration course lists the ways to reach the launchpad: any HTML5-ready web browser, SAP Business Client 6.0, and, for SAP Build Work Zone sites on iOS and Android, the Joule Work mobile app, which the page names as the successor to SAP Mobile Start since May 2026. It also lists the launch addresses of an ABAP system: the original path under /sap/bc/ui5_ui5/ui2/ushell/shells/abap/, the shorter current address /sap/bc/ui2/flp, and the transaction /UI2/FLP, which signs the user in automatically with the application server credentials.

Source: SAP Fiori Launchpad on the SAP Help Portal

Summary

  • The SAP Fiori launchpad is the single entry point to the apps a user may use, on desktop and mobile, and in current systems it also starts classic transactions.

  • Its layout is spaces, which contain pages, which contain sections of tiles; tiles come from catalogs, and spaces are assigned to business roles. A role without a space shows no apps.

  • The group-based home page is deprecated in favor of spaces and pages; administrators use Manage Launchpad Spaces and Manage Launchpad Pages.

  • My Home has To-Dos, Pages, Apps and Insights; My Inbox tasks feed To-Dos; users personalize pages through Edit Current Page and My Home Settings.

  • To find which app, role and catalog serve a task, use the SAP Fiori apps reference library; the classic address is retiring and its successor is fal.cloud.sap.

  • On premise (2025 FPS02) the launchpad belongs to the ABAP platform; in Cloud Public Edition 2608 it is documented in its own product set; on SAP BTP it is delivered through SAP Build Work Zone.
