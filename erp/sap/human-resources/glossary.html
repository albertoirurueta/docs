HR Glossary

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This glossary explains, in plain words, the human resources terms used across the HR part of the SAP section, such as infotype, personnel action, wage type and payroll schema, and links each one to the page that teaches it. Use it when an HR page uses a word you have not met. General SAP terms are in the SAP Glossary. Example values on the HR pages, such as the company Example Trading Co. and its employees, are made up. Terms are listed alphabetically.

0-9

1H and 2H releases

SAP SuccessFactors is a cloud product, so SAP does not ship it as one big version every few years. Instead it delivers two large batches of new features each year, called the first-half (1H) and second-half (2H) releases. See SAP SuccessFactors Overview.

A

Absence

An absence is a stretch of time inside an employee’s planned working time in which the person is not at work, such as vacation or sick leave. It is recorded as a record of the Absences infotype (2001). See Time Management Basics.

Absence quota

An absence quota is a time account that holds an entitlement, counted in days or hours, such as the 30 vacation days of a year. Absences are deducted from it as they are taken, and it is kept in the Absence Quotas infotype (2006). See Time Management Basics.

ALE

Application Link Enabling (ALE) is SAP’s way of keeping data in step between systems: one system packs data into messages called IDocs and sends them to the systems named in a distribution model. In HR it is used, for example, to copy master data and organizational data to another system. See HR Interfaces and Data Conversion.

ALV

ALV is the SAP List Viewer, the standard way to show a table of data on screen so the user can sort, filter and download it. A report fills an internal table and hands it to ALV. See Custom HR Reports and Performance.

Archiving

Archiving moves data that is no longer needed day to day out of the main database into archive files, which saves space and keeps the system fast. It differs from blocking, which only hides data, and from destruction, which removes it. See Data Privacy: Blocking and Destruction.

Attendance

An attendance is a recorded working time, or a deviation from the planned working time, such as a business trip or overtime. It is recorded as a record of the Attendances infotype (2002). See Time Management Basics.

Authorization level

The authorization level is an HR-specific field, named AUTHC, that says what kind of access a user has to HR data, such as read or write. It is checked together with the other fields of an authorization object. See HR Authorizations.

Authorization main switch

An authorization main switch is a setting that turns one part of the HR authorization check on or off. The switches are stored under the group AUTSW in the table T77S0, so a part with no active switch is not checked. See HR Authorizations.

Authorization object

An authorization object is a named group of authorization fields that the system checks together before it lets a user do something. A user passes the check only if one of the user’s authorizations matches the values asked for in all its fields. See HR Authorizations.

B

BAdI

A BAdI (Business Add-In) is a place that SAP has prepared in its own program where a customer can plug in their own code to extend or change the standard behavior, without modifying SAP’s code. See Custom Infotypes and Enhancements.

BAPI

A BAPI is a ready-made function that a business object offers so that programs outside the system can use it, for example to read or create employee data. Technically it is a function module that can be called remotely. See HR Interfaces and Data Conversion.

Blocking

Blocking takes away access to personal data that is no longer needed for its original purpose, for example for an employee who left, without deleting it. Only users with a special authorization can still see blocked data. See Data Privacy: Blocking and Destruction.

Business catalog

A business catalog is a bundle of apps that SAP delivers for one area of work. An administrator picks catalogs to build the role that gives a group of users, such as employees or managers, their apps. See Employee and Manager Self-Services.

Business Integration Builder

The Business Integration Builder is the Customizing area where you define which Employee Central field feeds which field in SAP S/4HANA when employee data is copied across. See Employee Central to SAP S/4HANA Integration.

Business rule

A business rule in Employee Central is a small set of conditions and actions of the form If, Then, Else. When data changes, it can fill in values, show a message or start an approval workflow, without programming. See Employee Central Data Models and MDF.

C

Change document

A change document is a log entry that records who changed which fields of an infotype record, when, and from which old value to which new value. It lets you audit changes to HR data afterwards. See HR Reporting Tools.

Change pointer

A change pointer is a small log entry that notes that some data changed. A periodic job reads the pointers and distributes just the changed data to the other systems. See HR Interfaces and Data Conversion.

Change validation

Change validation is a function of the Interface Toolbox that exports only the HR data that changed since the previous export, instead of sending everything again each time. See HR Interfaces and Data Conversion.

Check class

A check class is the ABAP class that holds the business logic and the input checks of one infotype built with the decoupled infotype framework. It replaces logic that used to sit in the screen program. See Custom Infotypes and Enhancements.

Chief position

The chief position is the position that manages an organizational unit. In the running example, the Sales Manager is the chief position of Sales. See Organizational Management.

CI include

A CI include is the customer include of an infotype structure, with a name of the form CI_P followed by the infotype number. It is where you add your own fields to a standard infotype. See Custom Infotypes and Enhancements.

Cluster

A cluster is a group of related data, such as fields and internal tables, that the system packs into one record of a cluster file and reads back as a whole. HR uses clusters for bulky results such as payroll results. See HR Data Structures and Tables.

Cluster B2

Cluster B2 is the area of the HR cluster file PCL2 in which time evaluation stores its results for each employee and period, such as balances and time wage types. See Time Evaluation.

Compatibility pack

A compatibility pack is a temporary arrangement that lets a customer keep using an older SAP feature inside SAP S/4HANA while moving to the newer way of working. The HR compatibility pack is the one that applies to human resources. See SAP HCM, H4S4 and SuccessFactors.

Compound Employee API

The Compound Employee API is an interface of Employee Central, based on SOAP, that returns the data of an employee, bundled in one structured message. It is used to extract employee data so that other systems, such as payroll, can receive a copy. See Employee Central Payroll.

Concurrent employment

Concurrent employment means one person holds several employments at the same time, for example two part-time contracts. Each employment has its own personnel number, and all of them belong to the same person. See Logical Databases PNP/PNPCE and HR Macros.

Container

In the decoupled infotype framework, a container is an object that stands for one infotype record, with its secondary data, when you write the record through the framework’s buffer. See Reading and Writing Infotypes.

Conversion class

A conversion class is a class that translates between the data as it is stored for an infotype and the data as the screen shows it. See Custom Infotypes and Enhancements.

Core hybrid

A core hybrid is a setup in which the core HR data, such as people and organization, lives in the cloud in SAP SuccessFactors Employee Central, while payroll or time management keeps running in SAP HCM for SAP S/4HANA. Data is copied from the cloud to the S/4HANA system. See Employee Central to SAP S/4HANA Integration.

Corporate Data Model

The Corporate Data Model is the configuration file of Employee Central that describes the company’s organization, built from foundation objects such as departments and locations. See Employee Central Data Models and MDF.

Customer infotype

A customer infotype is an infotype that a company builds for itself, using a number from the range reserved for customers (9000 to 9999), so that it holds data SAP does not deliver and an upgrade does not overwrite it. See Custom Infotypes and Enhancements.

Customizing table

A customizing table holds the settings of a company, such as the list of its personnel areas or the rules for wage types, and not the data of individual employees. See HR Data Structures and Tables.

D

Daily work schedule

A daily work schedule describes the working time of one day: when work starts and ends, when the breaks are and how many hours are planned. Daily work schedules are the building blocks of longer schedules. See Time Management Basics.

Data conversion

Data conversion is the one-time transfer of data from an old system into the SAP system, for example when employee records are loaded at the start of a project. It differs from an interface, which runs again and again. See HR Interfaces and Data Conversion.

Data privacy

Data privacy covers the rules and tools that limit who may see personal data and how long it may be kept. In SAP HR this is done with authorizations, blocking and destruction of data. See Data Privacy: Blocking and Destruction.

Data Replication Monitor

The Data Replication Monitor is a screen in Employee Central that shows, employee by employee, whether the copy of the data to Employee Central Payroll worked and what went wrong when it did not. See Employee Central Payroll.

Data selection period

The data selection period is the date range for which a report reads the records of the persons it has selected. It can be wider than the period in which persons are chosen. See Custom HR Reports and Performance.

Decoupled infotype framework

The decoupled infotype framework is a way of building infotypes in which the business logic and checks live in ABAP classes instead of in the screen program, so the same logic serves different user interfaces. See Custom Infotypes and Enhancements.

Delimitation

Delimitation means ending the validity of an existing record by setting its end date. The system does it automatically when a new record of the same infotype starts, so that the two records do not overlap. See Time Constraints and Validity Periods.

Destruction lock

A destruction lock, also called a legal hold, is a record that stops data from being destroyed even though its retention period has ended, for example because it is needed in a legal case. See Data Privacy: Blocking and Destruction.

Destruction object

A destruction object is a bundle of related data that can be destroyed together in one run. For HR it stands for the data of one personnel number. See Data Privacy: Blocking and Destruction.

Dynamic action

A dynamic action is a rule that starts automatically when an infotype record is saved and leads to follow-up processing, for example creating another record or showing a message. See Personnel Actions and Master Data Maintenance.

Dynamic processing rule

A dynamic processing rule is the successor of the dynamic action in the Web Dynpro ABAP master data application. It is a configured rule with conditions and operations that runs when data is saved. See Personnel Actions and Master Data Maintenance.

E

Effective dating

Effective dating means keeping every version of a record together with the date range in which that version is valid, instead of overwriting old values. It lets you ask what was true on any given day. See Employee Central Data Models and MDF.

Employee Central

Employee Central is the core human resources application of SAP SuccessFactors. It stores employee, employment and organization data in the cloud and is usually the source from which other systems get people data. See SAP SuccessFactors Overview.

Employee Central Payroll

Employee Central Payroll is a cloud payroll service that SAP operates for the customer. It reads its people data from Employee Central and calculates pay from it. See Employee Central Payroll.

Employee group

The employee group is the main way of dividing employees by kind, for example active employees or pensioners. In the running example, group 1 is Active. See Enterprise and Personnel Structure.

Employee grouping for account determination

This is a value derived from the employee, such as hourly or salaried staff, that lets the same payroll item be posted to different general ledger accounts depending on the kind of employee. See Posting Payroll to Accounting.

Employee lifecycle

The employee lifecycle is the series of stages of a person’s employment, from being hired through changes such as promotions or transfers to leaving or retiring. HR and payroll data follow these stages. See HR and Payroll Basics.

Employee Self-Service

Employee Self-Service (ESS) is a set of services with which employees display and change their own HR data and send requests, such as a leave request, without going through the HR department. See Employee and Manager Self-Services.

Employee subgroup

The employee subgroup divides an employee group further, for example into salaried and hourly staff. It influences how payroll and time management treat the employee. In the running example, AA is Salaried staff and AB is Hourly staff. See Enterprise and Personnel Structure.

Enterprise structure

The enterprise structure is the way a company is divided for HR purposes: client, company code, personnel area and personnel subarea. It decides where employees are assigned and which settings apply to them. See Enterprise and Personnel Structure.

Evaluation path

An evaluation path is a recipe that says which relationships to follow from a start object, and so which objects to collect. For example, it can list all positions below an organizational unit. See Organizational Management.

Evaluation period

The evaluation period is the date range on the selection screen of an HR report that tells it which records it is interested in. See Logical Databases PNP/PNPCE and HR Macros.

Event reason

An event reason states why an employee’s job or pay data changed, such as a hire, a promotion or a termination. Employee Central records it with the change and can use it to drive follow-up behavior. See Hire to Retire, End to End.

F

Factoring

Factoring is reducing or splitting an amount in payroll by a partial period factor, so that an employee who works or is paid for only part of a period gets only the matching part of the amount. See Partial Periods and Retroactive Accounting.

Form Builder

The Form Builder is the graphical layout tool, connected to the HR Forms Workplace, that produces PDF-based forms such as payslips. See HR Forms and Payslips.

Form class

A form class is a grouping of forms of one kind, such as payslips or time statements. It fixes which catalog of data and which data a form of that kind may use. See HR Forms and Payslips.

Foundation object

A foundation object is a master data object in Employee Central that describes the company rather than a person, such as a department, a location or a job classification. Employee records point to these objects. See Employee Central Data Models and MDF.

Full transmission start date

The full transmission start date is the date from which Employee Central sends the data of an employee to payroll or to SAP S/4HANA. Data dated before it is not part of the copy. See Employee Central Payroll.

Function

A function is one step of a payroll or time evaluation schema, such as copying a subschema, starting a loop or calling a rule. A schema is a list of functions that the program carries out in order. See Payroll Schemas and Personnel Calculation Rules.

G

Generic object

A generic object is a custom object that a company defines itself in the Metadata Framework of SuccessFactors, with its own fields and rules, when the delivered objects do not fit. See Employee Central Data Models and MDF.

Gross pay

Gross pay is the pay agreed with the employee before anything is deducted. In the running example, Ana Torres has a gross monthly pay of 4,000.00 EUR. See HR and Payroll Basics.

H

H4S4

H4S4 is the short name for SAP HCM for SAP S/4HANA, the set of classic HR features such as personnel administration, time management and payroll that can run inside SAP S/4HANA. See SAP HCM, H4S4 and SuccessFactors.

HCM

HCM stands for Human Capital Management and is the name SAP uses for its human resources software. See SAP HCM, H4S4 and SuccessFactors.

High date

The high date is the date 31.12.9999. It is used as the end date of a record that has no planned end, so a record that is valid until further notice still has a complete date range. See Time Constraints and Validity Periods.

Hire to retire

Hire to retire is the chain of steps in an employee’s working life, from filling a job opening and hiring through the working years to the end of employment and the erasure of the data. See Hire to Retire, End to End.

HIS

HIS is the Human Resources Information System, a tool that starts HR reports along a hierarchical structure such as the organizational structure, so you pick a unit and run a report for the people below it. See HR Reporting Tools.

HR Form Editor

The HR Form Editor is the older tool for designing payroll forms such as the classic remuneration statement. It is started with the transaction PE51. See HR Forms and Payslips.

HR Forms Workplace

The HR Forms Workplace is the central tool for HR forms, started with the transaction HRFORMS. In it you choose the data of a form, link it to a layout tool, activate the form and print it. See HR Forms and Payslips.

HR macro

An HR macro is a piece of ABAP code that SAP defines once and that is copied into each report that uses it. Reports use macros to read infotype records, for example the one named RP_PROVIDE_FROM_LAST. See Logical Databases PNP/PNPCE and HR Macros.

HRIS element

An HRIS element is one named block of fields in an Employee Central data model, such as personal information or job information. See Employee Central Data Models and MDF.

HRMD_A

HRMD_A is the name of the ALE message type used to distribute HR master data and organizational data from one SAP system to another. See HR Interfaces and Data Conversion.

I

IDoc

An IDoc is a structured data container, with a message type that says what it carries, in which ALE sends data from one system to another. See HR Interfaces and Data Conversion.

InfoNet

The InfoNet is the part of the data catalog that one concrete HR form uses. In the HR Forms Workplace it is shown as a tree, next to the MetaNet from which you pick the data. See HR Forms and Payslips.

Information Lifecycle Management (ILM)

Information Lifecycle Management (ILM) is the SAP component that manages how long data is kept and when it is destroyed, using retention rules that you define. See Data Privacy: Blocking and Destruction.

InfoSet

An InfoSet is a view that picks the fields of one or more data sources, in HR usually a logical database, and offers them to queries. Users build reports from the fields of an InfoSet. See HR Reporting Tools.

InfoSet Query

InfoSet Query is a tool for building a report without programming: you tick the selection fields and the output fields of an InfoSet and run it. In HR it is also called Ad Hoc Query. See HR Reporting Tools.

Infotype

An infotype is one kind of record in the HR master data, covering one area of information about an employee, such as personal data or basic pay. Each infotype has a four-digit number, and its records are kept with their validity dates. See Infotypes.

Infotype group

An infotype group, or infogroup, is the sequence of infotypes that the system shows one after another while a personnel action such as a hire runs. See Personnel Actions and Master Data Maintenance.

Interface format

An interface format is the description, built from database, cluster, table and field objects, of what the Interface Toolbox exports and how the exported file is laid out. See HR Interfaces and Data Conversion.

Interface Toolbox

The Interface Toolbox is an HR tool, started with the transaction PU12, that generates an export program and a file format for sending HR data to a system of another vendor. See HR Interfaces and Data Conversion.

J

Job

A job is a general description of a kind of work, such as Clerk or Manager, shared by many positions. In the running example, the positions Sales Clerk and Warehouse Clerk both use the job Clerk. See Organizational Management.

L

Lock

A lock is a mark that stops two users or programs from changing the data of the same employee at the same moment. Code that writes infotype records sets a lock first and releases it afterward. See Reading and Writing Infotypes.

Logical database

A logical database is a program, owned by SAP, that reads data from a tree of related tables and hands it to a report record by record. It is old technology in general ABAP, but it is still the standard way for HR reports to read master data, through PNP and PNPCE. See Logical Databases PNP/PNPCE and HR Macros.

M

Macro

A macro is a named block of ABAP statements that is copied into the program where it is used. Macros are used a lot in HR programs to read and process infotype data. See Reading and Writing Infotypes.

Manager Self-Service

Manager Self-Service (MSS) is a set of services with which line managers see their team and approve or start HR tasks for it, such as approving a leave request. See Employee and Manager Self-Services.

Master cost center

The master cost center is the cost center stored with the employee’s organizational assignment. Posting of payroll to accounting uses it when no other cost assignment applies to an amount. See Posting Payroll to Accounting.

Matchcode W

Matchcode W is the list of personnel numbers that payroll rejected or that were corrected after an error. A payroll correction run uses it to pick up exactly those employees. See The Payroll Process.

MDF

MDF stands for Metadata Framework, a mechanism in SuccessFactors for defining your own business objects, which can then be exposed as OData entities. See SuccessFactors Talent Modules.

Metadata Framework (MDF)

The Metadata Framework (MDF) is the SuccessFactors platform for building custom objects, and rules that work on them, through configuration instead of programming. See Employee Central Data Models and MDF.

MetaNet

The MetaNet is the catalog of all the data that can be printed on HR forms. In the HR Forms Workplace it is shown as a tree on the left, from which the data of a form is picked. See HR Forms and Payslips.

Middleware

Middleware is software that sits between two systems. It accepts the message one system sends, converts it into the form the other system expects and passes it on. In the Employee Central to SAP S/4HANA integration, SAP Cloud Integration plays this role. See Employee Central to SAP S/4HANA Integration.

Migration object

A migration object tells the SAP S/4HANA migration cockpit how one kind of business data is moved into the system. For HR, objects exist for employees, organizational objects and relationships, and which ones you see depends on the scope and approach you activated. See HR Interfaces and Data Conversion.

MODE N

MODE N is an addition to the INFOTYPES statement in a report. Normally the logical database fills an infotype table for every person it reads; with MODE N the table is left alone and the program reads the records itself, so it can load only what it needs. See Custom HR Reports and Performance.

N

Net pay

Net pay is the money the employee actually receives. It is what remains of the gross pay after taxes and the employee’s social contributions have been taken off. See HR and Payroll Basics.

O

OAuth 2.0

OAuth 2.0 is a standard way for a program to prove it may call an API without sending a password each time. The program first obtains a short-lived token and then sends that token with every request. See SuccessFactors OData API.

Object manager

The object manager is the search and selection area on the left of the HR master data screens. You use it to find and pick the employee you want to work on. See Personnel Actions and Master Data Maintenance.

Object type

An object type is the kind of thing an Organizational Management object is, written as a one-letter code. For example, O is an organizational unit, S a position, C a job and P a person. See Organizational Management.

OData

OData is a standard way of reading and changing data over HTTP, using plain web addresses. SuccessFactors offers it as its main API, so other programs can use its data without a special client. See SuccessFactors Talent Modules.

OData API

An OData API is a web interface that lets a program read and change data in the SuccessFactors modules. It follows the OData standard, so requests are ordinary HTTP calls. See SAP SuccessFactors Overview.

OData service

An OData service is the web interface of the SAP back end that a Fiori app calls. The app asks the service for the data it shows and sends changes back through it. See Employee and Manager Self-Services.

Off-cycle payroll

Off-cycle payroll is a payroll run for one employee that happens on any day, outside the regular schedule of payroll periods. It is used when someone must be paid at a time that the normal monthly run does not cover. See The Payroll Process.

On Behalf

On Behalf is a function with which a manager carries out an employee’s self-service task for that employee. The manager acts for the employee instead of the employee doing it personally. See Employee and Manager Self-Services.

Operation

An operation is the smallest building block of a personnel calculation rule, one single statement such as storing a wage type. Rules combine several operations to calculate a value. See Payroll Schemas and Personnel Calculation Rules.

Organizational assignment

Organizational assignment is the fact that an employee belongs somewhere in the company: to a position, a department, a cost center or under a manager. In the integration it is part of the data replicated for each employee. See Employee Central to SAP S/4HANA Integration.

Organizational key

An organizational key is a 14-character field, derived from the Organizational Assignment infotype, that refines where an employee belongs. Authorization checks can use it to decide who may see or change which employees. See HR Authorizations.

Organizational Management

Organizational Management is the SAP component that stores the structure of a company by tasks and roles rather than by people. It holds objects such as organizational units, jobs and positions and the relationships between them. See Organizational Management.

Organizational object

An organizational object is a part of the company structure, such as a unit, a job or a position, as opposed to an employee. Employees are then assigned to these objects. See Employee Central to SAP S/4HANA Integration.

Organizational unit

An organizational unit is a functional part of a company, such as a department, a group or a project team. Positions are placed inside organizational units, which in turn form a hierarchy. See Organizational Management.

P

Pagination

Pagination means returning a long answer in pages instead of all at once. The client asks for the first page, then fetches the next ones one after another until it has everything. See SuccessFactors OData API.

Parallel processing

Parallel processing splits the work of one report into packages that several work processes run at the same time. For a report that reads many employees, this can shorten the total runtime. See Custom HR Reports and Performance.

Partial period factor

A partial period factor is the fraction by which an amount is multiplied when an employee is paid for only part of a period. For example, someone present for half of the month receives half of the monthly amount. See Partial Periods and Retroactive Accounting.

Payroll area

A payroll area is a group of employees whose payroll is run together, at the same time and for the same periods. Each employee is assigned to exactly one payroll area through the Organizational Assignment infotype. See The Payroll Process.

Payroll Control Center

The Payroll Control Center is a set of applications that checks the quality of data and guides the payroll process. It helps the payroll team see what must be corrected before and after a run. See Employee Central Payroll.

Payroll control record

The payroll control record belongs to a payroll area and holds its next payroll period, its payroll status and its retroactive accounting limit. The payroll run reads it to know which period to process. See The Payroll Process.

Payroll correction run

A payroll correction run is a payroll run limited to the personnel numbers collected in matchcode W, the list of employees that payroll rejected or that were corrected. It lets you rerun only the people who had a problem. See The Payroll Process.

Payroll driver

The payroll driver is the program that runs payroll, with one version for each country. It executes the payroll schema for the employees of a payroll area. See Payroll Schemas and Personnel Calculation Rules.

Payroll past

The payroll past is the set of all payroll periods for which payroll was already run and exited. Retroactive accounting looks into it when data that affects those periods is changed. See Partial Periods and Retroactive Accounting.

Payroll period

A payroll period is the stretch of time that one payroll run pays for, for example one calendar month. It is defined by the period parameters of the payroll area. See HR and Payroll Basics.

Payroll result

A payroll result is the outcome of a payroll run for one employee and one period. It is stored in a cluster of the database file PCL2 and holds the wage types, amounts and other values calculated. See Wage Types, Internal Tables and Payroll Results.

Payroll run

A payroll run is the program execution that calculates pay for all employees of a payroll area for one period. It produces a payroll result for each employee. See HR and Payroll Basics.

Payroll simulation

A payroll simulation is a payroll run for individual employees that saves nothing and changes no status. It lets you check what a calculation would produce without affecting the real payroll. See The Payroll Process.

Period of responsibility

A period of responsibility is a time interval in which a user is responsible for an employee, and therefore authorized to work with that employee’s data. Time logic compares it with the validity of a record. See HR Authorizations.

Period work schedule

A period work schedule is a repeating sequence of daily work schedules, such as a week from Monday to Friday or a rotating shift plan. It describes the pattern, not the days of one particular person. See Time Management Basics.

Person selection period

The person selection period is the time span in which a person must meet the selection conditions to be selected by a report at all. It is separate from the period for which that person’s records are then read. See Custom HR Reports and Performance.

Personal work schedule

A personal work schedule is the planned working time of one employee, day by day, for a period. It is the generic work schedule adjusted by that person’s own absences, attendances and substitutions. See Time Management Basics.

Personnel action

A personnel action is a predefined procedure, such as hiring, that creates or changes a series of infotype records for one employee in one go. It guides the user through the screens needed for one business event. See Personnel Actions and Master Data Maintenance.

Personnel area

A personnel area divides a company code into smaller units that differ in personnel administration, time management or payroll. It is the first level of the enterprise structure used for HR. See Enterprise and Personnel Structure.

Personnel assignment

A personnel assignment is one employment of a person, identified by a personnel number. A person with two employment contracts therefore has two personnel assignments. See Logical Databases PNP/PNPCE and HR Macros.

Personnel calculation rule

A personnel calculation rule is a small decision tree of operations that calculates values such as amounts and hours for wage types. Payroll and time evaluation schemas call rules to refine a processing step. See Payroll Schemas and Personnel Calculation Rules.

Personnel calculation schema

A personnel calculation schema is the ordered list of steps, called functions, that a payroll or time evaluation program follows. It is like a recipe that says what to calculate and in which order. See Payroll Schemas and Personnel Calculation Rules.

Personnel number

A personnel number is the number under which all records of one employment are stored. The HR master data, time data and payroll results of an employee are all found through it. See HR and Payroll Basics.

Personnel structure

The personnel structure groups employees by kind: employee group, employee subgroup and payroll area. It is used alongside the enterprise structure to control how employees are processed. See Enterprise and Personnel Structure.

Personnel subarea

A personnel subarea is a subdivision of a personnel area. Most HR control data, such as pay scales and work schedules, is set at this level. See Enterprise and Personnel Structure.

PNP

PNP is the logical database SAP delivers for HR master data, time data and payroll. It reads the data and raises one event per personnel number, so a report can process employees one at a time. See Logical Databases PNP/PNPCE and HR Macros.

PNPCE

PNPCE is the enhanced version of the PNP logical database. It also understands concurrent employment, where one person has several personnel numbers. See Logical Databases PNP/PNPCE and HR Macros.

Point-to-point replication

Point-to-point replication is the direct copy of employee data from Employee Central into Employee Central Payroll, with no middleware between the two. It keeps the payroll system supplied with the employee data it needs. See Employee Central Payroll.

Position

A position is one place in the organization that one person can fill, such as the sales manager of the sales department. It sits in an organizational unit and is described by a job. See Organizational Management.

Posting document

A posting document is a summarized document that a posting run creates from payroll results. Accounting then creates its own accounting documents from it. See Posting Payroll to Accounting.

Posting run

A posting run is the central object of the step that sends payroll to Accounting. It has a unique number, groups the posting documents created from payroll results and carries a status. See Posting Payroll to Accounting.

Posting to Accounting

Posting to Accounting is the SAP component that evaluates payroll results and posts them to Finance and Controlling. It is the interface between Payroll and Accounting. See Posting Payroll to Accounting.

Q

QuickViewer

QuickViewer is a tool that builds a simple report on a table, a view or a join without any ABAP coding. It suits quick looks at data rather than formatted reports. See HR Reporting Tools.

R

Recalculation difference

A recalculation difference is the amount by which a period recalculated by retroactive accounting differs from what was paid before. The difference is carried into the current period. See Partial Periods and Retroactive Accounting.

Relationship

A relationship is a stored link between two Organizational Management objects, kept in infotype 1001. For example, a position belongs to an organizational unit through a relationship. See Organizational Management.

Remuneration statement

The remuneration statement is SAP’s name for the payslip. It lists the amounts and information for one employee and one payroll period. See HR Forms and Payslips.

Replication

Replication means copying data from one system to another, here regularly and in one direction. In this integration, employee data is copied so the second system can work with it. See Employee Central to SAP S/4HANA Integration.

Replication request

A replication request is one entry in the staging area, created for one employee when a run brings new or changed data. It waits there until the data is written into infotypes. See Employee Central to SAP S/4HANA Integration.

Retention rule

A retention rule says how long data of a certain kind must be kept, counted from a start date. When the period ends, the data becomes eligible for blocking or destruction. See Data Privacy: Blocking and Destruction.

Retroactive accounting

Retroactive accounting is the recalculation of payroll for periods that were already paid, because data that affects them was changed afterward. The result is a correction in the current period. See Partial Periods and Retroactive Accounting.

Retroactive accounting limit

The retroactive accounting limit is the furthest date in the past up to which payroll data may be changed and recalculated. Changes older than the limit do not lead to a recalculation. See Partial Periods and Retroactive Accounting.

RPTIME00

RPTIME00 is the report that runs time evaluation. It selects the employees, retrieves their time data, processes it with a schema and stores the results. See Time Evaluation.

S

SAP Business Client

SAP Business Client is the client, available as a desktop or an HTML version, in which the Web Dynpro ABAP self-services run. It provides the container the user works in. See Employee and Manager Self-Services.

SAP Query

SAP Query is a general reporting tool that offers more formatting and calculation options than InfoSet Query. It also manages the user groups and InfoSets on which queries are built. See HR Reporting Tools.

Schema

In time evaluation, a schema is the ordered list of processing steps, called functions, that run for each employee and each day. It controls how recorded time becomes results. See Time Evaluation.

Screen structure

A screen structure is a dictionary structure that contains every field the user interface of an infotype shows. The infotype screen is built from it. See Custom Infotypes and Enhancements.

Staging area

The staging area is a holding table in SAP S/4HANA where received data waits before it is written into infotypes. It decouples receiving data from applying it. See Employee Central to SAP S/4HANA Integration.

Structural authorization

A structural authorization is a permission that follows the organizational structure instead of listing individual values. A manager can, for example, be allowed to see everyone below their own organizational unit. See HR Authorizations.

Structural profile

A structural profile is a start object plus an evaluation path, and a few more fields, that together return the set of objects a user may access. It is what a structural authorization is built from. See HR Authorizations.

Subschema

A subschema is a schema that another schema calls with the COPY function to do one subtask. It keeps large schemas organized into smaller parts. See Payroll Schemas and Personnel Calculation Rules.

Subtype

A subtype is a subdivision of an infotype, such as the address type Permanent residence inside the Addresses infotype. It can carry rules, such as a time constraint, of its own. See Infotypes.

SuccessFactors

SuccessFactors is SAP’s cloud suite for human resources. It is made of separately subscribed modules, with Employee Central as the core. See SAP SuccessFactors Overview.

Succession Data Model

The Succession Data Model is the data model of SuccessFactors that describes the fields of people and their employments. It is made of blocks of fields, which are configured for the company. See Employee Central Data Models and MDF.

Symbolic account

A symbolic account is a Customizing object placed between a wage type and a G/L account. Because of it, payroll settings and accounting settings can change independently of each other. See Posting Payroll to Accounting.

System of record

A system of record is the system whose copy of a fact is the one to trust and to change. Other systems that hold a copy receive it by replication. See Employee Central to SAP S/4HANA Integration.

T

Talent module

A talent module is a SuccessFactors product for one stage of an employee’s relationship with the company, such as Recruiting or Learning. Customers subscribe to the modules they need. See SuccessFactors Talent Modules.

Tenant

A tenant is one customer’s own instance of a cloud service. API requests are addressed to the server of a particular tenant. See SuccessFactors OData API.

Time constraint

A time constraint is a rule of an infotype that says whether a record must exist, how many records may be valid at one time and whether they may overlap. The system checks it whenever records are created or changed. See Time Constraints and Validity Periods.

Time evaluation

Time evaluation is the SAP component that turns recorded working time into results such as balances, time wage types and quota updates. Payroll later uses these results to pay for the time worked. See Time Evaluation.

Time logic

Time logic is the rule that compares the period of responsibility of a user with the validity dates of the record being accessed. It decides whether access is allowed for that time span. See HR Authorizations.

Time management status

The time management status is a setting in infotype 0007 that says whether and how an employee is processed by time evaluation. It tells the system, for example, whether recorded times are evaluated for that person. See Time Management Basics.

Time pair

A time pair is a start time and an end time, for example a clock-in and the matching clock-out. Time evaluation forms pairs from the individual clock events. See Time Evaluation.

Time type

A time type is a bucket in which time evaluation collects durations that mean the same thing, such as planned time or overtime. Balances are kept per time type. See Time Evaluation.

Time wage type

A time wage type is a wage type that carries a number of hours, selected by time evaluation, which payroll later values in money. It is the link between recorded time and pay. See Time Evaluation.

Transformation template group

A transformation template group is a named bundle of the field mappings used by one replication scenario. It states how fields from Employee Central are turned into SAP S/4HANA fields. See Employee Central to SAP S/4HANA Integration.

Transparent table

A transparent table is a database table whose fields can be read one by one with an ordinary query. Infotype data is stored in tables of this kind, unlike the cluster tables used for payroll results. See HR Data Structures and Tables.

U

Upsert

An upsert is a single operation that updates a record when it already exists and creates it when it does not. The caller does not need to check beforehand. See SuccessFactors OData API.

User group

A user group is a named set of users in SAP Query. It decides which InfoSets those users may use to build queries. See HR Reporting Tools.

V

Validity period

A validity period is the span of days, from a start date to an end date, during which one infotype record applies. In the data these dates are BEGDA and ENDDA. See Time Constraints and Validity Periods.

Variable key

A variable key is the column of a personnel calculation rule that holds the possible answers of a decision operation. The rule follows the line whose key matches the value being tested. See Payroll Schemas and Personnel Calculation Rules.

W

Wage type

A wage type is one kind of payment or deduction, such as basic pay or social contributions. It appears as one line of a payslip or payroll result, with an amount, a number or a rate. See Wage Types, Internal Tables and Payroll Results.

Wage type reporter

The wage type reporter is the standard report H99CWTR0 that totals wage types of payroll results. It answers questions such as how much of one wage type was paid across employees. See HR Reporting Tools.

Web Dynpro ABAP

Web Dynpro ABAP is an older SAP user interface technology. The previous generation of the employee and manager self-services is built on it. See Employee and Manager Self-Services.

Work schedule rule

A work schedule rule is the object that says which period work schedule applies to which employees. It also sets the public holiday calendar and the day of the period from which the pattern starts. See Time Management Basics.
