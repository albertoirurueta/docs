SAP HR Guide: Compute Pay for a Partial Period and Gross-to-Net

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Checked on 2026-11-13 against CAP Node.js 10.2 (@sap/cds 10.2.2, @sap/cds-dk 10.2.1, @cap-js/cds-test 1.0.2), the Fiori elements preview of cds watch (SAPUI5 1.145.0), curl 8.7 and Node.js 24.21.

What you build

This is a teaching model built with CAP. It is not SAP S/4HANA, SAP HCM or SAP Payroll and does not reproduce their screens.

You build a small model of one payroll calculation. An employee who is paid for only part of a month receives the basic pay multiplied by a partial period factor, a fraction made of working days. The model offers three of the methods that SAP documents for this factor: the PWS method (personal work schedule), the payment method and the deduction method. From the resulting gross pay it forms the net pay with two flat-rate statutory deductions, social contributions and income tax, and one voluntary deduction that is taken from the net pay. Every step is done in whole cents, with one stated rounding rule, and every amount on this page is checked by a test. You read the result as a payslip in a Fiori elements object page.

Before you start

  • No account is needed: the CAP tools and curl install without signing in. Installing @sap/cds-dk means accepting the SAP Developer License Agreement, version 3.2, which the lab README names.

  • Do the guides Your First CAP Service (it explains cds init, CDS files, CSV data and cds watch) and CAP Domain Model and Custom Logic first. Model Employee Records with Validity Periods builds the records that this guide’s model reads (here reduced to one basic pay amount per employee).

  • Read Partial Periods and Retroactive Accounting, Wage Types and Payroll Results and HR and Payroll Basics. This guide computes the examples of those pages.

  • You need curl 7.82 or newer, which has the option --json. curl --version prints the version.

  • The example is the one of the HR pages: Example Trading Co., payroll area E1 "Monthly EX01", and the employees Ana Torres 00001234 (4,000.00 EUR a month) and Ben Okoye 00001235 (2,400.00 EUR a month). All codes, rates and amounts are invented example values, not values delivered by SAP. Dates in the model are written YYYY-MM-DD, as in code; the SAP screens of the reference pages show DD.MM.YYYY, so 16.03.2026 is 2026-03-16.

  • The rates are generic flat example rates and are not any country’s rules: employee social contributions 20.00 percent of gross pay, income tax 15.00 percent of gross pay minus the social contributions, and employer contributions 21.00 percent of gross pay. Ana’s March 2026 payslip with these rates is the one of the reference pages: gross 4,000.00, social contributions 800.00, tax 480.00, net 2,720.00 and employer contributions 840.00.

  • Ben’s five days of unpaid leave, Monday 16.03.2026 to Friday 20.03.2026, and the general period working time of 21 days are the example of Partial Periods and Retroactive Accounting; the 21 days are an invented average. The voluntary deduction, a canteen card of 25.00 EUR a month, is also invented, and so is the idea that Ben has it.

  • Taken from SAP pages that were read: the formula of the partial period factor, the three methods and their divisors (the SAP Help pages Partial Period Factor, PWS Method, Payment Method and Deduction Method) and the order from gross to net with deductions after net (Payroll Basics). The model’s own, not SAP’s: the tables and the action calculate, the rounding rule, the counting of working days (Monday to Friday, public holidays ignored, as on the reference page), the payslip line texts and the way a hire or a leaving inside the month is treated as days that are not paid. The hybrid and the all-or-nothing method are left out. A real SAP system applies the factor in a payroll schema, which this model does not imitate.

  • The figures are drawings of the editor, the terminal and the Fiori pages, not screenshots. A highlighted box with a number marks the file, the line or the page part of the step with the same number. A figure leaves out the blank lines of a log.

Steps

Create the project and model the payroll data

  1. Create a CAP project named payroll-period and install it, as in the first guide:

    cds init payroll-period --nodejs
cd payroll-period
npm install

  2. Create db/schema.cds. PayrollAreas holds the general period working time, the divisor of two of the methods. Employees holds the monthly basic pay, Rates the flat percentages (20.00 means 20 percent), Absences the unpaid leave of an employee and VoluntaryDeductions fixed amounts that are taken from the net pay. Payslips and PayslipLines store each calculated payslip as it was calculated, so a later change of a rate cannot rewrite an old payslip.

    namespace sap.guide.payroll;

// A teaching model of one payroll calculation, not SAP S/4HANA, not SAP HCM and
// not SAP Payroll. Names, rates, numbers and dates are invented example values.
entity PayrollAreas {
  key Code           : String(2);
  Text               : String(40);
  GeneralWorkingDays : Integer; // the divisor of the payment and deduction methods
}

entity Employees {
  key PersonnelNumber : String(8);
  Name                : String(40);
  PayrollArea         : String(2);
  MonthlyBasicPay     : Decimal(9,2);
}

// Flat example rates, not the rules of any country. Percent 20.00 is 20 percent.
entity Rates {
  key Code : String(10);
  Text     : String(40);
  Percent  : Decimal(5,2);
}

// Unpaid leave of an employee, from the first to the last day (both inclusive).

  key Employee  : Association to Employees;
  key BeginDate : Date;
  EndDate       : Date;
  Kind          : String(20);

// A fixed amount taken from the net pay each month. An invented example.
entity VoluntaryDeductions {
  key Employee : Association to Employees;
  key Code     : String(10);
  Text         : String(40);
  Amount       : Decimal(9,2);

// One calculated payslip, a snapshot: the name and the numbers stay as they were.
entity Payslips {
  key Number      : Integer;
  PersonnelNumber : String(8);
  EmployeeName    : String(40);
  Period         : String(7);   // YYYY-MM
  FromDate       : Date;        // first day paid inside the period
  ToDate         : Date;        // last day paid inside the period
  Method         : String(10);  // PWS, PAYMENT or DEDUCTION
  PlannedDays    : Integer;
  AbsentDays     : Integer;
  DivisorDays    : Integer;
  Numerator      : Integer;
  Factor         : Decimal(7,4);
  BasicPay       : Decimal(9,2);
  GrossPay       : Decimal(9,2);
  SocialEmployee : Decimal(9,2);
  IncomeTax      : Decimal(9,2);

  Voluntary      : Decimal(9,2);
  Payment        : Decimal(9,2);

Write the pay arithmetic

  1. Create srv/pay.js. It holds only arithmetic and has no CAP code, so it can be tested alone. Money is kept as whole cents and a rate as hundredths of a percent (20.00 percent is 2000), so no step uses floating point money. The rounding rule is stated once, in roundDiv: divide and round half up to the whole cent. The factor itself is never rounded; it is a fraction of two whole numbers, and the gross pay is the basic pay times that fraction, rounded once. partialPeriodFactor returns the numerator and the divisor for each method, in working days. Each percentage line of grossToNet is rounded to the cent on its own, and the lines that follow are formed from the rounded ones, so the payslip adds up to the cent.

    // Pay arithmetic of the teaching model. Money is whole cents (integers) and a
// rate is in hundredths of a percent (20.00 percent is 2000), so no step of
// the calculation uses floating point money.

// The rounding rule: divide and round half up to the next whole cent.
// Only values of zero or more are divided here.
export const roundDiv = (numerator, divisor) =>
  (numerator - (numerator % divisor)) / divisor +
  (2 * (numerator % divisor) >= divisor ? 1 : 0)

// A percentage of an amount in cents, rounded to the cent.
export const percentOf = (cents, hundredths) => roundDiv(cents * hundredths, 10000)

export const METHODS = ['PWS', 'PAYMENT', 'DEDUCTION']

// The partial period factor as a fraction numerator / divisor, in working days.
//   planned: working days of the period      absent: days not paid
//   general: the general period working time of the payroll area
export function partialPeriodFactor(method, planned, absent, general) {
  switch (method) {
    case 'PWS': return { numerator: planned - absent, divisor: planned }
    case 'PAYMENT': return { numerator: planned - absent, divisor: general }
    case 'DEDUCTION': return { numerator: general - absent, divisor: general }
  }
}

// Gross pay: the basic pay times the factor, rounded once, to the cent.
export const grossPay = (basicCents, { numerator, divisor }) =>
  roundDiv(basicCents * numerator, divisor)

// From gross to net. Every line is rounded to the cent on its own; the lines
// that follow are formed from the rounded ones.
export function grossToNet(gross, rates, voluntary) {
  const socialEmployee = percentOf(gross, rates.socialEmployee)
  const taxable = gross - socialEmployee
  const incomeTax = percentOf(taxable, rates.incomeTax)
  const netPay = taxable - incomeTax
  const payment = netPay - voluntary
  const socialEmployer = percentOf(gross, rates.socialEmployer)
  return { socialEmployee, taxable, incomeTax, netPay, payment, socialEmployer,
    employerCost: gross + socialEmployer }
}

// Dates are YYYY-MM-DD strings, handled in UTC so daylight saving time cannot
// move a day.
const toDate = (text) => new Date(`${text}T00:00:00Z`)
export const addDays = (text, days) => {
  const d = toDate(text)
  d.setUTCDate(d.getUTCDate() + days)
  return d.toISOString().slice(0, 10)
}

// Monday to Friday between two dates, both included. Public holidays are
// ignored, as on the reference page.
export function workingDays(from, to) {
  let count = 0
  for (let day = from; day <= to; day = addDays(day, 1)) {
    const weekday = toDate(day).getUTCDay()
    if (weekday !== 0 && weekday !== 6) count++
  }
  return count
}

// First and last day of a period written YYYY-MM.
export function periodBounds(period) {
  const [year, month] = period.split('-').map(Number)
  const last = new Date(Date.UTC(year, month, 0)).getUTCDate()
  const end = `${period}-${String(last).padStart(2, '0')}`
  return { begin: `${period}-01`, end }
}

// The amount of a number of cents as text, with a thousands separator.
export const money = (cents) =>
  (cents / 100).toLocaleString('en-US', {
    minimumFractionDigits: 2, maximumFractionDigits: 2 })

export const toCents = (amount) => Math.round(Number(amount) * 100)
export const toAmount = (cents) => cents / 100

    In words, with the planned working days of the period, the days that are not paid and a divisor, the factor is

    and the three methods differ in the divisor and in what the first term is. The PWS method uses the planned days of the period as divisor, the payment method the general period working time, and the deduction method replaces the planned days by the general period working time as well, so that only the absence is deducted. The gross pay is the basic pay times the factor.

    Source: PWS Method, Payment Method and Deduction Method (SAP Help)

  2. Create srv/payroll-service.cds. It exposes the tables read-only and one action, calculate, that takes the personnel number, the period YYYY-MM and the method, and optionally FromDate and ToDate, the days of the month on which the employee is paid:

    using { sap.guide.payroll as db } from '../db/schema';

service PayrollService {
  @readonly entity PayrollAreas        as projection on db.PayrollAreas;
  @readonly entity Employees           as projection on db.Employees;
  @readonly entity Rates               as projection on db.Rates;
  @readonly entity Absences            as projection on db.Absences;
  @readonly entity VoluntaryDeductions as projection on db.VoluntaryDeductions;
  @readonly entity Payslips            as projection on db.Payslips;
  @readonly entity PayslipLines        as projection on db.PayslipLines;

  // Calculates one payslip and stores it. FromDate and ToDate are optional: the
  // days of the period in which the employee is paid (a hire or a leaving).
  action calculate(PersonnelNumber : String(8), Period : String(7),
                   Method : String(10), FromDate : Date, ToDate : Date)
    returns Payslips;
}

  3. Create srv/payroll-service.js. The action first checks its input. It counts the planned working days of the period and the days that are not paid: the working days outside the window FromDate to ToDate (a hire or a leaving inside the month) plus the working days of unpaid leave inside it. It looks up the divisor of the payroll area, forms the fraction and refuses a negative one. It then calculates gross pay and the lines down to the payment in cents, writes the payslip lines (the basic pay, the partial period adjustment as the difference to the gross pay, the deductions and the employer contributions as a note) and stores the payslip under the next number.

    import cds from '@sap/cds'
import { METHODS, addDays, grossPay, grossToNet, money, partialPeriodFactor,
  periodBounds, toAmount, toCents, workingDays } from './pay.js'

const db = cds.entities('sap.guide.payroll')

export default class PayrollService extends cds.ApplicationService {
  init() {
    this.on('calculate', async (req) => {
      const { PersonnelNumber, Method, Period } = req.data
      if (!METHODS.includes(Method)) {
        return req.error(400, `The method must be one of ${METHODS.join(', ')}`)
      }
      if (!/^\d{4}-(0[1-9]|1[0-2])$/.test(Period)) {
        return req.error(400, 'The period must be written YYYY-MM')
      }
      const employee = await SELECT.one.from(db.Employees)
        .where({ PersonnelNumber })
      if (!employee) return req.error(404, `Employee ${PersonnelNumber} not found`)

      const bounds = periodBounds(Period)
      const from = req.data.FromDate ?? bounds.begin
      const to = req.data.ToDate ?? bounds.end
      if (from < bounds.begin || to > bounds.end || from > to) {
        return req.error(400, `The dates must lie inside ${Period}, from before to`)
      }

      // Working days of the period, and the days that are not paid: those
      // outside the paid window and those of unpaid leave inside it.
      const planned = workingDays(bounds.begin, bounds.end)
      let absent = workingDays(bounds.begin, addDays(from, -1)) +
        workingDays(addDays(to, 1), bounds.end)
      const leaves = await SELECT.from(db.Absences)
        .where({ Employee_PersonnelNumber: PersonnelNumber })
      for (const leave of leaves) {
        absent += workingDays(
          leave.BeginDate > from ? leave.BeginDate : from,
          leave.EndDate < to ? leave.EndDate : to)
      }

      const area = await SELECT.one.from(db.PayrollAreas)
        .where({ Code: employee.PayrollArea })
      const { numerator, divisor } =
        partialPeriodFactor(Method, planned, absent, area.GeneralWorkingDays)
      if (numerator < 0) {
        return req.error(400, 'The partial period factor is negative')
      }

      const basic = toCents(employee.MonthlyBasicPay)
      const gross = grossPay(basic, { numerator, divisor })
      const rate = {}
      for (const r of await SELECT.from(db.Rates)) rate[r.Code] = toCents(r.Percent)
      const voluntaryLines = await SELECT.from(db.VoluntaryDeductions)
        .where({ Employee_PersonnelNumber: PersonnelNumber })
      const voluntary = voluntaryLines.reduce((s, v) => s + toCents(v.Amount), 0)
      const pay = grossToNet(gross,
        { socialEmployee: rate.SOCIAL_EE, incomeTax: rate.TAX,
          socialEmployer: rate.SOCIAL_ER }, voluntary)

      const factorText = (numerator / divisor).toFixed(4)
      const percent = (code) => `${(rate[code] / 100).toFixed(2)}%`
      const lines = [
        ['Basic pay (monthly)', `${money(basic)}`, basic],
        ['Partial period adjustment', `${numerator} / ${divisor} = ${factorText}`,
          gross - basic],
        ['Gross pay', '', gross],
        ['Employee social contributions',
          `${percent('SOCIAL_EE')} of ${money(gross)}`, -pay.socialEmployee],
        ['Income tax', `${percent('TAX')} of ${money(pay.taxable)}`,
          -pay.incomeTax],
        ['Net pay', '', pay.netPay],
        ...voluntaryLines.map((v) => [`Voluntary: ${v.Text}`, 'fixed per month',
          -toCents(v.Amount)]),
        ['Payment', '', pay.payment],
        ['Employer contributions (not on the payslip)',
          `${percent('SOCIAL_ER')} of ${money(gross)}`, pay.socialEmployer]
      ]

      const last = await SELECT.one.from(db.Payslips).columns('max(Number) as n')
      const Number = (last?.n ?? 0) + 1
      await INSERT.into(db.Payslips).entries({
        Number, PersonnelNumber, EmployeeName: employee.Name, Period,
        FromDate: from, ToDate: to, Method, PlannedDays: planned,
        AbsentDays: absent, DivisorDays: divisor, Numerator: numerator,
        Factor: factorText, BasicPay: toAmount(basic), GrossPay: toAmount(gross),
        SocialEmployee: toAmount(pay.socialEmployee),
        IncomeTax: toAmount(pay.incomeTax), NetPay: toAmount(pay.netPay),
        Voluntary: toAmount(voluntary), Payment: toAmount(pay.payment),
        SocialEmployer: toAmount(pay.socialEmployer),
        EmployerCost: toAmount(pay.employerCost),
        Lines: lines.map(([Text, Basis, cents], i) =>
          ({ Position: i + 1, Text, Basis, Amount: toAmount(cents) }))
      })
      return SELECT.one.from(db.Payslips).where({ Number })
    })

    return super.init()
  }
}

  2. Create the folder http and in it calc-ana.json, the request for Ana’s March 2026 payslip with the PWS method. Open a second terminal in the project folder and post it. Variations

  • Pay only the first half of the month. http/calc-ben-split.json asks for Ben’s payslip with the days from 2026-03-01 to 2026-03-15, as if he were reassigned on 16.03.2026 and the pay had to be split. The 12 working days outside the window count as not paid, so the numerator is 10 and the divisor 22:

    {
  "PersonnelNumber": "00001235",
  "Period": "2026-03",
  "Method": "PWS",
  "FromDate": "2026-03-01",
  "ToDate": "2026-03-15"
}
    curl -s --json @http/calc-ben-split.json http://localhost:4004/odata/v4/payroll/calculate | grep -oE '"(Number|FromDate|ToDate|AbsentDays|DivisorDays|Numerator|Factor|GrossPay)":("[^"]*"|[0-9]+)'

    The answer lists Number 5, FromDate 2026-03-01, ToDate 2026-03-15, AbsentDays 12, DivisorDays 22, Numerator 10, Factor 0.4545 and GrossPay 1090.91. This is the first partial period of the reference page; with the methods PAYMENT and DEDUCTION the same window gives 1142.86 and 1028.57. Only the PWS method uses the real length of the month as divisor, so only it adds up to the agreed basic pay when both partial periods are paid. The test checks the second half of the month for Ana: 1,818.18 + 2,181.82 = 4,000.00.

  • Pay a long month with no absence under the payment method. http/calc-ben-april-payment.json asks for Ben, April 2026, PAYMENT:

    {
  "PersonnelNumber": "00001235",
  "Period": "2026-04",
  "Method": "PAYMENT"

What can go wrong

Symptom Cause Fix

The method must be one of PWS, PAYMENT, DEDUCTION and HTTP 400

The Method is spelled differently (the model has no HYBRID method) or is missing from the request file.

Use PWS, PAYMENT or DEDUCTION, in capital letters.

The period must be written YYYY-MM and HTTP 400

The Period is 2026-13 or another text that is not a year and a month.

Write the period as 2026-03.

Employee 99999999 not found and HTTP 404

The personnel number is not one of the two in db/data.

Use 00001234 or 00001235.

The dates must lie inside 2026-03, from before to and HTTP 400

FromDate or ToDate lies outside the period, or FromDate is after ToDate.

Give two days of the period, the first not after the second.

The partial period factor is negative and HTTP 400

With the DEDUCTION method the days that are not paid exceed the general period working time of 21 days, for example when the window holds a single Sunday.

Check the dates, or use the PWS or PAYMENT method.

Unsupported Media Type and HTTP 415

The request was sent with -d instead of --json, so curl sent it as a form.

Use --json @http/<file>.json.

Parsing URL failed at position 27 and a long list of expected tokens

The address of the list is in double quotes, so the shell replaced $select and $orderby by nothing.

Put the address in single quotes, as in step 12.

The list has more than four payslips and their numbers do not start at 1

Each calculate stores a new payslip, and the variations add more.

Stop cds watch and start it again: the database is in memory and begins with no payslip.

Clean up

Press Ctrl+C in the terminal that runs cds watch. The database lives only in memory, so the payslips are gone at the next start; the CSV files bring back the starting data.
