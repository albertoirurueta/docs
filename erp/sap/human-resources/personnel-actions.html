Personnel Actions and Master Data Maintenance

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

When a company hires someone, a whole set of paperwork follows: the contract, the address, the bank details, the pay, the working hours. In an HR system the same paperwork is a set of records called infotypes, and nobody wants to remember which twenty of them a new employee needs. SAP solves this with personnel actions: you tell the system "hire this person", and it walks you through exactly the records that a hiring needs, one screen after the other. For small corrections, such as a new address, you skip the walk-through and open a single record. This page explains both ways of working, the screens around them, and the automatic follow-up steps the system can trigger, using the hiring of Ben Okoye at Example Trading Co. as the running case. It is written against SAP S/4HANA 2025 FPS02 on premise and Private Edition, where the HR functions come from SAP HCM for SAP S/4HANA (H4S4), a separately licensed component. SAP SuccessFactors maintains employee data in a different way that later pages cover.

Before you read

  • Infotypes: what an infotype, a subtype and a validity period are.

  • Enterprise and Personnel Structure: the personnel area, employee group and employee subgroup that a hiring assigns.

  • Organizational Management: the positions that a hiring can link an employee to.

Key terms

  • Personnel action: a predefined procedure, such as hiring, that adds, changes or delimits a series of infotype records for one employee.

  • Infotype group: the sequence of infotypes the system shows while one personnel action runs, also called an infogroup.

  • Personnel number: the number under which all HR records of one employee are stored.

  • Dynamic action: an automatic follow-up step that the system starts when an infotype is maintained in the SAP GUI transactions.

  • Dynamic processing rule: the successor of the dynamic action in the Master Data application, a configured rule with conditions and operations.

  • Object manager: the search and selection area on the left of the HR master data screens, used to find the employee to work on.

The running example: Example Trading Co.

All HR pages on this site use one fictitious business, Example Trading Co. All keys, names, numbers and dates are invented example values chosen for this site. They are not values delivered by SAP, and a real system defines its own. Dates are written DD.MM.YYYY, as an SAP screen shows them, and the high date is 31.12.9999.

This page follows 00001235 Ben Okoye, hired 01.09.2024 as Sales Clerk (position 51000002, job 52000002 Clerk, in the organizational unit 50000002 Sales). Ben is a salaried employee (employee subgroup AA "Salaried staff") in personnel area EX01 "Example Trading Co.", personnel subarea 0001 "Head office", employee group 1 "Active" and payroll area E1 "Monthly EX01". His basic pay is 2,400.00 EUR a month, he works 40 hours a week (Monday to Friday 08:00 to 16:30 with an unpaid break of 30 minutes, 8 paid hours a day) and his annual leave entitlement is 30 days. Where this page needs something the shared example does not contain, it says that it extends the example.

Two ways to maintain employee data

SAP Help describes the functions for maintaining HR master data as the way to enter, update and analyze employee data. The data is entered in infotypes, and SAP Help names two kinds of access:

  • The functions that open one infotype record of an employee. In the SAP GUI this is the transaction Maintain HR Master Data (PA30). A sibling, Display HR Master Data (PA20), shows the same data read-only. You use PA30 when one thing changes and you know which infotype holds it.

  • The personnel actions. In the SAP GUI this is the transaction Personnel Actions (PA40). You use it when a business event touches many infotypes at once, such as a hiring. SAP Help calls these basic tasks "grouped together as personnel actions".

All three transactions share one screen layout. SAP Help describes it as an object manager, a search area and a selection area that together find the employees, and a work area where the transaction-specific functions run. You search for the employee, double-click the result in the selection area and then work in the work area.

The table puts the two ways side by side for Ben.

What a personnel action is

SAP Help defines a personnel action as a series of infotypes that are added, changed, completely or partially deleted, or delimited for the reason specified, for example hiring, change of cost center and leaving. Each personnel action contains the infotypes for which you have to enter data for that procedure and displays them for you to process, which ensures that the core data of the procedure is entered. The standard system includes these personnel actions:

  • Hiring

  • Organizational Reassignment, for employees who are promoted, demoted or transferred to an equivalent work center

  • Early retirement/retirement

  • Leaving

  • Reentry into Company

SAP Help also names Change in Pay as an action type in the description of how to perform an action. Customers add action types of their own in Customizing; the exact Customizing path is not covered by the pages used for this page.

The order and the content of the infotypes of an action come from the infotype group (infogroup). SAP Help says an infogroup exists in the standard system for every personnel action type, that you define the order of the infotypes in Customizing for the Human Resource Management System, that you can make infogroups depend on the user group, and that you can change an infogroup temporarily with the Change Infotype Group function. A function to scroll through all infotype records of an infogroup of an employee also exists.

Most personnel actions create a record in the Actions infotype (0000). In it you enter the personnel action type, the reason for the action and the employee’s employment status. That record is what later shows an employee’s history as a list of stages: hired, moved, left.

Sources: Personnel Action (SAP Help, Human Resources), Infotype Group (SAP Help, Human Resources), Performing a Personnel Action (SAP Help, Human Resources)

Hiring Ben step by step

SAP Help describes how an administrator performs a personnel action, and the hiring follows the same pattern. The steps below apply it to Ben. They require an SAP system; not run here, so no screen output is shown.

  1. In the SAP Easy Access menu, choose Human Resources, Personnel Management, Administration, HR Master Data, Personnel Actions. The Personnel Actions screen appears.

  2. Enter the start date of the action, 01.09.2024. The system transfers this date to all infotype records of the action. For a new employee the personnel number is assigned either by the system (internal number assignment) or by you (external number assignment); in the example it is 00001235.

  3. Choose the personnel action type Hiring. If Organizational Management is integrated with Personnel Administration, the personnel area, employee group and employee subgroup are linked with the position, so you do not enter them on this screen. You maintain the Position field instead, and for Ben you enter position 51000002 Sales Clerk.

  4. Choose Execute. The Actions infotype (0000) appears. Enter the reason for the hiring (SAP Help gives expansion and special projects as examples of reasons) and save.

  5. The system shows the next infotype of the hiring infogroup. SAP Help lists the kinds of data a hiring covers: organizational data, personal data (name, date of birth, marital status, addresses, bank details), payroll-relevant data (basic pay, savings plans, insurance and tax data), contractual and corporate agreements, and time data (working days and times and the leave entitlement). For Ben that means his organizational assignment, his personal data, his basic pay of 2,400.00 EUR a month, his planned working time of 40 hours a week and his leave entitlement of 30 days. Fill in the required fields and save each record.

  6. After the last infotype is saved, the system returns to the initial Personnel Actions screen. The action is complete.

Three details from SAP Help make the walk-through forgiving:

  • The entry date, here 01.09.2024, is the start of the validity period in the Actions infotype and in many other infotypes. It determines seniority and the first payroll run. The default end date is 31.12.9999, which means the validity is unlimited; SAP Help says not to change it for permanent work relationships.

  • If you do not have all the data yet, you can still run the action and skip individual infotypes (on the infotype screen, choose Goto, Next record, and confirm the warning), and you can interrupt an action and restart it later.

  • If the entry date was entered wrongly, it can be changed after the hiring is complete.

Had Ben applied through Recruitment, his applicant data could be transferred directly from Recruitment, or with the action types Transfer applicant data and Transfer other applicant data in Personnel Administration. The example enters him directly.

Fast entry, infotype menus and the second view

Entering twenty screens for each of fifty new employees is tedious, so SAP Help describes Fast Entry of Personnel Actions. In it only the required fields of each infotype are shown, the fields that have automatic default values are not displayed, and all required fields of all infotypes of the action appear on one screen. You reach it in the SAP Easy Access menu under Human Resources, Personnel Management, Administration, HR Master Data, Fast Entry: Actions. You enter the start date, choose the action and execute it. If you need more data in an infotype, you select the Further infotype data check box for it, and after saving the last infotype you return to the initial screen. The administrator can design fast entry screens for each action type in the Implementation Guide of Personnel Administration. SAP Help says the function is available for some actions and performs an action for one employee.

The infotype menus of PA30 and PA40 can differ by country. SAP Help explains that the transactions use a user group parameter set in the HR administrator’s user settings, and that the Customizing activity Map User Group to Country Grouping Code (under Personnel Management, Personnel Administration, Customizing Procedures, Infotype Menus) assigns the user group to a country grouping code. Then an administrator who enters a personnel number sees the infotype menus that belong to the country of that employee.

Sources: Using Fast Entry of Personnel Actions for an Employee (SAP Help, Human Resources), Personnel Action (SAP Help, Human Resources), Managing Infotype Menus (SAP Help, Human Resources)

Automatic follow-up: dynamic actions

Changing one record often means another record needs a change too. When Ben moves to another position, his personnel administrator may change as well. SAP Help names the example of objects on loan, company ID cards and system users that must be returned when an employee is reassigned or leaves, so the responsible administrator should be told. Dynamic actions handle such chains: SAP Help defines them as actions that trigger automatic processing when infotypes are maintained. If you change data of one infotype and this affects a second infotype, the system automatically shows that infotype. Unlike personnel actions, which a person starts, dynamic actions are started by the system. You set up your own processing chains in Customizing of Personnel Administration. SAP Help gives an example: an automatic email through SAPoffice to the responsible administrator when a corresponding infotype record has been changed, which is useful when an employee is reassigned or leaves.

For Ben, as an extension of the example, a dynamic action could notify his administrator when he is later reassigned to another position. Setting one up requires an SAP system; not run here.

Sources: Dynamic Actions (SAP Help, Human Resources), Performing the Organizational Reassignment Personnel Action Type for an Employee (SAP Help, Human Resources)

The Master Data application and dynamic processing rules

The SAP GUI transactions are one user interface. SAP Help also describes the master data application Personnel & Organization, a Web Dynpro application named HRPAO_PAOM_MASTERDATA, which edits master data for organizational units, positions and employees and their assignments to each other. The system starts it automatically when you select an object or an action using the Fiori apps in Human Resources. Its functions, as SAP Help lists them:

  • An object navigator with an integrated search and search criteria to find the objects to display or edit.

  • An object profile page that shows, in business cards for each subject area, the most important master data valid on the chosen date.

  • An infotype-specific page that shows all data of an object for a selected infotype, for a selectable period.

  • An action menu on the object, from which you start processes or open an infotype-specific page directly; for the Employee Actions, the system calls a process-specific page.

Dynamic actions are tied to the SAP GUI transactions. The equivalent here is the dynamic processing rule (DPR). SAP Help states that DPRs are the successors of the dynamic actions used in PA30 and PA40, and that existing dynamic actions can be converted. A DPR responds to changes in a triggering infotype and either guides the user to the next infotype that needs an update or updates data in the background. SAP Help gives the example of the number of children in Personal Data (0002) not matching the Family Members/Dependents infotype (0021). A rule is made of these parts, defined in Customizing for Personnel & Organization under Master Data Application, Defining Dynamic Processing Rules:

  • The actions in the starting infotype that trigger the rule.

  • The conditions those actions must meet.

  • The operations triggered in the target infotype, with optional default values.

  • Parameter groups, for calculation methods that need importing parameters.

  • An optional order of the rules, where lower numbers are processed first.

SAP delivers some DPRs, for example Maintain Children. The comparison table in SAP Help lists, for instance, that the rule name in a DPR groups all definitions of one rule, while a dynamic action uses a sequence number as a key, and that DPRs support the operations Create, Change and Delimit where dynamic actions support Create, Change and Delete.

Sources: Master Data Application (SAP Help, Human Resources), Dynamic Processing Rules (SAP Help, Human Resources), Dynamic Actions and Dynamic Processing Rules (SAP Help, Human Resources)

What older books show, and what has changed

The book SAP ERP HCM: Technical Principles and Programming, 1st edition (2013), shows personnel actions as events that change employee data, recorded in infotype 0000 and entered with the transaction PA40, and it devotes a section to dynamic actions as activities triggered automatically while infotypes are maintained. That concept is the same today: the current SAP Help still describes personnel actions, the Actions infotype and the transactions PA30 and PA40. What has changed is the setting. The book describes SAP ERP HCM, while in SAP S/4HANA the functions come as SAP HCM for SAP S/4HANA (H4S4), which SAP says needs a separate license. SAP also says that from SAP S/4HANA 2025 the business function for H4S4 is activated by default and HCM can no longer run in compatibility mode. The book’s SAP GUI view is only one of two now: the Master Data application has its own dynamic processing rules in place of dynamic actions, and SAP SuccessFactors holds employee data in its own way. Technical names the book gives for how dynamic actions are stored are not repeated here, because the pages used for this page do not name them.

Sources: SAP ERP HCM: Technical Principles and Programming (SAP PRESS; the publisher page lists the 2nd edition, the consulted copy is the 1st edition), SAP HCM for SAP S/4HANA (SAP Help)

Summary

  • A personnel action is a predefined procedure such as hiring that walks the administrator through the infotypes it needs and records the action itself in the Actions infotype (0000).

  • PA40 runs personnel actions, PA30 maintains a single infotype and PA20 displays; all use the same object manager layout.

  • An infotype group sets which infotypes an action shows and in which order; it is set in Customizing and can be changed temporarily.

  • Ben Okoye’s hiring on 01.09.2024 creates records valid from that date to 31.12.9999 in the infotypes of the hiring infogroup.

  • Dynamic actions start automatic follow-up processing in the SAP GUI; dynamic processing rules do the same in the Master Data application and can be converted from dynamic actions.

  • The infotype concept and the personnel actions are the same as in older SAP ERP HCM books, while the product around them is now H4S4.
