SAP HR Cheat Sheet

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A one-page reference for everyday SAP Human Resources work, using the invented Example Trading Co. of this section (see Human Resources). It condenses the finished pages for H4S4 on SAP S/4HANA 2025 FPS02 and SuccessFactors 2H 2026 (2611). Every key, name and number in the examples is an invented value, not an SAP-delivered one. Each section links to the page that explains it in depth, and the full list of pages is at the end.

Landscape

  • Options: SAP ERP HCM (classic), SAP HCM for SAP S/4HANA (H4S4, separate license, active by default from SAP S/4HANA 2025, so compatibility mode is no longer possible), SAP SuccessFactors Employee Central and Employee Central Payroll.

  • Published dates: Business Suite 7 mainstream maintenance to the end of 2027, optional extended maintenance to the end of 2030, and an SAP S/4HANA commitment to the end of 2040. No H4S4 end date is stated.

  • Core hybrid: Employee Central holds core HR and SAP HCM for SAP S/4HANA runs payroll or time management. Data is replicated through SAP Cloud Integration with the add-on ECS4HCM.

See SAP HCM, H4S4 and SuccessFactors.

Enterprise and personnel structure

  • Enterprise structure: client, company code, personnel area (4 characters), personnel subarea (4 characters). The subarea carries pay scales, work schedules and the public holiday calendar.

  • Personnel structure: employee group (1 character), employee subgroup (2 characters, with the groupings for the personnel calculation rule, wage types, work schedule and quotas) and payroll area (2 characters).

  • The assignment is stored in Organizational Assignment (0001). Example: EX01, 0001, 1, AA, E1.

See Enterprise and Personnel Structure.

Personnel actions

Transaction Use

PA40

personnel actions (hiring, move, leaving)

PA30

maintain one infotype

PA20

display only

HRFE_MASS_UPDATE

mass update of one infotype

A hiring runs in PA40: enter the start date, choose the action type Hiring and the position, then save the infotypes of the infogroup (0000, 0001, 0002, 0006, 0007, 0008). The action itself is recorded in 0000. A new record delimits the previous one, and an open end is 31.12.9999. A change in a period already paid triggers retroactive accounting.

See Personnel Actions and Master Data Maintenance and Time Constraints and Validity Periods.

Time management and evaluation

Daily EXDAY 08:00-16:30, break 0.5 h = 8.0
Period EXWEEK Mon-Fri EXDAY = 40.0 h
Rule EXRULE; shifts EXEARLY, EXLATE

The Time Management status in Planned Working Time (0007): 0 no time evaluation, 1 and 2 actual times, 9 only deviations, 7 evaluation without transfer to payroll, 8 external employees.

Time evaluation is the report RPTIME00 (transaction PT60). The day’s input table TIP becomes the output table TOP, the balances go to TES, ZES and SALDO, and the time wage types go from DZL and ZML to ZL in cluster B2. The indicator IFTYP says where a time wage type came from: S planned work, M overtime, A absence. Payroll imports ZL with IMPRT B2. Time types are set in the table T555A.

See Time Management Basics and Time Evaluation (RPTIME00).

Payroll process

The payroll control record (transaction PA03) moves through these statuses:

Exit payroll > Released for payroll
  > run / Check result
  > Released for correction > release again
  > Exit payroll

The driver is RPCALCx0 or HxxCALC0 (international: RPCALCX0), and PC00_M99_CALC starts it. H99_DISPLAY_PAYRESULT lists the results. A test run is T and a simulation is S. Off-cycle runs use blank (regular), A (bonus), B (correction) and C (manual check). Result status: A current, P previous, O older. Setting Payroll Status (0003) for a person makes the run skip that person.

See The Payroll Process and Employee Central Payroll.

Schemas, rules and wage types

COPY XIN0 init     COPY XBD0 basic data
COPY XT00 gross    COPY XAP9 add. pay
LPBEG ... LPEND iteration (XDD9, XNA9)
COPY XRR0 retro    COPY XNN0 net
COPY XEND final

A star in column D switches a schema line off. The rule X011 reads Recurring Payments/Deductions (0014) and Additional Payments (0015) and stores wage types with ADDWT; VWTCL is a decision operation and GCY calls a subrule. The editors are PE01 (schema), PE02 (rule) and PE04 (documentation of operations).

Wage type fields: AMT amount, RTE rate, NUM number. Internal tables: WPBP, IT, RT, CRT, BT, C0, C1, ORT. Secondary wage types: /101 Total Gross Amount and /559 Bank Transfer.

See Payroll Schemas and Personnel Calculation Rules and Wage Types, Internal Tables and Payroll Results.

HR ABAP and key transactions

TABLES pernr.   INFOTYPES 0008.
GET pernr (PNP)   GET peras (PNPCE)
PROVIDE * FROM p0008 BETWEEN
  pn-begda AND pn-endda.  ENDPROVIDE.

Macros and function modules: RP-READ-INFOTYPE, RP_PROVIDE_FROM_LAST, RP_UPDATE, HR_READ_INFOTYPE, and HR_INFOTYPE_OPERATION together with BAPI_EMPLOYEE_ENQUEUE and BAPI_EMPLOYEE_DEQUEUE. Other transactions: SU21 (authorization objects), PFCG (roles), SE37 (function modules), SE36 (logical databases) and PU12 (Interface Toolbox).

See Logical Databases PNP/PNPCE and HR Macros, Reading and Writing Infotypes and HR Interfaces and Data Conversion.

SuccessFactors OData API

Entity Business key

PerPerson

personIdExternal

EmpEmployment

personIdExternal, userId

EmpJob

userId, startDate, seqNumber

Navigation properties: employmentNav and jobInfoNav. An effective-dated query uses asOfDate, or fromDate with toDate, never both:

GET https://<api-server>/odata/v2/EmpJob?$filter=userId eq '00001234'&asOfDate=2025-06-30&$format=JSON

Writes use POST https://<api-server>/odata/v2/upsert, and the required property eventReason must be given. One query returns at most 1,000 records: page with $top and $skip, or with paging=cursor or paging=snapshot.

See SuccessFactors OData API.
