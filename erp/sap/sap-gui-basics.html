SAP GUI Basics

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

SAP GUI is the classic desktop program that you use to work in an SAP system built on the ABAP application server. Before you open a screen you choose a system in a small program called SAP Logon, and then you give three things: a client, a user and a language. After logon you see a menu, the SAP Easy Access menu, and you start one task, called a transaction, by choosing it in the menu or by typing its short code into a box at the top of the window, the command field. This page teaches that routine: what you see at logon, how to open, switch and close windows, how favorites and the F1 and F4 help keys save time, and what the most common transaction codes stand for. It is written for SAP S/4HANA 2025 FPS02 on premise and Private Edition, where SAP GUI is still a normal way to work next to the SAP Fiori launchpad. In SAP S/4HANA Cloud Public Edition 2608 business users work in the SAP Fiori launchpad and most of the administration codes below are not offered to them, so treat the table of transactions as a map of the on-premise and Private Edition world.

Before you read

  • Getting Started with ABAP: what an ABAP system is and what a transaction does.

  • Classic Tools: SE80, SE38, SE11, SE37 and SE16: the development transactions that you open from the command field.

Key terms

  • SAP GUI: the front-end program that shows the screens of an ABAP-based SAP system on your computer.

  • SAP Logon: the small program that lists the systems you may open and starts SAP GUI for the one you choose.

  • Client: a business-level subdivision of one SAP system, normally a company; you can log on only to a client where you have a user master record.

  • Transaction code: a short name, such as SU01, that starts one screen or task.

  • Command field: the input box at the top left of the window in which you type a transaction code or a command that begins with a slash.

  • SAP Easy Access: the menu screen that you see after logon, with a tree of folders and transactions.

  • Session: one SAP GUI window of a logon; one logon can have several.

  • Input help: the list of allowed values for a field, opened with F4.

SAP GUI and SAP Logon

SAP GUI is the presentation layer of an ABAP-based system: it draws the screens, and the application server runs the programs. An SAP Learning course describes three variants. SAP GUI for Windows is written in C and C++, runs on Windows and supports all transactions. SAP GUI for Java is platform independent, so it can run on systems such as macOS or Linux, and it works only with ABAP-based systems. SAP GUI for HTML runs in a web browser and needs the SAP Internet Transaction Server on the server side, which makes installing the front end simpler. The Windows and Java variants talk to the system with the DIAG protocol, which sends compact control and input information instead of whole screens, so they work well over slow networks. The common names "Java GUI" and "Web GUI" are unofficial.

SAP Logon is the launcher. It reads a list of systems from a file named SAPUILandscape.xml, which an administrator usually prepares centrally and hands out to the users. Business users may see a reduced version called SAP Logon Pad that cannot change the list. You select an entry and choose Log On.

Source: Describing SAP GUI and SAP Logon (SAP Learning)

The logon screen: client, user, language

The logon screen asks for the client, the user and the password. The logon language is optional: if you leave it empty, the system uses a default language that an administrator sets with a parameter. The client usually corresponds to a company, and you can reach only the clients in which you have a user master record. The system always supports at least English and German, and the installed languages decide what else you can choose. A button for a new password lets you change your password, but only once a day. With single sign-on you may not type credentials at all, and administrators can add a text of their own to the logon screen.

A logon can hold several sessions, which are the windows you work in. An administrator sets the maximum number of sessions for a logon. When you log on again with the same user, the system offers three choices: end the existing sessions and log on again, open an additional session, or cancel. The second choice can be turned off for the whole system.

Source: Describing SAP GUI and SAP Logon (SAP Learning)

The SAP Easy Access menu

After logon the SAP Easy Access screen shows a tree. SAP documentation distinguishes two menus in it: the user menu and the SAP standard menu. You can use either, and the documentation on favorites talks about adding an item "from the SAP standard menu or user menu". Administrators decide in role maintenance (transaction PFCG) which transactions a role offers; the Menu tab of a role lists them.

You reach a transaction in one of three ways: by following the menu folders, by typing its code into the command field, or through your favorites. Beginners follow the folders; experienced users type codes because it is faster. The code is the stable name: menu folders differ between systems and roles, but SU01 is SU01 everywhere.

Source: Creating Favorites (SAP documentation, older release) and Maintaining User Authorizations with Roles and Profiles (SAP Learning)

The command field

The command field is the box in the toolbar. Since release 4.6 it is closed by default: you open it with the arrow to the left of the Save icon and close it with the arrow to its right. Its dropdown list shows the transaction codes you have used since logon.

A plain code is enough on the Easy Access screen. Inside another transaction you put a command before the code, and the command decides what happens to the window that you are working in.

Entry What it does

/n plus a code, for example /nmb01

Ends the current task and opens the initial screen of the new transaction. Save your work first, because the task that ends is not kept open.

/o plus a code

Opens that transaction in a new session and leaves the current one untouched.

/o alone

Shows a list of all your sessions for this system, where you can also create and end sessions.

/i

Closes the session in which you typed it.

/i plus a number, for example /i3

Closes the session with that number, whichever session you type it in.

/nend

Asks for confirmation and then closes all sessions and logs you off.

/nex

Closes all sessions and logs you off at once, without a confirmation dialog. Unsaved data is lost.

The /n entry is documented in the classic help on transaction codes, which also advises opening a new session when you want to keep the current task. The /o, /i, /nend and /nex entries are listed in the help of SAP Business Client, which shows SAP GUI transactions in tabs; the SAP Learning course quoted above names /nend and /nex for SAP GUI itself. If a command does nothing in your system, ask an administrator, because in Business Client the command field is available only when a setting is enabled.

Favorites

Favorites are your own shortcut list at the top of the Easy Access tree. It can hold transactions, files and web addresses. To add an item from the SAP standard menu or the user menu, select an executable entry and choose Favorites, then Add. To add a transaction you know by code, choose Favorites, then Add Transaction, type the code and choose Continue; the item takes the name of the transaction. To add a web address or a file, choose Favorites, then Add Other Objects, give a name and the address, and choose Continue. A new item is appended to the end of the list.

Source: Creating Favorites (SAP documentation, older release)

F1 and F4 help

Two keys explain a screen to you. F1 shows the help text of the field where the cursor is, and the help icon next to the field does the same. F4 shows the list of possible entries for that field, and you copy a value into the field from the list; the input help button at the right of the field does the same. F1 and F4 are standard system functions, so no program can assign other functions to them. The lists come from search helps of the ABAP Dictionary or from help that a developer programmed. Reading how the Dictionary provides those lists is the topic of DDIC Views and Search Helps.

Source: Field Help, Input Help, and Dropdown Boxes (SAP Library, older release)

Common transactions and their modern alternatives

Documentation, colleagues and error messages quote codes, so you need a short list of the ones you meet first. The table gives the code, what the official documentation says you do there, and, where the cited documentation confirms one, a modern alternative. A dash means that no Fiori app or other alternative is named in that documentation, which is not a statement that none exists; the Fiori apps reference library lists the apps of your release.

Code What you do there Modern alternative

SU01

User Maintenance: add a user by creating a user master record, and assign roles to it.

-

PFCG

Role Maintenance, formerly called the Profile Generator: create roles and generate their authorizations. SAP Fiori catalogs and spaces are also given authorizations here.

-

SE80

Object Navigator: the central entry point to the ABAP Workbench, which opens with the Repository Browser.

ABAP Development Tools in Eclipse; see Classic Tools.

SM59

Maintain RFC destinations and their SNC options.

-

STMS

Start the Transport Management System, which organizes, performs and monitors transports between systems.

gCTS in some landscapes; see Packages, Transports, gCTS and abapGit.

SM37

Job overview: select background jobs and display them.

The Application Jobs app schedules and monitors application jobs; it does not show other kinds of job.

SM12

Managing lock entries: display and delete the locks in use and look at lock statistics.

-

ST22

ABAP dump analysis: list runtime errors and open their short dumps.

The ABAP Runtime Error Viewer of ADT; see Debugging.

/IWFND/MAINT_SERVICE

Activate and maintain OData services on the SAP Gateway server, a step of setting up SAP Fiori apps.

-

The codes SU01, PFCG, SM37, SM12, ST22 and STMS belong to the administration of a system you run yourself, that is on premise and Private Edition. Do not try them as a business user: your role decides which codes you may start, and a missing authorization is the usual reason that a valid code is refused.

Source: Creating Users in SAP S/4HANA Cloud Private Edition (SU01), Maintaining User Authorizations with Roles and Profiles (PFCG), Object Navigator (SE80), Maintaining RFC Destinations and their SNC Options Using Transaction SM59, Transport Management System (STMS), Managing Jobs from the Job Overview (SM37), Application Jobs, Managing Lock Entries (SM12), ABAP Dump Analysis (ST22), Displaying ABAP Runtime Errors and Activating the OData Services (/IWFND/MAINT_SERVICE)

Summary

  • SAP Logon lists the systems; SAP GUI shows the screens. You give a client, a user and optionally a language, and one logon can hold several sessions.

  • After logon the SAP Easy Access menu offers a user menu and the SAP standard menu; you start a transaction by menu path, by code in the command field, or from your favorites.

  • /n plus a code replaces the current task, /o plus a code opens a new session, /i closes one session, and /nend logs off after a confirmation; /nex logs off without asking.

  • F1 explains a field and F4 lists its possible values.

  • The common administration codes are SU01, PFCG, SM59, STMS, SM37, SM12, ST22 and SE80, and /IWFND/MAINT_SERVICE sets up OData services for Fiori apps. Most of them are for the people who run a system, not for business users.
