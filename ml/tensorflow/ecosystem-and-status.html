Ecosystem & Project Status

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

TensorFlow is no longer the fast-moving, everything-included platform that older books and tutorials describe. Since the Keras 3 rewrite and the 2.21 release the project is run mostly as a stable, maintained core, while new model-building work has moved to Keras 3 (multi-backend) and KerasHub. This page explains how to read the release process, which parts of the ecosystem are alive, which are archived, and where their successors live. It is the status companion to TensorFlow overview, Installation and Devices.

It targets Python 3.13 and TensorFlow 2.21 with Keras 3.15 (TensorFlow 2.22 is labelled "upcoming"), and was checked against the official documentation on 2026-10-30. Examples were run on Python 3.13 with TensorFlow 2.21 and Keras 3.15 (CPU) on 2026-10-31. For a framework-neutral comparison see Choosing a Framework and, for the sibling framework, the PyTorch ecosystem.

How TensorFlow is released

The release history is public in two places:

  • The GitHub releases page of the tensorflow/tensorflow repository lists tagged releases and release candidates.

  • RELEASE.md at the repository root is the human-written changelog. Each version has the headings Breaking Changes, Known Caveats, Major Features and Improvements, Bug Fixes and Other Changes and a thanks list. The file on the master branch also contains sections for versions still under development, with template placeholders that have not been filled in yet. At the time of checking, its newest sections were headed 2.23.0 and 2.22.0. Treat anything in those sections as "upcoming" until a release is tagged; the stable line documented on this site is 2.21.

TensorFlow follows semantic versioning for its public API in the 2.x line (see the versioning guide linked below), with the usual exceptions for the experimental namespaces and for private symbols. In practice:

  • Patch releases (2.21.x) carry bug and security fixes.

  • Minor releases (2.22, 2.23, …​) update dependencies and Python support and may remove deprecated symbols; read RELEASE.md "Breaking Changes" before upgrading.

  • Anything under tf.compat.v1, tf.experimental or tf.raw_ops carries weaker guarantees than the rest.

# Which versions are on PyPI, and what do I have?
python -m pip index versions tensorflow
python - <<'PY'
import tensorflow as tf, keras
print("TensorFlow", tf.__version__)
print("Keras", keras.__version__)
print("tf.keras is", tf.keras.__name__)  # keras._tf_keras.keras: Keras 3 from TF 2.16 on
PY

Source: https://www.tensorflow.org/versions

The maintenance focus of 2.21

The announcement for TensorFlow 2.21 (published on the Google Developers blog in March 2026) states the direction explicitly: the team will concentrate on security and critical bug fixes, dependency updates (including support for new Python releases in minor versions) and reviewing critical community fixes. The post names the surrounding libraries that get the same treatment: tf.data, TensorFlow Serving, TFX, TensorFlow Data Validation, Transform, Model Analysis, Recommenders, Text, TensorBoard and TensorFlow Quantum. For new generative-AI work the post points to Keras 3, JAX and PyTorch rather than to new TensorFlow-specific features.

What this means for you:

  • Existing TensorFlow code, SavedModels and serving stacks keep working; the core is stable rather than abandoned.

  • Do not expect new layers, new distribution strategies or new tutorials in the core. New model families appear in KerasHub (see below) and in other frameworks first.

  • Plan new greenfield projects with the framework choice in mind: Keras 3 lets the same model code run on the TensorFlow, JAX or PyTorch backend (see Keras multi-backend).

The same announcement reports that TensorFlow Lite has been renamed LiteRT and is developed as a separate project; see LiteRT on-device inference.

Source: https://developers.googleblog.com/whats-new-in-tensorflow-221/

TensorFlow Addons

TensorFlow Addons collected contributions that did not belong in the core or in Keras (extra optimizers such as AdamW and LAMB, the CRF layers, image ops, activations such as Mish, metrics and so on). Its development and new features ended and the planned end of life was May 2024; the repository is now archived and read-only. The final release (0.22.0) supports TensorFlow 2.12 to 2.14 on Python 3.9 to 3.11, so it will not install cleanly beside TensorFlow 2.21 and Keras 3.

Migration is symbol by symbol. Many Addons features were upstreamed under the same or similar names, for example the AdamW optimizer is available as keras.optimizers.AdamW, Mish as keras.activations.mish, and MultiHeadAttention as keras.layers.MultiHeadAttention. For other features search Keras, KerasHub and the core tf.* namespaces before copying code out of the archived repository. Check each replacement’s semantics, because defaults (for example weight-decay handling) differ between implementations.

Source: https://github.com/tensorflow/addons

KerasCV, KerasNLP and KerasHub

KerasCV (computer vision) and KerasNLP (language) were separate libraries built on Keras. Their model work is consolidated in KerasHub, a single library of pre-trained model presets that runs on every Keras 3 backend. The KerasCV repository was archived in March 2026, and its README states that it will not continue to work as is, that nothing will break, and that new vision development belongs in KerasHub. See KerasHub for usage; the following minimal check shows the import you migrate to.

# pip install keras keras-hub
import keras
import keras_hub  # replaces: import keras_cv / import keras_nlp

print(keras.__version__)
print(hasattr(keras_hub, "models"))  # presets live under keras_hub.models

Source: https://github.com/keras-team/keras-cv and https://keras.io/keras_hub/

TensorFlow Hub and Kaggle Models

The tensorflow/hub README opens with the statement that TensorFlow Hub has moved to Kaggle Models. Since November 2023, tfhub.dev links redirect to their Kaggle Models counterparts, the tensorflow_hub library continues to download models first uploaded to tfhub.dev, and a list of unmigrated assets was deleted in March 2024. The tensorflow.org Hub page itself still shows older hub.KerasLayer("https://tfhub.dev/...") examples, which illustrates why old tutorials need care.

import tensorflow as tf
import tensorflow_hub as hub  # pip install tensorflow-hub "setuptools<81"

# Old-style URLs still resolve through the redirect, but check the model
# page on Kaggle first: format (SavedModel, TF2) and license are listed there.
layer = hub.KerasLayer("https://tfhub.dev/google/nnlm-en-dim128/2", trainable=False)
emb = layer(tf.constant(["the rain in spain", "falls mainly"]))
print(emb.shape)  # (2, 128)

Source: https://github.com/tensorflow/hub and https://www.tensorflow.org/hub

Two practical issues show up with tensorflow_hub 0.16.1 in a fresh Python 3.13 environment. First, it imports pkg_resources, which recent setuptools releases no longer ship (setuptools 84 in the test environment), so import tensorflow_hub fails with ModuleNotFoundError: No module named 'pkg_resources' until you install setuptools<81. Second, hub.KerasLayer is a tf_keras (Keras 2) layer: calling it directly on tensors works, as above, but adding it to a Keras 3 model raises ValueError: Only instances of keras.Layer can be added to a Sequential model. To build models around Hub layers, use the tf_keras path described below.

tf_keras and legacy Keras 2

Since TensorFlow 2.16 the name tf.keras resolves to Keras 3. Two ways keep Keras 2 behaviour, both described on the Keras 3 page:

  1. Install the standalone tf_keras package (the Keras 2 API under a new name, maintenance only) and import it explicitly with import tf_keras. This is the safer option because it affects only your code.

  2. Install tf_keras and set the environment variable TF_USE_LEGACY_KERAS=1 before importing TensorFlow, which redirects tf.keras for every package in the process, including third-party libraries.

python -m pip install tf_keras
TF_USE_LEGACY_KERAS=1 python -c "import tensorflow as tf; print(tf.keras.__name__)"   # tf_keras.api._v2.keras

Source: https://keras.io/keras_3/

Common mistakes

  • Following a tutorial that imports tensorflow_addons, keras_cv or kerastuner unchanged and then fighting version conflicts. Check the project’s status first.

  • Assuming tf.keras is Keras 2. From TensorFlow 2.16 it is Keras 3.

  • Reading the master RELEASE.md as a statement of what 2.21 contains; its top sections describe unreleased versions.

  • Treating "maintenance mode" as "deprecated". The 2.21 announcement describes a focus on security, bug fixes and dependency updates, not a removal plan; still, do not rely on new features landing.

  • Pinning only tensorflow and forgetting keras, tensorboard and ml_dtypes, which are resolved as dependencies and can change behaviour between minors.
