= Hybrid Apps
:description: Landing page for the Hybrid Apps reference under Apps -- what hybrid and cross-platform app development means, the tools used to build and run React Native, Expo, Flutter, Ionic and Capacitor apps, and the full Flutter and Dart and Ionic and Capacitor references.
:keywords: hybrid apps, cross-platform, React Native, Expo, Ionic, Capacitor, Flutter, WebView, native toolchains, Android Studio, Xcode, emulator, simulator

A hybrid app is written once, mostly in web technologies or a cross-platform language, and runs on Android and iOS: either inside a native WebView with a bridge to device APIs (Ionic with Capacitor), or as a JavaScript or TypeScript program that drives native UI components (React Native with Expo). A third approach, Flutter, draws its own UI with a Dart codebase. This subsection collects the tools that every such project needs, and contains the full references for Flutter with Dart and for Ionic with Capacitor; the React Native reference lives in its own subsection. It is written for web developers who want to ship a mobile app, and for mobile developers choosing between a hybrid framework and a native toolchain.

== What's covered

* xref:apps/hybrid/flutter/index.adoc[Flutter and Dart]: the Dart language, widgets, rendering, state, navigation, data, platform integration, testing and release for Flutter apps, built around the Trailhead example.
* xref:apps/hybrid/ionic/index.adoc[Ionic and Capacitor]: Ionic components, the Capacitor native bridge and plugins, navigation, data, platform integration, testing and release, with the same Trailhead example in Angular.
* xref:apps/hybrid/ides-and-tools.adoc[Hybrid Apps: IDEs & Tools]: the editors, the native toolchains (Android Studio and Xcode), the emulators and simulators, and the Expo, Ionic and Capacitor tooling used for hybrid and cross-platform apps, with links to each official page.

== Reading path

. Start with xref:apps/hybrid/ides-and-tools.adoc[Hybrid Apps: IDEs & Tools] to set up an editor and the native toolchains, which every hybrid project needs even though the application code is not native.
. To choose a stack, compare xref:apps/hybrid/flutter/getting-started.adoc[Getting Started with Flutter] and xref:apps/hybrid/ionic/getting-started.adoc[Getting Started with Ionic and Capacitor], which both include a comparison table.
. For a web codebase packaged as a store app, read xref:apps/hybrid/ionic/index.adoc[Ionic and Capacitor]; for a Dart codebase with its own renderer, read xref:apps/hybrid/flutter/index.adoc[Flutter and Dart].
. For a JavaScript and TypeScript codebase that renders native components, continue with xref:apps/react-native/index.adoc[React Native], starting from xref:apps/react-native/getting-started.adoc[Getting Started with React Native].
. For Kotlin code shared between platforms, read xref:apps/kotlin-multiplatform/index.adoc[Kotlin Multiplatform] instead.
. For a native-only comparison, read xref:apps/android/index.adoc[Android] and xref:apps/apple/index.adoc[Apple Platforms].
