Welcome to the Apple Platforms reference. It documents how to build *native* apps for Apple devices -- iPhone,
iPad, Mac, Apple Watch and Apple Vision Pro -- with Apple's own tools, frameworks and language: Xcode, Swift,
SwiftUI and the system frameworks underneath. The result runs directly on each platform's UI toolkit and system
services, with no cross-platform layer in between.

This section documents the **27 releases**: iOS, iPadOS, macOS, watchOS and visionOS 27, built with **Xcode 27**
and **Swift 6.4**. Every example targets a **deployment minimum of 26**, the previous year's releases, so an app
built this way still runs on devices that have not updated yet; APIs that exist only in the 27 SDKs are called
out as "new in 27" in the prose and guarded with `if #available(iOS 27, macOS 27, watchOS 27, visionOS 27, *)` in
code. Apple's operating systems use year-based version numbers since 2025, so the releases after 18 are 26 (2025)
and 27 (2026); there is no iOS 19. macOS 26 is *Tahoe* and macOS 27 is *Golden Gate*.

SwiftUI is the primary UI framework on every page, because it is the only one that runs on all five platforms.
UIKit (iOS, iPadOS, tvOS and visionOS) and AppKit (macOS) are documented where an app still needs them: for
existing codebases, for features SwiftUI does not cover yet, and for mixing the two. This section does not
re-explain the Swift language itself -- for optionals, generics, protocols, macros, result builders, concurrency
and the rest, see the xref:programming-languages/swift/index.adoc[Swift Reference], and for the Objective-C side
of mixed codebases, the xref:programming-languages/objective-c/index.adoc[Objective-C Reference].

== How Apple app development got here

[cols="1,4",options="header"]
|===
| Year | What changed

| 2008
| The iPhone SDK opened the phone to third-party apps, written in Objective-C against Cocoa Touch and its UI
  framework, UIKit -- the mobile sibling of the Mac's Cocoa and AppKit. The App Store launched the same year.

| 2014
| Swift was introduced as a safer, modern language for Apple platforms, able to mix with Objective-C in the same
  app target.

| 2019
| SwiftUI brought a declarative UI framework that runs on every Apple platform, with state-driven views instead
  of view controllers and manual updates.

| 2021
| Swift concurrency arrived: `async`/`await`, structured tasks and actors, with `@MainActor` for UI code and
  SwiftUI's `.task` modifier tying work to a view's lifetime.

| 2023
| The Observation framework (`@Observable`) replaced `ObservableObject` as the way to drive SwiftUI from model
  data, SwiftData added Swift-native persistence, and visionOS was announced.

| 2025
| Operating system versions became year-based, jumping to 26 on every platform. The 26 releases introduced the
  Liquid Glass design language across all platforms and the Foundation Models framework for on-device Apple
  Intelligence.

| 2026
| The 27 releases: in Xcode 27 `@State` is a macro, `ContentBuilder` replaces the type-specific result builders,
  apps built with the 27 SDK must adopt the UIKit scene-based life cycle, and Swift 6.4 ships with Xcode 27.
|===

Much of what older books, tutorials and forum answers describe predates this timeline: `NavigationView`,
`ObservableObject`-first data flow, app-delegate-only life cycles, completion-handler concurrency, ClockKit
complications and pre-Liquid Glass bar styling. These pages document the current approach and name the older
one only where a reader is likely to meet it in an existing codebase.

== The FieldNotes app

Every code example across these pages is a slice of one running app, *FieldNotes*: a notes app that keeps
*notes* grouped into *notebooks*, with tags, pinning, search and, later in the section, persistence, sync,
widgets, Siri and Shortcuts actions, and on-device summaries. It lives in one Xcode project,
`FieldNotes.xcodeproj`, with a multiplatform `FieldNotes` app target for iOS, iPadOS, macOS and visionOS, a
separate `FieldNotesWatch` target for watchOS, a `FieldNotesWidgets` widget extension and a `FieldNotesTests`
target for Swift Testing. Its bundle identifiers start with `com.example.fieldnotes`, and the app and its
extensions share data through the App Group `group.com.example.fieldnotes`.

The code is split into local Swift packages: `FieldNotesKit` holds the `FieldNotesModel` module (the `Note` and
`Notebook` types) and the `FieldNotesServices` module (the `@Observable` `NoteStore` and the service protocols
such as `NoteSyncing` and `SummaryGenerating`), and `FieldNotesUI` holds the shared views and styles. The
`FieldNotesApp` entry point creates the store once and injects it into the environment; `ContentView` is a
three-column `NavigationSplitView` of notebooks, notes and the selected note, and the macOS and visionOS builds
add a Settings window, a menu bar extra and an immersive map space. The data, system and device pages then grow
it further: SwiftData persistence with CloudKit sync behind a `NotePersisting` layer, a pinned-notes widget, a
Control Center control and a field-trip Live Activity, App Intents for Siri and Shortcuts, on-device summaries
with Foundation Models, location and photo attachments, Keychain and passkey sign-in, and a *FieldNotes Pro*
subscription. Because every page extends the same codebase, the pages compose into one coherent app rather
than a set of unrelated snippets.
