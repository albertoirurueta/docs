= Resources, Endpoints and Authentication
:description: The Foundry resource and the legacy resource kinds, the endpoints each Foundry Tool uses, custom subdomains, and authentication with keys, STS tokens and Microsoft Entra ID, with Bicep for Bookshelf's keyless setup.
:keywords: Foundry resource, AIServices, CognitiveServices, single-service resource, az cognitiveservices account create, list-kinds, custom subdomain, cognitiveservices.azure.com, services.ai.azure.com, project endpoint, Ocp-Apim-Subscription-Key, Ocp-Apim-Subscription-Region, issueToken, Microsoft Entra ID, Cognitive Services User, Azure AI User, Foundry roles, DefaultAzureCredential, managed identity, disableLocalAuth, Bicep

include::partial$azure-disclaimer.adoc[]

This page targets Azure CLI 2.90.0, Bicep 0.47.16 and the `Microsoft.CognitiveServices/accounts` API version
`2025-06-01`. Code samples use `azure-identity` 1.26.0 (Python), `Azure.Identity` 1.21.0 (.NET) and
`com.azure:azure-identity` 1.18.7 (Java), checked on 2026-10-06.

Every Foundry Tool call needs two things: an **endpoint** to send the request to and a **credential** to prove who
is calling. Both come from the Azure resource you create first. This page covers which resource to create, which
endpoint each tool uses, and how to authenticate without keys.

The examples use these shell variables:

[source,bash]
----
RG=rg-bookshelf
LOCATION=eastus2
FOUNDRY=foundry-bookshelf
----

Source: https://learn.microsoft.com/azure/ai-services/multi-service-resource[Create a Foundry resource]

== Resource kinds

image::azure-foundry-resource-model.svg["Foundry resource model: one AIServices resource with projects, tool and project endpoints, regional Speech and global Translator hosts, and keys vs Entra ID",width=820]

The `--kind` of a `Microsoft.CognitiveServices/accounts` resource decides which APIs it exposes:

[cols="2,4", options="header"]
|===
| Kind | What it is

| `AIServices` (the **Foundry resource**)
| The recommended kind. One endpoint and one set of keys for Azure OpenAI and other Foundry Models, plus all the
Foundry Tools: Speech, Translator, Language, Vision, Document Intelligence, Content Understanding and Content
Safety. It can contain **projects**, which group agents, evaluations and connections. Bookshelf's
`foundry-bookshelf` is this kind.

| `CognitiveServices` (legacy multi-service)
| The older multi-service resource. It exposes the tools but not Foundry Models or projects. Convert it in place
(see below) instead of creating new ones.

| Single-service kinds
| One tool per resource. `FormRecognizer` (Document Intelligence), `Face` and `TextAnalytics` (Language) are
confirmed. Other common values are `SpeechServices`, `TextTranslation`, `ComputerVision`, `ContentSafety` and
`ImmersiveReader`. Run `az cognitiveservices account list-kinds` to get the current list before you rely on one.
|===

A single-service resource is still required in a few cases:

* **commitment tiers** (prepaid monthly capacity) are bought per single-service resource
* some **containers**, especially disconnected ones, must be billed against a single-service resource
* a few features, such as Immersive Reader, still need their own kind

You can convert a legacy multi-service resource (for example an older `aisvc-bookshelf`) to a Foundry resource
without changing its endpoint or keys:

[source,bash]
----
az cognitiveservices account update \
  --name aisvc-bookshelf \
  --resource-group "$RG" \
  --kind AIServices
----

Source: https://learn.microsoft.com/cli/azure/cognitiveservices/account#az-cognitiveservices-account-update[Azure CLI reference -- az cognitiveservices account update]

=== In the Azure portal

. Open the Foundry portal at `https://ai.azure.com` and select *Create new* -> *Foundry resource*. Alternatively,
  in the Azure portal search for *Foundry* and select *Create a Foundry resource*.
. **Basics**: subscription, resource group `rg-bookshelf`, name `foundry-bookshelf`, region *East US 2*. The name
  becomes the **custom subdomain**.
. **Project**: accept the default project name or enter `proj-bookshelf`.
. **Networking**: leave *All networks* for now.
  xref:cloud/azure/foundry-tools/networking-security-and-responsible-ai.adoc[] adds a private endpoint later.
. **Identity**: turn on the *System assigned* managed identity. Customer-managed keys and some tools need it.
. *Review + create*, then *Create*.

=== With the Azure CLI

[source,bash]
----
az cognitiveservices account create \
  --name "$FOUNDRY" \
  --resource-group "$RG" \
  --location "$LOCATION" \
  --kind AIServices \
  --sku S0 \
  --custom-domain "$FOUNDRY" \
  --assign-identity \
  --allow-project-management \
  --yes

az cognitiveservices account project create \
  --name "$FOUNDRY" \
  --resource-group "$RG" \
  --project-name proj-bookshelf \
  --location "$LOCATION"

az cognitiveservices account list-kinds --output table
----

Source: https://learn.microsoft.com/cli/azure/cognitiveservices/account#az-cognitiveservices-account-create[Azure CLI reference -- az cognitiveservices account create]

== Endpoints

[cols="2,3,3", options="header"]
|===
| Endpoint | Form | Used by

| Tool endpoint
| `+https://<name>.cognitiveservices.azure.com/+`
| Language, Vision, Document Intelligence, Content Understanding, Content Safety, Speech REST (batch, fast
transcription), document translation, and the SDKs of all of these.

| Project endpoint
| `+https://<name>.services.ai.azure.com/api/projects/<project>+`
| The Foundry SDK (`azure-ai-projects`): agents, evaluations, connections. Voice Live and some Language features
use the `+https://<name>.services.ai.azure.com/+` host.

| Azure OpenAI endpoint
| `+https://<name>.openai.azure.com/+`
| Foundry Models through the OpenAI-compatible API. Not a Foundry Tool, but on the same resource.

| Regional Speech hosts
| `+https://<region>.stt.speech.microsoft.com+`, `+https://<region>.tts.speech.microsoft.com+`
| Older Speech SDK and REST samples that use a key and region instead of an endpoint.

| Global Translator host
| `+https://api.cognitive.microsofttranslator.com/+`
| Text translation. With a key, also send `Ocp-Apim-Subscription-Region: <region>` (for example `eastus2`).
With Entra ID, use the custom-subdomain endpoint instead.
|===

=== Custom subdomains

A custom subdomain (`--custom-domain`) gives the resource the `+<name>.cognitiveservices.azure.com+` host
name. It is **required for Microsoft Entra ID authentication and for virtual networks**, and it **cannot be changed
or removed later**. Pick the name with care. Speech is the exception: it still accepts the regional host names for
key-based calls, but needs the custom subdomain for Entra ID and private endpoints.

Source: https://learn.microsoft.com/azure/ai-services/cognitive-services-custom-subdomains[Custom subdomain names]

== Authentication

=== Keys

Every resource has two keys, `KEY1` and `KEY2`. Send one in the `Ocp-Apim-Subscription-Key` header. Two keys let
you rotate without downtime: move clients to `KEY2`, regenerate `KEY1`, move them back, then regenerate `KEY2`.
Store keys in xref:cloud/azure/key-vault-and-secrets.adoc[Key Vault], never in code.

[source,bash]
----
az cognitiveservices account keys list --name "$FOUNDRY" --resource-group "$RG"
KEY=$(az cognitiveservices account keys list --name "$FOUNDRY" --resource-group "$RG" --query key1 -o tsv)

az cognitiveservices account keys regenerate \
  --name "$FOUNDRY" --resource-group "$RG" --key-name Key2

curl -s "https://$FOUNDRY.cognitiveservices.azure.com/language/:analyze-text?api-version=2024-11-01" \
  -H "Ocp-Apim-Subscription-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"kind":"LanguageDetection","analysisInput":{"documents":[{"id":"1","text":"Hola mundo"}]}}'
----

Source: https://learn.microsoft.com/azure/ai-services/rotate-keys[Rotate keys]

=== STS token exchange

Speech and Translator also accept a short-lived bearer token exchanged for a key. The token lasts **10 minutes**.
This is useful for browser or mobile clients, because the key stays on your server:

[source,bash]
----
TOKEN=$(curl -s -X POST \
  "https://$FOUNDRY.cognitiveservices.azure.com/sts/v1.0/issueToken" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Content-Length: 0")
----

Source: https://learn.microsoft.com/azure/ai-services/authentication[Authenticate requests to Foundry Tools]

=== Microsoft Entra ID and roles

With Entra ID the caller gets an access token for the scope `https://cognitiveservices.azure.com/.default` and
sends it as `Authorization: Bearer <token>`. The identity needs a **data-plane role** on the resource:

[cols="2,4", options="header"]
|===
| Role | Grants

| `Cognitive Services User`
| Call any tool's data-plane APIs and list keys. The usual role for an application.

| Service-specific roles
| For example `Cognitive Services Speech User`, `Cognitive Services Language Reader`,
`Cognitive Services Face Recognizer` and `Cognitive Services OpenAI User`. Use them to narrow access to one tool.

| Foundry roles: `Azure AI User`, `Azure AI Project Manager`, `Azure AI Account Owner`, `Azure AI Owner`
| The Foundry portal's roles, being renamed to *Foundry User*, *Foundry Project Manager*, *Foundry Account Owner*
and *Foundry Owner*. *User* can build and call agents and models in a project. The others add project and
resource management.
|===

`Owner` and `Contributor` are **control-plane** roles. They can create the resource and read its keys, but they
have **no data actions**, so a token for a user with only `Owner` gets `401` from a tool endpoint.

Source: https://learn.microsoft.com/azure/ai-foundry/concepts/rbac-azure-ai-foundry[Role-based access control for Microsoft Foundry]

=== `DefaultAzureCredential` in code

`DefaultAzureCredential` tries the managed identity in Azure and your developer sign-in (Azure CLI, Visual Studio,
IntelliJ) locally, so the same code runs in both places.

[source,python]
----
from azure.identity import DefaultAzureCredential
from azure.ai.textanalytics import TextAnalyticsClient

client = TextAnalyticsClient(
    endpoint="https://foundry-bookshelf.cognitiveservices.azure.com/",
    credential=DefaultAzureCredential(),
)
print(client.detect_language(["Hola mundo"])[0].primary_language.name)
----

Source: https://learn.microsoft.com/azure/ai-services/authentication#authenticate-with-microsoft-entra-id[Authenticate with Microsoft Entra ID]

[source,csharp]
----
using Azure.AI.TextAnalytics;
using Azure.Identity;

var client = new TextAnalyticsClient(
    new Uri("https://foundry-bookshelf.cognitiveservices.azure.com/"),
    new DefaultAzureCredential());

DetectedLanguage language = client.DetectLanguage("Hola mundo");
Console.WriteLine(language.Name);
----

Source: https://learn.microsoft.com/dotnet/api/overview/azure/ai.textanalytics-readme[Azure Text Analytics client library for .NET]

[source,java]
----
import com.azure.ai.textanalytics.TextAnalyticsClient;
import com.azure.ai.textanalytics.TextAnalyticsClientBuilder;
import com.azure.identity.DefaultAzureCredentialBuilder;

TextAnalyticsClient client = new TextAnalyticsClientBuilder()
    .endpoint("https://foundry-bookshelf.cognitiveservices.azure.com/")
    .credential(new DefaultAzureCredentialBuilder().build())
    .buildClient();

System.out.println(client.detectLanguage("Hola mundo").getName());
----

Source: https://learn.microsoft.com/java/api/overview/azure/ai-textanalytics-readme[Azure Text Analytics client library for Java]

Assign the role to the identity that runs the code:

[source,bash]
----
az role assignment create \
  --assignee "$(az ad signed-in-user show --query id -o tsv)" \
  --role "Cognitive Services User" \
  --scope "$(az cognitiveservices account show --name "$FOUNDRY" --resource-group "$RG" --query id -o tsv)"
----

Source: https://learn.microsoft.com/azure/ai-services/authentication#assign-a-role-to-a-service-principal[Assign a role]

=== Disabling local authentication

Once every client uses Entra ID, turn keys off. `disableLocalAuth: true` makes the resource reject
`Ocp-Apim-Subscription-Key` and STS tokens. The built-in Azure Policy *Azure AI Services resources should have key
access disabled (disable local authentication)* audits or denies resources that still allow keys.

[source,bash]
----
az resource update \
  --ids "$(az cognitiveservices account show --name "$FOUNDRY" --resource-group "$RG" --query id -o tsv)" \
  --set properties.disableLocalAuth=true
----

Source: https://learn.microsoft.com/azure/ai-services/disable-local-auth[Disable local authentication]

== Bookshelf: keyless Foundry resource in Bicep

`catalog-api` and `orders-api` run in Container Apps, each with its own user-assigned managed identity:
`id-catalog-api` and `id-orders-api`, as in the rest of the Azure section. The Bicep below creates
`foundry-bookshelf` with keys disabled, the `proj-bookshelf` project, and a `Cognitive Services User` role
assignment for both identities.

[source,bicep]
----
param location string = resourceGroup().location
param principalIds array // principal IDs of id-catalog-api and id-orders-api

resource foundry 'Microsoft.CognitiveServices/accounts@2025-06-01' = {
  name: 'foundry-bookshelf'
  location: location
  kind: 'AIServices'
  sku: { name: 'S0' }
  identity: { type: 'SystemAssigned' }
  properties: {
    customSubDomainName: 'foundry-bookshelf'
    disableLocalAuth: true
    allowProjectManagement: true
    publicNetworkAccess: 'Enabled'
  }
}

resource project 'Microsoft.CognitiveServices/accounts/projects@2025-06-01' = {
  parent: foundry
  name: 'proj-bookshelf'
  location: location
  identity: { type: 'SystemAssigned' }
  properties: {}
}

var cognitiveServicesUser = subscriptionResourceId(
  'Microsoft.Authorization/roleDefinitions', 'a97b65f3-24c7-4388-baec-2e87135dc908')

resource userRoles 'Microsoft.Authorization/roleAssignments@2022-04-01' = [for principalId in principalIds: {
  scope: foundry
  name: guid(foundry.id, principalId, cognitiveServicesUser)
  properties: {
    roleDefinitionId: cognitiveServicesUser
    principalId: principalId
    principalType: 'ServicePrincipal'
  }
}]

output endpoint string = foundry.properties.endpoint
----

Source: https://learn.microsoft.com/azure/templates/microsoft.cognitiveservices/accounts[Bicep reference -- Microsoft.CognitiveServices/accounts]

Deploy it with:

[source,bash]
----
CATALOG_PRINCIPAL=$(az identity show --name id-catalog-api --resource-group "$RG" --query principalId -o tsv)
ORDERS_PRINCIPAL=$(az identity show --name id-orders-api --resource-group "$RG" --query principalId -o tsv)

az deployment group create \
  --resource-group "$RG" \
  --template-file foundry.bicep \
  --parameters principalIds="[\"$CATALOG_PRINCIPAL\",\"$ORDERS_PRINCIPAL\"]"
----

Source: https://learn.microsoft.com/cli/azure/deployment/group#az-deployment-group-create[Azure CLI reference -- az deployment group create]

== Clean up

[source,bash]
----
az cognitiveservices account delete --name "$FOUNDRY" --resource-group "$RG"
az cognitiveservices account purge --name "$FOUNDRY" --resource-group "$RG" --location "$LOCATION"
----

Source: https://learn.microsoft.com/azure/ai-services/recover-purge-resources[Recover or purge deleted resources]

A deleted resource is soft-deleted for 48 hours and keeps its custom subdomain reserved. Purge it to reuse the name
straight away.
