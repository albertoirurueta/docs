== Pricing

=== F0 vs S0

* **F0 (free)** is available on single-service resources for most tools. It has a small monthly allowance (for
  example 5,000 Language text records, 2 million Translator characters, 5 audio hours of speech to text, 500
  Document Intelligence pages) and low rate limits. One F0 resource per tool per subscription. Good for
  prototypes, never for production.
* **S0 (standard)** is pay-as-you-go. A Foundry resource (`AIServices`) only offers S0.

=== Billing units per tool

[cols="2,3", options="header"]
|===
| Tool | Billing unit

| Speech to text
| Audio hours (real-time, fast and batch priced differently). Custom speech adds endpoint hosting per hour.

| Text to speech
| Characters synthesized (neural and HD voices priced differently). Custom voice adds training and hosting.

| Voice Live
| Per token, by tier (Pro, Standard, Lite).

| Translator
| Characters for NMT text and document translation. Tokens for LLM translation.

| Language
| Text records of up to 1,000 characters each.

| Vision, Face
| Transactions (one image and one feature per transaction).

| Document Intelligence
| Pages, priced per model family (read, prebuilt, custom) and add-on.

| Content Understanding
| Content extraction per page, minute or image, plus the tokens of the models you bring for field extraction.

| Content Safety
| Text records (1,000 characters) and images.

| Azure AI Search
| Search units per hour (separate resource), plus semantic ranker queries and agentic retrieval tokens.
|===

=== Commitment tiers

A **commitment tier** is a prepaid monthly quantity (for example a fixed number of audio hours or pages) at a lower
unit price, with overage at a discounted rate. Commitment tiers are purchased on **single-service** resources
(`SpeechServices`, `TextTranslation`, `TextAnalytics`, `FormRecognizer` and so on), not on the Foundry resource. They
are also how disconnected containers are billed.

Source: https://learn.microsoft.com/azure/ai-services/commitment-tier[Purchase commitment tier pricing]

Estimate costs with the https://azure.microsoft.com/pricing/calculator/[Azure pricing calculator] and the
https://azure.microsoft.com/pricing/details/cognitive-services/[Foundry Tools pricing pages].

== Quotas and rate limits

S0 resources start at about **10 transactions per second (TPS)** per tool, with higher defaults on some tools:

[cols="2,4", options="header"]
|===
| Tool | Default limits (S0)

| Language
| Up to 1,000 requests per minute; sync requests take up to 5 documents (25 for some features, 1,000 for language
detection) of 5,120 characters each.

| Translator
| 50,000 characters per request (NMT). 2 million characters per hour per resource (S1 rate).

| Speech to text
| 100 concurrent real-time requests. Fast transcription: files up to 500 MB and 5 hours.

| Document Intelligence
| 15 TPS for analyze; 50 TPS for get-result polling.

| Content Safety
| 1,000 requests per 10 seconds for text and image analysis.

| Vision Image Analysis
| 30 TPS (S1).
|===

Source: https://learn.microsoft.com/azure/ai-services/document-intelligence/service-limits[Document Intelligence service limits]

=== Autoscale

**Autoscale** (`dynamicThrottlingEnabled`) lets a resource temporarily exceed its default rate limit when the
backend has capacity. It doesn't guarantee capacity, so you still need retries.

[source,bash]
----
az resource update \
  --ids "$(az cognitiveservices account show --name "$FOUNDRY" --resource-group "$RG" --query id -o tsv)" \
  --set properties.dynamicThrottlingEnabled=true
----

Source: https://learn.microsoft.com/azure/ai-services/autoscale[Autoscale Foundry Tools limits]

=== Handling 429

When you exceed a limit, the tool returns **`429 Too Many Requests`**, usually with a `Retry-After` header. The
Azure SDKs retry automatically with exponential backoff. Tune their retry policy rather than writing your own loop:

[source,python]
----
from azure.ai.textanalytics import TextAnalyticsClient
from azure.identity import DefaultAzureCredential

client = TextAnalyticsClient(
    endpoint="https://foundry-bookshelf.cognitiveservices.azure.com/",
    credential=DefaultAzureCredential(),
    retry_total=6,           # attempts
    retry_backoff_factor=1.0,  # seconds, exponential
    retry_backoff_max=60,
)
----

Source: https://learn.microsoft.com/azure/developer/python/sdk/azure-sdk-library-usage-patterns[Azure SDK for Python usage patterns]

[source,csharp]
----
using Azure.AI.TextAnalytics;
using Azure.Core;
using Azure.Identity;

var options = new TextAnalyticsClientOptions();
options.Retry.Mode = RetryMode.Exponential;
options.Retry.MaxRetries = 6;
options.Retry.Delay = TimeSpan.FromSeconds(1);
options.Retry.MaxDelay = TimeSpan.FromSeconds(60);

var client = new TextAnalyticsClient(
    new Uri("https://foundry-bookshelf.cognitiveservices.azure.com/"),
    new DefaultAzureCredential(), options);
----

Source: https://learn.microsoft.com/dotnet/azure/sdk/configure-retries[Configure retries in the Azure SDK for .NET]

For REST calls, honor `Retry-After`:

[source,bash]
----
curl -s -o /dev/null -w "%{http_code} %header{retry-after}\n" \
  "https://$FOUNDRY.cognitiveservices.azure.com/contentsafety/text:analyze?api-version=2024-09-01" \
  -H "Authorization: Bearer $(az account get-access-token --resource https://cognitiveservices.azure.com --query accessToken -o tsv)" \
  -H "Content-Type: application/json" -d '{"text":"hello"}'
----

Source: https://learn.microsoft.com/azure/ai-services/content-safety/quickstart-text[Content Safety text quickstart]

== Containers

Many tools ship as Docker containers from `mcr.microsoft.com/azure-cognitive-services/`. The container runs the
model on your hardware, so data never leaves your network. A **connected** container still sends **usage
metering** (not your data) to an Azure resource for billing.

[cols="2,4", options="header"]
|===
| Tool | Containers

| Speech
| Speech to text, custom speech to text, neural text to speech, fast transcription (preview), language
identification.

| Language
| NER, PII, sentiment, key phrases, language detection, CLU, Text Analytics for health, summarization.

| Translator
| Text translation and document translation (gated).

| Vision
| Read OCR (`read`).

| Document Intelligence
| Read, layout, and several prebuilt models (v4.0 containers for read and layout).

| Content Safety
| Text and image analysis (gated).
|===

Source: https://learn.microsoft.com/azure/ai-services/cognitive-services-container-support[Foundry Tools containers]

**Disconnected containers** run fully offline, for air-gapped sites. They need an approved application form, a
**commitment tier** on a single-service resource, and a license file downloaded once while connected. Usage is
recorded locally and uploaded later.

Typical uses are hospitals that can't send patient audio or notes to the cloud, factories with poor connectivity,
and defense or government sites with air-gapped networks.

Run a connected Language container:

[source,bash]
----
docker run --rm -it -p 5000:5000 --memory 8g --cpus 1 \
  mcr.microsoft.com/azure-cognitive-services/textanalytics/language:latest \
  Eula=accept \
  Billing="https://foundry-bookshelf.cognitiveservices.azure.com/" \
  ApiKey="$LANGUAGE_KEY"

curl -s "http://localhost:5000/language/:analyze-text?api-version=2024-11-01" \
  -H "Content-Type: application/json" \
  -d '{"kind":"LanguageDetection","analysisInput":{"documents":[{"id":"1","text":"Bonjour"}]}}'
----

Source: https://learn.microsoft.com/azure/ai-services/language-service/language-detection/how-to/use-containers[Use language detection containers]

`Eula`, `Billing` and `ApiKey` are required. Containers need a **key**: they can't use Entra ID for billing, so a
resource with `disableLocalAuth` can't meter containers.

== Monitoring

=== Diagnostic settings

Send logs and metrics to Log Analytics. The categories are **Audit** (control-plane and key access),
**RequestResponse** (one row per data-plane call, without request bodies) and **AllMetrics**.

[source,bash]
----
az monitor diagnostic-settings create \
  --name diag-foundry \
  --resource "$(az cognitiveservices account show --name "$FOUNDRY" --resource-group "$RG" --query id -o tsv)" \
  --workspace "$(az monitor log-analytics workspace show --resource-group "$RG" --workspace-name law-bookshelf --query id -o tsv)" \
  --logs '[{"category":"Audit","enabled":true},{"category":"RequestResponse","enabled":true}]' \
  --metrics '[{"category":"AllMetrics","enabled":true}]'
----

Source: https://learn.microsoft.com/azure/ai-services/diagnostic-logging[Enable diagnostic logging]

Requests and errors per operation over the last day:

[source,kusto]
----
AzureDiagnostics
| where ResourceProvider == "MICROSOFT.COGNITIVESERVICES"
| where Category == "RequestResponse"
| where TimeGenerated > ago(1d)
| summarize calls = count(), throttled = countif(ResultSignature == "429"),
            errors = countif(toint(ResultSignature) >= 500), p95_ms = percentile(DurationMs, 95)
  by OperationName, bin(TimeGenerated, 1h)
| order by TimeGenerated desc
----

Source: https://learn.microsoft.com/azure/ai-services/diagnostic-logging[Enable diagnostic logging]

=== Alerts

Alert on throttling (`TotalErrors` or `ClientErrors` filtered to status 429) and on unexpected spend:

[source,bash]
----
az monitor metrics alert create \
  --name alert-foundry-429 --resource-group "$RG" \
  --scopes "$(az cognitiveservices account show --name "$FOUNDRY" --resource-group "$RG" --query id -o tsv)" \
  --condition "total ClientErrors > 50" \
  --window-size 5m --evaluation-frequency 1m \
  --action "$(az monitor action-group show --resource-group "$RG" --name ag-bookshelf-oncall --query id -o tsv)"
----

Source: https://learn.microsoft.com/azure/azure-monitor/alerts/alerts-create-metric-alert-rule[Create a metric alert rule]
