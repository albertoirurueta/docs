Welcome to the Azure reference. It documents Microsoft Azure for practitioners who work from the Azure portal
and the Azure CLI -- provisioning resources, wiring them together, and operating what results -- rather than
from the perspective of an AZ-900-style conceptual overview. Examples across this section target Azure CLI
version 2.90.0, Bicep version 0.47.16 and the Azure Developer CLI (`azd`) version 1.34.2; this baseline was
re-verified as current on 2026-09-27, and each page also names the extension or preview-feature versions it
specifically depends on, since Azure ships new capabilities to individual services on its own schedule.

Coming from AWS? See the xref:cloud/aws/index.adoc[AWS (Amazon Web Services)] section, which includes a
service-mapping table to Azure, and the xref:cloud/google-cloud/index.adoc[Google Cloud] section.

== The Bookshelf scenario

Most pages in this section build up one running example, *Bookshelf*: a small online bookshop with a public
catalog, a checkout flow and an order-confirmation email, deployed entirely on Azure. Every resource in it
shares one resource group and one naming convention, so a command copied from one page composes with a command
copied from another:

[cols="1,2", options="header"]
|===
| Concern | Name / value

| Resource group
| `rg-bookshelf`

| Region
| `eastus2` (a placeholder -- pick the region closest to the reader)

| ACR
| `acrbookshelf`

| Container Apps environment
| `cae-bookshelf`

| Container Apps
| `catalog-api`, `orders-api`, `notifier` (as a job)

| AKS cluster
| `aks-bookshelf`

| `stbookshelf`

| `afd-bookshelf`

| PostgreSQL flexible server
| `pg-bookshelf` (database `catalog`)

| Azure DocumentDB / Cosmos cluster
| `docdb-bookshelf` (database `orders`)

| Azure Managed Redis
| `redis-bookshelf`

| Key Vault
| `kv-bookshelf`

| App Configuration store
| `appcs-bookshelf`

| API Management
| `apim-bookshelf`

Bookshelf starts on Container Apps (`cae-bookshelf`, covered in the Compute group below) and later moves its
three services -- `catalog-api`, `orders-api` and the `notifier` job -- onto an AKS cluster
(`aks-bookshelf`), covered in xref:cloud/azure/aks-clusters.adoc[] and xref:cloud/azure/aks-microservices.adoc[].
The figure below shows Bookshelf's *end state*, once every group's pages have been applied: the AKS-hosted
services behind API Management and Front Door, with the databases, secrets and configuration store reached
through private endpoints inside `vnet-bookshelf`, an admin VPN path, and Azure Monitor watching all of it. It
is not the architecture a reader has running after just the Compute pages -- see
xref:cloud/azure/choosing-a-compute-service.adoc[] and xref:cloud/azure/container-apps.adoc[] for the earlier,
Container-Apps-only stage.

image::azure-bookshelf-architecture.svg["Bookshelf end-state architecture on AKS: Front Door in front of a static site on Blob Storage and an API Management gateway, which fronts catalog-api, orders-api and the notifier job running on AKS inside a private VNet with private endpoints to PostgreSQL, Azure DocumentDB, Azure Managed Redis, Key Vault and App Configuration, an admin VPN Gateway, Azure Communication Services for outbound email, and Azure Monitor observing everything"]

== Reading path

Read this section foundations first -- accounts, regions, resource groups, identity and infrastructure as code
-- then compute, where Bookshelf's services first get deployed. From there, storage and CDN put the static
front end and its assets somewhere durable and fast to serve, and managed databases give `catalog-api` and
`orders-api` somewhere to persist data. Security and runtime configuration then centralize the secrets and
settings every earlier page referenced loosely, before networking, gateways and VPN lock the whole thing behind
a private network and a proper API front door. Email and integration wire `notifier` up to the outside world,
and operations, governance and beyond closes the loop: monitoring, cost, compliance, migration paths and the
developer tooling that ties CI/CD back to everything above.
