:description: Landing page for the Git & GitHub reference -- getting started, repositories and cloning, commits, branches, checkout/switch/restore, fetch/pull/push, merging/rebasing and conflicts, pull requests, and tags and releases, each with command-line, GitHub.com, IntelliJ IDEA and VS Code walkthroughs, plus a downloadable cheat sheet.

*Git* is the distributed version-control tool that tracks every change to a project's files as a graph of
snapshots; *GitHub* is a hosting and collaboration platform built around Git repositories, adding pull requests,
issues, code review, Actions and a web UI on top of the same underlying Git history. This section teaches the
day-to-day Git and GitHub workflow -- repositories, commits, branches, tags, checkout/switch/restore, fetch/pull/push
and merging -- explaining each concept, then showing the same operation four ways: the **command line** (`git`, and
`gh` where relevant), **GitHub.com**, **IntelliJ IDEA** and **VS Code**. The examples are written and verified
against Git 2.55.x, GitHub CLI 2.101.x, IntelliJ IDEA 2026.2, current stable VS Code with the *GitHub Pull Requests
and Issues* extension, and github.com as of September 2026, with `main` as the default branch throughout.

== What's covered

=== Foundations

* xref:git-repositories/git-and-github/getting-started.adoc[Getting Started with Git and GitHub] -- version
  control and why Git is distributed, Git versus GitHub, installing Git, first-time setup, authenticating with
  HTTPS or SSH, and IDE setup in IntelliJ IDEA and VS Code.
* xref:git-repositories/git-and-github/repositories-and-cloning.adoc[Repositories and Cloning] -- the `.git`
  directory and the three areas (working tree, staging area, repository), `git init` versus `git clone`,
  `.gitignore`, remotes, and creating, cloning or forking a repository.

=== Everyday work

* xref:git-repositories/git-and-github/commits.adoc[Commits] -- what a commit is, staging and committing, writing
  good commit messages, inspecting history, and amending, restoring, reverting and resetting.
* xref:git-repositories/git-and-github/branches.adoc[Branches] -- branches as movable pointers, the branch
  commands, local versus remote-tracking branches, and GitHub flow versus a Git-flow-style workflow.
* xref:git-repositories/git-and-github/checkout-switch-and-restore.adoc[Checkout, Switch and Restore] -- how
  `git checkout`'s two jobs became `git switch` and `git restore`, detached `HEAD`, and switching with
  uncommitted changes.
* xref:git-repositories/git-and-github/tags-and-releases.adoc[Tags and Releases] -- tags as fixed pointers,
  lightweight versus annotated tags, and GitHub releases built on tags.

=== Collaborating

* xref:git-repositories/git-and-github/fetch-pull-and-push.adoc[Fetch, Pull and Push] -- moving commits between a
  local repository and `origin`, rejected non-fast-forward pushes, and `--force-with-lease` versus `--force`.
* xref:git-repositories/git-and-github/merging-rebasing-and-conflicts.adoc[Merging, Rebasing and Conflicts] --
  fast-forward and three-way merges, resolving merge conflicts, and `git rebase`.
* xref:git-repositories/git-and-github/pull-requests.adoc[Pull Requests] -- proposing, reviewing and merging
  changes with pull requests, on github.com, with the GitHub CLI, in IntelliJ IDEA and in VS Code.
