This page compares the four documentation tools of this section: Antora 3.2.1, Docusaurus 3.10.2, Zensical 0.0.72 and
DocFX 2.81.0. Material for MkDocs 9.8.0 and MkDocs 1.6.1 appear as context for Zensical, which grew out of them. Every
number was fetched on 2026-10-26 and every claim about a feature is explained, with an example, on the page of the
tool named in the table. The approach follows the Programming Languages Comparative (issue #196) of this site: data kept
in CSV files, charts generated from them, and a stated source and date for every figure. The comparison does not rank
the tools, because the right one depends on what is being documented; the last sections turn the data into
recommendations by purpose.

== Strengths and weaknesses

[cols="1,3,3,2",options=header]
|===
|Tool
|Strengths
|Weaknesses
|Where it is explained

|Antora
|Native multi-repository sites and versions from Git; AsciiDoc with resource-ID cross references, partials and examples;

|Smallest ecosystem of the four; several concepts (playbook, sources, UI bundle) before the first page; no API reference

|Docusaurus
|Largest ecosystem; MDX and React components; built-in versioning, i18n and blog; deep customisation through swizzling

|Zensical

|Alpha software; no native versioning or content translation yet; a subset of the MkDocs plugins; no PDF

|DocFX
|API reference generated straight from .NET XML comments; Swagger 2.0 REST pages; PDF output; .NET tool in the build
|Community-maintained with several hundred open issues; no versions or translations documented; OpenAPI 3 is not supported

The strengths and weaknesses come from the official documentation of each tool and from the checks run for the pages
of this section; the official sources are listed under References. Three observations deserve a longer explanation.

* *Aggregation and versions are Antora's reason to exist.* Antora builds a site from many repositories, and each branch
  or tag becomes a version. The other three tools can reach a similar result only by assembling the content first
  (Docusaurus), by publishing separate sites (DocFX) or by waiting for the roadmap (Zensical). This site uses Antora for
  that reason: it combines the documentation of about a dozen other repositories, as described in
  xref:documentation-tools/antora/case-study-this-site.adoc[Case study: this site].
* *Docusaurus trades aggregation for reach.* Its numbers are an order of magnitude above Antora's and DocFX's on every
  adoption metric below, and it is the only one of the four with versioning, i18n and a blog all built in. The price is
  that every site is a React application, so a documentation team takes on a JavaScript toolchain.
* *Zensical and DocFX answer different questions.* Zensical is a Markdown site generator that is replacing Material for
  MkDocs; DocFX turns .NET code into an API reference. They rarely compete for the same project, because the input they
  exist for, Markdown prose or .NET code, differs.

=== Caveats

* *Downloads are not comparable across ecosystems.* npm, PyPI and NuGet are inflated differently by continuous
  integration systems, mirrors and caches, so compare the series of one ecosystem with each other and treat the
  absolute values between ecosystems as unrelated.
* *Antora is on GitLab and often runs in Docker.* GitLab stars and forks do not compare with GitHub's, and downloads of
  a container image are not counted by npm.
* *The DocFX figure is cumulative.* NuGet only reports a total since the first publication, so DocFX has no weekly value.
* *Zensical is new and partly migration traffic.* It launched publicly on 2025-11-05, and part of its downloads are
  Material for MkDocs users trying a migration.
* *Stars over time are missing.* On the snapshot date the GitHub stargazers interface did not return star dates, so no
  star history is charted.
* *Counts of stable releases* only include versions of the form x.y.z, so the two-number MkDocs versions of 2014 and
  the Docusaurus pre-releases before 2.0.0 are not counted.

== Scores on ten axes

The radar charts condense the comparison into ten axes scored from 0 to 10, higher being better. Two axes are
computed from the data of this page: Ecosystem comes from the stars (100 stars scores 0 and 100,000 stars scores 10, on
a logarithmic scale) and Maintenance health averages the recency of the latest release, the number of stable releases in
the last 12 months and the share of closed issues. The other eight are editorial scores with the basis for each one
written next to it in `data/radar-scores.csv`: 2 means possible only by a custom script, 4 possible with extra
documented work, 6 supported with limits, 8 good built-in support and 10 the defining strength of the tool. Build speed
is the weakest axis: Zensical and Docusaurus have timings on the small Pocket Units site (see
xref:documentation-tools/docusaurus/docusaurus-faster-and-v4-readiness.adoc[Docusaurus Faster]), while Antora and DocFX
were not timed and sit at the middle value 5. The scores are a way to read the matrix quickly, not a ranking.

== Recommendations by purpose

The data snapshot date for every figure below is 2026-10-26.

* *Product documentation spanning many repositories and versions: Antora.* It scores 10 on aggregation and on versioning,
  and no other tool of the four reaches 8 on both (Docusaurus scores 2 and 8, Zensical 2 and 3, DocFX 4 and 2). The cost is
  the smallest ecosystem: 599 GitLab stars, about 24,000 npm downloads a week and 31 Stack Overflow questions, so
  expect to read the documentation rather than search for answers, and to maintain the UI bundle. It needs the extra
  work described in xref:documentation-tools/antora/ui/index.adoc[Antora UI bundles].
* *Open source project site with a blog, translations and versioned docs: Docusaurus.* It has the most adopters in
  the data (66,588 stars, 900,103 npm downloads a week, 515 Stack Overflow questions, 457 contributors), and it is the
  only tool that includes blog, i18n and versioning together. Plan for its single-project model and for the move from
  3.10 to 4, as explained in xref:documentation-tools/docusaurus/docusaurus-faster-and-v4-readiness.adoc[Docusaurus
  Faster and v4 readiness].
* *Python or Markdown-first projects: Zensical, or Material for MkDocs for now.* Zensical grew about 3.3 times in weekly
  PyPI downloads over six months and published 69 releases in the last year, which supports betting on it, and it reads
  the existing `mkdocs.yml`. It is still alpha at 0.0.72 and lacks native versioning, so a project that needs
  production stability today can stay on Material for MkDocs, whose maintenance mode promises fixes until 2027-05-05, and
  plan the move after the 0.1.0 line planned for 2026-11-05.
* *.NET libraries that need an API reference: DocFX.* It scores 9 on API reference, and the 6.55 million cumulative NuGet
  downloads show that it is the default .NET tool. Check the 403 open issues and the lack of versions and translations
  first, and pin the version in continuous integration. OpenAPI 3 files are not supported in 2.81.0.
* *Teams currently on Material for MkDocs: plan, do not rush.* The project is in maintenance mode, MkDocs has no stable
  release since 2024-08-30 and Zensical is the successor from the same team. Follow
  xref:documentation-tools/zensical/migrating-from-material-for-mkdocs.adoc[Migrating from Material for MkDocs] and the
  Zensical roadmap, and rerun the build with `zensical build` on a branch before committing to the change.

The chart tooling is the one of the Programming Languages Comparative (issue #196). The Antora
xref:documentation-tools/antora/site-search.adoc[site search] page covers the Lunr, Pagefind and Algolia options that
issue #255 discusses for this site.
