Welcome to the Couchbase reference. https://www.couchbase.com/[Couchbase Server] is a *distributed,
memory-first JSON document database that is also a key-value store*: it stores each record as a JSON document
addressed by a key, keeps its working set in memory for microsecond key-value access, exposes a SQL-like query
language (*SQL++*, formerly N1QL) and an aggregation-and-search stack through separately scalable *services*,
and shards every bucket into 1024 vBuckets spread across the cluster with automatic replication and failover.
This section documents the current Couchbase Server line as a database-developer reference -- the data model,
the key-value and sub-document APIs, SQL++, indexing, search, analytics and eventing, clustering and
cross-datacenter replication, storage, security and operations, and the drivers -- written and verified
against https://docs.couchbase.com/server/current/[the Couchbase Server documentation].

[NOTE]
====
Some capabilities (Enterprise-Edition-only Analytics, auditing, encryption at rest, the Backup service and rack-zone awareness, and Capella-only App Services and Columnar) are **linked, not documented in depth**.
====

If you are new to Couchbase, read xref:database/couchbase/getting-started.adoc[What Couchbase Server is & how
to run it] first, then xref:database/couchbase/buckets-scopes-collections.adoc[Buckets, scopes & collections]
and xref:database/couchbase/documents-keys-and-metadata.adoc[Documents, keys, metadata & expiration], followed
by xref:database/couchbase/kv-and-subdocument-operations.adoc[Key-value & sub-document operations] and
xref:database/couchbase/sql-plus-plus-querying.adoc[Querying with SQL++]. Everything after that builds on those
foundations.

The pages share one running example, an online *shop*: a `shop` bucket with a `sales` scope holding `customers`,
`products`, `orders` (each embedding its lines), `categories` and `accounts` collections. It is built in
xref:database/couchbase/getting-started.adoc[the first page] and used for the key-value, modeling, query,
index and transaction examples that follow, and the output shown for it was produced by a Couchbase Server
7.6.2 node and the Java SDK 3.7.

For the relational and document-database baselines this section contrasts with, see the sibling
xref:database/sql/index.adoc[SQL Reference] and xref:database/mongodb/index.adoc[MongoDB Reference], which the
Couchbase pages cross-link rather than restate.

== Version baseline

This section documents **the current Couchbase Server 7.6.x line** as published at https://docs.couchbase.com/server/current/[the Couchbase Server documentation], **which is the reference these pages are written and verified against**.
No specific patch version is pinned.

== What's covered

=== Getting started

* xref:database/couchbase/getting-started.adoc[What Couchbase Server is & how to run it] -- Couchbase as a
  distributed, memory-first document and key-value database, the document model versus the relational model,
  the services model and Multi-Dimensional Scaling, the Enterprise and Community editions and Capella, running
  a node, and driving it from the Web Console, `cbq` and Couchbase Shell.

=== Data & modeling

* xref:database/couchbase/buckets-scopes-collections.adoc[Buckets, scopes & collections] -- the
  `bucket.scope.collection` keyspace, the `_default` and `_system` namespaces, the Couchbase / Ephemeral /
  Memcached bucket types with their RAM, replica, durability and TTL settings, and how the keyspace path is
  written in SQL++, in the SDKs and in DDL.
* xref:database/couchbase/documents-keys-and-metadata.adoc[Documents, keys, metadata & expiration] -- an item
  as key + value + metadata, document-key rules and patterns, JSON and binary values and the 20 MB limit, the
  CAS / expiry / flags metadata and Extended Attributes, TTL and expiry precedence with tombstones, and the
  SDK data structures.
* xref:database/couchbase/kv-and-subdocument-operations.adoc[Key-value & sub-document operations] -- the
  key-value API from `Cluster` to `Collection`, the CRUD verbs and their typed errors, atomic counters and
  binary append/prepend, KV Range Scan, bulk and reactive variants, and the `lookupIn` / `mutateIn`
  sub-document API.
* xref:database/couchbase/concurrency-locking-and-durability.adoc[Concurrency, locking & durable writes] --
  optimistic concurrency with CAS and the compare-and-swap retry loop, pessimistic locking with `getAndLock`,
  the CAS-as-ETag pattern, and the `majority` / `majorityAndPersistToActive` / `persistToMajority` durable-write
  levels that supersede observe-based `PersistTo` / `ReplicateTo`.
* xref:database/couchbase/data-modeling.adoc[Document-oriented data modeling] -- embed versus reference,
  key-based relationships and cardinality, the normalization trade-off, collections and schema versioning as
  modeling tools, and the anti-patterns that push a workload off Couchbase.

=== Querying -- SQL++

* xref:database/couchbase/sql-plus-plus-querying.adoc[Querying with SQL++ (SELECT & joins)] -- the Query
  service and how to run a statement, the `SELECT` clause set, `RAW` / `VALUE` projections, nested-path and
  array expressions, `UNNEST` and `NEST`, lookup / ANSI / index joins, `WITH` and recursive CTEs, subqueries,
  collection operators, and avoiding large `OFFSET` values with a keyset seek query.
* xref:database/couchbase/sql-plus-plus-dml-functions-transactions.adoc[SQL++ data modification, functions &
  transactions] -- `INSERT` / `UPSERT` / `UPDATE` / `DELETE` / `MERGE` with `KEY`, `VALUE`, `USE KEYS` and
  `RETURNING`; scalar, aggregate, window, array, object and metadata functions plus user-defined functions;
  and distributed ACID transactions through the SDK lambda API and the `BEGIN` / `COMMIT` / `ROLLBACK`
  statements.

=== Indexing & search

* xref:database/couchbase/indexes-and-views.adoc[Indexing with the Index service (and legacy Views)] -- how the
  Index service builds Global Secondary Indexes (primary, secondary, composite, partial, array, adaptive,
  covering, partitioned and deferred), how `EXPLAIN`, `ADVISE` and the cost-based optimizer choose a plan, and
  why current GSI + SQL++ supersedes the legacy MapReduce Views mechanism.
* xref:database/couchbase/search-analytics-eventing.adoc[Full-Text & Vector Search, Analytics & Eventing] --
  the Search service for full-text, geo and vector / hybrid search from SQL++, the Enterprise Analytics service
  for columnar MPP queries over shadow datasets, and the Eventing service for JavaScript functions that run on
  the change feed.

=== Distributed architecture & operations

* xref:database/couchbase/clusters-replication-and-xdcr.adoc[Clusters, replication, failover & XDCR] -- how a
  cluster spreads 1024 vBuckets across nodes with Multi-Dimensional Scaling, how DCP replicates active vBuckets
  to replicas, how automatic, graceful and hard failover and Server Group awareness work, and how XDCR mirrors
  buckets between data centers.
* xref:database/couchbase/storage-security-and-administration.adoc[Storage internals, security &
  administration] -- how the managed cache, disk write queue, Couchstore and Magma engines, compaction, DCP and
  warm-up move data to disk; the RBAC, authentication, TLS and auditing model; and the console, CLI, backup,
  import/export and monitoring tooling.

=== SDKs & Mobile

* xref:database/couchbase/sdks-and-mobile.adoc[SDKs, connectors & Couchbase Mobile] -- the SDK family and its
  shared API surface, the singleton `Cluster` and its connection string, timeouts and the retry / error model,
  the Kafka / Spark / Elasticsearch connectors, and Couchbase Mobile (Couchbase Lite, Sync Gateway, App
  Services, Edge Server and peer-to-peer sync).

=== Cheat sheet

* xref:database/couchbase/cheat-sheet.adoc[Cheat Sheet (PDF)] -- a single-page, printable summary of everything
  in this section, with a downloadable PDF.

*Deliberately out of scope.* This section is a developer reference for the current Couchbase Server line, not a port of three books written for 3.x and 4.0. The following topics appear in most books on the subject but live elsewhere on this site, or are intentionally not covered:

* *Moxi and Memcached buckets* -- Moxi is gone and the server itself prints "Memcached buckets are deprecated, please use ephemeral buckets instead"; see xref:database/couchbase/buckets-scopes-collections.adoc[Buckets, scopes & collections] for the Ephemeral replacement.
* *MapReduce Views as a design tool* (design documents, map and reduce functions, spatial and collated views, development versus production views) -- kept to a legacy and migration overview in xref:database/couchbase/indexes-and-views.adoc[Indexing with the Index service (and legacy Views)], because Global Secondary Indexes and SQL++ replace them.
* *The Elasticsearch connector plug-in and XDCR to Elasticsearch* -- superseded by the built-in Search service, see xref:database/couchbase/search-analytics-eventing.adoc[Full-Text & Vector Search, Analytics & Eventing]; for Elasticsearch itself see xref:database/elasticsearch/index.adoc[Elasticsearch Reference].
* *The Hadoop connector, `cbtransfer` and the per-database migration walk-throughs* (MongoDB, Cassandra, Oracle) -- the Hadoop connector and `cbtransfer` are retired; `cbimport` and `cbexport` are shown in xref:database/couchbase/getting-started.adoc[What Couchbase Server is & how to run it], the Kafka and Spark connectors in xref:database/couchbase/sdks-and-mobile.adoc[SDKs, connectors & Couchbase Mobile], and the general migration approach in xref:database/migration/index.adoc[Database Migration].
* *Spring Data Couchbase and repository abstractions* -- see xref:backend/springboot/spring-data-couchbase.adoc[Spring Data Couchbase].
* *Language-by-language SDK tutorials and the to-do MVC application* (PHP, Ruby, Node.js, Python, .NET, C) -- the shared API surface and error model are in xref:database/couchbase/sdks-and-mobile.adoc[SDKs, connectors & Couchbase Mobile]; application structure belongs to the web and backend sections of this site.
* *The NoSQL landscape, taxonomies and the "why NoSQL" argument* -- see xref:database/choosing-the-right-database.adoc[Choosing the Right Database].
* *Installation on each operating system, sizing worksheets and cloud-provider deployment chapters* -- a Docker start is shown in xref:database/couchbase/getting-started.adoc[What Couchbase Server is & how to run it] and explained in xref:backend/docker/running-containers.adoc[Running Containers]; native packages, sizing and Capella are linked to the official documentation; Kubernetes is in xref:backend/kubernetes/index.adoc[Kubernetes].
* *Monitoring stacks beyond the Couchbase tools* -- see xref:database/prometheus/index.adoc[Prometheus & Monitoring] and xref:backend/monitoring-alerting/index.adoc[Monitoring & Alerting] for the generic tooling.
* *Building Couchbase Lite apps on Android and iOS* -- the mobile architecture is in xref:database/couchbase/sdks-and-mobile.adoc[SDKs, connectors & Couchbase Mobile]; app development itself is under xref:apps/index.adoc[Apps].
