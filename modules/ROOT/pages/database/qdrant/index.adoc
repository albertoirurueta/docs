Welcome to the Qdrant reference. https://qdrant.tech/[Qdrant] is an *open-source, self-hostable vector similarity
search engine* written in Rust: it stores high-dimensional vectors alongside a JSON payload in collections, indexes
them with an HNSW approximate-nearest-neighbor graph, and exposes both a REST and a gRPC API (with official Python
and Java clients, among others) for filtered similarity search, hybrid dense/sparse retrieval, and the
retrieval step of Retrieval-Augmented Generation pipelines.

[NOTE]
====
Some capabilities (Qdrant Cloud-only features and the full breadth of client-library APIs beyond Python and Java) are **linked, not documented in depth**.
====

xref:database/qdrant/collections-and-points.adoc[Collections & Points] and

== Version baseline

This section documents **the current Qdrant 1.x line** (latest **1.20.0**), written against https://qdrant.tech/documentation/[the official Qdrant documentation]
and verified by running its examples against a Qdrant 1.20.0 server, including a three-node cluster, a TLS-enabled node and JWT-based access control.
No specific patch version is pinned. The Python examples use `qdrant-client` 1.16 and the Java examples `io.qdrant:client` 1.20.0.

== Running example

The section follows one small data set so the pages can be read in any order and their outputs compared. A product
catalog named `products` holds six items with hand-made 4-dimensional vectors, a payload of name, category, price,
rating, brand, stock flag, tags and location, and a few related collections: `catalog` (text and image named vectors),
`docs` (multivectors), `articles` (dense plus sparse vectors for hybrid search), `kb_chunks` (a RAG knowledge base) and
a three-node cluster that holds a replicated `documents` collection. Tiny vectors make the arithmetic checkable by
hand; the calls are identical to the ones a real embedding model would drive.
