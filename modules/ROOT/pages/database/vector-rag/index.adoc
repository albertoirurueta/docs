= Vector Databases & RAG
:description: Landing page for the Vector Databases & RAG reference -- embeddings, similarity search, ANN indexing and quantization, vector search in SQL and dedicated engines, Retrieval-Augmented Generation, agentic RAG, framework integration and production operations.
:keywords: vector database, embeddings, similarity search, ann index, hnsw, faiss, pgvector, sqlite-vec, rag, retrieval augmented generation, agentic rag, langchain, spring ai, ragas, vector database cheat sheet

include::partial$vector-rag-disclaimer.adoc[]

Welcome to the Vector Databases & RAG reference. This section covers *vector databases* -- data stores purpose-
built to index and search high-dimensional embeddings -- and *Retrieval-Augmented Generation* (RAG), the pattern
of grounding a large language model's answers in text retrieved from such a store, through to the agentic
patterns and framework integrations built on top of it. Code examples target Python 3.12 with
sentence-transformers 6.1, FAISS 1.15.1, sqlite-vec 0.1.9 and pgvector 0.8.6, plus Ollama 0.34 for local
embedding and chat models; the RAG and agent pages layer in langchain / langchain-core / langgraph 1.4 / 1.6 /
1.2, langchain-text-splitters 1.1 and langchain-postgres 0.0.18 on the Python side, LangChain4j 1.20.1 and
Spring Boot / Spring AI 4.1 / 2.0.1 on the Java side, RAGAS 0.4.3 for evaluation, and the Model Context Protocol
spec dated 2026-07-28 for agent tool-calling. This baseline was checked and re-verified as current on
2026-09-26.

Most pages in this section share one running example, *DocsAssistant*: an AI agent that answers questions about
a corpus of technical documentation -- specifically, this site's own AsciiDoc pages. A single embedding model
and a single chat model are used across every stack (plain Python, LangChain, Spring AI) so the examples stay
interoperable, with a smaller model reserved for standalone embedding demos.

[cols="1,3", options="header"]
|===
| Aspect | Choice used throughout DocsAssistant

| Sample corpus
| Three small AsciiDoc files, written out inline on
  xref:database/vector-rag/document-ingestion-and-chunking.adoc[Document Ingestion & Chunking] and used in every
  example: `docs/vector-rag/hnsw.adoc` ("HNSW indexes"), `docs/vector-rag/pgvector.adoc` ("pgvector basics") and
  `docs/spring-ai/rag.adoc` ("RAG with Spring AI"), with metadata `component` = `vector-rag` or `spring-ai`

| Embedding model
| Ollama `nomic-embed-text` (768 dimensions, cosine distance); sentence-transformers `all-MiniLM-L6-v2`
  (384 dimensions) is used separately for standalone concept demos on the embedding pages

| Chat model
| Ollama `llama3.1:8b`

| Primary database
| PostgreSQL + pgvector, database `docsassistant`, with a parallel SQLite/sqlite-vec version

| Indexes
| HNSW (pgvector's `chunk_embeddings_hnsw`, FAISS `IndexHNSWFlat`), IVF (FAISS `IndexIVFFlat`), exact
  brute-force KNN in sqlite-vec's `vec0` table (no ANN index), plus Qdrant for cross-engine benchmarking

| Frameworks used
| LangChain / LangGraph (Python) and Spring AI (Java), each wired to the same embedding and chat models

| Agent tool
| A retrieval tool exposed to the chat model, called directly in-process and, in the agent pages, via MCP
|===

== How to read this section

The 23 pages in this section build up in six stages: *concepts* first (what embeddings are and how similarity
search works), then *engines* (the ANN algorithms and the concrete libraries/databases that implement them),
then *RAG* itself (chunking, retrieval and prompt construction), then *agents* (agentic RAG loops and
persistent memory), then the two *framework* integrations, and finally *operations* (evaluation and running
this in production). Start with xref:database/vector-rag/what-is-a-vector-database.adoc[What Is a Vector
Database?] and xref:database/vector-rag/embeddings.adoc[Embeddings], then
xref:database/vector-rag/generating-embeddings-in-practice.adoc[Generating Embeddings in Practice] to get a
model actually producing vectors. From there, move into similarity search and indexing --
xref:database/vector-rag/similarity-metrics-and-semantic-search.adoc[Similarity Metrics & Semantic Search],
xref:database/vector-rag/ann-indexes.adoc[ANN Indexes], xref:database/vector-rag/quantization-and-compression.adoc[
Quantization & Compression] and xref:database/vector-rag/faiss.adoc[FAISS] -- followed by filtering and hybrid
retrieval (xref:database/vector-rag/metadata-filtering.adoc[Metadata Filtering],
xref:database/vector-rag/hybrid-search-and-reranking.adoc[Hybrid Search & Re-ranking]), then vector search
inside SQL databases and how to choose an engine
(xref:database/vector-rag/sqlite-vector-search.adoc[SQLite], xref:database/vector-rag/postgresql-pgvector.adoc[
PostgreSQL & pgvector], xref:database/vector-rag/vector-database-landscape.adoc[The Landscape] and
xref:database/vector-rag/comparing-vector-databases.adoc[Comparing Vector Databases]). The RAG cluster
(xref:database/vector-rag/rag-fundamentals.adoc[RAG Fundamentals] through
xref:database/vector-rag/prompt-augmentation-and-generation.adoc[Prompt Augmentation & Generation]) and the
agent cluster (xref:database/vector-rag/agentic-rag.adoc[Agentic RAG],
xref:database/vector-rag/agent-memory-and-semantic-cache.adoc[Agent Memory & Semantic Cache]) come next, then
the two framework pages, and the section closes with
xref:database/vector-rag/evaluating-rag-systems.adoc[Evaluating RAG Systems] and
xref:database/vector-rag/production-considerations.adoc[Production Considerations].

This section covers the ANN algorithms and general-purpose libraries (FAISS) and SQL extensions (sqlite-vec,
pgvector) behind vector search, but several full database engines that also do vector search already have their

== What's covered

*Foundations*

* xref:database/vector-rag/what-is-a-vector-database.adoc[What Is a Vector Database?] -- why unstructured data
  needs semantic search, the vector data type and its three operations, and the hybrid architecture every
  vector database implements.
* xref:database/vector-rag/embeddings.adoc[Embeddings] -- what an embedding is, how embedding models are
  trained, and the properties (dimensionality, distance, clustering) that make them useful for search.
* xref:database/vector-rag/generating-embeddings-in-practice.adoc[Generating Embeddings in Practice] --
  producing embeddings with sentence-transformers and with Ollama, batching, and normalization.

*Similarity search & indexing*

* xref:database/vector-rag/similarity-metrics-and-semantic-search.adoc[Similarity Metrics & Semantic Search] --
  cosine similarity, dot product and Euclidean distance, and when each one applies.
* xref:database/vector-rag/ann-indexes.adoc[ANN Indexes: Flat, IVF, HNSW and Beyond] -- exact search versus
  approximate nearest neighbour, inverted-file indexes, and the HNSW graph.
* xref:database/vector-rag/quantization-and-compression.adoc[Quantization & Compression] -- scalar and product
  quantization, and the recall/memory/latency trade-offs they introduce.
* xref:database/vector-rag/faiss.adoc[FAISS] -- Facebook AI Similarity Search as a standalone ANN library, its
  index factory, and GPU acceleration.

*Filtering, hybrid search & relevance*

* xref:database/vector-rag/metadata-filtering.adoc[Metadata Filtering] -- combining vector similarity with
  structured filters, and pre- versus post-filtering trade-offs.
* xref:database/vector-rag/hybrid-search-and-reranking.adoc[Hybrid Search & Re-ranking] -- combining dense and
  sparse (keyword) retrieval with Reciprocal Rank Fusion, and cross-encoder re-ranking.

*Vector search in SQL databases & choosing an engine*

* xref:database/vector-rag/sqlite-vector-search.adoc[Vector Search in SQLite] -- the sqlite-vec extension and
  its `vec0` virtual tables.
* xref:database/vector-rag/postgresql-pgvector.adoc[PostgreSQL & pgvector] -- the `vector` column type, HNSW and
  IVFFlat indexes, and using PostgreSQL as both the primary and the vector store for DocsAssistant.
* xref:database/vector-rag/vector-database-landscape.adoc[The Vector Database Landscape] -- a survey of
  dedicated vector databases and multi-model engines that support vector search.
* xref:database/vector-rag/comparing-vector-databases.adoc[Comparing Vector Databases] -- a feature, deployment
  and pricing comparison across the landscape, including managed-service offerings.

*RAG*

* xref:database/vector-rag/rag-fundamentals.adoc[RAG Fundamentals] -- the retrieve-then-generate loop and why
  grounding an LLM's answers in retrieved text reduces hallucination.
* xref:database/vector-rag/document-ingestion-and-chunking.adoc[Document Ingestion & Chunking] -- splitting
  source documents into chunks, chunk size/overlap trade-offs, and late chunking.
* xref:database/vector-rag/retrieval-strategies.adoc[Retrieval Strategies] -- top-k retrieval, maximal marginal
  relevance, and multi-query retrieval.
* xref:database/vector-rag/prompt-augmentation-and-generation.adoc[Prompt Augmentation & Generation] --
  assembling retrieved context into a prompt, context-window budgeting, and citation.

*Agents*

* xref:database/vector-rag/agentic-rag.adoc[Agentic RAG] -- letting an agent decide when and what to retrieve,
  instead of a fixed retrieve-then-generate pipeline.
* xref:database/vector-rag/agent-memory-and-semantic-cache.adoc[Agent Memory & Semantic Cache] -- persisting
  conversation memory as embeddings, and caching semantically similar prior queries.

*Frameworks*

* xref:database/vector-rag/integrating-with-langchain.adoc[Integrating with LangChain] -- vector store
  integrations, retrievers, and LangGraph agentic-RAG graphs.
* xref:database/vector-rag/integrating-with-spring-ai.adoc[Integrating with Spring AI] -- the `VectorStore`
  abstraction, the ETL pipeline, `Advisor`s, and chat memory.

*Quality & operations*

* xref:database/vector-rag/evaluating-rag-systems.adoc[Evaluating RAG Systems] -- RAGAS metrics (faithfulness,
  answer relevance, context precision/recall) and ANN-Benchmarks-style recall/latency evaluation.
* xref:database/vector-rag/production-considerations.adoc[Production Considerations] -- re-indexing, monitoring,
  cost, and scaling a vector search + RAG deployment.

* xref:database/vector-rag/cheat-sheet.adoc[Cheat Sheet (PDF)] -- a single-page, printable summary of everything
  in this section, with a downloadable PDF.
