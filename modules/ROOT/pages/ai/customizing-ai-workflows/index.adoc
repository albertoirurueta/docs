xref:ai/ai-assisted-development/index.adoc[AI-Assisted Development] covers *using* Copilot and Claude Code on a
task; this sub-section covers *shaping* the assistant itself, so those everyday workflows behave the way a team
wants by default rather than needing to be re-explained every session. Each surface below answers a different
question about how an assistant's behavior gets fixed in place:

* *Instructions and memory files* (`CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md`, path-specific
  `*.instructions.md`) are the always-on layer -- facts and rules loaded automatically at the start of every
  session, never invoked by name.
* *Prompt files and slash commands* (`.github/prompts/*.prompt.md`, Claude Code custom commands) package a
  reusable procedure behind a name the user or the model can invoke on demand.
* *Skills* (`SKILL.md`, the open Agent Skills standard) go further than a prompt file: a name, a triggering
  description, a body of imperative steps, and optional supporting files and scripts, invocable by the user or
  discovered by the model from its description.
* *Subagents and custom agents* delegate a task to a worker running in its own, isolated context window, so the
  caller's context only receives the result, not everything the worker read along the way.
* *Hooks* run a shell command at a fixed point in the agent's turn, outside the model, so an enforcement rule
  becomes deterministic instead of a request the model might skip.
* *Permissions and settings* decide, independently of what an instruction or prompt asks for, which tool calls
  the assistant is actually allowed to run, at what scope (managed / project / user), and in what mode.
* *MCP* connects an external capability -- a database, an API, a document store -- as tools, resources or
  prompts the assistant can call, without writing a bespoke integration for the assistant itself.
* *Output styles, the status line and related settings* change how a turn is framed or what a CLI shows, rather
  than what the assistant is allowed to do.
* *Plugins and marketplaces* package skills, agents, hooks and MCP servers as one distributable, versioned unit
  instead of a team copying loose folders between projects.
