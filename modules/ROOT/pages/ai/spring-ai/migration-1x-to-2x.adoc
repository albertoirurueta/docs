Written against Spring AI 2.0.1, Spring Boot 4.1.x and Java 21 (verified 2026-09-29), from the official https://docs.spring.io/spring-ai/reference/upgrade-notes.html[Upgrade Notes] as they stood on that date, checked against the 2.0.1 jars and, where marked, by running code. Spring AI
version 2.0.0 became generally available on 2026-06-12 and 2.0.1 is the current stable release. The 2.0 line requires Java 17 or later, Spring Boot 4.0 or 4.1 with Spring Framework 7, Jackson 3 and JSpecify nullability, so a Spring AI upgrade is also a Spring Boot upgrade, and the
Boot 4 migration is the larger part of the work for most projects. This page is the reference to keep beside the compiler while you upgrade: the rows are the changes DocsAssistant-style code runs into, each with a link to the note it comes from. The rest of the sub-section describes 2.0.1 as if
it were the only version; this page is the one place that looks back. A 2.1 milestone exists on Maven Central, but nothing here is based on it.
The most common renames also fit in one box of the printable xref:ai/spring-ai/cheat-sheet.adoc[Spring AI Cheat Sheet], and the
xref:ai/spring-ai/index.adoc#_version_baseline[version baseline] on the landing page lists every version this sub-section targets.

== How to upgrade

[mermaid]
....
flowchart TD
  A["1.x application on Boot 3.x"] --> B["Get the tests green on 1.x first"]
  B --> C["Move to Spring Boot 4.x and Java 17+ (Framework 7, Jackson 3)"]
  C --> D["Set spring-ai-bom to 2.0.x"]
  D --> E["Run OpenRewrite recipes for the mechanical part"]
  E --> F["Fix what the compiler reports: tables below"]
  F --> G["Update properties: drop .options, renamed keys"]
  G --> H["Review the silent changes: same code, different behaviour"]
  H --> I["Run the evaluation suite and compare answers, cost, latency"]
....

. *Green tests first.* An upgrade of this size needs a baseline. Tests with a scripted `ChatModel` (see xref:ai/spring-ai/testing.adoc[Testing]) are ideal, since they do not change when the provider does.
. *Boot 4 and Java.* Move the platform first or together with the BOM; Spring AI 2.0.x supports Spring Boot 4.0.x and 4.1.x. Jackson 3 changes the `ObjectMapper` package to `tools.jackson.databind` and the builder to `JsonMapper`.
. *BOM.* Import `spring-ai-bom` 2.0.1 (or the latest 2.0.x). All `org.springframework.ai` artifacts take their version from it.
. *Recipes.* Run the OpenRewrite recipes in the next section, then read the diff.
. *Compile.* Work through the tables below.
. *Properties.* Start the application with a configuration check; unknown keys under `spring.ai` are silently ignored by Boot, so compare your files with the tables, or run the recipe that renames them.
. *Behaviour.* Read the "compiles but behaves differently" table. These are the changes no compiler will report.

== OpenRewrite recipes

Three sets of recipes exist. Two are from Spring AI and cover the MCP changes of 2.0.0-M3; one is a community recipe that covers most of the mechanical 2.0 changes.

.Recipes for the 1.x to 2.0 upgrade
[cols="3,4,3"]
|===
|Recipe |What it does |Source

|`io.arconia.rewrite.spring.ai2.UpgradeSpringAi_2_0`
|Upgrades `org.springframework.ai` dependencies to 2.0.x; flattens the `.options.` infix in property keys for embedding, image, audio, moderation and OCR; comments out removed properties; converts `ChatOptions` arguments to builders; renames `toolCallbacks(...)`/`defaultToolCallbacks(...)` to `tools(...)`/`defaultTools(...)`; renames `getDefaultOptions()` to `getOptions()` and `N()` to `n()`; updates coordinates and types for Anthropic, MCP, Mistral, OpenAI and Google. It does not migrate `AnthropicChatModel` construction from `AnthropicApi`
|https://docs.arconia.io/arconia-migrations/latest/spring/spring-ai/2-0/[Arconia: Spring AI 2.0] (community project)

|`org.springframework.ai.migration.M3MigrateMcpAnnotations`
|Removes the `org.springaicommunity:mcp-annotations` dependency and rewrites imports to `org.springframework.ai.mcp.annotation.*`
|`migrate-to-2-0-0-M3.yaml` in the Spring AI repository, see the upgrade notes

|`org.springframework.ai.migration.M3MigrateMcpSpringTransports`
|Moves the `mcp-spring-webflux` and `mcp-spring-webmvc` coordinates and the transport classes to Spring AI's packages
|same file

|`org.springframework.ai.migration.M3MigrateMcpClientCustomizer`
|Rewrites `McpSyncClientCustomizer` and `McpAsyncClientCustomizer` to `McpClientCustomizer<McpClient.SyncSpec>` and `<McpClient.AsyncSpec>`
|same file

|`org.springframework.ai.migration.MigrateToSpringAI200M3`
|Umbrella recipe that applies all of the M3 recipes above
|same file
|===

The recipe names were read from the community documentation and from the YAML file in the Spring AI repository on 2026-09-29; the recipes themselves were not run for this page. The Spring AI ones are invoked like this, with the plugin version the notes use:

[source,shell]
----
mvn org.openrewrite.maven:rewrite-maven-plugin:6.32.0:run \
  -Drewrite.configLocation=https://raw.githubusercontent.com/spring-projects/spring-ai/refs/heads/main/src/rewrite/migrate-to-2-0-0-M3.yaml \
  -Drewrite.activeRecipes=org.springframework.ai.migration.M3MigrateMcpAnnotations \
  -Dmaven.compiler.failOnError=false
----

Source: https://docs.spring.io/spring-ai/reference/upgrade-notes.html[Spring AI: Upgrade Notes] (the M3 recipes and the plugin version).

The community recipe is run like this:

[source,shell]
----
./mvnw -U org.openrewrite.maven:rewrite-maven-plugin:run \
  -Drewrite.recipeArtifactCoordinates=io.arconia.migrations:rewrite-spring:LATEST \
  -Drewrite.activeRecipes=io.arconia.rewrite.spring.ai2.UpgradeSpringAi_2_0
----

Source: https://docs.arconia.io/arconia-migrations/latest/spring/spring-ai/2-0/[Arconia Migrations: Spring AI 2.0].

Two cautions. A recipe changes source files, so run it on a clean branch and read every hunk; `LATEST` in the second command floats, so pin a version for a repeatable run. And the M3 note warns that a `pom.xml` that declares `mcp-spring-webflux` without a version, relying
on a BOM, may fail to parse before the recipe can run, which is why that note tells you to patch those files first. The same community project has `io.arconia.rewrite.spring.ai1.UpgradeSpringAi_1_0` for the older 0.8 to 1.0 jump
(https://docs.arconia.io/arconia-migrations/latest/spring/spring-ai/1-0/[Arconia: Spring AI 1.0]); the Spring AI notes link to it for the 1.0.0-RC1 upgrade.

== Tools

.Tool calling
[cols="3,3,2"]
|===
|Old (1.x) |New (2.0.1) |Notes

|Each `ChatModel` runs the tool loop; `internalToolExecutionEnabled(false)` to run it yourself
|The loop lives in `ToolCallingAdvisor`, auto-registered by `ChatClient`. `ChatModel.call` returns the raw tool calls. `internalToolExecutionEnabled` and its property are removed
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_internaltoolexecutionenabled_from_toolcallingchatoptions[upgrade notes]

|`ToolExecutionEligibilityPredicate`
|`ToolExecutionEligibilityChecker` on `ToolCallingAdvisor.Builder`, or as a bean
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_toolexecutioneligibilitypredicate_and_defaulttoolexecutioneligibilitypredicate[upgrade notes]

|`ToolCallAdvisor`
|`ToolCallingAdvisor`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_renamed_toolcalladvisor_toolcallingadvisor[upgrade notes]

|`FunctionCallback`, `FunctionCallingOptions`, `defaultFunctions(...)`, `.functions(...)`
|`ToolCallback` / `FunctionToolCallback`, `ToolCallingChatOptions`, `defaultTools(...)`, `.tools(...)`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_renamed_functioncallback_api_toolcallback_api[upgrade notes]

|`toolNames(...)` and tools found by bean name (`SpringBeanToolCallbackResolver`)
|Attach a `ToolCallback` or a `@Tool` object to the request; the resolver is removed. In 2.0.1 the bean fallback is off by default (`spring.ai.tools.resolution.fallback.enabled`)
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_springbeantoolcallbackresolver_and_toolnames[upgrade notes]

|`ChatClient` `ToolSpec` consumer
|Removed; use `tools(...)`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_toolspec_consumer_api_on_chatclient[upgrade notes]

|`MethodToolCallbackProvider` throwing `IllegalStateException`
|`IllegalArgumentException` for no `@Tool` methods or duplicate names
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_changed_methodtoolcallbackprovider_throws_illegalargumentexception_instead_of_illegalstateexception[upgrade notes]

|`ToolContext.TOOL_CALL_HISTORY`, `getToolCallHistory()`
|Removed; conversation history belongs to the advisors
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_conversation_history_removed_from_toolcontext[upgrade notes]

|Every tool definition sent on every call
|New and optional: `ToolSearchToolCallingAdvisor` (`org.springframework.ai.chat.client.advisor.toolsearch`, starter `spring-ai-starter-tool-search-advisor`, `spring.ai.chat.client.tool-search-advisor.enabled=true`) sends only the tools that match the request
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_new_toolsearchtoolcallingadvisor_auto_configuration_and_starter[upgrade notes]

|`streamToolCallResponses` on the advisor builders and its properties
|Removed
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_streamtoolcallresponses_from_advisor_builders_and_auto_configuration[upgrade notes]
|===

The `@Tool` and `ToolCallbackProvider` model itself did not change; see xref:ai/spring-ai/tool-calling.adoc[Tool Calling] and xref:ai/spring-ai/tool-calling-advisor-and-tool-search.adoc[ToolCallingAdvisor & Tool Search].

== ChatClient, advisors and memory

.ChatClient, advisors and chat memory
[cols="3,3,2"]
|===
|Old (1.x) |New (2.0.1) |Notes

|`MessageChatMemoryAdvisor.builder(memory).conversationId("s1")`
|No default conversation ID; pass `ChatMemory.CONVERSATION_ID` on every call, or the advisor throws `IllegalArgumentException`. `ChatMemory.DEFAULT_CONVERSATION_ID` is removed
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_chat_memory_advisors_conversation_id_is_now_required[upgrade notes]

|`PromptChatMemoryAdvisor`
|`MessageChatMemoryAdvisor` (same builder API; history goes in as messages, not text in the system prompt)
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_removed_promptchatmemoryadvisor[upgrade notes]

|`BaseChatMemoryAdvisor.getConversationId(Map, String)`
|`getConversationId(Map)`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_changed_basechatmemoryadvisor_getconversationid_signature[upgrade notes]

|Memory advisor default order `HIGHEST_PRECEDENCE + 1000`
|`Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER` = `HIGHEST_PRECEDENCE + 200`, outside the tool loop (`+ 300`); memory stores only the final exchange
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_changed_advisor_default_chat_memory_precedence_order_default_value[upgrade notes]

|JDBC repository table without a sequence column
|`sequence_id` BIGINT column and an index; the timestamp is exposed as metadata
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_jdbc_chat_memory_sequence_id_column[upgrade notes]

|`MongoChatMemoryRepository` returning newest first
|Oldest first like every other repository; remove any reversal workaround
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_mongodb_chat_memory_message_ordering_fixed[upgrade notes]

|`ChatClient.create(chatModel)` running an internal tool loop
|Auto-registers `ToolCallingAdvisor`; disable with `spring.ai.chat.client.tool-calling.enabled=false`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_automatic_toolcallingadvisor_registration[upgrade notes]

|`ChatMemory` as the only memory abstraction
|Unchanged in 2.0. The community `spring-ai-session` project, which handles tool-call messages, is planned to replace it in 2.1; see xref:ai/spring-ai/agentic-patterns.adoc[Agentic Patterns]
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_changed_advisor_default_chat_memory_precedence_order_default_value[upgrade notes]

|Marker-less advisors
|New marker interfaces `ToolAdvisor` and `MemoryAdvisor`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_new_tooladvisor_marker_interface[upgrade notes]
|===

See xref:ai/spring-ai/chat-memory.adoc[Chat Memory], xref:ai/spring-ai/chat-memory-repositories.adoc[Chat Memory Repositories] and xref:ai/spring-ai/advisors.adoc[Advisors] for the 2.0.1 behaviour.

== Structured output, MCP, audio and observability

.Other areas
[cols="3,3,2"]
|===
|Old (1.x) |New (2.0.1) |Notes

|`CreateMessageResult.builder()`, `CreateMessageRequest.builder()` with no arguments
|Required fields up front: `CreateMessageResult.builder(role, content, model)`, `CreateMessageRequest.builder(messages, maxTokens)`; the no-argument builders are deprecated
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_mcp_sdk_breaking_changes_required_fields[upgrade notes]

|`elicit(TypeReference)`
|`ParameterizedTypeReference`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_mcp_elicitation_api_typereference_replaced_by_parameterizedtypereference[upgrade notes]

|`McpSyncClientCustomizer`, `McpAsyncClientCustomizer`; `customizeRequest()` on transport builders
|`McpClientCustomizer<B>`; `httpRequestCustomizer()` / `asyncHttpRequestCustomizer()`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_mcp_client_customizer_api_consolidated[upgrade notes]

|`@McpTool` methods that throw a checked exception or `Error` and expect the model to see it (2.0.1)
|Only `RuntimeException`s (other than `McpError`) reach the model as an error result; the rest fail hard
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_mcp_tool_exception_handling[upgrade notes]

|`SpeechModel`, `StreamingSpeechModel`, `SpeechPrompt`, `SpeechResponse` (`org.springframework.ai.openai.audio.speech`)
|`TextToSpeechModel`, `StreamingTextToSpeechModel`, `TextToSpeechPrompt`, `TextToSpeechResponse` in `org.springframework.ai.audio.tts`; the speed is a `Double`. Removed in 1.1.0-RC1, so a 1.1 application has already seen this
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#upgrading-to-1-1-0-RC1[upgrade notes]

|`TranscriptionModel` alone; `OpenAiAudioSpeechModel.stream` buffering the whole reply
|`TranscriptionModel` extends `StreamingTranscriptionModel` (the default `stream` fails with `UnsupportedOperationException`); OpenAI speech streams real chunks (2.0.1), so `blockFirst()` returns only the first chunk
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_transcriptionmodel_now_extends_streamingtranscriptionmodel[upgrade notes]

|Tool span `tool_call <name>`, `gen_ai.operation.name=framework`
|Span `execute_tool <name>`, `gen_ai.operation.name=execute_tool`; new `spring.ai.tool.type` and `spring.ai.tool.call.id`. Update dashboards and alerts that match the old names
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_observability[upgrade notes]

|Provider-specific cache numbers in metadata
|`Usage.getCacheReadInputTokens()` and `getCacheWriteInputTokens()`
|https://docs.spring.io/spring-ai/reference/upgrade-notes.html#_unified_cache_usage_metrics_on_usage[upgrade notes]

.Providers

|===

== Same code, different behaviour

These changes need no edit to compile, and each can change what a running application does. Check every row against your code.

== Migrating code from the books

Two books in this guide's bibliography were written against versions before 2.0. Their concepts are sound; their code needs the changes below. The snippets are shapes of the API those versions used, written for this page (not taken from the books), and are not compiled.

=== Spring AI in Action (Spring AI 1.0.3, Spring Boot 3.5)

_Spring AI in Action_ is close to 2.0 in style: fluent `ChatClient`, advisors, tools with `@Tool`, MCP. Most of the migration is the tables above. Its examples typically look like this:

.Spring AI 1.0.x style: does not compile on 2.0.1
[source,java]

    .defaultAdvisors(PromptChatMemoryAdvisor.builder(memory).conversationId("session-1").build())
    .defaultOptions(OpenAiChatOptions.builder().temperature(0.2).build())

Source: https://docs.spring.io/spring-ai/reference/upgrade-notes.html[Spring AI: Upgrade Notes].

and the 2.0.1 form is:

.MigratedDocsAssistant.java: the 2.0.1 forms of the changes above
[source,java]
----
package com.example.docsassistant;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.client.advisor.ToolCallingAdvisor;
import org.springframework.ai.chat.memory.ChatMemory;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.prompt.ChatOptions;
import org.springframework.ai.model.tool.ToolExecutionEligibilityChecker;
import org.springframework.ai.openai.OpenAiChatOptions;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.ai.tool.function.FunctionToolCallback;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/** The 2.0.1 form of the code the older books and 1.x tutorials show. */
@Configuration(proxyBeanMethods = false)
class MigratedDocsAssistant {

    record WeatherRequest(String city) { }

    record WeatherResponse(String summary) { }

    /** Was: a raw java.util.function.Function bean found by name. Now: an explicit ToolCallback. */
    @Bean
    ToolCallback currentWeather() {
        return FunctionToolCallback.builder("currentWeather",
                        (WeatherRequest request) -> new WeatherResponse("sunny in " + request.city()))
                .description("Get the weather in a city")
                .inputType(WeatherRequest.class)
                .build();
    }

    /** Was: an advisor created with .conversationId("...") or PromptChatMemoryAdvisor. */
    @Bean
    ChatClient memoryClient(ChatModel chatModel, ChatMemory chatMemory, ToolCallback currentWeather) {
        return ChatClient.builder(chatModel)
                .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())
                .defaultTools(currentWeather)   // defaultToolCallbacks(...) is deprecated for removal in 2.0
                .build();
    }

    String ask(ChatClient client, String conversationId, String question) {
        return client.prompt()
                .user(question)
                // options() takes the builder, not a built object; the fields you set override the model's start-up options,
                // and a request's options replace (not merge with) any defaultOptions(...) on the client
                .options(OpenAiChatOptions.builder().temperature(0.2))
                // the conversation id is required and supplied per call; derive it from the authenticated user, never from client input alone
                .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
                .call()
                .content();
    }

    /** Was: options.copy() / fromOptions(). Options are immutable; mutate() starts a builder from one. */
    ChatOptions lowerTemperature(ChatOptions options) {
        return options.mutate().temperature(0.0).build();
    }

    /** Was: internalToolExecutionEnabled(false). Now: decide in the advisor when the loop continues. */
    @Bean
    ToolExecutionEligibilityChecker stopOnFinishReasonStop() {
        return response -> response != null && response.hasToolCalls()
                && !"stop".equals(response.getResult().getMetadata().getFinishReason());
    }

    ToolCallingAdvisor insideTheLoopHistory() {
        return ToolCallingAdvisor.builder().disableInternalConversationHistory().build();
    }
}
----

Source: https://docs.spring.io/spring-ai/reference/upgrade-notes.html[Spring AI: Upgrade Notes].

The class compiled against 2.0.1. It is not a program to run; each method shows one change:

* the `Function` bean found by name becomes an explicit `ToolCallback` and is attached to the client;
* the memory advisor is `MessageChatMemoryAdvisor`, with the conversation ID passed on each call;
* `options(...)` takes the builder;
* `mutate()` replaces `copy()`;
* a `ToolExecutionEligibilityChecker` and `ToolCallingAdvisor.builder()` replace `internalToolExecutionEnabled`.

Other points for the _Spring AI in Action_ examples, in the book's own order of topics:

== Verify the upgrade

Compiling is not enough. After the mechanical changes:

* Run the scripted-model tests: they catch wiring, advisor order and tool-loop changes without a provider.
* Run the evaluation set against the same model before and after, and compare answers, latency, token use and cost; see xref:ai/spring-ai/evaluation.adoc[Evaluation]. Answers change with the default temperature and with structured-output schema changes even when the model is the same.
* Check the metrics and dashboards listed in xref:ai/spring-ai/observability.adoc[Observability] for the renamed tool span and the accumulated usage.
* Read the startup log for deprecation warnings on `.options` property paths and fix them now; the deprecated forms exist to ease the transition.
* Re-test the security paths from xref:ai/spring-ai/security-and-guardrails.adoc[Security & Guardrails]: per-request tool registration, `@PreAuthorize` on tools and the conversation ID derived from the token.
