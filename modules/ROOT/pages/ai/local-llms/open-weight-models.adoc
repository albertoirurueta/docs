== Licence classes

Open *weights* are not the same thing as open *source*, and the licence decides whether you may use a model at all:

* *Permissive (Apache-2.0, MIT)* -- use, modify, fine-tune and redistribute, commercially, with attribution.
  Apache-2.0 adds an explicit patent grant. Qwen3.6, Qwen3.8-27B, Gemma 4, Mistral Small 4, Ministral 3 and gpt-oss (Apache-2.0)
  and DeepSeek V3.2 / V4 (MIT) are in this class. This is the class to prefer for anything you ship.
* *Community licences* -- custom terms written by the vendor. The Llama 4 Community License, for example, is a
  separate agreement with its own acceptable-use policy and conditions; older DeepSeek models used a "DeepSeek
  License" model agreement distinct from the MIT code licence, and within Qwen3.8 the 2.4T-A95B
  (`qwen3.8-max`) and Flash-Next (`qwen-community-1.0`) models carry custom licences even though the 27B is
  Apache-2.0 -- so a family name never tells you the licence; the individual repository does. Read the actual text: these licences can restrict
  use cases, require attribution in product names, or add conditions for very large deployments.
* *Gated* -- the Hub repository requires you to accept the licence (and sometimes share contact details) before
  downloading. Gating is a distribution mechanism, not a licence type: a gated model can carry a permissive or a
  community licence. Pass `HF_TOKEN` to the engine after accepting.

The licence of a Hub repository is in its model card metadata (`license:`), with the full text usually in a
`LICENSE` file; see https://huggingface.co/docs/hub/repositories-licenses[Hugging Face -- Licenses]. Quantized
re-uploads (GGUF, AWQ) inherit the original licence -- check the base model's, not the uploader's summary. This is
engineering guidance, not legal advice; involve your legal team for anything customer-facing.

== Choosing by task

Choose by task first, then by what fits (see xref:ai/local-llms/hardware-sizing.adoc[Hardware Sizing]); this site
quotes no benchmark numbers, so evaluate the two or three candidates on your own prompts.

* *Coding and coding agents* -- use the coding-tuned variants (Devstral, Qwen-Coder, and the general Qwen3.6 /
  Qwen3.8 models, which their vendor positions for agentic coding). Tool-calling reliability and at least 64k
  context matter more than raw size for the assistants on
  xref:ai/local-llms/local-models-in-claude-code.adoc[Local Models in Claude Code] and
  xref:ai/local-llms/local-models-in-github-copilot.adoc[Local Models in GitHub Copilot].
* *Reasoning* -- models with a thinking mode (gpt-oss with adjustable reasoning effort, DeepSeek, Qwen's hybrid
  reasoning, Phi-4-reasoning). They trade latency and tokens for accuracy; see
  xref:ai/llm-foundations/reasoning-models.adoc[Reasoning Models].
* *Tool use and agents* -- a model whose chat template supports tools (the Ollama library tags them), served with
  the right parser (`--jinja` in llama.cpp, `--tool-call-parser` in vLLM). MoE models with few active parameters
  (gpt-oss-20b, Qwen3.6-35B-A3B, Gemma 4 26B-A4B) are fast enough for multi-step loops on one GPU.
* *Multilingual* -- Qwen3.5 and later state support for 201 languages and dialects; Gemma and Mistral are also
  strong multilingual families. Test in your languages -- 4-bit quantization hurts non-English text first
  (see xref:ai/local-llms/quantization-for-inference.adoc#_quality_vs_size_trade_offs[Quality vs. size]).
* *Embeddings* -- a separate, much smaller model: DocsAssistant uses `nomic-embed-text`; see
  xref:database/vector-rag/generating-embeddings-in-practice.adoc[Generating Embeddings in Practice].
* *On-device and in-app* -- the smallest variants (Gemma 4 E2B / E4B, Qwen3.5 0.8B-4B, Phi-4-mini) are the subject
  of the planned *Hugging Face & On-Device Models* sub-section.

== Example: serving an Apache-2.0 model in Ollama and vLLM

`gpt-oss-20b` is Apache-2.0, runs within 16 GB of memory thanks to its MXFP4 experts (per OpenAI's README), and
runs in both engines. In Ollama:

[source,shell]
----
ollama pull gpt-oss:20b
ollama run gpt-oss:20b "Explain the difference between Apache-2.0 and a community licence in three bullets."
----

See the https://github.com/openai/gpt-oss[openai/gpt-oss README] (Ollama section) and
xref:ai/local-llms/ollama.adoc[Ollama]. On a GPU server with vLLM:

[source,shell]
----
vllm serve openai/gpt-oss-20b --enable-auto-tool-choice --tool-call-parser openai
curl http://localhost:8000/v1/chat/completions -H "Content-Type: application/json" \
  -d '{"model": "openai/gpt-oss-20b", "messages": [{"role": "user", "content": "Hello"}]}'
----

See the https://github.com/openai/gpt-oss[openai/gpt-oss README] (vLLM section) and
https://docs.vllm.ai/en/stable/serving/online_serving/[vLLM -- Online serving]. The same pattern works for
Qwen3.6 (`ollama pull qwen3.6`, `vllm serve Qwen/Qwen3.6-27B`) once you have checked its licence on the model card.
