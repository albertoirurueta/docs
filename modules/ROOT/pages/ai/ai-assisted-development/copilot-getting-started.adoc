This page targets the current stable release of Visual Studio Code with the built-in GitHub Copilot and GitHub
Copilot Chat extensions, the GitHub Copilot plugin for JetBrains IDEs, and the standalone GitHub Copilot CLI
(the `@github/copilot` package), all checked against the official GitHub and VS Code documentation as of
2026-09-28. Both products ship updates frequently, so command names, keybindings and `#` references are the
ones documented on that date; re-check the linked pages if a menu or shortcut has moved since. The running
example throughout is *DocsAssistant API*, the small Spring Boot + Python sample used across this sub-section,
with its controller at `src/main/java/com/example/docsassistant/DocsController.java` and its tests under
`src/test/java/com/example/docsassistant/`.

== Installing and Signing In

GitHub Copilot needs a GitHub account with an active Copilot plan (Free, Pro, Pro+, Business or Enterprise) --
plans differ in how many completions, chat requests and premium-model requests they include, and those limits
are not repeated here: see
link:https://docs.github.com/en/copilot/get-started/plans[GitHub -- Plans for GitHub Copilot] for the current
figures.

*In VS Code*, the GitHub Copilot and GitHub Copilot Chat extensions are bundled with recent VS Code releases,
so there is usually nothing to install manually beyond opening VS Code itself. To sign in, use any of:

* select *Sign in to use Copilot* from the Copilot menu in the Status Bar;
* select the Accounts menu in the Activity Bar, then *Sign in with GitHub to use GitHub Copilot*;
* run the *GitHub Copilot: Sign in* command from the Command Palette.

*In JetBrains IDEs* (IntelliJ IDEA, PyCharm, WebStorm and the rest of the family), open *Settings -> Plugins*,
search the Marketplace for *GitHub Copilot*, install it, restart the IDE, and sign in from the Copilot tool
window that appears. The JetBrains plugin covers ghost-text completions, next edit suggestions, chat, inline
chat and commit-message generation from staged changes.

See
link:https://docs.github.com/en/copilot/how-tos/set-up/installing-the-github-copilot-extension-in-your-environment[GitHub
-- Installing the GitHub Copilot extension in your environment].

== Ghost-Text Completions and Next Edit Suggestions

Copilot offers two related kinds of inline suggestion directly in the editor:

* *Ghost-text completions* -- dimmed, greyed-out text that completes the current line or suggests a whole new
  block, generated from the current file and other open files as context.
* *Next edit suggestions* (Copilot NES) -- rather than completing what you are typing, NES predicts the
  *location* of your next edit elsewhere in the file (shown as an arrow in the gutter) and *what* that edit
  should be, for example fixing a typo, propagating a rename, or updating a related line after you changed a
  class's shape. NES is opt-in, enabled through the `github.copilot.nextEditSuggestions.enabled` setting.

Suppose the DocsAssistant controller only exposes `GET /api/pages`, and a comment sketches the next endpoint:

[source,java]
----
// GET /api/pages/{id} - return a single page by id, or 404 if it does not exist
@GetMapping("/api/pages/{id}")
public ResponseEntity<PageDto> getPage(@PathVariable Long id) {

}
----

Typing that comment and the method signature is usually enough for ghost text to suggest the method body; once
part of the file has changed, NES's gutter arrow can then point at the matching test class and offer to add a
`getPage_returns404WhenMissing` case there.

Accepting, rejecting, partially accepting and cycling through suggestions all use dedicated keybindings, which
differ slightly between macOS and Windows/Linux:

[cols="2,1,1,3", options="header"]
|===
| Action | macOS | Windows / Linux | Command

| Accept the current ghost-text suggestion, or navigate to / accept an NES edit
| kbd:[Tab]
| kbd:[Tab]
| `editor.action.inlineSuggest.commit`

| Dismiss (reject) the current suggestion
| kbd:[Esc]
| kbd:[Esc]
| `editor.action.inlineSuggest.hide`

| Accept only the next word or the next line of a ghost-text suggestion (partial accept)
| kbd:[Cmd+Right]
| kbd:[Ctrl+Right]
| `editor.action.inlineSuggest.acceptNextWord` / `acceptNextLine`

| Cycle to the next alternative suggestion
| kbd:[Option+]]
| kbd:[Alt+]]
| `editor.action.inlineSuggest.showNext`

| Cycle to the previous alternative suggestion
| kbd:[Option+[]
| kbd:[Alt+[]
| `editor.action.inlineSuggest.showPrevious`

| Manually trigger a suggestion at the cursor
| kbd:[Option+\]
| kbd:[Alt+\]
| `editor.action.inlineSuggest.trigger`
|===

These are VS Code's defaults; any of them can be rebound in the Keyboard Shortcuts editor by searching for the
command name. See
link:https://docs.github.com/en/copilot/reference/keyboard-shortcuts[GitHub -- Keyboard shortcuts for GitHub
Copilot in the IDE] and
link:https://code.visualstudio.com/docs/editing/ai-powered-suggestions[VS Code -- Inline suggestions from GitHub
Copilot].

== Chat and Inline Chat

*Chat* is the panel-based conversation (the Chat view, or the newer Agents window), for anything from a
one-off question to a multi-file change. *Inline chat* (kbd:[Cmd+I] / kbd:[Ctrl+I] in the editor) scopes a
prompt to the active editor -- optionally to just the selected code -- and shows the suggested change as an
inline diff you accept with *Keep* or reject with *Undo*, without leaving the file; a separate terminal inline
chat does the same for shell commands in the integrated terminal. See
link:https://code.visualstudio.com/docs/chat/inline-chat[VS Code -- Inline chat and Quick Chat].

=== `#` context references

Typing `#` in the chat input opens a picker of context you can attach explicitly, instead of relying on
Copilot's automatic workspace indexing. As of the date above, VS Code groups what appears behind `#` into three
kinds -- tools (actions, such as searching or reading a file), tool sets (named groups of tools) and plain
context items -- and the exact reference names have moved since Copilot chat first shipped, so don't assume any
older list is still complete. The context items you attach directly are:

* `#<file>`, `#<folder>` and `#<symbol>` -- a specific file, folder or code symbol picked from the `#` list
  (open the file first to reference a symbol inside it), for example `#DocsController.java`.
* `#selection` -- the text currently selected in the editor.
* `#codebase` -- tells Copilot to treat the whole indexed workspace as context, backed by the same semantic
  search tool the picker calls `#search/codebase`.

Terminal context, which older documentation named as a standalone `#terminalLastCommand` reference, is now
surfaced under the `#read` tool set as `#read/terminalLastCommand` (the last command and its output) and
`#read/terminalSelection` (the current terminal selection); typing `#read` or `#terminalLastCommand` in the
picker shows the current name. See
link:https://code.visualstudio.com/docs/agents/reference/tools-reference[VS Code -- Tools and context reference]
and
link:https://code.visualstudio.com/docs/chat/copilot-chat-context[VS Code -- Add context to chat] for the
authoritative, up-to-date list.

=== Attaching files and images

Beyond `#`-mentions, you can drag files or folders from the Explorer, Search view or editor tabs onto the Chat
view, or select *Add Context* and choose *Files & Folders* or *Symbols* from the picker. Chat also supports
vision: paste a screenshot (from the clipboard or by dragging it from a browser) or attach an image file, and
ask Copilot to explain it or turn a UI sketch into code. See
link:https://code.visualstudio.com/docs/chat/copilot-chat-context[VS Code -- Add context to chat].

=== Example: adding an endpoint to DocsAssistant API

A chat prompt that asks for a new `GET /api/pages/\{id}` endpoint, with the file attached explicitly so Copilot
edits the right controller instead of guessing at one:

[source,text]
----
#DocsController.java Add a GET /api/pages/{id} endpoint that returns the page as a PageDto,
or a 404 with a JSON error body when no page has that id. Follow the same style as the
existing GET /api/pages handler above it.
----

Copilot proposes the new method as an inline diff in the Chat view (or directly in the editor, for inline
chat), which you review and accept before it is written to
`src/main/java/com/example/docsassistant/DocsController.java`. See
link:https://code.visualstudio.com/docs/copilot/chat/copilot-chat[VS Code -- Use chat in VS Code].

== The Copilot CLI and Copilot on github.com

=== Copilot CLI

The GitHub Copilot CLI is a standalone terminal agent, separate from the IDE extensions, distributed as the
`@github/copilot` package. It replaces the older `gh copilot` GitHub CLI extension, which only answered
one-shot "explain" and "suggest" questions; the Copilot CLI is a full agent that can read, edit and run
commands in a project, and act on github.com on your behalf. Install it with any of:

[source,console]
----
$ npm install -g @github/copilot          # all platforms, needs Node.js 22+
$ brew install --cask copilot-cli         # macOS / Linux
$ winget install GitHub.Copilot           # Windows
$ curl -fsSL https://gh.io/copilot-install | bash   # macOS / Linux install script
----

Run `copilot` with no arguments to start an interactive session; on first use it prompts you to run `/login`
and authenticate with your GitHub account. Inside the session, press kbd:[Shift+Tab] to switch between the
default ask/execute mode and a plan mode that drafts a structured implementation plan before touching any
files. A first prompt against DocsAssistant API might be:

[source,console]
----
$ copilot
> Add a GET /api/pages/{id} endpoint to DocsController that returns the page as a PageDto,
  or a 404 with a JSON error body when the id doesn't exist. Then run the existing tests.
----

For a one-shot, non-interactive invocation instead of a session, use `-p`/`--prompt`, combined with an
allow-tool option so it can act without an approval prompt for that one command:

[source,console]
----
$ copilot -p "Summarize this week's commits" --allow-tool='shell(git)'
----

See
link:https://docs.github.com/en/copilot/concepts/agents/about-copilot-cli[GitHub -- About GitHub Copilot CLI]
and
link:https://docs.github.com/en/copilot/how-tos/set-up/install-copilot-cli[GitHub -- Installing GitHub Copilot
CLI].

=== Copilot on github.com

Copilot is also available directly on github.com: a chat panel at `github.com/copilot` (and inline on any
issue, pull request or file page) answers questions about a repository, its commits and its pull requests, and
can create issues on your behalf. On a pull request specifically, selecting *Summary* in the description or
comment editor's toolbar generates an AI-written overview -- a short prose summary followed by a bulleted list
of key changes linked to the files they touch -- meant to help a reviewer decide where to look first, not to
replace a human description. See
link:https://docs.github.com/en/copilot/how-tos/copilot-on-github[GitHub -- GitHub Copilot on GitHub] and
link:https://docs.github.com/en/copilot/how-tos/copilot-on-github/copilot-for-github-tasks/create-a-pr-summary[GitHub
-- Creating a pull request summary with GitHub Copilot].
