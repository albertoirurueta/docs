== Tool categories

Every tool below fits at least one of six categories. A single product can span several: GitHub Copilot, for
example, ships a completion engine, a chat panel, an agent mode and a cloud agent all at once.

Completion:: Inline "ghost text" that continues the line or block you are typing, plus next-edit suggestions
that predict a related edit elsewhere in the file. It needs no prompt beyond the code and comment already
there. Example: typing `// return all pages whose title contains the given keyword` above an empty method in
`DocsController.java` and accepting the suggested body with kbd:[Tab]. See
https://docs.github.com/en/copilot/concepts/completions[GitHub Copilot — Completions].

IDE chat:: A conversational panel inside the editor that answers questions and can edit the file you are
looking at, but only when you ask; it does not act on its own. Example: asking "Explain what this method does
and list its edge cases" in the chat panel with `DocsController.java` open. See
https://code.visualstudio.com/docs/chat/chat-overview[VS Code — Use chat in VS Code].

IDE agent:: A mode where the assistant plans a multi-file change, edits, runs commands (build, test, lint) and
reports back, asking for approval at configured points. Example: "Add a `GET /api/pages/\{id}` endpoint with a
test" run in agent mode inside the IDE. See https://code.visualstudio.com/docs/agents/overview[VS Code — Build
with agents in VS Code].

Terminal agent:: The same agentic loop, run from the command line instead of an IDE, so it composes with shell
pipes, scripts and CI. Example: `claude "write tests for DocsController and run them"`. See
https://code.claude.com/docs/en/overview[Claude Code — Overview].

Cloud / background agent:: An agent that runs unattended in its own remote sandboxed environment -- typically
started from an issue, a PR comment or a chat mention -- and reports back with a pull request once it is done.
Example: assigning a GitHub issue to Copilot and letting it open a draft PR while you do something else. See
https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent[GitHub Copilot — About Copilot
cloud agent].

App builder:: A prompt- or screenshot-driven tool that generates a runnable UI or small app from scratch,
optimized for a fast prototype rather than for editing an existing large codebase. Example: "Build a page that
lists DocsAssistant's indexed pages with a search box" typed into a fresh v0 project. See
https://v0.app/docs[v0 by Vercel — What is v0?]. This category is covered in depth on
xref:ai/ai-assisted-development/prototyping-with-ai.adoc[Prototyping with AI].

=== The autonomy ladder

The categories above sit on a single ladder of increasing autonomy: each rung keeps everything the rung below it
can do, and adds the ability to act with less turn-by-turn supervision.

[mermaid]
....
flowchart LR
  A["Completion<br/>finishes what you type"] --> B["Chat<br/>answers when asked"]
  B --> C["Agent<br/>plans, edits, runs, verifies"]
  C --> D["Background agent<br/>runs unattended, reports back"]
....

App builders sit alongside this ladder rather than on it: they are agentic in the same sense as an IDE or
terminal agent, but scoped to generating a new app rather than working inside an existing one. The ladder itself
-- and the "70{nbsp}% problem" of the extra effort needed to take an agent's output the rest of the way -- is
introduced on xref:ai/ai-assisted-development/index.adoc[AI-Assisted Development] and covered in more depth on
xref:ai/ai-assisted-development/agent-mode.adoc[Agent Mode].

== When to use which

[cols="3,2,4", options="header"]
|===
| Task | Best-fit category | Why

| A one-line edit while typing (a getter, a loop bound, an obvious continuation)
| Completion
| Ghost text finishes the line in place; there is no round trip to a chat panel to interrupt typing flow.

| "Explain this" or "what does this parameter do" about code already open
| IDE chat
| The answer sits next to the code, using open tabs and the current selection as context, with no file changes.

| "Add an endpoint and its tests" spanning a controller, a service and a test file
| IDE agent
| The agent plans across files, runs the build and test commands itself, and presents one reviewable diff.

| A scripted, repeatable task: a formatting pass, a bulk rename, a CI step
| Terminal agent
| Composable with shell pipes, flags and exit codes, so it fits a script or a CI job rather than a chat UI.

| "Pick up this issue and open a PR" while you are away from the keyboard
| Cloud / background agent
| Runs unattended in its own sandboxed environment and comes back with a pull request to review later.

| "Turn this idea or screenshot into a working UI, fast"
| App builder
| Optimized for a working prototype from a short prompt or an image, not for editing a large existing codebase.
|===

=== One example per category, in its native form

.Completion -- a comment that grows into a method
[source,java]
----
// return all pages whose title contains the given keyword, case-insensitively
----
Typed above an empty method in `DocsController.java`; Copilot's ghost text completes the method body beneath it.
See https://docs.github.com/en/copilot/concepts/completions[GitHub Copilot — Completions].

.IDE chat -- a question about open code
[source,text]
----
Explain what DocsController.getPageById does and list its edge cases.
----
Asked in the VS Code Chat view with `DocsController.java` open. See
https://code.visualstudio.com/docs/chat/chat-overview[VS Code — Use chat in VS Code].

.IDE agent -- a multi-file change
[source,text]
----
Add a GET /api/pages/{id} endpoint to DocsController, backed by PageService, with a passing test.
----
Run in VS Code's agent mode. See https://code.visualstudio.com/docs/agents/overview[VS Code — Build with agents
in VS Code].

.Terminal agent -- the same task from a shell
[source,console]
----
$ claude "add a GET /api/pages/{id} endpoint to DocsController, backed by PageService, with a passing test"
----
See https://code.claude.com/docs/en/overview[Claude Code — Overview].

.Cloud / background agent -- delegating a whole issue
[source,text]
----
@claude please pick up issue #42 (add pagination to GET /api/pages) and open a PR.
----
Posted as a GitHub issue or PR comment once the Claude GitHub App is installed. See
https://code.claude.com/docs/en/github-actions[Claude Code — GitHub Actions]. The Copilot cloud agent equivalent
is assigning the issue directly to Copilot; see
https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent[GitHub Copilot — About Copilot
cloud agent].

.App builder -- a prompt that generates a new UI
[source,text]
----
Build a page that lists DocsAssistant's indexed pages with a search box, using a simple card layout.
----
Typed into a new v0 project. See https://v0.app/docs[v0 by Vercel — What is v0?].
