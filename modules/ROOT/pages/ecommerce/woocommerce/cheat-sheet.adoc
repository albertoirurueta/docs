== Cloud deployment

The summary printed in the PDF for running WooCommerce on many pods in the cloud on Amazon EKS (checked on 2026-10-29); each row is explained on the pages above.

[cols="1,5",options=header]
|===
|Topic |Rule

|Database
|RDS for MariaDB 11.8 or MySQL 8.4 sized from orders, not page views; HPOS on and compatibility mode off after `wp wc hpos verify_data`; clean `woocommerce_sessions`; checkout always reads the writer, never a replica.

|State placement
|Media on S3 behind CloudFront; object cache on Valkey; sessions in the `woocommerce_sessions` table; CloudFront bypasses cart, checkout, account, Store API, `wc-ajax` and `wc-api`; payment webhooks reach any pod and must be idempotent; extensions only through the image.

|Cron
|`DISABLE_WP_CRON` true plus one CronJob for WP-Cron; Action Scheduler async runner off (`action_scheduler_allow_async_request_runner` false) and a worker Deployment looping `wp action-scheduler run`, scaled by KEDA on pending actions.

|Release steps
|Pre-upgrade Job runs `wp wc update` once with a migration database user (automatic update off through `woocommerce_enable_auto_update_db`), rolling update, RDS snapshot before; freeze calendar for peak season.

|Key commands
|`wp wc hpos status`, `wp action-scheduler status`, `wp wc update`, `wp wc webhook list`, `wp maintenance-mode activate`, `helm upgrade pocketcoffee ./pocketcoffee-woocommerce`.
|===
