== Cloud deployment

The summary printed in the PDF for running Magento on many pods in the cloud on Amazon EKS (checked on 2026-10-29); each row is explained on the pages above.

[cols="1,5",options=header]
|===
|Topic |Rule

|Database
|RDS for MySQL 8.4 or MariaDB 12.3, or Aurora MySQL 3 (listed by Adobe for 2.4.9); `env.php` reads the environment with TLS; `mg_app` and a migration user; split database is deprecated since 2.4.2.

|State placement
|Five services: RDS, OpenSearch 3.x, two Valkey groups (cache and sessions), Amazon MQ for RabbitMQ 4.3, S3 for media (remote storage driver, `remote-storage:sync`); Varnish StatefulSet for the full page cache; `config.php` committed, secrets in the environment; code, DI and static content built into the image.

|Cron
|One CronJob running `cron:run --group=<id> --bootstrap=standaloneProcessStarted=1` per group; consumers as Deployments running `queue:consumers:start` scaled by KEDA, `cron_consumers_runner` off; indexers on Update by Schedule.

|Release steps
|Gate with `setup:db:status`; pre-upgrade Job `setup:upgrade --keep-generated` (or `app:config:import`); pause consumers and cron; rolling update behind Varnish; static content and DI are built into the image, so nothing is compiled at run time.

|Key commands
|`bin/magento setup:db:status`, `indexer:status`, `queue:consumers:list`, `cache:status`, `config:show web/secure/base_url`, `helm upgrade pocketcoffee ./pocketcoffee-magento`.
|===
