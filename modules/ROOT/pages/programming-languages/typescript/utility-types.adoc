= Utility Types
:description: TypeScript's built-in generic type helpers -- Partial, Pick, Record, Exclude, ReturnType, Awaited, Uppercase and the rest -- and the one-line mapped or conditional type behind each.
:keywords: TypeScript, utility types, Partial, Required, Readonly, Record, Pick, Omit, Exclude, Extract, NonNullable, Parameters, ConstructorParameters, ReturnType, InstanceType, ThisParameterType, OmitThisParameter, Awaited, Uppercase, Lowercase, Capitalize, Uncapitalize, NoInfer
:page-aliases: web/typescript/utility-types.adoc

include::partial$ai-disclaimer.adoc[]

TypeScript ships a set of generic types in the global scope that transform other types: make every
property optional, pull the return type out of a function, drop members from a union. They are ordinary
mapped and conditional types -- nothing magic -- and the full list lives in
https://www.typescriptlang.org/docs/handbook/utility-types.html[Utility Types]. This page groups them by
what they operate on and shows the definition behind each. For how those definitions are built, see
xref:programming-languages/typescript/type-manipulation.adoc[]; for the generic syntax they use, see
xref:programming-languages/typescript/generics.adoc[].

== Object-shape utilities

These rework the property set of an object type. `Partial`, `Required` and `Readonly` flip a modifier on
every property; `Pick` and `Omit` select or drop a subset of keys; `Record` builds a fresh object type
from a key union and a value type.

[source,ts]
----
interface User {
  id: number;
  name: string;
  email: string;
}

// Partial<T> -- every property optional (patch objects)
function applyPatch(user: User, patch: Partial<User>): User {
  return { ...user, ...patch };
}
applyPatch({ id: 1, name: "Ada", email: "a@x.io" }, { name: "Ada L." });

// Required<T> -- every property required (undo optionality)
interface Config { host?: string; port?: number; }
const resolved: Required<Config> = { host: "localhost", port: 5432 };

// Readonly<T> -- every property read-only (compile-time freeze)
const frozen: Readonly<User> = { id: 1, name: "Ada", email: "a@x.io" };
// frozen.name = "x"; // Error: Cannot assign to 'name' because it is a read-only property.

// Pick<T, Keys> -- keep only the listed keys
type UserPreview = Pick<User, "id" | "name">;   // { id: number; name: string }

// Omit<T, Keys> -- drop the listed keys
type UserDraft = Omit<User, "id">;              // { name: string; email: string }

// Record<Keys, Value> -- object type with those keys, each of Value
type RolePermissions = Record<"admin" | "editor" | "viewer", boolean>;
const perms: RolePermissions = { admin: true, editor: true, viewer: false };
----

`Pick` keys must exist on `T`; `Omit` keys are not constrained, which makes `Omit` convenient but
slightly looser. See
https://www.typescriptlang.org/docs/handbook/utility-types.html#picktype-keys[`Pick`],
https://www.typescriptlang.org/docs/handbook/utility-types.html#omittype-keys[`Omit`] and
https://www.typescriptlang.org/docs/handbook/utility-types.html#recordkeys-type[`Record`]. For the
`interface` versus type-alias choice these produce, see xref:programming-languages/typescript/objects-and-interfaces.adoc[].

== Union algebra

`Exclude` and `Extract` filter a union member by member; `NonNullable` is the special case that removes
`null` and `undefined`.

[source,ts]
----
type Shape = "circle" | "square" | "triangle" | null;

type NamedShape = Exclude<Shape, null>;            // "circle" | "square" | "triangle"
type Corners = Exclude<NamedShape, "circle">;      // "square" | "triangle"
type OnlyCircle = Extract<NamedShape, "circle" | "hexagon">; // "circle"

type MaybeName = string | null | undefined;
type Name = NonNullable<MaybeName>;                // string

// Extract also works structurally: keep union members assignable to a shape
type Events =
  | { kind: "click"; x: number; y: number }
  | { kind: "key"; code: string }
  | { kind: "scroll"; dy: number };
type PointerEvents = Extract<Events, { x: number }>; // the "click" member
----

`Exclude<T, U>` keeps the members of `T` *not* assignable to `U`; `Extract<T, U>` keeps the ones that
*are*. Docs:
https://www.typescriptlang.org/docs/handbook/utility-types.html#excludeuniontype-excludedmembers[`Exclude`],
https://www.typescriptlang.org/docs/handbook/utility-types.html#extracttype-union[`Extract`] and
https://www.typescriptlang.org/docs/handbook/utility-types.html#nonnullabletype[`NonNullable`].

== Function and class reflection

These read types back out of functions, constructors and promises. Each is a conditional type with an
`infer` clause.

[source,ts]
----
function createUser(name: string, age: number, admin = false) {
  return { name, age, admin, createdAt: Date.now() };
}

type CreateArgs = Parameters<typeof createUser>; // [name: string, age: number, admin?: boolean]
type NewUser = ReturnType<typeof createUser>;    // { name: string; age: number; admin: boolean; createdAt: number }

class Connection {
  constructor(public host: string, public port: number) {}
  query(sql: string) { return [] as unknown[]; }
}

type ConnArgs = ConstructorParameters<typeof Connection>; // [host: string, port: number]
type Conn = InstanceType<typeof Connection>;              // Connection

// this-parameter helpers
interface Account { name: string; }
function describe(this: Account, prefix: string): string {
  return `${prefix}: ${this.name}`;
}
type DescribeThis = ThisParameterType<typeof describe>;  // Account
type DescribeBound = OmitThisParameter<typeof describe>; // (prefix: string) => string

// Awaited<T> -- unwrap Promise (recursively), mirrors `await`
type A = Awaited<Promise<string>>;              // string
type B = Awaited<Promise<Promise<number>>>;     // number
type C = Awaited<ReturnType<typeof fetch>>;     // Response
----

`Awaited` is what `async` functions and `Promise.all` use internally; reach for it whenever you name the
resolved type of a promise. See
https://www.typescriptlang.org/docs/handbook/utility-types.html#parameterstype[`Parameters`],
https://www.typescriptlang.org/docs/handbook/utility-types.html#returntypetype[`ReturnType`],
https://www.typescriptlang.org/docs/handbook/utility-types.html#instancetypetype[`InstanceType`] and
https://www.typescriptlang.org/docs/handbook/utility-types.html#awaitedtype[`Awaited`]. Promise-heavy code
is covered in xref:programming-languages/typescript/async-and-iterators.adoc[].

== String-literal utilities and inference control

`Uppercase`, `Lowercase`, `Capitalize` and `Uncapitalize` are intrinsic types that transform string
literal types -- most useful inside the template literal types described in
xref:programming-languages/typescript/type-manipulation.adoc[].

[source,ts]
----
type Method = "get" | "post" | "delete";
type ScreamMethod = Uppercase<Method>;            // "GET" | "POST" | "DELETE"
type LowerMethod = Lowercase<"GET" | "POST">;     // "get" | "post"

type DomEvent = "click" | "focus";
type Handler = `on${Capitalize<DomEvent>}`;       // "onClick" | "onFocus"
type Field = Uncapitalize<"FirstName" | "LastName">; // "firstName" | "lastName"
----

=== NoInfer<T>

`NoInfer<T>` blocks a type parameter from being inferred from the position it wraps, so inference is
driven only by the other arguments.

[source,ts]
----
function paint<C extends string>(palette: C[], selected: NoInfer<C>) {
  /* ... */
}

paint(["red", "green", "blue"], "green"); // ok
paint(["red", "green", "blue"], "pink");  // Error: "pink" is not assignable to "red" | "green" | "blue"
// Without NoInfer, `selected: "pink"` would widen C to include "pink" and the call would compile.
----

See https://www.typescriptlang.org/docs/handbook/utility-types.html#noinfertype[`NoInfer`]. It pairs well
with the `const` type parameters from xref:programming-languages/typescript/generics.adoc[].

== How each is implemented

Every utility above is one line of the machinery from xref:programming-languages/typescript/type-manipulation.adoc[]. The
object-shape helpers are homomorphic mapped types; the union helpers are distributive conditional types;
the reflection helpers are conditional types with `infer`:

[source,ts]
----
// Standard library definitions (from lib.es5.d.ts), simplified:
type Partial<T>  = { [P in keyof T]?: T[P] };
type Required<T> = { [P in keyof T]-?: T[P] };
type Readonly<T> = { readonly [P in keyof T]: T[P] };

type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Record<K extends keyof any, T> = { [P in K]: T };

type Exclude<T, U> = T extends U ? never : T;
type Extract<T, U> = T extends U ? T : never;
type NonNullable<T> = T extends null | undefined ? never : T;

type Parameters<T extends (...a: any) => any> =
  T extends (...a: infer P) => any ? P : never;
type ReturnType<T extends (...a: any) => any> =
  T extends (...a: any) => infer R ? R : never;
----

`Omit` is the one composite: `type Omit<T, K> = Pick<T, Exclude<keyof T, K>>` -- pick every key except
the excluded ones. Because `Exclude` distributes over unions, `Exclude<"a" | "b" | "c", "b">` is
evaluated for each member separately and the survivors are unioned back together. `Uppercase` and its
three siblings are the exception: they are compiler intrinsics with no TypeScript-level definition.

== Keeping two values in sync with Record

A `Record` key union is checked for completeness, so deriving one table's type from a single source
union keeps every table over that union aligned. Add a member and each `Record` fails to compile until
its object literal is updated.

[source,ts]
----
const LOCALES = ["en", "es", "fr"] as const;
type Locale = (typeof LOCALES)[number];          // "en" | "es" | "fr"

// Every locale must have a greeting -- a missing key is a compile error.
const greetings: Record<Locale, string> = {
  en: "Hello",
  es: "Hola",
  fr: "Bonjour",
};

// Same union, second table stays in step.
const flags: Record<Locale, string> = { en: "GB", es: "ES", fr: "FR" };
----

== One source of truth: deriving every shape from `User`

The best use of utility types is to define a domain type once and *derive* each variant, so that adding a field
changes every variant at the same time. The `User` of the
xref:programming-languages/typescript/worked-example.adoc[worked example] shows the pattern:

[mermaid]
....
flowchart TD
    U["User<br/>id, name, email, passwordHash, address"] --> PU["PublicUser = Omit(User, passwordHash)"]
    U --> NU["NewUser = Omit(User, id and passwordHash)"]
    U --> UP["UserPatch = Partial(Pick(User, name and email))"]
    PU --> RO["Readonly(PublicUser)<br/>what the UI receives"]
    UP --> AP["applyPatch(user, patch)"]
....

[source,typescript]
----
interface User {
  id: string; name: string; email: string; passwordHash: string;
  address: { city: string; zip: string };
}
type PublicUser = Omit<User, "passwordHash">;
type UserPatch  = Partial<Pick<User, "name" | "email">>;
type NewUser    = Omit<User, "id" | "passwordHash">;

type Bad1 = Pick<User, "nope">;                 // error
type Ok2  = Omit<User, "nope">;                 // accepted: Omit does not check its keys

declare const pu: PublicUser;
pu.passwordHash;                                // error: the field is gone from the type
const patch: UserPatch = { name: "x", email: undefined };   // ok by default
const patch2: UserPatch = { nam: "x" };         // error: typo caught
----

[source,console]
----
ut.ts(5,24): error TS2344: Type '"nope"' does not satisfy the constraint 'keyof User'.
ut.ts(8,4): error TS2339: Property 'passwordHash' does not exist on type 'PublicUser'.
ut.ts(10,29): error TS2561: Object literal may only specify known properties, but 'nam' does not exist in type 'Partial<Pick<User, "name" | "email">>'. Did you mean to write 'name'?
----

The asymmetry on lines 5 and 6 is the reason to prefer `Pick` when you want a typo to be an error and `Omit` when you
want to stay open to a removed field. A type that mentions a key that no longer exists compiles silently with
`Omit`, so a rename can leave a stale entry that does nothing.

== Three pitfalls, each with its output

*`Partial` and `Readonly` are shallow.* They flip the modifier on the top-level properties only:

[source,typescript]
----
const deep: Partial<User> = { address: { city: "x" } };   // error: zip is still required inside address
const frozen: Readonly<{ tags: string[] }> = { tags: [] };
frozen.tags.push("a");                                     // accepted: the array itself is mutable
----

[source,console]
----
ut.ts(12,31): error TS2741: Property 'zip' is missing in type '{ city: string; }' but required in type '{ city: string; zip: string; }'.
----

A `DeepPartial` or `DeepReadonly` needs a recursive mapped type, as built on
xref:programming-languages/typescript/type-manipulation.adoc[Type Manipulation].

*`Omit` and `Pick` do not distribute over a union.* `keyof` of a union is only the keys they have in common, so
`Omit` on a union of two shapes collapses them into one weak shape:

[source,typescript]
----
type Shape = { kind: "circle"; r: number } | { kind: "square"; side: number };
type O1 = Omit<Shape, "kind">;                       // {} -- both r and side are lost
type DistOmit<T, K extends PropertyKey> = T extends unknown ? Omit<T, K> : never;
type O2 = DistOmit<Shape, "kind">;                   // { r: number } | { side: number }
const o3: O2 = { side: 2 };                          // ok
const o4: O2 = { };                                  // error
----

[source,console]
----
ut.ts(22,7): error TS2322: Type '{}' is not assignable to type 'O2'.
----

`DistOmit` uses the same distributive trick from the conditional-types section to apply `Omit` to each member
separately.

*`ReturnType` of a generic function loses the type parameter.* The checker cannot know which `T` you would have
supplied, so it uses the constraint, which for an unconstrained `T` is `unknown`:

[source,typescript]
----
function id<T>(x: T): T { return x; }
type IR = ReturnType<typeof id>;
declare const ir: IR;
const n: number = ir;
----

[source,console]
----
ut2.ts(4,7): error TS2322: Type 'unknown' is not assignable to type 'number'.
----

== Reflecting on functions and classes

`Parameters`, `ReturnType`, `Awaited`, `ConstructorParameters` and `InstanceType` turn a function or class you already
have into types, which keeps wrappers in sync with the thing they wrap. Applied to an `async` function from the
running example:

[source,typescript]
----
async function fetchUser(id: string, opts?: { cache: boolean }): Promise<User | undefined> { return undefined; }

type FP = Parameters<typeof fetchUser>;                    // [id: string, opts?: { cache: boolean }]
type FR = ReturnType<typeof fetchUser>;                    // Promise<User | undefined>
type FA = Awaited<ReturnType<typeof fetchUser>>;           // User | undefined

const fp: FP = ["a", { cache: true }, 3];                  // error: too many elements
const fr: FR = 1;                                          // error: not a Promise
const fa: FA = 1;                                          // error: 'number' is not 'User'

class Svc { constructor(public url: string, n: number) {} }
type CP = ConstructorParameters<typeof Svc>;               // [url: string, n: number]
const cp: CP = ["a"];                                      // error: n is required
----

[source,console]
----
ut.ts(28,7): error TS2322: Type '[string, { cache: true; }, number]' is not assignable to type '[id: string, opts?: { cache: boolean; } | undefined]'.
  Source has 3 element(s) but target allows only 2.
ut.ts(29,7): error TS2322: Type 'number' is not assignable to type 'Promise<User | undefined>'.
ut.ts(30,7): error TS2322: Type 'number' is not assignable to type 'User'.
ut.ts(38,7): error TS2322: Type '[string]' is not assignable to type '[url: string, n: number]'.
  Source has 1 element(s) but target requires 2.
----

Note the labels in the tuple types (`id`, `opts`, `url`, `n`): they come from the parameter names, and a wrapper
that spreads `+...args: Parameters<typeof fetchUser>+` keeps the names for editor hints. Note also that `Awaited` is
needed because `ReturnType` of an `async` function is the *promise*, not the value inside it.

== Summary

[cols="1,3",options="header"]
|===
| Utility | Transforms

| `Partial<T>`               | Every property of `T` optional
| `Required<T>`              | Every property of `T` required
| `Readonly<T>`              | Every property of `T` read-only
| `Record<K, V>`             | Object type with keys `K`, each value `V`
| `Pick<T, K>`               | Object type with only the keys `K` of `T`
| `Omit<T, K>`               | `T` without the keys `K`
| `Exclude<T, U>`            | Union `T` without members assignable to `U`
| `Extract<T, U>`            | Union `T` keeping only members assignable to `U`
| `NonNullable<T>`           | `T` without `null` and `undefined`
| `Parameters<F>`            | Tuple of `F`&#39;s parameter types
| `ConstructorParameters<C>` | Tuple of `C`&#39;s constructor parameter types
| `ReturnType<F>`            | `F`&#39;s return type
| `InstanceType<C>`          | Instance type produced by `new C`
| `ThisParameterType<F>`     | Type of `F`&#39;s `this` parameter
| `OmitThisParameter<F>`     | `F` with its `this` parameter removed
| `Awaited<T>`               | Resolved type of a `Promise` (recursive)
| `Uppercase<S>` / `Lowercase<S>` | String literal `S` upper- / lower-cased
| `Capitalize<S>` / `Uncapitalize<S>` | First character of `S` up- / down-cased
| `NoInfer<T>`               | `T`, but excluded from type inference
|===

The handbook page https://www.typescriptlang.org/docs/handbook/utility-types.html[Utility Types] is the
authoritative list and tracks additions each release.
