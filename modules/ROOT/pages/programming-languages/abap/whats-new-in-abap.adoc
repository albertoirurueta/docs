= What's New in ABAP
:description: How ABAP changed over time, from the expression syntax of release 7.40 to Standard ABAP 8.16 and ABAP for Cloud Development 9.20 (2608), and how to read the official release news.
:keywords: ABAP, release news, 7.40, 8.16, 9.20, 2608, ABAP Cloud, Standard ABAP, CDS aspects, external entities, TYPE ANY STRUCTURE, DELETE DUPLICATES, MERGE

include::partial$ai-disclaimer.adoc[]

ABAP is a language that keeps growing: every release adds statements, built-in functions and data-modelling features, and
very rarely removes something that already works. A newcomer meets this history in two places. Old code that was written
years ago looks different from code written today, and the official documentation tells you which release introduced each
feature. This page explains how ABAP releases are numbered, how the two flavours of the language (Standard ABAP and ABAP
for Cloud Development) are released, what the big steps were, and how to find out whether a statement is available on
the system you work on. It is written against Standard ABAP release 8.16 (on premise and private cloud) and ABAP for
Cloud Development release 9.20, delivered as 2608 in SAP S/4HANA Cloud Public Edition and in the SAP BTP ABAP
environment. The next release for the BTP ABAP environment, 9.21, is planned for 2611. After reading you can look up a
feature in the release news and decide whether you may use it in ABAP Cloud, in classic Standard ABAP, or in both.

== Before you read

* xref:programming-languages/abap/index.adoc[ABAP] gives the overview of the section and the version baseline.
* You do not need to know any ABAP syntax. The code samples are short and each one is explained in plain words.
* The pages xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects], xref:programming-languages/abap/internal-tables.adoc[Internal Tables] and xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects] explain these features in full.

== Key terms

* xref:programming-languages/abap/glossary.adoc#abap-release[ABAP release]: the number, such as 8.16 or 9.20, that names the version of the ABAP language and runtime delivered with a SAP product.
* xref:programming-languages/abap/glossary.adoc#standard-abap[Standard ABAP]: the full language, with all classic statements, used on premise and in the private cloud editions.
* xref:programming-languages/abap/glossary.adoc#abap-cloud[ABAP Cloud]: the restricted, upgrade-safe way of programming ABAP that uses only released APIs and the language version ABAP for Cloud Development.
* xref:programming-languages/abap/glossary.adoc#release-news[Release news]: the part of the ABAP Keyword Documentation that lists, per release, what is new.
* xref:programming-languages/abap/glossary.adoc#cds-entity[CDS entity]: a data model object defined in ABAP CDS, the data definition language of ABAP.
* xref:programming-languages/abap/glossary.adoc#constructor-expression[Constructor expression]: an expression such as `VALUE`, `CONV` or `NEW` that builds a value at the place where it is needed.

== Two language versions, two numbering schemes

Before looking at features, you need to know that SAP delivers ABAP in two flavours, and that each has its own release
list.

* Standard ABAP is the complete language. Its releases are numbered like 7.58 or 8.16 and ship with SAP S/4HANA and
  SAP S/4HANA Cloud Private Edition. Release 8.16 uses kernel release 9.16.
* ABAP for Cloud Development is the restricted language version behind ABAP Cloud. Its releases are numbered like 9.19
  or 9.20, and each also has a date-style name made of year and month: 9.20 is 2608. It is
  delivered with SAP S/4HANA Cloud Public Edition and with the SAP BTP ABAP environment. SAP now presents the BTP
  capabilities as part of SAP Business AI Platform, while the help portal still uses the name SAP BTP.

The release number is the technical release of the underlying software component, so ABAP is not released on its own: you
get a new ABAP release when the product that contains it is upgraded. In the BTP ABAP environment and in S/4HANA Cloud
Public Edition this happens on a fixed schedule; on premise, the date is chosen by the customer's own upgrade project.

== How a feature travels

A language feature is usually described in the release news of the release that introduced it. For classic Standard
ABAP, the news pages list the changes of each release in turn. For ABAP Cloud, the news pages follow the quarterly
cadence. Many features are available in both versions, but some are only in one. Some statements and objects are
part of Standard ABAP only; the keyword documentation marks which ones.

[mermaid]
----

== The 7.40 turning point: expressions and inline declarations

One of the biggest changes for readers of ABAP source code was the expression syntax that arrived from around release 7.40 on.
Before, every variable had to be declared at the top of a method, and a value had to be built with a series of
statements. Since then, ABAP offers inline declarations, which declare a variable at the place of its first use, table
expressions and constructor expressions, and current code also uses string templates. If you see code that does not
use any of them, it was probably written for an older system. The sections below show the same task in both styles. The two samples are
equivalent; the second is what current code looks like.

The first sample is in the older style. It runs in the local playground; the report writes one line, which is
`Second entry: 20`.

[source,abap]
----
DATA lt_numbers TYPE STANDARD TABLE OF i WITH EMPTY KEY.
DATA lv_number  TYPE i.
DATA lv_text    TYPE string.

APPEND 10 TO lt_numbers.
APPEND 20 TO lt_numbers.
READ TABLE lt_numbers INDEX 2 INTO lv_number.
lv_text = lv_number.
CONCATENATE 'Second entry:' lv_text INTO lv_text SEPARATED BY space.
WRITE / lv_text.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap[ABAP Keyword Documentation for Standard ABAP]

The same task in current style, requiring an SAP system and not run here, builds the table with `VALUE`, reads the
second line with a table expression and writes the text with a string template.

[source,abap]
----
DATA(lt_numbers) = VALUE int4_table( ( 10 ) ( 20 ) ).
DATA(lv_text) = |Second entry: { lt_numbers[ 2 ] }|.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap[ABAP Keyword Documentation for Standard ABAP]

Later releases extended the language in many small steps. One example from the official news: SQL expressions in the
`ORDER BY` clause were introduced with release 7.57.

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap/abap-sql-in-abap-release-8-16[ABAP SQL in ABAP Release 8.16]

== Standard ABAP 8.16

The release news for 8.16 is long and mostly about data modelling and ABAP SQL. The items below are a sample taken
from the official list, sorted by theme.

* *CDS aspects*: reusable elements of CDS entities are defined once with `DEFINE ASPECT`, attached to a CDS view
  entity with `BIND ASPECT` and pulled into an entity with `INCLUDE`.
* *CDS external entities*: a new kind of CDS entity that gives access to data in external database systems, declared
  with `DEFINE EXTERNAL ENTITY`. The news also lists writable external entities, declared with `WRITABLE`, and the ABAP
  SQL addition `PROVIDED BY`, which names the logical external schema that maps an external entity to an external system.
* *CDS table entities*: a CDS table entity defines a database table in ABAP CDS and is described as the ABAP Cloud
  successor of DDIC database tables, which are the classic dictionary tables defined in transaction SE11.
* *Writable CDS view entities* and *CDS delegated buffers*.
* *ABAP SQL*: fully dynamic `SELECT` through new dynamic forms of `WITH` and `OPEN CURSOR`, connection objects,
  level-based hierarchies, the addition `OPTIONS` and the addition `DECLARE CLIENT`.
* *ABAP Objects*: a global class that can be part of an inheritance tree must contain a `PROTECTED SECTION` and a
  `PRIVATE SECTION`, even when they are empty; before 8.16 the syntax warning for missing sections appeared only for
  non-final classes, and now it also appears for final subclasses.
* *Documentation*: from release 8.16 the ABAP Keyword Documentation is delivered and supported in English only.

If your system is older than 8.16, none of these items are available. The sample is not a complete list; the official
news page is the reference.

=== Removing duplicates without sorting

Before 9.19, the usual way to remove duplicate lines from an internal table was to sort it first and then use `DELETE
ADJACENT DUPLICATES`. The `DELETE DUPLICATES` statement, new in 9.19, does not require the sort. The example uses claim numbers
from the Expense claims running example. It requires an SAP system; not run here.

[source,abap]
----
DATA claim_numbers TYPE STANDARD TABLE OF zexp_claim-claim_id WITH EMPTY KEY.

claim_numbers = VALUE #( ( 'C-001' ) ( 'C-002' ) ( 'C-001' ) ).

DELETE DUPLICATES FROM claim_numbers.
" claim_numbers now holds C-001 and C-002
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords/news-for-abap-release-9-19[News for ABAP Release 9.19]

=== Generic structures in method parameters

Release 9.20 added `TYPE ANY STRUCTURE`, which creates fully generic structured types, and `TYPE ANY STRUCTURE
CONTAINING`, which creates partially generic ones. The sample is an interface that offers a method for logging one
structure of any type. It requires an SAP system; not run here.

[source,abap]
----
INTERFACE zif_exp_logger.
  METHODS log_structure
    IMPORTING is_data TYPE ANY STRUCTURE.
ENDINTERFACE.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords/news-for-abap-release-9-20[News for ABAP Release 9.20]

== Older material you may meet

Books, blog posts and old programs usually reflect the language as it was when they were written. The most frequent
differences are these.

* Declarations at the top. Older code declares every variable before the first statement. Current code declares most
  variables inline with `+DATA( )+` or `+FINAL( )+` at first use, and ABAP Doc comments can now be attached to those
  declarations too.
* Statements instead of expressions. Older code builds tables with a series of `APPEND` statements and reads lines with
  `READ TABLE`. Current code uses `VALUE`, `CONV`, `CORRESPONDING` and table expressions such as `+itab[ 1 ]+`.
* Concatenation. Older code uses `CONCATENATE` and `+WRITE ... TO+`. Current code uses string templates.
* Sorting before removing duplicates. This was the only choice before `DELETE DUPLICATES` was introduced.
* Classic-only statements and dictionary objects. Much older code uses statements, function modules and DDIC objects that
  are not allowed in ABAP Cloud. The page on xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs] in this section explains which is which.

Old code is not wrong and keeps running on newer releases. When you maintain it, learn to read both styles, and use the
current style for new code unless a rule of the system forbids it.

== How to read the official release news

The ABAP Keyword Documentation contains a release news section for each language version. For Standard ABAP, it lists
each release with its topics. For ABAP Cloud, it lists the releases of ABAP for Cloud Development. When you need to know
whether a feature is available on your system:

. Find the release of your system, for example by asking your system administrator or by looking at the system status.
. Decide which version of the language you are programming in: Standard ABAP or ABAP for Cloud Development.
. Open the release news of that version and search for the keyword.
. Compare the release listed in the news with the release of your system.

The SAP sample repository `abap-cheat-sheets` also collects a plain-text summary of the news from both documentation
versions, which is easier to search than the portal. It is a community-style sample from SAP, not part of the official
documentation, and it says itself that it may not reflect all releases.

Source: https://github.com/SAP-samples/abap-cheat-sheets/blob/main/33_ABAP_Release_News.md[ABAP Release News cheat sheet]

== Summary

* ABAP has two language versions with separate release lists: Standard ABAP (release 8.16 on this site) and ABAP for
  Cloud Development (release 9.20, delivered as 2608).
* The expression syntax of release 7.40 changed how ABAP code reads; older code uses declarations at the top and
  statement sequences instead.
* Release 8.16 brought CDS aspects, CDS external entities and many ABAP SQL additions to Standard ABAP.
* ABAP Cloud from 2602 to 2608 added `MERGE`, `DELETE DUPLICATES`, recursive structure references and `TYPE ANY STRUCTURE`,
  among other items.
* Before using a feature, check the release news and the release of your system; 9.21 is planned for 2611 and is not
  described here.
