= ABAP Glossary
:description: Alphabetical glossary of the ABAP and AS ABAP terms used in the ABAP section, from ABAP Cloud and ABAP SQL to RAP and transport request, each in plain words with a link to the page that explains it, for ABAP Cloud and classic ABAP on SAP S/4HANA 2025.
:keywords: ABAP glossary, ABAP terms, ABAP Cloud, AS ABAP, RAP, CDS, ABAP SQL, ABAP Unit, transport request, internal table, definitions

include::partial$ai-disclaimer.adoc[]

This glossary explains, in plain words, the ABAP and AS ABAP terms used across the ABAP section of this documentation, and links each one to the page that teaches it. ABAP is the programming language of SAP systems, and AS ABAP is the application server that runs it. Use the glossary when a page uses a word you have not met; every entry ends with the page where the idea is explained in full. Terms are listed alphabetically, and a term the pages write in several ways shows each spelling.

== A

[[abap-annotation]]ABAP annotation::
An annotation, a piece of metadata attached to a CDS entity, that the ABAP runtime itself reads, for example when the entity is activated. Other annotations are only read by tools such as UI frameworks. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[abap-channels]]ABAP Channels::
The common name of AMC and APC. They let programs communicate through messages, between application server instances and with the Internet, instead of polling for changes. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[abap-cloud]]ABAP Cloud::
The cloud-ready way of writing ABAP: you use the restricted language version for cloud development and call only released APIs, so that your code survives upgrades of the SAP system. Obsolete statements are mostly forbidden in it. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[abap-debugger]]ABAP Debugger::
The tool that stops a running program at a point you choose and lets you look at its variables and at the chain of calls that led there. See xref:programming-languages/abap/debugging.adoc[Debugging].

[[abap-development-tools]]ABAP Development Tools::
ABAP Development Tools (ADT)::
The plug-ins from SAP for the Eclipse programming environment, with which you create and change ABAP objects on an SAP system. It is the environment in which modern ABAP is written. See xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

[[abap-dictionary]]ABAP Dictionary::
The central, transportable store of type definitions: tables, data elements, domains, structures, views and similar objects. Programs and databases both use these definitions, so a type is described once and reused. Classic systems maintain it with transaction SE11. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[abap-for-cloud-development]]ABAP for Cloud Development::
A restricted ABAP language version. It allows only a subset of statements that suits cloud systems, and it lets code call released objects only. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[abap-for-key-users]]ABAP for Key Users::
The smallest ABAP language version, meant for small extensions that business users (key users) make in dedicated tools instead of in a full development environment. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[abap-formatter]]ABAP Formatter::
The editor function that re-indents code and changes the case of keywords according to the team's settings, so that all code looks alike. In SAP GUI the same function is called Pretty Printer. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

[[abap-language-version]]ABAP language version::
A setting on a development object that fixes which statements the object may use and which other objects it may call. It is how the same system can hold both classic and cloud-ready code. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[abap-memory]]ABAP memory::
A memory area that all programs of one call chain in one main session can read and write, and that nobody else can reach. Programs use it to pass data to the programs they call. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[abap-profiler]]ABAP Profiler::
The ADT tool that records how long each part of a running ABAP program takes, so that you can see where the run time goes before you try to speed it up. It succeeds the classic transaction SAT. See xref:programming-languages/abap/performance-and-sql-trace.adoc[Performance, SQL Trace and Profiling].

[[abap-programming-model-for-sap-fiori]]ABAP Programming Model for SAP Fiori::
The programming model of the 7.5x era for building transactional Fiori apps, which combined CDS views, BOPF and SAP Gateway. RAP is its successor. See xref:programming-languages/abap/bopf-and-the-fiori-programming-model.adoc[BOPF and the ABAP Programming Model for SAP Fiori].

[[abap-project]]ABAP project::
An Eclipse project in ADT that manages the connection to one ABAP back-end system. You open and edit that system's objects through it. See xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

[[abap-release]]ABAP release::
The number, such as 8.16 or 9.20, that names the version of the ABAP language and runtime delivered with a SAP product. It tells you which statements and features you can use. See xref:programming-languages/abap/whats-new-in-abap.adoc[What's New in ABAP].

[[abap-sql]]ABAP SQL::
The SQL of the ABAP language: the statements, written inside ABAP programs and checked by the ABAP compiler, that read and change database tables. The runtime passes them on to the database. See xref:programming-languages/abap/abap-sql-basics.adoc[ABAP SQL: Reading Data].

[[abap-test-cockpit]]ABAP Test Cockpit::
ABAP Test Cockpit (ATC)::
The SAP tool that runs groups of quality and compatibility checks over development objects and lists the findings with a priority. See xref:programming-languages/abap/clean-core-and-cloud-readiness.adoc[Clean Core and Cloud Readiness].

[[atc]]ABAP Test Cockpit (ATC)::
SAP's tool for static analysis of ABAP code: it examines development objects without running them and reports findings. It can also run ABAP Unit tests. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[abap-unit]]ABAP Unit::
The built-in ABAP framework that finds, runs and evaluates the automatic tests you write as test classes. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[abap-workbench]]ABAP Workbench::
The set of classic SAP GUI tools for creating and changing ABAP development objects, such as SE80, SE38 and SE11. See xref:programming-languages/abap/classic-tools-se80-and-se11.adoc[Classic Tools: SE80, SE38, SE11, SE37 and SE16].

[[abapgit]]abapGit::
A Git client written in ABAP that exports development objects as plain text files and imports them again, with one file per object. It lets ABAP sources live in an ordinary Git repository. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[abaplint]]abaplint::
A free checker for ABAP source code that reports style and correctness findings, each named by a rule. See xref:programming-languages/abap/hands-on-lab.adoc[Hands-on Lab].

[[abstract-class]]Abstract class::
A class that cannot be instantiated itself and may leave methods without an implementation, which its subclasses must supply. It serves as a common base for related classes. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[access-rule]]Access rule::
One statement inside a CDS role that names a CDS entity and says which rows a user may read, either by an access condition or by full access. See xref:programming-languages/abap/cds-access-control.adoc[CDS Access Control (DCL)].

[[rap-action]]Action::
A named operation on a business object that is more than create, update or delete, such as submitting a claim. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[activation]]Activation::
The step that turns a saved but inactive version of an object into the version that the system actually runs. See xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

[[adbc]]ADBC (ABAP Database Connectivity)::
The ABAP Objects classes and interfaces with which a program sends Native SQL, that is database-specific SQL, to the database and reads the result. See xref:programming-languages/abap/native-sql-adbc-and-amdp.adoc[Native SQL, ADBC and AMDP].

[[additional-save]]Additional save::
Extra code of your own that runs in the saver class of a managed business object while the framework still does the normal saving. A typical use is writing change documents. See xref:programming-languages/abap/rap-managed-and-unmanaged.adoc[Managed, Unmanaged and Unmanaged Save].

[[adobe-forms]]Adobe forms::
The third generation of SAP form tools. The layout is designed in Adobe LiveCycle Designer, and Adobe Document Services renders the finished form as PDF. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[aggregate-expression]]Aggregate expression::
A function such as SUM or COUNT that turns many rows into a single value. Using it in the query lets the database do the adding up. See xref:programming-languages/abap/abap-for-sap-hana-and-code-pushdown.adoc[ABAP for SAP HANA and Code Pushdown].

[[alias]]Alias::
A short second name for a component of an interface that a class implements, so that you can use the component without the long interface prefix. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[alv]]ALV::
The SAP List Viewer, a standard tool that shows an internal table as an interactive table with sorting, filtering, totals and export. See xref:programming-languages/abap/alv.adoc[ALV (SAP List Viewer)].

[[alv-object-model]]ALV object model::
The set of SALV classes, with CL_SALV_TABLE and its sub-objects, that SAP recommends for new ALV output. See xref:programming-languages/abap/alv.adoc[ALV (SAP List Viewer)].

[[amc]]AMC (ABAP Messaging Channel)::
A named channel, stored as a repository object, through which ABAP programs send and receive messages. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[amdp]]AMDP::
AMDP (ABAP Managed Database Procedures)::
Database code written in SQLScript but kept as a method of an ABAP class, so that ABAP manages its creation and transport. The method runs inside the database. See xref:programming-languages/abap/native-sql-adbc-and-amdp.adoc[Native SQL, ADBC and AMDP].

[[analytical-query]]Analytical query::
A CDS-based query with measures (numbers to add up) and dimensions (ways to group them) that Fiori reports read through an OData service. See xref:programming-languages/abap/sap-query-and-quickviewer.adoc[SAP Query and QuickViewer].

[[annotation-layer]]Annotation layer::
The level of a metadata extension (core, localization, industry, partner or customer) that decides which extension wins when several set the same annotation. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[anonymous-data-object]]Anonymous data object::
A data object created while the program runs that has no name, only a reference that points to it. You create one with CREATE DATA or NEW. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[apc]]APC (ABAP Push Channel)::
A repository object that lets an ABAP system act as a WebSocket or TCP socket server or client, so that it can push messages to a connected partner. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[apc-handler-class]]APC handler class::
The class that the system creates to react to the events of one push channel connection, such as an incoming message. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[append-structure]]Append structure::
An extra set of fields that adds to an existing table or structure without changing the original object. A customer can thus extend an SAP table without modifying it. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[application-destination]]Application destination::
The destination that the system creates from a communication target when a communication arrangement is saved. Outbound calls use it to find the remote system. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[application-event]]Application event::
A control event whose handler is called later, when the program calls the dispatch method of the Control Framework in a PAI module, instead of immediately. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

[[afl]]Application function library (AFL)::
The mechanism through which SAP HANA offers compiled functions, such as PAL, to SQLScript. See xref:programming-languages/abap/hana-search-and-predictive-functions.adoc[SAP HANA Search and Predictive Functions from ABAP].

[[application-job]]Application job::
The ABAP Cloud form of a scheduled job, created from a job template in the Application Jobs app or through an API. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[ale]]Application Link Enabling (ALE)::
The technology that distributes business data between loosely linked systems, mostly by sending IDocs. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[application-log]]Application log::
A stored list of messages that a program writes and that can be read later, for example after a background job has finished. See xref:programming-languages/abap/messages.adoc[Messages].

[[application-server]]Application server::
The computer that runs your ABAP program. It sits between the user's screen and the database, which runs on a separate computer, and talks to both. See xref:programming-languages/abap/getting-started.adoc[Getting Started].

[[asjson]]asJSON::
The fixed JSON layout that the identity transformation produces and expects when ABAP data is converted to JSON and back. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[assertion]]Assertion::
A check inside a test, written as a call of the class CL_ABAP_UNIT_ASSERT, that makes the test fail when the result is not the expected one. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[arfc]]Asynchronous RFC (aRFC)::
A remote function call in which the caller continues at once without waiting and collects the result later in a callback routine. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[atc-exemption]]ATC exemption::
An approved request that hides one ATC finding which cannot be fixed now, so that it no longer blocks the check. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[attribute]]Attribute::
A variable, constant or type that belongs to a class or to its objects. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[authorization]]Authorization::
An entry in a user's permissions that gives complete or generic values for the fields of one authorization object. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[authorization-check]]Authorization check::
The comparison of the values a program needs with the values in the user's authorizations. It is either explicit, with the statement AUTHORITY-CHECK, or implicit. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[authorization-field]]Authorization field::
The smallest unit of an authorization object. It stands either for data, such as a key field of a table, or for an activity such as display or change. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[authorization-object]]Authorization object::
A named set of up to ten authorization fields that the system compares with the values assigned to a user before it allows an action. Checks and permissions always refer to one such object. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[automation-queue]]Automation queue::
The buffer in which the Control Framework collects method calls for GUI controls and sends them to the user's PC in one go. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

== B

[[background-job]]Background job::
A unit of work, made of one or more job steps, that the system runs without a user dialog. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[background-processing-framework]]Background processing framework::
The ABAP Cloud framework that runs methods of your classes asynchronously and reliably. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[bgrfc]]Background RFC (bgRFC)::
A remote call that is stored and sent after COMMIT WORK. It is the modern successor of tRFC and qRFC. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[background-work-process]]Background work process::
A work process reserved for background jobs. Unlike a dialog work process it is not subject to the dialog time limit (the profile parameter `rdisp/max_wprun_time`). See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[badi]]BAdI::
Business Add-In: an object-oriented enhancement option made of an interface, filters and settings. The standard code calls it, and your own ABAP class plugs in to add behavior. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[bapi]]BAPI::
A standardized, remote-enabled function module that is a method of a business object, so that other systems can call it in a defined way. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[basic-list]]Basic list::
The first list of a program, with list level 0. It is what the report writes before the user does anything. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[batch-input]]Batch input::
A technique that feeds data automatically into the screens of transactions, controlled by batch input sessions or batch input tables. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[batch-input-session]]Batch input session::
A stored series of transaction calls with their input data, managed in transaction SM35. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[batch-input-table]]Batch input table::
An internal table whose line type is BDCDATA and that holds the screens and field values for one transaction. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[bdcdata]]BDCDATA::
The dictionary structure of one line of a batch input table, with the components PROGRAM, DYNPRO, DYNBEGIN, FNAM and FVAL. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[behavior-definition]]Behavior definition::
A repository object, written in the RAP Behavior Definition Language, that describes the operations and characteristics of a business object. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[behavior-pool]]Behavior pool::
The global ABAP class named in the behavior definition. Its local classes hold the handler and saver code of the business object. See xref:programming-languages/abap/rap-managed-and-unmanaged.adoc[Managed, Unmanaged and Unmanaged Save].

[[bopf]]BOPF::
The Business Object Processing Framework: a runtime that holds a business object as a tree of nodes together with its business logic. See xref:programming-languages/abap/bopf-and-the-fiori-programming-model.adoc[BOPF and the ABAP Programming Model for SAP Fiori].

[[bopf-based-rap-business-object]]BOPF-based RAP business object::
The result of SAP's migration tool: a RAP business object whose runtime is still provided by BOPF. See xref:programming-languages/abap/bopf-and-the-fiori-programming-model.adoc[BOPF and the ABAP Programming Model for SAP Fiori].

[[branch]]Branch::
One of several alternative blocks of statements of which only one runs, chosen by a condition. See xref:programming-languages/abap/control-flow.adoc[Control Flow].

[[breakpoint]]Breakpoint::
A marker that makes the debugger stop when execution reaches a given line, statement, message or exception. See xref:programming-languages/abap/debugging.adoc[Debugging].

[[built-in-function]]Built-in function::
A function that is part of the language itself and is called inside an expression, for example abs( x ) for the absolute value. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

[[bulk-access]]Bulk access::
One statement that handles many rows at once, for example from an internal table, instead of one statement per row. See xref:programming-languages/abap/abap-sql-writing-data.adoc[ABAP SQL: Writing Data].

[[bundling-technique]]Bundling technique::
A way to collect change requests in an SAP LUW and carry them out together later, instead of executing each one at once. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[business-key]]Business key::
The key attributes of a persistent class that come from the primary key of its table and are visible to the program. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[business-object-repository]]Business Object Repository (BOR)::
The catalog of SAP business object types and their methods, in which BAPIs are defined. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

== C

[[calculation-type]]Calculation type::
The data type in which ABAP carries out an arithmetic expression, chosen from the types of its operands. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[call-sequence]]Call sequence::
The chain of programs in which each one has called the next and is waiting for it, with the newest at the end. The programs of one call sequence share one ABAP memory. See xref:programming-languages/abap/calling-programs-and-memory.adoc[Calling Programs, Transactions and Memory].

[[association-cardinality]]Cardinality::
How many rows of the target can match one row of the source of an association, for example many to one. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

[[foreign-key-cardinality]]Cardinality::
How many rows on one side of a foreign key can belong to one row on the other side. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[catchable-exception]]Catchable exception::
An exception that a program can handle with TRY and CATCH. The opposite is an uncatchable one, which ends the program. See xref:programming-languages/abap/exceptions.adoc[Class-Based Exceptions].

[[cds-abstract-entity]]CDS abstract entity::
A CDS entity that only describes a structure and has neither data nor a database object. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-access-control]]CDS access control::
The rule that restricts which rows of a CDS entity a user gets when ABAP SQL reads it. It is written in CDS roles. See xref:programming-languages/abap/cds-access-control.adoc[CDS Access Control (DCL)].

[[cds-annotation]]CDS annotation::
A line that starts with the at sign and adds metadata to a CDS entity or to one of its elements. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[cds-aspect]]CDS aspect::
A named set of elements that several CDS view entities can reuse. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-association]]CDS association::
A named, reusable link from one CDS entity to another, declared once with a join condition. It is evaluated only when it is used. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

[[cds-composition]]CDS composition::
A pair of to-child and to-parent associations that makes a child entity depend on its parent for its existence. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

[[cds-custom-entity]]CDS custom entity::
A CDS entity that only describes a result. An ABAP class provides the rows when a framework asks for them. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-entity]]CDS entity::
The common name for an object defined in ABAP CDS, the data definition language of ABAP, such as a view entity, that you can read with ABAP SQL. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[cds-external-entity]]CDS external entity::
A CDS entity that reads data from a table in another database. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-hierarchy]]CDS hierarchy::
A CDS entity that turns rows with a parent column into a tree and adds columns such as the level of each node. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-role]]CDS role::
The object created with DEFINE ROLE. It holds one or more access rules and applies to every user. See xref:programming-languages/abap/cds-access-control.adoc[CDS Access Control (DCL)].

[[cds-table-function]]CDS table function::
A CDS entity whose rows are produced by a database function written in SQLScript inside an ABAP class (an AMDP method), so that ABAP SQL and other CDS views can read it like a view. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[cds-view-entity]]CDS view entity::
A view defined in ABAP CDS that selects data from one or more data sources and can be read like a table. It is the current kind of CDS view and replaces classic views and DDIC-based CDS views. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[cts]]Change and Transport System (CTS)::
All the tools of an ABAP system that manage development objects and transport them between systems. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[check-indicator]]Check indicator::
A setting that decides whether a check on an authorization object really takes place in the current context. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[check-table]]Check table::
The table that holds the allowed values of a foreign key, because its primary key is the foreign key. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[check-variant]]Check variant::
A named set of checks that an ATC run executes. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[class]]Class::
The blueprint that defines the attributes and methods of a kind of object. Objects are created from it and bundle data with the methods that work on it. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[class-agent]]Class agent::
The generated class, also called class actor, that creates, loads and deletes the objects of one persistent class. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[class-pool]]Class pool::
The program that the system generates for a global class. See xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure].

[[classic-api]]Classic API::
An older SAP object, such as a function module or a class of classic ABAP, that SAP has nominated as the next-best option where no released API exists. See xref:programming-languages/abap/clean-core-and-cloud-readiness.adoc[Clean Core and Cloud Readiness].

[[classic-exception]]Classic exception::
A name in the interface of a function module that the code raises with RAISE and that the caller tests through sy-subrc. It is the opposite of a class-based exception. See xref:programming-languages/abap/function-modules-and-function-groups.adoc[Function Modules and Function Groups].

[[classic-list]]Classic list::
The page-oriented text output that WRITE creates and that the user sees on a special list screen after the report has run. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[clean-abap]]Clean ABAP::
SAP's public style guide that applies the ideas of the book Clean Code to the ABAP language. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

[[clean-core]]Clean core::
Keeping the SAP standard free of changes and extending it only through released or officially classified interfaces, so that upgrades stay simple. See xref:programming-languages/abap/clean-core-and-cloud-readiness.adoc[Clean Core and Cloud Readiness].

[[clean-core-level]]Clean core level::
One of the four classes A, B, C and D that SAP uses to rate how upgrade-stable a custom object is. See xref:programming-languages/abap/clean-core-and-cloud-readiness.adoc[Clean Core and Cloud Readiness].

[[client]]Client::
A self-contained unit of business data inside one SAP system. ABAP SQL reads only the client you are logged on to. See xref:programming-languages/abap/abap-sql-basics.adoc[ABAP SQL: Reading Data].

[[client-field]]Client field::
The first key column of a client-dependent table, which separates the data of the different clients of one system. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[client-handling]]Client handling::
The automatic restriction of a client-dependent view to the rows of the client the program runs in. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[client-safety]]Client safety::
The guarantee that a statement or an AMDP method reads the data of the current client only. See xref:programming-languages/abap/native-sql-adbc-and-amdp.adoc[Native SQL, ADBC and AMDP].

[[cloudification-repository]]Cloudification Repository::
SAP's published list that says, for each SAP object, whether it is released, classic, deprecated or not recommended, and which object replaces it. See xref:programming-languages/abap/clean-core-and-cloud-readiness.adoc[Clean Core and Cloud Readiness].

[[code-inspector]]Code Inspector::
The older SAP check tool, started with transaction SCI, whose name still appears inside ATC settings. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[code-pushdown]]Code pushdown::
Moving a calculation from the ABAP program to the database, so that only the result travels back. It is also called code-to-data. See xref:programming-languages/abap/abap-for-sap-hana-and-code-pushdown.adoc[ABAP for SAP HANA and Code Pushdown].

[[collaborative-draft]]Collaborative draft::
A draft, in the RAP draft concept, that several invited users edit together instead of one person alone. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[commercial-rounding]]Commercial rounding::
The everyday way of rounding: when a value lies exactly halfway between two possible results, it goes to the one farther from zero, so 2.5 becomes 3 and -2.5 becomes -3. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[common-table-expression]]Common table expression::
A named intermediate result that you define at the start of an ABAP SQL statement with `WITH` and then read like a table. It exists only while that one statement runs. See xref:programming-languages/abap/abap-sql-joins-ctes-and-window-functions.adoc[ABAP SQL: Joins, CTEs, Window Functions and Path Expressions].

[[communication-arrangement]]Communication arrangement::
The runtime setup, made by an administrator, that ties a communication scenario to a particular communication system, including its address and the credentials to use. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[communication-scenario]]Communication scenario::
A development object that lists the outbound and inbound services a piece of integration uses, so that an administrator can later connect it to a real system. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[communication-target]]Communication target::
A development object that generates a class your code uses to get the right destination for an outbound call, so that no address is written in the program. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[constructor]]Constructor::
A special method that prepares an object, or the class itself, when it is created or first used. You use it to give the new object its starting values. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[constructor-expression]]Constructor expression::
An expression that starts with an operator such as `VALUE`, `COND` or `NEW`, ends with a closing parenthesis and builds a value at the place where it is needed. See xref:programming-languages/abap/constructor-expressions.adoc[Constructor Expressions].

[[consumer-proxy]]Consumer proxy::
A generated class that hides the SOAP message of a web service, so that calling the service looks like calling an ordinary method. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[container-control]]Container control::
A GUI control whose job is to hold other controls and give them an area on the screen, for example the custom container. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

[[content-id]]Content ID::
The temporary name `%cid` that you give a new instance inside one EML request, so that later lines of the same request can refer to it before it has a real key. See xref:programming-languages/abap/eml.adoc[Entity Manipulation Language (EML)].

[[control-framework]]Control Framework::
The set of ABAP classes and front-end services that create GUI controls on the user's PC, call their methods and pass their events back to your program. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

[[control-level]]Control level::
A point in a sorted loop over a table where the value of a leading column changes. The older statements `AT NEW` and `AT END OF` react to these points. See xref:programming-languages/abap/internal-tables-processing-and-grouping.adoc[Looping, Grouping and Control Levels].

[[controlled-sap-luw]]Controlled SAP LUW::
A checking mechanism that detects statements and calls that break the rules of the SAP LUW, for example a database change made outside the intended update step. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[conversion-exit]]Conversion exit::
A pair of routines attached to a data element or domain that translates a value between the form in which it is stored and the form in which it is shown, for example leading zeros that are hidden on screen. See xref:programming-languages/abap/ddic-domains-and-data-elements.adoc[Domains and Data Elements].

[[conversion-rule]]Conversion rule::
The rule that decides how a value of one data type is changed into another when it is assigned, for example text into a number. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[cds]]Core data services (CDS)::
The part of ABAP in which you describe data models, such as views, as text that the system turns into database objects. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[currency-conversion]]Currency conversion::
Turning an amount in one currency into another by using an exchange rate that is valid on a given date. See xref:programming-languages/abap/currencies-units-and-conversions.adoc[Currencies, Units and Conversion Exits].

[[currency-key]]Currency key::
A short code such as EUR or JPY, kept in a separate field next to an amount, that says which currency the amount is in. See xref:programming-languages/abap/currencies-units-and-conversions.adoc[Currencies, Units and Conversion Exits].

[[customer-exit]]Customer exit::
An older, now obsolete way for a customer to add logic to an SAP program, using function modules that are managed with the transactions SMOD and CMOD. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[customer-namespace]]Customer namespace::
The part of the name range that SAP leaves to customers: names that start with Y or Z, or that sit between the slashes of a namespace you have reserved. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

== D

[[data-cluster]]Data cluster::
A group of named data objects that `EXPORT` stores in a memory medium and that `IMPORT` reads back later. See xref:programming-languages/abap/calling-programs-and-memory.adoc[Calling Programs, Transactions and Memory].

[[data-element]]Data element::
A Dictionary object that gives a single value (or a reference) its type and its business meaning, including the field labels shown on screens. See xref:programming-languages/abap/ddic-domains-and-data-elements.adoc[Domains and Data Elements].

[[data-object]]Data object::
A named place in memory, such as a variable or a constant, that holds one value of a data type. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

[[data-reference]]Data reference::
A variable that holds the address of a data object instead of the value itself, so that a program can reach the object through it. You create one with `REF`. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[data-type]]Data type::
The description of a value's shape, such as text of ten characters or a number with two decimals. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

[[database-luw]]Database LUW::
A sequence of database changes that the database either completes in full at a commit or undoes in full at a rollback. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[dcl]]DCL (Data Control Language)::
The language in which access controls for CDS entities are written. Each CDS role has its own DCL source. See xref:programming-languages/abap/cds-access-control.adoc[CDS Access Control (DCL)].

[[ddic-database-table]]DDIC database table::
The Dictionary description of a table, from which the system creates the real table on the database. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[ddic-database-view]]DDIC database view::
A classic view that combines several tables with a join and is created as a view on the database. See xref:programming-languages/abap/ddic-views-and-search-helps.adoc[Dictionary Views and Search Helps].

[[ddic-structure]]DDIC structure::
A named group of fields that describes one row of data. A structure holds no data of its own. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[debuggee]]Debuggee::
The program that runs under the control of the debugger, which you can stop, step through and inspect. See xref:programming-languages/abap/debugging.adoc[Debugging].

[[delivery-class]]Delivery class::
The table setting that says what kind of data the table holds, such as customizing or application data, and how that data is transported and copied. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[depended-on-component]]Depended-on component::
Anything the code under test uses that is not part of the test itself, such as another class, a database table or an authority check. Test doubles stand in for it. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[dependency-injection]]Dependency injection::
Giving an object the other objects it needs from outside, usually through its constructor, instead of letting it create them itself. See xref:programming-languages/abap/design-patterns-in-abap.adoc[Design Patterns in ABAP].

[[derived-event]]Derived event::
An event defined on top of an existing event that has a different payload and needs no code of its own. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[design-pattern]]Design pattern::
A named, reusable arrangement of classes that solves a problem which comes up often in programs. See xref:programming-languages/abap/design-patterns-in-abap.adoc[Design Patterns in ABAP].

[[details-list]]Details list::
A list written in answer to a user action on a displayed list, for example a double-click on a line. It has a list level of 1 or more. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[determination]]Determination::
Logic that changes instances automatically when a trigger happens, such as a create or the change of a field, for example to calculate a total. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[dialog-module]]Dialog module::
A block of ABAP code between `MODULE` and `ENDMODULE` that the flow logic of a dynpro calls. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[dialog-transaction]]Dialog transaction::
A transaction code that starts a module pool with its first dynpro. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[direct-input]]Direct input::
A technique that checks data and writes it to the database through function modules, without processing any screen. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[directory-traversal]]Directory traversal::
An attack in which a manipulated file name makes a program reach files outside the directory it was meant to use. See xref:programming-languages/abap/files-and-frontend-services.adoc[Files: Application Server and Front End].

[[dispatcher]]Dispatcher::
The part of the application server that hands each incoming request to a free work process. See xref:programming-languages/abap/getting-started.adoc[Getting Started].

[[domain]]Domain::
A Dictionary object that describes the technical shape of a single value, such as its type and length, and optionally the values it may have. See xref:programming-languages/abap/ddic-domains-and-data-elements.adoc[Domains and Data Elements].

[[downcast]]Downcast::
Assigning a reference to a more specific type than the one it has now. It must be written explicitly and is checked when the program runs. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[draft-action]]Draft action::
An action that the framework provides for draft business objects, such as Edit, Activate, Discard, Resume and Prepare. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[draft-handling]]Draft handling::
The RAP concept that stores the content of the transactional buffer in draft tables, so that one transaction can span several ABAP sessions. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[draft-indicator]]Draft indicator::
The component `%is_draft` that tells a request whether it is meant for the draft or for the active instance. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[draft-table]]Draft table::
The database table that holds the draft instances of one entity. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[dynamic-programming]]Dynamic programming::
Writing programs that use names, types or whole statement parts that are only known while the program runs, instead of being fixed in the source text. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[dynamic-token]]Dynamic token::
A part of a statement that is given as the content of a variable in parentheses, such as the table name in `+SELECT * FROM (name)+`, so that it is decided at run time. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[dynpro]]Dynpro::
A classic screen, made of a screen layout and flow logic, that always belongs to one ABAP program. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

== E

[[edit-draft-instance]]Edit draft::
A draft that is a copy of an existing active instance, made so that the claim can be changed without touching the active data until the change is activated. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[elementary-type]]Elementary type::
A type that describes a single value, for example a number, a piece of text or a date. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

[[eml]]EML::
The ABAP statements `READ ENTITIES`, `MODIFY ENTITIES`, `COMMIT ENTITIES` and `ROLLBACK ENTITIES` that a program uses to work with the instances of a RAP business object. See xref:programming-languages/abap/eml.adoc[Entity Manipulation Language (EML)].

[[enhancement]]Enhancement::
An addition to a repository object that changes its behavior without modifying the original. An enhancement is a transport object of its own. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[enhancement-category]]Enhancement category::
The setting that says whether and how a structure or table may be extended with more fields. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[enhancement-framework]]Enhancement Framework::
The technology that adds code to SAP objects through enhancement options without changing the original object. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[enhancement-implementation]]Enhancement implementation::
The container for the enhancements that implement the options of one enhancement spot. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[enhancement-option]]Enhancement option::
A position in a repository object where an enhancement can be attached. It is explicit when a developer placed it and implicit when it is always there. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[enhancement-spot]]Enhancement spot::
The container in which explicit enhancement options, including BAdIs, are defined and made known to other developers. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[enqueue-server]]Enqueue server::
The part of the system that holds the lock table and decides whether a new lock request collides with an existing lock. See xref:programming-languages/abap/locks-and-enqueue.adoc[Lock Objects and the SAP Lock Concept].

[[etag]]ETag::
A field whose value changes whenever an instance changes, so that a client that works from old data can be recognized and cannot silently overwrite a newer change. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[event]]Event::
A signal declared in a class that the class can send, so that other objects react to it through handler methods. You send it with `RAISE EVENT`. See xref:programming-languages/abap/events.adoc[Events].

[[event-binding]]Event binding::
The development object that maps an event of a business object to a namespace, a business object name and an operation, so that systems outside can subscribe to it. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[event-block]]Event block::
A block of statements that the runtime runs when one particular event occurs. It is introduced by an event keyword and ends where the next block starts. See xref:programming-languages/abap/classic-reports-and-events.adoc[Classic Reports and Event Blocks].

[[event-handler]]Event handler::
A method that is registered for an event and runs when the event is raised. See xref:programming-languages/abap/events.adoc[Events].

[[event-handler-class]]Event handler class::
The class that consumes events of a business object in the same system. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[event-payload]]Event payload::
The information that travels with an event: always the key of the instance and, if the event has a parameter, more fields. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[exception]]Exception::
An event during the run of a program that interrupts the normal flow because the program cannot continue in a meaningful way. The program can catch it and react instead of stopping. See xref:programming-languages/abap/exceptions.adoc[Class-Based Exceptions].

[[exception-category]]Exception category::
One of three groups, static check, dynamic check and no check, that decides whether the caller must declare or handle an exception. See xref:programming-languages/abap/exceptions.adoc[Class-Based Exceptions].

[[exception-class]]Exception class::
A class whose objects describe an exception. Its name starts with `CX_` for SAP classes and `ZCX_` for your own. See xref:programming-languages/abap/exceptions.adoc[Class-Based Exceptions].

[[exclusive-draft]]Exclusive draft::
A draft that only the user who created it may change, activate or discard. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[executable-program]]Executable program::
A program that a user or a background job can start directly, usually to read data and show a list. See xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure].

[[exposure]]Exposure::
Listing an association in the select list of a CDS entity so that other entities and ABAP SQL can use it. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

== F

[[factory-method]]Factory method::
A static method whose job is to create and return an object, so that the caller does not need to know which class is actually built. See xref:programming-languages/abap/design-patterns-in-abap.adoc[Design Patterns in ABAP].

[[fallback-class]]Fallback class::
The class that a single-use BAdI uses when no implementation matches. See xref:programming-languages/abap/enhancements-and-badis.adoc[Enhancements and BAdIs].

[[feature-table]]Feature table::
The page of the Keyword Documentation that lists every CDS language element together with the release in which it appeared. See xref:programming-languages/abap/cds-table-functions-and-advanced-features.adoc[Table Functions, Hierarchies, Custom Entities and Aspects].

[[feed-reader]]Feed Reader::
A view in ADT that shows feeds from the system, for example runtime errors or check results. See xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

[[field-catalog]]Field catalog::
The description of the columns of a list (name, heading, type, width) that the older ALV tools needed from the programmer. The object model builds it for you. See xref:programming-languages/abap/alv.adoc[ALV (SAP List Viewer)].

[[field-label]]Field label::
The short, medium, long and heading texts of a data element that screens use as a caption or column title. See xref:programming-languages/abap/ddic-domains-and-data-elements.adoc[Domains and Data Elements].

[[field-symbol]]Field symbol::
A name that points straight at a row in a table, so that a change made through it changes the table itself. It is written in angle brackets. See xref:programming-languages/abap/internal-tables-processing-and-grouping.adoc[Looping, Grouping and Control Levels].

[[file-interface]]File interface::
The ABAP statements for files on the application server: `OPEN DATASET`, `READ DATASET`, `TRANSFER`, `CLOSE DATASET` and `DELETE DATASET`. See xref:programming-languages/abap/files-and-frontend-services.adoc[Files: Application Server and Front End].

[[fixed-values]]Fixed values::
The list of single values or intervals that a domain names as the allowed ones, each with a short text. See xref:programming-languages/abap/ddic-domains-and-data-elements.adoc[Domains and Data Elements].

[[fixture]]Fixture::
The starting situation of a test, prepared by the special methods `setup` and `class_setup` and cleaned up by `teardown` and `class_teardown`. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[flow-logic]]Flow logic::
The script of a dynpro that calls dialog modules at the events PBO and PAI. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[foreign-key]]Foreign key::
One or more fields of a table whose values must match the primary key of another table. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[foreign-key-table]]Foreign key table::
The table that contains the foreign key fields and points at the check table. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[form]]Form::
A template for a printed or PDF document that mixes fixed text with fields filled in at run time. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[framework-specific-annotation]]Framework-specific annotation::
An annotation that another SAP component reads, such as the OData service or the SAP Fiori user interface, instead of the core CDS language itself. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[friend]]Friend::
A class that the owner of another class has allowed to see its private components and to create objects of it. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[function-code]]Function code::
The short name, up to 20 characters, that a menu entry, button or function key sends to the program, available afterwards in `sy-ucomm`. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[function-group]]Function group::
The container program, also called function pool, that holds function modules and the data they share. See xref:programming-languages/abap/function-modules-and-function-groups.adoc[Function Modules and Function Groups].

[[function-module]]Function module::
A procedure stored in a function group that any program can call with `CALL FUNCTION`. See xref:programming-languages/abap/function-modules-and-function-groups.adoc[Function Modules and Function Groups].

[[functional-method-call]]Functional method call::
A call of a method that returns one value, written at a place where a value is expected, such as `+cl_abap_context_info=>get_system_date( )+`. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

[[fuzzy-score]]Fuzzy score::
A number from 0 to 1 that says how similar a found value is to the search term. A score of 1 means identical. See xref:programming-languages/abap/hana-search-and-predictive-functions.adoc[SAP HANA Search and Predictive Functions from ABAP].

[[fuzzy-search]]Fuzzy search::
A search that also returns rows whose text is close to the search term, for example because of a typing error. See xref:programming-languages/abap/hana-search-and-predictive-functions.adoc[SAP HANA Search and Predictive Functions from ABAP].

== G

[[gcts]]gCTS::
The Git-enabled Change and Transport System, which keeps transported objects as files in a Git repository. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[global-authorization]]Global authorization::
A check that depends only on the user and the operation, not on a particular claim. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[group-key]]Group key::
The value, or the set of values, that makes rows belong to the same group. See xref:programming-languages/abap/internal-tables-processing-and-grouping.adoc[Looping, Grouping and Control Levels].

[[gui-control]]GUI control::
A user interface element that runs in SAP GUI on the user's PC and is managed by the Control Framework, for example the ALV grid. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

[[gui-status]]GUI status::
The menu bar, toolbars and function keys of a screen or list, which decide which function codes the user can trigger. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

== H

[[handler-class]]Handler class::
A local class that inherits from `+CL_ABAP_BEHAVIOR_HANDLER+` and implements operations, determinations, validations and checks during the interaction phase and the save sequence. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[hashed-table]]Hashed table::
A table kind whose rows are found through a calculated address, so a lookup by its unique key takes about the same time however many rows there are. See xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Secondary Keys].

[[header-line]]Header line::
A work area with the same name as an internal table, created implicitly in old programs. Modern code does not allow it. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[help-view]]Help view::
A classic view that is used as the data source of a search help. See xref:programming-languages/abap/ddic-views-and-search-helps.adoc[Dictionary Views and Search Helps].

[[hide-area]]Hide area::
The part of a list level in which `HIDE` stores values together with the number of the current line. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[hierarchy]]Hierarchy::
Data in which each row can have one parent row, such as a tree of cost centers. See xref:programming-languages/abap/abap-sql-joins-ctes-and-window-functions.adoc[ABAP SQL: Joins, CTEs, Window Functions and Path Expressions].

[[host-variable]]Host variable::
An ABAP variable used inside an ABAP SQL statement, always written with a leading `@`. See xref:programming-languages/abap/abap-sql-basics.adoc[ABAP SQL: Reading Data].

[[hot-spot]]Hot spot::
A statement or call that uses a large share of the total run time. See xref:programming-languages/abap/performance-and-sql-trace.adoc[Performance, SQL Trace and Profiling].

[[http-client]]HTTP client::
The object that sends an HTTP request to another system and returns its response. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[hungarian-notation]]Hungarian notation::
A habit of putting the kind of a variable into its name, such as `lv_` for a local variable or `it_` for an importing table. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

== I

[[identity-transformation]]Identity transformation::
The predefined transformation `ID` that converts ABAP data to XML or JSON and back without any rules written by you. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[idoc]]IDoc::
An intermediate document, the common exchange format between systems, made of a control record, data records and status records. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[include-program]]Include program::
A piece of source text that cannot run alone and is pasted into other programs. See xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure].

[[infoset]]InfoSet::
A view of one or more data sources, prepared by an administrator, from which queries take their fields. See xref:programming-languages/abap/sap-query-and-quickviewer.adoc[SAP Query and QuickViewer].

[[inheritance]]Inheritance::
Deriving a subclass from a superclass so that the subclass has all the visible components of the superclass and can add or redefine its own. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[initial-value]]Initial value::
The value a variable holds before your program puts anything into it. For a number it is zero, for text it is blanks, and every data type has its own initial value. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[injection]]Injection::
Handing the code you want to test a stand-in object instead of the real component it normally uses. With the stand-in in place, the test does not touch a database or another system. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[inline-declaration]]Inline declaration::
Creating a variable at the exact spot where it first receives a value, instead of in a separate declaration earlier. ABAP works out the type from the value, so you do not write it yourself. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

[[input-parameter]]Input parameter::
A value that the reader of a CDS view entity hands in when it reads the view, for example a status to filter by. It lets one view serve different callers without being copied. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[instance-authorization]]Instance authorization::
An authorization check that looks at the data of one particular record, not only at who the user is. For example, a user may be allowed to change a claim only while it still has a certain status. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[instance-guid]]Instance GUID::
A technical identifier that the persistence service of Object Services uses to tell apart the objects of a persistent class. It is of the type OS_GUID. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[ida]]Integrated Data Access (IDA)::
A way to show a database table in an ALV list without first reading all rows into an internal table. Sorting, filtering and paging then happen in the database, so large tables stay fast. See xref:programming-languages/abap/alv.adoc[ALV (SAP List Viewer)].

[[interaction-phase]]Interaction phase::
The first part of a RAP transaction, in which requests change data in the transactional buffer in memory. Nothing is written to the database yet; that happens later in the save phase. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[interface]]Interface::
A named list of components, mostly methods, that a class can promise to provide. Callers rely on the list and not on one particular class, and an interface has no instances of its own. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[interface-reference]]Interface reference::
A variable typed as a reference to an interface, written with TYPE REF TO. It can point to an object of any class that implements that interface, and through it you reach only the interface components. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[internal-session]]Internal session::
The memory area created for one program call inside a window of a user session. It holds the data of the programs loaded into it and disappears when the call ends. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[internal-table]]Internal table::
A list of rows of the same shape that lives only in the memory of the running program, while it runs. It can hold any number of rows and is the everyday way to work with sets of data in ABAP. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[iteration-expression]]Iteration expression::
The FOR part of a constructor expression, which repeats once for each row of a table or each value of a counter. It builds a new table or value from the repeated results. See xref:programming-languages/abap/constructor-expressions.adoc[Constructor Expressions].

== J

[[job-step]]Job step::
One unit of work inside a background job: a program, usually with a variant, or an external command. A job runs its steps one after the other. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[join]]Join::
A query that combines the rows of two data sources into one result by matching columns, for example claims with their employees. Only the rows that satisfy the matching condition appear in an inner join. See xref:programming-languages/abap/abap-sql-joins-ctes-and-window-functions.adoc[ABAP SQL: Joins, CTEs, Window Functions and Path Expressions].

[[json]]JSON::
A plain-text format for exchanging data, built from objects in curly brackets, arrays in square brackets, strings, numbers and true or false values. Web services commonly use it, and ABAP can convert it to and from structures and tables. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

== L

[[lsmw]]Legacy System Migration Workbench (LSMW)::
A guided SAP tool, started with transaction LSMW, that reads data from a legacy system, converts it and loads it with techniques such as batch input, direct input, BAPIs or IDocs. It is an older tool for migrating data. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[list-buffer]]List buffer::
The memory area in which a program keeps the lists it has written, one after another. It is what lets the user move back from a detail list to the list before it. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[list-cursor]]List cursor::
The position in a list at which the next output will appear. The system fields sy-linno and sy-colno hold its line and column. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[list-event]]List event::
An event that occurs while a classic list is built or after the user acts on a displayed list. Examples are TOP-OF-PAGE for a page header and AT LINE-SELECTION for a double click on a line. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[list-level]]List level::
The position of a list in the list buffer: the basic list is level 0 and each detail list opened from it gets the next level. The system field sy-lsind holds the current level. See xref:programming-languages/abap/classic-lists-and-interactive-reports.adoc[Classic Lists and Interactive Reports].

[[local-mode]]Local mode::
The addition IN LOCAL MODE to an EML statement, which a business object uses on itself to skip feature control and authorization checks. It is meant for the object's own code, not for outside callers. See xref:programming-languages/abap/eml.adoc[Entity Manipulation Language (EML)].

[[lock-master]]Lock master::
In a RAP business object, the entity whose instance is locked whenever any instance of a lock-dependent entity below it is locked. It is always a root, so one lock protects the whole tree of related records. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[lock-mode]]Lock mode::
The kind of lock that is requested, such as shared or exclusive, which decides what other lock requests are accepted while it exists. The page lists the modes S, E, X and O. See xref:programming-languages/abap/locks-and-enqueue.adoc[Lock Objects and the SAP Lock Concept].

[[lock-object]]Lock object::
A repository object in the ABAP Dictionary that says which tables and which key fields a lock covers. Generating it creates the function modules a program calls to set and release the lock. See xref:programming-languages/abap/locks-and-enqueue.adoc[Lock Objects and the SAP Lock Concept].

[[lock-table]]Lock table::
The table in the memory of the enqueue server that holds one entry for each lock currently set in the system. A new lock request is checked against it. See xref:programming-languages/abap/locks-and-enqueue.adoc[Lock Objects and the SAP Lock Concept].

[[logical-expression]]Logical expression::
A condition made of comparisons joined with AND, OR and NOT, which is either true or false. Statements such as IF and WHILE use it to decide what happens next. See xref:programming-languages/abap/control-flow.adoc[Control Flow].

[[logical-file-name]]Logical file name::
A name that does not depend on the operating system, which settings in the system link to a real path. The program uses the logical name and never contains the path, so it runs unchanged on different servers. See xref:programming-languages/abap/files-and-frontend-services.adoc[Files: Application Server and Front End].

[[logon-language]]Logon language::
The language a user picks when logging on to the system. It decides which translated copy of a text, such as a text element or message, the program shows. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[loop]]Loop::
A block of statements that is run again and again until a condition or a statement ends it. In ABAP it is written with statements such as DO, WHILE and LOOP AT. See xref:programming-languages/abap/control-flow.adoc[Control Flow].

== M

[[macro]]Macro::
A named piece of source text, defined between DEFINE and END-OF-DEFINITION, that the compiler pastes in wherever the name is used. Because it is only text substitution, newer code prefers methods. See xref:programming-languages/abap/modularization-overview.adoc[Modularization Overview].

[[main-session]]Main session::
One window of a user's logon, also called an ABAP session in the Keyword Documentation. Each main session has its own stack of program calls and its own memory. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[maintenance-view]]Maintenance view::
A classic Dictionary view that lets a user maintain the data of several linked tables as if it were one object. It is typically used for customizing tables. See xref:programming-languages/abap/ddic-views-and-search-helps.adoc[Dictionary Views and Search Helps].

[[managed-business-object]]Managed business object::
A RAP business object whose standard behavior, such as create, update and delete, is supplied by the RAP framework. The developer adds only the rules and extra actions. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[managed-rap-bo]]Managed RAP business object::
A RAP business object whose transactional buffer and standard operations (create, update, delete) are provided by the framework. You describe the behavior and RAP does the standard work, including saving to the database. See xref:programming-languages/abap/rap-managed-and-unmanaged.adoc[Managed, Unmanaged and Unmanaged Save].

[[mapping-assistant]]Mapping Assistant::
The part of the Class Builder that links the columns of a database table to the attributes of a persistent class. With these links Object Services can load and save the objects. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[matchcode-object]]Matchcode object::
The older predecessor of the search help, which offered input help through a view of one or more tables. New developments use search helps instead. See xref:programming-languages/abap/ddic-views-and-search-helps.adoc[Dictionary Views and Search Helps].

[[message-class]]Message class::
A named collection of numbered message texts kept in the system, not inside the program. Programs refer to a text by class and number, which lets one text be shared and translated. See xref:programming-languages/abap/messages.adoc[Messages].

[[message-type]]Message type::
A one-letter code that decides how a message is shown and whether the program carries on. The page describes the types A, E, I, S, W and X. See xref:programming-languages/abap/messages.adoc[Messages].

[[metadata-extension]]Metadata extension::
A separate piece of CDS source code that adds annotations to an existing CDS entity without changing the entity itself. It is commonly used to describe how the fields appear in a user interface. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[method]]Method::
A named block of code that belongs to a class, with its own parameters and local data. You call it to make an object, or the class, do something and possibly return a result. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[migration-object]]Migration object::
The description of how one kind of business data, such as a customer, is migrated. It names the source and target structures, the field mappings and the conversion rules. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[modification]]Modification::
A change made in a customer system to an object that SAP delivered, so that the object no longer matches SAP's original. Such changes must be reviewed and adjusted at an upgrade or support package import. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[modification-assistant]]Modification Assistant::
The function of the development workbench that protects an SAP object in a modification mode and logs each change in detail. The log makes it easier to adjust the change later. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[modification-browser]]Modification Browser::
An overview of all modifications and enhancements in a system, opened with transaction SE95 or from within the adjustment transactions. It helps you find what was changed. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[modification-group]]Modification group::
A short label of up to three characters that you give to screen elements so that a program can change several of them together. For example, it can hide all elements of one group at once. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[module-pool]]Module pool::
A program of the type module pool, which holds the dialog modules and the screens (dynpros) of a dialog application. It cannot run on its own and is started with a transaction code. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

== N

[[nast]]NAST::
The message table behind the older output control, in which an application records the outputs, such as printouts, it wants to produce. Newer S/4HANA applications use output management instead. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[native-sql]]Native SQL::
SQL text that is passed to the database unchanged and follows the rules of that database, not those of ABAP. It gives access to database features that ABAP SQL does not offer, at the cost of portability. See xref:programming-languages/abap/native-sql-adbc-and-amdp.adoc[Native SQL, ADBC and AMDP].

[[new-draft-instance]]New draft::
A draft that has no active instance yet, because the record is still being created. Saving it later turns it into the first active instance. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[bopf-node]]Node::
One level of the tree structure of a BOPF business object, with its own attributes and logic. A business object has a root node and can have child nodes below it. See xref:programming-languages/abap/bopf-and-the-fiori-programming-model.adoc[BOPF and the ABAP Programming Model for SAP Fiori].

== O

[[object]]Object::
One instance built from a class, with its own copy of the instance attributes. Many objects can be created from the same class, each holding different data. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[object-navigator]]Object Navigator::
The screen of the classic development workbench, opened with transaction SE80, that shows packages, programs, classes and other objects as one tree. You browse, open and edit development objects from there. See xref:programming-languages/abap/classic-tools-se80-and-se11.adoc[Classic Tools: SE80, SE38, SE11, SE37 and SE16].

[[object-services]]Object Services::
A software layer in ABAP Objects that provides persistence, transaction handling and queries for objects. It lets a program store objects in the database without writing the SQL itself. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[obsolete-language-element]]Obsolete language element::
A statement or addition that still works for old programs but that SAP advises against in new code. Newer constructs replace it, and some are not allowed at all in ABAP Cloud. See xref:programming-languages/abap/obsolete-language-elements.adoc[Obsolete Language Elements].

[[odata]]OData::
A web protocol for reading and changing data with ordinary HTTP requests and URLs. RAP services are exposed as OData services that user interfaces and other applications can call. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[offset-and-length]]Offset and length::
A way to address part of a text by its start position and the number of characters to take. It is written by adding the position and length after the variable name. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[ok-field]]OK field::
The field of a screen (dynpro) that receives the function code of the user's action, such as a pressed button or menu entry. The program reads it to decide what to do. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[online-text-repository]]Online Text Repository::
A central store of reusable texts that many objects can share and translate once. It is opened with transaction SOTR_EDIT. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[open-abap]]open-abap::
A community open-source project that runs a subset of ABAP on Node.js. It is not SAP software, and it is what lets the examples run without an SAP system. See xref:programming-languages/abap/hands-on-lab.adoc[Hands-on Lab].

[[operand-type]]Operand type::
The data type that a constructor expression has to produce. It is written after the operator or taken from the place where the expression is used. See xref:programming-languages/abap/constructor-expressions.adoc[Constructor Expressions].

[[optimistic-concurrency-control]]Optimistic concurrency control::
A way to handle several users changing the same data without blocking anyone. A change is accepted only if the data is still in the state the client saw, which an ETag value proves. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[outer-join]]Outer join::
A join that keeps the rows of one side even when nothing on the other side matches them. The columns of the missing side are then left empty. See xref:programming-languages/abap/abap-sql-joins-ctes-and-window-functions.adoc[ABAP SQL: Joins, CTEs, Window Functions and Path Expressions].

[[output-management]]Output management::
The S/4HANA framework that decides which document is produced, through which channel (print, email) and with which form. It replaces the older output control based on the NAST table. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

== P

[[package]]Package::
A container that groups development objects that belong together. It is also the unit that connects each object to the transport system and to the rules about who may use what. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[package-interface]]Package interface::
The list of objects that a package offers for use by other packages under the package concept. Objects not in the interface are meant to stay internal. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[packed-number]]Packed number::
A number type that stores decimal digits exactly, which makes it the usual choice for amounts and quantities. Unlike floating point numbers, it does not introduce rounding noise in decimal calculations. See xref:programming-languages/abap/currencies-units-and-conversions.adoc[Currencies, Units and Conversion Exits].

[[pai]]PAI (Process After Input)::
The event of a screen that runs after the user acts on it, when the program reads and checks what was entered. It is the counterpart of PBO, which runs before the screen is shown. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[parameter-interface]]Parameter interface::
The list of parameters and exceptions through which a function module talks to its caller. Each parameter has a name and a type, and says whether it goes in, comes out or both. See xref:programming-languages/abap/function-modules-and-function-groups.adoc[Function Modules and Function Groups].

[[partner-profile]]Partner profile::
The settings that say which messages a communication partner may exchange with the system, through which port, and how incoming messages are processed. IDoc exchange needs one for each partner. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[path-expression]]Path expression::
A chain of association names that reaches a field of a related entity. CDS separates the names with periods, ABAP SQL with backslashes, and the system turns the path into a join for you. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

[[pbo]]PBO (Process Before Output)::
The event of a screen that runs before the screen is shown, used to prepare what is displayed, such as filling fields or hiding elements. The counterpart is PAI. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[persistent-class]]Persistent class::
A class created in the Class Builder whose objects are managed by the persistence service of Object Services and can be stored in the database. Its attributes are linked to table columns. See xref:programming-languages/abap/object-services-and-persistence.adoc[Object Services: Persistence and Transaction Services].

[[perspective]]Perspective::
An Eclipse window layout that arranges the editors and views for one kind of task. ABAP Development Tools bring an ABAP perspective for development and a debug perspective for debugging. See xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

[[pessimistic-concurrency-control]]Pessimistic concurrency control::
A way to handle concurrent changes by locking a record while one user changes it. Every other change request for that record is rejected until the lock is gone. See xref:programming-languages/abap/rap-authorization-and-concurrency.adoc[RAP Authorization, Locking and Concurrency].

[[pfcg-condition]]PFCG condition::
A condition of a CDS access rule that compares fields of the entity with the authorizations the current user received through role maintenance (transaction PFCG). Only rows matching the user's authorization values are returned. See xref:programming-languages/abap/cds-access-control.adoc[CDS Access Control (DCL)].

[[physical-file-name]]Physical file name::
The real path and name of a file in the notation of the operating system of the server or PC. A logical file name is resolved to it at runtime. See xref:programming-languages/abap/files-and-frontend-services.adoc[Files: Application Server and Front End].

[[placeholder]]Placeholder::
A marker such as &1 in a message text that is replaced by a value when the message is raised. It lets one text carry variable details, such as a claim number. See xref:programming-languages/abap/messages.adoc[Messages].

[[polymorphism]]Polymorphism::
The same call running different code depending on the class of the object behind the reference. A caller can work with an interface or a superclass and still get the behavior of the actual class. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[pragma]]Pragma::
A marker written in the source that silences one particular warning of the compiler or of a check tool for that statement. It starts with two number signs and has replaced the older pseudo comments. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[predicate-expression]]Predicate expression::
A test on a single operand, such as asking whether a variable is initial, that is either true or false. It is used wherever a condition is expected. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[pal]]Predictive Analysis Library (PAL)::
A library of ready-made statistical and machine-learning algorithms that run inside SAP HANA. They are called from SQLScript, so the data does not have to leave the database. See xref:programming-languages/abap/hana-search-and-predictive-functions.adoc[SAP HANA Search and Predictive Functions from ABAP].

[[presentation-server]]Presentation server (front end)::
The user's own PC, on which SAP GUI runs. Files there are reached from ABAP through the class CL_GUI_FRONTEND_SERVICES, as opposed to files on the application server. See xref:programming-languages/abap/files-and-frontend-services.adoc[Files: Application Server and Front End].

[[primary-key]]Primary key::
The columns that identify a row of a table. For an internal table, ABAP uses them for fast key-based access, and the key can be unique or non-unique depending on the table kind. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[print-program]]Print program::
The ABAP program that reads the data for a document, chooses the form and hands the data to it. The form itself only lays the data out. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[processing-block]]Processing block::
A unit of code that the ABAP runtime starts and leaves as a whole. Examples are a method, a function module, a subroutine and an event block. See xref:programming-languages/abap/modularization-overview.adoc[Modularization Overview].

[[program-group]]Program group::
A main program, such as a loaded class pool or function pool, together with the programs loaded for it inside one internal session. Programs in a group share their global data. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[program-type]]Program type::
An attribute of a program that tells the system how it can be started and what it may contain. Examples are executable programs, module pools, function pools and class pools. See xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure].

[[projection-view]]Projection view::
A view that shows only a part of what lies below it. In RAP it is a CDS view entity that selects, and may rename, elements of one entity of a business object for one service; a classic Dictionary projection view does the same for one table. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[pseudo-comment]]Pseudo comment::
The older way of hiding a warning of a check tool, written as a comment that the tool reads. It is obsolete, and pragmas replace it. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

[[publish-and-subscribe]]Publish and subscribe::
A way to communicate in which the sender publishes a message without knowing who receives it. Receivers subscribe to the messages they care about. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[push-channel-protocol]]Push Channel Protocol (PCP)::
SAP's own message format for WebSocket messages, made of name and value fields and a body. It is used by ABAP Push Channels to structure what is sent. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

== Q

[[quickviewer]]QuickViewer::
The classic tool, started with transaction SQVI, with which one user builds a simple personal list without programming. It is meant for quick reports on a few tables. See xref:programming-languages/abap/sap-query-and-quickviewer.adoc[SAP Query and QuickViewer].

== R

[[raiser]]Raiser::
The object or class whose method raises an event. Handlers react to the event without the raiser needing to know them. See xref:programming-languages/abap/events.adoc[Events].

[[ranges-table]]Ranges table::
An internal table with the columns sign, option, low and high that stores a set of conditions on one value. A selection screen creates one for each select option, and it can be used in the WHERE clause of a query. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[rap]]RAP::
The ABAP RESTful Application Programming Model, the transactional programming model of ABAP Cloud. It combines CDS entities, behavior definitions and services to build business objects and OData apps. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[rap-business-event]]RAP business event::
A record that a significant change happened to an entity of a RAP business object, so that interested parties can react. It is announced to other systems, for example through an event messaging service. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[rap-business-object]]RAP business object::
A tree of CDS entities together with a behavior definition that says what may be done with them. A claim with its items is an example, and it is the unit RAP manages. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[redefinition]]Redefinition::
Giving an inherited method a new implementation in a subclass, with the same name and parameters. It is the way a subclass changes behavior it received from its superclass. See xref:programming-languages/abap/interfaces-and-inheritance.adoc[Interfaces, Inheritance and Polymorphism].

[[reference-field]]Reference field::
The field that an amount or quantity points to, so that the system knows its currency or unit. Without it, a number alone does not say what it counts. See xref:programming-languages/abap/currencies-units-and-conversions.adoc[Currencies, Units and Conversion Exits].

[[reference-variable]]Reference variable::
A variable that points to an object, declared with TYPE REF TO. You work with the object through it, and several variables can point to the same object. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

[[regular-expression]]Regular expression::
A pattern that describes which texts match, for example three digits followed by a letter. ABAP uses patterns like this to find, check and replace parts of strings. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[relational-expression]]Relational expression::
A comparison of two operands, such as one value being smaller than another, that is either true or false. It is the building block of conditions. See xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments].

[[release-contract]]Release contract::
The named promise that says for which kind of use an SAP object is released. The contracts are named C0 to C4, and each one fixes what you may do with the object and how stable it stays. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[release-news]]Release news::
The part of the ABAP Keyword Documentation that lists, release by release, what is new in the language. It is the place to check which release introduced a statement. See xref:programming-languages/abap/whats-new-in-abap.adoc[What's New in ABAP].

[[released-api]]Released API::
An SAP object that SAP has marked as stable and allowed for use by your own code. ABAP Cloud development may use only released APIs, so upgrades do not break your code. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[rfc]]Remote Function Call (RFC)::
A call of a function module that runs in another system, or in another session, through the RFC interface. The caller names a destination, and the function module must be marked as remote-enabled. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[remote-enabled-function-module]]Remote-enabled function module::
A function module that is marked in its properties as callable by RFC. Only such function modules can be called from other systems. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[reporting-event]]Reporting event::
One of the events of an executable program, from loading to the end of data processing. INITIALIZATION and START-OF-SELECTION are examples, and the runtime raises them in a fixed order. See xref:programming-languages/abap/classic-reports-and-events.adoc[Classic Reports and Event Blocks].

[[rfc-destination]]RFC destination::
The stored connection data, such as target system, connection type and logon data, that a call refers to by name after DESTINATION. It keeps connection details out of the program. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[rfc-group]]RFC server group::
A named set of application server instances that parallel processing may use. Naming the group in a parallel call limits where the work can run. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[root-entity]]Root entity::
The top parent of a composition tree, the entity that stands for the whole RAP business object. All child entities hang below it through compositions. See xref:programming-languages/abap/cds-associations.adoc[CDS Associations and Compositions].

[[rounding-mode]]Rounding mode::
The rule that decides in which direction a value lying exactly halfway between two results is rounded, for example up, down or to the even neighbor. Rounding functions let you choose it. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

[[rttc]]RTTC::
Runtime type creation: building a new data type while the program runs, for example a structure whose columns are only known then. It is done with the runtime type services classes. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[rtti]]RTTI::
Runtime type identification: reading the properties of a type, such as its kind, components or length, while the program runs. It is the tool for code that must handle data of types it does not know in advance. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[runtime-error]]Runtime error::
The termination of a program because something went wrong that nothing handled, for example an exception nobody caught. The system records it in a short dump that you can analyze afterward. See xref:programming-languages/abap/exceptions.adoc[Class-Based Exceptions].

[[runtime-type]]Runtime type::
The actual class of an object at the moment the program runs. It can be more specific than the declared type of the variable pointing to it. See xref:programming-languages/abap/control-flow.adoc[Control Flow].

== S

[[sap-event-mesh]]SAP Event Mesh::
The SAP messaging service that carries events between systems. A system publishes events to it and other applications subscribe to them. See xref:programming-languages/abap/rap-business-events.adoc[RAP Business Events].

[[fiori-elements]]SAP Fiori elements::
SAP technology that builds the screens of an app, such as a list page and a detail page, from annotations on a service instead of hand-written screen code. You describe the data and its labels, and the framework draws the user interface. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[sap-fiori-elements]]SAP Fiori elements::
SAP user interface technology that builds list pages and detail pages from the annotations of a service, so no screen code is needed. The annotations on a CDS view tell it which columns, headers and sections to show. See xref:programming-languages/abap/cds-annotations-and-metadata-extensions.adoc[CDS Annotations and Metadata Extensions].

[[sap-hana-database]]SAP HANA database::
The in-memory database that is the standard database of current ABAP systems. Because it can calculate on large amounts of data itself, ABAP programs are written to let it do the heavy work. See xref:programming-languages/abap/abap-for-sap-hana-and-code-pushdown.adoc[ABAP for SAP HANA and Code Pushdown].

[[sap-lock]]SAP lock::
A logical lock that tells other users "this record is being edited, wait". It is created from a lock object, kept in the lock table of the enqueue server and not on the database, so it can last across several screens of a dialog. See xref:programming-languages/abap/locks-and-enqueue.adoc[Lock Objects and the SAP Lock Concept].

[[sap-luw]]SAP LUW::
A business change made of one or more database steps that must be saved or undone together. It ends with `COMMIT WORK` or `ROLLBACK WORK`, and it can span several screens and work processes. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[sap-memory]]SAP memory::
The memory of one logged-on user that holds named parameters, the SPA/GPA parameters, and that every window of that logon can read. Typical uses are default values such as a company code that are filled into input fields. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[sap-query]]SAP Query::
A classic SAP tool in which an administrator defines queries so that a group of business users can build and run list reports without programming. It is reached through transaction SQ01 and works on InfoSets. See xref:programming-languages/abap/sap-query-and-quickviewer.adoc[SAP Query and QuickViewer].

[[migration-cockpit]]SAP S/4HANA migration cockpit::
The tool of current SAP S/4HANA for loading business data into a new system. It moves the data with migration objects, either from staging tables filled from template files or directly from another SAP system. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[sapscript]]SAPscript::
The oldest SAP technology for print forms such as invoices and letters. Its forms are edited in transaction SE71, and newer form technologies have largely replaced it. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[save-sequence]]Save sequence::
The last part of a RAP transaction. After the changes have been collected in the transactional buffer and a save is requested, the framework checks that the buffer is consistent, writes it to the database and cleans up. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[saver-class]]Saver class::
A local class of a RAP behavior pool that takes part in saving, for example to assign final keys or to add extra writes. It inherits from a class delivered by SAP, named `CL_ABAP_BEHAVIOR_SAVER`. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[search-help]]Search help::
A Dictionary object that builds the list of values offered when a user presses F4 in an input field. It helps people pick a valid value instead of typing it from memory. See xref:programming-languages/abap/ddic-views-and-search-helps.adoc[Dictionary Views and Search Helps].

[[secondary-index]]Secondary index::
An extra index on a database table for columns other than the primary key. Like the index of a book it lets the database find rows by those columns quickly, at the cost of extra work when rows are written. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[secondary-key]]Secondary key::
An additional, named key of an internal table that gives it a second way to be searched. It speeds up lookups by other columns, but it costs extra memory and upkeep. See xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Secondary Keys].

[[segment]]Segment::
One structured piece of the data of an IDoc, a message between systems. Segments are arranged in a tree of parents and children, and each holds a set of related fields. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[select-list]]Select list::
The part of a CDS view definition, written in braces, that names the elements (columns) the view returns. It decides what the view shows from its data source. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[selection-criterion]]Selection criterion::
An input field of a selection screen declared with `SELECT-OPTIONS`. It lets the user enter several single values, ranges and exclusions at once instead of just one value. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[selection-parameter]]Selection parameter::
A single input field on a selection screen, declared with `PARAMETERS` and backed by one variable of the program. The value the user types is available in that variable when the program runs. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[selection-screen]]Selection screen::
The input form that a classic report shows before it runs, so the user can enter values that restrict the data. It is generated from ABAP statements rather than drawn by hand. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[selection-text]]Selection text::
The caption shown next to an input field of a selection screen. It is kept as a text element of the program, so it can be translated. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[selection-variant]]Selection variant::
A saved set of values for the fields of one selection screen. Starting the report with a variant fills in the same answers again. See xref:programming-languages/abap/selection-screens.adoc[Selection Screens and Variants].

[[selectivity]]Selectivity::
How well the values of a field tell the rows of a table apart. A field with many different values is selective, and an index on such a field pays off, while an index on a field with few values does not. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[sender]]Sender::
The implicit parameter that every handler of an instance event can read to find out which object raised the event. You do not declare it yourself; ABAP fills it in. See xref:programming-languages/abap/events.adoc[Events].

[[serialization]]Serialization::
Turning ABAP data, such as a structure or a table, into a text format like JSON or XML so it can be sent or stored. Reading the text back into ABAP data is called deserialization. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[service-binding]]Service binding::
The object that connects a service definition to a protocol, such as OData V4, and to a kind of service, a UI service or a Web API. Publishing the binding makes the service reachable. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[service-definition]]Service definition::
The list of CDS entities that a business service exposes, written without choosing a protocol. A service binding later attaches it to a protocol. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[shared-memory]]Shared memory::
An area of one application server that many users and programs can read, used for data that is expensive to build. It is kept apart from the memory of a single logon. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[short-dump]]Short dump::
The error report that ABAP writes when a program ends with a runtime error that nobody caught. You read it in transaction ST22 or in ABAP Development Tools to see where and why the program stopped. See xref:programming-languages/abap/debugging.adoc[Debugging].

[[simple-transformation]]Simple transformation::
A small declarative program, written in a special XML-based language, that maps ABAP data to XML or JSON and back. It is used when the standard mapping is not the shape you need. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[singleton]]Singleton::
A class written so that only one object of it exists in the running program. Everyone who asks for it gets the same object. See xref:programming-languages/abap/design-patterns-in-abap.adoc[Design Patterns in ABAP].

[[smart-forms]]Smart Forms::
The second generation of SAP print forms. A form is designed graphically in the Form Builder (transaction SMARTFORMS) and activated into a function module that a program calls. See xref:programming-languages/abap/forms-sapscript-smart-forms-and-adobe.adoc[Forms: SAPscript, Smart Forms and SAP Forms by Adobe].

[[soap]]SOAP::
An older web service protocol that wraps its XML messages in an envelope and is described by a WSDL file. Many SAP systems still offer and call SOAP services. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[software-component]]Software component::
The delivery unit that a package belongs to. It also decides the ABAP language version that the objects of its packages follow. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[sorted-table]]Sorted table::
A kind of internal table that always keeps its rows in key order. Because of that order it finds a row by repeatedly halving the range to search, which is much faster than reading every row. See xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Secondary Keys].

[[spa-gpa-parameter]]SPA/GPA parameter::
A named value of up to 20 characters in the user memory of SAP memory. It prefills input fields and passes short values between programs and transactions of the same logon. See xref:programming-languages/abap/calling-programs-and-memory.adoc[Calling Programs, Transactions and Memory].

[[spau]]SPAU::
The transaction that, during an update, adjusts modified repository objects such as programs, function modules and screens. It lets you re-apply or discard your changes against the new delivery. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[spdd]]SPDD::
The transaction that adjusts modified ABAP Dictionary objects during an update, before the new dictionary objects are activated. It lets you re-apply or discard your changes against the new delivery. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[spool-request]]Spool request::
The stored print output of a job step. It waits in the spool until it is printed or shown on screen. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[sql-monitor]]SQL Monitor::
A tool that records, in a running system over a long time, which ABAP SQL statements are executed and how often. It shows which statements matter in real use rather than in one test run. See xref:programming-languages/abap/performance-and-sql-trace.adoc[Performance, SQL Trace and Profiling].

[[sql-trace]]SQL trace::
A recording of every database statement a program sends, with its duration and parameters. It lets you see what a program really asks the database and where the time goes. See xref:programming-languages/abap/performance-and-sql-trace.adoc[Performance, SQL Trace and Profiling].

[[sqlscript]]SQLScript::
The programming language of the SAP HANA database, an extension of SQL with variables and control flow. It is used for procedures and functions that run inside the database. See xref:programming-languages/abap/native-sql-adbc-and-amdp.adoc[Native SQL, ADBC and AMDP].

[[sscr]]SSCR::
The SAP Software Change Registration, a procedure that registers developers and manual changes to SAP source code and Dictionary objects. A developer needs an access key to make such a change. See xref:programming-languages/abap/modifications-and-modification-assistant.adoc[Modifications, Modification Assistant and SPAU/SPDD].

[[staging-table]]Staging table::
A temporary table in which data waits during a migration. It is filled from template files or by a tool, and the migration cockpit then moves it into the system. See xref:programming-languages/abap/batch-input-and-data-migration.adoc[Batch Input, Direct Input and Data Migration].

[[standard-abap]]Standard ABAP::
The full, classic ABAP language version, with all statements and unrestricted access to system objects. It is used on premise and in private cloud editions, while ABAP for Cloud Development restricts the language. See xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs].

[[stateful-apc]]Stateful and stateless APC::
Whether the handler of an APC connection keeps its attributes between the messages of one connection (stateful) or starts fresh for every message (stateless). APC is the ABAP Push Channel framework for WebSocket and TCP connections. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[static-check]]Static check::
A check that reads the source text of a program and reports problems without running it. The syntax check and the extended program check are examples. See xref:programming-languages/abap/coding-standards-and-clean-abap.adoc[Coding Standards and Clean ABAP].

[[static-code-analysis]]Static code analysis::
Checking source code for problems without running it. In ABAP the ABAP Test Cockpit is the main tool for this. See xref:programming-languages/abap/atc-and-code-inspector.adoc[ABAP Test Cockpit (ATC)].

[[status-bar]]Status bar::
The line at the bottom of a classic screen where short messages, such as success, warning and error texts, appear. Which messages show there depends on the message type. See xref:programming-languages/abap/messages.adoc[Messages].

[[strategy]]Strategy::
A design pattern in which several interchangeable classes implement the same interface and one of them is chosen at run time. It lets you swap a rule, such as how a fee is calculated, without changing the code that uses it. See xref:programming-languages/abap/design-patterns-in-abap.adoc[Design Patterns in ABAP].

[[string]]String::
A text of any length whose size grows and shrinks as needed, declared with the type `string`. It is the usual type for text in modern ABAP. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[string-function]]String function::
A built-in function that takes a text and returns a new text or a number, such as one that gives the length of a text. It does not change the original text. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[string-template]]String template::
A text written between vertical bars that can contain expressions in curly braces. ABAP replaces each expression with its value, which makes it an easy way to build messages. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[structure]]Structure::
A data object made of several named components, much like one filled-in row of a form. One claim with an ID, a status and an amount is a typical structure. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

[[subroutine]]Subroutine::
An old kind of procedure written between `FORM` and `ENDFORM` and called with `PERFORM`. It is obsolete; new code uses methods instead. See xref:programming-languages/abap/modularization-overview.adoc[Modularization Overview].

[[subscreen]]Subscreen::
A screen that is shown inside a reserved area of another screen, for example on one tab page. It lets one big screen be assembled from smaller ones. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[sy-index]]sy-index::
The system field that holds the number of the current pass through a `DO` or `WHILE` loop, counting from 1. In nested loops it belongs to the loop that runs at that moment. See xref:programming-languages/abap/control-flow.adoc[Control Flow].

[[sy-subrc]]sy-subrc::
The system field that holds the return code of the statement that ran last, where 0 usually means success. After a function module call it holds the number given to the exception that was raised. See xref:programming-languages/abap/function-modules-and-function-groups.adoc[Function Modules and Function Groups].

[[srfc]]Synchronous RFC (sRFC)::
A remote function call in which the caller waits until the remote function has finished and then continues with the result. It is the plainest kind of RFC. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[system-event]]System event::
An event of a GUI control that is passed to its handler at once, before field checks and without the usual screen processing. See xref:programming-languages/abap/control-framework-and-gui-controls.adoc[Control Framework and GUI Controls].

[[system-field]]System field::
A read-only value that the ABAP runtime fills in, for example the result of the last statement or the current date. All of them are components of the structure `sy`. See xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects].

== T

[[table-buffering]]Table buffering::
Keeping the rows of a rarely changed database table in the memory of the application server so that a read need not go to the database. It makes repeated reads faster. It suits tables that are read often and changed rarely. See xref:programming-languages/abap/performance-and-sql-trace.adoc[Performance, SQL Trace and Profiling].

[[table-control]]Table control::
A screen element of a classic dialog that shows and lets the user edit the lines of an internal table, like a small spreadsheet. See xref:programming-languages/abap/dynpros-and-module-pools.adoc[Dynpros, Module Pools and Transactions].

[[table-expression]]Table expression::
An operand written as the name of an internal table followed by square brackets, which picks out one row of the table. It is the short modern way to read a single row. See xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Secondary Keys].

[[table-index]]Table index::
The position number of a row in an internal table, counted from 1. Standard and sorted tables have it, and hashed tables do not. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[table-key]]Table key::
The columns by which an internal table finds its rows quickly. It is either the primary key chosen with the table or a secondary key added to it. See xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Secondary Keys].

[[table-kind]]Table kind::
The way an internal table stores and finds its rows, one of standard, sorted or hashed. The choice decides how fast lookups are. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[transport-task]]Task::
The part of a transport request that belongs to one developer. Each developer writes changes into their own task, and the request is released when its tasks are done. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[test-class]]Test class::
A class marked `FOR TESTING` that holds test methods. It is checked by ABAP Unit and is never part of the production behavior. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[test-double]]Test double::
An object or table that stands in for a real component during a test, so the test controls what the component answers. It is like a crash-test dummy for the part of the code you do not want to involve. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[test-seam]]Test seam::
A marked piece of production code that a test can replace with other statements. It lets you test code that is hard to isolate without rewriting it first. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[text-analysis]]Text analysis::
A feature of the SAP HANA database that finds words, languages and named entities such as people and places in text. ABAP reaches it through database-specific means. See xref:programming-languages/abap/hana-search-and-predictive-functions.adoc[SAP HANA Search and Predictive Functions from ABAP].

[[text-element]]Text element::
A text kept in the text pool of a program or class instead of inside its source code. Text symbols, selection texts and list headings are text elements, and they can be translated. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[text-field]]Text field::
A text of fixed length, declared with the type `c`, which is padded with blanks on the right. It differs from a string, which has no fixed length. See xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions].

[[text-symbol]]Text symbol::
A numbered or named text element that code reads as `+TEXT-001+`. Keeping the wording outside the code makes it translatable. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[text-table]]Text table::
A table that holds the language-dependent texts of the rows of a check table. It has the key of the check table plus a language key. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[time-stamp]]Time stamp::
A single value that names one exact moment, down to a fraction of a second. It is not tied to the clock of any place. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

[[time-zone]]Time zone::
A region whose clocks show the same local time, written in ABAP as a short key such as `EST` or `UTC`. It is needed to show a moment as local time to a user. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

[[total-etag]]Total ETag::
A field of a RAP business object that changes whenever the active data changes. A draft uses it to notice that the active data has moved on since the draft was created. See xref:programming-languages/abap/rap-draft.adoc[Draft Handling].

[[transaction-code]]Transaction code::
A short name such as SE80 that you type in the command field of SAP GUI to open one screen or start one program. Each code is linked to a program or method. See xref:programming-languages/abap/classic-tools-se80-and-se11.adoc[Classic Tools: SE80, SE38, SE11, SE37 and SE16].

[[transactional-buffer]]Transactional buffer::
The memory area that holds the data of a RAP business object while it is being worked on. Changes wait there until they are saved or discarded. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[transactional-phase]]Transactional phase::
One of the two stages, modify and save, that a controlled SAP LUW distinguishes. Changes are made in the modify phase, and the save phase writes them. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[trfc]]Transactional RFC (tRFC)::
The older kind of remote function call that is stored and sent when the caller commits. It is obsolete; background RFC replaces it. See xref:programming-languages/abap/rfc-bapis-and-idocs.adoc[RFC, BAPIs and IDocs].

[[translation]]Translation::
The work of adding the same text in another language so the system can show the right copy to each user. See xref:programming-languages/abap/text-elements-and-translation.adoc[Text Elements and Translation].

[[transparent-table]]Transparent table::
The usual kind of Dictionary table. It exists on the database under its own name and with the same columns as its Dictionary definition. See xref:programming-languages/abap/ddic-tables-and-structures.adoc[Database Tables and Structures].

[[transpiler]]Transpiler::
A program that translates source code from one language into another. In the hands-on lab it translates ABAP into JavaScript so that the code can run without an SAP system. See xref:programming-languages/abap/hands-on-lab.adoc[Hands-on Lab].

[[transport-layer]]Transport layer::
The group of development projects that share the same transport routes. It decides where the changes of a package travel after they are released. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[transport-request]]Transport request::
A container that records changed objects so they can be moved from the development system to the next system. Without a request, a change stays where it was made. See xref:programming-languages/abap/transports-packages-and-gcts.adoc[Packages, Transports, gCTS and abapGit].

[[type-description-object]]Type description object::
The one object per type that carries the properties of that type, such as its length or components. It is created by the static methods of the type description classes and answers "what type is this?" while the program runs. See xref:programming-languages/abap/rtti-and-dynamic-programming.adoc[RTTI, RTTC and Dynamic Programming].

[[type-group]]Type group::
A special program that only holds type definitions and constants for shared use. See xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure].

== U

[[unit-of-measure]]Unit of measure::
A code such as KG or PC that says what a quantity is counted in. A quantity field is meaningful only together with its unit. See xref:programming-languages/abap/currencies-units-and-conversions.adoc[Currencies, Units and Conversion Exits].

[[unit-test]]Unit test::
A test of one small unit of code, such as a method, that runs automatically and needs no person to judge the outcome. In ABAP it is written with ABAP Unit. See xref:programming-languages/abap/abap-unit-and-test-doubles.adoc[ABAP Unit and Test Doubles].

[[unmanaged-business-object]]Unmanaged business object::
A RAP business object whose behavior, including its buffer, is coded by the developer. See xref:programming-languages/abap/rap-overview.adoc[RAP Overview].

[[unmanaged-rap-bo]]Unmanaged RAP business object::
A RAP business object whose transactional buffer and operations you implement yourself in the behavior pool. The framework does not provide them for you. See xref:programming-languages/abap/rap-managed-and-unmanaged.adoc[Managed, Unmanaged and Unmanaged Save].

[[unmanaged-save]]Unmanaged save::
Your own code that replaces the standard save of a managed RAP business object. It is used when the changes must be written by your own code, for example existing function modules, instead of by the framework. See xref:programming-languages/abap/rap-managed-and-unmanaged.adoc[Managed, Unmanaged and Unmanaged Save].

[[update-function-module]]Update function module::
A function module marked as an update module. A program registers it during its work, and it runs later, in a special work process, when the program issues `COMMIT WORK`. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[update-task]]Update task::
The mechanism that stores registered update function modules and runs them when the program commits. It is part of classic ABAP and is not available in ABAP Cloud. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[update-work-process]]Update work process::
A work process reserved for running update function modules. It performs the database changes that the dialog program registered. See xref:programming-languages/abap/sap-luw-and-update-tasks.adoc[SAP LUW, Update Tasks and Commit].

[[user-group]]User group::
In SAP Query, the set of users that may use a given set of InfoSets and queries. A query is available to the members of its user group. See xref:programming-languages/abap/sap-query-and-quickviewer.adoc[SAP Query and QuickViewer].

[[user-master-record]]User master record::
The record that exists for every user of an SAP system and holds, among other things, the authorizations that user has. Authority checks read it to decide whether an action is allowed. See xref:programming-languages/abap/authority-checks.adoc[Authorization Checks].

[[user-session]]User session::
Everything that belongs to one logon of one user to one application server. It starts at logon and ends at logoff, and it can contain several windows. See xref:programming-languages/abap/memory-organization-and-sessions.adoc[Memory Organization and Sessions].

[[utclong]]UTCLONG::
The built-in type that holds a time stamp in Coordinated Universal Time with a resolution of 100 nanoseconds. See xref:programming-languages/abap/date-time-and-numeric-functions.adoc[Dates, Times and Built-in Functions].

== V

[[validation]]Validation::
A check on the data of a RAP business object that runs when it is saved and rejects the save when the data is wrong. A validation only checks; it never changes the data. See xref:programming-languages/abap/rap-behavior-definitions.adoc[Behavior Definitions and Implementations].

[[value-help]]Value help::
The list a user can open next to an input field to pick a valid value. The term covers Dictionary search helps as well as CDS-based lists and Fiori apps. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[value-table]]Value table::
A table named by a domain that serves only as a default proposal for the check table of a foreign key. It does not trigger any input check by itself. See xref:programming-languages/abap/ddic-foreign-keys-and-indexes.adoc[Foreign Keys, Check Tables and Indexes].

[[variable]]Variable::
A named place in memory that holds one value which the program can change. The name lets the program read and replace that value later. See xref:programming-languages/abap/programming-concepts-for-newcomers.adoc[Programming Concepts for Newcomers].

[[vdm]]Virtual data model (VDM)::
SAP's layered set of CDS views, in which each layer has a defined purpose and a naming prefix. It gives applications a stable, business-oriented way to read SAP data. See xref:programming-languages/abap/cds-view-entities.adoc[CDS View Entities].

[[visibility-section]]Visibility section::
One of the three parts of a class, `PUBLIC`, `PROTECTED` and `PRIVATE`. The section in which a component is declared decides who may use it. See xref:programming-languages/abap/classes-and-objects.adoc[Classes and Objects].

== W

[[watchpoint]]Watchpoint::
A marker on a variable that makes the debugger stop as soon as the value of that variable changes. It is useful when you do not know where a wrong value is set. See xref:programming-languages/abap/debugging.adoc[Debugging].

[[web-api]]Web API::
A service meant for programs rather than for people, which carries no user interface information in its metadata. It is the alternative to a UI service. See xref:programming-languages/abap/rap-services-and-odata-v4.adoc[Projections, Service Definitions and OData V4 Bindings].

[[websocket]]WebSocket::
A protocol that keeps one connection open so that both sides can send messages at any time. It suits live updates better than repeated requests. See xref:programming-languages/abap/abap-channels-apc-and-amc.adoc[ABAP Channels: APC and AMC].

[[window-expression]]Window expression::
A function followed by `OVER` that computes a value for each row from a group of related rows, such as a rank or a running total, without merging the rows into one. See xref:programming-languages/abap/abap-sql-joins-ctes-and-window-functions.adoc[ABAP SQL: Joins, CTEs, Window Functions and Path Expressions].

[[work-area]]Work area::
A single structure that holds one row while you read it from or write it to an internal table. See xref:programming-languages/abap/internal-tables.adoc[Internal Tables].

[[work-package]]Work package::
One independent slice of the data that one parallel task processes. Cutting the data into packages lets several tasks work at the same time. See xref:programming-languages/abap/background-processing.adoc[Background Jobs and Parallel Processing].

[[work-process]]Work process::
A worker inside the application server that runs your ABAP code when it is given a request. It handles one piece of ABAP at a time. See xref:programming-languages/abap/getting-started.adoc[Getting Started].

[[wrapper]]Wrapper::
A small class of your own that hides a call to old code behind a released interface. ABAP Cloud code then calls the wrapper instead of the classic code. See xref:programming-languages/abap/migrating-classic-code-to-abap-cloud.adoc[Migrating Classic Code to ABAP Cloud].

[[writable-database-object]]Writable database object::
A database table or CDS entity that the statements `INSERT`, `UPDATE`, `MODIFY` and `DELETE` are allowed to change. See xref:programming-languages/abap/abap-sql-writing-data.adoc[ABAP SQL: Writing Data].

== X

[[xco-library]]XCO library::
A class library delivered by SAP and released for ABAP Cloud, which includes a module for working with JSON. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].

[[xslt]]XSLT::
The W3C language for turning one XML document into another. ABAP can run such an XSL transformation with `CALL TRANSFORMATION`. See xref:programming-languages/abap/outbound-http-json-and-xml.adoc[HTTP Clients, JSON and XML Transformations].
