= ABAP Guide: Work with Internal Tables
:description: Step-by-step guide to internal tables in the local ABAP playground (open-abap 2.14.30): build the items of an expense claim with VALUE, read rows with a table expression, line_exists and READ TABLE, sort and list by category with AT NEW, and total and filter with REDUCE and FILTER.
:keywords: ABAP, internal table, VALUE, table expression, line_exists, READ TABLE, SORT, AT NEW, REDUCE, FILTER, sy-subrc, open-abap, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-13 against open-abap 2.14.30 (the abaplint transpiler and runtime, with open-abap-core commit a9acc41) and Node.js 24.21.

== What you build

You write a class named `zit_claim_items` that holds the six items of one expense claim in an internal table, an
internal table being a list of rows that lives only while the program runs. Four methods work on that list. `build`
fills it with the `VALUE` expression, `read_rows` reads single rows in three ways, `list_by_category` sorts the table and
prints the items under a heading per category, and `total_and_filter` adds up the amounts with `REDUCE` and keeps only
the travel items with `FILTER`. A report named `zit_internal_tables` creates the class and calls the methods, and you
run it on Node.js after every phase. At the end you ask for a row that does not exist and read the error that follows.

The playground is open-abap, a community open-source project, not SAP software. It runs only the part of the ABAP
language that it implements, so a program that works here needs a check on a real SAP system before you rely on it
there. The lab's items are simpler than the real claim items of an SAP system: a category, an item number and a whole
euro amount. The statement `+LOOP AT ... GROUP BY+` and the statement `COLLECT` do not run in the playground and are not
used; they are explained on xref:programming-languages/abap/internal-tables-processing-and-grouping.adoc[Internal Tables: Processing and Grouping].

This guide adds files to the `src` folder of the same `abap-lab` folder.

Two pages go deeper than this guide does: xref:programming-languages/abap/table-expressions-and-keys.adoc[Table Expressions and Keys] and xref:programming-languages/abap/constructor-expressions.adoc[Constructor Expressions].

== Steps

The class grows by one method in each phase. In every phase you add two pieces to the class: the `METHODS` line in the `DEFINITION` part, which announces the method, and the `+METHOD ... ENDMETHOD+` block in the `IMPLEMENTATION` part, which holds its code. Then you add one line to the report that calls the method.

=== Write the class and build the table

. In the `src` folder, create the file `src/zit_claim_items.clas.abap` with the source below. The statement `+TYPES: BEGIN OF ty_item ... END OF ty_item+` describes one row, a structure with three components. `TYPES ty_items TYPE STANDARD TABLE OF ty_item WITH EMPTY KEY` describes the whole table: a standard table, which keeps its rows in the order they were added, with no key, because this guide only loops over the rows and looks them up with conditions. The method `build` hands the table back as its result. In it, `+VALUE #( ( ... ) ( ... ) )+` builds a table: every pair of inner parentheses is one row, and `#` means that the type of the result is taken from the receiving variable `items`. The category stands first in the row, which matters in a later phase.

=== Read rows

A program often needs one row of a table, for example the item with number 3. ABAP has two ways to read one row: a table expression, which is the name of the table followed by a condition in square brackets, and the statement `READ TABLE`.

[start=6]
. In `src/zit_claim_items.clas.abap`, add the line that declares the method to the `DEFINITION` part, below the declaration of `build`, and the method itself to the `IMPLEMENTATION` part, below `build`. In the method, `items[ item_no = 3 ]` is a table expression: it stands for the first row whose `item_no` is 3, and `DATA(third)` declares a variable that receives that row. `line_exists( items[ item_no = 9 ] )` is true or false, so nothing fails when the row is missing. `+READ TABLE ... WITH KEY+` copies a row into a variable and reports the result in `sy-subrc`: 0 when a row was found and 4 when it was not.

=== Sort and list by category

The items are in the order they were entered, and the categories are mixed. To print the items under one heading per category, sort the table by category first, then use a control-level statement inside a loop.

[start=10]
. Add the declaration of `list_by_category` and the method. `DATA(sorted) = items` copies the table, so that the original keeps its order. `SORT sorted BY category item_no` puts the rows in ascending order of category and, within a category, of item number. `LOOP AT sorted INTO DATA(item)` runs the block once per row. `AT NEW category` runs its block when the value of `category` differs from the row before, so it runs once per category and prints the heading. The statement compares the named column and every column to its left, which is why `category` is the first component of `ty_item`.

=== Total and filter

[start=14]
. Add the declaration of `total_and_filter` and the method. `REDUCE` reduces a table to one value: `INIT` gives the start value of `sum`, `FOR item IN items` repeats over the rows, `NEXT` says what happens on every row, and the result is the final `sum`, of type `i`. `FILTER` with a `WHERE` condition on `category` builds a new table with only the matching rows. `FILTER` needs a table with a sorted or hashed key on the compared column, so the method first copies the items into `by_category`, a sorted table with the non-unique key `category`. === Read a row that is not there

A table expression stands for a row, so the row has to exist. You make that fail on purpose, in a place where you know the fix.

[start=18]
. In `read_rows`, change the first line of the method from `items[ item_no = 3 ]` to `items[ item_no = 9 ]`. There is no item 9. Save the file.
. Run `npm run run:items`. The report prints its first line, then the program stops: no row matches, so the table expression raises the exception `cx_sy_itab_line_not_found`, and nothing catches it. Node.js prints the exception as a stack trace. Read the lines that name your code: `zit_claim_items.read_rows` is the method, and the number pair after `clas.mjs` is the position in the generated JavaScript, not in your ABAP source. Node.js ends with exit code 1. The figure leaves out the unrelated lines of the trace and shortens the long paths with three dots.
+
image::sap-abap-guide-work-with-internal-tables-07-first-error.svg["Terminal after npm run run:items when the table expression asks for item 9: the program prints Claim 1001 has 6 items and then Node.js prints a stack trace that names cx_sy_itab_line_not_found, the runtime function tableExpression and the method read_rows; callout 19 marks the exception line",width=900]
. Change `9` back to `3`, save and run `npm run run:items`. The 17 lines of output return.

== Check the result

`npm run run:items` ends without an error and prints 17 lines: the count `Claim 1001 has 6 items`, the four lines of `read_rows`, the three headings with their six items, and the three lines `Total: 249 EUR`, `Travel items: 3` and `Travel total: 89 EUR`. `npm run lint` prints `abaplint: 0 issue(s) found, 14 file(s) analyzed` and `npm test` still passes.

== Variations

* Catch the missing row instead of letting the program stop. Wrap the table expression for item 9 in `TRY.` and `CATCH cx_sy_itab_line_not_found.` and write a line in the `CATCH` part: the program then prints that line and goes on.
* Give a fallback instead of an exception: `+VALUE ty_item( items[ item_no = 9 ] OPTIONAL )+` returns an empty row, so `amount` is 0 and the program goes on.
* Add a seventh item to `build` and run again to see the totals and the headings change. A new category such as `FLIGHT` gets its own heading, in alphabetical order.
* Read a row by position: `items[ 2 ]` is the second row of the table in its current order.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|`Error: check_syntax, Method "read_row" not found, methodCallChain, zit_internal_tables.prog.abap:8` and no program output
|The report calls a method name that the class does not have, here `read_row` instead of `read_rows`.
|Open the file and line at the end of the message and correct the name. `npm run lint` shows the same finding with the column.

|`cx_sy_itab_line_not_found [Error]` and a Node.js stack trace that names `tableExpression`
|A table expression asked for a row that does not exist, and no `TRY` block catches the exception.
|Ask first with `line_exists( )`, give a fallback with `OPTIONAL`, or catch the exception.

|`READ TABLE: sy-subrc 4` where you expected a row
|No row matches the `WITH KEY` condition. `READ TABLE` does not stop the program: it only sets `sy-subrc`.
|Check the key value, for example the spelling and the case of the category, and test `sy-subrc` before you use the variable.
|===
