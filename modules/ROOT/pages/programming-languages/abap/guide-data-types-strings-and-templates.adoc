= ABAP Guide: Data Types, Strings and String Templates
:description: Step-by-step guide to the local ABAP playground (open-abap 2.14.30): declare text and number variables, convert values with CONV, build text with string templates and string functions, split a record, check it with a regular expression and print one claim summary line.
:keywords: ABAP, data types, string, string template, CONV, DATA, inline declaration, condense, substring, SPLIT, regular expression, PCRE, open-abap, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-13 against open-abap 2.14.30 (the abaplint transpiler and runtime), open-abap-core a9acc41, abaplint 2.120.103 and Node.js 24.21.

== What you build

You work with one expense claim in text form. Along the way you declare variables of different types, convert values from one type to another, build sentences with string templates, clean and cut text with string functions, split a semicolon-separated record into parts and test the claim number with a regular expression (a pattern for text). At the end a small class, `zdt_claim_text`, turns the raw record `+C-1001; ada  lovelace ;125.5;eur+` into the summary line `+Claim C-1001 | ADA LOVELACE | 125.50 EUR+`, and a report named `zdt_summary` prints it.

The claim number, the name and the amounts are made-up example values. The playground is open-abap, a community open-source project, not SAP software. It runs only the part of the ABAP language that it implements, so check a program on a real SAP system before you rely on it there. Output is written with `WRITE`, the classic list statement, because that is what the playground offers.

== Before you start

* No account is needed: Node.js, the abaplint tools and open-abap install from the public npm registry without signing in. The licences you accept by installing (MIT for the abaplint packages) are listed in the README of the ABAP lab.
* Set up the lab first, with the guide xref:programming-languages/abap/guide-set-up-a-local-abap-playground.adoc[Set Up a Local ABAP Playground], and work through xref:programming-languages/abap/guide-first-abap-program.adoc[Your First ABAP Program]: you need the folder `abap-lab` with `npm install` done, the habit of one `.abap` file plus one `.xml` file per object, and an editor such as Visual Studio Code open on it.
* The lab already holds the finished files of this guide in `modules/ROOT/examples/abap-lab/src/`. Type them yourself rather than copying them, so that you meet the errors in this guide on your own screen.
* Read xref:programming-languages/abap/data-types-and-data-objects.adoc[Data Types and Data Objects] for the types used here, xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions] for the text tools, and xref:programming-languages/abap/expressions-and-operators.adoc[Expressions, Operators and Assignments] for how a value changes type when it is stored or calculated.
* The figures are drawings of the editor and the terminal, not screenshots. A highlighted box with a number marks the file or the output of the step with the same number. A figure of a run shows only the lines that the phase added, and no figure shows the lines the transpiler prints about its file counts.

== Steps

The report `zdt_summary` grows from phase to phase. Every phase adds a block of lines at the end of the report and ends with a run, so the output of each run contains the lines of all earlier phases too. All names that start with `zdt_` belong to this guide.

=== Declare data and convert values

. Create the report `src/zdt_summary.prog.abap` with the lines below, and its attribute file `src/zdt_summary.prog.xml` next to it. A variable is declared with `DATA`, a name and a type. The type `string` holds a text of any length and keeps every character, including blanks at the end. The type `c LENGTH 20` is a text field of exactly twenty characters: a shorter value is filled up with blanks, and a longer value is cut off, as `short_name` shows, which has room for five characters only. The statement `+DATA(item_count) = 3.+` is an inline declaration: ABAP works out the type from the value, here an integer. Each `WRITE` line prints a template (the text between vertical bars, with values in `+{ }+`) and `strlen` counts the characters.

=== Split a record and check it

[start=7]
. Add a raw record, as it might arrive from a file, and cut it at the semicolons. `+SPLIT ... INTO TABLE+` puts every piece in one row of an internal table (a list of values, here of texts). `lines( parts )` counts the rows, and the `LOOP` prints each row in square brackets, so you see that the blanks around the name are still there: splitting does not clean.
+

----

Source: https://github.com/SAP-samples/abap-cheat-sheets/blob/main/07_String_Processing.md[ABAP Cheat Sheet: String Processing]
. Add the pattern checks. The pattern `+C-\d{4}+` reads: the letter C, a dash, then exactly four digits (`pass:c[\d]` is one digit). `matches` is true only when the whole text fits the pattern, so `C-1001` fits and `C-12` does not. In `FIND PCRE`, the parts of the pattern in parentheses are remembered and handed back with `SUBMATCHES`: here the first word and the amount behind it. `replace` with a pattern and `occ = 0` replaces every match. Inside backquotes the backslashes stay as they are.

=== Read your first error

[start=13]
. In `src/zdt_summary.prog.abap`, remove the spaces inside the braces of the first `WRITE` statement (line 10), so that `+{ claim_id }+` becomes `+{claim_id}+`. Save the file.
. Run `npm run run:summary`. The transpiler checks the syntax first and stops at the first problem. The line names the check that failed (`parser_error`), says that the statement is not valid, gives the statement it could not read (`WRITE`) and ends with the file and line. Node.js does not run the program. The message does not name the real cause, the missing spaces, so look at the braces on that line.
+
image::sap-abap-guide-data-types-strings-and-templates-06-first-error.svg["Terminal after npm run run:summary with the spaces removed inside the braces of the first template: the transpiler stops with the line Error: parser_error, Statement does not exist in the configured ABAP version or a parser error, WRITE, zdt_summary.prog.abap:10 and the program does not run; callout 14 marks the error line",width=900]
. Put the spaces back, save and run `npm run run:summary` again. The 28 lines return.

== Check the result

`npm run run:summary` ends without an error and prints 28 lines, from `C-1001: 6 characters` to `Cannot read: C-1002;Ben`. `npm run lint` prints `abaplint: 0 issue(s) found`, and `npm test` still passes with the test of the lab's greeter class.

== Variations

* Change the declaration of `short_name` to `c LENGTH 8` and run again to see how much of the name fits.
* Ask `find` for a piece of text that is not there, for example `+find( val = claim_id sub = `X` )+`: it returns -1.
* Change the amount in the raw record to `7` and read `7.00` in the summary line.
* The template options `WIDTH`, `ALIGN` and `PAD` format text to a fixed width. They are described on xref:programming-languages/abap/strings-and-string-templates.adoc[Strings, String Templates and Regular Expressions]; the playground does not apply the alignment the way an SAP system does, so this guide leaves them out.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|`Error: parser_error, Statement does not exist in the configured ABAP version(or a parser error), "WRITE", zdt_summary.prog.abap:10`
|There is no space after `+{+` or before `+}+` inside a template.
|Open the file and line named at the end of the message and write `+{ name }+` with a space on both sides.

|A calculation shows 4 where you expected 3.5
|Both operands of `+7 / 2+` are integers, so the calculation is done in whole numbers.
|Convert one operand first: `+CONV decfloat34( 7 ) / 2+`.

|A long block of text starts with `cx_sy_conversion_no_number [Error]` and the exit code is 1
|`+CONV i( ... )+` was given a text that holds no number, such as `abc`, and nothing handles the exception.
|Check the text first, for example with `pass:c[matches( val = text pcre = `\d+` )]`, or handle the exception (the guide on xref:programming-languages/abap/guide-classes-interfaces-and-exceptions.adoc[classes, interfaces and exceptions] shows how).

|A long block of text starts with `cx_sy_range_out_of_bounds [Error]`
|`substring` was asked for characters behind the end of the text, for example `off = 4 len = 10` on the six characters of `C-1001`.
|Compare the length with `strlen` first, or use `substring_before` and `substring_after`.

|A text that you wrote as `+'ab   '+` is 2 characters long, not 5
|A text between single quotes is a text field literal, and the blanks at the end are not kept when it is stored in a `string`.
|Write a text that must keep trailing blanks between backquotes: `+`ab   `+`.

|`npm run lint` prints `Variable "n" not used (unused_variables) [E]`
|A variable was declared with `DATA` or an inline declaration and never read.
|Use the variable or delete the declaration.
|===
