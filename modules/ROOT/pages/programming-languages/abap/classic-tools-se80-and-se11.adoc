= Classic Tools: SE80, SE38, SE11, SE37 and SE16
:description: The classic ABAP Workbench transactions SE80, SE38, SE11, SE37, SE16 and SE84, when you still meet them in Standard ABAP and which ABAP Development Tools feature replaces each one.
:keywords: ABAP, SE80, SE38, SE11, SE37, SE16, SE84, SE24, ABAP Workbench, Object Navigator, ABAP Editor, ABAP Dictionary, Function Builder, Data Browser, Repository Information System, ADT, classic ABAP

include::partial$ai-disclaimer.adoc[]

Long before Eclipse, ABAP developers worked inside SAP GUI, the classic desktop client of SAP systems. Each task had its own
screen that you opened by typing a short code, called a transaction code, into the command field: SE80 to browse everything
you have written, SE38 to edit a program, SE11 to define database tables, SE37 to work on function modules and SE16 to look
at table rows. Together these screens are called the ABAP Workbench. This page explains what each one does, when you still
meet it, and which feature of ABAP Development Tools (ADT, the Eclipse-based editor) does the same job. It is written
against Standard ABAP release 8.16 (the keyword documentation for SAP S/4HANA Cloud Private Edition and SAP S/4HANA 2025)
and ABAP for Cloud Development release 9.20 (2608). The Workbench transactions exist only in classic, Standard ABAP systems
such as SAP S/4HANA on premise and Private Edition; they are not available in ABAP Cloud, the SAP BTP ABAP environment or
SAP S/4HANA Cloud Public Edition, where ADT is the only development tool. For the Eclipse side, see
xref:programming-languages/abap/adt-eclipse-setup.adoc[ABAP Development Tools (ADT)].

== Key terms

* xref:programming-languages/abap/glossary.adoc#transaction-code[Transaction code]: a short name such as SE80 that you type in the SAP GUI command field to open one screen.
* xref:programming-languages/abap/glossary.adoc#abap-workbench[ABAP Workbench]: the set of classic SAP GUI tools for creating and changing ABAP development objects.
* xref:programming-languages/abap/glossary.adoc#object-navigator[Object Navigator]: the Workbench screen (SE80) that shows packages, programs, classes and other objects as one tree.
* xref:programming-languages/abap/glossary.adoc#abap-dictionary[ABAP Dictionary]: the central place where tables, data elements and other type definitions are kept, maintained with SE11.
* xref:programming-languages/abap/glossary.adoc#function-module[Function module]: a reusable procedure stored in a function group that can be called from any program.
* xref:programming-languages/abap/glossary.adoc#transport-request[Transport request]: a container that records changed objects so they can be moved from a development system to the next system.
* xref:programming-languages/abap/glossary.adoc#abap-development-tools[ABAP Development Tools]: the Eclipse-based environment in which ABAP is written for ABAP Cloud and, optionally, for classic systems.

== What the ABAP Workbench is

A development object is anything you create and store in the system's repository: a program, a class, a table definition, a
function module. The ABAP Workbench groups the tools that create and change those objects. Every object belongs to a
package and, in most systems, is recorded in a transport request when you change it, so the change can travel from the
development system to test and production systems later.

Two ideas help to read the transaction list that follows. First, SE80 is a hub that shows objects as one tree, while the
other transactions are focused tools for one kind of object. Second, the tools overlap: you can reach the same function
module through SE80 or through SE37, which is why experienced developers mention the codes casually.

== SE80 and SE84: finding your way

Open SE80, choose a type in the drop-down list (package, program, class, function group, transaction and so on), type a
name and press Enter. The left pane becomes a tree; double-clicking a leaf opens the right tool in the right pane. This
beats typing codes one at a time when you are exploring unfamiliar code, which is why it is the usual entry point in a
maintenance project.

SE84 is the Repository Information System. Where SE80 shows one package or program at a time, SE84 answers questions across
the whole system, such as every program in a package or every table with a given name pattern. It also offers where-used
searches, which tell you which programs use an object before you change it. In ADT the same two jobs are Open Development
Object and the where-used list.

== SE38: programs

SE38 opens the ABAP Editor. You type a program name, choose Create, Change or Display, and the editor appears. Executable
programs, the kind that start with the `REPORT` statement, are started from here with the Execute button. The editor also
holds the syntax check and the activation function.

The following executable program reads one claim from the running Expense claims example. It requires an SAP system; not
run here.

[source,abap]
----
REPORT zexp_show_claim.

PARAMETERS p_claim TYPE zexp_claim-claim_id OBLIGATORY.

START-OF-SELECTION.
  SELECT SINGLE * FROM zexp_claim
    WHERE claim_id = @p_claim
    INTO @DATA(ls_claim).
  IF sy-subrc = 0.
    WRITE: / 'Claim', ls_claim-claim_id.
  ELSE.
    WRITE: / 'Claim not found'.
  ENDIF.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap[ABAP Keyword Documentation for Standard ABAP]

The statements `REPORT`, `PARAMETERS`, `START-OF-SELECTION` and `WRITE` belong to classic list-based programs of Standard
ABAP. In ADT a class can be run as a console application with Run As > ABAP Application (Console), shortcut F9, as
described on the ADT page.

== SE11: the ABAP Dictionary

SE11 is where database tables are defined. You enter a name starting with `Z` or `Y` (the customer namespace), fill in the
fields, assign data elements to them, set the technical settings, and activate. The same transaction maintains structures,
data elements, domains and table types.

In a classic system a table such as ZEXP_CLAIM of the running example would be created here, with the key fields and the
item table ZEXP_ITEM linked to it by a foreign key. In ADT the same kind of object is edited in a text-based database table editor, as the ADT user guide describes. The
semantics are the same; only the editor changes. Where the ABAP Dictionary and its objects are covered in depth is a later page of this section
that deals with the data model.

== SE37: function modules

A function module is a procedure stored in a function group. SE37 opens the Function Builder: screens for the interface
(its parameters and exceptions) and the source code, and a test function that runs the module with input you type, which
makes SE37 a popular tool to try a function module before you call it in your own code.

You call a function module with `CALL FUNCTION`. The sketch below requires an SAP system; not run here, and the module name
is a placeholder for any module you have looked up in SE37.

[source,abap]
----
CALL FUNCTION 'Z_EXP_GET_CLAIM'
  EXPORTING
    iv_claim_id = lv_id
  IMPORTING
    es_claim    = ls_claim
  EXCEPTIONS
    not_found   = 1
    OTHERS      = 2.
IF sy-subrc <> 0.
  " handle the error
ENDIF.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap[ABAP Keyword Documentation for Standard ABAP]

New code is normally written as methods of a class instead of function modules, but function modules remain everywhere in
older SAP code and in interfaces such as remote function calls, so reading them is a daily skill in maintenance work.

== SE16: the Data Browser

SE16 shows the rows of a table. You enter the table name, optionally fill in selection criteria, and run. It is useful for
checking test data and for understanding what a program wrote. Because it can show any table content, treat it as a development
and support tool rather than a reporting tool.

In ADT the same need is covered by Data Preview: choose Open With > Data Preview on a table or view, or press Alt+F8. By default
it shows the top 100 records, and you can set filters, sort and choose columns.

== When you still meet these tools

* You maintain or extend a classic program, report, function module or screen in S/4HANA on premise or Private Edition.
* A colleague, an SAP Note or an older tutorial says "go to SE38" or "check it in SE37".
* You work with classic screens, which ADT can open in an embedded SAP GUI (Ctrl+6), so the Workbench tool stays the editor.
* You support users, who are sent to a transaction code to look at data or run a program.

In a new ABAP Cloud project you never use them, and in a classic system ADT can do most of the day-to-day work as well. The
choice between the two is mostly habit and the kind of object, not capability.

== Older material you may meet

Older books and tutorials are written around the Workbench: they teach you to create every program in SE38, every table in
SE11 and every function module in SE37, and they use the classic form of the language. When you read them, expect these
differences from current ABAP.

* Declarations. Older code declares all variables in a block at the top with `DATA`. Newer ABAP lets you write
  inline declarations such as `+DATA(ls_claim)+` where a value first appears, as in the program above.
* Open SQL. Older code writes `+SELECT ... INTO ls_claim+` without the escaping `@` on host variables; the examples
  on this site use the strict form with `@`, as in the program above.
* Function modules and list output. Older material uses function modules for most reusable logic and `WRITE` for output.
  Current practice favours classes and, for user interfaces, Fiori apps over list reports.
* Tools. Older material has no mention of ADT. Development for ABAP Cloud is done in ADT, and classic
  objects can also be edited there, as the ADT page shows.

== Summary

* SE80, SE38, SE11, SE37, SE16, SE24 and SE84 are the classic SAP GUI tools of the ABAP Workbench; SE80 is the hub that
  opens the others.
* They exist in Standard ABAP systems such as S/4HANA on premise and Private Edition, and not in ABAP Cloud.
* Each one has an ADT counterpart: the Project Explorer, the source editor, the dictionary editors, Data Preview, and Open
  Development Object with the where-used list.
* You still meet them when you maintain classic code, follow older instructions or support users, so know what each does.
* New development is written in ADT, with classes and the released APIs of ABAP Cloud.
