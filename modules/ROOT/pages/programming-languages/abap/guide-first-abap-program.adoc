= ABAP Guide: Your First ABAP Program
:description: Step-by-step guide to the local ABAP playground (open-abap 2.14.30): write a class with a run method, start it from a report, transpile and run it, then read and fix your first error message.
:keywords: ABAP, first program, class, method, REPORT, WRITE, START-OF-SELECTION, open-abap, abaplint, transpile, error message, step by step, guide

Checked on 2026-11-13 against open-abap 2.14.30 (the abaplint transpiler and runtime), abaplint 2.120.103 and Node.js 24.21.

== What you build

You write a small ABAP program in two pieces: a class named `zcl_first_program` with a method `run` that prints three lines about
one expense claim, and a report named `zfirst_program` that creates the class and calls `run`. You transpile the sources to
JavaScript, run them on Node.js and read the output. Then you make a deliberate spelling mistake, read the first error message
that the tools print, and fix it.

The playground is open-abap, a community open-source project, not SAP software. It runs only the part of the ABAP language that
it implements, so a program that works here needs a check on a real SAP system before you rely on it there. Output is written
with `WRITE`, the classic list statement; the keyword documentation no longer recommends it for new code, and it is what the
playground offers.

image::sap-abap-guide-first-abap-program-06-result.svg["Terminal with the command npm run run:first followed by the three program lines Claim 1001, Status: New and Amount: 45 EUR",width=900]

== Before you start

* No account is needed: Node.js, the abaplint tools and open-abap install from the public npm registry without signing in. The licences you accept by installing (MIT for the abaplint packages) are listed in the README of the ABAP lab.
* Set up the lab first, with the guide xref:programming-languages/abap/guide-set-up-a-local-abap-playground.adoc[Set Up a Local ABAP Playground]: the folder `abap-lab` with `npm install` done, and an editor such as Visual Studio Code open on it. This guide adds files to its `src` folder.
* The lab already holds the finished files of this guide in `modules/ROOT/examples/abap-lab/src/`. Type them yourself rather than copying them, so that you meet the errors in this guide on your own screen.
* Read xref:programming-languages/abap/programming-concepts-for-newcomers.adoc[Programming Concepts for Newcomers] for the words variable, statement and method, and xref:programming-languages/abap/program-types-and-structure.adoc[Program Types and Structure] for what a report is.
* The figures are drawings of the editor and the terminal, not screenshots. A highlighted box with a number marks the file or line of the step with the same number.

== Steps

An ABAP object in the lab is stored as two files with the same name, the layout of the abapGit project: a `.abap` file with the source and a `.xml` file with the object's attributes (its name, its description and the like). The tools find objects by these file names, so the names matter. A class is `<name>.clas.abap` and `<name>.clas.xml`, and a report is `<name>.prog.abap` and `<name>.prog.xml`.

=== Transpile and run

ABAP does not run on Node.js directly. The transpiler turns every ABAP file of `src` into a JavaScript file in the `output` folder, and Node.js runs the JavaScript file of the report.

[start=4]
. In the terminal, in the `abap-lab` folder, run the script that does both:
+
[source,bash]
----
npm run run:first
----
. Read the output. The transpiler first prints how many files it found in `src` and in the open-abap library (which it fetches once) and how many output files it wrote; the figure shows one example run, and your counts will differ because the lab grows with every guide. The last three lines come from your program:
+
[source,text]
----
Claim 1001
Status: New
Amount: 45 EUR
----
+
The figure leaves out the lines that tell which library version the transpiler cloned.
+
image::sap-abap-guide-first-abap-program-03-transpile-and-run.svg["Terminal after npm run run:first: the transpiler counts its source and library files and reports the output files written (one example run), and the program prints Claim 1001, Status: New and Amount: 45 EUR; callout 4 marks the command and callout 5 marks the three output lines",width=900]

=== Read your first error

Every programmer meets error messages daily. You make one on purpose, in a place where you know the fix.

[start=6]
. Open `src/zcl_first_program.clas.abap` and change the variable in the third `WRITE` statement (line 14) from `amount` to `amont`. Save the file. The name `amont` was never declared, so the program no longer makes sense.
. Run `npm run run:first` again. The transpiler checks the syntax before it translates anything, stops at the first problem and prints one line, and Node.js does not run. The line has four parts: `check_syntax` is the check that failed, `"amont" not found` is what is wrong, `findTop` is an internal detail you can ignore, and `zcl_first_program.clas.abap:14` is the file and the line.
+
image::sap-abap-guide-first-abap-program-04-first-error.svg["Terminal after npm run run:first with a misspelled variable: the transpiler stops with the line Error: check_syntax, amont not found, findTop, zcl_first_program.clas.abap:14 and the program does not run; callout 7 marks the error line",width=900]
. Run `npm run lint` to ask abaplint, the static checker of the lab, about the same file. It reports the same problem with the column as well. The finding reads `file[line, column] - message (rule) [severity]`: line 14, column 24 is where the unknown name starts, `check_syntax` is the rule that found it, and `[E]` means error.
+
[source,bash]
----
npm run lint
----
+
image::sap-abap-guide-first-abap-program-05-lint-finding.svg["Terminal after npm run lint: abaplint prints one finding, src/zcl_first_program.clas.abap at line 14 column 24, the message amont not found, findTop, the rule name check_syntax and the severity E, then 1 issue found in 10 files; callout 8 marks the finding",width=900]
. Change `amont` back to `amount`, save and run `npm run run:first`. The three output lines return, and `npm run lint` reports `0 issue(s) found`.

== Check the result

`npm run run:first` ends without an error and prints the three lines `Claim 1001`, `Status: New` and `Amount: 45 EUR`. `npm run lint` prints `abaplint: 0 issue(s) found, 10 file(s) analyzed`, and `npm test` still passes with the test of the lab's greeter class.

== Variations

* Change the start values (`1001`, `New`, `45`) and run again to see your values in the output.
* Add a fourth `DATA` variable and a fourth `WRITE` line, for example for a currency code.
* Delete the final period of one statement and read how the error message changes.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|`Error: check_syntax, "x" not found, findTop` and no program output
|A name is misspelled or was never declared.
|Open the file and line named at the end of the message and correct the name.

|The old output appears although you changed the code
|You ran `node output/project/zfirst_program.prog.mjs` yourself after a failed transpile. Node.js ran the files of the last successful build.
|Run `npm run run:first`: it runs the program only when the transpile succeeded.

|`Error: Cannot find module` with the path of the report
|The `output` folder does not exist yet, or the report file has a different name.
|Run `npm run run:first`, which transpiles first, and check that the report is named `zfirst_program.prog.abap`.

|`npm run lint` reports nothing for a file you added
|The file is not under `src`, or its name does not end in `.abap`.
|Move it to `src` and keep the name layout `<name>.<type>.abap`.
|===
