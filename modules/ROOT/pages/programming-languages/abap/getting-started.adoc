ABAP is the programming language in which SAP writes its business software, and the language you use to extend it. A program
written in ABAP does not run on your own computer: it runs on an application server that sits between the people using the
software and the database that stores the data. This page explains that three-part layout, what a work process is, and which
SAP products run ABAP today, so that the rest of this section has a place to hang its examples. It is written against
Standard ABAP release 8.16 and ABAP for Cloud Development release 9.20 (2608). Standard ABAP is the full language as it runs
on an SAP S/4HANA on-premise or Private Edition system, where classic features such as reports and `WRITE` output are still
available. ABAP Cloud is the restricted, cloud-ready model used on SAP BTP and in SAP S/4HANA Cloud Public Edition, and it
allows only released APIs. After reading you can name the three tiers, say where your code runs, and tell which examples in
this section need a real SAP system and which run in a free local playground.

== Key terms

* xref:programming-languages/abap/glossary.adoc#application-server[Application server]: the program layer that runs your ABAP code and talks to both the user's screen and the database.
* xref:programming-languages/abap/glossary.adoc#work-process[Work process]: a worker inside the application server that runs your ABAP code when it is given a request.
* xref:programming-languages/abap/glossary.adoc#dispatcher[Dispatcher]: the part of the application server that hands each incoming request to a free work process.
* xref:programming-languages/abap/glossary.adoc#abap-cloud[ABAP Cloud]: the cloud-ready way of writing ABAP that uses only released APIs and can be upgraded safely.
* xref:programming-languages/abap/glossary.adoc#standard-abap[Standard ABAP]: the unrestricted language version of classic ABAP, which covers all elements of the ABAP technology.
* xref:programming-languages/abap/glossary.adoc#abap-development-tools[ABAP Development Tools (ADT)]: the Eclipse-based programming environment in which modern ABAP is written.

== What ABAP is

ABAP is a statement-based language for business applications: it has built-in support for tables of records, amounts,
dates, database access and, in its modern form, classes and interfaces. Your source code is kept as development objects inside
the SAP system itself, not as loose files on your computer. This is the main difference from most languages you may know:
the system is both the place you develop and the place the program runs.

The language exists in two flavours, and you will meet both. Standard ABAP is the unrestricted language version and covers all elements of the ABAP technology. ABAP for Cloud
Development is a restricted language version, and ABAP Cloud is the programming model built on it: you may use only the
repository objects SAP has released for that purpose (released APIs), and development with ABAP Cloud is meant to give
cloud-ready, upgrade-stable solutions. On S/4HANA on premise and Private Edition you can use both. The page xref:programming-languages/abap/abap-language-versions-and-released-apis.adoc[Language Versions and Released APIs] explains the difference in detail.

== The three tiers

An SAP system that runs ABAP is built in three tiers, shown in the diagram below.

[mermaid]
----
flowchart TB
    subgraph T1[Presentation tier]
        FIORI[SAP Fiori in a browser]
        GUI[SAP GUI]
        ADT[ABAP Development Tools in Eclipse]
    end
    subgraph T2[Application tier: application server for ABAP]
        DISP[Dispatcher]
        WP1[Work process]
        WP2[Work process]
        WP3[Work process]
        DISP --> WP1
        DISP --> WP2
        DISP --> WP3
    end
    subgraph T3[Database tier]
        HANA[(SAP HANA database)]
    end
    FIORI --> DISP
    GUI --> DISP
    ADT --> DISP
    WP1 --> HANA
    WP2 --> HANA
    WP3 --> HANA
----

The presentation tier is what people see: SAP Fiori apps in a web browser, the older SAP GUI desktop client, and ADT, the
development tool. None of them runs business logic. They send a request to the application server and show the answer.

The application tier is the application server for ABAP. The ABAP dispatcher distributes the requests it receives to the work
processes. A work process is a worker that runs your ABAP code for a request. The server has several work processes, so
requests from many users can be handled side by side. Work processes come in types: a dialog work process executes the
dialog steps that an active user triggers, and a background work process processes background jobs. Your program reaches the
database from the application server, never from the presentation tier.

The database tier stores the data. In the diagram it is SAP HANA, the database of the S/4HANA products. Modern ABAP lets
the database do as much of the work as it can, using ABAP SQL and CDS views, instead of reading every row into the program.
Later pages of this section return to that idea.

== Your first ABAP class

Modern ABAP programs are written as classes. The smallest useful one implements the interface `IF_OO_ADT_CLASSRUN`, which
lets you run a class from ADT with *Run As > ABAP Application (Console)* (or the F9 key) and see its output in the ADT
console.
The method `+main( )+` receives an output object, and `+out->write( )+` prints whatever you give it. This example requires an
SAP system; not run here, because the playground below has no output class for `IF_OO_ADT_CLASSRUN`.

[source,abap]
----
CLASS zcl_hello DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    INTERFACES if_oo_adt_classrun.
ENDCLASS.

CLASS zcl_hello IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    out->write( 'Hello' ).
  ENDMETHOD.
ENDCLASS.
----

Source: https://github.com/SAP-samples/abap-cheat-sheets/blob/main/19_ABAP_for_Cloud_Development.md[ABAP Cheat Sheet: ABAP for Cloud Development]; running a class: https://github.com/SAP-samples/abap-cheat-sheets/blob/main/README.md[ABAP Cheat Sheets: README]

Read it from the top. `+CLASS ... DEFINITION+` declares the class name and that it is public and cannot be subclassed
(`FINAL`). `INTERFACES` says the class promises to provide the methods of the interface. `+CLASS ... IMPLEMENTATION+` holds
the code, and `METHOD` implements the single method `main` of the interface, whose name is written with a tilde:
`+if_oo_adt_classrun~main+`. Each statement ends with a period, and the string literal `+'Hello'+` is passed to the method.

== Trying ABAP without an SAP system

You do not need an SAP system to learn the language. A free local playground transpiles ABAP to JavaScript with abaplint and
runs it on Node.js, using the open-abap runtime. It needs no account and no sign-in. Many language examples in this section
run there. In a report, output is
written with `WRITE` instead of `+out->write( )+`. This tiny program matches a file of the lab and runs in the local
playground:

[source,abap]
----
REPORT zhello.

WRITE / 'Hello from the local ABAP playground'.
----

Source: https://help.sap.com/docs/abap-cloud/abap-keywords-standard-abap/lists[ABAP Keyword Documentation: Lists]

Some topics cannot run there and need a real SAP system: CDS views, the RAP programming model, ADT itself, and anything
that depends on SAP-delivered objects. The playground also lacks a few statements, such as `+LOOP AT ... GROUP BY+`,
`COLLECT` and SQL aggregate functions, and each page says when an example needs a real system. A page that does so marks its examples "requires an SAP system; not run here".

== Older material you may meet

Many books, blog posts and older systems show ABAP written before release 7.40. Older code declares every variable at the
top of the program with `DATA`, fills internal tables with `APPEND` and `READ TABLE`, and builds text with `CONCATENATE`.
Current ABAP uses inline declarations such as `+DATA(name) = ...+`, constructor expressions such as `VALUE` and `NEW`, string
templates in `+| |+`, and table expressions such as `+itab[ 1 ]+`. Older code is still valid on Standard ABAP and you will
read a lot of it in maintenance work, but ABAP Cloud and new development favour the modern forms. Classic lists written with
`WRITE`, which the keyword documentation no longer recommends, and classic dynpro screens belong to classic ABAP; ABAP Cloud
has no access to SAP GUI and is built on classes and the RAP programming model.

== Summary

* ABAP is SAP's business-application language; your code is stored in and runs inside the SAP system.
* An SAP system has a presentation tier (Fiori, SAP GUI, ADT), an application tier (a dispatcher plus work processes) and a
  database tier (SAP HANA).
* The dispatcher distributes requests to work processes, which run your ABAP code; dialog and background are two types.
* Standard ABAP release 8.16 is documented for S/4HANA 2025 and Private Edition; ABAP for Cloud Development release 9.20
  (2608) is documented for BTP and S/4HANA Cloud Public Edition and allows only released APIs.
* A class that implements `IF_OO_ADT_CLASSRUN` is the simplest way to run code from ADT; many language examples also run in a
  free local playground without an SAP system.
