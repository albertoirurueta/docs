= Regular Expressions
:description: Swift regular expressions -- regex syntax (literals, metacharacters, quantifiers, anchors, character classes, groups, assertions), regex literals and extended delimiters, the Regex type and run-time construction, firstMatch/matches/wholeMatch/contains/replacing/split, typed captures, and the RegexBuilder DSL.
:keywords: Swift, regular expressions, Regex, regex literal, RegexBuilder, typed captures, firstMatch, wholeMatch, replacing, split

include::partial$ai-disclaimer.adoc[]

Swift 5.7 added first-class regular expression support to the language and standard library: regex literals
checked by the compiler, a `Regex<Output>` type whose captures are statically typed, and a result-builder DSL
(`RegexBuilder`) for composing a regex out of named, reusable pieces instead of a single opaque pattern string --
see xref:programming-languages/swift/pattern-matching.adoc[Pattern Matching] for how a `Regex` also participates
in `switch`/`if case` pattern matching via `+~=+`.

== Regex Syntax Refresher

A regex describes a set of strings by combining: *literal characters* (matched as-is); *metacharacters* with
special meaning (`.` any character, `+^+`/`$` start/end anchors); *character classes* (`[abc]`, `[a-z]`, `\d`
digits, `\w` word characters, `\s` whitespace, each negatable as `+[^...]+`/`\D`/`\W`/`\S`); *quantifiers*
(`+*+` zero-or-more, `pass:c[+]` one-or-more, `?` zero-or-one, `+{n,m}+` a repetition range), each greedy by default and
made lazy with a trailing `?` (`+.*?+`); *groups* `+(...)+` for capturing a sub-match, `+(?:...)+` for grouping
without capturing, and `+(?<name>...)+` for a named capture; and *assertions* like `+(?=...)+`/`+(?!...)+` (lookahead)
and `+(?<=...)+`/`+(?<!...)+` (lookbehind) that match a position without consuming characters.

== Regex Literals and the `Regex` Type

[source,swift]
----
let simplePattern = /\d{3}-\d{4}/                         // a regex literal -- checked by the compiler like any expression
let withSlashes = #/https://example\.com/(?<path>.+)/#     // extended literal: #/ ... /# allows literal `/` and `#` inside

let dynamicPattern = "\\d+"
let runtimeRegex = try Regex(dynamicPattern)               // Regex<AnyRegexOutput> -- built from a string at run time
----

A *regex literal* (`/pattern/`) is checked for syntax errors at compile time and typed as `Regex<Output>`, where
`Output` is inferred from the literal's capture groups -- exactly analogous to how a string literal is checked
and typed as `String`. The *extended* delimiter form (`+#/pattern/#+`, with as many leading `+#+` as needed) lets the
pattern itself contain an unescaped `/` or `+#+`, useful for patterns like a URL matcher. Building a `Regex` from a
`String` at run time (`try Regex(pattern)`) is necessary whenever the pattern isn't known until run time (read
from a config file, constructed from user input); it can throw if the string isn't a valid pattern, and its
captures are erased to `AnyRegexOutput` since the compiler cannot inspect a run-time string's groups.

== Matching, Replacing and Splitting

[source,swift]
----
let text = "Order #1234 shipped on 2026-09-01, order #5678 shipped on 2026-09-03"
let orderPattern = /order #(?<id>\d+) shipped on (?<date>\d{4}-\d{2}-\d{2})/.ignoresCase()

if let match = text.firstMatch(of: orderPattern) {
    match.id     // "1234" -- named captures are accessible as properties on the match's output tuple
    match.date   // "2026-09-01"
}

for match in text.matches(of: orderPattern) {
    print("\(match.id) on \(match.date)")
}

let onlyDigits = "12345"
if let whole = try? Regex(#"\d+"#).wholeMatch(in: onlyDigits) {
    print(whole.output)   // matches only if the ENTIRE string matches, unlike firstMatch
}

"hello world".contains(/wor.d/)                                  // true
let redacted = text.replacing(/\d{4}/, with: "****")               // replaces every 4-digit run
let fields = "a,b,,c".split(separator: /,/, omittingEmptySubsequences: false)  // ["a", "b", "", "c"]
----

`firstMatch(of:)` finds the first (leftmost) match anywhere in the string and returns a `Regex<Output>.Match`
whose `.output` (or named-capture properties, as with `match.id`/`match.date` above) exposes the captures with
their inferred static types; `matches(of:)` returns every non-overlapping match as a sequence; `wholeMatch(in:)`
succeeds only if the pattern matches the entire input, not just a substring of it. `+contains(_:)+` is a `Bool`
shortcut for "does a match exist anywhere," and `+replacing(_:with:)+`/`split(separator:)` are regex-aware
overloads of the same-named `String`/`Collection` operations already covered in
xref:programming-languages/swift/strings-and-characters.adoc[Strings and Characters] and
xref:programming-languages/swift/collections.adoc[Collections].

== Typed Captures

[source,swift]
----
let logLine = "2026-09-01 14:32:07 ERROR disk full"
let logPattern = /(\d{4}-\d{2}-\d{2}) (\d{2}:\d{2}:\d{2}) (\w+) (.+)/

if let match = logLine.firstMatch(of: logPattern) {
    let (_, date, time, level, message) = match.output   // (Substring, Substring, Substring, Substring, Substring)
    print("\(level): \(message) at \(date) \(time)")
}
----

Every unnamed capture group in a regex literal widens the match's `.output` tuple by one `Substring` element (the
first element is always the whole match itself), fully typed at compile time -- there is no need to index into
an untyped array of strings the way most regex APIs require, and mismatched group counts or types are caught
before the code ever runs.

== The `RegexBuilder` DSL

[source,swift]
----
import RegexBuilder

let orderRegex = Regex {
    "order #"
    Capture {
        OneOrMore(.digit)
    } transform: { Int($0)! }          // transform lets a capture come out as Int instead of Substring
    " shipped on "
    TryCapture {
        Repeat(count: 4) { .digit }
        "-"
        Repeat(count: 2) { .digit }
        "-"
        Repeat(count: 2) { .digit }
    } transform: { try? Date($0, strategy: .iso8601.year().month().day()) }
}
.ignoresCase()

let choice = Regex {
    ChoiceOf {
        "cat"
        "dog"
        "bird"
    }
}
----

`RegexBuilder` (imported separately from the standard library) builds a `Regex` out of composable pieces using
the same result-builder mechanism as
xref:programming-languages/swift/result-builders.adoc[Result Builders]: `Capture`/`TryCapture` mark a
sub-pattern as a typed capture (optionally with a `transform` closure converting the matched `Substring` into
another type, `Int`/`Date`/anything else, and failing the whole match if `TryCapture`&#39;s transform returns `nil`);
`One`/`OneOrMore`/`ZeroOrMore`/`Repeat` express quantifiers without regex-string counting; and `ChoiceOf`
expresses alternation. The payoff mirrors the one in
xref:programming-languages/swift/result-builders.adoc[Result Builders]: a regex assembled this way is easier to
read, comment, and reuse piece by piece than a single dense pattern string, while still compiling down to the
same `Regex<Output>` engine.

== Worked Example: Parsing Catalogue Lines

The bookshelf catalogue arrives as text lines of the form `Title (Year) by Author`. Parsing it shows the three ways to
write a regex in Swift side by side -- the literal, the `RegexBuilder` DSL and the string-based
`+try Regex("...")+` -- and the main thing they have in common: *the captures are part of the static type*, so a
successful match gives typed values rather than an array of optional substrings.

[source,swift]
----
import RegexBuilder

struct Entry {
    let title: String
    let year: Int
    let author: String
}

let lines = [
    "Dune (1965) by Frank Herbert",
    "Emma (1815) by Jane Austen",
    "not a catalogue line",
    "Kim (1901) by Rudyard Kipling",
]

// 1. A regex literal with named captures; the output type tracks the captures.
let literal = /(?<title>.+) \((?<year>\d{4})\) by (?<author>.+)/
for line in lines {
    if let m = line.wholeMatch(of: literal) {
        print(m.title, m.year, m.author)
    } else {
        print("skip: \(line)")
    }
}

// 2. The same pattern with RegexBuilder; TryCapture converts the year to Int while matching.
let titleRef = Reference(Substring.self)
let yearRef = Reference(Int.self)
let builder = Regex {
    Capture(OneOrMore(.any), as: titleRef)
    " ("
    TryCapture(as: yearRef) { Repeat(.digit, count: 4) } transform: { Int($0) }
    ") by "
    Capture(OneOrMore(.any))
}
let entries: [Entry] = lines.compactMap { line in
    guard let m = line.wholeMatch(of: builder) else { return nil }
    return Entry(title: String(m[titleRef]), year: m[yearRef], author: String(m.3))
}
print(entries.map { "\($0.title)=\($0.year)" })
print(type(of: builder).self)

// 3. replacing and splitting use regexes too.
print("a1b22c333".replacing(/\d+/, with: "#"))
print("2024-05-01".split(separator: /-/))

// 4. A pitfall: matching is by Character, not by Unicode scalar, unless asked.
let accented = "Cafe\u{301}"           // "Café" built from e + combining acute accent
print(accented.count, accented.unicodeScalars.count)
print(accented.contains(/Café/))
print(accented.firstMatch(of: /e/) == nil)
----

[source,text]
----
Dune 1965 Frank Herbert
Emma 1815 Jane Austen
skip: not a catalogue line
Kim 1901 Rudyard Kipling
["Dune=1965", "Emma=1815", "Kim=1901"]
Regex<(Substring, Substring, Int, Substring)>
a#b#c#
["2024", "05", "01"]
4 5
true
true
----

What the program demonstrates:

* *Named captures become properties.* In `m.title`, `m.year` and `m.author` the compiler generated the properties
  from the `+(?<name>...)+` groups, and a typo is a compile error, not a runtime `nil`.
* *The type records the shape.* The builder version prints `Regex<(Substring, Substring, Int, Substring)>`: the
  first element is always the whole match, then one element per capture. The `TryCapture` with a transform changed
  the second capture from `Substring` to `Int` and rejects lines whose year does not convert, so a bad row is a
  non-match instead of a crash later.
* *`wholeMatch` versus `firstMatch`.* `wholeMatch(of:)` requires the entire input to match, which is what you want when
  validating a line; `firstMatch(of:)` and `contains` look for the pattern anywhere, and `prefixMatch(of:)` anchors
  at the start.
* *Matching is Character-aware.* `+Cafe\u{301}+` has four characters but five Unicode scalars, and the regex `Café`
  matches it because comparison uses canonical equivalence, while the lone `e` does not match inside the grapheme
  cluster. Use `.matchingSemantics(.unicodeScalar)` to match scalar by scalar instead.

=== Choosing Between the Forms

[cols="2,3,3",options="header"]
|===
| Form | Strength | Weakness
| Literal `+/.../+` | compact, typed captures, checked at compile time | hard to read when long
| `RegexBuilder` | readable, composable, reusable pieces, typed conversion | verbose for small patterns
| `+try Regex("...")+` | pattern can come from data or the user | captures are `AnyRegexOutput`, errors at run time
|===

=== Pitfalls

* A `Substring` capture keeps the whole original string alive; convert with `+String(...)+` before storing it in a
  long-lived model.
* Greedy quantifiers such as `pass:c[.+]` can match more than you expect: `+Title (1) (2000) by X+` would put `Title (1)` in
  the first capture. Prefer `pass:c[.+?]` or a more specific class when the title may contain parentheses.
* Pathological patterns can backtrack for a very long time on hostile input; do not run user-supplied patterns
  against large strings without a timeout.
