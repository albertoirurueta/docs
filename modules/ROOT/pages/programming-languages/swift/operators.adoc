= Operators
:description: Swift's built-in operators -- assignment, arithmetic and remainder, compound assignment, comparison (including tuple comparison), the ternary conditional operator, nil-coalescing, ranges, logical operators and short-circuiting, explicit parentheses, and the full operator precedence table.
:keywords: Swift, operators, assignment operator, arithmetic operators, remainder operator, compound assignment, comparison operators, tuple comparison, ternary conditional operator, nil-coalescing operator, range operators, logical operators, short-circuit evaluation, operator precedence, associativity

include::partial$ai-disclaimer.adoc[]

Swift's operator set is close to what a C-family language offers, plus range operators purpose-built for
loops and slicing, and every operator's exact precedence is queryable from a single, extensible table rather
than memorized folklore.

== Assignment

[source,swift]
----
let b = 10
var a = 5
a = b                       // a is now 10

let (x, y) = (1, 2)         // assignment also decomposes a tuple into multiple constants
----

Unlike C's, Swift's assignment operator does not itself return a value -- `+if x = y { ... }+` is a compile
error, which rules out the classic `=`-for-`==` typo entirely.

== Arithmetic and Remainder

[source,swift]
----
let sum = 1 + 2            // 3
let difference = 5 - 3     // 2
let product = 3 * 2        // 6
let quotient = 10.0 / 2.5  // 4.0

print("hello, " + "world")  // + is also overloaded for String concatenation

let remainder = 9 % 4       //  1
print(-9 % 4)                // -1 -- result takes the sign of the dividend, matching C's `%`
print(4 % -9)                //  4
print(8.0.truncatingRemainder(dividingBy: 2.5))   // 0.5 -- % has no floating-point overload; use this instead
----

Unary plus (`pass:c[+x]`) is a no-op provided purely for symmetry with unary minus (`-x`); overflow on `pass:c[+]`/`-`/`+*+`/`/`
*traps* by default (a runtime crash), unlike C's silent wraparound -- see the `pass:c[&+]`/`&-`/`+&*+` overflow
operators in xref:programming-languages/swift/advanced-operators.adoc[Advanced Operators] for the opt-in
wrapping versions.

== Compound Assignment

[source,swift]
----
var a = 1
a += 2          // a = a + 2, now 3
a -= 1
a *= 4
a /= 2
----

A compound-assignment operator's result cannot itself be used as a value -- `pass:c[let b = (a += 2)]` does not
compile -- which differs from C's compound assignment.

== Comparison Operators

[source,swift]
----
print(1 == 1)   // true
print(2 != 1)   // true
print(2 > 1)    // true
print(1 < 2)    // true
print(1 >= 1)   // true
print(2 <= 1)   // false

let tuple1 = (1, "zebra")
let tuple2 = (2, "apple")
print(tuple1 < tuple2)      // true -- compares 1 against 2 first; the strings are never reached
print((1, "zebra") < (1, "apple"))   // false -- first elements tie, so the second elements decide
----

Tuples compare *left to right*, element by element, short-circuiting at the first pair that differs; Swift
provides these comparison operators for tuples of up to six elements out of the box, and every element's type
must itself be `Comparable` (or, for `==`/`!=`, `Equatable`).

== The Ternary Conditional Operator

[source,swift]
----
let contentHeight = 40
let hasHeader = true
let rowHeight = hasHeader ? contentHeight + 50 : contentHeight + 20   // 90
----

`question ? answer1 : answer2` is shorthand for a two-branch `if`/`else` that produces a value; exactly one of
`answer1`/`answer2` is evaluated. Nested ternaries read poorly fast -- prefer a plain `if`/`else` expression
(Swift 5.9+) or a `switch` once a condition gets past one level.

== Nil-Coalescing

[source,swift]
----
let defaultColorName = "red"
let userDefinedColorName: String? = nil

let colorNameToUse = userDefinedColorName ?? defaultColorName   // "red"
----

`a ?? b` unwraps `a` if non-nil, otherwise evaluates `b`; it is covered in full, alongside every other way to
work with optionals, in xref:programming-languages/swift/optionals.adoc[Optionals].

== Range Operators

[source,swift]
----
for index in 1...5 { print(index) }        // 1 2 3 4 5 -- closed range, includes both ends

let names = ["Anna", "Alex", "Brian", "Jack"]
for i in 0..<names.count { print(names[i]) }   // half-open range, excludes the upper bound -- the usual array-index range

print(names[2...])          // ["Brian", "Jack"]   -- one-sided range: from index 2 to the end
print(names[...2])          // ["Anna", "Alex", "Brian"]   -- one-sided range: from the start through index 2
print(names[..<2])          // ["Anna", "Alex"]            -- one-sided, half-open

for name in names[1...2] { print(name) }    // one-sided/closed ranges work as subscripts and as sequences alike

print((1...5).contains(3))  // true -- a range is a real value, testable with `contains`
// let backwards = 5...1    // runtime error: a closed range's lower bound must be <= its upper bound
----

A *closed range* (`+a...b+`) includes both endpoints; a *half-open range* (`a..<b`) excludes the upper bound and
is the natural fit for zero-based array indices; a *one-sided range* (`+a...+`, `+...b+`, `..<b`) is a range
Swift infers as far as context allows -- typically "to the end" or "from the start" of a collection.

== Logical Operators

[source,swift]
----
let enteredDoorCode = true
let passedRetinaScan = false

if enteredDoorCode && passedRetinaScan {
    print("Welcome!")
} else {
    print("ACCESS DENIED")               // printed -- && short-circuits, evaluated left to right
}

let hasDoorKey = false
let knowsOverridePassword = true
if hasDoorKey || knowsOverridePassword {
    print("Welcome!")                    // printed -- || also short-circuits
}

print(!enteredDoorCode)                  // false -- logical NOT
----

`&&` and `||` are *short-circuiting*: the right operand is evaluated only if the left one leaves the result
undetermined, which means a right-hand side with a side effect (a function call) may not run at all -- exactly
like C, Java, or JavaScript.

== Explicit Parentheses

[source,swift]
----
let result = 2 + 3 % 4 * 5      // 17, following the precedence table below -- but is that clear at a glance?
let clearer = 2 + ((3 % 4) * 5) // also 17, spelled out
----

Swift lets every operator's precedence resolve an unparenthesized expression unambiguously, but that does not
make it *readable* -- adding parentheses purely for clarity, even where they change nothing, is idiomatic
Swift wherever a mix of operator kinds (bitwise with arithmetic, `??` with comparison, `&&` with `||`) could
make a reader stop and think.

== Precedence and Associativity

Every operator belongs to a *precedence group*, and each group has an explicit relative ordering to every
other group plus its own associativity -- the table below lists the standard library's groups from highest to
lowest:

[cols="2,3,1",options="header"]
|===
| Precedence group | Representative operators | Associativity

| `BitwiseShiftPrecedence`   | `<<` `>>`                                            | none
| `MultiplicationPrecedence` | `+*+` `/` `%` `+&*+` `&`                                 | left
| `AdditionPrecedence`       | `pass:c[+]` `-` `pass:c[&+]` `&-` `\|` `+^+`                           | left
| `RangeFormationPrecedence` | `+...+` `..<`                                          | none
| `CastingPrecedence`        | `is` `as` `as?` `as!`                                | none
| `NilCoalescingPrecedence`  | `??`                                                 | right
| `ComparisonPrecedence`     | `<` `+<=+` `>` `>=` `==` `!=` `===` `!==` `+~=+`         | none
| `LogicalConjunctionPrecedence` | `&&`                                            | left
| `LogicalDisjunctionPrecedence` | `\|\|`                                          | left
| `DefaultPrecedence`        | most custom operators land here if unspecified       | --
| `TernaryPrecedence`        | `?:`                                                 | right
| `AssignmentPrecedence`     | `=` `pass:c[+=]` `-=` `+*=+` `/=`                              | right
|===

[source,swift]
----
infix operator +-: AdditionPrecedence
func +- (left: Int, right: Int) -> Int { left + right - right }
// declares a custom operator explicitly slotted into an existing precedence group
----

A group with associativity *none* cannot be chained without parentheses at all -- `1 < 2 < 3` is a compile
error, unlike a language where comparisons quietly chain or coerce to booleans. Declaring a custom operator's
own `precedencegroup`, with `higherThan`/`lowerThan` relations to existing groups, is covered alongside every
other advanced-operator feature in
xref:programming-languages/swift/advanced-operators.adoc[Advanced Operators].

== Worked Example: Computing an Overdue Fine

Operators are functions with special syntax, and the interesting questions about them are *what gets evaluated, in
which order, and what happens at the edges*. The following program computes an overdue fine for a book (in cents) and
deliberately visits the places where operator behaviour surprises people.

[source,swift]
----
// Fines for overdue books: operators, precedence and their pitfalls in one place.
let daysOverdue = 17
let weeklyFine = 150            // cents
let cap = 1000

// 1. Integer division truncates toward zero; % keeps the sign of the dividend.
print(daysOverdue / 7, daysOverdue % 7, -daysOverdue / 7, -daysOverdue % 7)
print((-daysOverdue).quotientAndRemainder(dividingBy: 7))

// 2. Precedence: multiplication binds tighter than addition; parentheses state intent.
let fine = daysOverdue / 7 * weeklyFine + 50      // ((17 / 7) * 150) + 50
print(fine, daysOverdue / (7 * weeklyFine))

// 3. min and the ternary operator for a capped fine; ?? for defaults.
let waiver: Int? = nil
let payable = min(fine, cap) - (waiver ?? 0)
print(payable, payable > 300 ? "send reminder" : "ok")

// 4. Range operators and ~= in patterns.
let band: String
switch daysOverdue {
case ..<8: band = "grace"
case 8...21: band = "late"
default: band = "severe"
}
print(band, (1...3).contains(2), (1..<3).contains(3))

// 5. Short-circuit evaluation: the right side runs only when needed.
func expensiveCheck() -> Bool { print("  expensive check ran"); return true }
print(daysOverdue < 0 && expensiveCheck())
print(daysOverdue > 0 || expensiveCheck())
print(daysOverdue > 0 && expensiveCheck())

// 6. Overflow is a trap by default; &+ wraps; addingReportingOverflow tells you.
let big = Int8.max
print(big &+ 1, big.addingReportingOverflow(1))
// print(big + 1)        // Fatal error: arithmetic operation overflowed (a run-time trap)

// 7. Floating point: == on computed values, and nan.
let x = 0.1 + 0.2
let notANumber = Double.nan
print(x == 0.3, abs(x - 0.3) < 1e-9, notANumber == notANumber)

// 8. Identity versus equality.
final class Branch { let name: String; init(_ n: String) { name = n } }
let a = Branch("North"), b = Branch("North")
print(a === b, a === a)
----

[source,text]
----
2 3 -2 -3
(quotient: -2, remainder: -3)
350 0
350 send reminder
late true false
false
true
  expensive check ran
true
-128 (partialValue: -128, overflow: true)
false true false
false true
----

* *Integer division truncates toward zero and `%` follows the dividend's sign*: `-17 / 7` is `-2` and `-17 % 7` is `-3`, so
  `pass:c[(a / b) * b + a % b == a]` always holds. `quotientAndRemainder(dividingBy:)` returns both from one operation. There is no
  floored modulo in the standard library.
* *Precedence reads left to right within a level.* `pass:c[17 / 7 * 150 + 50]` is `pass:c[((17 / 7) * 150) + 50 = 350]`, while moving the
  parentheses (`+17 / (7 * 150)+`) gives `0`. When intent is not obvious, add the parentheses.
* *`??` and `?:` replace small `if` statements.* `waiver ?? 0` supplies a default; the ternary picks between two
  values and is an expression, so it can sit inside `print`.
* *Range operators double as patterns.* `..<8` (a partial range) and `+8...21+` are matched with `+~=+` in `switch`.
* *`&&` and `||` short-circuit.* `daysOverdue < 0 && expensiveCheck()` never calls the check; only the last line prints
  `expensive check ran`. That is why a guard such as `index < array.count && array[index] > 0` is safe.
* *Overflow traps by default.* `pass:c[Int8.max + 1]` stops the program with an arithmetic-overflow error. `pass:c[&+]` wraps around to `-128`,
  and `addingReportingOverflow` returns the result together with an overflow flag.
* *Floating-point `==` compares bit patterns.* `pass:c[0.1 + 0.2 == 0.3]` is `false`, and `Double.nan` is not equal to
  itself. Compare with a tolerance, and use `isNaN` to test for not-a-number.
* *`===` is identity, `==` is equality.* Two branches with the same name are different objects.

=== Pitfalls

* Mixing `Int` and `Double` needs an explicit conversion (`+Double(daysOverdue) * rate+`); Swift never converts numeric types
  implicitly.
* Compound assignment (`pass:c[+=]`) has no value, so `pass:c[a = b += 1]` is not allowed, which removes a classic C pitfall.
* The ternary operator is right-associative, but nesting more than one is rarely readable; use `switch`.
* `%` is defined for integers only; for floating point use `truncatingRemainder(dividingBy:)` or `remainder(dividingBy:)`.
