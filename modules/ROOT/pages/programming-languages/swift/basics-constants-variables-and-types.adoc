:keywords: Swift, let, var, constants, variables, type annotation, type inference, print, string interpolation, Int, UInt, Int8, Int16, Int32, Int64, Double, Float, numeric literals, type conversion, typealias, Bool, tuples, assert, precondition, fatalError

Every Swift value has a type, and every name that holds one is declared either a constant or a variable. Those
two facts -- explicit mutability and a value's type -- are the foundation the rest of the language builds on.

== Constants and Variables

`let` declares a *constant*: its value is set once and cannot change. `var` declares a *variable*:

[source,swift]
----
let maximumLoginAttempts = 10
var currentLoginAttempt = 0

currentLoginAttempt += 1
// maximumLoginAttempts += 1   // error: cannot assign to a `let` constant

var x = 0, y = 0, z = 0        // multiple declarations on one line
----

Prefer `let` by default; reach for `var` only when a value genuinely needs to change. The compiler flags a
`var` that is never mutated after its initial assignment as a candidate for `let`.

== Type Annotations and Type Inference

A *type annotation* spells out a name's type explicitly; without one, Swift *infers* the type from the
initial value:

[source,swift]
----
var welcomeMessage: String            // annotation -- no initial value yet
welcomeMessage = "Hello"

var red, green, blue: Double          // one annotation covering three names

let inferredInt = 42                  // inferred as Int
let inferredDouble = 3.14             // inferred as Double
----

A stored constant or variable must have a value before it is read, and (unlike a `var`) a `let` may be
assigned exactly once, at any point before its first use -- it need not be initialized at its declaration.

== Printing and String Interpolation

[source,swift]
----
let name = "Ada"
let attempts = 3

print("Hello, \(name)!")                       // "Hello, Ada!"
print("Attempt \(attempts) of \(attempts * 2)") // expressions are allowed inside \(...)
print(name, attempts, separator: ", ", terminator: "\n")
----

`+print(_:separator:terminator:)+` writes to standard output; `terminator` defaults to a newline and can be set
to `""` to suppress it. String interpolation (`+\(...)+`) is covered in full, including custom
`String(reflecting:)`/`CustomStringConvertible` formatting, in
xref:programming-languages/swift/strings-and-characters.adoc[Strings and Characters].

== Integer Types

Swift ships fixed-width signed and unsigned integer types in 8, 16, 32 and 64-bit sizes, plus `Int`/`UInt`
sized to the platform's native word:

[cols="1,1,2",options="header"]
|===
| Type | Width | Range

| `Int8` / `UInt8`   | 8 bits  | -128...127 / 0...255
| `Int16` / `UInt16` | 16 bits | -32768...32767 / 0...65535
| `Int32` / `UInt32` | 32 bits | ~ ±2.1 x 10^9^ / 0...~4.3 x 10^9^
| `Int64` / `UInt64` | 64 bits | ~ ±9.2 x 10^18^ / 0...~1.8 x 10^19^
| `Int` / `UInt`     | 32 or 64 bits | same as `Int32`/`UInt32` or `Int64`/`UInt64`, matching the platform's native word size
|===

[source,swift]
----
let minValue = UInt8.min      // 0
let maxValue = UInt8.max      // 255

let int8Max = Int8.max        // 127
----

*Use `Int` unless you specifically need a fixed-width or unsigned type* -- for a loop counter, an array
index, or a count, even when the value can never be negative. `Int` is what type inference produces for an
integer literal, it interoperates with every standard-library API without a cast, and its width already
matches the platform's native integer on every current Apple and Linux target. Reach for `UInt` only for a
value that mirrors an unsigned type in an external API, and for a fixed-width type (`Int32`, `UInt8`, ...)
only for on-the-wire formats, bit manipulation, or interop that needs a specific width.

== Floating-Point Types and Choosing Between Them

`Double` (64-bit, at least 15 decimal digits of precision) and `Float` (32-bit, at least 6 decimal digits) are
both IEEE 754 binary floating point. *Prefer `Double`*: it is the type Swift infers for a floating-point
literal, and its extra precision costs little on modern hardware. Reach for `Float` only under real memory or
interop pressure (large buffers of graphics data, an API that requires it).

[source,swift]
----
let pi: Double = 3.14159
let ratio: Float = 1.0 / 3.0

print(0.1 + 0.2 == 0.3)              // false -- binary floating point, same trap as every other language
print(Double.infinity, Double.nan)   // special values exist, as IEEE 754 requires
print(Double.nan == Double.nan)      // false -- compare with .isNaN instead
----

== Numeric Literals

[source,swift]
----
let decimal = 17
let binary = 0b10001          // 17
let octal = 0o21              // 17
let hexadecimal = 0x11        // 17

let hexFloat = 0xC.3p0        // 12.1875 -- hexadecimal floating-point, base-16 mantissa with a required `p` exponent

let paddedDouble = 000123.456
let justOverOneMillion = 1_000_000.000_000_1   // `_` is an ignored separator anywhere in a literal
----

Numeric literals carry no type of their own -- they are inferred from context (`Int` for an integer literal,
`Double` for a floating-point one) unless an annotation or an existing value says otherwise.

== Numeric Type Conversion

Swift never converts numeric types *implicitly*, even between two integer types that could hold every value of
each other -- every conversion is written out with an initializer:

[source,swift]
----
let twoThousand: UInt16 = 2_000
let one: UInt8 = 1
// let twoThousandAndOne = twoThousand + one          // error: UInt16 and UInt8 don't mix
let twoThousandAndOne = twoThousand + UInt16(one)      // explicit conversion

let three = 3
let pointOneFourOneFiveNine = 0.14159
let pi = Double(three) + pointOneFourOneFiveNine       // Int -> Double, also explicit

let integerPi = Int(pi)          // 3 -- Double -> Int truncates toward zero, it does not round
----

This is deliberate: a language with implicit numeric conversions hides overflow and precision-loss bugs behind
innocuous-looking arithmetic; Swift makes every narrowing or cross-type conversion a visible call site.

== Type Aliases

`typealias` gives an existing type an additional name, useful for a domain-specific name or for a long generic
type spelled out repeatedly:

[source,swift]
----
typealias AudioSample = UInt16

var maxAmplitudeFound = AudioSample.min   // 0 -- AudioSample is just another name for UInt16

typealias JSONDictionary = [String: Any]
----

A type alias introduces no new type -- `AudioSample` and `UInt16` are completely interchangeable everywhere,
including in overload resolution.

== Booleans

[source,swift]
----
let orangesAreOrange = true
let turnipsAreDelicious = false

if turnipsAreDelicious {
    print("Mmm, tasty turnips!")
} else {
    print("Eww, turnips are horrible.")
}
----

`Bool` is a genuine, distinct type -- unlike C, `1` and `0` are not interchangeable with `true`/`false`, and
`+if 1 { ... }+` does not compile.

== Tuples

A tuple groups multiple values, of any types, into a single compound value; the individual values need not be
the same type:

[source,swift]
----
let http404Error = (404, "Not Found")            // type is (Int, String)

let (statusCode, statusMessage) = http404Error   // decomposed into two constants
print("The status code is \(statusCode)")
print("The status message is \(statusMessage)")

let (justTheCode, _) = http404Error              // `_` ignores a component you don't need
print("The status code is \(justTheCode)")

print("The status code is \(http404Error.0)")    // access by index...
let http200Status = (statusCode: 200, description: "OK")
print("The status code is \(http200Status.statusCode)")   // ...or by name, when named at creation
----

Tuples are a lightweight way to return multiple values from a function without defining a named type -- see
xref:programming-languages/swift/functions.adoc[Functions] -- and appear again as a pattern-matching target in
xref:programming-languages/swift/pattern-matching.adoc[Pattern Matching].

== Assertions, Preconditions, and Fatal Errors

`assert` and `precondition` both check a condition at run time and stop execution if it is false; they differ
only in when the check runs:

[source,swift]
----
let age = -3

// assert: checked only in debug builds (-Onone); compiled out entirely in -O release builds.
assert(age >= 0, "A person's age cannot be less than zero.")

// precondition: checked in both debug AND release builds -- use it for a violated
// condition that could genuinely corrupt program state if execution continued.
func indexIsValid(_ index: Int, count: Int) -> Bool { index >= 0 && index < count }
func element(at index: Int, in array: [Int]) -> Int {
    precondition(indexIsValid(index, count: array.count), "Index out of range")
    return array[index]
}

// fatalError: unconditionally stops execution, with no check -- for a code path that
// must never be reached, such as an unimplemented `required init` or an exhaustive
// switch's supposedly unreachable default.
func processedValue(for input: Int) -> Int {
    switch input {
    case let n where n >= 0: return n
    default: fatalError("Negative input is not supported by this API")
    }
}
----

Use `assert` for conditions expensive enough that checking them in shipping code is wasteful, `precondition`
for conditions cheap enough (or important enough) to check everywhere, and `fatalError` for a path that
signals a programming error rather than a recoverable one -- none of the three is a substitute for
`throws`/`Result`, which model *expected*, recoverable failure and are covered in
xref:programming-languages/swift/error-handling.adoc[Error Handling].

== Worked Example: The Types in a Loan Record

Swift is *statically typed* but rarely makes you write the types: the compiler infers them from the initial value. The listing
builds a book-loan record out of the basic types and then probes where inference and conversion rules matter.

[source,swift]
----
// A loan record built from Swift's basic types: inference, conversion, ranges and tuples.
let title = "Dune"                         // String, inferred
let pages = 412                            // Int, inferred from the literal
let rating = 4.5                           // Double: floating literals default to Double
let isLent = false                         // Bool
let initial: Character = "D"
let shelfNumber: UInt8 = 200               // an explicit type picks a narrower integer
print(type(of: title), type(of: pages), type(of: rating), type(of: isLent), type(of: initial), type(of: shelfNumber))

// The same literal can become different types depending on context.
let a: Double = 3                          // integer literal used as Double
let b = 3 + 0.5                            // literal 3 becomes Double because of 0.5
print(a, b, type(of: b))

// Numeric types never convert implicitly.
let avgPages = Double(pages) / 3           // convert explicitly
let wholePages = Int(avgPages)             // truncates toward zero
print(avgPages, wholePages, Int(-2.9), Int(2.9.rounded()))

// Initializers that can fail instead of crashing.
print(Int("42") as Any, Int("4x2") as Any, UInt8(exactly: 300) as Any, UInt8(truncatingIfNeeded: 300))

// Integer limits and sizes.
print(Int.max, Int8.min, UInt16.max, MemoryLayout<Int>.size, MemoryLayout<Int8>.size, MemoryLayout<Double>.size)

// Underscores and radix literals make large numbers readable.
let million = 1_000_000
let mask = 0b1111_0000
let colour = 0xFF8800
print(million, mask, colour, 1.5e3, 0x1p4)

// Tuples group values without declaring a type; decompose or access by name.
let record = (title: title, pages: pages, rating: rating)
let (t, p, _) = record
print(record.title, t, p, record.2)

// Type aliases give a domain name to an existing type.
typealias Cents = Int
func fine(days: Int, perDay: Cents = 25) -> Cents { days * perDay }
print(fine(days: 4), type(of: fine(days: 4)))

// let versus var: constants are checked by the compiler.
var counter = 0
counter += 1
let limit = 3
// limit = 4        // error: cannot assign to value: 'limit' is a 'let' constant
print(counter < limit, "\(title) has \(pages) pages (\(Double(pages) / 100) hundreds)")

// Optional is a type too: Int? is not Int.
let maybe: Int? = Int("12")
// let sum = maybe + 1   // error: value of optional type 'Int?' must be unwrapped
print((maybe ?? 0) + 1)
----

[source,text]
----
String Int Double Bool Character UInt8
3.0 3.5 Double
137.33333333333334 137 -2 3
Optional(42) nil nil 44
9223372036854775807 -128 65535 8 1 8
1000000 240 16746496 1500.0 16.0
Dune Dune 412 4.5
100 Int
true Dune has 412 pages (4.12 hundreds)
13
----

* *Inference picks defaults.* An integer literal is an `Int`, a floating literal a `Double`, `+"..."+` a `String` and a quoted single
  character needs an annotation to be a `Character`. The type is fixed at declaration: `title` can never later hold a number.
* *Literals are not typed until context says so.* `let a: Double = 3` makes the integer literal a `Double`; in `pass:c[3 + 0.5]` the
  `0.5` forces both to `Double`. This is the only place numeric types mix without a conversion.
* *Conversions are explicit and honest.* `Double(pages) / 3` is `+137.33...+`; `Int(avgPages)` truncates to 137, `Int(-2.9)` is `-2` and
  `Int(2.9.rounded())` is `3`. `Int("4x2")` and `UInt8(exactly: 300)` return `nil` instead of crashing, whereas
  `UInt8(truncatingIfNeeded: 300)` deliberately keeps the low 8 bits (44).
* *Sizes are known.* `Int` is 8 bytes on a 64-bit platform, `Int8` one byte; the types of the same family trap on overflow
  rather than wrap (see xref:programming-languages/swift/operators.adoc[Operators]).
* *Readable literals.* `1_000_000`, `0b1111_0000`, `0xFF8800` and the hexadecimal float `0x1p4` (16.0) are all just numbers.
* *Tuples and aliases.* `record` is an unnamed structure of three values with labels; destructuring with `+_+` ignores one. A
  `typealias` such as `Cents` documents intent without creating a new type: `type(of: fine(days: 4))` is still `Int`.
* *Optionals are different types.* `Int?` and `Int` do not mix; the commented line is a compile error, which is the point of
  the type system (see xref:programming-languages/swift/optionals.adoc[Optionals]).

=== Pitfalls

* `let` is not "slightly safer `var`&quot;, it is the default: use `var` only when a value really changes, so a reader can trust the rest.
* Avoid `Double` for money; use integer cents (as the `Cents` alias does) or `Decimal` from Foundation.
* `Int` is platform dependent only in size (32 or 64 bit); use a sized type such as `Int32` when the width is part of a file or
  network format.
* Out-of-range integer literals are compile errors (`let x: UInt8 = 300`), but values computed at run time trap.
* A tuple is convenient for a local result; if it crosses an API boundary, give it a name by making a struct.
