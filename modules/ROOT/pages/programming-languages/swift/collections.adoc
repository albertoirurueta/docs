= Collections
:description: Swift's collection types in depth -- Array, Set and Dictionary (creation, access, mutation, iteration, set algebra, hash values), ArraySlice and ranges as collections, the Sequence/Collection protocol family, the higher-order essentials (map, filter, reduce, compactMap, flatMap, sorted, first(where:), contains), lazy, zip, enumerated, stride, and the Swift 6.2 InlineArray and Span types.
:keywords: Swift, Array, Set, Dictionary, ArraySlice, Sequence, Collection, BidirectionalCollection, RandomAccessCollection, MutableCollection, RangeReplaceableCollection, map, filter, reduce, compactMap, flatMap, sorted, lazy, zip, enumerated, stride, InlineArray, Span

include::partial$ai-disclaimer.adoc[]

Swift ships three collection types you reach for constantly -- `Array`, `Set` and `Dictionary` -- built on a
protocol hierarchy that lets a single set of higher-order operations (`map`, `filter`, `reduce`, and the rest)
work identically over all of them, over ranges, and over any type you write yourself.

== `Array`

[source,swift]
----
var shoppingList = ["Eggs", "Milk"]                 // type inferred as [String]
let emptyArray = [Int]()                             // explicit element type, empty
var threeDoubles = Array(repeating: 0.0, count: 3)   // [0.0, 0.0, 0.0]

shoppingList.append("Flour")                          // mutation requires `var`
shoppingList += ["Baking Powder"]
shoppingList.insert("Maple Syrup", at: 0)
shoppingList[1...3] = ["Bananas", "Apples"]            // range subscript replaces a run of elements

print(shoppingList.first ?? "empty", shoppingList.last ?? "empty", shoppingList.count, shoppingList.isEmpty)

let mapleSyrup = shoppingList.remove(at: 0)
for (index, item) in shoppingList.enumerated() {
    print("Item \(index + 1): \(item)")
}
----

Assigning an `Array` to a new `let`/`var`, or passing it to a function, copies it -- as with `String` and every
other Swift collection, that copy is only actually materialized, copy-on-write, the moment either side is
mutated.

== `Set`

[source,swift]
----
var letters = Set<Character>()                        // an empty set of Characters
var favoriteGenres: Set<String> = ["Rock", "Classical", "Hip hop"]   // set literal, type inferred

favoriteGenres.insert("Jazz")
if let removed = favoriteGenres.remove("Rock") { print("\(removed)? Never much cared for it.") }
print(favoriteGenres.contains("Classical"))

let oddDigits: Set = [1, 3, 5, 7, 9]
let evenDigits: Set = [0, 2, 4, 6, 8]
let singleDigitPrimes: Set = [2, 3, 5, 7]

print(oddDigits.union(evenDigits).sorted())                    // all ten digits
print(oddDigits.intersection(evenDigits).sorted())              // []
print(oddDigits.subtracting(singleDigitPrimes).sorted())        // [1, 9]
print(oddDigits.symmetricDifference(singleDigitPrimes).sorted()) // [1, 2, 9]
----

Every `Set` element must conform to `Hashable`, providing a `hashValue`-backed `==` so membership and set-algebra
operations run in roughly constant time instead of scanning; unlike `Array`, a `Set` has no defined order, which
is exactly why it offers union/intersection/subtraction/symmetric-difference instead of index-based mutation.

== `Dictionary`

[source,swift]
----
var namesOfIntegers: [Int: String] = [:]              // empty dictionary literal
namesOfIntegers[16] = "sixteen"

var airports: [String: String] = ["YYZ": "Toronto Pearson", "DUB": "Dublin"]
airports["LHR"] = "London Heathrow"
airports["LHR"] = "London Heathrow Airport"            // updates the existing value
if let oldValue = airports.updateValue("Dublin Airport", forKey: "DUB") {
    print("The old value for DUB was \(oldValue).")
}

if let airportName = airports["DUB"] {                  // subscript access returns an Optional
    print("The name of the airport is \(airportName).")
}
airports["APL"] = nil                                    // assigning nil removes a key-value pair

for (airportCode, airportName) in airports {             // iteration yields (key, value) tuples, order not guaranteed
    print("\(airportCode): \(airportName)")
}
print(Array(airports.keys), Array(airports.values))
----

== Mutability, `ArraySlice`, and Ranges as Collections

[source,swift]
----
let fibonacci = [1, 1, 2, 3, 5, 8, 13]
let middle: ArraySlice<Int> = fibonacci[2...4]          // [2, 3, 5] -- shares fibonacci's storage, no copy yet
print(middle.startIndex, middle.endIndex)                 // 2 5 -- indices are preserved from the original array

let backToArray = Array(middle)                           // convert once you plan to keep the slice around

print((1...5).map { $0 * $0 })                              // ClosedRange is itself a Collection
print((0..<3).reduce(0, +))                                  // 3 -- so is Range
----

`let`/`var` govern collection mutability exactly as with `String`: a `let` array, set, or dictionary cannot be
mutated at all, even element-by-element. `ArraySlice<Element>` is `Array`&#39;s counterpart to `Substring` -- a
non-owning, storage-sharing view meant for short-term use -- and both `Range<Bound>` and `ClosedRange<Bound>`
conform to `Collection` (when `Bound` is a `Strideable` integer type), so the range operators from
xref:programming-languages/swift/operators.adoc[Operators] are themselves usable with every sequence algorithm on
this page.

== The `Sequence`/`Collection` Protocol Family

image::swift-collection-protocol-hierarchy.svg["The Swift collection protocol hierarchy: Sequence at the root, refined by Collection, refined by BidirectionalCollection, refined in turn by RandomAccessCollection, MutableCollection and RangeReplaceableCollection, with Array, Set, Dictionary, Range and ArraySlice placed at the protocols they conform to",width=750,role=text-center]

Each protocol in the chain adds one capability, and conforming types pick up every algorithm written against the
protocols they satisfy for free:

* `Sequence` -- a single-pass walk (`for-in`, `makeIterator()`); no guarantee it can be walked twice.
* `Collection` -- refines `Sequence` with a stable `startIndex`/`endIndex`, subscript access by index, and
  multi-pass iteration.
* `BidirectionalCollection` -- adds `index(before:)`, so it can be walked backwards.
* `RandomAccessCollection` -- adds O(1) index arithmetic (`Array` conforms; a linked-list-backed collection
  typically would not).
* `MutableCollection` -- adds a settable subscript, for in-place element replacement without changing length.
* `RangeReplaceableCollection` -- adds `insert`/`remove`/`append` over arbitrary subranges, changing length.

`Array` conforms to all six; `Set` and `Dictionary` conform only through `Collection` (they have no meaningful
before/after order, so neither is `BidirectionalCollection` nor `RandomAccessCollection`, and neither supports
arbitrary subrange replacement).

== Higher-Order Functions

[source,swift]
----
let numbers = [1, 2, 3, 4, 5, 6, 7, 8]

let doubled = numbers.map { $0 * 2 }                         // [2, 4, 6, 8, 10, 12, 14, 16]
let evens = numbers.filter { $0 % 2 == 0 }                    // [2, 4, 6, 8]
let sum = numbers.reduce(0) { $0 + $1 }                        // 36
let sumShorthand = numbers.reduce(0, +)                         // 36, using an operator as a function value

let strings = ["3", "banana", "-7", "42"]
let parsed = strings.compactMap { Int($0) }                    // [3, -7, 42] -- drops the elements that fail
let nested = [[1, 2], [3, 4], [5]]
let flattened = nested.flatMap { $0 }                            // [1, 2, 3, 4, 5]

let sortedDescending = numbers.sorted(by: >)                     // [8, 7, 6, 5, 4, 3, 2, 1]
let firstEven = numbers.first(where: { $0.isMultiple(of: 2) })   // Optional(2)
print(numbers.contains(where: { $0 > 6 }))                        // true
----

== `lazy`, `zip`, `enumerated`, and `stride`

[source,swift]
----
let names = ["Anna", "Alex", "Brian", "Jack"]
let ages = [61, 32, 25, 43]

for (name, age) in zip(names, ages) {                    // pairs elements until the shorter sequence runs out
    print("\(name) is \(age)")
}

for (index, name) in names.enumerated() {
    print("\(index): \(name)")
}

for value in stride(from: 0, to: 10, by: 2) { print(value) }     // 0 2 4 6 8 -- half-open, like ..<
for value in stride(from: 1, through: 10, by: 3) { print(value) } // 1 4 7 10 -- closed, like ...

let hugeRange = 1...1_000_000
let firstFiveSquares = hugeRange.lazy
    .map { $0 * $0 }
    .filter { $0 % 2 == 0 }
    .prefix(5)                                              // computed on demand, element by element
print(Array(firstFiveSquares))
----

Without `.lazy`, chaining `map`/`filter` over a huge sequence builds a complete intermediate array at every step;
`.lazy` defers each transformation until an element is actually consumed, which is what makes `.prefix(5)` above
touch only as many elements of `hugeRange` as it needs.

== `InlineArray` and `Span` (Swift 6.2)

[source,swift]
----
// InlineArray<count, Element>: a fixed-size, inline-storage array -- no heap allocation, no copy-on-write
// indirection -- useful where a small, statically-sized buffer matters, such as tight numeric code.
let fixed: InlineArray<4, Int> = [1, 2, 3, 4]
print(fixed[0], fixed.count)

// Span<Element>: a non-owning, safe view over contiguous memory -- a memory-safe alternative to
// UnsafeBufferPointer for reading contiguous storage without copying it or taking ownership.
func sum(of values: Span<Int>) -> Int {
    var total = 0
    for i in values.indices { total += values[i] }
    return total
}
----

Both types arrived in the Swift 6.2 standard library as part of an ongoing push for allocation-free,
memory-safe alternatives to heap-backed collections and unsafe pointers; `Span` is covered again alongside its
unsafe-pointer relatives in
xref:programming-languages/swift/memory-safety-and-unsafe-pointers.adoc[Memory Safety and Unsafe Pointers].

== Worked Example: Cataloguing Books With the Three Collections

`Array`, `Set` and `Dictionary` are all generic *value types* with copy-on-write storage, but they answer different
questions: "what is at position n?", "have I seen this?" and "what belongs to this key?". The bookshelf program uses
each for what it is good at and walks into the classic traps on purpose.

[source,swift]
----
struct Book: Hashable { let title: String; let author: String; let year: Int }

let catalogue = [
    Book(title: "Dune", author: "Herbert", year: 1965),
    Book(title: "Emma", author: "Austen", year: 1815),
    Book(title: "Persuasion", author: "Austen", year: 1817),
    Book(title: "Kim", author: "Kipling", year: 1901),
]

// Array: ordered, indexed, amortised O(1) append.
var shelf: [Book] = []
shelf.reserveCapacity(4)
for b in catalogue { shelf.append(b) }
print(shelf.count, shelf.capacity >= 4)

// ArraySlice shares storage and KEEPS the original indices: a classic trap.
let slice = shelf[1...2]
print(slice.startIndex, slice.endIndex, slice.first?.title ?? "-")
// slice[0]   // would trap: index 0 is not in 1..<3
let rebased = Array(slice)
print(rebased[0].title)

// Dictionary: keyed lookup, default values, grouping; iteration order is NOT stable.
var byAuthor: [String: [Book]] = [:]
for b in catalogue { byAuthor[b.author, default: []].append(b) }
for author in byAuthor.keys.sorted() {
    print(author, byAuthor[author]!.map(\.title))
}
let years = Dictionary(uniqueKeysWithValues: catalogue.map { ($0.title, $0.year) })
print(years["Kim"] ?? 0, years["Unknown", default: -1])
let merged = years.merging(["Kim": 1902, "Ulysses": 1922]) { old, new in new }
print(merged.count, merged["Kim"] ?? 0)

// Set: uniqueness and set algebra, O(1) membership.
let reading: Set = ["Dune", "Emma", "Kim"]
let owned: Set = ["Kim", "Persuasion", "Dune"]
print(reading.intersection(owned).sorted(), reading.subtracting(owned).sorted(), reading.symmetricDifference(owned).sorted())
print(reading.isDisjoint(with: ["Ulysses"]), Set([1, 2, 2, 3, 3, 3]).count)

// Copy-on-write: copies are cheap until one of them is modified.
var copy = shelf
copy.removeFirst()
print(shelf.count, copy.count)

// A removal pitfall: modifying while iterating is not possible with value semantics, use removeAll(where:).
shelf.removeAll { $0.year < 1900 }
print(shelf.map(\.title))

// Sort by a total order (author, then year) so that the result is deterministic.
print(catalogue.sorted { ($0.author, $0.year) < ($1.author, $1.year) }.map(\.title))
print(catalogue.max(by: { $0.year < $1.year })?.title ?? "-", catalogue.first(where: { $0.year > 1900 })?.title ?? "-")
----

* *`reserveCapacity` avoids reallocation.* An array grows geometrically, so appending is amortised constant time, but each
  growth copies every element; reserving capacity up front when the size is known skips those copies.
* *A slice keeps the base array's indices.* `+shelf[1...2]+` has `startIndex` 1 and `endIndex` 3, so `slice[0]` would trap even
  though the slice has two elements. Index with `slice.startIndex`, or convert to `Array(slice)` to rebase at zero. A slice
  also keeps the whole base array alive in memory.
* *`default:` makes dictionaries accumulate.* `byAuthor[b.author, default: []].append(b)` creates the list on first use and
  mutates it in place, replacing a read-modify-write dance with optionals. Printing the groups through
  `keys.sorted()` matters: dictionary and set iteration order is unspecified and differs between runs.
* *`Dictionary(uniqueKeysWithValues:)` traps on duplicate keys*; use `+Dictionary(_:uniquingKeysWith:)+` when duplicates are
  possible, and `+merging(_:uniquingKeysWith:)+` to combine two dictionaries (here the new value wins).
* *Sets are for membership and algebra.* `intersection`, `subtracting` and `symmetricDifference` read like the maths they
  mirror, and `contains` is constant time provided the elements hash well.
* *Copies are free until written.* `var copy = shelf` shares storage; `removeFirst` on `copy` triggers the real copy and
  leaves `shelf` at 4 elements.

=== Choosing a Collection

[cols="2,2,3",options="header"]
|===
| Need | Use | Cost to know
| ordered list, positional access | `Array` | insert and remove in the middle shift elements
| fast "is it in there?" | `Set` | elements must be `Hashable`; order is unspecified
| lookup by key | `Dictionary` | keys must be `Hashable`; order is unspecified
| ordered unique items | `Array` plus a `Set` of seen items | the standard library has no ordered set
| fixed small size without heap allocation | `InlineArray` (Swift 6.2) | size is part of the type
|===

=== Pitfalls

* Removing elements inside a `for` loop over the same array is impossible by design (the loop iterates a copy); use
  `removeAll(where:)` or `filter`.
* `array.count` is O(1), but `+array.filter { ... }.count+` allocates a temporary array; use `array.count(where:)` (Swift 6) instead.
* Hashing needs consistent `==` and `hash(into:)`; a type whose hash changes while stored in a `Set` is corrupted there.
* The dictionary subscript returns an optional, and assigning `nil` removes the key rather than storing a nil value.
