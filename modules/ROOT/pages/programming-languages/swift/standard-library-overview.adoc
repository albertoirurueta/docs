:description: A map of the Swift module -- numeric protocols (Numeric, BinaryInteger, FloatingPoint), Equatable/Hashable/Comparable/Identifiable, CustomStringConvertible and friends, ExpressibleBy...Literal, Sequence/Collection and iterators, Optional/Result, ranges and Stride, print/readLine, random numbers, Codable in overview, and Never.

include::partial$ai-disclaimer.adoc[]

The `Swift` module -- imported implicitly into every Swift file -- is where the language's built-in types
(`Int`, `String`, `Array`, `Optional`, ...) and the protocols that give them a common vocabulary actually live.
This page is a map of that module: what the core protocol families are for and how they relate, with detail
pages elsewhere covering the types built on top of them in depth.

== Numeric Protocols

[cols="1,3",options="header"]
|===
| Protocol | What it adds

| `Numeric` | `pass:c[+]`, `-`, `+*+`, a magnitude, and creation from an integer literal -- the floor for anything
  number-like.
| `BinaryInteger` | Integer semantics: division and remainder truncate toward zero, bitwise operators, and
  conversion between integer types.
| `FixedWidthInteger` | Refines `BinaryInteger` with a fixed `bitWidth`, `min`/`max`, and overflow-reporting
  operations -- every concrete integer type (`Int`, `UInt8`, ...) conforms.
| `FloatingPoint` | IEEE 754-style semantics: `NaN`, infinities, rounding rules, `ulp`, and exact
  representability concerns.
| `SignedNumeric` / `SignedInteger` / `UnsignedInteger` | Narrow a generic parameter to only signed, or only
  unsigned, numeric types.
|===

[source,swift]
----
func sum<T: Numeric>(_ values: [T]) -> T {
    values.reduce(0, +)                     // works for Int, Double, Decimal, or any custom Numeric type
}

func isEven<T: BinaryInteger>(_ value: T) -> Bool {
    value % 2 == 0                          // works for any integer type, signed or unsigned
}
----

See xref:programming-languages/swift/advanced-operators.adoc[Advanced Operators] for `BinaryInteger` and
`FixedWidthInteger` used in bit-manipulation code, and
xref:programming-languages/swift/generics.adoc[Generics] for constraining type parameters to protocols in
general.

== `Equatable`, `Hashable`, `Comparable`, `Identifiable`

[cols="1,2,2",options="header"]
|===
| Protocol | Requirement | Typically

| `Equatable` | `+static func == (lhs: Self, rhs: Self) -> Bool+` | Synthesized automatically for structs/enums
  whose members are all `Equatable`.
| `Hashable` | `func hash(into: inout Hasher)`, refines `Equatable` | Synthesized alongside `Equatable`; lets a
  type be a `Set` element or `Dictionary` key.
| `Comparable` | `+static func < (lhs: Self, rhs: Self) -> Bool+`, refines `Equatable` | Unlocks `<`, `+<=+`, `>`,
  `>=`, `sorted()`, and `min`/`max`.
| `Identifiable` | `+var id: ID { get }+` | A stable identity distinct from equality -- two values can be
  `Identifiable`-equal (same `id`) while their contents differ.
|===

[source,swift]
----
struct User: Identifiable, Comparable {
    let id: Int
    var name: String

    static func < (lhs: User, rhs: User) -> Bool {
        lhs.name < rhs.name
    }
}

let users = [User(id: 2, name: "Bo"), User(id: 1, name: "Ada")]
users.sorted()                              // sorted by name, via Comparable
Set(users.map(\.id))                        // Hashable Int ids, not the User itself
----

`Identifiable` is deliberately independent of `Equatable`/`Hashable`: a UI list keyed by `id` can still detect
*content* changes separately by also conforming to `Equatable`.

== `CustomStringConvertible` and Friends

[cols="1,3",options="header"]
|===
| Protocol | Used by

| `CustomStringConvertible` | `String(describing:)`, string interpolation, `print` -- provide `description`.
| `CustomDebugStringConvertible` | `debugPrint`, the debugger's `po` -- provide `debugDescription`, typically
  more detailed.
| `LosslessStringConvertible` | Refines `CustomStringConvertible` and adds `+init?(_ description: String)+` --
  round-trips through a string (`Int`, `Double`, `Bool` all conform).
| `TextOutputStream` / `TextOutputStreamable` | The other direction: a custom destination `print` can write
  into.
|===

[source,swift]
----
struct Point: CustomStringConvertible {
    var x: Double, y: Double
    var description: String { "(\(x), \(y))" }
}

print(Point(x: 1, y: 2))                    // "(1.0, 2.0)" -- print uses `description` automatically
----

== `+ExpressibleBy...Literal+`

A type that conforms to one of these can be constructed directly from a literal in source, with the compiler
inferring which `init` to call:

[source,swift]
----
struct Fraction: ExpressibleByIntegerLiteral {
    var numerator: Int
    var denominator: Int = 1

    init(integerLiteral value: Int) {
        numerator = value
    }
}

let half: Fraction = 1                      // calls init(integerLiteral:) -- no explicit constructor call
----

`ExpressibleByStringLiteral`, `ExpressibleByBooleanLiteral`, `ExpressibleByArrayLiteral`,
`ExpressibleByDictionaryLiteral` and `ExpressibleByNilLiteral` follow the same shape for their respective literal
forms; `Optional`&#39;s conformance to `ExpressibleByNilLiteral` is what makes bare `nil` type-check as any optional
type.

== `Sequence` and `Collection`

`Sequence` requires only `+makeIterator() -> some IteratorProtocol+`, which is enough to support `+for...in+` and
every lazy, one-pass algorithm (`map`, `filter`, `reduce`, ...); `Collection` refines it with random-access
indices (`startIndex`, `endIndex`, `subscript`), letting a value be traversed more than once and indexed
directly. See xref:programming-languages/swift/collections.adoc[Collections] for the concrete `Array`, `Set` and
`Dictionary` types built on these protocols, and
xref:programming-languages/swift/control-flow.adoc[Control Flow] for `+for...in+` over any `Sequence`.

== `Optional` and `Result`

`Optional<Wrapped>` and `Result<Success, Failure>` are ordinary enums in the standard library, not compiler
magic -- `Optional` has cases `none` and `some(Wrapped)`; `Result` has `success(Success)` and
`failure(Failure)`. See xref:programming-languages/swift/optionals.adoc[Optionals] for `Optional` in depth, and
xref:programming-languages/swift/error-handling.adoc[Error Handling] for `Result` alongside `throws`.

== Ranges and `Stride`

[source,swift]
----
let closed = 1...10                         // ClosedRange<Int>
let halfOpen = 1..<10                       // Range<Int>
let partial = 1...                          // PartialRangeFrom<Int>

for value in stride(from: 0, to: 10, by: 2) {   // 0, 2, 4, 6, 8 -- `to` excludes the end
    print(value)
}
for value in stride(from: 10, through: 0, by: -2) {   // 10, 8, ..., 0 -- `through` includes the end
    print(value)
}
----

`Range`/`ClosedRange` model a span between two bounds; `stride(from:to:by:)`/`stride(from:through:by:)` produce a
`Sequence` stepping by an arbitrary amount, which a plain range (whose implicit step is always `1`) cannot
express. See xref:programming-languages/swift/operators.adoc[Operators] for the `+...+`/`..<` range operators
themselves.

== `print`, `readLine` and Random Numbers

[source,swift]
----
print("value:", 42, separator: " ", terminator: "\n")   // configurable separator/terminator
let line = readLine()                       // String?, nil at end-of-input

let roll = Int.random(in: 1...6)
let coin = Bool.random()
let card = ["clubs", "diamonds", "hearts", "spades"].randomElement()   // Element?, nil if empty
----

`Int.random(in:)`, `Double.random(in:)`, `Bool.random()` and `Collection.randomElement()`/`shuffled()` all draw
from the system's default random source; a type conforming to `RandomNumberGenerator` can be passed explicitly
(`+Int.random(in: 1...6, using: &myGenerator)+`) for reproducible sequences in tests.

== `Codable`, in Overview

`Codable` (`Encodable & Decodable`) lets a type convert to and from an external representation such as JSON,
with conformance synthesized automatically when every stored property is itself `Codable`. This page stops at
that overview -- see xref:programming-languages/swift/codable-and-serialization.adoc[Codable and Serialization]
for `CodingKeys`, custom `init(from:)`/`encode(to:)`, and `JSONEncoder`/`JSONDecoder` in depth.

[IMPORTANT]
====
**`UniqueArray` and `Ref` are Swift 6.4-beta only.** `UniqueArray<Element>` is a noncopyable, uniquely-owned
array (no reference-counting overhead, no accidental sharing); `Ref<Value>` is a lightweight, non-atomic
reference wrapper for giving a noncopyable value reference semantics inside a single isolation domain. Neither
has shipped in a stable Swift release as of 6.3; treat both as subject to change until they do.
====

== `Never`

[source,swift]
----
func fatalErrorExample() -> Never {
    fatalError("unreachable")
}

func processOrCrash(_ value: Int?) -> Int {
    guard let value else {
        fatalError("value must not be nil")   // return type Never unifies with Int here
    }
    return value
}
----

`Never` is an enum with no cases, so no value of type `Never` can ever exist; a function returning `Never`
therefore can never return normally -- it must trap, loop forever, or `throw`. The type checker exploits this:
`Never` unifies with any other type, which is why a `guard`/`switch` branch calling a `Never`-returning function
type-checks against whatever the surrounding function actually returns.

== Worked Example: Plugging a Book Type Into the Library

The standard library is mostly a set of *protocols* with generous default implementations: conform to a small core, receive a large
API. The listing makes `Book` a good citizen (`Identifiable`, `Hashable`, `Comparable`, `CustomStringConvertible`, a string literal), builds a
`Countdown` sequence and a `Shelf` collection from their minimal requirements and writes a numeric algorithm once for all numeric types.

[source,swift]
----
struct Book: Identifiable, Hashable, Comparable, CustomStringConvertible, ExpressibleByStringLiteral {
    let id: Int
    let title: String

    // ExpressibleByStringLiteral: "Dune" builds a Book with an id derived from the text.
    init(stringLiteral value: String) { self.init(id: abs(value.hashValue) % 1000, title: value) }
    init(id: Int, title: String) { self.id = id; self.title = title }

    static func < (a: Book, b: Book) -> Bool { a.title < b.title }
    var description: String { "#\(id) \(title)" }
}

// Sequence: a one-pass countdown iterator -- all the default algorithms come for free.
struct Countdown: Sequence, IteratorProtocol {
    var remaining: Int
    mutating func next() -> Int? {
        defer { remaining -= 1 }
        return remaining > 0 ? remaining : nil
    }
}
print(Array(Countdown(remaining: 4)), Countdown(remaining: 5).map { $0 * $0 }, Countdown(remaining: 3).contains(2))

// Collection: add startIndex/endIndex/subscript/index(after:) and gain count, first, indices, slicing, sort, ...
struct Shelf: Collection, ExpressibleByArrayLiteral {
    private var storage: [Book]
    init(arrayLiteral elements: Book...) { storage = elements }

    var startIndex: Int { storage.startIndex }
    var endIndex: Int { storage.endIndex }
    func index(after i: Int) -> Int { storage.index(after: i) }
    subscript(position: Int) -> Book { storage[position] }
}

let shelf: Shelf = [Book(id: 1, title: "Kim"), Book(id: 2, title: "Dune"), Book(id: 3, title: "Emma")]
print(shelf.count, shelf.first!, shelf.sorted().map(\.title), shelf.map(\.id), shelf.dropFirst().count)
print(shelf.firstIndex { $0.title == "Emma" } as Any, shelf[1...2].map(\.title), shelf.isEmpty)

// Hashable gives Set and Dictionary membership; Identifiable gives a stable identity.
let set: Set<Book> = [Book(id: 1, title: "Kim"), Book(id: 1, title: "Kim")]
print(set.count, shelf.map(\.id).reduce(0, +), shelf.max()?.title ?? "-")
let literal: Book = "Anything"
print(literal.title)

// Numeric protocols: write one algorithm for every numeric type.
func sum<T: Numeric>(_ values: [T]) -> T { values.reduce(0, +) }
func average<T: BinaryFloatingPoint>(_ values: [T]) -> T { values.isEmpty ? 0 : sum(values) / T(values.count) }
print(sum([1, 2, 3]), sum([1.5, 2.5]), average([1.0, 2.0, 4.0] as [Float]))

// Result and Optional are plain enums.
let ok: Result<Int, Never> = .success(5)
print(ok, Optional(3).map { $0 * 2 } as Any)

// Never: the type with no values, for functions that cannot return.
func crash(_ message: String) -> Never { fatalError(message) }
let value: Int = Int("7") ?? { crash("not a number") }()
print(value)
----

[source,text]
----
[4, 3, 2, 1] [25, 16, 9, 4, 1] true
3 #1 Kim ["Dune", "Emma", "Kim"] [1, 2, 3] 2
Optional(2) ["Dune", "Emma"] false
1 6 Kim
Anything
6 4.0 2.3333333
success(5) Optional(6)
7
----

* *A `Sequence` needs only `next()`.* `Countdown` is both the sequence and its own iterator; `map`, `contains`, `+Array(_:)+`, `reduce` and the
  rest come from protocol extensions. The `defer` in `next()` decrements after the value is chosen. A sequence may be consumable once: do not
  assume you can iterate it twice unless it is also a `Collection`.
* *A `Collection` adds four requirements:* `startIndex`, `endIndex`, `index(after:)` and a subscript. In return `Shelf` has `count`, `first`,
  `isEmpty`, `firstIndex(where:)`, slicing, `sorted()`, `dropFirst()` and the lazy algorithms, none of which the type wrote.
* *Literals are protocols.* `Shelf` conforms to `ExpressibleByArrayLiteral`, so `[a, b, c]` builds one, and `Book` conforms to
  `ExpressibleByStringLiteral`, so `"Anything"` is a `Book` where one is expected. Use this for types that really are written inline
  (URLs, versions), not as a general shortcut.
* *Equality, hashing and ordering come in a chain.* `Hashable` implies `Equatable`; because `id` and `title` are `Hashable`, the compiler
  synthesises both, which is why two equal books collapse into one set element; `Comparable` needs only `<`.
* *`Numeric` and `BinaryFloatingPoint` abstract over number types.* `sum` works for `Int` and `Double` alike; `average` needs division, so it
  requires a floating-point protocol.
* *`Optional` and `Result` are enums*, as the printed `success(5)` shows, and *`Never`* has no values, so a function returning it cannot
  return; that is why `crash` can stand where an `Int` is expected.

=== Pitfalls

* A `Sequence` that is not a `Collection` may be destructive: calling `makeIterator()` twice can give different results (a stream or a
  generator), so do not iterate it twice.
* If a collection's index is not an `Int`, do not assume `collection[0]` works; use `startIndex`, `+index(_:offsetBy:)+` or iterate.
* Conformances should satisfy the *semantic* requirements, not just compile: `Hashable` requires equal values to have equal hashes, and
  `Comparable` requires a strict total order.
* `hashValue` is randomised per process, so never persist it or use it as an identifier; the listing prints only the title of the
  literal-built book for this reason.
