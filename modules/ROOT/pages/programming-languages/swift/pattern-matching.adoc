= Pattern Matching
:description: Swift's pattern grammar in full -- the eight pattern kinds (wildcard, identifier, value-binding, tuple, enumeration case, optional, type-casting, expression) and where each may appear, nested destructuring, custom ~= overloads, and matching against ranges and regular expressions.
:keywords: Swift, pattern matching, wildcard pattern, identifier pattern, value-binding pattern, tuple pattern, enumeration case pattern, optional pattern, type-casting pattern, expression pattern, tilde equals operator, destructuring, switch, if case, for case, while case, catch

include::partial$ai-disclaimer.adoc[]

A *pattern* is what appears on the left of a `case` (or after `if`/`for`/`while case`, or in a `catch`): a shape
that a value either matches or doesn't, optionally extracting pieces of it into new constants or variables along
the way. Swift defines exactly eight pattern kinds, and the same grammar is shared by every construct that
matches something against a `case`.

== The Eight Pattern Kinds

[source,swift]
----
let point = (2, 0)

switch point {
case _:                            // wildcard pattern -- matches anything, binds nothing
    break
}

switch point {
case let anyPoint:                 // identifier pattern -- matches anything, binds it to a new name
    print(anyPoint)
}

switch point {
case (let x, 0):                   // value-binding pattern -- `let`/`var` inside a larger pattern
    print("on the x-axis at \(x)")
default:
    break
}

switch point {
case (0, 0):                       // tuple pattern -- matches each element position
    print("origin")
default:
    break
}

enum Direction { case north, south, east, west }
let heading = Direction.north
switch heading {
case .north:                       // enumeration case pattern
    print("heading up")
default:
    break
}

let maybeNumber: Int? = 7
switch maybeNumber {
case .some(let number):             // optional pattern (`case let x?` is sugar for this)
    print(number)
case .none:
    print("nothing")
}

let value: Any = 42
switch value {
case is String:                     // type-casting pattern (`is`)
    print("a string")
case let intValue as Int:            // type-casting pattern (`as`), also binds
    print("an Int: \(intValue)")
default:
    break
}

switch 5 {
case 0..<10:                        // expression pattern -- matches via the `~=` operator (here, Range's)
    print("single digit")
default:
    break
}
----

[cols="1,3", options="header"]
|===
| Pattern kind | Where it typically appears

| Wildcard (`+_+`) | anywhere a value is matched but not needed
| Identifier | anywhere -- always matches, just binds a name
| Value-binding (`let`/`var`) | inside a tuple, enum-case, or optional pattern
| Tuple | `switch`, `if case`, `for case`, `while case`
| Enumeration case (`.foo`) | `switch`, `if case`, `for case`, `while case`
| Optional (`x?`) | `switch`, `if case`/`if let`, `for case`, `while case`/`while let`
| Type-casting (`is`/`as`) | `switch`, `if case`, `catch`
| Expression (via `+~=+`) | `switch`, `if case`
|===

== Where Each Pattern May Appear

[source,swift]
----
for case let .some(value) in [1, nil, 3, nil, 5] {     // for case: skips elements that don't match
    print(value)                                          // 1 3 5 -- nil elements are silently skipped
}

var stack = [1, 2, 0, 4]
while case let top? = stack.popLast(), top != 0 {        // while case: loops only while the pattern matches
    print(top)
}

do {
    throw CustomError.timeout(seconds: 30)
} catch CustomError.timeout(let seconds) {                 // catch matches a pattern too, like switch's cases
    print("timed out after \(seconds)s")
} catch {
    print("some other error")
}

enum CustomError: Error { case timeout(seconds: Int) }
----

`switch`, `if case`, `for case`, `while case` and `catch` all match a value against one or more patterns using
the identical grammar above; only `switch` and `catch` require the full set of cases to be exhaustive.

== Nested Destructuring

[source,swift]
----
enum Shape {
    case circle(radius: Double)
    case rectangle(width: Double, height: Double)
}

let shapes: [(String, Shape)] = [("a", .circle(radius: 2)), ("b", .rectangle(width: 3, height: 4))]

for (label, shape) in shapes {
    switch (label, shape) {                                          // patterns nest inside patterns freely
    case let (name, .circle(radius)) where radius > 1:
        print("\(name): a circle bigger than radius 1 (r = \(radius))")
    case let (name, .rectangle(width, height)):
        print("\(name): a \(width)x\(height) rectangle")
    default:
        print("\(label): something else")
    }
}

let points = [(0, 0), (1, 1), (2, 4)]
for case (let x, let y) in points where y == x * x {                  // tuple pattern + where, nested in for case
    print("(\(x), \(y)) lies on y = x^2")
}
----

Any pattern kind can nest inside any other -- a tuple pattern's elements can themselves be enum-case patterns,
which can themselves bind values, all matched and destructured in one `case`.

== Custom `+~=+` Overloads

[source,swift]
----
struct Interval {
    let lowerBound: Int
    let upperBound: Int
}

func ~= (interval: Interval, value: Int) -> Bool {                    // teaches switch how to match `value`
    interval.lowerBound...interval.upperBound ~= value
}

let score = 82
switch score {
case Interval(lowerBound: 90, upperBound: 100): print("A")
case Interval(lowerBound: 80, upperBound: 89): print("B")            // matches via the custom ~= above
default: print("C or below")
}
----

An *expression pattern* matches by calling `+~=(pattern, value)+` and checking whether it returns `true` -- the
standard library already overloads it for `Range`/`ClosedRange` (matching membership) and `Equatable` (matching
`==`), and defining your own overload, as above, lets `switch` accept a custom type as a `case` pattern.

== Matching Against Ranges and Regular Expressions

[source,swift]
----
let bmi = 24.5
switch bmi {
case ..<18.5: print("underweight")
case 18.5..<25: print("healthy weight")                              // range patterns via the built-in `~=`
case 25..<30: print("overweight")
default: print("obese")
}

let line = "error: 42 issues found"
if case let match = try! Regex(#"\d+"#).firstMatch(in: line), let match {
    print("first number: \(line[match.range])")                       // "42"
}

switch "user@example.com" {
case /\w+@\w+\.\w+/:                                                    // a regex literal used directly as a pattern
    print("looks like an email address")
default:
    print("not an email address")
}
----

A range on the left of `case` matches through the same `+~=+` mechanism as any expression pattern; a `Regex` value
or regex literal on the left of `case` matches the same way, via the standard library's `+~=(Regex<Output>,
String)+` overload -- see xref:programming-languages/swift/regular-expressions.adoc[Regular Expressions] for
`Regex` itself, its literal syntax, and capture groups.

== How `switch` Evaluates Its Cases

[mermaid]
....
flowchart TD
    A["switch value {"] --> B["Case 1 pattern"]
    B -->|"matches, and any where clause is true"| M1["Run Case 1's body, then exit the switch"]
    B -->|"no match, or where is false"| C["Case 2 pattern"]
    C -->|"matches"| M2["Run Case 2's body, then exit the switch"]
    C -->|"no match"| D["... remaining cases, in source order"]
    D -->|"none match"| E{"Is a default: case\npresent?"}
    E -->|"yes"| M3["Run default's body"]
    E -->|"no"| F["Compile error: switch must be exhaustive"]

    style M1 fill:#eefaf2,stroke:#2f7d51
    style M2 fill:#eefaf2,stroke:#2f7d51
    style M3 fill:#eefaf2,stroke:#2f7d51
    style F fill:#fdf3f3,stroke:#b5523d
....

Cases are tried strictly top to bottom; the first one whose pattern matches -- and whose `where` clause, if any,
evaluates `true` -- runs, and (without an explicit `fallthrough`) the `switch` exits immediately afterward,
never falling through to a later case the way C's `switch` does by default.

== Worked Example: Reading a Book's Status

Pattern matching shines when data has *shape*: a tuple of an enum and a number, an enum with payloads, an optional inside
a sequence. The bookshelf models a book's lifecycle as an enum with associated values and answers "what should the
desk clerk say?" with one `switch`.

[source,swift]
----
enum Status {
    case onShelf
    case lent(to: String, daysLeft: Int)
    case reserved(by: [String])
    case lost
}

struct Book { let title: String; let pages: Int; var status: Status }

func message(for book: Book) -> String {
    switch (book.status, book.pages) {
    case (.onShelf, let p) where p > 500:
        return "\(book.title): heavy, on the shelf"
    case (.onShelf, _):
        return "\(book.title): available"
    case (.lent(let who, let days), _) where days < 0:
        return "\(book.title): \(who) is \(-days) days overdue"
    case (.lent(to: let who, daysLeft: 0...3), _):
        return "\(book.title): \(who) should return it soon"
    case (.lent(let who, _), _):
        return "\(book.title): lent to \(who)"
    case (.reserved(let names), _) where names.count > 1:
        return "\(book.title): \(names.count) readers waiting, first is \(names[0])"
    case (.reserved(let names), _):
        return "\(book.title): reserved by \(names.first ?? "?")"
    case (.lost, _):
        return "\(book.title): lost"
    }
}

let books = [
    Book(title: "Emma", pages: 474, status: .onShelf),
    Book(title: "War and Peace", pages: 1225, status: .onShelf),
    Book(title: "Kim", pages: 336, status: .lent(to: "Ada", daysLeft: -4)),
    Book(title: "Dune", pages: 412, status: .lent(to: "Linus", daysLeft: 2)),
    Book(title: "Ulysses", pages: 730, status: .lent(to: "Grace", daysLeft: 9)),
    Book(title: "Hamlet", pages: 120, status: .reserved(by: ["Ada", "Grace"])),
    Book(title: "Lolita", pages: 336, status: .lost),
]
books.forEach { print(message(for: $0)) }

// Patterns outside switch: if case, guard case, for case, and optional patterns.
let lentCount = books.filter { if case .lent = $0.status { true } else { false } }.count
print("lent:", lentCount)
for book in books {
    if case .lent(let who, let d) = book.status, d < 5 { print("due soon:", book.title, who) }
}
let statuses = books.map(\.status)
for case .lent(let who, _) in statuses { print("lent to", who) }
let numbers: [Int?] = [1, nil, 3]
for case let n? in numbers { print("value", n) }

// A custom ~= makes your own type usable as a pattern.
struct PageRange { let range: ClosedRange<Int>
    static func ~= (pattern: PageRange, value: Int) -> Bool { pattern.range.contains(value) }
}
let novella = PageRange(range: 1...200), novel = PageRange(range: 201...600)
for pages in [120, 474, 1225] {
    switch pages {
    case novella: print(pages, "novella")
    case novel: print(pages, "novel")
    default: print(pages, "epic")
    }
}
----

----

War and Peace: heavy, on the shelf
Kim: Ada is 4 days overdue
Dune: Linus should return it soon
Ulysses: lent to Grace
Hamlet: 2 readers waiting, first is Ada
Lolita: lost
lent: 3
due soon: Kim Ada
due soon: Dune Linus
lent to Ada
lent to Linus
lent to Grace
value 1

----

* *Tuple patterns match several values at once.* `switch (book.status, book.pages)` lets one case inspect the status and
  the page count together. Cases are tried top to bottom and the first match wins, so the more specific cases (a heavy book
  on the shelf, an overdue loan) come before the general ones.
* *`where` adds a boolean test* to a pattern, after the bindings it uses: `+(.lent(let who, let days), _) where days < 0+`.
* *Value patterns can be ranges.* `+daysLeft: 0...3+` matches through the `+~=+` operator, which is also how a `case` can
  match a `PageRange` struct: defining `+static func ~=+` gives your own type a pattern meaning (the last three lines).
* *The switch is exhaustive.* There is no `default`, and the compiler checked that every combination is covered. Adding a new
  `Status` case makes this function a compile error until it is handled, which is the main reason to prefer enums with
  a `switch` over strings and flags.
* *Patterns work outside `switch`.* `if case`, `guard case`, `for case` and `for case let n?` use the same syntax to match one
  shape without writing a full `switch`.

=== Pitfalls

* Struct and class instances cannot be destructured in a pattern; match on an enum or tuple extracted from them (the loop
  above uses `book.status`), or use `if case` with a field.
* A `case` ordering mistake is silent: a general case placed first makes a later specific case unreachable. The compiler warns
  only for provably dead cases.
* `where` clauses apply to the single `case` pattern they follow; with several comma-separated patterns in one case,
  repeat the `where` for each.
* Binding the same name in several patterns of one case requires the same type in each.
