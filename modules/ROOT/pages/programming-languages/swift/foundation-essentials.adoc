Everything documented so far in this reference belongs to the `Swift` module, available on every platform with
no import beyond the language itself. `Foundation` is a separate, much larger module that layers dates,
networking, the filesystem and other everyday utilities on top -- this page covers the pieces most Swift code
reaches for.

== What Foundation Adds, and `swift-foundation`

Foundation is *not* part of the Swift language or its standard library -- it is ``import``ed explicitly, and
historically was only fully available on Apple platforms via `Foundation`/`CoreFoundation`. The
https://github.com/swiftlang/swift-foundation[`swift-foundation`] project reimplements Foundation's essential
types (`Date`, `Calendar`, `Data`, `URL`, `JSONEncoder`, ...) in pure Swift, so the same behavior now ships
consistently on Linux and other non-Apple platforms too, without the historical gaps between `Foundation` and
its open-source `swift-corelibs-foundation` counterpart. `FoundationEssentials` is the lighter-weight module
`swift-foundation` exposes for code that needs these core types without the rest of Foundation's larger surface
(notifications, `NSObject`-based bridging, and Apple-platform-only APIs).

[source,swift]
----
import Foundation   // the full module: Date, URL, FileManager, URLSession, NotificationCenter, ...
// or, on platforms/targets that only need the essentials:
// import FoundationEssentials
----

== `Date`, `Calendar`, `DateComponents`

[source,swift]
----
let now = Date()                            // an absolute point in time, independent of any calendar or time zone
let later = now.addingTimeInterval(3600)    // one hour later
now.timeIntervalSince(later)                 // -3600

var calendar = Calendar(identifier: .gregorian)
calendar.timeZone = TimeZone(identifier: "Europe/Madrid")!

let components = calendar.dateComponents([.year, .month, .day, .hour], from: now)
components.year                              // e.g. 2026

var startOfNextMonth = DateComponents()
startOfNextMonth.month = 1
let nextMonth = calendar.date(byAdding: startOfNextMonth, to: now)!
----

`Date` is deliberately calendar-agnostic -- just a number of seconds relative to a reference date. Converting a
`Date` to or from year/month/day/hour concepts always goes through a `Calendar` (which calendar system, which
time zone), since "what day is it" is meaningless without both.

== `Date.FormatStyle` and `DateFormatter`

[source,swift]
----
let formatted = now.formatted(.dateTime.year().month(.wide).day().hour().minute())   // "September 13, 2026 at 9:41 AM"
let iso = now.formatted(.iso8601)

let legacyFormatter = DateFormatter()
legacyFormatter.dateStyle = .medium
legacyFormatter.timeStyle = .short
let legacyFormatted = legacyFormatter.string(from: now)
----

`Date.FormatStyle` (`+.formatted(...)+`) is the modern, `Codable`-friendly, locale-aware API, built on the same
`FormatStyle` protocol behind `Measurement`&#39;s and numbers' own `.formatted()`. `DateFormatter` is the older
`NSFormatter`-based API -- still common in existing code and still fully supported, but `Date.FormatStyle` is
preferred for new code.

== `TimeZone`, `Locale`, `Measurement`

[source,swift]
----
let tokyo = TimeZone(identifier: "Asia/Tokyo")!
let spanish = Locale(identifier: "es_ES")

let distance = Measurement(value: 42.195, unit: UnitLength.kilometers)
distance.converted(to: .miles).value         // ~26.22
distance.formatted()                          // locale-aware: "42,195 km" under a comma-decimal locale
----

`TimeZone` and `Locale` parameterize almost every other Foundation date/number API (`Calendar`, `DateFormatter`,
`NumberFormatter`) rather than being consumed directly very often. `Measurement<UnitType>` pairs a numeric value
with a `Dimension` (`UnitLength`, `UnitDuration`, `UnitTemperature`, ...), converting between units and
formatting them without hand-written conversion factors.

== `URL`, `Data`, `FileManager`

[source,swift]
----
let fileURL = URL(filePath: "/tmp/notes.txt")               // file-system URL
let remoteURL = URL(string: "https://example.com/api/users")!

let text = "hello, file"
try text.write(to: fileURL, atomically: true, encoding: .utf8)
let readBack = try String(contentsOf: fileURL, encoding: .utf8)

let bytes: Data = try Data(contentsOf: fileURL)
bytes.count

let fm = FileManager.default
fm.fileExists(atPath: fileURL.path)
try fm.createDirectory(at: fileURL.deletingLastPathComponent(), withIntermediateDirectories: true)
try fm.removeItem(at: fileURL)
----

`URL` represents both remote and local (`file://`) locations uniformly; `Data` is Foundation's byte-buffer type,
bridging to `[UInt8]` where needed. `FileManager` is the entry point for everything else file-system-related:
existence checks, directory creation/traversal, copying, moving, and deleting.

== `URLSession` with `async`/`await`

[source,swift]
----
struct User: Codable {
    var id: Int
    var name: String
}

func fetchUser(id: Int) async throws -> User {
    let url = URL(string: "https://example.com/api/users/\(id)")!
    let (data, response) = try await URLSession.shared.data(from: url)

    guard let httpResponse = response as? HTTPURLResponse, httpResponse.statusCode == 200 else {
        throw URLError(.badServerResponse)
    }
    return try JSONDecoder().decode(User.self, from: data)
}
----

`URLSession.shared.data(from:)`/`data(for:)` are `async` from the start -- no completion-handler bridging
needed -- and pair naturally with `Codable` (see
xref:programming-languages/swift/codable-and-serialization.adoc[Codable and Serialization]) for decoding the
response body, and with
xref:programming-languages/swift/async-await-and-tasks.adoc[Async/Await and Tasks] for the `async`/`await`
mechanics themselves.

== `UUID`, `NotificationCenter`, `NumberFormatter`

[source,swift]
----
let id = UUID()                             // e.g. E621E1F8-C36C-495A-93FC-0C247A3E6E5F
UUID(uuidString: "E621E1F8-C36C-495A-93FC-0C247A3E6E5F")   // parses back, or nil if malformed

NotificationCenter.default.addObserver(forName: .NSSystemClockDidChange, object: nil, queue: .main) { note in
    print("clock changed:", note)
}
NotificationCenter.default.post(name: Notification.Name("MyCustomEvent"), object: nil)

let currency = NumberFormatter()
currency.numberStyle = .currency
currency.locale = Locale(identifier: "en_US")
currency.string(from: 19.99)                  // "$19.99"
----

`UUID` wraps a 128-bit universally-unique identifier with `Codable`/`Hashable`/`CustomStringConvertible`
conformance built in. `NotificationCenter` is Foundation's process-wide publish/subscribe mechanism, predating
Combine and `AsyncSequence` but still widely used, especially for system notifications. `NumberFormatter`
formats numbers as currency, percentages, or spelled-out text, locale-aware exactly like `DateFormatter`.

== Bridging Between Swift and `NS` Types

[source,swift]
----
let swiftString: String = "hello"
let nsString = swiftString as NSString      // toll-free bridged: no copy on Apple platforms

let swiftArray: [Int] = [1, 2, 3]
let nsArray = swiftArray as NSArray          // bridges element-by-element

let swiftDict: [String: Int] = ["a": 1]
let nsDict = swiftDict as NSDictionary
----

`String`/`NSString`, `Array`/`NSArray`, `Dictionary`/`NSDictionary`, and several other pairs are *toll-free
bridged* on Apple platforms -- convertible with `as`, often without copying -- because the Swift standard
library types were designed to interoperate directly with their long-established Foundation counterparts. On
Linux, where the `NS`-prefixed classes are Foundation's own Swift implementations rather than Objective-C
runtime classes, the same `as` conversions still work, but without the toll-free (zero-copy) guarantee.

== Worked Example: Due Dates, Units and URLs

Foundation's value types encode decades of hard-won rules about time, text and addresses. The best advice is to *let them do the arithmetic*.
The program below computes when a book is due and how late it is, formats the date for two locales, converts a weight, builds a URL
with query parameters safely and handles `Data` and `UUID`. It fixes the calendar's time zone to UTC and uses fixed dates so the output is
reproducible; production code uses `Calendar.current` and the user's locale.

[source,swift]
----
import Foundation

// Fixed instants and a fixed time zone keep the output reproducible.
var calendar = Calendar(identifier: .gregorian)
calendar.timeZone = TimeZone(identifier: "UTC")!

let borrowed = calendar.date(from: DateComponents(year: 2026, month: 1, day: 30, hour: 9))!
let dueDate = calendar.date(byAdding: .day, value: 21, to: borrowed)!
let today = calendar.date(from: DateComponents(year: 2026, month: 3, day: 1, hour: 9))!

// Date arithmetic belongs to Calendar, not to seconds.
let late = calendar.dateComponents([.day], from: dueDate, to: today).day ?? 0
print("due:", dueDate.formatted(.iso8601.year().month().day()), "days late:", late)
print(calendar.component(.weekday, from: dueDate), calendar.isDate(borrowed, inSameDayAs: borrowed.addingTimeInterval(3600)))

// One month after Jan 30 is clamped to the end of February, not "Feb 30".
print(calendar.date(byAdding: .month, value: 1, to: borrowed)!.formatted(.iso8601.year().month().day()))

// Formatting with a fixed locale; user-facing text would use the current locale instead.
var style = Date.FormatStyle(date: .long, time: .omitted, locale: Locale(identifier: "en_US"), calendar: calendar, timeZone: calendar.timeZone)
print(dueDate.formatted(style))
style.locale = Locale(identifier: "es_ES")
print(dueDate.formatted(style))

// Measurement and unit conversion.
let weight = Measurement(value: 1.2, unit: UnitMass.kilograms)
print(weight.converted(to: .pounds).formatted(.measurement(width: .abbreviated, usage: .asProvided).locale(Locale(identifier: "en_US"))))

// URLs: parse and build instead of concatenating strings.
var components = URLComponents(string: "https://library.example/api/books")!
components.queryItems = [URLQueryItem(name: "title", value: "War & Peace"), URLQueryItem(name: "page", value: "2")]
print(components.url!.absoluteString)
let url = URL(string: "https://library.example/api/books/42?format=json")!
print(url.host ?? "-", url.pathComponents, url.lastPathComponent, url.query ?? "-")

// Data and UUID.
let bytes = Data("Dune".utf8)
print(bytes.count, bytes.map { String($0, radix: 16) }.joined(), bytes.base64EncodedString())
let id = UUID(uuidString: "E621E1F8-C36C-495A-93FC-0C247A3E6E5F")!
print(id.uuidString.lowercased(), UUID() != UUID())

// Numbers as text, with explicit locale.
let price = 1234.5
print(price.formatted(.number.locale(Locale(identifier: "en_US")).precision(.fractionLength(2))), price.formatted(.currency(code: "EUR").locale(Locale(identifier: "es_ES"))))
----

----
due: 2026-02-20 days late: 9
6 true
2026-02-28
February 20, 2026
20 de febrero de 2026
2.645549 lb
https://library.example/api/books?title=War%20%26%20Peace&page=2
library.example ["/", "api", "books", "42"] 42 format=json
4 44756e65 RHVuZQ==
e621e1f8-c36c-495a-93fc-0c247a3e6e5f true
1,234.50 1234,50 €
----

* *Dates are instants, not calendar days.* A `Date` is a point in time (seconds from a reference date); *which day* it is depends on a
  `Calendar` and a `TimeZone`. That is why the program builds every date through `Calendar` and why adding "21 days" uses
  `calendar.date(byAdding:)` rather than `pass:c[+ 21 * 86400]`: a day is not always 86,400 seconds (daylight-saving transitions).
* *Components arithmetic respects the calendar.* `dateComponents([.day], from:to:)` gave 9 days late, and adding one month to 30 January
  produced 28 February, the clamped end of the shorter month, not an invalid date.
* *Formatting is locale data.* The same `Date.FormatStyle` printed `February 20, 2026` and `20 de febrero de 2026` by changing the locale only; never
  build date strings by hand, and never share the `String` across locales.
* *`Measurement` carries units.* `1.2 kg` converts to `2.645549 lb` with a type-checked unit (`UnitMass`), so a mass and a length
  cannot be added by mistake.
* *`URLComponents` encodes for you.* The ampersand in `War & Peace` became `%26`; string concatenation would have produced a broken query.
  Use `URL` and `URLComponents` instead of strings for anything with structure.
* *`Data` is bytes, `UUID` is an identifier.* `Data("Dune".utf8)` has 4 bytes (`44756e65` in hexadecimal), and `UUID(uuidString:)` parses and
  validates, returning `nil` for a malformed string.

=== Pitfalls

* Creating `DateFormatter` repeatedly is expensive; prefer `Date.FormatStyle` or reuse one formatter, and set `locale` explicitly when parsing fixed
  formats (`en_US_POSIX`).
* Comparing dates with `==` compares instants to sub-second precision; compare with `+calendar.isDate(_:inSameDayAs:)+` or by components when you mean days.
* `Locale.current` and `TimeZone.current` make unit tests non-deterministic; inject them.
* Foundation on Linux and Windows is `swift-foundation` plus `swift-corelibs-foundation`; most of the value types above behave the same, but a
  few Apple-only APIs are missing there.
