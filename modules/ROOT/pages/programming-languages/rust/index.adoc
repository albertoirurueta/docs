This section is written against *Rust 1.99.0*, the current stable release (2026-10-01), and the *2024 edition*, checked
on 2026-10-06. Rust ships a new stable release every six weeks from a train of three channels -- *stable*, *beta* (1.100,
due on 2026-11-12) and *nightly* (1.101) -- and each page notes the release in which a feature appeared, so you can tell
what needs a recent compiler. Nightly-only features are labelled as such where they are mentioned.

== What Rust is

Rust is a compiled, statically typed systems language whose central promise is *memory safety without a garbage
collector*. An ownership system, checked at compile time, decides when every value is freed and rules out dangling
pointers, double frees, iterator invalidation and data races -- with no runtime cost. Around that core, Rust offers an
expressive type system (enums with data, pattern matching, traits and generics), zero-cost abstractions such as iterators
and async/await, a single official toolchain (rustup, Cargo, rustfmt, Clippy, rustdoc, rust-analyzer), and a large package
ecosystem on crates.io. It is used for operating systems and browsers, command-line tools, network services, WebAssembly,
embedded firmware and native extensions for other languages.

== The shelf scenario

The examples across the section share one small, original domain: *shelf*, a Cargo workspace for a library catalogue.

* `shelf-core` is a library crate with `Book`, `Author`, `Isbn` (a validated newtype), `Loan` and `LoanState` types, a
  `Catalog` trait, and an in-memory implementation.
* `shelf` is a command-line binary that searches, lends and returns books and imports and exports JSON.
* `shelf-macros` holds a small derive macro; the FFI, PyO3 and WebAssembly pages wrap `shelf` logic for C, Python and
  JavaScript.

The xref:backend/axum/index.adoc[Axum] section reuses `shelf-core` as the domain layer of its *Bookshelf* web
application, so you can see the same types behind a CLI and behind an HTTP API.
