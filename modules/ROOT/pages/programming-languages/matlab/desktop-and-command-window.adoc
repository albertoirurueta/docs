Written against MATLAB R2026b. The Command Window sessions below were run in GNU Octave 11.3.0 (MATLAB code that Octave also accepts) and the output shown is Octave's; MATLAB prints the same values with slightly different layout, such as `3×1` size headers. The desktop is where you spend most of a first month with MATLAB. This page describes its layout since R2025a, the settings that matter, and the Command Window, which is the interactive prompt at the heart of it. Getting MATLAB is on xref:programming-languages/matlab/getting-started.adoc[Getting Started]; the variables that the Command Window creates are on xref:programming-languages/matlab/workspace-variables-and-mat-files.adoc[Workspace Variables and MAT-Files].

== The desktop since R2025a

When MATLAB starts, the desktop appears in its default layout. The documentation lists the areas of that layout as the *Files panel* (access your files), the *Workspace panel* (explore the data you create or import), the *Command Window* (enter commands at the prompt `>>`) and the *sidebars* (access tools docked in the desktop and additional panels) (https://www.mathworks.com/help/matlab/learn_matlab/desktop.html[MATLAB documentation: Desktop Basics]).

image::matlab-desktop-layout.svg["Schematic of the MATLAB desktop. A toolstrip with a search box on top, the Files panel on the left, the Editor with figures as tabs in the centre, the Workspace panel on the right and the Command Window along the bottom, with sidebars on both sides.",width=720]

The figure is an original schematic, not a screenshot. The arrangement is the default; everything can be moved.

The R2025a release replaced the previous Java-based desktop with a new one. Its release notes describe these changes:

* *Customizable sidebars* on the left, right and bottom. The tools docked there include the Files panel (previously called the Current Folder browser), the Workspace panel and the Command Window. Click a panel's icon on the sidebar to show or hide it, drag its title bar or sidebar icon to move it, and use the _Open more panels_ button for panels that are not open.
* *Themes.* A light or dark theme (and, in the settings, a system-following option) changes the desktop colours: open _Settings_ from the _Home_ tab, then _MATLAB_ > _Appearance_ and set _Desktop Theme_.
* *Search.* The box in the top-right corner finds toolstrip actions, settings and Help Center resources such as functions, examples, answers and videos. Press Ctrl+Shift+Space (Command+Shift+Space on macOS) to reach it from the keyboard; typing `layout` offers the action that restores the default layout.
* *Figures as tabs.* Figures open in the centre of the desktop next to documents, rather than as separate windows.
* *Accessibility.* Screen-reader and keyboard support for the Command Window, the desktop tools, the Editor and the Live Editor.
* *Settings, not preferences.* What used to be called preferences are now *settings*, in a searchable Settings window.

Two compatibility points matter if you used an earlier release: layouts saved before R2025a are not supported, and some tools, such as the Files and Workspace panels, can no longer be undocked into separate windows (undocking the Command Window, the Find Files panel and the Variables editor is still possible). R2026a and R2026b added more flexible layouts: you can move the Files, Workspace, Command History and Project panels to the centre of the desktop, drag panels to reposition them, and show panel title bars only on hover.

Source: https://www.mathworks.com/help/matlab/release-notes.html[MATLAB release notes: R2025a Environment and R2026b Environment], https://www.mathworks.com/help/matlab/matlab_env/change-the-desktop-layout.html[MATLAB documentation: Configure the Desktop]

=== Panels

Besides the Command Window, the Editor, the Files and Workspace panels, the sidebars open further panels depending on what you are doing. The ones this section meets are:

[cols="1,3",options="header"]
|===
|Panel |Used for

|Files
|Browsing and opening the files of the current folder (see xref:programming-languages/matlab/search-path-startup-and-files.adoc[Search Path, Startup and Files]).

|Workspace
|Listing variables, previewing and editing them in the Variables editor.

|Command History
|Browsing, searching and re-running previous statements (https://www.mathworks.com/help/matlab/ref/commandhistory.html[Command History]).

|Stepping through code (see xref:programming-languages/matlab/debugging.adoc[Debugging]).

|Projects and Git integration (see xref:programming-languages/matlab/projects-and-source-control.adoc[Projects and Source Control]).

The Editor edits scripts, functions and classes, with the Code Analyzer underlining problems as you type, and the Live Editor edits live scripts (see xref:programming-languages/matlab/live-scripts-and-the-live-editor.adoc[Live Scripts and the Live Editor]).

=== Settings and where they live

Open the Settings window with the _Settings_ button in the _Environment_ section of the _Home_ tab, or with the command `preferences`. It controls fonts, colours, the initial working folder, the MAT-file version used by `save`, Command Window behaviour and much more. Settings, the layout and other files are stored in a settings folder that `prefdir` returns; settings from up to three preceding releases can be imported when you start a new release.

[source,matlab]
----
prefdir
----

Not run here: the folder differs per machine and operating system.

Source: https://www.mathworks.com/help/matlab/desktop.html[MATLAB documentation: Desktop], https://www.mathworks.com/help/matlab/ref/prefdir.html[MATLAB documentation: prefdir], https://www.mathworks.com/help/matlab/ref/preferences.html[MATLAB documentation: Settings Window]

== Working in the Command Window

=== Entering statements

Type a statement after `>>` and press Enter. MATLAB evaluates it immediately; a statement that creates a variable also adds it to the workspace.

[source,matlab]
----
a = 1
b = 2;
c = a + b
a = 1, b = 2; c = 3
d = cos(a);
sin(a)
ans
----

Octave 11.3.0 output:

[source,text]
----
a = 1
c = 3
a = 1
c = 3
ans = 0.8415
ans = 0.8415
----

Reading this output line by line:

* `a = 1` has no semicolon, so MATLAB prints `a = 1`.
* `b = 2;` ends with a semicolon, which runs the statement and *suppresses* the display. The printed output has no line for `b`.
* `pass:c[c = a + b]` prints `c = 3`.
* On the fourth line, statements are separated by a comma or a semicolon. Statements that end with a comma (or nothing) display their result, so `a = 1` is printed again; `b = 2;` is silent; the last one prints `c = 3`.
* `sin(a)` is an expression whose value is not assigned, so MATLAB stores it in the special variable `ans` ("answer"), and `ans` shows it again. `ans` changes with every command that returns a value that is not assigned to a variable. The assignment `d = cos(a);` does not change `ans`.

The documentation adds that you can enter several statements before running any of them with Shift+Enter between lines (not needed for paired keywords such as `for` and `end`), that Esc clears the current line without running it, and that you can select part of the code at the prompt and press Enter to run only that part.

Source: https://www.mathworks.com/help/matlab/matlab_env/enter-statements-in-command-window.html[MATLAB documentation: Enter Statements in Command Window]

[source,matlab]
----
A = magic(5), B = ones(5) * 4.7; C = A./B
----

Octave 11.3.0 output:

[source,text]
----
A =

   17   24    1    8   15
   23    5    7   14   16
    4    6   13   20   22
   10   12   19   21    3
   11   18   25    2    9

C =

   3.6170   5.1064   0.2128   1.7021   3.1915
   4.8936   1.0638   1.4894   2.9787   3.4043
   0.8511   1.2766   2.7660   4.2553   4.6809
   2.1277   2.5532   4.0426   4.4681   0.6383
   2.3404   3.8298   5.3191   0.4255   1.9149

----

Only `A` and `C` are displayed, because `B` ended with a semicolon.

Source: https://www.mathworks.com/help/matlab/matlab_env/enter-statements-in-command-window.html[MATLAB documentation: Enter Statements in Command Window]

=== Command syntax and function syntax

A statement such as `format long` is written in *command syntax*: the command name followed by words without parentheses or quotes. It is equivalent to the function call `format("long")`. Command syntax works only when you are not requesting an output and the arguments are plain words. xref:programming-languages/matlab/syntax-statements-and-variables.adoc[Syntax, Statements and Variables] explains the rules and the traps (`hold on` and `hold("on")` are the same call; `x = hold on` is an error).

Source: https://www.mathworks.com/help/matlab/matlab_prog/command-vs-function-syntax.html[MATLAB documentation: Choose Command Syntax or Function Syntax]

=== Recalling and completing commands

* The up and down arrows recall previous statements. If you type the first letters of a statement first, the arrows recall only those that begin with the same letters.
* The Command History panel lists what you ran, across sessions, and re-runs or copies statements.
* Tab completion completes function and variable names and file names after you type a few characters, and a *function hint* appears when you pause after typing the opening parenthesis of a call (see xref:programming-languages/matlab/getting-help-and-documentation.adoc[Getting Help and Documentation]).
* `clc` clears the text in the Command Window; it does not touch the workspace. To clear variables, see `clear`.

[source,matlab]
----
clc
----

Not run here (it clears the screen and has no printed result).

Source: https://www.mathworks.com/help/matlab/ref/clc.html[MATLAB documentation: clc]

=== Display format: `format`

`format` changes how numbers are displayed. It does not change how they are computed or stored.

[source,matlab]
----
x = 0.1 + 0.2;
format long
x
format short
x
----

Octave 11.3.0 output:

[source,text]
----
x = 0.300000000000000
x = 0.3000
----

MATLAB's own documentation shows `format long` printing `pi` as `3.141592653589793`, so a double is displayed with 15 significant digits and a single with fewer. The styles named by the reference page include `short` (the default, 5 significant digits), `long`, `shortE` and `longE` (scientific notation), `shortG` and `longG` (the more compact of fixed-point and scientific notation), `shortEng` and `longEng` (engineering notation with exponents that are multiples of 3), `hex`, `bank`, `rat` and `pass:c[+]`. `format compact` and `format loose` control blank lines (the default is `loose`); `format` with no arguments restores the default. Since R2021a, `fmt = format` returns the current style and `fmt = format(style)` returns the previous one while setting the new one, which lets a function restore the format afterwards:

[source,matlab]
----
oldFormat = format("longG");
disp(pi)
format(oldFormat)
----

Not run here (the `format` output forms are R2021a and later; Octave's `format` does not return a value). The style `shortG` is documented as displaying numeric values in a compact form with 5 total digits.

Source: https://www.mathworks.com/help/matlab/ref/format.html[MATLAB documentation: format], https://www.mathworks.com/help/matlab/matlab_prog/display-format-for-numeric-values.html[MATLAB documentation: Display Format for Numeric Values]

=== Showing values: `disp`, `display` and implicit display

Omitting the semicolon displays a variable as `name = value`. The function `disp` displays only the value, without the name, and is the usual choice inside functions:

[source,matlab]
----
disp(pi)
disp([1 2 3])
disp("heatflow")
----

Octave 11.3.0 output:

[source,text]
----
3.1416
   1   2   3
heatflow
----

Implicit display (no semicolon) is a call to the function `display`, which MATLAB calls for you and which classes can customise (see xref:programming-languages/matlab/properties-and-methods.adoc[Properties and Methods]). `fprintf` and `sprintf` give full control over the text (see xref:programming-languages/matlab/strings-and-character-arrays.adoc[Strings and Character Arrays]).

Source: https://www.mathworks.com/help/matlab/ref/disp.html[MATLAB documentation: disp]

=== Markdown and ANSI styling (R2026b)

R2026b can render text styled with Markdown and with ANSI escape codes directly in the Command Window.

* `markdowndisp(textToRender)` renders Markdown (bold, italic, strikethrough, headings, bulleted lists, tables, and LaTeX equations between dollar signs) in the Command Window or the Live Editor.
* The Command Window renders ANSI escape codes for bold, underlined, italic and strikethrough text and for foreground and background colours, when the text is displayed with `fprintf`, `sprintf` or `compose`.

[source,matlab]
----
markdowndisp("**Plate ready:** 5 sensors")
----

Not run here: `markdowndisp` is new in R2026b, so earlier releases (and Octave) have no such function. The documentation example is the same pattern, a string with `+**bold text**+` and `+~~strikethrough text~~+`.

Source: https://www.mathworks.com/help/matlab/ref/markdowndisp.html[MATLAB documentation: markdowndisp], https://www.mathworks.com/help/matlab/release-notes.html[MATLAB release notes: R2026b Environment]

=== Logging a session: `diary`

`diary` records the commands you type and the text output into a file, which is handy for keeping a record of an exploration.

[source,matlab]
----
diary heatflow_log.txt
y = 3*4
diary off
type heatflow_log.txt
----

Not run here as written: MATLAB's `diary` writes a UTF-8 text file named `diary` in the current folder if you give no name, appends if the file exists, and also captures keyboard input. Octave's diary captures output only. `diary off` stops logging and `diary on` resumes it; `get(0,"Diary")` returns `"on"` or `"off"`. Switch logging off before opening the file so that the log is complete. If the name has no folder part, the path is resolved against the current folder every time logging is enabled, so a changed current folder can send the log to a different file.

Source: https://www.mathworks.com/help/matlab/ref/diary.html[MATLAB documentation: diary]

== Pitfalls

* *Forgetting the semicolon on large arrays* floods the window. R2026b truncates the display of very large matrices in the Command Window, but a semicolon is still the habit to build.
* *`ans` is overwritten* by every unassigned result, so do not rely on it in scripts; name results.
* *`clc` is not `clear`.* `clc` only clears the text on screen.
* *`format long` hides nothing, but it also does not make computations more precise.* It changes only the display.
* *Layouts saved before R2025a* cannot be loaded; reset with the search box and the `layout` action.

== Where older books differ

Books for MATLAB 7 show a desktop with docked Command Window, Command History and Current Folder windows, a Start button, and preferences dialogs. The Current Folder window is today's *Files panel*, "preferences" are *settings*, and the Help browser has been replaced by the web documentation. The Command Window statements shown in those books are still valid.
