== Declarations, Overloading, and Default Arguments

[source,cpp]
----
int add(int a, int b);
double add(double a, double b);        // overload: same name, different parameter types
int add(int a, int b, int c = 0);      // default argument -- callable as add(1, 2) or add(1, 2, 3)

// int add(int a, int b);              // error if both existed: return type alone cannot distinguish overloads
----

Overload resolution picks the *best viable match* by implicit-conversion ranking (exact match > promotion >
standard conversion > user-defined conversion); an ambiguous call is a compile error, never a silent guess.

== Defaulted and Deleted Functions

[source,cpp]
----
class NonCopyable {
public:
    NonCopyable() = default;                          // ask the compiler for its usual implementation
    NonCopyable(const NonCopyable&) = delete;           // forbid copying entirely -- a compile error, not UB
    NonCopyable& operator=(const NonCopyable&) = delete;
    NonCopyable(NonCopyable&&) = default;                // moving is still allowed
    NonCopyable& operator=(NonCopyable&&) = default;
};

void onlyIntegers(int) {}
template <typename T> void onlyIntegers(T) = delete;   // = delete also blocks a whole overload set for other T
----

See xref:programming-languages/cpp/classes-and-objects.adoc[Classes and Objects] for how `= default`/`= delete`
interact with the rule of zero/three/five.

== Lambdas

[source,cpp]
----
#include <vector>
#include <algorithm>
#include <iostream>

int main() {
    auto square = [](int x) { return x * x; };          // no captures
    int factor = 3;
    auto scale = [factor](int x) { return x * factor; };  // capture by value (a snapshot at creation)
    auto scaleRef = [&factor](int x) { return x * factor; }; // capture by reference (sees later changes)
    auto captureAll = [=]() { return factor; };            // capture everything used, by value
    auto captureAllRef = [&]() { factor++; };               // capture everything used, by reference

    std::vector<int> v = {5, 3, 1, 4, 2};
    std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // descending
    for (int x : v) std::cout << x << ' ';

    auto generic = [](auto a, auto b) { return a + b; };    // generic lambda (C++14): implicitly a template
    std::cout << generic(1, 2) << generic(1.5, 2.5) << '\n';

    auto templated = []<typename T>(std::vector<T> const& vec) { return vec.size(); }; // template lambda (C++20)
    std::cout << templated(v) << '\n';

    (void)square; (void)scale; (void)scaleRef; (void)captureAll; (void)captureAllRef;
}
----

=== Recursive Lambdas

A lambda cannot name itself directly, but {cpp}23's *deducing this* lets it take a self-parameter:

[source,cpp]
----
auto factorial = [](this auto self, int n) -> int {
    return n <= 1 ? 1 : n * self(n - 1);
};
static_assert(factorial(5) == 120);
----

Before {cpp}23, the usual workarounds were `std::function` with a captured reference to itself, or
`std::function` passed by reference into the lambda's own capture list.

== `std::function`, `std::invoke`, and Function Composition

[source,cpp]
----
#include <functional>
#include <iostream>

int addTwo(int x) { return x + 2; }

struct Multiplier {
    int factor;
    int operator()(int x) const { return x * factor; }
};

int main() {
    std::function<int(int)> f = addTwo;      // type-erased callable: functions, lambdas, functors all fit
    f = [](int x) { return x * 10; };
    std::cout << f(5) << '\n';                // 50

    Multiplier times3{3};
    std::cout << std::invoke(times3, 5) << '\n';   // 15 -- std::invoke handles callables uniformly, including
                                                     // member function pointers and pointers-to-member-data

    auto compose = [](auto g, auto h) {
        return [g, h](auto x) { return g(h(x)); };
    };
    auto addThenDouble = compose([](int x) { return x * 2; }, addTwo);
    std::cout << addThenDouble(3) << '\n';     // (3+2)*2 = 10
}
----

Higher-order functions -- functions taking or returning other functions, like `compose` above, or the
map/fold-style algorithms in xref:programming-languages/cpp/iterators-and-algorithms.adoc[Iterators and
Algorithms] -- are idiomatic in modern {cpp} thanks to lambdas and templates.

== `noexcept` and `+[[nodiscard]]+`

[source,cpp]
----
void mayThrow();
void neverThrows() noexcept;              // promises not to throw; std::terminate if it does anyway

template <typename T>
void swapValues(T& a, T& b) noexcept(noexcept(std::swap(a, b)))   // conditional noexcept
{
    using std::swap;
    swap(a, b);
}

[[nodiscard]] int computeChecksum(int data);   // ignoring the return value is now a compiler warning
----

`noexcept` functions let containers like `std::vector` choose to *move* elements on reallocation instead of
copying them (see xref:programming-languages/cpp/move-semantics-and-value-categories.adoc[Move Semantics and Value
Categories]) -- the strong exception-safety guarantee otherwise requires a fallback to copying.

== What a Lambda Really Is

A lambda expression is shorthand for a class: the compiler generates an unnamed *closure type* with one data member
per captured variable and a `const operator()` holding the body. Seeing the equivalent hand-written class removes
most of the mystery around captures, `mutable` and size.

[mermaid]
....
flowchart LR
    L["[threshold](const Book&amp; b)<br/>{ return b.copies >= threshold; }"] -->|"compiler generates"| C["closure class<br/>int threshold_ (the capture)<br/>bool operator()(const Book&amp;) const"]
    C -->|"instance"| O["closure object<br/>sizeof == sizeof(int)"]
    O -->|"stored in"| F["auto variable: exact type, no allocation"]
    O -->|"or type-erased into"| SF["std::function: heap allocation possible,<br/>virtual-style call"]
....

.lambdas.cpp
[source,cpp]
----
#include <algorithm>
#include <format>
#include <functional>
#include <print>
#include <string>
#include <vector>

struct Book {
    std::string title;
    int year;
    int copies;
};

// What the compiler generates for [threshold](const Book& b) { return b.copies >= threshold; }
class AtLeast {
    int threshold_;
public:
    explicit AtLeast(int t) : threshold_(t) {}
    bool operator()(const Book& b) const { return b.copies >= threshold_; }
};

std::function<bool(const Book&)> make_filter(int min_year) {
    return [min_year](const Book& b) { return b.year >= min_year; };   // captures by value: safe to return
}

int main() {
    std::vector<Book> shelf{{"Dune", 1965, 2}, {"Emma", 1815, 0}, {"Neuromancer", 1984, 5}};

    int threshold = 2;
    auto lambda = [threshold](const Book& b) { return b.copies >= threshold; };
    AtLeast manual{threshold};
    std::println("lambda finds {}, hand-written functor finds {}", std::ranges::count_if(shelf, lambda),
                 std::ranges::count_if(shelf, manual));
    std::println("sizeof(lambda) = {} (one captured int), sizeof(captureless) = {}", sizeof(lambda),
                 sizeof([](int x) { return x; }));

    // Capture by reference sees later changes; capture by value froze the old value.
    int counter = 0;
    auto by_ref = [&counter] { return ++counter; };
    auto by_val = [counter]() mutable { return ++counter; };   // mutable: modifies its own copy
    by_ref(); by_ref(); by_val();
    std::println("counter = {}, the by-value copy counted separately", counter);

    // Generic lambda: a template in disguise.
    auto describe = [](const auto& x) { return std::format("[{}]", x); };
    std::println("{} {}", describe(42), describe(std::string("Dune")));

    // std::function type-erases: flexible, but larger than the lambda it holds and may allocate.
    std::function<bool(const Book&)> f = make_filter(1900);
    std::println("sizeof(std::function) = {}", sizeof(f));
    auto modern = std::ranges::count_if(shelf, f);
    std::println("books since 1900: {}", modern);

    // Recursive lambda with C++23 deducing this.
    auto fact = [](this auto self, int n) -> long { return n <= 1 ? 1 : n * self(n - 1); };
    std::println("10! = {}", fact(10));
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra lambdas.cpp -o lambdas
$ ./lambdas
lambda finds 2, hand-written functor finds 2
sizeof(lambda) = 4 (one captured int), sizeof(captureless) = 1
counter = 2, the by-value copy counted separately
[42] [Dune]
sizeof(std::function) = 32
books since 1900: 2
10! = 3628800
----

* A lambda with one captured `int` is four bytes; a captureless one is a one-byte empty class, and can convert to a
  plain function pointer. `std::function` is 32 bytes on this library whatever it holds, and stores callables
  larger than its small buffer on the heap, so prefer a template parameter or `auto` in hot paths and reserve
  `std::function` for places that must store callables of different types behind one type.
* A by-value capture is copied once, when the lambda is created; `mutable` lets the call change *that copy*, which is
  why the by-value counter in the output is not reflected in `counter`.
* A by-reference capture does not extend the lifetime of what it refers to. Returning `+[&]{ ... }+` from a function
  that captures a local gives a closure holding a dangling reference; `make_filter` above captures `min_year` by
  value for exactly this reason. In a lambda stored beyond the current scope, capture by value or move into the
  closure with an init-capture (`[b = std::move(book)]`).
* Generic lambdas (`auto` parameters) have a templated `operator()`, so each distinct argument type instantiates a
  separate function.
* Since {cpp}23 a lambda can take an explicit object parameter, `this auto self`, which is how the recursive
  factorial above names itself without `std::function`.
