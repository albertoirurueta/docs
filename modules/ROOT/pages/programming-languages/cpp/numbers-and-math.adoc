== Floating-Point Pitfalls

IEEE-754 floating point cannot represent most decimal fractions exactly, so direct equality comparison is
almost always wrong:

[source,cpp]
----
#include <cmath>
#include <cassert>

int main() {
    double a = 0.1 + 0.2;
    assert(a != 0.3);                              // true! 0.1+0.2 is 0.30000000000000004...
    assert(std::abs(a - 0.3) < 1e-9);               // compare within a tolerance instead
    return 0;
}
----

Other pitfalls: `NaN` compares unequal to *everything*, including itself (`std::isnan(x)` is the only reliable
test); accumulating many small floating-point additions loses precision (prefer `std::accumulate` with a wider
accumulator type, or a compensated-summation algorithm like Kahan summation, for long reductions).

== `<cmath>`

[source,cpp]
----
#include <cmath>
#include <cassert>

int main() {
    assert(std::sqrt(16.0) == 4.0);
    assert(std::pow(2.0, 10.0) == 1024.0);
    assert(std::abs(-5) == 5);
    assert(std::floor(3.7) == 3.0);
    assert(std::ceil(3.2) == 4.0);
    assert(std::round(3.5) == 4.0);
    assert(std::isnan(std::sqrt(-1.0)));
    assert(!std::isfinite(1.0 / 0.0));    // infinity
    return 0;
}
----

== `<numbers>`

{cpp}20's `<numbers>` replaces hand-copied constants like `+#define M_PI+` with type-generic, `constexpr` values:

[source,cpp]
----
#include <numbers>
#include <iostream>

int main() {
    std::cout << std::numbers::pi << '\n';         // double, by default
    std::cout << std::numbers::pi_v<float> << '\n'; // explicit precision
    std::cout << std::numbers::e << '\n';
    std::cout << std::numbers::sqrt2 << '\n';
}
----

== `<random>`: Engines, Distributions, and Seeding

`<random>` separates the *engine* (a source of uniformly distributed bits) from the *distribution* (how those
bits are shaped into a useful range) -- never use `rand()`/`srand()` in new code, they are low-quality and their
period/distribution are unspecified:

[source,cpp]
----
#include <random>
#include <iostream>

int main() {
    std::random_device rd;                    // a (usually hardware) source of non-deterministic entropy
    std::mt19937 engine(rd());                 // Mersenne Twister, seeded from rd() -- fast, good statistical
                                                // quality, NOT cryptographically secure
    std::uniform_int_distribution<int> dice(1, 6);
    std::cout << dice(engine) << '\n';          // a uniformly distributed integer in [1, 6]

    std::mt19937 reproducible(42);              // a fixed seed -- makes the sequence reproducible for tests
    std::normal_distribution<double> heights(170.0, 10.0);   // mean, stddev
    std::cout << heights(reproducible) << '\n';
}
----

Reseeding the *same* `mt19937` with a fixed integer literal, as `reproducible` does above, is exactly how to
make a randomized test deterministic without giving up the same distribution shape used in production.

== `<bit>` and `std::bitset`

`<bit>`&#39;s free functions (covered in
xref:programming-languages/cpp/operators-and-expressions.adoc[Operators and Expressions]) operate on plain
unsigned integers; `std::bitset<N>` is a fixed-size, indexable, printable bit sequence:

[source,cpp]
----
#include <bitset>
#include <iostream>

int main() {
    std::bitset<8> flags(0b0010'1100);
    flags.set(0);              // turn bit 0 on
    flags.flip(1);              // toggle bit 1
    std::cout << flags << '\n';           // prints as "00101111"
    std::cout << flags.count() << '\n';    // number of set bits -- 5
    std::cout << flags.to_ulong() << '\n'; // as an unsigned long -- 47
}
----

== Checked Conversions

`std::in_range<T>(value)` ({cpp}20, `<utility>`) checks whether a value fits in a target integer type *before*
converting, avoiding both undefined behavior and silent truncation:

[source,cpp]
----
#include <utility>
#include <cassert>
#include <cstdint>

int main() {
    long long big = 300;
    assert(!std::in_range<int8_t>(big));    // 300 doesn't fit in a signed 8-bit type
    assert(std::in_range<int32_t>(big));     // but does fit in a 32-bit one
    return 0;
}
----

== Floating-Point, Randomness and Bits, Run Through the Compiler

Floating-point numbers follow IEEE 754: a sign, an exponent and a fixed number of significant binary digits. Most
decimal fractions, including 0.1, are not exactly representable, and every operation rounds. The program below
shows the consequences with the inventory's fee arithmetic, then the pieces of `<random>` and `<bit>` that replace
the C idioms.

[mermaid]
....
flowchart LR
    subgraph fp["a double: 64 bits"]
      direction LR
      SG["1 bit<br/>sign"] --- EX["11 bits<br/>exponent"] --- MA["52 bits<br/>mantissa"]
    end
    fp --> N["value = (-1)^sign x 1.mantissa x 2^(exponent-1023)"]
    N --> R["0.1 rounds to the nearest representable value:<br/>0.1000000000000000055..."]
....

.numbers.cpp
[source,cpp]
----
#include <bit>
#include <cmath>
#include <cstdint>
#include <limits>
#include <numbers>
#include <print>
#include <random>
#include <vector>

int main() {
    // Floating-point is binary: 0.1 has no exact representation.
    double sum = 0.0;
    for (int i = 0; i < 10; ++i) sum += 0.1;
    std::println("sum == 1.0: {}   difference: {:e}", sum == 1.0, sum - 1.0);
    bool close = std::abs(sum - 1.0) <= 4 * std::numeric_limits<double>::epsilon();
    std::println("close enough: {}", close);

    // NaN compares unequal to everything, including itself.
    double nan = std::numeric_limits<double>::quiet_NaN();
    std::println("nan == nan: {}  isnan: {}", nan == nan, std::isnan(nan));
    std::println("1/0.0 = {}  -1/0.0 = {}", 1.0 / 0.0, -1.0 / 0.0);

    // Money: use integers (cents) and round once.
    double price = 19.99;
    long cents = std::lround(price * 100);
    std::println("price in cents: {}", cents);

    std::println("pi = {:.10f}  e = {:.10f}", std::numbers::pi, std::numbers::e);
    std::println("sqrt(2) = {:.6f}, hypot(3,4) = {}", std::sqrt(2.0), std::hypot(3.0, 4.0));

    // <random>: separate the engine (bits) from the distribution (shape); seed it explicitly.
    std::mt19937 gen(12345);   // fixed seed -> reproducible output
    std::uniform_int_distribution<int> copies(0, 5);
    std::vector<int> v;
    for (int i = 0; i < 8; ++i) v.push_back(copies(gen));
    for (int c : v) std::print("{} ", c);
    std::println("");

    // <bit>: portable bit tricks.
    std::uint32_t mask = 0b1011'0000;
    std::println("popcount={} countr_zero={} bit_width={} has_single_bit(64)={} bit_ceil(100)={}",
                 std::popcount(mask), std::countr_zero(mask), std::bit_width(mask), std::has_single_bit(64u),
                 std::bit_ceil(100u));
    std::println("rotl(0x80000001, 1) = {:#x}", std::rotl(0x80000001u, 1));
}
----

* Summing `0.1` ten times does not give `1.0`; the error is about `1.1e-16`, one unit in the last place. Compare
  floating-point values with a tolerance scaled to the magnitude (`std::numeric_limits<double>::epsilon()` is the
  spacing near 1.0, so scale it), never with `==`.
* `NaN` is not equal to anything, itself included, so `x == x` is false for it; test with `std::isnan`. Dividing a
  non-zero double by zero is well-defined on IEEE platforms and gives infinity; dividing an *integer* by zero is
  undefined behaviour.
* Never store money in a `double`. Store integer cents (or a decimal type) and round once, at the boundary, with
  `std::lround`.
* `<random>` separates the *engine* (`std::mt19937`, a generator of raw bits) from the *distribution*
  (`uniform_int_distribution`, which shapes them). Seeding with a constant gives the same sequence every run, which
  is what you want in tests; seed from `std::random_device` in production. Never use `std::rand() % n`, which is
  biased and not thread-safe in practice. Distributions are not required to produce identical values across
  standard libraries, so do not hard-code expected numbers across platforms.
* `<bit>` gives portable names for what used to be compiler intrinsics: `popcount`, `countr_zero`, `bit_width`,
  `rotl` and `rotr`, `bit_ceil`, `has_single_bit` and `std::bit_cast`. Unlike shifts on signed values, all of them
  are defined for every unsigned input.
