= Getting Started
:description: What {cpp} is, the standard editions from {cpp}98 to {cpp}26, the major compilers, "Hello, World" with std::println (and a portable fallback), and compiling with -std=c{plus}{plus}23 -Wall -Wextra.
:keywords: {cpp}, {cpp}23, {cpp}26, WG21, ISO/IEC 14882, GCC, Clang, MSVC, std::println, Compiler Explorer

include::partial$ai-disclaimer.adoc[]

https://isocpp.org/[{cpp}] is a general-purpose, statically-typed, compiled language standardized by ISO/IEC JTC1/SC22
*Working Group 21* (https://www.open-std.org/jtc1/sc22/wg21/[WG21]). It gives direct control over memory and layout
(like C) while adding zero-overhead abstractions -- classes, templates, RAII -- that cost nothing at run time
compared to hand-written C. This section targets **{cpp}23** (ISO/IEC 14882:2024), the edition current at the time
of writing, and flags any feature that is {cpp}20/23-only alongside its {cpp}17 fallback.

== The Standard Editions

WG21 ships a new edition roughly every three years. Each is informally named after the year it was ratified:

[cols="1,3"]
|===
|Edition |Headline additions

|{cpp}98/03 |The original ISO standard; the STL (containers, iterators, algorithms).
|{cpp}11 |`auto`, lambdas, move semantics, `nullptr`, range-`for`, smart pointers, `<thread>`.
|{cpp}14 |Generic lambdas, generalized `constexpr`, variable templates.
|{cpp}17 |`if`/`switch` with init, structured bindings, `std::optional`/`variant`/`any`, `<filesystem>`, fold expressions.
|{cpp}20 |Concepts, ranges, coroutines, modules, `+<=>+`, `std::span`, `std::format` (specification only).
|{cpp}23 |`std::print`/`std::println`, `std::expected`, `std::mdspan`, `std::flat_map`, `deducing this`, `if consteval`.
|{cpp}26 |Not yet ISO-published at time of writing -- see xref:programming-languages/cpp/cpp-standards-and-cpp26.adoc[{cpp} Standards and {cpp}26].
|===

== Compilers

Three toolchains track the standard closely and are what this section's examples are verified against:

* **GCC** (`pass:c[g++]`) -- the GNU Compiler Collection, paired with the **libstdc{plus}{plus}** standard library.
* **Clang** (`pass:c[clang++]`) -- LLVM's compiler, usually paired with **libc{plus}{plus}** (though it can also target libstdc{plus}{plus}).
* **MSVC** (`cl.exe`) -- Microsoft's compiler on Windows, shipped with Visual Studio.

None of the three has finished every {cpp}23 library feature yet; https://en.cppreference.com/w/cpp/compiler_support/23[cppreference's
{cpp}23 compiler support table] is the definitive, continuously updated source for what's implemented where. This
section's own examples were checked against GCC 13 / Clang 18 with libstdc{plus}{plus}, which accepts every {cpp}23
*language* feature used here but does not yet provide the `<print>`, `<generator>`, `<flat_map>` or `<mdspan>`
headers; the pages that use those call it out where it matters.

== "Hello, World"

{cpp}23 adds `std::println` (header `<print>`), which formats and writes a line in one call -- no manual `"\n"`,
no `std::endl` flush semantics to reason about:

[source,cpp]
----
#include <print>

int main() {
    std::println("Hello, World!");
}
----

NOTE: `<print>` is standard-conformant {cpp}23 (verified against cppreference and the working draft) but is not yet
shipped by every standard library -- it needs GCC 14+, a recent libc{plus}{plus}, or MSVC; it is *not* available in this
environment's libstdc{plus}{plus} 13. The portable {cpp}17 fallback below compiles everywhere, including in this environment:

[source,cpp]
----
#include <iostream>

int main() {
    std::cout << "Hello, World!\n";
}
----

== Compiling

Turning a `.cpp` file into a running program is four stages -- preprocess, compile, assemble, link -- that
`pass:c[clang++]`/`pass:c[g++]` run in one invocation:

image::cpp-compilation-pipeline.svg[Preprocess, compile, assemble, and link stages producing an executable from one or more translation units]

This section's examples are written to compile clean under:

[source,shell]
----
clang++ -std=c++23 -Wall -Wextra -o hello hello.cpp
./hello
----

`pass:c[-std=c++23]` selects the language edition; `-Wall -Wextra` turns on the warnings that catch most beginner
mistakes (unused variables, sign comparisons, uninitialized reads). Add `-Werror` in CI once a codebase is warning-clean,
so new warnings fail the build instead of accumulating.

== Compiler Explorer

https://godbolt.org/[Compiler Explorer] ("Godbolt") compiles a snippet against dozens of compiler
versions/`-std=` combinations in the browser and shows the generated assembly side by side -- the fastest way to
check whether a given compiler actually implements a specific {cpp}20/23 feature before committing to it in a
real project.

== From Source File to Running Program

Every {cpp} program you build goes through the same four stages, even when one command such as `pass:c[clang++ main.cpp]`
hides them. Knowing the stages tells you which tool is complaining when a build fails: a missing header is a
preprocessor error, a type mismatch a compiler error, and an "undefined reference" a linker error.

[mermaid]
....
flowchart LR
    S["inventory0.cpp<br/>(source)"] -->|"1. preprocess<br/>#include, #define"| T["translation unit<br/>(one big text)"]
    T -->|"2. compile<br/>parse, type-check, optimize"| A["assembly (.s)"]
    A -->|"3. assemble"| O["object file (.o)<br/>machine code + symbols"]
    O -->|"4. link<br/>with libc++ and other .o files"| E["executable"]
....

The running example for this whole section is a small library inventory: `Book`, `Member`, `Loan` and a `Library`
that ties them together. Later pages grow it with classes, templates, containers, concurrency and coroutines. The
first version is deliberately tiny: an aggregate, a `std::vector` of books and a loop.

.inventory0.cpp
[source,cpp]
----
// inventory0.cpp -- the first version of the running example: a tiny library inventory.
#include <print>
#include <string>
#include <vector>

struct Book {
    std::string title;
    int year;
    int copies;
};

int main() {
    std::vector<Book> shelf{
        {"The C++ Programming Language", 1985, 3},
        {"A Tour of C++", 2013, 2},
        {"Effective Modern C++", 2014, 0},
    };

    int available = 0;
    for (const Book& b : shelf) {
        std::println("{:<30} {} copies={}", b.title, b.year, b.copies);
        available += b.copies;
    }
    std::println("{} titles, {} copies on the shelf", shelf.size(), available);
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra inventory0.cpp -o inventory0
$ ./inventory0
The C++ Programming Language   1985 copies=3
A Tour of C++                  2013 copies=2
Effective Modern C++           2014 copies=0
3 titles, 5 copies on the shelf
----

The `-Wall -Wextra` flags cost nothing and catch real mistakes, so use them from the first file. The compiler used
for every example in this section is Apple clang 21 with libc{plus}{plus}, compiled as `pass:c[-std=c++23]`; the standard library
headers `<print>`, `<expected>`, `<flat_map>` and `<mdspan>` are available with it, while `<generator>`,
`<stacktrace>` and `<spanstream>` are not (the pages that discuss those features say so).

=== Looking at each stage

You can stop the pipeline after any stage and inspect what it produced. `-E` stops after preprocessing, `-S`
after compilation and `-c` after assembly:

[source,console]
----
$ clang++ -std=c++23 -E inventory0.cpp | wc -l
   49112
----

[source,console]
----
$ clang++ -std=c++23 -E inventory0.cpp | grep -c '^struct Book'
1
----

The five-line `+#include+` list of the source expands to tens of thousands of lines of library declarations. This is
the main reason {cpp} compile times grow with every header you add, and the reason modules (see
xref:programming-languages/cpp/namespaces-modules-and-the-preprocessor.adoc[Namespaces, Modules, and the
Preprocessor]) exist.

[source,console]
----
$ clang++ -std=c++23 -c inventory0.cpp -o inventory0.o && nm -C inventory0.o | grep -E ' T _main$'
0000000000000000 T _main
----

`nm` lists the symbols of the object file; `T` marks code defined here, and `+_main+` is the program's entry point (macOS prefixes C-linkage symbols with an underscore; Linux shows plain `main`).
Symbols marked `U` are undefined in this file: they are the library functions the linker still has to find. A
few of them (printed below with `nm -u`) come from the {cpp} runtime in the standard library, the rest are
templates that were instantiated inside this object file.

[source,console]
----
$ nm -u -C inventory0.o | head -5
__Unwind_Resume
std::runtime_error::what() const
std::__1::locale::use_facet(std::__1::locale::id&) const
std::logic_error::logic_error(char const*)
std::length_error::~length_error()
----

=== Warnings worth turning into errors

A first useful habit is to make the compiler stop on the mistakes that are almost always bugs. This one-line
program has an unused variable and a comparison between signed and unsigned values:

.warn0.cpp
[source,cpp]
----
#include <vector>
#include <print>

int main() {
    std::vector<int> v{1, 2, 3};
    int unused = 42;
    int i = -1;
    if (i < v.size()) {
        std::println("i is smaller");
    } else {
        std::println("i is NOT smaller: -1 converted to a huge unsigned value");
    }
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra warn0.cpp -o warn0
warn0.cpp:6:9: warning: unused variable 'unused' [-Wunused-variable]
    6 |     int unused = 42;
      |         ^~~~~~
warn0.cpp:8:11: warning: comparison of integers of different signs: 'int' and 'size_type' (aka 'unsigned long') [-Wsign-compare]
    8 |     if (i < v.size()) {
      |         ~ ^ ~~~~~~~~
2 warnings generated.
$ ./warn0
i is NOT smaller: -1 converted to a huge unsigned value
----

Neither line is an error under the standard, which is exactly why they only show up with `-Wall -Wextra`. In CI use
`-Werror` (or the narrower `-Werror=sign-compare`) so a new warning fails the build; see
xref:programming-languages/cpp/build-and-tooling.adoc[Build and Tooling].
