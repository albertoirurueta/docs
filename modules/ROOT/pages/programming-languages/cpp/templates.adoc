== Function and Class Templates

[source,cpp]
----
template <typename T>
T maxOf(T a, T b) {
    return a > b ? a : b;
}

template <typename T>
class Box {
public:
    explicit Box(T value) : value_(value) {}
    T get() const { return value_; }
private:
    T value_;
};
----

`typename` and `class` are interchangeable in a template parameter list (`template <class T>` means exactly the
same thing) -- `typename` is the more common modern convention.

== Template Argument Deduction

[source,cpp]
----
int m = maxOf(3, 5);            // T deduced as int from the arguments -- no need to write maxOf<int>
double d = maxOf(3.0, 5.0);      // T deduced as double
// auto bad = maxOf(3, 5.0);    // error: T can't be deduced as both int and double -- an explicit
                                  // maxOf<double>(3, 5.0) resolves the ambiguity
----

== CTAD and Deduction Guides

**Class Template Argument Deduction** ({cpp}17) lets a class template's constructor arguments determine its
template arguments, the same way function templates already worked:

[source,cpp]
----
Box b(42);                    // CTAD: deduces Box<int> from the constructor argument, no "<int>" needed
std::vector v = {1, 2, 3};      // CTAD: deduces std::vector<int>
std::pair p(1, "one");           // CTAD: deduces std::pair<int, const char*>
----

A **deduction guide** tells the compiler how to deduce arguments when the constructor alone is ambiguous or
insufficient:

[source,cpp]
----
template <typename T>
struct Wrapper {
    Wrapper(T value) : value_(value) {}
    T value_;
};
Wrapper(const char*) -> Wrapper<std::string>;   // without this guide, Wrapper("hi") would deduce
                                                  // Wrapper<const char*>, not the likely intended Wrapper<std::string>
----

== Non-Type Template Parameters

A template parameter can be a *value* (an integer, a pointer, an enum, and since {cpp}20 a floating-point value
or a literal class type), not just a type:

[source,cpp]
----
template <typename T, std::size_t N>
class FixedArray {
public:
    T& operator[](std::size_t i) { return data_[i]; }
    static constexpr std::size_t size() { return N; }
private:
    T data_[N]{};
};

FixedArray<int, 10> arr;        // N is a compile-time constant, baked into the type itself
static_assert(arr.size() == 10);
----

`std::array<T, N>` is exactly this pattern, in the standard library.

== Alias Templates

Covered in xref:programming-languages/cpp/basic-types-and-values.adoc[Basic Types and Values]; they are the
`using`-based way to give a partially-applied template a shorter name:

[source,cpp]
----
template <typename T>
using IntKeyMap = std::map<int, T>;

IntKeyMap<std::string> m;   // same as std::map<int, std::string>
----

== Variadic Templates and Fold Expressions

A **parameter pack** (`+Args...+`) accepts any number of template arguments; a **fold expression** ({cpp}17)
collapses the pack with an operator in one expression, replacing the recursive-unpacking idiom {cpp}11/14 needed:

[source,cpp]
----
#include <iostream>

template <typename... Args>
auto sumAll(Args... args) {
    return (args + ...);              // unary right fold: arg1 + (arg2 + (arg3 + ...))
}

template <typename... Args>
void printAll(const Args&... args) {
    ((std::cout << args << ' '), ...);   // fold over the comma operator -- prints every argument
}

int main() {
    std::cout << sumAll(1, 2, 3, 4) << '\n';   // 10
    printAll("a", 1, 3.5, 'x');                 // a 1 3.5 x
}
----

== Specialization and Partial Specialization

A **full specialization** provides a completely different implementation for one specific set of template
arguments; a **partial specialization** does so for a *pattern* of arguments (only available for class
templates, not function templates):

[source,cpp]
----
template <typename T>
struct TypeName {
    static constexpr const char* value = "unknown";
};

template <>                              // full specialization
struct TypeName<int> {
    static constexpr const char* value = "int";
};

template <typename T>                     // partial specialization: any pointer type
struct TypeName<T*> {
    static constexpr const char* value = "pointer";
};

static_assert(std::string_view(TypeName<int>::value) == "int");
static_assert(std::string_view(TypeName<double*>::value) == "pointer");
static_assert(std::string_view(TypeName<double>::value) == "unknown");
----

== Two-Phase Lookup Basics

A template's body is checked in two phases: **phase 1**, at definition, resolves names that do *not* depend on
a template parameter (ordinary lookup applies); **phase 2**, at instantiation, resolves names that *do* depend
on a template parameter (found via Argument-Dependent Lookup at the point of instantiation). This is why a
dependent base class's members need `+this->+` or explicit qualification -- phase 1 cannot see them yet:

[source,cpp]
----
template <typename T>
struct Base {
    void baseMethod() {}
};

template <typename T>
struct Derived : Base<T> {
    void callIt() {
        // baseMethod();       // error: not found in phase 1 -- Base<T> is a dependent base
        this->baseMethod();     // fine: "this->" defers lookup to phase 2, when T is known
    }
};
----

== Instantiation, Specialization and Variadics Run for Real

A template is not code; it is a recipe. The compiler generates ("instantiates") a real function or class each time
you use the template with a new set of arguments, which is why templates have no run-time cost and why their errors
appear at the point of use, deep inside the library code.

[mermaid]
....
flowchart TB
    U["call: max_of(3, 7)"] --> D["deduce T = int from the arguments"]
    D --> L{"instantiation of max_of&lt;int&gt;<br/>already exists in this TU?"}
    L -->|"no"| I["substitute T = int into the body<br/>and compile it"]
    L -->|"yes"| R["reuse it"]
    I --> OK["machine code for max_of&lt;int&gt;"]
    I -->|"body does not compile for T"| ERR["error at the use site,<br/>reported inside the template body"]
....

.tmpl.cpp
[source,cpp]
----
#include <concepts>
#include <print>
#include <string>
#include <type_traits>
#include <vector>

// Function template: the compiler stamps out one function per distinct T.
template <typename T>
T max_of(const T& a, const T& b) { return a < b ? b : a; }

// Class template: a bounded shelf of any item type, with a non-type parameter for capacity.
template <typename T, std::size_t Capacity>
class Shelf {
public:
    bool add(T item) {
        if (items_.size() == Capacity) return false;
        items_.push_back(std::move(item));
        return true;
    }
    std::size_t size() const { return items_.size(); }
    static constexpr std::size_t capacity() { return Capacity; }

private:
    std::vector<T> items_;
};

// Primary template plus full and partial specializations.
template <typename T> struct Describe { static std::string text() { return "unknown"; } };
template <> struct Describe<int> { static std::string text() { return "integer"; } };
template <typename T> struct Describe<T*> { static std::string text() { return "pointer to " + Describe<T>::text(); } };
template <typename T> struct Describe<std::vector<T>> { static std::string text() { return "vector of " + Describe<T>::text(); } };

// Variadic template with a fold expression: how many arguments are books titles longer than n?
template <typename... Args>
std::size_t count_long(std::size_t n, const Args&... titles) {
    return (static_cast<std::size_t>(std::string(titles).size() > n) + ...);
}

template <typename... Ts>
auto sum_all(Ts... xs) { return (xs + ...); }

// CTAD: deduction guide so Pair{"a", 1} deduces Pair<std::string, int>.
template <typename A, typename B>
struct Pair { A first; B second; };
template <typename A, typename B> Pair(A, B) -> Pair<A, B>;

// Generic code trap: T must support <, and only the instantiation reveals it.
struct NoCompare {};

int main() {
    std::println("{} {} {}", max_of(3, 7), max_of(2.5, 1.5), max_of(std::string("emma"), std::string("dune")));

    Shelf<std::string, 2> shelf;
    std::println("{} {} {}", shelf.add("Dune"), shelf.add("Emma"), shelf.add("Ulysses"));
    std::println("size {} of capacity {}", shelf.size(), Shelf<std::string, 2>::capacity());

    std::println("{} / {} / {}", Describe<double>::text(), Describe<int*>::text(), Describe<std::vector<int*>>::text());

    std::println("long titles: {}", count_long(4, "Dune", "Neuromancer", "Hyperion"));
    std::println("sum = {}, mixed = {}", sum_all(1, 2, 3, 4), sum_all(1, 2.5, 3));

    Pair p{std::string("Dune"), 1965};
    std::println("{} {}", p.first, p.second);

    // max_of(NoCompare{}, NoCompare{});   // error: invalid operands to binary expression ('const NoCompare' and ...)
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra tmpl.cpp -o tmpl
$ ./tmpl
7 2.5 emma
true true false
size 2 of capacity 2
unknown / pointer to integer / vector of pointer to integer
long titles: 2
sum = 10, mixed = 6.5
Dune 1965
----

* `max_of` instantiates three distinct functions (`int`, `double`, `std::string`); the two `int` calls share one.
  Deduction does not apply conversions: `max_of(1, 2.5)` fails because `T` would be both `int` and `double`.
* `Shelf<T, Capacity>` uses a *non-type template parameter*, so `Shelf<std::string, 2>` and `Shelf<std::string, 3>`
  are unrelated types, and the capacity is a compile-time constant.
* `Describe` shows the specialization rules: the primary template is the default; `Describe<int>` is a full
  specialization; `+Describe<T*>+` and `Describe<std::vector<T>>` are partial specializations selected by pattern.
  Only class and variable templates can be partially specialized; for functions use overloading or `if constexpr`.
* The fold expression `pass:c[(... + xs)]` expands over the parameter pack. A fold over an empty pack is an error for `pass:c[+]`
  (it has no identity), while `&&`, `||` and `,` have defined empty values; supply an initial value with a binary
  fold `pass:c[(0 + ... + xs)]` when the pack may be empty.
* CTAD deduces class template arguments from constructor arguments (`+Pair p{std::string("Dune"), 1965}+`); a
  deduction guide covers the cases the implicit guides miss.

=== The error you get when the template body does not fit

.badtmpl.cpp
[source,cpp]
----
template <typename T>
T max_of(const T& a, const T& b) { return a < b ? b : a; }
struct NoCompare {};
int main() { max_of(NoCompare{}, NoCompare{}); }
----

[source,console]
----
$ clang++ -std=c++23 badtmpl.cpp -o bt 2>&1 | head -6
badtmpl.cpp:2:45: error: invalid operands to binary expression ('const NoCompare' and 'const NoCompare')
    2 | T max_of(const T& a, const T& b) { return a < b ? b : a; }
      |                                           ~ ^ ~
badtmpl.cpp:4:14: note: in instantiation of function template specialization 'max_of<NoCompare>' requested here
    4 | int main() { max_of(NoCompare{}, NoCompare{}); }
      |              ^
----

The error points into the template body (`a < b`) and the "in instantiation" note points to the offending call.
With more layers of templates the chain of notes grows long, which is the motivation for constraining templates
with concepts: see xref:programming-languages/cpp/concepts-and-constraints.adoc[Concepts and Constraints].

Two further rules prevent subtle bugs. Template definitions must be visible in every translation unit that
instantiates them, so they normally live in headers (or are explicitly instantiated with `template class
Shelf<int, 4>;` in one source file). And a dependent name that is a type needs `typename`
(`typename T::value_type x;`), a dependent member template needs `template` (`obj.template get<0>()`), because the
compiler cannot know what `T::value_type` means until `T` is known.
