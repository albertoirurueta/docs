= {cpp} Standards and {cpp}26
:description: The editions from {cpp}98 to {cpp}23 and their headline features, feature-test macros, compiler support pages, and {cpp}26 (reflection, contracts, std::execution, erroneous behaviour, hardened library).
:keywords: {cpp}, {cpp}98, {cpp}11, {cpp}14, {cpp}17, {cpp}20, {cpp}23, {cpp}26, reflection, contracts, std::execution, erroneous behaviour, hardened library

include::partial$ai-disclaimer.adoc[]

This section has targeted **{cpp}23** throughout, flagging {cpp}20/23-only features against their {cpp}17 fallback
where a toolchain gap made that concrete (see xref:programming-languages/cpp/getting-started.adoc[Getting
Started]). This closing page puts every edition on one timeline and looks ahead to **{cpp}26**.

== The Editions, {cpp}98 to {cpp}23

[cols="1,1,4"]
|===
|Edition |Year |Headline features

|{cpp}98/03 |1998/2003 |The original ISO standard; the STL (containers, iterators, algorithms); templates; exceptions.
|{cpp}11 |2011 |`auto`, lambdas, move semantics/rvalue references, `nullptr`, range-`for`, smart pointers, `<thread>`, variadic templates, `constexpr`.
|{cpp}14 |2014 |Generic lambdas, generalized `constexpr`, variable templates, `std::make_unique`.
|{cpp}17 |2017 |Structured bindings, `if`/`switch` with init, `std::optional`/`variant`/`any`, `<filesystem>`, fold expressions, guaranteed copy elision, `std::string_view`.
|{cpp}20 |2020 |Concepts, ranges, coroutines, modules, `+<=>+`, `std::span`, `std::format` (spec only), `consteval`/`constinit`, `std::jthread`.
|{cpp}23 |2023 |`std::print`/`std::println`, `std::expected`, `std::mdspan`, `std::flat_map`, deducing this, `if consteval`, `std::generator`, multidimensional `operator[]`.
|===

This progression is visualized below, and every page in this section links the specific cppreference/WG21
source for the features it covers -- this table is a map, not a replacement for those primary sources.

== Feature-Test Macros

Covered in xref:programming-languages/cpp/namespaces-modules-and-the-preprocessor.adoc[Namespaces, Modules, and
the Preprocessor] -- `<version>` and macros like `+__cpp_concepts+`/`+__cpp_lib_expected+` let code detect,
per-feature, exactly what a given compiler+standard-library combination actually implements, which -- as this
section's own toolchain notes (e.g. `<print>`, `<generator>`, `<flat_map>`, `<mdspan>` not yet in this
environment's libstdc{plus}{plus} 13) demonstrate -- can lag behind the `-std=` flag accepting a given edition at all.

== {cpp}26

At the time of writing, **{cpp}26** is feature-complete at the WG21 committee level but **not yet formally
ISO-published** -- its contents are stable in the working draft but the ratification/publication process is
still in progress, so treat everything below as the current committee consensus (subject to the standard
process's own final steps) rather than a shipped, ISO-numbered edition the way {cpp}23 (ISO/IEC 14882:2024) is:

[cols="1,3"]
|===
|Feature |What it adds

|Reflection (`std::meta`) |Compile-time introspection over types/members -- generate boilerplate (serializers, comparisons) without external code generators.
|Contracts (`pre`/`post`/`contract_assert`) |Preconditions/postconditions as a first-class language feature, checkable at configurable severity levels.
|`std::execution` (P2300, "senders/receivers") |A unified, composable asynchrony model, generalizing beyond `std::future`/`std::async` (see xref:programming-languages/cpp/async-futures-and-atomics.adoc[Async, Futures, and Atomics]).
|Erroneous behaviour |A new category between well-defined and undefined behavior: a specific, diagnosable default result (e.g. reading an uninitialized `int` reliably yields a fixed sentinel pattern) instead of "anything can happen."
|Hardened standard library |Optional, standardized run-time bounds/precondition checking in library functions (e.g. `vector::operator[]`), for a safety/performance trade-off projects can opt into explicitly.
|===

Because none of this is ISO-published yet, this section deliberately does not include worked, verified code
examples for {cpp}26 the way it does for {cpp}23 -- by the time {cpp}26 ships and toolchains catch up, consult
https://eel.is/c{plus}{plus}draft/[eel.is/c{plus}{plus}draft] (which tracks the latest working draft, {cpp}26 included) and the
compiler support pages above for what actually landed and where.

== Asking Your Compiler What It Supports

The most reliable table of "what works here" is the one your compiler prints. Every language and library feature
has a *feature-test macro*, and `<version>` defines all the library ones without including anything else. The
program below reports the value of a selection of them for the toolchain used on this page (Apple clang 21 with
libc{plus}{plus}, `pass:c[-std=c++23]`); each value is the year and month of the standard wording the implementation matches, and
`missing` means the feature is not available.

[mermaid]
....
flowchart LR
    Q["can I use feature X?"] --> M{"feature-test macro<br/>defined?"}
    M -->|"no"| FB["use the fallback:<br/>another library, or the older idiom"]
    M -->|"yes, value >= the year that matters"| OK["use it"]
    M -->|"yes, but older value"| P["an earlier version of the paper:<br/>check the specific change"]
    OK --> G["guard code with #if or if constexpr<br/>so other compilers still build"]
....

.ftm.cpp
[source,cpp]
----
#include <print>
#include <version>   // defines every __cpp_lib_* macro without including the library itself

// Language feature-test macros (C++11..C++23) and a few library ones. Each prints its value or "missing".
#define STR2(x) #x
#define STR(x) STR2(x)   // two levels: the argument is macro-expanded before it is stringized
#define REPORT(m) std::println("{:<34} {}", #m, defined_or_missing(STR(m), #m))
constexpr const char* defined_or_missing(const char* expanded, const char* name) {
    // If the macro is not defined, the preprocessor leaves its own name in place.
    const char* a = expanded; const char* b = name;
    while (*a && *b && *a == *b) { ++a; ++b; }
    return (*a == 0 && *b == 0) ? "missing" : expanded;
}

int main() {
    std::println("__cplusplus = {}", __cplusplus);
    REPORT(__cpp_concepts);
    REPORT(__cpp_modules);
    REPORT(__cpp_impl_coroutine);
    REPORT(__cpp_consteval);
    REPORT(__cpp_explicit_this_parameter);
    REPORT(__cpp_multidimensional_subscript);
    REPORT(__cpp_lib_format);
    REPORT(__cpp_lib_print);
    REPORT(__cpp_lib_expected);
    REPORT(__cpp_lib_ranges);
    REPORT(__cpp_lib_ranges_to_container);
    REPORT(__cpp_lib_generator);
    REPORT(__cpp_lib_flat_map);
    REPORT(__cpp_lib_mdspan);
    REPORT(__cpp_lib_stacktrace);
    REPORT(__cpp_lib_jthread);
    REPORT(__cpp_lib_span);
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra ftm.cpp -o ftm
$ ./ftm
__cplusplus = 202302
__cpp_concepts                     202002
__cpp_modules                      missing
__cpp_impl_coroutine               201902L
__cpp_consteval                    202211L
__cpp_explicit_this_parameter      202110L
__cpp_multidimensional_subscript   202211L
__cpp_lib_format                   202110L
__cpp_lib_print                    202207L
__cpp_lib_expected                 202211L
__cpp_lib_ranges                   202406L
__cpp_lib_ranges_to_container      202202L
__cpp_lib_generator                missing
__cpp_lib_flat_map                 202511L
__cpp_lib_mdspan                   202207L
__cpp_lib_stacktrace               missing
__cpp_lib_jthread                  201911L
__cpp_lib_span                     202002L
----

* `+__cplusplus+` is `202302` for `pass:c[-std=c++23]`. Language macros have a `+__cpp_+` prefix and library macros a
  `+__cpp_lib_+` prefix; the library ones come from `<version>`.
* The names matter: the macro for coroutine support is `+__cpp_impl_coroutine+`, and for explicit object parameters
  ("deducing this") it is `+__cpp_explicit_this_parameter+`. A macro name that looks right but does not exist is
  silently "missing", which is why the program prints the name next to the value.
* Gaps in the table are real: `<generator>`, `<stacktrace>` and `+__cpp_modules+` are missing here, although the
  language mode is {cpp}23. Standard editions are adopted feature by feature, so the compiler's own
  status pages are as important as the standard itself.
* Use the macros for conditional code: `+#if __cpp_lib_flat_map >= 202207L+` around a `std::flat_map` alias that
  falls back to `std::map`, rather than testing the compiler version.

=== A first look at {cpp}26

Selecting `pass:c[-std=c++2c]` (the {cpp}26 working mode) turns on the features the compiler has implemented so far. Two small
{cpp}26 features that work with this compiler, with the language version they report:

.cpp26.cpp
[source,cpp]
----
#include <print>
#include <string>
#include <utility>

// C++26: pack indexing -- name the Nth element of a pack directly.
template <typename... Ts>
auto first_of(Ts... xs) { return xs...[0]; }

// C++26: a reason string on a deleted function shows up in the diagnostic.
void borrow(const std::string&);
void borrow(int) = delete("ids are not titles: pass the title string");

int main() {
    std::println("first_of = {}", first_of(7, std::string("Dune")));
    auto [_, copies] = std::pair{"Dune", 3};   // C++26: _ may be redeclared / unused placeholder
    std::println("copies = {}", copies);
    std::println("__cplusplus = {}", __cplusplus);
}
void borrow(const std::string&) {}
----

[source,console]
----
$ clang++ -std=c++2c -Wall -Wextra cpp26.cpp -o cpp26
$ ./cpp26
first_of = 7
copies = 3
__cplusplus = 202400
----

Pack indexing (`+xs...[0]+`) names the Nth element of a pack directly, replacing recursion or `std::get` on a tuple.
`= delete("reason")` attaches a message that appears in the error when a deleted function is called:

.cpp26bad.cpp
[source,cpp]
----
void borrow(int) = delete("ids are not titles: pass the title string");
int main() { borrow(3); }
----

[source,console]
----
$ clang++ -std=c++2c cpp26bad.cpp -o b 2>&1 | head -1
cpp26bad.cpp:2:14: error: call to deleted function 'borrow': ids are not titles: pass the title string
----

Under `pass:c[-std=c++23]` the same pack-indexing code compiles with a warning that it is a {cpp}26 extension, which shows
why the standard mode and the feature-test macros, not "it compiled", are the evidence of support. {cpp}26's headline
features (static reflection, contracts, `std::execution`) are not usable with this toolchain; treat anything about
them beyond the sections above as a preview.
