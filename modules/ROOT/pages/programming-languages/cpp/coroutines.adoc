:keywords: {cpp}, coroutines, co_await, co_yield, co_return, promise type, awaitable, task, generator, std::generator

include::partial$ai-disclaimer.adoc[]

A {cpp}20 coroutine is an ordinary-looking function that uses `co_await`, `co_yield`, or `co_return` -- their mere
presence makes the *whole function* a coroutine, compiled into a state machine that can suspend and later
resume exactly where it left off, instead of running start-to-finish in one go.

== `co_await`, `co_yield`, `co_return`

* `co_await expr` -- suspend until `expr` (an **awaitable**) says it's ready, then resume with its result.
* `co_yield value` -- produce one value to the caller and suspend, resuming on the next request (drives
  generators).
* `co_return value;` (or bare `co_return;`) -- finish the coroutine, delivering `value` to whatever is
  consuming it.

Unlike an ordinary `return`, none of these three unwind the coroutine's local state -- that's exactly what lets
it resume later with everything still intact.

== Promise Types and Awaitables

The compiler doesn't know what "suspend" or "produce a result" *mean* for your coroutine on its own -- a
**promise type** (unrelated to `std::promise`) spells that out, and an **awaitable** (anything with
`await_ready`/`await_suspend`/`await_resume`) spells out what a single `co_await` does:

[source,cpp]
----
#include <coroutine>

struct MinimalPromise {
    // required promise-type interface:
    auto get_return_object() { return std::coroutine_handle<MinimalPromise>::from_promise(*this); }
    std::suspend_always initial_suspend() { return {}; }   // suspend immediately -- caller decides when to start
    std::suspend_always final_suspend() noexcept { return {}; }
    void return_void() {}
    void unhandled_exception() { std::terminate(); }        // simplest possible policy: give up on an exception
};
----

`std::suspend_always`/`std::suspend_never` are the two trivial, standard-provided awaitables (always suspend /
never suspend) -- most real coroutine types (below) define their own richer ones.

== A `task` Type

A minimal, fire-and-run "start a coroutine, don't wait for a result" type built from the pieces above:

[source,cpp]
----
#include <coroutine>
#include <iostream>

struct Task {
    struct promise_type {
        Task get_return_object() { return Task{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        std::suspend_never initial_suspend() { return {}; }    // start running immediately
        std::suspend_always final_suspend() noexcept { return {}; }   // stay suspended at the end -- lets
                                                                          // Task's destructor own destroying the
        void return_void() {}                                             // frame; suspend_never here would
        void unhandled_exception() { std::terminate(); }                   // auto-destroy it, and ~Task's
    };                                                                       // handle.destroy() would then be
                                                                               // a double-free

    std::coroutine_handle<promise_type> handle;
    ~Task() { if (handle) handle.destroy(); }
};

Task greet() {
    std::cout << "before suspend\n";
    co_await std::suspend_always{};    // suspends here -- something else would need to call handle.resume()
    std::cout << "after resume\n";      // to reach this line
}
----

== A `generator` Type

A minimal, from-scratch lazy generator using `co_yield` -- what a hand-written `generator` needs to implement,
before reaching for the standard one below:

[source,cpp]
----
#include <coroutine>
#include <optional>

template <typename T>
struct Generator {
    struct promise_type {
        T currentValue;
        Generator get_return_object() {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        std::suspend_always yield_value(T value) {   // called for every "co_yield value"
            currentValue = value;
            return {};
        }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> handle;
    explicit Generator(std::coroutine_handle<promise_type> h) : handle(h) {}
    ~Generator() { if (handle) handle.destroy(); }

    bool next() {
        if (handle.done()) return false;
        handle.resume();
        return !handle.done();
    }
    T value() const { return handle.promise().currentValue; }
};

Generator<int> countUpTo(int n) {
    for (int i = 1; i <= n; ++i) {
        co_yield i;
    }
}

// Generator<int> g = countUpTo(3);
// while (g.next()) { use(g.value()); }   // 1, 2, 3
----

== `std::generator` ({cpp}23)

{cpp}23 standardizes exactly this pattern as `std::generator<T>`, eliminating the promise-type boilerplate above
for the common case:

[source,cpp]
----
#include <generator>

std::generator<int> countUpTo(int n) {
    for (int i = 1; i <= n; ++i) {
        co_yield i;
    }
}

// for (int value : countUpTo(3)) { use(value); }   // works directly with range-for -- 1, 2, 3
----

NOTE: `<generator>` is standard-conformant {cpp}23 (verified against cppreference and the working draft) but is
not yet shipped by this environment's libstdc{plus}{plus} 13 -- it needs GCC 14+, a recent libc{plus}{plus}, or MSVC (see
xref:programming-languages/cpp/getting-started.adoc[Getting Started]). The hand-written `Task`/`Generator` types
above *do* compile locally, and demonstrate the exact mechanism `std::generator` packages.

    Running --> Done: co_return, or falls<br/>off the end

== A Complete Generator and Task, Step by Step

A coroutine is a function that can *suspend* and later *resume*, keeping its local variables alive in a heap
*coroutine frame* in between. A function is a coroutine if its body contains `co_await`, `co_yield` or `co_return`.
The compiler transforms the body into a state machine over the frame and calls into a user-supplied *promise type*
(and *awaiter* types) at each of those points, which is why you must write the surrounding machinery yourself until
a library provides it.

[mermaid]
....
stateDiagram-v2
    [*] --> InitialSuspend: coroutine called,<br/>frame allocated
    InitialSuspend --> Running: resume()<br/>(suspend_always waits for the first resume)
    Running --> Suspended: co_yield / co_await<br/>that suspends
    Suspended --> Running: resume()
    Running --> FinalSuspend: end of body or co_return
    FinalSuspend --> Destroyed: handle.destroy()<br/>frame freed
    Destroyed --> [*]
....

.coro.cpp
[source,cpp]
----
#include <coroutine>
#include <exception>
#include <print>
#include <string>
#include <utility>
#include <vector>

// A minimal generator<T>: the coroutine produces values lazily with co_yield.
template <typename T>
class Generator {
public:
    struct promise_type {
        T current;
        std::exception_ptr error;
        Generator get_return_object() { return Generator{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        std::suspend_always initial_suspend() noexcept { return {}; }   // lazy: do nothing until first resume
        std::suspend_always final_suspend() noexcept { return {}; }     // keep the frame so done() can be queried
        std::suspend_always yield_value(T v) { current = std::move(v); return {}; }
        void return_void() {}
        void unhandled_exception() { error = std::current_exception(); }
    };

    explicit Generator(std::coroutine_handle<promise_type> h) : h_(h) {}
    Generator(Generator&& o) noexcept : h_(std::exchange(o.h_, nullptr)) {}
    Generator(const Generator&) = delete;
    ~Generator() { if (h_) h_.destroy(); }   // destroying the handle frees the coroutine frame

    bool next() {
        h_.resume();
        if (h_.promise().error) std::rethrow_exception(h_.promise().error);
        return !h_.done();
    }
    const T& value() const { return h_.promise().current; }

private:
    std::coroutine_handle<promise_type> h_;
};

// The coroutine: its local variables live in a heap-allocated frame across suspensions.
Generator<std::string> overdue_notices(const std::vector<std::string>& members) {
    int sent = 0;
    for (const auto& m : members) {
        std::println("  [producing notice for {}]", m);
        co_yield "Dear " + m + ", your book is overdue (#" + std::to_string(++sent) + ")";
    }
    std::println("  [coroutine body finished]");
}

// A minimal awaitable: co_await suspends and later resumes; here it resumes immediately.
struct Ready {
    bool await_ready() const noexcept { return true; }   // true: do not suspend
    void await_suspend(std::coroutine_handle<>) const noexcept {}
    int await_resume() const noexcept { return 7; }
};

struct Task {
    struct promise_type {
        int result = 0;
        Task get_return_object() { return Task{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        std::suspend_never initial_suspend() noexcept { return {}; }   // eager: runs at once
        std::suspend_always final_suspend() noexcept { return {}; }
        void return_value(int v) { result = v; }
        void unhandled_exception() { std::terminate(); }
    };
    std::coroutine_handle<promise_type> h;
    ~Task() { if (h) h.destroy(); }
};

Task compute() {
    int a = co_await Ready{};
    co_return a * 6;   // 42
}

int main() {
    std::vector<std::string> members{"Ada", "Bob", "Cy"};
    auto gen = overdue_notices(members);
    std::println("coroutine created, nothing has run yet");
    while (gen.next()) std::println("got: {}", gen.value());
    std::println("generator exhausted");

    Task t = compute();
    std::println("Task result: {} (done: {})", t.h.promise().result, t.h.done());
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra coro.cpp -o coro
$ ./coro
coroutine created, nothing has run yet
  [producing notice for Ada]
got: Dear Ada, your book is overdue (#1)
  [producing notice for Bob]
got: Dear Bob, your book is overdue (#2)
  [producing notice for Cy]
got: Dear Cy, your book is overdue (#3)
  [coroutine body finished]
generator exhausted
Task result: 42 (done: true)
----

How the output maps onto the machinery:

* Calling `overdue_notices` allocates the frame and builds the `Generator` through `get_return_object()`, then
  stops at `initial_suspend()`. Because that returns `suspend_always`, *none of the body ran*: the first line
  of output ("nothing has run yet") appears before any `+[producing ...]+` line. A promise returning `suspend_never`
  would start the body immediately, as the `Task` does.
* Each `gen.next()` calls `resume()`. The body runs until `co_yield expr`, which is translated into
  `co_await promise.yield_value(expr)`; our `yield_value` stores the value and returns `suspend_always`, so the
  coroutine suspends and `next()` returns to the loop. The `sent` counter keeps its value between resumptions,
  because it lives in the frame.
* After the last member the body ends, prints `[coroutine body finished]`, and reaches `final_suspend()`. We return
  `suspend_always` there so the frame stays alive long enough for `done()` to be queried; a coroutine that falls off
  the end at `final_suspend` and is never destroyed leaks its frame.
* `+co_await Ready{}+` asks the awaiter three questions: `await_ready()` (true means skip suspension),
  `await_suspend(handle)` if it does suspend, and `await_resume()` for the value of the whole expression. Real
  awaiters hand the handle to a thread pool, an I/O completion or a timer from `await_suspend`.
* `+co_return a * 6;+` calls `promise.return_value(42)` and then falls to `final_suspend`.

Pitfalls specific to coroutines:

* *Reference parameters dangle.* The frame copies the parameter, which is a reference, not the object it refers
  to. `overdue_notices(const std::vector<std::string>& members)` works above only because `members` outlives the
  generator; passing a temporary would leave a dangling reference after the first suspension. Take parameters by
  value in coroutines.
* A lambda coroutine's captures live in the lambda object, not in the frame; if the lambda is destroyed before the
  coroutine finishes, the captures dangle.
* `std::generator` is standardized in {cpp}23 and replaces the hand-written `Generator` here, but the library used
  for this page does not provide `<generator>`; the hand-written type above works with any {cpp}20 compiler.
