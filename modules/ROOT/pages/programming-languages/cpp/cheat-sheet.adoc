== Pitfalls at a Glance

Every row below is demonstrated, with compiler output, on the page named in the last column.

[cols="3,3,2"]
|===
|Trap |Fix |Page

|`+std::vector<int> v{3, 7};+` makes two elements, not three sevens
|Use parentheses for a count and a value: `+std::vector<int> v(3, 7);+`
|xref:programming-languages/cpp/constants-enumerations-and-initialization.adoc[Constants, Enumerations, and Initialization]

|`+flags & mask == mask+` tests the wrong thing
|Parenthesize: `+(flags & mask) == mask+`
|xref:programming-languages/cpp/operators-and-expressions.adoc[Operators and Expressions]

|`+-1 < 1u+` is false
|`std::cmp_less(a, b)`
|xref:programming-languages/cpp/basic-types-and-values.adoc[Basic Types and Values]

|Returning a `string_view` or `span` of a local
|Return the owning type, or take the view as a parameter only
|xref:programming-languages/cpp/strings-and-text.adoc[Strings and Text]

|Passing a derived object by value slices it
|Pass by reference or pointer; give polymorphic bases a virtual destructor
|xref:programming-languages/cpp/inheritance-and-polymorphism.adoc[Inheritance and Polymorphism]

|`+return std::move(local);+` blocks copy elision
|`+return local;+`
|xref:programming-languages/cpp/move-semantics-and-value-categories.adoc[Move Semantics and Value Categories]

|Two `shared_ptr` owning each other leak
|Make one direction a `weak_ptr`
|xref:programming-languages/cpp/memory-management-and-smart-pointers.adoc[Memory Management and Smart Pointers]

|Holding an iterator across a `push_back`
|Use indices, `reserve` first, or a node-based container
|xref:programming-languages/cpp/containers.adoc[Containers]

|Lazy view over a destroyed container
|Keep the owner alive; materialize with `ranges::to`
|xref:programming-languages/cpp/ranges-and-views.adoc[Ranges and Views]

|Plain `std::thread` destroyed while joinable terminates the program
|Use `std::jthread`
|xref:programming-languages/cpp/threads-and-synchronization.adoc[Threads and Synchronization]

|Ignored `std::async` future blocks in its destructor
|Keep the future and call `get()` when needed
|xref:programming-languages/cpp/async-futures-and-atomics.adoc[Async, Futures, and Atomics]

|Reference parameters of a coroutine dangle after the first suspension
|Take coroutine parameters by value
|xref:programming-languages/cpp/coroutines.adoc[Coroutines]

|Signed overflow is undefined; the optimizer relies on that
|Check before the operation; test with `-fsanitize=undefined`
|xref:programming-languages/cpp/performance.adoc[Performance]

|Header edit does not rebuild users
|Generate dependency files (`-MMD`) or use CMake or Ninja
|xref:programming-languages/cpp/build-and-tooling.adoc[Build and Tooling]
|===

== Choosing a Tool

[mermaid]
....
flowchart TB
    A["I need to..."] --> B{"own a resource?"}
    B -->|"sole owner"| U["unique_ptr, or a value member"]
    B -->|"shared owners"| S["shared_ptr + weak_ptr for back-links"]
    A --> C{"hold several things?"}
    C -->|"default"| V["vector"]
    C -->|"by key"| K["unordered_map, or map if ordered"]
    A --> D{"may fail?"}
    D -->|"anticipated"| E["expected or optional"]
    D -->|"exceptional"| X["exception + RAII"]
    A --> F{"run concurrently?"}
    F -->|"one result"| FU["async / future"]
    F -->|"shared data"| M["mutex + jthread, atomic for counters"]
    F -->|"lazy sequence"| CO["coroutine generator"]
....
