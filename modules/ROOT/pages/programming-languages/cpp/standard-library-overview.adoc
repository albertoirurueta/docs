== How the Library Is Organized

The standard library is organized by area rather than by one monolithic header; the pages in this section
mirror that layout roughly one-to-one:

[cols="1,2"]
|===
|Area |Representative headers

|Containers |`<vector>`, `<array>`, `<map>`, `<unordered_map>`, `<flat_map>`
|Iterators & algorithms |`<iterator>`, `<algorithm>`, `<numeric>`, `<ranges>`
|Strings & text |`<string>`, `<string_view>`, `<charconv>`, `<format>`, `<regex>`
|Vocabulary types |`<optional>`, `<variant>`, `<any>`, `<expected>`, `<tuple>`, `<utility>`
|Numerics |`<cmath>`, `<numbers>`, `<random>`, `<complex>`, `<bit>`
|I/O |`<iostream>`, `<fstream>`, `<sstream>`, `<print>`, `<filesystem>`
|Time |`<chrono>`
|Concurrency |`<thread>`, `<mutex>`, `<atomic>`, `<future>`, `<coroutine>`
|Memory |`<memory>`, `<memory_resource>`, `<new>`
|Error handling |`<exception>`, `<stdexcept>`, `<system_error>`, `<stacktrace>`
|Metaprogramming |`<type_traits>`, `<concepts>`, `<version>`
|===

== The `std` Namespace

Every standard-library name lives in `namespace std` (or a nested namespace like `std::chrono`,
`std::filesystem`, `std::ranges`) -- see
xref:programming-languages/cpp/namespaces-modules-and-the-preprocessor.adoc[Namespaces, Modules, and the
Preprocessor] for why `using namespace std;` at global/header scope is best avoided.

== C Compatibility Headers

{cpp} wraps most of the C standard library, offering it under two names: the `+<c*.h>+` C-style name (global
namespace) and the `+<c*>+` {cpp}-style name (`std::` namespace, and often also injected into the global namespace
as an implementation-defined extension):

[source,cpp]
----
#include <cmath>       // preferred: std::sqrt, std::pow, ...
#include <math.h>       // legacy C header: sqrt, pow, ... in the global namespace

#include <cstdlib>      // preferred: std::malloc, std::exit, ...
#include <cstring>       // preferred: std::memcpy, std::strlen, ...
----

Prefer the `+<c*>+` forms in new {cpp} code -- they guarantee the names are in `std::`, avoiding accidental global
namespace pollution.

== Freestanding vs. Hosted

A **hosted** implementation (what runs on a desktop/server OS) provides the *entire* standard library. A
**freestanding** implementation (embedded targets, kernels, some game-console SDKs) is only required to provide
a minimal subset -- core language support (`<type_traits>`, `<concepts>`, parts of `<utility>`/`<atomic>`), but
not, in general, containers, iostreams, or exceptions-dependent facilities. {cpp}23 formalized and grew exactly
which library parts freestanding implementations must supply (`std::vector`, `std::string_view`, and several
algorithms newly became freestanding-required).

== `std::size`, `std::data`, and `std::ssize`

Free functions ({cpp}17/20, `<iterator>`) that work uniformly across C arrays, containers, and
`std::initializer_list`, instead of a member call that arrays don't have:

[source,cpp]
----
#include <iterator>
#include <vector>
#include <cassert>

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    std::vector<int> v = {1, 2, 3};

    assert(std::size(arr) == 5);              // works on a raw array -- arr.size() would not compile
    assert(std::size(v) == 3);                 // works on any container with .size()
    assert(std::data(v) == &v[0]);              // pointer to the first element
    assert(std::ssize(v) == 3);                  // C++20: signed size, avoiding signed/unsigned comparison bugs
                                                   // (see std::cmp_less in Operators and Expressions)
    return 0;
}
----

== `std::hash` and Hashing Custom Types

Unordered containers (`std::unordered_map`/`std::unordered_set`, see
xref:programming-languages/cpp/containers.adoc[Containers]) need a `std::hash<Key>` specialization for any
custom key type:

[source,cpp]
----
#include <unordered_map>
#include <string>
#include <functional>

struct Point {
    int x, y;
    bool operator==(const Point&) const = default;
};

template <>
struct std::hash<Point> {
    std::size_t operator()(const Point& p) const noexcept {
        return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);   // a simple, illustrative combiner --
    }                                                                    // prefer boost::hash_combine or a
};                                                                        // well-reviewed combiner in production

int main() {
    std::unordered_map<Point, std::string> labels;
    labels[Point{0, 0}] = "origin";
    return 0;
}
----

== `std::exit` and `std::atexit`

[source,cpp]
----
#include <cstdlib>
#include <cstdio>

void cleanup() { std::puts("cleaning up"); }

int main() {
    std::atexit(cleanup);       // registered cleanup functions run, in reverse order, on normal termination
    if (false) {
        std::exit(EXIT_FAILURE);   // terminates immediately -- runs atexit handlers, but NOT local destructors
    }                                // on the current call stack (unlike a normal "return" from main)
    return 0;
}
----

`std::exit` skips stack unwinding entirely -- prefer throwing an exception or returning an error and letting
`main` return normally whenever local destructors (RAII cleanup) must run.

== Hashing Your Own Types, and Other Everyday Library Hooks

The standard library is a set of templates that are customized by *you* in a few well-defined ways: specializing
`std::hash`, providing `+operator<=>+`/`operator==`, supplying iterators, or giving a container a custom allocator or
comparator. The overview below shows the most common hook, hashing, with the inventory's `Isbn` and `Edition`
types, and the small utility functions that treat arrays and containers uniformly.

[mermaid]
....
flowchart LR
    K["key type: Isbn"] -->|"std::hash&lt;Isbn&gt;{}(key)"| H["size_t hash value"]
    H -->|"hash % bucket_count"| B["bucket index"]
    B --> C["bucket: chain of nodes"]
    C -->|"operator== on each candidate"| F["found / not found"]
....

.stdov.cpp
[source,cpp]
----
#include <cstdlib>
#include <functional>
#include <iterator>
#include <print>
#include <string>
#include <unordered_map>
#include <unordered_set>
#include <vector>

struct Isbn {
    std::string digits;
    bool operator==(const Isbn&) const = default;
};

// Specializing std::hash for a user type: the one specialization of std that the standard allows.
template <>
struct std::hash<Isbn> {
    std::size_t operator()(const Isbn& i) const noexcept { return std::hash<std::string>{}(i.digits); }
};

// Combining several members: a small hash_combine helper.
struct Edition {
    std::string title;
    int year;
    bool operator==(const Edition&) const = default;
};
struct EditionHash {
    std::size_t operator()(const Edition& e) const noexcept {
        std::size_t h = std::hash<std::string>{}(e.title);
        h ^= std::hash<int>{}(e.year) + 0x9e3779b97f4a7c15ULL + (h << 6) + (h >> 2);
        return h;
    }
};

void goodbye() { std::println("atexit handler runs after main returns"); }

int main() {
    std::unordered_map<Isbn, int> copies;
    copies[Isbn{"978-0-13-468599-1"}] = 3;
    copies[Isbn{"978-0-13-468599-1"}] += 1;
    std::println("entries: {}, copies: {}", copies.size(), copies[Isbn{"978-0-13-468599-1"}]);

    std::unordered_set<Edition, EditionHash> editions;
    editions.insert({"Dune", 1965});
    editions.insert({"Dune", 1965});
    editions.insert({"Dune", 1984});
    std::println("distinct editions: {}", editions.size());

    int raw[] = {5, 6, 7};
    std::vector<int> v{1, 2, 3, 4};
    std::println("size/ssize: {} {}  data non-null: {}  ssize is signed: {}", std::size(raw), std::ssize(v),
                 std::data(v) != nullptr, std::ssize(v) - 10 < 0);

    std::atexit(goodbye);
    std::println("main is ending");
}
----

[source,console]
----
$ clang++ -std=c++23 -Wall -Wextra stdov.cpp -o stdov
$ ./stdov
entries: 1, copies: 4
distinct editions: 2
size/ssize: 3 4  data non-null: true  ssize is signed: true
main is ending
atexit handler runs after main returns
----

* Programs may not add declarations to namespace `std`, with one deliberate exception: specializing a standard
  *class template* for a user-defined type, as with `template <> struct std::hash<Isbn>`. Everything else (adding
  an overload of `std::swap` or a function to `std`) is undefined behaviour; put `swap` in your own namespace and
  let ADL find it.
* A hash and its equality must agree: values that compare equal must hash equally. `Edition` hashes both members
  with a hash-combine step; combining by simple `xor` of two member hashes makes `+{a, b}+` and `+{b, a}+` collide
  and is a common mistake.
* The functions `std::size`, `std::ssize`, `std::data` and `std::empty` work on containers, built-in arrays and
  anything with the right members, which is what lets generic code treat a `std::vector` and a C array the same.
  `std::ssize` returns a *signed* value, avoiding the `i < v.size()` sign-compare warning in index loops.
* `std::atexit` handlers run when `main` returns or `std::exit` is called, in reverse registration order, but
  not when the program calls `std::abort` or `std::quick_exit`; static objects are destroyed after the handlers
  registered after them. Prefer RAII to atexit for cleanup.
* A *freestanding* implementation provides only a subset of the library (no `<iostream>`, no containers on most
  targets); a *hosted* one, which is what desktop and server programs use, provides all of it.
