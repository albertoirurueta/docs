== Iterator Categories

Algorithms are written against the *weakest* iterator category they need, so they work across the widest range
of containers. Each category is a strict superset of the guarantees below it:

image::cpp-iterator-category-hierarchy.svg[Iterator category hierarchy: input and output iterators at the base; forward iterators add multi-pass guarantees; bidirectional adds reverse traversal; random-access adds O(1) indexed jumps and iterator arithmetic]

* **Input** -- single-pass, read-only (`std::istream_iterator`).
* **Output** -- single-pass, write-only (`std::ostream_iterator`, `std::back_inserter`).
* **Forward** -- multi-pass, read (`std::forward_list::iterator`).
* **Bidirectional** -- forward plus `--` (`std::list::iterator`, `std::map::iterator`).
* **Random-access** -- bidirectional plus `O(1)` `it + n`/`it[n]` (`std::vector::iterator`, raw pointers).
* **Contiguous** (C++20) -- random-access plus a guarantee the elements are laid out contiguously in memory
  (`std::vector::iterator`, `std::array::iterator`, but not `std::deque::iterator`).

== `begin`/`end` and Non-Member Access

[source,cpp]
----
#include <vector>
#include <iterator>

std::vector<int> v = {1, 2, 3};
auto it1 = v.begin();      // member function
auto it2 = std::begin(v);   // free function -- also works on a raw C array, which has no .begin() member
auto it3 = std::cbegin(v);   // always a const_iterator, even if v is non-const
----

Range-`for` (see xref:programming-languages/cpp/control-flow.adoc[Control Flow]) uses the non-member
`begin`/`end` internally, found via ADL -- which is exactly why it works on raw arrays too.

== `<algorithm>` and `<numeric>`

[source,cpp]
----
#include <algorithm>
#include <numeric>
#include <vector>
#include <iostream>

int main() {
    std::vector<int> v = {5, 3, 1, 4, 2};

    std::sort(v.begin(), v.end());                      // {1, 2, 3, 4, 5}
    auto it = std::find(v.begin(), v.end(), 3);           // iterator to the found 3
    bool has4 = std::binary_search(v.begin(), v.end(), 4);  // requires a sorted range: true
    auto maxIt = std::max_element(v.begin(), v.end());     // iterator to 5

    std::vector<int> a = {1, 3, 5}, b = {2, 3, 4}, result;
    std::set_intersection(a.begin(), a.end(), b.begin(), b.end(), std::back_inserter(result));  // {3}

    std::vector<int> seq(5);
    std::iota(seq.begin(), seq.end(), 1);                  // {1, 2, 3, 4, 5}
    std::fill(seq.begin(), seq.end(), 0);                    // {0, 0, 0, 0, 0}
    std::generate(seq.begin(), seq.end(), [n = 0]() mutable { return n++; });   // {0, 1, 2, 3, 4}

    int sum = std::accumulate(v.begin(), v.end(), 0);        // 15
    (void)it; (void)has4; (void)maxIt; (void)sum;
    for (int x : result) std::cout << x << ' ';
}
----

== Insert Iterators

`std::back_inserter`/`std::front_inserter`/`std::inserter` adapt an *output* iterator so an algorithm can grow a
container instead of overwriting a fixed range -- used with `std::set_intersection` above, and idiomatic
anywhere an algorithm's output size isn't known ahead of time:

[source,cpp]
----
#include <algorithm>
#include <vector>
#include <iterator>

std::vector<int> source = {1, 2, 3};
std::vector<int> destination;
std::copy(source.begin(), source.end(), std::back_inserter(destination));   // grows destination as needed,
                                                                               // instead of requiring it to
                                                                               // already have 3 elements
----

== Writing a Random-Access Iterator

[source,cpp]
----
#include <iterator>
#include <cstddef>

class IntRangeIterator {
public:
    using iterator_category = std::random_access_iterator_tag;
    using value_type = int;
    using difference_type = std::ptrdiff_t;
    using pointer = const int*;
    using reference = const int&;

    explicit IntRangeIterator(int value) : value_(value) {}
    int operator*() const { return value_; }
    IntRangeIterator& operator++() { ++value_; return *this; }
    bool operator==(const IntRangeIterator&) const = default;
    IntRangeIterator operator+(difference_type n) const { return IntRangeIterator(value_ + static_cast<int>(n)); }
    difference_type operator-(const IntRangeIterator& other) const { return value_ - other.value_; }

private:
    int value_;
};
----

C++20's `std::iterator_traits` can deduce most of these members automatically for a well-formed iterator,
reducing the boilerplate above -- see xref:programming-languages/cpp/ranges-and-views.adoc[Ranges and Views] for
the concept-based (`std::input_iterator`, `std::random_access_iterator`, ...) way ranges validate an iterator
type instead.

== `std::erase_if`

C++20 unifies the "erase matching elements" idiom (previously the notoriously named erase-remove idiom) into
one free function per container category:

[source,cpp]
----
#include <vector>
#include <algorithm>

std::vector<int> v = {1, 2, 3, 4, 5, 6};
std::erase_if(v, [](int x) { return x % 2 == 0; });   // {1, 3, 5} -- replaces
                                                        // v.erase(std::remove_if(v.begin(), v.end(), pred), v.end())
----
