== `chrono::duration`

A `duration` is a compile-time-checked span of time -- a count plus a ratio (seconds, milliseconds, ...), so
mixing units is either a safe implicit conversion or a compile error, never a silent unit mismatch:

[source,cpp]
----
#include <chrono>
#include <iostream>

int main() {
    using namespace std::chrono_literals;

    std::chrono::seconds s = 5s;
    std::chrono::milliseconds ms = s;             // implicit widening conversion: 5000ms
    // std::chrono::seconds bad = ms;              // error: narrowing (ms -> s) needs an explicit cast

    auto rounded = std::chrono::duration_cast<std::chrono::seconds>(1500ms);  // explicit: 1s (truncates)
    std::cout << s.count() << ' ' << ms.count() << ' ' << rounded.count() << '\n';
}
----

== Clocks and `time_point`

A `time_point` is a point on a specific clock's timeline -- three standard clocks cover almost every need:

[source,cpp]
----
#include <chrono>

auto wallClock = std::chrono::system_clock::now();    // wall-clock time, convertible to calendar time; CAN
                                                          // jump (NTP sync, manual change) -- not for measuring
                                                          // elapsed durations
auto monotonic = std::chrono::steady_clock::now();      // never jumps backward -- the right clock for measuring
                                                          // elapsed time/timeouts
auto highRes = std::chrono::high_resolution_clock::now(); // often an alias for one of the above; prefer
                                                             // steady_clock explicitly when steadiness matters
----

== Measuring Execution Time

[source,cpp]
----
#include <chrono>
#include <iostream>
#include <thread>

int main() {
    auto start = std::chrono::steady_clock::now();
    std::this_thread::sleep_for(std::chrono::milliseconds(10));
    auto end = std::chrono::steady_clock::now();

    auto elapsed = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    std::cout << elapsed.count() << " microseconds\n";
}
----

== Calendars: `year_month_day`

{cpp}20 added a full calendar library on top of `chrono`, replacing manual day/month/year arithmetic and the
error-prone `struct tm`:

[source,cpp]
----
#include <chrono>
#include <iostream>

int main() {
    using namespace std::chrono;

    year_month_day today{2024y, January, 15d};
    year_month_day lastDay = today.year() / today.month() / last;   // last day of that month
    std::cout << static_cast<unsigned>(lastDay.day()) << '\n';            // 31

    sys_days asDays = today;                                          // convert to a time_point at midnight
    sys_days nextWeek = asDays + days{7};
    year_month_day nextWeekYmd = nextWeek;
    std::cout << static_cast<unsigned>(nextWeekYmd.day()) << '\n';         // 22
}
----

== Time Zones

`<chrono>`&#39;s time-zone database ({cpp}20) converts between UTC and a named IANA zone -- no more manually applying
UTC offsets:

[source,cpp]
----
#include <chrono>
#include <iostream>

int main() {
    using namespace std::chrono;
    // requires a populated IANA tzdata database on the host system
    const time_zone* newYork = locate_zone("America/New_York");
    zoned_time zoned{newYork, system_clock::now()};
    std::cout << zoned << '\n';
}
----

NOTE: the time-zone database requires the platform's IANA tzdata (or the bundled fallback, depending on
standard-library configuration) to actually be installed -- verify with a small test program before relying on
it in a deployed environment, as availability varies by OS/container image.

== Formatting and Parsing Times

`std::format`/`std::chrono` compose directly via `std::formatter` specializations the library already provides
for chrono types:

[source,cpp]
----
#include <chrono>
#include <format>
#include <iostream>

int main() {
    using namespace std::chrono;
    year_month_day date{2024y, March, 5d};
    std::cout << std::format("{:%Y-%m-%d}", date) << '\n';    // 2024-03-05

    auto duration = 90min;
    std::cout << std::format("{:%H:%M}", duration) << '\n';    // 01:30
}
----

== Due Dates and Timing, Verified

`<chrono>` separates three ideas that are usually blurred together: a *duration* (how long), a *time point* (when,
relative to a clock's epoch) and a *calendar date* (a human label for a day). Each is a distinct type, so the
compiler rejects nonsense such as adding two time points or treating seconds as days.

[mermaid]
....
flowchart LR
    D["duration<br/>count + ratio<br/>(21 days, 90 s)"] --> TP["time_point<br/>clock + duration since epoch"]
    TP -->|"floor to days: sys_days"| CAL["year_month_day<br/>2026-11-10"]
    CAL -->|"sys_days{ymd}"| TP
    CLK["clock<br/>system_clock: wall time, can jump<br/>steady_clock: monotonic, for measuring"] --> TP
....

.chrono.cpp
[source,cpp]
----
#include <chrono>
#include <print>
#include <thread>

using namespace std::chrono;
using namespace std::chrono_literals;

// A loan is due after a number of days; due dates use calendar arithmetic, not seconds.
sys_days due_date(sys_days borrowed, days period) { return borrowed + period; }

int main() {
    // Durations are a count and a ratio; conversions that lose precision need duration_cast.
    seconds s = 90s;
    minutes m = duration_cast<minutes>(s);          // truncates toward zero: 1 minute
    milliseconds ms = s;                            // lossless conversions are implicit
    std::println("{} = {} = {}", s, ms, m);
    auto d = 1h + 30min + 15s;
    std::println("{} in seconds: {}", d, duration_cast<seconds>(d).count());
    std::println("floating duration: {}", duration<double, std::ratio<3600>>(d).count());

    // Calendar types.
    year_month_day borrowed = 2026y / November / 10;
    sys_days due = due_date(sys_days{borrowed}, days{21});
    year_month_day due_ymd{due};
    std::println("borrowed {} due {} ({})", borrowed, due_ymd, weekday{due});
    std::println("valid date check: {} {}", year_month_day{2026y / February / 29}.ok(),
                 year_month_day{2028y / February / 29}.ok());
    std::println("last day of February 2028: {}", year_month_day_last{2028y / February / last}.day());

    // Formatting a duration and a time_point.
    sys_seconds epoch{};
    std::println("epoch: {:%Y-%m-%d %H:%M:%S}", epoch);

    // steady_clock for measuring elapsed time: never goes backward, unlike system_clock.
    auto t0 = steady_clock::now();
    std::this_thread::sleep_for(20ms);
    auto elapsed = duration_cast<milliseconds>(steady_clock::now() - t0);
    std::println("slept at least 20 ms: {}", elapsed >= 20ms);
    std::println("steady_clock is steady: {}, system_clock is steady: {}", steady_clock::is_steady,
                 system_clock::is_steady);
}
----

* A duration stores a count and a compile-time ratio. Converting to a *coarser* unit (`seconds` to `minutes`) can
  lose information, so it requires `duration_cast` and truncates toward zero; converting to a finer unit
  (`seconds` to `milliseconds`) is implicit and exact. The `1.5041666666666667` line is a floating-point duration,
  where no truncation takes place.
* Due dates are calendar arithmetic: add `+days{21}+` to a `sys_days` (a time point with day resolution) and convert
  back to `year_month_day`. Adding `days` is exact. For month or year arithmetic use `pass:c[year_month_day + months]`
  and check `.ok()` afterwards (31 January plus one month is not a valid date), because a `std::chrono::months`
  duration is a fixed average length of 30.436875 days, not a calendar month.
* `+year_month_day{...}.ok()+` validates a date: 29 February 2026 does not exist, 2028 is a leap year. The
  `/` operator builds dates readably (`2026y / November / 10`), in any order that is unambiguous.
* Use `steady_clock` to measure elapsed time. It never goes backwards; `system_clock` follows the wall clock, which
  the user or NTP may adjust in the middle of your measurement.
* This standard library provides durations, clocks, calendars and formatting, but not the time-zone database
  (`std::chrono::locate_zone`, `zoned_time`); the compiler used here rejects them as undeclared. Zone support
  needs a recent libstdc{plus}{plus} or MSVC, or the Howard Hinnant `date` library that the standard facility came from.
  Store instants in UTC (`system_clock`) and convert to a zone only for display.
