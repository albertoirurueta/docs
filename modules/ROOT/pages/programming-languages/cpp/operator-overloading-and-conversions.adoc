== Member vs. Non-Member Operators

Binary operators can be a member (the left operand is implicit `+*this+`) or a free function; a free function is
required whenever the left operand isn't your type (as with `std::ostream <<`), and is the conventional choice
even when a member *would* work, so both operand types get the same implicit conversions applied:

[source,cpp]
----
class Vector2D {
public:
    Vector2D(double x, double y) : x_(x), y_(y) {}

    Vector2D operator+(const Vector2D& other) const {   // member: works for v1 + v2
        return Vector2D(x_ + other.x_, y_ + other.y_);
    }

    double x() const { return x_; }
    double y() const { return y_; }
private:
    double x_, y_;
};

Vector2D operator*(double scalar, const Vector2D& v) {   // free function: needed for 2.0 * v
    return Vector2D(scalar * v.x(), scalar * v.y());      // (v * 2.0 could be a member; scalar * v cannot,
}                                                           // since double isn't Vector2D)
----

== `+operator<=>+` and Defaulted Comparisons

Covered briefly in xref:programming-languages/cpp/operators-and-expressions.adoc[Operators and Expressions];
hand-writing `+<=>+` (rather than `= default`) lets a type return a specific ordering category:

[source,cpp]
----
#include <compare>

class Fraction {
public:
    Fraction(int num, int den) : num_(num), den_(den) {
        if (den_ < 0) { num_ = -num_; den_ = -den_; }   // normalize the sign into the numerator -- otherwise
    }                                                    // cross-multiplying by a negative flips the ordering

    std::strong_ordering operator<=>(const Fraction& other) const {
        long long lhs = static_cast<long long>(num_) * other.den_;
        long long rhs = static_cast<long long>(other.num_) * den_;
        return lhs <=> rhs;                    // cross-multiply to compare without floating-point division
    }
    bool operator==(const Fraction& other) const {
        return (*this <=> other) == std::strong_ordering::equal;
    }

private:
    int num_, den_;
};
----

`std::strong_ordering` (a total order, substitutable equality), `std::weak_ordering` (a total order, equal
values need not be substitutable), and `std::partial_ordering` (comparisons can be "unordered", e.g. `NaN`) are
the three categories `+<=>+` may return.

== `operator[]` (Multidimensional in {cpp}23)

{cpp}23 allows `operator[]` to take *multiple* arguments (previously limited to exactly one), so a matrix-like
type no longer needs `operator()` or chained single-index calls as a workaround:

[source,cpp]
----
#include <vector>

class Matrix {
public:
    Matrix(std::size_t rows, std::size_t cols)
        : rows_(rows), cols_(cols), data_(rows * cols, 0.0) {}

    double& operator[](std::size_t row, std::size_t col) {          // C++23: two-argument operator[]
        return data_[row * cols_ + col];
    }
    double operator[](std::size_t row, std::size_t col) const {
        return data_[row * cols_ + col];
    }

    std::size_t rows() const { return rows_; }
    std::size_t cols() const { return cols_; }

private:
    std::size_t rows_, cols_;
    std::vector<double> data_;
};
----

== `operator()`

Overloading the call operator makes an object callable like a function -- a **function object** or **functor**,
usable anywhere a callable is expected (algorithms, `std::function`, sorting comparators):

[source,cpp]
----
class Adder {
public:
    explicit Adder(int amount) : amount_(amount) {}
    int operator()(int value) const { return value + amount_; }
private:
    int amount_;
};

// Adder addFive(5); addFive(10) == 15;
----

== Conversion Operators and `explicit`

A conversion operator lets a user-defined type convert *to* another type; `explicit` on it ({cpp}11) blocks
*implicit* use the same way it does on constructors:

[source,cpp]
----
class Fraction2 {
public:
    Fraction2(int num, int den) : num_(num), den_(den) {}

    explicit operator double() const {           // explicit: must write static_cast<double>(f), not "double d = f;"
        return static_cast<double>(num_) / den_;
    }
    explicit operator bool() const { return num_ != 0; }   // common idiom: explicit operator bool for
                                                             // "is this valid/non-empty" checks (see std::optional)
private:
    int num_, den_;
};
----

== Stream Operators

Overloading `<<`/`>>` for `std::ostream`/`std::istream` is what makes a type printable/readable with the usual
stream syntax -- always as a free function, since the left operand is the stream, not your type:

[source,cpp]
----
#include <iostream>

class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}
    int x() const { return x_; }
    int y() const { return y_; }
private:
    int x_, y_;
};

std::ostream& operator<<(std::ostream& os, const Point& p) {
    return os << '(' << p.x() << ", " << p.y() << ')';
}

std::istream& operator>>(std::istream& is, Point& p) {
    int x, y;
    if (is >> x >> y) { p = Point(x, y); }
    return is;
}
----

== Comparison, Subscripts, Call and Conversion Operators in One Example

Overloaded operators are ordinary functions with special names, and the compiler rewrites expressions into calls to
them. Since {cpp}20 the most important rewriting is for comparison: `a < b` becomes `+(a <=> b) < 0+`, and `a != b`
becomes `!(a == b)`, so one `+operator<=>+` and one `operator==` provide all six operators.

.opov.cpp
[source,cpp]
----
#include <array>
#include <compare>
#include <iostream>
#include <print>
#include <string>
#include <utility>
#include <vector>

// Isbn: strongly typed wrapper with defaulted comparison and a stream operator.
class Isbn {
public:
    explicit Isbn(std::string digits) : digits_(std::move(digits)) {}
    auto operator<=>(const Isbn&) const = default;
    friend std::ostream& operator<<(std::ostream& os, const Isbn& i) { return os << "ISBN " << i.digits_; }
    explicit operator bool() const { return !digits_.empty(); }   // explicit: usable in `if`, not in arithmetic

private:
    std::string digits_;
};

// A custom ordering where only the year matters: <=> returning a weak ordering.
struct ByYear {
    std::string title;
    int year;
    std::weak_ordering operator<=>(const ByYear& o) const { return year <=> o.year; }
    bool operator==(const ByYear& o) const { return year == o.year; }
};

// Shelf grid indexed with C++23 multidimensional operator[].
class Grid {
public:
    Grid(std::size_t rows, std::size_t cols) : cols_(cols), cells_(rows * cols, 0) {}
    int& operator[](std::size_t r, std::size_t c) { return cells_[r * cols_ + c]; }
    int operator[](std::size_t r, std::size_t c) const { return cells_[r * cols_ + c]; }

private:
    std::size_t cols_;
    std::vector<int> cells_;
};

// operator(): a stateful function object, here counting how many titles it has seen.
struct TitleCounter {
    int seen = 0;
    bool operator()(const std::string& t) { ++seen; return t.starts_with("The"); }
};

int main() {
    Isbn a("978-0-13-468599-1"), b("978-0-13-468599-2");
    std::cout << a << (a < b ? " < " : " >= ") << b << "\n";
    std::println("equal: {}  three-way is less: {}", a == b, (a <=> b) < 0);
    Isbn empty("");
    if (!empty) std::println("an empty ISBN converts to false in a condition");

    ByYear x{"Emma", 1815}, y{"Persuasion", 1815};
    std::println("same year: equal={} less={} (weak ordering: equivalent, not identical)", x == y, x < y);

    Grid g(3, 4);
    g[1, 2] = 42;
    std::println("g[1, 2] = {}, g[0, 0] = {}", g[1, 2], std::as_const(g)[0, 0]);

    TitleCounter counter;
    std::vector<std::string> titles{"The Hobbit", "Dune", "The Stand"};
    int the_count = 0;
    for (const auto& t : titles) the_count += counter(t);
    std::println("{} titles start with 'The', counter saw {}", the_count, counter.seen);
}
----

* `+auto operator<=>(const Isbn&) const = default;+` compares the members in declaration order and also declares a
  defaulted `operator==`. The *return type* of `+<=>+` carries meaning: `strong_ordering` means equal values are
  indistinguishable, `weak_ordering` (as in `ByYear`) means two values can be equivalent without being identical,
  and `partial_ordering` (floating point) admits "unordered" for `NaN`. Note that a user-written `+<=>+` does *not*
  declare `==`; `ByYear` therefore defines it separately.
* `operator<<` for a stream must be a free function (or a friend), because the left operand is the stream. Defining
  it as a hidden friend inside the class keeps it out of the surrounding namespace and still found by ADL.
* `explicit operator bool` allows `if (isbn)` and `!isbn` but blocks `pass:c[isbn + 1]` and `int n = isbn;`. A non-explicit
  conversion operator is almost always a bug waiting to happen; combined with other implicit conversions it can
  make overloaded calls ambiguous.
* `g[1, 2]` is the {cpp}23 multidimensional subscript: `operator[]` may now take any number of arguments, so a
  matrix no longer needs `operator()` or a proxy object. A comma inside `[]` is no longer the comma operator.
* A class with `operator()` is a *function object*. Unlike a lambda it can be named, extended and given several
  overloads, and the state (`seen`) lives in the object, which is why `counter` must be taken by reference when
  passing it to an algorithm that would otherwise copy it.

Guidelines that follow: overload an operator only when its meaning is unsurprising for the type; keep `pass:c[+]` and `pass:c[+=]`
consistent (implement `pass:c[+]` using `pass:c[+=]`); never overload `&&`, `||` or `,`, which lose their short-circuit and
sequencing behaviour; and prefer a named function (`isbn.digits()`) when an operator would hide a cost.
