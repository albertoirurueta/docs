== RAII

Covered fully in xref:programming-languages/cpp/memory-management-and-smart-pointers.adoc[Memory Management and
Smart Pointers] -- the foundational {cpp} idiom nearly everything below builds on.

== Pimpl (Pointer to Implementation)

Hides a class's private implementation details behind an opaque pointer, so changing them doesn't force every
includer to recompile -- a real compile-time/ABI-stability win, not just an aesthetic one:

[source,cpp]
----
// widget.h -- unchanged even if Impl's members change; includers never see Impl's definition
#include <memory>
class Widget {
public:
    Widget();
    ~Widget();                        // must be declared here, DEFINED in the .cpp (see below)
    void doSomething();
private:
    class Impl;                        // incomplete type -- fine as a unique_ptr target
    std::unique_ptr<Impl> impl_;
};
----

[source,cpp]
----
// widget.cpp
#include "widget.h"

class Widget::Impl {
public:
    void doSomething() { /* real implementation, changeable without recompiling includers */ }
};

Widget::Widget() : impl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;    // MUST be defined where Impl is complete -- unique_ptr's destructor needs
                                   // to know Impl's full definition, which the header alone doesn't provide
void Widget::doSomething() { impl_->doSomething(); }
----

== NVI (Non-Virtual Interface)

The public interface is non-virtual and calls a private/protected virtual "hook" -- the base class controls
*when* and *how* the hook runs (validation, logging, timing) around it, something a plain public virtual
function cannot enforce:

[source,cpp]
----
class Shape {
public:
    double area() const {              // public, non-virtual -- callers use only this
        validateState();
        return computeArea();            // the actual customization point
    }
    virtual ~Shape() = default;

private:
    virtual double computeArea() const = 0;   // private virtual -- derived classes override, but cannot
    void validateState() const { /* ... */ }    // be called directly, and cannot skip validateState()
};
----

== CRTP and Static Polymorphism (with `deducing this`)

The **Curiously Recurring Template Pattern** gets polymorphism-like customization resolved at *compile time*,
with no vtable/virtual-call overhead:

[source,cpp]
----
template <typename Derived>
class Comparable {
public:
    bool operator<(const Derived& other) const {
        return static_cast<const Derived&>(*this).compareTo(other) < 0;   // "virtual" call resolved statically
    }
};

class Version : public Comparable<Version> {
public:
    explicit Version(int v) : value_(v) {}
    int compareTo(const Version& other) const { return value_ - other.value_; }
private:
    int value_;
};
----

{cpp}23's **deducing this** (`this Self&& self` as an explicit first parameter) replaces most CRTP use cases with
plain, more readable inheritance:

[source,cpp]
----
class ComparableV2 {
public:
    template <typename Self>
    bool operator<(this const Self& self, const Self& other) {   // "self" deduces to the most-derived type --
        return self.compareTo(other) < 0;                          // no CRTP base-template needed at all
    }
};

class VersionV2 : public ComparableV2 {
public:
    explicit VersionV2(int v) : value_(v) {}
    int compareTo(const VersionV2& other) const { return value_ - other.value_; }
private:
    int value_;
};
----

== Mixins

Small, composable base classes that each add one capability, combined via multiple inheritance -- distinct from
CRTP in that a mixin doesn't need to know the derived type at all:

[source,cpp]
----
class Loggable {
public:
    void log(const std::string& msg) const { std::cout << "[log] " << msg << '\n'; }
};
class Serializable {
public:
    std::string serialize() const { return "{}"; }
};

class Widget2 : public Loggable, public Serializable {   // gains both capabilities with no code duplication
};
----

== Type Erasure

Hides a concrete type behind a uniform interface, without an explicit inheritance relationship -- `std::function`
(xref:programming-languages/cpp/functions-and-lambdas.adoc[Functions and Lambdas]) and `std::any`
(xref:programming-languages/cpp/vocabulary-types.adoc[Vocabulary Types]) are standard-library examples; the
pattern itself:

[source,cpp]
----
#include <memory>
#include <string>

class Drawable {
public:
    template <typename T>
    Drawable(T obj) : self_(std::make_unique<Model<T>>(std::move(obj))) {}   // T need not derive from anything
    std::string draw() const { return self_->draw(); }

private:
    struct Concept { virtual ~Concept() = default; virtual std::string draw() const = 0; };
    template <typename T>
    struct Model : Concept {
        explicit Model(T obj) : obj_(std::move(obj)) {}
        std::string draw() const override { return obj_.draw(); }
        T obj_;
    };
    std::unique_ptr<Concept> self_;
};
// any type with a "std::string draw() const" method can be stored in a Drawable, with no shared base class
----

== The Named-Parameter Idiom

{cpp} has no native named arguments; a builder-style chain simulates them for constructors/functions with many
optional parameters:

[source,cpp]
----
class HttpRequestBuilder {
public:
    HttpRequestBuilder& url(std::string u) { url_ = std::move(u); return *this; }
    HttpRequestBuilder& timeout(int seconds) { timeout_ = seconds; return *this; }
    HttpRequestBuilder& retries(int n) { retries_ = n; return *this; }
private:
    std::string url_;
    int timeout_ = 30, retries_ = 0;
};

// HttpRequestBuilder{}.url("https://example.com").timeout(5).retries(3);
----

Designated initializers ({cpp}20, see
xref:programming-languages/cpp/constants-enumerations-and-initialization.adoc[Constants, Enumerations, and
Initialization]) cover the simpler case of an aggregate with named fields, with no builder needed.

== Attorney-Client

Grants one specific class *limited*, explicit access to another's private members, narrower than a blanket
`friend`:

[source,cpp]
----
class Widget3 {
private:
    void internalReset() { /* ... */ }
    friend class WidgetAttorney;   // only WidgetAttorney (the "attorney"), not everyone, gets in
};

class WidgetAttorney {              // the ONLY class allowed to call internalReset() -- acts as a
public:                              // narrow, audited gatekeeper instead of a wide-open friend declaration
    static void resetFor(Widget3& w) { w.internalReset(); }
};
----

== Factories Without `if`/`else`

A registry of creation functions, keyed by a discriminator, replaces a long `if`/`else`-`if` (or `switch`)
chain and lets new types register themselves without editing the factory's own code:

[source,cpp]
----
#include <functional>
#include <unordered_map>
#include <memory>
#include <string>

class Shape { public: virtual ~Shape() = default; };
class Circle : public Shape {};
class Square : public Shape {};

class ShapeFactory {
public:
    using Creator = std::function<std::unique_ptr<Shape>()>;

    void registerShape(const std::string& name, Creator creator) {
        creators_[name] = std::move(creator);
    }
    std::unique_ptr<Shape> create(const std::string& name) const {
        auto it = creators_.find(name);
        return it != creators_.end() ? it->second() : nullptr;
    }
private:
    std::unordered_map<std::string, Creator> creators_;
};

// factory.registerShape("circle", [] { return std::make_unique<Circle>(); });
// factory.registerShape("square", [] { return std::make_unique<Square>(); });
// auto shape = factory.create("circle");
----

== Thread-Safe Singleton

Since {cpp}11, a function-local `static` is guaranteed to be initialized exactly once, even under concurrent
first-time access -- no manual double-checked locking needed:

[source,cpp]
----
class Logger {
public:
    static Logger& instance() {
        static Logger singleton;    // thread-safe initialization guaranteed by the language itself (C++11+)
        return singleton;
    }
    Logger(const Logger&) = delete;
    Logger& operator=(const Logger&) = delete;
private:
    Logger() = default;
};
----

== Five Idioms in One Compilable File

Idioms are the recurring solutions {cpp} developers reach for because the language has no direct feature for them.
The program below implements five of them for the inventory: Pimpl, NVI, CRTP (with {cpp}23 deducing this), type
erasure, and named parameters through designated initializers.

[mermaid]
....

    end
    subgraph nvi["NVI"]
      direction LR
      PUB["export_all()<br/>public, non-virtual"] -->|"calls"| PV1["header() virtual"]
      PUB --> PV2["format_item() virtual"]
    end

      CN --> M3["Model of Poster"]
    end
....

.patterns.cpp
[source,cpp]
----
#include <format>
#include <memory>
#include <print>
#include <string>
#include <vector>

// ---- Pimpl: the public class exposes no private members; the implementation can change without recompiling users.
class Catalog {
public:
    Catalog();
    ~Catalog();                          // must be defined where Impl is complete
    Catalog(Catalog&&) noexcept;
    Catalog& operator=(Catalog&&) noexcept;
    void add(std::string title);
    std::size_t size() const;

private:
    struct Impl;
    std::unique_ptr<Impl> impl_;
};
// (normally in catalog.cpp)
struct Catalog::Impl { std::vector<std::string> titles; };
Catalog::Catalog() : impl_(std::make_unique<Impl>()) {}
Catalog::~Catalog() = default;
Catalog::Catalog(Catalog&&) noexcept = default;
Catalog& Catalog::operator=(Catalog&&) noexcept = default;
void Catalog::add(std::string t) { impl_->titles.push_back(std::move(t)); }
std::size_t Catalog::size() const { return impl_->titles.size(); }

// ---- NVI: public non-virtual function wraps a private virtual one, so the base keeps control of pre/post-conditions.
class Exporter {
public:
    virtual ~Exporter() = default;
    std::string export_all(const std::vector<std::string>& titles) const {
        std::string out = header();
        for (const auto& t : titles) out += format_item(t);
        return out + "-- " + std::to_string(titles.size()) + " items --";
    }

private:
    virtual std::string header() const { return ""; }
    virtual std::string format_item(const std::string& t) const = 0;
};
class CsvExporter : public Exporter {
    std::string header() const override { return "title\n"; }
    std::string format_item(const std::string& t) const override { return t + "\n"; }
};

// ---- CRTP with C++23 deducing this: static polymorphism, no vtable.
template <typename Derived>
struct Printable {
    void print() const { std::println("{}", static_cast<const Derived&>(*this).describe()); }
};
struct Book : Printable<Book> {
    std::string describe() const { return "Book: Dune"; }
};
struct Dvd {
    // Deducing this: one function template, `self` has the derived type.
    void print(this const auto& self) { std::println("{}", self.describe()); }
    std::string describe() const { return "Dvd: Alien"; }
};

// ---- Type erasure: unrelated types behind a value-semantic interface, no common base required.
class Describable {
public:
    template <typename T>
    Describable(T x) : self_(std::make_shared<Model<T>>(std::move(x))) {}
    std::string describe() const { return self_->describe(); }

private:
    struct Concept {
        virtual ~Concept() = default;
        virtual std::string describe() const = 0;
    };
    template <typename T>
    struct Model : Concept {
        explicit Model(T v) : value(std::move(v)) {}
        std::string describe() const override { return value.describe(); }
        T value;
    };
    std::shared_ptr<const Concept> self_;
};
struct Poster { std::string describe() const { return "Poster: Metropolis"; } };

// ---- Named-parameter idiom with designated initializers (C++20).
struct LoanOptions { int days = 14; bool renewable = true; std::string note = ""; };
std::string make_loan(const std::string& title, LoanOptions o = {}) {
    return std::format("{}: {} days, renewable={}, note='{}'", title, o.days, o.renewable, o.note);
}

int main() {
    Catalog c;
    c.add("Dune"); c.add("Emma");
    Catalog moved = std::move(c);
    std::println("pimpl catalog size {}", moved.size());

    CsvExporter csv;
    std::print("{}\n", csv.export_all({"Dune", "Emma"}));

    Book{}.print();
    Dvd{}.print();

    std::vector<Describable> items{Book{}, Dvd{}, Poster{}};
    for (const auto& i : items) std::println("erased: {}", i.describe());

    std::println("{}", make_loan("Dune"));
    std::println("{}", make_loan("Emma", {.days = 7, .note = "reserved"}));
}
----

* *Pimpl* hides the data members behind a pointer to an incomplete type, so changing them does not force every
  includer to recompile and the header exposes no implementation headers. The pitfalls are visible in the code:
  the destructor and move operations must be *defined* where `Impl` is complete (`= default` in the source file),
  otherwise the deleter of `unique_ptr` needs a complete type at the point of the implicit definition and compilation
  fails. The cost is one allocation and one indirection.
* *NVI* (non-virtual interface) makes the public function non-virtual and the customization points private virtual
  functions. The base class keeps the algorithm and any invariant (the header, the item count) and derived classes
  can only fill in the steps. `CsvExporter` overrides private virtuals, which is legal.
* *CRTP* gives a base class access to the derived type at compile time. `Printable<Book>::print` calls
  `describe()` with no virtual call and no vptr. The {cpp}23 `this auto self` form (`Dvd::print`) removes the base
  class entirely, because an explicit object parameter deduces the type of the object the function is called on.
* *Type erasure* (`Describable`) gives unrelated types (`Book`, `Dvd`, `Poster` share no base class) one
  value-semantic type with a uniform interface. The abstract `Concept` and the templated `Model` are the usual
  construction; `std::function`, `std::any` and the deleter of `std::shared_ptr` work the same way. The stored object
  is held through a `shared_ptr<const Concept>` so copies of `Describable` are cheap and immutable.
* *Named parameters*: `+make_loan("Emma", {.days = 7, .note = "reserved"})+` passes an options struct with designated
  initializers, so a call site names what it sets and everything else keeps its default. Designators must appear in
  declaration order.
