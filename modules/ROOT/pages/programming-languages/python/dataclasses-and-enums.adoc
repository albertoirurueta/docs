= Dataclasses and Enums
:description: Python's @dataclass decorator -- auto-generated __init__/__repr__/__eq__, field defaults and default_factory, frozen=True -- plus enum.Enum, auto(), IntEnum, Flag and IntFlag.
:keywords: Python, dataclass, dataclasses, field, default_factory, frozen, immutability, enum, Enum, auto, IntEnum, Flag, IntFlag, bitwise flags
:page-aliases: web/python/dataclasses-and-enums.adoc

include::partial$ai-disclaimer.adoc[]

**`@dataclass`** generates the boilerplate methods a plain attribute-holding class needs, and **`enum.Enum`**
gives a fixed, named set of values -- both are covered end to end by the standard library's
https://docs.python.org/3/library/dataclasses.html[`dataclasses`] and
https://docs.python.org/3/library/enum.html[`enum`] modules, which are the only sources behind this page:
`@dataclass` is recent enough that there is no book cross-reference for this page; the `dataclasses` and `enum`
module docs above are the only sources.

== `@dataclass` Basics

Decorating a class with
https://docs.python.org/3/library/dataclasses.html#dataclasses.dataclass[`@dataclass`] inspects its class-level
variable annotations and generates `+__init__+`, `+__repr__+`, and `+__eq__+` from them -- no more copying each
attribute name into three different methods by hand:

[source,python]
----
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p1 = Point(3, 4)
p2 = Point(3, 4)

print(p1)             # Point(x=3, y=4)          -- generated __repr__
print(p1 == p2)        # True                     -- generated __eq__ compares field by field
print(p1 is p2)        # False                    -- still two distinct objects
----

=== Field Defaults and `default_factory`

An annotation can carry a plain default just like a function parameter, but a *mutable* default (a `list` or
`dict`) must go through
https://docs.python.org/3/library/dataclasses.html#dataclasses.field[`+field(default_factory=...)+`] instead --
using a bare mutable default is rejected at class-creation time, precisely to avoid the shared-mutable-default
trap:

[source,python]
----
from dataclasses import dataclass, field

@dataclass
class Cart:
    owner: str
    items: list = field(default_factory=list)   # a *new* list per instance
    discount_pct: float = 0.0                    # plain default: fine for immutable values

# @dataclass
# class Broken:
#     items: list = []   # ValueError: mutable default <class 'list'> for field items is not allowed

cart_a = Cart("Alice")
cart_b = Cart("Bob")
cart_a.items.append("book")
print(cart_a.items, cart_b.items)   # ['book'] []   -- lists are independent
----

=== `frozen=True` for Immutability

Passing `frozen=True` to the decorator makes every field read-only after `+__init__+`: assigning to an
attribute raises `FrozenInstanceError`, and a generated `+__hash__+` is added so frozen instances can be used as
`dict` keys or set members. This parameter is documented alongside the rest of
https://docs.python.org/3/library/dataclasses.html#dataclasses.dataclass[`@dataclass`&#39;s options]:

[source,python]
----
from dataclasses import dataclass, FrozenInstanceError

@dataclass(frozen=True)
class Coordinate:
    lat: float
    lon: float

home = Coordinate(40.4168, -3.7038)
print(home)   # Coordinate(lat=40.4168, lon=-3.7038)

try:
    home.lat = 0.0
except FrozenInstanceError as exc:
    print(f"cannot mutate: {exc}")   # cannot mutate: cannot assign to field 'lat'

waypoints = {home}   # OK: frozen dataclasses are hashable
----

== `@dataclass` vs. a Hand-Written Class vs. `dict`/`tuple`

A hand-written class gives the exact same *behavior* as a `@dataclass`, just typed out manually -- `@dataclass`
saves that typing without changing what the class can do, and you can still add your own methods, validation
in `+__post_init__+`, or override any generated method:

[source,python]
----
# Equivalent by hand -- @dataclass generates exactly this for the Point example above
class PointByHand:
    def __init__(self, x: int, y: int) -> None:
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"PointByHand(x={self.x!r}, y={self.y!r})"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, PointByHand):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)
----

A plain `dict` or `tuple` needs no class at all, but trades away named, checked attributes for positional or
string-keyed access -- fine for a short-lived, throwaway grouping; a liability once the shape matters or the
data is passed between functions:

[source,python]
----
# dict: flexible, but no fixed shape -- a typo in a key is only caught at runtime
p_dict = {"x": 3, "y": 4}
print(p_dict["x"])          # 3
# print(p_dict["z"])         # KeyError at runtime, not a static check

# tuple: fixed shape, but fields are unnamed -- readers must remember the order
p_tuple = (3, 4)
print(p_tuple[0])           # 3, but what is "0"? readers must know it means x

# @dataclass: fixed shape *and* named, type-hinted fields, with __init__/__repr__/__eq__ for free
p_data = Point(3, 4)
print(p_data.x)              # 3 -- self-documenting
----

Reach for `@dataclass` whenever a group of related values has a fixed shape and outlives one function call;
keep `dict`/`tuple` for quick, local, shape-free groupings; write a full hand-written class only when you need
custom invariants or behavior beyond what `@dataclass`&#39;s hooks (`+__post_init__+`, custom methods) comfortably
express -- xref:programming-languages/python/classes-and-objects.adoc[] covers writing that class by hand.

== `enum.Enum`

An https://docs.python.org/3/library/enum.html#enum.Enum[`Enum`] defines a fixed set of named constants --
*members* -- instead of scattering plain strings or integers through the code where any typo silently passes:

[source,python]
----
from enum import Enum

class Direction(Enum):
    NORTH = "N"
    SOUTH = "S"
    EAST = "E"
    WEST = "W"

heading = Direction.NORTH
print(heading)              # Direction.NORTH
print(heading.name)         # NORTH
print(heading.value)        # N
print(heading is Direction.NORTH)   # True -- members are singletons
----

=== Auto Values with `auto()`

When the actual value doesn't matter -- only that each member is distinct --
https://docs.python.org/3/library/enum.html#enum.auto[`auto()`] assigns increasing integers (starting at `1`)
without spelling them out:

[source,python]
----
from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    ACTIVE = auto()
    DONE = auto()

for member in Status:
    print(member.name, member.value)
# PENDING 1
# ACTIVE 2
# DONE 3
----

=== `IntEnum` for Integer Interop

https://docs.python.org/3/library/enum.html#enum.IntEnum[`IntEnum`] members *are* integers -- they compare
equal to and can be used anywhere a plain `int` is expected (a regular `Enum` member never equals a plain
value):

[source,python]
----
from enum import IntEnum, Enum

class HttpStatus(IntEnum):
    OK = 200
    NOT_FOUND = 404

print(HttpStatus.OK == 200)        # True -- IntEnum compares equal to int
print(HttpStatus.OK + 0)           # 200 -- usable as an int

class PlainStatus(Enum):
    OK = 200

print(PlainStatus.OK == 200)       # False -- a plain Enum member never equals a raw value
----

=== `Flag` and `IntFlag` for Bitwise Combinations

https://docs.python.org/3/library/enum.html#enum.Flag[`Flag`] (and its integer-compatible sibling
https://docs.python.org/3/library/enum.html#enum.IntFlag[`IntFlag`]) members can be combined with `|` and
tested with `&`, which suits sets of independent on/off options:

[source,python]
----
from enum import Flag, auto

class Permission(Flag):
    READ = auto()
    WRITE = auto()
    EXECUTE = auto()

editor = Permission.READ | Permission.WRITE
print(editor)                              # Permission.READ|WRITE
print(Permission.WRITE in editor)          # True
print(Permission.EXECUTE in editor)        # False
print(editor & Permission.READ)            # Permission.READ
----

=== Iterating Members: `.name` and `.value`

Every `Enum` subclass is iterable in definition order, yielding each member so its `.name` and `.value` can be
read without hardcoding the member list elsewhere:

[source,python]
----
class Direction(Enum):
    NORTH = "N"
    SOUTH = "S"

for member in Direction:
    print(f"{member.name} -> {member.value}")
# NORTH -> N
# SOUTH -> S

names = [member.name for member in Direction]
print(names)   # ['NORTH', 'SOUTH']
----

== What the Decorators and Metaclass Generate

=== `@dataclass` is code generation

`@dataclass` reads the class's annotations (in order) and *writes* methods onto the class: `+__init__+`, `+__repr__+`,
`+__eq__+`, and optionally ordering methods (`order=True`), `+__hash__+` and a frozen `+__setattr__+`. The result is an
ordinary class, so inheritance, properties and your own methods work as usual. Only annotated names become fields; an
unannotated class attribute is a plain class attribute.

[mermaid]
....
flowchart LR
    A["Annotated class body:\nyear: int, title: str"] --> B["@dataclass(order=True, frozen=True)"]
    B --> C["__init__(self, year, title)"]
    B --> D["__repr__ and __eq__\nusing the fields as a tuple"]
    B --> E["__lt__, __le__, __gt__, __ge__"]
    B --> F["__setattr__ and __delattr__\nraise FrozenInstanceError"]
    B --> G["__hash__ from the fields\nwhen eq and frozen are true"]
....

The options that matter in practice:

* `field(default_factory=list)` gives each instance its own mutable default; a bare `[]`, `+{}+` or `set()` default raises
  `ValueError` when the class is defined, which prevents the shared-default bug;
* `field(compare=False)` or `field(repr=False)` removes a field from comparison, hashing and display, and
  `field(init=False)` excludes it from the constructor;
* `+__post_init__+` runs after the generated `+__init__+` for validation or derived values, and `InitVar` fields are passed to
  it without being stored;
* `frozen=True` blocks attribute assignment (use `dataclasses.replace` to derive a changed copy) and, with `eq=True`,
  makes the class hashable so instances can be dictionary keys or set members;
* `order=True` compares fields as tuples in declaration order, so put the sort key first;
* `dataclasses.asdict`, `astuple` and `fields` convert and introspect (`asdict` recurses into nested dataclasses and copies containers);
* `slots=True`, `kw_only=True` and `match_args` options exist on newer releases (3.10+) and are not used in the sample below.

[source,python]
----
from dataclasses import dataclass, field, fields, replace, asdict, astuple, InitVar, is_dataclass


@dataclass(order=True, frozen=True)
class Book:
    year: int
    title: str = field(compare=False)
    tags: tuple = field(default=(), repr=False)

    def label(self):
        return f"{self.title} ({self.year})"


a, b = Book(1965, "Dune", ("sf",)), Book(1815, "Emma")
print(a, b < a, a == Book(1965, "Other title", ("sf",)))        # title is excluded from comparison
print([f.name for f in fields(Book)], is_dataclass(a))
print(asdict(a), astuple(b))
print(replace(a, title="Dune Messiah").label())          # frozen: derive a new value instead
try:
    a.year = 2000
except Exception as exc:
    print(type(exc).__name__)
print(hash(a) == hash(Book(1965, "Other title", ("sf",))))         # frozen + eq generate __hash__


# mutable defaults are rejected at class creation
try:
    @dataclass
    class Bad:
        items: list = []
except ValueError as exc:
    print("ValueError:", exc)


@dataclass
class Shelf:
    name: str
    books: list = field(default_factory=list)            # a fresh list per instance
    capacity: InitVar[int] = 10                           # passed to __post_init__, not stored
    full: bool = field(init=False, default=False)

    def __post_init__(self, capacity):
        self.full = len(self.books) >= capacity

s1, s2 = Shelf("a"), Shelf("b", ["x"] * 3, capacity=3)
s1.books.append("Dune")
print(s1, s2.full, s2.books is not s1.books)
print(Shelf.__init__.__code__.co_varnames[:6])
----

Output:

[source,text]
----
Book(year=1965, title='Dune') True True
['year', 'title', 'tags'] True
{'year': 1965, 'title': 'Dune', 'tags': ('sf',)} (1815, 'Emma', ())
Dune Messiah (1965)
FrozenInstanceError
True
ValueError: mutable default <class 'list'> for field items is not allowed: use default_factory
Shelf(name='a', books=['Dune'], full=False) True True
('self', 'name', 'books', 'capacity')
----

In the first line `a` equals a book with another title because `title` is excluded from comparison (the other fields
agree), and `hash(a)` is derived from the same compared fields, so the equal/hash contract described in
xref:programming-languages/python/collections.adoc[Collections] still holds. Choose a dataclass for records of data,
a `NamedTuple` when you need immutability and tuple unpacking, a plain class when behaviour dominates, and Pydantic
or `attrs` when you need validation or conversion at the boundaries (see xref:programming-languages/python/type-hints.adoc[Type Hints]).

=== Enums are classes whose members are singletons

An `Enum` class body defines *members*: each name is turned into a unique instance, and `Status.LOANED` always returns the
same object, so identity comparison (`is`) is correct and cheap. Members have `name` and `value`, can carry methods and
properties, and are looked up by value (`Status(2)`) or name (`Status["LOANED"]`); an unknown value raises `ValueError`.
Two names with the same value define an *alias* (`MISSING` for `LOST`): aliases are the same object, are skipped when
iterating and appear in `+__members__+`. `@unique` turns accidental aliases into an error.

[mermaid]
....
flowchart TD
    A["class Status(Enum): body"] --> B["EnumMeta collects the namespace"]
    B --> C{"Value already\nused by a member?"}
    C -- No --> D["Create a new member\nobject: name and value"]
    C -- Yes --> E["Bind the new name\nas an alias of that member"]
    D --> F["Status.LOANED is the one\nsingleton; Status(2) returns it"]
    E --> F
....

Pick the base class by how members interact with other values. Plain `Enum` members are not equal to their raw values
(`Status.LOANED == 2` is false), which prevents mixing up codes. `IntEnum` members *are* integers, which helps with
legacy APIs and sorting but weakens that protection. `Flag` and `IntFlag` support `|`, `&` and `in` for sets of options
and may define composite members such as `ADMIN`. The functional API (`Enum("Color", "RED GREEN")`) builds an enum
dynamically, and `auto()` assigns values so you do not number members by hand.

[source,python]
----
from enum import Enum, Flag, IntEnum, auto, unique


class Status(Enum):
    AVAILABLE = auto()
    LOANED = auto()
    LOST = auto()
    MISSING = LOST                                     # an alias: same value, same member

    @property
    def can_borrow(self):
        return self is Status.AVAILABLE

    @classmethod
    def parse(cls, text):
        return cls[text.strip().upper()]               # lookup by name; cls(value) looks up by value


print(Status.MISSING is Status.LOST, list(Status))     # aliases are skipped when iterating
print(Status.LOANED.name, Status.LOANED.value, Status(2), Status.parse(" lost "))
print(list(Status.__members__))                         # includes aliases
print(Status.AVAILABLE.can_borrow, Status.LOANED == 2, Status.LOANED in Status)
try:
    Status(9)
except ValueError as exc:
    print("ValueError:", exc)

try:
    @unique
    class Dup(Enum):
        A = 1
        B = 1
except ValueError as exc:
    print("ValueError:", exc)


class Priority(IntEnum):
    LOW = 1
    HIGH = 3

print(Priority.HIGH > Priority.LOW, Priority.HIGH + 1, sorted([Priority.HIGH, Priority.LOW]))


class Perm(Flag):
    READ = auto()
    WRITE = auto()
    ADMIN = READ | WRITE

p = Perm.READ | Perm.WRITE
print(p is Perm.ADMIN, Perm.READ in p, bool(Perm(0)))

Color = Enum("Color", "RED GREEN")                      # functional API
print(Color.GREEN, Color["RED"].value)
----

Output:

[source,text]
----
True [<Status.AVAILABLE: 1>, <Status.LOANED: 2>, <Status.LOST: 3>]
LOANED 2 Status.LOANED Status.LOST
['AVAILABLE', 'LOANED', 'LOST', 'MISSING']
True False True
ValueError: 9 is not a valid Status
ValueError: duplicate values found in <enum 'Dup'>: B -> A
True 4 [<Priority.LOW: 1>, <Priority.HIGH: 3>]
True True False
Color.GREEN 1
----

Use enums instead of string or integer constants wherever a value comes from a closed set: it gives completion, typo
safety, exhaustive-matching support in type checkers and a readable `repr`. Store `member.value` when serialising and
rebuild with `Status(value)` on load.
