*birdtally* is a library with a command, `birdtally`. Users who only want the command should not have to manage a virtual
environment or risk breaking the system Python (PEP 668, see
xref:programming-languages/python/build-tools/environments-and-externally-managed-pythons.adoc[Environments & Externally Managed Pythons]).
This page covers the ways to ship the command, run on 2026-10-22 with pipx 1.18.4, Poetry 2.5.1 and CPython 3.14.6 against the
local index of this section. Distribution channels beyond Python (Homebrew, winget, native binaries) are compared on
xref:ai/cli-for-agents/packaging-and-distribution.adoc#_pipx_and_uv_tool_for_python[Packaging & Distribution for CLI tools].

== Entry points make the command

[source,toml]
----
[project.scripts]
birdtally = "birdtally.cli:main"
----

When the wheel is installed, the installer writes a small wrapper named `birdtally` into the environment's `bin/` (`Scripts\` on
Windows, as `birdtally.exe`) that imports `birdtally.cli` and calls `main()`, using that environment's Python. `main()` should
return an exit code (the wrapper passes it to `sys.exit`). Nothing in the project needs a `+__main__+` shebang file;
`gui-scripts` do the same for windowed programs on Windows.

Source: https://packaging.python.org/en/latest/specifications/entry-points/#use-for-scripts[PUG: Entry points: use for scripts],
https://packaging.python.org/en/latest/guides/creating-command-line-tools/#pyproject-toml[PUG: Creating command-line tools: pyproject.toml].

== pipx: an environment per application

pipx installs each application into its own virtual environment and puts only its commands on `PATH`:

[source,bash]
----
python -m pip install pipx                         # or the OS package
pipx install --index-url http://127.0.0.1:8084/simple/ birdtally
birdtally examples/survey.csv --by site
----

[source,text]
----
creating virtual environment...
installing birdtally...
  installed package birdtally 0.1.2, installed using Python 3.14.6
  These apps are now available
    - birdtally
…
done! ✨ 🌟 ✨
{
  "north-marsh": 6,
  "east-dunes": 3
}
----

(the warning that the scratch `+PIPX_BIN_DIR+` is not on `PATH` removed; `pipx ensurepath` fixes that on a real machine). Optional
dependencies go into the same environment with `pipx inject birdtally rich` (or `pipx install "birdtally[pretty]"`), after
which `birdtally survey.csv --pretty` drew its table:

[source,text]
----
┏━━━━━━━━━━┳━━━━━━━┓
┃ Species  ┃ Count ┃
┡━━━━━━━━━━╇━━━━━━━┩
│ lapwing  │ 7     │
│ redshank │ 2     │
└──────────┴───────┘
----

`pipx upgrade birdtally`, `pipx list` and `pipx uninstall birdtally` manage it. `uv tool install` is the equivalent in uv.
Compared with `pip install birdtally` into a shared environment, nothing else can break the tool's dependencies and removing it
leaves nothing behind. Recommend `pipx install birdtally` in the README for users who want the command.

Source: https://packaging.python.org/en/latest/guides/installing-stand-alone-command-line-tools/[PUG: Installing stand alone command line tools],
https://packaging.python.org/en/latest/guides/creating-command-line-tools/#installing-the-package-with-pipx[PUG: Installing the package with pipx].

== Poetry: file scripts

`+[project.scripts]+` covers Python entry points. A script that is a *file* (a shell script, a pre-written launcher) goes in
`+[tool.poetry.scripts]+` with `type = "file"`, and poetry-core ships it in the wheel's `.data/scripts/`:

[source,toml]
----
[tool.poetry.scripts]
birdtally-help = { reference = "bin/birdtally-help", type = "file" }
----

[source,text]
----
       62  2016-01-01 00:00   birdtally-0.1.2.data/scripts/birdtally-help
       48  2016-01-01 00:00   birdtally-0.1.2.dist-info/entry_points.txt
----

After `pip install`, the environment's `bin/` held both `birdtally` and `birdtally-help`, and `birdtally-help` printed
`birdtally survey helper: run birdtally <csv>`. (Poetry 2.5.0 fixed `poetry install` not installing file scripts for the
project itself.)

Source: https://python-poetry.org/docs/pyproject/#scripts-1[Poetry: tool.poetry scripts].

== Shipping an environment

* `poetry bundle venv /opt/birdtally` (poetry-plugin-bundle) installs the project and its locked dependencies into a fresh
  virtual environment that can be copied to machines with the same Python and platform; shown on
  xref:programming-languages/python/build-tools/poetry/exporting-requirements-and-bundling.adoc#_poetry_bundle_venv[Exporting Requirements & Bundling].
* A container image with the environment, built as on
  xref:programming-languages/python/build-tools/poetry/tox-nox-pre-commit-and-docker.adoc#_docker_build_with_poetry_ship_the_environment[tox, nox, pre-commit & Docker].
* *Executable archives*: the standard library's `zipapp`, and the third-party shiv and pex, pack an application and its pure-Python
  dependencies into one file that runs with a matching Python.
* *Frozen applications* that include the interpreter: PyInstaller, and per platform py2exe (Windows), py2app (macOS) and Pynsist
  (Windows installers, buildable on Linux).
* *Operating-system packages* (deb, rpm, Homebrew, winget) package the application for one platform's package manager.

Source: https://packaging.python.org/en/latest/discussions/deploying-python-applications/#os-packaging-installers[PUG: Deploying Python applications: OS packaging & installers],
https://packaging.python.org/en/latest/discussions/deploying-python-applications/#application-bundles[Application bundles],
https://github.com/python-poetry/poetry-plugin-bundle[poetry-plugin-bundle].

== The smallest unit: a single-file script (PEP 723)

A script that declares its own requirements needs no project, no build and no index:

[source,python]
----
# /// script
# requires-python = ">=3.10"
# dependencies = ["rich>=13"]
# ///
"""Count sightings per species in a survey CSV and print a table."""
import csv
import sys
from collections import Counter

from rich.console import Console
from rich.table import Table

counts = Counter()
with open(sys.argv[1], newline="") as f:
    for row in csv.DictReader(f):
        counts[row["species"]] += int(row["count"])

table = Table("Species", "Count")
for species, n in counts.most_common():
    table.add_row(species, str(n))
Console().print(table)
----

[source,bash]
----
pipx run count_birds.py examples/survey.csv
----

[source,text]
----
Installed 4 packages in 8ms
┏━━━━━━━━━━┳━━━━━━━┓
┃ Species  ┃ Count ┃
┡━━━━━━━━━━╇━━━━━━━┩
│ lapwing  │ 7     │
│ redshank │ 2     │
└──────────┴───────┘
----

pipx created a cached environment with rich for the script (a deprecation warning printed by uv, which this pipx used
for the installation, about the machine's `+UV_NATIVE_TLS+` setting removed). `+uv run count_birds.py+` does the same; with pip,
`+pip install --requirements-from-script count_birds.py+` (pip 26.0) installs the requirements into the current environment, see
xref:programming-languages/python/build-tools/pip/dependency-groups-and-inline-script-metadata.adoc[pip: Dependency Groups & Inline Script Metadata].
Share the file itself: by URL, in a gist, or in a repository.

Source: https://packaging.python.org/en/latest/specifications/inline-script-metadata/[PUG: Inline script metadata].
