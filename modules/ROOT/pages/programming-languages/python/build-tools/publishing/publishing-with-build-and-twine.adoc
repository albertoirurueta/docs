:description: The pip-side release round trip for birdtally, run end to end against a local pypiserver 2.4.2 -- python -m build, twine check --strict, twine upload with --repository-url and with a .pypirc repository, installing the release from the index and running it, then the errors: re-uploading the same file, --skip-existing refused for a non-PyPI index, wrong credentials; every twine upload option and TWINE_* variable, keyring and proxies, GPG signatures no longer used, twine register, the TestPyPI and PyPI commands (not run), and PyPI's own upload errors (filename reuse, file and project size limits, silently ignored form fields).

This page publishes the pip-flavoured *birdtally* with the standard tools: build makes the files, twine checks and uploads them.
Every command below ran on 2026-10-22 against a *local* pypiserver 2.4.2 on `localhost:8084` that requires HTTP basic
authentication for uploads (`pypi-server run -p 8084 -a update -P htpasswd packages`), with build 1.6.1, twine 7.0.0 and pip
26.2.2 on CPython 3.14.6. The TestPyPI and PyPI commands at the end are *not run here*. The short introduction is on
xref:programming-languages/python/virtual-environments-and-packaging.adoc#_publishing_with_twine[Virtual Environments & Packaging];
running the index itself is on
xref:programming-languages/python/build-tools/publishing/private-indexes-and-alternative-distribution.adoc[Private Indexes & Alternative Distribution].

Never use `python setup.py upload`: the `upload` and `register` commands were removed from setuptools long ago, and they sent
credentials in ways twine replaced for good reasons.

== The round trip

[source,bash]
----
rm -rf dist/
python -m build
twine check --strict dist/*
export TWINE_USERNAME=birdwatch
export TWINE_PASSWORD=…              # from your secret store
twine upload --disable-progress-bar --repository-url http://localhost:8084/ dist/*
----

[source,text]
----
Successfully built birdtally-0.1.0.tar.gz and birdtally-0.1.0-py3-none-any.whl
Checking dist/birdtally-0.1.0-py3-none-any.whl: PASSED
Checking dist/birdtally-0.1.0.tar.gz: PASSED
Uploading distributions to http://localhost:8084/
Uploading birdtally-0.1.0-py3-none-any.whl
Uploading birdtally-0.1.0.tar.gz
----

Then, from a fresh environment, install the release *from the index* and run it:

[source,bash]
----
python -m venv /tmp/from-index
/tmp/from-index/bin/python -m pip install --index-url http://localhost:8084/simple/ birdtally
/tmp/from-index/bin/birdtally examples/survey.csv
----

[source,text]
----
Collecting birdtally
  Downloading birdtally-0.1.1-py3-none-any.whl (3.7 kB)
Installing collected packages: birdtally
Successfully installed birdtally-0.1.1
{
  "lapwing": 7,
  "redshank": 2
}
----

(by then 0.1.1 had also been uploaded, see below, and pip picked the newest). Clean `dist/` before each release build:
`+twine upload dist/*+` uploads whatever it finds there, including last release's files.

=== With a `.pypirc` repository

Name the index once in `.pypirc` (see
xref:programming-languages/python/build-tools/publishing/pypi-and-testpypi-accounts-and-tokens.adoc#_pypirc[PyPI & TestPyPI Accounts & Tokens])
and refer to it with `-r`:

[source,ini]
----
[distutils]
index-servers =
    birdwatch

[birdwatch]
repository = http://localhost:8084/
username = birdwatch
----

[source,bash]
----
twine upload --disable-progress-bar --config-file pypirc-demo -r birdwatch dist/*
----

[source,text]
----
Uploading distributions to http://localhost:8084/
Uploading birdtally-0.1.1-py3-none-any.whl
Uploading birdtally-0.1.1.tar.gz
----

The password came from `+TWINE_PASSWORD+`; the default `--config-file` is `+~/.pypirc+`.

Source: https://packaging.python.org/en/latest/specifications/pypirc/#using-another-package-index[PyPA: The .pypirc file, using another package index],
https://twine.readthedocs.io/en/stable/#configuration[twine: Configuration].

== When the upload fails

=== The file already exists

Uploading the same 0.1.0 files a second time:

[source,text]
----
Uploading distributions to http://localhost:8084/
Uploading birdtally-0.1.0-py3-none-any.whl
WARNING  Error during upload. Retry with the --verbose option for more details.
ERROR    HTTPError: 400 Bad Request from http://localhost:8084/
         Bad Request
----

`--verbose` shows the server's reason, here pypiserver's HTML page: `+Package 'birdtally-0.1.0-py3-none-any.whl' already exists!
You may start server with `--overwrite` option.+`. PyPI answers a re-upload with `Filename or contents already exists` or
`Filename has been previously used`, and there is no override: a filename can never be reused, *even after the file, the
release or the whole project is deleted*. The fix is always a new version (a `.post1` if only packaging changed).

`--skip-existing` makes twine skip files the index already has, but twine only supports it for PyPI:

[source,text]
----
ERROR    UnsupportedConfiguration: The configured repository
         'http://localhost:8084/' does not have support for the following
         features: --skip-existing and is an unsupported configuration
----

(twine 6.2.0 removed its workarounds for other indexes.)

Source: https://docs.pypi.org/publishing/troubleshooting/#why-am-i-getting-a-filename-or-contents-already-exists-or-filename-has-been-previously-used-error[PyPI: Filename or contents already exists],
https://twine.readthedocs.io/en/stable/#twine-upload[twine: twine upload],
https://twine.readthedocs.io/en/stable/changelog.html#twine-6-2-0-2025-09-04[twine 6.2.0 changelog].

=== Wrong credentials

[source,text]
----
Uploading distributions to http://localhost:8084/
Uploading birdtally-0.1.0-py3-none-any.whl
WARNING  Error during upload. Retry with the --verbose option for more details.
ERROR    HTTPError: 403 Forbidden from http://localhost:8084/
         Forbidden
----

PyPI's equivalent is `403 Invalid or non-existent authentication information`; its causes are on
xref:programming-languages/python/build-tools/publishing/pypi-and-testpypi-accounts-and-tokens.adoc#_invalid_or_non_existent_authentication_information[PyPI & TestPyPI Accounts & Tokens].
`--non-interactive` (used here) fails instead of prompting, which is what CI needs.

Source: https://twine.readthedocs.io/en/stable/#entering-credentials[twine: Entering credentials],
https://docs.pypi.org/publishing/troubleshooting/#why-am-i-getting-an-invalid-or-non-existent-authentication-information-error-when-uploading-files[PyPI: Invalid or non-existent authentication information].

=== PyPI-only errors (not run here)

* `+Invalid distribution metadata: unrecognized or malformed field '…'+`: a metadata field PyPI does not accept; twine 7.0.0
  rejects metadata version "2.0" and accepts up to 2.5.
* `HTTPError: 400 Client Error: File too large. Limit for project 'sampleproject' is 100 MB.`: the default limits are 100 MB per
  file and 10 GB per project; increases are requested through PyPI support.
* Transient 5xx responses: twine retries, printing `Received "503: Service Unavailable"`, `Package upload appears to have
  failed. Retry 1 of 5.` and so on (from twine's source; the status varies).
* Anyone writing their own uploader: form fields must use the upload API's names; a field such as `Description-Content-Type`
  sent in its metadata spelling is *silently ignored*.
* Since 2026-07-22 PyPI also refuses new files for a release that is more than 14 days old (see
  xref:programming-languages/python/build-tools/publishing/managing-published-releases.adoc[Managing Published Releases]).

Source: https://docs.pypi.org/publishing/troubleshooting/#why-am-i-getting-a-filename-or-contents-already-exists-or-filename-has-been-previously-used-error[PyPI: Filename or contents already exists],
https://docs.pypi.org/project-management/storage-limits/#file-size-limits[PyPI: File size limits],
https://docs.pypi.org/project-management/storage-limits/#project-size-limits[Project size limits],
https://docs.pypi.org/api/upload/#upload-a-file[PyPI: Upload API],
https://pypi.org/help/#file-name-reuse[PyPI help: file name reuse].

== `twine upload` reference

[cols="2,5",options="header"]
|===
| Option | Meaning

| `-r`, `--repository NAME` | A section of the config file (default `pypi`); `+TWINE_REPOSITORY+`.
| `--repository-url URL` | An upload URL, overriding `-r`; `+TWINE_REPOSITORY_URL+`.
| `-u`, `--username` | `+TWINE_USERNAME+`. "Has no effect on PyPI or TestPyPI", where it is always `+__token__+`.
| `-p`, `--password` | `+TWINE_PASSWORD+`. Prefer the variable or keyring: a command-line password lands in shell history and process lists.
| `--non-interactive` | Fail instead of prompting for missing credentials; `+TWINE_NON_INTERACTIVE+`.
| `--config-file` | Another `.pypirc`.
| `--skip-existing` | Skip files that already exist (PyPI only).
| `--attestations` | Upload each file's PEP 740 attestation (`<file>.publish.attestation`) next to it; PyPI and TestPyPI only. See xref:programming-languages/python/build-tools/publishing/trusted-publishing-and-attestations.adoc[Trusted Publishing & Attestations].
| `-s`, `--sign`, `--sign-with`, `-i`, `--identity` | GPG signatures. No longer useful on PyPI, which dropped support for them; attestations took their place.
| `-c`, `--comment` | A comment stored with the file (legacy).
| `--cert`, `--client-cert` | A CA bundle (`+TWINE_CERT+`) and a client certificate for the index.
| `--verbose`, `--disable-progress-bar` | More detail; no progress bars in logs.
|===

*Keyring*: twine looks up the password with `keyring` (installed with it) by repository URL and username. Where the keyring
backend prompts unexpectedly (headless Linux, CI), the twine documentation's fix is `keyring --disable`. *Proxies*: twine uses requests, so `+HTTPS_PROXY+` and `+NO_PROXY+` apply. `twine register` exists for other indexes;
PyPI answers that registration "is not required with PyPI.org".

Recent twine releases: 5.0.0 (2024-02-10) requires `+__token__+` for PyPI; 6.0.0 (2024-11-29) makes it the default username;
6.1.0 (2025-01-17) adds preliminary built-in Trusted Publishing and drops eggs, wininst and `.tar.bz2`; 6.2.0 (2025-09-04) refreshes
Trusted Publishing tokens every 15 minutes; 7.0.0 (2026-07-27) accepts metadata 2.5, rejects "2.0" and reads `.pypirc` as UTF-8.

Source: https://twine.readthedocs.io/en/stable/#environment-variables[twine: Environment variables],
https://twine.readthedocs.io/en/stable/#keyring-support[twine: Keyring support],
https://twine.readthedocs.io/en/stable/#disabling-keyring[Disabling keyring],
https://twine.readthedocs.io/en/stable/#proxy-support[Proxy support],
https://twine.readthedocs.io/en/stable/#twine-register[twine register],
https://twine.readthedocs.io/en/stable/changelog.html#twine-7-0-0-2026-07-27[twine changelog: 7.0.0],

== TestPyPI, then PyPI (not run here)

[source,bash]
----
# rehearsal: needs a TestPyPI account and token
TWINE_PASSWORD="$TESTPYPI_TOKEN" twine upload --repository testpypi dist/*
python -m pip install --index-url https://test.pypi.org/simple/ --extra-index-url https://pypi.org/simple/ birdtally

# the release: a project-scoped PyPI token, or better Trusted Publishing from CI
TWINE_PASSWORD="$PYPI_TOKEN" twine upload dist/*
----

Without `-r`, twine uploads to `pypi` (`+https://upload.pypi.org/legacy/+`). Each upload of a version needs fresh filenames on each
index, so rehearse with dev versions on TestPyPI. From CI, publish with Trusted Publishing instead of a token:
xref:programming-languages/python/build-tools/publishing/github-actions-and-gitlab-ci-release-workflows.adoc[GitHub Actions & GitLab CI Release Workflows].

Source: https://packaging.python.org/en/latest/guides/distributing-packages-using-setuptools/#upload-your-distributions[PUG: Upload your distributions],
https://packaging.python.org/en/latest/guides/using-testpypi/#using-testpypi-with-twine[PUG: Using TestPyPI with twine].
