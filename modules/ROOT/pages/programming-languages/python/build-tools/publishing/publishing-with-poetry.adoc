= Publishing with Poetry
:description: The Poetry-side release round trip for birdtally, run against a local pypiserver -- a publishable repository with poetry config repositories.<name> (legacy upload API only, trailing slash added since 2.4), credentials through http-basic, pypi-token, the keyring or POETRY_HTTP_BASIC_*/POETRY_PYPI_TOKEN_*, poetry publish -r --build (the "files ready for publishing" prompt and its non-interactive warning), --dry-run, --skip-existing that works against other indexes, the 409 Conflict and 403 errors, every publish option, TestPyPI and PyPI (not run), certificates, Poetry 2.5's refusal to send https credentials over http, and the missing native Trusted Publishing (python-poetry/poetry#7940) with its workaround.

Poetry builds and uploads in one tool: `poetry build` makes the sdist and wheel, `poetry publish` uploads the current version's
files to PyPI or to any index that implements the legacy upload API. This page publishes the Poetry-flavoured *birdtally* to the
same local pypiserver used on
xref:programming-languages/python/build-tools/publishing/publishing-with-build-and-twine.adoc[Publishing with build & twine]
(`localhost:8084`, uploads require HTTP basic authentication), with Poetry 2.5.1 on 2026-10-22. TestPyPI and PyPI are *not
used*. Repositories and credentials in general are on
xref:programming-languages/python/build-tools/poetry/repositories-and-package-sources.adoc[Repositories & Package Sources].

== Configure the target

Upload targets are per-user configuration, not part of `pyproject.toml`:

[source,bash]
----
poetry config repositories.local http://localhost:8084
poetry config repositories.local
export POETRY_HTTP_BASIC_LOCAL_USERNAME=birdwatch
export POETRY_HTTP_BASIC_LOCAL_PASSWORD=…        # from your secret store
----

[source,text]
----
{'url': 'http://localhost:8084'}
----

* The URL is the *upload* (legacy API) endpoint, not the `/simple/` one. Since 2.4 Poetry adds a missing trailing slash, so
  `http://localhost:8084` works.
* Credentials: `poetry config http-basic.local <user>` (prompts for the password; keyring or `auth.toml`),
  `poetry config pypi-token.<name> <token>` for token-based indexes, or the environment variables
  `+POETRY_HTTP_BASIC_<NAME>_USERNAME+`/`+_PASSWORD+` and `+POETRY_PYPI_TOKEN_<NAME>+` in CI. `pypi` and `testpypi` use
  `pypi-token.pypi` / `pypi-token.testpypi`.
* A password that starts with `-` needs `poetry config -- http-basic.local user -secret`; an empty password (some hosted indexes,
  such as Gemfury, use the token as the username) is `poetry config http-basic.local <token> ""`.
* Since 2.5.0 Poetry never sends credentials configured for an `https` repository over `http`.

Source: https://python-poetry.org/docs/repositories/#publishable-repositories[Poetry: Publishable repositories],

== Publish

With an old 0.1.0 build still in `dist/` and the version bumped to 0.1.2:

[source,bash]
----
poetry version 0.1.2
poetry publish -n -r local --build --dry-run
----

[source,text]
----
Bumping version from 0.1.0 to 0.1.2
Warning: There are 2 files ready for publishing in dist. Build anyway!
Creating virtualenv birdtally-CYLjbS5k-py3.13 in …/virtualenvs
Building birdtally (0.1.2)
Building sdist
  - Building sdist
  - Built birdtally-0.1.2.tar.gz
Building wheel
  - Building wheel
  - Built birdtally-0.1.2-py3-none-any.whl

Publishing birdtally (0.1.2) to local
 - Uploading birdtally-0.1.2.tar.gz 0%
 - Uploading birdtally-0.1.2.tar.gz 100%
 - Uploading birdtally-0.1.2-py3-none-any.whl 0%
 - Uploading birdtally-0.1.2-py3-none-any.whl 100%
----

Three details:

* `--build` builds first. If `dist/` already holds files, Poetry *asks* `There are 2 files ready for publishing in dist. Build
  anyway? (yes/no) [no]`; without a terminal that prompt repeats forever, so pass `-n` (then it prints the warning above and
  builds) or clean `dist/` yourself.
* Only the files of the *current* version are uploaded: the 0.1.0 files were left alone. Since 2.4.0 a failed `--build` stops
  the publish instead of uploading stale files.
* `--dry-run` does everything except the upload, progress lines included. Without it, the same command uploaded both files, and
  the local index then listed `birdtally-0.1.2-py3-none-any.whl` and `birdtally-0.1.2.tar.gz` next to the earlier releases.

Publishing again fails, here with pypiserver's `409 Conflict` (twine got a 400 for the same situation):

[source,text]
----
Publishing birdtally (0.1.2) to local
 - Uploading birdtally-0.1.2.tar.gz 0%
 - Uploading birdtally-0.1.2.tar.gz 100%

HTTP Error 409: Conflict | b'\n    <!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML 2.0//EN">…<pre>Package &#039;birdtally-0.1.2.tar.gz&#039; already exists!…'
----

Unlike twine, Poetry's `--skip-existing` works against this index:

[source,text]
----
 - Uploading birdtally-0.1.2.tar.gz 0%
 - Uploading birdtally-0.1.2.tar.gz 100%
 - Uploading birdtally-0.1.2.tar.gz File exists. Skipping
 - Uploading birdtally-0.1.2-py3-none-any.whl 0%
 - Uploading birdtally-0.1.2-py3-none-any.whl 100%
 - Uploading birdtally-0.1.2-py3-none-any.whl File exists. Skipping
----

A wrong password ends in `HTTP Error 403: Forbidden`, exit code 1.

Source: https://python-poetry.org/docs/cli/#publish[Poetry CLI: publish],
https://python-poetry.org/docs/libraries/#publishing-to-a-private-repository[Poetry: Publishing to a private repository],
https://python-poetry.org/docs/repositories/#publishing-to-a-private-repository[Repositories: Publishing to a private repository].

== `poetry publish` options

[cols="2,5",options="header"]
|===
| Option | Meaning

| `-r`, `--repository` | The configured repository (default: PyPI).
| `-u`, `--username`, `-p`, `--password` | Credentials on the command line; prefer configuration or environment variables.
| `--cert`, `--client-cert` | A CA bundle and a client certificate (or set `certificates.<name>.cert` / `.client-cert`).
| `--dist-dir` | Where the files are (default `dist`, 1.8).
| `--build` | Build before publishing.
| `--dry-run` | Do everything but upload.
| `--skip-existing` | Ignore files the repository already has.
|===

Source: https://python-poetry.org/docs/configuration/#certificatesnamecert[Poetry: certificates.<name>.cert],
https://python-poetry.org/docs/configuration/#certificatesnameclient-cert[certificates.<name>.client-cert],
https://python-poetry.org/docs/repositories/#custom-certificate-authority-and-mutual-tls-authentication[Custom certificate authority and mutual TLS].

== TestPyPI and PyPI (not run here)

[source,bash]
----
poetry config repositories.testpypi https://test.pypi.org/legacy/
export POETRY_PYPI_TOKEN_TESTPYPI="$TESTPYPI_TOKEN"
poetry publish -n -r testpypi --build

export POETRY_PYPI_TOKEN_PYPI="$PYPI_TOKEN"
poetry publish -n --build
----

`pypi` needs no `repositories` entry. Poetry uses the token as the password with the `+__token__+` username.

Source: https://python-poetry.org/docs/libraries/#publishing-to-pypi[Poetry: Publishing to PyPI],
https://python-poetry.org/docs/configuration/#keyringenabled[keyring.enabled].

== No Trusted Publishing in Poetry

Poetry has no built-in support for PyPI Trusted Publishing or PEP 740 attestations: the request, python-poetry/poetry#7940, has
been open since 2023-05-17. The documented way to combine them is to *build* with Poetry and *upload* with the PyPA action, which
handles the OIDC exchange and the attestations:

[source,yaml]
----
- run: pipx install poetry==2.5.1
- run: poetry build
- uses: pypa/gh-action-pypi-publish@release/v1      # in a job with id-token: write
----

The complete workflow is on
xref:programming-languages/python/build-tools/publishing/github-actions-and-gitlab-ci-release-workflows.adoc#_the_poetry_variant[GitHub Actions & GitLab CI Release Workflows].

Source: https://github.com/python-poetry/poetry/issues/7940[python-poetry/poetry#7940].

== Compared with build & twine

[cols="1,2,2",options="header"]
|===
| | Poetry | build + twine

| Build | `poetry build` (or `--build`) | `python -m build`
| Target | `poetry config repositories.<name>` | `.pypirc` or `--repository-url`
| Credentials | keyring, `auth.toml`, `+POETRY_*+` | keyring, `.pypirc`, `+TWINE_*+`
| Check before upload | `poetry check` (metadata only) | `twine check --strict` (renders the README)
| `--skip-existing` | any index | PyPI only
| Trusted Publishing, attestations | no | twine 6.1+ (preliminary), the PyPA action
|===

`twine check` also works on Poetry's `dist/`: run it before `poetry publish`.
