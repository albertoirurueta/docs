A requirements file is a list of `pip install` arguments, one per line, that pip reads with `-r`. It is not a standard: the format
is defined by pip, and other tools (uv, Poetry's export, pip-tools) read or write it because pip does. This page documents the
format of pip 26.2.2. The examples were run on CPython 3.14.6 on 2026-10-22 with the *birdtally-report* application, whose
`birdtally` dependency comes from the local *birdwatch* index (pypiserver on `localhost:8080`, which redirects names it does not
host to PyPI).

== What requirements files are for

The pip user guide names four uses:

. *Holding the result of `pip freeze`*, so an environment can be recreated (`pip freeze > requirements.txt`).
. *Forcing a version of a sub-dependency* that would otherwise be resolved differently, for example to avoid a broken release.
. *Overriding dependency resolution* by naming exact versions, for instance during an upgrade.
. *Installing from an alternative source*: a local patched copy, a VCS URL or a private index for some of the requirements.

What they are not is a place for a library's _abstract_ dependencies: those belong in `[project] dependencies`. A requirements file
describes an environment, `pyproject.toml` describes a project; see
xref:programming-languages/python/build-tools/lock-files-and-reproducible-installs.adoc[Lock Files & Reproducible Installs].

Source: https://pip.pypa.io/en/stable/user_guide/#requirements-files[pip user guide: Requirements files],
https://packaging.python.org/en/latest/discussions/install-requires-vs-requirements/[PyPA: install_requires vs requirements files].

== A complete example

`requirements.txt` for *birdtally-report*:

[source,text]
----
# birdtally-report: runtime requirements (pip flavour)
--index-url ${BIRDWATCH_INDEX_URL}
--only-binary :all:

birdtally[pretty] == 0.1.0   # from the local birdwatch index
rich >= 15, \
     < 16
-c constraints.txt
----

`constraints.txt`, referenced from it:

[source,text]
----
# organisation-wide pins: only apply if something requires them
pygments == 2.21.0
markdown-it-py == 4.2.0
----

and `requirements-dev.txt`, which includes the runtime file:

[source,text]
----
-r requirements.txt
pytest >= 8
----

[source,bash]
----
BIRDWATCH_INDEX_URL=http://localhost:8080/simple python -m pip install -r requirements-dev.txt
----

[source,text]
----
Looking in indexes: http://localhost:8080/simple
Collecting birdtally==0.1.0 (from birdtally[pretty]==0.1.0->-r …/requirements.txt (line 5))
  Downloading birdtally-0.1.0-py3-none-any.whl (3.7 kB)
Collecting rich<16,>=15 (from -r …/requirements.txt (line 6))
Collecting pytest>=8 (from -r requirements-dev.txt (line 2))
Collecting markdown-it-py>=2.2.0 (from rich<16,>=15->-r …/requirements.txt (line 6))
Collecting pygments<3.0.0,>=2.13.0 (from rich<16,>=15->-r …/requirements.txt (line 6))
Collecting iniconfig>=1.0.1 (from pytest>=8->-r requirements-dev.txt (line 2))
Collecting packaging>=22 (from pytest>=8->-r requirements-dev.txt (line 2))

(The `+Using cached …+` lines are left out.) Every `Collecting` line names the file and line number that asked for the package, which is
the quickest way to find why something is installed. The parts of the example are explained below.

Source: https://pip.pypa.io/en/stable/reference/requirements-file-format/#example[pip: Requirements file format, example].

== Structure

* *One requirement or option per line.* A requirement is anything `pip install` accepts as an argument: a PEP 508 specifier
  (`rich >= 15`), a local path, a URL, or `-e <path-or-VCS-URL>`. Spaces around operators are allowed.
* *Encoding.* The file is read as UTF-8, unless it declares another encoding with a PEP 263 style comment
  (`+# -*- coding: latin-1 -*-+`).
* *Line continuations.* A line ending in a backslash is joined with the next one, as in the `rich` requirement above.
* *Comments.* A `+#+` at the start of a line, or after whitespace, starts a comment to the end of the line. A `+#+` without whitespace
  before it is part of the line, which is how URL fragments such as `+#subdirectory=+` and `+#sha256=+` survive.
* *Relative paths* in `-r`, `-c`, `-e` and local requirements are relative to the requirements file, not to the current directory.

Source: https://pip.pypa.io/en/stable/reference/requirements-file-format/#structure[pip: Structure],
https://pip.pypa.io/en/stable/reference/requirements-file-format/#encoding[pip: Encoding],
https://pip.pypa.io/en/stable/reference/requirements-file-format/#line-continuations[pip: Line continuations],
https://pip.pypa.io/en/stable/reference/requirements-file-format/#comments[pip: Comments].

== Supported options

Only some `pip install` options are allowed. *Global options* apply to the whole install and must be on a line of their own:

[cols="2,4",options="header"]
|===
| Option | Notes

| `-i`, `--index-url` | Replaces PyPI as the index for the whole run.
| `--extra-index-url` | Adds an index. Every index is searched equally, which is the dependency-confusion risk described on xref:programming-languages/python/build-tools/supply-chain-security.adoc[Supply-Chain Security].
| `--no-index` | Use only `--find-links` locations.
| `-c`, `--constraint` | Include a constraints file; see xref:programming-languages/python/build-tools/pip/constraints-and-build-constraints.adoc[Constraints & Build Constraints].
| `-r`, `--requirement` | Include another requirements file.
| `-e`, `--editable` | An editable requirement (a local project or a VCS URL).
| `-f`, `--find-links` | A directory or HTML page of archives.
| `--no-binary`, `--only-binary`, `--prefer-binary` | Wheel/sdist selection, as on the command line.
| `--require-hashes`, `--no-require-hashes` | Force hash-checking mode, or (26.2) stop it from switching on automatically.
| `--pre`, `--all-releases`, `--only-final` | Pre-release controls (the last two since 26.0).
| `--trusted-host` | Accept a host without valid HTTPS. Avoid it.
| `--use-feature` | Enable a feature flag for the run.
|===

*Per-requirement options* go at the end of a requirement line:

* `--config-settings` (`-C`) passes a setting to the build backend when _that_ requirement is built from source, for example
  `+./birdtally --config-settings editable_mode=compat+`; see
  xref:programming-languages/python/build-tools/pip/build-system-interface.adoc[Build System Interface];
* `+--hash=sha256:…+` lists an allowed hash, and any line with a hash switches on hash-checking mode for the whole run; see
  xref:programming-languages/python/build-tools/pip/repeatable-and-secure-installs.adoc[Repeatable & Secure Installs].

An option that is not supported is a parse error that names the bad line:

[source,bash]
----
printf 'rich --upgrade\n' > bad-req.txt
python -m pip install --dry-run -r bad-req.txt
----

[source,text]
----
ERROR: Invalid requirement: rich --upgrade
__main__.py: error: no such option: --upgrade
----

Source: https://pip.pypa.io/en/stable/reference/requirements-file-format/#supported-options[pip: Supported options],
https://pip.pypa.io/en/stable/reference/requirements-file-format/#global-options[pip: Global options],
https://pip.pypa.io/en/stable/reference/requirements-file-format/#per-requirement-options[pip: Per-requirement options].

== Nested files

`-r other.txt` includes another requirements file and `-c constraints.txt` a constraints file, both relative to the file that
names them. The usual split is a runtime file and a development file that includes it, as in the example: production installs
`requirements.txt`, developers install `requirements-dev.txt` and get both. Since PEP 735, the development half is better expressed as
a dependency group in `pyproject.toml` (`pip install --group dev`), which Poetry and uv read as well; see
xref:programming-languages/python/build-tools/pip/dependency-groups-and-inline-script-metadata.adoc[Dependency Groups & Inline Script Metadata].

Source: https://pip.pypa.io/en/stable/reference/requirements-file-format/#referring-to-other-requirements-files[pip: Referring to other requirements files].

== Environment variables

pip expands `+${NAME}+` in a requirements file from the environment, which keeps index URLs and tokens out of the file:

[source,text]
----
--index-url https://${BIRDWATCH_USER}:${BIRDWATCH_TOKEN}@pypi.internal.example/simple
----

* *Only* the `+${NAME}+` form is expanded; `$NAME` and `%NAME%` are left as they are, so the same file works on every platform.
* Use the POSIX form with braces around an upper-case name, as the documentation asks.
* An unset variable is left as it is. With `+--index-url ${NOPE_UNSET}+` pip 26.2.2 warned
  `+The index url "${NOPE_UNSET}" seems invalid, please provide a scheme.+` and then failed to find any package, so a missing variable
  shows up as `(from versions: none)` rather than as a clear error.

Never commit a token in a requirements file; put it in the environment (or a keyring) and the variable in the file. See
xref:programming-languages/python/build-tools/pip/authentication-proxies-and-certificates.adoc[Authentication, Proxies & Certificates].

Source: https://pip.pypa.io/en/stable/reference/requirements-file-format/#using-environment-variables[pip: Using environment variables].

== Mistakes pip warns about

Forgetting `-r`:

[source,bash]
----
python -m pip install requirements.txt
----

[source,text]
----
ERROR: Could not find a version that satisfies the requirement requirements.txt (from versions: none)
HINT: You are attempting to install a package literally named "requirements.txt" (which cannot exist). Consider using the '-r' flag to install the packages listed in requirements.txt
ERROR: No matching distribution found for requirements.txt
----

Other classic mistakes:

* *Committing a freeze of a development machine* as production requirements; it contains your tools and only your platform's
  dependencies.
* *Mixing `--index-url` lines in several nested files.* The last one read wins for the whole run, not just for the lines after it.
* *Using a requirements file as a library's dependency list* (`+install_requires=open("requirements.txt")…+`). The library then pins
  its users.
* *Expecting a requirements file to remove packages.* `pip install -r` only adds and upgrades; extra packages stay. Recreate the venv,
  or use Poetry's `sync`.

== pip and Poetry

Poetry does not read requirements files. `poetry export -f requirements.txt` writes one from `poetry.lock` (with hashes and markers
by default), and importing one into a Poetry project is described on
xref:programming-languages/python/build-tools/choosing-and-migrating.adoc#_migrating_a_requirements_txt_project_to_poetry[Choosing & Migrating].
