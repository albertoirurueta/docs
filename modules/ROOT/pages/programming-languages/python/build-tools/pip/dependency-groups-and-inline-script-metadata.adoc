= Dependency Groups & Inline Script Metadata
:description: Two standard alternatives to requirements files that pip installs directly -- PEP 735 dependency groups with pip install --group [path:]group (pip 25.1), including include-group expansion, no project discovery and combining a group with -e ., and PEP 723 inline script metadata with pip install --requirements-from-script (pip 26.0) for a single-file birdtally report script -- and when to prefer each over a requirements file.
:keywords: pip install --group, dependency groups, PEP 735, dependency-groups, include-group, requirements-from-script, inline script metadata, PEP 723, script block, requires-python, single-file script, requirements files

include::partial$python-build-tools-disclaimer.adoc[]

Requirements files are pip's own format. Two newer standards cover two of their most common uses: _development dependencies of a
project_ (PEP 735 dependency groups, in `pyproject.toml`) and _the dependencies of a single script_ (PEP 723 inline script
metadata, in the script itself). pip installs both directly. This page was written against pip 26.2.2 and run on CPython 3.14.6 on
2026-10-22, with the pip flavour of *birdtally* and the local *birdwatch* index on `localhost:8080`.

== Dependency groups: `--group` (pip 25.1)

*birdtally* declares four groups in `pyproject.toml`; `dev` includes two others:

[source,toml]
----
[dependency-groups]
test = ["pytest>=8"]
lint = ["ruff>=0.6"]
docs = ["mkdocs>=1.6"]
dev = [{ include-group = "test" }, { include-group = "lint" }]
----

The format is described on xref:programming-languages/python/build-tools/pyproject-toml.adoc#_the_dependency_groups_table[pyproject.toml].
`--group <name>` installs one group from the `pyproject.toml` in the current directory, and can be repeated:

[source,bash]
----
cd birdtally
python -m pip install --group test
----

[source,text]
----

Collecting iniconfig>=1.0.1 (from pytest>=8)
Collecting packaging>=22 (from pytest>=8)
Collecting pluggy<2,>=1.5 (from pytest>=8)
Collecting pygments>=2.7.2 (from pytest>=8)
Installing collected packages: pygments, pluggy, packaging, iniconfig, pytest

Successfully installed iniconfig-2.3.1 packaging-26.3 pluggy-1.7.0 pygments-2.21.0 pytest-9.1.1
----

(The `+Using cached …+` lines are left out.) Three things to notice:

* *The project itself is not installed.* A group is a list of requirements, not a requirement on the project; `pip list` shows
  no `birdtally` afterwards. To test the project, install both: `pip install -e . --group dev`.
* *Includes are expanded.* `--group dev` brings in `test` and `lint`.
* *There is no project discovery.* pip reads `pyproject.toml` in the current directory, or the one you name with
  `path/to/pyproject.toml:group`; the file name must be `pyproject.toml`. That makes it possible to install groups of several
  projects at once (`--group ./sub1/pyproject.toml:test --group ./sub2/pyproject.toml:test`).

[source,bash]
----
python -m pip install -e . --group dev
python -m pytest -q
----

[source,text]
----

…
Successfully built birdtally
Installing collected packages: ruff, birdtally
Successfully installed birdtally-0.1.0 ruff-0.17.1
…

----

The errors are specific:

[source,text]
----
$ python -m pip install --dry-run --group nope
ERROR: [dependency-groups] resolution failed for 'nope' from 'pyproject.toml': Dependency group 'nope' not found

$ python -m pip install --dry-run --group ../pip-flavour/birdtally:dev
--group error: group paths use 'pyproject.toml' filenames
----

Run outside a project directory without a path, pip reports `ERROR: pyproject.toml not found. Cannot resolve '--group' option.`
Groups contain only standard dependency specifiers: no `-e`, `-c`, `--hash` or index options, unlike requirements files.
`--group` cannot be combined with `--only-deps`. The specification recommends against naming a group like an extra, because tools
may treat that as an error.

Source: https://pip.pypa.io/en/stable/user_guide/#dependency-groups[pip user guide: Dependency groups],
https://pip.pypa.io/en/stable/cli/pip_install/#install-group[pip install: --group],
https://packaging.python.org/en/latest/specifications/dependency-groups/#installing-dependency-groups-extras[PyPA: Installing dependency groups and extras],
https://packaging.python.org/en/latest/specifications/dependency-groups/#validation-and-compatibility[PyPA: Validation and compatibility].

The test, lint and docs tools these groups name are described in xref:programming-languages/python/testing.adoc[Testing],
xref:programming-languages/python/debugging-and-tooling.adoc[Debugging & Tooling] and
xref:programming-languages/python/docstrings.adoc[Docstrings]. Poetry reads the same table; see
xref:programming-languages/python/build-tools/poetry/managing-dependencies-and-groups.adoc[Poetry: Managing Dependencies & Groups].

== Inline script metadata: `--requirements-from-script` (pip 26.0)

A single-file script has no `pyproject.toml`. PEP 723 lets it carry its metadata in a comment block that starts with
`+# /// script+` and ends with `+# ///+`; the lines in between, with the leading `+# +` removed, are TOML with `requires-python` and
`dependencies`. A weekly report for the survey team:

[source,python]
----
# /// script
# requires-python = ">=3.10"
# dependencies = [
#   "birdtally[pretty]>=0.1.0",
# ]
# ///
"""Print the weekly bird-survey report as a table."""

import sys

from birdtally import read_sightings, tally_by_site
from rich.console import Console
from rich.table import Table

totals = tally_by_site(read_sightings(sys.argv[1]))
table = Table("Site", "Count", title="Sightings per site")
for site, count in totals.items():
    table.add_row(site, str(count))
Console().print(table)
----

[source,bash]
----
python -m venv .venv
.venv/bin/python -m pip install --index-url http://localhost:8080/simple --requirements-from-script weekly_report.py
.venv/bin/python weekly_report.py survey.csv
----

pip checks `requires-python` against the interpreter it runs with:

[source,text]
----
ERROR: Script 'future.py' requires a different Python: 3.14 not in '>=3.15'
----

pip only installs the dependencies; it does not create an environment or run the script. Runners such as `uv run`, `pipx run` and
Hatch do both, and the specification recommends that such tools pick the newest Python that satisfies `requires-python`. A script
block may also contain a `[tool]` table for those tools.

Source: https://pip.pypa.io/en/stable/cli/pip_install/#install-requirements-from-script[pip install: --requirements-from-script],
https://packaging.python.org/en/latest/specifications/inline-script-metadata/#specification[PyPA: Inline script metadata, specification],
https://packaging.python.org/en/latest/specifications/inline-script-metadata/#script-type[PyPA: The script type],
https://packaging.python.org/en/latest/specifications/inline-script-metadata/#example[PyPA: Example],
https://packaging.python.org/en/latest/specifications/inline-script-metadata/#recommendations[PyPA: Recommendations].

== Which one to use

[cols="2,3,3,3",options="header"]
|===
| | Requirements file | Dependency group | Script metadata

| Lives in | `+requirements*.txt+` | the project's `pyproject.toml` | the script
| Standard | No (pip format) | PEP 735 | PEP 723
| May contain pip options (indexes, hashes, `-e`) | Yes | No | No
| Read by | pip, uv | pip 25.1+, Poetry 2.2+, uv, PDM, Hatch | pip 26.0+, uv, pipx, Hatch
| Typical use | Pinned environments, locks | Test, lint and docs tools of a project | One-file tools and reports
|===

Prefer a group for a project's development tools, because every modern tool reads it and it keeps the dependencies next to the
project metadata. Prefer script metadata for a script that is shared on its own. Keep requirements files for what only they can do:
index options, hashes and pinned environments.
