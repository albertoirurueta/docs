== Global options

These work with every command, before or after the command name.

[cols="2,5",options="header"]
|===
| Option | Meaning

| `-h`, `--help` | Help for the command (`poetry help <command>` does the same and also works for `run`).
| `-q`, `--quiet` | No output.
| `-V`, `--version` | Poetry's version: `Poetry (version 2.5.1)`.
| `--ansi`, `--no-ansi` | Force or disable colours.
| `-n`, `--no-interaction` | Never ask a question; use it in CI and scripts.
| `--no-plugins` | Do not load plugins (for example to rule a plugin out when debugging).
| `--no-cache` | Ignore Poetry's caches for this command, as if they were cold; nothing is deleted.
| `-P`, `--project=PROJECT` | Use the `pyproject.toml` in another directory, resolving arguments against the current directory (2.0).
| `-C`, `--directory=DIRECTORY` | Change to that directory first, then run (since 2.0 it really switches directory).
| `-v`, `-vv`, `-vvv` | More output; `-vvv` shows debug output such as every HTTP request.
|===

The `+SHELL_VERBOSITY+` environment variable sets the same levels without touching the command line, which helps in CI: `-1`
is `-q`, `0` the default, `1` to `3` are `-v` to `-vvv`. With `+SHELL_VERBOSITY=3+`, `poetry version` first printed
`+Loading configuration file …/config.toml+` and the sources it registered.

[source,bash]
----
cd /tmp && poetry -P …/birdtally-report version
poetry -C /tmp version
----

[source,text]
----
birdtally-report 0.1.0

Poetry could not find a pyproject.toml file in /tmp or its parents
----

Source: https://python-poetry.org/docs/cli/#global-options[Poetry CLI: Global options].

== Exit codes

In every case tried, Poetry exited with 0 on success and 1 on an error it reported itself: an unknown command or option, an invalid setting, a failed
resolution, a validation error, a missing project. `poetry run` returns the exit code of the program it ran.

[source,bash]
----
poetry nosuch;                                  echo "exit=$?"
poetry add --bogus x;                           echo "exit=$?"
poetry show nosuchpkg;                          echo "exit=$?"
poetry run python -c "raise SystemExit(3)";     echo "exit=$?"
----

[source,text]
----
The requested command nosuch does not exist.

Documentation: https://python-poetry.org/docs/cli/
exit=1

The option "--bogus" does not exist
exit=1

Package nosuchpkg not found
exit=1
exit=3
----

== Commands

=== `new`

Usage: `+poetry new [options] [--] <path>+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+path+` | The path to create the project at.
| `+-i, --interactive+` | Allow interactive specification of project configuration.
| `+--name=NAME+` | Set the resulting package name.
| `+--src+` | Use the src layout for the project. Deprecated: This is the default option now.
| `+--flat+` | Use the flat layout for the project.
| `+--readme=README+` | Specify the readme file format. Default is md.
| `+--description=DESCRIPTION+` | Description of the package.
| `+--author=AUTHOR+` | Author name of the package.
| `+--python=PYTHON+` | Compatible Python versions.
| `+--dependency=DEPENDENCY+` | Package to require, with an optional version constraint, for example `+requests:^2.10.0+` or `+requests=2.11.1+`. (multiple values allowed)
| `+--dev-dependency=DEV-DEPENDENCY+` | Package to require for development, with an optional version constraint, for example `+requests:^2.10.0+` or `+requests=2.11.1+`. (multiple values allowed)
| `+-l, --license=LICENSE+` | License of the package.
|===

Example: `+poetry new --name birdtally birdtally+`. Details: xref:programming-languages/python/build-tools/poetry/basic-usage-and-project-setup.adoc[Basic Usage & Project Setup]. Since 2.0 the `src` layout is the default (`--src` is deprecated) and `-i` asks for the fields interactively.

=== `init`

Usage: `+poetry init [options]+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+--name=NAME+` | Name of the package.

| `+--dev-dependency=DEV-DEPENDENCY+` | Package to require for development, with an optional version constraint, for example `+requests:^2.10.0+` or `+requests=2.11.1+`. (multiple values allowed)

|===

Example: `+poetry init -n --name birdtally --python ">=3.10"+`. Writes `pyproject.toml` in an existing directory, interactively unless `-n`. Details: xref:programming-languages/python/build-tools/poetry/basic-usage-and-project-setup.adoc[Basic Usage & Project Setup].

=== `add`

Usage: `+poetry add [options] [--] <name>...+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+name+` | The packages to add.
| `+-G, --group=GROUP+` | The group to add the dependency to. [default: "main"]
| `+-D, --dev+` | Add as a development dependency. (shortcut for `+-G dev+`)
| `+-e, --editable+` | Add vcs/path dependencies as editable.
| `+-E, --extras=EXTRAS+` | Extras to activate for the dependency. (multiple values allowed)
| `+--optional=OPTIONAL+` | Add as an optional dependency to an extra.
| `+--python=PYTHON+` | Python version for which the dependency must be installed.
| `+--platform=PLATFORM+` | Platforms for which the dependency must be installed.
| `+--markers=MARKERS+` | Environment markers which describe when the dependency should be installed.
| `+--source=SOURCE+` | Name of the source to use to install the package.
| `+--allow-prereleases+` | Accept prereleases.
| `+--dry-run+` | Output the operations but do not execute anything (implicitly enables --verbose).
| `+--lock+` | Do not perform operations (only update the lockfile).
|===

Example: `+poetry add "rich>=13" --optional=pretty+`. Constraint forms (`+^+`, `+~+`, `+@latest+`, git, path and URL) are on xref:programming-languages/python/build-tools/poetry/dependency-specification.adoc[Dependency Specification]; groups and `--optional` on xref:programming-languages/python/build-tools/poetry/managing-dependencies-and-groups.adoc[Managing Dependencies & Groups]. Since 2.0, `--optional` takes the name of the extra.

=== `show`

Usage: `+poetry show [options] [--] [<package>]+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+package+` | The package to inspect
| `+--without=WITHOUT+` | The dependency groups to ignore. (multiple values allowed)
| `+--with=WITH+` | The optional dependency groups to include. (multiple values allowed)
| `+--only=ONLY+` | The only dependency groups to include. (multiple values allowed)
| `+-t, --tree+` | List the dependencies as a tree.

| `+-f, --format=FORMAT+` | Specify the output format (`+json+` or `+text+`). Default is `+text+`. `+json+` cannot be combined with the --tree option. [default: "text"]
|===

Example: `+poetry show --tree --only main+`. Details: xref:programming-languages/python/build-tools/poetry/managing-dependencies-and-groups.adoc[Managing Dependencies & Groups].

=== `install`

Usage: `+poetry install [options]+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+--without=WITHOUT+` | The dependency groups to ignore. (multiple values allowed)
| `+--with=WITH+` | The optional dependency groups to include. (multiple values allowed)
| `+--only=ONLY+` | The only dependency groups to include. (multiple values allowed)
| `+--sync+` | Synchronize the environment with the locked packages and the specified groups. (Deprecated)
| `+--no-root+` | Do not install the root package (the current project).
| `+--no-directory+` | Do not install any directory path dependencies; useful to install dependencies without source code, e.g. for caching of Docker layers)
| `+--dry-run+` | Output the operations but do not execute anything (implicitly enables --verbose).
| `+-E, --extras=EXTRAS+` | Extra sets of dependencies to install. (multiple values allowed)
| `+--all-extras+` | Install all extra dependencies.
| `+--all-groups+` | Install dependencies from all groups.
| `+--only-root+` | Exclude all dependencies.
| `+--compile+` | Compile Python source files to bytecode.
|===

Example: `+poetry install --with docs --extras pretty+`. `--sync` is deprecated since 2.0 in favour of `poetry sync`. Details: xref:programming-languages/python/build-tools/poetry/lock-file-install-update-and-sync.adoc[Lock File, Install, Update & Sync].

[cols="2,5",options="header"]

=== `build`

Usage: `+poetry build [options]+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

=== `publish`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

=== `check`

Usage: `+poetry check [options]+`

[cols="2,5",options="header"]
|===
| Argument or option | Meaning

| `+--lock+` | Checks that poetry.lock exists for the current version of pyproject.toml.
| `+--strict+` | Fail if check reports warnings.
|===

Example: `+poetry check --lock --strict+`. Validates `pyproject.toml` and that `poetry.lock` matches it; a stale lock file fails with exit code 1 and `+Error: pyproject.toml changed significantly since poetry.lock was last generated. …+`. `--lock` (1.6.0, replacing `poetry lock --check`) also fails when there is no lock file. Prints `All set!` and exits 0 when everything is fine.

| `+-o, --output=OUTPUT+` | The name of the output file.
| `+--without-hashes+` | Exclude hashes from the exported file.
| `+--without-urls+` | Exclude source repository urls from the exported file.
| `+--dev+` | Include development dependencies. (Deprecated)
| `+--all-groups+` | Include all dependency groups
| `+--with=WITH+` | The optional and non-optional dependency groups to include. By default, only the main dependencies are included. (multiple values allowed)
| `+--only=ONLY+` | The only dependency groups to include. (multiple values allowed)
| `+--without=WITHOUT+` | The dependency groups to ignore. (Deprecated) (multiple values allowed)
| `+-E, --extras=EXTRAS+` | Extra sets of dependencies to include. (multiple values allowed)
| `+--all-extras+` | Include all sets of extra dependencies.
| `+--with-credentials+` | Include credentials for extra indices.
|===

Example: `+poetry export -f requirements.txt -o requirements.txt+`. Provided by `poetry-plugin-export`, which is no longer bundled since Poetry 2.0. Details: xref:programming-languages/python/build-tools/poetry/exporting-requirements-and-bundling.adoc[Exporting Requirements & Bundling].

attrs     26.1.0 26.1.0 Classes Without Boilerplate

Resolving dependencies...

attrs 26.1.0 Classes Without Boilerplate

Note the second command: `debug resolve` reported `birdtally`, which lives only on the `explicit` *birdwatch* source, as not
found, while `poetry lock` resolves it through the project's source constraint. Check such packages with `poetry lock` or
`poetry show`.

== Compared with pip

pip has no project commands (`new`, `init`, `add`, `lock`, `version`, `build`, `publish`); `pip install`, `pip uninstall`,
`pip list`, `pip show`, `pip lock` (experimental), `pip config`, `pip cache` and `pip debug` are the closest counterparts of
`install`/`sync`, `remove`, `show`, `lock`, `config`, `cache` and `debug info`/`debug tags`. See the
xref:programming-languages/python/build-tools/choosing-and-migrating.adoc[Choosing & Migrating] mapping table and
xref:programming-languages/python/build-tools/pip/running-pip-and-general-options.adoc[pip: Running pip & General Options].
