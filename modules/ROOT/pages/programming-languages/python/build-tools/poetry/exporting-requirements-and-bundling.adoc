= Exporting Requirements & Bundling
:description: Getting a Poetry project's locked dependencies out of Poetry -- poetry export from poetry-plugin-export 1.10.1 (a plugin since Poetry 2.0) to requirements.txt, constraints.txt and pylock.toml, with every option (--format, --output, --with, --only, --all-groups, -E, --all-extras, --without-hashes, --without-urls, --with-credentials), markers and hashes in the output, private sources as --extra-index-url, installing the result with pip --no-deps --require-hashes, and poetry bundle venv from poetry-plugin-bundle for a self-contained virtual environment.
:keywords: poetry export, poetry-plugin-export, requirements.txt, constraints.txt, pylock.toml, --without-hashes, --without-urls, --with-credentials, --only, --with, --all-groups, --extras, --all-extras, pip install --no-deps, --require-hashes, extra-index-url, trusted-host, poetry bundle venv, poetry-plugin-bundle, deployment

include::partial$python-build-tools-disclaimer.adoc[]

`poetry.lock` is read only by Poetry. When another tool has to install the locked set (pip in a container, a platform that
expects `requirements.txt`, an auditing tool, a PEP 751 installer), export it; when the target is a ready-to-run environment,
bundle it. This page uses Poetry 2.5.1, poetry-plugin-export 1.10.1 and poetry-plugin-bundle 1.8.0. The examples ran on
2026-10-22 on Linux with CPython 3.14.6 and pip 26.2.2, on the *birdtally* project (no main dependencies, a `pretty` extra
pulling in `rich`, and `test`, `lint`, `docs` and `dev` groups). Hashes are shortened to their first eight characters
(`+…+`).

== Installing the export plugin

Poetry 1.2 to 1.8 depended on `poetry-plugin-export`, so `poetry export` was always there. Poetry 2.0 dropped that dependency:

[source,bash]
----
poetry self add poetry-plugin-export
----

or declare it for the project, so that `poetry install` provides it to everyone working on it (see
xref:programming-languages/python/build-tools/poetry/plugins.adoc[Plugins]):

[source,toml]
----
[tool.poetry.requires-plugins]
poetry-plugin-export = ">=1.10"
----

Source: https://python-poetry.org/docs/cli/#export[Poetry CLI: export],
https://github.com/python-poetry/poetry-plugin-export[poetry-plugin-export].

== `poetry export`

[cols="2,5",options="header"]
|===
| Option | Meaning

| `-f`, `--format` | `requirements.txt` (default), `constraints.txt` or `pylock.toml` (plugin 1.10.0).
| `-o`, `--output` | Write to a file instead of standard output.
| `--with`, `--only`, `--all-groups` | Dependency groups, as for `poetry install`. By default only the main dependencies are exported; `--only test` exports a group without them.
| `-E`, `--extras`, `--all-extras` | Extras to include.
| `--without-hashes` | Leave out the `--hash` options.
| `--without-urls` | Leave out the `--extra-index-url`/`--trusted-host` lines for the project's sources.
| `--with-credentials` | Write the sources' credentials into those lines.
| `--without`, `--dev` | Deprecated. The README also lists a deprecated `--default`, which the 1.10.1 `--help` no longer shows.
|===

Every line pins the locked version and carries the markers from `poetry.lock`, so one file serves every platform the lock covers.
With no main dependencies there is nothing to export (the output is empty); with the extra:

[source,bash]
----
poetry export -E pretty --without-hashes
poetry export --only test --without-hashes
----

[source,text]
----
markdown-it-py==4.2.0 ; python_version >= "3.10"
mdurl==0.1.2 ; python_version >= "3.10"
pygments==2.21.0 ; python_version >= "3.10"
rich==15.0.0 ; python_version >= "3.10"
colorama==0.4.6 ; python_version >= "3.10" and sys_platform == "win32"
exceptiongroup==1.3.1 ; python_version == "3.10"
iniconfig==2.3.1 ; python_version >= "3.10"
packaging==26.3 ; python_version >= "3.10"
pluggy==1.7.0 ; python_version >= "3.10"
pygments==2.21.0 ; python_version >= "3.10"
pytest==9.1.1 ; python_version >= "3.10"
tomli==2.5.0 ; python_version == "3.10"
typing-extensions==4.16.0 ; python_version == "3.10"
----

By default every file of every locked release is listed as a hash:

[source,bash]
----
poetry export -E pretty -o requirements.txt
----

[source,text]
----

    --hash=sha256:04a21681… \
    --hash=sha256:9f7ebbcd…
mdurl==0.1.2 ; python_version >= "3.10" \
    --hash=sha256:84008a41… \
    --hash=sha256:bb413d29…

    --hash=sha256:2363c69b… \
    --hash=sha256:610ca751…
rich==15.0.0 ; python_version >= "3.10" \
    --hash=sha256:33bd4ef7… \

----

`-f constraints.txt` has the same lines, for use with `pip install -c` (see
xref:programming-languages/python/build-tools/pip/constraints-and-build-constraints.adoc[pip: Constraints & Build Constraints]).
`-f pylock.toml` writes a PEP 751 lock file; its content is shown on
xref:programming-languages/python/build-tools/lock-files-and-reproducible-installs.adoc[Lock Files & Reproducible Installs].

Source: https://github.com/python-poetry/poetry-plugin-export#usage[poetry-plugin-export: Usage],
https://python-poetry.org/docs/pre-commit-hooks/#poetry-export[Poetry: the poetry-export pre-commit hook].

=== Installing an export with pip

Poetry has already resolved everything, so install with `--no-deps`: pip must not resolve again (and can fail to, for example with
git dependencies exported at their commit). Hashes make pip check every file:

[source,bash]
----
python -m venv .venv
.venv/bin/python -m pip install --no-deps --require-hashes -r requirements.txt
.venv/bin/python -m pip install --no-deps dist/birdtally-0.1.0-py3-none-any.whl
----

[source,text]
----
Installing collected packages: rich, pygments, mdurl, markdown-it-py

Successfully installed markdown-it-py-4.2.0 mdurl-0.1.2 pygments-2.21.0 rich-15.0.0
…
Successfully installed birdtally-0.1.0
----

The project itself is not in the export; install its wheel (or `pip install --no-deps .`) after the dependencies. This two-step
install is the basis of the container recipes on
xref:programming-languages/python/build-tools/ci-caching-and-containers.adoc[CI Caching & Containers].

=== Private sources

The project's sources become index options. For *birdtally-report*, which takes `birdtally` from the explicit, authenticated
*birdwatch* source over plain HTTP:

[source,bash]
----
poetry export --without-hashes
poetry export --without-hashes --with-credentials
----

[source,text]
----
--trusted-host 127.0.0.1:8082
--extra-index-url http://127.0.0.1:8082/simple

attrs==26.1.0 ; python_version >= "3.13"
birdtally==0.1.0 ; python_version >= "3.13"
--trusted-host birdwatch:<password>@127.0.0.1:8082
--extra-index-url http://birdwatch:<password>@127.0.0.1:8082/simple

attrs==26.1.0 ; python_version >= "3.13"
birdtally==0.1.0 ; python_version >= "3.13"
----

(the real password replaced by `<password>`). Three things to notice:

* An `explicit` source becomes an `--extra-index-url`, and pip merges all indexes: the per-package source constraint is lost, so
  the exported file is exposed to dependency confusion that `poetry.lock` was not. Prefer `--require-hashes` (a look-alike
  release fails the hash check) or `--without-urls` with a single index set in pip's configuration.
* `--with-credentials` writes the password into the file in plain text, here even into the `--trusted-host` line. Do not commit
  such a file; pass credentials to pip through `.netrc` or keyring instead (see
  xref:programming-languages/python/build-tools/pip/authentication-proxies-and-certificates.adoc[pip: Authentication, Proxies & Certificates]).
* `--trusted-host` appears because the source uses `http://`.

== `poetry bundle venv`

`poetry-plugin-bundle` installs the project and its locked dependencies, not as editable, into a new virtual environment: an
application ready to copy into a container image or onto a server with the same Python.

[source,bash]
----
poetry self add poetry-plugin-bundle
poetry bundle venv --python=python3.14 --only=main /opt/birdtally
/opt/birdtally/bin/birdtally --help
----

[source,text]
----
  • Bundling birdtally (0.1.0) into /opt/birdtally
  • Bundling birdtally (0.1.0) into /opt/birdtally: Creating a virtual environment using Python …/python3.14
  • Bundling birdtally (0.1.0) into /opt/birdtally: Installing dependencies
  • Bundling birdtally (0.1.0) into /opt/birdtally: Installing birdtally (0.1.0)
  • Bundled birdtally (0.1.0) into /opt/birdtally
usage: birdtally [-h] [--by {species,site}] [--pretty] csv
----

(the target directory shown as `/opt/birdtally`; the run used a scratch directory). The bundled environment held only
`birdtally` and pip. Options: `--with`, `--without`, `--only` for groups; `-p`/`--python` for the interpreter; `--clear` to empty
an existing environment first (without it, a second run installs `over existing file`); `--compile`; and the *experimental*
`--platform` to pick wheels for another platform. Version 1.8.0 has no option for extras.

Like the export plugin, it can be declared for a project instead of installed globally:

[source,toml]
----
[tool.poetry.requires-plugins]
poetry-plugin-bundle = ">=1.8"
----

Source: https://github.com/python-poetry/poetry-plugin-bundle[poetry-plugin-bundle].

== Compared with pip

pip has nothing to export: its lock formats are the inputs (`requirements.txt` with `==` and `--hash`, produced by pip-tools or
`pip freeze`, and `pylock.toml` from the *experimental* `pip lock`). See
xref:programming-languages/python/build-tools/pip/repeatable-and-secure-installs.adoc[pip: Repeatable & Secure Installs] and
xref:programming-languages/python/build-tools/pip/pip-lock-and-pylock-toml.adoc[pip: pip lock & pylock.toml].
