= Managed Attributes
:description: Computed and validated attributes with @property and its setters/deleters, the descriptor protocol that implements @property, and the difference between __getattr__ and __getattribute__.
:keywords: Python, property, property setter, property deleter, descriptor, descriptor protocol, __get__, __set__, __delete__, __set_name__, __getattr__, __getattribute__, managed attributes, data descriptor, non-data descriptor
:page-aliases: web/python/managed-attributes.adoc

A *managed attribute* looks like a plain field from the outside (`obj.value`) but runs code on access,
assignment, or deletion. Python gives you three layers to build one: `@property` for the common case, the
*descriptor protocol* it is built on, and the `+__getattr__+`/`+__getattribute__+` hooks for whole-object
attribute interception.

== `@property`: Computed and Validated Attributes

`@property` turns a method into an attribute-like accessor, so callers write `obj.value` instead of
`obj.get_value()` while the class still runs code on every read. Reference:
https://docs.python.org/3/library/functions.html#property[the `property()` built-in].

[source,python]
----
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @property
    def area(self):
        return 3.14159 * self._radius ** 2   # computed on every read, never stored


c = Circle(2)
print(c.radius)    # 2            -- looks like a plain attribute
print(c.area)       # 12.56636    -- computed, not stored
----

=== Setters and Deleters

A bare `@property` is read-only -- assigning to it raises `AttributeError`. `@<name>.setter` and
`@<name>.deleter` add the missing operations, letting a setter *validate* before storing:

[source,python]
----
class Circle:
    def __init__(self, radius):
        self.radius = radius          # goes through the setter below, validated from construction on

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("radius must be positive")
        self._radius = value

    @radius.deleter
    def radius(self):
        del self._radius


c = Circle(3)
c.radius = 5          # runs the setter's validation
# c.radius = -1        # raises ValueError: radius must be positive
del c.radius           # runs the deleter
----

The setter and deleter are attached with `@radius.setter`/`@radius.deleter` -- decorating a *second and
third* method that reuses the property's name, which is why all three defer to a single private
`+self._radius+` for storage.

== Descriptors: the Protocol Behind `@property`

`@property` is not special-cased in the interpreter -- it is an ordinary class implementing the
*descriptor protocol*: any object defining `+__get__+`, `+__set__+`, or `+__delete__+` and assigned as a
*class* attribute intercepts attribute access on every instance. Full walkthrough, including how `property`
itself is implemented in pure Python: https://docs.python.org/3/howto/descriptor.html[the Descriptor HowTo
Guide].

[source,python]
----
class PositiveNumber:
    def __set_name__(self, owner, name):
        self._name = "_" + name        # remembers which attribute it was assigned to

    def __get__(self, instance, owner):
        if instance is None:
            return self                # accessed on the class itself, e.g. Circle.radius
        return instance.__dict__[self._name]

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self._name[1:]} must be positive")
        instance.__dict__[self._name] = value

    def __delete__(self, instance):
        del instance.__dict__[self._name]


class Circle:
    radius = PositiveNumber()          # descriptor instance, assigned as a CLASS attribute

    def __init__(self, radius):
        self.radius = radius           # triggers PositiveNumber.__set__


c = Circle(3)
print(c.radius)   # 3   -- triggers PositiveNumber.__get__
c.radius = 5       # triggers PositiveNumber.__set__
# c.radius = -1     # raises ValueError: radius must be positive
----

A descriptor defining `+__set__+` or `+__delete__+` is a *data descriptor* and takes priority over an
instance's own `+__dict__+`; one defining only `+__get__+` is a *non-data descriptor* and an instance
attribute of the same name wins instead. `@property` always defines all three methods, so it is always a
data descriptor -- which is why assigning `+self.radius = ...+` inside `+__init__+` still goes through its
setter rather than silently creating a shadowing instance attribute.

== `+__getattr__+` vs. `+__getattribute__+`

Both hooks intercept `obj.name`, but at different points in the lookup, per
https://docs.python.org/3/reference/datamodel.html#object.__getattr__[the data model reference]:

* `+__getattribute__+` runs for *every* attribute access, unconditionally -- normal lookup (instance
  `+__dict__+`, then class, then descriptors) is whatever the default implementation does internally.
  Overriding it means reimplementing that lookup yourself for every attribute, including ones you do not
  care about.
* `+__getattr__+` runs only as a *fallback*, after normal lookup has already failed with
  `AttributeError` -- it never sees an attribute that was found normally, so it only needs to handle the
  missing case.

=== Validating with `+__getattr__+` (the common case)

Use `+__getattr__+` to compute or validate attributes that do not otherwise exist, without touching lookup
for anything that does:

[source,python]
----
class Config:
    def __init__(self):
        self.debug = True                 # a real attribute; __getattr__ never sees it

    def __getattr__(self, name):
        if name.startswith("_"):
            raise AttributeError(name)
        return f"<no setting '{name}'>"    # fallback for any other missing attribute


cfg = Config()
print(cfg.debug)        # True                          -- normal lookup, __getattr__ not called
print(cfg.timeout)       # <no setting 'timeout'>        -- lookup failed, __getattr__ called
----

=== Validating with `+__getattribute__+` (intercepting everything)

Use `+__getattribute__+` only when *every* access -- existing attributes included -- must be checked, and
always delegate to the base implementation to keep normal lookup working:

[source,python]
----
class Locked:
    def __init__(self):
        self.value = 42

    def __getattribute__(self, name):
        if name == "value":
            print(f"reading {name!r}")
        return super().__getattribute__(name)   # required: performs the actual lookup


obj = Locked()
print(obj.value)   # prints "reading 'value'", then 42 -- runs even though 'value' exists
----

Forgetting `+super().__getattribute__(name)+` and instead writing `self.name` inside `+__getattribute__+`
recurses infinitely, since reading `self.name` calls `+__getattribute__+` again.

== Descriptors Step by Step

A *descriptor* is any object stored as a class attribute that defines `+__get__+`, and optionally `+__set__+` and `+__delete__+`.
When the attribute is looked up through an instance, Python calls the descriptor instead of returning it. Properties,
methods, `classmethod`, `staticmethod`, `functools.cached_property` and `+__slots__+` members are all descriptors, so this one
mechanism sits under most of Python's attribute behaviour (see the
https://docs.python.org/3/howto/descriptor.html[Descriptor HowTo Guide]).

=== The lookup order that decides who wins

Attribute lookup (`obj.name`) consults the type first. A *data descriptor* (one that defines `+__set__+` or `+__delete__+`) wins
over the instance dictionary; the instance dictionary wins over a *non-data descriptor* (only `+__get__+`, which is how
functions bind as methods) and over a plain class attribute. Assignment (`obj.name = value`) calls the data descriptor's
`+__set__+` if there is one, and otherwise writes the instance dictionary.

[mermaid]
....
flowchart TD
    A["obj.name"] --> B{"name found on type(obj)\nthrough the MRO?"}
    B -- No --> C{"name in obj.__dict__?"}
    B -- Yes --> D{"Is it a data descriptor\nwith __set__ or __delete__?"}
    D -- Yes --> E["Call type attribute's __get__\n(data descriptor wins)"]
    D -- No --> F{"name in obj.__dict__?"}
    F -- Yes --> G["Return the instance value"]
    F -- No --> H{"Non-data descriptor\nwith __get__?"}
    H -- Yes --> I["Call its __get__ (methods bind here)"]
    H -- No --> J["Return the plain class attribute"]
    C -- Yes --> G
    C -- No --> K["Call __getattr__ if defined,\nelse AttributeError"]
....

[source,python]
----
class NonData:
    def __get__(self, obj, objtype=None):
        return "from non-data descriptor"


class Data(NonData):
    def __set__(self, obj, value):
        print("Data.__set__ intercepted", value)


class Demo:
    plain = "class attribute"
    non_data = NonData()
    data = Data()


d = Demo()
d.__dict__["non_data"] = "instance value"
d.__dict__["data"] = "instance value"
d.__dict__["plain"] = "instance value"
print(d.plain)         # instance dict beats a plain class attribute
print(d.non_data)      # instance dict beats a non-data descriptor
print(d.data)          # a data descriptor beats the instance dict
d.data = 5

# functions are non-data descriptors: that is how methods bind
class K:
    def f(self):
        return "called"
k = K()
print(K.f.__get__(k, K)(), K.__dict__["f"].__get__(None, K) is K.f)
k.f = lambda: "instance override"                # allowed: functions are non-data descriptors
print(k.f())
----

Output:

[source,text]
----
instance value
instance value
from non-data descriptor
Data.__set__ intercepted 5
called True
instance override
----

The last two lines show why you can monkey-patch a method on an *instance* (functions are non-data descriptors) but cannot
do the same to a property.

=== A reusable validating descriptor

A property validates one attribute of one class; a descriptor validates a *kind* of attribute across many classes.
`+__set_name__+` (3.6+) tells the descriptor the attribute name it was assigned to, so the same `Positive` instance logic
can serve `days` and `copies`. When the descriptor is accessed on the class (`Loan.days`), `obj` is `None` and the
convention is to return the descriptor itself, which is also how tools and documentation reach it. Store per-instance
values on the *instance* (as `+_days+` here), never on the descriptor, because the descriptor object is shared by every instance.

[source,python]
----
class Positive:
    """A data descriptor: defines __set__, so it overrides the instance __dict__."""

    def __set_name__(self, owner, name):        # called once, when the class is created
        self.name = name
        self.storage = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:                          # accessed on the class: return the descriptor itself
            return self
        return getattr(obj, self.storage)

    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name} must be positive, got {value}")
        setattr(obj, self.storage, value)


class Loan:
    days = Positive()
    copies = Positive()

    def __init__(self, days, copies):
        self.days = days                         # triggers Positive.__set__
        self.copies = copies


loan = Loan(14, 2)
print(loan.days, loan.copies, vars(loan))        # values stored under _days and _copies
print(type(Loan.days).__name__, Loan.__dict__["days"] is Loan.days)
try:
    loan.days = 0
except ValueError as exc:
    print("ValueError:", exc)

loan.__dict__["days"] = 99                       # sneaking a value into the instance dict...
print(loan.days)                                 # ...does not matter: the data descriptor wins
----

Output:

[source,text]
----
14 2 {'_days': 14, '_copies': 2}
Positive True
ValueError: days must be positive, got 0
14
----

=== Properties and cached properties

`@property` builds a data descriptor from a getter, with `@name.setter` and `@name.deleter` adding the other halves; a
property with no setter is read-only, which is the cheapest way to expose a computed value without storing it. Use a
property when access should look like an attribute but needs validation, computation or a stable public name over changing
internals; do not use it to hide expensive work (callers expect attribute access to be cheap). `functools.cached_property`
(3.8+) is a *non-data* descriptor: the first access computes the value and stores it in the instance dictionary, which then
shadows the descriptor, so later reads are plain dictionary hits. It needs a writable instance `+__dict__+`, so it does not
work with `+__slots__+` classes unless a `+__dict__+` slot exists.

[source,python]
----
import functools


class Book:
    def __init__(self, title, pages):
        self.title = title
        self._pages = pages

    @property
    def pages(self):
        return self._pages

    @pages.setter
    def pages(self, value):
        if not isinstance(value, int) or value <= 0:
            raise ValueError("pages must be a positive int")
        self._pages = value

    @property
    def reading_hours(self):                      # computed on access, no storage
        return round(self._pages / 40, 1)

    @functools.cached_property                    # computed once, stored in the instance __dict__
    def checksum(self):
        print("computing checksum")
        return sum(map(ord, self.title))


b = Book("Dune", 600)
print(b.pages, b.reading_hours)
b.pages = 800
print(b.reading_hours, type(Book.pages).__name__)
try:
    b.reading_hours = 3
except AttributeError:
    print("AttributeError: read-only property")
print(b.checksum, b.checksum, "checksum" in vars(b))


# __getattr__ is the fallback; __getattribute__ sees every access
class Trace:
    def __init__(self):
        self.real = 1

    def __getattr__(self, name):
        print("fallback for", name)
        return None

    def __getattribute__(self, name):
        if not name.startswith("__"):
            print("lookup", name)
        return super().__getattribute__(name)

t = Trace()
t.real
t.missing
----

Output:

[source,text]
----
600 15.0
20.0 property
AttributeError: read-only property
computing checksum
396 396 True
lookup real
lookup missing
fallback for missing
----

=== `+__getattr__+` and `+__getattribute__+`: the escape hatches

`+__getattribute__+` runs for *every* attribute read, so overriding it is powerful and risky: any `self.x` inside it recurses
unless you go through `+super().__getattribute__(name)+` or `+object.__getattribute__+`. `+__getattr__+` only runs after normal
lookup has failed, which makes it the safe choice for fallbacks, lazy attributes and proxies. In both cases remember that
implicit special-method lookup (`len(obj)`, `pass:c[obj + 1]`) bypasses them. Reach for a descriptor or property first; reserve
these hooks for dynamic proxies and attribute-forwarding wrappers (see
xref:programming-languages/python/advanced-oop-design.adoc[Advanced OOP Design]).
