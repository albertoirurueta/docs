== The Mental Models Behind the Sheet

The sheet is dense because Python is small: almost everything on it is an application of five ideas. When a line of the
sheet surprises you, ask which of the five applies.

[mermaid]
....
flowchart TD
    M["Python's core mental models"] --> N["Names refer to objects;\nassignment never copies"]
    M --> P["Everything is an object\nwith a type and an identity"]
    M --> Q["Syntax is sugar for protocols:\niter, next, enter, exit, call, getitem"]
    M --> R["Attribute lookup:\ninstance, class, bases in MRO order,\ndescriptors in between"]
    M --> S["Code runs when it is executed:\ndef, class and import are statements"]
    N --> N1["Aliasing, mutable defaults,\nshallow vs deep copy"]
    Q --> Q1["for loops, with blocks,\noperators, len, truthiness"]
    R --> R1["super, mixins, property,\nmethods binding"]
    S --> S1["Default arguments, decorators,\nclass creation, import side effects"]
....

[cols="2,3,2",options="header"]
|===
|When this surprises you |Remember |Page

|Two names change together |Names refer to the same object; copy explicitly |xref:programming-languages/python/variables-and-dynamic-typing.adoc[Variables and Dynamic Typing]
|`pass:c[0.1 + 0.2 != 0.3]` |Floats are binary doubles; use `Decimal` or `math.isclose` |xref:programming-languages/python/numbers.adoc[Numbers]
|A default list keeps growing |Defaults are evaluated once, at `def` time |xref:programming-languages/python/functions.adoc[Functions]

|An attribute ignores what I stored |A data descriptor beats the instance dictionary |xref:programming-languages/python/managed-attributes.adoc[Managed Attributes]

|A task never finishes under `asyncio` |A blocking call stalls the single-threaded loop |xref:programming-languages/python/concurrency-and-async.adoc[Concurrency and Async]

=== A self-check you can run

The script below turns twelve of the sheet's claims into assertions. If one fails on your interpreter, the corresponding
page explains the behaviour.

[source,python]
----
"""Executable versions of the cheat sheet's key claims. Each check prints OK or raises AssertionError."""
import functools

def check(label, condition):
    assert condition, label
    print("OK  ", label)

a = [1]; b = a; c = list(a)
check("assignment aliases, copy() does not", b is a and c is not a)
check("tuples hash, lists do not", hash((1, 2)) is not None and getattr([], "__hash__") is None)
check("and/or return an operand", ("" or "x") == "x" and (1 and 2) == 2)
check("default args are evaluated once", (lambda f: f() is f())(lambda x=[]: x))
check("closures capture variables", [f() for f in [lambda: i for i in range(2)]] == [1, 1])
check("generators are single-pass", (lambda g: (list(g), list(g)))(x for x in "ab") == (["a", "b"], []))
check("sort is stable", sorted([("b", 1), ("a", 1)], key=lambda t: t[1]) == [("b", 1), ("a", 1)])

class A:
    def who(self): return "A"
class B(A):
    def who(self): return "B" + super().who()
check("super follows the MRO", B().who() == "BA" and [k.__name__ for k in B.__mro__] == ["B", "A", "object"])

class P:
    @property
    def x(self): return 1
check("property is a data descriptor on the class", hasattr(type(P.x), "__set__"))

@functools.lru_cache(maxsize=None)
def sq(n): return n * n
sq(3); sq(3)
check("lru_cache caches by arguments", sq.cache_info().hits == 1)

with open(__file__) as f:
    pass
check("with closes the file", f.closed)

try:
    {}["k"]
except KeyError as e:
    check("exceptions are objects with a type", type(e).__name__ == "KeyError" and e.args == ("k",))
----
