== Duration: a length of time

A `time.Duration` is an `int64` counting *nanoseconds*. That makes it exact, cheap and comparable with `<`, and it limits
the range to about 292 years. It is a defined type with methods, and the package provides constants for the units, so
that a duration is written as a number times a unit:

[cols="1,2",options="header"]
|===
| Constant | Value

| `time.Nanosecond`
| 1

| `time.Microsecond`
| 1000 nanoseconds

| `time.Millisecond`
| 1000 microseconds

| `time.Second`
| 1000 milliseconds

| `time.Minute`
| 60 seconds

| `time.Hour`
| 60 minutes
|===

There is no `Day`, `Week`, `Month` or `Year` constant, on purpose: a day is not always 24 hours (see
<<_time_zones_and_location,daylight saving>>) and a month has no fixed length. A period measured in calendar units is
added to a `Time` with `AddDate`, not expressed as a `Duration`. The `String` method prints the largest unit that fits
(`1h30m0s`, `1.5s`, `250ms`), and `ParseDuration` reads the same notation with the units `ns`, `us` (or `µs`), `ms`,
`s`, `m` and `h`, each number optionally fractional and signed.

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func main() {
	// A loan period is a Duration: an int64 count of nanoseconds.
	loan := 21 * 24 * time.Hour
	grace := 90 * time.Minute
	fmt.Println(loan, grace, loan+grace)
	fmt.Printf("%d %T\n", time.Second, time.Second)

	// Accessors return float64 (Seconds, Minutes, Hours) or int64.
	fmt.Println(loan.Hours(), grace.Minutes(), grace.Milliseconds())

	// Parsing and printing.
	d, err := time.ParseDuration("1h15m30.5s")
	fmt.Println(d, err)
	_, err = time.ParseDuration("3 days")
	fmt.Println(err)

	// Round and Truncate round to a multiple; Abs (1.19) is safe at MinInt64.
	fmt.Println(d.Round(time.Minute), d.Truncate(time.Hour), (-d).Abs())

	// Multiply a Duration by a count only after converting the count.
	n := 3
	fmt.Println(time.Duration(n)*time.Second, 1500*time.Millisecond)

	// Duration arithmetic wraps around silently on overflow.
	big := time.Duration(1<<63 - 1)
	fmt.Println(big, big+1)
}
----

A few details in the output deserve a closer look.

* `Hours`, `Minutes` and `Seconds` return `float64`; `Milliseconds`, `Microseconds` and `Nanoseconds` return `int64`.
  Use the integer ones for exact values.
* `Round` and `Truncate` round a duration to a multiple of `m`; halfway values round away from zero. `Abs` (Go 1.19)
  returns the absolute value and, unlike negating by hand, saturates at the minimum value instead of overflowing.
* `ParseDuration` accepts no days (`3 days`, or `1d`): the error names the unit it could not read.
* A `Duration` converts to a number (`int64(d)`) and back, and prints with `%d` as raw nanoseconds, with `%v` and `%s`
  through `String`.
* Arithmetic on `Duration` is plain `int64` arithmetic and wraps around on overflow, as the last line shows. `Time.Sub`
  is the exception: it saturates at the largest and smallest durations.

=== Multiplying a duration by a number

The constants are *typed* constants of type `Duration`, and Go has no implicit conversions. Two mistakes follow, and both
are rejected by the compiler:

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func main() {
	n := 3
	fmt.Println(n * time.Second)
	fmt.Println(1.5 * time.Second)
}
----

[source,text]
----
./main.go:10:14: invalid operation: n * time.Second (mismatched types int and time.Duration)
./main.go:11:14: 1.5 (untyped float constant) truncated to int64
----

The first is the most common compile error with this package: `+n * time.Second+` where `n` is an `int` variable. Convert
the count: `+time.Duration(n) * time.Second+`. The second looks harmless and is not: `1.5` is converted to the type of
`time.Second`, `Duration`, which is an integer type, and an untyped constant that cannot be represented exactly is an
error. Write `+1500 * time.Millisecond+`, or `+time.Duration(1.5 * float64(time.Second))+` when the factor is computed at run
time. See xref:programming-languages/go/variables-constants-and-iota.adoc[Variables, Constants and iota] for the rules
of typed and untyped constants.

== Time: an instant, with two clocks

A `time.Time` represents an *instant* with nanosecond precision, together with a `Location` used when the instant is
shown as a calendar date. It is a small value type (a wall-clock reading, an optional monotonic reading and a location
pointer), meant to be copied and passed by value, never by pointer. It is safe to share between goroutines because no
method mutates it.

The zero value, `+time.Time{}+`, is January 1 of year 1, 00:00:00 UTC. It is not the Unix epoch, and `IsZero` is the
correct way to ask "was this field ever set?" (a `Time.Unix()` of `0` is the year 1970, not an unset value).

=== Wall clock and monotonic clock

`time.Now()` returns two readings of the clock. The *wall clock* is the calendar time of day; it is what
`Format` prints, and it can jump: an administrator or NTP changes it, a virtual machine resumes, or a leap second is
smeared. The *monotonic clock* only moves forward at a steady rate and is meant for measuring intervals. A `Time` made
by `Now` carries both; when two `Time` values both carry a monotonic reading, `Sub`, `Since`, `Until`, `Before`, `After`,
`Equal` and `Compare` use it and ignore the wall clock. A program that measures `time.Since(start)` therefore keeps
working across a clock change, which is the behaviour the older `time` API of other languages makes you ask for
explicitly.

The monotonic reading is a property of the value. `Add` keeps it, and every operation whose purpose is to change how the
wall time is read *strips* it: `Round` and `Truncate` (with any argument), `UTC`, `Local` and `In`. Values built by
`Date`, `Parse` and `Unix` never have one. `Round(0)` is the idiom to strip it on purpose, for example before comparing
with `==` or before storing the value. The monotonic reading shows in `String()` as `pass:c[m=+0.000012345]`; do not
parse it, and do not rely on it surviving serialisation.

[source,go]
----
package main

import (
	"fmt"
	"strings"
	"time"
)

func main() {
	// Now carries a wall-clock reading and a monotonic reading.
	start := time.Now()
	fmt.Println("Now:      ", hasMono(start))

	// Add keeps the reading; Round(0), UTC, Local and In strip it.
	fmt.Println("Add:      ", hasMono(start.Add(time.Hour)))
	fmt.Println("Round(0): ", hasMono(start.Round(0)))
	fmt.Println("UTC:      ", hasMono(start.UTC()))

	// Equal compares instants; == also compares location pointer and monotonic reading.
	a := time.Date(2026, time.October, 18, 12, 0, 0, 0, time.UTC)
	cet := time.FixedZone("CET", 3600)
	b := a.In(cet)
	fmt.Println("a == b:       ", a == b)
	fmt.Println("a.Equal(b):   ", a.Equal(b))
	fmt.Println("a.Compare(b): ", a.Compare(b))
	fmt.Println("a.Before(b.Add(time.Nanosecond)):", a.Before(b.Add(time.Nanosecond)))

	// Zero value: January 1, year 1, 00:00:00 UTC.
	var zero time.Time
	fmt.Println(zero, zero.IsZero(), zero.Unix())

	// Sub, Since, Until.
	due := a.AddDate(0, 0, 21)
	fmt.Println(due.Sub(a), due.Format(time.DateOnly), due.Weekday(), due.YearDay())
	y, w := due.ISOWeek()
	fmt.Println(y, w)

	// Time values from and to Unix timestamps.
	u := time.Unix(1_790_000_000, 0).UTC()
	fmt.Println(u, u.UnixMilli(), time.UnixMilli(u.UnixMilli()).UTC().Equal(u))
}

// hasMono reports whether t carries a monotonic clock reading: String
// appends it as "m=+0.000012345".
func hasMono(t time.Time) bool { return strings.Contains(t.String(), " m=") }
----

=== Comparing instants: Equal, Compare and ==

Three things look like equality and are not:

* `t1.Equal(t2)` is true when both are the *same instant*, whatever their locations. This is the comparison to use.
* `t1 == t2` compares the struct, including the location pointer and the monotonic reading, so the same instant in UTC
  and in `FixedZone("CET", 3600)` is *not* `==`. The output above prints `a == b: false` and `a.Equal(b): true` for the
  same instant. It is wrong in almost every program, and `reflect.DeepEqual` has the same problem because it compares the
  fields.
* `t1.Compare(t2)` (Go 1.20) returns `-1`, `0` or `+1` and is meant for sorting: `slices.SortFunc(loans, func(a, b Loan)
  int { return a.Due.Compare(b.Due) })`. `Before` and `After` are the boolean forms.

Because of the location pointer, a `time.Time` is a poor `map` key; the next sections show a fix. `Time` has no `<` or
`>`, which is why there are methods.

=== Calendar fields and Unix timestamps

`Year`, `Month` (a `time.Month`, printed as `October` and numbered from 1), `Day`, `Hour`, `Minute`, `Second`,
`Nanosecond`, `Weekday` (a `time.Weekday`, Sunday is 0), `YearDay`, `ISOWeek` and `Date()`/`Clock()` (all three fields at
once) read the date in the value's own location. `Unix`, `UnixMilli`, `UnixMicro` and `UnixNano` return the integer count
since 1970-01-01 UTC (`UnixNano` is undefined for dates outside the years 1678 to 2262), and `time.Unix(sec, nsec)`,
`time.UnixMilli` and `time.UnixMicro` build a `Time` from them; the result is in the *local* time zone, so call `.UTC()`
before printing a timestamp.

`Truncate(d)` and `Round(d)` round an instant to a multiple of `d` *counted from the zero time in UTC*. For a day that
is midnight UTC, not midnight in the value's location, so `+t.Truncate(24 * time.Hour)+` is the wrong way to find the
start of the local day; build it with `time.Date(t.Year(), t.Month(), t.Day(), 0, 0, 0, 0, t.Location())`. The last
example on this page shows the difference.

== Time zones and Location

A `+*time.Location+` is a set of rules that maps an instant to an offset from UTC and an abbreviation (`EST`, `CET`). A
`Time` holds one, and `t.In(loc)` returns the same instant presented in `loc` (the value and its monotonic reading are
unchanged apart from the stripping described above). Three locations are always available:

* `time.UTC`: no offset, no rules.
* `time.Local`: the zone of the machine, from the `TZ` environment variable or the system's configuration. Servers
  usually run in UTC, laptops do not; code that works in `Local` therefore behaves differently in development and in
  production. Store and exchange instants in UTC (or as Unix timestamps) and convert to a zone only to show them.
* a `time.FixedZone(name, offsetSeconds)`: a constant offset with no daylight saving, for a zone you know only by its
  offset.

`time.LoadLocation("America/New_York")` loads a zone with full history from the IANA time zone database. It searches, in
order: the directory or uncompressed zip file named by the `ZONEINFO` environment variable, the system's installation
(`/usr/share/zoneinfo` on Unix), `$GOROOT/lib/time/zoneinfo.zip`, and the copy embedded in the binary if the program
imports `time/tzdata` (or is built with `-tags timetzdata`). The embedded copy adds about 450 KB; import it from the
`main` package of programs that run in minimal containers (a `scratch` or `distroless` image has no zone files), not from
libraries. `LoadLocation("")` and `LoadLocation("UTC")` return UTC, `LoadLocation("Local")` returns `Local`, and an
unknown name is an error, as the first lines of the output show.

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func main() {
	ny, err := time.LoadLocation("America/New_York")
	if err != nil {
		fmt.Println(err)
		return
	}
	_, err = time.LoadLocation("Mars/Olympus_Mons")
	fmt.Println(err)

	// A branch closes at 18:00 local time, whatever the offset is that day.
	closing := time.Date(2026, time.March, 7, 18, 0, 0, 0, ny)
	fmt.Println(closing)

	// AddDate works on the calendar; Add works on the clock.
	fmt.Println(closing.AddDate(0, 0, 1))              // next day, still 18:00 local
	fmt.Println(closing.Add(24 * time.Hour))           // 24 hours later: 19:00 EDT
	fmt.Println(closing.AddDate(0, 0, 1).Sub(closing)) // only 23 hours apart

	// A wall time that does not exist is normalised; one that happens
	// twice picks one of the two instants.
	gap := time.Date(2026, time.March, 8, 2, 30, 0, 0, ny)
	fmt.Println("gap: ", gap)
	twice := time.Date(2026, time.November, 1, 1, 30, 0, 0, ny)
	fmt.Println("twice:", twice, twice.IsDST())

	// Zone, ZoneBounds (1.19) and In.
	name, offset := closing.Zone()
	start, end := closing.ZoneBounds()
	fmt.Println(name, offset, start, end)
	fmt.Println(closing.In(time.UTC), closing.UTC().Location(), time.Local != nil)

	// A fixed offset has no daylight saving rules.
	ist := time.FixedZone("IST", 5*3600+30*60)
	fmt.Println(closing.In(ist).Format(time.RFC1123Z))

	// Month overflow is normalised, not rejected.
	fmt.Println(time.Date(2026, time.January, 31, 0, 0, 0, 0, time.UTC).AddDate(0, 1, 0).Format(time.DateOnly))
	fmt.Println(time.Date(2026, time.February, 30, 25, 61, 0, 0, time.UTC))
}

What this output teaches:

* `AddDate(0, 0, 1)` moves the *calendar* by one day and keeps the local time of day (18:00), so across the March
  daylight saving change the two instants are only 23 hours apart. `+Add(24 * time.Hour)+` moves the *clock* by 24
  hours and lands at 19:00 EDT. For "the book is due in three weeks" use `AddDate(0, 0, 21)`; for "the hold expires in 48
  hours" use `+Add(48 * time.Hour)+`.
* A local time that does not exist (02:30 on the spring-forward day) or that happens twice (01:30 on the fall-back day)
  is resolved by `Date` without an error, and the documentation says the choice between the two possible results is not
  guaranteed. Code that must be exact near a change represents the instant in UTC or uses the offset (`-0500`).
* `Zone()` returns the abbreviation and offset in effect, `ZoneBounds()` (Go 1.19) the start and end of that period (the
  zero `Time` when unbounded), and `IsDST()` (Go 1.17) whether daylight saving is in effect. Abbreviations are not
  unique (`IST` is Indian, Irish and Israel Standard Time) and must not be parsed back for a zone.
* `Date` normalises out-of-range fields instead of rejecting them: month 13 becomes January of the next year,
  `pass:c[January 31 + 1 month]` becomes March 3 (February 31 does not exist), and `February 30, 25:61` carries over into March.
  Validate user-supplied dates by comparing the fields you passed with the fields of the result.

== Formatting and parsing: the reference time

Go formats times with an example instead of with codes. A *layout* is the reference time

[source,text]
----
Mon Jan 2 15:04:05 MST 2006
----

(which is also `+01/02 03:04:05PM '06 -0700+`: month 1, day 2, hour 3 or 15, minute 4, second 5, year 2006, zone offset
-7 hours) written the way the output should look. `Format` replaces each recognised element of the layout with the
matching field of the time; `Parse` reads a string with the same layout. The reference time was chosen so that each
element has a different number, which is how the parser tells `01` (month) from `02` (day) from `04` (minute).

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func main() {
	t := time.Date(2026, time.October, 18, 15, 4, 5, 123456789, time.UTC)

	// The layout is the reference time written the way you want the output.
	// Mon Jan 2 15:04:05 MST 2006 is 01/02 03:04:05PM '06 -0700.
	layouts := []struct{ name, layout string }{
		{"DateTime", time.DateTime},
		{"DateOnly", time.DateOnly},
		{"TimeOnly", time.TimeOnly},
		{"RFC3339", time.RFC3339},
		{"RFC3339Nano", time.RFC3339Nano},
		{"RFC1123", time.RFC1123},
		{"Kitchen", time.Kitchen},
		{"custom", "Mon 2 Jan 2006, 3:04pm"},
		{"millis", "2006-01-02 15:04:05.000"},
		{"trimmed fraction", "15:04:05.999"},
	}
	for _, l := range layouts {
		fmt.Printf("%-16s %s\n", l.name, t.Format(l.layout))
	}

	// Parse reads the same layouts; a missing zone means UTC.
	p, err := time.Parse(time.DateTime, "2026-11-08 09:30:00")
	fmt.Println(p, err)

	// ParseInLocation interprets an offset-less time in a given location.
	ny, _ := time.LoadLocation("America/New_York")
	q, err := time.ParseInLocation(time.DateTime, "2026-11-08 09:30:00", ny)
	fmt.Println(q, err)

	// Errors are *time.ParseError values.
	_, err = time.Parse(time.DateOnly, "18/10/2026")
	fmt.Println(err)
	_, err = time.Parse(time.DateOnly, "2026-02-30")
	fmt.Println(err)

	// The classic trap: 2016 is not a year in the reference time.
	fmt.Println(t.Format("2016-01-02"))
	fmt.Println(t.Format("2006-01-02"))

	// AppendFormat avoids an allocation when building log lines.
	buf := []byte("due=")
	buf = t.AppendFormat(buf, time.DateOnly)
	fmt.Println(string(buf))
}

=== Parsing, locations and errors

* `time.Parse(layout, s)` returns a time in UTC when `s` has no zone information, and in a made-up location with the
  given abbreviation and a zero offset when it has an abbreviation that the process's `Local` does not know. Prefer
  numeric offsets in anything you control.
* `time.ParseInLocation(layout, s, loc)` is the correct call for a string such as `2026-11-08 09:30:00` that means
  "9:30 in this branch's zone"; the example shows the result in `America/New_York` (`-0500 EST`, because daylight saving
  has ended by that date).
* Failures are `+*time.ParseError+` values with the layout, the value and the element that failed. Beyond a wrong layout
  they include a day that does not exist (`2026-02-30` is `day out of range`); unlike `Date`, `Parse` validates.
* Leap seconds and `:60` are not supported, and a seconds field may be followed by a fraction in the input even if the
  layout has none.

=== The classic layout mistake

The layout must be built from the reference numbers, not from today's date. `t.Format("2016-01-02")` is not a year
2016 layout: `2006` is the year element and `2016` is not, so the digits are read as other elements and the result is
garbage such as `18106-10-18`. Layouts borrowed from other languages fail silently too: `YYYY-MM-DD HH:mm` contains no
recognised element and is copied to the output unchanged (the check run for this page printed it back verbatim). When a time prints strangely, check the layout against
`time.Layout`. The output of the example shows the failing and the correct form side by side.

== Time and Duration in JSON, maps and comparisons

`Time` marshals as an RFC 3339 string with nanoseconds, in the value's own offset, and unmarshals only that format;
`Duration` has no special treatment and marshals as an integer count of nanoseconds, which is rarely what an API wants.
The next program shows both, the `map` key problem from the comparison section, and the `Truncate` surprise.

[source,go]
----
package main

import (
	"encoding/json"
	"fmt"
	"time"
)

type Loan struct {
	Member string        `json:"member"`
	Due    time.Time     `json:"due"`
	Grace  time.Duration `json:"grace"`
}

func main() {
	// Time marshals as RFC 3339 with nanoseconds; Duration as a bare integer.
	est := time.FixedZone("EST", -5*3600)
	l := Loan{"ada", time.Date(2026, time.October, 18, 9, 0, 0, 0, est), 90 * time.Minute}
	b, _ := json.Marshal(l)
	fmt.Println(string(b))

	var back Loan
	fmt.Println(json.Unmarshal(b, &back), back.Due.Equal(l.Due), back.Due == l.Due)

	var bad Loan
	fmt.Println(json.Unmarshal([]byte(`{"due":"2026-10-18"}`), &bad))

	// == on Time compares the location pointer too, so it is a poor map key:
	utc := time.Date(2026, time.October, 18, 14, 0, 0, 0, time.UTC)
	seen := map[time.Time]string{utc: "UTC"}
	_, ok := seen[utc.In(est)]
	fmt.Println("same instant found via map key:", ok)
	byUnix := map[int64]string{utc.UnixNano(): "UTC"}
	_, ok = byUnix[utc.In(est).UnixNano()]
	fmt.Println("same instant found via UnixNano:", ok)

	// Truncate rounds down relative to the zero time (UTC), not to local midnight.
	ist := time.FixedZone("IST", 5*3600+30*60)
	t := time.Date(2026, time.October, 18, 10, 0, 0, 0, ist)
	fmt.Println(t.Truncate(24*time.Hour), "vs", time.Date(t.Year(), t.Month(), t.Day(), 0, 0, 0, 0, t.Location()))

	// Sub saturates at the Duration limits instead of wrapping.
	fmt.Println(time.Time{}.Sub(time.Date(3000, 1, 1, 0, 0, 0, 0, time.UTC)) == time.Duration(-1<<63))
}

== Sleeping, waiting and timers

`time.Sleep(d)` blocks the current goroutine for at least `d`; a non-positive `d` returns immediately. Sleeping is cheap
(the goroutine is parked, see xref:programming-languages/go/goroutines-and-the-scheduler.adoc[Goroutines and the
Scheduler]) but cannot be interrupted, so production code that must stop early waits on a channel or a context instead.

[cols="2,3,3",options="header"]
|===
| Type or function | Fires | Delivers

| `time.NewTimer(d)` / `+*Timer+`
| once, after `d`
| the time on `t.C`; `Stop` and `Reset` control it

| `time.After(d)`
| once, after `d`
| `NewTimer(d).C`: the channel only, no way to stop it

| `time.AfterFunc(d, f)`
| once, after `d`
| runs `f` in its own goroutine; `t.C` is nil; `Stop` cancels it

| `time.NewTicker(d)` / `+*Ticker+`
| every `d` until stopped; panics when `+d <= 0+`
| the time on `tk.C`; `Reset` changes the period; slow receivers lose ticks

| `time.Tick(d)`
| every `d`
| `NewTicker(d).C` only; returns nil when `+d <= 0+`
|===

A timer's channel carries the *time at which the timer fired*. The channel is never closed: a timer is not a signal that
a goroutine can range over, and `+<-t.C+` blocks forever on a stopped timer. The delivery is a single send of one value
(see the corrections at the end of this page).

[source,go]
----
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

// fetch stands in for a slow call; it returns when work is done.
func fetch(delay time.Duration) <-chan string {
	ch := make(chan string, 1) // buffered: the sender never blocks if nobody listens
	go func() {
		time.Sleep(delay)
		ch <- "catalogue page"
	}()
	return ch
}

func main() {
	// 1. time.After in a select: a one-shot timeout.
	select {
	case v := <-fetch(10 * time.Millisecond):
		fmt.Println("got", v)
	case <-time.After(time.Second):
		fmt.Println("timeout")
	}
	select {
	case v := <-fetch(time.Second):
		fmt.Println("got", v)
	case <-time.After(20 * time.Millisecond):
		fmt.Println("timeout")
	}

	// 2. Ticker: periodic work. Stop it when finished.
	tk := time.NewTicker(10 * time.Millisecond)
	defer tk.Stop()
	for i := 1; i <= 3; i++ {
		<-tk.C
		fmt.Println("tick", i)
	}
	tk.Reset(5 * time.Millisecond) // change the period (1.15)

	// 3. AfterFunc: run f in its own goroutine after d. No channel.
	done := make(chan struct{})
	hold := time.AfterFunc(20*time.Millisecond, func() {
		fmt.Println("hold expired")
		close(done)
	})
	<-done
	fmt.Println("Stop after run:", hold.Stop())

	// 4. A cancelled AfterFunc never runs.
	never := time.AfterFunc(time.Hour, func() { fmt.Println("never printed") })
	fmt.Println("Stop before run:", never.Stop())

	// 5. Prefer a context for deadlines that cross function boundaries.
	ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)
	defer cancel()
	select {
	case <-fetch(time.Second):
	case <-ctx.Done():
		fmt.Println(ctx.Err(), errors.Is(ctx.Err(), context.DeadlineExceeded))
	}
}
----

tick 1

hold expired

Stop before run: true

Reading the example:

* The first `select` uses `time.After` as a one-shot timeout. The `fetch` helper's channel is *buffered* (capacity 1) so
  the abandoned goroutine in the timeout case can finish its send and exit; with an unbuffered channel it would block
  forever and leak (see xref:programming-languages/go/concurrency-patterns.adoc[Concurrency Patterns]).
* `Ticker` sends on its channel at a fixed rate and *drops* ticks for a receiver that is slower than the period instead
  of queuing them. Always `Stop` a ticker when you are done with it in a long-running program: although the garbage
  collector can reclaim it since Go 1.23, stopping it releases the runtime timer immediately and states the intent.
* `AfterFunc` runs `f` on its own goroutine. `Stop` returns `false` once `f` has *started* (not once it has finished);
  it does not wait for `f`. If the caller needs to know that `f` is complete it must coordinate, for example with a
  channel as the example's `done`. A stopped `AfterFunc` never runs.
* For a deadline that crosses function boundaries, `context.WithTimeout` is better than a hand-passed timer: it
  composes with parent cancellation and shows up in `ctx.Err()`. The last `select` uses it. See
  xref:programming-languages/go/context.adoc[Context].

Source: https://pkg.go.dev/time#AfterFunc[time.AfterFunc]

=== The timer changes of Go 1.23

Before Go 1.23 timers had two sharp edges that generated years of bug reports.

. *Timers were not garbage collected until they fired.* A `time.After(time.Hour)` in a loop leaked an hour-long timer
  per iteration, and every `time.NewTimer` was followed by a `defer t.Stop()` to avoid it, while `time.Tick` was documented
  as leaking its ticker forever.
. *The timer channel was buffered (capacity 1).* A timer that fired while the program was busy left a value in the
  channel, and a later `Stop` or `Reset` could not remove it. The code that followed the rules read like this:
  `+if !t.Stop() { <-t.C }+` before every `Reset`, which itself deadlocks when the channel was already drained.

Go 1.23 changed both, and the release notes state the effect: timers and tickers that are no longer referenced become
eligible for garbage collection immediately, and the channel is now *synchronous* (capacity 0), so the runtime
guarantees that after `Stop` or `Reset` returns no stale value will be received. The program below checks each guarantee
on Go 1.27.

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func main() {
	// Go 1.23+: the channel of a Timer or Ticker is synchronous.
	t := time.NewTimer(10 * time.Millisecond)
	fmt.Println("len, cap:", len(t.C), cap(t.C))

	// Let the timer expire without receiving from it.
	time.Sleep(50 * time.Millisecond)
	fmt.Println("len after expiry:", len(t.C))

	// Stop reports true: no value was delivered, and none will be.
	fmt.Println("Stop:", t.Stop())
	select {
	case v := <-t.C:
		fmt.Println("stale value:", v.IsZero())
	default:
		fmt.Println("no stale value after Stop")
	}

	// Reset after expiry is just as safe: no draining loop is needed.
	t.Reset(20 * time.Millisecond)
	start := time.Now()
	<-t.C
	fmt.Println("fired after Reset:", time.Since(start) >= 20*time.Millisecond)

	// After the value was received, Stop returns false.
	fmt.Println("Stop after receive:", t.Stop())

	// An unreferenced, unexpired timer is garbage collected; no defer t.Stop().
	for range 3 {
		_ = time.NewTimer(time.Hour)
	}
	fmt.Println("done")
}
----

How to read this:

* `len(t.C)` and `cap(t.C)` are both 0 (they were 0 and 1 before the change), and an expired timer that nobody received
  from does not "contain" a value. A timer's value is produced at the moment of the receive.
* `Stop` returns `true` here even though the 10 ms deadline had long passed, because the value had never been received:
  from the program's point of view the timer had not yet delivered. `Stop` returns `false` only when the value was already
  received (the second-to-last line) or the timer was already stopped. After `Stop` returns, a receive from `t.C` blocks
  rather than yielding a stale value.
* `Reset` after expiry is safe without draining: any receive after `Reset` returns sees the new deadline's time.
* The draining idiom still compiles, but it is dead weight: `+if !t.Stop() { <-t.C }+` can now *block forever* when
  `Stop` returns false because the value was already received. Delete it. The same holds for the `defer t.Stop()`
  added only to help the collector; keep it when the stop has a real purpose such as releasing an `AfterFunc`.
* The behaviour was gated by the `go` line in `go.mod`: modules declaring `go 1.23` or newer got the new channels in Go
  1.23 to 1.26, and older modules could opt in or out with the `asynctimerchan` GODEBUG setting.

would be removed in Go 1.27, and it was. The Go 1.27 release notes say that channels created by the `time` package are
now always unbuffered, irrespective of GODEBUG settings, and the toolchain's `godebug.md` lists the setting among the
removed ones. A module that still carries the old setting does not build with a clear message:

=== Patterns: one timer for many waits, and an idle timeout

A loop that waits for events *or* a timeout should reuse one `Timer` with `Reset` rather than calling `time.After` per
iteration; each `time.After` call allocates a new timer, which the collector now reclaims but which still costs an
allocation on a hot path.

[source,go]
----
package main

import (
	"fmt"
	"time"
)

// drain forwards events until none arrives for idle, resetting one Timer
// instead of allocating a time.After per iteration.
func drain(events <-chan string, idle time.Duration) {
	timer := time.NewTimer(idle)
	defer timer.Stop()
	for {
		select {
		case e, ok := <-events:
			if !ok {
				fmt.Println("channel closed")
				return
			}
			fmt.Println("event:", e)
			// Since Go 1.23 no <-timer.C drain is required before Reset.
			timer.Reset(idle)
		case <-timer.C:
			fmt.Println("idle for", idle)
			return
		}
	}
}

func main() {
	events := make(chan string)
	go func() {
		for _, e := range []string{"lend", "return", "renew"} {
			events <- e
			time.Sleep(5 * time.Millisecond)
		}
	}()
	drain(events, 50*time.Millisecond)

	defer func() { fmt.Println("recovered:", recover()) }()
	_ = time.NewTicker(0)
}
----

Other rules for waiting:

* Never use `time.Sleep` to wait for another goroutine in a test or in production; wait on a channel, a `WaitGroup` or a
  `context`.
* Backoff with jitter for retries is `time.Duration` arithmetic plus `math/rand/v2` (`rand.N(maxJitter)`) and a `select`
  between `ctx.Done()` and a timer; xref:programming-languages/go/concurrency-patterns.adoc[Concurrency Patterns] shows
  the loop.
* A wait is "at least" `d`, never "exactly" `d`: the timer resolution depends on the operating system and the scheduler.
* HTTP and database timeouts belong in `http.Server`, `http.Client` and request contexts, not in goroutine-and-timer
  constructions; see xref:programming-languages/go/net-http-clients-and-servers.adoc[net/http Clients and Servers].

== Measuring elapsed time

Start with `start := time.Now()` and end with `time.Since(start)`: both use the monotonic reading, so the result is a
correct duration even if the wall clock changed in between. `time.Until(t)` is `t.Sub(time.Now())`. When the measurement
is deferred, the arguments of a deferred call are evaluated when the `defer` statement executes, which is a classic
slip:

[source,go]
----
package main

import (
	"fmt"
	"time"
)

func report(label string, d time.Duration) {
	fmt.Println(label, d < time.Millisecond)
}

func work() {
	start := time.Now()
	// Wrong: time.Since(start) is evaluated now, when defer runs the statement.
	defer report("evaluated early, under 1ms:", time.Since(start))
	// Right: the closure reads the clock when the function returns.
	defer func() { report("evaluated late, under 1ms:", time.Since(start)) }()
	time.Sleep(30 * time.Millisecond)
}

func main() { work() }
----

`go vet` reports it with its `defers` analyzer:

[source,text]
----
./main.go:15:46: call to time.Since is not deferred
----

[source,text]
----
evaluated late, under 1ms: false
evaluated early, under 1ms: true
----

The first line printed is the correct one (the closure runs when the function returns, about 30 ms later, so the
comparison `d < 1ms` is false), and the second is the early one, evaluated at the moment of the `defer` and therefore
nearly zero. The deferred function value (a closure) is the fix. For benchmarks do not hand-roll this at all: use
`testing.B` and `b.Loop`, see xref:programming-languages/go/benchmarks-fuzzing-and-synctest.adoc[Benchmarks, Fuzzing and
synctest].

== Testing code that depends on time

Tests that sleep for real are slow, and tests that sleep for a guess are flaky. There are three tools, from simplest to
most powerful.

. *Pass the time in.* A function that needs "now" takes a `time.Time` argument, or the type holds a `func() time.Time`
  field defaulting to `time.Now`. `Loan.IsOverdue(now time.Time)` in the next listing needs no fake clock at all, and a
  test passes `due` and `due.Add(time.Nanosecond)`. This is the right design for pure decisions.
. *Inject the waiting* when production code must block (an interface with `+After(d) <-chan time.Time+`, or a function
  field). It works on every Go version, at the price of an abstraction that production code never changes.
. *Use `testing/synctest`* when the production code uses the real `time` package. Inside a bubble, `time.Now`, `Sleep`,
  timers and tickers run on a fake clock that starts at midnight UTC on 2000-01-01 and jumps forward only when every
  goroutine in the bubble is durably blocked, so a three-hour wait takes microseconds and is deterministic.
  `synctest.Test` was experimental in Go 1.24 (`GOEXPERIMENT=synctest`), generally available in Go 1.25, and gained
  `synctest.Sleep` (sleep and wait until all goroutines settle) in Go 1.27. The rules of a bubble, failure modes, the
  fake network and the details are on xref:programming-languages/go/benchmarks-fuzzing-and-synctest.adoc[Benchmarks,
  Fuzzing and synctest]; this page shows one more example, with a ticker.

The code under test sends a reminder every interval once a loan is overdue. `overdue.go`:

[source,go]
----
package overdue

import (
	"context"
	"time"
)

// Loan is a book lent until Due.
type Loan struct {
	Member string
	Due    time.Time
}

// IsOverdue reports whether l is past due at now. The caller supplies the
// clock reading, so tests need no fake clock at all.
func (l Loan) IsOverdue(now time.Time) bool { return now.After(l.Due) }

// Remind sends the member's name on out every interval once l is overdue,
// until ctx is done.
func Remind(ctx context.Context, l Loan, interval time.Duration, out chan<- string) {
	tk := time.NewTicker(interval)
	defer tk.Stop()
	for {
		select {
		case <-ctx.Done():
			return
		case now := <-tk.C:
			if l.IsOverdue(now) {
				out <- l.Member
			}
		}
	}
}
----

Source: https://pkg.go.dev/time#NewTicker[time.NewTicker] and https://pkg.go.dev/time#Time.After[time.Time.After]

and `overdue_test.go`, which is a `_test.go` file because `testing/synctest` is only meant for tests and runs with
`go test`:

[source,go]
----
package overdue

import (
	"context"
	"testing"
	"testing/synctest"
	"time"
)

func TestIsOverdue(t *testing.T) {
	due := time.Date(2026, time.October, 18, 0, 0, 0, 0, time.UTC)
	l := Loan{Member: "ada", Due: due}
	if l.IsOverdue(due) {
		t.Error("overdue exactly at the due time")
	}
	if !l.IsOverdue(due.Add(time.Nanosecond)) {
		t.Error("not overdue one nanosecond later")
	}
}

func TestRemind(t *testing.T) {
	synctest.Test(t, func(t *testing.T) {
		start := time.Now() // always midnight UTC 2000-01-01 in a bubble
		t.Logf("bubble starts at %s", start.UTC().Format(time.DateTime))

		l := Loan{Member: "ada", Due: start.Add(2 * time.Hour)}
		out := make(chan string)
		ctx, cancel := context.WithCancel(t.Context())
		go Remind(ctx, l, time.Hour, out)

		// Nothing is sent before the loan is due: let the goroutine reach
		// its select and the clock reach the first tick, one hour in.
		synctest.Sleep(time.Hour)
		select {
		case m := <-out:
			t.Fatalf("early reminder for %s at %s", m, time.Since(start))
		default:
		}

		// The tick at 2h is not yet past the due time; the one at 3h is.
		synctest.Sleep(time.Hour)
		<-out
		t.Logf("first reminder after %s", time.Since(start))

		cancel()
		synctest.Wait() // Remind has returned; no goroutine leaks from the bubble
	})
}

The test would take three real hours. Points worth noting:

* `time.Now()` in the bubble is `2000-01-01 00:00:00 UTC` regardless of the machine; print it with `.UTC()`, because
  `Now` returns the `Local` zone (the first attempt at this example printed 01:00 on a machine in Central European
  time).
* `synctest.Sleep(time.Hour)` advances the clock one hour and returns when the other goroutines have reacted. The ticker
  fires at 1 h (not overdue: no message), at 2 h (equal to the due time, `After` is false: no message) and at 3 h
  (message). The assertion that no message arrived uses `select` with `default`, which is safe because the goroutines
  are quiescent.
* `+<-out+` blocks durably, so the bubble's clock jumps to the next tick instead of waiting.
* The goroutine is stopped by cancelling a context derived from `t.Context()`, and `synctest.Wait()` confirms it
  returned. A goroutine that is still blocked when the test function returns makes `Test` panic or fail, which is a feature:
  it finds leaks.
* Operations that wait on the outside world (network reads, mutex locks, system calls) are not durably blocking, so a
  bubble containing them cannot fast-forward; test the time logic separately from the I/O.

== Pitfalls

[cols="2,3,3",options="header"]
|===
| Pitfall | Symptom | Fix

| `+n * time.Second+` with an `int` `n`
| compile error: mismatched types
| `+time.Duration(n) * time.Second+`

| `+1.5 * time.Second+`
| compile error: truncated to int64
| `+1500 * time.Millisecond+`

| `t1 == t2` for instants
| false for the same instant in two zones or after `Round(0)`
| `t1.Equal(t2)`, or `Compare`

| `time.Time` as a map key
| duplicate keys for the same instant
| key by `UnixNano()` or a normalised `UTC().Round(0)`

| Layout built from today's date (`2016-01-02`, `YYYY-MM-DD`)
| garbled output
| use the reference time or a constant such as `time.DateOnly`

| `time.Parse` of a local time without a zone
| the value is read as UTC
| `time.ParseInLocation`

| `+Add(24 * time.Hour)+` for "tomorrow"
| off by an hour near daylight saving changes
| `AddDate(0, 0, 1)`

| `+Truncate(24 * time.Hour)+` for "start of day"
| midnight UTC, not local
| `time.Date(y, m, d, 0, 0, 0, 0, loc)`

| `defer log(time.Since(start))`
| duration near zero; `go vet` reports it
| `+defer func() { log(time.Since(start)) }()+`

| `LoadLocation` in a minimal container
| `unknown time zone`
| import `time/tzdata` in `main`

| `time.Sleep` to wait for a goroutine
| flaky or slow
| channel, `WaitGroup`, `context`

| `+<-t.C+` after `Stop`
| blocks forever
| select with a done channel; do not drain

| Using `time.Now()` deep inside business logic
| tests need real waiting
| pass the time in, or use `synctest`

| `Round(0)` forgotten before storing or hashing a `Now()` value
| the monotonic reading makes `==` and `String()` differ from a reloaded copy
| `t.Round(0)`, or store `UnixNano`
|===

== Where the books are outdated

The two books this reference consulted for structure predate the changes below; the corrected form is what this page
teaches.

* *Timer channels and `Stop`/`Reset`.* Learning Go Programming (Vivien, ch. 9) describes `time.After` as a channel that
  gets closed; the channel receives one value and is never closed. Anything written before Go 1.23 about draining
  `t.C` before `Reset`, calling `defer t.Stop()` to avoid a leak, or `time.Tick` leaking its ticker, is obsolete: since Go
  1.23 timers are collected when unreferenced and the channel is synchronous, and since Go 1.27 the old behaviour cannot
  be restored with `asynctimerchan`.
* *Layout constants.* Learning Go (Bodner, ch. 11) shows layouts spelled out by hand; Go 1.20 added `DateTime`,
  `DateOnly` and `TimeOnly`, and `Time.Compare`.
* *Time and testing.* Both books test time-dependent code with real sleeps or hand-written fakes; `testing/synctest` is
  generally available since 1.25, with `synctest.Sleep` in 1.27.
* *`Duration.Abs`* (1.19), *`Time.ZoneBounds`* (1.19), *`Time.IsDST`* (1.17) and *`time.UnixMilli`* (1.17) are newer
  than both books' time sections.
* *Modern companions.* Where older tutorials call `rand.Seed` or `ioutil` helpers next to `time`, use `math/rand/v2`
  (`rand.N(d)` accepts a `Duration`) and `os`/`io`; see xref:programming-languages/go/whats-new-and-migrating-older-code.adoc[What's New and Migrating Older Code].

== Version notes

* Go 1.9: monotonic clock readings in `Time` (`Now` carries one); `Duration.Round` and `Truncate`.
* Go 1.15: `Ticker.Reset`.
* Go 1.17: `Time.IsDST`, `UnixMilli`, `Time.UnixMilli`.
* Go 1.19: `Duration.Abs`, `Time.ZoneBounds`.
* Go 1.20: `time.DateTime`, `DateOnly`, `TimeOnly`; `Time.Compare`.
* Go 1.23: timers and tickers are garbage collected when unreferenced; the timer channel is synchronous; `asynctimerchan`
  added as the opt-out.
* Go 1.24: `T.Context`; `testing/synctest` experimental (`GOEXPERIMENT=synctest`).
* Go 1.25: `testing/synctest` generally available with `synctest.Test`.
* Go 1.27: `asynctimerchan` removed; `synctest.Sleep`; `httptest.NewTestServer` on an in-memory network for use in a
  bubble.
