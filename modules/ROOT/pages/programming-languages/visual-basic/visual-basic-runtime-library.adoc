This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is a complete console program that
starts with `Option Strict On`, was built with warnings treated as errors (unless the text says otherwise) and was run in the .NET 10 SDK container (Linux, arm64); the output shown is
real output. Several programs have a `Sub Main` selected with the `StartupObject` property in one project whose root namespace is `ShelfRt`. The SDK imports `System`, `System.Collections.Generic`,
`System.IO`, `System.Linq` and others project-wide, and the compiler always imports `Microsoft.VisualBasic`, which is why `Left`, `Len`, `Now`, `Choose` and `vbCrLf` need no `Imports` line.

The Visual Basic *runtime library* is the assembly of helper functions, constants and types that ships with the language. It is the part of Visual Basic that old programs call most (`Mid`, `InStr`, `Format`, `CInt`, `MsgBox`,
`FileOpen`, `Err`) and that new code should call with care: some of it is a thin layer over the BCL, some is a Visual Basic 6 compatibility layer whose behaviour differs from the BCL in one-based indexes, culture
and null handling, some is Windows-only, and a little is obsolete. This page maps the library, measures what the .NET assembly really contains, and gives each area a tested example. Topics that have their own page are summarised and linked:
strings on xref:programming-languages/visual-basic/strings-and-text.adoc[Strings and Text], conversions on xref:programming-languages/visual-basic/type-conversions.adoc[Type Conversions],
dates on xref:programming-languages/visual-basic/dates-times-and-formatting.adoc[Dates, Times and Formatting], numbers and the financial functions on
xref:programming-languages/visual-basic/numbers-and-math.adoc[Numbers and Math], and `My` on xref:programming-languages/visual-basic/the-my-namespace.adoc[The My Namespace].

== What the library is on .NET

On .NET Framework the whole library was `Microsoft.VisualBasic.dll`. On .NET it is split in two assemblies of the shared framework: `Microsoft.VisualBasic.Core`, which holds the runtime that every Visual Basic program references, and a small
`Microsoft.VisualBasic` assembly next to it for code that refers to the old assembly name. The Windows Forms parts (`My.Computer`, the Application Framework, the dialogs behind `MsgBox` and `InputBox`) are in a third assembly,
`Microsoft.VisualBasic.Forms`, that ships with the Windows Desktop runtime (see xref:programming-languages/visual-basic/the-my-namespace.adoc[The My Namespace]).
The program below asks `Microsoft.VisualBasic.Core` what it exports, grouping the public types of each namespace by kind. A Visual Basic `Module` compiles to a sealed class marked with `StandardModuleAttribute`, so the program uses that attribute to recognise modules:

[source,vbnet]
----
Option Strict On

Imports System.Reflection
Imports Microsoft.VisualBasic.CompilerServices

Module Program
    Private Function Kind(t As Type) As String
        If t.IsEnum Then Return "Enum"
        If t.IsInterface Then Return "Interface"
        If t.IsSubclassOf(GetType(MulticastDelegate)) Then Return "Delegate"
        If t.IsSubclassOf(GetType(Attribute)) Then Return "Attribute"
        If t.IsDefined(GetType(StandardModuleAttribute), False) Then Return "Module"
        If t.IsValueType Then Return "Structure"
        Return "Class"
    End Function

    Sub Main()
        Dim asm As Assembly = GetType(Microsoft.VisualBasic.Strings).Assembly
        For Each ns As String In {"Microsoft.VisualBasic", "Microsoft.VisualBasic.CompilerServices", "Microsoft.VisualBasic.FileIO"}
            Console.WriteLine("== " & ns)
            Dim groups As New SortedDictionary(Of String, List(Of String))()
            For Each t As Type In asm.GetExportedTypes()
                If t.Namespace = ns Then
                    Dim k As String = Kind(t)
                    If Not groups.ContainsKey(k) Then groups(k) = New List(Of String)()
                    groups(k).Add(t.Name)
                End If
            Next
            For Each kv In groups
                kv.Value.Sort()
                Console.WriteLine(kv.Key & ": " & String.Join(", ", kv.Value))
            Next
        Next
    End Sub
End Module
----

== What is hidden, obsolete or Windows-only

The assembly records its own warnings as attributes, and the compiler and analyzers act on them, so reflection can list them. The program below goes through every public static member of the nine modules and counts those hidden from IntelliSense,
marked obsolete, annotated as supported only on Windows (`SupportedOSPlatform`) or unsupported on some platforms, or marked as unsafe for trimming (`RequiresUnreferencedCode`). It then prints each obsolete member with its message, and each platform annotation.
(In Visual Basic a variable declared in a loop body keeps its value between iterations, so the counters are re-initialised at the top of the loop body.)

[source,vbnet]
----
Option Strict On

Imports System.ComponentModel
Imports System.Reflection
Imports System.Runtime.Versioning
Imports Microsoft.VisualBasic.CompilerServices

Module Program
    Sub Main()
        Dim asm As Assembly = GetType(Microsoft.VisualBasic.Strings).Assembly
        Dim flags As BindingFlags = BindingFlags.Public Or BindingFlags.Static Or BindingFlags.DeclaredOnly
        Console.WriteLine("module            members  hidden  obsolete  unsupported-os  supported-os  needs-unreferenced-code")
        For Each t As Type In asm.GetExportedTypes().OrderBy(Function(x) x.Name)
            If t.Namespace = "Microsoft.VisualBasic" AndAlso t.IsDefined(GetType(StandardModuleAttribute), False) Then
                Dim total As Integer = 0, hidden As Integer = 0, obs As Integer = 0
                Dim unsup As Integer = 0, sup As Integer = 0, ruc As Integer = 0
                For Each m As MemberInfo In t.GetMembers(flags)
                    If TypeOf m Is MethodInfo AndAlso DirectCast(m, MethodInfo).IsSpecialName Then Continue For
                    total += 1
                    Dim eb = m.GetCustomAttribute(Of EditorBrowsableAttribute)()
                    If eb IsNot Nothing AndAlso eb.State = EditorBrowsableState.Never Then hidden += 1
                    If m.IsDefined(GetType(ObsoleteAttribute), False) Then obs += 1
                    If m.IsDefined(GetType(UnsupportedOSPlatformAttribute), False) Then unsup += 1
                    If m.IsDefined(GetType(SupportedOSPlatformAttribute), False) Then sup += 1
                    If m.IsDefined(GetType(System.Diagnostics.CodeAnalysis.RequiresUnreferencedCodeAttribute), False) Then ruc += 1
                Next
                Console.WriteLine(t.Name.PadRight(18) & total.ToString().PadLeft(5) & hidden.ToString().PadLeft(8) & obs.ToString().PadLeft(9) & unsup.ToString().PadLeft(13) & sup.ToString().PadLeft(14) & ruc.ToString().PadLeft(14))
            End If
        Next
        Console.WriteLine("--- obsolete members")
        For Each t As Type In asm.GetExportedTypes().OrderBy(Function(x) x.Name)
            For Each m As MemberInfo In t.GetMembers(BindingFlags.Public Or BindingFlags.Static Or BindingFlags.Instance Or BindingFlags.DeclaredOnly)
                Dim o = m.GetCustomAttribute(Of ObsoleteAttribute)()
                If o IsNot Nothing Then
                    Dim msg As String = If(o.Message, "")
                    Console.WriteLine(t.Name & "." & m.Name & " : " & msg)
                End If
            Next
            Dim ot = t.GetCustomAttribute(Of ObsoleteAttribute)()
            If ot IsNot Nothing Then Console.WriteLine("TYPE " & t.Name & " : " & ot.Message)
        Next
        Console.WriteLine("--- platform attributes")
        For Each t As Type In asm.GetExportedTypes().OrderBy(Function(x) x.Name)
            For Each m As MemberInfo In t.GetMembers(BindingFlags.Public Or BindingFlags.Static Or BindingFlags.Instance Or BindingFlags.DeclaredOnly)
                For Each a In m.GetCustomAttributes(False)
                    If TypeOf a Is OSPlatformAttribute Then
                        Console.WriteLine(t.Name & "." & m.Name & " : " & a.GetType().Name & " " & DirectCast(a, OSPlatformAttribute).PlatformName)
                    End If
                Next
            Next
        Next
    End Sub
End Module

What this means in practice:

* *Obsolete.* Only two public members of the nine modules are obsolete: the constant `vbNewLine` and the `FilePut` overload that takes an `Object`. The `+Fallback...+` members of `NewLateBinding` and `Operators` are compiler plumbing that must not be called.
  Both obsolete members are shown in "Constants" below.
* *Windows-only.* `Beep`, the registry settings functions (`GetSetting`, `SaveSetting`, `DeleteSetting`, `GetAllSettings`), `CreateObject`/`GetObject` (COM), `StrConv`, `Dir`, `Rename`, `CurDir`, `ChDrive` and the setters of `Today`, `TimeOfDay`, `DateString` and `TimeString` carry
  `SupportedOSPlatform("windows")`. A call from code that can run elsewhere makes the analyzer rule CA1416 report them, and with `TreatWarningsAsErrors` the build fails (see the example in "Constants" below). `Lock`, `Unlock` and `InputString` are unsupported on iOS, macOS and tvOS.
  An annotation is a warning that the call may not work, not proof that it does not: `Dir` worked in the file example below on Linux, while `Rename` threw and `Shell`, `MsgBox` and `InputBox` have no annotation but threw too.
* *Not trim-safe.* `Conversion.CTypeDynamic` (two overloads), `Interaction.CallByName`, `CreateObject`, `GetObject`, `FileGet`, `FilePut`, `FileGetObject`, `FilePutObject`, `Input` and the `Len` overload for `Object` are marked `RequiresUnreferencedCode`, because they use reflection; avoid them in programs that are trimmed or compiled ahead of time
  (see xref:programming-languages/visual-basic/early-and-late-binding.adoc[Early and Late Binding]).
* *Hidden.* None of the module members is hidden from IntelliSense, but all 29 types of `Microsoft.VisualBasic.CompilerServices` are (see below).

== Strings

The `Strings` module is the VB6 string library: functions with *one-based* positions, tolerant of `Nothing`, with an optional `Compare` argument that follows `Option Compare`. The BCL equivalents are zero-based and throw on `Nothing`.
Both can be right; the point is to know which one a piece of code uses. The details of every function are on xref:programming-languages/visual-basic/strings-and-text.adoc[Strings and Text]; this program shows the differences that cause bugs:

[source,vbnet]
----
Option Strict On

Imports System.Globalization

Module StringsTour
    Private Sub Try1(label As String, action As Func(Of String))
        Try
            Console.WriteLine(label & " = " & action())
        Catch ex As Exception
            Console.WriteLine(label & " -> " & ex.GetType().Name & ": " & ex.Message)
        End Try
    End Sub

    Sub Main()
        Dim title As String = "The Left Hand of Darkness"
        Dim missing As String = Nothing

        Console.WriteLine("-- one-based positions")
        Console.WriteLine("InStr(title, ""Left"")        = " & InStr(title, "Left").ToString())
        Console.WriteLine("title.IndexOf(""Left"")       = " & title.IndexOf("Left").ToString())
        Console.WriteLine("Mid(title, 5, 4)            = " & Mid(title, 5, 4))
        Console.WriteLine("title.Substring(4, 4)       = " & title.Substring(4, 4))
        Console.WriteLine("Left / Right                = " & Left(title, 3) & " / " & Right(title, 8))
        Console.WriteLine("InStr(6, title, ""e"")        = " & InStr(6, title, "e").ToString())
        Console.WriteLine("InStrRev(title, ""e"")        = " & InStrRev(title, "e").ToString())

        Console.WriteLine("-- Nothing is tolerated")
        Console.WriteLine("Len(Nothing)                = " & Len(missing).ToString())
        Console.WriteLine("UCase(Nothing) is empty     = " & (UCase(missing).Length = 0).ToString())
        Console.WriteLine("Left(Nothing, 3) is empty   = " & (Left(missing, 3).Length = 0).ToString())
        Try1("missing.Length", Function() missing.Length.ToString())

        Console.WriteLine("-- but bad arguments still throw")
        Try1("Mid(title, 0)", Function() Mid(title, 0))
        Try1("Left(title, -1)", Function() Left(title, -1))
        Try1("title.Substring(40)", Function() title.Substring(40))
        Console.WriteLine("Left(title, 100) = " & Left(title, 100))
        Console.WriteLine("Mid(title, 100)  = '" & Mid(title, 100) & "'")

        Console.WriteLine("-- whitespace and padding")
        Console.WriteLine("[" & Trim("  a b  ") & "] [" & LTrim("  a") & "] [" & RTrim("a  ") & "]")
        Console.WriteLine("Trim leaves tabs: " & (Trim(vbTab & "a" & vbTab).Length).ToString() & " vs String.Trim: " & (vbTab & "a" & vbTab).Trim().Length.ToString())
        Console.WriteLine("[" & Space(3) & "] [" & StrDup(3, "ab") & "] [" & StrReverse("Dune") & "]")
        Console.WriteLine("[" & LSet("ab", 5) & "] [" & RSet("ab", 5) & "]")

        Console.WriteLine("-- characters and codes")
        Console.WriteLine("Asc(""A"") = " & Asc("A").ToString() & ", Chr(66) = " & Chr(66) & ", AscW(""é"") = " & AscW("é").ToString() & ", ChrW(&H263A) = " & ChrW(&H263A))

        Console.WriteLine("-- Replace, Split, Join, Filter")
        Console.WriteLine(Replace(title, "the", "A", 1, 1, CompareMethod.Text))
        Console.WriteLine(Replace("a-b-c-d", "-", "+", 3))
        Dim parts As String() = Split("Dune;Emma;;Ulysses", ";")
        Console.WriteLine(parts.Length.ToString() & " parts, Join = " & Join(parts, "|"))
        Console.WriteLine("Filter: " & Join(Filter(parts, "e", True, CompareMethod.Text), ","))

        Console.WriteLine("-- formatting helpers (en-US)")
        CultureInfo.CurrentCulture = New CultureInfo("en-US")
        Console.WriteLine(FormatNumber(1234567.891, 2) & " | " & FormatCurrency(19.5) & " | " & FormatPercent(0.256, 1) & " | " & Format(1234.5, "#,##0.00"))
        Console.WriteLine(FormatNumber(-3.5, 1, TriState.UseDefault, TriState.True) & " | " & FormatNumber(0.5, 2, TriState.False))
    End Sub
End Module

Points the output makes concrete:

* `InStr` returns 5 where `IndexOf` returns 4, and `InStr` returns 0 for "not found" where `IndexOf` returns -1. `Mid(title, 5, 4)` and `Substring(4, 4)` are the same slice.
* `Len`, `UCase`, `Left` and the other functions treat `Nothing` as the empty string; the member call `missing.Length` throws `NullReferenceException`.
* The functions still validate their arguments: a start of 0 or a negative length throws `ArgumentException` with the VB-style message "Argument 'Start' must be greater than zero.". But a length that is too long is clipped (`Left(title, 100)`), and a start beyond the end gives an empty string, where `Substring` throws.
* `Trim`, `LTrim` and `RTrim` remove *spaces only*: the string with tabs around `a` keeps length 3, where `String.Trim()` gives 1.
* `Replace(expression, find, replacement, start, count, compare)` with a `start` greater than 1 returns only the text *from* `start`: `Replace("a-b-c-d", "-", "+", 3)` printed `b+c+d`, and the first characters are gone. This is the most surprising function in the module.
* `Format`, `FormatNumber`, `FormatCurrency` and `FormatPercent` use the current culture, which is why the program sets `en-US` first (in the invariant culture the currency symbol is a generic sign). The `TriState` arguments choose the leading zero, the parentheses for negative numbers and the grouping.
* `StrConv` with `VbStrConv.ProperCase` and the Japanese and Chinese conversions is annotated as Windows-only; `TextInfo.ToTitleCase` is the cross-platform way.
* The module has `Space`, `StrDup`, `StrReverse` and `LSet`/`RSet` (fixed-width padding), which have no one-word BCL equivalent. `StrReverse` reverses UTF-16 code units, so it breaks surrogate pairs and combining marks.

== Conversion

The `Conversion` module has the number-to-text and number-to-integer helpers of VB6. They interact with the conversion keywords (`CInt`, `CStr`, `CDate`, which are compiler features, not functions of this module) described on
xref:programming-languages/visual-basic/type-conversions.adoc[Type Conversions].

[source,vbnet]
----
Option Strict On

Module ConversionTour
    Sub Main()
        Console.WriteLine("-- Val reads the leading number only, always with the invariant format")
        Console.WriteLine(Val("1234abc").ToString() & " " & Val("  3.5e2xyz").ToString() & " " & Val("&H1F").ToString() & " " & Val("&O17").ToString() & " " & Val("abc").ToString() & " " & Val("1,5").ToString())
        Console.WriteLine("-- Str keeps a sign column")
        Console.WriteLine("[" & Str(42) & "] [" & Str(-42) & "] [" & CStr(42) & "]")
        Console.WriteLine("-- Hex and Oct")
        Console.WriteLine(Hex(255) & " " & Hex(-1) & " " & Oct(8) & " " & Hex(CByte(10)))
        Console.WriteLine("-- Fix and Int")
        Console.WriteLine(Fix(-2.7).ToString() & " " & Int(-2.7).ToString() & " " & Fix(2.7).ToString() & " " & Int(2.7).ToString())
        Console.WriteLine("-- CInt rounds to even; CType from Object")
        Console.WriteLine(CInt(2.5).ToString() & " " & CInt(3.5).ToString() & " " & CInt(CObj("12")).ToString())
        Console.WriteLine("-- CTypeDynamic converts at run time")
        Console.WriteLine(CTypeDynamic(Of Integer)("77").ToString() & " " & CTypeDynamic(Of Date)("2026-10-19").ToString("yyyy-MM-dd"))
        Console.WriteLine("-- ErrorToString")
        Console.WriteLine(ErrorToString(5))
        Console.WriteLine(ErrorToString(11))
        Console.WriteLine(ErrorToString(0).Length.ToString())
    End Sub
End Module

* `Val` reads the leading characters that look like a number, never throws, always uses the period as the decimal separator, and understands `&H` and `&O` prefixes. `Val("1,5")` is 1, not 1.5, and `Val("abc")` is 0 with no way to tell "not a number" from zero. Use `Double.TryParse` with a culture when you must distinguish the cases.
* `Str` reserves a column for the sign, so positive numbers get a *leading space*; `CStr` does not. Code that compares `Str(42)` with "42" fails.
* `Hex(-1)` is `FFFFFFFF` because `-1` is an `Integer`; the result depends on the argument's type. `Fix` truncates toward zero and `Int` rounds down. `CInt(2.5)` is 2 and `CInt(3.5)` is 4: banker's rounding.
* `ErrorToString(n)` gives the VB6 message for an error number; 0 gives an empty string.
* `CTypeDynamic` converts at run time by the type's `IConvertible` or conversion operators and is marked as not trim-safe.

* `DateDiff` counts *boundaries crossed*, not elapsed time: from 31 December to 1 January it reports 1 day, 1 year and 1 month. For elapsed time subtract the dates and use the `TimeSpan`.

* `IsNumeric` is much more permissive than `Double.TryParse`: it accepts currency symbols, parentheses for negatives, the `&H` and `&O` prefixes and surrounding spaces. It is `True` for `"&HFF"`, which `Double.Parse` rejects, and it says nothing about whether the value fits in the target type.

== The legacy file I/O in FileSystem

The `FileSystem` module of `Microsoft.VisualBasic` (not the `FileIO.FileSystem` class) is the VB6 file model: you open a file on a *file number*, then `Print`, `Write`, `Input`, `LineInput`, `FileGet` and `FilePut` on that number. It is not obsolete and it works on .NET,
but `System.IO` is the model for new code (see xref:programming-languages/visual-basic/files-directories-and-streams.adoc[Files, Directories and Streams]). The program exercises all four modes and the file-system helpers; the first line turns CA1416 off because `Dir` and `Rename` are annotated as Windows-only:

[source,vbnet]
----
Option Strict On

    Sub Main()
        Dim folder As String = Path.Combine(Path.GetTempPath(), "shelf-legacy-io")
        If Directory.Exists(folder) Then Directory.Delete(folder, True)
        MkDir(folder)
        Dim textFile As String = Path.Combine(folder, "books.txt")

        Console.WriteLine("-- report output: Print, PrintLine, TAB and SPC")
        Dim n As Integer = FreeFile()
        FileOpen(n, textFile, OpenMode.Output)
        PrintLine(n, "Title", TAB(12), "Year")
        PrintLine(n, "Dune", TAB(12), 1965)
        Print(n, "no line end, ")
        PrintLine(n, "then one", SPC(3), "x")
        PrintLine(n, "a", "b", True)
        FileClose(n)
        Console.Write(File.ReadAllText(textFile))

        Console.WriteLine("-- data output and input: WriteLine, Input, EOF")
        Dim dataFile As String = Path.Combine(folder, "books.csv")
        n = FreeFile()
        FileOpen(n, dataFile, OpenMode.Output)
        WriteLine(n, "Dune", 1965, True)
        WriteLine(n, "Emma", 1815, False)
        FileClose(n)

            Dim title As String = Nothing, year As Integer, inPrint As Boolean

* `Print`/`PrintLine` are for reports: items are separated into 14-character print zones (the `a  b  True` line), `TAB(n)` moves to a column, `SPC(n)` inserts spaces. `Write`/`WriteLine` write *data*: strings in quotes, booleans as `+#TRUE#+`, items separated by commas, which `Input` reads back.
* `Input` recognises `CR` and `CRLF` as the end of a line, *not a lone `LF`*. `WriteLine` wrote `LF` only on Linux (the program counts 2 `LF` and no `CR`), and a first version of the program that read it straight back failed with `+InvalidCastException: Conversion from string ... to type 'Boolean' is not valid+`. The program therefore rewrites the file with `vbCrLf` before reading it.
  `LineInput` and `EOF` coped with the `LF` file.
* Random-access files use a *record length* given in `FileOpen`; `FilePut(n, value, recordNumber)` and `FileGet` are one-based in record numbers and `LOF` is in bytes. The first draft of the example opened the file with record length 8 for 4-byte integers and `LOF \ 8` gave 2 records instead of 3, so keep the record length equal to the data.
* Binary mode uses `Seek` (one-based position). Fixed-length strings need `VBFixedString`.
* `Rename` threw `PlatformNotSupportedException` on Linux, so the program falls back to `File.Move`. `Dir` with a pattern and then `Dir()` with no arguments returns the next match, `""` at the end; the sort in the program is only to make the output order stable.
* `+FileOpen(..., OpenMode.Output)+` truncates; `OpenMode.Append` appends; the `OpenAccess` and `OpenShare` enumerations give the access and the locking. A forgotten `FileClose` keeps the file locked until the process exits.
* The `FilePut` overload that takes an `Object` is obsolete (see below); write a single value with `FilePutObject` or give `FilePut` a typed variable.

* The sign convention is the Excel one: money you pay is negative (`Pmt` is -377.42 for a 20,000 loan), money you receive is positive. Mixing the signs gives silently wrong answers or an exception from `IRR`.
* The rate and the number of periods must use the same unit (`0.05 / 12` with 60 months). The functions work in `Double`; do not use them to post amounts to a ledger, use `Decimal` and round once.
* `NPV` discounts *every* value from the first period, so the initial investment (period 0) is usually added outside the call. `IRR` starts from a guess and can fail to converge.
* `DDB`, `SLN` and `SYD` are three depreciation methods; `DDB` takes an optional factor (2 means double-declining).
* `Rnd` returns a `Single` in [0, 1).   `Rnd` is not suitable for anything that must be unpredictable or fair: use `Random.Shared` or `RandomNumberGenerator`.

== ErrObject

`Err` is a global `ErrObject` that VB6 used for error handling. In structured code it is still there: after an exception is caught, `Err` describes it. It also provides `Err.Raise`, which throws.

[source,vbnet]
----
Option Strict On

Module ErrTour
    Sub Main()
        Console.WriteLine("-- Err is a global object that mirrors the last exception")
        Try
            Dim zero As Integer = 0
            Console.WriteLine(10 \ zero)
        Catch ex As DivideByZeroException
            Console.WriteLine("Err.Number      : " & Err.Number.ToString())
            Console.WriteLine("Err.Description : " & Err.Description)
            Console.WriteLine("Err.Source      : " & Err.Source)
            Console.WriteLine("GetException is the same object: " & Object.ReferenceEquals(Err.GetException(), ex).ToString())
            Err.Clear()
            Console.WriteLine("after Clear     : " & Err.Number.ToString() & " '" & Err.Description & "'")
        End Try

        Console.WriteLine("-- Err.Raise throws an exception that Try can catch")
        Try
            Err.Raise(vbObjectError + 1000, "ShelfApp", "The shelf is full")
        Catch ex As Exception
            Console.WriteLine(ex.GetType().Name & ": " & ex.Message & " (Err.Number = " & (Err.Number - vbObjectError).ToString() & " + vbObjectError, Source = " & Err.Source & ")")
        End Try
        Try
            Err.Raise(5)
        Catch ex As Exception
            Console.WriteLine(ex.GetType().Name & ": " & ex.Message)
        End Try
        Try
            Err.Raise(53)
        Catch ex As Exception
            Console.WriteLine(ex.GetType().Name & ": " & ex.Message)
        End Try

        Console.WriteLine("-- Err.Number for other exceptions")
        Dim samples As New List(Of Exception) From {
            New InvalidCastException(), New OverflowException(), New IndexOutOfRangeException(), New NullReferenceException(),
            New IO.FileNotFoundException(), New FormatException(), New ArgumentException(), New OutOfMemoryException()
        }
        For Each ex As Exception In samples
            Try
                Throw ex
            Catch caught As Exception
                Console.WriteLine(caught.GetType().Name.PadRight(26) & Err.Number.ToString().PadLeft(6) & "  " & Err.Description)
            End Try
        Next
    End Sub
End Module
----

== Collection

The VB6 `Collection` stores `Object` items, is *one-based*, and can be addressed by position or by a case-insensitive string key; `Add` can place an item `Before` or `After` another.

[source,vbnet]
----
Option Strict On

Module CollectionTour
    Sub Main()
        Dim shelf As New Collection()
        shelf.Add("Dune", "dune")
        shelf.Add("Emma", "emma")
        shelf.Add("Ulysses")
        shelf.Add("Beloved", "beloved", Before:=1)
        shelf.Add("Ivanhoe", "ivanhoe", After:=2)

        Console.WriteLine("-- one-based, ordered by Before and After")
        For i As Integer = 1 To shelf.Count
            Console.Write(i.ToString() & "=" & CStr(shelf(i)) & " ")
        Next
        Console.WriteLine()
        Console.WriteLine("-- keys are case-insensitive")
        Console.WriteLine(CStr(shelf("DUNE")) & ", Contains: " & shelf.Contains("emma").ToString() & "/" & shelf.Contains("zzz").ToString())
        Console.WriteLine("-- items are Object, For Each yields Object")
        For Each item As Object In shelf
            Console.Write(item.ToString() & ";")
        Next
        Console.WriteLine()
        Console.WriteLine("-- errors")
        Try
            shelf.Add("Duplicate", "dune")
        Catch ex As ArgumentException
            Console.WriteLine("add duplicate key  : " & ex.GetType().Name & ": " & ex.Message)
        End Try
        Try
            Console.WriteLine(shelf(0))
        Catch ex As IndexOutOfRangeException
            Console.WriteLine("index 0            : " & ex.GetType().Name & ": " & ex.Message)
        End Try
        Try
            Console.WriteLine(shelf("zzz"))
        Catch ex As ArgumentException
            Console.WriteLine("missing key        : " & ex.GetType().Name & ": " & ex.Message)
        End Try
        shelf.Remove("emma")
        shelf.Remove(1)
        Console.WriteLine("after Remove       : " & shelf.Count.ToString())

        Console.WriteLine("-- the generic replacements")
        Dim titles As New List(Of String) From {"Dune", "Emma"}
        Dim byKey As New Dictionary(Of String, String)(StringComparer.OrdinalIgnoreCase) From {{"dune", "Dune"}, {"emma", "Emma"}}
        Console.WriteLine(titles(0) & " " & byKey("EMMA") & " " & byKey.ContainsKey("Dune").ToString())
    End Sub
End Module

== CompilerServices: code you do not write

The 29 public types of `Microsoft.VisualBasic.CompilerServices` are *called by the compiler*: `Conversions`, `Operators`, `LikeOperator`, `NewLateBinding`, `ObjectFlowControl`, `StaticLocalInitFlag`, `Versioned`, `Utils`, `ProjectData`, `StandardModuleAttribute`,
`OptionCompareAttribute` and the `+...Type+` helper classes. They are public because the generated code has to call them from your assembly. They are hidden from IntelliSense and not part of the supported surface, but nothing stops you calling them.
Reading the IL of five methods shows which helper each construct becomes:

[source,vbnet]
----

Imports System.Reflection
Imports System.Reflection.Emit
Imports System.Runtime.CompilerServices

        Return text Like pattern
    End Function

    Public Shared Function Same(a As String, b As String) As Boolean
        Return a = b
    End Function

    Public Shared Function ToInt(value As Object) As Integer
        Return CInt(value)
    End Function

    Public Shared Function Shorten(text As String) As String
        Return Left(text, 3) & Trim(text)
    End Function

    Public Shared Function Describe(value As Object) As String
        Return TypeName(value) & Len(CStr(value)).ToString()
    End Function
End Class

Module CompilerServicesTour
    ' Lists the methods called by a method body by scanning its IL for call opcodes
    Private Function CalledMethods(m As MethodInfo) As List(Of String)
        Dim result As New List(Of String)()
        Dim il As Byte() = m.GetMethodBody().GetILAsByteArray()
        For i As Integer = 0 To il.Length - 5
            If il(i) = &H28 OrElse il(i) = &H6F Then
                Dim token As Integer = BitConverter.ToInt32(il, i + 1)
                Dim table As Integer = (token >> 24) And &HFF
                If table = &H6 OrElse table = &HA OrElse table = &H2B Then
                    Try
                        Dim target As MethodBase = m.Module.ResolveMethod(token)
                        result.Add(target.DeclaringType.Name & "." & target.Name)
                        i += 4
                    Catch ex As ArgumentException
                    End Try
                End If
            End If
        Next
        Return result
    End Function

    Sub Main()

== When to prefer the BCL

[cols="3,3,4",options="header"]
|===
|Runtime library |BCL |Reason to choose the BCL

|`Left`, `Mid`, `Right`, `InStr` |`Substring`, `IndexOf`, `Contains`, ranges |zero-based like the rest of .NET, culture and comparison explicit; but the VB functions never throw for a too-long length
|`UCase`, `LCase` |`ToUpperInvariant`, `ToLowerInvariant` |the culture is explicit
|`Format`, `FormatNumber` |interpolation with format strings, `ToString(format, culture)` |culture and format are visible
|`CStr`, `Str` |`ToString` |no leading space, culture explicit
|`Val`, `IsNumeric` |`TryParse` with `NumberStyles` and culture |no guessing
|`IsNothing`, `TypeName` |`Is Nothing`, `GetType().Name` |reads the same in every .NET language
|`DateAdd`, `DateDiff` |`DateTime.AddMonths`, subtraction to `TimeSpan` |no boundary-count surprise
|`Now`, `Today` |`DateTime.Now`, `TimeProvider` |testable clock
|`FileOpen`/`Print`/`Input` |`StreamReader`, `StreamWriter`, `File` |encodings, async, `Using`
|`Collection` |`List(Of T)`, `+Dictionary(Of ...)+` |typed and zero-based
|`Err`, `Err.Raise` |exceptions |typed, stack traces
|`Shell`, `Environ`, `Command` |`Process.Start`, `Environment`, `args` |cross-platform, arguments preserved
|`MsgBox`, `InputBox` |`MessageBox.Show`, own dialog |no hidden Windows Forms dependency in the call
|`Rnd`, `Randomize` |`Random`, `RandomNumberGenerator` |quality, thread safety
|`Choose`, `Interaction.Switch` |`Select Case`, `If` |only the needed branch is evaluated
|`Pmt`, `NPV`, `IRR` etc. |none in the BCL |keep the VB functions, in `Decimal`-aware wrappers if money is involved
|===

The VB functions remain good when you port VB6 or VBA logic unchanged, when you need the VB-specific behaviour on purpose (tolerance of `Nothing`, clipping), or when brevity matters in a throw-away script.

== Differences from C#

* C# has no equivalent keywords: every function above is called as `+Strings.Left(...)+`, `+Interaction.Choose(...)+`, `+Financial.Pmt(...)+` after adding `using Microsoft.VisualBasic;` (the reference is already available in .NET projects). Calling `FileSystem.FileOpen` from C# works and is used when reading legacy files.
* Type conversion keywords (`CInt`, `CType`) are language features in Visual Basic and have no C# form; `Convert.ToInt32` and casts differ in rounding and in the way strings are parsed.
* `vbCrLf` and the other constants have no C# counterpart; C# uses the escape sequences `"\r\n"`.
* C# compares strings with `==` ordinally, while Visual Basic's `=` follows `Option Compare`; the library functions that have a `Compare` argument follow it as well.
* See xref:programming-languages/csharp/strings-and-text.adoc[Strings and Text (C#)] and xref:programming-languages/csharp/csharp-and-dotnet.adoc[C# and .NET] for the other side.

== Where the books are outdated

[cols="3,4",options="header"]
|===
|Book habit |Today

|`vbNewLine` in every example |obsolete (BC40000); use `vbCrLf` or `Environment.NewLine`
|`FilePut` with an `Object` |obsolete; use `FilePutObject`
|`MsgBox` and `InputBox` as the I/O of a console exercise |throw `PlatformNotSupportedException`; use `Console`
|`Shell("notepad")` |throws on Linux; `Process.Start`
|`GetSetting`/`SaveSetting` for preferences |Windows registry only; use JSON or `My.Settings`
|`Microsoft.VisualBasic.Compatibility.VB6` from the Upgrade Wizard |not available on .NET
|`DoEvents` and `Sleep`-style loops |`Await Task.Delay`; see xref:programming-languages/visual-basic/async-and-await.adoc[Async and Await]
|Treating `Rnd` as random |predictable; use `Random.Shared`
|unstructured error handling plus `Err` as the main idiom |`Try`/`Catch`
|===

== Diagnostics reference

[cols="2,5",options="header"]
|===
|Diagnostic |Meaning

|BC40000 |use of an obsolete member (`vbNewLine`, the `FilePut` overload for `Object`)
|BC30109 |a class name used as an expression, for example `+Switch(...)+` resolving to `System.Diagnostics.Switch`
|BC30518 |overload resolution failed, for example `FilePut` with an `Object` argument

== Pitfalls checklist

* Positions in the VB string functions are one-based; in the BCL they are zero-based.
* `Trim` removes spaces only; `Replace` with a start argument drops the prefix; `Str` adds a leading space; `Val` and `IsNumeric` accept formats that `TryParse` rejects.
* `Choose` and `Interaction.Switch` evaluate all arguments; refer to `Interaction.Switch` explicitly.
* `DateSerial` and `DateAdd` overflow quietly; `DateDiff` counts boundaries.
* `ControlChars.NewLine` is CR LF on every platform; `Environment.NewLine` follows the platform.
* The legacy `Input` needs CR or CR LF line ends.
* A Windows-only annotation (CA1416) is a build error under `TreatWarningsAsErrors`; guard with `OperatingSystem.IsWindows()` or avoid the call.
* Do not use `Rnd`, `IsNumeric` or `CallByName` where unpredictability, strictness or trimming matter.
* Do not call `Microsoft.VisualBasic.CompilerServices` directly.
