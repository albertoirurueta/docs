This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example that talks to a
database and prints results is a complete program that was built with warnings treated as errors (`Option Strict On`, root namespace
`ShelfApp`) and *run* in the .NET 10 SDK container on Linux. Databases that need a server (SQL Server, MongoDB, Redis) cannot run in that

reference types and no `Await Using`, and the tooling around it (the EF Core command line, the
designers) was built for C# first. This page shows what works as in C#, what needs a different spelling, and what does not work at all. The reference
scenario is the *shelf* catalogue; the entities are `Book`, `Author` and the others from `Shelf.Core`.

SQL itself, indexes and schema design are not repeated here: see xref:database/sql/index.adoc[the SQL reference] and
xref:database/index.adoc[the Databases section]. EF Core concepts are explained for C# on xref:web/aspnet/core/data-access-ef-core.adoc[Data Access with EF Core]

== ADO.NET in one page

ADO.NET is a set of abstract classes in `System.Data.Common` that every provider implements:

[cols="2,3,4",options="header"]
|===
|Abstract type |SQL Server (`Microsoft.Data.SqlClient`) |SQLite (`Microsoft.Data.Sqlite`)

|`DbConnection`
|`SqlConnection`
|`SqliteConnection`

|`DbCommand`
|`SqlCommand`
|`SqliteCommand`

|`DbParameter`
|`SqlParameter`
|`SqliteParameter`

|`DbDataReader`
|`SqlDataReader`

|`DbTransaction`

|`SqliteTransaction`

|`DbDataAdapter`
|`SqlDataAdapter`

|`DbException`
|`SqlException` (with `Number`, `Class`, `State`)

The provider you pick is a NuGet package. For SQL Server use `Microsoft.Data.SqlClient`, which replaces `System.Data.SqlClient` (the old package is the one that
older books and answers show; the replacement keeps the names, so `Imports System.Data.SqlClient` becomes `Imports Microsoft.Data.SqlClient`, and the new provider
encrypts by default; see below). `System.Data.OracleClient` no longer exists; Oracle's own managed provider is `Oracle.ManagedDataAccess.Core`. Npgsql (PostgreSQL) and
MySqlConnector (MySQL, MariaDB) are community providers with the same shape. The abstract types let a repository be written once against `DbConnection`
and `DbCommand`, and `DbProviderFactory` creates the concrete ones when the provider is chosen at run time.

Source: https://learn.microsoft.com/dotnet/framework/data/adonet/ado-net-overview[ADO.NET overview] and https://learn.microsoft.com/dotnet/api/system.data.common.dbconnection[DbConnection]

== Connections, pooling and connection strings

A connection is expensive to open and cheap to keep in a pool. The rule that follows is the same in every language: open late, close early, and let the pool do the sharing. In Visual Basic that means a
`Using` block around every `SqlConnection` or `SqliteConnection`; the `Dispose` at `End Using` returns the physical connection to the pool, it does not close the socket.

=== Pooling defaults, and a failed connect, without a server

Two things about SQL Server connections can be checked without a server. The first is what the connection-string builder assumes when you say nothing; the second is what a failed connection
looks like. This program was run (a loopback port with nothing listening gives an immediate refusal, so no network is needed):

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.SqlClient

Module Offline
    Sub Main()
        Dim builder As New SqlConnectionStringBuilder()
        Console.WriteLine("Defaults of SqlConnectionStringBuilder:")
        Console.WriteLine("  Encrypt             = " & builder.Encrypt.ToString())
        Console.WriteLine("  TrustServerCertificate = " & builder.TrustServerCertificate)
        Console.WriteLine("  Pooling             = " & builder.Pooling)
        Console.WriteLine("  Min / Max Pool Size = " & builder.MinPoolSize & " / " & builder.MaxPoolSize)
        Console.WriteLine("  Connect Timeout     = " & builder.ConnectTimeout)
        Console.WriteLine("  MultipleActiveResultSets = " & builder.MultipleActiveResultSets)

        builder.DataSource = "db.example.test"
        builder.InitialCatalog = "Shelf"
        builder.IntegratedSecurity = True
        builder.ApplicationName = "Shelf.Cli"
        builder.ConnectTimeout = 1
        Console.WriteLine("Built: " & builder.ConnectionString)

        ' Nothing listens on this loopback port, so the failure is immediate and needs no network.
        builder.DataSource = "127.0.0.1,1"
        Using connection As New SqlConnection(builder.ConnectionString)
            Try
                connection.Open()
            Catch ex As SqlException
                Console.WriteLine("SqlException number " & ex.Number & ", class " & ex.Class)
                Console.WriteLine("  message starts: " & ex.Message.Substring(0, ex.Message.IndexOf(" The server")))
            End Try
        End Using
    End Sub
End Module
----

[source,text]
----
Defaults of SqlConnectionStringBuilder:
  Encrypt             = True
  TrustServerCertificate = False
  Pooling             = True
  Min / Max Pool Size = 0 / 100
  Connect Timeout     = 15
  MultipleActiveResultSets = False
Built: Data Source=db.example.test;Initial Catalog=Shelf;Integrated Security=True;Connect Timeout=1;Application Name=Shelf.Cli

  message starts: A network-related or instance-specific error occurred while establishing a connection to SQL Server.

Read the defaults: *pooling is on* with a maximum of 100 connections per distinct connection string, the connect timeout is 15 seconds, and, since version 4 of `Microsoft.Data.SqlClient`, *`Encrypt`
is True and `TrustServerCertificate` is False*. A program that used to connect to a development server with a self-signed certificate through `System.Data.SqlClient` therefore fails with a certificate
error after the switch. The fix for a real server is a valid certificate. For a throw-away local server, `TrustServerCertificate=True` makes the error go away and removes the protection, so keep it out of
production configuration. A failed connect raises `SqlException`, whose `Number` is 0 for transport failures and a server error number once the server answered; the text of the transport message varies by operating system, which is why the
program prints only its first sentence.

Source: https://learn.microsoft.com/sql/connect/ado-net/sql-server-connection-pooling[SQL Server connection pooling] and https://learn.microsoft.com/dotnet/api/microsoft.data.sqlclient.sqlconnectionstringbuilder[SqlConnectionStringBuilder]

Pooling rules that matter (SQL Server):

* A pool belongs to one connection string (character for character), one process and, with integrated security, one identity. Ten strings that differ only by `Application Name` make ten pools.
* A connection that is not disposed is not returned: the classic symptom is `InvalidOperationException` ("Timeout expired. The timeout period elapsed prior to obtaining a connection from the pool"). Visual Basic's
  `Using` makes the correct code the short code; the leak appears when the connection is stored in a field and nobody owns its disposal.
* `SqlConnection.ClearAllPools()` and `ClearPool(connection)` exist for tests and for failover; do not call them in normal code.
* `Microsoft.Data.Sqlite` pools too (the `Pooling` keyword; `New SqliteConnectionStringBuilder().Pooling` is True, see the check below) and its in-memory databases live only as long as one connection stays open, which is why the EF examples below keep a connection open for the duration.

Source: https://learn.microsoft.com/dotnet/framework/data/adonet/connection-pooling[Connection pooling] and https://learn.microsoft.com/dotnet/standard/data/sqlite/connection-strings[SQLite connection strings]

=== Connection strings come from configuration

A connection string holds a server name and often credentials. It does not belong in source code, in the repository, or in a compiled resource. Read it from configuration at start-up, and keep the secret part in a
store that is not in the repository: environment variables, `dotnet user-secrets` for development, a cloud key vault or the platform's secret manager in production, or integrated authentication so that there is no secret at all.
`Microsoft.Extensions.Configuration` layers sources, and later sources override earlier ones. The program writes a small `appsettings.json`, then overrides the value with an environment variable (the double underscore stands for the `:` separator):

[source,vbnet]
----
Option Strict On

Imports System.IO
Imports Microsoft.Data.Sqlite
Imports Microsoft.Extensions.Configuration

Module ConfigDemo
    Sub Main()
        Dim folder = Path.Combine(Path.GetTempPath(), "shelf-config-demo")
        Directory.CreateDirectory(folder)
        File.WriteAllText(Path.Combine(folder, "appsettings.json"),
            "{ ""ConnectionStrings"": { ""Shelf"": ""Data Source=shelf-dev.db;Cache=Shared"" } }")

        Dim configuration = New ConfigurationBuilder().
            SetBasePath(folder).
            AddJsonFile("appsettings.json", optional:=False).
            AddEnvironmentVariables(prefix:="SHELF_").
            Build()

        Dim fromFile = configuration.GetConnectionString("Shelf")
        Console.WriteLine("From appsettings.json: " & fromFile)

        Environment.SetEnvironmentVariable("SHELF_ConnectionStrings__Shelf", "Data Source=:memory:")
        Dim withEnvironment = New ConfigurationBuilder().
            SetBasePath(folder).
            AddJsonFile("appsettings.json", optional:=False).
            AddEnvironmentVariables(prefix:="SHELF_").
            Build()
        Dim effective = withEnvironment.GetConnectionString("Shelf")
        Console.WriteLine("With SHELF_ConnectionStrings__Shelf set: " & effective)

        Dim builder As New SqliteConnectionStringBuilder(effective)
        builder.Mode = SqliteOpenMode.ReadWriteCreate
        builder.Pooling = False
        Console.WriteLine("Normalised: " & builder.ConnectionString)

        Using connection As New SqliteConnection(builder.ConnectionString)
            connection.Open()
            Console.WriteLine("Opened, server version " & connection.ServerVersion.Split("."c)(0) & ".x")
        End Using
        File.Delete(Path.Combine(folder, "appsettings.json"))
    End Sub
End Module
----

[source,text]
----
From appsettings.json: Data Source=shelf-dev.db;Cache=Shared
With SHELF_ConnectionStrings__Shelf set: Data Source=:memory:
Normalised: Data Source=:memory:;Mode=ReadWriteCreate;Pooling=False
Opened, server version 3.x
----

Source: https://learn.microsoft.com/dotnet/core/extensions/configuration[Configuration in .NET] and https://learn.microsoft.com/dotnet/core/extensions/configuration-providers[Configuration providers]

Visual Basic specifics seen in this program: named arguments use `:=` (`optional:=False`); the extension methods `AddJsonFile` and `AddEnvironmentVariables` need their packages and `Imports Microsoft.Extensions.Configuration`; and a local variable named
`directory` would hide `System.IO.Directory` because names are not case-sensitive (the first version of this program failed with BC30456, `+'CreateDirectory' is not a member of 'String'+`, for exactly that reason). Use `SqlConnectionStringBuilder` (or
`SqliteConnectionStringBuilder`) instead of concatenating strings: it validates keywords, escapes values and shows the normalised result, as the `Normalised:` line above does.

== Commands, parameters and readers

The first program uses everything in the basic cycle: create a table, insert rows with parameters, read a scalar, and read rows with a reader. It was built and run:

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite

Module Basics
    Private Structure BookSeed
        Public Title As String
        Public Year As Integer
        Public Isbn As String
        Public Subtitle As String
    End Structure

    Sub Main()
        Dim seeds = {
            New BookSeed With {.Title = "Dune", .Year = 1965, .Isbn = "9780441172719"},
            New BookSeed With {.Title = "Neuromancer", .Year = 1984, .Isbn = "9780441569595", .Subtitle = "A novel"},
            New BookSeed With {.Title = "Hyperion", .Year = 1989, .Isbn = "9780553283686"}}

        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()

            Using create = connection.CreateCommand()
                create.CommandText =
                    "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT NOT NULL, Year INTEGER NOT NULL, Isbn TEXT NOT NULL UNIQUE, Subtitle TEXT NULL)"
                create.ExecuteNonQuery()
            End Using

            Using insert = connection.CreateCommand()
                insert.CommandText = "INSERT INTO Books (Title, Year, Isbn, Subtitle) VALUES ($title, $year, $isbn, $subtitle)"
                insert.Parameters.Add("$title", SqliteType.Text)
                insert.Parameters.Add("$year", SqliteType.Integer)
                insert.Parameters.Add("$isbn", SqliteType.Text)
                insert.Parameters.Add("$subtitle", SqliteType.Text)

                For Each seed In seeds
                    insert.Parameters("$title").Value = seed.Title
                    insert.Parameters("$year").Value = seed.Year
                    insert.Parameters("$isbn").Value = seed.Isbn
                    insert.Parameters("$subtitle").Value = If(seed.Subtitle Is Nothing, DBNull.Value, CObj(seed.Subtitle))
                    Console.WriteLine($"Inserted {insert.ExecuteNonQuery()} row: {seed.Title}")
                Next
            End Using

            Using count = connection.CreateCommand()
                count.CommandText = "SELECT COUNT(*) FROM Books WHERE Year > $year"
                count.Parameters.Add("$year", SqliteType.Integer).Value = 1970
                Dim total = CLng(count.ExecuteScalar())
                Console.WriteLine($"Books after 1970: {total}")
            End Using

            Using query = connection.CreateCommand()
                query.CommandText = "SELECT Id, Title, Year, Subtitle FROM Books ORDER BY Year"
                Using reader = query.ExecuteReader()
                    Dim title = reader.GetOrdinal("Title")
                    Dim subtitle = reader.GetOrdinal("Subtitle")
                    While reader.Read()
                        Dim text = If(reader.IsDBNull(subtitle), "(none)", reader.GetString(subtitle))
                        Console.WriteLine($"{reader.GetInt32(0)}: {reader.GetString(title)} [{reader.GetInt32(2)}] subtitle={text}")
                    End While
                End Using
            End Using
        End Using
    End Sub
End Module
----

[source,text]
----
Inserted 1 row: Dune
Inserted 1 row: Neuromancer
Inserted 1 row: Hyperion
Books after 1970: 2
1: Dune [1965] subtitle=(none)
2: Neuromancer [1984] subtitle=A novel
3: Hyperion [1989] subtitle=(none)
----

Source: https://learn.microsoft.com/dotnet/standard/data/sqlite/parameters[SQLite parameters] and https://learn.microsoft.com/dotnet/api/system.data.common.dbdatareader[DbDataReader]

Points to take from it:

* *Parameters, always.* Every value that comes from outside the program goes in a parameter. The SQL text stays constant, the provider sends the values separately and the database never parses them as SQL.
  With SQL Server the idiom is `command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn`: the type and size are explicit, so the plan cache sees one statement. `Parameters.AddWithValue("@isbn", isbn)` is shorter and lets the provider infer the type from the .NET value, which
  produces a different parameter size for each string length and, for `String` against a `varchar` column, an implicit conversion that can stop an index from being used. Prefer `Add(name, type[, size]).Value`. `Microsoft.Data.Sqlite` accepts both and is not affected by the plan-cache issue; every example on this page still uses typed `Add`, so the habit carries over to SQL Server unchanged.
* *`+Parameters.Add(...)+` returns the new parameter*, so `.Value = x` can be chained onto it, as in `command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn` in the SQL Server listing below. The first program declares the parameters once and sets `Value` through the collection by name.
* *Reuse one command in a loop.* Declare the parameters once, change `Value` for each row, call `ExecuteNonQuery`. The program above inserts three rows with one prepared command shape.
* *Readers are forward-only and hold the connection.* Read by ordinal (`GetOrdinal` once, outside the loop) with the typed getters (`GetInt32`, `GetString`), not by `reader("Title")` in a loop, which does a name lookup for every row and returns `Object` that
  `Option Strict On` makes you convert.
* `ExecuteScalar` returns `Object`: convert it (`+CLng(...)+`; SQLite's `+COUNT(*)+` is a 64-bit integer, SQL Server's is a 32-bit one, and `CInt` on a boxed `Long` is a conversion, not an unboxing). `ExecuteNonQuery` returns the number of rows affected.

=== Nothing is not NULL

The most Visual Basic-specific mistake in data access is to pass `Nothing` for a missing value. In .NET, a database `NULL` is the singleton `DBNull.Value`; `Nothing` is a null reference, which the provider
treats as "no value was supplied". This program shows what the provider does with each, and the other classic ADO.NET failures: a closed connection, a constraint violation, SQL built by concatenation, and reading `NULL` with a typed getter:

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite

Module Pitfalls
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            ' 1. A command on a closed connection
            Using command = connection.CreateCommand()
                command.CommandText = "SELECT 1"
                Try
                    command.ExecuteScalar()
                Catch ex As InvalidOperationException
                    Console.WriteLine("Closed connection: " & ex.Message)
                End Try
            End Using

            connection.Open()
            Using create = connection.CreateCommand()
                create.CommandText = "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT NOT NULL, Isbn TEXT NOT NULL UNIQUE, Subtitle TEXT NULL)"
                create.ExecuteNonQuery()
            End Using

            ' 2. Nothing is not NULL
            Using insert = connection.CreateCommand()
                insert.CommandText = "INSERT INTO Books (Title, Isbn, Subtitle) VALUES ($title, $isbn, $subtitle)"
                insert.Parameters.Add("$title", SqliteType.Text).Value = "Dune"
                insert.Parameters.Add("$isbn", SqliteType.Text).Value = "9780441172719"
                insert.Parameters.Add("$subtitle", SqliteType.Text).Value = Nothing
                Try
                    insert.ExecuteNonQuery()
                Catch ex As InvalidOperationException
                    Console.WriteLine("Value Nothing: " & ex.Message)
                End Try
                insert.Parameters("$subtitle").Value = DBNull.Value
                Console.WriteLine("Value DBNull.Value: inserted " & insert.ExecuteNonQuery())
            End Using

            ' 3. A constraint violation
            Using duplicate = connection.CreateCommand()
                duplicate.CommandText = "INSERT INTO Books (Title, Isbn) VALUES ('Dune again', '9780441172719')"
                Try
                    duplicate.ExecuteNonQuery()
                Catch ex As SqliteException
                    Console.WriteLine($"SqliteException {ex.SqliteErrorCode}/{ex.SqliteExtendedErrorCode}: {ex.Message}")
                End Try
            End Using

            ' 4. Concatenated text versus a parameter
            Dim hostile = "x' OR '1'='1"
            Using unsafeCommand = connection.CreateCommand()
                unsafeCommand.CommandText = "SELECT COUNT(*) FROM Books WHERE Title = '" & hostile & "'"
                Console.WriteLine("Concatenated: " & unsafeCommand.CommandText)
                Console.WriteLine("  rows matched: " & CLng(unsafeCommand.ExecuteScalar()))
            End Using
            Using safeCommand = connection.CreateCommand()
                safeCommand.CommandText = "SELECT COUNT(*) FROM Books WHERE Title = $title"
                safeCommand.Parameters.Add("$title", SqliteType.Text).Value = hostile
                Console.WriteLine("Parameterised: " & safeCommand.CommandText)
                Console.WriteLine("  rows matched: " & CLng(safeCommand.ExecuteScalar()))
            End Using

            ' 5. Reading a NULL column without checking
            Using query = connection.CreateCommand()
                query.CommandText = "SELECT Subtitle FROM Books"
                Using reader = query.ExecuteReader()
                    reader.Read()
                    Try
                        Console.WriteLine(reader.GetString(0))
                    Catch ex As InvalidOperationException
                        Console.WriteLine("GetString on NULL: " & ex.Message)
                    End Try
                    Console.WriteLine("GetValue on NULL is DBNull: " & (reader.GetValue(0) Is DBNull.Value))
                End Using
            End Using
        End Using
    End Sub
End Module
----

The fifth block is worth understanding because it is the SQL injection demonstration in miniature. The concatenated text `+x' OR '1'='1+` closes the string literal and adds a condition that is always true, so the query matches a row that does not have that title; the same text sent as a parameter is just an unusual title and
matches nothing. With a database that supports stacked statements the same technique deletes tables. SQL injection is the only item on this page that can end a company, and the defence is mechanical: parameters for values, an allow-list for identifiers (a column name cannot be a parameter),
least-privilege database accounts, and no string building of SQL. See xref:programming-languages/visual-basic/security-and-cryptography.adoc[Security and Cryptography] for the rest of the security picture.

NULL handling in Visual Basic, in one table:

[cols="3,4",options="header"]
|===
|Task |Visual Basic spelling

|Send a NULL
|`parameter.Value = DBNull.Value`; for an optional value `If(value Is Nothing, CObj(DBNull.Value), CObj(value))` (both branches must be `Object`, or `Option Strict` complains about the `If` operands).

|Test a column
|`reader.IsDBNull(ordinal)` before a typed getter; the getters throw `InvalidOperationException` on NULL with Microsoft.Data.Sqlite (SqlClient throws `SqlNullValueException`).

|Map to a nullable value
|`If(reader.IsDBNull(i), CType(Nothing, Integer?), reader.GetInt32(i))`: one operand must be typed, because `Nothing` alone has no type for `If`.

|Compare in the SQL
|`WHERE Subtitle IS NULL`, never `= NULL`; in EF Core LINQ, `Where(Function(b) b.Subtitle Is Nothing)` is translated to `IS NULL`.
|===

== Transactions

A transaction makes a group of commands atomic. `BeginTransaction` returns an object that must be disposed; if neither `Commit` nor `Rollback` ran, disposing rolls back. With `Microsoft.Data.Sqlite` (as with SqlClient when you use explicit transactions) each command must be told which
transaction it belongs to. This program moves stock between two shelves; the second transfer violates a `CHECK` constraint and rolls back:

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite

Module Transactions
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()
            Execute(connection, "CREATE TABLE Accounts (Name TEXT PRIMARY KEY, Balance INTEGER NOT NULL CHECK (Balance >= 0))")
            Execute(connection, "INSERT INTO Accounts VALUES ('Reading room', 100), ('Archive', 50)")

            Transfer(connection, "Reading room", "Archive", 30)
            Transfer(connection, "Reading room", "Archive", 500)
            PrintBalances(connection)
        End Using
    End Sub

    Private Sub Transfer(connection As SqliteConnection, source As String, target As String, amount As Integer)
        Using transaction = connection.BeginTransaction()
            Try
                Move(connection, transaction, source, -amount)
                Move(connection, transaction, target, amount)
                transaction.Commit()
                Console.WriteLine($"Committed: {amount} from {source} to {target}")
            Catch ex As SqliteException
                transaction.Rollback()
                Console.WriteLine($"Rolled back ({ex.SqliteErrorCode}): {ex.Message}")
            End Try
        End Using
    End Sub

    Private Sub Move(connection As SqliteConnection, transaction As SqliteTransaction, name As String, delta As Integer)
        Using command = connection.CreateCommand()
            command.Transaction = transaction
            command.CommandText = "UPDATE Accounts SET Balance = Balance + $delta WHERE Name = $name"
            command.Parameters.Add("$delta", SqliteType.Integer).Value = delta
            command.Parameters.Add("$name", SqliteType.Text).Value = name
            command.ExecuteNonQuery()
        End Using
    End Sub

    Private Sub Execute(connection As SqliteConnection, sql As String)
        Using command = connection.CreateCommand()
            command.CommandText = sql
            command.ExecuteNonQuery()
        End Using
    End Sub

    Private Sub PrintBalances(connection As SqliteConnection)
        Using command = connection.CreateCommand()
            command.CommandText = "SELECT Name, Balance FROM Accounts ORDER BY Name"
            Using reader = command.ExecuteReader()
                While reader.Read()
                    Console.WriteLine($"{reader.GetString(0)}: {reader.GetInt32(1)}")
                End While
            End Using
        End Using
    End Sub
End Module
----

[source,text]
----
Committed: 30 from Reading room to Archive
Rolled back (19): SQLite Error 19: 'CHECK constraint failed: Balance >= 0'.
Archive: 80
Reading room: 70
----

Source: https://learn.microsoft.com/dotnet/standard/data/sqlite/transactions[SQLite transactions]

Rules of thumb: keep transactions short, open them as late as possible and commit as early as possible; never wait for a user inside one; catch the specific exception you can handle (`SqlException` with a known `Number`, such as 1205 for a deadlock victim in SQL Server, after which the whole unit of work may be retried) and roll back
in every other case. `System.Transactions.TransactionScope` is the ambient alternative and also works with the providers; it enlists connections that open inside the scope, which can silently escalate to a distributed transaction when two connection strings are used.
Prefer the explicit transaction unless the code you call is outside your control.

== Async ADO.NET

Every I/O method has an async twin (`OpenAsync`, `ExecuteReaderAsync`, `ReadAsync`, `ExecuteNonQueryAsync`) that takes a `CancellationToken`. Visual Basic has no `Await Using`, so the code uses a plain `Using` for synchronous disposal
or, when the asynchronous disposal matters, a `Try/Finally` with an explicit `Dispose`. Awaiting inside `Finally` is not allowed:

Imports System.Threading
Imports Microsoft.Data.Sqlite

Module AsyncAdo
    Sub Main()
        RunAsync().GetAwaiter().GetResult()
    End Sub

    Private Async Function RunAsync() As Task
        Dim connection As New SqliteConnection("Data Source=:memory:")
        Try
            Await connection.OpenAsync()
            Using create = connection.CreateCommand()
                create.CommandText = "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT NOT NULL)"
                Await create.ExecuteNonQueryAsync()
            End Using
            Using insert = connection.CreateCommand()
                insert.CommandText = "INSERT INTO Books (Title) VALUES ('Dune'), ('Hyperion'), ('Neuromancer')"
                Console.WriteLine("Inserted: " & Await insert.ExecuteNonQueryAsync())
            End Using

            Using query = connection.CreateCommand()
                query.CommandText = "SELECT Title FROM Books ORDER BY Title"
                Using reader = Await query.ExecuteReaderAsync()
                    While Await reader.ReadAsync()
                        Console.WriteLine("Read: " & reader.GetString(0))
                    End While
                End Using
            End Using

            Using cancelled As New CancellationTokenSource()
                cancelled.Cancel()

                        Await query.ExecuteScalarAsync(cancelled.Token)
                    Catch ex As OperationCanceledException
                        Console.WriteLine("Cancelled before it started: " & ex.GetType().Name)
                    End Try
                End Using
            End Using
        Finally
            connection.Dispose()
        End Try
    End Function

== SQL Server with Microsoft.Data.SqlClient

The code below is the SQL Server counterpart of the examples above: a typed lookup, a stored procedure with an output parameter, an explicit transaction with a deadlock-aware `+Catch ... When+`, an async reader with a cancellation token, a `DataAdapter` with generated update commands and a bulk copy. It
was *built, not run*: nothing here can execute without a server. The connection string is read from an environment variable with a safe development default, and the class that owns it is the only place that knows about it.

[source,vbnet]
----
Option Strict On

Imports System.Data
Imports System.Threading
Imports Microsoft.Data.SqlClient

' Built, not run: every method here needs a SQL Server that the build machine does not have.
Public Class SqlServerCatalog
    Private ReadOnly _connectionString As String

    ' The connection string comes from configuration or an environment variable, never from source code.
    Public Sub New()
        _connectionString = If(Environment.GetEnvironmentVariable("SHELF_SQL"), "Server=localhost;Database=Shelf;Integrated Security=True")
    End Sub

    ' Typed parameter, explicit size: one cached plan for every title length.
    Public Function FindIdByIsbn(isbn As String) As Integer?
        Using connection As New SqlConnection(_connectionString)
            connection.Open()
            Using command As New SqlCommand("SELECT Id FROM dbo.Books WHERE Isbn = @isbn", connection)
                command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn
                Dim result = command.ExecuteScalar()
                Return If(result Is Nothing OrElse result Is DBNull.Value, CType(Nothing, Integer?), CInt(result))
            End Using
        End Using
    End Function

    ' Stored procedure with an output parameter and a return value.
    Public Function AddBook(title As String, year As Integer, isbn As String) As Integer
        Using connection As New SqlConnection(_connectionString)
            connection.Open()
            Using command As New SqlCommand("dbo.AddBook", connection)
                command.CommandType = CommandType.StoredProcedure
                command.Parameters.Add("@title", SqlDbType.NVarChar, 200).Value = title
                command.Parameters.Add("@year", SqlDbType.Int).Value = year
                command.Parameters.Add("@isbn", SqlDbType.NChar, 13).Value = isbn
                Dim newId = command.Parameters.Add("@id", SqlDbType.Int)
                newId.Direction = ParameterDirection.Output
                command.ExecuteNonQuery()
                Return CInt(newId.Value)
            End Using
        End Using
    End Function

    ' Transaction: both commands enlist explicitly.
    Public Sub Rename(id As Integer, title As String)
        Using connection As New SqlConnection(_connectionString)
            connection.Open()
            Using transaction = connection.BeginTransaction(IsolationLevel.ReadCommitted)
                Try
                    Using command As New SqlCommand("UPDATE dbo.Books SET Title = @title WHERE Id = @id", connection, transaction)
                        command.Parameters.Add("@title", SqlDbType.NVarChar, 200).Value = title
                        command.Parameters.Add("@id", SqlDbType.Int).Value = id
                        command.ExecuteNonQuery()
                    End Using
                    transaction.Commit()
                Catch ex As SqlException When ex.Number = 1205
                    transaction.Rollback()
                    Throw New InvalidOperationException("Chosen as a deadlock victim; retry the whole unit of work.", ex)
                Catch
                    transaction.Rollback()
                    Throw
                End Try
            End Using
        End Using
    End Sub

    ' Async with a cancellation token. The Using block (not Await Using) disposes synchronously.
    Public Async Function GetTitlesAsync(minimumYear As Integer, token As CancellationToken) As Task(Of List(Of String))
        Dim titles As New List(Of String)
        Using connection As New SqlConnection(_connectionString)
            Await connection.OpenAsync(token)
            Using command As New SqlCommand("SELECT Title FROM dbo.Books WHERE Year >= @year ORDER BY Title", connection)
                command.Parameters.Add("@year", SqlDbType.Int).Value = minimumYear
                Using reader = Await command.ExecuteReaderAsync(token)
                    While Await reader.ReadAsync(token)
                        titles.Add(reader.GetString(0))
                    End While
                End Using
            End Using
        End Using
        Return titles
    End Function

    ' DataAdapter with generated update commands; the SELECT must return the primary key.
    Public Sub SaveChanges(table As DataTable)
        Using connection As New SqlConnection(_connectionString)
            Using adapter As New SqlDataAdapter("SELECT Id, Title, Year, Isbn FROM dbo.Books", connection)
                Using builder As New SqlCommandBuilder(adapter)
                    Dim updated = adapter.Update(table)
                    Console.WriteLine("Rows written: " & updated)
                End Using
            End Using
        End Using
    End Sub

    ' Bulk load.
    Public Sub Import(rows As DataTable)
        Using connection As New SqlConnection(_connectionString)
            connection.Open()
            Using copy As New SqlBulkCopy(connection) With {.DestinationTableName = "dbo.Books", .BatchSize = 1000}
                copy.WriteToServer(rows)
            End Using
        End Using
    End Sub
End Class

Source: https://learn.microsoft.com/sql/connect/ado-net/[Microsoft.Data.SqlClient documentation] and https://learn.microsoft.com/sql/connect/ado-net/microsoft-ado-net-sql-server[ADO.NET for SQL Server]

Visual Basic notes on this listing:

* `Catch ex As SqlException When ex.Number = 1205` is Visual Basic's exception filter (C# added the same idea as `+catch ... when+` in C# 6). The filter runs before the stack unwinds, so an exception that no `Catch` matches is not caught at all.
* `Return If(result Is Nothing OrElse result Is DBNull.Value, CType(Nothing, Integer?), CInt(result))` is how a function returns `Integer?`: the `CType(Nothing, Integer?)` types the first operand, and `CInt` converts to `Integer`, which widens to `Integer?`.
* A stored procedure needs `CommandType.StoredProcedure`, the procedure name as the command text, and `ParameterDirection.Output` for output parameters, whose `Value` is available after `ExecuteNonQuery` (and, for a reader, only after the reader is closed).
* `SqlCommandBuilder` generates the `INSERT`, `UPDATE` and `DELETE` for an adapter from its `SELECT`, which must return the primary key. It is convenient for tools and small tables; for a real data layer, write the commands or use EF Core.
* `SqlBulkCopy` is the fast way to load many rows; it has no equivalent in EF Core (EF's own bulk helpers are `ExecuteUpdate` and `ExecuteDelete`).
* The `Using` blocks dispose synchronously even inside `Async` methods. Provider objects implement `IAsyncDisposable`, but without `Await Using` Visual Basic code cannot call `DisposeAsync` in a `Finally`; in practice the synchronous `Dispose` of a pooled connection is cheap.

== A repository over ADO.NET

The `Shelf.Core` project defines `ICatalogStore`; any store that implements it can be plugged into `Catalog`. The class below implements it over SQLite with plain ADO.NET, mapping the `Book`/`Magazine` hierarchy to a single table with a `Kind` discriminator. It
is the classic data-access layer: SQL is in one class, parameters are always used, and the rest of the program sees only the interface.

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite
Imports Shelf.Core

' ICatalogStore from Shelf.Core, implemented over ADO.NET.
Public Class SqliteCatalogStore
    Implements ICatalogStore

    Private ReadOnly _connection As SqliteConnection

    Public Sub New(connection As SqliteConnection)
        _connection = connection
        Using command = _connection.CreateCommand()
            command.CommandText =
                "CREATE TABLE IF NOT EXISTS Items (Id INTEGER PRIMARY KEY, Kind TEXT NOT NULL, Title TEXT NOT NULL, Year INTEGER NOT NULL, Isbn TEXT NULL, Issue INTEGER NULL, Authors TEXT NULL)"
            command.ExecuteNonQuery()
        End Using
    End Sub

    Public Sub Add(item As CatalogItem) Implements ICatalogStore.Add
        Using command = _connection.CreateCommand()
            command.CommandText = "INSERT INTO Items (Kind, Title, Year, Isbn, Issue, Authors) VALUES ($kind, $title, $year, $isbn, $issue, $authors); SELECT last_insert_rowid()"
            command.Parameters.Add("$kind", SqliteType.Text).Value = item.Kind
            command.Parameters.Add("$title", SqliteType.Text).Value = item.Title
            command.Parameters.Add("$year", SqliteType.Integer).Value = item.Year
            Dim book = TryCast(item, Book)
            Dim magazine = TryCast(item, Magazine)
            command.Parameters.Add("$isbn", SqliteType.Text).Value = If(book Is Nothing, CObj(DBNull.Value), CObj(book.Isbn.Value))
            command.Parameters.Add("$issue", SqliteType.Integer).Value = If(magazine Is Nothing, CObj(DBNull.Value), CObj(magazine.IssueNumber))
            command.Parameters.Add("$authors", SqliteType.Text).Value = If(book Is Nothing, CObj(DBNull.Value), CObj(String.Join("; ", book.Authors)))
            item.Id = CInt(CLng(command.ExecuteScalar()))
        End Using
    End Sub

    Public Function GetAll() As IReadOnlyList(Of CatalogItem) Implements ICatalogStore.GetAll
        Dim result As New List(Of CatalogItem)
        Using command = _connection.CreateCommand()
            command.CommandText = "SELECT Id, Kind, Title, Year, Isbn, Issue, Authors FROM Items ORDER BY Id"
            Using reader = command.ExecuteReader()
                While reader.Read()
                    result.Add(Materialize(reader))
                End While
            End Using
        End Using
        Return result
    End Function

    Public Function Find(id As Integer) As CatalogItem Implements ICatalogStore.Find
        Using command = _connection.CreateCommand()
            command.CommandText = "SELECT Id, Kind, Title, Year, Isbn, Issue, Authors FROM Items WHERE Id = $id"
            command.Parameters.Add("$id", SqliteType.Integer).Value = id
            Using reader = command.ExecuteReader()
                Return If(reader.Read(), Materialize(reader), Nothing)
            End Using
        End Using
    End Function

    Private Shared Function Materialize(reader As SqliteDataReader) As CatalogItem
        Dim item As CatalogItem
        If reader.GetString(1) = "Book" Then
            Dim authors = reader.GetString(6).Split({"; "}, StringSplitOptions.RemoveEmptyEntries).Select(Function(name) New Author(name)).ToArray()
            item = New Book(reader.GetString(2), reader.GetInt32(3), Isbn.Parse(reader.GetString(4)), authors)
        Else
            item = New Magazine(reader.GetString(2), reader.GetInt32(3), reader.GetInt32(5))
        End If
        item.Id = reader.GetInt32(0)
        Return item
    End Function
End Class

Module Repository
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()
            Dim catalog As New Catalog(New SqliteCatalogStore(connection))
            catalog.Add(New Book("Dune", 1965, Isbn.Parse("9780441172719"), New Author("Frank Herbert")))
            catalog.Add(New Magazine("Byte", 1984, 12))
            catalog.Add(New Book("Neuromancer", 1984, Isbn.Parse("9780441569595"), New Author("William Gibson")))

            For Each item In catalog.Search("e")
                Console.WriteLine($"{item.Id}: {item.Describe()}")
            Next
        End Using
    End Sub
End Module

=== Caching in front of the store

A cache in front of a repository is the simplest performance step and the easiest to get wrong. The in-memory cache from `Microsoft.Extensions.Caching.Memory` replaces `System.Runtime.Caching.MemoryCache` of .NET Framework; the program counts database queries to show the effect:

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite
Imports Microsoft.Extensions.Caching.Memory

Module CacheDemo
    Private _queries As Integer

    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()
            Using setup = connection.CreateCommand()
                setup.CommandText = "CREATE TABLE Books (Id INTEGER PRIMARY KEY, Title TEXT); INSERT INTO Books (Title) VALUES ('Dune')"
                setup.ExecuteNonQuery()
            End Using

            Using cache As New MemoryCache(New MemoryCacheOptions())
                For i = 1 To 3
                    Dim title = cache.GetOrCreate("book:1",
                        Function(entry)
                            entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5)
                            Return LoadTitle(connection, 1)
                        End Function)
                    Console.WriteLine($"Request {i}: {title} (database queries so far: {_queries})")
                Next
                cache.Remove("book:1")
                Console.WriteLine("After Remove: " & cache.GetOrCreate("book:1", Function(entry) LoadTitle(connection, 1)) & " (queries: " & _queries & ")")
            End Using
        End Using
    End Sub

    Private Function LoadTitle(connection As SqliteConnection, id As Integer) As String
        _queries += 1
        Using command = connection.CreateCommand()
            command.CommandText = "SELECT Title FROM Books WHERE Id = $id"
            command.Parameters.Add("$id", SqliteType.Integer).Value = id
            Return CStr(command.ExecuteScalar())
        End Using
    End Function
End Module
----

[source,text]
----
Request 1: Dune (database queries so far: 1)
Request 2: Dune (database queries so far: 1)
Request 3: Dune (database queries so far: 1)
After Remove: Dune (queries: 2)
----

Source: https://learn.microsoft.com/dotnet/core/extensions/caching[Caching in .NET]

`GetOrCreate` takes a `Func(Of ICacheEntry, TItem)`; in Visual Basic a multi-line `+Function(entry) ... End Function+` lambda is required when the body has a statement, as with the expiration setting here. Cache keys are strings, so build them in one place; set an expiration; and invalidate (`Remove`) when you write. Remember that a cache is state: do not
cache anything that depends on the current user unless the user is in the key, and do not cache entities that are tracked by an EF context.

== Dapper

Dapper is a micro-ORM: extension methods on `IDbConnection` that run SQL and map rows to objects by column name. It is a community library (not from Microsoft) and is widely used from Visual Basic as well as C#. It adds nothing beyond what ADO.NET provides except the mapping code, which is what makes it fast and what keeps it out of the way. The program was built and run with Dapper 2.1.89:

[source,vbnet]

Option Strict On

Imports Dapper

Public Class BookRow

Module DapperDemo

            For Each book In newer
                Console.WriteLine($"{book.Id}: {book.Title} ({book.Year})")

            Console.WriteLine("Count: " & count)

            Dim first = connection.QuerySingleOrDefault(Of BookRow)("SELECT * FROM Books WHERE Isbn = @isbn", New With {.isbn = "0000000000000"})

Visual Basic notes: parameters are passed as an anonymous type (`+New With {.minimum = 1970}+`), whose property names become the `@minimum` parameter; the usual mapping target is a class with a parameterless constructor and settable properties named as the columns (name matching is case-insensitive, which suits Visual Basic); `QuerySingleOrDefault(Of T)` returns `Nothing`, not an
exception, for no row (but throws when more than one row matches); and the generic argument is `(Of BookRow)`, which is where C# writes `<BookRow>`. Dapper makes SQL injection as easy as plain ADO.NET if you concatenate: the parameter syntax is the protection.

== Entity Framework Core from Visual Basic

EF Core 10 is the version that ships with .NET 10. Everything in the runtime works from Visual Basic: the model, LINQ translation (both syntaxes), change tracking, `SaveChanges`, concurrency, raw SQL and seeding. What C# has and Visual Basic lacks are, again, a language feature (nullable reference types, so EF Core cannot infer which columns are required) and tooling (the design-time code generators for migrations and scaffolding emit C#; discussed below).

=== The model and the context

The entities are plain classes. A navigation collection is initialised with `As New List(Of BookEntity)`. The context configures the model in `OnModelCreating` with the fluent API, using lambdas (`Function(b) b.Title`, and `+Sub(book) ...+` for the entity configuration block). The ISBN is the `Isbn` structure from `Shelf.Core`, stored as text through a value converter. The context takes its options through
the constructor, so the same class can be used with SQLite in tests and another provider in production.

=== Option Compare Text breaks translation

String comparison with `=` in Visual Basic obeys the file's `Option Compare` setting. With the default, `Option Compare Binary`, `b.Title = "Dune"` becomes an ordinary equality that EF Core translates. With `Option Compare Text`, the compiler emits a call to a runtime comparison method instead, and the translator fails:

=== Async, transactions, concurrency and raw SQL

This program was run. It saves and queries asynchronously, rolls back an explicit transaction, provokes an optimistic-concurrency conflict with two contexts, and uses interpolated raw SQL:

[source,vbnet]
----
Option Strict On

Imports Microsoft.EntityFrameworkCore
Imports Microsoft.EntityFrameworkCore.ChangeTracking
Imports Shelf.Core

Module Advanced
    Sub Main()
        RunAsync().GetAwaiter().GetResult()
    End Sub

    Private Async Function RunAsync() As Task
        Using connection = OpenDatabase()
            Using context As New ShelfContext(CreateOptions(connection))
                Dim options = CreateOptions(connection)

                context.Books.Add(New BookEntity With {.Title = "Dune", .Year = 1965, .Isbn = Isbn.Parse("9780441172719"), .AuthorId = 1})
                Console.WriteLine("Saved: " & Await context.SaveChangesAsync())
                Dim titles = Await context.Books.Select(Function(b) b.Title).ToListAsync()
                Console.WriteLine("Titles: " & String.Join(", ", titles))

                Console.WriteLine("--- explicit transaction")
                Dim transaction = Await context.Database.BeginTransactionAsync()
                Try
                    context.Books.Add(New BookEntity With {.Title = "Temporary", .Year = 2000, .Isbn = Isbn.Parse("9780441569595"), .AuthorId = 2})
                    Await context.SaveChangesAsync()
                    Console.WriteLine("Inside transaction: " & Await context.Books.CountAsync())
                    Await transaction.RollbackAsync()
                Finally
                    transaction.Dispose()
                End Try
                context.ChangeTracker.Clear()
                Console.WriteLine("After rollback: " & Await context.Books.CountAsync())

                Console.WriteLine("--- optimistic concurrency")
                Using first As New ShelfContext(options), second As New ShelfContext(options)
                    Dim a = Await first.Books.FirstAsync()
                    Dim b = Await second.Books.FirstAsync()
                    a.Title = "Dune (edited by first)"
                    a.Version += 1
                    Await first.SaveChangesAsync()
                    b.Title = "Dune (edited by second)"
                    b.Version += 1
                    Dim conflict As EntityEntry = Nothing
                    Try
                        Await second.SaveChangesAsync()
                    Catch ex As DbUpdateConcurrencyException
                        Console.WriteLine("DbUpdateConcurrencyException, entries: " & ex.Entries.Count)
                        conflict = ex.Entries(0)
                    End Try
                    If conflict IsNot Nothing Then
                        Dim stored = Await conflict.GetDatabaseValuesAsync()
                        Console.WriteLine("Database has: " & CStr(stored(NameOf(BookEntity.Title))))
                    End If
                End Using

                Console.WriteLine("--- raw SQL")
                Dim year = 1960
                Dim raw = Await context.Books.FromSql($"SELECT * FROM Books WHERE Year > {year}").ToListAsync()
                Console.WriteLine("FromSql rows: " & raw.Count)
                Dim affected = Await context.Database.ExecuteSqlAsync($"UPDATE Books SET Year = Year + 1 WHERE Id = {raw(0).Id}")
                Console.WriteLine("ExecuteSql affected: " & affected)
            End Using
        End Using
    End Function

Visual Basic points in this listing:

* The conflict handler stores the entry in a variable and awaits *after* the `Try` block; `Await` inside the `Catch` is the BC36943 error shown earlier.
* The concurrency token here is an integer `Version` that the code increments, configured with `IsConcurrencyToken()`. SQL Server's `rowversion` column (`IsRowVersion()`) updates itself; SQLite has no such type.
* `+FromSql($"... {year}")+` takes a *formattable* string.   Do not assign an interpolated string to a `String` variable first and pass that: the holes are formatted into the text and the protection is gone.
* `Using first As New ShelfContext(options), second As New ShelfContext(options)` declares two resources in one `Using`.

=== Seeding

Two kinds. `HasData` in `OnModelCreating` (used in the model above) seeds rows with fixed keys and is part of the model, so it is included in migrations. `UseSeeding` (EF Core 9 and later) runs code when the database is created or migrated, which suits data that is computed or that needs the full context. This program ran:

[source,vbnet]
----
Option Strict On

Imports Microsoft.Data.Sqlite
Imports Microsoft.EntityFrameworkCore
Imports Shelf.Core

Module Seeding
    Sub Main()
        Using connection As New SqliteConnection("Data Source=:memory:")
            connection.Open()
            Dim builder As New DbContextOptionsBuilder(Of ShelfContext)()
            builder.UseSqlite(connection)
            builder.UseSeeding(
                Sub(context, storeCreated)
                    Dim set1 = context.Set(Of BookEntity)()
                    If Not set1.Any(Function(b) b.Title = "Dune") Then
                        set1.Add(New BookEntity With {.Title = "Dune", .Year = 1965, .Isbn = Isbn.Parse("9780441172719"), .AuthorId = 1})
                        context.SaveChanges()
                        Console.WriteLine("UseSeeding added Dune (store created by this call: " & storeCreated & ")")
                    End If
                End Sub)

            Using context As New ShelfContext(builder.Options)
                context.Database.EnsureCreated()
                Console.WriteLine("Books: " & context.Books.Count())
            End Using
        End Using
    End Sub
End Module
----

[source,text]
----
UseSeeding added Dune (store created by this call: True)
Books: 1
----

Source: https://learn.microsoft.com/ef/core/modeling/data-seeding[Data seeding]

The seeding delegate is a `Sub(context, storeCreated)` lambda; the second parameter says whether the call created the store. `UseAsyncSeeding` is the asynchronous counterpart, and both should be written so that running twice does not duplicate rows (the `Any` check above).

== Migrations and Visual Basic

Migrations are where Visual Basic stops working like C#. `dotnet ef migrations add` generates the migration as source code in the project's language, and EF Core ships a code generator for C# only. Run against a Visual Basic project, the tool says so:

[source,text]
----
$ dotnet ef migrations add Initial
Build started...
Build succeeded.
The project language 'VB' isn't supported by the built-in IMigrationsCodeGenerator service. You can try looking for an additional NuGet package which supports this language; moving your DbContext type to a C# class library referenced by this project; or manually implementing and registering the design-time service for the programming language.
----

(The message is the tool's own; it names the three ways out.) The options, from simplest to most flexible:

[cols="2,5",options="header"]
|===
|Option |Notes

|Keep the migrations in a small C# project
|The supported route, and the one this page tested. The model (`DbContext` and entities) stays in Visual Basic; a C# class library holds the generated migrations; the application and the tooling reference both.

|`EFCore.VisualBasic` (community)
|A package that adds a Visual Basic code generator to `dotnet ef` design time. As checked on 2026-10-19, the newest release on NuGet is 8.0.0 (for EF Core 8; earlier ones 7.0.0 and 6.x previews). See the test below: it does not work with EF Core 10.

|Hand-written migrations
|A migration is a class that derives from `Migration` with `Up` and `Down` methods that call `MigrationBuilder`; it can be written in Visual Basic, and the `ModelSnapshot` has to be kept in step by hand, which is the part nobody wants.

|`EnsureCreated`
|Creates the schema from the model without migrations. Right for tests and prototypes; it cannot evolve a schema and cannot be mixed with migrations on the same database.

|SQL scripts
|`dotnet ef migrations script` produces plain SQL from the C# migrations, to apply with the database's own tools; or maintain the schema with a dedicated tool outside EF.
|===

== Binding query results to Windows Forms and WPF

For a grid in Windows Forms the shape is: load into a list, wrap it in a `BindingList(Of T)` or a `BindingSource`, set `DataGridView.DataSource`. EF Core can also provide a ready local view (`context.Books.Local.ToBindingList()`), which stays in step with the change tracker. The listing below was *built, not run* (Windows Forms needs Windows); the
`Async Sub` override is the correct place to start asynchronous loading because it runs on the UI thread and resumes there.

[source,vbnet]
----
Option Strict On

Imports System.ComponentModel
Imports System.Windows.Forms
Imports Microsoft.EntityFrameworkCore

Public Class BookRow
    Public Property Id As Integer
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Public Class RowsContext
    Inherits DbContext

    Public Property Books As DbSet(Of BookRow)

    Protected Overrides Sub OnConfiguring(optionsBuilder As DbContextOptionsBuilder)
        optionsBuilder.UseSqlite("Data Source=shelf.db")
    End Sub
End Class

Public Class BookGridForm
    Inherits Form

    Private ReadOnly _grid As New DataGridView() With {.Dock = DockStyle.Fill, .AutoGenerateColumns = True}
    Private ReadOnly _source As New BindingSource()
    Private ReadOnly _rows As New BindingList(Of BookRow)

    Public Sub New()
        Text = "Shelf"
        _source.DataSource = _rows
        _grid.DataSource = _source
        Controls.Add(_grid)
    End Sub

    Public Shared Function TrackedRows(context As RowsContext) As BindingList(Of BookRow)
        ' A binding list that stays in step with the change tracker.
        Return context.Books.Local.ToBindingList()
    End Function

    Protected Overrides Async Sub OnShown(e As EventArgs)
        MyBase.OnShown(e)
        Using context As New RowsContext()
            ' AsNoTracking: the grid edits copies; save them explicitly with a separate unit of work.
            Dim loaded = Await context.Books.AsNoTracking().OrderBy(Function(b) b.Title).ToListAsync()
            _rows.RaiseListChangedEvents = False
            For Each row In loaded
                _rows.Add(row)
            Next
            _rows.RaiseListChangedEvents = True
            _rows.ResetBindings()
        End Using
    End Sub
End Class

Public Module Program
    <STAThread>
    Public Sub Main()
        Application.EnableVisualStyles()
        Application.Run(New BookGridForm())
    End Sub
End Module
----

Source: https://learn.microsoft.com/dotnet/desktop/winforms/[Windows Forms for .NET]

Notes: the entity here is a *row* class for the grid, with settable properties (a grid cannot edit read-only ones); the context loads with `AsNoTracking` because the grid edits copies and the program saves them explicitly; `RaiseListChangedEvents = False` while adding many rows avoids one grid refresh per row; do not keep the
context alive for the lifetime of the form. For WPF the equivalent is an `ObservableCollection(Of BookViewModel)` that the view model fills after `Await` returns (see
xref:programming-languages/visual-basic/wpf-applications.adoc[WPF Applications]), and a `DataTable.DefaultView` binds to a `DataGrid` in both frameworks. The Windows Forms details (`BindingSource`, `DataGridView` columns) are on
xref:programming-languages/visual-basic/windows-forms-applications.adoc[Windows Forms Applications].

== Other stores: MongoDB and Redis

Document and key-value stores have their own drivers, which are .NET libraries and therefore work from Visual Basic. The listing was *built, not run*: it needs servers on `localhost`. It uses `MongoDB.Driver` 3.12.0 and `StackExchange.Redis` 3.4.5 with expression lambdas in the
queries (the Mongo `Find` takes an expression tree, as LINQ does):

[source,vbnet]
----
Option Strict On

Imports MongoDB.Bson
Imports MongoDB.Driver
Imports StackExchange.Redis

' Built, not run: both stores need a running server.
Public Class BookDocument
    Public Property Id As ObjectId
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Module Program
    Sub Main()
        RunAsync().GetAwaiter().GetResult()
    End Sub

    Private Async Function RunAsync() As Task
        Dim client As New MongoClient("mongodb://localhost:27017")
        Dim books = client.GetDatabase("shelf").GetCollection(Of BookDocument)("books")
        Await books.InsertOneAsync(New BookDocument With {.Title = "Dune", .Year = 1965})
        Dim newer = Await books.Find(Function(b) b.Year > 1960).SortBy(Function(b) b.Title).ToListAsync()
        Console.WriteLine("Mongo documents: " & newer.Count)

        Dim redis = Await ConnectionMultiplexer.ConnectAsync("localhost:6379")
        Dim db = redis.GetDatabase()
        Await db.StringSetAsync("book:1:title", "Dune", TimeSpan.FromMinutes(5))
        Dim cached As RedisValue = Await db.StringGetAsync("book:1:title")
        Console.WriteLine("Redis value: " & cached.ToString())
    End Function
End Module
----

The data models, indexing and operations of these stores are explained with their native tools in xref:database/mongodb/drivers-and-tooling.adoc[MongoDB drivers and tooling] and xref:database/redis/clients-and-client-side-caching.adoc[Redis clients and client-side caching]; xref:database/choosing-the-right-database.adoc[Choosing the right database] helps to decide which store a feature needs.

== Legacy: EF6, LINQ to SQL and typed DataSets

* *EF6* (`EntityFramework` 6.x, the `System.Data.Entity` namespace) is in maintenance. The 6.5 line targets .NET and .NET Framework: a project test on .NET 10 restored `EntityFramework` 6.5.1, compiled a `DbContext`-derived class, and loaded the assembly at run time (`EF6 type loaded: EntityFramework 6.0.0.0`, `Runtime: .NET 10.0.13`). The test did not open a database; the EDMX designer and the Package Manager Console commands of EF6 (`Enable-Migrations`, `Update-Database`) were not exercised. For an application that already uses EF6, keeping it on .NET Framework is legitimate; moving to .NET 10 is a port to EF Core in practice, covered for C# on xref:web/aspnet/mvc/data-access-ef6.adoc[Data Access with EF6]. The official guide for the move is https://learn.microsoft.com/ef/efcore-and-ef6/porting/[Port from EF6 to EF Core].
* *LINQ to SQL* (`System.Data.Linq`, `.dbml` designer files) is documented in the .NET Framework data documentation (the link below sits under `/dotnet/framework/`), not in the .NET documentation. Plan to port a program that uses it to EF Core or Dapper as part of a move to .NET 10.
* *Typed DataSets* generated by older Visual Studio wizards are plain code on top of `System.Data` and port easily, but they are not a model to start from.
* *`System.Data.OracleClient`* and *`System.Data.SqlClient`* are the old provider names; see the opening table.

Source: https://learn.microsoft.com/ef/ef6/[Entity Framework 6], https://learn.microsoft.com/ef/efcore-and-ef6/[Compare EF Core and EF6] and https://learn.microsoft.com/dotnet/framework/data/adonet/sql/linq/[LINQ to SQL (.NET Framework)]

== Pitfalls

[cols="2,4",options="header"]
|===
|Pitfall |Remedy

|`Nothing` as a parameter value
|`DBNull.Value`.

|String-concatenated SQL
|Parameters; allow-list identifiers.

|`AddWithValue` with strings against SQL Server
|`Add(name, SqlDbType.NVarChar, size).Value`.

|`Await` in `Catch` or `Finally`
|Capture, leave the block, then await (BC36943).

|Visual Basic `Like` in a LINQ query
|`EF.Functions.Like`.

|`Option Compare Text` in a file with EF queries
|`Option Compare Binary`; collation in the database.

|`String` properties are nullable in EF Core
|`IsRequired()`.

|Local variable named like a type or a `DbSet`
|Rename; names are case-insensitive.

|Trying `dotnet ef migrations add` in a VB project
|Use a C# migrations project.

|One shared `DbContext` for the whole application
|One per unit of work.

|Leaked connection
|`Using` everywhere; do not store connections in fields.

|`TrustServerCertificate=True` to silence a certificate error
|Fix the certificate; use the flag only for throw-away local servers.

|Connection string in source control
|Configuration, user secrets, a key vault or integrated security.

|Unbounded query bound to a grid
|Page in the query (`Skip`/`Take`); see xref:database/pagination-strategies.adoc[pagination strategies].
|===
