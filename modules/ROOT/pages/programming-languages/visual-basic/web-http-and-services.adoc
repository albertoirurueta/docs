This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Examples marked "built and
run" are complete programs that start with `Option Strict On`, were built with warnings treated as errors and were run in the
.NET 10 SDK container (Linux, arm64); the output shown is real output. No example needs the internet: every web server in this page
listens on the loopback address (port 0, so the operating system chooses a free port) or runs in memory, and the client code talks
to it inside the same process. The scratch projects had the root namespace `App`. Code that needs .NET Framework or Windows is
labelled "built, not run" and was compiled against reference assemblies on Linux; nothing more is claimed for it.

"The web" means several different things to a Visual Basic programmer, and the answer to "can I do it in VB?" changes with each.
The server side has a hard edge: *ASP.NET Web Forms and ASP.NET MVC 5 are fully supported with Visual Basic, but they run only on
.NET Framework and IIS*, and *ASP.NET Core can be written in Visual Basic by hand, but Microsoft ships no Visual Basic template for
it and the Razor view engine has no Visual Basic syntax*. The client side has no edge at all: `HttpClient`, `System.Net.Http.Json`,
the SignalR client and `ClientWebSocket` are ordinary .NET libraries that Visual Basic calls like any other. This page covers both
sides, using the *shelf* library catalogue (an ISBN lookup service and its callers) as the running example. The existing sections on
xref:web/aspnet/web-forms/index.adoc[ASP.NET Web Forms], xref:web/aspnet/mvc/index.adoc[ASP.NET MVC] and
xref:web/aspnet/core/index.adoc[ASP.NET Core] document those frameworks in depth, in C# for ASP.NET Core and in markup plus C# or VB
code-behind for the Framework stacks; this page does not repeat them, it says what is different when the language is Visual Basic.

== Web Forms and MVC 5 with Visual Basic

Web Forms and MVC 5 are the stacks where Visual Basic is a first-class language on the server. A Web Forms page is markup in an
`.aspx` file with a Visual Basic code-behind file (`Default.aspx.vb`); an MVC 5 application has controllers in `.vb` files and
views in `.vbhtml`. Both run on .NET Framework 4.8.1 under IIS, which is why they have no `net10.0` form and why the rest of this
page cannot show them running on Linux. The listing below is the code-behind of a Web Forms search page and an MVC 5 controller for
the shelf, compiled against the .NET Framework 4.8 reference assemblies (`Microsoft.NETFramework.ReferenceAssemblies`, which the SDK
adds on its own for a `net48` target) with the `Microsoft.AspNet.Mvc` 5.3.0 package. It is *built, not run*: compiling proves the
language and API shapes, not that a page renders.

.Built, not run: Web Forms code-behind and an MVC 5 controller in Visual Basic (net48)
[source,vbnet]
----
Option Strict On

Imports System.Web
Imports System.Web.Mvc
Imports System.Web.UI
Imports System.Web.UI.WebControls

' Web Forms code-behind: the .aspx markup declares the controls, this class handles the events.
Public Partial Class BookSearch
    Inherits Page

    Protected SearchBox As TextBox
    Protected ResultLabel As Label

    Protected Sub SearchButton_Click(sender As Object, e As EventArgs)
        ResultLabel.Text = "Searching for " & HttpUtility.HtmlEncode(SearchBox.Text)
        Session("LastSearch") = SearchBox.Text
    End Sub
End Class

' ASP.NET MVC 5 controller.
Public Class BooksController
    Inherits Controller

    Function Index() As ActionResult
        ViewData("Title") = "Shelf"
        Return View()
    End Function

    <HttpPost>
    <ValidateAntiForgeryToken>
    Function Lend(isbn As String) As ActionResult
        Return RedirectToAction("Index")
    End Function
End Class
----

The project file is an SDK-style `.vbproj` targeting `net48`, with `<Reference Include="System.Web" />` and the two NuGet packages.
Visual Studio's "ASP.NET Web Application (.NET Framework)" template builds the same code.

[source,text]
----
ShelfWeb -> bin/Debug/net48/ShelfWeb.dll
Build succeeded.
----

Source: https://learn.microsoft.com/aspnet/web-forms/[ASP.NET Web Forms], https://learn.microsoft.com/aspnet/mvc/[ASP.NET MVC], https://learn.microsoft.com/aspnet/overview[ASP.NET overview]

Three things are specific to Visual Basic on these stacks. First, `Handles` clauses wire events in code-behind (`+Sub Page_Load(sender As Object, e As EventArgs) Handles Me.Load+`), exactly as in Windows Forms; the markup can also name the handler (`OnClick="SearchButton_Click"`) as above, in
which case no `Handles` is written. Second, `Public Partial Class` is how the designer-generated half of a page (the `.aspx.designer.vb`
file declaring the control fields) joins the half you edit; in a hand-written class the fields are plain `Protected` members. Third,
Razor views are `.vbhtml` files with Visual Basic expressions (`+@If model IsNot Nothing Then ... End If+`); that dialect exists only
in MVC 5 and Web Pages, and was never carried to ASP.NET Core.

The web `My` objects belong to the same world. `MyType=Web` makes the compiler generate `My.User`, `My.Request`, `My.Response`,
`My.Computer` (as `ServerComputer`) and `My.Log` (as `AspLog`), all backed by `System.Web`. On .NET Framework that works; on .NET 10 it
does not. The same project property that builds on `net48`:

[source,xml]
----
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Library</OutputType>
    <TargetFramework>net48</TargetFramework>
    <MyType>Web</MyType>
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="System.Web" />
  </ItemGroup>
</Project>
----

builds there (a class using `My.User.Name` compiled, not run), while `<MyType>Web</MyType>` in a `Microsoft.NET.Sdk.Web` project that
targets `net10.0` fails with five BC30002 errors:

[source,text]
----
vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.ApplicationServices.WebUser' is not defined.
vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.Devices.ServerComputer' is not defined.
vbc : error BC30002: Type 'Global.Microsoft.VisualBasic.Logging.AspLog' is not defined.
vbc : error BC30002: Type 'Global.System.Web.HttpRequest' is not defined.
vbc : error BC30002: Type 'Global.System.Web.HttpResponse' is not defined.
----

The generated `My` code names `System.Web.HttpRequest` and friends, which do not exist on .NET 10. The other `MyType` values
(`WindowsForms`, `WindowsFormsWithCustomSubMain`, `Console`, `Empty`) are described in
xref:programming-languages/visual-basic/the-my-namespace.adoc[The My Namespace].

Session and application state are the two ideas that Classic ASP, Web Forms and ASP.NET Core share, with different mechanics:
`Session("visits")` and `Application("hits")` are dictionaries of `Object` in Classic ASP and Web Forms. ASP.NET Core splits them:
per-visitor state is the opt-in session middleware (typed accessors such as `SetInt32`), application-wide state is an ordinary
singleton or a field. The ASP.NET Core version, written in Visual Basic, is shown further down in the section on sessions.

== ASP.NET Core written in Visual Basic

ASP.NET Core is a set of ordinary .NET libraries (the `Microsoft.AspNetCore.App` shared framework), so nothing stops Visual Basic from
calling them. What is missing is everything around the libraries: `dotnet new webapi -lang VB` does not exist, and the template
engine says so:

[source,text]
----
No templates found matching: 'webapi', -lang='VB'.
Allowed values for '-lang' option are: 'C#', 'F#'.
----

Microsoft's ASP.NET Core documentation shows C# only, and the Razor compiler produces C# and skipped the Visual Basic project in the
test below. The language strategy (see
xref:programming-languages/visual-basic/history-versions-and-language-strategy.adoc[History, Versions and Language Strategy])
says that new workloads are not planned for Visual Basic, so treat what follows as supported-by-the-compiler, not supported-by-the-product.

The project file is the C# one with a `.vbproj` extension: the Web SDK works for Visual Basic. The difference that matters is that there
is *no implicit `using` list*. C# web projects get `ImplicitUsings`, a generated file of global usings for `Microsoft.AspNetCore.Builder`,
`Microsoft.AspNetCore.Http`, `Microsoft.Extensions.DependencyInjection` and others; a Visual Basic project gets none of them, so every
file imports what it needs, and a missing import shows up as BC30456 on an extension method:

[source,text]
----
error BC30456: 'UseUrls' is not a member of 'ConfigureWebHostBuilder'.
error BC30456: 'ClearProviders' is not a member of 'ILoggingBuilder'.
----

Both are extension methods whose namespaces (`Microsoft.AspNetCore.Hosting` and `Microsoft.Extensions.Logging`) were not imported.
The demonstration project used in this page has one `.vbproj` and several modules; `StartupObject` selects the program, and each
listing is complete except for the shared types, shown first:

.The scratch project used by the ASP.NET Core examples (App.vbproj)
[source,xml]
----
<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <RootNamespace>App</RootNamespace>
    <OptionStrict>On</OptionStrict>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <StartupObject>App.MinimalApiDemo</StartupObject>
  </PropertyGroup>
  <ItemGroup>

    <PackageReference Include="Microsoft.AspNetCore.SignalR.Client" Version="10.0.13" />

  </ItemGroup>

The three `+Microsoft.AspNetCore.*+` packages and the resilience package are needed only by the later examples; the minimal API itself
needs none. (When switching `StartupObject` on the command line with `-p:StartupObject=App.X`, build with `--no-incremental`: MSBuild
does not see a changed property as a reason to recompile, and the previous program runs again.)

.Built and run: the shared types (Shared.vb), used by every later ASP.NET Core listing
[source,vbnet]
----
Option Strict On

Imports Microsoft.AspNetCore.Builder
Imports Microsoft.AspNetCore.Hosting.Server
Imports Microsoft.AspNetCore.Hosting.Server.Features
Imports Microsoft.Extensions.DependencyInjection

Public Class BookDto
    Public Property Isbn As String = ""
    Public Property Title As String = ""
    Public Property Year As Integer
End Class

Public Class BookStore
    Private ReadOnly _books As New Dictionary(Of String, BookDto) From {
        {"9780306406157", New BookDto With {.Isbn = "9780306406157", .Title = "Shelf Basics", .Year = 2020}}
    }

    Public Function Find(isbn As String) As BookDto
        Dim book As BookDto = Nothing
        Return If(_books.TryGetValue(isbn, book), book, Nothing)
    End Function

    Public Sub Add(book As BookDto)
        _books(book.Isbn) = book
    End Sub

    Public Function All() As IReadOnlyList(Of BookDto)
        Return _books.Values.ToList()
    End Function
End Class

Friend Module Hosting

    ' The loopback address Kestrel picked when asked for port 0.
    Friend Function ServerAddress(app As WebApplication) As String
        Return app.Services.GetRequiredService(Of IServer)().Features.Get(Of IServerAddressesFeature)().Addresses.First()
    End Function

End Module
----

`BookDto` is a plain class with public get/set properties and a parameterless constructor, which is what the JSON binder needs;
Visual Basic has no `record`, and a `Structure` or a class with only a parameterised constructor would not bind the way a C# record
does. `Hosting.ServerAddress` reads the address Kestrel chose for port 0 from `IServerAddressesFeature`.

=== A minimal API

A minimal API maps a URL pattern and a delegate to the request pipeline. Visual Basic lambdas are the delegates. Two things differ
from the C# examples in the ASP.NET Core documentation: a multi-statement lambda is written as a `Function` block ending in `End Function`, and the `As IResult` is worth keeping, because when the branches return different result types (here
`Results.NotFound()` and `Results.Ok(book)`) an explicit return type avoids relying on type inference.

.Built and run: a minimal API with GET and POST, called through HttpClient in the same process
[source,vbnet]
----
Option Strict On

Imports System.Net.Http
Imports System.Net.Http.Json
Imports Microsoft.AspNetCore.Builder
Imports Microsoft.AspNetCore.Hosting
Imports Microsoft.AspNetCore.Http
Imports Microsoft.Extensions.DependencyInjection
Imports Microsoft.Extensions.Hosting

Module MinimalApiDemo

    Sub Main(args As String())
        RunAsync(args).GetAwaiter().GetResult()
    End Sub

    Async Function RunAsync(args As String()) As Task
        Dim builder = WebApplication.CreateBuilder(args)
        builder.WebHost.UseUrls("http://127.0.0.1:0")
        builder.Configuration("Logging:LogLevel:Default") = "None"
        builder.Services.AddSingleton(Of BookStore)()
        Dim app = builder.Build()

        app.MapGet("/books", Function(store As BookStore) store.All())
        app.MapGet("/books/{isbn}",
                   Function(isbn As String, store As BookStore) As IResult
                       Dim book As BookDto = store.Find(isbn)
                       Return If(book Is Nothing, Results.NotFound(), Results.Ok(book))
                   End Function)
        app.MapPost("/books",
                    Function(book As BookDto, store As BookStore) As IResult
                        store.Add(book)
                        Return Results.Created("/books/" & book.Isbn, book)
                    End Function)

        Await app.StartAsync()
        Dim address As String = Hosting.ServerAddress(app)
        Console.WriteLine("listening on loopback: " & address.StartsWith("http://127.0.0.1:").ToString())

        Using client As New HttpClient With {.BaseAddress = New Uri(address)}
            Dim all = Await client.GetFromJsonAsync(Of List(Of BookDto))("/books")
            Console.WriteLine("GET /books -> " & all.Count & " book(s), first = " & all(0).Title)

            Dim created = Await client.PostAsJsonAsync("/books", New BookDto With {.Isbn = "9780131103627", .Title = "Types and Tables", .Year = 1988})
            Console.WriteLine("POST /books -> " & CInt(created.StatusCode) & " " & created.StatusCode.ToString() & ", Location = " & created.Headers.Location.ToString())

            Dim found = Await client.GetAsync("/books/9780131103627")
            Console.WriteLine("GET known -> " & CInt(found.StatusCode) & " " & Await found.Content.ReadAsStringAsync())

            Dim missing = Await client.GetAsync("/books/0000000000000")
            Console.WriteLine("GET unknown -> " & CInt(missing.StatusCode) & " " & missing.StatusCode.ToString())
        End Using

        Await app.StopAsync()
    End Function

End Module
----

[source,text]
----
listening on loopback: True
GET /books -> 1 book(s), first = Shelf Basics
POST /books -> 201 Created, Location = /books/9780131103627
GET known -> 200 {"isbn":"9780131103627","title":"Types and Tables","year":1988}
GET unknown -> 404 NotFound
----

Source: https://learn.microsoft.com/aspnet/core/fundamentals/minimal-apis[Minimal APIs overview]

Notes on the listing. `WebApplication.CreateBuilder(args)` and `builder.Build()` are the same calls as in C#. `app.StartAsync()`
(rather than `app.Run()`) starts Kestrel without blocking so that the program can drive it; a real service ends `Main` with
`app.Run()`. The entry point is a synchronous `Sub Main` that waits on an `Async Function`, because the language has no `Async Main`
(declaring one fails with BC30737, see the pitfalls below). `Configuration("Logging:LogLevel:Default") = "None"` silences the
request log so that the output stays readable; `ClearProviders()` would need `Imports Microsoft.Extensions.Logging`, and that import
makes the name `Console` bind to the namespace `Microsoft.Extensions.Logging.Console` (BC30456 on every `Console.WriteLine`), which is
why the listing uses configuration instead. If you do need the logging import, put it in a file that does not print.

=== Controllers

Web API controllers are classes decorated with attributes, which Visual Basic writes with angle brackets and line continuation
inside the brackets as usual. The action methods are `Function`s; `ActionResult(Of BookDto)` is `ActionResult<BookDto>`, and returning
a `BookDto` where an `ActionResult(Of BookDto)` is expected works through the implicit conversion that the type defines (Visual Basic
accepts the widening conversion without a cast). Validation attributes on the model class give the automatic `400
application/problem+json` response of `[ApiController]`.

.Built and run: a controller with model validation, called in the same process
[source,vbnet]
----
Option Strict On

Imports System.ComponentModel.DataAnnotations
Imports System.Net.Http
Imports System.Net.Http.Json
Imports System.Text.Json
Imports Microsoft.AspNetCore.Builder
Imports Microsoft.AspNetCore.Hosting
Imports Microsoft.AspNetCore.Http
Imports Microsoft.AspNetCore.Mvc
Imports Microsoft.Extensions.Configuration
Imports Microsoft.Extensions.DependencyInjection
Imports Microsoft.Extensions.Hosting

Public Class NewBook
    <Required, StringLength(13, MinimumLength:=10)>
    Public Property Isbn As String = ""

    <Required>
    Public Property Title As String = ""

    <Range(1450, 2100)>
    Public Property Year As Integer
End Class

<ApiController>
<Route("api/[controller]")>
Public Class BooksController
    Inherits ControllerBase

    Private ReadOnly _store As BookStore

    Public Sub New(store As BookStore)
        _store = store
    End Sub

    <HttpGet>
    Public Function GetAll() As IEnumerable(Of BookDto)
        Return _store.All()
    End Function

    <HttpGet("{isbn}")>
    Public Function GetOne(isbn As String) As ActionResult(Of BookDto)
        Dim book As BookDto = _store.Find(isbn)
        If book Is Nothing Then
            Return NotFound()
        End If
        Return book
    End Function

    <HttpPost>
    Public Function Create(newBook As NewBook) As ActionResult(Of BookDto)
        Dim book As New BookDto With {.Isbn = newBook.Isbn, .Title = newBook.Title, .Year = newBook.Year}
        _store.Add(book)
        Return CreatedAtAction(NameOf(GetOne), New With {.isbn = book.Isbn}, book)
    End Function
End Class

Module ControllersDemo

    Sub Main(args As String())
        RunAsync(args).GetAwaiter().GetResult()
    End Sub

    Async Function RunAsync(args As String()) As Task
        Dim builder = WebApplication.CreateBuilder(args)
        builder.WebHost.UseUrls("http://127.0.0.1:0")
        builder.Configuration("Logging:LogLevel:Default") = "None"
        builder.Services.AddSingleton(Of BookStore)()
        builder.Services.AddControllers()
        Dim app = builder.Build()
        app.MapControllers()
        Await app.StartAsync()

        Using client As New HttpClient With {.BaseAddress = New Uri(Hosting.ServerAddress(app))}
            Dim all = Await client.GetFromJsonAsync(Of List(Of BookDto))("/api/books")
            Console.WriteLine("GET /api/books -> " & all.Count & " book(s)")

            Dim ok = Await client.PostAsJsonAsync("/api/books", New NewBook With {.Isbn = "9780131103627", .Title = "Types and Tables", .Year = 1988})
            Console.WriteLine("POST valid -> " & CInt(ok.StatusCode) & ", Location = " & ok.Headers.Location.AbsolutePath)

            Dim bad = Await client.PostAsJsonAsync("/api/books", New NewBook With {.Isbn = "123", .Title = "", .Year = 3000})
            Console.WriteLine("POST invalid -> " & CInt(bad.StatusCode) & " " & bad.Content.Headers.ContentType.MediaType)
            Using problem As JsonDocument = JsonDocument.Parse(Await bad.Content.ReadAsStringAsync())
                Console.WriteLine(problem.RootElement.GetProperty("title").GetString())
                For Each field In problem.RootElement.GetProperty("errors").EnumerateObject().OrderBy(Function(p) p.Name)
                    Console.WriteLine("  " & field.Name & ": " & field.Value(0).GetString())
                Next
            End Using

            Dim missing = Await client.GetAsync("/api/books/0000000000000")
            Console.WriteLine("GET unknown -> " & CInt(missing.StatusCode))
        End Using
        Await app.StopAsync()
    End Function

End Module
----

----
GET /api/books -> 1 book(s)
POST valid -> 201, Location = /api/Books/9780131103627
POST invalid -> 400 application/problem+json
One or more validation errors occurred.
  Isbn: The field Isbn must be a string with a minimum length of 10 and a maximum length of 13.

Visual Basic specifics visible here. The attribute argument `"api/[controller]"` is just a string; `NameOf(GetOne)` works as in
C#; the anonymous type `+New With {.isbn = book.Isbn}+` supplies route values to `CreatedAtAction`; and the controller is discovered
because it is `Public` and declared at namespace level in the entry assembly (a `Public Class` nested inside a default `Friend Module`
is not visible outside the assembly, because its container is `Friend`; the same rule makes `XmlSerializer` fail on such a class). The
`Location` header reads `+/api/Books/...+` with a capital `B`: the `[controller]` token takes the class name without the `Controller`
suffix as written, so the casing of the class name appears in the URL, and URLs are case-insensitive in ASP.NET Core routing.

=== Handlers, attributes and the places where Visual Basic differs

The delegate-based API is where the language shows. These are the four things a C# example in the documentation does that a
Visual Basic program cannot, with the real compiler messages and the working replacement for each.

*1. A method group does not convert to `Delegate`.* `MapGet` takes a `Delegate` (and a `RequestDelegate`). C# converts a method
group to a delegate type it infers; Visual Basic's `AddressOf` needs a concrete delegate type to convert to:

[source,vbnet]
----
app.MapGet("/hello/{name}", AddressOf Hello)
----

[source,text]
----
Program.vb(14,13): error BC30518: Overload resolution failed because no accessible 'MapGet' can be called with these arguments:
----

Wrap the method in the delegate type that matches it: `New Func(Of String, IResult)(AddressOf Hello)`.

*2. No attributes on lambda parameters.* C# writes `+([FromQuery(Name = "q")] string term) => term+`. Visual Basic forbids attributes
on lambda parameters:

[source,vbnet]
----
app.MapGet("/search", Function(<FromQuery(Name:="q")> term As String) term)
----

[source,text]
----
Program.vb(10,40): error BC36634: Attributes cannot be applied to parameters of lambda expressions.
----

Put the attributes on a named method's parameters (allowed) and pass the method in a `Func`, as the listing below does, or bind a
whole parameter object with `<AsParameters>`.

*3. No `Optional` lambda parameters.* C# lambdas can have default values (`+(int page = 1) => ...+`); Visual Basic cannot:

[source,vbnet]
----
app.MapGet("/page", Function(Optional page As Integer = 1) page.ToString())
----

[source,text]
----
Program.vb(9,38): error BC33010: 'Lambda' parameters cannot be declared 'Optional'.
----

Use a named method with `Optional`, a nullable parameter (`page As Integer?`) or a property with a default in an `<AsParameters>` class.

=== Middleware, dependency injection and options

The pipeline is configured with `+app.Use...+`. An inline middleware is a lambda taking `HttpContext` and the next step. Spelling out
the parameter types, as below, selects the `Func(Of Task)` form unambiguously and reads better than untyped parameters. A
convention-based middleware class (a constructor taking `RequestDelegate` and an `InvokeAsync` method whose other parameters come from
dependency injection) needs `[next]` in brackets because `Next` is a Visual Basic keyword. Options bind configuration sections to a
class with `Configure(Of T)`; note that the property initialisers give the defaults.

=== Sessions and application state

The Classic ASP and Web Forms idioms `Session("visits")` and `Application("hits")` map to the session middleware and to a singleton (or,
as below, a captured variable). The session needs `AddDistributedMemoryCache()` and `AddSession()` registered and `UseSession()` in the
pipeline; the accessors `GetInt32` and `SetInt32` are extension methods in `Microsoft.AspNetCore.Http`. `If(a, b)` is the Visual Basic
replacement for C# `??` (the language has no `??`): `GetInt32` returns `Integer?`, and `If(x, 0)` supplies the default.

.Built and run: per-visitor session state and application-wide state
[source,vbnet]
----
Option Strict On

Imports Microsoft.AspNetCore.Builder
Imports Microsoft.AspNetCore.Hosting
Imports Microsoft.AspNetCore.Http

Imports Microsoft.Extensions.DependencyInjection
Imports Microsoft.Extensions.Hosting

        Await app.StartAsync()

            Console.WriteLine("ada:   " & Await ada.GetStringAsync("/visit"))
            Console.WriteLine("ada:   " & Await ada.GetStringAsync("/visit"))
            Console.WriteLine("grace: " & Await grace.GetStringAsync("/visit"))
            Console.WriteLine("ada:   " & Await ada.GetStringAsync("/visit"))
        End Using
        Await app.StopAsync()
    End Function

End Module

real deployment uses a distributed cache. The lambda captures the local `hits`, which is shared state mutated from several requests:
use `Interlocked` or a lock in real code.

=== OpenAPI

`AddOpenApi()` and `MapOpenApi()` (from the `Microsoft.AspNetCore.OpenApi` package) generate an OpenAPI 3.1 document at runtime
from the endpoint metadata. They work from Visual Basic. The output lists the two routes and the `BookDto` schema with its camelCase
property names. Two limits apply: lambda parameters carry no attributes in Visual Basic (see above), so richer metadata
comes from `+.WithName(...)+` and the `Produces` methods on the endpoint, not from attributes; and the package's integration with XML
documentation comments is implemented as a source generator, which was not tested from Visual Basic.

== A Visual Basic library behind a C# ASP.NET Core host

This is the pattern to prefer when the host needs Razor, Blazor, OpenAPI source generation or Native AOT. The domain (the catalogue
rules, validation, calculations) lives in a Visual Basic class library, and a C# project references it and exposes it. Nothing about
the library knows it is behind a web host. The C# host below was run with `dotnet run` and calls its own endpoints:

    Lent
    AlreadyOnLoan
    UnknownBook

    Public Property Title As String = ""
    Public Property OnLoan As Boolean

Public Class CatalogService
    Private ReadOnly _books As New Dictionary(Of String, Book)

        Dim book As Book = Nothing

        Dim book As Book = Find(isbn)
        If book Is Nothing Then Return LoanOutcome.UnknownBook
        If book.OnLoan Then Return LoanOutcome.AlreadyOnLoan
        book.OnLoan = True
        Return LoanOutcome.Lent
    End Function

== HTTP clients

An HTTP client is the part of the web story with no Visual Basic caveats. `HttpClient` is the only class to use; `WebClient`,
`HttpWebRequest` and `WebRequest` are obsolete (the diagnostic is SYSLIB0014, shown below). The shelf's ISBN lookup is the running
example: `IsbnClient` wraps one `HttpClient`, converts a `404` into `Nothing`, turns other failures into exceptions, and passes a
`CancellationToken` through.

.Built and run: a typed ISBN client, errors, cancellation and timeout (the service is a local Kestrel)

Public NotInheritable Class IsbnClient

    Public Sub New(http As HttpClient)

    End Sub

    Public Async Function FindAsync(isbn As String, cancellationToken As CancellationToken) As Task(Of BookDto)
        Using response As HttpResponseMessage = Await _http.GetAsync("isbn/" & isbn, cancellationToken)
            If response.StatusCode = HttpStatusCode.NotFound Then
                Return Nothing
            End If
            response.EnsureSuccessStatusCode()
            Return Await response.Content.ReadFromJsonAsync(Of BookDto)(cancellationToken)
        End Using
    End Function

    Public Async Function AddAsync(book As BookDto, cancellationToken As CancellationToken) As Task(Of String)
        Using response As HttpResponseMessage = Await _http.PostAsJsonAsync("isbn", book, cancellationToken)
            response.EnsureSuccessStatusCode()
            Return response.Headers.Location.ToString()
        End Using
    End Function

Rules shown or implied by the listing:

* *One `HttpClient` for the life of the program* (or one per named/typed client from the factory), not one per request: each instance
holds a connection pool, and creating many exhausts sockets. Dispose it with `Using` only when you really own the lifetime.
* *`BaseAddress` needs a trailing slash* when the relative paths have no leading slash (`+"isbn/..."+`): `http://host/api` plus
`"isbn/1"` resolves to `http://host/isbn/1`, dropping `api`. The listing appends `"/"`.
* *`GetFromJsonAsync(Of T)`, `PostAsJsonAsync` and `ReadFromJsonAsync(Of T)`* (namespace `System.Net.Http.Json`) replace the
manual `ReadAsStringAsync` plus `JsonSerializer.Deserialize` pair; they use the web defaults (camelCase, case-insensitive on read).
They are reflection-based, so a trimmed or AOT application needs a source-generated context (a C# helper project; see the
xref:programming-languages/visual-basic/serialization-json-and-xml.adoc[Serialization, JSON and XML] page).
* *`EnsureSuccessStatusCode()`* throws `HttpRequestException` whose `StatusCode` property carries the code (`ServiceUnavailable` above).
Decide per call whether a `404` is an error (here it is a normal "not found" result).
* *Cancellation and timeouts both surface as `TaskCanceledException`* (a subclass of `OperationCanceledException`). The
`HttpClient.Timeout` expiry carries a `TimeoutException` as its inner exception, as the last line of the output shows; that is how to
tell it from a cancellation by your own token. `Timeout` is set once, before the first request: changing it afterwards throws
`InvalidOperationException`.
* *Async is the rule*: see xref:programming-languages/visual-basic/async-and-await.adoc[Async and Await]; do not call `.Result` or
`.GetAwaiter().GetResult()` on a UI thread.

The obsolete classes still compile on .NET 10, but every use is reported as warning SYSLIB0014, which becomes an error under
`TreatWarningsAsErrors`. Creating a `WebClient` with `New`, or calling `WebRequest.Create` or `HttpWebRequest.Create`, each
produces a diagnostic of this form:

[source,text]
----

----

Source: https://learn.microsoft.com/dotnet/fundamentals/syslib-diagnostics/syslib0014[SYSLIB0014: WebRequest, HttpWebRequest, ServicePoint, and WebClient are obsolete]

This applies to every book example that downloads with `WebClient.DownloadString` or builds a request with

=== IHttpClientFactory, typed clients and resilience

In a Generic Host or ASP.NET Core application, `IHttpClientFactory` manages the handler lifetimes and offers typed clients: a class
that receives an `HttpClient` in its constructor, registered with `AddHttpClient(Of TClient)`. Message handlers (the HttpClient
pipeline's middleware) are added in registration order. `Microsoft.Extensions.Http.Resilience` adds `AddStandardResilienceHandler`
(retry, circuit breaker, timeouts) in one call. The program below plays a service that fails twice with `503` and then answers; the
client retries.

.Built and run: a typed client, a counting handler and the standard resilience handler against a flaky service
[source,vbnet]
----
Option Strict On

Imports System.Net
Imports System.Net.Http
Imports System.Net.Sockets
Imports System.Threading
Imports Microsoft.AspNetCore.Builder
Imports Microsoft.AspNetCore.Hosting
Imports Microsoft.AspNetCore.Http
Imports Microsoft.Extensions.Configuration
Imports Microsoft.Extensions.DependencyInjection
Imports Microsoft.Extensions.Hosting

' A DelegatingHandler is the HttpClient pipeline's middleware.
Public NotInheritable Class CountingHandler
    Inherits DelegatingHandler

    Public Shared Attempts As Integer

    Protected Overrides Async Function SendAsync(request As HttpRequestMessage,
                                                 cancellationToken As CancellationToken) As Task(Of HttpResponseMessage)
        Dim n As Integer = Interlocked.Increment(Attempts)
        Dim response As HttpResponseMessage = Await MyBase.SendAsync(request, cancellationToken)
        Console.WriteLine("  attempt " & n & " -> " & CInt(response.StatusCode))
        Return response
    End Function
End Class

Public NotInheritable Class ShelfApiClient
    Private ReadOnly _http As HttpClient

    Public Sub New(http As HttpClient)
        _http = http
    End Sub

    Public Function GetTitleAsync() As Task(Of String)
        Return _http.GetStringAsync("title")
    End Function
End Class

Module FactoryDemo

    Private Function FreePort() As Integer
        Dim listener As New TcpListener(IPAddress.Loopback, 0)
        listener.Start()
        Dim port As Integer = CType(listener.LocalEndpoint, IPEndPoint).Port
        listener.Stop()
        Return port
    End Function

    Sub Main(args As String())
        RunAsync(args).GetAwaiter().GetResult()
    End Sub

    Async Function RunAsync(args As String()) As Task
        Dim port As Integer = FreePort()

        ' The flaky service: the first two calls answer 503, the third succeeds.
        Dim serverBuilder = WebApplication.CreateBuilder(args)
        serverBuilder.WebHost.UseUrls("http://127.0.0.1:" & port)
        serverBuilder.Configuration("Logging:LogLevel:Default") = "None"
        Dim server = serverBuilder.Build()
        Dim calls As Integer = 0
        server.MapGet("/title",
                      Function() As IResult
                          calls += 1
                          Return If(calls < 3, Results.StatusCode(503), Results.Text("Shelf Basics"))
                      End Function)
        Await server.StartAsync()

        ' The client side: Generic Host, typed client, resilience handler.
        Dim builder = Host.CreateApplicationBuilder(args)
        builder.Configuration("Logging:LogLevel:Default") = "None"
        builder.Services.AddTransient(Of CountingHandler)()
        Dim clientBuilder = builder.Services.AddHttpClient(Of ShelfApiClient)(
            Sub(client) client.BaseAddress = New Uri("http://127.0.0.1:" & port & "/"))
        ' Handlers run in registration order: the resilience handler first, so the counting handler sees every attempt.
        clientBuilder.AddStandardResilienceHandler(
            Sub(options)
                options.Retry.MaxRetryAttempts = 3
                options.Retry.Delay = TimeSpan.FromMilliseconds(20)
                options.Retry.UseJitter = False
            End Sub)
        clientBuilder.AddHttpMessageHandler(Of CountingHandler)()
        Using host As IHost = builder.Build()
            Dim api = host.Services.GetRequiredService(Of ShelfApiClient)()
            Console.WriteLine("title: " & Await api.GetTitleAsync())
        End Using
        Await server.StopAsync()
    End Function

End Module

Visual Basic points. A handler subclass overrides `SendAsync` with an `Async Function` declared `Protected Overrides` and returning `Task(Of HttpResponseMessage)`; the base call is `MyBase.SendAsync`. The builder calls are made as separate statements on the
`IHttpClientBuilder` because the order of registration is the order of execution, and the resilience handler is registered *before*
the counting handler so that the counter sits inside the retry loop and sees all three attempts (registered the other way round it would
count once). `+AddHttpClient(Of ShelfApiClient)(Sub(client) ...)+` takes a `Sub` lambda; `+options.Retry.Delay = ...+` inside a `Sub` lambda
is an assignment statement and needs no `Return`. The defaults of the standard handler are tuned for production; the listing shortens the retry delay and turns jitter off
so that the run is quick and repeatable. `Host.CreateApplicationBuilder(args)` is the
non-web host builder (no Kestrel); it needs no `Imports` beyond `Microsoft.Extensions.Hosting`.

== SignalR and WebSocket clients

The SignalR .NET client (`Microsoft.AspNetCore.SignalR.Client`) is a library. The pieces to get right in Visual Basic: handlers are
registered with `+connection.On(Of T1, T2)("Method", Sub(a, b) ...)+` before `StartAsync`, a `Sub` lambda is the
`Action<T1, T2>` overload (an `Async Function` lambda would bind the `Func<T1, T2, Task>` overload), `InvokeAsync` calls a hub
method by name, and a connection is released with `Await connection.DisposeAsync()` because Visual Basic has no `Await Using`. The
program hosts the hub and a raw WebSocket endpoint and calls both from clients.

== SOAP and WCF clients

The books show "Add Service Reference" wizards and `ASMX` proxies. On .NET 10 the equivalents are the WCF client libraries
(`System.ServiceModel.Http` and `System.ServiceModel.Primitives`) plus `dotnet-svcutil`, a command-line tool that reads a WSDL and
writes the client code. The tool runs for Visual Basic projects but *wrote C#* in the test: it produced `ServiceReference1/Reference.cs`
next to a `.vbproj` and did not touch the project, because a Visual Basic project cannot compile a `.cs` file. The practical pattern
is to compile the generated file in a small C# library and reference it from Visual Basic.

To test this without an external service the example hosts a SOAP service with CoreWCF (an open-source server-side port of WCF) in a
Visual Basic ASP.NET Core application, then generates a proxy from its WSDL and calls it. The server, built and run on port 5080:

== gRPC and other protocols

== Differences from C#

[cols="2,3,3",options="header"]
|===
|Topic |C# |Visual Basic

|Web templates
|`webapi`, `web`, `blazor`, `grpc`, `worker` and more for `+-lang C#+`.
|None for ASP.NET Core; Visual Studio keeps Web Forms and MVC 5 templates for .NET Framework.

|Implicit usings
|`ImplicitUsings` adds ASP.NET Core namespaces.
|Not applied; import every namespace (extension methods fail with BC30456).

|Method group as a handler
|`app.MapGet("/x", Handlers.Get)`
|`+New Func(Of ..., ...)(AddressOf Handlers.Get)+`; a bare `AddressOf` fails with BC30518.

|Attributes on handler parameters
|`+([FromQuery] string q) => ...+`
|Not on lambdas (BC36634); use a named method or `<AsParameters>`.

|Default values in lambdas
|`+(int page = 1) => ...+`
|`Optional` is not allowed on lambda parameters (BC33010).

|Async handlers
|`+async () => "x"+` works as a delegate.
|Type the lambda as `Func(Of Task(Of String))` first; an untyped one returned an empty body in the test.

|Async filters
|`async ValueTask<object?>` methods.
|An `Async Function` cannot return `ValueTask` (BC36945); wrap a `Task` in `+New ValueTask(Of Object)(...)+`.

|Entry point
|Top-level statements, `await app.RunAsync()`.
|`Sub Main` that waits on an `Async Function`; no `Async Main` (BC30737).

|Models
|`record`, `required`, primary constructors.
|Classes with auto-properties and a parameterless constructor.

|`??`
|`session.GetInt32("k") ?? 0`
|`If(session.GetInt32("k"), 0)`.

|Views
|Razor Pages, MVC views, Blazor.
|Not available; `.cshtml` and `.razor` are ignored. `.vbhtml` exists only in MVC 5 and Web Pages.

|Source generators (request delegates, JSON, OpenAPI comments)
|Run and are what enable Native AOT for ASP.NET Core.
|The `System.Text.Json` generator needs a C# helper project (see the serialization page); the others were not tested; the examples use reflection.

== Pitfalls

* *An Async Main does not exist.* `Async Function Main(args As String()) As Task` fails with `BC30737: No accessible 'Main' method
with an appropriate signature was found in 'App'`. Use `Sub Main` and wait: `RunAsync(args).GetAwaiter().GetResult()`.
* *Changing `StartupObject` on the command line without `--no-incremental`* re-runs the previous program.
* *A local named after a child namespace* (`schema` with `Imports System.Text.Json`, `text` with `Imports System`) hides or is hidden
by the namespace, because Visual Basic names are case-insensitive.
* *`Imports Microsoft.Extensions.Logging` breaks `Console.WriteLine`* in the same file (BC30456): qualify as `System.Console` or keep
that import in another file.
* *`Public` is required for controllers, hubs and DTOs*; a type declared in a default `Friend Module` is `Friend` and invisible to
discovery and to the JSON serialisers.
* *A lambda passed where a `Delegate` is expected becomes a compiler-generated `VB$AnonymousDelegate` type*: give the handler a
real delegate type when its return type matters (async handlers).
* *Do not trust a build for a view layer*: `.cshtml`/`.razor` files in a VB project compile to nothing.
* *Security*: the shelf examples are demonstrations. Real services need authentication, authorization and hardened headers; see
xref:web/aspnet/core/authentication-and-identity.adoc[Authentication and Identity] and
xref:web/aspnet/core/security-hardening.adoc[Security Hardening]. SQL access from a handler is in
xref:programming-languages/visual-basic/data-access-ado-net-and-ef-core.adoc[Data Access: ADO.NET and EF Core]; secrets and
cryptography are in xref:programming-languages/visual-basic/security-and-cryptography.adoc[Security and Cryptography].

== Version notes

* Visual Basic 11 (Visual Studio 2012) introduced `Async`/`Await`; everything on the client side of this page needs that or later.
* The `If(a, b)` null-coalescing operator arrived in Visual Basic 9 (Visual Studio 2008).
* ASP.NET Core minimal APIs (`WebApplication.CreateBuilder`) arrived with .NET 6. `AddOpenApi()` (the in-box OpenAPI document
generator) arrived with .NET 9; the examples here target .NET 10.
* SYSLIB0014 was added in .NET 6.
