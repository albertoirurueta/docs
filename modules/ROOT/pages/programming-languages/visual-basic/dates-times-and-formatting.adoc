Dates and numbers are the two kinds of value whose text form depends on who is looking: the same `DateTime` is `1/5/2026` in the United States, `05.01.2026` in Germany and `2026/01/05` in Japan, and the same
`Decimal` has a comma or a point as its decimal separator. Visual Basic adds its own layer to the .NET types: the `Date` keyword with its `+#...#+` literals, the `DateAndTime` module that carries the VB6 date functions, and the `Format` family
of functions. This page explains the .NET date and time types as a VB programmer sees them, the VB functions and where they differ from the methods, the culture rules for parsing and formatting, and the format strings for both dates and numbers.
It was written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and checked on 2026-10-19. Every program was built with `Option Strict On` and `TreatWarningsAsErrors` and run in a Linux container, where the current culture is the invariant culture
and the time zone is UTC; programs that depend on a culture set it explicitly, and programs with dates avoid `Now` unless the output does not depend on it. The page on
xref:programming-languages/visual-basic/numbers-and-math.adoc[Numbers and Math] covers the arithmetic, rounding and the `Math` class, and
xref:programming-languages/visual-basic/strings-and-text.adoc[Strings and Text] covers composite formatting, interpolation basics and culture-sensitive comparison.

== The Date type and date literals

`Date` is the Visual Basic keyword for `System.DateTime`: a value type holding the number of 100-nanosecond ticks since midnight on 1 January 0001 in the proleptic Gregorian calendar, up to 31 December 9999, plus a `Kind` that records
whether the value is meant as local time, UTC, or unspecified. There is no time-zone information in a `Date`, and comparisons and arithmetic ignore `Kind`. The default value, `Nothing` or `Date.MinValue`, is 1 January 0001; a missing date needs `Date?`
(see xref:programming-languages/visual-basic/nothing-and-nullable-value-types.adoc[Nothing and Nullable Value Types]).

A *date literal* is enclosed in number signs and is always written in a culture-independent form, so a program compiles the same on every machine: the US form `+#1/15/2026#+` (month first) or the ISO-like form `+#2026-01-15#+`, optionally followed by a time in 12-hour
(`3:45:30 PM`) or 24-hour (`15:45:30`) notation. The literal has no fractional seconds (`+#2026-01-05 15:04:09.123#+` is BC30201 plus BC31085, "Date constant is not valid"): for milliseconds, call `New Date(2026, 1, 5, 15, 4, 9, 123)`. A literal is a `Date` only: there is no literal for `DateOnly`, `TimeOnly` or
`DateTimeOffset` (`+Dim o As DateOnly = #1/15/2026#+` is BC30311), which are built with constructors or conversions.

Things the program shows, and some related rules:

* `New Date(y, m, d)` throws `ArgumentOutOfRangeException` for an impossible date; `DateSerial(y, m, d)` is lenient and rolls over (`DateSerial(2026, 2, 31)` is 3 March) and `TimeSerial(25, 0, 0)` returns a `Date` on 1 January 0001 plus
  one day and one hour. Use the constructor when the input should be valid.
* `Year(d)`, `Month(d)`, `Day(d)`, `Hour(d)`, `Minute(d)`, `Second(d)` and `Weekday(d)` are the VB functions, and `d.Year`, `d.Month`, `d.DayOfWeek`... the properties. `Weekday` returns 1 for Sunday (and 5 for Thursday) by default, `DayOfWeek` is the 0-based
  `DayOfWeek` enumeration (Sunday = 0): the numbers differ by one.
* The `-` operator on two dates returns a `TimeSpan`; there is no `pass:c[+]` between `Date` and a number. Visual Basic 6 stored dates as a `Double` and let you write `pass:c[d + 1]`, `.NET` does not: `pass:c[d + 1]` is BC30452 ("Operator `pass:c[+]` is not defined for types `Date` and `Integer`"), and
  `CDbl(d)` is BC30532 ("requires calling the `Date.ToOADate` method"). Use `d.AddDays(1)`, `DateAdd(DateInterval.Day, 1, d)` or `pass:c[d + TimeSpan.FromDays(1)]`. `ToOADate` and `Date.FromOADate` convert to and from the VB6/VBA/Excel serial number when you need it.
* `Now` (the property of the `DateAndTime` module), `Date.Now` and `DateTime.Now` return the local time (`Kind` = Local); `Today` and `Date.Today` the local date at midnight; `Date.UtcNow` the current UTC instant. `TimeOfDay`, `TimeString`, `DateString` and `Timer`
  (seconds since midnight, as a `Double`) are legacy VB properties. Prefer `DateTime.UtcNow` or an injected `TimeProvider` for anything stored or compared.
* A date has 100 ns resolution (`TimeSpan.TicksPerSecond` = 10,000,000) but the system clock ticks coarsely, and `Now` is not a stopwatch: use `Stopwatch` or `TimeProvider.GetTimestamp` to measure durations.
* Two-digit years follow the calendar's `TwoDigitYearMax`, 2049 for the default Gregorian calendar: `Date.Parse("1/1/49")` is 2049 and `Date.Parse("1/1/50")` is 1950 (checked). Never accept two-digit years from an external source.

== The DateAndTime module and the DateTime members

The VB6 date functions live in `Microsoft.VisualBasic.DateAndTime` and are always in scope. Each has a .NET counterpart; the table shows how they differ.

[cols="2,2,3",options="header"]
|===
|VB function |.NET counterpart |Notes
|`DateAdd(interval, n, d)` |`d.AddYears`, `AddMonths`, `AddDays`, `AddHours`... |`DateInterval` has `Year`, `Quarter`, `Month`, `DayOfYear`, `Day`, `Weekday`, `WeekOfYear`, `Hour`, `Minute`, `Second`. `Weekday` adds calendar days, not working days. Month arithmetic
clamps to the end of the shorter month, as `AddMonths` does: 31 January plus one month is 28 February
|`DateDiff(interval, d1, d2)` |`(d2 - d1).TotalDays`... |Not simply the elapsed time: see below
|`DatePart(interval, d)` |`d.Year`, `Calendar.GetWeekOfYear`... |`DatePart(DateInterval.WeekOfYear, d)` depends on `FirstDayOfWeek` and `FirstWeekOfYear` arguments (the defaults are Sunday and the week that contains 1 January); `ISOWeek.GetWeekOfYear` gives the ISO 8601 week
|`DateSerial(y, m, d)`, `TimeSerial(h, m, s)` |`+New Date(...)+`, `+New TimeSpan(...)+` |Lenient: out-of-range values roll over
|`DateValue(text)`, `TimeValue(text)`, `CDate(text)` |`Date.Parse`, `DateOnly.Parse`, `TimeOnly.Parse` |Parse with the *current culture* of the thread; see the next sections
|`IsDate(text)` |`Date.TryParse` |`True` for text that the current culture parses; `IsDate("2026-02-30")` is `False`
|`Weekday(d)`, `WeekdayName(n)`, `MonthName(n)` |`d.DayOfWeek`, `d.ToString("dddd")`, `CultureInfo.DateTimeFormat.GetMonthName` |Names come from the current culture; the week of `Weekday` starts on Sunday unless `FirstDayOfWeek` says otherwise
|`Year`, `Month`, `Day`, `Hour`, `Minute`, `Second` |`d.Year`... |Inside a class that has a member with one of these names (such as the `CatalogItem.Year` property), the member hides the function; qualify it as `+DateAndTime.Year(d)+`
|`Now`, `Today`, `TimeOfDay`, `Timer` |`Date.Now`, `Date.Today`, `d.TimeOfDay`, `Stopwatch` |Same values; `Timer` is a `Double` number of seconds since midnight
|===

*DateDiff is not elapsed time.* The Language Reference describes `DateDiff` as counting the interval boundaries crossed. On .NET 10 the program shows that this is only true for `Year`, `Quarter` and `Month`: from 31 December 23:59 to 1 January 00:01 the result is 1 for years and months. The other intervals
return the number of whole elapsed units (truncated), so the same two moments are 0 days apart, and a Saturday-to-Sunday step shows 0 `WeekOfYear` boundaries. Know which semantics you need: for "how many calendar months are between these dates" use `+DateDiff(DateInterval.Month, ...)+` or
`pass:c[(d2.Year - d1.Year) * 12 + d2.Month - d1.Month]`; for "how long" use `d2 - d1`. Age is not a `+DateDiff(Year, ...)+`: it is a year count corrected for whether the birthday has happened (`Age` in the program).

== Beyond Date: DateTimeOffset, DateOnly, TimeOnly, TimeSpan and time zones

`Date` is a fine type for a local timestamp and a poor one for an instant, a calendar day or a time of day. .NET offers purpose-built types, and VB uses them like any other value type (without literals):

[cols="2,3,3",options="header"]
|===
|Type |Represents |Use for
|`DateTimeOffset` |An instant plus its UTC offset |Anything that crosses machines or time zones: audit stamps, due times stored in a database, API payloads
|`DateOnly` (.NET 6) |A calendar day, no time |Birth dates, due dates, holidays. Its `DayNumber` makes day counts exact
|`TimeOnly` (.NET 6) |A time of day on a 24-hour clock, with wrap-around arithmetic |Opening hours, alarm times
|`TimeSpan` |A duration (ticks) |Differences, timeouts, intervals. `TotalDays` is a `Double`, `Days` the whole days component
|`TimeZoneInfo` |A time zone with its rules |Converting an instant to local time, finding DST gaps and overlaps
|`TimeProvider` (.NET 8) |A source of "now" and of timestamps |Injecting a clock into a class so it can be tested
|===

        ' DateTime.Kind says what an instance means; arithmetic ignores it.
        Dim utc As Date = DateTime.SpecifyKind(#2026-07-01 12:00:00#, DateTimeKind.Utc)
        Dim unspecified As Date = #2026-07-01 12:00:00#
        Console.WriteLine($"Kinds: {utc.Kind}, {unspecified.Kind}; equal: {utc = unspecified}")

        Dim madrid = TimeZoneInfo.FindSystemTimeZoneById("Europe/Madrid")
        Dim local = TimeZoneInfo.ConvertTimeFromUtc(utc, madrid)
        Console.WriteLine($"UTC {utc:HH:mm} is {local:HH:mm} in Madrid (offset {madrid.GetUtcOffset(utc)}, DST: {madrid.IsDaylightSavingTime(utc)})")
        Dim winter = TimeZoneInfo.ConvertTimeFromUtc(DateTime.SpecifyKind(#2026-01-15 12:00:00#, DateTimeKind.Utc), madrid)
        Console.WriteLine($"In January the same UTC time is {winter:HH:mm}")

        ' DateTimeOffset keeps the offset with the instant.
        Dim stamp As New DateTimeOffset(2026, 7, 1, 14, 0, 0, TimeSpan.FromHours(2))
        Console.WriteLine($"Offset: {stamp:yyyy-MM-dd HH:mmzzz}; UtcDateTime: {stamp.UtcDateTime:HH:mm}; equal to the UTC instant: {stamp = New DateTimeOffset(utc)}")
        Console.WriteLine($"Unix seconds: {stamp.ToUnixTimeSeconds()}")
        Console.WriteLine($"In Tokyo: {TimeZoneInfo.ConvertTime(stamp, TimeZoneInfo.FindSystemTimeZoneById("Asia/Tokyo")):yyyy-MM-dd HH:mmzzz}")

        ' Daylight-saving transitions
        Dim gap As Date = #2026-03-29 2:30:00#
        Dim overlap As Date = #2026-10-25 2:30:00#
        Console.WriteLine($"2026-03-29 02:30 in Madrid is invalid: {madrid.IsInvalidTime(gap)}")

        ' DateOnly and TimeOnly

Rules that follow from the example:

* Store and exchange UTC (`DateTimeOffset.UtcNow`, `Date.UtcNow`), and convert to a time zone only to display it. `TimeZoneInfo.FindSystemTimeZoneById("Europe/Madrid")` accepts IANA names on Linux and macOS, and, since .NET 6 (with ICU), on Windows, where
  the Windows names such as `Romance Standard Time` also work.
* The local time zone may not exist on every machine (a trimmed container image may lack the time-zone data); check by running `TimeZoneInfo.FindSystemTimeZoneById` in the environment.
* The clock skips an hour in spring (a gap, where `IsInvalidTime` is `True`) and repeats one in autumn (an overlap, where `IsAmbiguousTime` is `True` and `GetAmbiguousTimeOffsets` lists both offsets). A local `Date` of 02:30 that day is either impossible or ambiguous; only a `DateTimeOffset` or a UTC value identifies the moment.
* `DateTime.SpecifyKind` only changes the label: it neither converts nor adjusts the value.
* `DateOnly` and `TimeOnly` convert with `ToDateTime`, `DateOnly.FromDateTime` and `TimeOnly.FromDateTime`. Neither has a VB literal; System.Text.Json and EF Core can serialise and map them.

=== Testable clocks with TimeProvider

Code that calls `Date.Now` directly is hard to test: the answer changes between runs. `System.TimeProvider` (.NET 8) is an abstract class with `GetUtcNow()`, `GetLocalNow()`, `LocalTimeZone`, `GetTimestamp()`, `GetElapsedTime()` and a `CreateTimer` factory; `TimeProvider.System` is the real clock. A class receives
a provider through its constructor (defaulting to `TimeProvider.System`) and a test passes its own subclass, or, in a test project, `FakeTimeProvider` from the `Microsoft.Extensions.TimeProvider.Testing` package. VB can subclass it without any special syntax:

[source,vbnet]
----
Option Strict On

' A TimeProvider makes "now" injectable, so overdue logic can be tested without waiting.
Public Class FixedTimeProvider
    Inherits TimeProvider

    Private _now As DateTimeOffset

    Public Sub New(now As DateTimeOffset)
        _now = now
    End Sub

    Public Sub Advance(by As TimeSpan)
        _now = _now.Add(by)
    End Sub

    Public Overrides Function GetUtcNow() As DateTimeOffset
        Return _now
    End Function
End Class

Public Class Loan
    Private ReadOnly _time As TimeProvider

    Public ReadOnly Property DueOn As DateTimeOffset

    Public Sub New(dueOn As DateTimeOffset, Optional time As TimeProvider = Nothing)
        Me.DueOn = dueOn
        _time = If(time, TimeProvider.System)
    End Sub

    Public ReadOnly Property IsOverdue As Boolean
        Get
            Return _time.GetUtcNow() > DueOn
        End Get
    End Property

    Public Function DaysOverdue() As Integer
        Dim late = _time.GetUtcNow() - DueOn
        Return If(late > TimeSpan.Zero, CInt(Math.Ceiling(late.TotalDays)), 0)
    End Function
End Class

Module Ex04

== Parsing dates

Dates in text are the largest source of culture bugs. Four ways to turn text into a date exist, with different risks.

[cols="2,3,3",options="header"]
|===
|Call |Culture used |Notes
|`CDate(text)`, `DateValue(text)`, `TimeValue(text)` |Current culture of the thread |`CDate` throws `InvalidCastException` on failure ("Conversion from string "not a date" to type 'Date' is not valid."). They parse day/month order, month names and separators by the thread's culture
|`Date.Parse(text)`, `Date.TryParse(text, result)` |Current culture, or the one you pass |Accept many formats, including the culture's; `TryParse` returns `False` instead of throwing `FormatException`
|`Date.ParseExact(text, format, provider)`, `TryParseExact` |The provider, and exactly the format you give |The safe option for any text with a known shape (files, APIs, user input with a picker). `TryParseExact` takes an array of formats
|`IsDate(text)` |Current culture |Equivalent to `Date.TryParse`; it cannot say which parse succeeded
|===

== Formatting dates

`ToString(format)`, the interpolation format specifier and composite formatting all use the same format strings. A *standard* format string is a single letter (`d`, `D`, `t`, `T`, `f`, `F`, `g`, `G`, `M`, `Y`, `s`, `u`, `o`, `R`) that stands for a culture-dependent pattern, except `s`, `o` and `R`, which never vary: `s` is the sortable
ISO form, `o` the round-trip form with 7 fractional digits and the offset or `Z`, `R` the RFC 1123 form. A *custom* format string is built from pattern letters.

[cols="1,3",options="header"]
|===
|Pattern |Meaning
|`yy`, `yyyy` |Year, two or four digits
|`M`, `MM`, `MMM`, `MMMM` |Month number, two digits, abbreviated name, full name. *Upper case M is month*
|`m`, `mm` |Minutes. *Lower case m is minutes*
|`d`, `dd`, `ddd`, `dddd` |Day of month, two digits, abbreviated and full day-of-week name
|`H`, `HH`, `h`, `hh`, `tt` |24-hour and 12-hour clock hour, and the AM/PM designator
|`s`, `ss`, `f`..`fffffff` |Seconds and fractions of a second (`F` suppresses trailing zeros)
|`K`, `zzz` |Time zone (nothing for unspecified, `Z` for UTC, `pass:c[+02:00]` for local) and the offset
|`/`, `:` |The culture's date and time *separators*, not the characters themselves
|`+'text'+`, `\c` |Literal text
|`%d` |A single custom letter that would otherwise be read as a standard format
|===

== Formatting numbers

Numbers follow the same model as dates. A *standard* numeric format string is a letter with an optional precision: `C` (currency), `D` (integers, padded), `E` (exponent), `F` (fixed point), `G` (general), `N` (number with group separators), `P` (percent, multiplies by 100), `R` (round trip), `X` (hexadecimal). A *custom* numeric format uses `0` (digit placeholder, pads with zeros), `+#+` (digit
placeholder, no padding), `.` and `,` (decimal and group separators, and scaling when `,` trails the digits), `%`, `;` (sections for positive, negative and zero), `pass:c[E+0]` and literal text in quotes.

Observations from the output:

* The currency symbol, separators and digit grouping all come from the culture: `de-DE` writes `1.234,57 €`, `fr-FR` uses a narrow no-break space (U+202F) as the group separator, and the invariant culture has the generic currency sign `¤`. === Composite formatting and interpolation

`String.Format`, `Console.WriteLine(format, args)`, `StringBuilder.AppendFormat` and `+$"..."+` strings all use composite formatting: `+{index[,alignment][:format]}+`. With `+String.Format(provider, ...)+` and with `+FormattableString.Invariant($"...")+` the culture is explicit; with a plain interpolated string it is the thread's culture.
A custom type participates by implementing `IFormattable`, as `DateTime`, `Decimal` and `TimeSpan` do; `TimeSpan` has its own format strings (`"c"`, `"g"`, `"G"` and custom ones such as `d\.hh\:mm`, where backslashes are required before literal characters).

What the output shows, and where the VB6 behaviour no longer applies:

* The named numeric formats work as documented (`"Currency"`, `"Fixed"`, `"Standard"`, `"Percent"`, `"Scientific"`, `"Yes/No"`, `"True/False"`, `"On/Off"`) and follow the culture. `FormatNumber`, `FormatCurrency` and `FormatPercent` take the number of digits, and `TriState` arguments for the leading digit, parentheses for negative numbers
  and digit grouping.
* The named date formats are supported, but with .NET's meaning: `"Medium Date"` is the same as the long date here, not the VB6 `dd-MMM-yy`, and `FormatDateTime(d, DateFormat.ShortTime)` is a 24-hour `15:04` while `"Short Time"` in `Format` is `3:04 PM` in `en-US`.
* *User-defined date patterns are the .NET ones, not the VB6 ones.* In VB6 `Format(d, "yyyy-mm-dd hh:mm:ss")` printed the month for the first `mm` and the minutes for the second. On .NET `mm` is always minutes: the program prints `2026-04-05`, a date in April, for 5 January, and `AM/PM` is not understood (it prints `A1/P1`). Write
  `yyyy-MM-dd HH:mm:ss` and `tt`, and prefer `ToString` or interpolation to `Format`.
* `FormatDateTime` takes only a `DateFormat` value: `FormatDateTime(d, "yyyy")` is BC30512 ("disallows implicit conversions from `String` to `DateFormat`"). It cannot format with a custom pattern, which is a common mistake in code written from older books.
* All the functions read the thread's culture. That is why the last line of the program changes from `$1,234.57` to `1.234,57 €` without any change of code.

Prefer `ToString(format, culture)`, interpolation and `String.Format` in new code: they are explicit about culture, behave the same in VB, C# and F#, and need no VB-specific knowledge. Keep `Format`/`FormatNumber` for code that already uses them.

*Where the books are outdated.* Both books present the VB6 date functions as the standard toolbox, and the `Format` and `FormatDateTime` functions as the way to format. Three corrections: `DateValue`, `CDate` and `Date.Parse(text)` depend on the current culture, so the examples in the books print different dates on different machines (and
a stored `DateValue` result written on one culture reads back differently on another); `FormatDateTime` accepts only the named `DateFormat` values and never a custom pattern; and the VB6 patterns that depend on the context of `mm` do not exist on .NET. Neither book covers `DateOnly`, `TimeOnly`, `DateTimeOffset`, time zones or `TimeProvider`.

== Pitfalls checklist

* `Dim d As Date = Nothing` is 1 January 0001, not a missing date. Use `Date?` for "unknown".
* `CDate` and `DateValue` parse by the thread's culture; use `ParseExact` and `CultureInfo.InvariantCulture` for data.
* Date literals are US-ordered (`+#1/2/2026#+` is 2 January) and cannot have fractions of a second.
* `+DateDiff(DateInterval.Day, ...)+` counts whole elapsed days, not midnights crossed; Year, Quarter and Month count calendar boundaries.
* `AddMonths` and `+DateAdd(Month, ...)+` clamp to the last day of the shorter month; adding a month and then subtracting it does not restore the date.
* `Weekday` starts the week on Sunday (1) by default, `DayOfWeek` is 0-based.
* `Now`, `Today` and `DateTime.Now` are local; compare and store UTC.
* `mm` is minutes and `MM` is months in .NET format strings, including the ones passed to `Format`.
* `FormatDateTime` accepts only `DateFormat` values.
* `Decimal` formats ties away from zero; `Double` formats exact ties to even; `Math.Round` is ties-to-even.
* A local time during a DST gap is invalid; during an overlap it is ambiguous.
* The invariant culture's currency sign is `¤`; use a real culture to display money.
