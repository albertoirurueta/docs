This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is
a complete console program that starts with `Option Strict On`, was built with warnings treated as errors (unless it is
meant to fail, in which case the compiler messages are shown) and was run in the .NET 10 SDK container (Linux); the
output shown is real output. The root namespace of the example projects is `ShelfDocs`, which is why run-time type names
such as ShelfDocs.Pair with the CLR arity suffix appear in the output. The project-level imports that the SDK adds (`System`,
`System.Collections.Generic`, `System.Linq`, `System.Threading.Tasks` and others) are why `List(Of T)` and `Func(Of T)`
need no `Imports`.

A generic type or procedure is code that is written once and parameterised by one or more types. `List(Of Book)` is a list
that holds only books, `Dictionary(Of String, List(Of Book))` maps names to lists of books, and a function
`Largest(Of T)` finds the biggest of anything that can be compared. The compiler checks every use against the type
arguments, so a wrong type is a compile-time error instead of an `InvalidCastException` at run time, and value types are
stored without boxing. This page covers how Visual Basic declares generics, how it infers and constrains type arguments,
the rules for `Nothing`, covariance and contravariance with `In` and `Out`, what generics look like at run time, the
generic collections of the base class library, the generic features that Visual Basic 17.13 can consume from C#
(`unmanaged`, `OverloadResolutionPriority`) and the ones it cannot, and the compiler errors you will meet.
The running example is the generic repository behind the `ICatalogStore` of the *shelf* library catalogue.

The shared .NET behaviour (the type system, JIT code generation, the variance annotations of the base class library) is
the same as in C#, which is covered in xref:programming-languages/csharp/generics.adoc[Generics (C#)]; this page concentrates on the Visual Basic
syntax and rules, and on the places where Visual Basic differs.

== Why generics exist

Before .NET 2.0 (and Visual Basic 2005, language version 8.0) the only way to write a reusable container was to store
`Object`, as `ArrayList` and `Hashtable` still do. Generics replaced that design:

* Type safety. `Dim books As New List(Of Book)` refuses `books.Add("a string")` at compile time. With `ArrayList` the same
  mistake compiles and fails later in whatever code casts the element.
* No casts, no late binding. A `List(Of Book)` returns `Book`; the caller never writes `DirectCast(list(0), Book)`.
* No boxing. A `List(Of Integer)` stores the integers themselves; an `ArrayList` allocates a box for each one. The runtime
  creates specialised code for each value type used as a type argument.
* One implementation. The algorithm is written once and checked once, for every element type.

The Learn topic on generic types lists the same advantages (type safety, performance, code consolidation, reuse, IDE
support). Generics are not a substitute for inheritance: use a generic when the code does not need to know what the type
is beyond a few capabilities (comparable, creatable, a reference type), and use a base class or an interface when it
needs members.

== Terminology

[cols="1,3", options="header"]
|===
|Term |Meaning

|Generic type |A class, structure, interface or delegate declared with a type parameter list: `Class Pair(Of TFirst, TSecond)`.
|Generic procedure |A `Sub` or `Function` with its own type parameter list: `+Function Largest(Of T)(...)+`. A method is not generic just because it sits in a generic class.
|Type parameter |The placeholder name in the declaration (`T`, `TKey`, `TValue`). By convention it starts with `T`.
|Type argument |The actual type that replaces it: `String` in `List(Of String)`.
|Constructed type |A generic type with type arguments supplied: `List(Of String)`. It is also called a closed type when no type parameter remains, for example `Pair(Of String, Integer)`.
|Open type |A generic type that still has type parameters: `Dictionary(Of ,)` (the generic type definition), or `List(Of T)` inside the body of a generic method with type parameter `T`.
|Constraint |A condition on the type argument, introduced by `As`: `+T As {Class, IEntity}+`.
|Variance |The rule that lets `IEnumerable(Of Book)` be used where `IEnumerable(Of CatalogItem)` is expected, declared with `Out` and `In`.
|===

== Declaring generic types and procedures

The type parameter list follows the name, in parentheses, and starts with the `Of` keyword. `Of` is written once, at the start
of the list; further parameters are separated by commas.

[source,text]
----
Class Name(Of T1, T2 As constraint)
Structure Name(Of T)
Interface Name(Of T)
Delegate Function Name(Of T)(arg As T) As Boolean
Function Name(Of T)(arg As T) As T
----

* Classes, structures, interfaces, delegates, `Sub` and `Function` can be generic.
* Modules, enumerations, constructors, properties, events and operators cannot (see the error table below). A generic
  property is written as a generic class with a property of type `T`, or as a generic method.
* A generic procedure may be placed in a non-generic class, structure or module, and a generic class may contain
  non-generic procedures.
* Visual Basic is case-insensitive: `T` and `t` are the same name (see BC32049 and BC32089 below). Type parameters have
  the scope of the declaration that introduces them.
* Visual Basic has no local functions and lambda expressions cannot declare type parameters, so a helper that must be generic
  is a private `Function` of the enclosing type or module.

The Learn topic on the `Of` clause documents the clause itself; the topic on generic procedures documents the rest.

The first example declares a generic class with two type parameters, two generic procedures (one with a constraint), a
generic class with a `Shared` field, and then looks at the constructed types.

[source,vbnet]
----
Option Strict On

Public Class Pair(Of TFirst, TSecond)
    Public ReadOnly Property First As TFirst
    Public ReadOnly Property Second As TSecond

    Public Sub New(first As TFirst, second As TSecond)
        Me.First = first
        Me.Second = second
    End Sub

    Public Function Swap() As Pair(Of TSecond, TFirst)
        Return New Pair(Of TSecond, TFirst)(Second, First)
    End Function

    Public Overrides Function ToString() As String
        Return "(" & First.ToString() & ", " & Second.ToString() & ")"
    End Function
End Class

Public Class Counter(Of T)
    Public Shared Count As Integer

    Public Sub New()
        Count += 1
    End Sub
End Class

Module Program
    Function Largest(Of T As IComparable(Of T))(first As T, ParamArray rest As T()) As T
        Dim best = first
        For Each candidate In rest
            If candidate.CompareTo(best) > 0 Then best = candidate
        Next
        Return best
    End Function

    Sub SwapValues(Of T)(ByRef left As T, ByRef right As T)
        Dim temp = left
        left = right
        right = temp
    End Sub

    Sub Main()
        Dim entry As New Pair(Of String, Integer)("Dune", 1965)
        Console.WriteLine(entry.ToString() & " -> " & entry.Swap().ToString())

        ' Type arguments inferred from the arguments, or given explicitly.
        Console.WriteLine(Largest(3, 9, 4))
        Console.WriteLine(Largest("pear", "apple", "zebra"))
        Console.WriteLine(Largest(Of Double)(1, 2.5))
        Console.WriteLine(Largest(1, 2.5))
        Console.WriteLine(TypeName(Largest(1, 2.5)))

        Dim a = "left"
        Dim b = "right"
        SwapValues(a, b)
        Console.WriteLine(a & " " & b)

        ' Each closed type has its own Shared fields.
        Dim c1 As New Counter(Of Integer)
        Dim c2 As New Counter(Of Integer)
        Dim c3 As New Counter(Of String)
        Console.WriteLine("Counter(Of Integer): " & Counter(Of Integer).Count)
        Console.WriteLine("Counter(Of String): " & Counter(Of String).Count)

        ' Open and closed constructed types at run time.
        Console.WriteLine(GetType(Pair(Of ,)))
        Console.WriteLine(GetType(Pair(Of String, Integer)))
        Console.WriteLine(GetType(Pair(Of ,)).IsGenericTypeDefinition)
        Console.WriteLine(GetType(Pair(Of String, Integer)).GetGenericTypeDefinition() Is GetType(Pair(Of ,)))
        Console.WriteLine(GetType(List(Of Integer)) Is GetType(List(Of Long)))
        GC.KeepAlive(New Object() {c1, c2, c3})
    End Sub
End Module
----

What this output shows:

* `Largest(3, 9, 4)` is the first inference. `T` is deduced from the arguments, with no `Of Integer` anywhere. The
  constraint `IComparable(Of T)` is what makes `candidate.CompareTo(best)` legal.
* `Largest(1, 2.5)` mixes an `Integer` and a `Double`. Visual Basic infers the dominant type of the arguments, `Double`, and
  `TypeName` confirms it. The rules are in the next section.
* `Counter(Of Integer).Count` is `2` and `Counter(Of String).Count` is `1`: every constructed type has its own `Shared`
  members. This is the same as in C#, and it surprises programmers who expect one counter per generic class.
* `GetType(Pair(Of ,))` is the open generic type definition (note the empty slot before the comma). The closed type
  `Pair(Of String, Integer)` knows its definition, and `List(Of Integer)` and `List(Of Long)` are different types. The
  CLR name of a generic type ends with a backtick and the number of type parameters (the arity), so `Pair` with two type
  parameters is printed as ShelfDocs.Pair followed by a backtick and 2.
* `ByRef` parameters work as usual in generic procedures; `SwapValues(Of T)` swaps two strings and would swap two
  integers just as well.

== Type inference

A call to a generic procedure may omit the type arguments. The compiler then infers them from the arguments of the call.

* Inference uses the arguments only, never the expected result type: `Dim e = Echo()` for `Function Echo(Of T)() As T`
  fails with BC32050 whatever variable receives the result.
* It is all or nothing. You may omit every type argument or supply them all; you cannot supply some and have the compiler
  infer the rest.
* If the arguments suggest several types, the compiler uses the dominant type, which is the one every candidate
  converts to widening. `Largest(1, 2.5)` infers `Double`. When no single type works (an `Integer` and a `String`) the call
  fails with BC36651 and you must name the type yourself, for example `Pick(Of Object)(1, "x")`.
* Inference exists only for procedures. A constructor call, `New Pair(Of String, Integer)("Dune", 1965)`, always spells out
  the type arguments, and a missing or extra one is BC32042 or BC32043. Lambda parameters are inferred from the delegate
  they are converted to, as in `books.Select(Function(b) b.Title)`.
* Array rank mismatches also defeat inference; the Learn topic on generic procedures gives an example.
* `Option Infer` controls the type inference of local variables (`+Dim e = ...+`); it does not control the inference of type
  arguments, which also works with `Option Infer Off` (tested). See xref:programming-languages/visual-basic/option-statements.adoc[Option Statements].

== Constraints

A type parameter with no constraint can be used only through the members of `Object`, and can be assigned `Nothing`.
Anything more has to be requested with an `As` clause. Several constraints are written in braces, and `As` appears once:

[source,text]
----
Class Repository(Of T As {Class, IEntity})
Function Create(Of T As {CatalogItem, New})(title As String) As T
----

[cols="2,3,3", options="header"]
|===
|Constraint |What it guarantees and allows |C# spelling

|`T As Class`
|`T` is a reference type. `Nothing` and `Is Nothing` are meaningful, and `T` can be used in a type with a reference-type-only restriction.
|`where T : class`

|`T As Structure`
|`T` is a non-nullable value type. `New T()` is allowed (a `Structure` constraint implies `New`), `T?` is legal, `Is Nothing` is not.
|`where T : struct`

|`T As New`
|`T` has an accessible parameterless constructor, so `New T()` compiles. It can be listed in any position (`+{New, Class}+` and `+{Class, New}+` both compile).
|`where T : new()`

|`T As BaseClass`
|`T` is `BaseClass` or derives from it; the members of the base class are available on `T`. At most one class constraint is allowed.
|`where T : BaseClass`

|`T As IInterface`
|`T` implements the interface; its members are available. Any number of interfaces may be listed, and the interface may mention `T` itself: `T As IComparable(Of T)`.
|`where T : IInterface`

|`TDerived As TBase`
|`TDerived` is `TBase` or derives from it. A constraint may name another type parameter of the same declaration (`Function Upcast(Of TDerived As TBase, TBase)`).
|`where TDerived : TBase`

|`T As unmanaged`
|Cannot be declared in Visual Basic. Visual Basic 17.13 does enforce it when it calls a generic type or method that C# declared with it (see below).
|`where T : unmanaged`
|===

Rules enforced by the compiler (all the messages are real, from the examples below):

* `Class` and `Structure` cannot appear together: BC32104.
* `Structure` and `New` cannot appear together: BC32103, because `Structure` already implies the constructor.
* `Class` cannot be combined with a specific class constraint: BC32107. A second class constraint is BC32047. A constraint on
  a `NotInheritable` class is BC32060, because only that class could ever satisfy it.
* A constraint must be a class, an interface or a type parameter: `T As Integer` is BC32048. `Object` and `System.ValueType`
  are rejected with BC32061; use `Class` or `Structure` instead.
* Listing the same interface twice is BC32071; constraining a parameter to itself is BC32113.
* Visual Basic has no spelling for `notnull`, `default`, `allows ref struct` or nullable-annotated constraints: the constraint
  list of the Learn *Type List* topic is interfaces, at most one class, `New`, and `Class` or `Structure`.

The next program uses most of them on the catalogue classes. Everything about `T` that is not in its constraints is
unavailable: `Oldest` can read `item.Year` because `CatalogItem` has the property, and `FirstOrNothing` can return
`Nothing` because of `Class`.

[source,vbnet]
----
Option Strict On

Public Interface IEntity
    ReadOnly Property Id As Integer
End Interface

Public MustInherit Class CatalogItem
    Implements IEntity

    Public Property Id As Integer Implements IEntity.Id
    Public Property Title As String
    Public Property Year As Integer

    Public Overrides Function ToString() As String
        Return Title & " (" & Year & ")"
    End Function
End Class

Public Class Book
    Inherits CatalogItem

    Public Sub New()
        Title = "Untitled book"
        Year = 2000
    End Sub
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Sub New(title As String)
        Me.Title = title
    End Sub
End Class

Module Program
    ' Base-class constraint plus New: both must hold for the type argument.
    Function Create(Of T As {CatalogItem, New})(title As String) As T
        Dim item As New T()
        item.Title = title
        Return item
    End Function

    ' Base-class constraint: members of CatalogItem are available on T.
    Function Oldest(Of T As CatalogItem)(items As IEnumerable(Of T)) As T
        Dim best As T = Nothing
        For Each item In items
            If best Is Nothing OrElse item.Year < best.Year Then best = item
        Next
        Return best
    End Function

    ' Class constraint: a reference-type argument, so Nothing and Is are available.
    Function FirstOrNothing(Of T As Class)(items As IEnumerable(Of T), predicate As Func(Of T, Boolean)) As T
        For Each item In items
            If predicate(item) Then Return item
        Next
        Return Nothing
    End Function

    ' Structure constraint: a non-nullable value type, so T? is legal.
    Function OrFallback(Of T As Structure)(value As T?, fallback As T) As T
        Return If(value.HasValue, value.Value, fallback)
    End Function

    Function ZeroOf(Of T As Structure)() As T
        Return New T()
    End Function

    ' A constraint may name another type parameter of the same procedure.
    Function Upcast(Of TDerived As TBase, TBase)(item As TDerived) As TBase
        Return item
    End Function

    ' With no constraint, Nothing means "the default value of T".
    Function DefaultOf(Of T)() As T
        Return Nothing
    End Function

    ' Is Nothing compiles for an unconstrained T: False for value types, True for a null reference.
    Function IsNull(Of T)(value As T) As Boolean
        Return value Is Nothing
    End Function

    Function IsDefault(Of T)(value As T) As Boolean
        Return EqualityComparer(Of T).Default.Equals(value, Nothing)
    End Function

    Sub Main()
        Dim book = Create(Of Book)("Dune")
        book.Year = 1965
        Dim old = New Book With {.Title = "Emma", .Year = 1815}
        Console.WriteLine(book.ToString() & " / " & Oldest({book, old}).ToString())
        Console.WriteLine(Oldest(New List(Of CatalogItem) From {New Magazine("Wired") With {.Year = 1993}, book}))
        Console.WriteLine(FirstOrNothing({"alpha", "beta"}, Function(s) s.StartsWith("b", StringComparison.Ordinal)))
        Console.WriteLine(FirstOrNothing({"alpha", "beta"}, Function(s) s.Length > 10) Is Nothing)
        Console.WriteLine(OrFallback(Of Integer)(Nothing, 7) & " " & OrFallback(New Date?(#2026-10-19#), Date.MinValue).Year)
        Console.WriteLine(ZeroOf(Of Integer)() & " " & ZeroOf(Of Date)().Year & " " & ZeroOf(Of Boolean)())

        Dim item As CatalogItem = Upcast(Of Book, CatalogItem)(book)
        Console.WriteLine(item.Title)

        Console.WriteLine("default Integer: " & DefaultOf(Of Integer)())
        Console.WriteLine("default String is Nothing: " & (DefaultOf(Of String)() Is Nothing))
        Console.WriteLine("default Date: " & DefaultOf(Of Date)().Year)
        Console.WriteLine(IsNull(0) & " " & IsNull(Of String)(Nothing) & " " & IsNull(Of Integer?)(Nothing))
        Console.WriteLine(IsDefault(0) & " " & IsDefault(5) & " " & IsDefault(Of String)(Nothing) & " " & IsDefault("x"))
    End Sub
End Module
----

=== Operators are not available on a type parameter

The Learn topic on generic procedures uses `CompareTo` instead of `=` in its example and says why: nothing guarantees that a
type argument supports the operator. Visual Basic operators are looked up on the declared type, and a type parameter declares none.

* To compare for equality, use `EqualityComparer(Of T).Default.Equals(a, b)` (the constraint-free way, which also handles
  `Nothing` and `Equals` overrides), or constrain `T As IEquatable(Of T)`.
* To order, constrain `T As IComparable(Of T)` and call `CompareTo`, or take a `Comparer(Of T)` or `IComparer(Of T)` argument.
* To add, subtract or multiply, take a `Func(Of T, T, T)` argument, or use `System.Linq.Enumerable.Sum` and its overloads
  when the element type is a built-in numeric type.
* The generic math interfaces such as `INumber(Of T)` (see
  xref:programming-languages/csharp/generics.adoc[Generics (C#)]) can be named in a constraint, but their members are static
  abstract members and Visual Basic 17.13 cannot call them: `T.Zero` is BC32098 and `pass:c[total += item]` is BC30452. The
  compiler accepts the declaration and rejects the use, as the first two errors of the listing show.

[source,vbnet]
----
Option Strict On
Imports System.Numerics

Public Class CatalogItem
End Class

Public Class Book
    Inherits CatalogItem
End Class

Module Program
    Function SumAll(Of T As INumber(Of T))(items As IEnumerable(Of T)) As T
        Dim total As T = Nothing
        For Each item In items
            total += item
        Next
        Return total
    End Function

    Function ZeroOf(Of T As INumber(Of T))() As T

== Default values and Nothing

`Nothing` in Visual Basic means "the default value of the type", not only "no object". For a type parameter it is the same
rule applied late: `Dim x As T = Nothing` is `null` when `T` is a reference type, `0` when it is a numeric type, `False`
for `Boolean`, the zero-initialised structure for any other structure. The constrained `Class` and `Structure` forms
narrow what `Nothing` can mean. C# spells the same idea `default` and `default(T)`; Visual Basic has no such keyword.
The rules of `Nothing` itself (the comparison `= Nothing`, strings, nullable value types) are on
xref:programming-languages/visual-basic/nothing-and-nullable-value-types.adoc[Nothing and Nullable Value Types].

* `Return Nothing` from a `+Function ... As T+` is always legal and always the default of `T`.
* `value Is Nothing` compiles for an unconstrained `T`. It is `False` for every value type (the value is boxed for the
  test) and `True` for a null reference; the `IsNull` function of the constraints example prints `False True True` for an
  `Integer`, a `String` that is `Nothing` and an `Integer?` that is `Nothing`. With a `Structure` constraint it is rejected
  with BC30020, because a value type can never be `Nothing`.
  With a `Class` constraint it is the normal null test.
* `EqualityComparer(Of T).Default.Equals(value, Nothing)` answers "is this the default value?" for any `T`, which the
  `IsDefault` function above shows: it is `True` for `0` and for a `Nothing` string.
* `T?`, that is `Nullable(Of T)`, requires `T As Structure`. `OrFallback(Of T As Structure)` in the constraints example
  takes a `T?`.

The `Dim best As T = Nothing` line in `Oldest` is the usual pattern for "no result yet" in a generic search loop; the test
`best Is Nothing OrElse item.Year < best.Year` is legal because `T` is constrained to the class `CatalogItem`.

== A generic repository for the shelf

The shelf library has a non-generic contract, `ICatalogStore`, that `Catalog` depends on. Behind it, the same bookkeeping
(auto-numbered identifiers, lookups, "list everything") is needed for books, magazines and loans. A generic repository
captures it once. The design is an `IEntity` interface (everything with an `Id`), a generic contract
`IRepository(Of T As IEntity)`, a generic implementation `+Repository(Of T As {Class, IEntity})+`, and an adapter that
presents a `Repository(Of CatalogItem)` as an `ICatalogStore`.

Reading the example:

* `IRepository(Of T As IEntity)` is covered by a constraint; `+Repository(Of T As {Class, IEntity})+` adds `Class` because the
  code uses `item Is Nothing` and returns `Nothing` from `Find`. Without `Class`, `Find` would return the default value of
  a structure when nothing is found, which is indistinguishable from a real result.
* `item.Id = 0` and `item.Id = _nextId` work through the `IEntity` constraint, with no cast. This is why `IEntity.Id` is
  declared read-write here: the repository assigns the next identifier when the item has none.
* `Implements IRepository(Of T).Add` names the closed interface member with the class's own type parameter. The
  `Implements` clause is what links a method to the interface member, so the method may have a different name (as
  `FormatBook` does in the collections example).
* `Public Overridable Sub Add` lets a derived repository override the behaviour; the `Overridable` modifier is independent
  of generics. Interfaces are covered on xref:programming-languages/visual-basic/interfaces.adoc[Interfaces] and inheritance
  on xref:programming-languages/visual-basic/inheritance-and-polymorphism.adoc[Inheritance and Polymorphism].
* `Inherits Repository(Of Book)` derives from a closed generic base class. `GetType(BookRepository).BaseType` prints the
  CLR name of that closed type, `ShelfDocs.Repository` with the arity suffix and `[ShelfDocs.Book]`.
* `Dim viaInterface As IRepository(Of Book) = books` converts to the generic interface; `TypeName` still reports the
  run-time class, `BookRepository`.
* `store.Find(99) Is Nothing` is the "not found" convention for a `Class`-constrained result. For a result that must
  also work for value types, use the `Try` pattern with a `ByRef` parameter and a `Boolean` return, as
  `Dictionary(Of TKey, TValue).TryGetValue` (used inside `Find`) and `LoanQueue(Of T).TryDequeue` below do.

== Members of generic types

=== Shared members and static constructors

Each closed type is a different type, with its own `Shared` fields, its own `Shared Sub New` and its own `Shared`
properties. Code in a generic class cannot assume that a `Shared` value is shared with other constructions of the same
generic type. The run-time example below makes this visible with a static constructor that runs once for each
construction.

=== Nested types

A type nested in a generic type is itself generic, with the type parameters of the outer type: `LoanQueue(Of T).Node` in the
collections example is a different type for each `T`, and its members can use `T` without declaring it again. A nested
type that should not depend on `T` has to be moved out of the generic class.

=== Shadowing and naming

A procedure may not reuse its own type parameter's name as the name of a parameter or local: `Make(Of U)(u As U)` is
BC32089, because Visual Basic ignores case and `u` and `U` are the same name. A class-level type parameter `T` and a parameter
named `t` are not in conflict, as the first method of the example shows. Redeclaring an enclosing type's type
parameter (`Sub Test(Of T)` inside `Holder(Of T)`) is accepted, with the warning BC40048, and the inner `T` shadows the outer.
Two type parameters that differ only in case are BC32049.

=== Inheritance and interfaces

* A generic class can inherit from a closed or open generic class (`Inherits Repository(Of Book)`, `Inherits List(Of T)`).
* A type may implement the same generic interface more than once with different type arguments, as `CatalogFormatter`
  does below with `IFormatter(Of Book)` and `IFormatter(Of Magazine)`; each `Implements` clause names the closed
  interface member.
* A `MustOverride` method may be generic. Unlike in C#, where an override inherits the constraints of the base method, a
  Visual Basic override must restate them exactly: dropping `New` from the override of `+Make(Of T As {Class, New})+` is
  BC32077, "differ by type parameter constraints". `DefaultFactory` in the example below does it correctly.

class; `CollectionExtensions.Validate` is a generic extension method (see
xref:programming-languages/visual-basic/extension-methods-and-partial-methods.adoc[Extension Methods and Partial Methods]);
and the `Main` procedure uses the common generic collections.

Public Class LoanQueue(Of T)
    Private Class Node
        Public ReadOnly Property Value As T
        Public Property [Next] As Node

        Public Sub New(value As T)
            Me.Value = value
        End Sub
    End Class

    Private _head As Node
    Private _tail As Node

    Public Sub Enqueue(value As T)
        Dim node As New Node(value)
        If _tail Is Nothing Then
            _head = node
        Else
            _tail.Next = node
        End If
        _tail = node
    End Sub

    Public Function TryDequeue(ByRef value As T) As Boolean
        If _head Is Nothing Then Return False
        value = _head.Value
        _head = _head.Next
        If _head Is Nothing Then _tail = Nothing
        Return True
    End Function
End Class

Points worth noting:

* Dictionary values that are lists are built with the lookup-or-create pattern (`TryGetValue`, then `Add`). With a
  `StringComparer.OrdinalIgnoreCase` argument the lookup `byAuthor("HERBERT")` finds `Herbert`.
* `SortedDictionary(Of TKey, TValue)` enumerates in key order; `HashSet(Of T)` is the set that removes duplicates;
  `KeyValuePair(Of TKey, TValue)` is a generic structure that you can name as the loop variable type.
* `List(Of T).Sort` is not stable: elements that compare equal may be reordered. `Comparer(Of Book).Create` turns a lambda
  into an `IComparer(Of Book)`.
* `Result(Of T)` has a private constructor and two `Shared` factory functions; with `T` set to `Integer` the structure
  holds the value with no allocation. The member named `Error` needs brackets (`[Error]`), because `Error` is a keyword.
* The `Validator(Of T)` delegate type is called with `rule(i)`. The framework's `Predicate(Of T)` and `Func(Of T, Boolean)` are
  equivalent for this purpose; a user-defined generic delegate is rarely needed.
* For a loop variable that shadows an in-scope name, the pitfall is described under pitfalls below.

The generic collections live in `System.Collections.Generic`; the immutable and concurrent ones are in
`System.Collections.Immutable` and `System.Collections.Concurrent`. The non-generic `ArrayList`, `Hashtable`, `Queue`,
`Stack` and `SortedList` in `System.Collections` still exist for compatibility; new code should use the generic ones.
The Visual Basic `Collection` class from the runtime library is a separate legacy type. All of them are compared on
xref:programming-languages/visual-basic/collections.adoc[Collections] and queried with
xref:programming-languages/visual-basic/linq-query-expressions.adoc[LINQ query expressions].

|Type |Use

|`List(Of T)` |Ordered, growable array. Fast index access and append; `Sort`, `BinarySearch`, `RemoveAll`, `ConvertAll`.
|`Dictionary(Of TKey, TValue)` |Hash table. Keys need good `GetHashCode` and `Equals`; enumeration order is not part of the contract.
|`SortedDictionary(Of TKey, TValue)`, `SortedSet(Of T)`, `SortedList(Of TKey, TValue)` |Ordered by key; `SortedList` is array-backed and cheaper in memory, `SortedDictionary` faster to insert.

|`LinkedList(Of T)` |Doubly linked list with O(1) insertion at a known node.
|`KeyValuePair(Of TKey, TValue)` |Pair structure used by dictionary enumeration.
|`IEnumerable(Of T)`, `ICollection(Of T)`, `IList(Of T)`, `IReadOnlyList(Of T)`, `IReadOnlyCollection(Of T)` |Interfaces; accept the weakest one a method needs (`IEnumerable(Of T)` for read-only iteration).

== Covariance and contravariance

Generic type arguments are normally invariant: `IList(Of Book)` is not an `IList(Of CatalogItem)`, even though `Book`
derives from `CatalogItem`, because a list can be written to and a `Magazine` would then end up in a list of books.
Variance recovers the safe cases. A type parameter marked `Out` may appear only in output positions (return types) and makes the
interface or delegate covariant: `IEnumerable(Of Book)` converts to `IEnumerable(Of CatalogItem)`. A type parameter marked
`In` appears only in input positions (parameters) and makes it contravariant: `IComparer(Of CatalogItem)` converts to
`IComparer(Of Book)`, because a comparer that can compare any two catalogue items can compare two books.

Visual Basic supports variance annotations on generic interfaces and delegates since Visual Basic 2010 (.NET Framework 4);
the Learn topic on covariance and contravariance states the same version. The rules:

* `Out` and `In` are allowed on interfaces and delegates only. A class or structure gets BC36722.
* An `Out` parameter cannot be used as a `ByVal` method parameter type (BC36742), an `In` parameter cannot be used as a
  return type (BC36743).
* Variance applies only to reference types as type arguments. `IEnumerable(Of Integer)` does not convert to
  `IEnumerable(Of Object)` (BC36754), because it would need a boxing conversion.
* Classes and the usual collections are invariant: `List(Of Book)` does not convert to `List(Of CatalogItem)` (BC36756,
  which suggests `IEnumerable(Of CatalogItem)`).

[source,vbnet]
----
Option Strict On

Public MustInherit Class CatalogItem
    Public Property Title As String

    Protected Sub New(title As String)
        Me.Title = title
    End Sub
End Class

Public Class Book
    Inherits CatalogItem

    Public Sub New(title As String)
        MyBase.New(title)
    End Sub
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Sub New(title As String)
        MyBase.New(title)
    End Sub
End Class

' Out: T appears only in output positions, so the interface is covariant.
Public Interface IProducer(Of Out T)
    Function Produce() As T
End Interface

' In: T appears only in input positions, so the interface is contravariant.
Public Interface IConsumer(Of In T)
    Sub Consume(item As T)
End Interface

Public Delegate Function Factory(Of Out T)() As T
Public Delegate Sub Handler(Of In T)(item As T)

Public Class BookProducer
    Implements IProducer(Of Book)

    Public Function Produce() As Book Implements IProducer(Of Book).Produce
        Return New Book("Dune")
    End Function
End Class

Public Class ItemPrinter
    Implements IConsumer(Of CatalogItem)

    Public Sub Consume(item As CatalogItem) Implements IConsumer(Of CatalogItem).Consume
        Console.WriteLine("consumed " & item.Title)
    End Sub
End Class

Public Class TitleComparer
    Implements IComparer(Of CatalogItem)

    Public Function Compare(x As CatalogItem, y As CatalogItem) As Integer Implements IComparer(Of CatalogItem).Compare
        Return String.Compare(x.Title, y.Title, StringComparison.OrdinalIgnoreCase)
    End Function
End Class

Module Program
    Function MakeBook() As Book
        Return New Book("Emma")
    End Function

    Sub Main()
        ' Covariance: a Book producer is a CatalogItem producer.
        Dim producer As IProducer(Of CatalogItem) = New BookProducer()
        Console.WriteLine(producer.Produce().Title)

        ' IEnumerable(Of T) is declared Out T; IReadOnlyList(Of T) too.
        Dim books As New List(Of Book) From {New Book("Emma"), New Book("Dune")}
        Dim items As IEnumerable(Of CatalogItem) = books
        Dim readOnlyItems As IReadOnlyList(Of CatalogItem) = books
        Console.WriteLine(items.Count() & " " & readOnlyItems(1).Title)

        ' Contravariance: a CatalogItem consumer can stand in for a Book consumer.
        Dim consumer As IConsumer(Of Book) = New ItemPrinter()
        consumer.Consume(New Book("Dune"))

        ' IComparer(Of T) is declared In T: sort Books with a comparer written for CatalogItem.
        books.Sort(New TitleComparer())
        Console.WriteLine(String.Join(", ", books.Select(Function(b) b.Title)))

        ' The same rules for delegates, with the Out / In modifiers on a user-defined delegate.
        Dim makeItem As Factory(Of CatalogItem) = AddressOf MakeBook
        Console.WriteLine(makeItem().Title)
        Dim handleBook As Handler(Of Book) = New Handler(Of CatalogItem)(Sub(item) Console.WriteLine("handled " & item.Title))
        handleBook(New Book("Dune"))

        ' Func(Of Out TResult) and Action(Of In T) are variant too.
        Dim bookFactory As Func(Of Book) = AddressOf MakeBook
        Dim makeAny As Func(Of CatalogItem) = bookFactory
        Dim actAny As Action(Of CatalogItem) = Sub(item) Console.WriteLine("action " & item.Title)
        Dim actBook As Action(Of Book) = actAny
        actBook(DirectCast(makeAny(), Book))
    End Sub
End Module

=== Array covariance

Arrays are covariant for reference element types, a legacy of the .NET 1.0 type system: `Dim objects As Object() = strings`
compiles, and the unsafe half of the design is checked at run time. Writing a value of the wrong type through the
widened reference throws `ArrayTypeMismatchException` (see the run-time example below). Generic collections do not have
this hole, which is one more reason to prefer `List(Of T)` and `IReadOnlyList(Of T)`.

== Generics at run time

.NET generics are reified: the closed types exist at run time, with their type arguments available to reflection. This is
different from Java, where the type arguments are erased (see
xref:programming-languages/java/index.adoc[Java Reference]).

* `GetType(T)` and `TypeOf value Is T` work inside a generic procedure. `DirectCast(value, T)` compiles for an unconstrained
  `T`; at run time a wrong type is an `InvalidCastException`.
* `GetType(Dictionary(Of ,))` is the generic type definition. `MakeGenericType` closes it at run time;
  `Activator.CreateInstance` creates an instance; `MakeGenericMethod` closes a generic method.
* Every value type used as a type argument gets its own code, specialised and unboxed. Reference types share code.
* A `Shared Sub New` runs once per closed type.

[source,vbnet]
----
Option Strict On
Imports System.Reflection

Public Class Registry(Of T)
    Public Shared ReadOnly Created As String

    ' Runs once for each closed type: Registry(Of Integer), Registry(Of String), ...
    Shared Sub New()
        Created = "static constructor ran for " & GetType(T).Name
        Console.WriteLine(Created)
    End Sub

    Public Function Describe(value As T) As String
        If TypeOf value Is IComparable Then
            Return GetType(T).Name & " is comparable"
        End If
        Return GetType(T).Name & " is not comparable"
    End Function
End Class

Public Class Plain
End Class

Module Program
    Function Cast(Of T)(value As Object) As T
        Return DirectCast(value, T)
    End Function

    Function IsInstance(Of T)(value As Object) As Boolean
        Return TypeOf value Is T
    End Function

    Sub Main()
        ' One static constructor run per closed type, on first use.
        Console.WriteLine(New Registry(Of Integer)().Describe(3))
        Console.WriteLine(New Registry(Of Plain)().Describe(New Plain()))
        Console.WriteLine(New Registry(Of Integer)().Describe(4))

        ' T is a real type at run time: TypeOf ... Is T and GetType(T) work.
        Console.WriteLine(IsInstance(Of Integer)(5) & " " & IsInstance(Of String)(5) & " " & IsInstance(Of IComparable)("x"))
        Console.WriteLine(Cast(Of Integer)(CObj(5)) + 1)
        Try
            Console.WriteLine(Cast(Of String)(CObj(5)))
        Catch ex As InvalidCastException
            Console.WriteLine("InvalidCastException: " & ex.Message)
        End Try

        ' Building and inspecting constructed types by reflection.
        Dim open = GetType(Dictionary(Of ,))
        Dim closed = open.MakeGenericType(GetType(String), GetType(List(Of Integer)))
        Console.WriteLine(closed)
        Console.WriteLine(String.Join(" | ", closed.GetGenericArguments().Select(Function(t) t.Name)))
        Dim instance = Activator.CreateInstance(closed)
        Console.WriteLine(instance.GetType().Name & " created, count " & DirectCast(instance, System.Collections.ICollection).Count)

        ' A generic method closed over a type chosen at run time.
        Dim method = GetType(Program).GetMethod("IsInstance", BindingFlags.Static Or BindingFlags.NonPublic Or BindingFlags.Public)
        Dim closedMethod = method.MakeGenericMethod(GetType(Date))
        Console.WriteLine(closedMethod.Invoke(Nothing, New Object() {#2026-10-19#}))

        ' List(Of Integer) stores the numbers unboxed; ArrayList boxes each one.
        Dim numbers As New List(Of Integer) From {1, 2, 3}
        Dim boxed As New ArrayList() From {1, 2, 3}
        Console.WriteLine(numbers.Sum() & " " & boxed.Cast(Of Integer)().Sum())

        ' Arrays are covariant for reference types; the check happens at run time.
        Dim strings As String() = {"a", "b"}
        Dim objects As Object() = strings
        Try
            objects(0) = 42
        Catch ex As ArrayTypeMismatchException
            Console.WriteLine("ArrayTypeMismatchException: " & ex.Message)
        End Try
    End Sub
End Module

== Generic features consumed from C#

Visual Basic 17.13 consumes two generic features that C# added after Visual Basic 16.9: the `unmanaged` constraint and
`OverloadResolutionPriorityAttribute`. You can call code that uses them; the `unmanaged` constraint cannot be declared in
Visual Basic, and neither feature has syntax of its own. This follows the language strategy of xref:programming-languages/visual-basic/history-versions-and-language-strategy.adoc[History, Versions and Language Strategy].

=== The unmanaged constraint

C# can declare `where T : unmanaged`: `T` is a value type whose fields, at any depth, are also non-nullable value types (no
references). Visual Basic 17.13 recognises the constraint on a method or type that came from C# and enforces it; it cannot
declare the constraint (`As unmanaged` is BC30002, "Type 'unmanaged' is not defined", as the Learn topic on generic types also
states). Under `LangVersion` 16.9 or lower the same call is BC36716.

The test needs two projects, because the generic method is written in C#. The library:

    public int Height;

    public int Value;

    public static string Plain(List<int> items) => "List<int>";

    public static string Ranked(List<int> items) => "List<int>";

=== OverloadResolutionPriority

.NET 9 added `OverloadResolutionPriorityAttribute`, which a library author uses to make the compiler prefer one overload when
several are applicable. Visual Basic 17.13 honours the attribute when it resolves a call to such a library method. In the
program above, `numbers` is a `List(Of Integer)`. `Native.Plain` has overloads for `List(Of Integer)` and
`IEnumerable(Of Integer)` and picks the more specific `List(Of Integer)`; `Native.Ranked` has the same two, but the
`IEnumerable` overload carries `OverloadResolutionPriority(1)`, and it wins. Under `LangVersion` 16.9, the same
`Ranked(numbers)` call chose the `List` overload, i.e. the attribute was ignored.

Library authors use this to introduce a new overload (for example one that takes a `ReadOnlySpan`) without breaking
callers or creating ambiguities. As a consumer you do not do anything; just be aware that the overload picked can be the
one with the highest priority, not the most specific.

Source: https://learn.microsoft.com/dotnet/api/system.runtime.compilerservices.overloadresolutionpriorityattribute[OverloadResolutionPriorityAttribute]

== Older material you may meet

* VB6 and VBA have no generics. The only reusable container was `Collection`, which stores `Variant`. Ports to .NET that
  keep `Microsoft.VisualBasic.Collection` or `ArrayList` pay for it in casts and boxing. See
  xref:programming-languages/visual-basic/migrating-legacy-visual-basic.adoc[Migrating Legacy Visual Basic].
* Early Visual Basic .NET tutorials (2002 and 2003, before generics) build typed collections by inheriting from
  `CollectionBase` and writing one class per element type. Replace those classes with `List(Of T)` or `Collection(Of T)`
  from `System.Collections.ObjectModel`.
* Tutorials from Visual Basic 2005 or 2008 have no covariance and contravariance; code that works around
  `IEnumerable(Of Derived)` to `IEnumerable(Of Base)` with `Cast(Of T)` or a copy no longer needs to.
* Books and articles that mix the .NET Framework and modern .NET often describe the same constructs as language
  features of a particular Visual Studio edition; the version table is on
  xref:programming-languages/visual-basic/history-versions-and-language-strategy.adoc[History, Versions and Language Strategy].
* Visual Basic 17.13 is the first version that can consume `unmanaged` constraints and `OverloadResolutionPriorityAttribute`;
  materials written for 16.9 and older show errors for them.

== Pitfalls

* Every closed type has its own `Shared` state and its own `Shared Sub New`.
* Do not expect `List(Of Derived)` to convert to `List(Of Base)`. Expose `IEnumerable(Of Base)` or `IReadOnlyList(Of Base)`.
* A `For Each` loop variable with no `As` clause whose name is already in scope binds to that name instead of declaring a
  new variable. The listing below uses `text` (which names the imported namespace `System.Text`, because Visual Basic
  ignores case) and `input` (which names the `Input` procedure of the runtime library); the compiler reports BC30112 and
  BC30516 at the loop header and in the body, while `entry` works. Choose names that are not imported members, or write
  `For Each entry As Book In books`.

[source,vbnet]
----
Option Strict On

Public Class Book
    Public Title As String
End Class

Module Program
    Sub Main()
        Dim books As New List(Of Book) From {New Book()}
        Dim names = {"a", "b"}

        For Each text In names
            Console.WriteLine(text.Length)
        Next

        For Each input In names
            Console.WriteLine(input.Length)
        Next

        For Each entry In names
            Console.WriteLine(entry.Length)
        Next
    End Sub
End Module
----

[source,text]
----
Program.vb(12,18): error BC30112: 'System.Text' is a namespace and cannot be used as an expression.
Program.vb(13,31): error BC30456: 'Length' is not a member of 'System.Text'.
Program.vb(16,18): error BC30516: Overload resolution failed because no accessible 'Input' accepts this number of arguments.
Program.vb(17,31): error BC30516: Overload resolution failed because no accessible 'Input' accepts this number of arguments.
----

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/statements/for-each-next-statement[For Each...Next Statement]

* `Pick(1, "x")` is BC36651 under `Option Strict On` and also under `Option Strict Off` (tested): no single type is
  dominant for an `Integer` and a `String`, and turning `Option Strict` off does not change that. Name the type
  argument, `Pick(Of Object)(1, "x")`. See xref:programming-languages/visual-basic/option-statements.adoc[Option Statements].
* A type parameter has the members of `Object` only. If you need `ToString` it works; if you need an arithmetic or comparison operator,
  use a constraint or a delegate.
* `Nothing` comparisons: `x Is Nothing` for a `T` that is a value type is always `False`. Use `EqualityComparer(Of T).Default` for
  "is it the default value".
* The `Class` constraint is not "not nullable": `T As Class` still allows `Nothing`.
* Do not expose `Dictionary(Of TKey, TValue)` or `List(Of T)` in a public contract when callers only read; prefer the read-only
  interfaces.
* Generic code that boxes (`ArrayList`, `Object` parameters, non-generic `IComparable`) loses the benefit of generics.
* Variance annotations are a public contract: adding `Out` to an interface and later adding a method that takes `T` is a
  breaking change.
