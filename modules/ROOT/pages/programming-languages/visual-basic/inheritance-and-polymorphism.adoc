This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. Every example is
a complete console program that starts with `Option Strict On`. The examples were built (with warnings treated as errors,
except the ones that are meant to show compiler messages, which say so) and run in the .NET 10 SDK container (Linux), and the
output shown is the real output. The project root namespace is `Shelf`, which is why runtime messages say `Shelf.Book`.
The project-level imports that the SDK adds (`System`, `System.Collections.Generic`, `System.Linq` and others) are why
`Console` and `List(Of T)` need no `Imports` statement.

Inheritance lets a class reuse and specialise the members of another class: a `Book` *is a* `CatalogItem`, so code that
works with catalogue items works with books, and the same call on the same variable behaves differently depending on the
object it holds. That second property is polymorphism, and it is the reason to inherit at all; sharing code is better
done by composition. The running example is the *shelf* library catalogue: an abstract `CatalogItem` with `Book` and
`Magazine` derived from it, held by a `Catalog` and lent through a `Loan`.

Visual Basic has had implementation inheritance since Visual Basic .NET 1.0 (2002). Visual Basic 6 and VBA had only
interface inheritance (`Implements`), so a programmer who comes from them must learn everything on this page; a programmer who
comes from C# knows the ideas but meets different keywords and a handful of rules that differ in ways that matter (the
order in which field initializers run, hiding by name, no covariant return types, no type patterns).

`CatalogItem` is abstract (`MustInherit`): there is no such thing as a catalogue item that is neither a book nor a
magazine, so the class cannot be instantiated, and `Kind` is a `MustOverride` member that every concrete class must
supply (the asterisk marks it as abstract in the diagram). `Describe` is `Overridable`, with a default implementation that
`Book` extends. `Loan` depends on the abstraction, so it lends books and magazines alike.

== Declaring a derived class

[source,text]
----
[attributes] [access] [Shadows] [MustInherit | NotInheritable] Class Name
    Inherits BaseClass
    ...
End Class
----

* `Inherits` must be the first statement in the class body, before any declaration (only comments and blank lines may
  precede it). A class has at most one base class (BC30121 is reported for a second name). The statement may also follow
  the class header after a colon: `Public Class LoudFormatter : Inherits Formatter`.
* The base must be a class. `Inherits IDisposable` is BC30258 ("Classes can inherit only from other classes"): to
  implement an interface use `Implements` (see
  xref:programming-languages/visual-basic/interfaces.adoc[Interfaces]). A class cannot inherit from a class declared
  `NotInheritable` (BC30299), which includes `String` and every structure.
* A class that has no `Inherits` statement inherits from `System.Object`. Every class, structure, enumeration, delegate
  and array is therefore also an `Object`.
* Structures cannot use `Inherits` (BC30628): they derive from `System.ValueType` implicitly, and enumerations from
  `System.Enum`. Modules are sealed classes that cannot be inherited either (see
  xref:programming-languages/visual-basic/modules-and-shared-members.adoc[Modules and Shared Members]).
* A derived class inherits every member of its base class except constructors and finalizers, but it can only *use* the
  ones its access level allows (see <<Access modifiers and inheritance>>).
* Classes are inheritable by default in Visual Basic, as in C#. Add `NotInheritable` to forbid it. The
  framework design guidelines recommend sealing a class that was not designed to be extended.
* A class nested in a base class is inherited as a member and can be shadowed by a nested class of the same name in the
  derived class (see <<Shadows versus Overloads versus Overrides>>).

Four facts follow from the output.

. `Object.ToString` returns the full type name (`Shelf.Plain`) unless you override it, which is why overriding `ToString` on
  every domain class is such a common first exercise.
. `Object.Equals` compares references for classes (`False` for two different instances, `True` for the same one). Value
  equality has to be written (see
  xref:programming-languages/visual-basic/operator-overloading-and-equality.adoc[Operator Overloading and Equality]).
. A `Module` is compiled to a sealed class; a structure is a `ValueType`; an enumeration is an `Enum`; an array type derives
  from `System.Array`, and a delegate type from `MulticastDelegate`.
. An interface type has no base type (`BaseType` is `Nothing`), although every object that implements it is an `Object`.

== A complete hierarchy

The following program declares `CatalogItem`, `Book` and `Magazine` as in the diagram (the ISBN is simplified to a
string so that the program stays self-contained) and uses them polymorphically through a `List(Of CatalogItem)`.

[source,vbnet]
----
Option Strict On

Public MustInherit Class CatalogItem
    Public Property Title As String
    Public Property Year As Integer

    Protected Sub New(title As String, year As Integer)
        Me.Title = title
        Me.Year = year
    End Sub

    Public MustOverride ReadOnly Property Kind As String

    Public Overridable Function Describe() As String
        Return $"{Kind}: {Title} ({Year})"
    End Function
End Class

Public Class Book
    Inherits CatalogItem

    Public ReadOnly Property Authors As New List(Of String)

    Public Sub New(title As String, year As Integer, ParamArray authors As String())
        MyBase.New(title, year)
        Me.Authors.AddRange(authors)
    End Sub

    Public Overrides ReadOnly Property Kind As String
        Get
            Return "Book"
        End Get
    End Property

    Public Overrides Function Describe() As String
        Return MyBase.Describe() & " by " & String.Join(", ", Authors)
    End Function
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Property IssueNumber As Integer

    Public Sub New(title As String, year As Integer, issueNumber As Integer)
        MyBase.New(title, year)
        Me.IssueNumber = issueNumber
    End Sub

    Public Overrides ReadOnly Property Kind As String = "Magazine"
End Class

Module Program
    Sub Main()
        ' Dim bad = New CatalogItem("x", 2020)   ' BC30569: New cannot be used on a MustInherit class
        Dim items As New List(Of CatalogItem) From {
            New Book("The Pragmatic Programmer", 1999, "Hunt", "Thomas"),
            New Magazine("Byte", 1984, 12),
            New Book("Domain-Driven Design", 2003, "Evans")
        }

        For Each item In items
            Console.WriteLine(item.Describe())
        Next

        Dim first As CatalogItem = items(0)
        Console.WriteLine(first.GetType().Name & " / " & TypeName(first))
        Console.WriteLine(first.Kind)
    End Sub
End Module
----

Magazine: Byte (1984)

----

What the example shows.

* `Protected Sub New` in an abstract class: only derived classes can call it (through `MyBase.New`), so the constructor does
  not appear in the public surface of the class. When a `MustInherit` class declares no constructor, the compiler generates a
  `Protected` one; a concrete class gets a `Public` one (verified by reflection in <<Constructors in a hierarchy>>).
* `MustOverride ReadOnly Property Kind` has no body and no `End Property`. `Book` overrides it with an explicit
  `Get` block, `Magazine` with a read-only auto-property that has an initializer (read-only auto-properties with
  initializers arrived in Visual Basic 14; overriding them is allowed).
* `Describe` is `Overridable`; `Book.Describe` calls `MyBase.Describe()` to extend the base behaviour instead of replacing it,
  and `Magazine` inherits the default.
* `Dim first As CatalogItem = items(0)` holds a `Book`. `first.GetType()` and `TypeName(first)` report the run-time class
  (`Book`), while the compiler only knows the static type (`CatalogItem`).
* The commented line shows the error BC30569 for `+New CatalogItem(...)+`: an abstract class is never instantiated.

== Abstract and sealed classes

`MustInherit` and `MustOverride` define a contract that the compiler enforces; `NotInheritable` and `NotOverridable` close a
hierarchy at the places where the design says it is finished.

[cols="2,5,4",options="header"]
|===
|Modifier |Meaning |C# equivalent
|`MustInherit` (class) |Cannot be instantiated; may contain implemented members, fields and constructors, and `MustOverride` members |`abstract class`
|`MustOverride` (member) |No body, implicitly `Overridable`; derived concrete classes must override it; the class must be `MustInherit` (BC31411) |`abstract` member
|`NotInheritable` (class) |Cannot be the base of another class (BC30299) |`sealed class`
|`NotOverridable` (member) |Only on an `Overrides` member: further derived classes cannot override it again (BC31088 without `Overrides`) |`sealed override`
|===

* A concrete class that inherits a `MustOverride` member without overriding it is rejected with BC30610 (the message lists
  the missing members). Declaring the class `MustInherit` too postpones the obligation to its own derived classes.
* `MyBase.Kind` or `MyClass.Id()` on a `MustOverride` member is BC30399 or BC30614: there is no implementation to call.
* `NotOverridable` in a `NotInheritable` class is BC30607, because nothing can override anyway. Seal the class, or
  seal the individual member, not both.
* An abstract class can implement an interface without implementing its members, by redeclaring them `MustOverride`
  (see xref:programming-languages/visual-basic/interfaces.adoc[Interfaces]).
* Visual Basic has no `static class` equivalent other than a `Module`; a `NotInheritable` class with only `Shared` members
  and a `Private Sub New` is the other way to say it.

== Overriding members

Visual Basic members are not virtual by default, as in C#. A base class opts in with `Overridable` (or `MustOverride`), and
a derived class takes part with `Overrides`. Both sides are explicit, so reading the keyword on a method tells you whether the
call is resolved at run time.

[cols="2,6,3",options="header"]
|===
|Keyword |Effect |C# equivalent
|`Overridable` |The member can be overridden; calls through a base-typed reference reach the most derived override |`virtual`
|`Overrides` |Replaces an inherited `Overridable`, `MustOverride` or already-overriding member; is itself overridable again unless `NotOverridable` is added |`override`
|`NotOverridable` |Seals an overriding member (only valid together with `Overrides`) |`sealed override`
|`MustOverride` |Declares the member without a body in a `MustInherit` class |`abstract`
|`Shadows` |Hides an inherited member of any kind by name; no run-time dispatch |`new`
|`Overloads` |Adds a member with the same name and a different signature next to the inherited ones |(implicit in C#)
|`MyBase` |Non-virtual call of the base class implementation |`base`
|`MyClass` |Non-virtual call of the member of the *current* class, ignoring overrides |no equivalent
|`Me` |The current object |`this`
|===

An override has to repeat the signature of the member it replaces. The compiler checks each part with a separate error, which
makes the messages a good checklist; every code in the table is produced by one of the listings of this page.

[cols="3,2,5",options="header"]
|===
|What must match |Error |Example
|Return type, exactly (no covariant returns) |BC30437 |`Overrides Function Self() As Book` over `Function Self() As CatalogItem`
|Access level |BC30266 |`Protected Overrides` over `Public Overridable`
|`ReadOnly` / `WriteOnly` of a property |BC30362 |adding a `Set` to an inherited read-only property
|Default values of `Optional` parameters |BC30307 |see below
|Base member must be overridable |BC31086 |`Overrides` of a plain method
|===

Two points deserve a closer look.

*No covariant return types.* C# 9 lets an override return a more derived type; Visual Basic 17.13 does not (BC30437 in the
listing above). The usual workaround is a second, non-virtual member with the more specific type.

*Optional parameters and overrides.* An override must declare the same optional parameters with the same default values, otherwise
the call would depend on the static type of the reference. The compiler refuses the mismatch with BC30307:

[source,vbnet]
----
Option Strict On

Public Class Base
    Public Overridable Function Format(value As Integer, Optional prefix As String = "base") As String
        Return prefix & ":" & value
    End Function
End Class

Public Class Derived
    Inherits Base

    Public Overrides Function Format(value As Integer, Optional prefix As String = "derived") As String
        Return "[" & MyBase.Format(value, prefix) & "]"
    End Function
End Class

Module Program
    Sub Main()
        Dim d As New Derived()
        Dim b As Base = d
        Console.WriteLine(d.Format(1))
        Console.WriteLine(b.Format(1))
    End Sub
End Module
----

=== The template method pattern

A public method that fixes an algorithm and calls `Protected` steps that derived classes may replace is the safest way to
offer extension: the base class keeps control of the order of the steps, and the extension points are small.
`Protected MustOverride` forces a subclass to supply the essential step, `Protected Overridable` offers an optional one,
and `NotOverridable Overrides` seals the diagnostic text, which is the same in every subclass.

[source,vbnet]
----
Option Strict On

Public MustInherit Class LoanPolicy
    ' Template method: the algorithm is fixed, the steps are overridable.
    Public Function DueDate(borrowed As Date) As Date
        Dim days = BaseDays()
        Dim due = borrowed.AddDays(days)
        Return AdjustForHolidays(due)
    End Function

    Protected MustOverride Function BaseDays() As Integer

    Protected Overridable Function AdjustForHolidays(due As Date) As Date
        Return due                                     ' default: no adjustment
    End Function

    Public NotOverridable Overrides Function ToString() As String
        Return Me.GetType().Name & "(" & BaseDays() & " days)"
    End Function
End Class

Public Class StandardPolicy
    Inherits LoanPolicy

    Protected Overrides Function BaseDays() As Integer
        Return 14
    End Function
End Class

Public Class WeekdayPolicy
    Inherits StandardPolicy

    Protected Overrides Function AdjustForHolidays(due As Date) As Date
        Select Case due.DayOfWeek
            Case DayOfWeek.Saturday : Return due.AddDays(2)
            Case DayOfWeek.Sunday : Return due.AddDays(1)
            Case Else : Return due
        End Select
    End Function
End Class

Public NotInheritable Class ShortPolicy
    Inherits WeekdayPolicy

    Protected Overrides Function BaseDays() As Integer
        Return MyBase.BaseDays() \ 2
    End Function
End Class

Module Program
    Sub Main()
        Dim policies As LoanPolicy() = {New StandardPolicy(), New WeekdayPolicy(), New ShortPolicy()}
        Dim borrowed As New Date(2026, 10, 17)     ' a Saturday
        For Each policy In policies
            Dim due = policy.DueDate(borrowed)
            Console.WriteLine(policy.ToString() & " -> " & due.ToString("yyyy-MM-dd ddd", Globalization.CultureInfo.InvariantCulture))
        Next
    End Sub
End Module
----

[source,text]
----
StandardPolicy(14 days) -> 2026-10-31 Sat
WeekdayPolicy(14 days) -> 2026-11-02 Mon
ShortPolicy(7 days) -> 2026-10-26 Mon
----

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/modifiers/notoverridable[NotOverridable]

* `WeekdayPolicy` overrides only the optional step and inherits the 14 days; `ShortPolicy` overrides the essential
  step and calls `MyBase.BaseDays()` (the 14 days of `StandardPolicy`) to halve it. `\` is the integer division operator.
  `ShortPolicy` inherits the weekday adjustment of its base class: 2026-10-24 is a Saturday, so the due date moves to Monday.
* `DueDate` is not overridable, so no subclass can change the algorithm. `ToString` is sealed with `NotOverridable Overrides`,
  an override of a member that was declared in `Object`, so no subclass can change the text.
* The 2026-10-17 borrow date is a Saturday. For `StandardPolicy` the due date, 14 days later, is also a Saturday.

=== How the compiler emits the modifiers

Reflection exposes what the keywords turn into in the assembly. The program prints the relevant flags for a few members of a
small hierarchy.

[source,vbnet]
----

Public MustInherit Class CatalogItem
    Public MustOverride ReadOnly Property Kind As String
    Public Overridable Function Describe() As String
        Return Kind
    End Function
    Public Function Plain() As String
        Return "plain"
    End Function
    Public Shared Function Create() As String
        Return "shared"
    End Function

Public Class Book

    Public Overrides ReadOnly Property Kind As String = "Book"
    Public Overrides Function Describe() As String
        Return "Book " & MyBase.Describe()
    End Function
End Class

    Public NotOverridable Overrides Function Describe() As String
        Return "Edition " & MyBase.Describe()

Public NotInheritable Class Rare

End Class

Module Program
    Sub Report(t As Type, name As String)

        If m Is Nothing Then
            Console.WriteLine(t.Name & "." & name & ": not declared here")

    End Sub

== Shadows versus Overloads versus Overrides

Three keywords decide what a derived-class member with the same name as an inherited one means.

* `Overrides` replaces an inherited member: the slot is shared, and the call is resolved at run time from the real class of the object.
* `Overloads` adds a member with a different signature, and keeps every inherited member of that name visible.
* `Shadows` introduces a *new* member that hides the inherited one by name, with no relation to it. A call through a
  base-typed reference still reaches the base member, and a call through a derived-typed reference reaches the new one.

[source,vbnet]
----
Option Strict On

Public Class CatalogItem
    Public Overridable Function Label() As String
        Return "CatalogItem.Label"
    End Function

    Public Function Fixed() As String
        Return "CatalogItem.Fixed"
    End Function

    Public Overridable Function Shelf() As String
        Return "CatalogItem.Shelf"
    End Function

    Public Sub Show(n As Integer)
        Console.WriteLine("CatalogItem.Show(Integer) " & n)
    End Sub

    Public Sub Show(s As String)
        Console.WriteLine("CatalogItem.Show(String) " & s)
    End Sub
End Class

Public Class Book
    Inherits CatalogItem

    Public Overrides Function Label() As String
        Return "Book.Label"
    End Function

    Public Shadows Function Fixed() As String
        Return "Book.Fixed"
    End Function

    Public Shadows Function Shelf() As String
        Return "Book.Shelf"
    End Function

    Public Overloads Sub Show(d As Double)
        Console.WriteLine("Book.Show(Double) " & d)
    End Sub
End Class

Public Class Atlas
    Inherits CatalogItem

    ' Shadows hides every Show of CatalogItem by name; without it the compiler warns (BC40003).
    Public Shadows Sub Show(d As Double)
        Console.WriteLine("Atlas.Show(Double) " & d)
    End Sub
End Class

Module Program
    Sub Main()
        Dim b As New Book()
        Dim viaBase As CatalogItem = b

        Console.WriteLine("Overrides: " & viaBase.Label() & " | " & b.Label())
        Console.WriteLine("Shadows  : " & viaBase.Fixed() & " | " & b.Fixed())
        Console.WriteLine("Shadows over Overridable: " & viaBase.Shelf() & " | " & b.Shelf())

        b.Show(1)
        b.Show("two")
        b.Show(3.5)

        Dim a As New Atlas()
        a.Show(4.5)
        a.Show(5)   ' Integer widens to Double: the base overloads are not even considered
        CType(a, CatalogItem).Show(5)
    End Sub
End Module
----

Reading the output line by line.

. `Label` is overridden: the base-typed and the derived-typed variable print the same text. This is polymorphism.
. `Fixed` is shadowed. The same object prints `CatalogItem.Fixed` through the base variable and `Book.Fixed` through the
  derived one. Shadowing is resolved at compile time from the variable's static type, which makes it a source of surprises:
  two variables for one object see two different methods.
. `Shelf` shadows an *overridable* method. It compiles without a warning because `Shadows` is explicit, and the base
  variable still reaches `CatalogItem.Shelf`. This is almost never what the author wanted; compare the warning BC40005 below.
. `Show(Double)` in `Book` is declared `Overloads`, so all three overloads are visible on a `Book`: `b.Show(1)` picks
  `Show(Integer)` from the base class.
. `Atlas.Show(Double)` is declared `Shadows` and therefore hides *both* `Show` overloads of `CatalogItem`: `a.Show(5)`
  converts the argument to `Double` and calls `Atlas.Show(Double)`, never `Show(Integer)`. Only a cast to the base type
  reaches the hidden overload.

=== Overloads Overrides, nested types and properties

`Overloads` and `Overrides` can be combined, and `Shadows` also hides nested types and properties.

[source,vbnet]
----

        Return "int:" & value
    End Function

        Return "str:" & value
    End Function

        Public Property Width As Integer = 10
    End Class

        Public Property Width As Integer = 99

a member with the *same signature*: the other overloads stay visible, which is the opposite default.

== MyBase, MyClass and Me

* `Me` is the current object, of its run-time class. A call `Me.Name()` of an `Overridable` member reaches the most
  derived override (virtual dispatch).
* `MyBase` accesses members of the immediate base class. `MyBase.Name()` is a *non-virtual* call of the base
  implementation, whatever the object is. It is how an override extends the base behaviour. `MyBase` is not a value: it
  must be followed by a dot and a member (`Return MyBase` is BC32027, see the error listing below).
* `MyClass` calls a member of the class where the call is written, *ignoring* overrides in derived classes: a non-virtual
  call of an `Overridable` method. C# has no equivalent. Use it to guarantee that the algorithm in the base class
  always uses the base implementation of a helper, or when a constructor has to call an overridable member without reaching
  the derived class.
* `+Me.New(...)+`, `+MyClass.New(...)+` and `+MyBase.New(...)+` are constructor calls; each must be the first statement of an instance
  constructor.

== Constructors in a hierarchy

* A derived-class constructor must call a base constructor. If its first statement is not `+MyBase.New(...)+` (or
  `+Me.New(...)+`/`+MyClass.New(...)+`), the compiler inserts `MyBase.New()`. When the base class has no accessible
  parameterless constructor, the compiler refuses: BC30387 for a class without any `Sub New`, BC30148 for a constructor that
  does not start with an explicit call.
* A constructor call is valid only as the first statement (BC30282).
* A class without constructors gets a default `Public Sub New()`; a `MustInherit` class gets a `Protected` one. The code
  below confirms it by reflection, together with two other defaults that differ from C#: a method without an access
  modifier is `Public`, a field declared with `Dim` is `Private`, and a top-level type without a modifier is `Friend`.

=== Initialization order, and a trap

The order in which field initializers and constructors run is the most important difference between Visual Basic and C#:

* In **C#** the field initializers of the derived class run *before* the base constructor.
* In **Visual Basic** the field initializers of the derived class run *after* the base constructor returns, right after
  the `MyBase.New` call.

This matters when a base constructor calls an overridable member: in Visual Basic the derived override sees the default
values of the derived fields.

[source,vbnet]
----
Option Strict On

Public Class Base
    Private ReadOnly _label As String = "base-field"

    Public Sub New()
        Console.WriteLine("Base.New: start")
        Console.WriteLine("Base.New: Describe() says: " & Describe())
        Console.WriteLine("Base.New: end")
    End Sub

    Public Overridable Function Describe() As String
        Return "Base.Describe (" & _label & ")"
    End Function
End Class

Public Class Derived
    Inherits Base

    Private ReadOnly _name As String = InitName("field initializer")
    Private _count As Integer = 5

    Public Sub New()
        MyBase.New()
        Console.WriteLine("Derived.New: after MyBase.New, _count = " & _count)
    End Sub

    Private Shared Function InitName(source As String) As String
        Console.WriteLine("Derived: initializing _name from " & source)
        Return "derived-field"
    End Function

    Public Overrides Function Describe() As String
        Return "Derived.Describe (_name = " & If(_name, "<Nothing>") & ", _count = " & _count & ")"
    End Function
End Class

Module Program
    Sub Main()
        Dim d As New Derived()
        Console.WriteLine(d.Describe())
    End Sub
End Module

== Run-time and compile-time polymorphism

Polymorphism in Visual Basic comes in two forms, and mixing them up is a classic source of confusion.

* *Run-time polymorphism* (also called overriding, subtype or dynamic polymorphism): the same call on a base-typed
  reference runs the method of the object's real class. It needs `Overridable`/`Overrides` (or an interface
  implementation) and is decided when the program runs.
* *Compile-time polymorphism* (overloading): several procedures with the same name but different parameters; the
  compiler picks one from the *static types* of the arguments. The object that a base-typed variable holds is not
  considered.

[source,vbnet]
----
Option Strict On

Public MustInherit Class CatalogItem
    Public Property Title As String = ""
    Public Overridable Function Describe() As String
        Return "item"
    End Function
End Class

Public Class Book
    Inherits CatalogItem
    Public Overrides Function Describe() As String
        Return "book"
    End Function
End Class

Module Program
    ' Overload resolution happens at compile time, from the static types of the arguments.
    Sub Print(item As CatalogItem)
        Console.WriteLine("Print(CatalogItem): " & item.Describe())
    End Sub

    Sub Print(book As Book)
        Console.WriteLine("Print(Book): " & book.Describe())
    End Sub

    Sub Main()
        Dim b As New Book()
        Dim asItem As CatalogItem = b

        Print(b)                    ' static type Book
        Print(asItem)               ' static type CatalogItem, although the object is a Book
        Print(DirectCast(asItem, Book))
    End Sub
End Module
----

[source,text]
----
Print(Book): book
Print(CatalogItem): book
Print(Book): book
----

Source: https://learn.microsoft.com/dotnet/visual-basic/programming-guide/language-features/objects-and-classes/overloaded-properties-and-methods[Overloaded Properties and Methods]

`Print(asItem)` calls `Print(CatalogItem)` although the object is a `Book`, and inside it `item.Describe()` is dispatched
at run time and still prints `book`. The choice of overload was made at compile time; the choice of `Describe` at run time.
To select the overload from the real class, cast first (`DirectCast(asItem, Book)`), or move the behaviour into an
overridable member of the hierarchy, which is the polymorphic solution and does not need a type test.

With `Option Strict Off`, a variable typed `Object` is *late bound*: the member is looked up when the program
runs, from the real class. That is a third form of dispatch, and it is why the late-bound code of old tutorials seems to
do polymorphism with no inheritance at all (see
xref:programming-languages/visual-basic/early-and-late-binding.adoc[Early and Late Binding]). Keep `Option Strict On` and use
an interface or a base class instead.

== Type tests and casts

[cols="3,5,3",options="header"]
|===
|Expression |Meaning |Result when it does not match
|`TypeOf x Is T` |`True` if `x` is not `Nothing` and its class is `T` *or derived from `T`* (or implements the interface `T`) |`False`
|`TypeOf x IsNot T` |`Not (TypeOf x Is T)` |`True`
|`x.GetType() = GetType(T)` |Exact class match; a derived class is *not* a match |`False`
|`GetType(T).IsInstanceOfType(x)` |Same as `TypeOf x Is T`, for a `Type` that is only known at run time |`False`
|`DirectCast(x, T)` |Reference conversion with a run-time check, no conversion functions |`InvalidCastException`
|`TryCast(x, T)` |Like `DirectCast`, but `Nothing` instead of the exception; `T` must be a reference type or a `Nullable` |`Nothing`
|`CType(x, T)` |Casts, plus every user-defined or built-in conversion (`Narrowing`/`Widening` operators) |`InvalidCastException`, or the exception of the conversion
|`x Is y` |Reference identity (the same object); does not test a type |`False`
|===

[source,vbnet]
----
Option Strict On

Public MustInherit Class CatalogItem
    Public Property Title As String = ""
    Public MustOverride ReadOnly Property Kind As String
End Class

Public Class Book
    Inherits CatalogItem
    Public Property Pages As Integer
    Public Overrides ReadOnly Property Kind As String = "Book"
End Class

Public Class Textbook
    Inherits Book
    Public Property Course As String = ""
End Class

Public Class Magazine
    Inherits CatalogItem
    Public Property IssueNumber As Integer
    Public Overrides ReadOnly Property Kind As String = "Magazine"
End Class

Module Program
    Function Summarize(item As CatalogItem) As String
        If TypeOf item Is Textbook Then
            Return "textbook for " & DirectCast(item, Textbook).Course
        ElseIf TypeOf item Is Book Then
            Return "book with " & DirectCast(item, Book).Pages & " pages"
        ElseIf TypeOf item Is Magazine Then
            Return "issue " & DirectCast(item, Magazine).IssueNumber
        End If
        Return "unknown"
    End Function

    Sub Main()
        Dim items As CatalogItem() = {
            New Book With {.Title = "Clean Code", .Pages = 464},
            New Textbook With {.Title = "Algorithms", .Course = "CS101", .Pages = 900},
            New Magazine With {.Title = "Byte", .IssueNumber = 7}
        }

        For Each item In items
            Console.WriteLine(item.Title & ": " & Summarize(item))
        Next
        Console.WriteLine()

        Dim t As CatalogItem = items(1)
        Console.WriteLine("TypeOf t Is Book       : " & (TypeOf t Is Book))
        Console.WriteLine("TypeOf t Is Textbook   : " & (TypeOf t Is Textbook))
        Console.WriteLine("t.GetType() = GetType(Book)    : " & (t.GetType() = GetType(Book)))
        Console.WriteLine("GetType(Book).IsInstanceOfType(t): " & GetType(Book).IsInstanceOfType(t))
        Console.WriteLine("TypeOf t IsNot Magazine: " & (TypeOf t IsNot Magazine))

        Dim nothingItem As CatalogItem = Nothing
        Console.WriteLine("TypeOf Nothing Is Book : " & (TypeOf nothingItem Is Book))
        Console.WriteLine("TryCast(Nothing)       : " & (TryCast(nothingItem, Book) Is Nothing))
        Console.WriteLine()

        Dim asBook As Book = TryCast(items(2), Book)
        Console.WriteLine("TryCast(magazine, Book) Is Nothing: " & (asBook Is Nothing))
        Dim viaCType As Book = CType(items(1), Book)
        Console.WriteLine("CType(textbook, Book)   : " & viaCType.Title)

        Try
            Dim wrong As Book = DirectCast(items(2), Book)
            Console.WriteLine(wrong.Title)
        Catch ex As InvalidCastException
            Console.WriteLine(ex.GetType().Name & ": " & ex.Message)
        End Try

        Select Case True
            Case TypeOf t Is Magazine : Console.WriteLine("select: magazine")
            Case TypeOf t Is Book : Console.WriteLine("select: book")
            Case Else : Console.WriteLine("select: other")
        End Select
    End Sub
End Module
----

----

Algorithms: textbook for CS101
Byte: issue 7

TypeOf t Is Textbook   : True
t.GetType() = GetType(Book)    : False

* The `Textbook` test comes first in `Summarize`: `TypeOf item Is Book` is also `True` for a `Textbook`, so the most specific
  class must be tested first. `GetType(Book)` equality is `False` for the same object. Pick the operator that matches the
  intent: `TypeOf` for "is usable as", `GetType` equality for "is exactly".
* `TypeOf Nothing Is Book` is `False` and `TryCast` of `Nothing` is `Nothing`; no `NullReferenceException`.
* The message of the `InvalidCastException` names the full class names (`Shelf.Magazine`, `Shelf.Book`). The root namespace is
  part of the name.
* `Select Case True` with `Case TypeOf t Is Magazine` is the nearest thing to a type switch: the cases are tested in
  order, so again, derived types before base types.
* `DirectCast` after a `TypeOf` test is correct but tests twice; `TryCast` followed by an `Is Nothing` check does both in one
  step and is the idiom when the cast result is needed. `TypeOf` alone is the idiom when only the answer is needed.
* The need for many `TypeOf` tests on the same hierarchy is usually a smell: add an overridable member
  to the hierarchy (the `Describe` of this page) so that each class does its own part.

== Variance and collections

A `Book` can be used wherever a `CatalogItem` is expected, but collections of books are not collections of items in general.
Visual Basic supports the .NET variance rules for generic interfaces and delegates (since Visual Basic 2010), and the array
covariance of the CLR.

[source,vbnet]
----
Option Strict On

Public MustInherit Class CatalogItem
    Public Property Title As String = ""
End Class

Public Class Book
    Inherits CatalogItem
End Class

Public Class Magazine
    Inherits CatalogItem
End Class

Module Program
    Sub PrintTitles(items As IEnumerable(Of CatalogItem))
        For Each item In items
            Console.WriteLine("  " & item.Title)
        Next
    End Sub

    Sub Main()
        Dim books As New List(Of Book) From {New Book With {.Title = "Refactoring"}}

        ' Covariance: IEnumerable(Of Book) is an IEnumerable(Of CatalogItem).
        Console.WriteLine("IEnumerable(Of T) is covariant:")
        PrintTitles(books)

        ' Contravariance: an Action(Of CatalogItem) accepts a Book.
        Dim printItem As Action(Of CatalogItem) = Sub(i) Console.WriteLine("  action got " & i.Title)
        Dim printBook As Action(Of Book) = printItem
        printBook(books(0))

        ' Arrays are covariant too, and unsafe.
        Dim bookArray As Book() = {New Book With {.Title = "Array book"}}
        Dim itemArray As CatalogItem() = bookArray
        Console.WriteLine("array covariance: " & itemArray(0).Title)
        Try
            itemArray(0) = New Magazine With {.Title = "Byte"}
        Catch ex As ArrayTypeMismatchException
            Console.WriteLine("store failed: " & ex.GetType().Name)
        End Try

        ' List(Of T) is invariant: Dim x As List(Of CatalogItem) = books fails with BC36756.
        Dim copy As New List(Of CatalogItem)(books)
        copy.Add(New Magazine With {.Title = "Byte"})
        Console.WriteLine("copy has " & copy.Count & " items, books still has " & books.Count)
    End Sub
End Module
----

[source,text]
----
IEnumerable(Of T) is covariant:
  Refactoring
  action got Refactoring
array covariance: Array book
store failed: ArrayTypeMismatchException
copy has 2 items, books still has 1
----

Source: https://learn.microsoft.com/dotnet/standard/generics/covariance-and-contravariance[Covariance and Contravariance in Generics]

* `IEnumerable(Of Book)` converts to `IEnumerable(Of CatalogItem)`: the interface is declared `Out T` (covariant), because items
  only come *out*. `Action(Of CatalogItem)` converts to `Action(Of Book)`: the delegate is declared `In T`
  (contravariant), because the argument goes *in*.
* `List(Of Book)` does not convert to `List(Of CatalogItem)` (BC36756): a class cannot be variant, because the
  list would allow `+Add(New Magazine ...)+` through the item-typed view. The message suggests `IEnumerable(Of CatalogItem)`.
  Copying (`New List(Of CatalogItem)(books)`) makes a separate list.
* Arrays are covariant, which compiles and is unsafe: storing a `Magazine` through a `CatalogItem()` that is really a
  `Book()` throws `ArrayTypeMismatchException` at run time. Prefer `IReadOnlyList(Of T)`/`IEnumerable(Of T)` for the
  parameters of methods that only read.
* Your own variant interfaces use `Out`/`In` in the declaration (see
  xref:programming-languages/visual-basic/generics.adoc[Generics]).

== Access modifiers and inheritance

[cols="2,5",options="header"]
|===
|Modifier |Visible to
|`Public` |every caller
|`Protected` |the declaring class and its derived classes, in any assembly; through a derived-typed reference only
|`Friend` |every type in the same assembly (C# `internal`)
|`Protected Friend` |the union: derived classes in any assembly, plus every type in the same assembly (C# `protected internal`)
|`Private Protected` |the intersection: derived classes *in the same assembly* only (C# `private protected`; Visual Basic 15.5)
|`Private` |the declaring type, including its nested types
|===

* A member without an access modifier is `Public` (members of types), a `Dim` field is `Private`, and a top-level type is
  `Friend`. C# defaults to `private` and `internal`.
* An override must have the same access as the member it overrides (BC30266).
* The `Protected` rule is subtle: inside `Book`, `Me.Secret()`, `MyBase.Secret()` and `otherBook.Secret()` compile, but
  `otherItem.Secret()` with `otherItem As CatalogItem` does not (BC30390, E1 in the constructor-errors listing), because the
  other object may be a `Magazine`, a sibling class whose protected members `Book` has no right to use.
* Keep the protected surface small: it is part of the public contract for every subclass, and it is as hard to change as a
  public member. The framework design guidelines list the rules.

== Events in a hierarchy

An event can be raised only by the class that declares it. A derived class that wants to raise it cannot (BC30029); the base
class offers a `Protected Overridable Sub OnXxx` method instead, which raises the event, and the derived class overrides it to
add behaviour before or after. This is the pattern of the .NET class libraries.

[source,vbnet]
----
Option Strict On

Public Class LoanEventArgs
    Inherits EventArgs
    Public ReadOnly Property Borrower As String
    Public Sub New(borrower As String)
        Me.Borrower = borrower
    End Sub
End Class

Public Class Loan
    Public Event Returned As EventHandler(Of LoanEventArgs)
    Public ReadOnly Property Borrower As String

    Public Sub New(borrower As String)
        Me.Borrower = borrower
    End Sub

    Public Sub [Return]()
        OnReturned(New LoanEventArgs(Borrower))
    End Sub

    ' The standard pattern: the event can be raised only inside the declaring class,
    ' so the class offers a Protected Overridable method for derived classes.
    Protected Overridable Sub OnReturned(e As LoanEventArgs)
        RaiseEvent Returned(Me, e)
    End Sub
End Class

Public Class AuditedLoan
    Inherits Loan

    Public Sub New(borrower As String)
        MyBase.New(borrower)
    End Sub

    Protected Overrides Sub OnReturned(e As LoanEventArgs)
        Console.WriteLine("audit: " & e.Borrower & " returned the item")
        MyBase.OnReturned(e)           ' forget this call and no handler is ever notified
    End Sub
End Class

Public Class Reader
    Public Sub Attach(loan As Loan)
        AddHandler loan.Returned, AddressOf OnLoanReturned
    End Sub

    Private Sub OnLoanReturned(sender As Object, e As LoanEventArgs)
        Console.WriteLine("reader notified: " & e.Borrower)
    End Sub
End Class

Public Class CatalogException
    Inherits Exception

    Public Sub New(message As String)
        MyBase.New(message)
    End Sub

    Public Sub New(message As String, innerException As Exception)
        MyBase.New(message, innerException)
    End Sub
End Class

Public Class DuplicateIsbnException
    Inherits CatalogException

    Public ReadOnly Property Isbn As String

    Public Sub New(isbn As String)
        MyBase.New("Duplicate ISBN " & isbn)
        Me.Isbn = isbn
    End Sub
End Class

Module Program
    Sub Main()
        Dim loan As New AuditedLoan("Ana")
        Dim reader As New Reader()
        reader.Attach(loan)
        loan.Return()

        Try
            Throw New DuplicateIsbnException("9780132350884")
        Catch ex As DuplicateIsbnException When ex.Isbn.StartsWith("978", StringComparison.Ordinal)
            Console.WriteLine("specific: " & ex.Message)
        Catch ex As CatalogException
            Console.WriteLine("general: " & ex.Message)
        End Try
    End Sub
End Module
----

[source,text]
----
audit: Ana returned the item
reader notified: Ana
specific: Duplicate ISBN 9780132350884
----

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/statements/raiseevent-statement[RaiseEvent Statement]

* `AuditedLoan` overrides `OnReturned`, does its own work and calls `MyBase.OnReturned(e)`. Forget the call and no handler is
  ever notified, and the compiler will not say so.
* The exception hierarchy at the bottom of the program shows the same shape: `DuplicateIsbnException` derives from
  `CatalogException`, which derives from `Exception` and forwards the message and the inner exception to
  `MyBase.New`. The `+Catch ... When+` filter and the order of the `Catch` blocks (most derived first) are covered in
  xref:programming-languages/visual-basic/structured-exception-handling.adoc[Structured Exception Handling]. Derive custom exceptions
  from `Exception`, not from `ApplicationException`.
* `Handles MyBase.Event` and `WithEvents` fields in a derived class are described in
  xref:programming-languages/visual-basic/events-and-handlers.adoc[Events and Handlers].

== Interfaces and inheritance

A class can implement an interface and inherit from a class; interface members implemented in a base class are
inherited by the derived classes. When the member is `Overridable`, the interface reaches the override. `Shadows` is not
an override, and the interface keeps pointing to the base member unless the derived class repeats `Implements`.

[source,vbnet]
----
Option Strict On

Public Interface IDescribable
    Function Describe() As String
End Interface

Public Class Item
    Implements IDescribable

    Public Overridable Function Describe() As String Implements IDescribable.Describe
        Return "Item"
    End Function
End Class

Public Class Book
    Inherits Item

    Public Overrides Function Describe() As String
        Return "Book"
    End Function
End Class

' Shadows without re-implementing: the interface still points at Item.Describe.
Public Class Atlas
    Inherits Item

    Public Shadows Function Describe() As String
        Return "Atlas"
    End Function
End Class

' Re-implementing the interface rebinds it to the new member.
Public Class Map
    Inherits Item
    Implements IDescribable

    Public Shadows Function Describe() As String Implements IDescribable.Describe
        Return "Map"
    End Function
End Class

Module Program
    Sub Main()
        Dim book As New Book()
        Dim atlas As New Atlas()
        Dim map As New Map()

        For Each d As IDescribable In New IDescribable() {book, atlas, map}
            Console.WriteLine("via interface: " & d.Describe())
        Next
        Console.WriteLine("via Item   : " & CType(atlas, Item).Describe() & ", " & CType(map, Item).Describe())
        Console.WriteLine("via Atlas  : " & atlas.Describe())
        Console.WriteLine("via Map    : " & map.Describe())
    End Sub
End Module
----

[source,text]
----
via interface: Book
via interface: Item
via interface: Map
via Item   : Item, Item
via Atlas  : Atlas
via Map    : Map
----

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/statements/implements-statement[Implements Statement]

* `Book` overrides `Describe`: the interface reaches `Book.Describe` (`Book`).
* `Atlas` shadows it: through the interface, `Item.Describe` still runs (`Item`); only through an `Atlas` variable does the new method run.
* `Map` repeats `Implements IDescribable` and names the interface member on its own method (interface
  re-implementation), so the interface reaches `Map.Describe` (`Map`), while a plain `Item` variable still reaches `Item.Describe`.

An abstract class can implement an interface partially: it redeclares the members it does not want to implement as
`MustOverride`, keeping the `Implements` clause on them, and the derived classes override them.

End Interface

    Implements IDescribable

    Public MustOverride Function Describe() As String Implements IDescribable.Describe
End Class

Public Class Book
    Inherits CatalogItem

    Public Overrides Function Describe() As String
        Return "Book"
    End Function
End Class

Module Program
    Sub Main()
        Dim d As IDescribable = New Book()
        Console.WriteLine(d.Describe())
    End Sub
End Module
----

----

----

xref:programming-languages/visual-basic/interfaces.adoc[Interfaces].

== Members every object inherits

`Object` contributes `ToString`, `Equals`, `GetHashCode`, `GetType`, the protected `MemberwiseClone` and `Finalize`, and
the static `Equals` and `ReferenceEquals`. The ones worth overriding in a domain class are described here only as they
relate to inheritance; the details are in other pages.

* `ToString` is `Overridable`; override it with `Public Overrides Function ToString() As String`. Seal it with `NotOverridable`
  when subclasses must not change the text, as the template-method example does.
* `Equals`/`GetHashCode` must be overridden together and be consistent across the hierarchy; a derived class that adds
  fields to the equality must be careful not to break symmetry with its base class (see
  xref:programming-languages/visual-basic/operator-overloading-and-equality.adoc[Operator Overloading and Equality]).
* `Finalize` is `Protected Overrides` in Visual Basic and almost never needed; implement `IDisposable` instead (see
  xref:programming-languages/visual-basic/object-lifetime-and-disposal.adoc[Object Lifetime and Disposal]).
* `MemberwiseClone` is `Protected`, so only the class itself (or a derived class) can call it, from a method such as
  `ShallowCopy`. It copies the fields bit by bit: value-type fields are duplicated, but reference-type fields are
  *shared* between the original and the copy.

[source,vbnet]
----
Option Strict On

Public Class Author
    Public Property Name As String = ""
End Class

Public Class Shelf2
    Public Property Label As String = ""
    Public Property Owner As New Author()
    Public Property Tags As New List(Of String)

    Public Function ShallowCopy() As Shelf2
        Return DirectCast(MemberwiseClone(), Shelf2)    ' Protected member of Object
    End Function
End Class

Module Program
    Sub Main()
        Dim a As New Shelf2 With {.Label = "Fiction"}
        a.Owner.Name = "Ana"
        a.Tags.Add("novel")

        Dim b As Shelf2 = a.ShallowCopy()
        b.Label = "Poetry"
        b.Owner.Name = "Ben"
        b.Tags.Add("verse")

        Console.WriteLine(a.Label & " / " & a.Owner.Name & " / " & String.Join(",", a.Tags))
        Console.WriteLine(b.Label & " / " & b.Owner.Name & " / " & String.Join(",", b.Tags))
        Console.WriteLine(Object.ReferenceEquals(a.Owner, b.Owner))
    End Sub
End Module
----

[source,text]
----
Fiction / Ben / novel,verse
Poetry / Ben / novel,verse
True
----

Source: https://learn.microsoft.com/dotnet/api/system.object.memberwiseclone[Object.MemberwiseClone]

Changing `b.Label` did not change `a.Label` (the field of the copy was reassigned), but `b.Owner.Name` and `b.Tags`
changed the objects that both copies refer to, which `ReferenceEquals` confirms. If a deep copy is needed, write it by hand
or use a copy constructor; a clone method on a hierarchy needs an override on every class, which is one more reason to
prefer copy constructors.

== Designing hierarchies

* *Is-a, not has-a.* A `Loan` is not a `CatalogItem`; it *has* one. Inheritance couples a class to the internals of its
  base class. Prefer composition (a field that holds another object, and delegates to it) and interfaces unless the
  derived class really is a specialisation that can stand in for the base in every context (the Liskov substitution
  principle).
* *Design for inheritance or prohibit it.* A class that is meant to be extended documents which `Overridable` members call which
  others, and which are safe to override. A class that is not meant to be extended is `NotInheritable`. Every `Overridable`
  member is a promise that the next version of the base class has to keep, so add extension points deliberately, as the
  framework design guidelines advise.
* *Fragile base class.* Adding or changing an `Overridable` member in the base class can break derived classes in other
  assemblies even without changing the signature, for example by calling it from a different place. Another reason to make
  the template method the only extension mechanism.
* *Keep hierarchies shallow.* Two or three levels are common; five are a design question. Abstract base classes are most useful
  when they hold shared state and algorithms (the `LoanPolicy` example), interfaces when only a contract is shared.
* *Do not use inheritance for reuse alone.* A `Stack` that inherits from `List` exposes insert and remove at any position.
  Wrap, do not inherit.
* *Inheriting from framework classes* is the common case: `Exception`, `EventArgs`, `Collection(Of T)` (override
  `InsertItem`, `SetItem`, `RemoveItem`), `Stream`, `DbContext`, `Form` and `UserControl`. Read the documentation of the base
  for the members intended to be overridden, and call the `MyBase` version unless it says otherwise.
* Where a hierarchy would need more than one base class, use interfaces plus composition. Visual Basic has no multiple class
  inheritance, and no mixins or traits.

== Differences from C# at a glance

[cols="3,3,3",options="header"]
|===
|Topic |Visual Basic |C#
|Declare inheritance |`Inherits Base` as the first statement of the body |`class Derived : Base`
|Make virtual / override |`Overridable` / `Overrides` |`virtual` / `override`
|Abstract / sealed |`MustInherit`, `MustOverride` / `NotInheritable`, `NotOverridable` |`abstract` / `sealed`
|Hide a member |`Shadows` (hides by name, all overloads) |`new` (hides by signature)
|Forgetting the keyword |warning BC40003 / BC40005 |warning CS0108 / CS0114
|Call the base implementation |`MyBase.Name()` |`base.Name()`
|Non-virtual call in the same class |`MyClass.Name()` |not possible
|Constructor chaining |`+MyBase.New(...)+` / `+Me.New(...)+` as the first statement |`+: base(...)+` / `+: this(...)+` after the signature
|Derived field initializers |run **after** the base constructor |run **before** the base constructor
|Covariant return types |not supported (BC30437) |supported since C# 9
|Type patterns (`x is Book b`) |not supported; `TypeOf` + `DirectCast`/`TryCast` |supported
|Default member access |`Public` |`private`
|Default constructor of an abstract class |`Protected` |`protected`
|Intersection of `Protected` and `Friend` |`Private Protected` (VB 15.5) |`private protected`
|Class inheritable by default |yes |yes
|Interface member in base, re-implementation |repeat `Implements` on the derived class |repeat the interface in the derived class
|===

The same hierarchy in C# has the following shape, which is what a C# consumer of a Visual Basic class library sees:

[source,csharp]
----
public abstract class CatalogItem
{
    protected CatalogItem(string title, int year) { Title = title; Year = year; }
    public string Title { get; set; }
    public int Year { get; set; }
    public abstract string Kind { get; }
    public virtual string Describe() => $"{Kind}: {Title} ({Year})";
}

public class Book : CatalogItem
{
    public Book(string title, int year, params string[] authors) : base(title, year) { Authors.AddRange(authors); }
    public List<string> Authors { get; } = new();
    public override string Kind => "Book";
    public override string Describe() => base.Describe() + " by " + string.Join(", ", Authors);
}
----

More on the C# side is in xref:programming-languages/csharp/inheritance-and-polymorphism.adoc[Inheritance and Polymorphism] in
the C# reference. Cross-language use of a Visual Basic hierarchy is covered in
xref:programming-languages/visual-basic/interop-with-csharp-and-other-dotnet-languages.adoc[Interop with C# and Other .NET Languages].

== Older material you may meet

* Visual Basic 6 and VBA have no implementation inheritance. Tutorials for them simulate it with `Implements` and
  delegation (a field that holds an inner object, and wrapper methods); in Visual Basic .NET use `Inherits` where the
  relation is is-a, and keep the delegation where it is has-a.
* `Class_Initialize` and `Class_Terminate` correspond to `Sub New` and, rarely, `Finalize` or `IDisposable`; the base
  class constructor must be called with `MyBase.New`, which VB6 had no concept of.
* Early Visual Basic .NET texts (2002 and 2003) derive exceptions from `ApplicationException` and omit `Option Strict On`;
  the examples here use neither.
* Texts that explain polymorphism with a hierarchy of shapes or animals and a cascade of `+TypeOf ... Is+` tests are showing
  the pattern that this page recommends replacing with an overridable member.
* Code written for `Option Strict Off` can call members on an `Object` variable and appear to be polymorphic without a common base;
  that is late binding (see
  xref:programming-languages/visual-basic/early-and-late-binding.adoc[Early and Late Binding]).
