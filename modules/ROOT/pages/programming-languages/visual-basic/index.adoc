This section is written against *Visual Basic 17.13 on .NET 10 (LTS)* with the .NET SDK 10.0.402 and Visual Studio 2026, checked on 2026-10-19. .NET 10 is supported until 2028-11-14. .NET 11 was still a release candidate on the check date (SDK 11.0.100-rc.2, general availability expected in November 2026), so it is treated as upcoming, and its compiler accepts the same `LangVersion` values as the .NET 10 one. Windows-only examples (Windows Forms, WPF, COM, `Declare` against Windows libraries, `My.Computer` devices) were built but not run.

== What Visual Basic is

Visual Basic is a statically typed (optionally late-bound), case-insensitive, object-oriented language for .NET with English-like syntax. It descends from BASIC and from Visual Basic 6, which Microsoft replaced in 2002 with a language that shares the name and much of the spirit but runs on the common language runtime: the Roslyn compiler turns `.vb` files into IL, and the same libraries, tools and runtime serve C# and F#. Visual Basic is stable and maintained by Microsoft, and it is strongest for Windows desktop applications, class libraries, automation and the large body of existing code that has to be kept running.

Microsoft's language strategy is the one thing to know before choosing it for new work: Visual Basic is kept stable, it receives the features that .NET and its runtime require it to consume (a "consumption-only" approach), it is not extended to new workloads, and the Visual Studio tooling for it keeps being maintained. In practice that means Windows Forms, WPF, console programs, libraries and tests in Visual Basic are fully supported on .NET 10, while ASP.NET Core web applications, Blazor, .NET MAUI and WinUI 3 are built in C#, with Visual Basic libraries behind them where that helps. The dated sources are on xref:programming-languages/visual-basic/history-versions-and-language-strategy.adoc[History, Versions and Language Strategy] and xref:programming-languages/visual-basic/visual-basic-and-dotnet.adoc[Visual Basic and .NET].

== The shelf scenario

The examples across the section share one small, original domain: *shelf*, a library catalogue written as a .NET solution (`Shelf.slnx`). It is deliberately the same domain as the xref:programming-languages/rust/index.adoc[Rust Reference], the xref:programming-languages/go/index.adoc[Go Reference] and the xref:programming-languages/ruby/index.adoc[Ruby Reference], so you can compare the languages on the same types.

* `Shelf.Core` holds `Isbn` (a validated value object), `Book`, `Author`, `LoanState`, `Loan`, `CatalogItem` with its `Magazine` subtype, the `ICatalogStore` interface and the `Catalog` that uses it.
* `Shelf.Data` offers in-memory, JSON and SQLite with EF Core stores.
* `Shelf.Cli` is a console program that reads CSV with `TextFieldParser`, builds XML with literals, queries with LINQ and looks up ISBNs asynchronously.
* `Shelf.Desktop` (Windows Forms) and `Shelf.Wpf` (WPF) are the graphical fronts, and `Shelf.Tests` (with xUnit and NUnit variants) holds the tests.
* A small legacy corner shows the old `On Error` and late-bound style next to its modern replacement.

== Coming from VB6, VBA or VBScript?

Visual Basic 6, Office VBA and VBScript are relatives, not versions, of the language in this section: they have their own runtimes, type systems, error handling and object models, and their own support stories (the VB6 runtime is supported only as part of Windows, and VBScript is deprecated). Start with xref:programming-languages/visual-basic/the-vb-family-vb6-vba-and-vbscript.adoc[The VB Family: VB6, VBA and VBScript] to see how they differ, then read xref:programming-languages/visual-basic/migrating-legacy-visual-basic.adoc[Migrating Legacy Visual Basic] for the migration paths and the legacy-to-modern table. The legacy constructs that still compile are explained on xref:programming-languages/visual-basic/unstructured-error-handling-on-error.adoc[Unstructured Error Handling (On Error)] and xref:programming-languages/visual-basic/early-and-late-binding.adoc[Early and Late Binding], and old books and tutorials are corrected in prose on the page that covers each concept.
