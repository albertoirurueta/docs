This page is written against Visual Basic 17.13 on .NET 10 (SDK 10.0.402) and was checked on 2026-10-19. A conversion changes how a value
is represented, so that it can be stored in a variable or passed to a parameter of another type. Visual Basic has more conversion
syntax than most languages, and each form has different rules for what it accepts, what it rounds, which culture it reads and which exception
it throws: the sixteen conversion functions (`CInt` and its relatives), the operators `CType`, `DirectCast` and `TryCast`, the
type test `+TypeOf ... Is+`, the `Convert` class, `Parse` and `TryParse`, and conversion operators that a type defines
for itself. This page puts them side by side. The rule that decides how many of them are allowed implicitly is
`Option Strict`, described on xref:programming-languages/visual-basic/option-statements.adoc[Option Statements]; the types themselves on
xref:programming-languages/visual-basic/data-types-and-literals.adoc[Data Types and Literals].

The page covers the following, in this order: widening and narrowing with the complete matrix produced by the compiler; the conversion
functions; the cast operators; text and culture; user-defined conversions; variance; enumerations and `Boolean`; a decision
flowchart; the exceptions; and the differences from C#. Operators and their result types are on
xref:programming-languages/visual-basic/operators-and-expressions.adoc[Operators and Expressions] and string formatting on
xref:programming-languages/visual-basic/strings-and-text.adoc[Strings and Text].

Every example is a complete program that was built with `Option Strict On` and warnings as errors on the .NET 10 SDK and run; the
output is the real one. The programs are small by design, and use the shelf catalogue's types (`CatalogItem`, `Book`, `Magazine`,
`Isbn`, `LoanState`). Examples that are meant not to compile are labelled and show the compiler's messages.

== Widening and narrowing

A conversion is *widening* when every value of the source type can be represented in the target type's range, and *narrowing* when
some cannot. Learn's definition adds that a widening conversion can still lose precision (`Long` to `Double` keeps the magnitude but not all the digits), so
widening is a statement about range and not about exactness. A conversion is *implicit* when the compiler applies it without being asked, and
*explicit* when the source code asks for it with a function or an operator. The rules:

* Widening conversions are always allowed implicitly, and never throw.
* Narrowing conversions are allowed implicitly only with `Option Strict Off`, where a failure appears at run time. With `Option Strict On` every narrowing conversion
  needs an explicit conversion (BC30512 otherwise).
* A constant that fits the target type converts implicitly in either direction (`Dim b As Byte = 200`).
* The `For Each` loop variable is the documented exception: its narrowing conversion from the element type is not checked at compile time.

The compiler can tell which pair is which, so the matrix below was *generated*: a program of 240 one-line assignments, `Dim t As Target = v`
for every ordered pair of the sixteen elementary types with `v` of the source type, was built with `Option Strict On`, and the pairs that produced no error are widening. It was
built only; the 179 diagnostics are the pairs that are not.

=== Plus is not concatenation

Visual Basic converts the operands of `pass:c[+]` toward numbers when one of them is a string, which is the origin of the best-known conversion bug of the language.
With `Option Strict On` the compiler stops it, and the messages show the two conversions that it refused:

[source,vbnet]
----
Option Strict On

Module Program
    Sub Main()
        Dim copies As Integer = 3
        Dim label As String = "Copies: " + copies
        Dim total As Integer = "5" + 1
        Dim joined As String = "Copies: " & copies
        Dim sum As String = "5" & 1 & 2
        Dim d As Date = #10/19/2026# + 1
    End Sub
End Module
----

----

Program.vb(6,31): error BC30512: Option Strict On disallows implicit conversions from 'Double' to 'String'.
Program.vb(6,31): error BC30512: Option Strict On disallows implicit conversions from 'String' to 'Double'.
Program.vb(7,32): error BC30512: Option Strict On disallows implicit conversions from 'Double' to 'Integer'.
Program.vb(7,32): error BC30512: Option Strict On disallows implicit conversions from 'String' to 'Double'.

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/operators/concatenation-operators[Concatenation Operators]

Each of lines 6 and 7 reports two BC30512 errors: the `String` operand would be converted to `Double` and the `Double` result converted back. The two
`&` lines compile, because every conversion to a string by the concatenation operator is considered widening. The last line shows that `pass:c[Date + Integer]` has
no meaning at all (BC30452, "Operator '+' is not defined"); `Date` arithmetic uses `AddDays` and its relatives. *Quickstart Guide* pp. 18 and 134 concatenate
with `pass:c[+]`; the correct operator is `&`, or an interpolated string.

== The conversion functions

The sixteen conversion functions are keywords of the language, one per elementary type. Each converts its argument to the target type, and
the compiler inlines the common cases. They are the usual way to write an explicit conversion between built-in types.

[cols="2,2,6",options="header"]
|===
| Function | Returns | Notes

| `CBool`
| `Boolean`
| Zero is `False`, any other number `True`. A string must be `"True"`, `"False"` or a number (`"1"` gives `True`); anything else is `InvalidCastException`.

| `CByte`
| `Byte`
| Rounds, then range-checks 0 to 255.

| `CChar`
| `Char`
| The first character of a string. An empty string gives `ChrW(0)`. Numbers do not convert (BC32007).

| `CDate`
| `Date`
| Parses the string with the *current culture*; `"2026-10-19"` works everywhere, `"31/12/2026"` only where day-first is the culture.

| `CDbl`
| `Double`
| Accepts exponents (`"1.5e2"`), whitespace, culture-specific separators.

| `CDec`
| `Decimal`
| From `Double` it rounds to 15 significant digits first, so `CDec(0.1)` is `0.1`, unlike the exact binary value of the double.

| `CInt`
| `Integer`
| Rounds half to even. Strings may be decimal or carry a `&H` or `&O` prefix.

| `CLng`
| `Long`
| As `CInt`.

| `CObj`
| `Object`
| Boxes a value type; never fails.

| `CSByte`
| `SByte`
| Range-checks -128 to 127.

| `CShort`
| `Short`
| As `CInt`.

| `CSng`
| `Single`
| Rounds to the nearest `Single`.

| `CStr`
| `String`
| `True` gives `"True"`, numbers and dates are formatted with the current culture, `Nothing` gives `Nothing`. Return values are tabulated in Learn's article on `CStr`.

| `CUInt`
| `UInteger`
| Negative values throw `OverflowException`.

| `CULng`
| `ULong`
| As `CUInt`.

| `CUShort`
| `UShort`
| As `CUInt`.
|===

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/functions/type-conversion-functions[Type Conversion Functions]

The program below applies the functions to values from the shelf scenario (a quantity typed as text, a price, a due date) and prints

        Catch ex As Exception
            shown = ex.GetType().Name & ": " & ex.Message

        Console.WriteLine(label.PadRight(26) & shown)
    End Sub

What the output teaches:

* `CInt("&H1F")` is 31: a string with a radix prefix is parsed as hexadecimal, which neither `Integer.Parse` nor C# does.
* `CInt(Nothing)` is 0, but `CInt("")` is `InvalidCastException`. A null `String` or `Object` reads as zero; an empty string is not a number.
* `CInt(3.99)` is 4: the conversion functions round to the nearest, they do not truncate (next section).
* `CInt(True)` is -1 (see the section on `Boolean`).
* `CInt(3000000000L)`, `CByte(300)`, `CByte(-1)`, `CUInt(-1)` and `CSByte(300)` throw `OverflowException`, "Arithmetic operation resulted in an overflow.", and so does
  a floating-point `NaN` stored in a variable. The compiler folds conversions of *constants*: `CInt(Double.NaN)` written with the constant compiled and
  was folded to 0 by the compiler with no diagnostic in an earlier build of this program, whereas the same conversion of a variable throws. Do not use a conversion of a constant to test the run-time behaviour.
* `CBool("yes")` throws `InvalidCastException`, "Conversion from string "yes" to type 'Boolean' is not valid."
* `CChar("")` is the NUL character (code 0), and `CChar("hello")` is `h`.
* `CDbl("1.5e2")` is 150 and `CDec(0.1)` is exactly `0.1`.
* `CDate("31/12/2026")` fails here because the process runs with the invariant culture, whose short date is month first.

=== Banker's rounding

When the argument is not integral, the integer conversion functions round to the nearest integer, and a value exactly halfway rounds to the
*even* neighbour (banker's rounding, IEEE 754 round half to even): 0.5 becomes 0, 1.5 becomes 2, 2.5 becomes 2 and 3.5 becomes 4. This is a
difference from C#, whose cast `(int)x` truncates toward zero. The next program prints the rounding family together, so you can pick the one you mean:

[source,vbnet]
----
Option Strict On

Imports System.Globalization

Module Program
    Sub Main()
        Dim inv As CultureInfo = CultureInfo.InvariantCulture
        Dim values As Double() = {-2.5, -1.5, -0.7, -0.5, 0.5, 1.5, 2.5, 2.7, 3.5}
        Console.WriteLine("value  CInt  Math.Round  AwayFromZero  Fix  Int  Floor  Ceiling  Truncate")
        For Each v In values
            Console.WriteLine(v.ToString("0.0", inv).PadLeft(5) & "  " &
                              CInt(v).ToString().PadLeft(4) & "  " &
                              Math.Round(v).ToString("0", inv).PadLeft(10) & "  " &
                              Math.Round(v, MidpointRounding.AwayFromZero).ToString("0", inv).PadLeft(12) & "  " &
                              Fix(v).ToString("0", inv).PadLeft(3) & "  " &
                              Int(v).ToString("0", inv).PadLeft(3) & "  " &
                              Math.Floor(v).ToString("0", inv).PadLeft(5) & "  " &
                              Math.Ceiling(v).ToString("0", inv).PadLeft(7) & "  " &
                              Math.Truncate(v).ToString("0", inv).PadLeft(8))
        Next

        ' Integer division truncates toward zero and works on integers; / returns a Double first.
        Dim total As Integer = 7
        Dim count As Integer = 2
        Console.WriteLine("7 \ 2 = " & (total \ count).ToString() & ", -7 \ 2 = " & (-total \ count).ToString() &
                          ", CInt(7 / 2) = " & CInt(total / count).ToString() & ", CInt(-7 / 2) = " & CInt(-total / count).ToString())

        ' Decimal rounds the same way: banker's rounding to even.
        Console.WriteLine("CInt(2.5D) = " & CInt(2.5D).ToString() & ", CInt(3.5D) = " & CInt(3.5D).ToString() & ", Math.Round(2.675D, 2) = " & Math.Round(2.675D, 2).ToString(inv))

        ' The optimized pattern of Visual Basic 16: the argument is already integral.
        Dim s As Single = 173.7619F
        Dim d As Double = s
        Console.WriteLine(CInt(Fix(s)).ToString() & " " & CByte(Int(d)).ToString() & " " & CShort(Math.Truncate(s)).ToString() & " " &
                          CInt(Math.Ceiling(d)).ToString() & " " & CInt(Math.Round(s)).ToString())
    End Sub
End Module
----

Compare the columns row by row. `CInt` and `Math.Round(v)` agree: both round half to even, `-2.5` to `-2` and `2.5` to `2`. `MidpointRounding.AwayFromZero` is the school rule (`2.5` to `3`, `-2.5` to `-3`)
and the one to use for money when the business says "round half up". `Fix` and `Math.Truncate` drop the fraction toward zero; `Int` and `Math.Floor` go toward negative
infinity (`-2.5` gives `-3`); `Math.Ceiling` toward positive infinity. Several cells print `-0`: `Fix`, `Math.Ceiling`, `Math.Truncate` and `Math.Round` of values between -1 and 0 return the `Double` negative zero, and the formatting of
.NET Core 3.0 and later shows its sign. The last lines show that the integer division `\` truncates toward zero (`-7 \ 2` is -3) and that `CInt(7 / 2)` rounds the
`Double` 3.5 to 4: the same two numbers, two different answers. `Decimal` rounds the same way as `Double`: `CInt(2.5D)` is 2 and `CInt(3.5D)` is 4.

=== Fix, Int and the Visual Basic 16 optimization

`Fix` and `Int` are runtime-library functions that return the integral part of a number: `Fix` drops the fraction (toward zero), `Int` rounds toward negative infinity. Both
return the same type as the argument, so `Fix(173.7619)` is the `Double` 173 and a conversion is needed to store it in an `Integer`. Visual Basic 16.0 (2019) made the
combination fast: when the argument of `CByte`, `CShort`, `CInt`, `CLng`, `CSByte`, `CUShort`, `CUInt` or `CULng` is the result of `Fix`, `Int`, `Math.Ceiling`, `Math.Floor`, `Math.Round` or
`Math.Truncate` on a `Double` or `Single`, the conversion is much faster; Learn says up to twice as fast for code with many
conversions, and that the optimization truncates rather than rounds. The argument is already a whole number in these cases, so the value is the same either way. The last output line of the program above applies the five pairs of the
documentation example to `173.7619` and prints `173 173 173 174 174`.

== CType, DirectCast and TryCast

The three operators convert between *any* types, not only built-in ones, and differ in what they are allowed to do:

[cols="2,3,3,3",options="header"]
|===
| Operator | What it does | Fails with | Typical use

| `CType(x, T)`
| Chooses the conversion at compile time from the static types: a built-in conversion, a user-defined one, a reference conversion or unboxing; with an `Object` source, a run-time conversion through the Visual Basic helpers (`CType(obj, Integer)` converts a `Short`, a `String` or a `Boolean`).
| `InvalidCastException`, `OverflowException`.
| The general explicit conversion, and the only operator that uses user-defined conversions.

| `DirectCast(x, T)`
| A reference cast or an unboxing. No helper is called and nothing is converted: the run-time type of the object must be `T` or derive from or implement it. For value types, *exactly* `T`.
| `InvalidCastException` when the type is wrong. `Nothing` is cast to `Nothing` for a reference type.
| Downcasts that you know are right, and unboxing. Learn notes that it has a small performance advantage over `CType` when converting to and from `Object`.

| `TryCast(x, T)`
| As `DirectCast` for reference types, but returns `Nothing` instead of throwing.
| Nothing; but `T` must be a reference type (BC30792 otherwise, `Integer?` included).
| A downcast that may legitimately be wrong, followed by `If result IsNot Nothing`.

| `TypeOf x Is T`
| `True` when `x` is not `Nothing` and its run-time type is `T`, derives from it or implements it. `IsNot` since Visual Basic 14.
| Nothing; the left operand must have a reference type (BC30021 for an `Integer` expression).
| The guard before a `DirectCast`.
|===

Source: https://learn.microsoft.com/dotnet/visual-basic/language-reference/operators/directcast-operator[DirectCast Operator]

== Text, culture and Parse

Converting between text and values is where conversion bugs live, because the same text means different things in different cultures and because users type incorrect text. There are
three families, with different defaults:

[cols="2,3,3,3",options="header"]
|===
| Family | Culture | On bad input | Notes

| `CInt`, `CDbl`, `CDate`, `CStr`, `Val`
| The *current culture*, except `Val`, which is always invariant.
| `InvalidCastException` (and `OverflowException` for range).
| Short, forgiving (`&H` prefix, whitespace). Right for text that came from the same user's culture.

| `Convert.ToInt32`, `Convert.ToBoolean`, ...
| The current culture, with an `IFormatProvider` overload.
| `FormatException`, `OverflowException`. `Nothing` gives 0 for numbers.
| Rounds like `CInt`; `Convert.ToInt32(True)` is 1, not -1.

| `Integer.Parse`, `Double.Parse`, `Date.ParseExact`
| The current culture unless you pass one.
| `FormatException`, `OverflowException`, `ArgumentNullException`.
| Explicit `NumberStyles` and `CultureInfo`. The right choice for data formats.

| `Integer.TryParse`, `Date.TryParseExact`, ...
| As `Parse`.
| Return `False`; the `ByRef` result is 0 or the default.
| The right choice for user input.
|===

Source: https://learn.microsoft.com/dotnet/visual-basic/programming-guide/language-features/data-types/conversions-between-strings-and-other-types[Conversions Between Strings and Other Types]

Reading it:

* `CStr(1234.5)` is `1234.5` in `en-US` and `1234,5` in `de-DE`. Text that is stored in a file or sent over a network must use `ToString(CultureInfo.InvariantCulture)`.

* `Val` does not look at the culture: it reads digits and the period, stops at the first other character and returns a `Double`, so `Val("1234.5abc")` is 1234.5 everywhere. It is also silent about
  bad input (`Val("abc")` is 0), which is why it has no place in validation.
* `CDate("10/11/2026")` is 11 October in `en-US` and 10 November in `de-DE`. Date text without a year-first format is ambiguous: store `yyyy-MM-dd`, parse with `Date.TryParseExact`, and
  never rely on `CDate`.
* `+Double.TryParse("1,5", NumberStyles.Float, ...)+` is `False` with the invariant culture and `True` (value 1.5) with `de-DE`.

== User-defined conversions

A `Structure` or a `Class` can define conversions to and from other types with the `Widening` and `Narrowing` operator forms. A `Widening` conversion is implicit and must never
fail or lose information; a `Narrowing` conversion has to be written with `CType` (or a conversion function, with `Option Strict On`) and may throw. The following structure is the shelf's ISBN, with the
two forms. Every `Isbn` is a valid `String`, so conversion to `String` is widening. Not every `String` is an `Isbn`, so the conversion from `String` validates, throws and is narrowing:

[source,vbnet]
----
Option Strict On

Public Structure Isbn
    Implements IEquatable(Of Isbn)

    Public ReadOnly Property Value As String

    Private Sub New(value As String)
        Me.Value = value
    End Sub

    Public Shared Function TryParse(text As String, ByRef result As Isbn) As Boolean
        Dim digits As String = If(text, "").Replace("-", "")
        If digits.Length = 13 AndAlso digits.All(AddressOf Char.IsDigit) AndAlso HasValidCheckDigit(digits) Then
            result = New Isbn(digits)
            Return True
        End If
        Return False
    End Function

    Private Shared Function HasValidCheckDigit(digits As String) As Boolean
        Dim sum As Integer = 0
        For i As Integer = 0 To 12
            Dim digit As Integer = AscW(digits(i)) - AscW("0"c)
            sum += If(i Mod 2 = 0, digit, digit * 3)
        Next
        Return sum Mod 10 = 0
    End Function

    ' Every Isbn is a valid String, so this conversion can never fail and may be implicit.
    Public Shared Widening Operator CType(isbn As Isbn) As String
        Return isbn.Value
    End Operator

    ' Not every String is an Isbn: the conversion validates, throws, and must be written explicitly.
    Public Shared Narrowing Operator CType(text As String) As Isbn
        Dim result As Isbn = Nothing
        If Not TryParse(text, result) Then
            Throw New InvalidCastException("'" & text & "' is not a valid ISBN-13.")
        End If
        Return result
    End Operator

    Public Overloads Function Equals(other As Isbn) As Boolean Implements IEquatable(Of Isbn).Equals
        Return Value = other.Value
    End Function

    Public Overrides Function ToString() As String
        Return Value
    End Function
End Structure

Module Program
    Private Function Shout(text As String) As String
        Return "[" & text.ToUpperInvariant() & "]"
    End Function

    Sub Main()
        Dim isbn As Isbn = CType("978-0-441-01359-3", Isbn)
        Dim asText As String = isbn
        Console.WriteLine("widening, no cast needed : " & asText & " (" & asText.Length.ToString() & " characters)")
        Console.WriteLine("as a String argument     : " & Shout(isbn))
        Try
            Dim bad As Isbn = CType("978-0-441-01359-4", Isbn)
            Console.WriteLine(bad)
        Catch ex As InvalidCastException
            Console.WriteLine("narrowing, bad check digit: " & ex.Message)
        End Try

        ' The conversion operator is chosen at compile time from the static types. DirectCast never uses it,
        ' and CType on an Object only unboxes: a String inside an Object is not turned into an Isbn.
        Dim boxed As Object = isbn
        Console.WriteLine("DirectCast(boxed, Isbn)  : " & DirectCast(boxed, Isbn).Value)
        Dim hidden As Object = "9780441013593"
        Try
            Console.WriteLine(DirectCast(hidden, Isbn))
        Catch ex As InvalidCastException
            Console.WriteLine("DirectCast of an Object String: " & ex.GetType().Name)
        End Try
        Try
            Console.WriteLine(CType(hidden, Isbn))
        Catch ex As InvalidCastException
            Console.WriteLine("CType of an Object String     : " & ex.GetType().Name)
        End Try
        Console.WriteLine("CType of a typed String       : " & CType(DirectCast(hidden, String), Isbn).Value)
    End Sub
End Module

The rules that follow:

* The conversion operator is `Public Shared Widening|Narrowing Operator CType(parameter As From) As To`, and *either* `From` or `To` has to be the type that declares it.
* A conversion cannot be defined between a type and its base type or an interface it implements, nor from or to `Object`; those exist already as reference conversions.
* The compiler chooses the operator from the *static* types at compile time. A `String` that arrives inside an `Object` is not converted: the last two attempts of the program, `DirectCast(hidden, Isbn)` and `CType(hidden, Isbn)`, both throw
  `InvalidCastException` although `CType` of a typed `String` works. `DirectCast` and `TryCast` never use user-defined conversions.
* An implicit widening conversion is applied to assignments and arguments (`Dim asText As String = isbn` and `Shout(isbn)`). It was not applied to the operand of `&` in the experiment: `"ISBN " & isbn` fails, as the next listing shows, and a member of the target type is not visible on the source (`isbn.Length`).
* A narrowing conversion whose failure is an exceptional case should throw `InvalidCastException`; callers that expect failure need a `TryParse` method next to it, as `Isbn.TryParse` is.

on a value type at line 59 (BC30792) and `Length` which `Isbn` does not have at line 60 (BC30456). Learn describes `Widening` as the modifier of an operator that converts to a type that
can always hold the value, and the rules for the combinations in the page for the `Operator` statement.

== Arrays, generics and delegates: variance

*Variance* is the rule that lets a `Book` collection stand in for a `CatalogItem` collection. Visual Basic supports it for arrays, for generic interfaces and delegates that declare it
(since Visual Basic 2010), and for delegate parameter types.

[source,vbnet]
----
Option Strict On

Imports System.Collections.Generic

Public MustInherit Class CatalogItem
    Public ReadOnly Property Title As String

    Protected Sub New(title As String)
        Me.Title = title
    End Sub
End Class

Public Class Book
    Inherits CatalogItem

    Public Sub New(title As String)
        MyBase.New(title)
    End Sub
End Class

Public Class Magazine
    Inherits CatalogItem

    Public Sub New(title As String)
        MyBase.New(title)
    End Sub
End Class

Module Program
    Sub Main()
        Dim books As Book() = {New Book("Dune"), New Book("Emma")}

        ' Array covariance: an array of Book is an array of CatalogItem, checked at run time on store.
        Dim items As CatalogItem() = books
        Console.WriteLine("array covariance: " & items.Length.ToString() & " items, runtime type " & items.GetType().Name)
        Try
            items(0) = New Magazine("Wired")
        Catch ex As ArrayTypeMismatchException
            Console.WriteLine("storing a Magazine in the Book array: " & ex.GetType().Name)
        End Try

        ' Generic covariance: IEnumerable(Of Out T) and read-only interfaces allow the conversion implicitly.
        Dim readOnlyItems As IEnumerable(Of CatalogItem) = books
        Console.WriteLine("IEnumerable(Of Book) -> IEnumerable(Of CatalogItem): " & readOnlyItems.Count().ToString())
        Dim list As New List(Of Book)(books)
        Dim readOnlyList As IReadOnlyList(Of CatalogItem) = list
        Console.WriteLine("List(Of Book) -> IReadOnlyList(Of CatalogItem): " & readOnlyList.Count.ToString())
        ' Dim itemList As List(Of CatalogItem) = list   ' error BC30512: List(Of T) is invariant

        ' Delegate contravariance: a method that accepts any CatalogItem can serve where a Book is supplied.
        Dim describeItem As Func(Of CatalogItem, String) = Function(i) "item " & i.Title
        Dim describeBook As Func(Of Book, String) = describeItem
        Console.WriteLine("Func(Of CatalogItem, String) -> Func(Of Book, String): " & describeBook(books(1)))
        Dim makeBook As Func(Of Book) = Function() New Book("Ulysses")
        Dim makeItem As Func(Of CatalogItem) = makeBook
        Console.WriteLine("Func(Of Book) -> Func(Of CatalogItem): " & makeItem().Title)

        ' Booleans and numbers.
        Dim hasCopies As Boolean = CBool(3)
        Console.WriteLine("CBool(3) = " & hasCopies.ToString() & ", CInt(True) = " & CInt(hasCopies).ToString() & ", Math.Abs(CInt(True)) = " & Math.Abs(CInt(hasCopies)).ToString())

        ' An array of one type is not an array of another: element conversion needs a loop or LINQ.
        Dim numbers As Integer() = {1, 2, 3}
        Dim doubles As Double() = Array.ConvertAll(numbers, Function(n) CDbl(n))
        Console.WriteLine("Array.ConvertAll: " & String.Join(", ", doubles))
    End Sub
End Module
----

[source,text]
----

storing a Magazine in the Book array: ArrayTypeMismatchException
IEnumerable(Of Book) -> IEnumerable(Of CatalogItem): 2
List(Of Book) -> IReadOnlyList(Of CatalogItem): 2

Func(Of Book) -> Func(Of CatalogItem): Ulysses

Source: https://learn.microsoft.com/dotnet/standard/generics/covariance-and-contravariance[Covariance and contravariance in generics]

* *Arrays* are covariant: a `Book()` converts implicitly to `CatalogItem()`. The conversion is unsafe, because the array keeps its real type and a store of the wrong element throws `ArrayTypeMismatchException`, as the second line shows.
  Arrays of value types are not covariant (see the errors below).
* *Generic interfaces* declare variance with `Out` (the type only comes out, so `IEnumerable(Of Book)` is an `IEnumerable(Of CatalogItem)`) and `In` (the type only goes in). `IReadOnlyList(Of Out T)` and `IEnumerable(Of Out T)` are
  covariant; `List(Of T)`, `ICollection(Of T)` and `IList(Of T)` are *invariant*, because they both read and write.
* *Delegates* are contravariant in their parameters and covariant in their result: a `Func(Of CatalogItem, String)` is a `Func(Of Book, String)`, and a `Func(Of Book)` is a `Func(Of CatalogItem)`. The `In` and `Out` of
  `Func(Of In T, Out TResult)` appear in the error message below.
* There is no conversion between arrays of unrelated element types. `Array.ConvertAll` (or `Select`...`ToArray`) creates the new array.

== Boolean and enumerations

* `CInt(True)` is -1 and `CInt(False)` is 0 because Visual Basic represents `True` as all bits set. Every non-zero number converts to `True`. `Convert.ToInt32(True)` is 1, and `True`
  stored in a database or sent to another language is a source of off-by-sign errors. Write `If(flag, 1, 0)` when you need the number 1.
* A `Boolean` widens only to `Object`. To a number or to `String` it is a narrowing conversion (and the reverse), so `Option Strict On` requires `CInt`, `CBool`, `CStr` and the like; to `Char` and `Date` no conversion exists (BC30311). In the shelf program, `CBool(3)` is `True` and `Math.Abs(CInt(True))` is 1.
* An `Enum` converts to and from its underlying integral type explicitly (`CInt(state)`, `CType(2, LoanState)`) and never checks that the number names a member. `Enum` values also convert to
  `String` with `ToString` and from `String` with `[Enum].Parse` or `TryParse`.

== The exceptions

[cols="2,4,4",options="header"]
|===
| Exception | Raised by | Remedy

| `InvalidCastException`
| `DirectCast` or `CType` with the wrong run-time type; `CInt`, `CBool`, `CDate` and friends with text that is not a value; a `Narrowing` operator that rejects its argument.
| Test with `+TypeOf ... Is+` or `TryCast`; use `TryParse`; validate before converting.

| `OverflowException`
| A conversion or arithmetic result outside the target range; `CByte(300)`, `CInt` of a large `Long`, `Integer.Parse("3000000000")`, floating-point `NaN` or infinity to an integer.
| Check the range, widen first (`CLng`), or use a larger type. Do not switch the project's overflow checking off to hide it.

| `FormatException`
| `Parse`, `Convert.ToInt32` and `Convert.ToDateTime` with text in the wrong format. (`CInt` reports the same problem as `InvalidCastException`; the `FormatException` is its inner exception.)
| `TryParse` with an explicit culture and styles.

| `ArgumentNullException`
| `Integer.Parse(Nothing)` and the other `Parse` methods.
| Test for `Nothing`, or use `Convert.ToInt32`, which treats `Nothing` as 0.

| `ArrayTypeMismatchException`
| Storing an element into an array that is covariantly typed as a base array.
| Prefer `IReadOnlyList(Of T)` or `IEnumerable(Of T)` for the covariant view.
|===

Source: https://learn.microsoft.com/dotnet/api/system.invalidcastexception[InvalidCastException]

== Differences from C#

[cols="2,4,4",options="header"]
|===
| Concern | Visual Basic | C#

| Implicit narrowing
| Error under `Option Strict On`; allowed (and checked at run time) under `Off`.
| Always an error.

| Cast of a floating-point number to an integer
| `CInt(2.5)` rounds half to even (2); `Fix(2.5)` truncates.
| `(int)2.5` truncates (2); `Math.Round` rounds.

| Overflow
| Checked by default: `OverflowException`.
| `unchecked` by default; `checked` to throw.

| Reference downcast
| `DirectCast(x, T)` (throws) and `TryCast(x, T)` (returns `Nothing`).
| `(T)x` and `x as T`.

| Type test
| `TypeOf x Is T`, `TypeOf x IsNot T` (VB 14).
| `x is T`, `x is not T`, pattern matching.

| Conversion of an `Object` to a number
| `CInt(obj)` converts a `Short`, a `String` or a `Boolean`; `DirectCast(obj, Integer)` unboxes exactly.
| `(int)obj` unboxes exactly; no helper converts.

| String to number
| `CInt("12")`, `Integer.Parse`, `Val`.
| `int.Parse`, `Convert.ToInt32`; no keyword conversions.

| `Boolean` to number
| `CInt(True)` is -1.
| No implicit or explicit conversion.

| User-defined conversions
| `Widening Operator CType` and `Narrowing Operator CType`.
| `implicit operator` and `explicit operator`.

| Type of `x / y`
| `Double` for integers; `\` is integer division.
| Integer division for integers.

| Generic variance
| `Out` and `In` on interfaces and delegates, from VB 10.
| `out` and `in`, from C# 4.
|===

Source: https://learn.microsoft.com/dotnet/csharp/language-reference/operators/type-testing-and-cast[Type-testing operators and cast expressions (C#)]

== Where the books are outdated or wrong

* *Mastering VB.NET* p. 43 assigns `a / b` and `+a ^ b+` to `Integer` variables: both operators return `Double`, and the assignments do not compile with `Option Strict On` (BC30512, as the matrix section shows). Write `a \ b`, or `CInt(a / b)` when rounding is the intent, and `+CInt(a ^ b)+`.
* *Mastering VB.NET* pp. 54-55, 119-121 and 128 say that `10 / 0` throws `DivideByZeroException`. `/` on integer operands converts to `Double` and gives `Infinity`; only `\`, `Mod` and `Decimal` division throw (the numbers section of
  xref:programming-languages/visual-basic/data-types-and-literals.adoc[Data Types and Literals] runs them).
* *Quickstart Guide* pp. 18 and 134 use `pass:c[+]` to concatenate strings, which the first section of this page shows is an `Option Strict On` error and a numeric addition in disguise otherwise. Use `&`.
* *Quickstart Guide* p. 80 presents `DateValue` as if its result did not depend on the culture. It does, like `CDate`, as the culture example shows; use `Date.TryParseExact` with the invariant culture for stored dates.
* *Quickstart Guide* pp. 83-84 give `FormatDateTime` custom format strings. It takes only the named formats; custom formats belong to `ToString(format)`. The page on
  xref:programming-languages/visual-basic/dates-times-and-formatting.adoc[Dates, Times and Formatting] covers both.
