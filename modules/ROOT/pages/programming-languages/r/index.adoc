== What R is

R is a language and environment for statistical computing and graphics. The R FAQ describes it as a system made of a language plus a run-time environment with graphics, a debugger, access to certain system functions and the ability to run programs stored in script files. Most of the functions a user calls are themselves written in R, and code that needs speed can call C, C{pp} or Fortran. Linear and generalized linear models, nonlinear regression, time series, classical tests, clustering, smoothing and a complete graphics system come with the base distribution; thousands of add-on packages on CRAN and Bioconductor extend it (https://cran.r-project.org/doc/FAQ/R-FAQ.html#What-is-R_003f[R FAQ 2.1]).

R is an implementation of the *S language*, designed by John Chambers and colleagues at Bell Laboratories and described in Becker, Chambers and Wilks' _The New S Language_ (1988). R looks very much like S, but its implementation and semantics, lexical scoping in particular, come from Scheme (https://cran.r-project.org/doc/FAQ/R-FAQ.html#What-is-S_003f[R FAQ 3.1], https://cran.r-project.org/doc/FAQ/R-FAQ.html#What-are-the-differences-between-R-and-S_003f[R FAQ 3.3]). Ross Ihaka and Robert Gentleman wrote the first versions at the University of Auckland. Since mid-1997 the *R Core Team* has maintained the source code, and the *R Foundation for Statistical Computing*, a not-for-profit organization founded by R Core, holds and administers the copyright of the software and its documentation (https://cran.r-project.org/doc/FAQ/R-FAQ.html#What-is-the-R-Foundation_003f[R FAQ 2.13], https://www.r-project.org/foundation/[The R Foundation]). R is an official part of the GNU project and is free software under the GNU General Public License, version 2 or version 3 (`GPL-2 | GPL-3` in the notation of a package's `License` field). `licence()` prints the terms:

The base distribution has two layers. The *base packages* (base, utils, stats, methods, graphics, grDevices, grid, tools, parallel, compiler, splines, stats4, datasets and tcltk) are part of R itself and versioned with it. The *recommended packages* (MASS, Matrix, lattice, survival, nlme, mgcv, codetools, foreign and a few more) are maintained separately on CRAN but shipped with every binary build. Everything else is an add-on package that you install from CRAN, Bioconductor or another repository; xref:programming-languages/r/packages-libraries-and-namespaces.adoc[Packages, Libraries and Namespaces] explains libraries and the search path.

This section teaches the language, its base packages and the tooling around it, from a first `Rscript` to a package on CRAN. Its statistics and graphics pages document what a learner of the language needs to read and fit models and draw charts; they are not a statistics course.

== Version baseline

The section targets *R 4.6*: every page was checked against *R 4.6.1* ("Happy Hop", released on 2026-06-24), the current release and the version every r-release manual describes. R 4.6.0 came out on 2026-04-24. R has one *x.y.0* release a year, in spring, followed by patch releases as needed and a final patch of the old series shortly before the next *x.y.0* (https://developer.r-project.org/[R Developer Page]). Re-checked on 2026-10-22: *R 4.6.2* ("Diversified Portfolio") is at release-candidate stage (code freeze on 2026-10-22) and is scheduled for 2026-10-29; https://cran.r-project.org/src/base/R-4/[the source releases] still end at R 4.6.1. The development version, *R-devel*, will become R 4.7.0, with no release date published; the few R-devel changes that matter to a learner are described as upcoming on xref:programming-languages/r/whats-new-and-migrating-older-code.adoc[What's New and Migrating Older Code].

How the pages were checked:

* Every example on every page is a complete script that was run with `Rscript` on R 4.6.1 (in a throwaway container) and passed `lintr::lint()` with the default linters (a line that deliberately shows a bad idiom carries a `# nolint` comment). The `#>` lines are the real output, reprex-style; output that depends on the machine (paths, platform strings, timings) is trimmed or replaced, and the page says so. Code that cannot run in a container, such as the RStudio and Positron user interfaces, the Windows and macOS installers or a CRAN submission, was checked against the official documentation and is labelled as not run.
* The code uses the current idioms: the native pipe `+|>+`, the `+\(x)+` lambda shorthand, `vapply()` with a declared result, `seq_along()` and `TRUE`/`FALSE`. Where older tutorials teach something else (magrittr's `+%>%+` as the only pipe, `stringsAsFactors = TRUE`, `T` and `F`, `sapply()` everywhere, `1:length(x)`), the page explains the difference in prose.
* Add-on packages change faster than R. Each page that uses one states the version it was checked against in its introduction instead of hard-coding versions in the prose. S7 is described as the CRAN package it is today (0.2.2), not as part of base R.
* Every concept is drawn from the official R documentation: the six manuals, the R FAQ, the help pages of the base and recommended packages, NEWS and the R Blog, and, for add-on packages, each package's own documentation, labelled as package documentation. Each example is followed by a `Source:` link, and every source is listed in the <<_bibliography>>.

== The shelf scenario

The examples across the section share one small, original domain: *shelf*, a library catalogue seen from the analysis side. It is the domain of the xref:programming-languages/rust/index.adoc[Rust Reference], the xref:programming-languages/go/index.adoc[Go Reference] and the xref:programming-languages/ruby/index.adoc[Ruby Reference] too, so the same data can be compared across languages.

* `books` is a 16-row data frame read with `read.csv("books.csv")`: `title`, `author`, `isbn`, `year`, `genre` and `pages`, with deliberate mess for the cleaning pages (stray blanks, two spellings of one author, genre variants, an empty ISBN, one with a wrong check digit, and missing years and page counts).
* `loans` has 60 loans (`loan_id`, `isbn`, `member`, `loan_date`, `return_date`) from January 2025 to June 2026, including an impossible date, a return before its loan, a member written two ways and seven loans still out.
* `shelf_today` is fixed at 2026-06-30 and `loan_days` at 21, so overdue results are reproducible.
* A `book` S3 class (constructor, validator, helper and `print`, `format` and `summary` methods) is re-modelled as an S4 class, an R6 class and an S7 class on the object-oriented pages.
* The analyses are loans per month, overdue rates by genre, the distribution of loan durations and a model of loan duration on pages and genre, drawn with base graphics, lattice and ggplot2.
* On the tooling pages the code becomes a small `shelf` package with roxygen2 documentation, testthat tests and a vignette, then an `Rscript` command-line report, a Shiny dashboard and a plumber API.

Pure-statistics pages also use the built-in data sets (`penguins` from R 4.5.0, `mtcars`, `airquality`). The pages build on each other, and the xref:programming-languages/r/cheat-sheet.adoc[cheat sheet] summarises the whole section.

== How to cite R

R is free, but its authors ask that it be cited when it is used for data analysis. `citation()` prints the recommended reference, as text and as a BibTeX entry; the year is the release year of the R version in use (`R.version$year`). Since R 4.6.0 the citation carries the DOI https://doi.org/10.32614/R.manuals[10.32614/R.manuals] (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS], https://cran.r-project.org/doc/FAQ/R-FAQ.html#Citing-R[R FAQ 2.8]).

[source,r]
----
citation()
#> To cite R in publications use:
#>
#>   R Core Team (2026). _R: A Language and Environment for Statistical
#>   Computing_. R Foundation for Statistical Computing, Vienna, Austria.
#>   doi:10.32614/R.manuals <https://doi.org/10.32614/R.manuals>.
#>   <https://www.R-project.org/>.
#>
#> A BibTeX entry for LaTeX users is
#>
#>   @Manual{,
#>     title = {R: A Language and Environment for Statistical Computing},
#>     author = {{R Core Team}},
#>     organization = {R Foundation for Statistical Computing},
#>     address = {Vienna, Austria},
#>     year = {2026},
#>     doi = {10.32614/R.manuals},
#>     url = {https://www.R-project.org/},
#>   }
#>
#> We have invested a lot of time and effort in creating R, please cite it
#> when using it for data analysis. See also ‘citation("pkgname")’ for
#> citing R packages.
----

Source: https://search.r-project.org/R/refmans/utils/html/citation.html[R documentation: citation]

Packages are cited the same way, with the package name as the argument. `citation("pkg")` returns a `bibentry` object, built from the package's `inst/CITATION` file when it has one and from its `DESCRIPTION` file otherwise, and `format()` renders it in a chosen style. Cite the package version you used too, which `packageVersion()` reports:

[source,r]
----
citation("ggplot2") |> format(style = "text") |> writeLines()
#> Wickham H (2016). _ggplot2: Elegant Graphics for Data Analysis_.
#> Springer-Verlag New York. ISBN 978-3-319-24277-4.
#> <https://ggplot2.tidyverse.org>.
packageVersion("ggplot2")
#> [1] ‘4.0.3’
----

Source: https://search.r-project.org/R/refmans/utils/html/bibentry.html[R documentation: bibentry]

xref:programming-languages/r/creating-packages.adoc[Creating Packages] shows how a package declares its own citation, and the R FAQ entry gives the BibTeX form to paste into a bibliography.

* xref:programming-languages/python/index.adoc[Python Reference]: Python is the other main language of data analysis. xref:programming-languages/r/design-philosophy-and-coming-from-other-languages.adoc[Design Philosophy and Coming from Other Languages] maps pandas and NumPy idioms to R, and xref:programming-languages/r/python-interop-with-reticulate.adoc[Python Interop with reticulate] calls Python from R.

* xref:programming-languages/fortran/index.adoc[Fortran Reference]: R calls Fortran through `.Fortran()` and `.Call()`, and its matrix algebra goes through BLAS and LAPACK, the classic Fortran linear-algebra libraries (see xref:programming-languages/r/interfacing-c-cpp-and-fortran.adoc[Interfacing C, C{pp} and Fortran] and xref:programming-languages/r/matrices-and-arrays.adoc[Matrices and Arrays]).

* xref:data-science/index.adoc[Data Science]: the Python-based counterpart of the statistics, graphics and tidyverse pages of this section, built on NumPy, pandas and scikit-learn.
* xref:backend/fastapi/serving-data-science-and-ai.adoc[Serving Data Science & AI]: the Python way to serve models and charts over HTTP, which xref:programming-languages/r/shiny-plumber-and-web-apis.adoc[Shiny, plumber and Web APIs] does in R.
* xref:database/sql/index.adoc[SQL Reference]: SQL itself is covered there; xref:programming-languages/r/databases-with-dbi.adoc[Databases with DBI] shows how R sends it to a database.
* xref:backend/docker/index.adoc[Docker]: container images are covered there; xref:programming-languages/r/reproducible-environments-with-renv.adoc[Reproducible Environments with renv] pins an R project's packages inside one, using the Rocker images.
* The xref:programming-languages/rust/index.adoc[Rust], xref:programming-languages/go/index.adoc[Go] and xref:programming-languages/ruby/index.adoc[Ruby] references use the same *shelf* domain, so you can compare how each language models the catalogue.
