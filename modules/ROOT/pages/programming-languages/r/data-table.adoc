== What a data.table is

A `data.table` is a data frame: its class is `c("data.table", "data.frame")`, it is a list of columns of equal length, and every
function that accepts a data frame accepts it. What differs is the `pass:c[[]` method. `pass:c[DT[i, j, by\]]` is a query language in the
brackets (the next section), `pass:c[DT[2\]]` is the second ROW (a data frame treats a single number as a column), and a data.table
never has or uses row names. Printing differs too: a data.table shows row numbers followed by a colon, a line of column classes under
the names (`<char>`, `<int>`), and for a long table only the first and last rows. `data.table()` builds a table from vectors as
`data.frame()` does, with `stringsAsFactors = FALSE` and `check.names = FALSE` as defaults and an optional `key` argument
(https://rdatatable.gitlab.io/data.table/reference/data.table.html[data.table package documentation: data.table]).

The first script attaches the package with a plain `library(data.table)` call, which is the only place on the page where its start-up
message is shown. `data.table` exports its own `%notin%` (added in data.table 1.15.0), and R 4.6.0 added `%notin%` to base R
(it is listed in the R NEWS for 4.6.0), so attaching the package prints a conflict message and the
data.table version is found first on the search path; both are the negation of `%in%`. In an interactive session `library(data.table)` also
prints a line with the version and the number of threads in use; `Rscript` does not, because the `.onAttach()` hook of the package
returns at once when `interactive()` is `FALSE`.

Real tables are usually already data frames, and data.table converts them in two ways. `as.data.table()` makes a copy and leaves the
original alone. `setDT()` changes the object in place: it adds the class and the over-allocation described below, copies nothing, and
returns the table invisibly, so it is called without an assignment. `setDF()` goes back in place. The next script converts the shelf
tables, and shows `keep.rownames` for a data frame whose row names carry information.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")

# books and loans from scenario.R are data frames.
class(books)
#> [1] "data.frame"

# as.data.table() copies; the original is untouched.
copy_dt <- as.data.table(books)
class(books)
#> [1] "data.frame"
class(copy_dt)
#> [1] "data.table" "data.frame"

# setDT() converts IN PLACE: no copy, no assignment, no result printed.
setDT(books)
setDT(loans)
class(books)
#> [1] "data.table" "data.frame"
class(loans)
#> [1] "data.table" "data.frame"

# Row names are dropped; keep.rownames = "isbn" keeps them in a column.
copies <- data.frame(copies = 2:3,
                     row.names = c("9780306406157", "9780141439518"))
as.data.table(copies)
#>    copies
#>     <int>
#> 1:      2
#> 2:      3
as.data.table(copies, keep.rownames = "isbn")
#>             isbn copies
#>           <char>  <int>
#> 1: 9780306406157      2
#> 2: 9780141439518      3

# setDF() goes back, also in place.
tmp <- copy(books[1:2, .(title, year)])
setDF(tmp)
class(tmp)
#> [1] "data.frame"
is.data.table(books)
#> [1] TRUE
----

== The general form: DT[i, j, by]

The package documentation reads the form out loud: "take `DT`, subset rows by `i`, then compute `j` grouped by `by`". The table
lines the three arguments up with the clauses of an SQL query, and lists the arguments that refine them. Every argument of a query is
optional, and the commas keep the positions: `pass:c[DT[, j\]]` has no `i`, `pass:c[DT[i\]]` has only `i`.

[cols="2,2,5",options="header"]
|===
|Argument |SQL clause |What it does
|`i` |`WHERE`, `ORDER BY`, `JOIN` |chooses and orders the rows: row numbers, a logical condition, `+order(...)+`, or another table to join to
|`j` |`SELECT`, `UPDATE` |what to compute: a column, an expression, a list written `+.(...)+`, or an assignment with `:=`
|`by`, `keyby` |`GROUP BY` |runs `j` for each group of the columns or expressions named; `keyby` also sorts the groups and sets a key
|`on`, `nomatch`, `mult`, `roll` |`JOIN` |how a table in `i` is matched: the columns, rows without a match, several matches, the nearest match
|`.SDcols`, `with`, `env` ||which columns `.SD` holds, whether `j` is a name lookup, and values to substitute into the query
|===

Source: https://rdatatable.gitlab.io/data.table/reference/data.table.html[data.table package documentation: data.table]

Queries chain by writing another pair of brackets straight after the first: `pass:c[DT[...\][...\]]` runs the second query on the result
of the first. That is how a result is sorted after grouping (`pass:c[DT[, .N, by = g\][order(-N)\]]`), and it replaces the temporary
variables of base R.

=== i: choosing and ordering rows

`i` is evaluated inside the table, so the columns are variables and `pass:c[books[year > 2020\]]` needs no `books$`. It can be a vector of row
numbers (negative numbers drop rows), a logical expression, or `+order(...)+` for sorting, where a minus sign means descending. A
logical `NA` in `i` is treated as `FALSE`, as the help page says, which differs from a data frame, where a logical `NA` produces a row of `NA` values. A logical `i` must be as long as the table: recycling a shorter one is an error. The operators `%between%`, `%chin%` and
`%like%` (a regular expression, as `grepl()`) are shortcuts for common conditions. `order()` inside `i` is handled by data.table's
own fast sort, which sorts text in C-locale, not in the locale of the session (see <<setters,the setters>>), and puts `NA` last, as base `order()` does.

When a variable of the calling environment has the name of a column, the column wins: after `+year <- 1900+`, `pass:c[books[year > 2022\]]` still
compares the column. The last lines of the script show it; the way to reach the variable is `env =` or `..` (see
<<programming,Programming with data.table>>).

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)

# i is evaluated inside the table: columns are variables, no books$ needed.
books[year > 2020, .(title, year)]
#>             title  year
#>            <char> <int>
#> 1:     Loud Roofs  2021
#> 2: THE LONG TABLE  2023
#> 3:    Ten Winters  2022

# Row numbers, negative numbers and logical vectors work as in a data frame.
books[-(3:16), .(title)]
#>                  title
#>                 <char>
#> 1:    The Dispossessed
#> 2: Pride and Prejudice

# NA in a logical i drops the row (year is NA in row 7).
books[year > 2020 | is.na(year), .(title, year)]
#>                    title  year
#>                   <char> <int>
#> 1:            Loud Roofs  2021
#> 2: Garden of Small Fires    NA
#> 3:        THE LONG TABLE  2023
#> 4:           Ten Winters  2022

# order() inside i sorts; - means descending. NA goes last for ascending.
books[order(-pages), .(title, pages)][1:3]
#>                  title pages
#>                 <char> <int>
#> 1: Pride and Prejudice   432
#> 2:    Notes on Gravity   410
#> 3:    The Dispossessed   387

# %between%, %chin% and %like% are shortcuts for common conditions.
books[year %between% c(2015, 2020), .(title, year)]
#>                   title  year
#>                  <char> <int>
#> 1:   the quiet streets   2019
#> 2:      Midnight Ledger  2016
#> 3:     Notes on Gravity  2017
#> 4:        Orchard Logic  2020
#> 5:      Salt and Static  2018
books[genre %chin% c("Poetry", "Mystery"), .(title, genre)]
#>                    title   genre
#>                   <char>  <char>
#> 1:       Midnight Ledger Mystery
#> 2: Garden of Small Fires  Poetry
#> 3:           Paper Moons  Poetry
#> 4:       Salt and Static Mystery
books[title %like% "^The", .(title)]
#>               title
#>              <char>
#> 1: The Dispossessed
#> 2: The Lamp at Noon
#> 3:   The Slow Comet

# A column named like an outside variable: the column wins.
year <- 1900
books[year > 2022, .(title)]
#>             title
#>            <char>
#> 1: THE LONG TABLE
----

=== j: columns, expressions and lists

`j` is evaluated in the scope of the table too. A bare column name returns the column as a vector, `.(a, b)` (an alias of `list(a, b)`)
returns a data.table, and any other expression is evaluated on whole columns. When `j` returns a list, every element becomes a column,
named after the argument, or `V1`, `V2` and so on when it is unnamed. A number or a character vector of names in `j` selects columns and
always gives a data.table back, which is the difference to `pass:c[df[, 2\]]` on a data frame, where one column becomes a vector. A
character vector held in a variable is looked up in the calling scope with the prefix `..` (one level up, like `..` in a file
path), or passed to `.SDcols`. `j` can be any code, so it can also run for its side effect (a plot, a `cat()`), and then its value is
what the code returns.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)

# A bare column in j comes back as a vector; .() or list() as a data.table.
books[, pages]
#>  [1] 387 432 214 198 301  NA  96 280 352 256  88 410 175 322  NA 244
books[1:3, .(pages)]
#>    pages
#>    <int>
#> 1:   387
#> 2:   432
#> 3:   214

# An expression is evaluated on the whole column. na.rm is needed for NA.
books[, mean(pages, na.rm = TRUE)]
#> [1] 268.2143
books[, .(mean_pages = mean(pages, na.rm = TRUE), n = .N)]
#>    mean_pages     n
#>         <num> <int>
#> 1:   268.2143    16

# Several results become several columns; unnamed ones are called V1, V2...
books[genre == "Poetry", .(title, nchar(title), pages * 2L)]
#>                    title    V2    V3
#>                   <char> <int> <int>
#> 1: Garden of Small Fires    21   192
#> 2:           Paper Moons    11   176

# A number in j selects a column and ALWAYS gives a data.table back.
books[1:2, 1]
#>                  title
#>                 <char>
#> 1:    The Dispossessed
#> 2: Pride and Prejudice
books[1:2, c("title", "year")]
#>                  title  year
#>                 <char> <int>
#> 1:    The Dispossessed  1974
#> 2: Pride and Prejudice  1813

# A character vector held in a variable is looked up one level up with
# `..`, or with .SD and .SDcols.
cols <- c("title", "year")
books[1:2, ..cols]
#>                  title  year
#>                 <char> <int>
#> 1:    The Dispossessed  1974
#> 2: Pride and Prejudice  1813
books[1:2, .SD, .SDcols = cols]
#>                  title  year
#>                 <char> <int>
#> 1:    The Dispossessed  1974
#> 2: Pride and Prejudice  1813
----

=== by and keyby: groups

`by` runs `j` once for each group of rows that share the values of the columns (or expressions) named, and stacks the results. The
groups come out in the order of their first appearance in the table; `keyby` sorts them and sets them as the key of the result,
which is the usual choice when the result is printed. `by` accepts a column name, a character vector of names, a range `a:c` of
columns, or a list of expressions in `+.(...)+`, and a computed grouping column needs a name there, as `decade` below. `i` is applied
before the grouping, which is how a filtered summary is written. A single unnamed value in `j` is called `V1` in the result; `.N` (the
size of the group) becomes `N`.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)
books[, genre := tolower(trimws(genre))]

# by groups; the groups come out in the order of first appearance.
books[, .(n = .N, pages = sum(pages, na.rm = TRUE)), by = genre]
#>              genre     n pages
#>             <char> <int> <int>
#> 1: science fiction     3  1119
#> 2:         classic     2   712
#> 3:         fiction     4   668
#> 4:         mystery     2   545
#> 5:     non-fiction     3   527
#> 6:          poetry     2   184

# keyby sorts the groups and sets a key on the result.
books[, .N, keyby = genre]
#> Key: <genre>
#>              genre     N
#>             <char> <int>
#> 1:         classic     2
#> 2:         fiction     4
#> 3:         mystery     2
#> 4:     non-fiction     3
#> 5:          poetry     2
#> 6: science fiction     3

# An unnamed single expression is called V1; .() and names fix that.
books[, mean(pages, na.rm = TRUE), by = genre]
#>              genre       V1

books[, .(n = .N), by = .(decade = year %/% 10L * 10L)][order(decade)]

== Adding, changing and removing columns by reference

=== The := operator

`:=` is data.table's assignment inside `j`. It adds a column, replaces a column or a part of one, or (with `NULL`) removes a column,
in the table itself: no copy of the table is made and nothing is assigned back, so `pass:c[books[, age := 2026L - year\]]` is a complete
statement. There are two spellings. The `LHS := RHS` form takes column names on the left (a single name, or a character vector in `c()`
or in parentheses) and a value or a list of values on the right. The functional form, `:=` called like a function, as in `+`:=`(a = ..., b = ...)+`, takes named
arguments, which lets each column carry its own comment; `let()` is an alias for it in the help page of the package, and it is present in
1.18.6.1. With `i`, only the rows chosen are changed, and a new column is `NA` in the other rows. With `by`, the value is computed for
each group and recycled within it. The call returns the table invisibly, so nothing is printed at the prompt
(<<printing-after-assignment,Printing after the := operator>> has the details), and `.Last.updated` holds the number of rows the last `:=` or `set()`
changed.

A name in parentheses, `(cols) :=`, means "the columns whose names are held in `cols`", where a bare `cols :=` would create a column
called `cols`. This is also how one function is applied to many columns, `pass:c[(cols) := lapply(.SD, f)]`. Since data.table 1.16.0
`pass:c[names(.SD) := lapply(.SD, f)]` updates every column of `.SD` (NEWS for 1.16.0). The help page states the rule for types: the
right-hand side is coerced to the type of the existing column, not the other way round (unlike `+<-+` on a data frame), and a whole
column given as the right-hand side replaces the column, with its new type ("plonk" syntax, as in `pass:c[(num_cols) := lapply(.SD, as.numeric)]`
below). Coercing a part of a column warns, and a right-hand side whose length is neither 1 nor the number of rows is an error
(both messages are in <<errors,Common errors and warnings>>).

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)

# := adds a column by reference: no assignment, and nothing is printed.
books[, age := 2026L - year]
books[1:3, .(title, year, age)]
#>                   title  year   age
#>                  <char> <int> <int>
#> 1:     The Dispossessed  1974    52
#> 2:  Pride and Prejudice  1813   213
#> 3:   the quiet streets   2019     7

# With i, only those rows change; a new column is NA in the others.
books[pages > 400L, size := "long"]
books[, .N, by = size]
#>      size     N
#>    <char> <int>
#> 1:   <NA>    14
#> 2:   long     2

# Several columns: names on the left, a list on the right.
books[, c("title", "genre") := .(trimws(title), tolower(trimws(genre)))]
books[3:4, .(title, genre)]
#>                title   genre
#>               <char>  <char>
#> 1: the quiet streets fiction
#> 2:        Loud Roofs fiction

# The functional form allows a comment next to each column.
books[, `:=`(
  author = gsub("\\s+", " ", trimws(author)), # collapse repeated blanks
  isbn = gsub("[^0-9X]", "", isbn) # keep digits and X only
)]
books[9:10, .(title, author, isbn)]
#>              title       author          isbn
#>             <char>       <char>        <char>
#> 1: Rivers of Glass  Tomas Arden
#> 2:  THE LONG TABLE Iris Fenwick 9780008000851

# One function over several columns: (cols) := lapply(.SD, f).
num_cols <- c("year", "pages")
books[, (num_cols) := lapply(.SD, as.numeric), .SDcols = num_cols]
vapply(books[, ..num_cols], class, character(1))
#>      year     pages
#> "numeric" "numeric"

# NULL deletes columns.
books[, c("age", "size") := NULL]
names(books)
#> [1] "title"  "author" "isbn"   "year"   "genre"  "pages"

# The result is invisible; a trailing [] prints it.
small <- books[1:3, .(title, year)]
small[, decade := year %/% 10 * 10][]
#>                  title  year decade
#>                 <char> <num>  <num>
#> 1:    The Dispossessed  1974   1970
#> 2: Pride and Prejudice  1813   1810
#> 3:   the quiet streets  2019   2010

=== Reference semantics and copy()

Because `:=` and the `+set*+` functions change the table where it is, two names can refer to one table, and a change made through one
name is seen through the other. `+b <- a+` gives a data.table a second name, as it does for every R object, and a `:=` on `b` then changes
the table both names refer to; a data frame, by contrast, is copied the moment it is modified. The same holds when a table is passed to
a function: the function receives the table itself, so a `:=` inside it changes the caller's data. `copy()` makes a real, independent
copy and is the way to protect the original. The vignette
https://rdatatable.gitlab.io/data.table/articles/datatable-reference-semantics.html[data.table package documentation: Reference semantics]
gives the reason: since R 3.1.0 adding a column to a data frame copies only the vector of column pointers (a shallow copy), but changing
some rows of a column with `pass:c[df$c[i\] <- value]` still copies the whole column, and `:=` does neither.

[source,r]
----
suppressPackageStartupMessages(library(data.table))

# b <- a does not copy a data.table, and := changes the one object.
a <- data.table(x = 1:3)
b <- a
b[, y := x * 2L]
names(a)
#> [1] "x" "y"
address(a) == address(b)
#> [1] TRUE

# copy() makes an independent table.
d <- copy(a)
d[, z := 0L]
names(a)
#> [1] "x" "y"
names(d)
#> [1] "x" "y" "z"
address(a) == address(d)
#> [1] FALSE

# A function that uses := on its argument changes the caller's table.
add_flag <- function(tbl) {
  tbl[, flag := TRUE] # nolint: object_usage_linter.
  invisible(NULL)
}
add_flag(a)
names(a)
#> [1] "x"    "y"    "flag"

# copy() at the top of the function keeps the caller's table untouched.
with_stamp <- function(tbl) {
  tbl <- copy(tbl)
  tbl[, stamp := "2026-06-30"] # nolint: object_usage_linter.
  tbl[]
}
res <- with_stamp(a)
names(res)
#> [1] "x"     "y"     "flag"  "stamp"
names(a)
#> [1] "x"    "y"    "flag"

# The base R way, a$col <- value, makes a (shallow) copy as usual.
e <- a
e$w <- 1
names(a)
#> [1] "x"    "y"    "flag"
names(e)
#> [1] "x"    "y"    "flag" "w"
----

Source: https://rdatatable.gitlab.io/data.table/articles/datatable-reference-semantics.html[data.table package documentation: Reference semantics]

`address(a) == address(b)` is `TRUE` when two names refer to the same table; the addresses themselves are memory locations that change
from run to run and are not worth printing. The last lines of the script show the base R way, `+e$w <- 1+`: the replacement function
`+$<-+` works on a (shallow) copy, so `a` is unchanged. Base R replacement functions such as `+attr<-+` are the usual way a data.table is
copied by accident, which is the subject of <<selfref,the self-reference warning>> below. The rule of thumb is to use `:=` and the
`+set*+` functions to change a data.table, `copy()` to keep the original, and not to rely on the copy-on-modify behaviour of a data
frame. The sharing of one table by several names is the
same idea as the shared environments of xref:programming-languages/r/scoping-environments-and-closures.adoc[Scoping, Environments and
Closures]; xref:programming-languages/r/memory-and-copy-semantics.adoc[Memory and Copy Semantics] covers when R copies and when it does not.

[[setters]]
=== set(), setnames(), setorder() and setcolorder()

Every function whose name starts with `set` changes its argument by reference and returns it invisibly. `set(DT, i, j, value)` is
described in the help page as a low-overhead, loop-able version of `:=` that cannot group: the cost of a `pass:c[DT[...\]]` call is small
but is paid on each iteration, and `set()` avoids it, which makes it the tool for updating columns in a `for` loop (`i` must be row
numbers, `j` a column name or number). `setnames()` renames columns by name or position, `setorder()` sorts the table itself (a minus
sign for descending; `NA` first), `setcolorder()` moves columns to the front (it gained `before` and `after` arguments in 1.15.0), and
`setattr()` sets an attribute without copying. `setkey()`, `setindex()` and `setDT()` are covered elsewhere on the page.

Sorting in data.table, whether by `setorder()`, `setkey()`, or `order()` in `i`, always uses the C-locale: capitals sort before lower
case whatever language the session is set to, and the order is the same on every machine. The help page of `setorder()` explains the
choice and says that `pass:c[DT[base::order(...)\]]` sorts by the locale of the session instead.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)

# set() is := for loops: one call per column, with no [.data.table overhead.
for (col in c("title", "author", "genre")) {
  set(books, j = col, value = trimws(books[[col]]))
}
# With i it changes only some rows (the rows must be numbers).
set(books, i = which(books$genre == "Science fiction"), j = "genre",
    value = "science fiction")
books[genre == "science fiction", .N]
#> [1] 3

# setnames() renames in place, by name or by position.
setnames(books, "pages", "n_pages")
setnames(books, c("title", "author"), c("book_title", "writer"))
names(books)
#> [1] "book_title" "writer"     "isbn"       "year"       "genre"
#> [6] "n_pages"

# setorder() sorts the table itself; - means descending, NA comes first.
setorder(books, year)
books[, .(book_title, year)][1:3]
#>               book_title  year
#>                   <char> <int>
#> 1: Garden of Small Fires    NA
#> 2:   Pride and Prejudice  1813
#> 3:      The Dispossessed  1974
setorder(books, genre, -year)
books[, .(genre, year)][1:4]
#>      genre  year
#>     <char> <int>
#> 1: Classic  1999
#> 2: Classic  1813
#> 3: Fiction  2023
#> 4: Fiction  2022

# Strings sort in C-locale (capitals first), whatever the session locale.
words <- data.table(w = c("brazil", "America", "america", "Brazil"))
setorder(words, w)
words$w
#> [1] "America" "Brazil"  "america" "brazil"

# setcolorder() moves columns to the front; the others keep their order.
setcolorder(books, c("isbn", "book_title"))
names(books)
#> [1] "isbn"       "book_title" "writer"     "year"       "genre"
#> [6] "n_pages"
----

=== Over-allocation

The help page of `truelength()` explains why a data.table has room for more columns than it uses. Adding a column by creating a new list
of column pointers (a shallow copy) "resulted in inconsistent behaviour in some circumstances", so data.table over-allocates the list
of column pointers when `data.table()` or `setDT()` creates a table, so that `:=` can add a column fully by reference. `truelength()`
is the number of slots allocated and `length()` the number in use. The default is 1024 spare slots, set by
`options(datatable.alloccol = )`. When the slots are used up, the next `:=` has to reallocate, which takes a shallow copy; the page
suggests `copy()` first, `setalloccol()` (also called `alloc.col()`) to reallocate in advance, or a larger option value to avoid it, and
`options(datatable.verbose = TRUE)` reports when a shallow copy is taken. The functions are described as experimental and somewhat
advanced, so the names might change.

A table that has been through `saveRDS()` and `readRDS()`, or `save()` and `load()`, comes back without its slots and without a valid
self-reference. The next `:=` or `set()` allocates them again, quietly, as the script shows with `truelength()` and the helper
`.selfref.ok()`. The help page of `.selfref.ok()` says that it is for technical use; it is shown only to make the mechanism visible.
Loading a table back is therefore not what triggers the warning in the next section.

[source,r]
----
suppressPackageStartupMessages(library(data.table))

# A data.table has room for more columns than it uses (over-allocation),
# which is why := can add a column without copying anything.
dt <- data.table(a = 1:3)
length(dt)
#> [1] 1
truelength(dt)
#> [1] 1025
getOption("datatable.alloccol")
#> [1] 1024

# Adding columns fills the spare slots, truelength() stays put.
dt[, c("b", "c") := 1L]
length(dt)
#> [1] 3
truelength(dt)
#> [1] 1025

# A table read back from disk has no spare room and no valid self-reference;
# := and set() allocate the room again, quietly.
path <- tempfile(fileext = ".rds")
saveRDS(dt, path)
back <- readRDS(path)
truelength(back)
#> [1] 0
.selfref.ok(back)
#> [1] FALSE
back[, d := 4L]
truelength(back)
#> [1] 1028
.selfref.ok(back)
#> [1] TRUE
other <- readRDS(path)
set(other, j = "e", value = 5L)
truelength(other)
#> [1] 1027
file.remove(path)
#> [1] TRUE
----

Source: https://rdatatable.gitlab.io/data.table/reference/truelength.html[data.table package documentation: truelength and setalloccol]

[[selfref]]
=== The self-reference warning

To know that a table is the one it allocated, data.table stores a pointer to the table itself in a hidden attribute,
`.internal.selfref`. A table that R copied, or that was assembled by hand, does not pass the check. This happens when a table is built
with `structure()` or by `+class<-+` on a data frame, when `+attr<-+` copies it, and when a package that knows nothing of data.table
returns a modified copy. `:=` still works on such a table, but it takes a shallow copy so that it can add the column, and warns that it
did. In data.table 1.18.6.1 the warning begins "A shallow copy of this data.table was taken so that := can add or remove 1 columns by
reference" (older releases, and many answers written for them, begin "Invalid .internal.selfref detected and fixed by taking a
(shallow) copy of the data.table"). The cure is the one the message gives: build tables with `setDT()` or `data.table()`, copy with
`copy()`, and use the `+set*+` functions in place of the base replacement functions.

[source,r]
----
suppressPackageStartupMessages(library(data.table))

# A data.table copied by R itself (attr<-, class<- on a data frame,
# structure()) loses its self-reference. := still works, with a warning.
df <- data.frame(x = 1:2)
class(df) <- c("data.table", "data.frame")
.selfref.ok(df)
#> [1] FALSE
res <- tryCatch(df[, y := 2L], warning = conditionMessage)
cat(strwrap(res, width = 70), sep = "\n")
#> A shallow copy of this data.table was taken so that := can add or
#> remove 1 columns by reference. At an earlier point, this data.table
#> was copied by R (or was created manually using structure() or
#> similar). Avoid names<- and attr<- which in R currently (and oddly)
#> may copy the whole data.table. Use set* syntax instead to avoid
#> copying: ?set, ?setnames and ?setattr. It's also not unusual for
#> data.table-agnostic packages to produce tables affected by this
#> issue. If this message doesn't help, please report your use case to
#> the data.table issue tracker so the root cause can be fixed or this
#> message improved.

# Taking the copy with copy() or setDT() avoids the problem.
df <- data.frame(x = 1:2)
setDT(df)
.selfref.ok(df)
#> [1] TRUE
df[, y := 2L]
df
#>        x     y
#>    <int> <int>
#> 1:     1     2
#> 2:     2     2
----

Source: https://rdatatable.gitlab.io/data.table/news/index.html[data.table package documentation: NEWS]

[[printing-after-assignment]]
=== Printing after :=

At the prompt, `pass:c[books[, x := 1\]]` prints nothing: inside `:=` data.table sets a global flag, which the print method uses to know
whether to print. The flag has a visible side effect: a function whose last expression is a `:=` returns the table, and the print of
that result can be swallowed. FAQ 2.23 of the package explains it and recommends a trailing `pass:c[[\]]` after the last `:=` in a
function (https://rdatatable.gitlab.io/data.table/articles/datatable-faq.html[data.table package documentation: Frequently asked questions]).
Since data.table 1.17.0 an explicit `pass:c[print(DT[, y := 2\])]` prints, because the detection of auto-printing was improved; the NEWS of
1.17.0 says this makes the older advice to append `pass:c[[\]]` unnecessary for that case. The script shows both in 1.18.6.1.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
a <- data.table(x = 1:2)

# At the prompt := returns the table invisibly: nothing is printed.
a[, y := 1L]

# An explicit print() prints it (since data.table 1.17.0, also around :=).
print(a[, y := 2L])
#>        x     y
#>    <int> <int>
#> 1:     1     2
#> 2:     2     2

# A function that ends with := returns the table, but the print of that
# result is swallowed by the flag := leaves behind. A trailing [] prints.
add_z <- function(tbl) {
  tbl <- copy(tbl)
  tbl[, z := 3L] # nolint: object_usage_linter.
}
add_z(a)
add_w <- function(tbl) {
  tbl <- copy(tbl)
  tbl[, w := 4L][] # nolint: object_usage_linter.
}
add_w(a)
#>        x     y     w
#>    <int> <int> <int>
#> 1:     1     2     4
#> 2:     2     2     4
----

Source: https://rdatatable.gitlab.io/data.table/articles/datatable-faq.html[data.table package documentation: Frequently asked questions]

== Special symbols: .SD, .SDcols, .N, .I, .GRP, .BY and .EACHI

Inside `j`, data.table defines a few read-only symbols, listed on the help page `special-symbols`.

[cols="2,5",options="header"]
|===
|Symbol |Meaning
|`.N` |the number of rows: in the whole table, or in the current group; alone in `i`, as in `pass:c[DT[.N\]]`, it is the last row
|`.SD` |the Subset of Data: a data.table with the columns of the current group, except the columns used in `by`
|`.SDcols` |not a symbol but an argument: which columns `.SD` holds, as names, positions, a function such as `is.numeric`, `patterns("regex")`, or the negation of any of these with `!`
|`.I` |the row numbers: `seq_len(nrow(DT))` ungrouped, and the positions in `DT` of the rows of the group when grouping
|`.GRP` |a counter of groups, 1 for the first group and so on; `.NGRP` is the number of groups
|`.BY` |a list holding the value of the grouping columns for the current group
|`.EACHI` |a value for `by`, not for `j`: `by = .EACHI` runs `j` for each row of the table in `i` of a join (see <<joins,Joins>>)
|`.ROW` |only with `:= NULL`, to delete rows by reference (see <<version-notes,Version notes>>)
|===

Source: https://rdatatable.gitlab.io/data.table/reference/special-symbols.html[data.table package documentation: special-symbols]

`.SD` is the symbol behind most "do this to every column" jobs: `pass:c[DT[, lapply(.SD, mean), by = g\]]` computes a mean for every
column that is not in `g`, and `.SDcols` restricts the columns so that a text column is not averaged. To change `.SD`
before returning it, take `copy(.SD)` first; the symbols are locked and assigning to them is an error. `.I` is the tool
for "the row where something is maximal in each group": `pass:c[DT[, .I[which.max(x)\], by = g\]]` returns the row numbers, which are
then used to subset the table, as the script does. The vignette
https://rdatatable.gitlab.io/data.table/articles/datatable-sd-usage.html[data.table package documentation: Using .SD for data analysis]
collects the more advanced uses of `.SD`.

== Keys, indices and joins

[[keys]]
=== Keys and binary search

A key is a sort order that the table remembers. `setkey(DT, col1, col2)` sorts the table by those columns, in place and ascending
(`NA` first), and marks them as the key (the "sorted" attribute). `key()` returns the key, `haskey()` tests for one, and
`setkeyv()` is the version that takes a character vector. A table has at most one key, because the key is the physical order. Its
purpose is speed and brevity: a subset by key value is a binary search, not a scan of the whole column, `pass:c[DT["x"\]]` finds the group
`"x"` of the first key column, and grouping by a leading part of the key is faster because the groups are already adjacent in memory
(the reasons are in the help page of `setkey()`). `setkey()` always sorts in C-locale. `nomatch = NULL` drops the values of `i` that
are not in the table, where the default `nomatch = NA` returns a row of `NA` for each, and `mult` chooses `"first"`, `"last"` or (the
default) `"all"` of several matches.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)
books[, isbn := gsub("[^0-9X]", "", isbn)]

# setkey() sorts the table by the column(s) and marks them as the key.
key(books)
#> NULL
setkey(books, isbn)
key(books)
#> [1] "isbn"
haskey(books)
#> [1] TRUE
books[, .(isbn, title)][1:3]
#> Key: <isbn>
#>             isbn                title
#>           <char>               <char>
#> 1:                    Rivers of Glass
#> 2: 9780001000100   the quiet streets
#> 3: 9780002000291           Loud Roofs

# A key subset is a binary search, not a scan of the column.
books["9780306406157", .(title, year)]
#>               title  year
#>              <char> <int>
#> 1: The Dispossessed  1974
books[.("9780306406157"), .(title, year)]
#>               title  year
#>              <char> <int>
#> 1: The Dispossessed  1974

# An unknown key gives a row of NA (nomatch = NA); nomatch = NULL drops it.
books[c("9780306406157", "0000000000000"), .(isbn, title)]
#>             isbn            title
#>           <char>           <char>
#> 1: 9780306406157 The Dispossessed
#> 2: 0000000000000             <NA>
books[c("9780306406157", "0000000000000"), .(isbn, title), nomatch = NULL]
#> Key: <isbn>
#>             isbn            title
#>           <char>           <char>
#> 1: 9780306406157 The Dispossessed

# mult picks one of several matches; here several books share an author.
setkey(books, author)
books["Mara Quill", .(title, year)]
#>                   title  year
#>                  <char> <int>
#> 1:   the quiet streets   2019
#> 2:           Loud Roofs  2021
#> 3:      Salt and Static  2018
books["Mara Quill", .(title, year), mult = "first"]
#>                   title  year
#>                  <char> <int>
#> 1:   the quiet streets   2019
books["Mara Quill", .(title, year), mult = "last"]
#>              title  year
#>             <char> <int>
#> 1: Salt and Static  2018
----

[[joins]]
=== Joins with on=

`pass:c[x[i, on = ...\]]` looks up the rows of `i` in `x`, and the result has one row for each row of `i` (for each match): in SQL terms
`pass:c[x[i\]]` is a right join, and `i` can be a data.table, a data frame, a list, or a vector. `on` names the columns to match: an unnamed
character vector when both tables have the same names (`on = "isbn"`, or `on = .(isbn)`), a named one when they differ
(`on = c(isbn = "code")`, or `on = "isbn==code"`), and an inequality for a non-equi join (next section). It overrides the keys of the
tables, and the help page recommends it even when the tables are keyed, because it makes the code readable. In `j`, a column of `i`
that has the same name as one of `x` is reached with the prefix `i.`, and one of `x` with `x.`.

The same tool makes the other joins of the table below. `nomatch = NULL` turns a join into an inner join, the `!` prefix gives the
rows of `x` that have no match in `i` (an anti join), `pass:c[x[i, col := i.col, on = ...\]]` is an update join that adds columns to `x`
by reference, and `by = .EACHI` evaluates `j` once for each row of `i`, with `.N` the number of matches, which is how counts and sums
over matches are written without first building the large joined table. `merge()` also works on data.tables, with `all`, `all.x`,
`all.y` and `by` as for data frames, `sort = TRUE` by default and a default `by` taken from the shared key (or the common column
names). A join that would produce more rows than `nrow(x) + nrow(i)` stops with an error unless `allow.cartesian = TRUE`, a guard
against joining on a key that is not unique in both tables.

[cols="2,3,3",options="header"]
|===
|SQL join |In `merge()` |With `on =`
|inner join |`merge(x, y, by = "k")` |`pass:c[x[y, on = "k", nomatch = NULL\]]`
|right join, keeping every row of `y` |`merge(x, y, by = "k", all.y = TRUE)` |`pass:c[x[y, on = "k"\]]`
|left join, keeping every row of `x` |`merge(x, y, by = "k", all.x = TRUE)` |`pass:c[y[x, on = "k"\]]`
|full outer join |`merge(x, y, by = "k", all = TRUE)` |no single form; use `merge()`
|anti join |not available |`pass:c[x[!y, on = "k"\]]`
|update join |not available |`pass:c[x[y, col := i.col, on = "k"\]]`
|cross join |not available (`by` must name columns) |`CJ()` for the combinations of vectors
|===

Source: https://rdatatable.gitlab.io/data.table/reference/merge.html[data.table package documentation: merge]

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)
setDT(loans)
books[, `:=`(isbn = gsub("[^0-9X]", "", isbn), genre = tolower(trimws(genre)))]

# x[i, on = ] looks every row of i up in x, so the result has the rows of i

[[rolling]]
=== Rolling and non-equi joins

Two joins have no counterpart in `merge()`. A rolling join, `roll = TRUE`, matches each row of `i` to the last row of `x` whose value is
less than or equal to it, in the last column of `on`; it is the tool for "the price, the fee or the status in force on this date". The
other values of `roll` are `-Inf` (the next row, the opposite direction), `"nearest"`, and a finite number that limits how far a row may be
carried. `rollends` decides what happens before the first row and after the last: by default a forward roll continues past the last
row, and a date before the first row gets `NA`. A non-equi join matches on `>=`, `>`, `+<=+` and `<` in `on`, which is how a value is placed in
a range or a band; the operators are written in `+on = .(lo <= pages, hi > pages)+` (a column of `x` on the left of each operator and a column of `i` on the
right) or as strings, `+on = c("lo<=pages", "hi>pages")+`. Joins on overlapping intervals have their own
function, `foverlaps()`
(https://rdatatable.gitlab.io/data.table/reference/foverlaps.html[data.table package documentation: foverlaps]). Non-equi joins match a row of `i` to every row of `x` that satisfies the condition, so the result can be larger than
either table.

The script gives each loan the late fee in force on its loan date from a small schedule (fees changed on 2025-07-01 and 2026-01-01),
then places books in page-size bands.

[source,r]

[[indices]]
=== Secondary indices and auto-indexing

A key reorders the table, and a table has one. A secondary index stores the sorted order of a column (a vector of row numbers) in an
attribute without moving any row, and a table can have many. `setindex(DT, col)` creates one, `indices(DT)` lists them, and
`setindex(DT, NULL)` removes them all. A subset on an indexed column, `pass:c[DT[col == value\]]`, `pass:c[DT[col %in% values\]]` or
`pass:c[DT[.(value), on = "col"\]]`, uses binary search through the index. Auto-indexing creates the index the first time a column is
used in `==` or `%in%` in `i`, so that the following subsets on that column are fast. The vignette says that auto-indexing is implemented for `==` and `%in%` (and for several of them combined with `&`), not yet for
`<` and `>=`, and that `on =` computes the index on the fly each time without saving it. It is on by default;
`options(datatable.auto.index = FALSE)` turns it off, and `options(datatable.use.index = FALSE)` stops the use of existing indices. Changing the
indexed column by reference drops the index, as the script shows, because it would no longer be correct. One consequence is that a `==` subset can change
the table it reads by adding an attribute, which is harmless for the data but visible in `attributes()`.

[source,r]
----
suppressPackageStartupMessages(library(data.table))

#> [1] "genre"

#> NULL

#>                    title
#>                   <char>
#> 1: Garden of Small Fires
#> 2:           Paper Moons
books[genre == "poetry", .(title)]
#>                    title
#>                   <char>
#> 1: Garden of Small Fires
#> 2:           Paper Moons

#> NULL
invisible(books[year == 2019])
indices(books)
#> [1] "year"

# Changing the indexed column by reference drops the index.
books[1, year := 1975L]
indices(books)

== Reading and writing files

`fread()` reads delimited text and returns a data.table. It detects the separator, the header, the quoting and the type of every
column, from a sample of 10,000 rows taken as 100 blocks spread over the file, and it re-reads a column from the beginning when a later row has a
higher type than the sample suggested. It is multi-threaded, and its help page describes it as similar to `read.csv()` but faster and
more convenient (compare xref:programming-languages/r/reading-and-writing-text-data.adoc[Reading and Writing Text Data]). The arguments
that matter most:

[cols="2,5",options="header"]
|===
|Argument |Use
|`input`, `file`, `text`, `cmd` |a path or URL, a path only, a string of text, or a shell command whose output is read
|`select`, `drop` |columns to keep or drop, by name or number; reading fewer columns is faster
|`colClasses` |as in `read.csv()`, and also a named list of class to column names, `list(character = c("a", "b"))`
|`na.strings` |strings read as `NA`; a quoted `""` is an empty string unless `na.strings = '""'`
|`nrows`, `skip` |the number of data rows to read and the lines to skip
|`sep`, `dec`, `quote` |`sep` and `dec` are detected by default (`dec` since 1.16.0); `quote` is the double quote
|`strip.white` |`TRUE` by default: leading and trailing blanks of unquoted fields are removed
|`integer64` |how integers larger than 2^31 are read: `"integer64"` (package bit64) by default, or `"double"` (as `read.csv()` does, possibly losing precision silently) or `"character"`
|`fill`, `blank.lines.skip`, `comment.char` |handling of ragged files
|`data.table` |`FALSE` returns a data.frame
|`nThread`, `showProgress` |threads for this call (default `getDTthreads()`), and a progress bar (default only when `interactive()`)
|`key`, `index` |set a key or an index on the result
|===

Two results in the script need a remark. The ISBNs of the loans are 13-digit numbers, so `fread()` reads them as numbers (`integer64`,
from package bit64), and an ISBN with a leading zero would lose it. The `colClasses` list is the fix, and it is the same discipline as `read.csv("loans.csv", colClasses = "character")` in the base
scenario. The date columns also differ: `return_date` is read as an `IDate` (data.table's integer-backed subclass of `Date`), and
`loan_date` as a plain `Date`, because that column holds the impossible date `2025-02-30` and cannot be parsed in one pass; with the
bad row removed, both columns are `IDate`. The compressed files `.gz` and `.bz2` (and `.zip` archives holding one file) are read by
`fread()` directly, according to its help page.

`fwrite()` writes a data.table or data frame, in parallel. It quotes a field only when it needs to (with `quote = "auto"`: when it contains the separator, a quote
or a line ending), writes dates as ISO 8601 and `NA` as an empty field, and has arguments for `sep`, `quote`, `na`, `col.names`,
`append`, `compress`, `nThread` and `encoding` (the last since 1.15.0). The default separator can be changed for a session with
`options(datatable.fwrite.sep = )`. A round trip is faithful with one trap that follows from the two defaults above: a value with
leading or trailing blanks is written unquoted, and `fread()` strips unquoted blanks by default, so `strip.white = FALSE` is needed to
read back what was written.

== Reshaping and stacking

`dcast()` and `melt()` change the shape of a table, and the formula that `dcast()` takes is the one described in
xref:programming-languages/r/formulas.adoc[Formulas]: `+rows ~ columns+`. `+dcast(DT, member ~ quarter, value.var = "N")+` makes one
row per member and one column per quarter; when several rows fall into one cell, `fun.aggregate` (a function, or a list of functions)
summarises them, and without it `dcast()` warns and counts the rows (the warning text is in <<errors,Common errors and warnings>>).
`fill` sets the value of empty cells, and an aggregate over no rows gives `NaN` for `mean()`, as the script shows for a member without
loans in a year. Since data.table 1.18.0, `dcast()` is an error when `fun.aggregate` returns more than one value. `melt()` turns columns
into rows: `id.vars` are kept, `measure.vars` are stacked, and `variable.name` and `value.name` name the two new columns. The helper
`measure()` (exported since 1.16.0) melts several groups of columns at once, using the pieces of the column names, as in
`measure(value.name, year = as.integer, sep = "_")`, which splits `loans_2025` into the output column `loans` and the value 2025 of the
column `year`.

`rbindlist()` stacks a list of tables in one pass, which its help page recommends for an unknown number of tables, such as the result of
`lapply(files, fread)`. `idcol` adds a column with the name of each list element, and `fill = TRUE` pads missing columns
with `NA`. Its default `use.names = "check"` is a trap: if the column names are the same set but in another order, `rbindlist()` sends a
message and then binds by position, as the script shows, with wrong results. `use.names = TRUE` matches by name, and `rbind()` on
data.tables has `use.names = TRUE` by default. Since data.table 1.16.0, `rbindlist()` also binds columns of different but compatible
classes (`Date` with `IDate`, for instance) and has `ignore.attr` to switch that safety net off. `split()` has a data.table method with
`by =` that returns a list of tables, and `rbindlist()` puts them back.

== Helper functions

data.table ships a set of vectorised helpers that are used inside `j`, but work on any vector. The first script covers the conditional
and membership ones: `fifelse()` is the help page's "faster and more robust replacement of `ifelse()`" (it keeps the attributes of the first non-missing
branch, so a `Date` stays a `Date`, which `ifelse()` does not do, and it requires `yes` and `no` to be of length 1 or of the length of
`test`; see <<errors,Common errors and warnings>>), `fcase()` is the `case_when()` of data.table (the first condition that is `TRUE` wins, and
`default =` catches the rest), `%between%` and `%inrange%` test ranges (`inrange()` against several ranges at once), `%chin%` is a
faster `%in%` for character vectors, `%like%` matches a regular expression (see
xref:programming-languages/r/strings-and-regular-expressions.adoc[Strings and Regular Expressions]), and `%notin%` is the negation of
`%in%`. The `fcase()` below splits the 32 overdue loans of the base-R analysis in
xref:programming-languages/r/data-frames.adoc[Data Frames] into 26 late loans and 6 very late ones (held for more than twice
`loan_days`), and the two loans that cannot be classified, the one returned before it was made and the one with no date, fall to the
`default`.

[source,r]

suppressPackageStartupMessages(library(data.table))

loans[, status := fifelse(is.na(return_date), "out", "returned")]

[[programming]]
== Programming with data.table

A query that names its columns in the code cannot be reused for another column, and building the text of a query for
`+eval(parse(text = ...))+` is fragile. data.table offers four routes, from the vignette
https://rdatatable.gitlab.io/data.table/articles/datatable-programming.html[data.table package documentation: Programming on data.table].

. `..var` in `j` (or `.SDcols = var`) looks up a character vector of column names in the calling scope. It selects columns; it does not
substitute names into an expression.
. `get(name)` and `mget(names)` inside `j` evaluate a name or names as columns. They work, but the column name is then hidden inside a string, where tools and readers cannot see it.
. `+env = list(a = value, ...)+` is the safe route: the names in the list are substituted into `i`, `j` and `by` BEFORE the query is
evaluated, as `substitute2()` does, so a function can take column names as arguments and build the query from them. By default a
character element of length 1 becomes a name (a longer one is an error), and `I()` keeps an element as it is, which is how a character
vector is inserted as a vector.
. `substitute2(expr, env)` shows the expression `env =` builds, which is how a generated query is checked. Its help page calls it an
experimental, more robust and friendlier `substitute()`.

The next script uses them in order. The function `mean_by()` carries the `nolint` comments mentioned in the introduction, because
lintr cannot see that `value` and `group` are substituted.

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)
books[, genre := tolower(trimws(genre))]

# 1. A column name held in a variable: ..col looks it up one level up.
col <- "pages"
books[1:3, ..col]
#>    pages
#>    <int>
#> 1:   387
#> 2:   432
#> 3:   214
# get() evaluates a name inside j; it works but hides the column from checks.
books[, mean(get(col), na.rm = TRUE)]
#> [1] 268.2143

# 2. env = substitutes names, calls and values into the query BEFORE it is
# evaluated, so the expression stays readable and safe.
mean_by <- function(tbl, value, group) {
  # nolint start: object_usage_linter.
  tbl[, .(avg = mean(value, na.rm = TRUE), n = .N), by = group,
      env = list(value = value, group = group)]
  # nolint end
}
mean_by(books, "pages", "genre")[1:2]
#>              genre   avg     n
#>             <char> <num> <int>
#> 1: science fiction   373     3
#> 2:         classic   356     2

# substitute2() shows what env = builds.
substitute2(mean(value, na.rm = TRUE), list(value = as.name("pages")))
#> mean(pages, na.rm = TRUE)
substitute2(f(x), list(f = "sum", x = "pages"))
#> sum(pages)

# 3. Many columns at once: .SDcols takes a character vector, and env with
# I() inserts a character vector as a vector (not as a name).
num_cols <- c("year", "pages")
books[, lapply(.SD, max, na.rm = TRUE), .SDcols = num_cols]
#>     year pages
#>    <int> <int>
#> 1:  2023   432
books[, cols, env = list(cols = I(num_cols))][1:2]
#>     year pages
#>    <int> <int>
#> 1:  1974   387
#> 2:  1813   432

# 4. Assigning to a column whose name is in a variable: (var) := value.
new_col <- "pages_k"
books[, (new_col) := pages / 1000]
books[1:2, .(title, pages_k)]
#>                  title pages_k
#>                 <char>   <num>
#> 1:    The Dispossessed   0.387
#> 2: Pride and Prejudice   0.432
books[, c(new_col) := NULL]
names(books)
#> [1] "title"  "author" "isbn"   "year"   "genre"  "pages"
----

== Printing and threads

`print.data.table()` has arguments for the number of rows shown (`nrows`, default 100, and `topn`, default 5: a longer table shows
the first and last `topn` rows with a `---` line between), `class` (the line of column classes), `row.names`, `col.names` (`"auto"`,
`"top"` or `"none"`), `print.keys` (the key and indices above the data), `trunc.cols` (only the columns that fit the width) and
`quote`. Every default is read from an option, `datatable.print.nrows`, `datatable.print.topn`, `datatable.print.class`,
`datatable.print.keys`, `datatable.print.rownames`, `datatable.print.colnames` and `datatable.print.trunc.cols`, so a session or a
profile can change it for every table (options are set in a script or in a startup file; see
xref:programming-languages/r/sessions-workspaces-and-startup.adoc[Sessions, Workspaces and Startup]). Character cells longer than `datatable.prettyprint.char` characters are truncated with
`+...+`. When a table of more than 20 rows is printed in full, since 1.18.0 the column classes are repeated at the bottom as the names already were (a truncated table, as in the first script below, shows its `---` line instead).

Threads are controlled separately. `fread()`, `fwrite()`, `forder()` (the sort behind `setkey()` and
`order()` in `i`), grouping with `GForce`, `fifelse()`, `nafill()` and a few other functions use OpenMP threads. The number of threads is
decided when the package is loaded: 50% of the logical CPUs by default (`R_DATATABLE_NUM_PROCS_PERCENT` changes the percentage and
`R_DATATABLE_NUM_THREADS` fixes the number, both read at load time), and never more than `OMP_THREAD_LIMIT` allows. `getDTthreads()`
reports it, and `setDTthreads(n)` changes it for the session (`setDTthreads(0)` is all logical CPUs) and returns the previous setting. The number depends on the machine, so the script prints only a comparison with 1 and a restored value. A `throttle`
(default 1024 rows) keeps small tasks on one thread, and data.table switches to a single thread inside a forked process (the mechanism
of `parallel::mclapply()`), so it does not oversubscribe the CPUs of code that is already parallel. CRAN's own checks set
`OMP_THREAD_LIMIT` to 2, and a package must not raise it above 2. See
xref:programming-languages/r/parallel-and-asynchronous-computing.adoc[Parallel and Asynchronous Computing] for the other parallel tools.

=== Overdue loans

A loan is overdue when it was held for more than `loan_days` (21) days: until the return date when there is one, and until
`shelf_today` (2026-06-30) when the book is still out. `fifelse()` picks the end date and keeps its class, so the subtraction is
between dates. The counts agree with the base-R page (27, 32 and 1), and the remaining overdue loans are the books to chase.

[source,r]

suppressPackageStartupMessages(library(data.table))
source("scenario.R")

  loan_date = as.Date(loan_date),
  return_date = as.Date(return_date)
)]

# Days held: until the return date, or until shelf_today when still out.
loans[, held := as.integer(fifelse(is.na(return_date), shelf_today,
                                   return_date) - loan_date)]
loans[, overdue := held > loan_days]
loans[1:4, .(loan_id, held, overdue)]

#>     <char> <int>  <lgcl>
#> 1:    L001    21   FALSE
#> 2:    L002    10   FALSE
#> 3:    L003     1   FALSE
#> 4:    L004    26    TRUE
loans[, .N, by = overdue][order(overdue)]
#>    overdue     N
#>     <lgcl> <int>
#> 1:   FALSE    27
#> 2:    TRUE    32
#> 3:      NA     1

== data.table or dplyr?

The two packages answer the same question, how to write a table transformation as a short, readable pipeline, and both are valid
choices. They differ in the vocabulary, in the treatment of the table, and in the cost of a wrong guess. The table lines up the same
operations in base R (the functions of xref:programming-languages/r/data-frames.adoc[Data Frames]), dplyr (the verbs of
xref:programming-languages/r/tidyverse-and-dplyr.adoc[The tidyverse and dplyr], following the official dplyr vignette on base R
equivalents) and data.table.

Speed depends on the operation, the size of the data and the machine, so this page prints no timings. The data.table website links to
the db-benchmark project (https://duckdblabs.github.io/db-benchmark/[db-benchmark], whose page lists the timings with the syntax timed and
the machine type, from 16 cores and 32 GB to 128 cores and 256 GB), and
xref:programming-languages/r/performance-profiling-and-benchmarking.adoc[Performance, Profiling and Benchmarking] shows how to measure a
real case with `bench`. The differences that do not depend on timings are these:

* *Syntax.* dplyr is a set of verbs, each doing one thing, joined with the pipe; data.table is one query form with three slots, in
which the work of several verbs fits into one call. The SQL reading of `pass:c[DT[i, j, by\]]` is a way to learn it.
* *Copying.* dplyr verbs return a new table and leave the input alone, so a pipeline can be reasoned about step by step; `:=` and the
`+set*+` functions change the table in place, which saves a copy of a large table and makes it easy to change something the caller did not
expect (see <<pitfalls,Pitfalls>>).
* *Joins.* dplyr has `join_by()` for equality, inequality, rolling and overlap joins since version 1.1.0
(https://dplyr.tidyverse.org/reference/join_by.html[dplyr package documentation: join_by]), so the two cover the same ground;
data.table's `on =` is terser, and `by = .EACHI` evaluates `j` for each row of `i`, which the error message for an accidental
many-to-many join suggests as a way "to avoid the large allocation".
* *Files.* `fread(data.table = FALSE)` returns a plain data frame and `fwrite()` writes data frames, so the two functions can be used
with either package.
* *Dependencies.* data.table depends on R 3.4.0 and imports only `methods`, which ships with R (`packageDescription("data.table")` in the
image used here). dplyr 1.2.1 depends on R 4.1.0 and imports thirteen packages (cli, generics, glue, lifecycle, magrittr, methods,
pillar, R6, rlang, tibble, tidyselect, utils and vctrs).
* *Mixing.* A data.table is a data frame, so the dplyr verbs accept it, but code that mixes the two vocabularies is read by people who
must know both, and a `:=` among pipes can surprise a reader who expects a copy. Teams usually choose one for the main pipeline.
* *dtplyr.* The package dtplyr (https://dtplyr.tidyverse.org/[dtplyr package documentation]) is a data.table back end for dplyr: its
README states the goal as translating dplyr code into the equivalent data.table code. It is installed in the image used for the examples
and is not run on this page.

[[pitfalls]]
== Pitfalls

* *`pass:c[DT[, 2\]]` is a data.table, not a vector.* A data frame drops a single column to a vector; data.table never does. Use
`pass:c[DT[[2\]\]]`, `pass:c[DT[, col\]]` or `DT$col` for the vector.
* *`+b <- a+` is not a copy.* A `:=` or `+set*+` call on `b` changes `a` too, and so does the same call inside a function that was given
`a`. Use `copy()` when the original must stay as it is. This is the opposite of the copy-on-modify rule that the rest of R follows
(xref:programming-languages/r/memory-and-copy-semantics.adoc[Memory and Copy Semantics]).
* *A column wins over a variable.* In `i`, `j` and `by` a name is looked up among the columns first, so after `+year <- 1900+` the
query `pass:c[DT[year > 2022\]]` still compares the column. Use `..var`, `env =` or a differently named variable.
* *`pass:c[x[y\]]` is a join, and the order matters.* `pass:c[x[i, on = \]]` starts from the rows of `i`. `pass:c[books[loans, on = "isbn"\]]` has 60 rows, one for each loan, and
`pass:c[loans[books, on = "isbn"\]]` starts from the books: a row for each loan of each book, and one row for a book that was never loaned.
* *Check how a join matched.* Keys that are not unique give a many-to-many join (an error unless `allow.cartesian = TRUE`), types that
differ give an error, and values that look alike but are not equal (trailing blanks, an ISBN with one digit missing) give `NA`.
* *`rbindlist()` binds by position unless told otherwise.* `use.names = "check"` (the default) reports a different order with a
message and binds by position. Pass `use.names = TRUE`.
* *`fread()` guesses.* A column of 13-digit codes is `integer64`; an empty quoted string stays `""`; unquoted blanks are stripped;
a date column with one impossible date is a different class from one without. Fix the types with `colClasses` and check them with
`pass:c[vapply(DT, \(x) class(x)[[1L\]\], character(1))]`.
* *Sorting is in C-locale.* `setkey()`, `setorder()` and `order()` in `i` sort capitals before lower case in every locale. Sort by the
locale of the session with `pass:c[DT[base::order(...)\]]` when that is what is wanted.
* *A function that ends with `:=` may print nothing.* Add a trailing `pass:c[[\]]` (see <<printing-after-assignment,Printing after the := operator>>).
* *Base replacement functions copy.* `+attr<-+`, `+class<-+` on a data frame and `structure()` produce tables that `:=` has to repair with a
warning (<<selfref,the self-reference warning>>). Use `setattr()`, `setDT()` and `setnames()`.
* *Loops need `set()`.* A `for` loop of `pass:c[DT[...\]]` calls pays the cost of the bracket on every iteration; `set()` does not.
* *Packages that use data.table.* In a package, import the symbols (`import(data.table)` or `importFrom(data.table, :=, .N)`), and
declare the columns used in `pass:c[DT[...\]]` to avoid the `R CMD check` NOTE about "no visible binding for global variable" (assign
them `NULL` or use character names), as the importing vignette describes; see
xref:programming-languages/r/packages-libraries-and-namespaces.adoc[Packages, Libraries and Namespaces] and
xref:programming-languages/r/creating-packages.adoc[Creating Packages].

The 1.18 additions that this page ran are in the next script. The row deletion works only with `i` (not `by`), clears the keys and
the indices of the table, and is the newest item in the table; the `mergelist()` call joins a list of tables from left to right with
`how` set to `"inner"` or `"left"` (the other modes are `"right"`, `"full"`, `"semi"`, `"anti"` and `"cross"`).

[source,r]
----
suppressPackageStartupMessages(library(data.table))
source("scenario.R")
setDT(books)

# data.table 1.18.6.1: rows can be deleted by reference with .ROW := NULL.
# Only i selects the rows (no by), and keys and indices are dropped.
n_before <- nrow(books)
books[is.na(year) | is.na(pages), .ROW := NULL]
c(before = n_before, after = nrow(books))
#> before  after
#>     16     13
books[, .(title, year, pages)][1:3]
#>                   title  year pages
#>                  <char> <int> <int>
#> 1:     The Dispossessed  1974   387
#> 2:  Pride and Prejudice  1813   432
#> 3:   the quiet streets   2019   214

# data.table 1.18.0: a sort_by() method for data.tables (see base R 4.4.0).
sort_by(books[, .(title, year)], ~year)[1:3]
#>                  title  year
#>                 <char> <int>
#> 1: Pride and Prejudice  1813
#> 2:    The Dispossessed  1974
#> 3:    The Lamp at Noon  1999

# data.table 1.18.0: mergelist() joins a list of tables, left to right.
parts <- list(
  data.table(id = 1:3, x = c("a", "b", "c")),
  data.table(id = c(1L, 2L, 4L), y = c("d", "e", "f")),
  data.table(id = c(1L, 3L, 4L), z = c("g", "h", "i"))
)
mergelist(parts, on = "id", how = "inner")
#>       id      x      y      z
#>    <int> <char> <char> <char>
#> 1:     1      a      d      g
mergelist(parts, on = "id", how = "left")
#>       id      x      y      z
#>    <int> <char> <char> <char>
#> 1:     1      a      d      g
#> 2:     2      b      e   <NA>
#> 3:     3      c   <NA>      h
----

== Where older tutorials differ

Much data.table material on the web predates the 1.15 to 1.18 releases. Most of it still runs; the differences below are the ones a
reader will meet.

[cols="3,3,4,2",options="header"]
|===
|Older tutorial |Current practice |Why |Version
|`+data.table(..., stringsAsFactors = FALSE)+` on every call |leave the argument out |its default is `FALSE`, and since R 4.0.0 so is that of `data.frame()` |R 4.0.0
|a join needs `setkey(x, k)` first, and `pass:c[x[y\]]` joins the keys |`pass:c[x[y, on = "k"\]]`, with keys optional |the help page recommends `on =` even for keyed tables; `on =` also allows non-equi and rolling joins |inequalities in `on =` since 1.9.8
|`dcast.data.table()` and `melt.data.table()` called by their full names |`dcast()` and `melt()` |`melt()` became a standard generic in 1.15.0 so that other packages can add methods; `dcast()` is data.table's own function and accepts a data.table (the full names still work) |1.15.0
|append `pass:c[[\]]` to every `:=` to see the result |`pass:c[print(DT[, y := 2\])]` prints; `pass:c[[\]]` is needed only at the end of a function that ends with `:=` |the detection of auto-printing was improved in 1.17.0 for the explicit `print()` case |1.17.0
|some older posts attribute the "Invalid .internal.selfref detected" warning to `readRDS()` or `load()` |`:=` and `set()` work silently on a table read back; the warning marks a table that R copied or that was built by hand |the message of 1.18.6.1 starts "A shallow copy of this data.table was taken" |1.18.6.1
|`rbind.fill()` from plyr, or `rbind()` that fails on different columns |`rbindlist(l, fill = TRUE)` or `rbind(a, b, fill = TRUE)` |both pad the missing columns with `NA`; `use.names = TRUE` matches by name |current
|`+eval(parse(text = ...))+`, `get()` or `bquote()` to program on columns |`+env = list(...)+` and `..var` |`env` substitutes names safely before evaluation |1.15.0
|`reshape2::melt()` and `reshape2::dcast()` on a data.table |`data.table::melt()` and `data.table::dcast()` |data.table has its own, which take several value columns (`measure()`, several `value.var`); the message of data.table's `dcast()` calls reshape2 superseded |current
|`fread(autostart = )`, `fwrite(logicalAsInt = )` and `droplevels(in.place = TRUE)` |`skip =`, `fwrite()` without the argument, and `setdroplevels()` |the arguments were removed in 1.18.0 (`in.place` was deprecated in 1.16.0) |1.18.0
|`options(datatable.nomatch = )` |`nomatch =` in the query |setting the option has been an error since 1.18.0, after warning from 1.15.0 |1.18.0
