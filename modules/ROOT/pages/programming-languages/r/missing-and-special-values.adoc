Statistics is the field where R was born, and a statistical language has to answer a question that most languages avoid: what do you store when a value exists in the world but you do not know it? R's answer is a family of special values. `NA` is the marker for a value that is not available, `NaN` is the result of arithmetic that has no sensible answer, `Inf` and `-Inf` are the infinities of IEEE 754 arithmetic, and `NULL` is the absence of an object altogether. They look alike on the console and they are tested in different ways, and most of the errors that beginners meet (`+missing value where TRUE/FALSE needed+`, `+argument is of length zero+`, a mean that comes out as `NA`) are one of these four being used as if it were another. This page separates the four, shows the rule by which `NA` spreads through a computation, lists the tools that remove, count and fill missing values, and ends with the zero-length vectors that `NULL` has as relatives and the checks that keep a condition from receiving one.

== Four things that are called "missing"

The manuals keep the four notions apart, and so must you. An Introduction to R introduces `NA` in the section on missing values: when a value is not available in the statistical sense, a place in the vector is reserved for it with the special value `NA`; any operation on an `NA` becomes an `NA`, because if the specification of an operation is incomplete the result cannot be known; and `is.na(x)` is the function that finds them (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Missing-values[An Introduction to R: Missing values]). The R Language Definition adds that this is the statistical sense of "missing" and must not be confused with the `missing` property of a function argument that was not supplied (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#NA-handling[The R Language Definition: NA handling]); that other meaning is on xref:programming-languages/r/functions.adoc[Functions]. `NULL` has its own subsection in the Language Definition: a special object used whenever it is necessary to indicate that an object is absent, and it should not be confused with a vector or list of zero length (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#NULL-object[The R Language Definition: NULL]).

[[missing-na]]
== NA and its typed variants

`NA` is a reserved word, a logical constant of length 1 that contains a missing-value indicator, and it can be coerced to any other vector type except raw. There are also constants for the other atomic types that support missing values: `NA_integer_`, `NA_real_`, `NA_complex_` and `NA_character_`. The help page documents that all five are reserved words in the language (https://search.r-project.org/R/refmans/base/html/NA.html[R documentation: NA]). The reason there are several is that an atomic vector has one type, so the missing value inside it must have that type too. The Language Definition points out the one case in which the difference matters to a user: the default `NA` is logical, so a bare `NA` used as an index triggers logical rather than numeric indexing (see <<missing-origins,Where missing values come from>>).

The first block shows the five constants and how a vector keeps its type when an `NA` joins it: `+c(1L, NA)+` is still integer, `+c("a", NA)+` is still character, because the logical `NA` is the lowest type in the coercion order and is promoted to the type of the other elements. The second block is the most common confusion: the character `NA` is not the string `"NA"`. A vector `+c("NA", NA)+` holds a string with two letters and a missing value; `is.na()` finds only the second, `nchar()` reports 2 for the first and `NA` for the second, and printing without quotes shows the missing one as `<NA>` to tell them apart (the Introduction to R mentions this printing). Real data brings the string case from files: `read.csv()` treats the text `NA` as a missing value in every column, including text columns (its `na.strings` argument defaults to `"NA"`), which is how the country code of Namibia becomes a missing value; `na.strings = character(0)` keeps it as text. The block after the empty year of the shelf shows both reads (the script builds the data with a text string, so no file is needed).

The type of an `NA` is visible to `identical()`, which compares the type as well as the value, and to the `+is.*()+` functions: `+identical(NA, NA_integer_)+` is `FALSE` even though both print as `NA`, and `is.numeric(NA)` is `FALSE` because the plain `NA` is logical. That is why code that must return a typed missing value spells it out. The `book()` helper of the shelf scenario has `author = NA_character_` and `year = NA_integer_` as defaults, which is what lets `validate_book()` and `new_book()` check types with `is.character()` and `is.integer()`; and `vapply()` needs a template of the right type, as in `+vapply(x, f, NA_real_)+`, where the `NA_real_` is only a way of writing a length-one double (see xref:programming-languages/r/apply-family-and-functionals.adoc[The apply Family and Functionals]).

#> [1] FALSE

Coercion keeps the missingness and changes the type: `as.integer(NA)`, `as.character(NA)` and `as.numeric(NA_character_)` are all missing values of the new type, and `as.character(NA)` is `NA_character_`, never the string `"NA"`. `rep(NA_real_, 3L)` is the idiom for a double vector that is to be filled later; `character(2L)` is two empty strings, not two missing values, and `numeric(3L)` is three zeros, which silently look like data. The last block shows the one type with no missing value: `as.raw(NA)` is `00` with a warning, because a byte cannot be unknown (the Language Definition says there is no `NA` for raw vectors).

[[missing-nan-inf]]
== NaN, Inf and -Inf

`NaN` ("not a number") and the infinities come from the floating-point arithmetic of the computer, not from R, and R follows IEEE 754 for doubles. Dividing a nonzero double by zero gives `Inf` or `-Inf`; `log(0)` is `-Inf`; a computation that overflows, such as `exp(1000)`, is `Inf`; and an operation with no defined result (`0/0`, `Inf - Inf`, `+Inf * 0+`) is `NaN`. The Language Definition says that `NaN` exists only in the double type and in the real or imaginary components of the complex type (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#NA-handling[The R Language Definition: NA handling]). An integer has no way to store either: integer division by zero is `NA` (`5L %/% 0L`), while the double `5 %/% 0` is `Inf` and `5 %% 0` is `NaN`, as described on xref:programming-languages/r/numbers-and-arithmetic.adoc[Numbers and Arithmetic].

A function called outside its domain returns `NaN` and says so with the warning `+NaNs produced+`, which is the same warning for `sqrt(-1)` and `log(-1)`. It is a warning because the result is a legitimate `NaN`, so the computation continues; the script catches it to print its text.

[source,r]
----
# Where NaN and Inf come from: arithmetic that has no sensible answer

#> [1] NaN
Inf - Inf

Inf * 0
#> [1] NaN
1 / 0
#> [1] Inf
-1 / 0
#> [1] -Inf
5 %% 0
#> [1] NaN
5 %/% 0
#> [1] Inf
5L %/% 0L
#> [1] NA
5L %% 0L
#> [1] NA
log(0)
#> [1] -Inf
exp(1000)
#> [1] Inf

#> [1] Inf

The four predicates are summarised by the next block. They answer different questions: `is.na()` is `TRUE` for `NA` and for `NaN`, `is.nan()` is `TRUE` only for `NaN`, `is.finite()` is `TRUE` only for ordinary numbers (it is `FALSE` for `NA`, `NaN` and both infinities), and `is.infinite()` is `TRUE` only for the infinities. Be careful with the direction of the relation: every `NaN` is `NA` as far as `is.na()` is concerned, but an `NA` is not a `NaN`, so `is.nan(NA)` is `FALSE`. If you need to tell the cases apart, test `is.nan()` first, or use `is.na(x) & !is.nan(x)` for "a true `NA`".

[source,r]
----
# The four tests, on the same six values
v <- c(1, NA, NaN, Inf, -Inf, 0)
v
#> [1]    1   NA  NaN  Inf -Inf    0
rbind(
  is_na = is.na(v),
  is_nan = is.nan(v),
  is_finite = is.finite(v),
  is_infinite = is.infinite(v)
)

#> is_na       FALSE  TRUE  TRUE FALSE FALSE FALSE
#> is_nan      FALSE FALSE  TRUE FALSE FALSE FALSE
#> is_finite    TRUE FALSE FALSE FALSE FALSE  TRUE
#> is_infinite FALSE FALSE FALSE  TRUE  TRUE FALSE

The help page for `NA` warns about one more difference between the two. A numerical computation that mixes an `NA` and a `NaN` (for example `pass:c[NA_real_ + NaN]`) may give either, depending on the platform and the compiler, and the help page says this is not guaranteed and may change on future CPUs, so this page does not print such a result and your code should not depend on it (https://search.r-project.org/R/refmans/base/html/NA.html[R documentation: NA]). Test for both with `is.na()` and do not rely on which of the two a mixed computation yields.

Comparisons follow the same rule as `NA`: `NaN` is not comparable, even to itself, so `NaN == NaN` is `NA`. The infinities, in contrast, are ordinary values that can be compared, so `Inf == Inf` is `TRUE` and `Inf > 1e308` is `TRUE`; `max()` and `range()` return them without complaint, which is why a `-Inf` or `Inf` in a result is a clue that a maximum or minimum was taken over an empty vector (see <<missing-zero-length,Zero-length vectors>>). Three rules hold for every argument, `NA` and `NaN` included, because the answer does not depend on the unknown: `+NA^0+` is 1, `+1^NA+` is 1, and `+Inf^0+` is 1, as documented on the help page of the arithmetic operators. `+NA * 0+`, in contrast, is `NA`, not 0: R applies no algebraic shortcut to an unknown, only the documented rules.

[source,r]
----
# Comparisons: NaN is incomparable, Inf is an ordinary extreme
NaN == NaN # nolint: equals_na_linter.
#> [1] NA
Inf == Inf
#> [1] TRUE
Inf > 1e308
#> [1] TRUE
-Inf < 0
#> [1] TRUE
Inf > NA
#> [1] NA
max(c(1, Inf, NA), na.rm = TRUE)
#> [1] Inf
range(c(2, Inf, -Inf, 7))
#> [1] -Inf  Inf
----

`is.finite()` and `is.infinite()` accept any vector: they return `FALSE` for strings (a string is not a finite number), `TRUE` for finite integers and logicals, and `logical(0)` for `NULL`. [[missing-null]]
== NULL

`NULL` is the one object of the type `NULL`. It has length 0, no attributes and no modifiable properties, and there is only one `NULL` in R, to which every reference points. It is what R returns when there is nothing to return: a function whose body is empty or that ends with an `if` without a taken branch, a `for` loop, `invisible(NULL)`, a missing list component. It is also how you ask for something to be removed (`+x$a <- NULL+`, `+rownames(m) <- NULL+`) and how you say that an argument has no value (`f(data = NULL)`). The first block shows the type and the family resemblance to the empty vector and the empty list: they all have length 0 but they are three different objects, `identical(NULL, list())` and `identical(NULL, logical(0))` are `FALSE`, and `NULL` is the only one for which `is.null()` is `TRUE`.

R 4.4.0 changed one of these relationships: `is.atomic(NULL)` is now `FALSE`, because `NULL` is not an atomic vector. The NEWS entry notes that strict backward compatibility for old code means replacing `is.atomic(foo)` by `+is.null(foo) || is.atomic(foo)+`, which should happen sparingly (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.4.0]). In the same release `NCOL(NULL)` became 0 instead of 1, for consistency with `cbind()` (<<missing-nrow,NROW and NCOL>> below).

[source,r]
----
# NULL is its own type, with length 0 and no attributes
typeof(NULL)
#> [1] "NULL"
class(NULL)

`NULL` vanishes when it is combined: `c(1, NULL, 3)` is a vector of two elements, `c(NULL, NULL)` is `NULL`, and `unlist()` drops the `NULL` components of a list. [[missing-is-na]]
== is.na() versus == NA

The Introduction to R states the rule in one sentence: `x == NA` is quite different from `is.na(x)`, because `NA` is not a value but a marker for a quantity that is not available, so the comparison asks whether an unknown is equal to another unknown, which is undecidable and therefore `NA` (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Missing-values[An Introduction to R: Missing values]). The result of `x == NA` is a vector of the length of `x` made only of `NA`, whatever `x` holds. Using it as an index returns a vector of `NA`s, summing it gives `NA`, and using it in an `if` is an error. The default `lintr` linters flag `x == NA` (`equals_na_linter`) for this reason, which is why the first block has `# nolint` comments: it is showing the mistake on purpose.

[source,r]
----
source("scenario.R")

# x == NA is never TRUE and never FALSE: every element is NA
books$year == NA # nolint: equals_na_linter.
#>  [1] NA NA NA NA NA NA NA NA NA NA NA NA NA NA NA NA
books$year[books$year == NA] # nolint: equals_na_linter.
#>  [1] NA NA NA NA NA NA NA NA NA NA NA NA NA NA NA NA
sum(books$year == NA) # nolint: equals_na_linter.
#> [1] NA
----

Source: https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Missing-values[An Introduction to R: Missing values]

`is.na()` is the test. It returns a logical vector of the same length (copying the `names`, `dim` and `dimnames` of its argument), so `which(is.na(x))` gives the positions, `pass:c[x[is.na(x)\]]` the missing elements, `sum(is.na(x))` the number of them and `mean(is.na(x))` the proportion, because `TRUE` counts as 1. The next block finds the one book without a year (row 7, "Garden of Small Fires") and shows the proportion of unknown page counts, 2 of 16. When the result must be a single `TRUE` or `FALSE` for an `if`, remember that a comparison involving an `NA` is itself `NA`: `if (first_year < 2000L)` stops with `+missing value where TRUE/FALSE needed+` when the year is unknown, and `if (NA)` stops with the same message. Decide what an unknown should do and say it: `if (is.na(first_year))` handles it first, or `isTRUE(first_year < 2000L)` folds the unknown into `FALSE`.

[[missing-origins]]
== Where missing values come from

A missing value enters a computation from a short list of places, and knowing the list helps to find the one that put it there. Data entry is the obvious source: an empty field in a CSV file becomes `NA` in numeric, logical and date columns (the year of "Garden of Small Fires", the page counts of the two books with a blank, the unreturned loans), and a text that cannot be parsed becomes `NA` with a warning. The rest are R's own rules, and the script below shows them in turn:

* An index that selects an element that does not exist gives `NA` for an atomic vector (`pass:c[x[5L\]]`, `pass:c[x["z"\]]`) and `NULL` for a list (`pass:c[lst[["z"\]\]]`), while the double-bracket forms on an atomic vector stop with `+subscript out of bounds+`. An `NA` in the index itself gives an `NA` element (`pass:c[x[c(1L, NA)\]]`), with the names of an atomic vector turning into `<NA>`.
* The type of the `NA` used as an index matters. A bare `NA` is logical, so `pass:c[y[NA\]]` is a logical index, which is recycled to the length of `y` and selects every element as unknown: the result is four `NA`s. `pass:c[y[NA_integer_\]]` is an integer index and selects one element, the result being one `NA`. The Language Definition points at this case in its NA handling section (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing-by-vectors[The R Language Definition: Indexing by vectors]).
* A logical index that contains `NA` gives an `NA` for each `NA` in the index. In a data frame this means a whole row of `NA`s with the row name `NA`: with the two unknown page counts, `pass:c[books[books$pages > 300L, \]]` has 8 rows although only 6 books have more than 300 pages, and the 4th and 5th rows of the printed excerpt show one of the phantom rows. `which()` drops the `NA`s, `subset()` does so too, and `!is.na(big) & big` says it explicitly. This is the most common way for missing values to damage a data frame silently.
* Assignment with an `NA` index is restricted: `+z[c(1L, NA)] <- c(0L, 1L)+` is an error, `+NAs are not allowed in subscripted assignments+`, because R cannot know which of the two values goes where; it is allowed with a single replacement value, and the `NA` positions are skipped.
* Making a vector longer with `+length<-+`, and joins that keep unmatched rows (`merge(all = TRUE)`, `merge(all.x = TRUE)`), pad with `NA`.
* Numbers: integer overflow gives `NA` with the warning `+NAs produced by integer overflow+`, a failed parse with `as.integer("seven")` gives `NA` and the warning `+NAs introduced by coercion+`, and a conversion outside the integer range gives `NA` and `+NAs introduced by coercion to integer range+` (see xref:programming-languages/r/numbers-and-arithmetic.adoc[Numbers and Arithmetic]).

[[missing-propagation]]
== How NA propagates

The rule of the manuals is that numeric and logical calculations with `NA` generally return `NA`, because the result would depend on a value nobody knows. The exceptions are the cases where the answer would be the same whatever the unknown was, and R does implement those: `FALSE & NA` is `FALSE` and `TRUE | NA` is `TRUE` (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#NA-handling[The R Language Definition: NA handling]). It is Kleene's three-valued logic, with `NA` as the third value "unknown". The first block shows arithmetic and comparison (every one is `NA`), and the second the logic operators, which are worth learning as a table:

[cols="1,1,1,1,1",options="header"]
|===
|`x` |`y` |`x & y` |`pass:c[x \| y]` |`!x`

|`TRUE`
|`NA`
|`NA`
|`TRUE`
|`FALSE`

|`FALSE`
|`NA`
|`FALSE`
|`NA`
|`TRUE`

|`NA`
|`NA`
|`NA`
|`NA`
|`NA`
|===

Source: https://search.r-project.org/R/refmans/base/html/Logic.html[R documentation: Logic]

The same logic extends to the summaries `any()` and `all()`: `any(c(NA, TRUE))` is `TRUE` because one `TRUE` is enough whatever the unknown is, while `any(c(NA, FALSE))` is `NA`; `all(c(NA, FALSE))` is `FALSE` and `all(c(NA, TRUE))` is `NA`. The scalar operators `&&` and `||` evaluate left to right and stop as soon as the answer is known, so `FALSE && NA` is `FALSE` and `TRUE || NA` is `TRUE`, but `NA && TRUE` is `NA`; a guard of the form `+isTRUE(x) && ...+` or `+!is.na(x) && ...+` keeps the unknown out of the condition (see xref:programming-languages/r/operators-and-precedence.adoc[Operators and Precedence] for the length-one rule and its errors).

=== Summaries and na.rm

A summary of a vector that contains an `NA` is `NA`, because the sum or the maximum of a set that includes an unknown is unknown. Most summary functions take the argument `na.rm`, which, when `TRUE`, removes the missing values (the `NA`s and the `NaN`s) before the computation. `sum(books$pages)` is `NA` and `sum(books$pages, na.rm = TRUE)` is 3755, the sum of the 14 known page counts; the mean is 268.2143 (rounded by the printing), the median 268, the range 88 to 432. `na.rm = TRUE` answers the question "of the values I know", and it changes the size of the sample behind the statistic, so for a report you also want the count of what was dropped (`sum(is.na(x))`).

The `na.rm` argument must be a single `TRUE` or `FALSE`. Since R 4.4.0, a call that names it twice, for instance `sum(1, na.rm = TRUE, na.rm = FALSE)`, is an error: `+formal argument "na.rm" matched by multiple actual arguments+`; before, the summary group silently produced either of two answers (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.4.0]). An `NA` as the value of `na.rm` is also an error for `sum()`: `+NA in coercion to boolean+`.

=== Strings, sorting and tables

Strings have their own missing value, `NA_character_`, and the string functions disagree on what to do with it. Most keep it (`toupper()`, `substr()`, `trimws()`, `nchar()` return `NA`), but `paste()` and `paste0()` convert it to the text `"NA"` (`+paste("pages:", c(214L, NA))+` is `"pages: NA"`), `sprintf()` does the same, and `format()` pads it to the common width. So a result that goes through `paste()` can no longer be tested with `is.na()`; test the inputs first. `nchar()` has a `keepNA` argument: the default returns `NA` for the character types (`type = "chars"` and `"bytes"`) and 2 for `type = "width"`, and `keepNA = FALSE` always returns 2, the number of characters in the printed `NA`. `nzchar(NA)` is `TRUE` by default, which means that `nzchar()` is not a missing-value test either: use `!is.na(x) && nzchar(x)` for "a non-empty string" (`nzchar(x, keepNA = TRUE)` returns `NA` for an `NA`).

Failing coercions produce `NA` and a warning, and the shape of the warning is the same in all of them: `+NAs introduced by coercion+`. That is a signal, not a nuisance, and the way to deal with it is to look at the strings that failed (`pass:c[x[is.na(as.numeric(x)) & !is.na(x)\]]`, with the warning suppressed) rather than to suppress the warning on the first line.

Sorting must put the missing values somewhere. `sort()` removes them by default (`na.last = NA`) and `order()` puts them last (`na.last = TRUE`), so the two do not agree on a vector with an `NA`: `sort(x)` has 3 elements and `pass:c[x[order(x)\]]` has 4. Both take `na.last = TRUE`, `FALSE` or `NA` (for `order()`, `NA` removes the indices; for `sort()` it removes the values), and `rank()` has the further choice `na.last = "keep"`, which returns an `NA` rank for an `NA` value instead of ranking it. The consequence for a data frame: `pass:c[books[order(books$pages), \]]` puts the two books with an unknown page count at the end, while `order(books$pages, na.last = NA)` leaves them out; the head of `pass:c[books[order(books$pages, decreasing = TRUE), \]]` shows the largest known books, still with the unknown ones last in the full result.

`table()` leaves `NA` out unless asked: `useNA = "ifany"` adds an `<NA>` count when there is at least one, `"always"` adds it even if it is zero, and `"no"` (the default) leaves it out. The default hides the missing values in exactly the place where a reader wants to see them, so a summary table of a column with unknowns is usually better with `useNA = "ifany"`. A factor does not have `NA` among its levels (`levels(factor(c("a", NA, "b")))` is `"a" "b"`), the missing value being stored as the integer code `NA`; `addNA()` makes it a level when you need that. `unique()` and `duplicated()` treat all `NA`s as the same value, and `tabulate()` ignores them. See xref:programming-languages/r/factors.adoc[Factors] for the details of the factor case.

== Removing missing values: na.omit(), complete.cases() and na.action

`na.rm` is an argument of one function. When the missing values have to be removed from the data itself, R has two families of tools. `na.omit()` returns the object without the missing observations, and records what it removed in an attribute called `na.action`, of class `omit`, that holds the positions (or, for a data frame, the row names) of the dropped elements. The attribute is the reason the printed vector from `na.omit()` shows an `attr(,"na.action")` section: the object is still a numeric vector that every function can use, and `as.vector()` or `c()` strips the attribute when it is in the way. `complete.cases()` returns the logical vector that says which rows are complete, for any mix of vectors, matrices and data frames of the same length, and is the better choice when you want to keep control of the subsetting: `pass:c[books[complete.cases(books), \]]` is what `na.omit(books)` returns, without the attribute. If the arguments differ in length it stops with `+not all arguments have the same length+`.

For one vector, `mean(x, na.rm = TRUE)` and `mean(na.omit(x))` give the same number. For several variables they are different operations, and the difference is the reason to know both. `na.rm = TRUE` is applied variable by variable, so each statistic uses all the values that variable has; `na.omit()` on a data frame performs listwise deletion, which drops a row when any of its variables is missing, so every statistic is computed on the same rows. On the shelf, `pass:c[colMeans(books[c("year", "pages")\], na.rm = TRUE)]` uses 15 years and 14 page counts, while `+colMeans(na.omit(...))+` uses the 13 rows that have both, and the means differ (1998.73 and 268.21 against 1996.23 and 281.46). Neither is wrong; they answer different questions, and a correlation or a regression needs the second, which is what the `use = "complete.obs"` argument of `cor()` and the default of `lm()` do.

=== The na.action family

`na.omit()`, `na.exclude()`, `na.fail()` and `na.pass()` are four ways to decide what an analysis does with an `NA`, and they share one help page (https://search.r-project.org/R/refmans/stats/html/na.fail.html[R documentation: na.fail]). They are called by the modelling functions (`lm()`, `glm()`, `model.frame()` and the other formula interfaces) through their `na.action` argument, whose default is the `na.action` option, which is `"na.omit"`.

[cols="1,3,3",options="header"]
|===
|Function |Behaviour |Typical use

|`na.omit()`
|removes the observations with an `NA` and records them in the `na.action` attribute (class `omit`)
|the default; the model is fitted on the complete rows

|`na.exclude()`
|the same as `na.omit()`, except that the `na.action` attribute has class `exclude`, which makes `residuals()`, `fitted()` and `predict()` pad their results with `NA` for the removed rows
|when the output must line up with the input rows

|`na.fail()`
|stops with the error `+missing values in object+` when there is any `NA`, and returns the object otherwise
|a strict analysis that must not drop data silently

|`na.pass()`
|returns the object unchanged
|when the called function deals with `NA` itself
|===

Source: https://search.r-project.org/R/refmans/stats/html/na.fail.html[R documentation: na.fail]

The effect of the choice shows in a regression of the page count on the year. With the default the 13 complete rows are used (`nobs()` is 13 and there are 13 residuals); with `na.action = na.exclude` the same 13 rows are used but `residuals()` has 16 elements, with `NA` at rows 6, 7 and 15, so it can be added to the data frame as a column; with `na.action = na.fail` the call stops. [[missing-filling]]
== Filling and recoding

Removing is not the only option and it is rarely a neutral one: dropping rows changes what the data represent. When a missing value has to be given a value, three tools do the job in base R, and all of them take a logical vector from `is.na()` to say where. `ifelse(is.na(x), fill, x)` is vectorised and returns a new vector; `replace(x, is.na(x), fill)` is the same without the wrapper (`replace()` is `pass:c[x[list\] <- values]` written as a function); and the assignment `pass:c[x[is.na(x)\] <- fill]` modifies in place. The fill can be a constant or a statistic of the known values (`mean(x, na.rm = TRUE)`, `median(x, na.rm = TRUE)`). Which one is correct is a statistical question that R cannot answer: filling a page count with zero tells the next function that the book has no pages, and filling with the mean shrinks the variance. `tidyr::replace_na()` and `dplyr::coalesce()` do the same job for data frames and are named in prose only (see xref:programming-languages/r/tidyr-purrr-and-stringr.adoc[tidyr, purrr and stringr] and xref:programming-languages/r/tidyverse-and-dplyr.adoc[The tidyverse and dplyr]).

`ifelse()` returns `NA` where its test is `NA`, so a classification such as long or short based on a page count leaves the two unknown books unclassified, and the second form of the example says explicitly what to do with them. The type of the fill matters: `replace(books$pages, is.na(books$pages), 0)` turns an integer column into a double one, because `0` is a double, and filling the year with `"unknown"` turns the column into a character vector, and every number in it into a string, which is why the fill value for an integer column is written `0L` and why a placeholder text does not belong inside a numeric column.

Base R has no function for "last observation carried forward", the fill that time-series data often needs, but the index trick of the last block does it: `+seq_along(x) * !is.na(x)+` is the position where the value is known and 0 where it is not, `cummax()` carries the last known position forward, and indexing with it repeats the known value. [source,r]

x[idx]

[[missing-null-lists]]
== NULL in lists

`NULL` is not a value that a vector can hold, but a list can hold it as a component, and that creates a trap that has its own entry in the R FAQ. The question is how to set a component of a list to `NULL`. The answer in R FAQ 7.1 is to use `pass:c[x[i\] <- list(NULL)]`, and not to set `pass:c[x[i\]]` or `pass:c[x[[i\]\]]` to `NULL`, because that removes the component from the list (https://cran.r-project.org/doc/FAQ/R-FAQ.html#How-can-I-set-components-of-a-list-to-NULL_003f[R FAQ 7.1: How can I set components of a list to NULL?]). The same entry notes that for dropping the row names of a matrix `+rownames(x) <- NULL+` is the easier way. The script runs the experiment on a list with three named components: `pass:c[x[["b"\]\] <- NULL]` and `+x$b <- NULL+` remove `b`, so the list has two components; `pass:c[x["b"\] <- NULL]` removes it as well, which is the case the FAQ warns about; and only `pass:c[x["b"\] <- list(NULL)]` leaves a component named `b` whose value is `NULL`, so the list still has three components, `x$b` is `NULL`, `is.null(x$b)` is `TRUE` and `"b" %in% names(x)` is `TRUE`.

[cols="3,3",options="header"]
|===
|Assignment |Result for `+x <- list(a = 1, b = "two", c = 3)+`

|`pass:c[x[["b"\]\] <- NULL]`, `+x$b <- NULL+`
|removes the component `b`; two components remain

|`pass:c[x["b"\] <- NULL]`
|removes the component `b` as well

|`pass:c[x["b"\] <- list(NULL)]`
|keeps a component `b` whose value is `NULL`; three components

|`+list(a = 1, b = NULL, c = 3)+`
|creates a list with a `NULL` component `b`; three components

|`pass:c[x[["b"\]\]]` or `+x$b+` when `b` is absent
|`NULL`; the same as a component that holds `NULL`
|===

Lists that hold `NULL` come from functions that sometimes return nothing. `lapply()` over a list returns a list that has a `NULL` where the function returned `NULL`; `sapply()` then cannot simplify the result and returns the list unchanged, which makes its return type depend on the data; and `vapply()` stops with an error that names the problem, `+values must be length 1,\n but FUN(X[[1]]) result is length 0+`. `unlist()` drops the `NULL`s, which is sometimes what you want and sometimes hides a bug. Asking for a field that does not exist (`b$notes`) is `NULL`. The reason is that `is.na(NULL)` is `logical(0)`, `!logical(0)` is `logical(0)`, and `+logical(0) && ...+` is `NA` (see <<missing-conditions,Conditions that are not one TRUE or FALSE>>), so the `if` receives an `NA`. A validator should check the field names before the values.

In a data frame the same two operators do the two jobs: `+df$b <- NULL+` removes a column and `+df$c <- NA+` creates a column of logical `NA`, with the type `logical`, to be replaced by a typed vector later. `pass:c[df["a"\] <- NULL]` on the last remaining column leaves a frame with 3 rows and no columns. See xref:programming-languages/r/data-frames.adoc[Data Frames].

[[missing-coalescing]]
== The null-coalescing operator %||%

Taking a default when something is `NULL` is so common (an optional argument, an absent list component, a missing option) that R 4.4.0 added an operator for it: `L %||% R` is the idiom for `if (!is.null(L)) L else R` (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.4.0]; documented with the control-flow operators in https://search.r-project.org/R/refmans/base/html/Control.html[R documentation: Control]). The right operand is evaluated only when the left one is `NULL`, like `||`. The operator tests for `NULL` and only for `NULL`: `NA %||% "default"` is `NA`, `character(0) %||% "default"` is `character(0)` and `list() %||% "default"` is `list()`, because none of them is `NULL`. For a missing value in a book field, `b$genre %||% "unclassified"` is `NA`, while `b$notes %||% "no notes"` is the default, and the safe test for the field is `is.na(b$genre)`. Code that supports R older than 4.4.0 defines the helper itself (the function `fallback()` in the script is one possible definition) and loses nothing when it runs on a newer R, though a package that defines its own `%||%` masks the base one inside its namespace.

[[missing-zero-length]]
== Zero-length vectors

A zero-length vector is a vector with no elements, and unlike `NULL` it has a type: `character(0)`, `integer(0)`, `numeric(0)`, `logical(0)` and the empty `list()`. Functions on an empty input follow the mathematics of the empty set, and a few of the results are surprising until the rule is seen. `sum(integer(0))` is 0 and `prod(numeric(0))` is 1, the identity elements of addition and multiplication; `any(logical(0))` is `FALSE` and `all(logical(0))` is `TRUE` (the "vacuous truth", for which no counter-example exists); `mean(numeric(0))` is `NaN`, because it computes 0/0; `median(numeric(0))` and `var(numeric(0))` are `NA`. === max() and min() of nothing

`max()` and `min()` of an empty vector have no mathematically sensible result, and R returns the identity of the operation, `-Inf` and `Inf`, with a warning: `+no non-missing arguments to max; returning -Inf+` and `+no non-missing arguments to min; returning Inf+`. The same warning appears when every value is `NA` and `na.rm = TRUE` removes them all, which is how a filter that matches nothing and a column that is all missing end up in the same message. `max(character(0))` returns `NA` with a different warning, `+no non-missing arguments, returning NA+`. `range()` of an empty vector warns once for the minimum. `which.max()` and `which.min()` ignore both cases and return `integer(0)`.

Two defences work. The first is to give `max()` a floor that is a legitimate answer for the data (`max(x, 0)`, or `max(numeric(0), -Inf)`, which is `-Inf` without the warning) and the second is to test first and choose the result explicitly, as the `safe_max()` function of the script does: if `x` is empty or all missing, return a default, else take the maximum of the known values. Suppressing the warning with `suppressWarnings()` leaves `-Inf` in the result, which then propagates as a number and shows up later as an impossible axis or a division by zero.

  range(numeric(0)),

#> [1] "no non-missing arguments to min; returning Inf"

The first two rows are the subject of this page. A `NULL` or an empty vector in a condition is the condition of length zero, and the cause is nearly always upstream: `books$pagez` (a typo) is `NULL`, `NULL > 300L` is `logical(0)`, and `if (logical(0))` stops with `+argument is of length zero+`; but filtering the right column on a title that does not exist gives the same message. Both messages mean that the value has no answer, and you should know before the `if` whether you expect exactly one answer. `while` reports the same two messages.

A zero-length operand of `&&` or `||` is not an error in R 4.6.1: `logical(0) && TRUE` is `NA`, and `logical(0) || TRUE` is `TRUE`, as if the empty operand were an `NA`. So an `if` whose condition has a zero-length operand on the left of `&&` reports `+missing value where TRUE/FALSE needed+`, not the length-zero message, which is the confusing error that `validate_book()` showed above. A `NULL` or a string is a different matter and is an error in `&&` and `||`, with the `+invalid 'x' type+` message.

=== Guarding a condition

Make the condition always have exactly one answer, and make the choice for the unknown explicit. The tools are few:

* `length(x) == 1L && !is.na(x) && x > 300L` spells out the three requirements in order, and relies on `&&` stopping at the first `FALSE`.
* `isTRUE(x > 300L)` is `TRUE` only when its argument is exactly the single value `TRUE`; `NA`, `FALSE`, `logical(0)` and a vector of length 2 all give `FALSE`. `isFALSE()` is its counterpart, true only for the single `FALSE`. Both are in the help page of the logical operators, and they are the shortest way to fold "unknown" into one of the branches. The price is that a typo in the column name also folds into `FALSE` silently, so use them where unknown really means no.
* `if (length(x))` tests that a vector is not empty, using the rule that 0 is `FALSE` and any other number is `TRUE`; `if (length(x) > 0L)` says the same more plainly.
* `any(x, na.rm = TRUE)` and `all(x, na.rm = TRUE)` reduce a vector to one answer, with `na.rm = TRUE` deciding to ignore the unknowns. For an empty vector `any()` is `FALSE` and `all()` is `TRUE`, so `all(x > 0)` on an empty filter is true: check `length(x)` first when "all of nothing" is not a sensible answer, as the `vacuous` line shows.
* `nzchar(x)` is not a test for a missing string (it is `TRUE` for `NA` by default), so use `!is.na(x) && nzchar(x)`.

`stopifnot()` is the tool for conditions that must hold. It treats `NA` as a failure: `stopifnot(books$pages > 0L)` stops with `+books$pages > 0L are not all TRUE+` because of the two unknown page counts, and `stopifnot(NA)` says `+NA is not TRUE+`. An empty logical vector passes (`stopifnot(logical(0))` is silent), as it is "all TRUE". A named argument supplies the message, as in `stopifnot("pages must be known" = !anyNA(books$pages))`, which is the form to use for input checks (see xref:programming-languages/r/defensive-programming-and-input-validation.adoc[Defensive Programming and Input Validation] and xref:programming-languages/r/conditions-and-error-handling.adoc[Conditions and Error Handling]).

[[missing-identical]]
== identical(), switch() and sizes

=== identical() and NA

`identical()` compares two objects for exact equality, including their types, and returns a single `TRUE` or `FALSE` that is never `NA`. That makes it the safe comparison for `NA` and `NULL`, but the exactness catches people: `identical(NA, NA_integer_)` is `FALSE` because the types differ, `identical(NA_real_, NaN)` is `FALSE`, `identical(NULL, character(0))` is `FALSE`, and `pass:c[identical(books$year[7L\], NA)]` is `FALSE`, because the year is an integer `NA` and the constant is a logical one. The comparison with the right type, `pass:c[identical(books$year[7L\], NA_integer_)]`, is `TRUE`, and `is.na()` avoids the question of type altogether. The second pitfall is the vector: `identical(x, NA)` for `+x <- c(NA, NA)+` is `FALSE` because the lengths differ, so it is not a test for "all missing"; use `all(is.na(x))`. The same exactness applies to `+isTRUE(all.equal(...))+` on `NULL` against `character(0)`.

[source,r]
----
source("scenario.R")

# identical(): exact, including the type of the NA
identical(NA, NA)
#> [1] TRUE
identical(NA, NA_integer_)
#> [1] FALSE
identical(NA_real_, NA_real_)
#> [1] TRUE
identical(NA_real_, NaN)
#> [1] FALSE
identical(NaN, NaN)
#> [1] TRUE
identical(c(1, NA), c(1, NA))
#> [1] TRUE
identical(books$year[7L], NA)
#> [1] FALSE
identical(books$year[7L], NA_integer_)
#> [1] TRUE
identical(is.na(books$year[7L]), TRUE)
#> [1] TRUE
is.na(books$year[7L])
#> [1] TRUE
identical(NULL, NULL)
#> [1] TRUE
identical(NULL, character(0))
#> [1] FALSE
identical(character(0), character(0))
#> [1] TRUE
identical(character(0), integer(0))
#> [1] FALSE
identical(list(), NULL)
#> [1] FALSE
isTRUE(all.equal(NULL, character(0)))
#> [1] FALSE
identical(logical(0), NULL)
#> [1] FALSE
----

=== switch() and NA

`switch()` selects by a string or by a number, and its help page does not describe what it does with a missing value, so the next block reports what R 4.6.1 does rather than a documented guarantee. With a string, an `NA_character_` is not an error: it takes the default alternative, and if an alternative is named `NA` (written `+"NA" = ...+`) it matches that one. With a number, an integer or logical `NA`, or a number outside the range, returns an invisible `NULL`. With a `NULL`, a zero-length vector or a vector of length two or more, it stops with `+EXPR must be a length 1 vector+`. So a `switch()` on data that may be missing needs an explicit `if (is.na(x))` before it, and one that returns a value should always have a default alternative. See xref:programming-languages/r/control-flow.adoc[Control Flow] for `switch()` in general.

[source,r]
----
# NA in switch(): a missing string, a missing number
sw_chr <- function(x) {
  switch(x, a = "first", b = "second", "default")
}
sw_chr("a")
#> [1] "first"
sw_chr("z")
#> [1] "default"
sw_chr(NA_character_)
#> [1] "default"
sw_na_branch <- function(x) {
  switch(x, a = "first", "NA" = "the string NA", "default")
}
sw_na_branch(NA_character_)
#> [1] "the string NA"
sw_na_branch("NA")
#> [1] "the string NA"
sw_num <- function(i) {
  switch(i, "one", "two", "three")
}
sw_num(2L)
#> [1] "two"
is.null(sw_num(5L))
#> [1] TRUE
is.null(sw_num(NA_integer_))
#> [1] TRUE
is.null(sw_num(NA))
#> [1] TRUE
withVisible(sw_num(NA))$visible
#> [1] FALSE
tryCatch(sw_num(NULL), error = \(e) conditionMessage(e))
#> [1] "EXPR must be a length 1 vector"
tryCatch(sw_num(integer(0)), error = \(e) conditionMessage(e))
#> [1] "EXPR must be a length 1 vector"
tryCatch(sw_num(1:2), error = \(e) conditionMessage(e))
#> [1] "EXPR must be a length 1 vector"
is.null(switch(NA, a = 1, 2))
#> [1] TRUE
switch(NA_character_, a = 1, 2)
#> [1] 2
tryCatch(
  switch(character(0), a = 1, 2),
  error = \(e) conditionMessage(e)
)
#> [1] "EXPR must be a length 1 vector"
tryCatch(
  switch(NULL, a = 1, 2),
  error = \(e) conditionMessage(e)
)
#> [1] "EXPR must be a length 1 vector"
----

[[missing-nrow]]
=== NROW, NCOL and lengths

`nrow()` and `ncol()` return `NULL` for anything that is not a matrix or data frame, which is awkward when the object may be a plain vector or `NULL`. `NROW()` and `NCOL()` treat a vector as a one-column matrix: `NROW(1:3)` is 3 and `NCOL(1:3)` is 1, `NROW(character(0))` is 0, and a data frame with no rows gives 0. R 4.4.0 made `NCOL(NULL)` return 0 instead of 1, consistently with `cbind()`, while `NROW(NULL)` was already 0 (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.4.0]); code written for older versions that counted columns of a possible `NULL` should be checked. `seq_len(NROW(x))` is a safe loop sequence for a vector, a matrix or a data frame that may be empty.

`length()` of a `list(NULL)` is 1, since the list holds one component that happens to be `NULL`, while `length(NULL)` and `length(list())` are 0. `lengths()` gives the lengths of the components of a list at once, and is the quick way to find the empty ones. `is.na()` on a list is true only for the components that are single missing values (the help page: a length-one atomic vector whose element is `NA` or `NaN`), so `is.na(list(1, NA, NULL, c(NA, 2), "a"))` is `FALSE TRUE FALSE FALSE FALSE`. `anyNA()` gives the same for a list unless `recursive = TRUE`, which looks inside the components: `anyNA(list(1, c(2, NA)))` is `FALSE` and `anyNA(list(1, c(2, NA)), recursive = TRUE)` is `TRUE`. `anyNA(NULL)` is `FALSE` and `is.na(NULL)` is `logical(0)`; R 3.1.0 introduced `anyNA()` as a fast version of `any(is.na(x))`, and `is.na(NULL)` stopped warning in 3.4.4 (https://cran.r-project.org/doc/manuals/r-release/NEWS.3.html[R NEWS (R 3.x): Changes in R 3.1.0 and 3.4.4]).

[source,r]
----
# NROW and NCOL, where nrow() and ncol() give NULL
nrow(1:3)
#> NULL
ncol(1:3)
#> NULL
NROW(1:3)
#> [1] 3
NCOL(1:3)
#> [1] 1
nrow(NULL)
#> NULL
NROW(NULL)
#> [1] 0
NCOL(NULL)
#> [1] 0
nrow(books)
#> [1] 16
NROW(books$title)
#> [1] 16
NROW(books[0L, ])
#> [1] 0
NROW(character(0))
#> [1] 0
NCOL(books)
#> [1] 6
dim(NULL)
#> NULL
dim(1:3)
#> NULL
nrow(books[books$year > 2100L & !is.na(books$year), ])
#> [1] 0
for (i in seq_len(NROW(NULL))) print(i)
----

Source: https://search.r-project.org/R/refmans/base/html/nrow.html[R documentation: nrow]

#> [1] 3 0 1 0

#> [1] FALSE  TRUE FALSE FALSE FALSE

== Where older tutorials differ

Older tutorials and answers are right about the basics and wrong or out of date about a few details. When one of them disagrees with this page, the table says why.

[cols="2,3,4,2",options="header"]
|===
|Older tutorial |Current practice |Why |Version

|`+x[x != NA]+`, `+if (x == NA)+`, `+x == NaN+`
|`pass:c[x[!is.na(x)\]]`, `if (is.na(x))`, `is.nan(x)`
|a comparison with an unknown is unknown; the result is all `NA`
|always (`equals_na_linter` flags it)

|`any(is.na(x))`
|`anyNA(x)`
|the same answer, simpler, and faster for atomic vectors; `any(is.na(x))` still works
|R 3.1.0

|`mean(x, na.rm = T)`
|`mean(x, na.rm = TRUE)`
|`T` and `F` are ordinary variables that can be reassigned; `TRUE` and `FALSE` are reserved words
|always

|a summary call that names `na.rm` twice, or passes it twice through `+...+`
|name it once
|it is now an error (`+formal argument "na.rm" matched by multiple actual arguments+`); it used to give either answer
|R 4.4.0

|`nchar(NA)` is 2
|`nchar(NA)` is `NA_integer_`; `nchar(x, keepNA = FALSE)` for the old 2
|the default of `keepNA` changed
|R 3.3.0

|`is.atomic(NULL)` is `TRUE`
|`is.atomic(NULL)` is `FALSE`; use `pass:c[is.null(x) \|\| is.atomic(x)]` for the old meaning
|`NULL` is not an atomic vector
|R 4.4.0

|`NCOL(NULL)` is 1
|`NCOL(NULL)` is 0
|consistency with `cbind()`
|R 4.4.0

|`is.na(NULL)` warns
|`is.na(NULL)` is `logical(0)`
|the warning was removed
|R 3.4.4

|defining `pass:c[%\|\|%]` in every project
|base `pass:c[%\|\|%]`
|it is in `base`; your own definition masks it and still works, but code that must run on an older R needs it
|R 4.4.0

|`pass:c[N <- NULL; N[[1\]\] <- val]` gives a vector for a length-one `val`
|it gives a list
|consistency
|R 4.0.0

|`if (c(TRUE, NA))` or `if (c(TRUE, FALSE))` "uses the first element"
|reduce with `any()`, `all()` or `isTRUE()`
|a condition of length greater than one is an error
|R 4.2.0

|`c(TRUE, TRUE) && TRUE` gives `TRUE` (a warning in 4.2.x)
|use `&`, `any()` or `all()`
|it is an error: `+'length = 2' in coercion to 'logical(1)'+`
|R 4.3.0

|`pass:c[x[["b"\]\] <- NULL]` and `pass:c[x["b"\] <- NULL]` "set the component to NULL"
|`pass:c[x["b"\] <- list(NULL)]`
|assigning `NULL` removes the component (R FAQ 7.1)
|always

|`sapply(x, f)` on a possibly empty input
|`vapply(x, f, <template>)`
|`sapply()` returns `list()` for an empty input and a list when some results are `NULL`
|always

|`ifelse(is.na(x), 0, x)` for every fill
|the same, but with the right type (`0L` for integers) or `replace()`
|a fill of the wrong type changes the type of the column
|always

|`pass:c[is.na(x) \| x == ""]` to find missing text
|`pass:c[is.na(x) \| !nzchar(x)]`, or `na.strings = c("NA", "")` when reading
|`""` is not `NA`, and `x == ""` is `NA` where `x` is `NA`
|always
|===
