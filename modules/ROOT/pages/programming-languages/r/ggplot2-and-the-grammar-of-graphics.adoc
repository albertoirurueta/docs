== The grammar of graphics

A chart type such as "scatter plot" or "bar chart" is a name for one combination of choices, not a primitive. The statistician Leland Wilkinson made that observation the basis of his book _The Grammar of Graphics_ (Springer, 1999; second edition 2005): a graphic is a sentence built from a small number of independent parts (the data, how variables are turned into visual properties, the geometric shapes, the statistical transformations, the scales, the coordinate system, the panels), and different sentences give the familiar chart types and many unfamiliar ones. Hadley Wickham adapted that idea to R in the paper "A Layered Grammar of Graphics" (Journal of Computational and Graphical Statistics, 2010), and ggplot2 is its implementation. Both are community and book material, not part of the official R documentation, and this page does not reproduce them; what it describes is ggplot2 4.0.3 as its own documentation describes it. The package's introduction names seven composable parts, and says that a chart needs at least three of them (data, a mapping and a layer) because the scales, facets, coordinates and themes have defaults (https://ggplot2.tidyverse.org/articles/ggplot2.html[ggplot2 package documentation: Introduction to ggplot2]).

[cols="2,5,4",options="header"]
|===
|Part |What it decides |Where it is written
|Data |The data frame, one row per observation. Each layer can have its own. |`ggplot(data)` or `+geom_*(data = )+`
|Mapping |Which variable drives which visual property (aesthetic): position, colour, fill, shape, size, alpha, line type, grouping. |`aes()`, in `ggplot()` or in a layer
|Layers |What is drawn: a geom (the shape), a stat (a computation applied to the data first) and a position adjustment (where overlapping shapes go). |`+geom_*()+`, `+stat_*()+`, `+position_*()+`
|Scales |How data values become visual values (a number to a position, a factor level to a colour) and how the axes and legends are labelled. |`+scale_*()+`, `lims()`, `labs()`
|Coordinates |How positions are projected onto the page: Cartesian, flipped, fixed aspect, polar, transformed. |`+coord_*()+`
|Facets |How the data is split into small multiples. |`+facet_*()+`
|Theme |Everything that is not data: fonts, grid lines, backgrounds, legend placement. |`+theme_*()+`, `theme()`, `+element_*()+`
|===

Source: https://ggplot2.tidyverse.org/articles/ggplot2.html[ggplot2 package documentation: Introduction to ggplot2]

The pipeline below follows the data through those parts in the order ggplot2 applies them. First `ggplot()` and the plus operator only record what was asked for in an object. Drawing it takes three stages. `ggplot_build()` runs the data through the layers and the scales and returns a list of data frames, one per layer, ready to draw; the reference page for it calls this the step that performs everything necessary to produce an object that can be rendered. `ggplot_gtable()` turns that into a table of grid graphical objects (grobs), applying the theme and building the legends. And a graphics device draws the table. `print()` on a plot, the automatic printing of a plot at the console, and `ggsave()` all run the three stages. The diagram orders the facets last, as the page would explain them, but the assignment of rows to panels is decided at the very start of the build (the plot's layout is set up before the aesthetics are evaluated), and the panels themselves are laid out and labelled in the gtable stage.

Every box in the diagram corresponds to a function family with a regular name: `+geom_*()+` and `+stat_*()+` build layers, `+position_*()+` the adjustments, `+scale_<aesthetic>_<type>()+` the scales, and `+coord_*()+`, `+facet_*()+` and `+theme_*()+` the rest. A name that follows the pattern can be guessed and found with tab completion, and the regularity is the reason the same few ideas cover a very large number of charts. The rest of this page takes the stages one by one, always by looking at the data or the object that the stage produced.

== A plot is an object

`ggplot()` does not draw anything. It returns an object, and everything after it with a plus sign returns a new object with one more component. The reference page for `ggplot()` says that it initializes the object, declares the default data frame and the aesthetic mappings that all later layers share unless they override them, and is almost always followed by a plus sign (https://ggplot2.tidyverse.org/reference/ggplot.html[ggplot2 package documentation: ggplot]). The script below creates a plot with no layers, adds one, and then takes the three stages of the pipeline apart: the object, the built data, and the gtable.

[source,r]
----
library(ggplot2)
source("scenario.R")

# Two books have no page count and one has no year; leave them out for now.
known <- subset(books, !is.na(pages) & !is.na(year))

# ggplot() builds an object; nothing is drawn until it is printed or saved.
p <- ggplot(known, aes(x = pages, y = year))
class(p)
#> [1] "ggplot2::ggplot" "ggplot"          "ggplot2::gg"     "S7_object"
#> [5] "gg"
length(p$layers)
#> [1] 0

# The plus operator returns a new plot with the layer added.
p2 <- p + geom_point()
length(p$layers)
#> [1] 0
length(p2$layers)
#> [1] 1
p2$layers
#> $geom_point
#> geom_point: na.rm = FALSE
#> stat_identity: na.rm = FALSE
#> position_identity
#>
p2$mapping
#> Aesthetic mapping:
#> * `x` -> `pages`
#> * `y` -> `year`
summary(p2)
#> data: title, author, isbn, year, genre, pages [13x6]
#> mapping:  x = ~pages, y = ~year
#> faceting:  <empty>
#> -----------------------------------
#> geom_point: na.rm = FALSE
#> stat_identity: na.rm = FALSE
#> position_identity
#>

# Stage 1, ggplot_build(): data to data (stats, positions, scales applied).
built <- ggplot_build(p2)
class(built)
#> [1] "ggplot2::ggplot_built" "ggplot_built"          "ggplot2::gg"
#> [4] "S7_object"
head(built$data[[1]], 3)
#>     x    y PANEL group shape colour fill size alpha stroke
#> 1 387 1974     1    -1    19  black   NA  1.5    NA    0.5
#> 2 432 1813     1    -1    19  black   NA  1.5    NA    0.5
#> 3 214 2019     1    -1    19  black   NA  1.5    NA    0.5

# Stage 2, ggplot_gtable(): the built plot to a gtable of grobs. Measuring
# text needs a graphics device, so open one that writes to a temporary file.
svg(tempfile(fileext = ".svg"))
gt <- ggplot_gtable(built)

ggsave(tempfile(fileext = ".svg"), p2, width = 6, height = 4)
----

Source: https://ggplot2.tidyverse.org/reference/ggplot_build.html[ggplot2 package documentation: ggplot_build]

Five things to take from the output. The class vector of a plot starts with `"ggplot2::ggplot"`: since ggplot2 4.0 the plot is an S7 object (see <<s7,ggplot2 4.0 on S7>>). Adding a layer returns a new plot and leaves the old one with no layers: the plot is a value, and `p` can be kept and extended into several plots. `summary()` of a plot prints the data frame's columns and size, the mapping, the facets and the layers, which is the quickest way to check what a long expression built. `ggplot_build()` returns an object of class `"ggplot2::ggplot_built"` whose data (`built$data`, one data frame per layer) already has the aesthetics evaluated and the scales applied: the first rows show the numbers `x` and `y` that will be drawn, the default `shape`, `colour`, `size` and `stroke` that the geom filled in, the panel the row belongs to and the group. `ggplot_gtable()` takes that built object and returns a `gtable`, a grid graphical object, and measuring the text for it needs a graphics device, which is why the script opens `svg()` to a temporary file around the call. The reference page for `ggplot_build()` documents the helpers that read the middle stage, `layer_data()` (the data of layer `i`) and `layer_scales()` (the scales of a panel), and in 4.0 their new names `get_layer_data()` and `get_panel_scales()`; the page says they are useful for tests, and this page uses `layer_data()` as a window on what a layer will draw. In ggplot2 4.0 the reference page also describes the internal function `build_ggplot()` as the builder and `ggplot_build()` as vestigial; `ggplot_build()` is the one that is exported by the package and the one to call.

=== Printing, `ggsave()` and the default device

A plot object is drawn when it is printed. At the console the value of an expression is printed automatically, so typing the name of a plot draws it. Inside a script that is executed with `source()`, inside a function or inside a loop, nothing is printed automatically and a plot that is never passed to `print()` is never drawn; this is a frequent surprise, and it has its own entry in the R FAQ, which names ggplot2 graphics among the objects that are created but not displayed until their `print()` method runs (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-do-lattice_002ftrellis-graphics-not-work_003f[R FAQ 7.22: Why do lattice/trellis graphics not work?]). The documentation of `print.ggplot()` makes the same point: the default top-level print method does it for you, and an explicit `print()` is needed to draw a plot inside a function or a for loop (https://ggplot2.tidyverse.org/reference/print.ggplot.html[ggplot2 package documentation: print.ggplot]).

The other half of the surprise happens under `Rscript`. No device is open when the script starts. The first operation that needs one, whether drawing a plot or just measuring text for `ggplotGrob()`, opens the default device, which for a non-interactive session is the pdf device, and the pdf device writes a file called `Rplots.pdf` in the working directory. The script below shows it, and cleans up after itself; code that is meant to run unattended should open its own device, or use `ggsave()`, so that no stray file appears.

[source,r]
----
library(ggplot2)
source("scenario.R")
known <- subset(books, !is.na(pages) & !is.na(year))
p <- ggplot(known, aes(pages, year)) + geom_point()

# Under Rscript no device is open until something needs one.
dev.cur()
#> null device
#>           1
g <- ggplotGrob(p) # measuring text opens the default device
dev.cur()
#> pdf
#>   2
file.exists("Rplots.pdf")
#> [1] TRUE

# Clean up: close the device and delete the file it wrote.
invisible(dev.off())
unlink("Rplots.pdf")
file.exists("Rplots.pdf")
#> [1] FALSE
----

Source: https://search.r-project.org/R/refmans/grDevices/html/pdf.html[R documentation: pdf]

=== The plus operator

Everything that can be added to a plot is added with the plus operator, which is a method of the plot class and returns a new plot. The script below adds a layer, a second layer, a scale, a coordinate system, a facet specification, a complete theme and a title, then shows where each landed. It also shows that a list of components is added element by element and that adding `NULL` does nothing, which is what makes it possible to keep a house style in one list and add it to every plot. The plus operator is a binary operator, so it must end the line when an expression continues on the next one: a line that starts with a plus is a new statement, and ggplot2 detects that case and says so.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
known <- subset(books, !is.na(pages) & !is.na(year))
base <- ggplot(known, aes(pages, year))

# The plus operator adds layers, scales, coordinates, facets, themes, labels,
# guides and lists of them; each lands in its own property of the plot.
p <- base +
  geom_point() +
  geom_rug() +
  scale_x_log10() +
  coord_cartesian(ylim = c(1900, 2030)) +
  facet_wrap(~genre) +
  theme_bw() +
  labs(title = "Pages and year")
length(p$layers)
#> [1] 2
vapply(p$layers, \(l) class(l$geom)[[1L]], character(1L))
#>  geom_point    geom_rug
#> "GeomPoint"   "GeomRug"
class(p$coordinates)[[1L]]
#> [1] "CoordCartesian"
class(p$facet)[[1L]]
#> [1] "FacetWrap"
p$theme@complete
#> [1] TRUE
get_labs(p)$title
#> [1] "Pages and year"

# A list of components is added element by element, and NULL adds nothing.
common <- list(theme_minimal(), labs(x = NULL), NULL)
q <- base + geom_point() + common
q$theme@complete
#> [1] TRUE
length(q$layers)
#> [1] 1

# Adding returns a new plot: p is unchanged. The building blocks can be kept
# in variables and reused.
r <- base + geom_point()
s <- r + geom_rug()
c(r = length(r$layers), s = length(s$layers))
#> r s
#> 1 2

# Starting a line with + is a syntax trap: R has already finished the statement.
tryCatch(+geom_point(), error = \(e) conditionMessage(e))
#> [1] "Cannot use `+` with a single argument.\nℹ Did you accidentally put `+` on a new line?"
tryCatch(base + "points", error = \(e) conditionMessage(e))
#> [1] "Can't add `\"points\"` to a <ggplot> object."
----

Source: https://ggplot2.tidyverse.org/reference/gg-add.html[ggplot2 package documentation: Add components to a plot]

The two messages at the end are the real text of the 4.0.3 errors. The first, `pass:c[Cannot use + with a single argument]`, is what a leading plus produces: R evaluated `pass:c[+geom_point()]`, the unary plus of a layer, as a statement of its own. The second names the object that cannot be added, with its value quoted. The package's own documentation calls the underlying generic `update_ggplot()` (the older `ggplot_add()` is described there as vestigial), which is the function an extension package implements a method for in order to make its own objects addable.

== Data and aesthetics

The first argument of `ggplot()` is the data, a data frame (the reference page says that anything else is converted by `fortify()`; the shelf `books` and `loans` of xref:programming-languages/r/data-frames.adoc[Data Frames] are data frames already). The second is the mapping, built by `aes()`. A mapping is a set of pairs: the name of an aesthetic on the left, an expression on the right that is evaluated in the data to give that aesthetic's values. The common aesthetics are `x` and `y`, `colour` (also spelt `color`), `fill`, `shape`, `size`, `alpha`, `linewidth`, `linetype`, `label` and `group`; each geom has a list of those it understands, printed by `GeomPoint$aesthetics()` in the script below, and the article on aesthetic specifications says which values each one accepts (https://ggplot2.tidyverse.org/articles/ggplot2-specs.html[ggplot2 package documentation: Aesthetic specifications]).

`aes()` quotes its arguments. Like `quote()` in xref:programming-languages/r/language-objects-and-quoting.adoc[Language Objects and Quoting], it does not evaluate `genre`; it records the expression together with the environment where it was written (a quosure), and ggplot2 evaluates it later, in the data. That is the data mask of xref:programming-languages/r/evaluation-and-non-standard-evaluation.adoc[Evaluation and Non-Standard Evaluation], and it is the reason a column name can be written without quotes or `books$`.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))

# aes() quotes its arguments: nothing is looked up when it is called.
m <- aes(x = pages, y = year, colour = genre)
class(m)
#> [1] "ggplot2::mapping" "uneval"           "gg"               "S7_object"
m$colour
#> <quosure>
#> expr: ^genre
#> env:  global
rlang::quo_get_expr(m$colour)
#> genre

# Mapping: colour is a variable; a scale turns it into colours and a legend
# appears.
mapped <- ggplot(books, aes(pages, year, colour = genre)) + geom_point()
head(layer_data(mapped)[c("x", "y", "colour")], 4)
#>     x    y  colour
#> 1 387 1974 #F564E3
#> 2 432 1813 #F8766D
#> 3 214 2019 #B79F00
#> 4 198 2021 #B79F00

# Setting: colour is one constant for the whole layer, no scale, no legend.
fixed <- ggplot(books, aes(pages, year)) + geom_point(colour = "red")
head(layer_data(fixed)[c("x", "y", "colour")], 4)
#>     x    y colour
#> 1 387 1974    red
#> 2 432 1813    red
#> 3 214 2019    red
#> 4 198 2021    red
names(fixed$layers[[1]]$aes_params)
#> [1] "colour"

# The classic mistake: quoting a constant inside aes() maps it.
oops <- ggplot(books, aes(pages, year)) + geom_point(aes(colour = "red"))
unique(layer_data(oops)$colour)
#> [1] "#F8766D"

# Aesthetics a geom understands.
GeomPoint$aesthetics()
#> [1] "x"      "y"      "shape"  "colour" "fill"   "size"   "alpha"  "stroke"
#> [9] "group"
----

Source: https://ggplot2.tidyverse.org/reference/aes.html[ggplot2 package documentation: aes]

The distinction between mapping and setting causes more confusion than any other. An aesthetic inside `aes()` is a mapping: it is evaluated against the data, goes through a scale, and gets a legend. The same name outside `aes()`, as an argument of the geom, is a setting: a constant for the layer, stored in `aes_params`, with no scale and no legend. The script shows both: the mapped `colour` column holds the hexadecimal colours the discrete colour scale picked for each genre, and the set `colour` holds the constant. The classic mistake, `aes(colour = "red")`, maps the constant string: it is a one-value variable, so it gets the first colour of the default palette (a salmon pink, `#F8766D`) and a legend with one entry called `"red"`. Write `colour = "red"` outside `aes()`.

=== Groups

Several geoms draw one shape per group, for example one line for each group. The `group` aesthetic says which rows belong together, and ggplot2 builds it by default from the interaction of all the discrete variables in the mapping (the `group` column of the built data in the first script was `-1`, meaning no discrete variable). When a line plot comes out as a single zigzag through all the groups, or as a set of single points, the cause is the group aesthetic: the cure is `+aes(group = ...)+`, and the message in the section on messages, "Each group consists of only one observation", is ggplot2 pointing at it.

=== Functions that take column names: `+{{ }}+` and `.data`

A function that builds a plot from a column the caller names has the problem described in the page on non-standard evaluation: `aes(var)` quotes the symbol `var`, not the argument that `var` stands for. Tidy evaluation, from rlang, solves it, and `aes()` supports it: embracing the argument with `+{{ var }}+` passes on what the caller wrote, and the `.data` pronoun indexes the data with a string held in a variable. The `.data` pronoun is re-exported by ggplot2 and the embrace operator is syntax that `aes()` understands, so no other package needs to be attached.

[source,r]
----
library(ggplot2)
source("scenario.R")
known <- subset(books, !is.na(pages))

# aes() quotes its arguments. {{ }} ("embrace") passes on the caller's argument.
shelf_plot <- function(df, var) {
  ggplot(df, aes({{ var }})) + geom_histogram(binwidth = 100)
}
p <- shelf_plot(known, pages)
p$mapping
#> Aesthetic mapping:
#> * `x` -> `pages`

# Without the embrace, aes() looks for a column called "field".
bad_plot <- function(df, field) {
  ggplot(df, aes(field)) + geom_histogram(binwidth = 100)
}
res <- tryCatch(
  layer_data(bad_plot(known, pages)),
  error = \(e) conditionMessage(e)
)
cat(res, sep = "\n")
#> Problem while computing aesthetics.
#> ℹ Error occurred in the 1st layer.
#> Caused by error:
#> ! object 'pages' not found

# A column name held in a string: the .data pronoun.
by_column <- function(df, col) {
  ggplot(df, aes(.data[[col]])) + geom_histogram(binwidth = 100)
}
q <- by_column(known, "pages")
q$mapping
#> Aesthetic mapping:
#> * `x` -> `.data[["pages"]]`
head(layer_data(q)[c("x", "count")], 3)
#>     x count
#> 1 100     2
#> 2 200     4
#> 3 300     4

# Two embraces in one aes(): the arguments are bare column names.
shelf_scatter <- function(df, x, y) {
  ggplot(df, aes({{ x }}, {{ y }})) + geom_point()
}
shelf_scatter(known, pages, year)$mapping
#> Aesthetic mapping:
#> * `x` -> `pages`
#> * `y` -> `year`

The first function, `shelf_plot()`, is the pattern to remember: `+aes({{ var }})+`, called as `shelf_plot(known, pages)`. The second shows the error that the version without the embrace raises: `aes(field)` captured the symbol `field`, evaluating it forced the argument that the caller wrote, `pages`, in the caller's frame, where there is no variable of that name. The third function takes the column name as a string, which is the usual case when the name comes from a configuration, a menu or a loop, and writes it `pass:c[.data[[col\]\]]`; the mapping that results shows `pass:c[.data[["pages"\]\]]`. The fourth takes two bare names. The embrace operator and the `.data` pronoun are documented by rlang (https://rlang.r-lib.org/reference/embrace-operator.html[rlang package documentation: Embrace operator]). The functions `aes_string()` and `aes_()` that older tutorials use for the same job are deprecated; see <<older,Where older tutorials differ>>. In a package, referring to columns of the data without `.data` makes `R CMD check` report "no visible binding for global variable", which the ggplot2 article on using it in packages treats (https://ggplot2.tidyverse.org/articles/ggplot2-in-packages.html[ggplot2 package documentation: Using ggplot2 in packages]).

== Layers: geoms, stats and positions

The heart of a plot is its layers. The introduction article says that every layer has three important parts: the geometry that decides how the data is displayed, the statistical transformation that may compute new variables from the data and affect which of it is shown, and the position adjustment that mostly decides where each piece of data is displayed. A layer is built either with a `+geom_*()+` or with a `+stat_*()+` function, and which one is used only decides which of the three parts the function sets as its default; the other two stay arguments (https://ggplot2.tidyverse.org/articles/ggplot2.html[ggplot2 package documentation: Introduction to ggplot2]). Underneath both is `layer()`, which takes the geom, the stat and the position explicitly and is what an extension package calls (https://ggplot2.tidyverse.org/reference/layer.html[ggplot2 package documentation: layer]). The script prints the triple for a representative set of constructors.

Read the matrix row by row. `geom_point()`, `geom_line()`, `geom_tile()` and `geom_errorbar()` draw the data as it is (`StatIdentity`, `PositionIdentity`). `geom_bar()` counts the rows first (`StatCount`) and stacks the bars that share a position, while `geom_col()` draws the heights it is given (`StatIdentity`) and stacks them. `geom_histogram()` is a bar geom fed by `StatBin`. `geom_boxplot()` computes the five numbers with `StatBoxplot` and dodges the boxes (`PositionDodge2`). `geom_smooth()` fits a model (`StatSmooth`), `geom_density()` estimates a density (`StatDensity`), `geom_violin()` a density per group (`StatYdensity`). `geom_jitter()` is `geom_point()` with `PositionJitter`. The last line of the script shows that the two spellings of one layer are the same layer: `geom_bar()` and `stat_count()` have the same stat, and `pass:c[stat_summary(geom = "point")]` swaps the geom of a stat-first constructor.

=== Bars: `geom_bar()` and `geom_col()`, histograms, boxes and smooths

`geom_bar()` and `geom_col()` are the pair that older tutorials mix up. `geom_bar()` takes only `x` (or only `y`) and counts the rows at each value; giving it a `y` as well is an error. `geom_col()` takes a `y` and draws a bar of that height; omitting it is the other error. The tutorials that write `pass:c[geom_bar(stat = "identity")]` to draw given heights were writing `geom_col()` by hand: the reference page says that `geom_col()` uses `stat_identity()` and leaves the data as it is. `geom_histogram()` bins a continuous variable by `binwidth` or by `bins` (30 by default, with a message that says so) and counts the rows in each bin; the script below uses `binwidth = 7` with `boundary = 0` so that the bins are weeks starting from day 0. `geom_boxplot()` gets its five numbers and its outliers from the stat. `pass:c[geom_smooth(method = "lm")]` fits the model and draws the line and its band; it prints a message when the `formula` was not given.

== Stats and computed variables

A stat is a function from the layer's data to new data. `geom_bar()` replaces the rows by counts; `geom_smooth()` replaces them by a fitted curve; `stat_summary()` replaces the rows of each group by a summary. The output has new columns, the computed variables, and the geom reads some of them by default: the histogram's bars read `count` as their height because `StatBin$default_aes` maps `y` to `after_stat(count)`, as the script prints. To use a different computed variable, map it with `after_stat()`, inside `aes()`: `pass:c[aes(y = after_stat(density))]` turns a histogram of counts into a density scale, and an expression such as `pass:c[after_stat(count / sum(count))]` can compute from the columns the stat produced. The reference page for the evaluation functions lists the three stages at which an aesthetic can be mapped: from the data, after the stat (`after_stat()`), and after the scale has mapped it (`after_scale()`); `after_stat()` replaces the older `stat()` and the dot-dot notation (https://ggplot2.tidyverse.org/reference/aes_eval.html[ggplot2 package documentation: Control aesthetic evaluation]). `after_scale()` works on the visual value that the scale produced, which is how the box outline in the script is made a darker version of its fill without a second scale.

== Position adjustments

When shapes land on the same position, the position adjustment decides what happens. It is the third part of a layer, and it works on the data after the stat, as a function from the data to data. `position_stack()` (the default of bars) puts the shapes on top of each other; `position_dodge()` puts them side by side, each taking part of the slot; `position_fill()` stacks and rescales every stack to the interval from 0 to 1, so that the bars show shares; `position_jitter()` adds random noise. The argument can be the name (`position = "dodge"`) or the object, which is the form to use when the adjustment has its own arguments (`pass:c[position_dodge(preserve = "single")]`, `pass:c[position_jitter(width = 0.2, height = 0, seed = 282)]`). The reference pages are https://ggplot2.tidyverse.org/reference/position_dodge.html[ggplot2 package documentation: position_dodge], https://ggplot2.tidyverse.org/reference/position_stack.html[ggplot2 package documentation: position_stack] and https://ggplot2.tidyverse.org/reference/position_jitter.html[ggplot2 package documentation: position_jitter].

The numbers show the three adjustments on the same bars. == Scales

A scale is the dictionary between data values and visual values for one aesthetic. The introduction article describes scales as the translation from what is shown on the graph back to an understanding of the data: they update the limits, set the breaks, format the labels and may apply a transformation, and in the plot they are represented by guides, the axes and legends. The functions are named `+scale_<aesthetic>_<type>()+`, where the aesthetic is one from the mapping and the type says what kind of scale it is: `scale_x_continuous()`, `scale_x_date()`, `scale_colour_manual()`, `scale_fill_brewer()`, `scale_colour_viridis_d()`. The type matches the data: continuous data gets a continuous scale, a factor a discrete one, a `Date` a date scale (xref:programming-languages/r/dates-and-times.adoc[Dates and Times] covers the class). If no scale is added for a mapped aesthetic, ggplot2 adds the default one for the type of the data, and it is that default scale which the scripts below read.

A scale has two jobs, in this order, on every layer's data: it is trained, which means it learns the range of the data (the limits for a continuous scale, the levels for a discrete one) across all the layers that use the aesthetic, and then it maps each data value to a visual value (a position, a colour, a size). The script below reads the trained scales from a built plot to show both steps, and then changes the limits, the breaks and the labels of a position scale, applies a logarithmic transformation, swaps the colour scale, and sets the titles with `labs()`.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
known <- subset(books, !is.na(pages) & !is.na(year))

base <- ggplot(known, aes(pages, year, colour = genre)) + geom_point()

# A scale is trained on the data of every layer, then maps data to values.
built <- ggplot_build(base)
x_scale <- built$layout$panel_scales_x[[1L]]
x_scale$get_limits()
#> [1]  88 432
x_scale$get_breaks()
#> [1] 100 200 300 400
colour_scale <- built$plot$scales$get_scales("colour")
class(colour_scale)[[1L]]
#> [1] "ScaleDiscrete"
colour_scale$get_limits()
#> [1] "classic"         "fiction"         "mystery"         "non-fiction"
#> [5] "poetry"          "science fiction"
colour_scale$map(c("poetry", "classic"))
#> [1] "#619CFF" "#F8766D"

# Position scale arguments: limits, breaks and labels.
tuned <- base +
  scale_x_continuous(
    limits = c(0, 500),
    breaks = seq(0, 500, by = 100),
    labels = scales::label_number(suffix = " p")

scale_tuned <- ggplot_build(tuned)$layout$panel_scales_x[[1L]]
scale_tuned$get_breaks()
#> [1]   0 100 200 300 400 500
scale_tuned$get_labels()
#> [1] "0 p"   "100 p" "200 p" "300 p" "400 p" "500 p"

# Transformations: transform = "log10" (argument trans before 3.5.0).
logged <- base + scale_x_continuous(transform = "log10")
ggplot_build(logged)$layout$panel_scales_x[[1L]]$get_transformation()$name
#> [1] "log-10"
shortcut <- base + scale_x_log10()
ggplot_build(shortcut)$layout$panel_scales_x[[1L]]$get_transformation()$name
#> [1] "log-10"

# Colour scales: manual, viridis, brewer.
manual <- base + scale_colour_manual(
  values = c(classic = "grey40", fiction = "orange", mystery = "purple",
             `non-fiction` = "brown", poetry = "steelblue",
             `science fiction` = "darkgreen")

unique(layer_data(manual)$colour)
#> [1] "darkgreen" "grey40"    "orange"    "purple"    "brown"     "steelblue"

unique(layer_data(viridis)$colour)
#> [1] "#FDE725FF" "#440154FF" "#414487FF" "#2A788EFF" "#22A884FF" "#7AD151FF"

The continuous scale learned the range 88 to 432 pages and chose four breaks; the discrete colour scale learned the six genres and its `map()` method turned `"poetry"` and `"classic"` into two of the default hue colours. In the second plot the three arguments of a position scale are visible: `limits` fix the range (and drop the data outside it, see the next section), `breaks` the positions of the ticks, and `labels` the text, here produced by `scales::label_number(suffix = " p")`, a function from the scales package that formats the break values; a character vector or a plain function of the breaks also works. The names of the transformation scales are the part that changed: the argument is `transform` since ggplot2 3.5.0 (earlier it was `trans`, which the NEWS lists as deprecated), and `scale_x_log10()` is the shortcut for `+scale_x_continuous(transform = "log10")+`. The script confirms that both produce the transformation `"log-10"`. The colour scales show three ways to choose colours: `scale_colour_manual(values = )` takes a named vector (names matched to levels, which is the safe form), `scale_colour_viridis_d()` uses the viridis palette and `scale_colour_brewer(palette = )` a ColorBrewer palette; the colours of the plot are the `colour` column of the layer data. Titles are not part of the scales but live in `labs()`: `title`, `subtitle`, `caption`, `x`, `y` and one entry per aesthetic that has a legend (`colour = "Genre"`), and `get_labs()` reads the completed set. Since 4.0 the labels are derived while the plot is built, so `p$labels` is empty until then; code that read it before the build should call `get_labs()` instead (the ggplot2 4.0.0 NEWS lists this among the breaking changes).

The scale reference pages used here are https://ggplot2.tidyverse.org/reference/scale_manual.html[ggplot2 package documentation: scale_manual], https://ggplot2.tidyverse.org/reference/scale_viridis.html[ggplot2 package documentation: scale_viridis], https://ggplot2.tidyverse.org/reference/scale_brewer.html[ggplot2 package documentation: scale_brewer], https://ggplot2.tidyverse.org/reference/labs.html[ggplot2 package documentation: labs] and, for dates, https://ggplot2.tidyverse.org/reference/scale_date.html[ggplot2 package documentation: scale_date]. The scales package that implements transformations, breaks and label formatters is documented at https://scales.r-lib.org/reference/label_number.html[scales package documentation: label_number].

=== Palettes and the 4.0 theme palettes

Until 4.0 the colours of a default discrete or continuous colour scale came from a global option. In 4.0 the default scales (`scale_colour_discrete()`, `scale_fill_continuous()` and the others for the aesthetics colour and fill) have a `palette` argument that is `NULL` by default, which means "ask the theme", and the theme has new elements `palette.colour.discrete`, `palette.colour.continuous` and the same for `fill`; that replaced the old options-based system, with some backward compatibility (ggplot2 4.0.0 NEWS). The practical effect is that a palette can now be part of a theme, see <<themes,Themes>>.

== Limits, dropped rows and zooming

The most common warning in ggplot2 is not about a mistake in the code. It is about data that cannot be drawn. A missing value in a mapped aesthetic cannot be placed, and a value outside the limits of a scale has been turned into a missing value by the scale; in both cases the row is removed before drawing and ggplot2 says how many were removed and by which layer. The same mechanism explains two spellings that look equivalent and are not: `xlim(100, 300)` (and `lims()`, and `limits =` in a scale) set the limits of the scale, so the data outside them is converted to `NA` and removed, and every stat then works on what is left; `pass:c[coord_cartesian(xlim = c(100, 300))]` only changes the window through which the plot is seen, and the stats still use all the data. When the question is "show me this part of the plot", use the coordinate system; when the question is "ignore these values", use the scale.

The script collects the conditions raised while a plot is built and drawn, to show the text of the warning in each case, and then compares what the two approaches do to a fitted line. The warning is raised while the plot is drawn, not when it is built, which is why the helper in the script saves the plot to a temporary file.

[source,r]
----
library(ggplot2)
source("scenario.R")

# Collect the messages and warnings raised while an expression runs.
conditions <- \(expr) {
  seen <- character()
  withCallingHandlers(
    expr,
    message = \(m) {
      seen <<- c(seen, conditionMessage(m))
      invokeRestart("muffleMessage")
    },
    warning = \(w) {
      seen <<- c(seen, conditionMessage(w))
      invokeRestart("muffleWarning")
    }
  )
  seen
}
draw <- \(p) ggsave(tempfile(fileext = ".svg"), p, width = 6, height = 4)

# Three books have no pages or no year: they are dropped when drawing.
base <- ggplot(books, aes(pages, year)) + geom_point()
cat(conditions(draw(base)), sep = "\n")
#> Removed 3 rows containing missing values or values outside the scale range
#> (`geom_point()`).

# xlim() sets scale limits: data outside is converted to NA, then removed.
cut_off <- base + xlim(100, 300)
cat(conditions(draw(cut_off)), sep = "\n")
#> Removed 10 rows containing missing values or values outside the scale range
#> (`geom_point()`).
sum(is.na(layer_data(cut_off)$x))
#> [1] 10

# coord_cartesian() zooms: no data is removed, only the window changes.
zoomed <- base + coord_cartesian(xlim = c(100, 300))
cat(conditions(draw(zoomed)), sep = "\n")
#> Removed 3 rows containing missing values or values outside the scale range
#> (`geom_point()`).
sum(is.na(layer_data(zoomed)$x))
#> [1] 2

# The difference matters when a stat uses the data: the fit changes. (The
# messages and warnings of these builds are the ones shown above.)
trend <- ggplot(books, aes(pages, year)) +
  geom_smooth(method = "lm", se = FALSE)
fit_range <- \(p) {
  d <- suppressWarnings(suppressMessages(layer_data(p, 1L)))
  round(range(d$y), 1)
}
fit_range(trend + xlim(100, 300))
#> [1] 2009.4 2024.0
fit_range(trend + coord_cartesian(xlim = c(100, 300)))
#> [1] 1953.0 2051.8

# oob controls what happens to values outside the limits; oob_keep() keeps them.
kept <- base + scale_x_continuous(limits = c(100, 300), oob = scales::oob_keep)
cat(conditions(draw(kept)), sep = "\n")
#> Removed 3 rows containing missing values or values outside the scale range
#> (`geom_point()`).

# expand adds padding around the data; expand = FALSE removes it.
tight <- base + coord_cartesian(expand = FALSE)
tight$coordinates$expand
#> [1] FALSE
base$coordinates$expand
#> [1] TRUE
----

Source: https://ggplot2.tidyverse.org/reference/lims.html[ggplot2 package documentation: Set scale limits]

Three books have no page count or no year, so the first plot already reports `Removed 3 rows containing missing values or values outside the scale range`, with the layer in brackets on the second line. With `xlim(100, 300)` the count is ten: the three rows with a missing value and seven more whose page count is outside the range; `layer_data()` shows `NA` in the `x` column of ten rows (the two missing page counts and eight books outside the range). With `coord_cartesian()` the count is back to three, and only the two missing page counts show up as `NA` in `x`. The fit shows why it matters: with `xlim()` the line is estimated only from the books with 100 to 300 pages, and its `y` runs from 2009.4 to 2024.0; with `coord_cartesian()` the line is estimated from all books over their whole range of pages, with `y` from 1953.0 to 2051.8, and the window only crops it. Neither is wrong; they answer different questions, and silently mixing them up is how a trend line changes when a plot is "zoomed". The scale argument `oob` ("out of bounds") says what happens to a value outside the limits: the default converts it to `NA`, and `scales::oob_keep` leaves it in the data (the plot is clipped to the panel). `expand` adds padding around the data; `pass:c[coord_cartesian(expand = FALSE)]` removes it, and the `expansion()` helper builds a padding of a given multiple or amount (https://ggplot2.tidyverse.org/reference/expansion.html[ggplot2 package documentation: expansion]). The coordinate system is documented at https://ggplot2.tidyverse.org/reference/coord_cartesian.html[ggplot2 package documentation: coord_cartesian] and the out-of-bounds handlers at https://scales.r-lib.org/reference/oob.html[scales package documentation: oob].

== Coordinate systems

The coordinate system turns the positions the scales produced into positions on the page. The default is `coord_cartesian()`, which also carries `xlim` and `ylim` (the zoom above), `expand` and, since 4.0, a `ratio` and a `reverse`. The others change the geometry. `coord_fixed(ratio = )` makes one unit on x as long as `ratio` units on y, which is right for maps and for plots where both axes are in the same unit; in 4.0 it is a wrapper around `coord_cartesian(ratio = )`. `coord_flip()` swaps the axes. `coord_polar()` maps x to an angle and y to a radius, and its successor `coord_radial()` (introduced with 3.5.0) adds a better axis system. `coord_transform()` (named `coord_trans()` before 4.0.0) applies a transformation after the stats, which is different from a scale transformation that is applied before them.

`coord_flip()` is the one that old tutorials use for horizontal bars and horizontal box plots, and the reason is historical: before ggplot2 3.3.0 the way to put the groups on the vertical axis was to draw the vertical version and flip the whole plot. Since 3.3.0 the geoms and stats that have a direction can choose it, deduced from the mapping or given by the `orientation` argument. Mapping the categorical variable to `y` is enough: `pass:c[ggplot(shelf, aes(duration, genre)) + geom_boxplot()]` draws horizontal boxes. The ggplot2 3.5.0 NEWS marks `coord_flip()` as superseded and recommends swapping the aesthetics and using `orientation`, and the script shows that both ways draw the same boxes.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)
shelf <- merge(loans, books[c("isbn", "genre", "pages")], by = "isbn")
shelf$duration <- as.integer(shelf$return_date - shelf$loan_date)
shelf <- subset(shelf, !is.na(duration) & duration >= 0)

# Horizontal boxes the old way: draw vertical ones, then flip the coordinates.
flipped <- ggplot(shelf, aes(genre, duration)) +
  geom_boxplot() +
  coord_flip()
class(flipped$coordinates)[[1L]]
#> [1] "CoordFlip"
flipped$coordinates$is_linear()
#> [1] TRUE

# The current way: put the continuous variable on x and the groups on y.
horizontal <- ggplot(shelf, aes(duration, genre)) + geom_boxplot()
class(horizontal$coordinates)[[1L]]
#> [1] "CoordCartesian"
layer_data(horizontal)$flipped_aes[[1L]]
#> [1] TRUE

# Same pictures, same boxes: the data differ only in the names of the columns.
a <- layer_data(flipped)
b <- layer_data(horizontal)
a$ymin[order(a$x)]
#> [1] 21  1 10 16 21  8
b$xmin[order(b$y)]
#> [1] 21  1 10 16 21  8

# coord_fixed(): one unit on x is as long as one unit on y.
fixed <- ggplot(shelf, aes(pages, duration)) +
  geom_point() +
  coord_fixed(ratio = 5)
fixed$coordinates$ratio
#> [1] 5

# coord_polar() and its successor coord_radial() change the geometry: this is
# how a pie chart is made, and why one is not drawn here.
pie <- ggplot(shelf, aes(x = "", fill = genre)) +
  geom_bar(width = 1) +
  coord_polar(theta = "y")
class(pie$coordinates)[[1L]]
#> [1] "CoordPolar"
class(coord_radial())[[1L]]
#> [1] "CoordRadial"
class(coord_transform(y = "log10"))[[1L]]
#> [1] "CoordTransform"
----

Source: https://ggplot2.tidyverse.org/reference/coord_flip.html[ggplot2 package documentation: coord_flip]

The two box plots have the same five numbers per genre (the vertical ones in the `ymin` column of the built data, the horizontal ones in `xmin`), and the layer data of the second records `flipped_aes` as `TRUE`, which is how the stat and the geom agree on the direction. `coord_fixed(ratio = 5)` stores its ratio. The last three lines show the class of a polar pie, of `coord_radial()` and of the transformed coordinate system. A pie chart is a bar chart in polar coordinates, `geom_bar(width = 1)` with `pass:c[coord_polar(theta = "y")]`, and the script builds one and shows its class; it is not drawn here because angles are read less accurately than lengths and a bar chart (the default of `geom_bar()`) says the same thing better. The reference pages are https://ggplot2.tidyverse.org/reference/coord_fixed.html[ggplot2 package documentation: coord_fixed], https://ggplot2.tidyverse.org/reference/coord_polar.html[ggplot2 package documentation: coord_polar and coord_radial] and https://ggplot2.tidyverse.org/reference/coord_transform.html[ggplot2 package documentation: coord_transform].

== Facets

Facets split the data into panels that share the scales and the layout. `facet_wrap()` makes a ribbon of panels from the levels of one or more variables and wraps it to fit; `facet_grid()` makes a grid with one variable on the rows and another on the columns. Both take the variables as `vars()` (the current spelling, which quotes like `aes()`) or as a formula such as `+~ genre+` or `+genre ~ period+`, which is the older spelling and still works. `facet_wrap()` has `ncol` and `nrow`, `scales` (`"fixed"`, `"free"`, `"free_x"` or `"free_y"` to let each panel have its own axis range), and `labeller`, a function that makes the text of the strip: `label_both` adds the variable name, `label_wrap_gen()` wraps long labels, and `as_labeller()` turns a named vector or a function into one.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)
shelf <- merge(loans, books[c("isbn", "genre", "pages")], by = "isbn")
shelf$duration <- as.integer(shelf$return_date - shelf$loan_date)
shelf <- subset(shelf, !is.na(duration) & duration >= 0)
shelf$period <- ifelse(shelf$loan_date < as.Date("2026-01-01"), "2025", "2026")

base <- ggplot(shelf, aes(duration)) + geom_histogram(binwidth = 7)

# facet_wrap(): a ribbon of panels, one per value of the variable.
wrapped <- base + facet_wrap(~genre, ncol = 3, scales = "free_y")
layout <- ggplot_build(wrapped)$layout$layout
layout[c("PANEL", "ROW", "COL", "genre", "SCALE_X", "SCALE_Y")]
#>   PANEL ROW COL           genre SCALE_X SCALE_Y
#> 1     1   1   1         classic       1       1
#> 2     2   1   2         fiction       1       2
#> 3     3   1   3         mystery       1       3
#> 4     4   2   1     non-fiction       1       4
#> 5     5   2   2          poetry       1       5
#> 6     6   2   3 science fiction       1       6

# facet_grid(): rows by one variable and columns by another.
grid_plot <- base + facet_grid(rows = vars(genre), cols = vars(period))
grid_layout <- ggplot_build(grid_plot)$layout$layout
head(grid_layout[c("PANEL", "ROW", "COL", "genre", "period")], 4L)

#> 1     1   1   1 classic   2025

The layout is a data frame with one row per panel: its position (`ROW`, `COL`), the value of each faceting variable, and which x and y scale it uses (`SCALE_X`, `SCALE_Y`). With `scales = "free_y"` each panel has its own `SCALE_Y`, from 1 to 6, and with the default `"fixed"` they would all be 1. `facet_grid()` crosses the two variables: six genres by two periods gives twelve panels, and the layout lists them in order, with the rows first. The faceting is done on the data: the number of rows of a point layer in each panel is the number of loans of that genre, which agrees with `table(shelf$genre)`. The last chunk saves two faceted plots with strip labels from `label_both` and from `as_labeller()`. The functions are documented at https://ggplot2.tidyverse.org/reference/facet_grid.html[ggplot2 package documentation: facet_grid], https://ggplot2.tidyverse.org/reference/labellers.html[ggplot2 package documentation: labellers], https://ggplot2.tidyverse.org/reference/as_labeller.html[ggplot2 package documentation: as_labeller] and https://ggplot2.tidyverse.org/reference/vars.html[ggplot2 package documentation: vars]. A faceted plot of different charts (a histogram next to a scatter plot) is not what facets are for: they repeat one chart over subsets. Different charts are combined with another package, see <<assembly,Combining different plots>>.

[[themes]]
== Themes

The theme controls everything that is not data: text, lines, backgrounds, spacing and the position of the legend. There are two layers to it. A complete theme, `theme_gray()` (the default, also spelt `theme_grey()`), `theme_bw()`, `theme_minimal()`, `theme_classic()`, `theme_light()`, `theme_dark()`, `theme_linedraw()` and `theme_void()`, sets every element at once and takes `base_size` and `base_family`; in 4.0 it also takes `ink`, `paper`, `accent` and `header_family`. A partial theme made by `theme()` sets only the elements named, and is added to the plot like any other component. The elements form a tree (`axis.text.x` inherits from `axis.text`, which inherits from `text`), and each is built by an element function: `element_text()` for text, `element_line()` for lines, `element_rect()` for rectangles, and `element_blank()` for "draw nothing", which is how a part of the plot is removed. The ggplot2 documentation describes this hierarchy in the reference pages for https://ggplot2.tidyverse.org/reference/theme.html[ggplot2 package documentation: theme], https://ggplot2.tidyverse.org/reference/ggtheme.html[ggplot2 package documentation: complete themes] and https://ggplot2.tidyverse.org/reference/element.html[ggplot2 package documentation: theme elements].

The four complete themes are all complete (`@complete` is `TRUE`), and the active default is identical to `theme_gray()`. `theme()` returns an incomplete theme, so `@complete` is `FALSE`; it holds exactly the three elements the script named (`axis.text.x` rotated, `legend.position` at the bottom, `plot.title` in bold face). `element_blank()` stores an object of class `"ggplot2::element_blank"` in the place of the element. `theme_set()` replaces the active theme for the rest of the session and returns the previous one, which is what lets a script restore it, and `theme_update()` modifies single elements of the active theme; in 4.0 their new names are `set_theme()` and `update_theme()` and `get_theme()` replaces `theme_get()`, and the old names keep working (https://ggplot2.tidyverse.org/reference/get_theme.html[ggplot2 package documentation: get_theme]). The first is `pass:c[theme(geom = element_geom(...))]`: the theme now carries the defaults of the layers, so `pointsize = 3` made every point layer draw size 3 points, and the `ink` argument of a complete theme drove the default colour of the points to red. The second is the `palette.colour.discrete` element, which supplies the colours of the default discrete colour scale. Both are listed in the 4.0.0 NEWS as new `theme()` arguments (`geom`, `+palette.{aes}.discrete+` and `+palette.{aes}.continuous+`).

== Guides

Guides are what scales draw to be read: axes for position scales, legends and colour bars for the others. The guides are built from the trained scales, and since ggplot2 3.5.0 they are ggproto objects styled through the theme (the 3.5.0 NEWS lists the rewrite of the whole guide system as its main breaking change). Two aesthetics mapped from the same variable merge into a single legend; a different variable makes a separate one; a continuous colour or fill gets a colour bar. The function `guides()` switches a guide off (`guides(size = "none")`; the old `FALSE` is deprecated since 3.3.4) or replaces it by a restyled one: `guide_legend(ncol = 2)` arranges the keys in two columns and `guide_colourbar(reverse = TRUE)` reverses the bar. The legend position is a theme setting, `theme(legend.position = )` with `"right"`, `"left"`, `"top"`, `"bottom"`, `"none"` or `"inside"`; a numeric vector as the position was deprecated in 3.5.0 in favour of `"inside"` with `legend.position.inside`. The reference pages are https://ggplot2.tidyverse.org/reference/guides.html[ggplot2 package documentation: guides], https://ggplot2.tidyverse.org/reference/guide_legend.html[ggplot2 package documentation: guide_legend] and https://ggplot2.tidyverse.org/reference/guide_colourbar.html[ggplot2 package documentation: guide_colourbar].

}

#> [1] "GuideLegend"

# The same variable on two aesthetics: the legends merge into one.
merged <- ggplot(known, aes(pages, year, colour = genre, shape = genre)) +
  geom_point()
guides_of(merged)
#> [1] "GuideLegend"

# Two variables: two legends. A continuous colour gets a colour bar.
two <- ggplot(known, aes(pages, year, colour = genre, size = pages)) +
  geom_point()
guides_of(two)
#> [1] "GuideLegend" "GuideLegend"

#> [1] "GuideColourbar"

#> [1] "GuideLegend"

columns$guides$guides$colour$params$ncol
#> [1] 2
reversed <- bar + guides(colour = guide_colourbar(reverse = TRUE))
class(reversed$guides$guides$colour)[[1L]]

bottom$theme$legend.position
#> [1] "bottom"

The first four plots show the merging rule: one variable on one aesthetic gives one legend; the same variable on `colour` and `shape` still gives one; a second variable (`size = pages`) gives a second legend; a continuous colour gives `GuideColourbar`. `guides(size = "none")` removes the second guide, and `guide_legend(ncol = 2)` is stored with the guide's parameters. The class names printed here are the ggproto classes of 3.5.0 and later; they are what an extension author subclasses.

== Saving plots: `ggsave()` and devices

`ggsave()` is the function to save a plot to a file. Its reference page says that it defaults to saving the last plot that was displayed, uses the size of the current device unless a size is given, and guesses the type of device from the extension of the file name. The arguments that matter are `filename`, `plot`, `device`, `path`, `width`, `height`, `units` (`"in"`, `"cm"`, `"mm"` or `"px"`), `dpi` (default 300; a number, or a string such as `"print"`), `scale`, `bg` and, since 3.5.0, `create.dir`. Always give a `plot` and a size in a script: the defaults refer to the last plot displayed and the size of whichever device happens to be current, which depends on the session, and ggplot2 says so with the message `Saving 7 x 7 in image` when the size had to be taken from the device. The return value is the file name, invisibly, since ggplot2 3.3.4. In 4.0.0 the plot argument can also be a list of plots, saved as the pages of a PDF.

The device is chosen by the extension, or by `device`, which is a name or a device function. For vector output ggplot2 maps `"svg"` to `svglite::svglite()` and checks that the svglite package is installed (it is a suggested, not a required, dependency: 3.5.1 made `ggsave()` offer to install it, and the NEWS entry that began using it is in 2.1.0); the package is documented at https://svglite.r-lib.org/reference/svglite.html[svglite package documentation: svglite]. The base R device `svg()` is the Cairo one and is still available by passing the function (`device = svg`), as the script shows. For PNG, JPEG and TIFF, ggplot2 uses the ragg package if it is installed and the base devices otherwise (the NEWS entry is in 3.3.4), which is why a PNG can look different on two machines. For PDF, `"pdf"` is the default and `cairo_pdf` (a device function, with `device = cairo_pdf`) embeds fonts through Cairo. The base R devices are documented at https://search.r-project.org/R/refmans/grDevices/html/cairo.html[R documentation: svg and cairo_pdf], https://search.r-project.org/R/refmans/grDevices/html/png.html[R documentation: png] and https://search.r-project.org/R/refmans/grDevices/html/pdf.html[R documentation: pdf]; the page xref:programming-languages/r/base-graphics-and-devices.adoc[Base Graphics and Devices] explains the device model. An alternative that does not use `ggsave()` is to open a device yourself, print the plot and close the device, as the script does with `svg()`; `print()` returns the plot invisibly, so it can sit inside a function.

The script writes SVG with svglite (the file starts with the XML declaration and contains the group marker `svglite`), then with the Cairo device (no marker), then two PNG files whose dimensions are read back from the file header: 6 by 4 inches at 100 dpi is 600 by 400 pixels, and 12.7 by 7.62 centimetres (5 by 3 inches) is 500 by 300. An extension that ggplot2 does not know is an error with the text `Unknown graphics device "xyz"`, not a guess, and `get_last_plot()` (called `last_plot()` before 4.0) returns the plot that was last created or modified, which is what a `ggsave()` call without `plot` saves. == Under the plot: grid and gtable

A rendered ggplot is not a bitmap or a special ggplot2 drawing language: it is a `gtable`, a table of grid graphical objects, drawn by the `grid` package that ships with R. `ggplotGrob(p)` returns that table, and so does `ggplot_gtable(ggplot_build(p))`. The table has a row and column structure (the script prints 16 rows by 13 columns), a `layout` data frame that says which cell each grob occupies and under which name (`panel`, `axis-l`, `axis-b`, `title`, the legend boxes), and heights and widths in grid units. Each cell holds a grid grob; the panel is a `gTree` whose children are the pieces of the layers (here points, with grid lines and borders that are empty `zeroGrob` placeholders). Because it is a grob, it can be drawn on any device with `grid.draw()` after `grid.newpage()`, edited cell by cell with the gtable functions, or combined with other grobs. The model of viewports, units and grobs is the subject of xref:programming-languages/r/grid-graphics-and-lattice.adoc[Grid Graphics and Lattice]; the structure and the way that the graphics engine drives it are described in the R Internals manual (https://cran.r-project.org/doc/manuals/r-release/R-ints.html#Grid-graphics[R Internals: Grid graphics]).

== Extending ggplot2 with ggproto

Everything that draws, computes or lays out in a plot is a ggproto object: `Geom`, `Stat`, `Position`, `Coord`, `Facet`, `Scale` and `Guide` are the base classes, and `GeomPoint`, `StatBin` and so on are their instances, as the matrix in the layers section showed. ggproto is ggplot2's own object system with mutable objects and inheritance that works across packages, designed for this purpose, and the article on extending ggplot2 gives its history and builds a stat, a geom, a facet and a guide with it (https://ggplot2.tidyverse.org/articles/extending-ggplot2.html[ggplot2 package documentation: Extending ggplot2]). The reference page for `ggproto()` documents the constructor (https://ggplot2.tidyverse.org/reference/ggproto.html[ggplot2 package documentation: ggproto]). The script defines the smallest useful extension: a stat that replaces each group's rows by the group's median point, and a constructor function that wraps `layer()` in the form that package code exports. The `nolint` block is there because ggproto objects are named in CamelCase and the layer constructors use the dotted argument names (`na.rm`, `show.legend`, `inherit.aes`) that every ggplot2 function uses.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
known <- subset(books, !is.na(pages) & !is.na(year))

# A stat is a ggproto object: compute_group() gets one group's data frame
# and returns a new data frame.
# nolint start: object_name_linter.
StatMedianPoint <- ggproto("StatMedianPoint", Stat,
  required_aes = c("x", "y"),
  compute_group = function(data, scales) {
    data.frame(x = median(data$x), y = median(data$y))
  }
)

# The user-facing function wraps layer(); it is what package code exports.
# The argument names are ggplot2's own conventions, hence the nolint block.
stat_median_point <- function(mapping = NULL, data = NULL, geom = "point",
                              position = "identity", ...,
                              na.rm = FALSE, show.legend = NA,
                              inherit.aes = TRUE) {
  layer(
    stat = StatMedianPoint, data = data, mapping = mapping, geom = geom,
    position = position, show.legend = show.legend,
    inherit.aes = inherit.aes, params = list(na.rm = na.rm, ...)
  )
}

# nolint end

p <- ggplot(known, aes(pages, year, colour = genre)) +
  geom_point(alpha = 0.3) +
  stat_median_point(size = 4)
class(StatMedianPoint)
#> [1] "StatMedianPoint" "Stat"            "ggproto"         "gg"
is_ggproto(StatMedianPoint)
#> [1] TRUE
medians <- layer_data(p, 2L)
medians[order(medians$group), c("x", "y", "group")]
#>       x    y group
#> 1 356.0 1906     1
#> 2 214.0 2021     2
#> 3 272.5 2017     3
#> 4 263.5 2016     4
#> 5  88.0 2005     5
#> 6 387.0 2014     6
ggsave(tempfile(fileext = ".svg"), p, width = 6, height = 4)
----

Source: https://ggplot2.tidyverse.org/articles/extending-ggplot2.html[ggplot2 package documentation: Extending ggplot2]

This is the whole mechanism: a ggproto class with `compute_group()`, a layer constructor, and the usual `+`. A geom is the same, with `draw_panel()` or `draw_group()`. Only an extension that adds a theme element or manipulates the plot object itself meets the S7 classes; the ones that add geoms, stats, positions, coordinates, facets and scales work with ggproto. Packages that extend ggplot2 (patchwork and cowplot among them) are named in the section on combining different plots and are not installed here.

== The shelf charts rebuilt in ggplot2

=== Loans per month

`geom_col()` draws the count per month, and the x axis is a date scale. A `Date` is a number of days to the scale, so the bars are `width = 25` days wide, centred on the first of the month. `scale_x_date(date_breaks = "3 months", date_labels = "%b %Y")` puts a tick every three months with the label format of `format()` for dates (xref:programming-languages/r/dates-and-times.adoc[Dates and Times] lists the codes). The loan with the impossible date 2025-02-30 became `NA` when `loans` was read and is dropped by `aggregate()`, so the count for February 2025 is two.

[source,r]

=== Pages against duration

A scatter plot of the number of pages of a book against the days it was kept, with a straight line fitted by `lm`. The `formula` is given, so no message is printed. The script then checks that the line is the same as the one from `lm()` itself, using the base R functions of xref:programming-languages/r/statistical-models.adoc[Statistical Models].

[source,r]
----
library(ggplot2)

#> [1] 42

  geom_point(alpha = 0.6) +
  geom_smooth(method = "lm", formula = y ~ x) +
  labs(title = "Pages and loan duration", x = "Pages", y = "Days")

round(coef(fit), 4)
#> (Intercept)       pages
#>     17.8693      0.0068
curve <- layer_data(p, 2L)
head(round(curve[c("x", "y", "ymin", "ymax")], 2), 3)
#>       x     y  ymin  ymax
#> 1 88.00 18.47 13.03 23.90
#> 2 92.35 18.50 13.16 23.84
#> 3 96.71 18.53 13.28 23.77

The coefficients are an intercept of about 17.9 days and a slope of 0.0068 days per page: a 300-page book is kept about two days longer than a 10-page one, and the data are far too few to say whether that is more than chance. The first three rows of the smooth layer match the `predict()` values to two decimals, which shows that `geom_smooth(method = "lm")` is a convenience over `lm()` and `predict()`, with the band computed from the standard errors of the fit.

=== Assembling charts

The charts that share data and a mapping are assembled with facets. The script below does that for pages against duration, one panel per genre with `scales = "free_x"`, and for the overdue share per genre as a bar chart. The table of shares is the one place where a dplyr pipeline is used; the base R equivalent (`aggregate()` with a function and an extra argument) follows it and gives the same numbers.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)
shelf <- merge(loans, books[c("isbn", "genre", "pages")], by = "isbn")
shelf$duration <- as.integer(shelf$return_date - shelf$loan_date)
shelf <- subset(shelf, !is.na(duration) & duration >= 0)

# One dplyr pipeline for the data preparation: overdue rate by genre.
by_genre <- shelf |>
  dplyr::group_by(genre) |>
  dplyr::summarise(
    loans = dplyr::n(),
    mean_days = round(mean(duration), 1),
    overdue = round(mean(duration > loan_days), 2)
  ) |>
  dplyr::arrange(dplyr::desc(overdue))
as.data.frame(by_genre)

#> 1         classic     5      21.4    0.60
#> 2     non-fiction     5      21.2    0.60
#> 3          poetry     5      20.0    0.60
#> 4         mystery     4      20.8    0.50
#> 5         fiction    18      19.3    0.44
#> 6 science fiction    13      20.5    0.38

  geom_point() +
  geom_hline(yintercept = loan_days, linetype = "dashed") +

The dplyr pipeline is called with `dplyr::` prefixes so that no package is attached and no function is masked, and `|>` is the native pipe of xref:programming-languages/r/pipes-and-the-native-pipe.adoc[Pipes and the Native Pipe]. The two tables agree: the classic, non-fiction and poetry books are kept more than 21 days in 60 per cent of the returned loans, science fiction in 38 per cent. These shares count only the loans that came back, because the script keeps the loans with a known, non-negative duration; the overdue rates on xref:programming-languages/r/tidyverse-and-dplyr.adoc[The tidyverse and dplyr] and xref:programming-languages/r/data-table.adoc[data.table] also count the loans still out on the reference day, and are therefore different (0.67 for poetry and 0.47 for science fiction there). The faceted plot has six panels, with the number of points per panel in the table at the end of the script (the loans of each genre that have a page count). For charts that are different from each other (a bar chart next to a scatter plot next to a histogram), facets are the wrong tool, and the usual answer is a package that arranges several plots on one page.

==== Combining different plots

The patchwork package arranges ggplot objects with the operators `pass:c[+]`, `|` and `/` (`pass:c[p1 | p2]` puts two plots side by side), cowplot offers `plot_grid()` and publication themes, and gridExtra has `grid.arrange()`; all three are community packages that work on the grid layer, and none is installed in the environment used for this page, so they are not run here. The grid layer is also available directly: `ggplotGrob()` returns the gtable of each plot, and `grid.layout()` and viewports (see xref:programming-languages/r/grid-graphics-and-lattice.adoc[Grid Graphics and Lattice]) place them. The base graphics equivalent, `par(mfrow = )` and `layout()`, does not work for ggplot objects, because they are drawn with grid and not with the graphics package.

== Pitfalls

* *A plot that is never printed is never drawn.* In `source()`, in a function and in a loop the automatic printing does not happen, so call `print(p)` or `ggsave()`. This is R FAQ 7.22, and it names ggplot2 graphics (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-do-lattice_002ftrellis-graphics-not-work_003f[R FAQ 7.22: Why do lattice/trellis graphics not work?]). Under `Rscript`, drawing without opening a device writes `Rplots.pdf` into the working directory.
* *A plus at the start of a line is a new statement.* End the line with the plus, not the next one. The error is `pass:c[Cannot use + with a single argument]`.
* *Mapping is not setting.* `aes(colour = "red")` maps a constant and adds a legend; `colour = "red"` outside `aes()` sets it.
* *`xlim()` and `limits` drop data; `coord_cartesian()` zooms.* They give different fits and different counts of removed rows.
* *`geom_bar()` counts, `geom_col()` draws heights.* Giving `geom_bar()` a `y` and `geom_col()` no `y` are the two errors in the table of messages.
* *Order of a discrete axis is the order of the factor levels* (alphabetical for a character vector). Reorder with a factor, or with `reorder()` as the genre chart does (xref:programming-languages/r/factors.adoc[Factors]).
* *Randomness in `geom_jitter()` and `position_jitter()` changes the plot at each draw.* Give the position a `seed` to make a plot reproducible.
* *Columns in `aes()` of package code need `.data`.* Otherwise `R CMD check` reports "no visible binding for global variable" (see the evaluation page). Inside `aes()`, `df$col` is discouraged and says so: `Use of known$pages is discouraged. Use pages instead.`
* *A global `theme_set()` changes every later plot in the session.* Keep the previous value that it returns and restore it, or pass the theme to each plot.
* *Lifecycle warnings are normally shown once per session.* A script that runs once shows each deprecation once; a long interactive session may have seen it earlier and show nothing.

== Where older tutorials differ

Tutorials written before ggplot2 3.4.0 (2022) contain idioms that now warn or fail, and some that only look dated. The script below runs the deprecated ones under a helper that prints the warning instead of raising it, so the message each one gives today is on record; the idioms in the last block are old but still fine.

[source,r]
----
library(ggplot2)
source("scenario.R")
books$genre <- tolower(trimws(books$genre))
known <- subset(books, !is.na(pages) & !is.na(year))

# Old idioms still run, mostly; this script only shows what they now say. The
# calls are wrapped so that the warning text is printed instead of raised.
old <- \(label, expr) {
  seen <- character()
  withCallingHandlers(
    expr,
    warning = \(w) {
      seen <<- c(seen, conditionMessage(w))
      invokeRestart("muffleWarning")
    }
  )
  cat("--", label, "\n", paste(seen, collapse = "\n"), "\n", sep = "")
}

old("qplot()", ggplot_build(qplot(pages, year, data = known)))
#> --qplot()
#> `qplot()` was deprecated in ggplot2 3.4.0.
old("..count..", ggplot_build(
  ggplot(known, aes(pages, ..count..)) + geom_histogram(binwidth = 50) # nolint
))
#> --..count..
#> The dot-dot notation (`..count..`) was deprecated in ggplot2 3.4.0.
#> ℹ Please use `after_stat(count)` instead.
old("stat(count)", ggplot_build(
  ggplot(known, aes(pages, stat(count))) + geom_histogram(binwidth = 50)
))
#> --stat(count)
#> `stat(count)` was deprecated in ggplot2 3.4.0.
#> ℹ Please use `after_stat(count)` instead.

))

#> ℹ See also `vignette("ggplot2-in-packages")` for more information.
old("aes(known$pages)", ggplot_build(

#> Use of `known$pages` is discouraged.

  ggplot(known, aes(genre)) + geom_bar(size = 2)

#> --geom_bar(size =)
#> Ignoring unknown parameters: `size`

  ggplot(known, aes(pages, year, colour = genre)) +
    geom_point() + guides(colour = FALSE)

#> --geom_errorbarh()
#> `geom_errorbarh()` was deprecated in ggplot2 4.0.0.
#> ℹ Please use the `orientation` argument of `geom_errorbar()` instead.
old("coord_trans()", coord_trans(y = "log10"))
#> --coord_trans()
#> `coord_trans()` was deprecated in ggplot2 4.0.0.
#> ℹ Please use `coord_transform()` instead.
old("expand_scale()", expand_scale(mult = 0.1))
#> --expand_scale()
#> `expand_scale()` was deprecated in ggplot2 3.3.0.
#> ℹ Please use `expansion()` instead.

#> `fortify(<lm>)` was deprecated in ggplot2 4.0.0.
