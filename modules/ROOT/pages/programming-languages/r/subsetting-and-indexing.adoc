== One idea, three operators

R has no separate array, record and dictionary syntax. Everything that holds several values is a vector (atomic or list) with optional attributes, and one family of operators takes parts out of any of them. The language definition lists the forms: `pass:c[x[i\]]`, `pass:c[x[i, j\]]`, `pass:c[x[[i\]\]]`, `pass:c[x[[i, j\]\]]`, `x$a` and `x$"a"`, and then gives the rules that the rest of this page unfolds: `pass:c[[]` can select several elements and returns an object of the same kind, `pass:c[[[]` selects exactly one element and returns it, and `$` is a shorthand for `pass:c[[[]` with a literal name that applies to lists, to `NULL` and to environments (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing[The R Language Definition: Indexing]). The help page puts the first distinction in one sentence: the most important distinction between `pass:c[[]`, `pass:c[[[]` and `$` is that `pass:c[[]` can select more than one element whereas the other two select a single element (https://search.r-project.org/R/refmans/base/html/Extract.html[R documentation: Extract]).

A way to remember the three is a box of items. `pass:c[[]` takes a smaller box with some of the items in it (the result has the type of the container). `pass:c[[[]` takes one item out of the box (the result has the type of the item). `$` does the same as `pass:c[[[]` and saves typing the quotes, at the price of the rules for names that the section on partial matching explains. The figure shows the nine combinations of the three operators and the three most common containers, and the table that follows lists the rules by operator.

All three operators are ordinary generic functions, and a class can supply its own method: `pass:c[[.data.frame]` and `pass:c[[.factor]` are the two methods that ship with R (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing-other-structures[The R Language Definition: Indexing other structures]). This page describes the default methods and, from the data frame section on, the data frame method. The classes of the xref:programming-languages/r/s3-classes-and-generics.adoc[S3 classes and generics] page can define their own `pass:c[[]` and `pass:c[[[]`; those methods do not have to follow the rules below, for example for partial matching.

An atomic vector is also what a matrix is, with a `dim` attribute, so every vector form of indexing works on a matrix with a single index (see <<matrices>>). The same is true of a data frame, which is a list of columns, so `pass:c[df[j\]]` and `pass:c[df[[j\]\]]` index it as a list (see <<data-frames-subsetting>>).

== The four kinds of index

An introduction to R lists four kinds of index vector for `pass:c[x[i\]]` on a vector: a logical vector, a vector of positive integers, a vector of negative integers, and a vector of character strings; and says that an indexed expression can also appear on the receiving end of an assignment (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Index-vectors[An Introduction to R: Index vectors; selecting and modifying subsets of a data set]). The language definition adds the special cases: a zero, real numbers, factors, the empty index, `NULL` and `NA` (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing-by-vectors[The R Language Definition: Indexing by vectors]). The first script works through all of them on a vector made from the shelf scenario: the number of days that each of the first eight loans lasted, with the loan ids as names. A loan lasts `return_date - loan_date` days, and `loan_days` (21) is the loan period.

[source,r]
----
source("scenario.R")

# Loan lengths in days for the first eight loans, named by loan id.
# Unreturned or impossible loans would give NA; here L001 to L008 are complete.
days <- as.integer(loans$return_date - loans$loan_date)
names(days) <- loans$loan_id
loan_len <- days[1:8]
loan_len
#> L001 L002 L003 L004 L005 L006 L007 L008
#>   21   10    1   26   26   17   24   10

# 1. Positive integers select by position, in the order given
loan_len[c(1, 3)]
#> L001 L003
#>   21    1
loan_len[c(3, 1)]
#> L003 L001
#>    1   21
loan_len[8:6]
#> L008 L007 L006
#>   10   24   17

# 2. Negative integers drop positions
loan_len[-1]
#> L002 L003 L004 L005 L006 L007 L008
#>   10    1   26   26   17   24   10
loan_len[-(1:5)]
#> L006 L007 L008
#>   17   24   10
loan_len[-c(1, 8)]
#> L002 L003 L004 L005 L006 L007
#>   10    1   26   26   17   24

# 3. Logical vectors keep the TRUE positions
loan_len > loan_days
#>  L001  L002  L003  L004  L005  L006  L007  L008
#> FALSE FALSE FALSE  TRUE  TRUE FALSE  TRUE FALSE
loan_len[loan_len > loan_days]
#> L004 L005 L007
#>   26   26   24

# 4. Character vectors select by name (exact matching)
loan_len[c("L004", "L002")]
#> L004 L002
#>   26   10
loan_len["L999"]
#> <NA>
#>   NA

# Zero is a no-op: nothing is selected, or nothing is dropped
loan_len[0]
#> named integer(0)
loan_len[c(0, 2)]
#> L002
#>   10
loan_len[c(-1, 0)]
#> L002 L003 L004 L005 L006 L007 L008
#>   10    1   26   26   17   24   10
loan_len[-0]
#> named integer(0)

# A negative index outside the vector is silently ignored, a positive one

loan_len[-20]

loan_len[10]

#>   NA

loan_len[c(2, 2, 2)]
#> L002 L002 L002
#>   10   10   10

The rules the output shows, one by one:

* A vector of **positive integers** selects by position, in the order given and as often as given. The result has the length of the index, so `pass:c[loan_len[c(3, 1)\]]` reverses two elements and `pass:c[loan_len[c(2, 2, 2)\]]` repeats one. The names of the selected elements are selected with them.
* A vector of **negative integers** selects everything except the positions given. The elements of the index must all have the same sign. A negative position that is outside the vector is silently ignored (`pass:c[loan_len[-20\]]` returns the whole vector); the language definition says this has been so since R 2.6.0, for compatibility with S, because dropping a non-existent element is an empty operation.
* A **logical vector** keeps the positions where it is `TRUE`. `loan_len > loan_days` is a logical vector with the names of `loan_len`, so it can be used directly as the index, and this is the form that most filters take: `pass:c[x[condition\]]`.
* A **character vector** is matched against the names of `x`. The match is exact for `pass:c[[]`: there is no partial matching with a single bracket for any object. A name that is not there gives `NA` with the name `<NA>`.
* **Zero** is the neutral index. `pass:c[x[0\]]` is an empty vector of the same type (a named empty vector when `x` has names, printed `named integer(0)`), and a zero among positive or negative indices is as if it were not there: `pass:c[x[c(0, 2)\]]` is `pass:c[x[2\]]` and `pass:c[x[c(-1, 0)\]]` is `pass:c[x[-1\]]`. The case of `pass:c[x[-0\]]` is a trap: `-0` is `0`, so `pass:c[x[-0\]]` selects nothing, it does not drop nothing. Code that builds the index as `-n` with `n` possibly zero (`pass:c[x[-n\]]`) returns an empty vector exactly when it should return all of `x`.
* A positive index larger than `length(x)` gives `NA` for that position, and the result still has the length of the index: `pass:c[loan_len[c(1, 10)\]]` has two elements, the second named `<NA>`.
* **Real numbers** are truncated towards zero, so `pass:c[loan_len[2.9\]]` is `pass:c[loan_len[2\]]` and `pass:c[loan_len[-1.9\]]` is `pass:c[loan_len[-1\]]`; `pass:c[loan_len[0.9\]]` is `pass:c[loan_len[0\]]`. R 4.2.0 made the implementation follow what had always been documented: the index is `as.integer(i)` unless that would overflow, and then `trunc(i)` (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.2.0]).
* The **empty index** `pass:c[x[\]]` returns `x` (all of it, with its names, `dim` and `dimnames`), and `NULL` is treated as `integer(0)`, so `pass:c[x[NULL\]]` is empty. The empty index matters most on the left of an assignment (`pass:c[x[\] <- 0]` keeps the attributes of `x`), see <<subassign-vectors,Sub-assignment of vectors>>.

== Zero, NA and the length of the index

Three things go wrong in practice with indexes that are not plain vectors of valid positions: mixing signs, missing values in the index and the interplay of logical indexes with recycling. The second script shows them, with the real text of the one error in the group.

[source,r]
----
source("scenario.R")

days <- as.integer(loans$return_date - loans$loan_date)
names(days) <- loans$loan_id
loan_len <- days[1:8]

# Mixing positive and negative subscripts is an error; zeros are the exception
tryCatch(loan_len[c(-1, 2)], error = \(e) conditionMessage(e))
#> [1] "only 0's may be mixed with negative subscripts"
loan_len[c(-1, 0)]
#> L002 L003 L004 L005 L006 L007 L008
#>   10    1   26   26   17   24   10

# An NA subscript gives NA: the logical NA recycles to the length of x, the
# integer NA selects one element
loan_len[NA]
#> <NA> <NA> <NA> <NA> <NA> <NA> <NA> <NA>
#>   NA   NA   NA   NA   NA   NA   NA   NA
loan_len[c(1, NA)]
#> L001 <NA>
#>   21   NA
loan_len[c(1, NA_integer_)]
#> L001 <NA>
#>   21   NA
loan_len[NA_character_]
#> <NA>
#>   NA

# An NA inside a logical index selects an NA element, so a comparison on data
# that holds a missing value returns an NA entry; which() keeps only the TRUEs
with_gap <- c(a = 21L, b = NA, c = 26L)
with_gap > 21L
#>     a     b     c
#> FALSE    NA  TRUE
with_gap[with_gap > 21L]
#> <NA>    c
#>   NA   26
with_gap[which(with_gap > 21L)]
#>  c
#> 26

# warns() lets expr finish and returns the text of the warnings it gave
warns <- function(expr) {
  seen <- character()
  withCallingHandlers(
    expr,
    warning = \(w) {
      seen <<- c(seen, conditionMessage(w)) # nolint: assignment_linter.
      invokeRestart("muffleWarning")
    }
  )
  seen
}

# A short logical index is recycled, a long one extends x with NA. R 4.6.1
# gives no warning when the length of the index does not divide length(x).
loan_len[c(TRUE, FALSE)]
#> L001 L003 L005 L007
#>   21    1   26   24
loan_len[c(TRUE, FALSE, FALSE)]
#> L001 L004 L007
#>   21   26   24
warns(loan_len[c(TRUE, FALSE, FALSE)])
#> character(0)
length(loan_len[rep(TRUE, 10)])
#> [1] 10
loan_len[rep(c(TRUE, FALSE), length.out = 10)]
#> L001 L003 L005 L007 <NA>
#>   21    1   26   24   NA

# Character subscripts on a vector without names, with unknown names, with "",
# and with duplicated names
plain <- c(21L, 10L, 1L)
plain["a"]
#> [1] NA
loan_len["L99"]
#> <NA>
#>   NA
loan_len[""]
#> <NA>
#>   NA
dup <- c(x = 1, y = 2, x = 3)
dup["x"]
#> x
#> 1
dup[c("x", "x")]
#> x x
#> 1 1

# [ never uses partial matching
loan_len["L00"]
#> <NA>
#>   NA

# A factor subscript uses the integer codes, not the labels
f <- factor(c("L003", "L001"))
as.integer(f)
#> [1] 2 1
loan_len[f]
#> L002 L001
#>   10   21
loan_len[as.character(f)]
#> L003 L001
#>    1   21

=== Mixing positive and negative subscripts

`pass:c[loan_len[c(-1, 2)\]]` is an error. The message of R 4.6.1 is `+only 0's may be mixed with negative subscripts+`: zero is the single value that may be combined with negative numbers, because it selects nothing and drops nothing. Some older posts quote the wording `+can't mix positive and negative subscripts+`; this is not the text that R 4.6.1 prints, and the NEWS files do not record the change of wording, so search for the message as printed on your version. The reason for the restriction is that "everything except 1, and also the second element" has no meaning: a negative index means "all but these", and a positive one means "only these".

=== NA in the index

The index can contain `NA`, and its type decides the result. The language definition explains it with one example: `pass:c[x[NA\]]` has the length of `x`, whereas `pass:c[x[c(1, NA)\]]` has length 2, because the literal `NA` is a logical value and the rules for logical indexes apply to it, while in `c(1, NA)` it is coerced to an integer. The output above shows both:

* `pass:c[loan_len[NA\]]` recycles the logical `NA` to the length of the vector and returns eight `NA` values, all with the name `<NA>`.
* `pass:c[loan_len[c(1, NA)\]]` returns the first element and one `NA`.
* `NA_integer_` and `NA_character_` select one unknown element and return one `NA`.

The help page generalises this: when extracting, a numeric, logical or character `NA` index picks an unknown element and returns `NA` in the corresponding position of a logical, integer, numeric, complex or character result, and `NULL` for a list (and a raw zero byte for a raw vector). The practical consequence is the one that gets its own section for data frames: a comparison on data that holds a missing value produces an `NA` in the logical index, and the result of the filter holds an `NA` element for it. `pass:c[with_gap[with_gap > 21L\]]` in the script returns `NA` and `26`, while `pass:c[with_gap[which(with_gap > 21L)\]]` returns only `26`, because `which()` drops everything that is not `TRUE`. The fix for a filter on data that may have missing values is one of `which()`, `!is.na(x) & x > 21L` or `subset()`; see <<na-row-trap>>.

=== Logical indexes and recycling

A logical index is recycled to the length of the vector if it is shorter, as the manual says, and if it is longer then the vector is conceptually extended with `NA` values. The script shows the three cases: `c(TRUE, FALSE)` selects every other element, `c(TRUE, FALSE, FALSE)` selects positions 1, 4 and 7 of a vector of length eight, and a logical index of length ten applied to a vector of length eight selects two positions that do not exist, which are returned as `NA`. One more observation belongs to <<devel-warning>>: R 4.6.1 gives no warning when the length of the logical index does not divide the length of the vector. The call `pass:c[warns(loan_len[c(TRUE, FALSE, FALSE)\])]` returns `character(0)`, which means that the expression produced no warning.

=== Character indexes

A character index is matched against `names(x)`. If `x` has no names at all, every name is the empty string and nothing matches: `pass:c[plain["a"\]]` is `NA`, and the result has no name because the vector has none to carry. Four rules are worth remembering:

* the string `""` matches no element, not even those without a name (`pass:c[loan_len[""\]]` is `NA`);
* `NA_character_` also matches nothing;
* when names are duplicated, a character index returns the first element with that name, and an index of two equal strings returns that element twice (`pass:c[dup[c("x", "x")\]]` is `1 1`); the second `x` of `dup` can only be reached by position;
* partial matching is never used by `pass:c[[]`, so `pass:c[loan_len["L00"\]]` is `NA` even though `"L00"` is a prefix of every name.

The script also shows the fifth kind of index that the manual lists, a factor. A factor index is the same as `pass:c[x[as.integer(f)\]]`: the integer codes are used and the labels are never looked at. The levels of `f` are sorted, so `+f <- factor(c("L003", "L001"))+` has the codes 2 and 1, and `pass:c[loan_len[f\]]` returns the second and the first element, not the elements called `L003` and `L001`. The result is wrong and nothing says so. If the labels are meant, convert them: `pass:c[loan_len[as.character(f)\]]`. This trap was more common when `read.csv()` and `data.frame()` made factors from strings by default; since R 4.0.0 the default of `stringsAsFactors` is `FALSE` and a character column is indexed by its values (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.0.0]). The xref:programming-languages/r/factors.adoc[Factors] page has the details on the factors themselves.

=== Attributes

`pass:c[[]` keeps `names` (and `dim` and `dimnames` for arrays) and drops all other attributes; the help page says that this holds for every subsetting except the one with an empty index. Classes that have their own method keep more, as the next script shows: `Date` and `factor` keep their class and `factor` also keeps all its levels, including those that no selected element uses.

[source,r]
----
source("scenario.R")

msg <- \(expr) tryCatch(expr, error = \(e) conditionMessage(e))

# [ keeps names, dim and dimnames; other attributes are dropped ...
x <- structure(c(a = 1, b = 2, c = 3), unit = "days", note = "demo")
attributes(x)
#> $names
#> [1] "a" "b" "c"
#>
#> $unit
#> [1] "days"
#>
#> $note
#> [1] "demo"
#>
attributes(x[1:2])
#> $names
#> [1] "a" "b"
#>

# ... except where a class has its own method, as Date and factor do
d <- as.Date("2026-06-30") + 0:2
class(d[1:2])
#> [1] "Date"
f <- factor(c("fiction", "poetry", "fiction"))
f[2:3]
#> [1] poetry  fiction
#> Levels: fiction poetry
class(f[2:3])
#> [1] "factor"
levels(f[2])
#> [1] "fiction" "poetry"

# An empty index keeps everything, so x[] <- v changes values and keeps the
# attributes, while x <- v does not
x[] <- 0
attributes(x)
#> $names
#> [1] "a" "b" "c"
#>
#> $unit
#> [1] "days"
#>
#> $note
#> [1] "demo"
#>

# Subscripts of an unsuitable type
msg(x[list(1)])
#> [1] "invalid subscript type 'list'"
msg(x[mean])
#> [1] "invalid subscript type 'closure'"
msg((1:3)[[list(1)]])
#> [1] "invalid subscript type 'list'"
msg(list(1, 2)[[mean]])
#> [1] "invalid subscript type 'closure'"

# Too many or too few subscripts
msg((1:3)[1, 2])
#> [1] "incorrect number of dimensions"
msg((1:3)[[1, 2]])
#> [1] "incorrect number of subscripts"
msg(matrix(1:4, 2)[[1, 2, 3]])
#> [1] "incorrect number of subscripts"
msg(matrix(1:4, 2)[3, 1])
#> [1] "subscript out of bounds"

# Rows beyond the end of a data frame give NA rows with made-up names
books[c(15, 17, 18), c("title", "year")]
#>            title year
#> 15   Ten Winters 2022
#> NA          <NA>   NA
#> NA.1        <NA>   NA
msg(books[, 7])
#> [1] "undefined columns selected"

The first two statements show the rule, the next four the exceptions and the empty index: `pass:c[x[\] <- 0]` changes the values and keeps the `unit` and `note` attributes, while `+x <- 0+` would replace the object. The error messages in the second half belong to the table at the end of the page.

[[subset-double]]
== Single bracket versus double bracket

`pass:c[[[]` selects one element and drops the container. On an atomic vector it also drops the names, which is one of the small semantic differences that the language definition mentions for vectors and matrices: `pass:c[[[]` drops any `names` or `dimnames` attribute, and it can use partial matching of character indexes when `exact = FALSE`. On a list it is the form that you use to take out one element, whereas `pass:c[[]` returns a list of the selected elements.

[source,r]
----
source("scenario.R")

The script shows the contrast and the messages of the errors:

* `pass:c[loan_len[2\]]` and `pass:c[loan_len["L002"\]]` return a named vector, `pass:c[loan_len[[2\]\]]` and `pass:c[loan_len[["L002"\]\]]` return the bare value 10.
* `pass:c[[[]` requires exactly one element. A vector of length two gives `+attempt to select more than one element in vectorIndex+`; a zero, `NULL` or a missing index gives `+attempt to select less than one element in get1index <real>+`, the same text without `<real>` for `NULL`, or `+missing subscript+` for `pass:c[x[[\]\]]`. R 4.3.0 turned `pass:c[c(a = 1, 2)[[\]\]]` from "matches the second element" into a classed error and made `pass:c[NULL[[\]\]]` an error too (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.3.0]); the help page says that `pass:c[x[[\]\]]` is always an error.
* **Out of bounds**. `pass:c[loan_len[10\]]` is `NA`, `pass:c[loan_len[[10\]\]]` is the error `+subscript out of bounds+`, and so is an unknown name (`pass:c[loan_len[["L99"\]\]]`), an `NA` index on an atomic vector and an infinite one (`pass:c[loan_len[[Inf\]\]]`). R 4.0.0 removed the undefined behaviour of `pass:c[x[[Inf\]\]]` (which is `NULL` for a list) and made `pass:c[x[[-Inf\]\]]` and `pass:c[x[[-n\]\]]` give more helpful messages (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.0.0]).
* **Negative numbers** are allowed in `pass:c[[[]` only when exactly one element is left. `pass:c[(1:2)[[-1\]\]]` is 2, while `pass:c[loan_len[[-1\]\]]` is `+invalid negative subscript in get1index <real>+`.
* The error of an out-of-bounds subscript has the class `subscriptOutOfBoundsError` and the error for an object that cannot be subset has the class `notSubsettableError`, with the object in the `object` field of the condition. R 4.2.0 introduced both classes, so that a handler can tell them from other errors without matching the text. For `pass:c[mean[1\]]`, the message is `+object of type 'closure' is not subsettable+`. The `subscript` field of the error is `NA` for the vector case in R 4.6.1 and the `index` field holds the erroneous index, while the help page says that `subscript` is zero for vector subscripting; use `index` and `object` and treat `subscript` with care.

For lists the rules for missing things are different from the ones for atomic vectors, and this is a very common source of silent errors: a name that does not exist gives `NULL` with `pass:c[[[]` and `$` on a list, an error with `pass:c[[[]` on an atomic vector, and `NA` with `pass:c[[]`. The help page says that attempting to extract a non-existent element by name returns `NULL`, and an out-of-bounds position on a list is an error (`pass:c[reading_list[[4\]\]]` below).

[[dollar]]
== The dollar operator and partial matching

`$` is the operator of records: `book$title` is the title of a book of the scenario. It is documented for lists, for pairlists and for `NULL`, and for environments; the language definition adds that the index is not computable (when the index has to be computed, use `pass:c[x[[expr\]\]]`) and that applying `$` to a non-recursive object is an error. The help page defines it by its equivalent: `x$name` is equivalent to `pass:c[x[["name", exact = FALSE\]\]]`.

What the output shows:

* A unique prefix is accepted. `dune$tit` is the title and `dune$p` is the number of pages, because only `pages` begins with `p`. Nothing warns by default. When several names have the prefix, as `pages` and `pagesize` have `pa`, the match fails and the result is `NULL`: an ambiguous prefix is not an error either.
* `pass:c[[[]` does not match partially by default. The usage of the help page is `pass:c[x[[i, exact = TRUE\]\]]` and the behaviour of R 4.6.1 agrees: `pass:c[shelf_entry[["pagesi"\]\]]` is `NULL`. The argument `exact` has three values: `TRUE` (no partial matching, the default), `NA` (partial matching with a warning) and `FALSE` (partial matching without warning). The warning has the text `+partial match of 'pagesi' to 'pagesize'+`. The language definition says in its section on indexing by vectors that the default of `exact` is `NA`; that sentence is out of date, the help page and the behaviour are the reference.
* `options(warnPartialMatchDollar = TRUE)` makes `$` warn with the same text whenever it matches a prefix. The option is `FALSE` unless you set it (the options page describes it as a logical switch that warns when partial matching is used for extraction by `$`). The warning for data frames was given by default in R versions before 3.1.1, whose NEWS says it is now only given when this option is `TRUE`. A package that wants to be sure that no code relies on a partial match can turn the option on in its tests (see xref:programming-languages/r/testing-with-testthat.adoc[Testing with testthat]); the help page example uses it to check `li$p`.
* `pass:c[[]` never matches partially, for any object: `pass:c[shelf_entry["pagesi"\]]` is a list with one `NULL` element named `<NA>`.
* `$` cannot be computed. `dune$field` looks for an element called `"field"` (and returns `NULL`), whereas `pass:c[dune[[field\]\]]` uses the value of the variable. `dune$"title"` works because a string is allowed as the name.
* `$` on an atomic vector is an error with the text `+$ operator is invalid for atomic vectors+`, and `$` on `NULL` returns `NULL`. The error is the usual sign of a vector that should have been a list or data frame, for example a column of a data frame (a vector) on which `$` was used again.
* `getElement(x, name)` is `pass:c[x[[name, exact = TRUE\]\]]`, and for S4 objects it reads the slot, so it works on both kinds of object.
* For **environments**, `$` and `pass:c[[[]` take a character name and do an exact lookup with `get(i, envir = x, inherits = FALSE)`; they return `NULL` when there is no match, and no partial matching is done. `shelf_env$op` is `NULL` although `shelf_env$open` exists. The replacement forms create or change a binding (see xref:programming-languages/r/scoping-environments-and-closures.adoc[Scoping, Environments and Closures]).

The advice that follows from the rules is to use the full names with `$`, to use `pass:c[[[]` with a variable holding a name, and to remember that partial matching exists when a result that should have been a vector is `NULL`.

=== The at operator for S4 slots

`@` is the fourth extraction operator and applies to S4 objects only, where it reads a slot (https://search.r-project.org/R/refmans/base/html/slotOp.html[R documentation: slotOp]). It is the S4 counterpart of `$`: `x@name` reads the slot `name`, `+x@name <- value+` replaces it after checking the class of the value, and `slot(x, "name")` is the function form that accepts a computed name. The next script defines a small S4 class and shows the three error messages. The full treatment of S4 is on xref:programming-languages/r/s4-classes-and-methods.adoc[S4 Classes and Methods].

[[matrices]]
== Matrices and arrays

A matrix is a vector with a `dim` attribute and an array is the same with more dimensions, so every kind of vector indexing works with a single index, and there are three more forms for several: one index per dimension, an index matrix, and (as a special case) the logical matrix. The rules for a matrix `pass:c[m[i, j\]]` are those for a vector applied to each dimension, with `dimnames` taking the place of `names` (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing-matrices-and-arrays[The R Language Definition: Indexing matrices and arrays]; https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Array-indexing[An Introduction to R: Array indexing. Subsections of an array]).

The examples use a matrix made from the shelf: the page counts of the first twelve books laid out as three shelves (A, B, C) of four slots each. Book 6 (`A Map of Salt`) has no page count in the scenario, so one cell is `NA`. The `dimnames` are named (`shelf` and `slot`), which is what makes the header lines of the printed matrices.

* With **two indexes**, `pass:c[m[i, j\]]`, each one is a vector index of any of the kinds above (positive, negative, logical or character, matched against the `dimnames`), and an empty index (`pass:c[m[2, \]]`, `pass:c[m[, "s2"\]]`) selects the whole extent of that dimension. A comma is what separates a matrix from a vector: `pass:c[m[1, \]]` is the first row, `pass:c[m[1\]]` is the first value.
* With **one index**, the `dim` and `dimnames` are ignored and the matrix is the vector of its values in column-major order and the result is that of `pass:c[c(m)[i\]]`; the manual warns that `pass:c[m[1\]]` is usually very different from `pass:c[m[1, \]]` or `pass:c[m[, 1\]]`. `pass:c[pages_grid[5\]]` is the fifth value, counted down the columns, which is the `NA` of book 6; `pass:c[pages_grid["A"\]]` is `NA` because a one-index character is matched against `names`, and a matrix has none.
* **Out of bounds** on a matrix is an error even for `pass:c[[]`: `pass:c[pages_grid[4, 1\]]` and `pass:c[pages_grid[, "s9"\]]` are `+subscript out of bounds+`, and the wrong number of indices is `+incorrect number of dimensions+`. A vector, in contrast, pads with `NA`.
* The result of selecting a single row or column has no dimensions: it is a vector (`pass:c[class(pages_grid[1, \])]` is `"integer"`, `+dim(...)+` is `NULL`), and it keeps the names that come from the other dimension. This is the subject of the next section.

=== Why do my matrices lose dimensions: drop = FALSE

When a subscripting operation leaves a dimension of length one, R removes it by default: `pass:c[row <- mat[2, \]]` is a vector, and an array of dimensions 2 x 3 x 1 x 4 becomes 2 x 3 x 4. The R FAQ says that the behaviour was kept after much discussion as a feature, and advises using `drop = FALSE` defensively when programming (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-do-my-matrices-lose-dimensions_003f[R FAQ 7.5: Why do my matrices lose dimensions?]). The argument is an additional argument to `pass:c[[]`, it does not count as an index (the manual: `pass:c[m[1, , drop = FALSE\]]` is the first row as a 1 by n matrix) and it must be named. The same applies to a one-dimensional array: any subsetting gives a vector unless `drop = FALSE` is used.

The trap is in code that works for the usual size of the input and fails on the edge. The next script defines a helper that selects the rows asked for, and calls it with two shelves and with one.

Source: https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-do-my-matrices-lose-dimensions_003f[R FAQ 7.5: Why do my matrices lose dimensions?]

`dim(rows_for(pages_grid, "A"))` is `NULL`: the result is a vector and anything downstream that expects a matrix (`nrow()`, `apply()` over the rows, `+%*%+`) fails or does something else. The second definition, with `, drop = FALSE`, returns a 1 x 4 matrix for one shelf and a 2 x 4 matrix for two, which is the type that the rest of the function can rely on. The same defence applies to data frames (see <<data-frames-subsetting>>), where the default for a single column is also to drop.

=== Index matrices, logical matrices and the triangles

A third form of indexing a matrix uses a matrix as the single index: a matrix with one column per dimension of `x`, where each row selects one element and the result is a vector of the length of the number of rows (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Index-matrices[An Introduction to R: Index matrices]). `+pick <- cbind(c(1, 2, 3), c(4, 3, 1))+` selects `pass:c[[1, 4\]]`, `pass:c[[2, 3\]]` and `pass:c[[3, 1\]]`, the elements that are on a diagonal of the layout, in one operation.

The rules, from the help page and the manual:

* the index matrix has one column per dimension and one row per element wanted;
* negative values are not allowed (`+negative values are not allowed in a matrix subscript+`);
* rows with a zero are ignored and rows with `NA` give `NA` (`pass:c[pages_grid[rbind(c(1, 1), c(0, 0), c(NA, 2))\]]` has two elements: the value at `pass:c[[1, 1\]]` and `NA`);
* a **character matrix** with one column per dimension is matched against the `dimnames` when the array has them; each row selects one element, `NA` gives `NA`, and an unmatched value or the empty string `""` is an error (`+subscript out of bounds+`). R 4.1.3 changed the case of an array without `dimnames`, where a character matrix of the right shape used to return meaningless results and is now an error;
* assignment works the same way: `pass:c[capped[long_ones\] <- 380L]` replaces the elements at the listed positions, which is the second use in the manual's example.

An Introduction to R says that an index matrix must be numeric and that any other form of matrix, such as a logical or a character one, is treated as an indexing vector. For logical matrices that is still right and it is the next case; for character matrices the help page of `pass:c[[]` documents the matching against the dimnames that the script shows, so the sentence of the introduction is older than the help page.

A **logical matrix** of the same shape as `x` is a vector of the same length when used as a single index: `pass:c[pages_grid[pages_grid > 300\]]` returns the values for which the comparison is `TRUE`, as a vector in column order, and the cell with `NA` is returned as `NA` because the logical index is `NA` there. `which(pages_grid > 300)` drops it. The comparison keeps the `dim` and `dimnames` of the matrix, so `pages_grid > 300` prints as a matrix with the shelf and slot labels.

`which(x, arr.ind = TRUE)` goes the other way, from a condition to an index matrix: the result is a matrix with one row per element, the row names are taken from the first dimension names, and its column names come from `names(dimnames(x))` when they exist (`shelf` and `slot` above, and `row` and `col` otherwise). It can be fed back as an index, which is what `pass:c[pages_grid[long_ones\]]` does. `arrayInd()` is the function that converts positions to an index matrix for a given `dim`.

`upper.tri()` and `lower.tri()` return logical matrices that mark the elements above or below the diagonal (with `diag = TRUE` they include it), so `pass:c[sq[upper.tri(sq)\]]` extracts the upper triangle as a vector, in column order. `diag(sq)` is the diagonal. `row(sq)` and `col(sq)` return the row and the column number of each element as matrices of the same shape, and a condition on them, such as `pass:c[row(sq) == col(sq) + 1]`, selects the sub-diagonal or any other band (https://search.r-project.org/R/refmans/base/html/lower.tri.html[R documentation: lower.tri]; https://search.r-project.org/R/refmans/base/html/row.html[R documentation: row]).

Subsetting a data frame with a logical or two-column integer matrix is possible, but the help page of `pass:c[[.data.frame]` advises against it: the data frame is first coerced to a matrix, so every column takes the type of the common one. The data frame section shows the replacement form that is useful.

=== Arrays

An array has one index per dimension; an empty index keeps the whole extent, and the rules of drop apply to each dimension that is left with length one. The array in the next script holds the copy numbers 1 to 24 of the books, in three shelves, four slots and two rooms, so the value of an element tells you where it is: R stores the first dimension fastest, so the copy number is `pass:c[shelf + 3 * (slot - 1) + 12 * (room - 1)]`.

[source,r]
----
# Copy numbers 1 to 24 stored in a 3 x 4 x 2 array: 3 shelves, 4 slots per
# shelf and 2 rooms. R fills the first dimension fastest, so copy number
# k = shelf + 3 * (slot - 1) + 12 * (room - 1).
msg <- \(expr) tryCatch(expr, error = \(e) conditionMessage(e))

copies <- array(
  1:24,
  dim = c(3, 4, 2),
  dimnames = list(
    shelf = c("A", "B", "C"),
    slot = c("s1", "s2", "s3", "s4"),
    room = c("main", "annex")
  )
)
dim(copies)
#> [1] 3 4 2

# One index per dimension; an empty index keeps the whole dimension
copies[2, 3, 1]
#> [1] 8
copies[, , 1]
#>      slot
#> shelf s1 s2 s3 s4
#>     A  1  4  7 10
#>     B  2  5  8 11
#>     C  3  6  9 12
copies["A", , ]
#>     room
#> slot main annex
#>   s1    1    13
#>   s2    4    16
#>   s3    7    19
#>   s4   10    22
copies[, "s2", "annex"]
#>  A  B  C
#> 16 17 18

# Slices lose the dimensions of length one; drop = FALSE keeps them
dim(copies[, , 1])
#> [1] 3 4
dim(copies[, , 1, drop = FALSE])
#> [1] 3 4 1
dim(copies[1, , , drop = FALSE])
#> [1] 1 4 2
dim(copies[1, 1, , drop = FALSE])
#> [1] 1 1 2

# Fewer indices than dimensions is an error; a single index works on the
# data vector and ignores the dimensions
msg(copies[1, 2])
#> [1] "incorrect number of dimensions"
copies[10]
#> [1] 10
copies[c(TRUE, FALSE, FALSE, FALSE)]
#> [1]  1  5  9 13 17 21

# slice.index() gives the position along one dimension, as row() and col() do
copies[slice.index(copies, 3) == 2][1:4]
#> [1] 13 14 15 16
sum(copies[, , "annex"])
#> [1] 222

# Index matrices work in any number of dimensions: one column per dimension
copies[rbind(c(1, 1, 1), c(3, 4, 2))]
#> [1]  1 24
which(copies > 21, arr.ind = TRUE)
#>   shelf slot room
#> A     1    4    2
#> B     2    4    2
#> C     3    4    2
----

Source: https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Array-indexing[An Introduction to R: Array indexing. Subsections of an array]

* `pass:c[copies[, , 1\]]` is a 3 x 4 matrix, the slice for the main room; `pass:c[copies["A", , \]]` is a 4 x 2 matrix with the slots as rows and the rooms as columns; `pass:c[copies[, "s2", "annex"\]]` is a vector of length three. The manual's example is `pass:c[a[2, , \]]`, which gives a 4 x 2 array.
* `drop = FALSE` keeps the extents of length one: `pass:c[dim(copies[, , 1, drop = FALSE\])]` is `3 4 1`, `pass:c[dim(copies[1, 1, , drop = FALSE\])]` is `1 1 2`.
* A wrong number of indices is an error (`pass:c[copies[1, 2\]]` for three dimensions gives `+incorrect number of dimensions+`), but a **single** index ignores the dimensions and uses the data vector: `pass:c[copies[10\]]` is 10 and `pass:c[copies[c(TRUE, FALSE, FALSE, FALSE)\]]` selects every fourth value.
* `slice.index(x, margin)` gives, for each element, its index along dimension `margin`, so `pass:c[copies[slice.index(copies, 3) == 2\]]` selects the second room, the same as `pass:c[copies[, , 2\]]` but as a vector and for any dimension.
* An index matrix has one column per dimension: `pass:c[copies[rbind(c(1, 1, 1), c(3, 4, 2))\]]` selects the first and the last copy, and `which(copies > 21, arr.ind = TRUE)` lists the three positions with the largest numbers, with the dimension names as column names.

Matrices and higher-dimensional arrays are covered in xref:programming-languages/r/matrices-and-arrays.adoc[Matrices and Arrays]; one thing from the R 4.6.0 NEWS belongs here: subassignment to a one-dimensional array with a name as the index (`pass:c[x["a"\] <- v]`) no longer drops the array to a plain vector (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.6.0]).

== Lists

A list is a vector whose elements can be anything, so subsetting it raises the question that atomic vectors do not: do you want a list back or the thing inside? The manual puts the rule in one sentence: for lists one generally uses `pass:c[[[]` to select any single element, whereas `pass:c[[]` returns a list of the selected elements (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing[The R Language Definition: Indexing]; https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Lists[An Introduction to R: Lists]). The script below uses a list of three `book` objects of the scenario, which is a list of lists, so every kind of nesting shows up.

[source,r]
----
source("scenario.R")

# A reading list: a list of three book objects

  dispossessed = book("The Dispossessed", "Ursula K. Le Guin", year = 1974),
  pride = book("Pride and Prejudice", "Jane Austen", year = 1813),

)
length(reading_list)
#> [1] 3
names(reading_list)
#> [1] "dispossessed" "pride"        "roofs"

# [ returns a list, [[ returns the element itself
class(reading_list[1])
#> [1] "list"
class(reading_list[[1]])
#> [1] "book"
reading_list[["pride"]]$title
#> [1] "Pride and Prejudice"
reading_list$pride$year
#> [1] 1813
reading_list[c("pride", "roofs")]
#> $pride
#> <book> Pride and Prejudice (Jane Austen, 1813)
#>
#> $roofs
#> <book> Loud Roofs (Mara Quill, 2021)
#>

reading_list[["pride"]][["year"]]
#> [1] 1813
reading_list[[c("pride", "year")]]
#> [1] 1813
reading_list[[c(2, 4)]]
#> [1] 1813
msg(reading_list[[c("pride", "isbn", "x")]])
#> [1] "subscript out of bounds"

# Negative and logical subscripts select lists the same way as vectors
names(reading_list[-1])

#> dispossessed        pride        roofs
#>         1974         1813         2021
names(reading_list[years > 1900])
#> [1] "dispossessed" "roofs"

# Out of bounds on a list
reading_list[4]
#> $<NA>
#> NULL

#> [1] "subscript out of bounds"
reading_list[["missing"]]
#> NULL

#> NULL
reading_list[["pr"]]
#> NULL

#> [1] "Pride and Prejudice"

Source: https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing[The R Language Definition: Indexing]

* `pass:c[reading_list[1\]]` is a list of length one (`class()` is `"list"`), `pass:c[reading_list[[1\]\]]` is the book (`class()` is `"book"`). Because `pass:c[[]` returns a list, the printing of `pass:c[reading_list[c("pride", "roofs")\]]` goes through the `print.book` method once per element, with the names as `$pride` and `$roofs`.
* A chain `pass:c[reading_list[["pride"\]\][["year"\]\]]` or `reading_list$pride$year` goes down one level at a time. A vector index in `pass:c[[[]` does the same: `pass:c[reading_list[[c("pride", "year")\]\]]` is `pass:c[reading_list[["pride"\]\][["year"\]\]]`, and `pass:c[reading_list[[c(2, 4)\]\]]` is the fourth field of the second book, its year. The help page says that `pass:c[alist[[i\]\]]` with a vector `i` of length `p` is equivalent to `pass:c[alist[[i1\]\]...[[ip\]\]]`, provided that all but the last indexing give a list. A wrong step is an error: `pass:c[reading_list[[c("pride", "isbn", "x")\]\]]` tries to use `pass:c[[["x"\]\]]` on a character string and gives `+subscript out of bounds+`.
* Negative and logical indexes select lists exactly as they select vectors, because a list is a vector. `pass:c[reading_list[years > 1900\]]`, with the logical vector made by `vapply()`, keeps two books.
* **Out of bounds.** `pass:c[reading_list[4\]]` is a list with one `NULL` element with the name `<NA>`, `pass:c[reading_list[[4\]\]]` is an error, and `pass:c[reading_list[["missing"\]\]]` and `reading_list$missing` are `NULL`. `NULL` is a valid value for an element of a list, so a `NULL` result does not tell you whether the element is missing or holds `NULL`; use `"missing" %in% names(reading_list)` or `is.null()` on `pass:c[[[]` for that. The partial matching rules are those of the previous section: `reading_list$pr$title` works through `$`, `pass:c[reading_list[["pr"\]\]]` is `NULL`.
* `pass:c[[]` keeps `names` and drops every other attribute: after `+attr(reading_list, "owner") <- "reading room"+`, `pass:c[attributes(reading_list[1:2\])]` has only the `names`.

A list that has a class, like each `book`, can have `pass:c[[]` and `pass:c[[[]` methods of its own. The `book` class of the scenario does not define any, so the default methods run and `pass:c[book[1\]]` is a plain list without the class. Defining `pass:c[[.book]` is the way to make a subset keep the class, and `NextMethod()` is the tool for it; see xref:programming-languages/r/s3-classes-and-generics.adoc[S3 Classes and Generics].

== Data frames

A data frame is a list of equal-length columns with a class and row names, and `pass:c[[.data.frame]` is the method that gives it two modes of indexing. The help page of `pass:c[[.data.frame]` describes both. With a single index (`pass:c[x[i\]]` or `pass:c[x[[i\]\]]`) it is indexed as a list of columns; with two indexes (`pass:c[x[i, j\]]`) it is indexed like a matrix. The method is documented on https://search.r-project.org/R/refmans/base/html/Extract.data.frame.html[R documentation: Extract.data.frame], and the language definition describes it in a paragraph as well (https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Indexing-other-structures[The R Language Definition: Indexing other structures]).

* **drop.** The default of the data frame method is to drop to a vector when only one column is left, but not to drop when only one row is left. The warning section of the help page says that the default behaviour when only one row is left is equivalent to `drop = FALSE`, and that dropping from a data frame to a list needs `drop = TRUE` to be explicit. This is the same defensive argument as for matrices (R FAQ 7.5) and with the same reason: `pass:c[df[, cols\]]` returns a data frame when `cols` has two names and a vector when it has one, so any helper that takes the columns as an argument should use `pass:c[df[, cols, drop = FALSE\]]` or the list form `pass:c[df[cols\]]`.
* The one-index form ignores `drop`, with a warning, because the list form never drops: `pass:c[books["year", drop = TRUE\]]` gives `+'drop' argument will be ignored+`. The language definition says the same.
* **Unknown columns.** `pass:c[books[, "publisher"\]]` and `pass:c[books["publisher"\]]` are errors with the text `+undefined columns selected+`; `pass:c[books[["publisher"\]\]]` and `books$publisher` are `NULL`. This is a difference that makes a typo in `df$name` silent and a typo in `pass:c[df[, "name"\]]` loud.
* **Partial matching.** There is no `$` method for data frames, so `books$yea` uses the default method for lists and matches the column `year` (and returns it, silently unless `warnPartialMatchDollar` is `TRUE`). `pass:c[[[]` and `pass:c[[]` do not match column names partially, with the same `exact` argument as for lists (the `exact = NA` call shows the warning `+partial match of 'yea' to 'year'+`). **Row names** are different: both `pass:c[[]` and `pass:c[[[]` extraction methods match row names partially, as the next script shows.
* A selection of rows or columns that keeps a data frame gives the result unique row names and column names, by `make.unique()`, so `pass:c[books[c(1, 1, 2), \]]` has row names `1`, `1.1` and `2`.

[[na-row-trap]]
=== Rows by condition and the NA-row trap

The most common way of using `pass:c[[]` on a data frame is a logical vector for the rows: `pass:c[df[df$year > 2000, \]]`. It has one trap that follows from the rule for `NA` in an index. When the condition is `NA` for a row, the row is selected as a row of `NA` values, and its row name is `NA`. No error and no warning says so. In the scenario, `books$year` has one missing value, the year of "Garden of Small Fires", so `books$year > 2020` has one `NA` and the filtered result has four rows where three books were published after 2020. The same happens in the loans: a loan with no return date has no number of days.

[source,r]
----
source("scenario.R")

msg <- \(expr) tryCatch(expr, error = \(e) conditionMessage(e))

books$year > 2020
#>  [1] FALSE FALSE FALSE  TRUE FALSE FALSE    NA FALSE FALSE  TRUE FALSE FALSE
#> [13] FALSE FALSE  TRUE FALSE
sum(is.na(books$year))
#> [1] 1

# The NA row trap: the NA in the logical index selects a row of NAs
recent <- books[books$year > 2020, c("title", "year")]
recent
#>             title year
#> 4      Loud Roofs 2021
#> NA           <NA>   NA
#> 10 THE LONG TABLE 2023
#> 15    Ten Winters 2022
nrow(recent)
#> [1] 4

# Three ways to keep only the rows that are TRUE
books[which(books$year > 2020), c("title", "year")]
#>             title year
#> 4      Loud Roofs 2021

* `recent` has a row named `NA` with `NA` in every column. Three fixes select only the rows that are `TRUE`: `which()` (which drops `NA` as not `TRUE`), an explicit test `!is.na(books$year) & books$year > 2020`, and `subset()`, which the help page documents as treating missing values in the condition as false.
* **Overdue loans.** A returned loan is overdue when it was out for more than `loan_days` days; a loan that has not been returned is overdue when it has been out that long at `shelf_today`. `returned_days` is a `difftime`, and `returned_days > loan_days` compares days with the number 21. The two rules each have missing values: an unreturned loan has no return date and one loan has the impossible date `2025-02-30`, which was read as `NA`. The script therefore protects each rule with `!is.na()`, and counts 25 overdue returned loans and 7 overdue unreturned ones, 32 in total. The naive filter `pass:c[loans[returned_days > loan_days, \]]` has 33 rows, 25 real ones and 8 rows of `NA` (the 7 unreturned loans and the loan with the impossible date), with row names `NA`, `NA.1`, `NA.2` and so on, because row names have to be unique.
* **The `-which()` trap.** Dropping the rows that match a condition as `pass:c[loans[-which(cond), \]]` fails when no row matches: `which()` returns `integer(0)`, `-integer(0)` is `integer(0)`, and an empty positive index selects nothing, so the result has no rows at all instead of all of them. Write the negation in the condition (`pass:c[loans[!cond, \]]`, with the `NA` handled) instead of in the index.

The rule is general: every comparison that has an `NA` in its data has an `NA` in its result, and `pass:c[[]` turns an `NA` in a logical index into an `NA` element or row. Missing values are covered in xref:programming-languages/r/missing-and-special-values.adoc[Missing and Special Values].

* `which(x)` returns the positions of the `TRUE` values of a logical vector, with the names of `x`; `NA` is treated as `FALSE`. The help page says that `which(x)` is `pass:c[seq_along(x)[!is.na(x) & x\]]`. It only accepts a logical argument: `which(c(1, 0, 1))` gives `+argument to 'which' is not logical+`. When nothing is `TRUE` the result is an integer vector of length zero, with the names attribute (`named integer(0)`) when `x` has names.
* `which.max(x)` and `which.min(x)` return the position of the first maximum or minimum, with its name, and ignore `NA`. `which.max(c(NA, 3, 3))` is 2, the first of two ties, and an all-`NA` argument gives `integer(0)`. Use `which(x == max(x))` for all of the ties (https://search.r-project.org/R/refmans/base/html/which.min.html[R documentation: which.min]).
* `which(x, arr.ind = TRUE)` on an array returns the matrix of indices, and `arrayInd(ind, .dim)` converts positions for a given shape. `arr.ind` must be a single `TRUE`; R 4.1.3 made `which()` check this instead of coercing the argument to logical and taking its first element (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.1.3]). For a matrix without `dimnames` the columns of the result are called `row` and `col`.
* `head(x, n)` and `tail(x, n)` return the first or last `n` elements, or rows of a data frame or matrix. A negative `n` means all but the last `abs(n)` elements for `head()` and all but the first `abs(n)` elements for `tail()`: `head(first_ten, -7)` is the first three and `tail(first_ten, -7)` is the last three. A value of `n` larger than the length returns everything and `0` returns an empty object of the same type. For matrices and data frames `tail()` labels the rows with their original numbers (`keepnums = TRUE`), for vectors it does not; `keepnums = FALSE` removes the labels. The arguments are documented on https://search.r-project.org/R/refmans/utils/html/head.html[R documentation: head]; R 4.0.0 extended `head()` and `tail()` to arrays with a vector `n`, which replaced the argument `addrownums` with `keepnums` (the old argument is deprecated), and R 4.3.0 made them signal an error if `n` is not numeric (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.0.0 and 4.3.0]).
* `match(x, table)` returns for each element of `x` the position of its first match in `table`, or `NA`. `x %in% table` is the logical version, `match(x, table, nomatch = 0) > 0`, and it never returns `NA`. `pass:c[first_ten[match(ids, names(first_ten))\]]` selects by a vector of ids, with an `NA` for the id that is not there, which is the lookup of a join in base R: `pass:c[books$title[match(loans$isbn, isbn)\]]` gives the title of every loan, and `nomatch = 0L` turns the one unmatched ISBN (the loan with the 12-digit ISBN) into a zero that can be tested. For one search value, the help page says `match(a, x)` is `min(which(x == a))` but much more efficient (https://search.r-project.org/R/refmans/base/html/match.html[R documentation: match]).

The advice is to use `which()` when the result will be an index, in a loop that needs the positions, or when `NA` must be excluded, and to use the logical vector itself when a filter feeds `sum()` or `mean()` of the `TRUE` values or when the `NA` values are meant to be carried.

== Sub-assignment

An index on the left of an assignment changes part of an object. The help page names it subassignment: the part of `x` that is indexed is set to the value of the right-hand side, no partial matching of character indexes is done, and the left-hand side is coerced as needed to accept the values. The form is `pass:c[x[i\] <- value]`, `pass:c[x[i, j\] <- value]`, `pass:c[x[[i\]\] <- value]` and `+x$name <- value+` (https://search.r-project.org/R/refmans/base/html/Extract.html[R documentation: Extract]; https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Subset-assignment[The R Language Definition: Subset assignment]). The result is a new value that is bound to the name: R evaluates a call to the replacement function and rebinds the variable, and it avoids the copy when no other name refers to the vector, a mechanism described in xref:programming-languages/r/assignment-names-and-values.adoc[Assignment, Names and Values].

* **Recycling.** The value is recycled to the length of the selection: `pass:c[x[1:4\] <- 0L]` assigns four zeros. When its length does not divide the number of replaced items, the assignment is still done and R warns with `+number of items to replace is not a multiple of replacement length+`: `pass:c[y[1:4\] <- 1:3]` gives 1, 2, 3, 1. The `warns()` helper shows the warning and lets the assignment run, which a plain `+tryCatch(warning = ...)+` would not do, because the handler leaves the expression before the assignment completes.
* **Extension.** An index beyond the end extends the vector and pads the gap with `NA`: `pass:c[z[6\] <- 99L]` on a vector of length three gives six elements, and a new name extends it too (`pass:c[z["new"\] <- 5L]`). The padded elements have the empty name `""`.
* **A value of length zero.** `pass:c[z[1:2\] <- integer(0)]` is the error `+replacement has length zero+`. If the index also selects nothing (`pass:c[z[integer(0)\] <- integer(0)]`, `pass:c[z[0\] <- 1L]`), nothing happens and there is no error.
* **Type change.** The vector takes the higher of the types of `x` and `value` in the hierarchy raw, logical, integer, double, complex, character, list, expression. Assigning `2.5` to an integer vector makes it double, and assigning a string turns everything into character (`"7"`, `"2.5"`, `"late"`), with `NA` staying `NA`. Attributes are kept, and `names`, `dim` and `dimnames` are adjusted.
* **NA in the index.** When replacing, an `NA` index selects nothing. As there is ambiguity about whether the corresponding element of the value should be used, an `NA` in the index is only allowed if the value has length one: `pass:c[w[c(1, NA)\] <- 10]` changes the first element, and `pass:c[w[c(1, NA)\] <- c(8, 9)]` is the error `+NAs are not allowed in subscripted assignments+`. A logical `NA` index (`pass:c[w[NA\] <- 0]`) changes nothing. The help page records the history: S documented that an `NA` index selects nowhere but still uses up an element of the value, and R has not done that.
* **Negative and zero indexes** work as for extraction (`pass:c[w[-1\] <- 0]` assigns to all but the first).
* **Order.** Subassignment is done sequentially, so if an index is repeated the last value wins: `pass:c[u[c(1, 1, 2)\] <- c(10, 20, 30)]` leaves `20` and `30`.
* **The empty index.** `pass:c[v[\] <- 0]` replaces every value and keeps all attributes, while `+v <- 0+` replaces the object, which now has no names. The empty index is what to use to reset the values of an object while preserving its shape.
* In a function, a replacement such as `pass:c[names(x)[2\] <- "b"]` or `pass:c[x[i\] <- v]` is applied to a local copy, unless the function uses `+<<-+` (see xref:programming-languages/r/functions.adoc[Functions]).

=== Lists: NULL deletes, list(NULL) stores

For lists the replacement has one rule with a very common consequence: a value of `NULL` deletes the corresponding element. The help page says that this is so in all three kinds of replacement (`pass:c[[<-]`, `pass:c[[[<-]` and `+$<-+`), and that to set entries to `NULL` you need `pass:c[x[i\] <- list(NULL)]`. The R FAQ has it as entry 7.1: use `pass:c[x[i\] <- list(NULL)]` to set component `i` of the list `x` to `NULL`, and do not set `pass:c[x[i\]]` or `pass:c[x[[i\]\]]` to `NULL`, because this removes the component (https://cran.r-project.org/doc/FAQ/R-FAQ.html#How-can-I-set-components-of-a-list-to-NULL_003f[R FAQ 7.1: How can I set components of a list to NULL?]).

* `pass:c[entry[["publisher"\]\] <- NULL]` and `+entry$year <- NULL+` remove elements; `pass:c[entry["genre"\] <- list(NULL)]` keeps a `genre` element whose value is `NULL` (`str()` shows `$ genre: NULL`, and `length(entry)` is still three); `pass:c[entry["pages"\] <- NULL]` removes `pages`.
* Assigning `NULL` to a name that does not exist is not an error (`+entry$missing <- NULL+`), and `pass:c[entry[c("title", "genre")\] <- NULL]` removes several elements in one step.
* `pass:c[[<-]` with a list value replaces several elements and recycles the list (`pass:c[point[c("a", "b", "c")\] <- list(0)]` sets three elements to 0). An empty list value is the error `+replacement has length zero+`.
* **Replacement does not match partially.** `+entry$pag <- 1L+` adds a new element called `pag` rather than changing `pages`; extraction with `$` would have matched. The help page says that no partial matching is done in subassignment.
* A vector index in `pass:c[[[<-]` replaces a nested element (`pass:c[nested[[c("a", "b")\]\] <- "new"]`), and `pass:c[nested[["a"\]\][["c"\]\] <- NULL]` removes a nested one.
* `+$<-+` on `NULL` first coerces it to `list()`, and so does `pass:c[[[<-]`; in R versions before 4.0.0 a length-one value assigned with `pass:c[[[<-]` to `NULL` gave an atomic vector, and since R 4.0.0 it gives a list (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.0.0]). `pass:c[out <- NULL; out[["first"\]\] <- 1]` has class `"list"`.
* An atomic vector cannot hold `NULL` or a longer value in a single slot: `pass:c[v[["a"\]\] <- NULL]` is `+replacement has length zero+` and `pass:c[v[["c"\]\] <- 1:2]` is `+more elements supplied than there are to replace+`.
* For the books, `pass:c[reading_list[["pride"\]\]$pages <- 432L]` changes a field of a book inside a list, which is a nested replacement, explained in the section after the data frames; `+reading_list$dispossessed <- NULL+` removes a book.

=== Data frames

A data frame is a list, so the list forms work, and the matrix forms follow the rules of `pass:c[[<-.data.frame]`. The replacement methods add whole columns by naming a column that does not exist; columns are added at the right-hand edge, rows can be added at any row after the last one and the columns are filled with missing values; and a `NULL` value deletes the column. Missing values in the indices are not allowed for replacement.

* **New columns.** `+stock$on_loan <- FALSE+` recycles the single value to the 16 rows. `+stock$bad <- 1:3+` is the error `+replacement has 3 rows, data has 16+`; a value is replicated only when an exact number of repeats fits, so `1:4` is accepted and repeated four times, and `1:5` is an error. A value of length one is the usual and safest case.
* **Update by condition.** The form `pass:c[df[df$pages < 100, "pages"\] <- NA]` is the one to be careful with when the condition can be `NA`: with an `NA` in `stock$pages` it is the error `+missing values are not allowed in subscripted assignments of data frames+`. The data frame form refuses an `NA` in the row index altogether, while the vector form `pass:c[x[cond\] <- v]` accepts it when the value has length one and then leaves the elements with an `NA` condition unchanged. Either way, write the condition so that it has no `NA`: use `which()` (`pass:c[stock$pages[which(stock$pages < 100)\] <- NA]`) or `!is.na()` in the condition.
* **Rows.** `pass:c[stock[nrow(stock) + 1L, \] <- list(...)]` appends a row from a list with one element for each column, and a condition replaces cells in selected rows; a filter keeps rows (`pass:c[stock[stock$title != "New Book", \]]`).
* **Columns.** `+stock$short <- NULL+` removes a column, as does `pass:c[stock[, -2\]]` (by position, in a copy), and `pass:c[stock["title"\] <- list(...)]` replaces a whole column through the list interface, as do `pass:c[[[]` and `$`. For `pass:c[[]`, the replacement value can be a list: each element is used to replace (part of) one column, and `NULL` elements delete columns when the replacement does not select rows.
* **Logical matrix.** `pass:c[nums[is.na(nums)\] <- 0L]` replaces the `NA` cells of every column in one step: for replacement a logical matrix index must have the same dimension as the data frame, and the replacement is done one column at a time, each value coerced to the type of the column it goes to. This is the replacement form of the matrix index that the help page advises against for extraction.

=== How a replacement call is evaluated

`pass:c[x[i\] <- v]` looks like an assignment to a part of `x`, but R evaluates it as a call to the replacement function named `pass:c[[<-]` and assigns the result to `x`. The language definition spells out the steps with a temporary variable that has the internal name `+*tmp*+`; the listing below is that conceptual expansion, a fragment and not a script to run. A function whose name is another name followed by `+<-+` works the same way, and its last argument must be called `value`. The second part of the listing is the nested case: `pass:c[names(x)[3\] <- "Three"]` is two replacements, evaluated from the inside out, where the value of the inner `pass:c[[<-]` call becomes the `value` of the outer `+names<-+` call.

[source,text]
----
x[3:5] <- 13:15
# is evaluated as if it were
`*tmp*` <- x
x <- "[<-"(`*tmp*`, 3:5, value = 13:15)
rm(`*tmp*`)

names(x)[3] <- "Three"
# is evaluated as if it were
`*tmp*` <- x
x <- "names<-"(`*tmp*`, value = "[<-"(names(`*tmp*`), 3, value = "Three"))
rm(`*tmp*`)
----

Source: https://cran.r-project.org/doc/manuals/r-release/R-lang.html#Subset-assignment[The R Language Definition: Subset assignment]

The index is converted to numbers first and the elements are replaced in order along them, as if by a `for` loop. The same mechanism works with `+<<-+`, where only the target variable is looked up in the enclosing environment and the other names of the expression are evaluated in the current one; the manual advises against a local variable with the same name as the target of a superassignment. The next script runs the equivalent steps by hand, defines a replacement function of its own and uses the ones that ship with R.

----

* The first statement of the script, `pass:c[names(x)[2\] <- "beta"]`, and the hand-written call in the second block give identical results (`identical()` is `TRUE`); the third block takes the same steps with an ordinary variable, `nm`.
* Calling `pass:c[[<-]` directly prints the modified copy and leaves `z` unchanged: it is the assignment that rebinds the name. That is why a replacement function must return the whole modified object.
* A replacement function is any function called `+name<-+` with a final argument `value`. The `+title<-+` in the script checks that its argument is a `book` and returns the changed copy, and then `+title(dune) <- "Dune Messiah"+` works at the top level, `+title(shelf_list$first) <- ...+` works on a list element and `pass:c[title(shelf_list[["first"\]\]) <- ...]` works with `pass:c[[[]`, because each step of a nested replacement calls the replacement function of the outer part with the result of the inner replacement. The functions `+names<-+`, `+dim<-+`, `+dimnames<-+`, `+levels<-+` and `+attr<-+` are all of this kind, as the last block shows.
* `+is.na(x) <- i+` is another replacement function: it sets the elements at position (or name) `i` to `NA`; the help page of `is.na` documents it with the replacement form (https://search.r-project.org/R/refmans/base/html/NA.html[R documentation: NA]).

== subset() versus [

`subset()` is a function that selects rows and columns with a condition written in terms of the columns. It is documented as a convenience function intended for use interactively, and it has a warning that it should not be used for programming (https://search.r-project.org/R/refmans/base/html/subset.html[R documentation: subset]). The condition `year > 2020` is not evaluated in the calling environment: `subset()` evaluates it in the data frame, so the columns are variables. That is non-standard evaluation, and xref:programming-languages/r/evaluation-and-non-standard-evaluation.adoc[Evaluation and Non-Standard Evaluation] explains the mechanism. The help page lists the differences from `pass:c[[]`:

* for a vector, `subset(x, cond)` is `pass:c[x[cond & !is.na(cond)\]]`: missing values in the condition count as `FALSE`, so there is no NA-row trap;
* for a data frame, the argument `subset` works on the rows and the argument `select` on the columns. `select` is an expression in which the column names have been replaced by the column numbers, so ranges (`title:year`), negative selections (`-c(isbn, genre)`) and `c()` of names all work without quotes;
* the argument `drop` is passed to `pass:c[[]`, but its default is `FALSE` for data frames and matrices, which is different from the default of the indexing operator;
* factors are not cleaned: unused levels remain, and `droplevels()` removes them (https://search.r-project.org/R/refmans/base/html/droplevels.html[R documentation: droplevels]);
* since R 4.3.0 the data frame method warns about extra arguments, which typically catches `=` written where `==` was meant, as in `subset(books, year = 2020)` (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS: Changes in R 4.3.0]).

=== Why not subset() in functions

The warning of the help page is about the evaluation. `subset()` looks the names in its condition up in the data frame first and then in the environment where it was called, so a name that is both a column and a variable is silently the column. The next script is the classic accident: a helper whose argument has the same name as a column.

[source,r]
----
source("scenario.R")

# A helper that keeps books longer than a given number of pages. The argument
# is called pages, which is also a column of the data frame.
longer_than <- function(df, pages) {
  subset(df, pages > pages)
}
nrow(longer_than(books, 400))
#> [1] 0

# The condition pages > pages compares the column with itself: the column
# wins, because subset() looks in the data frame first. No row is TRUE, so
# nothing is kept, and no error says why.
longer_than(books, 400)[, c("title", "pages")]
#> [1] title pages
#> <0 rows> (or 0-length row.names)

# With [ the two names cannot be confused
longer_than <- function(df, min_pages) {
  df[which(df$pages > min_pages), , drop = FALSE]
}
longer_than(books, 400)[, c("title", "pages")]
#>                  title pages
#> 2  Pride and Prejudice   432
#> 12    Notes on Gravity   410

# A column name held in a variable cannot be used with $ or inside subset():
# col is a string here, so the condition compares strings with "2020"
col <- "year"
head(books[[col]], 3)
#> [1] 1974 1813 2019
head(books$col, 3)
#> NULL
nrow(subset(books, col > 2020))
#> [1] 16
subset(books, get(col) > 2020)[, c("title", "year")]
#>             title year
#> 4      Loud Roofs 2021
#> 10 THE LONG TABLE 2023
#> 15    Ten Winters 2022

# The usual advice: use subset() at the console, [ in functions and packages.
# A function that needs the NSE can pass the expression on with eval().
newer_than <- function(df, year_min) {
  keep <- eval(substitute(year > year_min), df, parent.frame())
  df[which(keep), , drop = FALSE]
}
newer_than(books, 2020)[, c("title", "year")]
#>             title year
#> 4      Loud Roofs 2021
#> 10 THE LONG TABLE 2023
#> 15    Ten Winters 2022
----

Source: https://search.r-project.org/R/refmans/base/html/subset.html[R documentation: subset]

* `longer_than(df, pages)` calls `subset(df, pages > pages)`. Both `pages` are the column, because the data frame is searched before the function's argument, so the condition compares the column with itself and no row is `TRUE`: an empty data frame, without an error. The `pass:c[[]` version (`pass:c[df[which(df$pages > min_pages), , drop = FALSE\]]`) cannot have the problem, because the column is always `df$pages` and the argument has another name.
* A column name held in a variable does not work with `$` (`books$col` looks for a column called `col`, and returns `NULL`) or with the unquoted names of `subset()`. In the script `col` is the string `"year"` and `subset(books, col > 2020)` compares the string `"year"` with `"2020"` as strings, which is `TRUE` for every row: sixteen rows come back and no message says it. Use `pass:c[books[[col\]\]]` or `get(col)`, the latter inside the data frame as the script shows.
* When a function needs the non-standard form, it can build the condition itself, as `newer_than()` does with `+eval(substitute(...), df, parent.frame())+`, so that the caller's argument is evaluated with the columns of `df` visible. This is what dplyr and other packages automate; the details and their trade-offs are the subject of the evaluation page.

The practical rule is the one the help page gives: `subset()` for interactive work at the console, `pass:c[[]` and `pass:c[[[]` in functions, scripts that are run unattended, and packages.

== The upcoming R-devel warning for x[logi]

The development version of R (4.7.0, not released) has a change in the NEWS that affects the logical indexes of this page. The R-devel NEWS says that `pass:c[x[logi\]]`, with `logi` a logical index, now warns if `length(x)` is not a multiple of `length(logi)`, fixing PR#19155, after the discussions of several participants in R Dev Days and the R Sprint in 2026 (https://cran.r-project.org/doc/manuals/r-devel/NEWS.html[R NEWS: Changes in R-devel]). The text was read from the development NEWS on 2026-10-20 and the examples of this page were not run on R-devel, so what follows is the consequence and not a captured message.

* Today, in R 4.6.1, the call `pass:c[loan_len[c(TRUE, FALSE, FALSE)\]]` with a vector of eight elements is recycled silently and selects the positions 1, 4 and 7; the script of <<logical-recycling>> shows `warns()` returning no warning. A logical index of length ten for a vector of length eight is also silent (and gives two `NA` elements).
* According to the NEWS entry, the same expressions will warn in the development version. Code that relied on a short logical index that does not divide the length (a mask of length 3 recycled over 8 elements, usually by accident) will produce a warning there, and a test suite that turns warnings into errors will fail.
* A logical index whose length divides `length(x)` (`pass:c[x[TRUE\]]`, or `pass:c[x[c(TRUE, FALSE)\]]` on a vector of even length) and a logical index of the same length as `x`, which is the normal case, are multiples in the sense of the rule and are not affected.
* The fix is the same as for any recycling accident: build the mask with the length of the vector (`rep(c(TRUE, FALSE, FALSE), length.out = length(x))`, made explicit), or use `which()`.

The change is not in any release at the time of the check. Whether it appears under the number 4.7.0 and with this wording is for the NEWS of that release to say; the page xref:programming-languages/r/whats-new-and-migrating-older-code.adoc[What's New and Migrating Older Code] tracks the version differences.

== Version notes

[cols="2,5",options="header"]
|===
|Version |What changed for subsetting
|R 2.6.0 |negative out-of-bounds subscripts are silently ignored, for S compatibility (the language definition)
|R 3.1.1 |the warning for partial matching with `$` on data frames is given only when `warnPartialMatchDollar` is `TRUE`
|R 4.0.0 |`pass:c[N <- NULL; N[[1\]\] <- val]` gives a list also for a length-one value; `pass:c[x[[Inf\]\]]` no longer has undefined behaviour, and `pass:c[x[[-Inf\]\]]`, `pass:c[x[[-n\]\]]` have better errors; `head()` and `tail()` take a vector `n` for arrays and the argument `keepnums` replaces `addrownums`; `stringsAsFactors` defaults to `FALSE`
|R 4.1.3 |a character matrix index on an array without `dimnames` is an error; `which()` checks that `arr.ind` is `TRUE`
|R 4.2.0 |classed conditions `notSubsettableError` and `subscriptOutOfBoundsError`; the index of `pass:c[x[i\]]` and `pass:c[x[[i\]\]]` for non-integer `i` follows the documentation (`as.integer(i)`, or `trunc(i)` on overflow)
|R 4.3.0 |`pass:c[x[[\]\]]` is an error of class `MissingSubscriptError` (also `pass:c[NULL[[\]\]]` and `pass:c[x[[\]\] <- v]`); `head()` and `tail()` signal an error for a non-numeric `n`; the `subset()` method for data frames warns about extraneous arguments
|R 4.4.0 |`sort_by()` as a shorter form of `pass:c[df[order(df$a, df$b), \]]` (R FAQ 7.23)
|R 4.6.0 |subassignment to a one-dimensional array with a name as the index no longer drops it to a vector
|R-devel (4.7.0) |`pass:c[x[logi\]]` warns when `length(x)` is not a multiple of `length(logi)`; not released
|===

== Where older tutorials differ

[cols="2,3,4,2",options="header"]
|===
|Older tutorial |Current practice |Why |Version

|`pass:c[df[df$year > 2000, \]]` presented as the way to filter, with no mention of missing values
|`pass:c[df[which(df$year > 2000), \]]`, `pass:c[df[!is.na(df$year) & df$year > 2000, \]]` or `subset()`
|the `NA` in the condition becomes a row of `NA` with row name `NA`
|always

|`attach(df)` so that columns can be used by name
|`+with(df, ...)+`, `df$col`, `subset()` or `pass:c[df[...\]]` with the data frame named
|what is attached is a copy: an assignment to an attached name creates a masking variable in the workspace and the data frame is unchanged, and a change to the data frame is not seen until it is detached and attached again; this reference does not use `attach()`
|always

|`pass:c[x[-which(x > 5)\]]` to drop the elements that match
|`pass:c[x[x <= 5\]]`, or `pass:c[x[!(x > 5)\]]` with the `NA` handled
|when nothing matches, `which()` returns `integer(0)` and the result is empty
|always

|`pass:c[mat[i, \]]` and `pass:c[df[, j\]]` inside functions and loops
|`pass:c[mat[i, , drop = FALSE\]]`, `pass:c[df[j\]]` or `pass:c[df[, j, drop = FALSE\]]`
|a single row or column is silently turned into a vector (R FAQ 7.5)
|always

|`pass:c[x[[i\]\] <- NULL]` to set an element to `NULL`
|`pass:c[x[i\] <- list(NULL)]`
|a `NULL` value removes the element (R FAQ 7.1)
|always

|`df$na` relied on to reach `df$name` ("it works")
|the full name, `pass:c[df[["name"\]\]]`
|`$` matches a unique prefix silently; `pass:c[[[]` is exact; `warnPartialMatchDollar` finds the uses
|always; warning option since R 3.1.1

|the language definition says that `pass:c[[[]` has `exact = NA` by default
|`exact = TRUE` is the default; pass `exact = NA` to be warned, `FALSE` to allow
|the help page and the behaviour of R 4.6.1 give no partial matching by default
|R 4.6.1

|An Introduction to R: an index matrix must be numeric, and a character matrix is treated as an indexing vector
|a character matrix with one column per dimension indexes by `dimnames`
|the help page of `pass:c[[]` documents it, and R 4.1.3 made a wrong-shaped one an error
|R 4.1.3

|`subset()` inside functions and packages
|`pass:c[[]`, `pass:c[[[]` with `which()`
|non-standard evaluation looks columns up first, so a name that is both a column and an argument is the column
|always (help page warning)

|`pass:c[df[order(df$a, df$b), \]]` as the only way to sort rows
|still valid; `pass:c[sort_by(df, ~a + b)]` is a shorter alternative
|`sort_by()` is new in R 4.4.0 (R FAQ 7.23)
|R 4.4.0

|`pass:c[df$genre[2\]]` a factor, indexing "by the labels"
|`stringsAsFactors = FALSE` is the default; use `as.character(f)` as an index
|a factor index uses the integer codes
|R 4.0.0

|`pass:c[for (i in 1:nrow(df)) df[i, \]]` to process rows
|vectorised subsetting; `seq_len(nrow(df))` when a loop is needed
|`1:0` counts down, and a row at a time is slow
|always

|the error message `+can't mix positive and negative subscripts+`
|`+only 0's may be mixed with negative subscripts+`
|the text that R 4.6.1 prints; the NEWS files do not record when the wording changed
|R 4.6.1
|===
