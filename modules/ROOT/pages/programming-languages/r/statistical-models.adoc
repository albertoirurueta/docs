A statistical model in R is an ordinary object: a function such as `lm()` takes a formula and a data frame, fits the model and returns a list with a class, and a small set of generic functions (`print()`, `summary()`, `coef()`, `residuals()`, `predict()`, `anova()`, `confint()`, `plot()`, `update()`) read that list so that you never have to. The same design carries from straight-line regression to generalised linear models, nonlinear least squares and hand-written maximum likelihood, which is why this page is organised around the fitting functions and one shared vocabulary of extractors. It covers the formula interface of `lm()` and the full `summary.lm()` output, every extractor generic and what each returns, missing values and `na.action`, weights, offsets and subsets, influence measures and the diagnostic plots, `update()` and stepwise selection, factor predictors and contrasts, interactions and polynomials, `glm()` with its families and links (a logistic model for overdue loans, counts, positive durations, grouped binomial data), `nls()` and its failures, `optim()`, `optimize()`, `nlm()`, `nlminb()` and `stats4::mle()` for maximum likelihood, the model object as an S3 list with a wrapper class of your own, and broom.

Every example is a script that was run with `Rscript` on R 4.6.1 with warnings printed as they happen (`options(warn = 1)`), and the lines that start with `+#>+` are what it printed. The scripts also pass the default `lintr` linters. The names `books`, `loans`, `shelf_today`, `loan_days` and the `book()` constructor come from the running library-shelf scenario described on the xref:programming-languages/r/index.adoc#shelf-files[section index]: a script that needs them starts with `source("scenario.R")`. Where a message contains quotation marks, they are the typographic quotes R prints in a UTF-8 locale. A formula created at the top level of a script has the global environment as its environment, so printing it shows no `pass:c[<environment: ...>]` line; the one place where a model object holds an environment is its `terms` component, and the scripts never print it. Diagnostic plots are drawn to `svg()` or `pdf(NULL)` devices that are thrown away, so that the scripts run without a screen: the plots are not reproduced here, and the numbers behind each one are computed and printed instead.

== How R fits models

The chapter on statistical models in _An Introduction to R_ (chapter 11) starts from one idea: a model is described by a formula, fitted by a function that takes the formula and a data frame, and the result is an object that other functions take apart. The manual's own example is `pass:c[lm(y ~ x1 + x2, data = production)]`, and it points out that the `data` argument makes the variables come from that data frame first, whether or not the frame is attached to the search path, which is the first reason not to use `attach()` (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Linear-models[An Introduction to R: Linear models]). The value of `lm()` is, technically, a list of class `"lm"`, and generic functions that dispatch on that class display, extract and plot the results (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Generic-functions-for-extracting-model-information[An Introduction to R: Generic functions for extracting model information]). That is the design this page follows: learn the fitting functions once, and learn the vocabulary of extractors once, because the same words (`coef`, `residuals`, `predict`, `anova`, `logLik`, `AIC`) work for most of them.

Two further points of design are worth knowing before the code. First, the modelling functions evaluate the formula against the data frame with the same data-mask idea as `with()` and `subset()`, through `model.frame()` (see xref:programming-languages/r/evaluation-and-non-standard-evaluation.adoc[Evaluation and Non-Standard Evaluation]): a variable not found in `data` is looked up in the formula's environment, which is a source of confusing errors shown below. Second, the extractor generics are the interface and the list components are the implementation: `coef(fit)` and `fit$coefficients` return the same numbers for an `lm` today, but only the generic works for an `nls` fit, a model from another package, or a class that stores its coefficients under another name (see <<model-object,The model object as an S3 list>>). The R FAQ lists the differences from S that matter when reading old S-PLUS code: powers must be protected with `I()`, `na.action` is `"na.omit"` by default in R and unset in S, GLM family objects are implemented differently, terms objects are formulas with attributes, and unordered factors get treatment contrasts in R and Helmert contrasts in S (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Models[R FAQ 3.3.2: Models]).

== The data for the examples

A few examples use `books` alone (the number of pages on the publication year). The others describe how long a returned loan lasted, so it needs one row per loan with the book's attributes next to it. That is a join of `loans` to `books` on the ISBN, and it needs a little cleaning first: the ISBNs in `books.csv` are hyphenated in some rows and the ones in `loans.csv` are bare digits, so both are normalised with `normalise_isbn()` from the scenario; the `genre` column holds nine spellings of six genres (`"Fiction"`, `"fiction"`, `"Fiction "`), so it is cleaned with `pass:c[tolower(trimws())]`, exactly as on the formulas page. The join is `merge(loans, books, by = "isbn")`, an inner join: a loan whose ISBN matches no book (loan L005 has a digit missing) drops out, and a book never loaned does not appear. The duration is the difference of two `Date` columns, a `difftime`, which `as.numeric()` turns into a plain number of days (see xref:programming-languages/r/dates-and-times.adoc[Dates and Times]).

[source,r]
----
source("scenario.R")

# Clean the two columns that the join and the model use.
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)

# One row per loan, with the book's pages, year and genre next to it.
loan_books <- merge(loans, books, by = "isbn")
c(loans = nrow(loans), books = nrow(books), merged = nrow(loan_books))
#>  loans  books merged
#>     60     16     59

# Loan duration in days: a difftime becomes a number.
loan_books$days <- as.numeric(loan_books$return_date - loan_books$loan_date)
class(loan_books$days)
#> [1] "numeric"

# Keep the returned loans with a sensible duration (this drops the NA
# dates, the unreturned loans and the loan returned before it began).
dur <- loan_books[!is.na(loan_books$days) & loan_books$days >= 0, ]
nrow(dur)
#> [1] 50
table(dur$genre)
#>
#>         classic         fiction         mystery     non-fiction          poetry
#>               5              18               4               5               5
#> science fiction
#>              13
summary(dur$days)
#>    Min. 1st Qu.  Median    Mean 3rd Qu.    Max.
#>    1.00   14.50   21.00   20.22   26.75   37.00
sum(complete.cases(dur[, c("days", "pages", "genre")]))
#> [1] 42
----

Source: https://search.r-project.org/R/refmans/base/html/merge.html[R documentation: merge]

The numbers tell the story of the data. Sixty loans and sixteen books give 59 rows after the join (the loan with the short ISBN found no book). Of those, 50 are returned loans with a duration of zero or more days: seven loans are still out (the `NA` return dates), one has the impossible loan date `2025-02-30` (an `NA` date), and one was "returned" three days before it was loaned. Of the 50, only 42 have a known number of pages and a genre, because two books have `NA` pages. Every later script that models loan durations starts with these same six statements (the script above, with the comments left out), and filters further where it needs to.

Two warnings about this data apply to every model that follows. The sample is small (42 usable rows, and 13 distinct books among them), so every standard error is large and every test has little power; and the rows are not independent, because the same book appears in several loans and shares its `pages` and `genre` (the section on pitfalls shows what that does). The models fit and read correctly; the conclusions are weak, and the text says so.

== Linear models with lm()

=== The formula interface

`lm()` takes a formula and a data frame. The call `pass:c[lm(pages ~ year, data = books)]` regresses the page count on the publication year: the response is on the left of the tilde, the predictors on the right, an intercept is added unless it is removed with `-1` or `+0`, and the variables are found in `data` first. The value prints compactly: the call and the estimated coefficients. Everything else is hidden inside the object, and `summary()` returns a second object whose `print` method formats the full table (https://search.r-project.org/R/refmans/stats/html/lm.html[R documentation: lm]).

[source,r]
----
source("scenario.R")

# The data argument says where the variables come from.
fit <- lm(pages ~ year, data = books)
fit

class(fit)
#> [1] "lm"

The `summary()` output has five parts, and each one answers a different question:

[cols="2,5",options="header"]
|===
|Part |What it says
|`Call` |The matched call, as `lm()` recorded it. Because `match.call()` supplies the argument names, `pass:c[lm(pages ~ year, books)]` prints as `lm(formula = pages ~ year, data = books)`. `update()` re-evaluates this call.
|`Residuals` |The five-number summary of the residuals (minimum, quartiles, maximum) when there are more than five residual degrees of freedom; with fewer, the residuals themselves are printed. A residual is the observed value minus the fitted value.
|`Coefficients` |One row per estimated coefficient: the estimate, its standard error, the t value (estimate divided by standard error) and the two-sided p-value of the null hypothesis that the coefficient is zero, from a t distribution with the residual degrees of freedom. The stars are a legend (`Signif. codes`) for the p-value, not a separate result.
|`Residual standard error` |The estimate of the error standard deviation, the square root of the residual sum of squares divided by the residual degrees of freedom; `sigma(fit)` returns it. The lines below it say how many observations were deleted because of missing values.
|`Multiple R-squared`, `Adjusted R-squared`, `F-statistic` |The share of the variance of the response explained by the model, the same share penalised for the number of predictors, and the F test of the model against the model with the intercept only. For a model without an intercept, R-squared is computed against zero rather than against the mean (R FAQ 7.41).
|===

Source: https://search.r-project.org/R/refmans/stats/html/summary.lm.html[R documentation: summary.lm]

Read the pages-on-year summary like this. Thirteen books have both a year and a page count (three were deleted for missing values, and the output says so), so there are 11 residual degrees of freedom: 13 observations minus two coefficients. The slope is about -0.89 pages per year with a standard error of 0.46, a t value of -1.95 and a p-value of 0.077: newer books in this tiny sample are a little shorter, and the evidence is weak. R-squared is 0.257, adjusted R-squared 0.189, and the F test of the whole model has the same p-value as the slope's t test, because a model with one predictor has one test (F equals t squared: 3.804 is -1.950 squared).

`genre` is a character column, so `lm()` turns it into a factor (the levels are sorted alphabetically, so `"classic"` comes first) and codes it with treatment contrasts: the intercept is the predicted duration for the reference level `"classic"` at zero pages, and each `genre` coefficient is the difference between that genre and the reference. The coefficient of `pages` is 0.0009 days per page with a p-value of 0.98, and every genre coefficient has a p-value above 0.6; the F test of the whole model has p = 0.976 and the adjusted R-squared is negative, which happens when a model explains less than a random predictor would by chance. Duration does not depend on pages or genre in this data, and the model says that correctly. A negative adjusted R-squared is not a bug; it is the adjustment working.

=== The extractor generics

The vocabulary below is the part to memorise. Each row is a generic function; the right-hand column says what it returns for an `lm`. The manual lists the same family (add1, alias, anova, coef, deviance, drop1, effects, family, formula, kappa, labels, plot, predict, print, proj, residuals, step, summary, vcov) in its chapter on extracting model information (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Generic-functions-for-extracting-model-information[An Introduction to R: Generic functions for extracting model information]).

[cols="2,5",options="header"]
|===
|Generic |Returns
|`coef(fit)` (alias `coefficients`) |A named numeric vector of the estimated coefficients. `coef(summary(fit))` is the matrix of estimates, standard errors, t values and p-values.
|`residuals(fit)` (alias `resid`) |The residuals, named by the row names of the data. `rstandard()` and `rstudent()` give standardised and studentised versions.
|`fitted(fit)` (alias `fitted.values`) |The fitted values, named by row.
|`+predict(fit, newdata =, ...)+` |Predictions for new rows of data, optionally with `interval = "confidence"` or `"prediction"` and `se.fit = TRUE`.
|`confint(fit, parm, level)` |Confidence intervals for the coefficients (t based for an `lm`, profile likelihood for a `glm` or `nls`).
|`vcov(fit)` |The estimated variance-covariance matrix of the coefficients.
|`anova(fit)` or `+anova(fit1, fit2, ...)+` |A sequential analysis of variance, or a comparison of nested models.
|`logLik(fit)`, `AIC(fit)`, `BIC(fit)` |The maximised log-likelihood (with its degrees of freedom), and the information criteria derived from it.
|`deviance(fit)` |The residual sum of squares (weighted if appropriate) for an `lm`; the deviance for a `glm`.

|`formula(fit)`, `terms(fit)`, `model.frame(fit)`, `model.matrix(fit)` |The formula, its terms object, the data frame the fit used and the design matrix.
|`hatvalues(fit)`, `cooks.distance(fit)`, `influence.measures(fit)` |Leverage, Cook's distance and the full set of influence diagnostics.
|`update(fit, formula)`, `add1()`, `drop1()`, `step()` |Refit with a changed formula; test single additions or deletions; stepwise selection by AIC.
|`plot(fit)` |Up to six diagnostic plots.
|===

The residuals and the fitted values add back up to the response (`resid(fit) + fitted(fit)` equals `dur$days`), and with an intercept in the model the residuals sum to zero. `confint()` gives 95 per cent intervals by default; for an `lm` they are the estimate plus and minus the t quantile times the standard error, and `level =` changes the width. Every interval for `pages` contains zero and the intervals for the genres are wide (the one for `genrepoetry` runs from -27.5 to 25.2 days): the data cannot distinguish any genre from another.

The second script covers the counts and the likelihood-based summaries. === The model frame and the design matrix

Behind every fit are two objects that `formulas.adoc` explains in detail: the model frame, a data frame holding exactly the variables the formula mentions after `na.action` has removed incomplete rows, and the model matrix, the numeric design matrix built from it (one column of ones for the intercept, the numeric predictors, and one 0/1 column per non-reference factor level). `model.frame(fit)` and `model.matrix(fit)` recover them from the fit, which is how you check what a model actually saw. The coefficients of a linear model are the least-squares solution of the normal equations for that matrix, which the last lines of the script verify (`lm()` itself uses a QR decomposition, which is numerically safer than forming the cross-product matrix; the manual describes it in the appendix on least-squares fitting, https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Least-squares-fitting-and-the-QR-decomposition[An Introduction to R: Least squares fitting and the QR decomposition]).

=== Prediction

`predict()` evaluates the fitted model on new data. The data frame must contain every variable of the right-hand side under the same name, and a factor may only take levels that were in the fit. The `interval` argument adds either a confidence interval for the mean response (the uncertainty of the fitted line) or a prediction interval for a single new observation (that uncertainty plus the residual variance), and the prediction interval is always the wider one. `se.fit = TRUE` returns a list holding the fit, the standard errors, the residual degrees of freedom and the residual scale, and with no `newdata` the function returns the fitted values.

=== Comparing models with anova()

`anova()` on one `lm` is a sequential analysis of variance: each term's sum of squares is the decrease in the residual sum of squares when that term is added to the terms before it, in the order they appear in the formula. The manual says the table is for a sequence of fitted models and that only for orthogonal experiments is the order of inclusion irrelevant (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#ANOVA-tables[An Introduction to R: ANOVA tables]). The R FAQ explains why the numbers change with the order of the terms, and what to use if you want the "Type III" sums of squares that other packages print: compare two models with `anova(model1, model2)`, or call `drop1(model)`, which shows the change from dropping each term from the full model (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-does-the-output-from-anova_0028_0029-depend-on-the-order-of-factors-in-the-model_003f[R FAQ 7.18: Why does the output from anova() depend on the order of factors in the model?]).

=== Missing values and na.action

`na.action` decides what `lm()` does with rows that have an `NA` in any variable of the model. The default is whatever `options("na.action")` holds, `"na.omit"` in a fresh R session (the R FAQ lists it among the differences from S: R sets it, S does not), which drops the incomplete rows silently except for a note in `summary()`. The alternatives are `na.fail`, which stops with `missing values in object`, `na.exclude`, which drops the rows for the fit but remembers them, and `na.pass`, which passes the `NA` values on (the model-fitting code will then fail on them). The practical difference between `na.omit` and `na.exclude` is the length of `residuals()`, `fitted()` and `predict()`: with `na.exclude`, `naresid()` pads them with `NA` for the dropped rows, so the results line up with the original data frame and can be stored as columns.

=== Leverage, influence and Cook's distance

A fit can be dominated by a few rows. Three ideas separate the cases. The *leverage* of an observation is its diagonal entry in the hat matrix (`hatvalues()`), a number between 0 and 1 that depends only on the predictors; the leverages add up to the number of coefficients, so their mean is p over n, and a common rule of thumb flags those above twice the mean. A *standardised residual* (`rstandard()`) divides each residual by its estimated standard deviation, and a *studentised residual* (`rstudent()`) uses the estimate of sigma from the fit without that observation. *Cook's distance* (`cooks.distance()`) combines the two: how far the fitted values move when one observation is left out. `influence.measures()` collects the dfbetas, dffits, covariance ratios, Cook's distances and hat values together with logical flags, and `summary()` of the result prints only the observations flagged on at least one of them (https://search.r-project.org/R/refmans/stats/html/influence.measures.html[R documentation: influence.measures]).

Leverage in this data is set by how many loans fall in each genre cell, because `genre` has five dummy columns for 42 rows. === Diagnostic plots

`plot()` on an `lm` produces up to six diagnostic plots, chosen by the `which` argument, and by default draws four (`which = c(1, 2, 3, 5)`): the manual's chapter says "four plots", which is the default. They are, in order of the `which` number:

[cols="1,3,5",options="header"]
|===
|`which` |Plot |What to look for
|1 |Residuals against fitted values |A flat band around zero with no curve. A curve says the mean model is wrong (add a transformation, a polynomial or a missing predictor); a funnel says the variance grows with the mean.
|2 |Normal Q-Q plot of the standardised residuals |Points near the line. Heavy tails or an S shape say the errors are not normal. For a `glm` this is, since R 4.3.0, a half-normal plot of the absolute standardised deviance residuals.
|3 |Scale-location: the square root of the absolute standardised residuals against the fitted values |A flat trend. A rising trend is non-constant variance.
|4 |Cook's distance for each observation |Bars standing out from the rest; the `id.n` largest are labelled.
|5 |Residuals against leverage |Points in the upper or lower right corner, where both leverage and residual are large. Since R 4.6.0 the plot no longer draws a smoother.
|6 |Cook's distance against leverage divided by one minus leverage |Points beyond the contour lines of constant Cook's distance, which fan out from the origin.
|===

Source: https://search.r-project.org/R/refmans/stats/html/plot.lm.html[R documentation: plot.lm]

=== Weights, offsets and subsets

Three arguments change which observations count and how. `weights` multiplies each observation's contribution to the sum of squares: use precision weights (the inverse of each observation's variance), or frequency weights for rows that stand for several identical cases. Here every book gets the same total weight however many times it was loaned, by weighting each loan with one over the number of loans of its book, which reduces the dominance of often-loaned books. `offset()` is a term whose coefficient is fixed at one; it is how a known baseline enters, and it matters most in `glm()` for rates. `subset` selects rows with a logical or index expression evaluated in the data, before the model frame is built. A zero weight removes an observation from the fit (and from the degrees of freedom) while it stays in the model frame.

=== Updating a model, and choosing terms

`update(fit, new.formula)` refits the model with the stored call and a changed formula, in which `.` stands for the corresponding part of the old formula: `pass:c[. ~ . + year]` adds a term, `+log(.) ~ .+` transforms the response, `pass:c[. ~ . - genre]` drops one. Other arguments can be changed too (`+update(fit, subset = ...)+`). The manual explains the same facility, adds that a `data=` argument in the original call is passed on to `update()` and its allies, and names `add1()`, `drop1()` and `step()` as the functions for exploring incremental sequences of models (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Updating-fitted-models[An Introduction to R: Updating fitted models]). `update()` re-evaluates the stored call, so the data it names must still exist, with the same name, where `update()` is called.

`add1()` shows what adding each term in `scope` would do, `drop1()` what removing each term from the current model would do; both report the change in the residual sum of squares and in AIC, and `test = "F"` adds an F test. `step()` does this repeatedly: it adds or drops terms to minimise AIC and returns the final model with the path in its `anova` component. Be sceptical of stepwise selection: the p-values and intervals of the final model ignore the search that produced it, and with n = 42 and weak signal the search is fitting noise. It is shown here because it is in the manual, and the null model wins.

=== Factor predictors, contrasts, interactions and polynomials

A factor in a formula becomes a set of columns built by *contrasts*. The default for an unordered factor is `contr.treatment` (compare each level with the first), the default for an ordered factor is `contr.poly`, and `getOption("contrasts")` shows the pair; the R FAQ notes that S uses Helmert contrasts for unordered factors, a deliberate difference. The coefficient meanings change with the coding while the fitted values do not. `relevel()` changes the reference level, `pass:c[C(f, contr.sum)]` or `pass:c[contrasts(f) <- ...]` change the coding, and a factor with fewer than two levels cannot be coded at all (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Contrasts[An Introduction to R: Contrasts]; the contrast matrices and `C()` are explained on xref:programming-languages/r/formulas.adoc[Formulas]).

With treatment contrasts and `"classic"` as the reference, the intercept (21.40) is the mean duration of classic loans; after `relevel(ref = "fiction")` it is 17.46, the mean of fiction loans, and every coefficient is a difference from that. The group means printed by `tapply()` are the same in both fits, and so are the fitted values. With sum contrasts the intercept is the unweighted average of the six group means (20.27) and the coefficients are deviations from it, with the last level's deviation implied (the coefficients sum to zero). The error `contrasts can be applied only to factors with 2 or more levels` is what a factor with one level produces, usually after subsetting a data frame without `droplevels()`.

Interactions and polynomial terms use the formula operators from the formulas page; the models themselves are ordinary. `pass:c[a * b]` means `pass:c[a + b + a:b]`, so an interaction without its main effects (`a:b` alone) forces a common intercept, which is rarely what is meant. In a formula `^` means crossing, so a quadratic term is written `I(pages^2)` (R FAQ 3.3.2 gives the same warning), or with `poly(pages, 2)`, which builds orthogonal polynomials: the fitted values are identical to those from `I()`, the coefficients differ, and `predict()` re-uses the stored basis so that new data is coded consistently. `poly(pages, 2, raw = TRUE)` gives the same coefficients as `I()`.

* `object 'no_such_column' not found`: a name in the formula is neither a column of `data` nor a variable in the formula's environment. Check the spelling, and check that `data =` was given.
* `variable lengths differ (found for 'x')`: the variables came from the workspace and have different lengths (here 10 and 9); keep the variables as columns of one data frame so that this cannot happen.
* `0 (non-NA) cases`: after `na.action`, nothing is left to fit.
* A coefficient reported as `NA` is not an error: `lm()` has `singular.ok = TRUE` by default, so a column that is a linear combination of earlier ones (`pages2` is twice `pages`) is dropped and its coefficient is `NA`, with no warning. `alias(fit)` shows the dependency, and `summary()` prints `Coefficients: (1 not defined because of singularities)`. * `NAs introduced by coercion` followed by `NA/NaN/Inf in 'y'`: a character column used as the response is coerced to numeric, which produces `NA`, and the fit stops. Convert the column deliberately, or model a count or a factor with `glm()`.

The R FAQ's list of differences from S also warns about `lm(y ~ x^3)`: in a formula `^` is the crossing operator, so the cube must be protected with `I(x^3)` (https://cran.r-project.org/doc/FAQ/R-FAQ.html#Models[R FAQ 3.3.2: Models]).

== Generalised linear models

A linear model assumes a normal response with a constant variance and a mean that is a linear function of the predictors. A generalised linear model (GLM) keeps the linear predictor and relaxes the other two assumptions. The manual states the structure in three assumptions (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Generalized-linear-models[An Introduction to R: Generalized linear models]):

. The predictors act on the response only through a single *linear predictor*, `pass:c[eta = beta1 x1 + ... + betap xp]`.
. The response has a distribution from the exponential family (normal, binomial, Poisson, gamma, inverse Gaussian) whose variance is a function of its mean and possibly a scale parameter.
. The mean is a smooth invertible function of the linear predictor, `mu = m(eta)`, and the inverse function is the *link*.

The combination of a distribution and a link is a *family*. The chapter lists the families and the links that are available for each (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Families[An Introduction to R: Families]); the table below lists the default link of each family first, which is not the order of the manual's table, and adds `cauchit`, which `?family` lists for the binomial family.

[cols="2,3,4",options="header"]
|===
|Family |Links |Typical use
|`binomial` |logit, probit, cloglog, cauchit, log |Yes or no outcomes, and counts of successes out of trials
|`gaussian` |identity, log, inverse |The same model as `lm()` (less efficiently), with a non-identity link where needed
|`Gamma` |inverse, identity, log |Positive, right-skewed continuous responses: durations, costs
|`inverse.gaussian` |`pass:c[1/mu^2]`, inverse, identity, log |Positive responses with a variance that grows faster than the Gamma's
|`poisson` |log, identity, sqrt |Counts
|`quasi`, `quasibinomial`, `quasipoisson` |chosen with `link =` (and `variance =` for `quasi`) |Quasi-likelihood: only the mean-variance relation is specified, and the dispersion is estimated
|===

Source: https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Families[An Introduction to R: Families]

`glm(formula, family = family, data = data)` fits the model. The family argument is a family object or a function that generates one (`binomial` and `binomial()` are equivalent; `binomial(link = "probit")` chooses a non-default link). Under the hood `glm()` calls `glm.fit()`, which uses *iteratively reweighted least squares* (IRLS): starting from fitted values derived from the data, it repeatedly forms a working response and weights from the current linear predictor, solves a weighted least-squares problem, and stops when the deviance changes by less than `epsilon` (1e-8) or after `maxit` (25) iterations; `glm.control()` sets both. Each pass is an ordinary weighted least-squares fit (a working response `z` built from the linear predictor and the residuals, with weights `+mu * (1 - mu)+` for the logistic model), which is why a `glm` object inherits from `lm` and contains a QR decomposition.

=== Logistic regression for overdue loans

The coefficients are therefore changes in log odds of an overdue loan per unit of the predictor, with the same treatment-contrast coding of `genre` as before. === Deviance, anova and residuals

The *deviance* of a GLM is twice the difference between the log-likelihood of a saturated model and that of the fitted one; it plays the part the residual sum of squares plays for `lm()`. `anova(fit)` on a `glm` is a sequential analysis of deviance. The R 4.4.0 NEWS changed its default: it now computes test statistics and p-values, a chi-squared test when the dispersion is fixed and an F test when it is estimated, and `test = FALSE` suppresses them (so the explicit `test = "Chisq"` in older code is no longer needed, but it is harmless). `anova(g0, g1, g2, test = "Chisq")` compares nested models with the likelihood-ratio test, and the drop in deviance by hand against `pchisq()` gives the same number.

`residuals(fit, type =)` has four kinds for a GLM. The *deviance* residuals (the default) are the signed square roots of each observation's contribution to the deviance, so their squares add up to the deviance. The *Pearson* residuals divide the raw difference by the standard deviation implied by the variance function, and their squares add up to Pearson's chi-squared statistic. *Response* residuals are observed minus fitted on the response scale, and *working* residuals are those of the last IRLS step. The Pearson statistic divided by the residual degrees of freedom (1.19 here) estimates the dispersion: a binomial or Poisson model should give about 1, and a value much larger than 1 is *overdispersion*, where `quasibinomial` or `quasipoisson` (or a mixed model) is the usual remedy.

=== Warnings: separation and non-convergence

Two warnings appear whenever a logistic regression meets a pattern the data cannot support, and they are the two a user meets first. `glm.fit: fitted probabilities numerically 0 or 1 occurred` means that some fitted probabilities are indistinguishable from 0 or 1 in floating point. If it appears together with `glm.fit: algorithm did not converge`, the usual cause is *separation*: a predictor (or a combination of predictors) classifies the observations perfectly, so the likelihood has no finite maximum and IRLS pushes the coefficients to larger and larger values until it runs out of iterations. The estimates and standard errors are then meaningless (the Wald z statistic and p-value are useless), and the remedies are to remove or coarsen the offending predictor, to use a penalised method (Firth's bias-reduced logistic regression is available in add-on packages such as brglm2 or logistf; named only, not used here), or to collect more data. The overdue flag is defined from the duration, so the duration separates it perfectly. The second warning alone, `algorithm did not converge`, means that the limit of `maxit` iterations was reached; raising `maxit` through `glm.control()` may help, and if it does not the model is probably badly specified.

# Warnings do not stop glm(), so collect them while the model is fitted.
collect <- function(expr) {
  msgs <- character()
  value <- withCallingHandlers(expr, warning = \(w) {
    msgs <<- c(msgs, conditionMessage(w))
    invokeRestart("muffleWarning")
  })
  list(value = value, warnings = msgs)
}

# Complete separation: overdue is defined from days, so days predicts it
# perfectly.
sep <- collect(glm(overdue ~ days, family = binomial, data = dur))
sep$warnings
#> [1] "glm.fit: algorithm did not converge"
#> [2] "glm.fit: fitted probabilities numerically 0 or 1 occurred"
range(round(fitted(sep$value), 6))
#> [1] 0 1

# The estimate is not finite, only large, and its standard error explodes:
# the Wald z statistic is useless here.
coef(summary(sep$value))[, "Std. Error"] > 1000
#> (Intercept)        days
#>        TRUE        TRUE
sep$value$converged
#> [1] FALSE

# Too few iterations: "algorithm did not converge".
few <- collect(glm(overdue ~ pages + genre,
  family = binomial, data = dur,
  control = glm.control(maxit = 2)

few$warnings
#> [1] "glm.fit: algorithm did not converge"
c(converged = few$value$converged, iter = few$value$iter)
#> converged      iter
#>         0         2

=== Grouped binomial data

When the unit of analysis is a group, the binomial response is a two-column matrix of successes and failures, or a proportion with the number of trials as `weights`; the manual's example of the blind men of Kalythos uses the matrix form (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#The-glm_0028_0029-function[An Introduction to R: The glm() function]). The three formulations give the same coefficients. Grouping also makes goodness-of-fit testing possible, because the residual deviance of a model with fewer parameters than groups can be compared with a chi-squared distribution (the approximation needs expected counts that are not tiny, and these counts are, so treat the p-value as a demonstration).

=== Family objects

A family object is a list of functions and expressions that together define the model and the fitting: the link function and its inverse, the variance function, the deviance residuals and the AIC. == Nonlinear least squares with nls()

Some models are linear in their predictors and some are not. The manual separates the two cases: certain nonlinear models can be fitted by a GLM, but in the majority of cases the nonlinear curve-fitting problem is one of nonlinear optimisation, where there is no guarantee that the procedure converges on satisfactory estimates and every method needs initial guesses for the parameters (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Nonlinear-least-squares-and-maximum-likelihood-models[An Introduction to R: Nonlinear least squares and maximum likelihood models]). `nls()` minimises the sum of squared residuals of a formula whose right-hand side is an arbitrary R expression in the data and the parameters, by Gauss-Newton iteration from the `start` you supply. Parameters are the names in `start`; everything else in the formula is data.

The loan durations give a natural curve to fit. The share of returned loans that were back after at most `d` days is the empirical cumulative distribution function of the durations, `ecdf()`, which rises from near zero to one and looks like a logistic curve. The logistic curve `Asym / (1 + exp((xmid - d) / scal))` has an asymptote `Asym`, a midpoint `xmid` (the duration at which half of the asymptote is reached) and a scale `scal`. The points of a cumulative curve are not independent, so the standard errors below are optimistic; the example is about fitting a curve, not about inference.

=== Self-starting models

Finding start values is the hard part of `nls()`. A *self-starting model* is a function with an attached routine that computes good starting values from the data, so `start` can be omitted. `SSlogis(input, Asym, xmid, scal)` is the logistic curve above; the others in `stats` are `SSasymp`, `SSasympOff`, `SSasympOrig`, `SSbiexp`, `SSfol`, `SSfpl`, `SSgompertz`, `SSmicmen` and `SSweibull`. The manual's example fits the Michaelis-Menten model with `nls(y ~ SSmicmen(x, Vm, K), df)`. `getInitial()` shows the start values that the model computed, and `selfStart()` builds a self-starting model from a function and an initial routine.

R 4.1.0 changed the interface a little: `nls()` now passes `trace` and `control` to `getInitial()`, so the initial function of a self-starting model must have `+...+` in its argument list.

=== Why nls() fails, and the messages it gives

`nls()` fails in a small number of recognisable ways, and they are worth knowing by their texts. `singular gradient matrix at initial parameter estimates` means the matrix of derivatives of the model with respect to the parameters has no full rank at the start values: either the model has a redundant parameter (case 1 below: the two slopes `b` and `c` cannot be told apart) or the start is so far from the data that the model is flat in some direction. `singular gradient` (without the rest) is the same problem met after some iterations. `+step factor ... reduced below 'minFactor' of ...+` means that Gauss-Newton proposed a step that did not reduce the residual sum of squares, and halving it down to `minFactor` still did not; it points to a bad start or a model that does not fit. `number of iterations exceeded maximum of 50` is the iteration limit; it also happens for artificial data with *zero residuals*, where the convergence criterion (a ratio of the size of the residual component to the size of the rest) compares two vanishing numbers and never becomes small enough, and the help page warns against using `nls()` on such artificial data; `scaleOffset` (R 4.1.0) is the supported workaround. `Missing value or an infinity produced when evaluating the model` is a model that is not finite at the current parameters (case 4: dividing by `scal = 0`). Changing `control = nls.control(warnOnly = TRUE)` turns the convergence failures into warnings and returns the last iterate, which you can inspect but should not trust.

[[optim]]
== Optimisation and maximum likelihood

`nls()` is least squares specialised to a model formula. The general tools take any R function of the parameters. The manual names `optim()`, `nlm()` and `nlminb()` as the nonlinear optimisation routines, and shows two uses: minimising a sum of squared errors, and maximising a log-likelihood, the latter being a method that applies "even if the errors are not normal" (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Maximum-likelihood[An Introduction to R: Maximum likelihood]). The function to minimise takes the parameter vector as its first argument; to maximise, return the negative, or set `control = list(fnscale = -1)` for `optim()`.

=== optim() and the negative log-likelihood

The loan durations (50 values, mean 20.2 days, standard deviation 8.6) give a likelihood to work with. Assume for a moment that they are normal: the negative log-likelihood is minus the sum of `dnorm(x, mean, sd, log = TRUE)`. Working with `log = TRUE` avoids the underflow of multiplying many small densities, and the standard deviation is parametrised on the log scale so that the optimiser cannot propose a negative value. `optim()` offers six methods: `"Nelder-Mead"` (the default, derivative-free and robust, but slow), `"BFGS"` (a quasi-Newton method using gradients, by finite differences if you give none), `"CG"` (conjugate gradients), `"L-BFGS-B"` (BFGS with box constraints, the only method that accepts `lower` and `upper`), `"SANN"` (simulated annealing) and `"Brent"` (one dimension). The result is a list with the best parameters `par`, the `value` of the function there, the `counts` of function and gradient evaluations, a `convergence` code (0 is success) and a `message`. With `hessian = TRUE` the Hessian at the solution is added.

=== Bounds, maximising and gradients

Real parameters often have a natural range. For a Gamma model of the durations, `shape` and `rate` must be positive, so `"L-BFGS-B"` with `lower` bounds is the right method. Without bounds the unconstrained methods may step to a negative value, where `dgamma()` returns `NaN` with the warning `NaNs produced`; the script catches it. The maximum-likelihood fit is not the same as the method of moments (`shape = mean^2 / variance`), as the comparison shows: 3.57 against 5.48, because the durations are close to uniform between 1 and 37 days, not Gamma shaped. An analytic gradient given as `gr` makes the search quicker and more accurate; here the score of the Gamma log-likelihood is written with `digamma()`. `control` takes `maxit` (the iteration limit), `reltol` (the relative tolerance, about 1.5e-08), `parscale` (the typical size of each parameter) and `fnscale`; a `convergence` of 1 says that the limit of iterations was reached, 10 degeneracy of the Nelder-Mead simplex, and 51 or 52 a warning or an error from L-BFGS-B.

=== One-dimensional problems: optimize(), uniroot(), nlm() and nlminb()

`optimize(f, interval)` (alias `optimise`) minimises a function of one variable on an interval by golden-section search combined with parabolic interpolation, and `maximum = TRUE` maximises. Its default tolerance is about 1.2e-04, so the result of the exponential rate (0.04947 against the exact `1 / mean` of 0.04946) is accurate to four digits unless `tol` is tightened. `uniroot(f, interval)` finds a zero of a function of one variable (Brent's method) and needs the function to change sign across the interval; otherwise it stops with `f() values at end points not of opposite sign`. Solving the score equation of the exponential model gives the same rate. `nlm()` is a Newton-type minimiser that returns the estimate, the gradient, optionally the Hessian, and a `code` (1 means the gradient is close to zero); `nlminb()` uses the PORT library, accepts bounds, and returns the parameters, the objective, a convergence code and a message. Its relative-convergence message is of the same kind as the one `nls(algorithm = "port")` reports. The R-devel NEWS (in its section for the scheduled R 4.6.2, not run here) lists a fix of a long-standing bug in `nlminb()` with constraints.

[[mle]]

Writing `optim()` calls, extracting the Hessian and inverting it is the same boilerplate for every likelihood. The `stats4` package (part of R) wraps it in `+mle(minuslogl, start, method, fixed, nobs, lower, upper, ...)+`: you give the negative log-likelihood as a function of named parameters and a list of starting values, and get an object of S4 class `"mle"` with `coef()`, `vcov()`, `logLik()`, `AIC()`, `BIC()` (given `nobs`), `summary()`, `profile()` and `confint()` methods. `method` defaults to `"BFGS"`, or to `"L-BFGS-B"` when bounds are given. The function's parameters are its formal arguments, and the data are found in the calling environment. Because the object is S4, the printing uses `show()` and the slots are `@` fields (see xref:programming-languages/r/s4-classes-and-methods.adoc[S4 Classes and Methods]).

[[non-standard]]
== Some non-standard models

The manual closes its chapter on models with a short list of facilities beyond `lm()` and `glm()` (https://cran.r-project.org/doc/manuals/r-release/R-intro.html#Some-non_002dstandard-models[An Introduction to R: Some non-standard models]): mixed models (`lme()` and `nlme()` in the recommended nlme package, which make heavy use of formulas), local approximating regressions (`loess()`, in `stats`), robust regression (`lqs()` and `rlm()` in the recommended MASS package), additive models (`mgcv`, also recommended), and tree-based models. Survival models are in the recommended survival package. They share the interface of this page, a formula, a `data` argument and the same generics, so the habits carry over: the recommended packages ship with R and are installed with it, and are named here without being run.

[[model-object]]
== The model object as an S3 list

A fitted `lm` is a list. `class(fit)` is `"lm"`, `is.list(fit)` is true, and `names(fit)` lists its components: `coefficients`, `residuals`, `effects`, `rank`, `fitted.values`, `assign`, `qr`, `df.residual`, `contrasts`, `xlevels`, `call`, `terms` and `model`. The `qr` component is the QR decomposition of the design matrix, `terms` the terms object (a formula with attributes, one of which is the environment), and `model` the model frame. The script prints only classes, dimensions and names for `terms` and `model`, and uses `str(fit, max.level = 1, give.attr = FALSE)`, which lists the components without descending: calling `str()` on `fit$terms` would print `+<environment: ...>+` with a memory address that changes every run.

The list is the representation; the generics are the interface. `coef(fit)` returns `fit$coefficients` for an `lm`, but an `nls` fit has no `coefficients` component at all (its parameters live in the `m` component, a closure), `coef()` still works on it, and `$` on a list matches names partially, so `fit$coef` returns the coefficients too, which is a convenience at the console and a hazard in a package. === A wrapper class of your own

You can build on a model object in the two ways described on xref:programming-languages/r/s3-classes-and-generics.adoc[S3 Classes and Generics]. A wrapper holds the fit in a component and defines methods for the generics it wants to support; a generic without a method falls through to its default, which for `residuals()` reads a `residuals` component that the wrapper does not have and returns `NULL`, with no warning. A subclass prepends a class to the fit's own class vector, keeps all `lm` behaviour, and adds a method that calls `NextMethod()` to print the extra information first. The wrapper in this script prints a one-line summary; the subclass prints a header and then the ordinary `lm` print.

[source,r]
----
source("scenario.R")

# A small wrapper class around an lm fit: a constructor, a print method and
# methods for the generics that should keep working.
new_shelf_fit <- function(fit, label) {
  stopifnot(inherits(fit, "lm"), is.character(label), length(label) == 1L)
  structure(list(fit = fit, label = label), class = "shelf_fit")
}

print.shelf_fit <- function(x, ...) {
  cat("<shelf_fit> ", x$label, "\n", sep = "")
  cat("  formula:", deparse1(formula(x$fit)), "\n")
  r2 <- round(summary(x$fit)$r.squared, 3)
  cat("  n =", nobs(x$fit), " R-squared =", r2, "\n")
  invisible(x)
}

coef.shelf_fit <- function(object, ...) coef(object$fit)
predict.shelf_fit <- function(object, ...) predict(object$fit, ...)

books$genre <- tolower(trimws(books$genre))
sf <- new_shelf_fit(lm(pages ~ year, data = books), "pages on year")

== A tidy interface with broom

== Randomness: set.seed(), simulate() and the bootstrap

Anything that draws random numbers depends on the state of the random number generator, so `set.seed()` goes before it, in the same script (see xref:programming-languages/r/distributions-and-random-numbers.adoc[Distributions and Random Numbers]). `simulate(fit, nsim)` draws new responses from the fitted model (for an `lm`, the fitted values plus normal noise with the estimated residual variance) as a data frame with one column per simulation, named `sim_1`, `sim_2` and so on. A *nonparametric bootstrap* resamples rows of the data with replacement and refits the model, and the spread of the refitted coefficients estimates their sampling variability without assuming normal errors; a *parametric bootstrap* refits on responses simulated from the model. With 13 books the bootstrap interval for the slope of `pages` on `year`, from -3.6 to 3.1, is much wider than the t interval of -1.9 to 0.1: the bootstrap exposes how little 13 points say, and a single resample can contain the same few books many times.

[source,r]
----

set.seed(282)

dim(sim)
#> [1] 13  3
names(sim)
#> [1] "sim_1" "sim_2" "sim_3"

#>   sim_1 sim_2 sim_3
#> 1   272   308   430
#> 2   405   257   380
#> 3   291   444   282

# The same seed reproduces the draw.
set.seed(282)
identical(simulate(fit, nsim = 3), sim)
#> [1] TRUE

# A nonparametric bootstrap of the slope: resample the rows, refit, collect.
set.seed(282)
slopes <- replicate(500, {
  idx <- sample(nrow(books), replace = TRUE)
  coef(lm(pages ~ year, data = books[idx, ]))[["year"]]

#> -3.581 -0.931  3.092

round(confint(fit)["year", ], 3)
#>  2.5 % 97.5 %
#> -1.904  0.115

# A parametric bootstrap from the model: simulate, refit, collect.
set.seed(282)
sim500 <- simulate(fit, nsim = 500)
slopes2 <- vapply(sim500, \(y) coef(lm(y ~ books$year))[[2L]], numeric(1))

#> [1] 0.459
round(summary(fit)$coefficients["year", "Std. Error"], 3)
#> [1] 0.459

== Pitfalls

The mistakes below are the ones that produce wrong conclusions without producing an error.

. *Independence.* The 42 usable loans come from 13 books, and the rows for one book share `pages` and `genre`. The standard errors of a book-level predictor computed from loan-level rows are too small, because the effective sample size for that predictor is the number of books. Model one row per book (here, the mean duration per book) or use a mixed model (`nlme::lme()`, `lme4::lmer()`; the R FAQ explains why `lmer()` shows no p-values, https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-are-p_002dvalues-not-displayed-when-using-lmer_0028_0029_003f[R FAQ 7.35: Why are p-values not displayed when using lmer()?]).
. *No intercept.* `pass:c[y ~ x - 1]` and `pass:c[y ~ x + 0]` drop the intercept, and R-squared is then computed against zero: a model that explains nothing can still report 75 per cent (R FAQ 7.41: https://cran.r-project.org/doc/FAQ/R-FAQ.html#Why-does-summary_0028_0029-report-strange-results-for-the-R_005e2-estimate-when-I-fit-a-linear-model-with-no-intercept_003f[Why does summary() report strange results for the R^2 estimate when I fit a linear model with no intercept?]).
. *A numeric code is not a factor.* A genre coded 1 to 6 and used as a number is a single slope; wrap it in `factor()` to get one coefficient per level.
. *In-sample fit.* The residual standard error is computed on the rows the model was fitted to and is optimistic about new data. For a linear model the leave-one-out prediction error needs no refits: it is the residual divided by one minus the hat value, which the script checks against actual refits.
. *Different rows in different models.* `AIC()` of two models fitted to different rows are not comparable; compare `nobs()`.
. *Coefficient tests are not variable tests.* A factor with six levels has five coefficients; use `anova()` or `drop1()` to test the factor as a whole.
. *Stepwise selection* gives optimistic p-values and intervals, as noted above.
. *Extrapolation.* A prediction outside the range of the predictors is a statement about the model, not the data (the intercept of the pages-and-genre model is the duration at zero pages).

source("scenario.R")
books$genre <- tolower(trimws(books$genre))
books$isbn <- normalise_isbn(books$isbn)
loan_books <- merge(loans, books, by = "isbn")
loan_books$days <- as.numeric(loan_books$return_date - loan_books$loan_date)
dur <- loan_books[!is.na(loan_books$days) & loan_books$days >= 0, ]
dur <- dur[complete.cases(dur[, c("days", "pages", "genre")]), ]

# 1. The loans are not independent: a book contributes several rows.
table(table(dur$isbn))
#>
#> 1 2 3 4 6
#> 2 3 4 1 3
length(unique(dur$isbn))
#> [1] 13

# Rows of the same book share pages and genre, so the effective sample size for
# those variables is the number of books. Model one row per book instead.
per_book <- aggregate(days ~ isbn + pages + genre, data = dur, FUN = mean)
nrow(per_book)
#> [1] 13
book_fit <- lm(days ~ pages, data = per_book)
round(coef(summary(book_fit)), 4)
#>             Estimate Std. Error t value Pr(>|t|)
#> (Intercept)  18.1409     3.4729  5.2236   0.0003
#> pages         0.0062     0.0123  0.5034   0.6246
loan_fit <- lm(days ~ pages, data = dur)
round(coef(summary(loan_fit)), 4)
#>             Estimate Std. Error t value Pr(>|t|)
#> (Intercept)  17.8693     3.7175  4.8068    0.000
#> pages         0.0068     0.0129  0.5258    0.602

# 2. No intercept: R-squared is computed against zero, not against the mean
# (R FAQ 7.41), so it is not comparable with the usual one.
with_int <- lm(days ~ pages, data = dur)
no_int <- lm(days ~ pages - 1, data = dur)
round(c(
  with_intercept = summary(with_int)$r.squared,
  no_intercept = summary(no_int)$r.squared
), 3)
#> with_intercept   no_intercept
#>          0.007          0.751
y <- dur$days
round(1 - sum(residuals(no_int)^2) / sum(y^2), 3)
#> [1] 0.751
round(1 - sum(residuals(no_int)^2) / sum((y - mean(y))^2), 3)
#> [1] -0.567

# 3. A numeric code is not a factor: genre as 1..6 forces a straight line.
dur$genre_code <- as.integer(factor(dur$genre))
length(coef(lm(days ~ genre_code, data = dur)))
#> [1] 2
length(coef(lm(days ~ factor(genre_code), data = dur)))
#> [1] 6

# 4. Fitting and testing on the same rows overstates the fit: compare the
# residual standard error with a leave-one-out prediction error.
loo <- vapply(seq_len(nrow(dur)), \(i) {
  m <- lm(days ~ pages, data = dur[-i, ])
  dur$days[i] - predict(m, newdata = dur[i, ])
}, numeric(1))
round(c(sigma = sigma(with_int), loo_rmse = sqrt(mean(loo^2))), 2)
#>    sigma loo_rmse
#>     8.74     8.96
all.equal(unname(loo), unname(residuals(with_int) / (1 - hatvalues(with_int))))
#> [1] TRUE

== Version notes

The modelling functions are old and stable; most NEWS entries since R 4.0.0 are fixes and small additions, listed here from the NEWS files of the corresponding releases (https://cran.r-project.org/doc/manuals/r-release/NEWS.html[R NEWS]). The R 4.0.0 entries are in the same file; entries older than R 4.0.0 are in the R 3.x NEWS.

[cols="1,5",options="header"]
|===
|Version |Change
|R 4.0.0 |`mle()` in `stats4` accepts arguments of the negative log-likelihood that are vectors, with bounds, start values and fixed values following the same convention (the class gained a slot, so saved `"mle"` objects from earlier versions may need to be recomputed). `plot.lm()`: the `iter.smooth` argument defaults to 0 for every `glm` fit and the residuals plotted for a `glm` are Pearson residuals; Cook's distance in `plot.lm()` is computed from the weighted residuals. `methods(class = class(glm(..)))` warns more usefully and only once.
|R 4.1.0 |`nls()` has an optional `scaleOffset` in `nls.control()` for fits that are expected to be exact, `nls(trace = TRUE)` also shows the convergence criterion, `numericDeriv()` gains `eps` and `central` (reachable through `nls.control(nDcentral = TRUE)`), and `nls()` passes `trace` and `control` to `getInitial()`, so the initial function of a self-starting model must have `+...+` in its arguments.
|R 4.3.0 |`pass:c[predict(<rank-deficient lm>, newdata = *)]` obeys a new argument `rankdeficient`, whose default `"warnif"` warns only when `newdata` has non-estimable cases (still somewhat experimental, according to the NEWS). `plot.lm()` no longer draws a normal Q-Q plot for a `glm`: it plots a half-normal Q-Q plot of the absolute standardised deviance residuals. `predict.lm()` finds the offset of a model that has one in the correct environment. `sigma()` has a method for `"glm"` (it returned misleading results for binary GLMs). The `print()` method of `"summary.glm"` no longer shows summary statistics of the deviance residuals by default (`show.residuals`). `uniroot()` no longer converges outside the interval when `abs(f(x))` is infinite at an end point.
|R 4.3.3 |`pass:c[predict(<rank-deficient lm>, newdata = *)]` fixes the computation of the number of basis vectors (PR#16158).
|R 4.4.0 |The `confint()` methods for `"glm"` and `"nls"` objects, the `"glm"` method for `profile()`, and the `plot()` and `pairs()` methods for class `"profile"` are copied from MASS to `stats`; the MASS namespace is no longer loaded by `confint(glmfit)`. `confint()` and `profile()` for a `glm` gain a `test` argument, so profiling can use the Rao score statistic instead of the likelihood ratio, and `pairs()` for profiles a `which` argument. `anova()` for a `glm` computes test statistics and p-values by default, a chi-squared test when the dispersion is fixed and an F test when it is free (`test = FALSE` suppresses them). `dummy.coef()` works for `lm` models with character predictors.
|R 4.5.0 |New `qr.influence()`, a bare-bones interface to the leave-one-out diagnostics of `lm.influence()`. `optimize(f, *)` says more about the value in its warning when `f(x)` is not finite, and no longer replaces `-Inf` by the largest positive finite number.
|R 4.5.2 |The help pages of `lm()`, `glm()`, `poly()`, and `splines::bs()` and `ns()` gained notes (the R Dev Day after Rencontres R, May 2025).
|R 4.6.0 |The default `AIC()` and `BIC()` methods check whether the `methods` namespace (not `stats4`) is loaded; `confint.default()` works on S4 objects with suitable `coef()` and `vcov()` methods; `weighted.residuals()` returns weighted working residuals for `"glm"` objects; several influence measures for `"glm"` objects use Pearson instead of deviance residuals; `plot.lm()` omits the smoother in the residuals-versus-leverage plot (`panel.raw = panel.smooth` restores it); `hatvalues()` has a method for `"nls"`; profiling `"mle"` objects no longer fails because it started from the full maximum-likelihood estimate.
|===

The R-devel NEWS (the upcoming 4.7.0, never run here) lists, among others, a `wtol` argument for `lm()` and `glm()` that treats very small weights as zero; `lm(rock)` and `glm(rock)` style calls where the first argument is a data frame, and `update()` on such a fit; correct `AIC()` and `logLik()` for a `glm` with zero weights; `model.frame.glm()` using the same logic as `model.frame.lm()`; a fix for `drop1.glm()` on models fitted with `y = FALSE`; `anova(<glm>, test = tt)` partially matching the string `tt`; named `lower` and `upper` bounds of `nls()` in any order and for a subset of the parameters; and `summary(<aov>)` warning on an almost perfect fit, as `summary(<lm>)` does (https://cran.r-project.org/doc/manuals/r-devel/NEWS.html[R-devel NEWS: Changes in R-devel]). The same file's section for the scheduled R 4.6.2 lists a fix for a long-standing bug in `nlminb()` with constraints, and an update of `influence.measures()` to match `dffits()`, `dfbetas()` and `covratio()`.

== Where older tutorials differ

[cols="3,3,4,1",options="header"]
|===
|Older tutorial writes |Current practice |Why |Since
|`pass:c[attach(df)]` and then `pass:c[lm(y ~ x)]`, or `pass:c[lm(df$y ~ df$x)]` |`pass:c[lm(y ~ x, data = df)]` |`data` is searched first and does not depend on the search path; `predict(fit, newdata = )` needs the model's variables to be plain names |always
|`pass:c[library(MASS)]` to get `confint()` on a `glm` (and the message `+Waiting for profiling to be done...+` came from MASS) |`confint(fit)` from `stats` |the `glm` and `nls` methods were copied into `stats` and MASS is not loaded |R 4.4.0
|`pass:c[anova(fit, test = "Chisq")]` always needed for a `glm` |`anova(fit)` already gives the test |chi-squared for fixed dispersion, F for estimated dispersion are the defaults; `test = FALSE` suppresses them |R 4.4.0
|`+read.csv(..., stringsAsFactors = TRUE)+` implied, so `genre` was already a factor in the data frame |character columns, turned into factors by the model function (levels sorted alphabetically, stored in `fit$xlevels`) |`stringsAsFactors = FALSE` has been the default for data frames |R 4.0.0
|The residuals-versus-leverage plot has a smoother; the `glm` Q-Q plot is a normal Q-Q plot |no smoother in the leverage plot; a half-normal Q-Q plot of absolute standardised deviance residuals for a `glm` |the NEWS says the smoother never made much sense, and deviance residuals of a `glm` are not normal |R 4.6.0, R 4.3.0
|`predict()` warns for every prediction from a rank-deficient fit |warns only when `newdata` has non-estimable rows; `rankdeficient = "NA"` returns `NA` for them |the old warning could not tell estimable from non-estimable predictions |R 4.3.0
|`nlm()` for least squares and maximum likelihood, as in the manual's examples |`optim(method = "BFGS", hessian = TRUE)`, `nlminb()` with bounds, or `stats4::mle()` for a likelihood |`nlm()` works, but `optim()` offers several methods and bounds, and `mle()` gives the standard errors, the profile intervals and the AIC without boilerplate |always
|Hand-picked starting values for every `nls()` call |a self-starting model (`SSlogis`, `SSmicmen`, ...) or `algorithm = "port"` with bounds |the start is computed from the data; bounds keep parameters in range |always
|Type III sums of squares from another package, or the default `anova()` table read as if order did not matter |`anova(model1, model2)` or `drop1(model)` |R's default `anova()` is sequential, and its numbers depend on the order of the terms (R FAQ 7.18) |always
|`pass:c[lm(log(y) ~ x)]` back-transformed with `exp()` as "the mean" |`pass:c[glm(y ~ x, family = Gamma(link = "log"))]` (or `poisson`) when the mean is the target |the exponential of the mean of the logarithm is the geometric mean, not the mean |always
|`options(na.action = na.exclude)` at the top of a script |`na.action =` as an argument of the fit that needs it |a global option changes every later model in the session, including those in other packages |always
|`pass:c[lm(y ~ x^2)]` for a quadratic |`pass:c[lm(y ~ x + I(x^2))]` or `pass:c[lm(y ~ poly(x, 2))]` |`^` is crossing in a formula (R FAQ 3.3.2) |always
|`step()` on a large pool of variables as "model selection" |a model chosen from subject knowledge, cross-validation or penalised regression |the p-values after stepwise selection ignore the search |always

Two community habits are worth a sentence each. Tutorials written for other languages often fit a model and then parse the printed `summary()`; in R, take the number from the summary object (`summary(fit)$r.squared`) or use `broom::glance()`. And the "base R, tidyverse and tidymodels" split in modelling tutorials is about workflow (the tidymodels packages wrap fitting engines, including `lm()` and `glm()`, behind one interface), not about the fitting functions on this page, which they call.
