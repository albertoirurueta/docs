== What COBOL is

COBOL (COmmon Business-Oriented Language) was specified in 1959 and is still the language in which a large share of the world's banking, insurance, government, retail batch and transaction processing runs. It is a compiled, statically typed, record-oriented language designed so that business rules read almost like prose. Two properties explain why it has survived. Its arithmetic is decimal and fixed-point (`PIC 9(7)V99`, packed decimal `COMP-3`), so money is added, rounded and truncated exactly as an accountant would on paper rather than as binary floating point. And its input and output are built around fixed-length records, sequential, indexed and relative files and, on the mainframe, VSAM, Db2 and CICS, which is the shape that high-volume batch and online processing has.

COBOL is standardized by ISO/IEC. The language has gained structured programming, intrinsic functions, user-defined functions, object orientation, pointers, UTF-16 and UTF-8 data, `JSON` and `XML` statements and, in the 2023 edition, new numeric and syntax features, while compilers keep compiling programs written decades ago. This section teaches the modern language and also the old code you will meet in maintenance work.

== Version baseline

This section is written against *ISO/IEC 1989:2023*, the current published language standard (a fourth edition is in preparation and nothing in the section depends on it). The runnable toolchain is *GnuCOBOL 3.2*, released on 28 July 2023 and still the latest release when this section was checked on 2026-10-20: every portable example was compiled with `cobc -x -Wall` (plus `-std=ibm` where the page says so) and run, and the output shown is real. The mainframe pages follow *IBM Enterprise COBOL for z/OS 6.5* with its PTFs through September 2026, on z/OS 3.2, with Db2 13 for z/OS, CICS Transaction Server 6.x and IMS 15.6. z/OS-only code (JCL, IDCAMS, DFSORT, `EXEC SQL`, `EXEC CICS`, BMS maps and IMS calls) cannot run on a laptop, so it was checked statement by statement against the IBM manuals and the pages say "z/OS; not run here". The other compilers (IBM COBOL for Linux on x86, Rocket Visual COBOL and Enterprise Developer, Fujitsu NetCOBOL) are described from their documentation, because they were not available for testing. Where a feature came from a later standard or a later compiler release, the page names the release that introduced it.

== The Circulation scenario

The examples across the section share one small, original domain: *Circulation*, the batch and online back office of a public library.

* `BOOKMAST` is an indexed book master file keyed by book number (`BOOK-ID`), with the ISBN, title, copies on the shelf, price and a status (active or withdrawn).
* `MEMBMAST` is an indexed member file (member number, name, joining date, outstanding fines and a status, active or suspended). The fines are signed zoned decimal (`PIC S9(5)V99`) so that the sample files stay readable text; xref:programming-languages/cobol/usage-and-numeric-representation.adoc[USAGE and Numeric Representation] explains packed decimal (`COMP-3`), the form a z/OS master file normally uses for such amounts.
* `LOANTRAN` is a daily sequential transaction file of checkouts and returns, each with the member, the book and the date (`YYYYMMDD`).
* The record layouts live in the copybooks `BOOKREC`, `MEMBREC` and `LOANREC`, listed in full on xref:programming-languages/cobol/copybooks-and-replace.adoc[Copybooks, COPY, and REPLACE], so the same layouts appear on every page that uses them.
* The nightly batch run sorts the transactions, applies them to the masters with a balance-line update, computes overdue fines with `ROUNDED`, prints a circulation report with control breaks and exports a JSON summary.
* On the z/OS pages the same data lives in VSAM KSDS clusters and a Db2 `LOAN` table, the batch run is a JCL job and a CICS transaction `CINQ` answers "where is this book?" (on the shelf, all copies on loan, or withdrawn) from a 3270 map.

The pages build on each other. The xref:programming-languages/cobol/cheat-sheet.adoc[cheat sheet] summarises the whole section.

== How this section relates to the others

* xref:programming-languages/c/index.adoc[C Reference]: GnuCOBOL translates COBOL to C and compiles it with the system C compiler, so C linkage, the C runtime and calling conventions matter for xref:programming-languages/cobol/interoperability-with-c-java-and-python.adoc[interoperability].
* xref:programming-languages/java/index.adoc[Java Reference]: Java and COBOL meet through the Java interoperability facilities of Enterprise COBOL, and `BigDecimal` is the Java counterpart of COBOL decimal arithmetic (see xref:programming-languages/cobol/arithmetic-and-compute.adoc[Arithmetic and COMPUTE]).
* xref:database/sql/index.adoc[SQL Reference]: SQL itself is covered there; xref:programming-languages/cobol/embedded-sql-and-db2.adoc[Embedded SQL and Db2] shows how it is embedded in COBOL.
* xref:backend/architecture/decisions-and-migrations/migration-path-legacy-to-modern-stack.adoc[Migration Path: Legacy to Modern Stack]: xref:programming-languages/cobol/modernization-strategies.adoc[Modernization Strategies] applies the same strangler-fig approach to COBOL estates.

* Zowe: the https://docs.zowe.org/stable/[documentation] and Zowe Explorer (its https://marketplace.visualstudio.com/items?itemName=Zowe.vscode-extension-for-zowe[Marketplace page] and the https://docs.zowe.org/stable/user-guide/ze-install[installation guide])
* Editors and IDEs: https://ibm.github.io/zopeneditor-about/Docs/introduction.html[IBM Z Open Editor], Broadcom https://github.com/eclipse-che4z/che-che4z-lsp-for-cobol[COBOL Language Support] (also on its https://marketplace.visualstudio.com/items?itemName=BroadcomMFD.cobol-language-support[Marketplace page]) and https://www.ibm.com/docs/en/developer-for-zos[IBM Developer for z/OS], including zUnit and z/OS Debugger
* Testing: Broadcom Test4z (its documentation is on https://techdocs.broadcom.com/[Broadcom TechDocs]; search for Test4z there, because no stable address of the product pages could be confirmed), https://galasa.dev/docs[Galasa] and https://github.com/openmainframeproject/cobol-check[COBOL Check] (archived by its owner on 28 May 2026)
* Modernization: https://www.ibm.com/products/watsonx-code-assistant-z[IBM watsonx Code Assistant for Z] and its https://www.ibm.com/docs/en/watsonx/watsonx-code-assistant-4z[documentation]
* Community tools, labelled as such: the https://github.com/opensourcecobol/Open-COBOL-ESQL[Open-COBOL-ESQL] preprocessor used for GnuCOBOL with PostgreSQL
