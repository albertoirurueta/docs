`dotnet pack` builds a project and creates a NuGet package (`.nupkg`) from it, using MSBuild properties instead of a
hand-written `.nuspec`. This page lists the command's options with **.NET SDK 10.0.402** and shows the two that
surprise people. *Authoring* a good package -- metadata, layout, symbols, validation -- is the subject of the
xref:programming-languages/csharp/build-tools/publishing/index.adoc[Publishing and Distributing Libraries] group,
starting with
xref:programming-languages/csharp/build-tools/publishing/creating-packages-with-dotnet-pack.adoc[Creating Packages with dotnet pack].

== Options

[cols="2,4",options="header"]
|===
| Option | Effect

| `-c`, `--configuration`
| **Release** by default since .NET 8 (`PackRelease`); `-c Debug` packs a debug build.

| `-o`, `--output`
| The folder for the packages (default `bin/<Configuration>`).

| `--no-build`, `--no-restore`
| Pack existing build output. `--no-build` implies `--no-restore`.

| `--version <v>` (.NET 10)
| Set the package version.

| `--version-suffix <s>`
| Set `$(VersionSuffix)`.

| `--include-symbols`
| Also create a symbol package (`.snupkg` with `SymbolPackageFormat=snupkg`, otherwise `.symbols.nupkg`).

| `--include-source`
| Create a `.symbols.nupkg` with the PDBs *and* the source files under `src/`.

| `-s`, `--serviceable`
| Set `<serviceable>true</serviceable>` in the `.nuspec`.

| `-r`, `--ucr`, `--artifacts-path`, `--interactive`, `--disable-build-servers`, `-v`
| As for `dotnet build`
(xref:programming-languages/csharp/build-tools/dotnet-cli/restore-build-and-clean.adoc[Restore, Build and Clean]).
|===

== Packing Ledgerline

[source,bash]
----
dotnet pack src/Ledgerline -o pk
dotnet pack src/Ledgerline -o pk --no-build --version 1.1.0-beta.1
dotnet pack src/Ledgerline -o pk --no-build --version-suffix rc.1
dotnet pack src/Ledgerline -o pk --no-build --include-symbols -p:SymbolPackageFormat=snupkg
----

[source,text]
----
  Successfully created package '~/ledgerline/pk/Ledgerline.1.0.0.nupkg'.
  Successfully created package '~/ledgerline/pk/Ledgerline.1.1.0-beta.1.nupkg'.
  Successfully created package '~/ledgerline/pk/Ledgerline.1.0.0.nupkg'.
  Successfully created package '~/ledgerline/pk/Ledgerline.1.0.0.snupkg'.
----

Two of the four results are not what the commands suggest:

* **`--version-suffix` did nothing.** `Ledgerline.csproj` sets `<Version>1.0.0</Version>`, and `VersionSuffix` only
  takes part when the project sets `VersionPrefix` instead (`Version` is then `$(VersionPrefix)-$(VersionSuffix)`).
  The third command silently produced `Ledgerline.1.0.0.nupkg` again.
* **`--version` with `--no-build` versions the package, not the assemblies.** `Ledgerline.1.1.0-beta.1.nupkg` has
  `<version>1.1.0-beta.1</version>` in its `.nuspec`, but its `lib/net10.0/Ledgerline.dll` still says `1.0.0.0` and
  informational version `1.0.0+e33226ff…`, because it was built before. Pass the version to the *build* (`dotnet build
  -p:Version=1.1.0-beta.1`, then `dotnet pack --no-build -p:Version=1.1.0-beta.1`), or let `dotnet pack` build.

The `.snupkg` holds only the PDBs (`lib/<tfm>/Ledgerline.pdb`). `--include-source` instead created
`Ledgerline.1.0.0.symbols.nupkg` with the PDBs and `src/Ledgerline/*.cs`, the legacy format that nuget.org does not
accept as a symbol package
(xref:programming-languages/csharp/build-tools/publishing/symbols-source-link-and-deterministic-packages.adoc[Symbols, Source Link and Deterministic Packages]).
`-s` added `<serviceable>true</serviceable>` to the `.nuspec`.

Versioning strategy is covered on
xref:programming-languages/csharp/build-tools/publishing/versioning-and-prerelease-packages.adoc[Versioning and Prerelease Packages].

Source: https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-pack#examples[dotnet pack: Examples].

== Packing without a project

`dotnet pack` also accepts a `.nuspec` file -- useful for content-only packages that have nothing to compile:

[source,xml]
----
<?xml version="1.0" encoding="utf-8"?>
<package xmlns="http://schemas.microsoft.com/packaging/2013/05/nuspec.xsd">
  <metadata>
    <id>Ledgerline.Samples</id>
    <version>1.0.0</version>
    <authors>Ledgerline contributors</authors>
    <description>Sample journal files for Ledgerline.</description>
    <license type="expression">MIT</license>
  </metadata>
  <files>
    <file src="content/*.csv" target="contentFiles/any/any/journals" />
  </files>
</package>
----

[source,bash]
----
dotnet pack Ledgerline.Samples.nuspec -o out
----

[source,text]
----
[NuGet Manager] The package Ledgerline.Samples.1.0.0 is missing a readme. Go to https://aka.ms/nuget/authoring-best-practices/readme to learn why package readmes are important.
[NuGet Manager] Successfully created package 'out/Ledgerline.Samples.1.0.0.nupkg'.
----

A file-based app (`dotnet pack balance.cs`) packs as a .NET tool, because `PackAsTool` is on by default for
file-based apps (xref:programming-languages/csharp/build-tools/dotnet-cli/run-and-file-based-apps.adoc[Run and
File-Based Apps]).

Source: https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-pack[dotnet pack],
https://learn.microsoft.com/en-us/nuget/reference/msbuild-targets[NuGet pack and restore as MSBuild targets].

== Deterministic packs

From SDK 10.0.400, `-p:Deterministic=true -p:DeterministicTimestamp=<time>` makes two packs of the same build output
byte-for-byte identical (ZIP entry times and the `.psmdcp` part). With SDK 10.0.402, exporting `SOURCE_DATE_EPOCH`
alone was not enough; passing it as `DeterministicTimestamp` was. The experiment is on
xref:programming-languages/csharp/build-tools/reproducible-and-deterministic-builds.adoc[Reproducible and Deterministic Builds].

== Common mistakes

* *`--version-suffix` on a project that sets `Version`* -- ignored without a warning.
* *`--version` with `--no-build`* -- package and assembly versions disagree.
* *`--include-source` for nuget.org symbols* -- use `--include-symbols -p:SymbolPackageFormat=snupkg`.
* *Packing Debug by habit* -- `pack` defaults to Release since .NET 8; do not override it.
