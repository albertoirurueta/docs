NuGet reports problems with `NUxxxx` codes, grouped by hundreds: **NU10xx** project and CPM configuration, **NU11xx**
resolution, **NU13xx** sources, **NU14xx** lock files and integrity, **NU15xx** project content, **NU16xx** dependency
graph warnings, **NU17xx** compatibility, **NU18xx** source warnings and **NU19xx** auditing. This page gives a method
and the real messages, almost all reproduced on the other NuGet pages with **NuGet 7.9.0** (.NET SDK 10.0.402); each
row links where.

== A diagnosis method

. **Read the first NU code and its page** --
  `https://learn.microsoft.com/nuget/reference/errors-and-warnings/nuNNNN` (each page has *Issue* and *Solution*).
. **Restore alone, verbosely.** `dotnet restore -v:detailed` shows the sources queried (`GET`/`CACHE`), the
  `nuget.config` files used and why versions were chosen; `-bl` records it for the Structured Log Viewer.
. **Rule out caches.** `--no-http-cache`, an empty `RestorePackagesPath`, or `dotnet nuget locals all --clear`
  (xref:programming-languages/csharp/build-tools/nuget/global-packages-and-cache-folders.adoc[Global Packages and Cache Folders]).
. **Explain the graph.** `dotnet nuget why <project> <package>` and `dotnet package list --include-transitive`
  (xref:programming-languages/csharp/build-tools/nuget/dependency-resolution.adoc[Dependency Resolution]).

Source: https://learn.microsoft.com/en-us/nuget/reference/errors-and-warnings[NuGet errors and warnings reference].

The documentation prints NU1701 as "restored using 'TargetFrameworkA' **instead the** project target framework"; the
real message reads "instead of the".

NU1803 is the pre-.NET 9 warning that NU1302 replaced -- and it comes back when `SdkAnalysisLevel` is lowered. The same
HTTP source that fails with NU1302 by default produced only NU1803 with `-p:SdkAnalysisLevel=8.0.400`. The HTTPS
requirement is therefore one of the SDK behaviours that `SdkAnalysisLevel` controls, which is worth knowing before
using that property to quiet new warnings
(xref:programming-languages/csharp/build-tools/dotnet-cli/format-and-code-analysis.adoc[Format and Code Analysis]).

== Documentation gaps

* **NU1606** and **NU1607** appear in the errors-and-warnings index but have no page (the URLs return 404).
* **NU1020**, the .NET 11 minimum-publish-age error (`minPublishAgeHours`), has no page yet.
* NU1902 and NU1903/NU1904 share the NU1901-NU1904 page.

== Common mistakes

* *Fixing the last NU code first* -- the first one usually causes the rest.
* *Clearing every cache before reading the message* -- slow, and it hides the evidence.
* *Suppressing NU1605, NU1608 or NU1701 globally* -- each describes a real run-time risk.
* *Lowering `SdkAnalysisLevel` to silence one warning* -- it also relaxes other checks, such as HTTPS enforcement.
