NuGet takes its sources, credentials, folders and policies from `nuget.config` files. Several files usually apply at
once -- one in the repository, one per user, sometimes one per machine -- and their merge order explains most "it
restores on my machine" problems. This page covers the files and every section with **NuGet 7.9.0** (.NET SDK
10.0.402), using *Ledgerline*'s configuration.

== Which files apply

[cols="1,3",options="header"]
|===
| Level | Location

| Folder ("solution") | `nuget.config` (any casing) in the current folder and **every parent folder** up to the drive root.
| User | Windows `%appdata%\NuGet\NuGet.Config`; macOS/Linux `+~/.nuget/NuGet/NuGet.Config+` for the .NET CLI (Mono tools use `+~/.config/NuGet/NuGet.Config+`). Additional, read-only files: `+…/NuGet/config/*.config+`.
| Computer | Windows `%ProgramFiles(x86)%\NuGet\Config`; Linux `/etc/opt/NuGet/Config`; macOS `/Library/Application Support` (or `$NUGET_COMMON_APPLICATION_DATA/NuGet/Config`).
|===

`dotnet nuget config paths` lists the files that apply in a folder, closest first:

[source,bash]
----
cd ~/ledgerline && dotnet nuget config paths
----

[source,text]
----
~/ledgerline/nuget.config
~/.nuget/NuGet/NuGet.Config
----

The user file was created by the first `dotnet` NuGet operation on this profile, with nuget.org as its only source.
The documentation's two macOS/Linux user paths are a real inconsistency between tools: the .NET CLI used
`+~/.nuget/NuGet+`, as shown.

== How settings merge

NuGet reads the files from the computer level up to the closest one. For a single value (`globalPackagesFolder`), the
closest file wins. For lists (`packageSources`), entries **accumulate** across files -- unless a file contains
`<clear />`, which drops everything inherited from farther files.

A source added at user level:

[source,bash]
----
dotnet nuget add source ~/ledgerline/artifacts/feed --name user-feed
cd ~/scratch && dotnet nuget list source
cd ~/ledgerline && dotnet nuget list source
----

[source,text]
----
Package source with Name: user-feed added successfully.
Registered Sources:
  1.  nuget.org [Enabled]
      https://api.nuget.org/v3/index.json
  2.  user-feed [Enabled]
      ~/ledgerline/artifacts/feed
Registered Sources:
  1.  nuget.org [Enabled]
      https://api.nuget.org/v3/index.json
  2.  ledgerline-local [Enabled]
      ~/ledgerline/artifacts/feed
  3.  ledgerline-bagetter [Enabled]
      http://localhost:5555/v3/index.json
----

Outside the repository the user source applied; inside *Ledgerline* it did not, because the repository file starts its
`packageSources` with `<clear />`. A repository that wants identical restores everywhere should `<clear />` and list
every source it needs -- otherwise each developer's and agent's user and computer files add sources silently.

`NuGetDefaults.Config` (in the NuGet program-data folder) is the place for administrators to *add* default sources and
disable others for every user of a machine; it cannot remove sources that users add.

Source: https://learn.microsoft.com/en-us/nuget/consume-packages/configuring-nuget-behavior#how-settings-are-applied[How settings are applied],
https://learn.microsoft.com/en-us/nuget/consume-packages/configuring-nuget-behavior#settings-walkthrough[Settings walkthrough],
https://learn.microsoft.com/en-us/nuget/consume-packages/configuring-nuget-behavior#nuget-defaults-file[NuGet defaults file].

== Ledgerline's nuget.config

[source,xml]
----
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" protocolVersion="3" />
    <add key="ledgerline-local" value="./artifacts/feed" />
    <add key="ledgerline-bagetter" value="http://localhost:5555/v3/index.json" allowInsecureConnections="True" />
  </packageSources>
  <packageSourceMapping>
    <packageSource key="nuget.org">
      <package pattern="*" />
    </packageSource>
    <packageSource key="ledgerline-local">
      <package pattern="Ledgerline" />
      <package pattern="Ledgerline.*" />
    </packageSource>
  </packageSourceMapping>
</configuration>
----

Relative paths (`./artifacts/feed`) are relative to the file. The local BaGetter source is plain HTTP and needs
`allowInsecureConnections`, and it is *not* in the mapping, so no package is ever restored from it -- it is a push
target only
(xref:programming-languages/csharp/build-tools/nuget/package-sources-and-source-mapping.adoc[Package Sources and Source Mapping]).
`dotnet nuget config get all` prints the merged result for the current folder:

[source,text]
----
packageSources:
	clear
	add key="nuget.org" value="https://api.nuget.org/v3/index.json" protocolVersion="3"
	add key="ledgerline-local" value="./artifacts/feed"
	add key="ledgerline-bagetter" value="http://localhost:5555/v3/index.json" allowInsecureConnections="True"

packageSourceMapping:
	packageSource key="nuget.org"
	packageSource key="ledgerline-local"
----

Source: https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-config-get[dotnet nuget config get],
https://learn.microsoft.com/en-us/nuget/reference/nuget-config-file#example-config-file[nuget.config reference: Example config file].

== The sections

[cols="1,3",options="header"]
|===
| Section | Contents

| `config` | Single values: `globalPackagesFolder`, `repositoryPath` (packages.config), `defaultPushSource`, `http_proxy`, `signatureValidationMode`, `maxHttpRequestsPerSource`, `dependencyVersion`, …
| `packageRestore` | `enabled`, `automatic` -- restore on build in Visual Studio.
| `packageSources` | The sources, with `protocolVersion`, `allowInsecureConnections` and (.NET 11) `minPublishAgeHours`.
| `auditSources` | Sources used only for vulnerability data (xref:programming-languages/csharp/build-tools/nuget/auditing-packages-for-vulnerabilities.adoc[Auditing Packages for Vulnerabilities]).
| `packageSourceCredentials` | Per-source `Username`, `Password`/`ClearTextPassword`, `ValidAuthenticationTypes` (xref:programming-languages/csharp/build-tools/nuget/authenticated-feeds-and-credential-providers.adoc[Authenticated Feeds and Credential Providers]).
| `apikeys` | Encrypted push keys stored by `nuget.exe setapikey`.
| `disabledPackageSources` | Sources listed but disabled.
| `activePackageSource` | Visual Studio's selected source.
| `trustedSigners` | Trusted authors and repositories (xref:programming-languages/csharp/build-tools/nuget/signed-packages-and-trust-policies.adoc[Signed Packages and Trust Policies]).
| `fallbackPackageFolders` | Read-only folders searched before downloading.
| `packageSourceMapping` | Which source may supply which package IDs.
| `packageManagement` | `format` (`0` PackageReference, `1` packages.config) and `disabled` -- Visual Studio defaults.
| `bindingRedirects`, `solution` | Visual Studio / packages.config settings.
|===

== Environment variables

Values can reference environment variables as `%NAME%` on every platform:

[source,xml]
----
<packageSources>
  <add key="team" value="%LEDGER_FEED%" />
</packageSources>
----

[source,bash]
----
LEDGER_FEED=/srv/feeds/ledger dotnet nuget list source
----

[source,text]
----
Registered Sources:
  1.  team [Enabled]
      /srv/feeds/ledger
  2.  nuget.org [Enabled]
      https://api.nuget.org/v3/index.json
----

This is how CI supplies tokens without committing them: `+<add key="ClearTextPassword" value="%FEED_TOKEN%" />+` in
`packageSourceCredentials`. The folder file (`team`) is listed before the user file's sources.

Source: https://learn.microsoft.com/en-us/nuget/reference/nuget-config-file#using-environment-variables[nuget.config reference: Using environment variables].

== Changing settings from the CLI

[source,bash]
----
dotnet nuget config set defaultPushSource https://example.invalid/v3/index.json --configfile ./nuget.config
dotnet nuget config unset defaultPushSource --configfile ./nuget.config
----

`set` added a `<config>` section to the file:

[source,xml]
----
<config>
  <add key="defaultPushSource" value="https://example.invalid/v3/index.json" />
</config>
----

Without `--configfile`, `set` and `unset` change the **user** file. `get <key>` prints one effective value (`--show-path`
adds the file it came from); for a key that no file sets, it printed `+error: Key 'globalPackagesFolder' not found.+` --
even though the folder has a default -- so use `dotnet nuget locals global-packages --list` for folder locations.

Source: https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-config-set[dotnet nuget config set],
https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-config-unset[dotnet nuget config unset].

== Common mistakes

* *No `<clear />` in the repository file* -- user and machine sources leak into restores.
* *A `nuget.config` in a project folder* -- it only applies to commands run from that folder or below.
* *Credentials committed in `packageSourceCredentials`* -- use `%VARIABLES%` or a credential provider.
* *Expecting `dotnet nuget config get` to show defaults* -- it shows configured values only.
