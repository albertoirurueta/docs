**NuGet** is the package manager of .NET: a package format (`.nupkg`, a ZIP with a manifest), a protocol for feeds, the
public registry **nuget.org**, and the client built into the `dotnet` CLI, MSBuild, Visual Studio and `nuget.exe`.
This group covers the **consuming** side -- how packages are found, versioned, resolved, restored, configured,
audited and trusted -- at **NuGet 7.9.0**, the version in .NET SDK 10.0.400 and 10.0.402 (and in `nuget.exe` 7.9.0).
Producing and publishing packages is the
xref:programming-languages/csharp/build-tools/publishing/index.adoc[Publishing and Distributing Libraries] group; the
C# Reference's introduction is
xref:programming-languages/csharp/namespaces-assemblies-and-projects.adoc#_nuget_packages[Namespaces, Assemblies and
Projects -- NuGet Packages].

== Creators, hosts and consumers

[mermaid]
....
flowchart LR
    C["Creators<br/>dotnet pack, nuget pack"] -- "push .nupkg" --> H["Hosts<br/>nuget.org, Azure Artifacts,<br/>GitHub Packages, BaGetter, folders"]
    H -- "search, restore" --> U["Consumers<br/>dotnet restore, Visual Studio,<br/>nuget.exe"]
    U -. "become creators of<br/>their own packages" .-> C
....

A package declares its dependencies; a consuming project records only the packages it uses directly
(`PackageReference`); **restore** computes the full graph and downloads what is missing, so packages are never committed
to source control.

Source: https://learn.microsoft.com/en-us/nuget/what-is-nuget#the-flow-of-packages-between-creators-hosts-and-consumers[What is NuGet: The flow of packages],
https://learn.microsoft.com/en-us/nuget/what-is-nuget#managing-dependencies[Managing dependencies],
https://learn.microsoft.com/en-us/nuget/what-is-nuget#tracking-references-and-restoring-packages[Tracking references and restoring packages].

== The client tools

[cols="1,3",options="header"]
|===
| Client | Use

| `dotnet` CLI | `dotnet restore`, `dotnet package …`, `dotnet nuget …`, `dotnet pack` -- every platform, all SDK-style projects (xref:programming-languages/csharp/build-tools/nuget/dotnet-package-and-nuget-commands.adoc[dotnet package and nuget Commands]).
| MSBuild | `msbuild -t:restore`, `-t:pack` -- the same NuGet code as the CLI (xref:programming-languages/csharp/build-tools/nuget/package-restore.adoc[Package Restore]).
| Visual Studio | Package manager UI and Package Manager Console, Windows (xref:programming-languages/csharp/build-tools/nuget/nuget-exe-visual-studio-and-packages-config.adoc[nuget.exe, Visual Studio and packages.config]).
| `nuget.exe` | Standalone CLI, needed mainly for `packages.config` projects.
|===

Support follows the host: the NuGet inside an SDK is supported as long as that SDK, the NuGet in Visual Studio as long
as that Visual Studio; for `nuget.exe` only the **latest** version is fully supported, patched versions are released only
for critical security fixes for LTS releases, and out-of-support or vulnerable versions are removed from the
`tools.json` feed. Not every feature is in every client -- `packages.config` restore, for example, needs `nuget.exe` or MSBuild, not
`dotnet` -- and the "feature availability" table in the documentation lists which client version brought what.

Source: https://learn.microsoft.com/en-us/nuget/install-nuget-client-tools#tools-overview[Install NuGet client tools: Tools overview],
https://learn.microsoft.com/en-us/nuget/install-nuget-client-tools#support-policy[Support policy],
https://learn.microsoft.com/en-us/nuget/install-nuget-client-tools#patch-releases[Patch releases],
https://learn.microsoft.com/en-us/nuget/install-nuget-client-tools#nugetexe-unlisting[nuget.exe unlisting],

== nuget.org

nuget.org is the default source -- `https://api.nuget.org/v3/index.json`, the V3 service index
(xref:programming-languages/csharp/build-tools/nuget/nuget-server-api.adoc[NuGet Server API]). It repository-signs every
package, publishes vulnerability data, reserves ID prefixes for verified owners, and never deletes a published version
(it can only be unlisted). Accounts, API keys and Trusted Publishing are covered in the publishing group.

Source: https://learn.microsoft.com/en-us/nuget/nuget-org/overview-nuget-org#api-endpoint-for-nugetorg[nuget.org overview: API endpoint].

== Baseline and history

[source,bash]
----
dotnet nuget --version
----

[source,text]
----
7.9.0-rc.611+a8dd0577c5c13f43a2f57fe33b4ff11b90f6371e.a8dd0577c5c13f43a2f57fe33b4ff11b90f6371e
----

Visual Studio 2026 18.10 carries NuGet 7.10.0, a Visual Studio-only release; the .NET 11 release candidates carry a NuGet
8.0 prerelease. The milestones for consumers:

[cols="1,4",options="header"]
|===
| NuGet | Change

| 4.9 | lock files; trusted signers
| 6.0 | package source mapping
| 6.4 | Central Package Management production ready
| 6.8 (.NET 8) | NuGetAudit
| 6.11 | `dotnet nuget why`
| 6.12 (.NET 9) | new dependency resolver; HTTP sources are errors (NU1302)
| 7.0 (.NET 10) | transitive auditing and package pruning for `net10.0`+; `dotnet package update`
| 7.9 (SDK 10.0.4xx) | this group's baseline
| 8.0 (.NET 11 preview) | minimum publish age
|===

The full table, with the SDK and Visual Studio mapping, is on
