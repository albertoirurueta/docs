https://ant.apache.org/[Apache Ant] is an XML-driven build tool and a Java library of tasks. A build file (`build.xml`) names
targets, each target is a list of tasks such as `javac`, `jar`, `copy` or `junitlauncher`, and targets declare the targets they
depend on. Ant has no built-in conventions: it does not know where the sources live, what a test is or how a library is
versioned, so every one of those decisions is written into the build file. That is its strength and its cost. A build file is
explicit, runs the same way on any machine with a JDK, and can be read top to bottom; it also grows long, and each project
reinvents its own layout. Ant started inside the Tomcat code base, where it existed to build Tomcat, and became an independent
Apache project afterwards (see the https://ant.apache.org/faq.html[Ant FAQ]).

== Where Ant fits today

Ant is still a sound choice for a build that is mostly file and process orchestration: legacy projects whose build file already
works, builds that must call many external programs in a precise order, and builds that need a very small, dependency-free
tool. For a new library or application, Maven and Gradle bring a standard layout, dependency management and a plugin ecosystem
that Ant leaves to the build author. xref:programming-languages/jvm-build-tools/comparing-ant-maven-and-gradle.adoc[Comparing Ant, Maven & Gradle]
gives the side-by-side verdict and
xref:programming-languages/jvm-build-tools/migrating-between-tools.adoc[Migrating Between Tools] shows how to leave Ant when it
stops being the right fit.

Ant itself does not resolve dependencies. Two companions add that, and both have pages in this section:

* *Apache Ivy 2.6.0*, a dependency manager that runs inside Ant: an `ivy.xml` file declares the module and its configurations,
  `ivy:resolve` and `ivy:retrieve` fetch the libraries, and `ivy:publish` deploys the result. It starts at
  xref:programming-languages/jvm-build-tools/ant/ivy-overview.adoc[Ivy Overview].
* The *Maven Resolver Ant Tasks 2.0.0*, which expose Maven's own resolver to Ant, so a build can resolve, install and deploy with
  Maven coordinates and Maven repositories without Ivy. They are covered on
  xref:programming-languages/jvm-build-tools/ant/maven-resolver-ant-tasks.adoc[Maven Resolver Ant Tasks].

The concepts behind both are on
xref:programming-languages/jvm-build-tools/dependency-management-fundamentals.adoc[Dependency Management Fundamentals].
