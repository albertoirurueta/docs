This section is written against *Fortran 2023* (ISO/IEC 1539-1:2023, read in its final draft J3/23-007r1), the current published standard. Its first corrigendum (2026) is a bug-fix document and changes no feature used here, and Fortran 2028 is only a work in progress: the committee draft stage has been reached and nothing in the section depends on it, but the preview page says what is coming. Every program was compiled and run on 2026-10-18 with GNU Fortran 16.2 (`-std=f2023 -Wall -Wextra -pedantic -fimplicit-none -fcheck=all`) and, where a page says so, with LLVM Flang 23; Intel ifx 2026.1 and the other commercial compilers are described from their manuals, because they were not available for testing. The tools around the language are at fpm 0.13.0, stdlib 0.8.1, fortls 3.2.2 and test-drive 0.6.1, with OpenMP 6.0, OpenACC 3.4 and MPI 5.0 as the parallel specifications. Features newer than Fortran 2008 are marked with the standard that introduced them, and the pages say which compilers do not accept them yet.

== What Fortran is

Fortran (FORmula TRANslation) is the oldest high-level programming language still in wide use: the first compiler shipped for the IBM 704 in 1957. It is a compiled, statically typed, array-oriented language that ISO/IEC standardizes, designed so that a compiler can turn mathematical formulas over large arrays into fast machine code. That is why weather and climate models, computational fluid dynamics, quantum chemistry, astrophysics and many numerical libraries are written and still being extended in it.

Modern Fortran is far from the punched-card language of its reputation. Since Fortran 90 it has free-form source, modules, whole-array expressions and dynamic memory with `allocatable`; later revisions added derived types with type-bound procedures and polymorphism (Fortran 2003), coarrays and `do concurrent` (2008), teams, events and collectives (2018) and, in 2023, conditional expressions, `rank`-independent code, enumeration types and the `split` and `tokenize` string intrinsics. Parallelism is part of the language through coarrays and `do concurrent`, and OpenMP, OpenACC and MPI have first-class Fortran bindings. Compilers include GNU Fortran, LLVM Flang, Intel ifx, NAG, the HPE Cray and NVIDIA compilers; the community maintains the Fortran Package Manager (fpm), a standard library (stdlib), a language server (fortls) and a documentation generator (FORD).

== The heatflow scenario

The examples across the section share one small, original, numerical domain: *heatflow*, a solver for heat diffusion on a rectangular plate, organised as an fpm project (`fpm.toml`, `src/`, `app/`, `test/` and `example/`). Fortran is used where numbers are the point, so, unlike the Rust, Go and Ruby references, it deliberately does not use the *shelf* library catalogue.

* `heatflow_kinds` defines the `dp` kind from `iso_fortran_env`, and `heatflow_constants` the defaults.
* `grid_t` is a derived type holding the sizes, the spacing and an allocatable temperature field `u(:,:)`, with a constructor function.
* The boundary condition (`dirichlet`, `neumann`, `periodic`) is an enumeration; the `enum, bind(c)` form is the one the compilers accept today.
* An abstract `solver_t` with a deferred `step` binding is extended by `jacobi_solver_t` and `ftcs_solver_t`, implemented in submodules, with a `final` procedure.
* A run configuration is read from a namelist file, and results are written as CSV and as unformatted stream files, with defined derived-type I/O for `grid_t`.
* Parallel variants of the stencil use `do concurrent` (with `reduce` for the residual), OpenMP, a coarray halo exchange across images and an `mpi_f08` domain decomposition.
* A `bind(c)` C API, a C client, a Python wrapper built with f2py and Meson and a MATLAB MEX gateway call the same kernel.
* Tests with test-drive, a CMake build next to the fpm build and FORD documentation grow alongside the code.

The pages build on each other, and the xref:programming-languages/fortran/fortran-for-programmers-of-other-languages.adoc[comparison page] maps heatflow concepts to the xref:programming-languages/c/index.adoc[C] and the xref:programming-languages/python/index.adoc[Python] and xref:programming-languages/rust/index.adoc[Rust] references.
