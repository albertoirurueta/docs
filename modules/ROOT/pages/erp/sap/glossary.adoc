= SAP Glossary
:description: Alphabetical glossary of the general SAP terms used in the SAP section, from client, company code and transport request to SAP BTP, CAP, SAP Fiori and OData, each in plain words with a link to the page that explains it, for SAP S/4HANA 2025 and Cloud Public Edition.
:keywords: SAP glossary, SAP terms, SAP S/4HANA, SAP BTP, CAP, Fiori, UI5, OData, client, company code, transport, definitions

include::partial$ai-disclaimer.adoc[]

This glossary explains, in plain words, the general SAP terms used across the SAP section of this documentation, such as client, company code, transport request, SAP BTP, CAP and OData, and links each one to the page that teaches it. Use it when a page uses an abbreviation or product name you have not met. Terms specific to finance or to human resources are in the Finance Glossary and the HR Glossary of this section. Terms are listed alphabetically.

== A

[[abap-application-server]]ABAP application server::
The middle layer of an SAP system, the part that actually runs the ABAP programs and holds the business logic. Users reach it from a browser or SAP GUI, and it in turn reads and writes the database. See xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

[[atc]]ABAP Test Cockpit (ATC)::
A tool that automatically checks ABAP code against quality rules and, where they apply, rules about which objects may be used. Teams run it before a change moves on so that problems are found early. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[abap-unit]]ABAP Unit::
The built-in framework for writing automated tests of ABAP code. A test is a small piece of ABAP that calls your code and checks the result, so you can rerun it after every change. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[accounting-document]]Accounting document::
The record that a business posting leaves behind in financial accounting, with its debit and credit lines. A goods receipt or a supplier invoice, for example, each produce one. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[adaptation-transport-organizer]]Adaptation Transport Organizer (ATO)::
The tool that collects changes made in the test system of SAP S/4HANA Cloud Public Edition so they can be moved on to the production system. It plays the role that the transport tools of an ABAP system play in an on-premise landscape. See xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

[[adapter]]Adapter::
The part of an integration flow that knows how to speak one communication protocol, such as HTTPS or mail, so the flow can receive or send messages with another system. See xref:erp/sap/integration-suite-and-business-accelerator-hub.adoc[SAP Integration Suite and Business Accelerator Hub].

[[annotation]]Annotation::
A short piece of extra information attached to an entity or a field that tells a user interface how to present it, for example which columns a list shows. Fiori elements reads annotations to generate screens instead of someone drawing them. See xref:erp/sap/fiori-elements.adoc[SAP Fiori Elements].

[[api-management]]API Management::
The capability of SAP Integration Suite for publishing APIs and protecting them. It lets a company expose a back-end service in a controlled way, apply security and traffic rules, and watch how the API is used. See xref:erp/sap/api-management.adoc[API Management].

[[api-product]]API product::
A bundle of one or more API proxies, usually with a usage quota, that developers can subscribe to. It is what you offer to API users, as opposed to the individual proxies behind it. See xref:erp/sap/api-management.adoc[API Management].

[[api-proxy]]API proxy::
A front door that API Management puts in front of a back-end service. Callers talk to the proxy, which applies policies such as security checks and rate limits and then forwards the request, so the real back end stays hidden. See xref:erp/sap/api-management.adoc[API Management].

[[apirule]]APIRule::
A resource of the Kyma environment that makes a service running in the cluster reachable from the Internet under a host name. It also says which paths and HTTP methods are allowed and how callers must be checked. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

[[app-descriptor]]App descriptor::
The file manifest.json of a UI5 app, a settings file that says what the app is called, which version it is, which data sources it uses and how the launchpad may navigate to it. See xref:erp/sap/deploying-apps-to-the-fiori-launchpad.adoc[Deploying Apps to the SAP Fiori Launchpad].

[[ale]]Application Link Enabling (ALE)::
A technology for sending business data between separate SAP systems, or between SAP and other systems, without the sender waiting for the answer. The data usually travels as IDocs. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[application-router]]Application router::
The single entry point in front of a cloud application. It signs the user in and forwards each request to the right part of the application, such as the server module. See xref:erp/sap/cap-deployment-and-mta.adoc[Deploying CAP: HANA, XSUAA and MTA].

[[application-service]]Application service::
The service object that CAP creates for each service defined in your model. It already knows how to read and write data, and your own handlers are added to it to change or extend that behavior. See xref:erp/sap/cap-services-and-handlers-nodejs.adoc[Services and Custom Handlers in Node.js].

[[aspect]]Aspect::
A reusable bundle of fields or annotations in a CDS model that you can include in an entity or add to it later, so that common parts such as an ID or change timestamps are written once. See xref:erp/sap/cap-domain-modeling.adoc[CAP Domain Modeling].

[[association]]Association::
A reference from one entity to another in a CDS model, like a foreign key that points to a related record. The target exists on its own and does not depend on the entity that refers to it. See xref:erp/sap/cap-domain-modeling.adoc[CAP Domain Modeling].

[[authentication]]Authentication::
Proving who is calling, for example with a password or a signed token. It answers the question who you are, before anyone decides what you may do. See xref:erp/sap/cap-security.adoc[CAP Security].

[[authorization]]Authorization::
Deciding what a caller who has already been identified may do and with which data. It follows authentication and is checked for each action. See xref:erp/sap/cap-security.adoc[CAP Security].

[[authorization-object]]Authorization object::
A building block of the ABAP authorization concept that groups several authorization fields. A concrete permission is a set of allowed values for the fields of one such object. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

== B

[[bapi]]BAPI::
A standard, documented function that SAP delivers for working with a business object, such as reading or creating a sales order, and that other systems can call remotely. It is the supported alternative to writing straight into the database tables. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[billing-document]]Billing document::
The document, mostly an invoice, that ends the sales process by charging the customer. It also creates the posting in accounting. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[building-block]]Building block::
A ready-made, reusable piece of a Fiori elements page, such as a table or a filter bar, that you can place on a page you build yourself while keeping the standard behavior. See xref:erp/sap/fiori-elements.adoc[SAP Fiori Elements].

[[buildpack]]Buildpack::
A bundle of the runtime, libraries and services that an application of a given language needs. Cloud Foundry combines it with your code to produce something it can run, so you do not set up the runtime yourself. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

[[business-catalog]]Business catalog::
In SAP S/4HANA Cloud Public Edition, a bundle of apps that belong to one task or sub-process. Business roles are assembled from business catalogs. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[business-context]]Business context::
The place in a standard SAP application where a custom field can be added. Choosing it decides on which screens, reports and documents the new field appears. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

[[business-event]]Business event::
A short message announcing that something significant happened to a business object, such as a sales order being created. Other applications can listen for it without the sender knowing who they are. See xref:erp/sap/business-events.adoc[Business Events].

[[business-partner]]Business partner::
The single central record in SAP S/4HANA for a person, organization or group the company does business with. One partner can be customer and supplier at once, so its data is stored only once. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[business-partner-category]]Business partner category::
The basic type of a business partner: person, organization or group. It is chosen when the partner is created and cannot be changed afterward. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[business-partner-role]]Business partner role::
The part a business partner plays, such as customer or supplier. A role decides which additional data is kept for the partner and which business functions can use it. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[business-role]]Business role::
A set of permissions and launchpad content assigned to a user, based on a job function. It decides which apps the person sees and what they may do in them. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[business-user]]Business user::
A user of SAP S/4HANA Cloud Public Edition, created for an employee or other worker, who receives business roles that decide which apps and data are available. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

== C

[[calculation-view]]Calculation view::
A database view in SAP HANA that you build graphically from steps such as join, projection and aggregation, instead of writing one long query by hand. See xref:erp/sap/sap-hana-basics.adoc[SAP HANA Basics].

[[cap-role]]CAP role::
A plain business name, such as Employee, that a CDS annotation refers to when it restricts access. An administrator, or a test setup, assigns the role to users. See xref:erp/sap/cap-security.adoc[CAP Security].

[[catalog]]Catalog::
A collection of tiles and target mappings, with the technical information needed to start each app, that is assigned to roles. The roles a user has decide which catalogs, and so which apps, the launchpad shows. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

[[cds]]CDS (Core Data Services)::
Core Data Services (CDS)::
A text language for describing business data and services. In CAP you declare entities, relationships, services and annotations in CDS, and CAP builds the database tables and interfaces from that description. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[cds-view]]CDS view::
A database view that is defined with Core Data Services instead of plain SQL. It describes which data to read and how to present it, and it also carries annotations that tell applications how to use it. See xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

[[cds-dk]]cds-dk::
The CAP development kit, a package of command line tools that includes the cds command. You use it to create a CAP project, run it locally and compile its models. See xref:erp/sap/cap-getting-started.adoc[CAP Getting Started].

[[cds-test]]cds.test::
A helper of CAP that starts a service inside an automated test and lets the test send HTTP requests to it, so you can check the service without starting it by hand. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[central-finance]]Central Finance::
A setup in which one SAP S/4HANA system receives the financial postings of other systems, which can be SAP or non-SAP systems, so the company can report on them in one place. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

[[change-and-transport-system]]Change and Transport System (CTS)::
The set of tools of an ABAP system that records changes in transport requests and moves them through the systems of a landscape, for example from development to test to production. See xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

[[ci-cd]]CI/CD::
Short for continuous integration and continuous delivery. Every change is built and tested automatically, and a tested build is then moved toward production with as little manual work as possible. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[citizen-developer]]Citizen developer::
A person in a business role, not a professional programmer, who builds applications or automations with low-code or no-code tools. See xref:erp/sap/sap-build-low-code.adoc[SAP Build].

[[clean-core]]Clean core::
The practice of keeping the standard SAP system unmodified and adding your own functions beside it, using only released interfaces. This keeps upgrades simple. See xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core].

[[client]]Client::
A separate business unit inside one SAP system that you choose at sign-in, with its own master data and its own set of data. Users see only the data of the client they logged on to. See xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape].

[[client-dependent-data]]Client-dependent data::
Data that belongs to exactly one client and cannot be read or changed from another client, such as a customer record or a sales order. See xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape].

[[cloud-connector]]Cloud Connector::
A program you install in your own network that opens a secure connection from inside to SAP BTP. Only the systems and paths you allow can be reached through it, so no incoming firewall opening is needed. See xref:erp/sap/btp-connectivity-and-destinations.adoc[Connectivity, Destinations and Cloud Connector].

[[cloud-erp]]Cloud ERP::
ERP software that a vendor runs and updates as a service, so the company subscribes to it instead of operating the servers itself. See xref:erp/overview.adoc[ERP Overview].

[[cloud-foundry-environment]]Cloud Foundry environment::
One of the environments of a subaccount on SAP BTP, in which the open-source Cloud Foundry platform runs your applications and services. It organizes them in an org and its spaces. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

[[cloud-integration]]Cloud Integration::
The capability of SAP Integration Suite that receives messages, changes them as needed and passes them on. It runs the integration flows that connect systems. See xref:erp/sap/integration-suite-and-business-accelerator-hub.adoc[SAP Integration Suite and Business Accelerator Hub].

[[cloud-public-edition]]Cloud Public Edition::
The cloud version of SAP S/4HANA in which many customers share one SAP-run system and SAP upgrades it twice a year. Customers configure it rather than modify it. See xref:erp/sap/deployment-options.adoc[Deployment Options].

[[cloudevents]]CloudEvents::
A public specification that describes event data in a common format, so that different systems can read each other's events. See xref:erp/sap/business-events.adoc[Business Events].

[[column-store]]Column store::
A way of storing a table in which the values of one column are kept together. It suits queries that read a few columns of many rows and it compresses well. See xref:erp/sap/sap-hana-basics.adoc[SAP HANA Basics].

[[command-field]]Command field::
The input box at the top left of the SAP GUI window in which you type a transaction code, or a command that begins with a slash, to go straight to a function instead of using the menu. See xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

[[communication-arrangement]]Communication arrangement::
In SAP S/4HANA Cloud and ABAP Cloud, the administrator's setup that connects a communication scenario to a communication system and its credentials, so that a defined interface can be used. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[company-code]]Company code::
The smallest organizational unit in SAP for which a complete, self-contained set of accounting books can be kept, typically one legal company. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

[[compatibility-scope]]Compatibility scope::
Functions of the older SAP ERP suite that S/4HANA still contains for a limited time and with limited usage rights, to give customers time to move to the newer functions. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[composite-role]]Composite role::
A role that only collects other roles, so a single assignment gives a user all of them. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[composition]]Composition::
A part-of relationship in a CDS model in which the child entries belong to one parent and are created, read and deleted together with it, such as the items of an order. See xref:erp/sap/cap-domain-modeling.adoc[CAP Domain Modeling].

[[condition-record]]Condition record::
A stored price, discount or surcharge that applies to a given customer, product and period. Pricing reads condition records to work out the price of an order. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[configuration-data]]Configuration data::
The settings, also called Customizing, that decide how the standard software behaves in one company. It differs from master data, which describes things such as customers, and from transactional data, which records events. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[connectivity-service]]Connectivity service::
The SAP BTP service that, together with the Cloud Connector, lets an application on BTP reach systems that run in a company's own network. See xref:erp/sap/btp-connectivity-and-destinations.adoc[Connectivity, Destinations and Cloud Connector].

[[consumer-proxy]]Consumer proxy::
Generated ABAP code that packs a call into a SOAP message, sends it to a web service and reads the answer, so your program can call the service like an ordinary method. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[consumption-view]]Consumption view::
A view of the virtual data model with the prefix C_ that is made for one use, such as an app or an analytical query, and builds on the more general interface views. See xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

[[content-density]]Content density::
The sizing of controls on an SAP Fiori screen: cozy is roomy and meant for touch, compact is tighter and meant for mouse and keyboard. See xref:erp/sap/fiori-design-guidelines.adoc[SAP Fiori Design Guidelines].

[[ui5-controller]]Controller::
The JavaScript file that belongs to one view of a UI5 app and reacts to what the user does, such as pressing a button. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[controlling-area]]Controlling area::
The organizational unit in which costs and revenues are analyzed for management accounting. It can span one or several company codes. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

[[cql]]CQL (Conceptual Query Language)::
The SQL-like language in which CAP queries are written. It is independent of any particular database, so the same query works on SQLite and on SAP HANA. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[cqn]]CQN (Core Query Notation)::
The plain-data form of a query that CAP passes around at run time before it is translated into SQL for the database. It is what a query written in CQL or sent through OData turns into. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[cross-client-data]]Cross-client data::
Data that exists once per system and is the same and visible in every client of that system, such as the repository of programs and dictionary objects, or the public holiday calendar among the cross-client Customizing settings. See xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape].

[[csn]]CSN (Core Schema Notation)::
The machine-readable form that CDS source files are compiled to. The CAP runtimes and the compiler targets read it rather than the source text. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[csrf-token]]CSRF token::
A one-time value that a client must send along with a write request, so that a request forged by another web page is rejected. The client first asks the service for the token and then includes it. See xref:erp/sap/odata-and-sap-gateway.adoc[OData and SAP Gateway].

[[custom-business-object]]Custom business object::
A business object that you define yourself with the key-user tools, for which the database tables, services and screens are generated. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

[[customer-supplier-integration]]Customer/Supplier Integration (CVI)::
The link that keeps the older customer and supplier master records and the business partner in step in SAP S/4HANA. It is also called Customer/Vendor Integration in older material. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[customizing]]Customizing::
Configuring an SAP system by choosing settings instead of writing programs. For example, you define which company codes exist and how documents are numbered. See xref:erp/sap/customizing-and-implementation-guide.adoc[Customizing and the Implementation Guide].

[[customizing-client]]Customizing client::
The client in which configuration settings, and possibly development, are made before they are transported to the next system. See xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape].

[[customizing-request]]Customizing request::
A transport request that records the Customizing settings you changed, so they can be moved to the next system of the landscape. See xref:erp/sap/customizing-and-implementation-guide.adoc[Customizing and the Implementation Guide].

[[cutover]]Cutover::
The activities of the last days before go-live, between switching off the old systems and switching on the new one, such as the final data load. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

== D

[[data-binding]]Data binding::
The link that keeps an element on the screen and a value in a data model equal, in one direction or both, so a change in one shows up in the other. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[data-masking]]Data masking::
Replacing personal data in a prompt before it is sent to an AI model, so the model never sees the real names or numbers. See xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI].

[[deep-insert]]Deep insert::
A single request that creates a parent entry together with its child entries, for example an order with its items. See xref:erp/sap/cap-domain-modeling.adoc[CAP Domain Modeling].

[[design-principles]]Design principles::
The five rules that every SAP Fiori screen is meant to follow: role-based, adaptive, simple, coherent and delightful. See xref:erp/sap/fiori-design-guidelines.adoc[SAP Fiori Design Guidelines].

[[destination]]Destination::
A named set of connection details, such as the target address, proxy type and sign-in method, that an application looks up by name instead of hard-coding them. See xref:erp/sap/btp-connectivity-and-destinations.adoc[Connectivity, Destinations and Cloud Connector].

[[destination-service]]Destination service::
The SAP BTP service that stores destinations and carries out the sign-in steps configured in them when an application calls a remote system. See xref:erp/sap/btp-connectivity-and-destinations.adoc[Connectivity, Destinations and Cloud Connector].

[[developer-extensibility]]Developer extensibility::
Extensions that ABAP developers write directly in the S/4HANA system, in ABAP for Cloud Development, using only released objects. See xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core].

[[developer-hub]]Developer Hub::
The self-service portal of API Management where application developers find APIs, create applications and get the keys they need to call them. See xref:erp/sap/api-management.adoc[API Management].

[[directory]]Directory::
An optional folder on SAP BTP that groups subaccounts and other directories. It is only a way of organizing, so you cannot use a service at directory level. See xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model].

[[draft]]Draft::
An unfinished copy of a business object that the server keeps until the user saves or discards it, so work in progress is not lost and does not touch the active data. See xref:erp/sap/fiori-elements.adoc[SAP Fiori Elements].

[[dynamic-page]]Dynamic page::
The standard page layout of SAP Fiori, made of a header, a content area and a footer toolbar. Several floorplans are built on it. See xref:erp/sap/fiori-design-guidelines.adoc[SAP Fiori Design Guidelines].

== E

[[edmx]]EDMX::
The XML file that describes an OData service: its entities, properties and associations. CAP can read it to work with a remote service. See xref:erp/sap/cap-consuming-remote-services.adoc[Consuming SAP APIs from CAP].

[[end-to-end-process]]End-to-end process::
A chain of steps that runs across several departments and SAP modules from a trigger to a final result, such as from a purchase order to the payment of the supplier invoice. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[enterprise-structure]]Enterprise structure::
The set of organizational units of one SAP system, such as client, company code and plant, together with the assignments between them. It mirrors how the company is organized. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

[[entitlement]]Entitlement::
Your right to provision and consume a service plan on SAP BTP, for example to create a certain number of instances of a service. See xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model].

[[entity]]Entity::
A named structure of typed fields with a primary key. In CAP you declare entities in CDS, and in a relational database each one becomes a table. See xref:erp/sap/cap-domain-modeling.adoc[CAP Domain Modeling].

[[erp]]ERP::
Enterprise resource planning: business software that keeps the money, sales, purchasing, production and people data of a company together in one integrated system. See xref:erp/overview.adoc[ERP Overview].

[[event-handler]]Event handler::
A function registered with a service that runs before, on or after a given event. This is where your own business logic lives in a CAP application. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[event-mesh]]Event Mesh::
The SAP BTP service that carries business events between applications through topics and queues, so senders and receivers do not need to know each other. See xref:erp/sap/integration-suite-and-business-accelerator-hub.adoc[SAP Integration Suite and Business Accelerator Hub].

[[extensibility]]Extensibility::
The official ways in which customers and partners adapt standard SAP software to their own needs without changing the standard code. See xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core].

[[extension-item]]Extension item::
Anything you create with the key-user tools, such as a custom field, a piece of custom logic or a custom CDS view. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

== F

[[feature-pack-stack]]Feature pack stack (FPS)::
A package of corrections and small functional improvements that SAP delivers every six months between two major releases of on-premise SAP S/4HANA. See xref:erp/sap/deployment-options.adoc[Deployment Options].

[[fit-to-standard]]Fit-to-standard::
A way of starting an implementation in which the business sees the standard processes on a working system and records only the differences it still needs, instead of writing requirements from scratch. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

[[floorplan]]Floorplan::
A page template for one kind of task, such as listing objects or showing a single object. Fiori elements generates floorplans such as the list report and the object page. See xref:erp/sap/fiori-design-guidelines.adoc[SAP Fiori Design Guidelines].

== G

[[gardener]]Gardener::
The open-source project that creates and manages the Kubernetes clusters on which a Kyma environment runs. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

[[generative-ai-hub]]Generative AI hub::
The part of SAP AI Core that gives governed access to generative AI models, so applications can use them through one controlled entry point. See xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI].

[[generic-provider]]Generic provider::
The built-in behavior of a CAP service that answers reads and writes, validates data and fills in defaults from the model alone, so a service works before you write any code. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[global-account]]Global account::
The top level of the SAP BTP account model, which stands for the contract with SAP. From it you manage subaccounts, members, entitlements and quotas. See xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model].

[[goods-receipt]]Goods receipt::

[[grounding]]Grounding::

[[horizon-theme]]Horizon theme::

[[html5-application-repository]]HTML5 Application Repository::

[[hypercare]]Hypercare::
The period of intensive support by the project team in the first weeks after go-live, when users meet real problems for the first time. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

== I

[[identity-authentication]]Identity Authentication::
The SAP Cloud Identity Services service that signs users in and provides single sign-on, so one login works across several applications. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

[[identity-provider]]Identity provider::
The system that holds the users and checks who they are when they sign in, such as an SAP Cloud Identity Services tenant. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

[[idoc]]IDoc::
An intermediate document, a structured message that SAP systems use to exchange business data, for example in ALE and EDI. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[idoc-type]]IDoc type::
The technical structure of an IDoc, which segments and fields it contains, for example ORDERS01 for orders. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[img]]Implementation Guide (IMG)::
The tree of configuration activities, each with its documentation, that leads a team through the Customizing of an SAP system. It is opened with the transaction SPRO. See xref:erp/sap/customizing-and-implementation-guide.adoc[Customizing and the Implementation Guide].

[[input-help]]Input help::
The list of allowed values for a field in SAP GUI, opened with the F4 key, so you can pick a value instead of remembering it. See xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

[[instance-based-authorization]]Instance-based authorization::
An access rule that depends on the individual data row, such as allowing users to see only the claims that they created themselves. See xref:erp/sap/cap-security.adoc[CAP Security].

[[integration-flow]]Integration flow::
The graphical model in Cloud Integration that says how one kind of message is received, processed and sent on. See xref:erp/sap/integration-suite-and-business-accelerator-hub.adoc[SAP Integration Suite and Business Accelerator Hub].

[[intent]]Intent::
A pairing of a semantic object and an action, which the Fiori launchpad turns into a concrete app when a user opens it. It lets tiles and links name what the user wants to do instead of naming a specific app. See xref:erp/sap/deploying-apps-to-the-fiori-launchpad.adoc[Deploying Apps to the SAP Fiori Launchpad].

[[interface-view]]Interface view::
A view of the virtual data model with the prefix I_ that presents business data in a stable form to the rest of the model and to applications. See xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

== J

[[joule]]Joule::
SAP's AI assistant, which brings assistants and agents into the flow of work so that people can ask for information or actions in plain language. See xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI].

[[joule-agent]]Joule agent::
A purpose-built piece of software that carries out a business task in several steps on behalf of a user, for example collecting data and preparing a result. See xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI].

[[jwt]]JSON Web Token (JWT)::
A signed token that carries claims, which are pieces of information about the user, to an application, so the application can check the signature and trust the claims without asking the sign-in system each time. Which claims a token holds depends on the sign-in system and its settings. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

== K

[[key-user-extensibility]]Key user extensibility::
Key-user extensibility::
Changing and extending SAP applications with built-in apps, by business experts who do not need a development environment, for example by adding a custom field. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

[[kyma-environment]]Kyma environment::
One of the environments of a subaccount on SAP BTP, which provides managed Kubernetes clusters based on the open-source project Kyma. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

== L

[[least-privilege]]Least privilege::
The rule that a user, or a technical connection, gets only the permissions its task needs and nothing more, which limits the damage if an account is misused. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[line-of-business]]Line of business (LoB)::
A line of business is one area of a company's work, such as finance or manufacturing. SAP groups the functions of S/4HANA by these areas so that people can find the software that fits their department. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[logical-port]]Logical port::
When an ABAP system calls a SOAP web service, the logical port holds the settings for that call, such as the address it sends requests to. It belongs to the consumer proxy, the generated code that makes the call. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[low-code]]Low-code and no-code::
Low-code means building an application mostly with drag-and-drop editors and forms, writing little code. No-code goes one step further and needs no programming at all, so people close to the business can build simple apps. See xref:erp/sap/sap-build-low-code.adoc[SAP Build].

== M

[[manifest-json]]manifest.json::
A small settings file in a UI5 app that tells the framework which data models the app uses, which screens it can navigate between and which UI libraries it needs. UI5 reads it when the app starts. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[master-data]]Master data::
Master data is the information about the lasting things a business deals with, such as customers, suppliers, products and accounts. It is created once, changed rarely and reused by many business events. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[mrp]]Material requirements planning (MRP)::
Material requirements planning is a planning run that compares what customers will need with the stock and the incoming receipts. It then proposes what to buy or to produce, and when. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[message-type]]Message type::
In IDoc exchange, the message type is the name of the business function a document carries, such as ORDERS for an order. It tells the receiving system what kind of business message arrived. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[metadata-document]]Metadata document::
A file that describes an OData service in a form programs can read: which data sets it offers and which fields each has. It is served at the service address followed by `$metadata`. See xref:erp/sap/odata-and-sap-gateway.adoc[OData and SAP Gateway].

[[mocked-authentication]]Mocked authentication::
A login that CAP offers for local development, with a few fixed test users. It lets you try access rules without a real identity provider and is meant for development only. See xref:erp/sap/cap-security.adoc[CAP Security].

[[mocking]]Mocking::
Mocking means letting a simple local stand-in answer in place of a real system. With CAP, a remote service can be mocked from sample data, so you can develop and test without access to the real system. See xref:erp/sap/cap-consuming-remote-services.adoc[Consuming SAP APIs from CAP].

[[erp-module]]Module::
A module is the part of an ERP system that serves one business area, such as finance, procurement or sales. The modules share one database so that a change in one area is visible in the others. See xref:erp/overview.adoc[ERP Overview].

[[module]]Module::
In the older SAP systems a module is a functional area with a short code, such as FI for financial accounting or SD for sales and distribution. S/4HANA still uses these names, although it presents its functions by line of business. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[mta-archive]]MTA archive (MTAR)::
The MTA archive, with the file ending .mtar, is one file that packs the deployment description and the built content of every part of a multitarget application. It is the file that you hand to the deployment tool. See xref:erp/sap/cap-deployment-and-mta.adoc[Deploying CAP: HANA, XSUAA and MTA].

[[multitarget-application]]Multitarget application (MTA)::
A multitarget application is one application made of several parts, such as a server, a database deployer and an application router. They are described by one file, `mta.yaml`, and built, deployed and versioned together. See xref:erp/sap/cap-deployment-and-mta.adoc[Deploying CAP: HANA, XSUAA and MTA].

[[multitenancy]]Multitenancy::
Multitenancy means that one running application serves several customers, called tenants, while keeping each customer's data apart. It lets a provider run a single copy of the software for many customers. See xref:erp/sap/cap-deployment-and-mta.adoc[Deploying CAP: HANA, XSUAA and MTA].

[[mvc]]MVC (Model View Controller)::
A way of organizing an app into three parts: the model holds the data, the view shows it on screen and the controller holds the code that reacts to the user and connects the two. UI5 apps follow this split. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[my-home]]My Home::
My Home is the landing page that a user sees when opening the launchpad. It has sections for to-dos, pages, apps and insights. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

[[my-inbox]]My Inbox::
An app in the launchpad that gathers the tasks waiting for a person's decision, such as approvals, in one list. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

== N

[[new-implementation]]New implementation::
A new implementation is a fresh installation of S/4HANA, without taking over an old system. It is also called a greenfield implementation, and the company decides again how its processes should run. See xref:erp/sap/deployment-options.adoc[Deployment Options].

== O

[[odata]]OData::
OData is a standard way to read and change data over the web. It uses ordinary HTTP requests and addresses data as collections and entities in a URL, and SAP uses it for its APIs and for apps. See xref:erp/sap/odata-and-sap-gateway.adoc[OData and SAP Gateway].

[[on-premise]]On-premise::
On premise::
On-premise software is installed and run on the company's own servers, or on servers that the company rents and manages itself. The customer is responsible for operating and updating it. See xref:erp/sap/deployment-options.adoc[Deployment Options].

[[opa5]]OPA5::
OPA5 stands for One Page Acceptance tests. It is the SAPUI5 way of writing a test that clicks through one running page of an app and checks what appears. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[openui5]]OpenUI5::
OpenUI5 is the open-source edition of the UI5 framework for browser applications, licensed under the Apache License 2.0. SAPUI5 is the edition that SAP ships with its products. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[orchestration]]Orchestration::
In SAP's generative AI hub, orchestration is a service that wraps a call to a language model in extra steps such as filling a template, adding company data, masking sensitive text and filtering the result. See xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI].

== P

[[page]]Page::
In the launchpad, a page is a screen that arranges apps as tiles in sections. Pages are placed inside spaces. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

[[partner-profile]]Partner profile::
The settings, kept for each partner system, that say which messages the partner may exchange, through which port, and how incoming messages are processed. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[persistence-service]]Persistence service::
In CAP Java, the persistence service is the database client. It accepts queries on any stored entity and runs them against the database. See xref:erp/sap/cap-java.adoc[CAP Java].

[[pipeline]]Pipeline::
A pipeline is a fixed list of steps, called stages, that a server runs automatically after each change, for example to build, test and deploy the software. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[plant]]Plant::
A plant is a place in the company's structure where goods are produced, bought, maintained or planned. Materials are managed per plant. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

[[api-policy]]Policy::
In API management, a policy is a small configured step that does one job on a request or a response, such as checking a key or limiting how much traffic is allowed. See xref:erp/sap/api-management.adoc[API Management].

[[cloud-private-edition]]Private Edition::
The Private Edition is the cloud variant of S/4HANA that has its own system for each customer. SAP sells it within the RISE with SAP offering, and it is hosted by SAP or by a large cloud provider. See xref:erp/sap/deployment-options.adoc[Deployment Options].

[[product-master]]Product master::
The product master is the master record of a material or product. It holds the data that purchasing, inventory, sales and production need about it. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[production-order]]Production order::
A production order is the document that tells the factory which material to make, with which components and in which operations. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[project-img]]Project IMG::
A project IMG is a view of the implementation guide built for one implementation project. It lists only the configuration activities that the project selected. See xref:erp/sap/customizing-and-implementation-guide.adoc[Customizing and the Implementation Guide].

[[project-piper]]Project Piper::
Project Piper is SAP's open-source collection of ready-made pipeline steps, available as a library and as a command line tool. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[projection]]Projection::
In CAP's modeling language, a projection defines an entity as a selection of the fields of another entity, optionally with new names. It is a way to expose only what a service needs. See xref:erp/sap/cap-consuming-remote-services.adoc[Consuming SAP APIs from CAP].

[[protocol-adapter]]Protocol adapter::
A protocol adapter is the part of the CAP runtime that turns web requests of one protocol, such as OData, into requests that do not depend on the protocol, and turns the answers back. See xref:erp/sap/cap-concepts.adoc[CAP Concepts].

[[pseudo-role]]Pseudo role::
A pseudo role is a role, such as `authenticated-user`, that the CAP runtime assigns by itself depending on how the caller logged in. You do not assign it to users. See xref:erp/sap/cap-security.adoc[CAP Security].

[[purchase-order]]Purchase order::
A purchase order is the document with which a company orders materials or services from a supplier. See xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes].

[[purchasing-organization]]Purchasing organization::
The purchasing organization is the unit of the company that buys materials and services and negotiates the conditions with suppliers. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

== Q

[[queue]]Queue::
A queue is a place where a messaging service keeps events for one consumer until the consumer takes them. See xref:erp/sap/business-events.adoc[Business Events].

[[qunit]]QUnit::
QUnit is the JavaScript unit test framework that SAPUI5 uses for small tests of code. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[quota]]Quota::
A quota is the amount of a service plan that an account may use. It is a number that limits consumption. See xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model].

== R

[[read-access-logging]]Read access logging::
Read access logging records who looked at particularly sensitive data and when. It is switched on only for the data that you choose. See xref:erp/sap/security-and-operations.adoc[Security and Operations].

[[released-api]]Released API::
A released API is an SAP object that SAP has marked as stable for use by your own code, so that upgrades are meant not to break it. Clean-core extensions rely on such objects. See xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core].

[[rfc]]Remote Function Call (RFC)::
A Remote Function Call is a call of a function module in another system through SAP's RFC interface. It is the classic way for two SAP systems, or an SAP system and a program, to call each other. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[remote-service]]Remote service::
A remote service is a service that runs somewhere else, such as an SAP API. CAP lets your code call it in the same way as a local service. See xref:erp/sap/cap-consuming-remote-services.adoc[Consuming SAP APIs from CAP].

[[restriction-type]]Restriction type::
A restriction type is a group of restriction fields, such as company code or plant, that limits which data a business role may see or change. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[rfc-destination]]RFC destination::
An RFC destination is a named entry, maintained with transaction SM59, that stores where a remote call goes and how to log on there. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[rpa]]Robotic process automation (RPA)::
Robotic process automation uses software bots that repeat clicks and data entry in existing screens, so people no longer need to do such repetitive work by hand. See xref:erp/sap/sap-build-low-code.adoc[SAP Build].

[[pfcg-role]]Role (PFCG)::
A role in an ABAP system is a set of menu entries and authorizations that matches a job. It is maintained in transaction PFCG and assigned to users. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

[[role-collection]]Role collection::
In SAP BTP, a role collection is a group of application roles that an administrator assigns to users or user groups in one step. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

[[role-template]]Role template::
A role template is a blueprint in an application's security descriptor. It bundles scopes and attributes into a role that administrators can later use. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

[[rbac]]Role-based access control (RBAC)::
Role-based access control is the Kubernetes way of deciding what a user may do: permissions are put into roles, and roles are given to users or groups. See xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[Cloud Foundry and Kyma Environments].

SAP Logon is the small program that lists the systems you may open. It starts SAP GUI for the system you choose. See xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

[[sap-note]]SAP Note::
An SAP Note is a document from SAP that describes a correction or a recommendation. It is referred to by its number. See xref:erp/sap/security-and-operations.adoc[Security and Operations].

[[sap-reference-img]]SAP Reference IMG::
The SAP Reference IMG is the complete implementation guide that SAP delivers, with the configuration activities of all applications. See xref:erp/sap/customizing-and-implementation-guide.adoc[Customizing and the Implementation Guide].

[[sap-s4hana]]SAP S/4HANA::
SAP S/4HANA is SAP's current core ERP system, built on the SAP HANA database and the SAP Fiori user interface. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[migration-cockpit]]SAP S/4HANA migration cockpit::
The SAP S/4HANA migration cockpit is an SAP Fiori app that moves business data from another system into S/4HANA using migration objects. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

[[sap-solution-manager]]SAP Solution Manager::
SAP Solution Manager is the earlier on-premise product for application lifecycle management. SAP Cloud ALM succeeds it. See xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

[[sap-successfactors]]SAP SuccessFactors::
SAP SuccessFactors is SAP's cloud product for human resources. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[sapui5]]SAPUI5::
SAPUI5 is the edition of the UI5 framework for browser applications that SAP ships with its products. It includes more libraries than the open-source OpenUI5. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[sapui5-abap-repository]]SAPUI5 ABAP repository::
The SAPUI5 ABAP repository is the place in an ABAP system where the files of a SAPUI5 app are stored and from where they are served. See xref:erp/sap/deploying-apps-to-the-fiori-launchpad.adoc[Deploying Apps to the SAP Fiori Launchpad].

[[scope]]Scope::
A scope is a named permission that an application declares in its security descriptor and checks while it runs. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

[[secure-by-default]]Secure by default::
Secure by default is SAP's approach of delivering a system with the recommended protective settings already switched on. See xref:erp/sap/security-and-operations.adoc[Security and Operations].

[[security-audit-log]]Security audit log::
The security audit log is a technical record of security-relevant events, such as logons and transaction starts, kept for auditors. See xref:erp/sap/security-and-operations.adoc[Security and Operations].

[[selective-data-transition]]Selective data transition::
Selective data transition is a path between a new implementation and a system conversion. A tool carves chosen configuration and data out of the old system and moves it into the new one. See xref:erp/sap/implementation-projects-and-go-live.adoc[Implementation Projects and Go-Live].

[[semantic-object]]Semantic object::
A semantic object stands for a business thing, such as an expense claim, that apps and links refer to by name. Together with an action it forms the intent that starts an app. See xref:erp/sap/deploying-apps-to-the-fiori-launchpad.adoc[Deploying Apps to the SAP Fiori Launchpad].

[[session]]Session::
A session is one SAP GUI window of a logon. One logon can have several sessions. See xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

[[side-by-side-extensibility]]Side-by-side extensibility::
Side-by-side extensibility means building extensions that run on SAP BTP, outside the S/4HANA system. They talk to it through released interfaces. See xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core].

[[simplification-item]]Simplification item::
A simplification item is one entry of the Simplification List. It describes the change to one transaction, function or data structure. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[simplification-list]]Simplification List::
The Simplification List is the SAP document that lists, item by item, what changed between SAP ERP and SAP S/4HANA. Teams use it to plan a move. See xref:erp/sap/what-is-sap.adoc[What Is SAP].

[[soap]]SOAP::
SOAP is an XML message format for web services, sent over HTTP. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

[[software-collection]]Software collection::
A software collection is the bundle of extension items that you export from one system and import into the next. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

[[space]]Space::
A space is a top-level area of the launchpad, shown as a tab or ribbon. It frames one or more pages and is assigned to business roles. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

[[sqlscript]]SQLScript::
SQLScript is the extension of SQL in SAP HANA for writing procedures, functions and table variables. See xref:erp/sap/sap-hana-basics.adoc[SAP HANA Basics].

[[storage-location]]Storage location::
A storage location is the unit that separates the stocks of a material inside one plant. See xref:erp/sap/organizational-structures.adoc[Organizational Structures].

[[subaccount]]Subaccount::
A subaccount is the unit of an SAP BTP global account, tied to one region, in which you run applications, use services and manage subscriptions. See xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model].

[[system-conversion]]System conversion::
System conversion (brownfield)::
A system conversion is the guided technical process that turns an existing SAP ERP system into S/4HANA, keeping its data, custom code and configuration. It is also called brownfield. See xref:erp/sap/deployment-options.adoc[Deployment Options].

[[system-landscape]]System landscape::
The system landscape is all the SAP systems of a company or application area, linked by transport routes, for example development, quality and production. See xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape].

[[system-query-option]]System query option::
A system query option is an option in an OData URL that starts with a dollar sign, such as `$filter`, and shapes the answer. See xref:erp/sap/odata-and-sap-gateway.adoc[OData and SAP Gateway].

== T

[[target-mapping]]Target mapping::
A target mapping is the launchpad setting that says which app an intent starts. See xref:erp/sap/deploying-apps-to-the-fiori-launchpad.adoc[Deploying Apps to the SAP Fiori Launchpad].

[[tile]]Tile::
A tile is the clickable square or link in the launchpad that starts an app. See xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad].

[[topic]]Topic::
A topic is the address an event is published to. Consumers name the topics they care about. See xref:erp/sap/business-events.adoc[Business Events].

[[transaction-code]]Transaction code::
A transaction code is a short name, such as `SU01`, that starts one screen or task in SAP GUI. See xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

[[transactional-data]]Transactional data::
Transactional data are the records that each business event adds, such as a sales order or an invoice. They refer to master data. See xref:erp/sap/master-data-and-business-partner.adoc[Master Data and the Business Partner].

[[tls]]Transport Layer Security (TLS)::
Transport Layer Security is the protocol that encrypts web connections. It was known earlier as Secure Sockets Layer (SSL). See xref:erp/sap/security-and-operations.adoc[Security and Operations].

[[transport-management-system]]Transport Management System (TMS)::
The Transport Management System is the part of the Change and Transport System, started with transaction `STMS`, that defines the landscape and runs imports. See xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

[[transport-request]]Transport request::
A transport request is a container that records changes so that they can be moved to the next system of the landscape. See xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

[[trust-configuration]]Trust configuration::
A trust configuration is the setting in a subaccount that makes it accept logins from one identity provider. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].

== U

[[ui5-tooling]]UI5 Tooling (UI5 CLI)::
UI5 Tooling is the command line tool, started with the `ui5` command, that serves, builds and checks UI5 projects. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[user-master-record]]User master record::
The user master record is the record that makes a person or a technical connection known to an ABAP system. It holds the logon data, the assigned roles and the resulting authorizations. See xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

== V

[[virtual-data-model]]Virtual data model (VDM)::
The virtual data model is the set of CDS views, with common naming and modeling rules, through which S/4HANA exposes its business data. See xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

[[virtual-host]]Virtual host::
A virtual host is the made-up host name that the cloud side uses for an internal system. The Cloud Connector maps it to the real internal host and port. See xref:erp/sap/btp-connectivity-and-destinations.adoc[Connectivity, Destinations and Cloud Connector].

== W

[[wdi5]]wdi5::
wdi5 is an end-to-end test tool for SAPUI5 applications that runs in a real browser. See xref:erp/sap/ci-cd-and-testing.adoc[CI/CD and Testing].

[[webhook]]Webhook::
A webhook is a web address of the consumer to which a messaging service pushes each event. See xref:erp/sap/business-events.adoc[Business Events].

[[wsdl]]WSDL::
WSDL is the XML file that describes a web service, its operations and its messages. See xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

== X

[[xml-view]]XML view::
An XML view is a UI5 screen described as an XML file that names the UI controls to show. See xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics].

[[xsuaa]]XSUAA::
XSUAA is the SAP Authorization and Trust Management service. It acts as the OAuth 2.0 authorization server for applications on SAP BTP and issues the tokens that applications check. See xref:erp/sap/btp-security-xsuaa-and-identity.adoc[Security: XSUAA and Cloud Identity Services].
