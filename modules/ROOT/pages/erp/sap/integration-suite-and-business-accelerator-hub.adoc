= SAP Integration Suite and Business Accelerator Hub
:description: A newcomer's tour of SAP Integration Suite (Cloud Integration, API Management, event capabilities, Integration Advisor, Migration Assessment) and of the SAP Business Accelerator Hub catalog, as described in the product documentation of 2026 for SAP BTP.
:keywords: SAP Integration Suite, Cloud Integration, integration flow, iFlow, adapter, API Management, Event Mesh, Advanced Event Mesh, Integration Advisor, Open Connectors, Migration Assessment, SAP Process Orchestration, SAP PI/PO, SAP Business Accelerator Hub, api.sap.com, SAP BTP

A company that runs SAP S/4HANA rarely runs only SAP S/4HANA. Orders arrive from a web shop, invoices go to a bank, a
supplier sends an electronic document, a mobile app asks for customer data. Something has to carry each of these
messages from one system to the other, translate the formats and make sure nothing is lost. SAP sells that something
as SAP Integration Suite, a set of integration services that runs on SAP Business Technology Platform (SAP BTP). This
page explains what the suite contains, in which situations each part is used, how synchronous and asynchronous
integration differ, and how to browse the public catalog of ready-made interfaces, the SAP Business Accelerator Hub.
After reading it you can name the right capability for a simple integration task and find the matching SAP interface
description without logging in anywhere. The page follows the SAP Help Portal documentation as read on 2026-11-13. It
applies to SAP Integration Suite on SAP BTP in the Cloud Foundry environment, and it applies to SAP S/4HANA Cloud
Public Edition, SAP S/4HANA Cloud Private Edition and SAP S/4HANA on premise alike, because the suite sits next to the
ERP system and does not run inside it. Everything on this page needs an SAP BTP account to try for real, so no command
was run for it; the one catalog page that needs no account was opened in a browser.

== What SAP Integration Suite is

The official overview describes SAP Integration Suite as an "integration platform-as-a-service" that connects the
applications, data and processes of a company and beyond it. The service runs in the SAP BTP, Cloud Foundry
environment, and the integration content it runs can execute on SAP BTP or inside a private landscape. It is sold as one
service with several capabilities: the Cloud Integration page states that Cloud Integration, API Management,
Integration Advisor, Open Connectors and the other capabilities are not available separately, but only as part of the
Integration Suite service plan. A free service plan exists, and SAP Note 2903776 describes which feature set each plan
offers.

The overview lists these capabilities. The descriptions are shortened and put in plain words.

[cols="1,3,3"]
|===
|Capability |What it does |Typical use

|Cloud Integration
|Integrates SAP and non-SAP, cloud and on-premise applications and processes messages in real time, inside one company
or across companies.
|Send a purchase order from SAP S/4HANA to a supplier system and return the confirmation.

|API Management
|Gives access to digital assets through APIs, and lets you protect, govern and publish them.
|Offer a customer data service to partners with limits and keys.

|Event Mesh (and Advanced Event Mesh)
|Publishes and consumes business events across applications.
|Tell every interested system that a business partner changed.

|Open Connectors
|Prebuilt connectors to more than 160 non-SAP applications.
|Read contacts from a third-party service without writing a client.

|Integration Advisor
|Speeds up the design of business-oriented interfaces and mappings, using crowdsourcing and machine learning.
|Map your own order format to an industry message format.

|Trading Partner Management
|Manages business-to-business relationships with many trading partners in one user interface.
|Onboard a new supplier that exchanges electronic documents.

|OData Provisioning
|Gives access to data of SAP Business Suite through OData services.
|Expose data of an older SAP system as OData.

|Integration Assessment
|Helps define an integration landscape with the Integration Solution Advisory Methodology.
|Write down the integration strategy of a company.

|Migration Assessment
|Assesses existing integration scenarios in order to migrate them to SAP Integration Suite; the features list names SAP Process Orchestration scenarios.
|Estimate the effort of moving old interfaces to the cloud.

|Data Space Integration
|Offers, consumes and maintains assets in a data space.
|Share data with partners in a data space.
|===

Source: https://help.sap.com/docs/integration-suite/sap-integration-suite/what-is-sap-integration-suite[What is SAP Integration Suite?]

The same overview also names API Composition and Edge Integration Cell. The first exposes business data as a connected
data graph through one API, and the second lets a company run integrations inside an environment it manages itself,
which suits strict data or deployment requirements. This page does not go further into either one.

== Cloud Integration: integration flows and adapters

Cloud Integration is the part that moves messages. Its central object is the integration flow, often shortened to
iFlow. The official getting started page defines it: an integration flow "allows you to specify how SAP Cloud
Integration is to process a message", and it is designed in a graphical modeling environment in which you place the
senders, the receivers and the individual processing steps. You work in the SAP Cloud Integration Web UI, whose address
ends with `/itspaces`, and an integration flow always lives inside an integration package, which you create first.

A sender or receiver is connected to the flow through an adapter. An adapter is a connector that knows one protocol: it
accepts or sends the messages of that protocol and hands the content to the processing steps in between. Cloud
Integration comes with a set of prebuilt adapters for SAP and non-SAP systems on premise and in the cloud. The getting
started exercises use three of them as examples: an HTTPS sender adapter, an adapter that calls an external OData API,
and a mail adapter. If a protocol is missing, the Adapter Development Kit lets a developer build a custom adapter, and
the documentation has a section on developing custom adapters.

The getting started page walks through four integration flows of growing complexity:

. A smoke test that creates a message with the text `Hello World!` and has no receiver. You check the result in the
  monitoring application.
. The same flow plus an outbound call to an external data source that is exposed through OData.
. A flow that starts with a timer and sends the result to a mail receiver.
. A flow started by a sender, here an HTTP client on your own computer, through the HTTPS sender adapter.

To use the Web UI as a developer you need, in the Cloud Foundry environment, the authorization group
`PI_Integration_Developer`, and `PI_Business_Expert` to see message attachments in the monitoring. The
documentation also provides ready-made example flows and integration packages, which can be reached from the SAP
Business Accelerator Hub described below.

Requires an SAP BTP account; not run here. The steps that build the first integration flow are:

. Open the Cloud Integration Web UI of your tenant.
. Create an integration package.
. Inside the package create an integration flow, add the steps of the exercise, save and deploy it.
. Open the monitoring application and read the message processing log.

Source: https://help.sap.com/docs/cloud-integration/sap-cloud-integration/getting-started-with-integration-flow-development[Getting Started with Integration Flow Development]

Cloud Integration also covers more than design. The documentation lists operating and monitoring, public OData APIs for
administering the service, and connecting a customer system. The Cloud Connector, described on the connectivity page,
is the link to systems inside a company network. The same documentation states that Cloud Integration can be used
together with SAP Process Orchestration, SAP's on-premise integration platform, which matters for the migration
described below.

== Synchronous and asynchronous integration

Two communication styles decide how an integration is built. In a synchronous call the sender waits for the answer:
the web shop asks for the stock of an article and shows the number when it returns. In an asynchronous exchange the
sender hands the message over and carries on; the receiver processes it later, and a queue holds the message in
between. Cloud Integration supports both. The documentation says it can orchestrate business processes in synchronous
as well as in asynchronous scenarios, and that reliable messaging is built on asynchronous decoupling with queuing
mechanisms. The general ideas are those of xref:backend/messaging/messaging-models-and-patterns.adoc[Messaging Models and Patterns].

[mermaid]
----
sequenceDiagram
    participant S as Sender system
    participant I as Integration flow
    participant Q as Queue
    participant R as Receiver system
    Note over S,R: Synchronous: the sender waits for the answer
    S->>I: request
    I->>R: call
    R-->>I: response
    I-->>S: response
    Note over S,R: Asynchronous: the sender continues after the hand-over
    S->>I: message
    I->>Q: store
    I-->>S: accepted
    Q->>R: deliver later
----

Source: drawn for this page from the description in https://help.sap.com/docs/cloud-integration/sap-cloud-integration/what-is-sap-cloud-integration[What Is SAP Cloud Integration?]

The practical rule: use the synchronous style when the sender needs the answer to continue, and the asynchronous style
when the work may finish later or the receiver may be unavailable for a while. Events, the next section, are the
asynchronous style taken further: the sender does not even know who receives the message.

== API Management, events and Integration Advisor

*API Management* is for the case in which you offer a service to others. The overview says it lets you discover,
protect, govern and publish APIs to developers, and that you can check that APIs follow best-practice security
policies. It is the front door of an interface, not the code behind it.

*Events* are the second style of exposing business changes. The overview says the suite can "publish and consume
business events", so that applications are connected through an event-driven architecture. Two services are named.
SAP Event Mesh is described as the service that connects applications, services and systems across landscapes, with
queues and queue subscriptions, REST APIs and an add-on, SAP NetWeaver Add-On for Event Enablement, that exchanges data
between an SAP NetWeaver ABAP system and Event Mesh. SAP Integration Suite, Advanced Event Mesh is described as the
service that creates multiple event brokers in public or private clouds, and the overview says it supports distributed,
event-driven architectures with real-time responsiveness. Both are separate entries in the Help Portal. Read the
feature scope descriptions in both before choosing: a difference in features that is not written there is not a
difference this page can claim.

*Integration Advisor* helps with the interfaces and mappings of business-to-business scenarios. It uses crowdsourcing
and machine learning to propose interface definitions and mappings, so that fewer are written by hand, and it works
together with Trading Partner Management, which holds the agreements with each partner.

== Migrating from SAP PI and SAP PO

Many companies run SAP Process Orchestration, which contains SAP's older on-premise integration engine, usually called
PI or PO. Moving its interfaces to SAP Integration Suite is a project, not a switch. The documentation gives the
beginner three facts. Migration Assessment exists to assess existing integration scenarios and to estimate the
migration effort for SAP Process Orchestration scenarios. Cloud Integration is documented as working together with SAP
Process Orchestration, so old and new can run side by side during the move. And the Integration Suite service plans
and their feature sets are described in SAP Note 2903776, which you read before planning. The maintenance dates of SAP
Process Orchestration are not stated on the pages used here and are therefore not given on this page; check the
current SAP statement before you plan.

== SAP Business Accelerator Hub

The SAP Business Accelerator Hub at https://api.sap.com is SAP's public catalog of resources for integrating with and
extending SAP products. You can browse it without an account. On 2026-11-13 the start page, opened in a browser
without signing in, was organized like this:

* *Products*: pages per SAP product, such as SAP S/4HANA Cloud Public Edition and SAP S/4HANA Cloud Private Edition.
* *Artificial Intelligence*: resources that use AI at SAP, with a listing of AI agents.
* *Categories*: *APIs* (5563 listed that day), *Events* (593 event objects) and more.
* *Domains*: *Integrations*, which are integration packages between different products (5236 listed that day).
* *Industries*, *Partners* and *Community* content, and *process blueprints* such as a "Recruit to Retire" blueprint
  with solution variants.
* *Learning* links, for example to explanations of the SAP Integration Suite and of the ways to consume integration content.
* *Resources*: the SAP API Policy and its FAQ, the SAP API Deprecation Policy, the SAP CDS Deprecation Policy and the
  SAP Road Map Explorer.

The counts change daily; they show the size of the catalog, not a fixed fact. Three uses matter to a newcomer. First, to
find the API of a business object before you build anything: search for the object and read the API description,
including which entities and operations it offers, instead of guessing. Second, to find an event object, which tells
you what an event contains and when it is raised. Third, to find a prebuilt integration package that a Cloud
Integration tenant can import, which the Cloud Integration documentation points to for its example integration flows.
Reading the public descriptions needs no account. Trying an API, downloading a specification file or importing
content needs a sign-in to an SAP account, and this page does not use it; the SAP documentation for each API says how
to authenticate. Before using any API, read the SAP API Policy and the deprecation policies listed under *Resources*,
because they say how long a released API is supported.

Requires an SAP BTP account; not run here. The usual path from the catalog to a working call is:

. Find the API package for your product in the catalog and read its description.
. Choose the interface, then read its entities and operations.
. Obtain the credentials that the API's documentation describes for your system.
. Call the interface from a tool such as an HTTP client or from an integration flow.

Source: https://api.sap.com/[SAP Business Accelerator Hub] (public start page, read without signing in), and https://help.sap.com/docs/cloud-integration/sap-cloud-integration/getting-started-with-integration-flow-development[Getting Started with Integration Flow Development]

In the running example of expense claims, the catalog is the first stop when a claim must reach a payment system: you
look up the API or event of the target product, and the Integration Suite carries the message. The choice is simple.
Use Cloud Integration to move and transform messages between systems, API Management to publish a service to
consumers, events to tell many systems about a change, and the catalog to find out what already exists.

== Summary

* SAP Integration Suite is one service on SAP BTP that bundles Cloud Integration, API Management, event services,
  Open Connectors, Integration Advisor, Trading Partner Management and assessment capabilities.
* An integration flow models how a message is processed; adapters connect it to senders and receivers, and a custom
  adapter can be built with the Adapter Development Kit.
* Synchronous integration waits for the answer; asynchronous integration hands over the message and continues, and
  Cloud Integration supports both, with queues for reliable delivery.
* Event Mesh and Advanced Event Mesh carry business events; API Management publishes and protects APIs; Integration
  Advisor helps with interfaces and mappings.
* Migration Assessment helps move SAP Process Orchestration scenarios, which Cloud Integration can work beside.
* The SAP Business Accelerator Hub lists APIs, events and integration content publicly; downloads and trials need an
  SAP account, which this page does not use.
