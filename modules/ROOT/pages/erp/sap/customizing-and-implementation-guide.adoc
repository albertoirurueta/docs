Two companies that buy the same SAP software end up with systems that behave differently: one posts invoices in two
currencies, the other in five, one asks for a second approver, the other does not. Most of that difference is not
programming. It is configuration, the work of choosing settings that SAP has prepared in advance. SAP calls this work
Customizing, and a newcomer meets it in the first week of any implementation project. This page explains where the
settings live, how a change to a setting is recorded and moved from the development system to the production system,
and which tools guide the work. It is written for SAP S/4HANA 2025 FPS02 on premise and Private Edition (the
Implementation Guide and Customizing requests of the classic ABAP platform) and for SAP S/4HANA Cloud Public Edition
2608 (SAP Central Business Configuration, which replaces most of that classic way of working). It also places the SAP
Activate methodology, which describes the phases of an implementation project in both editions. Section
"Which edition uses which tool" at the end of the body gives the short comparison.

== What Customizing is

SAP software is delivered as a product that already contains many business processes: posting a supplier invoice,
creating a sales order, running payroll. The product is not finished for your company, because it does not know your
company codes, your currencies, your payment terms or your approval rules. Customizing is the step in which you tell the
system. You do not change program code; you maintain the values of tables that the delivered programs read at run
time. This is why two companies can run the same code and still get different behavior.

The keyword is the word _configuration_. Configuration choices are kept apart from the two other kinds of data in a
system. Master data describes long-lived things such as a business partner or a product. Transactional data records
what happened, such as an invoice. Configuration data decides how the system treats both, and it changes rarely, under
control, and in the development system first. The next section shows how the tools support that control.

A configuration setting can apply to the whole system or to one client. SAP Help defines a client as a commercially,
organizationally and technically self-contained unit of an SAP system with its own master records and set of tables. It
is the highest level of the hierarchy: what you specify there is valid for all company codes and all other
organizational structures below it, and every user logs on to one client and works in it. The system is delivered with
the clients 000 and 001, which already contain default settings. In practice a settings table is either client-specific,
so its entries belong to one client, or cross-client, so it holds one set of entries for the whole system. The
difference matters for transports, as the section on Customizing requests below shows.

== The Implementation Guide and SPRO (on premise and Private Edition)

In an SAP S/4HANA system on premise or in the Private Edition, the Customizing settings are not scattered across
hundreds of screens. They are collected in the Implementation Guide (IMG), a tree whose branches follow the
application areas: Financial Accounting, Sales, Plant Maintenance and so on. Each leaf of the tree is a configuration
activity. Opening it shows the documentation of the step and an Execute icon that leads to the table maintenance view
where you make the setting.

SAP Help describes the IMG as the tool that adjusts the system to the requirements of a company. It names three
variants, and the difference explains most of the vocabulary newcomers hear in an SAP project.

* The *SAP Reference IMG* is the complete guide that SAP delivers. It contains the work steps of all applications as IMG
  activities. A system that has everything is also large, which is why a project does not work in it directly.
* A *project IMG* is generated for one implementation project. The project team selects only the functions its business
  processes need, and the system generates a separate IMG for that project, and another for each release update.
* A *project view IMG* is a filtered view of a project, for example a view that contains only the mandatory activities.

The documentation for these three variants comes from an older release of the SAP help (the EWM 9.0 documentation).
Current S/4HANA documentation still uses the same terms, as the examples below show, but the older page has no counterpart
for the 2025 release that states them in one place, so treat it as a description of the concept and not of every screen.

Source: https://help.sap.com/saphelp_ewm900/helpdata/en/4d/aee029a4bc6d4be10000000a42189e/content.htm[SAP Help: Implementation Guide (IMG), older release]

=== Opening the IMG

The IMG is opened with transaction SPRO in SAP GUI. The S/4HANA 2025 documentation tells readers to execute
transaction SPRO and then follow a path that starts at SAP Customizing Implementation Guide, for example into Plant
Maintenance and Customer Service, and the SAP Gateway setup tells readers to find its settings under SAP Reference IMG,
ABAP Platform. An older page of the Financial Operations documentation gives the menu route as Tools,
AcceleratedSAP, Customizing, Edit Project, SAP Reference IMG, and describes the steps that follow in plain words:
expand a node such as Financial Accounting to see its subheadings (Financial Accounting Global Settings, General
Ledger Accounting, Accounts Receivable and Accounts Payable), double-click the text icon to read the description of an
activity, click the Execute icon to reach the screens for the setting, save, and return to the structure. The same
documentation shows how to find an activity without browsing: from the structure display, choose Edit and Find, enter
a word, and the system searches the titles of the IMG.

Projects are managed with a second transaction. The Responsibility Management documentation tells users to open the IMG
project management with transaction SPRO_ADMIN and gives a path under Cross Application Components, General Application
Functions. Some parts of the documentation also give a specific project instruction: the Swiss pension fund module
ships its own IMG structure and says that, when you create an implementation project, you specify its component, so the
project IMG contains the activities of that module.

An example of how deep a single area goes comes from the General Ledger Accounting documentation of the subsequent
implementation of document splitting. Its Customizing activities form one branch of the Implementation Guide, under
Financial Accounting, General Ledger Accounting, Business Transactions, Document Splitting, Subsequent Implementation of
Document Splitting, Preparatory Phase. The branch lists steps from creating the project to completing the preparations,
and the documentation warns that the last step is a confirmation that changes the project status and is not a
Customizing setting, so it is not transported. This shows two things at once: the IMG can contain steps that are
processes and not settings, and the documentation tells you which of them are recorded for transport.

== Customizing requests: how a setting travels

A setting made in the IMG changes a table of the system you are working in. Nobody wants that change typed again by hand in
the quality and production systems, with the risk of a typing error. The Change and Transport System solves it
the same way it solves it for programs: the Transport Organizer records the change in a request, and the request is
released and imported into the next system along the transport route.

The Transport Organizer documentation states the rule that matters here. It registers and documents changes to ABAP
development objects and to Customizing objects. In the change requests it records all changed development objects and
Customizing settings, such as settings of organizational units like plants and company codes. Development objects and
Customizing settings are entered and managed in separate requests, with specific checks for each. So a Workbench request
carries objects such as classes and tables, and a Customizing request carries settings. The documentation adds that
changes to Customizing data _can_ be registered by the Transport Organizer: whether they are recorded is a property of
the client.

=== Client settings decide whether recording is on

In Client Administration, the settings of a client include Automatic Recording of Changes. With that setting on, saving a
client-specific setting makes the system ask for a request number, and a change without a request cannot be saved. The
cross-client settings of the client decide whether changes to the repository and to cross-client Customizing are
allowed. The same rules are restated for the Public Edition: with automatic recording active, a request number is
required to save client-specific configuration, and cross-client configuration always requires a request number,
whatever the client setting says.

For the expense claim running example, imagine the team adds a new currency to the claim approval rules. The setting is made
once in the development system, recorded in a Customizing request, released, imported into the quality system for testing
and imported into the production system after the test. Nobody changes a setting directly in production. The example is
generic and does not name an IMG path, because the claim approval rules are not part of the standard IMG.

== Customizing in SAP S/4HANA Cloud Public Edition

In the Public Edition you do not open SPRO in SAP GUI. SAP describes the configuration environment as depending on the
system landscape. A 3-system landscape (development, test and production) uses SAP Central Business Configuration as its
main tool. A 2-system landscape (quality and production) uses either SAP Central Business Configuration or the Manage Your Solution app, and the documentation states that new customers are automatically connected to SAP Central
Business Configuration and that a step-by-step conversion of Manage Your Solution customers is planned. The page also
notes that the availability of the 3-system landscape must be checked with the SAP account executive, so this page does
not assume that every customer has it.

SAP Central Business Configuration is a cloud service integrated with the Public Edition. SAP describes it as supporting
the scoping, the organizational setup, the configuration and the continuous adoption of the system. The starting point
is SAP Best Practices: pre-configured solutions that can be explored with demo data before they are adapted and
launched. The lifecycle management in the service keeps the settings in a consistent state, so regular upgrades and updates
of the Best Practices content can be taken without breaking your own adjustments.

=== From scope to active configuration

SAP Learning describes the working order of an implementation project in the service, and the Public Edition
documentation confirms the vocabulary.

. *Scope.* The team selects countries or regions and business scenarios. Countries or regions and scope bundles are
  mandatory, other scenarios are optional, and once the scope is confirmed, countries, bundles and scenarios cannot be
  removed again, although enhancements can be added later.
. *Organizational structure.* The team models company codes and other units from predefined templates. Each selected
  country needs at least one company code, and each sales organization needs a plant assigned as its recommended
  delivery plant.
. *Configuration activities.* The service shows a tree of activities by business area, each labeled mandatory,
  recommended or optional, and launching an activity opens the target system. Marking an activity completed in the
  service does not by itself apply the setting: the change must be saved in the target system.
. *Deployment and synchronization.* Each project is connected to a dedicated tenant, and the settings are deployed to
  it. In a 3-system landscape each tenant of the development system is linked to a workspace, which holds the
  configuration data of the Best Practices content for the selected scope, and the data is released to the system at
  regular synchronization points.

SAP calls the main interface of the service Project Experience. It manages evaluation and implementation projects and
ongoing operations. An evaluation project offers pre-configured content and demo data with limited scope selection. An
implementation project allows free scope selection and organizational setup. The access roles named on the page are
program manager, project manager, key user, display user and auditor.

=== How settings are moved in the Public Edition

The idea of the Customizing request survives in the Public Edition, but the system creates it for you. The
documentation says that, in general, the settings made in Central Business Configuration are transported from the
configuration system to the subsequent systems. A request of the type "Central Business Configuration" is created by
the system when the workspace is deployed, its tasks are released automatically once they are implemented, and the
request is managed by the business process configuration expert. Other Customizing requests and cross-client Customizing
requests (technically a Workbench request) are available for settings made outside the service.

Not everything is configured only in the development system. SAP names current settings, which are tenant-specific or
must be changed regularly, so they are changed in the test and production systems too. Because the service is not
connected to the non-development systems of a 3-system landscape, the Public Edition provides apps for them. The
Implementation Activities app lists configuration activities of the system and plays the role that browsing the IMG plays on premise: you search by activity description, IMG activity id, Customizing object name or table name, filter for activities
editable in all systems or for client dependence, display the change log of the table, and use "Where Used in
Transports" to find the transports that contain an activity. Other apps display and maintain business configuration
stagings, run consistency checks for business configuration, and automate the import of transport requests in the
Import Collection app.

Two limits matter for a newcomer. After settings are imported, some manual rework activities must be done in the target
system. And some business configuration is not transferred when you branch into a parallel line of the system landscape:
a list of excluded configuration activities exists and shows the IMG activity name of each.

== SAP Activate: the method around the tools

The IMG and Central Business Configuration are tools. SAP Activate is the method that says when to use them. SAP Learning
describes it as SAP's methodology for implementing SAP solutions, aimed at faster deployments, continuous adoption of
innovations and different starting points for new SAP S/4HANA implementations. It has six phases.

[cols="1,3",options="header"]
|===
| Phase | What happens
| Discover | The company understands what the solution can do and what business value it brings.
| Prepare | The project is planned, the team onboarded and enabled, the initial landscape provisioned and the application
lifecycle management tools set up.
| Explore | A fit-to-standard analysis runs on a working system. The team confirms where the delivered processes fit and
identifies gaps that need configuration, data integration or extensibility.
| Realize | In agile iterations the team configures, extends and tests the business environment and runs data loads and
adoption activities.
| Deploy | The production landscape is finished, data is loaded, readiness is confirmed and the company goes live.
| Run | Adoption keeps expanding, regressions are tested for system upgrades and more functionality is activated as needed.
|===

Customizing belongs mostly to Explore and Realize. In Explore the team decides, with the fit-to-standard analysis, which
settings differ from the delivered Best Practices content. In Realize the team makes those settings in the IMG (on
premise) or in Central Business Configuration and the Implementation Activities app (Public Edition). For the Public
Edition 3-system landscape the Activate roadmap names the administrator tasks of transport configuration and output
management setup in Realize, under the Solution Configuration deliverable of Application Design and Configuration.

The detailed content of SAP Activate is the roadmap, a list of tasks and accelerators per phase. It is reached through
the SAP Activate Roadmap Viewer, which needs an S-user account and is updated continuously, or through SAP Cloud ALM,
which comes preloaded with the methodology and offers the same guidance with project management and other features. SAP
Cloud ALM and the other change tools are covered on the transports and change management page of this section. The SAP Help pages for configuration point to the roadmap and to the SAP Signavio
Process Navigator, which shows the solution scope of the Best Practices. This page does not describe the contents of the
roadmap beyond what the public pages state, because the viewer needs a login.

== Which edition uses which tool

[cols="2,3,3",options="header"]
|===
| Question | On premise and Private Edition (2025 FPS02) | Public Edition (2608)
| Where do I make a setting? | The IMG, opened with transaction SPRO in SAP GUI | Central Business Configuration, plus the Implementation Activities app for current settings
| What limits the work to one project? | A project IMG generated from the SAP Reference IMG | A project in Project Experience with a confirmed scope
| How is the change recorded? | A Customizing request, if automatic recording is on for the client | A request created by the system on deployment; cross-client requests where needed
| Who moves the change? | The transport team along the routes of the Transport Management System | The service synchronizes, apps export and import, and import can be automated
| Which method applies? | SAP Activate | SAP Activate
|===

The two editions answer the same question, how a standard product becomes the system of one company, with different
levels of freedom. On premise, the IMG leads the team through the settings of the whole system, which is why those projects need discipline
about requests. In the Public Edition the team works inside the scope it selected and the activities the service shows,
and SAP states that regular upgrades of the Best Practices content can be taken without impact on the adapted configuration.

== Summary

* Customizing is the configuration of a delivered SAP system by choosing settings. It is separate from programming and from
  master and transactional data.
* On premise and in the Private Edition the settings live in the Implementation Guide, opened with SPRO. SAP delivers the
  SAP Reference IMG, a project generates a project IMG from it, and a project view IMG filters it.
* A setting travels in a Customizing request when automatic recording is active for the client, along the same transport
  routes as programs. Cross-client settings always need a request.
* In the Public Edition, SAP Central Business Configuration takes over: scope, organizational structure, configuration
  activities and deployment, with settings synchronized to the system and moved by system-created requests.
* SAP Activate describes the six phases of the project, Discover to Run, and fit-to-standard in the Explore phase decides
  which settings differ from the delivered content.
