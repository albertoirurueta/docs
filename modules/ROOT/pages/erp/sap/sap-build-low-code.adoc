Not every business application needs a team of programmers. A department that wants an approval form for expense claims, a
small mobile app for warehouse staff, or a bot that copies numbers from one screen to another can often build it with
visual tools, without writing code. SAP bundles such tools, and also tools for professional developers, under one name,
SAP Build. This page explains in plain words what SAP Build contains, what each part is for, which part has been
deprecated, and how to choose between the parts. It is written against the SAP Help Portal and the SAP Build product page
as read on 2026-11-13. SAP Build is a cloud offering on SAP Business Technology Platform (SAP BTP), so it applies to SAP
S/4HANA Cloud Public Edition, SAP S/4HANA Cloud Private Edition and on-premise systems alike, because it extends them from
the side instead of changing them. Using SAP Build needs an SAP BTP account, which this documentation project does not have,
so nothing on this page was run: it describes the products from the official documentation only. After reading you can name
the parts of SAP Build, say who each part is meant for, and decide when a visual tool is enough and when a coded
extension is the better choice.

== Key terms

* xref:erp/sap/glossary.adoc#sap-build[SAP Build]: SAP's family of low-code and pro-code services for creating and extending
  business applications and automations.
* xref:erp/sap/glossary.adoc#low-code[Low-code and no-code]: building with drag-and-drop editors and forms, with little or no
  programming.
* xref:erp/sap/glossary.adoc#citizen-developer[Citizen developer]: a business user, not a professional programmer, who
  builds applications or automations with such tools.
* xref:erp/sap/glossary.adoc#sap-build-process-automation[SAP Build Process Automation]: the service for workflows, decision
  tables and software bots.
* xref:erp/sap/glossary.adoc#rpa[Robotic process automation (RPA)]: software bots that repeat clicks and data entry in

* xref:erp/sap/glossary.adoc#joule[Joule]: SAP's AI assistant, which SAP Build lets developers extend with their own skills.
* xref:erp/sap/glossary.adoc#sap-btp[SAP BTP]: SAP's cloud platform on which SAP Build runs.

== What SAP Build is

The SAP Help Portal describes the SAP Build ecosystem as "a number of services" that offer "both low-code and pro-code
offerings" for a range of people, from citizen developers to professional developers and business experts. Low-code means
building mostly with visual editors; pro-code means writing source code in a development environment. The point of putting
both under one roof is that a business expert and a programmer can work on the same solution, each in the tool that suits
them. The guide also says generative AI capabilities are available to automate daily tasks and optimize workflows. It adds
that the SAP Build service is only offered in the data centers and regions listed on the SAP Discovery Center page for SAP
Build, so the first check before planning is whether your region is on that list.

The same guide groups the offering into four capabilities, and then lists the services behind them.

[cols="1,3",options="header"]
|===
| Capability | What it is for

| Applications
| Development tools to create and extend business applications and services.

| Automated Process
| Creating, customizing and enhancing business processes: workflows, bots and intelligent document processing.

| Joule Skill
| Joule Studio, classic edition, which expands what SAP's AI assistant Joule can do for your organization.

| Business Site
| Digital workspaces and business sites, in the standard or the advanced edition of SAP Build Work Zone.
|===

Source: https://help.sap.com/docs/build-service/build-service-guide/what-is-sap-build[What Is SAP Build?], SAP Build service guide

The services listed under these capabilities include SAP Build Work Zone (standard and advanced edition), SAP Build Process
Automation, SAP Task Center, SAP Build Apps, SAP Mobile Services, the Application Frontend Service and SAP Business
Application Studio. A second list, "SAP Build Runtime Services", names the places where the results run: the Cloud Foundry
runtime, the SAP Business AI Platform ABAP environment, the Kyma runtime, SAP Document Management Service, SAP Cloud
Transport Management, SAP Continuous Integration and Delivery and SAP Alert Notification service. Several of these have
their own pages on this site, for example
xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[SAP BTP Environments: Cloud Foundry and Kyma].

The SAP product page for SAP Build presents the same idea from the buyer's side: one solution that combines "drag-and-drop
tools, traditional coding, and AI assistance", with governance, roles and clean-core alignment "built in from the start". It
also says SAP Build supports Visual Studio Code, connects to MCP servers and works with popular agentic development tools.

== SAP Build Apps and its deprecation

SAP Build Apps lets people develop full-stack applications visually, for native mobile use and the web, with drag-and-drop
user interface components, logic flows and formulas, and a no-code backend. The Help Portal states that it "is now
deprecated as a standalone product (effective March 23, 2026)". For new projects it points to SAP Build, and existing
customers can use SAP Build Apps until their current contract ends. A page called "SAP Build Apps - The Path Forward"
describes the migration to SAP Build Web Application Frontend projects. The practical consequence for a newcomer is that
older tutorials and videos that start with a standalone SAP Build Apps project show a path that SAP no longer recommends for
new work, so check the date of any tutorial before following it.

== SAP Build Process Automation

SAP Build Process Automation is the part of SAP Build for processes. The Help Portal calls it "a citizen developer solution
to adapt, improve, and innovate business processes with no-code workflow management and robotic process automation
capabilities". Its key features, as listed there, are:

* building or adapting processes in a graphical interface;
* forms-based workflows created with drag and drop;
* decision logic kept in spreadsheet-like decision tables;
* robotic process automation for repetitive tasks inside existing process flows;
* machine learning for intelligent actions and recommendations;
* a unified launchpad and task center;
* handing a project to professional developers, who can embed actions and advanced workflows;
* process visibility dashboards with real-time, event-driven transparency into process instances.

It also offers prebuilt content such as bots, process steps, business rules and workflow components.

To see how these pieces fit, take the expense claim that runs through this site. A claim is submitted, a rule decides who
approves it, the approver receives a task, and the result is posted. The three ideas map as follows: the _workflow_ is the
sequence of steps with a form for the person who submits the claim; the _decision table_ is the rule that picks the
approver; and a _bot_ could re-key the approved claim into an older system that has no interface. The table below is an
illustration of a decision table for the full claim record `ZEXP_CLAIM` of this site, which has the fields
`total_amount` and `currency_code`. The amounts and approver names are invented for teaching and are not taken from an SAP
page.

== SAP Build Code and the pro-code side

The product page says SAP Build application development "combines AI coding, low-code and pro-code in one solution". It
names Joule for developers (natural language to create applications), an open ecosystem (Visual Studio Code and other
tools), AI-assisted migration of ABAP custom code to SAP S/4HANA Cloud, generative AI code development for Java and
JavaScript on CAP, and ABAP development with AI capabilities. This is the family people usually mean by SAP Build Code: a
development environment that is based on SAP Business Application Studio, the browser-based development environment that
the service guide lists, and that is aimed at professional developers who build with CAP or ABAP. For the frameworks
themselves see xref:erp/sap/cap-getting-started.adoc[CAP Getting Started] and the ABAP section of this site. The
documentation pages read for this page did not describe SAP Build Code in detail, so the exact feature list, the commands
of the AI assistant and the licensing of Build Code should be checked on the current product page before a decision.

== Joule Studio and business sites

Joule is SAP's AI copilot. The service guide says it can do a lot, but every company has processes and resources that Joule
does not know, and that "Joule Studio, classic edition" lets you expand Joule's capabilities and knowledge to the needs of
your organization; the guide's task is titled "Create a Joule Studio Project". The product page adds that Joule Studio is
where teams can build AI agents grounded in their own business context. The edition name "classic edition" signals that
this area is changing, so treat any tutorial for Joule Studio as dated until it matches the current Help Portal text.

SAP Build Work Zone is the business-site part. The standard edition creates business sites that act as one entry point to
SAP, custom and third-party applications, in the cloud and on premise. The advanced edition adds collaboration, workspaces
and rich content. A site is what a user opens to reach their apps and tasks, and it relates to the launchpad idea described
in xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad]. SAP Task Center is the single place where a user sees the tasks
assigned from several applications, which is where the approval task of the process above would appear.

== Choosing a tool

[cols="2,2,3",options="header"]
|===
| Need | Start with | Why

| A form-based approval or a rule that changes often
| SAP Build Process Automation
| Citizen developers can change forms and decision tables without code.

| A repetitive task in a system that has no interface
| A bot in SAP Build Process Automation
| Robotic process automation repeats what a person does on screen.

| A new service with its own data and logic
| CAP, with SAP Build Code or SAP Business Application Studio
| Professional developers model data and write handlers. See xref:erp/sap/cap-getting-started.adoc[CAP Getting Started].

| A small change inside an SAP S/4HANA app
| In-app key-user tools
| No separate application is needed. See xref:erp/sap/key-user-extensibility.adoc[Key-User Extensibility].

| One starting point for users across apps
| SAP Build Work Zone
| A business site collects apps, tasks and content.
|===

Source: this page's summary of the capability descriptions in https://help.sap.com/docs/build-service/build-service-guide/what-is-sap-build[What Is SAP Build?]

Whatever the tool, the clean core rule of xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core]
still applies: the extension talks to the SAP system through released interfaces and does not modify the standard code.

== Summary

* SAP Build is a family of low-code and pro-code services on SAP BTP, grouped as Applications, Automated Process, Joule
  Skill and Business Site.
* SAP Build Apps is deprecated as a standalone product since March 23, 2026, so new projects start in SAP Build.
* SAP Build Process Automation offers workflows, decision tables, bots and process visibility for citizen developers.
* The pro-code side is based on SAP Business Application Studio, with AI assistance for CAP, ABAP, Java and JavaScript.
* Joule Studio extends Joule, and SAP Build Work Zone builds the business sites that users start from.
* Everything here needs an SAP BTP account; this page describes the official documentation and ran nothing.
