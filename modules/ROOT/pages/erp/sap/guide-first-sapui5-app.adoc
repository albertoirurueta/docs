= SAP Guide: Your First SAPUI5 App
:description: Step-by-step guide to a first UI5 app with OpenUI5 1.154 and UI5 Tooling 4: a small CAP OData V4 service, a UI5 Tooling project, an XML view with a table bound to the service, a controller with a search and an i18n file with English and German texts, all run in the browser.
:keywords: SAP, SAPUI5, OpenUI5, UI5 Tooling, ui5 serve, ui5.yaml, XML view, controller, manifest.json, OData V4 model, data binding, i18n, CAP, proxy, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-13 against OpenUI5 1.154.0, UI5 Tooling (`@ui5/cli`) 4.0.73, CAP Node.js 10.2 (`@sap/cds` 10.2.2, `@sap/cds-dk` 10.2.1) and Node.js 24.21.

== What you build

This is a teaching model built with CAP. It is not SAP S/4HANA or SAP SuccessFactors and does not reproduce their screens.

You build a small browser app for expense claims with UI5, the JavaScript library behind most SAP web screens. The app has one screen: a page with a search field and a table of claims. The table reads its rows from a CAP service over OData V4, and every text on the screen comes from a language file, in English and in German. You write the files by hand, so you see what each of them is for: the project file of UI5 Tooling, the start page, the component, the manifest, the XML view, the controller and the texts. Two small servers run on your machine: CAP serves the data and UI5 Tooling serves the app.

image::sap-general-guide-first-sapui5-app-08-search-result.svg["The app in a browser after the text Ho was typed into the search field: the table title reads Claims (1) and the only row is Hotel Berlin, Approved, 189.00 EUR",width=900]

== Before you start

* No account is needed. UI5 Tooling and OpenUI5 come from the public npm registry under the Apache License 2.0, and the app loads UI5 from your own machine, not from a content delivery network. UI5 Tooling downloads the OpenUI5 libraries that `ui5.yaml` names into a cache folder in your home directory the first time it runs. The CAP packages carry the SAP Developer License Agreement, version 3.2, which you accept by installing them, as in xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service].
* Install Node.js 22.12 or newer. `node -v` prints the version.
* Use a code editor such as Visual Studio Code, a terminal and a browser. You need two terminal windows: one keeps the CAP service running, the other runs the commands and UI5 Tooling.
* Read xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics] first, or at least know what a view, a controller and a model are, and read xref:erp/sap/cap-getting-started.adoc[CAP Getting Started] for the service part.
* The first phase builds the same three small files as the guide xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service], with four claims instead of one, so you can do this guide on its own. If you did that guide, you know the commands already. The CAP command line tools (`@sap/cds-dk`) must be installed, as that guide describes.
* The names are the model's own: the entity `Claims`, the status codes `N` (New), `A` (Approved) and `R` (Rejected), the titles and the amounts are made up for this guide. No name comes from an SAP page.
* The figures are drawings of the editor, the terminal and the browser, not screenshots. A highlighted box with a number marks the file, the command or the address of the step with the same number.

== Steps

=== Create the service

. Create the CAP project and install its dependencies. The option `--nodejs` chooses the JavaScript runtime of CAP:
+
[source,bash]
----
cds init claims-ui5 --nodejs
cd claims-ui5
npm install
----
+
`cds init` ends with `Successfully initialized CAP project`, and `npm install` with `found 0 vulnerabilities`. Open the folder in your editor (in Visual Studio Code, `code .`).

. In the first terminal, in the project folder, start the service in watch mode and leave it running:
+
[source,bash]
----
cds watch
----
+
The log lists the three model files, connects to a database that lives only in memory (`sqlite { url: ':memory:' }`), fills it from your CSV file and ends with `server listening on { url: 'http://localhost:4004' }`. The line `serving ClaimService` names the path `/odata/v4/claim`.
+
image::sap-general-guide-first-sapui5-app-02-cds-watch.svg["Terminal after cds watch: the log lists srv/claim-service.cds, db/schema.cds and the common.cds of CAP, connects to an in-memory SQLite database, initializes it from db/data/sap.guide.claims-Claims.csv, serves ClaimService at /odata/v4/claim and ends with server listening on http://localhost:4004; callout 5 marks the command",width=900]
+
The figure leaves out the banner that `cds watch` prints before the first line.
. In the second terminal, ask the service for the title and amount of every claim, sorted by title, with a count. The quotation marks keep your shell from reading the `$` and the `&`:
+
[source,bash]
----
curl 'http://localhost:4004/odata/v4/claim/Claims?$select=title,amount&$orderby=title&$count=true'
----
+
The answer is one line of JSON. It names the count, 4, and holds the four claims in the order Conference fee, Hotel Berlin, Team lunch, Train ticket. The key `ID` is part of every row, and the amount is a string in quotation marks, such as `"45.50"`. The app reads exactly this answer.
+
[source,json]
----
{"@odata.context":"$metadata#Claims","@odata.count":4,"value":[{"title":"Conference fee","amount":"1200.00","ID":"44444444-4444-4444-4444-444444444444"},{"title":"Hotel Berlin","amount":"189.00","ID":"22222222-2222-2222-2222-222222222222"},{"title":"Team lunch","amount":"62.40","ID":"33333333-3333-3333-3333-333333333333"},{"title":"Train ticket","amount":"45.50","ID":"11111111-1111-1111-1111-111111111111"}]}
----

=== Create the UI5 project

The app is its own npm project in a folder `ui`, next to `db` and `srv`. It has its own `package.json` because UI5 Tooling reads the dependencies of the project from it, and the dependencies of the app have nothing to do with those of the service.

[start=7]
. Create the folder `ui` and in it the file `ui/package.json`. It names one development dependency, UI5 Tooling, and a script `start`. `"type": "module"` lets UI5 Tooling load the small JavaScript file of step 9. Then install it from the `ui` folder and ask for the version:
+
[source,json]
----
include::example$sap-lab/claims-ui5/ui/package.json[]
----
+
[source,bash]
----
cd ui
npm install
npx ui5 --version
----
+
`npm install` prints a few warnings about deprecated packages and a summary of known vulnerabilities. They come from the packages of the UI5 command line tool, which only runs on your machine while you develop; the app itself never loads them. `ui5 --version` prints `4.0.73` followed by the location of the tool.
. Create the file `ui/ui5.yaml`, the project file of UI5 Tooling. The first part describes the project: the file format `specVersion`, the project name (it is also the id of the app), the type `application` and the `framework`. The framework section names the edition `OpenUI5`, the version `1.154.0` and the libraries the app needs: `sap.ui.core` is the base, `sap.m` has the controls for phones and desktops, and `themelib_sap_horizon` is the Horizon look. UI5 Tooling downloads these libraries from npm and serves them at `/resources`, so the app never needs the libraries in `package.json`. The part after `server:` and the second document, after the line of three dashes, add a small server extension that step 9 explains:
+
[source,yaml]
----

----

Source: https://ui5.github.io/cli/stable/[UI5 CLI documentation]
. Create the folder `ui/lib` and in it the file `odata-proxy.js`. The browser loads the app from `http://localhost:8080`, but the service lives at `http://localhost:4004`, which is a different origin. A browser lets a page call another origin only when that origin allows it (this is called CORS), and the service of this guide does not allow it for the requests that UI5 sends (the first row of the table in "What can go wrong" shows what that looks like). The way out is to let the browser talk to one origin only. This file is a small server extension for UI5 Tooling, about twenty lines of Node.js that you can read in one go: it takes every request whose path starts with `/odata` (the `prefix` of `ui5.yaml`) and hands it on to the CAP service (the `target`). === Run the app

[start=16]
. In the second terminal, from the project folder, start UI5 Tooling. The script `start` of `ui/package.json` runs `ui5 serve --port 8080`. Leave both terminals running:
+
[source,bash]
----
cd ui
npm start
----
+
The output names the script, the OpenUI5 version (`1.154.0`) and the address:
+
[source,text]
----
> claims-ui@1.0.0 start
> ui5 serve --port 8080

info graph:helpers:ui5Framework Using OpenUI5 version: 1.154.0
Server started
URL: http://localhost:8080
----
+
image::sap-general-guide-first-sapui5-app-06-ui5-serve.svg["Terminal in the folder ui after npm start: the script runs ui5 serve with port 8080, UI5 Tooling reports that it uses OpenUI5 version 1.154.0 and that the server started at http://localhost:8080; callout 16 marks the command",width=900]
. Open http://localhost:8080/index.html?sap-ui-language=en in the browser. The parameter `sap-ui-language` sets the language of the page, so you see the English texts whatever your browser uses. The page title is `Expense Claims`, the table is titled `Claims (4)` and lists the four claims sorted by title, with the status words and the amounts followed by `EUR`.
+
image::sap-general-guide-first-sapui5-app-07-app-list.svg["Browser at localhost:8080/index.html with the language parameter en, marked by callout 17: the app Expense Claims shows a search field in the page header and the table Claims (4) with the columns Title, Status and Amount and the rows Conference fee, Hotel Berlin, Team lunch and Train ticket, sorted by title, with the status words Rejected, Approved, New and New and the amounts with EUR",width=900]
. Type `Ho` into the search field and press Enter. The table shrinks to one row, Hotel Berlin, and its title reads `Claims (1)`. The filtering happens in the service: the request that UI5 sent, read from the browser, asks for the claims whose title contains `Ho`. UI5 sends its requests in a batch (a `POST` to `/odata/v4/claim/$batch`), and the request inside it reads:
+
[source,text]
----
GET Claims?$orderby=title&$select=ID,amount,status,title&$filter=contains(title,'Ho')&$skip=0&$top=100
----
+
The field only asks for the fields the view shows, as `autoExpandSelect` of step 12 promised.

== Check the result

* Both terminals show no line that starts with `[ERROR]`, and the one of UI5 Tooling ends with `URL: http://localhost:8080`.
* The page shows the title `Expense Claims`, the table `Claims (4)` with four rows and the search field.
* A search for `Ho` leaves the row Hotel Berlin and the title `Claims (1)`. An empty search shows the four rows again.
* The lab project holds two small checks that you can run from the project folder (not the `ui` folder) with `npm test`: they read the service and compare the keys of the view and the controller with the two language files.

== Variations

* Open http://localhost:8080/index.html?sap-ui-language=de. The same app now reads `i18n_de.properties`: the page title is `Spesenabrechnungen`, the table is `Abrechnungen (4)`, the columns are `Titel`, `Status` and `Betrag`, the status words are `Abgelehnt`, `Genehmigt` and `Neu`, and the amounts are written the German way, for example `1.200,00 EUR`. You did not format anything in code: the Decimal type uses the format of the language.
* Search for `ho` in lower case. The table shows `Claims (0)` and the text `No data`, because the service matched only the upper and lower case that you typed: `Hotel Berlin` contains `Ho`, not `ho`.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|The table says `No data`. The console reads `Could not load metadata: 0 error`, and the network list shows an `OPTIONS` request for `$metadata` that is answered with 200 followed by a `GET` that fails. This is what you get when the `uri` in `manifest.json` is the address of the service itself, `http://localhost:4004/odata/v4/claim/`.
|The page and the service are different origins. In development CAP answers with an `access-control-allow-origin` header, but its answer to the check that the browser makes before a request with OData headers does not list those headers, so the browser stops the request.
|Use the relative path `/odata/v4/claim/` in the manifest and the proxy of step 9.

|The table says `No data`, and `curl http://localhost:8080/odata/v4/claim/$metadata` answers HTTP 500 with an `ECONNREFUSED` error in the text.
|The CAP service is not running, so the proxy of UI5 Tooling finds nothing at port 4004.
|Start `cds watch` in the project folder and reload the page.

|The page shows the title and the search field but no table, and the console has no error.
|The page, the component and the view have no height, so the content of the page is 0 pixels high.
|Check that `html`, `body` and the `div` of `index.html` have `height: 100%`, that the `div` has `data-height="100%"` and that the root element of the view has `height="100%"`.

|A white page. The console reads `Unsupported operation mode: undefined`.
|The default model in `manifest.json` has no `operationMode`.
|Add `"operationMode": "Server"` to the settings of the model with the empty name.

|The page title shows `pageTitel` instead of a text, and the console reads `could not find any translatable text for key 'pageTitel' in bundle file(s): './i18n/i18n_en.properties'`.
|The key in the view is misspelled: UI5 shows the key itself when the file does not have it.
|Correct the key in the view or add it to both language files.

|`ui5 serve` stops with `Duplicate framework dependency definition(s) found for project sap.guide.claims`.
|OpenUI5 libraries such as `@openui5/sap.m` were added to `ui/package.json` as well as `ui5.yaml`.
|Remove them from `package.json`. The libraries are named only in `ui5.yaml`.
|===

== Clean up

Press `Ctrl+C` in both terminals. The database lived only in memory, so there is nothing to delete. UI5 Tooling keeps the downloaded OpenUI5 libraries in a folder in your home directory (`~/.ui5`), where other UI5 projects reuse them. The folder `claims-ui5` is yours to keep.
