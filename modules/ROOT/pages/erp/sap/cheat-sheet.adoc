== SAP GUI and transaction codes

[source,text]
----
/nmb01      end the current task and open a new transaction
/o SE80     open a transaction in a new session
/o          list your sessions
/i          close this session
/nend       confirm, then log off
/nex        log off at once, no confirmation
----

[cols="1,3",options="header"]
|===
| Code | Use
| `SU01` | user maintenance
| `PFCG` | role maintenance
| `SE80` | Object Navigator
| `SM59` | RFC destinations
| `STMS` | Transport Management System
| `SM37` | job overview
| `SM12` | lock entries
| `ST22` | ABAP dump analysis
| `/IWFND/MAINT_SERVICE` | activate and maintain OData services on SAP Gateway
|===

Details: xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics].

== Clients, landscape and transports

* SAP recommends a three-system group of development, quality assurance and production (DEV, QAS, PRD).
* Table `T000` is the client control table; `SCC4` is the code of the client settings; `MANDT` is the client key column.
* `SE09` and `SE01` show transport requests, `STMS` runs the Transport Management System, and `S_TRANSPRT` is the
  authorization object for transports.
* Public Edition uses the Adaptation Transport Organizer, BTP content uses SAP Cloud Transport Management, and SAP Cloud ALM
  orchestrates but does not move transports.

Details: xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape] and
xref:erp/sap/transports-and-change-management.adoc[Transports and Change Management].

== Users, roles and authorizations

* `SU01` creates users and assigns roles; `PFCG` builds roles, their menu and their authorizations.
* `SU53` shows the last failed authorization check, `SUIM` lists users, roles and critical authorizations, and `ST01` is
  the authorization trace.
* Public Edition: business roles made of business catalogs, narrowed by restriction types.
* SAP BTP: role templates, grouped into role collections, assigned to users or groups.

Details: xref:erp/sap/users-roles-and-authorizations.adoc[Users, Roles and Authorizations].

== Architecture and the virtual data model

* Presentation tier: SAP Fiori launchpad and SAP GUI (which talks DIAG). Application tier: ABAP server with SAP Gateway.
  Database tier: SAP HANA.
* View prefixes: `I_` interface view, `C_` consumption view, `P_` private view, and further prefixes such as `R_`, `A_`
  and `E_`.
* Build only on released views (stability contracts C0, C1 and C2).

Details: xref:erp/sap/architecture-and-virtual-data-model.adoc[Architecture and the Virtual Data Model].

== OData and SAP Gateway

[source,text]
----
$metadata
$filter=amount gt 50
$select
$orderby=ID
$top=5
$skip=10
$count=true
$expand=items
$batch
----

* `SEGW` builds V2 services and `/IWFND/MAINT_SERVICE` publishes them; V4 uses service groups and `/IWFND/V4_ADMIN`.
* Writes to SAP Gateway need a CSRF token fetched with `x-csrf-token: fetch`.

Details: xref:erp/sap/odata-and-sap-gateway.adoc[OData and SAP Gateway].

== Integration with RFC, BAPI and IDoc

* The ALE chain of settings: destination (`SM59`), port (`WE21`), partner profile (`WE20`), process codes (`WE41` or `WE42`).
* `WE02` displays IDocs and `WE19` helps to test.
* A BAPI is an RFC-capable function module; commit with `BAPI_TRANSACTION_COMMIT`. ABAP Cloud uses communication
  arrangements instead of `SM59`.
* Prefer OData and events for new interfaces.

Details: xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc and SOAP Integration].

== BTP and CAP commands

[source,shell]
----
npm i -g @sap/cds-dk
cds init expenses --nodejs
cds watch
cds version
cds env get requires.auth.kind
----

[source,shell]
----
cds add hana,xsuaa,mta
cds up
mbt build -t gen --mtar mta.tar
cf deploy gen/mta.tar -f
cf login --sso
cf target
cds add kyma
----

A global account holds subaccounts (one region each) and optional directories; Cloud Foundry gives an org with spaces,
Kyma gives clusters with namespaces.

xref:erp/sap/btp-account-model.adoc[SAP BTP Account Model] and

== SAPUI5 and Fiori elements

[source,shell]
----
npx ui5 serve --port 8127
npx ui5 build --dest ../dist
----

[cols="1,2",options="header"]
|===
| Annotation | Effect
| `@UI.LineItem` | list report columns
| `@UI.SelectionFields` | filter bar fields
| `@UI.HeaderInfo` | object names and title
| `@UI.Facets` | object page sections
| `@UI.FieldGroup` | fields inside a section
|===

An app is a component with a `manifest.json` that declares models, libraries and routes; views are XML and code loads with
`sap.ui.define`.

Details: xref:erp/sap/sapui5-basics.adoc[SAPUI5 and OpenUI5 Basics] and xref:erp/sap/fiori-elements.adoc[SAP Fiori Elements].

== Extensibility and deployment options

* Three kinds of extension: key user (low-code), developer (ABAP in the S/4HANA stack) and side-by-side (on SAP BTP). Start
  with key user extensibility for small changes.
* Clean core levels A to D map to ABAP Test Cockpit results of no finding, information, warning and error.
* Public Edition is multi-tenant (upgrades in February and August), Private Edition is single-tenant (RISE with SAP), and on
  premise is customer operated.
* Paths from SAP ERP: new implementation, system conversion or selective data transition.

Details: xref:erp/sap/extensibility-and-clean-core.adoc[Extensibility and Clean Core] and
xref:erp/sap/deployment-options.adoc[Deployment Options].
