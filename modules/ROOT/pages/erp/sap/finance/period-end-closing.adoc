When a month ends, the books are not finished. Some costs have arrived in the business but not yet as an invoice, some
amounts are still valued at an old exchange rate, some goods are in the warehouse without a matching invoice, and some
costs sit on the wrong department. Period-end closing is the set of steps a finance team runs, in a fixed order, to put
those things right so that the figures for the period can be reported and then frozen. A newcomer meets it in the first
week of a project, because the first question after "can we post?" is "can we close?". After reading this page you can name
the main closing steps, say which SAP tool performs each one, work out a foreign currency valuation difference by hand,
and explain the difference between the Financial Closing cockpit and Advanced Financial Closing. The page is written for
SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608. The classic closing
programs and the Accruals Management pages are cited from the on-premise documentation; the Accounting Accruals Agent is
a Public Edition feature.

== Key terms

* xref:erp/sap/finance/glossary.adoc#period-end-closing[Period-end closing]: the ordered set of periodic activities that
  correct and complete the books of a period before they are frozen.
* xref:erp/sap/finance/glossary.adoc#accrual[Accrual]: recording a cost or revenue in the period it belongs to, even if the
  invoice or the cash comes later.
* xref:erp/sap/finance/glossary.adoc#key-date[Key date]: the date on which a closing run evaluates the data, usually the
  last day of the period.
* xref:erp/sap/finance/glossary.adoc#foreign-currency-valuation[Foreign currency valuation]: revaluing foreign currency
  balances and open items at the exchange rate of the key date.
* xref:erp/sap/finance/glossary.adoc#gr-ir-clearing-account[GR/IR clearing account]: the account that holds goods
  received that are not yet invoiced, and the reverse.
* xref:erp/sap/finance/glossary.adoc#financial-closing-cockpit[Financial Closing cockpit]: the task-list tool delivered
  with SAP S/4HANA that plans, runs and monitors closing tasks.
* xref:erp/sap/finance/glossary.adoc#advanced-financial-closing[Advanced Financial Closing]: SAP's separately licensed
  closing solution that runs closing task lists across systems.

== What period-end closing is

SAP Help groups the closing work of General Ledger Accounting under the heading "Closing Operations" and lists these
functions: check and count (reconciling the receivables and payables between companies of a group), valuate, regroup,
allocation, carry forward and value adjustment. The page speaks of processes performed at the end of the fiscal year,
but most of them also run every month, so a team normally rehearses them each period and adds the year-end steps in the
last one. Controlling has its own period-end closing, which SAP Help describes as the period-related business
transactions executed after the period end.

== Accruals

An accrual books a cost in the right period when the invoice has not arrived. Example Trading Co. (company code `EX01`,
leading ledger `0L`) receives electricity throughout December 2026 and expects an invoice of EUR 1,200.00 in January. An
accrual of EUR 1,200.00 puts the cost into December: the expense account is debited and an accrued liabilities account
is credited. SAP's Accruals Management does the calculating and posting for you instead of a hand-made journal entry.

SAP Help describes it in these terms. Accruals Management offers functions for calculating, checking and posting
accruals, and it builds on the accrual engine. It has components for manual accruals (you enter or load the data of the
transaction), purchase order accruals (the data comes from Materials Management and is converted into accrual objects)
and service entry sheet accruals (based on the amounts of unapproved service entry sheets). The system calculates the
amounts at the end of the period, and it can adjust them when related postings arrive: actual costs, such as an invoice,
reduce, or utilize, the accrual, and amounts that are no longer needed can be released. A check and approval procedure
can be added so that proposed amounts are reviewed before posting.

Posting happens in a periodic posting run. SAP Help says that you always start the run manually for a specific key date,
that the update run creates the line items in the posting document and that the accrual is saved at least in the
transaction currency. A posting can be reversed in the accrual object, but SAP Help warns that this is an inverse posting
and not a true reversal, so choosing the action several times creates several inverse postings.

When the January invoice for EUR 1,150.00 arrives, it uses up EUR 1,150.00 of the accrual, and the remaining EUR 50.00
can be released. The calculation is simple, 1,200.00 - 1,150.00 = 50.00; what the system posts for utilization and release
depends on the posting schema and account determination of the accrual item type, which are Customizing settings.

=== The Accounting Accruals Agent

The Public Edition documentation describes the Accounting Accruals Agent as a feature that uses agentic AI to automate
the preparation of manual accruals during month-end closing. It reads the accounting policies to find the calculation
method, retrieves historical data, calculates the amounts and prepares the accrual journal entries, which you then
manage as accrual proposals. The page adds that using the feature may need additional entitlements and that it is
available only if SAP S/4HANA Cloud Public Edition is integrated with Joule. The documentation page used for this
summary was read in a machine-translated Spanish version, so check the English wording before relying on a detail. See
xref:erp/sap/joule-and-business-ai.adoc[Joule and Business AI] for the assistant itself.

== Foreign currency valuation

Example Trading Co. keeps its books in euros. It invoices a customer in pounds sterling and owes a supplier in pounds.
Both items stay open over the year end. While they are open, the exchange rate moves, so the euro value of the items is
no longer what it was when they were posted. Foreign currency valuation re-expresses them at the rate of the key date
and books the difference, so that the balance sheet shows the right euro amounts.

SAP Help says the valuation covers foreign currency balance sheet accounts (the balances of accounts not managed on an
open item basis) and open items posted in a foreign currency that are still open on the key date. You can value in the
local currency or in a parallel currency, such as a group currency, and you can use different valuation methods, for
example the lowest value principle. When additional currencies are translated from the local currency, valuation
performs the currency translation in line with FASB 52 (US GAAP). One rule matters in practice: you can run a valuation
only once for a valuation area and a specific key date.

=== The valuation difference in numbers

Write stem:[A] for the amount in the foreign currency, stem:[r_b] for the rate at which the item was booked and
stem:[r_k] for the rate on the key date. The rates here are quoted as pounds per euro, so a euro amount is the pound
amount divided by the rate. The valuation difference is the euro value at the key date minus the euro value at booking:

[stem]
++++
\Delta = \frac{A}{r_k} - \frac{A}{r_b}
++++

For an asset such as a receivable, a positive stem:[\Delta] is a gain; for a liability such as a payable, a positive
stem:[\Delta] is a loss, because the euro amount owed has grown. The numbers below use the site's running rate of 0.85
pounds per euro at booking and an invented key date rate of 0.80, so the pound has become stronger.

[cols="2,2,2,2,2,2",options="header"]
|===
| Item | Foreign amount | Booked at 0.85 (EUR) | Valued at 0.80 (EUR) | stem:[\Delta] (EUR) | Result

| Customer invoice (receivable) | GBP 8,500.00 | 10,000.00 | 10,625.00 | +625.00 | Gain 625.00
| Supplier invoice (payable) | GBP 4,250.00 | 5,000.00 | 5,312.50 | +312.50 | Loss 312.50
|===

The arithmetic, line by line, with stem:[A_1 = 8500] and stem:[A_2 = 4250]:

[stem]
++++
\frac{8500}{0.85} = 10000, \qquad \frac{8500}{0.80} = 10625, \qquad \Delta_1 = 10625 - 10000 = 625
++++

[stem]
++++
\frac{4250}{0.85} = 5000, \qquad \frac{4250}{0.80} = 5312.50, \qquad \Delta_2 = 5312.50 - 5000 = 312.50
++++

The net effect on the profit and loss statement of the period is a gain of stem:[625.00 - 312.50 = 312.50] euros. The two
items together are worth GBP 4,250.00 net, which is EUR 5,312.50 at 0.80 against EUR 5,000.00 at 0.85, so the same
difference of 312.50 results.

SAP Help names the accounts the run needs: expense and revenue accounts for exchange rate differences from valuation,
and, for receivables and payables accounts, financial statement adjustment accounts. The customer and supplier accounts
themselves are therefore not changed. A posting of the following shape results; the account names are generic, because
the real accounts come from your own Customizing.

[cols="4,2,2",options="header"]
|===
| Account | Debit (EUR) | Credit (EUR)

| Adjustment account for receivables | 625.00 |
| Unrealized gain from exchange rate differences | | 625.00
| Unrealized loss from exchange rate differences | 312.50 |
| Adjustment account for payables | | 312.50
| Total | 937.50 | 937.50
|===

This is a worked illustration built from the SAP Help description and the book's account list; it requires an SAP system
to reproduce and was not run here. The page on xref:erp/sap/finance/account-determination-and-automatic-postings.adoc[account
determination] shows the same idea for a foreign currency balance sheet account and says that the run can be reset or
reversed.

== GR/IR regrouping

When goods arrive before the invoice, the goods receipt credits the GR/IR clearing account; the invoice later clears it.
The worked example is on the page about xref:erp/sap/finance/account-determination-and-automatic-postings.adoc[account determination]. At
the key date some items are still uncleared: goods received and not invoiced leave a credit balance, an invoice entered
before the goods leaves a debit balance. Both are open obligations that a balance sheet should not hide inside one
net figure.

SAP Help states that before you create the balance sheet you can analyze the GR/IR clearing account and perform any
necessary correction postings. The documented path is Periodic Processing, Closing, Regroup, GR/IR Clearing in General
Ledger Accounting. On the selection screen you fill the parameters; when you post acquisition tax you must give an
interim account and an input tax code, and you can set the document type and the output specifications. You then choose
the execution method under Program. The page does not describe the adjustment postings in detail, so how an item is
shown on the balance sheet follows your accounting policy and the program documentation in the system.

The documentation for newer releases also lists apps and functions for reconciling GR/IR accounts, among them Reconcile
GR/IR Accounts and an intelligent GR/IR reconciliation. They are named in the table of contents only and were not read
for this page.

Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/651d8af3ea974ad1a4d74449122c620e/b152d7531a4d424de10000000a174cb4.html[SAP Help: Regrouping the GR/IR Clearing Account (on premise 2025 FPS02)]

== Regrouping receivables and payables

Before the financial statements, receivables and payables are ordered by remaining term so that they appear correctly.
SAP Help lists the cases that need adjustment postings: a customer account in credit, which cannot be shown as a
receivable and must appear as a payable; a vendor account in debit, which must appear as a receivable; a changed
reconciliation account, where items posted to the old account move to the new one; and, in some countries such as
France, investments that must be shown separately. The report is `SAPF100`. It analyzes all accounts managed on an open
item basis (foreign currency items always, local currency items only if they carry a due date) and posts the
transfer and adjustment postings for each G/L account, business area and currency. The menu path is Accounting,
Financial Accounting, Accounts Receivable or Accounts Payable, Periodic Processing, Closing, Regroup,
Receivables/Payables.

A small example: the customer account of an Example Trading Co. customer shows a credit balance of EUR 300.00 because of
an advance payment. The customer is a net creditor for that amount, so the report moves EUR 300.00 out of the
receivables total and into payables; the total of receivables falls by 300.00 and the total of payables rises by 300.00.
The balance of the customer account itself is unchanged. This describes the purpose stated in SAP Help; it was not run
here.

Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/651d8af3ea974ad1a4d74449122c620e/5f38d25320cd4608e10000000a174cb4.html[SAP Help: Transferring and Sorting Receivables and Payables (on premise 2025 FPS02)]

== Allocations and settlement

Controlling closes its own books on top of Financial Accounting. SAP Help lists these Cost Center Accounting steps:
periodic reposting, accrual cost calculation, transfer of statistical key figures, overhead calculation, periodic
allocations (distribution, assessment, indirect activity allocation, target equals actual activity allocation and
template allocation), variance calculation, predistribution of fixed costs and actual price calculation. The Schedule
Manager helps to carry out and check the closing. For internal orders, SAP Help lists revaluation at actual prices,
calculating overheads, periodic reposting, template allocation, internal order settlement, and the assessment and
distribution methods.

Allocation is covered on its own page, xref:erp/sap/finance/allocations.adoc[Allocations], with a rent example for three
cost centers. Settlement passes the costs collected on an order to the receivers of that order at period end; the page
xref:erp/sap/finance/cost-centers-and-internal-orders.adoc[Cost Centers and Internal Orders] explains the objects. The
Public Edition uses projects instead of internal orders for this kind of collecting object.

The order matters in the close. Allocations should run after all costs have been posted and accrued, because they spread
what is on the sender at the moment the cycle runs; settlement and variance calculation follow, and finance reviews the
result before the period is closed.

Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/5e23dc8fe9be4fd496f8ab556667ea05/7e10d553088f4308e10000000a174cb4.html[SAP Help: Overview: Period-End Closing (Cost Center Accounting)] and https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/5e23dc8fe9be4fd496f8ab556667ea05/3012d553088f4308e10000000a174cb4.html[SAP Help: Period-End Closing (Internal Orders)]

== Closing the periods

The last step of a close is to stop postings. A period stays open or closed according to the posting period variant of the
company code, so the closing lead closes period 012 after the final review and opens period 001 of the next year. A
special period (013 to 016) can stay open for year-end adjustments after the regular periods are closed. All of this is
explained, with the Manage Posting Periods app, on xref:erp/sap/finance/fiscal-year-and-posting-periods.adoc#_opening_and_closing_posting_periods[Fiscal
Year Variants and Posting Periods].

At the year end, balance carryforward carries the account balances into the new fiscal year. SAP Help describes it as a
function of closing operations; its documentation lists a Generate Balance Carryforward Distribution topic and a
retained earnings transfer at year end, which this page does not cover.

Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/651d8af3ea974ad1a4d74449122c620e/4b187752a9d07154e10000000a44176d.html[SAP Help: Closing Operations (on premise 2025 FPS02)]

== Financial Closing cockpit and Advanced Financial Closing

A real close has dozens of tasks and many people. A spreadsheet of tasks soon fails: nobody knows what is done, and
dependencies are in people's heads. SAP offers two tools.

The *SAP S/4HANA Financial Closing cockpit* is part of the software component S4CORE and is delivered with SAP S/4HANA.
SAP Help lists these cases for it: activities recur periodically, several people are involved, the activities follow a fixed
or dependency-driven sequence, a shared interface helps and the status of every periodic activity has to be visible. It
organizes closing activities by event, gives an overview with monitoring and offers analysis tools. Its building blocks
are hierarchies of the organizational objects, templates that reflect the organization, task lists derived from
templates, a monitor with critical paths and a Gantt diagram, dependencies between tasks and connections to external
schedulers through the Business Automation Enabler (BAE). Tasks can also run in remote systems as remote transactions,
programs or jobs. You can use it in SAP GUI or in the SAP Fiori Launchpad.

[cols="3,3,3",options="header"]
|===
| Activity | App on the SAP Fiori Launchpad | SAP GUI

| Create templates and task lists, release task lists
| Manage Task Templates (SAP S/4HANA Financial Closing cockpit)
| Financial Closing cockpit - Customizing (`FCLOCOC`)

| Change and release task lists
| Release Closing Cockpit Task Lists (SAP S/4HANA Financial Closing cockpit)
| Financial Closing cockpit - Preparation (`FCLOCOT`)

| Change and execute task lists
| Task Lists (SAP S/4HANA Financial Closing cockpit) and Process Closing Tasks (SAP S/4HANA Financial Closing cockpit)
| Financial Closing cockpit - Customizing (`FCLOCOC`)
|===

Requires an SAP system; not run here. The table follows the SAP Help page; the page does not give Fiori app IDs, so none
are shown.

*SAP Advanced Financial Closing (AFC)* is the other tool. The SAP Help page on integration with Advanced Financial Closing
states that the use of SAP Advanced Financial Closing requires an additional license. The page shows that a job such as
the intercompany matching run is available as a closing task in AFC, which you add to a task template with the Manage
Closing Task Lists app and then schedule or run in Process Closing Tasks. The cockpit is therefore the closing tool that
comes with S/4HANA, while AFC is a separately licensed product. Which one a company uses depends on its landscape and
its license; this page does not compare their features beyond what the cited pages state.

Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/8b1d76cd5e7644caa0553fcf338f3982/3fe49e8767d648a6b1b5edeec8849b8d.html[SAP Help: SAP S/4HANA Financial Closing (on premise 2025 FPS02)] and https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/651d8af3ea974ad1a4d74449122c620e/6f0b22e69daa4a9c89923b773ba8258d.html[SAP Help: Integration with Advanced Financial Closing]

== What older books show, and what has changed

The book Configuring SAP S/4HANA Finance, 3rd edition (2025), covers foreign currency valuation, regrouping and the
Financial Closing cockpit in its chapter on closing operations, including the automatic posting accounts that the
valuation needs. Its menu paths match the ones in this page. The book SAP S/4HANA Financial Accounting Configuration,

Public Edition documentation for the app-based equivalents.

== Common errors and pitfalls

[cols="2,3",options="header"]
|===
| Pitfall | What to do

| A valuation run is started twice for the same key date.
| SAP Help allows one run per valuation area and key date. Check the result list before starting another run.

| An accrual is reversed more than once.
| The Reverse action posts an inverse amount each time. Use it once and check the postings.

| Valuation runs before the last invoices are posted.
| Post and clear first, then value, so that the key date balances are complete.

| Accounts for exchange rate differences are missing.
| Define the expense, revenue and adjustment accounts in the Customizing for the automatic postings before the run.

| Allocations run before accruals.
| Post the accruals first, so that the sender holds all its costs when the cycle runs.

| The period is closed while the cockpit shows open tasks.
| Close the period only after the closing lead has checked the task list status.
|===

== Summary

* Period-end closing is an ordered set of steps: accruals, foreign currency valuation, regrouping, allocations and
  settlement, review, closing the period and, at the year end, balance carryforward.
* Accruals Management calculates and posts accruals in a periodic run for a key date; in the Public Edition the
  Accounting Accruals Agent helps to prepare manual accruals.
* A foreign currency valuation difference is stem:[\Delta = A/r_k - A/r_b] for rates quoted as foreign currency per
  euro; the sign and the item type tell gain or loss. In the example, EUR 625.00 gain and EUR 312.50 loss.
* GR/IR and receivables and payables regrouping make the balance sheet show the right terms and sides; Controlling
  allocates and settles on top.
* The Financial Closing cockpit comes with S/4HANA; Advanced Financial Closing requires an additional license.
