= SAP Finance Guide: Compute a Depreciation Schedule
:description: Step-by-step guide to a small CAP teaching model (CAP Node.js 10.2): a function that computes straight-line, remaining-life and declining-balance depreciation with a changeover for the delivery van of company code EX01, checked against the formulas and the worked examples of the SAP help pages.
:keywords: SAP, finance, asset accounting, depreciation, depreciation schedule, straight-line, remaining life, declining balance, changeover, net book value, acquisition cost, company code, CAP, function, step by step, guide
:stem: latexmath

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-13 against CAP Node.js 10.2 (`@sap/cds` 10.2.2, `@sap/cds-dk` 10.2.1, `@cap-js/cds-test` 1.0.2), curl 8.7, jq 1.7 and Node.js 24.21.

== What you build

This is a teaching model built with CAP. It is not SAP S/4HANA or SAP SuccessFactors and does not reproduce their screens.

You build a small service for the company code `EX01` of Example Trading Co. It holds two fixed assets, a delivery van of 15,000.00 EUR for the profit center `EX-RETAIL` and warehouse shelving of 12,000.00 EUR for `EX-WHOLE`, and it has a function that turns a method, a base amount and a number of years into a *depreciation schedule*: for every year the depreciation, and the net book value that is left. It knows the three methods that xref:erp/sap/finance/asset-accounting.adoc[Asset Accounting] describes: straight-line over the total useful life, straight-line from the net book value over the remaining life, and declining balance with a changeover to straight-line. You call the function with curl, and a test file proves the amounts against the worked examples of the SAP help pages: 1,000 over 10 years is 100 a year, a net book value of 500 over 5 remaining years is 100, and a net book value of 700 with a useful life of 10 and a factor of 3 is 210.

== Before you start

* No account is needed: the CAP tools, curl and jq install without signing in. Installing `@sap/cds-dk` means accepting the SAP Developer License Agreement, version 3.2, which the lab README names.
* Do the guide xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service] first (it explains `cds init`, CDS files, CSV data and `cds watch`). The guide xref:erp/sap/finance/guide-post-balanced-journal-entries.adoc[Post Balanced Journal Entries in a Teaching Ledger] is a good second step, but this guide does not depend on it.
* Read xref:erp/sap/finance/asset-accounting.adoc[Asset Accounting] for the terms (acquisition and production cost, net book value, depreciation key) and the formulas. This guide computes the table in the section A depreciation schedule for the van.
* You need curl and `jq`. `jq` prints each row of an answer on its own line; it is optional, and without it the answer is one long line of JSON.
* The names. The formulas and the three worked examples come from three pages of the SAP Help Portal for Asset Accounting, SAP S/4HANA 2025 FPS02 (Straight-Line Depreciation over Total Useful Life, Straight-Line from the Book Value over Remaining Useful Life, Declining-Balance Method of Depreciation), and the changeover conditions from the page Changeover Method; the Sources list them. The names of the model (`Assets`, `AcquisitionCost`, `UsefulLife`, `Method`, `Factor`, `Year`, `Depreciation`, `NetBookValue`, `Rule`) and the function names `calculate` and `plan` are our own. The asset numbers, the amounts, the profit centers and the factor of 2 are made up for the example.
* The figures are drawings of the editor and the terminal, not screenshots. A highlighted box with a number marks the file or the line of the step with the same number.

=== Write the depreciation rules

[start=4]
. Create `srv/schedule.js`. It is plain JavaScript without CAP, so you can test it alone. Amounts are whole cents, so that the sums are exact. `evenAmount` is the division of the two straight-line methods: depreciation is the acquisition and production cost (APC) divided by the useful life, or the net book value divided by the remaining life. The base differs, the division is the same. `decliningAmount` is the net book value times the rate from the useful life and the factor. The function `schedule` goes through the years. For declining balance it takes the declining amount until that amount is lower than the straight-line amount of the APC; from then on it spreads the net book value over the remaining years (the changeover). The last year takes what is left, so that the net book value ends at exactly zero.
+
[source,javascript]
----
include::example$sap-lab/depreciation/srv/schedule.js[]
----
+
Source: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/67e323b7117e4c91869c258933f47182/5e3dde531ed3424de10000000a174cb4.html[Declining-Balance Method of Depreciation (SAP Help Portal, on premise)]
+
image::sap-finance-guide-compute-a-depreciation-schedule-02-schedule-file.svg["Visual Studio Code with the file srv/schedule.js: an excerpt of the loop over the years that takes the straight-line amount of the book value over the remaining years, the declining amount, the changeover when the declining amount is lower than the straight-line amount of the cost, and the last year that takes the rest; callout 4 marks the file in the explorer",width=900]
. Create `srv/depreciation-service.cds`. It exposes the assets read-only and declares two functions. The unbound function `calculate` takes the method, the base, the years and the factor. The function `plan` is bound to an asset: it takes its numbers from the master record. A parameter is optional unless it is marked `not null`, so a call without `Factor` is allowed; the service checks it for declining balance. The functions are called `calculate` and `plan` because CAP warns about a custom function named `schedule`, which would shadow a method of the service base class.
+
[source,cds]
----

The handler of `calculate` reads the parameters from `req.data`, checks them with `check` and answers HTTP 400 with `req.error` when they are wrong. The handler of `plan` is declared for the entity `Assets`, so CAP gives it the key of the asset in `req.params`.

=== Start the service and ask for schedules

[start=7]
. In the terminal, in the project folder, start the server. The log shows the CSV file loaded and `DepreciationService` served at `/odata/v4/depreciation`; the line `impl: 'srv/depreciation-service.js'` shows that CAP found your rules.
+
[source,bash]
----
cds watch
----
+
image::sap-finance-guide-compute-a-depreciation-schedule-04-cds-watch.svg["Terminal after cds watch in the depreciation project: the log lists the model files, loads the CSV file for Assets into an in-memory SQLite database, serves DepreciationService at /odata/v4/depreciation with the implementation srv/depreciation-service.js and ends with server listening on http://localhost:4004; callout 7 marks the command",width=900]
. Open a second terminal in the project folder. A function is called with GET, with its parameters in the address. Ask for the straight-line schedule of 15,000 over 5 years. Put the address in double quotes, because the shell reads the parentheses and the single quotes otherwise. The command is one line; the figure wraps it the way the terminal does. Every year is 3,000.00 and the net book value ends at 0.00.
+
[source,bash]
----
curl -s "http://localhost:4004/odata/v4/depreciation/calculate(Method='straight-line',Base=15000,Years=5)" | jq -c '.value[] | {Year,Depreciation,NetBookValue,Rule}'
----
. Ask for the SAP help example of the remaining-life method: a net book value of 500 and 5 remaining years. Here `Base` is the net book value and `Years` the remaining life. The answer is 100.00 in each year, 500 / 5 = 100.
+
[source,bash]
----
curl -s "http://localhost:4004/odata/v4/depreciation/calculate(Method='remaining-life',Base=500,Years=5)" | jq -c '.value[] | {Year,Depreciation,NetBookValue,Rule}'
----
+
image::sap-finance-guide-compute-a-depreciation-schedule-05-even-schedules.svg["Terminal with two curl commands piped to jq: the straight-line schedule of 15000 over 5 years shows 3000.00 in each of the five years and a net book value of 0.00 at the end (callout 8), and the remaining-life schedule of a net book value of 500 over 5 years shows 100.00 in each year (callout 9); the long commands wrap onto a second line",width=900]
. Ask for the declining-balance schedule of the van: 15,000, 5 years, factor 2. The rate is 100% / 5 times 2 = 40%. The first two years are declining, 6,000.00 and 3,600.00. In year 3 the declining amount (2,160.00) is lower than the straight-line amount of the APC (3,000.00), so the rule changes to `changeover` and the net book value of 5,400.00 is spread over the 3 remaining years, 1,800.00 each.
+
[source,bash]
----
curl -s "http://localhost:4004/odata/v4/depreciation/calculate(Method='declining-balance',Base=15000,Years=5,Factor=2)" | jq -c '.value[] | {Year,Depreciation,NetBookValue,Rule}'
----
. Ask for the same schedule through the asset master record. `plan` is bound to the asset `10001`, so the address names the asset and the numbers come from the CSV file. The answer is the same as in step 10.
+
[source,bash]
----
curl -s "http://localhost:4004/odata/v4/depreciation/Assets('10001')/plan()" | jq -c '.value[] | {Year,Depreciation,NetBookValue,Rule}'
----
+
image::sap-finance-guide-compute-a-depreciation-schedule-06-declining-schedules.svg["Terminal with two curl commands piped to jq: the declining-balance schedule of 15000 over 5 years with factor 2 shows 6000.00 and 3600.00 with the rule declining, then 1800.00 in years 3 to 5 with the rule changeover and a net book value of 0.00 (callout 10); the schedule of the delivery van read from its master record is the same (callout 11)",width=900]
. Ask for a method that the model does not know, and add `-w` to see the status. The answer is HTTP 400 with the message `Unknown method sum-of-digits; use straight-line, remaining-life, declining-balance`.
+
[source,bash]
----
curl -s -w "\nHTTP %{http_code}\n" "http://localhost:4004/odata/v4/depreciation/calculate(Method='sum-of-digits',Base=15000,Years=5)"
----
. Ask for declining balance without a `Factor`. The answer is HTTP 400 with `The declining-balance method needs a Factor greater than zero`.
+
[source,bash]
----
curl -s -w "\nHTTP %{http_code}\n" "http://localhost:4004/odata/v4/depreciation/calculate(Method='declining-balance',Base=15000,Years=5)"
----
+
image::sap-finance-guide-compute-a-depreciation-schedule-07-input-rejected.svg["Terminal with two curl commands: the unknown method sum-of-digits is answered with the message Unknown method sum-of-digits; use straight-line, remaining-life, declining-balance and HTTP 400 (callout 12), and the declining-balance method without a factor is answered with The declining-balance method needs a Factor greater than zero and HTTP 400 (callout 13); long lines wrap",width=900]

== Check the result

The sums on this page are the amounts that the service answered and the tests assert. With stem:[APC] the acquisition and production cost, stem:[n] the useful life and stem:[NBV_t] the net book value at the start of year stem:[t]:

* Straight-line over the total life, the formula stem:[D_t = APC / n] of the SAP help page, gives for the van:
+
[stem]
++++
D_t = \frac{15{,}000}{5} = 3{,}000, \qquad 5 \times 3{,}000 = 15{,}000
++++
* Straight-line from the net book value, stem:[D_t = NBV_t / n_{rem}], gives the example of the SAP help page, a net book value of 500 and 5 remaining years:
+
[stem]
++++
D_t = \frac{500}{5} = 100
++++
* Declining balance, stem:[D_t = NBV_t \times \frac{100\%}{n} \times f], gives the SAP example (net book value 700, useful life 10, factor 3) and the first years of the van, with the changeover in year 3:
+
[stem]
++++
700 \times \left( \frac{100\%}{10} \times 3 \right) = 210
++++
+
[stem]
++++
D_1 = 15{,}000 \times 0.40 = 6{,}000, \qquad D_2 = 9{,}000 \times 0.40 = 3{,}600
++++
+
[stem]
++++
5{,}400 \times 0.40 = 2{,}160 < \frac{15{,}000}{5} = 3{,}000 \;\Rightarrow\; D_3 = D_4 = D_5 = \frac{5{,}400}{3} = 1{,}800
++++
+
[stem]
++++
6{,}000 + 3{,}600 + 3 \times 1{,}800 = 15{,}000
++++

These are the amounts in the table of the section A depreciation schedule for the van in xref:erp/sap/finance/asset-accounting.adoc[Asset Accounting].

Check that:

* the straight-line answer of step 8 and the remaining-life answer of step 9 show the same amount in every year, and the net book value ends at `0.00`;
* the answers of steps 10 and 11 are identical, and the sum of the five depreciation amounts is 15,000.00;
* `npm test` of step 16 shows a check for every test and no failed test.

== Variations

* Change the changeover rule. SAP's help lists several changeover methods, among them a changeover as soon as the amount of the next phase is higher. In `srv/schedule.js` replace `evenAmount(apc, years)` in the line that sets `changed` by `evenAmount(nbv, remaining)` and ask for the van again. The schedule is 6,000.00, 3,600.00, 2,160.00, 1,620.00 and 1,620.00, which also adds up to 15,000.00, but the changeover comes a year later. A real depreciation key sets its changeover method in Customizing, so the year of the changeover follows the key. Undo the edit afterwards: two tests fail with it.
* Ask for the shelving: `Assets('10002')/plan()` answers 10 rows of 1,200.00, because 12,000 / 10 = 1,200.
* Ask for the group area of the example in Asset Accounting, an APC of 15,300.00 over 5 years: `calculate(Method='straight-line',Base=15300,Years=5)` answers 3,060.00 a year.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|`zsh:1: number expected` (other shells print a syntax error) and no answer
|The address was not in double quotes, so the shell read the parentheses of the function call.
|Put the whole address in double quotes, as in step 8.

|`HTTP/1.1 405 Method Not Allowed`
|The function was called with POST (`curl -X POST`). Functions are called with GET; actions are called with POST.
|Call it with GET, which is curl's default.

|`+Unknown method ...+` or `The declining-balance method needs a Factor greater than zero` and HTTP 400
|The method is not one of `straight-line`, `remaining-life` or `declining-balance`, or the factor is missing.
|Correct the parameters of the call.

|`+[cds] - WARNING: custom function 'schedule()' conflicts with method in base class.+`
|A custom function was named `schedule`, which is also a method of the service base class `ApplicationService`.
|Choose another name, as in step 5.

|Two tests fail after the edit of the first variation
|The expected amounts of the van assume the changeover rule of step 4.
|Undo the edit, or change the expected amounts in the test deliberately.
|===
