= Start Here: SAP from Zero
:description: A guided path through the SAP section for a complete beginner, with reading times, from what SAP is through the user interface and the organizational structure to the first hands-on guides, and then a choice of Finance, human resources or development, with what you can safely skip at first.
:keywords: SAP, beginner, start here, learning path, SAP S/4HANA, SAP GUI, SAP Fiori, organizational structure, finance, human resources, ABAP, CAP, hands-on lab

SAP is a large family of business software, and the first week with it is confusing mainly because everything has an abbreviation. This page is the map for a complete beginner. It puts the pages of this section in an order that works, tells you roughly how long each takes to read, and shows where the path splits into finance, human resources and development so that you can choose by what you want to do. You do not have to read everything: the last part lists what you can skip at first. The pages are written for SAP S/4HANA 2025 FPS02 (on premise and Private Edition) and SAP S/4HANA Cloud Public Edition 2608, and each page says where a statement applies to only one of them. After this page you will know which page to open next and why.

== Before you read

No SAP knowledge is needed. If you have never programmed, read xref:programming-languages/abap/programming-concepts-for-newcomers.adoc[Programming Concepts for Newcomers] at the side of the development path; the finance and human resources paths need no programming at all.

== Key terms

* xref:erp/sap/glossary.adoc#erp[ERP]: enterprise resource planning, one business system that keeps a company's money, sales, purchasing, production and people data together.
* xref:erp/sap/glossary.adoc#sap-s4hana[SAP S/4HANA]: SAP's current core ERP system, built on the SAP HANA database.
* xref:erp/sap/glossary.adoc#sap-gui[SAP GUI]: the traditional desktop program for working with an SAP system by transaction codes.
* xref:erp/sap/glossary.adoc#sap-fiori-launchpad[SAP Fiori launchpad]: the browser start page that shows a user's apps as tiles.
* xref:erp/sap/glossary.adoc#company-code[Company code]: the smallest organizational unit for which a complete set of accounts can be kept.
* xref:erp/sap/glossary.adoc#client[Client]: a self-contained unit of data and settings inside one SAP system, entered at sign-in.
* xref:erp/sap/glossary.adoc#cap[SAP Cloud Application Programming Model (CAP)]: SAP's framework for building business services, used by the hands-on guides.

== Step 1: what SAP is (about 20 minutes)

Start with xref:erp/sap/what-is-sap.adoc[What Is SAP]. It names the product families around S/4HANA and explains the old module names (FI, CO, SD, MM and so on) that colleagues still use every day. When you have read it you can place any SAP product or module on the map. If you want to know why the same software appears as on premise, Private Edition and Public Edition, read xref:erp/sap/deployment-options.adoc[Deployment Options] (about 12 minutes) later; it is not needed yet.

== Step 2: how you work with SAP (about 25 minutes)

Two user interfaces exist side by side. xref:erp/sap/sap-gui-basics.adoc[SAP GUI Basics] (about 10 minutes) shows the classic desktop program, in which you open a function by typing a transaction code. xref:erp/sap/fiori-launchpad.adoc[SAP Fiori Launchpad] (about 16 minutes) shows the browser start page with tiles. Read both, because a real company usually uses both.

== Step 3: how a company is set up (about 35 minutes)

Before you can understand any process, you need to know where its data lives. xref:erp/sap/clients-and-system-landscape.adoc[Clients and the System Landscape] (about 16 minutes) explains the client you sign in to and the separate development, test and production systems. xref:erp/sap/organizational-structures.adoc[Organizational Structures] (about 17 minutes) explains company codes, plants and the other units that every posting refers to. Together they answer the question "where in the company is this happening?".

== Step 4: how work flows (about 16 minutes)

xref:erp/sap/end-to-end-processes.adoc[End-to-End Processes] follows a purchase and a sale from the first document to the accounting posting. It is the page that makes the earlier ones concrete. If a business term is new, look it up in the xref:erp/sap/glossary.adoc[SAP Glossary].

== Step 5: try it yourself

The xref:erp/sap/hands-on-lab.adoc[Hands-on Lab] explains the local lab that every guide uses. It needs no SAP account. Install Node.js, and then do xref:erp/sap/guide-first-cap-service.adoc[SAP Guide: Your First CAP Service] (about 9 minutes to read, and then the time the steps take). It builds a small expense-claim service on your own computer, so that the words "model", "service" and "OData" stop being abstract. If you plan to program in ABAP instead, use the xref:programming-languages/abap/hands-on-lab.adoc[ABAP Hands-on Lab] and start with xref:programming-languages/abap/guide-set-up-a-local-abap-playground.adoc[ABAP Guide: Set Up a Local ABAP Playground].

The reading times assume 200 words a minute and include the code and tables of the page; they are an estimate, not a promise. Doing the steps of a guide takes longer than reading it.

== What you can skip at first

* The pages about SAP BTP (xref:erp/sap/btp-account-model.adoc[account model], xref:erp/sap/btp-environments-cloud-foundry-and-kyma.adoc[environments], xref:erp/sap/btp-connectivity-and-destinations.adoc[connectivity], xref:erp/sap/btp-security-xsuaa-and-identity.adoc[security]) matter when you deploy to the cloud, not when you learn the ideas.
* The pages on xref:erp/sap/extensibility-and-clean-core.adoc[extensibility], xref:erp/sap/transports-and-change-management.adoc[transports] and xref:erp/sap/implementation-projects-and-go-live.adoc[implementation projects] matter when you work in a customer project; read them when you join one.
* The integration pages (xref:erp/sap/rfc-bapi-idoc-and-soap-integration.adoc[RFC, BAPI, IDoc], xref:erp/sap/odata-and-sap-gateway.adoc[OData], xref:erp/sap/api-management.adoc[API management]) are reference pages; return to them when a task needs one.
* Finance and human resources go into great depth; read one overview and one guide, then follow your questions.

== Summary

* Read What Is SAP, then the two user interfaces, then clients and organizational structures, then the end-to-end processes.
* Try the Hands-on Lab and xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service] early; they need no SAP account.
* Then choose Finance, human resources or development by what you want to do.
* The glossary of this section explains every abbreviation you meet.
* You can skip BTP, extensibility, transports and the integration pages until a task needs them.
