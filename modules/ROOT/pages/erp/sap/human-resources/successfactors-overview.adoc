= SAP SuccessFactors Overview
:description: What the SAP SuccessFactors suite contains (Employee Central, Employee Central Payroll, Recruiting, Onboarding, Performance and Goals, Compensation, Learning and Time Tracking), how the modules hand data to each other, and how the twice-yearly releases work, for release 2H 2026.
:keywords: SAP SuccessFactors, Employee Central, Employee Central Payroll, Recruiting, Onboarding, Performance and Goals, Compensation, Learning, Time Tracking, Time Off, Time Sheet, 1H, 2H, release, What's New Viewer, Compound Employee API
:stem: latexmath

include::partial$ai-disclaimer.adoc[]

SAP SuccessFactors is SAP's cloud suite for human resources. Instead of one big program installed in the company's own
data center, it is a set of separate cloud applications, called modules, that a company subscribes to one by one: one
keeps the employee records, one finds new people to hire, one welcomes them on the first day, one runs appraisals, one
plans pay raises, one trains staff, one records time and one calculates payroll. A newcomer meets the suite in job
descriptions, project plans and integration diagrams, usually as a list of product names that are hard to tell apart.
This page names each module in plain words, shows which module hands data to which, and explains the release rhythm of
1H and 2H. After reading it you can place any SuccessFactors term in the right module and know which later page of this
section goes deeper. It is written against SAP SuccessFactors release 2H 2026 (documentation version 2611). The
modules run in SAP's cloud and are used with a subscription, so nothing on this page can be tried without a company
instance and an account; every listing here is therefore labeled as requiring an SAP SuccessFactors system and not run
here.

== Key terms

* xref:erp/sap/human-resources/glossary.adoc#successfactors[SuccessFactors]: SAP's cloud suite for human resources, made of separately subscribed modules.
* xref:erp/sap/human-resources/glossary.adoc#employee-central[Employee Central]: the module that holds the core employee records and the company's organization, pay and job structures.
* xref:erp/sap/human-resources/glossary.adoc#employee-central-payroll[Employee Central Payroll]: the cloud payroll that SAP offers together with Employee Central.
* xref:erp/sap/human-resources/glossary.adoc#compound-employee-api[Compound Employee API]: a SOAP-based interface of Employee Central that extracts employee data for replication to other systems.
* xref:erp/sap/human-resources/glossary.adoc#odata-api[OData API]: a web interface for reading and changing data in SuccessFactors modules.
* xref:erp/sap/human-resources/glossary.adoc#half-year-release[1H and 2H releases]: the two large batches of new features that SAP SuccessFactors delivers every year.

== The example used on this page

Every page of this section uses one made-up business, Example Trading Co. (company code `EX01`, currency EUR). Its
employees are Ana Torres (personnel number `00001234`, Sales Manager, hired 01.03.2024), Ben Okoye (`00001235`, Sales
Clerk, hired 01.09.2024) and Chloe Martin (`00001236`, Warehouse Clerk, hired 15.01.2025, hourly staff in monthly
payroll area `E1`, which is the example's own choice). All codes and values are invented for this site; none is an
SAP-delivered value. On this page the example answers one question: if Example Trading Co. ran its people processes in
SuccessFactors, which module would hold which fact about Ana, Ben and Chloe? The mapping is an illustration of the
modules' roles, not a statement about how any real company configures them.

module says that Employee Central captures information about a company's organization, pay and job structure and its
employees, and that other modules such as Compensation and Variable Pay can read that information. The diagram shows
the hand-offs that the official pages describe; it is a simplification and leaves out many interfaces.

Two details from those pages prevent common mistakes. First, absences and attendances belong to different tools: the
documentation says that Time Off must not be used to record attendances and the reverse, and gives working from home as
an attendance. Second, the Employee Central documentation states that Employee Central Time Management is part of the
Employee Central subscription, while Time Tracking is not.

Later pages of this section go deeper: Employee Central data models and the Metadata Framework, the SuccessFactors
OData API, the talent modules (Recruiting, Onboarding, Performance, Compensation and Learning), and Employee Central
Payroll.

== How data moves between modules

Employee Central is where an employee is stored, so most hand-offs start or end there. Two are worth knowing early.

*From Onboarding to Employee Central.* The onboarding documentation describes the new hire as an external user until
the process ends, when the new hire is converted into an employee (an internal user). For Ben, hired 01.09.2024, this
is the point at which his employment record becomes a normal Employee Central employee.

*From Employee Central to payroll.* The Compound Employee API is based on SOAP and replicates employee master data from
Employee Central to SAP systems, payroll systems and benefits systems. Its documentation lists three properties that
matter to a payroll consumer: it returns all requested data of an employee in one hierarchically structured call, the
response includes all time slices of the entities in the request, and it replicates only data that has been approved in
Employee Central. For Employee Central Payroll, the payroll system itself calls this API on a schedule that an
administrator configures; the documentation shows a Customizing activity named Configure Compound Employee API Query
in the Employee Central Payroll system. That step requires an SAP SuccessFactors system; not run here.

Sources: https://help.sap.com/docs/SAP_SUCCESSFACTORS_EMPLOYEE_CENTRAL/5bb9a5b997a843c88e769a105e4af4d4/7600a92db04f440f890d1d9764c02670.html[Introduction to the Employee Central Compound Employee API] and https://help.sap.com/docs/SAP_SUCCESSFACTORS_EMPLOYEE_CENTRAL_PAYROLL/185f14fbe60d4bbb8d7d5e4f8d89b24b/bbcdc6f97e3742feb07da924e0293761.html[Configuring the Point-to-Point Replication]

The same Employee Central Payroll guide family has a deliverable for Employee Central Payroll based on SAP Human

variant based on SAP Human Capital Management for SAP ERP HCM. Both guides describe a payroll system that Employee Central calls or feeds, so the two
variants differ in the HR system they are based on. Payroll itself is taught
on the payroll pages of this section, such as xref:erp/sap/human-resources/payroll-process.adoc[The Payroll Process].

=== The March 2026 payslip, wherever it is calculated

Wherever payroll runs, the result for the same input is the same. The illustrative payslip of Ana Torres for March 2026
uses generic flat example rates that are not the rules of any country. Gross pay is 4,000.00 EUR. The employee social
contributions are 20.00% of gross, and the income tax is 15.00% of gross minus social contributions:

[stem]
++++
\text{social} = 4000.00 \times 0.20 = 800.00 \qquad
\text{tax} = (4000.00 - 800.00) \times 0.15 = 480.00 \qquad
\text{net} = 4000.00 - 800.00 - 480.00 = 2720.00
++++

The employer contributions are stem:[4000.00 \times 0.21 = 840.00], so the total employer cost is
stem:[4000.00 + 840.00 = 4840.00]. The arithmetic was checked by script. In a SuccessFactors landscape the calculation is
the job of Employee Central Payroll; Employee Central only supplies Ana's master data, such as her monthly basic pay of
4,000.00 EUR. Chloe, paid hourly at 14.00 EUR in the same monthly payroll area `E1`, would additionally need her recorded
attendances as input, which is the reason the Time Management module appears in the picture.

== Release cadence: 1H and 2H

SAP SuccessFactors releases large batches of new features twice a year, called 1H and 2H, and the documentation carries
the label of the batch, such as "2H 2026". The What's New Viewer is where the release notes appear. SAP changes the
default value of its Version filter when it publishes the notes of a new batch, so a reader waiting for the 2H notes can
tell from a default value of 1H that they are not yet published. This page's facts were read in documentation labeled
2H 2026; a page labeled for another batch may differ. Individual deliverables can follow their own rhythm: for example,
the Learning module documents a separate validated release schedule for customers who need a validated system. This
page does not state release dates because the pages read give none for the large batches.

== What older books show, and what has changed

The book SAP ERP HCM: Technical Principles and Programming, 1st edition (2013), by Dirk Liepold and Steve Ritter,
describes HR as a part of SAP ERP that the company installs and extends with its own ABAP programs. It was written
before SAP SuccessFactors Employee Central became the core of SAP's cloud HR offer and before SAP HCM for SAP S/4HANA
existed. A reader who learns from it should know that, in SuccessFactors, the company does not read tables or add its
own ABAP code to the modules; it configures them and connects to them through interfaces such as the Compound Employee
API and the OData APIs, and it receives new features in the twice-yearly releases. Details of the 2013 book that
concern ABAP and the classic HR tables remain background for the on-premise side and for Employee Central Payroll,
whose payroll system is an SAP system, but should be checked against the current documentation.

== Summary

* SAP SuccessFactors is a suite of separately subscribed cloud modules: Employee Central, Employee Central Payroll, Recruiting, Onboarding, Performance and Goals, Compensation, Learning and Time Tracking.
* Employee Central is the center; it holds employee, foundation and organization data that other modules read.
* Onboarding ends by turning a new hire into an employee, and Employee Central Payroll reads employee data from Employee Central through the Compound Employee API.
* Time Off and Time Sheet belong to the Employee Central subscription; Time Tracking needs a separate one.
* New features arrive in two large batches a year, 1H and 2H, and this page follows the 2H 2026 documentation.
* Nothing here was run: every step needs an SAP SuccessFactors system and an account.
