= HR Reporting Tools
:description: The tools that answer questions about HR data without programming, namely table utilities, InfoSets, QuickViewer, Ad Hoc Query, SAP Query, the Human Resources Information System, payroll evaluation with the wage type reporter and audit reporting, with Example Trading Co. questions, for SAP S/4HANA 2025 FPS02 on premise and Private Edition with SAP HCM for SAP S/4HANA.

Sooner or later somebody asks an HR system a question that no screen answers directly: "Which employees of the warehouse are paid
by the hour?", "What did we pay in basic salary in March?", "Who changed Ana's pay record, and when?" An HR consultant or
administrator does not need to write a program for most of these questions. SAP delivers more than 200 standard reports and a
small set of tools that build reports from point-and-click choices, and it delivers logs that record who read or changed what.
This page explains each of those tools in plain words, says what each one is good for and where it stops, and answers one question
per tool with the data of Example Trading Co. After reading it you can decide which tool fits a question and know where to look
when none of them does. The page is written for SAP S/4HANA 2025 FPS02 on premise and Private Edition with SAP HCM for SAP
S/4HANA (H4S4), a separately licensed component. It covers classic HR reporting inside the system. SAP SuccessFactors has its
own reporting tools, which other pages cover, and writing your own ABAP reports is the topic of a later page.

== Key terms

* xref:erp/sap/human-resources/glossary.adoc#infoset[InfoSet]: a view that picks fields of one or more data sources, here usually a logical database, and offers them to a query.
* xref:erp/sap/human-resources/glossary.adoc#user-group[User group]: a named set of users in SAP Query that decides which InfoSets they may use.
* xref:erp/sap/human-resources/glossary.adoc#infoset-query[InfoSet Query]: a general tool to build a report by ticking selection fields and output fields; in HR it is called Ad Hoc Query.
* xref:erp/sap/human-resources/glossary.adoc#sap-query[SAP Query]: a general reporting tool with more formatting and calculation options than InfoSet Query, which also manages user groups and InfoSets.
* xref:erp/sap/human-resources/glossary.adoc#quickviewer[QuickViewer]: a tool that builds a simple report on a table, a view or a join without ABAP coding.
* xref:erp/sap/human-resources/glossary.adoc#his[HIS]: the Human Resources Information System, a tool that starts reports along a hierarchical structure such as the organizational structure.
* xref:erp/sap/human-resources/glossary.adoc#wage-type-reporter[Wage type reporter]: the standard report H99CWTR0 that totals wage types of payroll results.
* xref:erp/sap/human-resources/glossary.adoc#change-document[Change document]: a log record of a change to infotype fields, evaluated with the report RPUAUD00.
* xref:erp/sap/human-resources/glossary.adoc#logical-database[Logical database]: a program owned by SAP that reads HR data and hands it to a report; HR queries are built on one.

== The running example

All HR pages on this site use one fictitious business, Example Trading Co. Every key, name, number and date below is an invented
example value, not a value delivered by SAP.

* `00001234` Ana Torres, Sales Manager, personnel area `EX01`, personnel subarea `0001`, employee subgroup `AA`, monthly basic pay 4,000.00 EUR.
* `00001235` Ben Okoye, Sales Clerk, personnel area `EX01`, personnel subarea `0001`, employee subgroup `AA`, monthly basic pay 2,400.00 EUR.
* `00001236` Chloe Martin, Warehouse Clerk, personnel area `EX01`, personnel subarea `0002`, employee subgroup `AB`, hourly rate 14.00 EUR.
* Payroll area `E1` is the monthly payroll area of Example Trading Co. The example's choice is that Chloe, although paid by the hour, is part of this monthly payroll area.

This page extends the example in one place: the payroll results of March 2026 for Ben and Chloe. Ana's results are fixed by the
other pages. Ben's result is simply his basic pay of 2,400.00 EUR. Chloe's result uses the 176.00 paid hours of March 2026 that
the page on xref:erp/sap/human-resources/wage-types-and-payroll-results.adoc[wage types and payroll results] derives (22 weekdays of 8 paid hours). All reports below are described, not run: using
them requires an SAP system, and the result tables on this page are worked out by hand and checked with a short script, not
copied from a system.

== The map of tools

SAP Help gives one overview table of the tools, and the rest of this page follows it. Read the table as a ladder of effort
and flexibility.

[cols="2,3,3,3",options="header"]
|===
| Tool | Purpose | Strength | Limit

| Standard reports
| Answer the most frequent questions.
| Usable immediately, no development.
| Little flexibility; you cannot choose the output fields freely.

| HIS
| Start reports along a hierarchy, such as the organizational structure.
| Friendly for browsing, very little training; reports of different HR areas start from one place.
| It starts existing reports (standard and customer reports) and cannot create reports.

| InfoSet Query (Ad Hoc Query in HR)
| Build your own report by choosing fields.
| No programming; very easy to use; can continue in SAP Query.
| InfoSets and user groups must exist first; multiline lists cannot be displayed.

| SAP Query
| Build your own report with more options.
| Extremely flexible without programming; aggregation, calculation and graphics; multiline lists; one basic list plus statistics and ranked lists.
| Reads SAP data only; each HR query uses one HR logical database; needs more training.

| Business Information Warehouse (BW)
| Analytical reporting, also with non-SAP data.
| Time series, averages, delivered HR business content.
| Works on data extracted from the operational system, so it is not real time.
|===

Table source: the SAP Help topic "Overview: HR Reporting", summarized in the wording of this site. For the three logical
databases that SAP Query uses in HR, the same topic names PNP for administration, time management and payroll, PCH for
all areas but especially personnel planning, and PAP for recruitment. In a system where concurrent employment is active, the
reports of the PNPCE logical database are used, and InfoSets for SAP Query are then created for PNPCE.

The next diagram condenses the purposes in that table and the topic "Selecting a Reporting Tool" into questions to ask in turn. The
last box, a custom report, is the way out when no tool fits.

[mermaid]
----
flowchart TD
    Q["A question about HR data"] --> S{"Does a standard report answer it?"}
    S -- yes --> R["Run the standard report"]
    S -- no --> H{"Do you want to browse a hierarchy and start reports from it?"}
    H -- yes --> HIS["HIS"]
    H -- no --> B{"Analysis over time or with non-SAP data?"}
    B -- yes --> BW["Business Information Warehouse"]
    B -- no --> A{"Is a simple list enough, with few formatting needs?"}
    A -- yes --> IQ["InfoSet Query, called Ad Hoc Query in HR"]
    A -- no --> SQ["SAP Query: control levels, statistics, multiline lists"]
    SQ --> C{"Still not enough?"}
    IQ --> C
    C -- yes --> ABAP["Custom ABAP report"]
----

== Table utilities

The simplest way to look at HR data is to look at the database table itself. The Data Browser, transaction `SE16`, shows the
contents of a table of the ABAP Dictionary. The authorization object that SAP Help documents for table access, S_TABU_DIS,
says that it controls access through standard table maintenance, extended table maintenance, the Data Browser and Customizing, and
that it can limit a user who may use `SE16` to the tables of certain authorization classes. That sentence shows the
point of caution: a table browser works below the HR authorization concept. A user who may see the table `PA0008` in
`SE16` sees the pay of every employee unless S_TABU_DIS or a similar setting limits the table, so table browsing belongs to
technical support staff and not to HR users.

In the example, the question "What rows exist for Ana's basic pay?" is a look at the table `PA0008` for the personnel number
`00001234`. The page on xref:erp/sap/human-resources/hr-data-structures-and-tables.adoc[HR data structures] explains the rows: one row per record with its validity period, so Ana has one row
that begins on 01.03.2024 and ends on 31.12.9999 until a raise creates a second one. A table browser is the right tool for a
consistency check or for tracing a problem, for example to see whether a payroll run read the rows that you expect. It is the
wrong tool for a business user, because it shows technical field names and no decoded texts. Clusters such as the payroll results in
`PCL2` cannot be read this way. Use a payroll report or the payroll result functions for them.

This page names only the transaction that the SAP Help pages confirm. Other table display transactions exist in the system and
the older book discussed below describes one of them. Look in the in-system documentation of your release for the
current set.

== InfoSets and user groups

A query tool needs a list of fields to offer. An InfoSet is that list: a view on a data source that chooses which fields users
may pick. For HR the data source is a logical database, which is why the HR reporting documentation says each HR query uses
data of one logical database only. The InfoSet decides what the query user can see, and a user group decides which users may use
which InfoSets. SAP Help states that SAP Query manages the user groups and InfoSets that InfoSet Query needs, unless you use
the InfoSets delivered in the standard system.

SAP delivers HR InfoSets, for example for Time Management. The topic "Time Management InfoSets" describes an InfoSet with all
relevant master data, time infotypes and simulated infotypes, and one InfoSet per time infotype, for example Absences (infotype
2001), Attendances (2002), Availability (2004) and Absence Quotas (2006). It advises using these as templates for your own InfoSets.
The topic "Evaluation of the Payroll Results Using Infotypes or the Logical Database" explains that payroll results reach a
query through payroll infotypes: the predefined infotypes 0402 and 0403 (period values) and 0458, 0459 and 0460 (monthly,
quarterly and annual cumulations of payroll results). You activate such an infotype in Customizing, and either the payroll
run fills it automatically if you configure that, or a report fills it independently. SAP recommends creating your own
payroll infotypes in the customer namespace `+9*+` rather than changing 0402 and 0403.

For your own InfoSets in a system with concurrent employment, SAP Help says to choose the PNPCE logical database, using the
Customizing activity Create InfoSets for HR. Its path is Personnel Management, Human Resources Information System, HR Settings for
SAP Query, Create InfoSets for HR. The steps to create an InfoSet and a user group are documented in the SAP Query documentation
of your system and need an SAP system; not run here.

== QuickViewer

QuickViewer, transaction `SQVI`, is the lightest tool of all. SAP Help describes it as a tool for quickly generating
client-dependent reports without ABAP coding. The steps on the page that SAP documents for it are short: name the quickview, give it a title, choose a data source (a table or view,
or a table join), choose which fields appear in the list and which fields are selection fields, save, execute, enter the selection
and execute again. The SAP page that describes this sits in the documentation of SAP Information Lifecycle Management, where it
is used for the Retention Warehouse, so treat it as a description of the tool and not as an HR topic.

For the example: a quickview on the table `PA0001` with the personnel area as a selection field would list the personnel
numbers of Example Trading Co., one row each for Ana, Ben and Chloe, but as raw table rows. Like the table browser it reads
tables, so the cautions of the previous section apply. The tool is useful for quick checks by consultants, and a business user
should use a query on an InfoSet instead.

== Ad Hoc Query (InfoSet Query in HR)

InfoSet Query lets a user choose selection fields and output fields directly, with no programming. SAP Help describes
it as the general SAP reporting tool that is particularly easy to use and says that you can save a report and reuse it when you
have the authorizations. When you start InfoSet Query from the Human Resources menu, the parameters work area and user group
are already filled and you can only do ad hoc reporting. SAP calls it Ad Hoc Query in HR. It reaches data across HR areas: personnel
administration data and person-related data from payroll, time management and personnel planning, and it can also report
on objects of personnel planning. Its limit is that multiline lists cannot be displayed and that InfoSets and user groups must exist.

Question 1 of Example Trading Co.: which employees of personnel area `EX01` belong to employee subgroup `AB`, hourly staff? The
query uses the selection fields Personnel Area `EX01` and Employee Subgroup `AB`, and the output fields personnel number and name. The
answer, worked out from the example data, is one row: `00001236` Chloe Martin. This is the kind of question that Ad Hoc Query is for,
a specific question asked once, which can be saved when it is needed again. A query like this reads through the logical database.
Which authorizations apply to it is a matter for the authorization concept of your company: see the HR authorization page of this
section for the objects behind the logical database.

== SAP Query

SAP Query is the cross-application tool behind Ad Hoc Query. SAP Help lists what it adds for HR reporting:

* Control levels, which group output fields, for example all addresses of one person. This matters for infotypes with subtypes or time constraint 3.
* One basic list, up to nine statistics and up to nine ranked lists in one query.
* Colors in output lists, and local fields that you define inside the query.
* Management of the user groups and InfoSets that InfoSet Query needs.

Use SAP Query when InfoSet Query cannot meet a requirement, or to refine a query that began in InfoSet Query. For time
data, the topic "SAP Queries in Time Management" recommends SAP Query instead of the HR Ad Hoc Query for the delivered time queries, because only SAP Query offers the full function range such as double-line lists.

Question 2 of Example Trading Co.: what is the total monthly basic pay of personnel subarea `0001` (head office)? A query with
the selection field Personnel Subarea `0001`, the output fields personnel number, name and monthly basic pay, and a
statistic that totals the pay gives these rows:

[cols="2,3,2",options="header"]
|===
| Personnel number | Name | Monthly basic pay (EUR)

| 00001234 | Ana Torres | 4,000.00
| 00001235 | Ben Okoye | 2,400.00
| Total | | 6,400.00
|===

The total is stem:[4{,}000.00 + 2{,}400.00 = 6{,}400.00]. Chloe is in subarea `0002`, so she is not in the list. The
table is worked out by hand from the example data and was checked with a script; no system produced it. The query would be
built on an InfoSet of the PNP logical database that offers the Basic Pay data, and building one requires an SAP system; not run here.

== The Human Resources Information System

HIS is the odd one of the family, because it creates no reports. SAP Help describes it as the tool to report on HR data along
hierarchical structures such as the organizational structure, the business event hierarchy or customer hierarchies. You
select the structure and the objects to show. The structure is displayed in SAP Structural Graphics, and a separate window lists
the reports that exist for the root object. These correspond to the standard HR reports, and Customizing lets you add your
own. HIS is especially helpful when you report on data of several HR components because every report starts from one place. It
needs no selection screen entries because it uses the parameters most often set in practice.

For Example Trading Co., the hierarchy is the organizational structure of the page on xref:erp/sap/human-resources/organizational-management.adoc[organizational management]: Example Trading Co.
(`50000001`) with the units Sales (`50000002`) and Warehouse (`50000003`). With HIS you would choose the structure, select the unit
Sales, and then start a report for that unit from the report list, for example a list of employees, without entering the
unit on a selection screen. Setting up HIS reports requires an SAP system; not run here.

== Payroll reporting and the wage type reporter

Payroll results are stored in a cluster, so table browsers cannot show them. SAP Help gives four ways to evaluate them: through payroll
infotypes and a query (above), through standard reports that use the payroll logical database, through the Business Information Warehouse,
and through the standard reports remuneration statement, payroll journal, payroll account and wage type reporter. Reports that depend on the country, such as statements
of contributions required by law, belong to the payroll of each country and are documented there. SAP Help lists payroll reports
for many countries and says that you reach them in the SAP menu under Human Resources, Payroll, the continent, the country and
Info System. This site does not model any country, so the example stays generic.

The wage type reporter, report H99CWTR0, evaluates wage types of payroll results. Per SAP Help it uses data from the results
table RT and the table WPBP (Work Center Basic Pay), and it does not include master data such as infotypes. Payroll must have run
successfully. It can evaluate a selected period or a specific payroll run, regular or off-cycle (for example a correction run, a
bonus payment or a manual check), compare two regular runs or two special runs of the same payroll type, show an in-period or
a for-period view, read archived payroll results, let you choose columns (for example company code, wage type, in-period) and wage
types, summarize selected wage types, and output to the SAP List Viewer or a Microsoft Excel table.

Question 3 of Example Trading Co.: which amounts do the wage types `1000` and `2000` total for payroll area `E1` in March 2026? The wage type
numbers are the invented ones of the page on xref:erp/sap/human-resources/wage-types-and-payroll-results.adoc[wage types and payroll results]. With the March 2026 results of the example, the
summarized output has this shape:

[cols="2,3,2,2",options="header"]
|===
| Wage type | Meaning | Employees | Amount (EUR)

| 1000 | Monthly salary | 00001234 Ana, 00001235 Ben | 6,400.00
| 2000 | Hourly pay | 00001236 Chloe | 2,464.00
| Total | | | 8,864.00
|===

Ana's 4,000.00 and Ben's 2,400.00 give 6,400.00, and Chloe's amount is stem:[176.00 \times 14.00 = 2{,}464.00]. The sum is
stem:[6{,}400.00 + 2{,}464.00 = 8{,}864.00]. The arithmetic was checked with a script. The table shows what the report would total,
it is not output copied from a system, and running the report requires an SAP system; not run here.

== Audit reporting

HR data is sensitive, so SAP provides records of who changed it and who ran reports on it.

* *Logged changes in infotype data.* If particular data needs special protection, you can activate change documents that log changes to infotype
  records. In the Implementation Guide for Personnel Management the path is Personnel Administration, Tools, Revision, Set up
  change document. SAP Help states that this log has nothing to do with authorization checks: it does not stop an unauthorized user, and it
  logs attempts by unauthorized users to access data. The report RPUAUD00, Logged Changes in Infotype Data, evaluates it. In the SAP menu
  it is under Human Resources, Personnel Management, Administration, Info System, Reports, Documents, Infotype Change. For changes to be
  recorded, the fields must be maintained in the views V_T585A (infotypes to be logged), V_T585B (field group definition) and V_T585C
  (field group characteristics). The report creates two kinds of documents. Long-term documents serve revision, can be archived
  with the archiving object PA_LDOC and are evaluated by personnel number and infotype. Short-term documents are stored in the
  database and selected by date and time.
* *Log of report starts.* The report RPUPROTD lists which reports were started. SAP Help says that a start is logged only if the report is
  entered in the table of HR report attributes, view V_T599R, with the flag "Record at start required online". The selection offers
  reports, user, date and time, and the output shows report, title, user, date and time.
* *Authorization objects for reporting.* The object P_ABAP (HR: Reporting) is used for HR reports based on the logical databases
  SAPDBPNP and SAPDBPAP, for evaluating logged changes in infotype data and for payment medium programs. Its fields are the report name (REPID)
  and the degree of simplification (COARS). SAP Help warns that a setting with COARS 2 for the report SAPDBPNP switches off the
  authorization checks of almost all HR reports, so it should not be given out lightly. The topic on the HR authorizations of this site
  explains the surrounding objects.
* *Utilities.* The page "Utilities in HR" lists RPUACG00 (code generation and authorization check), RPUAUD00 (infotype auditing) and RPINCL10
  (string search in reports), plus cluster utilities such as RPCLSTyy, which displays a cluster of PCLx.

For Example Trading Co., the audit question "who changed Ana's Basic Pay record, and when?" has the answer in RPUAUD00 only if infotype 0008 was
set up for logging before the change; a change made before logging was activated left no document. SAP Help makes the recording depend on the maintained
views, so check them before you promise an audit trail. That is why audit logging is decided early in a project.

== What older books show, and what has changed

The book SAP ERP HCM: Technical Principles and Programming, 1st edition (2013), by Dirk Liepold and Steve Ritter, devotes its chapter 7 to
these tools, and the concepts still hold: the table utilities, InfoSets for the logical databases, QuickViewer, InfoSet (Ad Hoc) Query, SAP Query, the
Human Resources Information System, payroll reporting with the wage type reporter, and the two audit reports. What changed since then:

* The book describes an SAP ERP HCM system. In SAP S/4HANA the HR functions come with SAP HCM for SAP S/4HANA, a separately licensed component
  whose business function is active by default from SAP S/4HANA 2025, so the documentation to read is the one for that component.
* The book names the table display transaction `SE16N` and several `S_AHR_` report transactions and menu paths. This page does not repeat these names because
  it did not find them on the SAP Help pages used here. Check them in your own system before relying on them.
* The book treats SAP BusinessObjects BI and SAP NetWeaver BW as separate platforms and keeps its focus on the tools delivered with the
  application. SAP Help still describes BW as the analytical option, without naming current products. Where a newer analytics
  offering applies to your landscape is a question for the landscape page of this section.
* The book predates SAP SuccessFactors as a replacement of the HR core. Where SuccessFactors holds the data, its own reporting tools apply, not the tools of this page.

== Summary

* Choose by the question. A standard report if one exists, HIS to start reports from a hierarchy, InfoSet Query (Ad Hoc Query in HR) for a simple, specific list, SAP Query for control levels, statistics and multiline lists, and Business Information Warehouse for analysis over time or with non-SAP data.
* Table utilities and QuickViewer read tables below the HR authorization concept, so they are for technical staff and need protection such as S_TABU_DIS.
* Queries need an InfoSet and a user group. In HR an InfoSet is built on one logical database (PNP, PCH, PAP, or PNPCE with concurrent employment), and payroll results reach queries through payroll infotypes.
* The wage type reporter H99CWTR0 totals wage types of payroll results; for March 2026 the example gives 6,400.00 for wage type `1000`, 2,464.00 for wage type `2000` and 8,864.00 in total.
* For audit, RPUAUD00 evaluates logged infotype changes (logging must be set up first), RPUPROTD lists report starts, and P_ABAP must be handled with care.
