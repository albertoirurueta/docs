= Deployment Options
:description: The three ways to run SAP S/4HANA (Cloud Public Edition, Private Edition and on premise), how often each one is upgraded, the three transition paths from SAP ERP, and the maintenance dates 2027, 2030, 2033 and 2040, for S/4HANA 2025 FPS02 and Cloud Public Edition 2608.

SAP S/4HANA is one product, but a company can run it in three different ways. In the first, SAP runs a shared system for
many customers and upgrades it on a fixed calendar. In the second, SAP or a cloud provider runs a system that belongs to
one customer only, and the customer decides how closely to follow new releases. In the third, the customer installs and
runs the software itself. A newcomer meets this choice in every project discussion, because it decides who installs
upgrades, how much the system may be changed, and what a company with an older SAP ERP system has to do and by when.
This page compares the three ways to run S/4HANA, explains the three paths from an older system, and puts the published
maintenance dates on one timeline. It is written against SAP S/4HANA 2025 FPS02 (October 2026), which applies to
on premise and Private Edition, and against SAP S/4HANA Cloud Public Edition 2608, which applies only to the public
cloud. The Public Edition gets a new release twice a year, so its number moves faster than the other two.

== Key terms

* xref:erp/sap/glossary.adoc#cloud-public-edition[Cloud Public Edition]: the multi-tenant cloud variant of SAP S/4HANA
  that SAP upgrades twice a year.
* xref:erp/sap/glossary.adoc#cloud-private-edition[Private Edition]: the single-tenant variant, hosted by SAP or a
  hyperscaler, that SAP sells in the RISE with SAP offering.
* xref:erp/sap/glossary.adoc#on-premise[On premise]: the variant that the customer installs and operates itself under a
  perpetual license.
* xref:erp/sap/glossary.adoc#feature-pack-stack[Feature pack stack (FPS)]: a package of corrections and small
  functional improvements delivered every six months between two major releases.
* xref:erp/sap/glossary.adoc#system-conversion[System conversion]: the guided technical process that turns an existing
  SAP ERP system into SAP S/4HANA, one to one.
* xref:erp/sap/glossary.adoc#new-implementation[New implementation]: a brand new installation, also called a
  greenfield implementation.
* xref:erp/sap/glossary.adoc#selective-data-transition[Selective data transition]: a tool-based way to pick which
  configuration, master data and transaction data move to the new system.
* xref:erp/sap/glossary.adoc#clean-core[Clean core]: the practice of keeping the standard system unmodified and putting
  extensions beside it through released interfaces.

== The three deployment options

SAP Learning describes three variants of SAP S/4HANA. They share the product name and, as far as the learning page
states, the on premise and Private Edition variants share the same functional scope and code. What differs is who
operates the system, how often it is upgraded and how freely it can be changed.

=== Cloud Public Edition

SAP S/4HANA Cloud Public Edition is the multi-tenant variant. Many customers use the same software, and SAP applies the
upgrades. SAP Learning states that there are two major upgrades per year, in February and August, installed
automatically on dates in a release schedule, so customers do not run a full upgrade themselves. The release number
follows the same rhythm; this page uses 2608, the August 2026 release. The variant offers ready-to-run processes based on
industry best practices. A customer that needs a process of its own keeps it through cloud-compliant extensibility under
a clean core strategy: the standard stays untouched and extensions use released interfaces, the same rule that the ABAP
for Cloud Development language version enforces in code. SAP Learning names the sales bundle for this variant as GROW
with SAP, and names SAP Cloud ERP as the marketing term.

=== Cloud Private Edition

SAP S/4HANA Cloud Private Edition is the single-tenant variant: the system belongs to one customer. SAP Learning states
that it is hosted by SAP or a hyperscaler, that SAP provides technical managed services under a standardized service
level agreement, and that the commercial model is a subscription. The sales bundle is RISE with SAP, and the
marketing term is SAP Cloud ERP Private. A new major release appears every two years, and feature pack stacks (FPS)
arrive every six months between two releases without a full upgrade. A Private Edition customer must stay within
mainstream maintenance, which SAP Learning states is now seven years, so the latest release has to be installed at
least once in that window. The variant provides a library of ready-to-run processes as a baseline, with high
flexibility to tailor processes for an industry.

=== On premise

SAP S/4HANA on premise is the variant the customer manages, either in its own data center or hosted. SAP Learning
states a two-year release cycle starting with the 2023 release, with FPS every six months, the same rhythm as the Private
Edition. The release used on this page, 2025 with FPS02 in October 2026, follows that rule. The differences from the
Private Edition are commercial and operational: a perpetual license instead of a subscription, no managed service from
SAP, and no requirement to install upgrades or to stay within mainstream maintenance. The same functional scope and
code as the Private Edition apply, covering end-to-end line-of-business processes and more than 25 industries.

== Choosing a path from an older system

A company that already runs SAP ERP has three paths to S/4HANA. SAP Learning names them as follows.

* *New implementation* is a brand new installation, "also known as a Greenfield implementation" on the SAP page. Only
  open items and master data move to the new system; closed transactional data does not. It suits organizations that
  want to redesign processes, retire obsolete technology or consolidate several legacy systems, and it gives a fresh
  start with a clean core.
* *System conversion* is a guided technical process for a one-to-one conversion of an existing SAP ERP system. It keeps
  the investment in data, processes and custom code, and existing database tables are converted to the new data model.
  The learning page states that it is a one-to-one transition only and is not applicable for system consolidation, and
  that the system must be on a recent release. The course on conversion names Software Update Manager, including the
  Database Migration Option, as the tool that migrates the database, updates the system and converts the data. In
  market talk this path is often called brownfield; the SAP Learning page uses the words system conversion and "re-use"
  and does not use the word brownfield.
* *Selective data transition* is a tool-based approach to selectively migrate and transform configuration, master data
  and transaction data. It suits customers that consolidate capabilities from several ERP systems, mix reused and
  redesigned processes, or want to keep historical data. SAP Learning names two forms: shell conversion, best when most
  processes are reused, and mix and match, best when most of the solution is redesigned. It also states that SAP does not
  certify third-party products for this path.

In a sample of about 10,000 SAP S/4HANA projects over three years, the learning page reports roughly 48 percent system
conversions, 50 percent new implementations and 2 percent selective data transitions. The decision depends on business
factors (corporate strategy and how much transformation is planned), technical factors (the existing landscape and the
need for historical data) and organizational factors (readiness and project sponsorship).

== The maintenance timeline

Two SAP News articles give the dates that most SAP ERP customers plan around. In February 2020 SAP committed to maintain
SAP S/4HANA until the end of 2040. The same article states that mainstream maintenance of the core applications of SAP
Business Suite 7 runs until the end of 2027, followed by optional extended maintenance until the end of 2030. Extended
maintenance covers three years, from the start of 2028 to the close of 2030, at a premium of two percentage points on the
existing maintenance basis. A customer that does not opt in by the end of 2027 but keeps running Business Suite 7 is
automatically moved to the customer-specific maintenance model.

In February 2025 SAP described a further option, the transition option for SAP ERP, private edition. It is available to
buy from 2028, and active use is planned for 2031 to 2033. SAP states that it is not a maintenance prolongation of SAP
ERP. It is aimed at larger and complex systems, requires the system to have moved to SAP ERP, private edition before the
end of 2030, supports SAP HANA only, and is centred on SAP ECC, so it excludes the full Business Suite 7 scope. The fees
for 2031 to 2033 are stated to be higher than for a comparable ERP cloud subscription before 2031. The article names the
intended next step as a transition to SAP cloud ERP.

The maintenance commitment names SAP S/4HANA as a whole. No official page read for this page gives a separate end date
for SAP HCM for SAP S/4HANA, which is a separately licensed component, so the HR pages of this site say only that.

== What each option means for a developer

The deployment option decides which extension techniques are open. In the Public Edition, custom code is limited to
cloud-compliant extensibility on released interfaces, which matches ABAP for Cloud Development. In the Private Edition
and on premise, classic Standard ABAP is available as well, and the guidance of a clean core still applies to new
extensions. The ABAP language versions page explains the difference in code terms. For upgrades, the Public Edition
needs no project from the customer, while a Private Edition or on premise customer plans a release or FPS update and
tests its own extensions against it.

== Summary

* SAP S/4HANA runs as Cloud Public Edition (multi-tenant, upgraded by SAP in February and August), Cloud Private Edition
  (single-tenant, RISE with SAP, a major release every two years and FPS every six months) or on premise (customer
  operated, perpetual license, no required upgrades).
* This page's baseline is S/4HANA 2025 FPS02 for Private Edition and on premise, and Public Edition 2608.
* A company with SAP ERP moves by new implementation, system conversion or selective data transition; SAP Learning
  gives system conversion and new implementation about half of the projects each.
* Business Suite 7 mainstream maintenance ends in 2027, optional extended maintenance in 2030, the ERP private edition
  transition option is planned for 2031 to 2033, and S/4HANA maintenance is committed until the end of 2040.
