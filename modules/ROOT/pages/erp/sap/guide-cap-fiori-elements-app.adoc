= SAP Guide: Add a Fiori Elements App to a CAP Service
:description: Step-by-step guide to the Fiori elements preview of CAP Node.js 10.2: add UI annotations to the expenses service to get a list report and an object page, edit a claim as a draft, add a value help for the status and create a claim.
:keywords: SAP, CAP, Fiori elements, list report, object page, UI annotations, UI.LineItem, UI.HeaderInfo, UI.Facets, draft, value help, Common.ValueList, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-13 against CAP Node.js 10.2 (`@sap/cds` 10.2.2, `@sap/cds-dk` 10.2.1), the Fiori elements preview of `cds watch` (it loads SAPUI5 1.145.0) and Node.js 24.21.

== What you build

This is a teaching model built with CAP. It is not SAP S/4HANA or SAP SuccessFactors and does not reproduce their screens.

You give the expenses service of the guide xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service] a user interface without writing any UI code. You write annotations, short pieces of metadata next to the service, and the Fiori elements preview of `cds watch` builds two pages from them: a list report that shows all claims in a table, and an object page that shows one claim. You switch a claim to a draft to edit it, add a value help that lets the user pick a status from a list, and create a second claim.

image::sap-general-guide-cap-fiori-elements-app-07-result.svg["Fiori elements list report with two claims: Train ticket with the status A and the amount 50.00, and Taxi with the status N and the amount 18.00",width=900]

== Before you start

* No account is needed: the preview is part of the CAP tools that you installed without signing in. It loads the SAPUI5 libraries from a public content delivery network, so the computer needs internet access. Installing `@sap/cds-dk` means accepting the SAP Developer License Agreement, version 3.2, which the lab README names.
* Do the guide xref:erp/sap/guide-first-cap-service.adoc[Your First CAP Service] first. You need its project `expenses` with `db/schema.cds`, `srv/expense-service.cds` and the CSV file, and `cds watch` must work.
* Read xref:erp/sap/fiori-elements.adoc[SAP Fiori Elements] for the idea of the floorplans and annotations, and xref:erp/sap/fiori-design-guidelines.adoc[SAP Fiori Design Guidelines] for the design rules behind the pages.
* The preview takes its language from the browser. Add `sap-language=EN` to the address, as in step 5, to get the English texts of this guide.
* The figures are drawings of the pages, not screenshots, so small details can differ from your screen. A highlighted box with a number marks the part of the page that the step with the same number deals with.

== Steps

The two numbered overviews show the pages that the preview builds. The list report is the start page: a filter bar above a table. The object page opens when you click a row.

. Open `srv/expense-service.cds` and put `@odata.draft.enabled` above the entity line. It tells CAP to keep a draft copy of a claim while someone edits it, which the object page needs for its Edit button. The file now reads:
+

----

----

Source: https://cap.cloud.sap/docs/guides/uis/fiori[CAP: Serving SAP Fiori UIs]

. In the terminal, in the project folder, start the server (or leave it running: `cds watch` reloads when you save):

The page is a list report: a filter bar with a search field and *Editing Status*, the buttons *Go* and *Adapt Filters*, and the table *Claims (1)* with the columns *Title*, *Status* and *Amount* and your claim.
+

=== Edit a claim as a draft

[start=9]
. Click *Edit*. The page becomes a draft: a marker *Draft* appears next to the title, a *Header* tab and section with the title field are added, the fields become input fields, and a footer bar shows *Save* and *Discard Draft*. Nothing is stored in the real claim yet; CAP keeps the changes in the draft.
. Change the *Amount* to `50.00`. The footer shows *Draft updated* as soon as you leave the field. Click *Save*. A message *Object saved* appears, and the object page shows the new amount; the field *Changed On* has a new time.
+
image::sap-general-guide-cap-fiori-elements-app-04-edit-draft.svg["Fiori elements object page of the claim in edit mode: next to the title the marker Draft is marked by callout 9, an extra Header tab and section appear, the Amount field holds 50.00 and the footer shows Draft updated with the buttons Save, marked by callout 10, and Discard Draft",width=900]

=== Create a claim

[start=15]
. Go back to the list with the arrow in the shell bar and click *Create*. A new draft opens with the status `N`, which is the default of the model. Type `Taxi` as the *Title* and `18.00` as the *Amount*, then click *Create* in the footer. The new claim appears in the list.
+
image::sap-general-guide-cap-fiori-elements-app-06-create-claim.svg["Fiori elements object page for a new claim titled Taxi with the status N and the amount 18.00; the footer shows Draft updated with the buttons Create, marked by callout 15, and Discard Draft",width=900]

== Check the result

* The list report shows *Claims (2)*: *Train ticket* with the status `A` and the amount `50.00`, and *Taxi* with the status `N` and the amount `18.00`.
* `http://localhost:4004/odata/v4/expense/Claims?$select=title,status,amount` returns the same two claims.
* The terminal shows no line that starts with `[ERROR]`.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom
|Cause
|Fix

|The object page shows only values, with no labels above them
|The fields have no label, because the annotation of step 2 is missing.
|Add the annotation of step 2 and reload the page.

|The texts are not in English
|The preview takes its language from the browser.
|Add `sap-language=EN` to the address, as in step 5.
|===

== Clean up

Press `Ctrl+C` in the terminal to stop `cds watch`. The database lived only in memory, so the claim `Taxi` and the changes are gone at the next start; the CSV files bring back the starting data.
