WordPress is an open-source content management system written in PHP that stores its content in MySQL or MariaDB and
is extended through themes, plugins and blocks. This sub-section of
xref:cms/index.adoc[CMS (Content Management System)] documents *self-hosted WordPress*, the software distributed by
WordPress.org; the hosted WordPress.com service is a different product and appears only where the difference matters. It
covers the whole life of a site: installing and using it, administering the servers it runs on, building block and
classic themes, writing plugins and blocks, working with its APIs from PHP, JavaScript and the command line, delivering
it through CI/CD and containers, and using it as a headless back end or as a source of tools for AI agents.

The pages are written for four audiences:

* *site owners and editors*, who write content, manage users and choose plugins and themes from the dashboard
* *administrators*, who install, configure, secure, back up, scale and update WordPress on Apache or nginx
* *theme developers*, who build block themes with `theme.json`, templates and patterns, or maintain classic themes
* *plugin and block developers*, who extend WordPress with hooks, custom post types, REST routes, blocks and the
  Interactivity, Bindings and Abilities APIs

== The running scenario: Lumen Press

Every example builds one site for *Lumen Press*, a fictitious independent publishing house. The local and staging site
is `lumenpress.test` and production is `lumenpress.example`. The editorial team has an administrator, the editor
`maria.editor`, the author `tom.author` and the catalogue manager `lena.catalogue`, who holds the custom
`lp_catalogue_manager` role. Across the sub-section the site gains:

* a news blog, static pages (About, Contact, Submissions) and a *book catalogue*: the custom post type `lp_book` under
  `/books/`, the taxonomies `lp_genre` and `lp_series`, and the meta fields `lp_isbn`, `lp_pages`, `lp_published_on`
  and `lp_stock` ("The Lighthouse Ledger", ISBN 978-1-23456-789-7, is the book most examples use)
* the block theme `lumen` (templates, template parts, patterns, `theme.json` version 3, the "Paper" and "Midnight" style
  variations and section styles), its child theme `lumen-child`, and a classic theme `lumen-classic` used only to teach
  classic themes and the migration to blocks
* the plugin `lumen-catalog` (namespace `Lumen\Catalog`, Composer PSR-4 autoloading), with a settings screen, a
  shortcode, the REST namespace `lumen/v1`, the WP-CLI command `wp lumen import`, a cron job that syncs stock from a
  fictitious distributor every six hours, a personal-data exporter and translations
* the blocks `lumen/book-card` (static), `lumen/latest-books` (dynamic), `lumen/series-shelf` (hybrid),
  `lumen/book-shelf` (parent with block context), `lumen/wishlist` (Interactivity API), `lumen/local-bookshop` (a hooked
  block) and `lumen/call-to-action` (registered from PHP only), plus a Block Bindings source for the book meta
* operations: `wp-env` and Docker Compose locally, staging and production servers, a Redis object cache, nginx,
  backups, and a Multisite variant for the imprints *Lumen Kids* and *Lumen Noir*
* a Next.js reader app over the REST API, and the abilities `lumen/get-book` and `lumen/summarize-book` exposed to AI
  agents through the MCP Adapter

== Version baseline

The examples were tested on *WordPress 7.1.3*, released on 2026-10-06. *WordPress 7.1.4*, a security-only release
published on 2026-10-28, is the current release and the one to run in production; it changes no API, so every example
applies to it unchanged. *WordPress 7.2* is in beta and planned for 2026-12-08; where a page mentions a 7.2 feature
(such as the Secrets API or the "Ipsum" default theme) it is labelled as upcoming. In WordPress numbering, *X.Y* together
is a major release (6.9, 7.0 and 7.1 are consecutive majors) and *Z* is a maintenance or security release; see
xref:cms/wordpress/versions-and-release-cycle.adoc[Versions and Release Cycle].

The rest of the baseline:

[cols="2,3",options="header"]
|===
| Component | Version used in this sub-section
| PHP | 7.4 minimum (since WordPress 7.0); 8.3 or later recommended; the examples run on PHP 8.4
| Database | MariaDB 11.8 in the examples; see xref:cms/wordpress/requirements-and-hosting.adoc[Requirements and Hosting] for the differing official minimums
| `theme.json` | Version 3, schema `https://schemas.wp.org/wp/7.1/theme.json`
| `block.json` | `apiVersion` 3, schema `https://schemas.wp.org/wp/7.1/block.json`
| Gutenberg plugin | 24.2.0, for features not yet merged into core
| `@wordpress/scripts` | 37.0.0 (unit tests run on Vitest since 36)
| `@wordpress/create-block` | 5.0.0
| `@wordpress/env` | 12.0.0
| `@wordpress/interactivity` | 8.0.0
| WP-CLI | 2.12.0
| WordPress Coding Standards | 3.4.1
|===

Versions, release dates and links on these pages were checked on 2026-10-28. Older advice found in books, tutorials and
answers often predates block themes, `theme.json`, bcrypt password hashing (6.8) or the PHP 7.4 minimum;
xref:cms/wordpress/where-older-books-and-tutorials-are-outdated.adoc[Outdated Advice] lists the corrections in one place.
