A *content management system* (CMS) is an application that lets people who do not write code create, organise, review
and publish content, while developers decide how that content is structured, stored and presented. This section explains
the ideas that every CMS shares and then documents individual products in their own sub-sections. The first one is
xref:cms/wordpress/index.adoc[WordPress], written against WordPress 7.1.3 (released 2026-10-06, PHP 7.4 minimum and 8.3
or later recommended; 7.1.4, a security release of 2026-10-28, is the version to run in production), with WordPress 7.2
in beta and planned for 2026-12-08. The second is xref:cms/webflow/index.adoc[Webflow], a SaaS visual website builder
with a built-in CMS, hosting and developer APIs. The third is xref:cms/drupal/index.adoc[Drupal], a content-management
framework for structured content, multilingual sites and headless delivery, and the fourth is
xref:cms/joomla/index.adoc[Joomla], a CMS with its own extension model and Web Services API. The
xref:cms/comparison.adoc[CMS Comparison] sets them against twelve other systems with dated metrics,
charts and recommendations by purpose. For running WordPress as stateless containers on several Kubernetes nodes with a
managed database, start with xref:cms/wordpress/cloud-reference-architecture.adoc[Cloud Reference Architecture]. The version numbers and links on this page
were checked on 2026-10-28.

The xref:cms/overview.adoc[overview] explains what a CMS is made of, the traditional, headless and hybrid architectures, open source and SaaS products, and when a CMS is the right tool and when a web framework is.

  including Composer, testing, static analysis, OPcache and debugging.

  with its web server and database.

  shared-uploads and shared-cache questions every CMS has to answer when it scales out.
