*Joomla* is a free and open-source content-management system written in PHP and published under the GNU General Public
License. It stores articles in categories, adds structure with custom fields, tags and workflows, shows them through
menu items, templates and modules, controls who may do what with groups, access levels and an access control list, and
exposes the same content through a Web Services API with token authentication. Its extension model (components,
modules, plugins, templates, languages, libraries, files and packages) lets a single code base serve a small club site
and a large multilingual portal. This sub-section explains Joomla from the installation on a web server to a package
that adds a trail catalogue, a scheduled import and a console command, and a decoupled front end that reads the
catalogue back.

== Who this sub-section is for

* *Site builders and editors* who write articles, organise categories and tags, add custom fields, manage media, menus
  and modules, set up users and access levels, run a basic editorial workflow and publish in several languages without
  writing code.
* *Administrators* who install Joomla on Apache or nginx, edit `configuration.php`, harden the site with multi-factor
  authentication and passkeys, keep core and extensions up to date, tune caching, back up and restore, run Joomla from the
  command line and troubleshoot a broken site.
* *Template designers* who create a child template of Cassiopeia, override layouts, define positions and module chromes,
  register assets with the Web Asset Manager, support colour modes, right-to-left languages and accessibility, or build a
  template from scratch.
* *Extension developers* who write components with the namespaced MVC structure, modules with a dispatcher and a helper,
  plugins that subscribe to events, scheduled-task and console plugins, installer scripts and update servers, and who
  test, analyse and package them in a CI pipeline.
* *Architects and front-end developers* who use Joomla as a content back end behind Astro or Next.js, and teams that plan
  a move from Joomla 3, 4 or 5 to the current series.

== The running example: Tallpine Hiking Club

Every page uses one fictitious scenario, the *Tallpine Hiking Club*, a mountain club whose site is built step by step.
The figure shows how the parts fit together.

image::cms-joomla-tallpine-map.svg["Map of the Tallpine Hiking Club site: content, the cassiopeia_tallpine child template, the com_tallpine component, the mod_tallpine_nexthikes module, four plugins and an API front end",width=760]

* *Content*: trail reports and news kept as articles in the nested categories _Trails_ (with _Alpine_ and _Valley_) and
  _News_. Articles carry the custom fields `distance-km`, `elevation-gain`, a `difficulty` list, a `gpx-file` media field
  and `season` checkboxes. The tags are `family-friendly` and `dog-friendly`. Contacts describe the board, banners
  advertise partner shops and a Smart Search index makes everything searchable.
* *People*: Super User, Administrator, Editor, Author and Registered member, plus a custom *Trail Warden* group with its
  own access level for member-only trail conditions, and a basic editorial workflow.
* *Languages*: English (default) and German, with associations between translated items.
* *Template*: `cassiopeia_tallpine`, a child template of Cassiopeia with a colour scheme, fonts, new positions, overrides
  for the article and custom-fields layouts and a `joomla.asset.json` file, plus a minimal standalone template that
  explains `templateDetails.xml`.
* *Extensions*, shipped as the package `pkg_tallpine`: the component `com_tallpine` (namespace
  `Tallpine\Component\Tallpine`) with a `trail` entity, administrator and site views, a router, `access.xml`, categories
  and custom-fields integration, Web Services API endpoints, language files and SQL scripts; the module
  `mod_tallpine_nexthikes`; and four plugins, `plg_content_tallpine_conditions`, `plg_webservices_tallpine`,
  `plg_task_tallpine_trailsync` (a scheduled task that syncs trail closures from a fictitious park-authority API) and
  `plg_console_tallpine` (the command `tallpine:import`). An installer script and an update server complete the package.
* *Operations*: Docker Compose with the Joomla 6.2 image, MariaDB and Mailpit locally, then staging and production with
  Automated Core Updates, MFA and passkeys for administrators, backups and a reverse proxy.
* *Headless*: an Astro or Next.js trail map that reads the Web Services API with an API token.

No real names, tokens or credentials appear anywhere; secrets always come from environment variables or are obvious
placeholders.

== Check date and version baseline

Everything in this sub-section was checked against the official documentation on *2026-10-30*. The state of the platform
on that date is:

|===
|Item |State on 2026-10-30 |What the pages assume

|6.2 is the current minor; 6.2.0 was released on 2026-10-13. 6.3 is projected for April 2027 and the bridge release 6.4 for October 2027.
|New sites start on Joomla 6.2. Examples are written for 6.2.x.

|Joomla 5
|5.4 is the bridge release of its series and is in the security-only window (5.4.10 was the last bugfix release; security fixes continue until 2027-10-12).

|Joomla 7
|Not released. It follows the rule of a major every two years in October of odd years and is projected for October 2027, together with 6.4.

Joomla uses semantic versioning. A major release ships every two years in October of odd years and contains four
minors, one every six months; the fourth minor (x.4) is a bridge release without new features and the only starting
point for the next major. After x.4.0 a series gets one year of bugfixes and two of security fixes, and a minor loses
support when the next one ships. Deprecated code is removed in the second major after its deprecation, and downgrades
are not supported. xref:cms/joomla/versions-release-cycle-and-support.adoc[Joomla Versions, Release Cycle and Support]
explains the cadence, the support windows and the projected timeline. Dates marked "projected" are plans, not facts.

Many older books and tutorials describe Joomla 3 or 4. They show the `+J*+` class aliases such as `JFactory` and `JText`
(available in Joomla 6 only through the Behaviour - Backward Compatibility 6 plugin), the `$app` and `$db` properties
of plugins (their auto-detection is removed in 7.0), generic `Event::getArgument()` arrays instead of concrete event
classes (since 5.0), `setError()` instead of exceptions, Codeception as the core test tool (core uses Cypress),
child templates as a brand-new feature and Joomla 4 as the current release.
xref:cms/joomla/where-older-books-and-tutorials-are-outdated.adoc[Where Older Books and Tutorials Are Outdated] lists
each point with its correction.

== Where the official documentation lives

The project reorganised its documentation, and an older link often leads to a retired page.

* The *Joomla! User Guide* at https://guide.joomla.org/[guide.joomla.org] is the current documentation for site builders
  and administrators: every screen, field and option of the administrator interface.
* The *Joomla! Developer Manual* at https://manual.joomla.org/docs/[manual.joomla.org] is the current documentation for
  developers: the architecture, extension development, the Web Services API, coding standards and the migration and update
  notes of each version. Some pages (for example the lifecycle and the Web Services API) are still short, so the pages of
  this sub-section also cite the source tree of the CMS on GitHub, and the API reference at https://api.joomla.org/[api.joomla.org] for classes.
* The project's developer site at https://developer.joomla.org/[developer.joomla.org] holds the roadmap, the strategy
  documents and the Security Centre with the security announcements.
* Release announcements are published at https://www.joomla.org/announcements/release-news/[joomla.org] and the
  https://magazine.joomla.org/[Joomla Community Magazine] reports on features and events.
* The *legacy wiki* at https://docs.joomla.org/[docs.joomla.org] still ranks high in search results, but its pages mark
  themselves as obsolete. These pages cite it only where nothing newer exists, and say so.
