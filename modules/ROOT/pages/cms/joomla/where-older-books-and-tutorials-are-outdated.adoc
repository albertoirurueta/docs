= Where Older Books and Tutorials Are Outdated
:description: A dated list of what older Joomla books, tutorials and wiki pages got wrong or no longer match -- Joomla 4 and 5.0 platform minimums, the J* class aliases and BC6, generic events, plugin db and app properties, Codeception, TFA, reCAPTCHA, TinyMCE settings, keyword SEO advice, brand-new child templates, docs.joomla.org links and manual core updates -- each as "older advice, current state, since, source", grouped by area.

Joomla follows a two-year major cycle with four minor releases, and its backward-compatibility policy removes deprecated code in
the second major after the deprecation. A book that was correct when it was printed therefore describes a platform that has
since moved on, sometimes by two majors. This page was checked on 2026-10-30 against Joomla 6.2, which was released on 13
October 2026, with 5.x in its security-only period and 4.x and 3.x end of life. It lists, area by area, what older material
says, what is true now, since which version, and where the official source is. It covers two books published by Packt in 2023:
_Developing Extensions for Joomla! 5_ by Carlos M. Cámara Mora and _Joomla! 4 Masterclass_ by Luca Marzo, and the advice
that recurs in wiki pages, blog posts and forum answers from the Joomla 3 and 4 era. In the tables they are shortened to
_Developing Extensions_ and _Masterclass_. The books are cited only to show where they differ from current documentation;
none of their text, figures or screenshots is reproduced, and the book structure is described in our own words. Their
explanations of concepts such as the namespaced MVC layout, the Web Services API, access control, custom fields, menus and
overrides remain a good introduction, and _Developing Extensions_ is the best single book on extension development. Where any
older source and the official documentation disagree, the official documentation wins.

_Developing Extensions_ targets Joomla 5.0 and PHP 8.2; _Masterclass_ targets Joomla 4.x (4.1 child templates and Scheduled
Tasks, 4.2 multi-factor authentication) and states no PHP or database versions. Joomla 4.x reached end of life in October
2025. The timeline behind most rows is on xref:cms/joomla/versions-release-cycle-and-support.adoc[Versions, Release Cycle and Support],
and the code-level consequences of the 6.0 removals are on xref:cms/joomla/upgrading-joomla-5-to-6.adoc[Upgrading Joomla 5 to 6]
and xref:cms/joomla/deprecations-and-preparing-for-joomla-7.adoc[Deprecations and Preparing for Joomla 7].

|W3Techs reported about 1.1 percent of all websites in October 2026. Cross-CMS figures are kept on one page so that they have one date.
|n/a

|A major ships every two years in October of odd years with four minors, one every six months. The x.4 release is a bridge with no new features and the only start point for the next major. == Installation

[cols="3,4,1,3",options=header]
|===
|Older advice |Current state |Since |Official source and site page

|Installation is described for 3.x or 4.x: upload the files into the document root, run the installer, delete the `installation` folder.
|The installer still runs from the web or the command line, but Joomla can also be served from a `public` folder that keeps `configuration.php`, `libraries` and the administrator code outside the web root. The installer shows an opt-out for Automated Core Updates.
|5.0 and 5.4
|https://guide.joomla.org/user-guide/hosting[Joomla User Guide: Hosting and Installation]; xref:cms/joomla/installation-and-the-public-folder.adoc[Installation and the Public Folder]

|_Masterclass_ and _Developing Extensions_ cover requirements and installation in little detail and use `docs.joomla.org/J4.x` links.
|The end-user documentation is the Joomla! User Guide at guide.joomla.org and the developer documentation is the Joomla! Developer Manual at manual.joomla.org. docs.joomla.org is a legacy wiki whose pages mark themselves obsolete, and launch.joomla.org links are dead.
|n/a
|https://guide.joomla.org/user-guide/hosting[Joomla User Guide]; https://manual.joomla.org/docs/get-started/technical-requirements/[Joomla Manual]

== Using Joomla: content and site building

[cols="3,4,1,3",options=header]
|===
|Older advice |Current state |Since |Official source and site page

|_Masterclass_ describes the Joomla 4 article editor, with an image button that opens its own modal.
|The image picker opens the Media Manager, the Article, Contact and Menu buttons share one link picker and Read More is also a toolbar button. The editor is TinyMCE 8 in the 6.2 source tree.
|6.2
|https://www.joomla.org/announcements/release-news/joomla-6-2-is-here.html[Joomla 6.2 release announcement]; xref:cms/joomla/articles.adoc[Articles]

|_Masterclass_ describes the Media Manager as in 4.x with both the image path and the file path pointing to the `images` folder.
|On a new installation the file path defaults to `files` and there is a per-root thumbnail switch. Media custom fields gained Audio, Video and Documents types in 6.1, and the `accessiblemedia` field and `types` attribute arrived in 6.1.
|5.3 and 6.1
|https://www.joomla.org/announcements/release-news/joomla-6-1-is-here.html[Joomla 6.1 release announcement]; xref:cms/joomla/media-manager.adoc[Media Manager]

|_Masterclass_ lists the custom-field types of Joomla 4, with no Note or Number type.
|Joomla 6.1 adds Audio, Video and Documents field types on top of the current set, so the field-type list of the book is incomplete.
|6.1
|xref:cms/joomla/custom-fields.adoc[Custom Fields]

|_Masterclass_ describes child templates as new in Joomla 4.1 and Cassiopeia as the new default.
|Child templates are the established way to customise Cassiopeia, and 6.0 ships `cassiopeia_extended` as a core child template.
|4.1 and 6.0
|https://guide.joomla.org/user-guide/templates/templates-child-templates[Joomla User Guide: Child Templates]; xref:cms/joomla/child-templates.adoc[Child Templates]

|_Masterclass_ refers to jQuery as a core library that tutorials may depend on.
|Joomla core does not rely on jQuery for its own behaviour; script dependencies are declared in the Web Asset Manager, and ES5 assets were removed in 5.0.
|5.0
|https://manual.joomla.org/docs/general-concepts/web-asset-manager[Joomla Manual: Web Asset Manager]; xref:cms/joomla/web-asset-manager.adoc[Web Asset Manager]

== Administration

[cols="3,4,1,3",options=header]
|===
|Older advice |Current state |Since |Official source and site page

|Manual core updates: download the update package, upload it, run the update; or check for updates by hand each month. _Masterclass_ stops at the notification panel of Joomla 4.
|Core updates are TUF-verified from 5.1. Automated Core Updates (5.4 and 6.0) cover minor, patch and security releases: a joomla.org server triggers the site through the Joomla Update web-service endpoints, and the site does the work. They are on by default for new installs with an opt-out in the installer, and off for upgraded sites. They need a publicly reachable site, the Default update channel, Stable minimum stability and 5.4 or later. Major-version upgrades remain manual.
|5.1 and 5.4
|https://guide.joomla.org/user-guide/migration/migration-version-update[Joomla User Guide: Version Update]; xref:cms/joomla/updating-joomla-and-automated-core-updates.adoc[Updating Joomla and Automated Core Updates]

|_Masterclass_ presents Akeeba Backup and CMigrator as part of the standard workflow.
|Core ships no backup and no multisite feature. Akeeba and similar tools are useful third-party options, one choice among host tools, `mysqldump` and phpMyAdmin.
|n/a
|https://guide.joomla.org/user-guide/security/security-best-practices[Joomla User Guide: Security best practices]; xref:cms/joomla/backups-and-recovery.adoc[Backups and Recovery]

|_Masterclass_ describes the Atum dashboard and Guided Tours of 4.x and child templates as new; the colour scheme switch and Joomla 6 are not covered.
|Atum is inheritable, so it can have child templates; it supports a colour scheme and dark mode, and a Joomla 6 administrator has a redesigned Help page (6.2).
|4.1 and 6.2
|xref:cms/joomla/administrator-template-atum.adoc[Administrator Template Atum]

|_Masterclass_ describes the TinyMCE plugin's own valid and prohibited element settings as the place to control markup.
|TinyMCE follows the Joomla text filter of the user's groups by default. Begin with the Text Filters tab and use the plugin settings only for editor behaviour.
|6.2
|https://www.joomla.org/announcements/release-news/joomla-6-2-is-here.html[Joomla 6.2 release announcement]; xref:cms/joomla/global-configuration.adoc[Global Configuration]

|Mail settings offer only the password methods.
|SMTP can authenticate with OAuth 2.0 (XOAuth2) for Microsoft 365 and Google Workspace.
|6.2
|https://guide.joomla.org/user-guide/configuration/sending-email-using-oauth-2-0[Joomla User Guide: Sending Email Using OAuth 2.0]; xref:cms/joomla/mail-templates-and-email-settings.adoc[Mail Templates and Email Settings]

== Security

[cols="3,4,1,3",options=header]
|===
|Older advice |Current state |Since |Official source and site page

|Enable two-factor authentication (TFA) with the Google Authenticator or YubiKey plugin.
|Multi-factor authentication has been core since 4.2 and replaced the TFA plugins. Methods include email, TOTP, WebAuthn, YubiKey and backup codes, and passkeys log in without a password.
|4.2
|https://guide.joomla.org/user-guide/users/users-multi-factor-authentication[Joomla User Guide: Multi-factor Authentication]; xref:cms/joomla/security-hardening-mfa-and-passkeys.adoc[Security Hardening, MFA and Passkeys]

|Protect forms with the Google reCAPTCHA plugin.
|The core reCAPTCHA plugin was removed in 5.0. The core captcha in 6.1 is a Proof-of-Work plugin that needs no account or API and solves puzzles silently; third-party captcha extensions are also available.
|5.0 and 6.1
|https://www.joomla.org/announcements/release-news/joomla-6-1-is-here.html[Joomla 6.1 release announcement]; xref:cms/joomla/security-hardening-mfa-and-passkeys.adoc[Security Hardening, MFA and Passkeys]

|Web Services API access with a Basic Auth plugin.
|On fresh 6.2 installs the API token plugin is enabled and the Basic Auth API plugin is disabled.
|6.2
|xref:cms/joomla/web-services-api.adoc[Web Services API]

|Extension updates all look the same in the list.
|Developers can flag a release as a security update with a severity from None to Critical; flagged updates show on the Extensions update page and on the dashboard.
|6.2
|https://www.joomla.org/announcements/release-news/joomla-6-2-is-here.html[Joomla 6.2 release announcement]; xref:cms/joomla/update-servers-and-the-jed.adoc[Update Servers and the JED]

|Wiki security tutorials call `JRequest::getVar()`, `JFactory::getDbo()`, `+$db->quote()+` and `JSession::checkToken()`.
|`JRequest` was removed long ago, the `+J*+` names work only through BC6, and the replacements are `Input` with a filter, `getDatabase()` with `bind()`, and `Session::checkToken()`.
|3.x to 6.0
|https://manual.joomla.org/updates/54-60/removed-backward-incompatibility/[Joomla Manual: Removed and Backward Incompatibility (5.4 to 6.0)]; xref:cms/joomla/security-in-extensions.adoc[Security in Extensions]
|===

|Older advice |Current state |Since |Official source and site page

|Template examples use `JFactory`, `JHtml`, `JText` and `+$doc->addScript()+`, often with jQuery.
|Use namespaced classes and the Web Asset Manager. The aliases are no longer defined on a new Joomla 6 install.
|6.0
|https://manual.joomla.org/docs/general-concepts/web-asset-manager[Joomla Manual: Web Asset Manager]; xref:cms/joomla/templates-and-template-styles.adoc[Templates and Template Styles]

|Both are lost on update or create a copy to maintain. Put overrides in the media folder of a child template.
|4.1
|xref:cms/joomla/child-templates.adoc[Child Templates]

|Third-party frameworks and page builders are the usual way to design a site.
|Their Joomla 6 support arrived at different times and must be checked one by one. A release that supports only Joomla 4 or 3 is obsolete.
|n/a
|xref:cms/joomla/template-frameworks-and-page-builders.adoc[Template Frameworks and Page Builders]

|The books do not describe colour schemes and dark mode.
|Templates read the `data-color-scheme` attribute and the `joomla:color-scheme-change` event.

== Extension development

[cols="3,4,1,3",options=header]
|===
|Older advice |Current state |Since |Official source and site page

|_Developing Extensions_ shows a web services plugin that extends `CMSPlugin`, registers routes in `onBeforeApiRoute(&$router)` and is not namespaced.
|Plugins use `services/provider.php` and an Extension class that extends `CMSPlugin` and implements `SubscriberInterface`; routes are registered with the concrete `BeforeApiRouteEvent`.
|5.0
|https://manual.joomla.org/docs/building-extensions/plugins/how-plugins-work[Joomla Manual: How plugins work]; xref:cms/joomla/extending-the-web-services-api.adoc[Extending the Web Services API]

|Event handlers read `Event::getArgument()` arrays.
|Use the concrete event classes with getters, for example `ContentPrepareEvent`. Captcha, editor and editors-xtd plugins use the setup events.
|5.0
|https://manual.joomla.org/docs/building-extensions/plugins/plugin-events[Joomla Manual: Plugin events]; xref:cms/joomla/plugin-development-and-events.adoc[Plugin Development and Events]

|Plugins read `+$this->db+` and `+$this->app+` as if they were declared properties.
|Use `getApplication()`, `getDatabase()` and the Aware traits. Joomla 7.0 removes the auto-detection of the `$app` and `$db` plugin properties.
|5.x
|xref:cms/joomla/deprecations-and-preparing-for-joomla-7.adoc[Deprecations and Preparing for Joomla 7]

|`Factory::getLanguage()` and `+get('DatabaseDriver')+` retrieve services.
|Take the language from the application and the database from the container or `DatabaseAwareTrait`. Prepared statements use `bind()` and `whereIn()`.
|4.0
|https://manual.joomla.org/docs/general-concepts/database/[Joomla Manual: Database]; xref:cms/joomla/database-api.adoc[Database API]

|The query builder translates one query for every database, so install SQL is portable.
|The builder does not make raw install SQL portable: MySQL and PostgreSQL still need their own files.
|n/a
|xref:cms/joomla/installer-scripts-and-sql-updates.adoc[Installer Scripts and SQL Updates]

|An installer script is a plain class that extends nothing.
|Use `InstallerScriptInterface` with `InstallerScriptTrait`, optionally returned from `services/provider.php`.
|6.0
|xref:cms/joomla/installer-scripts-and-sql-updates.adoc[Installer Scripts and SQL Updates]

|Entry files begin with `defined('JPATH_PLATFORM') or die;` and use `\Joomla\CMS\Input`.
|`JPATH_PLATFORM` is no longer defined; use `+defined('_JEXEC') or die;+`. Use `\Joomla\Input`. `\Joomla\CMS\Filesystem` is moved to BC6 for removal in 7.0. `AdminModel::getItem()` returns `stdClass`, and views lose `+$this->db+`.
|6.0
|https://manual.joomla.org/updates/54-60/removed-backward-incompatibility/[Joomla Manual: Removed and Backward Incompatibility]; xref:cms/joomla/error-handling-and-legacy-apis.adoc[Error Handling and Legacy APIs]

|Errors are reported through `setError()`.
|Use exceptions. `setUseExceptions(true)` has been the default since 5.4, core drops `setError()` calls in 7.0 and the trait goes in 8.0.
|5.4
|xref:cms/joomla/error-handling-and-legacy-apis.adoc[Error Handling and Legacy APIs]

|Console commands are CLI application scripts built on `CliApplication`.
|The CMS `BaseApplication` and `CliApplication` are gone; write a console plugin.
|6.0
|https://manual.joomla.org/updates/54-60/removed-backward-incompatibility/[Joomla Manual: Removed and Backward Incompatibility]; xref:cms/joomla/console-command-plugins.adoc[Console Command Plugins]
|===

== Changed since older tutorials

The books and wiki pages above share a short list of changes that account for most of what no longer works.

[cols="3,4",options=header]
|===
|You may read |Do this now

|`JFactory`, `JText` and other `+J*+` aliases
|Namespaced classes (`Factory`, `Text`). On 6.x the aliases exist only in the Behaviour - Backward Compatibility 6 plugin, which is off by default on new installs and is removed with Joomla 7.

|Generic `Event` objects and `Event::getArgument()`
|Concrete event classes in a `SubscriberInterface` plugin (5.0 and later)

|`+$this->app+` and `+$this->db+` in a plugin
|`getApplication()` and `getDatabase()` with the Aware traits

|Codeception
|Cypress for system tests

|docs.joomla.org
|The Joomla! User Guide (guide.joomla.org) and the Developer Manual (manual.joomla.org)

|Two-factor authentication (TFA)
|Multi-factor authentication (MFA, 4.2) and passkeys

|TinyMCE 6 with its own element lists
|TinyMCE 8, following the Joomla text filter by default (6.2)

|reCAPTCHA
|The Proof-of-Work captcha (6.1)

|Download and upload a core update by hand
|Automated Core Updates (5.4 and later), with TUF verification since 5.1

|Joomla 4
|Joomla 5.4 as a bridge and Joomla 6.x as the target
|===

== Generic warning signs in older tutorials

A tutorial is probably out of date when it:

* targets Joomla 2.5, 3 or 4, or PHP below 8.3;
* links to docs.joomla.org, `docs.joomla.org/J4.x` or launch.joomla.org pages;
* uses `JFactory::getDbo()`, `JRequest`, `JLoader::register()` or `JPATH_PLATFORM`;
* shows a plugin that extends `CMSPlugin` with no `SubscriberInterface`, or reads `getArgument()`;
* mentions Codeception, TFA, the reCAPTCHA plugin or the Joomla 4 pre-update check as the safe way to upgrade;
* recommends a template framework or page builder without a Joomla 6 release.

When in doubt, check the date of the source against the timeline on
xref:cms/joomla/versions-release-cycle-and-support.adoc[Versions, Release Cycle and Support] and confirm the fact in the
official documentation below.
