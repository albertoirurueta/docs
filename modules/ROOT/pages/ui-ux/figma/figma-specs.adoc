== What a Spec is and where it lives

A Spec is a document made of blocks, kept in Figma next to the work it describes. It can exist in three places.

. A standalone Spec file, created from the file browser.
. A Spec inserted on the canvas of a Figma Design file.
. A Spec inserted on a FigJam board.

The point is that written intent, the designs and the code context stay in one place and can move between them. In Design files and FigJam you can drag content between the Spec and the canvas or board.

. A Heading 1 block with the brief's title.

. A Figma file embed block that shows the card frame from the canvas.

== Creating a Spec

* Standalone file: in the file browser click Spec at the top, or open figma.com/spec/new in a browser.
* Inside a Design file or a FigJam board: click Spec in the toolbar, or press D.
* In FigJam only: select objects on the board and click Summarize AI to turn them into a Spec, for example to summarise a design critique.
* With the agent: prompt the Figma agent to create a Spec, such as a brief from frames, a critique agenda from selected frames, or design system documentation.

Once the feature reaches your account you see a Spec option in the file browser and a Spec icon in the Design and FigJam toolbars.

Source: https://help.figma.com/hc/en-us/articles/44049066011671[Figma Learn: Guide to Specs in Figma]

== Blocks and Markdown shorthand

Type / inside a Spec to open the block menu. Some blocks also accept Markdown shorthand typed at the start of a line.

[cols="2,2",options="header"]
|===
| Block | Markdown shorthand

| Heading 1, 2 and 3 | `+#+`, `+##+` and `+###+`
| Bullet list | `+*+` or `-`
| Numbered list | `1.`
| To-do | `[]`
| Quote | `>`
| Code block | three backticks
| Image, Figma file embed, divider | none, use the block menu
|===

To change the type of an existing block, click the block's handle, choose Turn into and pick the new type. In a Design file or FigJam board the top-right corner of the Spec offers View as scrollable page and Open full-screen editor.

.Typing Markdown shorthand turns lines into blocks
image::ui-ux-figma-figma-specs-block-menu.svg["The slash block menu next to a table mapping Markdown shorthand such as hash, dash, number and greater-than to heading, bullet list, numbered list and quote blocks",width=720]

. The block menu, opened by typing / on an empty line, lists every block type.
. Markdown shorthand typed at the start of a line creates the same blocks; images, embeds and dividers have no shorthand.

Source: https://help.figma.com/hc/en-us/articles/44049066011671[Figma Learn: Guide to Specs in Figma]

== Embedding frames, boards and files

The block menu contains a Figma file embed block, which is how a Spec points at design content. The guide does not give step-by-step instructions for choosing which frame or board an embed shows, nor the permission rules for viewers of the embedded file, so expect the exact prompts to differ and check the guide. Figma's Specs product page also says you can pull diagrams, tables and designs from Figma into a Spec. Because a Spec inserted into a Design file already sits beside the frames, dragging a frame into it from the canvas is the shortest path.

Source: https://help.figma.com/hc/en-us/articles/44049066011671[Figma Learn: Guide to Specs in Figma] and https://www.figma.com/specs/[Figma: Specs]

== Collaborating

Share the Spec like other Figma files, leave comments on it, and spotlight yourself during a presentation. Sharing permission levels are not described in the Specs guide, so rely on the general rules in xref:ui-ux/figma/files-folders-teams-and-sharing.adoc[Files, Folders, Teams and Sharing].

== Specs with the agent and MCP

Specs are designed to be read and written by agents as well as by people.

* The Figma agent can create Specs from frames, and can generate technical specification documents from designs. See xref:ui-ux/figma/figma-agent-and-skills.adoc[The Figma Agent and Skills].
* Coding agents connected to the Figma MCP server can use the figma-spec skill to read, create and update standalone and embedded Specs. Figma states that edits are targeted and that comments stay attached to the right text. See xref:ui-ux/figma/figma-mcp-server.adoc[The Figma MCP Server].
* Specs can bring in context from connected tools, such as a GitHub connector, and push context out, such as updating Linear issues or a GitHub repository from a Spec.
* The guide describes a round trip: turn a requirements document into designs and code, or designs and code into a technical spec.

Using the agent with Specs consumes AI credits, and the amount varies with the task and the attached context; hovering over the receipt after each prompt shows its cost. Writing and editing directly in a Spec does not use the agent and costs no credits. The agent has been generally available since 2026-10-06, so an older Figma article that says it uses no credits during its beta is out of date; check the current credit rules on xref:ui-ux/figma/plans-seats-and-ai-credits.adoc[Plans, Seats and AI Credits].

.From a brief to an agent
image::ui-ux-figma-figma-specs-agent-and-mcp.svg["A Spec connected to the Figma agent on the canvas and, through the MCP server, to an external coding agent, each reading and updating the same document",width=720]

. People write, edit and comment in the Spec directly, which costs no AI credits.
. Agents read and update the same Spec: the Figma agent uses AI credits, and a coding agent works through the figma-spec skill of the MCP server, with targeted edits that keep comments attached.

== Procedure: write the Bookshelf card brief

. Open the Bookshelf file in Figma Design and press D, or click Spec in the toolbar, to insert a Spec next to the book card frames.
. Type # and a title, such as "Book card", then press Enter. The line becomes a Heading 1 block.
. Type / and add a short paragraph, a bullet list of requirements (cover, title, Add to shelf button) and a to-do list of open questions, using `+*+` and `[]` as shorthand.
. Type / and choose Figma file embed to reference the card design, or drag the frame from the canvas into the Spec.
. Add a code block with three backticks for the intended component properties.
. Select a block, click its handle and choose Turn into if a bullet should become a to-do.
. Share the file, leave a comment for the developer, and optionally ask the agent to turn the brief into a technical spec.

Source: https://help.figma.com/hc/en-us/articles/44049066011671[Figma Learn: Guide to Specs in Figma]

== Pitfalls

* The feature is in open beta and rolling out gradually; a missing Spec button usually means it has not reached the account yet.
* Edit access to the file is needed to add or change a Spec.
* A Spec is documentation, not a handoff replacement: inspection of measurements and code stays in xref:ui-ux/figma/dev-mode.adoc[Dev Mode].
* Older books and guides predate Specs, as they predate the agent and the MCP server, so they describe annotations and external documents instead.
