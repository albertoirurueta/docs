= Embeds
:description: Embedding Figma files, FigJam boards, Slides and prototypes in other sites and tools: the Share embed code in UI3, Embed Kit 2.0 URLs and parameters, access rules, the Embed API for prototypes and Make prototype embeds.
:keywords: Figma, embeds, Embed Kit 2.0, Embed API, iframe, prototype, FigJam, Slides, Make, client ID, postMessage, Bookshelf

This page was written on 2026-10-30 against the UI3 interface of Figma Design, FigJam, Slides and Make. Getting an embed code from the Share dialog is available on all plans, and the official pages used for this page state no seat requirement for it or for the Embed Kit 2.0 developer features, so check the current documentation for your plan. Embed Kit 2.0 and the Embed API are generally available (Embed Kit 2.0 was released in 2024). Embedding a Make prototype inside Figma is documented for the Starter, Professional, Education (not K-12), Organization, Government and Enterprise plans; Make itself is described on xref:ui-ux/figma/figma-make.adoc[Figma Make].

An embed shows a live Figma file or prototype inside another page, so the Bookshelf team can put the current design of its catalog screen in a wiki, a blog post or the Bookshelf documentation site, and it is always up to date. This page covers the three routes: the copy-and-paste embed code in Figma, the developer route with Embed Kit 2.0 and the Embed API, and the opposite direction, embedding a Make prototype inside a Figma file. For sharing a prototype with a link see xref:ui-ux/figma/presenting-and-testing-prototypes.adoc[Presenting and Testing Prototypes], and for the REST side of the developer platform see xref:ui-ux/figma/rest-api-and-webhooks.adoc[REST API and Webhooks].

Source: https://developers.figma.com/docs/embeds/[Figma Developer Docs: Embeds]

== How an embed works

An embed is an `iframe` whose `src` points at a Figma embed URL. The viewer is view-only: it lets people pan and zoom, change pages, open full screen and follow a link back to the file, but not select layers or edit. Prototype embeds behave like presentation view, and the arrow keys move between screens.

.The request path of an embedded file, from the host page to the access check
image::ui-ux-figma-embeds-architecture.svg["A Bookshelf web page holding an iframe that loads the Figma embed viewer, which asks an access check based on the file's share settings",width=720]

. The host page contains an `iframe` whose `src` is the embed URL.
. Figma checks access before the file is shown; the embed follows the same share settings as opening the file directly.
. The result is rendered in the embed viewer, or the viewer asks the person to log in or to allow embedded content.

Source: https://developers.figma.com/docs/embeds/security-access/[Figma Developer Docs: Security and access]

Embeds work only in browser-based applications; the help article states that they cannot be added inside native or desktop applications. Embeds also need the browser to allow embedded content and the Storage Access API, which is used so that the viewer can still honour the person's Figma login when third-party cookies are blocked. When they are blocked, the viewer must change the browser's site settings (Chrome and Firefox are documented). The documentation describes these problems as rare.

Source: https://developers.figma.com/docs/embeds/troubleshooting/[Figma Developer Docs: Troubleshooting]

== Embed a file or prototype from Figma

This is the route for people who do not write code.

=== A file or FigJam board

. Open the file and, optionally, select the top-level frame you want to show.
. In UI3, click Share in the top-right area of the editor (the help article says the right sidebar).
. Set the audience and the permission level.
. Click "Get embed code", then Copy.
. Paste the code into the other application.

=== A prototype

. Open the file and the page that holds the prototype, click Present and pick a flow in the left sidebar.
. Click "Share prototype" in the toolbar and set the audience and permission level.
. Click the "Get embed code" link, then Copy, and paste the code.

You can embed an entire page, which exposes all of its flows, or a single flow.

Source: https://help.figma.com/hc/en-us/articles/360039827134-Embed-files-and-prototypes[Figma Learn: Embed files and prototypes]

Some tools (the article lists Coda, Notion, Jira, Dropbox, Confluence, P2, StoriesOnBoard, Storybook and Zeroheight) can show a file when you paste only its URL, but only in their browser versions. The conversion of a pasted link into a card is a feature of each host tool; the official embed pages consulted for this page do not document oEmbed, so this page makes no claim about it.

Source: https://help.figma.com/hc/en-us/articles/360045003494-Storybook-and-Figma[Figma Learn: Storybook and Figma]

=== Access rules

[cols="1,3",options="header"]
|===
| Situation | What the viewer sees
| Link sharing on (public file) | Anyone can view the embed
| Link sharing off (private file) | The viewer needs "can view" or "can edit" access
| File shared only within an organization | The viewer must log in
| No access | An Organization file reports that the viewer does not have access; a Professional file reports file not found
| Password protected | Documentation disagrees, see below
|===

The two Figma sources disagree about password-protected files: the help article says they cannot be accessed through an embed, while the developer documentation and the "Interact with embeds" article say the viewer is prompted for the password. Test your own file before promising it to readers.

Source: https://help.figma.com/hc/en-us/articles/360051741274-Interact-with-embeds[Figma Learn: Interact with embeds]

== Embed Kit 2.0

Embed Kit 2.0 is the developer route. It adds security features and more control over the viewer: the host `embed.figma.com`, a choice of page for the viewer, a hidden interface, a view locked to a page, frame or slide, opening in Dev Mode or Figma Design (see xref:ui-ux/figma/dev-mode.adoc[Dev Mode]), a light, dark or system theme, and, for prototypes, events in both directions.

Embed Kit 1.0 used `figma.com/embed`. To tell which version an embed uses, look at the host in its URL. Files embedded with version 1.0 keep working, so you only upgrade for the new features or to use the Embed API with a prototype; Embed API support for 1.0 has ended.

Source: https://developers.figma.com/docs/embeds/embed-kit-2.0/[Figma Developer Docs: Embed Kit 2.0]

.The parts of an Embed Kit 2.0 URL for the Bookshelf catalog file
image::ui-ux-figma-embeds-url-anatomy.svg["Embed URL split into host, file type path, file key, required embed-host parameter and optional parameters",width=720]

. The embed host: `embed.figma.com`.
. The file type path: `design`, `board`, `slides`, `deck` or `proto`.
. The file key copied from the normal Figma URL; the hyphenated file name after it is optional.
. The required `embed-host` parameter, any unique string that identifies your site or product.
. Optional parameters, the first after `?` and the others after `&`.

Source: https://developers.figma.com/docs/embeds/embed-figma-file/[Figma Developer Docs: Embedding a Figma file]

=== Build the URL for a file

. Copy the file's normal URL from the browser.
. Replace `www` with `embed` in the host.
. Add `embed-host` and any optional parameters.
. Put the URL in the `src` of an `iframe`, with `height`, `width` and `allowfullscreen`.

[source,html]
----
<iframe
  style="border: 1px solid rgba(0, 0, 0, 0.1);"
  width="800"
  height="450"
  src="https://embed.figma.com/design/FILE_KEY_PLACEHOLDER?embed-host=bookshelf-docs&node-id=0-3"
  allowfullscreen>
</iframe>
----

Source: https://developers.figma.com/docs/embeds/embed-figma-file/[Figma Developer Docs: Embedding a Figma file]

[cols="1,2,3",options="header"]
|===
| Parameter | Values | Purpose
| `embed-host` | Any unique string (required) | Identifies the site or product embedding the file
| `mode` or `m` | `dev` | Opens the file in Dev Mode
| `node-id` | A node ID such as `0-3` | Shows a specific page or frame
| `footer` | `true` (default) | Shows or hides the Figma footer
| `viewport-controls` | `true` (default) | Lets viewers pan and zoom; in Slides, move between slides
| `page-selector` | `true` (default) | Shows the page selector so viewers can change pages
| `theme` | `light` (default), `dark`, `system` | Theme of the embed interface
|===

Source: https://developers.figma.com/docs/embeds/embed-figma-file/[Figma Developer Docs: Embedding a Figma file]

=== Build the URL for a prototype

A prototype URL uses `https://embed.figma.com/proto/` followed by the file key, `embed-host`, and the parameters below. Use the recommended `450px` height and `100%` width, and add `allowfullscreen` for full-screen support.

[cols="1,2,3",options="header"]
|===
| Parameter | Default or values | Purpose
| `embed-host` | Required | Identifies your site or product
| `client-id` | None | OAuth app client ID, needed only for the Embed API
| `node-id` | Default flow | Node shown when the embed loads
| `starting-point-node-id` | Default flow | Node where the flow starts and restarts
| `version-id` | Latest version | A specific prototype version
| `footer`, `viewport-controls` | `true` | Footer and pan and zoom controls
| `show-proto-sidebar` | `false` | Left sidebar that lists the flows
| `hotspot-hints` | `true` | Highlights clickable areas after a click
| `device-frame` | `true` | Shows or hides the device frame
| `scaling` | `scale-down` | Also `contain`, `min-zoom`, `scale-down-width`, `fit-width`, `free`
| `content-scaling` | `fixed` | Or `responsive`
| `disable-default-keyboard-nav` | `false` | Turns default keyboard navigation off when `true`
|===

When `node-id` and `starting-point-node-id` differ, the embed opens at `node-id` and a restart begins at `starting-point-node-id`.

Source: https://developers.figma.com/docs/embeds/embed-figma-prototype/[Figma Developer Docs: Embedding a Figma prototype]

== Embed API

The Embed API controls an embedded prototype and receives events caused by the viewer. It uses `window.postMessage` and works with Embed Kit 2.0 prototypes only.

=== Set up

. Create an OAuth app on the Figma developer apps page with a name, website and logo, and copy its client ID. Keep the client ID in your configuration; it is public in the iframe URL, but never publish the client secret.
. In the app's modal, open Embed API and add your site's origin as an embed origin.
. Add `client-id=CLIENT_ID_PLACEHOLDER` to the prototype's iframe URL.

Source: https://developers.figma.com/docs/embeds/embed-api/[Figma Developer Docs: Embed API]

.Messages the Bookshelf page sends to the prototype and events it receives
image::ui-ux-figma-embeds-embed-api-messages.svg["Sequence between the Bookshelf host page and the prototype iframe showing INITIAL_LOAD, NAVIGATE_FORWARD, PRESENTED_NODE_CHANGED and RESTART",width=720]

. The prototype reports `INITIAL_LOAD` when it has loaded for the first time.
. The page sends `NAVIGATE_FORWARD` when the person presses Next.
. The prototype reports `PRESENTED_NODE_CHANGED` with the new `presentedNodeId`.
. The page sends `RESTART` to go back to the start.

Source: https://developers.figma.com/docs/embeds/embed-api/[Figma Developer Docs: Embed API]

=== Messages and events

[cols="2,3",options="header"]
|===
| Message sent to the embed | Effect
| `NAVIGATE_TO_FRAME_AND_CLOSE_OVERLAYS` with `data.nodeId` | Closes open overlays, then goes to the node
| `NAVIGATE_FORWARD`, `NAVIGATE_BACKWARD` | Next or previous frame in sequence
| `CHANGE_COMPONENT_STATE` with `data.nodeId` and `data.newVariantId` | Switches an instance to another variant
| `RESTART` | Restarts from the starting node
|===

[cols="2,3",options="header"]
|===
| Event received | Trigger
| `INITIAL_LOAD` | The prototype finished loading the first time
| `PRESENTED_NODE_CHANGED` | Navigation between frames or overlays
| `MOUSE_PRESS_OR_RELEASE` | A click or click-like input
| `NEW_STATE` | A component instance changed variant
| `REQUEST_CLOSE` | The person pressed the spacebar in an inline preview
| `LOGIN_SCREEN_SHOWN`, `PASSWORD_SCREEN_SHOWN` | A private or password-protected embed asks for credentials
|===

Source: https://developers.figma.com/docs/embeds/embed-api/[Figma Developer Docs: Embed API]

=== A minimal controller

The listener checks that events come from `https://www.figma.com`, and every message names the same target origin. Node IDs and the file key below are placeholders.

[source,html]
----
<iframe id="embed-frame"
  src="https://embed.figma.com/proto/FILE_KEY_PLACEHOLDER?embed-host=bookshelf-docs&client-id=CLIENT_ID_PLACEHOLDER"
  width="100%" height="450px" allowfullscreen></iframe>
<button id="next" disabled>Next</button>
<script>
  const figmaOrigin = "https://www.figma.com";
  const iframe = document.querySelector("#embed-frame");
  const next = document.querySelector("#next");

  window.addEventListener("message", (event) => {
    if (event.origin !== figmaOrigin) return;
    if (event.data.type === "INITIAL_LOAD") next.disabled = false;
    if (event.data.type === "PRESENTED_NODE_CHANGED") {
      console.log("Now showing", event.data.data.presentedNodeId);
    }
  });

  next.addEventListener("click", () => {
    iframe.contentWindow.postMessage({ type: "NAVIGATE_FORWARD" }, figmaOrigin);
  });
</script>
----

Source: https://developers.figma.com/docs/embeds/embed-api/[Figma Developer Docs: Embed API]

== Embed a Make prototype in Figma

The reverse direction puts a working Make prototype on a Figma canvas, which is useful in a design review.

. Open the Make file and click Share in the top-right corner.
. Click Copy link, then choose "Copy link as Make file".
. Paste the URL into a Figma Design file, a FigJam board or a Slides deck.
. Click play on the embed to interact, stop to reset it, and "Go to Make file" to open the source. Resize it by dragging its edges.

You need edit access to the file where you paste and view access to the Make file. While a Make embed plays it sits above other layers, other people in the file keep seeing the thumbnail, and playing many embeds at once can slow a large file.

Source: https://help.figma.com/hc/en-us/articles/37617790464535-Embed-a-Make-prototype-in-a-slide-deck-board-or-design-file[Figma Learn: Embed a Make prototype in a slide deck, board, or design file]

== What older guides get wrong

Older books describe the top toolbar and Share menu of the previous interface; UI3 has been the only interface since 2025-04-30, so use the Share button and the Present and "Share prototype" controls described above. Their wording about "editor" and "viewer" access and the "Paid Team plan" predates the seat model of Full, Dev, Collab and View in force since 2025-03-11 (see xref:ui-ux/figma/plans-seats-and-ai-credits.adoc[Plans, Seats and AI Credits]). Mirroring a prototype to a phone with the mobile app changed with the current mobile app, so follow the presentation steps on xref:ui-ux/figma/presenting-and-testing-prototypes.adoc[Presenting and Testing Prototypes]. Sharing and link permissions are described on xref:ui-ux/figma/files-folders-teams-and-sharing.adoc[Files, Folders, Teams and Sharing]; since 2026-08-03 what older guides call projects are folders.

Source: https://help.figma.com/hc/en-us/articles/360039827134-Embed-files-and-prototypes[Figma Learn: Embed files and prototypes]

== Pitfalls

* Using the `www` host or the old `figma.com/embed` path and expecting the Embed API to work: it needs Embed Kit 2.0.
* Forgetting `embed-host` on a version 2.0 URL, which is required.
* Not registering the page origin on the OAuth app, so the prototype ignores messages.
* Sending messages with a target origin other than `https://www.figma.com`.
* Embedding a private file and expecting anonymous readers to see it; they follow the file's sharing settings.
* Pasting an embed into a desktop application, which is not supported.

Source: https://developers.figma.com/docs/embeds/embed-kit-2.0/[Figma Developer Docs: Embed Kit 2.0]
