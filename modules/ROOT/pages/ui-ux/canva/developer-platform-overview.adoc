This page was checked against the official Canva developer documentation at https://www.canva.dev/docs/apps/ on 2026-11-07. It covers the *Canva Developers SDK*, the product Canva documents for everything you build on top of Canva. Building apps and using the MCP server need only a Canva account on any plan, including a free one; the REST APIs additionally need multi-factor authentication on your account, and some individual endpoints and tools depend on the subscription of the people using them (see xref:ui-ux/canva/plans-pricing-and-ai-allowance.adoc[Plans, Pricing and AI Allowance]). Prices are not repeated here; they are published at https://www.canva.com/pricing/. The platform mixes stable and preview APIs, and this page flags the status of each piece where it matters. AI features reached through the platform draw on the account allowance described in Plans, Pricing and AI Allowance.

The running example is *Bookshelf*, the book catalogue and reading-list app designed in the xref:ui-ux/figma/index.adoc[Figma sub-section]. On the developer side its launch campaign needs three things: a "Bookshelf Covers" app that inserts book covers into a design, a REST script that fills the "Book of the week" brand template and exports PNGs, and the Canva MCP server driven from Claude Code. Each one lives on a different surface of the same SDK, and this page is the map to them.

== One SDK, three surfaces

The Developers SDK is one product. Everything you build with it is an *app*, registered in the Developer Portal, and each app targets one or more of three surfaces.

.The three surfaces of the Canva Developers SDK and where Bookshelf uses each
image::ui-ux-canva-developer-platform-overview-three-surfaces.svg["Schematic of the Developers SDK with three columns: apps inside Canva, Canva for your platform and Canva for AI assistants, each with its former name and a Bookshelf example",width=720]

[cols="2,3,3,2", options="header"]
|===
| Surface | What it is | Bookshelf example | Details

| Apps inside Canva
| JavaScript apps that run inside the Canva editor, in an iframe in the side panel or in an overlay, built with the SDK packages and the App UI Kit
| The "Bookshelf Covers" app (Design Editor intent)
| xref:ui-ux/canva/building-apps-inside-canva.adoc[Building Apps Inside Canva]

| Canva for your platform
| The Canva REST APIs, called over HTTPS from your own backend or script to work with designs, assets, brand templates, exports and more
| A script that autofills "Book of the week" and exports PNGs
| xref:ui-ux/canva/rest-apis.adoc[REST APIs]

| Canva for AI assistants
| The Canva MCP server, which lets an assistant that speaks the Model Context Protocol search, create and edit designs for its user
| Claude Code driving the campaign designs
| xref:ui-ux/canva/canva-mcp-server.adoc[Canva MCP Server]
|===

Intents, the declarations that tell Canva what an app can do inside the editor, are covered on xref:ui-ux/canva/app-intents.adoc[App Intents]. Publishing and earning money from an app are on xref:ui-ux/canva/publishing-and-monetizing-apps.adoc[Publishing and Monetizing Apps].

=== Previous product names

Older tutorials and blog posts use names that no longer head the documentation. Canva documents the mapping explicitly, and released versions keep the names they shipped under, so pages such as the Apps SDK v2 upgrade guide still say "Apps SDK".

[cols="2,3,2", options="header"]
|===
| Older name | Now | Changed

| Apps SDK | The Apps inside Canva surface | Around 2026-09
| Connect APIs | The Canva REST APIs, used for Canva for your platform | Around 2026-09
| Canva MCP, as a product name | The Canva for AI assistants surface | Around 2026-09
| Canva Button | Retired; use the REST APIs | Keys deactivated after 2025-12-30 outside China
|===

The old `docs/connect/` address redirects to the REST API pages under `docs/apps/rest-apis/`, so bookmarks keep working, but the new addresses are the ones to cite. The Canva Button, an embeddable "design with Canva" button, was shut down everywhere except China, and its Help Center article points partners to the REST APIs.

Source: https://www.canva.dev/docs/apps/llms.txt[Canva Developers SDK documentation index, Previous product names], https://www.canva.com/help/canva-button/[Canva Help Center: Canva Button]

== The Developer Portal

The Developer Portal at https://www.canva.com/developers/apps is where you register and configure an app. An app has settings for the places it works: *Inside Canva* settings such as intents and authentication providers (an authentication provider option appears once the app has an intent), and *Outside Canva* settings where you switch on the REST APIs or the Canva MCP integration method. Listing details and OAuth configuration live in the portal, not in the app's `canva-app.json` manifest. The CLI can pull and push the configuration, and a push replaces the whole configuration, so check status first.

The app type matters. The distribution of an app (public or private) is chosen at creation and cannot be changed afterwards, and so is the type of a REST app: since 2026-11-06 a REST app can be a service app that authenticates with the OAuth client credentials flow instead of acting for a signed-in user. The authentication details are on xref:ui-ux/canva/rest-apis.adoc[REST APIs].

Source: https://www.canva.dev/docs/apps/rest-apis/changelog/[Canva REST APIs changelog], https://www.canva.dev/docs/apps/canva-cli/[Canva CLI]

== Prerequisites

The Prerequisites page lists what each surface needs. The tools are the same for the two code-heavy surfaces: Node.js v24 with npm v11 (npm is bundled with Node.js 24) and git. The starter kits pin the Node.js version in an `.nvmrc` file, so running `nvm install` in a kit's root directory installs the right one. Verify with `node -v` and `npm -v`.

.Prerequisites by surface
image::ui-ux-canva-developer-platform-overview-prerequisites.svg["Table comparing the prerequisites of the three surfaces: account, Node.js and npm, git, multi-factor authentication and an MCP-capable tool",width=720]

* Apps inside Canva: a Canva account (a free one is enough), a modern browser (Chrome is the one Canva actively supports), a terminal, git, Node.js v24 with npm v11, and working knowledge of React, which the App UI Kit requires. TypeScript is optional, but the docs and starter kits assume it. React components for the editor are covered in the xref:web/react/index.adoc[React section].
* Canva for your platform: a Canva account with multi-factor authentication turned on, git, and Node.js v24 with npm v11. Backends that verify tokens from apps are covered in the xref:backend/express/index.adoc[Express section].
* Canva for AI assistants: a Canva account on any plan and an assistant or tool that supports MCP. See xref:ai/mcp/index.adoc[MCP] for the protocol itself.

Source: https://www.canva.dev/docs/apps/prerequisites/[Canva Developers SDK: Prerequisites]

== Reading the documentation, by people and by agents

The documentation is organised into getting started, building, publishing, managing, reference and examples. The Quickstart gets an app running on any surface in a few minutes, and the Canva concepts pages explain apps, designs, elements, content, assets and folders, the vocabulary every surface shares.

Two conventions make the documentation easy for tools to consume:

* The documentation index is also published as a Markdown file at `https://www.canva.dev/docs/apps/llms.txt`, a table of contents with a one-line summary per page.
* Pages link to Markdown variants whose address ends in `.md`, for example `https://www.canva.dev/docs/apps/prerequisites.md`. Give those to a coding agent instead of the rendered HTML.

The API reference for the SDK packages has a `latest` track and a `preview` track, with a changelog per package. Preview APIs can change without notice.

Source: https://www.canva.dev/docs/apps/llms.txt[Canva Developers SDK documentation index]

== The Dev MCP server

The Canva *Dev MCP server* is a local tool for the person building an app. It runs on your machine through the CLI, fetches Canva documentation from canva.dev and other sources, and gives your AI coding agent context about your app. It does not transmit your code or prompts anywhere except to your AI tool, and it cannot be called directly: the model decides when to use it, so mention terms such as "App UI Kit" or "Canva Developers SDK" in your question. It is a different server from the Canva MCP server, which works on designs and is described on xref:ui-ux/canva/canva-mcp-server.adoc[Canva MCP Server]; the Dev MCP server cannot reach your designs.

It needs git, Node.js v24 or later, npm and an MCP client. For Claude Code, run:

[source,bash]
----
claude mcp add canva-dev -- npx -y @canva/cli@latest mcp
----

Source: https://www.canva.dev/docs/apps/dev-mcp-server/[Canva Developers SDK: Dev MCP server]

For Cursor, add the same command to `.cursor/mcp.json` under `mcpServers`:

[source,json]
----
{
  "mcpServers": {
    "canva-dev": {
      "command": "npx",
      "args": ["-y", "@canva/cli@latest", "mcp"]
    }
  }
}
----

Source: https://www.canva.dev/docs/apps/dev-mcp-server/[Canva Developers SDK: Dev MCP server]

For VS Code, use `.vscode/mcp.json`, where the top-level key is `servers` and the entry needs `"type": "stdio"`:

[source,json]
----
{
  "servers": {
    "canva-dev": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@canva/cli@latest", "mcp"]
    }
  }
}
----

Source: https://www.canva.dev/docs/apps/dev-mcp-server/[Canva Developers SDK: Dev MCP server]

In Cursor and VS Code the MCP tools work only in Agent mode, and both editors need a restart after you save the file.

=== Procedure: give Claude Code the Canva docs

. Check the toolchain: run `node -v` and `npm -v` and confirm Node.js v24 and npm v11.
. In the *Bookshelf* repository, register the server with the `claude mcp add` command above.
. Ask a test question, "How many components are in the App UI Kit?". Your client should ask you to accept a tool invocation; that confirms the connection.
. Ask the agent to outline the "Bookshelf Covers" app. It now answers from current documentation instead of from memory.

== The CLI and packages at a glance

The Canva CLI, `@canva/cli`, creates, previews, builds and uploads apps, switches login profiles, starts the Dev MCP server and, in recent versions, can call the REST APIs with your CLI login. Its commands are taught on xref:ui-ux/canva/building-apps-inside-canva.adoc[Building Apps Inside Canva]. Versions checked on the npm registry on 2026-11-07:

[cols="2,1,3", options="header"]
|===
| Package | Version | Role

| `@canva/cli` | 2.17.0 | CLI and Dev MCP server
| `@canva/design` | 2.14.0 | Design editing and export APIs for apps
| `@canva/app-ui-kit` | 5.15.0 | React components for app interfaces
| `@canva/app-scripts` | 1.1.2 | Build tooling and dev server, generally available since 2026-08-12
|===

Some related packages, such as `@canva/app-middleware`, are published only as pre-release versions; check their status before depending on them.

Source: https://www.npmjs.com/package/@canva/cli[npm: @canva/cli], https://www.canva.dev/docs/apps/canva-app-scripts/[Canva app-scripts]

== Changelogs and deprecation policy

The REST API changelog is at https://www.canva.dev/docs/apps/rest-apis/changelog/. Recent entries include the 2026-11-06 support for service apps, the 2026-11-05 addition of a possible `429` error with the `model_capacity_reached` code when creating an image generation job, and the 2026-10-28 change that returns `402` instead of `429` when a credit quota is exhausted. Each SDK package has its own changelog in the API reference, and the App UI Kit has one too. Migrations between major versions are run with `canva apps migrate`.

Canva's deprecation policy covers the public, stable version of the SDK, not beta or other unstable APIs, which can change without warning. A deprecated feature stays available for at least 6 months, after which Canva may remove it at any time. Canva announces a deprecation, and again when the feature becomes obsolete, by email to the developer, in the developer community at https://community.canva.dev/ and as alerts in the documentation and the Developer Portal. A security fix that needs a breaking change can skip the 6-month period.

Source: https://www.canva.dev/docs/apps/deprecation-policy/[Canva Developers SDK: Deprecation policy]

== Where older guides are outdated

* "Apps SDK" and "Connect APIs" are now surfaces of the Canva Developers SDK, documented together at `docs/apps/`.
* The Canva Button is retired outside China; use the REST APIs.
* The Canva MCP server is a developer surface of its own, not only an end-user connector: see xref:ui-ux/canva/canva-in-ai-assistants.adoc[Canva in AI Assistants] for the user side.
* Neither of the book guides covers the developer platform at all; the sources of this page are the official developer documents listed below.
