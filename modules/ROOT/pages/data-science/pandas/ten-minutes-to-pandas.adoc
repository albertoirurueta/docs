This page is a quick, practical tour of **pandas 3.1** for readers who know some Python and want to get productive
fast. It follows the order of the official "10 minutes to pandas" guide (create, view, select, set, handle missing data,
operate, combine, group, reshape, work with time, categoricals, plot, read and write), but every snippet was rewritten with
deterministic data and run on **Python 3.13 with pandas 3.1.0 and NumPy 2.5.4**; the output shown is real. It was checked in
October 2026. Install pandas first if you have not (xref:data-science/pandas/installation-and-versions.adoc[Installing
pandas and Understanding Its Versions]); each topic below has a dedicated page that goes much deeper, linked at the end of
its section.

Three differences from tutorials written before 2026 appear on almost every screen, so keep them in mind:

* **Strings are a dedicated `str` dtype**, not `object`: a column of text prints `dtype: str`, and so do column labels
  made of strings (`+Index([...], dtype='str')+`).
* **Datetimes default to microsecond resolution** (`datetime64[us]`), no longer nanoseconds.
* **Copy-on-Write is the only mode.** A subset never writes through to its parent, so chained assignment such as
  `df["a"][mask] = 1` does nothing (it emits a `ChainedAssignmentError` warning).

== Object creation

pandas has two workhorse structures: a **Series** (one labelled column of one dtype) and a **DataFrame** (a table of
Series sharing one row index). A Series made from a list takes a default `RangeIndex`, and `np.nan` makes the dtype
`float64`:

[source,python]
----
import numpy as np
import pandas as pd

s = pd.Series([1, 3, 5, np.nan, 6, 8])
print(s)
print(s.dtype)
----

== Selection

There are four selectors worth learning by heart: `[]` for a column or a row slice, `.loc` for **labels** (slice ends
are *inclusive*), `.iloc` for **positions** (slice ends are *exclusive*, like Python), and `.at` and `.iat` for a single
value.

[source,python]
----
print(df["A"].head(2))                          # one column -> Series
print(df[0:3])                                  # row slice by position
print(df["2013-01-02":"2013-01-04"])            # row slice by label, end included
print(df.loc[dates[0]])                         # one row by label -> Series
print(df.loc["2013-01-02":"2013-01-04", ["A", "B"]])
print(df.loc[dates[0], "A"], df.at[dates[0], "A"])
print(df.iloc[3:5, 0:2])                        # positions, end excluded
print(df.iloc[[1, 2, 4], [0, 2]])
print(df.iat[1, 1])
----

== Setting values

Assign a new column from a Series and pandas aligns it on the index (rows without a partner become `NaN`); assign single
values with `.at` and `.iat`, and whole columns with `.loc`:

[source,python]
----
s1 = pd.Series([1, 2, 3, 4, 5, 6], index=pd.date_range("2013-01-02", periods=6))
df["F"] = s1                                   # aligned on the index
df.at[dates[0], "A"] = 0                       # by label
df.iat[0, 1] = 0                               # by position
df.loc[:, "D"] = np.array([5] * len(df))       # a whole column
print(df)

df3 = df.copy()
df3[df3 > 0] = -df3                            # where positive, flip the sign
print(df3)
----

The classic mistake is **chained assignment**: indexing twice and assigning to the intermediate result. With
Copy-on-Write the intermediate object is a copy, so the original is never modified, and pandas 3 warns you:

[source,python]
----
import warnings

d = pd.DataFrame({"a": [1, 2, 3], "b": [4, 5, 6]})
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    d["a"][d["b"] > 4] = 99                    # does nothing
print(d.to_dict("list"), [type(w.message).__name__ for w in caught])

d.loc[d["b"] > 4, "a"] = 99                    # one indexing operation: works
print(d.to_dict("list"))
----

[source,text]
----
{'a': [1, 2, 3], 'b': [4, 5, 6]} ['ChainedAssignmentError']
{'a': [1, 99, 99], 'b': [4, 5, 6]}
----

`SettingWithCopyWarning` no longer exists; `ChainedAssignmentError` is a warning, not an exception. Always select rows
and columns in one `.loc` call when assigning. Assigning a float into an integer column also no longer silently
upcasts (PDEP-6): it raises, so convert the column first with `astype`.

== Missing data

pandas uses `NaN` (and `NaT` for datetimes) to represent missing values. `reindex` creates or changes the row and column
labels and is a convenient way to produce gaps. `dropna` removes rows with missing values, `fillna` replaces them and
`pd.isna` returns a boolean mask:

[source,python]
----
df1 = df.reindex(index=dates[0:4], columns=list(df.columns) + ["E"])
df1.loc[dates[0]:dates[1], "E"] = 1
print(df1)
print(df1.dropna(how="any"))
print(df1.fillna(value=5))
print(pd.isna(df1))
----

== Operations

Statistics skip missing values by default and work along an axis (`axis=0` collapses rows, giving one value per column;
`axis=1` gives one value per row). Arithmetic between objects aligns on labels first and puts `NaN` where a label has no
partner:

[source,python]
----
df = pd.DataFrame(np.random.default_rng(42).standard_normal((6, 4)).round(2),

df["F"] = pd.Series([1, 2, 3, 4, 5, 6], index=dates)

print(df.mean().round(2))                       # per column
print(df.mean(axis=1).round(2))                 # per row

s = pd.Series([1, 3, 5, np.nan, 6, 8], index=dates).shift(2)

== Concat and merge

`pd.concat` glues objects together along an axis. Never grow a DataFrame row by row: `DataFrame.append` was removed in
pandas 2.0 and repeated concatenation is quadratic. Collect pieces in a list and call `concat` once. `pd.merge` joins on
columns, like a SQL join:

[source,python]
----
pieces = [df.iloc[:3], df.iloc[3:5], df.iloc[5:]]
print(pd.concat(pieces).shape)                 # (6, 5): the pieces are stacked back together

left = pd.DataFrame({"key": ["foo", "bar"], "lval": [1, 2]})
right = pd.DataFrame({"key": ["foo", "bar"], "rval": [4, 5]})
print(pd.merge(left, right, on="key"))

# duplicate keys multiply: every left row pairs with every right row of the same key
left = pd.DataFrame({"key": ["foo", "foo"], "lval": [1, 2]})
right = pd.DataFrame({"key": ["foo", "foo"], "rval": [4, 5]})
print(pd.merge(left, right, on="key"))

# anti-join (pandas 3.0): rows of the left frame without a partner on the right
customers = pd.DataFrame({"key": ["a", "b", "c"], "v": [1, 2, 3]})
orders = pd.DataFrame({"key": ["a", "b"]})
print(pd.merge(customers, orders, on="key", how="left_anti"))
----

== Grouping

*Group by* means splitting the data into groups, applying a function to each and combining the results. The grouped
columns become the index of the result; selecting the columns to aggregate explicitly keeps the code stable when the frame
has text columns:

[source,python]
----
g = pd.DataFrame({
    "A": ["foo", "bar", "foo", "bar", "foo", "bar", "foo", "foo"],
    "B": ["one", "one", "two", "three", "two", "two", "one", "three"],
    "C": [1.5, 2.0, 0.5, 1.0, 2.5, 3.0, 1.0, 0.5],
    "D": [10, 20, 30, 40, 50, 60, 70, 80],
})
print(g.groupby("A")[["C", "D"]].sum())
print(g.groupby(["A", "B"])[["C", "D"]].sum())
print(g.groupby("A").agg(total_c=("C", "sum"), mean_d=("D", "mean"), n=("D", "size")))
----

[source,text]
----

A
bar  6.0  120
foo  6.0  240
             C   D

bar one    2.0  20
    three  1.0  40

bar      6.0    40.0  3

== Reshaping

`stack` moves column labels into the row index (long format) and `unstack` does the reverse; `pivot_table` summarises one
column over two keys:

[source,python]

df2 = pd.DataFrame({"A": [1.0, 2.0, 3.0, 4.0], "B": [10.0, 20.0, 30.0, 40.0]}, index=index)

stacked = df2.stack()
print(stacked)
print(stacked.unstack())          # undoes stack (last level by default)
print(stacked.unstack(0))         # unstack another level instead

== Time series

pandas is strong at time-indexed data. `resample` aggregates by a new frequency, `tz_localize` attaches a time zone to
naive timestamps and `tz_convert` changes it, and date offsets such as `BusinessDay` skip weekends:

[source,python]
----
idx = pd.date_range("2012-01-01", periods=10, freq="min")
ts = pd.Series(np.arange(10), index=idx)
print(ts.resample("5min").sum())
print(ts.head(3).tz_localize("UTC").tz_convert("US/Eastern"))
print(pd.Timestamp("2012-03-09") + pd.offsets.BusinessDay(1))     # a Friday
print(pd.date_range("2024-01-31", periods=3, freq="ME"))
----

[source,text]
----

2012-01-01 00:05:00    35
Freq: 5min, dtype: int64
2011-12-31 19:00:00-05:00    0
2011-12-31 19:01:00-05:00    1
2011-12-31 19:02:00-05:00    2
Freq: min, dtype: int64
2012-03-12 00:00:00

Frequency aliases changed in 2.2 and the old ones were removed in 3.0: month-end is `ME` (not `M`), quarter-end `QE`,
year-end `YE`, hours `h` (not `H`), minutes `min` (not `T`), milliseconds `ms` and microseconds `us`. `Period` aliases
still use `M`, `Q` and `Y`. Time zones use the standard library `zoneinfo` and `pytz` is not installed by default.

== Categoricals

A categorical column stores a small set of repeated values compactly and can carry an order, which then drives sorting.
Renaming categories is cheap; `set_categories` can add categories that have no rows yet, which `groupby` then reports
only if you ask with `observed=False` (the default became `observed=True` in 3.0):

[source,python]
----
df = pd.DataFrame({"id": [1, 2, 3, 4, 5, 6], "raw_grade": ["a", "b", "b", "a", "a", "e"]})
df["grade"] = df["raw_grade"].astype("category")
df["grade"] = df["grade"].cat.rename_categories({"a": "very good", "b": "good", "e": "very bad"})
df["grade"] = df["grade"].cat.set_categories(["very bad", "bad", "medium", "good", "very good"])

print(df.sort_values(by="grade"))              # by category order, not alphabetically
print(df.groupby("grade", observed=False).size())
print(df.groupby("grade").size())               # observed=True: empty categories omitted
----

== Plotting

`Series.plot` and `DataFrame.plot` draw with Matplotlib (an optional dependency, installed with `pandas[plot]`) and
return the Matplotlib `Axes`, so you can keep customising with Matplotlib:

[source,python]
----
import matplotlib.pyplot as plt

ts = pd.Series(np.random.default_rng(1).standard_normal(1000),
               index=pd.date_range("2000-01-01", periods=1000)).cumsum()
ax = ts.plot()
ax.set_title("A random walk")
plt.show()          # in a script; notebooks display the figure automatically
----

== Getting data in and out

Each format has a `+read_*+` function and a `+to_*+` method. The three most common are CSV (text, universal), Parquet (typed
and columnar, the best default for analytical data) and Excel:

[source,python]
----
d = pd.DataFrame(np.arange(12).reshape(4, 3), columns=list("ABC"))

d.to_csv("foo.csv", index=False)
print(pd.read_csv("foo.csv").head(2))

d.to_parquet("foo.parquet")            # needs pyarrow (or fastparquet)
print(pd.read_parquet("foo.parquet").dtypes.to_dict())

d.to_excel("foo.xlsx", sheet_name="Sheet1", index=False)   # needs openpyxl
print(pd.read_excel("foo.xlsx", sheet_name="Sheet1", engine="openpyxl").shape)
----

[source,text]
----
   A  B  C
0  0  1  2
1  3  4  5
{'A': dtype('int64'), 'B': dtype('int64'), 'C': dtype('int64')}
(4, 3)
----

Pass `index=False` unless the index carries information, otherwise it is written as an extra, unnamed column that you
will find again on reading. The Excel and Parquet calls need the optional dependencies described in
xref:data-science/pandas/installation-and-versions.adoc[Installing pandas and Understanding Its Versions]; if one is
missing pandas raises an `ImportError` that names the package.

pandas: Getting data in/out]. More in xref:data-science/pandas/io-csv-and-text.adoc[CSV & Text Files],

== Gotchas

Using a Series in a boolean context, such as `if` or `and`, is ambiguous (is a Series "true" when any element is true, or
all, or when it is non-empty?) and raises a `ValueError` that lists the explicit alternatives:

[source,python]
----
try:
    if pd.Series([False, True, False]):
        pass
except ValueError as exc:
    print(exc)

print(pd.Series([True]).item(), pd.Series([False, True]).any(),
      pd.Series([False, True]).all(), pd.Series([], dtype=float).empty)
----

[source,text]
----
The truth value of a Series is ambiguous. Use a.empty, a.item(), a.any() or a.all().
True True False True
----

Source: https://pandas.pydata.org/docs/user_guide/10min.html#gotchas[pandas documentation, 10 minutes to pandas: Gotchas]
and https://pandas.pydata.org/docs/user_guide/gotchas.html[Frequently Asked Questions and Gotchas]. More in
xref:data-science/pandas/faq-and-gotchas.adoc[FAQ & Gotchas].

For combining masks use the element-wise operators `+&+`, `+|+` and `+~+` with parentheses around each comparison, never
`and`, `or` and `not`. Adding rows one at a time is slow; build a list of records and construct the frame once:

[source,python]
----
rows = [{"a": i, "b": i * 2} for i in range(3)]
print(pd.DataFrame(rows))
print(pd.concat([pd.DataFrame({"a": [1]}), pd.DataFrame({"a": [2]})], ignore_index=True))
----
