= Series
:description: pandas 3.1 Series: construction from lists, dicts, scalars and arrays, the Index and the name, label and positional selection, label alignment in arithmetic, missing values, array versus to_numpy, Copy-on-Write semantics and the pitfalls that changed in pandas 3, checked in October 2026.
:keywords: pandas, Series, Index, loc, iloc, alignment, to_numpy, array, Copy-on-Write, dtype, name, attrs, data science

include::partial$data-science-pandas-disclaimer.adoc[]

A `Series` is a one-dimensional labelled array: a sequence of values that all share one dtype, plus an
xref:data-science/pandas/index-objects.adoc[Index] that gives every value a label. Every column of a
xref:data-science/pandas/dataframe.adoc[DataFrame] is a `Series`, and almost every pandas feature (selection, alignment,
missing data, grouping, time series) is first defined on it.

This page targets **pandas 3.1** (3.1.0 was released on 22 October 2026) on **Python 3.13 or 3.14**. pandas 3.1 itself
supports Python 3.11 and requires NumPy 2.0.2 or later. Every example was run on pandas 3.1.0, NumPy 2.5.4 and Python
3.13, and the output shown is real. Examples assume `import numpy as np` and `import pandas as pd`. Related pages:
xref:data-science/pandas/essential-basics.adoc[Essential Basic Functionality],
xref:data-science/pandas/dtypes-overview.adoc[Data Types Overview],
xref:data-science/pandas/indexing-and-selecting.adoc[Indexing & Selecting] and
xref:data-science/pandas/missing-data.adoc[Missing Data].

== Anatomy of a Series

A `Series` has three parts that matter in practice: the values (stored in one array with one dtype), the index (labels
for the values) and an optional name (used as the column name when the `Series` becomes a column).

[source,python]
----
import numpy as np
import pandas as pd

s = pd.Series([4.5, 7.2, -1.0], index=["a", "b", "c"], name="temp")
print(s)
print(s.dtype, s.index, s.name, s.shape, s.size, s.ndim, sep="\n")
----

[source,text]
----
a    4.5
b    7.2
c   -1.0
Name: temp, dtype: float64
float64
Index(['a', 'b', 'c'], dtype='str')
temp
(3,)
3
1
----

Source: https://pandas.pydata.org/docs/user_guide/dsintro.html#series

Note the index dtype: since pandas 3.0 an index of strings has the dedicated `str` dtype, not `object`
(see xref:data-science/pandas/text-data-and-str-dtype.adoc[Text Data & the str Dtype]).

== Creating a Series

The constructor is `pd.Series(data=None, index=None, dtype=None, name=None, copy=None)`. The accepted `data` kinds
behave differently with respect to the index.

[source,python]
----
# From a dict: keys become the index, in insertion order
print(pd.Series({"x": 1, "y": 2, "z": 3}))

# A dict plus an explicit index: the index selects and orders the keys, missing keys become NaN
print(pd.Series({"x": 1, "y": 2, "z": 3}, index=["z", "x", "w"]))

# A scalar is repeated for every label of the index
print(pd.Series(5, index=list("abc")))

# A list or NumPy array gets a default RangeIndex
print(pd.Series(np.arange(3)))
----

[source,text]
----
x    1
y    2
z    3
dtype: int64
z    3.0
x    1.0
w    NaN
dtype: float64
a    5
b    5
c    5
dtype: int64
0    0
1    1
2    2
dtype: int64
----

Source: https://pandas.pydata.org/docs/reference/api/pandas.Series.html

Rules worth remembering:

* With a dict and an `index`, the dict is **reindexed**: keys not in the index are dropped and labels not in the dict
  become `NaN`, which promotes an integer `Series` to `float64`.
* With a list or array, the length of `index` must equal the length of the data. Otherwise pandas raises
  `ValueError: Length of values (3) does not match length of index (2)`.
* With a scalar and no index, the result has one element. To get a longer `Series`, pass an index.
* `dtype=` converts on construction: `pd.Series([1, 2, 3], dtype="float32")`, `dtype="Int64"` (nullable integer) or
  `dtype="Int64[pyarrow]"` when PyArrow is installed.
* `name=` sets the name; `pd.Series(other_series, name="new")` keeps the data and replaces the name.

=== Does the constructor copy the data

With Copy-on-Write (the only mode since 3.0) pandas never lets two objects change each other silently, so
`pd.Series(ndarray)` **copies the array by default**. Pass `copy=False` to share memory with the array.

[source,python]
----
arr = np.array([1, 2, 3])
s = pd.Series(arr)
arr[0] = 99
print(s.tolist())          # [1, 2, 3]   (the Series owns its own copy)

s2 = pd.Series(arr, copy=False)
arr[1] = 77
print(s2.tolist())         # [99, 77, 3] (shared memory: the array changed under the Series)
----

Source: https://pandas.pydata.org/docs/user_guide/migration.html

Sharing memory is an optimisation for large arrays. Prefer the default unless you have measured a problem.

== The Index and the name

The index is mutable as an attribute (you can assign a new one) but each `Index` object is immutable.

[source,python]
----
s = pd.Series([1, 2, 3], index=list("abc"))
s.index = ["x", "y", "z"]            # replaces all labels at once
print(s.index.tolist())              # ['x', 'y', 'z']

print(s.rename(lambda label: label.upper()).index.tolist())   # ['X', 'Y', 'Z']
print(s.rename("score").name)                                  # score  (a scalar renames the Series)
print(s.reset_index())                                         # labels become a column, DataFrame result
print(s.reset_index(drop=True))                                # labels are discarded
----

`Series.rename` is overloaded: a scalar or hashable changes the **name**, while a function, dict or Series changes the
**index labels**. `Series.rename_axis("row")` names the index itself, which is what `reset_index` uses as the column
name. See xref:data-science/pandas/index-objects.adoc[Index Objects] for the full API.

Source: https://pandas.pydata.org/docs/reference/api/pandas.Series.rename.html

== Selecting values

Three accessors cover every case. Use them explicitly: they behave the same on every index type, which plain `[]` does
not.

[cols="2,3,3",options="header"]
|===
|Accessor|Selects by|Slice end
|`+s.loc[...]+`|label, list of labels, boolean mask, callable|**inclusive** (`s.loc["a":"b"]` includes `"b"`)
|`+s.iloc[...]+`|integer position, list of positions, boolean array|**exclusive**, like Python lists
|`s.at[label]`, `s.iat[pos]`|one scalar by label or by position|not applicable; the fastest scalar access
|===

[source,python]
----
s = pd.Series([4.5, 7.2, -1.0], index=["a", "b", "c"], name="temp")
print(s["b"])                      # 7.2
print(s[["a", "c"]].tolist())      # [4.5, -1.0]
print(s.loc["a":"b"].tolist())     # [4.5, 7.2]   label slice, inclusive
print(s.iloc[0:2].tolist())        # [4.5, 7.2]   position slice, exclusive
print(s.iloc[-1])                  # -1.0         negative positions count from the end
print(s.get("zz", -1))             # -1           get() returns a default instead of raising KeyError
----

Source: https://pandas.pydata.org/docs/user_guide/indexing.html

=== The integer-label trap

When the index holds integers, `s[0]` means the **label** 0, not the first position. Mixing the two readings is the
oldest pandas pitfall; `loc` and `iloc` make the intent visible.

[source,python]
----
t = pd.Series([10, 20, 30], index=[2, 1, 0])
print(t[0], t.iloc[0], t.loc[0])   # 30 10 30
----

[source,text]
----
30 10 30
----

Source: https://pandas.pydata.org/docs/reference/api/pandas.Series.html[pandas.Series]

For an index of strings, older pandas fell back to position for `s[-1]` or `s[0]`. That fallback was deprecated and
**no longer exists in pandas 3**: `pd.Series([1, 2, 3], index=["a", "b", "c"])[-1]` now raises `KeyError: -1`. Use
`.iloc[-1]`. Plain slices such as `s[0:2]` still slice by position, and a boolean mask or list of labels in `[]` still
works, but the recommendation is to write `.loc` and `.iloc`.

Missing labels: `s.loc[["a", "zz"]]` raises `+KeyError: "['zz'] not in index"+` (reindexing, which gives `NaN` for
missing labels, is `s.reindex(["a", "zz"])`).

=== Duplicate labels

An index may contain duplicates. A label that appears once returns a scalar; a repeated label returns a `Series`.

[source,python]
----
d = pd.Series([1, 2, 3], index=list("aab"))
print(d["a"])               # a Series with the two rows labelled "a"
print(d["b"])               # 3
print(d.index.is_unique)    # False
----

Source: https://pandas.pydata.org/docs/reference/api/pandas.Series.html[pandas.Series]

Operations that need unique labels (for example `reindex`) raise `InvalidIndexError`. To forbid duplicates up front, use
`s.set_flags(allows_duplicate_labels=False)`: later operations that would create duplicates raise `DuplicateLabelError`.
See xref:data-science/pandas/duplicates.adoc[Duplicate Labels & Rows].

== Arithmetic aligns on labels

Operations between two Series do not match by position: pandas first **aligns** the two indexes, then operates label by
label. Labels present on only one side produce `NaN`.

.Adding two Series whose indexes only partly overlap
image::data-science-pandas-series-alignment.svg["Two Series with indexes a, b, c and b, c, d are added: the result has labels a to d and NaN where one side is missing",width=720]

[source,python]
----
a = pd.Series([1, 2, 3], index=list("abc"))
b = pd.Series([10, 20, 30], index=list("bcd"))
print(a + b)
print(a.add(b, fill_value=0))
----

[source,text]
----
a     NaN
b    12.0
c    23.0
d     NaN
dtype: float64
a     1.0
b    12.0
c    23.0
d    30.0
dtype: float64
----

Source: https://pandas.pydata.org/docs/user_guide/basics.html#flexible-binary-operations

The method forms (`add`, `sub`, `mul`, `div`, `floordiv`, `mod`, `pow` and the reflected `radd`, `rsub`, ...) accept
`fill_value` to substitute a value for labels missing on **one** side. A label missing on both sides still gives `NaN`.

Comparisons are stricter than arithmetic. `pd.Series([1, 2, 3]) == pd.Series([1, 2])` raises
`ValueError: Can only compare identically-labeled Series objects`, because a boolean result with ambiguous labels would
be misleading. Reindex first, or compare `.to_numpy()` arrays of equal length. `Series.equals` compares values, dtype
and labels, and treats NaN in the same place as equal, whereas `==` yields `False` for NaN:

[source,python]
----
print((pd.Series([np.nan]) == pd.Series([np.nan])).tolist())   # [False]
print(pd.Series([1, np.nan]).equals(pd.Series([1, np.nan])))   # True
----

Source: https://pandas.pydata.org/docs/user_guide/dsintro.html#vector-operations-and-label-alignment-with-series

A Series in a boolean context is ambiguous: `if s:` raises
`ValueError: The truth value of a Series is ambiguous. Use a.empty, a.item(), a.any() or a.all().` Use `s.any()`,
`s.all()`, `s.empty` or, for a single element, `s.item()`.

Operations with scalars and NumPy functions keep the index and the name:

[source,python]
----
s = pd.Series([4.5, 7.2, -1.0], index=list("abc"), name="temp")
print(s * 2)
print(np.exp(s).round(2))
print(s.abs())
print(s.sum(), round(s.mean(), 3), s.idxmax(), s.argmax(), s.nlargest(2).index.tolist())
----

[source,text]
----

b    14.4
c    -2.0
Name: temp, dtype: float64
a      90.02
b    1339.43
c       0.37
Name: temp, dtype: float64
a    4.5
b    7.2
c    1.0
Name: temp, dtype: float64
10.7 3.567 b 1 ['b', 'a']
----

Source: https://pandas.pydata.org/docs/user_guide/dsintro.html#vector-operations-and-label-alignment-with-series

`idxmax` returns the **label** of the maximum, `argmax` the **position**.

== Boolean masks, where and mask

A comparison produces a boolean `Series` that selects rows when passed to `[]` or `.loc`. `where` and `mask` keep the
shape and replace the non-selected values instead of dropping them.

[source,python]
----
print(s[s > 0])               # drops c
print(s.where(s > 0))         # keeps the shape: c becomes NaN
print(s.mask(s > 0, 0))       # replaces the values where the condition is True
----

[source,text]
----
a    4.5
b    7.2
Name: temp, dtype: float64
a    4.5
b    7.2
c    NaN
Name: temp, dtype: float64
a    0.0
b    0.0
c   -1.0
Name: temp, dtype: float64
----

Source: https://pandas.pydata.org/docs/reference/api/pandas.Series.where.html

Combine masks with `&`, `|` and `+~+` (never `and`, `or`, `not`) and parenthesise each comparison:
`+s[(s > 0) & (s < 5)]+`. `s.between(2, 3)` is an inclusive range test and `s.isin([1, 3])` a membership test. `s.clip(lower, upper)` limits values without removing them.

== array, to_numpy and values

Three ways to reach the stored values, with different guarantees.

[cols="2,3,3",options="header"]
|===
|Access|Returns|Use it for
|`s.array`|an `ExtensionArray`; for NumPy dtypes a `NumpyExtensionArray`, for `str` an `ArrowStringArray` when PyArrow is installed|the data exactly as pandas stores it, with no conversion
|`s.to_numpy()`|a `numpy.ndarray`; may be a **read-only view** of the data|handing data to NumPy, SciPy or scikit-learn
|`s.values`|`ndarray` or an extension array depending on the dtype|legacy code; prefer `array` or `to_numpy()`
|===

[source,python]
----
s = pd.Series([4.5, 7.2, -1.0], index=list("abc"))
print(type(s.array), type(s.to_numpy()), s.to_numpy().flags.writeable)

x = s.to_numpy()
try:
    x[0] = 99
except ValueError as e:
    print(type(e).__name__, e)             # ValueError assignment destination is read-only

print(s.to_numpy(copy=True).flags.writeable)   # True: an independent writable copy

# Nullable dtypes need an explicit NumPy dtype and a replacement for NA
n = pd.Series([1, 2, None], dtype="Int64")
print(n.to_numpy(dtype="float64", na_value=np.nan))
----

[source,text]
----
<class 'pandas.arrays.NumpyExtensionArray'> <class 'numpy.ndarray'> False
ValueError assignment destination is read-only
True
[ 1.  2. nan]
----

Source: https://pandas.pydata.org/docs/user_guide/basics.html#attributes-and-underlying-data

The read-only flag is Copy-on-Write at work: the array shares memory with the `Series`, so pandas forbids writes through
it. If you need to modify the NumPy array, ask for `copy=True`. For a 1-D string `Series`, `to_numpy()` returns an
`object` array.

== Copy-on-Write semantics

Since pandas 3.0 every object derived from another behaves as an independent copy, even though pandas shares memory
lazily and copies only when one of them is modified. Setting values on a derived Series never changes its parent:

[source,python]
----
orig = pd.Series([1, 2, 3])
sub = orig[:2]
sub.iloc[0] = 100
print(orig.tolist(), sub.tolist())    # [1, 2, 3] [100, 2]
----

Consequences:

* **Chained assignment never works.** `df["v"][mask] = 0` assigns into a temporary and emits `ChainedAssignmentError`
  (a warning, not an exception, unless you turn warnings into errors). Write `df.loc[mask, "v"] = 0`. The same rule
  applies to a Series that comes from a DataFrame column.
* `SettingWithCopyWarning` no longer exists.
* Setting a value of an incompatible type does not silently upcast (PDEP-6). Assigning `1.5` into an `int64` Series
  raises `+TypeError: Invalid value '1.5' for dtype 'int64'+`; convert first with `astype("float64")`.
* `s.copy()` is rarely needed: methods return new objects. It is only useful to detach a Series you intend to mutate in
  place and want to keep isolated.

See xref:data-science/pandas/copy-on-write.adoc[Copy-on-Write] for the complete rules.

Source: https://pandas.pydata.org/docs/user_guide/migration.html

== Missing values in a Series

`None` and `np.nan` are both missing values in a float or `str` Series; `pd.NA` is the missing value of the nullable
dtypes; `NaT` is the missing value of datetimes and timedeltas.

[source,python]
----
m = pd.Series([1, 2, np.nan])
print(m.sum(), m.sum(skipna=False))                     # 3.0 nan
print(pd.Series([], dtype=float).sum())                  # 0.0  the sum of an empty Series is 0
print(pd.Series([None, None], dtype=float).sum(min_count=1))   # nan  require at least one value
print(pd.Series([1, None], dtype="Int64").add(1).tolist())     # [2, <NA>]
----

Reductions skip missing values by default (`skipna=True`). `isna()`, `notna()`, `dropna()`, `fillna()`, `ffill()`,
`bfill()` and `interpolate()` handle them; see xref:data-science/pandas/missing-data.adoc[Missing Data] for the full
treatment, including three-valued logic.

Source: https://pandas.pydata.org/docs/user_guide/missing_data.html

== Accessors

Specialised methods live under namespaces that exist only for compatible dtypes.

[source,python]
----
d = pd.Series(pd.to_datetime(["2026-10-01", "2026-10-31"]))
print(d.dtype, d.dt.day.tolist(), d.dt.day_name().tolist())   # datetime64[us] [1, 31] ['Thursday', 'Saturday']
print(pd.Series(["Ab", "cD"]).str.upper().tolist())            # ['AB', 'CD']
----

* `.str` for string data (see xref:data-science/pandas/text-data-and-str-dtype.adoc[Text Data & the str Dtype]);
* `.dt` for datetimes, periods and timedeltas (see xref:data-science/pandas/time-series.adoc[Time Series & Dates]);
* `.cat` for categoricals (see xref:data-science/pandas/categorical-data.adoc[Categorical Data]);
* `.sparse` and `.list`/`.struct` for sparse and PyArrow-backed nested data.

Source: https://pandas.pydata.org/docs/reference/series.html#accessors

== Metadata: attrs and flags

`s.attrs` is a dict of user metadata that propagates to results of most operations (for example `s.abs().attrs`). It is
experimental in the official documentation, so do not build critical logic on it. `s.flags` holds behaviour flags such as
`allows_duplicate_labels`:

[source,python]
----
s = pd.Series([1, 2, 3], index=list("abc"))
s.attrs["unit"] = "m"
print(s.attrs, s.abs().attrs)             # {'unit': 'm'} {'unit': 'm'}

f = s.set_flags(allows_duplicate_labels=False)
try:
    f.rename({"a": "b"})
except Exception as e:
    print(type(e).__name__)               # DuplicateLabelError
----

Source: https://pandas.pydata.org/docs/user_guide/duplicates.html#disallowing-duplicate-labels

== Pitfalls

* **Alignment surprises.** `pass:c[a + b]` with different indexes silently produces `NaN`. If you wanted positional addition use
  `pass:c[a.to_numpy() + b.to_numpy()]` (same length) or `pass:c[a.reset_index(drop=True) + b.reset_index(drop=True)]`.
* **Integer labels.** `s[0]` is a label lookup on an integer index. Use `.iloc[0]` for the first element.
* **Float equality.** `pd.Series([0.1, 0.2, 0.3]).sum() == 0.6` is `False`; compare with `np.isclose`.
* **Dtype of the result.** A single `NaN` turns an `int64` Series into `float64`. Use a nullable dtype when you need
  integers with missing values (see xref:data-science/pandas/nullable-dtypes.adoc[Nullable Integer & Boolean]).
* **`in` tests the index.** `"b" in s` is `True` and `7.2 in s` is `False`; to test values write `7.2 in s.values` or
  `s.isin([7.2]).any()`.
* **Sort order of strings.** `pd.Series(["b", "A", "c"]).sort_values()` puts uppercase first (`+['A', 'b', 'c']+`);
  pass `key=lambda x: x.str.lower()` for a case-insensitive sort.
* **Mutating through `to_numpy()`.** The array may be read-only; request a copy first.
