= HDF5 and Pickle
:description: HDFStore, read_hdf and to_hdf with the fixed and table formats, queries, compression and limits, plus pickle serialisation with compression and the security risks of loading untrusted files, in pandas 3.1, checked in October 2026.
:keywords: pandas, HDF5, HDFStore, PyTables, read_hdf, to_hdf, data_columns, complib, complevel, pickle, to_pickle, read_pickle, serialisation, security, untrusted data, compression

include::partial$data-science-pandas-disclaimer.adoc[]

This page covers two older ways of saving a DataFrame that you will still meet in notebooks and scripts: HDF5 files
written through PyTables (`to_hdf`, `read_hdf` and `HDFStore`), and Python's own pickle format (`to_pickle` and
`read_pickle`). Both are convenient, and both come with real limits. HDF5 is awkward with new dtypes and is not
thread-safe for writing. Pickle can run arbitrary code when it is loaded. For most new work
xref:data-science/pandas/io-parquet-feather-orc-iceberg.adoc[Parquet] is the better default; this page explains when
HDF5 or pickle is still reasonable and how to avoid their traps.

The page targets Python 3.12 or newer and pandas 3.1 and was checked in October 2026. Every example was run on pandas
3.1.0 with PyTables 3.11.1 and NumPy 2.5.4 on Python 3.13.

== HDF5 with PyTables

HDF5 is a hierarchical container: a file holds *groups* (like directories) and *datasets* (arrays), each with metadata.
pandas stores its objects inside it using the PyTables library and its own layout. That is why `read_hdf` and
`HDFStore` read files written by pandas but not arbitrary HDF5 files. To read a general HDF5 file from another tool use `h5py`
or PyTables directly.

[source,bash]
----
python -m pip install "pandas>=3.1" tables
----

Source: https://pandas.pydata.org/docs/user_guide/io.html#hdf5-pytables[pandas user guide: HDF5 (PyTables)]

=== Two storage formats

`to_hdf` and `HDFStore.put` can store an object in one of two formats:

[cols="1,2,2"]
|===
| | `fixed` (the default) | `table`

| How to ask
| `format="fixed"` or `"f"`
| `format="table"` or `"t"`

| Write and read speed
| Fastest to write, slightly faster to read
| Slower to write than fixed

| Append rows later
| No
| Yes, with `append` or `HDFStore.append`

| Query part of it with `where`
| No: raises `TypeError`
| Yes, on the index and on `data_columns`

| Delete rows
| No
| Yes

| Non-unique column names
| Not supported
| Not covered by the official guide; use unique names
|===

The sample table for this page:

[source,python]
----
import numpy as np
import pandas as pd

df = pd.DataFrame({
    "order_id": np.arange(1, 7),
    "country": ["ES", "FR", "ES", "DE", "FR", "ES"],
    "amount": [10.5, 20.0, 5.0, 7.25, 3.0, 99.9],
    "ordered": pd.to_datetime([
        "2026-01-01", "2026-01-02", "2026-02-01",
        "2026-02-15", "2026-03-01", "2026-03-02",
    ]),
})
----

=== The fixed format

[source,python]
----
df.to_hdf("fixed.h5", key="orders")           # format="fixed" by default
print(pd.read_hdf("fixed.h5", "orders").dtypes)

try:
    pd.read_hdf("fixed.h5", "orders", where="amount > 5")
except TypeError as exc:
    print(exc)
----

[source,text]
----
order_id             int64
country                str
amount             float64
ordered     datetime64[us]
dtype: object
cannot pass a where specification when reading from a Fixed format store. this store must be selected in its entirety
----

A fixed store must be read in full. Use it for a quick snapshot of a whole table that you will read whole.

=== The table format and queries

`format="table"` stores the data so that parts of it can be selected on disk, without loading the file. Only the index and the
columns you list in `data_columns` can appear in a `where` expression; other columns are stored but cannot be filtered on.

[source,python]
----
df.to_hdf("table.h5", key="orders", format="table", data_columns=["country", "amount"])

print(pd.read_hdf("table.h5", "orders", where="country == 'ES' & amount > 6"))
print(pd.read_hdf("table.h5", "orders", where="index < 3", columns=["amount"]))
----

[source,text]
----
   order_id country  amount    ordered
0         1      ES    10.5 2026-01-01
5         6      ES    99.9 2026-03-02
   amount
0    10.5
1    20.0
2     5.0
----

The `where` string uses `&` and `|` for "and" and "or", the comparison operators, and the word `index` for the index.
A reference to an unknown name (typically a column that is not in `data_columns`) raises `ValueError`, and an invalid
expression raises `SyntaxError`. `start` and `stop` apply before `where`, not after it, so
`+select(..., where="A > 0", stop=1)+` can return nothing even though matching rows exist; this is different from SQL `LIMIT`.

=== HDFStore: appending, several tables and a context manager

[source,python]
----
with pd.HDFStore("table.h5", mode="a") as store:
    more = df.assign(order_id=df["order_id"] + 10)
    store.append("orders", more, data_columns=["country", "amount"])
    print(store.keys(), store.get_storer("orders").nrows)
    print(store.select("orders", where="country == 'DE'"))
    print(store.select_column("orders", "country").unique())

    store.put("raw/clean", df, format="table")     # keys can be hierarchical
    print(store.keys())
----

[source,text]
----
['/orders'] 12
   order_id country  amount    ordered
3         4      DE    7.25 2026-02-15
3        14      DE    7.25 2026-02-15
<ArrowStringArray>
['ES', 'FR', 'DE']
Length: 3, dtype: str
['/orders', '/raw/clean']
----

Notes on this example:

* The `with` block closes the file even if an error occurs; `store.is_open` tells you the state. Always close a store,
  so that everything is flushed to disk.
* `append` requires the same columns in the same order every time, and the `data_columns` cannot be changed after the first
  write. The index values are not reset, which is why the DE row appears with index 3 twice.
* `select_column` reads just one data column, which is a cheap way to list the distinct keys.
* Keys such as `raw/clean` create nested groups and are always absolute. `store.remove("raw")` deletes everything below the
  key. Attribute access (`store.raw.clean`) does not work for hierarchical keys; use `store.get("raw/clean")`.
* Appending to an object that was stored as `fixed` raises `ValueError` ("Can only append to Tables"). Write it with
  `format="table"` first, or set `pd.set_option("io.hdf.default_format", "table")`.
* In pandas 3.1 `HDFStore.put` warns that the default of `track_times` will change from `True` to `False` in a future version.
  Pass `track_times=False` to get files that are byte-identical for identical data, which helps caching and version control.

=== Strings and dtypes

In a table, string columns are stored at a fixed width taken from the first write. A longer string in a later append is an
error; reserve room with `min_itemsize`:

[source,python]
----
with pd.HDFStore("w.h5", mode="w") as store:
    store.append("t", pd.DataFrame({"s": ["ab"]}))
    try:
        store.append("t", pd.DataFrame({"s": ["abcdefgh"]}))
    except ValueError as exc:
        print(str(exc).splitlines()[0])

    store.append("u", pd.DataFrame({"s": ["ab"]}), min_itemsize={"s": 50})
----

[source,text]
----
Trying to store a string with len [8] in [values_block_0] column but
----

The same section of the official guide documents further restrictions:

* Pandas extension dtypes such as `Int64`, `Float64`, `boolean`, `IntervalDtype` and `SparseDtype` cannot be written; the call raises
  `NotImplementedError` (tested with `Int64`). Convert to NumPy dtypes first, for example with `astype("float64")` after handling the
  missing values (see xref:data-science/pandas/nullable-dtypes.adoc[Nullable Integer and Boolean]).
* The `index` keyword is reserved and cannot be a level or column name, and column names that are not valid Python identifiers
  produce a `NaturalNameWarning`.
* Object columns that PyTables cannot represent natively are pickled, which is slow (a `PerformanceWarning`) and brings the
  security risk described below.
* A time zone is stored by its name. Reading with a different time-zone database version can shift values, so keep the
  libraries the same on both sides or store UTC.
* All-NaN rows are kept by default. The `dropna` keyword of `to_hdf`, `put` and `append` is deprecated in pandas 3.1 (it raised a
  `Pandas4Warning` in the tested environment); call `df.dropna()` before writing instead.

=== Compression

Without compression, a 200,000-row table of 4 small integer columns used 8.2 MB. With a compression level it shrinks a lot:

[source,python]
----
import os

big = pd.DataFrame(np.random.default_rng(0).integers(0, 10, size=(200_000, 4)), columns=list("abcd"))
for kw in [{}, {"complevel": 5, "complib": "blosc:zstd"}, {"complevel": 5, "complib": "zlib"}]:
    big.to_hdf("big.h5", key="b", format="table", mode="w", **kw)
    print(kw, os.path.getsize("big.h5"))
----

[source,text]
----
{} 8210230
{'complevel': 5, 'complib': 'blosc:zstd'} 631208
{'complevel': 5, 'complib': 'zlib'} 666760
----

`complib` takes effect only when `complevel` is greater than 0. Passing `complib="zlib"` alone writes uncompressed data and
emits `+UserWarning: complib='zlib' was specified without complevel+`. An unknown `complib` raises `ValueError`, and a library missing from
your PyTables build falls back to `zlib`.

=== Limits to know before choosing HDF5

* *No concurrent writing.* `HDFStore` is not thread-safe for writes, and two writers corrupt the file. Reading from several
  threads or processes at once is fine.
* *Space is not reclaimed.* Deleting rows or rewriting a table leaves the file the same size. Repack with the `ptrepack`
  tool that ships with PyTables.
* *Fragile for sharing.* The layout is specific to pandas and PyTables; Spark, DuckDB and most other tools read Parquet but not
  these files.
* *Writes are chunked.* The default `chunksize` is 50,000 rows; give `expectedrows` on the first `append` when you know the final size.
* An empty DataFrame in table format is not written; pandas emits a `UserWarning`. Use `format="fixed"` to store an empty
  object.

Source: https://pandas.pydata.org/docs/user_guide/io.html#hdf5-pytables[pandas user guide: HDF5 (PyTables)]

== Pickle

`to_pickle` serialises any pandas object with Python's `pickle` module and `read_pickle` loads it back. It preserves every
dtype, the index, categories, extension arrays, and even Python objects stored in object columns, with no conversion rules to learn.

[source,python]
----
df.to_pickle("orders.pkl")
print(pd.read_pickle("orders.pkl").equals(df))
----

[source,text]
----
True
----

The default `protocol` is 5. `compression="infer"` chooses the codec from the file extension:

[source,python]
----
import os

for ext in ["gz", "bz2", "xz"]:
    df.to_pickle(f"orders.pkl.{ext}")
    print(ext, os.path.getsize(f"orders.pkl.{ext}"), pd.read_pickle(f"orders.pkl.{ext}").equals(df))

df.to_pickle("fast.pkl.gz", compression={"method": "gzip", "compresslevel": 1})
----

[source,text]
----
gz 898 True
bz2 971 True
xz 928 True
----

The supported codecs are `gzip`, `bz2`, `xz` and `zstd` for reading and writing, and `zip` for reading only (the archive must
contain exactly one file). A dictionary with a required `"method"` key passes options such as `compresslevel` to the underlying
library. On the tested Python 3.13 the `zstd` codec needed the optional `zstandard` package and raised `ImportError` without it.

Source: https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.to_pickle.html[pandas.DataFrame.to_pickle]

=== Why pickle is dangerous

Unpickling can execute arbitrary code. A pickle file does not store data only; it stores instructions for rebuilding objects,
and an attacker can make those instructions call any function. This harmless demonstration prints a message while loading:

[source,python]
----
class Demo:
    def __reduce__(self):
        return (print, ("code ran while loading the pickle",))

pd.to_pickle(Demo(), "demo.pkl")
pd.read_pickle("demo.pkl")
----

[source,text]
----
code ran while loading the pickle
----

Replace `print` with a call that deletes files or sends data out, and a downloaded "dataset" becomes an attack. The pandas
documentation warns that loading pickled data from untrusted sources is unsafe, and the same applies to HDF5 files that
contain pickled object columns. The rules:

* Never call `read_pickle` or `read_hdf` on a file that came from the internet, an email or a person you do not control.
* Do not unpickle from a shared folder that other people can write to.
* Prefer Parquet or Feather for data that crosses a trust boundary.
* For trained scikit-learn models see xref:data-science/scikit-learn/model-persistence.adoc[Model Persistence and Security].

=== Compatibility

`read_pickle` is only guaranteed to read pickles written by the current or the previous major pandas version. In pandas 3.x the
earliest supported pickle comes from pandas 2.0.0. A pickle is also tied to your Python version and the classes it contains, so it is
a short-term cache or a checkpoint, never an archive. Stored data that must be read in two years belongs in Parquet.

Source: https://pandas.pydata.org/docs/user_guide/io.html#pickling[pandas user guide: Pickling]

== Choosing between them

[cols="2,2,3"]
|===
| Need | Choose | Reason

| Archive or share a table
| Parquet
| Open, typed, safe to read, supported everywhere

| Quick cache of an expensive result in one project, on one machine
| Pickle or Feather
| No conversion rules; pickle also keeps arbitrary Python objects

| Query slices of a very large table on disk
| Parquet with filters, or HDF5 `table`
| HDF5 `table` works but is single-writer and pandas-specific

| Several named tables in one file
| HDF5 or a database
| `HDFStore` groups keys; a SQL database also adds concurrency (see xref:data-science/pandas/io-sql.adoc[SQL Databases])
|===

== Where older tutorials are outdated

[cols="2,3"]
|===
| Older statement | Current situation (October 2026)

| "Use `to_msgpack` and `read_msgpack` for fast serialisation" (pandas 0.x books and posts)
| Removed in pandas 1.0.0. The documentation recommends pickle or Arrow IPC (Feather) instead.

| "HDF5 is the standard fast format for big DataFrames" (articles around 2015 to 2018)
| Parquet and Feather are now the usual choice; HDF5 keeps the single-writer and no-space-reclaim limits.

| "Pickle is a safe way to share a DataFrame"
| It is not safe for untrusted files, and pickles are only guaranteed to load across one pandas major version.

| `+to_hdf(..., dropna=True)+` drops all-NaN rows on append
| The `dropna` keyword is deprecated in pandas 3.1; call `dropna()` before writing.
|===
