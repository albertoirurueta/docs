= What's New in 3.x and Migrating
:description: What changed from pandas 2.0 to 3.1 and how to migrate: release dates, minimum versions, Copy-on-Write, the str dtype, datetime resolution, frequency aliases, removed APIs, the PDEP-17 deprecation policy, inplace deprecations, upcoming changes, and where older books and tutorials are outdated.
:keywords: pandas, pandas 3, migration, what's new, deprecation, Pandas4Warning, str dtype, frequency aliases, ME, inplace, Copy-on-Write, outdated tutorials, data science

include::partial$data-science-pandas-disclaimer.adoc[]

This page was checked in October 2026 against pandas 3.1 (3.1.0, released 2026-10-22) on Python 3.13 with NumPy 2.5, and the printed output of every example was produced on those versions. It summarises what changed between pandas 2.0 and 3.1, gives a migration checklist for code written for pandas 1.x or 2.x, and ends with the places where older books and tutorials no longer match current pandas. Items from the development branch (3.2.0.dev0, unreleased) are labelled "upcoming" and may change before release.

== Minimum versions

[cols="1,2,2",options="header"]
|===
| Dependency | pandas 3.0 | pandas 3.1
| Python | 3.11 | 3.11
| NumPy | 1.26.0 | 2.0.2 (NumPy 1.x is no longer supported)
| PyArrow (optional) | 13.0.0 | 16.0.0
| Matplotlib (optional) | 3.9.3 | 3.10.5
| `pytz` | optional (`+pip install pandas[timezone]+`) | optional
|===

PyArrow is still an optional dependency. Notes from the 2.x era that said it would become required in pandas 3.0 are out of date: that change was postponed, and the `str` dtype falls back to a NumPy `object` backing when PyArrow is not installed. Install it anyway for speed and memory.

== What pandas 3.0 changed

=== Copy-on-Write only

Every derived object behaves as a copy, chained assignment never updates the original, `SettingWithCopyWarning` no longer exists and arrays returned by `+to_numpy()+` can be read-only. See xref:data-science/pandas/copy-on-write.adoc[Copy-on-Write] for the rules and the fixes.

=== The `str` dtype is the default

String columns are inferred as the dedicated `str` dtype instead of `object`. It is backed by PyArrow when installed, holds only strings or missing values, and uses `NaN` as the missing marker (the older opt-in `+"string"+` dtype uses `pd.NA`). It is described in PDEP-14.

[source,python]
----
import pandas as pd

df = pd.DataFrame({"name": ["a", "b"], "n": [1, 2]})
print(df.select_dtypes(include=["object", "string"]).columns.tolist())
print(df.select_dtypes(include="str").columns.tolist())
print(df.dtypes.astype(str).to_dict())
print(df["name"].astype(object).dtype, pd.Series(["a"], dtype="object").dtype)

ser = pd.Series(["a", None, "c"])
print(ser.map(str, na_action="ignore").tolist(), ser.map(str).tolist())
----

Output:

----
['name']
['name']
{'name': 'str', 'n': 'int64'}
object object
['a', nan, 'c'] ['a', 'nan', 'c']
----

Source: https://pandas.pydata.org/docs/user_guide/migration.html[pandas user guide: Migration guide (the new string data type)].

The code changes the migration guide asks for are:

* Replace `+ser.dtype == object+` with `+pd.api.types.is_string_dtype(ser)+` (works on 2.x and 3.x) or `+ser.dtype == "str"+` (3.x only).
* Remove hard-coded `+dtype="object"+` for text, which keeps the old dtype, or write `+dtype="str"+`.
* In `+select_dtypes+`, pass `+include=["object", "string"]+` to work on both versions; `+include=["str"]+` fails on 2.x.
* Test for missing values with `+pd.isna+`, not by comparing with `None` or `np.nan`.
* Expect `TypeError` when assigning a non-string into a `str` column; convert with `+astype(object)+` if you really need mixed values.
* `+astype(str)+` keeps missing values missing; use `+ser.map(str)+` for the old behaviour of producing the text `nan`.
* `+Series.values+` returns an extension array for `str`; use `+to_numpy()+` for a NumPy array.
* `+prod()+` on string data now raises `TypeError`.

See xref:data-science/pandas/text-data-and-str-dtype.adoc[Text Data and the str Dtype].

=== Datetime resolution and time zones

Resolution is now inferred instead of always being nanoseconds. Strings give microseconds (nanoseconds only when the text has that precision), standard-library `datetime` objects keep microseconds, NumPy `datetime64` and `timedelta64` keep their unit (limited to seconds through nanoseconds), and integer input uses the unit passed by the caller. In 3.1, numeric input without an explicit unit also defaults to microseconds. The practical trap is that `+astype("int64")+` on datetimes is 1000 times smaller than code written for nanoseconds expects. Use `+Series.dt.as_unit("ns")+` where a specific resolution matters, and avoid integer casts of datetimes. The default time zone implementation is `zoneinfo` (and `datetime.timezone` for fixed offsets); `pytz` objects are still accepted if you pass them, but `pytz` is no longer installed with pandas, and ambiguous or nonexistent local times raise `ValueError`. `pd.offsets.Day` is now a calendar day that keeps the wall-clock time across a daylight-saving change, so `Day(1)` and `Hour(24)` are no longer equal.

=== Frequency aliases

The aliases deprecated in 2.2 were removed in 3.0, and they now raise `ValueError` with a suggestion.

[cols="1,1,1",options="header"]
|===
| Meaning | Old alias (removed) | Current alias
| Month end | `M` | `ME`
| Business month end | `BM` | `BME`
| Semi-month end | `SM` | `SME`
| Quarter end | `Q` | `QE`
| Year end | `Y` (and `A`) | `YE`
| Hour | `H` | `h`
| Minute | `T` | `min`
| Second | `S` | `s`
| Millisecond, microsecond, nanosecond | `L`, `U`, `N` | `ms`, `us`, `ns`
|===

`Period` and `PeriodIndex` frequencies keep `M`, `Q` and `Y` (for example `+freq="M"+` in `+pd.period_range+`), and `H` and `A` are rejected there as well. Lower-case `d`, `b` and `c` still work in 3.1 but emit a `Pandas4Warning`; use `D`, `B` and `C`.

[source,python]
----
import pandas as pd

sales = pd.Series(
    [10, 20, 30, 40],
    index=pd.date_range("2024-01-15", periods=4, freq="2W"),
)
print(sales.resample("ME").sum())

for old in ["M", "H", "T", "S"]:
    try:
        pd.date_range("2024-01-31", periods=2, freq=old)
    except ValueError as exc:
        print(old, "->", str(exc).splitlines()[0][:70])

print(pd.date_range("2024-01-31", periods=3, freq="ME").strftime("%Y-%m-%d").tolist())
print(pd.date_range("2024-01-01", periods=3, freq="h").freqstr, pd.period_range("2024-01", periods=2, freq="M").freqstr)
----

Output:

----
2024-01-31    10
2024-02-29    50
2024-03-31    40
Freq: ME, dtype: int64
M -> Invalid frequency: M. Failed to parse with error message: ValueError("
H -> Invalid frequency: H. Failed to parse with error message: ValueError('
T -> Invalid frequency: T. Failed to parse with error message: ValueError('
S -> Invalid frequency: S. Failed to parse with error message: ValueError('
['2024-01-31', '2024-02-29', '2024-03-31']
h M
----

Source: https://pandas.pydata.org/docs/whatsnew/v3.0.0.html[pandas 3.0.0 release notes] and https://pandas.pydata.org/docs/user_guide/timeseries.html[Time series / date functionality].

See xref:data-science/pandas/resampling-and-frequencies.adoc[Resampling and Frequencies] and xref:data-science/pandas/time-series.adoc[Time Series and Dates].

=== Removed in 3.0 and earlier

The table lists APIs that older code still uses, when they went away and what to write now. Each name was checked by calling it on pandas 3.1.

[cols="2,1,2",options="header"]
|===
| Removed | Gone since | Use instead
| `+DataFrame.append+`, `+Series.append+` | 2.0 | Collect frames in a list and call `+pd.concat+` once
| `+iteritems+` | 2.0 | `+items+`
| `+Int64Index+`, `+UInt64Index+`, `+Float64Index+` | 2.0 | `+pd.Index(values, dtype=...)+`
| `+.ix+`, `+get_value+`, `+set_value+`, `+read_msgpack+`, `+pd.TimeGrouper+` | 1.0 | `+loc+`/`+iloc+`, `+at+`, Parquet or Feather, `+pd.Grouper+`
| `+DataFrame.applymap+` | 3.0 | `+DataFrame.map+`
| `+fillna(method="ffill")+` and `+method="bfill"+` | 3.0 | `+ffill()+`, `+bfill()+`
| `+groupby(..., axis=1)+` | 3.0 | Transpose, group, transpose back
| `+DataFrame.first+`, `+DataFrame.last+`, `+swapaxes+` | 3.0 | Slice the index with `+loc+`; `+transpose+`
| `+pd.value_counts(x)+` | 3.0 | `+x.value_counts()+`
| `+errors="ignore"+` in `+to_datetime+`, `+to_numeric+`, `+to_timedelta+` | 3.0 | Catch the exception, or `+errors="coerce"+`
| `+delim_whitespace=True+`, `+infer_datetime_format+`, `+date_parser+` in readers | 3.0 | `pass:c[sep=r"\s+"]`, nothing, `+date_format=+`
| `+mode.use_inf_as_na+` | 3.0 | Replace infinities with `NaN` explicitly
| `+read_gbq+`, `+to_gbq+` | 3.0 | The `pandas-gbq` package
| `+Series.view+`, `+Series.ravel+`, `+DataFrame.bool+` | 3.0 | `+astype+`, `+to_numpy().ravel()+`, `+bool(df.iloc[0, 0])+`
|===

Behaviour changes in the same release include: `+groupby+` defaults to `+observed=True+` for categorical keys, `+DataFrame.stack+` uses the new implementation (the `+future_stack+` argument and the old `+dropna+`/`+sort+` arguments are being retired), `+str.replace+` treats the pattern literally unless `+regex=True+`, assigning an incompatible value into a column raises instead of upcasting (PDEP-6), and `NaN` is treated as `NA` in nullable and Arrow-backed floating dtypes.

[source,python]
----
import pandas as pd

rows = [{"id": i, "score": i * 1.5} for i in range(3)]
frames = [pd.DataFrame([r]) for r in rows]     # collect, then concatenate once
result = pd.concat(frames, ignore_index=True)
print(result)

print(hasattr(pd.DataFrame, "append"), hasattr(pd.DataFrame, "applymap"), hasattr(pd.DataFrame, "map"))
df = pd.DataFrame({"a": [" x ", "y"]})
print(df.map(str.strip).to_dict("list"))
print(df.ffill().shape, hasattr(pd, "value_counts"), df["a"].value_counts().to_dict())
print(pd.Series(["a.b"]).str.replace(".", "-").tolist(), pd.Series(["a.b"]).str.replace(".", "-", regex=True).tolist())
----

Output:

----
   id  score
0   0    0.0
1   1    1.5
2   2    3.0
False False True
{'a': ['x', 'y']}
(2, 1) False {' x ': 1, 'y': 1}
['a-b'] ['---']
----

Source: https://pandas.pydata.org/docs/whatsnew/v3.0.0.html[pandas 3.0.0 release notes] and https://pandas.pydata.org/docs/whatsnew/v2.0.0.html[pandas 2.0.0 release notes].

=== New in 3.0

* `+pd.col()+` expressions, usable in `+assign+`, `+loc+` and `+[]+`, replace many one-off `lambda` callables.
* Anti-joins: `+how="left_anti"+` and `+how="right_anti"+` in `+merge+` and `+join+`.
* `+read_iceberg()+` and `+DataFrame.to_iceberg()+` for Apache Iceberg tables, `+DataFrame.from_arrow()+` and `+Series.from_arrow()+` through the Arrow PyCapsule interface.
* A `skipna` argument for groupby reductions, `+Rolling.first+`, `+Rolling.last+`, `+Rolling.nunique+`, `+iloc+` with boolean masks, `+to_sql(if_exists="delete_rows")+` and half-year offsets.
* The three-stage deprecation policy of PDEP-17 (below).

== What pandas 3.1 changed

[cols="1,3",options="header"]
|===
| Change | Details
| `+DataFrame.select()+` | Select columns by label or `+pd.col+` expression, and add computed columns with keyword arguments that can refer to earlier ones
| `+filter(cond=...)+` | Filter rows with a boolean mask, callable or `+pd.col+` expression; a positional list of booleans now warns
| Parallel `+read_csv+` | The C engine reads local, uncompressed files of at least 5 MB in parallel by default; `+mode.max_threads+` (default: number of CPUs, capped at 6) controls it, and `1` forces a serial read
| Resolution for numeric input | `+to_datetime+`, `+to_timedelta+`, `+Timestamp+` and `+Timedelta+` default to microseconds
| Read-only index arrays | `+Index.values+` and `+Index.array+` return read-only arrays
| `+select_dtypes+` | Dtype instances match exactly; `+"datetime64[ns]"+` matches only that resolution; classes such as `decimal.Decimal` raise `TypeError`
| `+read_csv(dtype="category")+` | Numeric and boolean columns get numeric or boolean categories; use `+dtype="str"+` then `+astype("category")+` for string categories
| `numexpr` | `eval` and `query` raise `ImportError` for the unsupported numexpr 2.14.1 when `+engine="numexpr"+` is requested explicitly; install 2.14.2 or newer
| HDF5 | Files written with `+format="table"+` by 3.1 cannot be read by 3.0 or earlier
| Build | C++20 is required to build from source
|===

[source,python]
----
import pandas as pd

df = pd.DataFrame({"name": ["a", "b"], "n": [1, 2]})
print(df.assign(m=pd.col("n") * 10).select("name", total=pd.col("n") + pd.col("n")))
----

Output:

----
  name  total
0    a      2
1    b      4
----

Source: https://pandas.pydata.org/docs/whatsnew/v3.1.0.html[pandas 3.1.0 release notes].

=== `inplace` is deprecated for methods that are not truly in place

Since 3.1 the `+inplace=+` keyword emits a `Pandas4Warning` on `+drop+`, `+rename+`, `+rename_axis+`, `+reset_index+`, `+set_index+`, `+dropna+`, `+drop_duplicates+`, `+sort_values+`, `+sort_index+`, `+eval+` and `+query+` (PDEP-8). These methods always built a new object internally, so the keyword saved nothing. Reassign instead: `+df = df.reset_index()+`. `+fillna+` and `+replace+` keep the keyword for now, although `+inplace=True+` on a column selection no longer reaches the parent frame (see xref:data-science/pandas/copy-on-write.adoc[Copy-on-Write]).

=== Other 3.1 deprecations worth knowing

[cols="2,3",options="header"]
|===
| Deprecated in 3.1 | Replacement
| `+.values+` on tz-aware, period and interval data (lossy) | `+Series.array+`, `+to_numpy()+`, or `+ser.dt.tz_convert(None).to_numpy()+`
| `+mode.chained_assignment+` and `+mode.copy_on_write+` options | Delete; `ChainedAssignmentError` is always emitted
| `+future.infer_string+` option | Always on in pandas 4.0
| `+engine="fastparquet"+` and `+engine="auto"+` in Parquet functions | `+engine="pyarrow"+` or omit
| `+xlrd+` and `+pyxlsb+` engines in `+read_excel+` | `+engine="calamine"+` (or `openpyxl` for `.xlsx`)
| `+ExcelFile.parse()+` | `+read_excel()+`
| `+dayofweek+`, `+dayofyear+`, `+daysinmonth+` attributes | `+day_of_week+`, `+day_of_year+`, `+days_in_month+`
| `+lsuffix+` and `+rsuffix+` in `+DataFrame.join+` | `+suffixes=+`
| Setitem or `+fillna+` that needs a dtype change | Cast first; the change will become an error
|===

== The deprecation policy (PDEP-17)

Since 3.0, a deprecation moves through three stages: a `PandasDeprecationWarning` (a `DeprecationWarning` subclass, quiet by default outside tests), a `PandasFutureWarning` (a `FutureWarning` subclass, shown to users) in the last minor release before removal, and removal in the next major version. The base class is `pandas.errors.PandasChangeWarning`, and each warning names the version that will remove the feature: `Pandas4Warning` means pandas 4.0. Because `Pandas4Warning` is a `DeprecationWarning`, test suites should turn it into an error so that deprecations surface while they are still cheap to fix.

[source,python]
----
import warnings
import pandas as pd

print([c.__name__ for c in pd.errors.Pandas4Warning.__mro__[:4]])

df = pd.DataFrame({"a": [3, 1, 2]})
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    work = df.copy()
    work.sort_values("a", inplace=True)            # deprecated in 3.1
print([type(w.message).__name__ for w in caught])

df = df.sort_values("a")                           # reassign instead
print(df["a"].tolist())

warnings.filterwarnings("error", category=pd.errors.Pandas4Warning)
try:
    pd.DataFrame({"a": [1]}).reset_index(inplace=True)
except pd.errors.Pandas4Warning as exc:
    print("escalated:", type(exc).__name__)
----

Output:

----
['Pandas4Warning', 'PandasDeprecationWarning', 'PandasChangeWarning', 'DeprecationWarning']
['Pandas4Warning']
[1, 2, 3]
escalated: Pandas4Warning
----

Source: https://pandas.pydata.org/docs/whatsnew/v3.0.0.html[pandas 3.0.0 release notes (deprecation policy)] and https://pandas.pydata.org/pdeps/0017-backwards-compatibility-and-deprecation-policy.html[PDEP-17].

== Migration checklist

. Upgrade to Python 3.11 or newer and, for pandas 3.1, NumPy 2.0.2 or newer (see xref:data-science/numpy/numpy-2-migration.adoc[Migrating to NumPy 2.x]).
. Move to pandas 2.3 (2.3.3 is the last 2.x release) and run the tests with deprecation warnings turned into errors. Fix every warning.
. In 2.3, try `+pd.options.future.infer_string = True+` and `+pd.options.mode.copy_on_write = "warn"+`, and repair the code they flag. The Copy-on-Write warnings are intentionally broad, so you do not need to clear every one.
. Replace removed APIs using the table above, including frequency aliases (`ME`, `QE`, `YE`, `h`, `min`) and `+DataFrame.map+` for `applymap`.
. Replace chained assignment with a single `+loc+` call, remove `SettingWithCopyWarning` handling, and stop writing into arrays from `+to_numpy()+`.
. Replace `object` dtype checks and `select_dtypes(include=object)` with the string-aware forms.
. Review datetime-to-integer casts and any code that assumes nanosecond resolution.
. Move to 3.0, then 3.1, fixing `Pandas4Warning` messages as they appear; reassign instead of using `+inplace=True+`.
. Pin the tested range in `pyproject.toml` (for example `pandas>=3.1,<4`), and read the release notes of every minor release.

== Upcoming (unreleased)

The following items come from the 3.2.0 development notes and may still change: `+read_csv(sep=None)+` separator sniffing with the C engine, `+Categorical.to_dense()+`, `+DatetimeIndex.set_freq()+`, `+Series.groupby(as_index=False)+`, a deprecation of `+pandas.to_pickle+` in favour of the object methods, an error for suffix collisions in `+merge+`, and a `ValueError` from `+DataFrame.query+` when the expression is not boolean. Pandas 4.0 will remove the deprecated options and every feature marked with a `Pandas4Warning`. Treat all of this as planned, not available.

== Where older books and tutorials are outdated

Most of what is still taught about pandas was written for versions before 2.0. When a book or tutorial disagrees with the pages in this section, the official documentation wins. The tables name the editions and their dates only to help you translate the examples you may meet; they do not reproduce any text.

=== Books

=== Tutorials and answers written before 2024

[cols="2,3",options="header"]
|===
| Typical advice | Current situation
| "Ignore `SettingWithCopyWarning`{empty}" or "add `.copy()` everywhere" | The warning is gone; chained assignment does nothing; defensive copies are unnecessary. See xref:data-science/pandas/copy-on-write.adoc[Copy-on-Write]
| Build a DataFrame by calling `+append+` in a loop | `append` was removed in 2.0; collect rows or frames and call `+pd.concat+` once
| `+freq="M"+`, `+"Q"+`, `+"A"+`, `+"H"+`, `+"T"+` | Removed in 3.0; use `ME`, `QE`, `YE`, `h`, `min`
| `+applymap+`, `+fillna(method=...)+`, `+groupby(axis=1)+`, `+df.ix+` | All removed; see the table of removed APIs
| `+df.dtypes == object+` or `+select_dtypes(include="object")+` for text | Text is `str`; use `+is_string_dtype+` or `+include=["object", "string"]+`
| "PyArrow will be required in pandas 3.0" | Postponed; PyArrow stays optional
| `+inplace=True+` is faster and saves memory | It never did for most methods and is deprecated in 3.1
| `+astype("int64")+` on datetimes gives nanoseconds | The unit now depends on the data; use `+dt.as_unit("ns")+`
| Regular-expression behaviour of `+str.replace+` | A literal match by default; pass `+regex=True+`
|===
