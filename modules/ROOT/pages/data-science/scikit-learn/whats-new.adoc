:description: What changed in scikit-learn 1.6, 1.7, 1.8 and 1.9 (1.10 upcoming): FrozenEstimator, array API, callbacks, narwhals, metric_at_thresholds, deprecations and removals with dates, and where older books and tutorials are outdated.

This page was checked in October 2026 against the scikit-learn 1.9.1 release (September 2026) and the 1.10 development notes, on Python 3.13 with NumPy 2.5 and pandas 3.1. The probes and examples were run on those versions. It has two jobs: to summarise what the four most recent minor releases changed, and to list what older books and tutorials get wrong today, so that you can translate their code. Everything labelled "upcoming" is in the unreleased 1.10 development line and may change before release.

scikit-learn ships a minor release about every six months, with bug-fix releases in between. A deprecation normally lasts two minor releases: the first release warns, and the second one after it removes the feature. The warnings are `FutureWarning` or `DeprecationWarning`, so run your tests with warnings turned into errors before you upgrade (`python -W error::FutureWarning -m pytest`).

== Release by release

=== 1.6 (December 2024)

* *FrozenEstimator.* `sklearn.frozen.FrozenEstimator` freezes a fitted estimator: `fit` does nothing and `clone` returns the same object. It replaces `+CalibratedClassifierCV(cv="prefit")+`. See xref:data-science/scikit-learn/frozen-estimator.adoc[FrozenEstimator].
* *Pipeline metadata.* `Pipeline` can transform metadata up to the step that needs it, through the `transform_input` parameter.
* *Estimator tags.* `+__sklearn_tags__+` is the new way to set estimator tags; the private helpers `+_more_tags+`, `+_get_tags+` and `+_safe_tags+` are deprecated (they raise `DeprecationWarning` from 1.6.1). Third-party estimators must inherit from `BaseEstimator`, which implements the new method. `utils.validation.validate_data` replaces the private `+_validate_data+` method.
* *Free-threaded Python.* Preliminary support, with wheels for the experimental free-threaded CPython 3.13 on all supported platforms.
* *Lazy submodule access.* `import sklearn; sklearn.svm.SVC()` now works without importing `sklearn.svm`.
* *Array API.* Search classes (`GridSearchCV`, `RandomizedSearchCV`, `HalvingGridSearchCV`, `HalvingRandomSearchCV`) accept array API inputs when their base estimator does. Support for `cupy.array_api` was removed in favour of the top-level `cupy` module.
* *Deprecations that followed.* `+AdaBoostClassifier(algorithm=...)+` (removal announced for 1.8; the `SAMME.R` value itself was deprecated in 1.4), `force_all_finite` (renamed `ensure_all_finite`, removal announced for 1.8), `+scoring="max_error"+` (use `+"neg_max_error"+`), and the default `response_method=None` of `make_scorer`.

=== 1.7 (June 2025)

* *Sparse arrays.* As part of the SciPy move from `spmatrix` to `sparray`, internal code accepts both. Input of either kind works.
* *Vendored array libraries.* `array-api-compat` and `array-api-extra` ship inside scikit-learn, so array API users no longer install `array-api-compat` themselves.
* *HistGradientBoosting.* `X_val`, `y_val` and `sample_weight_val` can be passed to `fit` to control the early-stopping validation set.
* *Metrics.* `brier_score_loss` supports multiclass problems and has a `scale_by_half` argument; `RocCurveDisplay.from_cv_results` plots curves from `cross_validate` results; in `RocCurveDisplay.from_predictions` the argument `y_pred` was renamed `y_score`.
* *Estimators.* `DictionaryLearning` and `SparseCoder` gained `inverse_transform`; the neural network estimators accept `sample_weight`; mixture models store `lower_bounds_`.
* *Deprecations.* `liblinear` with a one-versus-rest multiclass scheme in `LogisticRegression` (an error from 1.8; wrap in `OneVsRestClassifier`), `n_alphas` in the cross-validated Lasso and Elastic-Net classes (use `alphas` with an integer), `force_int_remainder_cols` in `ColumnTransformer`, and integer columns in `partial_dependence`.

=== 1.8 (December 2025)

* *Calibration.* `CalibratedClassifierCV` has `+method="temperature"+`.
* *Manifold learning.* `ClassicalMDS` (classical multidimensional scaling) was added; `MDS` accepts arbitrary metrics.
* *Array API.* `StandardScaler`, `RidgeCV`, `RidgeClassifier`, `GaussianMixture`, `PolynomialFeatures`, `GaussianNB`, `cross_val_predict` and many metrics gained support.
* *Free-threaded Python 3.14.* Wheels are available for all supported platforms on the free-threaded CPython 3.14, which the project recommends over 3.13 for trying free-threading.
* *Metrics.* `confusion_matrix_at_thresholds` and `d2_brier_score`.
* *Linear models.* `penalty` of `LogisticRegression` and `LogisticRegressionCV` is deprecated: use `l1_ratio` (0 for L2, 1 for L1, in between for elastic net) and `C=np.inf` for no regularisation. `n_jobs` of `LogisticRegression` is deprecated because it has had no effect since 1.8. `PassiveAggressiveClassifier` and `PassiveAggressiveRegressor` are deprecated in favour of `SGDClassifier` and `SGDRegressor` with `+learning_rate="pa1"+` or `+"pa2"+`.
* *Discriminant analysis.* `QuadraticDiscriminantAnalysis` gained `solver`, `covariance_estimator` and `shrinkage`.

=== 1.9 (June 2026, 1.9.1 in September 2026)

* *Callback API (experimental).* `set_callbacks` attaches callbacks to the fit of supporting estimators. `sklearn.callback.ProgressBar` (needs `rich`) and `sklearn.callback.ScoringMonitor` ship with it. `LogisticRegression` (with `+solver="lbfgs"+`), the search classes, `Pipeline` and `StandardScaler` support callbacks. The API may change without the usual deprecation cycle.
* *Thresholds.* `metric_at_thresholds` computes a metric at every threshold for the decision-threshold workflow; `PrecisionRecallDisplay.from_cv_results` plots several curves.
* *Sparse interface.* The configuration key `sparse_interface` chooses whether functions return SciPy sparse matrices (`+"spmatrix"+`, the default) or sparse arrays (`+"sparray"+`). The plan is to change the default to `+"sparray"+` in a few releases.
* *narwhals.* The new dependency described above.
* *HTML representation.* Estimators display a table of their fitted attributes (public attributes ending in an underscore) and, for `ColumnTransformer` and `FeatureUnion`, the names of the output features with a copy button.
* *Zero weights.* A `ValueError` is raised when `sample_weight` contains only zeros, in all estimators that accept it.
* *Array API.* `LogisticRegression` and `PoissonRegressor` (with `+solver="lbfgs"+`), `FeatureUnion`, `Nystroem`, `RidgeCV` and more metrics gained support; the `move_estimator_to` utility was added.
* *Deprecations.* `+SVC(probability=...)+` and `+NuSVC(probability=...)+`, with the `probA_` and `probB_` attributes (use `CalibratedClassifierCV(SVC(), ensemble=False)`); `shuffle` and `random_state` of `TargetEncoder` (pass a splitter as `cv`); `+criterion="friedman_mse"+` for trees and the `criterion` parameter of gradient boosting; `n_alphas` in `lasso_path` and `enet_path`; positional `sample_weight` in `LogisticRegressionCV.score`.
* *Behaviour changes.* `+PowerTransformer(method="yeo-johnson")+` uses `scipy.stats.yeojohnson`, so results can differ in the last digits; random forests and extra trees draw samples using `sample_weight`; `MiniBatchKMeans` handles sample weights correctly; `LinearDiscriminantAnalysis` with `+solver="svd"+` normalises like `+solver="eigen"+` (1.9.1).
* *1.9.1 fixes.* Array API metrics accept pandas labels; metadata is routed to sub-estimators of `SelectFromModel`, `RFE`, `RFECV`, `SequentialFeatureSelector` and `IterativeImputer` inside pipelines, and `BaggingClassifier` and `TransformedTargetRegressor` route it correctly; `ScoringMonitor` works with multi-process backends; `DBSCAN` and `OPTICS` stop warning on precomputed sparse matrices; `fetch_openml` recovers from a corrupted download; memory leaks and an out-of-bounds write in `LinearSVR` and `LinearSVC` were fixed.

Source: https://scikit-learn.org/stable/whats_new/v1.9.html[scikit-learn 1.9 release notes]; https://scikit-learn.org/stable/whats_new/v1.8.html[1.8]; https://scikit-learn.org/stable/whats_new/v1.7.html[1.7]; https://scikit-learn.org/stable/whats_new/v1.6.html[1.6].

=== 1.10 (upcoming)

The development notes (1.10.dev0, October 2026) list changes that are not in any release yet.

* *Metadata auto-requests.* `set_config(enable_metadata_auto_requests=True)` lets estimators, scorers and splitters request common metadata such as `sample_weight` automatically; `+HistGradientBoosting*+` auto-request `X_val`, `y_val` and `sample_weight_val`.
* *IterativeImputer.* No longer experimental: import it from `sklearn.impute`, and the old enabling import becomes a warning and a no-op. On 1.9.1 you still need `from sklearn.experimental import enable_iterative_imputer`.
* *Experimental import.* `sklearn.experimental.enable_hist_gradient_boosting` is deprecated (removal in 1.12).
* *Random forests.* `categorical_features` for `+RandomForest*+` and `+ExtraTrees*+`, including `+"from_dtype"+`, which is planned to become the default in 1.13.
* *GLMs and logistic regression.* New `newton-cd` and `newton-cd-gram` solvers and L1 and elastic-net penalties for `GammaRegressor`, `PoissonRegressor` and `TweedieRegressor`.
* *Parametrisation.* `C` of `LogisticRegression` and `Cs` of `LogisticRegressionCV` are deprecated in favour of `alpha` and `alphas` (`alpha = 1 / C`), with removal planned for 1.14.
* *Array API.* More estimators and metrics (`LedoitWolf`, `OAS`, `LogisticRegressionCV`, `matthews_corrcoef`) and fixes for mixed namespaces.
* *Changed models.* `QuantileTransformer` estimates quantiles differently and no longer caps `n_quantiles` at `n_samples`; `+HistGradientBoosting*+` draw the per-split feature subset differently when `max_features < 1.0`; `partial_dependence` computes its grid with `numpy.nanquantile`.

Source: https://scikit-learn.org/dev/whats_new/v1.10.html[scikit-learn 1.10 development release notes].

== Run the new features

=== A callback that records a score at each iteration

[source,python]
----
from sklearn.callback import ScoringMonitor
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression

X, y = make_classification(random_state=0)
monitor = ScoringMonitor(scoring="accuracy")
clf = LogisticRegression(solver="lbfgs", max_iter=50).set_callbacks(monitor)
clf.fit(X, y)

log = monitor.get_logs()
df = log.data_as_pandas
print(type(log).__name__)
print(df.columns.tolist())
print(df[["task_name", "accuracy"]].head())
print(len(df))
----

Output:

----

The monitor scores the model on the training data at each `lbfgs` iteration and stores the rows in a log that converts to a pandas frame. The API is experimental: the column names and the way `get_logs` groups runs may change.

=== A metric at every threshold

[source,python]
----
import numpy as np
from sklearn.datasets import make_classification
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score, metric_at_thresholds
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=300, random_state=0)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)
scores = LogisticRegression().fit(X_tr, y_tr).predict_proba(X_te)[:, 1]

values, thresholds = metric_at_thresholds(y_te, scores, f1_score)
best = int(np.argmax(values))
print(values.shape, thresholds.shape)
print(round(float(thresholds[best]), 3), round(float(values[best]), 3))
----

Output:

----
(75,) (75,)
0.684 0.932
----

`+metric_at_thresholds(y_true, y_score, metric_func, ...)+` calls `metric_func` for the predictions obtained at each distinct score threshold, so you can plot or maximise any metric. Choosing a threshold on the same data you evaluate on is optimistic; use a validation set, or `TunedThresholdClassifierCV`, as in xref:data-science/scikit-learn/decision-threshold.adoc[Tuning the Decision Threshold].

Source: https://scikit-learn.org/stable/modules/classification_threshold.html[scikit-learn user guide: Tuning the decision threshold for class prediction].

== Where older books and tutorials are outdated

Learning material about scikit-learn ages quickly, because the project removes deprecated code after two releases. The tables below translate what you will meet in older books and tutorials. They list API names and release dates, not book text. Wherever a book and the official documentation disagree, the official documentation of the current release wins.

=== Names that no longer exist

The probe below imports or calls each legacy name on scikit-learn 1.9.1 and prints the kind of error it produces.

[source,python]
----
import importlib

import numpy as np

warnings.simplefilter("ignore")
rng = np.random.RandomState(0)
X = rng.rand(30, 3)

def status(fn):
    try:
        fn()
        return "works"
    except Exception as exc:
        return type(exc).__name__

def imp(code):
    return lambda: exec(code, {})

|Positional hyper-parameters such as `+LogisticRegression("l2", 0.5)+`
|Keyword arguments
|Enforced since 1.0; the probe shows `TypeError`.
|===

=== Defaults that changed in 0.22

Code written before December 2019 (scikit-learn 0.22.0 was released on December 3, 2019) may assume the old defaults. These are the current values, confirmed on 1.9.1.

[cols="2,1,1",options="header"]
|===
|Setting |Current default |Used to be

|`+RandomForestClassifier(n_estimators=...)+`
|100
|10

|`+cross_val_score(..., cv=None)+` and other searches
|5 folds
|3 folds

|`+LogisticRegression(solver=...)+`
|`+"lbfgs"+`
|`+"liblinear"+`

|`+SVC(gamma=...)+`
|`+"scale"+`
|`+"auto"+`
|===

Other defaults that moved later: `+KMeans(n_init="auto")+` since 1.4 (older code often passes `n_init=10`), keyword-only arguments since 1.0, and `+fetch_openml(as_frame="auto")+`, which returns a DataFrame by default, so code that indexes the result as an array, such as `+X[0]+`, fails.

=== Other statements to watch for

* *Seeding.* Tutorials call `np.random.seed(42)` and then rely on global state. scikit-learn recommends passing `random_state` explicitly; see xref:data-science/scikit-learn/common-pitfalls.adoc[Common Pitfalls].
* *`+StratifiedKFold(random_state=...)+` without `shuffle=True`.* It raises `ValueError`.
* *Experimental imports.* `+HistGradientBoosting*+` is stable and its enabling import is a warning today. `IterativeImputer` and the halving searches still need their `sklearn.experimental` imports on 1.9.1.
* *`TargetEncoder`.* `fit(X, y).transform(X)` differs from `fit_transform(X, y)`, which cross-fits to avoid leakage.
* *`set_output`.* Pandas output arrived in 1.2 and polars output in 1.4; dataframe handling now rests on narwhals. On 1.9.1 with pandas 3.1, `make_column_selector(dtype_include=object)` still selects the new `str` columns, so older pandas code keeps working.
* *Pickled models.* Loading a model in a different scikit-learn version is unsupported. See xref:data-science/scikit-learn/model-persistence.adoc[Model Persistence and Security].
* *Python 2 code.* `print` statements, integer division, `xrange` and `import pylab` need translating before anything else.

None of the books covers `FrozenEstimator`, array API dispatch, `set_output`, metadata routing, the callback API, or the modern leakage and reproducibility practices on this page and in xref:data-science/scikit-learn/common-pitfalls.adoc[Common Pitfalls]; those topics come only from the official documentation.

== Staying current

* Subscribe to the release history and read the "API Change" lines first.
* Run your tests with `-W error::FutureWarning -W error::DeprecationWarning` on a CI job that installs the newest release.
* Pin the minor version of scikit-learn in the environment that trains and serves a model, and rebuild the model when you upgrade; see xref:data-science/scikit-learn/model-persistence.adoc[Model Persistence and Security].
* Treat anything labelled experimental (array API, callbacks, `sparse_interface` defaults) as subject to change without a deprecation cycle.
