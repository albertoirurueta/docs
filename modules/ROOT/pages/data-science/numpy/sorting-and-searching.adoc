= Sorting, Searching & Counting
:description: Sorting, searching and counting in NumPy 2.5: np.sort, argsort, lexsort, partition, searchsorted, nonzero, argmax, count_nonzero, bincount and digitize, with stable and descending sorting, NaN ordering and top-k patterns, checked in October 2026.
:keywords: NumPy, sort, argsort, lexsort, partition, argpartition, searchsorted, stable sort, descending, NaN ordering, nonzero, argwhere, argmax, nanargmax, count_nonzero, bincount, digitize, top-k, take_along_axis

include::partial$data-science-numpy-disclaimer.adoc[]

Ordering data, finding where a value would fit, and counting what is there are three of the most frequent operations
in numerical code. NumPy gathers them in the routines documented under "Sorting, searching, and counting": a family of
sorts that return values or positions, a binary search, functions that locate non-zero or extreme elements, and
counters for integers and bins.

This page targets **NumPy 2.5**, as checked against the official documentation in **October 2026**. Examples target
Python 3.13 or 3.14 and were run on Python 3.13. Every code block was run with NumPy 2.5.4 and the printed output is real. Related pages
in this part: xref:data-science/numpy/index.adoc[NumPy overview], xref:data-science/numpy/indexing-advanced.adoc[Advanced & Boolean Indexing]
(the index arrays that `argsort` and `nonzero` produce are used there),
xref:data-science/numpy/reductions-and-axes.adoc[Reductions & Axis Semantics], xref:data-science/numpy/statistics.adoc[Statistics & Histograms]
and xref:data-science/numpy/set-operations.adoc[Set Operations].

== Sorting values with np.sort

`np.sort(a)` returns a sorted copy; the method `a.sort()` sorts in place and returns `None`. Both sort along the **last
axis** by default.

[source,python]
----
import numpy as np

a = np.array([3, 1, 2, 1, 5, 4])
print(np.sort(a))
print(np.sort(a, descending=True))
b = a.copy()
b.sort()
print(b)

m = np.array([[3, 1, 2], [9, 7, 8]])
print(np.sort(m, axis=1))   # each row (the default)
print(np.sort(m, axis=0))   # each column
print(np.sort(m, axis=None))  # flattened first
----

----
[1 1 2 3 4 5]
[5 4 3 2 1 1]
[1 1 2 3 4 5]
[[1 2 3]
 [7 8 9]]
[[3 1 2]
 [9 7 8]]
[1 2 3 7 8 9]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.sort.html[numpy.sort]

The signature has three options that matter:

* `axis`: the axis to sort along; `axis=None` flattens first.
* `kind`: `+'quicksort'+` (the default), `+'mergesort'+`, `+'heapsort'+` or `+'stable'+`. According to the documentation,
  `+'stable'+` and `+'mergesort'+` both use timsort or radix sort depending on the dtype, and `+'mergesort'+` is kept only
  for backward compatibility. Despite its name, the default `+'quicksort'+` is an introsort, which bounds the worst case.
* `stable=` (added in NumPy 2.0): `stable=True` selects `+kind='stable'+` and `stable=False` or `None` makes no
  promise. This is the spelling to prefer, because the array API standard uses it.
* `descending=` (added in NumPy 2.5): `descending=True` sorts from largest to smallest.

Before `descending=` existed, code reversed the result with a slice (`np.sort(a)[::-1]`), or negated the input
(`np.sort(-a)`), which fails for unsigned integers and mishandles the smallest signed value. On NumPy 2.5 write
`np.sort(a, descending=True)` and let the library handle the dtype. On older NumPy releases the reversal slice remains
the portable spelling, so a library that supports NumPy below 2.5 cannot use `descending=` yet.

=== NaN and infinity ordering

NaN values are sorted to the **end**, after `inf`, and `descending=True` keeps them at the end instead of moving them
to the front.

[source,python]
----
x = np.array([2.0, np.nan, 1.0, -np.inf, np.inf])
print(np.sort(x))
print(np.sort(x, descending=True))
----

----
[-inf   1.   2.  inf  nan]
[ inf   2.   1. -inf  nan]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.sort.html[numpy.sort] (the Notes section on the ordering of complex numbers, NaN and masked values)

This is the opposite of what a naive "NaN is the smallest value" intuition suggests, and it is also different from
`np.argmin` and `np.argmax`, covered below, which treat NaN as the extreme value.

=== Sorting strings and structured data

Strings sort lexicographically by code point, so uppercase letters come before lowercase ones (`+'A'+` before `+'a'+`).
Structured arrays (see xref:data-science/numpy/structured-arrays.adoc[Structured Arrays]) are sorted by field with the
`order` argument; fields that are not named still break ties, in dtype order. Complex numbers sort by real part and then
imaginary part, and `np.sort_complex` is the dedicated function for that.

[source,python]
----
people = np.array(
    [("lee", 30), ("kim", 25), ("lee", 22)],
    dtype=[("name", "U3"), ("age", "i4")],
)
print(np.sort(people, order=["name", "age"]))
print(np.sort_complex([2 + 1j, 1 + 5j, 1 + 2j]))
----

----
[('kim', 25) ('lee', 22) ('lee', 30)]
[1.+2.j 1.+5.j 2.+1.j]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.sort.html[numpy.sort] and https://numpy.org/doc/stable/reference/generated/numpy.sort_complex.html[numpy.sort_complex]

== Sorting positions with argsort

`np.argsort(a)` returns the **indices** that would sort `a`. Positions are more useful than values whenever a second
array has to be reordered the same way (names by score, labels by feature, rows by key). It accepts the same `axis`,
`kind`, `stable` and `descending` arguments as `np.sort`.

[source,python]
----
scores = np.array([70, 90, 70, 85, 90])
names = np.array(["ann", "bob", "cy", "dee", "eve"])

print(np.argsort(scores, stable=True))
print(np.argsort(scores, stable=True, descending=True))
print(names[np.argsort(scores, stable=True, descending=True)])
----

----
[0 2 3 1 4]
[1 4 3 0 2]
['bob' 'eve' 'dee' 'ann' 'cy']
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.argsort.html[numpy.argsort]

The two 90s keep their original order (`bob` before `eve`) and so do the two 70s, because the sort is stable. That
matters whenever ties exist: with the default quicksort the order of equal elements is not defined, so a result can
differ between NumPy versions, platforms or array sizes even though each one is a valid sort. Request `stable=True`
whenever tie order is observable, for example when ranking, when sorting in several passes (sort by the secondary key
first, then by the primary key), or when the output is compared against a stored expected result.

The older idiom for descending order, `np.argsort(-scores)`, is stable only for the ties among negated values, and it is
wrong for unsigned integers and for strings; `descending=True` replaces it.

=== Sorting every row or column independently

On a 2-D array, `argsort(axis=1)` gives, per row, the column order. Apply it with `np.take_along_axis`, which expects an
index array with the same number of dimensions as the data. Plain fancy indexing `M[idx]` would index rows instead.

[source,python]
----
rng = np.random.default_rng(0)
M = rng.integers(0, 10, size=(3, 4))
idx = np.argsort(M, axis=1)
print(M)
print(idx)
print(np.take_along_axis(M, idx, axis=1))
----

----
[[8 6 5 2]
 [3 0 0 0]
 [1 8 6 9]]
[[3 2 1 0]
 [1 2 3 0]
 [0 2 1 3]]
[[2 5 6 8]
 [0 0 0 3]
 [1 6 8 9]]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.take_along_axis.html[numpy.take_along_axis]

With `axis=None`, `argsort` works on the flattened array and the indices refer to flat positions; convert them to
coordinates with `np.unravel_index`.

== Sorting by several keys with lexsort

`np.lexsort(keys)` sorts by several keys and returns indices. The **last** key in the sequence is the primary key,
which is the reverse of the order in which a person would say "by last name, then first name".

[source,python]
----
last = np.array(["lee", "kim", "lee", "kim"])
first = np.array(["bo", "zoe", "al", "amy"])
order = np.lexsort((first, last))   # primary key last
print(order, last[order], first[order])
----

----
[3 1 2 0] ['kim' 'kim' 'lee' 'lee'] ['amy' 'zoe' 'al' 'bo']
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.lexsort.html[numpy.lexsort]

`lexsort` is always stable. For tabular data with named columns, pandas `+sort_values(by=[...])+` is usually clearer; see
xref:data-science/pandas/index.adoc[the pandas part].

== Partial sorting: partition and argpartition

A full sort costs O(n log n). If only the k smallest or largest elements, or a single order statistic such as the
median, are needed, `np.partition(a, kth)` does less work (the algorithm is introselect, linear on average). It places
the element that would sit at position `kth` in a fully sorted array in that position, puts everything smaller or equal
before it and everything larger after it, and promises **nothing about the order inside each side**.

[source,python]
----
a = np.array([7, 1, 5, 3, 9, 2, 8])
p = np.partition(a, 2)
print(p, p[2])                       # p[2] is the 3rd smallest
print(np.partition(a, -3)[-3:])      # the 3 largest, unordered
print(np.sort(np.partition(a, -3)[-3:])[::-1])  # the 3 largest, descending
print(np.argpartition(a, 2)[:3], a[np.argpartition(a, 2)[:3]])
print(np.partition(a, (1, 4)))       # several pivots at once
----

----
[1 2 3 5 9 7 8] 3
[7 9 8]
[9 8 7]
[1 5 3] [1 2 3]
[1 2 3 5 7 9 8]
----

The output above came from NumPy 2.5.4 on Apple silicon. Only the values at the pivot positions are guaranteed; the order
on each side of a pivot depends on the NumPy build and the CPU, so another machine can print the same elements in a
different order.

Source: https://numpy.org/doc/stable/reference/generated/numpy.partition.html[numpy.partition] and https://numpy.org/doc/stable/reference/generated/numpy.argpartition.html[numpy.argpartition]

Typical uses are a top-k selection (partition, then sort only the k winners), and a robust location estimate without a
full sort. `kth` may be negative and may be a sequence of positions. A stable tie order is not available with
partition, so if ties must be broken deterministically use a full `argsort(stable=True)` and slice the first k. `np.median`
and `np.percentile` use partitioning internally, as described on xref:data-science/numpy/statistics.adoc[Statistics & Histograms].

== Binary search with searchsorted

`np.searchsorted(a, v)` finds the index at which each value of `v` would have to be inserted into the **already sorted**
array `a` to keep it sorted. It uses binary search, so it costs O(log n) per value, and it accepts a whole array of
queries at once.

[source,python]
----
s = np.array([10, 20, 20, 30])
print(np.searchsorted(s, 20))                  # side="left" is the default
print(np.searchsorted(s, 20, side="right"))
print(np.searchsorted(s, [5, 25, 99]))
----

----
1
3
[0 3 4]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.searchsorted.html[numpy.searchsorted]

.For a repeated value, side="left" returns the index of its first copy and side="right" the index after its last copy
image::data-science-numpy-searchsorted-sides.svg["Sorted array 10, 20, 20, 30 with insertion indices 0 to 4; the value 20 gives index 1 with side left and index 3 with side right",width=720]

In the figure, marker 1 is the answer for `side="left"` (the insertion point before the existing 20s) and marker 2 is the
answer for `side="right"` (after them). The difference between the two is exactly the number of copies of the value,
which makes `searchsorted(a, v, "right") - searchsorted(a, v, "left")` a counter for sorted data.

Three consequences are worth keeping in mind:

* **The input must be sorted.** `searchsorted` does not check, and unsorted input returns indices that look valid but
  are meaningless. If the array is not sorted but you do not want to reorder it, pass the permutation from `argsort`
  as `sorter=`.
* **It does not test membership.** The returned index can point at a value different from the one searched for. To
  test membership, compare `s[i] == v` after clipping `i` to the length, or use `np.isin`
  (see xref:data-science/numpy/set-operations.adoc[Set Operations]).
* **It is the building block of binning.** Searching with `side="right"` against bin edges and subtracting one gives
  the interval each value falls in, which is what `np.digitize` below packages.

[source,python]
----
bins = np.array([0, 18, 65])             # [0,18), [18,65), [65,inf)
ages = np.array([3, 18, 40, 70])
print(np.searchsorted(bins, ages, side="right") - 1)

u = np.array([30, 10, 20])               # unsorted: supply the sorter
srt = np.argsort(u)
print(srt[np.searchsorted(u, 20, sorter=srt)])   # position of 20 in u
----

----
[0 1 1 2]
2
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.searchsorted.html[numpy.searchsorted]

NaN is treated as larger than every number, consistent with `np.sort`, so a NaN query is inserted at the end of an
array whose NaNs are last. For sorted string arrays or dates the same function works unchanged.

== Finding elements: nonzero, argwhere, where and extract

Several functions return the **positions** of elements that satisfy a condition.

[source,python]
----
z = np.array([[0, 3], [4, 0]])
print(np.nonzero(z))        # tuple of index arrays, one per axis
print(np.argwhere(z))       # one row of coordinates per element
print(np.flatnonzero(z))    # indices into the flattened array
print(np.where(z > 0, "pos", "zero"))   # three-argument form: choose per element
w = np.array([[1, 5], [7, 2]])
print(np.extract(w > 1, w))
----

----
(array([0, 1]), array([1, 0]))
[[0 1]
 [1 0]]
[1 2]
[['zero' 'pos']
 ['pos' 'zero']]
[5 7 2]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.nonzero.html[numpy.nonzero] and https://numpy.org/doc/stable/reference/generated/numpy.where.html[numpy.where]

* `np.nonzero(a)` returns a tuple with one index array per dimension; it can be used directly as an index
  (`a[np.nonzero(a)]`), and `np.nonzero(a > 3)` is the idiomatic way to turn a condition into positions.
* `np.argwhere(a)` returns the same coordinates grouped per element, a `(count, ndim)` array that is convenient for
  looping or for later feeding a plot.
* `np.flatnonzero(a)` is `np.nonzero(np.ravel(a))[0]`.
* `np.where(cond)` with one argument is the same as `np.nonzero(cond)`; with three arguments it is an element-wise
  conditional that selects from `x` or `y`. Both branches are fully evaluated, so use it for selection, not to avoid an
  invalid computation such as a division by zero (`np.errstate` and the `where=` argument of ufuncs are the tools for
  that; see xref:data-science/numpy/floating-point-errors.adoc[Floating-Point Errors & errstate]).
* `np.extract(cond, a)` is a flat `a[cond]`; ordinary Boolean indexing is almost always preferable.

Boolean indexing and these functions are compared in xref:data-science/numpy/indexing-advanced.adoc[Advanced & Boolean Indexing].

== Locating extremes: argmax, argmin and the NaN variants

`argmax` and `argmin` return the position of the first maximum or minimum. They take `axis=` and `keepdims=`. With `axis=None` the index refers to the flattened array, and `np.unravel_index` turns it back into
coordinates.

[source,python]
----
v = np.array([3, 9, 9, 1])
print(np.argmax(v), np.argmin(v), np.argmax(v, keepdims=True))

w = np.array([[1, 5], [7, 2]])
print(np.argmax(w, axis=1))
print(np.unravel_index(np.argmax(w), w.shape))

x = np.array([3.0, np.nan, 1.0])
print(np.argmin(x), np.nanargmin(x))
print(np.argmax([1, np.nan, 3]), np.nanargmax([1, np.nan, 3]))
----

----
1 3 [1]
[1 0]
(np.int64(1), np.int64(0))
1 2
1 2
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.argmax.html[numpy.argmax] and https://numpy.org/doc/stable/reference/generated/numpy.nanargmax.html[numpy.nanargmax]

`np.argmax` and `np.argmin` treat NaN as an extreme value: any NaN wins, so an array containing a NaN returns the
position of the first NaN. `np.nanargmax` and `np.nanargmin` ignore NaN instead, and raise `ValueError` ("All-NaN slice
encountered") when a slice contains nothing else. Ties return the **first** occurrence; to find all of them compare
with the maximum and call `np.flatnonzero`.

== Counting

[source,python]
----
w = np.array([[1, 5], [7, 2]])
print(np.count_nonzero(w > 1), np.count_nonzero(w > 1, axis=0))

print(np.bincount([0, 1, 1, 3, 1]))
print(np.bincount([0, 1, 1, 2], weights=[0.5, 1, 2, 3], minlength=5))

vals, counts = np.unique(np.array(["a", "b", "a", "c", "a"]), return_counts=True)
print(vals, counts)
----

----
3 [1 2]
[1 3 0 1]
[0.5 3.  3.  0.  0. ]
['a' 'b' 'c'] [3 1 1]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.count_nonzero.html[numpy.count_nonzero] and https://numpy.org/doc/stable/reference/generated/numpy.bincount.html[numpy.bincount]

* `np.count_nonzero(a)` counts non-zero (or `True`) elements, with `axis=` and `keepdims=`. For a Boolean condition it
  is the fastest way to count matches (`np.count_nonzero(a > 3)`), and `(a > 3).sum()` gives the same result more slowly.
* `np.bincount(x)` counts occurrences of each **non-negative integer**; the result has length `pass:c[x.max() + 1]`, or at
  least `minlength`. With `weights=` it sums the weights per value instead, which makes it a very fast group-by-sum over
  integer codes. Negative values raise `ValueError`, and floats raise `TypeError` because they cannot be cast safely to
  integers.
* `np.unique(x, return_counts=True)` counts any sortable values, at the cost of a sort (or, for
  `np.unique_values` since NumPy 2.3, a hash-based pass); see xref:data-science/numpy/set-operations.adoc[Set Operations].

A cumulative count is `np.cumsum(np.bincount(x))`, and `np.searchsorted(sorted_a, v, "right") - np.searchsorted(sorted_a, v, "left")`
counts the copies of `v` in sorted data without scanning it.

== Binning with digitize and histogram

`np.digitize(x, bins)` returns, for every value, the index of the bin it falls into. The bins must be monotonically
increasing or decreasing. With `right=False` (the default) bin `i` is the half-open interval `+bins[i-1] <= x < bins[i]+`;
with `right=True` it is `+bins[i-1] < x <= bins[i]+`. Values below the first edge get index 0 and values at or above the
last edge get `len(bins)`, so there are `pass:c[len(bins) + 1]` possible results.

[source,python]
----
x = np.array([0.2, 6.4, 3.0, 1.6, 1.0, 4.0, 10.0, -1.0])
bins = [0.0, 1.0, 2.5, 4.0, 10.0]
print(np.digitize(x, bins))
print(np.digitize(x, bins, right=True))
----

----
[1 4 3 2 2 4 5 0]
[1 4 3 2 1 3 4 0]
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.digitize.html[numpy.digitize]

The values that sit exactly on an edge (1.0, 4.0 and 10.0) are the ones that change between the two calls, so decide
the edge convention explicitly whenever data can hit a boundary, such as ages, prices or integer counts. `np.digitize`
returns the bin of every value; `np.histogram` returns how many values fall into each bin and always treats the last
bin as closed. Counting per bin is the subject of xref:data-science/numpy/statistics.adoc[Statistics & Histograms]; pandas offers
`pd.cut` and `pd.qcut` for labelled and quantile bins.

== Top-k recipes

[source,python]
----
sc = np.array([5, 9, 9, 1, 9])
k = 2

# deterministic: ties keep their original order
print(np.argsort(sc, stable=True, descending=True)[:k])

# fast for large arrays: partition, then order only the k winners
r = np.random.default_rng(3).normal(size=100_000)
top = np.sort(np.partition(r, -5)[-5:])[::-1]
print(np.allclose(top, np.sort(r)[::-1][:5]))
----

----
[1 2]
True
----

Source: https://numpy.org/doc/stable/reference/generated/numpy.partition.html[numpy.partition]

The first form is exact and stable but sorts everything; the second does linear work plus a sort of k elements, and
it returns the values only. Use `argpartition` when positions are needed, accepting that ties at the cut-off are
resolved arbitrarily.

== Pitfalls and what changed

* **Stability is opt-in.** The default sort does not promise to keep equal elements in order. Pass `stable=True`.
* **`searchsorted` on unsorted data** silently returns nonsense; sort first or pass `sorter=`.
* **Descending sorts.** On NumPy 2.5 use `descending=True`. Reversing with `[::-1]` also reverses the order of ties,
  which breaks stability.
* **`argsort(axis=1)` indices cannot be applied with `M[idx]`.** Use `np.take_along_axis`.
* **`np.lexsort` takes the primary key last.**
* **NaN sorts last** in `sort`, `argsort`, `partition` and `searchsorted`, but wins `argmax`/`argmin`.
* **`np.partition` is not a sort.** Only position `kth` (and the split around it) is meaningful.
* **`bincount` needs small non-negative integers**; a single huge value allocates an array of that length. Use
  `+np.unique(..., return_counts=True)+` for sparse or arbitrary keys.
* **Old tutorials** use `np.sort(-a)` or `a[::-1]` for descending order and rely on the unspecified tie order of the default
  sort. Both still run, but only `descending=True` (NumPy 2.5) and `stable=True` (NumPy 2.0) say what is meant. The
  `+kind='mergesort'+` spelling is still accepted and means the same as `+'stable'+`.
