*OpenGL* is the cross-platform graphics API that taught a generation of programmers how a GPU draws. This sub-section
teaches desktop OpenGL 4.6, OpenGL ES 3.2, their shading languages GLSL 4.60 and GLSL ES 3.20, and EGL 1.5, the glue that
connects them to a window. It follows one running example, the *Bookshelf GL* program, from a single triangle to a small
game, and it says plainly where OpenGL stands in 2026: frozen at version 4.6, deprecated on Apple platforms, still
extended by Khronos and still the base of OpenGL ES on Android and embedded devices. The pages build on the general pages of
xref:graphics-games/index.adoc[Graphics & Games]; read those first if the rendering pipeline or the transformation chain are new
to you.

== What OpenGL, OpenGL ES, GLSL and EGL are

[cols="1,3",options=header]
|===
|Name |What it is

|OpenGL
|A specification, maintained by the Khronos Group, of a C API that sends buffers, textures, shaders and draw commands to the GPU. Drivers implement it; there is no library to download. Version 4.6 is the last.

|OpenGL ES
|The subset and variant for phones, tablets and embedded devices. ES 2.0 and 3.0 dominate mobile history, and ES 3.2 is the last version. WebGL is its JavaScript binding.

|GLSL and GLSL ES
|The C-like shading languages in which the programmable stages are written. A shader is passed to the driver as text (or as SPIR-V since OpenGL 4.6) and compiled at run time.

|EGL
|The Khronos API that creates displays, surfaces and contexts for OpenGL ES (and desktop OpenGL) on Android, embedded Linux and several desktop systems.
|===

OpenGL is a *state machine* with a global current context: a function call changes the state of the context that is current on
the calling thread. The pages in this sub-section keep returning to that fact, because it explains the shape of the API, its
convenience for learning and its cost compared with the explicit APIs described in
xref:graphics-games/explicit-vs-implicit-apis.adoc[Explicit vs Implicit Graphics APIs].

== The family tree

.Releases of desktop OpenGL, OpenGL ES, WebGL and the mesh shader extension, 1992 to 2026
image::graphics-games-opengl-index-family-timeline.svg["Three timelines, desktop OpenGL from 1.0 in 1992 to 4.6 in 2017, OpenGL ES from 1.0 in 2003 to 3.2 in 2015, and WebGL 1 and 2 with the 2025 mesh shader extension",width=720]

Desktop OpenGL grew from IRIS GL (see xref:graphics-games/history-of-real-time-graphics.adoc[History of Real-Time Graphics])
through a fixed-function era to the shader-based versions 2.0 and 3.x, and then through 4.0 to 4.6 added tessellation,
compute shaders, direct state access and SPIR-V. OpenGL ES forked from it for mobile hardware; ES 2.0 removed the fixed
function pipeline in 2007, years before the desktop did. WebGL 1 and 2 expose ES 2.0 and ES 3.0 to JavaScript. The details and
the mapping between versions are on xref:graphics-games/opengl/versions-profiles-and-extensions.adoc[Versions, Profiles and
Extensions].

== When to choose OpenGL in 2026

Choose OpenGL when you are learning how the pipeline works, when you maintain or extend an existing OpenGL code base, when
you target Android or embedded Linux devices where ES is the lowest common denominator, or when a small cross-platform tool
matters more than the last 20 percent of performance. Choose Vulkan, Metal or WebGPU for a new engine, for features such as
ray tracing, or for an Apple-only product. The full reasoning is in
xref:graphics-games/opengl/opengl-in-2026.adoc[OpenGL in 2026], and the general criteria are in
xref:graphics-games/choosing-an-api-or-engine.adoc[Choosing an API or Engine].

== Bookshelf GL, the running example

*Bookshelf GL* is a {cpp}20 program built with CMake, GLFW, glad2 and GLM. Its baseline is an *OpenGL 4.1 core* context, so that it
runs on macOS, with optional 4.6 paths (direct state access, SPIR-V, compute and mesh shaders). An Android variant in Kotlin
with `GLSurfaceView` uses an *OpenGL ES 3.0* context and shares the ES-compatible GLSL. It loads the shared
xref:attachment$bookshelf.glb[bookshelf.glb] and the textures described on the
xref:graphics-games/index.adoc#_the_bookshelf_scene_and_shared_assets[section landing page], and it grows page by page:

. a triangle (xref:graphics-games/opengl/hello-triangle.adoc[Hello Triangle])
. a coloured quad that becomes a book spine (xref:graphics-games/opengl/buffers-and-vertex-specification.adoc[Buffers and Vertex Specification])
. a textured, rotating book box (xref:graphics-games/opengl/textures-and-samplers.adoc[Textures and Samplers in OpenGL])
. the shelf mesh lit by a Blinn-Phong desk lamp (xref:graphics-games/opengl/lighting-blinn-phong.adoc[Lighting with Blinn-Phong in OpenGL])
. normal-mapped wood and a shadow map (xref:graphics-games/opengl/materials-and-normal-mapping.adoc[Materials and Normal Mapping in OpenGL], xref:graphics-games/opengl/shadow-mapping.adoc[Shadow Mapping])
. an instanced shelf of books (xref:graphics-games/opengl/instancing-and-indirect-drawing.adoc[Instancing and Indirect Drawing])
. picking a book with an ID buffer (xref:graphics-games/opengl/text-ui-and-input.adoc[Text, UI and Input])
. post-processing with bloom and a vignette (xref:graphics-games/opengl/framebuffers-and-render-to-texture.adoc[Framebuffers and Render to Texture])
. compute-shader dust particles (xref:graphics-games/opengl/compute-shaders.adoc[Compute Shaders in OpenGL])
. a tiny game, "catch the falling book", with an orbit camera, input, a score and timer queries (xref:graphics-games/opengl/performance.adoc[OpenGL Performance])
