include::partial$ai-disclaimer.adoc[]

Every Unity project starts in the same place: the Hub installs an Editor version, creates a project folder from a template, and opens that folder in the Editor. After that, almost all of the work happens in a handful
of windows. This page installs Unity 6.3 LTS, creates the *Bookshelf* project that the rest of the Unity section builds on, tours the windows and the folders on disk, and ends with a first script on a first book.

The facts were checked in November 2026. The version documented is Unity 6.3 LTS (6000.3, released on 4 December 2025 and supported until December 2027); where the later Unity 6.6 release or the Unity 7.0 alpha differs, the text says so.
Requirements: Windows, macOS or Linux with the Editor's published system requirements, a Unity ID, and an activated licence (see
xref:graphics-games/unity/licensing-and-pricing.adoc[Licensing and Pricing]). The Editor is not a web or mobile app: it runs on workstation or laptop form factors without emulation or compatibility layers.
The Bookshelf project is the running example: a whitebox shelf and a `Book` prefab on the Universal Render Pipeline (URP) with the Input System package, whose steps are drawn in the xref:graphics-games/unity/render-pipelines-overview.adoc[Render Pipelines Overview].
If you came here from the general xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats] page, this is where its ideas become windows and files.

== The Hub and the Editor are two programs

.From download to an open project
image::graphics-games-unity-getting-started-hub-and-editor-install-flow.svg["Five boxes in a row: install the Hub, activate a licence, install an Editor version, add modules, create a project from a template",width=720]

The *Unity Hub* is the launcher. It signs you in, activates the licence, downloads Editor versions and the optional modules that go with them, lists your projects, and starts each project with the Editor version that project was created with. The *Editor* is the program in which you
actually build the game. The two are separate on purpose: a studio keeps several Editor versions side by side (for example the 6.3 LTS of a game in production and a newer release for evaluation), and the Hub picks the right one for each project.
You can also install an Editor without the Hub, with installer files, the Download Assistant, or from the command line, but modules can only be added later through the Hub to Editors that the Hub installed.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/install-and-upgrade/getting-started-installing-unity[Install Unity]

=== Which version to install

Unity 6 has two kinds of release. A *Long Term Support (LTS)* release is supported for two years and is recommended for games that are about to lock in production; an *Update* release is supported until the next one is published, with the same quality assurance and weekly patches. Unity 6.3 LTS
is the LTS this section documents. Unity 6.0 LTS was supported through October 2026, so a new project should not start on it. By November 2026 the latest Update release is Unity 6.6, the last Supported release of the Unity 6 family, and Unity 6.7 LTS is in beta. Unity 7.0 is in a public alpha on a CoreCLR runtime foundation and is not for
production use. The practical rule: stay on one release for the length of a project, and use 6.3 LTS unless you need something only a later release has.

[cols="2,2,3"]
|===
|Release |Status in November 2026 |Use it for

|Unity 6.0 LTS (6000.0)
|supported through October 2026
|keeping an existing project alive; do not start new work on it

|Unity 6.3 LTS (6000.3)
|supported until December 2027
|new production work, and the version of every example in this section

|Unity 6.6 (6000.6)
|latest Update release
|trying newer features: WebGPU production-ready, the Build Analysis window, no domain reload by default for new projects

|Unity 6.7 LTS
|beta
|the next LTS; check its release notes before moving

|Unity 7.0
|public alpha
|experimentation only
|===

Source: https://unity.com/releases/unity-6/support[Unity 6 releases and support]

== Installing the Editor

Install the Hub from the Unity website and sign in with a Unity ID. Then install an Editor version from it.

.Procedure: install Unity 6.3 LTS
. Open the Hub.
. Select *Installs* in the left sidebar.
. Select *Install Editor* at the top right. The window has tabs for *Official releases* (the LTS releases), *Pre-releases* (alpha and beta versions) and *Archive* (older, unsupported versions).
. Choose Unity 6.3 LTS and select *Install*.
. In the modules window, select the modules you need and select *Install*. Download progress is shown in the *Downloads* panel of the Hub toolbar.

Source: https://docs.unity.com/en-us/hub/add-editor[Unity Hub: Download and install the Unity Editor]

*Modules* are optional components of an Editor installation: build support for platforms (Android, iOS, Web, Universal Windows Platform, Linux and so on), documentation, language packs and developer tools. Install only what you need, because each platform module is large.
For the Bookshelf, the desktop build support that matches your operating system is enough to start; the Android and Web modules are added later, when
xref:graphics-games/unity/build-profiles-and-platforms.adoc[Build Profiles and Platforms] and xref:graphics-games/unity/web-and-webgpu.adoc[Web and WebGPU] need them.

.Procedure: add a module to an installed Editor
. Open the Hub and select *Installs*.
. Find the Editor version and select *Manage*.
. Select *Add modules*.
. Choose the modules and select *Install*.

Source: https://docs.unity.com/en-us/hub/add-modules[Unity Hub: Add modules to a Unity Editor installation]

If *Add modules* is missing, the Editor was installed without the Hub; uninstall it and reinstall through the Hub, or install the module from the installer files.

=== Check the system requirements first

The manual lists the hardware and operating-system requirements of the Editor and of the Player for every target platform on one page. The Editor requirements and the Player requirements differ: a game can target an older Android device than the Editor supports as a host. Two
platform minimums changed recently: Unity 6.5 and 6.6 raised the Android minimum to API level 26 with OpenGL ES 3.1, and 6.6 deprecated macOS on Intel processors.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/install-and-upgrade/getting-started-installing-unity/system-requirements[System requirements for Unity 6.3]

== Creating the Bookshelf project

Projects are created from *templates*. In the Hub, templates come in three categories: *Core* (general 2D and 3D, VR, AR, MR and mobile starting points that set up the render pipeline and packages), *Sample* (pre-built scenes that demonstrate setups) and *Learning* (guided tutorials).
The Bookshelf uses a Core 3D template that selects URP; recent Hubs call it Universal 3D. The template installs URP, the Input System package and a default scene with a camera, a directional light and a global volume for post-processing.

.Procedure: create the Bookshelf project
. Open the Hub and select *Projects*, then *New project*.
. Select the Editor version, Unity 6.3 LTS.
. Choose the Core 3D template that uses URP. If the template is not downloaded yet, select *Download template* and wait for it to finish.
. Enter the project name, `Bookshelf`.
. Choose the location on disk. Keep it outside any cloud-synchronised folder.
. Optionally choose a source control provider to create a remote repository now.
. Select *Create project*. The Hub creates the project, adds it to the list and opens it in the Editor.

Source: https://docs.unity.com/en-us/hub/project-create[Unity Hub: Create a new project]

.Storyboard: from the Hub to a saved Bookshelf scene
image::graphics-games-unity-getting-started-hub-and-editor-bookshelf-storyboard.svg["Six panels: the Hub template picker, the first open Editor with SampleScene, creating folders, importing bookshelf.glb, placing the model in the Hierarchy, and saving the scene and pressing Play",width=720]

The first open takes a while: Unity imports the template's assets and compiles its scripts, and it shows a progress bar while it does. The result is a project folder that contains the
folders described below and a scene called `SampleScene`.

Storing a project in cloud-synchronised storage (a shared drive that syncs files in the background) is an unsupported workflow that can corrupt the project, because the Editor writes many small files and expects exclusive control of them. Use version control instead.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/first-time-user/create-first-project[Create your first project]

== The Editor window by window

.The default layout
image::graphics-games-unity-getting-started-hub-and-editor-editor-layout.svg["A schematic of the Editor: the main menu and toolbar on top, the Hierarchy on the left, the Scene and Game views in the middle with an orientation overlay, the Inspector on the right, and the Project and Console windows along the bottom",width=720]

The default layout is a set of dockable windows. You can drag any tab to another place, float it, or save the arrangement as a layout from the toolbar; the main windows are:

* *Hierarchy.* Lists every GameObject in the open scenes, indented by parent and child. Right-click empty space and choose a GameObject to create, or press `pass:c[Ctrl+Shift+N]` (macOS `pass:c[Cmd+Shift+N]`) for an empty one. Duplicate with `pass:c[Ctrl+D]` (macOS `pass:c[Cmd+D]`). Drag one
  object onto another to parent it, and drag it to a free position to unparent it. Several scenes can be open at once, each shown as its own group. Paste after a copy keeps the world position of a pasted child.
* *Scene view.* The editing view of the world: select, move, rotate and scale objects with the tools in the top-left corner, with the Hand tool for navigation. Gizmos show the axes of the selection (red, green and blue for X, Y and Z), lights, cameras and colliders.
* *Game view.* What the game camera sees, at the resolution you choose. It is what the player will see and where the game runs when you press Play.
* *Inspector.* Shows the components of the selected GameObject, with their properties. The name, active checkbox, tag, layer and static flags are at the top.
* *Project window.* The files under the project's `Assets` folder (and the packages), as a folder tree and an asset browser. Open it from the Window menu, General, Project, or with `pass:c[Ctrl+5]` (macOS `pass:c[Cmd+5]`).
* *Console.* Log messages, warnings and errors from the Editor and from `Debug.Log` calls in scripts. Read it after every script change: a compile error means the Editor keeps running the previous code.
* *Toolbar and overlays.* The toolbar holds the Play, Pause and Step buttons, search, the layers menu and the layouts menu. Overlays are panels inside the Scene view.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference[Unity Editor windows and views reference]

=== The Hierarchy and the new Hierarchy

Unity 6.3 introduces a different version of the Hierarchy window as a preview. It shows extra information about GameObjects and can alternate the colour of rows. You enable it from Preferences, under General, by selecting the *New Hierarchy* setting. Because it is in preview, its behaviour
may change in later versions; the classic Hierarchy remains the default.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/hierarchy-window/hierarchy-reference[Hierarchy window reference]

Icons in the Hierarchy tell the story at a glance: an outline cube marks a plain GameObject and a blue cube marks a prefab instance (see xref:graphics-games/unity/prefabs-and-scenes.adoc[Prefabs and Scenes]). Names are just labels; the order is the order of creation, which you can change by dragging.
Create new objects with a naming plan from the start. A Bookshelf with `Shelf`, `Board_1` to `Board_5` and `Book_01` and so on is easy to read, and scripts that use `Find` by name break if the label changes.

=== Overlays in the Scene view

Overlays are small panels floating over the Scene view: the Tools overlay, the View Options overlay that chooses which layers are shown, the Orientation overlay (the axis gizmo that snaps the camera to a direction when you click an arm) and
so on. Unity 6.3 made overlays more dynamic: you can collapse and expand them, change their height and size, drag them onto the toolbar, or dock them at any edge of the view.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/working-with-scenes/scenes-manage-gameobjects/overlays/reference[Overlays reference]

=== Navigating the Scene view

With the View (Hand) tool selected (shortcut `Q`), dragging pans the camera, `Alt` (macOS `Option`) plus left-drag orbits it around the pivot, and `Alt` plus right-drag zooms. The arrow keys walk the camera forward, backward and sideways, and `Shift` speeds up any of them.
*Flythrough mode* is the first-person way: hold the right mouse button, look with the mouse, and press `W`, `A`, `S` and `D` to move. Select an object and press `F` to frame it in the Scene view. Flythrough mode is meant for perspective views and is not available in 2D mode.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-windows-views-reference/using-the-scene-view/scene-view-navigation[Scene view navigation]

The camera you navigate is the *Scene Camera*, an editing camera that is not part of your scene. The camera that the player sees is a separate `Main Camera` GameObject with a Camera component and shows up in the Game view. Beginners often move one while expecting the other.

== What is on disk

.A new project folder
image::graphics-games-unity-getting-started-hub-and-editor-project-folders.svg["A folder tree of the Bookshelf project showing Assets, Packages and ProjectSettings marked as committed, and Library, Logs, Temp and UserSettings marked as generated",width=720]

A Unity project is an ordinary folder. Opening it in the Editor creates and fills several subfolders:

[cols="1,3"]
|===
|Folder |Role

|`Assets`
|everything you create or import: scripts, scenes, models, textures, materials, prefabs, audio. The template adds `InputSystem_Actions` (a default input action asset), `Scenes` (with `SampleScene`), `Settings` (the render pipeline assets chosen by the template) and `TutorialInfo`.

|`Packages`
|the project manifest (`manifest.json`) that lists the packages the project uses, and `packages-lock.json` that pins the resolved versions.

|`ProjectSettings`
|project-wide settings: Player, input, physics, tags and layers, graphics, quality.

|`Library`
|the cache of imported assets, compiled assemblies, shaders, packages and Editor state. Unity regenerates it; it can be large and is safe to delete when the project is closed.

|`Logs`, `Temp`
|log files and temporary data of the running Editor.

|`UserSettings`
|per-user preferences, such as the window state, which are not shared with a team.
|===

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/project-configuration/default-directories[Default project directories]

Some folder names inside `Assets` are reserved and have special meaning: `Editor` holds scripts that run only in the Editor and are not part of the Player build, `Resources` holds assets that can be loaded by name at runtime, `StreamingAssets` is copied as it is into the build, and `Plugins` holds native libraries.
Do not use those names for ordinary folders. The `Editor` folder rule is the reason that the editor scripts in this section sit in `Editor` folders or assembly definitions.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/project-configuration/special-folders[Reserved folder name reference]

=== The meta files

Every file and folder in `Assets` has a companion `.meta` file with the same name. It stores the asset's GUID, a unique identifier that other assets use to refer to it, and its import settings. Moving a file inside the Project window moves its `.meta` file with it, so references stay valid; moving it
outside the Editor, in a file manager, breaks the link if the `.meta` file stays behind. Always commit an asset together with its `.meta` file.

=== Version control from day one

Use version control for every project, even a solo one. The rule is to commit `Assets`, `Packages` and `ProjectSettings`, and to ignore the generated folders. Unity supports Unity Version Control, Perforce and Git; Git needs a Unity-specific ignore file and, for large binary assets, a large-file extension.
Scenes and prefabs are text files in YAML, so Unity ships a smart merge tool (`UnityYAMLMerge`) that merges them in a semantically correct way.

[source,gitignore]
----
# Bookshelf/.gitignore, the essentials of a Unity ignore file
/[Ll]ibrary/
/[Tt]emp/
/[Oo]bj/
/[Bb]uild/
/[Bb]uilds/
/[Ll]ogs/
/[Uu]ser[Ss]ettings/

# Generated IDE project files
*.csproj
*.sln
*.slnx
.vs/
.idea/

# OS files
.DS_Store
Thumbs.db
----

Source: https://docs.unity.com/en-us/engine/6000.3/manual/get-started/project-configuration/version-control[Version control]

Do not lose the `.meta` files to a blanket ignore rule: they must be tracked. Check that the project's *Asset Serialization* mode is *Force Text* and its *Version Control* mode is *Visible Meta Files*, so that scenes and prefabs are readable text and the `.meta` files exist on disk.

== Script editors

Unity does not include a code editor. In Preferences, under External Tools, choose the program that opens C# scripts. The common choices are Visual Studio on Windows (and Visual Studio Code on any system) with the Unity integration, and JetBrains Rider on all three. Visual Studio for Mac was retired by Microsoft on 31 August 2024, so on macOS use Visual
Studio Code with the Unity extension or Rider. The integration packages (`com.unity.ide.visualstudio`, `com.unity.ide.rider`) are installed by the template and generate the project files that give the editor completion and diagnostics. See xref:programming-languages/csharp/ides-and-tools.adoc[IDEs and Tools] for the C# side.

Source: https://docs.unity3d.com/Packages/com.unity.ide.visualstudio@2.0/manual/index.html[Visual Studio Editor package]

Source: https://docs.unity3d.com/Packages/com.unity.ide.rider@3.0/manual/index.html[JetBrains Rider Editor package]

== Importing the shared Bookshelf model

All pages of this section use the same original model, xref:attachment$bookshelf.glb[bookshelf.glb], a glTF 2.0 binary with a shelf of six boards, nine books that share one mesh, and PBR materials, with the PNG textures beside it in the same folder of the site. Unity's built-in importers read
FBX, OBJ, Collada and DXF files and the formats of the common modelling programs; glTF is not among them. The glTF format is read by Unity glTFast, an official package that imports and exports glTF files in the Editor and at runtime, and which is installed from the Package Manager.

.Procedure: import bookshelf.glb
. Open the Package Manager from the Window menu.
. Choose the Unity Registry list, search for `glTFast` (the package `com.unity.cloud.gltfast`) and select *Install*. The Editor installs the package and its dependencies and recompiles.
. Download xref:attachment$bookshelf.glb[bookshelf.glb] and the four textures from the site into `Assets/Bookshelf/Models`, in the Project window or in a file manager (then let the Editor refresh).
. Select the imported asset. The Inspector shows its import settings; the textures are PNG files, sRGB base colour.
. Drag the model into the Hierarchy. Reset its Transform (the three dots menu of the Transform, then Reset) so that it sits at the origin and faces the camera.
. Press `F` in the Scene view to frame it.

Source: https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.16/manual/installation.html[Unity glTFast: Installation]

Source: https://docs.unity.com/en-us/engine/6000.3/manual/packages-list/managing-packages-window[Package management with the Package Manager window]

If you prefer FBX, export the model from a modelling program such as Blender and import it the same way; Unity recommends FBX as the best-supported source format, and converts the other supported formats to it on import.

Source: https://docs.unity.com/en-us/engine/6000.3/manual/assets-and-media/asset-types/models/creating-dccassets/3d-formats[Model file formats reference]

== Setting up the folders with a script

You can create the folders by hand, but a ten-line Editor script makes the layout repeatable and also shows the first piece of the Editor's scripting API. Place the script in an `Editor` folder (for example `Assets/Bookshelf/Editor/BookshelfFolders.cs`).

[source,csharp]
----
#if UNITY_EDITOR
using System.IO;
using UnityEditor;
using UnityEngine;

namespace Bookshelf.Editor
{
    /// <summary>Creates the standard Bookshelf folder layout under Assets.</summary>
    public static class BookshelfFolders
    {
        private const string Root = "Assets/Bookshelf";

        private static readonly string[] Children =
        {
            "Art", "Materials", "Models", "Prefabs", "Scenes", "Scripts", "ScriptableObjects", "Settings"
        };

        [MenuItem("Bookshelf/Create Folder Layout")]
        public static void Create()
        {
            if (!AssetDatabase.IsValidFolder(Root))
            {
                AssetDatabase.CreateFolder("Assets", "Bookshelf");
            }

            foreach (string child in Children)
            {
                string path = $"{Root}/{child}";
                if (!AssetDatabase.IsValidFolder(path))
                {
                    string guid = AssetDatabase.CreateFolder(Root, child);
                    Debug.Log($"Created {AssetDatabase.GUIDToAssetPath(guid)}");
                }
            }

            AssetDatabase.Refresh();
        }
    }
}
#endif
----

Source: https://docs.unity.com/en-us/engine/6000.3/script-reference/unityeditor/assetdatabase/createfolder[AssetDatabase.CreateFolder]

Run it from the Bookshelf menu that appears in the main menu bar after the script compiles. The `#if UNITY_EDITOR` guard and the `Editor` folder are belt and braces: each is enough by itself to keep editor code out of a Player build.

== A first script on a first book

A script is a class that derives from `MonoBehaviour`; Unity runs its `Update` method once per frame while the object is active. The following component spins a book around its vertical axis. The next page, xref:graphics-games/unity/csharp-scripting-and-monobehaviour-lifecycle.adoc[C# Scripting and the MonoBehaviour Lifecycle], explains the full lifecycle; here
the goal is to see something move.

[source,csharp]
----
using UnityEngine;

namespace Bookshelf
{
    /// <summary>Spins the book it is attached to around the world up axis.</summary>
    [DisallowMultipleComponent]
    public sealed class BookSpinner : MonoBehaviour
    {
        [SerializeField, Tooltip("Rotation speed in degrees per second.")]
        private float degreesPerSecond = 45f;

        private void Update()
        {
            // Multiplying by deltaTime makes the speed independent of the frame rate.
            transform.Rotate(0f, degreesPerSecond * Time.deltaTime, 0f, Space.World);
        }
    }
}
----

Source: https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/transform/rotate[Transform.Rotate]

Put the file in `Assets/Bookshelf/Scripts/BookSpinner.cs`; the file name must match the class name. Drag the script onto a book in the Hierarchy (or use Add Component in the Inspector), press Play, and the book spins. Change `degreesPerSecond` in the Inspector while the game runs to see the value change at once; those changes
are lost when you stop, which is a good way to experiment. Stop Play mode before you edit anything you want to keep: changes to an object's properties in Play mode are discarded on exit.

== Saving, undo and Play mode

Save the scene with `pass:c[Ctrl+S]` (macOS `pass:c[Cmd+S]`); the Editor prompts for a location the first time. The `Edit` menu has Undo and Redo, and the Undo History window lists the actions. Unsaved scenes are marked in the Hierarchy with an asterisk. Saving the scene does not save script changes in other
windows of your code editor, and saving a script does not save the scene; they are separate files.

Play mode runs the scene in the Editor. It is a different state from edit mode: components run, physics simulates, and every change to a scene object is temporary. Since Unity 6.6 new projects use the *Reload Scene only* option by default, which enters Play mode without reloading the scripting
domain, so a static variable keeps its value between runs unless you reset it; see xref:graphics-games/unity/csharp-scripting-and-monobehaviour-lifecycle.adoc[C# Scripting and the MonoBehaviour Lifecycle].

Source: https://docs.unity.com/en-us/engine/6000.3/manual/unity-editor/editor-navigating-managing/saving[Saving]

== Common mistakes

* *Editing in Play mode and losing the work.* The Editor tints the interface while playing; make that a habit cue. Copy a component in Play mode and use "Paste Component Values" after stopping if you want to keep the result.
* *Putting a project in a cloud-synchronised folder.* The sync clients race with the Editor and can corrupt `Library` and the scene files.
* *Deleting `.meta` files, or committing an asset without its `.meta`.* All references from scenes and prefabs are GUIDs; losing the file loses the references.
* *Moving assets outside the Editor.* Move them in the Project window so the `.meta` follows.
* *Ignoring the Console.* A compile error stops every script from updating; the Editor keeps running the last good code.
* *Starting a long project on an Update release or a pre-release.* Use an LTS release for production.
* *Giving a file a different name from its `MonoBehaviour` class.* Unity cannot attach it.
* *Using the Scene Camera when you mean the Game camera.*
* *Installing every platform module.* The disk space adds up quickly, and so does the time of an update.

== Performance notes

* The first import of a project can take minutes; the `Library` folder makes later opens fast. Do not delete it casually, and exclude the project folder from real-time antivirus scanning where your policy allows.
* Keep the project on a fast local SSD. Importing and shader compilation are heavy on small random reads and writes.
* The Editor's own cost is in the Game view too: the Stats overlay and gizmos make Play mode slower than a build. Measure performance in a Player build, not in the Editor (xref:graphics-games/unity/profiling-and-optimization.adoc[Profiling and Optimization]).
* Fewer open windows means fewer repaints; close the ones you are not using when you profile.
