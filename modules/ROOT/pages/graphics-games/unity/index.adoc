= Unity
:description: Landing page for the Unity sub-section of Graphics & Games -- what Unity is and where it stands in 2026, the release model (6.3 LTS, 6.6, 6.7 LTS beta and the 7.0 alpha), the re-verified version baseline, when to choose it, a learning path, the Bookshelf running example with its design summary, every page grouped by topic and a coverage map of the official documentation and of two books.
:keywords: Unity, Unity 6, Unity 6.3 LTS, Unity 6.6, Unity 6.7 LTS, Unity 7, Unity Hub, URP, HDRP, Built-in Render Pipeline, Render Graph, Input System, UI Toolkit, DOTS, Addressables, Netcode, Build Profiles, WebGPU, IL2CPP, learning path, Bookshelf, coverage map, bibliography

include::partial$ai-disclaimer.adoc[]

*Unity* is a general-purpose game engine with an Editor for building scenes, a C# scripting layer on top of a {cpp} runtime, a choice of render pipelines and one-click builds for desktop, mobile, consoles, the Web and XR headsets. It is
what a team reaches for when the scene, the physics, the animation and the tools matter more than controlling the GPU directly. This sub-section teaches Unity 6.3 LTS with the Universal Render Pipeline (URP) and the Input
System package. It covers the Editor, the scripting model, physics, graphics, animation, UI, content, the Data-Oriented Technology Stack (DOTS), multiplayer, platforms, profiling and testing, and it marks what changed in the later releases up to
Unity 6.6. It follows one running example, the *Bookshelf*, from a whitebox shelf to a small game called "Shelve-it", and it says plainly where Unity stands in 2026: a yearly LTS with a stream of Supported releases in between, one
render pipeline as the clear investment, a pricing model settled after the Runtime Fee was cancelled, and a runtime moving towards CoreCLR. The pages build on the general pages of
xref:graphics-games/index.adoc[Graphics & Games]; read those first if the rendering pipeline or the transformation chain are new to you.

[discrete]
=== What Unity and its neighbours are

[cols="1,3",options=header]
|===
|Name |What it is

|Unity Hub
|The launcher that installs Editor versions and their platform modules, and creates and opens projects.

|Unity Editor
|The application where scenes, prefabs and assets are assembled, and where the game runs in Play mode.

|Player
|What a build produces: the game without the Editor, for one platform.

|Packages
|Versioned features added through the Package Manager, such as the Input System, Cinemachine, Addressables or Entities.

|URP, HDRP and Built-in
|The render pipelines. URP is the main investment, HDRP is in maintenance and the Built-in Render Pipeline is deprecated.

|Mono and IL2CPP
|The two scripting back ends. Mono runs compiled C# in a virtual machine; IL2CPP converts it to {cpp} and compiles it ahead of time.

|DOTS
|The data-oriented stack of Entities, the C# Job System and the Burst compiler, an alternative to GameObjects for large numbers of objects.

|OpenGL, Vulkan, Metal and WebGPU
|The graphics APIs underneath. Unity selects one for each platform; xref:graphics-games/opengl/index.adoc[OpenGL], xref:graphics-games/vulkan/index.adoc[Vulkan], xref:graphics-games/metal/index.adoc[Metal] and xref:graphics-games/webgl/index.adoc[WebGL] teach them directly.
|===

=== Where Unity sits

.The layers between your Unity project and the GPU
image::graphics-games-unity-index-engine-stack.svg["Six stacked layers from your project, through the Unity Editor and packages, the engine and scripting runtime, the render pipeline and the graphics API, to the GPU, with notes saying which layers you write, which Unity provides and that the render pipeline picks the API for each platform",width=720]

A Unity project is data plus C#. You write scripts and assemble scenes; Unity runs them on the same engine under every plan. The render pipeline turns the scene into draw calls for the graphics API of the platform, which is why
the same project can build for Direct3D 12, Vulkan, Metal or WebGPU. The figure is also a map of this sub-section: the first groups of pages are about the top layers, and the graphics pages reach down to the render pipeline, where
xref:graphics-games/unity/render-graph-and-custom-passes.adoc[Render Graph and Custom Passes] is as close to the API as Unity lets you go without a native plug-in.

.What a Unity project is made of
image::graphics-games-unity-index-project-anatomy.svg["A Bookshelf project containing a scene with a Book GameObject and its components, an Assets folder with prefabs, data assets, materials, scripts, input actions and the shelf model, the Packages and ProjectSettings folders, and Build Profiles that produce a Player for each target",width=720]

The vocabulary of the figure is used on every page: a *scene* holds *GameObjects*, a GameObject is a list of *components*, and an *asset* is a file under `Assets` with a `.meta` file that holds its GUID. The tour of the windows and
of the folders on disk is in xref:graphics-games/unity/getting-started-hub-and-editor.adoc[Getting Started: Hub and Editor].

=== The release model

.Unity releases, October 2024 to the end of 2027
image::graphics-games-unity-index-release-timeline.svg["Timeline with lanes for LTS, Supported and pre-release versions: Unity 6.0 LTS supported through October 2026, Unity 6.3 LTS supported until December 2027, Unity 6.4, 6.5 and 6.6 in March, June and September 2026, Unity 6.7 LTS in beta and Unity 7.0 in public alpha, with November 2026 marked",width=720]

Unity publishes two kinds of release. A *Long Term Support (LTS)* release comes once a year and is supported for two years, with a third year for Enterprise and Industry customers; Unity recommends it for live games and for teams about
to lock production. A *Supported* release, also called an Update release, comes several times a year, has the same quality assurance and weekly patches, and is supported only until the next one ships. Alpha and beta versions are open to
anyone through the Hub and are not meant for production.

Unity 6.3 LTS is the version documented here. Unity 6.6 (announced on 1 September 2026) is the final Supported release of the Unity 6 family, Unity 6.7 LTS is in beta and due at the end of the year, and Unity 7.0 has been in public alpha since
5 October 2026, with the move to CoreCLR arriving step by step during its alpha and beta. A new project should use 6.3 LTS unless it needs something only a later release has. Where a page depends on a later release, it says so.

=== When to choose what

[mermaid]
....
flowchart TD
    A[Build a real-time 3D or 2D product] --> B{Own renderer or to learn the GPU?}
    B -- yes --> C[Vulkan, Metal, OpenGL or WebGPU]
    B -- no --> D{High-end visuals on PC and console as the first goal?}
    D -- yes --> E[Unreal Engine]
    D -- no --> F{Scripting in C#, mobile, Web or XR reach?}
    F -- yes --> G[Unity 6.3 LTS with URP]
    F -- no --> H{Browser only, small scene?}
    H -- yes --> I[three.js]
    H -- no --> G
....

Choose *Unity* when a small or medium team needs to ship on many platforms, when the game is 2D, mobile, Web or XR, or when C# and the Asset Store matter. Choose *URP* for any new Unity project. Choose *HDRP* only for a project that already
depends on it, because it is in maintenance. Choose an existing LTS for a game that is about to lock production, and a Supported release only when you need one of its features and can follow the next one. The general criteria are in
xref:graphics-games/choosing-an-api-or-engine.adoc[Choosing an API or Engine], and what a plan costs is in xref:graphics-games/unity/licensing-and-pricing.adoc[Licensing and Pricing].

== Running example

The Bookshelf runs on Unity 6.3 LTS with the URP 3D template and the Input System. It imports the shared xref:attachment$bookshelf.glb[bookshelf.glb] model used by every sub-section of
xref:graphics-games/index.adoc[Graphics & Games], so that the same shelf can be compared across APIs and engines.

.The ten stages from a whitebox shelf to every platform
image::graphics-games-unity-index-running-example.svg["Ten stages in two rows: a whitebox shelf with a Book prefab, BookData assets, controls, physics, light and look, the Shelve-it game, HUD and sound, content and saves, scale and finally co-op, Web and Quest builds",width=720]

. a whitebox shelf and a `Book` prefab rotated by a `BookSpinner` script (xref:graphics-games/unity/getting-started-hub-and-editor.adoc[Getting Started: Hub and Editor] and xref:graphics-games/unity/prefabs-and-scenes.adoc[Prefabs and Scenes])
. `BookData` assets that drive prefab variants (xref:graphics-games/unity/scriptableobjects-and-data-driven-design.adoc[ScriptableObjects and Data-Driven Design])
. Input System actions to select, rotate and pull out a book, with an orbit camera (xref:graphics-games/unity/input-system.adoc[Input System] and xref:graphics-games/unity/cameras-and-cinemachine.adoc[Cameras and Cinemachine])
. toppling books, a trigger "return slot" and raycast picking (xref:graphics-games/unity/physics-3d.adoc[3D Physics])
. a baked shelf, a real-time desk lamp, Adaptive Probe Volumes, a hover glow, dust, a sparkle and an outline pass (xref:graphics-games/unity/materials-textures-and-lighting.adoc[Materials, Textures and Lighting], xref:graphics-games/unity/shader-graph-and-hlsl.adoc[Shader Graph and HLSL], xref:graphics-games/unity/particles-and-vfx-graph.adoc[Particles and VFX Graph] and xref:graphics-games/unity/render-graph-and-custom-passes.adoc[Render Graph and Custom Passes])
. the game "Shelve-it", with State for the game flow, Command for undo and replay, Object Pool for the books and event channels for the HUD (xref:graphics-games/unity/project-architecture-and-design-patterns.adoc[Project Architecture and Design Patterns])
. a UI Toolkit HUD and menu and a crossfading audio Mixer (xref:graphics-games/unity/ui-toolkit.adoc[UI Toolkit] and xref:graphics-games/unity/audio.adoc[Audio])
. Addressables cover art, JSON saves and tests (xref:graphics-games/unity/assets-addressables-and-content.adoc[Assets, Addressables and Content], xref:graphics-games/unity/saving-loading-and-networking-http.adoc[Saving, Loading and HTTP Networking] and xref:graphics-games/unity/testing-and-ci.adoc[Testing and CI])

. a co-op version and builds for the Web and for Quest (xref:graphics-games/unity/multiplayer-and-netcode.adoc[Multiplayer and Netcode], xref:graphics-games/unity/web-and-webgpu.adoc[Web and WebGPU] and xref:graphics-games/unity/xr-development.adoc[XR Development])

=== The Bookshelf design summary

A game design document records what a game is before anyone builds it. For a project of this size one table is enough, and it is the starting point of every later decision.

[cols="1,4",options=header]
|===
|Topic |Decision

|Concept
|"Shelve-it": books fall towards a shelf, and the player catches them and returns each one to its slot.

|Player and controls
|A librarian moves along the shelf with *Move*, takes a book with *Grab* and pauses with *Pause*, on keyboard, gamepad and touch.

|Rules
|A shelved book scores 10 points, with a bonus for every third book in a row, and a book that hits the floor costs 5 points. Shelving can be undone.

|Game flow
|A menu, then a round that is playing, paused or over, handled by a state machine.

|Look and sound
|The shared shelf model, a warm reading-room lighting set-up and music that crossfades through an audio Mixer.

|Target
|Desktop first, then the Web and a Quest headset. A session lasts a few minutes.

|Out of scope
|Accounts, in-app purchases and a level editor.
|===
