= What Has Changed Since the Older Unity Guides
:description: Row-by-row corrections for the two Unity books this sub-section was checked against (Unity in Action and Game Development Patterns with Unity 2021), with what each says, what is current in 2026, the Unity release or date of the change and the page to read, plus a procedure for moving an older project to Unity 6.3 LTS.
:keywords: outdated Unity tutorials, Unity in Action, Game Development Patterns with Unity, Input.GetAxis, Rigidbody.velocity, linearVelocity, OnGUI, Built-in Render Pipeline, Build Profiles, WebGPU, PVRTC, BinaryFormatter, FindObjectOfType, FindAnyObjectByType, domain reload, Runtime Fee, migration

The ideas in the two older Unity books are still sound: GameObjects composed of components, the Transform hierarchy, the MonoBehaviour lifecycle, prefabs, colliders and raycasts, Mecanim, and the design patterns that keep a game
maintainable. What has changed is much of what is typed and clicked: the input calls, some physics property names, the HUD code, the shaders and the render pipeline, the lighting workflow, the build window, the Web target and the plans.
_Unity in Action_ targets Unity 2020.3 LTS with the Built-in Render Pipeline and the legacy Input Manager, and _Game Development Patterns with Unity 2021_ targets Unity 2021.1 and later; this sub-section documents Unity 6.3 LTS (6000.3) and
marks what changed up to Unity 6.6. This page lists, book by book, the statements that are out of date and what to do today, so that you can keep reading the books for their explanations and use the pages of this sub-section for
current code. The facts were checked on 5 November 2026 against the Unity Manual, the what's-new pages of each release and Unity's support and pricing pages. For the changes that affect all graphics libraries, not only Unity, see
xref:graphics-games/whats-changed-since-older-guides.adoc[What Has Changed Since the Older Guides].

The books have the short names used in the tables: UIA (Joseph Hocking, _Unity in Action_, 3rd edition, Manning, 2022) and GDP (David Baron, _Game Development Patterns with Unity 2021_, 2nd edition, Packt, 2021). Chapter numbers are those of
the books. Both are listed in the xref:graphics-games/index.adoc#_bibliography[section bibliography].

The left column is the style of both books; the right column is what the pages of this sub-section use. Part of the left column still compiles, which is why older code does not always fail on the first line: the cost of staying on it is
warnings, missing features and, in the newest releases, compilation errors.

== From Unity 2020.3 to Unity 6.6

.What changed at each step from Unity 2020.3 to Unity 6.6
image::graphics-games-unity-whats-changed-version-ladder.svg["Seven steps from Unity 2020.3 LTS and 2021.1, the versions of the books, through 6.0 with Build Profiles and the Web platform, 6.3 LTS with the GPU lightmapper, 6.4 removing Compatibility Mode and PVRTC, 6.5 deprecating Built-in, to 6.6 with WebGPU and no domain reload for new projects",width=720]

Unity also changed its version numbers on the way: the releases named after years (2020.3, 2021.3, 2022.3) were followed by Unity 6, internally 6000.0, and tutorials from the 2023 releases are closer to Unity 6 than to the books. A
tutorial's version is the first thing to check, because the same menu path can mean something different on each side of Unity 6.

== The corrections, book by book

=== Both books

[cols="1,3,3,1,2",options=header]
|===
|Chapters |What the books say |What is current |Release or date |Read more

|UIA 3 and 7, GDP 4 to 7
|Runtime HUDs and test buttons are drawn in `OnGUI` with IMGUI.
|Use UI Toolkit for runtime UI, or uGUI where a project already uses it. IMGUI remains useful for quick debug overlays.
|UI Toolkit recommended in Unity 6
|xref:graphics-games/unity/ui-toolkit.adoc[UI Toolkit], xref:graphics-games/unity/ugui-and-textmeshpro.adoc[uGUI and TextMeshPro]

|GDP 4, UIA 9
|Static singletons and managers can rely on static fields being cleared when Play mode starts.
|Since 6.6 new projects default to Reload Scene only, so a static keeps its value between runs. Reset statics with `RuntimeInitializeOnLoadMethod`. Unity recommends keeping domain reload off to prepare for its removal in a future version.
|Unity 6.6
|xref:graphics-games/unity/csharp-scripting-and-monobehaviour-lifecycle.adoc[C# Scripting and the MonoBehaviour Lifecycle], xref:graphics-games/unity/project-architecture-and-design-patterns.adoc[Project Architecture and Design Patterns]

|Both books
|Neither book mentions Render Graph or `EntityId`, and older samples use accessors such as `GameObject.rigidbody`.
|Custom passes in URP use Render Graph. Identifiers use the 64-bit `EntityId`. The old accessors are removed: use `+GetComponent<T>()+`.
|Unity 6.4 and 6.5
|xref:graphics-games/unity/render-graph-and-custom-passes.adoc[Render Graph and Custom Passes], xref:graphics-games/unity/gameobjects-components-and-transforms.adoc[GameObjects, Components and Transforms]
|===

== Moving an older project

.Storyboard: moving a 2020-era project to Unity 6.3 LTS
image::graphics-games-unity-whats-changed-upgrade-storyboard.svg["Six panels: commit a backup to Git, open the project in Unity 6.3 LTS from the Hub and accept the API Updater, convert to URP with the Render Pipeline Converter and re-bake lighting, install the Input System and set Active Input Handling to Both, replace OnGUI and BinaryFormatter, and create Build Profiles and test on each device",width=720]

.Procedure: move a project from Unity 2020 or 2021 to Unity 6.3 LTS
. Commit the project to version control, so that you can always go back. Leave the `Library` folder out.
. In the Hub, add the project and open it with Unity 6.3 LTS. Accept the API Updater, which rewrites calls it can translate, then fix the remaining console errors.
. Move the project to URP with the Render Pipeline Converter (xref:graphics-games/unity/render-pipelines-overview.adoc[Render Pipelines Overview]), then generate the lighting again (xref:graphics-games/unity/materials-textures-and-lighting.adoc[Materials, Textures and Lighting]).
. Install the Input System and set Active Input Handling to Both while you port one script at a time (xref:graphics-games/unity/input-system.adoc[Input System]).
. Replace `OnGUI` HUDs with UI Toolkit and `BinaryFormatter` saves with JSON (xref:graphics-games/unity/ui-toolkit.adoc[UI Toolkit] and xref:graphics-games/unity/saving-loading-and-networking-http.adoc[Saving, Loading and HTTP Networking]).
. Create a Build Profile for each target, check the texture formats, test on the devices and profile again (xref:graphics-games/unity/build-profiles-and-platforms.adoc[Build Profiles and Platforms] and xref:graphics-games/unity/profiling-and-optimization.adoc[Profiling and Optimization]).

Move in one step to the LTS rather than through each release between: the API Updater handles the old calls, and every intermediate version would cost a test pass of its own.

== What is still correct in the books

.What to keep from the books and what to replace
image::graphics-games-unity-whats-changed-keep-and-replace.svg["Two columns, the ideas to keep such as composition, transforms, the lifecycle, prefabs, Mecanim, the design patterns and pooling, and what to replace such as the input calls, Built-in shaders and setup, IMGUI HUDs, Build Settings, PVRTC, BinaryFormatter, statics that rely on a domain reload, and plan and IDE advice",width=720]

* The explanations of composition, the Transform hierarchy, execution order, coroutines, prefabs, colliders, triggers, raycasts, sprites, Mecanim and audio remain correct. Only some of the names around them have changed.
* The GDP catalogue of patterns does not depend on a Unity version: the reasons for State, Command, Observer, Object Pool, Strategy and the others apply as before.
* The structure of the UIA projects (block out a level, add a player, add behaviour, then polish and build) is the structure of the Bookshelf in the xref:graphics-games/unity/index.adoc[Unity] sub-section.
* Where a book and the Unity Manual disagree, follow the Manual for the version you use.
