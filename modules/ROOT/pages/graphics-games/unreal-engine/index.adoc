:description: Landing page for the Unreal Engine sub-section of Graphics & Games -- what Unreal Engine is and where it stands in 2026, the release model and the announced UE6 target, the re-verified version baseline for UE 5.8 and hotfix 5.8.4, when to choose it, a learning path, the Bookshelf running example, every page grouped by topic and a coverage map of the official documentation and of six books.

*Unreal Engine* is Epic Games' real-time 3D engine: an editor for building levels and assets, a {cpp} runtime, the Blueprints visual scripting language, and a renderer built around Nanite, Lumen and MegaLights, with builds for desktop, mobile, consoles and XR headsets. It is what a team reaches for when high-end visuals, large worlds and a complete set of tools matter more than a small footprint. This sub-section teaches Unreal Engine 5.8 with {cpp} base classes and Blueprint subclasses. It covers the editor, the object model, the gameplay framework, input, rendering, animation, physics, worlds, UI, AI, networking, packaging, profiling and testing. It follows one running example, the *Bookshelf*, from a single book actor to a co-op library packaged for Windows and Android, and it says plainly where Unreal stands in 2026: 5.8 is the current release, UE6 is announced with Early Access targeted for the end of 2027, and the licence charges nothing until a product earns more than US$1M. The pages build on the general pages of xref:graphics-games/index.adoc[Graphics & Games]; read those first if the rendering pipeline or the transformation chain are new to you.

=== What Unreal Engine and its neighbours are

[cols="1,3",options=header]
|===
|Name |What it is

|Epic Games Launcher
|The desktop application that installs binary versions of the engine on Windows and macOS.

|Unreal Editor
|The application where levels, Blueprints, materials and other assets are assembled, and where the game runs with Play In Editor.

|Unreal Build Tool and Unreal Automation Tool
|UBT compiles the modules of a project. UAT drives longer jobs such as cooking and packaging, and the Unreal Header Tool generates the reflection code that the macros ask for.

|Blueprints
|The visual scripting language. A Blueprint class can extend a {cpp} class, which is how the Bookshelf is built.

|Fab
|Epic's marketplace for assets and plugins.

|Unreal Editor for Fortnite and Verse
|UEFN is a separate editor for experiences that run inside Fortnite, and Verse is its programming language. Both are context for UE 5.8 and central to the announced UE6.

|Direct3D 12, Vulkan, Metal and OpenGL ES
|The graphics APIs underneath, reached through Unreal's Render Hardware Interface (RHI). xref:graphics-games/vulkan/index.adoc[Vulkan], xref:graphics-games/metal/index.adoc[Metal] and xref:graphics-games/opengl/index.adoc[OpenGL] teach them directly.
|===

=== Where Unreal Engine sits

.The layers between your Unreal project and the GPU
image::graphics-games-unreal-engine-index-engine-stack.svg["Six stacked layers from your project, through the gameplay framework and systems, the engine runtime, the renderer and the RHI with its graphics APIs, to the GPU, with notes saying which layers you write, that Epic provides the engine as a binary or as source code, and that the RHI hides the API",width=720]

An Unreal project is modules of {cpp}, Blueprints and content. You write gameplay on top of the framework classes, and the engine runs it in the same way on every platform. The renderer draws the scene through the RHI, which is why the same project can build for Direct3D 12, Vulkan or Metal. The figure is also a map of this sub-section: the first groups of pages are about the top layers, and xref:graphics-games/unreal-engine/rendering-overview.adoc[Rendering Overview] reaches down to the renderer and the RHI. Because the source of the whole engine is available, every layer below your project can be read, and with a source build it can be changed.

.What an Unreal project is made of
image::graphics-games-unreal-engine-index-project-anatomy.svg["A Bookshelf project with its uproject file, a Source folder with the Bookshelf C++ module and its Build.cs and Target.cs files, a Content folder with levels, Blueprints, materials, Input Actions, widgets and the shelf model, Config and Plugins folders, and generated folders that stay out of Git",width=720]

The vocabulary of the figure is used on every page: a *level* holds *actors*, an actor is made of *components*, an *asset* is a `.uasset` file under `Content`, and a *module* is a unit of {cpp} code with its own `Build.cs`. The folders in detail are on xref:graphics-games/unreal-engine/project-structure-and-modules.adoc[Project Structure and Modules], and the windows of the editor on xref:graphics-games/unreal-engine/editor-tour.adoc[Editor Tour].

=== The release model

.Unreal Engine 5 releases and the UE6 target
image::graphics-games-unreal-engine-index-release-timeline.svg["Timeline from 2022 to 2028 with the minor versions 5.0 to 5.8, the 5.8 hotfix stream up to 5.8.4 on 20 October 2026, a marker at November 2026 and Epic's target of Early Access for UE6 at the end of 2027",width=720]

Epic ships a minor version a few times a year, each with its own release notes, and in between it publishes hotfixes for the latest minor version (5.8.1, 5.8.2 and so on). There is no long-term support version: a project chooses a minor version, takes its hotfixes and moves to a newer one when it has a reason to. Each feature carries a stability label in the release notes: *Production Ready*, *Beta* or *Experimental*. A new project should start on the latest minor version with its latest hotfix. Epic has announced UE6 and targets Early Access for the end of 2027, and xref:graphics-games/unreal-engine/verse-uefn-and-ue6-context.adoc[Verse, UEFN and UE6 Context] explains what that means for a project started today.

=== When to choose what

[mermaid]
....
flowchart TD
    A[Build a real-time 3D or 2D product] --> B{Own renderer or to learn the GPU?}
    B -- yes --> C[Vulkan, Metal, OpenGL or WebGPU]
    B -- no --> D{High-end visuals, large worlds, PC and console first?}
    D -- yes --> E[Unreal Engine 5.8]
    D -- no --> F{Scripting in C#, mobile, Web or XR reach first?}
    F -- yes --> G[Unity]
    F -- no --> H{Browser only, small scene?}
    H -- yes --> I[three.js]
    H -- no --> E
....

Choose *Unreal Engine* when the visuals, the size of the world or the built-in systems matter most: Nanite, Lumen, the gameplay framework, replication and the animation tools are all there from the first day, with the source to read. It asks for more in return: strong hardware for development, large downloads, and {cpp} for anything Blueprints cannot do. There is no Web target. Choose *Blueprints only* for prototypes and for designers' logic, and *{cpp} with Blueprint subclasses* for anything that will grow; xref:graphics-games/unreal-engine/cpp-and-blueprints-together.adoc[{cpp} and Blueprints Together] explains the split. The general criteria are in xref:graphics-games/choosing-an-api-or-engine.adoc[Choosing an API or Engine], and what a shipped game costs is in xref:graphics-games/unreal-engine/versions-licensing-and-history.adoc[Versions, Licensing and History].

== Running example

The Bookshelf runs on UE 5.8 from the Third Person template, with a {cpp} module named `Bookshelf`, {cpp} base classes and Blueprint subclasses. It imports the shared xref:attachment$bookshelf.glb[bookshelf.glb] model used by every sub-section of xref:graphics-games/index.adoc[Graphics & Games], so that the same shelf can be compared across APIs and engines. Each code example shows the header and source pair, with the Blueprint equivalent where it helps.

.The twelve stages from a book actor to a packaged co-op library
image::graphics-games-unreal-engine-index-running-example.svg["Twelve stages in two rows: book and shelf actors, Lumen light and a desk lamp, Grab and Read input, score in the GameMode and GameState, a HUD, Niagara dust, Chaos falling books, a librarian NPC, a Speed-read ability, co-op, a World Partition library level, and Win64 and Android builds",width=720]

. `ABookActor` and `AShelfActor`, a static-mesh book with a material instance and a socketed row of books, built from the shared model (xref:graphics-games/unreal-engine/actors-and-components.adoc[Actors and Components], xref:graphics-games/unreal-engine/cpp-and-blueprints-together.adoc[{cpp} and Blueprints Together] and xref:graphics-games/unreal-engine/materials-and-material-editor.adoc[Materials and the Material Editor])
. Lumen lighting with a MegaLights desk lamp (xref:graphics-games/unreal-engine/lighting-lumen-and-megalights.adoc[Lighting, Lumen and MegaLights])
. a "Grab/Read" action (xref:graphics-games/unreal-engine/enhanced-input.adoc[Enhanced Input])
. `ABookshelfGameMode` and a score in the GameState (xref:graphics-games/unreal-engine/gameplay-framework.adoc[Gameplay Framework])
. a HUD with the book title (xref:graphics-games/unreal-engine/umg-slate-and-commonui.adoc[UMG, Slate and CommonUI])
. dust when a book is pulled (xref:graphics-games/unreal-engine/niagara-vfx.adoc[Niagara VFX])
. books that can fall (xref:graphics-games/unreal-engine/chaos-physics-and-collision.adoc[Chaos Physics and Collision])
. a "librarian" NPC that re-shelves books (xref:graphics-games/unreal-engine/ai-navigation-and-perception.adoc[AI, Navigation and Perception] and xref:graphics-games/unreal-engine/behavior-trees-and-statetree.adoc[Behavior Trees and StateTree])
. a "Speed-read" ability (xref:graphics-games/unreal-engine/gameplay-ability-system.adoc[Gameplay Ability System])
. two-player co-op with replicated book state (xref:graphics-games/unreal-engine/networking-and-replication.adoc[Networking and Replication])
