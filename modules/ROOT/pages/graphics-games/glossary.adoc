= Glossary
:description: Definitions of the terms used across the Graphics & Games section, in alphabetical order, each linking to the page that explains the concept.
:keywords: graphics glossary, rendering terms, shader, mipmap, tone mapping, quaternion, glTF, ECS, OpenXR, SPIR-V, game engine terminology

include::partial$graphics-games-disclaimer.adoc[]

This glossary lists 139 terms used by the general pages of the Graphics & Games section. Each entry gives a short definition and links to the page that explains the concept in depth. Terms are sorted alphabetically.

[cols="2,5,3",options=header]
|===
|Term |Meaning |Explained on

|*6DoF*
|Six degrees of freedom: three of position and three of orientation.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*Acceleration structure*
|A GPU-built tree of geometry, usually a BVH, that ray tracing traverses to find the nearest hit quickly.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Accessor*
|A glTF object that describes how to read typed values (component type, count, offset) out of a buffer view.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Accumulator*
|The leftover simulation time carried between frames in a fixed-timestep loop.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Alpha blending*
|Combining a new fragment with the colour already in the target using the fragment alpha as a weight.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Alpha to coverage*
|Turning a fragment alpha into a multisample coverage mask so cut-outs such as leaves anti-alias.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Ambient occlusion*
|An approximation of how much ambient light reaches a point, darkening creases and contact areas.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Anchor*
|A pose that an AR system keeps fixed to the real world while its tracking estimate improves.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*ANGLE*
|A library that implements OpenGL ES (and EGL) on top of Direct3D, Vulkan, Metal and OpenGL.
|xref:graphics-games/cross-platform-translation-layers.adoc[Cross-Platform Translation Layers]

|*Anisotropic filtering*
|Texture filtering that takes more samples along the direction of a stretched pixel footprint to keep oblique surfaces sharp.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Archetype*
|In an ECS, the set of component types an entity has; entities of one archetype are stored together.
|xref:graphics-games/entity-component-system.adoc[Entity Component System]

|*Axis-angle*
|A rotation described by a unit axis and an angle around it.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*Back-face culling*
|Discarding triangles whose winding shows their back to the camera.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Bind group*
|The WebGPU object that groups the buffers, textures and samplers a pipeline reads.
|xref:graphics-games/explicit-vs-implicit-apis.adoc[Explicit vs Implicit Graphics APIs]

|*Blinn-Phong*
|A specular model that uses the half vector between light and view directions.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Bloom*
|A post-process that blurs bright areas and adds them back so highlights glow.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*BRDF*
|The bidirectional reflectance distribution function: how much light a surface reflects from one direction to another.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Broad phase*
|The collision stage that quickly rules out pairs of objects that cannot touch.
|xref:graphics-games/physics-audio-and-input-basics.adoc[Physics, Audio and Input Basics]

|*BVH*
|Bounding volume hierarchy: a tree of nested bounding boxes used to accelerate ray queries and culling.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Cascaded shadow maps*
|Several shadow maps for consecutive slices of the view frustum, trading resolution against distance.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Choreographer*
|The Android API that delivers a callback in step with the display refresh.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Clip space*
|The 4D space that vertex shaders output to, before the perspective divide.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*Clipping*
|Removing or cutting the parts of primitives that lie outside the view volume.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Collider*
|A simple shape attached to an object that the physics engine uses to detect contact.
|xref:graphics-games/physics-audio-and-input-basics.adoc[Physics, Audio and Input Basics]

|*Command buffer*
|A recorded list of GPU commands that is submitted to a queue for execution.
|xref:graphics-games/gpu-architecture-basics.adoc[GPU Architecture Basics]

|*Compute shader*
|A shader that runs outside the graphics pipeline, as general parallel work over a grid of threads.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Cube map*
|A texture with six square faces addressed by a direction vector.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Culling*
|Skipping objects or primitives that cannot contribute to the image, for example outside the view frustum.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Deferred shading*
|Rendering surface attributes to a G-buffer first and lighting them in a later pass.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Delta time*
|The time elapsed since the previous frame, used to scale movement.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Depth bias*
|A small offset applied to shadow-map depth comparisons to avoid self-shadowing.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Depth buffer*
|A per-pixel record of the nearest surface, used by the depth test to resolve visibility.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Descriptor set*
|The Vulkan object that binds resources to a pipeline layout.
|xref:graphics-games/explicit-vs-implicit-apis.adoc[Explicit vs Implicit Graphics APIs]

|*Display P3*
|A wide-gamut RGB colour space used by Apple devices and many HDR displays.
|xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Color Spaces, HDR and Tone Mapping]

|*Draco*
|A geometry compression format used by the glTF extension `+KHR_draco_mesh_compression+`.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Draw call*
|One command that asks the GPU to render a set of vertices with the current state.
|xref:graphics-games/performance-and-profiling.adoc[Performance and Profiling]

|*Draw-call batching*
|Merging draw calls that share state to reduce CPU cost.
|xref:graphics-games/performance-and-profiling.adoc[Performance and Profiling]

|*Early-Z*
|A hardware optimisation that rejects fragments by depth before running the fragment shader.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*ECS*
|Entity component system: an architecture that stores data as components processed by systems.
|xref:graphics-games/entity-component-system.adoc[Entity Component System]

|*Entity*
|In an ECS, an identifier that groups components and carries no data of its own.
|xref:graphics-games/entity-component-system.adoc[Entity Component System]

|*Euler angles*
|A rotation described by three successive angles about coordinate axes.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*Fixed timestep*
|A simulation that always advances by the same step, independent of the frame rate.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Forward+ shading*
|Forward shading with a per-tile list of lights so many lights can be shaded cheaply.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Fragment*
|A candidate pixel produced by rasterisation, before the per-fragment tests decide whether it is written.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Fragment shader*
|The program that computes the colour of each fragment; called a pixel shader in Direct3D.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Frame pacing*
|Delivering frames to the display at even intervals.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Frame time*
|The duration of one frame, the unit used for budgeting instead of frames per second.
|xref:graphics-games/performance-and-profiling.adoc[Performance and Profiling]

|*Frames in flight*
|Frames the CPU has recorded while the GPU is still working on earlier ones.
|xref:graphics-games/explicit-vs-implicit-apis.adoc[Explicit vs Implicit Graphics APIs]

|*Fresnel*
|The increase in reflectivity at grazing angles, approximated in real time by the Schlick formula.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Frustum*
|The truncated pyramid of space that a perspective camera sees.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*FXAA*
|Fast approximate anti-aliasing: an edge-smoothing post-process on the final image.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*G-buffer*
|The set of render targets that hold surface attributes in deferred shading.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Game engine*
|A framework that adds an editor, asset pipeline, physics, audio, scripting and packaging above a graphics API.
|xref:graphics-games/graphics-apis-vs-game-engines.adoc[Graphics APIs vs Game Engines]

|*Gaussian splatting*
|A scene representation made of many oriented, soft 3D Gaussians rendered by splatting.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Geometry shader*
|An optional stage that can emit new primitives; usually avoided for performance.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Gimbal lock*
|The loss of one degree of freedom when two Euler rotation axes line up.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*GLB*
|The single-file binary container form of glTF.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*glTF*
|The Khronos transmission format for 3D scenes (version 2.0), also standardised as ISO/IEC 12113.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Gouraud shading*
|Lighting computed per vertex and interpolated across the triangle.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*GPU timer*
|A query that measures how long the GPU spent on a range of commands.
|xref:graphics-games/performance-and-profiling.adoc[Performance and Profiling]

|*Handedness*
|Whether the coordinate axes follow the right-hand or left-hand rule.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*HDR*
|High dynamic range: image data and displays that go beyond the 0 to 1 range of standard output.
|xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Color Spaces, HDR and Tone Mapping]

|*Hit test*
|A ray cast from the screen into the tracked world that returns planes or feature points.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*HLSL*
|The High-Level Shading Language of Direct3D.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*Homogeneous coordinates*
|Coordinates with an extra component w that lets one matrix express translation and projection.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*Image-based lighting*
|Lighting a surface from an environment image such as a cube map.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Immediate mode*
|An API in which the application issues drawing commands every frame.
|xref:graphics-games/graphics-apis-vs-game-engines.adoc[Graphics APIs vs Game Engines]

|*Index buffer*
|A buffer of integers that selects vertices to form primitives, so shared vertices are stored once.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Input assembly*
|The stage that reads vertex and index buffers and builds primitives.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Instancing*
|Drawing many copies of one mesh in a single call, each with its own per-instance data.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Interleaved vertex buffer*
|A layout where all attributes of one vertex are adjacent in memory.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Interpolation (game loop)*
|Blending between the last two simulation states to draw a position between steps.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*Interpolation (render)*
|Blending a per-vertex value across a primitive for each fragment, perspective-correct in 3D.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*KTX 2.0*
|The Khronos texture container that holds mip chains and Basis Universal or GPU-compressed data.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Lambert*
|A diffuse model where brightness is proportional to the cosine of the angle to the light.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Level of detail*
|Using a cheaper version of a model or texture as it gets farther away.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Linear colour*
|Colour values proportional to physical light intensity, the space in which lighting maths is correct.
|xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Color Spaces, HDR and Tone Mapping]

|*Look-at*
|A function that builds a view or rotation from an eye position, a target and an up direction.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*Mesh shader*
|A compute-like stage that generates meshlets and replaces input assembly and vertex shading.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Meshlet*
|A small cluster of triangles processed together by a mesh shader.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Metallic-roughness*
|The glTF PBR material model with base colour, metallic and roughness parameters.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Mipmap*
|A pre-filtered, smaller version of a texture; the full set is called a mip chain.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Mixed reality*
|Experiences where virtual objects are anchored in and interact with the real environment.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*Model matrix*
|The matrix that moves an object from its local space to world space.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*MoltenVK*
|A Vulkan implementation that runs on Metal.
|xref:graphics-games/cross-platform-translation-layers.adoc[Cross-Platform Translation Layers]

|*MSAA*
|Multisample anti-aliasing: several coverage samples per pixel, shaded once.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*MSL*
|The Metal Shading Language.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*Narrow phase*
|The collision stage that computes exact contact between candidate pairs.
|xref:graphics-games/physics-audio-and-input-basics.adoc[Physics, Audio and Input Basics]

|*NDC*
|Normalised device coordinates: the cube that clip space maps to after the perspective divide.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*Normal map*
|A texture that stores perturbed surface normals to add apparent detail.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*OpenUSD*
|Pixar-originated scene description format, standardised by the Alliance for OpenUSD.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*OpenXR*
|The Khronos API for XR runtimes, devices and applications.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*Order-independent transparency*
|Techniques that composite transparent surfaces correctly without sorting them.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Overdraw*
|Shading the same pixel more than once because surfaces overlap.
|xref:graphics-games/performance-and-profiling.adoc[Performance and Profiling]

|*PCF*
|Percentage-closer filtering: averaging several shadow-map comparisons for softer edges.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Perspective divide*
|Dividing clip-space x, y and z by w to reach NDC.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*Physically based rendering*
|Shading with energy-conserving, measured-looking material parameters, abbreviated PBR.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*Pipeline state object*
|An immutable object that bundles shaders and fixed-function state for a draw.
|xref:graphics-games/explicit-vs-implicit-apis.adoc[Explicit vs Implicit Graphics APIs]

|*Premultiplied alpha*
|Colour stored already multiplied by its alpha, which composites and filters correctly.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Projection matrix*
|The matrix that maps view space into clip space, perspective or orthographic.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*Quaternion*
|Four numbers that represent a rotation without gimbal lock and interpolate smoothly.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*Queue*
|The GPU entry point to which command buffers are submitted.
|xref:graphics-games/gpu-architecture-basics.adoc[GPU Architecture Basics]

|*Rasterisation*
|Converting a primitive into the fragments it covers.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*Ray query*
|Inline ray tracing from any shader stage, without a separate ray tracing pipeline.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Retained mode*
|An API in which the library keeps the scene and draws it for you.
|xref:graphics-games/graphics-apis-vs-game-engines.adoc[Graphics APIs vs Game Engines]

|*Reversed-Z*
|Mapping the near plane to depth 1 and the far plane to 0 to improve floating-point precision.
|xref:graphics-games/vectors-matrices-and-homogeneous-coordinates.adoc[Vectors, Matrices and Homogeneous Coordinates]

|*Rigid body*
|A simulated object that keeps its shape and moves under forces and collisions.
|xref:graphics-games/physics-audio-and-input-basics.adoc[Physics, Audio and Input Basics]

|*Scene graph*
|A tree of nodes carrying transforms, bounds and appearance that a library traverses.
|xref:graphics-games/scene-graphs-and-asset-formats.adoc[Scene Graphs and Asset Formats]

|*Shader*
|A small program that runs on the GPU for each vertex, fragment or compute thread.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*Shadow acne*
|Speckled self-shadowing caused by limited shadow-map depth precision.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Shadow map*
|A depth image rendered from the light, used to test whether a point is lit.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*SIMT*
|Single instruction, multiple threads: the GPU execution model of lockstep thread groups.
|xref:graphics-games/gpu-architecture-basics.adoc[GPU Architecture Basics]

|*SLAM*
|Simultaneous localisation and mapping: estimating a device pose while building a map.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*Slang*
|A shading language and compiler hosted by Khronos that targets many back ends.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*Slerp*
|Spherical linear interpolation between two rotations.
|xref:graphics-games/rotations-and-quaternions.adoc[Rotations & Quaternions]

|*Specular*
|The mirror-like part of surface reflection.
|xref:graphics-games/lighting-and-shading-models.adoc[Lighting & Shading Models]

|*SPIR-V*
|The Khronos binary intermediate representation for shaders and kernels.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*sRGB*
|The standard colour space and transfer curve of most displays and images.
|xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Color Spaces, HDR and Tone Mapping]

|*SSAO*
|Screen-space ambient occlusion computed from the depth buffer.
|xref:graphics-games/shadows-and-global-illumination.adoc[Shadows and Global Illumination]

|*Swapchain*
|The set of images that are presented to the display in turn.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*TAA*
|Temporal anti-aliasing: accumulating jittered samples over several frames.
|xref:graphics-games/transparency-blending-and-post-processing.adoc[Transparency, Blending and Post-processing]

|*Tangent space*
|The per-vertex frame of tangent, bitangent and normal in which normal maps are stored.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Task shader*
|A stage before the mesh shader that decides how many mesh shader groups to launch.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*TBDR*
|Tile-based deferred rendering: a mobile GPU design that shades one screen tile at a time in fast on-chip memory.
|xref:graphics-games/gpu-architecture-basics.adoc[GPU Architecture Basics]

|*Tessellation*
|Subdividing patches into many small triangles on the GPU.
|xref:graphics-games/advanced-pipeline-stages.adoc[Advanced Pipeline Stages]

|*Texel*
|One element of a texture.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Tone mapping*
|Compressing HDR scene values into the range a display can show.
|xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Color Spaces, HDR and Tone Mapping]

|*Topology*
|How vertices form primitives: points, lines, triangle lists or strips.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Translation layer*
|Software that implements one graphics API on top of another.
|xref:graphics-games/cross-platform-translation-layers.adoc[Cross-Platform Translation Layers]

|*UV coordinates*
|Two-dimensional coordinates that map a surface to a texture.
|xref:graphics-games/textures-sampling-and-mipmaps.adoc[Textures, Sampling & Mipmaps]

|*Vertex shader*
|The program that runs once per vertex and outputs a clip-space position.
|xref:graphics-games/the-rendering-pipeline.adoc[The Rendering Pipeline]

|*View matrix*
|The matrix that moves world space into the camera frame.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*Viewport*
|The window rectangle onto which NDC is mapped.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]

|*Vsync*
|Synchronising buffer presentation with the display refresh to avoid tearing.
|xref:graphics-games/game-loop-and-frame-timing.adoc[The Game Loop and Frame Timing]

|*WebGPU*
|The W3C API that exposes modern GPU features to the web, with the WGSL shading language.
|xref:graphics-games/history-of-real-time-graphics.adoc[History of Real-Time Graphics]

|*WebXR*
|The W3C API for augmented and virtual reality in the browser.
|xref:graphics-games/augmented-and-mixed-reality-basics.adoc[Augmented and Mixed Reality Basics]

|*WGSL*
|The WebGPU Shading Language.
|xref:graphics-games/shading-languages-landscape.adoc[Shading Languages Landscape]

|*Winding order*
|The clockwise or counter-clockwise order of a triangle vertices, which defines its front face.
|xref:graphics-games/meshes-and-vertex-data.adoc[Meshes & Vertex Data]

|*Y-flip*
|The inversion of the Y axis needed because APIs disagree on whether the framebuffer origin is at the top or the bottom.
|xref:graphics-games/coordinate-spaces-and-transforms.adoc[Coordinate Spaces and Transforms]
