= Metal
:description: Landing page for the Metal sub-section of Graphics & Games -- what Metal is and where it stands in 2026, its place in the Apple stack, the re-verified version baseline (Metal 4, MSL 4.1, Xcode 27), a decision tree, a learning path, every page grouped by topic, the Metal Bookshelf running example and a coverage map of the official documentation and of two books.
:keywords: Metal, Metal 4, MTL4CommandQueue, Metal Shading Language, MSL 4.1, MetalKit, MTKView, MetalFX, Metal Performance Shaders, ray tracing, mesh shaders, Xcode 27, Apple silicon, visionOS, Game Porting Toolkit, learning path, Bookshelf, coverage map, bibliography

include::partial$graphics-games-metal-disclaimer.adoc[]

*Metal* is Apple's low-level graphics and compute API for iOS, iPadOS, macOS, tvOS and visionOS. It gives an app direct access to
the GPU of an iPhone, an iPad, a Mac with Apple silicon, an Apple TV or an Apple Vision Pro, with a small set of object types, a
shading language that is {cpp} (the Metal Shading Language, MSL) and tools built into Xcode. This sub-section teaches Metal 4, the
generation that arrived with the 26 operating systems, together with the Metal 3 equivalent where code must still run on
older devices, and it covers MetalKit, MetalFX, Metal Performance Shaders, ray tracing, mesh shaders, the debugging tools,
porting from other platforms and visionOS. It follows one running example, the *Metal Bookshelf*, from a first triangle to a small game,
and it says plainly where Metal stands in 2026: the only supported low-level graphics API on Apple platforms, with OpenGL deprecated
since 2018, and an API that is still gaining features every year, with machine learning now part of the frame. The pages build on
the general pages of xref:graphics-games/index.adoc[Graphics & Games]; read those first if the rendering pipeline or the
transformation chain are new to you.

== What Metal and its neighbours are

[cols="1,3",options=header]
|===
|Name |What it is

|Metal
|The GPU API: devices, command queues, command buffers, encoders, pipeline states and resources. Metal 4 adds a new core API with the `MTL4` types next to the older `MTL` types.

|Metal Shading Language (MSL)
|The {cpp}-based language of the shaders, compiled by the Metal Toolchain into a library that the app loads at run time.

|MetalKit
|Helpers for apps: `MTKView` to host a drawable, `MTKTextureLoader` to load images and `MTKMesh` to build meshes from Model I/O.

|MetalFX and Metal Performance Shaders
|Upscaling, frame interpolation and denoising, and a library of tuned image, linear algebra and neural-network kernels, with MPSGraph for graphs of them.

|SwiftUI, RealityKit and SceneKit
|Higher levels. SwiftUI shows an `MTKView` and applies shader effects, RealityKit draws entity scenes with Metal underneath, and SceneKit is in maintenance. They are named here, not taught.

|Vulkan, OpenGL and WebGPU
|The other graphics APIs. On Apple platforms MoltenVK and KosmicKrisp translate Vulkan to Metal, Safari implements WebGPU on top of it, and OpenGL is deprecated.
|===

Metal gives you the GPU and little else: you manage the resources, the synchronisation and the frame pacing, and you decide what
a scene is. That is why most games use an engine that already speaks Metal, and why learning Metal first makes an engine's
behaviour predictable. The reasoning about when each layer pays off is in
xref:graphics-games/choosing-an-api-or-engine.adoc[Choosing an API or Engine].

== Where Metal sits

.Specifications, hardware and API milestones, 2014 to 2026
image::graphics-games-metal-index-timeline.svg["Timeline from 2014 to 2026 with Metal, Metal 2, the deprecation of OpenGL, Apple silicon Macs, Metal 3, hardware ray tracing on A17 and M3, residency sets, Metal 4 and MSL 4.1 with Xcode 27",width=720]

Metal appeared in 2014 for iOS, before Direct3D 12 and Vulkan, as one of the first modern explicit APIs. Metal 2 (2017)
and Metal 3 (2022) added argument buffers, MetalFX, mesh shaders and fast resource loading, and Apple deprecated OpenGL and OpenGL ES
in 2018. Hardware ray tracing came with the A17 and M3 in 2023, residency sets in 2024 and Metal 4 in 2025. What each release
changed is on xref:graphics-games/metal/whats-new-in-metal-4.adoc[What's New in Metal 4].

.The layers between an Apple app and the GPU
image::graphics-games-metal-index-stack.svg["Five stacked layers from the app with SwiftUI and RealityKit, through MetalKit and the helper frameworks, Metal itself, the Metal driver and system, to the Apple silicon GPU",width=720]

The same layers appear in the general
xref:graphics-games/graphics-apis-vs-game-engines.adoc[Graphics APIs vs Game Engines] page. Apple silicon matters for how you write Metal:
the GPU shares memory with the CPU and renders in tiles, which the page
xref:graphics-games/metal/gpu-architecture-and-tbdr.adoc[GPU Architecture and TBDR] explains and which later pages use again and again.

== Version baseline

The facts below were checked on 1 November 2026 against the official pages cited in the last column. Items that follow a
release can change, so check them again before relying on them.

[cols="2,3,3",options=header]
|===
|Item |Version and status |Source

|API generation
|*Metal 4*, announced at WWDC25 and available from iOS, iPadOS, macOS, tvOS and visionOS 26.0. The `MTL4` types (`MTL4CommandQueue`, `MTL4CommandBuffer`, `MTL4Compiler`, `MTL4ArgumentTable`, `MTL4MachineLearningCommandEncoder` and `MTLTensor`) can be adopted one at a time next to the older `MTL` types.
|https://developer.apple.com/documentation/metal/understanding-the-metal-4-core-api[Understanding the Metal 4 core API]

|Shading language
|*MSL 4.1*, with the specification dated 4 June 2026. `MTLLanguageVersion.version4_1` is available from the 27 operating systems and `version4_0` from the 26 ones.
|https://developer.apple.com/metal/Metal-Shading-Language-Specification.pdf[Metal Shading Language Specification], https://developer.apple.com/documentation/metal/mtllanguageversion[MTLLanguageVersion]

|Metal 4 hardware
|A14 Bionic or later (iPhone, iPad and Apple TV), a Mac with Apple silicon (M1 or later) and Apple Vision Pro.
|https://developer.apple.com/metal/[Metal]

|Toolchain
|*Xcode 27* with Swift 6.4 and the 27 SDKs. It needs an Apple-silicon Mac on macOS 26.6 or later. The Metal Toolchain is a separately downloaded Xcode component, as it has been since Xcode 26.
|https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes[Xcode 27 release notes]

|Intel phase-out
|`MTLStorageMode.managed`, `MTLGPUFamily.mac2` and `.common3` are deprecated in the 27 operating systems, and with macOS 27 as the deployment target `ARCHS_STANDARD` drops x86_64.
|https://developer.apple.com/documentation/metal/mtlstoragemode/managed[MTLStorageMode.managed]

|GPU families
|`apple7` is the A14 and M1, `apple8` the A15, A16 and M2, `apple9` the A17, M3 and M4. Check the Feature Set Tables for later chips. The Metal 3 and Metal 4 families are `.metal3` and `.metal4`.
|https://developer.apple.com/documentation/metal/mtlgpufamily[MTLGPUFamily], https://developer.apple.com/metal/Metal-Feature-Set-Tables.pdf[Metal Feature Set Tables]

|WWDC26 additions
|Quantised tensor formats, support for the Neural Accelerators of the M5 Pro and M5 Max, MetalFX neural upscaling and denoising, Game Porting Toolkit 4 and the command-line tools `gpucapture`, `gpudebug` and `metalperftrace`.
|https://developer.apple.com/metal/whats-new/[What's new in Metal], https://developer.apple.com/metal/tools/[Metal developer tools]

|Deprecated
|`MTLFeatureSet` (use `supportsFamily(_:)`, iOS 16 and macOS 13), `MPSRayIntersector` (use acceleration structures, iOS 17 and macOS 14), PVRTC texture formats (iOS 18 and macOS 15), and OpenGL and OpenGL ES (iOS 12 and macOS 10.14).
|The per-symbol pages under https://developer.apple.com/documentation/metal[Metal documentation]

|Still current
|`MTKView`, `MTLArgumentEncoder`, `MTLResidencySet` (iOS 18 and macOS 15), `CAMetalDisplayLink` (iOS 17 and macOS 14), mesh pipelines and `MTLIOCommandQueue` (iOS 16 and macOS 13).
|The same pages
|===

== When to choose what

[mermaid]
....
flowchart TD
    A[Draw 3D graphics on an Apple platform] --> B{Need your own renderer or to learn the GPU?}
    B -- yes --> C[Metal 4 with MetalKit and MSL]
    B -- no --> D{Scene, physics and tools ready made?}
    D -- yes --> E{Mostly Apple platforms?}
    E -- yes --> F[RealityKit, or SceneKit for old projects]
    E -- no --> G[Unity, Unreal or another engine, which use Metal underneath]
    D -- no --> H{Existing OpenGL or DirectX code?}
    H -- yes --> I[Port with the migration sample, metal-cpp or Game Porting Toolkit]
    H -- no --> C
    C -.-> J[Metal 3 path keeps older devices working]
....

Choose *Metal* when you are building a renderer or an engine feature, when you need compute, ray tracing, mesh shaders or machine
learning in the frame, or when you want the least overhead on Apple hardware. Choose *RealityKit* or an engine when the scene,
the physics and the tools matter more than control. Choose a *port* when the code exists already: Apple's OpenGL migration
sample, metal-cpp and Game Porting Toolkit are covered on
xref:graphics-games/metal/migrating-from-opengl.adoc[Migrating from OpenGL] and
xref:graphics-games/metal/metal-cpp-and-game-porting.adoc[metal-cpp and Game Porting]. The general criteria are in
xref:graphics-games/choosing-an-api-or-engine.adoc[Choosing an API or Engine].

== The Metal Bookshelf running example

The *Bookshelf* scene of the section landing page, described in
xref:graphics-games/index.adoc#_the_bookshelf_scene_and_shared_assets[The Bookshelf scene and shared assets], is built as a
*multiplatform SwiftUI app hosting an `MTKView`*, with a Metal 4 path, a Metal 3 fallback and a visionOS target. The model and the
textures are the shared xref:attachment$bookshelf.glb[bookshelf.glb] and the files in the same folder. The pages grow the app
in ten stages, and the shader structs are shared between Swift and MSL through a bridging header.

.The ten stages from a triangle to an immersive space
image::graphics-games-metal-index-running-example.svg["Ten stages in two rows, a triangle, a lit textured book, the shelf as USDZ, PBR and a shadow, many books, dust particles, ray-traced reflections, temporal upscaling, the Sort the shelf game and a visionOS version",width=720]

. a triangle (xref:graphics-games/metal/hello-triangle-metal4.adoc[Hello Triangle with Metal 4])
. a textured, lit, rotating book with the model-view-projection chain and Blinn-Phong
  (xref:graphics-games/metal/transforms-and-camera.adoc[Transforms and Camera],
  xref:graphics-games/metal/textures-and-samplers.adoc[Textures and Samplers] and
  xref:graphics-games/metal/lighting-fundamentals.adoc[Lighting Fundamentals in Metal])
. the shared shelf as USDZ through Model I/O (xref:graphics-games/metal/models-with-model-io-and-usd.adoc[Models with Model I/O and USD])
. physically based materials and a shadow map (xref:graphics-games/metal/pbr-materials.adoc[PBR Materials in Metal] and
  xref:graphics-games/metal/shadows.adoc[Shadows in Metal])
. many books with instancing, then argument buffers and an indirect command buffer with GPU culling
  (xref:graphics-games/metal/argument-buffers-and-bindless.adoc[Argument Buffers and Bindless Resources] and
  xref:graphics-games/metal/gpu-driven-rendering-icb.adoc[GPU-Driven Rendering and Indirect Command Buffers])
. compute dust particles (xref:graphics-games/metal/particles.adoc[Particles])
. ray-traced reflections on a glossy shelf (xref:graphics-games/metal/ray-tracing.adoc[Ray Tracing in Metal])
. MetalFX temporal upscaling (xref:graphics-games/metal/metalfx-upscaling-and-frame-interpolation.adoc[MetalFX])
. a tiny game, "Sort the shelf": pick books with a ray query and drag them into order
  (xref:graphics-games/metal/ray-tracing.adoc[Ray Tracing in Metal])
. the immersive visionOS version through Compositor Services (xref:graphics-games/metal/metal-on-visionos.adoc[Metal on visionOS])
