= Migrating from Keras 2 to Keras 3
:description: What changed between Keras 2 (tf.keras up to TensorFlow 2.15) and Keras 3.15: imports, tf_keras fallback, keras.ops, saving and export, optimizers, Lambda layers and safe_mode, stateless random numbers, custom train steps and scikit-learn wrappers.
:keywords: Keras 3, Keras 2, tf_keras, TF_USE_LEGACY_KERAS, keras.ops, model.export, .keras format, SavedModel, safe_mode, Lambda layer, SKLearnClassifier, SciKeras, migration

include::partial$ml-tensorflow-disclaimer.adoc[]

Keras 3 is a rewrite of Keras as a multi-backend library that runs on TensorFlow, JAX and PyTorch. Since TensorFlow 2.16 it is also what `tf.keras` resolves to, so code and books written for the Keras 2 era (`tf.keras` up to TensorFlow 2.15) can break in subtle ways. This page lists what changed, what the fallback package `tf_keras` is for, and how to port the most common patterns. The overview of the current package layout is on xref:ml/tensorflow/keras-overview.adoc[Keras 3 Overview], multi-backend usage on xref:ml/tensorflow/keras-multi-backend.adoc[Keras Multi-Backend], and the older TensorFlow 1 history on xref:ml/tensorflow/migrating-from-tf1.adoc[Migrating from TensorFlow 1].

It targets Python 3.13, TensorFlow 2.21 with Keras 3.15 (TensorFlow 2.22 is labelled upcoming) and scikit-learn 1.9, and was checked against the official documentation on 2026-10-30. TensorFlow and Keras were not installed while preparing this page, so the snippets follow the documented API and were not executed. Items that could not be confirmed against a primary source are marked "not verified".

== Which Keras do you get?

The release notes for TensorFlow 2.16.1 state that Keras 3 became the default Keras version. In practice:

* `import keras` gives Keras 3.
* With TensorFlow 2.16 or later and no special configuration, `tf.keras` also resolves to Keras 3.
* `tf_keras` is a separate package that contains the Keras 2 code (version series 2.16 and later were published alongside TensorFlow) for projects that cannot migrate yet.

.Which Keras an import resolves to in a default and in a legacy-configured environment.
image::ml-tensorflow-keras-package-resolution.svg["Which Keras a TensorFlow 2.21 program imports",width=720]

To keep Keras 2 behaviour under `tf.keras`, install `tf-keras` and set an environment variable before TensorFlow is imported. The release notes warn that the variable applies to every package in the Python process.

[source,bash]
----
pip install tf-keras
export TF_USE_LEGACY_KERAS=1
python -c "import tensorflow as tf; print(tf.keras.__version__)"   # a 2.x version string
----

[source,python]
----
import os

os.environ["TF_USE_LEGACY_KERAS"] = "1"   # must be set before importing tensorflow

import tensorflow as tf            # tf.keras now resolves to tf_keras (Keras 2)
import tf_keras as keras           # or import tf_keras directly, which is more explicit
----

Source: https://github.com/tensorflow/tensorflow/blob/master/RELEASE.md

Whether the pinned `tf-keras` series for TensorFlow 2.21 is still maintained at the same pace, and exactly which Keras 2 version it contains, was not verified; check https://pypi.org/project/tf-keras/ before choosing it for new work. Treat `tf_keras` as a bridge, not a destination: new features land in Keras 3.

== Imports and namespaces

The simplest migration step is to stop writing `tf.keras` and import Keras directly.

[cols="2,2",options="header"]
|===
|Keras 2 era |Keras 3

|`from tensorflow import keras`
|`import keras`

|`from tensorflow.keras import layers`
|`from keras import layers`

|`tf.keras.Model`, `tf.keras.layers.Dense`
|`keras.Model`, `keras.layers.Dense`
|===

Source: https://keras.io/guides/migrating_to_keras_3/

With TensorFlow installed, `tf.keras` still works in a default environment and is the same Keras 3, but importing `keras` makes the dependency explicit and works unchanged on the JAX and PyTorch backends.

== Dated table of renames and removals

The table lists items documented in the official migration guide, verified on 2026-10-30 against Keras 3.15. "Port" says what to use instead.

[cols="3,3,2",options="header"]
|===
|Keras 2 behaviour or API |Keras 3 |Port

|`model.save("dir")` writes a SavedModel; `load_model("dir")` reads it
|SavedModel is not written by `save`; the loader does not accept SavedModel directories
|Use `.keras` for models, `+model.export(...)+` for serving artifacts, `keras.layers.TFSMLayer` to call an existing SavedModel

|`ThresholdedReLU` layer
|Removed
|`+keras.layers.ReLU(threshold=...)+`

|`LocallyConnected1D`, `LocallyConnected2D`
|Removed
|Copy the implementation into your code base

|`keras.layers.experimental.RandomFourierFeatures`, `keras.constraints.RadialConstraint`
|Removed
|Copy the implementation if needed

|Symbolic `Layer.add_loss()` outside `call()`
|Removed; `add_loss` inside `call()` still works
|Move the call into `call()`

|Layer attributes `metrics` and `dynamic` (`Model.metrics` stays)
|Removed
|Track metrics explicitly

|RNN arguments `constants` and `time_major`
|Removed
|Reshape or restructure the inputs

|`reset_metrics` argument of `train_on_batch`, `test_on_batch`
|Removed
|Call `model.reset_metrics()` yourself

|Autograph active inside `Layer.call`
|Off by default
|Use `keras.ops` control flow or decorate with `tf.function`

|Per-output loss values reported by `evaluate()` for multi-output models
|Not reported automatically
|Add the losses to `metrics` explicitly

|Nested dictionaries as functional-model inputs or outputs
|Rejected beyond one level
|Flatten to a list, tuple or single-level dict

|`None` in nested arguments of `call()`
|Not allowed
|Use an optional argument with a default of `None`

|`jit_compile` default
|`True` on GPU in Keras 3
|Pass `jit_compile=False` to `compile` if XLA fails, for example with `tf.strings` ops

|`tf.Variable` assigned as a layer attribute is tracked
|Not tracked
|Use `+self.add_weight(...)+` or `keras.Variable`
|===

Source: https://keras.io/guides/migrating_to_keras_3/

Two further items matter but are explained in more depth below: the optimizer and the `train_step` rewrite. For the current layer, loss and metric catalogues see xref:ml/tensorflow/keras-layers.adoc[Core Keras Layers], xref:ml/tensorflow/keras-losses.adoc[Losses] and xref:ml/tensorflow/keras-metrics.adoc[Metrics].

== From TensorFlow ops to keras.ops

A Keras 3 layer that must run on any backend cannot call `+tf.*+` functions on symbolic tensors during functional model construction. Replace them with `keras.ops`, which mirrors a large part of NumPy plus neural-network operations.

[cols="2,2",options="header"]
|===
|TensorFlow |keras.ops

|`tf.reduce_sum`, `tf.reduce_mean`, `tf.reduce_max`, `tf.reduce_min`
|`keras.ops.sum`, `mean`, `max`, `min`

|`tf.reduce_prod`, `tf.reduce_all`, `tf.reduce_any`
|`keras.ops.prod`, `all`, `any`

|`tf.math.reduce_variance`, `tf.math.reduce_std`
|`keras.ops.var`, `keras.ops.std`

|`tf.abs`, `tf.clip_by_value`, `tf.math.pow`
|`keras.ops.absolute`, `clip`, `power`

|`tf.concat`, `tf.range`, `tf.rank`, `tf.reverse`
|`keras.ops.concatenate`, `arange`, `ndim`, `flip`

|`tf.gather`, `tf.nn.embedding_lookup`
|`keras.ops.take`

|`tf.nn.sparse_softmax_cross_entropy_with_logits`
|`keras.ops.sparse_categorical_crossentropy` (mind `from_logits`)

|`tf.nn.sigmoid_cross_entropy_with_logits`
|`keras.ops.binary_crossentropy` (mind `from_logits`)

|`tf.nn.conv1d`, `conv2d`, `conv3d`, `tf.nn.convolution`
|`keras.ops.conv`

|`tf.nn.dropout`
|`keras.random.dropout`

|`tf.convert_to_tensor`, `x.numpy()`
|`keras.ops.convert_to_tensor`, `keras.ops.convert_to_numpy(x)`
|===

Source: https://keras.io/guides/migrating_to_keras_3/ and https://keras.io/api/ops/

[source,python]
----
import keras
from keras import layers, ops


class SquaredNorm(layers.Layer):
    """Backend-agnostic: only keras.ops inside call."""

    def call(self, x):
        return ops.sum(ops.square(x), axis=-1, keepdims=True)


inputs = keras.Input(shape=(8,))
outputs = SquaredNorm()(inputs)        # works with symbolic tensors on any backend
model = keras.Model(inputs, outputs)
print(model.output_shape)               # (None, 1)
----

Source: https://keras.io/api/ops/

Code that stays inside TensorFlow can keep using `+tf.*+` in a layer's `call` when run on the TensorFlow backend, but it will not work on JAX or PyTorch, and symbolic construction can fail. The wider backend story is on xref:ml/tensorflow/keras-multi-backend.adoc[Keras Multi-Backend].

== Model saving and export

This is the change that breaks the most scripts. The Keras 3 native format is a zip archive with the extension `.keras` containing a JSON configuration, a weights file and metadata (including the Keras version). Full-model saving to a SavedModel directory is no longer what `model.save` does; serving artifacts come from `model.export`.

[cols="3,3",options="header"]
|===
|Older books and Keras 2 tutorials |Keras 3.15

|`model.save("my_model")` creates a SavedModel directory
|`model.save("my_model.keras")` writes the native format; `model.export("export_dir")` writes a SavedModel (inference artifact) for TensorFlow Serving

|`model.save("model.h5")` as the default
|`.h5` is the legacy format; use `.keras` for new work

|`model.save_weights("ckpt")` in the TensorFlow checkpoint format
|`model.save_weights("name.weights.h5")`; the file name must end with `.weights.h5`

|`load_model("my_model")` on a SavedModel directory
|Wrap it: `keras.layers.TFSMLayer("my_model", call_endpoint="serving_default")`
|===

Source: https://keras.io/guides/serialization_and_saving/ and https://keras.io/guides/migrating_to_keras_3/

[source,python]
----
import keras

model = keras.Sequential([keras.Input(shape=(4,)), keras.layers.Dense(2)])

model.save("my_model.keras")                       # architecture + weights + compile + optimizer state
restored = keras.models.load_model("my_model.keras")

model.save_weights("my_model.weights.h5")          # weights only
model.load_weights("my_model.weights.h5")

model.export("exported_model")                     # SavedModel for serving (TensorFlow backend)

# Reload a SavedModel as an inference-only layer
layer = keras.layers.TFSMLayer("exported_model", call_endpoint="serving_default")
----

Source: https://keras.io/guides/serialization_and_saving/ and https://keras.io/guides/migrating_to_keras_3/

Custom classes must be findable at load time because the `.keras` file stores their configuration but not their Python code. Register them with `@keras.saving.register_keras_serializable(package="MyPkg")`, pass `custom_objects=` to `load_model`, or use `keras.saving.custom_object_scope`. A custom layer with non-primitive constructor arguments (for example sublayers) needs `get_config` and a `from_config` class method. The complete walk-through is on xref:ml/tensorflow/saving-keras-models.adoc[Saving Keras Models], with SavedModel details on xref:ml/tensorflow/savedmodel.adoc[SavedModel and Signatures], checkpoints on xref:ml/tensorflow/checkpoints.adoc[Training Checkpoints], and an interchange view on xref:ml/onnx-and-interoperability.adoc[ONNX and Interoperability].

== Lambda layers and safe_mode

Keras 2 tutorials often wrap arbitrary Python in `keras.layers.Lambda`. A Lambda layer serializes Python bytecode, which makes loading an untrusted model file equivalent to running untrusted code. Keras 3 therefore loads models in a safe mode by default that refuses to deserialize such code. The migration guide itself does not discuss this (not covered there); the behaviour below is from the `load_model` documentation and general Keras 3 knowledge and was not re-verified against Keras 3.15 here.

* Prefer replacing a `Lambda` with a small subclassed layer that implements `call` and `get_config`; it is portable and loads under the default safety settings.
* Only when you fully trust the file and cannot rewrite the layer, load with the `safe_mode=False` argument of `load_model`, or enable unsafe deserialization through the Keras saving utilities. Never do this with files from the internet.

[source,python]
----
import keras
from keras import ops


@keras.saving.register_keras_serializable(package="demo")
class Scale(keras.layers.Layer):
    """Replaces keras.layers.Lambda(lambda x: x * factor)."""

    def __init__(self, factor=2.0, **kwargs):
        super().__init__(**kwargs)
        self.factor = factor

    def call(self, x):
        return ops.multiply(x, self.factor)

    def get_config(self):
        return {**super().get_config(), "factor": self.factor}


model = keras.Sequential([keras.Input(shape=(3,)), Scale(3.0)])
model.save("scaled.keras")
reloaded = keras.models.load_model("scaled.keras")   # no safe_mode override needed
----

Source: https://keras.io/guides/making_new_layers_and_models_via_subclassing/ and https://keras.io/guides/serialization_and_saving/

== Optimizers

Keras 3 ships a new optimizer implementation. The optimizers listed in the API reference include SGD, RMSprop, Adam, AdamW, Adadelta, Adagrad, Adamax, Adafactor, Nadam, Ftrl, Lion, Lamb, Muon, plus wrappers such as `LossScaleOptimizer`. Learning-rate schedules live in `keras.optimizers.schedules` and are passed as the `learning_rate`.

Things to check when porting (the API reference page does not discuss these, so they come from general knowledge of Keras 3 and are marked not verified):

* The Keras 2 `tf.keras.optimizers.legacy` namespace has no counterpart; scripts that selected legacy optimizers for speed on Apple silicon or for exact old semantics must drop that import or stay on `tf_keras`.
* Custom optimizers written against the Keras 2 `+_resource_apply_dense+` style must be rewritten to the Keras 3 base class (`build`, `update_step`, `get_config`); the official page documents this protocol.
* Optimizer state saved in Keras 2 checkpoints does not transfer to Keras 3 optimizers; plan to restart the optimizer state.
* Gradient clipping, weight decay and exponential moving averages are constructor options of the optimizer base class in Keras 3 (not verified for each argument name; see xref:ml/tensorflow/keras-optimizers.adoc[Optimizers and Learning-Rate Schedules]).

Source: https://keras.io/api/optimizers/

[source,python]
----
import keras

schedule = keras.optimizers.schedules.ExponentialDecay(
    initial_learning_rate=1e-2, decay_steps=10_000, decay_rate=0.9
)
optimizer = keras.optimizers.SGD(learning_rate=schedule, momentum=0.9)

model = keras.Sequential([keras.Input(shape=(4,)), keras.layers.Dense(1)])
model.compile(optimizer=optimizer, loss="mse", jit_compile=False)
----

Source: https://keras.io/api/optimizers/

For how the optimizer family relates to the theory, see xref:ml/optimizers-and-learning-rate-schedules.adoc[Optimizers and Learning-Rate Schedules].

== Custom train_step and training loops

TensorFlow-specific training code does not run on other backends. The migration guide recommends:

* If you only change how the loss is computed, override `compute_loss(self, x=None, y=None, y_pred=None, sample_weight=None)`, which is backend-agnostic, instead of `train_step`.
* If you need the gradient step, write one version per backend and choose it from the active backend; the TensorFlow version uses `tf.GradientTape`, the JAX version a stateless `jax.value_and_grad`, the PyTorch version `loss.backward()`.

[source,python]
----
import keras


class WeightedMSE(keras.Model):
    def compute_loss(self, x=None, y=None, y_pred=None, sample_weight=None, **kwargs):
        errors = keras.ops.square(y - y_pred)
        return keras.ops.mean(errors * 2.0)      # same code on TensorFlow, JAX and PyTorch


inputs = keras.Input(shape=(4,))
outputs = keras.layers.Dense(1)(inputs)
model = WeightedMSE(inputs, outputs)
model.compile(optimizer="adam")
----

Source: https://keras.io/guides/migrating_to_keras_3/

Details and full examples: xref:ml/tensorflow/custom-train-step.adoc[Customizing fit() with train_step] and xref:ml/tensorflow/custom-training-loop.adoc[Writing a Training Loop from Scratch].

== Random numbers are stateless

`keras.random` functions are stateless: calling one twice with `seed=123` returns the same values twice. TensorFlow's `tf.random` functions are stateful. A layer that needs fresh randomness on every call should hold a `keras.random.SeedGenerator` and pass it as the seed; a plain Python integer that is incremented inside `call` is frozen into the compiled graph.

[source,python]
----
import keras


class AddNoise(keras.layers.Layer):
    def __init__(self, scale=0.1, **kwargs):
        super().__init__(**kwargs)
        self.scale = scale
        self.seed_generator = keras.random.SeedGenerator(1337)

    def call(self, x, training=False):
        if not training:
            return x
        noise = keras.random.normal(keras.ops.shape(x), stddev=self.scale, seed=self.seed_generator)
        return x + noise
----

Source: https://keras.io/guides/migrating_to_keras_3/

== scikit-learn wrappers: legacy wrappers, SciKeras and keras.wrappers

Keras 2 offered `tf.keras.wrappers.scikit_learn.KerasClassifier` and `KerasRegressor`. They were deprecated and are absent from Keras 3. The community project SciKeras (`scikeras`) took over their role for years; the issue outline for this section records it as archived and legacy, which I did not re-verify on its repository (not verified), so check its status before adopting it in new code.

Keras 3.15 documents its own scikit-learn compatible wrappers in `keras.wrappers`: `SKLearnClassifier`, `SKLearnRegressor` and `SKLearnTransformer` (a scikit-learn transformer, not a deep-learning Transformer). All share the signature `(model, warm_start=False, model_kwargs=None, fit_kwargs=None)`. The `model` argument is either a compiled Keras model, which is cloned before fitting unless `warm_start=True`, or a callable that builds and compiles a model from `X` and `y`.

[source,python]
----
import keras
from keras.wrappers import SKLearnClassifier
from sklearn.datasets import make_classification
from sklearn.model_selection import cross_val_score


def build_model(X, y, hidden=(32, 32)):
    n_classes = int(y.max()) + 1
    model = keras.Sequential([keras.Input(shape=(X.shape[1],))])
    for units in hidden:
        model.add(keras.layers.Dense(units, activation="relu"))
    model.add(keras.layers.Dense(n_classes, activation="softmax"))
    model.compile(loss="sparse_categorical_crossentropy", optimizer="adam", metrics=["accuracy"])
    return model


X, y = make_classification(n_samples=500, n_features=10, n_informative=5, random_state=0)
est = SKLearnClassifier(model=build_model, model_kwargs={"hidden": (16, 16)}, fit_kwargs={"epochs": 5, "verbose": 0})
print(cross_val_score(est, X, y, cv=3).mean())
----

Source: https://keras.io/api/utils/sklearn_wrappers/

Because the page does not state in which Keras release the wrappers appeared, check the Keras release notes before depending on them in a pinned environment. For pipelines, cross-validation and parameter cloning, see xref:data-science/scikit-learn/pipelines.adoc[Pipelines], xref:data-science/scikit-learn/cross-validation.adoc[Cross-Validation] and xref:data-science/scikit-learn/params-and-clone.adoc[Parameters and clone].

== A migration checklist

. Pin versions: Python 3.13, TensorFlow 2.21, Keras 3.15; decide whether `tf_keras` is needed temporarily.
. Replace `tf.keras` imports with `import keras`.
. Run the test suite; fix `SavedModel` saves first (`.keras` and `export`).
. Replace `Lambda` layers with subclassed layers.
. Replace `+tf.*+` calls inside layers by `keras.ops`.
. Rewrite custom `train_step` code with `compute_loss`, or keep it TensorFlow-only on purpose.
. Revisit optimizers, learning-rate schedules, mixed precision and `jit_compile`.
. Retrain or reload weights; compare metrics against the Keras 2 baseline.
. Only then consider running on JAX or PyTorch.

Compare with how PyTorch handles state and serialization in xref:ml/pytorch/saving-and-loading.adoc[Saving and Loading], and for choosing between stacks see xref:ml/choosing-a-framework.adoc[Choosing a Framework].
