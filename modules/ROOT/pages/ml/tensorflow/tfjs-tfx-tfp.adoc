= TF.js, TFX & TF Probability (Positioning)
:description: Where TensorFlow.js, TFX and TensorFlow Probability fit in 2026: what each library does, the evidence for its maintenance status from the official sites and repositories, version constraints such as TFX and Python 3.13, and when to choose an alternative.
:keywords: TensorFlow.js, tfjs, TFX, TensorFlow Extended, TensorFlow Probability, TFP, tfp.substrates.jax, ML pipelines, TensorFlow Transform, TensorFlow Data Validation, TensorFlow Model Analysis, ML Metadata, status, positioning

include::partial$ml-tensorflow-disclaimer.adoc[]

Around the core TensorFlow and Keras libraries sit several satellite projects with their own sites, release schedules and maintainers. This page positions three of them: TensorFlow.js for machine learning in JavaScript, TFX for production ML pipelines, and TensorFlow Probability for probabilistic modelling. For each it states what the project is for, what the official pages and repositories say about its status, and what to use instead when it does not fit. It is deliberately a positioning page, not a tutorial: the three libraries are large enough to deserve their own books, and the evidence about their health is more useful than a toy example. The wider ecosystem list is on xref:ml/tensorflow/ecosystem-and-status.adoc[Ecosystem and Project Status]; model deployment to servers and devices is on xref:ml/tensorflow/serving.adoc[Serving with TensorFlow Serving] and xref:ml/tensorflow/litert-on-device.adoc[On-Device Inference with LiteRT]; the framework-neutral view of pipelines, tracking and monitoring is on xref:ml/experiment-tracking-and-mlops.adoc[Experiment Tracking and MLOps] and xref:ml/deploying-and-serving-models.adoc[Deploying and Serving Models].

It targets Python 3.13 and TensorFlow 2.21 with Keras 3.15 (TensorFlow 2.22 is "upcoming" and not covered), and the status statements were checked against the official sites and GitHub pages on 2026-10-30. "Status" here means only what those pages visibly state; a page that is silent is reported as silent, not as healthy or abandoned. The TensorFlow Probability example was run on Python 3.13 with TensorFlow 2.21, Keras 3.15 and TensorFlow Probability 0.25 (CPU) on 2026-10-31. The TensorFlow.js commands need the `tensorflowjs` converter and a JavaScript runtime and were not executed.

== At a glance

[cols="1,2,3,3",options="header"]
|===
|Project |Purpose |What the official pages show (2026-10-30) |When to prefer something else
|TensorFlow.js |Run and train models in the browser and Node.js |The tensorflow.org page gives no deprecation or maintenance statement; the GitHub releases page lists 4.22.0 (21 October, marked latest), 4.21.0 (4 September) and 4.20.0 (3 June), so releases are frequent but maintenance-sized |Large models, WebGPU-first stacks and LLMs in the browser (see ONNX Runtime Web and Transformers.js in xref:ml/onnx-and-interoperability.adoc[ONNX and Interoperability])

|TensorFlow Probability |Distributions, bijectors, MCMC, variational inference, probabilistic layers |README says it is under active development and interfaces may change; the site gives no status statement; it can run on JAX through a substrate import; no Keras 3 statement on either page |Pyro, NumPyro or PyMC for Bayesian modelling, or `torch.distributions` in PyTorch
|===

Note that a feature-frozen library can still be fine to use. The risk is not age but compatibility: a library that stays pinned to an older Python or Keras version forces your whole environment to stay there too. Check the compatibility tables before adopting any of them.

== TensorFlow.js

TensorFlow.js is a JavaScript library for developing and running ML models in the browser or Node.js. The official page describes three paths: run existing models (official JavaScript models, or Python TensorFlow models converted for the web), retrain existing models with transfer learning on your own data, and develop and train models directly in JavaScript.

Typical uses are small to medium models where the privacy or latency of running on the client matters: pose or hand tracking from a webcam, audio keyword spotting, on-page classifiers, interactive demonstrations.

[source,bash]
----
# Convert a Keras 3 / SavedModel export for the browser (tensorflowjs pip package)
pip install tensorflowjs
tensorflowjs_converter --input_format=tf_saved_model \
    models/my_model/1 web_model/
----

Source: https://www.tensorflow.org/js/tutorials/conversion/import_saved_model

[source,javascript]
----
import * as tf from '@tensorflow/tfjs';

const model = await tf.loadGraphModel('web_model/model.json');
const x = tf.tensor2d([[0.1, 0.2, 0.3, 0.4]]);
const y = model.predict(x);
y.print();
----

Source: https://www.tensorflow.org/js/tutorials/conversion/import_saved_model

Points to know:

* The conversion command line and the `loadGraphModel` call follow the TensorFlow.js conversion tutorial linked in the references; confirm the flags and file names there for the converter version you install. The Python converter package may lag the newest Keras 3 exports; if conversion fails, export a SavedModel with `model.export` (see xref:ml/tensorflow/saving-keras-models.adoc[Saving Keras Models]) or convert through ONNX.
* The overview page does not name browser backends. Backend choice (CPU, WebGL, WebAssembly, WebGPU) and its availability change quickly, so check the TensorFlow.js documentation for the browsers you target. The release notes mention WebGPU work; check the maturity of that backend in the TensorFlow.js documentation before depending on it.
* Model size matters more than accuracy tweaks: users download the weights. Quantize first (see xref:ml/tensorflow/quantization-optimization.adoc[Quantization and Model Optimization]) and shard weights.
* TensorFlow.js is unaffected by the TensorFlow Lite to LiteRT rename, according to the 2024 announcement, which says it continues as part of the TensorFlow codebase.

== TFX (TensorFlow Extended)

TFX is described on tensorflow.org as an end-to-end platform for deploying production ML pipelines: a pipeline is a sequence of components built from TFX libraries, and those libraries can also be used on their own. The libraries the site names are ML Metadata, TensorFlow Data Validation, TensorFlow Transform, TensorFlow Model Analysis and TensorFlow Serving (the last is covered on xref:ml/tensorflow/serving.adoc[Serving with TensorFlow Serving]).

[mermaid]
----
flowchart LR
    A[Ingest examples] --> B[Validate data]
    B --> C[Transform features]
    C --> D[Train]
    D --> E[Evaluate]
    E -->|blessed| F[Push to serving]
    E -.->|metadata| G[(ML Metadata)]
----

What the repository README shows today:

* The latest release listed in the compatibility table is 1.21.0, tested with TensorFlow 2.21, Apache Beam 2.73.0 and `tensorflow-model-analysis` 0.52.0, with `tensorflow-serving-api` 2.19.1.
* The supported Python range is greater than or equal to 3.10 and less than 3.13, for both 1.21.0 and the master branch. This page targets Python 3.13, so a full TFX pipeline does not fit that baseline according to the README; the standalone libraries might, which must be checked per package.
* The README and website contain no deprecation or maintenance notice, and the table says untested combinations may also work.

Source: https://github.com/tensorflow/tfx

TFX's strengths are the discipline it encodes: schema-driven data validation, feature transforms that are applied identically at training and serving time (a TensorFlow Transform graph embedded in the model), and model analysis gates before a model is pushed. Its costs are Apache Beam, a heavy dependency stack and a pipeline-as-code model that fits best when the whole organization commits to it.

Alternatives, when TFX does not fit: put the same ideas into generic orchestrators (see xref:ml/experiment-tracking-and-mlops.adoc[Experiment Tracking and MLOps]) with Great Expectations or Pandera-style data checks, Keras preprocessing layers inside the exported model for train-serve consistency (xref:ml/tensorflow/keras-preprocessing-layers.adoc[Keras Preprocessing Layers]) and your CI system for evaluation gates. For the input pipeline alone, `tf.data` (xref:ml/tensorflow/tf-data.adoc[tf.data]) is usually enough.

== TensorFlow Probability

TensorFlow Probability (TFP) is a Python library built on TensorFlow for combining probabilistic models and deep learning on CPU, GPU and TPU. The site lists a wide selection of probability distributions and bijectors, tools for deep probabilistic models including probabilistic layers and the `JointDistribution` abstraction, variational inference and Markov chain Monte Carlo, and optimizers such as Nelder-Mead, BFGS and SGLD.

[source,python]
----
import tensorflow as tf
import tensorflow_probability as tfp

tfd = tfp.distributions

# A Normal distribution and a log-probability
d = tfd.Normal(loc=0.0, scale=1.0)
print(d.log_prob(0.5).numpy())   # -1.0439385

# Fit a Bernoulli GLM, adapted from the project home page
features = tfd.Normal(loc=0.0, scale=1.0).sample(int(1e5))
labels = tfd.Bernoulli(logits=1.618 * features).sample()
coeffs, linear_response, is_converged, num_iter = tfp.glm.fit(
    model_matrix=features[:, tf.newaxis],
    response=tf.cast(labels, tf.float32),
    model=tfp.glm.Bernoulli(),
)
print(coeffs.numpy())   # close to [1.618], for example [1.6197685]
----

Source: https://www.tensorflow.org/probability

What the official sources say about status:

* The README states TFP is under active development and that interfaces may change at any time.
* TensorFlow is not a dependency of the `tensorflow-probability` package; you install TensorFlow separately. The README says building from source needs Bazel, with 6.4.0 the most recent supported version and 7.0.0 or later still work in progress.
* The README says TFP also works "in pure JAX" through a substrate import (`from tensorflow_probability.substrates import jax as tfp`). TFP 0.25 predates JAX 0.12: with JAX 0.12 that import fails with `AttributeError: module 'jax.interpreters.xla' has no attribute 'pytype_aval_mappings'`, so pair it with an older JAX release.
* Neither the site nor the README mentions Keras 3 or `tf_keras`. In TFP 0.25 the probabilistic layers (`tfp.layers`) are `tf_keras` (Keras 2) layers: adding `tfp.layers.DistributionLambda` to a Keras 3 model raises a `ValueError` ("Only instances of keras.Layer can be added to a Sequential model"), while the same layer works in a `tf_keras.Sequential` model. Use them only through `tf_keras` (see xref:ml/tensorflow/keras-overview.adoc[Keras 3 Overview]).
* The repository Releases section was empty on 2026-10-30; the latest version on PyPI is 0.25.0.

Alternatives: for Bayesian inference NumPyro (on JAX), PyMC and Stan are widely used; in PyTorch use `torch.distributions` and Pyro; in scikit-learn, Gaussian processes and Bayesian ridge cover small cases (see xref:data-science/scikit-learn/index.adoc[scikit-learn]). The mathematics of likelihoods behind these tools is on xref:ml/information-theory-and-losses.adoc[Information Theory and Losses].

== Deciding quickly

[cols="2,3",options="header"]
|===
|Need |Choice
|Model runs in the user's browser |TensorFlow.js, or ONNX Runtime Web for ONNX models
|Model runs on Android or iOS |LiteRT, see xref:ml/tensorflow/litert-on-device.adoc[On-Device Inference with LiteRT]
|Model served from a data center |TensorFlow Serving or a Python server, see xref:ml/tensorflow/serving.adoc[Serving with TensorFlow Serving]
|Reproducible data validation, transform and evaluation pipelines in TensorFlow |TFX, if its Python and TensorFlow constraints suit your environment
|Distributions, MCMC, variational inference in TensorFlow or JAX |TensorFlow Probability, after checking compatibility with your Keras version
|Anything else |Start from xref:ml/choosing-a-framework.adoc[Choosing a Framework]
|===
