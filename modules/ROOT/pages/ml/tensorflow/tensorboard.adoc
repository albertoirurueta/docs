TensorBoard is the visualisation tool of the TensorFlow ecosystem: it reads event files written during training and shows scalar curves, the model graph, weight histograms, images, text, embeddings and profiler traces in a browser. This page shows the Keras callback, writing summaries yourself in a custom loop, how to launch the UI locally, in a notebook and on a remote machine, and how to organise runs. Profiling views are expanded on xref:ml/tensorflow/performance-xla-profiling.adoc[Performance, XLA and Profiling]; callbacks in general are on xref:ml/tensorflow/keras-callbacks.adoc[Callbacks]; the PyTorch integration is xref:ml/pytorch/tensorboard.adoc[TensorBoard Integration] and broader tooling is in xref:ml/experiment-tracking-and-mlops.adoc[Experiment Tracking and MLOps].

It targets Python 3.13 and TensorFlow 2.21 with Keras 3.15 (TensorFlow 2.22 is "upcoming" and not covered), and was checked against the official documentation on 2026-10-30. TensorFlow was not installed while preparing this page, so the snippets follow the documented API and were not executed.

== The Keras TensorBoard callback

[source,python]
----
import datetime
import keras

log_dir = "logs/fit/" + datetime.datetime.now().strftime("%Y%m%d-%H%M%S")

tensorboard_cb = keras.callbacks.TensorBoard(
    log_dir=log_dir,
    histogram_freq=1,        # weight and bias histograms every epoch (0 disables)
    write_graph=True,        # log the model graph
    update_freq="epoch",     # "epoch", "batch" or an integer number of batches
    profile_batch=0,         # 0 disables the profiler; (10, 20) profiles those batches
)

model.fit(
    x_train, y_train,
    epochs=5,
    validation_data=(x_test, y_test),
    callbacks=[tensorboard_cb],
)
----

Source: https://www.tensorflow.org/tensorboard/get_started and https://keras.io/api/callbacks/tensorboard/

Arguments worth knowing (the first two are demonstrated in the official guide; the others are described in the Keras callback reference and should be re-checked against the version installed):

* `log_dir`: use a fresh timestamped subdirectory per run so TensorBoard can overlay runs; reusing a directory mixes events from different runs.
* `histogram_freq`: epochs between weight histograms; off by default.
* `write_graph`: whether to log the model graph for the Graphs dashboard.
* `update_freq`: `"epoch"` writes metrics once per epoch, `"batch"` or an integer writes more often at the cost of speed and disk.
* `profile_batch`: batch or range to profile; see the profiler page.
* Keras 3 note: callback options that depended on the TensorFlow 1 style graph or on `write_images` and embeddings may behave differently or be unavailable on non-TensorFlow backends. The callback is documented for all backends, but the profiler and graph views are TensorFlow-specific.

== Launching TensorBoard

[source,bash]
----
pip install tensorboard            # installed with TensorFlow; the profile tab needs tensorboard-plugin-profile
tensorboard --logdir logs/fit      # then open http://localhost:6006
tensorboard --logdir logs/fit --port 6007
tensorboard --logdir_spec baseline:logs/a,tuned:logs/b   # name runs from different roots
----

[source,python]
----
# In Jupyter or Colab
%load_ext tensorboard
%tensorboard --logdir logs/fit
----

Source: https://www.tensorflow.org/tensorboard/get_started

On a remote machine forward the port through SSH (`ssh -L 6006:localhost:6006 user@host`) rather than exposing the server publicly, since TensorBoard has no built-in authentication. TensorBoard reads log directories on cloud storage too (for example `gs://` paths) when the corresponding filesystem support is installed.

== Writing summaries yourself

In a custom loop (see xref:ml/tensorflow/custom-training-loop.adoc[Writing a Training Loop from Scratch] and xref:ml/tensorflow/core-training-loop.adoc[A Training Loop with TF Core]) create one file writer per run and split, then call `tf.summary` functions with a step number inside the writer's context.

[source,python]
----
import datetime
import numpy as np
import tensorflow as tf
import keras

stamp = datetime.datetime.now().strftime("%Y%m%d-%H%M%S")
train_writer = tf.summary.create_file_writer(f"logs/gradient_tape/{stamp}/train")
test_writer = tf.summary.create_file_writer(f"logs/gradient_tape/{stamp}/test")

train_loss = keras.metrics.Mean(name="train_loss")
train_acc = keras.metrics.SparseCategoricalAccuracy(name="train_accuracy")

for epoch in range(5):
    for x, y in train_ds:
        train_step(x, y)                      # updates train_loss and train_acc

    with train_writer.as_default():
        tf.summary.scalar("loss", train_loss.result(), step=epoch)
        tf.summary.scalar("accuracy", train_acc.result(), step=epoch)
        # Other summary types
        tf.summary.histogram("logits", model(x_batch, training=False), step=epoch)
        tf.summary.image("inputs", x_batch[:6], max_outputs=6, step=epoch)   # [N, H, W, C]
        tf.summary.text("note", f"epoch {epoch}", step=epoch)

    with test_writer.as_default():
        tf.summary.scalar("loss", evaluate_loss(), step=epoch)

    train_loss.reset_state()
    train_acc.reset_state()
----

Source: https://www.tensorflow.org/tensorboard/get_started

Key rules:

* Metrics are accumulated with stateful `keras.metrics` objects, logged once per epoch, and reset with `reset_state()` (see xref:ml/tensorflow/keras-metrics.adoc[Metrics]).
* Using the same tag (`loss`) in two sibling writers (`train` and `test`) overlays the curves in one chart, which is the idiomatic way to compare training and validation.
* `tf.summary.image` expects a four-dimensional tensor `[batch, height, width, channels]` with values in [0, 1] for floats or [0, 255] for integers. `tf.summary.histogram` takes any tensor and `tf.summary.text` a string tensor. These three functions are described in the API reference rather than the getting-started page.
* Summaries inside a `tf.function` work when a default writer is active at trace time; pass the step as a tensor or a `tf.Variable` so it is not frozen in the graph.
* Call `writer.flush()` before reading the logs from another process if data seems missing.

== Dashboards

[cols="2,5"]
|===
| Dashboard | Content

| Time Series, Scalars | loss, metrics, learning rate and any `tf.summary.scalar`
| Graphs | the model graph (`write_graph=True`) or a traced `tf.function`
| Histograms, Distributions | how weight and activation values change over training
| Images, Text | logged image and text samples, useful for augmentation checks and generated output
| Profile | profiler tools such as the input pipeline analyzer, see xref:ml/tensorflow/performance-xla-profiling.adoc[Performance, XLA and Profiling]
| HParams | compare hyperparameter runs, see below
|===

Source: https://www.tensorflow.org/tensorboard/get_started

Other dashboards appear when you log other data types; inactive ones are listed in the "Inactive" dropdown at the top right.

== Logging hyperparameters

The HParams plugin records the hyperparameters of each run next to its final metrics so runs can be compared in a table and a parallel-coordinates view. It is the natural companion of xref:ml/tensorflow/keras-tuner.adoc[Hyperparameter Tuning with KerasTuner].

[source,python]
----
from tensorboard.plugins.hparams import api as hp

hparams = {"units": 128, "dropout": 0.2, "lr": 1e-3}

with tf.summary.create_file_writer(f"logs/hparam_tuning/run-{run_id}").as_default():
    hp.hparams(hparams)                                   # record this run's configuration
    accuracy = train_and_evaluate(hparams)
    tf.summary.scalar("accuracy", accuracy, step=1)
----

Source: https://www.tensorflow.org/tensorboard/hyperparameter_tuning_with_hparams

== Practical advice

* Keep one directory per experiment and one subdirectory per run; delete or move old runs rather than pointing TensorBoard at a huge tree, which slows loading.
* Log less often for large models: per-batch scalars every step produce large event files; use `update_freq` with an integer.
* Do not log from every worker in distributed training; log from the chief only (xref:ml/tensorflow/distributed-training.adoc[Distributed Training]).
* TensorBoard is local-first; for team dashboards, artifact tracking and model registries consider the hosted tools in xref:ml/experiment-tracking-and-mlops.adoc[Experiment Tracking and MLOps].
* Combine with `ModelCheckpoint` and `EarlyStopping` in the same callback list (xref:ml/tensorflow/keras-callbacks.adoc[Callbacks]).
* Older material uses `tf.summary.FileWriter` and `tf.contrib.summary`; both belong to TensorFlow 1 and are gone. Use `tf.summary.create_file_writer`.
