This page collects the Flow features an application reaches for once the basics are in place. Each is small on
its own; together they cover lifecycle, error handling, refresh behaviour, file transfer and
internationalisation. It follows https://vaadin.com/docs/latest/flow/advanced[the Advanced Topics section].

== Lifecycle hooks

A `VaadinServiceInitListener` runs once at startup and is the place to register the other listeners.
Discovered automatically as a Java service or a Spring bean:

[source,java]
----
@Component
public class ApplicationInitListener implements VaadinServiceInitListener {

    @Override
    public void serviceInit(ServiceInitEvent event) {

        event.getSource().addUIInitListener(uiEvent -> {
            UI ui = uiEvent.getUI();
            ui.addBeforeEnterListener(this::checkMaintenanceMode);
        });

        event.getSource().addSessionInitListener(sessionEvent ->
                sessionEvent.getSession().setErrorHandler(new AppErrorHandler()));
    }
}
----

`IndexHtmlRequestListener` (and, in bootstrap mode, `BootstrapListener`) let you modify the served HTML shell.

=== The order of the hooks

Each hook fires at a different scope, and knowing the order tells you which one to use. The service listener runs
once per deployment, the session listener once per user, the UI listener once per tab, and navigation events run
every time the user moves between views.

[mermaid]
....
sequenceDiagram
    participant Container as Servlet container
    participant Service as VaadinService
    participant Session as VaadinSession
    participant Tab as UI
    Container->>Service: start the servlet
    Service->>Service: VaadinServiceInitListener.serviceInit (once)
    Note over Service: first request from a user
    Service->>Session: create the session
    Session->>Session: SessionInitListener (once per user)
    Session->>Tab: create the UI for a browser tab
    Tab->>Tab: UIInitListener (once per tab)
    Tab->>Tab: BeforeEnter, view created, AfterNavigation
    Tab->>Tab: further navigation repeats BeforeEnter and AfterNavigation
    Note over Tab: tab closed or heartbeats missed
    Tab->>Tab: detach listeners and onDetach on components
    Session->>Session: SessionDestroyListener (session timeout or logout)
....

Register `BeforeEnter` listeners in the `UIInitListener` as shown above to apply a rule to every view, and use the
`SessionInitListener` for per-user setup such as the error handler.

== Error handling and system messages

A session `ErrorHandler` catches exceptions thrown from UI event handlers that nothing else handled:

[source,java]
----
public class AppErrorHandler implements ErrorHandler {
    @Override
    public void error(ErrorEvent event) {
        LoggerFactory.getLogger(getClass()).error("Unhandled", event.getThrowable());
        UI.getCurrent().access(() ->
                Notification.show("Something went wrong.").addThemeVariants(
                        NotificationVariant.LUMO_ERROR));
    }
}
----

The messages Vaadin shows for session expiry, an internal error, or a lost connection are overridden with a
`SystemMessagesProvider`:

[source,java]
----
service.setSystemMessagesProvider(info -> {
    CustomizedSystemMessages messages = new CustomizedSystemMessages();
    messages.setSessionExpiredCaption("Session ended");
    messages.setSessionExpiredMessage("Please sign in again.");
    messages.setSessionExpiredNotificationEnabled(true);
    return messages;
});
----

=== Telling expected failures from bugs

A single `ErrorHandler` for the session usually serves two audiences: the user, who needs a short message, and
operations, who need the stack trace. Separating the exceptions your code *expects* from the ones it does not keeps
both honest:

[source,java]
----
public class AppErrorHandler implements ErrorHandler {

    private static final Logger log = LoggerFactory.getLogger(AppErrorHandler.class);

    @Override
    public void error(ErrorEvent event) {
        Throwable cause = event.getThrowable();
        if (cause instanceof BusinessRuleException expected) {
            notify(expected.getMessage());                 // a rule the user can fix, no stack trace
            return;
        }
        log.error("Unhandled error in a UI event", cause);  // a bug: log everything
        notify("Something went wrong. Please try again.");
    }

    private void notify(String text) {
        UI ui = UI.getCurrent();
        if (ui != null) {                                   // null when the error came from a background thread
            ui.access(() -> Notification.show(text));
        }
    }
}
----

`BusinessRuleException` stands for whatever exception type your services throw for rule violations. The handler is
called on the thread that was running the failing request, so `UI.getCurrent()` is normally set;
the null guard covers failures raised from background threads, where the current `UI` is not available. Since
`ErrorHandler` has a single method, a unit test can call it directly: `handler.error(new ErrorEvent(new
IllegalStateException("boom")))` reaches the handler with `event.getThrowable().getMessage()` equal to `boom`.

== Preserving a view across refresh

By default a browser refresh builds a fresh `UI` and view instance. `@PreserveOnRefresh` on a view (or its
layout) keeps the same instance -- and its unsaved state -- when the user reloads the same URL:

[source,java]
----
@Route("wizard")
@PreserveOnRefresh
public class WizardView extends VerticalLayout { }
----

== Loading indicator

The blue progress bar Vaadin shows during a slow server round trip is themable and its delays are
configurable:

[source,java]
----
ui.getLoadingIndicatorConfiguration().setFirstDelay(300);
ui.getLoadingIndicatorConfiguration().setSecondDelay(1500);
ui.getLoadingIndicatorConfiguration().setThirdDelay(5000);
----

== Downloads and uploads

Stream a generated file through a `StreamResource` behind an `Anchor`; receive an uploaded file with the
`Upload` component and a `Receiver`:

[source,java]
----
StreamResource report = new StreamResource("report.pdf",
        () -> new ByteArrayInputStream(reportService.pdf()));
Anchor download = new Anchor(report, "Download report");
download.getElement().setAttribute("download", true);

Upload upload = new Upload(new MemoryBuffer());
upload.addSucceededListener(e -> importService.process(
        ((MemoryBuffer) upload.getReceiver()).getInputStream()));
----

== Long-running tasks

Run slow work on the shared executor that Flow owns (`VaadinService.getExecutor()`, see
xref:web/vaadin/server-push.adoc[]) and hand the result back to the UI with `UI.access`. The Vaadin session lock
is not held on the background thread, so capture what you need first and re-enter the UI only to render:

[source,java]
----
Executor executor = VaadinService.getCurrent().getExecutor();
executor.execute(() -> {
    Result r = slowJob.run();
    ui.access(() -> render(r));
});
----

== Internationalisation

Implement `I18NProvider` (a Spring bean or Java service), back it with `ResourceBundle` files, and call
`+getTranslation(key, args...)+` from views:

[source,java]
----
@Component
public class MessagesProvider implements I18NProvider {

    private static final List<Locale> LOCALES = List.of(Locale.ENGLISH, Locale.forLanguageTag("es"));
    private static final ResourceBundle.Control NO_FALLBACK =
            ResourceBundle.Control.getNoFallbackControl(ResourceBundle.Control.FORMAT_PROPERTIES);

    @Override
    public List<Locale> getProvidedLocales() { return LOCALES; }

    @Override
    public String getTranslation(String key, Locale locale, Object... params) {
        ResourceBundle bundle = ResourceBundle.getBundle("messages", locale, NO_FALLBACK);
        if (!bundle.containsKey(key)) {
            return "!" + locale.getLanguage() + ": " + key;     // visible marker for a missing key
        }
        return new MessageFormat(bundle.getString(key), locale).format(params);
    }
}

// in a view
add(new Span(getTranslation("customer.greeting", customer.getName())));
----

[source,properties]
----
# messages.properties (the default, English)
customer.greeting = Hello, {0}

# messages_es.properties
customer.greeting = Hola, {0}
----

=== Two pitfalls in message lookup

*The JVM default locale leaks in.* `ResourceBundle.getBundle("messages", Locale.ENGLISH)` does not simply use
`messages.properties` when there is no `messages_en`: by default it falls back to the *JVM's default locale*
first. On a server whose default locale is Spanish, an English user would get the Spanish text. The no-fallback
`Control` in the provider above skips that step, so a requested locale without its own bundle (French, here)
resolves to the base `messages.properties`, which is the behaviour you want.

*Apostrophes belong to `MessageFormat`.* A single quote starts a quoted section and is dropped, along with the
placeholder it protects. In `messages.properties`, `+Don't panic, {0}+` is rendered as `+Dont panic, {0}+`; write
`+Don''t panic, {0}+` to get `+Don't panic, Ada+`. The same class gives plurals for free through a `choice` pattern:

[source,properties]
----
customer.count = {0,choice,0#No customers|1#One customer|1<{0} customers}
customer.count = {0,choice,0#Ningún cliente|1#Un cliente|1<{0} clientes}
----

(the second line belongs in `messages_es.properties`). Formatting `0`, `1` and `5` in English gives `No customers`,
`One customer` and `5 customers`; in Spanish, `5` gives `5 clientes`. Languages with more plural forms than
"one" and "other" need a library such as ICU4J's `MessageFormat` instead.

=== Changing the language at run time

`UI.getCurrent().setLocale(locale)` changes the locale of the current tab, but text already placed in components
does not update itself. A view that implements `LocaleChangeObserver` is told about every change, and is also
called when the view is first attached, so one method serves both purposes:

[source,java]
----
@Route("")
public class GreetingView extends Div implements LocaleChangeObserver {

    private final Span text = new Span();

    public GreetingView() {
        add(text, new Button("Español", e -> UI.getCurrent().setLocale(Locale.forLanguageTag("es"))));
    }

    @Override
    public void localeChange(LocaleChangeEvent event) {
        text.setText(getTranslation("customer.greeting", "Ada"));
    }
}
----

Set a right-to-left locale's direction on the UI:

[source,java]
----
UI.getCurrent().setDirection(Direction.RIGHT_TO_LEFT);
----
