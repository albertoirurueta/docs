Vaadin is a Java web framework for building browser user interfaces without hand-writing HTML or JavaScript. This
page introduces its two programming models, its open-source and commercial editions, and how to create, run and
structure a project; https://vaadin.com/docs/latest/getting-started[the official Getting Started guide] is the
reference it follows.

== Flow, Hilla and Web Components

Vaadin is *server-driven*: your application logic runs as Java on the server, and a thin client-side engine keeps
the browser DOM in sync over an HTTP/WebSocket channel. Two programming models sit on top of that channel and can
coexist in one project:

* *Flow* -- server-side Java, and the style used throughout this section. You compose a view from Java component
  objects (`Button`, `Grid`, `VerticalLayout`); every click or keystroke is an event handled on the server,
  which returns the minimal DOM change. See https://vaadin.com/docs/latest/flow/what-is-flow[What is Flow?] and
  the https://vaadin.com/docs/latest/flow[Flow reference].
* *Hilla* -- a browser-side UI written in React and TypeScript that calls type-safe endpoints generated from your
  Java services. Covered in xref:web/vaadin/hilla-and-react-views.adoc[] and xref:web/react/index.adoc[].

Both models render the same underlying *Web Components* -- framework-agnostic custom elements such as
`<vaadin-grid>` and `<vaadin-button>` -- so a Flow view and a Hilla view share one component set, one theme and
one build. A single application can route some paths to Flow views and others to Hilla views.
xref:web/vaadin/architecture.adoc[] covers the request lifecycle. In Vaadin 7 the UI was also server-side Java,
but built on GWT; Flow replaced that architecture and is the only current model.

== Editions: open source and commercial

The framework itself -- Flow, Hilla, routing, `Binder` data binding and 40+ UI components -- is *open source
under Apache-2.0* and free for commercial use. A separate set of commercial components and tools needs a
subscription (https://vaadin.com/pricing[Pricing]):

* *Pro components* -- Charts, Grid Pro, CRUD, Dashboard and Map. The component set is listed in
  xref:web/vaadin/components-overview.adoc[] and https://vaadin.com/docs/latest/components[Components].
* *TestBench*, the end-to-end UI testing tool.
* *Acceleration Kits* -- for example the https://vaadin.com/docs/latest/tools/sso[SSO Kit], Kubernetes Kit,
  Azure Cloud Kit and Observability Kit. Not all Kits are commercial: the
  https://vaadin.com/docs/latest/tools/collaboration[Collaboration Kit] is itself Apache-2.0.
* The *Enterprise* subscription tier adds long-term support and security guarantees on top of the Pro contents.

Commercial parts compile and run in development mode without a licence; a *production build* validates the
subscription and fails without one. xref:web/vaadin/configuration-and-dev-tools.adoc[] covers those checks.

== Creating a project

There are three official routes, all producing a Spring Boot and Maven project (Gradle and plain-servlet
variants also exist -- see https://vaadin.com/docs/latest/getting-started/starters[Starters]). Install a JDK and
an IDE first: https://vaadin.com/docs/latest/getting-started/dev-environment[Set up the environment].

*Vaadin Start.* The configurator at https://start.vaadin.com/[start.vaadin.com] lets you pick views, a theme, the
Java version and add-ons, then downloads a ready project. This is the route in
https://vaadin.com/docs/latest/getting-started/quick-start[the Quick Start].

*Spring Initializr.* If you already use Spring Boot, generate at https://start.spring.io[start.spring.io] and add
the *Vaadin* dependency -- see
https://vaadin.com/docs/latest/getting-started/starters/spring-initializr[Spring Initializr].

*Maven archetype.* From the command line
(https://vaadin.com/docs/latest/getting-started/starters/maven-archetype[Maven Archetype]):

[source,bash]
----
mvn -B archetype:generate \
  -DarchetypeGroupId=com.vaadin \
  -DarchetypeArtifactId=vaadin-archetype-application \
  -DarchetypeVersion=LATEST \
  -DgroupId=com.example \
  -DartifactId=my-app
----

== Project structure

A generated project follows the standard Maven layout with a frontend folder added:

[listing]
----
my-app/
├── pom.xml                       Maven build, Vaadin BOM and plugin
├── package.json                  frontend dependencies (managed by Vaadin)
├── src/main/java/                Flow views, layouts, services, the main() class
├── src/main/frontend/            TypeScript / React (Hilla) sources, themes, index.html
├── src/main/resources/
│   └── application.properties    Spring Boot and Vaadin configuration
└── src/main/resources/META-INF/resources/   static assets
----

`src/main/java` holds server-side code: the `@Route`-annotated Flow views and the Spring Boot `main()` class.
`src/main/frontend` holds browser-side sources -- Hilla React views under `views/`, theme files, and the
generated `index.html`; Vaadin watches this folder in development mode
(https://vaadin.com/docs/latest/getting-started/run[Run in your IDE]). `package.json` and `vite.config.ts` are
generated and rarely edited by hand.

`pom.xml` pulls the platform in through a BOM and the Spring Boot starter, plus `vaadin-maven-plugin` for the
frontend build:

[source,xml]
----
<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>com.vaadin</groupId>
      <artifactId>vaadin-bom</artifactId>
      <version>24.5.0</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>
    <groupId>com.vaadin</groupId>
    <artifactId>vaadin-spring-boot-starter</artifactId>
  </dependency>
</dependencies>
----

A `production` Maven profile activates the `vaadin:build-frontend` goal for an optimized bundle; see
https://vaadin.com/docs/latest/flow/configuration/maven[Maven configuration] and
xref:web/vaadin/spring-boot-integration.adoc[].

`application.properties` carries both Spring and Vaadin keys:

[source,properties]
----
server.port=8080
vaadin.launch-browser=true
vaadin.frontend.hotdeploy=true
----

xref:web/vaadin/configuration-and-dev-tools.adoc[] lists the Vaadin-specific properties.

== Running the application

A Spring Boot Vaadin app starts like any other -- from the IDE, or with Maven:

[source,bash]
----
mvn spring-boot:run
----

The first start also downloads npm packages and builds the frontend, then serves the app at
`http://localhost:8080`. Running in *development mode* (the default) enables:

* *Live reload* -- editing a Java class triggers an automatic restart, or a hot swap when run under a debugger or
  the Vaadin IDE plugin; editing anything under `src/main/frontend` is pushed to the browser with no restart
  (https://vaadin.com/docs/latest/getting-started/run[Run in your IDE]).
* *Vaadin Copilot* -- a visual, AI-assisted editor that appears as a toolbar in the running app for inspecting
  and editing components, themes and views (https://vaadin.com/docs/latest/tools/copilot[Copilot]).
* The *dev tools* window for build warnings, plus the Vite-served frontend development bundle.

A production build (`mvn -Pproduction package`) instead pre-compiles and minifies the frontend into the JAR.

== A first view

A Flow view is a Java class mapped to a route:

[source,java]
----
package com.example.views;

import com.vaadin.flow.component.button.Button;
import com.vaadin.flow.component.notification.Notification;
import com.vaadin.flow.component.orderedlayout.VerticalLayout;
import com.vaadin.flow.component.textfield.TextField;
import com.vaadin.flow.router.Route;

@Route("")
public class MainView extends VerticalLayout {

    public MainView() {
        TextField name = new TextField("Your name");
        Button greet = new Button("Say hello", e ->
                Notification.show("Hello, " + name.getValue()));
        add(name, greet);
    }
}
----

The click handler runs on the server; Vaadin sends only the notification's markup back to the browser. The Hilla
equivalent is a `.tsx` file under `src/main/frontend/views` that uses the same components as React elements --
see xref:web/vaadin/hilla-and-react-views.adoc[] and xref:web/vaadin/components-overview.adoc[]. For the
TypeScript side of a Hilla view, see xref:web/typescript/index.adoc[].

== Versions and baseline

Vaadin ships a major release roughly twice a year. Two lines matter
(https://vaadin.com/docs/latest/upgrading[Upgrading]):

[cols="1,3",options="header"]
|===
| Line | Baseline

| *Vaadin 24 (LTS)* | Long-term support. Java 17+, Spring Boot 3 / Spring Framework 6, Jakarta EE 10
  (Servlet 6). The safe default for a new production app.

| *Vaadin 25* | Current feature line. Java 21+, Spring Boot 4 / Spring Framework 7, Jakarta EE 11
  (Servlet 6.1).
|===

Both lines use the same Flow and Hilla APIs -- the difference is the platform baseline, not how you write views.
Choose the LTS unless you need something newer; moving between lines is covered step by step in
https://vaadin.com/docs/latest/upgrading[the upgrade guide].
