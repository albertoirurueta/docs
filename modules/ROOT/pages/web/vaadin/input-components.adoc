= Input Components
:description: Vaadin Flow's data-entry fields -- text, numeric, boolean and choice, date and time, ComboBox with lazy loading, Upload and Slider -- plus the shared HasValue contract, value-change modes, and the required, helper-text, prefix, suffix and read-only features every field carries.
:keywords: Vaadin, Flow, input components, HasValue, TextField, TextArea, EmailField, PasswordField, NumberField, IntegerField, BigDecimalField, Checkbox, CheckboxGroup, RadioButtonGroup, Select, ListBox, DatePicker, TimePicker, DateTimePicker, ComboBox, lazy loading, MultiSelectComboBox, Upload, Slider, ValueChangeMode, required, helper text, prefix, suffix, read-only

include::partial$ai-disclaimer.adoc[]

Vaadin ships about twenty ready-made input components -- one per data type a business form needs. They all
implement the same `HasValue` contract, so `Binder` drives any of them the same way. This page follows the
individual component pages under https://vaadin.com/docs/latest/components[Components], starting with
https://vaadin.com/docs/latest/components/text-field[Text Field]; for wiring fields to a bean see
xref:web/vaadin/data-binding.adoc[].

== The HasValue contract

Every field implements https://vaadin.com/docs/latest/flow/binding-data/components-binder[`HasValue<E, V>`]:
`getValue()` / `setValue(v)`, an empty value (`isEmpty()`, `clear()`), `+addValueChangeListener(...)+`, and
`setReadOnly(boolean)` / `setRequiredIndicatorVisible(boolean)`. A value-change event reports the old value,
the new value, and whether the change came from the client (`isFromClient()`).

[source,java]
----
TextField name = new TextField("Name");
name.addValueChangeListener(e -> {
    String old = e.getOldValue();
    String current = e.getValue();
    boolean typed = e.isFromClient();   // false for setValue(...) from server code
    Notification.show(old + " -> " + current);
});
----

Because the API is uniform, a helper method can accept any field:

[source,java]
----
void logChanges(HasValue<?, ?> field) {
    field.addValueChangeListener(e -> log.info("value = {}", e.getValue()));
}
----

== Value-change modes

Text-like fields (`TextField`, `TextArea`, `EmailField`, `PasswordField`, `NumberField`, `IntegerField`,
`BigDecimalField`) expose a https://vaadin.com/docs/latest/components/text-field[`ValueChangeMode`] that
decides *when* the server hears about typing:

[cols="1,3",options="header"]
|===
| Mode | When the value-change event fires

| `ValueChangeMode.ON_CHANGE` (default) | On blur, and on Enter.
| `ValueChangeMode.ON_BLUR` | Only when the field loses focus.
| `ValueChangeMode.EAGER` | On every keystroke -- one round trip per character.
| `ValueChangeMode.LAZY` | On every keystroke, but debounced by `setValueChangeTimeout(ms)`.
|===

[source,java]
----
TextField search = new TextField("Search");
search.setValueChangeMode(ValueChangeMode.LAZY);
search.setValueChangeTimeout(300);      // fire 300 ms after the user stops typing
search.addValueChangeListener(e -> results.setItems(service.search(e.getValue())));
----

`LAZY` is the right choice for as-you-type filtering; `ON_CHANGE` for ordinary form fields.

== When the server hears about typing

The modes differ only in *when* the browser sends the current text to the server. The diagram follows a user who
types three characters in quick succession and then leaves the field:

[mermaid]
....
sequenceDiagram
    participant User
    participant Field as Browser field
    participant Server as Server TextField
    User->>Field: types a, b, c quickly
    alt EAGER
        Field->>Server: value a
        Field->>Server: value ab
        Field->>Server: value abc
    else LAZY with a 300 ms timeout
        Note over Field: timer restarts on every keystroke
        Field->>Server: value abc (300 ms after the last key)
    else ON_CHANGE (default)
        User->>Field: presses Enter or leaves the field
        Field->>Server: value abc
    end
....

`LAZY` is the best trade-off for search boxes: the server sees one event per pause instead of one per
keystroke. With `EAGER` every character costs a round trip and a lock acquisition, which adds up quickly with
many concurrent users.

== Shared field features

The field pages document a common set of properties, shown here on a
https://vaadin.com/docs/latest/components/text-field[`TextField`] but available on almost every field:

[source,java]
----
TextField iban = new TextField("IBAN");
iban.setRequiredIndicatorVisible(true);          // the * marker (Binder.asRequired adds the rule)
iban.setHelperText("Two-letter country code followed by up to 32 characters");
iban.setErrorMessage("Not a valid IBAN");        // shown while the field is invalid
iban.setPrefixComponent(VaadinIcon.MONEY.create());
iban.setSuffixComponent(new Span("verified"));
iban.setClearButtonVisible(true);
iban.setReadOnly(true);
iban.setPlaceholder("DE89 3704 ...");
iban.setTooltipText("Shown on hover and focus");  // https://vaadin.com/docs/latest/components/tooltip
----

Validation constraints such as `setMaxLength`, `setPattern`, `setMin` / `setMax` and `setRequired` participate
in `Binder` validation because these components implement `HasValidator` -- see
xref:web/vaadin/data-binding.adoc[].

== Empty values and programmatic changes

Two details save debugging time when fields meet `Binder`:

* *The empty value depends on the field.* `TextField.getEmptyValue()` is the empty string `""`, so a cleared text
  field is never `null`, while `IntegerField`, `DatePicker` and `ComboBox` use `null`. A bean property bound to a
  text field therefore receives `""` rather than `null` unless a converter or
  `withNullRepresentation` says otherwise.
* *Server-side changes are events too.* `+setValue(...)+` and `clear()` fire value-change listeners just as typing
  does; the event's `isFromClient()` is `false` for them. Guard listeners that update other fields with this flag
  to avoid ping-pong between two fields that set each other.

[source,java]
----
TextField name = new TextField("Name");
List<String> events = new ArrayList<>();
name.addValueChangeListener(e ->
        events.add(e.getOldValue() + "|" + e.getValue() + "|" + e.isFromClient()));

name.setValue("a");
name.setValue("ab");
name.clear();
// events: "|a|false", "a|ab|false", "ab||false"
----

== Built-in validation on the field itself

Fields carry their own constraints -- `setRequired`, `setMinLength` / `setMaxLength`, `setPattern`, `setMin` /
`setMax` -- and evaluate them on the server whenever the value changes. `isInvalid()` reports the result and
`setErrorMessage` supplies the text the field shows:

[source,java]
----
TextField code = new TextField("Code");
code.setPattern("[A-Z]{3}-\\d{3}");
code.setRequired(true);

code.setValue("abc");      // code.isInvalid() == true
code.setValue("ABC-123");  // code.isInvalid() == false
code.clear();              // invalid again: required

IntegerField quantity = new IntegerField("Quantity");
quantity.setMin(1);
quantity.setMax(99);
quantity.setValue(0);      // quantity.isInvalid() == true
----

When such a field is bound with `Binder`, its own constraints run first (they are its `HasValidator` default
validator). A failure there marks the field invalid and shows the field's `errorMessage`, but the
`BindingValidationStatus` message that `Binder` reports is empty. A form summary built from `Binder` messages
therefore only lists rules added with `withValidator`; put a rule in `withValidator` when its text must appear
in such a summary.

== Text fields

`TextField` (single line), `TextArea` (multi-line, `setMaxRows`), `EmailField` (built-in email pattern) and
`PasswordField` (masked, with a reveal button) all produce `String` values.

[source,java]
----
TextField fullName = new TextField("Full name");
fullName.setMaxLength(60);

TextArea notes = new TextArea("Notes");
notes.setMaxRows(6);

EmailField email = new EmailField("Email");        // https://vaadin.com/docs/latest/components/email-field

PasswordField password = new PasswordField("Password");
password.setRevealButtonVisible(false);            // https://vaadin.com/docs/latest/components/password-field

add(fullName, notes, email, password);
----

== Numeric fields

https://vaadin.com/docs/latest/components/number-field[`NumberField`] yields `Double`, `IntegerField` yields
`Integer`, and `BigDecimalField` yields `BigDecimal` for money and other exact values. All three accept
`setMin`, `setMax`, `setStep` and an optional step-controls spinner.

[source,java]
----
NumberField weight = new NumberField("Weight (kg)");
weight.setStep(0.1);
weight.setStepButtonsVisible(true);

IntegerField quantity = new IntegerField("Quantity");
quantity.setMin(1);
quantity.setMax(99);

BigDecimalField price = new BigDecimalField("Price");
price.setValue(new BigDecimal("19.99"));
----

For a text field that stores a number, bind a plain `TextField` through a `Converter` instead -- see
xref:web/vaadin/data-binding.adoc[].

== Boolean and choice fields

* https://vaadin.com/docs/latest/components/checkbox[`Checkbox`] -- a single `Boolean`.
* `CheckboxGroup<T>` -- a `Set<T>` of selected items.
* https://vaadin.com/docs/latest/components/radio-button-group[`RadioButtonGroup<T>`] -- one `T`, all
  options visible.
* https://vaadin.com/docs/latest/components/select[`Select<T>`] -- one `T` from a drop-down (no free text).
* https://vaadin.com/docs/latest/components/list-box[`ListBox<T>`] / `MultiSelectListBox<T>` -- a scrollable,
  unstyled list for one or many `T`.

[source,java]
----
Checkbox subscribe = new Checkbox("Subscribe to the newsletter");

CheckboxGroup<String> roles = new CheckboxGroup<>("Roles");
roles.setItems("ADMIN", "EDITOR", "VIEWER");
Set<String> chosen = roles.getValue();

RadioButtonGroup<Priority> priority = new RadioButtonGroup<>("Priority");
priority.setItems(Priority.values());
priority.setRenderer(new TextRenderer<>(Priority::getLabel));

Select<Country> country = new Select<>();
country.setLabel("Country");
country.setItems(countryService.findAll());
country.setItemLabelGenerator(Country::getName);
country.setEmptySelectionAllowed(true);
----

== Date and time fields

https://vaadin.com/docs/latest/components/date-picker[`DatePicker`] gives a `LocalDate`, `TimePicker` a
`LocalTime`, and `DateTimePicker` a `LocalDateTime`. `DatePicker` supports `setMin` / `setMax`, a custom
`+setI18n(...)+` for locale text, and `+setInitialPosition(...)+`.

[source,java]
----
DatePicker birthDate = new DatePicker("Date of birth");
birthDate.setMax(LocalDate.now());
birthDate.setValue(LocalDate.of(1990, 1, 1));

TimePicker openingTime = new TimePicker("Opens at");
openingTime.setStep(Duration.ofMinutes(30));

DateTimePicker deadline = new DateTimePicker("Deadline");
deadline.setDatePlaceholder("Date");
deadline.setTimePlaceholder("Time");
----

== ComboBox and lazy loading

https://vaadin.com/docs/latest/components/combo-box[`ComboBox<T>`] is a single-select drop-down with
type-ahead filtering. For a small list, `+setItems(...)+` holds every item in server memory and filters in the
browser:

[source,java]
----
ComboBox<Country> country = new ComboBox<>("Country");
country.setItems(countryService.findAll());
country.setItemLabelGenerator(Country::getName);
----

For a large table, register *lazy* callbacks: `ComboBox` passes the current filter text, offset and limit in
a `Query`, and only the matching page is fetched. This is the `ComboBoxLazyDataView` path described on the
https://vaadin.com/docs/latest/components/combo-box[Combo Box] page.

[source,java]
----
ComboBox<Customer> customer = new ComboBox<>("Customer");
customer.setItemLabelGenerator(Customer::getName);
customer.setItems(
        query -> customerService
                .findByNameLike(query.getFilter().orElse(""),
                        query.getOffset(), query.getLimit())
                .stream(),
        query -> customerService.countByNameLike(query.getFilter().orElse("")));
----

`MultiSelectComboBox<T>` is the same component returning a `Set<T>`, with chips for the chosen items:

[source,java]
----
MultiSelectComboBox<String> tags = new MultiSelectComboBox<>("Tags");
tags.setItems("java", "flow", "hilla", "spring");
Set<String> selectedTags = tags.getValue();
----

`setAllowCustomValue(true)` plus an `addCustomValueSetListener` lets the user add entries that are not in the
list.

== Upload

https://vaadin.com/docs/latest/components/upload[`Upload`] pairs with a `Receiver` that returns the
`OutputStream` each incoming file is written to. `MemoryBuffer` keeps one file in memory;
`MultiFileMemoryBuffer` accepts several.

[source,java]
----
MemoryBuffer buffer = new MemoryBuffer();
Upload upload = new Upload(buffer);
upload.setAcceptedFileTypes("image/png", "image/jpeg");
upload.setMaxFileSize(5 * 1024 * 1024);

upload.addSucceededListener(event -> {
    String name = event.getFileName();
    try (InputStream in = buffer.getInputStream()) {
        avatarService.store(name, in.readAllBytes());
    }
});
upload.addFileRejectedListener(event -> Notification.show(event.getErrorMessage()));
----

For an upload straight to disk or a service, provide a custom `Receiver` that returns your own stream. File
*downloads* are covered in xref:web/vaadin/rest-and-services.adoc[].

== Slider

https://vaadin.com/docs/latest/components/slider[`Slider`] picks a numeric value by dragging a thumb along a
track; `setMin`, `setMax` and `setStep` bound it, and a *range* variant with two thumbs selects an interval.

[source,java]
----
Slider volume = new Slider("Volume");
volume.setMin(0);
volume.setMax(100);
volume.setStep(5);
volume.setValue(60d);
volume.addValueChangeListener(e -> player.setVolume(e.getValue()));
----

For an integer-only control with a spinner instead of a track, use `IntegerField` with
`setStepButtonsVisible(true)`.

== Worked example: a sign-up form

The form below uses one field per kind of data and binds them all with a `Binder`. The name field uses the `LAZY`
mode, the e-mail and password rules live in `withValidator` (so their messages reach the `Binder`), and the date of
birth uses the field's own `setMax` constraint plus an error message.

[source,java]
----
public class SignUpForm extends FormLayout {

    private final TextField name = new TextField("Full name");
    private final EmailField email = new EmailField("Email");
    private final PasswordField password = new PasswordField("Password");
    private final DatePicker birthDate = new DatePicker("Date of birth");
    private final ComboBox<String> country = new ComboBox<>("Country");
    private final Checkbox terms = new Checkbox("I accept the terms");
    private final Binder<SignUp> binder = new Binder<>(SignUp.class);

    public SignUpForm(List<String> countries) {
        name.setMaxLength(60);
        name.setValueChangeMode(ValueChangeMode.LAZY);         // validate when the user pauses
        name.setValueChangeTimeout(400);

        password.setHelperText("At least eight characters");

        birthDate.setMax(LocalDate.now().minusYears(18));      // adults only
        birthDate.setErrorMessage("You must be at least 18");  // shown by the field's own constraint
        country.setItems(countries);

        binder.forField(name).asRequired("Tell us your name")
                .bind(SignUp::getName, SignUp::setName);
        binder.forField(email).asRequired("An email address is required")
                .withValidator(new EmailValidator("Not a valid email address"))
                .bind(SignUp::getEmail, SignUp::setEmail);
        binder.forField(password).asRequired("Choose a password")
                .withValidator(p -> p.length() >= 8, "At least eight characters")
                .bind(SignUp::getPassword, SignUp::setPassword);
        binder.forField(birthDate).asRequired("Date of birth is required")
                .bind(SignUp::getBirthDate, SignUp::setBirthDate);
        binder.forField(country).bind(SignUp::getCountry, SignUp::setCountry);
        binder.forField(terms)
                .withValidator(accepted -> accepted, "You must accept the terms")
                .bind(SignUp::isTermsAccepted, SignUp::setTermsAccepted);

        add(name, email, password, birthDate, country, terms);
    }

    public SignUp read() throws ValidationException {
        SignUp result = new SignUp();
        binder.writeBean(result);              // throws ValidationException if anything is wrong
        return result;
    }
}
----

`SignUp` is a plain bean with the six properties. Running the form with a blank `SignUp` loaded produces five
field errors (everything required except the optional country). Filling it with a ten-year-old birth date and a
five-character password leaves the date and password fields invalid; correcting both lets `read()` return the
populated bean. `EmailValidator` rejects an *empty* value by default, so in a form where e-mail is optional use
`new EmailValidator("Not a valid email address", true)` to accept blanks.
