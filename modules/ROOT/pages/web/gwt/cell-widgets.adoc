This page is written against GWT 2.13.1 (2026-06-19), `gwt-maven-plugin` 1.3.0 (`net.ltgt.gwt.maven`), JDK 21 running the compiler with `-sourceLevel 17`, and the Jakarta Servlet 6 server of the Bookshelf scenario, checked on 2026-10-08.
Cell widgets are **client** knowledge: they are classes of `gwt-user` (the `com.google.gwt.user.User` module inherits them) that the GWT compiler turns into JavaScript together with your code.
The data they show is usually **shared** with the server (the `Book` and `BookPage` classes travel over GWT-RPC), the **server** side of paging and sorting is a few lines of plain Java, and the **build** needs nothing beyond what any GWT module already has (see xref:web/gwt/project-structure-and-modules.adoc[Project Structure & Modules]).
Every example on this page was compiled with the 2.13.1 compiler and loaded in headless Chrome; the Bookshelf catalogue also ran against the Jetty 12 backend of the scratch application, and the HTML, the request payloads and the messages quoted below are what the browser and the compiler printed.

Cell widgets are the GWT answer to the question "how do I show a thousand rows without a thousand widgets?".
An ordinary widget (a `Label`, a `Button`, a row of a `FlexTable`) is a Java object with a DOM element, event handlers and a place in the widget hierarchy, so a table of 1,000 rows by 5 columns is 5,000 objects that have to be created, attached and eventually detached.
A **cell widget** (`CellList`, `CellTable`, `DataGrid`, `CellTree`, `CellBrowser`) keeps one HTML string per page of data instead: it asks a small, stateless **cell** to *render* each value into that string, assigns the whole string to the browser with `innerHTML`, and lets the cell look at events afterwards.
The same handful of cell objects serve every row, which is the flyweight pattern the official guide names.

== What a cell widget is

[[what]]
Four ideas explain almost everything on this page.

* **A cell renders a value into `SafeHtml`.** `Cell<C>` has a `render(Context, C, SafeHtmlBuilder)` method that appends HTML for one value. It does not create DOM nodes. A cell for a `String` is a few lines; a cell for a whole `Book` can be a `<div>` with an image and two lines of text.
* **A cell is a flyweight.** One `TextCell` object renders the title of row 1 and of row 10,000, and it receives the browser events of all those rows. It must not keep per-row state in its fields; the `Context` argument tells it *which* row and column it is working for.
* **A cell widget shows a page of rows.** Cell widgets are always **paged**: a widget has a *visible range* (a start index and a length), it renders only those rows, and it announces range changes. The page size defaults to 25 for `CellList`, 15 for `CellTable` and 50 for `DataGrid`. "No paging" simply means a page size as big as the data.
* **Data arrives through a data provider.** The widget does not own the data. A *data provider* is told which range the widget wants and pushes rows back with `updateRowData`. When the data changes, the provider pushes again and the widget re-renders the affected rows.

`CellPanel`, in spite of its name, is not a cell widget: it is a base class of table-based panels such as `HorizontalPanel` (the official guide makes the same remark).
The `Grid` and `FlexTable` panels that the 2007 book teaches hold ordinary widgets in table cells and are covered with the other panels (see the xref:web/gwt/panels-and-layout.adoc[Panels & Layout] and xref:web/gwt/widgets.adoc[Widgets] pages).

.Widgets in a table versus cell widgets
[cols="2,3,3",options="header"]
|===
| | `FlexTable` or `Grid` with widgets | `CellTable`, `DataGrid`, `CellList`

| Object per visible cell
| A `Widget` (plus its DOM element and handlers)
| None: the column's single `Cell` renders HTML

| Rendering
| DOM calls, widget by widget
| One HTML string per page, assigned with `innerHTML`

| Events
| One handler per widget
| One listener on the widget; the cell is told the row, column and key

| Large data
| Slows down with the number of rows on screen
| Cost follows the page size, not the data size

| Paging, sorting, selection
| Hand-written
| `HasData`, `ColumnSortList`, `SelectionModel` and pagers are part of the design

| Arbitrary widget inside a cell
| Natural
| Not directly: a cell renders HTML, not widgets, so a cell that must contain a full widget calls for a different design
|===

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellWidgets.html[GWT -- Developer Guide: Cell Widgets]

Choose a cell widget when the data set is large or changes often, when the columns map to data fields, when you need paging, sorting or selection, or when you want the table to stay cheap on a phone.
Choose a plain widget (or xref:web/gwt/uibinder.adoc[UiBinder]) for a small, form-like layout where each part is a different component.
A cell widget can still contain interactive parts: buttons, check boxes, text inputs and drop-downs are all built-in cells.

The module `com.google.gwt.user.User` already inherits `com.google.gwt.user.cellview.CellView`, so an application needs no extra `inherits` line.
The widgets bring their own styles as `ClientBundle`s (`CellTable.Resources`, `DataGrid.Resources`, `CellList.Resources` and so on), injected the first time a widget is created.

Source: https://github.com/gwtproject/gwt/blob/2.13.1/user/src/com/google/gwt/user/cellview/client/AbstractHasData.java[GWT source (2.13.1) -- AbstractHasData.java]

All the cell widgets that show a flat page of rows (`CellList`, `CellTable`, `DataGrid`) extend `AbstractHasData`, which is where the page size, `setRowData`, `setRowCount`, the selection model, the key provider and the keyboard policies live.
Since the data model is in `com.google.gwt.view.client` and not in the widgets, a view can be tested with a hand-written fake of `HasData`, and the same provider can feed a table and a pager at the same time.

== Cells

[[cells]]
=== The `Cell` interface

[[cell-interface]]
`Cell<C>` is an interface, but the Javadoc warns against implementing it directly: it may change in small but breaking ways as the library is tuned for speed, so extend `AbstractCell<C>` instead.
These are its methods in 2.13.1.

.The methods of `Cell<C>`
[cols="3,5",options="header"]
|===
| Method | Purpose

| `render(Context, C, SafeHtmlBuilder)`
| Append the HTML for a value. The only method `AbstractCell` leaves abstract.

| `getConsumedEvents()`
| The event types the cell wants (`+"click"+`, `+"keydown"+`, `+"change"+`...). Read once, when the cell is added to a widget.

| `onBrowserEvent(Context, Element, C, NativeEvent, ValueUpdater<C>)`
| Called when one of those events happens on something the cell rendered. `Element` is the *parent* element that contains the cell's HTML.

| `isEditing(Context, Element, C)`
| True while the cell shows an editor; the widget then leaves the cell alone when it re-renders.

| `setValue(Context, Element, C)`
| Re-render one cell in place (`AbstractCell` renders into a `SafeHtmlBuilder` and assigns it to the parent).

| `resetFocus(Context, Element, C)`
| Give focus back to the cell's focusable part after a re-render.

| `dependsOnSelection()`, `handlesSelection()`
| Whether the cell's HTML changes with the row's selection state, and whether the cell manages selection itself (a check box that is the selection).
|===

`Cell.Context` carries three facts about the instance that is being rendered: `getIndex()` (the row, as an absolute index), `getColumn()` and `getKey()` (the row's key from the `ProvidesKey`); a fourth, `getSubIndex()`, is 0 unless the row value renders to more than one row element (see the table builders below).
Nothing else about the row is passed: a cell receives the *value* of its column, not the row object.

The value of a cell can be `null`.
The official guide warns that cell widgets can pass `null` for rows that have no data yet, for example when data arrives in the middle of the visible range, so every `render` starts with a null check.

Source: https://www.gwtproject.org/javadoc/latest/com/google/gwt/cell/client/Cell.html[GWT Javadoc -- Cell]

=== Built-in cells

[[builtin-cells]]
All of these live in `com.google.gwt.cell.client`; every class name in the table exists in 2.13.1.

.The built-in cells
[cols="2,2,5",options="header"]
|===
| Cell | Value type | What it renders and does

| `TextCell`
| `String`
| Escaped text (no element at all, only the text). The default for a `TextColumn`.

| `ClickableTextCell`
| `String`
| Text (no element of its own, like `TextCell`) that calls the `ValueUpdater` on a click or on Enter.

| `EditTextCell`
| `String`
| Text that becomes an `<input>` when clicked. Return commits, Escape cancels. The edited text is kept as *view data* under the row's key.

| `TextInputCell`
| `String`
| An always-visible `<input type="text">`; it consumes the `change` and `keyup` events and calls the updater with the text.

| `ButtonCell`, `TextButtonCell`
| `String`
| A `<button>` whose label is the value. The value never changes: the updater only reports the click.

| `ActionCell<C>`
| `C`
| A button with a fixed label and a `Delegate<C>` whose `execute` is called with the cell's value on a click or on Enter.

| `CheckboxCell`
| `Boolean`
| A check box. `new CheckboxCell(true, false)` (depends on the selection, does not handle it) is the form used for a selection column; the one-argument `CheckboxCell(boolean isSelectBox)` is deprecated.

| `SelectionCell`
| `String`
| A `<select>` built from a `List<String>` of options.

| `DateCell`, `DatePickerCell`
| `Date`
| A formatted date (`DateTimeFormat` and optional `TimeZone`); the second one opens a month calendar for editing.

| `NumberCell`
| `Number`
| A number formatted with a `NumberFormat`.

| `ImageCell`, `SafeImageCell`, `ImageResourceCell`, `ImageLoadingCell`
| `String`, `SafeUri`, `ImageResource`, `String`
| Images from a URL, a sanitised URI, a `ClientBundle` resource, or a URL with a loading indicator.

| `SafeHtmlCell`
| `SafeHtml`
| Already-safe HTML, appended as is.

| `CompositeCell<C>`
| `C`
| Several cells side by side, each described by a `HasCell<C, X>` (a cell, how to get its value, an optional `FieldUpdater`).

| `IconCellDecorator<C>`
| `C`
| Adds an icon (an `ImageResource`) in front of another cell.
|===

The cells that take input (`EditTextCell`, `TextInputCell`, `CheckboxCell`, `SelectionCell`, `DatePickerCell`) extend `AbstractEditableCell`, which adds *view data*: a map from the row key to what the user typed but has not saved.
That is the second reason a `ProvidesKey` matters (see below): with the default key (the row object itself) a re-fetched row looks like a new row and the pending edit is lost.
The pending value stays until the row's underlying value changes (a successful commit) or until `AbstractEditableCell.clearViewData(key)` is called, which is what a failed save should do. An editable cell object shared by two columns or two widgets shares that pending state too, and the other widget shows it when it is next redrawn.

=== `ValueUpdater` and `FieldUpdater`

[[updaters]]
A cell tells the outside world about a user action through a `ValueUpdater<C>`: its single method `update(C newValue)` is called with the new value (the text typed, the box state, the selected option; for a button, the same value again as a "something happened" signal).
A cell widget with no columns, such as `CellList`, takes the updater directly with `setValueUpdater`.
A table column wraps it: `Column.setFieldUpdater(FieldUpdater<T, C>)` provides `update(int index, T row, C value)`, which is what you almost always want, because it knows the row.

An updater **does not re-render** anything.
It is a notification. The code in it must change the model and then ask for the affected row to be drawn again, as the pitfalls table below shows with a measurement.

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellWidgets.html#updating-database[GWT -- Developer Guide: Cell Widgets, updating a database from changes in a cell]

== `CellList`

[[celllist]]
`CellList<T>` is the simplest cell widget: one cell type renders every row, one row per `<div>`.
It is the right choice for a list of "cards" (a result list, a chat, a menu) and for the nodes of the two tree widgets, which are `CellList`-like internally.

The example fills a `CellList<Book>` through a `ListDataProvider`, identifies rows by the book id and selects one.
The cell is an `AbstractCell<Book>` that escapes the title and the author with `SafeHtmlBuilder`.

.A `CellList` of books with a key provider and a selection model (`CellLab.java`)
[source,java]
----
ProvidesKey<Book> keys = book -> book == null ? null : book.getId();

CellList<Book> list = new CellList<>(new AbstractCell<Book>() {
  @Override
  public void render(Context context, Book book, SafeHtmlBuilder sb) {
    if (book != null) {
      sb.appendEscaped(book.getTitle()).appendHtmlConstant(" <i>")
          .appendEscaped(book.getAuthor()).appendHtmlConstant("</i>");
    }
  }
}, keys);

SingleSelectionModel<Book> selection = new SingleSelectionModel<>(keys);
list.setSelectionModel(selection);

ListDataProvider<Book> provider = new ListDataProvider<>(keys);
provider.addDataDisplay(list);
provider.getList().addAll(books);
selection.setSelected(books.get(2), true);

// Rename the selected book, then push every row again:
books.get(2).setTitle("Refactoring, 2nd ed.");
provider.refresh();
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellWidgets.html#celllist[GWT -- Developer Guide: Cell Widgets, CellList]

Headless Chrome printed this for the five rows. The compiler obfuscates the style names (they were short generated names such as `+GBG2FFLDAB+`); the excerpt writes each one as the `CellList.Style` method it stands for.
The third row is the selected one and it is still selected after the rename and `refresh()`; the first row carries the keyboard-focus style and the only `tabindex`. Because the lab renamed the very same object, this does not prove the key provider; the section on keys below measures that.
The fourth title is the text `<script>alert(1)</script> Tricks`: it arrived as text, not as markup.

== `CellTable`

[[celltable]]
`CellTable<T>` renders a page of rows of type `T` as an HTML `<table>`; each **column** shows one aspect of the row.
A `Column<T, C>` has to implement `getValue(T row)`, and a `Cell<C>` (given to its constructor) renders that value.
`TextColumn<T>` is the shortcut for a text column (`Cell<String>` is a `TextCell`), and `IdentityColumn<T>` passes the row itself to the cell, which is what a `CompositeCell` or an "actions" cell needs.

=== A table with the built-in cells

[[builtin-example]]
The example below shows a table of **loans**, with one column per interesting built-in cell.
`Loan` is a client-side class here (title, due date, returned flag, status); the table itself would look the same with any row type.

.A `CellTable<Loan>`: check box, editable text, date, drop-down, number, clickable text, button and a composite (`CellLab.java`)
[source,java]
----
ProvidesKey<Loan> keys = loan -> loan.id;
CellTable<Loan> table = new CellTable<>(10, keys);

// A selection model driven by the check boxes only:
MultiSelectionModel<Loan> selection = new MultiSelectionModel<>(keys);
table.setSelectionModel(selection, DefaultSelectionEventManager.<Loan>createCheckboxManager());

Column<Loan, Boolean> pick = new Column<Loan, Boolean>(new CheckboxCell(true, false)) {
  @Override
  public Boolean getValue(Loan loan) { return selection.isSelected(loan); }
};
table.addColumn(pick, "");
table.setColumnWidth(pick, 3, Unit.EM);

Column<Loan, String> title = new Column<Loan, String>(new EditTextCell()) {
  @Override
  public String getValue(Loan loan) { return loan.title; }
};
title.setSortable(true);
title.setFieldUpdater((index, loan, value) -> loan.title = value);
table.addColumn(title, "Title", "titles");                       // header and footer text

table.addColumn(new Column<Loan, Date>(new DateCell(DateTimeFormat.getFormat("yyyy-MM-dd"))) {
  @Override
  public Date getValue(Loan loan) { return loan.due; }
}, "Due", "dates");

Column<Loan, String> status =
    new Column<Loan, String>(new SelectionCell(Arrays.asList("ok", "late", "lost"))) {
      @Override
      public String getValue(Loan loan) { return loan.status; }
    };
status.setFieldUpdater((index, loan, value) -> loan.status = value);
table.addColumn(status, "Status");

Header<String> fineTotal = new Header<String>(new TextCell()) {   // a footer that follows the data
  @Override
  public String getValue() {
    double total = 0;
    for (Loan loan : table.getVisibleItems()) {
      total += loan.id * 1234.5;
    }
    return "Total " + NumberFormat.getFormat("#,##0.00").format(total);
  }
};
table.addColumn(new Column<Loan, Number>(new NumberCell(NumberFormat.getFormat("#,##0.00"))) {
  @Override
  public Number getValue(Loan loan) { return loan.id * 1234.5; }
}, new TextHeader("Fine"), fineTotal);

table.addColumn(new Column<Loan, String>(new ClickableTextCell()) {
  @Override
  public String getValue(Loan loan) { return "details"; }
});
table.addColumn(new Column<Loan, String>(new ButtonCell()) {
  @Override
  public String getValue(Loan loan) { return "Return"; }
});

List<HasCell<Loan, ?>> parts = new ArrayList<>();
parts.add(/* a HasCell<Loan, String> with a TextCell showing "#" + id */);
parts.add(/* a HasCell<Loan, Loan> with ActionCell<>("Renew", loan -> loan.due = nextWeek(loan)) */);
table.addColumn(new IdentityColumn<>(new CompositeCell<>(parts)), "Actions");
----

What the experiment also showed:

* The `CheckboxCell(true, false)` combined with `createCheckboxManager()` made a click on a **check box** select a row (the row got the selected style and the box was checked), while a click on any other cell of the row only moved the keyboard focus. With `createDefaultManager()` (the default) a click on the row would select it, with the control key to add to the selection and, for a `MultiSelectionModel`, the shift key to select a range.
* Headers and footers are `Header` objects, rendered every time the row data changes or the table is redrawn. Passing the *same* header instance to adjacent columns makes it span them: the two columns without a header received `null` for it and shared one `colspan="2"` cell.
* The footer total is recomputed on every render because `Header.getValue()` is called then; that is why a header can show a sum, a count or a filter box.

=== Column and cell styling

[[table-styling]]
`Column.setCellStyleNames("name")` sets a style for every cell of a column, and `Column.getCellStyleNames(Cell.Context, T row)` can return a style per cell, as the Bookshelf catalogue does for books with no copies left.
`AbstractCellTable.setRowStyles(RowStyles<T>)` takes an object with `getStyleNames(T row, int rowIndex)` for the whole row.
`setColumnWidth(Column, double, Unit)` and `setColumnWidth(Column, String)` control widths, `+Column.setHorizontalAlignment(...)+` and `+setVerticalAlignment(...)+` the alignment, and `addColumnStyleName(int, String)` a style on a `<col>`.

The widths need a fixed layout to be reliable.
By default the columns grow to fit the contents of their cells, which looks jumpy when the content changes with paging; `table.setWidth("100%", true)` switches to the fixed table layout and lets you give the columns percentages (which should add up to 100%), pixels, or a mix: a narrow pixel column for a check box and percentages for the rest.
The official guide adds that with `table.setWidth("auto", true)` a column without a width is invisible, because its width defaults to 0.

The look of the widget itself comes from its `Resources` bundle.
`CellTable.Resources` defines `cellTableStyle()` (a `CellTable.Style` `CssResource` whose default stylesheet is `CellTable.css`) and the images for the header and footer backgrounds, the loading indicator and the sort arrows; `CellTable.BasicResources` is the variant for the GWT standard style theme and uses `CellTableBasic.css`.
To restyle it, extend `CellTable.Resources`, re-declare `cellTableStyle()` with `+@Source({CellTable.Style.DEFAULT_CSS, "mytable.gss"})+` and pass an instance to a constructor such as `CellTable(int pageSize, Resources resources)`; the CSS and GSS directives are the subject of the xref:web/gwt/styling-css-and-gss.adoc[Styling: CSS & GSS] page.

=== Taking over the table's HTML

[[table-builders]]
For layouts the column model cannot express (several rows per item, a detail row under an expanded item, group headers) a table can be given its own markup builders: `AbstractCellTable.setTableBuilder(CellTableBuilder)`, `setHeaderBuilder(HeaderBuilder)` and `setFooterBuilder(FooterBuilder)`, with `AbstractCellTableBuilder`, `DefaultCellTableBuilder` and `AbstractHeaderOrFooterBuilder` as starting points.
They came with GWT 2.5 (see the older-material section) and are the escape hatch to use instead of abandoning the cell table for a hand-made `FlexTable`.

Source: https://www.gwtproject.org/javadoc/latest/com/google/gwt/user/cellview/client/CellTable.html[GWT Javadoc -- CellTable]

== Sorting

[[sorting]]
A cell table does not sort anything by itself; it provides the *user interface* and an *event*, and you decide where the sort happens.

. `column.setSortable(true)` makes the column header clickable (`role="button"`) and shows an arrow once it is the sort column.
. A click on the header pushes the column onto the table's `ColumnSortList` and fires a `ColumnSortEvent`.
. Handlers registered with `+table.addColumnSortHandler(...)+` react.

Two handlers ship with GWT, one for each kind of data provider.

.The two sort handlers
[cols="2,3,3",options="header"]
|===
| | `ColumnSortEvent.ListHandler<T>` | `ColumnSortEvent.AsyncHandler`

| Use with
| `ListDataProvider`: the data is in the browser
| `AsyncDataProvider`: the data is on the server

| What it does
| Looks up the `Comparator<T>` registered for the sorted column and sorts the `java.util.List` it was given (use `provider.getList()`), descending order by negating the comparator
| Calls `setVisibleRangeAndClearData(currentRange, true)` on the widget, which clears the rows and fires a `RangeChangeEvent`, so the provider's `onRangeChanged` runs again

| What you write
| One `setComparator(column, comparator)` per sortable column
| The provider reads `table.getColumnSortList()` and sends the field and the direction to the server
|===

.Local sorting with `ListHandler` (`CellLab.java`)
[source,java]
----
ColumnSortEvent.ListHandler<Loan> sorter = new ColumnSortEvent.ListHandler<>(provider.getList());
sorter.setComparator(title, Comparator.comparing(l -> l.title));
table.addColumnSortHandler(sorter);

// Mark the initial order in the header (this does not fire the event by itself):
table.getColumnSortList().push(title);
ColumnSortEvent.fire(table, table.getColumnSortList());
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellTable.html#columnSorting[GWT -- Developer Guide: Cell Tables, column sorting]

The loans came out ordered "Clean Code", "Effective Java", "Refactoring"; clicking the sorted header then reversed the order, because `ColumnSortList.push(column)` on the column that is already first *flips its direction* (ascending becomes descending and back).
That flip is why the lab pushed the column programmatically only once.

The sort list can hold more than one column (`ColumnSortList.setLimit`), which a server-side sorter can use for "sort by author, then by year".
`Column.setDefaultSortAscending(false)` makes the first click sort descending, for a "newest first" date column.
The server-side variant, with `AsyncHandler`, is the Bookshelf example further down.

Two behaviours of `ListHandler` follow from its source: a column that is `setSortable(true)` but has **no comparator** registered is silently ignored (the arrow moves, the rows stay), and `onColumnSort` sorts the list with `Collections.sort`, so the list must be modifiable.

== `DataGrid`

[[datagrid]]
`DataGrid<T>` is the `CellTable` for application screens: its Javadoc describes it as a table with a fixed header and footer and a scrollable data section between them. It was added in GWT 2.4.
Both extend `AbstractCellTable`, so columns, headers, footers, sorting, widths, row styles, selection, key providers and table builders work the same way, and a `CellTable` can usually be turned into a `DataGrid` by changing the class name and the place it is put in.

.`CellTable` and `DataGrid`
[cols="2,3,3",options="header"]
|===
| | `CellTable` | `DataGrid`

| Default page size
| 15
| 50

| Scrolling
| The table grows with its rows and the *page* scrolls
| The header and footer stay in place and the data section scrolls inside the widget

| Layout
| An ordinary widget: it takes the height of its content
| Implements `RequiresResize`: it fills the space its parent *gives* it

| Typical parent
| A `FlowPanel`, `VerticalPanel`, `ScrollPanel`
| A layout panel: `RootLayoutPanel`, `DockLayoutPanel`, `SplitLayoutPanel`, `SimpleLayoutPanel`, or any element with a size

| Width control
| `setWidth(String, boolean)`, `setColumnWidth`
| `setColumnWidth`, plus `setTableWidth(double, Unit)`, `setMinimumTableWidth(double, Unit)`, `clearTableWidth()`, `setAlwaysShowScrollBars(boolean)`

| Resources
| `CellTable.Resources`, `CellTable.Style`
| `DataGrid.Resources`, `DataGrid.Style` (default stylesheet `DataGrid.css`)

| Best for
| Short tables embedded in a page
| A list that takes a screen, or a pane in a split layout
|===

Source: https://www.gwtproject.org/javadoc/latest/com/google/gwt/user/cellview/client/DataGrid.html[GWT Javadoc -- DataGrid]

The consequence of `RequiresResize` is the most common `DataGrid` surprise: **a `DataGrid` placed in a parent that does not give it a size shows only its header.**
The lab put the same grid twice, once in a plain `FlowPanel` and once in a `SimpleLayoutPanel` of `20em` by `10em`, and asked the browser for the markup.

.A `DataGrid` in a `FlowPanel`: the data section has height 0 (`s7`), and in a `SimpleLayoutPanel` it has 104px (`s8`)
[source,html]
----
<!-- FlowPanel: header at top: 0, data section starts at top: 26px and is 0px high -->
<div style="position: absolute; left: 0px; width: 100%; overflow: hidden; top: 26px; height: 0px;">

<!-- SimpleLayoutPanel of 20em x 10em: the same div is 104px high and the five rows fit -->
<div style="position: absolute; left: 0px; width: 100%; overflow: hidden; top: 26px; height: 104px;">
----

There was no error and no log message: the grid had been given data (the rows were in the markup) but no room to show them.
The fix is always the same: put the grid in a layout panel (`RootLayoutPanel.get().add(grid)`, the center of a `DockLayoutPanel`, a `SimpleLayoutPanel` with a size) or give its host element a CSS height.
This is the same layout rule that makes a `DockLayoutPanel` inside a plain `SimplePanel` render blank, covered on the xref:web/gwt/panels-and-layout.adoc[Panels & Layout] page.

== `CellTree` and `CellBrowser`

[[trees]]
A **tree** cell widget shows hierarchical data without a widget per node.
The widgets know nothing about your hierarchy; a **`TreeViewModel`** answers two questions:

. `<T> NodeInfo<?> getNodeInfo(T value)`: "the children of this value are provided by this data provider, rendered by this cell, selected through this selection model".
. `boolean isLeaf(Object value)`: "this value cannot be opened".

The tree asks `getNodeInfo(rootValue)` for the first level, where `rootValue` is the object you pass to the constructor and the tree never displays (`null` is accepted), and calls it again with the value of each node that the user opens.
`NodeInfo<T>` is an interface with a cell, a key provider, a selection model, a value updater and the `setDataDisplay`/`unsetDataDisplay` that attach a list to the node; `TreeViewModel.DefaultNodeInfo<T>` implements it from a data provider and a cell (and optionally a selection model and a value updater), which covers nearly every case.

.A catalogue tree: authors, then the books of an author (`CatalogTreeModel.java`)
[source,java]
----
public class CatalogTreeModel implements TreeViewModel {
  private final List<Book> books;
  private final SingleSelectionModel<Book> bookSelection = new SingleSelectionModel<>(b -> b.getId());

  public CatalogTreeModel(List<Book> books) {
    this.books = books;
  }

  @Override
  public <T> NodeInfo<?> getNodeInfo(T value) {
    if (value == null) {                         // the hidden root: its children are the authors
      ListDataProvider<String> authors = new ListDataProvider<>();
      authors.getList().addAll(new TreeSet<>(authorNames()));
      return new DefaultNodeInfo<>(authors, new TextCell());
    }
    String author = (String) value;              // an author node: its children are the books
    ListDataProvider<Book> byAuthor = new ListDataProvider<>(b -> b.getId());
    for (Book b : books) {
      if (b.getAuthor().equals(author)) {
        byAuthor.getList().add(b);
      }
    }
    return new DefaultNodeInfo<>(byAuthor, new AbstractCell<Book>() {
      @Override
      public void render(Context context, Book book, SafeHtmlBuilder sb) {
        if (book != null) {
          sb.appendEscaped(book.getTitle());
        }
      }
    }, bookSelection, null);
  }

  @Override
  public boolean isLeaf(Object value) {
    return value instanceof Book;
  }
}
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellWidgets.html#celltree[GWT -- Developer Guide: Cell Widgets, CellTree]

The model is the same for both widgets.
`CellTree` shows the levels one under the other, with an open/close arrow and an optional animation; `CellBrowser` shows each opened level in a column of its own, side by side like a file browser.

.The tree and the browser over the same model (`CellLab.java`)
[source,java]
----

tree.setAnimationEnabled(false);
tree.getRootTreeNode().setChildOpen(0, true);     // open the first author

browser.setAnimationEnabled(false);
browser.getRootTreeNode().setChildOpen(0, true);
browser.setHeight("12em");
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCellWidgets.html#celltree[GWT -- Developer Guide: Cell Widgets, CellTree and CellBrowser]

A `TreeNode` (from `getRootTreeNode()`) lets code walk and change the tree: `getChildCount()`, `getChildValue(int)`, `isChildLeaf(int)`, `isChildOpen(int)` and `setChildOpen(int, boolean)`.

== Data providers, ranges and pagers

[[data]]
=== `HasData`, `HasRows` and `Range`

[[hasdata]]
A cell widget exposes its paging state through `HasRows`: `getVisibleRange()`, `setVisibleRange(int start, int length)`, `getRowCount()`, `isRowCountExact()`, `setRowCount(int)` and `setRowCount(int, boolean)`, plus handlers for `RangeChangeEvent` and `RowCountChangeEvent`.
`HasData<T>` adds `setRowData(int start, List<? extends T>)`, `getVisibleItem(int)`, `getVisibleItems()` and `setSelectionModel`.
A `Range` is the pair *start index, length* (`new Range(0, 10)`), a plain serializable value class, so it can also be an argument of an RPC method.

The **row count** is separate from the rows: a widget can show rows 10 to 19 and still know that there are 25 in all.
The count can be *exact* or an *estimate*: when a count is not exact, the pager shows "of over N" and lets the user keep going while data keeps arriving, which suits a stream or a server that cannot count cheaply.

=== `ListDataProvider`

[[listdataprovider]]
`ListDataProvider<T>` is a provider whose data is a `java.util.List` in the browser.
`getList()` returns a *wrapper* of the list: every change made through it (`add`, `set`, `remove`, `clear`, `sort`) is noticed and pushed to the displays, **at the end of the current event loop**, so several changes cost one refresh.
`flush()` pushes immediately, `refresh()` re-sends every row, and `setList(List)` replaces the underlying list.
The page size of the display decides which rows of the list are shown, so a list of 200 items and a `CellList` of 25 produce eight pages without further code.

The wrapper cannot see changes **inside** the items: the Javadoc says so, and the lab measured it with a `CellList` showing one `Book`.

.Changing an item behind the provider's back (`CellLab.java`, results in the page text)
[cols="3,3",options="header"]
|===
| Step | Row 0 after the browser rendered it

| rendered with the title "Before"
| `Before`

| `book.setTitle("After")` then `provider.flush()`
| `Before` (nothing changed)

| `provider.refresh()`
| `After`

| `book.setTitle("After list.set")` then `provider.getList().set(0, book)`
| `After list.set`
|===

`getList().set(index, item)` is the cheaper way when one row changed: the provider knows which rows were modified and pushes only those, while `refresh()` pushes all.
After a `FieldUpdater` changed an item in place, either of the two (or `display.redrawRow(index)` for one row, as the pitfalls table shows) is needed.

Source: https://github.com/gwtproject/gwt/blob/2.13.1/user/src/com/google/gwt/view/client/ListDataProvider.java[GWT source (2.13.1) -- ListDataProvider.java]

=== `AsyncDataProvider`

[[asyncdataprovider]]
`AsyncDataProvider<T>` is for data that lives on a server or is expensive to produce.
It is deliberately small: you subclass it and implement a single method.

[source,java]
----
protected abstract void onRangeChanged(HasData<T> display)
----

GWT calls that method **whenever a display needs a different range**: the moment the display is added with `addDataDisplay` (the display's current visible range is "initialised" right away, which is why adding the display is the signal to load the first page), when the user pages, when the page size changes, and after a sort when `AsyncHandler` clears the data.
The method's job is to read `display.getVisibleRange()`, start the request and, when the answer comes, call two methods that `AsyncDataProvider` makes public:

* `updateRowCount(int count, boolean exact)` tells all displays how many rows exist.
* `updateRowData(int start, List<T> values)` gives them the rows that start at index `start`.

The provider does not hold on to the data: it forwards to each display only the rows that fall inside that display's visible range (an empty list that starts at the page start is delivered too) and ignores the rest, so a late answer for an old range does not put foreign rows on the page.
The only state it keeps is the last row count it was told, which it passes to a display that is added later.

The guide's own example simulates the server with a `Timer` and ends with `cellList.setRowData(start, dataInRange)` on the *widget*.
That works for one display, but `updateRowData` on the *provider* is the call that serves every display attached to it (a table and a list showing the same query) and applies the range check, so use it in real code.

The guide also describes a provider-less way: a widget fires `RangeChangeEvent`s, so a presenter can listen with `addRangeChangeHandler`, send a request and push rows with `setRowData`; force the first event with `setVisibleRangeAndClearData(new Range(0, 25), true)`.
A data provider is just that code, written once.

==== Out-of-order answers

[[stale-answers]]
Two requests can be in flight at once (the user pages twice, or sorts while a page is loading), and the network does not promise to answer them in order.
The provider cannot know which answer is newer, so the code that owns the request does: the Bookshelf presenter below numbers each request and drops a response that is not the latest, and a JVM unit test delays the first answer and checks that the late one is ignored.

=== Pagers

[[pagers]]
A pager is a widget that is connected to any `HasRows` with `setDisplay(HasRows)` and calls `setVisibleRange` on it.
Because it listens to `RangeChangeEvent` and `RowCountChangeEvent`, it works the same on a `CellList`, a `CellTable`, a `DataGrid`, a custom `HasRows`, and when the data comes from either provider.

.The pagers in `com.google.gwt.user.cellview.client`
[cols="2,6",options="header"]
|===
| Pager | Behaviour

| `SimplePager`
| First/previous/next/last-page buttons (image buttons with `role="button"` and `aria-label` "First page", "Previous page", "Next page"), a "1-10 of 25" label and an optional fast-forward button (1,000 rows by default). Constructors take a `SimplePager.TextLocation` (`CENTER`, `LEFT`, `RIGHT`), the fast-forward switch and distance, and a `SimplePager.Resources`.

| `PageSizePager`
| "Show More" and "Show Less" links that grow or shrink the *page size* by an increment (`new PageSizePager(50)`). The widget keeps its start and shows more rows: an "infinite list" pattern.

| `AbstractPager`
| The base class for your own: a `Composite` that implements `onRangeOrRowCountChanged()` and has protected helpers `firstPage()`, `nextPage()`, `previousPage()`, `lastPage()`, `setPage(int)`, `getPageCount()`, `hasNextPage()` and so on.
|===

`AbstractPager.setRangeLimited(boolean)` decides whether the paging operations adjust so that there is always data visible on the page ("range limited") or not.

The label depends on whether the provider told the widget the **exact** row count.
The lab connected a `SimplePager` to a `CellTable` of page size 5 over five books, once with an `AsyncDataProvider` that called only `updateRowData`, and once with `updateRowCount(5, true)` first:

.What the pager printed
[cols="3,2,2",options="header"]
|===
| Provider calls | Label | `getRowCount()` and `isRowCountExact()`

| `updateRowData` only
| `1-5 of over 5`
| 5 and `false`

| `updateRowCount(5, true)` then `updateRowData`
| `1-5 of 5`
| 5 and `true`
|===

Without the count the pager has no way to know that the data ends, and the next-page button stays enabled.
Always call `updateRowCount` with the real total as soon as the server knows it (the Bookshelf page carries the total in `BookPage`).

== Selection and keys

[[selection]]
A cell widget does not store which rows are selected; it asks its **selection model**, and tells it when the user selects.
The model decides what "selected" means, can be shared by several widgets, and fires `SelectionChangeEvent`.

.The selection models
[cols="2,6",options="header"]
|===
| Model | Behaviour

| `SingleSelectionModel<T>`
| At most one selected item: `getSelectedObject()`, `setSelected`, `clear()`, `getSelectedSet()`.

| `MultiSelectionModel<T>`
| Any number of selected items: `getSelectedSet()`, `clear()`. `OrderedMultiSelectionModel<T>` keeps the order of selection (it uses `LinkedHashMap`, which can add to the compiled size).

| `NoSelectionModel<T>`
| Nothing is ever selected, but the widget still fires events: `getLastSelectedObject()` and the change handler turn a list into a list of clickable items (a menu) without the "selected" highlight.

| `DefaultSelectionModel<T>`
| An abstract base class that selects by default and records the exceptions: you implement `isDefaultSelected(T)`. The guide suggests it for special cases such as "select all" across several pages.
|===

A model is attached with `setSelectionModel(model)`, optionally with a second argument, an event manager, that decides *which user actions select*.
`DefaultSelectionEventManager` is a `CellPreviewEvent.Handler`: the widget fires a `CellPreviewEvent` for every cell event before the cell sees it, and the manager turns clicks and the space bar into `SelectionModel.setSelected` calls.

.The factories of `DefaultSelectionEventManager`
[cols="3,5",options="header"]
|===
| Factory | Selection happens when

| `createDefaultManager()`
| A click or the space bar on a row. The control key toggles; with a `MultiSelectionModel` the shift key selects a range. This is what a widget uses when you do not pass a manager.

| `createCheckboxManager()` and `createCheckboxManager(int column)`
| A click on a check box (in any column, or in the given one). Clicking elsewhere does not select, as the lab measured.

| `+createBlacklistManager(int...)+` and `+createWhitelistManager(int...)+`
| A click on a column that is not in the blacklist, or that is in the whitelist.

| `createCustomManager(EventTranslator)`
| Whatever your `EventTranslator<T>` returns for each event: a `SelectAction` of `DEFAULT`, `SELECT`, `DESELECT`, `TOGGLE` or `IGNORE`.
|===

Source: https://www.gwtproject.org/javadoc/latest/com/google/gwt/view/client/DefaultSelectionEventManager.html[GWT Javadoc -- DefaultSelectionEventManager]

=== `ProvidesKey`

[[keys]]
Every selection model, data provider and cell widget can be given a `ProvidesKey<T>`, whose single method `Object getKey(T item)` returns the **identity** of an item.
Without one, an item is its own key and the model uses `equals` and `hashCode` (`SimpleKeyProvider` is that default).
The keys matter in three places:

* **Selection survives new instances.** A server answer creates new `Book` objects every time, so a model that remembers the *objects* would forget the selection at each page load. With the book id as key it recognises them.
* **Edits survive a redraw.** `EditTextCell` and the other input cells keep their pending text as view data under the key.
* **Updates reach the right row.** Row events carry the key in the `Context`.

The lab compared two `SingleSelectionModel<Book>` instances, one without and one with a key provider that returns the id, after `setSelected(book)` and then `isSelected(sameBookAgain)` with a *new* `Book` object with the same id:

.Selection with and without a key provider
[cols="3,2",options="header"]
|===
| Model | `isSelected(newInstanceWithTheSameId)`

| `new SingleSelectionModel<>()`
| `false`

| `+new SingleSelectionModel<>(b -> b.getId())+`
| `true`
|===

Give the **same** key provider to the widget, the data provider and the selection model, and make `getKey` null-safe, because widgets call it with `null` for filler rows (the guide says "always do a null check").
The `Book::getId` method reference used in the Bookshelf `DataGrid` constructor is not null-safe, but there it only ever receives books that the grid is rendering.

=== Keyboard

[[keyboard]]
`setKeyboardSelectionPolicy` takes a `KeyboardSelectionPolicy`: `DISABLED`, `ENABLED` (the default: the arrow keys move a focus highlight, the first row has `tabindex="0"`) or `BOUND_TO_SELECTION` (the arrow keys also change the selection).
`setKeyboardPagingPolicy` takes `CURRENT_PAGE`, `CHANGE_PAGE` (the default: the arrow keys can move into the next page) or `INCREASE_RANGE` (the page grows).
The focus highlight is a style of its own (`cellListKeyboardSelectedItem` in the `CellList` output above), separate from the selected style, which is what the `+tabindex="0"+` row and the `role="button"` headers make reachable without a mouse.
A cell that handles the Enter key through `onEnterKeyDown` (see below) is activated from the keyboard the same way.

== Custom cells

[[custom-cells]]
The built-in cells cover forms and tables; a custom cell is how a book, an author or a rating gets its own look without a widget per row.
The recipe has four steps, and every step is a decision the guide spells out.

. **Extend `AbstractCell<C>`**, with `C` the type of value the cell shows. The constructor lists the events the cell wants: `super("click", "keydown")`.
. **Implement `render(Context, C, SafeHtmlBuilder)`.** Check for `null`, escape anything that came from a user, and append HTML.
. **Override `+onBrowserEvent(...)+`** if the cell reacts to events, and `+onEnterKeyDown(...)+` for the keyboard.
. **Report changes** by calling the `ValueUpdater` that is passed in (it can be `null`).

=== Rendering safely: `SafeHtmlBuilder` and `SafeHtmlTemplates`

[[safehtml]]
The HTML a cell appends is assigned to the page without any further escaping, so the cell is where cross-site scripting is prevented or allowed.
`SafeHtmlBuilder` supports the safe habit: `appendEscaped(String)` turns `<` and `&` into entities, `appendHtmlConstant(String)` is for literals written by the developer (never for data) and `append(SafeHtml)` adds something already known to be safe (the xref:web/gwt/safehtml-and-xss.adoc[SafeHtml & XSS] page covers the type system behind it).
The lab fed the title `<script>alert(1)</script> Tricks` to a cell that used `appendEscaped`, and the browser received `&lt;script&gt;alert(1)&lt;/script&gt; Tricks`, displayed as text.

For anything with attributes, string concatenation quickly gets unreadable and unsafe, so GWT generates the code from a **template**: an interface that extends `SafeHtmlTemplates`, with one method per fragment and the HTML in an annotation.
The type of each parameter says how it is escaped: a `String` is escaped as text or as an attribute value, a `SafeHtml` is inserted as is, `SafeStyles` goes in a `style` attribute and `SafeUri` in a `href` or `src`.

The lab's `CopiesBadgeCell` shows the number of copies of a book as a small badge; clicking it (or pressing Enter on it) asks to borrow a copy.

.A custom cell with a template and events (`CopiesBadgeCell.java`)
[source,java]
----
public class CopiesBadgeCell extends AbstractCell<Integer> {

  interface Templates extends SafeHtmlTemplates {
    @SafeHtmlTemplates.Template("<span class=\"{0}\" title=\"{1}\">{2}</span>")
    SafeHtml badge(String styleName, String tooltip, String text);
  }

  private static final Templates TEMPLATES = GWT.create(Templates.class);

  public CopiesBadgeCell() {
    super("click", "keydown");               // the events this cell wants to receive
  }

  @Override
  public void render(Context context, Integer copies, SafeHtmlBuilder sb) {
    if (copies == null) {
      return;                                // widgets pass null for filler cells
    }
    String style = copies == 0 ? "bk-badge bk-out" : "bk-badge";
    String text = copies == 0 ? "none left" : copies + " left";
    sb.append(TEMPLATES.badge(style, "Row " + context.getIndex(), text));
  }

  @Override
  public void onBrowserEvent(Context context, Element parent, Integer copies, NativeEvent event,
      ValueUpdater<Integer> updater) {
    super.onBrowserEvent(context, parent, copies, event, updater);   // Enter -> onEnterKeyDown
    if ("click".equals(event.getType())
        && parent.getFirstChildElement().isOrHasChild(Element.as(event.getEventTarget()))) {
      borrow(copies, updater);
    }
  }

  @Override
  protected void onEnterKeyDown(Context context, Element parent, Integer copies, NativeEvent event,
      ValueUpdater<Integer> updater) {
    borrow(copies, updater);
  }

  private void borrow(Integer copies, ValueUpdater<Integer> updater) {
    if (copies != null && copies > 0 && updater != null) {
      updater.update(copies - 1);
    }
  }
}
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiCustomCells.html#cell-render[GWT -- Developer Guide: Custom Cells]

The pieces to notice:

* `GWT.create(Templates.class)` is deferred binding (see xref:web/gwt/deferred-binding-and-generators.adoc[Deferred Binding & Generators]): the compiler generates the implementation and checks the template while it compiles, so a typo in a placeholder is a build error and not a runtime surprise. The messages are in the pitfalls table.
* The `title` attribute is a `String` parameter, so a book title with a quote in it cannot break out of the attribute.
* `parent` in `onBrowserEvent` is the element that *contains* the cell's HTML, not the outermost element the cell wrote (a `TextCell` writes no element at all). `parent.getFirstChildElement().isOrHasChild(target)` is the guide's test for "the click really hit what I rendered".
* `+super.onBrowserEvent(...)+` is called first because `AbstractCell` is what turns a `keydown` with the Enter key into a call of `onEnterKeyDown`. The cell must list `"keydown"` among its events for that to happen.

=== What happens when the user clicks

[[cell-events]]
A cell widget does not attach a handler to each cell.
When a column (or a `CellList`) is created, the widget asks every cell for `getConsumedEvents()` **once** and sinks exactly those events on its root element.
When the browser delivers one, the widget finds the row and column from the attributes in the markup (`+__idx+`, `+__gwt_row+`, `+__gwt_cell+`), builds the `Context`, offers the event to the selection manager as a `CellPreviewEvent`, and hands it to the cell.

=== Combining cells: `CompositeCell` and `HasCell`

[[compositecell]]
One table cell can hold several cells.
`CompositeCell<C>` takes a `List<HasCell<C, ?>>`; each `HasCell<C, X>` names a `Cell<X>`, how to get its value `X` from the cell's value `C` and an optional `FieldUpdater<C, X>`.
Each part is rendered in a `<span>` of its own, and the composite hands every event to the part that rendered the target.
The loan table above ends with an "Actions" column built this way (rendered `<span>#3</span><span><button …>Renew</button></span>`): a `TextCell` that shows the loan number and an `ActionCell` whose `Delegate` extends the due date.
`IdentityColumn<T>` is the column to use with it, because the composite's value is the whole row.

`IconCellDecorator<C>` wraps one cell and puts an `ImageResource` in front of it (the constructor can also set the vertical alignment); it is the lightweight way to add an icon to a built-in cell without writing a new one.

=== Rules of thumb

[[cell-rules]]
* **Cells are shared:** a field of the cell holds configuration (a format, a style name), never the row being rendered.
* **Escape everything that came from outside**, including titles, author names, file names and data that comes from the server. Use `appendEscaped`, a `String` template parameter, or a `SafeHtmlRenderer`; do not build markup by string concatenation and do not use `appendHtmlConstant` on data.
* **Return early on `null`.**
* **Keep a cell's HTML small**; it is generated for every visible row, on every redraw.
* **Make interactive parts reachable by keyboard**: a `<button>` is focusable, a `<span>` with a click handler is not; add `tabindex` and handle Enter, as `ClickableTextCell` does, or use a button.

== `@UiRenderer`: cells from UiBinder templates

[[uirenderer]]
Writing HTML in Java strings, even with templates, is awkward for anything with structure.
GWT 2.5 added a second way to produce a cell's HTML: a xref:web/gwt/uibinder.adoc[UiBinder] template with **no widgets**, only HTML elements, and a generated *renderer*.
You declare an interface that extends `UiRenderer` with a `render` method whose first parameter is a `SafeHtmlBuilder`, and the compiler writes the implementation from `OwnerClass.ui.xml`.

The lab's `AuthorChipCell` renders an "author chip" (name and number of titles) for a value of the nested type `Author`.

.The template: `AuthorChipCell.ui.xml`
[source,xml]
----
<ui:UiBinder xmlns:ui="urn:ui:com.google.gwt.uibinder">
  <ui:with field="name" type="java.lang.String"/>
  <ui:with field="titles" type="java.lang.String"/>
  <span ui:field="chip" class="bk-chip"><b><ui:text from="{name}"/></b> (<ui:text from="{titles}"/>)</span>
</ui:UiBinder>
----

.The cell with the renderer interface and an event handler (`AuthorChipCell.java`)
[source,java]
----
public class AuthorChipCell extends AbstractCell<AuthorChipCell.Author> {

  public static class Author {
    final String name;
    final int titles;
    public Author(String name, int titles) { this.name = name; this.titles = titles; }
  }

  interface Renderer extends UiRenderer {
    void render(SafeHtmlBuilder sb, String name, String titles);      // names match the ui:with fields

    void onBrowserEvent(AuthorChipCell owner, NativeEvent event, Element parent, Author author);

    SpanElement getChip(Element parent);                              // "get" + the ui:field name
  }

  private static final Renderer RENDERER = GWT.create(Renderer.class);

  public AuthorChipCell() {
    super("click");
  }

  @Override
  public void render(Context context, Author author, SafeHtmlBuilder sb) {
    if (author != null) {
      RENDERER.render(sb, author.name, author.titles + (author.titles == 1 ? " title" : " titles"));
    }
  }

  @Override
  public void onBrowserEvent(Context context, Element parent, Author author, NativeEvent event,
      ValueUpdater<Author> updater) {
    RENDERER.onBrowserEvent(this, event, parent, author);             // dispatches to @UiHandler methods
  }

  @UiHandler("chip")
  void onChipClick(ClickEvent event, Element parent, Author author) {
    RENDERER.getChip(parent).setTitle("Filter by " + author.name);
  }
}
----

Source: https://www.gwtproject.org/doc/latest/DevGuideUiBinder.html#Rendering_HTML_for_Cells[GWT -- Developer Guide: UiBinder, rendering HTML for cells]

The rules, from the guide and from the generator's source (`UiBinderWriter`):

* The renderer interface may declare **one** `render` method, which must return `void` and whose first parameter is a `SafeHtmlBuilder`. The other parameters are matched **by name** with the `<ui:with>` fields of the template.
* An `onBrowserEvent` method takes the owner (the object whose `@UiHandler` methods are called), the `NativeEvent`, the parent `Element`, and then any arguments you like, which are passed on unchanged to the handlers. A handler is a method with `@UiHandler("fieldName")`; its first parameter selects the event type (`ClickEvent`) and the others repeat the extra arguments of `onBrowserEvent` (here the `Element` and the `Author`).
* `getFieldName(Element parent)` returns an element marked `ui:field`, so the cell can change the rendered markup after the fact (above, the handler sets a `title` on the chip). A getter with no parameters whose name matches a `<ui:style>` returns the style object.
* The cell must still list the events (`super("click")`) and forward the browser event to the renderer.

=== Shared and server

[[bookshelf-shared]]
The RPC contract carries the range and the sort order; the answer carries one page and the total.

/** Sorts on a whitelisted field only; an unknown field falls back to id order. */
public BookPage page(int start, int length, String sortField, boolean ascending) {
  List<Book> all = new ArrayList<>(books.values());
  Comparator<Book> order = comparatorFor(sortField);
  if (order != null) {
    all.sort(ascending ? order : order.reversed());
  }
  int from = Math.max(0, Math.min(start, all.size()));
  int to = Math.max(from, Math.min(all.size(), from + Math.max(0, length)));
  return new BookPage(all.subList(from, to), all.size());
}

private static Comparator<Book> comparatorFor(String field) {
  if (field == null) {
    return null;
  }
  switch (field) {
    case "title":  return Comparator.comparing(Book::getTitle).thenComparing(Book::getId);
    case "author": return Comparator.comparing(Book::getAuthor).thenComparing(Book::getId);
    case "year":   return Comparator.comparingInt(Book::getYear).thenComparing(Book::getId);
    case "copies": return Comparator.comparingInt(Book::getCopies).thenComparing(Book::getId);
    default:       return null;
  }
}
----

Source: https://www.gwtproject.org/doc/latest/DevGuideServerCommunication.html[GWT -- Developer Guide: Communicating with a Server]

The tie-break by id makes the order total: without it, two rows with the same author could swap places between two requests, and a row would appear on two pages or on none.
In a real application the sort would be a database `ORDER BY` with the same whitelist, and `start` and `length` a `LIMIT` and `OFFSET` (or, better for large tables, a keyset condition).

=== The presenter

[[bookshelf-presenter]]
The presenter is plain Java: it has no `GWT.create` call, so a JVM unit test runs it with a fake service.
It numbers the requests and ignores the answer of a request that is no longer the latest (the out-of-order problem described with the provider).

.`CatalogPresenter.java`
[source,java]
----
public class CatalogPresenter {
  private final CatalogServiceAsync service;
  private final CatalogDisplay display;
  private int latestRequest;

  public CatalogPresenter(CatalogServiceAsync service, CatalogDisplay display) {
    this.service = service;
    this.display = display;
  }

  public void load(int start, int length, String sortField, boolean ascending) {
    final int request = ++latestRequest;
    service.getBooks(start, length, sortField, ascending, new AsyncCallback<BookPage>() {
      @Override
      public void onSuccess(BookPage page) {
        if (request == latestRequest) {   // a newer range or sort order was requested meanwhile
          display.showRows(start, page.getBooks(), page.getTotal());
        }
      }

      @Override
      public void onFailure(Throwable caught) {
        if (request == latestRequest) {
          display.showError(caught.getMessage());
        }
      }
    });
  }
}
----

Source: https://github.com/gwtproject/gwt/blob/2.13.1/user/src/com/google/gwt/user/cellview/client/ColumnSortEvent.java[GWT source (2.13.1) -- ColumnSortEvent.java]

Three details are easy to get wrong and were all exercised:

* **`connect()` is separate from the constructor.** `addDataDisplay` calls `onRangeChanged` at once. In an earlier version of the view the display was added in the constructor, before the activity had created the presenter; the first range request hit a `null` listener, the exception was thrown inside `Activity.start`, the widget was never attached, and nothing was shown, silently, because the uncaught-exception handler only logged. The activity now creates the view, then the presenter, shows the view and *then* calls `connect()`.
* **The sort field comes from the column**, through a map filled in `addSortable`, so adding a sortable column is one line and the provider never learns column positions.
* **Sorting keeps the page.** `AsyncHandler` reuses the current range, so sorting on page 2 asks for rows 10 to 19 of the *sorted* list. If the user expects to go back to the top, call `grid.setVisibleRange(0, grid.getPageSize())` (or `pager.firstPage()`) in a sort handler of your own.

== Accessibility and keyboard use

[[accessibility]]
The cell widgets bring some of the accessibility work, and leave the rest to the cells.
What the lab's markup showed: sortable table headers have `role="button"` and `tabindex="-1"`; the `SimplePager` buttons are `<img>` elements with `role="button"`, an `aria-label` ("First page", "Previous page", "Next page", "Fast forward") and `aria-disabled`; `CellTree` sets `role="tree"` and gives each node `role="treeitem"` with `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded` and `aria-selected`; the focused row or cell has `tabindex="0"`.
The pager labels come from `SimplePager.ImageButtonsConstants`, a `Constants` interface, so they are translated with the module's locale.

What to do in your own cells: use a real `<button>` or `<input>` for actions (they are focusable and announced), give an icon-only control an `aria-label` in the template, handle Enter and not only the click, and keep `KeyboardSelectionPolicy` at `ENABLED` or `BOUND_TO_SELECTION` rather than `DISABLED` unless another way to reach the rows exists.
A table also needs an accessible name; give the widget's element an `aria-label` or `aria-labelledby` yourself.
The ARIA roles and states API of GWT (`com.google.gwt.aria.client.Roles`) and the rest of the guidance are on the xref:web/gwt/accessibility-and-aria.adoc[Accessibility & ARIA] page.

Source: https://www.gwtproject.org/javadoc/latest/com/google/gwt/user/cellview/client/SimplePager.html[GWT Javadoc -- SimplePager]

== Pitfalls

[[pitfalls]]
Most mistakes with cell widgets are silent: the page is blank, a number is stale or a selection disappears, and nothing is logged.
The first column quotes what the compiler or the browser printed, or says what was observed; each row was reproduced with the 2.13.1 compiler and headless Chrome, or comes from the source named in the last column.

[cols="3,3,3,2",options="header"]
|===
| Symptom (quoted or observed) | Cause | Fix | Evidence

| A `DataGrid` shows its header and no rows; no error. The data section has `top: 26px; height: 0px`.
| `DataGrid` is a `RequiresResize` widget and its parent (a `FlowPanel`, a `SimplePanel`) gave it no height.
| Put it in a layout panel (`RootLayoutPanel`, a `DockLayoutPanel` centre, a `SimpleLayoutPanel` with a size) or give the host element a height.
| Lab: `FlowPanel` 0px, `SimpleLayoutPanel` 104px

| A cell shows `3 left` after the user clicked it, although the `FieldUpdater` ran.
| A `FieldUpdater` or `ValueUpdater` only notifies; it does not redraw.
| Change the model, then `redrawRow(index)`, `provider.getList().set(i, item)` or `provider.refresh()`.
| Lab: `3 left` before and after; `2 left` with `redrawRow`

| Changing a field of an item in the provider's list and calling `flush()` leaves the old text.
| The provider only sees changes made through the list wrapper, not changes inside the items.
| `getList().set(index, item)` for one row, `refresh()` for all.
| Lab: `Before`, then `After` only after `refresh()`

| The pager says `1-5 of over 5` and keeps the next-page button enabled.
| The provider pushed rows but never called `updateRowCount(total, true)`.
| Call `updateRowCount` with the real total as soon as it is known.
| Lab: `1-5 of over 5` against `1-5 of 5`

| The selection disappears every time a page is loaded.
| No `ProvidesKey`: the selection model compares the objects, and the server sent new instances.
| Pass the same key provider to the widget, the provider and the selection model.
| Lab: `isSelected(new instance)` is `false` without it and `true` with it

| The grid is blank, and the uncaught exception handler only logged: a `NullPointerException` thrown inside `Activity.start`.
| `addDataDisplay` runs `onRangeChanged` immediately, before the presenter or listener it needs exists.
| Add the display in a separate `connect()` after the presenter is created.
| Seen in the Bookshelf scratch application

| Clicking a header changes the arrow but not the rows.
| `ListHandler` has no comparator for that column; `onColumnSort` returns silently.
| `setComparator(column, comparator)` for every sortable column.
| Source: `ColumnSortEvent.ListHandler`

| A sortable column on a server-backed table sorts nothing.
| No `ColumnSortEvent.AsyncHandler` was added, or `onRangeChanged` does not read `getColumnSortList()`.
| `table.addColumnSortHandler(new ColumnSortEvent.AsyncHandler(table))` and send the field and the direction.
| Source: `ColumnSortEvent.AsyncHandler`

| Sorting while on page 2 shows rows 11 to 20 of the sorted list, not the top. The request had start `10`.
| `AsyncHandler` re-requests the current range.
| Reset the range in your own handler if you want the first page.
| Browser run, third payload above

| A slow old answer replaces a newer one: a sorted page flashes back to the unsorted rows.
| Responses arrive out of order; the provider does not know which request is newer.
| Number the requests in the presenter and drop stale answers.
| JUnit test with a fake service

| A click on a custom cell does nothing, or Enter does not work.
| The event type was not passed to `+super(...)+`, or `"keydown"` is missing for `onEnterKeyDown`, or the cell's `getConsumedEvents()` changes after the widget read it.
| List every event the cell uses and keep the set constant.
| Source: `AbstractHasData.cellConsumesEventType`; the guide

| `+[ERROR] Argument 2 beyond range of arguments: <span>{0} {2}</span>+`, then `+[ERROR] Line 18: Failed to resolve 'bad.client3.Bad3.Templates' via deferred binding+`
| A `SafeHtmlTemplates` method has fewer parameters than the placeholders in its template.
| Make the number of parameters match the highest placeholder.
| Compiler output

| `Template with variable in URL attribute context: The template code generator will sanitize the URL. Use SafeUri to specify arguments in a URL attribute context that should not be sanitized.`
| A `String` parameter was used in an `href` or `src`. This is a log line, not an error.
| Pass a `SafeUri` (for example `UriUtils.fromString`) when the URL is yours to trust, or leave the sanitising on.
| Compiler output

| `+[ERROR] bad.client.Bad1.ChipCell.Renderer does not declare a render(SafeHtmlBuilder ...) method+` and `+Failed to resolve 'bad.client.Bad1.ChipCell.Renderer' via deferred binding+`
| The `UiRenderer` interface has no `render` method with a `SafeHtmlBuilder` first parameter.
| Declare `void render(SafeHtmlBuilder sb, …)`.
| Compiler output

| `[ERROR] Line 40: Type mismatch: cannot convert from int to String` in a generated `Bad1_ChipCell_RendererImpl`
| A `render` parameter has a different type from the `ui:with` field of the same name.
| Use the type declared in `ui:with`.
| Compiler output

| A `@UiRenderer` cell renders an empty `<span gwtuirendered="gwt-uid-1"></span>`, with no error.
| A `render` parameter is named differently from the `ui:with` field (`nom` against `name`): it is not matched and the field keeps its default.
| Name the parameters exactly like the fields.
| Lab: the span was empty

| `The following non-obfuscated class is present in a strict CssResource: low-stock. Fix by adding String accessor method(s) to the CssResource interface for obfuscated classes, or use an @external declaration for unobfuscated classes.`
| A style class used by the cells (for example through `getCellStyleNames`) is a dashed name, `.low-stock`, that no accessor of the strict `CssResource` binds to.
| Add an accessor (`lowStock()` binds to `.lowStock`) or declare the class with `@external`.
| Reproduced earlier in the scratch application (GSS styles)

| `Your ClientBundle is referencing css files instead of gss.` … `Add this line to your gwt.xml file to temporary avoid this:<set-configuration-property name="CssResource.conversionMode" value="strict" />`
| `CssResource.enableGss` is on, while GWT's own `NativeHorizontalScrollbar` UiBinder template still uses a CSS file.
| Set `CssResource.conversionMode` to `strict`, as the Bookshelf module does.
| Reproduced with `enableGss`
|===

== What changed since the older material

[[history]]
* **The book predates cell widgets.** The 2007 first edition (GWT 1.3 and 1.4) builds tables from `Grid` and `FlexTable` panels with widgets in the cells and listener interfaces for events, as did every GWT application until 2010. Cell widgets arrived with the first 2.1 milestone (19 May 2010; 2.1.0 final 27 October 2010), announced together with an application framework for large business applications. None of the cell classes in this page is in the book.
* **`DataGrid`** is a 2.4.0 feature (7 September 2011): a scrolling table with a fixed header and footer.
* **`CellTableBuilder`, custom headers and footers, and UiBinder rendering of cells** (the `UiRenderer` of this page) came with the 2.5.0 release candidates (27 June 2012; 2.5.0 final 25 October 2012).
* **Selection by event manager.** `DefaultSelectionEventManager` and its factories are how current code chooses what selects. The 2.5.0 release notes list `AbstractCellTable.doSelection(Event,Object,int,int)`, `AbstractHasData.onUpdateSelection()` and `CellList.doSelection(Event, Object, int)` among the removed methods, so code from the 2.1 and 2.2 era that overrides them does not compile any more. The same notes record that the `LEFT` and `RIGHT` placement of the text in `SimplePager` was fixed, which may swap it for applications that had worked around the bug.
* **Deprecated or stale API in the guide's examples.** `CheckboxCell(boolean isSelectBox)` is deprecated in favour of the two-argument constructor. The guide says `ActionCell` acts on mouseUp; in 2.13.1 it consumes `click` and `keydown`. The sort examples refer to a `Tester.Contact` type that exists only in the file they were copied from. The table of contents of the cell widget guide links to `#cellbrowser`, an anchor the page does not define, and the guide's `AsyncDataProvider` example pushes rows with `cellList.setRowData` instead of `updateRowData` on the provider.
* **Showcase link.** The guide's demo link uses `http://samples.gwtproject.org/samples/Showcase/Showcase.html#!CwCellSampler`; the same page over https is listed in the references.
* **J2CL.** Cell widgets ship in `gwt-user`. Among the `+org.gwtproject.*+` libraries that are published for J2CL (all still 1.0.0 release candidates when checked on 2026-10-08) there is no `gwt-user`-style module that contains them, so a cell-widget application is a GWT application today (see xref:web/gwt/j2cl-and-the-future.adoc[J2CL & the Future]).

Source: https://www.gwtproject.org/release-notes.html[GWT -- Release Notes]
