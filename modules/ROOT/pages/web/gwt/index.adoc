This section is written against GWT 2.13.1 (released 2026-06-19), the version managed by the `org.gwtproject:gwt` BOM,
together with `gwt-maven-plugin` 1.3.0 (`net.ltgt.gwt.maven`), the `modular-webapp` archetype 2026.6.22, JDK 21 running
the tools with `-sourceLevel 17`, Jakarta Servlet 6 on Jetty 12 and Elemental2 1.3.2 (versions verified on 2026-10-08).
GWT is a community-run open-source project: Google created and released it in 2006, a steering committee has governed it
since 2012, and volunteers publish the releases at a slow but steady pace of roughly one or two a year. The 2.13 line is
the current one, and the roadmap says that 2.13.0 is likely the last release whose compiler and tools run on Java 11. There is no GWT 3 release: Google's own successor to the GWT compiler is J2CL, a separate
Java-to-JavaScript transpiler used inside Google, and the `org.gwtproject.*` libraries are being prepared to work with both
compilers. Where the book listed in the bibliography or older tutorials describe different behaviour, the pages say so,
and xref:web/gwt/whats-changed-and-migration.adoc[What's Changed & Migration] collects every difference in one place.

== What GWT is

GWT is a **Java-to-JavaScript compiler** together with a toolkit. You write the browser side of a web application in
Java, with an IDE, a type checker and JUnit, and the compiler turns it into optimised, obfuscated JavaScript that runs in
every current browser. It is not a server-side UI framework: nothing of the Java code you compile runs on the server, and
the server is any ordinary Java (or non-Java) backend that exposes services.

A single toolchain provides:

* the compiler, with whole-program optimisation, dead-code elimination, one compiled **permutation** per combination of
  locale and browser flavour, **deferred binding** to pick implementations at compile time and **code splitting** to
  download the application in parts
* a JRE emulation library, so that a subset of `java.lang` and `java.util` and your own shared classes behave in the
  browser as they do on the JVM
* Super Dev Mode, which recompiles in seconds and lets you debug the Java source in the browser's developer tools
* widgets, panels and layout panels, the event and handler system, **UiBinder** templates, cell widgets and data
  providers, the **Editor** framework, `ClientBundle` resources with CSS and GSS, internationalization, history,
  Activities and Places, Bean Validation and logging
* client-server communication: **GWT-RPC**, `RequestBuilder` with JSON and XML, **RequestFactory** and the hooks that REST
  libraries use
* interoperability with JavaScript through **JsInterop** and Elemental2, and the legacy JSNI and overlay types
* unit testing with `GWTTestCase` and plain JUnit, and the security classes `SafeHtml` and the XSRF tokens

This section is for developers who:

* know Java and want to build rich single-page browser applications without writing the client in JavaScript or
  TypeScript, sharing classes and validation rules with a Java server
* maintain an existing GWT application, often one written for GWT 2.0 to 2.8, and need the current idioms for
  `org.gwtproject`, Jakarta servlets, JsInterop and the `net.ltgt` Maven plugin
* learned GWT from the 2007 book or from older tutorials (hosted mode, listeners, `ImageBundle`, `webAppCreator`) and need
  to know what still applies
* are choosing between GWT and a server-rendered Java framework or a TypeScript framework, and want the trade-offs

== The Bookshelf scenario

Every example builds one small original application, _Bookshelf_, in the same domain as the
xref:web/thymeleaf/index.adoc[Thymeleaf], xref:web/django/index.adoc[Django], xref:web/php-laravel/index.adoc[PHP and Laravel]
and xref:web/nextjs/index.adoc[Next.js] sections, so that the stacks can be compared page by page. Here it is a three-module
GWT 2.13 application generated from the `modular-webapp` archetype:

* `bookshelf-shared`: plain Java used on both sides, such as the `Book`, `Author` and `Review` classes, the RPC service
  interfaces and the Bean Validation constraints
* `bookshelf-client`: the code compiled to JavaScript, with the `EntryPoint`, a UiBinder shell, a `DataGrid` catalogue,
  Activities and Places, an Editor-based book form, English and Spanish messages, a `ClientBundle` with GSS, a JsInterop
  binding to a chart library and `GWT.runAsync` split points
* `bookshelf-server`: a Jakarta servlet backend (Jetty for development, plus a Spring Boot variant) with a **GWT-RPC**
  `CatalogService` protected by XSRF tokens and a small REST/JSON endpoint called with `RequestBuilder` and a REST library
* tests: `GWTTestCase` with HtmlUnit, plain JUnit tests of presenters with mocked views, server-side RPC tests and a
  Playwright end-to-end test

.The Bookshelf: shared, client and server modules, the GWT compiler producing JavaScript, and the browser talking to the server with GWT-RPC and REST
image::gwt-bookshelf-architecture.svg["Diagram of the Bookshelf architecture. The bookshelf-client and bookshelf-shared modules are compiled by the GWT compiler into bookshelf.nocache.js and one cache.js file per permutation. The bookshelf-shared and bookshelf-server modules are compiled by javac and war packaging into classes that run in a servlet container on the JVM. The browser loads the JavaScript from the server through a script tag in the host page, then talks to the server with GWT-RPC protected by an XSRF token and with REST and JSON through RequestBuilder.",width=100%]

The final project layout (`bookshelf-client/src/main/java` packages for `client/{ui,activity,place,resources,i18n}`, the
`Bookshelf.gwt.xml` module file, `bookshelf-shared/src/main/java` with the `shared` package, and
`bookshelf-server/src/main/java` with the `server` package plus `src/main/webapp/index.html` and `WEB-INF/web.xml`) is
assembled on xref:web/gwt/getting-started.adoc[Getting Started].

== Reading path

The pages are ordered so that each one builds on the previous ones. Read them in this order the first time, then use
them as a reference. Before starting, be comfortable with the language and the build underneath: the
xref:programming-languages/java/index.adoc[Java Reference] for generics, annotations, lambdas and the Maven basics, and,
for the backend variant of the Bookshelf, the xref:backend/springboot/index.adoc[SpringBoot Reference].

. *Foundations*: what GWT is, a first project, the module XML, the build, the compiler, development mode and the JRE
  emulation.
. *Java and JavaScript*: JsInterop, the legacy JSNI, the DOM and Elemental2, deferred binding and the scheduler.
. *Building user interfaces*: widgets, panels, events, custom widgets, UiBinder, cell widgets, Editors, styling,
  `ClientBundle`, HTML5, accessibility and internationalization.
. *Application architecture*: history, Activities and Places, validation and logging.
. *Client-server communication*: the overview, GWT-RPC, `RequestBuilder`, REST libraries, RequestFactory and the server
  integration and deployment.
. *Security*: `SafeHtml` and XSS, then XSRF and server-side security.
. *Performance and optimisation*: code splitting, compile reports and linkers.
. *Testing*, then *the ecosystem, the future and migration*, and finally the cheat sheet.
