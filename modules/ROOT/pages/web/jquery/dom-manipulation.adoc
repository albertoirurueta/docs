= DOM Manipulation
:description: Reading and writing element content with jQuery (.html/.text/.val), inserting elements inside and outside a target, wrapping, removing and detaching, cloning and replacing, and creating new elements.
:keywords: jQuery DOM manipulation, html, text, val, append, prepend, appendTo, after, before, insertAfter, wrap, unwrap, remove, detach, empty, clone, replaceWith, create element

include::partial$ai-disclaimer.adoc[]

jQuery's manipulation methods change the content and structure of matched elements. Most act on *every* element
in the set and return the set, so they chain.

== Reading and writing content

[source,javascript]
----
$('#box').html();                       // GET: inner HTML of the FIRST element
$('#box').html('<b>Hi</b>');            // SET: inner HTML of EVERY element (parses HTML)

$('#box').text();                       // GET: combined text of ALL elements
$('#box').text('<b>Hi</b>');            // SET: assigns as literal text (escapes < >)

$('#name').val();                       // GET: value of the first form control
$('#name').val('Ada');                  // SET: value of every matched control
$('#tags').val(['a', 'b']);             // multi-select: select these options
----

A getter reads the first element; a setter writes them all. `.text()` is HTML-safe (it sets `textContent`);
`.html()` parses its argument as markup, so never pass unsanitized user input to it.

== Inserting elements

=== Inside a target

[source,javascript]
----
$('#list').append('<li>last</li>');     // as the last child of #list
$('#list').prepend('<li>first</li>');   // as the first child of #list

$('<li>moved</li>').appendTo('#list');  // same as append, target/source swapped
$('<li>moved</li>').prependTo('#list'); // same as prepend, swapped
----

`a.append(b)` reads "put b inside a"; `b.appendTo(a)` reads "put b inside a" from b's side -- use whichever
makes the chain read better.

=== Outside a target

[source,javascript]
----
$('#anchor').before('<hr>');            // as a preceding sibling
$('#anchor').after('<hr>');             // as a following sibling
$('<hr>').insertBefore('#anchor');      // same as before, swapped
$('<hr>').insertAfter('#anchor');       // same as after, swapped
----

=== Wrapping

[source,javascript]
----
$('.field').wrap('<div class="row"></div>');   // wrap EACH element individually
$('.field').wrapAll('<div class="row"></div>'); // wrap the whole set in ONE wrapper
$('.field').wrapInner('<span></span>');          // wrap each element's CONTENTS
$('.field').unwrap();                            // remove each element's parent, keep the element
----

== Removing elements

[source,javascript]
----
$('#tmp').remove();     // detach from the DOM AND discard jQuery data / event handlers
$('#tmp').detach();     // detach but KEEP data / handlers, so it can be re-inserted
$('#tmp').empty();      // keep #tmp, delete all of its children
----

Use `.detach()` when you will re-insert the same nodes (their bound events still work); use `.remove()` when
you are done with them -- it frees the associated event handlers and `.data()` to avoid a leak.

[source,javascript]
----
const $row = $('#row').detach();       // pull it out, handlers intact
// ... reorder, measure, whatever ...
$row.appendTo('#table tbody');         // put it back, still clickable
----

== Cloning and replacing

[source,javascript]
----
$('#tpl').clone();          // deep copy of the elements, WITHOUT event handlers / data
$('#tpl').clone(true);      // deep copy WITH event handlers and data copied too

$('#old').replaceWith('<div id="new"></div>');   // swap #old for the new markup
$('<div id="new"></div>').replaceAll('#old');    // same, source/target swapped
----

== Creating elements

Pass an HTML string, or -- clearer for setting several properties at once -- a tag plus an attributes object.
Referring to that second form in prose, it looks like `+$('<li>', { text: 'Item', class: 'new' })+`: the second
argument is a plain object whose keys are jQuery methods (`text`, `html`, `css`, `on`, ...) or attribute names.

[source,javascript]
----
const $item = $('<li>', {
  text: 'Item 3',              // -> .text('Item 3')
  class: 'new',                // -> attribute class="new"
  'data-id': 42,               // -> attribute data-id="42"
  click: () => console.log('clicked')   // -> .on('click', ...)
});
$item.appendTo('#list');
----

== Where each insertion method puts the node

The eight insertion methods are two pairs of "inside" and "outside" positions, each in a normal form and a
swapped form. Picturing a single target element makes the names easy to keep apart:

== Building many rows efficiently

Each call that touches the live DOM can force the browser to recompute layout. Building the rows detached and
inserting them once is both faster and easier to read. The running shopping list loads its saved items like this:

[source,javascript]
----
const items = ['Tea', 'Apples', 'Coffee'];

// map each string to a detached <li>, then insert the whole array in ONE call
$('#list').append(items.map(function (text) {
  return $('<li>').append($('<span>').text(text));
}));
----

`.append()` accepts a jQuery object, a DOM node, an HTML string, an array of any of those, or several arguments:

[source,javascript]
----
$('#list').append('<li>a</li>', '<li>b</li>');            // several arguments
$('#list').append(function (index, currentHtml) {          // a function returning content
  return index === 0 ? '<li>first list only</li>' : '';
});
----

When the same new content is appended to *several* targets, the original goes into the last target and every other
target receives a clone without handlers or data, so bind behaviour with delegation rather than on the new content.

== Escaping: `.text()` versus `.html()` on user input

The shopping list takes its text from an input box. Assigning it with `.text()` makes markup inert, while
`.html()` would run it:

[source,javascript]
----
const $s = $('<span>').text('<script>alert(1)</script>');
$s.html();       // '&lt;script&gt;alert(1)&lt;/script&gt;'  -- stored as text, displayed literally
----

Both `.text()` and `.html()` also accept a function receiving `(index, oldValue)`, which makes read-modify-write
a single call:

[source,javascript]
----
$('#list span').text(function (index, old) {
  return (index + 1) + '. ' + old;          // number every label: "1. Milk", "2. Eggs", ...
});
----

== Sorting rows with `.detach()`

Sorting is a good use of the `remove()` versus `detach()` distinction. Pull every row out of the document in one
call, sort the detached array in memory, and insert them back in the new order. Because `.detach()` keeps data and
handlers, rows stay fully functional:

[source,javascript]
----
function sortList() {
  const $list = $('#list');
  const label = function (li) { return $(li).text().trim().toLowerCase(); };

  const $rows = $list.children('li').detach();               // out of the DOM, handlers kept
  $rows.sort(function (a, b) { return label(a).localeCompare(label(b)); })
       .appendTo($list);                                     // back in, in sorted order
}
----

A jQuery object is array-like, so `.sort()` (the native `Array.prototype.sort` borrowed by jQuery) works on it and
returns the same object. Appending a node that is already in the document *moves* it, which is why the same
pattern also works without `.detach()`; the detach step just avoids re-flowing the page once per row.

== `.clone()` and event handlers

`.clone()` copies markup only unless you ask otherwise. This matters when a "template row" has handlers or data:

[source,javascript]
----
let clicks = 0;
const $b = $('<button>').on('click', function () { clicks++; }).appendTo('body');

$b.clone().appendTo('body').trigger('click');       // clicks is still 0 -- no handler on the copy
$b.clone(true).appendTo('body').trigger('click');   // clicks is now 1 -- handlers and data copied
----

In practice a delegated handler on the parent (see xref:web/jquery/events.adoc[Event Handling]) makes the
distinction unnecessary: a cloned row is handled automatically.

== Wrapping and unwrapping a group

`.wrapAll()` wraps the whole set in a single new parent, placed where the first element was, which is how you group
a run of siblings. `.unwrap()` reverses it:

[source,javascript]
----
$('#list li').slice(0, 2).wrapAll('<ol class="group"></ol>');
// the first two rows are now inside one <ol class="group">

$('#list li').slice(0, 2).unwrap();       // removes that <ol> again, keeping the rows
----

== Templates for repeated markup

When the same row structure is created in many places, a `<template>` element keeps the markup in the HTML
instead of in a string. jQuery has no template engine of its own, but cloning the template's content is two lines:

[source,html]
----
<template id="row-template">
  <li><span></span> <button class="del" title="Delete">&times;</button></li>
</template>
----

[source,javascript]
----
function rowFromTemplate(text) {
  const row = document.getElementById('row-template').content.firstElementChild.cloneNode(true);
  return $(row).find('span').text(text).end();     // wrap, fill in the text, return the <li>
}
----

== Modern equivalent

`el.innerHTML` / `el.textContent` / `input.value` read and write content. `Element.append`, `prepend`,
`before`, `after`, `remove`, and `replaceWith` are all native now and accept strings or nodes.
`el.cloneNode(true)` deep-clones (never copies listeners). Create with `+document.createElement('li')+` then set
properties, or use a `<template>`. See xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics].
