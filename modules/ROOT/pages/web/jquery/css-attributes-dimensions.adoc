= CSS, Classes, Attributes and Dimensions
:description: Managing classes and inline styles with jQuery (.addClass/.css), the .attr() vs .prop() distinction and the checked/selected/disabled gotcha, and the element dimension and position/scroll methods.
:keywords: jQuery css, addClass, removeClass, toggleClass, hasClass, attr, prop, removeAttr, width, height, innerWidth, outerWidth, offset, position, scrollTop

include::partial$ai-disclaimer.adoc[]

These methods read and write the presentational state of matched elements: their classes, their inline styles,
their attributes and DOM properties, and their measured size and position.

== Classes

[source,javascript]
----
$('#box').addClass('active');
$('#box').addClass('active big');          // several at once, space-separated
$('#box').removeClass('active');
$('#box').removeClass();                   // remove ALL classes
$('#box').toggleClass('active');           // add if absent, remove if present
$('#box').toggleClass('active', isOn);     // force on/off from a boolean
$('#box').hasClass('active');              // boolean -- true if ANY matched element has it
----

== Inline styles with `.css()`

[source,javascript]
----
$('#box').css('color');                        // GET one computed property (first element)
$('#box').css(['color', 'fontSize']);          // GET several -> plain object
$('#box').css('color', 'red');                 // SET one on every element
$('#box').css({ color: 'red', 'font-size': '14px' });  // SET several
$('#box').css('width', (i, cur) => parseFloat(cur) * 2);// functional setter
----

`.css()` writes to the element's `style` attribute (an inline style, high specificity). Prefer toggling a class
so the styling stays in the stylesheet; reach for `.css()` for genuinely dynamic values (a drag position, a
computed height).

== Attributes vs. properties

`.attr()` reads/writes the HTML *attribute* (the markup's initial value); `.prop()` reads/writes the live DOM
*property* (the current state). For most things they agree, but for boolean form state they do not:

[source,javascript]
----
// <input type="checkbox" id="agree" checked>

$('#agree').attr('checked');   // "checked"  -- the attribute, i.e. the DEFAULT state
$('#agree').prop('checked');   // true/false -- whether it is ticked RIGHT NOW

// after the user unticks it:
$('#agree').attr('checked');   // still "checked"  (attribute unchanged)
$('#agree').prop('checked');   // false            (property tracks reality)
----

Rule of thumb: use `.prop()` for `checked`, `selected`, `disabled`, `readOnly`, `value` (current), and
`.attr()` for everything genuinely attribute-shaped (`id`, `href`, `src`, `+data-*+`, `colspan`, ARIA
attributes). `+.removeAttr('name')+` deletes an attribute; `.removeProp()` exists but is rarely correct.

== Dimensions

[source,javascript]
----
$('#box').width();              // content width only, in px, as a Number
$('#box').height();             // content height only
$('#box').innerWidth();         // content + padding
$('#box').outerWidth();         // content + padding + border
$('#box').outerWidth(true);     // content + padding + border + margin
$('#box').width(300);           // SET the content width (accepts Number px or a string)
----

Unlike CSS `+.css('width')+` (which returns a string like `"300px"`), `.width()` returns a unitless Number and is
unaffected by `box-sizing` -- it always means the content box. The figure below shows which box each method
measures:

image::jquery-dimensions.svg[Box overlay: width() is the content box; innerWidth() adds padding; outerWidth() adds the border; outerWidth(true) also adds the margin,role=text-center]

== Position and scroll

[source,javascript]
----
$('#box').offset();             // { top, left } relative to the DOCUMENT
$('#box').position();           // { top, left } relative to the offset PARENT
$('#box').offset({ top: 100, left: 40 });   // move it (document coordinates)

$(window).scrollTop();          // current vertical scroll of the window
$('#pane').scrollTop(0);        // scroll an overflow container back to the top
$('#pane').scrollLeft(120);     // horizontal scroll position
----

`.offset()` is for "where is this on the page"; `.position()` is for "where is this inside its positioned
container", e.g. when placing an absolutely-positioned tooltip.

== Attribute versus property, step by step

The `checked` example above is easiest to remember as a timeline. The attribute records what the markup said; the
property tracks what the user has done since:

[mermaid]
....
sequenceDiagram
    participant M as Markup
    participant A as Attribute
    participant P as Property
    participant U as User
    M->>A: parsed, checked attribute present
    A->>P: initial property value set to true
    U->>P: unticks the box, property becomes false
    Note over A: attribute is unchanged and still reports checked
    U->>P: ticks the box again, property becomes true
    P-->>U: .prop reads the live value, .attr still reads the markup
....

Since jQuery 1.6, `+.attr('checked')+` on a checkbox returns the attribute as written, not the live state, so
using it to test a box is a bug that only shows after the user has clicked it.

== Worked example: a "select all" checkbox for the list

The shopping list gains a checkbox per row and a master checkbox. The master must tick or untick every row, and it
must show a third, *indeterminate* state when only some rows are ticked. That state exists only as a DOM property,
so `.prop()` is the only way to set it:

[source,javascript]
----
$('#list li').prepend('<input type="checkbox" class="pick">');
$('body').prepend('<input type="checkbox" id="all">');

const $picks = $('.pick');

// master -> rows
$('#all').on('change', function () {
  $picks.prop('checked', this.checked)
        .closest('li').toggleClass('selected', this.checked);
});

// rows -> master
$picks.on('change', function () {
  const n = $picks.filter(':checked').length;
  $('#all').prop({
    checked: n === $picks.length,
    indeterminate: n > 0 && n < $picks.length
  });
});
----

`.prop()` accepts an object to set several properties at once, `this.checked` is the plain DOM property (no
wrapper needed inside a handler), and `.toggleClass(name, state)` takes a boolean so the class always follows the
state instead of flipping.

== Function arguments for classes, styles and attributes

Most setters accept a function receiving `(index, currentValue)` that returns the new value. This is the way to
express "each element gets a value that depends on its position or its current value" without an explicit loop:

[source,javascript]
----
$('#list li').toggleClass(function (index) {
  return index % 2 ? 'odd' : 'even';       // zebra striping by position
});

$('#list li').css('opacity', function (index, current) {
  return 0.5 + index * 0.1;                // a fade gradient down the list
});
----

Setting a CSS custom property works the same way as an ordinary property, which makes `.css()` a convenient bridge
to a stylesheet that reads `var(--accent)`:

[source,javascript]
----
$('#list li').first().css('--accent', 'red');     // style="--accent: red;"
$('#list li').first().css('--accent');             // 'red'
----

== Attributes that are not properties

ARIA state and custom data live in attributes only, so `.attr()` is correct for them. `.removeAttr()` deletes one
and `.attr(name, null)` is a shorthand for the same thing; an object sets several at once:

[source,javascript]
----
$('#list li').eq(2).attr({ title: 'Bread', 'aria-label': 'Bread, not done' });
$('#list li').eq(2).removeAttr('title');
$('#add-form button').prop('disabled', true);        // property: live and reflected
----

NOTE: A value given to `.attr()` is always stored as a string, and `+.attr('data-id')+` on a missing attribute
returns `undefined`. `.data()` (see xref:web/jquery/data-and-utilities.adoc[Element Data and Utility Functions])
is the right tool for typed, non-markup values.

== Measuring needs a layout engine

The dimension methods read computed layout, so they only make sense for elements that are in the rendered
document. A detached element reports `0`, and so does every element in a layout-less environment such as jsdom.
jQuery temporarily shows an element that is merely `display: none` in order to measure it, but it cannot measure a
node that has no place in the document, so insert first and measure afterwards:

[source,javascript]
----
const $row = $('<li>Tea</li>').appendTo('#list');    // inserted, so the browser can lay it out
const w = $row.outerWidth(true);                     // content + padding + border + margin
$row.height();                                       // content height only, as a Number
----

== Modern equivalent

`el.classList.add/remove/toggle/contains` replaces the class methods. `getComputedStyle(el)` reads styles;
`el.style.prop = value` sets them. Use `el.checked` / `el.disabled` (properties) and
`el.getAttribute`/`setAttribute`/`removeAttribute` for attributes. `el.getBoundingClientRect()` gives
border-box size and viewport position in one call; `el.offsetWidth`/`clientWidth`/`scrollTop` cover the rest.
See xref:programming-languages/javascript/browser-css.adoc[Accessing CSS from JavaScript] and
xref:programming-languages/javascript/browser-geometry-scrolling.adoc[Document geometry & scrolling].
