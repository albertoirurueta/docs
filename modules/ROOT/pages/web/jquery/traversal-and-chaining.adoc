= Traversal and Chaining
:description: Moving around the DOM from an existing jQuery set -- descendant, ancestor, and sibling traversal; filtering and iterating a set; and how method chaining plus the destructive-operation stack (.end(), .addBack()) work.
:keywords: jQuery traversal, find, children, parent, parents, closest, siblings, next, prev, filter, not, is, each, map, chaining, end, addBack

include::partial$ai-disclaimer.adoc[]

Once you have a wrapped set, traversal methods return a *new* set relative to it -- down to descendants, up to
ancestors, or sideways to siblings -- without going back through `$()`. Every traversal method returns a jQuery
object, so calls chain.

== Traversing the tree

=== Downward

[source,javascript]
----
$('#list').find('a')        // all <a> descendants, any depth
$('#list').children()       // direct children only
$('#list').children('.done')// direct children matching a selector
----

=== Upward

[source,javascript]
----
$('span.tag').parent()              // immediate parent (one level)
$('span.tag').parents()             // all ancestors up to <html>
$('span.tag').parents('.panel')     // ancestors filtered by selector
$('span.tag').parentsUntil('.panel')// ancestors, stopping before .panel
$('span.tag').closest('.panel')     // nearest ancestor matching .panel (incl. self)
----

`.closest()` walks up starting from each element itself and stops at the first match -- the usual tool for
"which card was clicked?" inside a delegated handler. `.parents()` always returns *every* ancestor and never
includes the element itself.

=== Sideways

[source,javascript]
----
$('li.current').siblings()          // all siblings (not the element itself)
$('li.current').next()              // immediately following sibling
$('li.current').nextAll()           // all following siblings
$('li.current').nextUntil('.stop')  // following siblings up to .stop
$('li.current').prev()              // immediately preceding sibling
$('li.current').prevAll()           // all preceding siblings
$('li.current').prevUntil('.stop')  // preceding siblings up to .stop
----

== Filtering a set

These narrow an existing set instead of moving in the tree:

[source,javascript]
----
$('li').filter('.active')       // keep only those matching
$('li').filter((i, el) => i % 2 === 0)  // keep by predicate (index, element)
$('li').not('.active')          // drop those matching
$('li').is('.active')           // boolean: does ANY element match?
$('li').has('a')                // keep those containing a matching descendant
$('li').eq(0)                   // the element at an index, as a set
$('li').first()                 // first, as a set  (prefer over :first)
$('li').last()                  // last, as a set
$('li').slice(1, 3)             // a sub-range, as a set
----

== Iterating

[source,javascript]
----
$('li').each(function (index, element) {
  // `this` === element (a raw DOM node); wrap it to use jQuery methods
  $(this).attr('data-pos', index);
});

const texts = $('li').map(function (index, element) {
  return $(this).text().trim();   // return undefined/null to skip an item
}).get();                         // .get() converts the jQuery set to a plain array
----

In `.each()` and `.map()`, `this` is the raw element and the callback receives `(index, element)` -- the
opposite order from `Array.prototype.forEach`{apos}s `(element, index)`.

== Chaining and the destructive-operation stack

Because traversal and most manipulation methods return a jQuery set, calls compose in one statement:

[source,javascript]
----
$('#list')
  .find('li')          // set A: the <li> descendants
  .addClass('row')
  .filter('.done')     // set B: only the done ones
  .css('opacity', 0.5)
  .end()               // pop back to set A (all <li> again)
  .removeClass('row');
----

jQuery keeps an internal stack of prior sets. A method that *narrows* the set (`.find`, `.filter`, `.children`,
`.eq`, ...) pushes the old set; `.end()` pops it, so the chain continues from where it branched. `.addBack()`
merges the previous set back in instead of replacing:

[source,javascript]
----
$('#item').nextAll().addBack().addClass('highlight');
// highlights #item AND all of its following siblings
----

Without `.end()` / `.addBack()`, a chain can only ever get more specific.

== Worked example: summarising the list

Traversal methods earn their keep when a page needs to read its own state. On the running shopping list, three
questions can be answered without any separate data model:

[source,javascript]
----
const $items = $('#list li');

// 1. progress: how many rows are done?
const total = $items.length;
const done = $items.filter('.done').length;
$('#count').text(done + ' of ' + total + ' done');               // "1 of 3 done"

// 2. which row does this button belong to, and where is it in the list?
$('#list').on('click', '.del', function () {
  const $row = $(this).closest('li');          // button -> its row
  console.log('removing row', $row.index());   // 0-based position among the siblings
});

// 3. read every label into a plain array
const names = $items.map(function () {
  return $(this).children('span').text();
}).get();                                      // ['Milk', 'Eggs', 'Bread']
----

`+.children('span')+` is deliberately used instead of `+.find('span')+`: `.children()` looks one level down only, so
it stays correct if a row later gains a nested element that also contains a `span`.

== Ranges between two elements

The `+*Until+` methods select the elements *between* a starting element and a stop condition, exclusive of both ends.
That is the natural way to express "everything after the first completed row, up to the last row":

[source,javascript]
----
$('li.done').nextAll();                    // every row after the done row
$('li.done').nextUntil('li:last');         // rows between the done row and the last row (exclusive)
$('li:last').prevUntil('li.done');         // the same range, walked backwards
$('li.done').nextAll().addBack();          // the done row plus everything after it
$('li.done').siblings();                   // every other row
----

== Combining sets with `.add()` and `.contents()`

`.add()` is the union operation. It is the way to apply one change to elements that no single selector describes,
and the result is returned in document order with duplicates removed:

[source,javascript]
----
$('li').add('form').addClass('panel');     // four elements: three rows and the form
----

`.contents()` returns *all* child nodes, including text and comment nodes, which `.children()` skips. It is the
tool for reading or wrapping bare text:

[source,javascript]
----
$('#list').contents().filter(function () {
  return this.nodeType === Node.TEXT_NODE;  // the whitespace between rows
}).remove();
----

== Stopping an iteration early

`.each()` has an escape hatch that the native `forEach` does not: returning `false` from the callback ends the
loop. Returning anything else (including `undefined`) continues, which is why an unrelated `return;` is harmless:

[source,javascript]
----
let seen = 0;
$('li').each(function (index) {
  seen++;
  if (index === 1) return false;     // stop after the second row
});
// seen === 2
----

== How the chain stack evolves

The destructive-operation stack described above is easiest to understand as a trace. Each narrowing call pushes a
new set on top of the previous one, and each `.end()` removes the top:

[mermaid]
....
sequenceDiagram
    participant C as Chain
    participant S as Set stack
    C->>S: $('#list') pushes set 1 (the ul)
    C->>S: .find('li') pushes set 2 (three rows)
    C->>S: .addClass('row') edits set 2, stack unchanged
    C->>S: .filter('.done') pushes set 3 (the done row)
    C->>S: .css('opacity', 0.5) edits set 3, stack unchanged
    C->>S: .end() pops set 3, current set is set 2
    C->>S: .removeClass('row') edits set 2 again
....

The previous set is also reachable directly through `prevObject`, which is what `.end()` reads:

[source,javascript]
----
$('li').first().prevObject.length;   // 3 -- the set the .first() call narrowed
----

Use `.end()` sparingly. A chain with more than one `.end()` is usually clearer as two statements that each name
their set (`+const $rows = ...+`), which also avoids re-running the selection.

== Modern equivalent

`el.closest(sel)`, `el.querySelectorAll(sel)`, `el.children`, `el.parentElement`, `el.nextElementSibling` /
`previousElementSibling` cover tree movement natively. There is no built-in sibling-list or "until" helper --
build one with a small loop. Iterate a `NodeList` with `+for...of+`; map with `Array.from(list, fn)`. See
xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics].
