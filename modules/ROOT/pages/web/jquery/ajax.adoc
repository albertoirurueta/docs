= AJAX
:description: Making HTTP requests with jQuery -- the jQuery.ajax() core and its shorthands, the jqXHR promise object and its .done()/.fail()/.always()/.then() callbacks, form serialization, and global AJAX events.
:keywords: jQuery AJAX, jQuery.ajax, $.get, $.post, $.getJSON, $.getScript, load, jqXHR, done, fail, always, then, Deferred, when, serialize, serializeArray, jQuery.param, ajaxStart

include::partial$ai-disclaimer.adoc[]

"AJAX" (Asynchronous JavaScript and XML) means updating a page with server data without a full reload. jQuery
wraps `XMLHttpRequest` in `jQuery.ajax()` plus a set of shorthands, and -- since jQuery 3 -- returns a
Promises/A+ compliant object.

== `jQuery.ajax(url, settings)`

[source,javascript]
----
jQuery.ajax('/api/users', {
  method: 'POST',              // HTTP verb (alias: type); default 'GET'
  data: { name: 'Ada' },       // GET -> query string; POST -> request body
  dataType: 'json',            // how to parse the response: 'json' | 'text' | 'html' | 'script'
  contentType: 'application/json; charset=UTF-8',  // request body media type
  headers: { 'X-Requested-With': 'XMLHttpRequest' },
  timeout: 8000,               // ms before the request is aborted with a 'timeout' error
  beforeSend: (jqXHR, settings) => { /* e.g. show a spinner, set an auth header */ }
});
----

=== Shorthands

[source,javascript]
----
jQuery.get('/api/users', params);           // GET
jQuery.post('/api/users', body);            // POST
jQuery.getJSON('/api/users', params);       // GET with dataType 'json'
jQuery.getScript('/widgets/chart.js');      // GET a script and execute it
$('#panel').load('/fragments/list.html');   // GET HTML and inject it into #panel
$('#panel').load('/fragments/list.html #rows'); // inject only the #rows subtree
----

== Handling the response: the jqXHR object

Every AJAX call returns a **jqXHR** -- a superset of the native `XMLHttpRequest` that is also a thenable.
Prefer the deferred-style callbacks:

[source,javascript]
----
jQuery.getJSON('/api/users')
  .done((data, textStatus, jqXHR) => { /* 2xx: use data */ })
  .fail((jqXHR, textStatus, errorThrown) => { /* network error, 4xx/5xx, parse error, timeout */ })
  .always((/* ... */) => { /* runs on success OR failure -- hide the spinner here */ });

// Promises/A+ since jQuery 3 -- chainable and await-able:
try {
  const data = await jQuery.getJSON('/api/users');
} catch (jqXHR) { /* ... */ }
----

The legacy `success` / `error` / `complete` settings still work but are discouraged: the deferred style
composes, supports multiple callbacks, and can be ``await``ed.

[source,javascript]
----
// coordinating several requests
jQuery.when(jQuery.getJSON('/a'), jQuery.getJSON('/b'))
  .done((aResult, bResult) => { /* both resolved; each is [data, status, jqXHR] */ });

// your own deferred (rarely needed now -- prefer a native Promise)
const d = jQuery.Deferred();
setTimeout(() => d.resolve('ok'), 100);
d.promise().then(v => console.log(v));
----

== Serializing form data

[source,javascript]
----
$('#form').serialize();        // "name=Ada&role=admin"  (application/x-www-form-urlencoded)
$('#form').serializeArray();   // [ { name: 'name', value: 'Ada' }, ... ]
jQuery.param({ a: 1, b: [2, 3] });  // "a=1&b%5B%5D=2&b%5B%5D=3"
----

== Global AJAX events

Bound on `document`, these fire for *every* jQuery AJAX request on the page -- handy for a shared loading
indicator:

[source,javascript]
----
$(document).on('ajaxStart', () => $('#spinner').show());
$(document).on('ajaxStop',  () => $('#spinner').hide());
$(document).on('ajaxError', (event, jqXHR, settings, thrownError) => log(thrownError));
----

== Worked example: loading and saving the list

The shopping list talks to a small JSON API with two endpoints: `GET /api/items` returns an array and
`POST /api/items` creates one and returns it with its new `id`. The two calls show the options that matter most in
real code.

[source,javascript]
----
// load: GET /api/items -> [{ id, text, done }, ...]
$.getJSON('/api/items')
  .done(function (items) {
    $('#list').append(items.map(function (item) {
      return $('<li>').data('id', item.id).toggleClass('done', item.done)
                      .append($('<span>').text(item.text));
    }));
  })
  .fail(function (jqXHR, textStatus) {
    $('#count').text('Could not load the list (' + textStatus + ')');
  });

// save: POST a JSON body -- contentType and JSON.stringify must be set explicitly
function createItem(text) {
  return $.ajax('/api/items', {
    method: 'POST',
    contentType: 'application/json',
    data: JSON.stringify({ text: text, done: false }),
    dataType: 'json'                      // parse the 201 response body
  });
}

createItem('Bread').done(function (item) { console.log('created', item.id); });
----

Passing a plain object as `data` sends `application/x-www-form-urlencoded`; a JSON API normally needs the explicit
`contentType` plus `JSON.stringify` shown above. `+dataType: 'json'+` only controls how the *response* is parsed.

== Request lifecycle and the Deferred states

A jqXHR is a *Deferred*, which has exactly three states. A request leaves `pending` once and never goes back, so a
callback added after the request has finished still runs immediately:

[mermaid]
....
stateDiagram-v2
    [*] --> pending: request sent
    pending --> resolved: 2xx and body parsed
    pending --> rejected: network error, 4xx or 5xx, parse error, timeout, abort
    resolved --> [*]: done callbacks, then always callbacks
    rejected --> [*]: fail callbacks, then always callbacks
....

[source,javascript]
----
const d = $.Deferred();
d.state();            // 'pending'
d.resolve(1);
d.state();            // 'resolved'
d.done(function (v) { console.log(v); });   // runs at once, with 1
----

The `textStatus` passed to `.fail()` tells the failures apart: `"error"` for HTTP and network errors,
`"parsererror"` when `+dataType: 'json'+` met a body that is not valid JSON, `"timeout"`, and `"abort"`.

== Errors, timeouts and cancelling

[source,javascript]
----
$.getJSON('/api/items')
  .fail(function (jqXHR, textStatus, errorThrown) {
    if (jqXHR.status === 500) {
      console.log(jqXHR.responseJSON.error);      // parsed error body, when the server sent JSON
    } else if (textStatus === 'timeout') { /* retry or tell the user */ }
  });

const slow = $.ajax('/api/slow', { timeout: 5000 });
slow.abort();                                      // cancel; fires .fail with textStatus 'abort'

$.ajax('/api/items/9', {
  statusCode: {                                    // handlers keyed by HTTP status
    404: function () { console.log('already gone'); }
  }
});
----

A `204 No Content` response (the usual answer to a `DELETE`) is reported as a success with the status text
`"nocontent"`, even when `+dataType: 'json'+` is set. A `200` response with an empty body and `+dataType: 'json'+` is a
`"parsererror"`, so make sure the server really sends JSON, or omit `dataType` and let jQuery guess from the
`Content-Type` header.

== Several requests, and `await`

`jQuery.when()` waits for several requests. In `.done()` or `.then()` it passes each result as an array
`[data, textStatus, jqXHR]`:

[source,javascript]
----
$.when($.getJSON('/api/items'), $.getJSON('/api/stats'))
  .done(function (itemsResult, statsResult) {
    const items = itemsResult[0];                  // [0] is the data, [1] the status text, [2] the jqXHR
    const stats = statsResult[0];
  });
----

A jqXHR can be awaited, but `await` receives only the *first* resolved value, so the status and jqXHR are not
available. For parallel requests with `await`, hand the requests to the native `Promise.all`:

[source,javascript]
----
async function loadAll() {
  try {
    const [items, stats] = await Promise.all([$.getJSON('/api/items'), $.getJSON('/api/stats')]);
    return { items, stats };
  } catch (jqXHR) {
    console.log('failed with status', jqXHR.status);      // the rejection value is the jqXHR itself
    throw jqXHR;
  }
}
----

`.then()` chains: returning a value from a handler passes it on, and returning another request waits for it:

[source,javascript]
----
$.getJSON('/api/items')
  .then(function (items) { return items.map(function (i) { return i.text; }); })
  .then(function (names) { console.log(names); });          // ['Milk', 'Eggs', 'Bread']
----

== Form serialization requires `name` attributes

`.serialize()` and `.serializeArray()` read form controls by their `name` attribute. A control with only an `id`
is silently skipped, so the shopping list's input needs `name="item"`. Spaces are encoded as `%20`:

[source,javascript]
----
$('#add-input').attr('name', 'item').val('Tea & cake');
$('#add-form').serialize();         // 'item=Tea%20%26%20cake'
$('#add-form').serializeArray();    // [ { name: 'item', value: 'Tea & cake' } ]
----

Disabled controls, unticked checkboxes, and file inputs are omitted, matching what a native form submit sends.

== Shared behaviour with prefilters

`jQuery.ajaxPrefilter()` runs a function before every request is sent and can edit its options, which is the
supported way to add an authorization header everywhere without passing it at every call site:

[source,javascript]
----
$.ajaxPrefilter(function (options) {
  options.headers = Object.assign({ 'X-Requested-With': 'XMLHttpRequest' }, options.headers);
});
----

== Modern equivalent

`fetch(url, options)` returns a real `Promise`; pair it with `AbortController` for `timeout`-style
cancellation. Note `fetch` only rejects on a *network* failure -- check `response.ok` for HTTP 4xx/5xx
yourself. Build request bodies with `FormData` (`new FormData(formEl)`) or `URLSearchParams`. Cross-origin
requests are subject to CORS regardless of which API you use -- see xref:web/cors.adoc[What is CORS?]. For the
full `fetch`, SSE, and WebSocket reference see xref:programming-languages/javascript/browser-networking.adoc[Networking], and
xref:programming-languages/javascript/async-javascript.adoc[Asynchronous JavaScript] for promises and `async`/`await`.
