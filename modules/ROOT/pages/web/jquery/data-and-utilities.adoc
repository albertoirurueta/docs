= Element Data and Utility Functions
:description: Storing per-element data with .data(), finding an element's position with .index(), getting raw DOM nodes out of a set with .get()/.toArray(), and the jQuery.* static utility helpers and their native replacements.
:keywords: jQuery data, data method, data attributes, index, get, toArray, jQuery.each, jQuery.map, jQuery.grep, jQuery.extend, jQuery.merge, jQuery.inArray, jQuery.trim, jQuery.parseJSON, jQuery.fn.jquery

include::partial$ai-disclaimer.adoc[]

Two families here: instance methods that read information off a wrapped set (`.data()`, `.index()`, `.get()`),
and static `+jQuery.*+` functions that operate on plain values rather than DOM elements.

== `.data()` -- per-element storage

[source,javascript]
----
$('#row').data('state', 'open');     // store (in jQuery's internal cache, NOT the DOM)
$('#row').data('state');             // read -> 'open'
$('#row').data();                    // read all -> { state: 'open' }
$('#row').removeData('state');       // remove one key
----

`.data()` also *reads* `+data-*+` attributes, once:

[source,html]
----
<div id="row" data-user-id="42" data-config='{"open":true}'></div>
----

[source,javascript]
----
$('#row').data('userId');   // 42  (number -- jQuery coerces; note camelCase from data-user-id)
$('#row').data('config');   // { open: true }  (valid JSON is parsed to an object)
----

Key points that surprise people:

* The `+data-*+` attribute is read **only on first access**, then cached. Later `.data()` calls read the cache.
* `+.data('userId', 99)+` updates the cache but does **not** write back to the `data-user-id` attribute -- the
  DOM still shows `42`. Use `+.attr('data-user-id', 99)+` if the attribute itself must change.
* `data-user-id` in HTML becomes `userId` in `.data()` (kebab-case to camelCase).

== `.index()` -- position among siblings

[source,javascript]
----
$('#item').index();               // position of #item among its siblings (0-based)
$('li').index($('#item'));         // position of #item within the jQuery set of all <li>
$('li').index(domNode);            // same, given a raw element
$('#list li.active').index();      // position of the first .active <li> among its siblings
----

== Getting raw DOM nodes out

[source,javascript]
----
$('li').get();        // -> real Array of HTMLLIElement
$('li').get(0);       // -> the first raw element (supports negative index: .get(-1) = last)
$('li').toArray();    // -> real Array (same as .get() with no arg)
$('li')[0];           // -> the first raw element (bracket access, no negative index)
----

`.get(0)` and `[0]` return the same node; `.get()` is preferred when you want the negative-index convenience or
a genuine array to run `Array` methods on.

== Static utility functions

[source,javascript]
----
jQuery.each(coll, (key, val) => { /* ... */ });   // iterate array OR object; return false to break
jQuery.map(arr, (val, i) => val * 2);              // map; returned null/undefined items are dropped
jQuery.grep(arr, (val, i) => val > 0);             // filter
jQuery.grep(arr, fn, true);                         // filter, INVERTED
jQuery.extend(target, src1, src2);                 // shallow-merge sources into target
jQuery.extend(true, target, src);                  // DEEP merge
jQuery.merge(first, second);                        // append second's items onto first (mutates first)
jQuery.inArray(value, arr);                         // index of value, or -1  (like indexOf)
jQuery.now();                                       // Date.now()
jQuery.fn.jquery;                                   // the loaded version string, e.g. "3.7.1"
----

=== Deprecated -- use the native form

[cols="1,1",options="header"]
|===
| Deprecated jQuery utility | Native replacement

| `jQuery.trim(str)` | `str.trim()`
| `jQuery.type(x)` | `typeof x` / `Array.isArray(x)` / `x === null`
| `jQuery.isArray(x)` | `Array.isArray(x)`
| `jQuery.isFunction(x)` | `+typeof x === 'function'+`
| `jQuery.parseJSON(s)` | `JSON.parse(s)`
| `jQuery.each` / `jQuery.map` / `jQuery.grep` | `Array.prototype.forEach` / `map` / `filter`, `+for...of+`
| `jQuery.inArray(v, a)` | `a.includes(v)` / `a.indexOf(v)`
| `+jQuery.extend({}, a, b)+` | `+Object.assign({}, a, b)+` / `+{ ...a, ...b }+`
| `jQuery.now()` | `Date.now()`
|===

== Worked example: saving and restoring the list

The shopping list needs a plain, serializable representation of its rows so it can be saved and restored. The
`.map()` / `.get()` pair of the previous pages produces it, and `.data()` carries values that have no place in the
visible markup, such as a database id:

[source,javascript]
----
function readItems() {
  return $('#list li').map(function () {
    const $row = $(this);
    return {
      id: $row.data('id') ?? null,                   // typed value from data-id, if present
      text: $row.children('span').text(),
      done: $row.hasClass('done')
    };
  }).get();                                           // jQuery set -> plain array
}

function writeItems(items) {
  const $list = $('#list').empty();
  $.each(items, function (index, item) {
    $('<li>')
      .data('id', item.id)
      .toggleClass('done', item.done)
      .append($('<span>').text(item.text))
      .appendTo($list);
  });
}

const json = JSON.stringify(readItems());   // '[{"id":null,"text":"Milk","done":true}, ...]'
writeItems(JSON.parse(json));
----

`.map()` flattens an array returned from the callback and drops `null` and `undefined`, so `.get()` is needed
afterwards to turn the jQuery wrapper into a real array that `JSON.stringify` serializes cleanly.

== The `.data()` cache lifecycle

`.data()` reads the `+data-*+` attribute once, caches it, and from then on only the cache is consulted. Reads and
writes after that first access never touch the attribute:

[mermaid]
....
sequenceDiagram
    participant C as Calling code
    participant J as jQuery data cache
    participant A as data-id attribute
    C->>J: .data('id')
    J->>A: first access only, read and convert the value
    A-->>J: "7" converted to the number 7
    J-->>C: 7
    C->>J: .data('id', 99)
    Note over J: cache now holds 99
    Note over A: attribute still says 7
    C->>J: .data('id')
    J-->>C: 99, no attribute read
    C->>A: .attr('data-id', 5)
    Note over J: cache still holds 99
....

Two practical rules follow. Use `.data()` for values owned by the script, and `+.attr('data-*')+` (or `dataset`)
when other code, CSS attribute selectors, or the server reads the markup. And never rely on the attribute to
reflect a `.data()` write when you serialize the DOM, for example with `.outerHTML` or `.html()`.

== Merging options safely

`jQuery.extend()` is the tool plugins use to merge caller options onto defaults. The first argument decides what
is modified, so pass a fresh `+{}+` to leave the defaults untouched, and pass `true` first when nested objects must
merge instead of being replaced:

[source,javascript]
----
const defaults = { sort: 'manual', limits: { max: 10, min: 1 } };

const shallow = $.extend({}, defaults, { limits: { max: 5 } });
shallow.limits;            // { max: 5 } -- the whole nested object was replaced

const deep = $.extend(true, {}, defaults, { limits: { max: 5 } });
deep.limits;               // { max: 5, min: 1 } -- merged recursively
----

Deep merge copies plain objects and arrays but not class instances or DOM nodes.

== Type checks and array helpers that are still current

Most of the static helpers are deprecated in favour of native code (see the table above), but a handful have no
one-line native equivalent and remain supported:

[source,javascript]
----
$.isPlainObject({});                 // true: created by {} or new Object
$.isPlainObject(new Date());         // false
$.isEmptyObject({});                 // true: no own enumerable properties
$.makeArray($('li'));                // real array from a jQuery set or NodeList
$.contains(document.documentElement, document.body);   // is the second node inside the first?
$.uniqueSort([nodeA, nodeA, nodeB]); // sort into document order, remove duplicates (DOM nodes only)
----

== Parsing HTML without running it

`jQuery.parseHTML()` turns a string into nodes without inserting them, and by default it drops any `<script>`
elements. That makes it the safer way to handle markup that came from outside, compared with `$(html)`, which may
keep inline event attributes:

[source,javascript]
----
$.parseHTML('<b>x</b><script>alert(1)</script>').length;            // 1 -- script removed
$.parseHTML('<b>x</b><script>alert(1)</script>', document, true).length;  // 2 -- third argument keeps scripts
----

Even with scripts removed, attributes such as `onerror` survive, so untrusted markup still needs a real sanitizer
before it is inserted with `.html()`.

== A leak-free alternative: `WeakMap`

`.data()` is cleaned up for you by `.remove()` and `.empty()`, but plain code that stores per-element state in its
own object keeps the node alive forever. A `WeakMap` keyed by the element avoids that and works without jQuery:

[source,javascript]
----
const state = new WeakMap();
$('#list li').each(function () {
  state.set(this, { clicks: 0 });          // dropped automatically when the <li> is garbage collected
});
----

== Modern equivalent

`el.dataset.userId` reads/writes `+data-*+` attributes directly (string values only -- parse JSON yourself).
For arbitrary non-string per-element data with no DOM footprint, a `WeakMap` keyed by the element is the
leak-free equivalent of jQuery's data cache. The utility functions map to `Array`/`Object` built-ins as in the
table above. See xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics] and
xref:programming-languages/javascript/arrays.adoc[Arrays & typed arrays].
