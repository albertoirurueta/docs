= Getting Started with jQuery
:description: What jQuery is, the jQuery/$ function and the wrapped set, why and when (not) to use it, how to add it to a page via download or CDN with Subresource Integrity, and the document-ready pattern.
:keywords: jQuery, getting started, $, jQuery function, wrapped set, jQuery object, CDN, code.jquery.com, slim build, Subresource Integrity, integrity, crossorigin, document ready, noConflict

include::partial$ai-disclaimer.adoc[]

jQuery is a small JavaScript library that wraps the browser DOM APIs of its era in a terse, chainable,
cross-browser interface. A single global function -- `jQuery`, almost always written as `$` -- selects
elements, and the object it returns carries dozens of methods for reading and changing them. In 2006 that
smoothed over deep browser inconsistencies; today the native APIs have caught up, so this page gives equal
weight to *when not to* reach for it.

== The `jQuery` function and the `$` alias

`$` is just another name for the `jQuery` function. Called with a CSS selector string it returns a *wrapped
set* (also called a "jQuery object"): an array-like object holding zero or more matched DOM nodes plus every
jQuery method.

[source,javascript]
----
$('p.intro');            // wrapped set of every <p class="intro">
jQuery('p.intro');       // identical -- $ is an alias for jQuery

const $items = $('#list li');
$items.length;           // how many matched -- 0 means "selected nothing"
$items[0];               // the first raw DOM element (HTMLLIElement), not a jQuery object
$items.get(0);           // same raw element, via the jQuery accessor
$items.eq(0);            // a NEW wrapped set containing only the first element
----

The same function does four different jobs depending on what you pass it:

[source,javascript]
----
$('div.card')                       // 1. selector string  -> find existing elements
$(document.body)                    // 2. DOM node/NodeList -> wrap existing nodes
$('<li class="new">Hi</li>')        // 3. HTML string       -> create a detached element
$(function () { /* ... */ })        // 4. function          -> run it when the DOM is ready
----

A wrapped set is *not* an array and the elements inside it are *not* jQuery objects. Convert deliberately:
`$(rawNode)` wraps a node, `$set.get(i)` / `$set[i]` unwraps one, `$set.toArray()` unwraps all.

== Why use jQuery -- and when not to

Reasons it still appears in codebases:

* Terse selection and iteration: `+$('.x').addClass('y')+` acts on every match with no explicit loop.
* Implicit null-safety: operating on an empty set is a silent no-op rather than a `TypeError`.
* Chaining: most methods return the set, so calls compose left to right.
* A large plugin ecosystem accumulated over ~15 years.

Reasons to prefer native APIs for new work:

[cols="1,1",options="header"]
|===
| jQuery | Modern native equivalent

| `$(sel)` | `document.querySelectorAll(sel)` (+ `+for...of+`)
| `.addClass` / `.removeClass` / `.toggleClass` | `el.classList.add` / `.remove` / `.toggle`
| `+.on('click', fn)+` | `+el.addEventListener('click', fn)+`
| `.append` / `.prepend` / `.before` / `.after` / `.remove` | same-named native methods on `Element`
| `$.ajax` / `$.get` / `$.getJSON` | `fetch()` (+ `AbortController`)
| `.each` | `+for...of+`, `Array.prototype.forEach`
|===

Bootstrap 5, most component frameworks (React, Vue, Angular), and modern build tooling dropped jQuery entirely.
For a greenfield project the native DOM is enough; see
xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics].

== Adding jQuery to a page

=== Downloaded file

Download `jquery-3.7.1.min.js` from https://jquery.com/download/[jquery.com/download] and serve it yourself:

[source,html]
----
<script src="/js/jquery-3.7.1.min.js"></script>
----

Self-hosting avoids a third-party origin and works offline, at the cost of the shared-cache benefit a common
CDN once offered.

=== Official CDN

https://code.jquery.com/[code.jquery.com] serves each release. Add `integrity` and `crossorigin` so the
browser refuses a tampered file
(https://developer.mozilla.org/en-US/docs/Web/Security/Subresource_Integrity[Subresource Integrity]):

[source,html]
----
<script
  src="https://code.jquery.com/jquery-3.7.1.min.js"
  integrity="sha256-..."
  crossorigin="anonymous"></script>
----

Copy the current `integrity` value verbatim from https://code.jquery.com/[the official CDN page] -- it is a
base64-encoded hash specific to that exact file, and the browser rejects the script if the served bytes do not
match. `crossorigin="anonymous"` is required for the check to run on a cross-origin script. Load jQuery
*before* any script that uses `$`.

=== `slim` vs. full build

The `slim` build drops the AJAX module (`$.ajax` and friends) and the entire effects module (`.animate()`,
`.fadeIn()` / `.fadeOut()`, `.slideUp()` / `.slideDown()`, and the rest of
xref:web/jquery/effects-and-animation.adoc[Effects and Animation]), saving a few kilobytes. Use it only if the
page needs neither. The full build is the default and what the rest of this section assumes.

== Running code when the DOM is ready

Selecting an element before the browser has parsed it yields an empty set. Wait for the DOM:

[source,javascript]
----
$(document).ready(function () { /* DOM parsed; elements selectable */ });
$(function () { /* identical shorthand -- the common form */ });
----

`ready` fires as soon as the DOM tree exists, *before* images and stylesheets finish loading -- earlier than
the native `window.onload` (which waits for every sub-resource). A modern script loaded with `defer`, or an ES
module (which is deferred by default), or a `<script>` placed just before `</body>`, already runs after the DOM
is parsed, making the wrapper largely redundant today -- but it is harmless and still common.

`jQuery.noConflict()` releases the `$` global back to whatever owned it before (some older libraries also used
`$`); `jQuery` keeps working, and you can capture a private alias: `+jQuery(function ($) { /* $ is jQuery here */ });+`.

TIP: The browser DevTools console is the fastest way to experiment -- on any page that has jQuery loaded, type
`+$('h1').css('color', 'red')+` and watch it apply live.

== What the `$()` function does with its argument

The four jobs listed above are not four functions: `jQuery(arg)` is one function that inspects its argument and
dispatches. Knowing the order of the checks explains several surprises, such as why a string that happens to start
with `<` is parsed as HTML instead of being used as a selector.

[mermaid]
....
flowchart TD
    A["jQuery(arg)"] --> B{"What is arg?"}
    B -->|"falsy: undefined, null, empty string"| E["empty set, length 0"]
    B -->|"function"| R["register a ready callback"]
    B -->|"DOM node or window"| W["wrap that one node"]
    B -->|"jQuery object or array-like"| C["copy the nodes into a new set"]
    B -->|"string"| S{"Starts with an angle bracket?"}
    S -->|"yes: looks like HTML"| H["parse the markup, return detached nodes"]
    S -->|"no"| Q["run the selector engine"]
    Q --> Q1{"Valid CSS?"}
    Q1 -->|"yes"| Q2["native querySelectorAll, fast path"]
    Q1 -->|"no: jQuery extension"| Q3["Sizzle JavaScript engine, slow path"]
....

Two consequences matter in day-to-day code:

* A selector built from user input can be mistaken for markup. `$(userText)` is an injection risk if
  `userText` can start with `<`; use `$(document).find(userText)` or, better, never build selectors from untrusted
  text at all.
* An empty set is a legitimate result of every branch. `$()`, `$(null)` and `+$('#missing')+` all return a set of
  length 0 that accepts every jQuery method.

== The page-load timeline and `ready`

The browser reaches `ready` well before the page is fully loaded, and that gap is the reason `$(fn)` exists:

[mermaid]
....
flowchart LR
    P["HTML parsed into the DOM"] --> D["DOMContentLoaded"]
    D --> RD["jQuery ready callbacks run"]
    D --> L["images, fonts and iframes finish loading"]
    L --> LD["window load event"]
....

Since jQuery 3, a ready callback is *always* invoked asynchronously, even when the DOM was already parsed at the
moment you registered it. Code after the registration therefore always runs first, which keeps the behaviour
identical whether the script is loaded early or late:

[source,javascript]
----
const order = [];
$(function () { order.push('ready callback'); });
order.push('script continues');
// order is now ['script continues'] -- the ready callback is queued, never run synchronously
// a moment later: ['script continues', 'ready callback']
----

Each ready callback receives `jQuery` as its first argument, so `+jQuery(function ($) { ... })+` gives the callback a
private `$` even after `jQuery.noConflict()`.

== Setting up the running example

The pages that follow keep returning to one small project: the shopping list built on
xref:web/jquery/interactive-list-project.adoc[Worked Example: An Interactive List]. Its markup is a form, a count
line, and an empty `<ul id="list">`. A first script that only proves the wiring works:

[source,html]
----
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Shopping list</title></head>
<body>
  <form id="add-form">
    <input id="add-input" name="item" type="text" autocomplete="off" required>
    <button type="submit">Add</button>
  </form>
  <p id="count"></p>
  <ul id="list">
    <li class="done"><span>Milk</span></li>
    <li><span>Eggs</span></li>
    <li><span>Bread</span></li>
  </ul>

  <script src="/js/jquery-3.7.1.min.js"></script>
  <script>
    $(function () {
      console.log('jQuery ' + $.fn.jquery);               // jQuery 3.7.1
      const $rows = $('#list li');
      $('#count').text($rows.filter('.done').length + ' of ' + $rows.length + ' done');  // 1 of 3 done
    });
  </script>
</body>
</html>
----

`$.fn.jquery` is the loaded version string; printing it first is the quickest way to find out which of several
copies of jQuery a page actually loaded.

== Troubleshooting the first five minutes

[cols="2,3",options="header"]
|===
| Symptom | Usual cause

| `$ is not defined` in the console
| jQuery loaded after the script that uses it, the `<script src>` failed (check the Network tab), or another
  library took `$` and `jQuery.noConflict()` was called.

| `+$('#x').length+` is `0`
| The script ran before the element existed (wrap it in `$(fn)` or use `defer`), the id is misspelled, or the
  element is inside a `<template>` and so is not in the live document.

| The browser blocks the CDN script with an integrity error
| The `integrity` hash does not match that exact file. Copy the hash for the same version from the CDN page.

| `+$(...).slideDown is not a function+`
| The `slim` build was loaded; it has no effects module.

| Two different versions behave differently on one page
| A plugin bundled its own copy of jQuery. Check `$.fn.jquery` and `jQuery.fn.jquery` after each script loads.
|===

== Modern equivalent

`$(fn)` -> put the script in a `defer`-ed `<script>` or a `<script type="module">` and the DOM is already
parsed when it runs, or use `+document.addEventListener('DOMContentLoaded', fn)+`. `$(sel)` ->
`document.querySelectorAll(sel)`. See xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics] for
the native selection, creation, and traversal APIs.
