= Plugins and Modern Usage
:description: Writing a well-behaved jQuery plugin on $.fn -- chainable, options-driven via $.extend -- an orientation to jQuery UI/Mobile and common plugins, and how to migrate a codebase off jQuery with jquery-migrate and a jQuery-to-native map.
:keywords: jQuery plugin, $.fn, jQuery.fn, extend, chainable plugin, jQuery UI, jQuery Mobile, jquery-migrate, migrate off jQuery, jQuery to vanilla JS

include::partial$ai-disclaimer.adoc[]

Every jQuery instance method lives on `jQuery.fn` (an alias of `jQuery.prototype`). A "plugin" is just a
function you add there so it is callable on any wrapped set.

== A minimal plugin

The contract for a well-behaved plugin: iterate the set with `.each()`, return `this` so the call stays
chainable, and namespace everything. In prose the skeleton reads
`+$.fn.myThing = function (options) { return this.each(...); };+`:

[source,javascript]
----
(function ($) {
  $.fn.highlight = function (options) {
    // merge caller options over defaults into a fresh object
    const settings = $.extend({}, $.fn.highlight.defaults, options);

    // return the set so callers can keep chaining
    return this.each(function () {
      $(this).css({
        backgroundColor: settings.color,
        color: settings.textColor
      });
    });
  };

  // published defaults -- callers can override globally
  $.fn.highlight.defaults = { color: '#fff7b0', textColor: '#222' };
}(jQuery));
----

[source,javascript]
----
$('.term').highlight();                       // defaults
$('.term').highlight({ color: '#c8f7c5' });   // per-call override
$('.term').highlight().addClass('marked');    // still chainable
----

Guidelines: never assume the set is non-empty (`this.each` handles zero elements fine), do not break the chain
(always `return this` or a jQuery set), read configuration from a single `options` object merged with
`$.extend`, and keep any event handlers in a namespace (`+.on('click.highlight', ...)+`) so the plugin can clean
up after itself.

== Worked example: a `checklist` plugin

The shopping list behaviour can be packaged as a plugin so another page can turn any `<ul>` into a checklist with
one call. This version follows the contract above and adds the pieces real plugins need: an options object merged
over published defaults, a per-element instance kept with `.data()`, a string form to call methods
(`+.checklist('add', 'Milk')+`), custom events, a namespace for its handlers, and a `destroy` that undoes the setup.

[source,javascript]
----
(function ($) {
  const KEY = 'checklist';

  $.fn.checklist = function (options, ...args) {
    // method call: $('#list').checklist('add', 'Milk')
    if (typeof options === 'string') {
      let result = this;
      this.each(function () {
        const api = $.data(this, KEY);
        if (!api || typeof api[options] !== 'function') {
          throw new Error('checklist: cannot call "' + options + '" before init or with an unknown name');
        }
        const value = api[options](...args);
        if (value !== undefined) { result = value; return false; }   // getter: stop and return it
      });
      return result;
    }

    const settings = $.extend({}, $.fn.checklist.defaults, options);

    return this.each(function () {
      if ($.data(this, KEY)) return;                  // initialise once per element
      const el = this;
      const $list = $(el).addClass(settings.listClass);

      const api = {
        add(text) {
          $('<li>').append($('<span>').text(text)).appendTo($list);
          $list.trigger('checklist:add', [text]);
        },
        items() {
          return $list.children('li').map(function () {
            return { text: $(this).children('span').text(), done: $(this).hasClass(settings.doneClass) };
          }).get();
        },
        destroy() {
          $list.off('.checklist').removeClass(settings.listClass);
          $.removeData(el, KEY);
        }
      };

      $list.on('click.checklist', 'li > span', function () {
        $(this).parent().toggleClass(settings.doneClass);
        $list.trigger('checklist:toggle', [$(this).text()]);
      });

      $.data(el, KEY, api);
    });
  };

  $.fn.checklist.defaults = { listClass: 'checklist', doneClass: 'done' };
}(jQuery));
----

Using it:

[source,javascript]
----
$('#list').checklist({ doneClass: 'ok' });            // initialise
$('#list').on('checklist:toggle', function (event, text) {
  console.log('toggled', text);
});

$('#list').checklist('add', 'Milk').checklist('add', 'Eggs');   // setters return the set: chainable
$('#list li span').first().trigger('click');                    // toggles the "ok" class
$('#list').checklist('items');     // [{ text: 'Milk', done: true }, { text: 'Eggs', done: false }]
$('#list').checklist('destroy');   // handlers and class removed, instance forgotten
----

Several design choices in that listing are worth copying:

* **One instance per element.** `+$.data(el, 'checklist')+` stores the API object, so calling the plugin twice on
  the same element is a no-op instead of binding every handler twice.
* **Methods return `this` or a value.** A method that changes state returns `undefined` from the API, and the
  plugin then returns the jQuery set so the call chains. A method that reads state returns its value and stops
  iterating, which is how `+.checklist('items')+` can hand back an array.
* **A namespace for every handler.** `click.checklist` lets `destroy` call `+.off('.checklist')+` and remove exactly
  what the plugin added, without touching handlers the page bound itself.
* **Events instead of callbacks.** `checklist:add` and `checklist:toggle` are triggered on the list, so page code
  subscribes with an ordinary `.on()` and several listeners can coexist.
* **Capture the element, not `this`.** Inside the API methods `this` is the API object, not the element, so the
  closure keeps the element in a variable (`el`) for `+$.removeData(el, 'checklist')+`.

== Extending the selector engine from a plugin

A plugin can also register new pseudo-selectors on `jQuery.expr.pseudos`; the completed-rows filter used on the
xref:web/jquery/selectors.adoc[selectors page] is the smallest example. A pseudo that takes an argument is built
with `jQuery.expr.createPseudo()`:

[source,javascript]
----
$.expr.pseudos.starts = $.expr.createPseudo(function (prefix) {
  return function (element) {
    return $(element).text().trim().toLowerCase().indexOf(prefix.toLowerCase()) === 0;
  };
});

$('#list li:starts(m)');      // rows whose label starts with "m", case-insensitively
----

== The wider plugin ecosystem

* https://jqueryui.com/[jQuery UI] -- a curated set of interactions (draggable, sortable, resizable), widgets
  (datepicker, dialog, autocomplete, tabs), and additional easing functions. Largely in maintenance mode.
* https://api.jquerymobile.com/[jQuery Mobile] -- a touch-oriented UI framework built on jQuery UI. Officially
  deprecated; do not start new work with it.
* Standalone plugins that were ubiquitous -- Slick / slick-carousel, Select2, DataTables, Chosen, Magnific
  Popup. Most now ship, or have been superseded by, a dependency-free version; check before adding jQuery to a
  project solely to run one.

This section does not document those libraries; treat the links as a starting point.

== Migrating off jQuery

The official https://github.com/jquery/jquery-migrate[jquery-migrate] plugin restores APIs removed across
jQuery 1.x -> 3.x and logs a console warning every time deprecated behaviour is hit. Load it right after
jQuery, exercise the app, and use the warnings as a to-do list; then remove it once the log is clean.

To remove jQuery entirely, translate call by call:

[cols="1,1",options="header"]
|===
| jQuery | Native

| `$(sel)` | `document.querySelectorAll(sel)`
| `$el.find(sel)` | `el.querySelectorAll(sel)`
| `+$el.addClass('x')+` | `+el.classList.add('x')+`
| `+$el.toggleClass('x', on)+` | `+el.classList.toggle('x', on)+`
| `+$el.attr('href')+` | `+el.getAttribute('href')+`
| `+$el.prop('checked')+` | `el.checked`
| `+$el.on('click', fn)+` | `+el.addEventListener('click', fn)+`
| `+$el.on('click', 'li', fn)+` | `+el.addEventListener('click', e => { if (e.target.closest('li')) fn(e); })+`
| `$el.append(node)` | `el.append(node)`
| `$el.remove()` | `el.remove()`
| `+$el.css('color', 'red')+` | `+el.style.color = 'red'+`
| `$el.each(fn)` | `+for (const el of list) { ... }+`
| `$.ajax` / `$.getJSON` | `fetch()` (+ `AbortController`)
| `$(fn)` (ready) | `<script defer>` / `DOMContentLoaded`
|===

A pragmatic middle step is a tiny helper -- `+const $ = (s, r = document) => r.querySelectorAll(s);+` -- plus
`Array.prototype` methods, which covers most day-to-day selection and iteration without the library.

== Using jQuery UI sortable on the list

jQuery UI is a plugin collection built on its own widget factory. Drag-to-reorder on the shopping list, instead of
the up and down buttons, takes one call once jQuery UI and its stylesheet are loaded after jQuery:

[source,html]
----
<script src="/js/jquery-3.7.1.min.js"></script>
<script src="/js/jquery-ui.min.js"></script>
<script>
  $('#list').sortable({
    handle: 'span',                         // drag by the label
    update: function () { $('#list').trigger('list:change'); }
  });
</script>
----

Widgets configure with an options object, expose methods through the same string form shown above
(`+$('#list').sortable('destroy')+`), and fire callbacks such as `update`. The native replacement is the HTML Drag
and Drop API or a small dependency-free library; that is a considerable amount of code, which is the usual reason
a project keeps jQuery UI for one widget.

== Migrating the running example, step by step

A realistic migration is incremental. The order below keeps the page working after every step:

[mermaid]
....
flowchart TD
    A["Load jquery-migrate after jQuery and exercise the page"] --> B["Fix every console warning"]
    B --> C["Upgrade jQuery to the current 3.x release"]
    C --> D["Replace static helpers: trim, isArray, each, extend"]
    D --> E["Replace selection and traversal with querySelectorAll and closest"]
    E --> F["Replace events and delegation with addEventListener"]
    F --> G["Replace effects with CSS transitions, and AJAX with fetch"]
    G --> H["Remove jquery-migrate, then jQuery itself"]
....

Step one in markup:

[source,html]
----
<script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
<script src="https://code.jquery.com/jquery-migrate-3.5.2.min.js"></script>
----

Copy the exact file names and their `integrity` values from the https://code.jquery.com/[CDN page]. After the last
step, the shopping list from xref:web/jquery/interactive-list-project.adoc[the worked example] has no jQuery at all.
This is the add, remove, reorder and toggle behaviour ported to native DOM APIs, with delegation done through
`event.target.closest()`:

[source,javascript]
----
document.addEventListener('DOMContentLoaded', () => {
  const list = document.querySelector('#list');
  const input = document.querySelector('#add-input');

  const rowFor = (text) => {
    const li = document.createElement('li');
    li.innerHTML =
      '<span></span>' +
      '<button class="up" title="Move up">&uarr;</button>' +
      '<button class="down" title="Move down">&darr;</button>' +
      '<button class="del" title="Delete">&times;</button>';
    li.querySelector('span').textContent = text;   // textContent escapes, like .text()
    return li;
  };

  document.querySelector('#add-form').addEventListener('submit', (event) => {
    event.preventDefault();
    const text = input.value.trim();
    if (!text) return;
    list.append(rowFor(text));
    input.value = '';
    input.focus();
  });

  // delegation: one listener, then closest() on the event target
  list.addEventListener('click', (event) => {
    const li = event.target.closest('li');
    if (!li || !list.contains(li)) return;
    if (event.target.closest('.del')) li.remove();
    else if (event.target.closest('.up') && li.previousElementSibling) li.previousElementSibling.before(li);
    else if (event.target.closest('.down') && li.nextElementSibling) li.nextElementSibling.after(li);
    else if (event.target.closest('span')) li.classList.toggle('done');
  });
});
----

The ported version is shorter than it looks only because the animations were dropped. The rule of thumb that
emerges: selection, traversal, class changes, insertion and events port line for line, while effects and AJAX
need a design decision (CSS transitions and `fetch`) rather than a mechanical rewrite.

== Modern equivalent

The whole page: modern browsers need no library for DOM work. For reusable UI behaviour, a Web Component
(custom element) is the native equivalent of a stateful jQuery plugin -- see
xref:programming-languages/javascript/browser-web-components.adoc[Web Components] -- and
xref:programming-languages/javascript/browser-dom-basics.adoc[Web programming basics] for the selection/manipulation primitives.
