= Effects and Animation
:description: jQuery's built-in effects -- show/hide, fading, and sliding -- the general-purpose .animate() method, and the per-element effects queue controlled by .stop(), .finish(), .delay(), and jQuery.fx.
:keywords: jQuery effects, show, hide, toggle, fadeIn, fadeOut, fadeTo, slideDown, slideUp, animate, easing, stop, finish, delay, jQuery.fx.off, effects queue

include::partial$ai-disclaimer.adoc[]

jQuery ships a small animation system built on `setInterval`/`requestAnimationFrame`. Every effect method
takes an optional `duration` (milliseconds, or `"slow"` = 600, `"fast"` = 200) and an optional `complete`
callback that runs once the animation finishes.

== Show, hide, toggle

[source,javascript]
----
$('#panel').hide();               // instant: sets display:none
$('#panel').show();               // instant: restores the previous display value
$('#panel').hide(400);            // animated: shrinks size + fades opacity over 400ms
$('#panel').toggle(400, () => console.log('done'));  // hide if visible, else show
----

== Fading

[source,javascript]
----
$('#img').fadeIn(300);
$('#img').fadeOut(300);
$('#img').fadeToggle(300);
$('#img').fadeTo(300, 0.4);        // fade to a specific opacity (0.4), keeps layout space
----

`fadeOut` ends at `display:none`; `fadeTo` only changes opacity and leaves the element occupying space.

== Sliding

[source,javascript]
----
$('#menu').slideDown(200);         // animate height from 0 to auto
$('#menu').slideUp(200);           // animate height to 0, then display:none
$('#menu').slideToggle(200);
----

== General-purpose `.animate()`

[source,javascript]
----
$('#box').animate(
  { width: '300px', opacity: 0.5, marginLeft: '+=40' },  // properties to tween
  600,                                                    // duration
  'swing',                                                // easing
  function () { /* complete callback; `this` is the element */ }
);
----

Notes on the properties object (referred to in prose it looks like `+{ width: '300px', opacity: 0.5 }+`):

* Only properties with **numeric** values can be animated -- lengths, `opacity`, `scrollTop`. Colours and
  `display` cannot (jQuery UI adds colour tweening).
* Relative values: `pass:c['+=40']` / `+'-=40'+` animate by a delta from the current value.
* Special keywords: `+'toggle'+`, `+'show'+`, `+'hide'+` as a value animate that property in/out.
* Built-in easing is `+'swing'+` (default, ease-in-out) and `+'linear'+`. More easings (`easeInOutQuad`, ...) come
  from https://jqueryui.com/effect/[jQuery UI] or a plugin.

== Controlling the queue

Each element has its own FIFO **effects queue** (the `"fx"` queue). Calling an effect method while one is
already running *appends* to that element's queue rather than interrupting it; jQuery drains the queue one
animation at a time.

[mermaid]
....
flowchart TB
    A["chained calls on #box: slideDown(200), then fadeTo(200, 0.5), then animate(300)"]
    A --> q1["queue step 1: slideDown 200ms"]
    q1 --> q2["queue step 2: fadeTo 200ms"]
    q2 --> q3["queue step 3: animate 300ms"]
    q3 --> R["steps run one at a time; stop() drops the current step; finish() clears the whole queue"]
....

[source,javascript]
----
$('#box').stop();             // stop the CURRENT animation; leave the rest of the queue
$('#box').stop(true);         // stop current AND clear the queued animations
$('#box').stop(true, true);   // clear queue AND jump the current one to its end state
$('#box').finish();           // stop everything and jump ALL queued animations to their end
$('#box').delay(1000).fadeIn();          // insert a 1s pause between queued effects
----

Global switches:

[source,javascript]
----
jQuery.fx.off = true;         // disable all animation: effects jump straight to the end
jQuery.fx.interval = 16;      // ms between animation frames (default ~13)
jQuery.fx.speeds.slow;        // 600  -- the named-duration table (editable)
----

Setting `jQuery.fx.off` is how you honour a user's `prefers-reduced-motion` preference globally.

== Worked example: animating list rows

The shopping list animates rows opening and closing. Two details turn the simple effects into reliable behaviour:
waiting for an animation with `.promise()`, and preventing double-clicks from stacking animations.

[source,javascript]
----
// remove a row only AFTER it has slid shut
$('#list').on('click', '.del', function () {
  const $li = $(this).closest('li');
  $li.stop(true, true)            // finish any animation already running on this row
     .slideUp(150)
     .promise()                   // resolves when the row's queue is empty
     .done(function () { $li.remove(); });
});
----

`.promise()` returns a promise that resolves when all queued animations on the set have finished. Called on a set,
it also waits for *every* element, so it is the right way to run code after a group animation:

[source,javascript]
----
$('#list li').fadeOut(200).promise().done(function () {
  console.log('every row has faded out');
});

// or with async/await
await $('#list li').fadeIn(200).promise();
----

== The effects lifecycle

Every effect call joins the element's `fx` queue and passes through the same states, which is why `.stop()` and
`.finish()` behave consistently regardless of which method started the animation:

[mermaid]
....
stateDiagram-v2
    [*] --> Queued: effect method called
    Queued --> Running: queue reaches this step
    Running --> Done: duration elapsed
    Running --> Done: stop with jumpToEnd set to true
    Running --> Dropped: stop without jumpToEnd
    Queued --> Dropped: stop with clearQueue set to true
    Done --> [*]: complete callback runs, next step starts
    Dropped --> [*]: complete callback does not run
....

Two points follow from the diagram. First, a `complete` callback runs only for animations that finish; a
`.stop()` that drops an animation also drops its callback, so cleanup belongs in `.promise()` or in a handler that
runs regardless. Second, `.stop()` on its own affects just the *current* step, which is why the guard above uses
`stop(true, true)` to clear the queue and jump to the end state.

== Adding your own steps to the queue

`.queue()` lets any function take a place in the animation sequence. It receives a `next` function that must be
called to let the queue continue:

[source,javascript]
----
$('#count')
  .queue(function (next) {
    $(this).text('Saving...');
    next();                         // continue to the next queued step
  })
  .fadeTo(200, 0.5)
  .delay(500)
  .queue(function (next) {
    $(this).text('Saved');
    next();
  })
  .fadeTo(200, 1);
----

Forgetting to call `next()` stalls every later effect on that element. `.dequeue()` can restart a stalled queue,
and `+.queue('name', fn)+` uses a named queue instead of `fx` so work can be sequenced without auto-starting.

== Observing progress with `step`

The options form of `.animate()` accepts a `step` callback that runs on every frame, and `+.is(':animated')+` tells
whether an element is mid-animation:

[source,javascript]
----
$('#bar').animate({ width: 300 }, {
  duration: 400,
  step: function (now, fx) {
    // `now` is the current value of fx.prop, here the width in px
    $('#percent').text(Math.round((now / 300) * 100) + '%');
  }
});

if ($('#bar').is(':animated')) { /* an animation is running right now */ }
----

== Honouring reduced motion

A single switch is enough to give a user who has asked their system for reduced motion immediate state changes
instead of animations; every effect then jumps to its end state, but queues, promises and callbacks still run in
order:

[source,javascript]
----
if (window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
  jQuery.fx.off = true;
}
----

When effects are disabled, `+$('#list li').slideUp(150).promise().done(...)+` still resolves, so code written against
`.promise()` works unchanged with and without animation.

== Modern equivalent

CSS transitions and `@keyframes` animations handle most show/hide/slide/fade effects with no JavaScript --
toggle a class and let the stylesheet animate. For scripted control use the
https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API[Web Animations API]
(`el.animate(keyframes, options)`), which returns a controllable `Animation` object. See
xref:web/html-css/transitions.adoc[Transitions], xref:web/html-css/animations.adoc[Animations & Keyframes],
and xref:programming-languages/javascript/browser-animations.adoc[Animations via JavaScript].
