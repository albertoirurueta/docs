Welcome to the ASP.NET Core reference. https://learn.microsoft.com/en-us/aspnet/core/[ASP.NET Core] is a
cross-platform, open-source framework for building web apps, HTTP APIs, and real-time services on .NET. This
section documents the current **.NET 10 (LTS)** release -- the minimal hosting model, the middleware pipeline,
dependency injection, Minimal APIs, MVC and Razor Pages, Blazor with the current render modes, SignalR and
gRPC, EF Core, ASP.NET Core Identity and policy-based authorization, output caching, and rate limiting --
written and verified against https://learn.microsoft.com/en-us/aspnet/core/[Microsoft Learn].

If you are new to ASP.NET Core, start with xref:web/aspnet/getting-started.adoc[Getting Started with ASP.NET
Core], then xref:web/aspnet/request-pipeline-and-middleware.adoc[Request Pipeline and Middleware] and
xref:web/aspnet/minimal-apis.adoc[Minimal APIs], then work down the list or jump to what you need.

== What's covered

=== Getting started

* xref:web/aspnet/getting-started.adoc[Getting Started with ASP.NET Core] -- what ASP.NET Core is, the .NET 10
  LTS release cadence, the SDK and `dotnet` CLI, the project layout, the minimal hosting model, and how to
  choose an app model.

=== Fundamentals

* xref:web/aspnet/request-pipeline-and-middleware.adoc[Request Pipeline and Middleware] -- the pipeline as an
  ordered chain of `RequestDelegate`s, `Use` / `Run` / `Map`, the recommended order, the built-in middleware,
  writing custom middleware, and `HttpContext`.
* xref:web/aspnet/hosting-servers-and-environments.adoc[Hosting, Servers, and Environments] -- `WebApplication`
  vs. the Generic Host, background services, Kestrel / IIS / HTTP.sys, reverse proxies and forwarded headers,
  and environment-based configuration.
* xref:web/aspnet/configuration-and-options.adoc[Configuration and the Options Pattern] -- configuration
  providers and precedence, reading `IConfiguration`, binding to typed options, `IOptions` vs. `IOptionsSnapshot`
  vs. `IOptionsMonitor`, named options, and options validation.
* xref:web/aspnet/dependency-injection.adoc[Dependency Injection] -- the built-in container, service lifetimes
  and the captive-dependency pitfall, registration techniques including keyed services, consuming services
  across the framework, and replacing the container.
* xref:web/aspnet/routing.adoc[Routing] -- the match/execute model, route templates and constraints, the `Map`
  methods and route groups, attribute vs. conventional routing, URL generation, and short-circuit routes.

=== Building HTTP APIs & apps

* xref:web/aspnet/minimal-apis.adoc[Minimal APIs] -- `Map` methods and route groups, parameter binding,
  `IResult` and `TypedResults`, endpoint filters, validation, error handling, and a full worked CRUD example.
* xref:web/aspnet/mvc-and-razor-pages.adoc[MVC and Razor Pages] -- the MVC pattern, controllers and action
  results, Razor views with layouts and partials, Razor Pages and `PageModel` handlers, Tag Helpers, session
  and state, and localization.
* xref:web/aspnet/model-binding-and-validation.adoc[Model Binding and Validation] -- binding sources and order,
  binding attributes, custom model binders, DataAnnotations and custom validation, and client-side validation.
* xref:web/aspnet/web-apis.adoc[Controller-based Web APIs and OpenAPI] -- `ApiController` conventions, action
  return types, content negotiation and JSON options, `ProblemDetails`, DTOs, the built-in OpenAPI package, API
  versioning, and CORS.

=== Interactive & real-time UI

* xref:web/aspnet/blazor.adoc[Blazor] -- the Blazor Web App project, the four render modes, the component model
  and lifecycle, routing, forms, JS interop, state and performance, and security.
* xref:web/aspnet/real-time-and-rpc.adoc[Real-time and RPC: SignalR and gRPC] -- hubs, clients, transports,
  groups, streaming and scale-out with SignalR, and contract-first RPC with gRPC, gRPC-Web, and JSON
  transcoding.

=== Data

* xref:web/aspnet/data-access-ef-core.adoc[Data Access with EF Core] -- registering a `DbContext`, querying and
  change tracking, saving and concurrency, modelling with the Fluent API, migrations, resiliency, and Dapper as
  an alternative.

=== Security

* xref:web/aspnet/authentication-and-identity.adoc[Authentication and ASP.NET Core Identity] -- authentication
  schemes and handlers, cookie and JWT bearer authentication, OAuth 2.0 / OpenID Connect, ASP.NET Core Identity
  for local accounts, and the Identity API endpoints.
* xref:web/aspnet/authorization.adoc[Authorization] -- the `Authorize` attribute, role and claims checks,
  policy-based authorization with requirements and handlers, resource-based authorization, and advanced policy
  features.
* xref:web/aspnet/security-hardening.adoc[Security Hardening] -- the Data Protection API, HTTPS and HSTS, secret
  management, CORS, antiforgery / CSRF, XSS and Content Security Policy, open-redirect and SQL-injection
  avoidance, and an OWASP Top 10 map.

=== Operations

* xref:web/aspnet/error-handling-logging-and-observability.adoc[Error Handling, Logging, and Observability] --
  `UseExceptionHandler` and `IExceptionHandler`, the Operation Result pattern, structured logging with
  `ILogger`, HTTP logging, health checks, and metrics and tracing with OpenTelemetry.
* xref:web/aspnet/performance-and-caching.adoc[Performance and Caching] -- response vs. output caching,
  `IMemoryCache` / `IDistributedCache` / `HybridCache`, rate limiting, request timeouts and compression,
  outbound-call resilience, and an EF Core and runtime checklist.

=== Architecture & delivery

* xref:web/aspnet/architecture-and-patterns.adoc[Architecture and Patterns] -- SOLID and design principles,
  layering and Clean Architecture, DTO mapping, cross-cutting patterns in DI, CQRS and the mediator pattern,
  and vertical slices vs. modular monoliths.
* xref:web/aspnet/testing.adoc[Testing] -- the xUnit test project and test doubles, unit-testing controllers,
  handlers, middleware and validators, integration testing with `WebApplicationFactory`, test infrastructure,
  and end-to-end and load testing.
* xref:web/aspnet/deployment.adoc[Deployment] -- `dotnet publish` options, IIS, Linux with Nginx and systemd,
  containers, running behind a proxy or load balancer, production config and secrets, and a CI/CD pipeline.

=== UI libraries

* xref:web/aspnet/ui-component-libraries.adoc[UI Component Libraries] -- styling an ASP.NET Core UI (Bootstrap,
  Tailwind, Sass, Blazor CSS isolation) and the main Blazor component libraries, free and open-source first
  (MudBlazor, Radzen, Blazorise, Fluent UI, Ant Design, HAVIT, Blazor Bootstrap, MatBlazor), commercial suites
  last, plus accessibility.
