= Configuration and the Options Pattern
:description: Configuration providers and precedence, reading IConfiguration, binding to strongly typed options, IOptions vs. IOptionsSnapshot vs. IOptionsMonitor, named options, and options validation.
:keywords: ASP.NET Core configuration, IConfiguration, appsettings.json, user secrets, environment variables, Options pattern, IOptions, IOptionsSnapshot, IOptionsMonitor, named options, options validation

include::partial$ai-disclaimer.adoc[]

Configuration is a set of key/value pairs assembled from layered *providers*. The *Options pattern* binds
sections of that configuration to typed classes and injects them where they are needed.

== Providers and precedence

`WebApplication.CreateBuilder` adds providers in this order -- **later providers win**:

. `appsettings.json`
. `+appsettings.\{Environment}.json+`
. User Secrets (Development only)
. Environment variables
. Command-line arguments

[source,bash]
----
dotnet user-secrets init
dotnet user-secrets set "ConnectionStrings:Default" "Server=localhost;Database=app;Trusted_Connection=True"

# environment variable overriding a nested key (":" -> "__" for portability)
export ConnectionStrings__Default="Server=prod;Database=app;User Id=app;Password=..."

dotnet run --Feature:BetaSearch=true
----

Hierarchical keys use `:` in code and JSON; use `+__+` (double underscore) in environment-variable names. Add
extra providers (Azure Key Vault, JSON files, in-memory) explicitly:

[source,csharp]
----
builder.Configuration.AddJsonFile("shared.json", optional: true, reloadOnChange: true);
----

See https://learn.microsoft.com/en-us/aspnet/core/fundamentals/configuration/[Configuration in ASP.NET Core].
For the Key Vault configuration provider itself -- RBAC, the underlying SDK, and `DefaultAzureCredential` --
see xref:cloud/azure/key-vault-and-secrets.adoc[].

== Reading configuration directly

[source,csharp]
----
IConfiguration config = builder.Configuration;

int pageSize       = config.GetValue<int>("Search:PageSize", 20);
string? cs         = config.GetConnectionString("Default");          // ConnectionStrings:Default
IConfigurationSection smtp = config.GetSection("Smtp");
string host        = smtp["Host"]!;
----

Reading keys ad hoc is fine for one-offs; for anything reused, bind to a class (below).

== The Options pattern

Define a class, bind a section to it, inject `IOptions<T>`:

[source,csharp]
----
public sealed class SmtpOptions
{
    public const string Section = "Smtp";
    public required string Host { get; init; }
    public int Port { get; init; } = 25;
    public bool UseTls { get; init; } = true;
}

builder.Services.Configure<SmtpOptions>(builder.Configuration.GetSection(SmtpOptions.Section));

// consume it
public sealed class Mailer(IOptions<SmtpOptions> options)
{
    private readonly SmtpOptions _smtp = options.Value;
}
----

[cols="1,3",options="header"]
|===
| Accessor | Semantics

| `IOptions<T>` | Singleton, value computed once. Use for values that never change at runtime.
| `IOptionsSnapshot<T>` | Scoped; recomputed per request. Picks up `reloadOnChange` edits. Not valid in
  singletons.
| `IOptionsMonitor<T>` | Singleton with `CurrentValue` and `+OnChange(...)+`. Use in singletons / background
  services that must react to changes.
|===

When the reloaded values come from Azure App Configuration rather than a local file, see
xref:cloud/azure/runtime-configuration.adoc[] for the sentinel-key polling and `ConfigureRefresh` setup that
feeds `IOptionsSnapshot<T>`/`IOptionsMonitor<T>` this way.

**Named options** bind several instances of the same type:

[source,csharp]
----
builder.Services.Configure<SmtpOptions>("Primary",  config.GetSection("Smtp:Primary"));
builder.Services.Configure<SmtpOptions>("Fallback", config.GetSection("Smtp:Fallback"));

public sealed class Mailer(IOptionsMonitor<SmtpOptions> monitor)
{
    private readonly SmtpOptions _primary = monitor.Get("Primary");
}
----

See https://learn.microsoft.com/en-us/aspnet/core/fundamentals/configuration/options[Options pattern in ASP.NET
Core].

== Validation

Validate options at startup so a misconfigured app fails fast rather than at first use:

[source,csharp]
----
builder.Services.AddOptions<SmtpOptions>()
    .Bind(builder.Configuration.GetSection(SmtpOptions.Section))
    .ValidateDataAnnotations()                       // [Required], [Range], ...
    .Validate(o => o.Port is > 0 and < 65536, "Port out of range")
    .ValidateOnStart();                              // run all validators during app start
----

For complex rules implement `IValidateOptions<T>`. The *configuration-binding source generator* and the
*options-validation source generator* (enable `EnableConfigurationBindingGenerator` /
`[OptionsValidator]`) remove the runtime reflection and make binding/validation trimming- and AOT-friendly.

Never put credentials in `appsettings.json` -- keep them in User Secrets locally and a secret store in
production. See xref:web/aspnet/core/security-hardening.adoc[Security hardening].

== Deep dive: how configuration is built and reloaded

`WebApplication.CreateBuilder` assembles an `IConfigurationRoot` from an ordered list of providers. Each provider is
asked for a key in *reverse* order, so the last provider that defines the key wins. Hierarchical keys are flattened
with a colon (`Broker:Host`); environment variables use a double underscore (`+Broker__Host+`) because a colon is not
valid in every shell.

[mermaid]
....
flowchart LR
    A[appsettings.json] --> B[appsettings.Environment.json]
    B --> C[User Secrets - Development only]
    C --> D[Environment variables]
    D --> E[Command-line arguments]
    E --> F[IConfigurationRoot]
    F --> G[IOptions of T - read once]
    F --> H[IOptionsSnapshot of T - per request]
    F --> I[IOptionsMonitor of T - live with change callback]
....

=== Worked example: broker settings for the Orders service

The Orders service publishes events to a message broker. Its settings are a typed class, bound from the `Broker`
section, validated at startup, and reloaded without a restart for the one value that is safe to change live.

[source,csharp]
----
using System.ComponentModel.DataAnnotations;
using Microsoft.Extensions.Options;

public sealed class BrokerOptions
{
    public const string SectionName = "Broker";

    [Required, MinLength(1)]
    public string Host { get; init; } = "";

    [Range(1, 65535)]
    public int Port { get; init; } = 5672;

    [Range(1, 500)]
    public int BatchSize { get; init; } = 50;
}

// Program.cs
builder.Services
    .AddOptions<BrokerOptions>()
    .Bind(builder.Configuration.GetSection(BrokerOptions.SectionName))
    .ValidateDataAnnotations()
    .Validate(o => o.Host != "localhost" || builder.Environment.IsDevelopment(),
              "localhost is only allowed in Development")
    .ValidateOnStart();                      // fail at startup, not at the first request
----

[source,json]
----
{
  "Broker": { "Host": "broker.internal", "Port": 5672, "BatchSize": 100 }
}
----

A consumer chooses the interface by how fresh it needs the data:

[source,csharp]
----
public sealed class OrderPublisher(IOptionsMonitor<BrokerOptions> options)
{
    public int CurrentBatchSize => options.CurrentValue.BatchSize;   // sees file edits
}
----

Use `IOptions<T>` for values fixed for the process lifetime, `IOptionsSnapshot<T>` (scoped) when a request must see a
consistent value, and `IOptionsMonitor<T>` in singletons (hosted services, middleware) that need to follow changes.
Injecting `IOptionsSnapshot<T>` into a singleton is a captive-dependency error.

=== Overriding a value from the outside

The same key can be supplied by a higher-precedence provider without touching the file:

[source,bash]
----
Broker__Host=broker-eu.internal dotnet run
dotnet run --Broker:BatchSize=25
----

=== Testing the binding

A binding test needs no web host; build a configuration from an in-memory dictionary:

[source,csharp]
----
var config = new ConfigurationBuilder()
    .AddInMemoryCollection(new Dictionary<string, string?>
    {
        ["Broker:Host"] = "h", ["Broker:Port"] = "70000"
    })
    .Build();

var services = new ServiceCollection();
services.AddOptions<BrokerOptions>().Bind(config.GetSection("Broker")).ValidateDataAnnotations();
using var sp = services.BuildServiceProvider();

var ex = Assert.Throws<OptionsValidationException>(() => sp.GetRequiredService<IOptions<BrokerOptions>>().Value);
Assert.Contains("Port", ex.Message);
----
