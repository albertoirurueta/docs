= Minimal APIs
:description: Building HTTP APIs with Minimal APIs -- Map methods and route groups, parameter binding, IResult and TypedResults, endpoint filters, validation, error handling, and a full worked CRUD example.
:keywords: ASP.NET Core Minimal APIs, MapGet, MapGroup, parameter binding, AsParameters, IResult, TypedResults, Results union, IEndpointFilter, AddValidation, ProblemDetails, RequireAuthorization

include::partial$ai-disclaimer.adoc[]

Minimal APIs express an HTTP endpoint as a route plus a handler delegate, with no controller class. They are
the default for new APIs and the lowest-overhead option.

== Endpoints and groups

[source,csharp]
----
var app = builder.Build();

app.MapGet("/products", GetAllProducts);                    // method-group handler
app.MapGet("/products/{id:int}", (int id) => ...);          // lambda handler

var products = app.MapGroup("/products")
    .WithTags("Products")
    .RequireAuthorization()
    .AddEndpointFilter<LoggingFilter>();

products.MapPost("/", CreateProduct);
products.MapDelete("/{id:int}", DeleteProduct);

static IResult GetAllProducts(IProductStore store) => TypedResults.Ok(store.All());
----

`MapGroup` factors out a shared prefix and shared metadata (tags, auth, filters). See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/overview[Minimal APIs overview].

== Parameter binding

Handler parameters are bound, by convention, from:

[cols="1,3",options="header"]
|===
| Source | Bound when...

| Route values | the parameter name matches a `+\{route}+` token
| Query string | a simple-type parameter has no matching route token
| Header | annotated `[FromHeader]`
| Body (JSON) | a complex-type parameter (one allowed per handler)
| Form / `IFormFile` | annotated `[FromForm]`, or an `IFormFile` / `IFormFileCollection`
| DI container | the type is a registered service
| `HttpContext` | parameter is `HttpContext`, `HttpRequest`, `ClaimsPrincipal`, `CancellationToken`, ...
|===

[source,csharp]
----
app.MapGet("/search", (string q, int page, int size, ISearchService svc, CancellationToken ct)
    => svc.QueryAsync(q, page, size, ct));

// group many query/route params into one struct
app.MapGet("/report", ([AsParameters] ReportQuery query, IReportService svc) => svc.Run(query));
public readonly record struct ReportQuery(DateOnly From, DateOnly To, string? Region);
----

Custom types bind from route/query by declaring `static bool TryParse(string, out T)`, or from the body/other
sources by declaring `static ValueTask<T?> BindAsync(HttpContext)`. Explicit attributes -- `[FromRoute]`,
`[FromQuery]`, `[FromHeader]`, `[FromBody]`, `[FromForm]`, `[FromServices]` -- override the convention. See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/parameter-binding[Parameter binding].

== Results

Return an `IResult`, a `TypedResults` value, or a plain object (serialized to JSON with a 200):

[source,csharp]
----
app.MapGet("/products/{id:int}", async Task<Results<Ok<Product>, NotFound>> (int id, IProductStore store) =>
{
    var p = await store.FindAsync(id);
    return p is null ? TypedResults.NotFound() : TypedResults.Ok(p);
});
----

`TypedResults` is strongly typed (better for testing); the `+Results<T1, T2, ...>+` union declares every possible
response so OpenAPI can describe them all. `+Results.Problem(...)+` and `+Results.ValidationProblem(...)+` produce
RFC 9457 payloads. .NET 10 adds `+TypedResults.Stream(...)+` and `+TypedResults.ServerSentEvents(...)+` for
streaming responses. See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/responses[Create responses].

== Endpoint filters

`IEndpointFilter` wraps a handler for cross-cutting concerns -- validation, logging, short-circuiting -- and,
unlike middleware, has access to the bound arguments.

[source,csharp]
----
public sealed class LoggingFilter(ILogger<LoggingFilter> logger) : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(EndpointFilterInvocationContext ctx, EndpointFilterDelegate next)
    {
        logger.LogInformation("-> {Endpoint}", ctx.HttpContext.GetEndpoint()?.DisplayName);
        var result = await next(ctx);
        logger.LogInformation("<- done");
        return result;
    }
}

app.MapPost("/orders", CreateOrder).AddEndpointFilter<LoggingFilter>();
----

See https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/min-api-filters[Filters in Minimal
API apps].

== Validation

.NET 10 adds built-in validation: register it and annotate the request type; a failing request returns a 400
`ValidationProblemDetails` automatically.

[source,csharp]
----
builder.Services.AddValidation();          // .NET 10

public sealed record CreateProduct(
    [property: Required, StringLength(100)] string Name,
    [property: Range(0.01, 100000)] decimal Price);

app.MapPost("/products", (CreateProduct dto, IProductStore store) => TypedResults.Created($"/products/1"));
----

Before .NET 10 (or for custom rules) do it in a filter:

[source,csharp]
----
app.MapPost("/products", CreateProduct)
   .AddEndpointFilter(async (ctx, next) =>
   {
       var dto = ctx.GetArgument<CreateProduct>(0);
       if (string.IsNullOrWhiteSpace(dto.Name))
           return Results.ValidationProblem(new Dictionary<string, string[]>
               { ["name"] = ["Name is required"] });
       return await next(ctx);
   });
----

See https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/validation[Minimal API validation].

== Error handling and auth

[source,csharp]
----
builder.Services.AddProblemDetails();      // uniform error bodies for unhandled + status-code responses

app.MapGet("/secret", () => "shh").RequireAuthorization("AdminOnly");
app.MapGet("/public", () => "hi").AllowAnonymous();
----

== Worked example: a Todo CRUD API

[source,csharp]
----
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddValidation();
builder.Services.AddOpenApi();
builder.Services.AddSingleton<TodoDb>();

var app = builder.Build();
if (app.Environment.IsDevelopment()) app.MapOpenApi();

var todos = app.MapGroup("/todos").WithTags("Todos");

todos.MapGet("/", (TodoDb db) => TypedResults.Ok(db.All()))
     .WithName("ListTodos");

todos.MapGet("/{id:int}", Results<Ok<Todo>, NotFound> (int id, TodoDb db) =>
        db.Find(id) is { } t ? TypedResults.Ok(t) : TypedResults.NotFound())
     .WithName("GetTodo");

todos.MapPost("/", Results<Created<Todo>, ValidationProblem> (CreateTodo dto, TodoDb db) =>
{
    var created = db.Add(dto.Title);
    return TypedResults.Created($"/todos/{created.Id}", created);
})
.AddEndpointFilter<LoggingFilter>();

todos.MapDelete("/{id:int}", Results<NoContent, NotFound> (int id, TodoDb db) =>
    db.Remove(id) ? TypedResults.NoContent() : TypedResults.NotFound());

app.Run();

public sealed record Todo(int Id, string Title, bool Done);
public sealed record CreateTodo([property: Required, StringLength(200)] string Title);

public sealed class TodoDb
{
    private readonly List<Todo> _items = [];
    private int _next = 1;
    public IEnumerable<Todo> All() => _items;
    public Todo? Find(int id) => _items.FirstOrDefault(t => t.Id == id);
    public Todo Add(string title) { var t = new Todo(_next++, title, false); _items.Add(t); return t; }
    public bool Remove(int id) => _items.RemoveAll(t => t.Id == id) > 0;
}
----

== Deep dive: growing the Todo API without growing `Program.cs`

The worked example above fits in one file, which is exactly why Minimal APIs scale badly if every route stays in
`Program.cs`. The idiomatic answer is not controllers but plain extension methods on `IEndpointRouteBuilder`: each
feature owns its routes, and `Program.cs` only composes features.

[source,csharp]
----
// TodoEndpoints.cs
public static class TodoEndpoints
{
    public static IEndpointRouteBuilder MapTodoEndpoints(this IEndpointRouteBuilder routes)
    {
        var group = routes.MapGroup("/todos").WithTags("Todos");

        group.MapGet("/", (TodoDb db) => TypedResults.Ok(db.All())).WithName("ListTodos");
        group.MapGet("/{id:int}", GetTodo).WithName("GetTodo");
        group.MapPost("/", AddTodo).AddEndpointFilter<IdempotencyFilter>();

        return routes;
    }

    private static Results<Ok<Todo>, NotFound> GetTodo(int id, TodoDb db)
        => db.Find(id) is { } todo ? TypedResults.Ok(todo) : TypedResults.NotFound();

    private static Created<Todo> AddTodo(CreateTodo dto, TodoDb db)
    {
        var created = db.Add(dto.Title);
        return TypedResults.Created($"/todos/{created.Id}", created);
    }
}

// Program.cs
app.MapTodoEndpoints();
----

Named methods instead of lambdas also give each handler a real name in OpenAPI and stack traces, and let the compiler
infer the `+Results<...>+` union from the declared return type.

=== A filter that short-circuits and post-processes

An endpoint filter sees the bound arguments, can return a result *without* calling `next` (short-circuit), and can
inspect or replace the result the handler produced. The idempotency filter below makes a retried `POST` safe: the
client sends an `Idempotency-Key` header, and a repeated key replays the first outcome instead of creating a second
Todo.

[source,csharp]
----
using Microsoft.Extensions.Caching.Memory;

public sealed class IdempotencyFilter(IMemoryCache cache) : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(EndpointFilterInvocationContext context, EndpointFilterDelegate next)
    {
        var request = context.HttpContext.Request;
        if (!request.Headers.TryGetValue("Idempotency-Key", out var key) || string.IsNullOrWhiteSpace(key))
            return TypedResults.Problem(detail: "The Idempotency-Key header is required.", statusCode: 400);

        var cacheKey = $"idempotency:{key}";
        if (cache.TryGetValue(cacheKey, out object? firstResult))
            return firstResult;                                   // short-circuit: handler is not called

        var result = await next(context);                         // run the rest of the chain and the handler
        cache.Set(cacheKey, result, TimeSpan.FromMinutes(10));
        return result;
    }
}

// registration
builder.Services.AddMemoryCache();
----

[mermaid]
....
flowchart TD
    REQ["POST /todos + Idempotency-Key"] --> F{"Key header present?"}
    F -- no --> P400["400 ProblemDetails"]
    F -- yes --> H{"Key seen before?"}
    H -- yes --> REPLAY["Replay stored result"]
    H -- no --> NEXT["next: binding, validation, handler"]
    NEXT --> STORE["Store result for 10 minutes"]
    STORE --> RES["201 Created"]
....

An in-memory cache only deduplicates within one process; behind several instances use a distributed store (see
xref:web/aspnet/core/performance-and-caching.adoc[Performance and Caching]). Filters run in registration order on
the way in and in reverse on the way out, and run *after* parameter binding, so a body that fails to deserialize
never reaches the filter.

=== Testing the endpoints in memory

[source,csharp]
----
// Program.cs must expose the entry point to the test project:
public partial class Program;

public class TodoEndpointTests(WebApplicationFactory<Program> factory) : IClassFixture<WebApplicationFactory<Program>>
{
    [Fact]
    public async Task Repeated_idempotency_key_creates_one_todo()
    {
        var client = factory.CreateClient();
        using var first = new HttpRequestMessage(HttpMethod.Post, "/todos") { Content = JsonContent.Create(new { title = "Buy milk" }) };
        first.Headers.Add("Idempotency-Key", "k-1");
        using var second = new HttpRequestMessage(HttpMethod.Post, "/todos") { Content = JsonContent.Create(new { title = "Buy milk" }) };
        second.Headers.Add("Idempotency-Key", "k-1");

        var a = await (await client.SendAsync(first)).Content.ReadFromJsonAsync<Todo>();
        var b = await (await client.SendAsync(second)).Content.ReadFromJsonAsync<Todo>();

        Assert.Equal(a!.Id, b!.Id);
    }
}
----

`WebApplicationFactory<Program>` boots the real pipeline (routing, filters, validation) against an in-memory server,
so the test exercises exactly what production runs. See xref:web/aspnet/core/testing.adoc[Testing] for the
`Microsoft.AspNetCore.Mvc.Testing` setup.
