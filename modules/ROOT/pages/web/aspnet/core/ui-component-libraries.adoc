= UI Component Libraries
:description: Styling an ASP.NET Core UI (Bootstrap, Tailwind, Sass, Blazor CSS isolation) and the main Blazor component libraries -- free and open-source first (MudBlazor, Radzen, Blazorise, Fluent UI, Ant Design, HAVIT, Blazor Bootstrap, MatBlazor), commercial suites last, plus accessibility.

This page covers how to style an ASP.NET Core UI and which ready-made component libraries to reach for. Free
and open-source options come first, in rough order of adoption; commercial suites are listed last, without
examples.

== Styling options

=== Bootstrap

The MVC, Razor Pages, and Blazor templates ship Bootstrap in `wwwroot/lib/bootstrap`. Manage the version with
**LibMan** (`libman.json`) or npm. Cross-link: xref:web/bootstrap/index.adoc[the Bootstrap Reference].

[source,json]
----
// libman.json
{ "defaultProvider": "cdnjs",
  "libraries": [ { "library": "bootstrap@5.3.3", "destination": "wwwroot/lib/bootstrap/" } ] }
----

=== Tailwind CSS

Install https://tailwindcss.com/[Tailwind CSS] with the standalone CLI (no Node) or a Node build, then use
utility classes directly in `.cshtml` / `.razor`.

[source,bash]
----
tailwindcss -i ./Styles/app.css -o ./wwwroot/css/app.css --watch
----

[source,razor]
----
<button class="rounded bg-blue-600 px-4 py-2 text-white hover:bg-blue-700">Save</button>
----

=== Sass

Add `AspNetCore.SassCompiler` and it compiles `.scss` on build and watch. Cross-link:
xref:web/sass/index.adoc[the Sass Reference].

[source,bash]
----
dotnet add package AspNetCore.SassCompiler
----

=== Blazor CSS isolation

A `Component.razor.css` file is scoped to that component: the build rewrites its selectors and adds a `b-<hash>`
attribute so rules do not leak. Use `::deep` to reach child markup, and put global rules in
`wwwroot/app.css`.

[source,css]
----
/* Counter.razor.css */
button { font-weight: 600; }
::deep .badge { color: rebeccapurple; }
----

Tag Helpers style *server-rendered* MVC/Razor Pages markup; **Razor component libraries** (below) target
*Blazor*. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/components/class-libraries[Razor class libraries] and
https://learn.microsoft.com/en-us/aspnet/core/blazor/components/css-isolation[CSS isolation].

== Blazor component libraries -- free and open-source

=== MudBlazor (MIT)

https://mudblazor.com/[MudBlazor] is a Material Design component set and the most widely used open-source Blazor
library.

[source,bash]
----
dotnet add package MudBlazor
----

[source,razor]
----
@* Program.cs: builder.Services.AddMudServices(); *@
<MudButton Variant="Variant.Filled" Color="Color.Primary" OnClick="Save">Save</MudButton>
<MudDialog @bind-Visible="open">Confirm?</MudDialog>
<MudDataGrid Items="@products" />
----

=== Radzen Blazor Components (MIT)

https://blazor.radzen.com/[Radzen Blazor Components] is a free set of ~90 components including `RadzenDataGrid`.
Radzen Blazor Studio (the visual designer) is a separate paid product; the components themselves are free.

[source,bash]
----
dotnet add package Radzen.Blazor
----

[source,razor]
----
@* Program.cs: builder.Services.AddRadzenComponents(); *@
<RadzenButton Text="Save" Click="@Save" />
<RadzenDialog />
<RadzenDataGrid Data="@products" TItem="Product" />
----

=== Blazorise (Apache-2.0 core)

https://blazorise.com/[Blazorise] renders through a provider you choose -- Bootstrap, Bulma, Tailwind, Material,
or AntDesign. The core is Apache-2.0; a few advanced extensions are licensed.

[source,razor]
----
<Button Color="Color.Primary" Clicked="@Save">Save</Button>
<Modal @ref="modal"><ModalContent>Confirm?</ModalContent></Modal>
<DataGrid TItem="Product" Data="@products" />
----

=== Microsoft Fluent UI Blazor (MIT)

https://www.fluentui-blazor.net/[Microsoft Fluent UI Blazor]
(`Microsoft.FluentUI.AspNetCore.Components`) implements the Fluent 2 design system, is maintained by Microsoft,
and powers the .NET Aspire dashboard.

[source,razor]
----
@* Program.cs: builder.Services.AddFluentUIComponents(); *@
<FluentButton Appearance="Appearance.Accent" @onclick="Save">Save</FluentButton>
<FluentDialog @bind-Hidden="hidden">Confirm?</FluentDialog>
<FluentDataGrid Items="@products.AsQueryable()" />
----

=== Ant Design Blazor (MIT)

https://antblazor.com/[Ant Design Blazor] is an enterprise-oriented Ant Design port with a rich `Table` and
`Form`.

[source,razor]
----
<Button Type="@ButtonType.Primary" OnClick="Save">Save</Button>
<Modal Title="Confirm" @bind-Visible="visible">Delete this item?</Modal>
<Table TItem="Product" DataSource="@products" />
----

=== HAVIT Blazor (MIT) and Blazor Bootstrap (Apache-2.0)

https://havit.blazor.cz/[HAVIT Blazor] and https://demos.blazorbootstrap.com/[Blazor Bootstrap] are Bootstrap 5
component sets (Blazor Bootstrap also has charts). Cross-link: xref:web/bootstrap/index.adoc[the Bootstrap
Reference].

[source,razor]
----
<Button Color="ButtonColor.Primary" @onclick="Save">Save</Button>
<Modal @ref="modal" Title="Confirm" />
<Grid TItem="Product" Data="@products" />
----

=== MatBlazor (MIT)

https://www.matblazor.com/[MatBlazor] is a Material component set; note it is less actively maintained than
MudBlazor.

[source,razor]
----
<MatButton Raised="true" OnClick="Save">Save</MatButton>
<MatDialog @bind-IsOpen="open">Confirm?</MatDialog>
<MatTable Items="@products" />
----

== Server-rendered (MVC / Razor Pages) UI

Server-rendered UI is mostly **Bootstrap + Tailwind + custom Tag Helpers** -- there is no large open-source
"component suite" for it the way there is for Blazor. The richer grid/scheduler/pivot kits for MVC and Razor
Pages come from the commercial vendors below.

== Commercial suites -- paid / licensed

Listed last, without examples. Some offer a free community licence for individuals or small teams under a
revenue threshold.

== Accessibility

A component library gives you accessible primitives, but you still own the wiring: label every control, manage
focus in dialogs and menus, honour `prefers-reduced-motion`, and test with a keyboard and a screen reader.
Cross-link: xref:web/accessibility.adoc[Web Accessibility].

== Deep dive: adopting a library without being owned by it

A component library is a long-term dependency: its components appear in hundreds of pages, and replacing it later is
expensive. Two habits keep that cost bounded: choose with the constraints written down, and isolate the library behind
a thin layer of your own components.

[mermaid]
....
flowchart TD
    START["Need a UI toolkit"] --> Q1{"Server-rendered pages<br/>MVC or Razor Pages?"}
    Q1 -- "yes" --> SR["Bootstrap or Tailwind + Tag Helpers;<br/>commercial grids only if required"]
    Q1 -- "no, Blazor" --> Q2{"Licence budget<br/>for a commercial suite?"}
    Q2 -- "no" --> OSS["Open source: MudBlazor, Radzen,<br/>Fluent UI, Blazorise"]
    Q2 -- "yes, and need pivot, scheduler, reports" --> COM["Commercial suite"]
    OSS --> Q3{"Design language fixed?"}
    Q3 -- "Microsoft look" --> FLU["Fluent UI Blazor"]
    Q3 -- "Material look" --> MUD["MudBlazor"]
    Q3 -- "existing Bootstrap or Ant site" --> BOT["Blazorise, Blazor Bootstrap, Ant Design"]
....

Evaluate candidates against criteria you can test in a day: does the grid support server-side paging and sorting;
does it work with the render modes you use (interactive components need an interactive render mode, so a static SSR
page that uses them renders markup but nothing responds); how does it handle keyboard navigation and screen readers;
what is the release cadence and how often do majors break the API; and what does the licence allow.

=== A thin wrapper around the data grid

The example uses MudBlazor 8. `ProductGrid` is the only component in the application that knows about `MudDataGrid`;
pages use `ProductGrid` and pass it data through a callback. Switching to Radzen or a commercial grid later changes one
file.

[source,razor]
----
@* Components/ProductGrid.razor *@
@using MudBlazor

<MudDataGrid T="ProductDto" ServerData="LoadAsync" Dense="true" Hover="true">
    <Columns>
        <PropertyColumn Property="p => p.Name" Title="Product" />
        <PropertyColumn Property="p => p.Price" Title="Price" Format="C" />
    </Columns>
    <PagerContent>
        <MudDataGridPager T="ProductDto" />
    </PagerContent>
</MudDataGrid>

@code {
    /// <summary>Supplies one page of data; the grid never talks to the API directly.</summary>
    [Parameter, EditorRequired] public Func<int, int, CancellationToken, Task<PagedResult<ProductDto>>> Source { get; set; } = default!;

    private async Task<GridData<ProductDto>> LoadAsync(GridState<ProductDto> state, CancellationToken ct)
    {
        var page = await Source(state.Page, state.PageSize, ct);   // state.Page is zero-based
        return new GridData<ProductDto> { Items = page.Items, TotalItems = page.TotalCount };
    }
}
----

[source,razor]
----
@* Pages/Products.razor *@
@page "/products"
@rendermode InteractiveServer
@inject IProductApi Api

<ProductGrid Source="(page, size, ct) => Api.SearchAsync(page, size, ct)" />
----

[source,csharp]
----
// Program.cs
builder.Services.AddMudServices();

// Layout (MainLayout.razor) must host the providers the components use:
//   <MudThemeProvider /> <MudPopoverProvider /> <MudDialogProvider /> <MudSnackbarProvider />
----

Everything the grid needs from the application crosses one narrow seam, `Source`, so the data layer stays testable
without the library. Theming is also central: define one `MudTheme` in a single place and pass it to
`<MudThemeProvider Theme="AppTheme.Default" />`, rather than overriding colours in many stylesheets.

=== Customizing without forking

[source,csharp]
----
public static class AppTheme
{
    public static readonly MudTheme Default = new()
    {
        PaletteLight = new PaletteLight { Primary = "#1a5fb4", AppbarBackground = "#1a5fb4" },
        PaletteDark = new PaletteDark { Primary = "#78aeed" },
    };
}
----

Prefer the library's theme and CSS-variable hooks over `::deep` overrides of its internal class names. Internal class
names are not part of the public API and change between majors, which is how a "small" style tweak turns into a
blocker for a library upgrade.
