= Razor Syntax and Tag Helpers
:description: The Razor view engine -- C#/HTML syntax, _ViewImports and _ViewStart, layouts and sections, partial views, view components, built-in Tag Helpers, writing custom Tag Helpers, and HTML encoding.
:keywords: Razor syntax, cshtml, _ViewImports, _ViewStart, RenderBody, RenderSection, partial view, view component, Tag Helpers, asp-for, HtmlTargetElement, HTML encoding

include::partial$ai-disclaimer.adoc[]

Razor mixes C# and HTML in `.cshtml` files. It is the view engine shared by
xref:web/aspnet/core/mvc-controllers-and-views.adoc[MVC] and xref:web/aspnet/core/razor-pages.adoc[Razor Pages].

== Razor syntax

[source,cshtml]
----
@model IReadOnlyList<Product>
@{
    ViewData["Title"] = "Products";
    var expensive = Model.Where(p => p.Price > 100);
}
<h1>@ViewData["Title"]</h1>
<ul>
@foreach (var p in Model)
{
    <li>@p.Name - @p.Price.ToString("C")</li>
}
</ul>
@if (expensive.Any())
{
    <p>@expensive.Count() premium products.</p>
}
----

* `@expression` -- an implicit expression, HTML-encoded and written inline.
* `+@\{ ... }+` -- an explicit code block; mixed markup inside it needs `<text>` or `@:` to escape back to HTML.
* `@model` -- declares the view's strongly typed model (`Model` in code).
* `@functions` -- declares local methods/fields usable from markup.
* `+@*  ... *@+` -- a Razor comment (never sent to the client, unlike an HTML comment).

See https://learn.microsoft.com/en-us/aspnet/core/mvc/views/razor[Razor syntax reference for ASP.NET Core].

== `_ViewImports` and `_ViewStart`

[source,cshtml]
----
@* Views/_ViewImports.cshtml -- applies to every view under Views/ *@
@using MyApp.Models
@namespace MyApp.Views
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
----

[source,cshtml]
----
@* Views/_ViewStart.cshtml -- runs before every view; usually just sets Layout *@
@{
    Layout = "_Layout";
}
----

`_ViewImports.cshtml` and `_ViewStart.cshtml` apply to every view in their folder and subfolders; a
subdirectory can add its own to extend (not replace) the parent's imports.

== Layouts and sections

A layout is a normal view that calls `@RenderBody()` where the child view's content goes, and optionally
`@RenderSection` for named, optional regions such as page-specific scripts:

[source,cshtml]
----
@* Views/Shared/_Layout.cshtml *@
<!DOCTYPE html>
<html>
<head><title>@ViewData["Title"]</title></head>
<body>
    @await Html.PartialAsync("_Nav")
    <main>@RenderBody()</main>
    @RenderSection("scripts", required: false)
</body>
</html>
----

[source,cshtml]
----
@section scripts {
    <script src="~/js/products.js"></script>
}
----

See https://learn.microsoft.com/en-us/aspnet/core/mvc/views/layout[Layout in ASP.NET Core].

== Partial views

A partial view renders a reusable fragment with no layout of its own:

[source,cshtml]
----
<partial name="_ProductRow" model="p" />
@* or asynchronously *@
@await Html.PartialAsync("_ProductRow", p)
----

See https://learn.microsoft.com/en-us/aspnet/core/mvc/views/partial[Partial views].

== View components

A view component is a small, reusable piece of server-rendered UI with its own logic -- unlike a partial view,
it does not depend on a controller action having already built its model:

[source,csharp]
----
public sealed class CartViewComponent(ICartService cart) : ViewComponent
{
    public async Task<IViewComponentResult> InvokeAsync()
    {
        var items = await cart.GetItemsAsync(HttpContext);
        return View(items);   // renders Views/Shared/Components/Cart/Default.cshtml
    }
}
----

[source,cshtml]
----
@await Component.InvokeAsync("Cart")
<vc:cart></vc:cart>  @* Tag Helper invocation form *@
----

See https://learn.microsoft.com/en-us/aspnet/core/mvc/views/view-components[View components].

== Built-in Tag Helpers

Tag Helpers attach server behavior to HTML-looking elements, so markup stays close to plain HTML instead of
mixing in `+@Html.*+` helper calls:

[source,cshtml]
----
<form asp-controller="Products" asp-action="Create" method="post">
    <input asp-for="Name" class="form-control" />
    <span asp-validation-for="Name" class="text-danger"></span>
    <select asp-for="CategoryId" asp-items="Model.Categories"></select>
    <button type="submit">Save</button>
</form>

<a asp-controller="Products" asp-action="Details" asp-route-id="@p.Id">@p.Name</a>
<img src="~/img/logo.png" asp-append-version="true" />

<environment include="Development">
    <link rel="stylesheet" href="~/css/site.css" />
</environment>
<environment exclude="Development">
    <link rel="stylesheet" href="~/css/site.min.css" />
</environment>
----

Common ones: `asp-for` (model-binds a field, wiring up name/id/validation attributes), `asp-controller` /
`asp-action` / `asp-page` / `+asp-route-*+` (URL generation), `asp-validation-for` / `asp-validation-summary`,
`asp-append-version` (cache-busting via a content hash), and the `<environment>` and `<cache>` elements.

== Custom Tag Helpers

Subclass `TagHelper` and target elements or attributes:

[source,csharp]
----
[HtmlTargetElement("email", Attributes = "address")]
public sealed class EmailTagHelper : TagHelper
{
    public string Address { get; set; } = "";

    public override void Process(TagHelperContext context, TagHelperOutput output)
    {
        output.TagName = "a";
        output.Attributes.SetAttribute("href", $"mailto:{Address}");
        output.Content.SetContent(Address);
    }
}
----

[source,cshtml]
----
<email address="support@example.com"></email>
----

Register custom Tag Helpers from `_ViewImports.cshtml` with `+@addTagHelper *, MyApp+`. See
https://learn.microsoft.com/en-us/aspnet/core/mvc/views/tag-helpers/authoring[Author Tag Helpers in ASP.NET
Core].

== HTML encoding

Razor HTML-encodes `@expression` output by default, which is the main defense against reflected XSS. Opt out
explicitly and only for content you trust:

[source,cshtml]
----
<p>@userComment</p>                       @* encoded: <script> renders as text *@
<p>@Html.Raw(trustedMarkupFromCms)</p>    @* NOT encoded -- only for known-safe HTML *@
----

See xref:web/aspnet/core/security-hardening.adoc[Security Hardening] for the broader XSS/CSP picture and
https://learn.microsoft.com/en-us/aspnet/core/mvc/views/overview[Views in ASP.NET Core MVC].

== Deep dive: how a Tag Helper runs, and two worth writing

A Tag Helper is not interpreted at request time by scanning HTML. The Razor compiler matches elements and attributes
against the Tag Helpers registered with `@addTagHelper` *while it compiles the view*, and emits C# that creates the
Tag Helper, assigns its properties from the attributes, and calls it during rendering. That is why a misspelled
attribute on a matched element is a compile-time concern (Visual Studio dims it) rather than a silent runtime no-op,
and why elements that no Tag Helper targets pass through untouched.

[mermaid]
....
flowchart LR
    SRC["Alert.cshtml markup<br/>&lt;alert kind=warning&gt;Saved&lt;/alert&gt;"] --> CMP["Razor compiler<br/>matches registered Tag Helpers"]
    CMP --> GEN["Generated C#:<br/>create AlertTagHelper, set Kind"]
    GEN --> RUN["At render: Init, then ProcessAsync"]
    RUN --> CHILD["GetChildContentAsync<br/>renders inner markup"]
    CHILD --> OUT["TagHelperOutput becomes the final HTML"]
....

=== A wrapper element: `<alert>`

When a Tag Helper wraps existing content, it needs the *child content* the author wrote between the tags. That
requires `ProcessAsync`, because rendering children is asynchronous.

[source,csharp]
----
[HtmlTargetElement("alert")]
public sealed class AlertTagHelper : TagHelper
{
    private static readonly HashSet<string> Kinds = ["info", "success", "warning", "danger"];

    public string Kind { get; set; } = "info";

    public override async Task ProcessAsync(TagHelperContext context, TagHelperOutput output)
    {
        var kind = Kinds.Contains(Kind) ? Kind : "info";             // whitelist: never echo arbitrary class names

        output.TagName = "div";
        output.Attributes.SetAttribute("role", "alert");
        output.Attributes.SetAttribute("class", $"alert alert-{kind}");
        output.PreContent.SetHtmlContent("<strong>Note:</strong> ");

        _ = await output.GetChildContentAsync();                      // renders inner markup into the output
    }
}
----

[source,cshtml]
----
<alert kind="warning">Your session ends in five minutes.</alert>
----

`SetAttribute` HTML-encodes values, so `kind` cannot break out of the attribute; the whitelist additionally stops
callers from injecting arbitrary CSS classes. Only the literal `PreContent` string is written as raw HTML because
it is a constant in the Tag Helper, not user input.

=== A conditional attribute: `asp-if`

A Tag Helper may target any element that carries a given attribute, which is how `asp-for` and `asp-controller`
work. This one hides an element when a condition is false, replacing `@if` blocks around single elements:

[source,csharp]
----
[HtmlTargetElement(Attributes = "asp-if")]
public sealed class ConditionTagHelper : TagHelper
{
    [HtmlAttributeName("asp-if")]
    public bool Condition { get; set; }

    public override void Process(TagHelperContext context, TagHelperOutput output)
    {
        if (!Condition) output.SuppressOutput();                      // render nothing, not even the tag
    }
}
----

[source,cshtml]
----
<button asp-if="Model.CanDelete" type="submit">Delete</button>
----

Hiding a button is presentation, not security: the server must still authorize the delete action itself (see
xref:web/aspnet/core/authorization.adoc[Authorization]).

=== Registration and ordering

[source,cshtml]
----
@* Views/_ViewImports.cshtml *@
@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers
@addTagHelper *, Shop.Web
----

The second line registers every Tag Helper in the assembly named `Shop.Web` (the assembly name, not a namespace). When
several Tag Helpers target the same element, their `Order` property decides who runs first; lower values run first.
Use `[HtmlTargetElement]` attributes to narrow a Tag Helper, for example `ParentTag = "form"` to apply only inside a
form.

=== Testing a Tag Helper

`TagHelperContext` and `TagHelperOutput` can be built by hand, so no view engine is needed:

[source,csharp]
----
using Microsoft.AspNetCore.Razor.TagHelpers;

[Fact]
public async Task Unknown_kind_falls_back_to_info()
{
    var context = new TagHelperContext(new TagHelperAttributeList(), new Dictionary<object, object>(), "test");
    var output = new TagHelperOutput(
        "alert",
        new TagHelperAttributeList(),
        (useCachedResult, encoder) =>
        {
            var content = new DefaultTagHelperContent();
            content.SetContent("Saved");
            return Task.FromResult<TagHelperContent>(content);
        });

    await new AlertTagHelper { Kind = "<script>" }.ProcessAsync(context, output);

    Assert.Equal("div", output.TagName);
    Assert.Equal("alert alert-info", output.Attributes["class"].Value);
}
----
