= Routing
:description: Endpoint routing in ASP.NET Core -- the match/execute model, route templates and constraints, the Map methods, route groups, attribute vs. conventional routing, URL generation, and short-circuit routes.
:keywords: ASP.NET Core routing, endpoint routing, UseRouting, route template, route constraint, MapGet, MapControllers, MapGroup, attribute routing, conventional routing, LinkGenerator, short-circuit route

include::partial$ai-disclaimer.adoc[]

Routing maps an incoming request to an *endpoint* -- a delegate plus metadata. It runs in two steps: `UseRouting`
selects the endpoint, and the endpoint middleware at the end of the pipeline executes it.

== The two-step model

[source,csharp]
----
var app = builder.Build();

app.UseRouting();          // 1. match: sets HttpContext.GetEndpoint()
app.UseAuthentication();
app.UseAuthorization();    // can read the selected endpoint's metadata (e.g. [Authorize])

app.MapGet("/ping", () => "pong");   // 2. execute: the endpoint middleware runs the match
app.Run();
----

In the minimal hosting model `UseRouting` and the terminal endpoint middleware are added automatically if you
do not add them yourself; call `UseRouting` explicitly only when you need middleware *between* matching and
execution. All registered endpoints live in an `EndpointDataSource`. See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/routing[Routing in ASP.NET Core].

== Route templates

A template is literal text plus `+\{parameter}+` segments:

[cols="1,3",options="header"]
|===
| Syntax | Meaning

| `+products/\{id}+` | required parameter `id`
| `+products/\{id?}+` | optional parameter
| `+products/\{id=1}+` | parameter with a default value
| `+files/\{*path}+` | catch-all (greedy); `+\{**path}+` also un-escapes slashes
| `+products/\{id:int}+` | route *constraint* -- must parse as `int`
| `+users/\{name:minlength(3)}+` | constrained length
| `+orders/\{code:regex(...)}+` | regex constraint (pattern in parentheses)
|===

[source,csharp]
----
app.MapGet("/products/{id:int}", (int id) => $"product {id}");
app.MapGet("/blog/{*slug}", (string slug) => $"post: {slug}");
----

Built-in constraints include `int`, `long`, `bool`, `guid`, `datetime`, `alpha`, `length(n)`,
`min(n)`/`max(n)`, `range(a,b)`, and `+regex(...)+`. Register a custom `IRouteConstraint` in
`RouteOptions.ConstraintMap`.

== Mapping endpoints

[source,csharp]
----
app.MapGet("/health", () => Results.Ok());
app.MapPost("/orders", (CreateOrder c) => Results.Created());

app.MapControllers();                                  // attribute-routed controllers
app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}");  // conventional
app.MapRazorPages();
app.MapHub<ChatHub>("/hubs/chat");
app.MapGrpcService<GreeterService>();
----

**Route groups** share a prefix and metadata:

[source,csharp]
----
var admin = app.MapGroup("/admin").RequireAuthorization("AdminOnly").WithTags("Admin");
admin.MapGet("/users", ListUsers);
admin.MapDelete("/users/{id:guid}", DeleteUser);
----

== Attribute vs. conventional routing

Controllers can be routed by attributes on the class/action or by a global convention. Attribute routing is the
default for Web APIs; conventional routing suits classic MVC sites.

[source,csharp]
----
[ApiController]
[Route("api/[controller]")]                 // -> api/orders
public sealed class OrdersController : ControllerBase
{
    [HttpGet("{id:int}")]                   // -> GET api/orders/42
    public ActionResult<Order> Get(int id) => ...;

    [HttpGet("recent")]                     // -> GET api/orders/recent
    public IEnumerable<Order> Recent() => ...;
}
----

When two routes could match, the more specific template wins; break remaining ties with `Order` on the
attribute or `+[HttpGet("...", Order = 2)]+`. See
https://learn.microsoft.com/en-us/aspnet/core/mvc/controllers/routing[Routing to controller actions].

== URL generation and short-circuiting

[source,csharp]
----
app.MapGet("/build-link", (LinkGenerator links, HttpContext ctx) =>
    links.GetUriByName(ctx, "GetOrder", new { id = 42 }));

app.MapGet("/orders/{id:int}", (int id) => id).WithName("GetOrder");
----

A **short-circuit route** responds during matching and skips the rest of the pipeline (auth, other middleware) --
useful for `robots.txt` or health probes:

[source,csharp]
----
app.MapGet("/robots.txt", () => "User-agent: *\nDisallow:").ShortCircuit();
app.MapShortCircuit(404, "favicon.ico", "*.gif");
----

== Deep dive: a catalog API with a custom constraint

Route constraints decide whether a template *matches*; they are not validation. A request that fails a constraint
does not return `400`, it simply falls through to the next candidate and usually ends in `404`. That is the right
trade-off for shape checks that disambiguate routes (`+/catalog/{id:int}+` versus `+/catalog/{sku}+`), and the wrong one
for business rules, which belong in binding and validation (see
xref:web/aspnet/core/model-binding-and-validation.adoc[Model Binding and Validation]).

The example below builds a small catalog API on a custom `sku` constraint, a nested route group, named endpoints and
link generation. A SKU is three capital letters, a dash and four digits, such as `BKS-0042`.

[source,csharp]
----
using System.Text.RegularExpressions;
using Microsoft.AspNetCore.Routing;

public sealed record Product(string Sku, string Name, decimal Price);

public sealed partial class SkuConstraint : IRouteConstraint
{
    [GeneratedRegex("^[A-Z]{3}-[0-9]{4}$")]
    private static partial Regex SkuPattern();

    public bool Match(HttpContext? httpContext, IRouter? route, string routeKey,
                      RouteValueDictionary values, RouteDirection routeDirection)
        => values.TryGetValue(routeKey, out var raw)
           && raw is string text
           && SkuPattern().IsMatch(text);
}
----

[source,csharp]
----
var builder = WebApplication.CreateBuilder(args);
builder.Services.Configure<RouteOptions>(o => o.ConstraintMap["sku"] = typeof(SkuConstraint));

var app = builder.Build();

var products = new Dictionary<string, Product>
{
    ["BKS-0042"] = new("BKS-0042", "Bookshelf", 129.90m),
};

var api = app.MapGroup("/api");
var catalog = api.MapGroup("/catalog").WithTags("Catalog");

catalog.MapGet("/{sku:sku}", (string sku) =>
        products.TryGetValue(sku, out var p) ? TypedResults.Ok(p) : Results.NotFound())
    .WithName("GetProduct");

catalog.MapGet("/{id:int}", (int id) => TypedResults.Redirect($"/api/catalog/BKS-{id:D4}"));

catalog.MapPost("/", (Product product) =>
{
    products[product.Sku] = product;
    return TypedResults.CreatedAtRoute(product, "GetProduct", new { sku = product.Sku });
});

app.Run();
----

Walk through three requests against this table:

* `GET /api/catalog/BKS-0042` -- the `sku` constraint accepts the text, the `int` template does not match a string,
  so exactly one endpoint is a candidate and it runs.
* `GET /api/catalog/42` -- `42` fails the `sku` constraint but parses as `int`, so the redirect endpoint runs and
  the client lands on `/api/catalog/BKS-0042`.
* `GET /api/catalog/hello` -- neither constraint accepts it, no endpoint matches and the framework answers `404`.

Both templates have the same shape, one parameter segment, so the constraint is the only thing separating them.
When two candidate templates could both accept the same URL, ASP.NET Core ranks the more specific one first (literal
segments, then constrained parameters, then unconstrained ones) and throws an `AmbiguousMatchException`, answered as
`500`, if it still cannot choose. Fix it by tightening one template or setting `Order`.

=== Inspecting what the router knows

When a route does not behave, ask the router rather than guessing. `EndpointDataSource` lists every endpoint with its
pattern, order and metadata, which makes a useful development-only diagnostic:

[source,csharp]
----
if (app.Environment.IsDevelopment())
{
    app.MapGet("/_routes", (EndpointDataSource source) =>
        source.Endpoints.OfType<RouteEndpoint>().Select(e => new
        {
            Pattern = e.RoutePattern.RawText,
            e.Order,
            Name = e.Metadata.GetMetadata<IEndpointNameMetadata>()?.EndpointName,
            Methods = e.Metadata.GetMetadata<IHttpMethodMetadata>()?.HttpMethods,
        }));
}
----

Never expose such an endpoint in production. For per-request insight, `HttpContext.GetEndpoint()` returns the endpoint
selected by `UseRouting` and `HttpContext.GetRouteValue("sku")` returns the parsed route value, both usable from
middleware placed between matching and execution.
