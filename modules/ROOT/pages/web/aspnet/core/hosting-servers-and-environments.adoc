= Hosting, Servers, and Environments
:description: The Host abstraction, WebApplication vs. the Generic Host, background services, Kestrel/IIS/HTTP.sys, reverse proxies and forwarded headers, and environment-based configuration.
:keywords: ASP.NET Core host, Generic Host, WebApplication, IHostedService, BackgroundService, Kestrel, IIS, HTTP.sys, reverse proxy, UseForwardedHeaders, ASPNETCORE_ENVIRONMENT, IWebHostEnvironment

include::partial$ai-disclaimer.adoc[]

The *host* starts the app, owns dependency injection, configuration, logging, and the lifetime, and runs the
web server. Environments let one build behave differently in Development, Staging, and Production.

== `WebApplication` vs. the Generic Host

`WebApplication.CreateBuilder` is the web host: it configures Kestrel, HTTPS, routing, and the DI/config/logging
stack in one call. For a non-web worker (a queue processor, a scheduled job) use
`Host.CreateApplicationBuilder`, which gives the same DI/config/logging without a web server.

[source,csharp]
----
// worker process -- no HTTP server
var builder = Host.CreateApplicationBuilder(args);
builder.Services.AddHostedService<InvoiceWorker>();
var host = builder.Build();
await host.RunAsync();
----

*Host configuration* (content root, environment name, `DOTNET_`/`ASPNETCORE_` variables) is read before the app
is built; *app configuration* (`appsettings.json`, user secrets, etc.) is layered on top. Inject
`IHostApplicationLifetime` to react to `ApplicationStarted` / `ApplicationStopping` / `ApplicationStopped`. See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/host/generic-host[.NET Generic Host].

== Background work

Register long-running work as a hosted service. `BackgroundService` is the base class for a single
`ExecuteAsync` loop; implement `IHostedService` directly for start/stop hooks.

[source,csharp]
----
public sealed class InvoiceWorker(IServiceScopeFactory scopeFactory, ILogger<InvoiceWorker> logger)
    : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromMinutes(5));
        while (await timer.WaitForNextTickAsync(stoppingToken))
        {
            using var scope = scopeFactory.CreateScope();   // resolve scoped services safely
            var svc = scope.ServiceProvider.GetRequiredService<IInvoiceService>();
            await svc.ProcessPendingAsync(stoppingToken);
        }
    }
}

builder.Services.AddHostedService<InvoiceWorker>();
----

The host waits up to `HostOptions.ShutdownTimeout` (default 30s) for `stoppingToken`-aware work to finish. See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/host/hosted-services[Background tasks with hosted
services].

== Servers

**Kestrel** is the default cross-platform server. Configure endpoints in `appsettings.json` or code; it supports
HTTP/1.1, HTTP/2, and HTTP/3, TLS, and connection limits.

[source,json]
----
// appsettings.json
{
  "Kestrel": {
    "Endpoints": {
      "Https": { "Url": "https://*:7010", "Protocols": "Http1AndHttp2AndHttp3" }
    },
    "Limits": { "MaxConcurrentConnections": 1000, "MaxRequestBodySize": 10485760 }
  }
}
----

[source,csharp]
----
builder.WebHost.ConfigureKestrel(o => o.AddServerHeader = false);
----

**IIS / ASP.NET Core Module** hosts Kestrel on Windows: *in-process* (default, fastest -- the app runs inside
the IIS worker) or *out-of-process* (IIS reverse-proxies to Kestrel). **HTTP.sys** is a Windows-only
alternative server with kernel-mode features (Windows auth, port sharing). See
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/kestrel[Kestrel] and
https://learn.microsoft.com/en-us/aspnet/core/fundamentals/servers/httpsys[HTTP.sys].

== Behind a reverse proxy

Nginx, Apache, YARP, or a cloud load balancer terminate TLS and forward requests. Enable forwarded-headers
processing *first* in the pipeline so `Request.Scheme` and `Connection.RemoteIpAddress` reflect the original
client:

[source,csharp]
----
builder.Services.Configure<ForwardedHeadersOptions>(o =>
{
    o.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto;
    o.KnownProxies.Add(System.Net.IPAddress.Parse("10.0.0.5"));
});

app.UseForwardedHeaders();   // before UseHttpsRedirection, UseAuthentication, etc.
----

See https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/proxy-load-balancer[Configure ASP.NET Core to
work with proxy servers and load balancers].

== Environments

The `ASPNETCORE_ENVIRONMENT` variable (`Development`, `Staging`, `Production`, or any custom name) drives
`IWebHostEnvironment` and which `+appsettings.\{Environment}.json+` file is layered on.

[source,csharp]
----
if (app.Environment.IsDevelopment())
    app.UseDeveloperExceptionPage();
else
    app.UseExceptionHandler("/error");

if (app.Environment.IsEnvironment("QA"))
    app.UseCustomQaTools();
----

In Razor views, the `<environment>` tag helper renders content only for the named environments:

[source,cshtml]
----
<environment include="Development"><script src="~/js/app.js"></script></environment>
<environment exclude="Development"><script src="~/js/app.min.js" asp-append-version="true"></script></environment>
----

See https://learn.microsoft.com/en-us/aspnet/core/fundamentals/environments[Use multiple environments].

== Deep dive: a background invoice queue with graceful shutdown

A request handler should not block for work the client does not need to wait for, such as rendering a PDF invoice.
The usual shape is a producer/consumer pair: the endpoint enqueues a job and answers `202 Accepted`, and a hosted
service drains the queue. `System.Threading.Channels` gives an in-memory, async-friendly queue with back-pressure, so
the example needs no extra packages.

[source,csharp]
----
using System.Threading.Channels;

public sealed record InvoiceJob(Guid OrderId);

public interface IInvoiceQueue
{
    ValueTask EnqueueAsync(InvoiceJob job, CancellationToken ct = default);
    IAsyncEnumerable<InvoiceJob> ReadAllAsync(CancellationToken ct);
}

public sealed class InvoiceQueue : IInvoiceQueue
{
    // Bounded: when 100 jobs are pending, producers wait instead of exhausting memory.
    private readonly Channel<InvoiceJob> _channel = Channel.CreateBounded<InvoiceJob>(
        new BoundedChannelOptions(100) { FullMode = BoundedChannelFullMode.Wait, SingleReader = true });

    public ValueTask EnqueueAsync(InvoiceJob job, CancellationToken ct = default)
        => _channel.Writer.WriteAsync(job, ct);

    public IAsyncEnumerable<InvoiceJob> ReadAllAsync(CancellationToken ct)
        => _channel.Reader.ReadAllAsync(ct);
}

public sealed class InvoiceQueueWorker(
    IInvoiceQueue queue, IServiceScopeFactory scopes, ILogger<InvoiceQueueWorker> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        try
        {
            await foreach (var job in queue.ReadAllAsync(stoppingToken))
            {
                try
                {
                    using var scope = scopes.CreateScope();        // one scope per job
                    var invoices = scope.ServiceProvider.GetRequiredService<IInvoiceService>();
                    await invoices.RenderAsync(job.OrderId, stoppingToken);
                }
                catch (Exception ex) when (ex is not OperationCanceledException)
                {
                    logger.LogError(ex, "Invoice {OrderId} failed", job.OrderId);   // keep the loop alive
                }
            }
        }
        catch (OperationCanceledException)
        {
            logger.LogInformation("Invoice worker stopping");
        }
    }
}
----

[source,csharp]
----
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddSingleton<IInvoiceQueue, InvoiceQueue>();   // shared by the endpoint and the worker
builder.Services.AddScoped<IInvoiceService, InvoiceService>();
builder.Services.AddHostedService<InvoiceQueueWorker>();
builder.Services.Configure<HostOptions>(o => o.ShutdownTimeout = TimeSpan.FromSeconds(45));

var app = builder.Build();

app.MapPost("/orders/{id:guid}/invoice", async (Guid id, IInvoiceQueue queue) =>
{
    await queue.EnqueueAsync(new InvoiceJob(id));
    return TypedResults.Accepted($"/orders/{id}");
});

app.Run();
----

Two details carry most of the correctness. The worker is a singleton-lifetime object, so it must open a
`IServiceScope` per job to use scoped services such as a `DbContext`; injecting `IInvoiceService` directly into its
constructor would capture a scoped service forever (see
xref:web/aspnet/core/dependency-injection.adoc[Dependency Injection]). And the loop catches per-job failures: an
unhandled exception that escapes `ExecuteAsync` stops the whole host by default
(`BackgroundServiceExceptionBehavior.StopHost`), which is rarely what one failed invoice should cause.

[mermaid]
....
sequenceDiagram
    participant P as Process (SIGTERM)
    participant H as Host
    participant W as InvoiceQueueWorker
    participant Q as Channel
    H->>W: StartAsync (registration order)
    W->>Q: await ReadAllAsync
    Note over Q,W: normal operation, jobs flow
    P->>H: shutdown signal
    H->>W: cancel stoppingToken
    W->>Q: pending read throws OperationCanceledException
    W-->>H: ExecuteAsync completes
    Note over H: waits up to ShutdownTimeout, stops services in reverse order
    H-->>P: process exits
....

An in-memory channel loses its contents when the process stops, so it suits work that can be re-derived (re-rendered
invoices). For durable jobs, persist them first (an outbox table, a message broker) and let the worker read from
that.

=== When a loop is not enough: scheduled jobs

`PeriodicTimer` handles "every five minutes". Cron-style schedules ("02:00 every night"), misfire policies,
persistence and clustering are what job schedulers add. Quartz.NET integrates through the
`Quartz.Extensions.Hosting` package and plugs into the same host:

[source,csharp]
----
using Quartz;

[DisallowConcurrentExecution]
public sealed class NightlyReportJob(IReportService reports) : IJob
{
    public Task Execute(IJobExecutionContext context) => reports.BuildAsync(context.CancellationToken);
}

builder.Services.AddQuartz(q =>
{
    var key = new JobKey("nightly-report");
    q.AddJob<NightlyReportJob>(key);
    q.AddTrigger(t => t.ForJob(key).WithCronSchedule("0 0 2 * * ?"));   // 02:00 every day
});
builder.Services.AddQuartzHostedService(o => o.WaitForJobsToComplete = true);
----

Quartz resolves jobs from the container with a scope per execution, so scoped dependencies work in a job's
constructor. Hangfire is the alternative when a dashboard and persistent, retryable fire-and-forget jobs matter more
than cron expressiveness; both need a database to survive restarts and to coordinate several instances.
