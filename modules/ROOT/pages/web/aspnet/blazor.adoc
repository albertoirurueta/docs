= Blazor
:description: Interactive web UI with C# components -- the Blazor Web App project, the four render modes, component model and lifecycle, routing, forms, JS interop, state and performance, and security.
:keywords: Blazor, Blazor Web App, render modes, Static SSR, Interactive Server, Interactive WebAssembly, Interactive Auto, rendermode, EditForm, IJSRuntime, PersistentComponentState, AuthorizeView

include::partial$aspnet-disclaimer.adoc[]

Blazor builds interactive web UI from reusable *components* written in C# and Razor (`.razor` files) instead of
JavaScript. A single **Blazor Web App** project can render each component on the server, in the browser via
WebAssembly, or statically.

== What Blazor is

A component is a class (usually authored as Razor markup) that renders a fragment of UI and reacts to events.
The `dotnet new blazor` template creates a Blazor Web App with server-side rendering enabled and interactivity
opt-in per page or component.

[source,razor]
----
@* Counter.razor *@
<button class="btn" @onclick="Increment">Clicked @count times</button>

@code {
    private int count;
    private void Increment() => count++;
}
----

See https://learn.microsoft.com/en-us/aspnet/core/blazor/[Introduction to Blazor].

== Render modes

[cols="1,2,2",options="header"]
|===
| Mode | How it runs | Good for

| **Static SSR** | HTML rendered on the server, no interactivity | Content pages, SEO, first paint
| **Interactive Server** | Events run on the server over a SignalR circuit; DOM diffs pushed to the browser |
  Low-latency networks, small download, server-side secrets
| **Interactive WebAssembly** | Component runs in the browser on the .NET WASM runtime | Offline, no per-user
  server state, CDN hosting
| **Interactive Auto** | Starts on Server for a fast load, switches to WebAssembly once the runtime is cached |
  Best of both, at the cost of supporting both
|===

Apply a mode per component or per page:

[source,razor]
----
@rendermode InteractiveServer

@* or from the parent: *@
<Counter @rendermode="InteractiveWebAssembly" />
----

Standalone Blazor WebAssembly (`dotnet new blazorwasm`) and Blazor Hybrid (.NET MAUI) remain options for
pure-client and native-shell apps. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/components/render-modes[ASP.NET Core Blazor render modes].

== Components

[source,razor]
----
@* ProductCard.razor *@
<div class="card" @key="Product.Id">
    <h3>@Product.Name</h3>
    <button @onclick="() => OnBuy.InvokeAsync(Product)">Buy</button>
</div>

@code {
    [Parameter, EditorRequired] public ProductDto Product { get; set; } = default!;
    [Parameter] public EventCallback<ProductDto> OnBuy { get; set; }
    [CascadingParameter] public ThemeState? Theme { get; set; }
}
----

* `[Parameter]` inputs; `[EditorRequired]` flags a missing one at build time; `[CascadingParameter]` receives a
  value from an ancestor `<CascadingValue>`.
* `EventCallback` / `EventCallback<T>` raise events to the parent; `RenderFragment` / `RenderFragment<T>` accept
  templated child content.
* `@key` keeps identity stable across list re-renders; `@ref` captures a component or element reference.
* Lifecycle: `OnInitialized\{Async}`, `OnParametersSet\{Async}`, `OnAfterRender\{Async}`, `ShouldRender`, and
  `IDisposable` / `IAsyncDisposable` for cleanup.
* Call `StateHasChanged()` to re-render after an async update from outside an event; wrap UI updates raised on a
  background thread in `InvokeAsync(...)`.

See https://learn.microsoft.com/en-us/aspnet/core/blazor/components/[ASP.NET Core Razor components].

== Routing and navigation

[source,razor]
----
@page "/products/{Id:int}"
@inject NavigationManager Nav

<NavLink href="/products" Match="NavLinkMatch.All">All products</NavLink>
<button @onclick='() => Nav.NavigateTo("/products")'>Back</button>

@code {
    [Parameter] public int Id { get; set; }
}
----

`@page` sets the route (constraints allowed); `NavigationManager` reads/changes the URL; `<NavLink>` adds an
`active` class. .NET 10 adds `NavigationManager.NotFound()` and a `<NotFoundPage>` for "no such resource".
Enhanced navigation intercepts links and form posts to update the DOM without a full reload. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/fundamentals/routing[Blazor routing and navigation].

== Forms

[source,razor]
----
<EditForm Model="Input" OnValidSubmit="Save">
    <DataAnnotationsValidator />
    <ValidationSummary />
    <InputText @bind-Value="Input.Name" />
    <InputNumber @bind-Value="Input.Price" />
    <InputDate @bind-Value="Input.ReleaseOn" />
    <button type="submit">Save</button>
</EditForm>

@code {
    private ProductInput Input = new();
    private Task Save() => ProductApi.CreateAsync(Input);
}
----

`EditForm` builds an `EditContext` over the model; the `Input*` components bind fields and show validation.
.NET 10 adds `<InputHidden>` and nested-model validation. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/forms/[ASP.NET Core Blazor forms overview].

== JavaScript interop

[source,csharp]
----
// call JS from C#
var text = await JS.InvokeAsync<string>("navigator.clipboard.readText");

// isolated module colocated as wwwroot/js/chart.js
var module = await JS.InvokeAsync<IJSObjectReference>("import", "./js/chart.js");
await module.InvokeVoidAsync("render", elementRef, data);
----

Expose C# to JS with `[JSInvokable]` and a `DotNetObjectReference`. For WebAssembly, `[JSImport]` / `[JSExport]`
give low-overhead interop. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/javascript-interoperability/[Blazor JavaScript interop].

== State and performance

* Share state via a DI-scoped service, `<CascadingValue>`, or `PersistentComponentState` /
  `[PersistentState]` (.NET 10) to carry prerendered data across the SSR-to-interactive handover.
* `ProtectedLocalStorage` / `ProtectedSessionStorage` store per-user values encrypted with Data Protection.
* Data: inject `HttpClient` (or a typed client) to call APIs; `QuickGrid` for tables, `<Virtualize>` for long
  lists, streaming rendering for slow data, prerendering for first paint, and WASM lazy-loading + AOT for
  startup/throughput.

[source,razor]
----
<QuickGrid Items="products.AsQueryable()">
    <PropertyColumn Property="@(p => p.Name)" Sortable="true" />
    <PropertyColumn Property="@(p => p.Price)" Format="C" />
</QuickGrid>
----

== Security

[source,razor]
----
<AuthorizeView Policy="AdminOnly">
    <Authorized><AdminPanel /></Authorized>
    <NotAuthorized><p>Access denied.</p></NotAuthorized>
</AuthorizeView>
----

`[Authorize]` on a `@page` component, `<AuthorizeView>` for conditional UI, `AuthenticationStateProvider` for
the current user, and a cascading `AuthenticationState` from `<CascadingAuthenticationState>`. The .NET 10 Blazor
Web App template supports passkey (WebAuthn) sign-in out of the box. See
https://learn.microsoft.com/en-us/aspnet/core/blazor/security/[ASP.NET Core Blazor authentication and
authorization].
