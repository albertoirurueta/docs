= HTML Helpers and Forms
:description: Standard, strongly typed, templated, and inline HTML helpers, Html.BeginForm, the *For family (LabelFor, TextBoxFor, DropDownListFor, ...), validation helpers, Html.AntiForgeryToken, MvcHtmlString, and why ASP.NET Core replaced most of this with Tag Helpers.
:keywords: ASP.NET MVC 5, HTML helpers, Html.BeginForm, LabelFor, TextBoxFor, DropDownListFor, SelectList, ValidationMessageFor, AntiForgeryToken, HtmlHelper, MvcHtmlString, EnumDropDownListFor, Tag Helpers

include::partial$ai-disclaimer.adoc[]

This page documents ASP.NET MVC 5.3.x HTML helpers on .NET Framework 4.8.1 -- not ASP.NET Core's Tag Helpers,
which replace most of this API surface (see the cross-link at the end of this page).

== Four kinds of helper

* **Standard** -- untyped, string-keyed: `Html.TextBox("Name", value)`.
* **Strongly typed** -- a lambda expression over `Model`, giving compile-time checking and correct `name`/`id`
  attributes for model binding: `+Html.TextBoxFor(m => m.Name)+`.
* **Templated** -- resolved by type/metadata rather than naming a specific input:
  `+Html.EditorFor(m => m.Price)+` (see
  xref:web/aspnet/mvc/views-layouts-and-partials.adoc[Views, Layouts, and Partials]).
* **Inline** (`@helper`) -- a markup-producing function scoped to one view (see
  xref:web/aspnet/mvc/razor-syntax.adoc[Razor Syntax]).

Strongly typed helpers are preferred in current MVC 5 code: they survive a property rename (compile error
instead of a silent broken form) and their generated `name` attribute is exactly what the default model binder
expects (see xref:web/aspnet/mvc/model-binding-and-validation.adoc[Model Binding and Validation]).

== `Html.BeginForm` / `Html.BeginRouteForm`

Both return an `IDisposable` (`MvcForm`) that writes the closing `</form>` tag when disposed -- almost always
used with a `using` block:

[source,cshtml]
----
@using (Html.BeginForm("Edit", "Products", FormMethod.Post, new { @class = "form-horizontal" }))
{
    @Html.AntiForgeryToken()
    @Html.ValidationSummary(true)
    @* fields *@
    <button type="submit">Save</button>
}

@using (Html.BeginRouteForm("ProductDetails", new { id = Model.Id }, FormMethod.Post))
{
    @* posts to a specific named route instead of an action/controller pair *@
}
----

== The `+*For+` field helpers

[source,cshtml]
----
@model MyApp.Models.ProductEditViewModel

@Html.LabelFor(m => m.Name)
@Html.TextBoxFor(m => m.Name, new { @class = "form-control" })
@Html.ValidationMessageFor(m => m.Name)

@Html.PasswordFor(m => m.NewPassword)
@Html.TextAreaFor(m => m.Description, 5, 40, null)
@Html.CheckBoxFor(m => m.IsActive)
@Html.RadioButtonFor(m => m.Size, "Small")
@Html.RadioButtonFor(m => m.Size, "Large")

@Html.DropDownListFor(m => m.CategoryId,
    new SelectList(Model.Categories, "Id", "Name", Model.CategoryId), "-- choose --")
@Html.ListBoxFor(m => m.SelectedTagIds, new MultiSelectList(Model.AllTags, "Id", "Name"))

@Html.HiddenFor(m => m.Id)
@Html.EditorFor(m => m.Price)
@Html.DisplayFor(m => m.CreatedOn)

@Html.EnumDropDownListFor(m => m.Status)          <!-- MVC 5.1+: builds a SelectList from an enum's values -->
----

`SelectList`/`MultiSelectList` (`System.Web.Mvc`) wrap an `IEnumerable`, a value-field name, a text-field name,
and the currently selected value(s) -- constructed in the controller or the view model, not hand-built as
`<option>` tags.

== Validation helpers

[source,cshtml]
----
@Html.ValidationSummary(excludePropertyErrors: true, message: "Please correct the errors below.")
@Html.ValidationMessageFor(m => m.Email, "", new { @class = "text-danger" })
----

These render the error messages `ModelState` accumulated during model binding/validation (see
xref:web/aspnet/mvc/model-binding-and-validation.adoc[Model Binding and Validation]) and carry the
`+data-val-*+` attributes that unobtrusive client validation reads.

== `Html.AntiForgeryToken()`

Emits a hidden input carrying a per-user, per-session token that the matching `[ValidateAntiForgeryToken]`
action filter checks on submit -- MVC 5's CSRF defense; see
xref:web/aspnet/mvc/security-hardening.adoc[Security Hardening] for the full mechanism and the AJAX variant.

[source,cshtml]
----
@using (Html.BeginForm())
{
    @Html.AntiForgeryToken()
}
----

== `HtmlHelper` extension methods and `MvcHtmlString`

Every helper above is an extension method on `HtmlHelper`/`HtmlHelper<TModel>`, which is how custom helpers are
added without subclassing anything:

[source,csharp]
----
public static class CustomHtmlHelpers
{
    public static MvcHtmlString StarRating(this HtmlHelper html, int rating)
    {
        var stars = string.Concat(Enumerable.Range(0, 5)
            .Select(i => i < rating ? "&#9733;" : "&#9734;"));
        return new MvcHtmlString(stars);          // marks the string as "already safe", bypassing auto-encoding
    }
}
----

[source,cshtml]
----
@Html.StarRating(Model.Rating)
----

`MvcHtmlString` (implementing `IHtmlString`) is what tells Razor a value is already-encoded markup rather than
plain text to be HTML-encoded -- returning a bare `string` from a helper would get double-escaped when rendered.

== Deep dive: one edit form, a full round trip

The `+*For+` helpers are the glue between a view model, the rendered markup, and the model binder that reads the form
back. They generate `name` and `id` attributes from the expression (`+m => m.Price+` becomes `name="Price"`), take the
displayed value from `ModelState` first and from the model second, and emit the `+data-val-*+` attributes that unobtrusive
validation reads. A request that fails validation therefore re-displays exactly what the user typed.

[mermaid]
....

    B->>C: POST /Products/Edit/42 with the form fields
    C->>C: model binding fills ProductEditModel, validation fills ModelState
    alt ModelState invalid

        V-->>B: same form with typed values and error messages
    else valid
        C-->>B: 302 redirect to Index
    end
....

=== Worked example

The view model carries the validation rules and the list of categories needed by the drop-down:

[source,csharp]
----
using System.Collections.Generic;
using System.ComponentModel.DataAnnotations;
using System.Web.Mvc;

public class ProductEditModel
{
    public int Id { get; set; }

    [Required, StringLength(80)]
    [Display(Name = "Product name")]
    public string Name { get; set; }

    [Range(0.01, 100000)]
    [DataType(DataType.Currency)]
    public decimal Price { get; set; }

    [Display(Name = "Category")]
    public int CategoryId { get; set; }

    public IEnumerable<SelectListItem> Categories { get; set; }   // not posted back; rebuilt on every render
}
----

[source,html]
----
@model MyApp.Models.ProductEditModel

@using (Html.BeginForm("Edit", "Products", FormMethod.Post, new { @class = "form-horizontal" }))
{
    @Html.AntiForgeryToken()
    @Html.ValidationSummary(true, "", new { @class = "text-danger" })   @* model-level errors only *@
    @Html.HiddenFor(m => m.Id)

    <div class="form-group">
        @Html.LabelFor(m => m.Name, new { @class = "control-label" })
        @Html.TextBoxFor(m => m.Name, new { @class = "form-control" })
        @Html.ValidationMessageFor(m => m.Name, "", new { @class = "text-danger" })
    </div>
    <div class="form-group">
        @Html.LabelFor(m => m.Price)
        @Html.EditorFor(m => m.Price)                                  @* honors [DataType] and editor templates *@
        @Html.ValidationMessageFor(m => m.Price)
    </div>
    <div class="form-group">
        @Html.LabelFor(m => m.CategoryId)
        @Html.DropDownListFor(m => m.CategoryId, Model.Categories, "-- choose --", new { @class = "form-control" })
    </div>
    <input type="submit" value="Save" class="btn btn-primary" />
}
----

The controller pair rebuilds the drop-down on both paths, because `Categories` is never posted:

[source,csharp]
----
[HttpGet]
public ActionResult Edit(int id)
{
    var product = _repository.Find(id);
    if (product == null) return HttpNotFound();
    return View(ToModel(product));
}

[HttpPost, ValidateAntiForgeryToken]
public ActionResult Edit(ProductEditModel model)
{
    if (!ModelState.IsValid)
    {
        model.Categories = LoadCategories();          // the posted model has no list
        return View(model);
    }
    _repository.Update(FromModel(model));
    return RedirectToAction("Index");
}
----

Two behaviors of this loop surprise most teams:

* **`ModelState` wins over the model.** If the action changes `model.Price` (for example normalizing a value) and
  then returns the view, the old posted text is still displayed, because the helper reads the attempted value from
  `ModelState`. Call `ModelState.Remove("Price")` or `ModelState.Clear()` before changing a posted value.
* **`name` is derived from the expression, not from the field's declared type.** `+TextBoxFor(m => m.Address.City)+`
  renders `name="Address.City"`, which the binder maps back through nested properties, so a nested view model binds
  with no extra code. Inside a loop, use `pass:c[for (var i = 0; i < Model.Items.Count; i++)]` with
  `+Html.TextBoxFor(m => m.Items[i].Quantity)+`; a `foreach` over `Model.Items` produces names without an index and
  breaks collection binding.

== Why ASP.NET Core replaced most of this with Tag Helpers

Two problems with HTML helpers motivated Tag Helpers: they read as C# method calls even though they produce
HTML (`+@Html.TextBoxFor(...)+` gives no visual cue in the rendered markup, and HTML/CSS tooling can't see
through it), and building one requires C#, not markup. ASP.NET Core's Tag Helpers
(`<input asp-for="Name" />`) attach to ordinary HTML attributes, stay readable as HTML in the source, and are
processed server-side without changing the tag a designer would otherwise write. See
xref:web/aspnet/core/razor-syntax-and-tag-helpers.adoc[Razor Syntax and Tag Helpers] for the ASP.NET Core
equivalent of every helper on this page, and
https://learn.microsoft.com/en-us/aspnet/mvc/overview/older-versions-1/views/creating-custom-html-helpers-cs[Creating
Custom HTML Helpers (C#)] for more on the MVC 5 model.

See also https://learn.microsoft.com/en-us/aspnet/mvc/overview/getting-started/introduction/adding-a-view[Adding a
View] and https://learn.microsoft.com/en-us/dotnet/api/system.web.mvc.html.inputextensions[InputExtensions] for the
helpers used above.
