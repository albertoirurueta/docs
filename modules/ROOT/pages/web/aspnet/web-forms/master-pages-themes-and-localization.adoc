= Master Pages, Themes, and Localization
:description: Master pages and ContentPlaceHolder/Content, nested masters, @MasterType and dynamic master selection, themes and skins, site navigation (Web.sitemap, SiteMapDataSource, Menu, TreeView), Web Forms URL routing, and culture-based localization.
:keywords: ASP.NET Web Forms, master pages, ContentPlaceHolder, MasterType, App_Themes, StyleSheetTheme, Web.sitemap, SiteMapDataSource, RouteTable, MapPageRoute, InitializeCulture, meta:resourcekey

include::partial$ai-disclaimer.adoc[]

This page covers the three mechanisms Web Forms uses to keep a site's shared layout, look, navigation, and
language consistent across many pages, without repeating markup or logic on each one.

== Master pages

A **master page** (`.master`) defines the shared chrome -- header, navigation, footer -- around one or more
named `ContentPlaceHolder` regions that content pages fill in:

[source,aspx]
----
<%-- Site.master --%>
<%@ Master Language="C#" CodeBehind="Site.master.cs" Inherits="WebFormsApp.SiteMaster" %>
<!DOCTYPE html>
<html>
<head runat="server">
    <title><asp:ContentPlaceHolder ID="TitleContent" runat="server" /></title>
</head>
<body>
    <form id="form1" runat="server">
        <header>My Site</header>
        <asp:ContentPlaceHolder ID="MainContent" runat="server" />
        <footer>&copy; 2026</footer>
    </form>
</body>
</html>
----

[source,aspx]
----
<%-- Default.aspx --%>
<%@ Page Language="C#" MasterPageFile="~/Site.master"
    CodeBehind="Default.aspx.cs" Inherits="WebFormsApp.Default" Title="Home" %>

<asp:Content ID="Content1" ContentPlaceHolderID="MainContent" runat="server">
    <h1>Welcome</h1>
</asp:Content>
----

**Nested masters** let a section of a site (e.g. an admin area) layer its own shared chrome on top of the
site-wide master, by giving the nested master its own `MasterPageFile` attribute and using
`ContentPlaceHolder` controls inside `Content` blocks.

== `@MasterType` and typed `Master` access

By default, `Page.Master` is typed as the base `MasterPage` class -- accessing a custom member requires a cast.
`@MasterType` gives a strongly typed, IntelliSense-friendly `Master` property instead:

[source,aspx]
----
<%@ MasterType VirtualPath="~/Site.master" %>
----

[source,csharp]
----
protected void Page_Load(object sender, EventArgs e)
{
    Master.SetPageHeading("Dashboard"); // strongly typed, no cast needed
}
----

== Dynamic master selection

Because the master page is applied during xref:web/aspnet/web-forms/page-lifecycle-and-postback.adoc[the
Initialization stage], it can only be changed in or before `PreInit` -- any later is too late:

[source,csharp]
----
protected override void OnPreInit(EventArgs e)
{
    base.OnPreInit(e);
    MasterPageFile = Request.IsAuthenticated ? "~/MemberSite.master" : "~/PublicSite.master";
}
----

See https://learn.microsoft.com/en-us/previous-versions/aspnet/wtxbf3hh(v=vs.100)[ASP.NET Master Pages].

== Themes and skins

A **theme** under `App_Themes/<ThemeName>/` bundles CSS files (applied automatically) and `.skin` files, which
set default property values for a control type site-wide:

[source]
----
<%-- App_Themes/Corporate/Buttons.skin --%>
<asp:Button runat="server" CssClass="btn btn-corporate" Font-Size="14px" />
----

[source,aspx]
----
<%@ Page Theme="Corporate" ... %> <%-- StyleSheetTheme="Corporate" is the low-priority variant --%>
----

`Theme` overrides any conflicting properties set in markup; `StyleSheetTheme` applies first and is itself
overridable by markup -- the choice determines whether a theme is a hard site-wide policy (`Theme`) or a
default a specific page can locally override (`StyleSheetTheme`). See
https://learn.microsoft.com/en-us/previous-versions/aspnet/ykzx33wh(v=vs.100)[ASP.NET Themes and Skins].

== Site navigation

`Web.sitemap` declares the site's logical page hierarchy in XML:

[source,xml]
----
<siteMap xmlns="http://schemas.microsoft.com/AspNet/SiteMap-File-1.0">
  <siteMapNode url="~/Default.aspx" title="Home">
    <siteMapNode url="~/Products/Default.aspx" title="Products">
      <siteMapNode url="~/Products/Details.aspx" title="Product Details" />
    </siteMapNode>
    <siteMapNode url="~/About.aspx" title="About" />
  </siteMapNode>
</siteMap>
----

`SiteMapDataSource` exposes that hierarchy to navigation controls: `SiteMapPath` (a breadcrumb trail), `Menu`,
and `TreeView`:

[source,aspx]
----
<asp:SiteMapDataSource ID="SiteMap1" runat="server" />
<asp:Menu ID="MainMenu" runat="server" DataSourceID="SiteMap1" Orientation="Horizontal" />
<asp:SiteMapPath ID="Breadcrumb" runat="server" />
----

== URL routing for Web Forms

`System.Web.Routing` lets `.aspx` pages be reached through friendly, parameterized URLs instead of a literal
file path, registered in `global.asax`:

[source,csharp]
----
// Global.asax.cs
protected void Application_Start(object sender, EventArgs e)
{
    RegisterRoutes(RouteTable.Routes);
}

private static void RegisterRoutes(RouteCollection routes)
{
    routes.MapPageRoute("ProductDetails", "products/{category}/{id}", "~/Products/Details.aspx");
}
----

[source,csharp]
----
// Products/Details.aspx.cs
protected void Page_Load(object sender, EventArgs e)
{
    string category = (string)Page.RouteData.Values["category"];
    string id = (string)Page.RouteData.Values["id"];
}
----

See https://learn.microsoft.com/en-us/previous-versions/aspnet/cc668201(v=vs.100)[ASP.NET Routing]. This
pre-dates and is unrelated to the reuse of `System.Web.Routing` by ASP.NET MVC; see
xref:web/aspnet/web-forms/model-binding-and-modern-web-forms.adoc[Model Binding and Modern Web Forms] for the
4.5+ "friendly URLs" feature layered on top.

== Localization

Web Forms localizes both static markup and code:

* **`Culture`/`UICulture`** on `@Page`, or set programmatically, control number/date formatting and resource
  lookup respectively:
+
[source,csharp]
----
protected override void InitializeCulture()
{
    // UserLanguages entries look like "fr-FR;q=0.8"; Culture needs a specific (not neutral) culture name.
    string lang = Request.UserLanguages != null && Request.UserLanguages.Length > 0
        ? Request.UserLanguages[0].Split(';')[0]
        : "en-US";
    try
    {
        string name = System.Globalization.CultureInfo.CreateSpecificCulture(lang).Name;
        UICulture = name;
        Culture = name;
    }
    catch (ArgumentException)
    {
        // unknown culture name sent by the client: keep the server default
    }

    base.InitializeCulture();
}
----
+
`InitializeCulture` must be overridden (rather than set in `Page_Load`) because culture must be established
before the page's resource-driven markup is parsed, earlier than `PreInit`.
* **Implicit localization** -- `meta:resourcekey` on a control pulls matching entries from the page's
  `App_LocalResources/Default.aspx.resx` (and culture-specific `.fr.resx`, etc.) automatically:
+
[source,aspx]
----
<asp:Label ID="GreetingLabel" runat="server" meta:resourcekey="GreetingLabelResource1" />
<%-- App_LocalResources/Default.aspx.resx contains key "GreetingLabelResource1.Text" --%>
----
* **Explicit expressions** -- `<%$ Resources: %>` reads from `App_GlobalResources` anywhere in markup:
+
[source,aspx]
----
<asp:Label ID="FooterLabel" runat="server"
    Text="<%$ Resources:Common, CopyrightNotice %>" />
----

See https://learn.microsoft.com/en-us/previous-versions/aspnet/fw6yc2wd(v=vs.100)[ASP.NET Globalization and
Localization].

== Worked example: a nested master for the order-entry area

The order screens of `WebFormsApp` share a section navigation bar that the rest of the site does not need, which is
the textbook case for a nested master. `Site.master` (shown above) owns the page frame and a `MainContent`
placeholder; `Orders/Orders.master` fills that placeholder with its own markup and declares a new placeholder for the
actual page content:

[source,aspx]
----
<%-- Orders/Orders.master --%>
<%@ Master Language="C#" MasterPageFile="~/Site.master"
    CodeBehind="Orders.master.cs" Inherits="WebFormsApp.Orders.OrdersMaster" %>

<asp:Content ID="OrdersFrame" ContentPlaceHolderID="MainContent" runat="server">
    <nav>
        <a href="~/Orders/NewOrder.aspx" runat="server">New order</a> |
        <a href="~/Orders/OrderList.aspx" runat="server">All orders</a>
        <asp:Label ID="CartCountLabel" runat="server" CssClass="badge" />
    </nav>
    <asp:ContentPlaceHolder ID="OrdersContent" runat="server">
        <p>This default content is shown when a page does not fill the placeholder.</p>
    </asp:ContentPlaceHolder>
</asp:Content>
----

[source,csharp]
----
// Orders/Orders.master.cs
using System.Web.UI;

namespace WebFormsApp.Orders
{
    public partial class OrdersMaster : MasterPage
    {
        public void SetCartCount(int count)
        {
            CartCountLabel.Text = count == 0 ? "" : count + " item(s) in the order";
        }
    }
}
----

Here the order-entry page is re-hosted as a content page of that nested master:

[source,aspx]
----
<%-- Orders/NewOrder.aspx (content page of the nested master) --%>
<%@ Page Title="New order" Language="C#" MasterPageFile="~/Orders/Orders.master"
    CodeBehind="NewOrder.aspx.cs" Inherits="WebFormsApp.Orders.NewOrder" %>
<%@ MasterType VirtualPath="~/Orders/Orders.master" %>

<asp:Content ID="Body" ContentPlaceHolderID="OrdersContent" runat="server">
    <asp:DropDownList ID="ProductList" runat="server" />
    <asp:Button ID="AddButton" runat="server" Text="Add" OnClick="AddButton_Click" />
</asp:Content>
----

[source,csharp]
----
protected void AddButton_Click(object sender, EventArgs e)
{
    var cart = (List<int>)(Session["Cart"] ?? new List<int>());
    cart.Add(int.Parse(ProductList.SelectedValue));
    Session["Cart"] = cart;
    Master.SetCartCount(cart.Count); // strongly typed through @MasterType
}
----

At request time, ASP.NET merges the three files into one control tree: the content page's `Content` controls are
poured into the matching placeholders of its master, which is in turn a content block of the outer master.

[mermaid]
....
flowchart TD
    subgraph SiteMaster["Site.master"]
        S1["header"]
        S2["ContentPlaceHolder MainContent"]
        S3["footer"]
    end
    subgraph OrdersMaster["Orders.master: Content for MainContent"]
        O1["nav bar and cart badge"]
        O2["ContentPlaceHolder OrdersContent"]
    end
    subgraph Page["NewOrder.aspx: Content for OrdersContent"]
        P1["ProductList and AddButton"]
    end
    S2 --> O1
    O1 --> O2
    O2 --> P1
....

Everything inside the placeholders ends up under the `form1` of the outermost master, which is why a content page
must not declare its own `<form>`, why a `FileUpload` in any content page makes the whole form
`multipart/form-data`, and why the client IDs of controls in a content page carry the prefix of the master
(`ctl00_MainContent_ctl00_OrdersContent_ProductList`; see
xref:web/aspnet/web-forms/server-controls.adoc[Server Controls] for naming containers and `ClientIDMode`). A
master should expose behavior through public members like `SetCartCount` rather than letting pages reach into its
controls with `Master.FindControl("CartCountLabel")`, which breaks silently when the control is renamed.

== Themes in practice: `SkinID`, `EnableTheming`, and choosing a theme per user

A skin without a `SkinID` is the *default skin* for its control type and applies to every control of that type on
the page; a skin with a `SkinID` is applied only to controls that name it:

[source]
----
<%-- App_Themes/Corporate/Buttons.skin --%>
<asp:Button runat="server" CssClass="btn" />
<asp:Button runat="server" SkinID="Danger" CssClass="btn btn-danger" />
<asp:GridView runat="server" CssClass="grid" HeaderStyle-CssClass="grid-head" />
----

[source,aspx]
----
<asp:Button ID="DeleteButton" runat="server" Text="Delete" SkinID="Danger" />
<asp:Button ID="LegacyButton" runat="server" Text="Keep my style" EnableTheming="false" />
----

`EnableTheming="false"` on a control (or a container, which applies to its children) opts out of the skin. Because
the theme is applied right after `PreInit`, a per-user theme is chosen there; storing the choice in a cookie keeps
it across visits:

[source,csharp]
----
protected override void OnPreInit(EventArgs e)
{
    base.OnPreInit(e);
    HttpCookie cookie = Request.Cookies["theme"];
    string[] allowed = { "Corporate", "HighContrast" };
    Theme = cookie != null && Array.IndexOf(allowed, cookie.Value) >= 0 ? cookie.Value : "Corporate";
}
----

Validating the cookie value against a list of known theme names matters: `Theme` is a folder name, and assigning an
unvalidated value from a cookie or query string turns a tampered cookie into an error page at best.

== Route values in data binding and generated URLs

The route registered earlier (`+products/{category}/{id}+`) is readable in markup as well as in code, which keeps
the data-bound controls free of `Request.QueryString` lookups:

[source,aspx]
----
<asp:SqlDataSource ID="ProductSource" runat="server"
    ConnectionString="<%$ ConnectionStrings:CatalogDb %>"
    SelectCommand="SELECT Id, Name, Price FROM Products WHERE Id = @Id">
    <SelectParameters>
        <asp:RouteParameter Name="Id" RouteKey="id" Type="Int32" />
    </SelectParameters>
</asp:SqlDataSource>

<asp:HyperLink runat="server" Text="View"
    NavigateUrl="<%$ RouteUrl:RouteName=ProductDetails, category=hardware, id=3 %>" />
----

`RouteUrl` and `RouteValue` are expression builders (resolved in an attribute of a server control), and
`+Page.GetRouteUrl("ProductDetails", new { category = "hardware", id = 3 })+` is the code-behind counterpart. Using
generated URLs instead of hand-built strings means that renaming the pattern in `RegisterRoutes` updates every link
in one place.

== Localizing the order form end to end

The pieces above combine into a complete flow: a base page picks the culture before parsing, markup pulls its
strings from resource files, and code reads the same resources by key.

[source]
----
App_GlobalResources/
    Common.resx          (neutral/default: OrderTitle = "New order")
    Common.es.resx       (OrderTitle = "Nuevo pedido")
App_LocalResources/
    NewOrder.aspx.resx   (AddButtonResource1.Text = "Add")
    NewOrder.aspx.es.resx(AddButtonResource1.Text = "Anadir")
----

[source,csharp]
----
// Pages/BasePage.cs -- every page in the application derives from this class
using System;
using System.Globalization;
using System.Web;
using System.Web.UI;

namespace WebFormsApp.Pages
{
    public abstract class BasePage : Page
    {
        protected override void InitializeCulture()
        {
            HttpCookie cookie = Request.Cookies["lang"];
            string requested = cookie != null ? cookie.Value : null;

            if (string.IsNullOrEmpty(requested) && Request.UserLanguages != null && Request.UserLanguages.Length > 0)
            {
                requested = Request.UserLanguages[0].Split(';')[0];
            }

            try
            {
                string name = CultureInfo.CreateSpecificCulture(requested ?? "en-US").Name;
                Culture = name;
                UICulture = name;
            }
            catch (ArgumentException)
            {
                // an unknown culture name from the client: keep the server default
            }

            base.InitializeCulture();
        }
    }
}
----

[source,aspx]
----
<asp:Label ID="TitleLabel" runat="server" Text="<%$ Resources:Common, OrderTitle %>" />
<asp:Button ID="AddButton" runat="server" meta:resourcekey="AddButtonResource1" />
<asp:Label ID="PriceLabel" runat="server" />
----

[source,csharp]
----
TitleLabel.Text = (string)GetGlobalResourceObject("Common", "OrderTitle");
// "C" formats with the CURRENT culture: the same decimal shows with the user's currency symbol and
// separators, without any change to this line.
PriceLabel.Text = product.Price.ToString("C");
----

`Culture` drives *formatting* (dates, numbers, currency, sort order) and `UICulture` drives which `.resx` file is
chosen; they are independent, and an application serving Spanish text to a user who works in dollars can set
them differently. Resource lookup falls back from the specific culture (`es-MX`) to the neutral one (`es`) to the
default file, so a missing key in `Common.es.resx` silently shows the English text rather than failing -- a
translation gap is only visible in testing, not at runtime.

See the https://learn.microsoft.com/en-us/aspnet/web-forms/[ASP.NET Web Forms documentation] and the https://learn.microsoft.com/en-us/previous-versions/aspnet/[ASP.NET 4 documentation archive]
for the site navigation and web page resources topics.
