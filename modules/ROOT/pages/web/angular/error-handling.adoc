= Error Handling
:description: Handling application errors in Angular -- framework error codes and the error reference, a custom global ErrorHandler with provideBrowserGlobalErrorListeners, catching HTTP errors centrally in a functional interceptor, and surfacing errors to users and a backend.
:keywords: Angular error handling, ErrorHandler, provideBrowserGlobalErrorListeners, NG0000, error codes, error reference, HttpErrorResponse, functional interceptor, HttpInterceptorFn, 401, 403, snackbar, toast, error reporting

include::partial$ai-disclaimer.adoc[]

Angular separates **framework errors** -- raised by Angular itself and carrying a numeric code -- from your own
**runtime errors**, and gives you a single global hook to catch, present, and report both. See
https://angular.dev/best-practices/error-handling[Error handling].

== Framework errors vs. runtime errors

* **Framework errors** are thrown by Angular and carry an `NG0000`-style code -- for example `NG0100`
  (`ExpressionChangedAfterItHasBeenChecked`), `NG0200` (circular dependency in DI), and `NG0103` (infinite
  change-detection loop). Every code has a dedicated explanation page in
  https://angular.dev/errors[the error reference].
* **Runtime errors** are the ordinary exceptions your code and its dependencies throw -- a `TypeError`, a
  rejected promise, a failed HTTP call.

Both, when left unhandled, reach Angular's `ErrorHandler`.

== A custom global ErrorHandler

`ErrorHandler` is the single sink for errors that escape change detection and lifecycle hooks. Provide your own
to normalise, log, de-duplicate, and forward them.

[source,typescript]
----
import { ErrorHandler, Injectable, NgZone, inject } from '@angular/core';

@Injectable()
export class GlobalErrorHandler implements ErrorHandler {
  private readonly zone = inject(NgZone);
  private readonly reporter = inject(ErrorReporter);

  handleError(error: unknown): void {
    const err = error instanceof Error ? error : new Error(String(error));
    this.reporter.report(err);                  // send to the backend
    this.zone.run(() => this.notify(err));      // show UI inside Angular's zone
    console.error(err);
  }

  private notify(err: Error): void {
    /* trigger a toast/snackbar -- see below */
  }
}
----

[source,typescript]
----
// app.config.ts
import {
  ApplicationConfig, ErrorHandler, provideBrowserGlobalErrorListeners,
} from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [
    provideBrowserGlobalErrorListeners(),
    { provide: ErrorHandler, useClass: GlobalErrorHandler },
  ],
};
----

`provideBrowserGlobalErrorListeners()` connects the browser's `error` and `unhandledrejection` events to the
same `ErrorHandler`, so failures outside Angular's execution context -- event callbacks, un-awaited promises --
are caught too. New workspaces include it in the generated `app.config.ts`. See
https://angular.dev/api/core/ErrorHandler[`ErrorHandler`].

== Catching HTTP errors centrally

A functional interceptor is the right place to handle transport failures once for the whole app. `catchError`
inspects the `HttpErrorResponse`, reacts to the status, and re-throws so the calling code still observes the
error.

[source,typescript]
----
import { HttpErrorResponse, HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { Router } from '@angular/router';
import { catchError, throwError } from 'rxjs';

export const errorInterceptor: HttpInterceptorFn = (req, next) => {
  const router = inject(Router);

  return next(req).pipe(
    catchError((err: HttpErrorResponse) => {
      if (err.status === 401) {
        // not authenticated -- go to login, keep the target URL
        router.navigate(['/login'], { queryParams: { returnUrl: router.url } });
      } else if (err.status === 403) {
        // authenticated but not allowed -- dedicated page
        router.navigate(['/forbidden']);
      }
      return throwError(() => err);
    }),
  );
};
----

Register it with `provideHttpClient(withInterceptors([errorInterceptor]))`. A `401` means "not authenticated" --
redirect to the login page and preserve the target URL so the user lands back where they started; a `403` means
"authenticated but not authorised" -- route to a distinct page rather than the login form. See
xref:web/angular/http-client.adoc[HTTP Client] for the interceptor chain, and
xref:web/angular/routing.adoc[Routing] for functional guards that block the navigation before the request is
ever made. Link https://angular.dev/guide/http/interceptors[Interceptors].

== Where errors travel

[mermaid]
....
flowchart TD
    A["Event listener in a template throws"] --> EH["ErrorHandler.handleError"]
    B["Template expression throws during change detection"] --> EH
    C["effect callback throws"] --> EH
    D["Uncaught exception or unhandled promise rejection in the window"] --> L["provideBrowserGlobalErrorListeners"]
    L --> EH
    E["HttpClient request fails"] --> I["Interceptor catchError"]
    I -->|"re-throws"| S["Subscriber error callback or catchError in the caller"]
    S -->|"nobody handles it"| D
    EH --> R["Report to backend, notify the user, log"]
....

Four kinds of failure reach the same `ErrorHandler`: an exception in a template event listener, an exception while a
template expression is evaluated during change detection, an exception in an `effect()`, and anything the browser
reports on `window` once `provideBrowserGlobalErrorListeners()` is installed. An HTTP failure is different: it travels
down the observable's error channel, so it reaches the global handler only when nothing in the chain handles it.

== Deep dive: a global handler for BookShelf

This is the handler from above, extended with de-duplication (a render loop can throw the same error on every pass) and a
`Notifier` service that holds the message a toast component displays:

[source,typescript]
----
@Injectable({ providedIn: 'root' })
export class Notifier {
  readonly message = signal<string | null>(null);
}

@Injectable()
export class GlobalErrorHandler implements ErrorHandler {
  private readonly zone = inject(NgZone);
  private readonly reporter = inject(ErrorReporter);
  private readonly notifier = inject(Notifier);
  private readonly seen = new Set<string>();

  handleError(error: unknown): void {
    const err = error instanceof Error ? error : new Error(String(error));
    if (this.seen.has(err.message)) return;          // a loop must not flood the backend
    this.seen.add(err.message);
    this.reporter.report(err);
    this.zone.run(() => this.notifier.message.set('Something went wrong. Please try again.'));
    console.error(err);
  }
}
----

The handler can be tested by driving real failures through a component and observing what it received (the
`ErrorReporter` shown below records each message in its `sent` array for exactly that purpose). By
default `TestBed` *rethrows* application errors so a failing event handler fails the test run with an uncaught exception;
set `rethrowApplicationErrors: false` in the testing module to let your handler absorb them and assert on its effects:

[source,typescript]
----
import { vi } from 'vitest';

@Component({
  selector: 'app-boom',
  template: `<button (click)="explode()">go</button> @if (bad()) { {{ fail() }} }`,
})
class Boom {
  readonly bad = signal(false);
  explode(): void { throw new Error('click failed'); }
  fail(): string { throw new Error('template failed'); }
}

describe('global error handling', () => {
  beforeEach(() => {
    vi.stubGlobal('fetch', vi.fn(() => Promise.reject(new Error('offline'))));   // the reporter's transport
    TestBed.configureTestingModule({
      rethrowApplicationErrors: false,
      providers: [
        provideBrowserGlobalErrorListeners(),
        { provide: ErrorHandler, useClass: GlobalErrorHandler },
      ],
    });
  });

  it('catches handler and template errors', async () => {
    const fixture = TestBed.createComponent(Boom);
    await fixture.whenStable();
    (fixture.nativeElement as HTMLElement).querySelector('button')!.click();
    const reporter = TestBed.inject(ErrorReporter);
    expect(reporter.sent).toEqual(['click failed']);

    fixture.componentInstance.bad.set(true);
    await fixture.whenStable();
    expect(reporter.sent).toContain('template failed');
    expect(TestBed.inject(Notifier).message()).toBe('Something went wrong. Please try again.');
  });

  it('forwards window errors and unhandled rejections', () => {
    TestBed.inject(ErrorHandler);
    window.dispatchEvent(new ErrorEvent('error', { error: new Error('window failed'), message: 'window failed' }));
    const rejection = new Event('unhandledrejection') as Event & { reason?: unknown };
    rejection.reason = new Error('promise failed');
    window.dispatchEvent(rejection);
    expect(TestBed.inject(ErrorReporter).sent).toEqual(expect.arrayContaining(['window failed', 'promise failed']));
  });
});
----

The same handler also receives errors thrown inside an `effect()`, and a rejected `fetch` inside `report()` is swallowed
by its own `catch`, so reporting a failure can never raise another one.

=== Framework errors worth recognising

* `NG0201` -- no provider for a token. Provide it (`providedIn: 'root'`, `@Service()`, or a `providers` entry) in
  the injector the request starts from. See xref:web/angular/dependency-injection.adoc[Dependency Injection].
* `NG0203` -- `inject()` called outside an injection context, typically inside a callback that runs later.
* `NG0950` -- a required input or model was read before it had a value; read it in a template, `computed()`, or
  `effect()`.
* `NG0100` -- a bound value changed after Angular had already checked it in the same pass. In a test this shows up
  for components that opt into `ChangeDetectionStrategy.Eager`:
+
[source,typescript]
----
@Component({
  selector: 'app-after-view',
  template: `<p>{{ text }}</p>`,
  changeDetection: ChangeDetectionStrategy.Eager,
})
class AfterView {
  text = 'before';
  ngAfterViewInit(): void { this.text = 'after'; }   // changes a bound field after the view was checked
}
// handler receives: NG0100: ExpressionChangedAfterItHasBeenCheckedError: Expression has changed after it was
// checked. Previous value: 'before'. Current value: 'after'.
----
+
The same component with the default `OnPush` strategy raises *no* error, but the DOM keeps showing `before`: the
field was changed outside any signal or event, so Angular never refreshed the view. Both outcomes are the same bug --
state that Angular was not told about -- and the fix is the same: hold the value in a `signal()`.

=== Choosing where to handle a failure

[cols="1,2",options="header"]
|===
| Failure | Where to handle it

| A request failed and the screen can recover (retry, show cached data)
| `catchError` in the service or `resource.error()` in the component; show an inline message

| Every request needs the same treatment (401 redirect, token refresh, logging)
| a functional interceptor

| A lazy `@defer` chunk or route chunk failed to download
| the `@error` block of the `@defer`, or `withNavigationErrorHandler()` on `provideRouter` for route chunks

| A bug: something that should never happen
| the global `ErrorHandler`: report it, tell the user something went wrong, keep the app running
|===

== Surfacing and reporting errors

**To the user:** show a non-blocking toast/snackbar with a recoverable message -- never a stack trace. With
Angular Material:

[source,typescript]
----
import { inject } from '@angular/core';
import { MatSnackBar } from '@angular/material/snack-bar';

private readonly snackbar = inject(MatSnackBar);

private notify(err: Error): void {
  this.snackbar.open('Something went wrong. Please try again.', 'Dismiss', { duration: 5000 });
}
----

**To a backend:** POST the error (message, stack, URL, user agent, release version) to your logging endpoint or
a service such as Sentry. Send it with a plain `fetch` rather than `HttpClient`, so a failing report cannot
re-enter the interceptor above and loop.

[source,typescript]
----
import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class ErrorReporter {
  readonly sent: string[] = [];                 // lets tests assert on what was reported

  report(err: Error): void {
    this.sent.push(err.message);
    fetch('/api/client-errors', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message: err.message, stack: err.stack, url: location.href }),
      keepalive: true,
    }).catch(() => {
      /* reporting is best-effort -- never throw from here */
    });
  }
}
----

Keep reporting best-effort and side-effect-free on failure. See
https://angular.dev/best-practices/error-handling[Error handling] for the full guidance, and
xref:web/angular/testing.adoc[Testing] for asserting that the handler runs.

=== Testing the interceptor

Drive the interceptor with a real `HttpClient` against `HttpTestingController`, and replace `Router.navigate` with a spy so
the test asserts on the redirect:

[source,typescript]
----
beforeEach(() => TestBed.configureTestingModule({
  providers: [
    provideRouter([]),
    provideHttpClient(withInterceptors([errorInterceptor])),
    provideHttpClientTesting(),
  ],
}));

it('redirects 401 to /login with the return URL and still re-throws', () => {
  const router = TestBed.inject(Router);
  const navigate = vi.spyOn(router, 'navigate').mockResolvedValue(true);
  const http = TestBed.inject(HttpClient);
  const controller = TestBed.inject(HttpTestingController);

  let status = 0;
  http.get('/api/x').subscribe({ error: (e) => (status = e.status) });
  controller.expectOne('/api/x').flush('no', { status: 401, statusText: 'Unauthorized' });

  expect(status).toBe(401);
  expect(navigate).toHaveBeenCalledWith(['/login'], { queryParams: { returnUrl: router.url } });
});
----
