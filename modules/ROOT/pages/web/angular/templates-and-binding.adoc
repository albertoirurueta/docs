:description: Interpolation and the property, attribute, class, and style bindings; event binding and two-way binding; template reference variables, @let, pipes, safe navigation, and the template expression rules.
:keywords: Angular, templates, interpolation, property binding, attribute binding, class binding, style binding, event binding, two-way binding, ngModel, model signal, template reference variable, let, pipe operator, safe navigation, expression syntax

include::partial$ai-disclaimer.adoc[]

An Angular template is HTML with binding syntax. Bindings connect the DOM to component state: values flow from
the class into the view, and events flow from the view back into the class.

== Interpolation and one-way bindings

*Interpolation* -- `+{{ expression }}+` -- inserts a stringified value into text or an attribute value.
*Property binding* -- `+[property]="expression"+` -- sets a DOM *property* (not an attribute). Related forms
target attributes, classes, and inline styles:

[source,html]
----
<h1>{{ title() }}</h1>
<p>{{ user().firstName }} {{ user().lastName }}</p>

<img [src]="avatarUrl()" [alt]="user().name" />
<button [disabled]="form.invalid">Save</button>

<td [attr.colspan]="span()">…</td>             <!-- attribute binding: no matching DOM property -->

<div [class.active]="isActive()"></div>          <!-- single class toggle -->
<div [class]="classExpr()"></div>                 <!-- string / array / Record<string, boolean> -->

<div [style.width.px]="width()"></div>            <!-- style with a unit -->
<div [style]="styleExpr()"></div>                 <!-- string or Record<string, string> -->
----

Use `[attr.x]` when there is no DOM property to bind (`colspan`, `+aria-*+`, `+data-*+`, SVG attributes). See
https://angular.dev/guide/templates[Templates] and https://angular.dev/guide/templates/binding[binding].

== Event binding and two-way binding

*Event binding* -- `+(event)="statement"+` -- runs a template statement when the event fires; `$event` is the
event payload (a DOM `Event`, or the value a component `output()` emitted).

[source,html]
----
<button (click)="save()">Save</button>
<input (input)="onInput($event)" />
<div (keydown.escape)="close()"></div>          <!-- key modifier -->
<app-rating (rated)="setRating($event)" />       <!-- custom output event -->
----

*Two-way binding* -- `+[(target)]="expr"+`, the "banana in a box" -- is shorthand for a property binding plus an
event binding named `targetChange`. It works with `ngModel` on form elements and with any component that
exposes a `model()` signal.

[source,html]
----
<!-- with ngModel (needs FormsModule in the component's imports) -->
<input [(ngModel)]="searchTerm" />

<!-- with a model() signal on a custom component -->
<app-slider [(value)]="volume" />
----

[source,typescript]
----
import { Component, model } from '@angular/core';

@Component({ selector: 'app-slider', template: `…` })
export class Slider {
  readonly value = model<number>(0);   // enables [(value)] on <app-slider>
}
----

See https://angular.dev/guide/templates/event-listeners[event listeners] and
https://angular.dev/guide/templates/two-way-binding[two-way binding].

== Reference variables, @let, pipes, and operators

*Template reference variables* -- `#name` -- capture a DOM element or a component instance for use elsewhere in
the same template.

*`@let`* declares a local template variable from an expression; it is re-evaluated as its dependencies change
and is read-only.

[source,html]
----
<input #box (input)="search(box.value)" />
<video #player src="clip.mp4"></video>
<button (click)="player.play()">Play</button>

@let fullName = user().firstName + ' ' + user().lastName;
@let total = cart().reduce((sum, item) => sum + item.price, 0);
<p>{{ fullName }} owes {{ total | currency }}</p>
----

The *pipe operator* `|` transforms a value for display (`+{{ value | date:'short' }}+`); chain pipes
left-to-right. The *safe navigation* operator `?.` short-circuits to `null` when the left side is nullish
(`+{{ user()?.address?.city }}+`), and the *non-null assertion* `!` tells the type-checker a value is not
null (`+{{ user()!.name }}+`) without emitting any runtime check.

Template expressions are a restricted subset of JavaScript. *Not allowed*: assignments (except `=` inside an
event statement and `+[(...)]+`), `new`, `++` / `--`, bitwise operators, and chained statements with `;` (again,
except in event statements). Expressions must have no visible side effects and should stay cheap, because they
run on every change-detection pass. Angular also collapses runs of whitespace and removes whitespace between
elements unless you set `preserveWhitespaces`. See
https://angular.dev/guide/templates/variables[template variables],
https://angular.dev/guide/templates/expression-syntax[expression syntax], and
https://angular.dev/guide/templates/whitespace[whitespace].

== How the four binding directions work

[mermaid]
....
flowchart LR
    subgraph Class["Component class (state)"]
        S["signals and fields"]
        H["methods and output()"]
    end
    subgraph View["Rendered DOM"]
        P["DOM properties<br/>[value], [disabled], [src]"]
        A["attributes<br/>[attr.aria-label]"]
        C["classes and styles<br/>[class.x], [style.width.px]"]
        T["text nodes: interpolation"]
        E["DOM and component events"]
    end
    S -- "one-way" --> P
    S --> A
    S --> C
    S --> T
    E -- "(event)=statement" --> H
    S <-. "[(two-way)] = [x] + (xChange)" .-> E
....

Everything flows down through bindings that read the class, and everything flows back up through event bindings
that call into it. Two-way binding is nothing more than both arrows combined.

== A worked example: one template, every binding

The template below is the catalog's book card, exercised in a test that rendered it and fired the events. Each
comment records what the DOM contained afterwards. The component class is a few signals (`book`, `draft`, `onSale`,
`extra`, `width`, `html`, `qty`, `stars`, `last`, `submitted`, `cancelled`) and an `ngModel`-bound `name` field.

[source,html]
----
<h1>{{ book().title }}</h1>                                           <!-- Dune -->
<input [value]="draft()" />                                           <!-- DOM property: hello -->
<input [attr.data-id]="book().id" [attr.aria-label]="'Edit ' + book().title" />
                                                                      <!-- data-id="7" aria-label="Edit Dune" -->
<div class="card" [class.sale]="onSale()" [class]="extra()"></div>    <!-- class="card featured sale" -->
<div [style.width.px]="width()" [style.--accent]="'tomato'"></div>    <!-- style="width: 120px; --accent: tomato;" -->
<p>{{ book().author?.name ?? 'unknown author' }}</p>                  <!-- unknown author -->
<p>[{{ nothing }}] [{{ nul }}]</p>                                    <!-- [] [] : undefined and null render as empty text -->
<p [innerHTML]="html()"></p>                                          <!-- sanitised, see below -->
<p>{{ 2 ** 10 }} {{ typeof book().price }} {{ 'price' in book() }} {{ `#${book().id}: ${book().title}` }}</p>
                                                                      <!-- 1024 number true #7: Dune -->
@let total = book().price * qty();
@let label = total | currency:'EUR':'symbol':'1.2-2':'en-US';
<p>{{ qty() }} x {{ book().price }} = {{ label }}</p>                 <!-- 2 x 12.5 = €25.00, then 3 x 12.5 = €37.50 after qty changes -->

<input #box (keydown.control.enter)="submit(box.value)" (keydown.escape)="cancelled.set(true)" />
<button (click)="qty.set(qty() + 1); clicks.set(clicks() + 1)">inc</button>
<app-rating [(value)]="stars" />                                      <!-- model() two-way: 3 -> 4 after one click -->
<input [(ngModel)]="name" />                                          <!-- typing "bob" updates name -->
<app-picker [book]="book()" (picked)="last.set($event)" />            <!-- $event is the number emitted by output() -->
----

Points the run made concrete:

* **Property bindings write the DOM property only when the bound value changes.** After the user typed into the
  `value`-bound input, re-setting the signal to its old value `'hello'` did **not** overwrite the typed text, and the
  HTML `value` attribute stayed absent. Binding is a one-directional push of *changes*, not a continuous
  "make the DOM equal to the model".
* **`[class]` and `[class.x]` merge.** The static `class="card"`, the `[class]` string and the `[class.sale]` toggle
  all ended up on one element; Angular does not let one binding wipe the others.
* **Custom properties work with `[style.--name]`.** The `--accent` property above is set on the element itself, which
  is how a component hands dynamic values to its stylesheet (see
  xref:web/angular/styling-and-ui-libraries.adoc[Styling and UI libraries]).
* **`null` and `undefined` interpolate as empty strings**, not as the words `null` and `undefined`.
* **Key events accept modifiers.** `(keydown.control.enter)` fired for Ctrl+Enter but not for a bare Enter, while
  `(keydown.escape)` fired for Escape.
* **Several statements can share one event.** `(click)="a(); b()"` is allowed in an event binding and nowhere else.
* **`@let` is re-evaluated** whenever its inputs change: the label moved from `25.00` to `37.50` after `qty` went
  from 2 to 3, with no extra code.

=== Expression features added in recent releases

Template expressions gained several operators from the language, all shown above: the exponentiation operator `+**+`,
the `typeof` and `in` operators, and template literals (backtick strings with `+${...}+`). They compile like their
JavaScript counterparts; bitwise operators, `new`, and increment/decrement are still rejected.

== Security: what Angular does to bound values

Angular treats every value bound into the DOM as untrusted. Interpolation and `[property]` bindings are escaped, and
bindings that can carry code -- `[innerHTML]`, `[href]`, `[src]` on frames and scripts, `[style]` -- run through a
sanitizer for their *security context*. Binding the string
`<b>bold</b><img src="x" onerror="alert(1)"><script>alert(2)</script>` to `[innerHTML]` rendered, in the test:

[source,html]
----
<b>bold</b><img src="x">
----

The `<script>` element and the `onerror` handler were removed, and the console logged a warning that sanitizing stripped
some content. Two rules follow:

* Prefer plain interpolation to `[innerHTML]`; when you must render HTML from a user or an API, let the sanitizer
  run.
* `DomSanitizer.bypassSecurityTrustHtml()` (and its `Url`, `Style`, `Script` and `ResourceUrl` siblings) switches the
  protection off for that value. Use it only for content you generated yourself, never for anything that has touched user input.

Templates themselves are trusted code, so never build a template string from user input.

== Reference variables, `@let`, and the safe-navigation operator together

A template reference variable gives you the DOM element (or the component, or a directive via `#ref="exportAs"`),
and is visible anywhere in the same template, including inside `@if` and `@for` blocks nested within it. `@let` is
scoped to its block and below. Using the safe-navigation operator for values that may be absent and `??` for a
fallback keeps templates free of `+@if (x) { ... }+` wrappers for simple cases:

[source,html]
----
<input #search (input)="query.set(search.value)" placeholder="Search" />
<p>{{ result()?.book?.author?.name ?? 'No author' }}</p>
----

Prefer the signal-based forms of these (a `computed()` that returns the exact display string) when an expression
grows beyond one or two operators; keeping logic in the class keeps it testable. See
xref:web/angular/testing.adoc[Testing] for how to render a component and assert on its bindings.

For the DOM event model underneath event bindings -- bubbling, `preventDefault()`, the `Event` object -- see
xref:programming-languages/javascript/browser-events.adoc[browser events].
