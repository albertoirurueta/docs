https://material.angular.dev/[Angular Material] is the first-party Material Design component library, built on
the Angular CDK. This page covers installing and theming it, the components you reach for most, and the CDK
underneath. The broader survey of other UI libraries lives on
xref:web/angular/styling-and-ui-libraries.adoc[Styling and UI Libraries].

== Install and theme

`ng add` installs the packages, adds links for the Roboto font and the Material Symbols icon font to `index.html`,
and writes a starter theme into the global stylesheet. It asks which starter pair of palettes you want
(Azure/Blue, Rose/Red, Magenta/Violet, or Cyan/Orange) and needs no animation provider: Material no longer depends on
`@angular/animations`.

[source,bash]
----
ng add @angular/material
----

Theming uses the Sass `mat.theme` mixin with Material 3 design tokens. Put it in the global stylesheet; a
`light-dark()` color scheme gives you dark mode for free when the OS requests it.

[source,scss]
----
// src/styles.scss
@use '@angular/material' as mat;

html {
  color-scheme: light dark;

  @include mat.theme((
    color: (
      primary: mat.$violet-palette,
      tertiary: mat.$orange-palette,
    ),
    typography: Roboto,
    density: 0,
  ));
}

// component-level override
.dense-section {
  @include mat.form-field-density(-3);
}
----

Read component styles with `+mat.get-theme-color(...)+`, and see
https://material.angular.dev/guide/theming[the theming guide] and https://material.angular.dev/[the component
docs] for the full token list.

=== What `mat.theme` actually emits

The mixin does not generate component-specific CSS. It writes a set of CSS custom properties on the element where it is
included, and every Material component reads them with `+var(--mat-sys-...)+`. Building the theme above produces, among
about 165 `+--mat-sys-*+` properties on `html`:

[source,css]
----
html {
  color-scheme: light dark;
  --mat-sys-background: light-dark(#fef8fc, #151316);
  --mat-sys-primary:    light-dark(#7d00fa, #d5baff);
  --mat-sys-on-primary: light-dark(#ffffff, #42008a);
  --mat-sys-error:      light-dark(#ba1a1a, #ffb4ab);
  /* ... surfaces, outlines, state-layer opacities, typography scale, corner radii ... */
}
----

Each colour is a CSS `light-dark()` pair, resolved by the browser from `color-scheme`. That is why one declaration gives
light and dark themes: set `color-scheme: light`, `dark`, or `light dark` (follow the OS) on `html` or on a subtree, and
nothing else changes.

[mermaid]
....
flowchart TD
    PAL["Palettes: mat.$violet-palette, mat.$orange-palette"] --> THEME["mat.theme(...) mixin"]
    TYPO["typography: Roboto"] --> THEME
    DENS["density: 0"] --> THEME
    THEME --> SYS["System tokens on html: --mat-sys-primary, --mat-sys-body-large, --mat-sys-corner-medium ..."]
    SYS --> COMP["Component tokens: --mat-table-..., --mat-form-field-... read the system tokens by default"]
    OVR["mat.table-overrides(...), mat.form-field-density(...)"] --> COMP
    COMP --> UI["Rendered component"]
    SYS --> OWN["Your own CSS: var(--mat-sys-surface-container)"]
....

You can use the same system tokens in your own components, so custom UI follows the theme without a Sass dependency:

[source,scss]
----
.brand-card {
  background: var(--mat-sys-surface-container);
  color: var(--mat-sys-on-surface);
  border-radius: var(--mat-sys-corner-medium);
  font: var(--mat-sys-body-large);
}
----

*Overrides are scoped custom properties.* The `+*-overrides+` and density mixins emit a rule that sets component tokens
under the selector you include them in, so a change affects only that subtree:

[source,scss]
----
.books-table {
  @include mat.table-overrides((
    row-item-container-height: 40px,
    header-headline-color: var(--mat-sys-primary),
  ));
}
// compiles to:
// .books-table { --mat-table-row-item-container-height: 40px; --mat-table-header-headline-color: var(--mat-sys-primary); }

.dense-section {
  @include mat.form-field-density(-3);          // shrinks every form field inside this section
}
----

== Common components

Every Material component is standalone -- import the ones a template uses. A form with a field, a select, and a
checkbox:

[source,typescript]
----
import { Component } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import { MatFormFieldModule } from '@angular/material/form-field';
import { MatInputModule } from '@angular/material/input';
import { MatSelectModule } from '@angular/material/select';
import { MatCheckboxModule } from '@angular/material/checkbox';

@Component({
  selector: 'app-profile-form',
  imports: [
    ReactiveFormsModule, MatFormFieldModule, MatInputModule,
    MatSelectModule, MatCheckboxModule,
  ],
  templateUrl: './profile-form.html',
})
export class ProfileForm {
  readonly name = new FormControl('');
  readonly role = new FormControl('dev');
  readonly subscribe = new FormControl(false);
}
----

[source,html]
----
<mat-form-field>
  <mat-label>Name</mat-label>
  <input matInput [formControl]="name" />
</mat-form-field>

<mat-form-field>
  <mat-label>Role</mat-label>
  <mat-select [formControl]="role">
    <mat-option value="dev">Developer</mat-option>
    <mat-option value="pm">Product manager</mat-option>
  </mat-select>
</mat-form-field>

<mat-checkbox [formControl]="subscribe">Email me updates</mat-checkbox>
----

A datepicker needs a date adapter provider (`provideNativeDateAdapter()` in the app config) plus the module:

[source,html]
----
<mat-form-field>
  <mat-label>Starts</mat-label>
  <input matInput [matDatepicker]="picker" />
  <mat-datepicker-toggle matIconSuffix [for]="picker" />
  <mat-datepicker #picker />
</mat-form-field>
----

A sortable, paginated table is `MatTableDataSource` wired to `MatSort` and `MatPaginator`:

[source,typescript]
----
import { AfterViewInit, Component, viewChild } from '@angular/core';
import { MatTableDataSource, MatTableModule } from '@angular/material/table';
import { MatSort, MatSortModule } from '@angular/material/sort';
import { MatPaginator, MatPaginatorModule } from '@angular/material/paginator';

interface User { name: string; role: string; }

@Component({
  selector: 'app-user-table',
  imports: [MatTableModule, MatSortModule, MatPaginatorModule],
  templateUrl: './user-table.html',
})
export class UserTable implements AfterViewInit {
  readonly displayedColumns = ['name', 'role'];
  readonly dataSource = new MatTableDataSource<User>([
    { name: 'Ada', role: 'dev' },
    { name: 'Grace', role: 'pm' },
  ]);

  private readonly sort = viewChild.required(MatSort);
  private readonly paginator = viewChild.required(MatPaginator);

  ngAfterViewInit(): void {
    this.dataSource.sort = this.sort();
    this.dataSource.paginator = this.paginator();
  }
}
----

[source,html]
----
<table mat-table [dataSource]="dataSource" matSort>
  <ng-container matColumnDef="name">
    <th mat-header-cell *matHeaderCellDef mat-sort-header>Name</th>
    <td mat-cell *matCellDef="let u">{{ u.name }}</td>
  </ng-container>
  <ng-container matColumnDef="role">
    <th mat-header-cell *matHeaderCellDef mat-sort-header>Role</th>
    <td mat-cell *matCellDef="let u">{{ u.role }}</td>
  </ng-container>
  <tr mat-header-row *matHeaderRowDef="displayedColumns"></tr>
  <tr mat-row *matRowDef="let row; columns: displayedColumns"></tr>
</table>
<mat-paginator [pageSizeOptions]="[5, 10]" />
----

Dialogs and snackbars are opened from injected services; menus, tabs, and steppers are declared in the
template:

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { MatDialog } from '@angular/material/dialog';
import { MatSnackBar } from '@angular/material/snack-bar';
import { ConfirmDialog } from './confirm-dialog';

@Component({ selector: 'app-toolbar', templateUrl: './toolbar.html' })
export class Toolbar {
  private readonly dialog = inject(MatDialog);
  private readonly snackBar = inject(MatSnackBar);

  remove(): void {
    this.dialog.open(ConfirmDialog).afterClosed().subscribe((ok) => {
      if (ok) this.snackBar.open('Removed', 'Undo', { duration: 5000 });
    });
  }
}
----

== The CDK

The https://material.angular.dev/cdk/categories[Component Dev Kit] is the unstyled behaviour Material is built
on, usable on its own:

* *Overlay* -- position a floating panel (tooltips, custom dropdowns) in a managed layer.
* *Portal* -- render a component or template into an `Overlay` or any other outlet.
* *a11y* -- `LiveAnnouncer` for screen-reader announcements, `cdkTrapFocus` / `FocusTrap` to contain focus,
  `FocusMonitor` to observe focus origin.
* *Layout* -- `BreakpointObserver` to react to media queries as observables or signals.
* *Drag and drop* -- `cdkDrag` / `cdkDropList` with sorting and transfer between lists.
* *Scrolling* -- `<cdk-virtual-scroll-viewport>` renders only the visible rows of a large list.

[source,typescript]
----
import { Component } from '@angular/core';
import { CdkDrag, CdkDropList, CdkDragDrop, moveItemInArray } from '@angular/cdk/drag-drop';
import { ScrollingModule } from '@angular/cdk/scrolling';

@Component({
  selector: 'app-reorder',
  imports: [CdkDropList, CdkDrag, ScrollingModule],
  template: `
    <cdk-virtual-scroll-viewport itemSize="40" style="height: 300px">
      <div
        cdkDropList
        (cdkDropListDropped)="drop($event)">
        <div *cdkVirtualFor="let item of items" cdkDrag>{{ item }}</div>
      </div>
    </cdk-virtual-scroll-viewport>
  `,
})
export class Reorder {
  items = Array.from({ length: 1000 }, (_, i) => `Item ${i}`);

  drop(event: CdkDragDrop<string[]>): void {
    moveItemInArray(this.items, event.previousIndex, event.currentIndex);
  }
}
----

== Accessibility of interactive components

Material components ship keyboard support and ARIA roles, but the wiring around them is still yours: give every
`mat-form-field` a `mat-label` or `aria-label`, set an accessible name on icon-only buttons, keep focus inside
an open `MatDialog` and return it to the trigger on close, and announce out-of-band changes with
`LiveAnnouncer`. Test every flow with the keyboard and a screen reader, and honour `prefers-reduced-motion`
when adding your own animations.

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { LiveAnnouncer } from '@angular/cdk/a11y';

@Component({
  selector: 'app-cart',
  template: `<button mat-button aria-label="Add to cart" (click)="add()">Add</button>`,
})
export class Cart {
  private readonly announcer = inject(LiveAnnouncer);
  add(): void {
    this.announcer.announce('Added to cart', 'polite');
  }
}
----

See xref:web/accessibility.adoc[Web Accessibility] for conformance levels and validation tools, and
https://material.angular.dev/cdk/a11y/overview[the CDK a11y overview] for the helpers above.

== Deep dive: the BookShelf catalogue table

The table, form field, dialog, and snack bar combine into a typical admin screen: filter the list, sort and page it, and
confirm a removal. Every piece is a standalone import.

[source,typescript]
----
@Component({
  selector: 'app-confirm-dialog',
  imports: [MatDialogModule, MatButtonModule],
  template: `
    <h2 mat-dialog-title>Remove book?</h2>
    <mat-dialog-actions>
      <button mat-button [mat-dialog-close]="false">Cancel</button>
      <button mat-flat-button [mat-dialog-close]="true" class="confirm">Remove</button>
    </mat-dialog-actions>
  `,
})
export class ConfirmDialog {}

@Component({
  selector: 'app-book-table',
  imports: [MatTableModule, MatSortModule, MatPaginatorModule, MatButtonModule, MatFormFieldModule, MatInputModule],
  template: `
    <mat-form-field>
      <mat-label>Filter</mat-label>
      <input matInput (input)="applyFilter($event)" />
    </mat-form-field>

    <table mat-table [dataSource]="dataSource" matSort class="books-table">
      <ng-container matColumnDef="title">
        <th mat-header-cell *matHeaderCellDef mat-sort-header>Title</th>
        <td mat-cell *matCellDef="let b">{{ b.title }}</td>
      </ng-container>
      <ng-container matColumnDef="price">
        <th mat-header-cell *matHeaderCellDef mat-sort-header>Price</th>
        <td mat-cell *matCellDef="let b">{{ b.price }}</td>
      </ng-container>
      <ng-container matColumnDef="actions">
        <th mat-header-cell *matHeaderCellDef></th>
        <td mat-cell *matCellDef="let b">
          <button mat-icon-button class="remove" aria-label="Remove book" (click)="remove(b)">x</button>
        </td>
      </ng-container>
      <tr mat-header-row *matHeaderRowDef="columns"></tr>
      <tr mat-row *matRowDef="let row; columns: columns"></tr>
    </table>
    <mat-paginator [pageSizeOptions]="[2, 10]" [pageSize]="2" />
  `,
})
export class BookTable implements AfterViewInit {
  readonly columns = ['title', 'price', 'actions'];
  readonly dataSource = new MatTableDataSource<Book>([...SAMPLE_BOOKS]);
  private readonly sort = viewChild.required(MatSort);
  private readonly paginator = viewChild.required(MatPaginator);
  private readonly dialog = inject(MatDialog);
  private readonly snackBar = inject(MatSnackBar);

  ngAfterViewInit(): void {
    this.dataSource.sort = this.sort();
    this.dataSource.paginator = this.paginator();
  }

  applyFilter(event: Event): void {
    this.dataSource.filter = (event.target as HTMLInputElement).value.trim().toLowerCase();
  }

  remove(book: Book): void {
    this.dialog.open(ConfirmDialog).afterClosed().subscribe((ok) => {
      if (ok) {
        this.dataSource.data = this.dataSource.data.filter((b) => b.id !== book.id);
        this.snackBar.open('Removed', 'Undo', { duration: 5000 });
      }
    });
  }
}
----

`MatTableDataSource` is what makes the table interactive: assigning `sort` and `paginator` in `ngAfterViewInit` (when the
view queries are resolved) connects header clicks and page changes, and setting `filter` filters every column's text
representation. Replacing `dataSource.data` re-renders the current page.

=== Testing with component harnesses

A *harness* is a test API for a Material component that hides its DOM structure: tests say "sort by Price" or "click the
Remove button" rather than querying CSS classes that can change between releases. Component harnesses come from
`@angular/material/<component>/testing` and run on `TestbedHarnessEnvironment`:

[source,typescript]
----
describe('book table', () => {
  let loader: HarnessLoader;
  let rootLoader: HarnessLoader;

  beforeEach(async () => {
    const fixture = TestBed.createComponent(BookTable);
    await fixture.whenStable();
    loader = TestbedHarnessEnvironment.loader(fixture);               // elements inside the component
    rootLoader = TestbedHarnessEnvironment.documentRootLoader(fixture); // overlays: dialogs, snack bars
  });

  it('pages, sorts and filters the table', async () => {
    const table = await loader.getHarness(MatTableHarness);
    expect((await table.getRows()).length).toBe(2);                    // pageSize 2
    const paginator = await loader.getHarness(MatPaginatorHarness);
    expect(await paginator.getRangeLabel()).toBe('1 \u2013 2 of 3');

    const sort = await loader.getHarness(MatSortHarness);
    const [price] = await sort.getSortHeaders({ label: 'Price' });
    await price.click();
    await price.click();                                               // second click: descending
    const cells = await table.getCellTextByColumnName();
    expect(cells['title'].text).toEqual(['Pro Angular', 'Modern Angular']);

    const filter = await loader.getHarness(MatInputHarness);
    await filter.setValue('learning');
    expect((await table.getRows()).length).toBe(1);
  });

  it('confirms in a dialog, then shows a snack bar', async () => {
    const removeButtons = await loader.getAllHarnesses(MatButtonHarness.with({ selector: '.remove' }));
    await removeButtons[0].click();
    const dialog = await rootLoader.getHarness(MatDialogHarness);       // dialogs live outside the component
    await (await dialog.getHarness(MatButtonHarness.with({ text: 'Remove' }))).click();

    const bar = await vi.waitFor(() => rootLoader.getHarness(MatSnackBarHarness));
    expect(await bar.getMessage()).toBe('Removed');
    expect(await bar.getActionDescription()).toBe('Undo');
  });
});
----

Two details are worth knowing. Dialogs and snack bars render in the CDK overlay container, outside the component's own DOM,
so they are found with `documentRootLoader`, not `loader`. And in jsdom the dialog closes through a timer, so the snack bar
appears slightly after the click; `vi.waitFor()` retries until it does, where a fixed sleep would be fragile. The same
harness classes work unchanged against a real browser in end-to-end tests.
