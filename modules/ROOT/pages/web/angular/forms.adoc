= Forms
:description: Template-driven and reactive forms in Angular -- ngModel and ngForm, strictly typed FormGroup, FormArray and FormBuilder, reading and reacting to control state, synchronous, asynchronous and cross-field validation, custom controls with ControlValueAccessor, dynamic forms, and Signal Forms.
:keywords: Angular forms, template-driven forms, reactive forms, ngModel, ngForm, NgModelGroup, FormControl, FormGroup, FormArray, FormBuilder, typed forms, nonNullable, Validators, ValidatorFn, AsyncValidatorFn, cross-field validation, ControlValueAccessor, dynamic forms, Signal Forms

include::partial$ai-disclaimer.adoc[]

Angular ships two ways to build forms. **Template-driven** forms keep the model in the template and suit small,
simple forms; **reactive** forms declare an explicit, strongly typed model in the component class and scale to
complex, dynamic, and heavily validated forms. A third API, **Signal Forms**, models the form as a signal.
See https://angular.dev/guide/forms[Forms].

[mermaid]
....
flowchart TD
    S["New form"] --> Q1{"Existing code or libraries built on FormControl and ControlValueAccessor?"}
    Q1 -->|"yes"| R["Reactive forms"]
    Q1 -->|"no"| Q2{"Is the form a handful of fields with simple rules?"}
    Q2 -->|"yes, and the model is a plain object you already have"| T["Template-driven forms"]
    Q2 -->|"no, or you want signals end to end"| SF["Signal Forms"]
    R --> N["Typed groups, arrays, async validators, a mature ecosystem"]
    T --> N2["Least code: ngModel and a plain object"]
    SF --> N3["The model is a signal; state and validation are signals too"]
....

All three coexist in one application, and a Signal Forms field can bind to a component that implements
`ControlValueAccessor`, so the choice can be made form by form.

== Template-driven forms

Import `FormsModule`. `ngModel` binds a field to a property, `ngForm` is applied automatically to every
`<form>` and tracks the aggregate state, and `ngModelGroup` nests a set of fields. Every control needs a
`name`.

[source,typescript]
----
import { Component } from '@angular/core';
import { FormsModule, NgForm } from '@angular/forms';

@Component({
  selector: 'app-signup',
  imports: [FormsModule],
  templateUrl: './signup.html',
})
export class Signup {
  model = { email: '', address: { city: '', zip: '' } };

  submit(form: NgForm): void {
    if (form.valid) {
      console.log(this.model);
    }
  }
}
----

[source,html]
----
<form #form="ngForm" (ngSubmit)="submit(form)">
  <input name="email" [(ngModel)]="model.email" required email #email="ngModel" />
  @if (email.invalid && email.touched) {
    <p class="error">A valid email is required.</p>
  }

  <fieldset ngModelGroup="address">
    <input name="city" [(ngModel)]="model.address.city" required />
    <input name="zip" [(ngModel)]="model.address.zip" pattern="\d{5}" />
  </fieldset>

  <button type="submit" [disabled]="form.invalid">Sign up</button>
</form>
----

`[(ngModel)]` is the "banana-in-a-box" shorthand for `[ngModel]` plus `(ngModelChange)`. Export a control as a
local template variable (`#email="ngModel"`) to read its `valid` / `touched` / `errors` in the template. See
https://angular.dev/guide/forms/template-driven-forms[Template-driven forms].

== Reactive forms

Import `ReactiveFormsModule`. Build the model from `FormControl`, `FormGroup`, and `FormArray`, then bind it
with `[formGroup]`, `formControlName`, `formGroupName`, and `formArrayName`.

[source,typescript]
----
import { Component } from '@angular/core';
import {
  FormControl, FormGroup, FormArray,
  ReactiveFormsModule, Validators,
} from '@angular/forms';

@Component({
  selector: 'app-profile',
  imports: [ReactiveFormsModule],
  templateUrl: './profile.html',
})
export class Profile {
  readonly form = new FormGroup({
    name: new FormControl('', { nonNullable: true, validators: [Validators.required] }),
    email: new FormControl('', {
      nonNullable: true,
      validators: [Validators.required, Validators.email],
    }),
    address: new FormGroup({
      street: new FormControl('', { nonNullable: true }),
      city: new FormControl('', { nonNullable: true }),
    }),
    tags: new FormArray<FormControl<string>>([]),
  });

  addTag(): void {
    this.form.controls.tags.push(new FormControl('', { nonNullable: true }));
  }

  save(): void {
    if (this.form.valid) {
      console.log(this.form.getRawValue());
    }
  }
}
----

[source,html]
----
<form [formGroup]="form" (ngSubmit)="save()">
  <input formControlName="name" />

  <fieldset formGroupName="address">
    <input formControlName="street" />
    <input formControlName="city" />
  </fieldset>

  <div formArrayName="tags">
    @for (tag of form.controls.tags.controls; track $index) {
      <input [formControlName]="$index" />
    }
  </div>
  <button type="button" (click)="addTag()">Add tag</button>
</form>
----

See https://angular.dev/guide/forms/reactive-forms[Reactive forms].

=== FormBuilder

`FormBuilder` is a terser factory. Its `nonNullable` variant applies `+{ nonNullable: true }+` to every control
in the group.

[source,typescript]
----
import { inject } from '@angular/core';
import { FormBuilder, Validators } from '@angular/forms';

private readonly fb = inject(FormBuilder);

readonly form = this.fb.nonNullable.group({
  name: ['', Validators.required],
  email: ['', [Validators.required, Validators.email]],
  address: this.fb.nonNullable.group({
    street: [''],
    city: [''],
  }),
  tags: this.fb.array<string>([]),
});
----

=== Strictly typed forms

Since Angular 14 reactive forms are **typed by default**. `form.value` is a partial view of the model
(disabled controls are omitted), while `form.getRawValue()` returns the complete type. `form.controls.name` is
a `FormControl<string | null>` unless you pass `+{ nonNullable: true }+`, which changes the type to `string` and
makes `reset()` restore the initial value instead of `null`. Reach for `UntypedFormGroup` /
`UntypedFormControl` only while migrating an old codebase. See
https://angular.dev/guide/forms/typed-forms[Typed forms].

== Reading and reacting to state

Every `AbstractControl` exposes a snapshot and a matching stream:

[cols="1,3",options="header"]
|===
| Member | Meaning

| `value` / `valueChanges` | current value / `Observable` that emits on every change
| `status` / `statusChanges` | `VALID` / `INVALID` / `PENDING` / `DISABLED`, and its stream
| `dirty` / `pristine` | whether the user has changed the value
| `touched` / `untouched` | whether the control has been blurred
| `errors` | the validation-errors map, or `null`
|===

[source,typescript]
----
import { takeUntilDestroyed, toSignal } from '@angular/core/rxjs-interop';
import { debounceTime } from 'rxjs';

constructor() {
  this.form.controls.email.valueChanges
    .pipe(debounceTime(300), takeUntilDestroyed())
    .subscribe((email) => this.lookup(email));
}

// Or expose the status as a signal:
readonly status = toSignal(this.form.statusChanges, { initialValue: this.form.status });
----

Write values with `setValue` (needs the **complete** shape), `patchValue` (accepts a partial), and `reset`
(clears to the initial value or `null` and restores `pristine` / `untouched`). Change a group's shape at
runtime with `addControl` / `removeControl` / `setControl`, and a `FormArray` with `push` / `insert` /
`removeAt`. See https://angular.dev/api/forms/AbstractControl[`AbstractControl`].

== Validation

Built-in https://angular.dev/api/forms/Validators[`Validators`]: `required`, `requiredTrue`, `min`, `max`,
`minLength`, `maxLength`, `pattern`, `email`, and `Validators.compose`. Attach them at construction or later
with `setValidators` / `addValidators`, followed by `updateValueAndValidity()`.

=== Custom synchronous validator

A `ValidatorFn` receives a control and returns an errors object or `null`.

[source,typescript]
----
import { AbstractControl, ValidationErrors, ValidatorFn } from '@angular/forms';

export function forbiddenName(pattern: RegExp): ValidatorFn {
  return (control: AbstractControl): ValidationErrors | null =>
    pattern.test(control.value) ? { forbiddenName: { value: control.value } } : null;
}

// name: new FormControl('', [Validators.required, forbiddenName(/admin/i)])
----

=== Cross-field validation

Put the validator on the **group** so it can compare siblings.

[source,typescript]
----
const passwordsMatch: ValidatorFn = (group: AbstractControl): ValidationErrors | null => {
  const pw = group.get('password')?.value;
  const confirm = group.get('confirm')?.value;
  return pw === confirm ? null : { passwordsMismatch: true };
};

readonly form = new FormGroup({
  password: new FormControl('', { nonNullable: true }),
  confirm: new FormControl('', { nonNullable: true }),
}, { validators: passwordsMatch });
----

=== Asynchronous validator

An `AsyncValidatorFn` returns a `Promise` or `Observable` that completes with the errors object or `null`; the
control's status stays `PENDING` until it settles.

[source,typescript]
----
import { AsyncValidatorFn } from '@angular/forms';
import { map, first } from 'rxjs';

export function uniqueEmail(api: UserApi): AsyncValidatorFn {
  return (control) =>
    api.exists(control.value).pipe(
      map((taken) => (taken ? { emailTaken: true } : null)),
      first(),
    );
}

// email: new FormControl('', {
//   validators: [Validators.required, Validators.email],
//   asyncValidators: [uniqueEmail(inject(UserApi))],
// })
----

Angular mirrors control state onto the host element as classes -- `ng-valid` / `ng-invalid`,
`ng-pristine` / `ng-dirty`, `ng-touched` / `ng-untouched`, and `ng-pending` -- so error styling needs no
template logic:

[source,scss]
----
input.ng-invalid.ng-touched {
  border-color: crimson;
}
----

See https://angular.dev/guide/forms/form-validation[Form validation].

== Custom form controls

Implement `ControlValueAccessor` so a component participates in `formControlName` / `ngModel` like a native
input, and register it through the `NG_VALUE_ACCESSOR` multi-provider.

[source,typescript]
----
import { Component, forwardRef, signal } from '@angular/core';
import { ControlValueAccessor, NG_VALUE_ACCESSOR } from '@angular/forms';

@Component({
  selector: 'app-star-rating',
  template: `
    @for (star of stars; track star) {
      <button type="button" (click)="pick(star)" [disabled]="disabled()">
        {{ star <= value() ? '★' : '☆' }}
      </button>
    }
  `,
  providers: [
    { provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => StarRating), multi: true },
  ],
})
export class StarRating implements ControlValueAccessor {
  readonly stars = [1, 2, 3, 4, 5];
  readonly value = signal(0);
  readonly disabled = signal(false);

  private onChange: (v: number) => void = () => {};
  private onTouched: () => void = () => {};

  writeValue(v: number): void { this.value.set(v ?? 0); }
  registerOnChange(fn: (v: number) => void): void { this.onChange = fn; }
  registerOnTouched(fn: () => void): void { this.onTouched = fn; }
  setDisabledState(isDisabled: boolean): void { this.disabled.set(isDisabled); }

  pick(v: number): void {
    this.value.set(v);
    this.onChange(v);
    this.onTouched();
  }
}
----

See https://angular.dev/api/forms/ControlValueAccessor[`ControlValueAccessor`].

== Dynamic forms

Build controls from data -- for example a field schema fetched from the server -- by iterating a config array
and assembling a `FormGroup` at runtime, then rendering it with `@for` over the same config. See
https://angular.dev/guide/forms/dynamic-forms[Dynamic forms].

[source,typescript]
----
interface FieldConfig { key: string; label: string; required?: boolean; }

buildForm(config: FieldConfig[]): FormGroup {
  const group: Record<string, FormControl<string>> = {};
  for (const field of config) {
    group[field.key] = new FormControl('', {
      nonNullable: true,
      validators: field.required ? [Validators.required] : [],
    });
  }
  return new FormGroup(group);
}
----

== Signal Forms

Signal Forms (`@angular/forms/signals`) is the signal-native forms API, stable in the current release. The *model* is an
ordinary `signal()` holding a plain object; `form()` wraps it in a tree of fields, and each field exposes its state --
`value`, `errors`, `valid`, `touched`, `dirty`, `pending`, `disabled` -- as signals. Validation rules are declared once,
in a schema function, against paths into the model.

[source,typescript]
----
import { Component, signal } from '@angular/core';
import { FormField, FormRoot, form, min, minLength, required, validate } from '@angular/forms/signals';

interface BookModel { title: string; price: number; discount: number; }

@Component({
  selector: 'app-signal-book-form',
  imports: [FormField, FormRoot],
  template: `
    <form [formRoot]="bookForm">
      <input [formField]="bookForm.title" />
      @for (e of bookForm.title().errors(); track e.kind) {
        <p class="error">{{ e.message }}</p>
      }
      <input type="number" [formField]="bookForm.price" />
      <input type="number" [formField]="bookForm.discount" />
      @for (e of bookForm.discount().errors(); track e.kind) {
        <p class="error">{{ e.message }}</p>
      }
      <button type="submit" [disabled]="!bookForm().valid()">Save</button>
    </form>
  `,
})
export class SignalBookForm {
  readonly model = signal<BookModel>({ title: '', price: 0, discount: 0 });
  readonly saved = signal<BookModel[]>([]);

  readonly bookForm = form(
    this.model,
    (path) => {
      required(path.title, { message: 'Title is required.' });
      minLength(path.title, 3, { message: 'At least 3 characters.' });
      min(path.price, 0);
      validate(path.discount, (ctx) =>
        ctx.value() > ctx.valueOf(path.price)
          ? { kind: 'discountTooHigh', message: 'Discount exceeds the price.' }
          : undefined,
      );
    },
    {
      submission: {
        action: async (f) => {
          this.saved.update((list) => [...list, f().value()]);
        },
      },
    },
  );
}
----

How the pieces fit together:

* `[formField]="bookForm.title"` binds a field to a native input, a signal-forms custom control, or (for compatibility)
  a `ControlValueAccessor` component. The binding is two-way: typing updates `model()`, and `+model.set(...)+` updates the
  input. The model is the single source of truth, so there is no second copy to keep in sync.
* `bookForm.title()` returns the field's *state*; `bookForm.title().value()` is the value signal and
  `bookForm.title().errors()` is a list of `+{ kind, message }+` objects. `bookForm()` is the root state, so
  `bookForm().valid()` summarises the whole form.
* The schema function runs once. `required`, `minLength`, `min`, `pattern`, and `email` are built in; `validate` takes any
  function that returns an error object or `undefined`. Because `ctx.valueOf(path.price)` reads another field, a rule can
  compare siblings, which is how cross-field validation works without a group-level validator.
* `[formRoot]` on the `<form>` element sets `novalidate`, cancels the browser's own submission, and calls the
  `submission.action` you configured -- only when the form is valid. Errors returned from the action are attached to the
  fields they name.

A custom control no longer needs `NG_VALUE_ACCESSOR`: it implements the `FormValueControl` interface, whose only
required member is a `model()` named `value`. Optional inputs such as `disabled` are kept in sync automatically.

[source,typescript]
----
import { Component, input, model } from '@angular/core';
import { FormValueControl } from '@angular/forms/signals';

@Component({
  selector: 'app-signal-star-rating',
  template: `
    @for (star of stars; track star) {
      <button type="button" [disabled]="disabled()" (click)="value.set(star)">{{ star <= value() ? '\u2605' : '\u2606' }}</button>
    }
  `,
})
export class SignalStarRating implements FormValueControl<number> {
  readonly value = model(0);
  readonly disabled = input(false);
  readonly stars = [1, 2, 3, 4, 5];
}

// <app-signal-star-rating [formField]="bookForm.rating" />
----

Compare this with the `ControlValueAccessor` version earlier on this page: no `writeValue` / `registerOnChange`
plumbing, no provider, and the value is a signal the component can compute from.

== The reactive-form model tree

[mermaid]
....
graph TD
    FG["FormGroup — form"]
    FG --> NAME["FormControl — name"]
    FG --> EMAIL["FormControl — email"]
    FG --> ADDR["FormGroup — address"]
    ADDR --> STREET["FormControl — street"]
    ADDR --> CITY["FormControl — city"]
    FG --> TAGS["FormArray — tags"]
    TAGS --> T0["FormControl — index 0"]
    TAGS --> T1["FormControl — index 1"]
....

A `FormGroup` keys its children by name; a `FormArray` indexes them; both can nest arbitrarily. `value`,
`status`, `dirty`, and `touched` aggregate upward from the leaves to the root control. Cross-links:
xref:web/angular/signals.adoc[Signals] for `toSignal` bridging, xref:web/angular/http-client.adoc[HTTP Client]
for submitting form data, and xref:web/angular/error-handling.adoc[Error Handling] for reporting failed
submissions.

== Deep dive: the BookShelf form with reactive forms

This is a complete reactive form that combines the validators above: a required title, an ISBN checked against a registry
asynchronously, a cross-field rule between price and discount, and a dynamic list of authors. Each control is
non-nullable, so `getRawValue()` is fully typed.

[source,typescript]
----
@Injectable({ providedIn: 'root' })
export class IsbnRegistry {                                  // stand-in for a call to the catalogue API
  private readonly taken = new Set(['978-0000000001']);
  exists(isbn: string): Observable<boolean> { return of(this.taken.has(isbn)); }
}

export const discountWithinPrice: ValidatorFn = (group: AbstractControl): ValidationErrors | null => {
  const price = group.get('price')?.value as number;
  const discount = group.get('discount')?.value as number;
  return discount > price ? { discountTooHigh: { price, discount } } : null;
};

export function uniqueIsbn(registry: IsbnRegistry, debounce = 300): AsyncValidatorFn {
  return (control) =>
    timer(debounce).pipe(                                   // debounce: a new keystroke unsubscribes this run
      switchMap(() => registry.exists(control.value)),
      map((taken) => (taken ? { isbnTaken: true } : null)),
    );
}

@Component({
  selector: 'app-book-form',
  imports: [ReactiveFormsModule],
  template: `
    <form [formGroup]="form" (ngSubmit)="save()">
      <input formControlName="title" />
      @if (form.controls.title.touched && form.controls.title.errors?.['required']) {
        <p class="error">Title is required.</p>
      }
      <input formControlName="isbn" />
      @if (form.controls.isbn.pending) { <p class="pending">Checking...</p> }
      @if (form.controls.isbn.hasError('isbnTaken')) { <p class="error">ISBN already registered.</p> }
      <input formControlName="price" type="number" />
      <input formControlName="discount" type="number" />
      @if (form.hasError('discountTooHigh')) { <p class="error">Discount exceeds the price.</p> }

      <div formArrayName="authors">
        @for (author of form.controls.authors.controls; track $index) {
          <input [formControlName]="$index" class="author" />
        }
      </div>
      <button type="button" class="add" (click)="addAuthor()">Add author</button>
      <button type="submit" [disabled]="form.invalid || form.pending">Save</button>
    </form>
  `,
})
export class BookForm {
  private readonly fb = inject(NonNullableFormBuilder);
  readonly registry = inject(IsbnRegistry);
  readonly saved = output<unknown>();

  readonly form = this.fb.group(
    {
      title: ['', [Validators.required, Validators.minLength(3)]],
      isbn: ['', { validators: [Validators.pattern(/^978-\d{10}$/)], asyncValidators: [uniqueIsbn(this.registry)] }],
      price: [0, [Validators.min(0)]],
      discount: [0, [Validators.min(0)]],
      authors: this.fb.array([this.fb.control('', Validators.required)]),
    },
    { validators: [discountWithinPrice] },
  );

  addAuthor(): void { this.form.controls.authors.push(this.fb.control('', Validators.required)); }

  save(): void {
    if (this.form.invalid || this.form.pending) {           // both: see the note on PENDING below
      this.form.markAllAsTouched();
      return;
    }
    this.saved.emit(this.form.getRawValue());
  }
}
----

=== The validation pipeline

Every time a value changes, a control recomputes its status in a fixed order, and the result bubbles up to its parents:

[mermaid]
....
flowchart TD
    V["Value changes: setValue, patchValue, or user input"] --> SYNC["Run synchronous validators"]
    SYNC --> OK{"Sync errors?"}
    OK -->|"yes"| INV["status = INVALID, async validators are skipped"]
    OK -->|"no"| ASYNC["Run async validators; status = PENDING"]
    ASYNC --> DONE{"Observable emits"}
    DONE -->|"errors object"| INV2["status = INVALID"]
    DONE -->|"null"| VAL["status = VALID"]
    INV --> UP["Recompute the parent group: its own validators, then children"]
    INV2 --> UP
    VAL --> UP
....

The ISBN control shows the sequence. Setting `+'bad'+` fails the `pattern` validator, so `statusChanges` emits `INVALID`
and the registry is never called; setting `+'978-0000000001'+` passes it, so `statusChanges` emits `PENDING`, and 300 ms later
`INVALID` again with `+{ isbnTaken: true }+`. Because each new value cancels the previous async subscription, a `timer()`
at the head of the validator is a debounce for free.

NOTE: A group's status is `PENDING` as soon as *any* descendant is pending, even if another child is already `INVALID`:
the group checks its own errors first, then `PENDING`, then `INVALID`. A form whose title is empty can therefore report
`pending` rather than `invalid` while the ISBN is being checked, which is why the submit handler and the button test
`form.invalid || form.pending` rather than `form.invalid` alone.

=== Testing the form

[source,typescript]
----
beforeEach(() => {
  TestBed.configureTestingModule({ providers: [IsbnRegistry] });
  vi.useFakeTimers();                       // lets the test step the 300 ms debounce deterministically
});
afterEach(() => vi.useRealTimers());

it('runs sync validators, then async with PENDING, then settles', () => {
  const fixture = TestBed.createComponent(BookForm);
  const form = fixture.componentInstance.form;
  const statuses: string[] = [];
  form.controls.isbn.statusChanges.subscribe((s) => statuses.push(s));

  form.controls.isbn.setValue('bad');
  expect(form.controls.isbn.errors).toHaveProperty('pattern');
  expect(statuses).toEqual(['INVALID']);                 // async skipped

  statuses.length = 0;
  form.controls.isbn.setValue('978-0000000001');
  expect(statuses).toEqual(['PENDING']);
  vi.advanceTimersByTime(300);
  expect(statuses).toEqual(['PENDING', 'INVALID']);
  expect(form.controls.isbn.errors).toEqual({ isbnTaken: true });
});

it('applies the group validator', () => {
  const form = TestBed.createComponent(BookForm).componentInstance.form;
  form.patchValue({ title: 'Angular', price: 10, discount: 20 });
  expect(form.errors).toEqual({ discountTooHigh: { price: 10, discount: 20 } });
  form.patchValue({ discount: 5 });
  expect(form.errors).toBeNull();
});

=== More control-state details

* **`updateOn`.** `+new FormControl('', { updateOn: 'blur' })+` (or on a whole group) delays the model update and validation
  until blur or submit, which avoids validating half-typed input. `setValue` still updates immediately.
* **Disabled controls.** A disabled control is excluded from the group's `value` but kept in `getRawValue()`, and a group
  whose *children are all disabled* is itself disabled, so its `value` falls back to the full object.
* **`reset()`.** A `nonNullable` control resets to its initial value; a nullable one resets to `null`.
* **`FormRecord`.** A group whose keys are not known at compile time, such as a set of feature toggles:
  `+new FormRecord<FormControl<boolean>>({})+`, then `+addControl(key, ...)+`.
* **The unified `events` stream.** `control.events` emits `ValueChangeEvent`, `StatusChangeEvent`, `PristineChangeEvent`,
  `TouchedChangeEvent`, and `FormSubmittedEvent`/`FormResetEvent` on groups, as typed objects. Calling `+setValue('a')+` and then
  `markAsTouched()` on a control emits `ValueChangeEvent`, `StatusChangeEvent`, `TouchedChangeEvent` in that order, so one
  subscription replaces the several `+*Changes+` observables.
