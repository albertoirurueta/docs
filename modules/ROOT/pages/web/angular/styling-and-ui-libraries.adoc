= Styling and UI Libraries
:description: Styling an Angular app with scoped component styles and view encapsulation, Sass, Tailwind CSS and CSS custom properties, the main free and open-source component libraries (Angular Material, PrimeNG, ng-bootstrap, NG-ZORRO, Taiga UI, spartan/ui, the CDK), the commercial suites, and accessibility.
:keywords: Angular styling, component styles, view encapsulation, host, ng-deep, Sass, Tailwind CSS, CSS custom properties, NgClass, NgStyle, Angular Material, PrimeNG, ng-bootstrap, ngx-bootstrap, NG-ZORRO, Taiga UI, spartan/ui, Clarity, Nebular, Angular CDK, Kendo UI, Ignite UI, Syncfusion, AG Grid

include::partial$ai-disclaimer.adoc[]

Angular scopes styles to a component by default, so most of an app's CSS lives next to the component it styles.
This page covers the built-in styling options and then surveys the component libraries -- free and open-source
first, commercial suites last.

== Styling options

=== Component styles and view encapsulation

Styles listed in `styles` (inline) or `styleUrl` / `styleUrls` (files) are *scoped to the component*.
`ViewEncapsulation` controls how: `Emulated` (default) rewrites selectors and adds per-component attributes so
rules do not leak in or out; `None` adds the rules to the document globally; `ShadowDom` renders into a real
shadow root. Inside those styles, `:host` targets the component's own element, `:host-context(.selector)` styles
it based on an ancestor, and `::ng-deep` forces a rule through to child components -- `::ng-deep` is
*deprecated*, so prefer a CSS custom property or a global rule instead.

[source,typescript]
----
import { Component, ViewEncapsulation } from '@angular/core';

@Component({
  selector: 'app-badge',
  template: `<span class="dot"></span><ng-content />`,
  styles: `
    :host { display: inline-block; }
    :host(.danger) .dot { background: red; }
    :host-context(.dark-theme) { color: #eee; }
  `,
  encapsulation: ViewEncapsulation.Emulated,
})
export class Badge {}
----

App-wide rules go in the global stylesheet listed under `styles` in `angular.json` (`src/styles.css` or
`src/styles.scss` by default). See https://angular.dev/guide/components/styling[styling components].

=== What encapsulation actually generates

The three `ViewEncapsulation` modes are easiest to understand by looking at what each one produces. A test rendered
this host, with an emulated badge, an unencapsulated component and a shadow-DOM one, plus a plain `.dot` element outside any of them:

[source,typescript]
----
@Component({
  selector: 'app-badge',
  encapsulation: ViewEncapsulation.Emulated,
  template: '<span class="dot"></span><ng-content />',
  styles: `
    :host { display: inline-block; }
    :host(.danger) .dot { background: red; }
    :host-context(.dark-theme) { color: #eee; }
    .dot { width: var(--dot-size, 8px); }
  `,
})
class Badge {}

@Component({ selector: 'app-plain', encapsulation: ViewEncapsulation.None,
             template: '<i class="dot"></i>', styles: '.dot { color: blue; }' })
class Plain {}

@Component({ selector: 'app-shadow', encapsulation: ViewEncapsulation.ShadowDom,
             template: '<i class="dot"></i>', styles: '.dot { color: green; }' })
class Shadow {}

@Component({
  imports: [Badge, Plain, Shadow],
  template: `
    <app-badge class="danger" [style.--dot-size.px]="size()">new</app-badge>
    <app-plain /><app-shadow />
    <div class="dot" id="outside"></div>
  `,
})
class Host { size = signal(12); }
----

The DOM and the injected `<style>` elements came out as follows (the generated suffix differs per component):

[source,text]
----
<app-badge> attributes     : class  _nghost-a-c3139744746  style
.dot inside the badge      : _ngcontent-a-c3139744746  class
.dot inside <app-plain>    : class                       (no marker attribute)
<div id="outside">         : id  class

<style> for the badge:
[_nghost-a-c3139744746] { display: inline-block; }
.danger[_nghost-a-c3139744746] .dot[_ngcontent-a-c3139744746] { background: red; }
.dark-theme[_nghost-a-c3139744746], .dark-theme [_nghost-a-c3139744746] { color: #eee; }
.dot[_ngcontent-a-c3139744746] { width: var(--dot-size, 8px); }

<style> for <app-plain> (added to the document unchanged):
.dot { color: blue; }

<app-shadow>: has a real shadow root, no light-DOM children, its style inside the shadow root
----

[mermaid]
....
flowchart TD
    A["Component with styles"] --> B{"encapsulation"}
    B -- "Emulated (default)" --> C["Angular adds _nghost-xxx to the host<br/>and _ngcontent-xxx to every template element<br/>and rewrites each selector with those attributes"]
    B -- "None" --> D["Styles are appended to the document as-is:<br/>global, and they can match anything"]
    B -- "ShadowDom" --> E["Template renders into a real shadow root<br/>the browser isolates styles in both directions"]
    C --> F["Rules cannot leak out; global rules can still leak in"]
    D --> G["Rules leak both ways"]
    E --> H["Nothing leaks either way<br/>except inherited properties and custom properties"]
....

What this tells you:

* **Emulated** scoping is purely attribute selectors. A global rule such as `+.dot { margin: 0 }+` still reaches
  the badge's `.dot`, because only the *component's* rules gained the attribute; the outside `<div class="dot">`
  stayed untouched by the badge's own rules. The elements *inside* a child component carry the child's marker attribute and not
  the parent's, which is exactly why a parent's styles cannot reach into a child (and why `::ng-deep`, which drops
  the marker from part of a selector, is discouraged).
* **`:host(.danger) .dot`** became `+.danger[_nghost-...] .dot[_ngcontent-...]+`: the class on the host element
  (set by the *parent* template) switches the child's style. `:host-context(.dark-theme)` became two selectors, one for
  the host itself and one for any host below a `.dark-theme` ancestor.
* **A custom property crosses every boundary.** The `[style.--dot-size.px]="size()"` binding sets `--dot-size` on the
  host element, and the badge's `var(--dot-size, 8px)` reads it -- from inside an emulated component, and equally
  from inside a shadow root, because custom properties inherit.

=== A themable component with custom properties and Sass

Custom properties are the supported way to make an encapsulated component themable. The component declares its
defaults on `:host`, uses them with `var()`, and exposes them as its styling API; a consumer overrides them from
outside, with no `::ng-deep`. Sass keeps the internal tokens tidy. This builds with the CLI's standard Sass support:

[source,scss]
----
// src/styles/_tokens.scss
@use 'sass:color';

$brand: #1976d2;

@mixin elevated($level: 1) {
  box-shadow: 0 #{$level * 2}px #{$level * 4}px rgb(0 0 0 / 0.2);
}

@function tint($c, $amount) {
  @return color.mix(white, $c, $amount);
}
----

[source,scss]
----
// src/app/badge/badge.scss
@use '../../styles/tokens' as t;

:host {
  display: inline-block;
  --badge-bg: #{t.$brand};          // the component's public styling hook, with a default
}

.dot {
  background: var(--badge-bg);
  @include t.elevated(2);

  &:hover { background: t.tint(t.$brand, 30%); }
}
----

[source,typescript]
----
@Component({ selector: 'app-badge', styleUrl: './badge.scss', template: '<span class="dot">new</span>' })
export class Badge {}
----

A consumer restyles it from its own template or stylesheet without touching the badge's internals:

[source,html]
----
<app-badge style="--badge-bg: tomato" />
<app-badge class="promo" />   <!-- .promo { --badge-bg: seagreen } in the consumer's stylesheet -->
----

The Sass above compiled with `ng build`, with the `@use` of a partial from outside the component folder, the mixin and
function all resolved by the build, and the finished CSS had the resolved shadow and color values already substituted (for example `box-shadow: 0 4px 8px rgba(0, 0, 0, 0.2)`) while
`var(--badge-bg)` stayed a runtime lookup -- Sass resolves what is known at build time and leaves the rest to the browser.

TIP: Component stylesheets count against the `anyComponentStyle` budget in `angular.json` (4 kB warning and 8 kB error
by default), a useful alarm when a stylesheet grows because tokens or utilities were pasted into a component instead of
being shared. See xref:web/angular/production-and-performance.adoc[Production and performance].

=== Sass

Scaffold a workspace with Sass by passing `--style=scss` to `ng new` (or set it as a schematic default); the
CLI then compiles `.scss` component and global stylesheets with no extra configuration.

[source,bash]
----
ng new my-app --style=scss
----

[source,scss]
----
// badge.component.scss
$brand: #1976d2;

:host {
  display: inline-block;
  .dot { background: $brand; }
}
----

See xref:web/sass/index.adoc[the Sass Reference] for the language itself.

=== Tailwind CSS

Install https://tailwindcss.com/[Tailwind CSS] per its
https://tailwindcss.com/docs/installation/framework-guides/angular[Angular framework guide], then use utility
classes directly in templates. Bind them conditionally with `[class]` (an object or string), `[ngClass]`, or
`[class.name]`.

[source,bash]
----
npm install tailwindcss @tailwindcss/postcss postcss
# add the @tailwindcss/postcss plugin to .postcssrc.json, then
# @import "tailwindcss"; in src/styles.css
----

[source,html]
----
<button
  class="rounded px-4 py-2 text-white"
  [class]="{ 'bg-blue-600 hover:bg-blue-700': !busy(), 'bg-gray-400': busy() }">
  Save
</button>
----

=== CSS-in-JS and dynamic theming

CSS-in-JS libraries are *uncommon in Angular* -- scoped component styles already give the colocation and
isolation they provide elsewhere. For values that change at runtime, set a CSS custom property with
`[style.--name]` and consume it from the component stylesheet.

[source,html]
----
<div class="chart" [style.--bar-color]="color()" [style.--bar-height.px]="height()"></div>
----

[source,scss]
----
.chart { background: var(--bar-color); height: var(--bar-height); }
----

=== NgClass / NgStyle vs. [class.x] / [style.x]

`NgClass` and `NgStyle` accept an object, array, or string and were the pre-v16 way to toggle several classes or
styles at once. The native bindings `[class.name]`, `[class]`, `[style.prop]`, and `[style]` now cover the same
ground, are faster, and need no import -- prefer them; reach for `NgClass` / `NgStyle` only for a dynamic map
whose keys are not known ahead of time.

[source,html]
----
<!-- preferred -->
<p [class.active]="isActive()" [style.color]="isActive() ? 'green' : 'gray'">Status</p>

<!-- NgClass / NgStyle: import { NgClass, NgStyle } from '@angular/common' -->
<p [ngClass]="classMap()" [ngStyle]="styleMap()">Status</p>
----

See https://angular.dev/guide/directives#special-considerations-for-ngclass-and-ngstyle[the NgClass / NgStyle
notes] in the directives guide.

== Component libraries -- free and open-source

Each ships ready-made, accessible components so you are not rebuilding dialogs, menus, and data tables by hand.
They are listed roughly in order of adoption.

=== Angular Material (MIT)

https://material.angular.dev/[Angular Material] is the first-party Material Design library, built on the Angular
CDK and by far the most widely used. Install it with `ng add`, which also wires up Material 3 (`mat.theme`)
theming and typography.

[source,bash]
----
ng add @angular/material
----

[source,typescript]
----
import { Component } from '@angular/core';
import { MatButtonModule } from '@angular/material/button';

@Component({
  selector: 'app-demo',
  imports: [MatButtonModule],
  template: `<button mat-flat-button (click)="save()">Save</button>`,
})
export class Demo {
  save(): void {}
}
----

This is a pointer only -- see xref:web/angular/angular-material.adoc[Angular Material] for the full treatment of
theming and components.

=== PrimeNG (MIT)

https://primeng.org/[PrimeNG] is a large free suite of roughly 90 components with design-token theming
configured through `providePrimeNG()`. Only the optional *templates* (starter admin layouts) are paid; every
component is free.

[source,typescript]
----
import { ApplicationConfig } from '@angular/core';
import { providePrimeNG } from 'primeng/config';
import Aura from '@primeng/themes/aura';

export const appConfig: ApplicationConfig = {
  providers: [providePrimeNG({ theme: { preset: Aura } })],
};
----

[source,typescript]
----
import { Component } from '@angular/core';
import { ButtonModule } from 'primeng/button';

@Component({
  selector: 'app-demo',
  imports: [ButtonModule],
  template: `<p-button label="Save" (onClick)="save()" />`,
})
export class Demo {
  save(): void {}
}
----

=== ng-bootstrap (MIT) and ngx-bootstrap (MIT)

https://www.ng-bootstrap.org/[ng-bootstrap] and https://valor-software.com/ngx-bootstrap/[ngx-bootstrap] both
re-implement Bootstrap 5 widgets as native Angular components with *no jQuery* and no Bootstrap JavaScript. Add
the Bootstrap CSS, then use the components.

[source,bash]
----
ng add @ng-bootstrap/ng-bootstrap
----

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { NgbModal } from '@ng-bootstrap/ng-bootstrap';

@Component({
  selector: 'app-demo',
  template: `
    <button class="btn btn-primary" (click)="open(tpl)">Open</button>
    <ng-template #tpl let-modal>
      <div class="modal-body">Confirm?</div>
      <button class="btn btn-secondary" (click)="modal.close()">Close</button>
    </ng-template>
  `,
})
export class Demo {
  private readonly modalService = inject(NgbModal);
  open(content: unknown): void {
    this.modalService.open(content);
  }
}
----

See xref:web/bootstrap/index.adoc[the Bootstrap Reference] for the underlying design system.

=== NG-ZORRO (MIT)

https://ng.ant.design/[NG-ZORRO] is an Ant Design port with a rich enterprise component set -- notably
`nz-table` and `nz-form`.

[source,bash]
----
ng add ng-zorro-antd
----

[source,typescript]
----
import { Component } from '@angular/core';
import { NzButtonModule } from 'ng-zorro-antd/button';

@Component({
  selector: 'app-demo',
  imports: [NzButtonModule],
  template: `<button nz-button nzType="primary" (click)="save()">Save</button>`,
})
export class Demo {
  save(): void {}
}
----

=== Taiga UI (Apache-2.0)

https://taiga-ui.dev/[Taiga UI] is a large, modular, Angular-native kit split into `@taiga-ui/core`, `/kit`,
`+/addon-*+` packages so you pull in only what you use.

[source,bash]
----
ng add @taiga-ui/cdk @taiga-ui/core @taiga-ui/kit
----

[source,typescript]
----
import { Component } from '@angular/core';
import { TuiButton } from '@taiga-ui/core';

@Component({
  selector: 'app-demo',
  imports: [TuiButton],
  template: `<button tuiButton type="button" (click)="save()">Save</button>`,
})
export class Demo {
  save(): void {}
}
----

=== spartan/ui (MIT)

https://spartan.ng/[spartan/ui] ships unstyled, accessible primitives (the `brain` packages) plus copy-in,
Tailwind-styled components (`helm`) that you own and edit -- the Angular analogue of Radix Primitives plus
shadcn/ui.

[source,bash]
----
npx nx g @spartan-ng/cli:ui button
----

[source,typescript]
----
import { Component } from '@angular/core';
import { HlmButtonDirective } from '@spartan-ng/ui-button-helm';

@Component({
  selector: 'app-demo',
  imports: [HlmButtonDirective],
  template: `<button hlmBtn (click)="save()">Save</button>`,
})
export class Demo {
  save(): void {}
}
----

=== Clarity (MIT) and Nebular (MIT)

https://clarity.design/[Clarity] is VMware's design system with Angular components and a data grid.
https://akveo.github.io/nebular/[Nebular] is a theming-focused kit with an auth module. Both are *less actively
maintained* than the libraries above -- check recent release activity before adopting.

[source,typescript]
----
import { Component } from '@angular/core';
import { ClrButtonModule } from '@clr/angular';

@Component({
  selector: 'app-demo',
  imports: [ClrButtonModule],
  template: `<button class="btn btn-primary" (click)="save()">Save</button>`,
})
export class Demo {
  save(): void {}
}
----

=== The Angular CDK alone (MIT)

https://material.angular.dev/cdk/categories[The Angular CDK] provides the unstyled behaviour behind a design
system -- `Overlay`, the `a11y` package, drag-and-drop, virtual scroll, `BreakpointObserver`, `Portal`, and
more. Use it directly to build bespoke components without adopting a full visual library.

[source,bash]
----
ng add @angular/cdk
----

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { BreakpointObserver, Breakpoints } from '@angular/cdk/layout';
import { toSignal } from '@angular/core/rxjs-interop';
import { map } from 'rxjs';

@Component({
  selector: 'app-demo',
  template: `@if (handset()) { <p>Compact layout</p> }`,
})
export class Demo {
  private readonly bp = inject(BreakpointObserver);
  readonly handset = toSignal(
    this.bp.observe(Breakpoints.Handset).pipe(map((r) => r.matches)),
  );
}
----

=== Choosing between them

[mermaid]
....
flowchart TD
    A["Need a component library?"] --> B{"Own the design system<br/>(custom look, brand tokens)?"}
    B -- "yes, full control" --> C["Angular CDK alone,<br/>or spartan/ui (copy-in components)"]
    B -- "no, a ready-made look is fine" --> D{"Which look?"}
    D -- "Material Design" --> E["Angular Material"]
    D -- "Bootstrap 5" --> F["ng-bootstrap"]
    D -- "Enterprise / data-heavy (Ant Design)" --> G["NG-ZORRO"]
    D -- "Largest component catalog, theme presets" --> H["PrimeNG"]
    D -- "Modular, tree-shakable kit" --> I["Taiga UI"]
....

[cols="1,2,2",options="header"]
|===
| Library | Choose it when | Watch out for

| Angular Material + CDK | you want first-party maintenance and the tightest fit with Angular releases | a recognisably Material look unless you invest in theming
| PrimeNG | you need many components (tables, trees, charts) quickly, with design-token theming | the breadth means a larger learning surface and API churn between majors
| ng-bootstrap | a Bootstrap 5 look, or existing Bootstrap CSS in the organisation | it covers the Bootstrap widgets only; no data grid
| NG-ZORRO | back-office and enterprise screens in an Ant Design style | the visual language is opinionated
| Taiga UI | a modular kit where you import only what you use | smaller community than the Material and PrimeNG ecosystems
| spartan/ui | your own design system on accessible primitives you can edit | you own and maintain the copied-in components
|===

Whichever you pick, check that the version supports your Angular major (library releases trail Angular's by weeks), and
that its components work under `OnPush` and zoneless change detection -- see
xref:web/angular/lifecycle-and-change-detection.adoc[Lifecycle and change detection].

== Commercial suites -- paid / licensed

These are licensed products; they are listed last and without examples.

* https://www.telerik.com/kendo-angular-ui[Kendo UI for Angular] -- a broad commercial component and data-grid
  suite from Progress Telerik.
* https://www.infragistics.com/products/ignite-ui-angular[Ignite UI for Angular] -- Infragistics' commercial
  suite, focused on high-performance grids and charts.
* https://www.syncfusion.com/angular-components[Syncfusion] -- a very large commercial suite; a free *community
  licence* is available for individuals and small teams under a revenue threshold.
* https://www.ag-grid.com/angular-data-grid/[AG Grid] -- the community edition is MIT-licensed; the enterprise
  grid features (row grouping, pivoting, server-side row model, and more) are paid.

== Accessibility

A component library gives you accessible primitives, but you still own the wiring: label every control, manage
focus in dialogs and menus, honour `prefers-reduced-motion`, and test with a keyboard and a screen reader. The
CDK `a11y` package helps -- `LiveAnnouncer` for polite/assertive announcements, `cdkTrapFocus` to keep focus
inside an open dialog, and `FocusMonitor` to track how an element gained focus.

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { A11yModule, LiveAnnouncer } from '@angular/cdk/a11y';

@Component({
  selector: 'app-dialog',
  imports: [A11yModule],
  template: `
    <div cdkTrapFocus role="dialog" aria-label="Confirm delete">
      <button (click)="confirm()">Delete</button>
    </div>
  `,
})
export class Dialog {
  private readonly announcer = inject(LiveAnnouncer);
  confirm(): void {
    this.announcer.announce('Item deleted', 'assertive');
  }
}
----

See xref:web/accessibility.adoc[Web Accessibility] for conformance levels and validation tools.
