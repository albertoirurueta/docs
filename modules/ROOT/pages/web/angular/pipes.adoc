= Pipes
:description: Angular's built-in pipes for formatting values in templates, parameterising and chaining them, the difference between pure and impure pipes and its change-detection cost, and writing a standalone custom pipe.
:keywords: Angular pipes, DatePipe, CurrencyPipe, DecimalPipe, PercentPipe, JsonPipe, KeyValuePipe, SlicePipe, AsyncPipe, pure pipe, impure pipe, custom pipe, transform

include::partial$ai-disclaimer.adoc[]

A **pipe** transforms a value for display in a template, using the `value | pipeName:arg1:arg2` syntax. Pipes
are pure functions of their input, so the same input always renders the same output. See
https://angular.dev/guide/templates/pipes[Pipes].

== Built-in pipes

Import the ones you use from `@angular/common` (or import `CommonModule`). Parameters follow the pipe name
separated by colons, and pipes **chain** left to right.

[source,html]
----
{{ createdAt | date:'medium' }}                    <!-- Jun 15, 2024, 9:03:01 AM -->
{{ createdAt | date:'yyyy-MM-dd':'UTC' }}          <!-- format + timezone -->
{{ price | currency:'EUR':'symbol':'1.2-2' }}      <!-- €1,234.50 -->
{{ ratio | percent:'1.0-1' }}                       <!-- 42.5% -->
{{ count | number:'1.0-0' }}                        <!-- 1,024 -->
{{ user | json }}                                   <!-- debugging: pretty-printed JSON -->
{{ 'hello world' | titlecase }}                     <!-- Hello World -->
{{ name | uppercase }} / {{ name | lowercase }}
{{ items | slice:0:3 }}                             <!-- first three -->
{{ longText | slice:0:100 | titlecase }}            <!-- chained -->
----

`keyvalue` turns an object or `Map` into an iterable of `+{ key, value }+` entries for `@for`:

[source,html]
----
@for (entry of settings | keyvalue; track entry.key) {
  <li>{{ entry.key }}: {{ entry.value }}</li>
}
----

The `async` pipe subscribes to an `Observable` or `Promise`, returns the latest value, and **unsubscribes
automatically** when the component is destroyed -- the idiomatic way to render reactive data without a manual
subscription.

[source,html]
----
@if (user$ | async; as user) {
  <p>Welcome, {{ user.name }}</p>
}
----

`@let` gives a second spelling that keeps the value available for the whole template, not just inside the `@if`:

[source,html]
----
@let user = user$ | async;
@if (user) { <p>Welcome, {{ user.name }}</p> } @else { <p>Loading</p> }
----

Each `| async` in a template is a separate subscription, so bind the observable once (with `as` or `@let`) instead of
repeating `(user$ | async)?.name` on several lines -- repeating it with a cold observable such as an `HttpClient`
call sends one request per occurrence.

Reference tables: https://angular.dev/guide/templates/pipes[Pipes guide] and
https://angular.dev/api/common/AsyncPipe[`AsyncPipe`]. Common date/number/currency pipes live under
https://angular.dev/api/common/DatePipe[`DatePipe`],
https://angular.dev/api/common/CurrencyPipe[`CurrencyPipe`],
https://angular.dev/api/common/DecimalPipe[`DecimalPipe`], and
https://angular.dev/api/common/PercentPipe[`PercentPipe`].

== Pure vs. impure pipes

Pipes are **pure** by default: Angular re-runs `transform()` only when the input **reference** changes (a new
object, not a mutated one). This makes them cheap -- a pure pipe is skipped on most change-detection cycles.

An **impure** pipe (`+@Pipe({ name: 'x', pure: false })+`) runs on **every** change-detection cycle, regardless
of whether its inputs changed. `AsyncPipe` is impure because it must emit values as they arrive. Write an
impure pipe only when unavoidable, keep its work trivial, and never do I/O in one -- otherwise it becomes a
performance hazard, especially under the eager (zone-style) change-detection strategy (see
xref:web/angular/lifecycle-and-change-detection.adoc[Lifecycle and change detection]).

[source,typescript]
----
// Pure: recomputes only when `items` is reassigned, not when it is push()-ed into.
@Pipe({ name: 'topN' })
export class TopNPipe implements PipeTransform {
  transform(items: readonly number[], n = 3): number[] {
    return [...items].sort((a, b) => b - a).slice(0, n);
  }
}
----

== How a pipe is evaluated

Angular decides per binding how often to call `transform()`:

[mermaid]
....
flowchart TD
    A["Change detection reaches a binding with a pipe"] --> B{"Pure pipe?"}
    B -- "yes (default)" --> C{"Input or argument reference changed<br/>since the last call?"}
    C -- "no" --> D["Reuse the cached result<br/>transform is not called"]
    C -- "yes" --> E["Call transform and cache the result"]
    B -- "no (pure: false)" --> F["Call transform on every pass"]
    E --> G["Write the DOM if the text changed"]
    F --> G
    D --> H["Nothing to write"]
....

== Pure and impure pipes measured

The difference is easy to measure. A pure `bookLabel` pipe and an impure `bookLabelImpure` pipe each count their
calls and are bound in an `Eager` component (see
xref:web/angular/lifecycle-and-change-detection.adoc[Lifecycle and change detection]) next to an unrelated `tick`
signal:

[source,typescript]
----
let pureCalls = 0;
let impureCalls = 0;

@Pipe({ name: 'bookLabel' })
export class BookLabelPipe implements PipeTransform {
  transform(book: Book): string { pureCalls++; return book.title; }
}

@Pipe({ name: 'bookLabelImpure', pure: false })
export class BookLabelImpurePipe implements PipeTransform {
  transform(book: Book): string { impureCalls++; return book.title; }
}

@Component({
  changeDetection: ChangeDetectionStrategy.Eager,
  imports: [BookLabelPipe, BookLabelImpurePipe],
  template: `
    <p id="pure">{{ book | bookLabel }}</p>
    <p id="impure">{{ book | bookLabelImpure }}</p>
    <p>{{ tick() }}</p>
  `,
})
class Host {
  readonly tick = signal(0);
  book: Book = { id: 1, title: 'Dune', price: 12.5, tags: [], published: new Date() };
}
----

Driving that component from a test produced:

[cols="3,1,1",options="header"]
|===
| Step | Pure calls | Impure calls

| First render (development mode also runs a verification pass) | 1 | 2
| Three unrelated `tick.update()` calls | 1 | 8
| `book.title = 'Dune Messiah'` in place, then one more `tick` update | 1 | 9
| `+book = { ...book, title: 'Children of Dune' }+`, then a `tick` update | 2 | 11
|===

After the in-place mutation the impure pipe printed `Dune Messiah` and the pure pipe still printed `Dune`; after
the new object was assigned the pure pipe caught up. Two practical rules follow:

* Give a pure pipe **immutable** data. Mutating an array or object in place is invisible to it; replace the
  reference (`+items = [...items, newItem]+`) or use a signal.
* Do not "fix" the stale result with `pure: false` unless the pipe is cheap and has no I/O, because it then runs on
  every pass of every view that uses it. A `computed()` that derives the value once per change is almost always
  better.

== Pipe, method, or `computed()`?

[cols="2,3",options="header"]
|===
| Use | When

| A pipe | A formatting step reused across templates that depends only on its inputs: dates, money, truncation, reading time
| A `computed()` | A value derived from component state, calculated once per change and reused wherever it is bound
| A method call in the template | Rarely: it runs on every pass, so keep it trivial (a `computed()` is the same call without the repeats)
| A formatting function (for example `formatDate`) | Outside templates -- logging, `title` strings, exports
|===

`formatDate(value, format, locale, timezone)` from `@angular/common` is the function behind `DatePipe`, so the output
is identical:

[source,typescript]
----
import { formatDate } from '@angular/common';

formatDate(new Date(Date.UTC(1965, 7, 1)), 'longDate', 'en-US', 'UTC');   // 'August 1, 1965'
----

== Verified output of the built-in pipes

For `+book = { title: 'Dune', price: 12.5, tags: ['sf', 'classic', 'desert'], published: 1965-08-01 UTC }+` the pipes
shown above render as follows (the locale is passed explicitly, so the result does not depend on the browser):

[cols="2,2",options="header"]
|===
| Template | Rendered

| `+{{ book.published \| date:'yyyy-MM-dd':'UTC' }}+` | `1965-08-01`
| `+{{ book.price \| currency:'EUR':'symbol':'1.2-2':'en-US' }}+` | `€12.50`
| `+{{ 1234.5678 \| number:'1.0-2':'en-US' }}+` | `1,234.57`
| `+{{ 0.425 \| percent:'1.0-1':'en-US' }}+` | `42.5%`
| `+{{ 'the left hand of darkness' \| titlecase }}+` | `The Left Hand Of Darkness`
| `+{{ book.tags \| slice:0:2 }}+` | `sf,classic`
| `+@for (e of map \| keyvalue; track e.key)+` over `+new Map([['b', 2], ['a', 1]])+` | `a=1; b=2;` (sorted by key)
|===

The number formats are `minIntegerDigits.minFractionDigits-maxFractionDigits`, so `'1.0-2'` means at least one
integer digit and between zero and two decimals.

=== The pipe operator binds loosely

The pipe operator has the lowest precedence of all template operators, so in a conditional it applies only to the
last branch. With `flag()` true:

[source,html]
----
{{ flag() ? 'yes' : 'no' | uppercase }}      <!-- yes  (uppercase applies to 'no' only) -->
{{ (flag() ? 'yes' : 'no') | uppercase }}    <!-- YES -->
----

Parenthesise the whole expression whenever a pipe should apply to it as a unit.

== A custom pipe with parameters, tested

A pipe may take several arguments and still be a pure function. This one turns a page count into a reading time,
with a words-per-page and a words-per-minute default that callers can override:

[source,typescript]
----
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'readingTime' })
export class ReadingTimePipe implements PipeTransform {
  transform(pages: number, wordsPerPage = 250, wpm = 200): string {
    const minutes = Math.ceil((pages * wordsPerPage) / wpm);
    const h = Math.floor(minutes / 60);
    const m = minutes % 60;
    return h > 0 ? `${h} h ${m} min` : `${m} min`;
  }
}
----

[source,html]
----
<p>{{ book().pages | readingTime }}</p>            <!-- 612 pages -> 12 h 45 min -->
<p>{{ book().pages | readingTime:300:250 }}</p>    <!-- override words per page and wpm -->
----

Because a pipe is a plain class, its unit test needs no `TestBed`:

[source,typescript]
----
it('formats reading time', () => {
  const pipe = new ReadingTimePipe();
  expect(pipe.transform(30)).toBe('38 min');
  expect(pipe.transform(612)).toBe('12 h 45 min');
});
----

If a pipe needs a service (a translation lookup, say), call `inject()` in a field initializer and create it in a test
with `+TestBed.runInInjectionContext(() => new MyPipe())+`. See
xref:web/angular/testing.adoc[Testing] for the rest of the testing toolbox.

== A custom pipe

Give `@Pipe` a `name`, implement `+PipeTransform.transform(value, ...args)+`, and add the pipe class to a
component's `imports`. Pipes are standalone by default.

[source,typescript]
----
import { Pipe, PipeTransform } from '@angular/core';

@Pipe({ name: 'truncate' })
export class TruncatePipe implements PipeTransform {
  transform(value: string, limit = 20, trail = '…'): string {
    if (value.length <= limit) {
      return value;
    }
    return value.slice(0, limit).trimEnd() + trail;
  }
}
----

[source,typescript]
----
@Component({
  selector: 'app-post',
  imports: [TruncatePipe],
  template: '<p>{{ post().body | truncate:80 }}</p>',
})
export class Post { /* ... */ }
----

See https://angular.dev/guide/templates/pipes#creating-custom-pipes[Creating custom pipes].
