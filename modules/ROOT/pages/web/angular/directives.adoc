= Directives
:description: Attribute directives with @Directive and host bindings, structural directives and the asterisk shorthand desugaring to ng-template, ng-container, and the built-in attribute directives and directive composition API.
:keywords: Angular directives, attribute directive, structural directive, ng-template, ng-container, TemplateRef, ViewContainerRef, NgClass, NgStyle, NgModel, NgOptimizedImage, hostDirectives, directive composition API

include::partial$ai-disclaimer.adoc[]

A **directive** is a class that attaches behaviour to an element. Components are directives with a template;
plain directives have none. Angular has two kinds: **attribute directives** change the appearance or behaviour
of an existing element, and **structural directives** add or remove elements from the DOM. See
https://angular.dev/guide/directives[Directives].

== How a directive reaches an element

The compiler matches every directive's `selector` against every element in a template at build time, so a directive runs
on an element only if the template's own `imports` (or a parent chain of `NgModule` exports) made it visible. At runtime
each matched directive becomes an object created next to the element:

[mermaid]
....
flowchart TD
    T["Template element: p with appHighlight=gold"] --> M{"Compiler: which imported directives have a selector matching this element?"}
    M -->|"none"| N["Plain element; an unknown attribute is just an attribute"]
    M -->|"one or more"| C["Create each matched directive in the element's injector"]
    C --> I["Bind inputs, then run ngOnInit-style hooks"]
    I --> H["Apply host metadata: listeners and bindings on the host element"]
    H --> L["Directive lives as long as its element, then DestroyRef callbacks run"]
....

Several directives can share one element, each with its own inputs, and a component is just one of those directives
(an element can match at most one component). A directive also gets its own entry in the element injector, which is why
sibling directives on the same element can `inject()` each other.

== Attribute directives

Declare one with `@Directive`, give it an attribute `selector`, and bind to its host element with the `host`
metadata or the `+host+` decorators. Signal `input()` reads a bound value; `@HostListener`-style entries in
`host` react to events. Directives are standalone by default and are added to a component's `imports`.

[source,typescript]
----
import { Directive, ElementRef, inject, input } from '@angular/core';

@Directive({
  selector: '[appHighlight]',
  host: {
    '(mouseenter)': 'onEnter()',
    '(mouseleave)': 'onLeave()',
    '[style.transition]': '"background-color 150ms"',
  },
})
export class HighlightDirective {
  private readonly el = inject(ElementRef<HTMLElement>);

  // <p [appHighlight]="'gold'"> -> the directive's own value
  readonly appHighlight = input<string>('yellow');

  private onEnter(): void {
    this.el.nativeElement.style.backgroundColor = this.appHighlight();
  }

  private onLeave(): void {
    this.el.nativeElement.style.backgroundColor = '';
  }
}
----

[source,html]
----
<p [appHighlight]="'gold'">Hover me</p>
----

Prefer binding through `host` metadata or `@HostBinding` / `@HostListener` over touching `nativeElement`
directly, so the directive stays testable and server-side-render safe. See
https://angular.dev/guide/directives/attribute-directives[Attribute directives].

== Structural directives

A structural directive is written with the `+*+` shorthand. Angular **desugars** `+*+` onto an
`<ng-template>` that wraps the host element, and the directive decides whether and how often to render that
template.

[source,html]
----
<!-- what you write -->
<section *appUnless="isLoading">Content</section>

<!-- what Angular expands it to -->
<ng-template [appUnless]="isLoading">
  <section>Content</section>
</ng-template>
----

`<ng-container>` is a grouping element that produces **no DOM node** -- useful to host a structural directive
without adding a wrapper, or to place several `@for` / `@if` blocks side by side. See
https://angular.dev/guide/templates/ng-container[ng-container] and
https://angular.dev/guide/templates/ng-template[ng-template].

[source,html]
----
<ng-container *appUnless="isLoading">
  <h2>{{ title() }}</h2>
  <p>No wrapper element is emitted around these two.</p>
</ng-container>
----

Write one by injecting `TemplateRef` (the content to stamp out) and `ViewContainerRef` (where to stamp it).

[source,typescript]
----
import { Directive, TemplateRef, ViewContainerRef, effect, inject, input } from '@angular/core';

@Directive({ selector: '[appUnless]' })
export class UnlessDirective {
  private readonly tpl = inject(TemplateRef<unknown>);
  private readonly vcr = inject(ViewContainerRef);

  readonly appUnless = input.required<boolean>();

  constructor() {
    effect(() => {
      this.vcr.clear();
      if (!this.appUnless()) {
        this.vcr.createEmbeddedView(this.tpl);
      }
    });
  }
}
----

The built-in `@if` / `@for` / `@switch` control flow (see
xref:web/angular/control-flow-and-defer.adoc[Control flow and @defer]) replaces `+*ngIf+` / `+*ngFor+` /
`+*ngSwitch+` for everyday branching and lists; custom structural directives remain useful for reusable
rendering rules. See https://angular.dev/guide/directives/structural-directives[Structural directives].

== Built-in attribute directives

Import these from `@angular/common`. With the built-in control flow they are needed less often, but they are
still current:

[cols="1,3",options="header"]
|===
| Directive | Use

| https://angular.dev/api/common/NgClass[`NgClass`] | Toggle several CSS classes from an object or array: `+[ngClass]="{ active: isActive() }"+`. For a single class prefer `[class.active]="isActive()"`.
| https://angular.dev/api/common/NgStyle[`NgStyle`] | Set several inline styles from an object: `+[ngStyle]="{ color: c() }"+`. For one property prefer `[style.color]="c()"`.
| https://angular.dev/api/forms/NgModel[`NgModel`] | Two-way bind a form field in template-driven forms (`[(ngModel)]`). See xref:web/angular/forms.adoc[Forms].
| https://angular.dev/api/common/NgOptimizedImage[`NgOptimizedImage`] | Apply the `ngSrc` attribute to `<img>` for automatic lazy-loading, `srcset` generation, and LCP prioritisation (`priority`).
|===

[source,html]
----
<button [ngClass]="{ primary: kind() === 'primary', danger: kind() === 'danger' }">Go</button>
<div [ngStyle]="{ 'font-size.px': size(), color: color() }">Sized text</div>

<img ngSrc="/assets/hero.jpg" width="1200" height="600" priority alt="Hero" />
----

[source,typescript]
----
import { NgClass, NgStyle, NgOptimizedImage } from '@angular/common';

@Component({
  selector: 'app-banner',
  imports: [NgClass, NgStyle, NgOptimizedImage],
  templateUrl: './banner.html',
})
export class Banner { /* ... */ }
----

== Directive composition API

`hostDirectives` lets a component or directive **apply other directives to its own host element**, optionally
re-exposing their inputs and outputs. It composes behaviour without inheritance or wrapper elements.

[source,typescript]
----
import { Directive, Component, input } from '@angular/core';

@Directive({
  selector: '[appTooltip]',
  host: { '(mouseenter)': 'show()', '(mouseleave)': 'hide()' },
})
export class Tooltip {
  readonly appTooltip = input<string>('');
  show(): void { /* ... */ }
  hide(): void { /* ... */ }
}

@Component({
  selector: 'app-icon-button',
  hostDirectives: [
    { directive: Tooltip, inputs: ['appTooltip: tooltip'] }, // re-expose as `tooltip`
  ],
  template: '<button><ng-content /></button>',
})
export class IconButton {}
----

[source,html]
----
<app-icon-button tooltip="Save">Save</app-icon-button>
----

Host directives must be **standalone**, and the list is static (it cannot be built at runtime). See
https://angular.dev/guide/directives/directive-composition-api[Directive composition API].

== Deep dive: directives for BookShelf

The attribute and structural examples above are real, runnable code. These are the details that matter when you
build your own.

=== Exporting a directive so the template can read it

`exportAs` makes a directive's instance available through a template reference variable, so the template can read its
state or call its methods:

[source,typescript]
----
@Directive({
  selector: '[appHighlight]',
  exportAs: 'appHighlight',
  host: {
    '(mouseenter)': 'onEnter()',
    '(mouseleave)': 'onLeave()',
    '[style.background-color]': 'color()',
  },
})
export class Highlight {
  readonly appHighlight = input('yellow');
  protected readonly color = signal('');

  protected onEnter(): void { this.color.set(this.appHighlight()); }
  protected onLeave(): void { this.color.set(''); }
  get active(): boolean { return this.color() !== ''; }
}
----

[source,html]
----
<p appHighlight="gold" #h="appHighlight">Hover me</p>
<span>{{ h.active ? 'highlighted' : 'idle' }}</span>
----

This version drives the style through a *signal* bound in `host`, so the directive never touches `nativeElement`:
when the signal changes, Angular updates the host's style on the next change-detection pass, and the directive stays
safe to run during server rendering.

=== A structural directive with a typed template context

A structural directive can hand values to the template it stamps out through a *context* object. `$implicit` feeds the
plain `let x` form, and every other key is picked up by name with `let y = key`. The static
`ngTemplateContextGuard` method tells the type checker the shape of the context, so the aliases inside the template
are typed rather than `any`:

[source,typescript]
----
interface RepeatContext { $implicit: number; index: number; count: number; }

@Directive({ selector: '[appRepeat]' })
export class Repeat {
  private readonly tpl = inject(TemplateRef<RepeatContext>);
  private readonly vcr = inject(ViewContainerRef);
  readonly appRepeat = input.required<number>();

  static ngTemplateContextGuard(_dir: Repeat, _ctx: unknown): _ctx is RepeatContext {
    return true;
  }

  constructor() {
    effect(() => {
      this.vcr.clear();
      const n = this.appRepeat();
      for (let i = 0; i < n; i++) {
        this.vcr.createEmbeddedView(this.tpl, { $implicit: i, index: i, count: n });
      }
    });
  }
}
----

[source,html]
----
<ul>
  <li *appRepeat="3; let i = $implicit; let n = count">{{ i }}/{{ n }}</li>
</ul>
<!-- renders: 0/3, 1/3, 2/3 -->
----

The micro-syntax after the directive name maps onto inputs and context: `3` binds to the directive's own input
(`appRepeat`), `let i = $implicit` and `let n = count` read the context. A bare `let i` would also work for the
`$implicit` value. Because the `effect()` runs again whenever `appRepeat()` changes, the whole embedded-view list is
rebuilt; for large lists a real directive would reuse views, which is exactly what `@for` does with `track`.

=== Re-exposing outputs through the composition API

`hostDirectives` can forward outputs as well as inputs. A reusable `Dismissable` behaviour, which emits when the user
presses Escape on the host, becomes part of the component's public API without the component re-declaring it:

[source,typescript]
----
@Directive({ selector: '[appDismissable]', host: { '(keydown.escape)': 'dismissed.emit()' } })
export class Dismissable {
  readonly dismissed = output<void>();
}

@Component({
  selector: 'app-panel',
  hostDirectives: [{ directive: Dismissable, outputs: ['dismissed'] }],
  template: `<ng-content />`,
})
export class Panel {}
----

[source,html]
----
<app-panel (dismissed)="closePanel()">...</app-panel>
----

=== Testing a directive

Test a directive through a host component that uses it, then query the element and drive it with DOM events. Reach the
directive instance itself through the element's injector when you need to assert on its state:

[source,typescript]
----
@Component({
  imports: [Highlight],
  template: `<p appHighlight="gold">hover</p>`,
})
class Host {}

it('highlights on hover', async () => {
  const fixture = TestBed.createComponent(Host);
  await fixture.whenStable();
  const p = fixture.debugElement.query(By.directive(Highlight));

  p.nativeElement.dispatchEvent(new MouseEvent('mouseenter'));
  await fixture.whenStable();
  expect(p.nativeElement.style.backgroundColor).toBe('gold');
  expect(p.injector.get(Highlight).appHighlight()).toBe('gold');

  p.nativeElement.dispatchEvent(new MouseEvent('mouseleave'));
  await fixture.whenStable();
  expect(p.nativeElement.style.backgroundColor).toBe('');
});
----
