= Routing and Navigation
:description: Configuring the Angular router with provideRouter, linking and navigating, reading route parameters and query params, child routes and lazy loading, and functional guards and resolvers.
:keywords: Angular router, provideRouter, withComponentInputBinding, withViewTransitions, router-outlet, Routes, base href, routerLink, routerLinkActive, Router navigate, navigateByUrl, named outlets, ActivatedRoute, route params, query params, fragment, child routes, lazy loading, loadComponent, loadChildren, CanActivateFn, CanMatchFn, CanDeactivateFn, ResolveFn

include::partial$ai-disclaimer.adoc[]

The Angular router maps the browser URL to a tree of components, swapping views without a full page reload. It
is configured functionally with `provideRouter` and a `Routes` array.

== Configuration

[source,typescript]
----
// app.routes.ts
import { Routes } from '@angular/router';
import { Home } from './home/home';

export const routes: Routes = [
  { path: '', component: Home, title: 'Home' },
  { path: 'books', loadComponent: () => import('./books/book-list').then((m) => m.BookList) },
  { path: 'books/:id', loadComponent: () => import('./books/book-detail').then((m) => m.BookDetail) },
  { path: 'legacy', redirectTo: 'books', pathMatch: 'full' },
  { path: '**', component: NotFound, title: 'Not found' }, // wildcard: keep last
];
----

[source,typescript]
----
// app.config.ts
import { provideRouter, withComponentInputBinding, withViewTransitions } from '@angular/router';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(
      routes,
      withComponentInputBinding(), // bind route params/data/query to component input() properties
      withViewTransitions(),       // animate route changes with the View Transitions API
    ),
  ],
};
----

Place a `<router-outlet>` where the matched component should render, and set a `<base href="/">` in
`index.html` so the router can resolve absolute paths (the CLI adds it):

[source,html]
----
<nav><a routerLink="/books">Books</a></nav>
<router-outlet />
----

Routes are matched top to bottom; the first match wins, so put specific paths before `:param` paths and the
`+**+` wildcard last. See https://angular.dev/guide/routing[Routing overview] and
https://angular.dev/guide/routing/define-routes[Define routes].

== Linking and navigating

`routerLink` builds URLs without reloading; `routerLinkActive` toggles a class when the link's route is
active. In code, inject `Router` and call `navigate` (a link-parameters array) or `navigateByUrl` (a string).

[source,html]
----
<a routerLink="/books">All books</a>
<a [routerLink]="['/books', book.id]" routerLinkActive="active">{{ book.title }}</a>
<a [routerLink]="['/books', book.id]" [queryParams]="{ tab: 'reviews' }" fragment="top">Reviews</a>

<!-- named (auxiliary) outlet -->
<router-outlet name="aside" />
<a [routerLink]="[{ outlets: { aside: ['help'] } }]">Open help</a>
----

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { Router, ActivatedRoute } from '@angular/router';

@Component({ /* ... */ })
export class BookActions {
  private readonly router = inject(Router);
  private readonly route = inject(ActivatedRoute);

  open(id: string) {
    this.router.navigate(['/books', id], { queryParams: { tab: 'reviews' } });
  }

  next() {
    // relative navigation: resolve against the current route
    this.router.navigate(['..', '43'], { relativeTo: this.route });
  }

  home() {
    this.router.navigateByUrl('/');
  }
}
----

See https://angular.dev/guide/routing/navigate-to-routes[Navigate to routes].

`routerLinkActive` matches by prefix, so a link to `/` would be active on every page. Add
`+[routerLinkActiveOptions]="{ exact: true }"+` to the home link to require an exact match:

[source,html]
----
<a routerLink="/" routerLinkActive="active" [routerLinkActiveOptions]="{ exact: true }">Home</a>
<a routerLink="/books" routerLinkActive="active">Books</a>
----

Observed with a router at `/`, the home link has the class `active` and the books link none; after navigating to
`/books/42` it is the other way round, because `/books/42` is below `/books` but is not `/`.

== Reading route state

Route data comes from `path` segments (`:id`), the static `data` object, the resolved `title`, and the URL's
`?query` and `#fragment`. Read it either from `ActivatedRoute` observables or -- with
`withComponentInputBinding()` -- straight from `input()` properties whose names match.

[source,typescript]
----
// route: { path: 'books/:id', component: BookDetail, data: { mode: 'view' } }

import { Component, inject, input } from '@angular/core';
import { ActivatedRoute } from '@angular/router';
import { toSignal } from '@angular/core/rxjs-interop';

@Component({ selector: 'app-book-detail', template: '{{ id() }} / {{ mode() }} / {{ tab() }}' })
export class BookDetail {
  // component input binding: matched from path param, data, query param, or resolver key
  readonly id = input.required<string>();
  readonly mode = input<'view' | 'edit'>('view');
  readonly tab = input<string>();

  // or, the observable form
  private readonly route = inject(ActivatedRoute);
  readonly params = toSignal(this.route.paramMap);
  readonly query = toSignal(this.route.queryParamMap);
}
----

Set a dynamic `title` with a `ResolveFn` on the route's `title` property. See
https://angular.dev/guide/routing/read-route-state[Read route state].

=== Snapshot versus observable

`ActivatedRoute.snapshot` holds the parameters at the moment the component was created; the observables
(`paramMap`, `queryParamMap`, `data`) emit again when the URL changes **while the same component instance stays
on screen**. That distinction matters because the router reuses a component when only its parameters change:
navigating from `/books/7` to `/books/8` re-emits `paramMap` on the existing `BookDetail` and does not create a new one.

[source,typescript]
----
@Component({ selector: 'app-book-detail', template: '{{ firstId }} | {{ currentId() }}' })
export class BookDetail {
  private readonly route = inject(ActivatedRoute);

  readonly firstId = this.route.snapshot.paramMap.get('id');        // fixed at creation: stale after /books/7 -> /books/8
  readonly currentId = toSignal(this.route.paramMap.pipe(map((p) => p.get('id'))));  // follows the URL
}
----

Use the snapshot only when the component is always recreated (for example the route has a guard that forces it), and
prefer `withComponentInputBinding()` inputs or `toSignal(paramMap)` otherwise.

== Child routes and lazy loading

A route with `children` renders them into a nested `<router-outlet>` inside its component. Splitting code by
route keeps the initial bundle small: `loadComponent` lazily loads one standalone component, `loadChildren`
lazily loads a child `Routes` array.

[source,typescript]
----
export const routes: Routes = [
  {
    path: 'books',
    component: BooksShell,          // has its own <router-outlet />
    children: [
      { path: '', component: BookList },
      { path: ':id', component: BookDetail },
    ],
  },
  {
    path: 'admin',
    canMatch: [isAdmin],
    loadChildren: () => import('./admin/admin.routes').then((m) => m.ADMIN_ROUTES),
  },
];
----

Each lazily loaded area gets its own environment injector, so `providers` on a lazy route are scoped to it
(see xref:web/angular/dependency-injection.adoc[Dependency injection]). See
https://angular.dev/guide/routing/loading-strategies[Lazy loading].

== Guards and resolvers

Guards are functions returning `boolean`, `UrlTree` (a redirect), or a `Promise`/`Observable` of either. They
run in the injection context, so they `inject()` services directly -- no class needed.

[source,typescript]
----
import { inject } from '@angular/core';
import {
  CanActivateFn, CanActivateChildFn, CanDeactivateFn, CanMatchFn, ResolveFn, Router,
} from '@angular/router';

// CanMatch: decide whether the route matches at all (skips to the next route if false)
export const isAdmin: CanMatchFn = () =>
  inject(AuthStore).role() === 'admin' || inject(Router).createUrlTree(['/forbidden']);

// CanActivate: guard entry to a route
export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthStore);
  return auth.isLoggedIn()
    ? true
    : inject(Router).createUrlTree(['/login'], { queryParams: { returnUrl: state.url } });
};

// CanActivateChild: guard entry to any child route
export const sectionGuard: CanActivateChildFn = (route, state) => authGuard(route, state);

// CanDeactivate: guard leaving (e.g. unsaved changes); typed to the component
export const confirmLeave: CanDeactivateFn<EditForm> = (component) =>
  component.saved() || confirm('Discard unsaved changes?');

// ResolveFn: pre-fetch data before activation; the value lands in the route's data
export const bookResolver: ResolveFn<Book> = (route) =>
  inject(BookApi).get(route.paramMap.get('id')!);
----

Wire them onto routes, alongside any route-scoped `providers`:

[source,typescript]
----
{
  path: 'books/:id',
  component: BookDetail,
  canActivate: [authGuard],
  canDeactivate: [confirmLeave],
  resolve: { book: bookResolver },
  providers: [BookApi],
  title: (route) => `Book ${route.paramMap.get('id')}`,
}
----

See https://angular.dev/guide/routing/route-guards[Route guards] and
https://angular.dev/guide/routing/data-resolvers[Data resolvers].

== A worked example: the book catalog routes

The sections above show each feature alone. This example wires them together for a small catalog: a public home page,
a protected `/books` area with a list, a detail page whose data is resolved before it renders, and an edit page that
asks before discarding changes. It was run against a real router in a test; the outcomes listed afterwards are what the
test observed.

[source,typescript]
----
import { inject, Injectable, signal } from '@angular/core';
import {
  CanActivateFn, CanDeactivateFn, CanMatchFn, RedirectCommand, ResolveFn, Router, Routes,
} from '@angular/router';

export interface Book { id: number; title: string }

@Injectable({ providedIn: 'root' })
export class Auth {
  readonly loggedIn = signal(false);
  readonly role = signal<'user' | 'admin'>('user');
}

const authGuard: CanActivateFn = (_route, state) =>
  inject(Auth).loggedIn()
    ? true
    : inject(Router).createUrlTree(['/login'], { queryParams: { returnUrl: state.url } });

const isAdmin: CanMatchFn = () => inject(Auth).role() === 'admin';

const confirmLeave: CanDeactivateFn<EditBook> = (component) => !component.dirty();

const bookResolver: ResolveFn<Book> = (route) => {
  const book = inject(BookApi).find(Number(route.paramMap.get('id')));
  // a RedirectCommand redirects from a resolver; the book is never rendered
  return book ?? new RedirectCommand(inject(Router).parseUrl('/404'));
};

export const routes: Routes = [
  { path: '', component: Home, title: 'Home' },
  { path: 'login', component: Login },
  {
    path: 'books',
    component: Shell,                       // contains <router-outlet />
    canActivate: [authGuard],
    children: [
      { path: '', component: BookList },
      {
        path: ':id',
        component: BookDetail,
        resolve: { book: bookResolver },
        data: { mode: 'view' },
        title: (route) => `Book ${route.paramMap.get('id')}`,
      },
      { path: ':id/edit', component: EditBook, canDeactivate: [confirmLeave] },
    ],
  },
  { path: 'admin', canMatch: [isAdmin], component: AdminPage },   // only matches for admins ...
  { path: 'admin', component: Forbidden },                         // ... everyone else falls through to this
  { path: 'legacy/:id', redirectTo: (route) => `books/${route.params['id']}` },  // redirectTo as a function
  { path: '404', component: NotFound },
  { path: '**', component: NotFound },
];
----

`BookDetail` declares `book = input.required<Book>()`, `tab = input('info')` and `mode = input('view')` and the
application calls `provideRouter(routes, withComponentInputBinding())`, so the resolved book, the `tab` query
parameter, and the route `data` all arrive as plain inputs.

[cols="2,3",options="header"]
|===
| Navigation | Observed result

| `/books/7?tab=reviews` while logged out | redirected to `/login?returnUrl=%2Fbooks%2F7%3Ftab%3Dreviews`
| the same URL after `auth.loggedIn.set(true)` | `BookDetail` renders `Book 7 / tab=reviews / mode=view`; the document title is `Book 7`; the resolver ran once
| `/books/500` (no such book) | the resolver returns a `RedirectCommand` and the URL becomes `/404`
| `/legacy/3` | the URL becomes `/books/3`
| `/admin` as a normal user | the first `admin` route is skipped by `canMatch`; the second one renders `Forbidden`
| `/admin` as an admin | `AdminPage`
| `/books/1/edit` with unsaved changes, then navigating to `/books` | `confirmLeave` returns `false`; the URL stays `/books/1/edit`
| `/nothing/here` | the `+**+` route renders `NotFound`
|===

Two behaviours in that table are easy to trip over. First, `canMatch` is a routing decision, not an access error: a
route that fails it is treated as if it did not exist, so the router moves on to the next entry -- that is how the
same path serves two different pages. Second, navigating to the URL you are already on does nothing by default:
after the admin check above had rendered `Forbidden` at `/admin`, changing the role and navigating to `/admin`
again changed nothing until the test navigated elsewhere first. If a retry from the same URL must re-run the guards,
configure `+withRouterConfig({ onSameUrlNavigation: 'reload' })+`.

=== What the router does during one navigation

[mermaid]
....
sequenceDiagram
    participant U as URL change
    participant R as Router
    participant G as Guards
    participant S as Resolvers
    participant O as router-outlet
    U->>R: NavigationStart
    R->>R: match routes and run redirects, then RoutesRecognized
    R->>G: GuardsCheckStart, run canMatch / canActivate / canDeactivate
    G-->>R: GuardsCheckEnd (true, false or a UrlTree)
    R->>S: ResolveStart, run resolvers
    S-->>R: ResolveEnd
    R->>O: ActivationStart, ChildActivationStart, create or reuse components
    R-->>U: NavigationEnd
....

Subscribing to `router.events` in a test for `/books/2` printed, in order: `NavigationStart`, `RoutesRecognized`,
`GuardsCheckStart`, then the `ChildActivationStart` / `ActivationStart` pairs for each level of the route tree,
`GuardsCheckEnd`, `ResolveStart`, `ResolveEnd`, the matching `ActivationEnd` / `ChildActivationEnd` events, and
finally `NavigationEnd`. A guard that returns `false` ends with `NavigationCancel` instead, and an exception with
`NavigationError`. A global "busy" indicator is a few lines on top of that stream:

[source,typescript]
----
import { Component, inject } from '@angular/core';
import { toSignal } from '@angular/core/rxjs-interop';
import {
  NavigationCancel, NavigationEnd, NavigationError, NavigationStart, Router,
} from '@angular/router';
import { filter, map } from 'rxjs';

@Component({
  selector: 'app-nav',
  template: `@if (navigating()) { <progress></progress> }`,
})
export class Nav {
  private readonly router = inject(Router);
  readonly navigating = toSignal(
    this.router.events.pipe(
      filter(
        (e) =>
          e instanceof NavigationStart || e instanceof NavigationEnd ||
          e instanceof NavigationCancel || e instanceof NavigationError,
      ),
      map((e) => e instanceof NavigationStart),   // true while a navigation is in flight
    ),
    { initialValue: false },
  );
}
----

== Preloading lazy routes

Lazy loading trades a smaller first download for a delay the first time the user opens a lazy route. A *preloading
strategy* fetches the lazy chunks in the background after the initial render, so the delay disappears for routes the user is
likely to visit:

[source,typescript]
----
import { provideRouter, withPreloading, PreloadAllModules } from '@angular/router';

export const appConfig: ApplicationConfig = {
  providers: [provideRouter(routes, withPreloading(PreloadAllModules))],
};
----

`PreloadAllModules` fetches every lazy route; for a large application, write a custom `PreloadingStrategy` that
inspects a flag in `route.data` and preloads only the important routes, or keep the default (no preloading) and
let `@defer` and route-level splitting do the work. See
xref:web/angular/production-and-performance.adoc[Production and performance] for how to see the resulting chunks.

== Testing routes

`RouterTestingHarness` navigates a real router inside a test and exposes the rendered result, so the table of
outcomes above can be asserted directly. Flip the `Auth` signals to arrange each case:

[source,typescript]
----
beforeEach(() =>
  TestBed.configureTestingModule({ providers: [provideRouter(routes, withComponentInputBinding())] }),
);

it('sends a logged-out visitor to the login page and remembers where they were going', async () => {
  const harness = await RouterTestingHarness.create();
  await harness.navigateByUrl('/books/7?tab=reviews');
  expect(TestBed.inject(Router).url).toBe('/login?returnUrl=%2Fbooks%2F7%3Ftab%3Dreviews');
});

it('binds the resolved book and the query parameter to inputs', async () => {
  TestBed.inject(Auth).loggedIn.set(true);
  const harness = await RouterTestingHarness.create();
  await harness.navigateByUrl('/books/7?tab=reviews');
  expect(harness.routeNativeElement?.textContent).toContain('Book 7');
  expect(harness.routeNativeElement?.textContent).toContain('tab=reviews');
});
----

When the target route is nested, the component `navigateByUrl(url, Type)` returns is the *top-level* routed component
(`Shell` here), not the leaf; assert on `routeNativeElement` or query the harness fixture instead. See
xref:web/angular/testing.adoc[Testing] for the surrounding `TestBed` setup.

== The activation sequence

[mermaid]
....
flowchart TD
    A["URL change"] --> B["Match a route (top to bottom)"]
    B --> C{"CanMatch?"}
    C -- "false / UrlTree" --> B2["Try the next route<br/>or redirect"]
    C -- "true" --> D{"CanActivate /<br/>CanActivateChild?"}
    D -- "false" --> R["Redirect to UrlTree<br/>(e.g. /login)"]
    D -- "true" --> E["Run resolvers<br/>(wait for data)"]
    E --> F["CanDeactivate the<br/>outgoing component?"]
    F -- "false" --> X["Cancel navigation"]
    F -- "true" --> G["Instantiate component,<br/>render into router-outlet"]
....

If any guard returns a `UrlTree`, the router cancels the current navigation and starts a new one to that URL --
the redirect branch above.
