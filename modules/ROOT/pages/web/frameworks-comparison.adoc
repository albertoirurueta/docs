This page compares *42 web frameworks*: client-side UI frameworks and libraries, meta-frameworks, server-driven and server-rendered view layers, and CSS frameworks.
It covers every framework documented on this site plus others that matter because they are popular, because they are growing, or for historical context.
Every number carries a source and a date, and anything that could not be sourced is shown as *n/a* instead of being estimated.
The data snapshot date is *2026-10-27*: all sources were read on that day, and each caption names the edition or measurement date of its data.

The raw data (CSV files), the chart and table generators and the scoring rubric are kept in the repository under `scripts/framework-charts/`; `npm run charts:frameworks` regenerates every figure and table on this page.
Full-stack frameworks are compared once, on the xref:backend/frameworks-comparison.adoc[Backend Frameworks Comparison] (routing, ORM, throughput); this page compares their view layers.
Content-management systems such as WordPress are not frameworks and are compared on the xref:cms/comparison.adoc[CMS Comparison].
Language-level metrics are on the xref:programming-languages/comparative.adoc[Programming Languages Comparative].
Jump to the <<_summary_and_recommendations,Summary and recommendations>> if you only need the conclusions.

== Scope and inclusion criteria

A framework is included when at least one of these holds:

. It has its own section or page on this site: xref:web/react/index.adoc[React], xref:web/angular/index.adoc[Angular], xref:web/vue/index.adoc[Vue.js], xref:web/jquery/index.adoc[jQuery], xref:web/nextjs/index.adoc[Next.js], xref:web/vaadin/index.adoc[Vaadin] (Flow and Hilla), xref:web/jsf/index.adoc[JSF], xref:web/thymeleaf/index.adoc[Thymeleaf], xref:web/jsp-struts/index.adoc[JSP], xref:web/gwt/index.adoc[GWT], xref:web/aspnet/core/blazor-overview-and-render-modes.adoc[Blazor], xref:web/aspnet/core/razor-pages.adoc[Razor Pages], xref:web/django/templates.adoc[Django templates], xref:web/php-laravel/blade-templates.adoc[Laravel Blade], xref:web/php-laravel/livewire.adoc[Livewire] and xref:web/php-laravel/inertia-and-starter-kits.adoc[Inertia], htmx (in the xref:web/thymeleaf/htmx-fundamentals.adoc[Thymeleaf] and axum sections), and the CSS frameworks xref:web/bootstrap/index.adoc[Bootstrap], xref:web/tailwind/index.adoc[Tailwind CSS] and xref:web/sass/index.adoc[Sass] (a preprocessor, for context).
. It appears in the framework lists of State of JS 2025, the Stack Overflow Developer Survey 2025 or the JetBrains survey 2023, or ranks in npm downloads or HTTP Archive detections: Svelte, SolidJS, Preact, Lit, Qwik and Alpine.js; Nuxt, SvelteKit, Remix (now React Router 7), Astro and Angular SSR; Phoenix LiveView and Hotwire; Bulma, Foundation, Material UI and shadcn/ui.
. It matters for history: ASP.NET Web Forms, GWT, jQuery, AngularJS (1.x), Backbone.js, Ember.js and Knockout.

CSS frameworks have their own metrics (popularity, usage on websites, stylesheet size, ease of use) and their own radar; they are never mixed with the JavaScript framework radars.
Frameworks without a section on this site get fewer metrics where data is scarce: the feature matrix and the site-coverage columns are only assessed for the documented ones.
Every framework name links to its section on this site, or to its official website when the site has no section.

*Radar scores (0 to 10, higher is better).* Each radar axis is either *computed* (C) or *editorial* (E), relative to the frameworks on this page; CSS frameworks are scored among themselves.

* *Popularity (C)*: survey usage relative to the most used framework, registry downloads (npm for most frameworks; a framework on several registries is scored in the one with the most frameworks on this page, so Inertia is ranked on npm), GitHub stars and HTTP Archive origins, the last three on a log scale.
* *Growth (C)*: change in survey usage (2023 to 2025), in npm downloads year over year and in State of JS usage, each scaled between the slowest and fastest grower.
* *Talent pool and jobs (C)*: professional survey usage and Hacker News job-posting share, relative to the best framework.
* *Ease of use, Ecosystem and maturity, Productivity (E)*: written rubric, with a basis per framework in the <<_radar_comparisons,radar tables>>.
* *Runtime performance (C)*: js-framework-benchmark CPU factor `f`, `10 × (1 − log2(f) / 3)`; 8 times slower than the fastest scores 0.
* *Bundle size (C)*: compressed size of the benchmark application relative to the smallest, on a log scale; 100 times larger scores 0.
* *Performance (C)*: mean of runtime performance, bundle size and the Core Web Vitals mobile pass rate relative to the best.

The full formulas, the rubric and the method of every dataset are in `scripts/framework-charts/data/NOTES.md`.

== Overview and timeline

jQuery (on npm since 2011), Backbone.js, Knockout and AngularJS (on npm since 2011 and 2012) shaped the early single-page applications; React's first npm release by the project dates from 2012 and Angular 2 and later (`@angular/core`) from 2016.
The component and compiler generation followed: Vue.js (2013), Svelte (2016), SolidJS (2018), Qwik and Astro (2021). Meta-frameworks arrived with Next.js and Nuxt (2016).
AngularJS reached its end of life on 2021-12-31 (endoflife.date).

== Ease of use and learning curve

Ease of use is an editorial score (rubric above, basis per framework in the <<_radar_comparisons,radar tables>>).
Libraries close to HTML (Vue.js, Svelte, Alpine.js, htmx, Thymeleaf) are quickest to start; React is small but needs a router and a framework choice; Angular asks for TypeScript, dependency injection, RxJS and signals before the first page, and Next.js's App Router and caching rules take time to master.
State of JS retention supports the picture: Astro (94%), SolidJS (90%), SvelteKit (88.7%) and Svelte (87%) keep their users best, Angular (48.1%) and Next.js (55.3%) least.
For tools and editors see xref:web/ides-and-tools.adoc[IDEs and tools]; for UI component libraries in the Java world see xref:web/vaadin/ui-component-libraries.adoc[Vaadin UI component libraries].

== Ecosystem and maturity

Angular publishes a dated support window per major (version 22 to 2028-06-30) and shipped ten majors in five years; React and Vue.js have no announced end-of-life date for their current major on endoflife.date, and Vue.js shipped no new major in five years.
Next.js had 88 releases in 12 months and Astro 113, while Bootstrap, Bulma and Foundation had none.

== Performance

*Runtime performance.* In js-framework-benchmark (Chrome 156, keyed implementations), the weighted geometric mean of the CPU benchmarks is 1.14 times the fastest for SolidJS, 1.19 for Svelte, 1.28 for Lit, 1.30 for Vue.js, 1.53 for Angular and 1.56 for React; vanilla JavaScript is 1.02.
Blazor WebAssembly (4.88), Qwik (3.31) and Alpine.js (2.98) are the slowest of the frameworks shown; jQuery, htmx and Backbone have no keyed implementation.

== Summary and recommendations

These recommendations are an *editorial judgement* built on the data above; each cites the metric it relies on. The snapshot date is 2026-10-27, and surveys, downloads and Core Web Vitals change every month, so re-check the numbers before a decision that will last years.

*Mainstream choices.*

* *xref:web/react/index.adoc[React] with xref:web/nextjs/index.adoc[Next.js]* has the largest talent pool (44.7% survey usage, 21.82% of 2025 hiring postings) and the most downloads; mind Next.js's lower retention (55.3%) and its advisory count (77).
* *xref:web/angular/index.adoc[Angular]* is the complete toolkit for large teams (the full feature matrix and a dated support window per major), at the cost of the lowest retention here (48.1%).
* *xref:web/vue/index.adoc[Vue.js] with Nuxt* combines high retention (84.5%) with official router and state libraries and a gentle learning curve.

*Trends to watch.* The data support Astro (State of JS retention 94%, origins up from 466 to 49,450 since January 2023), Svelte (62.4% admired, State of JS usage 14.5% to 27.5% since 2020), SolidJS (the best benchmark and Core Web Vitals results) and htmx (origins up from 1,235 to 25,156 since January 2023), plus Tailwind CSS for styling.

*Avoid for new projects, keep for legacy maintenance.*

* *AngularJS* reached its end of life on 2021-12-31 and its admired score is 21.9%; migrate to Angular or another framework.
* *xref:web/gwt/index.adoc[GWT]* has had no major release in five years and one of the lowest Core Web Vitals pass rates here (23.06% on mobile); *xref:web/jsp-struts/index.adoc[JSP] as a view layer* mixes logic into pages and has no component model. Thymeleaf or Vaadin fit new Java UIs better.
* *xref:web/jquery/index.adoc[jQuery] for new single-page applications*: it still runs on 64.4% of websites (W3Techs) but its survey usage fell from 48.7% (2019) to 23.4% (2025); keep it for existing pages.
* *xref:web/aspnet/web-forms/index.adoc[ASP.NET Web Forms]* runs on .NET Framework (current cycle 4.8.1 on endoflife.date), not on modern .NET; see the xref:backend/frameworks-comparison.adoc[Backend Frameworks Comparison].

*Hiring perspective.* React, jQuery, Next.js, Angular and Vue.js have the largest pools (professional survey usage); React and Next.js lead job postings. Svelte, SolidJS, Astro and htmx are niche but growing: easy to motivate developers for, harder to staff quickly.

For most teams the right choice is the one their back end and their developers already support; the metrics above matter most for performance-sensitive public sites and for hiring.
