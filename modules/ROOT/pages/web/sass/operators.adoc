= Operators
:description: Covers Sass operators -- arithmetic including the slash-as-division deprecation and math.div, unit arithmetic, string concatenation, comparison operators, boolean and or not, and operator precedence.
:keywords: Sass operators, Sass arithmetic, math.div, slash division deprecated, Sass units, string concatenation, comparison operators, boolean operators, and or not, operator precedence, interpolation

include::partial$ai-disclaimer.adoc[]

Sass evaluates expressions at compile time, so arithmetic, comparisons, and boolean logic can be written
directly in property values, variable declarations, and control-flow conditions. Everything on this page is
resolved before the browser ever sees the stylesheet.

== Arithmetic

[cols="1,3,2", options="header"]
|===
| Operator | Meaning | Example

| `+`
| Addition (also string concatenation)
| `8px + 4px` → `12px`

| `-`
| Subtraction
| `2rem - 0.5rem` → `1.5rem`

| `+*+`
| Multiplication
| `+8px * 3+` → `24px`

| `%`
| Modulo (remainder)
| `13 % 5` → `3`

| `math.div()`
| Division
| `math.div(100%, 3)` → `33.3333333333%`
|===

[source,scss]
----
@use "sass:math";

$base:    8px;
$gutter:  $base * 2;             // 16px
$half:    math.div($gutter, 2);  // 8px
$rest:    $base % 3;             // 2px

.grid {
  gap: $gutter;
  padding: $base + 4px;          // 12px
  width: math.div(100%, 3);      // 33.3333333333%
}
----

=== Division: use `math.div()`, not `/`

This is the single most important gotcha in Sass arithmetic. `/` was historically overloaded: it means division
in Sass, but it is also plain CSS syntax in values such as `font: 16px/1.5` and `grid-area: 1 / 3`. Sass had to
guess which was meant, and the heuristics were a frequent source of bugs.

Dart Sass therefore **deprecated `/` as a division operator**. Use `math.div()`:

[source,scss]
----
@use "sass:math";

// Deprecated -- emits a warning, and may not divide at all
$bad: 100px / 3;

// Correct
$good: math.div(100px, 3);       // 33.3333333333px
----

`/` is now treated as a plain separator, so `font: 16px/1.5` and `grid-area: 1 / 3` pass through to the CSS
untouched, which is what you want. To *build* a slash-separated value from variables, use `list.slash()` or
interpolation:

[source,scss]
----
@use "sass:list";

$size: 16px;
$lh: 1.5;

.a { font: #{$size}/#{$lh} sans-serif; }   // via interpolation
.b { font: list.slash($size, $lh) sans-serif; }
----

Note that interpolation produces an unquoted string, so the result can no longer be used in further arithmetic.

=== Units

Sass tracks units and applies real dimensional analysis, which catches genuine mistakes at compile time:

[source,scss]
----
@use "sass:math";

$a: 10px + 5px;          // 15px      -- same unit, fine
$b: 10px * 2;            // 20px      -- unit x unitless
$c: math.div(10px, 2);   // 5px       -- unit / unitless
$d: math.div(10px, 2px); // 5         -- units cancel, result is unitless
$e: 10px + 5;            // 15px      -- a unitless number adopts the other unit
$f: 1in + 10px;          // 1.1041666667in -- compatible units are converted
$g: 10px + 5em;          // ERROR: 10px and 5em have incompatible units
$h: 10px * 2px;          // valid number with unit px*px; written to CSS as calc(20px * 1px)
----

Two consequences worth internalising:

* **Multiplying two lengths gives you `+px*px+`**, which is not a valid CSS unit. Sass serializes it as
  `+calc(20px * 1px)+`, which a browser will reject for most properties. If you find yourself writing `+$a * $b+` with
  both carrying units, one of them should probably be unitless.
* **To strip a unit, divide by one of the same unit** -- `math.div($n, 1px)` when you know the unit, or
  `pass:c[math.div($n, ($n * 0 + 1))]` when you do not.

A *unitless* number is compatible with every unit, which is a frequent surprise: `10px + 5` is `15px`, and the
comparison `10px > 5` is `true`. Only two numbers that both carry *different, unrelated* units (`px` and `em`,
`px` and `%`) are an error. Compatible units -- the absolute lengths `in`, `cm`, `mm`, `pt`, `pc`, `px`, or `s` and
`ms`, or `deg` and `rad` -- are converted automatically.

`%` is a unit like any other in Sass, so `50% + 10%` works but `50% + 10px` is an error.

=== Arithmetic and `calc()`

CSS's `calc()` is evaluated by the *browser*, not by Sass. Modern Dart Sass parses `calc()` expressions, may
simplify them where all units are compatible, and lets Sass variables appear inside them without interpolation:

[source,scss]
----
$sidebar: 280px;
$gap: 16px;
$cols: 3;

.a {
  w: calc(100% - $sidebar);                              // calc(100% - 280px)
  b: calc(100% - #{$sidebar} - #{$gap * 2});             // calc(100% - 280px - 32px)
  c: calc((100% - #{$gap * ($cols - 1)}) / #{$cols});    // calc((100% - 32px) / 3)
  e: calc(var(--x) + $gap);                              // calc(var(--x) + 16px)
  f: calc(1px + 2px * 3);                                // 7px -- Sass could simplify it
  g: calc(100% / 3);                                     // 33.3333333333%
}
----

Plain variables work as they are. Interpolation (`+#{...}+`) is only needed when the value comes from a Sass
*expression* such as `+$gap * 2+`, which would otherwise be left for the browser to see as `+$gap * 2+`.

Use `calc()` when the computation genuinely needs runtime values -- mixing `%` with `px`, or referencing a CSS
custom property. Use Sass arithmetic when everything is known at build time, since it produces a plain literal and
costs the browser nothing:

[mermaid]
....
flowchart TD
    Q{"Is every input known<br/>when Sass compiles?"}
    Q -- yes --> S["Sass arithmetic or math functions<br/>result: a literal number in the CSS"]
    Q -- no --> C["calc() with var() or mixed units<br/>result: the browser computes it"]
    S --> O1["20px"]
    C --> O2["calc(100% - 280px)"]
....

=== Whitespace around `-`

Hyphens are legal in Sass identifiers, so the minus operator needs spaces. The cases below were compiled to see what
each does:

[source,scss]
----
$a: 10px;
$b: 3px;

.a {
  w1: $a - $b;   // 7px
  w5: -$b;       // -3px (unary minus)
  w7: 5-2;       // 3    (two numbers, so subtraction)
  w9: 5 -2;      // 5 -2 (a two-element list)
}

.bad { x: $a-$b; }   // ERROR: Undefined variable -- Sass looks for a variable named $a-
----

The `strict-unary` deprecation warning flags the ambiguous `$a -$b` form for the same reason. Write binary minus with a
space on each side.

== String operators

`+` concatenates strings. The quoting of the *left* operand determines the quoting of the result:

[source,scss]
----
$a: "foo" + "bar";      // "foobar"   (quoted)
$b: "foo" + bar;        // "foobar"   (quoted -- left operand wins)
$c: foo + "bar";        // foobar     (unquoted)
$d: foo + bar;          // foobar     (unquoted)
----

`-` and `/` between unquoted strings produce hyphen- and slash-separated unquoted strings, which is occasionally
useful but usually clearer via interpolation.

In practice, **interpolation is the better tool** for building strings, especially where a value must become
part of a selector or property name:

[source,scss]
----
$icon: "chevron";
$dir: left;

.icon-#{$icon}-#{$dir} {
  background-image: url("/icons/#{$icon}-#{$dir}.svg");
  margin-#{$dir}: 4px;
}
----

See xref:web/sass/built-in-modules.adoc[Built-in Modules] for `sass:string` functions such as `string.quote()`
and `string.unquote()`.

== Comparison operators

[cols="1,3,2", options="header"]
|===
| Operator | Meaning | Example

| `==`
| Equal
| `$theme == dark`

| `!=`
| Not equal
| `$size != null`

| `<`
| Less than
| `$width < 768px`

| `>`
| Greater than
| `$count > 0`

| `+<=+`
| Less than or equal
| `+$level <= 3+`

| `>=`
| Greater than or equal
| `$px >= 16px`
|===

`==` and `!=` work on every Sass type. The relational operators (`<`, `>`, `+<=+`, `>=`) apply only to numbers,
and the numbers must have compatible units (a unitless number counts as compatible):

[source,scss]
----
@if 768px < 1024px { /* true */ }
@if 1in > 50px     { /* true -- units converted */ }
@if 10px > 5       { /* true -- a unitless number is compatible with any unit */ }
@if 10px > 5em     { /* ERROR: incompatible units */ }
----

Equality is strict about type: `1 == 1px` is `false`, and `"foo" == foo` is `true` (quoting does not affect
string equality). It is also case-sensitive throughout -- `1px == 1PX` is `false` (unit names are compared
character-for-character, unlike in plain CSS) and `"a" == "A"` is `false` for strings.

== Boolean operators

Sass uses the words `and`, `or`, and `not` -- not `&&`, `||`, or `!`.

[source,scss]
----
@use "sass:math";

@mixin responsive-font($size, $scale: true) {
  @if $scale and $size > 16px {
    font-size: math.div($size, 1.2);
  } @else if not $scale or $size <= 16px {
    font-size: $size;
  }
}
----

`and` and `or` short-circuit, so the right operand is not evaluated when the left already decides the result.

**Truthiness**: everything is truthy except `false` and `null`. Notably `0`, `""` (the empty string), and `()`
(the empty list) are all **truthy** in Sass -- the opposite of JavaScript. This trips people up regularly:

[source,scss]
----
$value: 0;
@if $value { /* this RUNS -- 0 is truthy in Sass */ }

$missing: map.get($config, nope);   // returns null when absent
@if $missing { /* correctly skipped -- null is falsy */ }
----

== Precedence

From highest to lowest:

. Unary `not`, unary `-`
. `+*+`, `%`, and `math.div()` calls
. `+`, `-`
. `<`, `+<=+`, `>`, `>=`
. `==`, `!=`
. `and`
. `or`

Parentheses override precedence and are worth adding freely -- they cost nothing in the output and make intent
obvious:

[source,scss]
----
@use "sass:math";

$a: 2 + 3 * 4;                    // 14
$b: (2 + 3) * 4;                  // 20
$c: math.div($total, $count) + 1; // clearer than relying on precedence
----

One caveat: parentheses around a comma-separated value create a **list**, not a grouped expression -- `(1, 2)`
is a two-element list, while `(1 + 2)` is the number `3`. See xref:web/sass/lists-maps.adoc[Lists & Maps].

== Helpers that go with the operators

The `sass:math` module covers what the operators cannot. Each result below was produced by the compiler:

[source,scss]
----
@use "sass:math";

.units {
  a: math.unit(10px * 2);               // "px"
  b: math.is-unitless(5);               // true
  c: math.round(2.5) math.ceil(2.1) math.floor(2.9);   // 3 3 2
  d: clamp(1rem, 5vw, 2rem);            // plain CSS clamp(), passed through
  e: math.compatible(1in, 1px);         // true
  f: math.pow(2, 10);                   // 1024
  g: math.sqrt(16);                     // 4
  h: math.percentage(math.div(1, 3));   // 33.3333333333%
}
----

Note `clamp()` on its own line: it is the CSS function, and Sass leaves it for the browser. `math.clamp()` is the
Sass version, which requires compatible units and would reject `1rem` mixed with `5vw`. Sass prints numbers with at
most ten digits after the decimal point, so `math.div(100%, 3)` is `33.3333333333%`.

== Worked example: a modular type scale and a fluid grid

A modular type scale multiplies a base size by a constant ratio raised to the step number. Converting the result to
`rem` keeps it relative to the user's font setting, and a column grid turns counts into percentages. Both need only
the operators and `sass:math`:

[source,scss]
----
@use "sass:math";

$root-size: 16px;
$ratio: 1.25;
$columns: 12;
$gutter: 24px;

@function rem($px) {
  @return math.div($px, $root-size) * 1rem;
}

@function step($n) {
  @return rem($root-size * math.pow($ratio, $n));
}

h1    { font-size: step(3); }
h2    { font-size: step(2); }
p     { font-size: step(0); }
small { font-size: step(-1); }

@for $i from 1 through 3 {
  .col-#{$i} { width: math.percentage(math.div($i, $columns)); }
}

.col-4 { width: calc(#{math.percentage(math.div(4, $columns))} - #{$gutter}); }
.col-5 { width: calc(#{math.percentage(math.div(5, $columns))} - #{math.div($gutter, 2)}); }
----

[source,css]
----
h1 {
  font-size: 1.953125rem;
}

h2 {
  font-size: 1.5625rem;
}

p {
  font-size: 1rem;
}

small {
  font-size: 0.8rem;
}

.col-1 {
  width: 8.3333333333%;
}

.col-2 {
  width: 16.6666666667%;
}

.col-3 {
  width: 25%;
}

.col-4 {
  width: calc(33.3333333333% - 24px);
}

.col-5 {
  width: calc(41.6666666667% - 12px);
}
----

The two kinds of computation sit side by side. Everything that is known at build time (`step(3)`, the column
percentage) is reduced to a literal. The `calc()` in `.col-4` stays, because a percentage and a pixel gutter cannot
be combined until the browser knows the width of the container. The functions are covered in
xref:web/sass/functions.adoc[Functions].
