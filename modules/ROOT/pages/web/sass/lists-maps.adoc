= Lists and Maps
:description: Covers Sass lists -- comma, space and slash separated, indexing from 1, and the sass:list functions -- and maps, their (key: value) syntax, lookup and update with sass:map, plus worked breakpoint and palette examples.
:keywords: Sass lists, Sass maps, list.nth, list.append, list.index, map.get, map.set, map.merge, map.keys, map.values, breakpoints map, design tokens, immutable, nested maps

include::partial$ai-disclaimer.adoc[]

Lists and maps are Sass's two collection types. They are what turn a stylesheet from a pile of literal values
into something driven by a single source of truth -- a palette, a spacing scale, a set of breakpoints.

Both are **immutable**. Every "modifying" function returns a *new* collection rather than changing the original,
so results must be reassigned.

[mermaid]
....
flowchart LR
    V1["$scale<br/>(1: 4px)"] --> F["map.set($scale, 2, 8px)"]
    F --> N["new map<br/>(1: 4px, 2: 8px)"]
    F -. "unchanged" .-> V1
    N --> A["$scale: ... reassigns<br/>the variable to the new map"]
    F -.-> X["Without the assignment<br/>the new map is discarded"]
....

== Lists

A list is an ordered sequence of values. Sass is unusually relaxed about how one is written: elements may be
separated by commas, spaces, or slashes, and the surrounding parentheses are optional in most positions.

[source,scss]
----
$comma-list: 10px, 20px, 30px;
$space-list: 10px 20px 30px;
$font-stack: "Inter", "Helvetica Neue", sans-serif;
$shorthand: 1px solid #ccc;          // yes, this is a 3-element list
$nested: (1px 2px), (3px 4px);       // a 2-element list of 2-element lists
$empty: ();
$single: (10px,);                    // trailing comma forces a 1-element list
----

The key insight is that **ordinary CSS values already are lists**. `margin: 10px 20px` is a space-separated
two-element list, and `font-family: a, b, c` is a comma-separated three-element list. This is why a list's
separator is preserved through the compiler -- it becomes the punctuation in the output.

=== List functions

Load `sass:list`. **Sass lists are 1-indexed**, which is the single most common source of off-by-one bugs for
anyone arriving from another language.

[cols="2,3,2", options="header"]
|===
| Function | Description | Example

| `list.nth($list, $n)`
| Element at position `$n` (1-based; negative counts from the end)
| `list.nth(a b c, 2)` → `b`

| `list.length($list)`
| Number of elements
| `list.length(a b c)` → `3`

| `list.index($list, $v)`
| Position of `$v`, or `null` if absent
| `list.index(a b c, b)` → `2`

| `list.append($list, $v)`
| New list with `$v` added at the end
| `list.append(a b, c)` → `a b c`

| `list.join($l1, $l2)`
| Concatenates two lists
| `list.join(a b, c d)` → `a b c d`

| `list.separator($list)`
| `comma`, `space`, or `slash`
| `list.separator((a, b))` → `comma`

| `+list.slash($v1, $v2...)+`
| Builds a slash-separated list
| `list.slash(16px, 1.5)` → `16px / 1.5`

| `+list.zip($l1, $l2...)+`
| Combines lists element-wise
| `list.zip(1px 2px, solid dashed)` → `1px solid, 2px dashed`

| `list.is-bracketed($list)`
| Whether the list uses `[ ]`
| `list.is-bracketed([a b])` → `true`
|===

[source,scss]
----
@use "sass:list";

$shadows: (0 1px 2px rgb(0 0 0 / 0.1),);   // trailing comma forces a comma-separated list
$shadows: list.append($shadows, 0 4px 12px rgb(0 0 0 / 0.15));

.card { box-shadow: $shadows; }
----

Note the reassignment -- `list.append` returns a new list, it does not mutate `$shadows` in place. The base list
must already be comma-separated (hence the trailing-comma trick above): appending to a *space*-separated list and
passing `$separator: comma` doesn't wrap the new element in, it re-separates every existing element too, turning
`+0 1px 2px rgba(...)+` into four comma-joined pieces instead of one shadow.

=== Iterating a list

[source,scss]
----
$sides: top, right, bottom, left;

@each $side in $sides {
  .p-#{$side} { padding-#{$side}: 8px; }
  .m-#{$side} { margin-#{$side}: 8px; }
}
----

=== Gotchas

* **A single value is a one-element list.** `list.length(10px)` is `1`, and `list.nth(10px, 1)` is `10px`. This
  makes functions that accept "one or several" values easy to write.
* **`()` is both the empty list and the empty map.** They are the same value; `map.get((), x)` returns `null`.
* **Parentheses around a comma expression create a list, not a group.** `(1, 2)` is a list; `(1 + 2)` is `3`.
* **Comma beats space in nesting.** In `1px 2px, 3px 4px`, the comma is the outer separator, giving a
  two-element list of two-element lists.

=== Joining lists, separators and brackets

`list.join()` concatenates two lists. By default the result takes the separator of the first list (or of the second
when the first has fewer than two elements); `$separator:` forces one, and `$bracketed: true` wraps the result in
square brackets, the syntax CSS uses for grid line names:

[source,scss]
----
@use "sass:list";

$a: 1px 2px;
.l {
  join-space: list.join($a, 3px 4px);
  join-comma: list.join($a, 3px 4px, $separator: comma);
  join-brk:   list.join($a, 3px, $bracketed: true);
  set:        list.set-nth(a b c, 2, X);
  neg:        list.nth(a b c, -2);
  zip:        list.zip(a b, 1 2);
  slashed:    list.slash(10px, 20px, 30px);
}
----

[source,css]
----
.l {
  join-space: 1px 2px 3px 4px;
  join-comma: 1px, 2px, 3px, 4px;
  join-brk: [1px 2px 3px];
  set: a X c;
  neg: b;
  zip: a 1, b 2;
  slashed: 10px / 20px / 30px;
}
----

`list.set-nth()` replaces one element and returns a new list, and `list.index()` of a value that is absent returns
`null`, which makes a property that uses it disappear from the output rather than print `null`.

Building a list in a loop uses the same reassign-the-result idiom as maps. The next example collects names from a
list of maps (the records table in a later section) and uses the result as a comma-separated property value:

[source,scss]
----
@use "sass:list";
@use "sass:map";

$team: (
  (name: "Ada",   role: admin,  active: true),
  (name: "Grace", role: editor, active: true),
  (name: "Alan",  role: viewer, active: false)
);

$names: ();
@each $m in $team { $names: list.append($names, map.get($m, name), comma); }
.names { list: $names; len: list.length($names); }
----

[source,css]
----
.names {
  list: "Ada", "Grace", "Alan";
  len: 3;
}
----

== Maps

A map associates keys with values. It must always be written with parentheses:

[source,scss]
----
$theme-colours: (
  primary: #3f51b5,
  success: #43a047,
  warning: #fb8c00,
  danger:  #e53935
);

$breakpoints: (
  "sm": 576px,
  "md": 768px,
  "lg": 992px,
  "xl": 1200px
);
----

Keys may be any Sass value -- unquoted strings (as above) are conventional and read well. Quoted and unquoted
strings compare equal, so `map.get($breakpoints, md)` and `map.get($breakpoints, "md")` both work.

Maps are *not* valid CSS values: a map cannot be used as a property value directly. It exists purely as
compile-time data.

=== Map functions

Load `sass:map`.

[cols="2,3,2", options="header"]
|===
| Function | Description | Example

| `map.get($map, $key)`
| Value for `$key`, or `null` if absent
| `map.get($bp, md)` → `768px`

| `map.set($map, $key, $v)`
| New map with `$key` set
| `map.set($bp, xxl, 1400px)`

| `map.merge($m1, $m2)`
| New map combining both; `$m2` wins on conflicts
| `map.merge($defaults, $overrides)`

| `+map.remove($map, $keys...)+`
| New map without those keys
| `map.remove($bp, sm)`

| `map.has-key($map, $key)`
| Whether the key exists
| `map.has-key($bp, md)` → `true`

| `map.keys($map)`
| Comma-separated list of keys
| `map.keys($bp)` → `sm, md, lg, xl`

| `map.values($map)`
| Comma-separated list of values
| `map.values($bp)` → `+576px, 768px, ...+`
|===

`map.get`, `map.set`, and `map.has-key` also accept multiple keys to reach into **nested maps**:

[source,scss]
----
@use "sass:map";

$config: (
  colours: (
    brand: (primary: #3f51b5, secondary: #7986cb),
    state: (error: #e53935)
  )
);

$primary: map.get($config, colours, brand, primary);   // #3f51b5
$config: map.set($config, colours, state, warning, #fb8c00);
----

Without the multi-key form this would be a chain of nested `map.get()` calls, each needing its own null check.

=== Types, equality and deep operations

`meta.type-of()` tells the two collection types apart, which a recursive helper needs in order to know whether a value
is a leaf or another map. Note that the empty parentheses are both:

[source,scss]
----
@use "sass:meta";

.types {
  empty: meta.type-of(());          // list
  map: meta.type-of((a: 1));        // map
  pair: meta.type-of(1 2);          // list
  word: meta.type-of(a);            // string
}
----

[source,css]
----
.types {
  empty: list;
  map: map;
  pair: list;
  word: string;
}
----

Two maps are equal when they have the same keys with equal values, in *any* order: `(a: 1, b: 2) == (b: 2, a: 1)`
is `true`. Writing the same key twice in one map literal is a compile error (`Duplicate key`), so a typo in a large
token map is caught rather than silently shadowed.

The plain `map.merge()` is *shallow*: if both maps have a nested map under the same key, the second one replaces the
first outright. Two functions work through the nesting instead:

[cols="2,3", options="header"]
|===
| Function | Behaviour

| `map.deep-merge($m1, $m2)`
| Merges nested maps recursively, so only the leaves in `$m2` replace those in `$m1`

| `+map.deep-remove($map, $keys...)+`
| Removes the entry at the end of a key path, leaving siblings alone

| `+map.merge($map, $keys..., $m2)+`
| Merges `$m2` into the nested map found by following `$keys`
|===

[source,scss]
----
@use "sass:map";
@use "sass:meta";

$cfg: (colours: (brand: (primary: #3f51b5)));
$merged: map.merge($cfg, colours, brand, (secondary: #7986cb));
@debug meta.inspect($merged);
----

The `@debug` output (on standard error, not in the CSS) shows the second colour added beside the first:

----
(colours: (brand: (primary: #3f51b5, secondary: #7986cb)))
----

=== Worked example: a responsive breakpoints map

This is the single most common real use of a map -- one source of truth for breakpoints, consumed by a mixin
(see xref:web/sass/mixins.adoc[Mixins]):

[source,scss]
----
@use "sass:map";

$breakpoints: (
  sm: 576px,
  md: 768px,
  lg: 992px,
  xl: 1200px
) !default;

@mixin respond-to($name) {
  $width: map.get($breakpoints, $name);

  @if $width == null {
    @error "Unknown breakpoint `#{$name}`. Available: #{map.keys($breakpoints)}.";
  }

  @media (min-width: $width) {
    @content;
  }
}

.container {
  padding: 0 16px;

  @include respond-to(md) { max-width: 720px; margin: 0 auto; }
  @include respond-to(lg) { max-width: 960px; }
  @include respond-to(xl) { max-width: 1140px; }
}
----

[source,css]
----
.container { padding: 0 16px; }
@media (min-width: 768px) { .container { max-width: 720px; margin: 0 auto; } }
@media (min-width: 992px) { .container { max-width: 960px; } }
@media (min-width: 1200px) { .container { max-width: 1140px; } }
----

The `!default` on `$breakpoints` means a consumer can supply their own scale via `+@use ... with+` (see
xref:web/sass/partials-modules.adoc[Partials & Modules]), and the `@error` guard turns a typo into a clear
compile-time failure naming the valid options, rather than a silently missing media query.

=== Worked example: a palette with generated utilities

[source,scss]
----
@use "sass:map";
@use "sass:color";

$palette: (
  primary: #3f51b5,
  success: #43a047,
  danger:  #e53935
);

// Derive light/dark variants without hand-writing them
@each $name, $base in $palette {
  .bg-#{$name}       { background: $base; }
  .bg-#{$name}-light { background: color.adjust($base, $lightness: 20%); }
  .bg-#{$name}-dark  { background: color.adjust($base, $lightness: -15%); }
  .text-#{$name}     { color: $base; }
}
----

Adding one entry to `$palette` now produces four more classes automatically -- see
xref:web/sass/control-flow.adoc[Control Flow] for the loop constructs and
xref:web/sass/built-in-modules.adoc[Built-in Modules] for `color.adjust()`.

=== Iterating a map

`@each` with two variables destructures each entry:

[source,scss]
----
@each $name, $value in $breakpoints {
  .min-#{$name} { min-width: $value; }
}
----

Map iteration order is the insertion order, so the output is deterministic and matches how the map was written.

=== Worked example: light and dark themes from maps

A theme is naturally a nested map: groups of related tokens, each holding named values. Define the light theme in full,
give the dark theme only the entries that differ, and combine them with `map.deep-merge()` so everything else is
inherited. A recursive mixin then flattens either map into CSS custom properties, using `meta.type-of()` to decide
whether to descend:

[source,scss]
----
@use "sass:map";
@use "sass:meta";

$base: (
  surface: (page: #ffffff, card: #f5f5f5),
  text: (body: #212121, muted: #616161),
  accent: #3f51b5
);

$dark-overrides: (
  surface: (page: #121212, card: #1e1e1e),
  text: (body: #eeeeee, muted: #b0b0b0)
);

$dark: map.deep-merge($base, $dark-overrides);

@mixin emit-tokens($tokens, $prefix: "") {
  @each $key, $value in $tokens {
    @if meta.type-of($value) == map {
      @include emit-tokens($value, "#{$prefix}#{$key}-");
    } @else {
      --#{$prefix}#{$key}: #{$value};
    }
  }
}

:root { @include emit-tokens($base); }
[data-theme="dark"] { @include emit-tokens($dark); }
----

[source,css]
----
:root {
  --surface-page: #ffffff;
  --surface-card: #f5f5f5;
  --text-body: #212121;
  --text-muted: #616161;
  --accent: #3f51b5;
}

[data-theme=dark] {
  --surface-page: #121212;
  --surface-card: #1e1e1e;
  --text-body: #eeeeee;
  --text-muted: #b0b0b0;
  --accent: #3f51b5;
}
----

The dark theme never mentions `accent`, yet it appears in the output because the deep merge kept it; with a shallow
`map.merge()` the entire `surface` and `text` groups of the light theme would have been replaced by the override and
any entry missing from the override (such as a future `text-disabled` token) would have vanished from the dark
theme. Note also that interpolating the value, as in `+#{$value}+`, is required for custom properties, as the
xref:web/sass/variables.adoc[Variables] page explains.

=== Worked example: validated configuration

Library code often accepts a map of options. Merging with `map.deep-merge()` fills in defaults, and checking the
user's keys against the defaults with `map.keys()` and `map.has-key()` turns a misspelled option into an error that names
the valid ones:

[source,scss]
----
@use "sass:map";
@use "sass:meta";

$defaults: (columns: 12, gutter: 16px, breakpoints: (sm: 576px, md: 768px));

@function configure($user: ()) {
  @each $key in map.keys($user) {
    @if not map.has-key($defaults, $key) {
      @error "Unknown option `#{$key}`. Valid options: #{map.keys($defaults)}.";
    }
  }
  @return map.deep-merge($defaults, $user);
}

$cfg: configure((gutter: 24px, breakpoints: (lg: 992px)));
.cfg {
  columns: map.get($cfg, columns);
  gutter: map.get($cfg, gutter);
  bps: meta.inspect(map.get($cfg, breakpoints));
}
----

[source,css]
----
.cfg {
  columns: 12;
  gutter: 24px;
  bps: (sm: 576px, md: 768px, lg: 992px);
}
----

Calling `configure((colums: 8))` instead stops the build with:

----
Error: "Unknown option `colums`. Valid options: columns, gutter, breakpoints."
----

=== Worked example: a list of maps as a table of records

A list whose elements are maps works as a small table. `@each` visits one record at a time and `map.get()` reads its
fields, so data that would otherwise need parallel lists stays together:

[source,scss]
----
@use "sass:map";

$team: (
  (name: "Ada",   role: admin,  active: true),
  (name: "Grace", role: editor, active: true),
  (name: "Alan",  role: viewer, active: false)
);

@each $member in $team {
  @if map.get($member, active) {
    .role-#{map.get($member, role)}::after { content: map.get($member, name); }
  }
}
----

[source,css]
----
.role-admin::after {
  content: "Ada";
}

.role-editor::after {
  content: "Grace";
}
----

The inactive record is skipped by the `@if`, so no rule is emitted for it.

== Immutability in practice

Because both types are immutable, a loop that builds up a collection must reassign each time:

[source,scss]
----
@use "sass:map";
@use "sass:math";

$scale: ();
@for $i from 1 through 6 {
  $scale: map.set($scale, $i, 4px * $i);   // reassign -- map.set returns a new map
}
// $scale is now (1: 4px, 2: 8px, 3: 12px, 4: 16px, 5: 20px, 6: 24px)
----

Forgetting the reassignment is a silent no-op: the function computes a new collection and throws it away. If a
map or list "isn't updating", this is almost always why.
