Welcome to the SASS reference. Sass is a CSS preprocessor: it adds variables, nesting, mixins, functions, and a
real module system on top of CSS, then compiles down to the plain CSS browsers understand. This section is
organized by topic, from the two syntaxes through the language features to the build step that turns it all into
CSS, so you can jump straight to what you need, or work through it top to bottom as a refresher.

[NOTE]
====
This section documents **Sass/SCSS as implemented by https://sass-lang.com/dart-sass/[Dart Sass]**, the current official and actively maintained compiler -- it is not tied to any specific book, build tool, or CSS framework (Bootstrap, Bulma, etc.).
Sass continues to evolve, so behaviour described here may lag the compiler you are actually running.
====

If you are new to Sass, read xref:web/sass/syntax.adoc[Syntax] and xref:web/sass/variables.adoc[Variables]
first, then xref:web/sass/compilation.adoc[Compilation] to get a build running.

== What's covered

* xref:web/sass/syntax.adoc[Syntax: SCSS vs. Sass] -- the two syntaxes Dart Sass accepts, the same stylesheet
  written both ways, why SCSS is the practical default, and Sass's silent `//` comments.
* xref:web/sass/variables.adoc[Variables] -- `$name: value` declarations, global vs. local scope and the
  `!global` flag, overridable defaults with `!default`, and how Sass variables differ from CSS custom
  properties.
* xref:web/sass/nesting.adoc[Nesting] -- nested selectors and how they flatten, the `&` parent selector for
  pseudo-classes and BEM-style suffixes, nested properties and media queries, and how this compares to native
  CSS nesting.
* xref:web/sass/partials-modules.adoc[Partials & Modules] -- `_partial.scss` files, loading modules with `@use`
  (namespaces, `as`, `with`), re-exporting with `@forward` (`show`/`hide`, prefixes), and why `@import` is
  deprecated.
* xref:web/sass/mixins.adoc[Mixins] -- `@mixin`/`@include`, positional and named arguments, default values,
  variadic `+$args...+`, and passing content blocks with `@content`.
* xref:web/sass/functions.adoc[Functions] -- `@function`/`@return`, how functions differ from mixins, purity,
  and reporting problems with `@error`/`@warn`/`@debug`.
* xref:web/sass/extend.adoc[Selector Inheritance (`@extend`)] -- how `@extend` merges selectors rather than
  copying declarations, `%placeholder` targets, a side-by-side comparison with mixins, and the media-query and
  selector-bloat caveats.
* xref:web/sass/operators.adoc[Operators] -- arithmetic and unit handling, the `math.div()` rule that replaces
  `/` for division, string concatenation, comparison and boolean operators, and Sass's truthiness rules.
* xref:web/sass/control-flow.adoc[Control Flow] -- `@if`/`@else if`/`@else`, `@for` (`through` vs. `to`),
  `@each` over lists and maps with destructuring, and `@while`, with utility-class generation examples.
* xref:web/sass/lists-maps.adoc[Lists & Maps] -- 1-indexed lists and the `sass:list` functions, map syntax and
  `sass:map` lookups including nested keys, immutability, and a worked responsive-breakpoints example.
* xref:web/sass/built-in-modules.adoc[Built-in Modules] -- the `sass:math`, `sass:color`, `sass:list`,
  `sass:map`, `sass:string`, `sass:selector`, and `sass:meta` modules, and the deprecated global functions they
  replace.
* xref:web/sass/compilation.adoc[Compilation] -- why Sass must be compiled, Dart Sass vs. the deprecated
  LibSass/`node-sass` and Ruby Sass, the `sass` CLI and its flags, output styles, source maps, and Vite/Webpack
  integration.
* xref:web/sass/cheat-sheet.adoc[Cheat sheet] -- a one-page, downloadable PDF summary of the essentials above
  for quick memorization.

*Deliberately out of scope.* This section is about Dart Sass: the language, the module system and the compiler. The following topics appear in most books on the subject but live elsewhere on this site, or are intentionally not covered:

* *Compass and Susy* (the Ruby-era framework and grid) -- not supported by Dart Sass; see xref:web/sass/compilation.adoc[Compilation] for the modern replacements.
* *Less and other preprocessors* -- intentionally not covered; this section covers Dart Sass only.
* *GUI compile applications and editor compile-on-save* -- see xref:web/sass/compilation.adoc[Compilation] for the CLI and bundler workflow.
* *Output styles `nested` and `compact`* -- removed in Dart Sass; see xref:web/sass/compilation.adoc[Compilation].
* *Building a grid system from scratch* -- see xref:web/sass/control-flow.adoc[Control Flow] for the generator and xref:web/html-css/layout.adoc[Layout: Float, Flexbox and Grid] for the CSS.
* *Build optimization and workflow automation* -- see xref:web/html-css/performance-build-optimization.adoc[Performance and Build Optimization].
