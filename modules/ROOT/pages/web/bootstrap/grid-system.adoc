= The Grid System
:description: Explains Bootstrap's 12-column flexbox grid -- containers, rows, columns, breakpoints, sizing/offsetting/ordering/nesting -- and why classes from different breakpoints never conflict.
:keywords: bootstrap grid, container, container-fluid, row, col, breakpoints, responsive design, offset, order, nesting, 12-column grid

include::partial$ai-disclaimer.adoc[]

Bootstrap's grid is a 12-column, flexbox-based layout system built from three layers that always nest in the
same order: a **container**, one or more **rows**, and one or more **columns** inside each row. Every
responsive layout in Bootstrap -- from a simple two-column page to a complex dashboard -- is composed from
just those three layers plus a small vocabulary of breakpoint suffixes.

== Containers

A container is the outermost wrapping element. It centers content horizontally and applies responsive
`padding` (and, indirectly, the `margin` that separates it from the viewport edge -- see
xref:web/html-css/box-model.adoc[The Box Model] for what padding/margin mean structurally). Three variants
exist:

[source,html]
----
<div class="container">      <!-- fixed max-width per breakpoint, with gutters -->
<div class="container-fluid"><!-- always 100% of the viewport width -->
<div class="container-md">   <!-- fluid below md, fixed-width at md and up -->
----

`.container` sets a `max-width` that changes at each breakpoint (roughly matching that breakpoint's minimum
width, minus gutters), so the content column stays a comfortable reading width on large screens instead of
stretching edge-to-edge. `.container-fluid` never caps its width -- it is always `100%`, which suits app-like
layouts (dashboards, full-bleed hero sections) more than long-form content. The `+.container-{breakpoint}+`
variants (`sm`, `md`, `lg`, `xl`, `xxl`) are fluid up to that breakpoint and fixed-width from it upward -- a
middle ground useful when a layout should be edge-to-edge on mobile but capped on desktop.

== Rows and columns

A row is a flex container (`display: flex; flex-wrap: wrap;`) that introduces a negative margin to offset the
gutter padding columns add, so columns and containers align correctly at the edges. Columns are the flex items
inside it:

[source,html]
----
<div class="container">
  <div class="row">
    <div class="col">Column A</div>
    <div class="col">Column B</div>
    <div class="col">Column C</div>
  </div>
</div>
----

Bare `.col` (no number) divides the available width *equally* among however many sibling columns share the
row -- three `.col` elements each take a third, four take a quarter, and so on, recalculated automatically.

== The 12-column logic

Bootstrap's grid conceptually divides each row into 12 equal-width units. A numbered column class,
`+.col-{n}+`, spans `n` of those 12 units -- `.col-4` is one third of the row, `.col-6` is half, `.col-12` is
the full width:

[source,html]
----
<div class="row">
  <div class="col-4">col-4</div>
  <div class="col-4">col-4</div>
  <div class="col-4">col-4</div>
</div>

<div class="row">
  <div class="col-6">col-6</div>
  <div class="col-6">col-6</div>
</div>

<div class="row">
  <div class="col-3">col-3</div>
  <div class="col-9">col-9</div>
</div>
----

Column widths do not have to sum to exactly 12: if a row's columns add up to *more* than 12, the excess
columns wrap onto a new line as a unit (they do not split); if they add up to *less*, the row simply leaves
unused space on the right (in a left-to-right document).

The same markup can carry different column classes for different breakpoints simultaneously (see below), which
is how a single set of `<div>` elements goes from stacked-on-mobile to a three-column desktop layout without
any JavaScript or duplicated HTML.

== Breakpoints

Every column class can be suffixed with a breakpoint infix that makes it apply from that viewport width
*upward* (mobile-first: an unsuffixed class applies at all widths unless overridden by a wider breakpoint):

[cols="1,2,2", options="header"]
|===
| Breakpoint | Infix | Applies from

| Extra small
| _(none)_
| `0px` and up (always, unless overridden)

| Small
| `sm`
| `≥576px`

| Medium
| `md`
| `≥768px`

| Large
| `lg`
| `≥992px`

| Extra large
| `xl`
| `≥1200px`

| Extra extra large
| `xxl`
| `≥1400px`
|===

Combining several breakpoint classes on the same element produces a genuinely responsive layout:

[source,html]
----
<div class="row">
  <div class="col-12 col-md-6 col-lg-4">
    Full width on phones, half width from md, a third from lg upward
  </div>
  <div class="col-12 col-md-6 col-lg-4">...</div>
  <div class="col-12 col-md-6 col-lg-4">...</div>
</div>
----

These classes never conflict with each other because each one is generated inside its *own* `+@media (min-width: ...)+`
query in Bootstrap's compiled CSS -- `.col-md-6` literally only exists inside a
`@media (min-width: 768px)` block. At a 900px viewport, only the `md` (and unsuffixed) rules apply; the `lg`/`xl`/`xxl`
rules simply are not part of any matching media query yet, so there is nothing to override. This is why
stacking multiple breakpoint classes on one element is the normal, supported pattern rather than a hack.

== Sizing, offsetting, ordering, and nesting

=== Auto-sizing and equal-width columns

Besides fixed `+.col-{n}+` widths, a column can be told to size itself to its content (`.col-auto`) while its
siblings share the rest equally:

[source,html]
----
<div class="row">
  <div class="col-auto">Fits content</div>
  <div class="col">Takes the remaining space</div>
</div>
----

=== Offsetting

`+.offset-{breakpoint}-{n}+` pushes a column to the right by `n` of the 12 units, using margin rather than an
empty sibling column -- useful for centering or skipping columns without adding markup:

[source,html]
----
<div class="row">
  <div class="col-md-4">col-md-4</div>
  <div class="col-md-4 offset-md-4">col-md-4, offset 4</div>
</div>
----

=== Ordering

`+.order-{n}+` (0 through 5, plus `.order-first`/`.order-last`) changes the *visual* order of columns via the
flexbox `order` property, independent of their order in the HTML source:

[source,html]
----
<div class="row">
  <div class="col order-3">First in HTML, renders last</div>
  <div class="col order-1">Second in HTML, renders first</div>
  <div class="col order-2">Third in HTML, renders second</div>
</div>
----

Because `order` is purely visual, screen readers and keyboard tab order still follow the *source* order --
worth keeping in mind for any layout that reorders columns for visual effect, per the accessibility notes on
xref:web/bootstrap/getting-started.adoc[Getting Started].

=== Nesting

A `.row` can be nested inside a `.col`, starting a fresh 12-column context scoped to that column's own width
-- the nested row's columns are fractions of the *parent column*, not the page:

[source,html]
----
<div class="row">
  <div class="col-sm-9">
    Level 1: col-sm-9
    <div class="row">
      <div class="col-8 col-sm-6">Level 2: col-8 col-sm-6</div>
      <div class="col-4 col-sm-6">Level 2: col-4 col-sm-6</div>
    </div>
  </div>
</div>
----

=== Gutters

The space between columns is the **gutter**. It is not a margin between the columns: every column carries horizontal
padding equal to half the gutter, and the row pulls itself outward by the same half-gutter with a negative margin so
the first and last columns line up with the container's content edge. The gutter width is held in a CSS custom
property, `--bs-gutter-x` (and `--bs-gutter-y` for the vertical gap between wrapped lines), which the gutter
utilities set:

[cols="1,3", options="header"]
|===
| Class | Effect

| `.g-0`
| Removes both horizontal and vertical gutters (edge-to-edge columns).

| `.g-3`
| Sets both gutters to the third spacing step (`1rem` by default).

| `.gx-5`
| Sets only the horizontal gutter (`3rem` by default).

| `.gy-2`
| Sets only the vertical gutter, which also spaces columns that wrap onto a second line.

| `.g-md-4`
| Breakpoint-aware: applies from `md` upward.
|===

Because the gutter is a custom property, a single row can also be adjusted without a class,
`<div class="row" style="--bs-gutter-x: 3rem">`, and the same property is what the Sass `$grid-gutter-width`
variable ultimately sets.

=== Alignment

Rows are flex containers, so the flexbox alignment utilities apply directly. Vertical alignment is set on the row for
all of its columns (`.align-items-start`, `.align-items-center`, `.align-items-end`) or on a single column
(`.align-self-start`, `.align-self-center`, `.align-self-end`). Horizontal distribution of columns that do not fill
the row uses `.justify-content-start`, `-center`, `-end`, `-between`, `-around` and `-evenly`:

[source,html]
----
<div class="row align-items-center justify-content-between" style="min-height: 8rem">
  <div class="col-4">Vertically centered in the row</div>
  <div class="col-4 align-self-end">Aligned to the bottom edge</div>
</div>
----

All of these also have breakpoint variants (`.justify-content-md-center`, `.align-items-lg-end`).

=== Equal columns per row with `+.row-cols-*+`

Instead of sizing every column, `+.row-cols-{n}+` on the *row* sets the width of all direct children at once, which is
the usual way to build a card grid whose column count changes with the viewport:

[source,html]
----
<div class="row row-cols-1 row-cols-sm-2 row-cols-lg-4 g-3">
  <div class="col">Task A</div>
  <div class="col">Task B</div>
  <div class="col">Task C</div>
  <div class="col">Task D</div>
  <div class="col">Task E</div>
</div>
----

That markup renders one column per line on phones, two from `sm`, and four from `lg`; the fifth item simply wraps to
a second line. `.row-cols-auto` sizes every child to its content.

== The nesting-containers antipattern

`.container`/`.container-fluid` should appear **once**, at the top of the layout -- they set page-level
horizontal padding and center the whole layout. Nesting a second `.container` inside a `.row`/`.col` is a
common mistake: the inner container adds its *own* responsive padding and (for the fixed variant) `max-width`
on top of the outer one, which produces doubled gutters and, worse, causes the inner content to stop growing
past the inner container's `max-width` even though the outer container has more room. Rows and columns nest
freely (see above); containers do not.

[source,html]
----
<!-- Wrong: container nested inside a column -->
<div class="container">
  <div class="row">
    <div class="col">
      <div class="container">...</div>  <!-- doubled gutters, unexpected max-width -->
    </div>
  </div>
</div>

<!-- Right: only rows/columns nest -->
<div class="container">
  <div class="row">
    <div class="col">
      <div class="row">...</div>        <!-- fine, see Nesting above -->
    </div>
  </div>
</div>
----

The one legitimate exception is deliberately mixing container types at the top level for a page section that
needs to break out of the page's normal width -- for example, a full-bleed `.container-fluid` hero banner
followed by a normally-constrained `.container` for the rest of the page. That is two *sibling* top-level
containers, not one nested inside the other, so it does not hit the doubled-gutter problem above.

== How the grid maths works

Everything above reduces to a handful of rules in the compiled CSS. These are the real declarations Bootstrap 5.3
generates; reading them once removes most of the mystery around "why does this column wrap?":

[source,css]
----
.row {
  --bs-gutter-x: 1.5rem;
  --bs-gutter-y: 0;
  display: flex;
  flex-wrap: wrap;
  margin-top: calc(-1 * var(--bs-gutter-y));
  margin-right: calc(-0.5 * var(--bs-gutter-x));
  margin-left: calc(-0.5 * var(--bs-gutter-x));
}
.row > * {
  flex-shrink: 0;
  width: 100%;
  max-width: 100%;
  padding-right: calc(var(--bs-gutter-x) * 0.5);
  padding-left: calc(var(--bs-gutter-x) * 0.5);
  margin-top: var(--bs-gutter-y);
}
@media (min-width: 768px) {
  .col-md-6 { flex: 0 0 auto; width: 50%; }
}
----

Three consequences follow directly:

* **Any direct child of a `.row` is a column.** The `+.row > *+` rule gives every child `width: 100%` and the gutter
  padding, so an element with no `+.col-*+` class at all stacks full-width. The `+.col-*+` classes only *narrow* it.
* **Columns wrap because `flex-wrap: wrap` is set and the widths add up past 100%.** There is no 12-column
  arithmetic at run time: `.col-md-6` is literally `width: 50%`, and `.col-md-4` is `33.33333333%`. Three `.col-md-6`
  elements are `150%` wide in total, so the third moves to a new line.
* **The gutter lives in the padding of the column and the negative margin of the row.** That is why a `.row` placed
  directly inside a `.container` lines up perfectly (the container's own padding absorbs the negative margin), and
  why a `.row` outside any container makes the page scroll horizontally by half a gutter.

== Worked example: the Taskboard page layout

The Taskboard page has a sidebar of projects, a main area with a grid of task cards, and a summary panel that drops
below the main area on narrow screens. One container, one row for the page shell, and a nested row for the cards are
all that is needed:

[source,html]
----
<div class="container-xl py-4">
  <div class="row g-4">
    <aside class="col-12 col-md-3 col-xxl-2">
      <h2 class="h6 text-uppercase">Projects</h2>
      <!-- project list -->
    </aside>

    <main class="col-12 col-md-9 col-xxl-7">
      <div class="row row-cols-1 row-cols-sm-2 row-cols-xl-3 g-3">
        <div class="col"><div class="card h-100"><div class="card-body">Write docs</div></div></div>
        <div class="col"><div class="card h-100"><div class="card-body">Fix login bug</div></div></div>
        <div class="col"><div class="card h-100"><div class="card-body">Review PR</div></div></div>
      </div>
    </main>

    <section class="col-12 col-xxl-3" aria-labelledby="summary-heading">
      <h2 id="summary-heading" class="h6 text-uppercase">Summary</h2>
      <!-- totals -->
    </section>
  </div>
</div>
----

[cols="1,1,1,1", options="header"]
|===
| Viewport | Sidebar | Main | Summary

| below 768px
| full width, first
| full width
| full width, last

| 768px to 1399px
| 3 of 12
| 9 of 12
| full width, below both
  (wrapped, since 3 + 9 already fills the row)

| 1400px and up
| 2 of 12
| 7 of 12
| 3 of 12 (2 + 7 + 3 = 12, one line)
|===

The DOM order (sidebar, main, summary) already matches the visual order at every width, so no `+.order-*+` class is
needed and keyboard focus follows what the eye sees.

== Customizing the grid in Sass

Because the grid is generated from Sass maps, the breakpoints, container widths, column count and gutter can all be
changed at compile time. This example (compiled and checked with Bootstrap 5.3.3 and Dart Sass) sets a 16-column
grid with a wider gutter and its own breakpoints, then uses the grid mixins to give two semantic class names the
same behavior as `.col-md-4` / `.col-md-12` without touching the markup:

[source,scss]
----
@import "bootstrap/scss/functions";

// 1. Grid variables, before the variables partial
$grid-columns: 16;
$grid-gutter-width: 2rem;
$grid-breakpoints: (xs: 0, sm: 576px, md: 768px, lg: 1024px, xl: 1280px, xxl: 1600px);
$container-max-widths: (sm: 540px, md: 720px, lg: 984px, xl: 1220px, xxl: 1540px);

@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";
@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";
@import "bootstrap/scss/containers";
@import "bootstrap/scss/grid";

// 2. Grid mixins applied to semantic class names
.board         { @include make-row(); }
.board__sidebar { @include make-col-ready(); @include media-breakpoint-up(md) { @include make-col(4, 16); } }
.board__main    { @include make-col-ready(); @include media-breakpoint-up(md) { @include make-col(12, 16); } }
----

The compiled output contains `.col-md-16`, `.col-md-8` becomes `width: 50%`, every container `max-width` uses the new
values, and `+.board__main+` compiles to `flex: 0 0 auto; width: 75%` inside `@media (min-width: 768px)`. Keep the
`$container-max-widths` values at or below the matching breakpoint minus one gutter, or the container is wider than
the viewport at that breakpoint.

=== Opting in to the CSS Grid layout

Setting `$enable-cssgrid: true` before the variables partial makes Bootstrap additionally emit a second, CSS
Grid-based system next to the flexbox one: a `.grid` container (`display: grid`, with the column count and gap read
from `--bs-columns` and `--bs-gap`) and `+.g-col-*+` children that use `grid-column: auto / span n`. The flexbox
`.row`/`+.col-*+` classes keep working unchanged. Reach for it when columns must also line up *vertically* across
several rows, which flexbox rows cannot do because each row sizes independently.

For the full grid API -- including the CSS Grid-based `+.row-cols-*+` and gap utilities -- see the official
https://getbootstrap.com/docs/5.3/layout/grid/[Layout: Grid] documentation.
