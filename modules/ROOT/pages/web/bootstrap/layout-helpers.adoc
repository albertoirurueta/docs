= Layout Helpers
:description: Covers Bootstrap 5 layout helpers beyond the grid and utility classes -- native CSS Flexbox and Grid integration, responsive visibility/display classes, and z-index/positioning helpers used to arrange whole page regions.
:keywords: Bootstrap layout, CSS Flexbox, CSS Grid, responsive visibility, z-index, stacking context, position helpers, page layout, container, ratio

include::partial$ai-disclaimer.adoc[]

Bootstrap's xref:web/bootstrap/grid-system.adoc[Grid System] arranges content into rows and columns, and
xref:web/bootstrap/utilities.adoc[Utilities] cover the single-property helper classes applied to any element.
Layout helpers sit alongside both: a smaller set of concerns specific to arranging *whole page regions* --
which layout model a container uses, whether a region is visible at a given breakpoint, and which region sits
on top when several overlap. This page does not repeat the grid or utility classes themselves; it covers how
these pieces combine into full-page layout.

== Flexbox as the layout backbone

The grid is itself built on CSS Flexbox: a `.row` is `display: flex; flex-wrap: wrap`, and each `+.col-*+` is a
flex item with a computed `flex-basis`. This is why the flex utilities documented on
xref:web/bootstrap/utilities.adoc[Utilities] (`d-flex`, `+justify-content-*+`, `+align-items-*+`, `+gap-*+`) work
seamlessly *inside* a grid layout as well as outside it -- they are not a separate system bolted on, but the
same mechanism the grid itself uses:

[source,html]
----
<div class="row">
  <div class="col-md-8 d-flex align-items-center">
    <!-- flex utilities inside a grid column, no conflict -->
    <img src="thumb.jpg" class="me-3" alt="" />
    <div>Vertically centered against the image, using the same flex utilities as elsewhere on the page.</div>
  </div>
  <div class="col-md-4">Sidebar</div>
</div>
----

A common pattern for full-page shells is a flex column with one growing region, using `flex-grow-1` to push a
footer to the bottom of the viewport regardless of content height:

[source,html]
----
<body class="d-flex flex-column min-vh-100">
  <header class="p-3">Site header</header>
  <main class="flex-grow-1 p-3">Main content -- grows to fill remaining space</main>
  <footer class="p-3 bg-light">Footer, always at the bottom</footer>
</body>
----

== CSS Grid integration

Bootstrap 5.1 added an opt-in CSS Grid mode alongside the flexbox grid, using its own `.grid`/`+.g-col-*+`/
`+.g-start-*+` classes rather than `.row`/`+.col-*+`. It is opt-in at the Sass level, not just a class a page can
reach for: `$enable-cssgrid` defaults to `false`, so `.grid` and friends do not exist in the stock CDN
`bootstrap.min.css` or the npm `dist` build at all -- they only appear after setting `$enable-cssgrid: true` and
recompiling from source (see xref:web/bootstrap/customization.adoc[Customization]). `+.g-col-*+`/`+.g-start-*+` are
also unrelated to the flexbox grid's own `+.g-*+` gutter classes (`g-3`, `gx-2`, and so on), which *are* in the
default build -- the shared `g-` prefix is a naming collision worth double-checking against, not a sign the two
systems interoperate:

[source,html]
----
<div class="grid">
  <div class="g-col-6">Half width</div>
  <div class="g-col-3">Quarter</div>
  <div class="g-col-3">Quarter</div>
</div>
----

`+.g-col-*+` sets `grid-column: span N`, and `+.g-start-*+` positions an item at a specific starting column line
for layouts that need explicit placement rather than sequential flow:

[source,html]
----
<div class="grid">
  <div class="g-col-4 g-start-3">Starts at column 3, spans 4</div>
</div>
----

This mode is deliberately narrower in scope than the full flexbox grid (no nesting or gutters system as rich as
`.row`/`.col`), and is meant for CSS-Grid-native layouts -- a photo mosaic, a dashboard of unevenly sized
panels -- rather than as a wholesale replacement for the flexbox grid documented in
xref:web/bootstrap/grid-system.adoc[The Grid System].

== `.ratio` for intrinsic aspect ratios

A layout helper worth calling out on its own: `.ratio` maintains an element's aspect ratio as its width
changes, using the CSS aspect-ratio box trick so an embedded video or map keeps its proportions responsively
without JavaScript:

[source,html]
----
<div class="ratio ratio-16x9">
  <iframe src="https://www.example.com/video" title="Embedded video" allowfullscreen></iframe>
</div>
----

Bootstrap ships `ratio-1x1`, `ratio-4x3`, `ratio-16x9`, and `ratio-21x9`; an arbitrary ratio is set with an
inline custom property, `style="--bs-aspect-ratio: 75%;"`, on the `.ratio` element itself.

== Responsive visibility and display

Whether a whole region is present at a given viewport width is handled by the same `+d-*+` display utilities
covered on xref:web/bootstrap/utilities.adoc[Utilities], applied at the layout-region level rather than to an
individual inline element:

[source,html]
----
<nav class="d-none d-lg-flex">Full desktop navigation</nav>
<button class="btn d-lg-none" type="button" data-bs-toggle="offcanvas" data-bs-target="#mobile-nav">
  Menu
</button>

<aside class="col-md-3 d-none d-md-block">Sidebar, hidden on narrow viewports</aside>
<main class="col-md-9">Main content, full width below md</main>
----

There is a second, narrower visibility mechanism worth distinguishing from `d-none`: the `.visually-hidden`
class, which hides content *visually* while keeping it in the accessibility tree (screen readers still
announce it). `d-none` removes an element from both the visual layout and the accessibility tree; the two are
not interchangeable, and picking the wrong one either hides content from sighted users unnecessarily or hides
it from assistive technology while leaving it visible. See
xref:web/bootstrap/accessibility.adoc[Accessibility] for more on `.visually-hidden` and its use with
screen-reader-only text.

== Positioning and stacking (z-index)

Layout regions that overlap -- a fixed header above scrolling content, a modal above the page, a dropdown above
a card -- need a coherent stacking order, or a lower layer can visually leak through a higher one. Bootstrap
defines a small, deliberately limited z-index scale via CSS custom properties, exposed through utility classes:

[source,html]
----
<header class="position-sticky top-0 z-3 bg-white border-bottom">Sticky header</header>
<div class="position-relative z-0">Base content layer</div>
<div class="position-absolute z-1">Slightly raised overlay</div>
----

`z-n1`, `z-0`, `z-1`, `z-2`, and `z-3` cover the layering a typical page layout needs; Bootstrap's own
components (modals, dropdowns, tooltips, the fixed/sticky navbar) use a *separate*, higher internal z-index
scale defined in Sass variables (`$zindex-modal`, `$zindex-dropdown`, `$zindex-tooltip`, and so on) specifically
so that page-level content using the `+z-*+` utilities can never accidentally sit on top of a modal or dropdown.
Mixing arbitrary inline `z-index` values into a layout instead of these scales is what usually causes a
stacking bug -- two unrelated parts of a page independently reaching for a large round number like `9999`.

Combined with `position-relative`/`position-absolute`/`position-fixed`/`position-sticky` and the `+top-*+`/
`+bottom-*+`/`+start-*+`/`+end-*+` offset utilities (all covered on xref:web/bootstrap/utilities.adoc[Utilities]),
`+z-*+` is normally the last piece needed to arrange overlapping page regions without a single line of custom
CSS.

== Stacks and the vertical rule

`.hstack` and `.vstack` are shortcuts for the two flex shapes that account for most small layouts. `.hstack` is a
row (`display: flex; flex-direction: row; align-items: center`) and `.vstack` a column that grows to fill its
container (`flex: 1 1 auto; flex-direction: column`). Both use `align-self: stretch`, so they fill the cross axis of
their parent, and spacing between children comes from the `+gap-*+` utilities. A `.ms-auto` on one child pushes it
(and everything after it) to the far end, and `.vr` draws a thin vertical divider that stretches to the row's height:

[source,html]
----
<div class="hstack gap-3 border-bottom pb-2">
  <h2 class="h5 mb-0">Orders</h2>
  <div class="vr"></div>
  <span class="text-body-secondary">12 open</span>
  <button type="button" class="btn btn-sm btn-primary ms-auto">New order</button>
</div>

<div class="vstack gap-2">
  <div class="p-2 border">First</div>
  <div class="p-2 border">Second</div>
</div>
----

== Sticky and fixed helpers

Besides the general `+position-*+` utilities, there are four dedicated classes that combine a position with an offset
and a z-index: `.fixed-top`, `.fixed-bottom`, `.sticky-top` and `.sticky-bottom`. A fixed element is taken out of the
flow, so the page needs top (or bottom) padding to avoid hiding content under it, whereas a sticky element keeps its
place in the flow and only sticks once its container is scrolled. The sticky classes also exist per breakpoint
(`.sticky-md-top`, `.sticky-lg-bottom` and so on), which is how a sidebar sticks only when it is a column and not
when it is stacked on a phone. A sticky element needs an ancestor that is taller than itself, and it is clipped if
any ancestor sets `overflow: hidden`, `auto` or `scroll`.

`.stretched-link` is the layout helper for making a whole card clickable. It adds an `::after` pseudo-element, with
`position: absolute` and `z-index: 1`, covering the nearest positioned ancestor, so give that ancestor
`.position-relative` (a `.card` already has it):

[source,html]
----
<div class="card position-relative">
  <div class="card-body">
    <h3 class="card-title h5">Mechanical Keyboard</h3>
    <a href="/products/kb-0089" class="stretched-link">View details</a>
  </div>
</div>
----

Any other link or button inside that card needs `.position-relative` and `.z-2` to stay clickable above the
stretched area.

A skip link is the accessibility counterpart of these helpers. `.visually-hidden-focusable` hides an element until it
(or something inside it) receives focus, so keyboard users can jump past a long header:

[source,html]
----
<a class="visually-hidden-focusable" href="#main">Skip to main content</a>
----

== The z-index scale

The `+z-*+` utilities (`-1` through `3`) are meant for ordering ordinary page content among its siblings. Bootstrap's
own overlays use a separate, much higher scale, declared as Sass variables and exposed as CSS custom properties.
These are the values in the compiled stylesheet:

[cols="1,1", options="header"]
|===
| Layer | `z-index`

| Dropdown menu | 1000
| `.sticky-top`, `.sticky-bottom` | 1020
| `.fixed-top`, `.fixed-bottom` | 1030
| Offcanvas backdrop | 1040
| Offcanvas panel | 1045
| Modal backdrop | 1050
| Modal | 1055
| Popover | 1070
| Tooltip | 1080
| Toast | 1090
|===

[mermaid]
....
flowchart BT
    CONTENT["Page content<br/>z-index -1 to 3 (z-* utilities)"]
    DROPDOWN["Dropdown menu<br/>1000"]
    STICKY["Sticky header<br/>1020"]
    FIXED["Fixed bars<br/>1030"]
    OFFCANVAS["Offcanvas<br/>1040-1045"]
    MODAL["Modal<br/>1050-1055"]
    POPOVER["Popover 1070"]
    TOOLTIP["Tooltip 1080"]
    TOAST["Toast 1090"]

    CONTENT --> DROPDOWN --> STICKY --> FIXED --> OFFCANVAS --> MODAL --> POPOVER --> TOOLTIP --> TOAST
....

Two consequences follow. A sticky header (1020) correctly stays above page content but below a modal, so opening a
modal covers the header as expected. A dropdown (1000) is *below* a sticky header, so a menu that is open while the
page scrolls slides under the header instead of covering it. The scale also leaves deliberate gaps: an
application overlay that must sit between a fixed bar and the offcanvas drawer can take a value from 1031 to 1039
without touching Bootstrap's variables.

A stacking context changes the picture: `z-index` only competes among siblings of the same stacking context, and an
ancestor with `transform`, `opacity` below 1, `filter` or its own positioned `z-index` creates a new one. This is
why a tooltip or popover inside a card with a `transform` can be drawn under a neighboring card even though its
`z-index` is 1080. By default Bootstrap inserts the tooltip right after its trigger, and the `container: "body"`
option moves it to the end of `<body>`, out of any such context.

== CSS Grid mode in practice

When `$enable-cssgrid` is on, `.grid` becomes a CSS Grid container driven by three custom properties, which can be
set per element: `--bs-columns` (default 12), `--bs-rows` (default 1) and `--bs-gap` (default `1.5rem`). The column
helpers are scoped to descendants of `.grid` (the compiled selector is `.grid .g-col-4`), so they do nothing outside
a grid. Responsive variants exist per breakpoint (`.g-col-md-6`), and the column count can be changed without a
Sass rebuild:

[source,html]
----
<div class="grid" style="--bs-columns: 6; --bs-gap: 1rem;">
  <div class="g-col-6 g-col-md-4">Spans all six columns on phones, four from md</div>
  <div class="g-col-6 g-col-md-2">Fills the rest of the row from md</div>
</div>
----

== Deep dive: an admin shell for the product catalog

The helpers above compose into the page shell used by the catalog's admin screens: a sticky header, a sidebar that
is a permanent column on desktop and an offcanvas drawer on phones, a main region, and a footer pinned to the bottom
of short pages:

[source,html]
----
<body class="d-flex flex-column min-vh-100">
  <header class="sticky-top bg-body border-bottom">
    <div class="container-fluid hstack gap-3 py-2">
      <button class="btn btn-outline-secondary d-lg-none" type="button"
              data-bs-toggle="offcanvas" data-bs-target="#sidebar" aria-controls="sidebar">Menu</button>
      <strong>Catalog admin</strong>
      <div class="ms-auto">Signed in as Ada</div>
    </div>
  </header>

  <div class="container-fluid flex-grow-1">
    <div class="row">
      <aside class="col-lg-3 col-xl-2 border-end p-0">
        <div class="offcanvas-lg offcanvas-start" tabindex="-1" id="sidebar" aria-labelledby="sidebar-title">
          <div class="offcanvas-header">
            <h2 class="offcanvas-title h5" id="sidebar-title">Sections</h2>
            <button type="button" class="btn-close" data-bs-dismiss="offcanvas"
                    data-bs-target="#sidebar" aria-label="Close"></button>
          </div>
          <div class="offcanvas-body vstack gap-1">
            <a href="/products" class="link-body-emphasis">Products</a>
            <a href="/orders" class="link-body-emphasis">Orders</a>
          </div>
        </div>
      </aside>
      <main class="col-lg-9 col-xl-10 py-3">Page content</main>
    </div>
  </div>

  <footer class="border-top py-2 text-center small">Footer</footer>
</body>
----

Reading it from the top: `d-flex flex-column min-vh-100` plus `flex-grow-1` on the middle region pins the footer;
`.sticky-top` keeps the header visible at z-index 1020, below the offcanvas drawer (1045) that opens over it on
phones; `d-lg-none` shows the "Menu" button only while the sidebar is a drawer; and `.offcanvas-lg` turns the
sidebar into an ordinary block in the grid column from `lg` upward. The close button repeats
`data-bs-target="#sidebar"` because, for a responsive offcanvas, the dismiss lookup for the closest `.offcanvas`
ancestor finds nothing: the element carries `.offcanvas-lg` instead.

== Where layout helpers stop and other pages start

This page intentionally stays at the level of arranging whole regions. For the column/row mechanics themselves
-- breakpoints, gutters, offsets, column ordering -- see xref:web/bootstrap/grid-system.adoc[The Grid System].
For every single-property class referenced above -- `d-flex`, `gap-3`, `position-sticky`, `top-0`, `z-3` -- see
xref:web/bootstrap/utilities.adoc[Utilities], including how the whole set is generated and how to add project-
specific ones via xref:web/bootstrap/utility-api.adoc[The Utility API].
