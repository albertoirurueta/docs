= Utilities
:description: Surveys Bootstrap 5's utility classes for spacing, color, backgrounds, borders, flexbox, display, position, sizing, and shadows -- the single-purpose classes applied directly in markup instead of custom CSS.
:keywords: Bootstrap utilities, spacing utilities, mt-3, px-2, color utilities, background utilities, border utilities, flexbox utilities, display utilities, position utilities, sizing utilities, shadow utilities

include::partial$ai-disclaimer.adoc[]

Bootstrap ships hundreds of small, single-purpose classes -- *utilities* -- each of which sets exactly one CSS
property (or a tightly related handful of them). Instead of writing a custom rule for "add a bit of top margin"
or "hide this on small screens," a page composes utility classes directly in markup:

[source,html]
----
<div class="mt-3 px-2 bg-light border rounded shadow-sm">
  Spacing, background, border, and shadow -- all from utility classes, no custom CSS.
</div>
----

This page surveys the utility groups you reach for constantly. Every one of them is generated by Bootstrap's
Sass build from a shared configuration mechanism, covered separately in
xref:web/bootstrap/utility-api.adoc[The Utility API].

== Spacing

Spacing utilities set `margin` and `padding` using a short, consistent naming scheme:

[source,text]
----
{property}{sides}-{size}
----

* `property` is `m` (margin) or `p` (padding).
* `sides` is `t` (top), `b` (bottom), `s` (start -- left in LTR), `e` (end -- right in LTR), `x` (left and
  right), `y` (top and bottom), or omitted entirely for all four sides.
* `size` is `0`--`5` on Bootstrap's default spacing scale (a multiple of `$spacer`, which defaults to `1rem`),
  or `auto` for margin.

[source,html]
----
<div class="mt-3">Margin-top: 1rem (spacer * 1)</div>
<div class="px-2">Padding-left and padding-right: 0.5rem</div>
<div class="mb-0">Margin-bottom: 0</div>
<div class="mx-auto" style="width: 200px;">Horizontally centered block</div>
<div class="py-5">Padding-top and padding-bottom: 3rem</div>
----

Negative margins follow the same pattern with an `n` prefix before the size, e.g. `mt-n2` for a negative
top margin of `0.5rem` -- but only once `$enable-negative-margins` has been set to `true` and Bootstrap's CSS
recompiled from Sass; it defaults to `false`, so `n`-prefixed classes generate no CSS at all in the stock CDN or
npm `dist` build. The scale itself -- how many steps it has and what each one measures -- is a Sass map
under the hood, not a hard-coded list of classes; see
xref:web/bootstrap/utility-api.adoc[The Utility API] for how to extend, renumber, or enable a disabled utility
group like this one.

== Colors and backgrounds

Text color and background color utilities are generated from the same theme-color palette
(`primary`, `secondary`, `success`, `danger`, `warning`, `info`, `light`, `dark`) used throughout Bootstrap's
components:

[source,html]
----
<p class="text-primary">Primary-colored text</p>
<p class="text-danger">Danger-colored text</p>
<p class="text-muted">Muted, de-emphasized text</p>

<div class="bg-success text-white p-3">Success background, white text</div>
<div class="bg-light p-3">Light background</div>
<div class="bg-dark text-white p-3">Dark background, white text</div>
----

Bootstrap 5.3 introduced *subtle* color utilities and full color-mode (light/dark) support, so `bg-primary-subtle`
and `text-primary-emphasis` pair a low-saturation background with a readable foreground automatically, rather
than requiring a hand-picked lighter shade:

[source,html]
----
<div class="bg-primary-subtle text-primary-emphasis border border-primary-subtle rounded p-3">
  Subtle background, readable emphasis text, matching subtle border.
</div>
----

Opacity utilities compose with color: `text-opacity-75`, `bg-opacity-25`, and friends set the alpha channel of
the corresponding CSS custom property that the color utility itself defines.

== Borders

Border utilities add, remove, round, or color a border:

[source,html]
----
<div class="border">All four sides</div>
<div class="border-top border-3">Top only, 3x width</div>
<div class="border-0">No border (removes one inherited from a component)</div>
<div class="border border-danger">Danger-colored border</div>

<img src="avatar.jpg" class="rounded-circle" alt="Avatar" />
<div class="rounded-3">Larger corner radius</div>
<div class="rounded-top-0">Square top corners only</div>
----

`rounded` (and its directional/sized variants `rounded-top`, `rounded-3`, `rounded-pill`, `rounded-circle`)
sets `border-radius`; it works whether or not the element actually has a visible border, since rounding and
bordering are independent concerns kept as separate utility groups.

== Flexbox

Bootstrap's grid is itself built on flexbox (see xref:web/bootstrap/grid-system.adoc[The Grid System]), and the
same flex utilities are available for any element, grid or not:

[source,html]
----
<div class="d-flex justify-content-between align-items-center">
  <span>Left</span>
  <span>Right</span>
</div>

<div class="d-flex flex-column flex-md-row gap-3">
  <div class="p-2 bg-light">One</div>
  <div class="p-2 bg-light">Two</div>
</div>

<div class="d-flex flex-wrap">
  <div class="p-2">Wraps onto a new line once it runs out of room</div>
</div>

<div class="d-flex">
  <div class="flex-grow-1">Grows to fill remaining space</div>
  <div>Fixed width</div>
</div>
----

The common flex properties are all covered: `flex-row`/`flex-column` (and `-reverse` variants),
`+justify-content-*+`, `+align-items-*+`, `+align-self-*+`, `flex-wrap`/`flex-nowrap`, `flex-fill`,
`+flex-grow-*+`/`+flex-shrink-*+`, `+order-*+`, and `+gap-*+` for the spacing between flex (or grid) children --
`+gap-*+` is a single utility that replaced a lot of manual margin juggling between siblings.

== Display

`+d-*+` sets the CSS `display` property, and is one of the most frequently used utility groups because it is also
the mechanism for responsive show/hide:

[source,html]
----
<div class="d-none d-md-block">Hidden below md, visible md and up</div>
<div class="d-block d-md-none">Visible below md, hidden md and up</div>
<span class="d-inline-block">inline-block</span>
<table class="d-table"><!-- forces display: table --></table>
----

Every responsive utility in Bootstrap follows this same breakpoint-infix pattern: no infix targets all
viewport sizes (mobile-first, since Bootstrap's breakpoints are `min-width` media queries), and `-sm-`,
`-md-`, `-lg-`, `-xl-`, `-xxl-` progressively raise the minimum width at which the rule takes effect.

== Position

Positioning utilities cover the `position` property and the four offset properties:

[source,html]
----
<div class="position-relative">
  <span class="position-absolute top-0 end-0 badge bg-danger">9</span>
  Parent providing the positioning context
</div>

<div class="position-fixed bottom-0 start-0">Fixed to the bottom-left of the viewport</div>
<nav class="position-sticky" style="top: 0;">Sticky nav, sticks once scrolled to top: 0</nav>
----

`+top-*+`, `+bottom-*+`, `+start-*+`, `+end-*+` (each with `0`, `50`, `100` percentage values) and the
`translate-middle` family combine to center an element precisely over a positioned ancestor -- the classic use
being the notification badge shown above, offset and translated so it sits on the corner of its parent rather
than inside it.

== Sizing

`+w-*+` and `+h-*+` set `width`/`height` as a percentage of the containing block, plus `mw-100`/`mh-100` for a
max constraint that never overflows its parent:

[source,html]
----
<div class="w-25">25% width</div>
<div class="w-50">50% width</div>
<div class="w-100">100% width</div>
<img src="hero.jpg" class="w-100 h-auto" alt="Hero image, full width, proportional height" />

<div style="height: 300px;">
  <div class="h-100 bg-light">Fills the 300px parent</div>
</div>
----

`vw-100` and `vh-100` size against the viewport instead of the containing block, useful for a full-bleed hero
section or a full-height layout shell.

== Shadows

`+shadow-*+` applies one of a small fixed set of `box-shadow` presets, rather than an arbitrary elevation scale:

[source,html]
----
<div class="shadow-none p-3 mb-3">No shadow</div>
<div class="shadow-sm p-3 mb-3">Small shadow -- subtle depth for a card or input</div>
<div class="shadow p-3 mb-3">Regular shadow -- the default elevation</div>
<div class="shadow-lg p-3 mb-3">Large shadow -- a modal, popover, or dropdown menu</div>
----

Four steps (`none`, `sm`, default, `lg`) is deliberately small: Bootstrap favors a few consistent elevation
levels over a large scale that different developers would apply inconsistently across a project.

== Which class wins

Utilities are declared with `!important`, so a utility beats any component rule (`.card`, `.btn`) and any normal
rule from your own stylesheet. When two utilities set the same property on one element, both are `!important` with
equal specificity, so the one that appears *later in the compiled CSS* wins. The compiled order is fixed and
predictable: every utility group in the order of the `$utilities` map, first for the base (no infix) and then once
per breakpoint, from `sm` up to `xxl`, with the `print` variants last. In the compiled stylesheet `.d-none` comes
before `.d-md-block`, and `.mt-3` before `.mt-md-3` and `.mt-lg-3`, which is why the larger breakpoint overrides the
smaller one when several apply:

[source,html]
----
<div class="p-2 p-md-4 p-xl-5">Padding 0.5rem, then 1.5rem from md, then 3rem from xl</div>
<div class="d-none d-md-block d-xl-none">Visible only from md up to just below xl</div>
----

Within a single group the order of the *values* decides ties: `.mt-3 .mt-5` always renders `mt-5`, because the
generator emits `mt-0` through `mt-5` in ascending order. Never rely on that: apply one value per property per
breakpoint. If a utility must lose to custom CSS, either set `$enable-important-utilities: false` in a Sass build
(see xref:web/bootstrap/customization.adoc[Customization]), which drops `!important` from all utilities, or put the
exception behind a more specific selector with its own `!important`.

== Color and opacity are composed with variables

The color utilities do not hard-code an alpha channel. `.bg-primary` sets `--bs-bg-opacity: 1` and then paints
`rgba(var(--bs-primary-rgb), var(--bs-bg-opacity))`, and `.bg-opacity-25` merely changes the variable to `0.25`.
Because the opacity utilities are generated after the color utilities, the two combine whichever order the classes
are written in, and the opacity affects only the background, not the text inside:

[source,html]
----
<div class="bg-primary bg-opacity-25 text-primary-emphasis p-3">Tinted background, full-strength text</div>
<div class="border border-primary border-opacity-50 p-3">Half-strength border</div>
<a class="link-primary link-underline-opacity-25 link-underline-opacity-100-hover" href="#">Faint underline</a>
----

The same pattern is used by `+.text-opacity-*+`, `+.border-opacity-*+`, `+.link-opacity-*+` and
`+.link-underline-opacity-*+`. The `+.opacity-*+` utilities, in contrast, set the CSS `opacity` property, which fades the
whole element including its children. The helper `+.text-bg-*+` (for example `.text-bg-primary`) sets both the
background and a contrasting text color in one class, which is the quickest way to build a badge-like chip.

== Less obvious utility groups

[cols="2,3", options="header"]
|===
| Classes | Effect

| `.overflow-auto`, `.overflow-hidden`, `.overflow-visible`, `.overflow-scroll`
| The `overflow` property; the `-x` and `-y` variants exist too.

| `.visible`, `.invisible`
| `visibility`. An `.invisible` element still takes up space, unlike `.d-none`, and is hidden from assistive
  technology.

| `.object-fit-cover`, `.object-fit-contain`, `.object-fit-fill`, `.object-fit-scale`, `.object-fit-none`
| How an image or video fits a box of a different aspect ratio; pair with `.w-100` and a fixed height.

| `.pe-none`, `.pe-auto`, `.user-select-none`, `.user-select-all`
| `pointer-events` and `user-select`. `.pe-none` makes an element click-through, which does not remove it from
  keyboard focus.

| `.link-primary`, `.link-body-emphasis`, `.link-offset-2`, `.link-underline-opacity-50`
| Link color, underline offset and underline opacity, with `-hover` variants for the offset and opacity.

| `.focus-ring`, `.focus-ring-danger`
| A custom focus indicator drawn as a `box-shadow` from the `+--bs-focus-ring-*+` variables, replacing the outline.

| `.icon-link`, `.icon-link-hover`
| An inline-flex link with an icon, where the icon nudges sideways on hover or focus.

| `.bg-gradient`
| Adds the translucent white gradient overlay on top of any `+.bg-*+` color.

| `.float-start`, `.float-end`, `.clearfix`
| The classic float helpers, with breakpoint variants; `.clearfix` clears floated children of a container.
|===

== Deep dive: composing a catalog card from utilities

The product card used across this section needs: a clickable thumbnail, a price, a stock chip, and a footer with
an action. None of it requires a custom CSS rule:

[source,html]
----
<article class="position-relative d-flex flex-column h-100 border rounded-3 shadow-sm overflow-hidden bg-body">
  <img src="keyboard.jpg" class="object-fit-cover w-100" style="height: 10rem;" alt="Mechanical Keyboard">
  <span class="position-absolute top-0 end-0 m-2 badge rounded-pill text-bg-warning">Low stock</span>

  <div class="d-flex flex-column gap-2 p-3 flex-grow-1">
    <h2 class="h5 mb-0">
      <a class="link-body-emphasis link-underline-opacity-0 link-underline-opacity-75-hover stretched-link"
         href="/products/kb-0089">Mechanical Keyboard</a>
    </h2>
    <p class="mb-0 text-body-secondary small">Hot-swappable switches, USB-C.</p>
    <p class="fs-4 fw-semibold mb-0 mt-auto">$89.99</p>
  </div>

  <div class="d-flex justify-content-between align-items-center border-top bg-body-tertiary px-3 py-2">
    <span class="small text-body-secondary">3 left</span>
    <button type="button" class="btn btn-sm btn-primary position-relative z-2">Add to cart</button>
  </div>
</article>
----

Reading the classes by purpose: `position-relative d-flex flex-column h-100` makes the card a vertical flex
container that fills its grid cell, so the footer lines up across cards of different content height;
`border rounded-3 shadow-sm overflow-hidden` draws the outline and clips the image to the rounded corners;
`object-fit-cover w-100` crops the photo without distortion; `position-absolute top-0 end-0 m-2` pins the chip to a
corner; `text-bg-warning` gives it its background and readable text in one class; `mt-auto` on the price pushes it
to the bottom of the body when the description is short; `stretched-link` makes the whole card open the product,
and `position-relative z-2` lifts the button above the stretched link so "Add to cart" stays independently clickable.

== Where these classes come from

Components and utilities are meant to be combined on the same element, for example
`+class="card shadow-sm p-3 text-center"+`. When a utility and a component set the same property, the utility
wins because Bootstrap declares utilities with `+!important+`, not because of its position in the `class`
attribute (attribute order never matters). See xref:web/html-css/selectors-specificity.adoc#class-order[Class order and the cascade].

Every utility shown on this page -- `mt-3`, `text-primary`, `d-flex`, `shadow-sm`, and the rest -- is not
hand-written CSS in Bootstrap's source. It is generated at Sass-compile time from a single configuration map,
`$utilities`, which drives the class name, the CSS property, the set of values, and whether responsive and
`!important` variants are produced. See xref:web/bootstrap/utility-api.adoc[The Utility API] for how that map
works and how to add, remove, or restyle any utility class without touching Bootstrap's own source files.
