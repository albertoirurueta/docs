= Tables
:description: Covers Bootstrap's table styling variants -- striped, bordered, hover, and responsive -- with a fully styled responsive table example.
:keywords: bootstrap tables, table-striped, table-bordered, table-hover, table-responsive, table-dark, table variants

include::partial$ai-disclaimer.adoc[]

Bootstrap restyles the plain HTML `<table>` element with sensible base spacing and typography (part of
xref:web/bootstrap/reboot.adoc[Reboot]), then layers a set of modifier classes on `<table>` itself to control
striping, borders, hover feedback, row/cell coloring, and horizontal overflow behavior on small screens.

== The base class

Every styled table starts with `.table` on the `<table>` element. On its own it applies Bootstrap's spacing,
a horizontal divider between rows, and typography consistent with the rest of the page -- with no border
around the outside and no striping yet:

[source,html]
----
<table class="table">
  <thead>
    <tr>
      <th scope="col">#</th>
      <th scope="col">First</th>
      <th scope="col">Last</th>
      <th scope="col">Handle</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">1</th>
      <td>Mark</td>
      <td>Otto</td>
      <td>@mdo</td>
    </tr>
    <tr>
      <th scope="row">2</th>
      <td>Jacob</td>
      <td>Thornton</td>
      <td>@fat</td>
    </tr>
  </tbody>
</table>
----

`scope="col"` / `scope="row"` on the header cells are plain HTML accessibility attributes, not
Bootstrap-specific -- they associate each header with the column or row it labels for screen readers, and
should be included regardless of which Bootstrap classes are applied.

== Styling variants

All of the following are modifier classes added directly to `.table`, and they combine freely with each
other:

[cols="2,3", options="header"]
|===
| Class | Effect

| `.table-striped`
| Zebra-striping -- alternating background color on odd rows via `:nth-of-type(odd)`

| `.table-striped-columns`
| Same idea, striped by column instead of by row

| `.table-bordered`
| Borders on all sides of every cell, not just the horizontal row dividers `.table` provides by default

| `.table-borderless`
| Removes all borders, including the default row dividers

| `.table-hover`
| Highlights whichever row is currently under the pointer

| `.table-sm`
| Halves the cell padding, for a denser table

| `.table-dark`
| Inverts the table to a dark background with light text

| `+.table-{color}+`
| Colors the whole table using one of the xref:web/bootstrap/colors.adoc[theme colors] (`primary`,
  `success`, `danger`, etc.) as its background
|===

Applied together on the base example above:

[source,html]
----
<table class="table table-striped table-bordered table-hover">
  ...
</table>
----

== Coloring individual rows or cells

The same theme-color contextual classes apply directly to a `<tr>` or a `<td>`/`<th>`, not just the whole
table -- useful for flagging a specific row (e.g. an error state) without affecting the rest:

[source,html]
----
<table class="table">
  <tbody>
    <tr class="table-success">
      <td>Row flagged success</td>
      <td>Extra cell</td>
    </tr>
    <tr>
      <td>Normal row</td>
      <td>with one flagged cell:</td>
      <td class="table-danger">Flagged cell</td>
    </tr>
  </tbody>
</table>
----

== Responsive tables

Wrapping a `.table` in a `.table-responsive` container lets the table scroll horizontally on narrow
viewports, instead of either overflowing the page or being squeezed unreadably into a phone-width column:

[source,html]
----
<div class="table-responsive">
  <table class="table">
    <!-- a table with many columns -->
  </table>
</div>
----

Breakpoint-specific variants -- `.table-responsive-sm`, `-md`, `-lg`, `-xl`, `-xxl` -- make the table
responsive only *below* that breakpoint, and a normal (non-scrolling) table from that breakpoint upward, using
the same breakpoint scale as xref:web/bootstrap/grid-system.adoc[the grid system].

== A fully styled responsive table

Combining the pieces above into one realistic example -- dense, striped, bordered, hoverable, dark header, and
horizontally scrollable on narrow viewports:

[source,html]
----
<div class="table-responsive">
  <table class="table table-sm table-striped table-bordered table-hover">
    <thead class="table-dark">
      <tr>
        <th scope="col">#</th>
        <th scope="col">Product</th>
        <th scope="col">Category</th>
        <th scope="col">Price</th>
        <th scope="col">In Stock</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">1</th>
        <td>Wireless Mouse</td>
        <td>Accessories</td>
        <td>$24.99</td>
        <td>Yes</td>
      </tr>
      <tr>
        <th scope="row">2</th>
        <td>Mechanical Keyboard</td>
        <td>Accessories</td>
        <td>$89.99</td>
        <td>Yes</td>
      </tr>
      <tr class="table-warning">
        <th scope="row">3</th>
        <td>USB-C Hub</td>
        <td>Accessories</td>
        <td>$39.99</td>
        <td>Low stock</td>
      </tr>
      <tr class="table-danger">
        <th scope="row">4</th>
        <td>27" Monitor</td>
        <td>Displays</td>
        <td>$299.99</td>
        <td>Out of stock</td>
      </tr>
    </tbody>
  </table>
</div>
----

`<thead class="table-dark">` applies the dark variant to just the header row group rather than the whole
table, which is the common pattern for making the header visually distinct from the striped body rows. The
`.table-warning`/`.table-danger` rows demonstrate flagging specific rows (low/out-of-stock) inline with the
rest of the styling, using the same xref:web/bootstrap/colors.adoc[theme color] names used everywhere else in
Bootstrap.

== Captions, dividers and vertical alignment

Three small features round out the base table. A `<caption>` gives the table an accessible name and a visible
title; Reboot puts it at the bottom of the table (`caption-side: bottom`) and `.caption-top` moves it above.
`.table-group-divider` on a `<thead>`, `<tbody>` or `<tfoot>` draws a thicker line (twice the border width, in the
current text color) between row groups, which is a lighter alternative to `.table-bordered` for separating the
header from the body. Finally, cells are top-aligned by default (`.table` sets `vertical-align: top`, and
`<thead>` is bottom-aligned), and the vertical alignment utilities `.align-top`, `.align-middle` and
`.align-bottom` can be applied to the table, a row group, a row or a single cell, because `<tbody>` inherits the
alignment of the table:

[source,html]
----
<table class="table align-middle">
  <caption class="caption-top">Open orders</caption>
  <thead>
    <tr><th scope="col">Order</th><th scope="col">Customer</th><th scope="col" class="text-end">Total</th></tr>
  </thead>
  <tbody class="table-group-divider">
    <tr><th scope="row">1001</th><td>Ada <br> <small class="text-body-secondary">VIP</small></td><td class="text-end">$114.98</td></tr>
    <tr><th scope="row">1002</th><td class="align-bottom">Grace</td><td class="text-end">$39.99</td></tr>
  </tbody>
</table>
----

Numeric columns are right-aligned with the `.text-end` utility from xref:web/bootstrap/typography.adoc[Typography],
so the digits line up.

== How a table cell is painted

Bootstrap 5.3 builds every table color from CSS custom properties declared on the `.table` element itself, which is
what makes the modifier classes composable. The relevant rule is:

[source,css]
----
.table > :not(caption) > * > * {
  color: var(--bs-table-color-state, var(--bs-table-color-type, var(--bs-table-color)));
  background-color: var(--bs-table-bg);
  box-shadow: inset 0 0 0 9999px
    var(--bs-table-bg-state, var(--bs-table-bg-type, var(--bs-table-accent-bg)));
}
----

Every cell gets its base color from `--bs-table-bg`, and then a second layer is painted on top of it with an
oversized inset `box-shadow`. That layer is chosen by a three-step fallback: a *state* (hover or `.table-active`)
wins over a *type* (striping), which wins over the *accent* (transparent unless a theme sets it). The classes only
set these variables:

* `.table-striped` sets `--bs-table-bg-type` on odd rows, so a striped row is a translucent overlay rather than a
  new background.
* `.table-hover` sets `--bs-table-bg-state` on the row under the pointer, which overrides the stripe.
* `.table-active` sets the same state variables permanently, so a "selected" row stays highlighted and still
  overrides the stripe.
* `.table-primary`, `.table-danger` and the other contextual classes redefine the whole palette (`--bs-table-bg`,
  and the striped, active and hover variants) for the element they are on, so stripes and hover inside a colored
  table are tinted consistently with it.

[mermaid]
....
flowchart TD
    BASE["Base layer:<br/>background-color = --bs-table-bg"]
    STATE{"--bs-table-bg-state set?<br/>hover or .table-active"}
    TYPE{"--bs-table-bg-type set?<br/>.table-striped odd row"}
    ACCENT["--bs-table-accent-bg<br/>(transparent by default)"]
    OVERLAY["Overlay layer painted with<br/>inset box-shadow"]

    BASE --> STATE
    STATE -- yes --> OVERLAY
    STATE -- no --> TYPE
    TYPE -- yes --> OVERLAY
    TYPE -- no --> ACCENT --> OVERLAY
....

Because the colors are variables, a single table can be re-themed without writing a selector, by setting the
variable on the element:

[source,html]
----
<table class="table table-striped" style="--bs-table-striped-bg: #eef3ff; --bs-table-striped-color: #1a237e;">
  ...
</table>
----

== Deep dive: a selectable orders table

The product tables above flag stock levels with static classes. A more interactive example is an orders table where
ticking a checkbox marks the row as selected. Since `.table-active` already overrides stripes and hover, the script
only has to toggle that class on the row:

[source,html]
----
<table class="table table-striped table-hover align-middle" id="orders">
  <caption class="caption-top">Open orders</caption>
  <thead>
    <tr><th scope="col"></th><th scope="col">Order</th><th scope="col" class="text-end">Total</th></tr>
  </thead>
  <tbody>
    <tr>
      <td><input type="checkbox" class="form-check-input select-row" aria-label="Select order 1001"></td>
      <th scope="row">1001</th><td class="text-end">$114.98</td>
    </tr>
    <tr>
      <td><input type="checkbox" class="form-check-input select-row" aria-label="Select order 1002"></td>
      <th scope="row">1002</th><td class="text-end">$39.99</td>
    </tr>
  </tbody>
</table>
<p id="selection-count" aria-live="polite">0 selected</p>
----

[source,js]
----
const table = document.getElementById("orders");
const count = document.getElementById("selection-count");

// One delegated listener covers every row, including rows added later
table.addEventListener("change", (event) => {
  if (!event.target.matches(".select-row")) return;
  event.target.closest("tr").classList.toggle("table-active", event.target.checked);
  count.textContent = `${table.querySelectorAll("tr.table-active").length} selected`;
});
----

The checkbox, not the color, carries the selection state for assistive technology (it has an `aria-label` and a
checked state), and the `aria-live="polite"` paragraph announces the new count. The row color is only a visual
reinforcement.

== Adding a table color to the Sass build

The contextual classes are generated by a loop over the `$table-variants` Sass map, so a project-specific color is a
`map-merge` between the `variables` and `maps` imports; Bootstrap derives the border, striped, active and hover
shades from the one color you give it:

[source,scss]
----
@import "bootstrap/scss/functions";
@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";

$table-variants: map-merge($table-variants, ("backorder": #ede7f6));

@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";
@import "bootstrap/scss/reboot";
@import "bootstrap/scss/tables";
----

This generates `.table-backorder`, which sets the same family of `+--bs-table-*+` variables as `.table-warning`
does. The mechanism is the same Sass-map approach described for utilities in
xref:web/bootstrap/utility-api.adoc[The Utility API].

See the official https://getbootstrap.com/docs/5.3/content/tables/[Tables] documentation for the complete
class reference, including vertical alignment and nested-table caveats.
