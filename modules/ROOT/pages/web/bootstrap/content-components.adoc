= Content Components
:description: Covers Bootstrap 5's card component (header, body, footer, images, and layout variants), list groups, and badges.
:keywords: bootstrap card, card-header, card-body, card-footer, list group, list-group-item, badge, pill badge

include::partial$ai-disclaimer.adoc[]

Cards, list groups, and badges are the components most Bootstrap pages reach for to present a self-contained
unit of content -- a product tile, a settings menu, a status label -- rather than a full-page layout. All three
are pure markup and CSS; none of them require the JavaScript bundle.

== Cards

=== Anatomy

A `.card` is a bordered, rounded container divided into an optional header, a body, and an optional footer:

image::bootstrap-card-anatomy.svg["A Bootstrap card's anatomy showing the card-header region at the top, the card-body region in the middle containing a card-title, card-text, and a button, and the card-footer region at the bottom"]

[source,html]
----
<div class="card" style="width: 18rem;">
  <div class="card-header">
    Featured
  </div>
  <div class="card-body">
    <h5 class="card-title">Card title</h5>
    <p class="card-text">
      Some quick example text to build on the card title and make up the bulk of the card's content.
    </p>
    <a href="#" class="btn btn-primary">Go somewhere</a>
  </div>
  <div class="card-footer text-body-secondary">
    2 days ago
  </div>
</div>
----

`.card-header` and `.card-footer` are both optional -- a card with neither is just `.card` wrapping a single
`.card-body`. Inside the body, `.card-title` sizes a heading element consistently regardless of which `<h1>`-
`<h6>` level is used, and `.card-subtitle` (paired with a muted `.text-body-secondary` utility) sits directly
under it for a secondary line.

=== Images

`.card-img-top` (or `.card-img-bottom`) places an image flush against the top or bottom edge of the card,
outside the padded body, with corners that follow the card's own border radius:

[source,html]
----
<div class="card" style="width: 18rem;">
  <img src="cap.jpg" class="card-img-top" alt="Descriptive alt text for the card's image">
  <div class="card-body">
    <h5 class="card-title">Card with image</h5>
    <p class="card-text">Text below the image, inside the padded body.</p>
  </div>
</div>
----

An image can also fill the *entire* card as a background, with text overlaid on top, using `.card-img` plus
`.card-img-overlay`:

[source,html]
----
<div class="card text-bg-dark">
  <img src="banner.jpg" class="card-img" alt="Descriptive alt text">
  <div class="card-img-overlay">
    <h5 class="card-title">Overlaid title</h5>
    <p class="card-text">Overlaid text, positioned absolutely over the image.</p>
  </div>
</div>
----

=== Layout: grids and groups

Multiple cards are usually laid out with the standard grid (see
xref:web/html-css/layout.adoc[Layout: Float, Flexbox & Grid]) rather than a card-specific class:

[source,html]
----
<div class="row row-cols-1 row-cols-md-3 g-4">
  <div class="col">
    <div class="card h-100">
      <div class="card-body"><h5 class="card-title">Card 1</h5></div>
    </div>
  </div>
  <div class="col">
    <div class="card h-100">
      <div class="card-body"><h5 class="card-title">Card 2</h5></div>
    </div>
  </div>
  <div class="col">
    <div class="card h-100">
      <div class="card-body"><h5 class="card-title">Card 3</h5></div>
    </div>
  </div>
</div>
----

`.row-cols-1.row-cols-md-3` wraps one card per row on narrow screens and three per row at `md` and up, `.g-4`
adds gutters, and `.h-100` on each `.card` stretches every card in a row to match the tallest one, so uneven
content doesn't leave ragged card heights. `.card-group` is a related but different layout, not a horizontally
scrolling variant of it: it renders its cards as an equal-height flex row with the gutters between them removed
so adjacent borders touch, wrapping onto a new line at narrow widths the same as the grid above rather than
scrolling. An actual horizontally scrolling strip of cards needs `.d-flex.flex-nowrap.overflow-auto` on the
wrapper instead.

== List groups

`.list-group` renders a flush, bordered list -- a common building block for a settings menu, a sidebar of
options, or a simple feed:

[source,html]
----
<ul class="list-group">
  <li class="list-group-item">An item</li>
  <li class="list-group-item active" aria-current="true">A second, active item</li>
  <li class="list-group-item disabled" aria-disabled="true">A disabled item</li>
  <li class="list-group-item">A fourth item</li>
</ul>
----

=== Actionable items

Swapping `<li>`/`<ul>` for `<a>`/`<div>` (or `<button>`/`<div>`) turns each row into a clickable, hoverable,
focusable action rather than static text -- useful for a navigation-style list:

[source,html]
----
<div class="list-group">
  <a href="#" class="list-group-item list-group-item-action active" aria-current="true">
    Inbox
  </a>
  <a href="#" class="list-group-item list-group-item-action">Sent</a>
  <a href="#" class="list-group-item list-group-item-action">Drafts</a>
  <button type="button" class="list-group-item list-group-item-action" disabled>
    Archived (unavailable)
  </button>
</div>
----

=== Contextual colors and badges

Each item accepts the same contextual color modifiers as alerts (see
xref:web/bootstrap/feedback-components.adoc[Feedback Components]), and a `.badge` (below) can sit inside an
item to show a count, right-aligned with a `d-flex justify-content-between` on the item itself:

[source,html]
----
<ul class="list-group">
  <li class="list-group-item list-group-item-success">A success item</li>
  <li class="list-group-item list-group-item-danger">A danger item</li>
  <li class="list-group-item d-flex justify-content-between align-items-center">
    Notifications
    <span class="badge text-bg-primary rounded-pill">14</span>
  </li>
</ul>
----

=== Horizontal and flush variants

`.list-group-horizontal` (and its `-sm`/`-md`/`-lg`/`-xl`/`-xxl` breakpoint variants) lays items out in a row
instead of a column above that breakpoint; `.list-group-flush` removes the group's own rounded corners and
outer border, which is useful when the list sits directly inside a `.card`:

[source,html]
----
<div class="card">
  <div class="card-header">Recent activity</div>
  <ul class="list-group list-group-flush">
    <li class="list-group-item">Signed in</li>
    <li class="list-group-item">Updated profile</li>
  </ul>
</div>
----

== Badges

A `.badge` is a small, inline count or label, typically sitting next to a heading or inside a button or list
item:

[source,html]
----
<h3>Notifications <span class="badge text-bg-secondary">4</span></h3>

<button type="button" class="btn btn-primary">
  Messages <span class="badge text-bg-light">12</span>
</button>
----

`+text-bg-*+` (covering the same semantic palette used throughout Bootstrap -- `primary`, `secondary`, `success`,
`danger`, `warning`, `info`, `light`, `dark`) sets both the background and a contrasting, readable text color
in one class. Adding `.rounded-pill` renders fully rounded, pill-shaped ends instead of the default slightly
rounded rectangle:

[source,html]
----
<span class="badge text-bg-success rounded-pill">New</span>
<span class="badge text-bg-danger rounded-pill">3</span>
----

A badge has no default `aria` handling of its own -- if it conveys meaning beyond decoration (an unread count,
for instance), that meaning should also be present in the surrounding text or an `aria-label`, since the
badge's small size and color are not something every user can rely on to perceive it.

== How a card is built

A card is a column of optional regions inside one bordered box. The classes form a small tree, and knowing which class
belongs at which level explains most card layout bugs (a `.card-title` outside `.card-body` loses its padding, for
example):

[mermaid]
....
flowchart TB
    CARD[".card<br/>border, radius, flex column"]
    CARD --> HEADER[".card-header<br/>optional"]
    CARD --> IMGTOP[".card-img-top<br/>optional"]
    CARD --> BODY[".card-body<br/>padded content"]
    CARD --> LIST[".list-group.list-group-flush<br/>optional"]
    CARD --> FOOTER[".card-footer<br/>optional"]
    BODY --> TITLE[".card-title"]
    BODY --> SUBTITLE[".card-subtitle"]
    BODY --> TEXT[".card-text"]
    BODY --> LINK[".card-link or .btn"]
    HEADER -.-> TABS[".nav.nav-tabs.card-header-tabs"]
....

Because `.card` is a flex column and its regions are siblings, several of them can repeat or be omitted: a card can
have two `.card-body` blocks, a list group between them, or no body at all.

== Worked example: a Taskboard project card

Each project on the Taskboard is a card: the header shows the project name and a status badge, the body a progress
bar and a one-line summary, a flush list group the next tasks, and the footer the actions. The whole card is one
clickable target through a stretched link, with the action buttons kept independently clickable above it:

[source,html]
----
<div class="card h-100">
  <div class="card-header d-flex justify-content-between align-items-center">
    <h2 class="h6 mb-0">
      <a href="/projects/website" class="stretched-link link-body-emphasis text-decoration-none">Website relaunch</a>
    </h2>
    <span class="badge text-bg-warning">At risk</span>
  </div>

  <div class="card-body">
    <div class="progress mb-2" role="progressbar" aria-label="Project progress" aria-valuenow="62" aria-valuemin="0" aria-valuemax="100">
      <div class="progress-bar" style="width: 62%">62%</div>
    </div>
    <p class="card-text text-body-secondary mb-0">8 of 13 tasks done. Next release on Friday.</p>
  </div>

  <ul class="list-group list-group-flush">
    <li class="list-group-item text-truncate">Write documentation</li>
    <li class="list-group-item text-truncate">Fix login bug</li>
  </ul>

  <div class="card-footer d-flex gap-2">
    <a href="/projects/website/edit" class="btn btn-sm btn-outline-secondary position-relative z-2">Edit</a>
    <button type="button" class="btn btn-sm btn-outline-danger position-relative z-2">Archive</button>
  </div>
</div>
----

How it works:

* `.stretched-link` adds an `::after` pseudo-element on the link that is `position: absolute` and covers the nearest
  *positioned* ancestor. Bootstrap's `.card` is already `position: relative`, so the clickable area is exactly the
  card. The same class on a link inside a plain `<div>` would stretch to some far ancestor (or the whole page) unless
  that `<div>` is given `.position-relative`.
* The pseudo-element sits at `z-index: 1`, so any other control inside the card would be covered by it. The Edit and
  Archive buttons are lifted above it with `.position-relative.z-2`, which keeps them separately clickable.
* The link text is the project name, inside the heading, which gives screen-reader users a single, meaningful link
  instead of a "Read more" link repeated on every card.
* `.text-truncate` on the list items keeps one line per task whatever the title length (it needs a block with a
  constrained width, which a list item inside a card has).
* `.h-100` makes cards in a `+.row-cols-*+` grid the same height (see the grid example earlier on this page), and the
  progress bar is a separate Bootstrap component whose own `aria-valuenow` carries the value, because its width is only
  visual.

Every class in this example exists in Bootstrap 5.3.3's compiled CSS.

== Cards with tabs and horizontal layouts

A card header can host a tab navigation (`.nav.nav-tabs.card-header-tabs`), which merges the tab strip with the card
border, and a card can be laid out horizontally with the grid instead of a card-specific class:

[source,html]
----
<div class="card mb-3" style="max-width: 540px;">
  <div class="row g-0">
    <div class="col-md-4">
      <img src="cover.jpg" class="img-fluid rounded-start h-100 object-fit-cover" alt="">
    </div>
    <div class="col-md-8">
      <div class="card-body">
        <h2 class="card-title h5">Mobile app</h2>
        <p class="card-text">Release 2.0 planning.</p>
      </div>
    </div>
  </div>
</div>
----

`.g-0` removes the gutters so that the image meets the card edge, and `.rounded-start` rounds only the side that sits
on the card's corner. Below `md` both columns are full width, which stacks the image above the body.

== Badges on other elements

A badge can be positioned over the corner of another element, such as an unread count on a button. The positioning
utilities do all the work; the one thing the badge needs for accessibility is text that says what the number means:

[source,html]
----
<button type="button" class="btn btn-outline-secondary position-relative">
  Inbox
  <span class="position-absolute top-0 start-100 translate-middle badge rounded-pill text-bg-danger">
    14
    <span class="visually-hidden">unread messages</span>
  </span>
</button>
----

`.top-0.start-100` places the badge's top-left corner at the button's top-right corner, and `.translate-middle` moves
it back by half of its own size so it is centered on that corner. The visually hidden text makes a screen reader
announce "Inbox 14 unread messages" instead of an unexplained "14".

== Customizing cards

Cards read their appearance from `+--bs-card-*+` custom properties, so one card can be changed in markup or CSS without
Sass:

[source,css]
----
.card-quiet {
  --bs-card-bg: transparent;
  --bs-card-border-color: transparent;
  --bs-card-cap-bg: transparent;
  --bs-card-spacer-y: 1.5rem;
}
----

To change every card, set the Sass variables before the variables partial. This compiled with Bootstrap 5.3.3 and
produced `--bs-card-spacer-y: 1.25rem`, `--bs-card-border-radius: 1rem` and `--bs-card-cap-bg: transparent` on `.card`:

[source,scss]
----
@import "bootstrap/scss/functions";
$card-spacer-y: 1.25rem;
$card-spacer-x: 1.25rem;
$card-border-radius: 1rem;
$card-cap-bg: transparent;
@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";
@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";
@import "bootstrap/scss/card";
----

See https://getbootstrap.com/docs/5.3/components/card/[the official Card docs],
https://getbootstrap.com/docs/5.3/components/list-group/[the official List Group docs], and
https://getbootstrap.com/docs/5.3/components/badge/[the official Badge docs] for the complete set of variants.
