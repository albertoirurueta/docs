= Typography
:description: Covers Bootstrap's heading styles, display headings, lead paragraphs, and inline/block text utility classes.
:keywords: bootstrap typography, headings, display headings, lead, text utilities, font weight, text alignment

include::partial$ai-disclaimer.adoc[]

Bootstrap's typography sets a consistent base font stack, size scale, and line height on the raw HTML text
elements (as part of xref:web/bootstrap/reboot.adoc[Reboot]), then layers a small set of classes on top for the
cases the raw elements do not cover -- oversized display headings, lead paragraphs, and general text utilities.

== Headings

`<h1>` through `<h6>` are styled out of the box with a descending size scale, so plain semantic markup already
looks reasonable with no classes at all:

[source,html]
----
<h1>h1. Bootstrap heading</h1>
<h2>h2. Bootstrap heading</h2>
<h3>h3. Bootstrap heading</h3>
<h4>h4. Bootstrap heading</h4>
<h5>h5. Bootstrap heading</h5>
<h6>h6. Bootstrap heading</h6>
----

The matching `.h1`-`.h6` classes apply the *same* styling to a non-heading element -- useful when the visual
size needed does not match the semantically correct heading level for the document outline:

[source,html]
----
<p class="h3">This paragraph looks like an h3, but is still a &lt;p&gt; in the outline.</p>
----

Keep the semantic element (`<h1>`-`<h6>`) chosen for document structure and accessibility, and reach for the
`.h1`-`.h6` classes only when the *visual* size needs to diverge from that structural level -- never the other
way around.

== Display headings

For a hero section or landing-page headline that needs to be larger and lighter-weight than even `<h1>`,
Bootstrap ships six display sizes, `.display-1` (largest) through `.display-6` (smallest, but still larger than
a normal `<h1>`):

[source,html]
----
<h1 class="display-1">Display 1</h1>
<h1 class="display-2">Display 2</h1>
<h1 class="display-3">Display 3</h1>
<h1 class="display-4">Display 4</h1>
<h1 class="display-5">Display 5</h1>
<h1 class="display-6">Display 6</h1>
----

Display classes use a larger `font-size` and a lighter `font-weight` (300) than the regular heading scale, and
their size is *fluid* below the `xl` breakpoint: the compiled CSS uses a `calc()` that mixes a `rem` base with a
viewport-width term, and switches to a fixed `rem` value from 1200px upward (see
<<responsive-font-sizes,Responsive font sizes>> below). It is not a `clamp()` expression and it does not jump
discretely at each breakpoint.

== Lead paragraphs

`.lead` makes a paragraph stand out from surrounding body text -- larger font size and a lighter weight --
commonly used for the introductory sentence under a heading:

[source,html]
----
<p class="lead">
  This is a lead paragraph. It stands out from regular paragraphs with a larger font size
  and lighter font weight.
</p>
----

== Inline text elements

The standard HTML inline elements for emphasis, marking, deletion, and small print are all restyled
consistently by Reboot, so they need no extra class:

[source,html]
----
<p>You can use the mark tag to <mark>highlight</mark> text.</p>
<p><del>This line of text is meant to be treated as deleted text.</del></p>
<p><s>This line of text is meant to be treated as no longer accurate.</s></p>
<p><ins>This line of text is meant to be treated as an addition to the document.</ins></p>
<p><u>This line of text will render as underlined.</u></p>
<p><small>This line of text is meant to be treated as fine print.</small></p>
<p><strong>This line rendered as bold text.</strong></p>
<p><em>This line rendered as italicized text.</em></p>
----

== Text utility classes

A larger set of single-purpose utility classes cover alignment, transformation, weight, and wrapping, and are
meant to be combined freely on any element:

[cols="2,3", options="header"]
|===
| Class(es) | Effect

| `.text-start` / `.text-center` / `.text-end`
| Horizontal text alignment (non-responsive)

| `.text-sm-center`, `.text-md-end`, ...
| Responsive alignment, following the same breakpoint infixes as
  xref:web/bootstrap/grid-system.adoc[the grid system]

| `.text-lowercase` / `.text-uppercase` / `.text-capitalize`
| CSS `text-transform`

| `.fw-bold` / `.fw-semibold` / `.fw-normal` / `.fw-light`
| Font weight

| `.fst-italic` / `.fst-normal`
| Font style (italic vs. normal)

| `.text-decoration-underline` / `.text-decoration-line-through` / `.text-decoration-none`
| Text decoration -- `.text-decoration-none` is frequently used to strip the default underline from an
  anchor styled to look like something other than a link

| `.text-wrap` / `.text-nowrap`
| Whether text is allowed to wrap onto multiple lines

| `.text-truncate`
| Truncates overflowing text with an ellipsis (requires the element to be `display: inline-block` or `block`
  with a constrained width)

| `.text-break`
| Forces long unbroken strings (URLs, tokens) to wrap rather than overflow their container

| `.text-body-secondary`
| Reduced-emphasis grey text that follows the active color mode. The older `.text-muted` still compiles in
  Bootstrap 5.3 but is deprecated in favor of this class -- see the note on
  xref:web/bootstrap/colors.adoc[color utility classes] for the full color set
|===

[source,html]
----
<p class="text-center text-uppercase fw-bold">Centered, uppercase, bold</p>
<p class="text-md-end text-nowrap">Right-aligned from md upward, never wraps</p>
<div class="text-truncate" style="max-width: 200px;">
  This sentence is too long to fit and will be truncated with an ellipsis.
</div>
----

== Responsive font sizes

Headings, `+.display-*+` and `+.fs-*+` do not use fixed pixel sizes. Bootstrap runs every large font size through
RFS (responsive font sizes), a Sass mixin that emits a fluid `calc()` below the `xl` breakpoint and the plain
size at and above it. For `h1` the compiled output is:

[source,css]
----
h1, .h1 { font-size: calc(1.375rem + 1.5vw); }
@media (min-width: 1200px) {
  h1, .h1 { font-size: 2.5rem; }
}
----

The `rem` part is the floor and the `vw` term makes the heading grow with the viewport until it reaches its
final size, so the curve is continuous: there is no jump at 1200px. Evaluating the formulas for a few viewport
widths (a 16px root font size) shows how the scale compresses on phones:

[cols="1,1,1,1", options="header"]
|===
| Viewport width | `h1` | `h2` | `.display-1`

| 360px | 27.4px | 24.4px | 42.2px
| 768px | 33.5px | 28.1px | 60.6px
| 992px | 36.9px | 30.1px | 70.6px
| 1200px and up | 40px | 32px | 80px
|===

`h5` and `h6` (1.25rem and 1rem) are small enough that RFS leaves them fixed. Because the unit is `rem`, a user who
raises the browser's default font size scales every heading as well. RFS is controlled by Sass variables such as
`$enable-rfs` and `$rfs-breakpoint`, covered in xref:web/bootstrap/customization.adoc[Customization].

== Font size, weight, line height and family utilities

The heading scale is also available as utilities for any element, which is the usual way to size text that is not
a heading:

[cols="2,3", options="header"]
|===
| Class(es) | Effect

| `.fs-1` through `.fs-6`
| The same sizes as `h1`--`h6`, including the fluid behavior of `.fs-1`--`.fs-4`.

| `.fw-lighter`, `.fw-light`, `.fw-normal`, `.fw-medium`, `.fw-semibold`, `.fw-bold`, `.fw-bolder`
| Font weight. `.fw-bolder` and `.fw-lighter` are relative to the parent, the others are absolute (300 to 700).

| `.lh-1`, `.lh-sm`, `.lh-base`, `.lh-lg`
| Line height `1`, `1.25`, `1.5` and `2`.

| `.font-monospace`
| Switches to the monospace font stack used for `code` and `pre`.

| `.small`, `.mark`
| The same restyling as `<small>` and `<mark>`, for elements that are not those tags.

| `.text-reset`
| Resets the text color to the inherited color, typically on a link inside a colored container.
|===

== Lists, quotes and abbreviations

Reboot gives lists a `2rem` left padding. Two classes undo the bullets for navigation-like content:
`.list-unstyled` removes the marker and padding, and `.list-inline` plus `.list-inline-item` lays the items out on
one line with a `0.5rem` gap:

[source,html]
----
<ul class="list-unstyled">
  <li>Wireless Mouse</li>
  <li>Mechanical Keyboard</li>
</ul>

<ul class="list-inline">
  <li class="list-inline-item">Accessories</li>
  <li class="list-inline-item">Displays</li>
</ul>
----

Quotations use `.blockquote` on a `<blockquote>`, with a `.blockquote-footer` for the attribution (it prepends an
em dash with CSS). Wrap the whole thing in a `<figure>` so the quote and its source stay together, and apply
`.text-end` or `.text-center` on the figure to align it. Abbreviations are written with `+<abbr title="...">+`,
which Reboot underlines with a dotted line, and `.initialism` shrinks and uppercases an all-caps abbreviation:

[source,html]
----
<figure class="text-center">
  <blockquote class="blockquote">
    <p>Utility classes keep the markup honest about what each element looks like.</p>
  </blockquote>
  <figcaption class="blockquote-footer">
    A team member in <cite title="Retrospective notes">Retrospective notes</cite>
  </figcaption>
</figure>

<p>An <abbr title="Stock Keeping Unit" class="initialism">sku</abbr> identifies each product.</p>
----

== Deep dive: typography for a product detail page

The product catalog used across this section needs a detail header with a headline, a price line, a short summary
and a spec list. The semantic element carries the document structure and the classes only adjust the look:

[source,html]
----
<header class="mb-4">
  <h1 class="display-5 fw-bold">
    Mechanical Keyboard
    <small class="d-block fs-5 fw-normal text-body-secondary">Accessories</small>
  </h1>
  <p class="lead">Hot-swappable switches, aluminium frame, USB-C.</p>
  <p class="fs-3 fw-semibold mb-1">$89.99</p>
  <p class="small text-body-secondary">
    <abbr title="Stock Keeping Unit" class="initialism">sku</abbr> KB-0089
  </p>
</header>

<ul class="list-inline">
  <li class="list-inline-item fw-medium">Layout</li>
  <li class="list-inline-item text-body-secondary">ANSI</li>
</ul>

<p class="text-truncate" style="max-width: 24rem;">
  A long marketing blurb that would otherwise push the layout wide on narrow screens.
</p>
----

The `<h1>` is the page's only top-level heading, and `.display-5` makes it larger than a normal `h1` without
changing its level. The category is a nested `<small>` turned into a block with `.d-block`, resized with `.fs-5`
and de-emphasized with `.text-body-secondary`, so the heading still reads as one unit to a screen reader. The
price is a paragraph styled with `.fs-3`: it looks like a heading, but it is not one, which keeps the outline
free of headings that only exist for their size.

== Where typography fits with the rest of Bootstrap

The base font family, sizes, and line-height Bootstrap applies to headings and body text are Sass variables
under the hood (`$font-family-base`, `$h1-font-size`, and so on) -- see
xref:web/bootstrap/customization.adoc[Customization] for overriding them, and
xref:web/bootstrap/reboot.adoc[Reboot] for the reset layer these styles build on top of. The color of any of
this text can be changed independently with the same
xref:web/bootstrap/colors.adoc[text color utility classes] used elsewhere on the page.

See the official https://getbootstrap.com/docs/5.3/content/typography/[Typography] documentation for the full
class list, including the responsive-alignment and list-style utilities not covered above.
