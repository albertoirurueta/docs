= Images
:description: Covers Bootstrap's image utilities -- responsive images with .img-fluid, thumbnails, and the figure/figure-caption components.
:keywords: bootstrap images, img-fluid, img-thumbnail, figure, figure-caption, responsive images

include::partial$ai-disclaimer.adoc[]

Bootstrap's image handling is deliberately small: one responsive-sizing utility, one decorative-border
utility, and a two-element component for images that need a caption. Everything else about an `<img>` --
lazy loading, `srcset`, alt text -- is left to plain HTML, since none of it is Bootstrap-specific.

== Responsive images: `.img-fluid`

`.img-fluid` applies `max-width: 100%` and `height: auto` to an image, so it scales down to fit its parent
container but never scales up past its natural size or overflows on a narrow viewport:

[source,html]
----
<img src="photo.jpg" class="img-fluid" alt="A responsive image that scales with its container">
----

Unlike some resets, xref:web/bootstrap/reboot.adoc[Reboot] does *not* set `max-width`/`height` on `<img>` -- its
only image-level rule is `vertical-align: middle`. That means `.img-fluid` is doing all of the real work here,
not reasserting a default that's already in place: an `<img>` without it can overflow its container on a narrow
viewport, so a card, grid column, or any other container with a constrained width should add `.img-fluid`
explicitly rather than relying on Reboot to have handled it.

== Thumbnails: `.img-thumbnail`

`.img-thumbnail` adds a rounded `1px` border, padding, and a subtle border-radius around an image -- a
lightweight frame, commonly used for a grid of gallery or avatar images:

[source,html]
----
<img src="photo.jpg" class="img-thumbnail" alt="An image styled with a rounded, padded border">
----

`.img-thumbnail` already includes `max-width: 100%; height: auto;` as part of its own rule set, so it does not
need to be combined with `.img-fluid` -- applying both is redundant, not additive.

== Figures

For an image that needs a caption below it, Bootstrap provides a small figure component built on the native
`<figure>`/`<figcaption>` elements: `.figure` on the wrapping `<figure>`, `.figure-img` on the `<img>` (usually
paired with `.img-fluid`), and `.figure-caption` on the `<figcaption>`:

[source,html]
----
<figure class="figure">
  <img src="photo.jpg" class="figure-img img-fluid rounded" alt="A sample photo">
  <figcaption class="figure-caption">A caption for the above image.</figcaption>
</figure>
----

`.figure-caption` sets a smaller, muted font size and color for the caption text, matching the visual weight
Bootstrap gives to other secondary/supporting text (see the `.text-muted` utility on
xref:web/bootstrap/typography.adoc[Typography]). Using the semantic `<figure>`/`<figcaption>` pair rather than
a `<div>`/`<p>` also gives assistive technology an explicit association between the image and its caption,
without any extra `+aria-*+` attributes needed.

=== Aligning a figure's caption

Because `.figure-caption` is just a text utility applied to a block element, it composes with the ordinary
text-alignment utilities from xref:web/bootstrap/typography.adoc[Typography]:

[source,html]
----
<figure class="figure text-center">
  <img src="photo.jpg" class="figure-img img-fluid rounded" alt="A centered sample photo">
  <figcaption class="figure-caption">Centered caption text.</figcaption>
</figure>
----

== Combining image utilities with other Bootstrap classes

Image classes are ordinary utility classes, so they combine freely with borders, shadows, and rounding
utilities that are not image-specific:

[source,html]
----
<img
  src="photo.jpg"
  class="img-fluid rounded shadow-sm"
  alt="A rounded image with a subtle drop shadow">
----

* **`.rounded`** (and its directional variants `.rounded-top`, `.rounded-circle`, etc.) applies `border-radius`.
* **`.shadow-sm`** / **`.shadow`** / **`.shadow-lg`** applies a `box-shadow` of increasing size.
* Border color utilities such as `.border` and `.border-primary` layer a colored border on top -- see
  xref:web/bootstrap/colors.adoc[Colors] for the full set of border-color utility classes.

== Images inside the grid

An image with `.img-fluid` placed inside a grid column (see xref:web/bootstrap/grid-system.adoc[The Grid
System]) automatically shrinks and grows with that column as the viewport crosses breakpoints, with no
additional media queries needed on the project's own side:

[source,html]
----
<div class="row">
  <div class="col-md-4">
    <img src="thumb-1.jpg" class="img-fluid rounded" alt="Thumbnail one">
  </div>
  <div class="col-md-4">
    <img src="thumb-2.jpg" class="img-fluid rounded" alt="Thumbnail two">
  </div>
  <div class="col-md-4">
    <img src="thumb-3.jpg" class="img-fluid rounded" alt="Thumbnail three">
  </div>
</div>
----

Because `.img-fluid` only ever scales an image *down*, the source file's actual resolution still matters for
performance -- serving a single very large image and relying on CSS scaling wastes bandwidth on small
viewports. Responsive image loading (`srcset`, `sizes`, `<picture>`) is plain HTML and outside Bootstrap's
scope; the framework only controls how the image is *displayed* once loaded, not which file the browser
fetches.

== Image alignment

Because `<img>` renders as an inline element by default, the ordinary float and alignment utilities apply to
it the same way they apply to any other inline or block content:

[source,html]
----
<!-- Float left/right -->
<img src="photo.jpg" class="img-fluid rounded float-start" alt="Floated left of surrounding text">
<img src="photo.jpg" class="img-fluid rounded float-end" alt="Floated right of surrounding text">

<!-- Centered: switch the image to a block element first, then center it as a block -->
<img src="photo.jpg" class="img-fluid rounded mx-auto d-block" alt="Centered image">
----

Centering deliberately takes two classes rather than one: `.mx-auto` (automatic left/right margin) only
centers a *block-level* element with a defined width, so `.d-block` is needed first to switch the image away
from its default `inline` display -- an `.mx-auto` alone on an inline `<img>` has no visible effect.

== Background images vs. `<img>`

Everything on this page concerns a real `<img>` element in the markup. A **background image**, set via CSS
`background-image` on a `<div>` or similar container, is a different mechanism entirely and is not covered by
`.img-fluid`, `.img-thumbnail`, or the figure component -- those classes only ever target the `<img>` tag's
own box. Bootstrap intentionally provides no dedicated background-image utility; sizing and positioning a
background image (`background-size: cover`, `background-position: center`) is plain CSS, chosen deliberately
for cases such as a hero banner where the image is purely decorative and should not appear in the accessibility
tree the way a real `<img>` (with meaningful `alt` text) does.

== Common pitfalls

* **Missing or empty `alt` text.** None of Bootstrap's image classes affect accessibility -- a meaningful,
  descriptive `alt` attribute (or `alt=""` for a genuinely decorative image) is still the author's
  responsibility on every `<img>`, exactly as covered in the accessibility notes on
  xref:web/bootstrap/getting-started.adoc[Getting Started].
* **Leaving off the `width` and `height` attributes because `.img-fluid` "handles sizing".** `.img-fluid` sets
  `max-width: 100%; height: auto`, which still scales the image correctly *after* it loads. Before it loads, the
  browser can only reserve the right amount of space if the tag carries the image's intrinsic `width` and `height`
  attributes, which modern browsers turn into an aspect ratio. Keep both attributes (they are the file's real pixel
  dimensions, not the displayed size) alongside `.img-fluid`, and the page does not jump when images arrive.
* **Stacking `.img-fluid` and `.img-thumbnail` together**, as noted above -- harmless, but redundant, since
  `.img-thumbnail` already includes the fluid-sizing rule.

== Worked example: Taskboard attachments and avatars

A task on the Taskboard can have a screenshot attachment and an assignee avatar. The attachment must scale with its
card, keep a stable shape so that cards in a row line up whatever the screenshot's dimensions, load a sharper file on
wide layouts, and avoid layout shift. The avatar is a small circle.

[source,html]
----
<div class="card" style="max-width: 24rem">
  <div class="ratio ratio-4x3">
    <img
      src="shot-400.jpg"
      srcset="shot-400.jpg 400w, shot-800.jpg 800w"
      sizes="(min-width: 768px) 24rem, 100vw"
      width="800" height="600"
      loading="lazy"
      class="card-img-top object-fit-cover"
      alt="Login form showing the 500 error banner">
  </div>
  <div class="card-body d-flex align-items-center gap-3">
    <img src="avatar-jane.png" width="40" height="40" class="rounded-circle" alt="">
    <div>
      <h2 class="h6 mb-0">Fix login bug</h2>
      <small class="text-body-secondary">Assigned to Jane</small>
    </div>
  </div>
</div>
----

Why each piece is there:

* `.ratio.ratio-4x3` reserves a 4:3 box (an `::before` pseudo-element with percentage padding) and stretches its
  direct child to fill it. The `<img>` must be that direct child, and `.object-fit-cover` crops the screenshot to the
  box instead of distorting it. A wrapper such as `<picture>` between the two would receive the stretching instead
  of the image. Aspect ratios available by default are `1x1`, `4x3`, `16x9` and `21x9`.
* `srcset` and `sizes` are plain HTML: they choose *which file* is downloaded (here the 400 or 800 pixel one,
  depending on the layout width). Bootstrap only decides how it is displayed afterwards. `<picture>` is for offering
  a different format or crop, and goes outside the ratio box when the two are combined.
* `width="800" height="600"` supply the intrinsic proportions so the space is reserved before the file arrives, and
  `loading="lazy"` defers images that are below the fold.
* The avatar has `alt=""` because the name is already printed next to it: an empty `alt` removes a purely redundant
  image from the accessibility tree, whereas the screenshot's `alt` describes what it shows.

=== Adding your own aspect ratio and thumbnail style

The ratio helper reads its choices from the `$aspect-ratios` map, and `.img-thumbnail` reads the `+$thumbnail-*+`
variables, so both can be changed at compile time. This was compiled and checked with Bootstrap 5.3.3:

[source,scss]
----
@import "bootstrap/scss/functions";
$thumbnail-padding: .5rem;
$thumbnail-border-radius: 1rem;

@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";
$aspect-ratios: map-merge($aspect-ratios, ("3x2": calc(2 / 3 * 100%)));

@import "bootstrap/scss/maps";
@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";
@import "bootstrap/scss/images";
@import "bootstrap/scss/helpers/ratio";
----

The result has `+.img-thumbnail { padding: 0.5rem; border-radius: 1rem; ... }+` and a new
`+.ratio-3x2 { --bs-aspect-ratio: 66.6666666667%; }+`, which is then used like any built-in class
(`<div class="ratio ratio-3x2">`).

See the official https://getbootstrap.com/docs/5.3/content/images/[Images] documentation for the full class
reference, including image alignment utilities.
