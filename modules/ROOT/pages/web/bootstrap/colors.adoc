= Colors
:description: Covers Bootstrap's theme color system -- primary, secondary, success, danger, warning, info, light, dark -- and the text, background, and border utility classes built on it.
:keywords: bootstrap colors, theme colors, text-primary, bg-primary, border-primary, contextual colors, utility classes

include::partial$ai-disclaimer.adoc[]

Bootstrap organizes color around a small named palette -- the **theme colors** -- rather than exposing raw hex
values throughout its component and utility classes. Every component that needs a contextual color (an alert,
a button, a badge, a border) draws from this same fixed set of names, which is what keeps a Bootstrap page's
color usage consistent without every author having to pick hex values by hand.

== The theme color set

Eight names make up the default theme palette, each carrying a semantic meaning rather than just a visual one:

[cols="1,3", options="header"]
|===
| Name | Typical meaning

| `primary`
| The brand's main color -- default emphasis (primary buttons, active nav links)

| `secondary`
| A muted, lower-emphasis complement to primary

| `success`
| A positive/confirmation state (a saved form, a completed step)

| `danger`
| An error or destructive-action state (a failed validation, a delete button)

| `warning`
| A caution state, something that needs attention but is not yet an error

| `info`
| A neutral, informational callout

| `light`
| A light neutral, typically near-white -- for a light background/surface

| `dark`
| A dark neutral, typically near-black -- for a dark background/surface
|===

These names appear consistently across unrelated Bootstrap components -- `.btn-primary`, `.alert-success`,
`.badge-danger`-lineage classes, and the table row classes covered in xref:web/bootstrap/tables.adoc[Tables]
(`.table-warning`, `.table-danger`) -- so learning the eight names once pays off across the whole framework,
not just the utility classes below.

== Text color utilities

`+.text-{color}+` sets the `color` (text/foreground color) property using one of the theme names:

[source,html]
----
<p class="text-primary">This text uses the primary theme color.</p>
<p class="text-success">This text uses the success theme color.</p>
<p class="text-danger">This text uses the danger theme color.</p>
<p class="text-muted">This text is deliberately de-emphasized, not a theme color.</p>
----

`.text-muted` is a related but distinct utility -- it is not one of the eight named theme colors, but a
separate, lower-opacity grey specifically meant for secondary/supporting text (see
xref:web/bootstrap/typography.adoc[Typography]).

Every `+.text-{color}+` class also has an `-emphasis` variant (`.text-primary-emphasis`, etc.) added in later
Bootstrap 5 releases, which resolves to a color tuned to keep sufficient contrast in both light and dark
xref:web/bootstrap/customization.adoc[color modes], rather than the flat theme color used as-is.

== Background color utilities

`+.bg-{color}+` sets `background-color` the same way, and is commonly paired with a matching or contrasting text
color to keep the result readable:

[source,html]
----
<div class="bg-primary text-white p-3">Primary background, white text</div>
<div class="bg-warning text-dark p-3">Warning background, dark text</div>
<div class="bg-light text-dark p-3">Light background, dark text</div>
<div class="bg-dark text-white p-3">Dark background, white text</div>
----

Because the theme colors have very different natural brightness (the yellow of `warning` is light, the near-black
of `dark` is dark), there is no single text color that reads well against all eight backgrounds -- pairing
`+.bg-{color}+` with an explicit `.text-white` or `.text-dark` (rather than relying on the default text color)
is standard practice, and matters for the contrast/accessibility points raised in
xref:web/bootstrap/getting-started.adoc[Getting Started].

`+.bg-{color}+` also accepts an opacity modifier, `+.bg-{color}-subtle+`, which uses a much lighter tint of the
color -- suited to a card or alert surface where the full-strength background would be too visually loud:

[source,html]
----
<div class="bg-danger-subtle text-danger-emphasis p-3 rounded">
  A subdued danger-tinted panel, rather than a solid danger-red block.
</div>
----

== Border color utilities

`+.border-{color}+` sets the `border-color` of an element that already has `.border` (or one of its directional
variants) applied -- the color utility does not itself add a border, only colors one that is already present:

[source,html]
----
<div class="border border-primary p-3 mb-2">Primary-colored border</div>
<div class="border border-success p-3 mb-2">Success-colored border</div>
<div class="border border-2 border-danger p-3">A thicker (border-2), danger-colored border</div>
----

`+.border-{n}+` (`0` through `5`) controls border *width* and composes independently of `+.border-{color}+`, which
controls only the color -- the two are applied together as in the third example above.

== Combining color utilities with components

Because these are plain utility classes rather than component-specific styles, they work equally well layered
onto an unrelated component -- an image (see xref:web/bootstrap/images.adoc[Images]), a table cell, or a plain
`<div>` used as a custom card:

[source,html]
----
<img
  src="photo.jpg"
  class="img-fluid rounded border border-primary"
  alt="An image with a primary-colored border">

<span class="badge bg-info text-dark">New</span>
----

== Customizing the palette

The eight theme colors are not hardcoded -- each one is backed by a Sass variable (`$primary`, `$secondary`,
`$success`, and so on) with a `!default` value, following exactly the pattern described in
xref:web/sass/variables.adoc[Variables]. Overriding `$primary` before importing Bootstrap's Sass changes not
only `.text-primary`/`.bg-primary`/`.border-primary`, but every component across the framework that draws on
the primary color -- buttons, links, form focus rings, and more -- from that single variable. That whole
customization workflow, including adding entirely new theme colors beyond the default eight, is covered in
xref:web/bootstrap/customization.adoc[Customization].

== How a theme color becomes classes

A single entry in the `$theme-colors` map fans out into custom properties, utility classes and component variants.
Seeing the chain explains why overriding one Sass value changes the whole page:

[mermaid]
....
flowchart LR
    MAP["$theme-colors<br/>primary: #0d6efd"] --> RGB["$theme-colors-rgb<br/>13, 110, 253"]
    MAP --> CONTRAST["color-contrast()<br/>picks #fff or #000"]
    RGB --> ROOT[":root<br/>--bs-primary and --bs-primary-rgb"]
    ROOT --> UTIL["utilities<br/>text-primary, bg-primary,<br/>border-primary, link-primary"]
    CONTRAST --> TEXTBG["text-bg-primary<br/>and button text colors"]
    MAP --> BTN["btn-primary, btn-outline-primary,<br/>alert-primary, badge, table-primary"]
    MAP --> SUBTLE["light mode: subtle, emphasis and<br/>border-subtle shades"]
    MAP --> SUBTLEDARK["dark mode: the same three shades,<br/>computed separately"]
    SUBTLE --> ROOT
    SUBTLEDARK --> ROOT
....

The colors that depend on it fall into three groups:

* **Solid colors** (`.text-primary`, `.bg-primary`, `.border-primary`) read `--bs-primary-rgb`, which is why they
  accept an opacity modifier (see below).
* **Contrast-picked text colors** (`+.text-bg-*+`, the text color of `+.btn-*+`) are computed by Sass at compile time.
* **Mode-dependent shades** (`-subtle` backgrounds, `-emphasis` text, `-border-subtle`) are separate custom properties
  with one value in light mode and another under `[data-bs-theme="dark"]`.

=== Automatic text contrast

`+.text-bg-{color}+` and the button variants do not hard-code white text. Bootstrap's `color-contrast()` Sass function
compares the background with `$color-contrast-light` (white) and `$color-contrast-dark` (black) and returns the first
one that reaches `$min-contrast-ratio` (4.5 by default, the WCAG AA threshold for normal text), or, when none does, the candidate with the
highest ratio (with a compile-time warning). Contrast ratios of the default palette, computed from the WCAG formula, and the color Bootstrap
chose:

|===

| `primary`
| `#0d6efd`
| 4.50
| 4.67
| white

| `secondary`
| `#6c757d`
| 4.69
| 4.48
| white

| `success`
| `#198754`
| 4.53
| 4.63
| white

| `danger`
| `#dc3545`
| 4.53
| 4.64
| white

| `warning`
| `#ffc107`
| 1.63
| 12.88
| black

| `info`
| `#0dcaf0`
| 1.96
| 10.72

| `light`

| 15.43

|===

Two observations: the default `primary` sits right at the 4.5 limit with white text, so even a slightly lighter blue
fails AA with white text; and where white and black are within a hair of each other (`primary`, `success`,
`danger`), Bootstrap prefers the first one in the comparison that clears 4.5, which is white. Pairing a utility such
as `.bg-warning` with an explicit `.text-dark` in markup reproduces by hand what `.text-bg-warning` does
automatically, so the `+text-bg-*+` form is the one to prefer.

=== Opacity and link utilities

Because the solid utilities are built on `rgba(var(--bs-primary-rgb), var(--bs-text-opacity))`, an opacity class
changes only the alpha channel:

[source,html]
----
<p class="text-primary text-opacity-50">A translucent primary text color.</p>
<div class="bg-success bg-opacity-25 border border-success border-opacity-50 p-3">Tinted panel</div>
<a href="#" class="link-primary link-underline-opacity-25 link-underline-opacity-100-hover">A themed link</a>
----

`.text-opacity-25` through `.text-opacity-100`, `.bg-opacity-10` through `.bg-opacity-100`, and the matching `+.border-opacity-*+` classes exist for the
three properties, and `+.link-{color}+` (with the `+.link-opacity-*+` and `+.link-underline-*+` helpers) colors a hyperlink
and its underline together.

NOTE: `.text-muted`, used earlier on this page, is deprecated since Bootstrap 5.3. New markup should use
`.text-body-secondary`, which reads the mode-aware `--bs-secondary-color` custom property and therefore stays
readable in dark mode.

== Color modes and the mode-aware utilities

Everything in the previous section recomputes when the color mode changes. A page opts in with
`data-bs-theme` on `<html>` (or on any subtree: `<div data-bs-theme="dark">` makes just that block dark):

[source,html]
----
<html lang="en" data-bs-theme="dark">
  <body class="bg-body text-body">
    <div class="bg-primary-subtle text-primary-emphasis p-3 rounded">Readable in both modes</div>
    <div class="bg-white text-dark p-3 rounded" data-bs-theme="light">Forced light panel</div>
  </body>
</html>
----

`.bg-body` and `.text-body` read `--bs-body-bg` and `--bs-body-color`, so they swap with the mode, while `.bg-white`
and `.bg-dark` are fixed colors that do not. In the default theme the `primary` subtle and emphasis shades are
`#cfe2ff` and `#052c65` in light mode and `#031633` and `#6ea8fe` in dark mode; the pair is chosen per mode so the
contrast holds in both, which a fixed `.bg-light text-dark` pair cannot do.

A small script lets the user choose and remembers the choice (it runs in the `<head>` to avoid a flash of the wrong
mode):

[source,javascript]
----
const stored = localStorage.getItem("theme");
const preferred = window.matchMedia("(prefers-color-scheme: dark)").matches ? "dark" : "light";
document.documentElement.setAttribute("data-bs-theme", stored ?? preferred);

function setTheme(mode) {
  localStorage.setItem("theme", mode);
  document.documentElement.setAttribute("data-bs-theme", mode);
}
----

== Worked example: adding the Taskboard brand colors

Taskboard needs a purple brand color and a coral accent that behave like built-in theme colors, including the subtle
and emphasis shades in both modes. The stylesheet below was compiled with Bootstrap 5.3.3 and Dart Sass. Note the
ordering: `$theme-colors` is extended right after the variables partial and *before* the maps partial (the maps are
derived from it), and the subtle/emphasis maps and the three hand-written utility maps are extended right *after*
the maps partial.

[source,scss]
----
@import "bootstrap/scss/functions";
@import "bootstrap/scss/variables";
@import "bootstrap/scss/variables-dark";

$brand: #6f42c1;
$accent: #ff6b6b;
$theme-colors: map-merge($theme-colors, ("brand": $brand, "accent": $accent));

@import "bootstrap/scss/maps";

// Shades for the new colors: light mode, then dark mode
$theme-colors-text: map-merge($theme-colors-text, ("brand": shade-color($brand, 60%)));
$theme-colors-bg-subtle: map-merge($theme-colors-bg-subtle, ("brand": tint-color($brand, 80%)));
$theme-colors-border-subtle: map-merge($theme-colors-border-subtle, ("brand": tint-color($brand, 60%)));
$theme-colors-text-dark: map-merge($theme-colors-text-dark, ("brand": tint-color($brand, 40%)));
$theme-colors-bg-subtle-dark: map-merge($theme-colors-bg-subtle-dark, ("brand": shade-color($brand, 80%)));
$theme-colors-border-subtle-dark: map-merge($theme-colors-border-subtle-dark, ("brand": shade-color($brand, 40%)));

// The -subtle / -emphasis utilities are listed by hand in Bootstrap's maps
$utilities-text-emphasis-colors: map-merge($utilities-text-emphasis-colors, ("brand-emphasis": var(--#{$prefix}brand-text-emphasis)));
$utilities-bg-subtle: map-merge($utilities-bg-subtle, ("brand-subtle": var(--#{$prefix}brand-bg-subtle)));
$utilities-border-subtle: map-merge($utilities-border-subtle, ("brand-subtle": var(--#{$prefix}brand-border-subtle)));

@import "bootstrap/scss/mixins";
@import "bootstrap/scss/root";
@import "bootstrap/scss/buttons";
@import "bootstrap/scss/helpers";
@import "bootstrap/scss/utilities";
@import "bootstrap/scss/utilities/api";
----

The compiled CSS contains `.btn-brand`, `.btn-outline-brand`, `.text-bg-brand` (white text, because
`color-contrast(#6f42c1)` is white: 6.51:1), `.text-bg-accent` (*black* text, because white on `#ff6b6b` is only
2.78:1 while black is 7.57:1), `.link-brand`, `.border-brand`, `.bg-brand-subtle`, `.text-brand-emphasis`,
`.border-brand-subtle`, and the custom properties `--bs-brand` and `--bs-brand-bg-subtle` in both the `:root` and the
dark-mode blocks. The shades chosen above give 11.35:1 (emphasis text on the subtle background) in light mode and
6.75:1 in dark mode.

If a brand color is added without the three subtle/emphasis maps, `.bg-brand` and `.btn-brand` still work, but
`.bg-brand-subtle` does not exist, which silently drops back to no background in markup that uses it. The same thing
happens if the three `+$utilities-*+` maps are left out: the custom properties exist, but no class exposes them.

The other Sass color helpers used here are `tint-color($color, $weight)` (mix with white), `shade-color($color,
$weight)` (mix with black), `shift-color($color, $weight)` (tint for a negative weight, shade for a positive one),
and `mix($a, $b, $weight)` from Sass itself, all of which accept a percentage weight.

See the official https://getbootstrap.com/docs/5.3/utilities/colors/[Colors] and
https://getbootstrap.com/docs/5.3/customize/color/[Color customization] documentation for the complete utility
class reference and the underlying Sass color system.
