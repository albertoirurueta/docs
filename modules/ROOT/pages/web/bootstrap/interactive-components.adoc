= Interactive Components
:description: Covers Bootstrap 5's dropdowns, accordions, and carousels, their required data attributes, and how each relies on the Popper.js-based positioning or vanilla-JS component API described in JavaScript Behavior.
:keywords: bootstrap dropdown, bootstrap accordion, bootstrap carousel, data-bs-toggle, popper.js, collapse, accordion-item

include::partial$ai-disclaimer.adoc[]

Dropdowns, accordions, and carousels are Bootstrap's three most commonly used *stateful* components -- each one
toggles between visual states (open/closed, expanded/collapsed, current/next slide) in response to user
interaction. All three are driven by the same underlying mechanism covered in full on
xref:web/bootstrap/javascript-behavior.adoc[JavaScript Behavior]: `+data-bs-*+` attributes for markup-only
wiring, and an equivalent `+new bootstrap.<Component>(...)+` JavaScript API for programmatic control. This page
assumes that mechanism and focuses on what is specific to each of the three components.

== Dropdowns

A dropdown pairs a toggle element with a menu that Bootstrap positions using https://popper.js.org/[Popper.js]
-- the same positioning engine covered on
xref:web/bootstrap/tooltips-popovers.adoc[Tooltips & Popovers], responsible for keeping the menu inside the
viewport and flipping its placement when it would otherwise overflow:

[source,html]
----
<div class="dropdown">
  <button class="btn btn-secondary dropdown-toggle" type="button" data-bs-toggle="dropdown" aria-expanded="false">
    Actions
  </button>
  <ul class="dropdown-menu">
    <li><a class="dropdown-item" href="#">Edit</a></li>
    <li><a class="dropdown-item" href="#">Duplicate</a></li>
    <li><hr class="dropdown-divider"></li>
    <li><a class="dropdown-item text-danger" href="#">Delete</a></li>
  </ul>
</div>
----

`data-bs-toggle="dropdown"` is the only attribute required to open the menu -- no `data-bs-target` is needed,
since the menu is simply the toggle's next sibling in the DOM. `aria-expanded` starts `false` and is flipped by
Bootstrap's JavaScript as the menu opens and closes, so it must be present in the initial markup even though
its value is managed at runtime afterward.

=== Placement and variants

`.dropstart`, `.dropend`, and `.dropup` (applied to the outer `.dropdown` wrapper) change which side of the
toggle the menu opens on, and `.dropdown-menu-end` right-aligns the menu against its toggle instead of the
default left alignment:

[source,html]
----
<div class="dropup">
  <button class="btn btn-secondary dropdown-toggle" data-bs-toggle="dropdown">Opens upward</button>
  <ul class="dropdown-menu">...</ul>
</div>

<div class="dropdown">
  <button class="btn btn-secondary dropdown-toggle" data-bs-toggle="dropdown">Right-aligned menu</button>
  <ul class="dropdown-menu dropdown-menu-end">...</ul>
</div>
----

A dropdown's toggle does not have to be a `<button>` -- a `<a class="nav-link dropdown-toggle">` inside a
navbar (see xref:web/bootstrap/navigation-components.adoc[Navigation Components]) uses the exact same
`data-bs-toggle="dropdown"` mechanism.

== Accordions

An accordion is a stack of collapsible panels, each built from an `.accordion-item` containing a header/button
pair and a collapsible body -- structurally, one accordion item is a styled wrapper around Bootstrap's plain
Collapse behavior:

[source,html]
----
<div class="accordion" id="faq-accordion">
  <div class="accordion-item">
    <h2 class="accordion-header">
      <button class="accordion-button" type="button" data-bs-toggle="collapse"
              data-bs-target="#faq-1" aria-expanded="true" aria-controls="faq-1">
        What is Bootstrap?
      </button>
    </h2>
    <div id="faq-1" class="accordion-collapse collapse show" data-bs-parent="#faq-accordion">
      <div class="accordion-body">
        A CSS/JS toolkit for building responsive, mobile-first sites.
      </div>
    </div>
  </div>

  <div class="accordion-item">
    <h2 class="accordion-header">
      <button class="accordion-button collapsed" type="button" data-bs-toggle="collapse"
              data-bs-target="#faq-2" aria-expanded="false" aria-controls="faq-2">
        Does it require jQuery?
      </button>
    </h2>
    <div id="faq-2" class="accordion-collapse collapse" data-bs-parent="#faq-accordion">
      <div class="accordion-body">
        No -- Bootstrap 5 uses vanilla JavaScript. See
        xref:web/bootstrap/javascript-behavior.adoc[JavaScript Behavior].
      </div>
    </div>
  </div>
</div>
----

`data-bs-parent="#faq-accordion"` on each `.accordion-collapse` is what makes the group *exclusive* -- opening
one panel automatically closes any other panel sharing the same parent. Omitting `data-bs-parent` (or giving
each item a different one) allows multiple panels to stay open simultaneously, turning the same markup into a
set of independent collapsibles rather than a true accordion.

The `.collapsed` class on the button and `.show` on the panel must be kept in sync with each other and with
`aria-expanded` in the *initial* HTML -- Bootstrap's JavaScript updates all three together after the first
interaction, but the page's starting state (which panel, if any, opens by default) is the author's
responsibility to set correctly up front.

== Carousels

A carousel cycles through a set of slides, each an `.carousel-item` inside `.carousel-inner`, with optional
indicators and previous/next controls:

[source,html]
----
<div id="promo-carousel" class="carousel slide" data-bs-ride="carousel">
  <div class="carousel-indicators">
    <button type="button" data-bs-target="#promo-carousel" data-bs-slide-to="0"
            class="active" aria-current="true" aria-label="Slide 1"></button>
    <button type="button" data-bs-target="#promo-carousel" data-bs-slide-to="1"
            aria-label="Slide 2"></button>
  </div>

  <div class="carousel-inner">
    <div class="carousel-item active">
      <img src="slide-1.jpg" class="d-block w-100" alt="Description of slide 1">
      <div class="carousel-caption d-none d-md-block">
        <h5>First slide</h5>
        <p>Some representative placeholder content.</p>
      </div>
    </div>
    <div class="carousel-item">
      <img src="slide-2.jpg" class="d-block w-100" alt="Description of slide 2">
    </div>
  </div>

  <button class="carousel-control-prev" type="button" data-bs-target="#promo-carousel" data-bs-slide="prev">
    <span class="carousel-control-prev-icon" aria-hidden="true"></span>
    <span class="visually-hidden">Previous</span>
  </button>
  <button class="carousel-control-next" type="button" data-bs-target="#promo-carousel" data-bs-slide="next">
    <span class="carousel-control-next-icon" aria-hidden="true"></span>
    <span class="visually-hidden">Next</span>
  </button>
</div>
----

Exactly one `.carousel-item` must carry `.active` in the initial markup (the first slide shown); the carousel
never infers a default on its own, and shipping none results in an empty carousel until the user or
`data-bs-ride` triggers the first transition. `data-bs-ride="carousel"` on the outer element starts automatic
cycling on page load; using `data-bs-ride="true"` instead only marks the carousel as ready to cycle without
starting it immediately.

=== Autoplay and accessibility

Auto-cycling content is a known accessibility concern -- WCAG requires a way to pause any content that moves,
blinks, or auto-updates for more than five seconds. Bootstrap's carousel automatically pauses on hover and on
focus by default (`data-bs-pause="hover"`), but for content that isn't purely decorative, explicitly offering a
visible pause control (calling the JavaScript API's `.pause()`/`.cycle()` from a button) is worth adding rather
than relying on hover/focus pausing alone, since neither helps a screen-reader user who isn't hovering or
tabbing through the carousel's own controls.

=== Dropdown behavior and options

A dropdown closes in more situations than a click on the toggle, and `autoClose` decides which ones count. Its
values are `true` (the default: close on a click inside or outside the menu, and on Escape), `"inside"` (close only
on a click inside), `"outside"` (close only on a click outside, which suits a menu that holds a form or filter
checkboxes) and `false` (close only through the toggle). Clicks on `input`, `select`, `textarea` and `form` elements
inside the menu never close it. Escape always closes it and returns focus to the toggle. The other options are
`offset` (`[skidding, distance]`, default `[0, 2]`), `boundary` (the clipping element, default `"clippingParents"`),
`reference` (`"toggle"` or `"parent"`, the element the menu is aligned to), `display` (`"dynamic"` or `"static"`; use
`static` to switch Popper off when the menu must not move) and `popperConfig` (an
object or a function that receives Bootstrap's defaults and returns the final Popper options).

[source,html]
----
<div class="dropdown">
  <button class="btn btn-outline-secondary dropdown-toggle" type="button"
          data-bs-toggle="dropdown" data-bs-auto-close="outside" aria-expanded="false">
    Filter
  </button>
  <form class="dropdown-menu p-3">
    <div class="form-check">
      <input class="form-check-input" type="checkbox" id="in-stock">
      <label class="form-check-label" for="in-stock">In stock only</label>
    </div>
    <button type="submit" class="btn btn-primary btn-sm mt-2">Apply</button>
  </form>
</div>
----

Responsive alignment is done with `.dropdown-menu-sm-end`, `.dropdown-menu-lg-start` and the other breakpoint
variants, and `data-bs-theme="dark"` on the menu gives it a dark theme (the older `.dropdown-menu-dark` class still compiles but is deprecated in 5.3). Inside the menu, `.dropdown-header`,
`.dropdown-item-text`, `.dropdown-divider`, `.active` and `.disabled` cover the non-link content. The dropdown events
(`show.bs.dropdown`, `shown.bs.dropdown`, `hide.bs.dropdown`, `hidden.bs.dropdown`) carry `relatedTarget` (the
toggle), and the `hide` and `hidden` events also carry `clickEvent` when the menu was closed by a click, which lets a
listener tell an outside click from a programmatic `hide()`.

== Collapse

Both the navbar toggler and the accordion are built on the Collapse plugin, which is also usable on its own for
"show more" regions. `data-bs-toggle="collapse"` plus `data-bs-target` (or an `href` on a link) toggles a `.collapse`
element, and the plugin keeps `aria-expanded` on the trigger and the `.collapsed` class in step with the state.
`data-bs-target` takes a selector, so one button can control several elements at once, and several buttons can
control one element. `.collapse-horizontal` makes the region animate its width instead of its height (give the
content a fixed width, because the animation has nothing else to size it):

[source,html]
----
<button class="btn btn-link p-0" type="button" data-bs-toggle="collapse"
        data-bs-target=".spec-row" aria-expanded="false" aria-controls="spec-1 spec-2">
  Show all specifications
</button>
<div class="collapse spec-row" id="spec-1">Switches: hot-swappable</div>
<div class="collapse spec-row" id="spec-2">Connection: USB-C</div>
----

The collapse events are `show.bs.collapse`, `shown.bs.collapse`, `hide.bs.collapse` and `hidden.bs.collapse`. When
`show()` is called on an element whose `data-bs-parent` points to an accordion, the plugin first hides whichever
sibling is currently open, which is why exactly one panel stays open.

=== Accordion variations

`.accordion-flush` removes the outer border, rounded corners and background, so an accordion can sit inside a card or
a page section without looking like a boxed widget. Leaving out `data-bs-parent` gives an "always open" accordion
where each panel opens and closes independently. In both cases the plugin updates `aria-expanded` on the button and
toggles `.collapsed` on it. With the FAQ markup from the Accordions section, after clicking the second button the
first button has `aria-expanded="false"` and `.collapsed`, and the second has `aria-expanded="true"` and no
`.collapsed`.

== Carousel options and events

The carousel options are `interval` (milliseconds between slides, default 5000), `keyboard` (arrow keys, default
`true`), `pause` (`"hover"` or `false`), `ride` (`false`, `true` or `"carousel"`), `touch` (swipe, default `true`) and
`wrap` (continuous loop, default `true`). With `wrap: false` the carousel stops at the first and last slide instead
of looping. An individual slide can override the delay with `data-bs-interval` on its `.carousel-item`. Adding
`.carousel-fade` to the carousel cross-fades instead of sliding, and `data-bs-theme="dark"` darkens the controls and
indicators for light slides (the older `.carousel-dark` class still compiles but is deprecated in 5.3).

The events are `slide.bs.carousel` (a slide change starts) and `slid.bs.carousel` (it finished). Both carry
`direction` (`"left"` or `"right"`), `from` and `to` (the zero-based indexes of the slides) and `relatedTarget`
(the incoming slide element). For a carousel with three slides, `next` from the first slide produces `direction:
"left"`, `from: 0`, `to: 1`, and a call to `.to(2)` after that gives `from: 1`, `to: 2`.

....
stateDiagram-v2
    [*] --> Idle
    Idle --> Cycling: cycle() or ride starts
    Cycling --> Sliding: interval elapsed
    Idle --> Sliding: next, prev, to() or indicator
    Sliding --> Cycling: transition ends, still cycling
    Sliding --> Idle: transition ends, not cycling
    Cycling --> Paused: pointer over carousel or pause()
    Paused --> Cycling: pointer leaves or cycle()
....

=== Deep dive: a product gallery with synced thumbnails and a pause button

A product page shows a gallery carousel with a thumbnail strip underneath. The thumbnails are not part of the
carousel markup: they are ordinary buttons with `data-bs-slide-to`, which the data API already treats as controls.
What the data API does *not* do for elements outside `.carousel-indicators` is keep them highlighted, so the script
listens to `slid.bs.carousel` and uses `event.to`. A play/pause button satisfies the accessibility requirement
described above:

[source,html]
----
<div id="gallery" class="carousel slide" aria-label="Product photos">
  <div class="carousel-inner">
    <div class="carousel-item active"><img src="front.jpg" class="d-block w-100" alt="Front view"></div>
    <div class="carousel-item"><img src="side.jpg" class="d-block w-100" alt="Side view"></div>
    <div class="carousel-item"><img src="back.jpg" class="d-block w-100" alt="Back view"></div>
  </div>
</div>

<div id="thumbs" class="d-flex gap-2 mt-2">
  <button type="button" class="btn btn-outline-secondary btn-sm active" aria-current="true"
          data-bs-target="#gallery" data-bs-slide-to="0">1</button>
  <button type="button" class="btn btn-outline-secondary btn-sm"
          data-bs-target="#gallery" data-bs-slide-to="1">2</button>
  <button type="button" class="btn btn-outline-secondary btn-sm"
          data-bs-target="#gallery" data-bs-slide-to="2">3</button>
  <button type="button" class="btn btn-link ms-auto" id="play-pause" aria-pressed="false">Pause</button>
</div>
----

[source,javascript]
----
import { Carousel } from "bootstrap";

const galleryEl = document.getElementById("gallery");
const gallery = Carousel.getOrCreateInstance(galleryEl, { interval: 4000, ride: "carousel" });
const thumbs = document.querySelectorAll("#thumbs [data-bs-slide-to]");

galleryEl.addEventListener("slid.bs.carousel", (event) => {
  thumbs.forEach((thumb, index) => {
    const current = index === event.to;
    thumb.classList.toggle("active", current);
    if (current) {
      thumb.setAttribute("aria-current", "true");
    } else {
      thumb.removeAttribute("aria-current");
    }
  });
});

const playPause = document.getElementById("play-pause");
let playing = true;
playPause.addEventListener("click", () => {
  playing = !playing;
  if (playing) {
    gallery.cycle();
  } else {
    gallery.pause();
  }
  playPause.textContent = playing ? "Pause" : "Play";
  playPause.setAttribute("aria-pressed", String(!playing));
});
----

Clicking the third thumbnail slides to the last photo, the `slid` listener moves `.active` and `aria-current` to the
third thumbnail, and the play/pause button stops and restarts the interval timer.

== Common thread: the JavaScript component API

All three components above can be created and driven entirely from `+data-bs-*+` attributes, but every one also
has a matching constructor for programmatic control -- opening a dropdown on some event other than a click,
jumping an accordion or carousel to a specific panel/slide from application code, and so on:

[source,js]
----
const dropdown = new bootstrap.Dropdown(document.getElementById("my-toggle"));
dropdown.show();

const carousel = new bootstrap.Carousel(document.getElementById("promo-carousel"));
carousel.to(1);   // jump to the second slide
carousel.pause();
----

See xref:web/bootstrap/javascript-behavior.adoc[JavaScript Behavior] for the full shape of that API --
instance creation via `getOrCreateInstance`, the common method/event naming conventions, and how it differs
from the `+data-bs-*+` markup-only approach used above. For the complete option/event reference of each
component, see https://getbootstrap.com/docs/5.3/components/dropdowns/[the official Dropdowns docs],
https://getbootstrap.com/docs/5.3/components/accordion/[the official Accordion docs], and
https://getbootstrap.com/docs/5.3/components/carousel/[the official Carousel docs].
