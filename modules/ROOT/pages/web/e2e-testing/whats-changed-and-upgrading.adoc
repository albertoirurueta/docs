= What's Changed and Upgrading
:description: A version-by-version map of what changed in browser end-to-end testing tools and services between mid-2024 and October 2026 -- Playwright 1.49 to 1.64 (aria snapshots, Test Agents, Chrome for Testing, screencast and trace CLI, passkeys and web storage, the component-testing rewrite, test locks, within and visible locators, WebMCP and getByRef, removed Node.js and operating systems), Cypress 15 to 16 (native network, Cypress.env removal, cy.env and Cypress.expose, cy.prompt, cypress tap, getByRole), Selenium 4.x (Selenium Manager, BiDi, Guava removal, postponed removals), renamed and retired services, and the Protractor end of life -- each with where it is documented in this section and what to do when upgrading.

Browser testing tools move quickly: Playwright ships a minor release roughly every month, Cypress shipped a new major
version in September 2026, and Selenium publishes a release every few weeks. This page collects the changes that matter
to someone maintaining an existing suite or writing a new one, organised by tool, and for every change it states the
version that introduced it, where this section documents it, and what an upgrade needs from you. It is written for
Playwright 1.64.1, Cypress 16.2.0 and Selenium 4.51.0, and every version, date and requirement was checked against the
official release notes, changelogs and migration guides on 25 October 2026.

Nothing on this page needed a running Bookshelf application. The only commands executed were version checks: in the
Playwright example project `npx playwright --version` printed `Version 1.64.1`, and in the Cypress example project
`npx cypress --version` reported Cypress package and binary version 16.2.0 (Electron 41.7.0). The migration snippets
below come from the official guides and were not run here; the pages linked in the tables contain the examples that
were run against Bookshelf. Items on this page that depend on commercial services or on AI products that need accounts
or paid keys are described from their official announcements and documentation.

== How to approach an upgrade

The same routine works for all three tools, and it keeps the number of simultaneous variables low.

. *Read the release notes between your version and the target.* Skipping versions is allowed for minor releases, but
the breaking changes accumulate, so read every version in between. Cypress and the other major-version tools ask for one
major at a time: the Cypress 16 migration guide explicitly says to be on 15.x first.
. *Upgrade the runtime before the tool.* Node.js, Python, the JDK and the operating system are the usual blockers; each
section below lists the versions that were dropped.
. *Pin the version.* Use an exact version in `package.json`, `pom.xml` or `requirements.txt`, and upgrade deliberately in
a dedicated branch. Browser binaries move with the tool (Playwright) or independently of it (Cypress, Selenium), so
record the browser versions too.
. *Run the suite once without changes and read the failures by category.* Most upgrade failures come from changed
defaults (visibility, headless mode, snapshot behaviour), removed APIs and updated screenshots, not from the tests.
. *Regenerate visual baselines in a controlled run* and review the differences, as described in
xref:web/e2e-testing/visual-regression-testing.adoc[Visual Regression Testing].
. *Update the container images and CI actions at the same time*, because the browser and the runner must match; see
xref:web/e2e-testing/running-in-ci-cd.adoc[Running in CI/CD].

[source,bash]
----
npm install --save-exact --save-dev @playwright/test@1.64.1
npx playwright install --with-deps
npx playwright --version
----

Executed here: `npx playwright --version` printed `Version 1.64.1` for the pinned example project; the install commands
are the documented upgrade steps and were already part of the project setup.

Source: https://playwright.dev/docs/intro[Playwright: Installation]

== Playwright 1.49 to 1.64

Playwright 1.49 (late 2024) to 1.64 (October 2026) covers sixteen releases. The tables group the changes by theme; the
last two tables list everything that was removed or changed incompatibly and the runtime requirements.

=== Locators and assertions

[cols="1,4,3,4",options="header"]
|===
|Version |Change |Documented here |Upgrade action

|1.49
|`+expect(locator).toMatchAriaSnapshot()+` compares the accessibility tree, written as YAML, with an expected snapshot.
1.50 allows snapshots in separate YAML files and adds `toHaveAccessibleErrorMessage()`; 1.52 adds `/children` for strict
matching and `/url` for links; 1.59 adds `page.ariaSnapshot()`, the `depth` and `mode` options and `boxes` (1.60); 1.60 lets
`toMatchAriaSnapshot()` run on a page; 1.63 adds `ariaSnapshotJSON()`.
|xref:web/e2e-testing/playwright/assertions.adoc[Assertions], xref:web/e2e-testing/accessibility-checks-in-e2e-tests.adoc[Accessibility Checks in E2E Tests]
|Optional. Adopt it for structural checks; generate snapshots with codegen and update them with `--update-snapshots`.

|1.51
|`locator.filter({ visible: true })` matches only visible elements.
|xref:web/e2e-testing/playwright/locators-actions-and-auto-waiting.adoc[Locators, Actions & Auto-Waiting]
|Optional; replaces ad-hoc `+:visible+` CSS selectors.

|1.52
|`expect(locator).toContainClass()` asserts individual class names.
|xref:web/e2e-testing/playwright/assertions.adoc[Assertions]
|Optional; replaces regular expressions against the `class` attribute.

|1.53
|`locator.describe()` names a locator for traces and reports.
|xref:web/e2e-testing/playwright/debugging-tracing-and-codegen.adoc[Debugging, Tracing & Codegen]
|Optional.

|1.59
|`locator.normalize()` rewrites a locator to follow best practice (test ids and roles), and `page.pickLocator()` lets you

|xref:web/e2e-testing/playwright/locators-actions-and-auto-waiting.adoc[Locators, Actions & Auto-Waiting]
|Optional.

|1.60
|`getByRole()` gains a `description` option (accessible description); `toHaveCSS()` gains `pseudo`; `locator.drop()`

|xref:web/e2e-testing/playwright/locators-actions-and-auto-waiting.adoc[Locators, Actions & Auto-Waiting]

=== Removed features and breaking changes

Read this table before moving across the listed versions; each row is a change that can fail a previously green suite.

[cols="1,5,4",options="header"]
|===
|Version |Breaking change |Upgrade action

|1.49
|`chrome` and `msedge` channels use the new headless mode. The `@playwright/experimental-ct-vue2` and
`-ct-solid` packages are no longer updated.
|Re-run the suite and refresh screenshots.

|1.50
|`toBeEditable()` and `isEditable()` throw if the element is not an editable element. `+updateSnapshots: 'all'+` now
rewrites every snapshot; `'changed'` keeps the old behaviour.
|Use `changed` in scripts that meant "update what differs".

|1.52
|URL glob patterns in `page.route()` no longer support `?` and `[]`. `route.continue()` ignores a `Cookie` header
override. WebKit updates stop for macOS 13.
|Use regular expressions in route patterns; set cookies on the context.

|1.54
|Node.js 16 support removed and Node.js 18 deprecated. The `-gv` flag is gone (use `--grep-invert`) and `+npx playwright open+` no longer opens the recorder (use `codegen`).
|Update scripts and CI to the runtimes in the table below.

|1.55
|Chromium extension manifest v2 support dropped.
|Port extensions to manifest v3; see xref:web/e2e-testing/playwright/advanced-topics.adoc[Advanced Topics].

|1.56
|`browserContext.on('backgroundpage')` is deprecated and never emitted.
|Use service-worker based extension testing.

|1.57
|`page.accessibility` removed after three years of deprecation.
|Use an axe integration; see xref:web/e2e-testing/accessibility-checks-in-e2e-tests.adoc[Accessibility Checks in E2E Tests].

|1.58
|The `+_react+` and `+_vue+` selectors, the `+:light+` selector suffix and the `devtools` launch option are removed. WebKit
updates stop for macOS 13.
|Use role, test id or CSS locators; pass `--auto-open-devtools-for-tabs` through `args`.

|1.59
|WebKit updates stop for macOS 14. `@playwright/experimental-ct-svelte` removed. The JUnit reporter separates errors from
failures.
|Check CI parsers that read `<failure>` elements.

|1.60
|Long-deprecated APIs removed: `Locator.ariaRef()`, the `handle` option of `exposeBinding`, the `logger` option of
`connect` and `connectOverCDP`, and the `videosPath` and `videoSize` context options.
|Use `ariaSnapshot()`, tracing and `recordVideo`.

|1.62
|Debian 11 is no longer supported.
|Move CI to a supported image.

|1.63
|Ubuntu 20.04 is no longer supported. The experimental React and Vue component-testing packages stop being updated.
|Use a current `mcr.microsoft.com/playwright` image.

|1.64
|`screen` from device descriptors is now forwarded, so `window.screen` and media queries see the emulated size. JSX in test
files follows your `tsconfig.json`. `--update-snapshots=missing` makes a run that only creates snapshots pass. Elements
inside hidden iframes count as hidden.
|Set `screen: undefined` to opt out of the first; review tests that rely on the others.

== Cypress 15 to 16

Cypress 15.0.0 (August 2025) and 16.0.0 (1 September 2026) are the two majors in this window. Version 16.2.0 was released
on 13 October 2026.

=== Breaking changes in 16.0

The official migration guide lists each change with an "action needed" column; this table follows it.

[cols="3,5,3,4",options="header"]
|===
|Change |What happens |Documented here |Upgrade action

|Native browser network
|Chrome, Chromium and Edge send test traffic over the native browser network, so the application negotiates HTTP/1.1,
HTTP/2 or HTTP/3 exactly as in production. Firefox, WebKit and Electron keep the legacy path. `req.httpVersion` is no
longer reported and compression headers and `304` responses behave differently inside `cy.intercept()`.
|xref:web/e2e-testing/cypress/network-stubs-spies-and-clocks.adoc[Network, Stubs, Spies & Clocks]
|Usually none. Update tests that assert on those fields; `forceHttp1: true` is a temporary escape hatch that is deprecated
at introduction.

|Node.js
|Node.js 20 and 25 are dropped; 22.x, 24.x or 26.x and later are required. The bundled Node.js moved from 22.19.0 to
24.15.0.
|xref:web/e2e-testing/cypress/getting-started.adoc[Getting Started]
|Upgrade the runtime on developer machines and CI before the package.

|`Cypress.env()` removed
|Use `cy.env()` for sensitive values and `Cypress.expose()` for public values. The `env` key is invalid in per-test
overrides (use `expose`), and the `allowCypressEnv` option is gone.
|xref:web/e2e-testing/cypress/sessions-authentication-and-cross-origin.adoc[Sessions, Authentication & Cross-Origin],
xref:web/e2e-testing/running-in-ci-cd.adoc[Running in CI/CD]
|Migrate every call (see the example below). `+CYPRESS_*+` variables fill `env` only, so pass public values with
`--expose`.

|`cy.exec()` and `cy.end()` removed
|Use `cy.task()` (and `taskTimeout`) instead of `cy.exec()`; delete `.end()` calls.
|xref:web/e2e-testing/cypress/getting-started.adoc[Getting Started]
|Register the command as a task in `setupNodeEvents`.

|`keystrokeDelay`
|The default delay in `cy.type()` changed from 10 to 0 milliseconds.
|xref:web/e2e-testing/cypress/core-concepts.adoc[Core Concepts]
|Only if a test relied on the delay: set `keystrokeDelay: 10` or pass `{ delay: 10 }`.

|Visibility
|`experimentalFastVisibility` is replaced by `visibilityStrategy`, which defaults to `+'modern'+`; `+'legacy'+` is a deprecated
escape hatch.
|xref:web/e2e-testing/cypress/core-concepts.adoc[Core Concepts]
|Rewrite assertions that relied on ancestor overflow clipping, transform-based hiding or coverage by fixed elements.

|Browser memory
|`experimentalMemoryManagement` became `manageBrowserMemory`, on by default.
|xref:web/e2e-testing/cypress/debugging-studio-plugins-and-reporters.adoc[Debugging, Studio, Plugins & Reporters]
|If you set the old option to `false`, replace it with `manageBrowserMemory: false`; deleting it silently turns the
feature on.

|Cookie and storage reads
|`cy.getCookie()`, `cy.getCookies()`, `cy.getAllCookies()`, `cy.getAllLocalStorage()` and `cy.getAllSessionStorage()` are
retry-able queries governed by `defaultCommandTimeout` and can no longer be overwritten with `Commands.overwrite()`.
|xref:web/e2e-testing/cypress/queries-assertions-and-custom-commands.adoc[Queries, Assertions & Custom Commands]
|Move assertions from `.then()` to `.should()`; use `overwriteQuery()`.

|Config at run time
|`viewportWidth`, `viewportHeight` and `blockHosts` cannot be changed with `Cypress.config()` during a test.
|xref:web/e2e-testing/cypress/core-concepts.adoc[Core Concepts]
|Use `cy.viewport()` or test configuration.

|Other removals
|`experimentalSourceRewriting`, built-in CoffeeScript support, and the environment variables printed by `cypress info`.
|xref:web/e2e-testing/cypress/debugging-studio-plugins-and-reporters.adoc[Debugging, Studio, Plugins & Reporters]
|Remove the options; convert `.coffee` files.

|Component testing minimums
|Angular 21 (18, 19 and 20 dropped), Vite 8 (5, 6 and 7 dropped), Next.js 15.0.4 (14 dropped). `@cypress/angular-zoneless`
merged into `@cypress/angular`.
|xref:web/e2e-testing/cypress/component-testing.adoc[Component Testing]
|Upgrade the framework tooling first.

|Electron deprecated
|The bundled Electron browser is deprecated as a test browser and will be removed in a future major version; targeting it
prints a warning.
|xref:web/e2e-testing/cross-browser-testing.adoc[Cross-Browser Testing]
|Set `defaultBrowser` or pass `--browser chrome` now.
|===

The example below is the migration pattern from the official guide, shown with the replacement for a secret and for a
public value. It is documentation, not a run.

[source,typescript]
----
// Before (Cypress 15): synchronous, everything is serialised into the browser
// const apiKey = Cypress.env('apiKey')

// After (Cypress 16): sensitive values stay in the Node process until requested
it('reads the API key', () => {
  cy.env(['apiKey']).then(({ apiKey }) => {
    expect(Boolean(apiKey)).to.be.true

=== Breaking changes in 15.0

If you are still on Cypress 14, upgrade to 15.x first. The 15.0.0 release removed Node.js 18 and 23, Linux distributions
with glibc older than 2.31, and Chrome DevTools Protocol automation of Firefox (Firefox is automated with WebDriver BiDi
only, which sets a minimum Firefox version). It also removed the three-argument form of `cy.stub()`, webpack 4 support,
Vite 4 and Angular 17 for component testing, renamed `Cypress.SelectorPlayground` to `Cypress.ElementSelector`, renamed
the `code` property of `cy.exec()` to `exitCode`, dropped the direct-download installation and made `@cypress/vite-dev-server`
ESM-only. Cypress 14 had earlier dropped Node.js 16 and macOS older than 11 and removed `open-ct` and `run-ct`.

== Selenium 4.x

Selenium has no new major version in this window: the 4.x line continues, and the policy is to deprecate for two releases
before removing. The table runs from the Selenium Manager releases that changed how drivers and browsers are obtained up
to 4.51.0 (9 October 2026).

[cols="1,5,3,4",options="header"]
|===
|Version |Change |Documented here |Upgrade action

|4.6 and 4.11
|Selenium Manager (a Rust command-line tool) ships in every binding from 4.6 and downloads the matching driver. From 4.11 it
also uses the Chrome for Testing endpoints to manage chromedriver and the Chrome browser itself, and the current
documentation describes it as automated driver and browser management.
|xref:web/e2e-testing/selenium/drivers-browsers-and-options.adoc[Drivers, Browsers & Options], xref:web/e2e-testing/selenium/getting-started.adoc[Getting Started]
|Delete manual driver management and driver-manager libraries; in locked-down CI, pre-populate the cache or point to your
own binaries.

|4.29
|Chrome DevTools Protocol support for Firefox removed after two releases of deprecation; use WebDriver BiDi.
|xref:web/e2e-testing/selenium/webdriver-bidi.adoc[WebDriver BiDi]
|Replace Firefox CDP code with the BiDi APIs.

|4.37
|Python 3.9 no longer supported; Python 3.10 or later is needed. Selenium 4.51 adds Python 3.15.
|xref:web/e2e-testing/selenium/getting-started.adoc[Getting Started]
|Upgrade the interpreter in CI images and virtual environments.

|4.44 to 4.46
|.NET assemblies strongly signed (around 4.44); Redis-backed `Distributor`, `SessionMap` and `SessionQueue` for the Grid
(4.44 and 4.45); `ElectronDriver` support (4.45); all BiDi Java classes marked beta (4.46); BiDi creation moves to
`RemoteWebDriver`.
|xref:web/e2e-testing/selenium/selenium-grid.adoc[Selenium Grid], xref:web/e2e-testing/selenium/webdriver-bidi.adoc[WebDriver BiDi]
|Pin the version when you use BiDi classes in Java, because beta APIs may change.

|4.47 to 4.49
|A BiDi transport layer for generated modules, subscription parameters for events, removal of FTP proxy support and of a
deprecated Grid file-download endpoint, and a prebuilt Selenium Manager for Linux arm64 in every binding.
|xref:web/e2e-testing/selenium/webdriver-bidi.adoc[WebDriver BiDi]
|Stop using FTP proxy settings.

|4.50
|Relative locators can be anchored to elements and shadow roots (Java and .NET); deprecated `HttpClient` interface methods
removed; deprecated Firefox profile extension and certificate methods removed from every binding.
|xref:web/e2e-testing/selenium/locating-and-interacting.adoc[Locating & Interacting], xref:web/e2e-testing/selenium/drivers-browsers-and-options.adoc[Drivers, Browsers & Options]
|Replace profile-based extension and certificate installation with the supported options or BiDi.

|4.51
|Java: Guava is no longer a dependency of the client bindings, so `ExpectedCondition` stops implementing Guava's `Function`;
`RemoteWebDriver.getClientFactory()` added; a BiDi code generator. JavaScript: the browser atoms are a standalone
`@selenium/atoms` package and the WebSQL and AppCache atoms are gone.
|xref:web/e2e-testing/selenium/waits-and-expected-conditions.adoc[Waits & Expected Conditions], xref:web/e2e-testing/selenium/webdriver-bidi.adoc[WebDriver BiDi]
|Search for `com.google.common.base.Function` in test code that touches `ExpectedCondition` and switch to the JDK interface.

|4.53 (planned)
|The removal of the deprecated `HttpCommandExecutor` fields was postponed from 4.51 to 4.53 to give users more time.
|xref:web/e2e-testing/selenium/drivers-browsers-and-options.adoc[Drivers, Browsers & Options]
|Use `getClientFactory()` and the `ClientConfig` API instead of the fields.
|===

Only code that explicitly typed a variable, field or parameter as Guava's `Function` is affected by the 4.51 change; passing
the result of an `ExpectedConditions` factory straight to `WebDriverWait.until()` or implementing `ExpectedCondition` with
a lambda compiles unchanged.

[source,java]
----
// Before 4.51: compiled because ExpectedCondition also extended Guava's Function
// com.google.common.base.Function<WebDriver, WebElement> condition = ExpectedConditions.elementToBeClickable(By.id("submit"));

// 4.51 and later: use the JDK interface (the apply method has the same signature)
java.util.function.Function<WebDriver, WebElement> condition =
    ExpectedConditions.elementToBeClickable(By.id("submit"));
----

Source: https://www.selenium.dev/blog/2026/expectedcondition-drops-guava/[Selenium blog: ExpectedCondition Drops Guava's Function Interface]

The Java minimum is the part of the Selenium requirements that is easiest to get wrong. Selenium announced in June 2023 that
Java 11 is the minimum for the Java bindings and the Grid, because the default HTTP client moved to the JDK's built-in
client. The 4.50 and 4.51 changelogs announce no higher minimum, and this section's Maven examples compile with
`--release 11` and ran on JDK 17, but the documentation's own requirements wording was not re-read for every binding on the
check date, so confirm it on the downloads page before moving a Java 11 runtime. The other bindings state their floors in their
package metadata: Python 3.10, Ruby 3.3, Node.js 22 and, for .NET, the `net462`, `netstandard2.0` and `net8.0` targets.

Selenium also published a documentation page on driving the browser with AI agents (announced in a blog post of 29 September
2026); it is covered in xref:web/e2e-testing/ai-agents/ai-features-in-cypress-and-selenium.adoc[AI Features in Cypress & Selenium].
For the Selenium IDE, which has had no release for about two years, and for the Selenium 3 to 4 migration, see
xref:web/e2e-testing/selenium/selenium-ide-and-legacy.adoc[Selenium IDE & Legacy].

== Protractor end of life

Protractor, the Angular team's former end-to-end test runner built on Selenium, is deprecated: the notice on its npm
package says it reached end of life by summer 2023, and its last published version, 7.0.0, dates from May 2020. The Angular
CLI no longer generates Protractor tests; `ng e2e` asks which package to add and offers Playwright, Cypress, Nightwatch,
WebdriverIO and Puppeteer schematics. With no maintained release, existing Protractor suites should be migrated rather than patched.

* To keep the WebDriver model, move to Selenium with explicit waits; see
xref:web/e2e-testing/selenium/waits-and-expected-conditions.adoc[Waits & Expected Conditions].
* To move to a tool with built-in auto-waiting, see xref:web/e2e-testing/choosing-a-tool.adoc[Choosing a Tool], which also
links Cypress's migration guide for Protractor users.
* Translate page objects first, because they are the largest reusable part of a Protractor suite; see
xref:web/e2e-testing/test-design-and-page-objects.adoc[Test Design & Page Objects].
