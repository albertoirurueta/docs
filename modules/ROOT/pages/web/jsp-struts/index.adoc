== What JSP, EL, JSTL and Struts are

*Jakarta Pages* (JSP, JavaServer Pages) turns a text document with embedded dynamic elements into a servlet: the container translates the page once,
compiles it, and runs the generated class for every request. *Jakarta Expression Language* (EL) is the small language inside
`+${...}+` and `+#{...}+` that reads beans, request parameters and scoped attributes. The *Jakarta Standard Tag Library* (JSTL, officially
Jakarta Tags) is the tag set that replaces scriptlets: conditionals, loops, URLs, formatting, internationalization and string functions.
All three run on *Jakarta Servlet*, the request and response API of the container.

*Apache Struts* is an action-based MVC framework on top of them. A single servlet filter maps each request to an action class,
runs a stack of interceptors around it (parameter binding, validation, file upload, security), and picks a result, usually a JSP, FreeMarker or
Velocity view. Struts 7 is the current line; Struts 1 ("Struts Classic") is a different framework and is covered only to read legacy code and to leave it.

This section is for developers who:

* maintain existing JSP and Struts applications and need an accurate, current reference for them
* modernise those applications, from `+javax.*+` to `+jakarta.*+`, from Struts 2.x to 7, or towards Spring MVC with Thymeleaf
* want to understand the roots of the Java web stack: servlets, the translation of a page, the Model 1 and Model 2 patterns

=== Version baseline and support status

* *Jakarta Pages 4.0, Expression Language 6.0, Servlet 6.1 and Tags 3.0* are specifications of Jakarta EE 11 and of its Web Profile. The Jakarta EE
  Tutorial states that Pages "has been archived in favor of Facelets", so Pages and Tags receive maintenance rather than features; the plans for Jakarta EE 12 list Pages 4.1,
  Tags 3.1, Expression Language 6.1 and Servlet 6.2 (in progress, not released). This section teaches them fully on the current versions.
* *Apache Tomcat 11.0.26* is the reference container. Jetty 12.1.14 and GlassFish 8.0.5 are shown as alternatives. There is no Tomcat 12 yet.
* *Apache Struts 7.4.0* is the current line, built for Java 17 and Servlet 6 and later; *6.12.0* is still maintained. Struts 2.5 (end of life on 2023-10-30),
  2.3 (2019-09-12) and 1.x (2013-04-05) are end of life.
* *Spring and Java:* Java 21 for the examples (17 is the minimum for Pages 4.0, Expression Language 6.0 and Struts 7), Spring Framework 7.0.9 and Spring Boot 4.1.1.
  Spring Boot documents that JSPs are not supported in an executable jar and that they should be avoided if possible, so the Spring pages use a WAR.

== The Bookshelf scenario

Every example builds one small original application, _Bookshelf_, in the same domain as the
xref:web/thymeleaf/index.adoc[Thymeleaf], xref:web/django/index.adoc[Django] and xref:web/php-laravel/index.adoc[PHP and Laravel] sections, so that the
stacks can be compared page by page. Here it exists twice, as two WARs on Tomcat 11 that share the domain, a service and a repository:

* `bookshelf-jsp` (Part I): a front controller servlet, request attributes, JSP views with EL and JSTL, custom tags, forms, validation, sessions and security
* `bookshelf-struts` (Part II): the same catalogue as Struts actions with `struts.xml`, interceptors, OGNL, validation, i18n, upload, tags, themes and plugins

.The two Bookshelf applications: a servlet or the Struts filter in front of a shared service and repository, and a JSP view that renders the response
image::jsp-struts-bookshelf-architecture.svg["Diagram of the two Bookshelf applications on Tomcat 11. The browser sends requests either to a front servlet in bookshelf-jsp or to the Struts filter in bookshelf-struts. Both call the same service and repository, which read and write the data store, and then forward to a JSP view under WEB-INF that renders the HTML response back to the browser.",width=100%]

The project layout of `bookshelf-jsp` is assembled in xref:web/jsp-struts/getting-started.adoc[Getting Started], and `bookshelf-struts` in
xref:web/jsp-struts/struts/getting-started.adoc[Struts Getting Started].

== Reading path

Read the pages in the order of the outline the first time, then use them as a reference. Before starting, be comfortable with
the xref:programming-languages/java/index.adoc[Java Reference] for the language and its build tooling.

. *Foundations*: the history and where JSP and Struts stand today, a first Maven WAR on Tomcat 11, and the servlet API underneath.
. *Part I, JSP, EL and JSTL*: the page lifecycle, syntax and directives, implicit objects, the Expression Language, the tag library, custom tags,
  and then forms, Spring MVC, Jasper configuration, security and testing (start at xref:web/jsp-struts/jsp/index.adoc[JSP, EL & JSTL]).

  and views, plugins, and then security, operations and Struts 1 (start at xref:web/jsp-struts/struts/index.adoc[Apache Struts]).
. *Migration and quick reference*: xref:web/jsp-struts/whats-changed-and-migration.adoc[What's Changed & Migration] and the
