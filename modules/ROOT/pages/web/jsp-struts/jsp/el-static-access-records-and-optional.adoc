This page is written against Jakarta Expression Language 6.0 (`jakarta.el:jakarta.el-api` 6.0.1), Jakarta Pages 4.0, Jakarta
Standard Tag Library 3.0 and Jakarta Servlet 6.1, on Java 21 and Tomcat 11.0.26, the container whose Jasper and EL
implementation ran every example. Everything was verified on 2026-10-08: the facts against the EL 6.0 and Pages 4.0
specifications and the EL Javadoc, and every example by building it into a Maven WAR and requesting it with `curl`; the
outputs and error messages shown are the ones that run produced. Besides properties of beans, maps and lists, EL can
reach four more kinds of thing: the static members of a class (`+${Integer.MAX_VALUE}+`, `+${Math.max(3, 7)}+`), the
constants of an enum, the `length` of an array, and the components of a Java `record`, and it can see through a
`java.util.Optional` if the page or application asks for it. Three of these are ordinary parts of every page, one is
off unless you switch it on, and each has an access rule that surprises people the first time it silently prints
nothing. The running scenario is the _Bookshelf_, a small catalogue of books; the same `Book` is a record with an enum
status and an optional ISBN.

[#bookshelf-app]
== The Bookshelf Used on This Page

The examples below are views of one WAR, deployed as `g4elstatic.war` under the context path `/g4elstatic`. A servlet
(`ViewServlet`, mapped to `+/view/*+`) puts a `Book`, a second `Book` without an ISBN, a list of both, an array of their
titles and an `+Optional<Book>+` into the request and forwards to `+/WEB-INF/views/<name>.jsp+` for a fixed list of view
names. The model is a record `Book` with an `Author` record and a `Status` enum, plus a final class `Shelf` that holds
constants and static helpers. The scenario classes are shown once here; every other listing on the page is a JSP or a
descriptor.

.Status.java and Author.java
[source,java]
----
public enum Status {
    AVAILABLE("On the shelf"), LOANED("Out on loan"), LOST("Lost");

    private final String label;

    Status(String label) {
        this.label = label;
    }

    public String getLabel() {
        return label;
    }
}

public record Author(String name, String country) {
}
----

.Book.java: a record with an enum component, an Optional component and two extra methods
[source,java]
----
public record Book(long id, String title, Author author, int year, Status status, Optional<String> isbn) {

    public boolean isRecent() {
        return year >= 2020;
    }

    public String shortTitle() {
        return title.length() > 12 ? title.substring(0, 12) + "..." : title;
    }
}
----

.Shelf.java: the static members the pages read (one is package-private and one is private on purpose)
[source,java]
----
public final class Shelf {

    public static final int MAX_LOANS = 3;
    public static final String NAME = "Main shelf";
    public static int counter = 0;
    static final int HIDDEN = 7;
    private static final int SECRET = 9;

    private Shelf() {
    }

    public static String describe(Book book) {
        return book.title() + " (" + book.year() + ")";
    }

    public static boolean canLoan(int current) {
        return current < MAX_LOANS;
    }
}
----

.ViewServlet.java (imports omitted)
[source,java]
----
@WebServlet("/view/*")
public class ViewServlet extends HttpServlet {

    private static final Set<String> VIEWS = Set.of("static", "enum", "record", "optional-basic", "m-ispresent", "m-orelse-empty", "m-orelse-present", "m-unwrap", "err-optional-get", "optional-nav", "optional-el", "array", "imports",
            "imports2", "imports4", "imports3", "err-array", "err-record-write", "err-record-hidden", "inc-main", "err-param", "err-assign", "err-private", "err-enum", "err-record", "err-nopub", "ctor");

    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        String name = req.getPathInfo() == null ? "" : req.getPathInfo().substring(1);
        if (!VIEWS.contains(name)) {
            resp.sendError(HttpServletResponse.SC_NOT_FOUND);
            return;
        }
        Author author = new Author("Ursula K. Le Guin", "US");
        Book book = new Book(1L, "The Dispossessed", author, 1974, Status.AVAILABLE, Optional.of("978-0-06-051275-0"));
        Book noIsbn = new Book(2L, "Zine Issue 7", new Author("Anon", "ES"), 2023, Status.LOANED, Optional.empty());
        req.setAttribute("book", book);
        req.setAttribute("noIsbn", noIsbn);
        req.setAttribute("books", List.of(book, noIsbn));
        req.setAttribute("titles", new String[] {book.title(), noIsbn.title()});
        req.setAttribute("hidden", new Hidden("secret-free")); req.setAttribute("status", Status.LOANED);
        req.setAttribute("rawOptional", Optional.of(book));
        req.getRequestDispatcher("/WEB-INF/views/" + name + ".jsp").forward(req, resp);
    }
}
----

The two `Book` instances, the list, the array and the `+Optional<Book>+` are ordinary request attributes, so every JSP
reads them as `+${book}+`, `+${noIsbn}+`, `+${books}+`, `+${titles}+` and `+${rawOptional}+`. A second copy of the WAR,
`g4elstaticopt.war`, differs from the first in one context parameter only; that is the Optional switch, explained in the
Optional section.

[#chain]
== Where These Features Sit in the Resolver Chain

Every EL expression in a page is evaluated through one `jakarta.el.CompositeELResolver` that the container builds. Pages 4.0
section 2.10 lists its components in order (the xref:web/jsp-struts/jsp/implicit-objects-and-scopes.adoc#el-implicit-objects[Implicit Objects and Scopes] page shows the same chain from the scope side), and the three features of this page are three of the entries. The
expression `+${Shelf.MAX_LOANS}+` is resolved by the import resolver (to a class), then by `StaticFieldELResolver` (to
the field); `+${book.title}+` is resolved by `RecordELResolver` before the generic `BeanELResolver` ever sees it; and
`+${book.isbn.value}+` can only work if somebody added `OptionalELResolver` to the part of the chain that is reserved for
application resolvers.

[#static]
== Static Fields and Methods

The syntax is `classname.member`, where `classname` is the simple class name without its package: `+${Boolean.TRUE}+`,
`+${Integer.MAX_VALUE}+`, `+${Math.max(3, 7)}+`. The specification attaches four security restrictions: only public
static fields and methods can be referenced, they must be in an accessible (exported) module, static fields cannot be
modified, and, except for `java.lang`, a class has to be imported before its static members can be named.

.Access rules for static members (EL 1.24.1 and observed on Tomcat 11.0.26)
[cols="2,3,3",options="header"]
|===
|Rule |What happens when it is broken |Observed message or result

|The member must be `public` and `static` |`PropertyNotFoundException` (package-private and private members are the same case) |`No public static field named [SECRET] was found on exported class [org.example.bookshelf.Shelf]`
|The class must be in an exported package (EL 1.24.1, "accessible module") |the member is not found |not reproduced separately; the message of the previous row says "on exported class"
|A static field is read-only |`PropertyNotWritableException` |`Writing to static fields (in this case field [counter] on class [org.example.bookshelf.Shelf]) is not permitted`
|The class must be imported (except `java.lang` and the Pages defaults) |the class name resolves to nothing, so the whole expression is `null` and prints as an empty string |no exception, no output
|An imported class must be public, concrete and not an interface |`ELException` when the import is explicit |`The class [jakarta.servlet.http.HttpServletResponse] must be public, in an exported package, non-abstract and not an interface`
|===

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#access-restrictions-and-imports[Jakarta Expression Language 6.0 -- 1.24.1 Access Restrictions and Imports]

Source: https://jakarta.ee/specifications/expression-language/6.0/apidocs/jakarta.el/jakarta/el/StaticFieldELResolver.html[Jakarta Expression Language 6.0 Javadoc -- StaticFieldELResolver]

=== Reading Static Fields and Calling Static Methods

The view below uses the `java.lang` classes `Boolean`, `Integer` and `Math` with no import, and the Bookshelf class
`Shelf` after a `page` directive import. Static methods take arguments in the normal way, and they can take beans from
the page: `+${Shelf.describe(book)}+` passes the `Book` request attribute to a static method.

Shelf.NAME = ${Shelf.NAME}
Shelf.describe(book) = ${Shelf.describe(book)}
Shelf.canLoan(2) = ${Shelf.canLoan(2)}
Shelf.canLoan(3) = ${Shelf.canLoan(3)}

[#default-imports]
=== Default Imports and the page Directive

The EL on its own imports `+java.lang.*+` only. The specification lets a technology that uses EL add more, and Pages does:
the `import` attribute of the `page` directive (see the xref:web/jsp-struts/jsp/directives.adoc[Directives] page) describes "the types that are available to the scripting and EL
environments", and the container implicitly imports `+java.lang.*+`, `+jakarta.servlet.*+`, `+jakarta.servlet.jsp.*+` and
`+jakarta.servlet.http.*+`. That the EL environment has the same defaults as the scripting environment was clarified in
Pages 3.1. A page can add more with `import`, as it does for `Shelf` above, and can import a whole package or a single
class.

.Where an EL class name can come from
[cols="2,4",options="header"]
|===
|Source |Effect

|`+java.lang.*+` |always imported: `Integer`, `Math`, `Boolean`, `String`, `System`, `Runtime`, `Thread` and the rest
|`+jakarta.servlet.*+`, `+jakarta.servlet.jsp.*+`, `+jakarta.servlet.http.*+` |implicitly imported by the container (Pages 4.0 1.10.1); concrete classes only, see the pitfall below
|`+<%@ page import="a.b.C, d.e.*" %>+` |adds a class or a package for the scripting and the EL environment of that page
|`+getELContext().getImportHandler().importClass("a.b.C")+` |adds a class from a scriptlet or a tag handler, at run time
|`+getELContext().getImportHandler().importPackage("a.b")+` |adds a package at run time
|`+getELContext().getImportHandler().importStatic("a.b.C.NAME")+` |lets a static field or method be named without its class: `+${NAME}+`, `+${max(3, 7)}+`
|`include-prelude` in a `jsp-property-group` |the specification's way to have extra imports "transparently" in many pages (see the xref:web/jsp-struts/jsp/configuration-and-property-groups.adoc[Configuration and Property Groups] page)
|===

The import handler is the object `ELContext.getImportHandler()` returns, and `PageContext.getELContext()` gives a page its
`ELContext`. The next view shows the three styles in one page: a package import (`+java.time.*+`), a class import
(`java.math.RoundingMode`, `org.example.bookshelf.Status`) and two static imports made from a scriptlet.

.imports.jsp
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
<%@ page import="java.math.RoundingMode, java.time.*" %>
<%@ page import="org.example.bookshelf.Status" %>
<%
    pageContext.getELContext().getImportHandler().importStatic("java.lang.Math.max");
    pageContext.getELContext().getImportHandler().importStatic("org.example.bookshelf.Shelf.MAX_LOANS");
%>
RoundingMode.FLOOR = ${RoundingMode.FLOOR}
LocalDate.of(2026, 10, 8).year = ${LocalDate.of(2026, 10, 8).year}
Duration.ofMinutes(90).toHours() = ${Duration.ofMinutes(90).toHours()}
max(3, 7) = ${max(3, 7)}
MAX_LOANS = ${MAX_LOANS}
Status.AVAILABLE = ${Status.AVAILABLE}
----

Two things in that output are worth stating. A static import (`importStatic`) of a static _method_ makes the name usable without its class, which is why
`+${max(3, 7)}+` works with no class. And the page-level `import` is per page: the import handler belongs to the page's `ELContext`, so a
class imported in one page is not known to a page that it includes dynamically. The include directive is different,
because it merges the source of the included file into the including page before translation, so the imports apply
to it. The next view includes the same fragment both ways.

.inc-main.jsp and the fragment inc-part.jsp
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
<%@ page import="org.example.bookshelf.Shelf" %>
main page : [${Shelf.MAX_LOANS}]
<jsp:include page="/WEB-INF/views/inc-part.jsp"/>
<%@ include file="/WEB-INF/views/inc-part.jsp" %>
----

[source,jsp]
----
part (included) : [${Shelf.MAX_LOANS}]
----

.Output of `+curl http://localhost:18080/g4elstatic/view/inc-main+`
[source,text]
----
main page : [3]
part (included) : []
part (included) : [3]
----

The `jsp:include` copy runs as a separate page, so `Shelf` is unknown there and prints nothing; the `include` directive copy
sees the import. The xref:web/jsp-struts/jsp/includes-forwards-and-page-composition.adoc[Includes, Forwards and Page Composition] page
treats the two mechanisms in full.

[#static-reach]
=== What java.lang Gives a Page, and Why That Matters

The default imports are a convenience for page authors and a hazard for everything else. `java.lang` contains `Runtime`,
`System`, `Thread` and `ProcessBuilder`, and the Pages packages contain `Cookie`, so an expression that an attacker can
choose is not limited to reading the Bookshelf. The next page prints only harmless values, which is the point: the
reach is there, and it is the reason this section never builds an expression from request input.

.imports2.jsp: what the default imports reach, and what they do not
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
Cookie('a','b').name = [${Cookie('a', 'b').name}]
PageContext.REQUEST_SCOPE = [${PageContext.REQUEST_SCOPE}]
HttpServletResponse.SC_NOT_FOUND = [${HttpServletResponse.SC_NOT_FOUND}]
HttpServletResponse.SC_NOT_FOUND via full name = [${jakarta.servlet.http.HttpServletResponse.SC_NOT_FOUND}]
HttpServletRequest.BASIC_AUTH = [${HttpServletRequest.BASIC_AUTH}]
Runtime.getRuntime().availableProcessors() > 0 = ${Runtime.getRuntime().availableProcessors() gt 0}
System.getProperty('java.specification.version') = ${System.getProperty('java.specification.version')}
----

.Output of `+curl http://localhost:18080/g4elstatic/view/imports2+`
[source,text]
----
Cookie('a','b').name = [a]
PageContext.REQUEST_SCOPE = []
HttpServletResponse.SC_NOT_FOUND = []
HttpServletResponse.SC_NOT_FOUND via full name = []
HttpServletRequest.BASIC_AUTH = []
Runtime.getRuntime().availableProcessors() > 0 = true
System.getProperty('java.specification.version') = 21
----

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#the-page-directive[Jakarta Pages 4.0 -- 1.10.1 The page Directive (import)]

Three rules follow from the output.

* **Concrete classes only.** `Cookie` is a class, so its constructor and `+.name+` work. `HttpServletResponse` and
  `HttpServletRequest` are interfaces and `PageContext` is an abstract class, so `+${HttpServletResponse.SC_NOT_FOUND}+`
  and `+${PageContext.REQUEST_SCOPE}+` print an empty string even though the packages are on the default import list.
  Naming such a class in a `page` import, or in `importStatic`, does not help: it raises the `ELException` quoted in
  the table above. To use `HttpServletResponse.SC_NOT_FOUND` in a page, put the number in a constant of your own class or
  write the literal.
* **Never the package-qualified name.** The qualified name is not parsed as a class: `jakarta` is looked up as an
  attribute, found nowhere, and the whole expression is `null`.
* **Empty is not an error.** An unimported class and an interface constant both evaluate to `null`, because
  `NotFoundELResolver` always resolves, and a `null` prints as nothing. The `errorOnELNotFound` setting changes that for
  a bare identifier in development; see the xref:web/jsp-struts/jsp/el-configuration-and-elprocessor.adoc#unknown[Expression Language Configuration] page of this section.

[#static-failures]
=== The Failures

Each of the three pages below fails or prints nothing on purpose; every message is quoted from the response.

.err-assign.jsp, err-private.jsp and err-nopub.jsp: assign to a static field, read a private one, and forget an import
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" %>
<%@ page import="org.example.bookshelf.Shelf" %>
before = ${Shelf.counter}
assign = ${Shelf.counter = 5}

<%@ page contentType="text/plain;charset=UTF-8" %>
<%@ page import="org.example.bookshelf.Shelf" %>
secret = ${Shelf.SECRET}

<%@ page contentType="text/plain;charset=UTF-8" %>
Shelf (no import) = [${Shelf.MAX_LOANS}]
Status (no import) = [${Status.AVAILABLE}]
book.status == Status.AVAILABLE (no import) = [${book.status == Status.AVAILABLE}]
----

.Result of each request
[cols="2,6",options="header"]
|===
|Request |Result

|`/g4elstatic/view/err-assign` |HTTP 500: `+jakarta.el.PropertyNotWritableException: Writing to static fields (in this case field [counter] on class [org.example.bookshelf.Shelf]) is not permitted+`
|`/g4elstatic/view/err-private` |HTTP 500: `+jakarta.el.PropertyNotFoundException: No public static field named [SECRET] was found on exported class [org.example.bookshelf.Shelf]+`
|`/g4elstatic/view/err-nopub` |HTTP 200 with three empty values (`Shelf`, `Status` and the comparison `book.status == Status.AVAILABLE`, which is `false`)
|===

The third row is the dangerous one: the comparison `+${book.status == Status.AVAILABLE}+` is quietly `false` for every
book when the `Status` import is missing, because `Status` is `null`. A page that shows a "Borrow" button only when the
status equals the constant would hide it for everybody, with no log line.

[#enums]
== Enums

An enum constant is a public static field, so `+${RoundingMode.FLOOR}+` and `+${Status.AVAILABLE}+` use the static syntax
above and need the same import. The specification adds a second route for values that are already enum instances: an
enum is compared with a string, and the string is coerced to the enum type with `Enum.valueOf`, so `+${mySuit == 'Spade'}+`
is true when `mySuit` is the `Spade` constant. Everything else about an enum is ordinary Java: its getters are
properties (`+${status.label}+` calls `getLabel()`), its methods are callable (`name()`, `ordinal()`), and its static
methods `values()` and `valueOf(String)` are static methods of the imported enum class.

.enum.jsp
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
<%@ page import="org.example.bookshelf.Status" %>
book.status = ${book.status}

[#records]
== Records

A Java `record` has no getters. Its accessors are methods named after its components (`title()`, not `getTitle()`),
so a resolver that only looks for `getX` and `isX`, which is what `BeanELResolver` does, cannot read it. EL 6.0 adds
`RecordELResolver` for exactly this case. It handles any base object that is a `java.lang.Record`, accepts any non-null
property, coerces it to a string with `toString()` and uses that string to find the accessor method of the component
with the same name. It is always read-only. Because EL 6.0 enables it by default and Pages 4.0 lists it right before
`BeanELResolver`, a record works as a bean on Tomcat 11 with no configuration: `+${book.title}+` calls `title()`.

.record.jsp
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
book.title = ${book.title}
book['year'] = ${book['year']}
book.author.name = ${book.author.name}
book.author.country == 'US' = ${book.author.country == 'US'}
book.title() (method call) = ${book.title()}
book.shortTitle() = ${book.shortTitle()}
books.stream().map(b -> b.title).toList() = ${books.stream().map(b -> b.title).toList()}
book.equals(book) = ${book.equals(book)}
book.toString() = ${book.toString()}
----

.Output of `+curl http://localhost:18080/g4elstatic/view/record+`
[source,text]
----

book['year'] = 1974
book.author.name = Ursula K. Le Guin
book.author.country == 'US' = true
book.title() (method call) = The Dispossessed
book.shortTitle() = The Disposse...
books.stream().map(b -> b.title).toList() = [The Dispossessed, Zine Issue 7]
book.equals(book) = true
book.toString() = Book[id=1, title=The Dispossessed, author=Author[name=Ursula K. Le Guin, country=US], year=1974, status=AVAILABLE, isbn=Optional[978-0-06-051275-0]]
----

Source: https://jakarta.ee/specifications/expression-language/6.0/apidocs/jakarta.el/jakarta/el/RecordELResolver.html[Jakarta Expression Language 6.0 Javadoc -- RecordELResolver]

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#changes-between-6-0-and-5-0[Jakarta Expression Language 6.0 -- A.1 Changes between 6.0 and 5.0 (#201)]

Nested records chain as usual (`+${book.author.name}+`), the bracket form works (`+${book['year']}+`), a lambda over a list of
records reads components with the same syntax, and the accessor can also be called as a method (`+${book.title()}+`),
which is the normal EL method-call rule and not something the record resolver adds. A record is also an ordinary Java
class, so `toString()`, `equals` and any method you add (`shortTitle()`) are callable; the `toString()` output shows the
`Optional` component in its Java form, which matters in the next section.

== java.util.Optional

There are two different `Optional` classes in EL and the page must not mix them up.

.The two Optionals

|Class |Where it comes from |What EL does with it

[#optional-enable]
=== Switching the Resolver On

`OptionalELResolver` is a normal `ELResolver`, so it is registered the way any application resolver is: through the
`JspApplicationContext` of the web application, which Pages 4.0 section 2.10 places right after the implicit objects in
the chain. The natural place is a `ServletContextListener`; the one below reads a context parameter so the same code ran
as the plain WAR (`false`) and the Optional-enabled WAR (`true`).

.OptionalSupport.java and the context parameter in web.xml
[source,java]
----
@WebListener
public class OptionalSupport implements ServletContextListener {

    @Override
    public void contextInitialized(ServletContextEvent event) {
        ServletContext context = event.getServletContext();
        if (Boolean.parseBoolean(context.getInitParameter("optionalEL"))) {
            JspFactory.getDefaultFactory().getJspApplicationContext(context).addELResolver(new OptionalELResolver());
        }
    }
}
----

[source,xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee https://jakarta.ee/xml/ns/jakartaee/web-app_6_1.xsd"
         version="6.1">
    <context-param>
        <param-name>optionalEL</param-name>
        <param-value>false</param-value>

----

The registration is application-wide and happens once, at start-up. After it the chain looks through every
`java.util.Optional` in every page of the application: this is a global change of semantics that cannot be limited to one page, so every page that calls `+.isPresent()+` or `+.orElse(...)+` breaks (below). The Javadoc defines the
behaviour precisely: for an `Optional` base, an empty Optional resolves every property to `null`; a populated one
resolves the property on its content, by calling the whole resolver chain with the content as the base; with a `null`
property the content itself is the value; method calls are forwarded to the content, and an empty Optional answers
`null` to every method call; and coercion to a type is done on the content, or on `null` when empty.

unreachable.

[#optional-advice]
=== What to Do With Optional in a Page

The pattern that works with and without the resolver, and that does not tie the pages to a global switch, is to unwrap in
the servlet or in the view model. Put the nullable value in the request (`book.isbn().orElse(null)`), or add a component
of a plain type to the view record, and let the page use the ordinary EL null handling, `empty`, `c:if` and `c:out
default`. Reach for the resolver only in an application that has chosen to model its optional properties as `Optional`
and to read them with property syntax everywhere, so that no page calls an Optional method. In that case register it
once, in a listener, and never mix the two styles, as the table above shows why.

[#optional-stream]
=== The Other Optional: Results of EL Streams

A terminal operation on an EL stream returns EL's own `Optional`, with four methods: `get()` (an `ELException` if
empty), `ifPresent`, `orElse` and `orElseGet`. It is independent of the resolver: the same pages behave the same on both
WARs.

.optional-el.jsp
[source,jsp]
----
<%@ page contentType="text/plain;charset=UTF-8" trimDirectiveWhitespaces="true" %>
books.stream().findFirst().get().title = ${books.stream().findFirst().get().title}
books.stream().map(b -> b.title).findFirst().orElse('none') = ${books.stream().map(b -> b.title).findFirst().orElse('none')}
books.stream().filter(b -> b.year > 2100).findFirst().orElse('none') = ${books.stream().filter(b -> b.year > 2100).findFirst().orElse('none')}
books.stream().filter(b -> b.year > 2100).findFirst().orElseGet(() -> 'none') = ${books.stream().filter(b -> b.year > 2100).findFirst().orElseGet(() -> 'none')}
books.stream().map(b -> b.title).findFirst().ifPresent(t -> t) = [${books.stream().map(b -> b.title).findFirst().ifPresent(t -> t)}]
----

.Output of `+curl http://localhost:18080/g4elstatic/view/optional-el+` (identical on the Optional-enabled WAR)
[source,text]
----
books.stream().findFirst().get().title = The Dispossessed
books.stream().map(b -> b.title).findFirst().orElse('none') = The Dispossessed
books.stream().filter(b -> b.year > 2100).findFirst().orElse('none') = none
books.stream().filter(b -> b.year > 2100).findFirst().orElseGet(() -> 'none') = none
books.stream().map(b -> b.title).findFirst().ifPresent(t -> t) = []
----

Calling `get()` on an empty one fails (`err-optional-get.jsp`, the expression `+${books.stream().filter(b -> b.year > 2100).findFirst().get()}+`): HTTP 500 with `+jakarta.el.ELException: It is illegal to call get() on an empty optional+`. There is no `isPresent()` on the EL class, so the test for emptiness is `orElse` with a default, or `orElseGet`. The lambdas and the stream
operations themselves are on the Lambdas, Collections and Streams page; the Java language side is on the
xref:programming-languages/java/optional.adoc[Optional], xref:programming-languages/java/lambdas-and-method-references.adoc[Lambdas
and Method References] and xref:programming-languages/java/streams-and-collectors.adoc[Streams and Collectors] pages.

.Static access, record and Optional pitfalls (rows marked "observed" were reproduced on Tomcat 11.0.26)

|Symptom or error |Cause |Fix

|`PropertyNotFoundException: No public static field named [X] was found on exported class` (observed) |the field is package-private, private or missing, or the class is in a non-exported package |make it `public static`, or expose a static method
|`+PropertyNotWritableException: Writing to static fields ... is not permitted+` (observed) |an assignment (`=`) to a static field |change it in Java, not in EL
|`+${book.status == Status.AVAILABLE}+` is always `false` (observed) |`Status` is not imported, so the right side is `null` |import the enum; turn on `errorOnELNotFound` in development
|`+ELException: Cannot convert [available] of type [class java.lang.String] to [class ...Status]+` (observed) |a string that is not a constant name compared with an enum |compare with the constant, or `+status.name() eq 'AVAILABLE'+`; validate input first
|`+${books.length}+` fails with `NumberFormatException` for the input string "length" (observed) |`length` is only special on Java arrays |`+${books.size()}+` or `+${fn:length(books)}+`
|`+PropertyNotFoundException: Property [recent] not found on type [...Book]+` (observed) |the property is not a record component (`isRecent()` is a method) |`+${book.isRecent()}+`, or make it a component
|`+ELException: Error reading [name] on type [...Hidden]+` with an `IllegalAccessException` (observed) |the record type is not public |declare the record `public`
|`+JspTagException: Invalid property in <set>+` (observed) |`c:set target=` on an immutable record |build a new record in the servlet
|`PropertyNotFoundException: Property [title] not found on type [java.util.Optional]` (observed) |navigating through an `Optional` with no `OptionalELResolver` registered |unwrap in the servlet, or register the resolver
|`+MethodNotFoundException: Method not found: class java.lang.String.orElse(...)+` (observed) |the resolver is registered and the page still calls the Optional API |drop the call, or remove the resolver
|`+${empty book.isbn}+` is false for an empty Optional (observed, both modes) |`empty` tests null, empty string, array, collection and map, never an `Optional` |`+${empty book.isbn.toString()}+` with the resolver, `+${not book.isbn.isPresent()}+` without it, or unwrap earlier
|`ELException: It is illegal to call get() on an empty optional` (observed) |`get()` on an empty EL stream `Optional` |`orElse` or `orElseGet`
|Request input becomes code |a servlet or tag builds an EL string from a parameter and evaluates it with `ExpressionFactory` or `ELProcessor` |never; input is data, and the default imports reach `Runtime`, `System` and more
|===

.Changes that touch static access, records and Optional
[cols="2,4",options="header"]
|===
|Change |Detail

|EL 6.0 (Jakarta EE 11) |Java 17 is the minimum; deprecated code is removed and the dependency on the `java.desktop` module becomes optional; `RecordELResolver` is new and on by default (#201); `OptionalELResolver` is new and off by default (#176); arrays get a `length` property (#175); module visibility is respected when calling class methods (#188); every reference to the Java `SecurityManager` is removed (#192)

|EL 6.1, Pages 4.1 (milestones) |milestone releases of both specifications are published (`jakarta.el-api` 6.1.0-M2 on Maven Central); nothing in them was verified for static access, records or Optional, so this page makes no claim about them

[#books-outdated]
== Where the Books Are Outdated

The books were written for JSP 1.2 and JSTL 1.0, before the Expression Language existed as a language (JSP 2.0) and long
before it could name classes (EL 3.0). What they teach about how a page reaches a constant, a
helper or an optional value is therefore built from the pieces they had, and the pieces have since been replaced.

.Material from the books and its current equivalent
[cols="3,4",options="header"]
|===
|The books' era |Today (EL 6.0, Pages 4.0, Servlet 6.1)

|Constants and helper methods reached through `+<%= Shelf.MAX_LOANS %>+` scriptlets, a `+<jsp:useBean>+` of a class that holds the value, or a custom tag |`+${Shelf.MAX_LOANS}+` and `+${Shelf.describe(book)}+` with a `page` import, in a page whose scripting is switched off
|EL functions declared in a TLD `+<function>+` element to call a static method (`+${fn:...}+`) |still valid for tag libraries; for your own helpers a static call needs no TLD, and the specification's own text notes that functions without a prefix can no longer be validated at translation time because of imports
|Enum values compared as strings, or an `+<%= %>+` scriptlet in the `test` of `c:if` |`+${book.status == Status.AVAILABLE}+`, or the string form, which EL coerces
|JSTL 1.0 `rt` libraries (`c_rt`) taking a Java expression in the attribute |plain EL in the attribute; JSTL 3.0 has one library per area (`jakarta.tags.core` and four more) and no `rt` variants
|A bean is a class with getters and setters; no records (Java 14 and later) |records work with `+${book.title}+` since EL 6.0 on any Pages 4.0 container, and a pre-6 container needs getters
|The size of an array through a scriptlet, `+<%= titles.length %>+` |`+${titles.length}+` (EL 6.0) or `+${fn:length(titles)}+`
|No `Optional` (it came in Java 8) |`java.util.Optional` is an object; the resolver that looks through it is opt-in and the better habit is to unwrap in the servlet
|`javax.el`, `javax.servlet.jsp` packages in a custom resolver or a tag |`jakarta.el`, `jakarta.servlet.jsp` since Jakarta EE 9
|Struts 1 and Struts 2 pages that read static values through the Struts tag libraries or OGNL (`@class@field`) |OGNL static access is restricted in current Struts releases; the xref:web/jsp-struts/struts/security-hardening.adoc[Struts Security Hardening] and xref:web/jsp-struts/struts/value-stack-action-context-and-ognl.adoc[ValueStack, ActionContext and OGNL] pages cover it with the other OGNL security settings. In a JSP, EL with a `page` import does the job under the rules of this page
|===
