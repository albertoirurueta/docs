[#bookshelf-app]
== The Bookshelf Used on This Page

The examples need data in scope and nothing else, so a `ServletContextListener` puts a handful of values into application
scope when the web application starts. The `Book` record is the one used in the rest of the section. Records are read
as beans by the EL since version 6.0, so `+${dune.title}+` works without getters.

.The Bookshelf values used by the examples (shortened; the full listener also defines a few more constants of the same kind)
[source,java]
----
public record Book(long id, String title, String author, int year) { }

public enum Status { AVAILABLE, LOANED }

public record Loan(Book book, Status status, LocalDate due) { }

@WebListener
public class ShelfListener implements ServletContextListener {
    @Override
    public void contextInitialized(ServletContextEvent event) {

        var neuro = new Book(2, "Neuromancer", "William Gibson", 1984);
        var dispossessed = new Book(3, "The Dispossessed", "Ursula K. Le Guin", 1974);
        ctx.setAttribute("books", List.of(dune, neuro, dispossessed));
        ctx.setAttribute("noBooks", List.of());
        ctx.setAttribute("catalog", Map.of("dune", dune));
        ctx.setAttribute("dune", dune);
        ctx.setAttribute("price", new BigDecimal("12.50"));      // BigDecimal
        ctx.setAttribute("copies", Integer.valueOf(3));          // Integer
        ctx.setAttribute("count", Long.valueOf(7));              // Long
        ctx.setAttribute("rating", Double.valueOf(4.5));         // Double
        ctx.setAttribute("ratio", Float.valueOf(0.1f));          // Float
        ctx.setAttribute("big", new BigInteger("9223372036854775807"));
        ctx.setAttribute("status", Status.AVAILABLE);            // enum

        ctx.setAttribute("today", LocalDate.of(2026, 10, 8));
        ctx.setAttribute("letter", Character.valueOf('a'));
        ctx.setAttribute("blank", "");
        ctx.setAttribute("spaces", "   ");
        ctx.setAttribute("trueText", "true");
        ctx.setAttribute("yes", Boolean.TRUE);
        ctx.setAttribute("no", Boolean.FALSE);
        ctx.setAttribute("noTags", new String[0]);

}

[#operator-map]
== The Operators at a Glance

EL has five groups of operators and two structural ones. The word forms exist for two reasons: they avoid the entity
references that `<`, `>` and `&` need in XML syntax (see <<xml-syntax>>), and they are the spelling XPath and ECMAScript
users know. A symbol and its word form behave identically.

.Every operator of Expression Language 6.0, highest precedence first (operators on one row have equal precedence)
[cols="1,4,5,2",options="header"]
|===
|Level |Operators (word form in parentheses) |Meaning |Specification section

|1 |`+[]+` `+.+` |Property, element, key or method access (xref:web/jsp-struts/jsp/expression-language-basics.adoc[basics page]) |1.6
|2 |`+()+` |Grouping, and function or lambda call |1.15, 1.18, 1.20
|3 |`+-+` (unary), `+!+` (`not`), `empty` |Numeric negation, logical negation, null-or-empty test |1.7.4, 1.10.2, 1.11
|4 |`+*+`, `+/+` (`div`), `+%+` (`mod`) |Multiplication, division, remainder |1.7.1 to 1.7.3
|5 |`pass:c[+]`, `+-+` (binary) |Addition and subtraction |1.7.1
|6 |`pass:c[+=]` |String concatenation |1.8
|7 |`+<+` (`lt`), `+>+` (`gt`), `+<=+` (`le`), `+>=+` (`ge`) |Ordering comparisons |1.9.1
|8 |`+==+` (`eq`), `+!=+` (`ne`) |Equality |1.9.2
|9 |`+&&+` (`and`) |Logical and, short-circuit |1.10.1
|10 |`+\|\|+` (`or`) |Logical or, short-circuit |1.10.1
|11 |`+? :+` |Conditional, right associative |1.12
|12 |`+->+` |Lambda expression, right associative (lambda page) |1.20
|13 |`+=+` |Assignment, right associative |1.13
|14 |`+;+` |Sequence: evaluate the left side, return the right |1.14
|===

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#operator-precedence[Jakarta Expression Language 6.0 -- 1.16 Operator Precedence]

Three words from this table, `empty`, `div` and `mod`, cannot be used as identifiers; the full list is in
<<reserved-words>>. The operators `pass:c[+=]`, `=`, `;` and `+->+` were added in EL 3.0 (Java EE 7, 2013). A page written
for JSP 2.0 to 2.2 knows only the arithmetic, relational, logical, `empty` and conditional operators, which is all
that the books in the bibliography describe.

[#arithmetic]
== Arithmetic Operators

The operators are `pass:c[+]`, `-`, `+*+`, `/` (or `div`), `%` (or `mod`) and the unary minus. They work on integers
(`BigInteger` and `Long`) and on floating-point numbers (`BigDecimal` and `Double`); every other numeric type, and a
`String`, is converted first. The specification picks the working type for `pass:c[+]`, `-` and `+*+` from the operands:

[mermaid]
....
flowchart TD
  start["A and B evaluated"] --> nn{"Both null?"}
  nn -- yes --> zero["Result is the Long 0"]
  nn -- no --> bd{"Either operand a BigDecimal?"}
  bd -- yes --> rbd["Both become BigDecimal"]
  bd -- no --> fl{"Either a Float, a Double, or a String containing . e or E?"}
  fl -- yes --> bi1{"Either a BigInteger?"}
  bi1 -- yes --> rbd
  bi1 -- no --> rdb["Both become Double"]
  fl -- no --> bi2{"Either a BigInteger?"}
  bi2 -- yes --> rbi["Both become BigInteger"]
  bi2 -- no --> rlg["Both become Long"]
....

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#binary-operators-a-b[Jakarta Expression Language 6.0 -- 1.7.1 Binary operators for addition, subtraction and multiplication]

The other three operators have their own rules.

.The working type chosen by each arithmetic operator
[cols="2,5,3",options="header"]
|===
|Operator |Rule |Typical result

|`pass:c[+]`, `-`, `+*+` |The diagram above: `BigDecimal`, then `Double`, then `BigInteger`, then `Long` |`3 + 4` is the `Long` 7
|`/`, `div` |`BigDecimal` division (rounding half up, keeping the scale of the left operand) when either side is `BigDecimal` or `BigInteger`, otherwise `Double` |`7 / 2` is 3.5, `8 div 2` is 4.0
|`%`, `mod` |`Double` if either side is `BigDecimal`, `Float`, `Double` or a String with `.`, `e` or `E`; `BigInteger` remainder if either is `BigInteger`; otherwise `Long` |`7 mod 3` is 1, `-7 mod 3` is -1
|`-` (unary) |`BigDecimal` and `BigInteger` are negated; a String becomes a `Double` if it contains `.`, `e` or `E` and a `Long` otherwise; `Byte`, `Short`, `Integer`, `Long`, `Float` and `Double` keep their type; anything else, such as a `Boolean`, is an error |`-copies` is the `Integer` -3
|===

When both operands are null the result is the `Long` 0, and a single null operand counts as 0 (the coercion of null to a
number is 0, see <<coercion>>). An operation that throws, such as a `Long` remainder by zero, becomes an error.

Reading the output against the rules:

* **Integer division does not exist.** `/` is `Double` division unless a `BigDecimal` or `BigInteger` is involved, so
  `+${7 / 2}+` is 3.5 and even `+${8 div 2}+` prints `4.0`. There is no operator for the whole-number quotient; round the
  result with `fmt:formatNumber` (maximum fraction digits 0, which rounds half to even) or move the arithmetic into the
  controller.
* **The money rule.** `price` is a `BigDecimal` with two decimals, so every operation stays exact and keeps scale 2 for
  `pass:c[+]`, `-` and `+*+` (`37.50`, `13.50`); the division is rounded half up to the scale of the left operand (`4.17`).
  A `Double` never enters a `BigDecimal` calculation unless it is a literal such as `0.1`: see the pitfalls.
* **A `Float` is widened to a `Double`**, which exposes the binary representation: `+0.1f * 3+` prints
  `0.30000000447034836`. Prefer `Double` or `BigDecimal` in model classes that a page multiplies.
* **`Long` arithmetic wraps silently.** `9223372036854775807 + 1` is `-9223372036854775808`. Use a `BigInteger` (the `big`
  value) when overflow is possible; `pass:c[${big + 1}]` is exact.
* **Division by zero is not an error for `Double`**: `1 / 0` is `Infinity` and `0 / 0` is `NaN`. A `Long` or
  `BigInteger` remainder by zero is an error (see the next example).
* **Null counts as zero**, and a `String` is parsed (`pass:c['12' + 1]` is 13, `pass:c['2.5' + 1]` is 3.5), including the empty String, which
  is 0 (`pass:c[${'' + 1}]` is 1).

Two lessons are in this output. First, the third line is the commonest mistake of everybody who comes from Java or
JavaScript: **`pass:c[+]` never concatenates**. The operands of `pass:c['Dune' + ' (1965)']` are parsed as numbers, and the
parse fails. The concatenation operator is `pass:c[+=]` (next section). Second, a number-conversion failure surfaces as a
raw `NumberFormatException` from `Long.valueOf` and not as an `ELException`, while a `Boolean` operand is rejected
with an `ELException`; handlers that map exceptions to pages must be ready for both. Whatever the type, the page never
renders partially in this case: the container answers 500 (or the configured error page, see the xref:web/jsp-struts/jsp/error-handling.adoc[error handling page]).

[#concatenation]
== String Concatenation: `pass:c[+=]`

`pass:c[${A += B}]` converts both operands to `String` and returns the concatenation. It exists because `pass:c[+]` is arithmetic
only. A null operand becomes the empty String and an enum becomes its `name()`, so there is no `NullPointerException`
and no "null" text, as there would be in Java.

.ops/concat.jsp: building a label
[source,jsp]
----
'Bookshelf: ' += copies = ${'Bookshelf: ' += copies}
dune.title += ' (' += dune.year += ')' = ${dune.title += ' (' += dune.year += ')'}
nothing += 'x' = [${nothing += 'x'}]
nothing += nothing = [${nothing += nothing}]
status += '!' = ${status += '!'}
1 + 2 += 3 + 4 = ${1 + 2 += 3 + 4}
----

[source,text]
----
'Bookshelf: ' += copies = Bookshelf: 3
dune.title += ' (' += dune.year += ')' = Dune (1965)
nothing += 'x' = [x]
nothing += nothing = []
status += '!' = AVAILABLE!
1 + 2 += 3 + 4 = 37
----

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#string-concatenation-operator-a-b[Jakarta Expression Language 6.0 -- 1.8 String Concatenation Operator]

The last line shows the precedence: `pass:c[+=]` binds more loosely than binary `pass:c[+]`, so both additions run first
(`3` and `7`) and the two numbers are then joined as "37". For readable pages keep the operands short and prefer
`c:out` and `fmt` tags for anything that is displayed; `pass:c[+=]` is best for building an attribute value such as a CSS
class or a URL fragment.

[#relational]
== Relational and Equality Operators

The ordering operators `<`, `>`, `+<=+`, `>=` (`lt`, `gt`, `le`, `ge`) and the equality operators `==`, `!=` (`eq`, `ne`)
return a `Boolean`. Their rules are tried top to bottom, and the first that matches decides the type of the comparison.
The rule list is the key to the surprises, so it is reproduced as a table.

.How an ordering comparison A op B is evaluated, in order
[cols="1,5",options="header"]
|===
|Step |Rule

|1 |If A and B are the same object, `+<=+`, `le`, `>=` and `ge` return true
|2 |If either is null, the result is false
|3 |If either is a `BigDecimal`, both become `BigDecimal` and `compareTo` decides
|4 |If either is a `Float` or `Double`, both become `Double`
|5 |If either is a `BigInteger`, both become `BigInteger` and `compareTo` decides
|6 |If either is a `Byte`, `Short`, `Character`, `Integer` or `Long`, both become `Long`
|7 |If either is a `String`, both become `String` and are compared lexically
|8 |If A is `Comparable`, `A.compareTo(B)` decides; else if B is `Comparable`, `B.compareTo(A)` decides (the sign is reversed)
|9 |Otherwise it is an error
|===

.How an equality comparison A == B (and A != B) is evaluated, in order
[cols="1,5",options="header"]
|===
|Step |Rule

|1 |If A and B are the same object, the operator is applied to that fact (`==` true, `!=` false)
|2 |If either is null, `==` is false and `!=` is true
|3 |If either is a `BigDecimal`, both become `BigDecimal` and `A.equals(B)` decides, so **the scale matters**
|4 |If either is a `Float` or `Double`, both become `Double`
|5 |If either is a `BigInteger`, both become `BigInteger` and `equals` decides
|6 |If either is a `Byte`, `Short`, `Character`, `Integer` or `Long`, both become `Long`
|7 |If either is a `Boolean`, both become `Boolean`
|8 |If either is an enum, both become that enum type (a String is looked up with `Enum.valueOf`)
|9 |If either is a `String`, both become `String` and are compared as text
|10 |Otherwise `A.equals(B)` decides; an exception in `equals` is an error
|===

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#a-ltgtlege-b[Jakarta Expression Language 6.0 -- 1.9.1 Ordering operators] and https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#a-eqne-b[1.9.2 Equality operators]

Points the output makes concrete:

* **Numbers compare as numbers whatever their type**: `1 eq 1.0`, `copies == 3.0` (an `Integer` against a `Double`) and
  `count == 7` (a `Long` against an `Integer` literal) are true. A `String` that is compared with a number is
  converted to a number (`+'1' eq 1+`, `+${'10' lt 9}+` is false because 10 is not less than 9).
* **Two Strings compare lexically**, not numerically: `+'10' lt '9'+` is true. The comparison is also case sensitive and
  based on `String.compareTo`, so `+'Zebra' lt 'apple'+` is true (upper case sorts first). To sort or filter book titles in
  a locale-aware way, do it in Java.
* **Null makes every ordering comparison false, with one exception**: `nothing le nothing` is true because the two operands
  are the same (null) and the operator allows equality (step 1 comes before the null test). `nothing == 0` and
  `+nothing == ''+` are false (null is never equal to a non-null value), and `blank == null` is false: the empty String is
  not null.
* **A `String` is compared with an enum by constant name** (`+status == 'AVAILABLE'+`), a `Boolean` with the text
  `+'true'+` or `+'false'+`, and any `Comparable`, such as `LocalDate`, with another of its kind (`loan.due lt today`).
* **Equality of unrelated objects falls back to `equals`**: `books[0] == dune` is true because the list holds the same
  record. A record has value-based `equals`, so two `Book` records with the same components are equal as well.

The cases where the rules produce an error rather than a false are worth seeing once.

Each failure follows from the rules. `+'1.0' eq 1+` meets an integer (step 6), so both become `Long`, and "1.0" is not a
`Long`. A `Book` record is not `Comparable` (step 8 finds neither side comparable), so `lt` between two books is an
error; compare `books[0].year lt books[1].year` instead. A `Character` is an integer for step 6, which turns the
String `+'a'+` into a `Long` and fails, even though comparing a `Character` with a one-letter text is what the author
meant; compare `letter eq 97`, or convert the text in Java. A String that does not name an enum constant fails
(an empty String does not: `+${status == ''}+` and `+${status == nothing}+` print `false` and `false`). The last line
shows that **chained comparisons do not exist**: `1 lt 2 lt 3` is `(1 lt 2) lt 3`, which compares a `Boolean` with 3.
Write `1 lt 2 and 2 lt 3`.

[#logical]

result is known: in `A and B and C`, if `B` is false then `C` is never evaluated. The unary `!` applies to the operand
that follows.

[#conditional]
== The Conditional Operator

`+${A ? B : C}+` coerces A to `Boolean` and evaluates and returns B when it is true and C when it is false; the branch
that is not selected is never evaluated. It is right associative, so a chain of tests needs no parentheses.

[#assignment]
== Assignment and the Semicolon

EL 3.0 added two operators that change state, both designed for the stand-alone `ELProcessor` and for lambdas, and
both available in a page.

* `+${A = B}+` evaluates B and writes it to the writable reference A, and the whole expression returns the value
  written. It is right associative: `+${a = b = 5}+` is `a = (b = 5)`. A that cannot be written throws
  `PropertyNotWritableException`.
* `+${A ; B}+` evaluates A, discards the value, then evaluates and returns B. It is the C comma operator, so it
  chains assignments: `pass:c[${x = 5; y = x * 2; x + y}]`.

What a bare name means to `=` is decided by the resolvers. In a page, the Pages
`ScopedAttributeELResolver` sets the attribute in whichever scope already holds that name, searching page, request,
session and application (the xref:web/jsp-struts/jsp/implicit-objects-and-scopes.adoc[scopes page] has the details), and **creates a page-scope attribute only if no scope has the name**.

[#reserved-words]
== Reserved Words and Identifiers

Sixteen words are reserved by section 1.17 and cannot be used as identifiers: `and`, `or`, `not`, `eq`, `ne`, `lt`, `gt`, `le`,
`ge`, `div`, `mod`, `empty`, `true`, `false`, `null` and `instanceof`. Some of them are operators today; others,
`instanceof`, are held back for future use and are already off limits. A name that collides cannot be read with the dot syntax, but the bracket syntax with a String does work:

.ops/res3.jsp, res4.jsp, res8.jsp and err-reserved2.jsp: a reserved word as a name (the `c` taglib directive is left out)

pageScope['div'] = ${pageScope['div']}
pageScope['and'] = ${pageScope['and']}
${pageScope.div}
${catalog.and}
${instanceof}
----

[#coercion]
== Type Coercion

Every expression is evaluated in the context of an expected type: an operator expects numbers, a `Boolean` or a `String`;
a tag attribute expects the type in its TLD; a method call expects the parameter type. The result of the sub-expression
rarely matches, so section 1.25 defines how a value `X` becomes a type `Y`. The first step is to find a custom
converter: an `ELResolver` can implement `convertToType`, and the resolvers in the chain are asked in order. Only when no
resolver converts does the default conversion run.

.The default coercion rules of section 1.25 (null handling first; "error" means an `ELException` or the exception of the conversion)
[cols="2,6",options="header"]
|===
|Target type |Rule

|Any non-primitive, non-String target |A null value stays null
|`String` |null becomes `""`; a `String` stays; an enum becomes `name()`; otherwise `toString()` (an exception is an error)
|Number type N (`Byte` ... `BigDecimal`) |null or `""` becomes 0; a `Character` becomes its numeric value; a `Boolean` is an error; a `Number` is converted quietly to N (a `BigDecimal` to `BigInteger` with `toBigInteger()`, a `Double` to `BigDecimal` with `new BigDecimal(double)`); a `String` is parsed with `N.valueOf` (`new BigDecimal(text)` and `new BigInteger(text)` for those two); anything else is an error
|`Character` or `char` |null or `""` becomes `(char) 0`; a `Character` stays; a `Boolean` is an error; a `Number` is converted to a `Short` and then to the character with that value; a `String` gives its first character; anything else is an error
|`Boolean` or `boolean` |null or `""` becomes false; a `Boolean` stays; a `String` goes through `Boolean.valueOf` (so only "true", in any case, is true); anything else is an error
|Enum type T |null stays null; an assignable value stays; `""` becomes null; a `String` goes through `Enum.valueOf`; anything else is an error
|Array of T |null stays null; an assignable array stays; any other array is copied with each element coerced to T; anything else is an error (one failing element fails the array)
|Functional interface |A lambda is wrapped so that calling the interface method invokes it (lambda page)
|Any other type T |null stays null; an assignable value stays; a `String` is converted through T's `PropertyEditor`; an empty String becomes null when there is no editor or the editor fails; anything else is an error
|===

Source: https://jakarta.ee/specifications/expression-language/6.0/jakarta-expression-language-spec-6.0.html#type-conversion[Jakarta Expression Language 6.0 -- 1.25 Type Conversion]

A primitive target is coerced as its box type and then unboxed; if the box is null, the conversion is an error. In
practice null becomes 0 and `""` becomes 0 or false for primitive targets, which section 1.25.1 spells out.

=== Coercion in Operators

All operators above call these rules, so `pass:c[${'12' + 1}]` is a `String`-to-`Long` coercion and `pass:c[${'abc' + 1}]` is the failing
one. The most useful single rule is the null one: **null is not special in EL arithmetic or boolean tests, it is
0, false or the empty String, whichever the operator needs**, which is why a missing value rarely breaks a page and
a malformed value does. The page `ops/coerce.jsp` (excerpt) shows the rules for numbers and text:

The text conversions are what a page prints: a null prints nothing, an enum prints its constant name, and any other
object prints `toString()`, which for a record is the readable `+Book[id=1, ...]+` form shown. Only a `String` is run
through a parser: `+'1e2'+` is the `Double` 100.0 because it contains `e`, and `pass:c[${letter + 1}]` is 98 because the
`Character` `+'a'+` is the number 97. `0.1 + 0.2` is the `Double` result of floating-point arithmetic, so equality tests on
computed `Double` values are as unreliable in a page as in Java.

=== Coercion in Method Calls and Tag Attributes

EL 2.2 added method invocation (`+${shelf.total(counts)}+`), and the arguments are coerced to the declared parameter types
by the same rules. The Bookshelf's `Shelf` bean is a plain Java class with a few methods that take an `int[]`, an enum, a
primitive `int`, an `Integer`, a `boolean`, a `char` and a `LocalDate`.

The rows line up with the table. The `String[]` `+{"1","2","3"}+` becomes an `int[]` element by element and sums to 6. The String
`+'LOANED'+` becomes the enum constant and the empty String becomes null, so `+describe('')+` reaches the method with a
null. The primitive `int` parameter turns both `+''+` and null into 0, while the boxed `Integer` parameter turns `+''+` into
0 and keeps null. `+'yes'+` is false for a `boolean` and for the `test` attribute of `c:if`, and a one-character `+'1'+` is
false as well, so `+<c:if test="${param.admin}">+` is false for `?admin=1`: the attribute expects "true" or "false" and
converts everything else to false without complaint. A `String` to `char` gives the first character
(`+'abc'+` is 97) and `+''+` is the character 0.

and when no overload accepts the argument the error is a `MethodNotFoundException`, not a number or conversion error**.

[#worked-example]
== Worked Example: a Paginated Shelf

The following page uses most operators for something a catalogue page does: it reads a page number, computes the
slice of books to show, labels each row and offers previous and next links. It uses `empty` and the conditional operator
for the default, arithmetic and `lt` for the slice, `mod` for the row style, a nested conditional for the label, and
`pass:c[+]`/`-` in the link targets.

.shelf.jsp: pagination with operators only
[source,jsp]
----
<%@ page contentType="text/html;charset=UTF-8" trimDirectiveWhitespaces="true" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<c:set var="perPage" value="2"/>
<c:set var="page" value="${empty param.page ? 1 : param.page + 0}"/>
<c:set var="first" value="${(page - 1) * perPage}"/>
<c:set var="shown" value="${books.size() - first lt perPage ? books.size() - first : perPage}"/>
<p>Showing ${first + 1} to ${first + shown} of ${books.size()}</p>
<ul>
<c:forEach var="book" items="${books}" begin="${first}" end="${first + perPage - 1}" varStatus="row">
  <c:set var="age" value="${today.year - book.year}"/>
  <li class="${row.index mod 2 eq 0 ? 'even' : 'odd'}"><c:out value="${book.title}"/> (${book.year}): ${age gt 50 ? 'classic' : age gt 30 ? 'established' : 'recent'}</li>
</c:forEach>
</ul>
<c:if test="${page gt 1}"><a href="?page=${page - 1}">previous</a></c:if>
<c:if test="${first + perPage lt books.size()}"><a href="?page=${page + 1}">next</a></c:if>
----

<ul>

<li class="odd">Neuromancer (1984): established</li>
</ul>

----

----

<ul>

Source: https://jakarta.ee/specifications/tags/3.0/jakarta-tags-spec-3.0.html#c:forEach[Jakarta Tags 3.0 -- c:forEach] and https://jakarta.ee/specifications/tags/3.0/jakarta-tags-spec-3.0.html#c:set[c:set]

Notes on the page. `param.page + 0` is the idiom for "this parameter, as a number": it turns the text "2" into the `Long`
2 so that `page - 1` and `page + 1` do arithmetic and the links print the numbers 1 and 3. An absent or empty
parameter is covered by `empty param.page`, but a parameter that is not a number (`?page=abc`) still ends in
`NumberFormatException: For input string: "abc"` and an HTTP 500: validate numeric input in a servlet or filter, or in
a tag that catches the error (`c:catch`), before the page reads it. The third response is the other trap: `?page=3` is
a valid number past the end of the data, and the page announces "Showing 5 to 3 of 3" with an empty list. The operators
cannot clamp the value without a `Math.min`, so compute the page range in the controller and hand the view the
numbers. The titles are printed through `c:out`; the `+${book.year}+` in text is a number and needs no escaping,
which is not true of `+${param.q}+` or of any text typed by a user.

[#security]
== Security Notes

* **EL does not escape.** The result of an expression in template text is written as is, so `+${param.q}+` is an XSS
  vector. Use `c:out` (which escapes `<`, `>`, `&`, `+'+` and `"` by default) or `fn:escapeXml`; operators do not change
  this, and the conditional `+${empty param.q ? 'all' : param.q}+` is as unsafe as the parameter it returns.
* **A request value is an operand, never code.** `pass:c[${param.page + 1}]` cannot make the container run the user's text as an
  expression. EL injection needs the text to be evaluated, for example by building an expression string from input and
  passing it to `ExpressionFactory.createValueExpression` or `ELProcessor.eval`; never do that. The
  xref:web/jsp-struts/jsp/syntax-comments-and-escaping.adoc[syntax and escaping page] of this section covers the
  template-text case, and the xref:web/jsp-struts/jsp/security.adoc[Security page] covers the rest.
* **`=` and `;` are statements.** Pages that contain them modify scoped attributes (see the typo example). Keep them out
  of templates, and prefer `c:set` for the assignments that do belong in a page.
* **Numeric input fails with 500.** An unvalidated `param.n + 1` is a denial-of-service nuisance and fills the error log;
  map `NumberFormatException` and `ELException` to an error page.

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#errors-warnings-default-values[Jakarta Pages 4.0 -- 2.9 Errors, Warnings, Default Values]

Source: https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html[OWASP -- Cross Site Scripting Prevention Cheat Sheet]

== Pitfalls and Error Names

.Operator and coercion pitfalls (rows marked "observed" were reproduced on Tomcat 11.0.26)
[cols="3,3,3",options="header"]
|===
|Symptom or error |Cause |Fix

|`java.lang.NumberFormatException: For input string: "Dune"` from `pass:c[${'Dune' + ' (1965)'}]` (observed) |`pass:c[+]` is arithmetic; both Strings are parsed as numbers |`pass:c[${'Dune' += ' (1965)'}]`
|`NumberFormatException` and HTTP 500 for `?page=abc` with `pass:c[${param.page + 1}]` (observed) |a String operand is parsed with `Long.valueOf`; there is no fallback |validate in a servlet or filter; `c:catch`; an error page for `NumberFormatException`
|`+${8 div 2}+` prints `4.0` and `+${7 / 2}+` prints `3.5` (observed) |`/` is `Double` division unless a `BigDecimal` or `BigInteger` is involved |no integer division in EL: `fmt:formatNumber` with zero fraction digits, or compute in Java
|`pass:c[${9223372036854775807 + 1}]` is negative (observed) |`Long` arithmetic wraps without error |use a `BigInteger` or `BigDecimal` operand
|`java.lang.ArithmeticException: / by zero` for `+${5 mod 0}+`, but `Infinity` and `NaN` for `Double` division (observed) |integer remainder throws, floating-point does not |test the divisor with `+${d ne 0}+` before dividing
|`+${price == 12.50}+` is false for a price of 12.50 (observed) |`BigDecimal.equals` compares scale and the literal `12.50` is the `Double` 12.5 |`price le x and price ge x`, or compare in Java
|`pass:c[${price + 0.1}]` prints 12.6000000000000000055511151231257827021181583404541015625 (observed) |a `Double` literal is converted to `BigDecimal` from its binary value |quote the literal: `pass:c[${price + '0.1'}]`
|`+${'10' lt '9'}+` is true (observed) |two Strings compare lexically |convert one operand to a number: `pass:c[${'10' + 0 lt '9' + 0}]` or compare in Java
|`ELException: Cannot convert [1.0] of type [class java.lang.String] to [class java.lang.Long]` for `+${'1.0' eq 1}+` (observed) |an integer operand makes the String a `Long`, and "1.0" is not one |`pass:c[${'1.0' + 0 eq 1}]` or use a `Double` operand
|`+ELException: Cannot convert [a] ... to [class java.lang.Long]+` for `+${letter == 'a'}+` (observed) |a `Character` takes the integer path of the equality rules |`+${letter eq 97}+`, or compare Strings
|`+ELException: Cannot compare [Book[...]] to [Book[...]]+` (observed) |neither value is `Comparable` |compare a property: `+${a.year lt b.year}+`
|`+ELException: Cannot convert [true] ... to [class java.lang.Long]+` for `+${1 lt 2 lt 3}+` (observed) |comparisons are not chained |`+${1 lt 2 and 2 lt 3}+`
|`+ELException: Cannot convert [1] ... to [class java.lang.Boolean]+` for `+${1 and true}+` (observed) |a number is not a Boolean |compare explicitly: `+${n ne 0}+`
|`+${'yes' and true}+` is false, silently (observed) |`Boolean.valueOf` is false for any text but "true" |expose real Booleans from the model

|`+${nothing ge 1}+` and `+${nothing lt 1}+` are both false (observed) |any ordering comparison with null is false, except identical operands with `le` and `ge` |test `+${empty x}+` first

|`+${yes ? copies:count()}+`: "The attribute prefix [copies] does not correspond to any imported tag library" (observed) |`copies:count()` parses as a qualified function |spaces around the colon, or parentheses
|`+Failed to parse the expression [${catalog.and}]+` (observed) |a reserved word used as a name after a dot |`+${catalog['and']}+`
|`+${copies = 99}+` changes the application-wide value (observed) |`=` assigns to the scope that already holds the name |type `==`; keep assignments out of templates
|`PropertyNotWritableException` for `+${param.q = 'x'}+` or `+${pageScope = 1}+` (observed) |assignment to a read-only map or implicit object |assign to a scoped attribute name

[#books-outdated]
== Where the Books Are Outdated

The section bibliography lists _JSTL in Action_ (Manning, 2002), which teaches the expression language of JSTL 1.0 on
JSP 1.2, and _Web Development with JavaServer Pages_ (Manning, 2001), which predates the EL. The operator concepts the
first one teaches (the arithmetic, comparison and logical operators with their word forms, `empty` and `null`) are still
exactly right; what has moved is where the EL may be used, the number of operators, and the platform.
