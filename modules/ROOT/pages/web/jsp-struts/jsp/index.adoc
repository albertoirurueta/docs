== What Part I covers

JSP is the oldest part of the stack and the part that every Java web framework of its generation still uses as a view. Part I explains how a page becomes a
servlet, every element of its syntax, the Expression Language that replaced scriptlets, the five tag libraries of JSTL, and how to write your own tags.
It then builds applications from those parts: a Model 2 application with a front controller, forms with validation and sessions, Spring MVC with JSP views, Jasper
configuration for development and production, security and testing. The status of each technology is stated on its page: scripting elements and the SQL and XML libraries of
JSTL are legacy, `jsp:plugin` and `isThreadSafe` are removed, and the EL and JSTL libraries are the current way to write a view.

Everything from Jakarta EE 9 on uses `+jakarta.*+` packages, and Tags 3.0 renames the tag library URIs to `+jakarta.tags.*+` (`+jakarta.tags.core+`, `+jakarta.tags.fmt+`,
`+jakarta.tags.functions+`, `+jakarta.tags.sql+`, `+jakarta.tags.xml+`). Java EE 8 and earlier (Pages 2.3, EL 3.0, JSTL 1.2, Servlet 4.0) used `+javax.*+` and the `+http://java.sun.com/jsp/jstl/...+` URIs.
xref:web/jsp-struts/whats-changed-and-migration.adoc[What's Changed & Migration] lists every change between them.

== Maven coordinates

The container supplies the Servlet, Pages and EL APIs, so a WAR compiles against them with `provided` scope. Tomcat does not ship JSTL, so the API and the
implementation are added with default scope and travel inside the WAR.

.The dependencies of `bookshelf-jsp`
[source,xml]
----
<dependencies>
    <dependency>
        <groupId>jakarta.servlet</groupId>
        <artifactId>jakarta.servlet-api</artifactId>
        <version>6.1.0</version>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>jakarta.servlet.jsp</groupId>
        <artifactId>jakarta.servlet.jsp-api</artifactId>
        <version>4.0.0</version>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>jakarta.el</groupId>
        <artifactId>jakarta.el-api</artifactId>
        <version>6.0.1</version>
        <scope>provided</scope>
    </dependency>
    <dependency>
        <groupId>jakarta.servlet.jsp.jstl</groupId>
        <artifactId>jakarta.servlet.jsp.jstl-api</artifactId>
        <version>3.0.2</version>
    </dependency>
    <dependency>
        <groupId>org.glassfish.web</groupId>
        <artifactId>jakarta.servlet.jsp.jstl</artifactId>
        <version>3.0.1</version>
    </dependency>
</dependencies>
----

Source: https://central.sonatype.com/[Maven Central -- coordinates and versions as of 2026-10-08], https://jakarta.ee/specifications/tags/3.0/[Jakarta Standard Tag Library 3.0]

The specification page of Pages lists its API as `+jakarta.pages:jakarta.pages-api+`, which does not exist on Maven Central; the artifact that does is
`+jakarta.servlet.jsp:jakarta.servlet.jsp-api+`, as above. The JSTL implementation is still 3.0.1 (2023-01-19).

== Reading order

The pages build on each other; read them in this order the first time and use them as a reference afterwards.

. *Core JSP*: lifecycle and translation first, then syntax, directives, implicit objects and scopes, scripting elements (to read legacy code), standard actions, composition,
  errors, encoding, JSP documents and configuration.
. *Expression Language*: the basics, then operators, lambdas and streams, static access, records and `Optional`, and configuration.
. *JSTL*: core, iteration, URLs, i18n, formatting, functions and the legacy SQL and XML libraries.
. *Custom tags*: simple tags, classic tags, the TLD and EL functions, and tag files.
. *Building applications*: Model 2 with servlets, forms and sessions, Spring MVC, Jasper, security, and testing and debugging.
