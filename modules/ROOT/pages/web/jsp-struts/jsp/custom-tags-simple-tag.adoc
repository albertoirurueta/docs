[#what-it-is]
== What a Simple Tag Handler Is

The specification introduces simple tags with an argument about complexity. The protocol of classic handlers is complicated
because scriptlets in a tag body can depend on variables the page created with other scriptlets, so the container has to
call the handler before and after the body, buffer it, loop it and keep the handler's state in step with the page. Once
pages are written with the expression language and the standard tag library, a body no longer needs scriptlets, and the
protocol can be one call. JSP 2.0 therefore added the _Simple Tag Extension_, which can be written in two ways: in Java, by
implementing the `SimpleTag` interface (or, in practice, by extending the convenience class `SimpleTagSupport`), or in JSP,
as a tag file. Both are the same thing to the page author, and a tag file is translated by the container into a `SimpleTag`
handler.

.Simple tags compared with the other ways of adding an action to a page
[cols="2,3,3",options="header"]
|===
|Mechanism |What you write |Status and when to choose it

|Simple tag handler (this page) |a Java class with `doTag()`; attributes as JavaBean setters; the body as a `JspFragment` |current; the default choice for a tag that needs Java (calls a service, builds markup, talks to the `JspContext`)
|Tag file |a `.tag` file in JSP syntax with `tag`, `attribute` and `variable` directives and `jsp:doBody` |current; the best choice for presentation-only tags (a card, a layout, a form row); no Java and no TLD entry required
|Classic tag handler |`doStartTag()`, `doAfterBody()`, `doEndTag()` with return codes, optional `BodyContent` buffering, handler pooling |legacy but still supported and used inside the standard tag library; choose it only to extend a classic class such as `LoopTagSupport` or to maintain old code
|EL function |a `public static` method declared in a TLD and called as `+${bs:initials(name)}+` |current; for a value, not for markup or flow control
|Scriptlet or `jsp:useBean` helper |Java in the page |legacy; disabled with `scripting-invalid` in a modern application
|===

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#simple-tag-handlers[Jakarta Pages 4.0 -- 7.1.5 Simple Tag Handlers]

The simple protocol has four properties that follow from the specification and that the rest of the page uses.

* *One call.* The container calls `doTag()` once and only once for each invocation of the tag. All the logic, including
  evaluation of the body any number of times, happens inside it. The Javadoc says that this gives simple handlers the
  equivalent power of `BodyTag` with a much simpler lifecycle.
* *A new instance per invocation.* The specification states that once a simple tag handler has been instantiated "it is
  executed and then discarded. The same instance must not be cached and reused." The reason given is that caching a
  handler does not necessarily make a page faster and makes portable handlers prone to error. Instance fields are therefore
  safe as per-invocation state; only `static` and other shared state needs care.
* *No servlet API.* `SimpleTag` depends on `JspContext`, the superclass of `PageContext`, and not on `PageContext`, so a
  simple handler is not tied to the servlet API. A handler that needs the request must cast, and should say so.
* *The body is a fragment.* The body of a simple tag is translated into a `JspFragment` and handed over with
  `setJspBody`. A fragment can contain template text and actions, never scriptlets, and the handler runs it zero, one or
  many times.

[#api]
== The API: SimpleTag, SimpleTagSupport, JspFragment and JspContext

`SimpleTag` has five methods. `SimpleTagSupport` implements all of them, keeps the values the container passes in and adds
three protected or static helpers; a handler normally extends it and overrides `doTag()` only. The Javadoc requires every
simple handler to have a public no-argument constructor, because the generated page calls it.

.The methods of SimpleTag and SimpleTagSupport (Jakarta Pages 4.0)
[cols="3,4,3",options="header"]
|===
|Method |What it does |Who calls it

|`void setJspContext(JspContext pc)` |stores the context of this invocation; `SimpleTagSupport` keeps it for `getJspContext()` |the container, first
|`void setParent(JspTag parent)` |stores the enclosing tag, for cooperating tags |the container, only when the tag is nested in another tag
|`void setJspBody(JspFragment body)` |stores the body; not called at all for an empty element, so `getJspBody()` returns `null` |the container, after the attribute setters
|`void doTag() throws JspException, IOException` |all the tag's work; `SimpleTagSupport.doTag()` does nothing |the container, once
|`JspTag getParent()` |the enclosing tag, or `null` |the handler or its children
|`protected JspContext getJspContext()` |the `JspContext` of this invocation (in practice the `PageContext`) |the handler (helper of `SimpleTagSupport`)
|`protected JspFragment getJspBody()` |the body fragment, or `null` |the handler (helper of `SimpleTagSupport`)
|`static JspTag findAncestorWithClass(JspTag from, Class<?> klass)` |the closest enclosing tag of a given class, looking through `TagAdapter` wrappers |the handler of a cooperating tag
|===

Source: https://jakarta.ee/specifications/pages/4.0/apidocs/jakarta.servlet.jsp/jakarta/servlet/jsp/tagext/SimpleTag.html#doTag()[Jakarta Pages 4.0 API -- SimpleTag]

Source: https://jakarta.ee/specifications/pages/4.0/apidocs/jakarta.servlet.jsp/jakarta/servlet/jsp/tagext/SimpleTagSupport.html#findAncestorWithClass(jakarta.servlet.jsp.tagext.JspTag,java.lang.Class)[Jakarta Pages 4.0 API -- SimpleTagSupport.findAncestorWithClass]

`JspFragment` is the type of the body. It has exactly two methods, and everything a tag does with its body goes through them.

.The two methods of JspFragment
[cols="3,5",options="header"]
|===
|Method |Behaviour

|`void invoke(Writer out)` |runs the fragment and sends its output to `out`, or, when `out` is `null`, to the `JspWriter` of the fragment's `JspContext`; throws `JspException`, `IOException` and, if the page is to stop, `SkipPageException`
|`JspContext getJspContext()` |the context the fragment runs in; this is where the handler puts the values the body reads
|===

Source: https://jakarta.ee/specifications/pages/4.0/apidocs/jakarta.servlet.jsp/jakarta/servlet/jsp/tagext/JspFragment.html#invoke(java.io.Writer)[Jakarta Pages 4.0 API -- JspFragment.invoke]

`JspContext` is what the handler uses to talk to the page. Its methods are the same scoped-attribute methods as on
`PageContext` (the xref:web/jsp-struts/jsp/implicit-objects-and-scopes.adoc[implicit objects and scopes page] describes the
four scopes and their lookup order): `setAttribute(name, value, scope)`, `getAttribute(name, scope)`, `findAttribute(name)`,
`removeAttribute(name, scope)`, `getOut()` for the `JspWriter`, `getELContext()`, and `pushBody(Writer)` and `popBody()` for
redirecting output. The scope arguments are the integer constants `PageContext.PAGE_SCOPE`, `REQUEST_SCOPE`,
`SESSION_SCOPE` and `APPLICATION_SCOPE`; there are no scope constants on `JspContext` itself.

[#lifecycle]
== The Lifecycle: What the Container Calls and in What Order

The Javadoc of `SimpleTag` gives a short, non-normative description of the lifecycle, and the Javadoc of `doTag()` adds that
the container resynchronises `AT_BEGIN` and `AT_END` variables after the method returns. The diagram shows one invocation.

.The life of a simple tag handler: one invocation, one instance
[mermaid]
....
sequenceDiagram
    participant P as Translated page (servlet)
    participant H as Tag handler
    participant F as JspFragment (the body)
    P->>H: new, public no-argument constructor
    P->>H: setJspContext(pageContext)
    opt the tag is nested in another tag
        P->>H: setParent(enclosing tag)
    end
    P->>H: one setter per attribute that was written
    opt the element has a body
        P->>H: setJspBody(fragment)
    end
    P->>H: doTag()
    loop zero, one or many times
        H->>F: invoke(null) or invoke(writer)
        F-->>H: body output goes to the page or to the writer
    end
    H-->>P: returns, or throws JspException or SkipPageException
    Note over P,H: the instance is now garbage, it is never reused
....

The order is easy to verify. The `TraceTag` below records every call the container makes on it, and a page nests one trace
tag inside another so that `setParent` happens as well.

.TraceTag: the handler records the calls it receives
[source,java]
----
public class TraceTag extends SimpleTagSupport {
    private static final AtomicInteger INSTANCES = new AtomicInteger();
    private final int id = INSTANCES.incrementAndGet();
    private final List<String> calls = new ArrayList<>();
    private String label = "-";

    public TraceTag() { calls.add("constructor"); }

    public void setLabel(String label) { this.label = label; calls.add("setLabel(" + label + ")"); }

    @Override public void setJspContext(JspContext pc) { super.setJspContext(pc); calls.add("setJspContext"); }
    @Override public void setParent(JspTag parent) { super.setParent(parent); calls.add("setParent"); }
    @Override public void setJspBody(JspFragment body) { super.setJspBody(body); calls.add("setJspBody"); }

    @Override
    public void doTag() throws JspException, IOException {
        calls.add("doTag");
        getJspContext().getOut().write("[" + label + "] instance #" + id + ": " + String.join(" > ", calls) + "\n");
        if (getJspBody() != null) {
            getJspBody().invoke(null);
        }
    }
}
----

.The first and the second request to trace.jsp (observed on Tomcat 11.0.26)
[source,text]
----
[outer] instance #1: constructor > setJspContext > setLabel(outer) > setJspBody > doTag
[inner] instance #2: constructor > setJspContext > setParent > setLabel(inner) > doTag

[outer] instance #3: constructor > setJspContext > setLabel(outer) > setJspBody > doTag
[inner] instance #4: constructor > setJspContext > setParent > setLabel(inner) > doTag
----

Four things are visible in it. The order is constructor, `setJspContext`, then `setParent` (only for the inner tag),
then the attribute setters, then `setJspBody` (only for the outer tag, whose element has a body, and not for the empty inner
one), then `doTag`. A new instance is created for every invocation, even for the same tag in the same page on the next
request: the instance numbers keep increasing from 1 to 4. The outer handler's `doTag()` runs _before_ the inner one's, because
the inner tag lives in the body and the body only runs when `invoke` is called. And the container calls nothing after `doTag()`
that the handler can see: there is no `release()` and no `doEndTag()`.

[#tld]
== Declaring the Tag: the TLD Entries a Simple Tag Needs

A tag exists for the container only through a tag library descriptor. The one for the Bookshelf is a single file,
`WEB-INF/bookshelf.tld`, which is found without any further configuration: the container scans `WEB-INF` (and the
`META-INF` of every JAR in `WEB-INF/lib`) for `.tld` files and maps the `uri` element of each to the descriptor, so a page
only needs a `taglib` directive with that URI. The URI is an identifier, not a link; it does not have to resolve to anything.
The element order inside `tag` follows the schema `web-jsptaglibrary_4_0.xsd`: `name`, `tag-class`, `body-content`,
`variable`, `attribute`, `dynamic-attributes`.

[#rating]
== Attributes: Building bs:rating

The first tag prints a star rating. It has a required integer attribute `value`, an optional `max` (default 5), and the
pair `var` and `scope` that the standard tag library also uses: with `var` the tag stores the result in a scoped variable
instead of printing it. Every attribute is a JavaBean property of the handler, so the container calls
`setValue(int)`, `setMax(int)`, `setVar(String)` and `setScope(String)`. The TLD says which attributes accept an expression
(`rtexprvalue` `true`) and of which type; the container converts the value to the setter's type with the same rules as for
every other action (a string literal is converted at translation time, an EL result at request time).

.RatingTag.java
[source,java]
----
public class RatingTag extends SimpleTagSupport {
    private int value;
    private int max = 5;
    private String var;
    private String scope = "page";

    public void setValue(int value) { this.value = value; }
    public void setMax(int max) { this.max = max; }
    public void setVar(String var) { this.var = var; }
    public void setScope(String scope) { this.scope = scope; }

    @Override
    public void doTag() throws JspException, IOException {
        if (max < 1 || max > 10) {
            throw new JspTagException("bs:rating: max must be between 1 and 10 but was " + max);
        }
        if (value < 0 || value > max) {
            throw new JspTagException("bs:rating: value " + value + " is outside 0.." + max);
        }
        String stars = "★".repeat(value) + "☆".repeat(max - value);
        JspContext ctx = getJspContext();
        if (var != null) {
            ctx.setAttribute(var, stars, scopeConstant(scope));
            return;
        }
        ctx.getOut().write("<span class=\"rating\" title=\"" + value + " of " + max + "\">" + stars + "</span>");
    }

    static int scopeConstant(String scope) throws JspTagException {
        return switch (scope) {
            case "page" -> PageContext.PAGE_SCOPE;
            case "request" -> PageContext.REQUEST_SCOPE;
            case "session" -> PageContext.SESSION_SCOPE;
            case "application" -> PageContext.APPLICATION_SCOPE;
            default -> throw new JspTagException("Invalid scope: " + scope);
        };
    }
}
----

Source: https://jakarta.ee/specifications/pages/4.0/apidocs/jakarta.servlet.jsp/jakarta/servlet/jsp/tagext/SimpleTagSupport.html#getJspContext()[Jakarta Pages 4.0 API -- SimpleTagSupport.getJspContext]

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#request-time-attribute-values[Jakarta Pages 4.0 -- 1.14.1 Request Time Attribute Values]

The handler validates its attributes in `doTag()` and signals a mistake with a `JspTagException` (a `JspException` that the
page's error handling shows like any other exception, see the xref:web/jsp-struts/jsp/error-handling.adoc[error handling
page]); it writes with `getJspContext().getOut()`, the page's own `JspWriter`, so that its output is in order with the template
text around it and obeys the page buffer.

The fourth line shows something that is true of every tag on this page and is easy to miss: the tag escaped nothing because
it printed nothing from the request, but the page's own `+${b.title}+` did not escape the title either. A tag does not
change the escaping rules of the template text next to it.

The `var` and `scope` form exports a value instead of printing it. A scoped variable written by a handler is read back by
the EL like any other, and it follows the normal scope rules.

The mistakes a page author can make with attributes are caught at three different times, and the message tells which.

.What happens with wrong attributes (observed on Tomcat 11.0.26)
[cols="3,2,4",options="header"]
|===
|Page |When |Result

The last row is the reason why `bs:rating` declares no `variable` element for its optional `var`: a
`name-from-attribute` variable makes the attribute mandatory in practice, because the translator cannot compute the name
without it. The EL does not need the declaration, since it reads scoped variables at run time; the declaration matters only
for a scripting variable that a scriptlet could read, which a modern page does not use. A tag whose `var` is required, like
`bs:pagination` below, can and should declare it.

[#body]
== The Body: JspFragment, invoke and Writers

The body of the tag is what the page author writes between the start and the end tag. The TLD's `body-content` decides what
is allowed there, and the handler decides what happens to it. Three patterns cover almost every tag.

.What a handler can do with its body
[cols="2,3,3",options="header"]
|===
|Pattern |In `doTag()` |Example

|Conditional |call `invoke(null)` only when the condition holds |`bs:when`
|Iteration |call `invoke(null)` in a loop, setting page-scoped values the body reads |`bs:pagination`
|Process the body |call `invoke(writer)` with a `StringWriter`, change the text, write the result |`bs:excerpt`
|Ignore the body |do not call `invoke` at all (and use `empty` in the TLD if no body should be written) |`bs:rating`
|===

[#excerpt]
=== Processing the Body: bs:excerpt

`bs:excerpt` shortens its body to a maximum length and prints it _escaped_. It hands `invoke` a `StringWriter`, so the body's
output never reaches the page; the handler gets it as a string and decides what to do with it. This is the simple tag
replacement for the classic `BodyContent` buffering, and the specification points out that, unlike `BodyContent`, the
output "does not need to be buffered" unless the handler wants to look at it.

.ExcerptTag.java
[source,java]
----
public class ExcerptTag extends SimpleTagSupport {
    private int max = 40;

    public void setMax(int max) { this.max = max; }

    @Override
    public void doTag() throws JspException, IOException {
        if (getJspBody() == null) {
            return;                                  // <bs:excerpt/> has no body: nothing to do
        }
        StringWriter captured = new StringWriter();
        getJspBody().invoke(captured);               // body output goes to our writer, not to the page
        String text = captured.toString().strip();
        if (text.length() > max) {
            text = text.substring(0, max).stripTrailing() + "…";
        }
        getJspContext().getOut().write(escape(text));
    }

    static String escape(String s) {
        StringBuilder sb = new StringBuilder(s.length() + 16);
        for (char c : s.toCharArray()) {
            switch (c) {
                case '&' -> sb.append("&amp;");
                case '<' -> sb.append("&lt;");
                case '>' -> sb.append("&gt;");
                case '"' -> sb.append("&#034;");
                case '\'' -> sb.append("&#039;");
                default -> sb.append(c);
            }
        }
        return sb.toString();
    }
}

[#pagination]
=== Iteration with Variables the Body Reads: bs:pagination

The second headline tag of the page is `bs:pagination`, which runs its body once for every page of a long list and tells
the body which page it is on. It teaches the part of the API that classic handlers needed `doAfterBody()` for: a loop that
puts values where the body reads them. The handler computes the number of pages from the list size (`total`) and the page
size, and for each page it stores the page number under the name given in `var` and a boolean `active` that is true for the
`current` page, both in the page scope of the `JspContext`, and then calls `invoke(null)`. The body is a fragment compiled
once; it sees the new values on every invocation, because it evaluates the EL again each time. The specification calls this
"parameterising a fragment": a handler sets page-scoped attributes on the `JspContext` that the fragment is bound to, and
the fragment reads them through the EL.

.PaginationTag.java
[source,java]
----
public class PaginationTag extends SimpleTagSupport {
    private int total;
    private int pageSize = 10;
    private int current = 1;
    private String var;
    private JspFragment separator;

    public void setTotal(int total) { this.total = total; }
    public void setPageSize(int pageSize) { this.pageSize = pageSize; }
    public void setCurrent(int current) { this.current = current; }
    public void setVar(String var) { this.var = var; }
    public void setSeparator(JspFragment separator) { this.separator = separator; }

    @Override
    public void doTag() throws JspException, IOException {
        if (pageSize < 1) {
            throw new JspTagException("bs:pagination: pageSize must be at least 1 but was " + pageSize);
        }
        JspFragment body = getJspBody();
        if (body == null) {
            return;
        }
        JspContext ctx = getJspContext();
        int pages = Math.max(1, (total + pageSize - 1) / pageSize);
        Object savedVar = ctx.getAttribute(var, PageContext.PAGE_SCOPE);
        Object savedActive = ctx.getAttribute("active", PageContext.PAGE_SCOPE);
        try {
            for (int p = 1; p <= pages; p++) {
                ctx.setAttribute(var, p, PageContext.PAGE_SCOPE);
                ctx.setAttribute("active", p == current, PageContext.PAGE_SCOPE);
                if (p > 1 && separator != null) {
                    separator.invoke(null);
                }
                body.invoke(null);
            }
        } finally {
            restore(ctx, var, savedVar);
            restore(ctx, "active", savedActive);
        }
    }

    private static void restore(JspContext ctx, String name, Object saved) {
        if (saved == null) {
            ctx.removeAttribute(name, PageContext.PAGE_SCOPE);
        } else {
            ctx.setAttribute(name, saved, PageContext.PAGE_SCOPE);
        }
    }
}
----

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#jsp-fragments[Jakarta Pages 4.0 -- 7.1.6 JSP Fragments]

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#iterations-2[Jakarta Pages 4.0 -- 7.1.7.4 Iterations]

[#fragment-attributes]
=== Fragment Attributes: jsp:attribute and the separator

The `separator` attribute of `bs:pagination` is declared in the TLD with `<fragment>true</fragment>`, so its type is
`JspFragment` and its value is not a string but a piece of page, written with `jsp:attribute`. When a custom tag has
`jsp:attribute` children, its body has to be written explicitly with `jsp:body`. The container
turns the body of the `jsp:attribute` into a fragment and passes it to `setSeparator`. The fragment must be scriptless, and
the handler calls `separator.invoke(null)` between the pages.

call `invoke` zero times, which is the way to write a body that appears only sometimes.

[#dynamic-attributes]
== Dynamic Attributes: bs:link

Some tags mimic an HTML element and cannot know which attributes the page author needs: `class`, `title`, `data-id`,
`aria-current`. Since JSP 2.0 a handler can declare that it accepts _attributes with dynamic names_. It implements
`DynamicAttributes`, whose single method `setDynamicAttribute(String uri, String localName, Object value)` is called by the
container for every attribute that the TLD does not name, and the tag's TLD entry carries `<dynamic-attributes>true</dynamic-attributes>`.
Without that element, an unknown attribute is a translation error (as for `colour` above). The handler must remember the
values itself, and a `JspException` thrown from the method means "I do not accept this one": the container then does not call
`doTag()`.

`bs:link` is an anchor with one declared attribute, `href`, and any number of dynamic attributes. It is written to be safe:
the names are limited to a conservative pattern, `style` and every `+on...+` event attribute are refused, the `javascript:`
scheme is refused, and every value and the `href` are escaped.

.LinkTag.java
[source,java]
----
public class LinkTag extends SimpleTagSupport implements DynamicAttributes {
    private static final Pattern NAME = Pattern.compile("[a-z][a-z0-9-]*");
    private String href;
    private final Map<String, String> extra = new LinkedHashMap<>();

    public void setHref(String href) { this.href = href; }

    @Override
    public void setDynamicAttribute(String uri, String localName, Object value) throws JspException {
        String name = localName.toLowerCase(Locale.ROOT);
        if (!NAME.matcher(name).matches() || name.startsWith("on") || name.equals("style")) {
            throw new JspTagException("bs:link does not accept the attribute \"" + localName + "\"");
        }
        if (value != null) {                         // an EL expression that evaluates to null drops the attribute
            extra.put(name, value.toString());
        }
    }

    @Override
    public void doTag() throws JspException, IOException {
        String safe = href == null ? "" : href.strip();
        if (safe.toLowerCase(Locale.ROOT).startsWith("javascript:")) {
            throw new JspTagException("bs:link: refusing a javascript: URL");
        }
        Writer out = getJspContext().getOut();
        out.write("<a href=\"" + ExcerptTag.escape(safe) + "\"");
        extra.forEach((n, v) -> {
            try {
                out.write(" " + n + "=\"" + ExcerptTag.escape(v) + "\"");
            } catch (IOException e) {
                throw new UncheckedIOException(e);
            }
        });
        out.write(">");
        if (getJspBody() != null) {
            getJspBody().invoke(null);
        }
        out.write("</a>");
    }
}
----

[#cooperating]
== Cooperating Tags: getParent, findAncestorWithClass and TagAdapter

Tags nested in other tags can talk to each other through the tree the container builds. `setParent` gives each handler its
enclosing tag, and `SimpleTagSupport.findAncestorWithClass(from, klass)` walks up the chain and returns the closest
ancestor of a class. `bs:numbered` is an ordered list
that numbers its `bs:item` children, and the item finds its parent by class.

.NumberedTag.java and ItemTag.java
[source,java]
----
public class NumberedTag extends SimpleTagSupport {
    private int counter;

    int next() { return ++counter; }

    @Override
    public void doTag() throws JspException, IOException {
        getJspContext().getOut().write("<ol>\n");
        if (getJspBody() != null) {
            getJspBody().invoke(null);
        }
        getJspContext().getOut().write("</ol>\n");
    }
}

public class ItemTag extends SimpleTagSupport {
    @Override
    public void doTag() throws JspException, IOException {
        NumberedTag parent = (NumberedTag) findAncestorWithClass(this, NumberedTag.class);
        if (parent == null) {
            throw new JspTagException("bs:item must be nested in bs:numbered");
        }
        StringWriter text = new StringWriter();
        getJspBody().invoke(text);
        getJspContext().getOut().write("<li value=\"" + parent.next() + "\">"
                + ExcerptTag.escape(text.toString().strip()) + "</li>\n");
    }
}

[#skip-page]
== Stopping the Page: SkipPageException

A classic handler stops the rest of the page by returning `SKIP_PAGE` from `doEndTag()`. A simple handler throws
`SkipPageException` from `doTag()` (or a fragment does, which a handler propagates). The Javadoc is explicit about the effect:
the calling page must cease evaluation. It is the mechanism behind a guard tag such as "stop unless the request has an id", and
it is also thrown by the container itself when a tag file invokes a classic handler that returned `SKIP_PAGE`.

.StopUnlessTag.java
[source,java]
----
public class StopUnlessTag extends SimpleTagSupport {
    private boolean test;

    public void setTest(boolean test) { this.test = test; }

    @Override
    public void doTag() throws JspException, IOException {
        if (!test) {
            throw new SkipPageException("condition not met");
        }
    }
}
----

Source: https://jakarta.ee/specifications/pages/4.0/apidocs/jakarta.servlet.jsp/jakarta/servlet/jsp/SkipPageException.html[Jakarta Pages 4.0 API -- SkipPageException]

.stop.jsp, and an including page stopinc.jsp (the taglib directives for `bs` and `fn` are left out)
[source,jsp]
----
<%-- stop.jsp --%>
before
<bs:stopUnless test="${not empty param.id}"/>
after: id=${fn:escapeXml(param.id)}

<%-- stopinc.jsp --%>
outer before
<jsp:include page="/stop.jsp"/>
outer after
----

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#plain-actions-2[Jakarta Pages 4.0 -- 7.1.7.1 Plain Actions]

.What the requests return (observed; all status 200)
[cols="3,4",options="header"]
|===
|Request |Body of the response

|`stop.jsp` |`before`
|`stop.jsp?id=7` |`before` and `after: id=7`
|`stopinc.jsp` |`outer before`, `before` and `outer after`
|===

The text before the tag was sent, the text after it was not, and the status is 200, because stopping the page is not an
error. The third row shows the scope of the stop: the page that _included_ `stop.jsp` carried on, since a `jsp:include` is a
separate request dispatch (see the xref:web/jsp-struts/jsp/includes-forwards-and-page-composition.adoc[includes and forwards
page]); only the page that contains the tag stops. Compare a `JspTagException`, which discards the buffer and produces an error
response. Use `SkipPageException` only for "the rest of this page makes no sense", for example after a redirect the tag has
already sent; the Javadoc adds that it "should not be thrown manually in a JSP page or tag file", meaning in a scriptlet.

[#other-api]
== The Rest of the API: Context, Injection, Ids and Listeners

*JspContext, PageContext and tag files.* A simple handler receives a `JspContext`. On Tomcat the object is the page's
`PageContextImpl`, so a cast to `PageContext` for the request, the response or the session works in an ordinary page, and
this is common in practice. It is not portable to every context: the same handler called from inside a tag file got a
`JspContextWrapper` (the page context of the tag file) in the test, and on Tomcat that class is also a `PageContext`:

.ContextTag, called from a page and from a tag file (observed)
[source,text]
----
context=org.apache.jasper.runtime.PageContextImpl, isPageContext=true
context=org.apache.jasper.runtime.JspContextWrapper, isPageContext=true
----

The specification only promises a `JspContext`, and a handler meant for reuse should use the `JspContext` methods and test with
`instanceof PageContext` before it needs the servlet API.

*Resource injection.* Handlers that implement `Tag` or `SimpleTag` may be annotated for injection (`@Resource`, `@EJB`,
`@PersistenceContext`, `@PostConstruct`, `@PreDestroy` and the others the Servlet specification lists in section 15.5); the
container injects them right after the instance is constructed and before any attribute is set. Injection is not supported for
JSP pages or tag files, and a container that is not a full Jakarta EE server is encouraged but not required to support it, so a
tag that relies on it is not portable to a plain servlet container.

*JspIdConsumer.* A handler that implements `JspIdConsumer` receives a `jspId` through `setJspId`, a string that is unique for
every tag in a page and the same for a given tag on every request. It is the way to generate stable HTML ids; the Javadoc notes
that such handlers cannot be reused, which is no restriction for simple tags.

*Event listeners.* A tag library may list listener classes in its TLD; the container registers them before the application
starts. The mechanism is the same for classic and simple libraries and is described on the tag library descriptors page.

*Scripting variables.* A `variable` declaration can create a scripting variable for scriptlets, but a tag body of a simple tag
is a fragment and cannot contain scriptlets: a translation error occurs if it does. The variables of this page are scoped
variables read through the EL.

*Pooling.* The container does not pool simple handlers (the trace above shows a new instance for every use), so the Jasper
option `enablePooling`, which controls the reuse of classic handlers, has no effect on them; the classic handlers page of this
section covers the option and the 2024 Tomcat vulnerability in tag recycling.

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#resource-injection[Jakarta Pages 4.0 -- 7.1.11 Resource Injection]

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#jspid-attribute[Jakarta Pages 4.0 -- 7.1.10 JspId Attribute]

Source: https://jakarta.ee/specifications/pages/4.0/jakarta-server-pages-spec-4.0.html#event-listeners[Jakarta Pages 4.0 -- 7.1.9 Event Listeners]

[#bookshelf-example]
== Worked Example: the Bookshelf Catalogue Page

The pieces come together in one page: a catalogue of two books per page with a link, a rating, a "classic" badge, an excerpt of
the blurb, and a pager. The application scope holds the four books (the `ShelfListener` of the scratch project sets them), and
the page chooses the books to show with `c:forEach begin` and `end` from the `p` request parameter.

.worked.jsp
[source,jsp]
----
<%@ page contentType="text/html;charset=UTF-8" %>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<%@ taglib prefix="fn" uri="jakarta.tags.functions" %>
<%@ taglib prefix="bs" uri="https://example.org/bookshelf/tags" %>
<c:set var="size" value="2"/>
<c:set var="cur" value="${empty param.p ? 1 : param.p}"/>
<!DOCTYPE html>
<html lang="en">
<body>
<h1>Bookshelf</h1>
<ul>
<c:forEach var="b" items="${books}" begin="${(cur - 1) * size}" end="${cur * size - 1}">
  <li>
    <bs:link href="${pageContext.request.contextPath}/books/${b.id}" class="title"><c:out value="${b.title}"/></bs:link>
    <bs:rating value="${b.rating}"/>
    <bs:when test="${b.year lt 1970}"><em>classic</em></bs:when>
    <p><bs:excerpt max="40">${b.blurb}</bs:excerpt></p>
  </li>
</c:forEach>
</ul>
<nav>
<bs:pagination total="${fn:length(books)}" pageSize="${size}" current="${cur}" var="n">
  <jsp:attribute name="separator"> | </jsp:attribute>
  <jsp:body><bs:link href="?p=${n}" class="page" aria-current="${active ? 'page' : null}">${n}</bs:link></jsp:body>
</bs:pagination>
</nav>
</body>
</html>
----

The page has no scriptlet and no Java, the tags do the presentation, and each of them is testable on its own. The decisions
that make it work: `c:out` for the title, because the body of `bs:link` is not escaped; the tag escapes the attribute values
and the excerpt, because they cross from data to markup inside the tag; the page uses `fn:length` for the total instead of
asking the tag to count; and the pager's separator is a fragment so that the page author, not the tag, decides what goes
between the numbers.

[#security]
== Security Notes

* *A tag is code that writes HTML. Decide where escaping happens and document it.* In the example the tags escape what they
  receive as attributes and as captured text (`bs:link`, `bs:excerpt`), and do not touch what they pass through unmodified
  (the body of `bs:link`, a fragment passed to `invoke(null)`). The page author must know which is which; the tag's
  `description` in the TLD is the place to say it.
* *Dynamic attributes are an injection channel.* `bs:link` accepts any attribute name. An unchecked name can carry `onclick`,
  `style` or a name with spaces and quotes, and an unchecked value can end the attribute and start another. Restrict names
  with a pattern, refuse event attributes, escape every value, and refuse `javascript:` in a URL (the three checks are in
  the example and were exercised above).
* *Never build EL or scripting from attribute values.* A handler that evaluates a string with `ELProcessor` or the
  `JspApplicationContext` factory turns a request value into code. Take the value as data; let the container evaluate the
  attribute (`rtexprvalue`) and give the handler the result.
* *Validate in the handler and fail loudly.* `max`, `pageSize` and the scope name are checked before use; an unchecked
  `pageSize` of 0 would divide by zero. Throw `JspTagException` with a message that names the tag and the attribute, so the
  page author finds it. Put no secrets, SQL or file paths in these messages: they reach the error page.
* *Instance fields are private to one use, `static` fields are not.* The per-invocation instance makes the handler itself
  thread-safe, but a static counter, cache or `SimpleDateFormat` is shared between all requests; use thread-safe types and
  never keep a `JspContext`, a request or a fragment in a static field.
* *Do not let a tag read request data it was not given.* A tag that calls `+((PageContext) ctx).getRequest().getParameter(...)+`
  hides an input that the page author cannot see. Pass values as attributes so that the page shows what feeds the tag.
* *`SkipPageException` is not an access check.* A guard tag that stops the page is a convenience; an authorisation rule
  belongs in a filter or in the security constraints of `web.xml`, because a page reached through a controller
  should never depend on a tag to refuse a request.
* *Keep tag libraries on the right side of the trust line.* A TLD and its classes run with the web application's privileges.
  Add only libraries from sources you trust, check them for the dependencies they bring, and remember that a `listener`
  element in a TLD registers code that runs when the application starts.

[#books-outdated]
== Where the Books Are Outdated

The section bibliography lists _Web Development with JavaServer Pages_ (Manning, 2001, JSP 1.2), whose chapters on custom
tags describe the tag extension mechanism of its time, and _JSTL in Action_ (Manning, 2002), whose last chapter builds custom
tags that cooperate with JSTL. The ideas that these chapters teach are still sound: a tag library as a vocabulary, a TLD that
describes it, attributes as bean properties, scoped variables as the way a tag gives data to its body, tags that cooperate
through their parent, and the discipline of separating tags from business logic. What changed is the API and the amount of
code needed.
