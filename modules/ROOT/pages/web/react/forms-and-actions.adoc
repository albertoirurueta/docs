= Forms and Actions
:description: Controlled inputs and form submission in React, and the React 19 Actions model with useActionState, useFormStatus, and useOptimistic plus progressive enhancement.
:keywords: React forms, controlled input, onSubmit, FormData, React 19 Actions, form action, useActionState, useFormStatus, useOptimistic, pending UI, progressive enhancement

include::partial$ai-disclaimer.adoc[]

React handles forms in two styles: the classic **controlled inputs + `onSubmit`** approach, and the React 19
**Actions** model, which wires an async function directly to a `<form>` and manages pending, error, and
optimistic state for you.

== Controlled inputs

Bind each field's `value` to state and update it in `onChange`. The component is the single source of truth.

[source,jsx]
----
function SignupForm({ onSubmit }) {
  const [email, setEmail] = useState('');
  const [note, setNote] = useState('');
  const [plan, setPlan] = useState('free');

  function handleSubmit(e) {
    e.preventDefault();
    onSubmit({ email, plan });
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="email" value={email} onChange={(e) => setEmail(e.target.value)} />
      <textarea value={note} onChange={(e) => setNote(e.target.value)} />
      <select value={plan} onChange={(e) => setPlan(e.target.value)}>
        <option value="free">Free</option>
        <option value="pro">Pro</option>
      </select>
      <button type="submit">Create account</button>
    </form>
  );
}
----

For a form with many fields you do not need to react to per keystroke, leave them **uncontrolled** and read
`new FormData(e.target)` on submit. See
https://react.dev/reference/react-dom/components/form[`<form>`].

== React 19 Actions

Pass a function to `<form action>` (or to `startTransition`). React calls it with the form's `FormData`, marks
the surrounding transition **pending** while it runs, resets uncontrolled fields on success, and surfaces
thrown errors.

[source,jsx]
----
import { useActionState } from 'react';

function CommentForm({ postId }) {
  const [state, formAction, isPending] = useActionState(
    async (prevState, formData) => {
      const text = formData.get('text');
      try {
        await addComment(postId, text);
        return { ok: true, error: null };
      } catch (err) {
        return { ok: false, error: err.message };
      }
    },
    { ok: false, error: null }
  );

  return (
    <form action={formAction}>
      <textarea name="text" required />
      <button disabled={isPending}>{isPending ? 'Posting…' : 'Post'}</button>
      {state.error && <p role="alert">{state.error}</p>}
    </form>
  );
}
----

* **`useActionState(fn, initialState)`** -> `[state, action, isPending]`. `state` is the last value the action
  returned.
* **`useFormStatus()`** (from `react-dom`) -- lets a **child** of the `<form>` (e.g. a `<SubmitButton>`) read
  `+{ pending }+` without prop drilling.
* **`useOptimistic(value, updateFn)`** -- render an immediate optimistic value while the action is in flight,
  automatically reverting if it fails.

[source,jsx]
----
import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'Saving…' : 'Save'}</button>;
}
----

When the action is a server function, `<form action>` also works **before** JavaScript loads (progressive
enhancement) -- the browser posts the form and the server responds. References:
https://react.dev/reference/react/useActionState[`useActionState`],
https://react.dev/reference/react-dom/hooks/useFormStatus[`useFormStatus`],
https://react.dev/reference/react/useOptimistic[`useOptimistic`],
https://react.dev/reference/rsc/server-functions[Server Functions]. For Server Actions in Next.js --
revalidation after a mutation, validation and security -- see
xref:web/nextjs/server-actions-and-mutations.adoc[Server Actions and Mutations].

== Deep dive: the life of an Action

An Action is just an async function, but React wraps it in a transition so that the UI can show progress and keep
handling input while it runs. For a `+<form action={formAction}>+` that was produced by `useActionState`, a submit goes
through these steps:

[mermaid]
....
sequenceDiagram
    participant U as User
    participant F as form
    participant R as React
    participant A as Your action
    U->>F: submit
    F->>R: submit event (default navigation prevented)
    R->>R: isPending = true, useFormStatus().pending = true
    R->>A: action(previousState, FormData)
    A-->>R: returns the next state (or throws)
    R->>R: isPending = false, state = returned value
    R->>F: reset uncontrolled fields
    R-->>U: re-render with the new state
....

Three details matter in practice. The action receives the **previous state** as its first argument when it comes from
`useActionState`, and only the `FormData` when you pass a plain function to `<form action>`. Actions queued by the
same hook run **one after another**, in order. And after the action completes, React **resets the form's uncontrolled
fields**; if you want to keep what the user typed after a validation error, send the values back in the state and
use them as `defaultValue`, as the next example does.

== Deep dive: a product review form with validation

The storefront's review form validates on the server side of the action (here, a stub), reports field errors, shows a
pending state in a child button, and keeps the user's text when something fails.

[source,jsx]
----
import { useActionState } from 'react';
import { useFormStatus } from 'react-dom';

function validate(formData) {
  const errors = {};
  const text = String(formData.get('text') ?? '').trim();
  const rating = Number(formData.get('rating'));
  if (text.length < 5) errors.text = 'Write at least 5 characters';
  if (!(rating >= 1 && rating <= 5)) errors.rating = 'Pick a rating from 1 to 5';
  return { errors, text, rating };
}

async function reviewAction(previousState, formData) {
  const { errors, text, rating } = validate(formData);
  if (Object.keys(errors).length > 0) {
    return { ok: false, errors, values: { text: formData.get('text'), rating: formData.get('rating') } };
  }
  try {
    await saveReview('kb', rating, text);          // your API call
    return { ok: true, errors: {}, values: { text: '', rating: '' } };
  } catch (e) {
    return { ok: false, errors: { form: e.message }, values: { text, rating: String(rating) } };
  }
}

function SubmitButton() {
  const { pending } = useFormStatus();             // reads the enclosing <form>
  return <button disabled={pending}>{pending ? 'Saving...' : 'Submit review'}</button>;
}

export function ReviewForm() {
  const [state, formAction] = useActionState(reviewAction, {
    ok: false, errors: {}, values: { text: '', rating: '' },
  });

  return (
    <form action={formAction}>
      <input name="rating" type="number" aria-label="Rating" defaultValue={state.values.rating} />
      {state.errors.rating && <p role="alert">{state.errors.rating}</p>}
      <textarea name="text" aria-label="Review" defaultValue={state.values.text} />
      {state.errors.text && <p role="alert">{state.errors.text}</p>}
      {state.errors.form && <p role="alert">{state.errors.form}</p>}
      {state.ok && <p role="status">Thanks!</p>}
      <SubmitButton />
    </form>
  );
}
----

Driving it from React Testing Library with `saveReview` stubbed to wait 30 ms and to reject text containing "spam", the
results are:

[cols="2,3",options="header"]
|===
| Interaction | Observed result

| Submit the empty form | Two alerts: `Pick a rating from 1 to 5` and `Write at least 5 characters`; nothing is saved.
| Rating 4, text "great spam" | After the delay one alert, `Rejected by the server`; the textarea still contains `great spam`.
| Rating 4, text "great keyboard" | The `Thanks!` status appears, the review is saved once, and the textarea is empty again.
|===

Because validation lives in the action, the same function can run on the server unchanged when the action is a Server
Function. Client-side checks (`required`, `minLength`, `type="email"`) remain a good first line of defence, but they
are a convenience: never skip validating on the server.

=== Accessibility notes

Associate every input with a label (`<label>` or `aria-label`), render errors in an element with `role="alert"` so
screen readers announce them, and keep the submit button reachable while pending (disabled is fine, removed is not).

== Deep dive: optimistic updates

`useOptimistic(value, reducer)` returns a value that equals `value` normally but includes a temporary change while an
Action is running. When the Action finishes, React discards the temporary value and shows whatever the real state is,
so a failure automatically rolls back.

[source,jsx]
----
import { useOptimistic } from 'react';

function Reviews({ reviews, addReview }) {
  const [optimistic, addOptimistic] = useOptimistic(
    reviews,
    (current, text) => [...current, { text, sending: true }],
  );

  async function action(formData) {
    const text = formData.get('text');
    addOptimistic(text);              // shown immediately
    await addReview(text);            // the parent updates `reviews` when this resolves
  }

  return (
    <>
      <ul>
        {optimistic.map((r, i) => (
          <li key={i}>{r.text}{r.sending && ' (sending...)'}</li>
        ))}
      </ul>
      <form action={action}>
        <input name="text" aria-label="New review" />
        <button>Add</button>
      </form>
    </>
  );
}
----

In a test the list starts as `+['first']+`. Right after the form is submitted it shows `first` and `+second (sending...)+`, and
once the 30 ms request resolves and the parent state updates, it shows `first` and `second` with no marker. The
optimistic update must be called inside an Action (a form `action`, or `startTransition`); outside one React warns and
the change is not shown.

Use the optimistic pattern for operations that almost always succeed (liking, adding to a list, toggling a flag), and keep
the pending/disabled pattern for operations whose outcome the user must see (payments).

== Deep dive: choosing a form strategy

[cols="2,3",options="header"]
|===
| Need | Approach

| A handful of fields, submit and navigate | Uncontrolled inputs plus `FormData` in `onSubmit`
| Live validation or dependent fields while typing | Controlled inputs
| Submit with pending and error state, minimal code | `<form action>` with `useActionState`
| A submit button that knows the form is busy | `useFormStatus` in a child component
| Immediate feedback before the server answers | `useOptimistic`
| Large forms with complex rules | A library such as React Hook Form or TanStack Form
|===
