= JSX and Rendering
:description: JSX syntax and how it maps to JavaScript, embedding expressions with curly braces, conditional rendering, rendering lists with keys, and mounting a React tree with createRoot.
:keywords: JSX, React elements, Fragment, className, curly braces in JSX, conditional rendering, ternary, logical AND, rendering lists, keys, map, createRoot, react-dom/client, StrictMode

include::partial$ai-disclaimer.adoc[]

JSX is an XML-like syntax extension for JavaScript. A build tool (Vite, Babel, the TypeScript compiler)
transforms it into `React.createElement` / `jsx()` calls that return plain objects describing the UI. You can
write React without JSX, but nearly everyone uses it.

== JSX basics

* A component returns **one** root element. Wrap siblings in a parent element or an empty **Fragment**
  `+<>...</>+` (import `Fragment` when you need to give it a `key`).
* Attributes are camelCase and follow the DOM property names: `className` (not `class`), `htmlFor` (not
  `for`), `onClick`, `tabIndex`.
* Every tag must be closed: `<br />`, `+<img src="..." />+`.
* JSX is an expression -- you can store it in a variable, return it, or pass it as a prop.

[source,jsx]
----
function Card() {
  return (
    <>
      <h2 className="card-title">Title</h2>
      <img src="/logo.png" alt="" />
    </>
  );
}
----

Converting HTML to JSX is mostly mechanical: rename `class`/`for`, close void elements, camelCase event and
style attributes, and wrap in a single parent. See
https://react.dev/learn/writing-markup-with-jsx[Writing Markup with JSX].

== Curly braces: JavaScript in JSX

Curly braces `+{ }+` embed a JavaScript **expression** in JSX -- in children or in an attribute value. A quoted
string is a literal; braces are code.

[source,jsx]
----
const user = { name: 'Ada', theme: 'dark' };

<h1>{user.name}'s dashboard</h1>          // expression in children
<img src={user.avatarUrl} alt="" />       // expression as an attribute
<p title={`Signed in as ${user.name}`}>…</p>
----

"Double curlies" are just an object literal inside the braces -- most often an inline `style` object (whose
keys are camelCased CSS properties):

[source,jsx]
----
<div style={{ color: 'red', marginTop: 8 }}>Warning</div>
----

Only strings, numbers, and JSX render as children; `true`, `false`, `null`, and `undefined` render nothing.
Objects do **not** render -- `+<p>\{user}</p>+` throws. See
https://react.dev/learn/javascript-in-jsx-with-curly-braces[JavaScript in JSX with Curly Braces].

== Conditional rendering

[source,jsx]
----
function Status({ user }) {
  if (!user) return null;                       // render nothing

  return (
    <div>
      {user.isAdmin ? <AdminBadge /> : <UserBadge />}   {/* ternary */}
      {user.messages.length > 0 && <Inbox count={user.messages.length} />}  {/* && */}
    </div>
  );
}
----

Beware `+{count && <Inbox />}+` when `count` is `0` -- React renders the `0`. Use `+count > 0 && …+` or
`+Boolean(count) && …+`. See https://react.dev/learn/conditional-rendering[Conditional Rendering].

== Rendering lists

Transform an array with `.map()` (and `.filter()`), returning one element per item. Each sibling needs a
stable, unique **`key`** so React can match elements across renders.

[source,jsx]
----
function TodoList({ todos }) {
  return (
    <ul>
      {todos
        .filter((t) => !t.archived)
        .map((t) => (
          <li key={t.id}>{t.text}</li>
        ))}
    </ul>
  );
}
----

`key` must be unique among siblings and come from the data (a database id, a slug). **Do not use the array
index** as a key when the list can reorder, filter, or grow at the front: React would keep state attached to
the wrong item. `key` is a hint to React, not a prop your component can read. See
https://react.dev/learn/rendering-lists[Rendering Lists].

== Rendering into the page

`createRoot` from `react-dom/client` connects a React tree to a real DOM node. Call `root.render` once with
your top component; later state changes re-render through the same root.

[source,jsx]
----
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'));
root.render(
  <StrictMode>
    <App />
  </StrictMode>
);
----

In development, `<StrictMode>` intentionally double-invokes component functions and Effect setup/cleanup to
help you catch impure renders and missing cleanup; this does not happen in production. For server-rendered
HTML you call `hydrateRoot` instead -- see xref:web/react/server-rendering.adoc[Server Rendering]. For the
underlying DOM API that `createRoot` drives, see xref:programming-languages/javascript/browser-dom-basics.adoc[Web Programming
Basics].

References: https://react.dev/reference/react-dom/client/createRoot[`createRoot`],
https://react.dev/reference/react/StrictMode[`<StrictMode>`],
https://react.dev/learn/describing-the-ui[Describing the UI].

== Deep dive: what JSX compiles to

JSX is syntax sugar. With the automatic runtime that Vite, Next.js and the TypeScript compiler use today, a tag
becomes a call to `jsx()` from `react/jsx-runtime`, and `children` become an ordinary prop. The older "classic"
transform produced `React.createElement` calls instead.

[source,jsx]
----
const a = <Price amount={9.5} className="x">hi</Price>;
----

compiles (automatic runtime) to:

[source,js]
----
import { jsx } from "react/jsx-runtime";
const a = jsx(Price, { amount: 9.5, className: "x", children: "hi" });
----

and with the classic transform to `+React.createElement(Price, { amount: 9.5 }, "hi")+`. Two consequences follow:

* Capitalization matters because the compiler emits a string for `<li>` and a variable reference for `<Price>`.
* An expression in braces is just a JavaScript expression inside that call, so anything that is not valid as an
  argument (a `for` loop, an `if` statement) is not valid in braces either. Compute it first, or use `map`, `&&` and
  the ternary.

== Deep dive: escaping, falsy values and Fragments with keys

JSX escapes every string you embed, so rendering user input as text is safe by default:

[source,jsx]
----
renderToString(<p>{'<img src=x onerror=alert(1)>'}</p>);
// <p>&lt;img src=x onerror=alert(1)&gt;</p>
----

The only way to inject raw HTML is the deliberately ugly `dangerouslySetInnerHTML` prop; only use it with content
you have sanitized.

Falsy values behave differently depending on their type:

[source,jsx]
----
renderToString(<p>{0 && <b>x</b>}|{[1, 2]}|{null}|{false}</p>);
// <p>0<!-- -->|<!-- -->1<!-- -->2<!-- -->|<!-- -->|</p>
----

The `0` is printed (the classic `+count && …+` bug), arrays are flattened, and `null` and `false` produce nothing. When
each item of a list needs *several* sibling elements, use the explicit `Fragment` so you can give it a `key`; the
`+<>...</>+` shorthand cannot take one.

[source,jsx]
----
import { Fragment } from 'react';

function Specs({ rows }) {
  return (
    <dl>
      {rows.map((r) => (
        <Fragment key={r.term}>
          <dt>{r.term}</dt>
          <dd>{r.def}</dd>
        </Fragment>
      ))}
    </dl>
  );
}
----

== Deep dive: why an index key corrupts state

Keys are how React decides which previous element a new one corresponds to, and therefore *which component
instance keeps which state*. In the storefront the rows of an admin list each hold a draft input:

[source,jsx]
----
function Row({ text }) {
  const [draft, setDraft] = useState('');
  return (
    <li>
      {text} <input aria-label={text} value={draft} onChange={(e) => setDraft(e.target.value)} />
    </li>
  );
}

function List({ items, byIndex }) {
  return <ul>{items.map((t, i) => <Row key={byIndex ? i : t} text={t} />)}</ul>;
}
----

Type "typed" into the *Keyboard* row, then reorder the items to `+['Mouse', 'Keyboard']+`:

[cols="1,2",options="header"]
|===
| Key | Result after the reorder

| Array index (`+key={i}+`) | `Mouse=typed, Keyboard=` -- the text stayed in the first slot and now sits next to the wrong product.
| Stable id (`+key={t}+`) | `Mouse=, Keyboard=typed` -- the instance moved with its item.
|===

With index keys React sees "position 0 is still a `Row`", reuses it and only changes its `text` prop. The state
stays where it was. The same applies to filtering and to inserting at the front. Use a database id or slug from the
data; if a list is purely static and never reordered, an index is harmless.
