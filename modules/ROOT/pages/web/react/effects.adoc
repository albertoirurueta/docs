= Effects and Lifecycle
:description: Synchronizing with external systems using useEffect, dependency arrays and cleanup, fetching in an Effect with a race guard, when you do not need an Effect, reactive effects and useEffectEvent, and useLayoutEffect.
:keywords: useEffect, dependency array, cleanup function, effect lifecycle, race condition, AbortController, you might not need an effect, useEffectEvent, useLayoutEffect, useInsertionEffect

include::partial$ai-disclaimer.adoc[]

An **Effect** lets a component synchronize with a system *outside* React -- the browser DOM, a network
connection, a third-party widget, a timer. Effects run *after* render and commit, not during. If you are not
synchronizing with an external system, you probably do not need an Effect.

== `useEffect`

[source,jsx]
----
import { useEffect, useState } from 'react';

function ChatRoom({ roomId }) {
  const [status, setStatus] = useState('connecting');

  useEffect(() => {
    const conn = createConnection(roomId);   // setup
    conn.on('open', () => setStatus('online'));
    conn.connect();
    return () => conn.disconnect();           // cleanup
  }, [roomId]);                               // dependencies

  return <p>{status}</p>;
}
----

* The **setup** function runs after the component mounts (and again after any dependency changes).
* The **cleanup** function runs before the next setup and when the component unmounts.
* The **dependency array** lists every reactive value (prop, state, or value derived from them) used inside.
  `[]` means "run once on mount". Omitting the array means "run after every render" -- rarely what you want.

In development `<StrictMode>` runs setup -> cleanup -> setup once extra, to prove your cleanup is correct.
References: https://react.dev/reference/react/useEffect[`useEffect`],
https://react.dev/learn/synchronizing-with-effects[Synchronizing with Effects].

== Fetching data in an Effect

Fetching in an Effect works but needs a **race guard**: a slow earlier request must not overwrite a faster
later one.

[source,jsx]
----
useEffect(() => {
  let ignore = false;
  fetch(`/api/products/${id}`)
    .then((r) => r.json())
    .then((data) => { if (!ignore) setProduct(data); });
  return () => { ignore = true; };            // or: const c = new AbortController(); ... c.abort()
}, [id]);
----

For anything beyond a trivial case, a framework loader or a data library (TanStack Query, SWR) handles caching,
deduplication, and races for you -- see xref:web/react/data-fetching.adoc[Data Fetching].

== You might not need an Effect

Common Effects that should be deleted:

* **Deriving data** -- compute it during render instead of storing it in state and syncing with an Effect.
+
[source,jsx]
----
// no Effect needed
const fullName = firstName + ' ' + lastName;
const visible = items.filter((i) => i.matches(query));
----
* **Responding to a user event** -- put that logic in the event handler, not an Effect that watches state.
* **Resetting state when a prop changes** -- give the component a different `key` so React remounts it.
* **Caching an expensive calculation** -- use `useMemo`, not state + Effect.

See https://react.dev/learn/you-might-not-need-an-effect[You Might Not Need an Effect].

== Reactive effects and `useEffectEvent`

An Effect is **reactive**: it re-runs when any dependency changes. Sometimes you want to read the latest value
of something *without* making it a dependency -- for example, log the current `theme` when a chat connects, but
do not reconnect when only the theme changes. Extract that part into an **Effect Event** with `useEffectEvent`,
available since React 19.2 (see https://react.dev/blog/2025/10/01/react-19-2[the React 19.2 post]):

[source,jsx]
----
import { useEffect, useEffectEvent } from 'react';

function ChatRoom({ roomId, theme }) {
  const onConnected = useEffectEvent(() => {
    showToast('Connected!', theme);          // reads latest theme, not reactive
  });

  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('open', onConnected);
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);                              // theme is NOT a dependency
}
----

References: https://react.dev/learn/lifecycle-of-reactive-effects[Lifecycle of Reactive Effects],
https://react.dev/learn/separating-events-from-effects[Separating Events from Effects],
https://react.dev/learn/removing-effect-dependencies[Removing Effect Dependencies].

== `useLayoutEffect` and `useInsertionEffect`

* **`useEffect`** -- runs after the browser paints. The default; use it unless you have a reason not to.
* **`useLayoutEffect`** -- runs *before* the browser paints, after DOM mutation. Use it only to measure layout
  (e.g. a tooltip's size) and re-render synchronously so the user never sees the intermediate state. It blocks
  painting, so keep it cheap.
* **`useInsertionEffect`** -- runs before any layout effect; for CSS-in-JS libraries injecting `<style>` tags.
  Application code should not need it.

== Deep dive: when each Effect runs

An Effect is not a "mounted" callback; it describes how to *start* and *stop* synchronizing with something, and React
decides when to run each half. Logging every phase of a small component shows the real order:

[source,jsx]
----
function Room({ roomId }) {
  log.push('render ' + roomId);
  useLayoutEffect(() => { log.push('layout ' + roomId); return () => log.push('layout cleanup ' + roomId); });
  useEffect(() => {
    log.push('connect ' + roomId);
    return () => log.push('disconnect ' + roomId);
  }, [roomId]);
  return <p>{roomId}</p>;
}
// render roomId="a", re-render with roomId="b", then unmount
----

[cols="1,3",options="header"]
|===
| Step | Log entries

| Mount | `render a`, `layout a`, `connect a`
| Update to `b` | `render b`, `layout cleanup a`, `layout b`, `disconnect a`, `connect b`
| Unmount | `layout cleanup b`, `disconnect b`
|===

Three rules can be read straight off this table: cleanup of the *previous* run always happens before the next
setup; layout Effects run synchronously right after the DOM is updated and before `useEffect` ones; and on update
the cleanup uses the values from the *old* render (`disconnect a`), not the new one.

== Deep dive: what `<StrictMode>` shows you

In development `<StrictMode>` mounts every component, immediately runs its cleanup, and mounts it again. For the same
component the log becomes:

----
render a, render a                       (the component is rendered twice)
layout a, connect a                      (first mount)
layout cleanup a, disconnect a           (simulated unmount)
layout a, connect a                      (mount again)
----

If `connect` and `disconnect` are symmetrical, the extra cycle is invisible. If you see a duplicated network
connection, a doubled subscription or a timer that runs twice, the cleanup is missing or incomplete. Do not "fix"
this by guarding with a ref; fix the cleanup. The extra cycle does not happen in production.

== Deep dive: a race condition, reproduced

A product detail panel fetches `/api/products/:id` whenever `id` changes. If the user switches quickly from product
1 to product 2, the response for product 1 can arrive *after* the one for product 2. To reproduce this
deterministically, replace `fetch` with a stub that returns promises you resolve by hand: resolve product 2's first,
then product 1's.

[source,jsx]
----
function Product({ id }) {
  const [product, setProduct] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    let ignore = false;
    setProduct(null);
    fetch(`/api/products/${id}`, { signal: controller.signal })
      .then((r) => r.json())
      .then((data) => { if (!ignore) setProduct(data); })
      .catch((e) => { if (e.name !== 'AbortError') setError(e); });
    return () => { ignore = true; controller.abort(); };
  }, [id]);

  return <p>{error ? 'error' : product ? product.name : 'loading'}</p>;
}
----

[cols="1,2",options="header"]
|===
| Variant | What the screen shows after both responses (id changed 1 to 2)

| No guard: `.then(setProduct)` | The data for product **1** -- stale data wins, because it resolved last.
| `ignore` flag and `AbortController` (above) | The data for product **2**.
|===

The flag is what makes the result correct: the cleanup for `id = 1` runs when `id` changes, and from then on its
`.then` callback is ignored. Aborting additionally cancels the request on the network. Treat `AbortError` as expected,
not as a failure. For anything with caching or retries use a data library (see
xref:web/react/data-fetching.adoc[Data Fetching]).

== Deep dive: synchronizing with the outside world

Effects exist for things React does not own. In the storefront, two small examples:

[source,jsx]
----
function CartTitle({ count }) {
  useEffect(() => {
    const previous = document.title;
    document.title = `Cart (${count})`;
    return () => { document.title = previous; };
  }, [count]);
  return null;
}
----

Mounting with `count = 2` sets the tab title to `Cart (2)`, re-rendering with `3` changes it to `Cart (3)`, and
unmounting restores `Shop`. Note how the cleanup restores the previous value rather than assuming one. (In React 19
you can also render `<title>` directly; see xref:web/react/getting-started.adoc[Getting Started].)

[source,jsx]
----
function Chat({ roomId, theme }) {
  const onConnected = useEffectEvent(() => { showToast(roomId, theme); });
  useEffect(() => {
    const conn = createConnection(roomId);
    conn.on('open', onConnected);
    conn.connect();
    return () => conn.disconnect();
  }, [roomId]);               // theme and onConnected are not dependencies
  return null;
}
----

Rendering `<Chat roomId="a" theme="light" />` and then changing only `theme` to `"dark"` does **not** reconnect;
changing `roomId` to `"b"` does, and the toast sees the latest `theme`. An Effect Event may only be called from
inside an Effect (or another Effect Event) and must not be passed to child components.

=== Choosing between an Effect and something else

[cols="2,2",options="header"]
|===
| Situation | Use

| The user clicked or typed | An event handler
| A value can be computed from props and state | Calculate it during render (`useMemo` if costly)
| Reset state when an id changes | A `key` on the component
| Subscribe to an external store | `useSyncExternalStore` (see xref:web/react/custom-hooks.adoc[Custom Hooks])
| Start and stop a connection, timer, listener or widget | `useEffect` with cleanup
| Measure the DOM before paint | `useLayoutEffect`
|===
