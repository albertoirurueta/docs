== What utility objects are

An _expression object_ is a name that starts with `+#+` and is available inside any variable expression, in addition to the model
variables you put in the context. Thymeleaf splits them in two groups. The _basic objects_ (`+#ctx+`, which exposes the locale, the variable names and, in a web environment, the web exchange, and
`+#locale+`) expose the evaluation context itself and are listed on the xref:web/thymeleaf/standard-expression-syntax.adoc[Standard Expression Syntax] page. The _utility objects_, which this page covers, are stateless helper
objects with a method per task: formatting a date, padding a number, testing a string, summing a list. They are the template-side
equivalent of a small standard library, and they exist so that presentation logic such as "show the date in the reader's locale" does
not have to be computed in the controller and stored in the model.

Four properties are worth knowing before the method tables:

* **They are plain method calls on a named object**, so `+${#strings.toUpperCase(name)}+` is an ordinary variable expression. Used
  inside `+*{...}+`, `+#{...}+` arguments, `+@{...}+` parameters, `+th:if+` conditions and everywhere else an expression is allowed,
  they behave the same.
* **Most families come in four shapes.** A scalar method (`+format+`), an `+array*+` variant, a `+list*+` variant and a `+set*+`
  variant that apply the same operation to every element (`+arrayFormat+`, `+listFormat+`, `+setFormat+`). The tables below name the
  scalar method and say when the other three exist, instead of repeating them.
* **They are locale-aware only where the table says so.** The locale is taken from the context (the request locale in Spring MVC and
  WebFlux, `+Context.setLocale+` standalone), so one template renders differently for `en-US` and `es-ES` without any change.
* **Their outputs are escaped like any other value.** The examples use `+th:text+`, so a `+&+` in a result is written as `+&amp;+`. A
  helper such as `+#strings.escapeXml+` therefore double-escapes when its result is passed to `+th:text+`; see the pitfalls.

The utility objects are implemented by classes in the `+org.thymeleaf.expression+` package of `thymeleaf` core, registered by the
Standard Dialect through its expression object factory. The Javadoc of each class is the authoritative method list, and Appendix B of
the _Using Thymeleaf_ tutorial is the narrative one.

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#appendix-b-expression-utility-objects[Using Thymeleaf -- Appendix B: Expression Utility Objects], https://www.thymeleaf.org/apidocs/thymeleaf/3.1.5.RELEASE/org/thymeleaf/expression/package-summary.html[Javadoc: org.thymeleaf.expression]

.Utility objects at a glance
[cols="2,3,4",options="header"]
|===
|Object |Handles |Locale-aware

|`+#execInfo+` |Template names and modes being processed |No
|`+#messages+` |Externalised messages, same lookup as `+#{...}+` |Yes
|`+#uris+` |Escaping and unescaping URI parts |No
|`+#conversions+` |The configured conversion service |Depends on the converter
|`+#dates+`, `+#calendars+` |`java.util.Date`, `java.util.Calendar` |Yes
|`+#temporals+` |`java.time` types |Yes
|`+#numbers+` |Formatting and sequences |Yes
|`+#strings+` |Text |No

|`+#arrays+`, `+#lists+`, `+#sets+`, `+#maps+`, `+#aggregates+` |Collections |No
|`+#ids+` |Unique `id` attributes inside iterations |No
|===

== The scratch application

All outputs below come from one controller that fills the model and one template with a paragraph per example. The domain is the
running Bookshelf scenario of this section, with a few extra values (a legacy `java.util.Date`, a `Calendar`, a `LocalDate`, a
`LocalDateTime` and a `ZonedDateTime`) so that every family has something to work on.

.The controller that feeds the examples
[source,java]
----
@Controller
public class UtilityController {

    @GetMapping("/util")
    public String demo(Model model) {
        model.addAttribute("title", "  the dispossessed  ");
        model.addAttribute("isbn", "978-0-06-051275-4");
        model.addAttribute("price", new BigDecimal("1234.5"));
        model.addAttribute("rating", 0.875);
        model.addAttribute("pages", 7);
        model.addAttribute("published", LocalDate.of(1974, 5, 1));
        model.addAttribute("loanedAt", LocalDateTime.of(2026, 10, 8, 14, 30, 15));
        model.addAttribute("dueAt", ZonedDateTime.of(2026, 10, 22, 9, 0, 0, 0, ZoneId.of("UTC")));
        GregorianCalendar cal = new GregorianCalendar(2026, Calendar.OCTOBER, 8, 14, 30, 15);
        cal.setTimeZone(TimeZone.getTimeZone("UTC"));
        model.addAttribute("calendar", cal);
        model.addAttribute("legacyDate", cal.getTime());
        model.addAttribute("authors", List.of("Le Guin", "Asimov", "Butler", "Asimov"));
        model.addAttribute("tags", new LinkedHashSet<>(List.of("sf", "classic")));
        model.addAttribute("stock", new LinkedHashMap<>(Map.of("dune", 3)));
        model.addAttribute("pageCounts", new int[] {300, 412, 250});
        model.addAttribute("prices", List.of(new BigDecimal("10.00"), new BigDecimal("12.50"), new BigDecimal("7.25")));
        model.addAttribute("nothing", null);
        model.addAttribute("flags", List.of(true, true, false));
        model.addAttribute("unsafeName", "Ursula K. Le Guin/Q&A #1");
        model.addAttribute("quoted", "It's a \"book\"");
        return "util/demo";
    }
}
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#expression-utility-objects[Using Thymeleaf -- Expression Utility Objects]

The message bundle used by the `+#messages+` examples has two keys with parameters, one per language:

[source,properties]
----
# messages.properties and messages_en.properties
books.title=Books
books.new=New book
books.count=The shelf holds {0} books by {1}

# messages_es.properties
books.title=Libros
books.new=Nuevo libro
books.count=La estanteria tiene {0} libros de {1}
----

Source: https://docs.spring.io/spring-boot/reference/features/internationalization.html[Spring Boot -- Internationalization]

Two Boot settings keep the outputs reproducible. By default Boot's message source falls back to the JVM's own locale when a bundle has
no entry for the requested one; `spring.messages.fallback-to-system-locale=false` turns that off, so the output depends only on the
request. The JVM default time zone decides how a `java.util.Date` is printed, so the test pins it to UTC.

== Execution information: `+#execInfo+`

`+#execInfo+` describes the template that is currently being processed. It is the one utility object with state, because the answer
changes as fragments are inserted. It has two views of the same stack: the _leaf_ template (where the events being processed were
parsed) and the _root_ template (the one the engine was originally asked to process).

[cols="3,5",options="header"]
|===
|Expression |Result

|`+${#execInfo.templateName}+`, `+${#execInfo.templateMode}+` |Name and mode of the leaf template
|`+${#execInfo.processedTemplateName}+`, `+${#execInfo.processedTemplateMode}+` |Name and mode of the root template
|`+${#execInfo.templateNames}+`, `+${#execInfo.templateModes}+` |Stacks (lists), root first and leaf last, with every inserted fragment's template in between
|`+${#execInfo.templateStack}+` |The same stack as a list of `TemplateData`, with the full metadata of each template
|===

.Leaf versus root template across a fragment insertion
[source,html]
----
<!-- util/demo.html -->
<p id="exec1" th:text="${#execInfo.templateName} + ' / ' + ${#execInfo.templateMode}">x</p>
<div th:insert="~{util/frag :: info}">x</div>
<p id="exec3" th:text="${#execInfo.templateNames}">x</p>

<!-- util/frag.html -->
<p th:fragment="info" id="exec2"
   th:text="${#execInfo.templateName} + ' in ' + ${#execInfo.processedTemplateName}">x</p>
----

[source,html]
----
<p id="exec1">util/demo / HTML</p>
<div><p id="exec2">util/frag in util/demo</p></div>
<p id="exec3">[util/demo]</p>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#execution-info[Using Thymeleaf -- Execution Info]

After the fragment has been inserted, the stack is back to the root template alone, which is why the last line prints one name. The
typical use is a debugging footer or an HTML comment showing which template produced a block.

`+#execInfo+` is one of the objects that **restricted expression mode forbids**. In a `+th:utext+` attribute (and in the other
contexts listed on the xref:web/thymeleaf/template-security-and-xss.adoc[Template Security & XSS] page) the same expression fails at runtime:

[source,text]
----
TemplateProcessingException: Access to variable '#execInfo' is forbidden in this context
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#restricted-mode-restrictions-applied[Using Thymeleaf -- Appendix D: Restricted mode, restrictions applied]

== Messages: `+#messages+`

`+#messages+` performs the same lookup as the `+#{...}+` message expression, but as a method call, so the key can be computed and the
result can be post-processed inside a larger expression.

[cols="3,5",options="header"]
|===
|Method |Behaviour

|`+msg(key)+`, `+msg(key, p1)+` up to three parameters |The message, or the placeholder `+??key_locale??+` when the key is missing
|`+msgWithParams(key, Object[])+` |Same, with any number of parameters in an array
|`+arrayMsg(keys)+`, `+listMsg(keys)+`, `+setMsg(keys)+` |Looks up a collection of keys and returns the same kind of collection of messages
|`+msgOrNull(key, ...)+`, `+msgOrNullWithParams+`, `+arrayMsgOrNull+`, `+listMsgOrNull+`, `+setMsgOrNull+` |The same family, but `null` for a missing key instead of the placeholder
|===

.Messages as method calls
[source,html]
----
<p id="msg1" th:text="${#messages.msg('books.title')}">x</p>
<p id="msg2" th:text="${#messages.msg('books.count', 3, 'Le Guin')}">x</p>
<p id="msg3" th:text="${#messages.msg('books.unknown')}">x</p>
<p id="msg4" th:text="${#messages.msgOrNull('books.unknown')} ?: 'no such key'">x</p>
<p id="msg5" th:text="${#messages.listMsg({'books.title', 'books.new'})}">x</p>
<p id="msg6" th:text="#{books.count(3, 'Le Guin')}">x</p>
----

[source,html]
----
<!-- request locale en-US -->
<p id="msg1">Books</p>
<p id="msg2">The shelf holds 3 books by Le Guin</p>
<p id="msg3">??books.unknown_en_US??</p>
<p id="msg4">no such key</p>
<p id="msg5">[Books, New book]</p>
<p id="msg6">The shelf holds 3 books by Le Guin</p>

<!-- request locale es-ES -->
<p id="msg1">Libros</p>
<p id="msg2">La estanteria tiene 3 libros de Le Guin</p>
<p id="msg3">??books.unknown_es_ES??</p>
<p id="msg4">no such key</p>
<p id="msg5">[Libros, Nuevo libro]</p>
<p id="msg6">La estanteria tiene 3 libros de Le Guin</p>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#messages-1[Using Thymeleaf -- Messages (utility object)], https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#messages[Using Thymeleaf -- Messages]

`msgOrNull` is the way to give a missing key a real fallback. The `+#{...}+` syntax is shorter for a fixed key and is preferred
there; `+#messages+` is for the cases where the key itself is an expression or a collection of keys. The xref:web/thymeleaf/internationalization.adoc[Internationalization] and
xref:web/thymeleaf/validation-and-error-messages.adoc[Validation & Error Messages] pages go deeper into bundles and the Spring `MessageSource`.

== URIs: `+#uris+`

`+#uris+` escapes and unescapes text for use in each part of a URI. The part matters because the set of characters that must be
percent-encoded differs between a path, a path segment, a query parameter and a fragment identifier. Every method has an overload that takes the character encoding as a second argument.

[cols="3,5",options="header"]
|===
|Methods |Escapes for

|`+escapePath+`, `+unescapePath+` |A whole URI path (the `+/+` separators are kept)
|`+escapePathSegment+`, `+unescapePathSegment+` |One segment between slashes (a `+/+` is encoded)
|`+escapeFragmentId+`, `+unescapeFragmentId+` |The fragment identifier after `+#+`
|`+escapeQueryParam+`, `+unescapeQueryParam+` |A query parameter name or value (`+&+` and `+=+` are encoded)
|===

.The four escapers applied to the same text
[source,html]
----
<p id="uri1" th:text="${#uris.escapePath(unsafeName)}">x</p>
<p id="uri2" th:text="${#uris.escapePathSegment(unsafeName)}">x</p>
<p id="uri3" th:text="${#uris.escapeQueryParam(unsafeName)}">x</p>
<p id="uri4" th:text="${#uris.escapeFragmentId(unsafeName)}">x</p>
<p id="uri5" th:text="${#uris.unescapeQueryParam('Le%20Guin%26Co')}">x</p>
<a id="uri6" th:href="@{/search(q=${unsafeName})}">x</a>
----

[source,html]
----
<p id="uri1">Ursula%20K.%20Le%20Guin/Q&amp;A%20%231</p>
<p id="uri2">Ursula%20K.%20Le%20Guin%2FQ&amp;A%20%231</p>
<p id="uri3">Ursula%20K.%20Le%20Guin/Q%26A%20%231</p>
<p id="uri4">Ursula%20K.%20Le%20Guin/Q&amp;A%20%231</p>
<p id="uri5">Le Guin&amp;Co</p>
<a id="uri6" href="/search?q=Ursula%20K.%20Le%20Guin/Q%26A%20%231">x</a>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#urisurls[Using Thymeleaf -- URIs/URLs]

Compare the first four lines: only `escapePathSegment` encodes the slash, and only `escapeQueryParam` encodes the `&`. (The `&amp;` in
the first, second and fourth outputs is the HTML escaping that `th:text` applies to a literal `&`; the URI escaper left it alone.)
The last line shows the better habit: a link expression `+@{/search(q=${unsafeName})}+` encodes its parameters for you. Use
`+#uris+` for the cases a link expression cannot cover, such as building a value for a `data-*` attribute or an `hx-get` target
string; never concatenate raw user input into a URL. The link expressions and URL rewriting are covered on the xref:web/thymeleaf/link-urls.adoc[Link URLs] page.

== Conversions: `+#conversions+`

`+#conversions+` runs the engine's conversion service at any point of a template, with one method, `+convert(object, targetClass)+`.
The target may be a `Class` or a class name given as a string. In a Spring application the service is the Spring `ConversionService`
(it is the same one that formats `+${{...}}+`), so every converter and formatter the application registered is available, including the formatters Boot registers for `java.time`.

.Converting with the Spring conversion service
[source,html]
----
<p id="conv1" th:text="${#conversions.convert('42', 'java.lang.Integer') + 1}">x</p>
<p id="conv2" th:text="${#conversions.convert('2026-10-08', 'java.time.LocalDate')}">x</p>
<p id="conv3" th:text="${{published}}">x</p>
----

[source,html]
----
<!-- en-US -->
<p id="conv1">43</p>
<p id="conv2">2026-10-08</p>
<p id="conv3">5/1/74</p>

<!-- es-ES -->
<p id="conv3">1/5/74</p>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/thymeleafspring.html#conversions-utility-object[Thymeleaf + Spring -- The #conversions utility object], https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#conversions[Using Thymeleaf -- Conversions]

The first line shows that the result is a real `Integer` (it can be added to); the third shows the double-brace form for contrast, whose
output follows the request locale. Standalone, without Spring, the service is Thymeleaf's own standard one, which knows far fewer
conversions; the xref:web/thymeleaf/conversion-and-formatting.adoc[Conversion & Formatting] page compares them.

== Dates and calendars: `+#dates+` and `+#calendars+`

`+#dates+` works on `java.util.Date` and `+#calendars+` on `java.util.Calendar`. The two have identical method names. The legacy
types remain in use in JPA entities, older libraries and `java.sql` values; for new code the model should carry `java.time` values
and the next section applies.

[cols="3,5",options="header"]
|===
|Methods (the four shapes exist for all of them) |Result

|`+format(d)+` |Date and time in the standard format of the context locale
|`+format(d, pattern)+` |Formatted with a `java.text.SimpleDateFormat`-style pattern
|`+formatISO(d)+` |ISO-8601 text
|`+day+`, `+month+`, `+year+`, `+hour+`, `+minute+`, `+second+`, `+millisecond+` |The numeric component
|`+monthName+`, `+monthNameShort+`, `+dayOfWeek+`, `+dayOfWeekName+`, `+dayOfWeekNameShort+` |The component as a number or as locale-aware text
|`+create(y, m, d)+` and the overloads with hour, minute, second and millisecond |A new `Date` (or `Calendar`); the month is **1 to 12**
|`+createNow()+`, `+createToday()+` (time 00:00) and `+createNowForTimeZone()+`, `+createTodayForTimeZone()+` |The current instant or day
|`+#calendars.createForTimeZone(...)+` |Same creation overloads with a trailing `TimeZone` (calendars only)
|===

.Formatting and decomposing a Date and a Calendar
[source,html]
----
<p id="d1" th:text="${#dates.format(legacyDate)}">x</p>
<p id="d2" th:text="${#dates.format(legacyDate, 'dd/MMM/yyyy HH:mm')}">x</p>
<p id="d3" th:text="${#dates.formatISO(legacyDate)}">x</p>
<p id="d4" th:text="${#dates.year(legacyDate)} + ' ' + ${#dates.monthName(legacyDate)} + ' ' + ${#dates.dayOfWeekName(legacyDate)}">x</p>
<p id="d5" th:text="${#dates.format(#dates.create(2026, 12, 25), 'yyyy-MM-dd')}">x</p>
<p id="c1" th:text="${#calendars.format(calendar, 'dd/MMM/yyyy HH:mm')}">x</p>
<p id="c2" th:text="${#calendars.formatISO(calendar)}">x</p>
<p id="c3" th:text="${#calendars.monthName(calendar)} + ' ' + ${#calendars.dayOfWeekNameShort(calendar)}">x</p>
----

[source,html]
----
<!-- en-US -->
<p id="d1">October 8, 2026, 2:30:15 PM UTC</p>
<p id="d2">08/Oct/2026 14:30</p>
<p id="d3">2026-10-08T14:30:15.000+00:00</p>
<p id="d4">2026 October Thursday</p>
<p id="d5">2026-12-25</p>
<p id="c1">08/Oct/2026 14:30</p>
<p id="c2">2026-10-08T14:30:15.000+00:00</p>
<p id="c3">October Thu</p>

<!-- es-ES -->
<p id="d1">8 de octubre de 2026, 14:30:15 UTC</p>
<p id="d2">08/oct/2026 14:30</p>
<p id="d4">2026 octubre jueves</p>
<p id="c3">octubre jue</p>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#dates[Using Thymeleaf -- Dates], https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#calendars[Using Thymeleaf -- Calendars]

The default `format(d)` output follows the request locale ("October 8, 2026, ..." in English, "8 de octubre de 2026, ..." in Spanish). Because the JVM's default
time zone is used to print a `Date`, two servers in different zones show different wall-clock text for the same instant; set the zone
explicitly (a `TimeZone` on the JVM, or the zoned methods of the next section) when the output must be stable.

== Temporals: `+#temporals+` (java.time)

`+#temporals+` is the `java.time` counterpart of `+#dates+`: it formats `LocalDate`, `LocalDateTime`, `LocalTime`, `ZonedDateTime`,
`OffsetDateTime`, `Instant` and the other `Temporal` types. It is part of `thymeleaf` core **since Thymeleaf 3.1**. Before 3.1 it
lived in the separate `thymeleaf-extras-java8time` module (last release 3.0.4), which is still found in older articles and in the
books; a 3.1 project does not need it and should not declare it.

[cols="3,5",options="header"]
|===
|Methods (the four shapes exist for the formatters and getters) |Result

|`+format(t)+`, `+format(t, locale)+` |The default locale format (a medium style for dates and date-times)
|`+format(t, pattern)+`, `+format(t, pattern, locale)+` |A `DateTimeFormatter` pattern, or one of the style names `SHORT`, `MEDIUM`, `LONG`, `FULL`
|`+format(t, pattern, zoneId)+` |The value converted to the given time zone before formatting
|`+formatISO(t)+` |ISO-8601 text
|`+day+`, `+month+`, `+year+`, `+hour+`, `+minute+`, `+second+`, `+nanosecond+` |The numeric component
|`+monthName+`, `+monthNameShort+`, `+dayOfWeek+`, `+dayOfWeekName+`, `+dayOfWeekNameShort+` |Number or locale-aware text
|`+create(y, m, d)+` |A `LocalDate`; the overloads with time components return a `LocalDateTime`
|`+createNow()+`, `+createNowForTimeZone(zoneId)+`, `+createToday()+`, `+createTodayForTimeZone(zoneId)+` |`LocalDateTime`, `ZonedDateTime` or `LocalDate` as named
|`+createDate(iso)+`, `+createDateTime(iso)+`, with an optional pattern as a second argument |Parse text into a `LocalDate` or `LocalDateTime`
|===

.Formatting java.time values, with a zone and with the context locale
[source,html]

<p id="t1" th:text="${#temporals.format(published)}">x</p>
<p id="t2" th:text="${#temporals.format(loanedAt, 'dd MMMM yyyy HH:mm')}">x</p>
<p id="t3" th:text="${#temporals.format(loanedAt, 'FULL')}">x</p>
<p id="t5" th:text="${#temporals.format(dueAt, 'dd/MM/yyyy HH:mm', 'Europe/Paris')}">x</p>
<p id="t6" th:text="${#temporals.dayOfWeekName(published)} + ' ' + ${#temporals.monthNameShort(published)} + ' ' + ${#temporals.year(published)}">x</p>
<p id="t7" th:text="${#temporals.create(2026, 12, 25)}">x</p>
<p id="t8" th:text="${#temporals.createDate('2026-10-08')}">x</p>
<p id="t9" th:text="${#temporals.createDate('08/10/2026', 'dd/MM/yyyy').dayOfYear}">x</p>

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#temporals-java.time[Using Thymeleaf -- Temporals (java.time)], https://www.thymeleaf.org/apidocs/thymeleaf/3.1.5.RELEASE/org/thymeleaf/expression/Temporals.html[Javadoc: Temporals]

== Numbers: `+#numbers+`

`+#numbers+` formats integers, decimals, currency and percentages with the context locale, and generates integer sequences. The
formatting methods all have the four shapes (`+formatInteger+`, `+arrayFormatInteger+`, `+listFormatInteger+`, `+setFormatInteger+`).

[cols="3,5",options="header"]
|===
|Method |Result

|`+formatInteger(n, minIntDigits)+`, with an optional thousands separator |Integer, padded with zeros to a minimum number of digits
|`+formatDecimal(n, minIntDigits, decimalDigits)+` |Decimal with an exact number of fraction digits
|`+formatDecimal(n, minInt, decimalDigits, decimalSep)+` and `+formatDecimal(n, minInt, thousandsSep, decimalDigits, decimalSep)+` |Same, choosing separators
|`+formatCurrency(n)+`, `+formatCurrency(n, currency)+` |Locale currency format
|`+formatPercent(n)+`, `+formatPercent(n, minIntDigits, decimalDigits)+` |Percentage; the input is the fraction (0.875 is 87.5%)
|`+sequence(from, to)+`, `+sequence(from, to, step)+` |An `Integer` array, for `th:each`
|===

The separator names accepted by the formatters are `POINT`, `COMMA`, `WHITESPACE`, `NONE` and `DEFAULT` (take the locale's own).

.Numbers in the locale of the request
[source,html]
----
<p id="n1" th:text="${#numbers.formatInteger(pages, 3)}">x</p>
<p id="n2" th:text="${#numbers.formatInteger(1234567, 1, 'POINT')}">x</p>
<p id="n3" th:text="${#numbers.formatDecimal(price, 1, 2)}">x</p>
<p id="n4" th:text="${#numbers.formatDecimal(price, 1, 'WHITESPACE', 2, 'COMMA')}">x</p>
<p id="n5" th:text="${#numbers.formatCurrency(price)}">x</p>
<p id="n6" th:text="${#numbers.formatPercent(rating, 1, 1)}">x</p>
<p id="n7" th:text="${#numbers.listFormatDecimal(prices, 2, 2)}">x</p>
<ul id="n8"><li th:each="i : ${#numbers.sequence(1, 5)}" th:text="${i}">x</li></ul>
<p id="n9" th:text="${#strings.arrayJoin(#numbers.sequence(0, 10, 5), ',')}">x</p>
----

<p id="n4">1 234,50</p>

turns `&lt;` into `&amp;lt;`. The escaping helpers are for the rare case where the target is not an HTML text node, such as building
a string for an attribute that `th:attr` will write without further processing; for JavaScript values the safer tool is JavaScript
inlining, described on the xref:web/thymeleaf/inlining.adoc[Inlining] page.

== Objects and booleans: `+#objects+` and `+#bools+`

`+#objects+` has one job, null safety: `+nullSafe(obj, default)+` returns the default when the object is `null`, with
`+arrayNullSafe+`, `+listNullSafe+` and `+setNullSafe+` to replace the null elements of a collection. In an expression the Elvis
operator `+?:+` often reads better for a single value; `+nullSafe+` earns its place in the collection variants.

`+#bools+` evaluates values as booleans (it accepts, for example, the string `"true"`) and adds aggregate checks:

[cols="3,5",options="header"]
|===
|Methods |Result

|`+isTrue(x)+`, `+isFalse(x)+` (and `array`, `list`, `set` variants) |Whether the value evaluates to true or to false
|`+arrayAnd+`, `+listAnd+`, `+setAnd+` |`true` when **all** elements are true
|`+arrayOr+`, `+listOr+`, `+setOr+` |`true` when **any** element is true
|===

.Null safety and aggregate booleans
[source,html]
----
<p id="o1" th:text="${#objects.nullSafe(nothing, 'fallback')}">x</p>
<p id="o2" th:text="${#objects.listNullSafe({'a', null}, 'z')}">x</p>
<p id="b1" th:text="${#bools.isTrue('true')} + ' ' + ${#bools.isFalse(false)}">x</p>
<p id="b2" th:text="${#bools.listAnd(flags)} + ' ' + ${#bools.listOr(flags)}">x</p>
----

[source,html]
----

<p id="o2">[a, z]</p>

<p id="b2">false true</p>

== Unique identifiers: `+#ids+`

Inside an iteration the same `id` would be repeated for every row, which makes HTML invalid and breaks `<label for>`. `+#ids+`
solves that by keeping a counter per name:

* `+${#ids.seq('copy')}+` returns the name followed by the next counter value (`copy1`, `copy2`, ...), for `th:id`.
* `+${#ids.next('copy')}+` returns the identifier the next `seq` call will produce, for a `<label>` written **before** its input.
* `+${#ids.prev('copy')}+` returns the identifier the last `seq` call produced, for a `<label>` written **after** its input.

.Checkbox list with matching labels, and the label-first order
[source,html]
----
<ul id="ids1">
  <li th:each="a : ${authors}">
    <input type="checkbox" th:id="${#ids.seq('author')}">
    <label th:for="${#ids.prev('author')}" th:text="${a}">x</label>
  </li>
</ul>
<div id="ids2"><label th:for="${#ids.next('copy')}">Copy</label><input th:id="${#ids.seq('copy')}"></div>
----

[source,html]
----
<li>
  <input type="checkbox" id="author1">
  <label for="author1">Le Guin</label>
</li>
<li>
  <input type="checkbox" id="author2">
  <label for="author2">Asimov</label>
</li>
<div id="ids2"><label for="copy1">Copy</label><input id="copy1"></div>
----

Source: https://www.thymeleaf.org/doc/tutorials/3.1/usingthymeleaf.html#ids[Using Thymeleaf -- IDs]

The _Thymeleaf + Spring_ tutorial uses the same two methods in forms, where `th:field` generates the ids of repeated checkboxes and radio buttons and the label is paired with `+#ids.prev+` or `+#ids.next+`; the xref:web/thymeleaf/forms-and-data-binding.adoc[Forms & Data Binding] page shows that pairing.

== Additions from the Spring integration: `+#fields+`, `+#mvc+`, `+#themes+`

When Thymeleaf is used through `thymeleaf-spring6` (Spring MVC and WebFlux) the `SpringStandardDialect` replaces OGNL with Spring EL
and registers three more expression objects. They are not available in a standalone engine.

[cols="2,6",options="header"]
|===
|Object |What it does

|`+#fields+` |Form-binding errors. `+hasErrors('field')+`, `+hasErrors()+`, `+hasAnyErrors()+`, `+hasGlobalErrors()+`, `+errors('field')+`, `+errors()+`, `+allErrors()+`, `+globalErrors()+`, `+detailedErrors()+`, `+detailedErrors('field')+`, `+allDetailedErrors()+`, `+globalDetailedErrors()+` and `+idFromName(name)+`. |`+#mvc+` |`+#mvc.url('UC#demo')+` starts a builder for a link to a controller method, equivalent to the JSP `spring:mvcUrl` function; `+.arg(index, value)+` supplies a method argument and `+.build()+` produces the URL
|`+#themes+` |`+#themes.code('key')+`, equivalent to the `spring:theme` JSP tag
|===

<p id="mvc1" th:text="${#mvc.url('UC#demo').build()}">x</p>

<p id="f2">true</p>

switching.

== Where utility objects run, and restricted mode

Utility objects run during the _processing_ phase, when the engine evaluates the attribute that holds the expression. They need no
preprocessing, and a template that uses them stays a natural template: the static prototype keeps the placeholder text
(`<p th:text="${#temporals.format(published)}">May 1, 1974</p>`) and the server replaces it with the computed value.

Most utility objects are also allowed in **restricted expression mode**, the stricter evaluation used for `th:utext`, preprocessing
`+__...__+`, `+th:on*+` handlers, fragment names and URL bases (Appendix D of the tutorial lists the contexts). In the scratch run,
`+#strings.toUpperCase(name)+` and `+#uris.escapePath(name)+` evaluate normally inside `th:utext`, but `+#execInfo+` is rejected
there, as shown above. The rule of thumb is that restricted mode forbids objects that expose the engine's internals, request
parameters, static access, object instantiation and Spring bean references, and leaves pure value helpers alone. Restricted mode is
defence in depth and does not replace validating data; the xref:web/thymeleaf/template-security-and-xss.adoc[Template Security & XSS] page treats it fully.

== Version notes and where the books are outdated

* **`#temporals` in core.** Since Thymeleaf 3.1 `+#temporals+` is part of core. Material for 3.0 (older articles and the books)
  asks for `thymeleaf-extras-java8time`; that module is frozen at 3.0.4 and is not needed with Thymeleaf 3.1 or Spring Boot 4.
* **Removed request-related basic objects.** Thymeleaf 3.1 removed the servlet-bound `+#request+`, `+#response+`, `+#session+` and
  `+#servletContext+` expression objects, and the `+${execInfo}+` variable form. The utility objects of this page are unaffected;
  `+#execInfo+` with the `#` is the current spelling. See the xref:web/thymeleaf/whats-changed-and-migration.adoc[What's Changed & Migration] page.
* **Package and module names.** In the Spring integration the classes behind `+#fields+`, `+#mvc+` and `+#themes+` live in
  `org.thymeleaf.spring6.expression`, in `thymeleaf-spring6`; there is no `thymeleaf-spring7` artifact, and Spring Boot 4.1.1 uses
  `thymeleaf-spring6`.
* **Books.** The _Modern frontends with htmx_ chapter on out-of-band swaps formats dates in a weekly view with `+#temporals.format+`. The call is the same today, and on Thymeleaf 3.1 it needs no extra dependency; pass `+#locale+` (or a pattern with a locale) when weekday and month names must follow the reader, as shown above.

== Pitfalls

.Common mistakes with utility objects
[cols="3,4,4",options="header"]
|===
|Mistake |What happens |Fix

|`+#dates.format(localDate)+` on a `java.time` value |`+SpelEvaluationException: Method format(java.time.LocalDate) cannot be found on type org.thymeleaf.expression.Dates+` |Use `+#temporals+` for `java.time`
|`+#temporals.format(legacyDate)+` on a `java.util.Date` |The mirror error: no `format(java.util.Date)` on `Temporals` |Use `+#dates+`, or convert in the controller
|`+#lists.size(nullList)+` |`+IllegalArgumentException: Cannot get list size of null+` |Guard with `+${list != null}+` or use `+#lists.isEmpty+`, which is null-safe
|Formatters on `null` (`+#temporals.format(null)+`, `+#numbers.formatDecimal(null, 1, 2)+`, `+#strings.toUpperCase(null)+`) |Render an empty string, no error |Intended; add `+?:+` or `+th:if+` when an empty cell is wrong
|`+#dates.create(2026, 13, 1)+` |No error: a lenient calendar rolls the month over into January 2027 |Validate inputs; months are 1 to 12
|`+#messages.msg('missing')+` |`+??missing_en_US??+` appears in the page |Use `+msgOrNull+` with a fallback, and test bundles
|`+#strings.escapeXml(x)+` inside `th:text` |Double-escaped text such as `+&amp;lt;+` |Drop the helper; `th:text` already escapes
|`+#numbers.formatCurrency+` with a language-only locale such as `en` |A generic currency sign instead of `$` |Provide a region (`en-US`) or pass the currency argument
|Hand-built URLs with `+#uris+` and `+'/path/' + value+` |Easy to miss an escaper for the right URI part |Use `+@{/path/{id}(id=${value})}+`
|`+#execInfo+` in `th:utext` or `+th:on*+` |`+Access to variable '#execInfo' is forbidden in this context+` |Compute it in the controller, or move it to `th:text`
|`+#fields+` or `+#mvc+` in a standalone engine |The expression object does not exist |They come from `SpringStandardDialect`; do the work in the model instead
|`+#themes+` on Spring Framework 7 |No theme source is available |Drop theme usage
|===
