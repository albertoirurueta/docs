== What Thymeleaf is

Thymeleaf is a server-side Java template engine for web and standalone environments. Its defining idea is the
_natural template_: a template is a valid HTML file that a browser can open directly as a static prototype, and that
Thymeleaf turns into a dynamic page by evaluating attributes such as `th:text` and `th:each` on the server. Because the
dynamic logic lives in attributes the browser ignores, designers and developers can work on the same files.

A single engine provides:

* six template modes (HTML, XML, TEXT, JAVASCRIPT, CSS and RAW), template resolvers, a context, and parsed-template and
  expression caches
* the Standard Dialect and its Spring flavour, the SpringStandard Dialect, built from attribute, element and model
  processors, with the Standard Expression language (`+${...}+`, `+*{...}+`, `+#{...}+`, `+@{...}+`, `+~{...}+`) and a
  family of utility objects
* fragments and, through the community Layout Dialect, layout inheritance
* inlining for text, JavaScript and CSS, and the textual template modes for emails and generated files
* integration with Spring MVC and Spring WebFlux, Spring Security (`sec:*` attributes), Spring's conversion,
  validation and message infrastructure
* an extension model for your own dialects and processors

This section is for developers who:

* know Java and want to build server-rendered web applications on Spring Boot, with forms, validation, security,
  internationalization and a maintainable layout system
* want interactive pages without a single-page application, using fragment rendering, htmx and Alpine.js
* learned Thymeleaf from older books and tutorials (Spring Boot 2, Thymeleaf 3.0, htmx 1) and need the current idioms
* are choosing between Thymeleaf and Vaadin, JSF or the template engines of other stacks, and want the trade-offs

== The Bookshelf scenario

Every example builds one small original application, _Bookshelf_, in the same domain as the
xref:web/django/index.adoc[Django], xref:web/php-laravel/index.adoc[PHP and Laravel] and
xref:web/nextjs/index.adoc[Next.js] sections, so that the stacks can be compared page by page. Here it is a
Spring Boot 4.1 and Thymeleaf application, the first Java implementation of the scenario:

* a public catalogue of books, authors and reviews with pagination, sorting and search
* a shared layout with header, navigation, flash messages and footer, and reusable fragment components
* create, edit and delete forms with Bean Validation, conversion, cover-image upload and dynamic rows
* English and Spanish internationalization with a locale switcher
* sign-in with Spring Security (form login, the roles `READER` and `LIBRARIAN`), `sec:*` attributes and CSRF
* an htmx-enhanced version: active search, click to load, inline editing, delete with confirmation, out-of-band
  counters, inline validation and Server-Sent Events notifications
* loan-reminder emails rendered from HTML and text templates
* an optional WebFlux variant of the catalogue
* tests with `@WebMvcTest`, HtmlUnit and end-to-end tools, Tailwind CSS v4 styling and a container deployment

.The Bookshelf application: browser, security filters, Spring MVC controller, service, repository, database, Thymeleaf view layer and static resources
image::thymeleaf-bookshelf-architecture.svg["Diagram of the Bookshelf application. The browser sends full page requests, form posts and htmx partial requests through the Spring Security filters (form login, CSRF token, roles) to a Spring MVC controller, which binds and validates input and calls a service. The service uses a Spring Data JPA repository that reads and writes the database. The controller fills the model and returns a view name, or a fragment name for htmx, to the Thymeleaf view layer, which renders the templates and returns the HTML response to the browser. Static resources such as CSS, htmx, Alpine.js and images are served separately.",width=100%]

The final project layout (`src/main/java` packages for `book`, `author`, `review`, `security` and `web`, and
`src/main/resources/templates` folders for `layout`, `fragments`, `books`, `authors`, `reviews`, `error` and `mail`) is
assembled on xref:web/thymeleaf/getting-started.adoc[Getting Started].

== Reading path

The pages are ordered so that each one builds on the previous ones. Read them in this order the first time, then use
them as a reference. Before starting, be comfortable with the language and the framework underneath:
the xref:programming-languages/java/index.adoc[Java Reference] for records, streams and `java.time`, and the
xref:backend/springboot/index.adoc[SpringBoot Reference] for dependency injection, auto-configuration, Spring Data and
Spring Security.

. *Foundations*: what Thymeleaf is, a first Spring Boot project, standalone use and the auto-configuration.
. *Core template language*: expressions, operators, utility objects, text and attributes, iteration, variables, links,
  inlining, textual modes and natural templates.
. *Fragments and layouts*: reuse of markup, the Layout Dialect and a component library.
. *Spring MVC*: controllers and views, forms, validation, conversion, internationalization, pagination and errors.
. *Security*: Spring Security integration, then escaping, restricted mode and the security advisories.
. *Dynamic and interactive pages*: fragment rendering, htmx, Alpine.js, push updates and reactive rendering.
. *Assets and other outputs*: styling, front-end assets and emails.
. *Quality, extension and operations*: testing, custom dialects, performance, tooling and migration.
