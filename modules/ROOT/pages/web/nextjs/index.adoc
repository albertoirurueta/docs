This section is written against Next.js 16.3 (16.3.8 was the latest release on 2026-10-03, when every version, URL
and example in the section was checked, and the official documentation reported `@doc-version` 16.3.8), React 19.3
(19.3.0), Node.js 20.9 or later and TypeScript 5.1 or later. It describes the **App Router** as the primary model and
the **Pages Router** wherever an existing application still uses it. Two caching models coexist in 16.3: the
**previous model** (the default) and the opt-in **Cache Components** model (`cacheComponents: true`); every page that
touches caching says which one each example uses.

Next.js publishes one major version a year and gives each one a long-term support life cycle. On 2026-10-03 the
https://nextjs.org/support-policy[support policy] listed Next.js 16.x (released 2025-10-21) as **Active LTS** --
new features, bug fixes and security patches until Next.js 17 ships -- and Next.js 15.x (released 2024-10-21) as
**Maintenance LTS**, which receives only critical bug fixes and security updates, as semver-minor releases, for two
years from its first release; 14.x and older are unsupported. Patch releases are frequent, and several of them in
2026 were security releases, so pin an exact version and read the release notes before updating. The
xref:web/nextjs/introduction-and-architecture.adoc#release-cadence[Release Cadence and Support Policy] section and the
xref:web/nextjs/whats-changed-and-upgrading.adoc[What's Changed & Upgrading] page cover the details.

== What Next.js is

Next.js is an open-source React framework, maintained by Vercel and developed in the open on GitHub, for building
full-stack web applications. React describes the user interface as components; Next.js supplies everything around
them that a production site needs:

* file-system routing: the **App Router** (`app/`, recommended) built on React Server Components, with the older
  **Pages Router** (`pages/`) still supported
* React Server Components, Client Components and Server Functions (Server Actions)
* every rendering strategy -- server-side rendering, client-side rendering, static site generation, incremental static
  regeneration and Partial Prerendering -- with streaming and hydration
* a multi-layer cache with explicit revalidation APIs
* Route Handlers for HTTP APIs, and Proxy (called Middleware before Next.js 16) in front of every request
* image, font and script optimisation, and the Metadata API for SEO
* Turbopack, the default bundler since Next.js 16, and the React Compiler
* deployment to a Node.js server, a Docker container, static hosting, or a platform through an adapter

A new project is one command away:

[source,bash]
----
npx create-next-app@latest bookshelf --yes
cd bookshelf
npm run dev
----

Source: https://nextjs.org/docs/app/getting-started/installation[Installation]

=== Who this section is for

The section is for developers who already know React and want to build and ship React applications with Next.js:

* React developers moving from a client-only single-page application (for example a Vite SPA with React Router) to
  server rendering, static generation and React Server Components
* readers of older Next.js books and tutorials, which mostly target the Pages Router and Next.js 12 or 13, who need to
  know what changed (async request APIs, `proxy.ts`, Turbopack, the new caching APIs, Auth.js v5)
* back-end developers on this site's FastAPI, NestJS or Django sections who want a front end for the same _Bookshelf_
  API, and teams choosing between Next.js and other React or non-React frameworks

It does not re-teach React itself: components, Hooks, Suspense, Actions and the React Compiler are covered in the
xref:web/react/index.adoc[React Reference], and the pages here link there instead of repeating it.

== The Bookshelf scenario

Every example builds one small, original application, _Bookshelf_: a Next.js App Router front end in the same domain
as the xref:backend/fastapi/index.adoc[Python FastAPI], xref:backend/nestjs/index.adoc[NestJS] and
xref:web/django/index.adoc[Django] sections, so that the stacks can be compared page by page. It extends the
Next.js files sketched on xref:backend/nestjs/nestjs-vs-nextjs.adoc[NestJS vs Next.js] and has:

* a public catalogue of `books`, `authors` and `reviews`: statically generated book pages (`generateStaticParams`
  with ISR or `'use cache'`), a server-rendered search page that reads `searchParams`, and client-side filters
* a personalised header and a "my reviews" area, rendered dynamically from `cookies()` and streamed with Suspense
* review creation and editing with Server Actions, `useActionState`, `useOptimistic` and `updateTag`
* an intercepted-route modal for book covers and a parallel-route slot
* sign-in with Auth.js v5, a Data Access Layer, and `forbidden()` / `unauthorized()`
* a JSON API built with Route Handlers, plus a backend-for-frontend variant that proxies the FastAPI, NestJS or Django
  _Bookshelf_ API
* `proxy.ts` for locale detection (`app/[locale]`) and an optimistic authentication check
* `next/image` covers, `next/font`, Tailwind CSS v4, and the Metadata API with Open Graph images, a sitemap and
  `robots.txt`
* tests with Vitest and Playwright
* a Docker `standalone` deployment, and a static-export variant of the catalogue

.The Bookshelf application: clients, the Next.js server and its backing services
image::nextjs-bookshelf-architecture.svg["Diagram titled Bookshelf: the Next.js App Router front end built across this section. Three kinds of client sit at the top: the browser (HTML first paint, then hydration; Client Components, Link and the router cache), crawlers and link previews (sitemap.ts, robots.ts, metadata and Open Graph images) and API clients (curl and mobile apps calling GET /api/books). == Reading path

Read the xref:web/react/index.adoc[React Reference] first if components, props, state, effects, Hooks and Suspense
are new; in particular xref:web/react/server-rendering.adoc[Server Rendering, SSG and React Server Components]
explains the React primitives that Next.js automates. Then read this section in order the first time, and use it as a
reference afterwards:

. *Foundations*: what a React framework adds, a first project, the project structure, and configuration,
  TypeScript and environment variables.
. *Routing*: the file-system router, layouts and special files, dynamic routes and route groups, linking and
  navigation, parallel and intercepting routes, redirects, rewrites and Proxy, and internationalisation.
. *Rendering*: the rendering model, Server and Client Components, server-side rendering, streaming, client-side
  rendering, static site generation, incremental static regeneration, hydration, and Partial Prerendering with Cache
  Components.
. *Data*: data fetching, Server Actions and mutations, caching, and Route Handlers with the backend-for-frontend
  pattern.
. *UI and optimisations*: styling, images, fonts and scripts, metadata and SEO, and performance.
. *Security and authentication*: authentication and authorisation, then data security and Content Security Policy.
. *Tooling, testing and operations*: Turbopack and the compiler, testing, and debugging, instrumentation and
  observability.
. *Production*: deployment and self-hosting, the Pages Router, and what changed and how to upgrade.
. *Beyond the basics*: advanced patterns.

Readers who know Next.js from older books or tutorials can start with
xref:web/nextjs/whats-changed-and-upgrading.adoc[What's Changed & Upgrading] and then jump to the topics they use.
The xref:web/nextjs/cheat-sheet.adoc[React + Next.js Cheat Sheet] condenses React and Next.js onto one printable page.
