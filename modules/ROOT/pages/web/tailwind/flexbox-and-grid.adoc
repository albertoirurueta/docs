= Flexbox and Grid
:description: Tailwind CSS v4 flexbox and grid utilities -- flex containers and items, flex-basis, grow and shrink, order, grid template columns and rows, spans and lines, auto tracks, gap, and box alignment for both layouts.
:keywords: Tailwind CSS flexbox, Tailwind grid, flex-direction, flex-wrap, flex-basis, grow, shrink, order, grid-cols, grid-rows, col-span, row-span, grid-flow, auto-cols, gap, justify-content, justify-items, place-content, align-items, self

include::partial$ai-disclaimer.adoc[]

Flexbox and CSS Grid share one set of *box-alignment* utilities in Tailwind and differ only in how tracks are
declared. This page covers both. For the underlying CSS model -- main vs. cross axis, the grid formatting
context, implicit tracks -- see xref:web/html-css/layout.adoc[].

== Flex container

`flex` (or `inline-flex`) starts a flex formatting context.
https://tailwindcss.com/docs/flex-direction[flex-direction] is `flex-row`, `flex-row-reverse`, `flex-col`,
`flex-col-reverse`. https://tailwindcss.com/docs/flex-wrap[flex-wrap] is `flex-wrap`, `flex-wrap-reverse`,
`flex-nowrap`.

[source,html]
----
<div class="flex flex-col gap-4 md:flex-row md:flex-wrap">
  <div class="...">1</div>
  <div class="...">2</div>
  <div class="...">3</div>
</div>
----

== Flex items

https://tailwindcss.com/docs/flex[flex] bundles `flex-grow`, `flex-shrink`, and `flex-basis`: `flex-1`
(`1 1 0%`), `flex-auto` (`1 1 auto`), `flex-initial` (`0 1 auto`), `flex-none` (`none`).
https://tailwindcss.com/docs/flex-basis[flex-basis] sets just the basis: `basis-0`, `basis-64`, `basis-1/2`,
`basis-full`, the `+--container-*+` scale (`basis-3xs` ... `basis-7xl`), or an arbitrary `basis-[30ch]`.

https://tailwindcss.com/docs/flex-grow[flex-grow] and https://tailwindcss.com/docs/flex-shrink[flex-shrink]:
in Tailwind v4 the classes are `grow`, `grow-0`, `shrink`, `shrink-0` (plus numeric `grow-2`, `shrink-2` and
arbitrary values). The v3 `+flex-grow-*+` / `+flex-shrink-*+` names were **removed** in v4 -- see
https://tailwindcss.com/docs/upgrade-guide#removed-deprecated-utilities[the upgrade guide] -- so use the short
forms. https://tailwindcss.com/docs/order[order] is `order-1` ...
`order-12`, `order-first`, `order-last`, `order-none`, and negative `-order-1`.

[source,html]
----
<div class="flex gap-4">
  <aside class="basis-64 shrink-0">fixed-ish sidebar</aside>
  <main class="grow">fills the rest</main>
</div>

<div class="flex">
  <div class="flex-1">equal</div>
  <div class="flex-1">equal</div>
  <div class="flex-none order-first">pinned to the start</div>
</div>
----

== Grid

https://tailwindcss.com/docs/grid-template-columns[grid-template-columns] --
https://tailwindcss.com/docs/grid-template-rows[grid-template-rows] give `grid-cols-1` ... `grid-cols-12`,
`grid-cols-none`, `grid-cols-subgrid`, and arbitrary track lists like `grid-cols-[24rem_2fr]` or
`grid-rows-[auto_1fr_auto]`. Place items with https://tailwindcss.com/docs/grid-column[grid-column]
(`col-span-3`, `col-span-full`, `col-start-2`, `col-end-4`, `-col-start-1`) and
https://tailwindcss.com/docs/grid-row[grid-row] (`row-span-2`, `row-start-1`, `row-end-3`).

https://tailwindcss.com/docs/grid-auto-flow[grid-auto-flow] is `grid-flow-row`, `grid-flow-col`,
`grid-flow-dense`, `grid-flow-row-dense`, `grid-flow-col-dense`. Size implicit tracks with
https://tailwindcss.com/docs/grid-auto-columns[auto-cols] (`auto-cols-auto`, `auto-cols-min`, `auto-cols-max`,
`auto-cols-fr`) and https://tailwindcss.com/docs/grid-auto-rows[auto-rows].

[source,html]
----
<div class="grid grid-cols-2 gap-4 md:grid-cols-[24rem_2fr]">
  <div class="col-span-2 md:col-span-1 md:row-span-2">feature</div>
  <div>b</div>
  <div>c</div>
</div>

<!-- a horizontally scrolling row of equal-width cards -->
<div class="grid grid-flow-col auto-cols-[16rem] gap-4 overflow-x-auto">
  <article class="...">card</article>
  <article class="...">card</article>
</div>
----

== Gap

https://tailwindcss.com/docs/gap[gap] works for both layouts: `gap-4` (row and column), `gap-x-8`, `gap-y-2`,
`gap-px`, or an arbitrary `gap-[3px]`. Values follow the spacing scale.

[source,html]
----
<div class="grid grid-cols-3 gap-x-8 gap-y-4">...</div>
<div class="flex flex-wrap gap-2">...</div>
----

== Box alignment (both layouts)

The same utilities align content in flex and grid containers:

[cols="1,3",options="header"]
|===
| Utility family | Aligns

| https://tailwindcss.com/docs/justify-content[`+justify-*+`] | The tracks along the main / inline axis
  (`justify-start`, `justify-center`, `justify-between`, `justify-around`, `justify-evenly`, `justify-stretch`,
  `justify-normal`).
| https://tailwindcss.com/docs/justify-items[`+justify-items-*+`] | Each grid item within its cell on the inline
  axis (`justify-items-start`, `-center`, `-end`, `-stretch`).
| https://tailwindcss.com/docs/justify-self[`+justify-self-*+`] | One grid item on the inline axis.
| https://tailwindcss.com/docs/align-content[`+content-*+`] | Multi-line / multi-row tracks on the cross / block
  axis (`content-start`, `content-center`, `content-between`, ...).
| https://tailwindcss.com/docs/align-items[`+items-*+`] | Items on the cross / block axis (`items-start`,
  `items-center`, `items-end`, `items-baseline`, `items-stretch`).
| https://tailwindcss.com/docs/align-self[`+self-*+`] | One item on the cross / block axis (`self-auto`,
  `self-start`, `self-center`, `self-stretch`, `self-baseline`).
| https://tailwindcss.com/docs/place-content[`+place-content-*+`] | Shorthand for `align-content` +
  `justify-content`.
| https://tailwindcss.com/docs/place-items[`+place-items-*+`] | Shorthand for `align-items` + `justify-items`.
| https://tailwindcss.com/docs/place-self[`+place-self-*+`] | Shorthand for `align-self` + `justify-self`.
|===

[source,html]
----
<!-- perfect centring, either layout -->
<div class="grid min-h-dvh place-items-center">
  <div class="flex items-center justify-between gap-4">
    <span>left</span><span>right</span>
  </div>
</div>
----

Tailwind's docs pages for https://tailwindcss.com/docs/flex-basis[flex-basis],
https://tailwindcss.com/docs/grid-template-columns[grid-template-columns], and
https://tailwindcss.com/docs/justify-content[justify-content] carry interactive diagrams that show each value
live -- use those rather than a static drawing when learning the axes.

== Choosing between flex and grid

Both layouts align boxes, but they start from opposite ends. Flexbox is *content-out*: the items decide how much
room they need and the container distributes the rest along one axis. Grid is *layout-in*: the container defines
tracks first and the items are placed into them. A reliable test is to ask whether the alignment has to hold in
*two* directions at once.

[mermaid]
....
flowchart TD
    Q["Arranging boxes"] --> D{"Items line up in rows and columns?"}
    D -->|"yes: two dimensions"| G["grid"]
    D -->|"no: one row or one column"| F["flex"]
    G --> GA{"Number of columns known?"}
    GA -->|"fixed"| GC["grid-cols-3"]
    GA -->|"as many as fit"| GR["grid-cols-[repeat(auto-fill,minmax(16rem,1fr))]"]
    F --> FA{"Should items wrap?"}
    FA -->|"yes"| FW["flex flex-wrap gap-4"]
    FA -->|"no"| FN["flex items-center justify-between"]
....

In the Acme page both are present and each in its natural place: the header is a *row* of a logo and a nav (flex),
and the feature cards form a *grid* whose columns must align across rows.

== Flex axes: what `justify` and `items` mean

`flex-row` makes the horizontal axis the *main* axis and the vertical one the *cross* axis; `flex-col` swaps
them. `+justify-*+` always works on the main axis and `+items-*+` on the cross axis, which is why `justify-center`
centres horizontally in a row but vertically in a column.

[mermaid]
....
flowchart LR
    subgraph ROW["flex-row"]
        direction LR
        R1["justify-*: horizontal"]
        R2["items-*: vertical"]
    end
    subgraph COL["flex-col"]
        direction LR
        C1["justify-*: vertical"]
        C2["items-*: horizontal"]
    end
....

The Acme header is the canonical case: `flex items-center justify-between` puts the logo at one end and the nav
at the other (`justify-between` on the main axis) and keeps them on one visual centre line (`items-center` on the
cross axis).

[source,html]
----
<header class="flex items-center justify-between border-b border-gray-200 px-6 py-4">
  <a href="/" class="text-lg font-bold">Acme</a>
  <nav class="flex gap-6 text-sm font-medium">
    <a href="/features">Features</a>
    <a href="/pricing">Pricing</a>
    <a href="/docs">Docs</a>
  </nav>
</header>
----

=== How grow, shrink and basis share the space

A flex item's final width is computed in three steps: start from its `basis`, then if the row has room left over
distribute it among the items that can `grow`, or if the items overflow take the excess away from the items that
can `shrink`. This explains the most common surprises. `flex-1` (grow 1, shrink 1, basis 0) makes items equal
widths regardless of their content, while `flex-auto` (basis `auto`) first gives each item its content width and
only then shares the remainder, so unequal content gives unequal widths.

[source,html]
----
<!-- three columns; the middle one takes what is left, the sides keep their size -->
<div class="flex gap-4">
  <aside class="w-48 shrink-0">filters</aside>
  <main class="min-w-0 flex-1">results</main>
  <aside class="w-48 shrink-0">ads</aside>
</div>
----

The `min-w-0` on the flexible item matters: a flex item's automatic minimum width is its content width, so a long
unbreakable string or a wide `pre` stops it shrinking and blows the layout out sideways. `min-w-0` lifts that
minimum so `truncate`, `overflow-x-auto` or wrapping can do their job.

== Worked example: the Acme page shell and card grid

Putting the pieces together, the page shell is a two-column, three-row grid -- a header across the top, a
fixed-width sidebar beside a flexible main area, and a footer across the bottom -- and the card area inside the
main column is a responsive grid that adds columns as space permits.

[source,html]
----
<body class="grid min-h-dvh grid-cols-[16rem_1fr] grid-rows-[auto_1fr_auto]">
  <header class="col-span-2 flex items-center justify-between border-b border-gray-200 px-6 py-4">
    <a href="/" class="text-lg font-bold">Acme</a>
  </header>

  <aside class="border-r border-gray-200 p-6">sidebar</aside>

  <main class="p-6">
    <div class="grid grid-cols-[repeat(auto-fill,minmax(16rem,1fr))] gap-6">
      <article class="rounded-xl border border-gray-200 p-6">Fast</article>
      <article class="rounded-xl border border-gray-200 p-6">Small</article>
      <article class="rounded-xl border border-gray-200 p-6">Simple</article>
    </div>
  </main>

  <footer class="col-span-2 border-t border-gray-200 px-6 py-4 text-sm text-gray-600">Acme Inc.</footer>
</body>
----

Reading it from the top: `grid-cols-[16rem_1fr]` is the arbitrary-value form of `grid-template-columns: 16rem 1fr`
(underscores stand for spaces); `grid-rows-[auto_1fr_auto]` sizes the header and footer to their content and lets the
middle row take the remaining height, and with `min-h-dvh` the footer sits at the bottom even on a short page.
`col-span-2` makes the header and footer cross both columns, and the card grid uses
`repeat(auto-fill,minmax(16rem,1fr))` so the browser, not a breakpoint, decides how many 16rem-wide columns fit.
Both arbitrary values build to exactly that CSS with Tailwind 4.3.

On a phone the sidebar should not take 16rem of a 375px screen. Apply the layout only from a breakpoint, and let
the default be a single column:

[source,html]
----
<body class="grid min-h-dvh grid-cols-1 md:grid-cols-[16rem_1fr] md:grid-rows-[auto_1fr_auto]">
  <header class="flex items-center justify-between border-b border-gray-200 px-6 py-4 md:col-span-2">...</header>
  <aside class="hidden border-r border-gray-200 p-6 md:block">sidebar</aside>
  <main class="p-6">...</main>
  <footer class="border-t border-gray-200 px-6 py-4 md:col-span-2">...</footer>
</body>
----

Compare the two card-grid strategies: `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3` (as in
xref:web/tailwind/worked-example.adoc[]) gives exact control at known breakpoints, while the `auto-fill` form adapts
to the container width, which is what you want when the grid sits in a main area whose width itself changes with
a sidebar.

=== Two common pitfalls

* *Gap versus margin.* `+gap-*+` puts space only *between* items, never on the outer edge, so it does not need the
  `first:` / `last:` exceptions that per-item margins do. It also works on wrapped flex rows. See
  xref:web/tailwind/spacing-and-sizing.adoc[] for when `+space-*+` is still the better choice.
* *Grid items that overflow.* Like flex items, a grid item's automatic minimum is its content size. A `1fr` track
  holding a wide table or code block grows past the container; write `grid-cols-[16rem_minmax(0,1fr)]` or put
  `min-w-0` on the item to let the track shrink.
