= Filters, Transitions, and Transforms
:description: Tailwind CSS v4 utilities for CSS filters and backdrop filters, transitions and timing, the built-in and custom animations, and 2D/3D transforms -- including the v4 blur rename, transition-discrete, and the 3D transform utilities.
:keywords: Tailwind filter, blur, brightness, drop-shadow, backdrop-blur, transition, duration, ease, delay, transition-discrete, starting variant, animate-spin, custom @keyframes, scale, rotate, translate, skew, perspective, transform-3d, rotate-x

include::partial$ai-disclaimer.adoc[]

These families animate and post-process the box: `+filter-*+` reprocesses pixels, `+transition-*+` /
`+animate-*+` move properties over time, and `transform` utilities scale, rotate, translate, and skew --
now in 3D as well. See https://tailwindcss.com/docs/filter[Filter],
https://tailwindcss.com/docs/transition-property[Transition Property], and
https://tailwindcss.com/docs/scale[Scale].

== Filters

[source,html]
----
<img class="blur-sm brightness-110 contrast-125 saturate-150" />
<img class="grayscale hover:grayscale-0 transition" />
<img class="invert sepia hue-rotate-60 drop-shadow-lg" />

<!-- backdrop-* filters process whatever is BEHIND the element -->
<div class="bg-white/30 backdrop-blur-md backdrop-saturate-150">frosted panel</div>
----

In v4 `blur` renamed down a step: the old `blur-sm` is now `blur-xs`, the old `blur` is `blur-sm` (same for
`backdrop-blur` and `drop-shadow`). See https://tailwindcss.com/docs/backdrop-filter-blur[Backdrop Filter].

== Transitions

[source,html]
----
<!-- what to transition -->
<button class="bg-sky-600 transition-colors hover:bg-sky-700">colours only</button>
<div class="transition hover:scale-105">the common set (colour, opacity, transform, filter, &#8230;)</div>
<div class="transition-all">everything</div>

<!-- timing -->
<div class="transition duration-300 ease-in-out delay-100 hover:opacity-50"></div>
<div class="transition ease-[cubic-bezier(0.34,1.56,0.64,1)]">custom curve</div>

<!-- discrete properties + @starting-style, for enter/exit without JS -->
<div popover class="opacity-0 transition-discrete transition
                    starting:open:opacity-0 open:opacity-100"></div>
----

Note that in v4 the `transition` set also includes `outline-color`, so a focus outline colour will animate
unless you set it unconditionally. See https://tailwindcss.com/docs/transition-duration[Transition Duration]
and https://tailwindcss.com/docs/transition-behavior[Transition Behavior].

== Animation

[source,html]
----
<svg class="animate-spin">&#8230;</svg>
<span class="animate-ping"></span>
<div class="animate-pulse">skeleton</div>
<div class="animate-bounce">&#8595;</div>
<div class="motion-reduce:animate-none">respects the user preference</div>
----

Define a custom animation by adding an `+--animate-*+` theme variable and its `@keyframes` inside `@theme`:

[source,css]
----
@import "tailwindcss";

@theme {
  --animate-fade-in-scale: fade-in-scale 0.3s ease-out both;

  @keyframes fade-in-scale {
    from { opacity: 0; transform: scale(0.95); }
    to   { opacity: 1; transform: scale(1); }
  }
}
----

[source,html]
----
<div class="animate-fade-in-scale">appears</div>
----

See https://tailwindcss.com/docs/animation[Animation].

== Transforms

[source,html]
----
<!-- 2D -->
<div class="scale-105 hover:scale-110">grow on hover</div>
<div class="rotate-3 -rotate-6">tilt</div>
<div class="translate-x-4 translate-y-2">nudge</div>
<div class="skew-x-6"></div>
<div class="origin-top-left scale-90">transform-origin</div>
<div class="transform-gpu">force GPU compositing</div>

<!-- 3D (new in v4): needs perspective on an ancestor and transform-3d on the moving element -->
<div class="perspective-[800px]">
  <div class="transform-3d rotate-x-30 rotate-y-45 backface-hidden">card face</div>
</div>

<!-- reset an individual transform, not the whole thing -->
<div class="scale-150 hover:scale-none"></div>
----

See https://tailwindcss.com/docs/rotate[Rotate], https://tailwindcss.com/docs/translate[Translate], and
https://tailwindcss.com/docs/perspective[Perspective].

== Worked example: a card that lifts and fades in

The feature cards of the running example (see xref:web/tailwind/worked-example.adoc[]) gain two small effects: a lift
and a deeper shadow while hovered, and a fade-in when the page loads. Both respect users who ask for less motion.

[source,css]
----
@import "tailwindcss";

@theme {
  --animate-fade-in: fade-in 300ms ease-out both;

  @keyframes fade-in {
    from { opacity: 0; transform: translateY(0.5rem); }
    to   { opacity: 1; transform: none; }
  }
}
----

[source,html]
----
<article class="animate-fade-in rounded-xl border border-gray-200 p-6
                transition duration-200 ease-out
                hover:shadow-lg motion-safe:hover:-translate-y-1
                motion-reduce:animate-none motion-reduce:transition-none">
  <h3 class="font-semibold">Fast</h3>
  <p class="mt-2 text-sm text-gray-600">Only the CSS you use is generated.</p>
</article>
----

How the pieces cooperate:

* `transition` lists the properties that may animate (colours, opacity, shadow, transform, filter and a few
  more), `duration-200` and `ease-out` set the time and curve. Without `transition` the hover change is instant,
  because the other classes only change the *end* state.
* `hover:shadow-lg` and `motion-safe:hover:-translate-y-1` change the end state. `motion-safe:` applies the
  lift only when the user has *not* asked the operating system to reduce motion; the shadow, which is not movement,
  stays for everyone.
* `animate-fade-in` is a custom utility created by the `--animate-fade-in` theme variable. `both` as the fill mode
  holds the first keyframe before the animation starts and the last after it ends.
* `motion-reduce:animate-none` and `motion-reduce:transition-none` switch both effects off for those users.

The generated rules show the media conditions explicitly: the lift is wrapped in
`@media (prefers-reduced-motion: no-preference)` and also in `@media (hover: hover)`, so it only happens on devices
that can hover, and the `@keyframes fade-in` rule is emitted only because a class uses it. The snippets on this page
were built with Tailwind 4.3.

=== What happens during a hover

A transition is the browser interpolating between two computed styles. Tailwind only supplies the two styles and
the timing; the interpolation is the browser's.

[mermaid]
....
stateDiagram-v2
    [*] --> Rest
    Rest --> Hovered: pointer enters, 200ms ease-out
    Hovered --> Rest: pointer leaves, 200ms ease-out
    Rest: border only
    Hovered: translated up 0.25rem, shadow-lg
....

If the pointer leaves halfway, the browser reverses from the *current* interpolated value rather than jumping, which
is why short durations feel responsive and long ones feel laggy: a card with `duration-700` is still travelling
when the pointer has already moved on. Keep UI transitions between 100ms and 300ms.

=== Which properties are cheap to animate

Not every property costs the same. `transform`, `opacity` and (in modern browsers) `filter` can be animated on the
compositor without recalculating layout, which keeps them smooth. Properties that change layout, such as `width`,
`height`, `padding` or `top`, force the browser to re-lay out the page on every frame. This is why the card lifts with
`-translate-y-1` and not with a changing `margin-top` or `top`, and why `transition-all` is best avoided on large
components: it also animates properties you did not intend, including layout ones.

[mermaid]
....
flowchart LR
    CH["property that changes"] --> Q{"Affects layout?"}
    Q -->|"yes: width, height, margin, top"| LAY["layout, paint, composite on each frame"]
    Q -->|"paint only: colour, shadow"| PNT["paint, composite"]
    Q -->|"transform, opacity"| CMP["composite only: cheapest"]
....

=== Transforms and the order they compose

In v4 `+translate-*+`, `+rotate-*+` and `+scale-*+` set their own CSS properties (`translate`, `rotate`, `scale`) rather
than sharing one `transform`, so they combine without surprises and can be transitioned independently. The
`hover:scale-none` reset shown above removes one without touching the others. Reach for the `transform` property
itself only through `+transform-[...]+`, for example when a keyframe needs a precise sequence.
