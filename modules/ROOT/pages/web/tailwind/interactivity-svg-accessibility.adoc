= Interactivity, SVG, and Accessibility
:description: Tailwind CSS v4 utilities for interactivity (accent/caret colour, appearance, cursor, field-sizing, pointer-events, resize, scroll behaviour and snap, touch-action, user-select, will-change), SVG fill/stroke, and accessibility (sr-only, forced-color-adjust).
:keywords: Tailwind interactivity, accent-color, caret-color, appearance-none, cursor, field-sizing, pointer-events, resize, scroll-smooth, scroll-snap, touch-action, select-none, will-change, fill, stroke, sr-only, forced-color-adjust, screen readers

include::partial$ai-disclaimer.adoc[]

A grab-bag of utilities that control how an element behaves under pointer, keyboard, and scroll, how inline
SVG is coloured, and how content is exposed to assistive technology. See
https://tailwindcss.com/docs/cursor[Cursor], https://tailwindcss.com/docs/fill[Fill], and
https://tailwindcss.com/docs/screen-readers[Screen Readers].

== Interactivity

[source,html]
----
<!-- native control accents -->
<input type="checkbox" class="accent-sky-600" />
<input type="text" class="caret-pink-500" />
<select class="appearance-none">strip the native chrome</select>
<div class="color-scheme-dark">form controls render dark</div>

<!-- pointer + sizing -->
<button class="cursor-pointer disabled:cursor-not-allowed">click</button>
<textarea class="field-sizing-content">grows with its content</textarea>
<div class="pointer-events-none">clicks pass through</div>
<textarea class="resize-y"></textarea>

<!-- scrolling -->
<html class="scroll-smooth">anchor jumps animate</html>
<section class="scroll-mt-16" id="pricing">offsets a sticky header</section>

<!-- scroll snap -->
<div class="snap-x snap-mandatory overflow-x-auto flex">
  <div class="snap-center shrink-0 w-80">slide</div>
  <div class="snap-center shrink-0 w-80">slide</div>
</div>

<!-- touch, selection, compositing hint -->
<div class="touch-pan-y">only vertical panning</div>
<p class="select-none">not selectable</p>
<pre class="select-all">click selects the whole block</pre>
<div class="will-change-transform">promoted for animation</div>
----

See https://tailwindcss.com/docs/scroll-snap-type[Scroll Snap Type] and
https://tailwindcss.com/docs/field-sizing[Field Sizing].

== SVG

`+fill-*+` and `+stroke-*+` take palette colours (and `fill-current` / `stroke-current` for `currentColor`), so an
inline icon inherits the surrounding text colour and reacts to variants:

[source,html]
----
<button class="text-gray-500 hover:text-sky-600">
  <svg class="size-5 fill-none stroke-current stroke-2" viewBox="0 0 24 24">
    <path d="M5 12h14" />
  </svg>
</button>

<svg class="fill-sky-500"><circle cx="12" cy="12" r="10" /></svg>
----

See https://tailwindcss.com/docs/stroke-width[Stroke Width].

== Accessibility

[source,html]
----
<!-- visually hidden, still announced by screen readers -->
<a href="/cart">
  <svg class="size-6">&#8230;</svg>
  <span class="sr-only">View cart</span>
</a>

<!-- reveal a visually-hidden element on focus (skip links) -->
<a href="#main" class="sr-only focus:not-sr-only">Skip to content</a>

<!-- opt an element out of Windows High Contrast remapping -->
<div class="forced-color-adjust-none bg-linear-to-r from-sky-500 to-indigo-500"></div>
----

Pair these with the preference variants from the states page -- `motion-reduce:`, `contrast-more:`,
`forced-colors:` -- to adapt the UI to user settings. See
https://tailwindcss.com/docs/forced-color-adjust[Forced Color Adjust].

== Worked example: an accessible Acme header

The header of the running example (see xref:web/tailwind/worked-example.adoc[]) has three interactive parts that
must work without a mouse: a skip link, a menu button for small screens, and in-page anchors that land below the
sticky bar. Each maps onto the utilities above.

[source,html]
----
<a href="#main"
   class="sr-only focus:not-sr-only focus:absolute focus:top-4 focus:left-4 focus:z-50
          focus:rounded-md focus:bg-white focus:px-4 focus:py-2 focus:shadow-lg">
  Skip to content
</a>

<header class="sticky top-0 z-20 flex items-center justify-between border-b border-gray-200 bg-white px-6 py-4">
  <a href="/" class="text-lg font-bold">Acme</a>

  <button type="button" aria-expanded="false" aria-controls="menu"
          class="rounded-md p-2 text-gray-700 hover:bg-gray-100 aria-expanded:bg-gray-100 sm:hidden
                 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-600">
    <svg class="size-6 fill-none stroke-current stroke-2" viewBox="0 0 24 24" aria-hidden="true">
      <path d="M4 7h16M4 12h16M4 17h16" />
    </svg>
    <span class="sr-only">Open menu</span>
  </button>

  <nav id="menu" class="hidden gap-6 text-sm font-medium sm:flex">
    <a href="#features">Features</a>
    <a href="#pricing">Pricing</a>
  </nav>
</header>

<main id="main" class="scroll-smooth">
  <section id="pricing" class="scroll-mt-20">...</section>
</main>
----

* *The skip link.* `sr-only` removes the link visually while keeping it in the tab order and the accessibility
  tree. On the first Tab press it receives focus and `focus:not-sr-only` puts it back, so keyboard users see it and
  can jump past the navigation. The combination relies on `not-sr-only` resetting `position`, `width`, `height`,
  `padding` and `margin`, followed by the other focus classes, which the generated stylesheet orders later so they
  apply.
* *The menu button.* An icon-only button needs a name: the `sr-only` label provides it and `aria-hidden="true"`
  on the SVG keeps it from being announced. `+focus-visible:outline-*+` draws an outline for keyboard focus but not
  for mouse clicks. `aria-expanded:bg-gray-100` reacts to the attribute your script toggles, so the open state is
  styled from the same attribute assistive technology reads rather than from a second class that can drift out of
  sync.
* *Anchors under a sticky header.* The header is about 4rem tall, so `scroll-mt-20` (5rem) on each target keeps
  the heading from hiding beneath it after a jump, and `scroll-smooth` animates the jump.

All of these classes (`sr-only`, `focus:not-sr-only`, `aria-expanded:`, `focus-visible:outline-2`, `scroll-mt-20`,
`scroll-smooth`) build as written with Tailwind 4.3; `aria-expanded:` compiles to the attribute selector
`[aria-expanded="true"]`.

=== Focus versus focus-visible

`focus:` fires whenever an element has focus, including after a mouse click, so an outline set with it flashes on
every button press. `focus-visible:` applies only when the browser decides focus should be shown, which in practice
means keyboard navigation (and for text fields, always). Prefer `focus-visible:` for buttons and links, and keep
`focus:` for text inputs.

[mermaid]
....
flowchart TD
    E["element receives focus"] --> H{"How was it focused?"}
    H -->|"mouse click on a button or link"| M["focus: applies, focus-visible: does not"]
    H -->|"Tab key or arrow keys"| K["focus: and focus-visible: both apply"]
    H -->|"click or Tab into a text input"| T["both apply, so the user sees the caret and the ring"]
....

=== Adapting to user preferences

The accessible page asks the browser about the user rather than assuming. Each preference has a variant:
`motion-reduce:` and `motion-safe:` for animation, `contrast-more:` for increased contrast, `forced-colors:` for
Windows High Contrast and similar modes, and `dark:` for the colour scheme. Because the variants wrap the same
declaration in a media query, a rule is simply absent when the preference does not match.

[mermaid]
....
flowchart LR
    OS["operating system settings"] --> RM["prefers-reduced-motion"]
    OS --> CM["prefers-contrast"]
    OS --> FC["forced-colors"]
    OS --> CS["prefers-color-scheme"]
    RM --> V1["motion-reduce: / motion-safe:"]
    CM --> V2["contrast-more:"]
    FC --> V3["forced-colors:"]
    CS --> V4["dark:"]
....

Under forced colours the browser replaces most colours with a small system palette, which removes gradients and
box shadows. A border that carried the boundary of a card then becomes the only visible edge, so keep real borders
on interactive elements and add `forced-colors:border-[ButtonText]` where a ring or shadow was the only outline.
Use `forced-color-adjust-none` sparingly and only on elements, such as a colour swatch, whose colour is the content.

=== A snap carousel that keyboard users can drive

Scroll snapping is pure CSS, and a scroll container is focusable in modern browsers when it overflows, so a
keyboard user can scroll it with the arrow keys; add `tabindex="0"` and a name for older browsers.

[source,html]
----
<ul class="flex snap-x snap-mandatory gap-4 overflow-x-auto pb-4"
    tabindex="0" role="region" aria-label="Customer stories">
  <li class="w-4/5 shrink-0 snap-center rounded-xl border border-gray-200 p-6 sm:w-1/3">Story one</li>
  <li class="w-4/5 shrink-0 snap-center rounded-xl border border-gray-200 p-6 sm:w-1/3">Story two</li>
  <li class="w-4/5 shrink-0 snap-center rounded-xl border border-gray-200 p-6 sm:w-1/3">Story three</li>
</ul>
----

`w-4/5` makes the next card peek at the edge on a phone, which shows that the row scrolls; `shrink-0` stops the flex
row squeezing the cards instead of overflowing; `snap-mandatory` makes each swipe land on a card.
