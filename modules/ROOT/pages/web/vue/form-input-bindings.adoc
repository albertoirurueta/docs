= Form Input Bindings
:description: Two-way binding of form controls in Vue with v-model -- text, textarea, checkbox, radio and select; what v-model desugars to; the .lazy, .number and .trim modifiers; and binding to dynamic values.
:keywords: Vue, v-model, form input bindings, two-way binding, checkbox array, true-value, false-value, radio, select multiple, v-model desugar, input event, lazy modifier, number modifier, trim modifier, VeeValidate, schema validation

include::partial$ai-disclaimer.adoc[]

`v-model` creates a two-way binding between a form control and a piece of reactive state: the control shows
the state, and editing the control writes it back. It picks the right DOM property and event for each control
type. The reference is https://vuejs.org/guide/essentials/forms.html[Form Input Bindings].

== The basics

[source,vue]
----
<script setup>
import { ref } from 'vue'

const message = ref('')
</script>

<template>
  <input v-model="message" placeholder="type here">
  <p>{{ message }}</p>
</template>
----

`v-model` ignores the initial `value`, `checked`, or `selected` attribute on the element -- the reactive
state is the single source of truth, so set the initial value on the ref instead. See
https://vuejs.org/guide/essentials/forms.html#basic-usage[Basic Usage].

== What v-model desugars to

For a text input, `v-model="message"` expands to roughly a `:value` bind plus an `@input` listener:

[source,vue]
----
<input
  :value="message"
  @input="message = $event.target.value">
----

Different controls use different pairs -- this is why the same directive covers all of them:

[cols="1,1,1"]
|===
| Control | Bound property | Listened event

| text, `<textarea>` | `value` | `input`
| checkbox, radio | `checked` | `change`
| `<select>` | `value` | `change`
|===

Knowing the expansion matters when you need something in between: bind `:value` yourself and add an `@input`
that transforms the text before storing it.

== Text and textarea

[source,vue]
----
<template>
  <input v-model="title">
  <textarea v-model="bio"></textarea>
</template>
----

Text interpolation does not work inside `<textarea>` -- use `v-model`.

== Checkbox

See https://vuejs.org/guide/essentials/forms.html#checkbox[Checkbox]. A lone checkbox binds to a boolean:

[source,vue]
----
<script setup>
import { ref } from 'vue'
const agreed = ref(false)
</script>

<template>
  <input type="checkbox" v-model="agreed">
</template>
----

Several checkboxes that share one array binding collect the `value` of each checked box:

[source,vue]
----
<script setup>
import { ref } from 'vue'
const picked = ref([])
</script>

<template>
  <input type="checkbox" value="vue" v-model="picked">
  <input type="checkbox" value="svelte" v-model="picked">
  <input type="checkbox" value="solid" v-model="picked">
  <!-- picked.value is e.g. ['vue', 'solid'] -->
</template>
----

`true-value` and `false-value` make a single checkbox store something other than the booleans -- and they
only affect `v-model`, not the element's `value` attribute. Bind them with `:true-value` / `:false-value` for
non-string values:

[source,vue]
----
<template>
  <input type="checkbox" v-model="answer" true-value="yes" false-value="no">
  <input type="checkbox" v-model="answer" :true-value="dynamicYes" :false-value="dynamicNo">
</template>
----

== Radio

See https://vuejs.org/guide/essentials/forms.html#radio[Radio].

[source,vue]
----
<script setup>
import { ref } from 'vue'
const size = ref('m')
</script>

<template>
  <input type="radio" value="s" v-model="size"> Small
  <input type="radio" value="m" v-model="size"> Medium
  <!-- :value for a non-string or dynamic value -->
  <input type="radio" :value="{ id: 3 }" v-model="size"> Custom
</template>
----

== Select

See https://vuejs.org/guide/essentials/forms.html#select[Select].

[source,vue]
----
<template>
  <select v-model="selected">
    <option disabled value="">Please select one</option>
    <option>A</option>
    <option>B</option>
  </select>
</template>
----

Provide an empty disabled option when the initial value matches no `<option>` -- otherwise iOS renders the
select in an unselectable state. For a `multiple` select, bind to an array:

[source,vue]
----
<template>
  <select v-model="selected" multiple>
    <option>A</option>
    <option>B</option>
    <option>C</option>
  </select>
</template>
----

Options rendered with `v-for` use `:value`, which can hold any type, not just a string -- see
https://vuejs.org/guide/essentials/forms.html#value-bindings[Value Bindings]:

[source,vue]
----
<template>
  <select v-model="selected">
    <option v-for="o in options" :key="o.id" :value="o">{{ o.text }}</option>
  </select>
</template>
----

== Modifiers

See https://vuejs.org/guide/essentials/forms.html#modifiers[v-model modifiers]. They chain, e.g.
`v-model.trim.lazy`.

[source,vue]
----
<template>
  <!-- sync on "change" instead of every "input" -->
  <input v-model.lazy="msg">

  <!-- cast to a number with parseFloat; kept as-is if the result is NaN -->
  <input v-model.number="age">

  <!-- strip leading and trailing whitespace -->
  <input v-model.trim="name">
</template>
----

`<input type="number">` already coerces to a number, so `.number` is mainly for text inputs that should hold
numeric values.

== The round trip behind `v-model`

On a native control, `v-model` is a loop between the state and the DOM. The DOM property is *written* from state on
each render, and an event writes the control's new value *back* into the state. The loop closes only because the
re-render writes the same value the user already typed.

[mermaid]
....
sequenceDiagram
    participant U as User
    participant E as input element
    participant S as reactive state
    participant R as render effect
    U->>E: types a character
    E->>S: input event: state = event.target.value
    S->>R: write triggers the render effect
    R->>E: sets the value property from state
    Note over E,R: equal to what was typed, so the cursor stays put
....

The *modifiers* are small transforms on the write-back leg: `.trim` strips whitespace, `.number` casts with
`parseFloat`, and `.lazy` listens for `change` instead of `input`. One practical consequence is *IME composition*
(typing Chinese, Japanese or Korean): `v-model` waits for the composition to end before syncing, so a half-composed
character is never written into state. If you need to react while composing, use the `:value` / `@input`
expansion instead.

== Worked example: a profile form with derived validation

Validation is a pure function of the form's state, which makes it a natural fit for a computed property: the error
messages, the validity flag and the disabled state of the submit button are all derived, never stored separately.

[source,vue]
----
<script setup>
import { reactive, computed } from 'vue'

const form = reactive({
  name: '',
  age: null,
  role: '',
  interests: [],
  newsletter: 'no',
  bio: ''
})

const errors = computed(() => {
  const e = {}
  if (form.name.length < 2) e.name = 'Name needs at least 2 characters'
  if (!(form.age >= 18)) e.age = 'You must be 18 or older'
  if (!form.role) e.role = 'Pick a role'
  return e
})
const valid = computed(() => Object.keys(errors.value).length === 0)

function submit() {
  if (!valid.value) return
  console.log(JSON.stringify(form))
}
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model.trim="form.name" placeholder="Name" />
    <small v-if="errors.name">{{ errors.name }}</small>

    <input v-model.number="form.age" placeholder="Age" />
    <small v-if="errors.age">{{ errors.age }}</small>

    <select v-model="form.role">
      <option disabled value="">Role</option>
      <option>Developer</option>
      <option>Designer</option>
    </select>
    <small v-if="errors.role">{{ errors.role }}</small>

    <label><input type="checkbox" value="vue" v-model="form.interests" /> Vue</label>
    <label><input type="checkbox" value="ts" v-model="form.interests" /> TypeScript</label>

    <label>
      <input type="checkbox" v-model="form.newsletter" true-value="yes" false-value="no" />
      Newsletter
    </label>

    <textarea v-model.lazy="form.bio"></textarea>
    <button :disabled="!valid">Save</button>
  </form>
</template>
----

The form starts with the *Save* button disabled and three messages showing. Filling it in with Vue Test Utils --
`+'  Ada '+` as the name, `36` as the age, *Developer*, both interest boxes, the newsletter box and a bio -- enables the
button, and submitting logs:

[source,json]
----
{"name":"Ada","age":36,"role":"Developer","interests":["vue","ts"],"newsletter":"yes","bio":"hi"}
----

Each binding stored the type its control implies: `.trim` removed the padding, `.number` produced the number `36`
rather than the string, the shared array collected the checked `value` attributes, and `true-value` / `false-value`
turned the single checkbox into `+'yes'+`. Showing errors only after a field was touched, or only after a first submit
attempt, is a small addition: keep a `touched` object next to `form` and show `errors.name` when `touched.name` is
true.

== Accessibility of form bindings

`v-model` binds *state*; it does not make a form usable. Give every control a visible `<label>` (wrapping the input,
or `for` / `id`), associate error messages with the control through `aria-describedby`, and mark invalid fields
with `aria-invalid`. A message that appears after submit should be reachable by assistive technology, for example
inside an `aria-live` region. See xref:web/accessibility.adoc[] and
xref:web/vue/security-and-accessibility.adoc[].

== When to bring in a validation library

The computed-errors pattern scales to a handful of fields. Beyond that -- cross-field rules, asynchronous checks,
nested arrays of fields, errors tied to a schema shared with the server -- a library pays for itself.
https://vee-validate.logaretm.com/v4/[VeeValidate] and https://formkit.com/[FormKit] provide field state (touched,
dirty, errors), submit handling and schema adapters, and they build on the same `v-model` mechanics shown here.

== Validation is not built in

Vue's core has no form-validation layer. For real forms, reach for a dedicated library:
https://vee-validate.logaretm.com/v4/[VeeValidate] wires field-level and whole-form *schema* validation
(Zod, Yup, Valibot) into Vue's reactivity. The official guide covers only the binding mechanics on this page.

== v-model on components

Everything above is `v-model` on native elements. `v-model` also works on your own components, backed by
`defineModel()`, with support for arguments and custom modifiers -- see
xref:web/vue/component-events-and-v-model.adoc[].
