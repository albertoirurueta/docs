Welcome to the Docker reference. *Docker* packages an application with everything it needs to run into an
*image* -- a stack of read-only filesystem layers plus a configuration, standardised by the Open Container
Initiative -- and runs that image as an isolated process called a *container* on any host with a container engine.
The same image is built once, tested, pushed to a registry and pulled unchanged into every environment, from a
developer laptop through CI to production, which is why Docker has become the default unit of packaging and
deployment for backend services.

The examples in this section are written and verified against Docker Engine 29.8.x, Docker Compose v5.5.x,
Buildx 0.37.x with BuildKit 0.33.x and the `docker/dockerfile:1` frontend, and Docker Desktop 4.91 or later; the
Java pages add Testcontainers for Java 2.0.5, Spring Boot 4.1.x and Java 25, and the CI pages use the current
majors of the official GitHub Actions (`actions/checkout@v7`, `actions/setup-java@v6`, `docker/*` actions such as
`docker/build-push-action@v7`).

*SpringBoot.* The xref:backend/springboot/index.adoc[SpringBoot Reference] already covers `@SpringBootTest` with
Testcontainers in xref:backend/springboot/unit-and-integration-testing.adoc[Unit and Integration Testing] and the
Surefire/Failsafe split in xref:backend/springboot/maven-quality-plugins.adoc[Maven Quality Plugins]. This section
links to those pages and adds the Docker side: building the service's image, the local Compose stack, how
Testcontainers talks to Docker, and running the integration tests locally and in GitHub Actions.

*Hibernate.* xref:backend/hibernate/integration-testing.adoc[Hibernate integration testing] and
xref:backend/hibernate/hibernate-search-integration-testing.adoc[Hibernate Search integration testing] use
PostgreSQL and Elasticsearch containers; xref:backend/docker/testcontainers-fundamentals.adoc[Testcontainers
Fundamentals] explains the machinery underneath them.

*Messaging.* xref:backend/messaging/spring-boot-testing-messaging.adoc[Spring Boot Testing for Messaging] covers
Kafka and RabbitMQ containers and broker-specific Docker Compose usage; this section documents the general
`spring.docker.compose.*` support once, on xref:backend/docker/compose-for-local-development.adoc[Compose for
Local Development], and links back for the brokers.

*Quarkus.* The Quarkus pages listed under "Other framework bindings" are the Quarkus equivalents of the Java and
Spring Boot pages here; Jib and Buildpacks are cross-referenced rather than repeated.

*Prometheus.* xref:database/prometheus/containers-and-kubernetes-monitoring.adoc[Containers & Kubernetes
monitoring] in the xref:database/prometheus/index.adoc[Prometheus reference] covers cAdvisor and container metrics;
xref:backend/docker/resources-logging-and-monitoring.adoc[Resources, Logging and Monitoring] covers the Docker
daemon's own metrics and links there for the rest.
