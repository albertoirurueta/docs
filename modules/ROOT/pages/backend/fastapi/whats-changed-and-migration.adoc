:description: A dated map of what changed in FastAPI, Pydantic and Starlette since older tutorials and books were written: Pydantic v2, Annotated, the fastapi CLI, lifespan, security libraries, dependencies with yield, parameter models, response handling, OpenAPI 3.1, and everything new through FastAPI 0.142.2, with old versus new code that was executed and links to the covering pages and release notes.

This page is written against FastAPI 0.142.2 (released 2026-09-30), Pydantic 2.13 and Starlette 1.7, checked on
2026-10-02. FastAPI supports Python 3.10 through 3.14; every current-style Python example on this page was executed on
Python 3.13 with `TestClient` or plain execution, and every deprecated or removed form is shown only as the _old way_
and was not run as a recommendation. FastAPI is still a 0.x project, so almost every release can contain a visible
change, and a large part of the material on the web (tutorials, blog posts, and the reference book listed in
xref:backend/fastapi/index.adoc#_bibliography[the section bibliography]) was written before many of those releases. This
page is the map between that older material and today's documentation: which release changed what, on which date, what
the old code looked like, what to write now, which page of this section covers it, and where the official release
notes say it.

[#how-to-read]
== How to Read the Tables

Each row has the FastAPI version that introduced the change, the release date, the old way you will meet in older
code, the new way, a link to the page of this section that covers it, and a link to the official release notes. The
version links use the anchor form of the release notes page, which is the version without dots followed by the release
date. Where a change belongs to a library or to Python rather than to a numbered FastAPI release, the version column
says so and the last column links the official page that documents it instead.

Two rules of thumb make migrations safe. Pin FastAPI to an exact version in `pyproject.toml` or in a lock file, as the
official versions page advises for a 0.x project, and read the release notes entries marked as breaking before every
upgrade. Run the test suite (it prints a deprecation warning from Starlette about `httpx` and `httpx2` with the current `TestClient`; see xref:backend/fastapi/testing.adoc[Testing]) after each upgrade: most of the changes
below fail loudly at import time or on the first request, not silently in production.

[#lifespan-example]
=== Startup and Shutdown: From `on_event` to `lifespan`

Older code registers startup and shutdown handlers with a decorator that is now deprecated:

[source,python]
.Old way (deprecated, not recommended; not run)
----
from fastapi import FastAPI

app = FastAPI()
resources: dict[str, str] = {}


@app.on_event("startup")
async def startup() -> None:
    resources["db"] = "connected"


@app.on_event("shutdown")
async def shutdown() -> None:
    resources.clear()
----
Source: https://fastapi.tiangolo.com/advanced/events/#alternative-events-deprecated[FastAPI: Lifespan Events, Alternative Events (deprecated)]

The replacement is one async context manager: everything before `yield` is startup, everything after is shutdown, and
the two halves can share local variables. The `with TestClient(app)` block runs the lifespan; without the `with`, it
does not run.

[source,python]
.Current: lifespan context manager
----
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from fastapi import FastAPI
from fastapi.testclient import TestClient

resources: dict[str, str] = {}


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    resources["db"] = "connected"      # startup
    yield
    resources.clear()                  # shutdown


app = FastAPI(lifespan=lifespan)


@app.get("/status")
def status() -> dict[str, str]:
    return resources


with TestClient(app) as client:
    print(client.get("/status").json())
print("after shutdown:", resources)
----
Source: https://fastapi.tiangolo.com/advanced/events/#lifespan[FastAPI: Lifespan Events, Lifespan]

[source,text]
----
{'db': 'connected'}
after shutdown: {}
----

[#pydantic-table]
=== The Pydantic v1 to v2 Replacements

These are the replacements to apply to code written for Pydantic v1. They come from the Pydantic migration guide and
from the FastAPI documentation, and they are shown in full on
xref:backend/fastapi/pydantic-v2-essentials.adoc[Pydantic v2 Essentials].

[cols="2,2,2",options="header"]
.Pydantic v1 to v2 (FastAPI 0.126.0 and later accept only v2)
|===
| Pydantic v1 (old way) | Pydantic v2 (new way) | Notes

| `.dict()`
| `model_dump()`
| `.json()` becomes `model_dump_json()`; `.parse_obj()` becomes `model_validate()`

| `conint(...)`, `constr(regex=..., to_upper=...)`
| `Annotated[int, Field(ge=1)]`, `Annotated[str, Field(pattern=...)]`, `StringConstraints(...)`
| `regex` is now `pattern`

| `min_items`, `max_items`
| `min_length`, `max_length`
| The same names apply to lists, strings and sets

| `Field(...)` to mark a field as required
| No default at all
| A field with no default is required

| `class Config:` with `orm_mode = True`
| `model_config = ConfigDict(from_attributes=True)`
| Class-based `Config` is deprecated

| `@validator`, `@root_validator`
| `@field_validator`, `@model_validator`
| Validators are classmethods in v2

| `Optional[X]` without a default looked optional
| Still required in v2: `X \| None` without a default must be sent
| Add `= None` to make it optional

| Error `type` such as `value_error.missing`
| Error `type` such as `missing`
| Error payloads also carry `input` and `loc`

| Models accepted positional arguments in some cases
| Keyword-only construction
| `Book(title="Dune")`, never `Book("Dune")`
|===

[source,python]
.Old way (Pydantic v1, removed from FastAPI; not run)
----
from pydantic import BaseModel, Field, validator


class Book(BaseModel):
    title: str = Field(..., min_items=1)
    tags: list[str] = Field(default_factory=list, min_items=0)

    class Config:
        orm_mode = True

    @validator("title")
    def strip_title(cls, value):
        return value.strip()


payload = Book(title=" Dune ").dict()
----
Source: https://pydantic.dev/docs/validation/latest/get-started/migration/[Pydantic: Migration Guide]

The same model in Pydantic v2 style. The script prints the dump, the new error `type` for a missing field, and shows
that positional construction is rejected.

[source,python]
.Current: Pydantic v2 equivalents
----
from typing import Annotated

from pydantic import BaseModel, ConfigDict, Field, ValidationError, field_validator


class Book(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    title: Annotated[str, Field(min_length=1, pattern=r"^\S.*$")]
    tags: Annotated[list[str], Field(max_length=5)] = []
    subtitle: str | None            # no default: still required in v2

    @field_validator("title")
    @classmethod
    def strip_title(cls, value: str) -> str:
        return value.strip()


class Row:
    title = "Dune"
    tags: list[str] = []
    subtitle = None


print(Book(title="Dune", subtitle=None).model_dump())
print(Book.model_validate(Row()).title)

try:
    Book(title="Dune")
except ValidationError as exc:
    print(exc.errors()[0]["type"], exc.errors()[0]["loc"])

try:
    Book("Dune")                    # type: ignore[misc]
except TypeError as exc:
    print("positional:", type(exc).__name__)
----
Source: https://pydantic.dev/docs/validation/latest/get-started/migration/[Pydantic: Migration Guide]

[source,text]
----
{'title': 'Dune', 'tags': [], 'subtitle': None}
Dune
missing ('subtitle',)
positional: TypeError
----

[#annotated-example]
=== `Annotated` Instead of Default-Value Metadata

The older style is still accepted, so you will meet it in existing code. New code uses `Annotated`, because the
default value stays a real default (and works for plain Python calls) and the metadata can be shared through an alias.

[source,python]
.Old way (still accepted, not recommended; not run)
----
from fastapi import Depends, FastAPI, Query

app = FastAPI()


def pagination(limit: int = Query(default=10, ge=1, le=100)) -> int:
    return limit


@app.get("/books")
def list_books(q: str | None = Query(default=None, max_length=50), limit: int = Depends(pagination)):
    return {"q": q, "limit": limit}
----
Source: https://fastapi.tiangolo.com/tutorial/query-params-str-validations/[FastAPI: Query Parameters and String Validations]

[source,python]
.Current: Annotated with a reusable alias
----
from typing import Annotated

from fastapi import Depends, FastAPI, Query
from fastapi.testclient import TestClient

app = FastAPI()


def pagination(limit: Annotated[int, Query(ge=1, le=100)] = 10) -> int:
    return limit


Limit = Annotated[int, Depends(pagination)]       # reusable alias


@app.get("/books")
def list_books(limit: Limit, q: Annotated[str | None, Query(max_length=50)] = None) -> dict:
    return {"q": q, "limit": limit}


client = TestClient(app)
print(client.get("/books", params={"q": "dune", "limit": 5}).json())
print(client.get("/books", params={"limit": 500}).status_code)
----
Source: https://fastapi.tiangolo.com/tutorial/query-params-str-validations/[FastAPI: Query Parameters and String Validations]

[source,text]
----
{'q': 'dune', 'limit': 5}
422
----

.Current: a PEP 695 type alias (0.128.2, Python 3.12 or later)

from typing import Annotated

from fastapi import FastAPI, Query

def list_books(size: PageSize = 20) -> dict[str, int]:

client = TestClient(app)
print(client.get("/books", params={"size": 7}).json(), client.get("/books", params={"size": 0}).status_code)
----

A related misunderstanding in older material is treating the password flow and the authorization code flow as one
thing. They are different OAuth2 flows: the password flow sends credentials to your own token endpoint, while the
authorization code flow redirects the user to an identity provider. The current form of the password flow is shown below.

[source,python]
.Old way (python-jose, passlib, utcnow, hardcoded key; not run)
----
import os
from datetime import datetime, timedelta

from jose import jwt
from passlib.context import CryptContext

SECRET_KEY = os.environ["SECRET_KEY"]          # never hardcode a key
pwd = CryptContext(schemes=["bcrypt"])
token = jwt.encode({"sub": "ana", "exp": datetime.utcnow() + timedelta(minutes=30)}, SECRET_KEY)
----
Source: https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/[FastAPI: OAuth2 with Password (and hashing), Bearer with JWT tokens]

The current example reads the signing key from the environment (generate one with `openssl rand -hex 32` and keep it in
your secret store), uses PyJWT and pwdlib, and shows that a missing token now answers 401.

[source,python]
.Current: PyJWT, pwdlib, timezone-aware expiry, 401 without credentials
----
import os
import secrets
from datetime import datetime, timedelta, timezone
from typing import Annotated

import jwt
from fastapi import Depends, FastAPI
from fastapi.security import OAuth2PasswordBearer
from fastapi.testclient import TestClient
from pwdlib import PasswordHash

# In a real app this comes from settings (openssl rand -hex 32); a random value keeps the demo self-contained.
SECRET_KEY = os.environ.get("BOOKSHELF_SECRET_KEY") or secrets.token_hex(32)
ALGORITHM = "HS256"

password_hash = PasswordHash.recommended()          # Argon2
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
app = FastAPI()


def create_token(subject: str) -> str:
    expire = datetime.now(timezone.utc) + timedelta(minutes=30)
    return jwt.encode({"sub": subject, "exp": expire}, SECRET_KEY, algorithm=ALGORITHM)


@app.get("/me")
def me(token: Annotated[str, Depends(oauth2_scheme)]) -> dict[str, str]:
    payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    return {"user": payload["sub"]}


hashed = password_hash.hash("a-test-password")
print(password_hash.verify("a-test-password", hashed))

client = TestClient(app)
print(client.get("/me").status_code)
print(client.get("/me", headers={"Authorization": f"Bearer {create_token('ana')}"}).json())
----
Source: https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/[FastAPI: OAuth2 with Password (and hashing), Bearer with JWT tokens]

[#data-and-dependencies]
== Data Access, Settings and Dependencies

The older way to reach a database was a module-global connection, with environment variables choosing between a fake
and a real module. The documented way is a session dependency with `yield` over SQLModel (the SQL tutorial was rewritten
in 0.115.1), configuration through `pydantic-settings`, and test doubles through `app.dependency_overrides`.

[cols="1,1,2,2,2,1",options="header"]
.Data access and dependency changes
|===
| Version | Date | Old way | New way | Covered on | Release notes

| 0.115.1
| 2024-10-12
| Module-global `sqlite3` connection; fake and real modules chosen by an environment variable
| SQLModel with a session dependency that uses `yield`; SQLAlchemy 2.0 underneath
| xref:backend/fastapi/sql-databases-with-sqlmodel.adoc[SQL Databases with SQLModel]
| https://fastapi.tiangolo.com/release-notes/#01151-2024-10-12[0.115.1]

| Not tied to a FastAPI release
| n/a

| Not tied to a FastAPI release
| n/a

from collections.abc import Iterator
from functools import cache, partial
from typing import Annotated

from fastapi import Depends, FastAPI
from fastapi.testclient import TestClient
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_prefix="BOOKSHELF_")
    database_url: str = "sqlite:///./bookshelf.db"


@cache
def get_settings() -> Settings:
    return Settings()


events: list[str] = []


def get_session(settings: Annotated[Settings, Depends(get_settings)]) -> Iterator[str]:
    events.append("open " + settings.database_url)
    try:
        yield "session"
    finally:
        events.append("close")


def greeting(prefix: str) -> str:
    return prefix + "!"


app = FastAPI()


@app.get("/books")
def books(session: Annotated[str, Depends(get_session, scope="function")]) -> dict[str, str]:
    return {"using": session}


@app.get("/hello")
def hello(text: Annotated[str, Depends(partial(greeting, "hello"))]) -> str:
    return text


client = TestClient(app)
print(client.get("/books").json(), events)
print(client.get("/hello").json())

app.dependency_overrides[get_session] = lambda: "fake-session"
print(client.get("/books").json())
----

[#errata]
== Corrected Forms for Frequent Mistakes

Printed books and tutorials contain code that never worked, and mistakes copy easily from one source to another. These
are the correct forms of the most frequent ones, so you can recognise and fix them in older code:

* Types come from `typing` or the standard library, and models from `pydantic`; `str` is the built-in string type, and
  `BaseModel` is the base class for models.
* Table metadata comes from SQLModel or SQLAlchemy as documented on
  xref:backend/fastapi/sql-databases-with-sqlmodel.adoc[SQL Databases with SQLModel].
* Streaming a large file means yielding it in chunks (see xref:backend/fastapi/streaming-json-lines-and-sse.adoc[Streaming, JSON Lines & SSE]),
  not reading the whole file into memory first.
* Every import should be checked against the official reference, and every example should run before it is trusted, which
  is how the examples on this page were prepared.

[#upgrade-checklist]
== Upgrade Checklist

* Pin FastAPI and read the release notes between your current and target versions, concentrating on entries marked
  breaking (0.106.0, 0.132.0, 0.137.0 among those listed above).
* Move to `fastapi[standard]` and the `fastapi` command; drop `fastapi-slim`.
* Remove Pydantic v1 code before upgrading past 0.126.0, using the Pydantic migration guide and `bump-pydantic`.
* Replace `on_event` with `lifespan`, `python-jose` and `passlib` with PyJWT and pwdlib, and `utcnow()` with
  `datetime.now(timezone.utc)`.
* Check tests that expected `403` for missing credentials, and clients that send JSON without a JSON `Content-Type`.
* Move `Query()` and `Depends()` defaults to `Annotated` gradually; both styles keep working.
* Re-run your tests with a warning filter set to error to find deprecated calls such as `ORJSONResponse` early.
