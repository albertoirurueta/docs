Welcome to the Messaging reference. *Messaging* is asynchronous, broker-mediated communication between
services: a producer publishes a message without waiting for a consumer to process it, and a *broker* takes on
the job of storing, routing and redelivering that message until it is handled. This decouples producers from
consumers in time, location and availability, and it underlies event-driven architectures, work distribution
across competing consumers, and integration between systems that otherwise share nothing.

The examples in this section are written and verified against **Apache Kafka 4.3.x**, **RabbitMQ 4.3.x**,
**Spring Boot 4.1.x**, **Spring for Apache Kafka 4.1.x**, **Spring AMQP 4.1.x** and **Spring Cloud Stream
5.0.x**.

If you are new to messaging, read xref:backend/messaging/getting-started.adoc[Getting Started with Messaging]
first, then xref:backend/messaging/messaging-models-and-patterns.adoc[Messaging Models and Patterns] and
xref:backend/messaging/delivery-guarantees.adoc[Delivery Guarantees] for the concepts every broker page builds
on. From there, read xref:backend/messaging/kafka-architecture.adoc[Kafka Architecture] and
xref:backend/messaging/rabbitmq-architecture-and-amqp-model.adoc[RabbitMQ Architecture and the AMQP Model] for
the two brokers this section covers in depth, xref:backend/messaging/kafka-vs-rabbitmq.adoc[Kafka vs. RabbitMQ]
to compare them directly, and finally the Spring Boot integration pages to map both onto Spring Boot 4.1.

This section is *broker- and protocol-first*, not framework-first: it documents what the brokers and the wire
protocols actually do, with plain Java client examples, before mapping any of it onto a framework. For the
Spring Boot services that use these brokers, see the sibling xref:backend/springboot/index.adoc[SpringBoot
Reference] -- in particular xref:backend/springboot/messaging-kafka.adoc[Messaging with Kafka] and
xref:backend/springboot/api-first-messaging.adoc[API-First: Messaging], which the Spring Boot integration pages
below link to rather than duplicate.

For messaging as a bridge into batch processing -- launching jobs from messages and distributing chunk
processing over a broker -- see xref:backend/spring-batch/spring-batch-integration.adoc[Spring Batch
Integration] in the sibling xref:backend/spring-batch/index.adoc[Spring Batch Reference].

For the equivalent mapping of this section's broker concepts onto Quarkus, see
xref:backend/quarkus/messaging.adoc[Messaging with SmallRye Reactive Messaging] in the sibling
xref:backend/quarkus/index.adoc[Quarkus Reference], listed again under "Other framework bindings" below.

== What's covered

=== Foundations

* xref:backend/messaging/getting-started.adoc[Getting Started with Messaging] -- the problem messaging solves,
  synchronous request/response vs. asynchronous messaging, brokered vs. brokerless, the shared vocabulary
  mapped across Kafka and RabbitMQ, running both brokers locally, and a first send/receive with each plain Java
  client.
* xref:backend/messaging/messaging-models-and-patterns.adoc[Messaging Models and Patterns] -- point-to-point
  and publish/subscribe as the two base models, request/reply on top of them, and the Enterprise Integration
  Patterns the rest of this section refers to, each mapped onto its Kafka and RabbitMQ realisation.
* xref:backend/messaging/delivery-guarantees.adoc[Delivery Guarantees] -- at-most-once, at-least-once and
  exactly-once from both the producer and the consumer side, acknowledgements and redelivery, duplicates and
  idempotent consumers, ordering, and durability, with a configuration comparison table.
* xref:backend/messaging/protocols.adoc[Messaging Protocols] -- AMQP 0-9-1, AMQP 1.0, the Kafka binary
  protocol, MQTT, STOMP, the RabbitMQ Stream protocol, WebSocket transports, and JMS/Jakarta Messaging, with a
  protocol-by-broker matrix.

=== Apache Kafka

* xref:backend/messaging/kafka-architecture.adoc[Kafka Architecture] -- events, topics, partitions and
  offsets, segments and the on-disk log, brokers, KRaft controllers and the metadata log, replication, retention,
  log compaction, and tiered storage.
* xref:backend/messaging/kafka-producers.adoc[Kafka Producers] -- the Producer API, the record accumulator and
  batching, the partitioner, `acks` and `min.insync.replicas`, the idempotent producer, retries, compression,
  and a plain-Java producer example.
* xref:backend/messaging/kafka-consumers.adoc[Kafka Consumers] -- consumer groups, the poll loop, partition
  assignment and rebalancing (including the broker-driven KIP-848 protocol), static membership, offsets and
  commits, and a plain-Java consumer example.
* xref:backend/messaging/kafka-share-groups.adoc[Kafka Share Groups] -- Queues for Kafka (KIP-932): share
  groups vs. consumer groups, record acquisition locks, per-record outcomes and lock renewal, delivery counts
  and poison-message protection, and a plain-Java `ShareConsumer` example.
* xref:backend/messaging/kafka-reliability-and-exactly-once.adoc[Kafka Reliability and Exactly-Once] -- the
  reliability toolkit end to end -- replication factor, `min.insync.replicas`, producer and consumer discipline
  -- then Kafka transactions (`transactional.id`, `read_committed`) and what exactly-once does and does not
  cover.
* xref:backend/messaging/kafka-streams.adoc[Kafka Streams] -- topology, `KStream`/`KTable`/`GlobalKTable`,
  stream-table duality, windowing, joins, state stores and changelog topics, exactly-once, and testing with
  `TopologyTestDriver`.
* xref:backend/messaging/kafka-connect.adoc[Kafka Connect] -- source vs. sink connectors, standalone vs.
  distributed workers, tasks, converters, single message transforms, error handling and the sink dead-letter
  queue, and the transactional-outbox pattern via CDC.
* xref:backend/messaging/kafka-serialization-and-schemas.adoc[Kafka Serialization and Schemas] --
  serializers/deserializers as a contract, bytes vs. String vs. JSON vs. Avro/Protobuf/JSON Schema, and the case
  for a schema registry.
* xref:backend/messaging/kafka-operations-and-monitoring.adoc[Kafka Operations and Monitoring] -- the CLI
  tools, partition-count decisions, dynamic configuration, key broker metrics and consumer lag, quotas, and
  geo-replication with MirrorMaker 2.
* xref:backend/messaging/kafka-security.adoc[Kafka Security] -- listeners and security protocols, TLS
  encryption and mTLS authentication, SASL mechanisms, ACLs, and multi-tenancy.
