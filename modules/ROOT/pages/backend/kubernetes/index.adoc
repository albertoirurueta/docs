Welcome to the Kubernetes reference. *Kubernetes* is an open-source system for running containerised
applications across a fleet of machines: you describe the desired state of your application in declarative
objects, and a set of controllers continuously reconciles the cluster towards that state -- scheduling Pods onto
nodes, replacing failed ones, rolling out new versions, balancing traffic and attaching storage. It grew out of
Google's internal Borg and Omega systems, was open-sourced in 2014 and is now the default platform for running
backend services at scale.

This section is for backend developers who already build container images (see the
xref:backend/docker/index.adoc[Docker reference]) and want to learn to deploy, operate and debug those workloads
on Kubernetes, from a local `kind` cluster to a production cluster. It explains the concepts, the `kubectl`
commands and the YAML manifests, and it links every example to the official documentation that backs it.

== Version baseline and release policy

The examples are written and checked against Kubernetes 1.37 (patch 1.37.1), `kubectl` 1.37, kind 0.33 with
`kindest/node:v1.37.0`, minikube 1.39, Helm 4.3, Kustomize 5.8 and Gateway API 1.6. Kubernetes ships a new minor
version roughly every four months, the project maintains release branches for the three most recent minor
versions, and each minor receives patch releases for about fourteen months; the version 1.38 release is planned
for 2026-12-16. Clients and nodes may run within a limited skew of the control plane, which
xref:backend/kubernetes/getting-started.adoc[Getting Started with Kubernetes] and
xref:backend/kubernetes/cluster-setup-and-administration.adoc[Cluster Setup and Administration] explain in detail.
Always check the release notes and the
https://kubernetes.io/docs/reference/using-api/deprecation-guide/[deprecated API migration guide] before upgrading,
and see xref:backend/kubernetes/whats-changed-and-migration.adoc[What's Changed and Migration] for what moved
since older tutorials were written.

== The Bookshelf scenario

Every example in this section deploys the same small application, *Bookshelf*, on a local `kind` cluster: a
`catalog-api`, a `reviews-api` and a `web` Deployment, PostgreSQL as a StatefulSet, Redis, and a `notifier` that
runs as a Job, a CronJob and a worker. Container images are neutral placeholders such as
`ghcr.io/example/bookshelf-catalog-api:1.0.0` and `postgres:18`, so nothing depends on real published images. The
scenario grows page by page and is assembled in xref:backend/kubernetes/bookshelf-end-to-end.adoc[Bookshelf End to
End].

== What's covered

=== Foundations

* xref:backend/kubernetes/introduction-and-architecture.adoc[Introduction and Architecture] -- why orchestration
  exists, the Borg and Omega lineage, declarative reconciliation, the control-plane and node components, and
  when not to use Kubernetes.

* xref:backend/kubernetes/getting-started.adoc[Getting Started with Kubernetes] -- installing kubectl, local
  clusters with kind, minikube and Docker Desktop, kubeconfig contexts and the first Bookshelf deployment.

* xref:backend/kubernetes/kubectl-essentials.adoc[kubectl Essentials] -- command structure, output formats and
  selectors, logs, exec and port-forward, dry-run, diff, server-side apply, patch and plugins.

* xref:backend/kubernetes/objects-and-the-api.adoc[Objects and the Kubernetes API] -- the object model, API
  groups and versions, namespaces, labels, selectors, annotations, owner references and finalizers.


=== Workloads

* xref:backend/kubernetes/pods.adoc[Pods] -- the unit of scheduling, lifecycle, init containers, native
  sidecars, multi-container patterns, environment variables and the Downward API.

* xref:backend/kubernetes/health-probes-and-lifecycle.adoc[Health Probes and Container Lifecycle] -- liveness,
  readiness and startup probes, lifecycle hooks and graceful termination.

* xref:backend/kubernetes/replicasets-and-deployments.adoc[ReplicaSets and Deployments] -- from
  ReplicationController to Deployment, rolling updates, rollout commands and revision history.

  update strategies.

* xref:backend/kubernetes/jobs-and-cronjobs.adoc[Jobs and CronJobs] -- batch Jobs, the one-shot,

== Bibliography

Every source used to write this section is listed below, each linked to its official website. The books were
consulted for the concept narrative, the structure and the bibliography only; neither is the primary source for
any command or manifest, and no text, listing or figure is copied from them. Every example is written against the
current official documentation. *Where a book and the official documentation disagree, the official documentation
wins.*

=== Books

* Rensin, D. K. _Kubernetes: Scheduling the Future at Cloud Scale_. O'Reilly Media, first edition, June 2015. ISBN
  978-1-491-93188-2. https://www.oreilly.com/library/view/kubernetes/9781492048718/[O'Reilly publisher page] (also
  https://www.oreilly.com/content/kubernetes-scheduling-the-future-at-cloud-scale/[the O'Reilly article]). A short,
  code-free primer from the Kubernetes 1.0 era; its mental model is lasting but its API details are badly out of
  date.
* Hightower, K., Burns, B. and Beda, J. _Kubernetes: Up and Running -- Dive into the Future of Infrastructure_, 1st
  edition. O'Reilly Media, September 2017. ISBN 978-1-491-93567-5.
  https://www.oreilly.com/library/view/kubernetes-up-and/9781491935668/[O'Reilly publisher page]. The copy
  consulted was the free sponsor sampler containing only five of the book's chapters, not the full book. The
  current edition is the 3rd edition (2022), available at
  https://www.oreilly.com/library/view/kubernetes-up-and/9781098110192/[the O'Reilly 3rd-edition page]. Its
  manifests target Kubernetes 1.5 to 1.7 and the retired `extensions/v1beta1` and `apps/v1beta1` APIs.
