:description: What changed in Kubernetes since the older books and tutorials -- a version and date table of outdated book material against the current approach, what is new, deprecated API removals by version, dockershim, PodSecurityPolicy, Ingress-NGINX, Endpoints, externalIPs, cgroup v1, IPVS, legacy package repositories, kubectl run generators, and how to find deprecated APIs in a cluster and in manifests.

Kubernetes ships about three minor releases a year and supports each for about 14 months. Older books and tutorials
(including the two O'Reilly books this section was cross-checked against) describe a Kubernetes that no longer
exists: they use removed API versions, removed `kubectl` behaviour and architecture that has since been replaced.
This page is the consolidated list of what changed, written against Kubernetes 1.37 ("Garhwal", released
2026-08-26, latest patch 1.37.1). Every version and date below was re-checked on 2026-09-30 against the
kubernetes.io release pages, the release notes and blogs, and the `kubernetes/website` and `kubernetes/kubernetes`
repositories. The currently supported minors are 1.37, 1.36 and 1.35, with 1.34 in maintenance mode until its end of
life on 2026-10-27, and 1.38 is scheduled for 2026-12-16. Re-verify anything that matters before relying on it:
the topic pages linked from each row give the current details, and xref:backend/kubernetes/index.adoc[the section landing page] gives the
reading path.

== Outdated in the books

Each row is a statement from one of the books, the version in which it stopped being true, and what to use
instead. "Book 1" is Rensin, *Scheduling the Future at Cloud Scale* (2015) and "Book 2" is the sampler of Hightower,
Burns and Beda, *Kubernetes: Up and Running* (2017).

[cols="3,2,1,4"]
|===
| Book (era) | Changed | Version and date | Current approach

| ReplicationController as the replication primitive (Book 1)
| Superseded
| Deployments GA in 1.9 (2017-12-15)
| ReplicaSet, always managed by a Deployment (`apps/v1`). See xref:backend/kubernetes/replicasets-and-deployments.adoc[ReplicaSets and Deployments].

| `kubectl rolling-update` with two ReplicationControllers (Book 1)
| Removed
| 1.18 (2020-03-25)
| `kubectl rollout status`, `history`, `undo`, `pause`, `restart` on a Deployment. See xref:backend/kubernetes/deployment-strategies.adoc[Deployment Strategies].

| `extensions/v1beta1` Deployment and ReplicaSet, `apps/v1beta1` StatefulSet (Book 2)
| Removed
| 1.16 (2019-09-18)
| `apps/v1`. See xref:backend/kubernetes/statefulsets.adoc[StatefulSets].

| `storage.k8s.io/v1beta1` StorageClass and the `volume.beta.kubernetes.io/storage-class` annotation (Book 2)
| Replaced
| `storage.k8s.io/v1` since 1.6
| `storage.k8s.io/v1`, `spec.storageClassName`, `storageclass.kubernetes.io/is-default-class`. See xref:backend/kubernetes/persistent-volumes-and-storage-classes.adoc[Persistent Volumes and Storage Classes].

| In-tree `gcePersistentDisk`, `azureDisk` and `nfs` volume plugins and provisioners (both books)
| Migrated to CSI; the cloud plugins were removed
| CSI migration over 1.17 to 1.27
| Container Storage Interface drivers (the cloud providers' drivers, or `csi-driver-nfs` for NFS).

| `kubectl run --restart=OnFailure` creating a Job, Services selecting `run:` labels (Book 2)
| Generators removed
| 1.18 (2020-03-25); `--filename` deprecated in 1.37
| `kubectl run` creates only a Pod. Use `kubectl create job` and `kubectl create deployment`, and the recommended `app.kubernetes.io/*` labels. See xref:backend/kubernetes/kubectl-essentials.adoc[kubectl Essentials].

| `kubectl get -a` (`--show-all`) (Book 2)
| Removed
| Long ago; not in any recent release
| Completed Pods are listed by default.

| `kubectl exec pod cmd` without `--` (Book 2)
| Removed
| Long-standing
| `kubectl exec pod -- cmd`.

| DNS names such as `mysql.svc.default.cluster` (Book 2, erratum)
| Was wrong
| n/a
| `<service>.<namespace>.svc.cluster.local`. See xref:backend/kubernetes/dns-and-service-discovery.adoc[DNS and Service Discovery].

| Portal IP and userspace kube-proxy round-robin (Book 1)
| Replaced
| nftables mode GA in 1.33 (2025-04-23); IPVS deprecated in 1.35 (2025-12-17)
| ClusterIP with kube-proxy in nftables mode (iptables still supported). See xref:backend/kubernetes/cluster-networking-and-cni.adoc[Cluster Networking and CNI].

| SkyDNS and kube2sky (Book 1)
| Replaced
| kube-dns, then CoreDNS default from 1.13
| CoreDNS.

| `CreateExternalLoadBalancer: true` (Book 1)
| Replaced
| Pre-1.0
| `type: LoadBalancer`. See xref:backend/kubernetes/services.adoc[Services].

| Pre-v1 `livenessProbe` fields (`enabled`, `type: http`) (Book 1)
| Replaced
| Pre-1.0
| `httpGet`, `tcpSocket`, `exec` and `grpc` probes, plus readiness and startup probes. See xref:backend/kubernetes/health-probes-and-lifecycle.adoc[Health Probes and Lifecycle].

| Docker as the node runtime; standalone cAdvisor (Book 1)
| dockershim removed
| 1.24 (2022-05-03)
| containerd or CRI-O through the CRI; cAdvisor is embedded in the kubelet. Docker-built images run unchanged.

| "Minions" (Book 1)
| Renamed
| Pre-1.0
| Nodes.

| "Ubernetes" and cluster federation (Book 1)
| KubeFed archived
| Archived project
| GitOps, Cluster API or managed fleet tools. See xref:backend/kubernetes/gitops-and-ci-cd.adoc[GitOps and CI/CD].

| Vagrant local clusters (Book 1)
| Replaced
| n/a
| kind, minikube, Docker Desktop, k3d. See xref:backend/kubernetes/getting-started.adoc[Getting Started].

| Google Container Engine, Azure Container Service, "AWS has no managed Kubernetes" (both books)
| Replaced
| n/a
| GKE, AKS, EKS. See xref:backend/kubernetes/managed-kubernetes-and-distributions.adoc[Managed Kubernetes and Distributions].

| Redis master and slave terminology (Book 2)
| Renamed
| n/a
| Primary and replica. See xref:backend/kubernetes/stateful-applications-in-practice.adoc[Stateful Applications in Practice].
|===

== Removals and deprecations worth knowing

* *Dockershim* (removed in 1.24, 2022-05-03). The kubelet no longer speaks to Docker Engine directly. Images built
  with Docker are OCI images and run unchanged on containerd or CRI-O; only tools that mounted the Docker socket, or
  nodes that used `docker` commands to inspect containers, need to change to `crictl`. See
  xref:backend/kubernetes/cluster-setup-and-administration.adoc[Cluster Setup and Administration].
* *PodSecurityPolicy* (removed in 1.25, 2022-08-23). Replaced by Pod Security Admission with the Pod Security
  Standards, or by ValidatingAdmissionPolicy and policy engines. See
  xref:backend/kubernetes/pod-security.adoc[Pod Security] and xref:backend/kubernetes/admission-control-and-policy.adoc[Admission Control and Policy].
* *Ingress-NGINX* (best-effort maintenance ended March 2026). No further releases, bugfixes or security updates;
  existing installs keep running. The Ingress API is frozen, not removed. Migrate to Gateway API, for example with
  the `ingress2gateway` tool. See xref:backend/kubernetes/ingress.adoc[Ingress].
* *Endpoints API* (deprecated in 1.33, 2025-04-23). The v1 Endpoints API still works and will not be removed, but
  new code should read EndpointSlices.
* *Service `externalIPs`* (marked deprecated in the Service documentation at 1.36, 2026-04-22). The field has been
  discouraged since 1.21 because of CVE-2020-8554; use a load balancer or Gateway API instead, and consider the
  `DenyServiceExternalIPs` admission controller. The 1.36 announcement describes a planned removal, but the 1.37
  changelog contains no removal, so the field still exists on 1.37.
* *cgroup v1* (maintenance mode in 1.31, deprecated in 1.35). The kubelet sets `failCgroupV1` to true by default
  from 1.35, so nodes refuse to start on cgroup v1 unless it is set to false. Move nodes to cgroup v2.
* *kube-proxy IPVS mode* (deprecated in 1.35, 2025-12-17). Migrate to nftables (GA in 1.33); iptables is still the
  default on Linux, and kube-proxy warns when no mode is set explicitly.
* *Legacy package repositories* (`apt.kubernetes.io` and `yum.kubernetes.io`, frozen on 2023-09-13). Use the
  community `pkgs.k8s.io` repositories, which are versioned per minor release.
* *`kubectl run` generators* (removed in 1.18, 2020-03-25). `kubectl run` creates a Pod; the ignored `--filename`
  flag was deprecated in 1.37.

== Finding deprecated APIs

=== In a running cluster

The API server counts every request to a deprecated API in a metric, which is the authoritative view of what clients
are doing right now:

[source,bash]
----
kubectl get --raw /metrics | grep apiserver_requested_deprecated_apis
----

[source,text]
----
apiserver_requested_deprecated_apis{group="policy",removed_release="1.25",resource="podsecuritypolicies",subresource="",version="v1beta1"} 1
----

Source: https://kubernetes.io/docs/reference/using-api/deprecation-guide/#locate-use-of-deprecated-apis[Kubernetes Docs -- Locate use of deprecated APIs]

The metric names the `removed_release`, so sort on it before an upgrade. To learn which client sent the request, turn
on audit logging, where each event carries an `k8s.io/deprecated` annotation. Third-party tools fill the rest of the
picture: *kubent* scans the live cluster, and *pluto* scans manifests and Helm releases:

[source,bash]
----
kubent
pluto detect-helm -o wide
----

=== In manifests

Scan Git before the cluster does: `pluto detect-files -d k8s/`, `kubectl apply --dry-run=server -f` (the server
reports warnings about deprecated versions to the client) and `kubectl convert` rewrite old manifests. The API
server also returns a `Warning:` header on any call to a deprecated API, which `kubectl` prints. In CI, validate
against the target version's schema with a tool such as kubeconform. Upgrade one minor release at a time and read the
release notes first; see xref:backend/kubernetes/cluster-setup-and-administration.adoc[Cluster Setup and Administration] for the upgrade sequence.
