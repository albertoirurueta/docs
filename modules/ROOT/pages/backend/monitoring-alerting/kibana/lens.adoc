Checked on 2026-11-09 against Kibana 9.5.x.

Lens is the editor that Kibana opens by default when you add a chart to a dashboard. It is where the Bookshelf "service
health" panels (request rate, 5xx ratio, latency percentiles, error logs by route) are built in the Kibana lab. Choosing
the right chart for a question is covered in
xref:backend/monitoring-alerting/choosing-visualizations.adoc[Choosing Visualizations]; this page explains the editor
itself, what each chart asks Elasticsearch for, and the features that matter for monitoring: formulas for ratios,
time shift for "versus last week", reference lines for SLO thresholds and annotations for deployments. The Grafana
counterpart is xref:backend/monitoring-alerting/grafana/visualizations-graphs-and-charts.adoc[Grafana Graphs and Charts].
Panels that Lens does not cover are in
xref:backend/monitoring-alerting/kibana/maps-vega-and-other-panels.adoc[Maps, Vega & Other Panels], and the older editors it
replaces are in
xref:backend/monitoring-alerting/kibana/legacy-editors-canvas-and-graph.adoc[Legacy Editors, Canvas & Graph].

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens[Kibana: Lens visualizations]. Lens is generally
available on Serverless and on the Elastic Stack.

== Two modes: point-and-click and query

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens[Kibana: Lens visualizations] (introduction).

*Point-and-click.* You pick a data view (see xref:backend/monitoring-alerting/kibana/data-views-and-discover.adoc[Data Views & Discover]), drag
fields into the layer pane and choose aggregations. Dragging a field selects an aggregation for you (Date histogram for a
time field, Intervals for a number, Top values for a keyword), and the *Suggestions* strip proposes alternative chart types
for the same data. New visualizations start as a bar or line chart. This mode is the quickest way to answer a question on a
known data view, and it is the one that exposes formulas, time shift and the other features below.

*Query mode.* You write an ES|QL or PromQL query and then map the result columns to chart dimensions. Choose it for
queries across several indices, complex filtering and custom calculations. The ES|QL flavour has its own page,
xref:backend/monitoring-alerting/kibana/esql-visualizations-and-variable-controls.adoc[ES|QL Visualizations & Variable Controls];
the PromQL command is documented at
https://www.elastic.co/docs/reference/query-languages/esql/commands/promql[ES|QL: PROMQL] and the query languages are compared in
xref:backend/monitoring-alerting/kibana/querying-with-kql-esql-and-promql.adoc[Querying with KQL, ES|QL & PromQL].

Lens visualizations can also be created and managed programmatically through the Visualizations API
(Serverless GA; on the Stack it was preview in 9.4 and is generally available since 9.5), which is the route used in
xref:backend/monitoring-alerting/kibana/dashboards-as-code.adoc[Dashboards as Code].

== Chart types and the aggregations behind them

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#lens-visualization-types[Kibana: Lens visualization types]
and the per-chart pages under https://www.elastic.co/docs/explore-analyze/visualize/charts/bar-charts[Kibana: Build bar charts].

Every chart is a front end for an Elasticsearch aggregation (see xref:database/elasticsearch/aggregations.adoc[Aggregations]
and xref:backend/monitoring-alerting/metric-types-and-aggregation.adoc[Metric Types and Aggregation]): *bucket* aggregations
group documents (a `terms` aggregation per route, a `date_histogram` per minute, numeric intervals, KQL filters), and
*metric* aggregations compute a number per bucket (count, average, sum, min, max, median, percentile, unique count). A
dimension in the layer pane is one of these two kinds, and the chart type decides how many of each it needs.

Lens does not list a state timeline equivalent; status over time is usually a heat map or a bar chart with a threshold line.

*What can go wrong.* A `terms` bucket returns only the top values (the default depends on the version: 9 values on Serverless and on
the Stack since 9.4, and 5 for the first and 3 for further dimensions before that), so anything below is folded into *Other* or
dropped; raise the number or aggregate by a lower-cardinality field. An *Include empty rows* setting controls whether a
time series shows zero buckets (off by default for bar charts on the Stack since 9.5). Field names also matter: bucketing
by a `text` field fails, so use its keyword sub-field or a keyword mapping (see
xref:database/elasticsearch/mapping-and-field-types.adoc[Mapping and Field Types]).

== Breakdowns

Source: https://www.elastic.co/docs/explore-analyze/visualize/charts/bar-charts#breakdown-options[Kibana: Bar charts, breakdown options].

A breakdown splits one chart into a series per value of a field. For XY charts the options are *Top values* (up to four fields),
*Date histogram*, *Intervals*, *Filters* or *Terms* ranked by count, alphabetical order, rarity, significance or a custom
metric, with an ascending or descending direction, include and exclude lists and an optional *Other* group. The *Collapse
by* setting merges the values of a dimension into one number (sum, min, max or average) when a chart needs the dimension for
sorting but not for display. For monitoring, break down by a low-cardinality attribute such as route template or status class;
a breakdown by user ID or raw URL produces an unreadable legend and an expensive query (see
xref:backend/monitoring-alerting/storage-retention-and-cost.adoc[Storage, Retention and Cost] on cardinality).

== Formulas

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#use-formulas-to-perform-math[Kibana: Use formulas to perform math].

A formula combines aggregations and maths in one dimension. It is how Lens computes ratios, which a plain count cannot do.
The documentation's filter-ratio example is the shape of the Bookshelf 5xx ratio (the field name depends on how the lab maps
the telemetry; use the one Discover shows):

[source,text]
----
count(kql='http.response.status_code >= 500') / count()
----

Set the *Value format* of the dimension to *Percent*, add a reference line at 0.05 for the lab's 5 % threshold (see
below) and the chart reads like the Grafana panel for the same alert. Two further documented patterns are a week-over-week
comparison, which repeats an aggregation with `+shift='1w'+`, and a percent of total, which divides a sum by
`overall_sum` of the same sum:

[source,text]
----
percentile(system.network.in.bytes, percentile=99) /
percentile(system.network.in.bytes, percentile=99, shift='1w')

sum(products.base_price) / overall_sum(sum(products.base_price))
----

Reference: https://www.elastic.co/docs/explore-analyze/visualize/lens#use-formulas-to-perform-math[Kibana: Use formulas to perform math].
For latency, `percentile(<latency field>, percentile=95)` follows the same form; Elasticsearch computes percentiles
approximately, and a percentile of per-minute buckets cannot be averaged into a longer window (see
xref:backend/monitoring-alerting/metric-types-and-aggregation.adoc[Metric Types and Aggregation]). The *Formula reference* icon in
the editor lists every function and its arguments, including moving averages, counter rates and differences; it is the
authority for the functions available in your version.

*What can go wrong.* A formula divides bucket by bucket, so an empty bucket gives no point rather than zero; the Lens FAQ on
gaps and *Include empty rows* explains the options. The `kql=` argument filters inside the formula only: it is separate from the
query bar, which filters the whole chart. Counter metrics sent as OpenTelemetry cumulative sums need a rate function, not a plain
sum, otherwise the chart climbs forever (see xref:backend/monitoring-alerting/metric-types-and-aggregation.adoc[Metric Types and Aggregation]).

== Time shift

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#compare-differences-over-time[Kibana: Compare differences over time].

Time shift compares the current value with the value one interval earlier. Open the dimension, expand *Advanced* and enter a
*Time shift* such as `1h`, `1d` or `1w`; the shifted series is drawn alongside the live one. It answers "is this traffic
normal for a Monday morning?" without a second query, and it is the Kibana counterpart of Grafana's query-option time shift.
In query mode the equivalent is a single `STATS` with per-aggregation `WHERE` filters anchored to `?_tend`, documented at
https://www.elastic.co/docs/explore-analyze/visualize/esorql#esql-viz-time-shift[Kibana: ES|QL time shift].

== Reference lines

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#add-reference-lines[Kibana: Add reference lines].

Reference lines mark a value on any chart that has axes. Open *Add layer* and choose *Reference lines*, then place the line at a
*Static* value, at a value computed by a quick function (for example the average of the series) or by a *Formula*. Icon, colour,
line style and fill above or below are configurable. For Bookshelf, draw the lab's thresholds: 0.05 on the 5xx ratio panel and
0.5 seconds on the p95 latency panel, so the dashboard shows the alert limit next to the data (the SLO-linked alerts are in
xref:backend/monitoring-alerting/kibana/observability-rules.adoc[Observability Rules]). A line that is typed in by hand drifts from the rule
it mirrors, so keep both values in one documented place.

== Annotations

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#add-annotations[Kibana: Add annotations].

Annotations call out events on a chart. In an *Annotations* layer you place them at a *Static date* (a point or a range) or with a
*Custom query*: a KQL query against any data view plus the field that holds the target date, so every document that matches
becomes an annotation. A deployment marker is the typical use: index deployment events (one document per release) in a small
data stream and annotate the latency chart with them, which turns "latency doubled at 14:05" into "latency doubled right after
release 1.4.2". Annotation groups can be saved to the Visualize library and shared by several charts, and a change to the group
applies to all of them. Annotation layers are a preview feature on the Stack.

== Colour mapping, filters and sampling

Source: https://www.elastic.co/docs/explore-analyze/visualize/lens#assign-colors-to-terms[Kibana: Assign colors to terms] and
https://www.elastic.co/docs/explore-analyze/visualize/lens#improve-visualization-loading-time[Kibana: Improve visualization loading time].

* *Colour mapping* fixes a colour per term so that a status class keeps its colour whatever the filters or sort order: 5xx always
  red, 2xx always green. It works on tables, XY breakdowns, partition charts and tag clouds, with categorical or gradient modes
  and palettes such as Elastic, Severity and the legacy Kibana palettes. It is GA on Serverless and on the Stack since 9.1
  (preview in 9.0); the Severity and line-optimised palettes are GA on the Stack since 9.4. The page also warns about colour contrast.
* *Filters* come from the query bar (the whole chart), the Filters function (per layer), legend clicks and filter pills.
* *Sampling* (layer settings, a slider) trades accuracy for speed on very large data sets; it is a preview feature on the Stack.
  Do not use it on a panel that feeds a decision about an alert threshold, since the numbers are estimates.
* *Open in Discover* and *Inspect* show the documents and the Elasticsearch requests behind a chart; Inspect can open the request
  in Dev Tools Console, the quickest way to see which aggregation a chart sent.

== Verifying in the lab

With the `kibana` profile of xref:backend/monitoring-alerting/hands-on-lab.adoc[the hands-on lab] running and the load generator on:

. Open *Dashboards*, create a dashboard and add a Lens panel on the lab's data view; drag `@timestamp` to build a request-count
  line chart, and confirm it moves while the load generator runs.
. Add the 5xx formula above, set *Value format* to *Percent*, add a reference line at 0.05 and break the chart down by route.
. Use *Inspect > Requests* and check that the request contains a `date_histogram` and, for the formula, a filter aggregation.
. Stop the application, wait a few minutes and observe the gap in the series; this is the symptom the "no data" alert of the lab detects.

== In the books

Shah (_Kibana 8.x Quick Start Guide_, chapter 4) teaches Lens as drag and drop of fields onto a workspace, explains the layer
pane and quick functions, and then shows that metric and bucket aggregations are what the charts ask Elasticsearch for. Konda
(_Elasticsearch in Action_, chapter 13) and Paro (_Elasticsearch 7.0 Cookbook_, chapter 7) describe those same metric, bucket
and pipeline aggregations from the REST side, which is the vocabulary behind the table above. What has changed since: the books
predate formulas with `shift`, reference lines and annotation layers, colour mapping, the query mode and the Visualizations API,
and Paro's Elasticsearch 7 request syntax needs adapting to current releases. For the REST syntax itself use
xref:database/elasticsearch/aggregations.adoc[Aggregations].
