= Kibana Guide: Spaces, Roles and Users
:description: Step-by-step guide to Kibana 9.5: create the space Guide ops with the Observability solution view, a role that reads the Bookshelf log index and has read access to the space, a user with that role, and check what the user sees after signing in.

Checked on 2026-11-11 against Kibana 9.5.x.

== What you build

You split the lab into a separate working area. You create a space called *Guide ops* whose navigation is focused on Observability, a role `guide-bookshelf-viewer` that can read the Bookshelf log index and has read access to that space, and a user `guide-viewer` with that role. After you sign in as that user, you see only the space and the data you granted.

== Before you start

* Start the Kibana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile kibana up -d
----
* Open http://localhost:5601 and sign in as `elastic` with the password `lab-elastic-password`. When Kibana opens its full-screen
  welcome page, click *Explore on my own*.
* Do the previous guide, xref:backend/monitoring-alerting/kibana/guide-observability-apps-tour.adoc[Tour of the Observability apps], and the guide that creates the data view, xref:backend/monitoring-alerting/kibana/guide-data-views-and-file-upload.adoc[Upload a file and create a data view]. The last steps use the data view *Bookshelf logs (guides)*.
* Spaces are included in every licence, and so are roles and users of the built-in realm; the lab runs a trial licence anyway. Roles and users need a user with the `superuser` role, which is the `elastic` user of the lab.
* The guide was checked on Elasticsearch and Kibana 9.5.6. The figures are drawings of the Kibana 9.5 user interface, not screenshots, so small details can differ from your screen.
  The choices of the solution view, the *Assign to space* flyout, the *Saved objects* list and the account menu are drawn generically; look for a control by its name when it is not where a figure shows it.
  A highlighted box with a number marks the control of the step with the same number.

== Steps

The guide works in *Stack Management*, in the pages *Spaces*, *Roles*, *Users* and *Saved objects*, and ends in a second browser session. Use a private window or a second browser profile for the last phase if you want to keep the `elastic` session open. A space has its own saved objects, so the guide copies the data view into the new space.

=== Create the space

. Click the menu button (*Toggle primary navigation*) at the left of the second bar.
. Under *Management*, click *Stack Management*.
+
image::monitoring-alerting-kibana-guide-k18-01-primary-navigation.svg["Kibana 9.5 with the primary navigation open and the Management section listing Dev Tools, Workflows, Integrations, Fleet, Osquery, Stack Monitoring, Cloud Connect, Stack Management and Streams; callout 1 marks the menu button of the second bar and callout 2 marks Stack Management",width=900]
. In the menu of *Stack Management*, under *Kibana*, click *Spaces*, then click the button that creates a space. The page *Create space* also opens directly at http://localhost:5601/app/management/kibana/spaces/create.
. In the section *Describe this space*, type `Guide ops` in *Name*.
. Check that *URL identifier* reads `guide-ops`. Kibana fills it from the name, and it cannot be changed once the space exists; edit it now if it differs.
+
image::monitoring-alerting-kibana-guide-k18-02-describe-space.svg["Create space page of Kibana 9.5 with the section Describe this space: the Name field holding Guide ops is marked by callout 4, the URL identifier field holding guide-ops with the hint that it cannot be changed is marked by callout 5",width=900]
. In the section *Select solution view*, open the select *Solution view* and choose *Observability*. The space then shows the navigation of the Observability solution only.
+
image::monitoring-alerting-kibana-guide-k18-03-solution-view.svg["Create space page of Kibana 9.5 with the section Select solution view and the Solution view select open with the choices Observability, Security and Search; the select is marked by callout 6",width=900]
. Leave *Set feature visibility* as it is. Every group (*Analytics* 10/10, *Alerting V2* 4/4, *Elasticsearch* 6/6, *Observability* 8/8, *Security* 9/9 and *Management* 26/26) stays fully visible. Click *Create space*.
+
image::monitoring-alerting-kibana-guide-k18-04-feature-visibility.svg["Create space page of Kibana 9.5 with the section Set feature visibility listing the groups Analytics 10 of 10, Alerting V2 4 of 4, Elasticsearch 6 of 6, Observability 8 of 8, Security 9 of 9 and Management 26 of 26; the Create space button is marked by callout 7",width=900]

=== Create the role

[start=8]
. In *Stack Management*, under *Security*, click *Roles*, then click the button that creates a role. The page *Create role* also opens directly at http://localhost:5601/app/management/security/roles/edit.
. Type `guide-bookshelf-viewer` in *Role name*. The name cannot be edited once the role is created.
. Type `Read the Bookshelf logs` in *Role description*.
+
image::monitoring-alerting-kibana-guide-k18-05-role-name.svg["Create role page of Kibana 9.5 with the Role name field holding guide-bookshelf-viewer, marked by callout 9, and the Role description field holding Read the Bookshelf logs, marked by callout 10",width=900]
. In the section *Index privileges* of the data layer (*Elasticsearch*), click *Add index privilege*.
. In *Indices*, type `logs-generic.otel-default` and press Enter.
. In *Privileges*, choose `read` and `view_index_metadata`. The first lets the user search the index, the second lets Kibana read its field list for a data view.
. In the section *Application layer - Kibana*, which says "This role does not grant access to Kibana", click *Assign to space*.
+
image::monitoring-alerting-kibana-guide-k18-06-index-privileges.svg["Create role page of Kibana 9.5 with the Index privileges section: the button Add index privilege is marked by callout 11, the Indices field holding logs-generic.otel-default by callout 12 and the Privileges field holding read and view_index_metadata by callout 13; below, in the Application layer - Kibana section, the button Assign to space is marked by callout 14",width=900]
. In the flyout that opens, choose the space `Guide ops` in *Spaces*.
. Choose the privilege `Read` for the Kibana features of the space.
. Confirm with the button at the bottom of the flyout (*Assign*).
+
image::monitoring-alerting-kibana-guide-k18-07-assign-to-space.svg["Flyout Assign role to space on the Create role page of Kibana 9.5: the Spaces field holding Guide ops is marked by callout 15, the privilege choice Read is marked by callout 16 and the Assign button is marked by callout 17",width=900]
. The section *Application layer - Kibana* now lists the space `Guide ops` with the privilege `Read`. Click *Create role*.
+
image::monitoring-alerting-kibana-guide-k18-08-create-role.svg["Create role page of Kibana 9.5 after the assignment: the Application layer - Kibana section lists the space Guide ops with the privilege Read; the Create role button is marked by callout 18",width=900]

=== Create the user

[start=19]
. In *Stack Management*, under *Security*, click *Users*, then click the button that creates a user. The page *Create user* also opens directly at http://localhost:5601/app/management/security/users/create.
. In the section *Profile*, type `guide-viewer` in *Username*.
. Type `Guide Viewer` in *Full name*.
. In the section *Password*, type `guide-viewer-password` in *Password*. The password must be at least 6 characters.
. Type the same password in *Confirm password*.
. In the section *Privileges*, choose the role `guide-bookshelf-viewer` in *Roles*.
. Click *Create user*.
+
image::monitoring-alerting-kibana-guide-k18-09-create-user.svg["Create user page of Kibana 9.5 with the Profile section (Username guide-viewer marked by callout 20, Full name Guide Viewer marked by callout 21), the Password section (Password marked by callout 22 and Confirm password marked by callout 23), the Privileges section with the role guide-bookshelf-viewer in the Roles field marked by callout 24, and the Create user button marked by callout 25",width=900]

=== Copy the data view into the space

[start=26]
. In *Stack Management*, under *Kibana*, click *Saved objects*.
. In the row of the data view *Bookshelf logs (guides)*, open the actions and choose the action that copies the object to a space.
+
image::monitoring-alerting-kibana-guide-k18-10-saved-objects.svg["Saved objects page of Kibana 9.5 listing the dashboard Bookshelf (guides) and the data view Bookshelf logs (guides); the Actions cell of the data view row is marked by callout 27",width=900]
. In the dialog, select the space `Guide ops` and confirm the copy.

=== Sign in as the new user

[start=29]
. Open the account menu (the avatar at the right of the first bar) and click *Log out*.
+
image::monitoring-alerting-kibana-guide-k18-11-account-menu.svg["Account menu of Kibana 9.5 open from the avatar at the right of the first bar with the user name elastic and the entry Log out, which is marked by callout 29",width=900]
. Sign in as `guide-viewer` with the password `guide-viewer-password`. If Kibana asks which space to open, choose *Guide ops*.

== Check the result

Kibana opens in the space *Guide ops* with the navigation of the Observability solution: *Overview*, *Alerts*, *SLOs*, *Cases*, *Logs*, *Infrastructure* and *Applications*. Open *Logs* → *Discover* and choose the data view *Bookshelf logs (guides)*: the log records of the lab appear, because the role reads `logs-generic.otel-default`. Then check what the user cannot do: *Stack Management* does not offer *Roles* or *Users* to this user, and a request to open http://localhost:5601/app/management/security/users/create is refused.

If Discover shows no records, force some traffic and widen the time picker to *Last 1 hour*:

[source,bash]
----
curl -X POST localhost:8090/mode/failing
----

Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Create a role without the index privilege and with the Kibana privilege *Read* only: the user opens Discover but sees no data.
* Hide a feature in *Set feature visibility* when you create or edit the space, for example *Machine Learning* under *Analytics*, and its entry disappears from the navigation of the space for everyone.
* Assign the same role to several spaces, with a different privilege in each, from the *Assign to space* flyout.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|The space shows the classic navigation, not the Observability one
|The solution view of the space was left on its default when the space was created.
|Edit the space in *Spaces*, choose *Observability* in *Solution view*, and save.

|The user signs in and Kibana reports that there is no access
|The role has no Kibana privilege on a space, or the user has no role.
|Open the role and check *Application layer - Kibana*, then open the user and check *Roles*.

|Discover offers no data view
|The data view lives in the *Default* space and was not copied to *Guide ops*.
|Copy *Bookshelf logs (guides)* to the space from *Saved objects*, or create a data view in the space with an account that may manage data views.

|Discover shows the data view but an error about the index
|The index privilege is missing or names another index.
|Check *Indices* and *Privileges* in the role: `logs-generic.otel-default` with `read` and `view_index_metadata`.
|===

== Clean up

The guide creates a space, a role and a user in the lab. To remove them, sign in again as `elastic` and open *Stack Management*: delete the user `guide-viewer` in *Users*, the role `guide-bookshelf-viewer` in *Roles*, and the space *Guide ops* in *Spaces*. Deleting a space also deletes the saved objects inside it, such as the copy of the data view. Stopping the profile with `docker compose --profile kibana down -v` removes all of them with the volumes.
