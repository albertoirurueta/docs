= Kibana
:description: What Kibana is (the UI of the Elastic Stack and of Elastic Observability, on Stack and Serverless), the 9.5 version baseline with what was removed or renamed in 9.x, and a reading path through the Kibana pages of the Monitoring & Alerting section.
:keywords: Kibana, Kibana 9.5, Elastic Stack, Elastic Observability, Elastic Cloud Serverless, solution views, Lens, ES|QL, alerting, rules, connectors, dashboards, SLO, EDOT, what's new, breaking changes, Bookshelf

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-09 against Kibana 9.5.x.

Kibana is the web interface of the Elastic Stack. It stores no telemetry itself: metrics, logs and traces live in Elasticsearch
data streams, and Kibana queries them, turns the answers into charts, dashboards, service maps and service-level objectives, and
runs rules that watch the same data and notify people when something is wrong. The official documentation describes it as the
user interface for Elastic solutions and Serverless projects that also manages other Elastic Stack components. This subsection
teaches Kibana from the point of view of someone who must build monitoring for a service: how to run it, how to model access, how to
get data in, how to explore and visualize it, and how to alert on it, with the Bookshelf example from the
xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] as the running case.

The concepts that are shared with Grafana (signals, metric types, SLOs, alert design) are on the section root pages and are not
repeated here; start with xref:backend/monitoring-alerting/observability-fundamentals.adoc[Observability Fundamentals] if the
vocabulary is new. Elasticsearch itself (indices, mappings, query DSL, cluster operations) is covered in
xref:database/elasticsearch/index.adoc[the Elasticsearch section]; this subsection links there instead of repeating it, and only
explains what is specific to monitoring and alerting with Kibana.

Source: https://www.elastic.co/docs/get-started/the-stack[The Elastic Stack] (section "Kibana", anchor `#stack-components-kibana`)
and https://www.elastic.co/docs/solutions/observability[Elastic Observability].

== Where Kibana runs

The same Kibana code base is delivered in three forms, and the documentation labels each feature with the forms where it exists.
This is why almost every page in this subsection says whether a feature is available on the Elastic Stack, on Serverless or on both.

[cols="1,3",options="header"]
|===
| Form
| What it means for monitoring

| Elastic Stack, self-managed
| You install Elasticsearch, Kibana and the ingest components yourself (packages, archives, Docker or Kubernetes), keep their
  versions identical, and own `kibana.yml`, encryption keys, upgrades and capacity. This is what the lab uses.
  See xref:backend/monitoring-alerting/kibana/installation-and-configuration.adoc[Installation & Configuration].

| Elastic Cloud Hosted
| The Elastic Stack operated by Elastic. You choose the version and size of a deployment; Kibana settings are changed through the
  deployment instead of by editing files on a server. Features follow the Stack versions (9.5.x here).

| Elastic Cloud Serverless
| Observability, Search and Security *projects* with no versions, nodes or shards to manage. Kibana is included, features arrive
  first on Serverless, and some Stack-only features (for example the legacy visualization editors, Watcher and index lifecycle
  management) do not exist there. Roles are managed in the Cloud organization, and the Spaces limit is fixed.
|===

Source: https://www.elastic.co/docs/get-started/the-stack[The Elastic Stack] (section "Deployment options") and
https://www.elastic.co/docs/deploy-manage/manage-spaces[Spaces] (section "Serverless differences").

The Observability documentation lists logs, metrics, infrastructure monitoring, APM and traces, synthetic monitoring, streams, AIOps,
alerting, SLOs, cases and profiling as parts of Elastic Observability and shows both Elastic Cloud Serverless and the Elastic Stack
as generally available for it. Stack deployments choose how much of that menu a user sees through *solution views* per space
(see xref:backend/monitoring-alerting/kibana/spaces-roles-and-privileges.adoc[Spaces, Roles & Privileges]).

Source: https://www.elastic.co/docs/solutions/observability[Elastic Observability overview].

== Version baseline: 9.5

The latest patch on the check date is 9.5.6 (security advisory ESA-2026-205, dated 2026-11-03, names 9.4.9 and 9.5.6). Version 9.5.0
became generally available on 2026-08-04, and 9.6 is not released, so anything marked "9.6+" or "Planned" in these pages is not
available yet. All pages in this subsection were checked against the 9.5 documentation at `https://www.elastic.co/docs/`. The
documentation moved to this address, and the older `+elastic.co/guide/en/kibana/...+` pages are frozen references for 8.x and earlier;
a page in this subsection cites one only when nothing newer exists, and says so. The Docker image used in the lab is
`docker.elastic.co/kibana/kibana:9.5.6`, paired with Elasticsearch 9.5.6, because all Elastic Stack components must run the same version.

Source: https://www.elastic.co/docs/release-notes/kibana[Kibana release notes] and
https://www.elastic.co/blog/whats-new-elastic-9-5-0[What's new in Elastic 9.5].

== What changed in 9.x

Most books and many articles describe Kibana 7 or 8, so this list is the quickest way to recognise advice that no longer applies.
Each row names the official page it was taken from.

[cols="1,4,2",options="header"]
|===
| Version
| Change
| Reference

| 9.0
| The deprecated `+/api/alerts/*+` endpoints were removed and return 404; use `+/api/alerting/*+` (for example `+GET /api/alerting/rules/_find+`
  and `+GET /api/alerting/rule_types+`). Several `xpack.actions`, `xpack.alerting` and `xpack.alerts` settings were removed, among them
  `xpack.actions.whitelistedHosts` and `xpack.alerting.defaultRuleTaskTimeout`.
| https://www.elastic.co/docs/release-notes/kibana/breaking-changes[Kibana breaking changes] (9.0.0, Alerting)

| 9.0
| Logs Explorer was removed (use Discover), and so were the Logs Stream app, the Observability logs settings page and the logs stream
  dashboard panel. Creating new scripted fields on the data view page was removed; existing ones can still be edited or deleted. Use
  runtime fields or ES\|QL. The legacy documents table in Discover was removed.
| https://www.elastic.co/docs/release-notes/kibana/breaking-changes[Kibana breaking changes] (9.0.0, Logs Explorer, Scripted fields)

| 9.0
| When TLS is enabled for Kibana, HTTP/2 becomes the default protocol; deployments on HTTP/1 or without TLS get a deprecation warning.
| https://www.elastic.co/docs/release-notes/kibana/deprecations[Kibana deprecations] (9.0.0)

| 9.2
| Maintenance windows are generally available, with KQL filters in place of rule categories. (The maintenance-windows page and the
  rules overview page label the status differently; this subsection follows the dedicated page.)
| https://www.elastic.co/docs/explore-analyze/alerting/alerts/maintenance-windows[Maintenance windows]

| 9.3
| Flapping detection can be set per rule or per space (9.0 to 9.2 had only a global setting), and alert tags are generally available.
| https://www.elastic.co/docs/explore-analyze/alerting/alerts/create-manage-rules[Create and manage rules]

| 9.4
| Acknowledging alerts is generally available on the Elastic Stack, ES\|QL `TS` queries for time series data are generally available
  (preview in 9.2 and 9.3), and Discover sessions can be dashboard panels on the Stack. The AI connector workflow steps
  `+inference.*+`, `+bedrock.*+`, `+gen-ai.*+` and `+gemini.*+` are deprecated.
| https://www.elastic.co/docs/explore-analyze/alerting/alerts/view-alerts[View and manage alerts] and
  https://www.elastic.co/docs/reference/query-languages/esql/commands/ts[ES\|QL TS command]

| 9.5
| Per-alert snooze is generally available and replaces per-alert mute. The dashboards-as-code workflow is generally available on the
  Stack. The EDOT Collector is built into Elastic Agent. The OpenAI, Amazon Bedrock, Google Gemini and Inference connector types are
  deprecated (existing connectors keep working and show a warning); Elasticsearch inference endpoints are recommended for new AI
  integrations. `elastic.apm` settings are deprecated in favour of OpenTelemetry, with removal planned for 10.0.0.
| https://www.elastic.co/docs/release-notes/kibana/deprecations[Kibana deprecations] (9.5.0) and
  https://www.elastic.co/docs/explore-analyze/dashboards/manage-dashboards-as-code[Manage dashboards as code]
|===

A few other facts are worth remembering because older material gets them wrong:

* *Names.* "Index patterns" are now *data views*, and saved searches are *Discover sessions*
  (xref:backend/monitoring-alerting/kibana/data-views-and-discover.adoc[Data Views & Discover]).
* *Editors.* Lens is the default visualization editor; the aggregation-based, TSVB and Timelion editors are legacy, exist only on the
  Stack and not on Serverless (xref:backend/monitoring-alerting/kibana/lens.adoc[Lens] and
  xref:backend/monitoring-alerting/kibana/legacy-editors-canvas-and-graph.adoc[Legacy Editors, Canvas & Graph]).
* *Three alerting systems.* Classic Alerting (rules plus connectors) is generally available on the Stack and Serverless.
  Universal Alerting (ES|QL rules, rule events, action policies, workflows) is generally available on Serverless and planned for the
  Stack. Watcher is available on the Stack only, not on Serverless
  (xref:backend/monitoring-alerting/kibana/alerting-overview.adoc[Alerting Overview] and
  xref:backend/monitoring-alerting/kibana/universal-alerting-and-watcher.adoc[Universal Alerting & Watcher]).
* *Connectors.* The UI says "connectors", while the API and settings still say "actions" (`+xpack.actions.*+`)
  (xref:backend/monitoring-alerting/kibana/connectors.adoc[Connectors]).
* *Collection.* OpenTelemetry through the EDOT Collector is the default path for hosts and applications; Elastic Agent has replaced
  Beats for most use cases, and Logstash remains for complex pipelines
  (xref:backend/monitoring-alerting/kibana/ingesting-monitoring-data.adoc[Ingesting Monitoring Data]).

Source: https://www.elastic.co/docs/explore-analyze/alerting/compare-alerting-systems[Compare alerting systems],
https://www.elastic.co/docs/release-notes/kibana/breaking-changes[breaking changes] and
https://www.elastic.co/docs/get-started/the-stack[The Elastic Stack] (Beats).

== The running example

Every page uses Bookshelf, the Spring Boot 4.1 book catalogue that is instrumented with Micrometer and OpenTelemetry
(`/actuator/prometheus`, OTLP traces, JSON logs, PostgreSQL). Its instrumentation is described in
xref:backend/springboot/metrics-and-observability.adoc[Spring Boot metrics and observability] and
xref:backend/springboot/logging.adoc[Spring Boot logging]; Kubernetes deployment in
xref:backend/kubernetes/observability-logging-and-metrics.adoc[Kubernetes observability]; load and resilience scenarios in
xref:backend/resilience/index.adoc[Resilience]. In the lab, the EDOT Collector ships Bookshelf's telemetry to Elasticsearch 9.5.6,
and Kibana 9.5.6 reads it from there. A small load generator keeps dashboards and alerts supplied with data, and a webhook receiver
shows the notifications that Kibana sends, without any external account.

== Verify it in the lab

. Start the profile with `docker compose --profile kibana up -d` (see the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab]).
. Open `http://localhost:5601` and log in as `elastic` with the password set in the lab's `.env` file.
. `curl -s -u elastic:"$ELASTIC_PASSWORD" http://localhost:5601/api/status` returns JSON with the overall status and a breakdown per
  service (Elasticsearch, saved objects, plugins). Unauthenticated callers get only a redacted overall level.
. `docker compose exec kibana bin/kibana --version` prints the Kibana version, which must equal the Elasticsearch version (`9.5.6`).

Source: https://www.elastic.co/docs/api/doc/kibana/operation/operation-get-status[Get Kibana's current status].

== In the books

Several books in the bibliography teach the Elastic Stack, and all of them describe older versions. *Kibana 8.x: A Quick Start Guide to
Data Analysis* (Shah) covers Kibana 8.11 and 8.12 and is the closest in time; it is still good for walkthroughs of Discover, Lens and
dashboards, but it predates the 9.0 removals above, solution views and the rule changes of 9.2 to 9.5. *Elasticsearch 7.0 Cookbook*
(Paro), *Practice guide: Elastic from A to Z by examples* (Melachi, Elastic 7.10) and *Learning ELK Stack* (Chhajed, Kibana 4) show the
historical picture of Beats, Logstash, Elasticsearch and Kibana; treat their Kibana screens, index patterns and Beats-first pipelines
as outdated. The publisher pages are linked in the xref:backend/monitoring-alerting/index.adoc#_bibliography[bibliography].
