= Kibana Guide: Arrange and Connect a Dashboard
:description: Step-by-step guide to Kibana 9.5: resize and move the panels of the dashboard Bookshelf (guides), group them in a collapsible section, add an options list, a range slider and a time slider, a Markdown panel and a Links panel, connect a panel to another dashboard and to a URL with drilldowns, and set the panel settings.
:keywords: Kibana, dashboard, collapsible section, controls, options list, range slider, time slider, Markdown, Links panel, drilldown, dashboard drilldown, URL drilldown, panel settings, Bookshelf, step by step, guide

Checked on 2026-11-11 against Kibana 9.5.x.

== What you build

You take the dashboard *Bookshelf (guides)* from a pile of panels to a dashboard that someone else can read and use. You resize and move the panels,
put the two charts in a collapsible section called *Requests*, add three controls (an options list for the log severity, a range slider for the HTTP status and a time slider),
a Markdown panel that says what the dashboard is and a Links panel with two links. Then you connect the bar chart to a copy of the dashboard with a dashboard drilldown
and to the lab's webhook receiver with a URL drilldown, and you give the chart a title and a description in the panel settings.

image::monitoring-alerting-kibana-guide-k11-15-result.svg["Finished Kibana dashboard Bookshelf (guides) in view mode: the controls Severity and Status code and a time slider on top, a Markdown panel and a Links panel, and an expanded section Requests with the bar chart Records by status and the line chart Requests over time",width=900]

== Before you start

* Start the Kibana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile kibana up -d
----
* Open http://localhost:5601 and sign in as `elastic` with the password `lab-elastic-password`. When Kibana opens its full-screen
  welcome page, click *Explore on my own*.
* Do the previous guide, xref:backend/monitoring-alerting/kibana/guide-maps.adoc[Maps], and the guides before it, which create the dashboard *Bookshelf (guides)*
  and fill it with panels. This guide needs the dashboard with at least the bar chart *Records by status* and a line chart; the names in the steps are the ones the earlier guides give.
  It also needs the data view *Bookshelf logs (guides)* (index pattern `logs-generic.otel-default`, time field `@timestamp`) and, for the link in step 24, the sample dashboard *[Logs] Web Traffic*
  from the guide xref:backend/monitoring-alerting/kibana/guide-first-steps.adoc[First steps in Kibana].
* The load generator sends traffic to the Bookshelf service in its default mode. Controls, sections, Markdown, Links and drilldowns need no licence beyond the basic one; the lab runs a trial licence anyway.
* The guide was checked on Elasticsearch and Kibana 9.5.6. The figures are drawings of the Kibana 9.5 user interface, not screenshots, so small details can differ from your screen.
  The Add to dashboard flyout, the More menu and the second bar were read in the lab; the flyouts of the controls, the Markdown panel, the Links panel, the drilldowns and the panel settings are drawn from the Elastic documentation,
  so look for a control by its name when it is not where a figure shows it. A highlighted box with a number marks the control of the step with the same number.

== Steps

The screen maps of a dashboard in edit mode and of the Lens editor are in the guide xref:backend/monitoring-alerting/kibana/guide-first-dashboard.adoc[Create a dashboard and the first Lens panel]; come back to them when a control is not where a figure shows it.
This guide stays on the dashboard in edit mode and opens its flyouts one after the other.

=== Arrange the panels

. Click the menu button (*Toggle primary navigation*) at the left of the second bar. Under *Analytics*, click *Dashboards*, then click *Bookshelf (guides)*.
. Click *Edit*.
+
image::monitoring-alerting-kibana-guide-k11-01-open-dashboard.svg["Kibana dashboard Bookshelf (guides) in view mode with a bar chart panel Records by status and a line chart panel Requests over time; the Edit button of the second bar is marked by callout 2",width=900]
. Point at the bottom right corner of the bar chart panel and drag it to make the panel a little smaller or larger. The panel snaps to the dashboard grid of 48 columns.
. Drag the line chart panel by the move control in its header, which is the icon with three lines at the right of the header, to another place, for example below the bar chart, and drop it. The other panels make room.
+
image::monitoring-alerting-kibana-guide-k11-02-resize-and-move.svg["Kibana dashboard in edit mode with two panels: the resize handle at the bottom right corner of the bar chart panel is marked by callout 3 and the move control in the header of the line chart panel by callout 4",width=900]

=== Group the charts in a collapsible section

[start=5]
. Click *Add* in the second bar. The flyout *Add to dashboard* opens on its tab *New*.
. Scroll to the group *Annotations and Navigation* and click *Collapsible section*.
+
image::monitoring-alerting-kibana-guide-k11-03-add-collapsible-section.svg["Dashboard in edit mode with the Add to dashboard flyout open and scrolled to the groups Controls and Annotations and Navigation: the Add button of the second bar is marked by callout 5 and the entry Collapsible section by callout 6",width=900]
. A new section appears at the top of the dashboard with a default title. Click its title, type `Requests` and confirm with the Enter key.
. Drag each of the two chart panels by its move control into the section, below the section title. A section has to be expanded to receive panels. Click the arrow at the left of the section title once to collapse the section and again to expand it: the state is saved with the dashboard.
+
image::monitoring-alerting-kibana-guide-k11-04-section-with-panels.svg["Dashboard in edit mode with an expanded collapsible section titled Requests above the two chart panels; the section title is marked by callout 7 and the move control of a chart panel, which is dragged into the section, by callout 8",width=900]

=== Add controls

[start=9]
. Click *Add* in the second bar.
. Under *Controls*, click *Control*.
+
image::monitoring-alerting-kibana-guide-k11-05-add-control.svg["Dashboard in edit mode with the Add to dashboard flyout open at its Controls group: the Add button of the second bar is marked by callout 9 and the entry Control, above Variable control and Time slider, by callout 10",width=900]
. In the control flyout, check that the data view is *Bookshelf logs (guides)* and select the field `severity_text`.
. As the control type, select *Options list*.
. In the label, type `Severity`.
. Save the control with the *Save* button of the flyout. The control appears above the panels.
+
image::monitoring-alerting-kibana-guide-k11-06-options-list-control.svg["The control flyout over the dashboard with the data view Bookshelf logs (guides), the field severity_text (callout 11), the control type Options list (callout 12) and the label Severity (callout 13); the Save button is marked by callout 14",width=900]
. Add a second control the same way, with the steps 9 to 14: select the field `attributes.status`, the control type *Range slider* (the field is a number) and the label `Status code`.
. Click *Add* again and, under *Controls*, click *Time slider*. The time slider appears at the top of the dashboard. It needs a data view with a time field, and a dashboard has at most one.
. Open the control *Severity* and select `ERROR`. The panels that use the field `severity_text` show only the error log records; with normal traffic they can be nearly empty, so start the failure mode of the load generator first (see *Check the result*). Clear the selection afterwards.
. Drag the selected window of the time slider, or one of its ends, to another part of the time range. The time-based panels follow it.
+
image::monitoring-alerting-kibana-guide-k11-07-controls-on-dashboard.svg["Dashboard in edit mode with three controls above the panels, Severity with its list open, Status code and a time slider: the entry ERROR of the Severity list is marked by callout 17 and the selected window of the time slider by callout 18",width=900]

=== Add a Markdown panel and a Links panel

[start=19]
. Click *Add* and, under *Annotations and Navigation*, click *Markdown text*.
. In the editor of the panel, type this text:
+
[source,markdown]
----
## Bookshelf service
Request counts and errors
of the lab Bookshelf service.
----
. Confirm the editor with its saving button (*Save* in the figure). The panel appears on the dashboard; drag it to the top row as in the finished dashboard.
+
image::monitoring-alerting-kibana-guide-k11-08-markdown-panel.svg["The Markdown text editor over the dashboard with the text of a heading and two lines in the editor (callout 20), a rendered preview under it, and the confirming button at the bottom marked by callout 21",width=900]
. Click *Add* and, under *Annotations and Navigation*, click *Links*.
. Add an external link: its label is `Webhook receiver` and its URL is `http://localhost:8081`.
. Add a dashboard link to the dashboard *[Logs] Web Traffic*.
. Confirm the editor with its saving button.
+
image::monitoring-alerting-kibana-guide-k11-09-links-panel.svg["The Links editor over the dashboard with the Add link button marked by callout 23, the empty list where the second link appears marked by callout 24, and the confirming button at the bottom marked by callout 25",width=900]

=== Connect the bar chart with drilldowns

A dashboard drilldown needs a destination dashboard, so the steps first make a copy of the dashboard.

[start=26]
. Click *Save* in the second bar. If a dialog opens, confirm it.
. Click *Exit edit*.
. Click *More* in the second bar.
. In the menu, click *Duplicate*.
+
image::monitoring-alerting-kibana-guide-k11-10-duplicate-dashboard.svg["Dashboard Bookshelf (guides) in view mode with the More menu open: the More button of the second bar is marked by callout 28 and the entry Duplicate, above Reset changes, Background searches and Full screen, by callout 29",width=900]
. In the dialog, type `Bookshelf details (guides)` as the title and confirm it. Kibana opens the copy.
. Open the dashboard *Bookshelf (guides)* again from *Dashboards*, as in step 1.
. Click *Edit*.
. Open the menu of the bar chart panel: the icon with three dots at the right of its header.
. Click *Create drilldown*.
+
image::monitoring-alerting-kibana-guide-k11-11-create-drilldown-menu.svg["Dashboard in edit mode with the panel menu of the bar chart open: the menu button in the panel header is marked by callout 33 and the entry Create drilldown, between Explore in Discover and Manage drilldowns, by callout 34",width=900]
. In the flyout, select the action *Go to dashboard*.
. In *Name*, type `Details by status`.
. In *Choose destination dashboard*, select *Bookshelf details (guides)*.
. Tick *Use filters and query from origin dashboard* and *Use date range from origin dashboard*, so that the destination receives the controls, the query and the time range of this dashboard.
. Click *Create drilldown*.
+
image::monitoring-alerting-kibana-guide-k11-12-dashboard-drilldown.svg["The Create drilldown flyout with the action Go to dashboard (callout 35), the name Details by status (callout 36), the destination dashboard Bookshelf details (guides) (callout 37), two ticked options that carry the filters, the query and the date range (callout 38) and the Create drilldown button (callout 39)",width=900]
. Open the panel menu again and click *Create drilldown* to add a second drilldown to the same panel.
. Select the action *Go to URL*.
. In *Name*, type `Webhook receiver`.
. Enter this URL template, which contains the variable `+{{event.value}}+` that Kibana replaces with the value you click, here the HTTP status:
+
[source,text]
----
http://localhost:8081/?status={{event.value}}
----
. Click *Create drilldown*. Leave *Open URL in new tab* and *Encode URL* on.
+
image::monitoring-alerting-kibana-guide-k11-13-url-drilldown.svg["The Create drilldown flyout with the action Go to URL (callout 41), the name Webhook receiver (callout 42), the URL template http://localhost:8081/?status= followed by the variable event.value in double braces (callout 43), the Additional options with Open URL in new tab and Encode URL turned on, and the Create drilldown button (callout 44)",width=900]

=== Set the panel settings and save

[start=45]
. Open the menu of the bar chart panel again and click *Settings*.
. In the title, type `Records by status`.
. In the description, type `Log records per HTTP status.`
. Apply the settings with the confirming button of the flyout (*Apply* in the figure).
+
image::monitoring-alerting-kibana-guide-k11-14-panel-settings.svg["The panel Settings flyout over the dashboard with the custom title Records by status (callout 46), the description Log records per HTTP status. (callout 47) and the Apply button at the bottom marked by callout 48",width=900]
. Click *Save* in the second bar and confirm the dialog if it opens.
. Click *Exit edit*.

== Check the result

Open *Dashboards* and then *Bookshelf (guides)*. The dashboard must open with the three controls on top, the Markdown panel and the Links panel, and the section *Requests* with the two charts.

* Start the failure mode, wait a minute, press *Refresh* and select `ERROR` in *Severity*; the bar chart then shows the error status values:
+
[source,bash]
----
curl -X POST localhost:8090/mode/failing
----
* Click a bar of the chart. A menu lists the two drilldowns *Details by status* and *Webhook receiver*. The first opens *Bookshelf details (guides)* with the clicked status as a filter and the same time range; the second opens
  `http://localhost:8081/?status=` followed by the clicked value in a new tab, where the webhook receiver answers with the deliveries it holds as JSON (an empty list until a webhook was sent).
* Collapse the section *Requests*, save the dashboard and reload it: it keeps the state it was saved with.

Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Drag a control out of the pinned bar into the body of the dashboard (an unpinned control) or into the section, so that it filters only the panels of that section; the controls page explains pinned and unpinned scope.
* Add a *Discover* drilldown instead of the URL drilldown to open the documents behind a bar in Discover.
* Use `+{{event.value}}+` and the other variables of the URL template to build a link to a runbook or a ticket search.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|The *Severity* list is empty
|The time range holds no log records, or the field `severity_text` was not chosen.
|Widen the time picker, check the load generator with `curl localhost:8090/`, and edit the control to select `severity_text`.

|A chart does not react to a control
|The panel uses a data view that does not have the field of the control.
|Use controls on fields that the data view of the panel has; an ES\|QL panel needs a variable control instead.

|The drilldown menu does not appear when you click a bar
|The dashboard is still in edit mode, or the drilldown was not saved with the dashboard.
|Save the dashboard, leave edit mode and click the bar again, or use *Manage drilldowns* in the panel menu.

|The destination dashboard shows no data after the drilldown
|The time range or the filter of the origin was not carried over.
|Edit the drilldown and tick *Use filters and query from origin dashboard* and *Use date range from origin dashboard*.

|The URL drilldown opens a page with the literal text of the variable
|The variable was typed with a different name or with single braces.
|Use exactly the name `+{{event.value}}+` inside double braces.

|A panel cannot be dropped into the section
|The section is collapsed.
|Expand the section first, then drag the panel.
|===

== Clean up

Keep the dashboard *Bookshelf (guides)*: the following guides use it. The copy *Bookshelf details (guides)* is only the destination of the drilldown; delete it from *Dashboards* when you no longer need it, and remove the drilldown with *Manage drilldowns* first, or it points to nothing.
