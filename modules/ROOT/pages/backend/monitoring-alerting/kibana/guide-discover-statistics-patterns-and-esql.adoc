= Kibana Guide: Field Statistics, Patterns and ES|QL in Discover
:description: Step-by-step guide to Kibana 9.5 Discover: read the Field statistics and Patterns tabs of the Bookshelf logs, switch to ES|QL, build a query with FROM, WHERE, KEEP, SORT, STATS BY and EVAL, and save the suggested chart on a new dashboard.
:keywords: Kibana, Discover, field statistics, patterns, log pattern analysis, ES|QL, FROM, WHERE, KEEP, SORT, STATS, EVAL, BUCKET, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Kibana 9.5.x.

== What you build

You read the Bookshelf logs in Discover through two summaries, the statistics of every field and the patterns of the messages, then you switch Discover to ES|QL and build a query one
command at a time. The last query counts the requests per minute, Discover suggests a line chart for it, and you save the chart on a new dashboard called *Discover ES|QL (guides)*.

image::monitoring-alerting-kibana-guide-k4-12-result.svg["Kibana dashboard Discover ES|QL (guides) in view mode with one panel, the line chart of requests per minute made from the ES|QL query in Discover",width=900]

== Before you start

* Start the Kibana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile kibana up -d
----
* Open http://localhost:5601 and sign in as `elastic` with the password `lab-elastic-password`. When Kibana opens its full-screen
  welcome page, click *Explore on my own*.
* Do the previous guide, xref:backend/monitoring-alerting/kibana/guide-explore-logs-in-discover.adoc[Explore logs in Discover],
  and the guide that creates the data view, xref:backend/monitoring-alerting/kibana/guide-data-views-and-file-upload.adoc[Upload a file and create a data view].
  This guide needs the data view *Bookshelf logs (guides)*, with the index pattern `logs-generic.otel-default` and the time field `@timestamp`.
* The tabs *Patterns* and *Field statistics* of Discover are available with the trial licence that the lab runs. ES|QL needs no licence beyond the basic one.
* The load generator sends traffic to the Bookshelf service in its default mode, which fills the log data stream.
* The guide was checked on Elasticsearch and Kibana 9.5.6. The figures are drawings of the Kibana 9.5 user interface, not screenshots, so small details can differ from your screen,
  and the numbers in the tables are only illustrations. A highlighted box with a number marks the control of the step with the same number.
  The contents of the *Field statistics* and *Patterns* tabs, the ES|QL editor of Discover and the *Edit visualization* flyout were not opened one by one in the lab for this guide; the figures show them in
  general form and the steps name the controls without describing their exact layout.

== Steps

Discover has a tab for the session, the buttons *Share*, *Query in ES|QL*, *More* and *Save* in the second bar, the data view picker and the time picker above the field list, a histogram and the results tabs
*Documents*, *Patterns* and *Field statistics*. The figures below show the parts that this guide uses. The map of Discover is in
xref:backend/monitoring-alerting/kibana/guide-explore-logs-in-discover.adoc[Explore logs in Discover].

=== Read the field statistics and the patterns

. Open the primary navigation with the menu button of the second bar and click *Discover* under *Analytics*.
. Open the *Data view* picker above the field list and choose *Bookshelf logs (guides)*. Set the time picker to *Last 1 hour*.
. Click the tab *Field statistics*, next to *Documents* and *Patterns*.
+
image::monitoring-alerting-kibana-guide-k4-01-discover.svg["Discover of Kibana 9.5 on the data view Bookshelf logs (guides) with the histogram and the result tabs Documents, Patterns and Field statistics; the Data view picker is marked by callout 2 and the Field statistics tab by callout 3",width=900]
. Find the row of the field `attributes.status`. It shows in how many documents the field exists and how many distinct values it has, with a small chart of the most frequent values, so you see at a glance which statuses the service returns.
. Click the tab *Patterns*.
+
image::monitoring-alerting-kibana-guide-k4-02-field-statistics.svg["Discover with the Field statistics tab open: a table with one row for each field of the data view and the columns Documents and Distinct values; the row of attributes.status is marked by callout 4 and the Patterns tab by callout 5",width=900]
. In the field selector of the tab, choose the text field `body.text`. Discover groups the messages into patterns, in which the parts that change, such as a path, are replaced by a wildcard, and counts the documents of each pattern.
. Use the control of the first pattern row that filters the documents, to see only the documents of that pattern in *Documents*.
+
image::monitoring-alerting-kibana-guide-k4-03-patterns.svg["Discover with the Patterns tab open: a field selector showing body.text, marked by callout 6, and a table of message patterns with their counts; the control of the first pattern row that filters the documents is marked by callout 7",width=900]

=== Switch Discover to ES|QL

[start=8]
. Click *Query in ES|QL* in the second bar. Discover changes its classic mode, with the filter row and the field sidebar, for a query editor.
+
image::monitoring-alerting-kibana-guide-k4-04-query-in-esql.svg["Discover in its classic mode with the Documents tab; the button Query in ES|QL of the second bar is marked by callout 8",width=900]
. Click in the editor, select all its text and type a query that reads the documents of the data stream:
+
[source,esql]
----
FROM logs-generic.otel-default
----
. Run the query with the keyboard shortcut Ctrl+Enter (Cmd+Enter on macOS) or with the run button of the editor. The results table lists the documents with all their fields.
+
image::monitoring-alerting-kibana-guide-k4-05-esql-from.svg["Discover in ES|QL mode: the query editor holds a single line, FROM logs-generic.otel-default, with a table of documents under it; the editor is marked by callout 9",width=900]

=== Build the query one command at a time

An ES|QL query is a pipeline: a source command, then commands joined with the pipe character, each one working on the table of the previous one. The time picker still limits the documents by `@timestamp`.

[start=11]
. Add a new line and keep only the failed requests with the command `WHERE`, then run the query:
+
[source,esql]
----
FROM logs-generic.otel-default
| WHERE attributes.status >= 400
----
+
image::monitoring-alerting-kibana-guide-k4-06-esql-where.svg["Discover in ES|QL mode with two query lines, FROM and WHERE attributes.status >= 400, typed on a new line; the new line is marked by callout 11",width=900]
. Add a line with the command `KEEP` to leave only the columns you need:
+
[source,esql]
----
| KEEP @timestamp, attributes.uri, attributes.status, body.text
----
. Add a line with the command `SORT` to show the newest documents first, and run the query:
+
[source,esql]
----
| SORT @timestamp DESC
----
+
image::monitoring-alerting-kibana-guide-k4-07-esql-keep-sort.svg["Discover in ES|QL mode with four query lines: FROM, WHERE, KEEP with four fields and SORT @timestamp DESC; the KEEP line is marked by callout 12 and the SORT line by callout 13",width=900]
. Replace all the lines by a query that aggregates with `+STATS ... BY+`: the number of requests for each status. The table now has one row for each status, not one for each document.
+
[source,esql]
----
FROM logs-generic.otel-default
| STATS requests = COUNT(*) BY attributes.status
----
+
image::monitoring-alerting-kibana-guide-k4-08-esql-stats.svg["Discover in ES|QL mode with the query FROM, then STATS requests = COUNT(*) BY attributes.status; the STATS line is marked by callout 14 and the table under it has one row for each status with the column requests",width=900]
. Replace the query by one that adds a computed column with `EVAL`: for each URI, the total of requests, the failed ones and the percentage of failures, with the worst URI first.
+
[source,esql]
----
FROM logs-generic.otel-default
| STATS total = COUNT(*), errors = COUNT(*) WHERE attributes.status >= 400 BY attributes.uri
| EVAL error_pct = ROUND(100.0 * errors / total, 1)
| SORT error_pct DESC
----
+
image::monitoring-alerting-kibana-guide-k4-09-esql-eval.svg["Discover in ES|QL mode with a four line query: FROM, STATS with a total and the errors for each attributes.uri, EVAL error_pct = ROUND and SORT; the EVAL line is marked by callout 15 and the table has the column error_pct",width=900]

=== Look at the suggested chart

[start=16]
. Replace the query by one that counts the requests for each minute, with the function `BUCKET`, and run it:
+
[source,esql]
----
FROM logs-generic.otel-default
| STATS requests = COUNT(*) BY minute = BUCKET(@timestamp, 1 minute)
----
. Discover draws a chart above the table for a query that aggregates, here a line of the requests over time. Click *Edit visualization*, at the right of the chart, to open the visualization editor and see the other chart types that Discover suggests for the result.
+
image::monitoring-alerting-kibana-guide-k4-10-suggested-chart.svg["Discover in ES|QL mode with the query FROM, then STATS requests = COUNT(*) BY minute = BUCKET(@timestamp, 1 minute), marked by callout 16; above the table Discover draws a line chart of requests per minute, with the Edit visualization button marked by callout 17",width=900]

=== Save the chart on a dashboard

[start=18]
. In the visualization editor, type `Requests per minute (guides)` as the title of the chart.
. Click *Save* in the editor.
+
image::monitoring-alerting-kibana-guide-k4-11-save-to-dashboard.svg["Discover with the Edit visualization flyout open at the right: the chart of requests per minute, a title control typed Requests per minute (guides), marked by callout 18, and the Save button of the flyout, marked by callout 19",width=900]
. In the dialog that follows, choose to add the chart to a new dashboard.
. Type `Discover ES|QL (guides)` as the name of the dashboard and confirm. Kibana opens the dashboard with the chart on it.

== Check the result

Open *Dashboards* and then *Discover ES|QL (guides)*. It must show one line chart of the requests per minute. The chart comes from the query, so it needs no data view.

To see the chart react, force errors and press *Refresh*:

[source,bash]
----
curl -X POST localhost:8090/mode/failing
----

The line stays high, because errors are requests too. To see the failures, run the query of the step with `EVAL` again in Discover: within about a minute the column `error_pct` grows. Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Replace the last line of the `WHERE` query by `| WHERE severity_text == "ERROR"` to filter on the severity instead of the status.
* In the table toolbar of Discover, *Save table to dashboard* puts the table of results on a dashboard, instead of a chart.
* In classic mode, the query bar uses KQL; the xref:backend/monitoring-alerting/kibana/querying-with-kql-esql-and-promql.adoc[querying page] compares it with ES|QL.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|The tabs *Patterns* and *Field statistics* are missing
|The licence of the cluster is basic and they need the trial or a paid licence.
|Use the lab as started by its compose file, which runs a trial licence, and restart the profile if you replaced the licence.

|The query ends with a red message about an unknown column
|A field name is mistyped, or a `KEEP` before it dropped the column.
|Check the names in the field list of classic mode, and keep the columns that later commands use.

|The table is empty
|The time picker covers *Last 15 minutes* or less and the load generator is stopped, or the lab started a moment ago.
|Widen the time picker to *Last 1 hour*, check the mode with `curl localhost:8090/`, and send `curl -X POST localhost:8090/mode/normal` if it is not `normal`.

|There is no chart above the table
|The query returns documents, not an aggregation.
|End the query with `+STATS ... BY+`; Discover draws charts for aggregated results.

|The `WHERE` query returns no rows
|In the normal mode there may be no failed requests in the time range.
|Switch the load generator to its failing mode as in *Check the result*, or widen the time picker.
|===

== Clean up

Keep the dashboard if you like; it is independent of the following guides, which create the dashboard *Bookshelf (guides)*. To remove it, open *Dashboards*, select *Discover ES|QL (guides)* and delete it.
Stopping the profile with `docker compose --profile kibana down -v` deletes the volumes and therefore the dashboard too.
