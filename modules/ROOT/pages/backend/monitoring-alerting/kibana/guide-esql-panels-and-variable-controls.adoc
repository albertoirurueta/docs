= Kibana Guide: ES|QL Panels and Variable Controls
:description: Step-by-step guide to Kibana 9.5: add an ES|QL panel to the dashboard Bookshelf (guides), choose its chart, and make it interactive with two variable controls, a static one and one fed by a query, with multiple selection and chaining.
:keywords: Kibana, ES|QL, Visualization (query), variable control, ?value, static values, values from a query, multiple selection, chained controls, dashboard, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Kibana 9.5.x.

== What you build

You add a panel to the dashboard *Bookshelf (guides)* that is drawn from an ES|QL query instead of a data view: the number of Bookshelf log records per time bucket, split by HTTP status.
Then you put two variable controls on the dashboard: *Severity*, a static list, and *URI*, a list that a query fills, that allows several selections and that depends on *Severity*. A reader changes the controls and the query runs again with the values they chose.

image::monitoring-alerting-kibana-guide-k9-13-result.svg["Finished Kibana dashboard Bookshelf (guides) in view mode with the controls Severity and URI above a line chart of the requests per time bucket, split by status",width=900]

+
[source,bash]
----
cd lab
docker compose --profile kibana up -d
----

  welcome page, click *Explore on my own*.

  This guide queries the data stream `logs-generic.otel-default` directly, so it needs no data view, but the Bookshelf log records must be flowing.

== Steps

The guide works on a dashboard in edit mode and in the editor of an ES|QL panel. The map of the dashboard is in the first dashboard guide; come back to it when a control is not where a figure shows it.
Kibana fills the variables `+?_tstart+` and `+?_tend+` with the bounds of the time picker, so the panel follows the time range of the dashboard.

=== Open an ES|QL panel

. Open *Dashboards* in the primary navigation and click *Bookshelf (guides)*.
. Click *Edit* in the second bar.
+
image::monitoring-alerting-kibana-guide-k9-01-open-dashboard.svg["Kibana dashboard Bookshelf (guides) in view mode with its bar chart panel; the Edit button of the second bar is marked by callout 2",width=900]
. Click *Add* in the second bar. The *Add to dashboard* flyout opens.
. In the flyout, click *Visualization (query)* ("Build charts, metrics, and tables with ES|QL."). On an empty dashboard the same editor is the card *Create visualization (query)*.
+
image::monitoring-alerting-kibana-guide-k9-02-add-visualization-query.svg["Dashboard in edit mode with the Add to dashboard flyout open: the Add button of the second bar is marked by callout 3 and the entry Visualization (query), which builds charts with ES|QL, by callout 4",width=900]

=== Write the query and choose the chart

[start=5]
. Click in the query editor and type the query. It counts the log records of the dashboard time range in buckets of the time axis:
+
[source,esql]
----
FROM logs-generic.otel-default
| WHERE @timestamp >= ?_tstart AND @timestamp < ?_tend
| STATS requests = COUNT(*) BY bucket = BUCKET(@timestamp, 50, ?_tstart, ?_tend)
| SORT bucket
----
. Run the query with the run button of the editor. The panel draws a chart from the result: a time column and a number column become a line or bar chart over time.
+
image::monitoring-alerting-kibana-guide-k9-03-first-query.svg["The ES|QL editor of the new panel with the query FROM logs-generic.otel-default, a WHERE on the dashboard time range, STATS requests = COUNT(*) by a BUCKET of @timestamp and SORT bucket (callout 5); the run button at the end of the editor is marked by callout 6",width=900]
. Edit the query to split the count by status: replace the `STATS` line with these two lines.
+
[source,esql]
----
| STATS requests = COUNT(*)
    BY bucket = BUCKET(@timestamp, 50, ?_tstart, ?_tend), status = attributes.status
----
. Run the query again. The first grouping column goes to the horizontal axis and the second one becomes the breakdown, so the chart now has one series per status.
+
image::monitoring-alerting-kibana-guide-k9-04-split-by-status.svg["The ES|QL editor with the STATS command split by bucket and status = attributes.status (callout 7) above the line chart of the first query; the run button is marked by callout 8",width=900]
. Look at the *Suggestions* next to the chart: they are alternative charts for the same result. Choose the one that draws a line chart with the two series `200` and `404`.
+
image::monitoring-alerting-kibana-guide-k9-05-suggestions.svg["The ES|QL editor with a line chart of two series, 200 and 404, and the Suggestions cards at the right; the card of the line chart is marked by callout 9",width=900]

=== Add a static control

[start=10]
. In the `WHERE` command, add a line below the time filter. As soon as you type `+?severity+`, the editor offers its autocomplete list:
+
[source,esql]
----
    AND severity_text == ?severity
----
. In the autocomplete list, choose *Create control*. A flyout for the variable control opens.
+
image::monitoring-alerting-kibana-guide-k9-06-create-control.svg["The ES|QL editor with the line AND severity_text == ?severity typed into the WHERE command (callout 10); the autocomplete list under it offers Create control, marked by callout 11",width=900]
. In the flyout, choose the control type that lists static values.
. Enter the values `INFO` and `ERROR`.
. Check that the variable name is `+?severity+` and keep the label *Severity*. The control keeps single selection.
. Confirm the flyout with its save button.
+
image::monitoring-alerting-kibana-guide-k9-07-static-control.svg["The variable control flyout over the ES|QL editor: the control type Static values (callout 12), the values INFO and ERROR (callout 13), the variable name ?severity (callout 14) and the label Severity; the save button is marked by callout 15",width=900]

=== Add a control fed by a query, with several selections

[start=16]
. Add one more line to the `WHERE` command. `MV_INTERSECTS` keeps a record when its value is any of the selected values, which is what a control with several selections needs:
+
[source,esql]
----
    AND MV_INTERSECTS(attributes.uri, ?uri)
----
. In the autocomplete list, choose *Create control* again.
+
image::monitoring-alerting-kibana-guide-k9-08-create-second-control.svg["The ES|QL editor with the line AND MV_INTERSECTS(attributes.uri, ?uri) typed into the WHERE command (callout 16); the autocomplete list offers Create control, marked by callout 17",width=900]
. In the flyout, choose the control type that takes its values from a query.
. Type the query of the control. It lists the URIs of the time range, and because it uses `+?severity+` it only offers the URIs of the severity that is selected: that is how controls are chained.
+
[source,esql]
----
FROM logs-generic.otel-default
| WHERE @timestamp <= ?_tend
    AND @timestamp > ?_tstart
    AND severity_text == ?severity
| STATS BY attributes.uri
----
. Check that the variable name is `+?uri+` and set the label to *URI*.
. Turn on *Allow multiple selections*. Several values then can be chosen at the same time, which only a value variable with a single question mark allows.
. Confirm the flyout with its save button.
+
image::monitoring-alerting-kibana-guide-k9-09-query-control.svg["The variable control flyout with the control type Values from a query (callout 18) and its query, which uses ?severity (callout 19), the variable name ?uri (callout 20), the switch Allow multiple selections turned on (callout 21) and the save button (callout 22)",width=900]

=== Use the controls on the dashboard

[start=23]
. Click *Apply and close* at the bottom of the editor. The panel is on the dashboard, and the two controls appear on it.
+
image::monitoring-alerting-kibana-guide-k9-10-apply-and-close.svg["The ES|QL editor with the finished query that uses ?severity and ?uri above the line chart; the Apply and close button at the bottom is marked by callout 23",width=900]
. Open the *Severity* control and select `INFO`. The query runs again with that value.
. Open the *URI* control, which now lists the URIs of `INFO` records, and select two of them, for example `/api/search` and `/api/books`.
+
image::monitoring-alerting-kibana-guide-k9-11-use-the-controls.svg["Kibana dashboard in edit mode with two controls above the line chart panel: Severity, marked by callout 24, and URI, marked by callout 25",width=900]
. Click *Save* in the second bar.
. Click *Exit edit* to return to view mode.
+
image::monitoring-alerting-kibana-guide-k9-12-save-the-dashboard.svg["Kibana dashboard in edit mode with the controls Severity set to INFO and URI set to /api/search and /api/books; the Save button of the second bar is marked by callout 26 and the Exit edit button by callout 27",width=900]

== Check the result

Open *Dashboards* and then *Bookshelf (guides)*. The panel must show a line per status, and the *Severity* and *URI* controls must be above it. Select *Severity* `ERROR` and check that the *URI* control now offers only the URIs that have error lines; if the lab has none yet, force them:

[source,bash]
----
curl -X POST localhost:8090/mode/log-errors
----

After about a minute press *Refresh* and open the *Severity* control again. Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

To see the query that really ran, open the panel menu and choose *Inspect*: the request shows the values of the controls and of the time picker in place of the variables.

== Variations

* Use a control with the double question mark, such as `+??group_by+`, to let the reader choose the field of the `BY` clause. A field name needs that syntax: a value variable cannot stand in for a field.
* Add a static control `+?interval+` and use it in `+BUCKET(@timestamp, ?interval)+` to let the reader change the bucket size.
* Turn the query into a table by choosing the table suggestion, for example to rank the URIs by count.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The panel shows an error about an unknown variable
|The query mentions a variable that no control provides, or the control was deleted.
|Create the control again from the autocomplete list, or remove the variable from the query.

|The chart does not follow the time picker
|The query has no filter on `+?_tstart+` and `+?_tend+`, or hard-codes a time such as `NOW() - 1 hour`.
|Compare `@timestamp` with `+?_tstart+` and `+?_tend+`, as in step 5.

|*Allow multiple selections* is on, but the query shows an error
|The filter compares the field with `==`, which takes one value.
|Use `MV_INTERSECTS(attributes.uri, ?uri)` as in step 16.

|The *URI* control is empty
|No record of the selected severity exists in the time range.
|Widen the time picker, or force records with `curl -X POST localhost:8090/mode/log-errors` and press *Refresh*.

|A `??` variable does not accept several values
|Only a value variable with one question mark allows multiple selection.
|Keep one value, or use a value variable.
|===
