= Kibana Guide: Maps
:description: Step-by-step guide to Kibana 9.5: add a Lens region map and a Maps panel with a choropleth layer joined on the country and a documents layer with tooltips to the dashboard Bookshelf (guides), using the Sample web logs data.
:keywords: Kibana, Maps, Lens, region map, choropleth, documents layer, layer style, tooltip, geo.src, geo.coordinates, sample web logs, dashboard, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Kibana 9.5.x.

== What you build

You add two geographic panels to the dashboard *Bookshelf (guides)*. The first is a Lens region map that shades each country by the number of requests that came from it. The second is a Maps panel with two layers: a choropleth layer that joins the country shapes to the same counts, and a documents layer that draws one point for each request, with a tooltip.
The Bookshelf logs have no geography, so both panels use the *Sample web logs* data of Kibana; the guide shows the steps, and the same steps work for any data with a country code or a `geo_point` field.

image::monitoring-alerting-kibana-guide-k10-15-result.svg["Finished Kibana dashboard Bookshelf (guides) in view mode with a region map of the sample web logs by country and a Maps panel with a choropleth layer and a documents layer",width=900]

== Before you start

* Start the Kibana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile kibana up -d
----
* Open http://localhost:5601 and sign in as `elastic` with the password `lab-elastic-password`. When Kibana opens its full-screen
  welcome page, click *Explore on my own*.
* Do the guide xref:backend/monitoring-alerting/kibana/guide-first-dashboard.adoc[Create a dashboard and the first Lens panel], which creates the dashboard *Bookshelf (guides)*
  and shows the maps of the Lens editor and of a dashboard in edit mode.
* Install the *Sample web logs* data, as the guide xref:backend/monitoring-alerting/kibana/guide-first-steps.adoc[First steps in Kibana] shows: *Home* → *Try sample data* → *Install data* on the card *Sample web logs*.
  This creates the data view *Kibana Sample Data Logs*, whose fields `geo.src`, `geo.dest` and `geo.coordinates` hold the country code of the source, the country code of the destination and the position of the request.
  The sample data covers about the last seven days, so the guide sets the time picker to *Last 7 days*.
* Maps and the region map need no licence beyond the basic one; the lab runs a trial licence anyway. The Elastic Maps Service, which provides the country shapes, is reached over the internet, so the lab host needs internet access for the country boundaries.
* The guide was checked on Elasticsearch and Kibana 9.5.6. The figures are drawings of the Kibana 9.5 user interface, not screenshots, so small details can differ from your screen.
  The Maps editor, the chart type list and the drop zones of the region map are drawn from the Elastic documentation, so look for a control by its name when it is not where a figure shows it. The maps in the figures draw the real country outlines (Natural Earth, at a scale of 1:110 million) in the colours of the Elastic Maps Service basemap; the shading and the points stand for the sample data, not for your exact counts.
  A highlighted box with a number marks the control of the step with the same number.

== Steps

The guide works in the Lens editor, in the Maps editor and on a dashboard in edit mode. The screen maps of the Lens editor and of the dashboard are in the first dashboard guide; come back to them when a control is not where a figure shows it.

=== Open a Lens editor on the dashboard

. Open *Dashboards* in the primary navigation and click *Bookshelf (guides)*.
. Click *Edit* in the second bar.
+
image::monitoring-alerting-kibana-guide-k10-01-open-dashboard.svg["Kibana dashboard Bookshelf (guides) in view mode with its bar chart panel; the Edit button of the second bar is marked by callout 2",width=900]
. Click *Add* in the second bar. The *Add to dashboard* flyout opens.
. In the flyout, click *Visualization* ("Build charts, metrics, and tables with a point-and-click editor.").
+
image::monitoring-alerting-kibana-guide-k10-02-add-visualization.svg["Dashboard in edit mode with the Add to dashboard flyout open: the Add button of the second bar is marked by callout 3 and the Visualization entry of the flyout by callout 4; the entry Maps is in the line under Other visualizations",width=900]

=== Build a region map in Lens

[start=5]
. Lens opens. Open the *Data view* picker above the field list and choose *Kibana Sample Data Logs*.
. Open the time picker, which shows *Last 15 minutes*, and choose *Last 7 days*, so that the editor covers the period of the sample data.
+
image::monitoring-alerting-kibana-guide-k10-03-data-view-and-time.svg["Lens editor with the data view picker open: the entry Kibana Sample Data Logs is marked by callout 5, and the time picker, which shows Last 15 minutes, is marked by callout 6",width=900]
. Open the chart type list with the button of the layer card, which shows *Bar*, and choose *Region map*.
+
image::monitoring-alerting-kibana-guide-k10-04-region-map-type.svg["Lens editor on the data view Kibana Sample Data Logs with the time picker at Last 7 days and the chart type list open under the Bar button; the entry Region map is marked by callout 7",width=900]
. In *Search field names*, type `geo`. Drag the field `geo.src` onto the dashed button of the region dimension. If Lens asks which boundaries to use, choose the world countries and the country code that matches the values of the field.
. Drag the entry *Records*, above *Available fields*, onto the dashed *Metric* button. Lens shows it as *Count of records* and shades each country by its count.
+
image::monitoring-alerting-kibana-guide-k10-05-region-map-dimensions.svg["Lens editor with the chart type Region map and the field list narrowed to geo.src and geo.dest; geo.src is dragged onto the dashed region button (callout 8) and Records onto the dashed Metric button (callout 9)",width=900]
. Click *Save and return*. The dashboard is back in edit mode with the region map as a new panel.
+
image::monitoring-alerting-kibana-guide-k10-06-save-the-region-map.svg["Lens editor with a region map of the log records per country of geo.src, countries shaded by the count; the Save and return button of the second bar is marked by callout 10",width=900]

=== Build a Maps panel with two layers

[start=11]
. Click *Add* and then, under *Other visualizations*, *Maps*. The Maps editor opens with a base map.
. Click *Add layer* in the *Layers* panel.
+
image::monitoring-alerting-kibana-guide-k10-07-maps-editor.svg["The Maps editor of a new map panel with the Layers panel at the left and the map at the right; the Add layer button of the Layers panel is marked by callout 12",width=900]
. In the list of layer types, choose *Choropleth*. A choropleth shades areas, here countries, by a value.
+
image::monitoring-alerting-kibana-guide-k10-08-choropleth-type.svg["The Maps editor with the Add layer flyout open and its list of layer types; the entry Choropleth is marked by callout 13",width=900]
. Choose the boundaries: the world countries of the Elastic Maps Service, and the field of the shapes that holds the two-letter country code (ISO 3166-1 alpha-2).
. Choose the statistics source: the data view *Kibana Sample Data Logs* and the join field `geo.src`. Kibana counts the records for each value of `geo.src` and joins the count to the shape whose country code has the same value.
. Confirm the flyout with its primary button.
+
image::monitoring-alerting-kibana-guide-k10-09-choropleth-settings.svg["Add layer flyout of the Choropleth layer: the boundaries World Countries and their join field ISO 3166-1 alpha-2 code are marked by callout 14, the statistics source Kibana Sample Data Logs with the join field geo.src by callout 15 and the confirm button by callout 16",width=900]
. In the settings of the layer, open the *Fill color* and choose a colour ramp from light to dark, so that the darker a country is, the more requests came from it.
+
image::monitoring-alerting-kibana-guide-k10-10-choropleth-style.svg["The Maps editor with the Choropleth layer World Countries drawn on the map and the layer settings flyout open; the Fill color group, a colour ramp, is marked by callout 17",width=900]
. Click *Add layer* again and choose *Documents*. A documents layer draws one point for each record.
+
image::monitoring-alerting-kibana-guide-k10-11-documents-type.svg["The Maps editor with the choropleth drawn and the Add layer flyout open; the entry Documents is marked by callout 18",width=900]
. Choose the data view *Kibana Sample Data Logs* and the geospatial field `geo.coordinates`.
. In the tooltip fields, add `clientip`, `response` and `bytes`. When a reader clicks a point, the tooltip lists these values of the record.
. Confirm the flyout with its primary button.
+
image::monitoring-alerting-kibana-guide-k10-12-documents-settings.svg["Add layer flyout of the Documents layer: the data view Kibana Sample Data Logs and the geospatial field geo.coordinates are marked by callout 19, the tooltip fields clientip, response and bytes by callout 20 and the confirm button by callout 21",width=900]
. Both layers are on the map. Click *Save and return*.
+
image::monitoring-alerting-kibana-guide-k10-13-save-the-map.svg["The Maps editor with the choropleth layer and the documents layer drawn on the map and listed in the Layers panel; the Save and return button of the second bar is marked by callout 22",width=900]

=== Save the dashboard

[start=23]
. The dashboard shows the region map and the Maps panel in edit mode (the figure leaves out the bar chart of the first guide). Click *Save* in the second bar.
. Click *Exit edit* to return to view mode.
+
image::monitoring-alerting-kibana-guide-k10-14-save-the-dashboard.svg["Kibana dashboard in edit mode with the region map panel and the Maps panel; the Save button of the second bar is marked by callout 23 and the Exit edit button by callout 24",width=900]

== Check the result

Open *Dashboards* and then *Bookshelf (guides)* and set the time picker to *Last 7 days*, because the sample data is older than the *Last 15 minutes* that the dashboard opens with. The region map and the choropleth layer must shade the countries, and the documents layer must show points on the Maps panel. Click a point: its tooltip lists `clientip`, `response` and `bytes`.

The sample data is static, so the load generator has no effect on these panels.

== Variations

* On the Maps panel, add a heat map layer to see the density of the requests instead of single points.
* Use `geo.dest` instead of `geo.src` as the join field to map where the requests were going to.
* In the query box of the Maps editor, type `response:404` to see only the missing pages; the filter applies to the layers that read from Elasticsearch.
* For a real service, map the field that holds the client position, as the xref:backend/monitoring-alerting/kibana/maps-vega-and-other-panels.adoc[reference page] shows; the Bookshelf logs of the lab have no such field.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The maps are empty
|The time picker covers *Last 15 minutes*, and the sample data is older.
|Set the time picker to *Last 7 days*.

|The countries have no shading
|The join does not match: the field of the shapes and `geo.src` hold different kinds of code.
|Join the two-letter country code of the shapes to `geo.src`, which holds two-letter codes.

|The country shapes do not load
|The lab host cannot reach the Elastic Maps Service.
|Check the internet access of the host, or use shapes that you uploaded.

|The documents layer shows no points
|The geospatial field is wrong, or the data view has no `geo_point` field.
|Choose `geo.coordinates`, which is a `geo_point` field in the sample data.

|The data view *Kibana Sample Data Logs* is not in the picker
|The sample web logs are not installed.
|Install them from *Home* → *Try sample data*, then reopen the editor.
|===

== Clean up

Keep the dashboard: the following guides extend it. To remove the sample data, open *Home* → *Try sample data* and click *Remove* on the card *Sample web logs*. To remove everything the lab stores, stop the
profile with `docker compose --profile kibana down -v`, which also deletes the volumes and therefore the dashboard.
