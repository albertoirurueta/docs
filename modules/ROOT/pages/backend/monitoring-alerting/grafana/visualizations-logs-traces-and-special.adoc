= Grafana Logs, Traces and Special Panels
:description: The Grafana visualizations for logs, traces, profiles, graphs of relations, maps and free-form layouts (Logs, Traces, Node graph, Flame graph, Geomap and Canvas), panel plugins, and the Angular panels (Graph, Singlestat, Worldmap) that were removed in Grafana 12 with their replacements.
:keywords: Grafana, logs panel, traces panel, TraceQL, node graph, flame graph, Pyroscope, geomap, canvas, panel plugins, Angular, Graph, Singlestat, Worldmap, Bookshelf

Checked on 2026-11-09 against Grafana 13.3.x.

To do this by hand, follow xref:backend/monitoring-alerting/grafana/guide-explore-logs-and-traces.adoc[Explore Logs and Traces], xref:backend/monitoring-alerting/grafana/guide-state-logs-and-text-panels.adoc[State Timeline, Status History, Logs and Text Panels] and xref:backend/monitoring-alerting/grafana/guide-geomap.adoc[Geomap].

Metrics tell you that something is wrong; logs, traces and profiles tell you why. Grafana has a panel for each of those
signals, plus panels for relations (node graph), places (Geomap) and free layouts (Canvas). They belong on the lower, drill-down
part of a dashboard (see xref:backend/monitoring-alerting/dashboard-design-principles.adoc[Dashboard Design Principles]) and are
what a data link from a metric panel (see
xref:backend/monitoring-alerting/grafana/field-configuration.adoc[Field Configuration]) should land on. Charts are covered in
xref:backend/monitoring-alerting/grafana/visualizations-graphs-and-charts.adoc[Graphs and Charts], single values and tables in
xref:backend/monitoring-alerting/grafana/visualizations-stats-tables-and-widgets.adoc[Stats, Tables and Widgets]. The data sources behind
these panels (Loki, Tempo, Pyroscope) are in xref:backend/monitoring-alerting/grafana/data-sources.adoc[Data Sources], and exploring
them without a dashboard is in
xref:backend/monitoring-alerting/grafana/queries-explore-and-drilldown.adoc[Queries, Explore and Drilldown]. The signals and how
to correlate them are explained in xref:backend/monitoring-alerting/observability-fundamentals.adoc[Observability Fundamentals].

== Logs

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/logs/[Grafana: Logs].

*What and when.* The Logs panel lists log records from data sources such as Loki, Elasticsearch and InfluxDB. Use it next
to a graph of the related metric while investigating an incident: the graph says when, the lines say what. The preferred data
shape (dataplane) has a `timestamp` time field and a `body` string field, with optional `severity`, `id` and `labels`
fields; in the legacy shape the first field is the time and the second becomes the log line. Grafana colours lines by the
first matching `level`, `detected_level`, `lvl` or `loglevel` label, tries the content if there is none, and otherwise
treats the level as unknown. The query option *Max data points* caps the number of rendered lines.

*Options.* Time (show timestamps, off by default, with milliseconds or nanoseconds resolution), *Display log level*,
*Unique labels* (show only the labels that are not common to all lines), *Wrap lines*, *Prettify JSON*, columns for displayed
fields, font size (Default or Small), *Enable logs highlighting*, *Enable log details* (on by default, in a sidebar or inline), *Enable infinite scrolling*,
*Show controls* (jump to the first or last line, filter by level) with a download control, *Deduplication* (None, Exact,
Numbers or Signature) and *Sort order* (Newest first or Oldest first). Expanding a line shows its labels and detected
fields, each with a statistics icon, and actions such as copying a shortlink or scrolling to the line.

*Bookshelf example.* Bookshelf writes JSON logs (see xref:backend/springboot/logging.adoc[Spring Boot Logging]) that the
Grafana lab ships to Loki. The panel query lists the error lines of one route, and the Prettify JSON option makes the
structured fields readable:

[source,logql]
----
{application="bookshelf"} | json | level="ERROR" | uri=~"$route"
----

Reference: https://grafana.com/docs/loki/latest/query/[Loki: LogQL] (the `json` parser and label filter expressions). The label name `application` follows the lab setup; use
the labels your collector attaches.

*What can go wrong.* Rendering tens of thousands of lines slows the browser (lower Max data points and filter in the query,
not in the panel); and a missing level label gives grey lines that cannot be filtered. Log volume and cost are covered in
xref:backend/monitoring-alerting/storage-retention-and-cost.adoc[Storage, Retention and Cost].

== Traces

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/traces/[Grafana: Traces].

*What and when.* The Traces panel follows one request across the services of the infrastructure. It renders one trace at a
time, chosen by a trace ID from a TraceQL query or from a dashboard variable; to search for traces, use a Table panel with a
TraceQL query and open one of them. The documentation describes setting up a Tempo data source for it. Span filters help in
long traces: free-form filters (text search, `duration`, `service.name`, `span.name`, with variable interpolation),
*Show matches only* and *Select critical path*; duration filters accept `=`, `>=`, `+<=+`, `>` and `<`, and *Show all spans* returns to
the full view.

*Building it in a dashboard.* The documented steps are: add a panel, choose the tracing data source and the *Traces*
visualization, enter `+${traceId}+` in the *TraceQL* tab, add a *Custom* dashboard variable named `traceId`, and then add a
Table panel with a TraceQL query that has a data link setting the `traceId` variable from the `traceID` field. Clicking a row
then loads that trace into the Traces panel. In a Table panel, the TraceID and SpanID columns open Explore, while the other
columns follow the data link.

[source,traceql]
----
{ resource.service.name = "bookshelf" && duration > 500ms }
----

Reference: https://grafana.com/docs/tempo/latest/traceql/construct-traceql-queries/[Tempo: Construct a TraceQL query]. The unscoped `duration`
is an alias of `span:duration`, so the query lists Bookshelf spans slower than half a second for the table that feeds the Traces
panel; use `trace:duration` for the end-to-end latency of whole traces.

The trace data comes from the OTLP traces the Bookshelf service already exports
(see xref:backend/springboot/metrics-and-observability.adoc[Metrics and Observability]); how the signals are linked is in
xref:backend/monitoring-alerting/observability-fundamentals.adoc[Observability Fundamentals].

== Node graph

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/node-graph/[Grafana: Node graph].

The Node graph draws elements as nodes connected by edges: networks, infrastructure, topologies, org charts, critical paths.
It needs two data frames, one of nodes and one of edges (the edges frame is the minimum); Grafana recognises them from
`+frame.meta.preferredVisualisationType = 'nodeGraph'+`, from a frame name or `refId` of `nodes` or `edges`, or from an `id`
field. The nodes frame requires `id` and may have `title`, `subtitle`, `mainstat`, `secondarystat`, `+arc__*+` fields for the
coloured ring, `+detail__*+` fields, `color`, `icon` and positioning fields; the edges
frame requires `id`, `source` and `target` and may have `mainstat`, `secondarystat`, `+detail__*+`, `thickness`, `color` and
`strokeDasharray`. Options are the zoom mode (Cooperative or Greedy), the layout algorithm (Layered, the default, Force for
500 or more nodes, or Grid), the arc sections and the units of the stats. By default up to 200 nodes are visible and the
rest hide behind clickable markers.

Use it to show the dependencies of Bookshelf (the web tier, the catalogue service, PostgreSQL, the cache) with the request rate
as the main stat and the error ratio as the arc colour, from a data source or a query that returns the two frames. The
documentation names the X-Ray data source (service map) as a supported source; for others, check the data source's page or
build the frames with a transformation.

== Flame graph

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/flame-graph/[Grafana: Flame graph].

The Flame graph shows profiling data from Grafana Pyroscope so you can find performance bottlenecks and the root cause of a
slowdown, including in distributed systems. The data is a nested set model with the fields `level` (depth), `value` (width),
`label` (function name) and `self`, plus `valueRight` and `selfRight` for diff profiles (baseline, comparison and difference).

How to read it: the width of a block is its `value` (CPU time, allocations or memory), the vertical position is the call
stack depth, and the colour is either by value or by package name; small functions are collapsed into grey sections.
Besides the flame graph itself the panel has a *Top table* (Symbol, Self and Total, with search and sandwich actions), a
*Call tree* and a split view with two of these side by side. The *Sandwich view* shows a function's callers above and
callees below, aggregating all of its occurrences; *Focus block* rescales a function to full width; *Search* highlights
matches. For Bookshelf, profile the JVM during the load generator's slow mode and open the flame graph from the slow trace:
the widest block under the controller tells you whether time goes to serialisation, the database driver or garbage collection.

== Geomap

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/geomap/[Grafana: Geomap].

The Geomap shows location data on a map: moving assets, sites and data centres, geographic trends, or a heat map of density.
It replaces the Worldmap panel. Data can carry coordinates (fields named `latitude` or `lat` and `longitude`, `lon` or
`lng`), a `geohash` field, or a `lookup` field of codes resolved through a gazetteer (country codes are detected
automatically; airport or US state codes need manual setup). The location mode is Auto, Coords, Geohash or Lookup.

* *Map view*: initial view (Fit to data, coordinates, or a default region), zoom, share view across geomaps of one dashboard, no map repeating, and syncing the view to a Custom
  dashboard variable.
* *Data layers*: Markers, Heatmap, GeoJSON, Night/Day, Route, Photos and Network, with the Icon at last point and Dynamic
  GeoJSON layers still alpha (they need `enable_alpha`).
* *Base layers*: CARTO (the default), OpenStreetMap, ArcGIS MapServer, XYZ tile layer and MapLibre style layer; the
  default is set with `default_baselayer_config`, and `enable_custom_baselayers` (default true) allows custom ones.
* Tooltip: None (click only) or Details (hover) for markers, heatmap and photos layers; controls such as zoom, scale and measure tools.

Bookshelf example: reader sessions by country, using a data source that returns an ISO country code as the `lookup` field and the
session count as the value, rendered as a markers layer sized by the count. An external base layer makes the browser request map
tiles from that host, which matters on air-gapped networks.

== Canvas

Source: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/canvas/[Grafana: Canvas].

The Canvas builds custom layouts with data overlaid in ways the standard panels cannot: a status diagram of the system. It
needs no particular data, only a supported data source. *Elements*: metric value, text, basic shapes (ellipse, rectangle,
triangle, cloud, parallelogram), icon (including a custom SVG path), server (single server, stack, database or terminal, with
status and bulb colour) and button (an experimental element type that makes basic, unauthenticated API calls). *Connections* are lines
between elements, with colour, size, direction and a Solid, Dashed or Dotted style. Elements live in layers
with a background and border; constraints (Left, Right, Left and Right, Center, Scale) decide how they follow the panel size.
Text, colours, icon and connection styles take a fixed value or a field, so a thresholds-based colour turns the
PostgreSQL box red when the connection pool saturates. *Inline editing* must be on to create connections and to add data
links or actions, and off for button clicks to call the API.

Release status: from Grafana 13.3 the canvas loads as a standalone plugin by default, bundled with Grafana, which can update
between releases; slim Docker images need it installed from Administration > Plugins and data > Plugins. In 13.x you can revert to the
core plugin with `as_external = false` in the `[plugin.canvas]` section and a restart, and Grafana 14.0 removes the core plugin, so the
setting will have no effect then.

[source,ini]
----
[plugin.canvas]
as_external = false
----

Reference: https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/canvas/[Grafana: Canvas] (section on release status).

== Panel plugins

Grafana can be extended with panel plugins from the plugin catalogue. A server administrator or organisation administrator
opens *Administration > Plugins and data > Plugins*, filters by *Panels*, selects the plugin and clicks *Install*. Plugins are checked
for a signature when they load, so prefer signed plugins from the catalogue. Install only what you will maintain: a
panel plugin runs in every viewer's browser and has to be compatible with each Grafana upgrade. Plugin types are panels, data sources and apps. 
Source: https://grafana.com/docs/grafana/latest/administration/plugin-management/[Grafana: Plugin management].

== The removed Angular panels

The books on Grafana were written when Graph, Singlestat and Worldmap Panel were core or popular Angular panels. Angular
support was deprecated and turned off by default in Grafana 11 and removed in Grafana 12; dashboards that still use the core
Angular panels are forced to migrate to the React versions. The documentation lists the automatic migrations:

[cols="2,2,4",options="header"]
|===
|Legacy panel |Replacement |Notes

|Graph (old)
|Time series
|See xref:backend/monitoring-alerting/grafana/visualizations-graphs-and-charts.adoc[Graphs and Charts].

|Singlestat
|Stat
|See xref:backend/monitoring-alerting/grafana/visualizations-stats-tables-and-widgets.adoc[Stats, Tables and Widgets].

|Table (old)
|Table
|See xref:backend/monitoring-alerting/grafana/visualizations-stats-tables-and-widgets.adoc[Stats, Tables and Widgets] for the cell types.

|Worldmap Panel
|Geomap
|See the Geomap section above.

|Pie Chart plugin (`grafana-piechart-panel`)
|Pie chart
|The core Pie chart panel replaced the plugin.
|===

A migrated panel is not saved in its new form unless you save the dashboard, and a panel from an Angular plugin that has no replacement in the list has to be replaced by hand, so check your dashboards
before upgrading.

Source: https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v12/whats-new-in-v12-0/[Grafana: What's new in 12.0] (section "Removal of Angular") and
https://archive.grafana.com/docs/grafana/v12.1/developers/angular_deprecation/angular-plugins/[Grafana 12.1 documentation: Angular plugins]
(the page of the current documentation was moved to the archive).

== Verify it in the lab

In the lab (xref:backend/monitoring-alerting/hands-on-lab.adoc[Hands-on Lab], profile `grafana`):

. Add a Logs panel with the LogQL query above under the 5xx graph, trigger errors with the load generator, and check that
  the lines appear with the right colours and that *Unique labels* hides the common ones.
. Create the `traceId` variable, the Traces panel and the TraceQL table, and click a slow request to open its trace.
. Open the same trace in Explore and compare the span filters.
. Add a Canvas panel with two elements and a connection, and drive a colour from a metric with thresholds.
. Import an old dashboard JSON that contains a Graph panel and look at which panel it becomes.

== In the books

Salituro (Learn Grafana 10.x) has a chapter on the Geomap panel with earthquake data, and McCollam (Getting Started with
Grafana) touches the node graph, state timeline and Geomap in the Grafana 8 era. Hernandez (Building IoT Visualizations using
Grafana) names the Worldmap Panel and the Singlestat panel next to the Geomap, which is what replaced them. None of the books covers the Logs panel with
its current options, the Traces panel variable workflow, the Flame graph sandwich view or the Canvas as a plugin.
