= Grafana Guide: Thresholds, Value Mappings, Overrides and Data Links
:description: Step-by-step guide to Grafana 13.3: build a table of the Bookshelf request rate by route, then use the four field tools on it, a unit with thresholds, a value mapping, a field override and data links to a detail dashboard and to Explore.
:keywords: Grafana, field options, thresholds, value mappings, field overrides, data links, cell type, unit, decimals, table panel, Prometheus, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You add a table panel called *Requests per second by route* to the dashboard *Bookshelf (guides)* and then shape how its
values look and behave with the field tools of the panel editor. The unit and the decimals format every rate, thresholds colour
the cells orange from 2 and red from 4 requests per second, a value mapping shows the word *Quiet* for the routes with little traffic, one override
turns the *Value* cells into coloured cells, and a second override turns each route name into a link that opens a detail
dashboard or Explore.

image::monitoring-alerting-grafana-guide-g11-15-result.svg["Finished table panel Requests per second by route in view mode: the column uri lists the four routes as links, and the Value column is coloured red, orange and green by thresholds, shows rates with the unit req/s and the word Quiet for the routes with little traffic",width=900]

----

== Steps

Grafana 13.3 has no separate *All* and *Overrides* tabs in the panel editor. The options pane of a visualization lists every category,
one below the other, and the *Show only overrides* icon in its header narrows the list to the options that overrides set. The
field tools of this guide live in the categories *Standard options*, *Data links and actions*, *Value mappings* and *Thresholds*, and in the *Add field override* button at the end of the pane.

The screen maps of the dashboard in edit mode and of the panel editor are in the guide xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel]; come back to them when a control is not where a figure shows it.

=== Add a table panel

. In the left navigation, click *Dashboards*, then open the folder *Guides* and the dashboard *Bookshelf (guides)*.
. Click *Edit*.
+
image::monitoring-alerting-grafana-guide-g11-01-open-dashboard.svg["Dashboard Bookshelf (guides) in view mode with the navigation docked: callout 1 marks the Dashboards item of the navigation and callout 2 marks the Edit button of the toolbar",width=900]
. Click *Add* in the toolbar.
. In the *Add* pane of the right sidebar, click the *Panel* tile.
+
image::monitoring-alerting-grafana-guide-g11-02-add-panel.svg["Dashboard Bookshelf (guides) in edit mode with the Add pane of the right sidebar open: callout 3 marks the Add button of the toolbar and callout 4 marks the Panel tile of the Add pane",width=900]
. In the *Panel* pane that replaces the *Add* pane, click *Edit visualization*.
+
image::monitoring-alerting-grafana-guide-g11-03-edit-visualization.svg["Dashboard in edit mode after the Panel tile was clicked: a new panel called New panel and the Panel pane of the sidebar with the Edit visualization button marked by callout 5",width=900]
. At the bottom of the panel editor, check that *Data source* shows *Prometheus*. In query *A*, click *Code* in the *Builder* / *Code* switch.
+
image::monitoring-alerting-grafana-guide-g11-04-code-mode.svg["Panel editor with an empty New panel on the Queries tab and the Prometheus data source: callout 6 marks the Code option of the Builder and Code switch",width=900]
. Click inside the query editor first, so that it has the focus, then type the query:
+
[source,promql]
----
sum by (uri) (rate(http_server_requests_seconds_count{application="bookshelf"}[1m]))
----
. Open the *Options* line of the query and set *Format* to *Table*.
. In the same line, set *Type* to *Instant*.
. Click *Run queries*.
+
image::monitoring-alerting-grafana-guide-g11-05-query-typed.svg["Panel editor in Code mode: the query that sums the request rate by uri is typed in the editor (callout 7), the opened Options row shows Format set to Table (callout 8) and Type set to Instant (callout 9), and Run queries is marked by callout 10",width=900]
. In the right column, click the *All visualizations* tab.
. Click *Table* ("Supports many column styles").
+
image::monitoring-alerting-grafana-guide-g11-06-pick-table.svg["Panel editor after Run queries: the preview shows the result as a table with the columns Time, uri and Value; the All visualizations tab of the right column is marked by callout 11 and its list offers Table with the description Supports many column styles, marked by callout 12",width=900]

=== Name the panel and set the unit

[start=13]
. In the options pane, under *Panel options*, type `Requests per second by route` in *Title*.
. Under *Standard options*, open *Unit* and choose the unit for requests per second (type `requests` in the search box of the picker).
. In *Decimals*, type `1`. The cells now read like `4.8 req/s`.
+
image::monitoring-alerting-grafana-guide-g11-07-title-unit-decimals.svg["Panel editor with the Table options pane: under Panel options the Title field holds Requests per second by route (callout 13), under Standard options the Unit is the requests per second unit (callout 14) and Decimals is 1 (callout 15); the preview shows values such as 4.8 req/s",width=900]

=== Colour the values with thresholds

[start=16]
. Open the category *Thresholds*. A new panel starts with a green *Base* step and one more step, which is red and normally holds `80`. Replace the value of the red step with `4`.
. Click *Add threshold*.
+
image::monitoring-alerting-grafana-guide-g11-08-thresholds-start.svg["Options pane with the Thresholds category open: a red step with the value 80 marked by callout 16, the green Base step, the Add threshold button marked by callout 17 and the Thresholds mode switch set to Absolute",width=900]
. Type `2` in the value of the new step. Leave *Thresholds mode* on *Absolute*, so that the values are request rates and not percentages.
. Click the colour dot of the new step and choose orange.
+
image::monitoring-alerting-grafana-guide-g11-09-thresholds-typed.svg["Options pane with three thresholds: the red step is 4, the new step holds the value 2 (callout 18) and its colour dot, set to orange, is marked by callout 19, above the green Base step",width=900]

The preview does not change yet: a table shows the colours of the thresholds only for a cell type that uses them, which step 26 sets.

=== Map values to words

[start=20]
. Open the category *Value mappings*.
. Click the control of the category that adds value mappings.
+
image::monitoring-alerting-grafana-guide-g11-10-value-mappings.svg["Options pane with the Value mappings category open and empty: the category header is marked by callout 20 and the control that adds value mappings, drawn as a dashed box with a plus, is marked by callout 21",width=900]
. In the dialog that opens, add a mapping for the range from `0` to `1.2` with the display text `Quiet`.
. Save the dialog with its confirm button. The category now lists the mapping.
+
image::monitoring-alerting-grafana-guide-g11-11-mapping-result.svg["Options pane after the mapping was saved: the Value mappings category lists the range 0 to 1.2 shown as the text Quiet (callout 22); the preview shows Quiet in the Value column for the two routes with little traffic and the rates with the unit for the other two",width=900]

=== Override one field

An override applies options to one field instead of to every field. Here it makes the *Value* cells show the colours of the thresholds.

[start=24]
. Scroll to the end of the options pane and click *Add field override*.
. In the new override, choose the matcher that selects a field by its name, and pick the field `Value`.
. Add the override property *Cell type*, found under *Cell options*, and set it to the coloured background type. The *Value* cells turn red, orange and green and show *Quiet* for the low rates.
+
image::monitoring-alerting-grafana-guide-g11-12-override-cell-type.svg["Options pane scrolled to its end: the Add field override button is marked by callout 24, the new override selects the field Value (callout 25) and sets the property Cell type to the coloured background type (callout 26); the preview colours the Value cells red, orange and green",width=900]

=== Link the rows to a dashboard and to Explore

[start=27]
. Click *Add field override* again.
. In the new override, choose the same matcher by name and pick the field `uri`.
. Add the override property for data links, the one named like the category *Data links and actions*.
. Add a link with the title `Route detail` and this URL, which opens the provisioned dashboard and sets its variable *Route* to the route you click:
+
[source,text]
----
/d/bookshelf-service-health?var-route=${__data.fields.uri}
----
. Add a second link with the title `Logs in Explore` and this URL on one line, which opens Explore on the Loki data source with the Bookshelf logs of the last hour:
+
[source,text]
----
/explore?schemaVersion=1&panes={"a":{"datasource":"loki","queries":[{"refId":"A","expr":"{application=\"bookshelf\"}"}],"range":{"from":"now-1h","to":"now"}}}
----
+
image::monitoring-alerting-grafana-guide-g11-13-override-data-links.svg["Options pane with two overrides: the first one is Value with its cell type, the Add field override button is marked by callout 27, the second override selects the field uri (callout 28) and its property Data links and actions (callout 29) lists the link Route detail (callout 30) and the link Logs in Explore (callout 31); the uri cells of the preview turn into links",width=900]
. Click *Save* in the header of the editor.
. In the *Save dashboard* drawer, click *Save*.
. Click *Back*.
. Click *Exit edit*.
. If Grafana 13.3.0 shows the dialog *Unsaved changes*, click *Save*, and click *Save* again in the drawer that opens.
. In the table, click the route `/api/books`. A menu offers the two links.
. Click *Route detail*. The dashboard *Bookshelf service health* opens with the *Route* variable set to `/api/books`.
. Use the back button of the browser, click the route again and choose *Logs in Explore*; Explore opens on the Loki data source.
+
image::monitoring-alerting-grafana-guide-g11-14-link-menu.svg["Dashboard Bookshelf (guides) in view mode: after a click on the route /api/books (callout 37) a menu offers the two data links, Route detail (callout 38) and Logs in Explore (callout 39)",width=900]

== Check the result

Open *Dashboards* → *Guides* → *Bookshelf (guides)*. The table shows one row for each of the four routes with the rate and the unit `req/s`. The route names are links. The *Value* cells are green below 2, orange from 2 and red from 4, and the routes with a rate up to 1.2 show the word *Quiet* instead of the number.

To see the mapping take over, stop the load generator, wait about two minutes for the one-minute rate window to drain, and press *Refresh*:

[source,bash]
----
curl -X POST localhost:8090/mode/stop
----

All the rows then show *Quiet* on green cells. Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Colour the cell text instead of the background, or draw the value as a bar: change only the *Cell type* property of the first override.
* Switch *Thresholds mode* to *Percentage* to treat the steps as a share of the field's *Min* and *Max*, set under *Standard options*.
* Use *Value mappings* on a status field to turn codes into words, for example the HTTP status `404` into `Not found`.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The thresholds change nothing in the table
|The default cell type draws plain numbers, so no colour is used.
|Set the override property *Cell type* to the coloured background type on the field `Value`, as in step 26.

|The *Value* column shows `4.8` without the unit
|The unit was not chosen, or the choice was typed into the picker without selecting an entry.
|Open *Unit* again, search for `requests` and click the entry in the list.

|A click on a route does nothing
|The override matched another field than `uri`, or the links were saved after leaving the editor without *Save*.
|Open the editor again, check the matcher of the second override and save the dashboard.

|Explore opens empty or ignores the query
|The URL of the second link was broken across lines or lost a bracket.
|Edit the link and paste the URL again on one line, exactly as in step 31.

|The detail dashboard shows all routes
|The link text is not exactly `+var-route=${__data.fields.uri}+`, or the link opens another dashboard.
|Check the URL of the first link against step 30.
|===

== Clean up

Keep the panel if you want to try the variations. To remove it, open the dashboard in edit mode, select the panel, click *Delete* in the *Panel* pane of the right sidebar and save the dashboard. The later guides in this series do not depend on it.
