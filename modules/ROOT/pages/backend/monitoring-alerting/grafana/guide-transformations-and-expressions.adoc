= Grafana Guide: Transformations and Expressions
:description: Step-by-step guide to Grafana 13.3: join two Prometheus queries of the Bookshelf service in a table, rename, calculate, filter, group and reduce its fields with transformations and debug them, then add a Math, a Reduce and a SQL expression to a time series panel.
:keywords: Grafana, transformations, Join by field, Organize fields by name, Add field from calculation, Filter data by values, Group by, Reduce, debug, expressions, Math, SQL expressions, Prometheus, Bookshelf, step by step, guide

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You add two panels to the dashboard *Bookshelf (guides)*. The first one, a table called *Route summary*, runs two Prometheus
queries, the request rate and the p95 latency of every route, and a chain of transformations joins the results, renames the
columns, adds a rate per minute, drops the quiet routes, groups the rows and reduces them to a single summary row. The second one, a time series
called *Requests per minute*, uses expressions to multiply a query by 60, to reduce it to a number and to run a SQL statement on it.

image::monitoring-alerting-grafana-guide-g12-15-result.svg["Finished dashboard Bookshelf (guides) in view mode with two new panels: the table Route summary with one row holding the highest request rate, the highest rate per minute and the highest p95 latency, and the time series Requests per minute that draws the rates of the status codes 200 and 404 times 60",width=900]

== Before you start

* Start the Grafana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile grafana up -d
----
* Open http://localhost:3000, sign in as `admin` with the password `admin`, and click *Skip* when Grafana 13.3 asks you to
  update the default password.
* Do the earlier guides in this series, at least xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel],
  which creates the dashboard *Bookshelf (guides)* in the folder *Guides*, and xref:backend/monitoring-alerting/grafana/guide-tables.adoc[Tables], which builds a first table.
* The data source *Prometheus* is provisioned by the lab and is the default data source. The load generator runs in its default
  mode and gives the queries traffic to draw. SQL expressions are available in the free Grafana 13.3 image.
* The guide was checked on Grafana Enterprise 13.3.0 (the free image, no licence key). Editing dashboards needs the *Editor* or *Admin* role of the organization; `admin` has it.
* The figures are drawings of the Grafana 13.3 user interface, not screenshots, so small details can differ from your screen.
  A highlighted box with a number marks the control of the step with the same number.

== Steps

A transformation changes the data after the data source returned it and before the visualization draws it; an expression is
calculated on the server from the results of queries. Both live in the panel editor: transformations under the bottom tab
*Transformations*, expressions under the button *Expression* below the queries. The settings of each transformation card
are drawn from the names Grafana gives them; if a label differs on your screen, pick the closest entry.

The screen maps of the dashboard in edit mode and of the panel editor are in the guide xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel]; come back to them when a control is not where a figure shows it.

=== Add a table panel with two queries

. In the left navigation, click *Dashboards*, then open the folder *Guides* and the dashboard *Bookshelf (guides)*.
. Click *Edit*.
+
image::monitoring-alerting-grafana-guide-g12-01-open-dashboard.svg["Dashboard Bookshelf (guides) in view mode with the navigation docked: callout 1 marks the Dashboards item of the navigation and callout 2 marks the Edit button of the toolbar",width=900]
. Click *Add* in the toolbar.
. In the *Add* pane of the right sidebar, click the *Panel* tile.
+
image::monitoring-alerting-grafana-guide-g12-02-add-panel.svg["Dashboard Bookshelf (guides) in edit mode with the Add pane of the right sidebar open: callout 3 marks the Add button of the toolbar and callout 4 marks the Panel tile of the Add pane",width=900]
. In the *Panel* pane that replaces the *Add* pane, click *Edit visualization*.
. At the bottom of the panel editor, check that *Data source* shows *Prometheus*. In query *A*, click *Code* in the *Builder* / *Code* switch.
. Click inside the query editor first, so that it has the focus, then type the request rate by route:
+
[source,promql]
----
sum by (uri) (rate(http_server_requests_seconds_count{application="bookshelf"}[1m]))
----
. Open the *Options* line of query *A* and set *Format* to *Table*.
. In the same line, set *Type* to *Instant*.
+
image::monitoring-alerting-grafana-guide-g12-03-query-a.svg["Panel editor on the Queries tab: callout 6 marks the Code option of query A, the query that sums the request rate by uri is typed in the editor (callout 7), and the opened Options row shows Format set to Table (callout 8) and Type set to Instant (callout 9)",width=900]
. Click *Add query*.
. In query *B*, click *Code*.
. Click inside the editor of query *B* and type the p95 latency by route on one line (the editor may wrap it):
+
[source,promql]
----
histogram_quantile(0.95, sum by (le, uri) (rate(http_server_requests_seconds_bucket{application="bookshelf"}[5m])))
----
. In the *Options* line of query *B*, set *Format* to *Table*.
. Set *Type* to *Instant*.
. Click *Run queries*.
+
image::monitoring-alerting-grafana-guide-g12-04-query-b.svg["Panel editor with two queries: Add query is marked by callout 10, query B has its Code option (callout 11) and the p95 latency query typed in the editor (callout 12), its Options row shows Format Table (callout 13) and Type Instant (callout 14), and Run queries is marked by callout 15",width=900]
. In the right column, click the *All visualizations* tab.
. Click *Table* ("Supports many column styles").
. In the options pane, under *Panel options*, type `Route summary` in *Title*.

=== Join the queries and tidy the columns

[start=19]
. At the bottom of the editor, click the *Transformations* tab.
. Click *Add transformation*.
+
image::monitoring-alerting-grafana-guide-g12-05-transformations-tab.svg["Panel editor on the Transformations tab with the table titled Route summary: the tab is marked by callout 19 and the empty state offers the Add transformation button, marked by callout 20",width=900]
. In the *Add another transformation* drawer, click *Join by field*.
. In the card, choose `uri` as the field to join by. The table now holds one row per route with the two value columns, named after their queries, `Value #A` for the rate and `Value #B` for the latency.
+
image::monitoring-alerting-grafana-guide-g12-06-join-by-field.svg["The Join by field transformation: its Field select holds uri (callout 22); the preview shows one table with the columns Time, uri, Value #A with the request rates and Value #B with the p95 latencies",width=900]
. Below the card, click the button that adds another transformation and choose *Organize fields by name*.
. Switch off every *Time* field, so that the time columns disappear.
. Type `Route` as the new name of `uri`.
. Type `Requests per second` as the new name of `Value #A`.
. Type `p95 latency (s)` as the new name of `Value #B`.
+
image::monitoring-alerting-grafana-guide-g12-07-organize-fields.svg["The Organize fields by name transformation: the Time field is switched off (callout 24), uri is renamed to Route (callout 25), Value #A to Requests per second (callout 26) and Value #B to p95 latency (s) (callout 27); the preview shows a table with three columns",width=900]

=== Calculate, filter and debug

[start=28]
. Add the transformation *Add field from calculation*.
. Set *Mode* to the binary operation.
. Build the operation `Requests per second` `+*+` `60`: choose the field `Requests per second`, the operator `+*+` and type `60`.
. Type `Requests per minute` in *Alias*.
+
image::monitoring-alerting-grafana-guide-g12-08-add-field-from-calculation.svg["The Add field from calculation transformation: the Mode is the binary operation (callout 29), the operands read Requests per second, the operator * and the value 60 (callout 30) and the Alias is Requests per minute (callout 31); the preview shows the new column Requests per minute",width=900]
. Add the transformation *Filter data by values*.
. Add a condition and choose the field `Requests per second`.
. Choose the operator *Greater*.
. Type `1.05` as the value. The route `/api/loans`, which gets about one request per second, leaves the table.
+
image::monitoring-alerting-grafana-guide-g12-09-filter-by-values.svg["The Filter data by values transformation with one condition: the field Requests per second (callout 33), the operator Greater (callout 34) and the value 1.05 (callout 35); the preview lists three routes, because /api/loans with 1.0 requests per second is gone",width=900]
. Click the debug icon in the header of the *Filter data by values* card. The card shows the data that goes in and the data that comes out, side by side. Click the icon again to close the view.
+
image::monitoring-alerting-grafana-guide-g12-10-debug-view.svg["The Filter data by values card with its debug view open: the debug icon in the card header is marked by callout 36, below it the Input table lists four routes and the Output table lists three",width=900]

=== Summarise with Group by and Reduce

In this lab every route appears once, so *Group by* only renames the columns here; it matters when a query returns several rows for a route, for example when you add `status` to the `sum by` clause.

[start=37]
. Add the transformation *Group by*.
. Set the field `Route` to *Group by*.
. Set the field `Requests per second` to *Calculate*.
. Choose the calculation *Total* for it.
. Set `Requests per minute` to *Calculate* with *Total*, and `p95 latency (s)` to *Calculate* with *Max*.
+
image::monitoring-alerting-grafana-guide-g12-11-group-by.svg["The Group by transformation: the field Route is set to Group by (callout 38), Requests per second is set to Calculate (callout 39) with the calculation Total (callout 40), and the other two fields are set the same way; the preview shows three routes with the totals and the maximum latency",width=900]
. Add the transformation *Reduce*.
. Set *Mode* to *Reduce fields*.
. In *Calculations*, choose *Max*. The table shrinks to one row.
+
image::monitoring-alerting-grafana-guide-g12-12-reduce.svg["The Reduce transformation: its Mode is Reduce fields (callout 43) and its Calculations select holds Max (callout 44); the preview shrinks to one row with the highest request rate, the highest rate per minute and the highest p95 latency",width=900]

=== Use expressions in a time series panel

Expressions calculate on time series, so the second panel uses a range query.

[start=45]
. Click *Back* in the header of the editor. The panel stays on the dashboard, which is still in edit mode.
. Add another panel and open its editor, as in steps 3 to 5.
. In query *A*, click *Code*.
. Click inside the editor and type the request rate by status:
+
[source,promql]
----
sum by (status) (rate(http_server_requests_seconds_count{application="bookshelf"}[1m]))
----
. Click *Run queries*.
. Under *Suggestions*, click *Time series*.
. Click *Expression* below the queries and choose *Math*.
. In the expression, type:
+
[source,text]
----
$A * 60
----
. Click *Expression* again and choose *Reduce*.
. Set *Function* to *Last*.
. Set *Input* to `A`.
. Set *Mode* to *Drop Non-numeric Values*.
+
image::monitoring-alerting-grafana-guide-g12-13-math-and-reduce.svg["Panel editor of a time series panel titled Requests per minute: the Expression button under query A is marked by callout 51, the Math expression C holds the text $A * 60 (callout 52), and the Reduce expression D has Function Last (callout 54), Input A (callout 55) and Mode Drop Non-numeric Values (callout 56)",width=900]
. Click *Expression* a third time and choose *SQL*.
. In the editor of the SQL expression, type a statement that reads query `A` as a table named `A`:
+
[source,sql]
----
SELECT * FROM A LIMIT 5
----
+
image::monitoring-alerting-grafana-guide-g12-14-sql-expression.svg["Panel editor with the Expression button marked by callout 57 and a new SQL expression E whose editor holds the statement SELECT * FROM A LIMIT 5, marked by callout 58",width=900]
. In the options pane, under *Panel options*, type `Requests per minute` in *Title*.
. Click *Save* in the header of the editor.
. In the *Save dashboard* drawer, click *Save*.
. Click *Back*.
. Click *Exit edit*.
. If Grafana 13.3.0 shows the dialog *Unsaved changes*, click *Save*, and click *Save* again in the drawer that opens.

== Check the result

Open *Dashboards* → *Guides* → *Bookshelf (guides)*. The table *Route summary* shows one row with the highest request rate, the highest rate per minute (60 times the rate) and the highest p95 latency of the routes that get more than one request per second. The time series *Requests per minute* draws the status codes `200` and `404` at 60 times the per-second rate.

To see the table react, make the Bookshelf service slow, wait a minute and press *Refresh*; the maximum of *p95 latency (s)* grows:

[source,bash]
----
curl -X POST localhost:8090/mode/slow
----

Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

To inspect the results of the Reduce and SQL expressions, open the panel *Requests per minute* in the editor and switch on *Table view* in its header.

== Variations

* Disable a transformation temporarily instead of deleting it, to see how the table looked before it, or open the debug view of any card.
* Replace *Filter data by values* with *Sort by* or *Limit* to keep only the busiest routes.
* Use the expressions *Resample* and *Threshold*, which the alerting guides need, in the same way: click *Expression* and choose the type.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The join gives an empty table or a single query's columns
|One query still has the format *Time series*, or a query was not run again after the change.
|Set *Format* to *Table* and *Type* to *Instant* in both queries and click *Run queries*.

|The latency column is empty
|The query for p95 has no data because the one-minute window of `rate` was too short, or the load generator is stopped.
|Keep the range `[5m]` of query *B*, wait a few minutes after starting the lab, and check `curl localhost:8090/` for the mode.

|The rename in *Organize fields by name* does not show
|The rename field was typed for a field that a join or another card renamed.
|Check the debug view of the previous card for the field names it passes on.

|The Math expression returns no data
|The query *A* of this panel is hidden or formatted as a table.
|Use the range query of step 48 with the default *Time series* format and click *Run queries*.

|The SQL expression reports an error
|The table name does not match the query's reference id.
|Name the query in the `FROM` clause exactly as the query, `A`.
|===
