= Grafana Guide: Users, Teams and Folder Permissions
:description: Step-by-step guide to Grafana 13.3: create the user guide-viewer and the team guide-team, give the team access to the folder Guides, sign in as that user to check what it sees, and create a service account with a token for the HTTP API.
:keywords: Grafana, users, teams, folder permissions, access control, service account, token, API, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You create a user *guide-viewer* and a team *guide-team*, add the user to the team, and give the team the *View* permission on the folder *Guides*. You then sign in as the new user in a
private window to see that it reaches the dashboard *Bookshelf (guides)* but cannot edit it. Finally you create a service account with a token and use the token against the Grafana HTTP API.

image::monitoring-alerting-grafana-guide-g19-08-result.svg["The dashboard Bookshelf (guides) seen by guide-viewer: the panel Requests per second by status is shown and the toolbar offers the time range, Refresh and Share but no Edit button",width=900]

== Before you start

* Start the Grafana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile grafana up -d
----
* Open http://localhost:3000, sign in as `admin` with the password `admin`, and click *Skip* when Grafana 13.3 asks you to update the default password. `admin` is a Grafana administrator and an organization administrator, which creating users, teams and service accounts requires.
* Do the earlier guides that create the folder *Guides* and the dashboard *Bookshelf (guides)*: xref:backend/monitoring-alerting/grafana/guide-first-steps.adoc[First steps in Grafana] and
  xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel]. The previous guide is xref:backend/monitoring-alerting/grafana/guide-silence-schedule-and-review-alerts.adoc[Silence, schedule and review alerts].
* The lab runs without single sign-on, so a user created in the interface can sign in with a password. Choose a password of your own for the new user and remember it for step 19.
* The guide was checked on Grafana Enterprise 13.3.0 (the free image, no licence key); the permission features used here are available without a licence.
* The figures are drawings of the Grafana 13.3 user interface, not screenshots, so small details can differ from your screen.
  A highlighted box with a number marks the control of the step with the same number.
  The user page, the team page, the folder permissions dialog and the service account forms were not read in the lab, so those steps name the controls by their function and the figures do not draw them.

== Steps

The guide works on three areas of the navigation: *Administration* → *Users and access* (*Users*, *Teams* and *Service accounts*), the folder page of *Guides* under *Dashboards*, and a private browser window for the check.

=== Create a user

. In the left navigation, click *Administration*, then *Users and access*, then *Users*.
. Click *New user*.
+
image::monitoring-alerting-grafana-guide-g19-01-users.svg["Users page of Grafana 13.3 with the Administration group of the navigation open: callout 1 marks Users under Users and access, and callout 2 marks the New user button; the group also lists Teams and Service accounts",width=900]
. In *Name*, type `Guide Viewer`.
. In *Email*, type `guide.viewer@example.com`.
. In *Username*, type `guide-viewer`.
. In *Password*, type a password of your own.
. Click *Create user*.
+
image::monitoring-alerting-grafana-guide-g19-02-new-user.svg["New user form: the field Name holds Guide Viewer (callout 3), Email holds guide.viewer@example.com (callout 4), Username holds guide-viewer (callout 5), Password holds dots (callout 6) and the Create user button is marked by callout 7",width=900]
. On the page of the new user, change the role of the user in the organization to *No basic role*, so that it sees only what is granted to it. Without this change a user with the *Viewer* role can see every folder, and the check at the end would not show the effect of the team permission.

=== Create a team

[start=9]
. In *Administration* → *Users and access* → *Teams*, click the button that creates a new team. The form is titled *New team*.
. In *Name*, type `guide-team`.
. Leave *Auto-create a team folder* switched off. The option creates a folder owned by the team; this guide grants access to the existing folder *Guides* instead.
. Click *Create*.
+
image::monitoring-alerting-grafana-guide-g19-03-new-team.svg["New team form: the field Name holds guide-team (callout 10), the Team folder option Auto-create a team folder is switched off (callout 11) and the Create button is marked by callout 12",width=900]
. On the page of the new team, add the user `guide-viewer` as a member.

=== Give the team access to the folder

[start=14]
. Open *Dashboards*, click the folder *Guides* and click *Folder actions*.
+
image::monitoring-alerting-grafana-guide-g19-04-folder-actions.svg["Folder page Guides with the tabs Dashboards, Panels and Alert rules and the dashboard Bookshelf (guides) listed; the Folder actions button at the top right is marked by callout 14",width=900]
. Choose the entry that opens the permissions of the folder. The entries of this menu were not read in the lab; look for the one named after permissions.
. Add a permission for the team: choose *Team*, select `guide-team`, choose the permission *View* and save it.

=== Check as the new user

[start=17]
. Keep your own session as `admin` and open a private (incognito) window of your browser at http://localhost:3000.
. In *Email or username*, type `guide-viewer`.
. In *Password*, type the password you chose in step 6.
. Click *Log in*.
+
image::monitoring-alerting-grafana-guide-g19-05-sign-in.svg["Sign-in page of Grafana 13.3 in a private window: the field Email or username holds guide-viewer (callout 18), the field Password holds dots (callout 19) and the Log in button is marked by callout 20",width=900]
. In the left navigation, click *Dashboards*.
. In the list, click the folder *Guides*. The folder *bookshelf* of the lab is not listed, because the user has no permission on it.
+
image::monitoring-alerting-grafana-guide-g19-06-dashboards-as-user.svg["Dashboards page of Grafana 13.3 signed in as guide-viewer: callout 21 marks Dashboards in the navigation, and callout 22 marks the folder Guides in the list, which has no folder bookshelf",width=900]
. Open the dashboard *Bookshelf (guides)*. It shows its panel, and the toolbar has no *Edit* button: the permission *View* allows reading, not changing.

=== Create a service account and a token

[start=24]
. Back in your own window as `admin`, open *Administration* → *Users and access* → *Service accounts*.
. Click *Add service account*.
+
image::monitoring-alerting-grafana-guide-g19-07-service-accounts.svg["Service accounts page with the filters All, With expired tokens and Disabled and the empty state You have not created any service accounts yet; the Add service account button is marked by callout 25",width=900]
. In the form, type `guide-sa` as the display name and choose the role *Viewer*.
. Create the service account.
. On its page, add a service account token with the button that generates a new token, and confirm.
. Copy the token when it is shown: Grafana shows it only once.
. Use the token against the HTTP API, replacing `<token>` with the value you copied:
+
[source,bash]
----
curl -s -H "Authorization: Bearer <token>" "http://localhost:3000/api/search?query=Bookshelf"
----
+
The answer is a JSON list that contains the dashboard *Bookshelf (guides)*.

== Check the result

* *Administration* → *Users and access* → *Users* lists *guide-viewer*, and *Teams* lists *guide-team* with one member.
* Signed in as `guide-viewer`, you see the folder *Guides*, the dashboard *Bookshelf (guides)* in view mode and no *Edit* button.
* The `curl` command with the token returns the dashboard; with a wrong token it answers `401`.
* Provoking traffic is not needed here. If you want live data in the panel, send `curl -X POST localhost:8090/mode/failing` and restore it with `curl -X POST localhost:8090/mode/normal`.

== Variations

* Give the team *Edit* instead of *View* on the folder, sign in again and compare: the *Edit* button appears.
* Create the team with *Auto-create a team folder* switched on and see the folder under *My team folders* of the *Dashboards* page.
* Give the user the role *Viewer* instead of *No basic role* and check that the folder *bookshelf* becomes visible too.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|The new user sees the folder *bookshelf* and every other folder
|The user has the organization role *Viewer*, which includes read access to all folders.
|Change the role to *No basic role* on the user page, then sign in again.

|The new user sees no folder at all
|The user is not a member of `guide-team`, or the team has no permission on *Guides*.
|Add the user to the team, and check the permissions of the folder *Guides*.

|The token is lost
|Grafana shows a service account token only once.
|Create a new token on the service account page and delete the old one.

|`curl` answers `401`
|The token was copied with a trailing space, or the service account is disabled.
|Copy the token again, and check the filters *Disabled* and *With expired tokens* of the service accounts page.
|===

== Clean up

Keep the user, the team and the service account if you want to explore further; none of them affects the lab dashboards. To remove them, delete the user, the team and the service account from their own pages
under *Administration* → *Users and access*, and remove the permission of the team from the folder *Guides*. To delete everything the lab stores, stop the profile with `docker compose --profile grafana down -v`.
