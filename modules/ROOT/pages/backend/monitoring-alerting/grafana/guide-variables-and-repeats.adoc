= Grafana Guide: Variables, Filters and Repeats
:description: Step-by-step guide to Grafana 13.3: add chained query variables, a custom, an interval and a data source variable and a Filter and Group by control to the dashboard Bookshelf (guides), use them in a panel query and title, and repeat the panel once for each route.
:keywords: Grafana, variables, query variable, chained variables, custom variable, interval variable, data source variable, Filter and Group by, repeat panel, repeat row, dashboard sidebar, Prometheus, Bookshelf, step by step, guide

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You add five variables to the dashboard *Bookshelf (guides)*: *Application* and *Route*, two chained query variables whose
values come from Prometheus, a custom variable *Percentile*, an interval variable *Window* and a data source variable *ds*. You
also add a *Filter and Group by* control. A new time series panel uses the variables in its data source, its query and its title,
and Grafana repeats it once for each route you select.

[source,bash]
----
cd lab
docker compose --profile grafana up -d
----

  update the default password.

== Steps

In Grafana 13.3 the variable settings no longer have a tab of their own: the *Variables* tab of the dashboard settings only says that they have moved
to the dashboard sidebar. The sidebar pane opened by the *Options* icon lists *Filters*, *Variables*, *Annotations* and *Links*, each with a plus button, and the old ad hoc filters are the *Filter and Group by* control of *Filters*.
The edit toolbar, the sidebar and the panel editor are drawn on the screen maps of the guide xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel]; come back to them when a control is not where a figure shows it.
The forms of the *Custom*, *Interval* and *Data source* variables and the *Repeat options* are drawn from the names Grafana gives them; if a label differs on your screen, pick the closest entry.

=== Open the variables pane

. In the left navigation, click *Dashboards*, then open the folder *Guides* and the dashboard *Bookshelf (guides)*.
. Click *Edit*.
+
image::monitoring-alerting-grafana-guide-g13-01-open-dashboard.svg["Dashboard Bookshelf (guides) in view mode with the navigation docked: callout 1 marks the Dashboards item of the navigation and callout 2 marks the Edit button of the toolbar",width=900]
. In the icon strip of the right sidebar, click *Options*.
. In the pane *Dashboard*, click the plus button next to *Variables*.
+
image::monitoring-alerting-grafana-guide-g13-02-options-pane.svg["Dashboard in edit mode with the Options icon of the right sidebar marked by callout 3 and the Dashboard pane open: View all settings, Title, Description, Layout and the lists Filters, Variables, Annotations and Links, each with a plus button; the plus of Variables is marked by callout 4",width=900]
. In the list *Choose variable type*, click *Query* ("Values are fetched from a data source query"). The list also offers *Switch*, a new type for a variable that is toggled on and off.
+
image::monitoring-alerting-grafana-guide-g13-03-variable-types.svg["The Choose variable type list of the dashboard sidebar with the types Query, Custom, Textbox, Constant, Data source, Interval and Switch; Query, described as values fetched from a data source query, is marked by callout 5",width=900]

=== Create the Application and Route query variables

[start=6]
. In the form *Query variable*, type `application` in *Name*.
. Type `Application` in *Label*.
. Under *Query options*, click *Open variable editor*.
+
image::monitoring-alerting-grafana-guide-g13-04-query-variable.svg["The Query variable form in the dashboard sidebar: the Name field holds application (callout 6), the Label field holds Application (callout 7), and the Open variable editor button under Query options is marked by callout 8; the Selection options toggles are all off",width=900]
. In the editor, choose the data source *Prometheus*.
. Set up the query so that it returns the values of the label `application` of the metric `http_server_requests_seconds_count`. In the definition of the query this reads:
+
[source,text]
----
label_values(http_server_requests_seconds_count, application)
----
. Close the editor.
+
image::monitoring-alerting-grafana-guide-g13-05-variable-editor.svg["The query editor of the variable opened with Open variable editor: the data source Prometheus is selected (callout 9), the query label_values with the metric http_server_requests_seconds_count and the label application is typed in the editor (callout 10), and the close icon of the editor is marked by callout 11",width=900]
. Click the plus button next to *Variables* again and choose *Query*.
. Type `route` in *Name*.
. Type `Route` in *Label*.
. Click *Open variable editor*.
+
image::monitoring-alerting-grafana-guide-g13-06-route-variable.svg["The Query variable form for the second variable: the Name field holds route (callout 13), the Label field holds Route (callout 14), and the Open variable editor button is marked by callout 15",width=900]
. Choose *Prometheus* and set up the query so that it returns the values of the label `uri`, filtered by the first variable. The query refers to the first variable as `$application`, which is what chains the two variables:
+
[source,text]
----
label_values(http_server_requests_seconds_count{application="$application"}, uri)
----
. Close the editor.
+
image::monitoring-alerting-grafana-guide-g13-07-chained-query.svg["The variable query editor with the chained query: label_values of the metric http_server_requests_seconds_count filtered by application equal to $application, for the label uri, typed in the editor (callout 16); the close icon is marked by callout 17",width=900]
. Under *Selection options*, switch on *Multi-value*.
. Switch on *Include All value*, so that the control offers *All* next to the single routes.
+
image::monitoring-alerting-grafana-guide-g13-08-selection-options.svg["The Query variable form of the variable route scrolled to Selection options: the toggle Multi-value is on (callout 18), Include All value is on (callout 19) and Allow custom values stays off",width=900]

=== Add a custom, an interval and a data source variable

[start=20]
. Click the plus button next to *Variables* and choose *Custom*.
. Type `percentile` in *Name*.
. Type `Percentile` in *Label*.
. In the list of values, type `0.5,0.9,0.95,0.99`.
+
image::monitoring-alerting-grafana-guide-g13-09-custom-variable.svg["A Custom variable form: Name percentile (callout 21), Label Percentile (callout 22) and the list of values 0.5,0.9,0.95,0.99 (callout 23)",width=900]
. Click the plus button next to *Variables* and choose *Interval* ("Values are timespans, ex 1m, 1h, 1d").
. Type `window` in *Name*.
. Type `Window` in *Label*.
. In the list of intervals, type `1m,5m,10m`.
+
image::monitoring-alerting-grafana-guide-g13-10-interval-variable.svg["An Interval variable form: Name window (callout 25), Label Window (callout 26) and the list of intervals 1m,5m,10m (callout 27)",width=900]
. Click the plus button next to *Variables* and choose *Data source*.
. Type `ds` in *Name*.
. Choose the type *Prometheus*.
+
image::monitoring-alerting-grafana-guide-g13-11-datasource-variable.svg["A Data source variable form: Name ds (callout 29) and the data source type Prometheus (callout 30)",width=900]

=== Add a Filter and Group by control

[start=31]
. Click the plus button next to *Filters*.
. For the new *Filter and Group by* entry, choose the data source *Prometheus*. The control now offers label filters and a group by for the queries of that data source.
+
image::monitoring-alerting-grafana-guide-g13-12-filters.svg["The Dashboard pane with the list Filters open: the plus button of Filters is marked by callout 31 and the new entry for the Filter and Group by control shows the data source Prometheus, marked by callout 32",width=900]

=== Use the variables in a panel

[start=33]
. Click *Add* in the toolbar, click the *Panel* tile in the *Add* pane and click *Edit visualization*, as in the first dashboard guide.
. Open the data source picker of query *A* and choose the variable `+${ds}+`, which is listed with the data sources.
. Click *Code* in the *Builder* / *Code* switch.
. Click inside the query editor first, so that it has the focus, then type the query on one line (the editor may wrap it):
+
[source,promql]
----
sum by (status) (rate(http_server_requests_seconds_count{application="$application", uri=~"$route"}[$window]))
----
. Click *Run queries*.
. Under *Suggestions*, click *Time series*.
. In the options pane, under *Panel options*, type `Requests per second for $route` in *Title*.
+
image::monitoring-alerting-grafana-guide-g13-13-panel-query.svg["Panel editor of a time series panel titled Requests per second for $route: the data source picker holds the variable ds (callout 34), the query that uses $application, $route and $window is typed in the editor (callout 36), Run queries is marked by callout 37 and the Title field of the options pane holds the same title (callout 39)",width=900]

=== Repeat the panel for each route

[start=40]
. In the options pane, open the category *Repeat options*.
. Choose the variable `route` as the variable to repeat by.
+
image::monitoring-alerting-grafana-guide-g13-14-repeat-options.svg["Options pane of the panel with the category Repeat options open: the category header is marked by callout 40 and its variable select holds route, marked by callout 41",width=900]
. Click *Save* in the header of the editor.
. In the *Save dashboard* drawer, click *Save*.
. Click *Back*.
. Click *Exit edit*.
. If Grafana 13.3.0 shows the dialog *Unsaved changes*, click *Save*, and click *Save* again in the drawer that opens.

== Check the result

Open *Dashboards* → *Guides* → *Bookshelf (guides)*. The controls *Application*, *Route*, *Window*, *Percentile* and *ds* sit above the panels. In *Route*, select `/api/books`, `/api/loans` and `/api/search`; the panel *Requests per second for $route* is drawn once for each of them, and the title of every copy names its route. Choosing *All* draws one copy for each of the four routes of the Bookshelf service. Change *Window* to `1m` and watch the lines get more jagged.

To try the *Filter and Group by* control, use it at the top of the dashboard to add a filter for the label `status` with the value `404`, and see the lines for the other status codes disappear from the panels that use the data source *Prometheus* queries.

To see a new series appear in every copy, force errors, wait about a minute and press *Refresh*:

[source,bash]
----
curl -X POST localhost:8090/mode/failing
----

Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Repeat a whole row instead of a panel: in edit mode add a row from the *Add* pane under *Group layouts*, move the panel into the row, remove the repeat of the panel and choose the variable `route` in the repeat options of the row.
* Use the custom variable in a latency query: put `$percentile` as the first argument of `histogram_quantile` and `$window` as the range of `rate`, and choose another percentile in the control.
* Add a *Switch* variable (the new type of step 5) and use it to turn a part of a query on and off.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The *Route* control is empty
|The second variable asks for the routes of `$application`, and the first variable has no value yet.
|Pick a value in *Application* and press *Refresh*, or check that the query of *Application* returns `bookshelf`.

|The panel is not repeated
|The variable of the repeat is not multi-value, or only one route is selected.
|Switch on *Multi-value* and *Include All value* in the variable `route` and select several routes or *All*.

|The panel says *No data* for `$window`
|The interval variable holds a value that is not a duration, such as an empty list entry.
|Open the variable `window` and keep only entries like `1m,5m,10m`.

|The picker does not list `+${ds}+`
|The data source variable was not saved, or its type is not *Prometheus*.
|Open the variable in the sidebar and set the type *Prometheus*, then open the picker again.

|The title of a copy shows `$route`
|The panel is not repeated, so the variable is shown with all its values.
|Select the routes in *Route* and check the repeat options of the panel.
|===

== Clean up

Keep the variables and the panel if you want to try the variations. To remove the panel, open the dashboard in edit mode, select it, click *Delete* in the *Panel* pane of the right sidebar and save the dashboard. A variable is removed from its form with *Delete*. The later guides in this series do not depend on them.
