Checked on 2026-11-09 against Grafana 13.3.x.

Grafana is a web application that connects to the places where telemetry is stored, queries them where they are, and turns
the answers into dashboards, exploration tools and alerts. It stores almost no telemetry itself: metrics stay in Prometheus
or Mimir, logs in Loki or Elasticsearch, traces in Tempo, and Grafana keeps only its own configuration (dashboards, folders,
users, alert rules). This subsection teaches that application from the point of view of someone who must build monitoring
for a service: how to run it, how to model access, how to query, how to design dashboards and how to alert, with the
Bookshelf example from the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] as the running case.

The concepts that are shared with Kibana (signals, metric types, SLOs, alert design) are on the section root pages and are not
repeated here; start with xref:backend/monitoring-alerting/observability-fundamentals.adoc[Observability Fundamentals] if the
vocabulary is new. The existing pages on xref:database/prometheus/index.adoc[Prometheus] already cover installing Prometheus,
PromQL and Alertmanager, and the short xref:database/prometheus/grafana-dashboards-and-visualization.adoc[Grafana: Dashboards & visualization]
page is a quick start; this subsection goes much deeper and reflects the current documentation.

== Editions

Grafana is delivered in three forms. They share one code base, so the pages of this subsection apply to all of them unless a
page says otherwise.

[cols="1,3",options="header"]
|===
| Edition
| What it is

| Grafana OSS
| The free, self-managed open source edition. It queries, visualizes and alerts on metrics, logs and traces, and includes
  provisioning, LDAP and OAuth authentication, notification contact points, and folder and dashboard permissions. Image:
  `grafana/grafana`.

| Grafana Enterprise
| A self-managed edition with the features that larger organisations ask for: role-based access control (RBAC), data source
  permissions, team sync, reporting, auditing, Vault integration, query caching and enterprise data source plugins, plus
  official support. Image: `grafana/grafana-enterprise`, which the official Docker guide recommends as the default and
  describes as free and including all OSS features. Features that need a licence are described on each page as "Enterprise".

| Grafana Cloud
| The fully managed platform hosted by Grafana Labs, bundling Grafana with hosted metrics, logs and traces back ends and
  with products that only exist there (for example SLOs and IRM, see
  xref:backend/monitoring-alerting/grafana/slo-and-irm.adoc[SLOs and IRM]). Some server-level concepts do not exist on Cloud
  (there is no server administrator and no configuration file).
|===

Source: https://grafana.com/docs/grafana/latest/introduction/[Grafana introduction] and
https://grafana.com/docs/grafana/latest/introduction/grafana-enterprise/[Grafana Enterprise].
The image recommendation is from https://grafana.com/docs/grafana/latest/setup-grafana/installation/docker/[Run Grafana Docker image].

This site describes capabilities only and names no prices; whether a feature needs a paid subscription is stated per feature.

== Version baseline: Grafana 13.3

The latest stable version on the check date is Grafana 13.3.0, released on 2026-10-27, together with maintenance releases of
the 13.2, 13.1, 13.0 and 12.4 lines. All the pages in this subsection were checked against the 13.3 documentation at
`https://grafana.com/docs/grafana/latest/`. Docs URLs changed along the way: dashboards, Explore and the Drilldown apps now
live under `/visualizations/`, and "As code and provisioning" is a top-level `/as-code/` section.

Source: https://github.com/grafana/grafana/releases[Grafana releases on GitHub] and
https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v13/whats-new-in-v13-3/[What's new in Grafana 13.3].

== What changed from 11.x to 13.x

Most books and many blog posts predate the changes below, so this list is the quickest way to recognise advice that no
longer applies. Each row links to the official page it was taken from.

[cols="1,4,2",options="header"]
|===
| Version
| Change
| Reference

| 11.0
| Legacy dashboard alerting was removed entirely and can no longer be enabled; only Grafana Alerting remains. (The
  "classic condition" expression still exists, but it is legacy; prefer Reduce and Threshold expressions.)
| https://archive.grafana.com/docs/grafana/v11.0/breaking-changes/breaking-changes-v11-0/[Breaking changes in 11.0] (archived)

| 12.0
| Angular plugins no longer run, and the core Angular panels in existing dashboards are force-migrated to their React
  versions (Graph became Time series, Singlestat became Stat, Worldmap became Geomap). The `editors_can_admin` setting was
  removed, so editors can no longer create and manage teams (they keep the teams they already created). Data source UIDs
  are validated strictly by the REST APIs and by provisioning. Metrics, Logs and Traces Drilldown are GA; Grafana-managed
  alerts and recording rules are GA.
| https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v12/whats-new-in-v12-0/[What's new in 12.0]

| 13.0
| Dynamic dashboards (Scenes-based) are GA and on by default, and the option to disable Scenes is gone; existing dashboards
  migrate to the new schema when opened. Git Sync is GA. Folders and dashboards move from the legacy SQL tables to unified
  storage at startup. `grafana-cli` and `grafana-server` were removed in favour of `grafana cli` and `grafana server`. The
  Image Renderer plugin is no longer supported (the renderer is a separate service). Data source APIs that use numeric `id`
  are disabled by default (use `uid`). `/api` is deprecated in favour of `/apis`. Legacy Alertmanager configuration
  endpoints were removed or restricted. HTTP compression (`enable_gzip`) is on by default. Version 13.0.0 had a migration
  bug and was withdrawn; use 13.0.1 or later, and restore a backup first if you already ran 13.0.0.
| https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v13/whats-new-in-v13-0/[What's new in 13.0] and
https://grafana.com/docs/grafana/latest/upgrade-guide/upgrade-v13/upgrade-v13.0/[Upgrade to 13.0]

| 13.1
| Git Sync additions (dashboard import into synced folders, verified commits); multi-property variables, section-level
  variables and the Filter and Group by control are GA. The page lists no removals.
| https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v13/whats-new-in-v13-1/[What's new in 13.1]

| 13.2
| Saved queries are GA on Enterprise and Cloud; the redesigned query variable editor is GA; Git Sync gains GitHub
  Enterprise support. The page lists no removals.
| https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v13/whats-new-in-v13-2/[What's new in 13.2]

| 13.3
| Public preview of the Prometheus Alerting app plugin (management of Prometheus, Mimir and Loki rules moves there;
  Grafana-managed alerting stays in core; experimental on Enterprise), Alertmanager configuration import, Alert Advisor,
  cross-dashboard variables and Notebooks. Role managers can revoke access they do not hold (Enterprise).
| https://grafana.com/docs/grafana/latest/whatsnew/whats-new-in-v13/whats-new-in-v13-3/[What's new in 13.3]
|===

Two renames are worth remembering because older material uses the old names. Explore Metrics, Logs, Traces and Profiles are
now the *Drilldown* apps (xref:backend/monitoring-alerting/grafana/queries-explore-and-drilldown.adoc[Queries, Explore and Drilldown]).
"Public dashboards" are now *externally shared dashboards* (menu entry "Share externally"), which still do not support variables
(xref:backend/monitoring-alerting/grafana/sharing-and-reporting.adoc[Sharing and Reporting]). Two security terms also changed:
API keys were replaced by service accounts, and "fine-grained access control" is now RBAC
(xref:backend/monitoring-alerting/grafana/users-teams-and-permissions.adoc[Users, Teams and Permissions]).

For the collectors, Grafana Agent reached end of life on 2025-11-01 and Promtail on 2026-03-02; the replacement for both is
Grafana Alloy (xref:backend/monitoring-alerting/telemetry-collection-pipelines.adoc[Telemetry Collection Pipelines]). Sources:
https://grafana.com/docs/loki/latest/setup/migrate/migrate-to-alloy/[Migrate to Alloy] and
https://grafana.com/docs/loki/latest/send-data/promtail/[Promtail].

== The running example

Every page uses Bookshelf, the Spring Boot 4.1 book catalogue that is instrumented with Micrometer and OpenTelemetry
(`/actuator/prometheus`, OTLP traces, JSON logs, PostgreSQL). Its instrumentation is described in
xref:backend/springboot/metrics-and-observability.adoc[Spring Boot metrics and observability] and
xref:backend/springboot/logging.adoc[Spring Boot logging]; Kubernetes deployment in
xref:backend/kubernetes/observability-logging-and-metrics.adoc[Kubernetes observability]; load and resilience scenarios in
xref:backend/resilience/index.adoc[Resilience]. In the lab, Alloy ships Bookshelf's telemetry to Prometheus (or Mimir), Loki and Tempo,
and Grafana 13.3 reads from all three.

== In the books

Several books in the bibliography teach Grafana, and all of them describe older versions: *Getting Started with Grafana*
(McCollam) covers Grafana 8.2/8.3, *Building IoT Visualizations using Grafana* (Hernandez) Grafana 8, *Learn Grafana 10.x*
(Salituro) Grafana 10 and *Observability with Grafana* (Chapman and Holmes) Grafana 10.2. They remain good for method (how
to think about dashboards, personas, SLO-driven alerting). The pages that follow state, section by section, what the books
get wrong for 13.3; as a rule of thumb, ignore any instruction that mentions API keys, "fine-grained access control",
Angular panels, the Graph, Singlestat or Worldmap panels, legacy alerting, Grafana Agent, Promtail, or `grafana-cli`.
The publisher pages are linked in the xref:backend/monitoring-alerting/index.adoc#_bibliography[bibliography].
