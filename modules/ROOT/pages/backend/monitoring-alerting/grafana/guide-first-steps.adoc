== What you build

You start Grafana in the lab, sign in, learn where the main areas of the left navigation lead, and open the dashboard
*Bookshelf service health* that the lab provisions. You change its time range, refresh it, and finally create an empty
folder called *Guides*. Every later guide in this series saves the dashboards it builds in that folder.

image::monitoring-alerting-grafana-guide-g1-11-result.svg["The new folder page Guides in Grafana 13.3: the title Guides, the tabs Dashboards, Panels and Alert rules, and the empty state This folder does not have any dashboards yet with a Create dashboard button",width=900]

== Before you start

* Docker with Compose must be running. The Grafana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] starts Grafana, Prometheus, Loki, Tempo, the Bookshelf service and its load generator.
  Start it and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile grafana up -d
----
* Open http://localhost:3000. The lab sign-in is `admin` with the password `admin`. When Grafana 13.3 shows the screen *Update your password*, click *Skip*.
* This is the first guide of the Grafana series, so no earlier guide is required. The installation page, xref:backend/monitoring-alerting/grafana/installation-and-configuration.adoc[Installation and Configuration], explains the same product outside the lab.
* The guide was checked on Grafana Enterprise 13.3.0 (the free image, no licence key). Creating a folder needs the *Editor* or *Admin* role of the organization; `admin` has it.
* The figures are drawings of the Grafana 13.3 user interface, not screenshots, so small details can differ from your screen.
  A highlighted box with a number marks the control of the step with the same number.

== Steps

The guide walks through five small areas: the sign-in, the navigation, the dashboard list, a dashboard and a folder. There is no screen map in this guide; the screen maps of the later guides show the dashboard, the panel editor and Explore.

=== Start the lab and sign in

. Open a terminal in the folder that holds the lab and start the Grafana profile. Skip this step if you started it already.
+
[source,bash]
----
docker compose --profile grafana up -d
----
. Open http://localhost:3000 and type `admin` in the field *Email or username*.
. Type `admin` in the field *Password*.
. Click *Log in*.
+
image::monitoring-alerting-grafana-guide-g1-01-sign-in.svg["Sign-in page of Grafana 13.3 titled Welcome to Grafana: the field Email or username holds admin (callout 2), the field Password holds dots (callout 3) and the Log in button is marked by callout 4",width=900]
. Grafana 13.3 now asks you to update the default password. Click *Skip* under the *Submit* button.
+
image::monitoring-alerting-grafana-guide-g1-02-update-password.svg["Update your password screen of Grafana 13.3 with the fields New password and Confirm new password, the Submit button and the Skip link, which is marked by callout 5",width=900]

=== Tour the navigation

[start=6]
. Look at the left navigation, which is docked open in 13.3. It lists *Bookmarks*, *Starred*, *Dashboards*, *Explore*, *Drilldown*, *AI*, *Alerting*, *Connections* and *Administration*. Grafana 13.3 has no separate *Home* entry in it.
. In the top bar, click *New* (the *+* button).
+
image::monitoring-alerting-grafana-guide-g1-03-home-navigation.svg["Home page of Grafana 13.3 with the docked left navigation listing Bookmarks, Starred, Dashboards, Explore, Drilldown, AI, Alerting, Connections and Administration (callout 6) and the New button of the top bar marked by callout 7",width=900]
. The menu offers *New dashboard* and *Import dashboard* under *Dashboards* and *New alert rule* under *Alerting*. Press the Escape key to close it.
+
image::monitoring-alerting-grafana-guide-g1-04-new-menu.svg["The New menu of the top bar is open with the headings Dashboards, offering New dashboard and Import dashboard, and Alerting, offering New alert rule; callout 8 marks the menu that the Escape key closes",width=900]

=== Open the provisioned dashboard

[start=9]
. In the left navigation, click *Dashboards*.
. Click the folder *bookshelf* to expand it.
. Click the dashboard *Bookshelf service health*. The lab provisions it, so it exists as soon as Grafana starts.
+
image::monitoring-alerting-grafana-guide-g1-05-dashboards-page.svg["Dashboards page of Grafana 13.3: callout 9 marks the Dashboards item of the navigation, callout 10 marks the folder bookshelf and callout 11 marks the dashboard Bookshelf service health listed under it",width=900]
. Look at the dashboard. The variables *Job*, *Application* and *Route* and the toggle *Deployments* are at the left of the toolbar. The toolbar at the right has the time range button, *Refresh*, the interval select, *Share* and *Edit*.
  The panels sit in three rows: *Golden signals*, *Logs and traces* and *Dependencies*.
+
image::monitoring-alerting-grafana-guide-g1-06-bookshelf-dashboard.svg["Dashboard Bookshelf service health in Grafana 13.3 with the variables Job, Application and Route and the toggle Deployments on the left, the toolbar with the time range, Refresh, interval, Share and Edit on the right, and the rows Golden signals, Logs and traces and Dependencies; callout 12 marks the variables",width=900]

=== Change the time range and refresh

[start=13]
. Click the time range button, which shows *Last 6 hours UTC* when the dashboard opens.
. Choose a shorter range from the list. The button now shows the new range and every panel redraws.
+
image::monitoring-alerting-grafana-guide-g1-07-time-range.svg["Toolbar of the dashboard Bookshelf service health: the time range button Last 6 hours UTC is marked by callout 13",width=900]
. Click *Refresh*. All panels run their queries again.
. Open the interval select next to *Refresh*. The lab provisions the dashboard with `30s`, so it reloads itself every 30 seconds. Choose another interval from the list if you want, and the dashboard follows it.
+
image::monitoring-alerting-grafana-guide-g1-08-refresh.svg["Toolbar of the dashboard Bookshelf service health: the Refresh button is marked by callout 15 and the interval select next to it, which shows 30s, is marked by callout 16",width=900]

=== Create the folder Guides

[start=17]
. In the left navigation, click *Dashboards* again.
. Click *New* at the top right of the page.
. Click *New folder*.
+
image::monitoring-alerting-grafana-guide-g1-09-new-folder-menu.svg["Dashboards page of Grafana 13.3 with the New menu open: callout 17 marks the Dashboards item of the navigation, callout 18 marks the New button and callout 19 marks New folder in the menu",width=900]
. In the drawer *New folder* that opens on the right, type `Guides` in *Folder name*.
. Click *Create*.
+
image::monitoring-alerting-grafana-guide-g1-10-new-folder-drawer.svg["New folder drawer of Grafana 13.3: the Folder name field holds Guides (callout 20) and the Create button is marked by callout 21",width=900]
. The folder page opens with the title *Guides*, the tabs *Dashboards*, *Panels* and *Alert rules*, and the message that the folder has no dashboards yet.

== Check the result

Open *Dashboards*. The list must now show a folder *Guides* next to *bookshelf*, and the dashboard *Bookshelf service health* must still draw its panels for the range you chose.

To see the dashboard react to the traffic, change the mode of the load generator and press *Refresh*:

[source,bash]
----
curl -X POST localhost:8090/mode/failing
----

Wait about a minute and refresh again; the panels of the row *Golden signals* show the failing requests. Restore normal traffic afterwards:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Mark the dashboard as a favorite with the star next to its name in the breadcrumbs, and find it again under *Starred* in the navigation.
* Open the dashboard with a fixed address instead of the folder tree: http://localhost:3000/d/bookshelf-service-health.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|http://localhost:3000 does not answer
|The containers are still starting, or the profile was not started.
|Wait a minute, then run `docker compose --profile grafana ps` in the lab folder and start the profile again with the command of the first step if Grafana is not listed.

|*Log in* is refused
|The password was changed in an earlier run, or the volumes of an older lab keep a different admin password.
|Use the password you set earlier, or remove the volumes with `docker compose --profile grafana down -v` and start again.

|The screen *Update your password* does not appear
|Grafana shows it only once, at the first sign-in with the default password.
|Nothing to fix; go on with the navigation.

|The panels of the dashboard are empty
|The lab started less than a minute ago, so Prometheus has few samples, or the load generator is stopped.
|Wait a minute and press *Refresh*. Check the mode with `curl localhost:8090/` and send `curl -X POST localhost:8090/mode/normal` if it is not `normal`.

|The folder *Guides* exists twice
|The steps were run twice.
|Check *Dashboards* before step 20 and open the existing folder instead of creating another.
|===

== Clean up

Keep the folder: the other guides of this series save their dashboards in it. To remove everything the lab stores, stop the
profile with `docker compose --profile grafana down -v`, which also deletes the volumes and therefore the folder.
