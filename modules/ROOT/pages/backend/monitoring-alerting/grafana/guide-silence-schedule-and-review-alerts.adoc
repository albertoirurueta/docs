= Grafana Guide: Silence, Schedule and Review Alerts
:description: Step-by-step guide to Grafana 13.3: silence the firing rule Guide high 5xx ratio for 30 minutes, create a time interval and attach it to the route of your notification policy tree, read the alert state history, add an alert list panel to the dashboard Bookshelf (guides) and create a Grafana-managed recording rule.
:keywords: Grafana, alerting, silence, mute timing, time interval, notification policy, state history, alert list panel, recording rule, Prometheus, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You keep the rule *Guide high 5xx ratio* running but stop its notifications in two ways: a one-off silence for 30 minutes and a recurring time interval
*guide-quiet-hours* attached to the route of your notification policy tree. You then review what happened in the alert state history, show the rule on the dashboard
*Bookshelf (guides)* with an alert list panel, and record the request rate by status as a new metric with a Grafana-managed recording rule.

image::monitoring-alerting-grafana-guide-g18-12-result.svg["The dashboard Bookshelf (guides) in view mode with two panels: the request rate by status and the new Alerts (guides) panel, an alert list that shows the rule Guide high 5xx ratio with the state Alerting",width=900]

== Before you start

* Start the Grafana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile grafana up -d
----
* Open http://localhost:3000, sign in as `admin` with the password `admin`, and click *Skip* when Grafana 13.3 asks you to update the default password.
* Do the previous guides: xref:backend/monitoring-alerting/grafana/guide-create-an-alert-rule.adoc[Create an alert rule] (the rule *Guide high 5xx ratio* in the evaluation group `guide-eval`),
  xref:backend/monitoring-alerting/grafana/guide-send-notifications.adoc[Send notifications] (the contact point *guide-webhook* and the tree *guide-tree* with the route `team = bookshelf-guides`)
  and xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel] (the dashboard *Bookshelf (guides)*).
* The lab provisions a policy tree, a time interval and rules that Grafana shows read-only. Everything you create here is new and prefixed `guide`.
* The recording rule writes to the lab's Prometheus, which accepts remote write. The lab sets it up; you do not have to change anything.
* The guide was checked on Grafana Enterprise 13.3.0 (the free image, no licence key). Notification and rule resources need the *Editor* or *Admin* role; `admin` has it.
* The figures are drawings of the Grafana 13.3 user interface, not screenshots, so small details can differ from your screen.
  A highlighted box with a number marks the control of the step with the same number.
  Where a form was not read in the lab (the route form, the recording rule form, the dashboard steps of the alert list), the figure shows the values and plain captions, and the step names the control by its function.

== Steps

The rule page and the list of rules are the screens of the guide xref:backend/monitoring-alerting/grafana/guide-create-an-alert-rule.adoc[Create an alert rule]; the dashboard and panel editor are those of
xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel].

=== Silence a firing alert

. Force the failure and wait about two minutes, until the rule is *Firing*:
+
[source,bash]
----
curl -X POST localhost:8090/mode/failing
----
. In *Alerting* → *Alert rules*, open the rule *Guide high 5xx ratio* in the folder *Guides*, evaluation group `guide-eval`.
+
image::monitoring-alerting-grafana-guide-g18-01-alert-rules.svg["Alert rules page of Grafana 13.3 with the grouped list: the folder Guides holds the evaluation group guide-eval, every 1m, and its rule Guide high 5xx ratio with the state Firing, marked by callout 2",width=900]
. Open the *Instances* tab.
. In the row of the firing instance, click *Silence*, in the *Destination* column.
+
image::monitoring-alerting-grafana-guide-g18-02-instances.svg["Rule page of Guide high 5xx ratio on the Instances tab, marked by callout 3: the table lists one instance with the state Alerting, its labels, the creation time and the destination guide-webhook with a Silence button, marked by callout 4",width=900]
. In the form *Silence alert rule*, which opens with the labels of the instance already filled in, type `30m` in *Duration*. *Silence start and end* changes to match.
. Type `Guide: planned test` in *Comment*.
. Click *Save silence*.
+
image::monitoring-alerting-grafana-guide-g18-03-silence-form.svg["Silence alert rule form prefilled from the instance: the Duration field holds 30m (callout 5), the Matching labels list alertname and team, the Comment field holds a short text (callout 6) and the Save silence button is marked by callout 7",width=900]

=== Mute a policy on a schedule

[start=8]
. In *Alerting* → *Notification configuration*, open the *Time intervals* tab and click the button that creates a new time interval. The form is titled *New time interval*.
. In *Name*, type `guide-quiet-hours`.
. Under *Time intervals* → *Time range*, type a *Start time* a few minutes before now, for example `10:00`.
. Type an *End time* after now, for example `12:00`.
. In *Location*, type `UTC`, so that the window uses the same clock as the receiver output, and take your start and end times from the current UTC time.
. Click *Save time interval*.
+
image::monitoring-alerting-grafana-guide-g18-04-time-interval-form.svg["New time interval form: the field Name holds guide-quiet-hours (callout 9), the Time range of the group Time intervals has the Start time 10:00 (callout 10) and the End time 12:00 (callout 11), the Location is UTC (callout 12), and the Save time interval button is marked by callout 13",width=900]
. Open the *Notification policies* tab. In the tree *guide-tree*, find the route `team = bookshelf-guides` and open its *More* menu.
+
image::monitoring-alerting-grafana-guide-g18-05-route-more.svg["Notification policies tab with the tree guide-tree and its route team = bookshelf-guides, whose More button at the right is marked by callout 14",width=900]
. Choose *Edit*, pick `guide-quiet-hours` as a mute timing in the timing options of the route, and save the route. The labels of the route form were not read in the lab, so look for the field that lists the time intervals to mute.

=== Read the alert history

[start=16]
. In the left navigation, click *Alerting*, then *History*.
. Set *End state* to *Alerting*. The *Start state* filter and the labels filter work the same way.
+
image::monitoring-alerting-grafana-guide-g18-06-history.svg["History page of Grafana 13.3 with the Alerting group of the navigation open: callout 16 marks History, and callout 17 marks the End state filter above the table Alert Events with the columns Timestamp, State, Alert rule and Instance",width=900]
. Read the table *Alert Events*: each row has a *Timestamp*, a *State*, the *Alert rule* and the *Instance* labels. The page lists every event whether or not a silence or a time interval applied, so your silenced alert is still there.

=== Show the alerts on the dashboard

[start=19]
. Open *Dashboards* → *Guides* → *Bookshelf (guides)* and click *Edit*.
. Click *Add*, click the *Panel* tile in the *Add* pane, and then *Edit visualization*, as in the first-dashboard guide.
. In the right column, under *Start without data*, click the card *Alert list*.
+
image::monitoring-alerting-grafana-guide-g18-07-choose-alert-list.svg["Panel editor of a new panel on the dashboard Bookshelf (guides): under Start without data the cards Text, Alert list and Dashboard list are offered and the Alert list card is marked by callout 21",width=900]
. Under *Panel options*, type `Alerts (guides)` in *Title*.
. Under *Filter*, type `Guide` in *Alert name*, so that only your rules are listed.
. Under *Alert state filter*, tick *Alerting / Firing* and *Pending*.
+
image::monitoring-alerting-grafana-guide-g18-08-alert-list-options.svg["Panel editor with the Alert list options pane: the Title field holds Alerts (guides) (callout 22), the Alert name filter holds Guide (callout 23) and the Alert state filter has Alerting or Firing and Pending ticked (callout 24); the preview lists the firing rule Guide high 5xx ratio",width=900]
. Click *Save*, *Back*, then *Exit edit*, and *Save* again if the dialog *Unsaved changes* appears, as in the first-dashboard guide.

=== Record the request rate

[start=26]
. In *Alerting* → *Alert rules*, click *More* and choose *New Grafana recording rule*.
+
image::monitoring-alerting-grafana-guide-g18-09-alert-rules-more.svg["Alert rules page with the buttons New alert rule and More at the top right; the More button is marked by callout 26 and opens the entry for a new Grafana recording rule",width=900]
. Type `Guide request rate` as the name of the rule.
. Type `guide:http_server_requests:rate1m` as the metric name.
. Choose the data source *Prometheus* and enter the query, as an instant query if the form offers the choice:
+
[source,promql]
----
sum by (status) (rate(http_server_requests_seconds_count{application="bookshelf"}[1m]))
----
. Choose the folder `Guides` and the evaluation group `guide-eval`.
. Click *Save rule*.
+
image::monitoring-alerting-grafana-guide-g18-10-recording-rule-form.svg["Form of a new Grafana recording rule, shown with its values: the rule name Guide request rate (callout 27), the metric name guide:http_server_requests:rate1m (callout 28), the Prometheus query for the request rate by status (callout 29), the folder Guides and the evaluation group guide-eval (callout 30) and the Save rule button (callout 31)",width=900]
. After a minute or two, open *Explore* with the data source *Prometheus* and run the recorded metric:
+
[source,promql]
----
guide:http_server_requests:rate1m
----
+
image::monitoring-alerting-grafana-guide-g18-11-explore-recorded.svg["Explore with the Prometheus data source in Code mode: the query guide:http_server_requests:rate1m, marked by callout 32, returns one line for the status 200 and one for 404, the series the recording rule writes",width=900]

== Check the result

* *Alerting* → *Silences* lists the silence with your comment until it ends. To see the effect on notifications, restore normal traffic (`curl -X POST localhost:8090/mode/normal`),
  wait until the rule is *Normal*, force the failure again and read the receiver with `curl localhost:8081/`: the rule goes *Pending* and *Firing* again, and *History* records it, but no new entry with the path `/guide` arrives while the silence lasts.
* The same holds while the time of day is inside `guide-quiet-hours`: the route does not send. Entries with the path `/grafana` still arrive, because the provisioned rules use the provisioned tree.
* The dashboard shows the panel *Alerts (guides)* with the rule *Guide high 5xx ratio* while it is *Alerting* or *Pending*.
* *Explore* returns one series per status for the metric `guide:http_server_requests:rate1m`. The lab did not measure how long the first point takes; the rule evaluates every minute.

Restore normal traffic when you are done:

[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

== Variations

* Open *Alerting* → *Silences* to create a silence from scratch, with your own matchers, instead of from an instance.
* Change the time interval to recurring days (for example Saturday and Sunday) with *Days of the week*, as the provisioned interval `bookshelf-weekends` does.
* Switch the alert list panel to its *Stat* view mode in the options pane.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix

|The instance has no *Silence* button
|The rule is not firing yet, so the *Instances* tab lists no alerting instance.
|Wait for the state *Firing* on the rule page; check the failure mode with `curl localhost:8090/`.

|The silence does not match the alert
|The matchers were edited, or the labels of the instance changed.
|Open the silence from the *Silence* button of the instance, so that the labels come prefilled.

|The time interval has no effect
|The window does not contain the current time in the chosen *Location*, or the interval is not attached to the route.
|Compare your clock in UTC with the window and check that the route lists `guide-quiet-hours`.

|The alert list panel is empty
|The *Alert name* filter does not match, or the state filter excludes the current state.
|Clear *Alert name* or tick more states, and press *Refresh*.

|The recorded metric does not appear in *Explore*
|The rule has not been evaluated yet, or the target data source does not accept the written samples.
|Wait two minutes and run the query again; check the evaluation state of the rule on the rule page.
|===

== Clean up

Keep the time interval, the panel and the recording rule if you want to continue with the next guide. To remove the mute, edit the route again and clear the time interval, or delete `guide-quiet-hours`
from the *Time intervals* tab once no route uses it. Silences expire on their own after their duration. Restore normal traffic with `curl -X POST localhost:8090/mode/normal`.
To delete everything the lab stores, stop the profile with `docker compose --profile grafana down -v`.
