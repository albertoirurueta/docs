= Grafana Guide: Create an Alert Rule
:description: Step-by-step guide to Grafana 13.3: create a webhook contact point and the alert rule Guide high 5xx ratio on the Bookshelf request metrics, force the failure with the lab load generator and watch the rule go from Normal to Pending to Firing.
:keywords: Grafana, alerting, alert rule, contact point, webhook, pending period, evaluation group, labels, runbook URL, Normal, Pending, Firing, Recovering, Prometheus, Bookshelf, step by step, guide

include::partial$ai-disclaimer.adoc[]

Checked on 2026-11-11 against Grafana 13.3.x.

== What you build

You create a Grafana-managed alert rule named *Guide high 5xx ratio* that fires when more than 20 percent of the requests answered by the Bookshelf
service end with a 5xx status. The rule lives in the folder *Guides*, is evaluated every minute by the group `guide-eval`, waits one minute in the
state *Pending* before it fires, and sends its notification to a webhook contact point called `guide-webhook`. You then break the Bookshelf service
on purpose with the load generator and watch the rule change state.

image::monitoring-alerting-grafana-guide-g16-14-result.svg["The finished alert rule Guide high 5xx ratio in the folder Guides while the load generator is in failing mode: the header badge reads Firing and the only instance is in the state Alerting, with its labels and the contact point guide-webhook",width=900]

== Before you start

* Start the Grafana profile of the xref:backend/monitoring-alerting/hands-on-lab.adoc[hands-on lab] and wait about a minute:
+
[source,bash]
----
cd lab
docker compose --profile grafana up -d
----
* Open http://localhost:3000, sign in as `admin` with the password `admin`, and click *Skip* when Grafana 13.3 asks you to update the default password.
* Do the previous guide, xref:backend/monitoring-alerting/grafana/guide-reuse-versions-and-sharing.adoc[Reuse, versions and sharing], or at least
  xref:backend/monitoring-alerting/grafana/guide-first-dashboard.adoc[Create a dashboard and the first panel], which creates the folder *Guides* and the dashboard *Bookshelf (guides)* used here.
* The data source *Prometheus* is provisioned by the lab. The load generator is in its default mode, `normal`, which answers with the status codes `200` and `404` only. Check it with `curl localhost:8090/`.
* The lab also provisions its own alert rules in the folder *bookshelf*, with their own contact point `bookshelf-webhook`. They react to the same failure you provoke later and deliver to the receiver path `/grafana`.
  The rule and the contact point you create here are separate from them and deliver to `/guide`, so you can tell the two apart.
* The guide was checked on Grafana Enterprise 13.3.0 (the free image, no licence key). Creating alert rules and contact points needs the *Editor* or *Admin* role of the organization; `admin` has it.
* The figures are drawings of the Grafana 13.3 user interface, not screenshots, so small details can differ from your screen.
  A highlighted box with a number marks the control of the step with the same number.

== Steps

The rule is built on one long form that has six numbered sections. The map shows them in order; the steps below follow the same order and come back to the form section by section.

image::monitoring-alerting-grafana-map-alert-rule.svg["Map of the Grafana 13.3 New alert rule form: a single column of six numbered sections from the rule name to the notification message, and the Save and Cancel buttons at the bottom",width=900]

=== Create the contact point

A rule needs somewhere to send its notifications. The provisioned contact point is shared with the lab's own rules, so you create a small one of your own first.
The later guide xref:backend/monitoring-alerting/grafana/guide-send-notifications.adoc[Send notifications] reuses it and goes through templates, policies and the test button in detail.

. In the left navigation, click *Alerting* → *Notification configuration*.
. On the *Contact points* tab, click *New contact point*.
+
image::monitoring-alerting-grafana-guide-g16-01-notification-configuration.svg["Notification configuration page of Grafana 13.3 on the Contact points tab: callout 1 marks the Alerting item of the navigation and callout 2 marks the New contact point button, next to the cards of the provisioned contact points",width=900]
. In *Name*, type `guide-webhook`.
. Open the *Integration* picker (it shows *Email* first) and choose *Webhook*.
. In *URL*, type `http://webhook-receiver:8080/guide`. The address is the one of the lab's webhook receiver as seen from inside the Docker network.
. Click *Save contact point*.
+
image::monitoring-alerting-grafana-guide-g16-02-contact-point-form.svg["Create contact point form: the Name field holds guide-webhook (callout 3), Integration is set to Webhook (callout 4), the URL field holds http://webhook-receiver:8080/guide (callout 5) and the Save contact point button is marked by callout 6",width=900]

=== Open the rule form

[start=7]
. In the left navigation, click *Alerting* → *Alert rules*.
. Click *New alert rule* at the top right. The *+* button of the top bar offers the same entry under *Alerting*.
+
image::monitoring-alerting-grafana-guide-g16-03-alert-rules.svg["Alert rules page of Grafana 13.3: callout 7 marks the Alerting item of the navigation and callout 8 marks the New alert rule button at the top right, above the list of the provisioned rules of the folder bookshelf",width=900]

=== Name the rule and write the query

[start=9]
. In section *1 Enter alert rule name*, type `Guide high 5xx ratio` in *Name*.
. In section *2 Define query and alert condition*, check that the data source picker shows *Prometheus*. If it shows another data source, open the picker and choose *Prometheus*.
. In query *A*, click *Code* in the *Builder* / *Code* switch.
. Click inside the query editor first, so that it has the focus, then type the query. It divides the request rate of the 5xx statuses by the rate of all requests, and the last part returns `0` while there are no 5xx at all, so that the rule has a value instead of *No data* in normal mode:
+
[source,promql]
----
(sum(rate(http_server_requests_seconds_count{application="bookshelf",status=~"5.."}[1m])) / sum(rate(http_server_requests_seconds_count{application="bookshelf"}[1m]))) or vector(0)
----
+
image::monitoring-alerting-grafana-guide-g16-04-name-and-query.svg["New alert rule form, sections 1 and 2: the Name field holds Guide high 5xx ratio (callout 9), the data source picker shows Prometheus (callout 10), the Code option of the Builder and Code switch is marked by callout 11 and the query editor holds the 5xx ratio query (callout 12)",width=900]
. Under *Alert condition*, the condition reads *WHEN* *QUERY* *IS ABOVE*. Type `0.2` in the value field at the end of the row.
. Click *Preview alert rule condition*. The preview shows the current value, which is `0` in normal mode, so the condition is not met.
+
image::monitoring-alerting-grafana-guide-g16-05-alert-condition.svg["New alert rule form, lower part of section 2: the Alert condition reads WHEN QUERY IS ABOVE with the value 0.2 typed in the last field (callout 13), and the Preview alert rule condition button below is marked by callout 14",width=900]

=== Choose the folder, the labels and the evaluation

[start=15]
. In section *3 Add folder and labels*, open the *Folder* picker and choose *Guides*.
. Click *Add labels* and add two labels: `team` with the value `bookshelf-guides` and `severity` with the value `critical`. Use the dialog that opens to choose the key and the value of each label and confirm it.
+
image::monitoring-alerting-grafana-guide-g16-06-folder-and-labels.svg["New alert rule form, section 3 Add folder and labels: the Folder picker shows Guides (callout 15) and the labels area says No labels selected, with the Add labels button marked by callout 16",width=900]
. In section *4 Set evaluation behavior*, click *New evaluation group*. Name the group `guide-eval` and set its evaluation interval to `1m`, then confirm the dialog. The rule is evaluated once a minute from then on.
. Open the *Pending period* picker and choose `1m`. A condition must stay true for a whole minute before the rule fires; the time before that is the *Pending* state. Leave *Keep firing for* at *None*.
+
image::monitoring-alerting-grafana-guide-g16-07-evaluation.svg["New alert rule form, section 4 Set evaluation behavior: the New evaluation group button is marked by callout 17 and the Pending period picker shows 1m (callout 18), above Keep firing for and the collapsed Configure no data and error handling",width=900]

=== Choose the contact point and write the message

[start=19]
. In section *5 Configure notifications*, leave *Recipient* on `Alertmanager:grafana`, open the *Contact point* picker and choose `guide-webhook`.
+
image::monitoring-alerting-grafana-guide-g16-08-notifications.svg["New alert rule form, section 5 Configure notifications: the Recipient shows Alertmanager:grafana and the Contact point picker shows guide-webhook (callout 19), with the link View or create contact points beside it",width=900]
. In section *6 Configure notification message*, type this template in *Summary (optional)*. It prints the value of the Reduce step, with two decimals, when the rule fires:
+
[source,text]
----
5xx ratio is {{ printf "%.2f" $values.B.Value }}
----
. In *Runbook URL (optional)*, type `https://example.com/runbooks/high-5xx`.
. Click *Link dashboard and panel* and choose the dashboard *Bookshelf (guides)* and its panel *Requests per second by status*. The notification then carries links to them.
. Click *Save* at the bottom of the form.
+
image::monitoring-alerting-grafana-guide-g16-09-message-and-save.svg["New alert rule form, section 6 Configure notification message: the Summary field holds a template that prints the 5xx ratio (callout 20), the Runbook URL field holds a URL (callout 21), the Link dashboard and panel button is marked by callout 22 and the Save button at the bottom by callout 23",width=900]

=== Watch the rule change state

[start=24]
. Open *Alerting* → *Alert rules*, expand the folder *Guides* and click the rule *Guide high 5xx ratio*. The header shows the state *Normal*.
. Click the *Instances* tab.
+
image::monitoring-alerting-grafana-guide-g16-10-rule-normal.svg["Rule page of Guide high 5xx ratio with the green Normal badge: the summary row names the contact point guide-webhook and the labels, and the Instances tab of the tab strip is marked by callout 25",width=900]
. In a terminal, switch the load generator to its failing mode, so that the Bookshelf service answers with errors:
+
[source,bash]
----
curl -X POST localhost:8090/mode/failing
----
. Reload the page now and then. After less than a minute (35 seconds in the check run) the instance changes to *Pending* and the header badge turns orange. The rule has seen the condition true once and now waits for the pending period.
+
image::monitoring-alerting-grafana-guide-g16-11-instance-pending.svg["Instances tab of the rule Guide high 5xx ratio with an orange Pending badge in the header: the State column of the only instance shows Pending (callout 27), next to its labels and the destination guide-webhook",width=900]
. One minute later, the length of the pending period, the instance changes to *Alerting* (the header badge reads *Firing*). Grafana now sends a notification to the contact point.
+
image::monitoring-alerting-grafana-guide-g16-12-instance-firing.svg["Instances tab of the rule Guide high 5xx ratio one minute later: the header badge reads Firing and the State column of the instance shows Alerting in red (callout 28)",width=900]
. About 30 seconds after the rule fires, ask the webhook receiver what it has received. The list holds an entry with the path `/guide`, which is your rule; entries with the path `/grafana` come from the provisioned lab rules, which react to the same failure:
+
[source,bash]
----
curl -s localhost:8081
----
. Restore normal traffic:
+
[source,bash]
----
curl -X POST localhost:8090/mode/normal
----

=== Create a rule from a panel

A panel that already draws the metric is a quicker starting point than the blank form. This last part only shows where it starts, and keeps nothing.

[start=31]
. Open *Dashboards* → *Guides* → *Bookshelf (guides)* and click *Edit*.
. Click the panel *Requests per second by status* to select it, then click *Edit visualization* in the *Panel* pane of the right sidebar.
. At the bottom of the panel editor, click the *Alert* tab. The tab only exists once the dashboard has been saved, which the first guide did.
+
image::monitoring-alerting-grafana-guide-g16-13-panel-alert-tab.svg["Panel editor of the saved dashboard Bookshelf (guides): the bottom tabs are Queries, Transformations and Alert, and the Alert tab is marked by callout 33",width=900]
. Use the button of the tab that creates an alert rule from the panel. Grafana opens the same *New alert rule* form with the query of the panel already filled in. Stop here and click *Cancel* at the bottom of the form, so that no second rule is created.
. Click *Back*, then *Exit edit*. If the dialog *Unsaved changes* appears, click *Discard*, because you changed nothing.

== Check the result

Open the rule *Guide high 5xx ratio* while the load generator is in failing mode, as in steps 26 to 28: the header must read *Pending* and later *Firing*, and the webhook receiver must list an entry with the path `/guide` and a title that starts with `[FIRING:1] Guide high 5xx ratio`.
After you restore normal traffic with `curl -X POST localhost:8090/mode/normal`, the rule returns to *Normal* after about a minute and a half, because the one minute rate window of the query must drain first.
The instance can show the state *Recovering* on the way. The notification that the alert is resolved arrives at the receiver about five minutes after the firing one, because the default notification policy of Grafana sends updates to a group every five minutes.

The *History* tab of the rule and *Alerting* → *History* list every state change, with a timestamp.

== Variations

* Switch on *Advanced options* in section 2 to see what the simple condition builds for you: a *Reduce* step that takes the last value of the query (function *Last*, input *A*) and a *Threshold* step that tests it (*Is above* `0.2`). The summary template reads the value of the Reduce step as `$values.B.Value`.
* Use a longer *Pending period* such as `5m` to ignore short spikes, or *Keep firing for* to avoid an alert that flaps. The reference page on rule states explains both.
* Switch on *Advanced options* in section 5 to choose *Use notification policy* instead of a contact point. The labels of section 3 then decide where the alert is routed, as the guide on notifications shows.

== What can go wrong

[cols="2,3,3",options="header"]
|===
|Symptom |Cause |Fix
|The rule shows *No Data* instead of *Normal* in normal mode
|The query returns nothing while there are no 5xx at all, and the rule has no default value.
|Keep the part `or vector(0)` at the end of the query, or open *Configure no data and error handling* in section 4 and choose how the rule treats missing data.

|The rule stays *Normal* after `mode/failing`
|The load generator is not in failing mode, or the evaluation has not run yet, or Prometheus has few samples because the lab started a moment ago.
|Check the mode with `curl localhost:8090/`, wait one more minute and reload the page.

|The rule fires but nothing arrives at `/guide`
|The contact point has another URL, or the notification is still waiting for the group wait of the notification policy, which is about 30 seconds.
|Open the contact point in *Alerting* → *Notification configuration*, check the URL `http://webhook-receiver:8080/guide`, and read `curl -s localhost:8081` again.

|The receiver lists entries with the path `/grafana` as well
|The provisioned lab rules react to the same failure and use the contact point `bookshelf-webhook`.
|Ignore them, or read only the entries with the path `/guide`.

|The folder picker does not list *Guides*
|The first-steps guide was skipped.
|Create the folder with *Dashboards* → *New* → *New folder* and open the form again.
|===

== Clean up

Keep the rule and the contact point: the following guides send notifications and silence alerts with them. If the load generator is still in failing mode, restore it with `curl -X POST localhost:8090/mode/normal`.
To remove the rule, open it in *Alerting* → *Alert rules* and use the *More* menu of its page; to remove everything the lab stores, stop the profile with `docker compose --profile grafana down -v`, which also deletes the volumes.
