This page is written against axum 0.8.9, axum-extra 0.12.6 and reqwest 0.13 on Rust 1.99 (edition 2024), checked on
2026-10-06. Many "real-time" features only need the server to *push*: notifications, progress bars, live dashboards,
long exports. A streaming HTTP response does that with no protocol switch: Server-Sent Events (SSE) for browser
events, newline-delimited JSON for machine clients. Two-way messaging is on xref:backend/axum/websockets.adoc[WebSockets].

== Server-Sent Events

SSE is a `text/event-stream` response that never ends. Each event is a few `field: value` lines followed by a blank
line, and browsers consume it with the built-in `EventSource` API, which *reconnects automatically* and sends the id of
the last event it saw. axum's `Sse<S>` wraps any `Stream` of `Result<Event, E>`:

[source,rust]
----
use std::convert::Infallible;
use std::sync::{Arc, Mutex};
use std::time::Duration;

use axum::{
    Json, Router,
    extract::{Query, State},
    http::HeaderMap,
    response::sse::{Event, KeepAlive, Sse},
    routing::{get, post},
};
use futures::{Stream, StreamExt, stream};
use serde::{Deserialize, Serialize};
use tokio::sync::broadcast;
use tokio_stream::wrappers::BroadcastStream;

#[derive(Clone, Serialize, Deserialize)]
struct LoanDue {
    member_id: u64,
    isbn: String,
    due_in_days: u8,
}

/// A notification with its sequence number (the SSE event id).
type Numbered = (u64, LoanDue);

#[derive(Clone)]
struct AppState {
    live: broadcast::Sender<Numbered>,
    history: Arc<Mutex<Vec<Numbered>>>, // a table or Redis stream in production
}

#[derive(Deserialize)]
struct Member {
    member_id: u64, // from the session in the real application
}

fn to_event((id, due): Numbered) -> Result<Event, Infallible> {
    let event = Event::default().event("loan-due").id(id.to_string());
    // json_data only fails if serialisation fails; fall back to plain data
    Ok(event.clone().json_data(&due).unwrap_or_else(|_| event.data("{}")))
}

async fn notifications(
    State(state): State<AppState>,
    Query(Member { member_id }): Query<Member>,
    headers: HeaderMap,
) -> Sse<impl Stream<Item = Result<Event, Infallible>>> {
    // 1. subscribe first, so nothing published during the replay is lost
    let live = BroadcastStream::new(state.live.subscribe())
        .filter_map(|msg| async move { msg.ok() }) // drop "lagged" notices
        .filter(move |(_, due)| std::future::ready(due.member_id == member_id))
        .map(to_event);

    // 2. replay what the client missed while disconnected (EventSource sends Last-Event-ID)
    let last_seen: u64 = headers.get("last-event-id").and_then(|v| v.to_str().ok()).and_then(|v| v.parse().ok()).unwrap_or(0);
    let missed: Vec<_> = state
        .history
        .lock()
        .expect("lock")
        .iter()
        .filter(|(id, due)| *id > last_seen && due.member_id == member_id)
        .cloned()
        .collect();
    let retry = stream::once(async { Ok(Event::default().retry(Duration::from_secs(5)).comment("connected")) });

    let events = retry.chain(stream::iter(missed).map(to_event)).chain(live);
    Sse::new(events).keep_alive(KeepAlive::new().interval(Duration::from_secs(15)).text("keep-alive"))
}

async fn publish(State(state): State<AppState>, Json(due): Json<LoanDue>) -> String {
    let mut history = state.history.lock().expect("lock");
    let id = history.len() as u64 + 1;
    history.push((id, due.clone()));
    let _ = state.live.send((id, due));
    format!("event {id}\n")
}

#[tokio::main]
async fn main() {
    let (live, _) = broadcast::channel(256);
    let state = AppState { live, history: Arc::default() };
    let app = Router::new()
        .route("/events/loans", get(notifications))
        .route("/internal/loan-due", post(publish))
        .with_state(state);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

Source: https://docs.rs/axum/0.8.9/axum/response/sse/index.html[axum: response::sse] and https://github.com/tokio-rs/axum/tree/axum-v0.8.9/examples/sse[axum example: sse]

[source,bash]
----
$ curl -s -N 'localhost:3000/events/loans?member_id=42' &
retry: 5000
: connected

$ curl -s -H 'content-type: application/json' -d '{"member_id":42,"isbn":"9780441013593","due_in_days":2}' localhost:3000/internal/loan-due
event 1
event: loan-due
id: 1
data: {"member_id":42,"isbn":"9780441013593","due_in_days":2}

$ curl -s -N -H 'last-event-id: 0' 'localhost:3000/events/loans?member_id=42'   # a reconnect replays event 1
----

In the browser:

[source,html]
----
<script>
  const source = new EventSource("/events/loans");          // cookies are sent: same-origin session
  source.addEventListener("loan-due", (e) => {
    const due = JSON.parse(e.data);
    showToast(`"${due.isbn}" is due in ${due.due_in_days} days`);
  });
</script>
----

* `Event` builders: `data` (text; multi-line text becomes several `data:` lines), `json_data` (serialises with serde),
  `event` (the type listened to with `addEventListener`), `id`, `retry` (the client's reconnect delay) and `comment`.
  Since 0.8.5, `Event::into_data_writer` writes arbitrary data incrementally.
* `KeepAlive` sends a comment line periodically so proxies and load balancers do not close the idle connection; keep
  the interval below their idle timeouts (often 60 s).
* `Sse` sets `content-type: text/event-stream` and `cache-control: no-cache`. Disable response *buffering* in proxies
  (`X-Accel-Buffering: no` for nginx) and exclude SSE from `CompressionLayer` (its default predicate already does).
* Each open stream holds a connection; HTTP/1.1 browsers allow about six per host, so use HTTP/2 or one shared stream
  per page.
* Subscribing *before* reading the history avoids losing events published in between; the price is possible
  duplicates, which the client can drop by id.

== Streaming any body

`Sse` is a special case of a streaming body. `Body::from_stream` turns any `Stream` of byte chunks into a response
(see xref:backend/axum/responses.adoc[Responses]); axum-extra's `JsonLines` does the same for newline-delimited JSON,
and is also an *extractor* for NDJSON uploads, yielding each line as it arrives:

[source,rust]
----
use std::convert::Infallible;

use axum::{Router, routing::get, routing::post};
use axum_extra::json_lines::{AsResponse, JsonLines};
use futures::{Stream, StreamExt, stream};
use serde::{Deserialize, Serialize};

#[derive(Serialize, Deserialize, Debug)]
struct Book {
    isbn: String,
    title: String,
}

// GET: one JSON object per line, produced lazily (e.g. from sqlx's fetch stream)
async fn export() -> JsonLines<impl Stream<Item = Result<Book, Infallible>>, AsResponse> {
    JsonLines::new(stream::iter(1..=3).map(|i| Ok(Book { isbn: format!("97800000000{i:02}"), title: format!("Book {i}") })))
}

// POST: consume an NDJSON upload incrementally, without buffering it all
async fn import(mut books: JsonLines<Book>) -> String {
    let mut count = 0;
    while let Some(book) = books.next().await {
        match book {
            Ok(book) => {
                tracing::info!(?book, "importing");
                count += 1;
            }
            Err(err) => return format!("stopped after {count} books: {err}\n"),
        }
    }
    format!("imported {count} books\n")
}

#[tokio::main]
async fn main() {
    let app = Router::new().route("/api/v1/books.ndjson", get(export)).route("/api/v1/imports", post(import));
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

Source: https://docs.rs/axum-extra/0.12.6/axum_extra/json_lines/struct.JsonLines.html[axum-extra: JsonLines]

$ curl -s localhost:3000/api/v1/books.ndjson
{"isbn":"9780000000001","title":"Book 1"}
{"isbn":"9780000000002","title":"Book 2"}
{"isbn":"9780000000003","title":"Book 3"}
$ curl -s localhost:3000/api/v1/books.ndjson | curl -s --data-binary @- localhost:3000/api/v1/imports

the same format on xref:backend/fastapi/streaming-json-lines-and-sse.adoc[Streaming, JSON Lines & SSE].

== Proxying a stream with reqwest

A gateway that forwards a large download from another service should not buffer it. ``reqwest``'s `bytes_stream()` is a
`Stream` of `Bytes`, which `Body::from_stream` forwards chunk by chunk, as the official `reqwest-response` example does:

[source,rust]
----
use axum::{
    Router,
    body::Body,
    extract::State,
    http::{StatusCode, header},
    response::{IntoResponse, Response},
    routing::get,
};

async fn proxy_export(State(client): State<reqwest::Client>) -> Response {
    let upstream = match client.get("http://127.0.0.1:3000/upstream/catalogue.csv").send().await {
        Ok(resp) if resp.status().is_success() => resp,
        Ok(resp) => return (StatusCode::BAD_GATEWAY, format!("upstream answered {}", resp.status())).into_response(),
        Err(_) => return StatusCode::BAD_GATEWAY.into_response(),
    };
    let content_type = upstream.headers().get(header::CONTENT_TYPE).cloned();
    let mut response = Body::from_stream(upstream.bytes_stream()).into_response();
    if let Some(ct) = content_type {
        response.headers_mut().insert(header::CONTENT_TYPE, ct);
    }
    response
}

#[tokio::main]
async fn main() {
    let app = Router::new()
        .route("/exports/catalogue.csv", get(proxy_export))
        .route("/upstream/catalogue.csv", get(|| async { ([(header::CONTENT_TYPE, "text/csv")], "isbn,title\n9780441013593,Dune\n") }))
        .with_state(reqwest::Client::new());
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

Source: https://github.com/tokio-rs/axum/tree/axum-v0.8.9/examples/reqwest-response[axum example: reqwest-response]

== SSE or WebSocket?

[cols="1,2,2",options="header"]
|===
| |Server-Sent Events |WebSockets
|Direction |server -> client |both ways
|Protocol |plain HTTP response; works through proxies, HTTP/2 multiplexing |upgraded connection (or RFC 8441 on HTTP/2)
|Reconnection and resume |built into `EventSource` (`Last-Event-ID`) |write it yourself
|Data |UTF-8 text (JSON in `data`) |text and binary frames
|Authentication |cookies like any request |cookies or a ticket; no custom headers from browsers
|Best for |notifications, feeds, progress, htmx `sse` swaps |chat, collaborative editing, games
|===

*Bookshelf* uses SSE for loan-due notifications (one direction, must survive reconnects) and a WebSocket for the live
review feed, mainly to demonstrate both. Yoon (*Beginning Axum*, chapter 6) builds the same kind of notification
feature with SSE.
