== askama: templates checked at compile time

askama compiles Jinja-like templates into Rust code when the crate builds. A typo in a variable name or a type error is
a *compile* error, rendering needs no parsing at runtime, and HTML escaping is on by default for `.html` templates.
Templates live in a `templates/` directory next to `Cargo.toml`:

[source,toml]
----
[dependencies]
askama = "0.16.1"
askama_web = { version = "0.16.0", features = ["axum-0.8"] }
----

[source,jinja]
----
{# templates/base.html #}
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{% block title %}Bookshelf{% endblock %}</title>
  <link rel="stylesheet" href="/static/app.css">
</head>
<body>
  <header>{% include "partials/nav.html" %}</header>
  <main>{% block content %}{% endblock %}</main>
</body>
</html>

{# templates/partials/nav.html #}
<nav><a href="/">Catalogue</a>{% if let Some(name) = user %} | Signed in as {{ name }}{% endif %}</nav>

{# templates/book.html #}
{% extends "base.html" %}

{% block title %}{{ book.title }} - Bookshelf{% endblock %}

{% block content %}
<h1>{{ book.title|title }}</h1>
<p>by {{ book.author }}, {{ book.year }}</p>
<ul>
  {% for review in reviews %}
  <li>{{ review.rating }}/5: {{ review.text|truncate(80) }}</li>
  {% else %}
  <li>No reviews yet.</li>
  {% endfor %}
</ul>
{% endblock %}
----

[source,rust]
----
use askama::Template;
use askama_web::WebTemplate;
use axum::{
    Router,
    extract::Path,
    http::StatusCode,
    response::{Html, IntoResponse},
    routing::get,
};

struct Book {
    title: String,
    author: String,
    year: u16,
}

struct Review {
    rating: u8,
    text: String,
}

/// `WebTemplate` (askama_web) implements axum's IntoResponse: render, set content-type, 500 on error.
#[derive(Template, WebTemplate)]
#[template(path = "book.html")]
struct BookPage {
    user: Option<String>,
    book: Book,
    reviews: Vec<Review>,
}

async fn show_book(Path(isbn): Path<String>) -> Result<BookPage, StatusCode> {
    if isbn != "9780441013593" {
        return Err(StatusCode::NOT_FOUND);
    }
    Ok(BookPage {
        user: Some("Ursula".into()),
        book: Book { title: "dune".into(), author: "Frank Herbert".into(), year: 1965 },
        reviews: vec![Review { rating: 5, text: "<script>alert('xss')</script> A classic.".into() }],
    })
}

/// Without askama_web: render explicitly and wrap in Html.
async fn show_book_manual() -> Result<impl IntoResponse, StatusCode> {
    let page = BookPage {
        user: None,
        book: Book { title: "dune messiah".into(), author: "Frank Herbert".into(), year: 1969 },
        reviews: vec![],
    };
    let html = page.render().map_err(|err| {
        tracing::error!(%err, "template rendering failed");
        StatusCode::INTERNAL_SERVER_ERROR
    })?;
    Ok(Html(html))
}

#[tokio::main]
async fn main() {
    let app = Router::new().route("/books/{isbn}", get(show_book)).route("/books-manual", get(show_book_manual));
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

[source,bash]
----
$ curl -s localhost:3000/books/9780441013593 | grep -E '<h1>|<li>|Signed'
  <header><nav><a href="/">Catalogue</a> | Signed in as Ursula</nav></header>
<h1>Dune</h1>
  <li>5/5: &#60;script&#62;alert(&#39;xss&#39;)&#60;/script&#62; A classic.</li>
----

* *Inheritance*: `+{% extends "base.html" %}+` with `+{% block %}+` overrides; *includes* with `+{% include %}+`;
  *macros* with `+{% macro %}+` for repeated fragments such as form fields.
* *Filters*: built-ins such as `title`, `truncate`, `upper`, `join`, `json`, `urlencode`, plus your own as Rust
  functions in a `filters` module. Template expressions are Rust: `+{% if let Some(name) = user %}+` and method calls
  work.
* *Escaping*: every `+{{ }}+` in an `.html` template is HTML-escaped, which is why the injected `<script>` above renders as
  text. `|safe` disables escaping for a value -- use it only for HTML you produced and sanitised yourself.
* *Errors*: a missing field or a type mismatch is reported by `cargo build` with the template line; `render()` itself
  can only fail at runtime for things like a failing `Display` impl, which `WebTemplate` turns into a `500`.

=== Where `askama_axum` went

askama 0.12 shipped integration crates such as `askama_axum`. askama 0.13 removed them; the replacement is either the
explicit `Html(template.render()?)` (no extra dependency) or `askama_web` with the `axum-0.8` feature, whose
`+#[derive(WebTemplate)]+` restores `impl IntoResponse`. Yoon (*Beginning Axum*) builds a React front end and does not
use askama; online tutorials that `use askama_axum::Template` need this change.

== minijinja: runtime templates

minijinja is a Jinja2 implementation from the author of Jinja itself. Templates are loaded and parsed *at runtime*, so
designers can edit them without recompiling, and a development server can reload them on every request. The price is
that errors surface at runtime and there is no type checking:

[source,rust]
----
use std::sync::Arc;

use axum::{
    Router,
    extract::State,
    http::StatusCode,
    response::Html,
    routing::get,
};
use minijinja::{Environment, context};

#[derive(Clone)]
struct AppState {
    templates: Arc<Environment<'static>>,
}

async fn catalogue(State(state): State<AppState>) -> Result<Html<String>, StatusCode> {
    let template = state.templates.get_template("catalogue.html").map_err(|_| StatusCode::INTERNAL_SERVER_ERROR)?;
    let html = template
        .render(context! { books => vec!["Dune", "The Left Hand of Darkness"], user => "Ursula" })
        .map_err(|err| {
            tracing::error!(%err, "render failed");
            StatusCode::INTERNAL_SERVER_ERROR
        })?;
    Ok(Html(html))
}

#[tokio::main]
async fn main() {
    let mut env = Environment::new();
    // In production use env.set_loader(minijinja::path_loader("templates")) (feature "loader"),
    // or embed templates with include_str! as here.
    env.add_template(
        "catalogue.html",
        "<h1>Catalogue</h1><p>Hello {{ user }}</p><ul>{% for b in books %}<li>{{ b }}</li>{% endfor %}</ul>",
    )
    .expect("valid template");

    let app = Router::new().route("/", get(catalogue)).with_state(AppState { templates: Arc::new(env) });
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

Source: https://docs.rs/minijinja/2.24.0/minijinja/[minijinja 2.24] and https://github.com/tokio-rs/axum/tree/axum-v0.8.9/examples/templates-minijinja[axum example: templates-minijinja]

Auto-escaping is decided by the template name's extension (`.html` escapes). For live reloading during development,
the `minijinja-autoreload` crate re-reads changed files; keep it behind a configuration flag.

== maud: HTML as a Rust macro

maud's `html!` macro is not a template language at all: markup is written in a compact Rust-like syntax inside your
code, checked by the compiler, and escaped by default. Its `Markup` type implements axum's `IntoResponse` with the
`axum` feature:

[source,rust]
----
use axum::{Router, routing::get};
use maud::{DOCTYPE, Markup, html};

fn layout(title: &str, body: Markup) -> Markup {
    html! {
        (DOCTYPE)
        html lang="en" {
            head { meta charset="utf-8"; title { (title) } }
            body { main { (body) } }
        }
    }
}

async fn catalogue() -> Markup {
    let books = [("Dune", 1965), ("Kindred", 1979)];
    layout(
        "Catalogue",
        html! {
            h1 { "Catalogue" }
            ul {
                @for (title, year) in books {
                    li.book { (title) " (" (year) ")" }
                }
            }
        },
    )
}

#[tokio::main]
async fn main() {
    let app = Router::new().route("/", get(catalogue));
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

Source: https://maud.lambda.xyz/[maud book] and https://docs.rs/maud/0.27.0/maud/[maud 0.27]

== Which one?

[cols="1,2,2,2",options="header"]
|===
| |askama 0.16 |minijinja 2 |maud 0.27
|Syntax |Jinja-like, in `.html` files |Jinja2, in files or strings |Rust macro in `.rs` files
|Checked at |compile time (fields, types) |runtime |compile time
|Change without rebuild |no |yes (reloadable) |no
|Escaping |automatic for `.html` |automatic by extension |automatic
|Performance |fastest (compiled Rust) |fast (bytecode) |fastest (compiled Rust)
|Best for |most server-rendered apps; designers comfortable with Jinja |user-editable templates, CMS-like features
|developers who prefer one language and composable functions
|===

*Bookshelf* uses askama: compile-time checks catch template bugs in CI, and the syntax is familiar to anyone who knows
Jinja, Django or Twig templates (compare this site's xref:web/django/index.adoc[Django] and
xref:web/php-laravel/index.adoc[Laravel] sections).
