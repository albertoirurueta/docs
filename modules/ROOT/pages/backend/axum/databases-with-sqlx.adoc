This page is written against sqlx 0.9.0 with axum 0.8.9 on Rust 1.99 (edition 2024) and PostgreSQL 16, checked on
2026-10-06. sqlx is an async SQL toolkit, not an ORM: you write SQL, and sqlx checks it against a real database at
compile time, binds parameters safely and maps rows to Rust types. SQL itself -- joins, indexes, transactions, query
plans -- is covered in this site's xref:database/sql/index.adoc[SQL Reference]; ORMs are compared on
xref:backend/axum/seaorm-and-diesel.adoc[SeaORM & Diesel], and migrations and transactions on the
xref:backend/axum/migrations-and-transactions.adoc[next page].

[source,toml]
----
[dependencies]
sqlx = { version = "0.9.0", features = ["runtime-tokio", "tls-rustls", "postgres", "macros", "migrate", "time", "uuid"] }
----

sqlx 0.9 requires Rust 1.94 or later. Since 0.9 the project lives in the `transact-rs` GitHub organisation (it was
`launchbadge/sqlx`), and the combined runtime-and-TLS features such as `runtime-tokio-rustls` were removed: select
`runtime-tokio` and `tls-rustls` (or `tls-native-tls`) separately.

== The *Bookshelf* schema

The examples on this and the next pages use this schema, created by a migration:

[source,sql]
----
CREATE TABLE authors (
    id   BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL
);

CREATE TABLE books (
    isbn      TEXT PRIMARY KEY CHECK (isbn ~ '^[0-9]{13}$'),
    title     TEXT NOT NULL,
    author_id BIGINT NOT NULL REFERENCES authors (id),
    year      SMALLINT NOT NULL,
    copies    INT NOT NULL DEFAULT 1 CHECK (copies >= 0),
    version   BIGINT NOT NULL DEFAULT 1
);

CREATE TABLE reviews (
    id         BIGSERIAL PRIMARY KEY,
    isbn       TEXT NOT NULL REFERENCES books (isbn) ON DELETE CASCADE,
    rating     SMALLINT NOT NULL CHECK (rating BETWEEN 1 AND 5),
    body       TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX reviews_isbn_idx ON reviews (isbn);
----

== A pool in state and checked queries

[source,rust]
----
use std::time::Duration;

use axum::{
    Json, Router,
    extract::{Path, State},
    http::StatusCode,
    routing::get,
};
use serde::Serialize;
use sqlx::postgres::{PgPool, PgPoolOptions};

#[derive(Serialize)]
struct BookDetails {
    isbn: String,
    title: String,
    author: String,
    year: i16,
    average_rating: Option<f64>,
}

async fn show_book(State(pool): State<PgPool>, Path(isbn): Path<String>) -> Result<Json<BookDetails>, StatusCode> {
    // checked at compile time against DATABASE_URL: columns, types and nullability
    let book = sqlx::query_as!(
        BookDetails,
        r#"SELECT b.isbn, b.title, a.name AS author, b.year,
                  (SELECT avg(r.rating)::float8 FROM reviews r WHERE r.isbn = b.isbn) AS average_rating
           FROM books b JOIN authors a ON a.id = b.author_id
           WHERE b.isbn = $1"#,
        isbn
    )
    .fetch_optional(&pool)
    .await
    .map_err(|err| {
        tracing::error!(%err, "query failed");
        StatusCode::INTERNAL_SERVER_ERROR
    })?;
    book.map(Json).ok_or(StatusCode::NOT_FOUND)
}

async fn count_books(State(pool): State<PgPool>) -> Result<String, StatusCode> {
    let n: i64 = sqlx::query_scalar!(r#"SELECT count(*) AS "n!" FROM books"#)
        .fetch_one(&pool)
        .await
        .map_err(|_| StatusCode::INTERNAL_SERVER_ERROR)?;
    Ok(format!("{n} books\n"))
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    tracing_subscriber::fmt().with_max_level(tracing::Level::INFO).init();
    let url = std::env::var("DATABASE_URL")?; // e.g. postgres://bookshelf:<password>@localhost/bookshelf
    let pool = PgPoolOptions::new()
        .max_connections(10)
        .min_connections(1)
        .acquire_timeout(Duration::from_secs(3)) // fail fast instead of queueing forever
        .idle_timeout(Duration::from_secs(600))
        .connect(&url)
        .await?;

    let app = Router::new()
        .route("/api/v1/books/{isbn}", get(show_book))
        .route("/api/v1/stats/books", get(count_books))
        .with_state(pool);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await?;
    axum::serve(listener, app).await?;
    Ok(())
}
----

Source: https://docs.rs/sqlx/0.9.0/sqlx/macro.query_as.html[sqlx: query_as!] and https://github.com/tokio-rs/axum/tree/axum-v0.8.9/examples/sqlx-postgres[axum example: sqlx-postgres]

[source,bash]
----
$ curl -s localhost:3000/api/v1/books/9780441013593
{"isbn":"9780441013593","title":"Dune","author":"Frank Herbert","year":1965,"average_rating":5.0}
$ curl -s localhost:3000/api/v1/stats/books
3 books
----

* `PgPool` is a cheap-to-clone handle (an `Arc` inside), so it goes into state directly or into an `AppState` with
  `FromRef` (see xref:backend/axum/state-and-dependency-injection.adoc[State & Dependency Injection]).
* `max_connections` caps concurrent queries per instance. The total across all replicas must stay below the database's
  `max_connections`; size it from measurements, starting around 2-4 times the CPU cores of the *database* divided by
  the number of instances. `acquire_timeout` turns pool exhaustion into a fast error (`sqlx::Error::PoolTimedOut`, a
  `503` in *Bookshelf*'s `AppError`) instead of an ever-growing queue.
* `connect` opens one connection eagerly so misconfiguration fails at start-up; `connect_lazy` defers it.

=== What the macros check

`query!`, `query_as!` and `query_scalar!` send the SQL to the database named by `DATABASE_URL` *at compile time*, ask
it to prepare the statement, and generate code with the exact column types. A typo is a compile error:

[source,bash]
----
error: error returned from database: column b.titel does not exist at line 3729
  --> src/routes/books.rs:24:16
   |
24 |     let book = sqlx::query_as!(
   |                ^^^^^^^^^^^^^^^^
----

* Nullability is inferred: `average_rating` is `Option<f64>` because `avg` can be `NULL`. Override with column aliases:
  `+AS "n!"+` forces non-null, `+AS "n?"+` forces nullable, `+AS "n: Isbn"+` sets a type.
* `query_as!` maps by column *name* into any struct with matching fields; it does not need `FromRow`.
* Parameters (`$1`) are always bound, never interpolated, so the macros are immune to SQL injection.

Source: https://docs.rs/sqlx/0.9.0/sqlx/macro.query.html[sqlx: query!]

== Offline mode: building without a database

CI and Docker builds usually have no database. `cargo sqlx prepare` (from `sqlx-cli`) runs the macros once against a
live database and stores their metadata in a `.sqlx` directory, which you commit. With `SQLX_OFFLINE=true` (or simply
no `DATABASE_URL`), the macros read `.sqlx` instead:

[source,bash]
----
$ cargo install sqlx-cli --no-default-features --features postgres,rustls
$ export DATABASE_URL=postgres://bookshelf:<password>@localhost/bookshelf
$ cargo sqlx prepare -- --all-targets   # writes .sqlx/query-<hash>.json for every macro invocation
$ git add .sqlx
$ cargo sqlx prepare --check -- --all-targets  # in CI: fail if .sqlx is stale
----

Source: https://docs.rs/sqlx/0.9.0/sqlx/macro.query.html#offline-mode[sqlx: Offline mode]

sqlx 0.9 also reads an optional per-crate `sqlx.toml` (feature `sqlx-toml`) to rename `DATABASE_URL`, set global type
overrides or relocate the migrations table -- useful in workspaces with several databases.

== Runtime queries, `FromRow` and `SqlSafeStr`

When the SQL is only known at runtime -- user-selected sort columns, optional filters -- use the functions
`sqlx::query`, `query_as` and `query_scalar` (no `!`), mapping rows with `+#[derive(sqlx::FromRow)]+`. Since sqlx 0.9
these functions take `impl SqlSafeStr`, which is implemented only for `+&'static str+` and for strings wrapped in
`AssertSqlSafe`. A `String` built with `format!` no longer compiles by accident; you must assert that you built it
safely:

[source,rust]
----
use axum::{
    Json, Router,
    extract::{Query, State},
    http::StatusCode,
    routing::get,
};
use serde::{Deserialize, Serialize};
use sqlx::{AssertSqlSafe, FromRow, PgPool, Postgres, QueryBuilder};

#[derive(Serialize, FromRow)]
struct BookRow {
    isbn: String,
    title: String,
    year: i16,
}

#[derive(Deserialize)]
struct Filters {
    sort: Option<String>,
    min_year: Option<i16>,
    q: Option<String>,
}

async fn list(State(pool): State<PgPool>, Query(f): Query<Filters>) -> Result<Json<Vec<BookRow>>, StatusCode> {
    // 1. dynamic ORDER BY: never interpolate user input; map it onto an allow-list
    let order = match f.sort.as_deref() {
        Some("year") => "year, isbn",
        Some("title") => "title, isbn",
        _ => "isbn",
    };

    // 2. optional filters: QueryBuilder binds every value
    let mut qb: QueryBuilder<Postgres> = QueryBuilder::new("SELECT isbn, title, year FROM books WHERE true");
    if let Some(min) = f.min_year {
        qb.push(" AND year >= ").push_bind(min);
    }
    if let Some(q) = f.q {
        qb.push(" AND title ILIKE ").push_bind(format!("%{q}%"));
    }
    qb.push(" ORDER BY ").push(order).push(" LIMIT 100");

    let books = qb.build_query_as::<BookRow>().fetch_all(&pool).await.map_err(|_| StatusCode::INTERNAL_SERVER_ERROR)?;
    Ok(Json(books))
}

async fn count_since(State(pool): State<PgPool>) -> Result<String, StatusCode> {
    // a runtime-built string must be asserted safe explicitly (sqlx 0.9)
    let table = "books"; // from code, not from the request
    let sql = format!("SELECT count(*) FROM {table} WHERE year >= $1");
    let n: i64 = sqlx::query_scalar(AssertSqlSafe(sql))
        .bind(1965_i16)
        .fetch_one(&pool)
        .await
        .map_err(|_| StatusCode::INTERNAL_SERVER_ERROR)?;
    Ok(format!("{n}\n"))
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let pool = PgPool::connect(&std::env::var("DATABASE_URL")?).await?;
    let app = Router::new()
        .route("/api/v1/books", get(list))
        .route("/api/v1/stats/since-1965", get(count_since))
        .with_state(pool);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await?;
    axum::serve(listener, app).await?;
    Ok(())
}
----

Source: https://docs.rs/sqlx/0.9.0/sqlx/trait.SqlSafeStr.html[sqlx: SqlSafeStr] and https://docs.rs/sqlx/0.9.0/sqlx/struct.QueryBuilder.html[QueryBuilder]

[source,bash]
----
$ curl -s 'localhost:3000/api/v1/books?min_year=1969&sort=title'
[{"isbn":"9780593099322","title":"Dune Messiah","year":1969},{"isbn":"9780441478125","title":"The Left Hand of Darkness","year":1969}]
----

Wrapping attacker-controlled text in `AssertSqlSafe` defeats the purpose; the wrapper is a reviewable marker, like
`unsafe`. Typical mappings: `SMALLINT` -> `i16`, `INT` -> `i32`, `BIGINT`/`BIGSERIAL` -> `i64`, `TEXT` -> `String`,
`TIMESTAMPTZ` -> `time::OffsetDateTime` (feature `time`) or `chrono::DateTime<Utc>`, `UUID` -> `uuid::Uuid`, `JSONB`
-> `sqlx::types::Json<T>`. Newtypes such as `Isbn` can derive `sqlx::Type` with `+#[sqlx(transparent)]+`.

== Streaming rows

`fetch_all` loads every row into a `Vec`. For exports, `fetch` returns a `Stream` that yields rows as Postgres sends
them. That stream borrows its executor, so it cannot be returned from the handler directly; a spawned task that owns
the pool drives it and feeds `Body::from_stream` through a bounded channel, keeping memory flat:

[source,rust]
----
use axum::{Router, body::Body, extract::State, http::header, response::IntoResponse, routing::get};
use futures::StreamExt;
use sqlx::PgPool;
use tokio::sync::mpsc;
use tokio_stream::wrappers::ReceiverStream;

async fn export(State(pool): State<PgPool>) -> impl IntoResponse {
    // The row stream borrows the pool, so it is driven by a task that owns the pool and
    // forwards lines through a bounded channel (which also applies back-pressure).
    let (tx, rx) = mpsc::channel::<Result<String, std::io::Error>>(32);
    tokio::spawn(async move {
        let mut rows = sqlx::query_as::<_, (String, String)>("SELECT isbn, title FROM books ORDER BY isbn").fetch(&pool);
        while let Some(row) = rows.next().await {
            let line = row.map(|(isbn, title)| format!("{isbn},{title}\n")).map_err(std::io::Error::other);
            let failed = line.is_err();
            if tx.send(line).await.is_err() || failed {
                break; // client went away, or the query failed (the response is truncated)
            }
        }
    });
    ([(header::CONTENT_TYPE, "text/csv")], Body::from_stream(ReceiverStream::new(rx)))
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let pool = PgPool::connect(&std::env::var("DATABASE_URL")?).await?;
    let app = Router::new().route("/exports/books.csv", get(export)).with_state(pool);
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await?;
    axum::serve(listener, app).await?;
    Ok(())
}
----

Source: https://docs.rs/sqlx/0.9.0/sqlx/query/struct.Map.html#method.fetch[sqlx: fetch]

The stream holds a pool connection until it finishes, so long exports reduce the connections available to other
requests; give exports their own small pool or a read replica.

== The repository pattern

*Bookshelf*'s services depend on traits, and the `db` module implements them with sqlx (see
xref:backend/axum/project-structure.adoc[Project Structure]). Repositories own the SQL, return domain types and map
database errors in one place:

[source,rust]
----
use sqlx::PgPool;

#[derive(Debug)]
pub struct Book {
    pub isbn: String,
    pub title: String,
    pub copies: i32,
}

#[derive(Clone)]
pub struct PgBookRepo {
    pool: PgPool,
}

impl PgBookRepo {
    pub fn new(pool: PgPool) -> Self {
        Self { pool }
    }

    #[tracing::instrument(skip(self), fields(db.system = "postgresql", db.operation = "SELECT"))]
    pub async fn find(&self, isbn: &str) -> sqlx::Result<Option<Book>> {
        sqlx::query_as!(Book, "SELECT isbn, title, copies FROM books WHERE isbn = $1", isbn)
            .fetch_optional(&self.pool)
            .await
    }

    /// Several books in ONE query, instead of one query per ISBN (N+1).
    pub async fn find_many(&self, isbns: &[String]) -> sqlx::Result<Vec<Book>> {
        sqlx::query_as!(Book, "SELECT isbn, title, copies FROM books WHERE isbn = ANY($1) ORDER BY isbn", isbns)
            .fetch_all(&self.pool)
            .await
    }
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    tracing_subscriber::fmt().with_max_level(tracing::Level::DEBUG).init();
    let repo = PgBookRepo::new(PgPool::connect(&std::env::var("DATABASE_URL")?).await?);
    println!("{:?}", repo.find("9780441013593").await?);
    let wanted = vec!["9780441013593".to_owned(), "9780593099322".to_owned()];
    println!("{} books in one round trip", repo.find_many(&wanted).await?.len());
    Ok(())
}
----

Source: https://docs.rs/sqlx/0.9.0/sqlx/macro.query_as.html[sqlx: query_as!]

=== Avoiding N+1 queries

The *N+1 problem* is one query for a list plus one query per item -- 1 + 50 round trips for a page of 50 books with
their authors. With hand-written SQL the fixes are explicit: a `JOIN` (as in `show_book` above), a second query with
`= ANY($1)` for all ids at once (as in `find_many`), or a `json_agg` subquery that returns the children as JSON. Watch
the query count per request in traces; a page that issues dozens of queries is the most common cause of slow
endpoints. See xref:database/diagnosing-slow-queries.adoc[Diagnosing and Fixing Slow Queries] for reading query plans.

== Instrumentation and pool metrics

Gangappa & Rangaraj (*Mastering Distributed Observability in Rust*, chapter 5) recommend a span per database call with
the OpenTelemetry semantic-convention attributes -- `db.system`, `db.operation`, `db.collection.name` (the table) --
and *sanitised* statements: record the SQL text with placeholders, never the bound values, which may contain personal
data. sqlx itself logs each statement at `DEBUG` (target `sqlx::query`, with elapsed time) and slow statements at
`WARN` (configurable with `ConnectOptions::log_slow_statements`).

Pool saturation is the early warning of database trouble (chapter 11): export `pool.size()` and `pool.num_idle()` as
gauges and the time spent in `acquire` as a histogram, and alert when idle connections stay at zero (see
xref:backend/axum/metrics-and-slos.adoc[Metrics & SLOs]).

== Other databases

* *tokio-postgres* with a `bb8` or `deadpool` pool is a lower-level Postgres driver without compile-time checks; the
  official `tokio-postgres` example shows it in state.
* *MySQL/MariaDB* and *SQLite* are supported by sqlx with the same API (features `mysql`, `sqlite`).
* *MongoDB* has an official async Rust driver (`mongodb` crate, also an official axum example); see
  xref:database/mongodb/drivers-and-tooling.adoc[MongoDB Drivers & Tooling].

== Where the books are outdated

Gangappa & Rangaraj use sqlx 0.8, where `+sqlx::query(&format!(...))+` compiled; in 0.9 it requires
`AssertSqlSafe`, and the MSRV is 1.94. The 0.8 `runtime-tokio-rustls` feature is gone (use `runtime-tokio` plus
`tls-rustls`). Yoon (*Beginning Axum*, chapter 3) uses SeaORM rather than sqlx; see
xref:backend/axum/seaorm-and-diesel.adoc[SeaORM & Diesel].
