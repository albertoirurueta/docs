== The upgrade handshake and the connection lifecycle

A WebSocket starts as an HTTP `GET` with `Upgrade: websocket`. The `WebSocketUpgrade` extractor validates the handshake
headers; the handler returns `ws.on_upgrade(callback)`, which sends `101 Switching Protocols` and later runs the
callback with the upgraded `WebSocket` on its own task. Everything after that is frames, not HTTP:

[mermaid]
....
sequenceDiagram
    participant B as Browser
    participant H as ws handler
    participant W as writer task
    participant R as reader task
    participant X as broadcast channel
    B->>H: GET /ws (Upgrade: websocket, Origin, Cookie)
    H->>H: check Origin + session, pick subprotocol
    H-->>B: 101 Switching Protocols
    H->>W: spawn: subscribe(), forward + ping every 30 s
    H->>R: spawn: read frames, enforce idle timeout
    X-->>W: "new review" (from POST /api/v1/reviews)
    W-->>B: Text frame
    B->>R: Pong / Text
    Note over R: no frame for 60 s -> stop
    R-->>H: finished: abort writer, connection closed
....

== The *Bookshelf* review feed

[source,rust]
----
use std::time::Duration;

use axum::{
    Router,
    extract::{
        State,
        ws::{Message, Utf8Bytes, WebSocket, WebSocketUpgrade},
    },
    http::{HeaderMap, StatusCode, header},
    response::{IntoResponse, Response},
    routing::{any, post},
};
use futures::{SinkExt, StreamExt};
use tokio::sync::broadcast;

const PING_EVERY: Duration = Duration::from_secs(30);
const IDLE_TIMEOUT: Duration = Duration::from_secs(60);
const ALLOWED_ORIGINS: [&str; 2] = ["https://bookshelf.example", "http://localhost:3000"];

#[derive(Clone)]
struct AppState {
    // one Sender, cloned into state: broadcast::Sender is already cheap to clone and thread-safe
    reviews: broadcast::Sender<String>,
}

async fn ws_handler(State(state): State<AppState>, headers: HeaderMap, ws: WebSocketUpgrade) -> Response {
    // Browsers send Origin on the upgrade; reject cross-site pages (CORS does not apply to WebSockets).
    let origin = headers.get(header::ORIGIN).and_then(|o| o.to_str().ok());
    if origin.is_some_and(|o| !ALLOWED_ORIGINS.contains(&o)) {
        return StatusCode::FORBIDDEN.into_response();
    }
    // (authenticate here with the session cookie or a one-time ticket; see below)
    ws.protocols(["bookshelf.reviews.v1"]) // subprotocol negotiation
        .max_message_size(64 * 1024)
        .on_upgrade(move |socket| handle_socket(socket, state))
}

async fn handle_socket(socket: WebSocket, state: AppState) {
    let (mut sink, mut stream) = socket.split();
    let mut feed = state.reviews.subscribe();

    // writer: broadcast messages and periodic pings -> client
    let mut writer = tokio::spawn(async move {
        let mut ping = tokio::time::interval(PING_EVERY);
        loop {
            tokio::select! {
                msg = feed.recv() => match msg {
                    Ok(review) => {
                        if sink.send(Message::Text(Utf8Bytes::from(review))).await.is_err() {
                            break; // client gone
                        }
                    }
                    // a slow client missed messages: tell it, keep going (or close it)
                    Err(broadcast::error::RecvError::Lagged(n)) => {
                        let notice = format!("{{\"type\":\"lagged\",\"missed\":{n}}}");
                        if sink.send(Message::Text(notice.into())).await.is_err() {
                            break;
                        }
                    }
                    Err(broadcast::error::RecvError::Closed) => break,
                },
                _ = ping.tick() => {
                    if sink.send(Message::Ping(axum::body::Bytes::from_static(b"keepalive"))).await.is_err() {
                        break;
                    }
                }
            }
        }
    });

    // reader: client -> server, with an idle timeout (pongs count as activity)
    let mut reader = tokio::spawn(async move {
        loop {
            match tokio::time::timeout(IDLE_TIMEOUT, stream.next()).await {
                Ok(Some(Ok(Message::Text(text)))) => tracing::debug!(%text, "client message"),
                Ok(Some(Ok(Message::Close(_)))) | Ok(None) | Ok(Some(Err(_))) => break,
                Ok(Some(Ok(_))) => {} // Ping (answered automatically), Pong, Binary
                Err(_) => break,      // idle for too long
            }
        }
    });

    // when either side finishes, stop the other
    tokio::select! {
        _ = &mut writer => reader.abort(),
        _ = &mut reader => writer.abort(),
    }
}

async fn post_review(State(state): State<AppState>, body: String) -> StatusCode {
    let _ = state.reviews.send(body); // Err only if nobody is subscribed
    StatusCode::ACCEPTED
}

#[tokio::main]
async fn main() {
    let (reviews, _) = broadcast::channel(256);
    let app = Router::new()
        .route("/ws", any(ws_handler)) // any(): HTTP/1.1 GET upgrades and HTTP/2 CONNECT (RFC 8441)
        .route("/api/v1/reviews", post(post_review))
        .with_state(AppState { reviews });
    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
----

== Messages

`Message` has five variants: `Text(Utf8Bytes)`, `Binary(Bytes)`, `Ping(Bytes)`, `Pong(Bytes)` and `Close(Option<CloseFrame>)`.
In axum 0.8, `Text` holds a `Utf8Bytes` and `Binary` a `Bytes` instead of `String` and `Vec<u8>`: messages can be cloned
and sent to many clients without copying. Convert with `.into()` from `String`/`+&'static str+`, and read with
`text.as_str()`. Ping frames from the client are answered with pongs automatically; you only send pings yourself, as
the writer does, to detect dead connections behind proxies that drop idle TCP connections silently. Axum 0.8 also
removed `WebSocket::close`: send a `Message::Close` frame to close cleanly.

== Splitting into reader and writer

A `WebSocket` is both a `Stream` of incoming messages and a `Sink` of outgoing ones. `split()` (from
`futures::StreamExt`) separates the two halves, so one task can read while another writes -- the standard structure
for anything more than echo. `tokio::select!` on the two ``JoinHandle``s ends the connection as soon as either side
stops, and `abort()` cancels the other; otherwise a closed client would leave a writer task subscribed forever.

== Fan-out: broadcast, slow consumers and several instances

`tokio::sync::broadcast` delivers every message to every subscriber, with a bounded buffer per channel. A subscriber
that falls more than the capacity behind gets `RecvError::Lagged(n)` and continues from the oldest retained message;
the writer above notifies the client, which can reload the list. Dropping slow clients instead (`break`) is equally
valid. This bounded behaviour is the backpressure strategy: one slow phone on a bad network can never make the server
buffer unboundedly or slow down everyone else.

The `Sender` is placed in state directly; it is `Clone`, `Send` and `Sync`, so it needs no `+Arc<Mutex<...>>+`. With
several replicas behind a load balancer, each process has its own channel; bridge them with Redis pub/sub as shown on
xref:backend/axum/redis-and-caching.adoc[Redis & Caching].

== Subprotocols (0.8.9)

Clients can propose application protocols in `Sec-WebSocket-Protocol`. `+ws.protocols([...])+` selects the first
server-supported protocol the client offered and echoes it in the response; if none matches, the upgrade still succeeds
without one. Since 0.8.9, `ws.requested_protocols()` and `+ws.set_selected_protocol(...)+` allow custom selection logic
(for example by version number).

== WebSockets over HTTP/2

axum 0.8 supports RFC 8441 WebSockets over HTTP/2, where the upgrade is an extended `CONNECT` request rather than a
`GET`. Route the endpoint with `any(handler)` instead of `get(handler)` and enable the `http2` feature; HTTP/1.1
clients keep working. The official `websockets-http2` example shows a browser connecting through TLS with ALPN `h2`.

== Authenticating browser clients

The browser `WebSocket` API cannot set an `Authorization` header. Use one of:

* the *session cookie*, which the browser sends with the upgrade request: extract the session (or `CurrentUser`) in
  `ws_handler` exactly as in an HTTP handler, and *check `Origin`* as above -- otherwise any website could open a
  socket with the user's cookies ("cross-site WebSocket hijacking");
* a short-lived *ticket*: an authenticated `POST /api/v1/ws-ticket` returns a random single-use token, the client
  connects to `+/ws?ticket=...+`, and the handler validates and deletes it before upgrading.

Authentication happens *before* `on_upgrade`, while you can still answer with an HTTP status. Long-lived tokens in the
URL leak into logs; tickets expire within seconds.

== Testing

The official `testing-websockets` example tests a WebSocket handler in two ways: against a real server bound to port 0
with `tokio-tungstenite` as the client, and in process by writing the socket logic against generic `Sink`/`Stream`
traits so it can be fed by channels. The xref:backend/axum/testing.adoc[Testing] page shows both.

== Where the books are outdated

Yoon (*Beginning Axum*, chapter 5) wraps the `broadcast::Sender` in `+Arc<Mutex<...>>+`, which is unnecessary (the
sender is already shareable) and adds lock contention; it also authenticates the socket with an `Authorization` header,
which browsers cannot send. Code written for axum 0.7 must change `Message::Text(String)` to `Utf8Bytes` and
`Message::Binary(Vec<u8>)` to `Bytes`, and replace `WebSocket::close()` with sending a close frame.
