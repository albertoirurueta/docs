This section is written against Node.js 26 (26.10.0, the Current line, which becomes LTS on 2026-10-28), with the
differences of Node.js 24 LTS (Krypton, 24.21.0) and Node.js 22 (Jod, 22.23.3, Maintenance) called out where they

All versions were checked on 2026-10-03. Node.js releases a new line every year; from Node.js 27 every line becomes LTS,
so the baseline is re-verified rather than assumed, and each page says which line introduced, stabilised or removed a
feature. Features still marked Experimental in the official stability index are labelled as such and kept short.

== What Node.js is

Node.js is an open-source, cross-platform JavaScript runtime. It combines the V8 JavaScript engine with libuv (the
asynchronous I/O library), a set of C++ bindings and a JavaScript core library, and it runs your code on a single main
thread driven by an event loop, handing blocking work to the operating system, a small thread pool, or worker threads.
It is a runtime, not a framework: it gives you files, sockets, HTTP, streams, cryptography, a test runner and an embedded
SQLite database, and leaves structure to you or to frameworks such as Express, Fastify or
xref:backend/nestjs/index.adoc[NestJS].

This section is for developers who:

* know some JavaScript (see the xref:programming-languages/javascript/index.adoc[JavaScript Development] reference) and
  want to learn how Node.js actually works, not only how to call frameworks
* come from Java, Python, .NET or Go and want the mental model of the event loop, modules and npm
* maintain older Node.js code or follow older tutorials and books, and need to know what changed (CommonJS to ES
  modules, `dotenv` to `--env-file`, Jest to `node:test`, `ts-node` to type stripping, Corepack removal)

== The Bookshelf scenario

Every example builds *Bookshelf*, the same domain used by the FastAPI, NestJS and Next.js sections, so the stacks can be
compared. It is built mostly from built-ins: a JSON service on `node:http` storing data in `node:sqlite`, a `bookshelf`
command-line tool, a streaming CSV import, cover-image hashing in a `worker_threads` pool, ISBN lookups with `fetch`, a
live "new review" feed over Server-Sent Events, `node:test` suites, clustering, a single-executable build and a Docker
image. Pages that need third-party libraries extend it with Express or Fastify, database clients, BullMQ, Nodemailer,
an LLM SDK or `ws`. Pages build on each other, but each can be read on its own.

== Reading path

The pages are ordered so that each one builds on the previous ones:

. Foundations: what Node.js is, installing it, the release lines, running scripts, flags and globals
. Modules and packages: CommonJS, ES modules, interop, `package.json`, npm, workspaces and publishing
. Asynchrony: the event loop, promises, timers, events, not blocking the loop, async context and cancellation
. Core APIs: process, errors, buffers, `util`, `os`/`path`/`url`, terminal I/O
. Files and streams: the file system, streams, Web Streams, zlib, SQLite and databases
. Networking: HTTP servers and clients, TLS and HTTP/2, WebSockets and SSE, TCP/UDP/DNS, hardening
. Concurrency: worker threads, child processes, cluster
. Testing: the built-in test runner, mocks, snapshots and coverage
. Diagnostics: debugging, profiling, memory, reports and observability
. Security: best practices, the permission model, cryptography
. TypeScript and tooling: type stripping, linting and formatting
. Building applications: REST APIs, frameworks, authentication, CLIs, queues, email, LLM APIs
. Production: deployment, containers, single executable applications, upgrading
