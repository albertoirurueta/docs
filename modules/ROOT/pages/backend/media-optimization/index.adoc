= Media Optimization
:description: Server-side media optimization for the backend: image formats and encoding, responsive variants and thumbnails, BlurHash, video transcoding, covers from frames, adaptive streaming, language-specific libraries for Java, Python, Node.js, .NET and Rust, upload pipelines with queues and jobs, and security and operations.
:keywords: media optimization, image optimization, video transcoding, AVIF, WebP, BlurHash, thumbnails, HLS, DASH, CMAF, FFmpeg, libvips, upload pipeline, pre-signed URL, queue, worker, Spring Boot, Quarkus, FastAPI, NestJS, ASP.NET Core, axum, bibliography, cheat sheet

include::partial$media-optimization-backend-disclaimer.adoc[]

Users upload photos and videos in whatever format their device produced, and a platform has to serve each client a file
it can decode, at a size it needs, with as few bytes as possible. This sub-section describes how the backend does that:
turn every image into a set of formats and sizes (with a BlurHash placeholder), turn every video into a ladder of
renditions that stream adaptively, produce covers and thumbnails, and do all of it in background workers rather than in the
HTTP request. It is current as of 2026-10-07. Each page states the versions it was checked against and flags unmaintained
or restrictively licensed libraries.

== Reading paths

* *Images only.* Start with xref:backend/media-optimization/image-formats-and-encoding.adoc[formats], then
  xref:backend/media-optimization/responsive-images-and-thumbnails.adoc[variants], then
  xref:backend/media-optimization/blurhash-algorithm.adoc[BlurHash], then the page for your language.
* *Video.* Read xref:backend/media-optimization/video-encoding-fundamentals.adoc[encoding],
  xref:backend/media-optimization/video-streaming.adoc[streaming] and
  xref:backend/media-optimization/video-covers-and-thumbnails.adoc[covers], then decide between self-hosted FFmpeg workers and a
  managed transcoder, see below.
* *A new platform.* Read xref:backend/media-optimization/upload-pipelines-queues-and-jobs.adoc[upload pipelines] first, since
  it fixes the architecture the other pages fit into, and
  xref:backend/media-optimization/security-and-operations.adoc[security and operations] before the first public upload.

== Managed alternatives in the cloud

Self-hosted FFmpeg and image workers are one choice. Each cloud offers a managed one, described in its own section:

* xref:cloud/aws/media-optimization/index.adoc[AWS]: Elemental MediaConvert, S3 and Lambda image processing, CloudFront delivery and a Video on Demand pipeline.
* xref:cloud/google-cloud/media-optimization.adoc[Google Cloud]: the Transcoder API, Cloud Run jobs, Media CDN and storage-triggered resizing.
* xref:cloud/azure/media-optimization.adoc[Azure]: Media Services was retired, so self-hosted FFmpeg in Container Apps jobs, Event Grid with Functions, and Front Door.

The frontend counterparts are xref:web/media-optimization/index.adoc[Media Optimization for the web] and
xref:apps/media-optimization/index.adoc[Media Optimization in apps].
