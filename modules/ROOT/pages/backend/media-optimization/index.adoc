= Media Optimization
:description: Server-side media optimization for the backend: image formats and encoding, responsive variants and thumbnails, BlurHash, video transcoding, covers from frames, adaptive streaming, language-specific libraries for Java, Python, Node.js, .NET and Rust, upload pipelines with queues and jobs, and security and operations.
:keywords: media optimization, image optimization, video transcoding, AVIF, WebP, BlurHash, thumbnails, HLS, DASH, CMAF, FFmpeg, libvips, upload pipeline, pre-signed URL, queue, worker, Spring Boot, Quarkus, FastAPI, NestJS, ASP.NET Core, axum, bibliography, cheat sheet

This is the *server-side* home of the topic; the client side is split in two: xref:web/media-optimization/index.adoc[Media Optimization for the web] for browsers and xref:apps/media-optimization/index.adoc[Media Optimization in apps] for native and cross-platform apps.

Users upload photos and videos in whatever format their device produced, and a platform has to serve each client a file
it can decode, at a size it needs, with as few bytes as possible. This sub-section describes how the backend does that:
turn every image into a set of formats and sizes (with a BlurHash placeholder), turn every video into a ladder of
renditions that stream adaptively, produce covers and thumbnails, and do all of it in background workers rather than in the
HTTP request. It is current as of 2026-10-07. Each page states the versions it was checked against and flags unmaintained
or restrictively licensed libraries.

*Deliberately out of scope.* This section is about turning uploaded images and videos into the files a client can use, and running that work safely. The following topics appear in image-processing, graphics, Spring Boot and
messaging books, but live elsewhere on this site or are intentionally not covered:

* *Image-processing algorithms and computer vision* (filters, feature detection, face detection, OpenCV) -- not covered. The pipeline here only decodes, resizes, converts and encodes. For learned image models see
  xref:ml/convolutional-neural-networks.adoc[Convolutional neural networks] and xref:ai/hugging-face/vision-models.adoc[Hugging Face vision models], and for generative image models xref:ml/generative-models.adoc[Generative models].
* *Real-time graphics, GPUs and texture pipelines* (OpenGL, Vulkan, Metal, mipmaps, texture compression) -- see xref:graphics-games/index.adoc[Graphics and games]. Colour management on a GPU is in
  xref:graphics-games/color-spaces-hdr-and-tone-mapping.adoc[Colour spaces, HDR and tone mapping]; here only the conversion of an uploaded image to sRGB is covered.
* *Reading documents and extracting content* (PDF, Office files, OCR, metadata of arbitrary files) -- see xref:backend/apache-tika/index.adoc[Apache Tika], xref:backend/apache-tika/ocr-with-tesseract.adoc[OCR with Tesseract] and
  xref:backend/pdf-generation/index.adoc[PDF generation]. The security lessons for untrusted files are shared with xref:backend/office-files/security-and-untrusted-files.adoc[Office files: security and untrusted files].
* *Multipart handling and file storage in each framework* (reactive file controllers, upload endpoints, object stores) -- see xref:backend/springboot/file-storage-and-object-stores.adoc[File Storage and Object Stores],
  xref:backend/nestjs/file-upload-and-streaming.adoc[NestJS file upload and streaming] and xref:backend/fastapi/forms-and-file-uploads.adoc[FastAPI forms and file uploads]. This section starts after the file is in storage.
* *Message-broker internals* (AMQP, Kafka, exchanges, partitions, exactly-once) -- see xref:backend/messaging/index.adoc[Messaging], and for dead-lettering in RabbitMQ
  xref:backend/messaging/rabbitmq-reliability-dead-lettering-and-ttl.adoc[RabbitMQ reliability, dead-lettering and TTL]. The upload pipeline page only describes the contract a media worker needs from a queue.
* *Containers, hardening and orchestration* in depth -- see xref:backend/docker/security.adoc[Docker security], xref:backend/kubernetes/pod-security.adoc[Kubernetes pod security] and
  xref:backend/kubernetes/resource-management.adoc[Kubernetes resource management]; this section shows only the flags a media worker needs.
* *Browser-side rendering and players* -- see xref:web/media-optimization/index.adoc[Media Optimization for the web] and xref:apps/media-optimization/index.adoc[Media Optimization in apps].
* *Live and real-time video* (RTMP ingest, WebRTC, low-latency HLS) -- see xref:web/webrtc-websockets/index.adoc[WebRTC and WebSockets]; this section covers on-demand files only.
* *Video editing, compositing, subtitles and audio mastering, camera RAW and TIFF workflows, animated images* -- intentionally not covered. Subtitles appear only as a reason to use a dedicated packager, and animation only as a column of the format table.
* *DRM and licence servers* -- the streaming page names the options, but key delivery is not covered.
* *Content moderation and abuse detection with machine learning* -- not covered. Upload validation here is structural (type, size, pixels, duration); for the cost and abuse risks of calling models see
  xref:ai/security/unbounded-consumption-and-denial-of-wallet.adoc[Unbounded consumption and denial of wallet].
* *Managed image and video services* -- see the AWS, Google Cloud and Azure pages in the section below.

== Reading path

* *Images only.* Start with xref:backend/media-optimization/image-formats-and-encoding.adoc[formats], then
  xref:backend/media-optimization/responsive-images-and-thumbnails.adoc[variants], then
  xref:backend/media-optimization/blurhash-algorithm.adoc[BlurHash], then the page for your language.
* *Video.* Read xref:backend/media-optimization/video-encoding-fundamentals.adoc[encoding],
  xref:backend/media-optimization/video-streaming.adoc[streaming] and
  xref:backend/media-optimization/video-covers-and-thumbnails.adoc[covers], then decide between self-hosted FFmpeg workers and a
  managed transcoder, see below.
* *A new platform.* Read xref:backend/media-optimization/upload-pipelines-queues-and-jobs.adoc[upload pipelines] first, since
  it fixes the architecture the other pages fit into, and
  xref:backend/media-optimization/security-and-operations.adoc[security and operations] before the first public upload.
