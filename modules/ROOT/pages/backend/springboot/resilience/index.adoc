This section is a practical guide to making a Spring Boot service tolerate the failures of the services it calls. It
documents https://resilience4j.readme.io/docs/getting-started[Resilience4j] **2.4.0** (released 2026-03-14, Java 17
or later) on **Spring Boot 4.1.x** and **Spring Framework 7.0.x** with Java 21, together with the pieces of the
Spring ecosystem that sit around it: Spring Cloud CircuitBreaker, the Spring Cloud Gateway and OpenFeign
integrations, and the native `@Retryable` and `@ConcurrencyLimit` of Spring Framework 7. Where the Spring Boot 3.5
starter differs, the pages show a short "Spring Boot 3" delta. The versions were verified on 4 October 2026.

== What resilience means for a Spring Boot service

A service that calls other services inherits their failures. A dependency that answers slowly holds your threads and
connections; one that fails intermittently turns every request into a coin toss; one that is down makes every caller
wait for a timeout; and a caller that retries aggressively can keep a struggling dependency from ever recovering.
_Resilience_ is the set of techniques that keep one failing dependency from becoming your failure:

* **timeouts** so that no call waits forever (TimeLimiter, plus the HTTP client's own timeouts)
* **retries** with exponential backoff and jitter for transient errors, on idempotent operations only (Retry)
* **circuit breakers** that stop calling a dependency that is clearly failing, and probe it again later (CircuitBreaker)
* **bulkheads** that cap how much of your capacity one dependency can consume (Bulkhead, ThreadPoolBulkhead)
* **rate limiters** that keep you under a dependency's quota, or keep clients under yours (RateLimiter)
* **fallbacks** that degrade gracefully instead of failing: a cached value, a default, an empty list

Resilience4j is the lightweight, functional fault-tolerance library that Netflix recommends in place of
https://github.com/Netflix/Hystrix[Hystrix], which has been in maintenance mode since 2018. Each pattern is a small
module with no dependencies beyond its own modules, composed by decorating a function; the Spring Boot starter adds
registries bound to `application.yml`, annotations, Actuator endpoints, health indicators and Micrometer metrics.

This section is for developers who:

* build or maintain Spring Boot services that call other HTTP, gRPC or database-backed services, and want to know
  which pattern answers which failure
* are on Spring Boot 4 (or still on 3.5) and need the starter, the AspectJ dependency and the configuration that
  actually work, because the official Resilience4j documentation does not cover Spring Boot 4
* come from Hystrix, Spring Retry or Spring Cloud Netflix, and need the migration path
* want to test the failure paths, observe them in production, and tune the numbers from real traffic

== The Bookshelf scenario

Every example builds on _Bookshelf_, the book-catalogue domain already used by the
xref:backend/fastapi/index.adoc[Python FastAPI], xref:backend/nestjs/index.adoc[NestJS],
xref:web/django/index.adoc[Django], xref:web/nextjs/index.adoc[Next.js] and
xref:backend/kubernetes/index.adoc[Kubernetes] sections, so that the stacks can be compared page by page. Here it
is a Spring Boot 4.1 `bookshelf-service` (Java 21, virtual threads enabled) that calls four downstream dependencies.
Each dependency motivates one set of patterns:

[cols="2,3,3",options="header"]
|===
|Dependency |Behaviour |Patterns

|`pricing-service`
|Slow and flaky.
|CircuitBreaker, TimeLimiter and a short Retry, with a fallback to the last known price.

|A third-party ISBN-metadata API
|Has a request quota and answers 429 or 503.
|A client-side RateLimiter, a Bulkhead, and Retry with exponential backoff and jitter that honours `Retry-After`.

|`recommendations-service`
|Expensive and optional.
|A ThreadPoolBulkhead with a CircuitBreaker and a TimeLimiter, degrading to an empty list.

|`reviews-service`
|Called reactively through `WebClient`.
|The Reactor operators of `resilience4j-reactor`.
|===

Spring Cloud Gateway sits in front of `bookshelf-service` with a CircuitBreaker filter, the service's own `search`
endpoint is protected by a RateLimiter that answers 429 with `Retry-After`, and the tests inject faults with WireMock
and Toxiproxy (through Testcontainers).

.The Bookshelf dependency map, annotated with the pattern that guards each call

The gateway forwards to bookshelf-service, whose search endpoint has a RateLimiter. The service calls pricing-service (CircuitBreaker, TimeLimiter, Retry and a fallback), the third-party ISBN-metadata API (RateLimiter, Retry and Bulkhead), recommendations-service (ThreadPoolBulkhead, CircuitBreaker and TimeLimiter) and reviews-service (Reactor operators for CircuitBreaker and TimeLimiter).",width=900,role=text-center]

=== The final layout

The layout below is where the pages end up. Individual examples sit in whichever package keeps them short (most
in the base package `com.example.bookshelf`), so treat the sub-packages as the tidy version of the same classes.

[source,text]
----
bookshelf-service/
├── pom.xml                                   # resilience4j-bom + resilience4j-spring-boot4 pinned,
│                                             # spring-boot-starter-aspectj, -actuator, -web, -webflux
└── src/
    ├── main/
    │   ├── java/com/example/bookshelf/
    │   │   ├── BookshelfApplication.java
    │   │   ├── pricing/                      # PricingClient (@CircuitBreaker, @TimeLimiter, fallback)
    │   │   ├── isbn/                         # IsbnMetadataClient (@RateLimiter, @Retry, @Bulkhead)
    │   │   ├── recommendations/              # RecommendationsClient (@Bulkhead(type = THREADPOOL))
    │   │   ├── reviews/                      # ReviewsClient (WebClient + Reactor operators)
    │   │   ├── search/                       # SearchController (@RateLimiter, 429 + Retry-After)
    │   │   ├── config/                       # BookshelfResilienceConfig (customizers, Clock)
    │   │   ├── MdcContextPropagator.java     # named in application.yml
    │   │   └── TransientHttpFailure.java     # named in application.yml
    │   └── resources/
    │       ├── application.yml               # shown below
    │       ├── application-test.yml          # tiny windows and waits
    │       └── application-local.yml         # breakers that stay closed while debugging
    └── test/java/com/example/bookshelf/      # registry unit tests, @SpringBootTest aspect checks,
                                              # WireMock faults, Toxiproxy (Testcontainers)
----

The configuration file is the complete resilience configuration of the service. It is the one explained, key by key,
on xref:backend/springboot/resilience/spring-boot-configuration.adoc#_the_bookshelf_configuration[Spring Boot
Configuration], where its effective values were read back from the registries on Spring Boot 4.1.1 and 3.5.16.

.application.yml of bookshelf-service
[source,yaml]
----
spring:
  application:
    name: bookshelf-service

resilience4j:
  circuitbreaker:
    tags:
      application: ${spring.application.name}
    configs:
      default:                                  # what an unlisted breaker gets
        slidingWindowType: COUNT_BASED
        slidingWindowSize: 20
        minimumNumberOfCalls: 10
        failureRateThreshold: 50
        waitDurationInOpenState: 30s
        permittedNumberOfCallsInHalfOpenState: 3
        automaticTransitionFromOpenToHalfOpenEnabled: true
        registerHealthIndicator: true
        eventConsumerBufferSize: 50
        recordExceptions:
          - org.springframework.web.client.ResourceAccessException
          - org.springframework.web.client.HttpServerErrorException
          - java.util.concurrent.TimeoutException
        ignoreExceptions:
          - org.springframework.web.client.HttpClientErrorException
    instances:
      pricing:                                  # critical, high traffic: time-based window
        baseConfig: default
        slidingWindowType: TIME_BASED
        slidingWindowSize: 10
        minimumNumberOfCalls: 20
        slowCallDurationThreshold: 800ms
        slowCallRateThreshold: 70
        waitDurationInOpenState: 20s
        enableExponentialBackoff: true
        exponentialBackoffMultiplier: 2
        exponentialMaxWaitDurationInOpenState: 2m
        permittedNumberOfCallsInHalfOpenState: 5
        maxWaitDurationInHalfOpenState: 10s
        allowHealthIndicatorToFail: false
      isbn:                                     # third-party API: jitter the probes
        baseConfig: default
        waitDurationInOpenState: 10s
        enableRandomizedWait: true
        randomizedWaitFactor: 0.25
        registerHealthIndicator: false
      recommendations:                          # optional feature: open early, tolerate slowness
        baseConfig: default
        failureRateThreshold: 30
        slowCallDurationThreshold: 1s
      reviews:
        baseConfig: default

  retry:
    configs:
      default:
        maxAttempts: 3
        waitDuration: 200ms
        enableExponentialBackoff: true
        exponentialBackoffMultiplier: 2
        enableRandomizedWait: true
        randomizedWaitFactor: 0.5
        ignoreExceptions:
          - io.github.resilience4j.circuitbreaker.CallNotPermittedException
    instances:
      pricing:
        baseConfig: default
        maxAttempts: 2
        retryExceptions:
          - org.springframework.web.client.ResourceAccessException
      isbn:
        baseConfig: default
        maxAttempts: 4
        exponentialMaxWaitDuration: 5s
        retryExceptionPredicate: com.example.bookshelf.TransientHttpFailure
        eventConsumerBufferSize: 200

  ratelimiter:
    configs:
      default:
        limitForPeriod: 10
        limitRefreshPeriod: 1s
        timeoutDuration: 0
    instances:
      isbn:                                     # client side: stay under the third-party quota
        baseConfig: default
        limitForPeriod: 5
        timeoutDuration: 500ms
        subscribeForEvents: true
        registerHealthIndicator: true
      search:                                   # server side: protect our own endpoint
        baseConfig: default
        limitForPeriod: 3
        limitRefreshPeriod: 2s
        subscribeForEvents: true

  bulkhead:
    configs:
      default:
        maxConcurrentCalls: 10
        maxWaitDuration: 0
    instances:
      isbn:
        baseConfig: default
        maxConcurrentCalls: 2
        maxWaitDuration: 100ms
        writableStackTraceEnabled: false

  thread-pool-bulkhead:
    configs:
      default:
        coreThreadPoolSize: 2
        maxThreadPoolSize: 4
        queueCapacity: 2
        keepAliveDuration: 20ms
        contextPropagators:
          - com.example.bookshelf.MdcContextPropagator
    instances:
      recommendations:
        baseConfig: default

  timelimiter:
    configs:
      default:
        timeoutDuration: 2s
        cancelRunningFuture: true
    instances:
      pricing:
        baseConfig: default
        timeoutDuration: 800ms
      recommendations:
        baseConfig: default
        timeoutDuration: 1s
      reviews:
        baseConfig: default
        timeoutDuration: 300ms
        cancelRunningFuture: false

management:
  endpoints:
    web:
      exposure:
        include: health,circuitbreakers,circuitbreakerevents,retries,ratelimiters,bulkheads,timelimiters,metrics,prometheus
  endpoint:
    circuitbreakers:
      access: read-only                         # no CLOSE / FORCE_OPEN / DISABLE over HTTP
    health:
      show-details: when-authorized
  health:
    circuitbreakers:
      enabled: true
    ratelimiters:
      enabled: true
----
