:description: A practical, example-driven guide to load and performance testing backend services with Apache JMeter 5.6.3: test plans, concurrent users, ramp-up and arrival rates, HTTP, REST, GraphQL, JDBC, JMS and gRPC testing, plugins, CLI, distributed and CI runs, the HTML dashboard and result analysis.

A backend that passes its unit and integration tests can still fall over when two hundred people use it at once. Load
testing answers a different question from functional testing: not "is the answer correct?" but "how fast, how often
and for how many users at the same time?". Apache JMeter is the long-standing open source tool for it. It is a pure
Java application that generates protocol-level traffic from many virtual users, records every response and reports on
latency, throughput and errors. This section is a practical, example-driven guide to using it, from a first test to a
continuous-integration job and a written analysis. Versions and dates are re-verified when each page is written and
stated as of the date checked.

== Running scenario: Bookshelf

Every page uses the same system under test so that readers can compare techniques: a local *Bookshelf API* started
with Docker Compose. It exposes:

* `+GET /api/books?query=+` and `+GET /api/books/{id}+`;
* `POST /api/auth/login`, which returns a JWT;
* `+POST /api/loans+` and `+GET /api/loans/{id}+`;
* a `/graphql` endpoint;
* a gRPC `bookshelf.v1.LoanService` with the unary methods `CreateLoan` and `GetLoan`, described by `bookshelf.proto`.

The section builds one test plan, `bookshelf-load.jmx`, step by step: a user journey (log in, search, view a book,
create a loan, view the loan) fed from `users.csv` and `search-terms.csv`, with the token correlated through a JSON
Extractor, plus assertions, think time and transactions. It then reuses the plan for the load profiles smoke, load,
stress, spike, soak and arrival-rate, and adds a companion `bookshelf-grpc.jmx`. The scenario is original and is not
copied from any tutorial or book. No example uses a real secret: credentials come from CSV files or `-J` properties
with placeholder values, and load is only ever aimed at `localhost` or at systems you own.

== How to read this section

The pages follow the life of a load test. A reader who is new to JMeter should read them roughly in order; a reader who
needs one answer can jump straight to the page that gives it.

[mermaid]
----
flowchart TD
    A([What do you need?]) --> B{First time with JMeter?}
    B -- Yes --> C[Foundations: architecture, installation, test plan model]
    B -- No --> D{What is the goal?}
    C --> D
    D -- Model users and load --> E[Thread groups, open model, timers, controllers]
    D -- Test an HTTP API --> F[HTTP requests, data, correlation, assertions, scripting]
    D -- Another protocol or a plugin --> G[JDBC, JMS, plugins, load shaping, gRPC]
    D -- Run and analyse --> H[CLI mode, results, dashboard, monitoring, analysis]
    D -- Scale and automate --> I[Distributed testing, tuning, CI/CD, DSLs]
    D -- Something is broken --> J[Troubleshooting and security]
----

The sections of the guide are:

* *Foundations*: what JMeter is and is not, performance testing concepts, installation, the GUI, the test plan model and
  its execution order, and properties, variables and functions.
* *Load modelling*: thread groups, ramp-up and duration, the open workload model and throughput control, timers and
  think time, logic controllers and transactions.
* *HTTP testing*: requests, sessions and authentication, REST, JSON, GraphQL and SOAP, recording and cURL import, test
  data, correlation, assertions and Groovy scripting.
* *Other protocols, plugins and gRPC*: JDBC, JMS, mail and TCP, other samplers, the Plugins Manager, custom thread groups
  and gRPC load testing.
* *Running tests and results*: CLI mode, listeners and result files, the HTML dashboard, real-time monitoring and
  finding bottlenecks.
* *Scaling and automation*: distributed testing, tuning, Maven, Docker and GitHub Actions, programmatic test plans,
  extending JMeter, troubleshooting, responsible load testing and what changed between versions.
* A downloadable one-page *cheat sheet*.

== What JMeter does not provide

The pages state these limits instead of inventing capabilities: core JMeter has no gRPC, WebSocket or HTTP/2 support
(community plugins add them); JMeter is not a browser, so it does not run JavaScript or render pages (for front-end
performance see the Playwright, Cypress and Selenium section, starting with xref:web/e2e-testing/choosing-a-tool.adoc[Choosing a Tool]); there is no official Docker image
and no official Gradle plugin; the Open Model Thread Group is experimental.

== Books and the official documentation

Three books supply much of the methodology: Bayo Erinle, _JMeter Cookbook_ (2014, JMeter 2.11); Bayo Erinle,
_Performance Testing with JMeter_ (2nd edition, 2015, JMeter 2.12); and Sai Matam and Jagdeep Jain, _Pro Apache JMeter_
(2017, JMeter 3.0). They are good on concepts such as test types, workload modelling and bottleneck hunting, but they
target old tooling: the WorkBench, the SOAP sampler and the Monitor Results listener
no longer exist, and the BSF and BeanShell elements are deprecated or discouraged. The pages use the books for concepts and cite them by chapter, and take every
element, menu path, property and command from the current official documentation.
