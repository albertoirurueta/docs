== What Flask is

Flask is a Python web framework for the WSGI protocol. It is deliberately small: it gives you routing, request and
response objects, a template engine, signed cookie sessions, a command-line interface and a test client, and it
leaves the choice of database layer, form library, authentication and every other building block to you or to
extensions. "Micro" means that the core does not decide those things for you, not that the framework is only for
small applications.

Flask is not written from scratch. It is a thin layer over the Pallets libraries, and most of what you use daily is
implemented one level down:

* https://werkzeug.palletsprojects.com/en/stable/[Werkzeug] provides the WSGI toolkit: the `Request` and `Response`
  classes, the URL routing system, the development server and the interactive debugger.
* https://jinja.palletsprojects.com/en/stable/[Jinja] renders the templates.
* https://click.palletsprojects.com/en/stable/[Click] implements the `flask` command and your own CLI commands.
* https://itsdangerous.palletsprojects.com/en/stable/[ItsDangerous] signs the session cookie and other tokens.
* https://markupsafe.palletsprojects.com/en/stable/[MarkupSafe] provides the escaping behind Jinja's autoescape.
* https://blinker.readthedocs.io/en/stable/[Blinker] provides the signals.

This section is for developers who:

* know Python and want to build server-rendered sites, JSON APIs or both with Flask, from a first route to a
  deployed, tested and monitored application
* are coming from Django, FastAPI, Spring Boot, Express or ASP.NET Core and want a precise map of what Flask does
  itself, what an extension does and what is left to you
* maintain a Flask application written for Flask 1.x or 2.x, or learned from older tutorials and books, and need
  the current idioms (`DeclarativeBase` models, `+db.session.execute(db.select(...))+`, `flask --app`, `from_prefixed_env`,
  `SECRET_KEY_FALLBACKS`) together with a table of what to change

== The Bookshelf scenario

Every example builds one small original application, the _Bookshelf_, so the pages fit together instead of being
isolated snippets:

* `books`, `authors`, `reviews` and `users` tables, modelled with SQLAlchemy 2.0 and versioned with Flask-Migrate
* a `catalog` blueprint (Jinja pages, WTForms forms, message flashing and uploads of cover images), an `auth`
  blueprint (Flask-Login), an `admin` blueprint (Flask-Admin) and an `api` blueprint (flask-smorest and JWT)
* English and Spanish pages with Flask-Babel, caching with Flask-Caching, a Celery job that sends a review digest
  and a live "new reviews" stream over Server-Sent Events
* tests with pytest, and deployment with Gunicorn behind nginx and in Docker

How each book is used:

* The two editions of the _Flask Framework Cookbook_ are recipe books that cover the whole ecosystem: configuration,
  Jinja, SQLAlchemy, WTForms, authentication, REST, administration, internationalization, testing, deployment,
  containers and miscellaneous tips. The 3rd edition targets Flask 2.2, Werkzeug 2.2, SQLAlchemy 2.0 and
  Flask-SQLAlchemy 3.0 on Python 3.11, and the 2nd edition targets Flask 1.0, Werkzeug 0.15, SQLAlchemy 1.3 and
  Flask-SQLAlchemy 2.4 on Python 3.7, so the 2nd edition matters mostly for the Flask 1.x idioms you will meet in old
  code.
* _Microservice APIs_ is a framework-agnostic API design book. Only its chapter on Flask uses flask-smorest and
  marshmallow, and its other chapters on API design, documentation, security and testing are applied to Flask on the
  API and testing pages of this section.
* _Full-Stack Flask and React_ is half a React book. Only its Flask chapters are relevant here, on Flask 2.3 with
  Flask-SQLAlchemy and Flask-JWT-Extended, and the React side is covered by the site's React section.

== Specifications used

The pages rely on these specifications and standards, each linked in the bibliography.

* PEP 3333 (WSGI) and the ASGI specification, for the two server interfaces
* RFC 9110 (HTTP semantics) and RFC 9111 (HTTP caching), and RFC 6265 (cookies), for status codes, headers,
  conditional requests and the session cookie
* RFC 9457 (Problem Details for HTTP APIs), for error payloads
* RFC 7519 (JSON Web Token), RFC 8725 and RFC 6750, for token authentication
* OpenAPI 3.1 and JSON Schema 2020-12, for API descriptions
* the WHATWG HTML Standard (Server-Sent Events) and the WHATWG Fetch Standard (CORS), for streaming and cross-origin
  requests
* the OWASP Cheat Sheet Series, for the security guidance the official security page leaves open

== Reading path

The pages are ordered so that each one builds on the previous ones. Read them in this order the first time, then use
them as a reference:

. *Foundations*: what Flask is made of, a first running app, the application factory, configuration and the two
  contexts.
. *Routing, views and requests*: URLs, request data, responses, errors, hooks and blueprints.
. *Templates, sessions, forms and files*: Jinja, static files, signed sessions, Flask-WTF and uploads.
. *Data*: sqlite3 and SQLAlchemy, migrations and the other data stores.
. *Authentication, authorization and security*: Flask-Login, social login, roles and the security checklist.
. *Building APIs*: REST design, OpenAPI with flask-smorest, JWT and single-page applications.
. *Extensions and ecosystem*: the extension model, the CLI, signals, the admin, translations, caching and Celery.
. *Async, streaming and real-time*: `async` views, gevent, Quart, streaming and Server-Sent Events.
. *Testing and debugging*: pytest, contract tests, logging and profiling.
. *Production*: Gunicorn, nginx, containers and cloud platforms.
. *Beyond the basics*: calling LLM APIs, and what changed between releases.

If you already know an older Flask, start with xref:backend/flask/whats-changed-and-migration.adoc[What's Changed & Migration]
and read the topic pages afterwards. The cheat sheet at xref:backend/flask/cheat-sheet.adoc[Flask Cheat Sheet]
condenses the whole section onto one page for quick lookup.
