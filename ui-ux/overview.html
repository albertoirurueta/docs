UI / UX Overview

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page holds the conceptual material of the UI / UX section: how UI and UX design differ, the UX process from discovery to iteration, and the landscape of design tools.

How does it look and feel to use?

The UX process at a glance

Real projects loop and skip steps, but most follow the same shape: learn about the problem, decide what to solve, explore solutions, make them tangible, test them with people, give developers what they need and keep improving after release.

flowchart LR D1[Discover] --> D2[Define] --> D3[Ideate] --> D4[Prototype] D4 --> D5[Test] --> D6[Hand off] --> D7[Iterate] D7 -. new findings .-> D1
Figure 2. Design is handed to developers, shipped and then iterated

  1. Discover: interviews, observation and analytics reveal who the users are and what they struggle with.

  2. Define: the findings become a clear problem statement, personas and success measures.

  3. Ideate: sketches, flows and information architecture explore several ways to solve it.

  4. Prototype: clickable mock-ups make the best ideas concrete enough to react to.

  5. Test: usability sessions show where the prototype fails real people.

  6. Hand off: specifications, assets and a design system let developers build what was designed.

  7. Iterate: metrics and feedback after release start the next round.

Accessibility belongs to every step, not only the last one. See Web Accessibility for the web, and for platform conventions the Apple Human Interface Guidelines, Liquid Glass and the Design System and Material 3 and Theming in Compose pages.

Design tools landscape

Interface design tools differ in platform, collaboration model and how close they sit to code. This site documents two of them (Figma and Canva) in depth; the others are only named so that readers know the landscape.
