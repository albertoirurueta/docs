App Intents

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was checked against the official Canva Developers documentation on 2026-11-07. It covers one concept of the platform that the other developer pages build on: the intent. An intent is a contract between an app and Canva. It lists the actions your app must implement, and in return Canva decides when and where to surface the app, in the editor side panel or in other contexts such as Canva AI. Every new app must implement at least one intent. Apps built before intents existed use the Design Editor intent implicitly and keep working without changes.

Building an app needs a Canva account on any plan; what the app’s users can do depends on their own plan. Distribution is either public, through the Apps Marketplace, or private, to a team (see Publishing and Monetizing Apps). The Design Editor, Data Connector and Content Publisher intents are generally available. The URL Expander intent is a preview: its API may change and it is delivered in the beta channel of the intents package, so a public app cannot be released with it until it becomes stable. More intents are announced as planned but are not published yet.

The running example is Bookshelf Covers, a small app that lets a designer insert book covers from the Bookshelf catalogue into a design. It starts as a Design Editor app and then grows a Data Connector for the reading list. The wider tour of the platform is on Developer Platform Overview, the full project workflow is on Building Apps Inside Canva, and the UI components used in the examples are described on React and the App UI Kit.

The four intents

Figure 1. The four intents an app can implement and the manifest key of each

An app can implement one intent or several, and each operates independently. The table summarises them.

Intent What it does Entry point and package Status

Design Editor

Renders your app inside the Canva editor and adds specialised editing tools next to the design. It is the default intent and includes the Design Editing APIs that existed before intents. Needs no permission by itself; the individual APIs you call may.

prepareDesignEditor from @canva/intents/design

Generally available

Data Connector

Your app provides a UI where users select data and a function that fetches it as a table. Canva surfaces it in data-related contexts and can refresh the data later through a stored reference.

prepareDataConnector from @canva/intents/data

Generally available

Content Publisher

Publishes designs to an external platform such as a social network or an email service: you describe output types, render settings and preview UIs, and publish when the user confirms. Needs the design read permission.

prepareContentPublisher from @canva/intents/content

Generally available

URL Expander

Imports content into Canva AI when a user pastes a URL from your platform. Needs the private asset write permission and up to three URL patterns registered in the Developer Portal.

prepareUrlExpander from @canva/intents/asset

Preview, beta package

Source: Canva Developers: App intents

The app is not limited to the editor side panel any more. Because Canva decides where an intent-based app appears, the same Data Connector can be offered where users pick data, and a URL Expander can be offered in the Canva AI conversation. The URL Expander is currently available in Canva AI in the editor, which is its only surface.

Rules for registering intents

Registration is the part that most often goes wrong, so Canva states it as rules:

  • Register each intent synchronously, as soon as the app loads, and only once.

  • Do not render UI at registration time. Rendering happens later, inside the intent’s own actions such as render.

  • Do not create global state at module level.

  • At module level only import the intent implementations and call the prepare functions. API calls, state setup and any asynchronous work belong inside the actions, with lazy initialisation inside components.

Figure 2. Registration at load, work inside the intent actions

The recommended layout puts each intent in its own folder, src/intents/<intent>/index.tsx, where the default export of the folder implements the intent’s contract. The root src/index.tsx only calls each prepare function. The CLI and the migration tools expect this structure, even for an app with a single intent.

// src/index.tsx
import { prepareDesignEditor } from "@canva/intents/design";
import designEditor from "./intents/design_editor";

prepareDesignEditor(designEditor);

Source: Canva Developers: App intents

The manifest and permissions

An intent is switched on in the Developer Portal, under Inside Canva > Intents of the app, or in the canva-app.json manifest with intent.<name>.enrolled set to true. The keys are design_editor, data_connector, content_publisher and url_expander. Permissions are declared in the same manifest under runtime.permissions, and the Developer Portal keeps the listing and OAuth configuration, which are not part of the manifest.

{
  "$schema": "https://www.canva.dev/schemas/app/v1/manifest-schema.json",
  "manifest_schema_version": 1,
  "runtime": {
    "permissions": [
      { "name": "canva:design:content:write", "type": "mandatory" }
    ]
  },
  "intent": {
    "design_editor": { "enrolled": true },
    "data_connector": { "enrolled": true }
  }
}

Source: Canva Developers: canva-app.json

Local changes are submitted to the Developer Portal with canva apps config push, which accepts --force and a conflict --strategy of local, remote or manual. Check the configuration before pushing, because the push replaces the portal configuration with the local one. Permissions are listed on Configuring intents and permissions.

Design Editor intent

The Design Editor intent is the intent for tools that live beside the canvas. Enabling it takes three steps: enrol the intent, register it with prepareDesignEditor and render the UI inside the render callback, mounting a React tree wrapped in AppUiProvider from @canva/app-ui-kit.

// src/intents/design_editor/index.tsx
import type { DesignEditorIntent } from "@canva/intents/design";

async function render() {
  // Mount the React app here, wrapped in AppUiProvider
}

const designEditor: DesignEditorIntent = { render };
export default designEditor;

Source: Canva Developers: Design Editor intent migration guide

If the app needs a third-party OAuth connection, start the flow from inside the intent’s render lifecycle, on a user action, so that it runs in the app iframe. Never start it when the module loads. The design APIs you call from here are covered on Building Apps Inside Canva.

Data Connector intent

A Data Connector has two halves. The selection UI lets the user choose and filter data; the fetch function returns it as a data table. In between, the app stores a data source reference, a small string with an optional title that you encode as an id, JSON or a query string, so that Canva can refresh the data later without opening your UI again.

sequenceDiagram participant U as Designer participant C as Canva participant A as Your app participant B as Your backend U->>C: Choose the app as a data source C->>A: renderSelectionUi(request) U->>A: Pick the reading list A->>C: updateDataRef(source, title) C->>A: getDataTable(dataSourceRef, limit) A->>B: Fetch rows for the reference B-->>A: Rows A-->>C: status completed, dataTable Note over C,A: Later refreshes call getDataTable again with the stored reference

For the Bookshelf reading list, the connector returns a title column and a rating column and respects the row limit that Canva passes in.

import { prepareDataConnector } from "@canva/intents/data";
import type { GetDataTableRequest, DataTableRow } from "@canva/intents/data";

prepareDataConnector({
  getDataTable: async ({ dataSourceRef, limit }: GetDataTableRequest) => {
    const books = await fetchReadingList(dataSourceRef.source);
    const rows: DataTableRow[] = books.slice(0, limit.row).map((b) => ({
      cells: [
        { type: "string", value: b.title },
        { type: "number", value: b.rating },
      ],
    }));

    return {
      status: "completed",
      dataTable: {
        columnConfigs: [
          { name: "Title", type: "string" },
          { name: "Rating", type: "number" },
        ],
        rows,
      },
    };
  },
  renderSelectionUi: () => {
    // Mount the selection UI and call updateDataRef({ source: "reading-list" })
  },
});

Source: Canva Developers: Data Connector implementation guide

Cell types are string, number, date (a Unix timestamp in seconds), boolean, variant and media. The request carries limit.row and limit.column; truncate to those limits or return an app_error asking the user to filter. The error statuses are outdated_source_ref (Canva asks the user to select again), remote_request_failed (retry later) and app_error with a message. The connector needs the design read and design write permissions.

Content Publisher intent

A Content Publisher sends the finished design to a platform. Canva calls four functions that you provide: getPublishConfiguration returns the output types, each with media slots, accepted formats and file counts; renderSettingsUi lets users enter platform options; renderPreviewUi shows how the content will look; and publishContent runs when the user clicks publish. Settings are serialised into publishRef, an opaque string of up to 32 KB that your app writes and reads, and a validity state tells Canva when the publish button can be enabled.

import { prepareContentPublisher } from "@canva/intents/content";

async function getPublishConfiguration() {
  return {
    status: "completed",
    outputTypes: [
      {
        id: "post",
        displayName: "Feed Post",
        contentNoun: "post",
        mediaSlots: [
          {
            id: "media",
            displayName: "Media",
            fileCount: { exact: 1 },
            accepts: { image: { format: "png" } },
          },
        ],
      },
    ],
  };
}

async function publishContent({ outputMedia, publishRef }) {
  // Call the platform's API here
  return {
    status: "completed",
    externalId: "1234567890",
    externalUrl: "https://example.com/posts/1234567890",
  };
}

prepareContentPublisher({
  getPublishConfiguration,
  renderSettingsUi: () => {},
  renderPreviewUi: () => {},
  publishContent,
});

Source: Canva Developers: Content Publisher implementation guide

URL Expander intent

A URL Expander lets a user paste a link from your platform into Canva AI and get the content imported. You register up to three wildcard URL patterns in the Developer Portal, request the canva:asset:private:write permission, install the beta intents package with npm install @canva/intents@beta and implement two functions. expandUrl recognises the URL and returns metadata for a preview, or not_found. getContent exports the asset and returns a publicly accessible URL. Both can ask the user to connect an account through the OAuth helpers.

import { prepareUrlExpander } from "@canva/intents/asset";

prepareUrlExpander({
  urlPatterns: ["https://docs.google.com/document/d/*"],
  expandUrl: async (request) => {
    // Parse the id from request.url and fetch metadata
    return {
      status: "completed",
      result: {
        ref: {
          type: "asset",
          id: "doc-id",
          name: "Title",
          iconUrl: "https://example.com/icon.png",
          description: "Preview text",
        },
      },
    };
  },
  getContent: async (request) => ({
    type: "generic",
    name: request.ref.name,
    url: "https://example.com/export.pdf",
    mimeType: "application/pdf",
  }),
});

Source: Canva Developers: URL Expander implementation guide

Migrating an older app to the Design Editor intent

An app built before intents renders its React tree directly from the entry file. It still works, but Canva recommends moving it to the explicit Design Editor intent. Upgrade to Apps SDK v2 first, then migrate, either automatically or by hand.

Figure 3. Before and after migrating a direct-render app

Automatic migration

canva apps migrate design-editor-intent --dry-run
canva apps migrate design-editor-intent
canva apps build

The --dry-run flag lists the proposed changes without touching files, and --debug and --force are also available. The other migration names are apps-sdk-v1-v2, app-ui-kit-v5 and webpack-to-app-scripts.

Manual migration

  1. Add the @canva/intents package to the app.

  2. Create src/intents/design_editor/index.tsx, wrap the existing render logic in an async function and default-export it inside an object typed as DesignEditorIntent (shown above).

  3. In src/index.tsx, import prepareDesignEditor and the intent object and pass it in, instead of calling the render code directly.

  4. Enrol the intent: in the Developer Portal use Inside Canva > Intents > Design Editor > Set up, or set intent.design_editor.enrolled to true in canva-app.json and push the configuration.

  5. Update tests that called render directly so that they mock prepareDesignEditor or test the function passed to it.

  6. Run canva apps build to catch TypeScript errors, then canva apps preview and confirm the app loads in the editor.

Source: Canva Developers: Design Editor intent migration guide

Previewing an intent

canva apps preview opens the app in Canva. When the app enrols several intents, choose which one with --intent. For an intent that runs in more than one place, choose the location with --target, which accepts editor or canva_ai. The --source flag loads the app from its development URL or from an uploaded bundle, and --no-open prints the preview URL instead of opening a browser.

canva apps preview --intent url_expander --target canva_ai

Source: Canva Developers: Canva CLI

Pitfalls

  • Calling fetch, creating stores or rendering at module level breaks the registration rules; move the work into render or the other actions.

  • Registering the same intent more than once is against the guidance; register once, from the entry file.

  • A Data Connector that ignores limit.row and limit.column returns tables Canva cannot accept.

  • Enrol every intent you register, in the manifest or the Developer Portal, so that the app declares what it implements.

  • The URL Expander is a preview; do not plan a public release around it until it becomes stable.

Recent changes

  • The documentation now describes apps inside Canva as intent-based; the older name Apps SDK now refers to one surface of the Canva Developers SDK, next to the REST APIs and the MCP server.

  • The design-editor-intent migration and the canva apps preview flags --intent and --target are documented for the Canva CLI, whose latest version on 2026-11-07 is 2.17.0.

  • The Canva Button was retired outside China, with API keys deactivated after 2025-12-30; the REST APIs are the replacement for server-side design creation (see REST APIs).
