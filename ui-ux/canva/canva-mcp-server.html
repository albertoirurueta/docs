The Canva MCP Server

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was checked against the official Canva developer documentation on 2026-11-07. It covers the Canva MCP server, the remote Model Context Protocol (MCP) server that Canva calls "Canva for AI assistants", one of the three surfaces of the Canva Developers SDK (the other two are apps inside Canva and the REST APIs, see the Canva Developers SDK overview). The server exposes Canva’s design capabilities as MCP tools, so an AI assistant that you or your users already work in can search, generate, edit, export and comment on designs through natural language. The self-serve developer route became generally available with the announcement of 2026-10-27.

Plans: according to the developer documentation, core features (design generation, editing, search, export, comments and asset upload) work on all Canva plans, while resizing designs, autofill, brand kits and brand templates need Canva Pro or above. The help articles for end users word availability per connector and account, so treat the developer page as the reference for what the server itself allows. Prices are not repeated here; they are published at https://www.canva.com/pricing/. Generation draws on the Canva AI allowance described on Plans, Pricing and AI Allowance.

This page is for developers who wire Canva into an assistant or an agent. If you only want to connect Claude, ChatGPT, Gemini or Copilot to your own account, read Canva in AI Assistants instead. The protocol itself (hosts, clients, servers, transports and authorization) is explained in the MCP section of this site.

The running example is Bookshelf, the book catalogue and reading-list app designed in the Figma sub-section. Here you drive the Canva MCP server from Claude Code to find the "Book of the week" post of the launch campaign, retitle it and swap its cover.

What the server is and what it is not

The Canva MCP server is a hosted service. You do not install or run it. Your MCP client (here Claude Code) connects to one URL and discovers the tools the server offers. Everything the tools do happens as the signed-in Canva user, with that user’s permissions, so an edit needs edit permission on the design.

Figure 1. Claude Code, the Canva MCP server and a Canva account

Three things are easy to confuse.

Server Purpose Runs where

Canva MCP server (this page)

Lets an assistant work with designs, assets, folders, brand templates, comments and exports

Remote, hosted by Canva, OAuth per user

Canva AI Connector

The same capability packaged for end users, set up from the Help Center

Built into assistants such as Claude, ChatGPT, Gemini and Copilot

Canva Dev MCP server

Gives a coding agent the developer documentation while you build an app. It cannot reach your designs

Local, started by the CLI over stdio

The Dev MCP server is covered on the Canva Developers SDK overview. A fourth idea runs the other way round: Canva AI can call your own MCP server as a connector. Canva builds all of those connectors itself and third-party submissions are closed, so the documentation points app developers to the Data Connector and URL Expander intents instead (see App intents).

Source: Canva developer documentation: Canva MCP

Enabling Canva MCP for an app

The self-serve path starts in the Developer Portal. You create an app, then switch the MCP integration method on.

  1. Create an app in the Developer Portal at https://www.canva.com/developers/apps and choose who can use it.

  2. Open Outside Canva and select Start integrating. This creates an OAuth client for the app.

  3. Under Outside Canva > Configuration > Integration methods, turn on the Canva MCP toggle. Leave Canva REST APIs off unless the same app also calls the REST APIs (see the REST APIs page).

  4. Under Credentials, note the Client ID and select Generate secret. The secret is shown only once. Treat it like a password, and keep it out of source control and client-side code.

  5. Under Outside Canva > Redirect URLs, add the URL Canva redirects to after a user authorizes your assistant. It must match the redirect URL in the assistant’s OAuth configuration.

You do not set an authorization URL or a token URL in the assistant. Clients that use a Client ID Metadata Document instead of a stored secret must join a waitlist; this page documents the client ID and secret route only. Before you publish an app for other people to use, read the page on verifying your app.

Source: Canva developer documentation: Quickstart, Canva for AI assistants and Access and permissions

The endpoint and per-user authorization

The remote MCP server URL published by Canva is:

https://api.canva.com/connect/v1/mcp

Source: Canva developer documentation: Quickstart, Canva for AI assistants

Authorization uses OAuth. The app identifies itself with its client ID and secret, and each person signs in with their own Canva account the first time a tool is used. Canva does not support organization-level or shared authentication, because designs, assets and permissions belong to individual users. A shared agent may share its configuration, but never tokens, and every user must authenticate separately. Responses from both canva.com and canva.ai must be allowed by your client so that results are not blocked by cross-origin rules.

Some products also circulate a shorter connector address for end users. Only the URL above appears in the developer documentation, so it is the only one this page uses.

Source: Canva developer documentation: Troubleshooting and common questions

Connecting from Claude Code

Claude Code connects to remote servers over HTTP. Put the credentials from the portal in environment variables, never in a script or a file you commit.

export CANVA_CLIENT_ID="your-client-id-from-the-developer-portal"
export MCP_CLIENT_SECRET="your-client-secret-from-the-developer-portal"

claude mcp add --transport http canva \
  https://api.canva.com/connect/v1/mcp \
  --client-id "$CANVA_CLIENT_ID" \
  --client-secret

Source: Claude Code documentation: Connect Claude Code to tools via MCP and Canva developer documentation: Quickstart

The --client-secret flag makes Claude Code take the secret from the MCP_CLIENT_SECRET environment variable, or prompt for it when the variable is not set. The Canva documentation itself gives no Claude Code command, so the command above combines Canva’s URL with Claude Code’s own options. Claude Code can also use a fixed --callback-port when a server needs a pre-registered redirect URL: register the redirect URL that matches that port in the Developer Portal. Check the Claude Code documentation for the exact callback path it uses.

If your client cannot talk to remote MCP servers, Canva documents a bridge that runs mcp-remote over stdio. The example below is the configuration published for VS Code.

{
  "servers": {
    "Canva": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote@latest",
        "https://api.canva.com/connect/v1/mcp"
      ]
    }
  }
}

Source: Canva developer documentation: Quickstart, Canva for AI assistants

Once the server is added, start Claude Code, run /mcp to see its state, and ask a harmless question such as "Show me my most recently edited Canva design". The first tool use opens a browser for the Canva login and consent screen. After the "authorization successful" message you return to the terminal and approve the tool call.

The documented limits include 100 requests per minute for searches and reads, 20 per minute for generate-design, 20 for create-design-from-brand-template, export-design and resize-design, 60 for autofill-design, 10 for generate-image and 30 for upload-asset-from-url. Editing transactions

Searching and generating are single calls. Changing the content of an existing design is different, because an edit is a transaction: you open it, apply operations, and commit. Edits stay in a draft until you commit.

Figure 3. The life of an editing transaction
sequenceDiagram actor U as Developer participant C as Claude Code participant M as Canva MCP server participant D as Design U->>C: Retitle the Book of the week post C->>M: search-designs M-->>C: design and edit_url C->>M: start-editing-transaction M->>D: Open draft M-->>C: transaction_id, richtexts, fills, element_id values C->>M: perform-editing-operations (transaction_id, element_id) M->>D: Apply to draft M-->>C: updated draft state C->>M: commit-editing-transaction M->>D: Save edits M-->>C: committed status C-->>U: Saved, open in Canva to review

The rules that matter, as the documentation states them:

  • start-editing-transaction returns a transaction object with its status and transaction_id, the edit_design_url, the editable text (richtexts), the editable fills such as images (fills) and the page metadata. Each editable element has an element_id.

  • Take element_id values from start-editing-transaction. Do not take them from get-design-content.

  • perform-editing-operations receives the transaction_id and the element IDs. The operation types are described on the tool’s own reference page, so read that page before you write instructions that depend on them.

  • Report an edit as saved only after commit-editing-transaction returns a committed status.

  • cancel-editing-transaction exists in the tool list; the documentation pages summarised here do not describe its output, so check its reference page before relying on it.

The start response has this shape, with placeholder values.

{
  "transaction": { "status": "open", "transaction_id": "TXN_EXAMPLE" },
  "edit_design_url": "https://www.canva.com/d/EXAMPLE",
  "richtexts": [ { "page_index": 1, "element_id": "ELEMENT_EXAMPLE_1" } ],
  "fills": [ { "type": "image", "asset_id": "ASSET_EXAMPLE", "element_id": "ELEMENT_EXAMPLE_2" } ],
  "pages": [ { "page_id": "PAGE_EXAMPLE", "page_number": 1, "is_editable": true } ]
}

Source: Canva developer documentation: start-editing-transaction

Procedure: retitle the Book of the week post from Claude Code

This procedure assumes you completed the setup above and that the launch campaign from the earlier pages exists in your account. Claude Code runs the tool calls; you review what it proposes.

  1. Add the server with the claude mcp add command and sign in when the browser opens.

  2. Ask: "Find my Instagram post named Book of the week in Canva."

  3. Ask: "Open it for editing and show me the editable text and images." Claude Code calls start-editing-transaction and lists the elements.

  4. Ask: "Change the title to Book of the week: a quiet classic and replace the cover with the second image." Claude Code calls perform-editing-operations.

  5. Ask: "Commit the edit and give me the link." Claude Code calls commit-editing-transaction and returns the edit link.

  6. Open the link, check the post in the editor and run the checks from Accessibility in Canva before you publish.

Autofill and the Bookshelf brand template

On Pro or above the same assistant can fill your Book of the week brand template: it finds the template with search-brand-templates, reads the fields with get-brand-template-dataset, and creates the filled design with autofill-design, then export-design produces the file. This is the conversational counterpart of the script on the REST APIs page. Prefer the REST APIs for unattended batch jobs and the MCP server where a person reviews each result. Brand templates and their approval rules are covered on Brand Templates, Controls and Approvals.

Best practices

  • Return an edit handoff after any design-touching call: a direct "Open in Canva" link near the top of the answer. The link comes from edit_url (search-designs, get-design), design_summary.urls.edit_url (create-design-from-candidate) or edit_design_url (start-editing-transaction). If none is present, build https://www.canva.com/design/DESIGN_ID/edit from the design ID. Do not end a workflow at export-design, which only produces a static file.

  • Treat thumbnail and export URLs as short-lived. Do not store or share them.

  • Poll asynchronous jobs at the interval in the returned polling_policy, tie each job ID to the current user and conversation, and never invent or reuse one.

  • Set the client timeout to at least 60 seconds for generate-design.

  • On HTTP 429, back off exponentially with a bounded number of retries, and do not use bulk automation to get around per-user limits. Show actionable errors instead of retrying a failing request.

  • Treat tool results as structured state and enforce state handling in your client where you can.

Source: Canva developer documentation: Best practices for Canva MCP and Design edit handoff

Usage policy

If you build an app on the MCP server for other people, the usage policy applies, and Canva can suspend or withdraw access for violations. In summary:

  • Be clear that your app uses Canva MCP, use compatibility wording such as "works with Canva", use only approved and unaltered logos and never imply that Canva built, endorsed or certified the app.

  • Use secure OAuth, validate inputs, handle errors and retries, and meet accessibility standards.

  • Request only the scopes you need, protect tokens, minimise retention and never use Canva-sourced data to train or improve external AI models.

  • Use Brand Kits only to create or edit Canva designs. Do not extract, cache, export or reuse them outside Canva, and do not analyse or replicate templates. Background or bulk access to designs, folders or Brand Kits needs an explicit, opt-in action from the user.

  • Work only within the authenticated user’s permissions, prevent cross-user caching, and do not act for another user without explicit delegation.

  • Display Canva credit usage without hiding it.

Source: Canva developer documentation: Usage policy and Prohibited use

Pitfalls

  • Sharing one login across a team does not work. Each person completes the OAuth flow.

  • Taking element IDs from the wrong tool makes operations fail. Use the IDs from the start response.

  • Declaring success before the commit result hides unsaved drafts.

  • Timeouts on generate-design are normal at short settings; raise them.

  • Resize, autofill, brand kits and brand templates fail on accounts below Pro.

  • Pasting the client secret into a command, a repository or a screenshot leaks it. Use environment variables and regenerate the secret if it is exposed.

Source: Canva developer documentation: Troubleshooting and common questions

What changed

Date Change

2026-10-27

Canva announced general availability of the Canva MCP server for developers, with self-serve access through the Developer Portal

Around 2026-09

The developer platform was renamed the Canva Developers SDK, with the MCP server as the surface "Canva for AI assistants"

Older tutorials describe the "Connect APIs", the "Apps SDK" and the Canva Button as separate products. Today the first two are surfaces of the Canva Developers SDK, and the Canva Button was shut down outside China, with its keys deactivated after 2025-12-30. See What changed since older guides.
