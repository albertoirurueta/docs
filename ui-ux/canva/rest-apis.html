Canva REST APIs

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was checked against the official developer documentation at https://www.canva.dev/docs/apps/rest-apis/ on 2026-11-07. It covers the second of the three surfaces of the Canva Developers SDK: Canva for your platform, the REST APIs that older material calls the "Connect APIs". The old address https://www.canva.dev/docs/connect/ now redirects to the current pages. The other surfaces are described on Building Apps Inside Canva and the Canva MCP server page, and the map of all three is on Developer Platform Overview.

The REST APIs are generally available, with individual endpoints labelled preview in the reference; the documentation states that preview APIs can change without a new version and that public apps using them fail review. Which plan you need depends on the endpoint: autofill and the brand template APIs act on behalf of a user on Canva Pro (which includes Education and Nonprofits), Teams or Enterprise, and some features, such as resize, are exposed as capabilities that depend on the user’s plan. Plan details and prices are on https://www.canva.com/pricing/ and are not repeated here. Calls that use AI features draw on AI credits.

The running example is a script for the Bookshelf launch campaign. It reads the fields of the "Book of the week" brand template from Brand Templates, Controls and Approvals, fills them for each book in a list, and exports every resulting design as a PNG. Doing the same by hand from a spreadsheet is described on Resize, Bulk Create and Translate.

What the REST APIs are for

An app inside Canva runs in the editor. A REST integration runs on your own servers or laptop and talks to Canva over HTTPS. Typical uses are to create and sync assets and designs, connect a digital asset management system, fill brand templates with data, and export finished designs.

Figure 1. The endpoint groups of the REST APIs and the ones the Bookshelf script uses

The base URL is https://api.canva.com/rest/v1/. Versioning is by date, and the v1 in the path is an epoch marker rather than the API version. Superseded versions are kept for at least six months. You can find the endpoint reference at https://www.canva.dev/docs/apps/rest-apis/reference/ and an OpenAPI description at https://www.canva.dev/sources/connect/api/latest/api.yml.

Source: Canva Developers: REST APIs and API versions

Endpoint groups

Group What it does

users

Create, list and get designs, list export formats, get a design dataset

Import a file or a URL as a design

exports

Create an export job and poll it; formats include pdf, png, jpg, gif, pptx, mp4 and csv

assets

Upload a file or a URL as an asset (URL upload generally available since 2026-10-19), get, update and delete

folders

Some of these groups changed during 2026. Autofill opened to Pro and Teams users on 2026-09-21, the chart, sheet and video autofill fields became generally available on 2026-08-25, design generation arrived as a preview on 2026-09-29 and image generation on 2026-10-01.

Authentication

Which flow you use depends on the type of app you register. Both flows get their tokens from the same endpoint, https://api.canva.com/rest/v1/oauth/token, called with HTTP basic authentication built from the client ID and the client secret. Token calls must come from a backend, because the browser blocks them.

Figure 2. Public and private apps compared with service apps

Authorization code with PKCE

Public and private apps act on behalf of a person, so the person must approve access once. The flow uses PKCE with the S256 method.

sequenceDiagram participant U as User participant B as Your backend participant C as Canva authorize page participant T as Canva token endpoint B->>B: Create code verifier, hash it into a challenge B->>U: Redirect to authorize URL with challenge, scopes and state U->>C: Review and approve the scopes C->>U: Redirect to your redirect URL with code and state U->>B: Browser follows the redirect B->>B: Check that state matches B->>T: POST code and code verifier with basic auth T-->>B: Access token and refresh token B->>T: Later: POST refresh token T-->>B: New access token and a new refresh token
Figure 3. The authorization code flow with PKCE

The details the documentation gives are these.

  • The authorize URL is https://www.canva.com/api/oauth/authorize, with the query parameters code_challenge, code_challenge_method (must be S256), scope (a space-separated list of scopes enabled in the Developer Portal), response_type (must be code), client_id (from the Credentials section of the app’s Outside Canva configuration page), state (optional but recommended for CSRF protection) and redirect_uri (optional when only one redirect URL is configured).

  • The code verifier is a random string of 43 to 128 characters drawn from letters, digits and -._~. Create a new one for every request, keep it on the backend and never put it in state.

  • The code challenge is the SHA-256 hash of the verifier, encoded as URL-safe Base64.

  • To exchange the code, send grant_type=authorization_code, the code and the code_verifier.

  • To renew, send grant_type=refresh_token. Each refresh token works once, and the response carries a new access token and a new refresh token. A refresh token cannot call protected APIs.

  • There are also endpoints to introspect and to revoke tokens.

import crypto from "node:crypto";

const codeVerifier = crypto.randomBytes(96).toString("base64url");
const codeChallenge = crypto
  .createHash("sha256")
  .update(codeVerifier)
  .digest("base64url");

Source: Canva Developers: Authentication

REST APIs also require multi-factor authentication to be turned on for the Canva account that owns the app, and REST access is switched on per app in the Developer Portal under Outside Canva, Configuration, where you also set the redirect URL and the scopes.

Scopes

Scopes follow a resource:action pattern, such as asset:read, asset:write, design:meta:read, design:content:read, design:content:write, brandtemplate:meta:read, brandtemplate:content:read, folder:read and comment:write. They must be listed explicitly: holding asset:write does not give asset:read. Enable each scope in the Developer Portal and request it in the authorization flow. The full list is at Scopes.

Service apps

On 2026-11-06 the changelog added service apps, which authenticate as the app itself with no person signing in. They use the client credentials flow, a separate set of scopes prefixed with service:, and a separate per-app rate limit. Their requests draw from the team’s API credit pool, so the team must have credits first. The documented differences from user apps are these.

  • No authorization URL, redirect and PKCE: you call the token endpoint with grant_type=client_credentials and an optional scope. Without a scope, the token gets the app’s default scopes.

  • No refresh token: request a new access token when the old one expires.

  • Capabilities do not apply to service app requests.

  • Only a subset of the APIs is available: assets, autofills, brand templates, designs, design imports, exports, folders, generations, merges and resizes.

  • The app type cannot be changed after you create the app, so choose it deliberately.

curl --request POST 'https://api.canva.com/rest/v1/oauth/token' \
  --user "$CANVA_CLIENT_ID:$CANVA_CLIENT_SECRET" \
  --data-urlencode 'grant_type=client_credentials' \
  --data-urlencode 'scope=service:design:meta:read service:asset:read'

Source: Canva Developers: Authentication and REST APIs changelog

The credentials come from the environment: CANVA_CLIENT_ID and CANVA_CLIENT_SECRET. Never commit them and never place them in a browser bundle.

Asynchronous jobs and polling

Operations that take time, such as asset upload, autofill and export, return a job instead of a result. The create call answers immediately with a job that has an id and a status of in_progress. You then call the matching "get" endpoint until the status is success or failed.

Figure 4. Life of an asynchronous job and an exponential backoff between polls

The documentation recommends exponential backoff: start with a short interval, increase it between polls and cap it at a maximum, so the experience stays responsive without hitting the rate limits.

sequenceDiagram participant S as Your script participant A as Canva REST API S->>A: POST create job A-->>S: job id, status in_progress loop until success or failed S->>S: Wait, doubling up to a cap S->>A: GET job by id A-->>S: status end A-->>S: success with result, or failed with error

Rate limits, credits and errors

Limits are set per endpoint and per user of your app, and each reference page lists its own. The ones the Bookshelf script meets are in the table.

Endpoint Limit documented on 2026-11-07

Create asset upload job

30 requests per minute per user

Create design autofill job

60 requests per minute per user

Create design export job

20 requests per minute per user; also 75 exports per 5 minutes per design

Get design export job

120 requests per minute per user

Get brand template dataset

100 requests per minute per user

Errors return the HTTP status, a code and a message; the code carries different information from the status. Examples are design_not_found with 404 and permission_denied with 403. Throttling is too_many_requests with 429. Since 2026-10-28, exhausted credits return 402 instead of 429: credit_quota_exceeded when a user has used their AI credit allowance, and app_credit_quota_exceeded when the app funding the request has run out. Failed export jobs carry license_required (premium elements not purchased), approval_required (the design needs reviewer approval) or internal_failure.

Source: Canva Developers: Error responses and the limits on each page of the reference

Brand template autofill

Autofill fills the named data fields of a brand template and creates a new design. The documented workflow has five steps.

  1. Optionally list brand templates to find the template ID. GET /v1/brand-templates accepts query, ownership (any, owned or shared), sort_by, dataset=non_empty to keep only templates with data fields, limit and a continuation token.

  2. Read the dataset with GET /v1/brand-templates/{id}/dataset. The result maps each field name to a type: text, image, chart, sheet or video.

  3. Upload any images, because image fields accept only an uploaded asset ID, never a URL.

  4. Create the autofill job with POST /v1/autofills.

  5. Poll GET /v1/autofills/{jobId} and use the design URL it returns.

{
  "brand_template_id": "TEMPLATE_ID",
  "title": "Book of the week: The Left Hand of Darkness",
  "data": {
    "BOOK_TITLE": { "type": "text", "text": "The Left Hand of Darkness" },
    "AUTHOR": { "type": "text", "text": "Ursula K. Le Guin" },
    "COVER": { "type": "image", "asset_id": "ASSET_ID" }
  }
}

Source: Canva Developers: Autofill guide and Create design autofill job

The field names in your request must match the names in the template’s dataset exactly, because unknown names are silently skipped. The request body also supports type values create_from_brand_template (the default), create_from_design and update_design. A finished job reports a design object with its edit URL and thumbnail. User apps need design:content:write, design:meta:read, brandtemplate:meta:read, brandtemplate:content:read and asset:read plus asset:write; service apps use the same names with a service: prefix.

Exporting designs

The export job takes a design ID and a format. For PNG the options documented on 2026-11-07 are width and height (40 to 25000, and if you set one the other keeps the aspect ratio), export_quality (regular or pro), lossless (default true), transparent_background (default false and a premium feature), as_single_image and pages, where the first page is 1. A successful job returns urls, one per page in page order, and those links expire after 24 hours. Multi-page designs cannot be exported as PPTX unless they are Canva Presentations.

{
  "design_id": "DESIGN_ID",
  "format": { "type": "png", "width": 1080, "height": 1080, "export_quality": "regular" }
}

Source: Create design export job and Get design export job

Procedure: set up the app and credentials

  1. In the Developer Portal at https://www.canva.com/developers/apps, turn on multi-factor authentication for your Canva account if it is off.

  2. Create a new app, or open an existing one, and turn on the REST APIs integration under Outside Canva, Configuration. For an unattended batch job, choose a service app; for a script that acts as you, choose a user app and add a redirect URL such as http://127.0.0.1:3001/oauth/callback.

  3. Enable the scopes the script needs: for a user app asset:read, asset:write, design:content:read, design:content:write, design:meta:read, brandtemplate:meta:read and brandtemplate:content:read; for a service app the same names with the service: prefix.

  4. Copy the client ID and generate a client secret. Put them in your shell as CANVA_CLIENT_ID and CANVA_CLIENT_SECRET, or in an untracked environment file loaded by your tooling.

  5. Make sure the account behind the brand template is on a plan with brand templates, and that the "Book of the week" template is published and has data fields named BOOK_TITLE, AUTHOR and COVER.

  6. Call the token endpoint once, as in the earlier command, to confirm the credentials work before writing any code.

Source: Canva Developers: Authentication

Procedure: autofill the Book of the week template and export PNGs

The script below uses a service app, so it needs no browser sign-in. It needs Node.js 24, which provides fetch. It follows the pipeline in the figure.

Figure 6. The six steps of the Bookshelf script
Figure 7. Storyboard of autofilling the template and exporting PNGs

  1. Create a folder bookshelf-rest, run npm init -y and set "type": "module" in package.json. No dependency is needed.

  2. Save the file below as bookshelf.mjs. It reads CANVA_CLIENT_ID, CANVA_CLIENT_SECRET and BRAND_TEMPLATE_ID from the environment.

  3. Put the cover images in a folder named covers, one PNG per book, named like the entries in the list.

  4. Run node bookshelf.mjs. The script prints the design URL of each book and writes the PNG files to out.

  5. Open one design URL in the editor to check the fields, then open the PNG to check the result.

import { readFile, writeFile, mkdir } from "node:fs/promises";

const API = "https://api.canva.com/rest/v1";
const { CANVA_CLIENT_ID, CANVA_CLIENT_SECRET, BRAND_TEMPLATE_ID } = process.env;

const books = [
  { title: "The Left Hand of Darkness", author: "Ursula K. Le Guin", cover: "left-hand.png" },
  { title: "Kindred", author: "Octavia E. Butler", cover: "kindred.png" },
];

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function getToken() {
  const basic = Buffer.from(`${CANVA_CLIENT_ID}:${CANVA_CLIENT_SECRET}`).toString("base64");
  const response = await fetch(`${API}/oauth/token`, {
    method: "POST",
    headers: {
      Authorization: `Basic ${basic}`,
      "Content-Type": "application/x-www-form-urlencoded",
    },
    body: new URLSearchParams({
      grant_type: "client_credentials",
      scope: [
        "service:asset:write",
        "service:design:content:write",
        "service:design:content:read",
        "service:brandtemplate:content:read",
      ].join(" "),
    }),
  });
  if (!response.ok) throw new Error(`Token request failed: ${response.status}`);
  return (await response.json()).access_token;
}

async function call(token, path, options = {}) {
  const response = await fetch(`${API}${path}`, {
    ...options,
    headers: { Authorization: `Bearer ${token}`, ...options.headers },
  });
  if (!response.ok) {
    const body = await response.text();
    throw new Error(`${options.method ?? "GET"} ${path} failed: ${response.status} ${body}`);
  }
  return response.json();
}

async function pollJob(token, path) {
  let wait = 1000;
  const deadline = Date.now() + 120_000;
  while (Date.now() < deadline) {
    const { job } = await call(token, path);
    if (job.status === "success") return job;
    if (job.status === "failed") throw new Error(`Job failed: ${JSON.stringify(job.error)}`);
    await sleep(wait);
    wait = Math.min(wait * 2, 8000);
  }
  throw new Error(`Timed out waiting for ${path}`);
}

async function uploadCover(token, file) {
  const name = Buffer.from(file).toString("base64");
  const { job } = await call(token, "/asset-uploads", {
    method: "POST",
    headers: {
      "Content-Type": "application/octet-stream",
      "Asset-Upload-Metadata": JSON.stringify({ name_base64: name }),
    },
    body: await readFile(`covers/${file}`),
  });
  const done = await pollJob(token, `/asset-uploads/${job.id}`);
  return done.asset.id;
}

async function autofill(token, book, assetId) {
  const { job } = await call(token, "/autofills", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      brand_template_id: BRAND_TEMPLATE_ID,
      title: `Book of the week: ${book.title}`,
      data: {
        BOOK_TITLE: { type: "text", text: book.title },
        AUTHOR: { type: "text", text: book.author },
        COVER: { type: "image", asset_id: assetId },
      },
    }),
  });
  const done = await pollJob(token, `/autofills/${job.id}`);
  return done.result.design;
}

async function exportPng(token, designUrl) {
  const designId = new URL(designUrl).pathname.split("/")[2];
  const { job } = await call(token, "/exports", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      design_id: designId,
      format: { type: "png", width: 1080, height: 1080 },
    }),
  });
  const done = await pollJob(token, `/exports/${job.id}`);
  return done.urls;
}

const token = await getToken();
const { dataset } = await call(token, `/brand-templates/${BRAND_TEMPLATE_ID}/dataset`);
console.log("Template fields:", Object.keys(dataset).join(", "));

await mkdir("out", { recursive: true });
for (const [index, book] of books.entries()) {
  const assetId = await uploadCover(token, book.cover);
  const design = await autofill(token, book, assetId);
  console.log(`${book.title}: ${design.url}`);
  const urls = await exportPng(token, design.url);
  const image = await fetch(urls[0]);
  await writeFile(`out/book-${index + 1}.png`, Buffer.from(await image.arrayBuffer()));
}

Source: adapted from the Autofill guide, the Create asset upload job reference and the Create design export job reference

Three points in the script are worth understanding. The design ID is taken from the design URL path, which has the shape /design/<ID>/edit. Exports are requested only after autofill reports success, because the design does not exist before. And the script processes books one at a time, which keeps it far below the per-minute limits; if you run large batches, add a pause or a queue and treat a 429 as a signal to wait before retrying.

Procedure: use the Canva CLI instead of writing code

The Canva CLI can call the same REST APIs with your own login, which is handy for exploring.

  1. Install and log in: canva login. If a call fails with MISSING_SCOPE, log in again so the CLI requests the access it needs.

  2. List your designs with canva api designs list, or fetch one with canva api designs get DESIGN_ID.

  3. Show an operation’s contract as JSON with canva api describe exports create.

  4. Upload a file with canva api assets create-upload --file ./cover.png --name "Left Hand cover", then check it with canva api assets get-upload JOB_ID. The CLI does not wait for the job, so repeat the second command until data.job.status is success or failed.

  5. Validate a command without sending it by adding --dry-run.

The output is one JSON object on standard output with ok, data and meta, so it pipes into jq.

Source: Canva Developers: Making REST API requests with the CLI

Webhooks

Webhooks let Canva push events to you instead of you polling for them. Canva sends an outgoing POST request and expects a 200 reply; webhooks are outgoing only, so to answer a comment you call the Comments API. Every notification type needs the collaboration:event scope, plus type-specific scopes, such as design:meta:read and comment:read for comments. There are eleven notification types: comment, suggestion, design_access_requested, folder_access_requested, design_approval_requested, design_approval_response, design_approval_reviewer_invalidated, design_mention, share_design, share_folder and team_invite.

A notification has a type, an id and a created_at UNIX time, with the event data under content. For a comment the event details are under content.comment_event. Users do not receive notifications for their own comments.

sequenceDiagram participant U as Canva user participant C as Canva participant W as Your webhook endpoint participant K as Canva keys endpoint U->>C: Comments on a design C->>W: POST notification, signed W->>W: Pick the cached key whose kid matches opt Unknown kid W->>K: GET keys, no authentication K-->>W: JSON Web Key Set W->>W: Cache the keys end W->>W: Verify the signature W-->>C: 200 W->>W: Handle the event, for example call the Comments API
Figure 8. Receiving and verifying a webhook

The keys endpoint is public: GET https://api.canva.com/rest/v1/connect/keys returns a JSON Web Key Set whose keys carry a kid, a kty of OKP, a crv of Ed25519 and the public key in x. Select the key by kid, cache the set and call the endpoint again only when a notification arrives signed with a key you do not know, because keys rotate. The signature header and the exact signing input are described in the official webhook pages, so follow those rather than a third-party snippet.

Source: Canva Developers: Webhooks and Keys

Desktop, mobile and other differences

The REST APIs are server-side and do not depend on a device. Two differences matter. A design created by autofill opens in the editor on any device from its URL, but the edit and view URLs a design object returns are temporary. And plan-gated behaviour follows the user the token represents, while a service app runs without capabilities and spends team credits.

Pitfalls

  • Putting the client secret in a browser bundle or a repository.

  • Calling the token endpoint from the browser, where the request is blocked.

  • Reusing a refresh token: each works once, so store the new one each time.

  • Forgetting that asset:write does not include asset:read.

  • Passing an image URL to an image field instead of an uploaded asset ID.

  • Misspelling a field name: unknown names in an autofill request are skipped silently, so check the dataset first.

  • Polling in a tight loop instead of backing off.

  • Downloading export links after 24 hours.

  • Treating a 402 as throttling: it means credits are exhausted, so waiting will not help.

  • Choosing the wrong app type: a service app cannot be converted to a user app.

  • Building a public app on a preview endpoint.
