What’s New in 3.x and Migrating

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page was checked in October 2026 against pandas 3.1 (3.1.0, released 2026-10-22) on Python 3.13 with NumPy 2.5, and the printed output of every example was produced on those versions. It summarises what changed between pandas 2.0 and 3.1, gives a migration checklist for code written for pandas 1.x or 2.x, and ends with the places where older books and tutorials no longer match current pandas. Items from the development branch (3.2.0.dev0, unreleased) are labelled "upcoming" and may change before release.

What pandas 3.0 changed

Copy-on-Write only

Every derived object behaves as a copy, chained assignment never updates the original, SettingWithCopyWarning no longer exists and arrays returned by to_numpy() can be read-only. See Copy-on-Write for the rules and the fixes.

The str dtype is the default

String columns are inferred as the dedicated str dtype instead of object. It is backed by PyArrow when installed, holds only strings or missing values, and uses NaN as the missing marker (the older opt-in "string" dtype uses pd.NA). It is described in PDEP-14.

import pandas as pd

df = pd.DataFrame({"name": ["a", "b"], "n": [1, 2]})
print(df.select_dtypes(include=["object", "string"]).columns.tolist())
print(df.select_dtypes(include="str").columns.tolist())
print(df.dtypes.astype(str).to_dict())
print(df["name"].astype(object).dtype, pd.Series(["a"], dtype="object").dtype)

ser = pd.Series(["a", None, "c"])
print(ser.map(str, na_action="ignore").tolist(), ser.map(str).tolist())

['a', nan, 'c'] ['a', 'nan', 'c']

Source: pandas user guide: Migration guide (the new string data type).

The code changes the migration guide asks for are:

  • Replace ser.dtype == object with pd.api.types.is_string_dtype(ser) (works on 2.x and 3.x) or ser.dtype == "str" (3.x only).

  • Remove hard-coded dtype="object" for text, which keeps the old dtype, or write dtype="str".

  • In select_dtypes, pass include=["object", "string"] to work on both versions; include=["str"] fails on 2.x.

  • Test for missing values with pd.isna, not by comparing with None or np.nan.

  • Expect TypeError when assigning a non-string into a str column; convert with astype(object) if you really need mixed values.

  • astype(str) keeps missing values missing; use ser.map(str) for the old behaviour of producing the text nan.

  • Series.values returns an extension array for str; use to_numpy() for a NumPy array.

  • prod() on string data now raises TypeError.

See Text Data and the str Dtype.

Datetime resolution and time zones

Resolution is now inferred instead of always being nanoseconds. Strings give microseconds (nanoseconds only when the text has that precision), standard-library datetime objects keep microseconds, NumPy datetime64 and timedelta64 keep their unit (limited to seconds through nanoseconds), and integer input uses the unit passed by the caller. In 3.1, numeric input with an explicit unit= gives microseconds (pd.Timestamp(1, unit="s").unit is "us"), while numbers without a unit are still nanoseconds since the epoch and give ns. The practical trap is that astype("int64") on datetimes is 1000 times smaller than code written for nanoseconds expects. Use Series.dt.as_unit("ns") where a specific resolution matters, and avoid integer casts of datetimes. The default time zone implementation is zoneinfo (and datetime.timezone for fixed offsets); pytz objects are still accepted if you pass them, but pytz is no longer installed with pandas, and ambiguous or nonexistent local times raise ValueError. pd.offsets.Day is now a calendar day that keeps the wall-clock time across a daylight-saving change, so Day(1) and Hour(24) are no longer equal.

Behaviour changes in the same release include: groupby defaults to observed=True for categorical keys, DataFrame.stack uses the new implementation (the future_stack argument and the old dropna/sort arguments are being retired), assigning an incompatible value into a column raises instead of upcasting (PDEP-6), and NaN is treated as NA in nullable and Arrow-backed floating dtypes. An older change that tutorials still get wrong: since pandas 2.0, str.replace treats the pattern literally unless regex=True is passed.

import pandas as pd

rows = [{"id": i, "score": i * 1.5} for i in range(3)]
frames = [pd.DataFrame([r]) for r in rows]     # collect, then concatenate once
result = pd.concat(frames, ignore_index=True)
print(result)

print(hasattr(pd.DataFrame, "append"), hasattr(pd.DataFrame, "applymap"), hasattr(pd.DataFrame, "map"))
df = pd.DataFrame({"a": [" x ", "y"]})
print(df.map(str.strip).to_dict("list"))
print(df.ffill().shape, hasattr(pd, "value_counts"), df["a"].value_counts().to_dict())
print(pd.Series(["a.b"]).str.replace(".", "-").tolist(), pd.Series(["a.b"]).str.replace(".", "-", regex=True).tolist())

New in 3.0

  • pd.col() expressions, usable in assign, loc and [], replace many one-off lambda callables.

  • Anti-joins: how="left_anti" and how="right_anti" in merge and join.

  • read_iceberg() and DataFrame.to_iceberg() for Apache Iceberg tables, DataFrame.from_arrow() and Series.from_arrow() through the Arrow PyCapsule interface.

  • A skipna argument for groupby reductions, Rolling.first, Rolling.last, Rolling.nunique, iloc with boolean masks, to_sql(if_exists="delete_rows") and half-year offsets.

  • The three-stage deprecation policy of PDEP-17 (below).

inplace is deprecated for methods that are not truly in place

Since 3.1 the inplace= keyword emits a Pandas4Warning on drop, rename, rename_axis, reset_index, set_index, dropna, drop_duplicates, sort_values, sort_index, eval and query (PDEP-8). These methods always built a new object internally, so the keyword saved nothing. Reassign instead: df = df.reset_index(). fillna and replace keep the keyword for now, although inplace=True on a column selection no longer reaches the parent frame (see Copy-on-Write).

The deprecation policy (PDEP-17)

Since 3.0, a deprecation moves through three stages: a PandasDeprecationWarning (a DeprecationWarning subclass, quiet by default outside tests), a PandasFutureWarning (a FutureWarning subclass, shown to users) in the last minor release before removal, and removal in the next major version. The base class is pandas.errors.PandasChangeWarning, and each warning names the version that will remove the feature: Pandas4Warning means pandas 4.0. Because Pandas4Warning is a DeprecationWarning, test suites should turn it into an error so that deprecations surface while they are still cheap to fix.

import warnings
import pandas as pd

print([c.__name__ for c in pd.errors.Pandas4Warning.__mro__[:4]])

df = pd.DataFrame({"a": [3, 1, 2]})
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    work = df.copy()
    work.sort_values("a", inplace=True)            # deprecated in 3.1
print([type(w.message).__name__ for w in caught])

df = df.sort_values("a")                           # reassign instead
print(df["a"].tolist())

warnings.filterwarnings("error", category=pd.errors.Pandas4Warning)
try:
    pd.DataFrame({"a": [1]}).reset_index(inplace=True)
except pd.errors.Pandas4Warning as exc:
    print("escalated:", type(exc).__name__)

Output:

['Pandas4Warning', 'PandasDeprecationWarning', 'PandasChangeWarning', 'DeprecationWarning']
['Pandas4Warning']
[1, 2, 3]
escalated: Pandas4Warning

Source: pandas 3.0.0 release notes (deprecation policy) and PDEP-17.

Migration checklist

  1. Upgrade to Python 3.11 or newer and, for pandas 3.1, NumPy 2.0.2 or newer (see Migrating to NumPy 2.x).

  2. Move to pandas 2.3 (2.3.3 is the last 2.x release) and run the tests with deprecation warnings turned into errors. Fix every warning.

  3. In 2.3, try pd.options.future.infer_string = True and pd.options.mode.copy_on_write = "warn", and repair the code they flag. The Copy-on-Write warnings are intentionally broad, so you do not need to clear every one.

  4. Replace removed APIs using the table above, including frequency aliases (ME, QE, YE, h, min) and DataFrame.map for applymap.

  5. Replace chained assignment with a single loc call, remove SettingWithCopyWarning handling, and stop writing into arrays from to_numpy().

  6. Replace object dtype checks and select_dtypes(include=object) with the string-aware forms.

  7. Review datetime-to-integer casts and any code that assumes nanosecond resolution.

  8. Move to 3.0, then 3.1, fixing Pandas4Warning messages as they appear; reassign instead of using inplace=True.

  9. Pin the tested range in pyproject.toml (for example pandas>=3.1,<4), and read the release notes of every minor release.

Upcoming (unreleased)

The following items come from the 3.2.0 development notes and may still change: read_csv(sep=None) separator sniffing with the C engine, Categorical.to_dense(), DatetimeIndex.set_freq(), Series.groupby(as_index=False), a deprecation of pandas.to_pickle in favour of the object methods, an error for suffix collisions in merge, and a ValueError from DataFrame.query when the expression is not boolean. Pandas 4.0 will remove the deprecated options and every feature marked with a Pandas4Warning. Treat all of this as planned, not available.

Where older books and tutorials are outdated

Most of what is still taught about pandas was written for versions before 2.0. When a book or tutorial disagrees with the pages in this section, the official documentation wins. The tables name the editions and their dates only to help you translate the examples you may meet; they do not reproduce any text.

Books

Typical advice Current situation

"Ignore SettingWithCopyWarning" or "add .copy() everywhere"
