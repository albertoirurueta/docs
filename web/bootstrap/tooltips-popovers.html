Tooltips & Popovers

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Tooltips and popovers both attach a small floating overlay to a trigger element — a short label for a tooltip, a richer title-plus-body panel for a popover. They are covered together because they share the same underlying mechanics: both are positioned by Popper.js, and, unlike the components on Interactive Components, neither one activates from data-bs-* attributes alone — both require an explicit JavaScript call to opt each element in.

Why explicit initialization is required

Bootstrap enables tooltips and popovers "opt-in" rather than automatically, for performance: computing a Popper.js position for every element that merely carries a title attribute on every page would be wasteful, so only elements the page explicitly initializes get the behavior. The standard pattern selects every element carrying the relevant data-bs-toggle value and constructs an instance for each:

const tooltipTriggers = document.querySelectorAll('[data-bs-toggle="tooltip"]');
tooltipTriggers.forEach((el) => new bootstrap.Tooltip(el));

const popoverTriggers = document.querySelectorAll('[data-bs-toggle="popover"]');
popoverTriggers.forEach((el) => new bootstrap.Popover(el));

This script must run after the DOM elements it queries exist — placed just before </body>, or inside a DOMContentLoaded listener — otherwise querySelectorAll finds nothing and no tooltip or popover on the page will ever show.

Tooltips

The markup itself only needs data-bs-toggle="tooltip" and a title attribute holding the tooltip’s text — the title is what Bootstrap’s JavaScript reads to build the tooltip’s content, and it is removed from the DOM (so the browser’s own native title tooltip never doubles up with Bootstrap’s):

<button type="button" class="btn btn-secondary" data-bs-toggle="tooltip" data-bs-placement="top"
        title="Saves the current document">
  Save
</button>

<a href="#" data-bs-toggle="tooltip" data-bs-placement="right" title="Opens in a new tab">
  External link
</a>
document.querySelectorAll('[data-bs-toggle="tooltip"]').forEach((el) => new bootstrap.Tooltip(el));

data-bs-placement accepts top, right, bottom, or left, and is only a preference — Popper.js still flips it automatically if the tooltip would otherwise render outside the viewport (for example, a top tooltip near the top edge of the page flips to bottom).

HTML content in a tooltip

By default the title text is inserted as plain text, escaping any markup it contains. Setting data-bs-html="true" allows real HTML inside the tooltip — only worth doing for trusted, static content, since it is otherwise an XSS vector if the title text ever comes from user input:

<button type="button" class="btn btn-secondary" data-bs-toggle="tooltip" data-bs-html="true"
        title="<em>Emphasized</em> tooltip text">
  Hover me
</button>

Popovers

A popover is structurally similar to a tooltip but supports both a title (the popover’s header) and a separate data-bs-content (its body), and stays open until dismissed rather than only while hovering, when combined with the focus/dismiss options below:

<button type="button" class="btn btn-primary" data-bs-toggle="popover" data-bs-placement="bottom"
        title="Dismissible popover" data-bs-content="And here's some amplifying body content.">
  Click to toggle popover
</button>
document.querySelectorAll('[data-bs-toggle="popover"]').forEach((el) => new bootstrap.Popover(el));

Popovers default to triggering on click rather than hover, which is why data-bs-toggle="popover" alone is enough to make the example above open on click without any extra configuration.

Dismiss on next click

data-bs-trigger="focus" closes the popover as soon as the user clicks anywhere else on the page (moving focus away from the trigger), which is the recommended pattern for a "dismissible on next click" popover — the trigger element must be focusable for this to work, so a plain <a> needs tabindex="0" if it lacks an href. For consistent behavior across browsers and platforms, Bootstrap’s own documentation uses <a tabindex="0" role="button"> for this pattern, because Safari and Firefox on macOS do not focus a <button> when it is clicked:

<button type="button" class="btn btn-secondary" data-bs-toggle="popover" data-bs-trigger="focus"
        title="Dismissible" data-bs-content="Clicking anywhere else closes this popover.">
  Dismissible popover
</button>

The JavaScript component API

Both components support the same instance-based API shape used across Bootstrap’s other stateful components (see JavaScript Behavior for the general pattern): show(), hide(), toggle(), and dispose(), retrieved either from the constructor’s return value or, for an instance created elsewhere, via bootstrap.Tooltip.getInstance(el):

const el = document.getElementById("save-button");
const tooltip = new bootstrap.Tooltip(el, {
  placement: "top",
  title: "Saves the current document",
});

tooltip.show();
tooltip.hide();
tooltip.dispose();   // removes the tooltip and its event listeners entirely

// elsewhere, without a reference to the original instance:
bootstrap.Tooltip.getInstance(el)?.hide();

dispose() matters specifically for content that is removed from the DOM dynamically (a row deleted from a table, a card removed from a list) — without disposing the tooltip/popover instance first, Popper.js keeps a reference to the now-detached element and its positioning listeners are never cleaned up, a small but real memory leak in a page that creates and destroys many such elements over its lifetime.

Custom triggers and events

The trigger option (or data-bs-trigger) accepts a space-separated combination of click, hover, focus, and manual — manual disables all automatic triggering, leaving show()/hide()/toggle() as the only way to control visibility, useful when a tooltip’s visibility should be driven by application logic rather than direct user interaction with the trigger element itself.

What happens when a tooltip is shown

Initialization does more than attach listeners. At construction time the title attribute is moved to data-bs-original-title (so the browser’s native tooltip never competes), and nothing is added to the DOM until the tooltip is first needed. The overlay element is created on demand, from the template option, and removed again when hidden. The complete sequence for a hover tooltip is:

sequenceDiagram participant U as User participant T as Trigger element participant B as Bootstrap Tooltip participant P as Popper U->>T: pointer enters or focus arrives T->>B: trigger event B->>B: wait for delay.show B->>T: dispatch show.bs.tooltip (cancelable) B->>T: insert overlay, set aria-describedby B-->>T: dispatch inserted.bs.tooltip B->>P: compute placement, flip if needed B-->>T: dispatch shown.bs.tooltip after the fade U->>T: pointer leaves or focus is lost B->>B: wait for delay.hide B->>T: dispatch hide.bs.tooltip, remove overlay B-->>T: dispatch hidden.bs.tooltip

The events are show.bs.tooltip, inserted.bs.tooltip, shown.bs.tooltip, hide.bs.tooltip and hidden.bs.tooltip (and the same with popover for popovers). inserted fires once the overlay is in the DOM and before shown, which is the moment to decorate or inspect it. While the overlay is shown, the trigger has aria-describedby pointing at the overlay’s id, so a screen reader announces the text as a description of the focused element.

Options reference

Every option can be given as a data-bs-* attribute or in the constructor (a constructor value wins, as described on JavaScript Behavior). The defaults below come from Bootstrap 5.3.

Option Meaning

title, content

Text, an HTML string (with html: true), an element, or a function returning one. A function is called when the overlay is about to be shown, so its content can depend on the current state.

html

Treat the content as HTML instead of text. Default false.

sanitize, allowList, sanitizeFn

With sanitize: true (the default) HTML content is filtered through an allow list of tags and attributes; a <script>, an onerror attribute or a javascript: URL is dropped. allowList extends it, and sanitizeFn replaces it with a library such as DOMPurify.

placement

top, right, bottom, left or auto. The default is top for tooltips and right for popovers.

fallbackPlacements

The order Popper tries when the preferred side does not fit. Default ["top", "right", "bottom", "left"].

offset

[skidding, distance] from the trigger. Default [0, 6].

trigger

Space-separated click, hover, focus, manual. The default is "hover focus" for tooltips and "click" for popovers.

delay

Milliseconds, or {"show": 500, "hide": 100}. Default 0.

container

A selector or element to append the overlay to. Default false: right after the trigger. Use "body" to escape clipping or stacking-context problems.

customClass

Extra class(es) on the overlay, such as tooltip-wide.

selector

A selector for delegated triggers, so one instance on an ancestor serves current and future descendants.

template

The overlay’s HTML skeleton, with .tooltip-inner, .popover-header and .popover-body slots.

animation

Apply the fade transition. Default true.

The sanitizer is the reason a tooltip title that contains user-supplied text is safe by default. With html: true, this input:

<em>ok</em><img src=x onerror="alert(1)"><script>1</script><a href="javascript:alert(1)">l</a>

is reduced to the following output: the script, the inline handler and the javascript: URL are removed. Turning sanitize off is only justified for markup you wrote yourself.

<em>ok</em><img src="x"><a>l</a>

Accessibility rules for tooltips

A tooltip is announced as a description, not as the control’s name, so an icon-only button still needs its own accessible name (aria-label or visually hidden text), with the tooltip repeating or supplementing it. The default trigger includes focus, so keyboard users get the tooltip too, but only when the trigger can take focus. A disabled button cannot be focused and does not fire pointer events, so its tooltip never appears. The documented workaround is to put the tooltip on a focusable wrapper:

<span class="d-inline-block" tabindex="0" data-bs-toggle="tooltip" title="Out of stock">
  <button class="btn btn-primary" type="button" disabled>Add to cart</button>
</span>

Nothing essential should be available only in a tooltip, since touch devices have no hover and a screen magnifier user may never trigger one.

Deep dive: catalog row details with a dynamic popover

The product table needs a small "info" button in each row that shows the SKU and stock level, with the stock level colored when it is low. The content depends on data attributes of the clicked row and must be built when the popover opens, not when the page loads, so content is a function. The popover is dismissed when focus leaves the button, and instances are disposed when a row is deleted:

<table class="table align-middle" id="catalog">
  <tbody>
    <tr>
      <td>Mechanical Keyboard</td>
      <td>
        <a tabindex="0" role="button" class="btn btn-sm btn-outline-secondary info-button"
           data-bs-title="Mechanical Keyboard" data-sku="KB-0089" data-stock="3"
           aria-label="Show details for Mechanical Keyboard">i</a>
      </td>
      <td>
        <span class="d-inline-block" tabindex="0" data-bs-toggle="tooltip" title="Out of stock">
          <button type="button" class="btn btn-sm btn-primary" disabled>Add to cart</button>
        </span>
      </td>
    </tr>
  </tbody>
</table>
import { Popover, Tooltip } from "bootstrap";

document.querySelectorAll("#catalog [data-bs-toggle='tooltip']").forEach((el) => new Tooltip(el));

document.querySelectorAll("#catalog .info-button").forEach((button) => {
  new Popover(button, {
    html: true,
    trigger: "focus",              // closes when focus moves elsewhere
    container: "body",             // escape the table's overflow and stacking context
    content: () => {
      const stock = Number(button.dataset.stock);
      const css = stock < 5 ? "text-danger" : "";
      return `<dl class="mb-0"><dt>SKU</dt><dd>${button.dataset.sku}</dd></dl>` +
             `<span class="${css}">${stock} left</span>`;
    },
  });
});

function removeRow(row) {
  row.querySelectorAll(".info-button").forEach((button) => Popover.getInstance(button)?.dispose());
  row.remove();
}

When the info control gets focus, the popover shows the title taken from data-bs-title, the SKU in a description list and "3 left" in red; when focus moves away, it closes. removeRow() disposes the instance before removing the row, so no overlay or listener outlives its trigger.

Two details are worth noting. dl, dt, dd and span are in the sanitizer’s allow list, as is the class attribute, so the markup survives sanitizing; a <script> appended to the same string would be removed. And the trigger is an <a tabindex="0" role="button"> rather than a <button> because trigger: "focus" depends on the element receiving focus when it is clicked, and Safari and Firefox on macOS do not focus a <button> on click.

Choosing between them

Use a tooltip for a short, supplementary label — what an icon-only button does, an abbreviation’s expansion — content the user does not strictly need to operate the page. Use a popover when there is more to say than fits in a one-line label, or when the content should stay visible while the user reads or interacts with it, rather than disappearing the instant the pointer moves away.

See the official Tooltips docs and the official Popovers docs for the complete option and event reference.
