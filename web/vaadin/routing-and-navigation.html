Routing and Navigation

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

In Flow a view is a component class annotated with @Route; the framework builds a URL-to-class map at startup and swaps views into a layout on navigation, all server-side. This page follows Routing & Navigation and Views & Navigation. It replaces the Vaadin 7 Navigator / View API entirely.

Mapping views

@Route("customers")            // https://.../customers
public class CustomerListView extends VerticalLayout { }

@Route(value = "", layout = MainLayout.class)   // the application root
public class DashboardView extends VerticalLayout { }

@Route("about")
@RouteAlias("info")            // a second path to the same view
public class AboutView extends Div { }

Omitting value derives the path from the class name (CustomerListView → customer-list). Register or inspect routes at runtime with RouteConfiguration.

Links and programmatic navigation

add(new RouterLink("Customers", CustomerListView.class));

// from an event handler
UI.getCurrent().navigate(CustomerListView.class);
UI.getCurrent().navigate("customers/42");

RouterLink renders an <a> that Flow intercepts, so navigation stays a single round trip with no full page load.

Route parameters

Three mechanisms, from simplest to most flexible:

// 1. A single typed parameter
@Route("customer")
public class CustomerView extends Div implements HasUrlParameter<Long> {
    @Override
    public void setParameter(BeforeEvent event, Long id) {
        show(customerService.findById(id));   // /customer/42
    }
}

// 2. Named parameters in a route template
@Route("order/:orderId/line/:lineId")
public class OrderLineView extends Div implements BeforeEnterObserver {
    @Override
    public void beforeEnter(BeforeEnterEvent event) {
        String orderId = event.getRouteParameters().get("orderId").orElseThrow();
    }
}

// 3. Query parameters
@Override
public void beforeEnter(BeforeEnterEvent event) {
    QueryParameters qp = event.getLocation().getQueryParameters();
    String tab = qp.getParameters().getOrDefault("tab", List.of("summary")).get(0);
}

Template segments support modifiers: :id? (optional), :path* (wildcard), and typed patterns such as :id(\\d+). See Route parameters.

The navigation lifecycle

Every navigation runs three phases. Observers implemented on the view — or registered globally with UI.addBeforeEnterListener(...) — can inspect the target, redirect, or defer.

(BeforeLeaveObserver)"] leave -->|"postpone()"| pending["navigation paused
e.g. 'discard unsaved changes?'"] pending -->|"proceed()"| enter leave -->|no postpone| enter["BeforeEnter on the TARGET view
(BeforeEnterObserver)"] enter -->|"rerouteTo(...) / forwardTo(...)"| reroute["restart with a new target"] reroute --> leave enter -->|allowed| render["view attached to the layout"] render --> after["AfterNavigation
(AfterNavigationObserver) — URL is updated"] after --> done([done])
public class EditorView extends Div implements BeforeLeaveObserver {
    @Override
    public void beforeLeave(BeforeLeaveEvent event) {
        if (binder.hasChanges()) {
            BeforeLeaveEvent.ContinueNavigationAction action = event.postpone();
            confirmDiscard(action::proceed);
        }
    }
}

// redirect an unauthenticated user
public void beforeEnter(BeforeEnterEvent event) {
    if (!authenticated()) {
        event.rerouteTo(LoginView.class);
    }
}

rerouteTo keeps the URL; forwardTo also updates it. See Navigation lifecycle.

Layouts

A view’s layout wraps it in a shared frame — typically an AppLayout with a navbar and drawer. A layout class implements RouterLayout; @ParentLayout nests one layout in another. Annotating a layout with @Layout makes it the automatic parent of every route that does not set its own.

@Layout                                   // wraps all routes by default
public class MainLayout extends AppLayout implements RouterLayout {
    public MainLayout() {
        addToNavbar(new DrawerToggle(), new H1("My App"));
        addToDrawer(new SideNav());
    }
}

@Route(value = "reports", layout = ReportsLayout.class)   // opt into a different frame
public class ReportsView extends Div { }

Page titles and error views

@Route("customers")
@PageTitle("Customers")                    // static <title>
public class CustomerListView extends VerticalLayout { }

@Route("customer")
public class CustomerView extends Div implements HasDynamicTitle {
    @Override
    public String getPageTitle() {
        return customer.getName() + " — Customers";
    }
}

// a 404 view
@Tag("div")
public class RouteNotFoundView extends Component
        implements HasErrorParameter<NotFoundException> {
    @Override
    public int setErrorParameter(BeforeEnterEvent event,
                                 ErrorParameter<NotFoundException> parameter) {
        getElement().setText("No such page.");
        return HttpStatusCode.NOT_FOUND.getCode();
    }
}

Dynamic routes and menus

RouteConfiguration.forSessionScope().setRoute("path", View.class) registers a route for one session only — useful for feature flags or per-tenant views. MenuConfiguration.getMenuEntries() returns every route annotated with @Menu, which pairs with SideNav to build a navigation drawer without a hand-maintained list:

SideNav nav = new SideNav();
MenuConfiguration.getMenuEntries().forEach(entry ->
        nav.addItem(new SideNavItem(entry.title(), entry.path(),
                entry.icon() == null ? null : new SvgIcon(entry.icon()))));

See Retrieving routes and Side Navigation.

How a URL becomes a view

At startup Flow scans the @Route classes and builds a route registry: a tree of static segments and template parameters. Resolving a URL is a lookup in that tree, followed by a walk up the layout chain, and only then do the lifecycle observers run. Understanding the order explains most routing surprises — for example why a view’s constructor must not read the URL.

flowchart TD url(["/customers/42/edit?tab=history"]) --> match["match against the route registry
(static segments win over :parameters)"] match -->|no match| nf["error view for NotFoundException"] match --> chain["build the layout chain
View -> ParentLayout -> ... -> UI"] chain --> guard["global BeforeEnter listeners
(for example the access checker)"] guard -->|reroute / forward| match guard --> obs["BeforeEnterObserver on each chain member"] obs -->|reroute / forward| match obs --> attach["attach the chain to the UI
reuse an instance that is already in place"] attach --> after["AfterNavigationObserver
URL pushed to the browser history"]

Three consequences follow from the diagram:

  • Instances are reused. Navigating from /customers/1/edit to /customers/2/edit keeps the same view instance and only runs beforeEnter again. Load per-record state in beforeEnter, never in the constructor.

  • Layouts are shared. A RouterLayout that is already attached is not rebuilt when the next view uses the same chain, so its state (an open drawer, a search box) survives navigation.

  • Redirects restart the pipeline. A rerouteTo, forwardTo or rerouteToError call re-enters the matching step with the new target, so guards run again for the redirect target too.

Call Effect

event.rerouteTo(LoginView.class)

Shows the target without changing the URL in the address bar.

event.forwardTo(LoginView.class)

Shows the target and updates the URL (the usual choice for a login redirect).

event.rerouteToError(NotFoundException.class, "message")

Renders the matching error view with that message.

event.postpone() (leave only)

Pauses navigation until action.proceed() is called; the user stays on the page.

UI.navigate(target, QueryParameters)

Navigates and replaces the query string; the same view is reused.

Worked example: a guarded customer editor

The example below combines every moving part of this page on the running customer application: a list view whose filter lives in the URL, an editor addressed by a route template, a guard that rejects unknown ids, and a leave-guard that protects unsaved edits.

The list keeps its filter in a query parameter, so a filtered view can be bookmarked and the browser’s back button restores it. Typing in the field navigates to the same route with a new query string; because the instance is reused, only beforeEnter runs again:

@Route(value = "customers", layout = MainLayout.class)
@PageTitle("Customers")
@PermitAll
public class CustomerListView extends VerticalLayout implements BeforeEnterObserver {

    private final CustomerService service;
    private final TextField filter = new TextField();
    private final Grid<Customer> grid = new Grid<>(Customer.class);

    public CustomerListView(CustomerService service) {
        this.service = service;
        filter.setPlaceholder("Filter by name");
        filter.addValueChangeListener(e -> UI.getCurrent().navigate("customers",
                QueryParameters.simple(Map.of("q", e.getValue()))));
        grid.addItemDoubleClickListener(e -> UI.getCurrent().navigate(
                CustomerEditorView.class,
                new RouteParameters("customerId", String.valueOf(e.getItem().getId()))));
        add(filter, grid);
    }

    @Override
    public void beforeEnter(BeforeEnterEvent event) {
        String q = event.getLocation().getQueryParameters().getSingleParameter("q").orElse("");
        filter.setValue(q);
        grid.setItems(service.findAll().stream()
                .filter(c -> c.getName().toLowerCase().contains(q.toLowerCase())).toList());
    }
}

The editor uses a template with a named parameter. RouteParameters.getLong parses the segment and returns an empty Optional when it is absent or not a number, so one expression covers both a malformed URL and an unknown record:

@Route(value = "customers/:customerId/edit", layout = MainLayout.class)
@RolesAllowed("ADMIN")
public class CustomerEditorView extends VerticalLayout
        implements BeforeEnterObserver, BeforeLeaveObserver, AfterNavigationObserver, HasDynamicTitle {

    private final CustomerService service;
    private final Binder<Customer> binder = new Binder<>(Customer.class);
    private final H2 heading = new H2();
    private final TextField name = new TextField("Name");
    private final EmailField email = new EmailField("Email");
    private Customer customer;

    public CustomerEditorView(CustomerService service) {
        this.service = service;
        binder.forField(name).asRequired().bind(Customer::getName, Customer::setName);
        binder.forField(email).bind(Customer::getEmail, Customer::setEmail);
        Button save = new Button("Save", e -> {
            if (binder.writeBeanIfValid(customer)) {
                service.save(customer);
                binder.readBean(customer);                    // clears the dirty state
                UI.getCurrent().navigate(CustomerListView.class);
            }
        });
        save.addThemeVariants(ButtonVariant.LUMO_PRIMARY);
        add(heading, name, email, save);
    }

    @Override
    public void beforeEnter(BeforeEnterEvent event) {
        customer = event.getRouteParameters().getLong("customerId")
                .flatMap(service::findById).orElse(null);
        if (customer == null) {
            event.rerouteToError(NotFoundException.class, "No such customer");
            return;
        }
        binder.readBean(customer);
    }

    @Override
    public void beforeLeave(BeforeLeaveEvent event) {
        if (binder.hasChanges()) {
            BeforeLeaveEvent.ContinueNavigationAction action = event.postpone();
            new ConfirmDialog("Discard changes?",
                    "Unsaved changes to " + customer.getName() + " will be lost.",
                    "Discard", e -> action.proceed(),
                    "Keep editing", e -> { }).open();
        }
    }

    @Override
    public void afterNavigation(AfterNavigationEvent event) {
        heading.setText("Edit " + customer.getName());
    }

    @Override
    public String getPageTitle() {
        return customer == null ? "Customer" : customer.getName() + " - Customers";
    }
}

CustomerService here is the Spring service from Spring Boot Integration; the signature Optional<Customer> findById(Long) is all the view needs. The Save handler calls readBean after a successful write because Binder.hasChanges() compares against the last bean that was read or written — without that call the leave-guard would still see a dirty form and prompt after a successful save.

The postponed navigation is a small conversation between the router, the view and the dialog. The router does not block: postpone() returns a handle, the leave observer returns, and the navigation resumes only when the user answers:

sequenceDiagram participant U as User participant R as Router participant V as CustomerEditorView participant D as ConfirmDialog U->>R: click a menu entry (navigate away) R->>V: beforeLeave(event) V->>V: binder.hasChanges() V->>R: event.postpone() returns action V->>D: open(...) Note over R: navigation is paused, the editor stays on screen alt user confirms Discard D->>R: action.proceed() R->>R: continue to BeforeEnter of the target else user keeps editing D->>D: close, action is dropped end

Two details are easy to get wrong. The leave observer only fires for navigation inside the application; closing the tab or reloading needs a browser-level beforeunload prompt, which Flow does not provide. And the @RolesAllowed("ADMIN") annotation on the editor is enforced before beforeEnter runs, so an unauthorised user is redirected by the access checker and never reaches the id lookup — see Security.
