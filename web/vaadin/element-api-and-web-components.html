The Element API and Web Components

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Flow’s component classes are wrappers over a server-side representation of DOM elements. When no component exists for what you need — a raw element, a browser API call, or a third-party Web Component — the Element API gives you direct, type-checked access to that DOM from Java. This page follows the Element API guide and Integrating Web Components. It replaces the Vaadin 7 GWT connector / shared-state / RPC widget model.

Working with elements

Every Component exposes getElement(); you can also build elements directly:

Element wrapper = new Element("section");
wrapper.setAttribute("class", "panel");
wrapper.getStyle().set("padding", "var(--lumo-space-m)");
wrapper.setText("Hello");

Element input = new Element("input");
input.setProperty("placeholder", "Search…");   // a JS property, not an attribute
input.setAttribute("type", "search");

wrapper.appendChild(input);
getElement().appendChild(wrapper);

Attributes are strings in HTML; properties are live values on the DOM object. setProperty accepts String, boolean, double and JsonValue. getStyle() sets inline CSS.

Inspecting and editing the element tree

An Element tree is ordinary mutable data, and printing it is the quickest way to see what a component will send to the browser. getOuterHTML() serialises a subtree:

Element wrapper = new Element("section");
wrapper.setAttribute("class", "panel");
wrapper.getStyle().set("padding", "var(--lumo-space-m)");
wrapper.setText("Hello");

Element input = new Element("input");
input.setProperty("placeholder", "Search");
input.setAttribute("type", "search");
wrapper.appendChild(input);

System.out.println(wrapper.getOuterHTML());
// <section style="padding:var(--lumo-space-m)" class="panel">
//  Hello<input type="search">
// </section>

Three details in that output matter:

  • setText creates a child. The text is a text node, so after appendChild(input) the section has two children (getChildCount() == 2). removeAllChildren() removes both and leaves getText() empty.

  • Properties are not attributes. The placeholder set with setProperty does not appear in the markup and getAttribute("placeholder") is null; it exists only as a live property of the browser’s element. Use setAttribute for things CSS selectors or other scripts must see.

  • Equality is by node. input.getParent().equals(wrapper) is true, but two Element objects wrapping the same node are different Java instances, so compare with equals, not ==.

getClassList() edits the class attribute as a set (add, remove, contains, set(name, boolean)), ElementFactory.createDiv("x") and friends shorten common cases, and insertChild(index, element) places a child at a position. Server-side setVisible(false) on an element behaves like it does on a component: the element is not sent to the browser at all.

DOM events

addEventListener wires a server-side listener to a client event; @EventData pulls fields off the event or element into the callback, and setFilter / debounce cut traffic:

input.addEventListener("input", e -> {
    String value = e.getEventData().getString("element.value");
    filter(value);
}).addEventData("element.value").debounce(300);

On a component, @DomEvent maps a custom element event to a typed ComponentEvent:

@DomEvent("selection-change")
public static class SelectionChangeEvent extends ComponentEvent<MyPicker> {
    private final String value;
    public SelectionChangeEvent(MyPicker source, boolean fromClient,
                                @EventData("event.detail.value") String value) {
        super(source, fromClient);
        this.value = value;
    }
}

Calling JavaScript

executeJs(expression, params...) runs a snippet in the element’s context; $0, $1, … are the parameters, and the returned PendingJavaScriptResult resolves with the expression’s value:

getElement().executeJs("return navigator.language").then(String.class, lang ->
        applyLocale(lang));

getElement().executeJs("$0.scrollIntoView({behavior:'smooth'})", target.getElement());

@ClientCallable exposes a server method to client code by name:

@ClientCallable
public void onClientReady(String token) {
    session.setToken(token);
}
// on the client: this.$server.onClientReady(myToken)

See Client-server RPC.

Integrating a Web Component

To use a published custom element, declare its npm package and module and map its tag to a Java class. @NpmPackage adds the dependency; @JsModule imports the module; @Tag binds the element:

@Tag("emoji-picker")
@NpmPackage(value = "emoji-picker-element", version = "1.21.0")
@JsModule("emoji-picker-element/index.js")
public class EmojiPicker extends Component {

    private static final PropertyDescriptor<String, String> LOCALE =
            PropertyDescriptors.propertyWithDefault("locale", "en");

    public void setLocale(String locale) { LOCALE.set(this, locale); }
    public String getLocale() { return LOCALE.get(this); }

    public EmojiPicker() {
        getElement().addEventListener("emoji-click", e -> fireEvent(
                new EmojiSelectedEvent(this, true,
                        e.getEventData().getString("event.detail.unicode"))));
    }
}

PropertyDescriptor gives a typed getter/setter over a DOM property with a default. Reusable behaviour — HasSize, HasStyle, Focusable<T>, or your own — is added through mixin interfaces whose default methods call the Element API, so a component gains setWidth, addClassName, focus() and the like just by implementing them. @CssImport and @JavaScript load a stylesheet or a plain script into the page. getElement().getShadowRoot() (or attachShadow()) reaches a shadow tree when you build one server-side.

Worked example: a Lit star rating

The Vaadin components are Lit-based Web Components, and a small one of your own follows the same recipe: write the element in TypeScript under src/main/frontend, then wrap it with a Java class that maps its property and its event. The element shows max stars, fills the first value of them, and fires a rating-changed event when the user clicks one.

// src/main/frontend/star-rating.ts
import { LitElement, css, html } from 'lit';
import { customElement, property } from 'lit/decorators.js';

@customElement('star-rating')
export class StarRating extends LitElement {
  static override styles = css`
    :host { display: inline-flex; gap: var(--lumo-space-xs, 0.25rem); cursor: pointer; }
    span.on { color: var(--lumo-primary-color, gold); }
  `;

  @property({ type: Number }) value = 0;
  @property({ type: Number }) max = 5;

  private pick(stars: number) {
    this.value = stars;
    this.dispatchEvent(
      new CustomEvent('rating-changed', { detail: { value: stars }, bubbles: true, composed: true })
    );
  }

  override render() {
    return html`${Array.from({ length: this.max }, (_, i) => html`
      <span class=${i < this.value ? 'on' : ''} @click=${() => this.pick(i + 1)}>
        ${i < this.value ? '★' : '☆'}
      </span>`)}`;
  }
}

The Java wrapper extends AbstractSinglePropertyField, which implements HasValue over one element property and needs only the property name, the default value and the DOM event after which the property is synchronised to the server. A PropertyDescriptor exposes the second property, max:

@Tag("star-rating")
@JsModule("./star-rating.ts")
public class StarRating extends AbstractSinglePropertyField<StarRating, Integer>
        implements HasSize, HasStyle {

    private static final PropertyDescriptor<Integer, Integer> MAX =
            PropertyDescriptors.propertyWithDefault("max", 5);

    public StarRating() {
        super("value", 0, false);
        setSynchronizedEvent("rating-changed");     // sync "value" to the server after this event
    }

    public void setMax(int max) { MAX.set(this, max); }
    public int getMax() { return MAX.get(this); }
}

Because the class is a HasValue, it works in a Binder and with addValueChangeListener like any built-in field. Calling setValue(3) and setMax(10) on the server leaves the element with value = 3 and max = 10 as properties, and a value listener sees the change 0 -> 3. The round trip for a click is:

sequenceDiagram participant User participant Lit as star-rating element participant Engine as Client engine participant Server as StarRating (Java) User->>Lit: clicks the third star Lit->>Lit: value = 3, re-render Lit->>Engine: rating-changed CustomEvent Engine->>Server: synchronise property value = 3 Server->>Server: ValueChangeEvent with isFromClient true Server-->>Engine: setValue(5) from server code Engine-->>Lit: property value = 5, re-render

The element’s source type-checks with tsc --strict against Lit 3 with experimentalDecorators enabled. The Vaadin components themselves depend on lit, so the package is already in the project’s node_modules; add an @NpmPackage declaration only to pin a specific version.
