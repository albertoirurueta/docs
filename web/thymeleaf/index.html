Thymeleaf

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This section is written against Thymeleaf 3.1.5 (released 2026-04-21), the version managed by Spring Boot 4.1.1 together with Spring Framework 7.0.9, Thymeleaf Layout Dialect 4.0.1 and htmx-spring-boot 5.2.0 (versions verified on 2026-10-07). Thymeleaf 3.1.5 is the minimum version this section teaches, because 3.1.4 and 3.1.5 together fixed the three 2026 expression-sandbox advisories. Thymeleaf has no formal end-of-life policy: in practice only the 3.1 line receives fixes, the 3.0 and 2.x lines are unsupported, and the project’s open milestones are 3.1.6, 3.2.0 and 4.0, none of them with a date. The Spring integration module is still called thymeleaf-spring6 (there is no thymeleaf-spring7), and it works with Spring Framework 7. Where the books or older tutorials describe different behaviour, the pages say so, and What’s Changed & Migration collects every difference in one place.

What Thymeleaf is

Thymeleaf is a server-side Java template engine for web and standalone environments. Its defining idea is the natural template: a template is a valid HTML file that a browser can open directly as a static prototype, and that Thymeleaf turns into a dynamic page by evaluating attributes such as th:text and th:each on the server. Because the dynamic logic lives in attributes the browser ignores, designers and developers can work on the same files.

A single engine provides:

  • six template modes (HTML, XML, TEXT, JAVASCRIPT, CSS and RAW), template resolvers, a context, and parsed-template and expression caches

  • the Standard Dialect and its Spring flavour, the SpringStandard Dialect, built from attribute, element and model processors, with the Standard Expression language (${...}, *{...}, #{...}, @{...}, ~{...}) and a family of utility objects

  • fragments and, through the community Layout Dialect, layout inheritance

  • inlining for text, JavaScript and CSS, and the textual template modes for emails and generated files

  • integration with Spring MVC and Spring WebFlux, Spring Security (sec:* attributes), Spring’s conversion, validation and message infrastructure

  • an extension model for your own dialects and processors

This section is for developers who:

  • know Java and want to build server-rendered web applications on Spring Boot, with forms, validation, security, internationalization and a maintainable layout system

  • want interactive pages without a single-page application, using fragment rendering, htmx and Alpine.js

  • learned Thymeleaf from older books and tutorials (Spring Boot 2, Thymeleaf 3.0, htmx 1) and need the current idioms

  • are choosing between Thymeleaf and Vaadin, JSF or the template engines of other stacks, and want the trade-offs

Running example

Every example builds one small original application, Bookshelf, in the same domain as the Django, PHP and Laravel and Next.js sections, so that the stacks can be compared page by page. Here it is a Spring Boot 4.1 and Thymeleaf application, the first Java implementation of the scenario:

  • a public catalogue of books, authors and reviews with pagination, sorting and search

  • a shared layout with header, navigation, flash messages and footer, and reusable fragment components

  • create, edit and delete forms with Bean Validation, conversion, cover-image upload and dynamic rows

  • English and Spanish internationalization with a locale switcher

  • sign-in with Spring Security (form login, the roles READER and LIBRARIAN), sec:* attributes and CSRF

  • an htmx-enhanced version: active search, click to load, inline editing, delete with confirmation, out-of-band counters, inline validation and Server-Sent Events notifications

  • loan-reminder emails rendered from HTML and text templates

  • an optional WebFlux variant of the catalogue

  • tests with @WebMvcTest, HtmlUnit and end-to-end tools, Tailwind CSS v4 styling and a container deployment

Figure 1. The Bookshelf application: browser, security filters, Spring MVC controller, service, repository, database, Thymeleaf view layer and static resources

The final project layout (src/main/java packages for book, author, review, security and web, and src/main/resources/templates folders for layout, fragments, books, authors, reviews, error and mail) is assembled on Getting Started.
