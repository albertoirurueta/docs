Expression Utility Objects

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Thymeleaf 3.1.5.RELEASE (2026-04-21), Spring Boot 4.1.1 (Spring Framework 7.0.9) and Java 21, checked on 2026-10-08, and every example was compiled and run on that stack (Maven wrapper, MockMvc against the Bookshelf scratch application, JVM time zone pinned to UTC, request locales en-US and es-ES). Everything on it applies to the Standard Dialect, so it works in all three environments: standalone (plain TemplateEngine), Spring MVC and Spring WebFlux. The few objects that belong to the Spring integration (#fields, #mvc, #themes) and to the Spring Security extras (#authentication, #authorization) are called out in their own section, because they only exist when the corresponding dialect is registered. Layout Dialect, htmx and the other add-ons are not involved.

What utility objects are

An expression object is a name that starts with # and is available inside any variable expression, in addition to the model variables you put in the context. Thymeleaf splits them in two groups. The basic objects (#ctx, which exposes the locale, the variable names and, in a web environment, the web exchange, and #locale) expose the evaluation context itself and are listed on the Standard Expression Syntax page. The utility objects, which this page covers, are stateless helper objects with a method per task: formatting a date, padding a number, testing a string, summing a list. They are the template-side equivalent of a small standard library, and they exist so that presentation logic such as "show the date in the reader’s locale" does not have to be computed in the controller and stored in the model.

Four properties are worth knowing before the method tables:

  • They are plain method calls on a named object, so ${#strings.toUpperCase(name)} is an ordinary variable expression. Used inside *{...}, #{...} arguments, @{...} parameters, th:if conditions and everywhere else an expression is allowed, they behave the same.

  • Most families come in four shapes. A scalar method (format), an array* variant, a list* variant and a set* variant that apply the same operation to every element (arrayFormat, listFormat, setFormat). The tables below name the scalar method and say when the other three exist, instead of repeating them.

  • They are locale-aware only where the table says so. The locale is taken from the context (the request locale in Spring MVC and WebFlux, Context.setLocale standalone), so one template renders differently for en-US and es-ES without any change.

  • Their outputs are escaped like any other value. The examples use th:text, so a & in a result is written as &amp;. A helper such as #strings.escapeXml therefore double-escapes when its result is passed to th:text; see the pitfalls.

The utility objects are implemented by classes in the org.thymeleaf.expression package of thymeleaf core, registered by the Standard Dialect through its expression object factory. The Javadoc of each class is the authoritative method list, and Appendix B of the Using Thymeleaf tutorial is the narrative one.

The scratch application

All outputs below come from one controller that fills the model and one template with a paragraph per example. The domain is the running Bookshelf scenario of this section, with a few extra values (a legacy java.util.Date, a Calendar, a LocalDate, a LocalDateTime and a ZonedDateTime) so that every family has something to work on.

The controller that feeds the examples
@Controller
public class UtilityController {

    @GetMapping("/util")
    public String demo(Model model) {
        model.addAttribute("title", "  the dispossessed  ");
        model.addAttribute("isbn", "978-0-06-051275-4");
        model.addAttribute("price", new BigDecimal("1234.5"));
        model.addAttribute("rating", 0.875);
        model.addAttribute("pages", 7);
        model.addAttribute("published", LocalDate.of(1974, 5, 1));
        model.addAttribute("loanedAt", LocalDateTime.of(2026, 10, 8, 14, 30, 15));
        model.addAttribute("dueAt", ZonedDateTime.of(2026, 10, 22, 9, 0, 0, 0, ZoneId.of("UTC")));
        GregorianCalendar cal = new GregorianCalendar(2026, Calendar.OCTOBER, 8, 14, 30, 15);
        cal.setTimeZone(TimeZone.getTimeZone("UTC"));
        model.addAttribute("calendar", cal);
        model.addAttribute("legacyDate", cal.getTime());
        model.addAttribute("authors", List.of("Le Guin", "Asimov", "Butler", "Asimov"));
        model.addAttribute("tags", new LinkedHashSet<>(List.of("sf", "classic")));
        model.addAttribute("stock", new LinkedHashMap<>(Map.of("dune", 3)));
        model.addAttribute("pageCounts", new int[] {300, 412, 250});
        model.addAttribute("prices", List.of(new BigDecimal("10.00"), new BigDecimal("12.50"), new BigDecimal("7.25")));
        model.addAttribute("nothing", null);
        model.addAttribute("flags", List.of(true, true, false));
        model.addAttribute("unsafeName", "Ursula K. Le Guin/Q&A #1");
        model.addAttribute("quoted", "It's a \"book\"");
        return "util/demo";
    }
}

Source: Spring Boot — Internationalization

Two Boot settings keep the outputs reproducible. By default Boot’s message source falls back to the JVM’s own locale when a bundle has no entry for the requested one; spring.messages.fallback-to-system-locale=false turns that off, so the output depends only on the request. The JVM default time zone decides how a java.util.Date is printed, so the test pins it to UTC.

Execution information: #execInfo

#execInfo describes the template that is currently being processed. It is the one utility object with state, because the answer changes as fragments are inserted. It has two views of the same stack: the leaf template (where the events being processed were parsed) and the root template (the one the engine was originally asked to process).

Expression Result

${#execInfo.templateName}, ${#execInfo.templateMode}

Name and mode of the leaf template

${#execInfo.processedTemplateName}, ${#execInfo.processedTemplateMode}

Name and mode of the root template

${#execInfo.templateNames}, ${#execInfo.templateModes}

Stacks (lists), root first and leaf last, with every inserted fragment’s template in between

${#execInfo.templateStack}

The same stack as a list of TemplateData, with the full metadata of each template
Leaf versus root template across a fragment insertion
<!-- util/demo.html -->
<p id="exec1" th:text="${#execInfo.templateName} + ' / ' + ${#execInfo.templateMode}">x</p>
<div th:insert="~{util/frag :: info}">x</div>
<p id="exec3" th:text="${#execInfo.templateNames}">x</p>

<!-- util/frag.html -->
<p th:fragment="info" id="exec2"
   th:text="${#execInfo.templateName} + ' in ' + ${#execInfo.processedTemplateName}">x</p>
<p id="exec1">util/demo / HTML</p>
<div><p id="exec2">util/frag in util/demo</p></div>
<p id="exec3">[util/demo]</p>

Source: Using Thymeleaf — Execution Info

After the fragment has been inserted, the stack is back to the root template alone, which is why the last line prints one name. The typical use is a debugging footer or an HTML comment showing which template produced a block.

#execInfo is one of the objects that restricted expression mode forbids. In a th:utext attribute (and in the other contexts listed on the Template Security & XSS page) the same expression fails at runtime:

TemplateProcessingException: Access to variable '#execInfo' is forbidden in this context

Source: Using Thymeleaf — Appendix D: Restricted mode, restrictions applied

Messages: #messages

#messages performs the same lookup as the #{...} message expression, but as a method call, so the key can be computed and the result can be post-processed inside a larger expression.

msgOrNull is the way to give a missing key a real fallback. The #{...} syntax is shorter for a fixed key and is preferred there; #messages is for the cases where the key itself is an expression or a collection of keys. URIs: #uris

#uris escapes and unescapes text for use in each part of a URI. The part matters because the set of characters that must be percent-encoded differs between a path, a path segment, a query parameter and a fragment identifier. Every method has an overload that takes the character encoding as a second argument.

Methods Escapes for

escapePath, unescapePath

A whole URI path (the / separators are kept)

escapePathSegment, unescapePathSegment

One segment between slashes (a / is encoded)

escapeFragmentId, unescapeFragmentId

The fragment identifier after #

escapeQueryParam, unescapeQueryParam

A query parameter name or value (& and = are encoded)
The four escapers applied to the same text
<p id="uri1" th:text="${#uris.escapePath(unsafeName)}">x</p>
<p id="uri2" th:text="${#uris.escapePathSegment(unsafeName)}">x</p>
<p id="uri3" th:text="${#uris.escapeQueryParam(unsafeName)}">x</p>
<p id="uri4" th:text="${#uris.escapeFragmentId(unsafeName)}">x</p>
<p id="uri5" th:text="${#uris.unescapeQueryParam('Le%20Guin%26Co')}">x</p>
<a id="uri6" th:href="@{/search(q=${unsafeName})}">x</a>
<p id="uri1">Ursula%20K.%20Le%20Guin/Q&amp;A%20%231</p>
<p id="uri2">Ursula%20K.%20Le%20Guin%2FQ&amp;A%20%231</p>
<p id="uri3">Ursula%20K.%20Le%20Guin/Q%26A%20%231</p>
<p id="uri4">Ursula%20K.%20Le%20Guin/Q&amp;A%20%231</p>
<p id="uri5">Le Guin&amp;Co</p>
<a id="uri6" href="/search?q=Ursula%20K.%20Le%20Guin/Q%26A%20%231">x</a>

Source: Using Thymeleaf — URIs/URLs

Compare the first four lines: only escapePathSegment encodes the slash, and only escapeQueryParam encodes the &. (The & in the first, second and fourth outputs is the HTML escaping that th:text applies to a literal &; the URI escaper left it alone.) The last line shows the better habit: a link expression @{/search(q=${unsafeName})} encodes its parameters for you. Use #uris for the cases a link expression cannot cover, such as building a value for a data-* attribute or an hx-get target string; never concatenate raw user input into a URL. The link expressions and URL rewriting are covered on the Link URLs page.

Conversions: #conversions

#conversions runs the engine’s conversion service at any point of a template, with one method, convert(object, targetClass). The target may be a Class or a class name given as a string. In a Spring application the service is the Spring ConversionService (it is the same one that formats ${{...}}), so every converter and formatter the application registered is available, including the formatters Boot registers for java.time.

Converting with the Spring conversion service
<p id="conv1" th:text="${#conversions.convert('42', 'java.lang.Integer') + 1}">x</p>
<p id="conv2" th:text="${#conversions.convert('2026-10-08', 'java.time.LocalDate')}">x</p>
<p id="conv3" th:text="${{published}}">x</p>
<!-- en-US -->
<p id="conv1">43</p>
<p id="conv2">2026-10-08</p>
<p id="conv3">5/1/74</p>

<!-- es-ES -->
<p id="conv3">1/5/74</p>

Source: Thymeleaf + Spring — The #conversions utility object, Using Thymeleaf — Conversions

The first line shows that the result is a real Integer (it can be added to); the third shows the double-brace form for contrast, whose output follows the request locale. Standalone, without Spring, the service is Thymeleaf’s own standard one, which knows far fewer conversions; the Conversion & Formatting page compares them.

Because the JVM’s default time zone is used to print a Date, two servers in different zones show different wall-clock text for the same instant; set the zone explicitly (a TimeZone on the JVM, or the zoned methods of the next section) when the output must be stable.

Temporals: #temporals (java.time)

#temporals is the java.time counterpart of #dates: it formats LocalDate, LocalDateTime, LocalTime, ZonedDateTime, OffsetDateTime, Instant and the other Temporal types. It is part of thymeleaf core since Thymeleaf 3.1. Before 3.1 it lived in the separate thymeleaf-extras-java8time module (last release 3.0.4), which is still found in older articles and in the books; a 3.1 project does not need it and should not declare it.

Unique identifiers: #ids

Inside an iteration the same id would be repeated for every row, which makes HTML invalid and breaks <label for>. #ids solves that by keeping a counter per name:

  • ${#ids.seq('copy')} returns the name followed by the next counter value (copy1, copy2, …​), for th:id.

  • ${#ids.next('copy')} returns the identifier the next seq call will produce, for a <label> written before its input.

  • ${#ids.prev('copy')} returns the identifier the last seq call produced, for a <label> written after its input.

Checkbox list with matching labels, and the label-first order
<ul id="ids1">
  <li th:each="a : ${authors}">
    <input type="checkbox" th:id="${#ids.seq('author')}">
    <label th:for="${#ids.prev('author')}" th:text="${a}">x</label>
  </li>
</ul>
<div id="ids2"><label th:for="${#ids.next('copy')}">Copy</label><input th:id="${#ids.seq('copy')}"></div>

Additions from Spring Security: #authentication and #authorization

With thymeleaf-extras-springsecurity6 on the classpath (Spring Boot registers its dialect automatically when Spring Security is present) two more expression objects exist, plus the sec:* attributes:

  • #authentication is the Spring Security Authentication of the current request, so ${#authentication.name} is the user name and ${#authentication.authorities} the granted authorities.

Where utility objects run, and restricted mode

Utility objects run during the processing phase, when the engine evaluates the attribute that holds the expression. They need no preprocessing, and a template that uses them stays a natural template: the static prototype keeps the placeholder text (<p th:text="${#temporals.format(published)}">May 1, 1974</p>) and the server replaces it with the computed value.

Most utility objects are also allowed in restricted expression mode, the stricter evaluation used for th:utext, preprocessing __...__, th:on* handlers, fragment names and URL bases (Appendix D of the tutorial lists the contexts). In the scratch run, #strings.toUpperCase(name) and #uris.escapePath(name) evaluate normally inside th:utext, but #execInfo is rejected there, as shown above. The rule of thumb is that restricted mode forbids objects that expose the engine’s internals, request parameters, static access, object instantiation and Spring bean references, and leaves pure value helpers alone. Restricted mode is defence in depth and does not replace validating data; the Template Security & XSS page treats it fully.

Version notes and where the books are outdated

  • #temporals in core. Since Thymeleaf 3.1 #temporals is part of core. Material for 3.0 (older articles and the books) asks for thymeleaf-extras-java8time; that module is frozen at 3.0.4 and is not needed with Thymeleaf 3.1 or Spring Boot 4.

  • Removed request-related basic objects. Thymeleaf 3.1 removed the servlet-bound #request, #response, #session and #servletContext expression objects, and the ${execInfo} variable form. The utility objects of this page are unaffected; #execInfo with the # is the current spelling. See the What’s Changed & Migration page.

  • Package and module names. In the Spring integration the classes behind #fields, #mvc and #themes live in org.thymeleaf.spring6.expression, in thymeleaf-spring6; there is no thymeleaf-spring7 artifact, and Spring Boot 4.1.1 uses thymeleaf-spring6.

  • Books. The Modern frontends with htmx chapter on out-of-band swaps formats dates in a weekly view with #temporals.format. The call is the same today, and on Thymeleaf 3.1 it needs no extra dependency; pass #locale (or a pattern with a locale) when weekday and month names must follow the reader, as shown above.
