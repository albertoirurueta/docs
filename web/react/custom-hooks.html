Custom Hooks

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A custom Hook is a function whose name starts with use and that calls other Hooks. It packages stateful logic so several components can reuse it. Each component that calls the Hook gets its own independent state — a custom Hook shares logic, not state.

Extracting a custom Hook

Move the useState / useEffect / other Hook calls into a useSomething function; return whatever the component needs (a value, a tuple, an object).

import { useState, useCallback } from 'react';

function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn((v) => !v), []);
  return [on, toggle];
}

// usage
function Panel() {
  const [open, toggleOpen] = useToggle();
  return <button onClick={toggleOpen}>{open ? 'Hide' : 'Show'}</button>;
}

Name it for the concept (useFormInput, useChatRoom), not the mechanism (useEffectAndState). Only extract when it removes real duplication or clarifies intent. See Reusing Logic with Custom Hooks.

Worked examples

// useLocalStorage — state mirrored to localStorage
function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    const raw = localStorage.getItem(key);
    return raw != null ? JSON.parse(raw) : initialValue;
  });
  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);
  return [value, setValue];
}

// useDebounce — a value that updates only after it stops changing
function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const t = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(t);
  }, [value, delay]);
  return debounced;
}

// useFetch — minimal data fetch with a race guard
function useFetch(url) {
  const [state, setState] = useState({ data: null, error: null, loading: true });
  useEffect(() => {
    let ignore = false;
    setState((s) => ({ ...s, loading: true }));
    fetch(url)
      .then((r) => r.json())
      .then((data) => !ignore && setState({ data, error: null, loading: false }))
      .catch((error) => !ignore && setState({ data: null, error, loading: false }));
    return () => { ignore = true; };
  }, [url]);
  return state;
}

// useOnlineStatus — subscribe to an external browser store
import { useSyncExternalStore } from 'react';

function useOnlineStatus() {
  return useSyncExternalStore(
    (callback) => {
      window.addEventListener('online', callback);
      window.addEventListener('offline', callback);
      return () => {
        window.removeEventListener('online', callback);
        window.removeEventListener('offline', callback);
      };
    },
    () => navigator.onLine,      // client snapshot
    () => true                   // server snapshot
  );
}

Custom Hooks compose: useFetch could build on useDebounce, a useChatRoom could call useEffectEvent. Pass reactive values (props, state) in as arguments and return reactive values out; keep the Hook body pure just like a component. See useSyncExternalStore.

Deep dive: a Hook shares logic, not state

Each call to a custom Hook creates its own slots in the calling component. Rendering two panels that both use useToggle and clicking the first one gives ['Hide', 'Show']: the two toggles are independent.

(one function, shared code)"] -.-> A1 H -.-> B1

To share state between components, lift it to a common ancestor, put it in context, or use an external store; a Hook then reads from that source. See State Management.

Deep dive: useCart, the storefront’s cart as a Hook

In Core Hooks the cart logic lived in a reducer. Wrapping it in a Hook gives components a small, intention-revealing API and hides the reducer entirely:

import { useReducer, useCallback, useMemo } from 'react';

function cartReducer(items, action) {
  switch (action.type) {
    case 'add':
      return items.some((i) => i.id === action.product.id)
        ? items.map((i) => (i.id === action.product.id ? { ...i, qty: i.qty + 1 } : i))
        : [...items, { ...action.product, qty: 1 }];
    case 'remove':
      return items.filter((i) => i.id !== action.id);
    default:
      throw new Error('Unknown action: ' + action.type);
  }
}

export function useCart() {
  const [items, dispatch] = useReducer(cartReducer, []);
  const add = useCallback((product) => dispatch({ type: 'add', product }), []);
  const remove = useCallback((id) => dispatch({ type: 'remove', id }), []);
  const total = useMemo(() => items.reduce((sum, i) => sum + i.price * i.qty, 0), [items]);
  const count = items.reduce((sum, i) => sum + i.qty, 0);
  return { items, total, count, add, remove };
}

A Hook can be tested without building a component, using renderHook from React Testing Library:

import { renderHook, act } from '@testing-library/react';
import assert from 'node:assert/strict';

const kb = { id: 'kb', name: 'Keyboard', price: 49.9 };
const cart = renderHook(() => useCart());

act(() => { cart.result.current.add(kb); cart.result.current.add(kb); });
assert.equal(cart.result.current.count, 2);
assert.equal(cart.result.current.total.toFixed(2), '99.80');

const addBefore = cart.result.current.add;
act(() => cart.result.current.remove('kb'));
assert.equal(cart.result.current.items.length, 0);
assert.equal(cart.result.current.add, addBefore);   // stable identity: safe in dependency arrays

Design guidelines the example follows: return stable callbacks so consumers can list them as Effect dependencies, derive values (total, count) instead of storing them, and expose operations in the vocabulary of the domain (add, remove) rather than dispatch.

Deep dive: hardening useLocalStorage and useDebounce

The useLocalStorage sketch above works, but real storage can throw (private mode, quota, corrupted JSON). A more robust version with the same signature:

function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const raw = localStorage.getItem(key);
      return raw != null ? JSON.parse(raw) : initialValue;
    } catch {
      return initialValue;          // corrupted JSON or storage unavailable
    }
  });

  useEffect(() => {
    try { localStorage.setItem(key, JSON.stringify(value)); } catch { /* quota or private mode */ }
  }, [key, value]);

  return [value, setValue];
}

Run against jsdom: with [{"id":"kb","qty":2}] already stored, the Hook restores it; after calling the setter the stored string is the new array; and a stored value of {oops falls back to the initial value instead of crashing.

Two caveats. Reading localStorage in the initializer returns the default on the server and the stored value in the browser, so a server-rendered page can mismatch during hydration; either read the value in an Effect after mount, or build the Hook on useSyncExternalStore with a server snapshot. And the storage event lets other tabs notify this tab, which useSyncExternalStore handles naturally.

useDebounce can be demonstrated in a test by changing the value quickly: with a delay of 50 ms, rendering with 'k' then re-rendering with 'ke' and 'key' still returns 'k' immediately, and returns 'key' once the delay has passed, because each change cleared the previous timer.

function SearchBox({ products }) {
  const [query, setQuery] = useState('');
  const debounced = useDebounce(query, 250);
  const results = products.filter((p) => p.name.toLowerCase().includes(debounced.toLowerCase()));
  return (
    <>
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
      <p>{results.length} results</p>
    </>
  );
}

The input stays responsive because query updates on every key press, while the expensive filtering (or a network request in an Effect) follows the debounced value.

Deep dive: useSyncExternalStore

useOnlineStatus subscribes to browser events and reads navigator.onLine as its snapshot. In a test, the Hook first returns true; after setting navigator.onLine to false and dispatching an offline event on window, it returns false. The contract is simple: subscribe registers a callback and returns an unsubscribe function, getSnapshot must return the same value until the store changes (return a cached object, not a new one each time), and the optional third argument supplies the snapshot used while rendering on the server and during hydration. This is the tearing-safe way to read any store that lives outside React — the same primitive state libraries use.
