Template Syntax

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Vue templates are valid HTML extended with interpolations and directives. The compiler turns a template into a render function; at runtime Vue keeps the DOM in sync with the component’s reactive state. This page follows Template Syntax and the built-in directives reference, then covers binding class and style.

The path from template to screen has four stages, and knowing them explains most of the rules below — why an expression must be a single expression, why {{ }} escapes, and why a binding re-evaluates only when something it read changes:

flowchart LR t["template
(HTML + mustaches
+ directives)"] -->|"compiler
(build time)"| rf["render function
(JavaScript)"] rf -->|"runs, reading
reactive state"| vn["virtual DOM
(vnodes)"] vn -->|"patch"| dom["real DOM"] st["reactive state"] -.->|"tracked reads
re-run the render"| rf

With a build step (Vite and @vitejs/plugin-vue) the compile stage happens ahead of time and no compiler ships to the browser. See Rendering, Render Functions, and Web Components for the render pipeline in detail.

Text interpolation

The double-brace mustache syntax inserts a value as plain text. It reacts to changes and is always escaped, so the content is never parsed as HTML.

<template>
  <span>Message: {{ msg }}</span>
  <span>{{ ok ? 'YES' : 'NO' }}</span>
</template>

To skip compilation of a block entirely, use v-pre; to show the raw markup until the component is ready, v-cloak paired with a CSS rule. Both are in the directives reference.

Raw HTML with v-html

{{ }} cannot output real HTML. v-html sets an element’s innerHTML from a string:

<template>
  <div v-html="renderedMarkdown"></div>
</template>
v-html runs whatever markup you give it. Never pass user-supplied or otherwise untrusted content through it — that is a cross-site scripting hole. Sanitize on the server or with a vetted library first, and see Security and Accessibility for the full rules.

Attribute bindings with v-bind

Mustaches do not work inside attributes. Bind an attribute to an expression with v-bind:, almost always written with its : shorthand:

<template>
  <img :src="imageUrl" :alt="imageAlt">
  <a :href="`/users/${user.id}`">Profile</a>
</template>

Boolean attributes. When the bound value is null, undefined or false, Vue removes the attribute entirely; any other value adds it:

<template>
  <button :disabled="isSubmitting">Save</button>
</template>

For attributes that are not boolean, only null and undefined remove the attribute. A false value is written out as the string "false", which is exactly what enumerated attributes such as aria-pressed and draggable need: :aria-pressed="false" renders aria-pressed="false", whereas :aria-pressed="null" renders nothing.

Same-name shorthand. If the attribute and the bound variable share a name, Vue 3.4+ lets you write just :id instead of :id="id".

Dynamic attribute names. Put an expression in square brackets to choose the attribute at runtime:

<template>
  <button :[attrName]="attrValue">Go</button>
</template>

The expression must resolve to a string (or null to bind nothing); it is lower-cased by the browser, so avoid uppercase and whitespace in it.

Binding an object of attributes. v-bind with no argument spreads every own property of an object onto the element — useful for forwarding a bag of props or DOM attributes:

<script setup>
const attrs = { id: 'main', 'data-role': 'panel', tabindex: 0 }
</script>

<template>
  <section v-bind="attrs">...</section>
</template>

Expressions in bindings, and their limits

Each binding holds one JavaScript expression — something that could sit after return. It is evaluated in a sandbox with access to the component’s template scope plus a short allowlist of globals (Math, Date, JSON, and a few more).

<template>
  <p>{{ count + 1 }}</p>
  <p>{{ message.split('').reverse().join('') }}</p>
  <p :class="isActive ? 'on' : 'off'"></p>
</template>

What is not allowed: statements (if, for, variable declarations), flow control (use the ternary operator or a computed property instead), assignment as the whole expression, and arbitrary user globals such as window or fetch. When logic grows past a readable one-liner, move it into an computed property or a method.

Anatomy of a directive

A directive is a template attribute whose name starts with v-. Its value is a single expression, except for a few (v-else, v-pre) that take none. The full grammar:

v-on : click .prevent .once = "handler"
 │      │       │              │
name   argument modifiers      value

  • Name — v-on, v-bind, v-if, v-for, v-model, …​ the directive to apply.

  • Argument — after the colon, names the target: the event for v-on:click, the attribute for v-bind:href, the slot for v-slot:header.

  • Dynamic argument — wrap the argument in square brackets to compute it: v-on:[eventName], v-bind:[attrName].

  • Modifiers — dot-prefixed flags that adjust behaviour: .prevent calls event.preventDefault(), .stop stops propagation, .once detaches after one call, .number / .trim / .lazy shape v-model.

Shorthands

Three directives are common enough to have a one-character form:

Directive Shorthand Example

v-bind:

:

:href="url"  — also :[key]="value"

v-on:

@

@click="onClick" — also @[event]="handler"

v-slot:

#

#header on a <template> inside a component

The shorthands are the idiomatic form; the long v- names appear mostly in documentation.

Binding class

:class accepts more than a string, and its result is merged with any static class on the same element. See Class and Style Bindings.

Object syntax — keys are class names, values decide whether each is present:

<template>
  <div class="card" :class="{ active: isActive, 'is-error': hasError }">...</div>
</template>

Rendered as class="card active" when isActive is truthy and hasError is not. The object can be a reactive object or a computed property returning one.

Array syntax — a list of class names or expressions; nest an object for conditional entries:

<template>
  <div :class="[baseClass, isActive ? 'active' : '', { disabled: isDisabled }]">...</div>
</template>

On a component — a class set by the parent is added to the component’s single root element (it does not replace the classes the component sets on itself). This is part of fallthrough attribute behaviour; with multiple root elements you direct it with :class="$attrs.class".

Binding style

Object syntax — the natural form. Property names may be camelCase or the CSS kebab-case (quoted):

<script setup>
import { ref } from 'vue'
const activeColor = ref('teal')
const fontSize = ref(14)
</script>

<template>
  <p :style="{ color: activeColor, fontSize: fontSize + 'px' }">...</p>
  <p :style="styleObject">bind a whole reactive object</p>
</template>

Auto-prefixing — when a CSS property needs a vendor prefix, Vue adds the right one at runtime after testing the current browser.

Multiple values — give an array for a property and Vue keeps the last value the browser accepts, letting you ship a fallback:

<template>
  <div :style="{ display: ['-webkit-box', '-ms-flexbox', 'flex'] }">...</div>
</template>

Array syntax on :style itself merges several style objects onto one element:

<template>
  <div :style="[baseStyles, overrideStyles]">...</div>
</template>

Worked example: a task card, from template to DOM

The running example is a task list. Its smallest piece is a card that shows a title, marks finished tasks and disables the button once a task is done. The template uses most of what this page covered — interpolation with an expression, :class with an object, an attribute binding, a boolean attribute and an event shorthand:

<template>
  <li class="task" :class="{ done: task.done }" :data-id="task.id">
    <span>{{ task.title.toUpperCase() }}</span>
    <button :disabled="task.done" @click="done(task.id)">Done</button>
  </li>
</template>

Given task = { id: 3, title: 'ship', done: true }, the rendered HTML is:

<li class="task done" data-id="3"><span>SHIP</span><button disabled>Done</button></li>

The static class and the object were merged, done: true added a class, the boolean disabled appeared as a bare attribute, and the @click listener left no trace in the markup.

What the compiler produced

Running the template through @vue/compiler-dom (the same compiler Vite uses) shows the render function that Vue actually executes:

import { compile } from '@vue/compiler-dom'

const { code } = compile(template, { mode: 'module', prefixIdentifiers: true, hoistStatic: true })
console.log(code)
const _hoisted_1 = ["data-id"]
const _hoisted_2 = ["disabled", "onClick"]

export function render(_ctx, _cache) {
  return (_openBlock(), _createElementBlock("li", {
    class: _normalizeClass(["task", { done: _ctx.task.done }]),
    "data-id": _ctx.task.id
  }, [
    _createElementVNode("span", null, _toDisplayString(_ctx.task.title.toUpperCase()), 1 /* TEXT */),
    _createElementVNode("button", {
      disabled: _ctx.task.done,
      onClick: $event => (_ctx.done(_ctx.task.id))
    }, "Done", 8 /* PROPS */, _hoisted_2)
  ], 10 /* CLASS, PROPS */, _hoisted_1))
}

Three things in this output explain the rules of the syntax:

  • Every template expression became ordinary JavaScript with its identifiers prefixed by _ctx.. That is why an expression can use the component’s state and why it cannot use statements: it is pasted into a return.

  • {{ ... }} became _toDisplayString(...), which escapes the value. Interpolation can never inject markup.

  • The numbers (1 /* TEXT */, 8 /* PROPS */, 10 /* CLASS, PROPS */) are patch flags. The compiler knows which parts of the template are dynamic, so on an update Vue compares only the text of the <span>, the disabled and onClick props of the button, and the class and data-id of the <li>. Everything static is skipped, which is the main reason templates are faster than hand-written render functions of the same shape.

Escaping, raw HTML and absent attributes, checked

The behaviour of text, v-html and attribute bindings is easy to confirm with the server renderer, which turns an app into a string without needing a browser:

import { createSSRApp } from 'vue'
import { renderToString } from 'vue/server-renderer'

const app = createSSRApp({
  data: () => ({
    html: '<b>x</b>',
    attrs: { id: 'main', 'data-role': 'panel', tabindex: 0 },
    name: 'title', value: 'T', maybe: null, off: false,
  }),
  template: `
    <div>
      {{ '<i>' }}
      <span v-html="html" />
      <section v-bind="attrs" :[name]="value" :hidden="off" :data-x="maybe" :aria-pressed="false" />
      <p v-once>{{ value }}</p>
    </div>`,
})
console.log(await renderToString(app))
<div>&lt;i&gt;<span><b>x</b></span><section id="main" data-role="panel" tabindex="0" title="T"
aria-pressed="false"></section><p>T</p></div>

(The output is one line; it is wrapped here for width.) Reading it against the template:

  • The mustache printed <i> as the text <i> while v-html emitted real <b>.

  • The bound object spread id, data-role and tabindex, and the dynamic attribute name :[name] became title.

  • :hidden="false" (a boolean attribute) and :data-x="null" produced nothing, while :aria-pressed="false" kept its "false" text.

Other built-in directives at a glance

The directives that belong to the template language itself, beyond the ones covered above and on the pages for conditionals, events and forms:

Directive Purpose

v-text

set an element’s text content from an expression; <span v-text="msg" /> equals <span>{{ msg }}</span>

v-once

render the element and its subtree once; later changes to the state they read are ignored

v-memo

skip re-rendering a subtree while the values in the given array are unchanged — a targeted optimization for very large v-for lists

v-pre

skip compilation, so mustaches in the subtree are shown literally

v-cloak

stays on the element until the app mounts; used with a CSS rule [v-cloak] { display: none } when templates are compiled in the browser

v-show

toggle the CSS display property; see Conditional and List Rendering

v-model

two-way binding on form elements and components; see Form Input Bindings

The authoritative list is the built-in directives reference.

Common mistakes

  • A mustache inside an attribute (<a href="/users/{{ id }}">). Mustaches only work as text; bind the attribute instead, as in the v-bind section above.

  • A statement as an expression ({{ if (ok) { ... } }}). Use the ternary operator or a computed property.

  • Heavy work in the template. {{ items.filter(...).sort(...) }} runs on every render of that component; compute it once with a computed property.

  • Mixed-case dynamic attribute names. In DOM templates the browser lower-cases attribute names, so :[someAttr] is read as :[someattr]; in SFCs this does not apply.

  • v-html with data from users. It is the one binding that bypasses escaping.
