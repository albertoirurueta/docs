Lifecycle Hooks

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Every component instance moves through a fixed sequence: it is created, mounted into the DOM, updated as its reactive state changes, and finally unmounted. Lifecycle hooks run your code at each of those points — fetch data, attach and detach non-Vue listeners, integrate a third-party widget, clear timers. The reference is Lifecycle Hooks and the lifecycle API.

The phases

  • Create. Props are resolved and reactive state and the setup() scope are established. No DOM yet.

  • Mount. Vue creates the DOM nodes and inserts them into the page; afterwards template refs are populated.

  • Update. A reactive dependency used by the render changed, so Vue re-runs the render function and patches the DOM.

  • Unmount. The instance is torn down: its DOM is removed, and its watchers and lifecycle-registered effects are stopped.

Each phase has a before hook that fires just ahead of the work and a completion hook that fires just after.

Registering hooks

In <script setup> (or setup()), import each hook and call it with a callback. The call binds the callback to the current instance, which is why hooks must be called synchronously during setup — never inside await, setTimeout, or a .then().

<script setup>
import {
  onBeforeMount, onMounted,
  onBeforeUpdate, onUpdated,
  onBeforeUnmount, onUnmounted
} from 'vue'

onBeforeMount(() => { /* DOM not created yet */ })
onMounted(() => { /* elements and template refs are ready */ })
onBeforeUpdate(() => { /* state changed, DOM not patched yet */ })
onUpdated(() => { /* DOM back in sync with state */ })
onBeforeUnmount(() => { /* instance still fully functional */ })
onUnmounted(() => { /* detach global listeners, clear intervals */ })
</script>

The same hook can be registered more than once; the callbacks run in registration order. Registering a hook from inside a composable works because the composable is itself called synchronously from setup. See onMounted and Registering Lifecycle Hooks. This does not:

setup() {
  setTimeout(() => {
    // warns: "onMounted is called when there is no active component instance"
    onMounted(() => {})
  })
}

onMounted, onUpdated, and onBeforeUnmount do not run during server-side rendering.

Error and debug hooks

  • onErrorCaptured(fn) — fires when an error propagating from any descendant is caught. It receives (err, instance, info); return false to stop the error propagating further.

  • onRenderTracked(fn) / onRenderTriggered(fn) — development only. tracked fires as each reactive dependency is registered by the render; triggered fires when one of them causes a re-render. Both get a DebuggerEvent, which is how you find out why a component re-rendered.

<script setup>
import { onErrorCaptured, onRenderTriggered } from 'vue'

onErrorCaptured((err, instance, info) => {
  report(err, info)
  return false   // handled here -- do not propagate
})

onRenderTriggered((e) => {
  console.log('re-render triggered by', e.type, e.key)
})
</script>

KeepAlive hooks

A component cached by <KeepAlive> is not unmounted when you navigate away from it — it is deactivated, and activated again when shown. onActivated(fn) and onDeactivated(fn) fire on that transition (and also on the initial mount and final unmount), for the cached component and all its descendants. See Components Basics for <KeepAlive> around <component :is>.

import { onActivated, onDeactivated } from 'vue'

onActivated(() => resumePolling())
onDeactivated(() => pausePolling())

The SSR hook

onServerPrefetch(fn) registers an async function that runs on the server before the component renders; its returned promise is awaited, so the data is present in the server-rendered HTML. Client-only hooks such as onMounted are skipped on the server, so pair it with a client fallback.

import { ref, onServerPrefetch, onMounted } from 'vue'

const data = ref(null)

onServerPrefetch(async () => {
  data.value = await fetchOnServer()   // awaited during SSR
})

onMounted(async () => {
  if (!data.value) data.value = await fetchOnClient()   // hydration fallback
})

Parent and child ordering

Hooks of nested components interleave in a fixed pattern, and it is worth knowing because it decides what is safe to read. Mounting is depth-first: a parent cannot finish mounting until every child it renders has mounted, so by the time a parent’s onMounted runs, the whole subtree is in the DOM. Unmounting mirrors it: the parent starts tearing down first, but it is not "unmounted" until all its children are.

sequenceDiagram participant P as Parent participant C as Child Note over P,C: Mount P->>P: setup, onBeforeMount P->>C: render creates the child C->>C: setup, onBeforeMount C->>C: DOM created, onMounted P->>P: onMounted (child already in the DOM) Note over P,C: Update, parent state changed P->>P: onBeforeUpdate C->>C: updates only if its own props or state changed P->>P: onUpdated Note over P,C: Unmount P->>P: onBeforeUnmount C->>C: onBeforeUnmount C->>C: onUnmounted P->>P: onUnmounted

Logging each hook from a Parent that renders a Child gives exactly this sequence (checked with Vue Test Utils):

mount:    Parent setup | Parent beforeMount | Child setup | Child beforeMount | Child mounted | Parent mounted
update:   Parent beforeUpdate | Parent updated          (Child's props did not change, so it is skipped)
unmount:  Parent beforeUnmount | Child beforeUnmount | Child unmounted | Parent unmounted

Two consequences follow. A parent can safely measure or query child DOM in onMounted, but never in setup(). And a child that needs a resource owned by an ancestor (a socket, a map instance) can rely on the ancestor still being fully alive in the child’s own onBeforeUnmount.

Hooks and await in <script setup>

The "register synchronously" rule has one convenient exception. In <script setup>, the compiler rewrites each top-level await so that the current instance is restored afterwards. Hooks registered after the first await of a <script setup> block therefore still work, provided the component is rendered under <Suspense> (see Async Components):

<script setup>
import { onMounted, ref } from 'vue'

const status = ref('loading')
await Promise.resolve()                        // first await
onMounted(() => { status.value = 'mounted' })  // still bound to this instance
</script>

<template><p>{{ status }}</p></template>

The same call after an await inside a hand-written async setup() function is not rescued and logs the "no active component instance" warning shown earlier. Both behaviours were confirmed by mounting the components under <Suspense>. Treat the exception as a safety net rather than a style: put hook registrations at the top of the block.

Worked example: loading data that cleans up after itself

A to-do list component loads its items when it mounts and must not touch state after the user has left. The pattern pairs onMounted with a cancellation handle released in onBeforeUnmount:

<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'

const todos = ref([])
const error = ref(null)
const controller = new AbortController()

onMounted(async () => {
  try {
    const res = await fetch('/api/todos', { signal: controller.signal })
    todos.value = await res.json()
  } catch (e) {
    if (e.name !== 'AbortError') error.value = e
  }
})

// leaving the page cancels a request that is still in flight
onBeforeUnmount(() => controller.abort())
</script>

<template>
  <p v-if="error" role="alert">Could not load todos</p>
  <ul v-else>
    <li v-for="t in todos" :key="t.id">{{ t.text }}</li>
  </ul>
</template>

A Vitest test with a stubbed fetch verifies both halves: after flushPromises() the list shows the loaded items, and after wrapper.unmount() the request’s AbortSignal reports aborted. When the same logic is needed by several components, move it into a composable that registers the hooks itself — the call is still synchronous from the caller’s setup().

Choosing the right hook

You want to …​ Use

read a template ref or measure the DOM

onMounted

start a timer, listener or subscription

onMounted, undone in onBeforeUnmount or onUnmounted

read the DOM before Vue changes it (for example the scroll position)

onBeforeUpdate

react to a state change with the DOM already updated

watch with flush: 'post', or await nextTick() — not onUpdated

re-run when one reactive value changes

watch, not a hook

run async work during SSR

onServerPrefetch

onUpdated fires after any re-render of the component, so changing state inside it risks an update loop. Prefer a watcher scoped to the value you care about (see Watchers).
