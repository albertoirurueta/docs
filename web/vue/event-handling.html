Event Handling

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Vue listens to DOM events with the v-on directive, almost always written with its @ shorthand. The handler is either an inline expression or a method, and a chain of modifiers absorbs the boilerplate that normally clutters an event callback. The reference for everything on this page is Event Handling.

v-on and the @ shorthand

@click="handler" is shorthand for v-on:click="handler". The name after the colon (or @) is the native DOM event type — click, input, submit, keyup, pointerdown, and so on. Components can also emit their own events; that case is in Component Events and v-model.

<script setup>
import { ref } from 'vue'

const count = ref(0)
</script>

<template>
  <button @click="count++">Add one</button>
  <p>Clicked {{ count }} times</p>
</template>

Inline vs. method handlers

An inline handler is a JavaScript statement — good for something trivial. A method handler is the name of a function (or a property path); Vue calls it with the native event as the only argument. See Method Handlers and Inline Handlers.

<script setup>
import { ref } from 'vue'

const count = ref(0)

function increment(event) {
  count.value++
  console.log(event.currentTarget.tagName) // "BUTTON"
}
</script>

<template>
  <!-- inline: a statement -->
  <button @click="count++">inline</button>

  <!-- method: receives the native event -->
  <button @click="increment">method</button>
</template>

Reaching the native event

In an inline handler the native event is available as the special $event variable; alternatively write an arrow function and name the parameter. Both let you pass extra arguments alongside the event. See Accessing Event Argument in Inline Handlers.

<template>
  <!-- $event -->
  <input @input="text = $event.target.value">

  <!-- arrow function -->
  <input @input="(e) => text = e.target.value">

  <!-- a value plus the event -->
  <button @click="save('draft', $event)">Save</button>
</template>

Event modifiers

Modifiers appended to the event handle the common DOM calls for you, so the method stays about logic. The full set is .stop, .prevent, .self, .capture, .once, and .passive; see Event Modifiers.

<template>
  <!-- event.stopPropagation() -->
  <a @click.stop="onClick">stop</a>

  <!-- event.preventDefault() -->
  <form @submit.prevent="onSubmit">prevent</form>

  <!-- chained: both, in order -->
  <a @click.stop.prevent="onClick">both</a>

  <!-- only when event.target is this element, not a descendant -->
  <div @click.self="onClick">self</div>

  <!-- listener attached in the capture phase -->
  <div @click.capture="onClick">capture</div>

  <!-- fires at most once, then the listener is removed -->
  <button @click.once="onClick">once</button>

  <!-- addEventListener(..., { passive: true }); cannot call preventDefault() -->
  <div @scroll.passive="onScroll">passive</div>
</template>

Modifiers are order-sensitive because the generated code runs in the order written: @click.prevent.self prevents the default on the element and its children, while @click.self.prevent only prevents it when the click is on the element itself.

.passive and .prevent contradict each other — .prevent is ignored on a passive listener and the browser logs a warning. Use .passive for touch and scroll listeners where you never need to cancel the default.

Key modifiers

For keyboard events, a modifier restricts the handler to a key. .enter, .tab, .delete (Delete and Backspace), .esc, .space, .up, .down, .left, and .right are named aliases; any other KeyboardEvent.key value works in kebab-case (@keyup.page-down, @keyup.arrow-up). See Key Modifiers.

<template>
  <input @keyup.enter="submit">
  <input @keyup.esc="clear">
  <input @keyup.page-down="onPageDown">
</template>

System modifier keys

.ctrl, .alt, .shift, and .meta require that modifier key to be held when the event fires. They pair with a key event or a mouse event, and unlike the key aliases they match even if other keys are also down. See System Modifier Keys.

<template>
  <input @keyup.alt.enter="send">
  <div @click.ctrl="onCtrlClick">Ctrl-click me</div>
</template>

.exact

.exact pins down which system modifiers may be pressed — no more, no less. See the .exact modifier.

<template>
  <!-- also fires when Alt or Shift is held too -->
  <button @click.ctrl="onClick">A</button>

  <!-- fires only when Ctrl and no other system modifier is held -->
  <button @click.ctrl.exact="onClick">B</button>

  <!-- fires only when no system modifier at all is held -->
  <button @click.exact="onClick">C</button>
</template>

Mouse-button modifiers

.left, .right, and .middle restrict a mouse handler to a single button. See Mouse Button Modifiers.

<template>
  <button @mousedown.middle="paste">middle-click paste</button>
  <div @click.right="onContextMenu">right-click</div>
</template>

How an event travels

A DOM event does not fire on one element only. It first travels down from the window to the target (the capture phase), is delivered to the target, and then travels back up through every ancestor (the bubble phase). A normal @click listener runs in the bubble phase; .capture moves it to the capture phase, .stop ends the journey, and .self ignores events that were merely passing through.

flowchart TD W["window"] -->|"1 capture: listeners marked .capture run"| Outer["outer element"] Outer -->|"capture continues"| Middle["middle element"] Middle -->|"capture continues"| Target["target: the clicked button"] Target -->|"2 target: its own listeners run"| TB["bubbling starts"] TB -->|"3 bubble: normal listeners run"| Middle2["middle element"] Middle2 -->|"bubble continues unless .stop"| Outer2["outer element"] Outer2 --> W2["document and window"]

The behaviour is easiest to believe when you watch it. The component below logs which listener ran, in order:

<script setup>
import { ref } from 'vue'

const log = ref([])
const note = (msg) => log.value.push(msg)
</script>

<template>
  <div class="outer" @click.capture="note('outer capture')" @click="note('outer bubble')">
    <div class="middle" @click.self="note('middle self')">
      <button class="plain" @click="note('button')">plain</button>
      <button class="stop" @click.stop="note('button (stopped)')">stop</button>
    </div>
  </div>
  <pre>{{ log.join(' | ') }}</pre>
</template>

Clicking the buttons and then the empty space of the middle <div> in order, the log reads:

plain:  outer capture | button | outer bubble
stop:   outer capture | button (stopped)
middle: outer capture | middle self | outer bubble

On the plain button the outer capture listener fires first, then the button, then the outer bubble listener. On the stop button the bubble listener never runs, but the capture listener still did — .stop cannot undo something that happened before the target. Clicking the middle <div> itself fires .self because that is the target, while the same listener stays silent for the button clicks above because their target is a descendant.

Worked example: the todo entry field

Putting several modifiers to work, here is the input that adds todos. Enter submits (the browser’s native form behaviour, so there is no key handler to maintain), Escape clears the field, and a Shift-click is repurposed to shout the text instead of submitting:

<script setup>
import { ref } from 'vue'

const emit = defineEmits(['add'])
const text = ref('')

function submit() {
  const value = text.value.trim()
  if (value) emit('add', value)
  text.value = ''
}
</script>

<template>
  <form @submit.prevent="submit">
    <input v-model="text" placeholder="What needs doing?" @keyup.esc="text = ''" />
    <!-- Enter submits the form natively; Shift-click shouts instead of submitting -->
    <button @click.shift.exact.prevent="text = text.toUpperCase()">Add</button>
  </form>
</template>

@submit.prevent stops the page reload that a form submission would otherwise cause. .shift.exact.prevent on the button runs only when Shift is the only modifier held and cancels the click’s default action — which, for a button in a form, is submitting. A plain click is untouched and submits as usual. Mounted under Vue Test Utils, a shift-click on ' hello ' turns the field into ' HELLO ' without emitting add, a following form submit emits add with 'HELLO', and a keyup with Escape empties the input.

Several statements and listeners

An inline handler can hold more than one statement separated by commas or semicolons, which is handy for two tiny actions, but the moment the logic needs a name, move it into a function:

<template>
  <button @click="count++; log('clicked')">Add</button>
</template>

Listeners are not exclusive: a component may also receive extra @click listeners from its parent through fallthrough attributes, and all of them run. Prefer a method handler for anything that is tested, reused or longer than a statement; the template then reads as a list of what happens and the script says how.

Listeners that clean up after themselves

v-on registers its listener when the element is created and removes it when the element is removed, so you never call removeEventListener for template events. Listeners on something outside the template — window, document, a timer — are your responsibility; register them in onMounted and remove them in onUnmounted, or wrap that pair in a composable.
