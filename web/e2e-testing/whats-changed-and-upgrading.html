What’s Changed and Upgrading

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Browser testing tools move quickly: Playwright ships a minor release roughly every month, Cypress shipped a new major version in September 2026, and Selenium publishes a release every few weeks. This page collects the changes that matter to someone maintaining an existing suite or writing a new one, organised by tool, and for every change it states the version that introduced it, where this section documents it, and what an upgrade needs from you. It is written for Playwright 1.64.1, Cypress 16.2.0 and Selenium 4.51.0, and every version, date and requirement was checked against the official release notes, changelogs and migration guides on 25 October 2026.

Nothing on this page needed a running Bookshelf application. The only commands executed were version checks: in the Playwright example project npx playwright --version printed Version 1.64.1, and in the Cypress example project npx cypress --version reported Cypress package and binary version 16.2.0 (Electron 41.7.0). The migration snippets below come from the official guides and were not run here; the pages linked in the tables contain the examples that were run against Bookshelf. Items on this page that depend on commercial services or on AI products that need accounts or paid keys are described from their official announcements and documentation.

How to approach an upgrade

The same routine works for all three tools, and it keeps the number of simultaneous variables low.

  1. Read the release notes between your version and the target. Skipping versions is allowed for minor releases, but the breaking changes accumulate, so read every version in between. Cypress and the other major-version tools ask for one major at a time: the Cypress 16 migration guide explicitly says to be on 15.x first.

  2. Upgrade the runtime before the tool. Node.js, Python, the JDK and the operating system are the usual blockers; each section below lists the versions that were dropped.

  3. Pin the version. Use an exact version in package.json, pom.xml or requirements.txt, and upgrade deliberately in a dedicated branch. Browser binaries move with the tool (Playwright) or independently of it (Cypress, Selenium), so record the browser versions too.

  4. Run the suite once without changes and read the failures by category. Most upgrade failures come from changed defaults (visibility, headless mode, snapshot behaviour), removed APIs and updated screenshots, not from the tests.

  5. Regenerate visual baselines in a controlled run and review the differences, as described in Visual Regression Testing.

  6. Update the container images and CI actions at the same time, because the browser and the runner must match; see Running in CI/CD.

npx playwright install --with-deps
npx playwright --version

Cypress 15 to 16

Cypress 15.0.0 (August 2025) and 16.0.0 (1 September 2026) are the two majors in this window. Version 16.2.0 was released on 13 October 2026.

Breaking changes in 16.0

The official migration guide lists each change with an "action needed" column; this table follows it.

Change What happens Documented here Upgrade action

Native browser network

Chrome, Chromium and Edge send test traffic over the native browser network, so the application negotiates HTTP/1.1, HTTP/2 or HTTP/3 exactly as in production. Firefox, WebKit and Electron keep the legacy path. req.httpVersion is no longer reported and compression headers and 304 responses behave differently inside cy.intercept().

Network, Stubs, Spies & Clocks

Usually none. Update tests that assert on those fields; forceHttp1: true is a temporary escape hatch that is deprecated at introduction.

Node.js

Node.js 20 and 25 are dropped; 22.x, 24.x or 26.x and later are required. The bundled Node.js moved from 22.19.0 to 24.15.0.

Getting Started

Upgrade the runtime on developer machines and CI before the package.

Cypress.env() removed

Use cy.env() for sensitive values and Cypress.expose() for public values. The env key is invalid in per-test overrides (use expose), and the allowCypressEnv option is gone.

Sessions, Authentication & Cross-Origin, Running in CI/CD

Migrate every call (see the example below). CYPRESS_* variables fill env only, so pass public values with --expose.

cy.exec() and cy.end() removed

Use cy.task() (and taskTimeout) instead of cy.exec(); delete .end() calls.

Getting Started

Register the command as a task in setupNodeEvents.

keystrokeDelay

The default delay in cy.type() changed from 10 to 0 milliseconds.

Core Concepts

Only if a test relied on the delay: set keystrokeDelay: 10 or pass { delay: 10 }.

Visibility

experimentalFastVisibility is replaced by visibilityStrategy, which defaults to 'modern'; 'legacy' is a deprecated escape hatch.

Core Concepts

Rewrite assertions that relied on ancestor overflow clipping, transform-based hiding or coverage by fixed elements.

Browser memory

experimentalMemoryManagement became manageBrowserMemory, on by default.

Debugging, Studio, Plugins & Reporters

If you set the old option to false, replace it with manageBrowserMemory: false; deleting it silently turns the feature on.

Cookie and storage reads

cy.getCookie(), cy.getCookies(), cy.getAllCookies(), cy.getAllLocalStorage() and cy.getAllSessionStorage() are retry-able queries governed by defaultCommandTimeout and can no longer be overwritten with Commands.overwrite().

Queries, Assertions & Custom Commands

Move assertions from .then() to .should(); use overwriteQuery().

Config at run time

viewportWidth, viewportHeight and blockHosts cannot be changed with Cypress.config() during a test.

Core Concepts

Use cy.viewport() or test configuration.

Other removals

experimentalSourceRewriting, built-in CoffeeScript support, and the environment variables printed by cypress info.

Debugging, Studio, Plugins & Reporters

Remove the options; convert .coffee files.

Component testing minimums

Angular 21 (18, 19 and 20 dropped), Vite 8 (5, 6 and 7 dropped), Next.js 15.0.4 (14 dropped). @cypress/angular-zoneless merged into @cypress/angular.

Component Testing

Upgrade the framework tooling first.

Electron deprecated

The bundled Electron browser is deprecated as a test browser and will be removed in a future major version; targeting it prints a warning.

Cross-Browser Testing

Set defaultBrowser or pass --browser chrome now.

The example below is the migration pattern from the official guide, shown with the replacement for a secret and for a public value. It is documentation, not a run.

// Before (Cypress 15): synchronous, everything is serialised into the browser
// const apiKey = Cypress.env('apiKey')

// After (Cypress 16): sensitive values stay in the Node process until requested
it('reads the API key', () => {
  cy.env(['apiKey']).then(({ apiKey }) => {
    expect(Boolean(apiKey)).to.be.true
  })
})

// Public configuration: declare it in the config under `expose`
// and read it synchronously
const apiVersion = Cypress.expose('apiVersion')

Breaking changes in 15.0

If you are still on Cypress 14, upgrade to 15.x first. The 15.0.0 release removed Node.js 18 and 23, Linux distributions with glibc older than 2.31, and Chrome DevTools Protocol automation of Firefox (Firefox is automated with WebDriver BiDi only, which sets a minimum Firefox version). It also removed the three-argument form of cy.stub(), webpack 4 support, Vite 4 and Angular 17 for component testing, renamed Cypress.SelectorPlayground to Cypress.ElementSelector, renamed the code property of cy.exec() to exitCode, dropped the direct-download installation and made @cypress/vite-dev-server ESM-only. Cypress 14 had earlier dropped Node.js 16 and macOS older than 11 and removed open-ct and run-ct.

Selenium 4.x

Selenium has no new major version in this window: the 4.x line continues, and the policy is to deprecate for two releases before removing. The table runs from the Selenium Manager releases that changed how drivers and browsers are obtained up to 4.51.0 (9 October 2026).

JavaScript: the browser atoms are a standalone @selenium/atoms package and the WebSQL and AppCache atoms are gone.

Waits & Expected Conditions, WebDriver BiDi

Search for com.google.common.base.Function in test code that touches ExpectedCondition and switch to the JDK interface.

4.53 (planned)

The removal of the deprecated HttpCommandExecutor fields was postponed from 4.51 to 4.53 to give users more time.

Drivers, Browsers & Options

Use getClientFactory() and the ClientConfig API instead of the fields.

Only code that explicitly typed a variable, field or parameter as Guava’s Function is affected by the 4.51 change; passing the result of an ExpectedConditions factory straight to WebDriverWait.until() or implementing ExpectedCondition with a lambda compiles unchanged.

// Before 4.51: compiled because ExpectedCondition also extended Guava's Function
// com.google.common.base.Function<WebDriver, WebElement> condition = ExpectedConditions.elementToBeClickable(By.id("submit"));

// 4.51 and later: use the JDK interface (the apply method has the same signature)
java.util.function.Function<WebDriver, WebElement> condition =
    ExpectedConditions.elementToBeClickable(By.id("submit"));

Source: Selenium blog: ExpectedCondition Drops Guava’s Function Interface

The Java minimum is the part of the Selenium requirements that is easiest to get wrong. Selenium announced in June 2023 that Java 11 is the minimum for the Java bindings and the Grid, because the default HTTP client moved to the JDK’s built-in client. The 4.50 and 4.51 changelogs announce no higher minimum, and this section’s Maven examples compile with --release 11 and ran on JDK 17, but the documentation’s own requirements wording was not re-read for every binding on the check date, so confirm it on the downloads page before moving a Java 11 runtime. The other bindings state their floors in their package metadata: Python 3.10, Ruby 3.3, Node.js 22 and, for .NET, the net462, netstandard2.0 and net8.0 targets.

Selenium also published a documentation page on driving the browser with AI agents (announced in a blog post of 29 September 2026); it is covered in AI Features in Cypress & Selenium. For the Selenium IDE, which has had no release for about two years, and for the Selenium 3 to 4 migration, see Selenium IDE & Legacy.

Protractor end of life

Protractor, the Angular team’s former end-to-end test runner built on Selenium, is deprecated: the notice on its npm package says it reached end of life by summer 2023, and its last published version, 7.0.0, dates from May 2020. The Angular CLI no longer generates Protractor tests; ng e2e asks which package to add and offers Playwright, Cypress, Nightwatch, WebdriverIO and Puppeteer schematics. With no maintained release, existing Protractor suites should be migrated rather than patched.

  • To keep the WebDriver model, move to Selenium with explicit waits; see Waits & Expected Conditions.

  • To move to a tool with built-in auto-waiting, see Choosing a Tool, which also links Cypress’s migration guide for Protractor users.

  • Translate page objects first, because they are the largest reusable part of a Protractor suite; see Test Design & Page Objects.
