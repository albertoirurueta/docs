This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

The reference material consulted while preparing these pages is listed in the section bibliography.

This page is written against GWT 2.13.1 (released 2026-06-19), gwt-maven-plugin 1.3.0 (net.ltgt.gwt.maven), JDK 21 running the compiler with -sourceLevel 17, the Jakarta Servlet 6 server of the Bookshelf scenario and the gwt-user widget library, checked on 2026-10-08. Everything here is client code: the classes are compiled to JavaScript and run in the browser. The shared and server modules of the Bookshelf do not know about widgets, and the build needs nothing beyond <inherits name="com.google.gwt.user.User"/>, plus com.google.gwt.editor.Editor for the editor integration shown near the end. Every example on this page was compiled with the 2.13.1 compiler, loaded in headless Chrome 155 and driven by dispatching real DOM events; the console output and the error messages are quoted as they were printed, once with assertions enabled (-checkAssertions) and once without. The rating widget also passed two GWTTestCase tests under HtmlUnit.

A widget is a Java object that owns one DOM element and knows how to react to events on it. GWT ships the common ones (buttons, text boxes, lists, tables; see the Widgets page), and an application soon needs one that does not exist: a star rating, a list of removable author names, a label that turns into a text box. There are three strategies, and this page is about the first two.

Composite and initWidget

The Developer Guide gives a first example: a check box that enables or disables a text box, laid out in a vertical panel. Compiled against GWT 2.13.1 exactly as printed, that snippet does not build. javac reported cannot find symbol: class ClickEvent (the snippet imports ClickHandler but never ClickEvent, which its onClick(ClickEvent) needs), and it compiles setChecked and isChecked with [deprecation] warnings, because CheckBox now uses setValue(Boolean) and getValue(). The version below is the same widget with the import and the current API, and it ran in the browser: before the click textBox enabled=true, after a dispatched click on the check box textBox enabled=false, checkbox checked=false.

A composite of a CheckBox and a TextBox (OptionalTextBox.java)
package com.example.bookshelf.client.widget;

import com.google.gwt.event.dom.client.ClickEvent;
import com.google.gwt.event.dom.client.ClickHandler;
import com.google.gwt.user.client.ui.CheckBox;
import com.google.gwt.user.client.ui.Composite;
import com.google.gwt.user.client.ui.TextBox;
import com.google.gwt.user.client.ui.VerticalPanel;

public class OptionalTextBox extends Composite implements ClickHandler {
  private final TextBox textBox = new TextBox();
  private final CheckBox checkBox = new CheckBox();

  public OptionalTextBox(String caption) {
    VerticalPanel panel = new VerticalPanel();
    panel.add(checkBox);
    panel.add(textBox);
    checkBox.setText(caption);
    checkBox.setValue(true);
    checkBox.addClickHandler(this);
    initWidget(panel);               // every composite must call this exactly once
    setStyleName("bk-OptionalTextBox");
  }

  @Override
  public void onClick(ClickEvent event) {
    textBox.setEnabled(checkBox.getValue());
  }

  public String getCaption() {
    return checkBox.getText();
  }

  public void setCaption(String caption) {
    checkBox.setText(caption);
  }
}

Source: GWT Developer Guide — Custom Widgets: Building Composites

What a Composite does

Composite.initWidget(Widget) is protected, takes the widget to wrap, and does five things (read from the 2.13.1 source):

  • it throws if a widget was already set (Composite.initWidget() may only be called once.) or if the argument is null (widget cannot be null)

  • it detaches the new child from any previous parent (widget.removeFromParent())

  • it calls setElement(widget.getElement()), so the composite is the wrapped element

  • it records the wrapped widget and makes the composite its parent (widget.setParent(this))

  • from then on, isAttached(), onAttach(), onDetach() and onBrowserEvent(Event) are delegated to the wrapped widget

The class also keeps the wrapped widget in a private field behind protected Widget getWidget(); the old setWidget(Widget) still exists but is @Deprecated in favour of initWidget. Composite additionally implements IsRenderable, an interface the Javadoc calls "very experimental" and which only UiBinder internals use; you never implement or call it.

The design reason is in the Developer Guide: you could subclass FlowPanel or VerticalPanel to build a new widget, but then every public method of the panel (add, clear, insert and so on) becomes part of your widget’s API, and callers can corrupt its structure. A composite exposes only what you declare. TabPanel (a TabBar plus a DeckPanel), SuggestBox, DisclosurePanel, CaptionPanel, StackLayoutPanel, TabBar, ValueListBox, ValuePicker and the DatePicker of the com.google.gwt.user.datepicker.client package are all composites in the 2.13.1 source.

Resizing composites and lazy widgets

Two small relatives matter inside layout panels:

  • ResizeComposite extends Composite and implements RequiresResize; its initWidget asserts that the wrapped widget is itself a RequiresResize (the assertion message is "ResizeComposite requires that its wrapped widget implement RequiresResize") and its onResize() forwards to it. Use it when the wrapped widget is a layout panel (DockLayoutPanel, SplitLayoutPanel, TabLayoutPanel) and the composite sits inside another layout panel; see the page on panels and layout.

  • LazyPanel extends SimplePanel, is abstract, and builds its child only when it is first made visible: you implement createWidget() and the framework calls it from ensureWidget() or setVisible(true). It suits expensive child widgets in tabs that the user may never open.

Choosing the interfaces to implement

The interfaces carry conventions that the compiler does not check:

  • setValue(v) is setValue(v, false), and only the two-argument form with true fires a ValueChangeEvent. Code that fills a form must not trigger the handlers that react to user edits.

  • Fire with ValueChangeEvent.fireIfNotEqual(this, oldValue, newValue), not fire. The static method compares with equals (null-safe) and stays silent when nothing changed; this is why the value classes below implement equals.

  • Register handlers with addHandler(handler, ValueChangeEvent.getType()). Widget.addHandler is public final, creates the handler manager lazily, and returns the HandlerRegistration that callers use to unregister.

  • getValue of a collection returns a copy (AuthorChips does), or callers can change the widget’s state behind its back and no event fires.

  • Treat null as a value you handle, usually as "empty" (RatingWidget maps it to zero, EditableLabel to the empty string).

The Events & Handlers page explains the handler machinery these conventions sit on.

An editable label

The first widget of the book’s chapter on composites is a label that becomes a text box when clicked; it is a good first composite because it has two states and two parts. This version uses a DeckPanel to show one of its two children, handlers instead of listeners, and implements HasText and HasValue<String>.

EditableLabel.java
public class EditableLabel extends Composite implements HasText, HasValue<String> {
  private static final int VIEW = 0;
  private static final int EDIT = 1;

  private final DeckPanel deck = new DeckPanel();
  private final Label label = new Label();
  private final TextBox box = new TextBox();
  private String value = "";

  public EditableLabel(String text) {
    deck.add(label);
    deck.add(box);
    initWidget(deck);
    setStyleName("bk-EditableLabel");
    label.addClickHandler((ClickEvent e) -> edit());
    box.addBlurHandler((BlurEvent e) -> commit());
    box.addKeyDownHandler((KeyDownEvent e) -> {
      int key = e.getNativeKeyCode();
      if (key == KeyCodes.KEY_ENTER) {
        commit();
      } else if (key == KeyCodes.KEY_ESCAPE) {
        cancel();
      }
    });
    setValue(text);
  }

  private void edit() {
    box.setText(value);
    deck.showWidget(EDIT);
    box.setFocus(true);
    box.selectAll();
  }

  private void commit() {
    if (deck.getVisibleWidget() == EDIT) {
      deck.showWidget(VIEW);
      setValue(box.getText(), true);
    }
  }

  private void cancel() {
    deck.showWidget(VIEW);
  }

  @Override public String getText() { return getValue(); }
  @Override public void setText(String text) { setValue(text); }
  @Override public String getValue() { return value; }
  @Override public void setValue(String v) { setValue(v, false); }

  @Override
  public void setValue(String v, boolean fireEvents) {
    String old = value;
    value = v == null ? "" : v;
    label.setText(value);                 // setText, never setHTML, for user data
    deck.showWidget(VIEW);
    if (fireEvents) {
      ValueChangeEvent.fireIfNotEqual(this, old, value);
    }
  }

  @Override
  public HandlerRegistration addValueChangeHandler(ValueChangeHandler<String> handler) {
    return addHandler(handler, ValueChangeEvent.getType());
  }
}

With a handler that appends the new value to a string, the lab calls setValue("Silent", false), setValue("Silent", true) and setValue("Loud", true) and prints EditableLabel events: [Loud] text=Loud: the first call is silent by contract and the second one fires nothing because the value did not change.

The Bookshelf rating widget

A review in the Bookshelf has a rating from 0 to 5. The widget is a composite of a FocusPanel (it owns the tab stop and receives key events), a FlowPanel and five InlineLabel stars. It implements HasValue<Integer> so that it behaves like any form field, HasEnabled so that a read-only view can disable it, Focusable by delegating to the FocusPanel, and IsEditor so that the editor framework can drive it. ARIA attributes make it a slider for assistive technology: Roles.getSliderRole() from com.google.gwt.aria.client sets role="slider", aria-valuemin, aria-valuemax, aria-valuenow and aria-disabled.

RatingWidget.java
public class RatingWidget extends Composite
    implements HasValue<Integer>, HasEnabled, Focusable, IsEditor<LeafValueEditor<Integer>> {

  public static final int MAX = 5;

  private final FocusPanel focus = new FocusPanel();
  private final InlineLabel[] stars = new InlineLabel[MAX];
  private int value;
  private boolean enabled = true;
  private LeafValueEditor<Integer> editor;

  public RatingWidget() {
    FlowPanel row = new FlowPanel();
    for (int i = 0; i < MAX; i++) {
      final int rating = i + 1;
      InlineLabel star = new InlineLabel();
      star.setStyleName("bk-star");
      star.addClickHandler(e -> {
        if (enabled) {
          setValue(rating, true);
        }
      });
      stars[i] = star;
      row.add(star);
    }
    focus.setWidget(row);
    focus.addKeyDownHandler(e -> {
      if (!enabled) {
        return;
      }
      int key = e.getNativeKeyCode();
      if (key == KeyCodes.KEY_RIGHT || key == KeyCodes.KEY_UP) {
        setValue(value + 1, true);
        e.preventDefault();
      } else if (key == KeyCodes.KEY_LEFT || key == KeyCodes.KEY_DOWN) {
        setValue(value - 1, true);
        e.preventDefault();
      }
    });
    initWidget(focus);
    setStyleName("bk-Rating");
    Roles.getSliderRole().set(getElement());
    Roles.getSliderRole().setAriaValueminProperty(getElement(), 0);
    Roles.getSliderRole().setAriaValuemaxProperty(getElement(), MAX);
    render();
  }

  private void render() {
    for (int i = 0; i < MAX; i++) {
      stars[i].setText(i < value ? "★" : "☆");
    }
    Roles.getSliderRole().setAriaValuenowProperty(getElement(), value);
  }

  @Override public Integer getValue() { return value; }
  @Override public void setValue(Integer v) { setValue(v, false); }

  @Override
  public void setValue(Integer v, boolean fireEvents) {
    Integer old = value;
    value = v == null ? 0 : Math.max(0, Math.min(MAX, v));
    render();
    if (fireEvents) {
      ValueChangeEvent.fireIfNotEqual(this, old, value);
    }
  }

  @Override
  public HandlerRegistration addValueChangeHandler(ValueChangeHandler<Integer> handler) {
    return addHandler(handler, ValueChangeEvent.getType());
  }

  @Override public boolean isEnabled() { return enabled; }

  @Override
  public void setEnabled(boolean enabled) {
    this.enabled = enabled;
    setStyleDependentName("disabled", !enabled);
    Roles.getSliderRole().setAriaDisabledState(getElement(), !enabled);
  }

  @Override public int getTabIndex() { return focus.getTabIndex(); }
  @Override public void setAccessKey(char key) { focus.setAccessKey(key); }
  @Override public void setFocus(boolean focused) { focus.setFocus(focused); }
  @Override public void setTabIndex(int index) { focus.setTabIndex(index); }

  @Override
  public LeafValueEditor<Integer> asEditor() {
    if (editor == null) {
      editor = TakesValueEditor.of(this);
    }
    return editor;
  }
}

Widgets from DOM elements

A composite is the right tool until the markup you need does not exist as a widget. A removable chip (a rounded span with a name and a small remove button) is two elements and one click rule; wrapping it in FlowPanel, Label and Button would work, but it creates three widgets and three elements for one visual. Building it from the DOM is shorter and cheaper, and it shows the mechanism that every GWT widget is built on.

The rules for a widget that extends Widget directly:

  • Create the element and call setElement(Element) exactly once, normally first in the constructor, with the root element of the widget. The element comes from Document.get().createXxxElement(); the dom.client classes are typed overlays, so there are no wrapper objects (see DOM & Elemental2). The setElement(com.google.gwt.user.client.Element) overload is @Deprecated.

  • getElement() returns com.google.gwt.user.client.Element, a subclass of com.google.gwt.dom.client.Element, and its Javadoc says not to override it.

  • Sink the events you handle with sinkEvents(int) and the bit constants of Event (Event.ONCLICK), or register through addDomHandler(handler, ClickEvent.getType()), which sinks the right bit for you. The bits are only recorded until the widget is attached and applied then.

  • Override onBrowserEvent(Event) and call super.onBrowserEvent(event), which dispatches to the handlers registered with addDomHandler. If you do not call super, those handlers silently stop working.

  • Put text in with setInnerText, which sets textContent. Reserve setInnerHTML for markup you built from constants, and use SafeHtml (see SafeHtml & XSS) when HTML must contain data.

Chip.java, a widget made of two DOM elements
public class Chip extends Widget implements HasText, HasCloseHandlers<Chip> {
  private final SpanElement label = Document.get().createSpanElement();
  private final ButtonElement remove = Document.get().createPushButtonElement();

  public Chip(String text) {
    SpanElement root = Document.get().createSpanElement();
    setElement(root);                       // exactly once, before anything else touches the element
    setStyleName("bk-chip");
    label.setClassName("bk-chip-label");
    remove.setClassName("bk-chip-remove");
    remove.setInnerText("×");          // text, not HTML
    root.appendChild(label);
    root.appendChild(remove);
    setText(text);
    sinkEvents(Event.ONCLICK);              // without this bit onBrowserEvent never sees a click
  }

  @Override public String getText() { return label.getInnerText(); }

  @Override
  public void setText(String text) {
    label.setInnerText(text);               // textContent: <script> in an author name stays text
    remove.setTitle("Remove " + text);
  }

  @Override
  public void onBrowserEvent(Event event) {
    super.onBrowserEvent(event);            // keeps handlers added with addDomHandler working
    if (event.getTypeInt() == Event.ONCLICK
        && Element.is(event.getEventTarget())
        && remove.isOrHasChild(Element.as(event.getEventTarget()))) {
      event.stopPropagation();
      CloseEvent.fire(this, this);
    }
  }

  @Override
  public HandlerRegistration addCloseHandler(CloseHandler<Chip> handler) {
    return addHandler(handler, CloseEvent.getType());
  }
}

Source: GWT Developer Guide — Using the DOM

CloseEvent and HasCloseHandlers<T> are the standard "something asked to go away" event from com.google.gwt.event.logical.shared, so the chip does not need an event class of its own. Before the sink bit is set, a click on the widget goes nowhere: the lab built two otherwise identical widgets, one that never called sinkEvents and one that did, dispatched a click on each, and printed click on widget that never sank ONCLICK: clicks=0; with sinkEvents: clicks=1.

The Developer Guide’s third strategy, writing methods in JSNI, is legacy; it names TextBox and TextBoxImpl as the example and advises deferred binding to isolate browser differences. The same advice survives in the 2.13.1 tree as the *Impl classes in com.google.gwt.user.client.ui.impl; for example FocusPanel asks for a FocusImpl, and Focus.gwt.xml replaces it with FocusImplStandard or FocusImplSafari depending on the user.agent permutation (see Deferred Binding & Generators). For new code, reach JavaScript through JsInterop native types (see JsInterop) rather than JSNI (see JSNI & Overlay Types).

The attach and detach callbacks

A widget lives in one of two states: attached (its element is inside the document, reachable from a RootPanel) or detached. The state changes only when an ancestor panel adds or removes the widget, and four callbacks tell the widget about it.

Table 3. The lifecycle methods of Widget (all protected, from the 2.13.1 source)
Method When it runs What to do there

onAttach()

sets the attached flag, installs the event listener, applies the pending sinkEvents bits, attaches children, then calls onLoad() and fires AttachEvent (isAttached() == true)

nothing: override onLoad; if you do override it, call super.onAttach()

onLoad()

after the widget and all its children are attached

start things that need the widget in the document: timers, global listeners, measuring the size

onUnload()

first thing in onDetach(), before anything is torn down

stop what onLoad started; the mirror image of onLoad

onDetach()

calls onUnload, fires AttachEvent (isAttached() == false), detaches children, removes the listener and clears the flag

nothing: override onUnload; if you do override it, call super.onDetach()

addAttachHandler(AttachEvent.Handler) is the non-subclassing alternative, delivering both transitions to an observer. The page DOM & Elemental2 shows the same machinery from the side of event handlers and memory leaks.

The rules that follow from the measurement:

  • Attach runs from the leaves up, detach from the root down. When an outer onLoad runs, every inner widget is already attached and measurable; when an outer onUnload runs, the inner widgets are still intact.

  • Inside onUnload, isAttached() is still true. The flag is cleared at the very end of onDetach (in a finally block).

  • A composite’s isAttached() is the wrapped widget’s, as the source shows, and it is false for a composite that never called initWidget.

Start in onLoad, stop in onUnload

The standard use is a resource that must exist only while the widget is on screen. DueLabel shows the seconds left on a loan and refreshes every second, using the GWT Timer (see Delayed Logic & Scheduler).

DueLabel.java
public class DueLabel extends Label {
  private final Timer ticker = new Timer() {
    @Override
    public void run() {
      refresh();
    }
  };
  private int secondsLeft;

  public DueLabel(int secondsLeft) {
    this.secondsLeft = secondsLeft;
    refresh();
  }

  private void refresh() {
    setText(secondsLeft-- > 0 ? "due in " + (secondsLeft + 1) + " s" : "overdue");
  }

  @Override
  protected void onLoad() {
    super.onLoad();
    ticker.scheduleRepeating(1000);        // start when the widget enters the document ...
  }

  @Override
  protected void onUnload() {
    ticker.cancel();                       // ... and stop when it leaves
    super.onUnload();
  }
}

Writing a new panel

The book’s chapter on panels ends with writing your own. A panel is a widget that owns child widgets, and ComplexPanel already implements the bookkeeping, so a new panel is often a dozen lines. ChipPanel puts its children one after another inside a single div:

ChipPanel.java
public class ChipPanel extends ComplexPanel {
  public ChipPanel() {
    setElement(Document.get().createDivElement());
    setStyleName("bk-chips");
  }

  @Override
  public void add(Widget child) {
    add(child, getElement());               // detaches from the old parent, adds to the DOM, adopts
  }

  public void insert(Widget child, int beforeIndex) {
    insert(child, getElement(), beforeIndex, true);
  }
}

Source: GWT Developer Guide — Panels

What the class hierarchy supplies:

  • Panel implements HasWidgets.ForIsWidget (add(IsWidget), remove(IsWidget), clear(), iterator()) and provides the two final methods every panel uses to maintain the parent link, adopt(Widget) and orphan(Widget), plus doAttachChildren and doDetachChildren, which attach and detach all children through an AttachDetachException command so that one failing child does not strand the others.

  • ComplexPanel implements IndexedPanel.ForIsWidget (getWidget(int), getWidgetCount(), getWidgetIndex(Widget), remove(int)), keeps the children in a WidgetCollection, and offers the two protected helpers used above. add(child, container) removes the child from its previous parent first, adds it to the collection, appends its element to the container element and calls adopt. insert(child, container, beforeIndex, domInsert) does the same at an index.

  • remove(Widget) of ComplexPanel returns false for a widget that is not a child, orphans the child (which detaches it when the panel is attached), removes its element from the parent element and takes it out of the collection.

  • The container element does not have to be the panel’s own element: HorizontalPanel creates a table cell for each child and passes that cell to add(child, container). A panel with several containers repeats the same call per container.

A panel that holds exactly one child extends SimplePanel instead and implements HasOneWidget; a panel that lays out with CSS layout (LayoutPanel, DockLayoutPanel) additionally implements RequiresResize or ProvidesResize. If the panel does not override add(Widget), Panel.add throws, which the lab confirmed with a ComplexPanel subclass that forgot it: java.lang.UnsupportedOperationException: This panel does not support no-arg add().

The lab also added the same widget to two panels in a row. ComplexPanel.add(child, container) calls child.removeFromParent() first, so the widget moved: in a: 0, in b: 1. A widget never has two parents, and adding it somewhere else is a move, not an error.

The Bookshelf author chips

The authors of a book are an ordered list of names. The widget has to show them as chips, let the user add one with the Enter key, remove one with its button, and report changes like any HasValue. It is a composite of the custom ChipPanel and a TextBox, so it combines everything above: a composite, a custom panel and custom widgets.

AuthorChips.java
public class AuthorChips extends Composite
    implements HasValue<List<String>>, HasEnabled, IsEditor<LeafValueEditor<List<String>>> {

  private final ChipPanel chips = new ChipPanel();
  private final TextBox input = new TextBox();
  private final List<String> authors = new ArrayList<>();
  private LeafValueEditor<List<String>> editor;

  public AuthorChips() {
    FlowPanel root = new FlowPanel();
    root.add(chips);
    root.add(input);
    initWidget(root);
    setStyleName("bk-AuthorChips");
    input.getElement().setAttribute("placeholder", "Add an author");
    input.addKeyDownHandler(e -> {
      if (e.getNativeKeyCode() == KeyCodes.KEY_ENTER) {
        add(input.getText().trim());
        input.setText("");
      }
    });
  }

  private void add(String name) {
    if (name.isEmpty() || authors.contains(name)) {
      return;
    }
    List<String> old = getValue();
    addChip(name);
    authors.add(name);
    ValueChangeEvent.fireIfNotEqual(this, old, getValue());
  }

  private void addChip(String name) {
    final Chip chip = new Chip(name);
    chip.addCloseHandler(e -> {
      List<String> old = getValue();
      authors.remove(chip.getText());
      chips.remove(chip);
      ValueChangeEvent.fireIfNotEqual(this, old, getValue());
    });
    chips.add(chip);
  }

  @Override public List<String> getValue() { return new ArrayList<>(authors); }   // defensive copy
  @Override public void setValue(List<String> v) { setValue(v, false); }

  @Override
  public void setValue(List<String> v, boolean fireEvents) {
    List<String> old = getValue();
    authors.clear();
    chips.clear();
    if (v != null) {
      for (String name : v) {
        authors.add(name);
        addChip(name);
      }
    }
    if (fireEvents) {
      ValueChangeEvent.fireIfNotEqual(this, old, getValue());
    }
  }

  @Override
  public HandlerRegistration addValueChangeHandler(ValueChangeHandler<List<String>> handler) {
    return addHandler(handler, ValueChangeEvent.getType());
  }

  @Override public boolean isEnabled() { return input.isEnabled(); }
  @Override public void setEnabled(boolean enabled) { input.setEnabled(enabled); }

  @Override
  public LeafValueEditor<List<String>> asEditor() {
    if (editor == null) {
      editor = TakesValueEditor.of(this);
    }
    return editor;
  }
}

Composites of composites

The book’s chapter on composites ends by assembling a colour picker from two slider composites and a few ordinary widgets. The same idea in the Bookshelf is the review box: a RatingWidget (a composite), a TextArea and a Button in a VerticalPanel, wrapped by one more composite that exposes a single value, a Review.

ReviewBox.java
public class ReviewBox extends Composite implements HasValue<ReviewBox.Review> {

  /** Immutable, with equals so that fireIfNotEqual works. */
  public static final class Review {
    private final int rating;
    private final String text;

    public Review(int rating, String text) {
      this.rating = rating;
      this.text = text;
    }

    public int getRating() { return rating; }
    public String getText() { return text; }

    @Override
    public boolean equals(Object o) {
      return o instanceof Review && ((Review) o).rating == rating && ((Review) o).text.equals(text);
    }

    @Override public int hashCode() { return 31 * rating + text.hashCode(); }
  }

  private final RatingWidget rating = new RatingWidget();
  private final TextArea text = new TextArea();
  private final Button save = new Button("Save review");
  private Review value = new Review(0, "");

  public ReviewBox() {
    VerticalPanel panel = new VerticalPanel();
    panel.add(rating);
    panel.add(text);
    panel.add(save);
    initWidget(panel);
    setStyleName("bk-ReviewBox");
    save.addClickHandler(e -> setValue(new Review(rating.getValue(), text.getText()), true));
  }

  @Override public Review getValue() { return value; }
  @Override public void setValue(Review v) { setValue(v, false); }

  @Override
  public void setValue(Review v, boolean fireEvents) {
    Review old = value;
    value = v == null ? new Review(0, "") : v;
    rating.setValue(value.getRating());
    text.setText(value.getText());
    if (fireEvents) {
      ValueChangeEvent.fireIfNotEqual(this, old, value);
    }
  }

  @Override
  public HandlerRegistration addValueChangeHandler(ValueChangeHandler<Review> handler) {
    return addHandler(handler, ValueChangeEvent.getType());
  }
}

One event for two operations (the click on Save changed nothing), and the element of the composite is the table of the VerticalPanel. Three consequences of composing composites:

  • Events reach the outer composite. A ClickHandler added to the ReviewBox with addDomHandler(handler, ClickEvent.getType()) saw a click that was dispatched on the inner Save button, because the click bubbles to the shared element: the lab printed ClickHandler on the composite sees a click on its inner Save button: 1. Composite.onBrowserEvent first fires the handlers registered on the composite and then delegates to the wrapped widget.

  • Each level adds a level of delegation, not of DOM. Three nested composites around one panel cost three Java objects and one element.

  • Expose one value, not the parts. Callers of ReviewBox see Review; the rating widget, the text area and the button stay private, so you can replace the stars with a slider without touching any caller.

What changed recently

  • GWT 1.1.0 (RC): the release notes announce that composites "must now call initWidget() in their constructors, rather than setWidget()", and Composite.setWidget has been deprecated since; it still exists in the 2.13.1 source.

  • GWT 2.8.0: Java 8 syntax, so the lambdas used for handlers on this page compile with -sourceLevel 8 or later; the examples were built with -sourceLevel 17.

  • GWT 2.12.0: the browser unload event is deprecated, and with it Window.addCloseHandler and RootPanel.detachOnWindowClose; a widget should be released with removeFromParent(), and onUnload is the place to drop registrations (see DOM & Elemental2).

  • GWT 2.9.0 to 2.13.1: the release notes do not mention Composite, ComplexPanel, onLoad or the attach lifecycle, so the code and the messages on this page are the 2.13.1 source behaviour, measured.

  • org.gwtproject.* (the J2CL-ready modules such as gwt-dom and gwt-event) has only release candidates on Maven Central, and the gwt-user widget library is not part of it: custom widgets based on Composite are GWT code that J2CL does not compile (see J2CL & the Future).
