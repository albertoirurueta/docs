Typography

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Text utilities set every common property of type: family, size, weight, spacing, colour, decoration, and wrapping. Values come from the --font-*, --text-*, and --font-weight-* theme namespaces, so text-lg, font-semibold, and font-sans all exist only because the theme defines them. The full per-utility reference starts at Font Family.

Font family, size, weight, and style

<p class="font-sans">System UI sans stack</p>
<p class="font-serif">Serif stack</p>
<code class="font-mono">Monospace stack</code>

<!-- size utilities pair a font-size with a sensible line-height -->
<p class="text-xs">12px</p>
<p class="text-base">16px (default)</p>
<h1 class="text-4xl">36px</h1>
<h1 class="text-6xl/tight">override the paired line-height inline</h1>

<!-- weight, style, smoothing -->
<p class="font-thin">100</p>
<p class="font-normal">400</p>
<p class="font-bold">700</p>
<p class="font-black">900</p>
<em class="not-italic">reset italic</em>
<p class="antialiased">smoother rendering on macOS/iOS</p>

<!-- width axis (variable fonts) and numeric variants -->
<p class="font-stretch-condensed">condensed</p>
<table class="tabular-nums">columns of figures line up</table>
<p class="slashed-zero oldstyle-nums">0 1 2 3</p>

text-* sizes run text-xs through text-9xl; each carries a default line-height you can override with the text-lg/7 slash syntax. See Font Size and Font Weight.

The official plugins

Two first-party plugins cover the gaps utilities leave. In v4 you register a plugin from CSS with @plugin:

@import "tailwindcss";
@plugin "@tailwindcss/typography";
@plugin "@tailwindcss/forms";

@tailwindcss/typography adds the prose classes for styling HTML you do not control — rendered Markdown, CMS output — in one shot:

<article class="prose prose-lg dark:prose-invert prose-headings:font-semibold prose-a:text-sky-600">
  <!-- raw <h2>, <p>, <ul>, <blockquote>, <pre> from a Markdown renderer -->
</article>

@tailwindcss/forms resets input, select, textarea, checkboxes, and radios to a consistent, utility-friendly baseline so rounded, border-gray-300, and focus:ring behave the same across browsers.

Worked example: the Acme hero headline and lead

The hero of the running example (see Building a Page with Utilities) is mostly typography. Its headline and lead paragraph, written with the utilities above, with a brand font installed through the theme:

@import "tailwindcss";

@font-face {
  font-family: "Satoshi";
  src: url("/fonts/Satoshi-Variable.woff2") format("woff2");
  font-weight: 300 900;
  font-display: swap;
}

@theme {
  --font-display: "Satoshi", ui-sans-serif, system-ui, sans-serif;
}
<section class="mx-auto max-w-3xl px-6 py-16 text-center">
  <h1 class="font-display text-5xl/none font-extrabold tracking-tight text-balance sm:text-6xl">
    Ship your site faster
  </h1>
  <p class="mx-auto mt-6 max-w-2xl text-lg/8 text-pretty text-gray-600 dark:text-gray-400">
    Utility-first CSS, no context switching. Write the styles where you read the markup, and
    ship only the rules your pages actually use.
  </p>
</section>

Reading the headline’s classes in the order the browser applies them: @font-face makes the font available and --font-display creates the font-display utility (the name is the variable’s name without --font-), while the stack after the first font lists fallbacks for the moment before the file loads. text-5xl/none sets the size from the scale and a line-height of 1, which is right for a short display line; sm:text-6xl then makes it larger from the sm breakpoint with its own paired line height. tracking-tight pulls the letters closer, which suits large sizes, and text-balance makes the browser even out the line lengths of a wrapped headline instead of leaving a one-word last line.

The lead uses text-lg/8 (1.125rem on a 2rem line height), text-pretty to avoid orphans, and a colour pair for light and dark mode. Using max-w-2xl with mx-auto caps the measure so lines do not become uncomfortably long on a wide screen. All of these utilities, plus the font-display and --font-display pair, build as written with Tailwind 4.3.

flowchart TD HTML["html: Preflight line-height 1.5, system font stack"] --> BODY["body: inherits"] BODY --> SEC["section: text-center is inherited by children"] SEC --> H1["h1: Preflight inherits size and weight, utilities override them"] SEC --> P["p: text-lg/8 and text-gray-600 set locally"] H1 --> FONT["font-display replaces the inherited family"]

Text properties such as font-family, color, text-align, line-height and letter-spacing are inherited through the document tree, which is the reason the example puts text-center on the section rather than on each child, and why a body-level font-sans text-gray-900 styles an entire page. Properties such as margin or padding are not inherited, so they have to be written on each element that needs them.

Choosing a size scale

The default text-* sizes are a type scale with a paired line height, so most pages pick three or four steps and keep to them rather than inventing sizes: for the Acme page, text-sm for card copy, text-base for body, text-lg for the lead, and text-4xl / text-5xl for headlines. If the design calls for another step, add it once with --text-hero: 4rem; and --text-hero--line-height: 1.05; in @theme and use text-hero everywhere, instead of repeating text-[4rem] in several places.

@theme {
  --text-hero: 4rem;
  --text-hero--line-height: 1.05;
}

Truncating copy in a card

Long titles are the common way to break a card grid. Use truncate for one line and line-clamp-N for several, and remember that truncation hides content from sighted users only: keep the full text in the markup and consider a title attribute or a link to the full item.

<article class="rounded-xl border border-gray-200 p-6">
  <h3 class="truncate font-semibold">A feature title that is much too long to fit on a single line of the card</h3>
  <p class="mt-2 line-clamp-3 text-sm/6 text-gray-600">
    Only the CSS you use is generated, so a production stylesheet stays small however many utilities exist in the
    framework, and nothing is shipped for classes that no template mentions.
  </p>
</article>

Styling content you do not control

Headings and paragraphs coming from Markdown or a CMS carry no classes, and Preflight has removed their default look, so they appear flat. The typography plugin supplies that styling under one wrapper class, and prose-invert flips it for dark mode:

<article class="prose prose-lg dark:prose-invert prose-a:text-sky-600">
  <h1>Release notes</h1>
  <p>Rendered Markdown from the server, with no classes on any element.</p>
</article>

With @plugin "@tailwindcss/typography"; in the CSS, the .prose rule applies max-width: 65ch and a full typographic style to the plain elements it contains. Use not-prose on a child (for example an embedded component) to opt that subtree out. In Tailwind 3 plugins were listed in tailwind.config.js; in v4 the @plugin directive shown above replaces that list.
