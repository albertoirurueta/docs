Backgrounds, Borders, and Effects

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

These three families decorate the box: what fills it, what frames it, and what floats above it. Several defaults changed in v4 — the border and ring colours especially — and this page flags each one. See Background Color, Border Width, and Box Shadow.

Backgrounds

<div class="bg-sky-500">solid colour</div>
<div class="bg-sky-500/20">20% opacity via the / modifier</div>

<!-- image, size, position, repeat, attachment -->
<div class="bg-[url(/hero.jpg)] bg-cover bg-center bg-no-repeat">covers the box</div>
<div class="bg-[url(/dots.svg)] bg-repeat-x bg-local">scrolls with content</div>

<!-- clip the background to the text -->
<h1 class="bg-linear-to-r from-sky-500 to-indigo-500 bg-clip-text text-transparent">gradient text</h1>

Gradients

<div class="bg-linear-to-r  from-sky-500 to-indigo-500"></div>
<div class="bg-linear-65    from-pink-500 via-red-500 to-yellow-500"></div>
<div class="bg-radial        from-white to-slate-200"></div>
<div class="bg-conic         from-sky-500 via-indigo-500 to-sky-500"></div>

<!-- stop positions, and stops that survive a variant override -->
<div class="bg-linear-to-r from-sky-500 from-30% to-indigo-500 dark:from-slate-700 dark:to-black"></div>

In v4 the direction utility is bg-linear-to-* (v3 called it bg-gradient-to-*). See Background Image.

Borders

<!-- width: all sides, one axis, one side -->
<div class="border">1px on all sides</div>
<div class="border-2 border-x-4 border-t-0">mixed widths</div>

<!-- colour: v4's default is currentColor, so always set one -->
<div class="border border-gray-300">visible grey frame</div>

<div class="border border-dashed"></div>

<!-- radius: `rounded` == `rounded-sm` in v4; the old `rounded-sm` is now `rounded-xs` -->
<div class="rounded-xl">large radius</div>
<div class="rounded-t-lg rounded-br-none">per-corner</div>
<div class="rounded-full">pill / circle</div>

<!-- dividers between children -->
<ul class="divide-y divide-gray-200">
  <li class="py-2">a</li><li class="py-2">b</li>
</ul>

The default border-color and divide-color are now currentColor, not gray-200. A bare border with no border-* colour picks up the element’s text colour. Always pair border with an explicit colour utility.

Outline and ring

<!-- outline (does not affect layout, follows border-radius) -->
<button class="outline outline-2 outline-offset-2 outline-sky-500 focus-visible:outline-4">Focus me</button>

<!-- outline-hidden replaces v3's outline-none (it keeps a transparent outline for forced-colors) -->
<input class="outline-hidden focus:outline-2 focus:outline-sky-500" />

<!-- ring: a box-shadow-based outline. In v4 `ring` is 1px and currentColor
     (v3: 3px + blue-500). Use ring-2 / ring-sky-500 explicitly. -->
<button class="ring-2 ring-sky-500 ring-offset-2 ring-offset-white">ringed</button>
<div class="inset-ring-2 inset-ring-white/20">inset ring</div>

See Outline and Ring.

Effects

<!-- box shadow: xs .. 2xl, plus coloured and inset -->
<div class="shadow-sm">subtle</div>
<div class="shadow-lg shadow-sky-500/30">coloured</div>
<div class="inset-shadow-sm">inset</div>

<!-- text shadow (new in v4) -->
<h1 class="text-shadow-lg text-shadow-sky-500/40">raised heading</h1>

<!-- opacity, blend modes -->
<img class="opacity-75" />
<div class="mix-blend-multiply">blends with siblings</div>
<div class="bg-[url(/x.jpg)] bg-blend-overlay bg-sky-500"></div>

<!-- mask utilities (new in v4): fade an element with a gradient mask -->
<img class="mask-b-from-50% mask-b-to-90%" />
<div class="mask-[url(/shape.svg)] mask-contain mask-center"></div>

In v4 shadow renamed down a step: the old shadow-sm is now shadow-xs, and the old shadow is shadow-sm (same shift for drop-shadow, blur, rounded, backdrop-blur). See Mask and Text Shadow.

Worked example: polishing the Acme call to action and cards

The plain buttons and cards of the running example (see Building a Page with Utilities) become finished UI with a handful of this page’s utilities. The call-to-action gets a gradient, a coloured glow and a focus outline; the card list gets a hairline ring instead of a border, dividers and a soft shadow; the headline gets a gradient fill.

<a href="/start"
   class="inline-block rounded-md bg-linear-to-r from-sky-500 to-indigo-500 px-5 py-2.5 font-semibold text-white
          shadow-lg shadow-sky-500/25 ring-1 ring-white/20 ring-inset
          hover:brightness-110
          focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-600">
  Get started
</a>

<ul class="divide-y divide-gray-200 rounded-xl shadow-sm ring-1 ring-gray-900/5">
  <li class="p-6">Fast</li>
  <li class="p-6">Small</li>
  <li class="p-6">Simple</li>
</ul>

<h2 class="bg-linear-to-r from-sky-500 to-indigo-500 bg-clip-text text-4xl font-extrabold text-transparent">
  Ship your site faster
</h2>

Taking the pieces in turn:

  • bg-linear-to-r from-sky-500 to-indigo-500 builds a linear-gradient from three variables set by from-*, via-* and to-*. An interpolation-space suffix chooses how colours blend: bg-linear-to-r/oklch produces a gradient in oklch, which avoids the muddy grey midpoint that sRGB interpolation gives between some hues.

  • shadow-lg shadow-sky-500/25 is two classes with two jobs: shadow-lg sets the geometry of the shadow and shadow-sky-500/25 sets only its colour (25% of the sky colour), so the same size can be re-coloured freely.

  • ring-1 ring-white/20 ring-inset draws a 1px translucent line inside the button, which makes a lighter edge that suits a gradient fill. Without ring-inset the ring draws outside the box.

  • divide-y puts a 1px top border on every list item except the first, which is why the list needs no per-item border classes; ring-1 ring-gray-900/5 draws a very faint outline that does not change the box’s size, unlike border.

  • bg-clip-text text-transparent clips the gradient to the glyph shapes and makes the text fill transparent so the gradient shows through.

Every class above builds with Tailwind 4.3, including the /oklch form.

How the shadow, ring and inset utilities combine

shadow-*, ring-*, inset-shadow-* and inset-ring-* do not conflict even though they all end up in the box-shadow property: each sets its own custom property, and the box-shadow of any of them lists all five layers. That is why a button can carry a shadow and a ring at once, and why hover:shadow-lg does not discard an existing ring-1.

flowchart TD BS["box-shadow = five layers, painted top to bottom"] --> L1["inset-shadow-*: inside, over the background"] BS --> L2["inset-ring-*: inside edge line"] BS --> L3["ring-offset: gap between element and ring"] BS --> L4["ring-*: outside edge line"] BS --> L5["shadow-*: soft drop shadow, behind everything"]

An unset layer is empty, so a plain ring-1 contributes just one layer. Since the two inset layers are drawn inside the border box, they sit on top of a bg-* colour or gradient, while the outer layers are painted outside it.

The order a box is painted

Knowing the paint order explains several surprises: why a border takes space but a ring does not, why a gradient shows behind the border, and why opacity on a parent fades every layer, children included, whereas a bg-black/50 colour modifier fades only that one background.

flowchart LR SH["outer shadow and ring"] --> BGL["background colour, then image or gradient"] BGL --> INS["inset shadow and inset ring, inside the padding edge"] INS --> BRD["border"] BRD --> CNT["content: text, images, children"]

Use opacity-* (or bg-* with a / modifier when only the fill should be translucent) and mix-blend-* on the element deliberately: either one creates a stacking context, so they interact with z-* like the cases in Layout.
