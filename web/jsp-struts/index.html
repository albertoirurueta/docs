JSP & Struts

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This section is written against Jakarta Pages 4.0, Jakarta Expression Language 6.0, Jakarta Standard Tag Library 3.0 (API 3.0.2, implementation 3.0.1) and Jakarta Servlet 6.1, running on Apache Tomcat 11.0.26 and Java 21, and against Apache Struts 7.4.0 (released 2026-10-02), with Spring Framework 7.0.9 and Spring Boot 4.1.1 where Spring is involved. The versions were verified on 2026-10-08, and the examples were built into WARs and run on Tomcat 11.0.26 with curl. Where the four books this section consulted, or older tutorials, describe different behaviour, the pages say so, and What’s Changed & Migration collects every difference in one place.

What JSP, EL, JSTL and Struts are

Jakarta Pages (JSP, JavaServer Pages) turns a text document with embedded dynamic elements into a servlet: the container translates the page once, compiles it, and runs the generated class for every request. Jakarta Expression Language (EL) is the small language inside ${...} and #{...} that reads beans, request parameters and scoped attributes. The Jakarta Standard Tag Library (JSTL, officially Jakarta Tags) is the tag set that replaces scriptlets: conditionals, loops, URLs, formatting, internationalization and string functions. All three run on Jakarta Servlet, the request and response API of the container.

Apache Struts is an action-based MVC framework on top of them. A single servlet filter maps each request to an action class, runs a stack of interceptors around it (parameter binding, validation, file upload, security), and picks a result, usually a JSP, FreeMarker or Velocity view. Struts 7 is the current line; Struts 1 ("Struts Classic") is a different framework and is covered only to read legacy code and to leave it.

This section is for developers who:

  • maintain existing JSP and Struts applications and need an accurate, current reference for them

  • modernise those applications, from javax.* to jakarta.*, from Struts 2.x to 7, or towards Spring MVC with Thymeleaf

  • want to understand the roots of the Java web stack: servlets, the translation of a page, the Model 1 and Model 2 patterns

Version baseline and support status

  • Jakarta Pages 4.0, Expression Language 6.0, Servlet 6.1 and Tags 3.0 are specifications of Jakarta EE 11 and of its Web Profile. The Jakarta EE Tutorial states that Pages "has been archived in favor of Facelets", so Pages and Tags receive maintenance rather than features; the plans for Jakarta EE 12 list Pages 4.1, Tags 3.1, Expression Language 6.1 and Servlet 6.2 (in progress, not released). This section teaches them fully on the current versions.

  • Apache Tomcat 11.0.26 is the reference container. Jetty 12.1.14 and GlassFish 8.0.5 are shown as alternatives. There is no Tomcat 12 yet.

  • Apache Struts 7.4.0 is the current line, built for Java 17 and Servlet 6 and later; 6.12.0 is still maintained. Struts 2.5 (end of life on 2023-10-30), 2.3 (2019-09-12) and 1.x (2013-04-05) are end of life.

  • Spring and Java: Java 21 for the examples (17 is the minimum for Pages 4.0, Expression Language 6.0 and Struts 7), Spring Framework 7.0.9 and Spring Boot 4.1.1. Spring Boot documents that JSPs are not supported in an executable jar and that they should be avoided if possible, so the Spring pages use a WAR.

Running example

Every example builds one small original application, Bookshelf, in the same domain as the Thymeleaf, Django and PHP and Laravel sections, so that the stacks can be compared page by page. Here it exists twice, as two WARs on Tomcat 11 that share the domain, a service and a repository:

  • bookshelf-jsp (Part I): a front controller servlet, request attributes, JSP views with EL and JSTL, custom tags, forms, validation, sessions and security

  • bookshelf-struts (Part II): the same catalogue as Struts actions with struts.xml, interceptors, OGNL, validation, i18n, upload, tags, themes and plugins

Figure 1. The two Bookshelf applications: a servlet or the Struts filter in front of a shared service and repository, and a JSP view that renders the response

The project layout of bookshelf-jsp is assembled in Getting Started, and bookshelf-struts in Struts Getting Started.
