PrimeFaces Extensions

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against Jakarta Faces 4.1 (API jakarta.faces-api 4.1.2, part of Jakarta EE 11) with Eclipse Mojarra 4.1.17 and Apache MyFaces Core 4.1.4, Java 17 or later (the examples were compiled with --release 21), PrimeFaces 16.0.0 and PrimeFaces Extensions 16.0.0 (both released on 2026-09-04, checked against Maven Central). The code was deployed as an exploded Bookshelf WAR on Tomcat 11.0.26 with Weld 6.0.4.Final, once with Mojarra and once with MyFaces. Server-side behaviour was driven with scripted Ajax and form posts, and the components that run JavaScript were loaded in headless Chrome and driven through their widget APIs, on 2026-10-08. Claims that were not run are marked as such. PrimeFaces itself is covered by the other PrimeFaces pages of this section (getting started and themes, Ajax, forms and validation, data components, panels, menus and dialogs, files, media, charts and drag and drop); this page assumes you have a working PrimeFaces page, and adds the extra library.

What PrimeFaces Extensions Is

PrimeFaces Extensions is a community-driven open source project (MIT licensed) that adds Faces components and utilities to PrimeFaces: components missing from PrimeFaces, and variants of existing ones. It is a separate project from PrimeFaces: it lives in its own GitHub organisation (primefaces-extensions) and has its own issue tracker and release notes. The project site says its releases are intended to follow the PrimeFaces releases, and the repository README maps each Extensions major line to one PrimeFaces line:

Three consequences follow from the pairing, and they decide most upgrade problems:

  • Upgrade both together. An Extensions release is compiled against one PrimeFaces version (the parent POM of 16.0.0 sets primefaces.core.version to 16.0.0). Mixing Extensions 16 with PrimeFaces 15 is not something the project promises.

  • The components are PrimeFaces components. Most of them extend PrimeFaces base classes, use PrimeFaces widgets (PF('name')), its Ajax engine and its search expressions, so what the other PrimeFaces pages say about process, update and the lifecycle applies unchanged.

  • Some components exist in both libraries. pe:blockUI, pe:tooltip and pe:remoteCommand have PrimeFaces core counterparts (p:blockUI, p:tooltip, p:remoteCommand); see What Is in 16.0.0.

Setup

Maven coordinates

The Extensions JAR does not bring PrimeFaces with it. In the published POM of 16.0.0 the primefaces dependency has scope provided, so a project that lists only the Extensions JAR gets no transitive PrimeFaces (checked with mvn dependency:tree, which listed the Extensions JAR alone). Declare both, with the same version:

pom.xml (dependencies)
<properties>
    <primefaces.version>16.0.0</primefaces.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.primefaces</groupId>
        <artifactId>primefaces</artifactId>
        <version>${primefaces.version}</version>
    </dependency>
    <dependency>
        <groupId>org.primefaces.extensions</groupId>
        <artifactId>primefaces-extensions</artifactId>
        <version>${primefaces.version}</version>
    </dependency>
</dependencies>

Source: primefaces-extensions 16.0.0 POM on Maven Central and PrimeFaces Extensions README: Maven

The namespace

Faces 4.0 and later identify tag libraries by URN. The Extensions JAR ships two tag library descriptors (checked in the JAR): the URN primefaces.extensions and the old URI http://primefaces.org/ui/extensions. PrimeFaces core has the same pair (primefaces and http://primefaces.org/ui). The old namespaces still work in 4.1, but support for them is planned to be removed in Faces 5.0, so use the URNs; the prefix is only an alias, and pe is the convention:

Two observations from running this page. First, radius="0" on pe:qrCode is deliberate: in 16.0.0 the component’s radius property is declared Double but its default is the Integer 0, so a pe:qrCode without an explicit radius fails while rendering with ClassCastException: class java.lang.Integer cannot be cast to class java.lang.Double, on Mojarra (HTTP 500) and on MyFaces alike (reproduced on both; the cast is in QRCodeBaseImpl.getRadius). Setting the attribute makes the component store a Double and the page renders. Second, the rendered page contained the Extensions script (primefaces-extensions.js, ?ln=primefaces-extensions) and a widget call PrimeFaces.cw("ExtTooltip",...): the library registers a resource handler and a system event listener from its own META-INF/faces-config.xml (it is ordered after PrimeFaces), so nothing is needed in web.xml or in your faces-config.xml.

Resources and the build

Extensions' own CSS and JavaScript are served by the Faces resource handler like any library resource (see resource handling) and are minified inside the JAR. The wiki page that explains a org.primefaces.extensions.DELIVER_UNCOMPRESSED_RESOURCES context parameter describes releases before 3.2.0 only and says that later releases ship no uncompressed copies (they use source maps for debugging); do not set it. For your own pages, the project also publishes a Maven plugin, org.primefaces.extensions:resources-optimizer-maven-plugin, which compresses and merges JavaScript and CSS at build time; Maven Central lists 2.7.9 as the latest version (checked 2026-10-08; the 16.0.0 build itself uses 2.6.6), and it was not run for this page. The performance page (combining resources) discusses the OmniFaces alternative; whether CombinedResourceHandler and the Extensions resource handler cooperate was not tested.

Safe HTML: Sanitizing Converters, Editors and the Output Listener

Extensions is the one library of this section that ships a dedicated defence for user-supplied HTML, and it deserves the first example because it is easy to use wrongly. It is built on the OWASP Java HTML Sanitizer, which parses markup and rebuilds it from an allow-list (a PolicyFactory).

pe:sanitizer: a converter

pe:sanitizer is a converter tag (class org.primefaces.extensions.converter.SanitizingConverter, registered as primefaces.SanitizingConverter). Its attributes are policy (a PolicyFactory; the default is a strict policy that allows no tags) and decodeHtml (default true). As a converter it runs when the submitted value is converted, in Process Validations (converters, lifecycle phases), so the bean setter only ever sees the sanitized text; getAsString sanitizes again on the way out.

The last two rows are the trap. With the default decodeHtml="true" the converter sanitizes and then decodes HTML entities (SanitizingConverter.sanitize calls the OWASP decoder after the policy). Entity-encoded markup survives the policy as harmless text and is then turned back into live markup: the stored value is plain text that contains <script> or an <img onerror>. That is safe only if every place that prints it escapes it. Printed with escape="false", as in the last column, the response contains the payload as markup, which is cross-site scripting (the test inspected the response, no browser ran it). The rule, which the security page gives for escape in general:

  • With the default converter, store plain text and print it escaped. The converter then merely removes markup the user should not be sending.

  • If you must print HTML, sanitize with decodeHtml="false" and an explicit policy, so the stored value is HTML that is already safe to print unescaped:

package org.example.bookshelf.web;

import jakarta.annotation.PostConstruct;
import jakarta.faces.view.ViewScoped;
import jakarta.inject.Named;
import java.io.Serializable;
import java.util.ArrayList;
import java.util.List;
import org.primefaces.extensions.model.dynaform.DynaFormControl;
import org.primefaces.extensions.model.dynaform.DynaFormLabel;
import org.primefaces.extensions.model.dynaform.DynaFormModel;
import org.primefaces.extensions.model.dynaform.DynaFormRow;

/** A form whose fields come from a model instead of from the page. */
@Named
@ViewScoped
public class BorrowDynaFormBean implements Serializable {

    /** The value holder of one field; the page binds the control to {@code data.value}. */
    public static class Field implements Serializable {
        private final String name;
        private final boolean required;
        private Object value;

        public Field(String name, boolean required) {
            this.name = name;
            this.required = required;
        }

        public String getName() {
            return name;
        }

        public boolean isRequired() {
            return required;
        }

        public Object getValue() {
            return value;
        }

        public void setValue(Object value) {
            this.value = value;
        }
    }

    private DynaFormModel model;
    private final List<String> submitted = new ArrayList<>();

    @PostConstruct
    void init() {
        model = new DynaFormModel();
        row(model.createRegularRow(), "Reader name", new Field("name", true), "text");
        row(model.createRegularRow(), "Email", new Field("email", true), "text");
        row(model.createRegularRow(), "Loan weeks", new Field("weeks", false), "select");
        row(model.createRegularRow(), "Note", new Field("note", false), "area");
    }

    private void row(DynaFormRow row, String label, Field field, String type) {
        DynaFormLabel l = row.addLabel(label);
        DynaFormControl c = row.addControl(field, type);
        l.setForControl(c);
    }

    public void submit() {
        submitted.clear();
        for (DynaFormControl control : model.getControls()) {
            Field f = (Field) control.getData();
            submitted.add(f.getName() + "=" + f.getValue());
        }
    }

    public DynaFormModel getModel() {
        return model;
    }

    public List<String> getSubmitted() {
        return submitted;
    }

    public List<Integer> getWeeks() {
        return List.of(1, 2, 3, 4);
    }
}

import jakarta.faces.view.ViewScoped;
import jakarta.inject.Inject;
import jakarta.inject.Named;
import java.io.Serializable;
import java.util.ArrayList;
import java.util.List;
import org.example.bookshelf.model.Book;
import org.example.bookshelf.service.BookService;
import org.primefaces.extensions.event.WaypointEvent;

/** Loads the next chunk of books when the sentinel at the end of the list scrolls into view. */
@Named
@ViewScoped
public class FeedScrollBean implements Serializable {

    private static final int CHUNK = 4;

    @Inject
    private transient BookService books;

    private final List<Book> shown = new ArrayList<>();
    private int events;

    public List<Book> getShown() {
        if (shown.isEmpty()) {
            appendChunk();
        }
        return shown;
    }

    /** Fires for both directions; only scrolling down loads more. */
    public void onReached(WaypointEvent event) {
        events++;
        if (event.getDirection() == WaypointEvent.Direction.DOWN) {
            appendChunk();
        }
    }

    private void appendChunk() {
        List<Book> all = books.all();
        int from = Math.min(shown.size(), all.size());
        shown.addAll(all.subList(from, Math.min(from + CHUNK, all.size())));
    }

    public int getEvents() {
        return events;
    }
}

Where the Books Are Outdated

Sudheer Jonna’s Learning PrimeFaces Extensions Development (Packt, 2014) targets Extensions 1.2.1 and PrimeFaces 4.0, and its sample code is on GitHub. For the Extensions-specific chapters it is a useful tour of ideas, but little of the setup and many of the components have changed:

  • Packaging and namespace. Its javax.faces pages with xmlns:pe="http://primefaces.org/ui/extensions" become jakarta.faces.* with the URN primefaces.extensions (Setup). The project wiki’s "Getting Started" page uses the old URI (still accepted) and says PrimeFaces is a transitive dependency, which is not true for 16.0.0 (the dependency is provided).

  • Components that are gone or renamed: CKEditor, exporter, timeline, spotlight and Ajax error handling (What Moved into PrimeFaces Core or Was Removed); their replacements are in PrimeFaces core, SunEditor and the core exception handler.

  • Components that stayed but were reworked: tooltips, pe:remoteCommand (typed parameters through pe:methodSignature and pe:methodParam), pe:dynaForm, pe:fluidGrid, pe:layout, pe:masterDetail, pe:codeMirror, pe:waypoint, pe:timePicker, QR codes and the image components: check each attribute against the VDL instead of trusting the book.

  • Utility functions and resource optimisation. The 16.0.0 tag library declares no EL functions, and resource handling is the optimizer plugin plus ordinary Faces resource handling (Setup, and the section’s performance page).

  • Security. Check any book sample that prints rich text or user input against Safe HTML: Sanitizing Converters, Editors and the Output Listener before copying it, in particular any escape="false" output. The CKEditor XSS fix in 8.0.4 and its removal in 12.0.5 show that rich-text input needs care.

  • Release practice. The book describes one downloadable release; Extensions now releases in step with PrimeFaces and still releases older lines (the release list shows 15.0.18 and 13.0.21), so choose the line that matches your PrimeFaces line.

Pitfalls

  • Mixed versions. Extensions 16.0.0 with PrimeFaces 15 (or the reverse) is not supported by the pairing table. Use one property for both.

  • Expecting a transitive PrimeFaces. The Extensions dependency is provided; leave out primefaces and the application has no PrimeFaces classes (not run: expect a class-loading failure).

  • Missing optional libraries. Editors with secure="true" want the OWASP sanitizer on the classpath, pe:convertJson wants Gson, pe:inputPhone wants libphonenumber. Add the dependency, or set secure="false" only if you accept the consequences.

  • Printing sanitized text with escape="false" after decodeHtml="true". Entity-encoded markup comes back as markup (Safe HTML: Sanitizing Converters, Editors and the Output Listener).

  • Trusting secure on pe:codeMirror. The renderer in 16.0.0 does not apply it; escape and validate the value yourself.

  • pe:qrCode without radius. A ClassCastException in 16.0.0 on both implementations; set radius="0".

  • Raw JavaScript attributes. pe:waypoint offset is emitted as JavaScript source, so a string needs quotes inside the attribute value.

  • Sheet events describe the selection, not the edit. Read changed values from the model; select a cell before scripting a change.

  • Mixing p: and pe: versions of blockUI, tooltip and remoteCommand. They are different components with different attributes.

  • User text in p:timeline events. Encode it with EscapeUtils.forHtml (or sanitize) before adding it to the model.

  • Assuming CSP support. The security page documents PrimeFaces' content security policy mode; whether the Extensions widgets (Handsontable, CodeMirror, SunEditor and others) work under a strict policy was not tested, so test them with primefaces.CSP set to reportOnly first (CSP).

  • Components not run. Monaco, Kanban, OrgChart, ECharts, GChart, OSMap, DocumentViewer, Keynote, CodeScanner, InputPhone and the rest of the catalogue were not run; learn each from the showcase before depending on it.
