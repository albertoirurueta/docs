PrimeFaces Data Components

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page is written against PrimeFaces 16.0.0 (released 2026-09-04), whose migration guide states that Jakarta Faces 4.0 is the baseline, on Jakarta Faces 4.1 with Eclipse Mojarra 4.1.17 and Apache MyFaces Core 4.1.4, Java 17 or later (the examples were compiled with --release 21). Faces 4.0 behaves the same for everything below. The examples were deployed in a scratch Bookshelf WAR on Apache Tomcat 11.0.26 with Weld 6.0.4.Final, once with Mojarra and once with MyFaces, and driven in headless Chrome: the numbers, request parameters, generated markup and every "what happened" statement come from those runs (checked on 2026-10-08), and the attributes were checked against the tag library inside the 16.0.0 jar. Where a statement rests only on the PrimeFaces documentation it says so.

The standard h:dataTable of the data tables page renders what it is given: no sorting, no filtering, no pager. The PrimeFaces data components add all of that, plus selection, in-cell editing, trees, calendars and export, and they do it with Ajax: every click on a column header, page link or filter field is a partial request that re-renders the table body. This page walks through them with one running example, the PrimeFaces variant of the Bookshelf catalogue: a table of books that grows from a plain list into a filterable, editable, selectable, lazy-loaded and exportable one. The setup of PrimeFaces itself (dependencies, context parameters, themes) is on the getting started page of the PrimeFaces part of this section; the Ajax model (process, update) on the PrimeFaces Ajax page; dialogs, panels and menus on their page, and file handling, charts and drag and drop on theirs. The table models and the view state they keep are discussed again for a cluster on the deployment page, and the browser tests of tables on the testing page.

How the Data Components Fit into Faces

p:dataTable, p:dataView, p:dataGrid, p:dataList and p:dataScroller are subclasses of the standard jakarta.faces.component.UIData (through org.primefaces.component.api.PrimeUIData; the class hierarchy was read in the 16.0.0 jar, and PrimeUIData was called UIData before 15.0.0). They iterate a DataModel row by row exactly as the standard table does, so the cursor, the var request attribute, the client ids with a row index (form:books:2:title) and the per-row state saving of the iteration section all apply. p:tree, p:treeTable and p:schedule are different: they extend UIComponentBase through PrimeFaces' own base classes and are driven by their own model objects (TreeNode, ScheduleModel) instead of a DataModel.

What PrimeFaces adds is a set of features that the table component handles itself, each triggered by an Ajax request that carries a marker parameter. The requests below were captured from the running pages; the client ids are those of the pages in this section:

The event names come from the components' getEventNames() in the 16.0.0 jar (listed in Ajax Events of the Data Components); a p:ajax child with event="..." and a listener turns each of them into a server-side callback, in the way the client behaviors page describes for f:ajax. Two details matter for the lifecycle. First, because the browser sends execute=form:books, the request runs all six phases for the table component only: Apply Request Values decodes the feature parameters and the selection, and the listener of a p:ajax behavior runs in Invoke Application, or in Process Validations for filter (the run logged onSort INVOKE_APPLICATION, onFilter PROCESS_VALIDATIONS, onRowSelect INVOKE_APPLICATION). Second, the sorted, filtered or paged result is computed when the table renders, in Render Response; a filteredValue setter was called in that phase. The lifecycle page describes the phases.

The Data and the Beans Used on This Page

The examples use a small catalogue of 24 books. A mutable JavaBean is needed because in-cell editing writes through setters, so the immutable Book record of the data tables page is replaced here by BookRow; RowService is an application-scoped stand-in for the repository behind the catalogue (the paging service of the standard-table page is the same idea). The only two things worth noticing in RowService (shown with its seed data abridged) are that it hands out copies (a table sorts the list it is given), and that it only accepts the column names in its FIELDS map as sort keys. The the persistence page of this section covers a real repository (lazy paging); the JPA version of the lazy table is shown below.

model/BookRow.java
package org.example.bookshelf.model;

import java.io.Serializable;
import java.math.BigDecimal;
import java.util.Objects;

/** The editable row type of the PrimeFaces catalogue: a JavaBean, because in-cell editing writes through setters. */
public class BookRow implements Serializable {

    private long id;
    private String title;
    private String author;
    private String genre;
    private int year;
    private BigDecimal price;
    private boolean available;

    public BookRow() {
    }

    public BookRow(long id, String title, String author, String genre, int year, String price, boolean available) {
        this.id = id;
        this.title = title;
        this.author = author;
        this.genre = genre;
        this.year = year;
        this.price = new BigDecimal(price);
        this.available = available;
    }

    public BookRow copy() {
        BookRow c = new BookRow();
        c.id = id;
        c.title = title;
        c.author = author;
        c.genre = genre;
        c.year = year;
        c.price = price;
        c.available = available;
        return c;
    }

    public long getId() { return id; }
    public void setId(long id) { this.id = id; }
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    public String getAuthor() { return author; }
    public void setAuthor(String author) { this.author = author; }
    public String getGenre() { return genre; }
    public void setGenre(String genre) { this.genre = genre; }
    public int getYear() { return year; }
    public void setYear(int year) { this.year = year; }
    public BigDecimal getPrice() { return price; }
    public void setPrice(BigDecimal price) { this.price = price; }
    public boolean isAvailable() { return available; }
    public void setAvailable(boolean available) { this.available = available; }

    @Override
    public boolean equals(Object o) {
        return o instanceof BookRow other && other.id == id;
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
service/RowService.java
package org.example.bookshelf.service;

import jakarta.enterprise.context.ApplicationScoped;
import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;
import java.util.Locale;
import java.util.Map;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.function.Function;
import java.util.stream.Stream;
import org.example.bookshelf.model.BookRow;

/**
 * In-memory stand-in for the repository behind the catalogue. The only columns a caller may sort or filter by are
 * the keys of FIELDS: the field names arrive from the browser, so an unknown name is refused, never concatenated into a query.
 */
@ApplicationScoped
public class RowService {

    private static final Map<String, Function<BookRow, Comparable<?>>> FIELDS = Map.of(
        "title", BookRow::getTitle,
        "author", BookRow::getAuthor,
        "genre", BookRow::getGenre,
        "year", BookRow::getYear,
        "price", BookRow::getPrice);

    private final List<BookRow> rows = new CopyOnWriteArrayList<>(List.of(
        new BookRow(1, "Pride and Prejudice", "Jane Austen", "Romance", 1813, "9.90", true),
        // ... 23 more books: id, title, author, genre, year, price, available
        ));

    public List<BookRow> findAll() {
        return new ArrayList<>(rows.stream().map(BookRow::copy).toList());
    }

    public BookRow byId(long id) {
        return rows.stream().filter(r -> r.getId() == id).findFirst().map(BookRow::copy).orElse(null);
    }

    public void save(BookRow row) {
        for (int i = 0; i < rows.size(); i++) {
            if (rows.get(i).getId() == row.getId()) {
                rows.set(i, row.copy());
            }
        }
    }

    /** Case-insensitive "contains" on the text fields; "available" is matched exactly. */
    public int count(Map<String, String> filters) {
        return (int) filtered(filters).count();
    }

    public List<BookRow> find(int first, int pageSize, String sortField, boolean ascending, Map<String, String> filters) {
        Function<BookRow, Comparable<?>> key = FIELDS.get(sortField == null ? "title" : sortField);
        if (key == null) {
            throw new IllegalArgumentException("Cannot sort by " + sortField);
        }
        @SuppressWarnings({"unchecked", "rawtypes"})
        Comparator<BookRow> order = (a, b) -> ((Comparable) key.apply(a)).compareTo(key.apply(b));
        if (!ascending) {
            order = order.reversed();
        }
        return filtered(filters).sorted(order).skip(first).limit(pageSize).map(BookRow::copy).toList();
    }

    private Stream<BookRow> filtered(Map<String, String> filters) {
        Stream<BookRow> stream = rows.stream();
        for (Map.Entry<String, String> f : filters.entrySet()) {
            String wanted = f.getValue().toLowerCase(Locale.ROOT);
            stream = switch (f.getKey()) {
                case "title" -> stream.filter(r -> r.getTitle().toLowerCase(Locale.ROOT).contains(wanted));
                case "author" -> stream.filter(r -> r.getAuthor().toLowerCase(Locale.ROOT).contains(wanted));
                case "genre" -> stream.filter(r -> r.getGenre().toLowerCase(Locale.ROOT).contains(wanted));
                case "year" -> stream.filter(r -> String.valueOf(r.getYear()).startsWith(wanted));
                case "available" -> stream.filter(r -> String.valueOf(r.isAvailable()).equals(wanted));
                default -> throw new IllegalArgumentException("Cannot filter by " + f.getKey());
            };
        }
        return stream;
    }
}

The view-scoped TableBean behind the small tables keeps the list loaded once, the list of filtered rows, the selection, and one method per event:

web/TableBean.java
package org.example.bookshelf.web;

import jakarta.annotation.PostConstruct;
import jakarta.faces.application.FacesMessage;
import jakarta.faces.context.FacesContext;
import jakarta.faces.view.ViewScoped;
import jakarta.inject.Inject;
import jakarta.inject.Named;
import java.io.Serializable;
import java.util.ArrayList;
import java.util.List;
import org.example.bookshelf.model.BookRow;
import org.example.bookshelf.service.RowService;
import org.primefaces.event.CellEditEvent;
import org.primefaces.event.RowEditEvent;
import org.primefaces.event.SelectEvent;
import org.primefaces.event.ToggleEvent;
import org.primefaces.event.UnselectEvent;
import org.primefaces.event.data.FilterEvent;
import org.primefaces.event.data.PageEvent;
import org.primefaces.event.data.SortEvent;

/** One view-scoped bean behind the small tables of this page: the rows, the filtered copy and the selection. */
@Named("table")
@ViewScoped
public class TableBean implements Serializable {

    @Inject
    private RowService service;

    private List<BookRow> rows;
    private List<BookRow> filteredRows;
    private List<BookRow> selectedRows = new ArrayList<>();
    private BookRow selectedRow;
    private String lastEvent = "none";

    @PostConstruct
    void init() {
        rows = service.findAll();
    }

    public List<BookRow> getRows() { return rows; }
    public List<BookRow> getFilteredRows() { return filteredRows; }
    public void setFilteredRows(List<BookRow> filteredRows) { this.filteredRows = filteredRows; }
    public List<BookRow> getSelectedRows() { return selectedRows; }
    public void setSelectedRows(List<BookRow> selectedRows) { this.selectedRows = selectedRows; }
    public BookRow getSelectedRow() { return selectedRow; }
    public void setSelectedRow(BookRow selectedRow) { this.selectedRow = selectedRow; }
    public String getLastEvent() { return lastEvent; }

    public List<String> getGenres() {
        return rows.stream().map(BookRow::getGenre).distinct().sorted().toList();
    }

    public String getSelectedTitles() {
        return selectedRows.stream().map(BookRow::getTitle).toList().toString();
    }

    public void borrowSelected() {
        lastEvent = "borrowed " + selectedRows.size();
    }

    public void onRowSelect(SelectEvent<BookRow> event) {
        lastEvent = "select " + event.getObject().getTitle();
    }

    public void onRowUnselect(UnselectEvent<BookRow> event) {
        lastEvent = "unselect " + event.getObject().getTitle();
    }

    public void onSort(SortEvent event) {
        lastEvent = "sort " + event.getSortBy().keySet();
    }

    public void onFilter(FilterEvent event) {
        lastEvent = "filter " + event.getFilterBy().keySet();
    }

    public void onPage(PageEvent event) {
        lastEvent = "page " + event.getPage() + " rows " + event.getRowsPerPage();
    }

    public void onRowToggle(ToggleEvent event) {
        lastEvent = "toggle " + event.getVisibility() + " " + ((BookRow) event.getData()).getTitle();
    }

    public void onRowEdit(RowEditEvent<BookRow> event) {
        service.save(event.getObject());
        lastEvent = "edited " + event.getObject().getTitle();
        FacesContext.getCurrentInstance().addMessage(null,
            new FacesMessage(FacesMessage.SEVERITY_INFO, "Saved", event.getObject().getTitle()));
    }

    public void onRowEditCancel(RowEditEvent<BookRow> event) {
        lastEvent = "cancelled " + event.getObject().getTitle();
    }

    public void onCellEdit(CellEditEvent<Object> event) {
        lastEvent = "cell " + event.getOldValue() + " -> " + event.getNewValue();
        BookRow row = (BookRow) event.getRowData();
        service.save(row);
    }
}

p:dataTable: Columns, Facets and Paging

The smallest useful table binds a List to value, names the row variable and declares the columns. A column can show a bean property directly with field, or contain any markup:

basic.xhtml (content of h:body)
<h:form id="form">
  <p:dataTable id="books" value="#{table.rows}" var="book" widgetVar="booksTable"
               paginator="true" rows="5" rowsPerPageTemplate="5,10,25"
               paginatorTemplate="{CurrentPageReport} {FirstPageLink} {PreviousPageLink} {PageLinks} {NextPageLink} {LastPageLink} {RowsPerPageDropdown}"
               currentPageReportTemplate="{startRecord}-{endRecord} of {totalRecords}"
               emptyMessage="No books found" stripedRows="true">
    <f:facet name="header">The Bookshelf catalogue</f:facet>
    <p:column headerText="Title" field="title"/>
    <p:column headerText="Author" field="author"/>
    <p:column headerText="Year" field="year" width="80"/>
    <p:column headerText="Price" style="text-align: right">
      <h:outputText value="#{book.price}">

What the run showed:

  • Five of 24 rows were rendered, and the page report read "1-5 of 24"; clicking "next" posted form:books_pagination=true&form:books_first=5&form:books_rows=5 and the second page held the sixth to tenth rows with the report "6-10 of 24". Choosing "10" in the rows-per-page dropdown re-rendered ten rows. All of that is one Ajax request each; no full page load.

  • A column with field="title" and no body shows #{book.title} as text (escaped); the body of the column is what you use to format, as the price column does with f:convertNumber.

  • field does more than name a property: it makes the column sortable and filterable. The header of the first column rendered a text filter input (<input ... type="search" class="ui-column-filter ...">) although the page never asked for filtering. Switch it off per column with sortable="false" or filterable="false", or use headerText with a body (as the price column does) if the column should be plain.

  • paginatorTemplate accepts the keys {FirstPageLink}, {PreviousPageLink}, {PageLinks}, {NextPageLink}, {LastPageLink}, {CurrentPageReport}, {RowsPerPageDropdown}, {JumpToPageDropdown} and {JumpToPageInput}; currentPageReportTemplate accepts {currentPage}, {totalPages}, {totalRecords}, {startRecord} and {endRecord}; paginatorPosition is top, bottom or both (the 16.0.0 taglib says the default is bottom, the documentation text says both; the rendered table had only the bottom paginator). A facet whose name is a template key you invent ({MyContent}) is rendered where the key appears (documentation, not run). The key names are those of the documentation; the taglib lists the attributes.

  • The attributes that change only the look: stripedRows, showGridlines, size (small, regular, large), rowHover, rowStyleClass (an expression evaluated for each row), tableStyle, emptyMessage and the emptyMessage facet, which accepts markup.

  • clientCache="true" makes the table fetch the next page in the background so that "next" is instant (documentation); reflow="true" and responsivePriority on columns are the two responsive modes; stickyHeader="true" keeps the header visible while the page scrolls. These were read in the documentation and the taglib and not run.

Header and footer. f:facet name="header" and name="footer" on the table, and the same facets or the headerText and footerText shortcuts on a column. escapeText (default true in the taglib) escapes headerText and footerText; leave it on for any text that comes from users.

The value is the model. A List, an array or any Collection works, as does any DataModel. The documentation advises against keeping the list in a longer-lived scope such as @ViewScoped, to avoid large sessions and serialisation: bind a request-scoped bean as in its getting started example, or a LazyDataModel that loads on the fly (the lazy section below). The view-scoped TableBean of this page is the other trade-off, kept for the filtering and selection examples because 24 rows are cheap; it is the same trade-off the data tables page makes for its editable table.

Sorting

Defining field (or sortBy) on a column makes it sortable. Clicking the header cycles ascending, descending and, only with allowUnsorting="true", unsorted. sortMode is multiple by default in the 16.0.0 taglib: a click sorts by that column alone, and a click with the Ctrl or Meta key held adds it to the sort group. A column’s sortOrder (asc or desc) with a sortPriority sets the initial sort; nullSortOrder, caseSensitiveSort and sortFunction refine it.

  • The table first rendered sorted by year (the column with sortOrder="asc" sortPriority="1"): 1811, 1813, 1815, 1817, 1818.

Selection and the rowKey

Lazy Loading with LazyDataModel

A table bound to a list renders one page but still needs the whole list in memory on every request. A table bound to an org.primefaces.model.LazyDataModel asks for one page at a time. The model has two abstract methods (since 11.0.0, when count became mandatory and setRowCount in load stopped being necessary):

Method Called with

int count(Map<String, FilterMeta> filterBy)

the active filters; return the number of rows that match, for the paginator

List<T> load(int first, int pageSize, Map<String, SortMeta> sortBy, Map<String, FilterMeta> filterBy)

the offset, the page size, the active sorters and filters; return the rows of that page

getRowKey(T) and getRowData(String rowKey) (or a Converter passed to the constructor) are needed when selection is on. loadOne(...) (renamed from getRowData(rowIndex, sortBy, filterBy) in 14.0.0) loads a single row. The table detects a lazy model by the type of its value: since 10.0.0 lazy="true" is no longer needed, and the taglib says lazy defaults to true when the value is a LazyDataModel. Use the column attribute field to name what is sorted and filtered: in load the keys of the sortBy and filterBy maps were the field names (the log printed sort=[year]), whereas the SortEvent of the non-lazy table above is keyed by column client ids; SortMeta.getField() and FilterMeta.getField() return the field in both cases, so use them.

web/RowLazyModel.java
package org.example.bookshelf.web;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;
import org.example.bookshelf.model.BookRow;
import org.example.bookshelf.service.RowService;
import org.primefaces.model.FilterMeta;
import org.primefaces.model.LazyDataModel;
import org.primefaces.model.SortMeta;

/** Translates what the table asks for into the service's page-sized query. */
public class RowLazyModel extends LazyDataModel<BookRow> {

    private final transient RowService service;

    public RowLazyModel(RowService service) {
        this.service = service;
    }

    @Override
    public int count(Map<String, FilterMeta> filterBy) {
        return service.count(toFilters(filterBy));
    }

    @Override
    public List<BookRow> load(int first, int pageSize, Map<String, SortMeta> sortBy, Map<String, FilterMeta> filterBy) {
        String field = "title";
        boolean ascending = true;
        if (!sortBy.isEmpty()) {
            SortMeta sort = sortBy.values().iterator().next();
            field = sort.getField();
            ascending = sort.getOrder().isAscending();
        }
        return service.find(first, pageSize, field, ascending, toFilters(filterBy));
    }

    @Override
    public String getRowKey(BookRow row) {
        return String.valueOf(row.getId());
    }

    @Override
    public BookRow getRowData(String rowKey) {
        try {
            return service.byId(Long.parseLong(rowKey));
        } catch (NumberFormatException e) {
            return null;
        }
    }

    private static Map<String, String> toFilters(Map<String, FilterMeta> filterBy) {
        Map<String, String> filters = new LinkedHashMap<>();
        for (FilterMeta meta : filterBy.values()) {
            if (meta.getFilterValue() != null && !String.valueOf(meta.getFilterValue()).isBlank()) {
                filters.put(meta.getField(), String.valueOf(meta.getFilterValue()).trim());
            }
        }
        return filters;
    }
}

The model is built in a request-scoped bean on purpose. It holds no rows, so there is nothing to keep, and the documentation advises against keeping a data model in a longer scope such as @ViewScoped (large sessions, serialisation). The RowService field is transient because LazyDataModel is Serializable; the CatalogueLazyModel of the performance page does the same.

What the run showed, with the 24 books and five rows per page:

  • Sorting by "Year" gave 1811 and 1813 first, then (second click) 1903 and 1902; the second page of the descending list started with "The Time Machine"; typing wells in the author filter left the two H. G. Wells books. All of it ran through RowLazyModel.load.

  • When the model is called. Logging the phase inside count and load showed: the first GET calls count and load once, in Render Response; a sort click or a page click calls them once, in Render Response, with the new state; a filter request calls them twice, first in Apply Request Values with the previous state (the table needs the current rows to decode a selection), then in Render Response with the new filters; and a button with process="@form" that does not re-render the table still calls them once in Apply Request Values. Each call is a query in a real repository, so keep count and load cheap and do not put a slow side effect into them.

  • The field names are not taken from the request. The browser posts the client id of the column (form:books_sortKey=form:books:j_idt9) and the table maps it to the column’s field declared in the view. Replacing the posted value with '; DROP TABLE book;-- made the table ignore it and render the default order, without an error; replacing sortDir=1 with abc made the Ajax response fail with IllegalArgumentException: No SorderOrder matching value: abc (that spelling is in the message). Do not rely on that: RowService accepts only the names in its FIELDS map, and the JPA model below binds every filter value as a parameter. Never concatenate a field name or a filter text into a query.

  • Selection works on a lazy table when the model can find a row from its key: the check boxes selected rows on different pages, and the posted 14,999,abc produced only the real book.

  • The one-query variants of the documentation (count returning 0 and setRowCount(page.getTotalElements()) inside load, or recalculateFirst) save the extra count query at the price of a known problem with first (PrimeFaces issue 1921, linked from the documentation). They were not run.

DefaultLazyDataModel

For a list that you can only fetch whole (a web service, a cache), DefaultLazyDataModel implements count and load for you: a supplier returns the list for the current filters, and the model filters and sorts by reflection on the column `field`s, then cuts the page. The documentation lists three reasons to prefer it over binding a list: reflection is faster than restoring component state for every row (it states "up to 30%"), the list does not sit in a view-scoped bean, and a lambda can add filtering or sorting.

p:tree

p:tree shows hierarchical data. Its model is a org.primefaces.model.TreeNode<T>, the root, built from DefaultTreeNode objects (the constructor attaches a node to its parent). TreeNode is generic since 11.0.0 ("typed data objects"), so the examples hold a record, ShelfBean.Entry, instead of the strings of the older material. A node has a type (the default is default), and p:treeNode components in the tree choose the markup and icons by that type: the Bookshelf tree has a genre folder type and a book leaf type.

package org.example.bookshelf.web;

import jakarta.annotation.PostConstruct;
import jakarta.faces.view.ViewScoped;
import jakarta.inject.Inject;
import jakarta.inject.Named;
import java.io.Serializable;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import org.example.bookshelf.model.BookRow;
import org.example.bookshelf.service.RowService;
import org.primefaces.event.NodeExpandEvent;
import org.primefaces.event.NodeSelectEvent;
import org.primefaces.event.NodeUnselectEvent;
import org.primefaces.model.CheckboxTreeNode;
import org.primefaces.model.DefaultTreeNode;
import org.primefaces.model.LazyDefaultTreeNode;
import org.primefaces.model.TreeNode;

/** The shelves of the library as a tree: genre folders containing books. */
@Named("shelf")
@ViewScoped
public class ShelfBean implements Serializable {

    /** What a node carries. Serializable, because view-scoped beans are. */
    public record Entry(String name, String kind, int year) implements Serializable {
    }

    @Inject
    private RowService service;

    private TreeNode<Entry> root;
    private TreeNode<Entry> checkRoot;
    private TreeNode<Entry> lazyRoot;
    private TreeNode<Entry> selected;
    private TreeNode<Entry>[] selectedNodes;
    private String lastEvent = "none";

    @PostConstruct
    @SuppressWarnings("unchecked")
    void init() {
        root = build(new DefaultTreeNode<>(new Entry("Shelves", "root", 0)), false);
        checkRoot = build(new CheckboxTreeNode<>(new Entry("Shelves", "root", 0)), true);
        lazyRoot = new LazyDefaultTreeNode<>(new Entry("Shelves", "root", 0),
            this::children, entry -> "book".equals(entry.kind()));
        selectedNodes = new TreeNode[0];
    }

    private TreeNode<Entry> build(TreeNode<Entry> top, boolean checkbox) {
        Map<String, TreeNode<Entry>> genres = new TreeMap<>();
        for (BookRow row : service.findAll()) {
            TreeNode<Entry> genre = genres.computeIfAbsent(row.getGenre(), g ->
                checkbox ? new CheckboxTreeNode<>("genre", new Entry(g, "genre", 0), top)
                         : new DefaultTreeNode<>("genre", new Entry(g, "genre", 0), top));
            if (checkbox) {
                new CheckboxTreeNode<>("book", new Entry(row.getTitle(), "book", row.getYear()), genre);
            } else {
                new DefaultTreeNode<>("book", new Entry(row.getTitle(), "book", row.getYear()), genre);
            }
        }
        top.setExpanded(true);
        return top;
    }

    /** Called by the lazy node only when a node is expanded for the first time. */
    private List<Entry> children(Entry parent) {
        if ("root".equals(parent.kind())) {
            return service.findAll().stream().map(BookRow::getGenre).distinct().sorted()
                .map(g -> new Entry(g, "genre", 0)).toList();
        }
        return service.findAll().stream().filter(r -> r.getGenre().equals(parent.name()))
            .map(r -> new Entry(r.getTitle(), "book", r.getYear())).toList();
    }

    public void onNodeSelect(NodeSelectEvent event) {
        lastEvent = "select " + ((Entry) event.getTreeNode().getData()).name();
    }

    public void onNodeUnselect(NodeUnselectEvent event) {
        lastEvent = "unselect " + ((Entry) event.getTreeNode().getData()).name();
    }

    public void onNodeExpand(NodeExpandEvent event) {
        lastEvent = "expand " + ((Entry) event.getTreeNode().getData()).name();
    }

    public String getSelectedNames() {
        StringBuilder names = new StringBuilder();
        for (TreeNode<Entry> n : selectedNodes) {
            names.append(n.getData().name()).append(';');
        }
        return names.toString();
    }

    public TreeNode<Entry> getRoot() { return root; }
    public TreeNode<Entry> getCheckRoot() { return checkRoot; }
    public TreeNode<Entry> getLazyRoot() { return lazyRoot; }
    public TreeNode<Entry> getSelected() { return selected; }
    public void setSelected(TreeNode<Entry> selected) { this.selected = selected; }
    public TreeNode<Entry>[] getSelectedNodes() { return selectedNodes; }
    /** The checkbox tree writes null when nothing is checked. */
    @SuppressWarnings("unchecked")
    public void setSelectedNodes(TreeNode<Entry>[] selectedNodes) {
        this.selectedNodes = selectedNodes == null ? new TreeNode[0] : selectedNodes;
    }
    public String getLastEvent() { return lastEvent; }
}

p:schedule

p:schedule is a calendar based on FullCalendar (version 5 since PrimeFaces 10.0.0). Its model is a ScheduleModel of ScheduleEvent objects; DefaultScheduleModel and DefaultScheduleEvent (created with DefaultScheduleEvent.builder(), with java.time.LocalDateTime start and end) are the ready-made ones. The Bookshelf calendar shows loans and a reading club; clicking a day opens a dialog (dialogs are on the PrimeFaces panels, menus and dialogs page) to add one.

web/LoanBean.java
package org.example.bookshelf.web;

import jakarta.annotation.PostConstruct;
import jakarta.faces.view.ViewScoped;
import jakarta.inject.Named;
import java.io.Serializable;
import java.time.LocalDate;
import java.time.LocalDateTime;
import org.primefaces.event.SelectEvent;
import org.primefaces.event.schedule.ScheduleEntryMoveEvent;
import org.primefaces.model.DefaultScheduleEvent;
import org.primefaces.model.DefaultScheduleModel;
import org.primefaces.model.LazyScheduleModel;
import org.primefaces.model.ScheduleEvent;
import org.primefaces.model.ScheduleModel;

/** Loans and returns on a calendar. */
@Named("loans")
@ViewScoped
public class LoanBean implements Serializable {

    private ScheduleModel model;
    private ScheduleModel lazyModel;
    private ScheduleEvent<?> event = new DefaultScheduleEvent<>();
    private String lastEvent = "none";

    @PostConstruct
    void init() {
        model = new DefaultScheduleModel();
        LocalDate first = LocalDate.now().withDayOfMonth(1);
        model.addEvent(DefaultScheduleEvent.builder().title("Emma due back")
            .startDate(first.plusDays(4).atTime(10, 0)).endDate(first.plusDays(4).atTime(11, 0)).build());
        model.addEvent(DefaultScheduleEvent.builder().title("Reading club")
            .startDate(first.plusDays(9).atTime(18, 0)).endDate(first.plusDays(9).atTime(19, 30)).build());
        lazyModel = new LazyScheduleModel() {
            @Override
            public void loadEvents(LocalDateTime start, LocalDateTime end) {
                clear();
                for (LocalDateTime d = start.toLocalDate().atStartOfDay(); d.isBefore(end); d = d.plusDays(7)) {
                    addEvent(DefaultScheduleEvent.builder().title("Weekly return day")
                        .startDate(d.withHour(9)).endDate(d.withHour(10)).build());
                }
            }
        };
    }

    public void onDateSelect(SelectEvent<LocalDateTime> select) {
        event = DefaultScheduleEvent.builder().startDate(select.getObject()).endDate(select.getObject().plusHours(1)).build();
        lastEvent = "date " + select.getObject();
    }

    public void onEventSelect(SelectEvent<ScheduleEvent<?>> select) {
        event = select.getObject();
        lastEvent = "event " + event.getTitle();
    }

    public void onEventMove(ScheduleEntryMoveEvent move) {
        lastEvent = "moved " + move.getScheduleEvent().getTitle() + " by " + move.getDayDelta() + "d " + move.getMinuteDelta() + "m";
    }

    public void save() {
        if (event.getId() == null) {
            model.addEvent(event);
        } else {
            model.updateEvent(event);
        }
        lastEvent = "saved " + event.getTitle();
        event = new DefaultScheduleEvent<>();
    }

    public ScheduleModel getModel() { return model; }
    public ScheduleModel getLazyModel() { return lazyModel; }
    public ScheduleEvent<?> getEvent() { return event; }
    public void setEvent(ScheduleEvent<?> event) { this.event = event; }
    public String getLastEvent() { return lastEvent; }
}

web/SafeCsvExporter.java
package org.example.bookshelf.web;

import org.primefaces.component.datatable.export.DataTableCSVExporter;

/** The built-in CSV exporter, with cell text that a spreadsheet could read as a formula defused. */
public class SafeCsvExporter extends DataTableCSVExporter {

    @Override
    protected String escapeQuotes(String value) {
        return super.escapeQuotes(defuse(value));
    }

    static String defuse(String value) {
        if (value != null && !value.isEmpty() && "=+-@\t\r".indexOf(value.charAt(0)) >= 0) {
            return "'" + value;
        }
        return value;
    }
}

Where the Books Are Outdated

The PrimeFaces Cookbook by Mert Çalışkan and Oleg Varaksin (second edition, Packt, 2015) teaches the data components with the PrimeFaces 5 API. Its chapter on data iteration is still a good tour of what the components are for. The code needs updating:

  • Selection. The book turns on selection with a selectionMode attribute on the table and uses <p:column selectionMode="single"/> for a radio or checkbox column. Since 13.0.0 the mode is deduced from the type of the selection property, the column attribute is selectionBox (14.0.0), the attributes were renamed, and a non-lazy table needs a rowKey (11.0.0); the run showed the error when it is missing.

  • Lazy loading. The book’s load(first, pageSize, sortField, sortOrder, filters) is gone and the setRowCount call is no longer needed (the method still exists). The model implements count and a load that receives maps of SortMeta and FilterMeta; lazy="true" is detected. JPALazyDataModel and DefaultLazyDataModel replace the hand-written Criteria API models the book recommends.

  • Sorting and filtering. sortBy="#{car.name}" with sortField or sortOrder on the table, and the SortOrder argument, were replaced in 10.0.0 by field, sortOrder and sortPriority on the column and by SortMeta; sort functions take three arguments since 14.0.0.

  • Schedule. The book’s LazyScheduleModel.loadEvents(Date, Date) and new DefaultScheduleEvent(title, Date, Date) use java.util.Date. In 16.0.0 the method takes LocalDateTime and events are built with DefaultScheduleEvent.builder() (both checked in the jar); the underlying FullCalendar is version 5 since 10.0.0, so the CSS and extender options differ.

  • Export. The book lists iText 2.1.7 and Apache POI 3.7 as the optional libraries. PrimeFaces 16 expects POI 5.5.1 and OpenPDF 1.4.2, the exporters are registered with DataExporters, and the exporter attribute is gone.

  • Icons and look. ui-icon-* classes (jQuery UI) in the book’s buttons and tree nodes give way to PrimeIcons (pi pi-folder), and p:calendar to p:datePicker, as the schedule dialog above uses.

  • Dependencies and platform. The book’s examples target Servlet 3 containers and javax.faces; PrimeFaces 16 needs Jakarta Faces 4.0 or later.

  • Trees. The book builds trees with raw new DefaultTreeNode("Root", null); they still compile but TreeNode<T> is generic (11.0.0), and the checkbox selection uses CheckboxTreeNode.

The components of PrimeFaces Extensions that Jonna’s book describes (including a spreadsheet-like table and its own exporter) are not covered here; the PrimeFaces Extensions page of this section says which of them remain. Where the book and the PrimeFaces 16 documentation disagree, the documentation and the jar win.

Pitfalls

  • Binding a getter that builds the list. The table sorts the list in place, and a getter that returns a new list on each call defeats the sort and runs the query for every evaluation. Load once in @PostConstruct or use a lazy model.

  • Immutable lists. List.of and Stream.toList() fail on the first sort with UnsupportedOperationException. Copy into an ArrayList.

  • Two tables on one list. They share the in-place sort.

  • field also enables filtering. Use filterable="false" where a filter box makes no sense.

  • A missing rowKey. HTTP 500 on the first request of a table with selection or rowExpansion. A rowKey that contains a comma breaks the selection.

  • Wrong event name for the selection column. rowSelect is for row clicks, rowSelectCheckbox for checkboxes.

  • A bare sortBy on the table. It did not sort the first render; use the column attributes or a List<SortMeta>, and name only fields that exist as columns.

  • A lazy model called twice per request. A filter request loads in Apply Request Values and again in Render Response; a process="@form" button loads once. Keep count and load cheap and free of side effects.

  • Trusting the browser. Selection keys, row indexes of edit requests and event ids come from the browser. Look up each row through the service and check the user’s rights; never place a posted field name or filter text in a query.

  • CSV export of user text. The built-in CSV exporter writes =..., @..., -... and +... cells verbatim; register an exporter that defuses them.

  • tree selection null. The checkbox tree writes null to its selection property; accept it.

  • A lazy tree without dynamic="true". It renders every node.

  • A schedule updated with update=. Use PF('widget').update() after changing the model, and set clientTimeZone.

  • Cell editing skips validation. The documentation says required and Bean Validation do not apply in cell mode.

  • Keeping a large model in a long scope. A @ViewScoped or session bean that holds thousands of rows is serialised with the view or the session; hold only what the user is editing.

  • Row grouping with a lazy table. Not supported (documentation).

  • virtualScroll. Not verified here. In the run its table showed no rows in the headless check, so test it with your model before using it; liveScroll with scrollRows loaded 6, 12, 18 and 24 rows on scrolling.
