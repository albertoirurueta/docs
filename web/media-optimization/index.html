Media Optimization for the Web

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This is the browser home of the topic. The backend produces optimized variants, see Media Optimization for the backend, and native apps consume them with the libraries in Media Optimization in apps. This sub-section is the other half of the backend: how a web page asks for the right variant, shows something useful while it loads, and plays video that adapts to the connection. It is current as of 2026-10-07, and each page names the versions it was checked against.

Deliberately out of scope. This section is about what the browser does with media that already exists in the right variants. The following topics appear in most web performance and responsive design books but live elsewhere on this site, or are intentionally not covered:

  • Producing the variants (encoding, formats, upload pipelines, thumbnails) — see Media Optimization for the backend and upload pipelines.

  • Layout, fluid grids and CSS media queries — see HTML and CSS; only the image attributes and aspect-ratio that prevent layout shift are repeated here.

  • General loading performance and Core Web Vitals tuning (fonts, scripts, caching headers) — see HTML and CSS: Performance and Loading.

  • Accessibility of media (alt text, captions, reduced motion) — see Accessibility.

  • Live and real-time video (WebRTC, WebSockets) — see WebRTC and WebSockets; this section covers on-demand playback only.

  • DRM and licence servers — the players support Widevine, PlayReady and FairPlay, but key delivery is not covered.

  • Native and cross-platform apps — see Media Optimization in apps.

  • Managed image and video services — see AWS, Google Cloud and Azure.
