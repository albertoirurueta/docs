Worked Example: An Interactive List

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page ties the section together: one small feature — a dynamic shopping list with add, remove, and reorder — that uses selection, DOM manipulation, events, and effects at once. The whole thing is one HTML file.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>Interactive list</title>
  <style>
    body { font: 16px/1.4 system-ui, sans-serif; max-width: 32rem; margin: 2rem auto; }
    li { display: flex; gap: .5rem; align-items: center; padding: .25rem 0; }
    li.done span { text-decoration: line-through; opacity: .6; }
    li span { flex: 1; }
    button { cursor: pointer; }
  </style>
</head>
<body>
  <h1>Shopping list</h1>

  <form id="add-form">
    <input id="add-input" type="text" placeholder="Add an item" autocomplete="off" required>
    <button type="submit">Add</button>
  </form>

  <ul id="list"></ul>

  <script
    src="https://code.jquery.com/jquery-3.7.1.min.js"
    integrity="sha256-..."
    crossorigin="anonymous"></script>
  <script>
  $(function () {
    const $list = $('#list');
    const $input = $('#add-input');

    // --- ADD: form submit handler (events page) ---
    $('#add-form').on('submit', function (event) {
      event.preventDefault();                 // don't reload the page
      const text = $input.val().trim();
      if (!text) return;

      // build the row with the tag + attributes object (dom-manipulation page)
      const $row = $('<li>', { html:
        '<span></span>' +
        '<button class="up" title="Move up">&uarr;</button>' +
        '<button class="down" title="Move down">&darr;</button>' +
        '<button class="del" title="Delete">&times;</button>'
      });
      $row.find('span').text(text);            // .text() escapes -- safe for user input

      $row.hide().appendTo($list).slideDown(150);   // effects page
      $input.val('').focus();
    });

    // --- DELEGATED handlers: one listener on #list for every current AND future row ---
    // (events page: delegation + traversal page: .closest())

    $list.on('click', '.del', function () {
      $(this).closest('li').slideUp(150, function () { $(this).remove(); });
    });

    $list.on('click', 'span', function () {
      $(this).closest('li').toggleClass('done');   // css-attributes page: toggleClass
    });

    $list.on('click', '.up', function () {
      const $li = $(this).closest('li');
      $li.prev('li').before($li);              // traversal: .prev() + manipulation: .before()
    });

    $list.on('click', '.down', function () {
      const $li = $(this).closest('li');
      $li.next('li').after($li);
    });
  });
  </script>
</body>
</html>

Walkthrough

Add

The submit handler (Events) calls event.preventDefault() so the form does not navigate. A new <li> is built with the $('<tag>', props) form from DOM Manipulation; the user’s text goes in through .text(), which escapes markup, so a pasted <script> is inert. .hide().appendTo(...).slideDown() (Effects and Animation) inserts it invisibly and animates it open.

Remove / toggle / reorder

All four are delegated: the handler is bound once to #list, with a selector (.del, span, .up, .down) as the second argument. Rows added later are handled with no re-binding — the reason delegation is the default pattern for dynamic lists (Events). Each handler uses .closest('li') (Traversal and Chaining) to get from the clicked button up to its row. Reordering combines a traversal step (.prev('li') / .next('li')) with an insertion step (.before() / .after()) from DOM Manipulation; moving an element that is already in the DOM relocates it rather than copying it.

Chaining

$row.hide().appendTo($list).slideDown(150) and $li.prev('li').before($li) both rely on every method returning a jQuery set (Traversal and Chaining).

Step two: one change event, persistence, editing and clearing

The first version keeps all state in the DOM. Real lists need three more things: a counter, persistence across page loads, and a way to correct a typo. Adding them is mostly a question of where the new code goes. The design below routes every mutation through a single custom event, list:change, so the counter and the saved copy can never get out of step with the DOM.

The markup gains a count line, a clear button, and a name on the input (needed by .serialize() should the form ever be posted):

<form id="add-form">
  <input id="add-input" name="item" type="text" placeholder="Add an item" autocomplete="off" required>
  <button type="submit">Add</button>
</form>
<p id="count"></p>
<button id="clear-done" type="button">Clear completed</button>
<ul id="list"></ul>

and the script becomes the following. Everything from the first version is still here; the new parts are rowFor/readItems/load (the model/DOM translation), the list:change listener, the edit handlers and the clear button.

$(function () {
  const STORAGE_KEY = 'shopping-list';
  const $list = $('#list');
  const $input = $('#add-input');
  const $count = $('#count');

  // --- model <-> DOM -------------------------------------------------------
  function rowFor(item) {
    return $('<li>', {
      'class': item.done ? 'done' : '',
      html: '<span></span>' +
            '<button class="up" title="Move up">&uarr;</button>' +
            '<button class="down" title="Move down">&darr;</button>' +
            '<button class="del" title="Delete">&times;</button>'
    }).find('span').text(item.text).end();
  }

  function readItems() {
    return $list.children('li').map(function () {
      const $li = $(this);
      return { text: $li.children('span').text(), done: $li.hasClass('done') };
    }).get();
  }

  function load() {
    try {
      const items = JSON.parse(localStorage.getItem(STORAGE_KEY) || '[]');
      $list.append(items.map(rowFor));
    } catch (e) { /* corrupt or unavailable storage: start empty */ }
  }

  // --- one place reacts to every change ------------------------------------
  $list.on('list:change', function () {
    const items = readItems();
    const left = items.filter(function (i) { return !i.done; }).length;
    $count.text(left + ' of ' + items.length + ' left');
    try { localStorage.setItem(STORAGE_KEY, JSON.stringify(items)); } catch (e) { /* ignore */ }
  });

  // --- add ----------------------------------------------------------------
  $('#add-form').on('submit', function (event) {
    event.preventDefault();
    const text = $input.val().trim();
    if (!text) return;
    rowFor({ text: text, done: false }).hide().appendTo($list).slideDown(150);
    $input.val('').focus();
    $list.trigger('list:change');
  });

  // --- delegated handlers --------------------------------------------------
  $list.on('click', '.del', function () {
    $(this).closest('li').slideUp(150, function () {
      $(this).remove();
      $list.trigger('list:change');
    });
  });

  $list.on('click', 'span', function () {
    $(this).closest('li').toggleClass('done');
    $list.trigger('list:change');
  });

  $list.on('click', '.up', function () {
    const $li = $(this).closest('li');
    $li.prev('li').before($li);
    $list.trigger('list:change');
  });

  $list.on('click', '.down', function () {
    const $li = $(this).closest('li');
    $li.next('li').after($li);
    $list.trigger('list:change');
  });

  // --- edit in place: double-click swaps the span for an input -------------
  $list.on('dblclick', 'span', function () {
    const $span = $(this);
    const $edit = $('<input type="text" class="edit">').val($span.text());
    $span.hide().after($edit);
    $edit.trigger('focus');
  });

  $list.on('keydown', 'input.edit', function (event) {
    const $edit = $(this);
    const $span = $edit.prev('span');
    if (event.key === 'Enter') {
      const text = $edit.val().trim();
      if (text) $span.text(text);
    } else if (event.key !== 'Escape') {
      return;                               // any other key: keep typing
    }
    $edit.remove();
    $span.show();
    $list.trigger('list:change');
  });

  // --- clear completed -----------------------------------------------------
  $('#clear-done').on('click', function () {
    $list.children('.done').remove();
    $list.trigger('list:change');
  });

  load();
  $list.trigger('list:change');
});

Points worth studying in this version:

  • Single source of truth for side effects. The count and the saved copy are derived from the DOM in one listener. Adding another reaction (a "dirty" marker, an analytics call) is one more .on('list:change', ...) and touches no mutation code. See Event Handling for namespaced custom events.

  • .text() at every boundary. Text enters the DOM through .text() in rowFor, is read back with .text(), and is stored as JSON, so a label such as <b>Eggs</b> stays literal text through a reload.

  • Storage failures are not fatal. Both the read and the write are wrapped in try/catch, because localStorage can be unavailable (private modes, blocked site data) or full, and the list should still work in memory.

  • Delete waits for the animation. .slideUp(150, callback) removes the row in the completion callback and only then announces the change, so the saved copy never lists a row that is still visible. With jQuery.fx.off = true the callback runs immediately, which is what makes the behaviour testable.

  • Edit keeps the row’s identity. The editor is a temporary <input> placed next to the label; the label is hidden, not replaced, so Escape restores it with no bookkeeping.

Testing the project without a browser

The list logic is plain DOM and events, so it runs under jsdom in Node. Turning effects off makes animations finish synchronously, and a short wait covers jQuery 3’s asynchronous ready callback. Save the listing above as app.js next to this file, run npm install jquery jsdom, then node list.test.js:

// run with: node list.test.js   (needs: npm install jquery jsdom)
const { JSDOM } = require('jsdom');
const assert = require('node:assert');
const fs = require('node:fs');

const html = `<!doctype html><body>
  <form id="add-form"><input id="add-input" name="item" type="text" required><button>Add</button></form>
  <p id="count"></p><button id="clear-done">Clear completed</button><ul id="list"></ul></body>`;

function boot(saved) {
  const dom = new JSDOM(html, { url: 'http://localhost/', runScripts: 'outside-only' });
  const { window } = dom;
  const $ = require('jquery')(window);
  window.jQuery = window.$ = $;
  $.fx.off = true;                                   // animations jump to their end state
  if (saved) window.localStorage.setItem('shopping-list', saved);
  window.eval(fs.readFileSync(__dirname + '/app.js', 'utf8'));
  return { $, window };
}

const settle = () => new Promise((resolve) => setTimeout(resolve, 20));   // jQuery 3 ready is async

(async () => {
  const { $, window } = boot();
  await settle();
  assert.strictEqual($('#count').text(), '0 of 0 left');

  const add = (text) => { $('#add-input').val(text); $('#add-form').trigger('submit'); };
  add('Milk'); add('<b>Eggs</b>'); add('   ');
  assert.strictEqual($('#list li').length, 2);                 // the blank entry was ignored
  assert.strictEqual($('#list b').length, 0);                  // markup was escaped, not parsed

  $('#list li').eq(0).find('span').trigger('click');           // toggle done
  assert.strictEqual($('#count').text(), '1 of 2 left');

  $('#list li').eq(1).find('.up').trigger('click');            // reorder
  assert.strictEqual($('#list li span').eq(0).text(), '<b>Eggs</b>');

  $('#clear-done').trigger('click');
  assert.strictEqual($('#list li').length, 1);

  const reloaded = boot(window.localStorage.getItem('shopping-list'));   // persistence round trip
  await settle();
  assert.strictEqual(reloaded.$('#list li').length, 1);
  console.log('all list tests passed');
})();

jsdom has no layout engine, so it can verify behaviour (which rows exist, in what order, with what classes and text) but not geometry or visual appearance; dimension methods such as .width() return 0 there. Use a real browser for those checks.

Exercises

  1. Add a Clear all link with a confirmation and make sure it also triggers list:change.

  2. Keep the completed rows at the bottom automatically, using the .detach() sort from DOM Manipulation.

  3. Replace the up and down buttons with jQuery UI sortable (see Plugins and Modern Usage) and keep persistence working.

  4. Package the behaviour as the checklist plugin from the plugins page and initialise it with one call.

  5. Port the finished page to native DOM APIs, using the migration map on the plugins page as a guide.

Modern equivalent

The same feature in vanilla JS: form.addEventListener('submit', ...), document.createElement('li'), list.addEventListener('click', e => { const li = e.target.closest('li'); ... }) for delegation, el.classList.toggle('done'), and refNode.before(li) / after(li) for reordering — plus a CSS transition instead of slideDown/slideUp. See Web programming basics and Events.
