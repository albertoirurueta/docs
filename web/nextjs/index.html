Next.js

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This section is written against Next.js 16.3 (16.3.8 was the latest release on 2026-10-03, when every version, URL and example in the section was checked, and the official documentation reported @doc-version 16.3.8), React 19.3 (19.3.0), Node.js 20.9 or later and TypeScript 5.1 or later. It describes the App Router as the primary model and the Pages Router wherever an existing application still uses it. Two caching models coexist in 16.3: the previous model (the default) and the opt-in Cache Components model (cacheComponents: true); every page that touches caching says which one each example uses.

Next.js publishes one major version a year and gives each one a long-term support life cycle. On 2026-10-03 the support policy listed Next.js 16.x (released 2025-10-21) as Active LTS — new features, bug fixes and security patches until Next.js 17 ships — and Next.js 15.x (released 2024-10-21) as Maintenance LTS, which receives only critical bug fixes and security updates, as semver-minor releases, for two years from its first release; 14.x and older are unsupported. Patch releases are frequent, and several of them in 2026 were security releases, so pin an exact version and read the release notes before updating. The Release Cadence and Support Policy section and the What’s Changed & Upgrading page cover the details.

What Next.js is

Next.js is an open-source React framework, maintained by Vercel and developed in the open on GitHub, for building full-stack web applications. React describes the user interface as components; Next.js supplies everything around them that a production site needs:

  • file-system routing: the App Router (app/, recommended) built on React Server Components, with the older Pages Router (pages/) still supported

  • React Server Components, Client Components and Server Functions (Server Actions)

  • every rendering strategy — server-side rendering, client-side rendering, static site generation, incremental static regeneration and Partial Prerendering — with streaming and hydration

  • a multi-layer cache with explicit revalidation APIs

  • Route Handlers for HTTP APIs, and Proxy (called Middleware before Next.js 16) in front of every request

  • image, font and script optimisation, and the Metadata API for SEO

  • Turbopack, the default bundler since Next.js 16, and the React Compiler

  • deployment to a Node.js server, a Docker container, static hosting, or a platform through an adapter

A new project is one command away:

npx create-next-app@latest bookshelf --yes
cd bookshelf
npm run dev

Source: Installation

Who this section is for

The section is for developers who already know React and want to build and ship React applications with Next.js:

  • React developers moving from a client-only single-page application (for example a Vite SPA with React Router) to server rendering, static generation and React Server Components

  • readers of older Next.js books and tutorials, which mostly target the Pages Router and Next.js 12 or 13, who need to know what changed (async request APIs, proxy.ts, Turbopack, the new caching APIs, Auth.js v5)

  • back-end developers on this site’s FastAPI, NestJS or Django sections who want a front end for the same Bookshelf API, and teams choosing between Next.js and other React or non-React frameworks

It does not re-teach React itself: components, Hooks, Suspense, Actions and the React Compiler are covered in the React Reference, and the pages here link there instead of repeating it.

Running example

Every example builds one small, original application, Bookshelf: a Next.js App Router front end in the same domain as the Python FastAPI, NestJS and Django sections, so that the stacks can be compared page by page. It extends the Next.js files sketched on NestJS vs Next.js and has:

  • a public catalogue of books, authors and reviews: statically generated book pages (generateStaticParams with ISR or 'use cache'), a server-rendered search page that reads searchParams, and client-side filters

  • a personalised header and a "my reviews" area, rendered dynamically from cookies() and streamed with Suspense

  • review creation and editing with Server Actions, useActionState, useOptimistic and updateTag

  • an intercepted-route modal for book covers and a parallel-route slot

  • sign-in with Auth.js v5, a Data Access Layer, and forbidden() / unauthorized()

  • a JSON API built with Route Handlers, plus a backend-for-frontend variant that proxies the FastAPI, NestJS or Django Bookshelf API

  • proxy.ts for locale detection (app/[locale]) and an optimistic authentication check

  • next/image covers, next/font, Tailwind CSS v4, and the Metadata API with Open Graph images, a sitemap and robots.txt

  • tests with Vitest and Playwright

  • a Docker standalone deployment, and a static-export variant of the catalogue

Figure 2. The Bookshelf application: clients, the Next.js server and its backing services

The final project layout (app/[locale]/(shop), app/[locale]/(account), @modal, components/, lib/dal.ts, lib/actions/, proxy.ts, instrumentation.ts and next.config.ts) is assembled on Project Structure. Stripe and headless-CMS commerce concepts are covered by a separate worked example on Advanced Patterns.
