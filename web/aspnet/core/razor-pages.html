Razor Pages

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A Razor Page pairs one .cshtml file with one PageModel code-behind class, so each URL has a single, self-contained handler instead of sharing a controller with unrelated actions.

Registering Razor Pages

builder.Services.AddRazorPages();

var app = builder.Build();
app.MapRazorPages();

Pages live under Pages/ by convention; Pages/Products/Edit.cshtml is served at /Products/Edit. See Introduction to Razor Pages.

@page and route templates

@page must be the first directive in the file — it both marks the file as a page and can carry a route template, exactly like [Route] on a controller:

@page "{id:int?}"
@model EditModel
<form method="post">
    <input asp-for="Product.Name" />
    <span asp-validation-for="Product.Name"></span>
    <button>Save</button>
</form>

Constraints (\{id:int}), optional segments (\{id?}), and catch-alls work the same as in routing. See Razor Pages route and app conventions.

PageModel and handler selection

public sealed class EditModel(IProductService products) : PageModel
{
    [BindProperty] public ProductInput Product { get; set; } = new();

    public async Task<IActionResult> OnGetAsync(int? id)
    {
        if (id is int i) Product = await products.GetInputAsync(i);
        return Page();
    }

    public async Task<IActionResult> OnPostAsync()
    {
        if (!ModelState.IsValid) return Page();
        await products.SaveAsync(Product);
        return RedirectToPage("Index");
    }
}

Handlers are selected by HTTP verb from the method name: OnGet/OnGetAsync, OnPost/OnPostAsync, and so on. A page can define named handlers for more than one action per page:

public async Task<IActionResult> OnPostDeleteAsync(int id) { ... }   // handler = "Delete"
<form method="post" asp-page-handler="Delete" asp-route-id="@p.Id">
    <button>Delete</button>
</form>

See Named handler methods.

[BindProperty]

[BindProperty] model-binds a property from the request the same way an action parameter would; add SupportsGet = true to also bind it on GET (off by default, since binding on GET from arbitrary query values is rarely intended):

[BindProperty(SupportsGet = true)]
public string? Search { get; set; }

See Model Binding and Validation for binding sources and validation, which apply identically to Razor Pages and MVC.

Page conventions

Configure routing, authorization, and folder-wide behavior from AddRazorPages, instead of repeating attributes on every page:

builder.Services.AddRazorPages(o =>
{
    o.Conventions.AuthorizeFolder("/Admin");
    o.Conventions.AllowAnonymousToPage("/Admin/Login");
    o.Conventions.AddPageRoute("/Products/Details", "products/{id:int}/details");
});

See Razor Pages authorization conventions.

Filters

IPageFilter / IAsyncPageFilter run around page handler execution — the Razor Pages analog of MVC action filters:

public sealed class AuditPageFilter : IAsyncPageFilter
{
    public Task OnPageHandlerSelectionAsync(PageHandlerSelectedContext context) => Task.CompletedTask;

    public async Task OnPageHandlerExecutionAsync(
        PageHandlerExecutingContext context, PageHandlerExecutionDelegate next)
    {
        // runs immediately before the handler
        await next();
        // runs after the handler, before the result executes
    }
}

Register it globally (o.Filters.Add<AuditPageFilter>() in AddRazorPages) or per page via a [TypeFilter] on the PageModel. See Filters and the MVC Pipeline for the full filter pipeline shared with MVC.

Razor Pages vs. MVC

Choose When

Razor Pages

The site is a set of pages/forms; each URL has one clear responsibility; you want the view and its handler colocated.

MVC

Many actions share a controller, filters, or a non-page-shaped URL space; building HTTP APIs alongside views (see MVC Controllers and Views).

Both share the same routing, model binding, validation, and Razor rendering pipeline underneath, so the choice is organizational, not a difference in capability. See Razor Pages vs MVC controllers and views.

Deep dive: a searchable, paged product list

A page that lists data adds three concerns the edit page does not have: it must work on GET (so it is bookmarkable and shareable), it must keep its filter state when paging, and it often needs a small side endpoint for the browser to call. Razor Pages handles all three inside one PageModel.

flowchart TD REQ["GET /Products?Q=shelf&PageNumber=2"] --> RT["Routing selects the page"] RT --> BIND["Bind properties marked SupportsGet"] BIND --> SEL{"handler query value?"} SEL -- "none" --> OG["OnGetAsync"] SEL -- "handler=Suggest" --> OS["OnGetSuggestAsync"] OG --> PAGE["Page result renders Index.cshtml"] OS --> JSON["JsonResult, no view"]

The page model

public sealed record PagedResult<T>(IReadOnlyList<T> Items, int TotalCount);

public sealed class IndexModel(IProductService products) : PageModel
{
    private const int PageSize = 10;

    [BindProperty(SupportsGet = true)] public string? Q { get; set; }
    [BindProperty(SupportsGet = true)] public int PageNumber { get; set; } = 1;

    public IReadOnlyList<ProductDto> Items { get; private set; } = [];
    public int TotalPages { get; private set; }

    public async Task OnGetAsync(CancellationToken ct)
    {
        PageNumber = Math.Max(1, PageNumber);                       // never trust a query-string number
        var result = await products.SearchAsync(Q, PageNumber, PageSize, ct);

        Items = result.Items;
        TotalPages = (int)Math.Ceiling(result.TotalCount / (double)PageSize);
    }

    // GET /Products?handler=Suggest&term=boo  -- named handler, bound parameter, JSON result
    public async Task<IActionResult> OnGetSuggestAsync(string term, CancellationToken ct)
        => new JsonResult(await products.SuggestAsync(term, ct));
}

A handler that returns void or Task renders the page implicitly. A handler that returns IActionResult chooses the result itself, which is how OnGetSuggestAsync skips the view and returns JSON from the same URL space. The CancellationToken parameter is bound from HttpContext.RequestAborted, so a database query stops when the browser navigates away.

The view

@page
@model IndexModel

<form method="get">
    <input asp-for="Q" placeholder="Search products" />
    <button type="submit">Search</button>
</form>

<ul>
@foreach (var p in Model.Items)
{
    <li><a asp-page="Details" asp-route-id="@p.Id">@p.Name</a> -- @p.Price.ToString("C")</li>
}
</ul>

<nav>
    @if (Model.PageNumber > 1)
    {
        <a asp-page="Index" asp-route-q="@Model.Q" asp-route-pagenumber="@(Model.PageNumber - 1)">Previous</a>
    }
    <span>Page @Model.PageNumber of @Model.TotalPages</span>
    @if (Model.PageNumber < Model.TotalPages)
    {
        <a asp-page="Index" asp-route-q="@Model.Q" asp-route-pagenumber="@(Model.PageNumber + 1)">Next</a>
    }
</nav>

Because the search form uses method="get", the filter lives in the URL, and the paging links carry q forward with asp-route-q. Route values that are not in the page’s route template are appended to the query string, so @page needs no template here. The Details link uses the asp-page Tag Helper, which generates the URL from the page name and survives moving the page’s route later.

Testing the page model without a server

A PageModel is a plain class, so the paging arithmetic can be tested directly:

public sealed class FakeProducts(int total) : IProductService
{
    public Task<PagedResult<ProductDto>> SearchAsync(string? q, int page, int pageSize, CancellationToken ct)
    {
        var items = Enumerable.Range((page - 1) * pageSize, Math.Max(0, Math.Min(pageSize, total - (page - 1) * pageSize)))
                              .Select(i => new ProductDto(i, $"Product {i}", 9.99m)).ToList();
        return Task.FromResult(new PagedResult<ProductDto>(items, total));
    }

    public Task<IReadOnlyList<string>> SuggestAsync(string term, CancellationToken ct)
        => Task.FromResult<IReadOnlyList<string>>([]);
}

[Fact]
public async Task Last_page_holds_the_remainder()
{
    var model = new IndexModel(new FakeProducts(total: 25)) { PageNumber = 3 };

    await model.OnGetAsync(CancellationToken.None);

    Assert.Equal(3, model.TotalPages);
    Assert.Equal(5, model.Items.Count);
}

[Fact]
public async Task Out_of_range_page_numbers_are_clamped()
{
    var model = new IndexModel(new FakeProducts(total: 25)) { PageNumber = -4 };

    await model.OnGetAsync(CancellationToken.None);

    Assert.Equal(1, model.PageNumber);
}

IProductService here is assumed to declare SearchAsync and SuggestAsync with the signatures shown. Rendering, routing and Tag Helper output are covered by integration tests with WebApplicationFactory, which request /Products?Q=shelf&PageNumber=2 and assert on the returned HTML; see Testing.
