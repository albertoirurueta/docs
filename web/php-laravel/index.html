PHP and Laravel

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This section is about building web applications with PHP. It starts with what plain PHP gives you: how a request reaches a script, how to read input, escape output, keep sessions, accept uploads, query a database with PDO and avoid the common security mistakes. It then builds the same kind of application with Laravel, the most widely used PHP framework, from a first route to production. It is written for developers who know some PHP, or another web framework, and want to build and run current PHP web applications. The language itself (syntax, types, objects, the standard library, Composer and testing tools) is covered in the PHP Reference, which these pages link to rather than repeat.

For the PHP-based online store platforms, see the E-commerce section, in particular PrestaShop, Magento and WooCommerce.

The pages are written against Laravel 13.x (13.34.0) on PHP 8.3 to 8.5, checked on 2026-10-05. Laravel ships one major version a year, and each one gets bug fixes for 18 months and security fixes for two years. Laravel 13 was released on 2026-03-17 and requires PHP 8.3 or newer. On 2026-10-05, Laravel 12 receives security fixes only, and 11 and older receive none. Laravel 14 is expected in the first quarter of 2027. PHP itself supports each release for four years, and 8.3 is in security-only support until the end of 2027. The details are on What’s Changed and Upgrading.

The two running examples

The examples on these pages build two small, original applications in the same domain as the Django, FastAPI and NestJS sections of this site, so that the stacks can be compared:

  • Bookshelf Lite is a book catalogue in plain PHP with PDO, a front controller and no framework. The plain PHP pages build it so that you can see exactly what a framework takes over.

  • Bookshelf is the same catalogue in Laravel 13: books, authors, reviews and loans with Blade pages, search and pagination, a starter-kit login with policies for editing reviews, cover uploads to an S3-compatible disk, English and Spanish translations, a live feed of new reviews over Reverb (and a server-sent events variant), moderation mail and notifications on a queue, Redis caching, a versioned JSON API with Sanctum and a JSON:API variant, scheduled tasks, and a Docker and FrankenPHP deployment.

Every Laravel example was run in that application, and its test suite (109 Pest tests at the end of this section) covers the examples that have behaviour to check. The pages say where something could not be run in the environment used to write them.
