Where Older Books and Tutorials Are Outdated

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

WordPress keeps old code working for a long time, so outdated advice rarely fails loudly: a post type registered without show_in_rest still saves posts, a 777 directory still accepts uploads, and a sitemap ping still returns a response. This page collects, in one place, the statements in older books and tutorials that the rest of this section corrects, with the version where the behaviour changed, the page that covers it in depth and the official source. It is a reference to check advice against before following it, not a substitute for the pages it links.

The page was written against WordPress 7.1.3 (released 2026-10-06), the release the examples in this section were tested on; WordPress 7.1.4 (released 2026-10-28) is the current security release and should be used in production, and WordPress 7.2 is in beta, planned for 2026-12-08. Other versions referred to: PHP 7.4 minimum and 8.3+ recommended, theme.json version 3, Gutenberg 24.2.0, @wordpress/scripts 37.0.0, @wordpress/create-block 5.0.0, @wordpress/env 12.0.0, @wordpress/interactivity 8.0.0, WordPress Coding Standards 3.4.1 and WP-CLI 2.12.0. Everything was checked on 2026-10-28.

The books compared

Three books published in 2024 were compared with the official documentation. They remain useful for their operational advice, and much of what they say about writing, publishing, vetting plugins, hosting choices and incident response still holds. Where they disagree with the official documentation, the official documentation wins. The tables below refer to them by short title:

Short title Book Targets and scope

All-in-One

Lisa Sabin-Wilson, WordPress All-in-One For Dummies, 5th edition (Wiley, 2024)

WordPress 6.3 to 6.4; site owners and administrators; block editor and block themes from the user’s side; no plugin, theme or block development

Pro WordPress

Sivaraj Selvaraj, Pro WordPress: Mastering the Techniques for Building, Securing and Scaling Websites (Apress, 2024)

No version stated (6.2 is the latest named); classic themes only; hosting, security, performance, SEO, Multisite and scaling; no block themes, theme.json, blocks or REST development

Ultimate Handbook

Daniel Bisett and Tricia Elizabeth Ulberg, Ultimate WordPress Handbook (Orange Education/AVA, 2024)

WordPress 6.4 to 6.6 and Twenty Twenty-Four; Customizer-centred design with a commercial theme and builder; troubleshooting runbooks, SEO, analytics and privacy

Rows marked Tutorials come from the wider body of blog posts, snippets and handbooks written for WordPress 5.x and early 6.x. None of the three books covers what arrived between 6.5 and 7.1 (Font Library, Block Bindings, the Interactivity API, Script Modules, section styles, pattern overrides, PHP-only blocks, the Abilities API, the AI Client, responsive styles, the always-iframed editor); for those the handbooks, the Make WordPress Core field guides and developer notes, and the WordPress Developer Blog are the only sources.

REST API: Extending It

Make WordPress Core: REST API Changes in WordPress 5.5

The REST route claim in the table above is easiest to see in code. The first block is the form many older tutorials show; the second is the form WordPress 5.5 and later expect.

<?php
// Before: no permission_callback, which triggers a _doing_it_wrong notice since 5.5.
add_action( 'rest_api_init', function () {
	register_rest_route( 'lumen/v1', '/ping', array(
		'methods'  => 'GET',
		'callback' => 'lumen_ping',
	) );
} );

// After: the access decision is explicit, here for a public read-only route.
add_action( 'rest_api_init', function () {
	register_rest_route( 'lumen/v1', '/ping', array(
		'methods'             => WP_REST_Server::READABLE,
		'callback'            => 'lumen_ping',
		'permission_callback' => '__return_true',
	) );
} );

How to read older material

  • Check the version the text targets. A book or post written for 6.2 to 6.6 predates everything in the 6.7 to 7.1 rows of Versions and Release Cycle.

  • Ask whether the advice is about classic or block themes. Template files, the Customizer, widgets and Appearance > Menus remain correct for classic themes; the equivalents for block themes are in the Themes Overview.

  • Treat security snippets with suspicion. Missing nonces, missing capability checks, unescaped output and string-built SQL are the most common defects in copied code; compare them with Security for Developers.

  • Prefer the handbooks, field guides and developer notes. They are updated with each release; this page and the section bibliography in WordPress link the ones used here.
