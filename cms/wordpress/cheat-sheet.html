Cloud deployment

The summary printed in the PDF for running WordPress on many pods in the cloud on Amazon EKS (checked on 2026-10-29); each row is explained on the pages above.

Topic Rule

Database

RDS for MariaDB 11.8 or MySQL 8.4 (Aurora MySQL 3 too), Multi-AZ, TLS with a verified CA through MYSQL_CLIENT_FLAGS and a db.php drop-in; an application user plus a separate migration user; keep pods x pm.max_children below max_connections.

State placement

Media: offload plugin and S3 behind CloudFront (EFS only as fallback; PHP code never on EFS). Object cache: ElastiCache for Valkey with WP_REDIS_*. Sessions: none (cookies and session_tokens). Configuration: environment variables read by wp-config.php; image immutable with DISALLOW_FILE_MODS.

Cron

DISABLE_WP_CRON true; one CronJob with concurrencyPolicy: Forbid running wp cron event run --due-now; web pods never schedule.

Release steps

Build one image per Git SHA, push to ECR, helm upgrade with a pre-upgrade Job running wp core update-db (add --network on Multisite), rolling update, --rollback-on-failure (Helm 4; --atomic in Helm 3).

Key commands

wp redis status, wp cron event list, wp core update-db, wp search-replace, kubectl -n lumenpress rollout status deployment/lumenpress-web, helm upgrade lumenpress ./lumenpress-wordpress.

Worked example

A small plugin file that combines the two hook types: an action that registers a shortcode on init, and a filter that appends a line to the content of single posts. Both callbacks are prefixed, escape their output, and the file refuses direct access.

<?php
/**
 * Plugin Name: Lumen Hello
 * Description: Registers a shortcode and appends a note to single posts.
 * Version:     1.0.0
 * Requires PHP: 7.4
 */

defined( 'ABSPATH' ) || exit;

/** Action: register the shortcode once WordPress has loaded. */
function lumen_hello_register_shortcode() {
	add_shortcode( 'lumen_hello', 'lumen_hello_render' );
}
add_action( 'init', 'lumen_hello_register_shortcode' );

/** Shortcode callback: return the markup, never echo it. */
function lumen_hello_render( $atts ) {
	$atts = shortcode_atts( array( 'name' => 'reader' ), $atts, 'lumen_hello' );

	return '<p>' . esc_html( 'Hello, ' . $atts['name'] ) . '</p>';
}

/** Filter: receive the content, return it modified. */
function lumen_hello_append_note( $content ) {
	if ( is_singular( 'post' ) && in_the_loop() && is_main_query() ) {
		$content .= '<p><em>' . esc_html__( 'Thanks for reading.', 'lumen-hello' ) . '</em></p>';
	}

	return $content;
}
add_filter( 'the_content', 'lumen_hello_append_note' );

An action callback does its work and returns nothing; a filter callback must always return a value, even when it changes nothing.
