Hooks: Actions and Filters

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Hooks are the extension mechanism of WordPress: core calls do_action() and apply_filters() at hundreds of named points, and plugins and themes attach callbacks to those names. This page goes beyond the short introduction in Introduction and Architecture: how callbacks are ordered and how many arguments they receive, why a removal silently fails, how the lumen-catalog plugin offers its own lumen_catalog_* hooks, how code tells which hook is running, the order in which core fires its actions on front-end, admin and REST requests, and the older pluggable functions mechanism.

The page was written against WordPress 7.1.3 (released 2026-10-06; 7.1.4, a security release of 2026-10-28, is the version to run in production), PHP 7.4 minimum and 8.3+ recommended, and WP-CLI 2.12.0, and checked on 2026-10-28. WordPress 7.2 is in beta and due in December 2026; it does not change the Plugin API so far. Two recent versions did: 6.9 added a $priority parameter to has_filter() and has_action(), and 7.1 changed how object and closure callbacks are identified internally. Every output below comes from a 7.1.3 site at lumenpress.test running Twenty Twenty-Five and the lumen-catalog plugin, on the stack described in Local Development Environments. For readability the examples are short procedural snippets with prefixed names (Lumen_Catalog_Stock, lumen_catalog_import_book()); the plugin itself keeps its code under the Lumen\Catalog namespace, as shown in Plugin Fundamentals.

Actions and filters

Both kinds of hook share one registry and one set of functions; they differ in what is expected of the callback.

Internally add_action() just calls add_filter(). Each hook name with callbacks owns a WP_Hook object (4.7+) in the global $wp_filter, which groups the callbacks by priority; $wp_current_filter is the stack of hooks running now. "No side effects in filters" is a design rule that WordPress does not enforce, and it matters because filters run more often than they seem: the_title for every menu item and REST response, the_content for excerpts and feeds too.

Namespaced functions need their full name, 'Lumen\Catalog\register_book_type' or __NAMESPACE__ . '\register_book_type'. A bare name is looked up in the global namespace when the hook fires, and call_user_func_array() fails with an "invalid callback" error.

Priority

Lower priorities run first, equal ones in the order they were added; the default is 10, and negative values, PHP_INT_MIN and PHP_INT_MAX are valid. A plugin filtering the_content chooses its place among core’s callbacks:

A plugin callback at 10 runs after core’s callbacks at 10 (added earlier) but before do_shortcode, so shortcodes in its markup are expanded; one before 9 sees raw block comments. The Lumen Press details box is appended at 20. A callback added to a hook while it runs is honoured if its priority has not been reached yet, because WP_Hook re-sorts the active iteration (4.7+).

Accepted arguments

WP_Hook passes the first $accepted_args arguments of the hook, all of them if the number is larger, none if it is 0. The default of 1 suits filters that need only the value, but not callbacks that need the context: the_title passes the title and the post ID, save_post the ID, the post and an update flag. The details box below is a filter at priority 20 that also fires a filter of its own, with two arguments, so that other code can add rows:

wp-content/plugins/lumen-catalog/includes/book-details.php
<?php
defined( 'ABSPATH' ) || exit;

// Priority 20: after do_blocks (9), wpautop (10), do_shortcode (11) and wp_filter_content_tags (12).
add_filter( 'the_content', 'lumen_catalog_append_book_details', 20 );

/**
 * Appends the details box to a book's content in the main loop.
 *
 * @param string $content Post content, already rendered by earlier callbacks.
 * @return string
 */
function lumen_catalog_append_book_details( $content ) {
	if ( ! is_singular( 'lp_book' ) || ! in_the_loop() || ! is_main_query() ) {
		return $content; // A filter always returns a value, even when it changes nothing.
	}

	$post_id = get_the_ID();
	$rows    = array(
		__( 'ISBN', 'lumen-catalog' )  => get_post_meta( $post_id, 'lp_isbn', true ),
		__( 'Pages', 'lumen-catalog' ) => get_post_meta( $post_id, 'lp_pages', true ),
	);

	/**
	 * Filters the rows of the book details box.
	 *
	 * @since 0.1.0
	 * @param array<string,string> $rows    Label => value pairs. Empty values are skipped.
	 * @param int                  $post_id Book ID.
	 */
	$rows = apply_filters( 'lumen_catalog_book_details_rows', $rows, $post_id );

	$html = '';
	foreach ( $rows as $label => $value ) {
		if ( '' !== (string) $value ) {
			$html .= '<dt>' . esc_html( $label ) . '</dt><dd>' . esc_html( $value ) . '</dd>';
		}
	}

	return $content . '<dl class="lp-book-details">' . $html . '</dl>';
}

Source: Plugin Handbook: Filters

The main plugin file loads it with require_once __DIR__ . '/includes/book-details.php';. The checks on is_singular(), in_the_loop() and is_main_query() keep the box out of excerpts, feeds, Query Loop blocks and the REST API, which all apply the_content too. To see what is attached to a hook, read $GLOBALS['wp_filter']['the_title']->callbacks: an array keyed by priority, then by callback identifier.

Two mistakes are not caught when the callback is added. A callback that requires more parameters than $accepted_args provides throws an ArgumentCountError when the hook fires, a fatal error on a real request (on the test site, "Too few arguments to function lumen_demo_title(), 1 passed in class-wp-hook.php on line 355 and exactly 2 expected"). A filter that does not return hands null on, and get_the_title() then returns NULL.

Removing callbacks

remove_action() and remove_filter() return whether a callback was removed. They fail silently, returning false, unless everything matches the original registration:

  • The same hook name and priority. A callback added at 20 needs remove_filter( $hook, $callback, 20 ).

  • The same callback. WordPress compares an identifier built by the internal _wp_filter_build_unique_id(): the name for a function, Class::method for a static method, an instance ID for objects and closures (on the test site 1961mark_out_of_stock for the stock badge below). Since 7.1 that ID comes from spl_object_id() instead of spl_object_hash(), and since 7.1.1 a closure’s ID has an spl_object_id: prefix so PHP never makes it an integer array key. Another instance of the same class, or a closure with the same code, is a different callback.

  • The right moment: after the callback is added and before the hook fires.

The catalogue’s stock badge (the lp_stock meta comes from the distributor sync in WP-Cron and Scheduled Tasks) is attached from an object:

wp-content/plugins/lumen-catalog/includes/class-lumen-catalog-stock.php
<?php
defined( 'ABSPATH' ) || exit;

/**
 * Stock badge in book titles. Its hooks are attached from an object, so removing them needs the same instance.
 */
final class Lumen_Catalog_Stock {

	/** @var Lumen_Catalog_Stock|null The instance that owns the hooks. */
	private static $instance = null;

	/**
	 * Returns the instance, creating it and attaching its callbacks on first use.
	 */
	public static function instance() {
		if ( null === self::$instance ) {
			self::$instance = new self();
			add_filter( 'the_title', array( self::$instance, 'mark_out_of_stock' ), 10, 2 );
		}
		return self::$instance;
	}

	/**
	 * Appends "(out of stock)" to the title of books whose stock is zero.
	 *
	 * @param string $title   Post title.
	 * @param int    $post_id Post ID, the second argument of the_title.
	 * @return string
	 */
	public function mark_out_of_stock( $title, $post_id = 0 ) {
		if ( 'lp_book' === get_post_type( $post_id ) && '0' === get_post_meta( $post_id, 'lp_stock', true ) ) {
			/* translators: %s: book title. */
			$title = sprintf( __( '%s (out of stock)', 'lumen-catalog' ), $title );
		}
		return $title;
	}
}

add_action( 'plugins_loaded', array( 'Lumen_Catalog_Stock', 'instance' ) );

Source: Plugin Handbook: Advanced Topics

The default value of $post_id keeps the callback working where the_title is applied with one argument. The static accessor makes the callback removable: a plugin that attaches array( new Something(), 'method' ) and keeps no reference leaves only remove_all_filters(), which also removes core’s and every other plugin’s callbacks. This script checks each rule; the comments show what wp eval-file printed:

hook-removal-demo.php
<?php
// Run with: wp eval-file hook-removal-demo.php
add_filter( 'lumen_demo', 'strtoupper', 20 );
var_dump( remove_filter( 'lumen_demo', 'strtoupper' ) );       // bool(false): wrong priority (default 10).
var_dump( remove_filter( 'lumen_demo', 'strtoupper', 20 ) );   // bool(true): same name and priority.

$exclaim = static fn( $text ) => $text . '!';
add_filter( 'lumen_demo', $exclaim );
var_dump( remove_filter( 'lumen_demo', static fn( $text ) => $text . '!' ) ); // bool(false): look-alike closure.
var_dump( remove_filter( 'lumen_demo', $exclaim ) );                          // bool(true): the same closure.

$stock = Lumen_Catalog_Stock::instance();
var_dump( has_filter( 'the_title', array( $stock, 'mark_out_of_stock' ) ) );                   // int(10): its priority.
var_dump( remove_filter( 'the_title', array( new Lumen_Catalog_Stock(), 'mark_out_of_stock' ) ) ); // bool(false): other instance.
var_dump( remove_filter( 'the_title', array( $stock, 'mark_out_of_stock' ) ) );                // bool(true): same instance.

Source: Code Reference: remove_filter(), Code Reference: has_filter()

Lumen Press removes the badge from a must-use plugin, which loads before the catalogue. The removal therefore waits: add_action( 'plugins_loaded', static fn() => remove_filter( 'the_title', array( Lumen_Catalog_Stock::instance(), 'mark_out_of_stock' ) ), 20 ). Core’s generator tag, attached in default-filters.php before any plugin loads, can be removed at once with remove_action( 'wp_head', 'wp_generator' ). With lp_stock set to 0, the book heading changes from The Quiet Lighthouse (out of stock) to The Quiet Lighthouse, and the <meta name="generator"> tag disappears. If the catalogue can be inactive, guard the removal with class_exists( 'Lumen_Catalog_Stock' ).

Custom hooks

Hooks fired by a plugin let other code change it without editing it, so lumen-catalog stays generic. The rules:

  • Prefix every hook name (lumen_catalog_). Two plugins firing an unprefixed book_imported run each other’s code.

  • Lowercase words separated by underscores; WPCS reports other names (WordPress.NamingConventions.ValidHookName).

  • An action where others react, a filter where others decide, and pass the context callbacks need after the value.

  • Document each hook with a docblock right above the call: summary, @since, one @param per argument.

  • Treat hooks as public API. Renaming one or changing its arguments breaks other people’s code; deprecate instead.

The import function behind wp lumen import fires a general filter, a filter whose name contains the source, and an action once the book exists:

wp-content/plugins/lumen-catalog/includes/import.php
<?php
defined( 'ABSPATH' ) || exit;

/**
 * Creates a book from an import row.
 *
 * @param array  $row    Keys: title, isbn, pages.
 * @param string $source Where the row comes from, for example 'csv' or 'distributor'.
 * @return int|WP_Error Post ID, or an error from wp_insert_post().
 */
function lumen_catalog_import_book( array $row, $source ) {
	/**
	 * Filters an import row from any source.
	 *
	 * @since 0.1.0
	 * @param array  $row    Import row.
	 * @param string $source Import source.
	 */
	$row = apply_filters( 'lumen_catalog_import_row', $row, $source );

	/**
	 * Filters an import row from one source only. The dynamic part, `$source`, is the import source.
	 *
	 * @since 0.1.0
	 * @param array $row Import row.
	 */
	$row = apply_filters( "lumen_catalog_import_row_{$source}", $row );

	$post_id = wp_insert_post(
		array(
			'post_type'   => 'lp_book',
			'post_status' => 'publish',
			'post_title'  => sanitize_text_field( $row['title'] ?? '' ),
			'meta_input'  => array(
				'lp_isbn'  => sanitize_text_field( $row['isbn'] ?? '' ),
				'lp_pages' => absint( $row['pages'] ?? 0 ),
			),
		),
		true
	);

	if ( ! is_wp_error( $post_id ) ) {
		/**
		 * Fires after a book has been imported.
		 *
		 * @since 0.1.0
		 * @param int    $post_id New book ID.
		 * @param array  $row     Import row, after the filters.
		 * @param string $source  Import source.
		 */
		do_action( 'lumen_catalog_book_imported', $post_id, $row, $source );
	}

	return $post_id;
}

	'lumen_catalog_import_row_distributor',
	static function ( array $row ) {
		$row['isbn']  = preg_replace( '/[^0-9X]/', '', strtoupper( $row['isbn'] ?? '' ) );

	10,

The plugin’s own dynamic hook

save_post_lp_book fires inside wp_insert_post(), so a callback that calls wp_update_post() on the same book triggers itself again. Detaching the callback around the update prevents the loop:

wp-content/plugins/lumen-catalog/includes/default-excerpt.php
<?php
defined( 'ABSPATH' ) || exit;

add_action( 'save_post_lp_book', 'lumen_catalog_default_excerpt', 10, 3 );

/**
 * Fills an empty excerpt from the first words of the content when a book is saved.
 *
 * @param int     $post_id Book ID.
 * @param WP_Post $post    Book object.
 * @param bool    $update  Whether an existing book was updated.
 */
function lumen_catalog_default_excerpt( $post_id, $post, $update ) {
	if ( wp_is_post_revision( $post_id ) || wp_is_post_autosave( $post_id ) || '' !== $post->post_excerpt ) {
		return;
	}

	// wp_update_post() fires save_post_lp_book again: detach first, or the callback calls itself forever.
	remove_action( 'save_post_lp_book', 'lumen_catalog_default_excerpt', 10 );
	wp_update_post(
		array(
			'ID'           => $post_id,
			'post_excerpt' => wp_trim_words( wp_strip_all_tags( $post->post_content ), 20 ),
		)
	);
	add_action( 'save_post_lp_book', 'lumen_catalog_default_excerpt', 10, 3 );
}

Inspecting hooks at run time

Function Answers

did_action( $hook ), did_filter( $hook ) (6.1+)

How many times the hook fired in this request: the usual "too early?" and "only once" guard

doing_action( $hook = null ), doing_filter( $hook = null )

Whether that hook is running now, anywhere in the stack; without an argument, whether any hook is. Both read the same stack: doing_action() calls doing_filter()

current_filter(), current_action()

The innermost hook running now; one callback attached to several hooks can branch on it

has_action(), has_filter()

Whether a hook has callbacks, or the priority of one callback (which can be 0, so compare with false using ===); since 6.9 an optional priority argument makes it return a boolean

The all hook

Callbacks that run before every action and filter, receiving the hook name first

The order in which core fires its hooks

The order explains most "my code does not run" reports: a callback added after its hook has fired never runs, and data exists only from the hook that creates it. It can be recorded with a must-use plugin on the all hook that logs each action once, at its first firing, and also the filters matching an optional regular expression:

wp-content/mu-plugins/lumen-hook-log.php
<?php
/**
 * Plugin Name: Lumen Hook Log
 * Description: Logs the first firing of each action (and of matching filters) in one request. Local only.
 */
defined( 'ABSPATH' ) || exit;

// LUMEN_HOOK_LOG: true logs actions; a regular expression also logs matching filters, shown in [brackets].
if ( 'local' !== wp_get_environment_type() || ! defined( 'LUMEN_HOOK_LOG' ) || ! LUMEN_HOOK_LOG ) {
	return;
}

$GLOBALS['lumen_hook_log'] = array();

add_action(
	'all',
	static function ( $hook_name ) {
		static $actions_seen = array();
		$log                 = &$GLOBALS['lumen_hook_log'];

		// do_action() counts the hook in $wp_actions before it calls 'all'; apply_filters() does not.
		$count                      = did_action( $hook_name );
		$is_action                  = $count > ( $actions_seen[ $hook_name ] ?? 0 );
		$actions_seen[ $hook_name ] = $count;

		if ( $is_action ) {
			$log[ $hook_name ] = $log[ $hook_name ] ?? $hook_name;
		} elseif ( is_string( LUMEN_HOOK_LOG ) && preg_match( LUMEN_HOOK_LOG, $hook_name ) ) {
			$log[ $hook_name ] = $log[ $hook_name ] ?? "[{$hook_name}]";
		}
	}
);

add_action(
	'shutdown',
	static function () {
		$uri = isset( $_SERVER['REQUEST_URI'] ) ? sanitize_text_field( wp_unslash( $_SERVER['REQUEST_URI'] ) ) : '';
		error_log( "Hooks for {$uri}:" . PHP_EOL . wordwrap( implode( ' ', $GLOBALS['lumen_hook_log'] ), 116 ) );
	},
	PHP_INT_MAX
);

Source: Code Reference: all, Advanced Administration Handbook: Must Use Plugins

It needs WP_ENVIRONMENT_TYPE set to local, WP_DEBUG_LOG set to true and the constant itself, for example wp config set LUMEN_HOOK_LOG true --raw. It adds a function call to every hook firing, thousands per request, so it never belongs on a shared site.

A logged-in request for the book list (/wp-admin/edit.php?post_type=lp_book) loads the same bootstrap, with the user authenticated early (auth_cookie_valid, set_current_user before after_setup_theme), and then wp-admin/admin.php takes over.   • admin_menu fires before admin_init, because admin.php builds the menu first: menu pages are added on admin_menu, settings on admin_init (see Administration Menus and Settings API). admin_init also fires in admin-ajax.php and admin-post.php.

Pluggable functions

Before hooks covered everything, WordPress offered another way to change behaviour. wp-includes/pluggable.php, which wp-settings.php loads after the plugins, wraps each of its functions in if ( ! function_exists( 'wp_mail' ) ), so a plugin that defines a function of the same name first replaces core’s. In 7.1.3 there are 38, among them wp_mail(), wp_get_current_user(), get_userdata(), get_user_by(), wp_authenticate(), wp_set_auth_cookie(), wp_validate_auth_cookie(), auth_redirect(), wp_redirect(), wp_safe_redirect(), wp_verify_nonce(), wp_create_nonce(), wp_salt(), wp_hash_password(), wp_check_password(), wp_password_needs_rehash() (6.8), wp_generate_password(), wp_rand(), wp_new_user_notification() and get_avatar().

Replacing one is a last resort. Only one replacement can exist (the first plugin loaded wins, and a second unguarded definition is a fatal "Cannot redeclare" error), the replacement must honour the whole contract of the original, including parameters and hooks added later, and it must be defined when the plugin file loads, not in a hook. Filters now cover most needs: pre_wp_mail (5.7) to short-circuit mail, wp_mail and phpmailer_init to change it, wp_hash_password_algorithm and wp_hash_password_options (6.8, when hashing moved to bcrypt), wp_redirect and allowed_redirect_hosts, nonce_life, and pre_get_avatar_data. Lumen Press logs mail on local sites with a filter:

wp-content/mu-plugins/lumen-mail-log.php
<?php
/**
 * Plugin Name: Lumen Mail Log
 * Description: Writes outgoing mail to the debug log instead of sending it (local environments only).
 */
defined( 'ABSPATH' ) || exit;

if ( 'local' !== wp_get_environment_type() ) {
	return;
}

// A filter, not a replacement of the pluggable wp_mail(): any other plugin can still hook mail.
add_filter(
	'pre_wp_mail',
	static function ( $short_circuit, array $atts ) {
		$to = implode( ', ', (array) $atts['to'] );
		error_log( sprintf( 'Mail not sent (local): to=%s subject="%s"', $to, $atts['subject'] ) );
		return true; // Any non-null value stops wp_mail() and becomes its return value.
	},
	10,
	2
);

Source: Code Reference: pre_wp_mail

Called from wp eval, wp_mail() returns true and the debug log shows Mail not sent (local): to=maria.editor@lumenpress.test subject="New submission". When a pluggable function misbehaves, ( new ReflectionFunction( 'wp_mail' ) )->getFileName() shows who defined it; on this site it is wp-includes/pluggable.php, line 189. Delivery itself is covered in Email Delivery. Parent themes use the same function_exists() pattern so that a child theme, whose functions.php loads first, can replace their functions (see Child Themes). In plugins, use it only for code meant to be pluggable; prefixes or namespaces avoid collisions everywhere else.

Security and performance

  • Hooks do not check permissions. Callbacks on init, admin_init or wp_ajax_* run for whoever sends the request; code that changes data checks current_user_can() and a nonce (Security for Developers). admin_init does not mean an administrator.

  • Escape what filters return: any plugin can add rows to the details box, so every row is escaped. Callbacks run on every request where their hook fires: heavy work on plugins_loaded or init slows pages, REST, cron and AJAX. One-off setup (roles, tables, rewrite flushes) belongs in the activation hook (Plugin Fundamentals). Since 6.7, __() before init triggers a "translation loading triggered too early" notice.

Where older books and tutorials are outdated

The All-in-One For Dummies book does not cover plugin development at all, and the other older books and many tutorials carry habits that no longer apply:

Older advice or code Current behaviour

add_role() called on every init (one book’s example)

Roles are stored in the database: add them once on activation, remove them on uninstall

Callbacks built with create_function()

Removed in PHP 8.0; use a named function, a static method or a stored closure

array( &$this, 'method' )

A PHP 4 idiom; array( $this, 'method' ) is enough

Reading or editing $wp_filter as nested arrays

Entries are WP_Hook objects since 4.7 and object IDs changed in 7.1; use the hook functions

Scripts enqueued on init or printed in wp_head

Enqueue on wp_enqueue_scripts or admin_enqueue_scripts; block assets come from block.json

Markup injected with get_header or loop_start

get_header never fires in block themes and loop hooks run before wp_head; use blocks, Block Hooks or block filters

Redefining wp_mail() or wp_hash_password()

Prefer pre_wp_mail, phpmailer_init and the 6.8 hashing filters

"Plugins cannot depend on each other", so probe with function_exists()

6.5 added the Requires Plugins header; hook into the dependency’s own actions

Common pitfalls

Symptom Cause and fix

A callback never runs

Added after its hook fired (add_action( 'plugins_loaded', ... ) in a theme), a misspelled name, or a front-end hook on a REST request. Check did_action() where the callback is added

remove_action() returns false

Different priority, instance or closure, or the removal runs before the callback is added

"Too few arguments to function"

$accepted_args is lower than the callback’s required parameters

A change also hits menus, widgets or REST

the_title and the_content fire everywhere; check in_the_loop(), is_main_query() or the post type

A save hangs until a time or memory limit

A save_post callback updates the same post without detaching itself (see above)
