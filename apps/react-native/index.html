React Native

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the React Native reference. React Native builds Android and iOS apps from one codebase using React: the same components, props, state and Hooks you already write for the web, rendered not to the DOM but to the platform’s own native views. A View becomes a UIView on iOS and an android.view.ViewGroup on Android; the result is a real native app, not a web page in a wrapper.

This section documents React Native 0.87 with React 19.2, written in TypeScript throughout. That baseline matters, because the platform changed substantially between 2024 and 2026: every page here assumes the New Architecture (it is the only architecture since 0.82), Hermes V1 as the JavaScript engine (the default since 0.84), and the Strict TypeScript API (the default since 0.87). Examples run in an Expo SDK 57 project created with npx create-expo-app@latest — the framework the official documentation recommends — and the pages that need bare native code use a @react-native-community/cli project instead.

If you already know React, you know most of this section’s programming model. What differs is everything around it: there is no DOM, styling is JavaScript objects rather than CSS files, layout is Flexbox with a different default, and the app runs across two threads with native modules underneath. This section documents those differences and does not re-explain React itself — for JSX, Hooks, Context, effects, Suspense and the Rules of React, see the React Reference.

How React Native got here

Release What changed

0.76 (2024)

The New Architecture became the default, and React Native DevTools replaced Flipper and the remote Chrome debugger.

0.82 (2025)

The New Architecture became the only architecture — the legacy bridge can no longer be re-enabled. Added DOM-like node APIs on refs and the web Performance APIs.

0.84 (2026)

Hermes V1 became the default engine, iOS ships precompiled binaries, legacy architecture code was removed, and React 19.2 landed.

0.85 (2026)

A new animation backend shared by Animated and Reanimated made useNativeDriver work with layout props; the Jest preset moved to @react-native/jest-preset.

0.86 (2026)

Edge-to-edge display became mandatory on Android 15 and later.

0.87 (2026)

The Strict TypeScript API became the default (deep imports are now type errors), Metro 0.87, experimental Swift Package Manager support, and AGP 9.

Anything the two consulted books describe that predates this timeline — the bridge, class components, Flow, Reanimated 2, CodePush, Flipper — is documented here as history, with the current approach given in its place.

Related material on this site

React Native sits on top of material documented elsewhere on this site, and these pages link to it rather than repeat it.   • Flutter and Dart and Ionic and Capacitor are the other cross-platform options, a Dart codebase with its own renderer and a web codebase in a native WebView shell.

  • Hybrid Apps: IDEs & Tools — editors, native toolchains, emulators and Expo, Ionic and Capacitor tooling, with links to each official page.
