Windows Apps

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the Windows Apps reference. It teaches how to build Windows desktop applications with C# on .NET 10: the XAML language, WPF (the mature desktop UI framework, and the centre of this section), the MVVM pattern with the MVVM Toolkit, the newer WinUI 3 and Windows App SDK stack, Windows Forms, and the part that is often forgotten, which is how to publish and distribute the result — .NET publish options, MSIX, code signing, the Microsoft Store, WinGet, App Installer, ClickOnce and continuous delivery. Each of the 48 concept pages explains one idea in detail, with tables of every option, pitfalls, runnable examples and a link to the official page each example derives from.

The section was written against these versions, verified on 23 October 2026:

  • .NET 10 LTS, latest patch 10.0.13, supported until 14 November 2028, with C# 14. .NET 8 and .NET 9 end support on 10 November 2026. .NET 11 is at release candidate 2; general availability is expected at .NET Conf, 10 to 13 November 2026.

  • Visual Studio 2026, latest 18.11.1.

  • Windows App SDK 2.5.1 (stable channel) and CommunityToolkit.Mvvm 8.4.2.

  • Windows 11 and Windows 10. Windows 10 reached end of support on 14 October 2025.

The language itself is covered elsewhere: for delegates and events, async and await, threads, native interop, testing and the dotnet CLI, see the C# Reference. This section adds what Windows desktop development needs on top of it.

New to Windows desktop development? Read the Foundations and XAML pages first, then the WPF pages from top to bottom (they are in dependency order: layout and properties before binding, binding before templates), then MVVM, and finish with Publishing and distribution. The Other stacks and platform integration pages can be read at any point after the WPF pages, because they compare themselves with WPF. Already know WPF? Jump to MVVM or Publishing and distribution. The official guidance, from the Windows developer FAQ, is that WinUI 3 with the Windows App SDK is the recommended choice for new native Windows apps, that WPF and Windows Forms are mature and still maintained on current .NET, and that UWP is in maintenance. The Bookshelf Desktop scenario

Every example builds one application, Bookshelf Desktop, a Windows client for the Bookshelf domain used in other sections of this site. It has a main window with a book list, a details pane, search and filtering, and add and edit dialogs with validation. A BooksViewModel built with the MVVM Toolkit talks to an IBookRepository (Entity Framework Core with SQLite) and to an IDialogService and an INavigationService, all registered in the Generic Host. The application is themed in light and dark Fluent styles, localized in English and Spanish and given accessibility names. The same main screen is re-implemented in WinUI 3 (x:Bind, NavigationView, Mica) and in Windows Forms (BindingSource), so the stack-comparison pages can show the differences. It is published as framework-dependent and self-contained builds, as an MSIX signed in CI, through an App Installer feed, as a WinGet manifest and as a Microsoft Store submission. The scenario is original and not copied from any tutorial or book.

Where the books are outdated or out of scope, the pages follow the official documentation:

  • Both books target .NET 9, which leaves support on 10 November 2026. This section uses .NET 10 LTS.

  • The Native AOT section of the Price book is about console apps. Native AOT and trimming are not supported for WPF and Windows Forms; WinUI documents PublishAot only in its release notes.

  • The Belmansour chapter on WinGet does not discuss code signing or MSIX. The distribution pages add signing, SmartScreen and Store requirements from the official documentation. WinGet itself does not require a signed installer; the signing discussion is there because unsigned installers are flagged by SmartScreen.

  • Neither book covers XAML, WPF, MVVM, WinUI, MSIX, the Microsoft Store or ClickOnce, so those pages rely on the official documentation alone.

  • The CLI-specific chapters (argument parsing, System.CommandLine, interactive CLIs) belong to the CLI section, not to this section.

The official documentation also has gaps, and the pages say so instead of inventing APIs: there is no Microsoft Learn MVVM article written for WPF, no official ViewModel-first navigation or dialog service, no official guidance on testing WPF view models, no conceptual WPF Ribbon page, no Native AOT or trimming support for WPF and Windows Forms, and no current Microsoft recommendation for desktop UI-test automation.
