CLI

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the CLI reference. It teaches how to build command-line and terminal applications for Windows, macOS and Linux: what a terminal really is, how a program talks to it through POSIX and Win32 interfaces, how to write native command-line programs in C, C++, Swift, Objective-C, .NET, Go, Rust and on the JVM and Kotlin, how to build full-screen terminal user interfaces (TUIs) with Ratatui (in depth), Bubble Tea, Textual, Terminal.Gui, ncurses, FTXUI and other libraries, how to handle prompts, progress output, shells, completions and services, and how to ship the result as signed native binaries and packages. Each of the 33 concept pages explains one idea in detail, with tables of every option, platform differences, pitfalls, examples and a link to the official page each example derives from. The printable Cheat Sheet (PDF) summarises every concept on one A4 page.

Scope and what this section links to instead

This section covers what is specific to native and terminal-facing programs. The repository already documents a lot of command-line material, and that material is linked, never repeated:

  • The Building CLIs for AI Agents sub-section covers designing a CLI that people and AI agents can both use: output formats, exit codes, errors, configuration, TUIs versus CLIs, frameworks, packaging and testing. Its own bibliography is at the Building CLIs for AI Agents bibliography.

  • Language and framework command-line pages stay where they are: Node.js CLI tools, Quarkus command mode, command-line PHP, Rust I/O, processes and environment, C program structure, the Go Reference, the Swift Reference and the Flask, Django, Pyramid and NestJS command pages listed under Related Guides in the navigation.

  • Windows desktop applications with a graphical interface are in Windows Apps, and macOS distribution is further covered in macOS distribution outside the App Store.

Reading map

Pick the path that matches what you are building. The pages are in dependency order inside each group.

  1. One-shot commands. Start with the landscape and stack chooser, then the foundations (terminals, escape sequences, POSIX and Windows), then the page for your language.

  2. Interactive prompts and shells. Add prompts and line editing, progress, colour and rich output and shells and completions.

  3. Full-screen TUIs. Read TUI architecture and concepts, then the library page for your language (the four Ratatui pages are the most detailed).

  4. Shipping. Finish with native binaries, signing and OS trust, packages and installers and testing.

Running example

Every example belongs to one tool, shelf, a command-line client for the Bookshelf domain used in other sections of this site. It grows with the section:

  • shelf list, shelf add, shelf loan and shelf return are one-shot subcommands, written in each language.

  • shelf repl is an interactive prompt with history and completion.

  • shelf tui is a full-screen catalogue browser with a list of books, a details pane, a loans table and a search box. It is implemented with Ratatui in depth and, more briefly, with Bubble Tea, Textual, Terminal.Gui, ncurses and FTXUI, so the libraries can be compared on the same screen.

  • shelfd is a background service with a local IPC socket, used by the services page.

The scenario is original and not copied from any tutorial.
