Hybrid Apps

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A hybrid app is written once, mostly in web technologies or a cross-platform language, and runs on Android and iOS: either inside a native WebView with a bridge to device APIs (Ionic with Capacitor), or as a JavaScript or TypeScript program that drives native UI components (React Native with Expo). A third approach, Flutter, draws its own UI with a Dart codebase. This subsection collects the tools that every such project needs, and contains the full references for Flutter with Dart and for Ionic with Capacitor; the React Native reference lives in its own subsection. It is written for web developers who want to ship a mobile app, and for mobile developers choosing between a hybrid framework and a native toolchain.

What’s covered

  • Flutter and Dart: the Dart language, widgets, rendering, state, navigation, data, platform integration, testing and release for Flutter apps, built around the Trailhead example.

  • Ionic and Capacitor: Ionic components, the Capacitor native bridge and plugins, navigation, data, platform integration, testing and release, with the same Trailhead example in Angular.

  • IDEs & Tools: the editors, the native toolchains (Android Studio and Xcode), the emulators and simulators, and the Expo, Ionic and Capacitor tooling used for hybrid and cross-platform apps, with links to each official page.

Reading path

  1. Start with Hybrid Apps: IDEs & Tools to set up an editor and the native toolchains, which every hybrid project needs even though the application code is not native.

  2. To choose a stack, compare Getting Started with Flutter and Getting Started with Ionic and Capacitor, which both include a comparison table.

  3. For a web codebase packaged as a store app, read Ionic and Capacitor; for a Dart codebase with its own renderer, read Flutter and Dart.

  4. For a JavaScript and TypeScript codebase that renders native components, continue with React Native, starting from Getting Started with React Native.

  5. For Kotlin code shared between platforms, read Kotlin Multiplatform instead.

  6. For a native-only comparison, read Android and Apple Platforms.
