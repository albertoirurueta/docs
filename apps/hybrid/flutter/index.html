Flutter and Dart

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Flutter is Google’s UI toolkit for building Android, iOS, web and desktop apps from a single Dart codebase. Unlike a WebView hybrid framework or a framework that drives native views, Flutter draws every pixel itself with its own renderer, so an app looks and behaves the same on every platform and OS version. This subsection is a reference for developers who know another stack, such as Kotlin, Swift, Java or TypeScript, and want to build a production Flutter app: it covers the Dart language first, then the framework, then the engineering topics around it (testing, platform code, release).

  2. Continue with Architecture and Rendering, Widgets and Layout and State Management for the core programming model.

  3. Add Navigation and Routing and Data, Storage and Networking to build a complete app.

  4. Finish with Platform Integration, Testing and Building and Releasing, and keep the Flutter Cheat Sheet at hand.

Running example

Every page builds Trailhead, a hiking journal: a searchable trail list loaded from a REST API (https://api.example.com/v1), a trail detail screen, favourites, a "log a hike" flow that attaches a camera photo and a GPS position, and an offline cache of the trails. The state layer uses Riverpod and routing uses go_router. The same app is built with Ionic and Capacitor in Ionic and Capacitor, so the two approaches can be compared on one problem.
