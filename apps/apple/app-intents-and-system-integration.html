App Intents, Siri, Shortcuts, Spotlight, Deep Links and Extensions

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production; see the section bibliography for the reference material consulted while preparing these pages.

Widgets, Complications and Controls gave FieldNotes a widget whose pin button runs TogglePinIntent, and a control that opens the capture sheet. This page defines those intents and everything around them. App Intents is the one framework through which an app reaches Siri, the Shortcuts app, Spotlight, widgets, controls, the Action button, visual intelligence and Apple Intelligence; the page then covers the other ways into an app: deep links (universal links, custom URL schemes and NSUserActivity) and app extensions such as the share extension. Everything targets the 27 releases (iOS 27, iPadOS 27, macOS 27, watchOS 27 and visionOS 27), built with Xcode 27 and Swift 6.4. FieldNotes keeps a deployment minimum of 26, so every 27-only API is labelled and guarded with if #available or @available.

App Intents replaced SiriKit custom intents, where an Intents extension defined INIntent subclasses in an .intentdefinition file to reach Siri and Shortcuts; new actions in a 27-baseline app are App Intents, which reach Siri, Shortcuts, Spotlight and the rest of the system. SiriKit’s system domains remain current where they apply: messaging and calling apps still use intents such as INSendMessageIntent and INStartCallIntent, which communication notifications require. App Intents are plain Swift: structs with property wrappers and an async method. Xcode extracts their metadata at build time, so the system knows the app’s actions and content before the app ever runs. The concurrency rules that apply to perform() are in the Swift reference under Async/Await and Tasks and Actors, Isolation and Sendable.

One Intent, Every Surface

An intent is a verb (create a note, pin this note). An entity is a noun (a note). A query is how the system finds nouns by identifier or by text. Once FieldNotes declares them, each system surface uses the same declarations; there is no Siri-specific or Spotlight-specific code path to maintain.

Where the Intents Live

Intents run in whichever process the system chooses. A widget button runs its intent in the widget extension; an intent that opens the app runs in the app; Siri and Shortcuts use the app, launching it in the background if needed. So the intent files sit in a shared folder with target membership in FieldNotes, FieldNotesWidgets and FieldNotesWatchWidgets, and the shared intents read and write through the App Group store with SharedNoteAccess, the helper defined on Widgets, Complications and Controls. It opens one container per process, so in the app it is the same persistence AppServices gives NoteStore. The app’s in-memory NoteStore reloads from the store when the app becomes active, so a pin that a widget button toggled in the extension is on screen when the user returns. App-only intents such as CreateNoteIntent go through NoteStore itself, obtained with @Dependency.

Core Types

NoteEntity

An app entity is a Sendable, Identifiable value that stands for one of the app’s objects. It needs a type name, a per-instance displayRepresentation (the title, subtitle and image Siri, Shortcuts and Spotlight show), a defaultQuery, and whichever properties the system should see, marked with @Property. FieldNotes's entity is built from a Note; it is not the model, just a projection of it:

// Shared/Intents/NoteEntity.swift  (FieldNotes, FieldNotesWidgets, FieldNotesWatchWidgets)
import AppIntents
import FieldNotesModel

struct NoteEntity: AppEntity {
    static let typeDisplayRepresentation = TypeDisplayRepresentation(
        name: "Note", numericFormat: "\(placeholder: .int) notes")
    static let defaultQuery = NoteEntityQuery()

    let id: UUID

    @Property(title: "Title")
    var title: String

    @Property(title: "Tags")
    var tags: [String]

    @Property(title: "Pinned")
    var isPinned: Bool

    @Property(title: "Created")
    var createdAt: Date

    var body: String
    var placeName: String?

    var displayRepresentation: DisplayRepresentation {
        DisplayRepresentation(title: "\(title)",
                              subtitle: "\(placeName ?? tags.joined(separator: ", "))",
                              image: .init(systemName: isPinned ? "pin.fill" : "note.text"))
    }

    init(_ note: Note) {
        id = note.id
        body = note.body
        placeName = note.location?.placeName
        title = note.title
        tags = note.tags
        isPinned = note.isPinned
        createdAt = note.createdAt
    }
}

See Apple Developer Documentation — AppEntity.

The identifier is the note’s own UUID, the same one the deep links carry and the one SwiftData stores as NoteRecord.id. That makes the entity stable across launches, which Shortcuts needs to remember "this note", and across devices once iCloud sync copies the record.

NoteEntity also conforms to IndexedEntity (for Spotlight) wherever Core Spotlight exists; that conformance is shown under Spotlight with IndexedEntity.

NoteEntityQuery

The query resolves identifiers back into entities, and suggests entities when the user is picking one in Shortcuts or a widget’s edit sheet. Adding EntityStringQuery lets Siri and Shortcuts search by spoken or typed text:

// Shared/Intents/NoteEntityQuery.swift
import AppIntents

struct NoteEntityQuery: EntityQuery {
    func entities(for identifiers: [NoteEntity.ID]) async throws -> [NoteEntity] {
        let persistence = try SharedNoteAccess.persistence()
        var entities: [NoteEntity] = []
        for id in identifiers {                              // one indexed lookup per requested note
            if let note = try await persistence.note(id: id) { entities.append(NoteEntity(note)) }
        }
        return entities
    }

    func suggestedEntities() async throws -> [NoteEntity] {
        let notes = try await SharedNoteAccess.persistence().fetchNotes()
        return notes.sorted { ($0.isPinned ? 1 : 0, $0.createdAt) > ($1.isPinned ? 1 : 0, $1.createdAt) }
            .prefix(10)
            .map(NoteEntity.init)
    }
}

extension NoteEntityQuery: EntityStringQuery {
    func entities(matching string: String) async throws -> [NoteEntity] {
        let notes = try await SharedNoteAccess.persistence().fetchNotes()
        return notes.filter {
            $0.title.localizedStandardContains(string) || $0.tags.contains { $0.localizedStandardContains(string) }
        }
        .map(NoteEntity.init)
    }
}

See Apple Developer Documentation — EntityQuery.

entities(for:) looks notes up one by one with note(id:) from Persisting Models with SwiftData, because the system often asks for a single note. The suggestion and string queries still fetch every note, which is fine for a notebook-sized app; a larger store would give them their own #Predicate fetches.

TogglePinIntent

An intent has a static title, @Parameter properties the system fills in (asking the user if needed), and a perform() method. TogglePinIntent is the one the widget’s pin button runs. Its supportedModes (26) says it never needs the app in the foreground:

// Shared/Intents/TogglePinIntent.swift  (FieldNotes, FieldNotesWidgets, FieldNotesWatchWidgets)
import AppIntents
import WidgetKit

struct TogglePinIntent: AppIntent {
    static let title: LocalizedStringResource = "Toggle Pin"
    static let description = IntentDescription("Pins or unpins a note.")
    static let supportedModes: IntentModes = .background

    @Parameter(title: "Note")
    var note: NoteEntity

    init() {}
    init(note: NoteEntity) { self.note = note }

    func perform() async throws -> some IntentResult {
        let persistence = try SharedNoteAccess.persistence()
        guard var current = try await persistence.note(id: note.id) else { return .result() }
        current.isPinned.toggle()
        try await persistence.save(current)
        await registerUndo(for: current.id, wasPinned: !current.isPinned)   // see UndoableIntent below
        WidgetCenter.shared.reloadTimelines(ofKind: SharedNoteAccess.pinnedNotesWidgetKind)
        return .result()
    }
}

See Apple Developer Documentation — AppIntent.

The explicit init() is required once a custom initializer exists: the system creates intents with init() and then sets their parameters. IntentModes arrived in the 26 releases; before them, openAppWhenRun was the only switch.

CreateNoteIntent

CreateNoteIntent is the action behind "Create a note in FieldNotes". It returns the new note as a value so that a Shortcut can pass it to the next action, speaks a confirmation, and, if the user asks for it, continues in the foreground to show the note. The parameter summary is the sentence the Shortcuts editor displays:

// FieldNotes/Intents/CreateNoteIntent.swift  (app only)
import AppIntents
import WidgetKit
import FieldNotesModel
import FieldNotesServices

struct CreateNoteIntent: AppIntent {
    static let title: LocalizedStringResource = "Create Note"
    static let description = IntentDescription("Creates a new field note.")
    static let supportedModes: IntentModes = [.background, .foreground(.dynamic)]

    @Parameter(title: "Title", requestValueDialog: "What should the note be called?")
    var noteTitle: String

    @Parameter(title: "Text", default: "")
    var text: String

    @Parameter(title: "Pin It", default: false)
    var pin: Bool

    @Parameter(title: "Open After Creating", default: false)
    var openAfterCreating: Bool

    @Dependency private var router: IntentRouter
    @Dependency private var store: NoteStore        // registered by FieldNotesApp; this intent runs in the app

    static var parameterSummary: some ParameterSummary {
        Summary("Create \(\.$noteTitle)") {
            \.$text
            \.$pin
            \.$openAfterCreating
        }
    }

    func perform() async throws -> some IntentResult & ReturnsValue<NoteEntity> & ProvidesDialog {
        let note = Note(title: noteTitle, body: text, isPinned: pin)
        // Through the app's NoteStore, so the note is on screen at once and saved by the one container.
        await store.add(note)
        await store.waitForPendingWrites()
        if pin { WidgetCenter.shared.reloadTimelines(ofKind: SharedNoteAccess.pinnedNotesWidgetKind) }
        if openAfterCreating {
            try await continueInForeground(alwaysConfirm: false)
            await MainActor.run { router.pendingNoteID = note.id }
        }
        return .result(value: NoteEntity(note), dialog: "Created “\(noteTitle)”.")
    }
}

Spotlight with IndexedEntity

Conforming an entity to IndexedEntity lets FieldNotes put notes into the Spotlight index as entities. Spotlight then shows them in search results, opens them with OpenNoteIntent, and Apple Intelligence can use the indexed content. @Property values and displayRepresentation are indexed automatically; attributeSet adds the rest. Core Spotlight isn’t on watchOS, so the conformance is guarded:

// Shared/Intents/NoteEntity+Spotlight.swift
#if canImport(CoreSpotlight) && !os(watchOS)
import AppIntents
@preconcurrency import CoreSpotlight
import FieldNotesModel

enum NoteSpotlightIndex {
    static let index = CSSearchableIndex(name: "FieldNotes-Notes")

    static func update(_ notes: [Note]) async throws {
        try await index.indexAppEntities(notes.map(NoteEntity.init))

    static func remove(_ ids: [Note.ID]) async throws {

    }
}
#endif

See Apple Developer Documentation — Making app entities available in Spotlight.

Visual Intelligence

Visual intelligence lets someone point the camera at something, or take a screenshot, and search apps for matching content. The system sends FieldNotes a SemanticContentDescriptor with general labels (in English, such as bird or tree) and the pixel buffer; the app answers with entities through an IntentValueQuery. FieldNotes matches the labels against note tags, so pointing at a heron finds notes tagged "heron" or "birds":

// FieldNotes/Intents/NoteVisualSearchQuery.swift  (app only)
#if os(iOS) || os(macOS)
import AppIntents
import VisualIntelligence

@available(iOS 26, macOS 27, *)
struct NoteVisualSearchQuery: IntentValueQuery {
    func values(for input: SemanticContentDescriptor) async throws -> [NoteEntity] {
        let labels = Set(input.labels.map { $0.lowercased() })
        let notes = try await SharedNoteAccess.persistence().fetchNotes()
        return notes
            .filter { note in note.tags.contains { labels.contains($0.lowercased()) } }
            .prefix(50)
            .map(NoteEntity.init)
    }
}
#endif

See Apple Developer Documentation — Integrating your app with visual intelligence.

Tapping a result runs OpenNoteIntent, the same one Spotlight uses, which is why every entity type returned here needs an OpenIntent. Visual intelligence is on iOS and iPadOS 26 and on macOS from 27, and it needs Apple Intelligence hardware.

App Schema Domains for Siri with Apple Intelligence

Custom App Shortcuts need phrases. App schema domains go further: an intent or entity that adopts a system schema tells Apple Intelligence exactly what it does, in the same shape as every other app in that domain, so Siri can use it with natural, unscripted requests and pass results between apps. The macros @AppIntent(schema:) and @AppEntity(schema:) check the conformance at compile time.

The 27 releases add a .notes domain with createNote and updateNote intents and note, folder and account entities, which is exactly FieldNotes's territory. The schema fixes the property names and types (name and content as AttributedString, attachments as [IntentFile], and so on), which differ from NoteEntity's, and the whole type must be 27-only. So FieldNotes adds schema-conforming siblings next to its 26-compatible types, sharing the same persistence code:

// FieldNotes/Intents/SiriNoteSchema.swift  (app only; iOS, iPadOS, macOS and visionOS 27)
#if !os(watchOS)
import AppIntents
import FieldNotesModel

@available(iOS 27, macOS 27, visionOS 27, *)
@AppEntity(schema: .notes.note)
struct SiriNoteEntity {
    static let defaultQuery = SiriNoteEntityQuery()

    let id: UUID
    var name: AttributedString
    var content: AttributedString?
    var attachments: [IntentFile]
    var isPinned: Bool
    var creationDate: Date?
    var modificationDate: Date?
    var folder: SiriNotebookEntity?               // declared the same way with @AppEntity(schema: .notes.folder)

    var displayRepresentation: DisplayRepresentation { DisplayRepresentation(title: "\(name)") }

    // Maps a `Note`; `SiriNoteEntityQuery` and `SiriCreateNoteIntent` both call it.
    init(_ note: Note) {
        id = note.id
        name = AttributedString(note.title)
        content = note.body.isEmpty ? nil : AttributedString(note.body)
        // Not exposed yet: `PhotoAttachment` is metadata only, and its bytes load asynchronously
        // through `PhotoDataStoring.photoData(for:)`, which this synchronous init can't call.
        attachments = []
        isPinned = note.isPinned
        creationDate = note.createdAt
        modificationDate = nil                    // `Note` records no modification date
        folder = nil
    }

    struct SiriNoteEntityQuery: EntityQuery {
        func entities(for identifiers: [UUID]) async throws -> [SiriNoteEntity] {
            try await SharedNoteAccess.persistence().fetchNotes()
                .filter { identifiers.contains($0.id) }
                .map(SiriNoteEntity.init)
        }
    }
}

LongRunningIntent and CancellableIntent

A normal intent has a short time budget. LongRunningIntent (a ProgressReportingIntent) runs its heavy part in performBackgroundTask, which gets extended background time, and reports progress the system can display. CancellableIntent adds a handler that receives why the intent was cancelled:

// FieldNotes/Intents/ReindexNotesIntent.swift  (app only)
#if canImport(CoreSpotlight) && !os(watchOS)
import AppIntents

@available(iOS 27, macOS 27, visionOS 27, *)
struct ReindexNotesIntent: LongRunningIntent, CancellableIntent {
    static let title: LocalizedStringResource = "Rebuild FieldNotes Search Index"

    func perform() async throws -> some IntentResult {
        let notes = try await SharedNoteAccess.persistence().fetchNotes()
        progress.totalUnitCount = Int64(notes.count)
        try await withIntentCancellationHandler {
            try await performBackgroundTask {
                for batch in stride(from: 0, to: notes.count, by: 100) {
                    try Task.checkCancellation()
                    let slice = Array(notes[batch..<min(batch + 100, notes.count)])
                    try await NoteSpotlightIndex.update(slice)
                    progress.completedUnitCount += Int64(slice.count)
                }
            }
        } onCancel: { reason in
            print("Reindex cancelled: \(reason)")
        }
        return .result()
    }
}
#endif

See Apple Developer Documentation — LongRunningIntent.

LongRunningTaskOptions has a requiresGPU option for work such as on-device model inference; indexing doesn’t need it. The same protocol appears on Persisting Models with SwiftData for a large import, and the general background-time rules are on Background Execution.

Deep Links

Intents are for the system; links are for people and for other apps. FieldNotes accepts the two link forms that Navigation and Presentation already routes through its DeepLink parser and onOpenURL: the custom scheme fieldnotes://note/<uuid> and the universal link https://fieldnotes.example.com/note/<uuid>;. This section covers the configuration behind them and when to use each.

Custom URL Schemes and Their Risks

A custom scheme is declared in the target’s Info › URL Types, which writes CFBundleURLTypes into Info.plist:

<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleURLName</key>
        <string>com.example.fieldnotes</string>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>fieldnotes</string>
        </array>
    </dict>
</array>

See Apple Developer Documentation — Defining a custom URL scheme for your app.

Custom schemes are convenient and work offline, but nothing stops another app from registering the same scheme, and the system doesn’t say which app wins. Treat every scheme URL as untrusted input: accept only the shapes DeepLink recognizes, never perform a destructive action straight from a link, and never carry tokens or secrets in one. That is why FieldNotes uses its scheme only for links it creates itself, from its own widgets, and why OAuth redirects on a mobile app should use a universal link or the ASWebAuthenticationSession callback (RFC 8252), as explained in OAuth for Native and Mobile Apps.

Universal Links

A universal link is an ordinary https URL on a domain the developer controls. If the app is installed and the domain vouches for it, the link opens the app; otherwise it opens the web page, which makes it safe to put in email, messages and shared notes. The two halves of the trust relationship are the Associated Domains entitlement in the app and the apple-app-site-association (AASA) file on the server:

<!-- FieldNotes.entitlements -->
<key>com.apple.developer.associated-domains</key>
<array>
    <string>applinks:fieldnotes.example.com</string>
    <string>webcredentials:fieldnotes.example.com</string>
</array>

See Apple Developer Documentation — Associated Domains Entitlement.

The AASA file is served at https://fieldnotes.example.com/.well-known/apple-app-site-association, as JSON, over HTTPS with a valid certificate and without redirects. It extends the file shown on the navigation page with a default, an excluded path and the webcredentials section that passkeys on Security and Privacy rely on:

{
  "applinks": {
    "defaults": { "caseSensitive": false },
    "details": [
      {
        "appIDs": ["ABCDE12345.com.example.fieldnotes"],
        "components": [
          { "/": "/account/*", "exclude": true, "comment": "Account pages stay on the web" },
          { "/": "/note/*", "comment": "fieldnotes.example.com/note/<uuid>" },
          { "/": "/notebook/*" }
        ]
      }
    ]
  },
  "webcredentials": {
    "apps": ["ABCDE12345.com.example.fieldnotes"]
  }
}

See Apple Developer Documentation — Supporting associated domains.

Components are matched in order, so the exclusion comes first. Devices don’t fetch the file from the domain directly; Apple’s CDN fetches it and devices download it from there when the app is installed or updated. During development, the suffix applinks:fieldnotes.example.com?mode=developer makes a development-signed build fetch the file directly from the server, so edits take effect without waiting for the CDN. Needs the Associated Domains capability and a paid developer account (the entitlement is tied to the Team ID in appIDs); link opening is best tested on a physical device.

SwiftUI delivers a universal link to the same onOpenURL handler as the custom scheme, so no extra code is needed. Apps that manage scenes themselves receive it as an NSUserActivity of type NSUserActivityTypeBrowsingWeb, and a SwiftUI view can observe that form too:

// Alternative to onOpenURL for universal links, with access to the full activity
.onContinueUserActivity(NSUserActivityTypeBrowsingWeb) { activity in
    guard let url = activity.webpageURL, let link = DeepLink(url: url) else { return }
    open(link)
}

See Apple Developer Documentation -- onContinueUserActivity(_:perform:).

When the user taps a universal link inside a page already on the same domain, the system keeps it in the browser; that’s by design. The server side of universal links, and how they compare with Android App Links in an OAuth flow, is in OAuth for Native and Mobile Apps.

NSUserActivity: Handoff and On-Screen Content

NSUserActivity describes what the user is doing now. Advertising one from the note detail view enables Handoff (continue on another device), adds the note to the on-device search history, and, with an appEntityIdentifier, tells Siri and Apple Intelligence which NoteEntity is on screen, so "pin this" means this note:

// FieldNotes/Views/NoteDetail+Activity.swift
import SwiftUI
import AppIntents
import FieldNotesModel

extension View {
    func advertisesViewing(_ note: Note) -> some View {
        userActivity("com.example.fieldnotes.viewNote") { activity in
            activity.title = note.title
            activity.isEligibleForHandoff = true
            activity.isEligibleForSearch = true
            activity.webpageURL = URL(string: "https://fieldnotes.example.com/note/\(note.id.uuidString)")
            activity.targetContentIdentifier = note.id.uuidString
            activity.appEntityIdentifier = EntityIdentifier(for: NoteEntity.self, identifier: note.id)
        }
    }
}

// In NoteDetail(note:)'s body:  .advertisesViewing(note)
// In ContentView, receiving Handoff on another device:
.onContinueUserActivity("com.example.fieldnotes.viewNote") { activity in
    guard let id = activity.targetContentIdentifier.flatMap(UUID.init(uuidString:)) else { return }
    open(.note(id))
}

See Apple Developer Documentation -- userActivity(_:isActive:_:).

The activity type must be listed under NSUserActivityTypes in Info.plist. Setting webpageURL to the universal link means a Mac or device without FieldNotes opens the web page instead. Handoff needs the devices signed in to the same Apple Account.

App Extensions

An app extension is a separate bundle inside the app that the system launches on its own to provide one service: a widget, a notification service, a share destination. Each extension runs in its own process with its own sandbox and memory limit, much lower than the app’s. It can’t call into the running app, and the app can’t call into it. App Groups

App Groups are the shared-container half of the extension model. Each target that joins the group gets the same entitlement, and UserDefaults(suiteName:) and FileManager.containerURL(forSecurityApplicationGroupIdentifier:) open the shared defaults and directory:

<key>com.apple.security.application-groups</key>
<array>
    <string>group.com.example.fieldnotes</string>
</array>

See Apple Developer Documentation — Configuring app groups.

On iOS, iPadOS, watchOS and visionOS, the group must be registered in the developer account, so this needs a paid account. On macOS, a group can also be named <Team ID>.<name>, and macOS then checks that the process’s code signature carries that Team ID. The same group. identifier can double as a Keychain access group, which Security and Privacy uses to share sign-in state with extensions.

The principal class receives the shared items through its extensionContext, shows a small SwiftUI form, saves the note to the App Group store, and completes the request. The iOS version hosts SwiftUI in a UIHostingController:

// FieldNotesShareExtension/ShareViewController.swift
#if os(iOS)
import UIKit
import SwiftUI
import UniformTypeIdentifiers
import FieldNotesModel

final class ShareViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        Task { @MainActor in
            let (title, body) = await sharedContent()
            let form = ShareNoteForm(title: title, text: body,
                                     onSave: { [weak self] note in self?.save(note) },
                                     onCancel: { [weak self] in self?.cancel() })
            let host = UIHostingController(rootView: form)
            addChild(host)
            host.view.frame = view.bounds
            host.view.autoresizingMask = [.flexibleWidth, .flexibleHeight]
            view.addSubview(host.view)
            host.didMove(toParent: self)
        }
    }

    private func sharedContent() async -> (String, String) {
        let items = extensionContext?.inputItems as? [NSExtensionItem] ?? []
        let providers = items.flatMap { $0.attachments ?? [] }
        for provider in providers where provider.hasItemConformingToTypeIdentifier(UTType.url.identifier) {
            if let url = try? await provider.loadItem(forTypeIdentifier: UTType.url.identifier) as? URL {
                return (items.first?.attributedContentText?.string ?? url.host() ?? "Link", url.absoluteString)
            }
        }
        for provider in providers where provider.hasItemConformingToTypeIdentifier(UTType.plainText.identifier) {
            if let text = try? await provider.loadItem(forTypeIdentifier: UTType.plainText.identifier) as? String {
                return (String(text.prefix(40)), text)
            }
        }
        return ("Shared note", "")
    }

    private func save(_ note: Note) {
        Task {
            try? await SharedNoteAccess.persistence().save(note)
            extensionContext?.completeRequest(returningItems: nil)
        }
    }

    private func cancel() {
        extensionContext?.cancelRequest(withError: CocoaError(.userCancelled))
    }
}

struct ShareNoteForm: View {
    @State var title: String
    @State var text: String
    let onSave: (Note) -> Void
    let onCancel: () -> Void

    var body: some View {
        NavigationStack {
            Form {
                TextField("Title", text: $title)
                TextField("Note", text: $text, axis: .vertical)
            }
            .navigationTitle("Save to FieldNotes")
            .toolbar {
                ToolbarItem(placement: .cancellationAction) { Button("Cancel", action: onCancel) }
                ToolbarItem(placement: .confirmationAction) {
                    Button("Save") { onSave(Note(title: title, body: text, tags: ["shared"])) }
                        .disabled(title.isEmpty)
                }
            }
        }
    }
}
#endif

See Apple Developer Documentation — NSExtensionContext.

The form doesn’t read NoteStore; the extension has no store, only the App Group. The macOS build of the extension uses the same form and sharedContent() logic in an AppKit view controller. Keep the extension small: it shares the FieldNotesModel and FieldNotesServices packages but not the app’s UI, and it’s killed if it exceeds its memory limit.

ShareLink: Sharing Out of FieldNotes

The share extension brings content in; ShareLink sends it out. In NoteDetail, the toolbar shares the note’s universal link, so the recipient lands on the web page or, with FieldNotes installed, straight on the note:

ToolbarItem {
    ShareLink(item: URL(string: "https://fieldnotes.example.com/note/\(note.id.uuidString)")!,
              subject: Text(note.title),
              message: Text(note.body.prefix(140))) {
        Label("Share", systemImage: "square.and.arrow.up")
    }
}
