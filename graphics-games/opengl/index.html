OpenGL

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

OpenGL is the cross-platform graphics API that taught a generation of programmers how a GPU draws. This sub-section teaches desktop OpenGL 4.6, OpenGL ES 3.2, their shading languages GLSL 4.60 and GLSL ES 3.20, and EGL 1.5, the glue that connects them to a window. It follows one running example, the Bookshelf GL program, from a single triangle to a small game, and it says plainly where OpenGL stands in 2026: frozen at version 4.6, deprecated on Apple platforms, still extended by Khronos and still the base of OpenGL ES on Android and embedded devices. The pages build on the general pages of Graphics & Games; read those first if the rendering pipeline or the transformation chain are new to you.

What OpenGL, OpenGL ES, GLSL and EGL are

Name What it is

OpenGL

A specification, maintained by the Khronos Group, of a C API that sends buffers, textures, shaders and draw commands to the GPU. Drivers implement it; there is no library to download. Version 4.6 is the last.

OpenGL ES

The subset and variant for phones, tablets and embedded devices. ES 2.0 and 3.0 dominate mobile history, and ES 3.2 is the last version. WebGL is its JavaScript binding.

GLSL and GLSL ES

The C-like shading languages in which the programmable stages are written. A shader is passed to the driver as text (or as SPIR-V since OpenGL 4.6) and compiled at run time.

EGL

The Khronos API that creates displays, surfaces and contexts for OpenGL ES (and desktop OpenGL) on Android, embedded Linux and several desktop systems.

OpenGL is a state machine with a global current context: a function call changes the state of the context that is current on the calling thread. The pages in this sub-section keep returning to that fact, because it explains the shape of the API, its convenience for learning and its cost compared with the explicit APIs described in Explicit vs Implicit Graphics APIs.

The family tree

Figure 1. Releases of desktop OpenGL, OpenGL ES, WebGL and the mesh shader extension, 1992 to 2026

Desktop OpenGL grew from IRIS GL (see History of Real-Time Graphics) through a fixed-function era to the shader-based versions 2.0 and 3.x, and then through 4.0 to 4.6 added tessellation, compute shaders, direct state access and SPIR-V. OpenGL ES forked from it for mobile hardware; ES 2.0 removed the fixed function pipeline in 2007, years before the desktop did. WebGL 1 and 2 expose ES 2.0 and ES 3.0 to JavaScript. The details and the mapping between versions are on Versions, Profiles and Extensions.

When to choose OpenGL in 2026

Choose OpenGL when you are learning how the pipeline works, when you maintain or extend an existing OpenGL code base, when you target Android or embedded Linux devices where ES is the lowest common denominator, or when a small cross-platform tool matters more than the last 20 percent of performance. Choose Vulkan, Metal or WebGPU for a new engine, for features such as ray tracing, or for an Apple-only product. The full reasoning is in OpenGL in 2026, and the general criteria are in Choosing an API or Engine.

  5. Give surfaces an appearance with Textures and Samplers in OpenGL, Lighting with Blinn-Phong in OpenGL and Blending, Depth and Stencil in OpenGL.

  6. Continue with the advanced pages on framebuffers, shadows, instancing, compute and post-processing, then the platform pages for the devices you target.

  7. Finish with debugging, performance and the porting map, and keep the OpenGL Cheat Sheet at hand.

Bookshelf GL, the running example

Bookshelf GL is a C++20 program built with CMake, GLFW, glad2 and GLM. Its baseline is an OpenGL 4.1 core context, so that it runs on macOS, with optional 4.6 paths (direct state access, SPIR-V, compute and mesh shaders). An Android variant in Kotlin with GLSurfaceView uses an OpenGL ES 3.0 context and shares the ES-compatible GLSL. It loads the shared bookshelf.glb and the textures described on the section landing page, and it grows page by page:

  1. a triangle (Hello Triangle)

  2. a coloured quad that becomes a book spine (Buffers and Vertex Specification)

  3. a textured, rotating book box (Textures and Samplers in OpenGL)

  4. the shelf mesh lit by a Blinn-Phong desk lamp (Lighting with Blinn-Phong in OpenGL)

  5. normal-mapped wood and a shadow map (Materials and Normal Mapping in OpenGL, Shadow Mapping)

  6. an instanced shelf of books (Instancing and Indirect Drawing)

  7. picking a book with an ID buffer (Text, UI and Input)

  8. post-processing with bloom and a vignette (Framebuffers and Render to Texture)

  9. compute-shader dust particles (Compute Shaders in OpenGL)

  10. a tiny game, "catch the falling book", with an orbit camera, input, a score and timer queries (OpenGL Performance)
