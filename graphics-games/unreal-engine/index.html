Unreal Engine

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Unreal Engine is Epic Games' real-time 3D engine: an editor for building levels and assets, a C++ runtime, the Blueprints visual scripting language, and a renderer built around Nanite, Lumen and MegaLights, with builds for desktop, mobile, consoles and XR headsets. It is what a team reaches for when high-end visuals, large worlds and a complete set of tools matter more than a small footprint. This sub-section teaches Unreal Engine 5.8 with C++ base classes and Blueprint subclasses. It covers the editor, the object model, the gameplay framework, input, rendering, animation, physics, worlds, UI, AI, networking, packaging, profiling and testing. It follows one running example, the Bookshelf, from a single book actor to a co-op library packaged for Windows and Android, and it says plainly where Unreal stands in 2026: 5.8 is the current release, UE6 is announced with Early Access targeted for the end of 2027, and the licence charges nothing until a product earns more than US$1M. The pages build on the general pages of Graphics & Games; read those first if the rendering pipeline or the transformation chain are new to you.

What Unreal Engine and its neighbours are

Name What it is

Epic Games Launcher

The desktop application that installs binary versions of the engine on Windows and macOS.

Unreal Editor

The application where levels, Blueprints, materials and other assets are assembled, and where the game runs with Play In Editor.

Unreal Build Tool and Unreal Automation Tool

UBT compiles the modules of a project. UAT drives longer jobs such as cooking and packaging, and the Unreal Header Tool generates the reflection code that the macros ask for.

Blueprints

The visual scripting language. A Blueprint class can extend a C++ class, which is how the Bookshelf is built.

Fab

Epic’s marketplace for assets and plugins.

Unreal Editor for Fortnite and Verse

UEFN is a separate editor for experiences that run inside Fortnite, and Verse is its programming language. Both are context for UE 5.8 and central to the announced UE6.

Direct3D 12, Vulkan, Metal and OpenGL ES

The graphics APIs underneath, reached through Unreal’s Render Hardware Interface (RHI). Vulkan, Metal and OpenGL teach them directly.

The difference between a graphics API and an engine is explained in Graphics APIs vs Game Engines, and how to decide between them in Choosing an API or Engine. The language itself is in the C++ Reference. If you know Unity, Epic’s Unreal Engine for Unity Developers maps the concepts of one engine to the other.

Where Unreal Engine sits

Figure 1. The layers between your Unreal project and the GPU

An Unreal project is modules of C++, Blueprints and content. You write gameplay on top of the framework classes, and the engine runs it in the same way on every platform. The renderer draws the scene through the RHI, which is why the same project can build for Direct3D 12, Vulkan or Metal. The figure is also a map of this sub-section: the first groups of pages are about the top layers, and Rendering Overview reaches down to the renderer and the RHI. Because the source of the whole engine is available, every layer below your project can be read, and with a source build it can be changed.

Figure 2. What an Unreal project is made of

The vocabulary of the figure is used on every page: a level holds actors, an actor is made of components, an asset is a .uasset file under Content, and a module is a unit of C++ code with its own Build.cs. The folders in detail are on Project Structure and Modules, and the windows of the editor on Editor Tour.

The release model

Figure 3. Unreal Engine 5 releases and the UE6 target

Epic ships a minor version a few times a year, each with its own release notes, and in between it publishes hotfixes for the latest minor version (5.8.1, 5.8.2 and so on). There is no long-term support version: a project chooses a minor version, takes its hotfixes and moves to a newer one when it has a reason to. Each feature carries a stability label in the release notes: Production Ready, Beta or Experimental. A new project should start on the latest minor version with its latest hotfix. Epic has announced UE6 and targets Early Access for the end of 2027, and Verse, UEFN and UE6 Context explains what that means for a project started today.

Licence

Free until a product’s lifetime gross revenue exceeds US$1M, then a 5 percent royalty, with Epic Games Store revenue exempt. Epic’s FAQ gives 3.5 percent under Launch Everywhere with Epic. Non-game companies with more than US$1M of annual gross revenue buy seats at US$1,850 per user per year. Read the terms on Epic’s pages before you ship.

Enhanced Input is enabled by default. Epic’s page calls the older mappings the legacy input system and offers an upgrade path. It does not call them deprecated.

UE5 migration guide

When to choose what

flowchart TD A[Build a real-time 3D or 2D product] --> B{Own renderer or to learn the GPU?} B -- yes --> C[Vulkan, Metal, OpenGL or WebGPU] B -- no --> D{High-end visuals, large worlds, PC and console first?} D -- yes --> E[Unreal Engine 5.8] D -- no --> F{Scripting in C#, mobile, Web or XR reach first?} F -- yes --> G[Unity] F -- no --> H{Browser only, small scene?} H -- yes --> I[three.js] H -- no --> E

Choose Unreal Engine when the visuals, the size of the world or the built-in systems matter most: Nanite, Lumen, the gameplay framework, replication and the animation tools are all there from the first day, with the source to read. It asks for more in return: strong hardware for development, large downloads, and C++ for anything Blueprints cannot do. There is no Web target. Choose Blueprints only for prototypes and for designers' logic, and C++ with Blueprint subclasses for anything that will grow; C++ and Blueprints Together explains the split. The general criteria are in Choosing an API or Engine, and what a shipped game costs is in Versions, Licensing and History.

Running example

The Bookshelf runs on UE 5.8 from the Third Person template, with a C++ module named Bookshelf, C++ base classes and Blueprint subclasses. It imports the shared bookshelf.glb model used by every sub-section of Graphics & Games, so that the same shelf can be compared across APIs and engines. Each code example shows the header and source pair, with the Blueprint equivalent where it helps.

Figure 5. The twelve stages from a book actor to a packaged co-op library

  1. ABookActor and AShelfActor, a static-mesh book with a material instance and a socketed row of books, built from the shared model (Actors and Components, C++ and Blueprints Together and Materials and the Material Editor)

  2. Lumen lighting with a MegaLights desk lamp (Lighting, Lumen and MegaLights)

  3. a "Grab/Read" action (Enhanced Input)

  4. ABookshelfGameMode and a score in the GameState (Gameplay Framework)
