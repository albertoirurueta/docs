GitHub Actions

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

GitHub Actions is the automation platform built into GitHub: a workflow, defined as YAML in .github/workflows/, runs jobs on a runner whenever an event such as a push, a pull request, a tag, a schedule or a manual dispatch occurs. It is the usual way to build, test, scan and publish a repository hosted on GitHub. This subsection is a reference for developers who already use Git and GitHub and want to write, secure and maintain real pipelines: it covers the workflow language first, then the execution model (jobs, runners, caching), then credentials and deployment, then reuse, hardening and releases.

Running example

The running example is this documentation site’s own pipeline: the publish workflow in .github/workflows/publish.yml, which runs every night at 03:00 UTC, installs Node.js and Antora with its extensions, validates the Mermaid diagrams, builds the site into build/site and pushes it to the gh-pages branch. A twin workflow, manual_publish, runs the same steps on workflow_dispatch. Each page explains the existing workflow through its topic and then shows, as a proposal, how it could be improved: more triggers and concurrency control, an npm cache, least-privilege permissions, SHA-pinned actions, a Pages environment and a shared reusable workflow.
