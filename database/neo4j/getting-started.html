Getting started with Neo4j

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Neo4j is a native graph database: data is stored as nodes and relationships rather than rows in tables, and a relationship is a first-class, traversable pointer rather than a foreign key resolved by a join. This page covers the editions and ways to run a server, the shells and APIs used to talk to it, and a first round trip of data through Cypher. It also defines the small movie dataset that every later page of this section reuses, so each query can be tried against the same graph.

Every command and result on this page was run against a neo4j:2026.01 container (kernel 2026.01.4, Community Edition).

How a Neo4j server is put together

A server is one process that exposes two network endpoints and keeps everything in a data directory. Clients never touch the store files: they send Cypher over Bolt (binary, port 7687) or over the HTTP Query API (port 7474), and the server parses, plans and executes it inside a transaction.

Two databases exist from the first start: neo4j, the default database that receives your data, and system, which stores users, roles and the catalog of databases themselves and is administered with Cypher commands rather than queried as a graph. A running instance reports them like this:

SHOW DATABASES YIELD name, type, currentStatus, default;
+-------------------------------------------------+
| name     | type       | currentStatus | default |
+-------------------------------------------------+
| "neo4j"  | "standard" | "online"      | TRUE    |
| "system" | "system"   | "online"      | FALSE   |
+-------------------------------------------------+

Editions and deployment options

Neo4j ships as two editions:

  • Community Edition — free and open-source, single-instance only. Enough to learn Cypher, prototype, and run smaller production workloads.

  • Enterprise Edition — adds clustering for high availability and read scale-out, role-based access control, and composite databases (a single logical database that federates queries across several physical databases or graphs — the modern replacement for the older "Fabric" name). A clustered deployment assigns each member the primary or secondary server role rather than the legacy CORE/READ_REPLICA terms.

You can tell which edition a server is running from Cypher itself:

CALL dbms.components() YIELD name, versions, edition RETURN name, versions, edition;
+----------------------------------------------+
| name           | versions      | edition     |
+----------------------------------------------+
| "Neo4j Kernel" | ["2026.01.4"] | "community" |
| "Cypher"       | ["5", "25"]   | ""          |
+----------------------------------------------+

2 rows

The second row lists the Cypher language versions the server understands (5 and 25); a query runs on the database’s default version unless it starts with a CYPHER 25 or CYPHER 5 prefix.

You can run either edition several ways:

  • Neo4j Desktop — a local GUI application that manages one or more local database instances and opens Neo4j Browser against them. Good for a first exploration on a laptop.

  • Docker — the official image, for a disposable local server or as the base of a containerized deployment.

  • Self-managed — native packages (Debian/RPM, a Windows installer, or a plain archive) run directly on a server or VM you operate yourself.

  • Aura — Neo4j’s fully managed cloud service. AuraDB is the managed graph database (Free, Professional, Business Critical, and Virtual Dedicated Cloud tiers); AuraDS is a managed Graph Data Science workspace built on the same infrastructure. Aura runs the same Cypher engine as a self-managed server and removes patching, backups, and cluster operations.

# Disposable local server via Docker: Bolt on 7687, Browser/HTTP on 7474.
# https://neo4j.com/docs/operations-manual/current/docker/
docker run -d --name neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/change-me-please \
  neo4j:2026.01

Neo4j moved from semantic versioning to calendar versioning (YYYY.MM) in 2025; the tag above pins a specific monthly release rather than a major.minor.patch. See Getting Started for the full installation matrix and What is Neo4j for the broader product tour this page assumes. The docker run options themselves are explained in Running Containers.

Configuring the container

The image keeps everything it writes under /data and reads imports from /var/lib/neo4j/import; mount named volumes or host directories there when the data must outlive the container. Any neo4j.conf setting can be given as an environment variable: prefix it with NEO4J_, replace each dot with an underscore and write each literal underscore as a double underscore.

docker run -d --name neo4j \
  -p 7474:7474 -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/change-me-please \
  -e NEO4J_server_memory_heap_max__size=1G \
  -e NEO4J_server_memory_pagecache_size=512M \
  -v neo4j-data:/data \
  -v "$PWD/import:/var/lib/neo4j/import" \
  neo4j:2026.01

Here server.memory.heap.max_size becomes NEO4J_server_memory_heap_max__size. NEO4J_AUTH sets the initial password for the neo4j user and only takes effect the first time the data volume is initialised: starting a new container on a volume that already holds a database ignores it. The Enterprise image additionally requires NEO4J_ACCEPT_LICENSE_AGREEMENT=yes.

The server is ready when it logs Started., which a script can wait for by polling Cypher instead of sleeping:

until docker exec neo4j cypher-shell -u neo4j -p change-me-please "RETURN 1" >/dev/null 2>&1; do
  sleep 2
done
$ docker logs neo4j 2>&1 | tail -n 8
INFO  Bolt enabled on 0.0.0.0:7687.
INFO  HTTP enabled on 0.0.0.0:7474.
INFO  Remote interface available at http://localhost:7474/
INFO  Started.

Aura: the managed cloud option

Aura removes the deployment step entirely: you create an instance through the web console or its API and get back a Bolt connection URI, with no server to patch or cluster to operate.

  • Aura docs — console usage, instance sizing, snapshots/backups, and the Aura API.

  • AuraDB — the managed graph database product page and its pricing tiers, including a free tier suitable for the examples on this page.

An AuraDB instance and a local Docker container are driven identically from here on: the same Bolt protocol, the same Cypher, and the same two shells described next. The one practical difference is the URI scheme: Aura hands out a neo4j+s://<id>.databases.neo4j.io URI (encrypted), whereas a local container is reached with neo4j://localhost:7687.

Neo4j Browser, cypher-shell and the HTTP API

Three ways to send Cypher ship with every Neo4j deployment (Aura included):

  • Neo4j Browser — a web UI (served on port 7474 for a local/Docker install; embedded in the console for Aura) for running Cypher, visualizing the returned graph, and browsing schema. Reference: Neo4j Browser manual.

  • cypher-shell — a command-line REPL bundled with the server and connecting over Bolt, for scripting and CI. Reference: cypher-shell.

  • The HTTP Query API — a JSON endpoint on the same port as the Browser, for tools that cannot speak Bolt.

$ docker exec -it neo4j cypher-shell -u neo4j -p change-me-please
Connected to Neo4j using Bolt protocol version 6.0 at neo4j://localhost:7687 as user neo4j.
Type :help for a list of available commands or :exit to exit the shell.
Note that Cypher queries must end with a semicolon.
neo4j@neo4j> RETURN "hello" AS greeting;
+----------+
| greeting |
+----------+
| "hello"  |
+----------+

1 row
ready to start consuming query after 1 ms, results consumed after another 0 ms
neo4j@neo4j> :exit
Bye!

\:exit (in cypher-shell) and the equivalent Browser command bar both accept the same Cypher, so anything run in one works unchanged in the other — including the round trip below.

cypher-shell is just as useful non-interactively. It runs a statement passed as an argument, a file given with -f, or text piped on standard input, and --format chooses between the table layout (verbose, which also prints the update counters) and a compact comma-separated one (plain); -P supplies a query parameter.

# a script file, as used in CI
cypher-shell -u neo4j -p change-me-please -f seed.cypher

# one statement, with a parameter and compact output
cypher-shell -u neo4j -p change-me-please --format plain \
  -P '{year: 1995}' \
  'MATCH (m:Movie) WHERE m.released < $year RETURN m.title ORDER BY m.title'
m.title
"Sleepless in Seattle"
"Speed"

The HTTP Query API takes a JSON body with a statement and optional parameters and answers with the field names and rows. It authenticates with HTTP basic auth and is addressed per database (/db/<database>/query/v2); the server advertises the endpoint at its root URL.

$ curl -s -u neo4j:change-me-please -H 'Content-Type: application/json' \
    -X POST http://localhost:7474/db/neo4j/query/v2 \
    -d '{"statement":"MATCH (p:Person) WHERE p.born > $year RETURN p.name AS name ORDER BY name LIMIT 3","parameters":{"year":1960}}'
{"data":{"fields":["name"],"values":[["Carrie-Anne Moss"],["Keanu Reeves"],["Lana Wachowski"]]},"bookmarks":["FB:kcwQtBY5KN5dSmCKXxG2LQUF/BmQ"]}

The bookmarks field is the same causal-consistency token described in Transactions & Drivers.

A first round trip in Cypher

A minimal write-then-read cycle: create two \:Person nodes, a \:Movie node, and an ACTED_IN relationship between one person and the movie, then read them back.

// Write: two people, a movie, and one relationship carrying its own property.
CREATE (keanu:Person {name: "Keanu Reeves", born: 1964})
CREATE (carrie:Person {name: "Carrie-Anne Moss", born: 1967})
CREATE (matrix:Movie {title: "The Matrix", released: 1999})
CREATE (keanu)-[:ACTED_IN {roles: ["Neo"]}]->(matrix)
CREATE (carrie)-[:ACTED_IN {roles: ["Trinity"]}]->(matrix);

// Read: everyone who acted in a given movie, and which role.
MATCH (p:Person)-[r:ACTED_IN]->(m:Movie {title: "The Matrix"})
RETURN p.name AS actor, r.roles AS roles;
+----------------------------------+
| actor              | roles       |
+----------------------------------+
| "Carrie-Anne Moss" | ["Trinity"] |
| "Keanu Reeves"     | ["Neo"]     |
+----------------------------------+

2 rows

That single query already touches the three things every later page builds on: labelled nodes, typed and directed relationships, and property maps on both. The property-graph vocabulary behind \:Person, ACTED_IN, and \{name: "Keanu Reeves"\} is covered in The property graph model, and the MATCH/CREATE/RETURN clauses used here are covered in full in Cypher fundamentals.

The movie dataset used throughout this section

The pages that follow query a slightly larger version of the graph above: eight people and six movies, linked by ACTED_IN (with the character names as a roles list) and DIRECTED relationships. The people and films are chosen so that the interesting patterns exist — an actor who appears in several films, a director linked to actors only through shared films, two clusters (the Matrix films and the Hanks and Ryan comedies) joined by a single bridge film, Cloud Atlas, and one actor who plays two roles in the same film.

Troubleshooting a first run

Symptom Likely cause and fix

42NFF ... permission/access denied. Access denied

Wrong password, or NEO4J_AUTH was ignored because the data volume already existed. Reset by removing the volume, or change the password with ALTER CURRENT USER SET PASSWORD FROM ... TO ....

Connection refused right after docker run

The server is still starting; wait for the Started. log line or poll as shown above.

port is already allocated

Another process owns 7474 or 7687; map different host ports, for example -p 27474:7474 -p 27687:7687, and connect to neo4j://localhost:27687.

The Enterprise image exits immediately

The licence was not accepted; add -e NEO4J_ACCEPT_LICENSE_AGREEMENT=yes (evaluation) or supply a licence.
