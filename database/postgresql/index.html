PostgreSQL Reference

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the PostgreSQL reference. PostgreSQL is an open-source object-relational database: it stores data in typed tables, speaks SQL with a very broad implementation of the standard plus its own extensions (arrays, ranges, jsonb, full-text search, user-defined types), guarantees ACID transactions through multiversion concurrency control and a write-ahead log, and grows through extensions such as PostGIS and pgvector. This section is written for developers and engineers who build on PostgreSQL or run it: it explains how the server works, the SQL and index features that are specific to it, how to read query plans, how concurrency behaves, and how to administer, back up, replicate and tune a deployment. It is verified against the PostgreSQL documentation.

If you are new to PostgreSQL, start with Getting Started, which runs a server in Docker, introduces psql and loads the shop dataset used by every page. Engine-agnostic SQL (DDL, queries, joins, window functions) is documented once in the sibling SQL Reference, which these pages link to rather than repeat.

Version baseline

This section documents PostgreSQL 18, the current major version, and every example was executed against PostgreSQL 18.6 from the official postgres:latest Docker image (Debian build, arm64). Where a feature depends on the version, the page says which release introduced it: for example MERGE (15), JSON_TABLE and MERGE ... RETURNING (17), and virtual generated columns, uuidv7(), skip scans on multicolumn B-tree indexes and OLD/NEW in RETURNING (18). The community releases one major version a year, supports each for five years and publishes minor releases quarterly; see the versioning policy and the release notes.

Running example

The worked examples share one running example, a small online shop in a schema named shop: four tables with 4 customers, 5 products, 8 orders and 11 order lines. The full seed script and the Docker commands to load it are on Getting Started; the same data set backs the MongoDB Reference, so the two engines can be compared on identical data. Pages that need volume (indexing, planning, locking) generate extra rows with generate_series in a scratch schema instead of changing the shop.

erDiagram customers ||--o{ orders : places orders ||--|{ order_items : contains products ||--o{ order_items : "appears in" customers { text id PK text name text email text city text tier timestamptz created_at } products { text sku PK text name text category numeric price integer stock text_array tags jsonb attrs } orders { integer id PK text customer_id FK text status timestamptz order_date } order_items { integer order_id PK text sku PK integer qty numeric price }

A customer places orders (status is open, shipped or cancelled); an order has one or more lines in order_items, each pointing at a product by sku with a quantity and the price at the time of purchase. products carries a tags array and an attrs jsonb document, which give the array, GIN and JSON examples something to work on. The outputs on the pages were produced by running the code on PostgreSQL 18.6 in a container, so every example can be reproduced step by step.
