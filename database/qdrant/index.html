Qdrant Reference

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Welcome to the Qdrant reference. Qdrant is an open-source, self-hostable vector similarity search engine written in Rust: it stores high-dimensional vectors alongside a JSON payload in collections, indexes them with an HNSW approximate-nearest-neighbor graph, and exposes both a REST and a gRPC API (with official Python and Java clients, among others) for filtered similarity search, hybrid dense/sparse retrieval, and the retrieval step of Retrieval-Augmented Generation pipelines.

Some capabilities (Qdrant Cloud-only features and the full breadth of client-library APIs beyond Python and Java) are linked, not documented in depth.

If you are new to Qdrant, read Getting Started first, then Collections & Points and Vector Indexing & HNSW, followed by Filtering & Payload Indexing, Hybrid & Sparse Search, CRUD & Batch Operations, Clustering & Storage, Security & Administration, and finally RAG Integration Patterns. Everything after the first two pages builds on those foundations.

Version baseline

This section documents the current Qdrant 1.x line (latest 1.20.0), written against the official Qdrant documentation and verified by running its examples against a Qdrant 1.20.0 server, including a three-node cluster, a TLS-enabled node and JWT-based access control. No specific patch version is pinned. The Python examples use qdrant-client 1.16 and the Java examples io.qdrant:client 1.20.0.

What’s covered

  • Getting Started — Qdrant as a vector similarity search engine written in Rust, running it via Docker or Qdrant Cloud, health probes, a first create-collection/upsert/search round-trip over REST, Python and Java, how to read responses and errors, and the running example.

  • Collections & Points — collections (fixed vector size and distance metric) and points (id + vector + payload), named vectors and multivectors with worked examples, and how the four distance metrics rank the same points differently.

  • Vector Indexing & HNSW — how Qdrant builds and tunes its HNSW index per collection or named vector, when the index exists at all, exact search, and a measured comparison of scalar, product and binary quantization with rescoring.

  • Filtering & Payload Indexing — payload indexes (keyword, integer, geo, text and more), the must/should/must_not/min_should filter model with its pitfalls, nested conditions, and filtered HNSW search.

  • Hybrid & Sparse Search — named sparse-vector configs, Reciprocal Rank Fusion and DBSF via the Query API’s prefetch mechanism with the arithmetic worked out, nested prefetch, and prefetch + re-ranking.

  • CRUD & Batch Operations — upserting, retrieving, partially updating and deleting points individually or in batches, write acknowledgement semantics, and paging through a collection with the scroll API.

  • Clustering & Storage — a real three-node cluster, sharding and replication, node failure, Raft-based cluster consensus, on-disk vs. in-memory storage trade-offs, and snapshot backup and restore.

  • Security & Administration — static API keys, TLS, JWT-based role-based access control, and the /metrics and /telemetry endpoints.

  • RAG Integration Patterns — chunking and embedding a corpus, storing chunks as points with metadata payloads, access control by filter, keeping the index in sync, evaluating retrieval, and wiring it up via LangChain or LlamaIndex.

  • Cheat Sheet (PDF) — a single-page, printable summary of everything in this section, with a downloadable PDF.

Deliberately out of scope. This section is about Qdrant: its collections, indexes, query API, clustering and security. The following topics appear in most books on the subject but live elsewhere on this site, or are intentionally not covered:

  • Why vector databases exist, and SQL or NoSQL versus vector stores — see What Is a Vector Database and Choosing the Right Database.

  • Embeddings theory (Word2Vec, Doc2Vec, transformer embedding models) and generating embeddings — see Embeddings and Generating Embeddings in Practice.

  • FAISS indexes and the general approximate-nearest-neighbor problem — see FAISS and ANN Indexes.

  • Vector search inside SQLite and PostgreSQL — see Vector Search in SQLite and PostgreSQL and pgvector.

  • Comparing Qdrant with other vector databases — see Comparing Vector Databases.

  • The full RAG pipeline with a local LLM (generation, prompt construction, Ollama) — this section covers only the retrieval half; see RAG Fundamentals, Prompt Augmentation and Generation and Ollama.

  • Conversation search and long-term memory for assistants — see Agent Memory and Semantic Cache.

  • A SQL-like vector query language — intentionally not covered; Qdrant is queried through its REST, gRPC and client APIs, not a query language.

Running example

The section follows one small data set so the pages can be read in any order and their outputs compared. A product catalog named products holds six items with hand-made 4-dimensional vectors, a payload of name, category, price, rating, brand, stock flag, tags and location, and a few related collections: catalog (text and image named vectors), docs (multivectors), articles (dense plus sparse vectors for hybrid search), kb_chunks (a RAG knowledge base) and a three-node cluster that holds a replicated documents collection. Tiny vectors make the arithmetic checkable by hand; the calls are identical to the ones a real embedding model would drive.
