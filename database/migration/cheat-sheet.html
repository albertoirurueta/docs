Cheat Sheet (PDF)

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

A single A4 page to print or keep beside the migration runbook, with the baseline date 2026-11-09 and Debezium 3.7.1.Final (connectors on Java 17 or later, Debezium Server and the Operator on Java 21 or later), Kafka 4.x in KRaft mode and the Bookshop pipeline from Oracle AI Database 26ai Free (FREEPDB1, schema BOOKSHOP) to PostgreSQL 18. Every value on the sheet is taken from the pages of this section, which explain it in full. It covers:

  • the five phases of a CDC migration, with the system that owns the writes, the direction of the change stream and the rollback path in each, from Migration Patterns with CDC;

  • the record key, the value envelope (before, after, source, op, the timestamps and transaction) and the c, u, d, r, t and m operation codes, from Anatomy of a Change Event;

  • the database prerequisites in one entry each for Oracle, PostgreSQL, MySQL and MariaDB, SQL Server and MongoDB, from Oracle Connector, PostgreSQL Connector, MySQL & MariaDB Connectors, SQL Server Connector and MongoDB Connector;

  • a minimal bookshop-oracle-source configuration with the JSON converter and schemas enabled, decimal.handling.mode=string, provide.transaction.metadata=true and the signal table FREEPDB1.BOOKSHOP.DEBEZIUM_SIGNAL, from Oracle Connector and Best Practices;

  • every snapshot.mode value with its deprecated aliases, from Initial Snapshots, and the execute-snapshot signal SQL with the INSERT and DELETE grant on the signal table that the official grant list leaves out, from Signaling & Notifications;

  • the essentials of the bookshop-pg-mirror-sink JDBC sink (insert.mode=upsert, primary.key.mode=record_key, delete.enabled=true, schema.evolution=none, a connection URL that ends in ?stringtype=unspecified, and the dead-letter queue switch), from JDBC Sink Connector;

  • ExtractNewRecordState with every delete.tombstone.handling.mode value, from Event Flattening, and the EventRouter, Filter and ToLogicalTopicRouter transformations with predicates, from Debezium Transformations and Outbox Event Router;

  • the Kafka Connect REST commands, including PUT /connectors/{name}/stop and the GET, PATCH and DELETE /offsets endpoints that need the connector in the STOPPED state, and exactly-once source support, from Offsets, Restarts & Exactly-Once;

  • the metrics to watch during a migration (snapshot progress, MilliSecondsBehindSource, queue capacity, long Oracle transactions, errors, safe restart), from Monitoring, Logging & Tracing;

  • the write cut-over checklist (freeze, drain, final reconciliation, reconfigure forward capture, write guard, start reverse replication, route writes, smoke test) and loop prevention, from Cut-over & Reverse Replication and Best Practices;

  • the properties renamed or removed up to Debezium 3.7 (topic.prefix, schema.history.internal.*, no_data, recovery, delete.tombstone.handling.mode, mongodb.connection.string, ToLogicalTopicRouter, the hybrid mining strategy, and the removal of continuous mining and the Cassandra 3 connector).
