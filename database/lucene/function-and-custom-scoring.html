Function scoring, expressions & sorting

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

Once a query has selected the matching documents, three tools reshape their order: FunctionScoreQuery folds a numeric signal into the score, the lucene-expressions module compiles a short JavaScript formula into a value source for scoring, sorting or faceting, and Sort replaces score order entirely with field order. All three are built on one abstraction — DoubleValuesSource, a per-document double computed lazily from doc values, the score, or another source.

The running example is the book catalogue. The text query is java OR search OR engines, and each book carries a popularity (copies sold, in thousands), a price and a publication year. The outputs below come from real runs against Lucene 10.4.0.

flowchart LR Q["text query: BM25 score"] --> F["FunctionScoreQuery"] V["DoubleValuesSource: doc values, SCORES, expression"] --> F F --> TD["TopDocs ordered by the new score"] Q --> S["IndexSearcher.search(query, n, Sort)"] V --> SF["SortField from DoubleValuesSource or Expression"] SF --> S S --> TF["TopFieldDocs ordered by field values"]

FunctionScoreQuery and DoubleValuesSource

FunctionScoreQuery wraps an inner Query and derives the final score from a DoubleValuesSource instead of (or on top of) BM25. It replaces the old CustomScoreQuery, which no longer exists; FunctionQuery and ValueSource still ship in the module for old code, but new code should use DoubleValuesSource. FunctionScoreQuery lives in the lucene-queries module.

<dependency>
  <groupId>org.apache.lucene</groupId>
  <artifactId>lucene-queries</artifactId>
  <version>10.4.0</version>
</dependency>
// https://lucene.apache.org/core/10_0_0/queries/org/apache/lucene/queries/function/FunctionScoreQuery.html
import org.apache.lucene.queries.function.FunctionScoreQuery;
import org.apache.lucene.search.DoubleValuesSource;
import org.apache.lucene.search.Query;

Query text = parser.parse("java OR search OR engines");   // ordinary BM25 relevance

// boostByValue: multiply the inner score by the value of a numeric field.
DoubleValuesSource popularity = DoubleValuesSource.fromLongField("popularity");
Query boosted = FunctionScoreQuery.boostByValue(text, popularity);

// boostByQuery: multiply the score by `boost` only for docs matching a second query.
Query recent = LongPoint.newRangeQuery("published", cutoffDay, Long.MAX_VALUE);
Query boostRecent = FunctionScoreQuery.boostByQuery(text, recent, 2.0f);

// General form: replace the score with an arbitrary source (see expressions, below).
Query custom = new FunctionScoreQuery(text, myDoubleValuesSource);

TopDocs hits = searcher.search(boosted, 10);

The semantics are exactly what the method names say, and the first one needs care. boostByValue multiplies the BM25 score by the raw value, so a field that spans orders of magnitude replaces text relevance instead of nudging it:

-- plain BM25
   1.0377  Introduction to Information Retrieval
   0.7142  Head First Java
   0.6989  Effective Java
   0.6989  Java Concurrency in Practice
   0.5539  Designing Data-Intensive Applications
   0.5358  Database Internals
-- boostByValue(popularity)
   663.9979  Effective Java
   518.8692  Introduction to Information Retrieval
   499.9055  Head First Java
   498.4997  Designing Data-Intensive Applications
   419.3671  Java Concurrency in Practice
   189.5695  Lucene in Action

Effective Java scores 0.6989 for the text and has popularity 950, so 0.6989 x 950 = 663.9979. The explanation confirms it as a plain product (product of: 0.69894516 ... 950.0 = double(popularity)). A book that barely matches the text but sells well (Designing Data-Intensive Applications, 0.5539 for the text) now outranks a better text match, and Lucene in Action, which matches only on search, enters the top six. Dampen the signal with a function before multiplying. DoubleValuesSource.fromField(field, LongToDoubleFunction) applies one per value:

DoubleValuesSource logPop = DoubleValuesSource.fromField("popularity", v -> Math.log(v));
Query dampened = FunctionScoreQuery.boostByValue(text, logPop);
-- boostByValue(ln(popularity))
   6.4491 Introduction to Information Retrieval
   4.7923 Effective Java
   4.6785 Head First Java
   4.4711 Java Concurrency in Practice

boostByQuery(text, recent, 2.0f) leaves documents that do not match recent untouched and doubles the rest. With recent meaning "published in 2014 or later", Effective Java (2018) goes from 0.6989 to 1.3979 and Designing Data-Intensive Applications (2017) from 0.5539 to 1.1078, while Head First Java (2005) keeps 0.7142.

DoubleValuesSource has factory methods for the common cases: fromLongField, fromIntField, fromDoubleField, fromFloatField and fromField read numeric doc values, SCORES exposes the relevance score, constant(d) is a fixed number, and fromQuery(q) yields the score of a second query. getSortField(reverse) turns any source into a SortField. Arithmetic over several sources is not a method on DoubleValuesSource: build it with an expression (below). See DoubleValuesSource.

FeatureField: numeric relevance signals

FeatureField stores one weight per named feature in a shared field, packed for cheap access at score time. Query it with a bounded transform — saturation, log, sigmoid or linear — so a raw count (popularity, pagerank, recency) contributes a well-behaved, diminishing score term rather than swamping the text relevance. Unlike the multiplicative boostByValue, a feature query is an additive SHOULD clause.

// https://lucene.apache.org/core/10_0_0/core/org/apache/lucene/document/FeatureField.html
import org.apache.lucene.document.FeatureField;
import org.apache.lucene.search.BooleanClause.Occur;
import org.apache.lucene.search.BooleanQuery;

// Index time: many features, one field.
doc.add(new FeatureField("features", "popularity", 950f));
doc.add(new FeatureField("features", "recent", 23f));      // years since 1995

// Query time: pick a saturation curve per feature.
Query bySat    = FeatureField.newSaturationQuery("features", "popularity", 1f, 500f);   // weight, pivot
Query byLog    = FeatureField.newLogQuery("features", "popularity", 1f, 4.5f);          // weight, scaling factor
Query byRecent = FeatureField.newSigmoidQuery("features", "recent", 1f, 15f, 2f);       // weight, pivot, exponent

Query q = new BooleanQuery.Builder()
        .add(text, Occur.MUST)          // must still match the text
        .add(bySat, Occur.SHOULD)       // features only add score
        .add(byRecent, Occur.SHOULD)
        .build();

The explanation of the top hit shows each term added to the BM25 score. Effective Java scores 0.699 from the text, 0.655 from the saturation of popularity 950 around the pivot 500 (950 / (950 + 500)) and 0.702 from the sigmoid of recency 23 around 15 with exponent 2 — together 2.0557:

2.055709 = sum of:
  0.69894516 = sum of:
    0.69894516 = weight(text:java in 0) [BM25Similarity], result of: ...
  0.6551724 = Saturation function on the features field for the popularity feature, computed as w * S / (S + k) from:
    1.0 = w, weight of this function
    500.0 = k, pivot feature value that would give a score contribution equal to w/2
    950.0 = S, feature value
  0.7015915 = Sigmoid function on the features field for the recent feature, computed as w * S^a / (S^a + k^a) from:
    1.0 = w, weight of this function
    15.0 = k, pivot feature value that would give a score contribution equal to w/2
    2.0 = a, exponent, higher values make the function grow slower before k and faster after k
    23.0 = S, feature value

newSaturationQuery("features", "popularity") without a pivot defers the choice: the query prints as SaturationFunction(pivot=null) until it is rewritten against an index, when Lucene derives a pivot from the feature’s value statistics. Passing an explicit pivot fixes the value at which the score reaches half its maximum and keeps scores comparable between indexes. Feature values must be positive finite numbers (a feature that does not apply to a document is simply not added), and a feature is stored at reduced precision, which is enough for ranking. Besides the query forms, the class also provides newLinearQuery, newFeatureSort(field, feature) to sort by a feature, and newDoubleValues(field, feature) to read it as a DoubleValuesSource — so boostByValue(text, FeatureField.newDoubleValues("features", "popularity")) gives the same 663.9979 as the doc-values version above.

Full curve maths and parameter meanings: FeatureField.

The lucene-expressions module

lucene-expressions compiles a JavaScript-syntax string into an Expression, then binds each free variable to a DoubleValuesSource. The result drives scoring, sorting or faceting without a custom Java class.

<dependency>
  <groupId>org.apache.lucene</groupId>
  <artifactId>lucene-expressions</artifactId>
  <version>10.4.0</version>
</dependency>
// https://lucene.apache.org/core/10_0_0/expressions/org/apache/lucene/expressions/js/JavascriptCompiler.html
import org.apache.lucene.expressions.Expression;
import org.apache.lucene.expressions.SimpleBindings;
import org.apache.lucene.expressions.js.JavascriptCompiler;
import org.apache.lucene.search.DoubleValuesSource;
import org.apache.lucene.search.Sort;

// Compile once; Expression is thread-safe, so cache it.
Expression expr = JavascriptCompiler.compile("sqrt(_score) + ln(popularity + 1) * 0.3");

SimpleBindings bindings = new SimpleBindings();
bindings.add("_score", DoubleValuesSource.SCORES);
bindings.add("popularity", DoubleValuesSource.fromLongField("popularity"));

// (a) sort by the expression, high value first
Sort sort = new Sort(expr.getSortField(bindings, true));
TopDocs bySort = searcher.search(query, 10, sort);

// (b) score by the expression
DoubleValuesSource score = expr.getDoubleValuesSource(bindings);
Query rescored = new org.apache.lucene.queries.function.FunctionScoreQuery(query, score);

Run against the catalogue the sort key is the expression value itself, so it can be read back from the FieldDoc:

-- sort by expression (sqrt(_score)+ln(pop+1)*0.3)
   Effective Java  key=2.893283622959714
   Introduction to Information Retrieval  key=2.8836763097553613
   Head First Java  key=2.8108267221232377
   Designing Data-Intensive Applications  key=2.7852884345643654
   Java Concurrency in Practice  key=2.7556078845566594
-- expression _score*(1+ln(pop)/10) used as the score
   1.6827  Introduction to Information Retrieval
   1.1820  Head First Java
   1.1782  Effective Java
   1.1461  Java Concurrency in Practice

The two orders differ because they are different formulas: the first adds a damped text term to a damped popularity term, the second multiplies the text score by a mild popularity factor. Expressions make such experiments a one-line change.

The built-in function set (abs, ceil, ln, log, pow, sqrt, min, max, trigonometric, haversin, …​) and the grammar are listed on the expressions.js package page. JavascriptCompiler.compile(source, functions) accepts a map from function name to MethodHandle, starting from JavascriptCompiler.DEFAULT_FUNCTIONS, to expose a custom static method (the older java.lang.reflect.Method maps convert with convertLegacyFunctions):

public static double discount(double price, double pct) { return price * (1 - pct / 100.0); }

Map<String, MethodHandle> fns = new HashMap<>(JavascriptCompiler.DEFAULT_FUNCTIONS);
fns.put("discount", MethodHandles.lookup().findStatic(MyFunctions.class, "discount",
        MethodType.methodType(double.class, double.class, double.class)));

Expression ex = JavascriptCompiler.compile("discount(priceD, 10)", fns);
SimpleBindings b = new SimpleBindings();
b.add("priceD", DoubleValuesSource.fromDoubleField("priceD"));
TopFieldDocs cheapest = searcher.search(new MatchAllDocsQuery(), 3, new Sort(ex.getSortField(b, false)));
cheapest after 10% off: Head First Java 35.1
cheapest after 10% off: The Pragmatic Programmer 37.800000000000004
cheapest after 10% off: Effective Java 40.5

A custom function must be a public static method taking and returning double. Expressions are compiled to bytecode, so only compile trusted or validated source; never feed user text straight to JavascriptCompiler.

The same DoubleValuesSource feeds a dynamic facet. A range facet needs per-document values that do not depend on the score, so use an expression over doc values — here the price after a 10% discount, bucketed:

// https://lucene.apache.org/core/10_0_0/facet/org/apache/lucene/facet/range/DoubleRangeFacetCounts.html
import org.apache.lucene.facet.*;
import org.apache.lucene.facet.range.DoubleRange;
import org.apache.lucene.facet.range.DoubleRangeFacetCounts;

FacetsCollector fc = searcher.search(new MatchAllDocsQuery(), new FacetsCollectorManager());
Expression disc = JavascriptCompiler.compile("priceD * 0.9");
SimpleBindings b2 = new SimpleBindings();
b2.add("priceD", DoubleValuesSource.fromDoubleField("priceD"));
Facets facets = new DoubleRangeFacetCounts("discounted", disc.getDoubleValuesSource(b2), fc,
        new DoubleRange("under 45", 0.0, true, 45.0, false),
        new DoubleRange("45 and over", 45.0, true, Double.POSITIVE_INFINITY, false));
dim=discounted path=[] value=10 childCount=2
  under 45 (5)
  45 and over (5)

A source that needs the score (DoubleValuesSource.SCORES) cannot back a range facet: the facet counts documents after the search, with no scorer, and the constructor fails with a NullPointerException.

More on the faceting collectors in Filtering & faceting.

Sorting: Sort, SortField, SortedNumericSortField

IndexSearcher.search(Query, n, Sort) returns TopFieldDocs ordered by field values rather than score. Each SortField names a doc-values field, a SortField.Type, and a reverse flag; a Sort is an ordered list of them, with SortField.FIELD_SCORE and SortField.FIELD_DOC available as tie-breakers. Sorting a field requires it to be indexed with a *DocValuesField or one of the IntField-style types (see Documents & fields).

// https://lucene.apache.org/core/10_0_0/core/org/apache/lucene/search/SortField.html
import org.apache.lucene.search.Sort;
import org.apache.lucene.search.SortField;
import org.apache.lucene.search.SortedNumericSelector;
import org.apache.lucene.search.SortedNumericSortField;

// Single-valued numeric field, descending, then by score.
SortField byPrice = new SortField("price", SortField.Type.LONG, true);
byPrice.setMissingValue(Long.MIN_VALUE);          // docs with no price sort last in a descending sort
Sort sort = new Sort(byPrice, SortField.FIELD_SCORE);

// Multi-valued field: choose which of the values represents the document.
SortField byRating = new SortedNumericSortField(
        "rating", SortField.Type.INT, true, SortedNumericSelector.Type.MAX);

// doDocScores=true also computes _score for the returned hits (extra work).
TopFieldDocs page = searcher.search(query, 10, new Sort(byRating), true);

Results for the catalogue (prices stored in cents as long, so 7000 is 70.00):

-- sort price desc
   Introduction to Information Retrieval
   Designing Data-Intensive Applications
   Database Internals
   Solr in Action
-- rating desc then popularity desc, with doDocScores
   Effective Java rating=5 pop=950 score=0.699
   Designing Data-Intensive Applications rating=5 pop=900 score=0.554
   Java Concurrency in Practice rating=5 pop=600 score=0.699
   Introduction to Information Retrieval rating=5 pop=500 score=1.038

All four books have rating 5, so the second key (popularity) orders them; the scores ride along unused. Without doDocScores=true the score of each ScoreDoc of a sorted search is NaN.

Missing values

A document without the sort field sorts as if it had a value. For numeric types the default is zero, not the type’s minimum, so in an ascending sort the documents with no value come first:

-- sort by sales ascending, default missing value
   Head First Java 0              (no sales field)
   Elasticsearch in Action 750
   Solr in Action 900
-- the same sort after setMissingValue(Long.MAX_VALUE)
   Elasticsearch in Action 750
   Solr in Action 900
   ...
   Effective Java 2850
   Head First Java 9223372036854775807

Call setMissingValue(...) with the sentinel that should sort first or last; for SortField.Type.STRING use the constants SortField.STRING_FIRST / SortField.STRING_LAST. Sorting on _score alone is just new Sort() (the default) or new Sort(SortField.FIELD_SCORE). Reference: Sort and SortedNumericSortField.

Paging a sorted result set with searchAfter and a FieldDoc cursor is covered in Retrieving results.

Choosing a tool

Goal Tool

Multiply the text score by a number or by a bonus for matching a second query

FunctionScoreQuery.boostByValue / boostByQuery

Add a bounded bonus for popularity, rank or recency

FeatureField queries as SHOULD clauses

Combine score and fields with a formula and iterate quickly

lucene-expressions as a FunctionScoreQuery source or a SortField

Order by a stored attribute and ignore text relevance

Sort with SortField

Reorder only the top N of a first pass

Rescorer / QueryRescorer (see kNN vector search)
