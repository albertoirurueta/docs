E-commerce Platforms Comparison

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page compares the four e-commerce platforms of this section: Shopify (Admin and Storefront API 2026-10, Shopify CLI 5.0.0), PrestaShop 9.2.0, Magento 2.4.9 (Magento Open Source and Adobe Commerce, with Mage-OS 3.6.0 as context) and WooCommerce 11.2.1 on WordPress. Every number was fetched on 2026-10-27 and every claim about a feature is explained, with examples, on the platform pages linked from the sections below. The approach follows the Documentation Tools Comparison and the Cloud Providers Comparison of this site: data kept in CSV files, charts generated from them, and a stated source and date for every figure. The page does not name a winner, because the right platform depends on who will run the store, what it must sell and who will pay for the work; the last sections turn the data into recommendations by purpose. The overview of the section, with the shared bibliography, is the E-commerce overview.

Scope, methodology and snapshot date

Scope. The four platforms are not the same kind of product. Shopify is a hosted software-as-a-service (SaaS) platform: Shopify runs the servers, the checkout and the upgrades, and the merchant configures a store and installs apps and themes. PrestaShop and Magento Open Source are free software that the merchant (or a host) installs and operates. Adobe Commerce is the licensed edition built from the Magento code base, offered on-premises, on Adobe’s cloud infrastructure and as a software-as-a-service edition. WooCommerce is a free plugin that turns a WordPress site into a store, so every WooCommerce figure also reflects WordPress, its themes, its plugins and the hosting it runs on. Mage-OS, a community distribution of the Magento Open Source code base, appears only as context.

Snapshot date. All values on this page were fetched on 2026-10-27 from the sources listed in References and in scripts/ecommerce-comparison-charts/data/sources.csv; every row of the CSV files carries its own fetch date. Time series end at the latest complete period at that date: 2026-09 for the HTTP Archive Tech Report (October is not published yet), 2026-Q4 to date for Store Leads, and 2026 to date for the yearly series. A value that could not be obtained is shown as n/a, never as zero, and a value that came from a secondary source or from a page that could not be opened from the authoring environment is marked unverified.

Where to check current values. Each table and figure names its source. The live pages are the W3Techs technology pages, the Store Leads reports, the HTTP Archive Tech Report, the Web Almanac e-commerce chapter, the GitHub, npm, WordPress.org and Stack Exchange APIs, the National Vulnerability Database (NVD) API, the official pricing pages and the official lifecycle policies listed in the References. The data and the scripts that draw the figures are in scripts/ecommerce-comparison-charts/, so the charts can be regenerated with npm run charts:ecommerce-comparison.

How the metrics are used. The sections after the feature matrix present metrics in six groups (popularity, performance, security, ease of use and maintenance, cost, and other characteristics), each with a statement of what it measures and what it does not. Three rules apply throughout:

  • Absolute values from different sources are never plotted on one axis, because they count different things: W3Techs counts the share of websites among the top sites it analyses, Store Leads counts live stores it detects, and the HTTP Archive counts origins visited by Chrome users.

  • Field data and counts are reported as measured. Where a number is a proxy (for example CVEs as a proxy for security), the section says what it cannot show.

  • The scores of the radar charts at the end combine this evidence with a stated rubric. Eight of the ten axes are editorial scores whose basis and source are written in data/radar-scores.csv; two (performance and ecosystem) are computed from the data. The rubric is given in Scores on ten axes.

Caveats that apply to the whole page.

  • The platform-comparison sources measure different populations, so a platform can lead in one and trail in another without a contradiction.

  • INP (Interaction to Next Paint) replaced FID (First Input Delay) in the Core Web Vitals definition on 2024-03-12, so pass rates before and after that date are not strictly comparable.

  • PrestaShop and Magento have shrinking populations of detected stores, so their pass rates can be biased by survivor effects (stores that were slow or unmaintained may have left the sample).

  • WooCommerce figures include the whole WordPress stack (theme, page builder, plugins, hosting).

  • Stack Overflow’s site-wide decline since 2023 affects every tag, so question counts for recent years say little about a platform on their own.

  • CVE counts measure disclosure, not real risk, and are not comparable between SaaS and self-hosted software.

  • G2 and Capterra ratings were not used: both sites returned HTTP 403 to automated clients, so the ratings are recorded as n/a (unverified), they would be self-selected user reviews, and they feed no score.

Source: W3Techs, content management systems, HTTP Archive Tech Report and Store Leads reports

Strengths and weaknesses

The table summarises the main strengths and weaknesses of each platform. Each cell is backed by the data later on this page or by the source named under the table.

Platform Strengths Weaknesses

Shopify

Highest Core Web Vitals pass rate of the four (76.25% mobile and 79.50% desktop in 2026-09); the vendor patches and upgrades the platform; hosting, SSL and scaling are included; headless is a documented path; a very large app store

Recurring cost (EUR 32 to 384 per month plus transaction fees); the checkout and the data model are constrained, and full checkout control is Plus-only; code runs only in apps and Functions, not in the platform; the merchant depends on one vendor (lock-in)

PrestaShop

Free and open source; the whole stack can be modified through hooks, overrides and services; multistore and multi-currency in core; a modern Symfony code base; second in the Core Web Vitals comparison (61.45% mobile)

The population of live stores has shrunk by about a third from its 2022 peak; the lowest median mobile Lighthouse score of the four (0.345); no official headless storefront framework; the core ships no Content Security Policy support (an open proposal would add one); far fewer extensions and developers than the largest ecosystems

Magento / Adobe Commerce

The most complete core for large catalogs: multiple sources and stores, scoped prices, B2B on Adobe Commerce, REST and GraphQL APIs; open source edition; deep extension points

Steepest learning curve and heaviest hosting needs; the second-lowest share of origins passing Core Web Vitals (44.57% mobile); six Adobe Commerce and Magento vulnerabilities in the CISA Known Exploited Vulnerabilities catalogue; the Adobe Commerce licence is quote-based

WooCommerce

The largest number of live stores (4,321,090 detected) and the largest share of e-commerce sites; free and open source; all of WordPress for content; the whole plugin ecosystem; a good fit for stores that are also content sites

The lowest Core Web Vitals pass rate (39.32% mobile), partly because the stack is whatever the merchant assembles; the merchant owns updates for WordPress, the theme and every plugin; the largest plugin attack surface (91% of the new WordPress vulnerabilities in 2025 were in plugins); no native multistore or B2B

Source: the figures are those of the tables below, with sources HTTP Archive Tech Report, Store Leads, Patchstack State of WordPress Security 2026, PrestaShop issue 42441 (no Content-Security-Policy in core) and CISA Known Exploited Vulnerabilities catalog

Shopify. The advantage is that the operational work is someone else’s. Hosting, certificates, scaling for peak traffic and platform patches are part of the subscription, and the HTTP Archive field data shows that this translates into the highest share of origins passing Core Web Vitals (see Performance). The price of this is a constrained platform: server-side code runs only in apps and Functions, and the checkout steps beyond the basics are customisable only on Plus. See Shopify Functions and Checkout Extensibility for what can and cannot be changed.

PrestaShop. It is the open-source option with the smallest operational footprint of the PHP platforms and a code base that has been modernised with Symfony in the 9.x line. The weaknesses are scale of ecosystem and momentum: Store Leads detects 144,665 live stores in 2026-Q4 to date against a peak of 220,112 in 2022-Q3. See PrestaShop architecture and hooks.

Magento and Adobe Commerce. The most capable core and the most demanding to run. Choose the edition first: Open Source is free but lacks the B2B extension and the Adobe services, while Adobe Commerce adds them for a licence fee. See Magento editions and ecosystem and versions, lifecycle and requirements.

WooCommerce. The market leader by number of stores, with the lowest barrier to start and the broadest choice of themes and plugins. The same freedom is its main risk: quality and security depend on the plugins chosen and on the host. See WooCommerce architecture and performance and security.

Reading the popularity data. WooCommerce leads every count of stores (4,321,090 live stores, 47.4% of e-commerce systems on W3Techs and 44.4% of e-commerce sites on mobile in the Web Almanac), Shopify is second and still growing, and PrestaShop and Magento are an order of magnitude smaller and shrinking. Magento has the largest developer community by cumulative questions (by far when its dedicated Stack Exchange site is counted) and contributors, a legacy of its peak years. None of these numbers measures revenue: the sources used here support no statement about sales volume or about the quality of the stores counted.

Performance

Performance here means field data: how real visitors experienced the origins (sites) that the HTTP Archive detected as running each platform, taken from the Chrome UX Report and from Lighthouse runs on the HTTP Archive crawl. It is not a controlled benchmark. An origin passes the Core Web Vitals when its 75th percentile values are good for Largest Contentful Paint (LCP), Interaction to Next Paint (INP) and Cumulative Layout Shift (CLS). The numbers describe the whole population of stores built on a platform, including their themes, apps, plugins, hosting and content, so they say how stores on a platform tend to perform, not how fast the platform could be if tuned. The pass rate is the number of origins with good results divided by the number of origins with enough traffic data to be tested.

Core Web Vitals over time

Figure 13: share of origins passing all Core Web Vitals on mobile, monthly from 2020-01 to 2026-09. Source: HTTP Archive Tech Report. The vertical marker is the replacement of FID by INP on 2024-03-12. Every platform improved: Shopify from 16.97% to 76.25%, PrestaShop from 18.94% to 61.45%, Magento from 11.63% to 44.57% and WooCommerce from 8.73% to 39.32%.

Figure 14: the same series on desktop. Source: HTTP Archive Tech Report. Desktop pass rates are close to mobile in 2026-09 (Shopify 79.50%, PrestaShop 62.27%, Magento 45.59%, WooCommerce 39.26%), although they were far higher than mobile in 2020 (Shopify 26.01% against 16.97%).

The INP break. On 2024-03-12 INP replaced FID as the responsiveness metric of the Core Web Vitals. The effect on the series is small but not uniform: between 2024-02 and 2024-03 the mobile pass rate moved from 68.11% to 65.38% for Shopify, from 43.92% to 41.76% for PrestaShop and from 24.79% to 23.28% for Magento, but rose from 26.10% to 26.47% for WooCommerce. A change of definition therefore does not shift all platforms the same way, and changes of a point or two around the marker should not be read as a real change in performance. Nowadays INP is rarely the limiting metric: in 2026-09 between 84.38% and 91.39% of mobile origins have a good INP on every platform, so the pass rate is decided mostly by LCP, where Shopify (87.67% good) leads WooCommerce (43.46%) by more than 44 points.

Survivor bias. The PrestaShop and Magento populations are shrinking (see Live stores and detected origins). If the stores that left were disproportionately the slow and unmaintained ones, the remaining origins look better than the average store of earlier years. The data cannot rule this out, so the rise of the PrestaShop and Magento lines may overstate the improvement of a typical store. The WooCommerce population grew, and its figures include every WordPress theme, page builder and plugin combination.

Security

Security data is the hardest to compare, so this section reports what is counted, says what each count can and cannot show, and explains why the totals for the platforms are not comparable. Three kinds of evidence are used: CVE records in the National Vulnerability Database (NVD), security advisories published by the vendors and the community, and notable incidents with their CVSS v3.1 base score and their status in the CISA Known Exploited Vulnerabilities (KEV) catalogue.

The core series counts CVEs filed against the platform’s own product (a CPE, the standard product identifier, for PrestaShop, for Magento Open Source and Adobe Commerce, and for the WooCommerce plugin). For Shopify the series is the CVEs of the vendor shopify in the NVD, which belong to its open-source libraries and command-line tools; the Shopify platform itself has no core series (n/a).

Why self-hosted PHP platforms and plugin-heavy stores have a larger attack surface

Three facts in the data explain why the exposure of PrestaShop, Magento and WooCommerce stores is larger:

  • The merchant is the patch manager. On a self-hosted platform a fix does not protect a store until someone applies it. Adobe publishes monthly isolated builds and out-of-band hotfixes, but the CISA catalogue added CosmicSting five weeks and SessionReaper six weeks after their publication, which shows that exploitation continued after fixes existed. WooCommerce pushed an automatic update to affected stores in July 2021 for the same reason.

  • Third-party code runs with the privileges of the store. Modules, extensions and plugins execute inside the same PHP process, with access to orders and customers. Patchstack’s State of WordPress Security 2026 reports 11,334 new vulnerabilities in the WordPress ecosystem in 2025, of which 91% were in plugins, 9% in themes and 6 in WordPress core. Friends-of-Presta published 141 advisories in 2023, nearly all for modules, and the Magecart campaigns inject skimmers through vulnerable or compromised extensions.

  • The stack is larger. The web server, PHP, the database, the search engine, the cache and the operating system are the merchant’s (or the host’s) responsibility, together with the platform and every extension.

A SaaS platform removes the first and third of these for the merchant, but not the risk of third-party apps (an app with excessive access scopes can still leak data) or of staff accounts. See PrestaShop security, Magento security and WooCommerce performance and security for the measures on each platform.

Why Shopify’s CVE count is not comparable

Shopify has 21 NVD CVEs by vendor identifier (1 in 2020, 1 in 2022 and 19 in 2026 to date), and a total of 29 by keyword search. These records belong to Shopify’s open-source libraries and command-line tools, such as the CLI, and not to the hosted platform. When Shopify fixes a vulnerability in the platform, it deploys the fix on its own servers and the merchants take no action, so the fix does not appear as a CVE: CVEs exist to tell users of installed software what to update. Shopify instead runs a public bug bounty program on HackerOne, as Automattic does for WooCommerce (Automattic on HackerOne). A CVE count of zero or near zero for a SaaS product therefore does not mean it has fewer vulnerabilities; it means that its vulnerabilities do not need to be announced to the customers. The same applies in reverse: a large number of CVEs for a self-hosted platform shows transparent disclosure as much as a large number of vulnerabilities. Counts should be compared only within one deployment model, and even then they measure disclosure effort, not risk.

Reading the security data. The evidence supports three statements. First, a merchant on Shopify delegates platform patching, which removes a whole class of risk. Second, of the incidents tracked here only Magento’s are in the CISA catalogue (four of its six entries are in the table above), so patching it quickly is not optional. Third, PrestaShop and WooCommerce have few core CVEs a year, and their exposure is concentrated in modules and plugins, so what counts is how many third-party extensions a store installs and how it vets them.

Ease of use

Ease of use has no objective public metric. This page does not use user-review ratings: G2 and Capterra could not be opened from the authoring environment (HTTP 403), their ratings would be self-selected reviews, and they are recorded as n/a (unverified) for all four platforms. The ease-of-use scores in the radar charts are editorial and rest on what a new merchant or developer has to do before the first sale:

  • Shopify (9). Hosting, SSL, a custom domain and upgrades are part of every plan; no server or command line is needed to open a store, and the theme editor and apps cover most needs. Source: Shopify pricing.

  • WooCommerce (7). A plugin installed on an existing WordPress site with a setup wizard in the admin, a familiar editor and a large page-builder ecosystem; the merchant still owns hosting, themes and plugin choices. Source: WooCommerce on WordPress.org.

  • PrestaShop (6). A web installer and a back office with guided onboarding, but the merchant must provide PHP and MySQL hosting and choose modules. Source: PrestaShop system requirements.

  • Magento (3). A Composer installation plus a search engine (OpenSearch), a cache store, cron and database tuning; the admin is powerful but large, and the learning curve is the steepest for merchants and developers. Source: Adobe Commerce system requirements.

For developers the learning curve follows the extension model: Shopify asks you to learn Liquid, the GraphQL APIs and the app and Functions model, and gives no access to the server; PrestaShop and Magento ask for PHP and Symfony or the Magento object manager and configuration (the learning path is on the Magento overview); WooCommerce asks for WordPress hooks and PHP, with React for the block-based admin and checkout. The platform sections start at the Shopify, PrestaShop, Magento and WooCommerce overviews, each with a learning path.

Tools, functionality and other characteristics

Tools and functionality. The scores are editorial and their basis is in data/radar-scores.csv: Magento 9 (the most complete core: multiple sources and stores, B2B on Adobe Commerce, GraphQL and REST), Shopify 8 (built-in checkout, point of sale, Markets, B2B, Flow automation, Functions and an app store with about 32,000 apps; advanced checkout control is Plus-only), WooCommerce 7 (the core covers catalog, orders and the blocks checkout, and most advanced features come from the 10,039 plugins tagged woocommerce and from WordPress itself) and PrestaShop 6 (catalog, multistore and, from 9.2, a one-page checkout and improved B2B behind flags, with breadth beyond the core from paid Addons modules).

Scalability. Shopify 9 (managed infrastructure that scales with traffic, with API rate limits and plan caps as the limits), Magento 8 (designed for large catalogs and traffic with indexers, message queues and cloud editions, at the cost of infrastructure and tuning), WooCommerce 6 (scales with WordPress hosting and caching; high order volumes need HPOS, the custom order tables, and careful plugin selection) and PrestaShop 5 (scales by sizing hosting and caching yourself; the platform targets small and mid-size catalogs and has the lowest median mobile Lighthouse score, 0.345).

Production deployment complexity. Shopify has none: the vendor runs the infrastructure. The three self-hosted platforms can all run as stateless containers on several Kubernetes nodes with a managed database, but the amount of state to move out of the server differs. WooCommerce inherits WordPress: uploads, the object cache, cron and the session table (WooCommerce: Cloud Deployment Overview). PrestaShop core has no S3 media option and no TLS setting for its database client, so images stay on shared storage and an encrypted database connection needs a workaround (PrestaShop: Cloud Reference Architecture). Magento needs the most: managed OpenSearch, Valkey and RabbitMQ in addition to the database, Varnish with purge fan-out, and separate consumers, cron and indexers (Magento: Cloud Reference Architecture). The WordPress-side design that the WooCommerce store builds on is in WordPress: Cloud Reference Architecture.

Customisation flexibility. WooCommerce and Magento 9 (open code with actions, filters and block extensibility, or with dependency injection, plugins, preferences, observers and layout XML), PrestaShop 8 (open PHP and Symfony code, hooks, overrides and services) and Shopify 6 (Liquid, theme blocks, apps and Functions allow wide changes, but server code, the checkout and the data model are constrained).

Vendor lock-in and data portability. Shopify is proprietary: the themes use Liquid, the apps use Shopify’s APIs and the data lives on Shopify’s servers, so leaving means exporting data and rebuilding the theme and the integrations. The open-source platforms keep the code and the database under the merchant’s control and can move between hosts, at the price of operating them. No numeric lock-in metric exists, so it does not appear in the radar charts.

Headless readiness. Shopify 9 (Storefront API, Customer Account API, Hydrogen and Oxygen: a documented first-class path), Magento 8 (GraphQL and REST APIs, PWA Studio and the headless Adobe Commerce storefront, with heavy integration work), WooCommerce 7 (REST API v3 and the Store API; GraphQL needs a community plugin) and PrestaShop 5 (data APIs only, with no official storefront framework or storefront API).

Internationalisation and B2B. Shopify Markets, the PrestaShop multistore with CLDR locales, Magento store views and WooCommerce through WordPress language packs and a multilingual plugin all support several languages and currencies, with different depth (see the feature matrix). B2B is built into Shopify on all plans with limits, into Adobe Commerce as an extension, behind a flag in PrestaShop 9.2, and only through plugins in WooCommerce.

Developer job demand. Not reported: no trusted public source with a comparable method was found.

Built-in features, APIs, developer tooling and marketplace breadth: 9-10 broad core plus enterprise features; 7-8 broad core or a very large app ecosystem; 5-6 solid catalog and checkout with extras from paid modules; below 5 limited

Security posture

editorial

Who patches, vendor response, exploited vulnerabilities (CISA KEV) and the attack surface of third-party code: 8-10 centrally patched SaaS; 5-7 predictable patches but exploited or module-heavy; 3-4 a very large third-party plugin attack surface

Low cost

editorial

10 is the lowest total cost of entry: 8-9 free software with moderate infrastructure; 5-6 subscription plus fees; 3-4 heavy infrastructure or a quote-based licence; 1-2 enterprise pricing

Customisation flexibility

editorial

How much of the stack can be changed: 9-10 open code with deep extension points; 7-8 open code; 5-6 constrained by the platform (checkout, data model)

Scalability

editorial

9-10 managed elastic infrastructure; 7-8 designed for large catalogs but needing tuning; 5-6 dependent on self-chosen hosting and caching

Ecosystem

computed

The mean of three log-scaled measures: live stores (10,000 scores 0 and 10,000,000 scores 10), Stack Overflow questions of the platform’s tags (1,000 scores 0 and 1,000,000 scores 10; dedicated Stack Exchange sites such as magento.stackexchange.com are not counted, because not every platform has one) and GitHub stars of the main repositories (100 scores 0 and 100,000 scores 10)

Headless readiness

editorial

9-10 a documented storefront API and framework; 7-8 full APIs without an official storefront framework; 5-6 data APIs only

Recommendations by purpose

The data snapshot date for every figure below is 2026-10-27. The recommendations are justified only by the data on this page. They name the option the evidence favours first and what to check, and they are not rankings: a team with deep experience of one platform can reasonably choose it against the table.

Use case Fits best Evidence on this page What to check, and where to read more

Small merchant, no technical staff

Shopify; WooCommerce on managed WordPress hosting

Shopify scores 9 on ease of use and maintenance and has the highest Core Web Vitals pass rate (76.25% mobile); Basic costs EUR 32 a month plus 2.1% and EUR 0.30 per card payment. WooCommerce has no licence fee and the largest number of live stores (4,321,090).

Recurring costs of apps and fees on Shopify; who updates WooCommerce and its plugins. See Shopify store setup and WooCommerce store setup.

Fast-growing direct-to-consumer brand

Shopify

Scalability 9 (managed infrastructure), API versions supported for 12 months or more, 32.4% of e-commerce systems on W3Techs and the fastest growth in live stores (3,189,134, up from 753,977 in 2019-Q1). Advanced and Plus add lower card rates (1.6% and 1.3%).

Plan caps and API rate limits; checkout customisation beyond the basics needs Plus. See Plans and Shopify Plus and Shopify Functions.

Full code ownership on a budget

PrestaShop or WooCommerce

Both are free software (EUR 0 licence), customisation flexibility 8 and 9, and neither charges a platform fee. PrestaShop has multistore and multi-currency in core; WooCommerce has the largest plugin ecosystem (10,039 tagged plugins).

Hosting and maintenance are yours: the self-hosted platforms have the heavier maintenance load and, for WooCommerce, the lowest security-posture score (4). See PrestaShop module basics, WooCommerce extension development and the Laravel route in Laravel for a store you build yourself.

Content-led store on an existing WordPress site

WooCommerce

WordPress is on 39.6% of all websites, WooCommerce is the e-commerce plugin with 7.8% of all websites, and ease of use is 7.

Core Web Vitals pass rate is the lowest (39.32% mobile), so budget for hosting, caching and an optimised theme. See WooCommerce performance and security.

Large catalog or B2B enterprise

Magento / Adobe Commerce; Shopify Plus for teams that prefer SaaS

Tools and functionality 9, scalability 8, B2B extension on Adobe Commerce; Shopify supports B2B on all plans (three catalogs) with unlimited catalogs on Plus.

Heavy infrastructure, specialist developers and the security record: six CISA KEV entries and seven Adobe bulletins in 2026 to date. See Magento catalog, multistore and B2B and Shopify B2B.

Headless storefront

Shopify; Magento

Headless readiness 9 (Shopify: Storefront API, Hydrogen, Oxygen) and 8 (Magento: GraphQL, PWA Studio); WooCommerce 7 with the Store API; PrestaShop 5 (data APIs, no storefront framework). Pair a headless storefront with a React framework such as Next.js.

Headless adds a front-end team and its own performance and security work. See Storefront API and Hydrogen, Magento REST and GraphQL APIs and WooCommerce Store API.

Regulated sector or data-residency requirements

A self-hosted platform (PrestaShop, Magento or WooCommerce), or a SaaS contract that satisfies the rules

The self-hosted platforms let the merchant choose the host and the region and audit the code. This page has no dataset on data residency (n/a), so a SaaS option must be checked against the vendor’s contract and certifications.

The merchant owns patching and compliance work on a self-hosted platform. See PrestaShop security and Magento security.

Two points matter in every case. First, the cheapest choice on the price list is often not the cheapest in total, because hosting, development and maintenance fall on the merchant for self-hosted platforms, and fees and apps accumulate on Shopify. Second, the performance and security figures describe populations of stores. A well-run Magento, PrestaShop or WooCommerce store can match the Shopify numbers, and a poorly configured Shopify store with many apps can fall behind them, so these recommendations are starting points that a short proof of concept on the shortlisted platforms should confirm.
