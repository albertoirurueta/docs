Multi-factor authentication and step-up

This documentation was generated with the assistance of AI. Please report any inaccuracies.

The password is the first factor. A second factor (a TOTP code or a recovery code) is asked when a request needs it, and the tokens that come out of that sign-in say so, so a resource server, or this server’s own account API, can demand a recent multi-factor sign-in for sensitive operations (RFC 9470).

When a second factor is required

A second factor is required when the client asks for it (its mfaRequired setting, read through IsClientMfaRequiredUseCase and the client port, so only the persistence adapter knows how it is stored), when an administrator forced it on the account (users.mfa_required) or when the user has confirmed a second factor: a factor the user enrolled protects every sign-in, whatever the client. The administrator flag stays separate, so removing the last second factor lifts the requirement only when no administrator set it. "Has a confirmed second factor" asks every SecondFactorEnrolmentQuery bean (TOTP’s is IsTotpEnabledUseCase, and the passkeys' is HasConfirmedPasskeyUseCase, see Passkeys (WebAuthn)), so a later second factor joins by declaring its own.

/**
 * Use case that tells whether the account of a user requires a second factor, whatever the client being served: when
 * an administrator forced it ({@code users.mfa_required}) or when the user has confirmed a second factor (asked to
 * {@link HasConfirmedSecondFactorUseCase}), since a factor the user enrolled must protect every sign-in. The two
 * stay separate: removing the last second factor lifts the second, never the first.
 */
@Service
@Transactional(readOnly = true)
@RequiredArgsConstructor
public class IsUserMfaRequiredUseCase {

    /** Port that provides the user accounts. */
    private final UserAccountRepository userAccountRepository;

    /** Port that stores the per-user multi-factor settings. */
    private final UserMfaSettingsRepository userMfaSettingsRepository;

    /** Use case that tells whether the user has confirmed a second factor. */
    private final HasConfirmedSecondFactorUseCase hasConfirmedSecondFactorUseCase;

    /**
     * Tells whether an account requires a second factor.
     *
     * @param username name the user signs in with.
     * @return {@code true} when the account exists and either an administrator requires it or the user has a
     *         confirmed second factor; {@code false} otherwise, or when the account does not exist.
     */
    public boolean execute(final String username) {
        return userAccountRepository.findByUsername(username)
                .map(UserAccount::id)
                .map(id -> userMfaSettingsRepository.isRequired(id) || hasConfirmedSecondFactorUseCase.execute(id))
                .orElse(false);
    }
}
/**
 * Use case that tells whether a client makes multi-factor authentication mandatory for every user signing in through
 * it ({@link ClientRegistration#mfaRequired()}). How the flag is stored is the business of the client port's adapter
 * alone.
 */
@Service
@Transactional(readOnly = true)
@RequiredArgsConstructor
public class IsClientMfaRequiredUseCase {

    /** Port that stores the clients. */
    private final ClientRegistrationRepository clientRegistrationRepository;

    /**
     * Tells whether a client requires a second factor.
     *
     * @param clientId public identifier of the client, or {@code null} when the request names none.
     * @return {@code true} when the client is registered and requires it; {@code false} otherwise.
     */
    public boolean execute(final String clientId) {
        return clientId != null && clientRegistrationRepository.findByClientId(clientId)
                .map(ClientRegistration::mfaRequired)
                .orElse(false);
    }
}

The sign-in policy (MfaPolicy) is satisfied by a strong primary factor alone, or by the password plus a second factor or a remembered (trusted) device; see Trusted devices and configuration.

Second-factor page

A user who signed in with a password and whose request needs a second factor is sent to GET /login/second-factor. The page is defined by the contract apis/auth-server/web-pages/auth-server-pages-v1.yaml; SecondFactorController implements the generated interface and renders second-factor.html, which shows the form of every SecondFactorFragment bean (see LoginMethodFragment in Login pages and the BFF). A fragment that depends on the signed-in user (an enrolment form, a warning) adds its data through modelAttributes. A factor is added by declaring its own fragment and filter, never by editing the page.

        security chain (for the TOTP code, a recovery code or the enrolment code, POST /login/second-factor/totp),
        never to this operation; once the factor is verified the browser resumes the request that was interrupted
        (after an enrolment, it first goes to the recovery codes page). A request without a signed-in session is

Lockout

Failed attempts are recorded through SecondFactorAttemptRepository; after authserver.mfa.max-failed-attempts consecutive failures the second factor is locked for authserver.mfa.lockout. Every verification (TOTP code, recovery code, enrolment code) starts with CheckSecondFactorLockoutUseCase, which reads the user’s attempt row FOR UPDATE inside the use case’s transaction: concurrent attempts of the same user run one after the other, so none of them can pass the check while another is about to count a failure.

/**
 * Use case that tells whether the second factor of a user is locked after too many failed attempts. It locks the
 * user's attempt row until the end of the caller's transaction, so the verifications of the same user (each a
 * transactional use case that starts with this check) run one at a time: none of them can pass the check while
 * another one is about to count a failure.
 */
@Service
@Transactional
@RequiredArgsConstructor
public class CheckSecondFactorLockoutUseCase {

    /** Port that stores the failed-attempt counters. */
    private final SecondFactorAttemptRepository secondFactorAttemptRepository;

    /** Source of the current time. */
    private final Clock clock;

    /**
     * Checks the lockout of a user.
     *
     * @param userId identifier of the user.
     * @return {@code true} if the second factor is locked right now.
     */
    public boolean execute(final UUID userId) {
        return secondFactorAttemptRepository.lockForUpdate(userId).isLocked(clock.instant());
    }
}
    /** Statement that creates the clean state of a user unless one exists, so there is always a row to lock. */
    private static final String ENSURE_ATTEMPTS = """
            INSERT INTO second_factor_attempts (user_id, failed_count) VALUES (?, 0)
            ON CONFLICT (user_id) DO NOTHING
            """;

    /**
     * Query returning the state of a user and locking its row until the end of the transaction: a concurrent
     * verification of the same user waits here until the first one commits.
     */
    private static final String LOCK_ATTEMPTS = """
            SELECT failed_count, locked_until FROM second_factor_attempts WHERE user_id = ? FOR UPDATE
            """;
    /**
     * Single-statement upsert that counts one failure and sets the lock when the maximum is reached. A lock that
     * has already ended restarts the counter at one. Concurrent failures serialize on the row, so none is lost.
     */
    private static final String RECORD_FAILURE = """
            INSERT INTO second_factor_attempts AS t (user_id, failed_count, locked_until)
            VALUES (:userId, 1, CASE WHEN 1 >= :maxAttempts THEN :lockedUntil ELSE NULL END)
            ON CONFLICT (user_id) DO UPDATE SET
                failed_count = CASE WHEN t.locked_until IS NOT NULL AND t.locked_until <= :now
                                    THEN 1 ELSE t.failed_count + 1 END,
                locked_until = CASE
                    WHEN (CASE WHEN t.locked_until IS NOT NULL AND t.locked_until <= :now
                               THEN 1 ELSE t.failed_count + 1 END) >= :maxAttempts THEN :lockedUntil
                    WHEN t.locked_until <= :now THEN NULL
                    ELSE t.locked_until END
            RETURNING failed_count, locked_until
            """;

TOTP and recovery codes

The code is verified by TotpAuthenticationFilter (POST /login/second-factor/totp) through TotpAuthenticationProvider; a recovery code is accepted in the same form and is consumed when used. Recovery codes only stand in for a confirmed second factor: they are generated (GenerateRecoveryCodesUseCase) and accepted (VerifyRecoveryCodeUseCase) only while the account has one, and an attempt without it fails and counts towards the lockout. On success the session id changes and the CSRF token is renewed, with the same session authentication strategy the form login uses (TotpChainCustomizer hands the chain’s shared strategy to the filter).

    /**
     * Builds the verification request from the form and the authentication the user already holds, and keeps in the
     * session the recovery codes an enrolment generates, until they are shown.
     *
     * @param request  the request.
     * @param response the response.
     * @return the authentication with the TOTP factor added.
     * @throws AuthenticationException if nobody is signed in or the code is not accepted.
     */
    @Override
    public Authentication attemptAuthentication(final HttpServletRequest request, final HttpServletResponse response)
            throws AuthenticationException {
        final var current = SecurityContextHolder.getContext().getAuthentication();
        if (current == null || !current.isAuthenticated() || current instanceof AnonymousAuthenticationToken) {
            throw new InsufficientAuthenticationException("The user has not signed in yet");
        }
        final var code = StringUtils.trimWhitespace(request.getParameter(CODE_PARAMETER));
        final var verification = new TotpAuthenticationToken(current, code == null ? "" : code, kindOf(request));
        final var verified = getAuthenticationManager().authenticate(verification);
        if (!verification.issuedRecoveryCodes().isEmpty()) {
            pendingRecoveryCodes.save(request, verification.issuedRecoveryCodes());
        }
        return verified;
    }

    /**
     * Remembers the device when the user asked for it, then saves the authentication and resumes the request.
     *
     * @param request    the request.
     * @param response   the response.
     * @param chain      the rest of the chain.
     * @param authResult the verified authentication.
     * @throws IOException      if the redirect cannot be sent.
     * @throws ServletException if the success handler fails.
     */
    @Override
    protected void successfulAuthentication(final HttpServletRequest request, final HttpServletResponse response,
            final FilterChain chain, final Authentication authResult) throws IOException, ServletException {
        if (request.getParameter(REMEMBER_PARAMETER) != null) {
            final var created = createTrustedDeviceUseCase.execute(userResolver.userIdOf(authResult.getName()),
                    authResult.getName(), userAgentSummary(request));
            cookieWriter.write(response, created);
        }
        super.successfulAuthentication(request, response, chain, authResult);
    }
    /**
     * Verifies the code.
     *
     * @param authentication the {@link TotpAuthenticationToken} to verify.
     * @return the authentication the user already holds with the TOTP factor added.
     * @throws AuthenticationException if the code is wrong, the second factor is locked or the account is unknown.
     */
    @Override
    public Authentication authenticate(final Authentication authentication) throws AuthenticationException {
        final var request = (TotpAuthenticationToken) authentication;
        final var primary = request.primary();
        final var username = primary.getName();
        final var userId = userResolver.userIdOf(username);
        final boolean accepted;
        try {
            accepted = totpCodeVerifier.verify(request, userId, username);
        } catch (final SecondFactorLockedException e) {
            throw new LockedException("The second factor is locked", e);
        } catch (final TotpNotEnrolledException | TotpAlreadyEnabledException e) {
            throw new BadCredentialsException("No enrolment is waiting to be confirmed", e);
        }
        if (!accepted) {
            throw new BadCredentialsException("The code is not valid");
        }
        return factorGrantor.grant(primary, TotpFactor.AUTHORITY);
    }
    /**
     * Hands the session authentication strategy of the chain to the TOTP filter. The strategy is a shared object of
     * the chain that only exists once every configurer has been initialised (the CSRF configurer adds its
     * {@code CsrfAuthenticationStrategy} to the session management one), so it is read in {@link #configure}, as the
     * form login does for its own filter. Package-private so its test can drive it.
     */
    @RequiredArgsConstructor
    static final class SessionStrategyConfigurer
            extends AbstractHttpConfigurer<SessionStrategyConfigurer, HttpSecurity> {

        /** The filter that gets the strategy. */
        private final TotpAuthenticationFilter filter;

        /**
         * Sets the shared strategy, when the chain has one, on the filter.
         *
         * @param http security builder of the chain.
         */
        @Override
        public void configure(final HttpSecurity http) {
            final var strategy = http.getSharedObject(SessionAuthenticationStrategy.class);
            if (strategy != null) {
                filter.setSessionAuthenticationStrategy(strategy);
            }
        }
    }

Enrolment during the sign-in

A user who must present a second factor but has none is not stuck: the TOTP fragment shows the enrolment form instead (a new pending secret as a QR code and as its otpauth URI). The QR code is a data: URI, which the pages' Content-Security-Policy allows for images. The first code is posted to the same filter with the enroll field; ConfirmTotpAtSignInUseCase confirms the app (a wrong code counts towards the lockout) and the code is the second factor of that sign-in. The browser then goes to GET /login/second-factor/recovery-codes, which shows the new recovery codes once (they are taken out of the session as the page renders) and whose Continue link resumes the interrupted authorization request.

/**
 * Contributes the TOTP forms to the second-factor page, as every second factor does through the
 * {@link SecondFactorFragment} extension point. What the fragment shows depends on the signed-in user:
 *
 * <ul>
 *   <li>without a confirmed authenticator app but with another confirmed second factor (for example a passkey),
 *       nothing: that factor completes the sign-in, so no secret is generated and no enrolment is offered;</li>
 *   <li>without any confirmed second factor, the enrolment form: a new secret is generated (replacing any pending
 *       one), shown as a QR code and as its {@code otpauth} URI, and the first code confirms it;</li>
 *   <li>with one, the form of its code and the recovery-code form, plus a warning when
 *       {@value CountRecoveryCodesUseCase#LOW_THRESHOLD} or fewer recovery codes are left.</li>
 * </ul>
 */
@Component
@RequiredArgsConstructor
public class TotpSecondFactorFragment implements SecondFactorFragment {

    /** Position of the TOTP forms in the second-factor page. */
    public static final int ORDER = 100;

    /** Model attribute telling the fragment to show anything at all. */
    public static final String OFFERED_ATTRIBUTE = "totpOffered";

    /** Model attribute telling the fragment to show the enrolment form. */
    public static final String ENROLMENT_ATTRIBUTE = "totpEnrolment";

    /** Model attribute with the {@code otpauth} URI of the enrolment. */
    public static final String OTPAUTH_URI_ATTRIBUTE = "totpOtpauthUri";

    /** Model attribute with the QR code of the enrolment, as a {@code data:} URI. */
    public static final String QR_CODE_ATTRIBUTE = "totpQrCode";

    /** Model attribute with the number of unused recovery codes. */
    public static final String CODES_LEFT_ATTRIBUTE = "totpRecoveryCodesLeft";

    /** Model attribute telling the fragment to warn that few recovery codes are left. */
    public static final String CODES_LOW_ATTRIBUTE = "totpRecoveryCodesLow";

    /** Resolves the identifier of the account of the signed-in user. */
    private final SecondFactorUserResolver userResolver;

    /** Tells whether the user has a confirmed authenticator app. */
    private final IsTotpEnabledUseCase isTotpEnabledUseCase;

    /** Tells whether the user has confirmed another second factor. */
    private final HasConfirmedSecondFactorUseCase hasConfirmedSecondFactorUseCase;

    /** Starts an enrolment. */
    private final EnrollTotpUseCase enrollTotpUseCase;

    /** Counts the unused recovery codes. */
    private final CountRecoveryCodesUseCase countRecoveryCodesUseCase;

    /** Renders the enrolment URI as a QR code. */
    private final QrCodeRenderer qrCodeRenderer;

    @Override
    public String templateName() {
        return "totp";
    }

    @Override
    public String fragmentName() {
        return "form";
    }

    @Override
    public int order() {
        return ORDER;
    }

    /**
     * Supplies the enrolment (a new pending secret) to a user without any confirmed second factor, the number of
     * recovery codes left to a user with a confirmed authenticator app, and hides the forms from a user whose only
     * confirmed second factors are other ones.
     *
     * @param authentication the authentication of the user the page is rendered for.
     * @return the model attributes; none when nobody is signed in.
     */
    @Override
    public Map<String, Object> modelAttributes(final Authentication authentication) {
        if (!MfaAuthorizationManager.isUser(authentication)) {
            return Map.of();
        }
        final var username = authentication.getName();
        final var userId = userResolver.userIdOf(username);
        if (!isTotpEnabledUseCase.execute(userId)) {
            if (hasConfirmedSecondFactorUseCase.execute(userId)) {
                return Map.of(OFFERED_ATTRIBUTE, false);
            }
            final var otpauthUri = enrollTotpUseCase.execute(userId, username);
            return Map.of(OFFERED_ATTRIBUTE, true, ENROLMENT_ATTRIBUTE, true, OTPAUTH_URI_ATTRIBUTE, otpauthUri,
                    QR_CODE_ATTRIBUTE, qrCodeRenderer.render(otpauthUri));
        }
        final var left = countRecoveryCodesUseCase.execute(userId);
        return Map.of(OFFERED_ATTRIBUTE, true, ENROLMENT_ATTRIBUTE, false, CODES_LEFT_ATTRIBUTE, left,
                CODES_LOW_ATTRIBUTE, left <= CountRecoveryCodesUseCase.LOW_THRESHOLD);
    }
}

Enrollment and account API

The user enrolls an authenticator and manages the recovery codes and trusted devices through the account API, defined in apis/auth-server/rest-server/auth-server-api-v1.yaml.

POST /api/account/totp

Starts the enrollment: returns the secret, the otpauth:// URI and a QR code.

POST /api/account/totp/confirm

Confirms the enrollment with a first code and returns the recovery codes (shown once).

Disables TOTP, removes the recovery codes and revokes every trusted device. Needs a step-up.

Generates a new set of recovery codes, invalidating the previous ones. Needs a confirmed authenticator app (otherwise 400, problem type urn:problem:mfa:totp-not-enrolled) and a step-up.

Lists the devices that skip the second factor.

Step-up on the account API

Removing or resetting the second factor must not be possible with a stolen token or a session left open. While the account has a confirmed second factor, StepUpGuard (called first by those controllers; the /api/** security chain is unchanged) requires the bearer token to show a multi-factor sign-in (acr urn:irurueta:acr:mfa) whose auth_time is within authserver.mfa.step-up-max-age. Otherwise the answer is 401 with WWW-Authenticate: Bearer error="insufficient_user_authentication", acr_values="urn:irurueta:acr:mfa", max_age="300" and a problem body: the client signs the user in again with those acr_values and max_age and retries. An account without a second factor cannot step up and is not asked to.

/**
 * Guards the API operations that remove or reset a second factor (disabling the authenticator app, generating new
 * recovery codes, revoking a trusted device): a stolen token, or a session left open, must not be enough to weaken the
 * account. While the account has a confirmed second factor, the bearer token must show a multi-factor sign-in
 * ({@code acr} {@value AuthenticationContextClass#MULTI_FACTOR}) whose {@code auth_time} is within
 * {@code authserver.mfa.step-up-max-age}; otherwise an {@link InsufficientUserAuthenticationException} asks the client
 * to step up (RFC 9470). An account without a second factor cannot step up, so it is not asked to. The controllers call
 * it first; the {@code /api/**} chain itself is not changed.
 */
@Component
@RequiredArgsConstructor
public class StepUpGuard {

    /** Tells whether the account has a confirmed second factor. */
    private final HasConfirmedSecondFactorUseCase hasConfirmedSecondFactorUseCase;

    /** Multi-factor settings, with the maximum age of the sign-in. */
    private final MfaProperties mfaProperties;

    /** Clock the age of the sign-in is measured with. */
    private final Clock clock;

    /**
     * Requires a recent multi-factor sign-in from the bearer token of the current request.
     *
     * @param userId identifier of the account the operation acts on.
     * @throws InsufficientUserAuthenticationException if the account has a confirmed second factor and the token does
     *                                                 not show a recent enough multi-factor sign-in.
     */
    public void requireRecentMultiFactor(final UUID userId) {
        if (!hasConfirmedSecondFactorUseCase.execute(userId)) {
            return;
        }
        final var maxAge = mfaProperties.stepUpMaxAge();
        final var authentication = SecurityContextHolder.getContext().getAuthentication();
        if (!(authentication instanceof JwtAuthenticationToken token)
                || !isRecentMultiFactor(token.getToken(), maxAge)) {
            throw new InsufficientUserAuthenticationException(AuthenticationContextClass.MULTI_FACTOR, maxAge);
        }
    }

    /**
     * Tells whether a token shows a multi-factor sign-in that is recent enough.
     *
     * @param jwt    the bearer token.
     * @param maxAge maximum age of the sign-in.
     * @return {@code true} when {@code acr} is the multi-factor class and {@code auth_time} is at most {@code maxAge}
     *         old (and not in the future).
     */
    private boolean isRecentMultiFactor(final Jwt jwt, final Duration maxAge) {
        if (!AuthenticationContextClass.MULTI_FACTOR.equals(jwt.getClaimAsString(IdTokenClaimNames.ACR))) {
            return false;
        }
        final var authTime = jwt.getClaimAsInstant(IdTokenClaimNames.AUTH_TIME);
        if (authTime == null) {
            return false;
        }
        final var age = Duration.between(authTime, clock.instant());
        return !age.isNegative() && age.compareTo(maxAge) <= 0;
    }
}
    /**
     * Answers a token whose sign-in is not recent or strong enough: {@code 401} with the RFC 9470 challenge, which
     * tells the client which {@code acr_values} and {@code max_age} to ask for when it signs the user in again.
     *
     * @param exception the failure.
     * @return the {@code 401} problem detail with the {@code WWW-Authenticate} challenge.
     */
    @ExceptionHandler(InsufficientUserAuthenticationException.class)
    public ResponseEntity<ProblemDetail> handleInsufficientUserAuthentication(

        final var problem = ProblemDetail.forStatusAndDetail(HttpStatus.UNAUTHORIZED, exception.getMessage());

Trusted devices and configuration

After a successful second factor the user may trust the device: a cookie lets later sign-ins skip the second factor until authserver.mfa.trusted-device-validity elapses, the device is revoked or the second factor is disabled. The cookie grants FACTOR_TRUSTED_DEVICE, a factor of strength REMEMBERED: it satisfies the sign-in policy, but it proves nothing about this sign-in, so the tokens report the password only (amr [pwd], acr urn:irurueta:acr:pwd) and a step-up request (acr_values asking for the multi-factor class) still needs a real second factor. When the second-factor page is reached for such a step-up, the trusted-device filter lets the page render the TOTP form instead of resuming the request (which would only redirect back). Recognising a device changes the session id.

The cookie (__Host-TRUSTED-DEVICE, HttpOnly, Secure, SameSite=Lax) holds the random token signed with HMAC-SHA256, as <token>.<signature> (Base64url). TrustedDeviceTokenSigner is a domain port; HmacTrustedDeviceTokenSigner in infrastructure/keys implements it with a key derived from the key-encryption secret for this purpose only (PurposeKeyDerivation, see Keys derived per purpose). FindTrustedDeviceUseCase checks the signature, in constant time, before the account or the device is looked up, so an unsigned or forged value is rejected at no database cost; only the SHA-256 hash of the token is stored. The cookie is only evaluated on the second-factor page (GET /login/second-factor), where every request that owes a second factor is sent: other requests are not looked into, so a user who never gets the factor is not looked up on every request.

/**
 * Port that signs the value of the trusted-device cookie and checks that signature, so a value the server did not
 * issue is rejected before anything is looked up. A signed value has the form {@code token.signature}.
 */
public interface TrustedDeviceTokenSigner {

    /**
     * Signs a token.
     *
     * @param token the raw token of a trusted device.
     * @return the value to put in the cookie: the token, a dot and its signature.
     */
    String sign(String token);

    /**
     * Checks the signature of a cookie value, in constant time.
     *
     * @param signedValue the value presented by the browser, possibly {@code null} or malformed.
     * @return the raw token when the value is well formed and its signature is valid; empty otherwise.
     */
    Optional<String> verify(String signedValue);
}
/**
 * {@link TrustedDeviceTokenSigner} that signs the trusted-device cookie with HMAC-SHA256, under a key derived from the
 * key-encryption secret for this purpose only ({@link PurposeKeyDerivation}). The value is
 * {@code token.signature}, the signature Base64url encoded without padding; it is compared in constant time.
 */
@Component
public class HmacTrustedDeviceTokenSigner implements TrustedDeviceTokenSigner {

    /** Label of the purpose the key is derived for. */
    public static final String PURPOSE = "trusted-device-cookie";

    /** Separator between the token and its signature. */
    private static final char SEPARATOR = '.';

    /** Name of the MAC algorithm. */
    private static final String ALGORITHM = "HmacSHA256";

    /** The signing key. */
    private final SecretKeySpec key;

    /**
     * Derives the signing key.
     *
     * @param derivation derives the key of a purpose from the key-encryption secret.
     */
    public HmacTrustedDeviceTokenSigner(final PurposeKeyDerivation derivation) {
        key = new SecretKeySpec(derivation.keyFor(PURPOSE), ALGORITHM);
    }

    @Override
    public String sign(final String token) {
        return token + SEPARATOR + Base64.getUrlEncoder().withoutPadding().encodeToString(mac(token));
    }

    @Override
    public Optional<String> verify(final String signedValue) {
        if (!StringUtils.hasText(signedValue)) {
            return Optional.empty();
        }
        final var separator = signedValue.lastIndexOf(SEPARATOR);
        if (separator <= 0 || separator == signedValue.length() - 1) {
            return Optional.empty();
        }
        final var token = signedValue.substring(0, separator);
        final byte[] presented;
        try {
            presented = Base64.getUrlDecoder().decode(signedValue.substring(separator + 1));
        } catch (final IllegalArgumentException e) {
            return Optional.empty();
        }
        return MessageDigest.isEqual(mac(token), presented) ? Optional.of(token) : Optional.empty();
    }

    /**
     * Computes the signature of a token.
     *
     * @param token the token.
     * @return the HMAC-SHA256 of its UTF-8 bytes.
     */
    private byte[] mac(final String token) {
        try {
            final var mac = Mac.getInstance(ALGORITHM);
            mac.init(key);
            return mac.doFinal(token.getBytes(StandardCharsets.UTF_8));
        } catch (final GeneralSecurityException e) {
            throw new IllegalStateException(ALGORITHM + " is not available", e);
        }
    }
}
/**
 * Use case that finds the usable (not revoked, not expired) trusted device of a user from the value of the cookie.
 * The signature of the value is checked first, in constant time: a forged or unsigned value is rejected before the
 * account or the device is looked up.
 */
@Service
@Transactional(readOnly = true)
@RequiredArgsConstructor
public class FindTrustedDeviceUseCase {

    /** Port that checks the signature of the cookie value. */
    private final TrustedDeviceTokenSigner trustedDeviceTokenSigner;

    /** Port that provides the user accounts. */
    private final UserAccountRepository userAccountRepository;

    /** Port that stores the trusted devices. */
    private final TrustedDeviceRepository trustedDeviceRepository;

    /** Creator and hasher of the tokens. */
    private final TrustedDeviceTokens trustedDeviceTokens;

    /** Source of the current time. */
    private final Clock clock;

    /**
     * Finds the device.
     *
     * @param username    name the user signed in with.
     * @param cookieValue the signed value presented by the browser.
     * @return the device, or empty if the signature is wrong, the account does not exist, or the token is unknown,
     *         expired, revoked or belongs to another user.
     */
    public Optional<TrustedDevice> execute(final String username, final String cookieValue) {
        return trustedDeviceTokenSigner.verify(cookieValue)
                .flatMap(token -> userAccountRepository.findByUsername(username)
                        .flatMap(account -> trustedDeviceRepository.findUsable(
                                account.id(), trustedDeviceTokens.hash(token), clock.instant())
                                .filter(device -> account.id().equals(device.userId()))));
    }
}
/**
 * Registers the trusted device as an authentication factor of strength {@link FactorStrength#REMEMBERED}: together
 * with the password it satisfies the sign-in policy, so a trusted browser is not asked for the code again, but it is
 * never reported in {@code amr}, {@code acr} or {@code auth_time} and never satisfies a step-up request
 * ({@code acr_values} asking for the multi-factor class, {@code max_age}), which still needs a real second factor.
 */
@Configuration(proxyBeanMethods = false)
public class TrustedDeviceFactor {

    /** Identifier of the factor. */
    public static final String ID = "trusted-device";

    /**
     * Value the factor would have in {@code amr}. RFC 8176 has none for a remembered device, and the factor is never
     * reported, so it is only a label.
     */
    public static final String AMR_VALUE = "trusted-device";

    /** Authority granted by {@link TrustedDeviceFilter} when the browser presents a valid trusted-device cookie. */
    public static final String AUTHORITY = "FACTOR_TRUSTED_DEVICE";

    /**
     * Declares the trusted-device factor.
     *

/**
 * Lets a browser that was trusted earlier skip the second factor of a sign-in. The cookie is only looked at where it
 * matters: on the second-factor page ({@code GET /login/second-factor}), where every request that owes a second
 * factor is sent. Every other request goes through untouched, so a user who never gets the factor is not looked up on
 * each request. When a signed-in user that does not hold the {@link TrustedDeviceFactor} yet reaches that page with
 * the {@code __Host-TRUSTED-DEVICE} cookie, and its signed value belongs to a device of that same user that has
 * neither expired nor been revoked, the authentication of the session is replaced by one that also holds the factor
 * authority (a remembered factor: it satisfies the sign-in policy but is never reported in the tokens), the session
 * id is changed, the session is saved and the request that was interrupted is resumed instead of asking for a code.
 * A forged or unsigned value is rejected by {@link FindTrustedDeviceUseCase} before anything is looked up. While a
 * step-up is pending ({@link SecondFactorRequiredEntryPoint#isStepUpPending}) the cookie is ignored: a trusted
 * device cannot satisfy it, so the page is rendered and asks for a real second factor.
 */
@RequiredArgsConstructor
public class TrustedDeviceFilter extends OncePerRequestFilter {

    /** Matches the request of the second-factor page. */
    private final PathPatternRequestMatcher secondFactorPageMatcher =
            PathPatternRequestMatcher.withDefaults().matcher(HttpMethod.GET, SECOND_FACTOR_PATH);

    /** Use case that finds the trusted device of a signed cookie value. */
    private final FindTrustedDeviceUseCase findTrustedDeviceUseCase;

    /** Adds the factor authority to an authentication. */
    private final FactorGrantor factorGrantor;

    /** Repository the upgraded security context is saved to. */
    private final SecurityContextRepository securityContextRepository;

    /** Handler that resumes the request that was interrupted. */
    private final AuthenticationSuccessHandler resumeHandler;

    /** Authority granted to a trusted device. */
    private final String authority;

    /**
     * Upgrades the authentication and resumes the interrupted request when the second-factor page is requested with
     * the cookie of a valid trusted device.
     *
     * @param request  the request.
     * @param response the response.
     * @param chain    the rest of the chain.
     * @throws ServletException if the chain fails.
     * @throws IOException      if the response cannot be written.
     */
    @Override
    protected void doFilterInternal(final HttpServletRequest request, final HttpServletResponse response,
            final FilterChain chain) throws ServletException, IOException {
        if (!secondFactorPageMatcher.matches(request) || SecondFactorRequiredEntryPoint.isStepUpPending(request)) {
            chain.doFilter(request, response);
            return;
        }
        final var cookie = WebUtils.getCookie(request, TrustedDeviceCookieWriter.COOKIE_NAME);
        final var current = SecurityContextHolder.getContext().getAuthentication();
        if (cookie != null && needsSecondFactor(current) && isTrusted(current, cookie.getValue())) {
            final var upgraded = factorGrantor.grant(current, authority);
            final var context = SecurityContextHolder.getContextHolderStrategy().createEmptyContext();
            context.setAuthentication(upgraded);
            SecurityContextHolder.getContextHolderStrategy().setContext(context);
            // a new level of authentication gets a new session id, against session fixation
            if (request.getSession(false) != null) {
                request.changeSessionId();
            }
            securityContextRepository.saveContext(context, request, response);
            resumeHandler.onAuthenticationSuccess(request, response, upgraded);
            return;
        }
        chain.doFilter(request, response);
    }

    /**
     * Tells whether an authentication is a signed-in user that does not hold the trusted-device authority yet.
     *
     * @param authentication the authentication of the request, possibly {@code null}.
     * @return {@code true} when a user is signed in and the trusted-device authority is missing.
     */
    private boolean needsSecondFactor(final Authentication authentication) {
        return authentication != null && authentication.isAuthenticated()
                && !(authentication instanceof AnonymousAuthenticationToken)
                && authentication.getAuthorities().stream()
                .noneMatch(granted -> authority.equals(granted.getAuthority()));
    }

    /**
     * Tells whether a signed cookie value identifies a valid trusted device of the signed-in user.
     *
     * @param authentication the signed-in user.
     * @param cookieValue    the signed value of the cookie.
     * @return {@code true} when the signature is valid and the device exists and belongs to the user; the use case
     *         only finds devices that have been neither revoked nor expired.
     */
    private boolean isTrusted(final Authentication authentication, final String cookieValue) {
        return findTrustedDeviceUseCase.execute(authentication.getName(), cookieValue).isPresent();
    }
}

Keys derived per purpose

The TOTP secrets are encrypted at rest (AesGcmTotpSecretCipher, AES-256-GCM) and the trusted-device cookie is signed, both from the key-encryption secret (authserver.keys.encryption.password and .salt), but neither shares the key that protects the signing keys. PurposeKeyDerivation derives a salt per purpose (HMAC-SHA256 of the purpose label, totp-secret or trusted-device-cookie, keyed with the configured salt) and, for the cookie, a 256-bit key from the passphrase and that salt (PBKDF2-HMAC-SHA256). The signing-key cipher (AesGcmKeyCipher) keeps the configured salt, so the keys already stored still decrypt.

/**
 * Derives, from the key-encryption secret ({@link KeyEncryptionProperties}), a distinct salt and key for each purpose
 * other than the encryption of signing keys, so no two uses share a key: a key exposed or misused for one purpose
 * says nothing about the others. The salt of a purpose is the HMAC-SHA256 of the purpose label keyed with the
 * configured salt; its key is derived from the passphrase and that salt with PBKDF2-HMAC-SHA256. The signing-key
 * cipher ({@link AesGcmKeyCipher}) keeps using the configured salt itself, so the keys already stored still decrypt.
 */
@Component
@RequiredArgsConstructor
public class PurposeKeyDerivation {

    /** Algorithm that derives the salt of a purpose. */
    private static final String SALT_ALGORITHM = "HmacSHA256";

    /** Algorithm that derives the key of a purpose. */
    private static final String KEY_ALGORITHM = "PBKDF2WithHmacSHA256";

    /** PBKDF2 iterations; a key is derived once per purpose, when its bean is created. */
    private static final int ITERATIONS = 100_000;

    /** Size of a derived key in bits (AES-256 / HMAC-SHA256). */
    private static final int KEY_BITS = 256;

    /** The passphrase and the salt of the key-encryption secret. */
    private final KeyEncryptionProperties properties;

    /**
     * Derives the salt of a purpose.
     *
     * @param purpose label of the purpose, for example {@code totp-secret}.
     * @return the salt, hex encoded, as {@code Encryptors.stronger} expects it.
     */
    public String saltFor(final String purpose) {
        try {
            final var mac = Mac.getInstance(SALT_ALGORITHM);
            mac.init(new SecretKeySpec(properties.salt().getBytes(StandardCharsets.UTF_8), SALT_ALGORITHM));
            return HexFormat.of().formatHex(mac.doFinal(purpose.getBytes(StandardCharsets.UTF_8)));
        } catch (final GeneralSecurityException e) {
            throw new IllegalStateException("The salt of " + purpose + " cannot be derived", e);
        }
    }

    /**
     * Derives the key of a purpose.
     *
     * @param purpose label of the purpose, for example {@code trusted-device-cookie}.
     * @return the 256-bit key.
     */
    public byte[] keyFor(final String purpose) {
        final var spec = new PBEKeySpec(properties.password().toCharArray(),
                HexFormat.of().parseHex(saltFor(purpose)), ITERATIONS, KEY_BITS);
        try {
            return SecretKeyFactory.getInstance(KEY_ALGORITHM).generateSecret(spec).getEncoded();
        } catch (final GeneralSecurityException e) {
            throw new IllegalStateException("The key of " + purpose + " cannot be derived", e);
        } finally {
            spec.clearPassword();
        }
    }
}

Step-up

A client asks for a recent multi-factor sign-in with the acr_values and max_age authorization request parameters. The tokens then carry amr, acr (urn:irurueta:acr:mfa) and auth_time (MfaClaimsContributor), and the resource server enforces the policy; see Resource server. Both the claims and the step-up checks read the factors through FactorTimeline: a remembered device never counts, and auth_time (and so max_age) is the time of the primary factor, not of a later second factor, so adding a code never makes an old sign-in look recent.

Whether a sign-in is multi-factor is decided in one place, MfaPolicy.isMultiFactor, which FactorTimeline applies to the counted factors: two distinct factors, or one factor that proves a multi-factor authentication by itself (the multiFactor flag of AuthenticationFactor). So the amr mfa value, the acr, the step-up of the authorization endpoint and StepUpGuard (which reads the acr of the token) always agree.

The same rule guards the session’s sensitive changes: the phone page (PhoneSessionStepUp) accepts a recent multi-factor session, so a trusted provider’s multi-factor sign-in may change the phone without a local second factor, as its bearer tokens may on the account API.

A passkey or a certificate proves one thing, however strongly: user verification of a passkey is only preferred, so possession is all it proves for certain, and a certificate is possession of a key. They let the user in without a second factor but do not claim a multi-factor sign-in.

/**
 * Reads, from the {@link FactorGrantedAuthority} instances of an authentication, the factors that prove something
 * about it and when they were presented. It is the single place the claims ({@link MfaClaimsContributor}) and the
 * step-up checks ({@link StepUpAuthorizationRequestConverter}) take {@code amr}, {@code acr} and {@code auth_time}
 * from, so both always agree:
 *
 * <ul>
 *   <li>only the factors of the {@link AuthenticationFactorRegistry} that {@link MfaPolicy#isReported} accepts count:
 *       a remembered (trusted) device does not;</li>
 *   <li>the authentication is multi-factor when {@link MfaPolicy#isMultiFactor} says so: at least two distinct
 *       factors count, or one counted factor proves a multi-factor authentication alone;</li>
 *   <li>{@code auth_time} is when the primary factor was presented (the earliest one when there are several), so a
 *       second factor added later never makes the sign-in look newer; without a primary factor it is the earliest
 *       counted factor.</li>
 * </ul>
 */
@Component
@RequiredArgsConstructor
public class FactorTimeline {

    /** Registry of the known factors. */
    private final AuthenticationFactorRegistry factorRegistry;

    /** Policy that tells which factors are reported and which are primary. */
    private final MfaPolicy mfaPolicy;

    /**
     * Lists the factor authorities of an authentication that count, oldest first.
     *
     * @param authentication the authentication.
     * @return the counted factor authorities, sorted by issue instant; empty when none.
     */
    public List<FactorGrantedAuthority> countedFactors(final Authentication authentication) {
        return factorsMatching(authentication, mfaPolicy::isReported);
    }

    /**
     * Lists the {@code amr} values of the counted factors, in the order they were presented, without duplicates.
     *
     * @param authentication the authentication.
     * @return the values; empty when no factor counts.
     */
    public List<String> amrValues(final Authentication authentication) {
        return countedFactors(authentication).stream()
                .map(authority -> factorRegistry.findByAuthority(authority.getAuthority()))
                .flatMap(Optional::stream)
                .map(AuthenticationFactor::amrValue)
                .distinct()
                .toList();
    }

    /**
     * Tells whether an authentication is multi-factor, by {@link MfaPolicy#isMultiFactor} over its counted factors.
     *
     * @param authentication the authentication.
     * @return {@code true} for a multi-factor authentication.
     */
    public boolean isMultiFactor(final Authentication authentication) {
        return mfaPolicy.isMultiFactor(countedFactors(authentication).stream()
                .map(authority -> factorRegistry.findByAuthority(authority.getAuthority()))
                .flatMap(Optional::stream)
                .collect(Collectors.toSet()));
    }

    /**
     * Finds the instant of the authentication, the one {@code auth_time} reports and {@code max_age} is measured
     * from.
     *
     * @param authentication the authentication.
     * @return the issue instant of the earliest primary factor, or else of the earliest counted factor; empty when no
     *         counted factor carries an instant.
     */
    public Optional<Instant> authTime(final Authentication authentication) {
        return earliest(factorsMatching(authentication,
                factor -> mfaPolicy.isReported(factor) && mfaPolicy.isPrimary(factor)))
                .or(() -> earliest(countedFactors(authentication)));
    }

    /**
     * Lists the factor authorities of an authentication whose registered factor passes a test, oldest first.
     *
     * @param authentication the authentication.
     * @param test           the test of the registered factor.
     * @return the matching authorities.
     */
    private List<FactorGrantedAuthority> factorsMatching(final Authentication authentication,
            final Predicate<AuthenticationFactor> test) {
        return authentication.getAuthorities().stream()
                .filter(FactorGrantedAuthority.class::isInstance)
                .map(FactorGrantedAuthority.class::cast)
                .filter(authority -> factorRegistry.findByAuthority(authority.getAuthority()).filter(test).isPresent())
                .sorted(Comparator.comparing(FactorGrantedAuthority::getIssuedAt,
                        Comparator.nullsLast(Comparator.naturalOrder())))
                .toList();
    }

    /**
     * Finds the earliest issue instant of some factor authorities.
     *
     * @param factors the authorities.
     * @return the earliest instant, or empty when none carries one.
     */
    private static Optional<Instant> earliest(final List<FactorGrantedAuthority> factors) {
        return factors.stream().map(FactorGrantedAuthority::getIssuedAt).filter(Objects::nonNull)
                .min(Comparator.naturalOrder());
    }
}
    /**
     * Checks the step-up parameters of a request.
     *
     * @param request the request.
     * @return always {@code null}: this converter only vetoes requests.
     * @throws ReauthenticationRequiredException if {@code max_age} is exceeded.
     * @throws SecondFactorRequiredException     if the requested {@code acr_values} are not reached.
     */
    @Override
    public Authentication convert(final HttpServletRequest request) {
        final var user = SecurityContextHolder.getContext().getAuthentication();
        if (!MfaAuthorizationManager.isUser(user)) {
            return null;
        }
        final var authTime = factorTimeline.authTime(user);
        if (authTime.isEmpty()) {
            return null;
        }
        if (maxAgeExceeded(request.getParameter(MAX_AGE_PARAMETER), authTime.get())) {
            throw new ReauthenticationRequiredException();
        }
        if (!acrReached(request.getParameter(ACR_VALUES_PARAMETER), factorTimeline.isMultiFactor(user))) {
            throw SecondFactorRequiredException.forStepUp();
        }
        return null;
    }
/**
 * Adds to the access and ID tokens how the user authenticated: {@code amr} (the RFC 8176 values of the factors really
 * presented, plus {@code mfa} when there are at least two), {@code acr} (the class of the authentication, see
 * {@link AuthenticationContextClass}) and {@code auth_time} (the epoch second the primary factor was presented, a
 * number per OIDC; access tokens only, because the framework sets it on ID tokens). Every value comes from the
 * {@link FactorTimeline}, which reads the {@link org.springframework.security.core.authority.FactorGrantedAuthority}
 * instances of the principal: authorities of an unknown factor and of a remembered (trusted) device are ignored, so a
 * browser that skipped the second factor gets {@code amr [pwd]} and the password class. A token with no counted factor
 * (for example of the client credentials grant) gets none of the claims.
 */
@Component
@Order(MfaClaimsContributor.ORDER)
@RequiredArgsConstructor
public class MfaClaimsContributor implements JwtClaimsContributor {

    /** Order of the contributor: after the built-in claims and the default contributors. */
    public static final int ORDER = 100;

    /** RFC 8176 {@code amr} value that tells that more than one factor was used. */
    public static final String MULTI_FACTOR_AMR_VALUE = "mfa";

    /** Reads the counted factors of the principal and their instants. */
    private final FactorTimeline factorTimeline;

    @Override
    public void contribute(final OAuth2TokenContext context, final Map<String, Object> claims) {
        final var principal = context.getPrincipal();
        if (principal == null) {
            return;
        }
        final var authTime = factorTimeline.authTime(principal);
        if (authTime.isEmpty()) {
            return;
        }
        // a mutable list on purpose: the authorization store only deserializes allow-listed types
        final var amr = new ArrayList<String>(factorTimeline.amrValues(principal));
        final var multiFactor = factorTimeline.isMultiFactor(principal);
        if (multiFactor) {
            amr.add(MULTI_FACTOR_AMR_VALUE);
        }
        claims.put(IdTokenClaimNames.AMR, amr);
        claims.put(IdTokenClaimNames.ACR,
                multiFactor ? AuthenticationContextClass.MULTI_FACTOR : AuthenticationContextClass.PASSWORD);
        // the framework sets auth_time itself on ID tokens (as a date it expects to read back on refresh)
        if (OAuth2TokenType.ACCESS_TOKEN.equals(context.getTokenType())) {
            claims.put(IdTokenClaimNames.AUTH_TIME, authTime.get().getEpochSecond());
        }
    }
}
