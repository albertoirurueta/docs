Building, testing and contributing

This documentation was generated with the assistance of AI. Please report any inaccuracies.

Project layout

Path Contents

lib/

The library (com.irurueta.android.gesturebitmap), published as com.irurueta:irurueta-android-gesture-bitmap-view.

lib/src/main/res/values/attrs.xml

XML attributes of GestureBitmapView.

lib/src/test/

Local unit tests (JUnit, run with Robolectric).

lib/src/androidTest/

Instrumented tests, run on a device or emulator against a test activity (GestureBitmapViewActivity) that hosts the view.

app/

The sample app.

docs/

This Antora documentation site.

Requirements

  • JDK 21 to run the build (required by the SonarCloud scanner). The library is still compiled for JVM target 17.

  • Android SDK with platform 36.

  • For instrumented tests: a connected device or emulator.

  • For the documentation: Node.js 20 or later.

Building

./gradlew :lib:assemble

Running the tests

# All local unit tests
./gradlew test

# Only the library's unit tests
./gradlew lib:test

# Instrumented tests (needs a device or emulator)
./gradlew connectedAndroidTest
./gradlew lib:connectedAndroidTest

Unit tests live in GestureBitmapViewTest, RotationGestureDetectorTest, MetricTransformationParametersTest and InvalidMatrixExceptionTest under lib/src/test/java/com/irurueta/android/gesturebitmap/. The instrumented GestureBitmapViewTest under lib/src/androidTest/ drives the view with real touch events.

Coverage

The debug build type enables unit and instrumented test coverage. To convert the unit test execution data into HTML and XML reports with the JaCoCo CLI bundled in the repository:

java -jar jacoco-0.8.13/lib/jacococli.jar report lib/build/jacoco/testReleaseUnitTest.exec \
  --classfiles lib/build/tmp/kotlin-classes/debug \
  --sourcefiles lib/src/main/java \
  --html lib/build/reports/coverage/test \
  --xml lib/build/reports/coverage/test/report.xml

API documentation

The KDoc API reference is generated with Dokka:

./gradlew lib:dokkaGenerate

The output is written to lib/build/dokka/html.

Static analysis

The library is analysed on SonarCloud:

./gradlew :lib:sonar

./gradlew lint runs Android lint.

Continuous integration

The CI GitHub Actions workflow (.github/workflows/main.yml) runs on pushes and pull requests to main. It runs ./gradlew clean test connectedAndroidTest lint lib:dokkaGenerate on an API 35 emulator, publishes the test results, converts the coverage report, sends the analysis to SonarCloud and deploys the Dokka output to GitHub Pages. The publish.yml workflow publishes the library to Maven Central when a GitHub release is published.

Building this documentation

From docs/ (Node.js 20 or later):

npm ci
npx antora antora-playbook.yml
npx pagefind --site build/site

The site is written to docs/build/site. Search only works over HTTP, for instance with python3 -m http.server 8090 --directory docs/build/site and http://localhost:8090.

Contributing

  1. Fork the repository and create a branch from main.

  2. Keep public API changes documented with KDoc, and update these pages when behavior or configuration changes.

  3. Add or update unit tests (and instrumented tests for gesture behavior), and make sure ./gradlew test passes.

  4. Open a pull request against main; the CI workflow must pass.
