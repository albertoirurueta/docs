### Mandatory conventions for every page task (from the issue and `CLAUDE.md`)

- Header: `= Title`, `:description:`, `:keywords:`, then `include::partial$r-disclaimer.adoc[]`; intro states the baseline (R 4.6 / 4.6.1, plus the
  versions of any packages outside base R used on the page, and the check date).
- Each page: detailed explanation (what/why with design rationale from the manuals, FAQ, NEWS or R Blog; how R implements it, linked to the manual
  section or help page; every relevant function, argument, operator, `options()` entry, environment variable, DESCRIPTION field or NAMESPACE directive;
  common errors and warnings with their real text; pitfalls with the R FAQ chapter 7 entry; version of introduction/change/deprecation), "where older
  tutorials are outdated" in prose for the concepts touched, and ends with `== References` listing only the online official documentation used.
  ★ pages are the most detailed in the section.
- Examples: `[source,r]` (kept per the user's choice), complete and runnable with `Rscript` on R 4.6 without errors or unexpected warnings (or clearly
  marked fragments), using `|>`, `\(x)`, `vapply`, `seq_along`, `TRUE`/`FALSE`; no `attach()`, no `T`/`F`; passing `lintr::lint()` with default linters.
  Console sessions show printed output as `#>` comments (reprex convention). Other tags: `text` for DESCRIPTION, NAMESPACE, Rd and `renv.lock`;
  `yaml` for `_quarto.yml` and GitHub Actions; `bash` for `R`/`Rscript`/`R CMD`; `c`, `cpp`, `fortran` for compiled code. **Each example is followed
  by `Source: <official URL>[label]`**; base-package help pages use `https://search.r-project.org/R/refmans/<pkg>/html/<Rd-name>.html` with the Rd file
  name (looked up, never guessed); manuals use `r-release/<NAME>.html#<node id>`; package docs link their pkgdown `/reference/<fn>.html` page, labelled
  as package documentation.
- Shelf scenario only; no real credentials, hosts or data (use `Sys.getenv()`/`.Renviron`). Experimental features avoided or labelled in prose.
- No `NOTE`/`TIP`/`WARNING`/`CAUTION`/`IMPORTANT` blocks except the disclaimer include.
- AsciiDoc pitfalls (`CLAUDE.md`): inline code containing `<-`, `->`, `<<-`, `->>`, `<=`, `=>`, `|>`, `...`, `~`, `^`, `*`, `__`, `{`, `#[` or an
  apostrophe next to a letter is written `` `+…+` ``; code containing `+` (or `x[1]`, which needs `\]`) uses `` `pass:c[…]` ``; backtick-quoted R names
  go in a `pass:c[…]` or a literal `[source,r]` block. Block `image::` macros on one line at column 0 with quoted alt text when it has a comma; every
  SVG referenced; Mermaid stereotypes as `&lt;&lt;…&gt;&gt;`.
- Per-page verification (run after writing): the three `image::` greps and the alt-comma grep from `CLAUDE.md` on the new files; confirm no admonition
  other than the disclaimer; run every example through the Task 1 helper and lint it.
