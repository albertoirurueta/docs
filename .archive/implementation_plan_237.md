### Choices made on the user's behalf

1. **One pass, one PR.** The issue suggests optionally splitting into 4 PRs; as with #199 and #230, this run
   implements everything on `feature/237` and opens a single draft PR to `main` with `Closes #237`.
2. **Tasks are untagged; no language/framework key applies.** Installed keys are `java`, `java-springboot`,
   `dotnet` and `database`; none fit AsciiDoc / Mermaid / SVG / PDF authoring, so tasks are implemented directly.
   Python and template code in pages is illustrative content, but every example is built and run in a scratch Django
   project (Task 2.6).
3. **The books appear only in `== Bibliography`** and in prose notes on outdated material. No text, listing, figure or
   sample project is copied, quoted or committed; the PDFs are never staged.
4. **Disclaimer:** `partials/django-disclaimer.adoc` is a single `[IMPORTANT]` block (AI-assistance disclosure +
   `xref:web/django/index.adoc#_bibliography[…]`). No other admonition in the section; deprecations, version changes,
   security caveats and "book is outdated" remarks are prose or table rows.
5. **Version baseline re-verified at implementation time and dated** (Group 1). The issue's numbers were checked
   2026-10-02; Django 6.1.2 is due 2026-10-06 and Channels had not declared 6.1 support, so they are re-verified, not
   copied. Django links pin `/en/6.1/`.
6. **Running scenario is the original *Bookshelf*** (catalogue of books/authors/reviews with server-rendered pages,
   custom user, admin curation, uploads, i18n, SSE/Channels feed, `django.tasks`/Celery emails, Redis cache, DRF/Ninja
   API, sitemap/feed, Docker deployment); pages build on each other.
7. **Existing pages get real `xref:`s; not-yet-existing ones stay plain prose.** Every `xref:` target outside the
   section is verified with `ls` before it is written. Links between pages of the new section are allowed because the
   whole section lands in the same PR; `index.adoc` and `cheat-sheet.adoc` are written last (Group 11).
8. **Placement:** Django sits under Web Development right after the Python include (language partial, then its
   framework); Backend Development only gets a cross-link, as the issue specifies.
9. **Figure floor:** every 📊 in the issue is delivered as Mermaid or `django-*.svg`; SVGs are original drawings (no
   Django logo — a DSF trademark — docs images or book figures).

### Lessons from the earlier section reviews (#198, #199, #230) — mandatory for every page task

**Verify every name against its official page before writing it** (every class, setting, option, command, import
path, package name and version number); if the docs don't confirm a detail, describe the behaviour without naming it.
**Security is correctness:** no hardcoded secrets (`SECRET_KEY` from the environment, `get_random_secret_key()`),
POST for state changes, CSRF shown, explicit `fields` in model forms. **Every concept gets at least one code
example**, each followed by a `Source:` link, and the URL goes in `== References`. **Run the examples** in the
Group 1 scratch project. **URL hygiene:** canonical, version-pinned URLs. **Cross-links accurate:** never `xref:` to a
non-existent page; no `xref:` inside backticks; no empty link text on a fragment xref. **AsciiDoc hygiene:** `.Title`
captions; no leaked authoring notes; `{placeholders}` and `{% … %}` literal inside `[source]` blocks and escaped in
prose; no prose line starting with `<digits>.`. **Never reproduce the books' errors** (the issue's errata list).

## Conventions every page task must follow

* **Header:** `= Title`, `:description:` (one sentence), `:keywords:`, blank line,
  `include::partial$django-disclaimer.adoc[]`.
* **Lead paragraph** states the versions written against (Django 6.1, Python 3.12–3.14, PostgreSQL 15+; 5.2 LTS
  differences noted where they matter), dated.
* **Content:** what/why, how Django implements it, every relevant option/setting/class/API, position in the
  request/response cycle, sync vs async behaviour, pitfalls, recent changes with versions, where the books are
  outdated. `[source,python]`, `[source,html+django]`, `[source,bash]` (with output where useful), `curl` +
  `[source,json]` for APIs; current APIs only.
* **Page ending:** `== References` listing only official docs (and the books' publisher pages where used).
