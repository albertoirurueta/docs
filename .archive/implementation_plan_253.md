`modules/ROOT/pages/web/nextjs/`, directly after the React Reference: a practical, example-driven guide to Next.js 16.3
(React 19.3, Node.js ≥ 20.9), written from the **official documentation** (https://nextjs.org/docs and

`~/Desktop/nextjs2.pdf` *Practical Next.js for E-Commerce*, Apress 2023) as consulted references for concept coverage,
narrative and the bibliography only.

  hydration/PPR/caching/static-export subsections, deployment paragraph, React 19.2/19.3 refresh)

### Choices made on the user's behalf

1. **One pass, one PR.** The issue suggests optionally splitting into 4 PRs; as with #237/#230/#199, this run
   implements everything on `feature/253` and opens a single draft PR to `main` with `Closes #253`.
2. **Tasks are untagged; no language/framework key applies.** Installed keys are `java`, `java-springboot`, `dotnet`
   and `database`; none fit AsciiDoc / Mermaid / SVG / PDF authoring, so tasks are implemented directly. TypeScript/TSX
   in pages is illustrative content, but every example is built and run in a scratch Next.js app (Task 2.6).
3. **The books appear only in `== Bibliography`** and in prose notes on outdated material. No text, listing, figure or
   sample project is copied; the PDFs are never staged.
4. **Disclaimer:** `partials/nextjs-disclaimer.adoc` is a single `[IMPORTANT]` block (AI-assistance disclosure +
   `xref:web/nextjs/index.adoc#_bibliography[…]`). No other admonition in the section; deprecations, version changes,
   security caveats and "book is outdated" remarks are prose or table rows.
5. **Version baseline re-verified at implementation time and dated** (Group 1). The issue's numbers were checked
   2026-10-03; Next.js ships patch releases often, so they are re-verified, not copied.
6. **Both caching models are taught and labelled** ("Cache Components" vs "previous model"), because
   `cacheComponents` and `partialPrefetching` are still opt-in; a page states which one each example uses.
7. **Running scenario is the original *Bookshelf*** Next.js front end, extending the files sketched in
   `backend/nestjs/nestjs-vs-nextjs.adoc`; pages build on each other.
8. **Existing pages get real `xref:`s; not-yet-existing ones stay plain prose.** Every `xref:` target outside the
   section is verified with `ls` before it is written. `index.adoc` and `cheat-sheet.adoc` are written last
   (Group 10); React updates and back-links come after the new pages exist (Group 11).
9. **Figure floor:** every 📊 in the issue is delivered as Mermaid or `nextjs-*.svg`; SVGs are original drawings (no
   Next.js/Vercel logos, docs images or book figures).

### Lessons from the earlier section reviews (#198, #199, #230, #237) — mandatory for every page task

**Verify every name against its official page before writing it** (every API, file convention, config key, import
path, package name and version number); if the docs don't confirm a detail, describe the behaviour without naming it.
**Security is correctness:** no hardcoded secrets, only `NEXT_PUBLIC_` for genuinely public values, POST/Server Actions
for state changes with authorisation, prices and permissions checked on the server. **Every concept gets at least one
code example**, each followed by a `Source:` link, and the URL goes in `== References`. **Run the examples** in the
Group 1 scratch app. **URL hygiene:** canonical nextjs.org / react.dev URLs. **Cross-links accurate:** never `xref:`
to a non-existent page; no `xref:` inside backticks; no empty link text on a fragment xref. **AsciiDoc hygiene:**
`.Title` captions; no leaked authoring notes; `{placeholders}` and JSX braces literal inside `[source]` blocks and
escaped in prose; no prose line starting with `<digits>.`. **Never reproduce the books' errors** (the issue's errata
list).

## Conventions every page task must follow

* **Header:** `= Title`, `:description:` (one sentence), `:keywords:`, blank line,
  `include::partial$nextjs-disclaimer.adoc[]`.
* **Lead paragraph** states the versions written against (Next.js 16.3, React 19.3, Node.js ≥ 20.9; docs `@doc-version`),
  dated, and whether the page covers the App Router, the Pages Router or both.
* **Content:** what/why, how Next.js implements it and on which React primitive, every relevant option/file
  convention/function/config key, where it runs (build, request, Proxy, client) and its effect on HTML/RSC
  payload/bundle, pitfalls and `nextjs.org/docs/messages/*` errors, recent changes with versions, where the books are
  outdated. `[source,tsx]`/`[source,ts]`, `[source,bash]` (with output such as the `next build` route table where
  useful), `curl` + `[source,json]` for Route Handlers; current APIs only (async `params`/`cookies()`, `proxy.ts`,
  `revalidateTag(tag, profile)`, `next/navigation`).
* **Page ending:** `== References` listing only official docs (and the books' publisher pages where used).
