# Implementation Plan: Step-by-step Grafana and Kibana guides with SVG figures (#389)

## Task summary

Source: GitHub issue #389
Base branch: main
Branch: feature/389-tutorials-examples-grafana-kibana

Issue [#389](https://github.com/albertoirurueta/docs/issues/389) asks for step-by-step guides in the **Grafana** and **Kibana** subsections of
`modules/ROOT/pages/backend/monitoring-alerting/`, so that a reader can complete the tasks the reference pages only describe (create a
panel, pick chart types, write queries, explore logs, create alerts) with numbered steps and a figure for each screen-changing step. The
issue body is the specification (guide catalogue, page template, figure rules, lab additions, acceptance criteria); read it with
`gh issue view 389 --json body`. Version baselines are unchanged: Grafana 13.3.x and Kibana 9.5.x (Stack, classic alerting).

Deliverables:

1. **38 guide pages**: 19 `grafana/guide-*.adoc` and 19 `kibana/guide-*.adoc`, in a new nav group **Step-by-step guides** per subsection.
2. **SVG figures** (no raster images) that resemble the real UI with the products' real colours and logos, generated from per-guide specs by a
   new generator `scripts/monitoring-guides/` (`npm run guides:figures`, `npm run test:guides`), plus 8 screen maps.
3. **Product theme modules** (colours and typography read from the running lab) and logo entries with sources in `LOGO-SOURCES.md`.
4. **Lab additions**: a provisioned TestData data source and `bookshelf-books.csv`.
5. **Cross-links**: a pointer from each reference page to its guide, a Grafana/Kibana task table, index, glossary, lab page, `CLAUDE.md`.

**Choices made on the user's behalf** (challenge them at review)

* Scope: everything in the issue in one plan and one PR, as #385 did for its 83 pages; the user chose this when asked.
* Docker: the user approved running the lab for real (UI facts, theme colours, replay of five guides per product). All Docker work runs in the
  main session or its sub-agents with that approval; no further prompts are expected, and every container is stopped at the end of each run.
* Figures are SVG only, drawn from what the running lab shows; real colours and logos are allowed (user decision), so the theme modules are an
  explicit exception to the single-palette rule of `scripts/cards/palette.mjs`.
* Execution follows #385: pages are written by background agents, a few per agent, all sharing one brief (`guides-brief/rules.md` in the
  session scratchpad, plus the two facts briefs); facts verified during the work go into the brief.
* Facts first: the labels and layouts in the guides come from the lab (Group 1), not from the books or the "latest" docs, because the docs
  disagree with each other in places (for example the Grafana panel editor and several Kibana 9.x labels).
* Guide ids follow the issue (G1 to G19, K1 to K19); the pilots are G5 and K5, written before the others to validate the template.
* Pages are documentation and Node scripts only, so tasks carry no language key.
* Observability-app guides (K14, K17) are written after Group 1 shows what the lab feeds; where it does not feed a view, the guide says so
  rather than inventing screens.

Open clarifications: none

## Current code state

* Repository is the Antora playbook and root component `ROOT` (`antora.yml`); no application code. Content in `modules/ROOT/pages/`,
  images in `modules/ROOT/images/` (all SVG), helper scripts in `scripts/` (Node `.mjs`, `node --test`). Project type `other`; no lint suite.
* `modules/ROOT/pages/backend/monitoring-alerting/grafana/` (33 pages) and `kibana/` (34 pages) exist from #385; both have `bookshelf-end-to-end.adoc`
  that build from provisioning files. `index.adoc` of each subsection is a template index (`== Version baseline`, `== Reading path`, ...), audited by
  `npm run audit:index-template`. The section has 13 conceptual SVGs and no UI figure.
* `modules/ROOT/nav.adoc`: Grafana block from line 1953, Kibana block from line 1992; each starts with a **Getting started** `*****` group. Nav titles equal
  the index text list and never link to a `#fragment`.
* Lab: `modules/ROOT/examples/monitoring-alerting-lab/` (`compose.yaml` with profiles `grafana` and `kibana`; Grafana 13.3.0, Kibana and Elasticsearch 9.5.6;
  `loadgen` on 8090 with modes `normal`, `failing`, `slow`, `log-errors`, `stop`; `webhook-receiver` on 8081; Grafana data sources provisioned in
  `grafana/provisioning/datasources/datasources.yaml`: Prometheus, Loki, Tempo, PostgreSQL). Documented in `hands-on-lab.adoc`.
* Generator model: `scripts/cards/` (`palette.mjs`, `extract-logos.mjs`, `logos.json`, `generate-cards.mjs`, `generate-cards.test.mjs`, `LOGO-SOURCES.md`).
* Page conventions (copy a sibling such as `grafana/variables.adoc`): `= Title`, `:description:`, `:keywords:`, `include::partial$ai-disclaimer.adoc[]`,
  `Checked on <date> against <product> <version>.`, `Source:` lines with links, `== Where to go next`. **The AI-assistance notice is the only admonition
  allowed in the section.** No tutorial pages carry a nested `index.adoc`, so the card manifest is unaffected.
* Precedent: `.archive/implementation_plan_385.md` (this section's creation, 11 groups, background agents with a shared brief, Docker lab group) and
  `.archive/implementation_plan_136.md`.

**Guide template** (every guide, in this order, as `==` headings): What you build; Before you start; Steps (with `===` phases); Check the result;
Variations (optional); What can go wrong; Clean up (when it creates resources); Where to go next; Sources.

**Rules for every guide task (R1 to R10)**

* R1. Labels, menu paths, defaults and layouts come from `guides-brief/*-facts.md`; never from memory, the books or older docs. A difference from earlier
  releases is a short sentence in the step, never an admonition.
* R2. One action per numbered step, labels in bold exactly as the product shows them, menu paths with `→`, every typed value (query, name, threshold) in full,
  queries in listing blocks. Inline code with `->`, `=>`, `*`, `~`, `|`, `'`, `{` uses the `+...+` passthrough per `CLAUDE.md`; code with `+` uses `pass:c[...]`.
* R3. The reader builds in new resources prefixed `guide-` (folder `Guides`, dashboard `Bookshelf (guides)`); guides never edit the provisioned dashboard or rules.
* R4. Each `===` phase of Steps has at least one figure; 6 to 15 figures per guide; figure file `monitoring-alerting-<product>-guide-<guide>-<nn>-<what>.svg`
  from the guide's spec; block macro on one line, alt text in double quotes, meaningful (screen and highlighted control).
* R5. Under **Before you start**, state the lab profile to start, earlier guides required, version, licence or role needs, and that the figures are drawings of the
  Grafana 13.3 / Kibana 9.5 UI, not screenshots.
* R6. **Check the result** says what to see and how to provoke it (load generator `curl`, webhook receiver GET).
* R7. **Sources** lists the official pages the steps were checked against; no text or image is taken from the books.
* R8. Link the reference pages listed in the task and the previous and next guide; use `xref:` with the path from `backend/monitoring-alerting/`; no `#fragment` in nav.
* R9. Only `modules/ROOT/pages/backend/monitoring-alerting/<product>/guide-<name>.adoc`, `scripts/monitoring-guides/figures/<product>-<id>.mjs` and the generated
  SVGs may be touched by a guide task; nav, indexes and reference pointers belong to Group 8.
* R10. Self-check before finishing a guide: no `NOTE:`/`TIP:`/`WARNING:`/`CAUTION:`/`IMPORTANT:` admonition, no stray backticks or bare `+`, no `[[x]]`,
  every `image::` target exists, no hard-coded colour in the spec.
