# Implementation plan: UI / UX section with a Figma sub-section (issue #250)

## Task summary

Add a top-level **UI / UX** section as the last entry under Guides & References (`modules/ROOT/pages/ui-ux/`) with a
**Figma** sub-section (`modules/ROOT/pages/ui-ux/figma/`): 64 heavily illustrated concept pages in 11 outline groups
(including the Figma landing page), a UI / UX landing page, a bibliography on the Figma landing page, a cheat-sheet page
and a one-page A4 cheat-sheet PDF. All examples follow the *Bookshelf* scenario. The per-page outline, version baseline,
books table, outdated-statement list, figure rules and conventions are in the body of issue #250 and are authoritative;
every page task below refers to them instead of repeating them.

Choices made: all tasks are documentation-only and untagged (implemented directly). Pages are grouped by outline area;
because every page is a new file, the page groups are parallelizable. The Figma landing page, cheat sheet, nav, home
tile and back-links come after all pages exist, followed by a single build-and-checks group. The issue suggests five
PRs; this plan is one plan for the whole issue, and the groups can be split across PRs along its suggested boundaries
(groups 1-3 and part of 4, then components/prototyping/UX, then collaboration/handoff/AI, then extending/admin and
wiring) if the user prefers. Facts must be re-verified against the official documentation at implementation time
(baseline date 2026-10-30). The 3rd-edition Staiano PDF was lost, so its rows rely on Packt's published contents. The
requester's books in `~/Desktop/libros/figma` are never committed or copied from, and the corrupted text file left there
is ignored.

## Per-page contract (applies to every page task)

Start with `= Title`, `:description:`, `:keywords:`, `include::partial$ui-ux-figma-disclaimer.adoc[]`; intro with the
check date (2026-10-30), UI3, product(s), plan and seat requirement and GA/beta status (tier names only, no prices); a
detailed concept explanation with where it lives in UI3, every relevant option, shortcuts (macOS and Windows), pitfalls,
change dates; numbered procedures on the *Bookshelf* scenario each followed by a `Source:` link to the official page;
code examples (`[source,typescript]`, `json`, `bash`, `css`) only where the concept is code, no real tokens (`FIGMA_TOKEN`
from the environment); outdated book statements as prose with dates; the "Content seat" is not documented; unofficial
techniques are labelled as such; the disclaimer is the only admonition; figures are original SVGs named
`ui-ux-figma-<topic>-*.svg` (≥2 per page, ≥4 per ★ page, one storyboard when a procedure is taught) with quoted alt text
when it contains a comma and a `.Title` caption, on one line at column 0; inline code containing `->`, `=>`, `*`, `{`,
`__`, `'`, `...` is a `` `+...+` `` passthrough (`pass:c[...]` if it contains `+`); Mermaid stereotypes as entities; end
with `== References` listing only official sources and, where used, publisher pages. Run the `CLAUDE.md` greps on each
page as it is written. Book content is never reproduced.
