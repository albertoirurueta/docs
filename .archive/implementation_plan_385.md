# Implementation Plan: "Monitoring & Alerting" section (Grafana and Kibana) under Guides & References / Backend Development

## Task summary

Source: GitHub issue #385
Base branch: main
Branch: feature/385-grafana-kibana-monitoring-alerting

Issue [#385](https://github.com/albertoirurueta/docs/issues/385) asks for a new section **Monitoring & Alerting**
(`modules/ROOT/pages/backend/monitoring-alerting/`) teaching how to turn telemetry into metrics, dashboards and alerts
with notifications using Grafana 13.3.x and Kibana 9.5.x. The issue body is the specification (scope, version baseline,
facts not to get wrong, conventions, bibliography). Its two comments contain the page outline and the coverage tables
(`gh issue view 385 --json body,comments`).

Deliverables:

1. **83 AsciiDoc pages**: 16 shared pages at the section root, 33 in `grafana/`, 34 in `kibana/`.
2. **Nav wiring** after the Terraform block, and a bullet in `backend/index.adoc`.
3. **Three partials** with the AI-assistance notice, the only admonition allowed anywhere in the section.
4. **Figures**: `monitoring-alerting-*.svg`, `monitoring-alerting-grafana-*.svg`, `monitoring-alerting-kibana-*.svg`
   in `modules/ROOT/images/`, plus Mermaid diagrams.
5. **Bibliography** on `index.adoc`, each source linked to its official site (books to the publisher page).
6. **Two cheat sheet pages** with one-page PDFs in `modules/ROOT/attachments/`.
7. **One Docker Compose lab** (`grafana` and `kibana` profiles) and two end-to-end Bookshelf pages.
8. **Cross-link edits** on 12 existing pages.

**Choices made on the user's behalf** (challenge them at review)

* Execution follows the Database Migration plan (#382): pages are written by background agents, a few pages per agent,
  all sharing one brief; facts verified during the work go into the brief's addendum.
* The official docs are the primary source for every fact and snippet; the ten books are read-only inputs used only for
  the topics listed in the issue, and are never modified.
* Docker verification: approved by the user. The lab and the snippets the issue marks as "assembled" are run for real
  (Group 8). All other configuration is derived from the official pages, and each page states what was run.
* The shared pages that need the finished subsections (index with bibliography, comparison, glossary) come last
  (Group 10); the cheat sheets come after all pages (Group 9).
* Pages are documentation only, so tasks carry no language key.

Open clarifications: none
