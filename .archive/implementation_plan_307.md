### Mandatory conventions for every page task (from the issue and `CLAUDE.md`)

- Header: `= Title`, `:description:`, `:keywords:`, then `include::partial$csharp-build-tools-disclaimer.adoc[]`; intro states the
  release it was written against (MSBuild 18.9, .NET SDK 10.0.402, NuGet 7.9.0); anything newer than .NET 8 names its release and says
  preview/experimental/deprecated in prose.
- Each concept: what/why with rationale, every relevant command/option (`dotnet` and MSBuild switch forms), property, item,
  `nuget.config`/`global.json` key, env var and exit code; cross-tool equivalents; real error messages; classic bugs (lists in the issue
  body); release where a feature appeared/changed/was deprecated.
- Each example: complete, runnable on the baseline, with **real output** (never invented), followed by `Source: https://…[…]` to the
  looked-up official page/anchor (no `?view=` query). Use the *Ledgerline* running scenario. No real keys, tokens, certificates or
  private hosts; placeholders such as `oy2a…`.
- Each page ends with `== References` (official online docs only).
- AsciiDoc pitfalls (`CLAUDE.md` + issue): `$(…)`, `@(…)`, `%(…)`, `->`, `=>`, `<=`, `'`, `{…}`, `**`, `#` in inline code use
  `` `+…+` ``; anything containing `+` (SemVer metadata) uses `` `pass:c[…]` `` (`]` as `\]`); NuGet ranges `[1.0,2.0)` and `|` in
  tables escaped. Image macros on one line at column 0, alt text with a comma double-quoted. Mermaid: `<` followed by a letter or `/`
  written as `&lt;`.
- Each task's own verification: run its examples; grep its files for unquoted-comma image alt text, unclosed block macros and stray
  admonitions; check each `Source:` URL/anchor as far as the network allows.
