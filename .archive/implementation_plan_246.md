# Implementation Plan: Guides & References — E-commerce (Shopify, PrestaShop, Magento, WooCommerce)

## Task summary

Source: GitHub issue #246
Base branch: main

Issue [#246](https://github.com/albertoirurueta/docs/issues/246) asks for a new top-level **E-commerce** section under
*Guides & References*, authored into this repo's own `ROOT` Antora component (`modules/ROOT/pages/ecommerce/`, nav title
**E-commerce**), placed after Documentation Tools. It teaches four platforms, each a subsection with one detailed page
per concept in the issue's outline: **Shopify** (27 pages), **PrestaShop** (26), **Magento** (27) and **WooCommerce**
(28), each with a landing page and a `cheat-sheet.adoc` linking a one-page A4 PDF. It also adds a section landing
`index.adoc` ending in `== Bibliography` (official sites, data sources and the 15 books) and a `comparison.adoc` with
time-series, bar and radar charts. The issue body **and its four "Findings: <platform>" comments** are the
specification; re-read them (`gh issue view 246 --json body,comments`) when writing each page, because the per-page
concept lists, findings, bibliography and page conventions are not repeated here.

Deliverables: 108 platform concept/landing pages, 4 cheat-sheet pages, the section `index.adoc` and `comparison.adoc`
(114 pages); the disclaimer partial; the nav block; a home-page tile and icon plus metadata; `ecommerce-*.svg` figures
and Mermaid diagrams; comparison data (CSV) and generator `scripts/ecommerce-comparison-charts/`; four
`ecommerce-<platform>-cheat-sheet.pdf` files; back-links on the existing pages listed in the issue.

**Choices made on the user's behalf**

* **Delivery:** one branch (`feature/246-ecommerce-section-shopify-prestashop-magento-woocommerce`) and one draft PR.
* **Tooling (user-confirmed):** the implementation may install npm/pip packages and run Docker, in the session
  scratchpad only and nothing committed, to run the examples: PrestaShop and WordPress + WooCommerce in Docker
  (`wp-env` or the official images), Magento through the **Mage-OS** distribution (no Adobe Marketplace keys needed),
  Liquid and Shopify CLI `theme check` offline. Anything that cannot be run is documented in full and the page says in
  plain prose (never an admonition) that it was not executed and why.
* **Shopify scope (user-confirmed):** no accounts are created. Only what runs offline is verified (Liquid, Theme Check,
  TOML/JSON, Function builds). Admin/Storefront API calls, app installation and deployments are documented against
  the official docs and the page states they were not executed.
* **Running example:** *Pocket Coffee* in all four subsections, as the issue specifies. Sources are shown in the
  pages and not committed as projects.
* **Version baseline:** the issue's table and the four findings comments, re-verified at implementation time; every
  page states its baseline and check date. Metrics are re-fetched, not copied from the issue.
* **Charts:** SVGs generated by a dependency-free Node script with CSV data kept in the repo, following
  `scripts/documentation-tools-charts/` and `scripts/cloud-comparison-charts/`; unknown values are `n/a`, never zero.
* **Admonitions:** `partials/ecommerce-disclaimer.adoc` is the only admonition in the section; version, edition, Plus-only,
  deprecation and security caveats are prose or table rows.
* **Task tags:** all tasks are AsciiDoc/SVG/CSV/PDF authoring with no matching `iru-*-code-one-task` skill (the Node chart
  generator has none either), so they are untagged and implemented directly. PHP, Liquid, XML, JS and TS appear only as
  listings verified in the scratchpad.
* **Parallelism:** page tasks are distinct files, so tasks within a platform group are parallelizable. Forward xrefs to
  pages in later groups are the only build errors allowed until Group 11.
* **Cross-issue references:** other issues are mentioned in prose only, never as `xref:`. This repo's playbook is not
  changed.

Open clarifications: none
