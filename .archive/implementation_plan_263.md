# Implementation Plan: Backend and Web frameworks comparison pages

## Task summary

Source: GitHub issue #263
Base branch: main

Issue [#263](https://github.com/albertoirurueta/docs/issues/263) asks for two comparison pages built the way #196 built
`programming-languages/comparative.adoc`:

* `modules/ROOT/pages/backend/frameworks-comparison.adoc` (**Backend Frameworks Comparison**), first child of Backend
  Development in the nav
* `modules/ROOT/pages/web/frameworks-comparison.adoc` (**Web Frameworks Comparison**), first child of Web Development

Each page compares every framework already documented on the site plus extra frameworks that matter, on popularity,
growth trends, talent pool and jobs, ease of use, ecosystem and maturity, productivity and performance (backend:
throughput, memory, startup time, concurrency model; web: runtime benchmark, bundle size, Core Web Vitals, SSR), plus
security, LTS and deployment targets. Data is sourced, dated and shown in generated SVG time-series, bar and radar
charts (plus scatter, timeline and recommendation matrix), with one summary table of every framework against every
metric, recommendations by purpose and by hiring, and a Bibliography. The issue body is the specification; re-read it
(`gh issue view 263 --json body -q .body`) when writing each section, because its per-section metric lists are not
repeated here.

**Choices made on the user's behalf**

* **Charts:** SVGs generated by a dependency-free Node script from CSVs kept in the repo, following #201/#247:
  `scripts/framework-charts/`, writing `modules/ROOT/images/backend-frameworks-comparison-<id>.svg` and
  `web-frameworks-comparison-<id>.svg`, reusing the renderers in `scripts/language-charts/generate-charts.mjs` and the
  `readCsvFiles`/`writeCharts`/`runChartCli` helpers. Mermaid is used only for decision flowcharts.
* **Data freshness and reachability:** every figure is re-fetched from a primary source at implementation time. After
  full network access was granted (re-probed 2026-10-27), `curl` reaches `registry.npmjs.org`, `api.npmjs.org`,
  `pypi.org`, `pypistats.org`, `api.nuget.org`, `repo.packagist.org`, `raw.githubusercontent.com`,
  `survey.stackoverflow.co`, `stateofjs.com`, `techempower.com`, `endoflife.date`, `hacker-news.firebaseio.com` and
  `index.crates.io`; `api.github.com` and `crates.io` still return 403 (use `WebFetch`, the GitHub MCP tools, or
  `index.crates.io`/crates.io dumps instead). Fetch real data from these sources rather than marking them n/a. Use
  `WebFetch`/`WebSearch` for the rest; record this reachability note in `NOTES.md`. A figure that cannot
  be read at all is `n/a` with a `note`, never estimated and never plotted as zero, and its Bibliography entry is marked
  "(unverified)" per the house convention. Do not fill gaps from memory.
* **Scope of frameworks:** the lists in the issue are the target. The CSVs record, per framework, the metrics found;
  frameworks outside the documented set get fewer metrics where data is scarce, and the page says so.
* **House benchmarks are out of scope for this change.** The issue allows a Docker harness under
  `scripts/framework-charts/bench/` only when no published memory/startup figure exists, and running ~15 stacks needs
  infrastructure this session may not have. Memory and startup time come from published sources (labelled
  vendor-reported where they are), otherwise `n/a`; the page states this and a follow-up ticket can add the harness.
  SSR throughput (house-only in the issue) is therefore also `n/a`/omitted, and the page says why.
* **Scores:** radar scores (0-10) are computed from the CSVs where possible (`scores.mjs`, formulas in `data/NOTES.md`)
  and otherwise editorial with a written rubric and a `basis` column, as in #201.
* **Admonitions:** a new `partials/frameworks-comparison-disclaimer.adoc` (single `[IMPORTANT]` AI-assistance block,
  same shape as `cloud-disclaimer.adoc`) is included by both pages and is the only admonition on them. The TIP used on
  the #196 page is not repeated.
* **Placement:** full-stack frameworks are compared once, on the backend page; the web page covers their view layers
  and links back, and the two pages cross-link.
* **Task tags:** every task is AsciiDoc/CSV/SVG authoring or a Node chart script, and no installed
  `*-code-one-task` skill covers plain Node/JS scripts (no JavaScript key is installed), so every task is untagged and
  implemented directly.
* **Parallelism:** data tasks write distinct CSVs and run in parallel; the two page tasks edit different files and run
  in parallel; section sub-tasks inside one page are sequential.

Open clarifications: none
