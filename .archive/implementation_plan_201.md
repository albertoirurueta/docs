# Implementation Plan: Cloud providers comparison page

## Task summary

Source: GitHub issue #201
Base branch: main

Issue [#201](https://github.com/albertoirurueta/docs/issues/201) asks for one new comparative page,
`modules/ROOT/pages/cloud/comparing-cloud-providers.adoc` (nav title **Comparing Cloud Providers**), under
*Guides & References / Cloud*. It compares **AWS**, **Azure** and **Google Cloud** on popularity, ecosystem, learning
curve, pricing, availability regions and other metrics, and ends with a recommendation matrix by workload type and
target region, plus a Mermaid decision flowchart. Every number carries a primary source and an "as of" date, scores
have a documented methodology, graphics are time-series and radar charts (and others), and a Bibliography lists every
source. The issue body is the specification; re-read it (`gh issue view 201 --json body -q .body`) when writing each
section, because its per-section concept lists are not repeated here.

**Choices made on the user's behalf**

* **Charts:** SVG figures generated by a dependency-free Node script with CSV data kept in the repo, following the
  precedent of `scripts/documentation-tools-charts/` (#247): `scripts/cloud-comparison-charts/`, writing
  `modules/ROOT/images/cloud-comparison-<id>.svg`, reusing the renderers of `scripts/language-charts/generate-charts.mjs`.
  Reason: reproducible, proven to render, and consistent provider colours. Mermaid `xychart-beta`/`radar-beta` are not
  used (no existing page uses them); Mermaid is used only for the decision flowchart.
* **Data freshness:** all metrics are re-fetched from primary sources at implementation time (web access required),
  not taken from memory. The snapshot date is recorded in the CSVs and on the page ("as of YYYY-MM-DD"). A figure with
  no reliable public source is shown as `n/a` and never plotted as zero or invented.
* **Scores:** radar scores (0-10) are derived from the underlying CSV data where possible (computed axes) and from a
  written rubric with evidence for subjective axes; the rubric lives in `data/NOTES.md` and in the page's methodology
  section.
* **Pricing worked example:** official pricing calculators are interactive and often cannot be scripted, so the page
  lists the exact inputs and the unit prices from the official pricing pages, computes the total arithmetically, and
  says how to reproduce it in each calculator. If a calculator was not run, the page says so in plain prose.
* **Admonitions:** `partial$cloud-disclaimer.adoc` is the only admonition on the page.
* **Optional issue items:** a "See also" link from each provider `index.adoc` is included (cheap and discoverable);
  provider bibliographies and the disclaimer partial are left unchanged because the new page's own Bibliography links
  every source.
* **Task tags:** all tasks are AsciiDoc/SVG/CSV/Node authoring with no matching `iru-*-code-one-task` skill, except
  the Node chart generator, which has none either (no JavaScript key is installed). Every task is untagged and
  implemented directly.
* **Parallelism:** data tasks write distinct CSVs and run in parallel. All page-section tasks edit the same file and
  are therefore sequential.

Open clarifications: none

## Current code state

* `modules/ROOT/pages/cloud/` holds `index.adoc` (landing; `== Sections` list at the top) and the `aws/`, `azure/`,
  `google-cloud/` subsections. Each provider has `index.adoc` (with `[[_bibliography]] == Bibliography`),
  `global-infrastructure.adoc` (Azure: `== Sovereign clouds`; AWS: `== Partitions`, GovCloud, China, European
  Sovereign Cloud), `choosing-a-compute-service.adoc`, `getting-started.adoc`, a cost page
  (`aws/cost-management-and-support.adoc`, `azure/cost-management.adoc`, `google-cloud/cost-management-and-billing.adoc`)
  and an AI/data overview (`aws/ai-data-and-analytics-overview.adoc`, `azure/ai-data-and-iot-overview.adoc` plus
  `azure/foundry-tools/`, `google-cloud/ai-data-and-analytics-overview.adoc`).
* `modules/ROOT/nav.adoc:2246` is `** xref:cloud/index.adoc[Cloud]`, followed directly by
  `*** xref:cloud/azure/index.adoc[Azure]`. The new entry goes between them.
* `modules/ROOT/partials/cloud-disclaimer.adoc` is the disclaimer partial.
* Style precedent: `database/vector-rag/comparing-vector-databases.adoc` (an "as of" date, evaluation criteria, and
  dated alt text on `vector-rag-cloud-availability-matrix.svg`).
* Chart precedent: `scripts/documentation-tools-charts/` (`generate-charts.mjs`, `chart-definitions.mjs`, `scores.mjs`,
  `generate-charts.test.mjs`, `data/*.csv`, `data/NOTES.md`) on top of `scripts/language-charts/` renderers; the
  `package.json` scripts `charts:docs-tools` and `test:charts:docs-tools` run it.
* Mermaid is configured (Mermaid 11) and validated by `npm run validate:mermaid`; stereotypes and `<` before letters
  must be written as entities.
* `CLAUDE.md` rules apply to every task: single-line `image::` macros, quoted alt text containing commas, inline code
  with special characters as passthroughs, every SVG referenced, and the verification greps.

Each task writes distinct files under `scripts/cloud-comparison-charts/data/`. Every CSV has a `source` id and a
`retrieved` date column and uses the literal `n/a` for missing values; `sources.csv` (owned by Task 4) maps ids to
URLs and access dates.
