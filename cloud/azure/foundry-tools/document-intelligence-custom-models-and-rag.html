Document Intelligence: Custom Models, Classification and RAG Ingestion

This content was generated with the assistance of AI and should be verified against the official documentation before being relied on in production.

This page targets Azure CLI 2.90.0, the Document Intelligence REST API v4.0 2024-11-30, and the client libraries azure-ai-documentintelligence 1.0.2 (Python), Azure.AI.DocumentIntelligence 1.0.0 (.NET), com.azure:azure-ai-documentintelligence 1.0.10 (Java) and azure-search-documents 12.0.0 (Python), checked on 2026-10-06.

The prebuilt models on Document Intelligence: Read, Layout and Prebuilt Models cover common documents. This page covers documents that are specific to your business (custom models), packets that mix several document types (classifiers), and preparing documents for retrieval-augmented generation (layout to Markdown).

Custom models

Model type How it works Choose it when

Custom template

Learns fixed positions of fields from a few labeled samples (5 or more).

Every document uses the same layout, such as your own order form.

Custom neural

A deep-learning model fine-tuned on your labeled samples; tolerates layout variation.

The same document type comes in different layouts, such as supplier statements.

Composed model

Groups up to 200 custom models behind one model ID, with a classifier choosing which model analyzes each document.

One endpoint for many forms.

Training limits: up to 50,000 pages per training set for template, neural training measured in compute time (a monthly free allowance, then billed), and a limit on the number of custom models per resource (check the service limits page). Labeling happens in Document Intelligence Studio: upload samples to a Blob container, draw boxes around fields, then train. Models can be copied between resources (copy-to) for promotion from test to production.

Custom classifiers

A custom classifier (documentClassifiers) recognizes the type of each document, and with splitMode=auto splits a multi-document file into its parts. Typical flow: classify, split, then send each part to the right extraction model.

flowchart LR inbox[Mailroom PDF with several documents] --> clf[Custom classifier, splitMode auto] clf -->|invoice pages| inv[prebuilt-invoice] clf -->|delivery note pages| dn[Custom neural model delivery-note] clf -->|contract pages| ct[prebuilt-contract] clf -->|unknown| review[Manual review queue] inv --> out[orders-api] dn --> out ct --> legal[Contracts store]

from azure.ai.documentintelligence.models import (
    AzureBlobContentSource, BuildDocumentModelRequest, DocumentBuildMode,
)
from azure.identity import DefaultAzureCredential

endpoint = "https://foundry-bookshelf.cognitiveservices.azure.com/"
admin = DocumentIntelligenceAdministrationClient(endpoint, DefaultAzureCredential())
model = admin.begin_build_document_model(BuildDocumentModelRequest(
    model_id="delivery-note-v1",
    build_mode=DocumentBuildMode.NEURAL,
    azure_blob_source=AzureBlobContentSource(
        container_url="https://stbookshelf.blob.core.windows.net/training-delivery-notes"),

print(model.model_id, list(model.doc_types))

Layout to Markdown for RAG

prebuilt-layout with outputContentFormat=markdown returns the document as Markdown: headings from paragraph roles, tables as HTML <table> elements (which keep merged cells), figures with captions, and page-break markers. Chunking by heading keeps each chunk on one topic, which improves retrieval.

The job below parses a publisher’s catalog PDF, splits it at ## headings, and uploads the chunks to the catalog-docs index on search-bookshelf:

import re
from azure.ai.documentintelligence import DocumentIntelligenceClient
from azure.ai.documentintelligence.models import AnalyzeDocumentRequest, DocumentContentFormat
from azure.identity import DefaultAzureCredential
from azure.search.documents import SearchClient

cred = DefaultAzureCredential()
di = DocumentIntelligenceClient("https://foundry-bookshelf.cognitiveservices.azure.com/", cred)
search = SearchClient("https://search-bookshelf.search.windows.net", "catalog-docs", cred)

source = "https://stbookshelf.blob.core.windows.net/media/publisher-catalog-2026.pdf"
result = di.begin_analyze_document(
    "prebuilt-layout",
    AnalyzeDocumentRequest(url_source=source),
    output_content_format=DocumentContentFormat.MARKDOWN,
).result()

def chunk_by_heading(markdown, max_chars=4000):
    sections = re.split(r"(?m)^(?=#{1,2} )", markdown)
    for section in sections:
        title = section.splitlines()[0].lstrip("# ").strip() if section.strip() else ""
        for start in range(0, len(section), max_chars):
            yield title, section[start:start + max_chars]

docs = [
    {"id": f"catalog-2026-{i}", "title": title, "content": text, "source": source}
    for i, (title, text) in enumerate(chunk_by_heading(result.content))
    if text.strip()
]
search.upload_documents(docs)
print(f"uploaded {len(docs)} chunks")

Vector fields are left to the index’s integrated vectorization, covered on Azure AI Search with Foundry Tools. The general parsing and freshness concerns are on Document Parsing and Ingestion Pipelines & Freshness.

Containers, batch API and the legacy package

  • Containers: v4.0 Read and Layout run as containers for on-premises processing, billed against a FormRecognizer resource (see Pricing, Quotas, Containers and Monitoring).

  • Batch API: documentModels/{modelId}:analyzeBatch analyzes every file in a Blob container and writes results to another container. Use it for backlogs instead of thousands of single calls.

  • Legacy package: azure-ai-formrecognizer (3.3.x) targets v3.0 and v2.1. v3.0 reaches end of support on 2029-03-30 and v2.1 on 2027-09-15. Move to azure-ai-documentintelligence, whose client and model names differ (DocumentAnalysisClient becomes DocumentIntelligenceClient).

Provisioning

In the Azure portal

  1. In Document Intelligence Studio (https://documentintelligence.ai.azure.com/studio), choose Custom extraction model or Custom classification model, create a project and connect it to foundry-bookshelf and a Blob container of samples.

  2. Label at least 5 samples per document type, then Train.

  3. Grant the resource’s managed identity Storage Blob Data Reader on the training container.

With the Azure CLI

az storage container create --account-name stbookshelf --name training-delivery-notes --auth-mode login
az storage blob upload-batch --account-name stbookshelf --destination training-delivery-notes \
  --source ./samples/delivery-notes --auth-mode login

When not to use it

  • When you can’t label samples, or the fields are described better in words than by examples, try Content Understanding field extraction (Content Understanding: Multimodal Analyzers).

  • For a handful of documents, a Foundry Model with the layout Markdown in the prompt may be enough.

  • See Choosing a Foundry Tool (or a Foundry Model).
